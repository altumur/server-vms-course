## Новые находки

### РН3-01 — Существенная. Инструкция автора сохраняет гейт старого Python после его заморозки

**Место:** `skills/lesson-spec/SKILL.md:44–47`; связанные проверки — `references/review-checklist.md:26–27` и `references/change-map.md:28` того же навыка.

**Цитата:** «При такой правке перед пушем в venv курса (`CLAUDE.md`) `python Source/tests/run.py test_boundary test_spec_verdicts test_platform_lists` не даёт новых отказов».

**Первичное основание:** `decisions/0080-лекции-как-спецификации.md:937–940`, доп. 16 п. 2: «на согласование его с меняющимся каноном не тратятся»; «Его тесты общей приёмки читают её на закреплённом срезе курса `a0bd9e53` … а не живую спецификацию»; «Долгов старому Python больше не назначают». Соответствие текущему канону показывает `cammeta-python`.

**Контрпример:** владелец разрешает очередное изменение живой общей таблицы `Source/tests/testdata/platform_lists.tsv` вместе с необходимой работой для остающегося Go-свидетеля. Автор по навыку должен дополнительно выполнить старый Python в своём новом дереве и обеспечить отсутствие новых отказов. Срез `a0bd9e53` в команде и её условиях вообще не назван. Если же проверить закреплённую старую приёмку, её успех ничего не проверяет в изменённой живой таблице. Инструкция не различает эти две проверки и всё ещё делает старый Python условием публикации живого канона.

**Последствие:** автор получает устаревший обязательный маршрут проверки и повод согласовывать замороженный свидетель с новым каноном; либо предъявляет проверку старых данных как проверку новой правки. Поведение самих тестовых скриптов здесь не утверждается: они не читались и не запускались. Противоречие находится в назначении проверки и отсутствующем в инструкции разграничении срезов.

**Происхождение:** инструкция была уточнена после ревью 2, затем решение `ce159f08c585f63d7486adcedb64268277848a73` заморозило Python без соответствующего изменения навыка. Это новый разрыв после изменения первичного правила, а не утверждение, что исходное замечание ревью 2 не исправлялось.

**Рекомендация / вопрос «Архитектору»:** исключить замороженный Python из гейта живых данных, явно сослаться на его закреплённый срез и отделить проверки текущего канона общими раннерами от обязательств остающихся свидетелей.

### РН3-02 — Существенная. Роль «Спецификация» запрещает каталоги общих данных, которыми теперь владеет

**Место:** `СЕССИИ.md:59`, список разрешённых каталогов роли «Спецификация»; зависимости — `skills/lesson-spec/SKILL.md:8–10,44–45`, `references/change-map.md:28`.

**Цитата:** «Пишешь только свои каталоги: эти четыре, `Source/tests/testdata/acceptance/<модуль>/<урок>/` … и `ХОД-Спецификация.md`».

**Первичное основание:** ADR-0080 доп. 16 п. 3, `decisions/0080-лекции-как-спецификации.md:943–946`: «Байты общих данных спецификации — `Source/tests/testdata/testsub*.yaml`, общие таблицы `Source/tests/testdata/*.tsv`, спеки подсистем `Source/vms/*.subsystem.yaml` — правит «Спецификация»». Условия изменения байтов остаются в силе; находка их не отменяет.

**Контрпример:** после явного назначения требуемого долга автору поручено поправить данные `Source/tests/testdata/testsub2.subsystem.yaml`. По доп. 16 п. 3 это её файл; по исчерпывающему «только» в промпте роли файл вне разрешённых каталогов. То же расхождение возникает для `Source/tests/testdata/platform_lists.tsv` и `Source/vms/*.subsystem.yaml`. Это не требование читать или править код реализации.

**Последствие:** новая сессия должна либо нарушить буквальный список своего владения, либо остановить разрешённую ADR работу как чужую. Навык ссылается на СЕССИИ как на правила владения, поэтому молчаливо разрешить расхождение внутри самого навыка нельзя. Старшинство ADR однозначно выбирает разрешение; степень — существенная, не блокер.

**Происхождение:** несогласованный список существовал до текущего ревью; точный коммит, впервые создавший расхождение, не установлен.

**Рекомендация / вопрос «Архитектору»:** дополнить список роли ссылкой на владение общими данными по доп. 16 п. 3, сохранив запрет на код и условия изменения байтов.

### РН3-03 — Существенная. `counts()` принимает подмножество и кодовый пример за счёт всего урока

**Место:** `skills/lesson-spec/scripts/check_spec.py:380–421`, особенно `393–401`; обещание границы — `skills/lesson-spec/references/validation.md:59`. Отдельной находкой ошибки двух ветвей не считаются: причина общая — поиск по сырому Markdown без различения назначения текста.

**Цитата границы:** «Распознаются только эти формы и только как счёт всего урока; другие формулировки (словами, подмножество) — вручную по чеклисту».

**Контрпример 1, допустимое подмножество:** таблица содержит два сценария по одному шагу. В инструкции написано: «Подмножество, только проверка гонок: 1 сценарий / 1 шаг. Остальные проверки сюда не входят». CLI возвращает код 1 и ошибки `says 1 scenarios, the tables have 2` / `says 1 steps, the tables have 2`, хотя утверждение про весь урок не сделано.

**Контрпример 2, пример формы:** единственный настоящий сценарий — `01-a`. Под Н5 помещён явно обозначенный пример таблицы внутри блока ` ```markdown ` со строкой `| 99 | будущий пример |`. CLI возвращает код 1: `Н5 names scenario 99, scenarios.tsv has no such scenario`. Строка внутри блока кода не является строкой опубликованной Markdown-таблицы Н5. Аналогично счёт другого стенда внутри ` ```text ` сравнивается с текущим уроком. Контроль без примера возвращает PASS.

**Основание и последствие:** проверка должна сверять фактические таблицы Н5 и однозначно распознанные общие счёты — ADR-0080 доп. 14 п. 3 (`decisions/0080-лекции-как-спецификации.md:818–822`) и названная граница validation.md. Сейчас корректный текст получает ложный FAIL; автор вынужден менять содержание под неописанную особенность парсера. Это не косметически неверный печатный счёт и не запрос поддержать неизвестный формат: используется поддержанный Markdown и явно исключённое из автоматической проверки подмножество.

**Воспроизведение:** генераторы `/private/tmp/review-skills-3-codex-logs/probe-checker.py` и `probe-subset.py`; точные argv, cwd, exit/stdout/stderr отдельных запусков — `probes/instruction-subset.json`, `probes/fenced-n5-table-example.json`, `probes/fenced-instruction-count-example.json`, контроль — `probes/control.json`. Данные проб лежат рядом, вне курса.

**Происхождение:** смешанное. Проба с подмножеством даёт тот же ложный FAIL на проверяющем скрипте среза `666dba63`; сырая обработка счётов существовала раньше. Ветка таблиц Н5 добавлена `632d5ad2ac0d3a1e4d16775229e2502abd9ef73d`: та же проба с кодовой таблицей до исправления даёт PASS, на текущем срезе — FAIL. Исходник до правки, генератор и результаты сохранены в `before-check_spec.py`, `probe-history.py`, `history-probes.*`, `probes/before-*.json`. Сравнивается инструмент с одинаковыми данными, не реализация урока.

**Рекомендация / вопрос «Архитектору»:** читать реальные Markdown-таблицы вне примеров и ограничить автоматические счёты явно обозначенным итогом всего урока; остальные формулировки оставлять ручной сверке, как обещает validation.md.

## Согласованность, применимость и проверяемость правил

- **Источник и владение.** Навык не разрешает автору менять ADR/навыки; `lesson-spec/SKILL.md:12–13` и `platform-review/SKILL.md:12–15` отдают навык «Архитектору». Участие «Архитектора» в коде самого проверяющего скрипта разрешено исключением доп. 14 п. 5; запрет на код продукта из роли этому не противоречит. Конфликт каталожного владения данными вынесен в РН3-02.
- **Чистая комната и экспорт.** Чеклист `:19–21` требует исполнимую норму в экспортируемом каноне, а не только в ADR. Шаблон инструкции `:20–22` не создаёт собственного раннера. Это согласуется с доп. 16 пп. 1 и 4. Генерация `cammeta-python/go`, экспорт и мутационная приёмка в этом ревью не выполнялись.
- **Порядок перед следующим прогоном.** Доп. 14 `:847–851` задаёт цепочку «исправления → экспорт → cammeta-python → мутации → ревью». В навыках нет разрешения заменить её одним PASS скрипта: `lesson-spec/SKILL.md:8–10,84–85` сохраняет старшинство ADR и предел механики. Отсутствие копии всей цепочки в каждом навыке не считаю отдельным дефектом: правило уже имеет одно первичное место.
- **Связь.** Правило 12(а–з) задаёт вид/длину сообщений, короткую запись хода, отсутствие heartbeat и ожидания старта, самостоятельное итоговое уведомление и поиск актуальной панели по заголовку. Навыки не предписывают обратного. Для этого задания применяется новая явная команда владельца о ревью старых находок навыков 2; общий запрет отдельного прохода закрытий уроков её не отменяет.
- **Одно правило — одно место.** Основной состав без OpenAPI и подключение Н0 определяет templates; полный ручной счёт — чеклист; validation — предел механического распознавания; change-map — адреса проверки, не вторые нормы.
