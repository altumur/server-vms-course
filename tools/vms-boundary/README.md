# Граница комплекта VMS

Проверка git, которая держит границу «сессии VMS платформу не правят» (ADR-0090 п. 3, доп. (1), (6) п. 8, (7) п. 4).
От ошибки, не от умысла: `--no-verify` хук обходит, его ловят `pre-push` и вехи «Архитектора».

| Файл | Что |
|---|---|
| `check.py` | правила: белый список сессии VMS, трейлер `Session:`, проверка диапазона коммитов |
| `hooks/pre-commit` | ветка `vms/<тема>`, пути индекса — из белого списка сессии дерева |
| `hooks/commit-msg` | один трейлер `Session: <сессия дерева>` |
| `hooks/pre-push` | каждый коммит отправляемого диапазона: трейлер сессии дерева, пути белого списка, `Source/vms/` не тронут |
| `install.sh <сессия>` | ставит хуки в рабочее дерево: `core.hooksPath` и `vms.session` в `config.worktree` |
| `sessions.txt` | сессии комплекта VMS (имя — как в `СЕССИИ.md` §2 и в трейлере); правит «Архитектор» |
| `source-vms.sha256` | байты свидетеля `Source/vms/` на срезе старта; их не правит никто, сверяет и `check_spec` |
| `test.sh` | проба на временном репозитории: каждая закрытая группа отклонена, белый список с трейлером проходит |

**Белый список сессии VMS:** `VMS/`, `М10B_ServerVMS/`, `М12A_Domain/`, `М12B_DomainVMS/`, `М13_Observability/`,
`М14_VendorVMS/`; свой `ХОД-<сессия, пробелы → «-»>.md`; `decisions/inbox/<дата>-запрос-vms-*.md` и
`<дата>-решение-владельца-vms-*.md`. `Source/vms/*` в нём нет (доп. (6) п. 8): канон манифестов — `VMS/<NN-sub>/`.

```sh
# сессия VMS, один раз в своём дереве
git -C /Users/murat/w2c/server-vms-course worktree add -b vms/<тема> <путь дерева> <COURSE_COMMIT выгрузки VMS>
cd <путь дерева> && tools/vms-boundary/install.sh "Спецификация VMS"
# коммит сессии
git commit -m "<что>" -m "Session: Спецификация VMS"
# «Архитектор» на вехе ХОД: весь main от коммита старта
python3 tools/vms-boundary/check.py range <коммит старта>..origin/main
```
