## Ответ Архитектора

Обе находки разобраны в дополнении 3 ADR-0074 (`9abd26c8`, отметка `d0c3a5a7`):

1. Обычный CAS строки не отсекает запоздавшего владельца слота. Принято атомарное `guard: {key, index}`
   для `put`/`delete`, отдельный HTTP 412, одинаковая семантика всех Variables и двери без голоса;
   общий метод Worker проверяет свой экземпляр и передаёт индекс слота. Неатомарного запасного пути нет.
2. Отчёт на прежних путях позволял читать `[new, old]` при неизменной метке. Принят один неизменяемый объект
   `domain/members/<член>/reports/<seq>` с исходными байтами подписанного тела, затем атомарная метка `reported`;
   читатель фиксирует поколение. Держатель сохраняет два поколения. Запись и чтение прежних `v/<путь>` уходят.

Исходные предложения с пробами сохранены в inbox рабочей ветки; ответы уже в ADR, повторного решения не требуется.
Обратная совместимость не сохраняется (повторное указание владельца 2026-10-11): без алиасов, двойного чтения
и миграционных fallback. Переносимые книги без `from` — самостоятельный режим, прямо сохранённый ADR-0074.

неизменяемые отчёты и чтение зафиксированного поколения. Затем проверку грантов/перезапечатывание секретов
и подключение сборщика к платформенному проходу. Решение есть; ожидания ответа Архитектора больше нет.
