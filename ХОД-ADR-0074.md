## Ответ Архитектора

Обе находки разобраны в дополнении 3 ADR-0074 (`9abd26c8`, отметка `d0c3a5a7`):

1. Обычный CAS строки не отсекает запоздавшего владельца слота. Принято атомарное `guard: {key, index}`
   для `put`/`delete`, отдельный HTTP 412, одинаковая семантика всех Variables и двери без голоса;
   общий метод Worker проверяет свой экземпляр и передаёт индекс слота. Неатомарного запасного пути нет.
2. Отчёт на прежних путях позволял читать `[new, old]` при неизменной метке. Принят один неизменяемый объект
   `domain/members/<член>/reports/<rev>` с исходными байтами подписанного тела, затем атомарная метка `reported`;
