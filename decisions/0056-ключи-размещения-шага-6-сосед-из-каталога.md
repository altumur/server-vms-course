# Ключи размещения шага 6 в платформе: `affinity`, `near.prefer`, `offers`; сосед из каталога, держатель у таблицы мест

## Context and Problem Statement
Три ключа размещения курса (`placement.affinity`, `placement.near.prefer`, `placement.offers`) в продукте были кодом
подсистемы или выводом платформы:
- `SpecController.Admit` — vms `GuardBackups`;
- `SpecController.NearRank` — vms `PreferBackups`;
- поле `SpecController.NearSpec`, которое vms ставит платформе: спека ведомой подсистемы для `nearHome`;
- запасные предлагались любой спеке, размещаемой по серверу (`CountsSpares()`).

По форме ключи совпадают с курсом. Механика продукта расходилась в трёх местах: откуда берётся спека соседа, сколько
стоит чтение и у какой таблицы `GET /<table>` говорит `held_by`.

## Decision Drivers
* Что платформа знает о другой подсистеме — это её каталог спек, а не поле, которое ставит подсистема (ADR-0002).
* Объявление без действия — тихое ослабление размещения (ADR-0012).
* Группа размещается целиком, нехватка считается по целой группе (ADR-0011).

## Considered Options
* Оставить `NearSpec`: спеку соседа передаёт подсистема.
* Спеку соседа берёт каталог (`KnownSpec`), процесс без неё ничего не предпочитает.
* Спеку соседа берёт каталог, спека без соседа в каталоге не грузится.

## Decision Outcome
Выбран третий вариант. Ключи — слово в слово курсовые.
- **`offers: true|false`**, по умолчанию false. Нехватку, офферы запасным и строки `<p>_workers_needed`,
  `units_short`, `spare_offers`, `spares_withheld` даёт только спека с `offers: true`. Вывод из `place_by` уходит.
- **`near.prefer`**: `{<их поле>[.<поле строки, на которую оно ref>]: <значение | список>}`, только при `near.of`.
  Это предпочтение, а не требование: из нескольких найденных сначала подходящие по всем ключам, потом остальные, внутри
  по их id. Хук `NearRank` уходит.
- **`affinity`**: `{field, table, server_field?, strict?}`, фильтр в порядке constraint → `spread_by` → affinity →
  группа. Место со строкой `admits: false` не берёт никого. Связывающая строка ведёт юнит только на своё место (и сервер
  `server_field`). Связывающее место не берёт юнит с другим домом. Нечитаемая строка не связывает и не отказывает. Хук
  `Admit` уходит.
- **Сосед из каталога.** `NearSpec` уходит; `nearHome` и `near.prefer` берут спеку соседа из каталога спек процесса
  (`KnownSpec(near)`, курсовой `catalog.spec`). Спека с `near.of` или `near.prefer`, чьего соседа каталог не держит,
  отказывается при загрузке и называет соседа. Курс переносит эту проверку из прохода в загрузку.
- **Цена чтения** — как в курсе, раз за проход: их строки, таблица по `ref`, таблица `affinity`. В продукте строки
  соседа держатся между проходами (`ListTable`/`RowCache`), и перечитывается только изменившееся.
- **`held_by` в `GET /<table>`** — у `places.table` в обоих деревьях: держатель есть только у места (hold
  `<sub>/holds/<row>`), у таблицы `affinity` без `places` его нет. Объединения нет; курс меняет условие в
  `console._table_route`.

### Consequences
* Good, because три хука подсистемы и одно поле-шов уходят, их смысл — в спеке (ADR-0002).
* Good, because спека, чей сосед не загружен, не размещает молча хуже, а не грузится.
* Bad, because спека по серверу без `offers: true` перестаёт предлагать запасных: спеки vms ставят ключ тем же окном
  («Сборка»), а контроллер vms загружает спеку rec в каталог (`KnowSpecs`).

### Confirmation
Тесты продукта: отказы загрузчика по каждому ключу и по соседу вне каталога; affinity на `testsub2` (`admits: false`,
связывающая строка, связывающее место, сервер, нечитаемая строка); `near.prefer` с ключом через `ref`; офферы только
при `offers: true`. Курс: проверка соседа при загрузке, `held_by` у `places.table`.
