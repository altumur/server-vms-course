# Подсистема экспорта VMS `exp` и предметный API экспорта в контракте форка

## Context and Problem Statement

Класс системы: платформенная система (подсистемы VMS) с консолью — форком consolem.

Слово владельца 2026-11-03 (через «Консоль»): по окну экспорта GUI оператора (one-psim-monitor, `d656b21`; кнопка экспорта кадра и окно целиком) сделать ADR с требованиями к новой подсистеме экспорта VMS и к OpenAPI форка, чтобы окно заработало в продукте; консоль пока не трогать. Отдельно проверить: монитор — клиент оператора, а `Me` в контракте — администратор.

Окно одно, входов пять: кадр живого видео, кадр архива, интервал архива, закладка, область кадра; печать кадра. Режимы — видео (MKV, MP4, AVI, EXE) и кадр (JPG, PDF); несколько камер и периодов; около 35 настроек; ход, готовность и «Скачать» — уведомлениями.

В VMS подсистемы экспорта нет; в контракте нет операций экспорта, кадра и скачивания. `rec` отдаёт куски fMP4 не длиннее 3600 с (V/02.5); групповая операция платформы (P/06.9) ограничивает шаг 30 с (`OPS_STEP_WAIT`) и хода в процентах не имеет. Байты идут мимо консоли и `backend` (ADR-0015): передача отдаёт только JSON, problem+json или поток событий, blob через консоль — не больше 32 МиБ.

## Decision Drivers

* Окно оператора должно работать в продукте; консоль пока не трогаем — сейчас нужны подсистема, нормы и контракт.
* Байты мимо консоли (ADR-0015), право судится на каждом обращении (V/11.1).
* «Доступ к живому просмотру, архиву и экспорту логируется» (`.cursor/rules/recording-and-retention.mdc`).
* Работа — рядом с архивом: видео не ходит по сети ради перекодирования.
* Окно скрывает то, чего система не умеет: каждая часть окна — объявленная возможность.
* Всё до первой генерации (ADR-0103 доп. (2)).

## Considered Options

1. **Своя подсистема `exp` и предметный API `/exports` (выбрано).**
2. **Групповая операция платформы P/06.9** — шаг 30 с, хода нет, итог — не файлы.
3. **Универсальное действие `longRunning` модели ADR-0116** — привязано к одной единице и отвечает операцией; у экспорта много камер и итог — файлы со сроком.
4. **Синхронный `GET …/frame` для кадра** рядом с заданием видео — вывел бы маску, титры и журнал из одного места в два.

## Decision Outcome

Выбран вариант 1.

### 1. Подсистема `exp`

1. Новый урок `VMS/13-exp` — по образцу `detjob` (V/05): задание — строка `exp/jobs/<id>`, `about: {sub: cam}` (права и журнал камеры), ход — `state.cursor`, итог — `state.result`, снятие — `retire_when … delete_after`. Номер — следующий после `VMS/12-psim` (ADR-0115); перечни ADR-0090 этим ADR дополняются.
2. **Размещение** — `near: {sub: rec, by: rec}` (сродство, не фильтр), метка `gpu` для перекодирования, бюджет — `capacity`. Задание нескольких камер делится на части по записям; часть идёт рядом со своей записью; «в один файл» собирает один сервер, чужие части тянет по дверям.
3. **Источник видео.** Архив — двери `rec` `/spans/<запись>`, `/samples/<запись>?from&to[&track=audio]`, как `detjob`; в `door.routes` `rec` добавляется роль воркера `exp` (правка V/02.5). Правила эпох и закрытых блоков — как у шкалы. Звук — поток `…/audio` записи.
4. **Живой кадр** — RTSP-дверь шлюза `live` с учёткой потока: она есть везде, где есть живое видео, право на неё уже судится. Кадр держателя камеры и последний блок записи — не источник.
5. **Дыры.** Отрезок с дырой отдаётся с дырой, часть помечается `partial`; ожидания дозаписи нет. Удержание при экспорте не ставится: выгрузка — копия, для удержания своя кнопка и право.
6. **Чужой кластер** — `409 OTHER_CLUSTER` со ссылкой «Открыть», как `live` и удержания.
7. **Свой том** `exp` (`parts.volumes`): файлы со сроком; кольцо архива их не трогает. При нехватке места новое задание отказывается, чужие файлы не вытесняются.

### 2. Ход, отмена, повтор

* Ход — доля готового по каждой части и общий процент, в `cursor` не реже раза в 5 с; `backend` переводит его в поток, как `discovery.progress`. Истина — `GET`.
* Отмена — своего задания; текущая часть может доиграть, следующая не начинается; готовые файлы удаляются.
* Отказ — код на часть: `no_recording`, `unreachable`, `no_space`, `limit`, `offline` (живой кадр); частичный успех — норма.
* Повтор неудачных частей — новым заданием с `retry_of`; повтор запроса — тот же `idempotencyKey` даёт то же задание.

### 3. Пределы

Константы в духе `OPS_*`, значения — «Архитектора», правятся замером:

| Константа | Значение |
|---|---|
| `EXPORT_TOTAL_MAX` — видео в одном задании суммарно | 24 ч |
| `EXPORT_PERIODS_MAX` | 32 |
| `EXPORT_CAMERAS_MAX` | 16 |
| `EXPORT_ACTIVE_PER_USER` | 4 |
| одновременных заданий на сервер | по `capacity` |
| `EXPORT_FILE_MB` — части файла | 4000 МБ, умолчание, правится в окне до предела |
| место под файлы | квота тома `exp` |
| `EXPORT_LINK_TTL` — токен ссылки | 120 с |

Все пределы — в `reference.export.limits`; окно берёт их оттуда.

### 4. Права

1. **Выгружать** — функция `EXPORT` роли плюс уровень камеры, дающий архив; для живого кадра — ещё живой просмотр. В V/11.8 `exp` входит в закрытый список подсистем точки и в перевод функций; создать задание — `edit` на `exp` по камере. `EXPORT` объявляется в `reference.access.features`.
2. **Без пароля** — `ALLOW_UNPROTECTED_EXPORT`; без неё пароль обязателен, проверяет сервер.
3. **Без маски** — `ALLOW_SHOW_PRIVACY_VIDEO_IN_ARCHIVE`; без неё маску ставит сервер (когда маскирование есть — вопрос 6).
4. **Глубина** — `depth` роли ограничивает отрезки.
5. **Своё и чужое** — задание и файл видит и скачивает автор; чужие — право на журнал или администрирование.
6. **Супервизор** и **водяной знак** — не объявляются до ответа на вопрос 8 и отдельного решения о знаке.

### 5. Журнал

Строки в журнале камеры (`about: cam`): `export.made` (кто, камеры, отрезки, формат, маска, знак, был ли пароль — без пароля, комментарий), `export.refused`, `export.finished` (файлы, размеры, SHA-256), `export.issued` (каждая выдача ссылки), `export.read` (каждое скачивание), `export.deleted` (человеком или по сроку).

### 6. Выдача файла

Файл отдаёт своя дверь `exp` по ссылке с токеном в адресе, как `playback` (`?t=`, `EXPORT_LINK_TTL`); мимо консоли и `backend`. Дверь отвечает `Content-Disposition: attachment` с именем файла и поддерживает `Range` (206) — это новые нормы двери, доля «Спецификации VMS» (и «Спецификации», если правило ответа 206 общее для дверей). Ссылку окно берёт непосредственно перед скачиванием.

### 7. Что делает задание

Перепаковка H.264 в MKV или MP4 без перекодирования; перекодирование — по настройкам качества, титрам, области, маске; программные титры и главы-закладки — дорожкой; кадр JPG или PDF — декодированием от ключевого кадра; нарезка по размеру — по ключевым кадрам. Справочник отдаёт по каждому сочетанию, нужно ли перекодирование. **Кадр — то же задание**, `mode: frame`, обычно готово за секунды. **Печать** — браузер печатает готовый JPG или PDF; своей операции нет.

### 8. Контракт форка

Предметный API, как шкала и удержания: `/exports` в этапах ADR-0116 не снимается.

* `GET /reference` → `export`: форматы (`id`, `kind`, кодеки, титры, главы, пароль, «в один файл», входы), ступени сжатия, разрешения, делители частоты, поля титров, шрифты, режимы маски, назначения, пределы. Окно строит списки только отсюда.
* Пути: `GET /me/export`, `GET /devices/{deviceId}/recording-days`, `POST /exports/check`, `POST /exports` (202), `GET /exports`, `GET /exports/{id}`, `POST /exports/{id}/cancel`, `POST /exports/{id}/retry-failed`, `DELETE /exports/{id}`, `POST /exports/{id}/files/{fileId}/link`. Тела `ExportCreate`, `Export`, `ExportCheck` — по требованиям «Консоли» (`ТРЕБОВАНИЯ-ЭКСПОРТ.md` § 4.4); `password` и `supervisor.password` — `writeOnly`.
* Ошибки с `field` — JSON Pointer по телу (ADR-0116 этап 0); новые коды `PASSWORD_REQUIRED`, `NO_RECORDING`, `LIMIT_EXCEEDED`, `EXPORT_EXPIRED` (410); `SUPERVISOR_REJECTED` — с вопросом 8.
* Поток — `export.progress`, `export.finished`, только автору (перечень `StreamMessage.type` открыт ADR-0116 этапом 0).
* Возможности — операции и коды `Feature`. В первой генерации объявляются: `exportVideo`, `exportFrame`, `exportLiveFrame`, `exportArea`, `exportMultiCamera`, `exportMultiPeriod`, `exportTranscode`, `exportTitles`, `exportAudio`. Остальные (`exportSingleFile`, `exportTracks`, `exportPrivacy`, `exportPassword`, `exportPlayer`, `exportCloud`, `exportEventTitles`, супервизор) — после ответов владельца на вопросы ниже: окно их скрывает.
* `backend`: `exp` — в `door.pass.calls`, строки `mapping.tsv` `/exports` → `exp/jobs`, судьбы операций — V/11.2.

### 9. Оператор и `Me` (отдельный вопрос владельца)

Да, это отдельная большая тема. В контракте `Me` — «текущий администратор», операторских сессий и прав оператора нет; монитор — клиент оператора. У w2c человек любого ранга (`view`, `edit`, `admin` по подсистемам) — уже человек платформы, поэтому со стороны VMS препятствия нет; меняется контракт: `Me` любого человека с его рангами и функциями, вход оператора, `GET /me/export` и права по видам — это этап 4 ADR-0116 (`kindAccess`, `objectAccess`). Решение — отдельным ADR «Оператор в контракте форка» до этапа 4; экспорт до него работает для человека, у которого есть права в нынешнем `Me`.

### 10. Вопросы владельцу

Ответы меняют только то, какие возможности объявлены; рекомендации — «Консоли», с ними согласен.

1. **Срок жизни файла** — рекомендация: настройка системы, умолчание 24 ч.
2. **«В один файл»** — рекомендация: несколько видеодорожек в одном MKV; для MP4 и AVI не показывать.
3. **EXE и «Добавить плеер»** — рекомендация: не делать в вебе.
4. **«В облако»** — рекомендация: кнопки нет, пока не назван адресат.
5. **Пароль** — рекомендация: ZIP AES-256, у PDF — свой пароль PDF.
6. **Треки и маскирование** — рекомендация: `det` пишет рамки дорожкой метаданных рядом с записью (правка V/02, V/04, отдельный ADR).
7. **Закладка — момент** — рекомендация: окно берёт ±30 с, правится в форме.
8. **Супервизор** — рекомендация: синхронная проверка второго человека в `POST /exports`; нужна правка платформы — проверка учётных данных без входа, отдельный ADR.

### 11. Объём

| Слой | Объём |
|---|---|
| Урок `VMS/13-exp` (нормы, манифест, приёмка) | большой |
| `rec` (роль в `door.routes`), `live` (кадр для `exp`) | малый |
| V/11 (`/exports`, `reference.export`, поток, права V/11.8, судьбы V/11.2) | средний |
| Контракт форка и тестовый сервер | средний: ~10 операций, справочник, коды, типы потока |
| Нормы двери файла (attachment, `Range` 206) | малый |
| Платформа | нет (супервизор — отдельным ADR по вопросу 8) |

### Consequences

* Хорошо, потому что окно экспорта оператора получает полный путь: справочник, проверку, задание, ход, файл, журнал.
* Хорошо, потому что кадр, видео и печать идут одним путём, одним правом, одной строкой журнала.
* Плохо, потому что урок большой и входит в первую генерацию; часть окна (треки, маска, супервизор, облако) ждёт ответов и отдельных решений.
* Нейтрально: работа с оператором в контракте — отдельный ADR; экспорт ему не мешает.

### Confirmation

* Приёмка урока: видео двух камер за два периода — два файла с верными SHA-256 в журнале; кадр архива и живой кадр — JPG; отмена посреди — файлов нет; дыра — `partial`; чужой кластер — `409 OTHER_CLUSTER`.
* Ссылка истекает через 120 с; повторная выдача пишет `export.issued`; скачивание с `Range` получает 206.
* Без `EXPORT` — `403`, без `ALLOW_UNPROTECTED_EXPORT` и без пароля — `422 PASSWORD_REQUIRED` у поля `/password`.
* Тесты API форка в профиле w2c: необъявленные возможности скрыты, `404 NO_ROUTE` у необъявленных операций.

## Дополнение (1), 2026-11-03 — слово владельца: вопросы 1–8 по рекомендациям, уточнение к 7

Владелец (через «Консоль»): вопросы 1–8 § 10 принимаются по рекомендациям; к 7 — «закладка — либо момент, либо отрезок (тип закладки)».

1. Срок жизни файла — настройка системы, умолчание 24 ч. «В один файл» — дорожки в одном MKV (`exportSingleFile`, только MKV). EXE и плеера нет. «В облако» нет. Пароль — ZIP AES-256, у PDF — пароль PDF (`exportPassword`). Треки и маска — рамки `det` дорожкой метаданных рядом с записью (`exportTracks`, `exportPrivacy`) — отдельный ADR о дорожке, правка V/02, V/04. Супервизор — синхронная проверка второго человека в `POST /exports` (`SUPERVISOR_REJECTED`) — отдельный ADR о проверке учётных данных без входа, правка платформы.
2. **Закладка** — тип `moment` или `span`: у `Bookmark`, `BookmarkCreate` поле `type: moment | span` и конец отрезка `to` у `span`; отметка `rec` получает необязательный конец (правка V/02.7 и `mapping.tsv`). Экспорт из отрезка — его границы, из момента — ±30 с (правится в форме).
3. Объявленные в первой генерации возможности § 8 дополняются `exportSingleFile`, `exportPassword`; `exportTracks`, `exportPrivacy`, супервизор — после своих ADR.
