# Внешняя команда лекций: канал — git, вопросы по ADR — файлами в `decisions/inbox/`, курс кладёт первым

## Context and Problem Statement
Класс системы: порядок работы, не код.

После этого этапа лекциями (курс `server-vms-course`: уроки, `_notes-ru/`, эталонный код `Source/`) занимается другая
команда. Сегодня курс ведёт сессия «Лекции» в одном окне с «Архитектором» и «Сборкой»: правило 12 держит сообщения, правило 5
и ADR-0019 — паритет спек «в тот же день на обеих сторонах», рулевой паритета правит обе ведомости. С отдельной командой
«тот же день» и «та же сессия» не работают: у команды нет окна «Сборки», нет голоса «Архитектора» под рукой и, возможно,
нет дерева продукта. Владелец спросил, как взаимодействовать, и предложил файл обратной связи об ADR.

## Decision Drivers
* принципы (ADR-0001, 0002, 0003, 0012) должны держаться без человека, который помнит их наизусть
* одна сторона контракта (курс) не должна молча расходиться с другой (продукт)
* два коллектива не должны править одну строку одного файла: файл обратной связи один раз уже обрезался
* история вопросов и ответов должна оставаться в git, а не в чате

## Considered Options
* Один файл обратной связи об ADR, куда команда дописывает пункты, «Архитектор» отвечает рядом.
* Папка входящих `decisions/inbox/`: один файл на один вопрос, предложение или возражение, ответ в этом же файле.
* Чат или почта вне репозитория.

## Decision Outcome
Выбрана папка входящих.

1. **Канал — git репозитория курса.** Текст уроков, `_notes-ru/`, тесты курса команда вливает в main сама. Пути, которые
   сверяет паритет и граница — `Source/vms/*.subsystem.yaml` и остальные спеки, `Source/tests/testdata/spec_parity_debt.txt`,
   общие таблицы (`testdata/*.tsv`), `Source/w2cplatform/**`, три файла модуля консоли, — идут только веткой; «Архитектор»
   читает diff до слияния, как читает `platform:` коммиты продукта по правилу 14.
2. **ADR — контракт; `decisions/` для команды только на чтение.** Вопрос, предложение или возражение по ADR — один файл
   `decisions/inbox/<дата>-<слово>.md` по форме `decisions/inbox/README.md`: вид (вопрос / предложение / возражение), номера
   затронутых ADR, контекст до ста слов, своя рекомендация обязательна (как у нас в правиле 12). «Архитектор» отвечает
   разделом «Решение» в том же файле; принятое уходит в ADR или дополнение к нему (правило 8), отклонённое получает причину;
   после этого файл удаляется коммитом, история остаётся в git. Один файл — один вопрос, один коммит — один файл.
3. **Паритет через границу команд: курс кладёт первым.** Новое имя на проводе или диске команда кладёт в курс и пишет
   строку долга только в ведомость курса с хвостом `# ADR-NNNN «курс»`; продукт догоняет. Ночная сверка продукта против
   main курса краснеет — это находка для «Сборки», не для команды. Продукт первым кладёт ключ только с разрешения
   «Архитектора»; тогда «Сборка» правит в курсе одну ведомость, а команде в `inbox/` ложится задача «зеркалить ключ».
   Правило 5 «в один день» для курса читается так: ключ и строка долга в одном коммите.
4. **Ревью** остаётся по ADR-0052: по слову владельца, пробы в `РЕВЬЮ-SERVERVMS-N/probes/`, ответы команды —
   в разделе ответов отчёта, по находке хеш.
5. **Рефакторинг команды — сначала в курсе** (владелец 2026-10-11): предложение команды по рефакторингу она
   реализует в курсе сама, веткой; продукт догоняет силами «Сборки» после слияния. Принципы 1–4 этого решения действуют
   и там: имена, пересекающие провод или диск, идут со строками долга в ведомости курса и образуют список догона для
   продукта; diff по путям контракта читает «Архитектор» до слияния; нарушение ADR-0001/0002/0003/0012 — не рефакторинг,
   а вопрос в `inbox/`.
6. **Вход для команды** — страница `ДЛЯ-КОМАНДЫ-ЛЕКЦИЙ.md` в корне курса: принципы, что менять свободно, что веткой,
   что через `inbox/`, промпт команды; передача дел — `ХОД-Лекции.md`.

### Consequences
* Good, because каждый вопрос — свой файл и свой коммит: нет конфликтов на одной строке, нет потерянных пунктов.
* Good, because ответ лежит рядом с вопросом и уходит в ADR тем же путём, что и решения владельца.
* Good, because курс остаётся каноном (ADR-0019), а расхождение ловит та сторона, у которой есть оба дерева.
* Bad, because ответ приходит не в том же окне: команда ждёт коммита «Архитектора», а не реплики.
* Bad, because у «Сборки» прибавляется работа зеркалить ключи курса по красной сверке.

### Confirmation
Папка `decisions/inbox/` с README в main; страница `ДЛЯ-КОМАНДЫ-ЛЕКЦИЙ.md` в main; первый вопрос команды проходит путь
файл → «Решение» → ADR или отказ → удаление; ночная сверка продукта против main курса бежит каждую ночь.

байт того, что продукт положил первым: строки ведомости долга, три файла модуля консоли (`console.js`, `console.css`,

команде от «Архитектора» (зеркало продукта в курсе, например ADR-0068 после окна 2c) кладутся файлом во входящие вида
«задача», команда закрывает его коммитом с хешем; (3) общую папку курса подтягивает тот, кто запушил в main (правило 4).
Роли «Паритет» и «Консоль» на стороне курса переходят команде вместе с ролью «Лекции»; на стороне продукта остаются у
«Сборки» (правило 14).

## Дополнение 2026-10-12: каждая сторона пишет только своё дерево; сводит «Архитектор»
Владелец: команда курса пишет только курс, «Сборка» — только продукт, сводит «Архитектор» решениями и чтением diff. Доступ:

| Кто | Пишет | Читает сверх своего |
|---|---|---|
| команда курса | `server-vms-course` | продукт — только для зеркала по задаче из входящих (можно без доступа: форма в задаче) |
| «Сборка» | `vmssubsystem` | курс: `W2C_COURSE_DIR` для тестов сверки и загрузки, diff для зеркал |
| «Архитектор» | курс: `decisions/` и входящие, `ХОД-*`, §5a, строки ведомостей для ключей продукт-первым; кода нигде | продукт целиком |
| «Ревью курса» / «Ревью продукта» | только отчёт и пробы в своём репозитории | своё дерево; продуктовый — байты спек курса для сверки |
| «Ночной прогон» | `vmssubsystem/scripts/nightly/**`, своя коробка | закреплённый worktree курса |

Общие байты (ведомости долга, `testdata/*.tsv`, три файла модуля консоли) пишет только курс; продукт забирает их командой
`scripts/sync-course.sh <коммит курса>` («Сборка» после каждого пуша курса; копия байт в байт из указанного коммита, отказ
при грязном дереве, хеш курса в сообщении коммита). Ключ продуктом первым — с разрешения: форма «Архитектору» до кода, он
пишет строку в ведомость курса с хвостом `# ADR-NNNN «продукт»`, «Сборка» кладёт ключ и забирает байты. Узкое право
«Сборки» писать в курс (дополнение от 11.10) снято. Ревью разделяется на двух ревьюверов, каждый читает своё дерево
(ADR-0052 доп.). Общую папку курса подтягивает запушивший в неё. Правило 15 `СЕССИИ.md`.
