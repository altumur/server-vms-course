# Чтение между процессами это дверь по роли; строка-запрос только для изменения состояния

## Context and Problem Statement
Продукт: регистратор получает записанное устройством (карта камеры) строкой-запросом к держателю камеры (`worker: {requests: [vms]}`). Курс: регистратор читает это через дверь воспроизведения держателя по роли, без строк.

## Considered Options
* строка-запрос на каждое чтение;
* чтение дверью по роли, семейство `requests` только для изменений состояния (команда устройству, удержание, дозапись по просьбе человека с её учётом).

## Decision Outcome
Выбрано второе. Строка на каждое чтение грузит raft, несёт жизненный цикл (жнец, срок, учёт), которого у чтения быть не должно, а дверь держателя и так сериализует доступ к карте. У `rec` остаётся `worker: {reads: [...]}`; право на дверь даёт роль (группа сейчас, mTLS по таблице дверей позже). Группа консоли `w2c-console`, как у всех процессов платформы.

### Consequences
* Good, because хранилище не видит чтений, а роли дверей описаны в одной таблице.
* Bad, because дозапись с устройства в продукте переписывается на дверь держателя (шаг 6/7).

### Confirmation
В спеках нет `worker.requests` ради чтения; таблица дверей «Безопасности» называет роль для двери воспроизведения.
