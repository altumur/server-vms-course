# Строку, которую никто не разместил, убирает контроллер платформы по ключу спеки, а не воркер и не хозяйство подсистемы

## Context and Problem Statement
Класс системы: платформенная система.

Строка потока `live/streams/<cam>` живёт, пока её кто-то смотрит: первый зритель создаёт (`POST /live/streams {cam}`),
шлюз удаляет через `grace` после ухода последнего (ADR-0057, окно 2). Шлюз же убирает строку, которую никто не
разместил (`sweepUnplaced`, `vms/live.go:528`). В кластере без шлюза, или когда упал последний, убирать некому:
на стенде (cam-b) строка после `POST` стоит вечно с `worker: null`, тревога «не размещено» не гаснет («Сборка»,
2026-10-07). В курсе этой уборки нет вовсе.

«Сборка» предложила перенести уборку в хозяйство подсистемы (`vms jobs`, `ConsoleLoop`). Но «никем не размещено»
это знание размещения: его держит контроллер спеки (`Unplaceable`, `/unplaceable`), а хозяйство подсистемы
выводило бы его заново из строк и снимка — обратная утечка §3 того же рода, что `consolepass` (шаг 7 плана).

## Decision Drivers
* платформа знает только спеку (ADR-0001); смысл хука идёт в спеку, воркер или страницу (ADR-0002)
* умолчание, которое удаляет строки, выключено, пока спека его не включила (ADR-0012)
* одна форма у курса и продукта (ADR-0019), ключ сначала в продукте с долгом паузы (правило 13(в))
* подсистема не выводит размещение сама (§3, шаг 7)

## Considered Options
* Ключ спеки: строка, не размещённая дольше N секунд, удаляется контроллером этой спеки; без ключа — никогда.
* Уборка в `vms jobs` по снимку размещения («Сборка»).
* Оставить как есть: строка висит до появления шлюза, тревога «не размещено» и есть сигнал.

## Decision Outcome
Выбран первый вариант.

1. Спека объявляет под `placement`, через сколько секунд контроллер удаляет единицу, которую не держит ни один
   воркер; имя ключа и место — форма «Платформы» до кода (предложение: `placement.unplaced: {delete_after: <с>}`,
   целое, `minimum: 1`; без ключа удаления нет). Удаление делает контроллер спеки на своём проходе, той же дверью
   и журналом, что `UnplaceDeleted`, со строкой журнала «unplaced, deleted after N s».
2. `live.subsystem.yaml` объявляет ключ со значением `grace` (30 с) на стороне продукта; байт кладёт «Сборка» с
   хвостом `# ADR-0067 «Лекции» (пауза)`; курс берёт ключ и контроллер при догоне. У `vms`, `rec`, `auto` ключа
   нет: камеру, запись и сценарий без держателя никто не удаляет.
3. `sweepUnplaced` шлюза уходит тем же окном (ADR-0003): шлюз удаляет только строки, которые держал и у которых
   вышел `grace` зрителей. В `vms jobs` уборки нет.
4. Срок считается от момента, когда контроллер впервые увидел единицу без держателя (его часы, ADR-0049), а не от
   `rev` строки.

### Consequences
* Good, because в кластере без шлюза строка уходит через 30 с, тревога гаснет, курс и продукт получают одно правило.
* Good, because подсистема не выводит размещение сама; шлюз меньше знает.
* Bad, because у контроллера появляется право удалять строки спеки; оно включается только ключом и только для
  единиц без держателя, и видно в журнале.
* Bad, because до догона курса ключ есть только в продукте (строка долга паузы).

### Confirmation
* Продукт: тест контроллера — строка спеки с ключом без воркеров удаляется через N с и пишет журнал; та же строка в
  спеке без ключа стоит; строка, получившая держателя до срока, не удаляется.
* Загрузчик: ключ в `testsub`; спека с `delete_after: 0` или не целым — отказ.
* Стенд cam-b: `POST /live/streams {cam}` без шлюза — строки нет через 30 с, тревога «не размещено» гаснет.
* Курс при догоне: тот же тест на `Source/`, `spec_parity_debt.txt` без строки.

## Pros and Cons of the Options

### Ключ спеки, удаляет контроллер
* Good, because знание «не размещено» остаётся там, где оно есть; умолчание безопасное.
* Bad, because новый ключ и проход у «Платформы» посреди окон 17–18.

### Уборка в `vms jobs`
* Good, because быстро и только в коде подсистемы.
* Bad, because хозяйство подсистемы выводит размещение из строк и снимка — обратная утечка; курсу пришлось бы
  повторять ту же логику в `jobs.py`.

### Оставить
* Bad, because строка и тревога вечные в кластере, где шлюза нет по замыслу (стенд cam-b).

## More Information
ADR-0001, ADR-0002, ADR-0012, ADR-0019, ADR-0049, ADR-0057 (окно 2, п. 2). Исполняет «Платформа» (ключ, загрузчик,
контроллер) после формы; «Сборка» — байт спеки и снятие `sweepUnplaced` (`vms-for-<окно>`).

**Форма ключа (2026-10-07, «Платформа продукта», принята «Архитектором»).** `placement: {unplaced: {delete_after: <целое ≥ 1, секунды>}}`; без ключа удаления нет; `0`, дробь, отрицательное или лишний ключ под `unplaced` — отказ загрузки (ADR-0012). Контроллер помнит первый проход без держателя по своим часам; после рестарта отсчёт начинается заново (позже, не раньше). По сроку удаляет строку единицы CAS-ом тем же путём и журналом, что `UnplaceDeleted`, строка журнала `unit.unplaced_deleted {after_s}`. Право роли `<sub>controller` из спеки — `DeleteOnly` на `<sub>/<rows>/*`, только при ключе. `testsub` несёт ключ и тест. Курс при догоне берёт те же имена: ключ, строку журнала, право.

**Уточнение 2026-10-07 (окно 17, a2a1286).** Ключ `placement.unplaced.delete_after` рядом с `unit.derived` — отказ загрузки: производные строки пишет консоль по строкам другой спеки, и контроллер их не удаляет; удалять их может только тот, кто их выводит.
