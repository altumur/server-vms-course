# Секрет привязан к полю, для значения которого он задан (`bound_to`)

## Context and Problem Statement
Класс системы: система сбора с устройств. Пустой секрет при правке оставляет хранимый (иначе форма, где секрет не показывается, стирала бы пароль). Но камере, которой сменили источник на другое устройство, прежний пароль уходил новому устройству.

## Considered Options
* знать в коде, какое поле адрес (`source`), и проверять его;
* объявить в спеке, к какому полю привязан секрет (`bound_to`), и проверять платформой для любой подсистемы.

## Decision Outcome
Выбрано второе: `cred_secret: {type: string, bound_to: [source]}`. Правка, меняющая поле из `bound_to` (по сравнению со строкой, как она хранится), без нового секрета — отказ 400 с именами обоих полей; маска вместо секрета — отказ; при создании правило не действует. `/spec` отдаёт `bound_to`, страница просит пароль заново, как только сменили адрес. Тома держат то же правило для `access_secret` и адреса тома.

### Consequences
* Good, because пароль одного устройства не уходит другому ни при какой правке.
* Bad, because смена адреса без смены пароля требует вписать тот же пароль ещё раз.

### Confirmation
`TestASecretBoundToAnAddressIsNotKeptAcrossItsChange` (w2cplatform): четыре правки адреса без секрета отказаны, тот же адрес с пустым секретом и новый адрес с новым секретом приняты.
