# Этапы реализации урока — форма `forms/stages.tsv`

## Context and Problem Statement

README реализации урока (`spec/*.README.md`) содержит раздел «Order of work» — порядок работы для исполнителя. В P/01 это 7 шагов. Цикл MiniMax в попытках 15–16 вёл модель по вехам, которые «Архитектор» сам придумал в задании, а с этим порядком не сверил. Сверка показала три беды:
- шаг 1 — «Read the norms of the chapters in full». Модель исполняет его буквально и 80–100 ходов читает, хотя нормы уже лежат у неё в голове;
- у шагов нет проверяемого конца;
- демон, без которого не идёт приёмка 1.1, по README появляется только в главе 1.3.

## Decision Drivers

* Одни этапы для всех исполнителей: человека, линий Codex и цикла MiniMax.
* У каждого этапа — проверка конца, которую видит машина.
* Ранние этапы проверяются своими тестами, а не приёмкой: приёмке нужен готовый стенд.

## Considered Options

* Вехи в задании цикла — расходятся с уроком (попытки 15, 16).
* Проза «Order of work» — у шагов нет проверяемого конца.
* Таблица этапов урока, которую читает цикл, — выбран.

## Decision Outcome

1. **Форма** `forms/stages.tsv` урока (раскладка ADR-0124), рядом с README реализации. Форма ADR-0120 «таблица». Столбцы:
   - `n` — номер этапа по порядку;
   - `stage` — имя (латиница);
   - `goal` — цель одной строкой, по-английски;
   - `norms` — ссылки на разделы норм (номера и якоря английского источника);
   - `gate` — проверка конца закрытого вида:
     - `own_tests` — свои тесты реализации проходят, и среди них есть тесты этого этапа;
     - `build` — сборка профиля проходит;
     - `accept:<цель>>=<N>` — приёмка цели урока даёт не меньше N проверок;
     - `accept:<цель>:<сценарии>` — названные сценарии проходят целиком;
   - `budget` — ориентир усилия в ходах цикла (для людей — справочно);
   - `depends` — номера этапов, без которых этот не начинается.
2. **README «Order of work»** ссылается на таблицу и её не повторяет (как у таблицы проверок, ADR-0120 доп. (5) п. 5, ADR-0125 доп. (1) п. 5). Шаг «прочитать нормы целиком» уходит из этапов: чтение норм — общее правило исполнителя, а не этап.
3. **Первым этапом урока с демоном** идёт запуск: процесс стартует по профилю и отвечает на один маршрут (`accept:…>=1`). Раньше него — только этапы с `own_tests`.
4. **Цикл MiniMax** берёт вехи из `forms/stages.tsv` урока, а не из задания. Задание называет только урок, цели приёмки и пределы. Генератор вех — `loop.py`.
5. **Сверка.** `check_spec` судит форму: номера подряд, закрытый вид `gate`, цели приёмки — из описи урока, ссылки `norms` ведут на существующие якоря, `depends` — только на прежние этапы.
6. **Порядок и доли.**
   - P/01 — первым, после вливания перераскладки (ADR-0124), «Спецификация».
   - Затем уроки платформы по мере попыток.
   - VMS — «Спецификация VMS», когда до VMS дойдут попытки.
   - Цикл и сверка в `check_spec` — «Архитектор».
   - Ревью формы — review-claude и Codex.

### Consequences

* Хорошо: один порядок работы у всех исполнителей. Вехи цикла выводятся из урока. У каждого этапа есть машинный конец.
* Плохо: ещё одна форма на урок и её сверка.
* Предел: таблица не учит писать код. Она задаёт порядок и проверку, а `budget` — только ориентир.
