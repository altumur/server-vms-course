# Отладочный вход без пароля на стенде: человек по переменной, только с loopback, всегда на виду

## Context and Problem Statement

Система отлаживается на одной машине (ADR-0003). Двери консоли кластера и держателя домена спрашивают, кто пришёл,
как только домен установлен. Поэтому каждая проверка консоли на стенде начинается со входа под stand-admin.
Пароль приходится брать из `vms-macos/recovery/stand-people.txt`. Сессии Claude не могут ни ввести его, ни передать
токен в браузер: система разрешений режет это как утечку учётных данных. В итоге карточку домена на стенде не может
посмотреть никто, кроме владельца. Владелец (2026-10-05): закрывать вход при отладке реально не нужно; сделать так,
чтобы для отладки входить не требовалось.

## Decision Drivers

* отладка без пароля и без токенов в руках у сессий;
* проверяется тот же путь прав, что в бою: у отладочного человека его настоящие гранты, а не «всё можно»;
* умолчание, ослабляющее отсечение, выключено, пока его не включили явно (принцип владельца, ADR-0012);
* включённое ослабление не бывает тихим;
* ни одной ветки кода «если отладка — не проверять».

## Considered Options

* не устанавливать домен на стенде: дверь открыта, пока домен не установлен;
* долгоживущий токен в файле, который подхватывает браузер или прокси;
* переменная процесса `W2C_DEBUG_PERSON=<имя>`: запрос без токена, пришедший с loopback, — этот человек.

## Decision Outcome

Предлагается третий вариант.

- **Где.** Ворота двери (сессия консоли кластера, ворота держателя) читают `W2C_DEBUG_PERSON`. Переменная пуста или
  не задана — ничего не меняется; это умолчание.
- **Кто.** Задана — запрос без токена и без cookie сессии, у которого адрес соединения loopback (`127.0.0.1`, `::1`),
  судится как запрос этого человека с его грантами из `domain/grants`. Человека нет или он выключен — отказ,
  как без входа. Запрос с токеном судится по токену, как всегда. С любого другого адреса — как без переменной.
- **На виду.**
  - `GET /session` отдаёт `{user, debug: true}`, и модуль консоли рисует в шапке красную метку «отладка: вход без
    пароля».
  - Процесс при старте пишет в журнал платформы тревогу `session.debug_open` с именем человека.
  - Каждая правка с таким входом журналится с `debug: true`.
- **Где включено.** Только env стенда `vms-macos` (у «Сборки»). `install.sh` и юниты боевой установки переменную не
  задают.

### Consequences

* Good, because консоль стенда открывается сразу: и владельцу, и сессиям в браузерной панели — без пароля и токена.
* Good, because права проверяются настоящие: отладочный человек получает свои гранты, и отказ по правам виден так же,
  как в бою.
* Good, because включённое ослабление видно в шапке, в журнале и тревогой.
* Bad, because на стенде любой локальный процесс ходит в консоль как stand-admin; машина одна и своя, но это так.
* Bad, because loopback за обратным прокси на той же машине тоже loopback: стенд за таким прокси эту переменную
  ставить не должен.

### Confirmation

- Тесты ворот у «Платформы»:
  - без переменной запрос без токена — 401;
  - с переменной с loopback — человек с его грантами; с не-loopback — 401;
  - запрос с чужим токеном судится по токену;
  - выключенный человек — 401.
- Тест модуля: метка в шапке по `debug: true`.
- Тест деплоя: переменной нет нигде, кроме env стенда.

## Pros and Cons of the Options

### Не устанавливать домен на стенде

* Good, because кода не нужно.
* Bad, because на стенде пропадает всё, что проверяется только с установленным доменом: доверие, ключи, гранты,
  аварийный вход.

### Долгоживущий токен в файле

* Good, because ворота не меняются.
* Bad, because это учётные данные в файле, которые кто-то должен прочесть и передать; сессиям это не дают делать,
  и правильно.

### `W2C_DEBUG_PERSON` с loopback

* Good, because без учётных данных, с настоящими правами, на виду.
* Bad, because это новая ветка в воротах, и её нужно держать выключенной всюду, кроме стенда.
