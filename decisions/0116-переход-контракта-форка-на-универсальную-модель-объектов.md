# Переход контракта форка consolem на универсальную модель объектов: гибрид, этапы 0–5

## Context and Problem Statement

Класс системы: платформенная система (подсистемы VMS) с консолью — форком consolem; контракт форка закреплён по SHA-256.

Слово владельца 2026-11-03: «Напиши следующий ADR на переход на рекомендованный новый openAPI». Рекомендованный — это ответ «Консоли» команде consolem на запрос «универсальная модель объектов» (`cammeta-console/ОТВЕТ-КОМАНДЕ-УНИВЕРСАЛЬНАЯ-МОДЕЛЬ.md`): Р-1 А — гибрид с поправками, этапами; Р-2 В — подписи `{key, text, lang}`, словарь интерфейса главнее; Р-3 Б — `field` указателем на путях ядра; Р-4 Б — этапы 0–5, один закреплённый контракт на этап; Р-6 А — новая подсистема требует строк в манифесте `backend`. Р-5 (страница плагина) решён ADR-0115.

Сегодня контракт типизирован: 142 операции, из них 124 переводятся `backend` на подсистемы, 15 — `NO_ROUTE` (V/11.2); виды — закрытые перечисления `DeviceType`, `TreeNode.kind`; форма каждого вида написана в форке вручную. ADR-0115 уже вводит ядро для видов плагинов psim (`GET /kinds`, `/units` для `origin: plugin`). Этот ADR — весь переход: от ядра для плагинов до снятия старых путей.

Особенность w2c, которую модель consolem не предполагала: **вид ≠ подсистема**. Камера — это `cam` + `rec` + `det`; `ipsrv`, канал, хранилище устройства выводятся из таблицы `cam/devices`; датчики и единицы СКУД — строки таблиц (`VMS/11-backend/data/mapping.tsv`). Таблицы w2c — строки с ключом, своей версией и `If-Match`, а не «документ».

## Decision Drivers

* Слово владельца: переход на рекомендованный контракт.
* Слово владельца «всё до первой генерации» (ADR-0103 доп. (2)): все этапы — работа первой генерации, этапы — порядок, не отсрочка.
* На каждом шаге `backend` w2c проходит тесты API consolem в своём профиле (V/11.6) — иначе закрепление контракта по SHA-256 теряет смысл.
* Новое поле, таблица, подсистема без ручного экрана форка — главный выигрыш: поток запросов «добавьте поле» уходит в данные.
* Сборка камеры (`recordMode` ↔ строки `rec`, каскады, замок одним пакетом с `cas`) — смысл, а не форма: её модель не упраздняет.
* Платформу не трогать сверх ADR-0115 (загрузчик манифеста), если без этого можно.

## Considered Options

1. **Гибрид этапами 0–5 (выбрано, Р-1 А, Р-4 Б).** Ядро модели рядом со старыми путями; каждый этап — новый закреплённый контракт; старые пути снимаются последним этапом.
2. **Порядок команды** (ядро рядом → WebUI по разделам → права → удаление). Отличие — нет отдельного этапа «только чтение» и «профили известных видов»: запись и перевод экранов идут вместе, риск для сборки камеры выше.
3. **Только ядро на чтение** (Р-1 Б): запись остаётся типизированной. Выигрыш «поле без экрана» тогда только для показа.
4. **Остаться на типизированном контракте** (Р-1 В). Каждый новый вид и поле — запрос команде и ручной экран.

## Decision Outcome

Выбран вариант 1.

### 1. Модель видов w2c

1. **Таблица видов `backend`** — данные, а не нормы: `kind` → из чего собран (подсистема и `unit`, или таблица, или сборка нескольких подсистем), профили, действия, события. Её строит `backend` из манифестов подсистем по правилу перевода манифеста; сборные виды (камера) — строкой сборки. Закрытая таблица видов V/11.3 Н1.2 заменяется этой таблицей.
2. **Сборные виды** — профилем: камера — вид `vms.camera/1`, его `PATCH /units/{uid}` `backend` пишет одним пакетом с `cas` по всем частям, как сейчас пишет камеру (V/11.4). `version` сборного вида — версия по всем его частям.
3. **Строки таблиц** — виды с `uid` = `<sub>/<таблица>/<ключ>`, своей версией и `If-Match`; не «документ».
4. **`kinds.changed`** у w2c — перезапуск после смены манифеста (P/02.3), клиент видит `stream.reset` и перечитывает `/kinds` по `ETag` (ADR-0115 доп. (5) п. 1).

### 2. Договорённости (этап 0)

1. `Problem.field` — JSON Pointer на путях ядра; на старых путях — имя поля, пока их не снимут (Р-3 Б). `errors[]`, `VALIDATION_FAILED` с `params.keyword`.
2. Подписи — `label {key, text, lang}` по `Accept-Language`; интерфейс ищет `key` в своём словаре и берёт `text`, только если ключа нет (Р-2 В). У w2c тексты подсистем — из `display` манифеста и `display.langs` (ADR-0115 доп. (2)).
3. `version` — непрозрачная строка для `If-Match`; у вида из одной строки — её версия, у сборного — свёртка версий частей.
4. `status` — раздельно «задано» (`properties`) и «наблюдается» (`status.observed`, `conditions`, `observedVersion`); у w2c «наблюдается» — `state` и пульс.
5. `TreeNode.kind`, `StreamMessage.kind` — открытые строки; незнакомое значение клиент показывает, а не роняет.

### 3. Этапы

| Этап | Что | Что `backend` w2c должен пройти |
|---|---|---|
| 0 | договорённости п. 2 | прежние тесты API в профиле; новые поля не ломают старые пути |
| 1 | ядро только на чтение: `GET /kinds`, `/kinds/{kind}`, `GET /units`, `/units/{uid}`, `/units/{uid}/schema`; незнакомый вид показывается | все виды w2c видны через `/units`, схемы — по правилу перевода манифеста |
| 2 | запись для видов без профиля: `POST`, `PATCH` (Merge Patch + `If-Match`), `DELETE /units`, `actions/{a}`, `validate`, шаги `/operations` по `uid`; строки таблиц w2c; виды плагинов ADR-0115 | набор `test.unknown` и строки таблиц w2c пишутся через ядро |
| 3 | профили известных видов: `vms.camera/1`, `vms.archive/1`, `vms.server/1` и прочие из таблицы видов; ручные экраны форка — на профили; старые пути живы | сборка камеры через `PATCH /units/{uid}` даёт те же строки, что старый путь |
| 4 | права и правила: `accessLevels` вида, `objectAccess`, `kindAccess`; события и действия правил — из описаний видов | перед этапом — отдельный ADR об области гранта «по виду» |
| 5 | снятие старых путей, `DeviceType`, плоского `Device`, `Role`/`RoleGlobal` кодов | `backend` проходит тесты этапов 1–4; V/11.2 — судьбы снятых операций |

На каждом этапе — один новый закреплённый контракт (`consolem.openapi.json` + SHA-256), а не на коммит.

### 4. Кто что делает

* Контракт и тестовый сервер в форке — мы (altumur), как сейчас.
* Построитель формы по схеме в WebUI — команда consolem; `index.html` — обе стороны.
* Курс: V/11.2 (судьбы операций по этапам), V/11.3 (таблица видов вместо закрытого перечня), V/11.4 (запись через ядро, сборка камеры профилем), V/11.8 (перечни), V/11.13 (ассистент: виды и поля из описаний), новая глава V/11 «перевод манифеста в описание вида»; `mapping.tsv` → таблица видов и профили; V/11.6 — профиль тестов на каждый этап.
* Платформа — без правок сверх ADR-0115 (ключи загрузчика). Этап 4 может потребовать области гранта «по виду» в правах платформы — это решит отдельный ADR до этапа 4.

### 5. Оценка объёма

| Слой | Объём |
|---|---|
| Курс, V/11 (2, 3, 4, 8, 13, новая глава) и `mapping.tsv` | большой: переписываются 4 главы, одна новая; 624 строки `mapping.tsv` сводятся к таблице видов и правилу |
| Контракт форка и тестовый сервер | большой: ~12 операций ядра, договорённости этапа 0, пять закреплений |
| WebUI форка | большой у команды: построитель формы, перевод ручных экранов на профили |
| `backend` (реализация) | большой: ядро поверх существующего перевода; сборка камеры сохраняется |
| Платформа | нет (кроме ADR-0115 и, возможно, ADR этапа 4) |

### Consequences

* Хорошо, потому что новое поле, таблица и подсистема — без ручного экрана и без запроса команде: около 24 из 42 прошлых запросов уходят в данные.
* Хорошо, потому что плагины psim (ADR-0115) и виды VMS ложатся на одно ядро.
* Плохо, потому что переход большой и идёт в первой генерации; пять закреплений контракта — пять проходов тестов API в профиле.
* Плохо, потому что сборка камеры остаётся смыслом `backend`: адаптер w2c тоньше не станет, станет тоньше только новое.
* Нейтрально: старые пути живут до этапа 5, поэтому клиент без перевода продолжает работать на этапах 0–4.

### Confirmation

* На каждом этапе: тесты API consolem в профиле w2c зелёные на новом закреплённом контракте (V/11.6).
* Этап 1: незнакомый форку вид виден в списке и в карточке.
* Этап 2: строка таблицы w2c и вид плагина пишутся через `/units` с `If-Match`, ошибка ложится под поле по указателю.
* Этап 3: `PATCH /units/{uid}` камеры и старый путь дают одинаковые строки `cam`, `rec`, `det`.
* Этап 5: ни одна операция не осталась без судьбы в V/11.2.

## Дополнение (2), 2026-11-03 — ревью (0): review-claude (`РЕВЬЮ-ADR-0116-Claude.md`), Codex (`РЕВЬЮ-ADR-0116-Codex.md`); решения «Архитектора»

1. **`kinds.changed` (review-claude С1).** Новое поле подсистемы VMS `backend` не перезапускает, поэтому «`kinds.changed` = перезапуск» верно только для плагинов. Для всех видов: `ETag` `/kinds` — ревизия каталога манифестов, событие `kinds.changed` в потоке событий при её смене; клиент перечитывает `/kinds` по нему и при переподключении. §1 п. 4 заменяется этим.
2. **`uid` (Codex С1, review-claude М1).** `uid` уникален в домене и стабилен. У объекта со старым id — тот же id (`Device.id` сборного вида — его `uid`): перевода ссылок нет. У строки таблицы без старого id — `<кластер>:<sub>/<таблица>/<ключ>`, обратимо в адрес строки; одинаковые ключи в разных кластерах не сливаются.
3. **Что публикуется видом (Codex С2).** Правило — до этапа 1: служебные таблицы (`backend/undo` и подобные) — не виды; таблицы воркера (наблюдаемые) — только чтение и `status`; временные предметные данные (поиск, задания) — на своих путях; таблицы с каскадом или частью сборки (`rec/volumes` и подобные) — без независимой записи в обход перевода `backend`. Возможность записи сервер судит с этапа 2, не ждёт `kindAccess` этапа 4.
4. **Этап 5 (Codex С3).** Снимается только типизированный CRUD (`Device`, `DeviceType` и прочие формы «создать, изменить, удалить»). Предметные операции — просмотр, PTZ, архив, выгрузка и подобные — остаются и с этапа 3 принимают `uid`. Снятие операции — только после проверенной замены каждого её сценария; приёмка этапа 5 — сквозная: просмотр, PTZ, архив, права, правила; прежнее покрытие тестами переносится, а не исключается.
5. **Чужой кластер (review-claude М2).** `/units` камеры чужого кластера без связи — тот же `409 SERVER_OFFLINE`, запись держится, как на старых путях.
6. **М (Codex).** `kind` камеры VMS — `vms.cam`, `implements: [vms.camera/1]`; виды камер плагинов — свои `kind` с тем же профилем. Закреплений контракта — шесть: этап 0 — своё.
