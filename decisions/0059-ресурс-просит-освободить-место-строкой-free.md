# Ресурс просит освободить место строкой `free-<сервер>-<том>`; подсистема говорит `freeing`

## Context and Problem Statement
Класс системы: платформенная система.

Ресурс сервера держит тома в пределах отметок места (`space`: `high`, `low`). Освобождать байты может только подсистема,
которая их записала: только она знает, какие её файлы где. Раньше ресурс звал хук подсистемы (`Freer`, `VolumeFreer`),
и это шло против границы (ГРАНИЦА §4, ADR-0002). Теперь ресурс просит строкой просьбы, а подсистема отвечает в биении.

Проход ресурса меряет том заново. Байты, которые подсистема уже освободила и том их показывает, ушли из `used`. Вычитать
их ещё раз из свежего `need` — двойной счёт (нашла «Сборка»). Но освобождение может отставать: движок хранилища ещё не
отдал место, файл удалён и ещё открыт. Тогда `statvfs` к следующему проходу ничего не показывает. Если не вычитать ничего,
ресурс снова попросит те же байты, и подсистема удалит больше, чем нужно.

## Decision Drivers
* ресурс не исполняет код подсистемы (ГРАНИЦА §4, ADR-0002)
* просьба не повторяется, пока освобождение в пути: лишнее не удаляется
* то, что уже видно на томе, не вычитается дважды
* строка, которую ресурс перестал писать, не живёт вечно

## Considered Options
* Подсистема говорит `freeing` — удалено и ещё не видно на томе; ресурс вычитает только его.
* Подсистема говорит `freed` — сколько дала с прошлой просьбы; ресурс вычитает его из свежего `need` (как было).
* Ресурс ничего не вычитает из свежего `need`.

## Decision Outcome
Выбран первый вариант. Это единственный, который верен и с отставанием, и без него.

**Форма.**
- Каждой спеке с `requests: {free: true}`, пока том выше `high`, ресурс пишет строку `<sub>/requests/free-<сервер>-<том>`
  `{free, volume, server, at}`, где `free` — байты до `low`.
- Форма строки платформенная (`IsFreeRequest` / `is_free_request`): не через дверь и не через базу воркера, схема
  семейства её не касается. Держатель её не исполняет и не метит.
- Под отметкой строка снимается. Строку, которую ресурс перестал писать (ресурс молчит), заканчивает жнец по `ttl`
  семейства.

**Ответ.** Воркер подсистемы на этом сервере говорит в биении `freeing: {<том>: байты}`: что он удалил, а том ещё не
показывает. Где отставания нет, `0`. Слова `freed` нет, алиаса нет (ADR-0003).

**Проход.** `need = used − total·low − freeing`, не ниже нуля. Ресурс просит `need`. Если `need` 0 при томе выше
отметки (всё в пути), строка снимается: ничего не просят снова.

### Consequences
* Good, because при отставании просьба не повторяется, и видео сверх нужного не удаляется.
* Good, because без отставания вычитания нет: просьба — то, что том показывает сейчас.
* Good, because ни одного хука подсистемы в ресурсе, а форма строки одна на все подсистемы.
* Bad, because подсистема обязана знать своё отставание: движок, который не говорит, сколько в пути, заставит считать его
  самой. Ошибётся вверх — ресурс недопросит, том подержится выше отметки дольше.
* Bad, because слово в биении меняется без алиаса: рекордер и ресурс выкатываются одним окном.

### Confirmation
* Продукт: `TestTheWatermarkAsksAndNeverDeletes` (`w2cplatform/lesson1_platform_test.go`) — просьба до `low`; с
  отставанием просит остаток; всё в пути — строка снята при томе выше отметки; без отставания просьба — свежая мера;
  слово вместо числа — 0, сказано.
* Курс: то же у «Лекций» в `relieve`.
* Рекордер продукта говорит `freeing` («Сборка», окно `resource-free`).

## Pros and Cons of the Options

### `freeing`
* Good, because верен в обоих случаях.
* Bad, because требует от подсистемы знать отставание своего движка.

### `freed`, вычитать из свежего `need`
* Good, because так уже было.
* Bad, because без отставания двойной счёт: просьба меньше нужного, том держится выше отметки.

### Ничего не вычитать
* Good, because проще всего.
* Bad, because при отставании ресурс каждый проход просит те же байты заново, и подсистема удаляет лишнее.
