# Папки как записи консоли кластера: строка на папку, состав по порядку, обратное членство единицы, версия — индекс строки; поле `cam.folders` уходит без переноса

## Context and Problem Statement
Класс системы: платформенная система (консоль кластера). Потребители — подсистема VMS `backend` (ADR-0094 A) и модуль
консоли платформы.

Ссылки вида `openapi:N` — строка N файла `VMS/11-backend/consolem.openapi.json` (закреплённый коммит consolem
`ef7175b`, V/11.2 Н1.1). «Разбор» — `decisions/inbox/2026-10-30-ревью-ADR-0095-0096-разбор.md`.

Что контракт consolem требует от папки:
- Запись `Folder` (`openapi:5035`): `id`, `name`, `domainId`, `parentId` (`null` — корень домена, `openapi:8614`),
  `deviceIds` — «Устройства папки по порядку; одно устройство может быть в нескольких папках» (`openapi:5058`),
  `version` — непрозрачная, меняется при любом видимом изменении, к прежнему не возвращается, без изменений не меняется
  (`openapi:5067`); «Папка физического расположения» (`openapi:5079`).
- `GET /folders`, `POST /folders` (`openapi:1028`); создание `FolderCreate` — `name`, `domainId`, `parentId`
  (`openapi:8592`–`8617`); ответы 201, 404, 422 (`openapi:1083`–`1101`) — **409 и 412 нет**.
- `GET`, `PATCH`, `DELETE /folders/{id}` (`openapi:1113`). Правка `FolderPatch` — только `name` и `deviceIds` целиком
  (`openapi:8575`–`8590`, `additionalProperties: false`): **родителя правкой не сменить**. `If-Match` обязателен
  (428 без него, 412 при расхождении).
- Удаление — «Удалить папку с подпапками; устройства остаются» (`openapi:1235`); групповое `POST /objects/delete`
  удаляет и «папки (с подпапками)» (`openapi:9760`).
- Удаление устройства «Убирает его из папок» (`openapi:985`) — то есть меняет `deviceIds` и версию папок.
- Создание устройства кладёт его в папку: `folderId` элемента `POST /devices` (`openapi:9558`), в ответе — «Папки, куда
  оно легло» (`openapi:9605`). Шаг операции `folderIds` — «Папки устройства целиком, по порядку» (`openapi:8254`).
- Права consolem по папкам: `folderAccess` — «Права на папки «Оборудования»: id папки или домена (корень) → поля»
  (`openapi:6165`). Правила адресуют папку как область (`RuleTarget`, `openapi:10306`).
- В записи `Device` поля папок нет: состав живёт только в `Folder.deviceIds`.

Что у нас сейчас:
- Папка — путь в поле-списке камеры `cam.folders` (`VMS/01-cam/cam.subsystem.yaml:212`): «A folder exists NOWHERE in the
  store… there are no empty folders… renaming one means rewriting the path on every camera under it»
  (`cam.subsystem.yaml:187`–`189`); уровни через `/`, камера в нескольких папках (`:184`); папка ничего не наследует и не
  несёт прав (`:195`–`197`). Список папок, которые предлагает страница, — общие настройки домена `shared: folders`
  (`cam.subsystem.yaml:433`–`436`).
- Модуль строит дерево по полю `display.tree.group_by` с `nested_by` (`Platform/06-console/spec/06.5-console.norms.md:106`);
  переименование группы переписывает поле у всех единиц (`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md:188`); пустая группа живёт в
  браузере (`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md:192`).
- У `backend` все пять дверей папок — 404 `NO_ROUTE` (V/11.2 № 21–25, `VMS/11-backend/spec/11.2-backend.norms.md:70`–`74`),
  `folderId` создания не `null` — `NOT_SUPPORTED` (V/11.3, `VMS/11-backend/spec/11.3-backend.norms.md:59`).
- Единицу удаляют не только дверью: у `det` объявлен срок `ends` (`VMS/04-det/det.subsystem.yaml:78`), и строку снимает
  контроллер (P/06.1 Н1.1).
- ADR-0003 (обратная совместимость не держится) запрещает миграции и двойное чтение старых форм.

Чего не хватает: у пути нет `id`, версии и порядка устройств; пустой папки нет; переименование — не одна запись, а
правка всех камер, и это не укладывается ни в «412 — ничего не изменилось», ни в предел пакета B9. «Консоль» назвала
это так же (`/Users/murat/w2c/cammeta-console/АДАПТЕР-CONSOLEM.md:59`, `:105`–`108`).

## Decision Drivers
* Контракт: `id`, порядок `deviceIds`, пустые папки, вложенность, версия с `If-Match` и 412.
* Состав папки — устройства **двух** подсистем: камеры `cam` и детекторы `det` (ADR-0094 A6; V/11.3).
* Права по папкам (`folderAccess`) — будущая область гранта; функция `may` — платформенная (`Platform/common/contracts/may.md`).
  Это решает ADR о ролях и группах (ADR-0094 C3), но место папки должно его не закрыть.
* Удаление единицы дверью убирает её из всех папок тем же пакетом и меняет их версию; пакет удаления ограничен.
* Ни цикла, ни воскрешения поддерева, ни записи под удалённой ветвью.
* Одна правда: папка не живёт и в поле камеры, и в записи; миграций нет (ADR-0003).
* Модулю консоли нужно то же: пустая папка на сервере, переименование одной записью.

## Considered Options
* **(а) Папка — строка консоли кластера (`platform/folders/<id>`): общая иерархия для единиц любых подсистем кластера,
  состав по порядку в строке папки, обратное членство — в строке единицы.**
* (б) Таблица подсистемы: `cam/folders` (или `backend/folders`) — строки манифеста, со ссылкой на папку у камеры или
  составом в строке папки.
* (в) Метки вместо папок: папка — метка единицы, права — уже готовые гранты `labels:L`.
* (г) Как сейчас: пути в `cam.folders`, `backend` собирает `Folder` из путей.

## Decision Outcome
Выбран вариант «(а)», потому что состав папки — единицы двух подсистем, удалять из папок должна консоль при любом
удалении единицы, а будущий грант по папке может проверить только платформа. Строка на папку даёт контракту `id`,
порядок, пустую папку и версию без сборки: версия — индекс одной строки. Все три ревьюера выбор подтвердили (разбор,
вступление). (б) делает папку знанием VMS, которого модуль и `may` не видят, а удаление детектора `det` — записью в
чужую таблицу `cam`. (в) смешивает группировку с размещением: метки камеры сверяет `labels-subset`
(`cam.subsystem.yaml:173`–`179` объясняет, почему папки — не метки), и у метки нет `id`, порядка, вложенности и версии.
(г) не даёт ни порядка, ни версии, ни пустой папки.

### 1. Строка папки и строка членства
- **Папка** — ключ `platform/folders/<id>`, писатель — консоль кластера. Поля: `name` (непустое), `parent` (`<id>`
  родителя или пусто — корень кластера), `members` — ссылки на единицы `<sub>/<rows>/<id>` по порядку, без повторов.
  Единица может быть в нескольких папках (`openapi:5058`).
- **Id папки не повторяется никогда** (разбор, Г18): 128 случайных бит или счётчик с учётом надгробий — форма в норме
  P/06. **Запись поверх надгробия папки — отказ**: исключение из ADR-0094 доп. (3) п. 9 для `platform/folders`.
- **Обратное членство** (разбор, А4 (а)) — ключ `platform/memberof/<sub>/<rows>/<id>` (рабочее имя), список папок
  единицы; писатель — консоль. Каждая запись состава (`PUT` папки, `folderId` создания, шаг `folderIds`, жнец) меняет с
  `cas` строку каждого добавленного или снятого члена **в том же пакете**. Удаление единицы читает её, а не все папки
  кластера.
- Единица — не больше чем в `FOLDERS_PER_UNIT_MAX` папках; сверх — 400 (у `backend` — 422 `VALIDATION_FAILED`). Число
  нормы с обязательством: наибольший каскад удаления вида плюс строки его папок и членства укладываются в предел пакета.
- Версия — индекс хранилища строки папки (B4: `ETag` — индекс). Подпапки в строке родителя не записаны, поэтому новая
  подпапка версию родителя не меняет — у `Folder` нет списка детей.
- Уникальности имени среди соседей нет: контракт не даёт 409 у создания (`openapi:1083`–`1101`).
- Наследования нет: папка группирует и ничего не несёт (как сейчас, `cam.subsystem.yaml:195`–`197`). Права по папке —
  ADR-0094 C3.
- **Кто может быть членом** (разбор, Г16): подсистема объявляет в манифесте таблицы, чьи единицы бывают членами папок (тот
  же ключ дерева P/02.1, §8). Ссылка на единицу иной таблицы — 400 у двери консоли. Так платформа не знает видов VMS, а у
  VMS членами бывают только `cam/cameras` и `det/units`.

### 2. Вложенность, циклы, цепочка до корня
- Родитель задаётся только при создании; правки родителя нет ни в контракте (`openapi:8575`–`8590`), ни у двери
  консоли. У новой папки нет потомков при создании, родитель задан навсегда и старше неё. Вместе с неповторимым id и
  отказом записи поверх надгробия ни цикл, ни воскрешение поддерева не возникают.
- **Цепочка до корня** (разбор, решение 5; Г17). Всякая запись папки — создание, имя, состав, удаление — и запись членов из
  чужого пакета (`folderId` создания устройства, шаг `folderIds` ADR-0095) читает цепочку предков до корня. Предок
  отсутствует или стоит надгробие — 404 (нет строки) или 409 (надгробие); в пакет записи идут **стражи на каждую строку
  цепочки** по прочитанному индексу. Предка удалили одновременно — 412, ничего не записано. Иначе запись в папку под
  удаляемым предком отвечала бы 200.
- Глубина — не больше `FOLDERS_DEPTH_MAX`. Связь `FOLDERS_DEPTH_MAX + 1 ≤ предела строк пакета` норма называет рядом с
  обоими числами (разбор, Г19 М-10).
- Перенос папки к другому родителю — не делаем, пока его не требует контракт.

### 3. Удаление непустой папки
- `DELETE` папки снимает её строку (`cas` по `If-Match`) и строки членства её членов с `cas` — одним пакетом. Подпапки с
  этого мига недостижимы: чтение отдаёт только папки, у которых вся цепочка предков жива, поэтому `GET` подпапки — 404,
  `PATCH` — 404. Снаружи удаление поддерева атомарно при любом его размере.
- Недостижимые строки и членство их членов снимает жнец — новая работа жнеца консоли P/06.4 Н3 с периодом в норме (не
  `sweep` P/06.1 Н1.5: тот снимает только в окне обслуживания).
- Устройства остаются (`openapi:1235`): папка — не владелец единиц.
- `backend` (V/11.5), получив удаление папки, сам отдаёт `entity.deleted` её потомкам, которые были достижимы до удаления
  (дерево он знает из своего чтения); лента B2 не меняется.

### 4. Состав и удаление единиц
- `PATCH` состава — список целиком (`openapi:8575`–`8590`). Член — живая единица объявленной таблицы в момент записи;
  ссылки на единицу, которой нет, — 400; повтор в составе — 400 (у `backend` — 422 `VALIDATION_FAILED`,
  `field: deviceIds`).
- **Удаление единицы дверью консоли** (одиночное и пакетом B9) читает её строку членства и кладёт в тот же пакет её
  снятие с `cas` и строки её папок с `cas`. Так версия папки меняется вместе с составом (`openapi:985`, `openapi:5067`), а
  папка, в которую единицу добавили после чтения, ловится `cas` строки членства (разбор, А4).
- **Права следствий** (разбор, Г15; решение владельца В6). Строки папок и членства, которые консоль сама добавляет в пакет
  удаления единицы, проверяются правом удаления этой единицы, а не правом записи папки. Иначе человек с `edit` на камеру
  без `admin` не удалил бы камеру, лежащую в папке. Правило частное — только для снятия члена при удалении; общее правило
  B9 «право по каждой строке» не меняется.
- Добавление в папку (`folderId`, шаг `folderIds`) меняет папку по воле человека — правом записи папки (§6).
- Удаление мимо двери (контроллер по `ends` или `delete_after`, воркер по `worker.deletes`, P/06.1 Н1.1) оставляет
  висячего члена; жнец убирает его и строку членства следующим проходом. Второго писателя семьи (контроллер) не вводим:
  один писатель на ключ. До прохода чтение отдаёт член как есть («Запрос продукту», п. 2).
- Состав из многих членов пишет консоль собственным пакетом: его ограничивает вес (`-max-body` хранилища), а не 64
  строки двери B9 (ADR-0095 §2, разбор А1). Шаг `folderIds` операции и `folderId` создания устройства — пакет B9 со
  строками затронутых папок, членства и стражами цепочек; новый член встаёт в конец списка папки.

### 5. Двери, версии, лента, память
- Двери консоли (рабочие имена, точные — норма P/06): `GET /folders`, `POST /folders`, `GET`, `PUT`, `DELETE
  /folders/<id>`. Сегмент `folders` и семья `memberof` — в перечень запрещённых имён `unit.rows` и таблиц (P/02.1 Н1.2а),
  а `folders` — и в запрещённые имена подсистем (P/02.1, таблица ключей): двери единиц `/[<sub>/]<rows>/<id>` и статика
  `/<sub>/<файл>` совпали бы с `/folders/<id>` (разбор, Г19 М-8).
- `If-Match` и 412 с текущей строкой (B4), память `Idempotency-Key` на записях (B3), коды и `field` (B5).
- Строки папок — в охвате ленты `/changes` (B2); сообщение об удалении несёт индекс надгробия (ADR-0094 доп. (3) п. 9).
- Пакетная дверь B9 принимает строки папок и членства рядом со строками единиц: так `backend` пишет устройство и его
  папки одним пакетом.
- Перечень обратного вызова `backend` (B1) пополняется дверями папок.

### 6. Права (до ADR-0094 C3)
- Чтение — право `view` без единицы (`may` шаг 6, `Platform/common/contracts/may.md:52`): папки видит всякий, у кого есть
  хоть одна строка гранта. Ссылки на всех членов папки видны обладателю гранта без фильтра по `view` единиц — это
  политика продукта, а не временная защита (решение владельца В6); иначе версия менялась бы от правок, которых читатель
  не видит.
- Запись папки — `admin` на `*` (решение владельца В6).
- Снятие члена при удалении единицы — правом на единицу (§4).
- Стык с C3: грант с областью `folder:<id>` (покрывает членов папки и её подпапок) — дело ADR о ролях и группах. Это
  решение даёт ему то, что нужно: папка и членство — строки платформы, цепочку предков читает консоль.

### 7. Что делает `backend`
- `Folder.id` — UUID v5 места строки по правилу V/11.4 Н1.6 (`VMS/11-backend/spec/11.4-backend.norms.md:200`–`205`),
  новый вид `folder`; `domainId` — наш кластер; `parentId` — id родителя или `null`; `deviceIds` — члены, переведённые в
  id устройств (член `cam/cameras/<id>` — камера, `det/units/<id>` — детектор).
- **Скрытые члены** (разбор, Г16). Потоки — строки `cam/cameras` с непустым `main` — отдельными устройствами не отдаются
  (V/11.4 Н1.1), поэтому в `deviceIds` их нет. При переводе `PATCH` `backend` сохраняет таких членов на прежних местах
  относительно видимых; правило слияния — V/11.4 («Спецификация VMS»). Смена `Folder.version` от правки скрытого члена —
  ограничение, его записывает V/11.4.
- Отказ консоли из-за цепочки (предка нет, надгробие, 412 стража цепочки) `backend` переводит в 404 `NOT_FOUND`: у
  `POST /folders` в контракте есть 404, а 412 и 409 нет (разбор, решение 5).
- Пять дверей папок, `folderId` в `POST /devices` и папки в `POST /objects/delete` — «переводится» (V/11.2, V/11.4 —
  «Спецификация VMS»).

### 8. Уход `cam.folders` — без переноса
- Поле `cam.folders` и `shared: folders` домена уходят **без переноса**, стенды переустанавливаются (решение владельца В4;
  разбор, Г13). Команда переноса — миграция, а поле «только для чтения» — двойное чтение; ADR-0003 запрещает оба. Перенос,
  если понадобится, — сначала дополнение ADR-0003 о первой подлинной установке, затем правило переноса.
- Модуль строит дерево по папкам платформы; ключ манифеста, которым подсистема это просит и называет таблицы членов, —
  P/02.1, P/06.5 («Спецификация»).
- Правка урока V/01 (`cam.subsystem.yaml`, комментарии `:173`–`212`, `:433`–`436`) — «Спецификация VMS».

### 9. Порядок
1. Нормы и код — отдельным приращением **после зачёта приращения B** (ADR-0094 B1–B9), не раньше: решение стоит на B2,
   B3, B4, B5, B9.
2. Раньше ADR-0095: шаг `folderIds` операции ждёт папок.
3. Платформа — «Спецификация»: P/06 (семьи папок и членства, двери, цепочка до корня, удаление из папок при удалении
   единицы, права следствий, жнец), P/02.1 (запрещённые имена, ключ манифеста дерева и таблиц членов), P/07 (дерево
   модуля), P/01.1 не правится.
4. VMS — «Спецификация VMS»: V/01 (уход `cam.folders` и `shared: folders`), V/11.2–V/11.5 (папки, скрытые члены,
   `entity.deleted` потомков), `profile.tsv`, строки файла 28–32 — `in`.
5. Запрос продукту — одним письмом с ADR-0095 через «Консоль», отправляет владелец.

### Consequences
* Good, because контракт получает всё из записи: `id`, порядок, пустые папки, версию — индекс одной строки, 412 —
  «ничего не изменилось».
* Good, because переименование — одна запись вместо правки всех камер; пустая папка живёт на сервере, а не в браузере.
* Good, because удаление единицы дверью снимает её из всех папок тем же пакетом, читает одну строку членства, а размер
  пакета ограничен `FOLDERS_PER_UNIT_MAX`.
* Good, because ни цикла, ни воскрешения поддерева, ни записи под удалённым предком: родитель навсегда, id не
  повторяется, цепочка до корня стоит стражами.
* Good, because папки общие для подсистем кластера, и будущий грант по папке ляжет на платформенную строку.
* Bad, because у консоли две новые семьи, двери, цепочка стражей на каждой записи и ещё одна работа жнеца.
* Bad, because каждая правка состава пишет ещё строки членства всех добавленных и снятых единиц.
* Bad, because поле `cam.folders` уходит без переноса: папки работающих стендов теряются, стенды переустанавливаются.
* Bad, because ссылки на единицы, которых читатель не видит, видны в составе папки.
* Bad, because единица не может лежать больше чем в `FOLDERS_PER_UNIT_MAX` папках.
* Neutral, because правка скрытого члена (потока) меняет `Folder.version` без видимой перемены.
* Neutral, because папки — на кластер (`domainId` consolem — наш кластер, ADR-0094 A6); общих папок домена после
  ухода `shared: folders` нет до отдельного решения.

## Pros and Cons of the Options

### (а) Строка консоли кластера
* Good, because члены — единицы любых подсистем; удаление единицы и состав папок — в руках одной консоли.
* Good, because модуль и будущий `may` по папке читают одну и ту же строку.
* Good, because версия — индекс строки, без сборки.
* Bad, because правка платформы: две семьи, двери, цепочка стражей, жнец, запрещённые имена.
* Bad, because уход `cam.folders` без переноса — потеря папок у установленных стендов.

### (б) Таблица подсистемы `cam` или `backend`
* Good, because правится только VMS: таблица манифеста, двери таблиц уже есть (P/06.1 Н1.6).
* Neutral, because состав в строке папки даёт порядок; ссылка у камеры (поле со списком папок) порядка в папке не даёт,
  а версия папки тогда — сборка из строк всех её камер.
* Bad, because удаление детектора `det` должно править таблицу `cam` — запись в чужую подсистему; у `backend/folders`
  её не сделает консоль при удалении единицы модулем.
* Bad, because модуль консоли общий и строку подсистемы как папку не понимает, а `may` по папке из таблицы подсистемы
  — платформа, читающая знание VMS.

### (в) Метки
* Good, because гранты по меткам уже есть (`may.md:55`).
* Bad, because метки камеры сверяет размещение (`labels-subset`): папка «Подъезд» в метках сделает камеру неразмещаемой
  (`cam.subsystem.yaml:173`–`179`).
* Bad, because у метки нет `id`, порядка членов, вложенности, пустого состояния и версии — ничего из `Folder`.

### (г) Пути в `cam.folders`, `backend` собирает `Folder`
* Good, because платформа не меняется, данные стендов сохраняются.
* Bad, because порядок `deviceIds` хранить негде; пустой папки нет; версия — склейка индексов всех камер папки.
* Bad, because переименование — правка всех камер, больше предела пакета B9: «412 — ничего не изменилось» не выполнить.
