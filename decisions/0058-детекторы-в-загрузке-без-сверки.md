# Спеки детекторов курса: продукт их грузит, сверка ключей их не касается

## Context and Problem Statement
Класс системы: платформенная система.

Спеки `det`, `detjob` и `survey` есть только в курсе (`Source/vms/*.subsystem.yaml`). Детекторов в продукте нет. Записка `ДЕТЕКТОРЫ-В-ПРОДУКТЕ.md` решает их «с чистого листа».

Продукт уже грузит эти спеки своим строгим загрузчиком (`vms/spec_load_test.go`), и его долг загрузки содержит их строки. Сверка ключей подсистемы одной стороны не сравнивает (ADR-0019). Нужно было решить, остаются ли эти спеки в паритете вообще.

## Considered Options
* Продукт грузит спеки детекторов, сверка ключей их не касается.
* Перенести детекторы в продукт сейчас и сверять их ключи наравне с `vms`, `rec`, `live`, `auto`.
* Вывести детекторы из паритета: продукт их не грузит, строки долга по ним снимаются.

## Decision Outcome
Выбран первый вариант. Загрузка дёшево проверяет, что язык спек курса полон для продукта: ключ, который детекторы курса объявляют, а загрузчик продукта не знает, виден сразу. При этом продукт не связывает себя формой детекторов, которую он ещё не решил.

### Consequences
* Good, because ключи платформы, которыми пользуются только детекторы курса (например, `metrics`, `unit.fields.*.ref`, `must_match`), остаются проверенными загрузчиком продукта.
* Good, because продукт решает детекторы с чистого листа, а не под форму курса.
* Bad, because строки долга загрузки по детекторам живут, пока продукт не примет соответствующие ключи, и каждая несёт ADR и владельца по правилу §1.7.

### Confirmation
* `vms/spec_load_test.go` продукта грузит `det`, `detjob`, `survey` курса. Долг по ним только убывает.
* `spec_parity_debt.txt` не содержит строк этих спек.
* Когда продукт начнёт детекторы, эти спеки входят в сверку ключей. Это отдельное решение.
