# Автоматизация consolem в V/07: одна модель правила, всё работает

## Context and Problem Statement

Класс системы: подсистема `auto`, перевод `backend`.

ADR-0103 ввёл автоматизацию в границу, доп. (2) снял «без работы». Перечень `decisions/inbox/2026-11-01-запрос-vms-перечень-out-adr-0103.md` показал: в V/07 как есть выразимо только ядро (наборы правил 0 из 9 и 0 из 6), слой хранения и слой исполнения — новая глава, слой ожидания — новая форма вычислителя. Нужны решения модели до норм.

## Decision Drivers

* один источник правды о правиле;
* «объявленное работает целиком, не имитируется»;
* вычислитель остаётся тем, кто решает: право, журнал, повтор по имени сработки.

## Considered Options

* расширить `auto/scenarios` до `Rule`;
* хранить `Rule` документом рядом, сценарий выводить.

## Decision Outcome

Выбрано: расширить `auto/scenarios`: два представления одного правила разъехались бы.

1. **Ключ** — `unit.id: numeric`, как у камеры; `name` — поле. Меняются `auto/<scenario>`, приёмка, V/08, V/10.
2. **Расписания, группы дней, режимы, окна** — таблицы `auto`. Функция момента одна, в вычислителе. `objectMode` считает вычислитель и говорит в пульсе; `backend` не считает.
3. **Условия** считаются по `occurred(e)`. «На связи» и «пишет» — текущее состояние в момент решения: истории нет, предел назвать.
4. **Цели-области.** `backend` не разворачивает, вычислитель читает папки: новое устройство входит само. Право судится при записи: автор должен иметь право на саму область. `runAsRoleId` — действие судится правом роли, а не автора; форму согласует «Спецификация», это чтение ролей воркером.
5. **Ожидание** — форма вычислителя: запуск правила становится строкой с шагом и сроком, переживает рестарт и переезд. `wait`, `waitEvent`, `ask`, `escalate` — на ней. Строка запуска — у `auto`, один писатель, продолжение идёт по имени сработки.
6. **`disable`** — просьба `cam`, держатель применяет; `Device.disabledBy*` из строки.
7. **`POST /rules/test`** — дверь вычислителя, код правила один.
8. **`armed`** — таблица воркера `cam/rule_state`, новая норма V/01: воркер строку `cam/cameras` не пишет, а новая `revision` перезапускала бы камеру. **`alarm`** — журнал тревог платформы. **`rec/segment.lost`** — новая норма V/02.
9. **`order`** действует среди правил одного вычислителя; между вычислителями порядка нет, предел называется.
10. **`operatorMenu`** — данные, запуск вручную по ним идёт через `POST /rules/{id}/run`.
11. Приёмка V/07.1 правится, новая приёмка главы расписаний. V/07 проходит стандарт пробы заново, Quint — на функцию момента и строку запуска.

### Consequences

* Good, because consolem работает с нашей автоматизацией без имитации.
* Bad, because V/07 переписывается на 550–850 строк, V/11 на 300–450, по оценке «Спецификации VMS»; строка запуска — новая устойчивая форма.
* Bad, because часть зависит от ответа consolem на запрос 8.

### Confirmation

Строки автоматизации в `profile.tsv`, `profile-tests.tsv` — `in`; наборы правил consolem грузятся и работают; ревью Claude.
