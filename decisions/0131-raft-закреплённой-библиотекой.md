# Raft из закреплённой библиотеки, модель пишет склейку

## Context and Problem Statement

Класс системы: платформенная система. По слову владельца З-24 алгоритм Raft берётся закреплённой библиотекой из двух вариантов: hashicorp/raft или go.etcd.io/raft. Зависимость фиксируется в `Platform/common/versions/go.mod`, передаётся вендором в пакет MiniMax, судья работает без сети. После этого этап `group` включается в отдельную пробу P/01. Модель пишет склейку, а не свой алгоритм консенсуса.

Нынешний manifest версий указывает Go1.22.0 и toolchain1.22.10. Выбранный upstream go.mod указывает Go1.20: текущая минимальная версия зависимости повышения не требует. Директивы Go/toolchain не повышаются отдельной подготовительной командой или будущим обновлением зависимости без явного решения; фактическая offline-сборка проверяется отдельно.

## Considered Options

- `github.com/hashicorp/raft v1.7.3`: Raft node с FSM, интерфейсами storage/snapshot и транспортной обвязкой.
- `go.etcd.io/raft`: детерминированное ядро Raft, у вызывающего остаётся организация Ready, диска и сообщений.

## Decision Outcome

Архитектор выбирает **`github.com/hashicorp/raft v1.7.3`** для порученной владельцем цели. Более готовый API сокращает объём ручной обвязки вокруг консенсуса. Версия закреплена явно; это не указание всегда брать latest.

1. Spec103 через src добавляет direct require в `Platform/common/versions/go.mod` и нужные checksum в go.sum; сохраняет остальные пины. Английский договор называет библиотеку и границу кода модели; русский текст производный. Не менять алгоритм и не исправлять код кандидата41.
2. Tools собирает отдельный пакет с полным runtime-транзитивным vendor closure, `vendor/modules.txt`, версиями, checksum, лицензиями и происхождением. Одного изменения go.mod недостаточно. Manifest версий не теряет прежние require из-за пустого `go mod tidy`/отсутствующих импортов. Подготовка с сетью допустима для vendoring; у судьи сеть отключена.
3. До передачи подтвердить импорт/сборку закреплённой библиотеки в чистом изолированном модуле из vendor при `GOPROXY=off`, `GOSUMDB=off`, `GOTOOLCHAIN=local`. Принудительно выбран vendor; workspace, неоговорённый replace и модульный кеш не подменяют пакет. Сопоставить фактически выбранные source/module/version с закреплённым составом. Отдельный отрицательный контроль в копии с новым build-кешем изымает необходимый vendor-файл: проверка должна завершиться ошибкой без восстановления из кеша/сети или регенерации. Конкретные команды и среду выбирает tools. Прежнее достаточное доказательство переиспользуется; если этого нового контроля ещё нет, добавляется только он, а не повторная приёмка всего архива. Это проверка доступности зависимости, не group/SUT PASS.
4. Модель пишет FSM и адаптеры к выбранным storage/snapshot/transport, mTLS, внешним дверям, версиям, тайм-аутам и ошибкам по норме P/01. Нужны корректные LogStore/StableStore, атомарное применение, восстановление и Shutdown. Наличие библиотеки не заменяет проверки долговечности, отката, ограничений замков и стоимости из ADR-0130.
5. После pin+vendor+offline-контроля подготовить отдельный P/01 пакет/вариант задания со стадией `group` для Владельца. Не менять запущенную/завершённую41, её рабочий каталог и исходный ce8d-пин сравнения. Новый Source/package/task пин назвать отдельно; задание модели и запуск выполняет Владелец. Инженерная проба group допустима до полной боевой квалификации ADR-0130: её подготовку не держит отсутствие ещё не поставленных среды или fault-привязок. В новом варианте явно указать пин норм, какие из17групп ADR-0130 уже применимы и обеспечены, а какие не исполнены/зависят от нового Source или входа. Неисполненное не PASS. Боевую готовность заявляют только после соответствующей принятой нормы и фактической приёмки; исторический ce8d не выдаётся за новую норму.

Стадия `group` P/01 проверяет Raft. Она отличается от совместной генерации циклической группы уроков P/03–P/06,P/08–P/10 по З-23. Запрет ручного алгоритма не означает, что интерфейсы библиотеки становятся внешним протоколом платформы.

### Consequences

- Good, because проверенный сторонний алгоритм уменьшает объём консенсусной логики, которую надо генерировать модели.
- Good, because зафиксированные версия и vendor позволяют судье строить код без сети.
- Bad, because остаётся ответственность за storage/FSM/transport и shutdown; библиотека не исправляет неправильный барьер или глобальный замок в склейке. Vendor увеличит размер пакета, и его состав нужно фиксировать.

### Confirmation

В Source версии закреплены, в готовом пакете есть полный vendor и результат чистой offline-сборки. Модель не получает старую реализацию P/01 или ручные Go-помощники вместо своей склейки. Затем Владелец получает отдельный вариант задания с `group`; group-готовность следует только из фактических проверок.

## Addendum (1): подтверждение vendor и граница инженерной пробы

2026-11-08, Архитектор. По двум независимым TEXT-ONLY отчётам на68b4 уточнены пункты3/5 и основание сохранения toolchain. Успешная сборка без сети сама по себе не доказывает источник пакетов: выбранные файлы должны происходить из переданного vendor, а изъятие необходимого файла должно обнаруживаться. Это способ проверки прежнего требования, не новый алгоритм или публичный API. Наличие инженерного group-варианта до полной ADR-0130 квалификации допустимо с явным перечнем применимых/неисполненных проверок; оно не объявляет боевую готовность.

### Consequences

- Good, because кеш или workspace не дают ложного подтверждения полноты vendor, а инженерная проба получает честный охват приёмки.
- Bad, because требуется один отдельный отрицательный контроль новой копии, если прежние доказательства его не содержат; полной боевой готовности у инженерной пробы может ещё не быть.

### Confirmation

Tools переиспользует свою положительную приёмку7b7eccdc и отдельно называет существующее либо новое доказательство отрицательного контроля; SRC и Архитектор архив не перепроверяют. Новый task/profile указывает собственную композицию ce8d SDK+c10 dependency и перечень применимых проверок; чужие пины/41 не меняются. Смысловой разбор двух текстовых отчётов — [здесь](inbox/2026-11-08-ADR0130-0131-разбор.md); новые дополнения идут на необходимое независимое ревью без промежуточных ACK.
