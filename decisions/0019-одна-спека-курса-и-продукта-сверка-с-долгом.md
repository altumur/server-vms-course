# Спеки курса и продукта — один YAML; расхождения проверяются тестами с убывающим долгом

## Context and Problem Statement
Класс системы: платформенная система. Курс и продукт описывают одни подсистемы (`vms`, `rec`, `live`, `auto`) своими спеками; ключи сводились по письмам, и файлы расходились: у курса ключи шагов 6–7, у продукта свои (`heartbeat.strings`, `secrets`, `objects.door`, слова консоли).

## Considered Options
* сводить ключи по договорённости, без проверки;
* проверять тестом на обеих сторонах, расхождения записывать долгом, который может только убывать.

## Decision Outcome
Выбрано второе. В продукте `vms/spec_parity_test.go` сверяет пути ключей общих спек с `Source/vms/*.subsystem.yaml` курса, а `vms/spec_load_test.go` грузит спеки курса строгим загрузчиком продукта; у курса зеркальные тесты. Данные (слова `display`, JSON Schema полей, строки `secret_in`) и подсистемы одной стороны не сравниваются. Долг каждого теста — файл с именами путей; новая разница — красный, устаревшая строка долга — красный. Без соседнего checkout другой стороны тест пропускается: каждая сторона собирается одна.

### Consequences
* Good, because расхождение видно в момент, когда его вносят, и закрывается явно: одна сторона реализует ключ, другая убирает, или обе переименовывают.
* Bad, because каждое изменение спеки на одной стороне требует хода на другой или строки долга.

### Confirmation
Тесты сверки и загрузки зелёные на обеих сторонах при соседних checkout; долг сверки продукта и курса совпадает байт в байт.

## Дополнение 2026-10-06: слова внутри списков («Архитектор», записал «Паритет»)
Сверка видела только пути ключей. Слово, которое одна сторона пишет в список, а другая нет, оставалось молчаливым расхождением. Например, `keeps` в `rec.door.routes`, `poll` против `polls` в `vms.domain.books`, поля `snapshot`.

Теперь оба теста (`spec_list_values` в курсе, `specListValues` в продукте) сверяют и слова внутри списков, как `путь[слово]`:
- список слов даёт каждое слово;
- список карт даёт `name` каждой карты, а если его нет — `field` (`metrics[].name`, `servers.status[].field`);
- то, что не строка, словом не считается;
- под данными ничего не читается.

Расхождения идут в ту же ведомость, с хвостом `# ADR-NNNN «владелец»` (`СЕССИИ.md` §1.7).

Правила для трёх семейств:
* `heartbeat.strings`: поле объявлено у обеих сторон, если обе его пишут. Иначе это строка долга `# ADR-0019` с владельцем той стороны, которой поля не хватает: она решает по смыслу, писать поле или убрать.
* `snapshot`: одинаковый набор полей, уходящих из кластера. Поле стоит в `snapshot`, если у него есть читатель в домене. Лишнее убирается на своей стороне, недостающее добавляется (`# ADR-0010`).
* `objects`: одно семейство под одним именем (ADR-0003). Строки, которые пишет только одна сторона, — долг `# ADR-0019`, пока вторая не начнёт их писать.

### Confirmation
`TestTheListsWordsAreReadAsTheCoursesTestDoes` и `test_the_lists_words_are_read_as_the_products_test_does` читают один пример одинаково. Долг сверки со строками `путь[слово]` совпадает на двух сторонах байт в байт.
