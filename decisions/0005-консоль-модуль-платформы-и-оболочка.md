# Консоль: платформа отдаёт модуль, продукт собирает страницу, облик прежней консоли

## Context and Problem Statement
Обе страницы платформы были страницами VMS, а платформенная часть UI (вход, домен, серверы, списание) жила в странице VMS. Нужно, чтобы платформенная консоль была чисто спековой, а оператор ничего не потерял.

## Decision Drivers
* ADR-0001, ADR-0002: показ это страница, платформа знает только спеки;
* оператор работает в одном дереве, где серверы и камеры вместе;
* решение владельца: новая консоль выглядит и работает точь-в-точь как прежняя консоль продукта.

## Considered Options
* (а) платформенная страница как оболочка, панели продукта в ней;
* (б) страница продукта как оболочка, платформа отдаёт JS-модуль со своими разделами;
* (в) две отдельные страницы.

## Decision Outcome
Выбран (б). Платформа отдаёт `/platform/console.js` и `console.css`; модуль строит из `/spec` и платформенных дверей дерево единиц, вход, серверы, домен, права, журнал; слова для показа берёт из `display` спеки как данные; байты не трогает, дверь держателя только отдаёт оболочке. Страница продукта подключает модуль и добавляет своё вызовами в библиотеку (`addTab`, `addSection`, `addTreeNodes`, `addDecor` и далее по контракту), которые хуками не считаются. Облик модуля это облик консоли продукта, общий для всех страниц. Набор значений поля из `enum` спеки, слова из `display.options`.

### Consequences
* Good, because платформенная страница и `testsub` проверяют контракт без продукта.
* Good, because новое слово страницы схему не трогает: словари `display` свободны, проверяются только имена полей.
* Bad, because контракт модуля это публичный API, который версионируется и за которым нужно следить.

### Confirmation
`../КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md` §10: тест модуля перехватывает `fetch` и сверяет каждый путь со списком §2, словарь по исходнику модуля и CSS; тест оболочки проверяет, что она не рисует платформенных разделов и пишет только через `console.api`.
