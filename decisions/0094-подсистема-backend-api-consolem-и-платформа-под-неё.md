# Подсистема `backend`: REST API consolem для WebUI — перевод на сервере; платформа даёт `door.pass` второго вида (билет на запрос), ленту изменений, версии и память повторов

## Context and Problem Statement
Класс системы: прикладной сервис (подсистема VMS) поверх платформенной системы; часть решения — изменение платформы.

Продуктовая команда утвердила интерфейс конфигуратора consolem (`github.com/ndm234234/consolem`): WebUI и его контракт с
сервером — `api/openapi.json` (60 операций и 3 служебные), приёмка — их тесты API против стенда. Сессия «Консоль» сравнила
его с нашей консолью (СВОДКА-КОНСОЛИ.md §5): принципы совпадают (сервер — правда, без оптимистичных обновлений, CAS по
версии, ключ идемпотентности), но платформа сейчас не держит того, что нужно этому API:
- браузер узнаёт о переменах опросом (модуль — около 8 + 2N запросов каждые 5 с);
- `If-Match` есть только у строки единицы и необязателен;
- память повторов `Idempotency-Key` — только у `POST /<rows>`;
- отказ — английское слово без указания поля;
- воркер не может действовать от имени человека.

Решения владельца 2026-10-29 (через «Консоль», АДАПТЕР-CONSOLEM.md §8; пересмотр после ревью — §16):
1. Адаптер к API consolem пишем мы.
2. Адаптер — подсистема VMS `backend`, целиком наша, перевод — на сервере. Пока транспорт к консоли — сокет роли, она
   стоит при консоли своего сервера; размещение рядом с `live` — после окна mTLS «консоль → воркер» (ADR-0075).
3. Пока у каждого кластера свой `backend`; общий для домена — следующим шагом.
4. **Вариант В: `door.pass` второго вида.** Консоль передаёт воркеру не удостоверение человека, а **билет на запрос**;
   обратный вызов дверей консоли — по билету, из закрытого перечня, объявленного манифестом; передача потоком для
   объявленных маршрутов. Это общее для всех `door.pass` (учётки `live` тоже перестают получать `Authorization`).
   Прежнее «делегирование токеном двери» снято ревью (блокер: удостоверение человека в руках воркера).
5. Единица — пересмотрена «Архитектором» (ниже, A2).
6. Контракт ведёт продукт: закрепляем коммит `openapi.json` consolem, сверяемся при каждой их правке; свои отличия — только
   объявлением возможностей, контракт не правим.

## Decision Drivers
* WebUI consolem утверждён продуктом — его API нужно отдать без правки контракта.
* У воркера не должно быть удостоверения человека, которое живёт отдельно от запроса этого человека (ревью, блокер Б-1/Б-2).
* Права и правду решает консоль платформы; второй источник прав недопустим (ADR-0093 доп. (1): учётных данных админа
  воркер не получает).
* Модулю консоли самому нужны те же механизмы (СВОДКА-КОНСОЛИ.md §4 пп. 1–5): тихое затирание правок без `If-Match`,
  опрос вместо подсказки о переменах.
* Текущая цель — Go GREEN 01–10 и генерация VMS (ADR-0090 доп. (14)); изменение платформы не должно её сорвать.

## Considered Options
* А. Делегирование токеном двери: консоль принимает токен двери `backend` как личность человека (первая редакция).
* А″. Обмен: браузер меняет сессию консоли на суженный токен делегирования, привязанный к листу предъявителя.
* Перевод в браузере: Service Worker на источнике консоли переводит API consolem в двери консоли сессией человека (по
  прецеденту `assist`, ADR-0093 доп. (1)).
* **В. `door.pass` второго вида: консоль передаёт `backend` запрос с билетом на этот запрос; `backend` переводит его и
  зовёт двери консоли обратно по билету.**
* Б. Адаптер внутри консоли платформы.
* В′. Адаптер вне платформы со своим входом и правами (сервисная учётная запись).
* Г. Править WebUI consolem под нашу консоль.

## Decision Outcome
Выбран вариант «В» (владелец), потому что перевод остаётся на сервере, а удостоверения, которое живёт у воркера без
запроса человека, нет нигде: билет привязан к одному открытому запросу, к выдавшему экземпляру консоли, к сокету роли
`backend` и к закрытому перечню дверей. Захваченный `backend` действует только за тех, чьи запросы идут через него в эту
секунду, и только в перечне — столько же мог бы переводчик внутри консоли. Попутно `door.pass` перестаёт передавать
воркеру `Authorization` человека (старая слабость, из-за которой ADR-0093 доп. (1) увёл `assist` с него). API годится и
не браузерам (скрипты, интеграции) — они зовут консоль с `Authorization: Bearer` человека.
А снят ревью (блокер); А″ оставляет у воркера удостоверение на минуту и требует TLS-привязки, которой нет в ADR-0075;
перевод в браузере требует HTTPS и Service Worker и не служит не браузерам; Б смешивает чужой контракт с платформой;
В′ — второй источник прав; Г — против решения владельца 6.

### A. Подсистема `backend` (урок `VMS/11-backend`, «Спецификация VMS»)
1. Контракт двери — `openapi.json` consolem на закреплённом коммите (сейчас `9dc1688`), без своих правок. Чего у нас
   нет — `404 NO_ROUTE` и объявление возможностей (запрос продукту — владелец).
2. Единица — «один на сервер», как модель `assist`: строка `backend/instances/<сервер>` на каждом сервере, где отдаёт
   консоль, размещение строго на свой сервер; входа на набор меток нет (при сокете роли он смысла не имеет). После окна
   mTLS (ADR-0075) — пересмотр к размещению по меткам рядом с `live`.
3. Воркер без своего состояния сверх памяти повторов (память группового `idempotencyKey`, пока нет B3). Браузер берёт
   всё по адресу консоли `/backend/…` (та же кука, сторожевая, Origin, `may`). **WebUI consolem `backend` не отдаёт** —
   его отдаёт сама консоль закреплённым набором байтов (коммит и SHA-256 сборки WebUI в уроке V/11, как канон оболочек
   VMS) со своей CSP. Консоль передаёт `backend` только запросы API; ответ передачи — `application/json` или
   `text/event-stream`, консоль добавляет `X-Content-Type-Options: nosniff` и `Content-Security-Policy: sandbox`; иной
   тип — 502 (иначе скрипт захваченного `backend` исполнился бы с кукой консоли мимо билета — второй круг ревью, блокер).
4. Своего входа нет: при 401 — на вход консоли.
5а. Служебные `/test/*` контракта consolem — только на стенде (ADR-0050: переменная окружения и петля), иначе
   `404 NO_ROUTE`.
6. Сопоставление «вид consolem ↔ подсистема VMS» — таблица данными урока (камера = `cam` + `rec` + `det`, правило =
   `auto`, хранилище = `rec/volumes`, домен consolem = наш кластер).
7. Закрытые перечни ADR-0090 (доп. (2) — уроки, доп. (3), доп. (5) п. 1 — подсистемы и имена) пополняются `backend` и
   `V/11` (по образцу ADR-0093 доп. (2) п. 1). Сверку закреплённого коммита контракта consolem ведёт «Спецификация VMS».

### B. Платформа (уроки P/06, P/07, P/10; «Спецификация», «Спецификация домена»)
1. **`door.pass` второго вида — билет на запрос** (общее для всех `door.pass`, ADR-0091; договор сторожевой и передачи):
   - консоль передаёт воркеру запрос человека **без** его `Authorization`, с билетом: 128 случайных бит, которые консоль
     помнит у себя как `{user, вид сессии, открытый внешний запрос}`;
   - **обратный вызов:** воркер, которому манифест разрешает звать консоль (`door.pass` с закрытым перечнем дверей),
     предъявляет билет; консоль принимает его, только если билет выдан этим экземпляром, внешний запрос ещё открыт,
     соединение пришло по транспорту роли этого воркера, дверь — в объявленном перечне, а `may` человека проходит свежей
     проверкой (выключение, отзыв); вид сессии — только `person` (break-glass и `open` билета на обратный вызов не дают);
   - ответ человеку закрыт или оборван — билет мёртв, обратный вызов — 401;
   - журнал консоли: `user`, `via: <sub>/<экземпляр>`, дверь; ряд `<sub>_passed_calls_total`;
   - **передача потоком** для маршрутов, объявленных потоковыми: без предела 5 с и буфера 4 МиБ (SSE, длинные ответы);
     билет потока годится только на чтения и `/changes`;
   - **транспорт:** сейчас — сокет роли воркера на сервере консоли (личность — сокет, как у хранилища и местной двери
     агента); после окна mTLS «консоль ↔ воркер» (дополнение к ADR-0075) — к воркеру на любом сервере, привязка к листу роли;
   - перечень дверей для `backend`: строки и таблицы `cam`, `rec`, `det`, `auto`, `/changes`; чтения `GET /manifest`,
     `/servers`, `/events`, `/session` (только «кто я»); без `/where`, записи `/session`, грантов, людей, ключей,
     break-glass и `/operations` (до ADR групповых операций, C);
   - предел ожидания передачи — по объявленному маршруту (манифест называет свой для составной записи, потолок — в
     норме), не общий `PASS_WAIT`; потоковость — объявлением маршрута в грамматике `door.pass` (P/02.1);
   - после окна mTLS билет привязан к экземпляру-адресату передачи: обратный вызов — от листа его сервера и роли, с
     именем этого экземпляра;
   - учётки `live` (V/03.6) переходят на тот же вид **вместе с окном mTLS**: до него передача идёт по сети к шлюзу, и
     проверить, что её отправила консоль, шлюзу нечем; до окна — нынешний `door.pass`.
2. **Лента изменений** `GET /changes` (SSE или длинный опрос): сообщения «строка X — ревизия R / удалена», **без
   значения** — значение клиент читает обычной дверью; это записанное отступление от ADR-0038 («ответ не несёт события»),
   ADR-0038 для прочих мест не меняется. Охват — строки единиц и таблиц; события, пульсы, метрики — своими дверями (у
   `/events` — курсор). Одно перечисление префиксов на экземпляр консоли, раздача подписчикам; такт и потолок называет
   норма; ряды цены `w2c_changes_*`. Номера — в пределах экземпляра; чужой номер, перезапуск экземпляра, смена грантов или
   меток в `view` подписчика — `reset`. Фильтр — по `view` человека; для таблиц — по праву `view` на таблицу. Модуль
   консоли переходит на неё для строк вместо опроса.
3. **Память повторов `Idempotency-Key`** на `PUT`, `DELETE` и записях таблиц, а не только на `POST /<rows>`. Порядок —
   «память повторов → `If-Match` → запись»; ключ — `(user, метод, путь, ключ)`; иное тело под тем же ключом — 409
   `key reused`; срок — как у `POST`.
4. **Версия на всех записях людей:** `revision` у строк таблиц и снимков настроек; `ETag`; `If-Match` на всех дверях
   записи; 412 с текущей строкой в теле (с маской `*_secret`, только при праве `view`). `If-Match` у двери остаётся
   необязательным, форма модуля шлёт его всегда (закрывает ADR-0091 доп. (28) п. 3). `base_rev` у `PUT /domain/shared`
   сводится к `If-Match` или норма называет, почему два.
5. **Коды отказов:** закрытый перечень `error` по дверям и `field` (путь поля) у 400, 409, 412 — рядом с нынешними
   словами, не вместо них.
6. **`/session`** отдаёт `server_time` и `timezone` (настройка кластера, не ОС сервера).

### C. Вторая очередь — отдельными ADR, когда до неё дойдёт урок `backend`
Папки (группы) как записи; групповые операции в консоли (шаги с ожидаемыми ревизиями, ход в ленту, пауза, отмена,
повтор, откат); роли, группы людей и каталоги LDAP в домене; просьбы с ходом и `GET` состояния; телеметрия сервера в
пульсе ресурса.

### Consequences
* Good, because адаптер без состояния и без своих прав; права и правду решает консоль; лента и версии нужны и нашему
  модулю консоли; приёмка `backend` — тесты продукта.
* Good, because `door.pass` перестаёт передавать воркеру удостоверение человека — и у `live`, и у будущих подсистем.
* Bad, because у консоли новое: билет, обратный вызов, передача потоком, перечень дверей; модель угроз билета — разбором
  ревью этой редакции.
* Bad, because пока транспорт — сокет роли, `backend` прикован к консоли своего сервера.
* Bad, because лента добавляет консоли работу: перечисление префиксов на каждый такт.
* Bad, because контракт ведёт чужая команда — идём за их правками.
* Neutral, because риск: тесты продукта без объявления возможностей и профиля под наш стенд не пройдут; версия сборной
  камеры у consolem — целое, у нас камера — несколько строк (вопрос продукту).

### Confirmation
* `backend`: тесты API consolem против стенда в профиле возможностей; `?selftest` их интерфейса на стенде; `/test/*` вне
  стенда — `404 TEST_SUPPORT_OFF`.
* Платформа: приёмка P/06 — обратный вызов по билету принят на двери из перечня и отвергнут (401) после закрытия запроса,
  с чужого транспорта, на двери вне перечня, после выключения человека, для break-glass; поток закрывается с запросом;
  ответ передачи вне типов доп. (3) п. 2 — 502 (204 удаления и 412 `problem+json` проходят), WebUI — байты закреплённого набора;
  журнал `via`; лента — `reset` при смене прав и перезапуске; `If-Match` и 412 на таблицах; память повторов `PUT`/`DELETE`
  и порядок с `If-Match`; jsdom модуля — форма с `ifMatch` и экран 412.

1. **Билет помнит исходное удостоверение (Б-1).** Запись билета у консоли — `{user, вид сессии, jti, kid, exp,
