# Перевод лекций в спецификации начинается сейчас отдельной сессией «Спецификация»; дерево курса делится по каталогам

## Context and Problem Statement
Класс системы: курс как источник правды (ADR-0080), две реализации (Python курса, Go продукта), команда курса на
другом провайдере (ADR-0073).

ADR-0080 назначил перевод уроков команде курса и отложил его до её шага C7. Продукт закрыл окно ADR-0074 целиком
(C1–C7, `domainpart` ушёл, main 6a98fa33 от 2026-10-14), команда — внутри C2, впереди C3–C7 на Python. Ждать её
значит держать единственную дошедшую до конца реализацию без спецификации ещё недели, а спецификация пишется из
решений (ADR, формы «до кода», прежние лекции), а не из кода: реализация ей свидетель. Вопрос владельца: можно ли,
имея Go, не дожидаясь команды, завести отдельную сессию под ADR-0080.

## Decision Drivers
* спецификация должна быть проверена на живой реализации с первого урока — такая реализация уже есть (Go);
* кто пишет норму, не пишет её первое воплощение (ADR-0081 п. 7);
* правило 15: у дерева курса один писатель — команда; две сессии в одном дереве требуют границы по каталогам;
* раскладка каталогов (спецификация, реализации, общие данные) — отложенное решение, без него сессию не завести.

## Considered Options
* ждать C7 команды курса, перевод — её (ADR-0080 как записан);
* сессия «Спецификация» сейчас, команда остаётся на догоняющих окнах Python, затем догоняет спецификацию;
* отдать перевод команде сейчас, остановив её окна Python.

## Decision Outcome
Выбран второй вариант.

1. **Сессия «Спецификация» заводится сейчас** (Claude, та же модель, что у «Архитектора»; свой worktree курса).
   Она переводит уроки по ADR-0080 и его дополнениям 1–4: записка `module-design` М10 → чтение «Архитектором» →
   урок 1 М10 «словарь операций хранилища» как образец → владелец смотрит форму, формат закрепляется поправкой к
   ADR-0080 → дальше М10 целиком, М11, М12A, М12B, затем М13 и М14. Источники по старшинству: ADR и формы «до кода»
   в них; прежние лекции (повествование, таблица соответствия в ADR-0080 доп. 4); Go-продукт — свидетель, не канон
   (читается, не правится; расхождение Go с ADR — находка «Архитектору», не норма); Python курса — отстающая
   реализация, не источник. Норма пишется словами ДОЛЖЕН/СЛЕДУЕТ/МОЖЕТ, «решает реализация» помечается явно.
2. **Команда курса перевод не делает.** Её очередь — догоняющие окна Python C2–C7 по ADR-0074 (окно за шаг,
   ADR-0073 доп. 2026-10-13), затем Python догоняет переведённые уроки по их приёмке, урок за уроком; расхождение
   Python с уроком — находка во входящие, чинится урок или Python, не ADR. Задача
   `inbox/2026-10-13-задача-adr-0080-после-adr-0074.md` переписана этим решением.
3. **Раскладка дерева курса (отложенное решение, закрывается здесь).**
   * `М10_Platform/`, `М11_Domain/`, `М12A_Subsystems/`, `М12B_Subsystems/` в корне курса — новые модули по
     ADR-0080 доп. 4, уроки `NN-<слово>.md` с повествованием и нормативными разделами; `module-design.md` в каждом;
     пишет только «Спецификация». Прежние каталоги `М10A_Platform/`, `М10B_ServerVMS/`, `М11_Cluster/`,
     `М12A_Domain/` заморожены: никто не правит; прежний урок удаляется «Спецификацией» в том коммите, где его
     содержание перенесено по таблице соответствия (ADR-0003: без двух версий одного урока).
   * `Source/tests/testdata/acceptance/<модуль>/<урок>/` — сценарии приёмки и журнал исправлений ИИ (общие данные,
     ADR-0080 доп. 1); пишет только «Спецификация», читают тесты Python (команда) и продукт — забирает
     `scripts/sync-course.sh`, который «Сборка» учит этому каталогу при первом сценарии. Остальное `Source/` —
     команды курса, как по правилу 15.
   * `ХОД-Спецификация.md` — её страница хода (правило 12д), записки о решениях спецификации — в уроках, не в
     отдельных файлах.
   * Спеки `*.subsystem.yaml`, таблицы `testdata/*.tsv`, ведомости — по-прежнему команды курса до перевода
     соответствующего урока; после перевода ключ живёт в разделе «Форма» урока, спека — его воплощение, и
     строка ведомости за него снимается (ADR-0080).
4. **Обмен.** «Спецификация» спрашивает «Архитектора» сообщением по правилу 12 (с рекомендацией); команда курса —
   файлами во входящие, как раньше; находки «Спецификации» о Go — «Архитектору», он ставит «Сборке». Нормативные
   дифы уроков и записки модулей «Архитектор» читает до следующего урока (ADR-0081 п. 7).
5. **«Приёмка»** (судья по ADR-0081 п. 7) заводится по слову владельца, когда есть первый каталог сценариев: прогон
   по дверям продукта сразу, по Python — когда догонит.

### Consequences
* Good, because спецификация проверяется на реализации, дошедшей до конца ADR-0074, с первого урока.
* Good, because норма и реализация в разных руках (ADR-0081 п. 7) с сегодняшнего дня, а не после Orca.
* Good, because отложенная раскладка каталогов закрыта без нового репозитория.
* Bad, because спецификация, писанная при одной дошедшей реализации, местами повторит её решения как норму; лекарство
  — источники по старшинству (п. 1) и находки Python при догоне, как находки команды сегодня (`kept_at`, метка).
* Bad, because в дереве курса два писателя: граница по каталогам, нарушение — находка «Архитектора».

### Confirmation
Образец М10/1 в main и прочитан «Архитектором»; формат закреплён поправкой к ADR-0080; первый каталог приёмки
вендорится в продукт и его сценарии проходят по дверям продукта; `ХОД-Спецификация.md` ведётся по урокам; тест на
документы курса (каждый путь из `*.md` существует) зелёный после каждого удаления прежнего урока.

## Дополнение 2026-10-14 (вечер): команде курса — никаких задач по М10 до завершения C7

Решение владельца (2026-10-14): команда курса не получает задач по урокам М10 (догон Python по приёмке М10/2–11, формы и пробы к ним), пока не завершён C7 по ADR-0074. Уже разрешённая интеграция окна М10/1 (`codex/course-m10-storage`, входящее `2026-10-14-м10-финальный-diff.md`) доводится до слияния и этим заканчивается; абзацы «Урок М10/N в main» в задаче `inbox/2026-10-13-задача-adr-0080-после-adr-0074.md` ждут C7. Находки команды об уроках (расхождение Python с уроком, найденное по пути C5–C7) — по-прежнему файлами во входящие, без работы по ним. Порядок п. 2 этого ADR тем самым восстановлен буквально: C2–C7, затем догон.

## Дополнение 2026-10-14 (ночь): пауза продукта до завершения ревью курса

Решение владельца (2026-10-14): работа «Сборки» над продуктом **приостановлена**, пока не завершены ревью курса
(прогоны «Ревью спецификации» и правки уроков по ним). Открытое окно М10/7 доводится до зафиксированного состояния в своей
ветке без слияния в main и без выкатки на стенд; новые окна (М10/8–11, поправки по ревью, синки общих байтов) не
начинаются; стенд и ночной прогон не трогаются. Снятие паузы — словом владельца через «Архитектора»; к тому моменту
«Архитектор» даёт «Сборке» один список норм, изменённых всеми прогонами, вместо поштучных сообщений. Причина: уроки
меняются каждым прогоном, и окна продукта по ним пришлось бы переделывать.

## Дополнение 2026-10-15 (2): прогоны ревью подряд до пустого; сигнал готовности — коммит отчёта
Решение владельца (2026-10-15): прогоны «Ревью спецификации» идут один за другим без отдельного слова на каждый:
«Архитектор» закрывает прогон (находки внесены, ответ и сведение записаны), тут же запускает следующий тем же срезом main и
останавливается, когда оба ревьювера в одном прогоне не нашли ничего; об остановке и о каждом закрытом прогоне — владельцу.
Сигнал готовности — **коммит отчёта в ветке ревьювера** (`codex/review-spec-N-codex` в копии Codex, `review-spec-N-kimi`
в общем репозитории): «Архитектор» следит за ним монитором и не ждёт сообщения в своей панели (отправка в занятую панель
не стартует ход — так потерялось сообщение Kimi о прогоне 12). Ревьюверы по-прежнему пишут о готовности в своей панели;
в панель «Архитектора» не пишут.

## Дополнение 2026-10-15 (3): ревью приостановлено на смену формы
Решение владельца (2026-10-15): с переходом уроков на форму «лекция + `spec/`» (ADR-0080 доп. 2026-10-15) прогоны ревью по
старой форме приостановлены: прогон 15 не закрыт (отчёт Codex принят и внесён, отчёт Kimi не запрашивается), прогон 16 не
запускается. Возобновление — словом владельца, с заданием, описывающим новую форму (каталог урока, канон — `spec/norms.md`).
