# Смена `source` на устройство, которого не открывал ни один держатель, — только по гранту на кластер; совпадение серийного номера — предупреждение, а не отказ

## Context and Problem Statement

Класс системы: подсистема VMS — камера называет устройство в поле `source`, права на реле и выходы устройства спрашиваются по камерам этого устройства.

После восьмого ревью держатель, узнав `identity` устройства (серийный номер, MAC) под другим ключом, считал новое имя «вторым именем» известного устройства и не открывал его. Девятое ревью показало запуском, что защита работает только при известной `identity`: в сборке курса фабрики устройств нет, `identity` не узнаётся, и обход через `nvr50.local`, `010.000.000.050`, полноширинные цифры, `10。0。0。50`, чужой драйвер или `rtsp://` давал `admin` одной камеры импульс реле чужого регистратора. Кроме того, серийный номер не уникален (клоны прошивки), и второй клон получал отказ навсегда; пустой ответ устройства стирал известную `identity`.

## Decision Drivers

* держатель не может отличить второе имя от клона, не разрешая DNS; оператор — может;
* права должны закрывать подмену и тогда, когда `identity` неизвестна;
* клон и устройство, промолчавшее о себе, не должны терять запись.

## Considered Options

* держатель отказывает второму имени по совпадению `identity` (правило восьмого ревью);
* разбор написаний адреса до одного канонического и отказ по нему;
* смену `source` на устройство с неизвестной `identity` разрешать только гранту на кластер; совпадение серийного номера называть и считать, но не отказывать.

## Decision Outcome

Выбран третий вариант. Пока держатель не открыл устройство и не записал `identity`, смена `source` на него требует гранта на кластер (`"*"` в `source_cams`, `Devices.known`); потом — `admin` на каждую камеру каждого ключа с той же `identity`. Совпадение `identity` под другим ключом записывается, говорится в лог один раз, считается (`identity_coincidences`, `vms_device_identity_coincidences`) и ставит `warning` в статус камер и `same_serial_as` в список устройств. Пустая `identity` не стирает известную. Вендор в сравнение не входит. Отказ держателя по второму имени снят: подмену закрывает консоль.

### Consequences

* Good, because шесть написаний из пробы ревью получают 403 у `admin` одной камеры, и защита не зависит от фабрики устройств.
* Good, because клоны с одним серийным номером оба пишут, а оператор видит предупреждение.
* Bad, because камеру, которую администратор кластера сам поставил на второе имя известного устройства, может командовать охранник с `edit` на неё, пока держатель не узнал `identity`; владелец этот риск принял.
* Bad, because строки устройств не удаляются: устаревшая строка старого имени даёт предупреждение о совпадении, пока оператор не удалит её в хранилище, маршрута консоли нет.

## Pros and Cons of the Options

### Отказ держателя по второму имени

* Good, because подмена закрыта там, где `identity` известна.
* Bad, because без `identity` защиты нет, а клон получает отказ навсегда.

### Каноническое написание адреса

* Good, because ловит написания одного адреса.
* Bad, because `nvr50.local` и `10.0.0.50` по строке не связать.

### Грант на кластер для неизвестного устройства

* Good, because закрывает подмену без знания `identity`.
* Bad, because администратор одной камеры не может сам перевести её на новое устройство.
