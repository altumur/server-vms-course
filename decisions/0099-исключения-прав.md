# Исключения прав: ранг `none`, внутри роли решает самая точная область, между ролями — наибольшее

Заменяет ADR-0098 п. 3 («понижения — `NOT_SUPPORTED`»),
ADR-0097 §7 «Понижение не переводится» и ADR-0097 §8.4 («запреты строкой»).

## Context and Problem Statement
Класс системы: платформенная система (`may`, гранты домена). Потребитель первым — `backend` (права consolem).

**Как сейчас.** Строки грантов только складываются: шаг 7 `may` — «хоть одна строка с рангом не ниже и покрывающей
областью». Поэтому роль consolem, которая даёт папке больше, чем камере в ней (`folderAccess` `FULL`, `objectAccess`
камеры 7 `FORBID` или `ONLY_ARCHIVE`), или подпапке меньше, чем родителю, не переводится: буквальный перевод молча дал
бы камере права папки. ADR-0097 §7 и ADR-0098 п. 3 отвечают такой роли `NOT_SUPPORTED`.

**Что решил владелец.** Исключения делать (2026-10-30). Смысл — как у consolem (`index.html`, `accRoleLevel` и
«Итоговый доступ», коммит контракта `aefcd19`):
- внутри роли — исключение объекта; нет — значение ближайшей папки объекта, где оно задано (сама папка, иначе выше);
  объект в нескольких папках — наибольшее из них; нет — умолчание роли; «неограниченный доступ» обходит всё;
- между ролями — наибольшее. Запрет в одной роли не отнимает того, что дала другая.

## Decision Drivers
* Смысл совпадает с consolem: роль переводится в строки без потерь и без расширения.
* Старые строки и их смысл не меняются (ADR-0003): прямые строки человека складываются, как сегодня.
* Ни один читатель не читает строки шире, чем записано: кто не знает исключений, не исполняет и строк ролей.
* Одна строка гранта — одна проверка; раскладки прав в строки на каждую единицу нет.
* Право на запись, принятое по составу папок, не расходится с составом (стражи членства, ADR-0097 §5).

## Considered Options
* **(а) Внутри субъекта решает самая точная область; между субъектами — наибольшее** (как consolem).
* (б) Запрещающая строка перекрывает всё: любая строка «нельзя» у человека или его роли — отказ.
* (в) Исключений нет, понижения — `NOT_SUPPORTED` (ADR-0097 §7, ADR-0098 п. 3).

## Decision Outcome
Выбран «(а)» (владелец, 2026-10-30).

### 1. Ранг `none`
```yaml
cap:   none | view | edit | admin       # none < view < edit < admin
none:  «в этой подсистеме и в этой области — ничего»; разрешения не даёт никогда; действует только как самая точная
       строка своей группы (§2)
```
- `none` — только в строках ролей (`subject: role:<имя>`, ADR-0098 §2). Строка человека или ключа индекса с `none` —
  400 bad line: прямые строки складываются, как сегодня, и понижать в них нечего.
- В `domain/grants/domain` ролей нет (ADR-0098 §2) — `none` там нет.
- Старый читатель сочтёт `none` не по форме и пропустит строку. Поэтому §6: исключения и роли — одним приращением.

### 2. `may`: группы строк и ярусы области
Шаг 5 (ADR-0097 §2, ADR-0098 §4) отбирает действующие строки по субъекту, сроку и `sub`. Дальше:

- **Группы.** Прямые строки человека (и ключа индекса) — одна группа; строки каждой действующей роли человека — своя
  группа на роль.
- **Прямая группа** — как сегодня: шаги 6–7 над её строками, строки только складываются.
- **Группа роли** — по каждой проверке `(cap, unit, sub)` берётся **первый ярус**, где у группы есть строка, покрывающая
  единицу; уровень группы — наибольший `cap` строк этого яруса (`none` — ничего). Ярусы, от точного к общему:

| ярус | строки |
|---|---|
| 1 | `unit:` — сама единица |
| 2 | `unit:` — её about-единица |
| 3 | `folder:` — ближайшие папки (ниже) |
| 4 | `labels:` |
| 5 | `*` |

- **Ближайшая папка.** Вход `may` у `unit` и `about` вместо набора `folders` (ADR-0097 §5) — цепочки: `chains:
  [[F, родитель F, …, корень]…]`, по одной на каждое членство единицы и её about-единицы, только живые (правило «только
  живая цепочка» ADR-0097 §5 без изменения). В каждой цепочке берётся первая папка, на которую у группы есть строка
  `folder:`; ярус 3 — строки этих папок по всем цепочкам, уровень — наибольший (consolem: «из нескольких папок —
  наибольшее»). Чтение членства не удалось — у этой группы ярус 3 не определён: группа не даёт ничего (не 503), прямая и
  другие группы считаются как обычно. Иначе строка `none folder:F` при сбое чтения превращалась бы в право яруса 5.
- **Итог** — разрешено, если прямая группа разрешает или хоть одна группа роли даёт уровень не ниже `cap`.
- Шаг 6 («`unit = null`, `cap = view`: хоть одна строка») — хоть одна строка с `cap ≠ none`.
- `unit = "*"` (создание — `admin` на `*`) покрывает только ярус 5; папка как объект записи (ADR-0097 §5) — ярусы 3 и 5
  по её цепочке `[F, предки F]`.
- Срок строки: истёкшая строка в ярусе не участвует — истёк `none` на камеру, и действует ярус папки.

Пример: роль «Оператор» — `view sub: live folder:Склад`, `none sub: live unit:cam/7`; роль «Охрана» — `view sub: live
unit:cam/7`. Человек с одной «Оператор» живого видео камеры 7 не видит (ярус 1 — `none`), остальные камеры склада
видит; с обеими — видит камеру 7 (`view` «Охраны»).

### 3. Цена и стражи
- Ярус 1–2 — без чтений. Ярус 3 читается, только если у группы роли есть строка `folder:` в этой `sub`, а ярусы 1–2
  пусты: у роли без строк `folder:` цена нулевая. Если первым ярусом с разрешением оказался 4 или 5, а у группы есть
  строки `folder:` — членство всё равно читается: более точная строка могла бы понизить. Порядок чтений на запрос — как
  ADR-0097 §5.
- Быстрый путь P/06.4 («`view *` без `sub` — видит всё») — только у прямой группы; у группы роли — если у неё нет строк
  точнее `*` в этой `sub`.
- **Стражи членства** (ADR-0097 §5): если решение о записи зависело от членства — разрешил ярус 3 **или** разрешил
  ярус 4–5 при прочитанном членстве, — консоль кладёт стражей строк членства единицы и её about. Иначе одновременное
  добавление в папку с `none` и запись по праву `*` разошлись бы.
- Лента `/changes` (ADR-0097 §3): `reset` при смене членства — подписчикам со строками `folder:` в прямых строках
  **или** в ролях; смена таблицы ролей (ADR-0098 §4) — как смена грантов.

### 4. Выдача
- `GET /session`: `grants: [{cap, sub?, scope, role?}]` — с `none`. Подсказка модуля консоли (P/07) — по тем же ярусам;
  сервер проверяет всегда.
- Доставка ключей книги по гранту и индекс имён (P/08.5 Н1.3, Н1.7) — по тем же группам и ярусам: строка `none` ключа
  не доставляет.
- `grant too wide` — по рангу, `none` ниже всех.

### 5. Перевод consolem (информативно; норма — V/11; заменяет ADR-0097 §7 «Понижение не переводится»)
- Роль → группа строк `role:<id>` (ADR-0098). `unr` → только `admin *` без `sub`; других строк у такой роли нет
  («неограниченный доступ обходит всё»).
- **Точки роли** — умолчание (`*`), каждая папка с заданным значением (`folder:F`, корень домена — `*`), каждый объект
  с исключением (`unit:`). В каждой точке `backend` считает уровень consolem по каждому полю вида (по правилу consolem:
  своё значение, иначе ближайшая папка выше, иначе умолчание) и пишет **строку на каждую подсистему вида** —
  наибольший ранг по всем полям и функциям, что этой подсистеме дают в этой точке, или `none`. Подсистемы, которых
  уровень не даёт, получают `none` явно: иначе ярус оказался бы пустым и сработал бы более общий.
  Пример: `folderAccess` «Склад» `cam: FULL`, `objectAccess` камеры 7 `cam: ONLY_ARCHIVE` → `folder:Склад`: `edit cam`,
  `view live`, `edit rec`; `unit:cam/7`: `view cam`, `none live`, `view rec`.
- Функции роли (`DEVICES_SETUP` → `admin cam` …, ADR-0097 §7) — тоже в точки: как функция сочетается с уровнем объекта
  (может ли `DEVICES_SETUP` настраивать камеру с `FORBID` или `MON`), — вопрос продукту ниже; до ответа `backend`
  считает «функция действует только там, где уровень объекта даёт хоть что-то в этой подсистеме».
- Подпапка ниже родителя — те же строки `folder:` подпапки: ярус 3 берёт ближайшую.
- Чего нет в строках (`tel`, `depth`, `restr`, расписания, …) — по-прежнему не объявляется (ADR-0097 §7).

### 6. Порядок
1. ADR-0097, ADR-0098 и это решение — **одним приращением** норм и кода (после зачёта B): читатель, который знает строки
   ролей, знает и ярусы; строки ролей без ярусов и `none` без ролей не исполняет никто.
2. «Спецификация домена»: P/08.4 Н1.3 (`cap: none`, 400 на `none` у прямых строк), договор `may` (группы, ярусы, вход
   `chains`, шаг 6), векторы `may` и `covers.tsv`, P/08.5 (доставка по ярусам).
3. «Спецификация»: договор сторожевой (стражи §3, цепочки во входе), P/06.4 (быстрый путь), P/06.7 (`/session`), лента
   B2, P/07 (подсказка).
4. «Спецификация VMS»: V/11 — перевод §5.
5. Пометки «заменяется ADR-0099» — в ADR-0097 §7, §8.4 и ADR-0098 п. 3 («Архитектор»).

### Consequences
* Good, because любая роль consolem с исключениями переводится без потерь: `NOT_SUPPORTED` по понижениям больше нет.
* Good, because смысл совпадает с consolem и с его «Итоговым доступом»: интерфейс показывает то, что решит сервер.
* Good, because прямые строки и их смысл не меняются; `none` в них запрещён.
* Good, because запрет в одной роли не отнимает права другой — добавить роль никогда не сужает права.
* Bad, because `may` сложнее: группы, пять ярусов, цепочки папок вместо набора.
* Bad, because у роли с `folder:` и `*` членство читается и тогда, когда разрешил `*`.
* Bad, because перевод пишет строку на каждую подсистему вида в каждой точке, в том числе `none`: строк у роли больше.
* Bad, because стражи членства ставятся чаще — и при разрешении по `*`.
* Neutral, because истёкшая строка-исключение поднимает права до уровня папки; у consolem сроков у исключений нет.
* Neutral, because `labels:` встаёт между папками и `*`; consolem меток не знает.

### Confirmation
* Векторы `may`: роль `edit folder:F` + `none unit:cam/7` — камера 7 deny, другая камера в `F` allow; та же роль и
  другая роль с `view unit:cam/7` — allow; прямая строка `admin *` + роль с `none unit:cam/7` — allow (прямая группа);
  подпапка `none` под `edit` родителя — deny; две папки объекта с `view` и `edit` — `edit`; `none` в прямой строке — код 2;
  членство нечитаемо при `none folder:F` в роли и `admin *` в той же роли — deny; `unit = "*"` — только ярус 5;
  истёкший `none` — ярус папки.
* `covers.tsv`: ярусы 1–5 и выбор первого непустого.
* Приёмка P/08.4: `none` у прямой строки — 400 bad line.
* Приёмка P/06: запись по `*` роли с `none folder:F` при одновременном добавлении единицы в `F` — 412 стража.
* Ревью — тремя.

## Pros and Cons of the Options
### (б) Запрет перекрывает всё
* Good, because правило проще: любое «нельзя» — отказ.
* Bad, because не совпадает с consolem: роль с исключением отнимала бы права, которые дают другие роли; добавление роли
  сужало бы права.

### (в) Без исключений
* Good, because `may` не меняется.
* Bad, because обычные роли consolem («вся папка, кроме этой камеры») не переводятся (отклонено владельцем).
