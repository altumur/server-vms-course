# Встроенная роль `admin`, «последний администратор» по ролям, управление пользователями ролью

Дополняет ADR-0098 и заменяет в нём:
- §2 «в `domain/grants/domain` строк ролей нет» — частично, §3 ниже;
- §3: правило `expiry_kept` и круг читателей `email`;
- §4: «таблица несёт только роли со строками» — кроме `admin`;
- §5: «`last_admin` не меняется»;
- §8.4 — частично.

Заменяет строку `unr` ADR-0097 §7 и определение `unr` ADR-0099 §7.

## Context and Problem Statement
Класс системы: платформенная система (люди, роли, гранты домена, `may`). Потребитель первым — `backend` (consolem).

**Как сейчас.** Администратор домена — человек с прямой строкой `{admin, *, until: 0}` в `domain/grants/domain`; первого
пишет команда `domain first-admin` (P/08.4 Н1.9). `last_admin` (Н1.3) не даёт снять последнюю такую строку. Роли
(ADR-0098) прав на двери домена не дают. Проход по сроку (ADR-0098 §3, `expiry_kept`) не выключает человека, если не
останется ни одного с прямой строкой. При администраторе только через роль это условие верно всегда, и срок учётных
записей перестал бы действовать.

**Что у consolem.** Прототип 11 (`7428c34`): переключателя «Неограниченный доступ» больше нет; «Администратор» —
встроенная роль: у неё есть всё, права не меняются, удалить нельзя; флаг `unr` — только у неё, по нему сервер проверяет,
что администратор не пропадёт. consolem просит: сервер отвечает отказом на `unr` у любой другой роли. Управление
пользователями — функция обычной роли `USERS_RIGHTS_SETUP`.

**Что решил владелец.** (а) Встроенная роль администратора и проверка «никакое действие не оставит систему без
администратора». Право управлять пользователями — функцией обычной роли, без доступа к камерам и без власти над
встроенным администратором.

## Decision Drivers
* Кто администратор — видно в одном месте; полные права нельзя выдать случайно галочкой на любой роли.
* Домен нельзя запереть: ни правкой, ни истечением срока, ни гонкой двух правок.
* Управлять людьми и правами можно без доступа к системе.
* Управляющий пользователями не делает себя администратором — ни дверью, ни пакетом, ни через людей, которых он завёл.
* Смысл совпадает с consolem: роль `admin` ↔ встроенный «Администратор».

## Considered Options
* **(а) Одна встроенная роль `admin` и проверка «последний администратор».**
* (б) Признак «полные права» на любой роли и та же проверка.

Право на пользователей:
* **(а) Строка роли в `domain/grants/domain` — функция «управление пользователями»; встроенного администратора не трогает.**
* (б) Вторая встроенная роль «администратор пользователей».
* (в) Только прямые строки человека, как сегодня.

## Decision Outcome
Выбраны «(а)» и «(а)» (владелец, 2026-10-30). Почему не другие:
- (б) по администратору расходится с consolem: у них одна встроенная роль, и флаг только у неё. Несколько ролей с
  полными правами их интерфейс не покажет.
- (б) по пользователям не переводит consolem. `USERS_RIGHTS_SETUP` включается в любой роли вместе с её правами, а
  назначения второй роли пришлось бы держать в лад с назначениями первой.
- (в): управлять людьми можно только поштучными прямыми строками, без ролей и групп.

**Слова.** *Действующее назначение `admin`* — элемент `assigned` роли `admin` напрямую или через группу, у которого
`until = 0` или `now < until` (ADR-0098 §4). *Действующая прямая строка* — `{cap: admin, scope: *}` в
`domain/grants/domain` с `until = 0` или `now < until`. *Администратор домена* — человек с действующим назначением `admin`
или с действующей прямой строкой.

### 1. Встроенная роль `admin`
- Строка `domain/roles/admin` (ADR-0098 §2) есть всегда. Её пишет `domain first-admin` (§5). У прежних установок её
  пишет сверка прохода (Н3), но только при **подтверждённом отсутствии** строки. Нечитаемую строку проход не трогает,
  журнал раз в проход. Создавая её, сверка один раз назначает роль `admin` (`until: 0`) каждому человеку с действующей
  бессрочной прямой строкой. Строку ему оставляет: снять её может администратор. Имя `admin` занято за этой ролью:
  `POST /domain/roles` с этим именем — 409 exists.
- Изменять у неё можно только `assigned` (людей и группы, со сроком). `title`, `comment` — постоянные: их правка, как и
  `DELETE`, — 409 `builtin`. Строка гранта с `subject: role:admin` в любом документе — 400 bad line: прав строками у неё
  нет, ослабить её нечем (`none`, ADR-0099, к ней не применяется).
- `assigned` роли `admin` — не больше `ADMIN_ASSIGNED_MAX` элементов (число — норме), сверх — 409. В `ROLES_TABLE_MAX`
  (ADR-0098 §4) эти назначения не считаются.
- **Право.** Действующее назначение `admin` — разрешено всё:
  - в кластере — любая `sub` (в том числе `platform`), любая единица, `"*"`; исключения других ролей (ADR-0099) не
    действуют;
  - в домене — все двери процесса `domain` и консоли домена (люди, группы, роли, гранты, аварийные учётки).
- **`may`.** Новый шаг 4а после шага 4 (`stale`): у `user` действует назначение `admin` → allow.
  - Таблица ролей члена (ADR-0098 §4) несёт назначения `admin` **всегда**, независимо от строк в документе члена.
  - Строки `domain/grants/<член>` нет, а у роли `admin` есть действующие назначения — держатель шлёт агенту
    `grants: {doc: {lines: []}, as_of}` с таблицей. Шаг 3 видит пустой документ, а не `null`. Нечитаемая строка
    документа — не «нет»: 503, как сегодня.
  - Таблица «нечитаема» (ADR-0098 §4) и прямые строки не разрешили — 503 `unavailable`, а не 403.
  - У процесса `domain` и консоли домена вход `roles` — из строк ролей и групп держателя, `as_of = null`. Нечитаемая
    `domain/roles/admin` или группа из её `assigned` — то же 503, если прямые строки не разрешили.
- **Прямая строка `{admin, *}` в `domain/grants/domain`** остаётся действующей формой (у прежних установок и для
  совместимости): даёт двери домена, как сегодня, и считается в §2. Новые установки её не пишут.
- **`GET /session`** несёт признак `admin: true`, когда действует шаг 4а. Это поле ответа, а не сохранённая строка.
  Модуль консоли (P/07) по нему ничего не скрывает.
- **Двери у консоли кластера, где сегодня `admin` кластера стоит вместо администратора домена**, — `POST /domain/move`
  (P/06.7, P/08.8 Н1.8) и подобные. Их `need` — шаг 4а по таблице этого кластера; строки `admin` кластера недостаточно,
  её выдаёт и управляющий (§3).

### 2. Последний администратор (заменяет P/08.4 Н1.3 `last_admin`, ADR-0098 §5 «`last_admin` не меняется» и правило `expiry_kept` ADR-0098 §3)
- **Доказанный администратор** — человек, у которого:
  - строка `domain/users` читается; `disabled = false`; `expires = 0`;
  - имени нет в `domain/disabled`; метки `domain/deleting/<имя>` нет;
  - есть **бессрочное** (`until = 0`) назначение `admin` — прямо или через читаемую группу — либо прямая строка
    `{admin, *, until: 0}` в `domain/grants/domain`.
  Нечитаемая `domain/roles/admin` — администраторов по роли нет.
- Только бессрочные: администратор со сроком учётной записи или назначения не считается — иначе домен запирался бы сам,
  по истечении, без правки, которую можно отклонить.
- **Проверка двери** — после каждой правки, которая может убрать доказанного администратора: человек (`disabled`,
  `expires`, `DELETE`), группа (`members`, `DELETE`), роль `admin` (`assigned`), `domain/grants/domain`. Нет ни одного —
  409 last admin, ничего не записано. Нечитаемые строки — как сегодня: человека «есть» для сверок, но администратором он
  не считается. Дверь пакета (ADR-0097 §8.5) проверяет итог пакета целиком.
- **Проход по сроку** не пишет имя в `domain/disabled` по сроку, если после этого не останется ни одного доказанного
  администратора. Так же — при неизвестном доказательстве (нечитаемые строки). Человек остаётся включённым, журнал
  `domain.user.expiry_kept {name}` раз в проход. Доказанный администратор бессрочен, поэтому в штатном состоянии правило
  не срабатывает. Это защита от аномалии (восстановление, старый писатель).
- **Сериализация — стражи доказательства.** Запись, прошедшая проверку, несёт в пакете B9 стражей версий строк,
  доказывающих хотя бы одного оставшегося администратора:
  - его строку `domain/users`;
  - `domain/disabled`;
  - отсутствие `domain/deleting/<имя>` (страж `index: ""`);
  - `domain/roles/admin` и строку группы, через которую идёт назначение, — либо `domain/grants/domain` для прямой
    строки.
  Конфликт стража — проверка с начала по свежему чтению, как стражи ссылок ADR-0098 §5. Предел повторов и ответ после
  него (503 `unavailable`) — норме. Две параллельные правки разных строк (группы G1 и G2, или роль `admin` и
  `domain/grants/domain`) так не уводят домен в ноль: каждая сторожит строку, которую меняет другая.
- **Без администратора.** Доказанных администраторов может не остаться после восстановления, когда применён `state`
  (P/08.8 Н1.8), или после аномалии. Тогда домен работает, перенос не останавливается, журнал `domain.no_admin` раз в
  проход. Путь назад — команда держателя `domain grant-admin <имя>` (через `admin.sock` держателя, как `first-admin`).
  Она действует только при нуле доказанных администраторов, иначе отказ. Команда назначает роль `admin` бессрочно
  существующему человеку и снимает с него `disabled`, `expires` и имя в `domain/disabled`.

### 3. Управление пользователями — строка роли в `domain/grants/domain`
- В `domain/grants/domain` разрешена строка роли **одной формы**: `{subject: role:<R>, cap: admin, scope: *, until}` — без
  `sub`, без `folder:`, `R ≠ admin`. Иные строки ролей там — 400 bad line (ADR-0098 §2 в остальном в силе).
- **Даёт** («управляющий пользователями»):
  - двери людей, групп, ролей и `PUT /domain/grants/<кластер>` (гранты кластеров);
  - контактные поля людей (`email` и прочие поля карточки, ADR-0098 §3). Их видят администратор домена и управляющий,
    а остальные — только в своём элементе.
  Прав в кластерах не даёт: камеры и архив — только строками роли в документах кластеров.
- **Не даёт** — 403 `{error: "admin only"}`:
  - назначать и снимать `admin` (`PUT /domain/roles/admin`);
  - менять, выключать, удалять администратора домена (§«Слова»), менять ему пароль, срок, имя;
  - менять состав группы с действующим назначением `admin`, удалять её;
  - писать `domain/grants/domain`: иначе он дал бы себе прямую строку или роль управляющего другому. Сюда же
    `DELETE /domain/roles/R`, если у `R` есть строка в `domain/grants/domain`;
  - двери аварийных учёток (`/domain/break-glass…`).
  Эти двери — только администратору домена.
- **Статус цели — три исхода.** Проверка «admin only» считает статус цели по исходным строкам (`domain/roles/admin`,
  группы из её `assigned`, `domain/grants/domain`), а не по отфильтрованной таблице `may`:
  - доказано, что цель — администратор домена: 403 `admin only`;
  - доказано, что нет (все эти строки читаются, и ни одна не даёт): разрешено в пределах роли;
  - иначе — 503 `unavailable`, ничего не записано.
  Запись несёт стражей версий этих строк, в том числе подтверждённого отсутствия (§2 «Сериализация»).
- **Дверь пакета** (ADR-0097 §8.5, ADR-0098 §6) применяет перечень к каждой строке, которую пакет **меняет**:
  - цель защищена до пакета или станет защищённой после него;
  - пакет меняет `assigned` роли `admin`, `domain/grants/domain` или строку аварийной учётки.
  Любая такая строка у управляющего — 403 `admin only` на весь пакет, ничего не записано. Строки снимка, которые пакет
  не меняет, не проверяются: consolem шлёт состояние целиком.
- **Повышение не передаёт управляющему администратора** (владелец, разбор ревью):
  - **токены:** токен человека, выпущенный раньше `at` его действующего назначения `admin` (напрямую или вхождения в
    группу с ним), шагу 4а и дверям «admin only» не служит;
  - **пароль:** строка человека несёт `pw_by`, имя того, кто последним задал пароль. Пишется при `first-admin`,
    `POST /domain/users`, смене пароля; строка без поля читается как «задал не администратор». Назначение `admin`
    человеку, у которого `pw_by` — не он сам и не администратор домена, — 409 `password set by a non-admin` (слово —
    норме). То же при включении такого человека в группу с назначением `admin` и при назначении `admin` группе с таким
    членом. Администратор сначала меняет пароль, потом назначает.
- **Предел.** Управляющий пользователями может выдать любые права в кластерах, в том числе себе: создать роль с полным
  доступом к камерам и назначить её себе. Закрыто одно: стать администратором домена. Каждая правка — в журнале с `by`
  (P/08.4 Н2 «Журнал», ADR-0098 §6).
- `may` процесса `domain` и консоли домена: шаги по `domain/grants/domain` с группами ADR-0099 (строка роли — своя
  группа), затем проверка «admin only» двери.

### 4. Перевод consolem (информативно; норма — V/11)
| consolem | платформа |
|---|---|
| встроенная роль «Администратор» (`unr`) | роль `admin`; назначения — `assigned` |
| `unr` у любой другой роли | `422 NOT_SUPPORTED` (`/access/apply`) |
| `USERS_RIGHTS_SETUP` в роли `R`, `ur: ALL` | строка `role:R admin *` в `domain/grants/domain` |
| `USERS_RIGHTS_SETUP` с `ur: NO` | `422 NOT_SUPPORTED` до ответа продукта |
| `ur: DEV` («права на права» только на свои устройства, по подписи) | `422 NOT_SUPPORTED` — выдачи в пределах своих прав у платформы нет (ADR-0098 §8.4) |
| инвариант «остаётся включённый администратор» | §2 (проверку делает платформа; `backend` не дублирует) |
| `SELF_LOCKOUT` на `/access/apply` (администратор снимает себя, даже при втором) | проверка V/11 в `backend` поверх §2, по контракту продукта |

Что именно разрешает `USERS_RIGHTS_SETUP` у consolem (может ли такой человек назначать «Администратора», менять
администраторов) — «Запрос продукту» ниже; до ответа — §3.

### 5. Порядок
1. **`first-admin`** пишет одним пакетом B9 три строки: человека с `pw_by` = он сам, `domain/roles/admin` с
   `{person: <имя>, until: 0}`, пустой `domain/grants/domain` (`{lines: []}`), если его нет. Пакет записан целиком или
   не записан, повтор после обрыва доводит. Прямой строки домена не пишет.
2. Нормы и код — одним приращением с ADR-0097, ADR-0098, ADR-0099 (после зачёта B).
3. «Спецификация» (уроки 08–10):
   - P/08.4 Н1.1 (`expires`, проход по сроку §2, `pw_by`), Н1.3 (`last_admin` §2 со стражами, строка роли в
     `domain/grants/domain`, таблица и пустой документ), Н1.9 (`first-admin` §5 п. 1, `grant-admin`), Н2 (`admin only`
     с тремя исходами и по разнице пакета, `builtin`, `ADMIN_ASSIGNED_MAX`, `password set by a non-admin`), Н3 (сверка
     `domain/roles/admin`);
   - договор `may` (шаг 4а, 503 при нечитаемой таблице);
   - P/06.7 и P/08.8 Н1.8 (`need` дверей администратора домена, исход восстановления без администратора);
   - P/07 и `GET /session` (`admin: true`);
   - P/10 (консоль домена).
4. «Спецификация VMS»: V/11 — перевод §4, `SELF_LOCKOUT`.
5. Пометки «дополняется/заменяется»: ADR-0097 §7 (`unr`), ADR-0098 §2, §3, §4, §5, §8.4, ADR-0099 §7.

### Consequences
* Good, because администраторы — назначения одной роли: видно кто, случайно не выдать.
* Good, because домен не запереть ни правкой, ни сроком, ни гонкой: считаются только бессрочные, доказательство
  сторожится, а без администратора есть команда держателя.
* Good, because людьми и правами можно управлять без доступа к камерам; администратором так не стать ни дверью, ни
  пакетом, ни повышением своих людей.
* Good, because совпадает с встроенным «Администратором» consolem и их просьбой отвергать `unr` у других ролей.
* Bad, because `last_admin` проверяется на правках групп и назначений, со стражами нескольких строк и повтором.
* Bad, because у дверей домена — проверка «admin only» по цели правки, с отказом 503, когда статус цели не установить.
* Bad, because управляющий пользователями может выдать себе любые права в кластерах и видит почту всех людей; защита —
  журнал.
* Bad, because повысить до `admin` человека, которому пароль задал управляющий, можно только после смены пароля
  администратором.
* Neutral, because прямая строка `{admin, *}` в `domain/grants/domain` остаётся вторым видом администратора; прежним
  таким администраторам сверка назначает роль.

### Confirmation
* Векторы `may`:
  - назначение `admin` — allow на любой `sub` и `"*"`, в том числе при `none` другой роли;
  - истёкшее назначение — нет;
  - выключенный — deny disabled;
  - давняя копия — deny `stale`;
  - нечитаемая таблица без прямых строк — 503;
  - строки документа нет, назначение есть — allow по пустому документу;
  - токен выпущен раньше `at` назначения — нет.
* Приёмка P/08.4:
  - `DELETE /domain/roles/admin` и правка `title` — 409 `builtin`; строка `role:admin` — 400;
  - последний администратор: выключение, `expires`, снятие из группы, снятие назначения, срок назначения — 409; второй
    бессрочный есть — 200; два параллельных снятия из разных групп — одно 200, другое 409;
  - проход по сроку: администратор только по роли, у обычного `u` истёк срок — `u` выключен;
  - управляющий пользователями:
    - человек без `admin` — 200; с `admin` — 403 `admin only`;
    - роль `admin` или группа испорчены — 503;
    - `PUT /domain/roles/admin` — 403; запись `domain/grants/domain` — 403; гранты кластера — 200;
    - пакет с собой в «Администраторе» — 403; тот же пакет от администратора — 200;
  - назначение `admin` человеку с паролем от управляющего — 409, после смены пароля администратором — 200;
  - `first-admin` — одним пакетом; `grant-admin` при нуле — 200, при доказанном администраторе — отказ;
  - `/domain/move` по строке `admin` кластера, выданной управляющим, — отказ.
* Ревью — тремя (разбор `decisions/inbox/2026-10-30-ревью-ADR-0100-разбор.md`).
