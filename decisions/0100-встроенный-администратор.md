# Встроенная роль `admin`, «последний администратор» по ролям, управление пользователями ролью

Дополняет ADR-0098 и заменяет в нём: §2 «в `domain/grants/domain` строк ролей нет» (частично, §3 ниже), §5 «`last_admin` не меняется», §8.4 (частично). Заменяет
строку `unr` ADR-0097 §7.

## Context and Problem Statement
Класс системы: платформенная система (люди, роли, гранты домена, `may`). Потребитель первым — `backend` (consolem).

**Как сейчас.** Администратор домена — человек с прямой строкой `{admin, *, until: 0}` в `domain/grants/domain`; первого
пишет команда `domain first-admin` (P/08.4 Н1.9). `last_admin` (Н1.3) не даёт снять последнюю такую строку. Роли
(ADR-0098) прав на двери домена не дают. Пробел ADR-0098: срок учётной записи (`expires`) последнего администратора
истекает сам, без правки, — `last_admin` этого не видит.

**Что у consolem.** Прототип 11 (`7428c34`): переключателя «Неограниченный доступ» больше нет; «Администратор» —
встроенная роль: у неё есть всё, права не меняются, удалить нельзя; флаг `unr` — только у неё, по нему сервер проверяет,
что администратор не пропадёт. consolem просит: сервер отвечает отказом на `unr` у любой другой роли. Управление
пользователями — функция обычной роли `USERS_RIGHTS_SETUP`.

**Что решил владелец.** (а) Встроенная роль администратора и проверка «никакое действие не оставит систему без
администратора». Право управлять пользователями — функцией обычной роли, без доступа к камерам и без власти над
встроенным администратором.

## Decision Drivers
* Кто администратор — видно в одном месте; полные права нельзя выдать случайно галочкой на любой роли.
* Домен нельзя запереть: ни правкой, ни истечением срока.
* Управлять людьми и правами можно без доступа к системе.
* Управляющий пользователями не делает себя администратором.
* Смысл совпадает с consolem: роль `admin` ↔ встроенный «Администратор».

## Considered Options
* **(а) Одна встроенная роль `admin` и проверка «последний администратор».**
* (б) Признак «полные права» на любой роли и та же проверка.

Право на пользователей:
* **(а) Строка роли в `domain/grants/domain` — функция «управление пользователями»; встроенного администратора не трогает.**
* (б) Вторая встроенная роль «администратор пользователей».
* (в) Только прямые строки человека, как сегодня.

## Decision Outcome
Выбраны «(а)» и «(а)» (владелец, 2026-10-30). (б) по администратору расходится с consolem (одна встроенная роль, флаг
только у неё): несколько ролей с полными правами их интерфейс не покажет. (б) по пользователям не переводит consolem:
`USERS_RIGHTS_SETUP` включается в любой роли вместе с её правами, а назначения второй роли пришлось бы держать в лад с
назначениями первой. (в) — управлять людьми можно только поштучными прямыми строками, без ролей и групп.

### 1. Встроенная роль `admin`
- Строка `domain/roles/admin` (ADR-0098 §2) есть всегда: её пишет `domain first-admin`, у прежних установок — сверка
  прохода (Н3), если строки нет. Имя `admin` занято за ней: `POST /domain/roles` с этим именем — 409 exists.
- Изменять у неё можно только `assigned` (людей и группы, со сроком). `title`, `comment` — постоянные; `DELETE` — 409
  `builtin`; строка гранта с `subject: role:admin` в любом документе — 400 bad line: прав строками у неё нет и ослабить
  её нечем (`none`, ADR-0099, к ней не применяется).
- **Право.** Действующее назначение `admin` (ADR-0098 §4: напрямую или через группу, срок не истёк) — разрешено всё:
  - в кластере — любая `sub` (в том числе `platform`), любая единица, `"*"`; исключения других ролей (ADR-0099) не
    действуют;
  - в домене — все двери процесса `domain` и консоли домена (люди, группы, роли, гранты, аварийные учётки).
- **`may`.** Новый шаг 4а после шага 4 (`stale`): у `user` действует назначение `admin` → allow. Таблица ролей копии
  (ADR-0098 §4) несёт назначения `admin` каждому кластеру, хотя строк у роли нет. У процесса `domain` и консоли домена
  вход `roles` — из строк ролей и групп держателя, `as_of = null`.
- **Прямая строка `{admin, *}` в `domain/grants/domain`** остаётся действующей формой (у прежних установок и для
  совместимости): она даёт двери домена, как сегодня, и считается администратором в §2. Новые установки её не пишут:
  `first-admin` назначает роль.

### 2. Последний администратор (заменяет P/08.4 Н1.3 `last_admin` и ADR-0098 §5 «`last_admin` не меняется»)
- **Доказанный администратор** — человек, у которого: строка `domain/users` читается; `disabled = false`; `expires = 0`;
  имени нет в `domain/disabled`; метки `domain/deleting/<имя>` нет; и есть **бессрочное** (`until = 0`) назначение `admin`
  — прямо или через читаемую группу — либо прямая строка `{admin, *, until: 0}` в `domain/grants/domain`.
- Только бессрочные: администратор со сроком учётной записи или назначения не считается — иначе домен запирался бы сам,
  по истечении, без правки, которую можно отклонить. Это закрывает пробел ADR-0098 §3.
- **Проверка** — после каждой правки, которая может убрать доказанного администратора: человек (`disabled`, `expires`,
  `DELETE`), группа (`members`, `DELETE`), роль `admin` (`assigned`), `domain/grants/domain`. Нет ни одного — 409 last
  admin, ничего не записано. Нечитаемые строки — как сегодня: человека «есть» для сверок, но администратором он не
  считается.
- Дверь пакета (ADR-0097 §8.5) проверяет итог пакета целиком, а не каждую строку.

### 3. Управление пользователями — строка роли в `domain/grants/domain`
- В `domain/grants/domain` разрешена строка роли **одной формы**: `{subject: role:<R>, cap: admin, scope: *, until}` — без
  `sub`, без `folder:`, `R ≠ admin`. Иные строки ролей там — 400 bad line (ADR-0098 §2 в остальном в силе).
- **Даёт** («управляющий пользователями»): двери людей, групп, ролей и `PUT /domain/grants/<кластер>` (гранты кластеров).
  Прав в кластерах не даёт: камеры, архив — только строками роли в документах кластеров.
- **Не даёт** — 403 `{error: "admin only"}`:
  - назначать и снимать `admin` (`PUT /domain/roles/admin`);
  - менять, выключать, удалять человека с действующим назначением `admin` или с прямой строкой домена, менять ему
    пароль, срок, имя;
  - менять состав группы, которой назначена `admin`, удалять её;
  - писать `domain/grants/domain` (иначе — дать себе прямую строку домена или роль управляющего другим);
  - двери аварийных учёток (`/domain/break-glass…`).
- Эти двери — только встроенной роли `admin` или прямой строкой домена.
- **Предел.** Управляющий пользователями может выдать любые права в кластерах, в том числе себе: создать роль с полным
  доступом к камерам и назначить её себе. Закрыто одно: стать администратором. Каждая правка — в журнале с `by`
  (P/08.4 Н2 «Журнал», ADR-0098 §6).
- `may` процесса `domain` и консоли домена: шаги по `domain/grants/domain` с группами ADR-0099 (строка роли — своя группа)
  плюс проверка «admin only» двери после `may`.

### 4. Перевод consolem (информативно; норма — V/11)
| consolem | платформа |
|---|---|
| встроенная роль «Администратор» (`unr`) | роль `admin`; назначения — `assigned` |
| `unr` у любой другой роли | `422 NOT_SUPPORTED` (`/access/apply`) |
| `USERS_RIGHTS_SETUP` в роли `R`, `ur: ALL` | строка `role:R admin *` в `domain/grants/domain` |
| `ur: DEV` («права на права» только на свои устройства, по подписи) | `422 NOT_SUPPORTED` — выдачи в пределах своих прав у платформы нет (ADR-0098 §8.4) |
| инвариант «остаётся включённый администратор» | §2 (проверку делает платформа; `backend` не дублирует) |

Что именно разрешает `USERS_RIGHTS_SETUP` у consolem (может ли такой человек назначать «Администратора», менять
администраторов) — «Запрос продукту» ниже; до ответа — §3.

### 5. Порядок
1. Нормы и код — одним приращением с ADR-0097, ADR-0098, ADR-0099 (после зачёта B).
2. «Спецификация домена»: P/08.4 Н1.1 (`expires` и доказанный администратор), Н1.3 (`last_admin` §2, строка роли в
   `domain/grants/domain`), Н1.9 (`first-admin` назначает роль), Н2 (`admin only`, `builtin`), Н3 (сверка: строка
   `domain/roles/admin`); договор `may` (шаг 4а); P/10 (консоль домена).
3. «Спецификация VMS»: V/11 — перевод §4.
4. Пометки «дополняется/заменяется» в ADR-0097 §7 (`unr`) и ADR-0098 §2, §5, §8.4 («Архитектор»).

### Consequences
* Good, because администраторы — назначения одной роли: видно кто, случайно не выдать.
* Good, because домен не запереть ни правкой, ни сроком: считаются только бессрочные.
* Good, because людьми и правами можно управлять без доступа к камерам; администратором так не стать.
* Good, because совпадает с встроенным «Администратором» consolem и их просьбой отвергать `unr` у других ролей.
* Bad, because `last_admin` проверяется на правках групп и назначений, а не только людей и строки домена.
* Bad, because у дверей домена — проверка «admin only» по цели правки (человек, группа, роль).
* Bad, because управляющий пользователями может выдать себе любые права в кластерах; защита — журнал.
* Neutral, because прямая строка `{admin, *}` в `domain/grants/domain` остаётся вторым видом администратора.

### Confirmation
* Векторы `may`: назначение `admin` — allow на любой `sub`, `"*"`, при `none` другой роли; истёкшее назначение — нет;
  выключенный — deny disabled.
* Приёмка P/08.4: `DELETE /domain/roles/admin` — 409; строка `role:admin` — 400; последний администратор: выключение,
  `expires`, снятие из группы, снятие назначения, срок назначения — 409; второй бессрочный есть — 200; управляющий
  пользователями: человек без `admin` — 200, с `admin` — 403 admin only, `PUT /domain/roles/admin` — 403, запись
  `domain/grants/domain` — 403, гранты кластера — 200; `first-admin` назначает роль.
* Ревью — тремя.

## Запрос продукту (через «Консоль», с «пушь» владельца; в шестой запрос)
1. Встроенная роль «Администратор» — берём. Наш сервер на `unr` у любой другой роли отвечает `422 NOT_SUPPORTED`;
   просим записать этот отказ в контракт.
2. Что разрешает `USERS_RIGHTS_SETUP`: назначать и снимать «Администратора», менять, выключать, удалять пользователей с
   ним? У нас — нет (§3). Как с ней связан `RoleGlobal.ur` (`NO`, `DEV`, `ALL`): `DEV` — выдавать права только на свои
   устройства? У нас — только `ALL`, `DEV` — `NOT_SUPPORTED`.
