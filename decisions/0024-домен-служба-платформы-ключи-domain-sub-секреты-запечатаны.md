# Домен — служба платформы; вклад подсистемы под `domain/<подсистема>/`; секреты домена запечатываются первой задачей

## Context and Problem Statement
Класс системы: платформенная система (слой над кластерами).

Домен назывался `vmsdomain`/`vmsagent`, лежал среди кода VMS и считался частью VMS-приложения. При этом держатель и его срок, перенос, доверие (корень, ключи, сертификаты членов), пользователи и права, аварийный доступ, общий вид по отчётам агентов и правки, уносимые агентом, нужны любой подсистеме. Ключи хранилища, которые приносит VMS (`domain/crossings`, `domain/sources/…` и подобные), лежали без имени подсистемы в пути. Попутно «Сборка» нашла, что секреты домена — пароли пользователей, RTSP-учётки, аварийный пароль, ключ подписывающего — лежат в хранилище открыто и не учитываются в `secrets seal|rotate|status`.

## Decision Drivers
* ADR-0001: платформа знает только спеки; служба, нужная любой подсистеме, — платформа;
* ключ вклада подсистемы должен называть подсистему, чтобы вторая подсистема легла рядом;
* открытый секрет в хранилище — дыра, не вопрос имён;
* обратная совместимость не держится (ADR-0003).

## Considered Options
* домен остаётся частью VMS, ключи `domain/*` без имени подсистемы, секреты запечатываются вместе с переносом домена;
* домен — служба платформы, вклад подсистемы — под `domain/<подсистема>/…` без переходного периода, секреты запечатываются отдельной задачей и первыми.

## Decision Outcome
Выбран второй вариант.
* Домен — служба платформы: `domain` и `domainagent` (бывшие `vmsdomain`, `vmsagent`), юниты `w2c-domain`, `w2c-domainagent`, пакеты `w2cplatform/domain`, `w2cplatform/trust`, роли `urn:w2c:role:domain`, `urn:w2c:role:domainagent`. Управление ключом платформы уходит из `vmsctl` в `w2cctl`.
* Вклад VMS (книги источников и основных, crossings, куда толкать поток, RTSP-учётки, сценарии) лежит под `domain/vms/…`; платформенные ключи домена остаются `domain/…`. Префикс `domain/<подсистема>/` даёт домен, подсистема имён не пишет. Переименование без переходного периода, данные стенда перенесены разово.
* Секреты домена запечатываются тем же кольцом ключей, что строки камер и томов, учитываются в `secrets seal|rotate|status`; задача идёт первой, не дожидаясь переноса домена.

### Consequences
* Good, because вторая подсистема получает домен без правки платформы, а её ключи не смешиваются с ключами VMS.
* Good, because ни один секрет домена не лежит в хранилище открытым.
* Bad, because разовая миграция ключей `domain/*` на всех установках и смена имён бинарников, юнитов, переменных окружения.
* Bad, because ключ подписывающего живёт только у держателя, а резервная копия едет к хранителям — общим кольцом его запечатать нельзя без решения о корне вне держателя.

### Confirmation
Тест «ничего открытого в хранилище» по всем секретным строкам платформы и подсистем (ветка продукта `r23-seal`); `w2cplatform/domain` не импортирует `vms` (тест границы); ключи вклада VMS только под `domain/vms/` (ветка `r23-domain`).

## Pros and Cons of the Options

### Домен остаётся частью VMS
* Good, because ничего не переносить.
* Bad, because каждая новая подсистема правит код домена; секреты ждут переноса.

### Домен — служба платформы, секреты первыми
* Good, because граница совпадает с ADR-0001, дыра закрыта сразу.
* Bad, because миграция ключей и имён.

## More Information
