# Схемы семей данных — источник в диалекте ADR-0087 у урока-владельца; один кодек строк; форма хранилища — шаг матрицы

## Context and Problem Statement
Класс системы: платформенная система — строки и объекты хранилища, через которые говорят микромодули «Платформы»
(ADR-0083: контракт «данные», каталог `Platform/common/data/catalog.tsv`). Стадия A, пункт A5.

Форму строк сейчас задаёт проза норм урока-владельца: псевдо-YAML в Н1 и пояснения к нему. Каждая реализация переводит
её в код сама. Колонка `schema` каталога у всех 117 строк — `-`. Записка «Схема строк хранилища»
(`/Users/murat/Downloads/ПРЕДЛОЖЕНИЕ-СХЕМА-СТРОК-ХРАНИЛИЩА.md`) предложила описать каждую строку логической схемой с
одним кодеком. Пилот (`/Users/murat/w2c/cammeta-schema-pilot/data/REPORT-data.md`) проверил это на JSON Schema:
32 семьи, 1215 строк, 34 756 экземпляров обеих реализаций и смесей. Схемы поймали пять расхождений, которые ломали
смешанные пары при зелёной приёмке одной реализации: X1 (`backup-taken` строками), X2 (`backup_key_rev` строкой), A3
(`domain/shared` текстом в отчёте), A13 (`cut_before: null`), R1 (`outcomes: {}`). Ещё семь мест формы (Д1–Д7) нормы
не называли; они внесены нормами (ход «добавлено пилотом схем семей данных»).

ADR-0087 п. 7 решил: схемы строк — тот же диалект и принцип «источник», отдельным ADR после формы спеки. Пилот же
рекомендовал статус ADR-0085 — проверку рядом с нормой на JSON Schema. Нужно выбрать статус, запись, кодек и место
проверки.

## Decision Drivers
* форма строки записывается один раз; проза, приёмка и реализации её не переводят каждый раз заново;
* расхождения формы, которые видны только в смешанной паре, ловит машина, а не следующая сверка;
* одно определение «строка нечитаема» вместо своего у каждого урока;
* в проверке нет чужого кода, решающего вердикт (выводы пилотов B и данных: `multipleOf`, `\s`, путь
  `propertyNames`, «целый знак»);
* перенос урока не меняет поведения (ADR-0083 доп. (1)).

## Considered Options
* схемы JSON Schema рядом с нормой как проверка (рекомендация пилота, статус ADR-0085);
* источник в диалекте ADR-0087 у урока-владельца; раздел формы строк строится из него; один кодек;
* без схем: проза и чтение строк в приёмке, как сейчас;
* числа прямо в хранилище (`items` — значения JSON, шаг 2 записки).

## Decision Outcome
Выбран вариант «источник в диалекте ADR-0087»: он один даёт одну запись формы без третьего описания и без чужого
валидатора в вердикте, а пилот показал, что схема строк ловит то, что приёмка одной реализации пропускает.

1. **Источник.** Каждая семья каталога — файл `NN-<процесс>/data/<семья>.form.yaml` урока-владельца в диалекте
   ADR-0087; колонка `schema` каталога называет его. Общие определения (время, `Entry`, `Outcome`, пульс и т. п.) —
   `Platform/common/data/common.form.yaml`. Байты — «Спецификация» (ADR-0080 доп. 16); источник входит в выгрузку.
   Форма записки каталога (`.schema.json` в колонке `schema`) правится под это.
2. **Экземпляр** — обёртка `{key, row}` для строки и `{key, object}` для объекта. Ключ проверяется грамматикой колонки
   `key` каталога.
3. **Кодек — один на платформу**, таблица `Platform/common/data/codec.tsv`: логический тип узла → запись в `items`
   (`integer`, `number`, `boolean`, `time`, список по правилу урока 3, `json` — канонический JSON ADR-0072, `string`).
   Два режима: **писатель** (время — до 3 знаков дроби, канонический список, целый знак) и **читатель** (терпимый:
   время любой длины). Целые в JSON-полях: писатель — целый знак (JCS так и пишет), читатель — по значению; где норма
   требует целый знак и у читателя (пульс `schema`, T3/T27), это правило урока-владельца пульса.
4. **«Нечитаемо»** — строка не раскодировалась или не прошла схему в режиме читателя; путь отказа входит в
   определение. Что делать с нечитаемой строкой, решает урок-владелец (Н4 урока 3: нечитаемый `gen` не заменять
   нулём).
5. **Слова диалекта** (словарь заморожен, ADR-0087 п. 2; это решение владельца):
   * тип `time` — логическое время М10/1 Н0 «Время в строке»;
   * пометка поля `encoding: json` — в `items` лежит текст JSON (`doc`, `certs`); снимает неоднозначность «список
     урока 3 или массив JSON» (пилот § 8);
   * ссылка на общий файл `ref: common.<имя>`.

   Режим читателя строится из того же файла: кодек читателя; закрытые `properties` открываются только после правки
   поведения «терпимый читатель» урока-владельца (ADR-0083 п. 3, доп. (1)).
6. **Что схема не выражает** (около 25 правил на 30 семей: подписи и `record`, суммы `sha256`, связь «метка —
   поколение», порядок массивов, повтор по части полей, монотонность, секреты внутри копии) — остаётся нормой урока и
   векторами. Что из этого выражается языком отношений ADR-0087, решает перенос урока.
7. **Проверки.** `check_spec`: у строки каталога с файлом схемы файл есть и строится; раздел формы строк урока
   строится из источника и совпадает с уроком байт в байт; корпус примеров строк по семьям (принятые и отказанные).
   Раннеры матрицы (A1): шаг «форма хранилища» — после сценария прочитать строки и объекты стенда, раскодировать и
   проверить в режиме писателя; то, что положил сам стенд, помечено и в вердикт не входит; смешанный шаг «передача
   py↔go» уроков 10–11.
8. **Когда.** Стадия A — это решение. Стадия B — урок-владелец в коммите своего переноса пишет схемы своих семей и
   заменяет псевдо-YAML норм построенным разделом; кодек и `common.form.yaml` — с переносом урока 1. До переноса
   урока матрица может гонять схемы пилота как средство поиска (находка — «Архитектору», не красный шаг); схема пилота
   семьи снимается, когда приходит источник урока. Стадия C — генераторы строят проверку строк из источника тем же
   построителем, что форму спеки (ADR-0087 п. 5).
9. **Числа прямо в хранилище** (шаг 2 записки) — не сейчас; если понадобится, отдельным ADR после схем.

### Consequences
* Good, because форма строки записана один раз: урок, приёмка и реализации строятся из неё.
* Good, because класс расхождений X1, X2, A3, A13, R1 ловит шаг матрицы, а не сверка после ошибки.
* Good, because «нечитаемо» определено один раз, ответ на порчу остаётся у урока-владельца.
* Good, because в вердикте нет чужого валидатора: различия библиотек пилота (`multipleOf`, `\s`, `vloc`, «целый
  знак») не входят в норму.
* Bad, because три новых слова диалекта — работа в каждом построителе и описании диалекта.
* Bad, because объём: около 1200 строк источника на 32 семьи и общий файл; псевдо-YAML норм большинства уроков
  заменяется построенным разделом.
* Bad, because около 25 правил на семью схемой не выражаются и остаются прозой; форма строки живёт в двух местах до
  переноса урока-владельца.
* Bad, because до стадии C реализации не используют источник, проверка — только в раннерах и `check_spec`; схемы
  пилота на переходе — временный третий источник, который нужно снять.

### Confirmation
* К концу стадии B у каждой строки каталога колонка `schema` называет файл, и он строится.
* Шаг матрицы «форма хранилища» зелёный на обеих реализациях и на смесях.
* Корпус строк держит пять расхождений пилота (X1, X2, A3, A13, R1) отказанными случаями из сырья пилота
  (`data/runs/raw-gz/`); построенная проверка их отказывает с путём.
* `check_spec` находит построенный раздел формы строк в уроке байт в байт.

## Pros and Cons of the Options

### JSON Schema рядом с нормой (пилот)
* Good, because готово: схемы и валидаторы пилота работают, 0 расхождений валидаторов на данных.
* Bad, because третье описание формы, которое держат руками (то же, что разбор ADR-0085).
* Bad, because пробы пилота: `multipleOf` у Python, `\s` ECMA против RE2, путь `propertyNames` v6, «целый знак» —
  правки и исключения в чужом коде.

### источник в диалекте ADR-0087
* см. Consequences.

### без схем
* Good, because нет новой работы.
* Bad, because пять расхождений, ломавших пары, приёмка одной реализации пропустила.

### числа в хранилище
* Good, because кодек исчезает, тип виден в данных.
* Bad, because меняет Н1 урока 1 и всё, что на нём стоит, у обеих реализаций, продукта и записанных строк сразу.
