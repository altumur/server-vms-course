# Запрос: запись в каталоге домена — `domain.ref` у `rec` и исполнители назначения в виде

**Что нашлось.** Манифест `rec` без `domain.ref` вне каталога домена (P/08.1 Н1.2 `no_ref`, `08.1-domain.norms.md:74`):

- дверь `PUT /domain/placement/rec/<ref>` — 404 «нет манифеста или без `domain.ref`» (P/08.6 Н2, `08.6-domain.norms.md:275`),
  значит записей `domain/placement/rec/*` нет и `domain/placed/rec/` у членов пуст;
- токен `cam.stream` (`placement: {sub: rec, …}`, V/01.6 Н1.3) не выдаётся никогда (`no_assignment`, P/08.7 Н3 шаг 5) —
  камера не толкает ни в один приёмник;
- пульсы `rec` не идут в отчёт члена (P/09.1 Н1.2 `member_objects`, `09.1-agent.norms.md:162`), теневой отчёт (P/08.1
  Н1.6) записи не видит; `domain.edit` записи мёртв (P/08.6 Н1.3 — 404).

V/01.6 и V/02.9 построены на назначении `domain/placement/rec/<ref камеры>`: `cluster` — кластер записи, `origin` —
кластер камеры, `copies` — кластеры резервов. Это подсистема чинит сама: `rec` объявляет `domain.ref: ref`, у записи —
поле `ref` (`fixed`, необязательное) — `ref` её камеры в домене; запись без `ref` — только своего кластера.

**Какая норма мешает.** Тогда основная запись в кластере `cluster` и резервная в кластере из `copies` дают один `ref` из
двух членов — P/08.1 Н3 шаг 4 (`08.1-domain.norms.md:426`): «ref, который дают два члена и больше → contested, единицы этого
ref из units снять», `complete: false`. Теневой отчёт того же прохода (Н1.6 `conflict`, `:179–180`) такие заявки спором не
считает: «у двух членов, не все из которых — исполнители назначения ref». Вид и теневой отчёт расходятся: законное
размещение по назначению (`cluster` + `copies`) — спор в виде.

Второе: строка единицы без значения поля `domain.ref` (запись только своего кластера) — что с ней в виде, не сказано
(`units[].ref` — «не из `""`», `08.1-domain.norms.md:265`).

**Что нужно VMS.** Камера `SN4471` кластера-камеры, основная запись в кластере `site`, резервная — в `dc` (назначение
`{cluster: site, origin: cam-sn4471, copies: [dc]}`): вид домена полон, обе записи в `units`, спора нет; запись `7` кластера
`site` без `ref` в виде отсутствует и вид не портит.

**Обход до решения.** V/02.9 Н1.1: `domain.ref: ref` у `rec`, поле `ref` у записи, назначение — по `ref` камеры; камера с
резервом в другом кластере — `contested` в виде (вид неполон) — строка долга в `ХОД-Спецификация-VMS.md`; запись без `ref`
в снимок идёт без поля (как прочие поля без значения).

**Второе — свежесть принесённого.** Резерв на карте камеры решает по копии книги `domain/rec/primaries` (V/02.9 Н1.6):
копия старше 45 с (агент не дотягивается до домена) — писать, а не верить «пишется». Отметки времени у копии книги нет;
момент последнего ответа домена — объект `domain/reached {ts}` (P/09.1 Н1.7), читатель по каталогу — только `domainagent`
(`catalog.tsv:84`). Обход: регистратор верит копии как свежей (строка долга); поток (`uncovered` приёмника) решает раньше книги.

**Рекомендация.** P/08.1 Н3 шаг 4: ref, который дают два члена и больше, — `contested`, кроме случая, когда все они —
исполнители назначения этого ref (`cluster` и `copies`, P/08.6 Н1.1) — то же правило, что `conflict` теневого отчёта;
P/08.1 Н1.2: строка без значения поля `domain.ref` (нет поля или `""`) — не единица домена (в `units` её нет, вид полноты
не теряет); каталог `domain/reached`: читатели — ещё `<s>worker`, объявивший его в `worker.reads` (как копии книг, P/02.5 Н1.4).
