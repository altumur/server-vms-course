## Этап 1 — стенд «группа хранилища» (P/01.3)

Кирпичи уже есть: `@tls-setup` (комплекты по описанию, сертификаты ролей) и `@kit-start` (один процесс роли с комплектом).
Нужен запуск нескольких демонов разом и двери к каждому.

- Словарь директив (common README, «Спецификация»):
  - `@store-start <n> <комплект> [<флаги>…]` — член группы `store#<n>` командой хранилища профиля: свой `{data}`, свой
    сокет роли, `-raft`/`-api` на петле со своими портами, `-tls` из комплекта (CN `configstore.<server>`); флаги P/01.3
    Н1.3 (`-bootstrap`, `-join`, `-group-size`, `-force`, `-door`, `-voters`) — как написаны; ожидание `ok` / `@exit 2`
    / `ok ~<текст>` — как у `@kit-start`;
  - `@sigkill store#<n>`, `@sigterm store#<n>`, `@start store#<n>` (прежние флаги и данные) — расширение имени `[#n]`;
  - `@cut store#<n>` / `@mend store#<n>` — посредник раннера на raft-порту члена (раздел группы);
  - дверь `store#<n> <запрос>` — P/01.1 сокетом роли члена; `store#<n> status` — `GET /v1/status`;
  - описание комплектов группы — `Platform/01-store/acceptance/3/tls-group.yaml` (по формату `tls/README.md`).
- Сценарии P/01.3 (`acceptance/3/scenarios.tsv`):
  - сц. 07 — без `@manual`: группа из трёх, четвёртый `-join` → 409 `refused`, с `-force` при объявленных трёх — код 2;
    дверь без голоса `-door -voters` на нём отвечает тем же файлом прав, строка `platform/configstore-doors/<id>` с `seen_at`;
  - сц. 17 — размеры и состав: 1/3/5 (`-group-size` 2 и 4 — код 2), `leave`/`admit`, лидер убит — новый не позже 5 с,
    большинство отсечено — 503 по трём ветвям Н1.3, ряд `configstore_doors` на `/metrics`;
  - сц. 18 — из системной 06: остановить все, `recover` без `-isolated` — отказ до изменений, `-upper` ниже вычисленного
    — отказ, `recover -isolated` — пол выше upper, прежний член с прежними данными — отсечён (эпоха не повторяется).
- Системная приёмка: 06 уходит в P/01.3 сц. 18 (строка id-map — «перенесено»), в системной остаётся ссылка.
- Профиль реализации: новых команд нет — хранилище уже запускается командой профиля с флагами P/01.3 (`@foreign store`
  так и делает); нужно `keys.tls_stand: 1` (как у `@tls-setup`).

## Этап 2 — стенд «кластер из трёх серверов» (системная 05)

Три сервера на одной машине: у каждого свой `SERVER_NAME`, ресурс со своим `{rport}` и томом, воркеры подсистемы
стенда; хранилище — группа этапа 1; один контроллер.

- Директивы: `@server-start <имя>` / `@power-pull <имя>` (раннер убивает `@sigkill` все процессы сервера и рвёт его
  дороги посредником — «выдернуть питание»), `@power-back <имя>` (те же каталоги, без `-join`); двери `resource#<имя>`.
- Сценарий системной 05 — без `@manual`, ожидания по сроку P/04 (ориентир 90 с + проход; `@until`), новая эпоха единиц,
  архив на томе цел, у соседей — только подтверждённые зеркальные копии; возврат: демон по `member.json`, restore
  бакетов, воркеры берут свободные имена, назад едет только объявленный `home`.
- Профиль: несколько ресурсов на одной машине (свои порты и каталоги) — проверить у обеих линий до старта этапа.
