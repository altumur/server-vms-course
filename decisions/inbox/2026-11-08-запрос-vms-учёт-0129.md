Это учёт решений по ADR-0114, не ревью уроков или норм VMS. Отдельный запрет

## Прочитанный срез и состав

Прочитаны основной текст, дополнения (1)–(28) и уточняющий контекст (29)
ADR-0129 на полной базе выше. `review_to` равен 28, поэтому авторский учёт
ограничен (0)–(28). Дополнение (29) не получает отдельной строки или повышения
счётчика, но заменённые им промежуточные правила не выдаются за действующие.

В `adr-norms.tsv` добавлено 29 строк с явной пометкой «доля VMS» и статусом
НЕ НОРМА: одна на основной текст и каждое дополнение до (28). Это означает
отсутствие новой назначенной правки предметного источника VMS в этой доле,
а не отмену общих правил курса. Платформенные строки НОРМА, РАСХОДИТСЯ и
НЕТ НОРМЫ сохранены, чужие находки и очереди ими не закрываются.

В `adr-pipeline.tsv` изменены только `norms_to` (`- → 28`) и `note` ADR-0129.
`review_to`, `plat_to`, `nrev_to`, `read_to`, `second_to`, `invariants_to`,
`quint_to`, `lane` и все остальные ADR сохранены. Это авторская сдача учёта,
которую отдельно принимает coord103-src; из неё не следует приёмка норм VMS.
Остальные два файла — эта записка и строка собственного журнала хода.

З-10 описывает только нынешнюю процедуру записи; схема писателя её не расширяет.
Пределы чтения равны пределам записи, превышение получает прежний `unreadable`.
История, старые состояния и положительные тесты совместимости не становятся
активной нормой или новым долгом реализации. Это постоянный критерий будущей
назначенной работы, а не результат повторного чтения уроков VMS сейчас.

Т2 учитывает место как урок и поведение со всеми зависимостями; без достаточных
эпизодов доля не выдумывается. Действуют (26)–(29): ввод по доле с расширениями
грамматики, порог 1/5; две доли до ответа владельца — только для меры после ввода.
Пакеты проб владельца на `ce8d6db6` защищены. Паспорта, недельная мера, снятие
`launch`/`gen_admin` и прочих частей остаются у tools и Архитектора. В этой сдаче
нет подсчёта Т2, снятия генераторов или запуска проб.

Применяются независимые ожидания и мутанты, а при гонках — Quint; ошибка среды,
сборки, пустой либо неполный ответ не дают обнаружения или PASS. Python, схема и
структурная проверка не выдаются за исполнение реализации. Пауза ms и отдельные
ограничения линий/Owner-only trials этим учётом не снимаются.

## Программа проверки учёта и фактический вывод

Запущено автором из нового worktree после добавления четырёх файлов в индекс.
Программа читает базу и индекс Git; для проверки уже закоммиченного среза
проверяющий использует тот же состав из точного авторского коммита.

```python
import csv
import io
import json
import subprocess

BASE = 'fd6d0c3f62ee1577dd436e088164352b05194839'
REPORT = 'decisions/inbox/2026-11-08-запрос-vms-учёт-0129.md'
ALLOWED = {'decisions/adr-norms.tsv', 'decisions/adr-pipeline.tsv', REPORT,
           'ХОД-Спецификация-VMS.md'}

def git(*args):
    return subprocess.check_output(['git', *args])

def blob(rev, path):
    return git('show', f'{rev}:{path}')

def tsv(data):
    return list(csv.reader(io.StringIO(data.decode()), delimiter='\t'))

assert set(git('diff', '--cached', '--name-only', '-z').decode().split('\0')) - {''} == ALLOWED
assert not git('diff', '--name-only', '-z')
assert not git('ls-files', '--others', '--exclude-standard', '-z')
ledger = 'decisions/adr-norms.tsv'
before, after = blob(BASE, ledger), blob('', ledger)
assert after.startswith(before)
added = tsv(after[len(before):])
assert len(added) == 29
assert [r[1] for r in added] == [str(i) for i in range(29)]
assert len({tuple(r[:3]) for r in added}) == 29
assert all(len(r) == 7 and r[0] == '0129' and r[3:6] == ['НЕ НОРМА', '-', '-']
           and r[6].startswith('доля VMS: ') for r in added)
pipeline = 'decisions/adr-pipeline.tsv'
left, right = tsv(blob(BASE, pipeline)), tsv(blob('', pipeline))
assert len(left) == len(right)
changes = [(a[0], i) for a, b in zip(left, right) for i, (x, y) in enumerate(zip(a, b)) if x != y]
assert all(len(a) == len(b) for a, b in zip(left, right))
assert changes == [('0129', 2), ('0129', 7)]
a = next(r for r in left if r[0] == '0129')
b = next(r for r in right if r[0] == '0129')
assert a[2] == '-' and b[2] == b[1] == '28' and len(b) == 11
log = 'ХОД-Спецификация-VMS.md'
old_log, new_log = blob(BASE, log), blob('', log)
assert new_log.startswith(old_log)
assert len([line for line in new_log[len(old_log):].splitlines() if line.strip()]) == 1
assert blob('', REPORT)
print(json.dumps({'status': 'PASS', 'base': BASE, 'changed_paths': sorted(ALLOWED),
                  'ledger_old_bytes_unchanged': True, 'vms_rows': 29,
                  'addenda': '0..28', 'pipeline_cells': ['0129.norms_to: - -> 28', '0129.note'],
                  'other_pipeline_cells_unchanged': True, 'own_log_append_only': True,
                  'all_other_tracked_paths_unchanged': True, 'unstaged_untracked': 0}, ensure_ascii=False, indent=2))
```
