## Б. Нужен выбор

**Б1 (п. 2). Сборка raft без `-raft`.** Приёмка главы 3 (в M) уже называет стенд без `-raft` «a single member of a box». `stand.import` работает офлайн, а sc. 16 ждёт форму статуса box от обеих сборок. Рекомендую записать в N3 `box`:
- режим задаёт `-raft`, а не сборка. Без `-raft` и без `-door` демон — box в любой сборке. С `-raft` — голосующий группы. С `-door` — дверь (`-raft` двери не нужен, как в стенде группы);
- в сборке raft без `-raft` флаги `-bootstrap`, `-join` и `-group-size 3|5` дают `start_config` (причина: «a group voter needs -raft»). Имя `box_no_raft` здесь не годится: его журнал гласит «this build has no raft»;
- дверь вместе с `-raft`, `-raft-bind`, `-bootstrap`, `-join` или `-group-size` — `start_config`;
- свежий каталог с `-raft` без `-bootstrap` и без `-join`, когда нет `member.json`, — `start_config` (L «first start»). `-raft -bootstrap -group-size 1` — группа из одного, с семантикой группы (`import` через `admin.sock` лидера);
- в сборке box флаги `-raft` и `-bootstrap` дают `box_no_raft`.

**Б2 (п. 3). Предикаты F и имена отказов.** Исход (код 2) не меняется, меняются только имя и журнал. Рекомендую правило в R007 и N4:
- синтаксис (неизвестное имя, чужая команда, повтор, bool со значением, позиционное слово), значение вне типа и невыполненный `required` — `start_flags`;
- `bad` — `start_config`;
- исключения уже названы N4: `-group-size` вне формы — `start_config`; `-tls`, обязательный из-за адреса вне loopback или из-за `-join`, — `start_config`; у `recover` — `recover_isolated`, `recover_upper`, `recover_peers`;
- при нескольких нарушениях — первое по порядку строк F, внутри строки: тип → required → bad;
- для адреса вне loopback явный `start_config` сохраняется.

**Б3 (п. 4). Запись через `admin.sock` у последователя.** `admin.sock` не пересылается, а `floor`, `import` и `restore` разрешены только у лидера. Рекомендую новое имя `admin_not_leader`:
- у последователя запись, `op: floor`, `import`, `restore`, `admit`, `join` и `leave` другого участника отказывают: http 503 `unavailable` без `Retry-After`, у CLI — exit !0. Запись не меняется;
- что делать вызывающему: та же команда у лидера (`leader_id` в `/v1/status`);
- `status`, `backup` и `leave` себя по-прежнему доступны на любом участнике. Свой `leave` демон передаёт лидеру внутренней операцией группы, а не пересылкой полномочий admin;
- `no_leader*` при живом лидере не выдаётся.

**Б4 (п. 5). restore, import, recover.**
- (а) **База `restore`** — `index` заголовка копии. Следующие записи получают версии выше неё и выше любой версии группы. Флага `-index-base` у `restore` нет, F не меняется.
- (б) **Потолок строки офлайн.** `-max-value` допускается и у `import`/`restore` (F: commands `daemon,import,restore`, тот же default). Он действует на офлайн-перенос box. В группе применяется действующий `-max-value` лидера, флаг CLI там не нужен. Запасной вариант без правки F: офлайн всегда default 524288. Но тогда копия box, запущенного с большим потолком, не импортируется.
- (в) **Новая попытка поверх незавершённой.** Попытку узнают по тому же входу: байты копии сравнивает реализация, способ — её выбор. Тот же вход продолжает попытку с тем же F1. Другой вход до «Done» отказывает без изменений, новое имя `import_other_input` (cli, exit !0). Новая полная попытка с новой генерацией — только после `recover`, как уже решено (F2).
- (г) **Что удаляет `recover`.** Только состояние членства отсутствующих: Raft-конфигурацию, их адреса в `members` и метки `leave`/`admit`. Строки хранилища любых семей, включая `platform/configstore-doors/<id>`, не удаляются.

**Б5 (п. 6). `op: floor` при нечитаемом текущем floor или `generation_at`.** Рекомендую новое имя `floor_unreadable`: http 409 `refused`, ничего не записано, журнал называет строку. `restore`, `import` и `recover` сообщают об этом как `recovery_unsafe`. Запрет недостоверного upper остаётся.

**Б6 (п. 7). Предел тела GET и порядок 403/413 на `/v1/write`.** Рекомендую один шаг кадра для всех дверей store, по образцу R017: framing и `-max-body` проверяются до маршрута и роли.
- Тело GET в пределах лимита читается и отбрасывается, как данные операции оно не используется (R047 уточняется). Сверх лимита — 413: `body_limit` у дверей главы 1.1, `service_body_limit` у служебных.
- Порядок на `/v1/write`: кадр (413) → маршрут → роль (403 по заголовку роли и доверию пересылке, P/01.2 шаги 1–2) → форма тела (400) → таблица `write-checks` (в ней 403 по правам).
- Если нужно, чтобы тело GET не ограничивалось, — скажите, и я запишу обратное.

**Б7 (п. 8). CLI `join [-force]`.** Позиционных слов в грамматике нет. Рекомендую так: команда просит локальный демон через `admin.sock` снова отправить в группу его же `join {id: -id, raft: -raft, api: -api, force}` через адрес `-join` или известного лидера. Повтор подчиняется `repeat`. У box — `join` своего id, ответ 200 `{}`, как уже сказано. `leave <другой>` и `admit` — по Б3.
