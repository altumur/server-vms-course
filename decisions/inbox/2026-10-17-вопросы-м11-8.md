# Вопросы М11/8 «Двери между кластерами»

Свидетели — курс (заморожен, `Source/w2cplatform/console.py`, `tls.py`) и продукт (`vmsworker/w2cplatform/domain/console.go`,
`roletls/`); расходятся в 24 местах. Без вопроса взято следующее.

- Консоль кластера — единственный адрес кластера для домена и единственная дверь процессов члена к домену. Шлюз и
  воркер идут к домену через свою консоль (ADR-0074, C5 «дорога шлюза»).
- Одна функция пересылки на всё: ответ уходит как пришёл, отдельный механизм не заводится (ADR-0061, доп. п. 6).
- `/domain/at/…` — только `GET` и только `where`, ровно один шаг (`X-W2C-Via`). Гейт пересылающей консоли спрашивает только
  «кто это», решает гейт члена (ADR-0061).
- Входящие `X-User`/`X-Operator` снимаются, исходящий `X-Operator: console` — служебный (ADR-0075 п. 3, C5 operator-pass).
- Лимит ответа 1 МиБ → 502 «answer too large» (ADR-0061, доп. п. 2).
- Комплекты ролей — М10/11 Н1.6.

## 1. Какие `/domain/*` консоль кластера пересылает

Курс пересылает всё, что не отвечает сам (открытый набор). Продукт держит закрытый список `Forwards` плюс объявленное
спекой.

**Рекомендация:** закрытый список. Урок 8 сводит таблицей двери консоли домена уроков 1, 3–6:

| Урок | Двери |
|---|---|
| 1 | `GET /domain`, `GET /domain/<sub>/<rows>`, `GET /domain/shadow` |
| 3 | `GET`/`POST /domain/members`, `DELETE /domain/members/<м>` |
| 4 | `GET`/`PUT /domain/topology` |
| 6 | `GET`/`PUT`/`DELETE /domain/placement…`, `POST`/`PUT`/`DELETE /domain/<sub>/<rows>…` |

Уроки 9–11 добавляют свои двери пометкой «добавлено М11/N».

Сама консоль кластера отвечает только на:
- книги своего члена `GET /domain/<sub>/books/<книга>` (урок 5);
- `/domain/at/…`;
- двери переноса (п. 6).

Прочее под `/domain/` — 404 «not a domain route», держатель не зовётся. Держатель тоже пересылает:
`GET /domain` у консоли кластера держателя идёт в консоль домена, как у всех. Курс отвечает из вида на месте, но одна
форма лучше двух.

## 2. Адрес: куда идёт пересылка

**Курс.** Адрес — `url` из `domain/view`. У члена вида нет, поэтому пересылка работает только у кластера держателя. Для
users/grants есть запасной путь по `CLUSTERS` к консоли кластера держателя.

**Продукт.** Член идёт к консоли кластера держателя по `CLUSTERS` и имени держателя (`toHolder`). Консоль кластера держателя
пересылает в консоль домена по `view.url`. Получается два перехода: между кластерами и на коробке.

**Рекомендация:** форма продукта.
- **Член.** Имя держателя — запись `how: "holder"` в `domain/member-list` (урок 3 Н3: держатель всегда в списке). Адрес —
  `CLUSTERS[имя]`.
- **Кластер держателя.** Адрес консоли домена — новое поле вида урока 1 `url`, его пишет процесс `domain` из
  `DOMAIN_CONSOLE_URL` своего окружения. Вид закреплён за держателем, поэтому адрес верен и после передачи (урок 10).
- **`X-W2C-Via`.** Консоль, получившая заголовок, никогда не пересылает в консоль другого кластера: 400 «one hop». В
  консоль домена своей коробки пересылает.

Отказы:
- 404 `no domain here` — держателя нет в списке или держатель — этот кластер, а вида нет;
- 503 — список не читается (не «не член», ADR-0061, доп. п. 5);
- 404 `no console of <к> is known here (CLUSTERS)`;
- 503 `CLUSTERS does not read`;
- 502 `<к>'s console did not answer`.

## 3. Заголовки, тело, `Content-Type`, сроки

- **Тело запроса.** Курс: 64 KiB → 413. Продукт: 64 KiB молча режет.
- **`X-Operator`.** Курс синтезирует, продукт не ставит.
- **`Content-Type` ответа.** Курс всегда ставит json, продукт сохраняет пришедший.

**Рекомендация:**
- тело — предел консоли (М10/9 Н1.3, 1 МиБ) с 413, никогда не резать;
- передаются `Authorization`, `Content-Type`, `Idempotency-Key`;
- ставятся `X-Operator: console` и `X-W2C-Via: <этот кластер>`;
- ответ — статус, `Content-Type`, `X-Unreachable` и тело как пришли;
- срок 5 с (передача — урок 10, 90 с);
- журнал `domain.forwarded {cluster, path, user, status}`: `path` — пришедший путь, `user` — доказанный гейтом (не
  `X-User`).

## 4. `/domain/at/<к>/<sub>/where/…`: форма и порядок

**Расхождения свидетелей:**
- форма: курс точная (`where/<id>`, `where/<places.table>/<место>`), продукт — любой хвост;
- держатель как член: курс берёт его из проверенной записи срока, продукт — без проверки подписи;
- тексты отказов у свидетелей разные.

**Рекомендация.** Форма точная, маршруты М10/4. Держатель — член по списку (п. 2). Проверки по порядку:

| Шаг | Отказ |
|---|---|
| 1. `X-W2C-Via` | 400 `one hop` |
| 2. не `GET` или не форма `where` известной спеки | 404 `not a route handed to a member` |
| 3. гейт (урок 9; до него петля — operator) | — |
| 4. список не читается | 503 `the list of members does not read` |
| 5. этот кластер | 404 `not another member` |
| 6. не в списке | 404 `no such member` |
| 7. адрес | `CLUSTERS`, как п. 2 |
| 8. пересылка на `<консоль>/<sub>/where/…` | корень или маунт снимает принимающая (ADR-0061, доп. п. 3) |

Тексты — §10a и продукт.

## 5. TLS между кластерами

Продукт исполняет окно 4 и уточнения 2–3 ADR-0075 полностью:
- `ca` в записи члена (не больше двух), `tls_ca` публикации;
- `POST /domain/members/<м>/ca`;
- сверка чужого сервера по отпечатку;
- `DOMAIN_CA`, `RELAY_CA`, `RELAY_MEMBER`.

У курса ничего этого нет. Решение C5 «два разных центра — 502» — узкая граница зеркала, не норма.

**Рекомендация: норма — форма продукта.**
- **Нормы.** `Entry.ca` (урок 3 закрыт с этим полем) и `publication.tls_ca`. Держатель пишет `ca` на проходе: rev + 1,
  журнал `domain.member.ca`. Публикация без `tls_ca` не чистит, третий отпечаток — отказ словами. Дверь администратора
  `POST /domain/members/<м>/ca {ca}`. Клиент принимает чужой сервер, когда:
  - в цепочке есть CA с отпечатком из записи члена назначения;
  - SAN URI — роль двери, SAN DNS — хост, IP — отказ;
  - нет отпечатка — отказ «foreign CA» с причиной.
  Первый контакт — `DOMAIN_CA`/`RELAY_CA`, они действуют, только пока записи не называют CA. `RELAY_MEMBER` обязателен при
  `https://`. `ca` записи срока — урок 10.
- **Приёмка.** Чистая функция `peer`: вход — цепочка PEM, отпечатки, роль, хост; выход — `ok` или слово отказа. Векторы на
  двух тестовых CA: принят, без отпечатка, чужая роль, IP, два отпечатка — любой, истёкший. Стенд остаётся на одном
  центре (М10/11), запись `ca` из `tls_ca` проверяется на стенде.
- Курсу долг зеркала окон 3–4 уже записан (C5).

## 6. Двери переноса на консоли

Двери: `/api/held`, `/api/backup` — консоль отвечает сама; `/api/prepare`, `/api/take`, `/domain/move` уходят на
`SIGNER_URL`. Их тела и смысл — урок 10, без них урок 8 проверить нечем.

**Расхождения свидетелей:**
- путь `move`: курс переписывает на `/api/move`, продукт и ADR-0066 оставляют как пришёл;
- `Via` перед подписантом есть только у продукта;
- тело: курс 64 KiB, продукт 1 МиБ.

**Рекомендация.** Все пять дверей целиком в урок 10. Урок 8 даёт им правило пересылки к подписанту:
- путь и тело как пришли;
- 1 МиБ;
- `Via` → 400;
- без `SIGNER_URL` — 404 `no signer here` с текстом ADR-0066;
- 502 `this box's signer did not answer`;
- срок называет урок 10.

Дверь пересылки подписанту — интерфейс со ссылкой вперёд. Курсу долг: `/api/move` и отсутствие `Via`.

## 7. `door.pass` на домене

Записка модуля и урок 5 Н1.6: `/domain/<sub>/<маршрут>` консоли домена передаётся воркеру на домене. Набор маршрутов:
- §10a — «всё под `/domain/<sub>/…`, что не строки, не таблица, не книга», открытый набор;
- продукт так же, напрямую с консоли кластера по адресу из пульса.

**Рекомендация.** Набор закрыт тем же ключом `door.pass` спеки (М10/11 Н1.8, нового ключа нет).
- Консоль домена передаёт `/domain/<sub>/<сегмент из pass>…` держателю слота `domain/<sub>/worker` (урок 5 Н1.6), роль
  `<sub>domain`. Правила М10/11 Н1.8: заголовки, 1 МиБ/4 МиБ, 503/502.
- Консоль члена пересылает эти пути держателю как часть списка п. 1.
- Курс шлёт путь `/<sub>/<маршрут>`, продукт — `/<маршрут>`. Норма — как М10/11 Н1.8 у консоли кластера.
- Учебного воркера на домене у стенда нет (долг урока 5), поэтому `door.pass` на домене проверяется чтением.

## 8. Страница держателя и модуль

Долги М10/9 к уроку 8: `sections: [domain]`, объекты `member:<м>` и `domain`.

**Рекомендация.** Урок 8 нормирует двери консоли домена для страницы по §10a и закрытый список вызовов модуля в режиме
`domain`:
- `GET /spec` → `{"name": "", "rows": null}`;
- `GET /mounts` по `SPEC_DIR`;
- `/session`.

В режиме `domain` модуль не зовёт `/servers`, `/unplaceable` и единицы. Ссылки `member:<м>` и `domain` — узлы дерева раздела.
Двери страницы проверяются стендом, вызовы модуля — jsdom-тестом команды курса (не приёмкой урока).

## Приёмка (предложение)

Стенд урока 3 (`hold`, `m1`, `m2`):
1. `GET /domain` через консоль `m1` равен ответу консоли домена;
2. правка назначения через консоль `m1` → 202 у держателя;
3. `/domain/at/m2/testsub/where/<id>` с консоли `m1` — ответ консоли `m2`, как пришёл;
4. отказы п. 4 по одному: `one hop`, не `GET`, свой кластер, не член, нет строки `CLUSTERS`, `m2` выключен → 502;
5. неизвестный `/domain/x` → 404 без звонка держателю;
6. `tls_ca` из публикации → `ca` в `GET /domain/members`, отказ третьего отпечатка;
7. векторы `peer`.

Строки реестра: `inputs/peer-*.json`, векторы `peer` в `scenarios.tsv`, директивы стенда — `@env <к> CLUSTERS=…` для
снятия строки.
