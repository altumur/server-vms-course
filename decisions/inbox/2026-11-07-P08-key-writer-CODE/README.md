# P/08: точная поддержка ключа писателя метки

7 ноября 2026, Архитектор. Это разрешение реализации уже выбранной формы из [решения о метке роли](../2026-11-07-P08-форма-метки-удаления-роли.md), ADR-0129 (19), (23) и действующего разделения З-12. Норма, значения и публичный протокол не меняются.

Пакет tools `PLAN.json` SHA256 `692a27747c096d13587e733be5b83baea35d48d614cf0910d60e29b6e5d7630c` прочитан вместе с картой блоков и вызывающих мест. База кода — `43750c8ef574ae4af747f481433fd7f4e0045793`. Все 12 идентичностей файлов совпали. У одного из 22 блоков поправлена координата: место вставки в `TestDefects` занимает физические строки LF 254–263, SHA256 прежний `f55d10775584b9f0c6a03c695fbf13fb63539588b56f79950fe16acb7906ca46`. Вставка перед `class TestRelations`; прежние методы не меняются. Полная нормализованная граница — `BLOCKS.json` рядом.

Разрешены семь существующих файлов кода и вставки в два существующих тестовых класса. Архитектор сохраняет владение `skills/**` и прямо поручает review103 только пять названных v7-путей, включая тест. Review103 также ведёт строку конструктора `family_judge.py` и новые методы `Synthetic`. Генераторы ведут только `gen_families.py` и `famrt2/go/runtime.go`. Каждый пишет в собственном дереве; tools сводит независимые доли. Остальные файлы и старые проверки защищены. Переписывание навыка, corpus/SUT, flat P01, typed Items, J-P05-02 и S08 не разрешено.

Существующая идентичность каталога и конкретный ключ доходят до проверки писателя. Только `domain/deleting/<name>` выбирает локальные `person_writer` или `role_writer`; содержимое items не выбирает форму. Для человека и суффикса `role:` используется существующий `common.person_name`. Плохой ключ получает прежний отказ ключа до чтения значения. Отсутствующий конкретный ключ, несовпадающая идентичность или неполный источник профилей означают ошибку проверки: Python `ValueError`/`SpecError` в своих слоях, Go — существующий механизм ошибки предусловия через panic. Это не смысловой отказ, успех или убитый мутант. Именованные Go `Judge`, `JudgeItems`, `Result` и публичные поля остаются прежними; дополнительные помощники закрытые.

Профиль выбирается до кодеков. Его явные поля имеют приоритет над разрешительным reader `additionalProperties/x-codec:any`. Сохраняются проверки корня, общего writer и выбранного профиля, исходная база локальных `$ref`, ограничения Time и конечности чисел. Общий `x-max-names:0` учитывает поля выбранного профиля. Ошибка кодека остаётся отказом даже после удаления нераскодированного поля. Контекст вызова не изменяет общий документ, writer, скомпилированную схему или кеш. Reader и остальные семейства сохраняют прежнее поведение. Наличие двух writer-определений без идентичности не разрешает анонимный writer-вызов и не считается выбором формы.

Первый вход — явно ограниченная синтетическая фикстура из `APPROVED-FIXTURE.json`. Корень читателя, `common.time` и `common.person_name` взяты побайтно по JSON-значению из deleting.schema на базе кода; writer-профили — из уже объявленного source-предложения. Это проверка механики на одобренном входе, не принятие ещё удержанных пяти исходных файлов, 15 зависимых записей или corpus. Новые тесты могут поместить этот ограниченный документ внутрь разрешённого класса; ожидаемые исходы заданы решением 505aa и примитивами формы, не результатами производителя.

Начальный этап разрешает написание кода, синтаксические/AST и raw-проверки, а также только перечисленные в `APPROVAL.json` новые Python-методы. Проверки Python должны выполняться по полным именам методов, без discovery старых классов. Функции старых Go-тестов, `Synthetic.test_against_v7`, `DocMode.setUpClass`, `synth_mismatches`, старые corpus/SUT и генерация не запускаются. Необходимые импорты существующих Python-модулей допустимы; установка зависимостей этим не разрешается. Внешние процессы запрещены в этой первой проверке; их неожиданный вызов завершает проверку ошибкой.

Рендеринг D0 и реальные Go-проверки G0 ждут отдельной точной составной области после поставки исходных профилей и кода. Карта input-boundary A0 также удержана: у старого set-A нет конкретного ключа, а SUT.family передаёт шаблон. Их нельзя засчитать покрытием person/role, подставить пример ключа или расширить протокол. Старые 15 person-случаев не покрывают роль. При нехватке разрешённого блока автор сохраняет проверяемую точку и присылает точный стык; не расширяет область сам.

Приёмка будет различать кодовый компонент, выбранные Python-проверки, предметную связку с точным SOURCE и общий результат. Сейчас новых исполнений нет. Общий срез, main merge, рендеринг, Go, GATE, ms, VMS и обе паузы Claude этим разрешением не меняются.
