# Запрос: поле `freeing` в пульсе воркера и адресат просьбы освободить место

**Какие нормы мешают.** P/05 Н1.4 `free_ask`, Н3 «relieve» (`05-resource.norms.md:230–236, 447–462, 778–784`): ресурс пишет
`<sub>/requests/free-<server>-<volume>` подсистемам с `requests.free: true` и считает `need = used − total·low − Σ freeing`;
форма `freeing` есть только в повествовании P/05 (`05-resource.md:57`: «`freeing: {<том>: байты}`»), в форме пульса P/03.4 Н1.1
поля нет. Имя тома в `free-*` — том **ресурса** (`[A-Za-z0-9_]{1,64}`, «на коробке один том — events»), а регистратор отвечает
по **своим** томам: кому из воркеров подсистемы адресована просьба и о каком томе — не сказано.

**Что нужно VMS.** Регистратор (V/02.7): ресурс просит освободить место на сервере; регистратор отвечает `freeing: 0` —
кольцо отдаёт старое само, файлов не удаляет (М10B/11 шаг 5, М10B/18 шаг 8).

**Обход до решения.** V/02.7 Н1.6: регистратор читает строки `rec/requests/free-<свой сервер>-*` и, пока строка стоит,
говорит в пульсе `freeing: {<том ресурса из строки>: 0}`; id в `fetched` не кладёт.

**Рекомендация.** P/03.4 Н1.1: `freeing: {<volume из просьбы>: <байты, целое ≥ 0>}` — поле платформы в пульсе воркера;
P/05: просьба адресована всем воркерам подсистемы на сервере `<server>`, `<volume>` — том ресурса; ответ любого воркера сервера
считается.

## Решение
**Решён** (2026-10-23, «Архитектор»; текстовый запрос — «Спецификации» по слову, без ADR). Рекомендация принята. P/03.4 Н1.1: `freeing: {<том ресурса>: <байты, целое ≥ 0>}` — поле платформы в пульсе воркера (форма из повествования P/05 переносится в норму). P/05 Н1.4, Н3 «relieve»: просьба `<sub>/requests/free-<server>-<volume>` адресована всем воркерам подсистемы на сервере `<server>`; `<volume>` — том ресурса, не место подсистемы; `Σ freeing` — сумма по пульсам воркеров этой подсистемы на этом сервере для этого тома. Приёмка P/05 — воркер отвечает `freeing: 0` и `freeing: N`.
