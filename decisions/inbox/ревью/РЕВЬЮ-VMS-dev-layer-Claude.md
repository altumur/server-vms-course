## Блокер

### Б-1. `configMode: current` — 422 у каждого добавления из WebUI

`VMS/11-backend/data/mapping.tsv:55`, `:87`, `:132`; `11.3:46`; `consolem.openapi.json` `DeviceCreate.configMode`.

Ход:
1. Мастер кладёт в узел `configMode: "current"` всегда: `index.html:16273`, `:16278`, `:16642`, `:16644`, CSV — `:16304`.
2. `nodeCreate` (`:2359`) шлёт все поля узла, кроме короткого перечня; `configMode` в нём нет.
3. `POST /devices`: поле `none`, умолчание ответа — «поля нет», `current` не умолчание.
4. `11.3:46`: 422 `NOT_SUPPORTED`, `field: configMode`. Элемент `failed`.

Ручное добавление и CSV не проходят. Тесты `in` поля не шлют, поэтому приёмка этого не видит. `cammeta-console/РЕВЬЮ-ПОЛЯ-НАСТРОЕК.md` уже называл `current` равным «не трогать». ADR-0103 ставит совместимость с consolem условием первой генерации.

Правка: `configMode: current` у всех видов записи — как умолчание `none`, пропускается; `default`, `template` — 422 `NOT_SUPPORTED`. Шаг сценария `11-devices`.

## Средние

### С-1. Версия камеры не видит строку `ipsrv`

`mapping.tsv:52`; `11.4:54`; `11.3:147`; `11.5:57`–`:58`.

Камера, `channels` 1 или не сказан, `parentId: null`, версия V. `POST /devices type: ipsrv` на тот же хост даёт камере `parentId` хоста. Строки `c`, `r`, `d`, `h` не менялись: версия V, сообщения камере нет. `DELETE` строки возвращает `null` с той же версией. Контракт велит менять версию при изменении видимого, `11.3` утверждает, что меняется.

Правка: часть индекса строки `ipsrv` в версии камеры и `entity.changed` камер хоста в `11.5:58`.

### С-2. `PATCH ip` меняет id `ipsrv`

`mapping.tsv:72`, `:82`; `11.3:125`–`:129`, `:140`–`:142`.

Id `ipsrv` — от хоста, а `ip` — `both`. `PATCH /devices/<id> {"ip": "10.9.9.2"}` даёт запись с другим id, старый отвечает 404 или остаётся без строки. `POST type: ipsrv` с адресом `driverpack://file/…` даёт строку без группы, id не определён.

Правка: смена хоста у `ipsrv` и строка без группы — 422 `NOT_SUPPORTED`, `field: ip`, `rtspUrl`.

### С-3. Без права на `cam/devices` `ipsrv` одновременно есть и нет

`11.4:48` против `11.4:243`, ADR-0102 доп. (6) п. 6.

Человек с грантом на камеру хоста или строку `ipsrv`: по `:48` 403 двери таблицы — части нет, `ipsrv` нет, `parentId` нет. По `:243` и ADR он виден. Ребёнок на строке получает `parentId` на запись, которой нет в списке.

Правка: выводить `ipsrv` по строке и адресу, без `cam/devices` молчат только `channels`, `subtype`, `videoChannel`.

### С-4. `/test/reset` неоткуда взять незавершённые операции (решение 13)

`11.6:75` против `Platform/06-console/spec/06.9-console.norms.md:266`.

Норма велит отменить незавершённые и ждать `done`, а `GET /{sub}/operations` — 405. Тест 409 оставляет операцию идти, корень занят, следующий тест получает 409. Правка: назвать источник id, например обход `backend/repeats`, и что с `retry-failed`, у которого строки памяти нет.

### С-5. `children` у `ipsrv`, `eventsrc`, `acfa` не названо

`mapping.tsv:51`, `:87`, `:132`; `11.3:38` «Полнота».

Строка есть только у камеры. Мастер шлёт `ipsrv` с `children: [{type: "storage"…}]` (`index.html:16650`). Поле не `none`, ответ не определён. Правка: строка `children` этих видов: 422 `NOT_SUPPORTED`, либо у `ipsrv` — правило создания `storage`.

### С-6. Дети не появляются в дереве на тихом кластере

`VMS/01-cam/cam.shell.html:879`; `Source/w2cplatform/console.js:2411`–`:2414`.

`refresh` приходит после `repaint`, `readChildren` кончается позже и дерево не перерисовывает. Следующий опрос: отпечаток тот же, `doTree` ложно. Открыл страницу — детей нет, пока не сменятся строки единиц или не будет клика. Новый вход и `gone` так же. `pc.refresh()` не поможет: отпечаток тот же; `pc.select` гасит живое. Это задача для модуля, а норма `08.1` обещает детей в дереве.

Правка: вызов перерисовки дерева в модуле по новому слову `features`, запрос платформе; до него записать пределом.

### С-7. Строка устройства есть, `can` нет: здоровый сценарий `refused`

`VMS/07-auto/spec/07.3-auto.norms.md:40`, `:49`, `:53`, `:63`.

Держатель молчит дольше `LOST_AFTER`, `cam/devices/<хост>` с `events` на месте, сценарий с `match.port` или `cam output`. «Не сказано» по `:63` требует «`can` нет, строки устройства нет». Буквально: `rays` нет — `camera 7 has no input 3: it has none`, `refused`. Рестарт держателя роняет сценарий. После оживления `since` = `now`, события этого окна потеряны: два правила складываются.

Правка: «`can` нет — `rays`, `relays`, `presets` не сказаны, `unchecked`; строка устройства даёт только `events`».

### С-8. Слово `codec` открыто, выбор по размеру молча отпадает

`VMS/01-cam/data/cam-heartbeat-words.schema.json` (`codec`: `string`); `01.2:141`; `03.3:51`; `03.4:46`.

ADR-0104 и V/02.4 пишут `H.264`, оффер даёт `H264`. Держатель пишет `H.264`, шлюз сверяет с оффером: все потоки отсеяны, всегда основной, без отказа и записки. Малое окно получает крупный поток, ADR-0104 не работает, приёмка 3 этого не видит, если стенд пишет иначе.

Правка: закрыть слово именем `rtpmap` (`H264`, `H265`), либо задать приведение в V/03.3. `Device.codec` контракта — строка, не мешает.
