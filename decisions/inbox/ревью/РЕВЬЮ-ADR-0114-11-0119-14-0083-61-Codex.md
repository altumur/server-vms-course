**ADR-0114 (11): Б 0, С 1, М 0.** Атомарный захват одного из двух файлов слотов закрывает прежнюю гонку подсчёта/запуска. Источник статуса зачётного прогона назван. Остался вопрос исполнения остановки.

## С1. Остановка PID держателя слота не гарантирует остановку всей серии

**Место:** (11) п. 2: «Машины останавливают её по PID держателя слота … слот освобождается сам»; п. 1 — слот держится, пока жив процесс серии.

**Норма:** (11) сохраняет приоритет зачётных прогонов и предел двух работающих серий. В существующем укладе `vrev` серия вызывает оболочки `s6.sh → scan.sh → sim.sh → quint → симулятор`; в этих скриптах нет управления отдельной группой процессов и передачи сигналов потомкам. `flock -n <слот> sh runs/sN.sh` удерживает блокировку, но не делает потомков управляемыми одним PID.

**Контрпример:** во время прогона судьи «Машины» посылают сигнал PID оболочки серии либо `flock`. Дочерний симулятор не обязан завершиться: сигнал одному PID не рассылается всему дереву. При унаследованном дескрипторе слот может остаться занят потомком; если блокировка освободилась, это всё равно не доказывает прекращения вычислений. Зачётный прогон уже должен получить приоритет, а старая нагрузка ещё идёт. Разбор статический, не результат прогона модели.

**Предложение:** запускать серию в отдельной группе/сессии либо cgroup, сохранять её идентификатор и останавливать всех потомков с проверкой завершения. Слот считать свободным для нового счёта только после прекращения вычислений этой серии. Механизм может быть иным, но PID одного процесса без такого охвата недостаточен. Это следует отразить в `go.sh` и передаче при исполнении (11).

## М1. «Без сети» следует уточнить для локального стенда группы

**Место:** (61) п. 1 — пользователь судей «без сети»; п. 4 — второй этап, группа P/01.

**Норма:** P/01.3 Н1 задаёт `-raft`, `-raft-bind`, `-api`, `-join` как адреса `host:port`; приёмка группы проверяет обмен и TLS на этих портах. `GOPROXY=off` и read-only кэш ограничивают зависимости, но не определяют доступность сетевых вызовов стенда.

**Предложение:** при исполнении «Машинами» записать профиль: запрещена внешняя сеть и сеть/службы хоста, но разрешён локальный транспорт участников и раннера внутри изолированного стенда (например, отдельного network namespace). Канарейки проверяют отсутствие выхода наружу при работающей локальной группе. Иначе буквальный полный запрет сети не позволит выполнить второй этап. Это уточнение профиля изоляции, нового дополнения не требует.

Назначение review-codex ревьювером свойств группы принято. Само ревью свойств выполняется после передачи конкретного замороженного кандидата, пина и паспорта; код старых реализаций для него не используется.

**Итого: Б 0, С 1, М 1.**
