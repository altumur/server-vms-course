## Находки

**Б1. C10: противоречие нормы форме — `revoked/README.md:24-25` против `wire.tsv:75`.** README судит множество серийников, форма требует точного равенства JSON-массива (`compare: value`), поэтому мутант `mut-revoked` (обратный порядок) нарушает только каноническую запись `expect` (README:19), а не смысл. Пока правка из таблицы не внесена, мутант не годится для красного набора (согласен с представителем, ответ на его вопрос 2 — «да, исключить до правки»). Режим `set` в закрытом списке `wire.md:71` есть, так что это правка строки формы, а не расширение грамматики.

**М1. C01: ссылка `README.md:348` в пакете неточна.** Фраза «A seam records an actual call and its effects; it does not replace an ordinary process scenario…» — на строке `Platform/common/acceptance/README.md:346`; строка 348 — «Vectors and scenarios remain judge-only». На исход не влияет, норма найдена.

**М2. C02: для P/01.1 содержимое файла движка совпадает с нормой.** По `README.md:122-124` глава 1 кладёт файл с одной ролью `acc` — точно тот JSON, что пишет движок (`run.go:129`). Значит, `readiness:role` на extra у движка имеет причину в другом звене (готовность/путь сокета), а не в выборе файла; на исход класса (движок) не влияет, но ворота C02 должны проверять файл прав для гл. 2/3 по готовому входу, а для гл. 1 — по acc-файлу README:122-124.

**М3. C03: в закрытом списке P/AC-R030 нет причины для неисполненного ASSERT.** Причина `assertion` движка вне списка `norms.md:61`. Исход класса это не меняет (форма ASSERT в словаре README:255-256, исполнение обязательно), но одна уточняющая строка в R030 («не связанные имена ASSERT — `not_executed` с причиной X») сняла бы двусмысленность. Ответ представителю на вопрос 2: привязки живут до конца сценария (README:309), у раннера шаг 11 сценария 33 зелёный — движок потерял привязки или не дошёл; в обоих случаях дефект движка.

**М4. C08: форма отчёта об отказе формата профиля не названа.** `PROFILE.md:13` читается как отказ до старта сборок/процессов (уровень прогона), но норма не говорит, что видят цели: отказ прогона без вердиктов или `not_executed` каждой цели. Предложение: одна строка в PROFILE.md «Command ownership» — «a profile format error refuses the run before any target starts; no target verdict is produced». На исход класса (движок) не влияет.

**М5. C09/C10: `MissingBinding` не сведён с перечнем R030.** R050 называет исход `not_executed` (`MissingBinding`) и README:452 говорит «retain `MissingBinding`/`NOTEXEC`», а в закрытом перечне причин R030 (`norms.md:61`) этого слова нет — оно покрывается разве что хвостом «the name of that interface or key». Гармонизация одной строкой («тестовый вход без файла — причина `MissingBinding` по R050») сняла бы вопрос для обоих классов. Итог C09 (`not_executed`, не `blocked`) из R031+R050+R047 выводится механически и без правки нормы; ответ на вопрос 1 представителя — `not_executed` с причиной N6.5 (у движка уже `fault`).

**М6. C05: 9 строк, красных у обоих судей, пакетом не разобраны.** По норме не решается (это наблюдение о кандидате или о общем чтении таблицы); в класс не входят и на исход C05 не влияют. Остаётся открытым наблюдением калибровки, а не находкой ревью — записал для полноты.

## Согласованность

- Исходы из закрытого списка доп. (8) п. 2; классы «раннер» (C07, C11) — только записи предела, правок нет (доп. (6)); решения владельца/Архитектора не оспариваются.
- C01 и C09 стоят на одной схеме R050: отсутствующий тестовый вход (мост/D7) → записи `not_executed` (`MissingBinding` / причины N6.5), итог цели `not_executed` по R031; `blocked` по R007/R015 — для интерфейсов/частей состава. Противоречия между правилами C01 и C09 нет — они взаимно подкрепляют друг друга.
- Ворота C04 (ключ профиля из `profile-keys.tsv` → маршрут из `targets.routing.tsv`) и C08 (имена подстановок из `profile-substitutions.tsv`) обе читают закрытые формы J-входа на префлайте, без литералов урока — схемы совместимы.
- C05 опирается на контроль «верное/чужое значение» доп. (9) п. 1 с тем же кадром native (`wire.tsv:63`); он не конфликтует с C06 (та же цель: в опись входят только строки `cases.tsv` по `consumers.tsv`).
- C10 — единственный класс «норма»; его правка (режим `set` + маркер `@bad`) меняет форму для всех потребителей `common/revoked`, включая двери из README «Who performs» — это сознательно: сравнение множества там объявлено для всех исполнителей (`revoked/README.md:24-27`).

## Итог

Из 11 классов восемь — движок (C01–C06, C08, C09), два — раннер как записанный предел инструмента (C07 — выход 139 не вердикт, C11 — 3 группы проб из 15 строк `extra.tsv`), один — норма (C10 — противоречие `revoked/README.md:24-25` и `wire.tsv:75`, правка: `compare` → `set` и маркер `@bad` в `wire.tsv:75`). По каждому классу «движок» предложены ворота линии судьи на данных J-входа без запуска кандидата, по C10 — дословная правка спецификации. Ссылки пакетов на нормы в целом точны (отклонение одно, М1); серьёзных пробелов норм, кроме C10, не выявлено — уточнения М3–М5 по желанию. Предложенные правила между собой не противоречат; C01 и C09 опираются на одну и ту же норму R050. Рекомендация: принять классы как разобранные, правку C10 внести до суда попытки 4, мутант `mut-revoked` до правки из красного набора исключить.
