## С

**С1. Право записи строки заказа не названо: таблица без `unit_of` судится не по камере.** П. 1: «Заказ `exp/jobs/<id>` — таблица без держателя».
- P/06.1: запись строки таблицы — `admin`, ниже — по `rights.routes`. `rights.unit_of` связывает строку с **одной** единицей из поля. Без `unit_of` грант точки камеры (`unit:cam/<id>`, `folder:F`) строку таблицы не покрывает, судится подсистема целиком.
- Оператор с `EXPORT` на одну папку получит 403 на строке заказа. Пакет заказа с частями — «всё или ничего», и экспорт отказан целиком, хотя каждую часть ему писать можно.

**Предложение.** Заказа отдельной строкой не делать: данные заказа (`by`, общие настройки) — в ведущей части, у прочих — `export: <id ведущей>`. Право тогда судит платформа по каждой части. Либо `rights.unit_of: {jobs: lead}` с ведущей частью и пометка: строка проверяется по ведущей камере, остальные — частями того же пакета. Тогда назвать, видит ли проверка `unit_of` строку части, создаваемую тем же пакетом.

**С2. Отмену в часть автор записать не может.** П. 1: «отмену [`backend`] пишет в каждую часть». Запись строки единицы после создания — PUT. У `detjob`, образца, «PUT and DELETE stay `admin` on the unit». `backend` пишет по билету автора, а у автора `edit` (`EXPORT`). Значит, отмена — 403.

**Предложение.** Отмена — просьбой `exp/requests` (`cancel-<часть>`), как у `rec` и `auto`: «подача только, судится человек билета» (`calls`, P/06.3 Н1.9). Воркер её читает и отвечает. Либо `rights.routes` даёт PUT ранга `edit` полю отмены. Тогда назвать, как ключ это выражает.

**С3. `admin` на `exp` без `EXPORT` даёт выгрузку, а обратное чтение — функцию, которой не было.** П. 4: `ALLOW_UNPROTECTED_EXPORT`, `ALLOW_SHOW_PRIVACY…` — `admin` на `exp` по камере.
- Ранги упорядочены: `admin` покрывает `edit`. Роль с `ALLOW_UNPROTECTED_EXPORT`, но без `EXPORT`, получает `admin` на `exp` и выгружает.
- Н1.4 читает такую строку обратно как `EXPORT` + оба флага. Перевод перестаёт быть обратимым («сверены перебором», Н1.3).
- `admin` на единицу — это ещё PUT и DELETE чужих частей той же камеры: «без пароля» даёт право снять чужую выгрузку.

**Предложение.** Условие в точке, как у функций Н1.3 («действуют только там, где…»): флаги дают `admin` только вместе с `EXPORT`. Без него флаг не переводится и строки не даёт — сужение. Побочное право на чужие части назвать пределом. Перебор Н1.4 — с `exp`.

## М

**М1. «`depth` — как V/11.8 судит его для архива»: V/11.8 его не судит.** Н1.6: `depth` «не по умолчанию» — 422 `NOT_SUPPORTED`, Н1.4 читает `0`. Для архива глубины нет вовсе. Записать: `depth` не переводится и не судится ни архивом, ни экспортом — предел.

**М2. «`retire_when` — по сроку» — через состояние.** `retire_when` судит значение из списка `in`, а не время. Временной ключ `ends` берёт поле строки (секунды Unix), записанное при создании, а срок файла известен только после `done`. Исполнимо так: держатель части по часам пишет `state.result.end: expired`, `retire_when.in` — `[expired, failed, cancelled]`, файлы удаляет он же. Назвать это, иначе реализация возьмёт `ends`.
