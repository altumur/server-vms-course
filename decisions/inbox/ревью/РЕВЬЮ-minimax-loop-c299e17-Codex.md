## Б1. Судья stagetests может закрыть этап после провала, ненулевого выхода или тайм-аута

**Место:** `loop.py:1788–1806` (`go_events`), `:1839–1855,1877` (`stagetests_gate`).

**Норма:** ADR-0126 доп. (6) п. 3: «Гонки — тем же судьёй с `-race -count=N`»; п. 4: «пропущенный тест красный»; доп. (7) п. 3: «Этап закрыт, когда держатся все».

`go_events` хранит только последнее событие каждого имени (`res[tn] = act`). При нескольких повторениях ранний FAIL затирается поздним PASS. Возвращённые `code` и `pkgfail` не участвуют в итоговом `ok`: ненулевой код замечается лишь в диагностике, если вообще нет событий тестов. Даже строка «таймаут» не меняет `broken`, вычисленный до запуска: если тесты уже напечатали PASS, зависшее завершение также не препятствует зелёному исходу.

**Проба:** в расширенной сухой пробе поддельный судья вернул FAIL подтеста и родителя, затем PASS всех ожидаемых подтестов/родителей, в конце событие `Package fail` и **код процесса 1**. `run_gate` вернул:

```json
{"ok": true, "green": 2, "total": 2, "excluded": 1, "lines": []}
```

Это непосредственно ломает проверку повторных прогонов гонок. В старой ветви `tests:store_core` код 0 требуется; задания 18/18q из рассматриваемого коммита пока используют именно старую ветвь, а не stagetests (см. С5).

**Предложение:** у каждого обычного/race-запуска требовать код 0, отсутствие тайм-аута и package failure. FAIL/skip любого повторения не должен исчезать при следующем PASS; сохранять историю повторов или отрицательный исход с приоритетом. Мера шага — только после всех обязательных повторов. Регрессии: FAIL→PASS, PASS→FAIL, все подтесты PASS + exit 1, package fail после PASS, тайм-аут после PASS.

## С1. Фиктивный ключ `local` останавливает обычный код Qwen и портит текст норм

**Место:** `loop.py:2298–2302` (`key = "local"`), `:514–518` (`leak[key]`), `Roots.scrub():153–156`.

**Договор:** local_api в `9ea9f88` и `tasks/p01-go.ct103-18q.json` — HTTP к локальному llama-server **без ключа**; стражи курса, путей и раннера сохраняются.

Для local_api отсутствие ключа представлено строкой `"local"`, которая затем безусловно используется как секрет: попадает в `secret_hints` и словарь утечек `chat`. Модель вправе написать `localVar`, `localhost`, `localIndex`; следующий запрос будет остановлен как утечка ключа. `scrub` также заменяет подстроку `local` на `<secret>`, включая её в текстах норм и выводе инструментов.

**Проба без транспорта:** настоящий `chat`, local_api, ключ-сентинел `local`, сообщение `localVar := "localhost"` → `не отправлено (ключ; сообщение 0, user)`. Соединение не создавалось. Это дефект активного локального пути, а не отсутствие стражей у него.

**Предложение:** отсутствие ключа обозначать `None`/пустым значением; включать в маскирование и leak только настоящий непустой ключ удалённого API. Для local_api не посылать фиктивный Authorization. Отдельно проверить, что путь хоста и метка раннера по-прежнему блокируются, а слова local/localhost проходят неизменными.

## С2. Настоящие исключённые строки описи генератора не принимаются

**Место:** `loop.py:1394–1412` (`read_inventory`), `:1469–1473` (проверка префикса имени теста).

**Норма:** ADR-0126 доп. (6) п. 4: мера — «зелёные / переведённые / исключённые»; ADR-0125 доп. (4) п. 2: «Остаток сценария исключается целиком с причиной».

Курс `tools/normgen/gen_stagetests.py` для исключённого шага пишет `test = "-"`, `race = "-"`: у шага нет исполняемого теста. `read_inventory` требует **у всех строк** `race in (yes,no)` и имя `Test…`. Одна корректная исключённая строка отвергает опись. После исправления только парсера она вновь будет отвергнута проверкой префикса имени теста, которая тоже проходит по всем строкам, а не только translated.

**Проба:** опись из одного translated-шага и одного `…\tstore_core\t-\texcluded\t-\tstand directive` → `PrepError: строка 3 описи пакета вне формы`. Штатная dry_run скрывает несовместимость: её `INV7` у excluded-шага содержит выдуманные `TestStoreCore_03Restart` и `race no`, в отличие от выхода генератора. Нынешний полный выбор P/01 даёт 204 translated без excluded, поэтому проба на e3022b40 не выявляет проблему.

**Предложение:** валидировать колонки по status; для excluded принимать отсутствие test/race, учитывать шаг в полноте сценария и числе исключённых, но не в выборе тестов/префиксе. Добавить интеграционную фикстуру описи от настоящего генератора с отсечённым хвостом.

## С3. Новые закрытые файлы пакета доступны через алиас пути; helper вне каталога тестов не сверяется

**Место:** `loop.py:103–111` (новое автоматическое readonly), `:119–136` (`Roots.resolve`), `:1376–1379` (`kit_dirs`), `:1820–1834` (целостность stagetests).

**Норма:** ADR-0126 доп. (7) п. 5: «пакет даёт `Handle`… модель пишет `Open`…»; доп. (6) п. 4: «каталог тестов пакета… закрыты для записи модели». README обвеса расширяет закрытие на не-editable файлы частей stagetests/vectors.

Readonly сравнивается с исходным `rest` **до** realpath. Путь `work/01-store/./internal/coreadapter/coreadapter.go` не совпадает с закрытым `01-store/internal/coreadapter/coreadapter.go`, затем нормализуется в тот же файл и разрешается. Это уже существовавший недостаток разрешения путей, на который новое автоматическое закрытие полагается без исправления.

Дополнительно `kit_dirs.files` включает только файлы **внутри** stagetests. Закрытый `coreadapter/coreadapter.go` с пакетным `Handle` находится снаружи и при суде его хеш не проверяется. Так модель может изменить долю пакета, которая должна оставаться доверенной; успешная запись также засчитывается как движение кода.

**Проба:** прямой путь в штатной dry_run запрещён; путь с `./` успешно записал временный helper. При поддельных успешных событиях судья stagetests остался зелёным — изменение helper не вошло в проверку целостности. Это проверка разрешения записи и целостности, а не утверждение о компилируемости изменённого Go.

**Предложение:** сравнивать readonly с нормализованным относительным путём после проверки выхода из корня; одинаково для write/edit. Сверять все не-editable файлы доверенных частей, а не один каталог тестов. Регрессии: `./`, `../`, алиасы файлов/каталогов; отдельно изменение `coreadapter.go` и `cmd/vectors` при прежних хешах тестов.

## С4. Время автоматических запусков исчезает из цены и часового потолка

**Место:** `loop.py:2558`, `:2579–2591`; `tasks/p01-go.ct103-18.json:7,154–157`.

**Договор:** задание ограничено `max_hours: 10`; ADR-0083 доп. (95) сравнивает попытки по активному времени и в п. 4 требует сравнения с шестнадцатой и семнадцатой.

`run_nudge` исполняет shell **до** `t0 = time.time()`. Его длительность нигде не добавляется в `active_sec`, который затем используется для паспорта и `max_hours`. Обычный модельный `run` учитывается через `t1`, автоматический — нет. На повторяющихся сборках и запусках новое вмешательство получает бесплатное активное время; один nudge может ждать весь `run_timeout` (по умолчанию 600 с).

**Проба:** вместо shell — поддельный nudge с коротким ожиданием, без команд/Go. Один nudge занял **0,085 с**, а весь `active_sec` двухходовой попытки составил **0,0009 с**. Счётчик `run_nudges = 1` появился, время — нет.

**Предложение:** измерять и учитывать каждый автоматический запуск в том же счётчике и паспорте, проверять остаток часового бюджета до запуска, ограничивать timeout остатком. Хранить длительность и исход каждого nudge, чтобы сравнение попыток учитывало вмешательство цикла.

## С6. Переименование заметок по-прежнему открывает чтение и даёт сброс

**Место:** `loop.py:57–60` (`code_write`), `:2677–2684` (бюджет и `writes`).

**Норма:** ADR-0083 доп. (95) п. 1: «Запись… — это файл кода или данных реализации… Заметки модели движением не считаются».

Функция проверяет только отрицательный список расширений `.md/.txt/.markdown`. Заметка `work/NOTES.json`, `work/LAUNCH-NOTES` или `work/log.rst` считается кодом независимо от её роли. Проверено в сухой пробе: `code_write("work/NOTES.json") == True`; обе ветви счётчиков используют этот результат без дальнейшей проверки. Причина предыдущего обхода LAUNCH-NOTES.md устраняется только для нескольких суффиксов, а запрет на движение заметками не обеспечен. Повторная запись тех же байтов подходящего файла тоже увеличивает `writes`.

**Предложение:** закрепить распознаваемую область памяти модели независимо от расширения (например, отдельный каталог/инструмент) и считать движение только реальным изменением файлов реализации вне неё и пакета. Не считать все неизвестные расширения кодом автоматически; договор допустимых кода/данных — в профиле. Как минимум добавить регрессии на заметки без расширения/в JSON и на запись без изменения байтов; явно назвать предел, если содержательную классификацию решено оставить модели.
