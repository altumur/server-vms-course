## 3. Соответствие ADR-0129

### (а) Места догадок и двусмысленности — правки нормы

**С1. Вход «ради совместимости» `silent_after?` (З-10).**
- Где: norms:418–420 («This compatibility input… when absent, use the supplied positive lost_after»); vectors/alarms/README:33 («without it the old native input retains `lost_after`»), :81.
- Вход: строки векторов 01–27 без `silent_after` (19 из 22 вычисляемых, `p03-counts.out`).
- Последствие: нынешний сборщик всегда передаёт `silent_after` (norms:413, шов s26). Ветка «поля нет» есть только ради старых строк векторов, писателя у неё нет. Это лишнее требование по З-10 п. 1. Реализация обязана поддерживать два вида входа.
- Предложение: сделать `silent_after` обязательным в обеих формах члена, дописать его в строки 01–27 (у сервера = `lost_after`) и убрать слова compatibility/old. Если `lost_after` больше ни для чего не нужен, решить, снимать ли и его. Решает Архитектор.
- Положительный сосед: строки 28–35 и s26/s27 — нынешний вход; сохраняются.

**С2. Устаревшие счёты векторов и перечни кода 2.**
- Где: spec README:86 («27 rows, rows 15, 17–23 — code 2»); acceptance/README:12 («(27 rows)»); norms:479 и vectors README:23 перечисляют `@exit 2` только 15, 17…23.
- Факт: 35 строк, 13 `@exit 2`, включая 31–35 (`p03-counts.out`). norms:475, vectors README:45 и acceptance README:151 говорят 35.
- Последствие: «Done when» инструкции даёт неверную цель — 27 строк и 8 кодов 2. Линия может закрыть урок без строк 28–35.
- Предложение: в README и N5 назвать 35/13 или сослаться на README набора без чисел (как доп. (5) п. 3). Перечень кода 2 — 15, 17–23, 31–35.
- Сосед: norms:475 и vectors README:45 верны.

**С3. Пересылка `/domain/edits` и `/domain/edits/stranded`: схема P/10 запрещает ответы процесса.**
- Где: api:3441–3478 (401 — только `Unauthenticated`; 403 — только `GateOrRole403`; 404 — только `NotADomainRoute`; 413 — только `ConsoleRefusal`; 503 — только Denied|Unavailable); api:3506–3525 (stranded: то же).

- Последствие: верный ответ процесса, переданный как есть (N1.3, N4), не проходит опубликованную форму. Реализация либо нарушает форму, либо переписывает ответ.
- Предложение: добавить в `anyOf` этих кодов тела P/08 по образцу соседних операций (api:3584–3586).
- Сосед: `passFolderCreate` api:3575–3650 сделан верно.

**С4. Четыре пересылки без ссылки на владельца; POST `/domain/batches` — 200 против 201.**

## 4. Совместимость со старым (З-10)

Проверены места:
- вход `alarms` и строки векторов 01–35;
- чтение вида, теневого отчёта, списка членов, топологии, размещений, `shared`, метки `reported` и поколений `reports/<rev>`;
- окно тревог;
- relay и kept;
- `door.pass` второго рода и обратный вызов;
- `no_kit`;
- пределы ответов 1000/5000;
- указатели истории в README, норме, приёмке, векторах.

Найдено лишнее:
- **С1** — вход `silent_after?` «compatibility», ветка без нынешнего писателя;
- **С10** — активные указатели `id-map.tsv` / former ids и `corrections.tsv`;
- **С12** — предел ответа relay не равен точному пределу писателя.

Нет лишнего:
- `reported: "garbled"`, `page: "garbled"`/`null`, `never` — нынешние отсутствие и повреждение;
- unreadable-исходы строк (503) — нынешнее повреждение;
- отказ `X-W2C-Pass-Ticket` 401 — нынешний запрет, а не старый формат;
- `no_kit` — нынешний режим без ключей;
- топология и размещения при отсутствии строки (`rev 0`) — подлинное отсутствие.

«former shared document» (api:293 и др.) — нынешнее «предыдущее значение», не старый формат.

Не проверено: формы P/08/P/09, которые P/10 берёт по `$ref`, глубже ссылок (раздел 1) — их пределы входят в доп. (19)/(20).

## 5. Три главные находки

1. **С3 + С4:** OpenAPI P/10 не пропускает ответы процесса. `/domain/edits(/stranded)` запрещают тела P/08 для 401/403/404/413/503. Четыре пересылки без `$ref`. `POST /domain/batches` — 200 у P/10 против 201 у P/08.
2. **С1:** `silent_after?` — вход «ради совместимости» без нынешнего писателя (З-10); 19 строк векторов держатся на нём.
3. **С2 + С5 + С6:** цель «27 строк / 8 кодов 2» вместо 35/13. Норма даёт 404 `/domain/alarms` и `not reported yet`, у которых нет формы.
