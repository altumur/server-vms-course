# Второе ревью ADR-0119 доп. (2) (main f3c2a2b67) вместе с (0), (1) («Спецификация»)

Сверено с:
- договором права (`input`, шаги 1–8, `iat`, `roles`, `disabled`);
- P/06.7 Н1.9 (копия грантов у консоли кластера);
- договором пересылки «Адрес клиента» (снятие пришедшего снаружи).

**Счёт: Б 0, С 1, М 2.**

Чисто:
- п. 1 — домен проверяет только пароль, право судит консоль кластера: `may` выразима её входами — копия `domain/grants`, `roles`, метки, `about`, `chains`;
- п. 2 — только билет и признак `X-W2C-Ticket`;
- п. 3 — автор — человек токена;
- п. 4.

## С

**С1. Входы `may` для проверенного человека, которого нет в сеансе.** `may` берёт `user`, `grants`, `roles`, `disabled`, `iat`, `glass`. Для проверенного:
- `user` — имя из `200 {user}` домена;
- `glass` — `false`;
- `grants`, `roles`, `as_of` — те же копии, что у сторожевой этого кластера;
- `disabled` — у члена `[]` по правилу договора. Выключенного домен уже не пропустил: сверка Н1.2 отказывает `disabled`.
- **`iat`** — токена у проверенного нет. Шаг 4а (роль `admin`) сравнивает `iat` с `at` назначения. Предлагаю `iat` = момент ответа домена: проверка свежая, и назначение `admin` раньше неё служит, а после — нет. Иначе — `null`, но `null` договор оставляет «только сессиям без токена».

Нужно это сказать, иначе две реализации посчитают шаг 4а по-разному.

## М

**М1. `need` не уходит в домен.** Тело двери у консоли кластера — `{user, password, need?: {cap, units}}`. Консоль пересылает домену ровно `{user, password}` (доп. (2) п. 4), `need` судит сама после 200. `units` — непустой список `<sub>/<id>` без повторов, не длиннее `EXPORT_CAMERAS_MAX` × частей или своего потолка двери. Иначе 400 до пересылки, без попытки в счёт предела.

**М2. `X-W2C-Ticket` снаружи.** Как `X-W2C-Client`: консоль кластера снимает пришедший снаружи заголовок и ставит свой только на пути билета. Консоль домена снимает его у соединения без сертификата роли `console` (договор пересылки «Адрес клиента»). Иначе человек подставил бы признак сам.
