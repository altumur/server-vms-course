# Ревью ADR-0115, дополнение (8), Codex

Проверена версия `origin/main` **49f6c575d**, вместе с действующими дополнениями (1)–(7). Сверены прежний отчёт Codex о (7), отчёт «Спецификации» о (7), P/06.1 Н3, договор проверки строки («Подготовка полей», П2), P/06.3 Н1.9, P/03.6 Н1.7 и `plugin.schema.json` из указанного клона psim-sdk. Код клонов не запускался.

**Счёт: Б 0, С 1, М 0.** Оба прежних замечания С1, С2 закрыты выбранными процедурами. Есть один новый граничный случай в области применения правила начальных значений.

## Что закрыто

* Прежний С1: начальные записываемые параметры получает шаг установки до создания строки, отсутствие значений — явный отказ. Пустые формы типов больше не используются как черновик настройки; явно переданные `0` и `false` не теряют смысл.
* Прежний С2: управляющий вид и допуск к строке `plugin` сохраняются при выключении. Включение и выключение выполняет названный шаг установки под admin, который меняет `enabled` и пересобирает backend. Состояние `enabled` читается сборщиком вместе с каталогом. Восстановление управления не требует ручной правки `calls`.
* Отказы для параметра `enabled` и таблицы `plugin` устраняют столкновения имён. Предел установки бинаря адаптера при выключении назван.

## С1. Из обязательного установочного ввода не исключены параметры `readonly`

**Место:** доп. (8) п. 1 в совокупности с доп. (3) п. 2.

**Цитаты решения:** «шаг установки получает начальные значения параметров без `default` … и создаёт строку уже с ними; без них установка не завершается». При этом доп. (3) п. 2: «У `parameters` плагина `readonly` — `unit.state.<имя>`».

**Норма источника:** `plugin.schema.json` применяет одну `definitions.parameter` и к параметрам объектов, и к собственным `parameters` плагина. Она допускает `readonly: true` без `default`; смысл `readonly`: «Пользователь не может изменять значение … платформа отклоняет пользовательские изменения». P/03.6 Н1.7 назначает писателем `unit.state` держателя единицы, а не шаг установки.

**Проблема:** допустим, плагин объявил собственный наблюдаемый параметр `connection_state` с `readonly: true` без `default`. Он не является полем конфигурационной строки `unit`, его значение должен опубликовать держатель в состоянии. Но по буквальному правилу п. 1 установка обязана запросить это значение у оператора и отказать без него. Даже полученное значение некуда положить в создаваемую строку: генератор перенёс этот параметр в `unit.state`. Так первоначальная настройка требует ввести наблюдаемое состояние, которое появится только после запуска. Пример выведен из схемы и норм; код плагина не запускался.

**Предложение:** ограничить установочный ввод записываемыми параметрами `Configure`, которые генератор кладёт в `unit.fields`. `readonly`-параметры явно исключить из требования начальных значений и из проверки готовности до `Configure`; до первой публикации их состояние отсутствует/неизвестно. Не переносить их обратно в строку единицы ради установки. Приёмка: плагин с одним настраиваемым параметром без `default` и одним `readonly` без `default` устанавливается после ввода только первого, запускается и затем публикует второй в `state`.
