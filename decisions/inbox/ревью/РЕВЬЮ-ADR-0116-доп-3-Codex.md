## Б1. `ManifestView` недостаточно для схем видов; хэш этой проекции не замечает изменения схемы

**Место:** доп. (3) п. 1, в совокупности с §1 п. 1 ADR-0116 и границей платформы в ADR-0115.

**Цитата решения:** «`ETag` `/kinds` — SHA-256 ответов `GET /manifest` подсистем, которые `backend` читает, и `backend` перечитывает их на каждый `/kinds`».

**Норма:** P/06.5 Н2: «Успех имеет форму `ManifestView`». В `Platform/06-console/spec/06-console.api.openapi.yaml`:

* `ManifestView` — закрытый объект (`additionalProperties: false`); есть `fields` единицы, `display`, метрики и другие перечисленные проекции, но нет `tables`, `unit.state`, `events` и `requests`;
* `FieldView` также закрыт; среди его свойств есть `name`, `type`, `default`, `required`, `enum`, `fixed`, `bound_to`, `inherit`, `merge`, но нет `schema`, `ref`, `hidden`, `items.ref` и `ref_label`.

V/11.1 Н1.3 позволяет backend читать данные только обратными вызовами по билету и закрытому перечню; прямое чтение `platform/manifest/*` не является запасным путём. ADR-0115 ограничивает изменение платформы загрузчиком P/02.1, без правки консоли.

**Проблема:** загрузчик может принять новые ключи, но существующий HTTP-контракт не передаст их backend. В частности, описаний CONTROLLER/SENSOR и `_seen` в `ManifestView` нет: по ADR-0115 это таблицы, а `fields` описывает единицу-плагин. Одна правка загрузчика не превращает эти сведения в свойства ответа закрытого API.

Даже для обычного поля единицы замена только `schema.pattern` или `schema.minimum` не меняет его `FieldView`. Аналогично изменение типа поля таблицы при прежних `display` и прочих проекциях не меняет `ManifestView`. Значит, два разных описания вида получают одинаковый хэш. После обрыва потока клиент отправит прежний `If-None-Match`, и выбранное правило не позволит определить, что ему нужна новая схема. Перезапуск консоли не восполняет потерю данных в проекции.

**Предложение:** явно определить доступный backend полный источник описаний. При сохранении чтения через `GET /manifest` — расширить `ManifestView` и `FieldView`, процедуру формирования ответа P/06.5 и приёмку консоли: передавать описания таблиц, состояния, ограничения полей и остальные метаданные, используемые для `/kinds`. Сохранить маскирование секретных значений. Это правка API/проекции консоли платформы, а не только загрузчика; границу и оценку работ ADR-0115/0116 нужно уточнить. Альтернатива — отдельная нормированная дверь описаний с допуском в `calls`.

**Приёмка:** через настоящий обратный вызов по билету получить схему вида из таблицы psim, затем изменить только ограничение поля, не меняя подписи и прочие старые свойства `ManifestView`. После переподключения запрос `/kinds` со старым `If-None-Match` должен вернуть изменённую схему и новый `ETag`. Пример выведен из контрактов; код не запускался.

## Остальные пункты

П. 1 в части разрыва потока при смене манифеста соответствует P/06.5 Н2 «Гонки». Замена недоступной ревизии на хэш читаемых данных разумна после устранения Б1. П. 2 сохраняет старые id и задаёт UUID v5 новым строкам с кластером и видом в имени; прежняя проблема формы id закрыта. П. 3 явно оставляет `_seen` в `status` основного вида и называет заменённые части решений. Новых замечаний к этим пунктам нет.
