## Прежние пути `harness`

- `harness.Instance` раньше `{data}` не создавал вовсе. Теперь создаёт `{data}` (права по umask) и в нём пустой `configstore` `0700`, затем `chmod`, чтобы umask не изменил право. По нормам `{data}` — существующий каталог экземпляра, внутри которого хранилище получает `-dir {data}/configstore` (`store` и с `a86a5cd88` `store1`).
- Сломаться мог бы только шаблон, который сам делает `mkdir {data}` без `-p`. Таких шаблонов в раннере нет, а норма такой шаблон не допускает: `{data}` даёт стенд.
- Подмена `c_store`: `harness.Instance` внутри `c_store` — это класс `instance_class`, который сам создаёт `data` и `configstore`; обёртка `__init__` (`c_store.py:479–487`) лишь ловит исключение. Двойного `mkdir` нет.
- `created_paths` пробы: теперь `out`, `out/data`, `out/data/configstore`, `out/run`, `rights.json` и файлы улик. Перечень читает только запись `lifecycle` (улика). Порядок — родитель раньше потомка.

## Находка

### М1. Нет теста на каталог у нативной пробы

**Код:** `tests/test_store_probe_native.py`. Новый тест покрывает `harness.Instance`. Путь `store_probe_native.Collector.start` (проба `07-framing`) проверяется только по коду: поддельного store, который отвергает отсутствующий или не `0700` каталог, у пробы нет. Повтор прежнего дефекта на этом пути тесты не увидят. Предложение: тот же `LISTEN`-store из `test_store_directory_prepared` через `Collector.start`, с проверкой `created_paths`.

## Совпадение с нормой

Во всех стендах хранилища каталог `{data}/configstore` создаётся пустым с правами `0700` до первого старта, демон его не создаёт. `-dir` шаблона `store` и `store1` — этот же каталог. Это совпадает с общим README «One data directory», PROFILE «Substitutions» (`a86a5cd88`), `lifecycle.md` и раскладкой P/02.4 N1.1.
