## С1. «Полный манифест» нужно отделить от выдачи секретных значений его умолчаний

**Место:** доп. (4) п. 1.

**Цитата решения:** «`GET /manifest` консоли отдаёт полный манифест подсистемы и его ревизию (`platform/manifest/<sub>`), по билету `backend` на чтение».

**Норма:** P/06.5 Н2: «Поля `*_secret` входят в fields, как прочие … их default — всегда null, даже если манифест его задал: значение секрета не выдаётся». Договор маски, `never.reply`: «201/200/GET — маска на любой глубине; таблицы — поле отсутствует». В P/02.3 Н1.5 поле `yaml` строки `platform/manifest/<sub>` — «байты файла манифеста как есть», то есть оно не является безопасной HTTP-проекцией.

**Проблема:** допустимый манифест может содержать строковый `default` поля `credential_secret`. Его значение сейчас намеренно отсутствует в ответе `/manifest`. Буквальная выдача полного документа из указанной строки вернёт это значение backend по обычному билету чтения манифеста. Расширение набора описаний для построения формы требует метаданных секрета, но не требует выдачи самого секрета. Текст не различает полноту структуры и возврат исходных байтов; это оставляет конфликт с действующим запретом выдачи значений.

**Предложение:** явно сохранить прежнюю границу: полное **структурное описание** манифеста плюс `rev`, с `default: null` у секретных полей, включая описатели таблиц, и действующим маскированием вложенных секретных значений. Сырые `yaml` из `platform/manifest/<sub>` не отдавать. `ETag` при этом остаётся по ревизиям: для его расчёта секретные значения не нужны. В приёмке — манифест с секретным умолчанием и обычным ограничением поля: по билету приходит полная схема и ревизия, а секретного значения в ответе и `/kinds` нет.
