# Второе ревью ADR-0119 доп. (5) (main 0b63e0304) вместе с (0)–(4) («Спецификация»)

Сверено с:
- договором права (`roles` — `"unreadable"`, срок копии);
- ADR-0098 §4;
- P/08.4 Н1.3б (строки ролей и двери их правки);
- договором пересылки («Адрес клиента»).

**Счёт: Б 0, С 1, М 2.**

Чисто:
- п. 1 — `need {cap, sub, units}`, `supervision {<sub>: <роль>}` без имён VMS;
- п. 2 — `required`, `ok` судит консоль;
- п. 3 — нечитаемое в пользу надзора;
- п. 4 — потолок общий с входом;
- п. 5 — слова `may`.

## С

**С1. «Признак билету» (п. 6, доп. (4) п. 1) — без формы, и у `required` два источника.** Без поля `supervisor` `backend` дверь проверки не зовёт и `required` из её ответа не получает. Отказ `403 SUPERVISOR_REQUIRED` держится только на признаке. Его форма по-прежнему не названа:
- имя и значение — например, `X-W2C-Supervision: <sub>[,<sub>…]`: ключи `supervision` всех ролей автора по копии, по возрастанию; нечитаемое — по п. 3 в пользу надзора, то есть все `<sub>` или слово `unreadable`;
- кому — передаче `door.pass` к воркеру по запросу автора;
- доверие — консоль снимает пришедший снаружи и ставит свой, как `X-W2C-Client`.

Нужно и правило согласия двух источников: `required` ответа проверки и признак передачи считаются одной функцией по одной копии ролей. Различие — по моменту чтения, тогда судит ответ проверки, он позже. Иначе реализация признака и реализация двери разойдутся на нечитаемом.

## М

**М1. Правка `supervision` у роли (п. 1).** Значение пишет администратор домена дверью ролей (P/08.4). Проверка формы при записи:
- ключ — имя подсистемы по грамматике P/02.1 `name`; существование подсистемы не судится, как у `ref`;
- значение — имя роли домена по её грамматике;
- роль супервизоров — не сама эта роль, иначе автор подтверждал бы сам себя ролью: 400.

Удалённая роль супервизоров — `ok: false` у всех, по п. 3 в пользу надзора.

**М2. Предел: копия ролей нечитаема.** По п. 3 у всех авторов с любой ролью тогда `required: true` и `ok: false`: экспорт с надзором встаёт целиком, пока копия не починится (P/09.1). Это верно по Driver, но стоит назвать пределом рядом с п. 3: оператор видит `SUPERVISOR_REJECTED`, а не «копия ролей нечитаема». Предлагаю в ответе проверки `supervision.unreadable: true` — `backend` покажет причину.
