## ADR-0115 (25)

Прежние С1 и М1 закрыты: дверь хранилища получает собственный барьер без индекса Raft; права проверяются локально, пересылка — чтением через дверь; сверка консоли разделяет хеш и номер ревизии. Пропуск перезапуска при равных загруженных правах согласуется с проверкой `/v1/rights`: совпадение прав не требует доказательства нового запуска демона. Ожидание `served` работающих подсистем вынесено перед обходом, новая подсистема остаётся отдельным случаем.

### М1. `applied` других участников нужно читать у них, а не в статусе лидера

**Место:** (25), п. 4 (в), строка 306.

**Цитата:** «что видно — голос и `applied` прочих по статусу лидера — команда проверяет сама».

**Норма для сверки:** P/01.3 Н2, `GET /v1/status`: `voters` — массив id, `members` — карта id → адрес `-api`; `commit` и `applied` относятся к самому отвечающему участнику, «Это локальное наблюдение, не подтверждение большинства». Контракт `Status` не содержит индексов остальных членов. P/02.4 Н1.9 `rollout.pre` уже предусматривает отдельные запросы статусов голосующих по адресам `members`.

**Проблема:** состав голосующих у лидера виден, а чужие `applied` в его ответе отсутствуют. Буквальный перенос последней фразы снова потребует данных, которых API не отдаёт. Здесь, в отличие от прежнего `match`, нужные данные доступны существующими отдельными запросами, поэтому достаточно уточнения источника.

**Предложение:** написать: состав/адреса — из `voters`/`members` лидера, состояние, `leader_id` и `applied` каждого прочего голосующего — из его собственного `/v1/status`, с проверкой по принятому барьеру. `-last` подтверждает завершение оператором прочих серверов; наличие флага не заменяет эти проверки. Нового поля статуса не нужно.

М1 можно внести прямо в нормы, без нового решения.

## ADR-0083 (68)

**Новых замечаний нет.**

- С1 (67) закрыт: сжатие охватывает старые вызовы записи и исполнения, а не только чтения; пары вызова/ответа снимаются вместе. NOTES/PLAN имеют отдельные пределы и один снимок; остаточное переполнение имеет явный исход `context`. Дописывание между сжатиями сохраняет неизменный префикс, паспорт разделяет кэшированный и некэшированный вход. Это исполнимый алгоритм для пробы; экономия денег остаётся предметом серверной меры, а не выводом из количества знаков.
- С2 (67) закрыт: свои тесты больше не заслоняют приёмку; остановить последующих судей могут сборка и `vet`. Мера использует неизменный перечень, пропуски не считаются прохождением; отдельный `build_stalled` закрывает раунды без приёмки. Ограничение обратной связи модели не обрезает паспорт.
- С3 (67) закрыт: догадки извлекаются до `done`, блокирующий вопрос приводит к явному выходу `waiting_answer`, ответ приходит через `--resume`. Время ожидания и счётчики отделены от работы модели; ответ без кода сохраняется дословно. Полный учёт ожиданий и вмешательств из (61) п. 2 остаётся обязательным, даже когда ожидание исключено из рабочего лимита часов.
- Независимое вычисление хеша, отдельный кандидат каждого раунда и итог «не годен» при открытых Б/С после третьего раунда устраняют неоднозначность финального ревью. Токены и деньги всех участников, внешний раннер и критерии годности (61) не отменены; границы исполнения и канарейки (61)–(66) также сохраняются.

Колонки конвейера и другие репозитории не изменялись. Нового дополнения по результату не требуется; М1 ADR-0115 — при переносе в нормы.
