## 3. Правило З-10 (доп. (12)): только нынешний формат, без совместимости со старым

Срез ddbd4e7. Проверены: все главы, lifecycle, формы, приёмка (README, scenarios, seams), outcomes, машины, векторы; скан `legacy|former format|old format|migration|deprecated|enc:v1|compatib|SLOT_INDEX|removed|before the key` по non-ru файлам урока + связанные контракты.

Результат: **лишних требований ради старых форматов, данных, состояний, миграций и прежних идентификаторов не найдено.** Разбор проверенных мест:

- читательские допуски нынешних писателей — не совместимость: `released` без значения / `holder` без поля / `server: ""` (03.2:205–209) — терпимость по ADR-0029 к строкам нынешней формы; сохранение `.<name>`-полей при перезаписи ({…row, …}) — общий каталожный паттерн; `previous_*` читается из нынешнего объекта heartbeat;
- «a reference «M11/N» … removed by the moves» (03.7:20) и «the map to former ids is id-map.tsv» — указатели на исторические записи, не требования; номера сценариев/шагов — бывшие номера, явно оговорены как история;
- `enc:v1` встречается только в общем контракте запечатывания («untouched: enc:v1 — do not touch the value, byte for byte», sealing.md:105) — владелец P/06.2, вне P/03; для ревью P/06.2 как контекст.

Два пограничных места (счёт — М6, М7 в разделе 5):

1. 03.5 N3: «not an envelope → as is (a row from before the key)» (03.5:83) + шов `s2-plain-unit` с значением `legacy-plain` (acceptance/5/seams.tsv:6). Формально это требование терпимости к старым данным; при этом sealing-контракт даёт нынешнее основание — development mode без кольца пишет открытые значения сегодня (sealing.md:67 «the values are open — by the norm of the lesson»; env-file.md:68 SECRETS_KEY «not set for a process — development mode»). Решение — «Архитектору»: либо основание переформулировать (development mode / строки до ввода ключа), либо признать лишним по З-10.
2. «`SLOT_INDEX` is removed: the worker unit does not set it» (lifecycle.md:53; дубль в env-file.md:102) — упоминание удалённой переменной в нормативном тексте. Оперативное правило («не задавать») нынешнее, но имя старой переменной — история; предложение — оставить правило без имени переменной, замечание — в исторические документы.

Пределы чтения равны пределам записи (З-10 п. 2) в P/03 подтверждены: все читаемые уроком строки имеют нынешних писателей и исходы нечитабельности; переходов/отказов/усечений ради старых состояний нет.

**Согласование с З-10 поля `gen` без читательского потолка (по вопросу «Архитектора»).** У семейства `slots` проверка двухуровневая. Уровень формы: пределы чтения и записи совпадают — в `data/slots.schema.json` у читателя (`gen: integer ≥ 0, x-whole`) нет потолка, и в `$defs.writer` потолка тоже нет: формат поля с обеих сторон «целое ≥ 0». Поведенческий предел 2^53−1 — не граница формата, а правило допуска операции захвата (P/03.2-R011: сравнение точного gen перед записью, отказ `generation_exhausted` до записи), и к читающей стороне оно применяется симметрично: строка с gen за пределом читается без округления и без зануления (иначе потерялась бы точная строка для оператора), но не захватывается и не перезаписывается, сохраняется байт-в-байт «for recovery»; исход — существующий исход закрытого каталога (refusals.tsv строка 3.2/31), переходов, прав и разрешений старому состоянию нет. Приёмка сама подаёт такие строки как отрицательные случаи (seams s20–s22; sc. 18), а З-10 п. 4 прямо разрешает отрицательную проверку, отвергающую строку нынешним исходом. Поэтому «the reader still accepts wider integers» (03.2:143) — не предел чтения шире предела записи, а отказ операции без потери точности наблюдения; совместимости со старым (захват, интерпретация, миграция) не возникает. Остаточное прочтение, вынесенное на разбор двух отчётов: если по букве З-10 п. 2 «предел записи» понимать как поведенческий предел операции (2^53−1), читательская сторона без потолка — кандидат на правку нормы (именной потолок формата); находкой у меня не засчитано, решение — за разбором.

## 5. Счёт находок: Б 0 / С 3 / М 7

### С1 — дубли объявлений значений таймингов: TTL/MARGIN и HEARTBEAT_EVERY в двух местах каждый

- Где: `Platform/03-worker/spec/03.2-worker.norms.md:58` (`LEASE_TTL: 30; LEASE_MARGIN: 5`) и `:174` (`TTL: 30; MARGIN: 5`); `Platform/03-worker/spec/03.3-worker.norms.md:48` (`HEARTBEAT_EVERY: 10`) и `Platform/03-worker/spec/03.4-worker.norms.md:152` (`HEARTBEAT_EVERY: 10`); третий раз `RENEW_EVERY: ~8.3` (03.2:107) со ссылкой на N1.2.
- reqID: P/03.2-R004, P/03.2-R014, P/03.3-R005, P/03.4-R005/6.
- Причина: доп. (5) п. 1 — каждое именованное число объявлено в одном месте; доп. (2) п. 4 — значение нельзя. Сейчас одни и те же значения несут два имени и два блока в разных главах; «a window of 25 s (N1.6)» (03.2:58) само указывает на другой владелец.
- Контрпример: правка `LEASE_TTL` только в N1.2 (источник шага lease) оставляет N1.6 `TTL: 30` — урок сам себе противоречит, и модель не может определить, какое место источник для формулы `may_act` (03.2:180).
- Предложение: объявить `LEASE_TTL/LEASE_MARGIN/LEASE_EVERY` один раз (N1.2), в N1.6 и в cadence 3.4 ссылаться по имени; `HEARTBEAT_EVERY` — один раз (3.3 N1.2, где уже живут loop-тайминги), в 3.4 N1.1 — имя.

### С2 — каталог отказов противоречит сам себе: условие исчерпания эпохи «=» против «≥»

- Где: `Platform/03-worker/forms/refusals.tsv:15` (строка 3.2/8: «max(current, `platform/epoch_floor`) = 2^53 − 1») против `forms/refusals.tsv:39` (строка 3.2/32: «max(current,floor) >= 2^53 - 1») и нормы `Platform/03-worker/spec/03.2-worker.norms.md:485` (P/03.2-R032: «max(current, floor) >= 2^53 − 1 → a refusal of the issue before the write»; также 03.2:162 и семейная таблица `epoch` — «< 2^53»).
- reqID: P/03.2-R032; форма — refusals.tsv (глава 3.2).
- Причина: одна форма задаёт два разных условия для одного исхода; «=» неверен при значении выше предела (читатель принимает целые шире uint53 — 03.2:143; floor — десятичное целое ≥ 0 по P/01.3).
- Контрпример: `platform/epoch_floor` записан админ-дверью как `2^53 + 10` → `max(current, floor) >= 2^53 − 1` истинно, норма и строка 3.2/32 — отказ до записи; строка 3.2/8 («= 2^53 − 1») не срабатывает — каталог внутренне противоречив.
- Предложение: в строке 3.2/8 заменить «= 2^53 − 1» на «≥ 2^53 − 1» (или снять строку 3.2/8 как дубль 3.2/32 с сохранением ссылки на N1.5).

### С3 — значения констант и безымянные компоненты формул повторяются в прозе и машине вместо имён/ссылок

- Где (избранное; полный список мест): «FOR 300» в тексте журнала и чеклисте (`Platform/03-worker/spec/03.4-worker.norms.md:444`, `:582`) при объявлении `FOR: 300` в `Platform/common/contracts/env-file.md:121`; «WatchdogSec=360» (`Platform/03-worker/lifecycle.md:22`) при объявлении в env-file.md:126; пределы двери 32/8/5 s/64 KiB/s/30 s/1 MiB в чеклисте P/03.4-11 (03.4:590) при объявлении в N1.7 (03.4:227–232); «40/50» (03.2:903 — чеклист P/03.2-12), «(40 − 8.3 ≈ 31 s)» (03.4:571), «20…50» (`lifecycle.md:84`, `03.4:569`) при объявлении в P/02.1 (02.1:459); «age < 50 s» (03.4:397 и heartbeats outcomes `<s>worker`) при объявлении `LOST_AFTER: 45` + `HOLD_SKEW: 5` (`Platform/common/contracts/observation.md:75,98`); литерал «45» вместо `SLOT_TERM` (03.2:99, 03.2:206, 03.2:270, 03.2:412) и в машине «wall + 45.0» (`forms/slot-capture.tsv:37–43`); безымянная «5» в формулах: `TORN_STILL: 45 + 5` (`Platform/common/contracts/slot.md:46`), `WRITE_WINDOW: 45 − 5 = 40`, `CLOSE_BY: 45 + 5 = 50` (03.2:67–68) при именованном «45 + HOLD_SKEW» в той же секции (03.2:66, 03.2:270).

### М2 — незакрытая граница STALL/FOR в `stand_in()`
