## С-01. Локальная метка не закрепляет коммиты отчётов на GitHub

Место: дополнение (1), п. 2, «метка ставится до удаления, чтобы ссылки ADR на коммиты отчётов не повисли»; п. 1 ссылается на достижимость из такой метки.

Точный случай: ветка с единственным отчётом не входит в историю origin/main. На CT создана локальная archive/review-x, после чего ветка удалена на GitHub. Буквальные условия о созданной метке выполнены; на GitHub сохраняемой ссылки на этот коммит может не быть. Локальная достижимость защищает местный объект, но не гарантирует доступность ссылки ADR на GitHub после удаления последней удалённой ссылки. Равенство содержимого с main также не доказывает достижимость исходного коммита отчёта.

Предложение: до удаления последней удалённой ветки требуется опубликованная сохраняемая метка, подтверждённая на том же remote по точному объекту. Для каждого сохраняемого коммита отчёта проверить достижимость из подтверждённого remote main либо сохраняемой remote-метки. Ошибка публикации/чтения/достижимости — пропуск удаления. Не считать создание только местной метки достаточным доказательством. Это проверка сохранности, без нового основания удаления.

## С-02. Один адрес archive/<ветка> не сохраняет независимые поколения ветки

Место: дополнение (1), пп. 1–2, фиксированное имя archive/<ветка>.

Точный случай без переписывания истории: ветка review/x завершилась отчётом A, которого нет в main; создана archive/review/x, ветка удалена. Позже новая ветка с тем же именем создана от нового main и получила отчёт B, не являющийся потомком A. Для второго удаления прежнюю метку нельзя одновременно сохранить на A и поставить на B. Перенос метки теряет единственную сохраняемую ссылку на A; сохранение старой не закрепляет B. Безопасный пропуск возможен, но в норме не определены неизменность меток и разрешение такого конфликта.

Есть и конфликт пространства имён: после сохранения archive/work новая ветка work/fix может быть создана, но метка archive/work/fix конфликтует с уже существующим префиксом. Это проверяется чтением формата имён; Git-команды создания/удаления для опыта не запускались.

Предложение: определить неизменяемое уникальное имя для каждого архивируемого конца, с однозначным кодированием имени ветки и идентификатором поколения/полным SHA. Существующие архивные метки не перемещать и не удалять. До определения совместимого формата совпадение имени или префикса — явный пропуск и строка в отчёте. Сохранять все прежние отчётные коммиты, а не только последний конец повторно использованной ветки.

## Ответы на вопросы задания

1. При совокупном применении основного решения удаление по новому классу также требует положительного release и общих защит, если дополнение не отменяет их явно. Отсутствие hold, чистота и совпадение содержимого с main не являются закрытием задачи. Самостоятельного доказанного случая удаления нужной работы при **всех** этих защитах не найдено. При реализации нельзя прочитать локальные перечисления пп. 1–2 как отмену release, пересечения hold родителем/потомком и проверок открытых файлов/отображений. Чистое дерево незакрытого чтения, чей процесс находится вне дерева между командами, — обязательный отрицательный контроль без release.

2. Одна лишь метка с указанным именем не гарантирует сохранность **всех** ссылок ADR: нужны удалённая достижимость и сохранение предыдущих поколений, как в С-01/С-02. Если отчётный коммит является предком подтверждённой сохраняемой удалённой ссылки, такая ссылка сохраняет его историю. Сходство файлов этого не заменяет.

3. Перед первым включением необходим список точных кандидатов и оснований; отрицательные проверки без release, с активной задачей/hold у родителя и потомка, открытым файлом или mmap при cwd снаружи, с неотслеживаемыми/игнорируемыми файлами, а также с отсутствующей удалённой меткой, недостижимым отчётом, повторным именем и конфликтом префикса метки. Отдельно проверить, что «ветка в origin/main по содержимому» не подменяет проверку достижимости SHA, а исчезновение/смена объекта между списком и удалением приводит к пропуску. Это предложения приёмки, не результаты выполненных опытов.
