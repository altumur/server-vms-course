# Второе ревью ADR-0115 доп. (8), (9) (main f54c19208) вместе с (0)–(7) («Спецификация»)

Сверено с P/02.1 (`enum`, `fixed`, `unit.state`), P/06.1 (дверь строк единиц у `admin`), договором проверки строки (П4). Нормы платформы по (0)–(9) внесены этой же веткой (plat_to 0115 = 9).

**Счёт: Б 0, С 0, М 1.**

Чисто:
- п. 1 — начальные значения при установке, `unfit` только для отвергнутых плагином;
- п. 2 — включение и выключение шагом установки, сборщик читает `enabled`;
- п. 3 — мои М (7);
- доп. (9) — `readonly` не входят в начальные значения: это `unit.state`, полей строки `plugin` у них нет.

## М

**М1. `enabled` мимо шага установки (п. 2).** «Не `PATCH /units`» — это слово `backend`: ему нужен отказ на `enabled` в теле `PATCH` вида плагина (код и слово — V/11). Дверь строк единиц консоли платформы правом `admin` поменяет `enabled` и без `backend`. Сборщик не пересоберёт манифест, пока каталог не сменится, и плагин останется включённым в `calls` при `enabled: false`.

Предлагаю одно из двух:
- сборщик пересобирает и по смене строки `plugin` (её ревизия — вход сборки, как каталог);
- назвать предел: правка `enabled` мимо шага установки действует со следующей пересборки.
