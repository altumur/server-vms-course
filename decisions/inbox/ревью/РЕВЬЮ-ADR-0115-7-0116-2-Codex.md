# Ревью ADR-0115, дополнение (7), Codex

Проверена версия `origin/main` **361b549b4**, вместе с действующим основным текстом и дополнениями (1)–(6). Сверены P/02.1, P/02.3 Н3, P/06.1 Н3, P/06.3 Н1.9, договор проверки строки «Подготовка полей», П2 и П4, V/11.1 Н1.3, исходная схема psim. Прочитаны прежние отчёты Codex, «Спецификации» о (5), (6) и Claude о (6). Код клонов не запускался.

**Счёт по ADR-0115 (7): Б 0, С 2, М 0.**

Закрыто: доступ к строке параметров плагина включён во фрагмент `calls`; единственный id ограничен декларативно; обязательность psim больше не приписывается платформенному `required`; полного удаления данных больше не обещают. Каталог манифестов назван источником сборки. Ниже — два оставшихся разрыва в исполнении уточнённого жизненного цикла.

## С1. Снятие `required` не гарантирует создание строки `plugin` без введённых параметров

**Место:** доп. (7) п. 2.

**Цитата решения:** «Строку `plugin` пишет шаг установки … со значениями `default`. Поля параметров для платформы необязательны (`required` не ставится) … параметр без `default` и без значения — `unfit` … форма заполняет их `PATCH`».

**Норма:** договор проверки строки, «Подготовка полей», шаг 4: для непереданного поля без умолчания берётся пустая форма типа — `""`, `0`, `false`, `[]`. Там же: «Проверки типа и ограничений применяются к полученным значениям». П2 проверяет `enum` и «schema поля любого типа, кроме json, — над разобранным значением». В исходной схеме psim параметр может иметь `pattern`, `min` и `enum_values` без `default`.

**Проблема:** допустим, у плагина есть параметр `endpoint` типа string с `pattern: ^https://` и без `default`. При создании единицы непереданное поле становится `""`, не проходит схему, установка получает 400. Аналогично integer с `min: 1` становится нулём; строковый перечень без пустого значения тоже не проходит. До `unfit` дело не доходит: строки, которую должна править форма, нет. Это уже не прежний отказ по `required`, а проверка ограничений необязательного поля. Для допустимых пустых форм появляется второй вопрос: по сохранённым `0`/`false` адаптер не отличит незаданный параметр от явно заданного допустимого значения.

**Предложение:** выбрать представление и процедуру первоначальной настройки, которые проходят П2. Самый прямой вариант — шаг установки сначала получает необходимые исходные значения и создаёт строку с ними. Если нужен черновик с последующим `PATCH`, явно описать хранение незаданности и проверку ограничений черновика, сохранив полную схему для формы и запуска. Приёмка: установка с параметром без `default` и с непроходящей пустой формой; затем ввод значения и запуск. Отдельно проверить явные `0` и `false`. Это граничные примеры по нормам, не результаты запуска кода.

## С2. Выключение убирает доступ к строке, через которую плагин включается

**Место:** доп. (7) пп. 1 и 4; доп. (5) п. 4 о `GET`/`PATCH` вида плагина.

**Цитата решения:** при `enabled: false` «сборщик исключает его фрагмент из `calls`, `/kinds` вид не показывает»; при этом предусмотрено «повторное включение того же плагина».

**Норма:** п. 1 того же дополнения включает `<s>/<unit.rows>` в обязательный фрагмент именно потому, что «без него форма параметров плагина … не читается и не пишется». P/06.3 Н1.9: «дверь вне `calls` на запросе — 401»; V/11.1 Н1.3 запрещает backend обходить этот перечень прямым доступом к хранилищу.

**Проблема:** после выключения и пересборки исчезает весь фрагмент, включая `<s>/<unit.rows>`. Backend больше не может прочитать `plugin` или записать в него `enabled: true`; вид скрыт из `/kinds`. Значит, предусмотренные `GET`/`PATCH` не дают пути повторного включения. Через прямую дверь консоли под admin это технически возможно, но текст не называет такую процедуру и её обязательную пересборку backend. Для изменения `enabled` обычным `PATCH` также не назван исполнитель, который запускает сборщик после изменения строки: каталог манифестов при этом сам по себе не меняется.

**Предложение:** либо сохранить управляющий вид экземпляра плагина и допуск к его строке при выключении, скрывая только объектные виды и отключая их вызовы; либо явно закрепить включение отдельным шагом установки под admin, вне `/units`. В обоих случаях назвать запуск пересборки после изменения `enabled` и включить состояние этой строки в данные, которые сборщик перечитывает при проверке актуальности результата. Приёмка: выключить плагин, дождаться новой ревизии backend, включить предусмотренным способом и увидеть прежние объекты без ручного восстановления манифеста backend.

# Ревью ADR-0116, дополнение (2), Codex

Проверена та же версия **361b549b4**. Сверены исходный ADR-0116, отчёты Codex и Claude о (0), ADR-0115, V/11.3, V/11.4, V/11.6 и рекомендованный ответ «Консоли» команде.

**Счёт по ADR-0116 (2): Б 0, С 0, М 0. Общий счёт отчёта: Б 0, С 2, М 0.**

* П. 1 возвращает уведомление о смене каталога для всех видов, а не только перезапуск при установке плагина.
* П. 2 сохраняет существующие id и вводит кластер в адрес новой строки таблицы: прежняя неоднозначность между членами домена устранена.
* П. 3 отделяет пользовательские виды от служебных таблиц и наблюдений, исключает независимую запись частей сборок и требует серверную проверку возможности записи уже на этапе 2.
* П. 4 ограничивает снятие типизированным CRUD, сохраняет предметные операции с переводом адресации на этапе 3 и требует сквозную проверку замены сценариев. Условие переноса прежнего покрытия согласуется с V/11.6.
* П. 5 сохраняет существующую семантику записи камеры чужого кластера; замечаний к этому уточнению нет.
* П. 6 разводит `kind` и профиль и исправляет число закреплений контракта.

Прежние С1–С3 и М1–М2 Codex по ADR-0116 закрыты. Новых находок к дополнению (2) нет.
