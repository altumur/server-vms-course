# Ревью ADR-0115 доп. (23), (24) (Claude)

main. Сверено с:
- P/02.3 «Смена манифеста» (процесс читает метку не реже раза в 30 с, останавливается и поднимается супервизором), P/02.3-03;
- P/02.5 Н1.4 (файл прав — префиксы хранилища по ролям), Н1.5 (`door.pass.calls` — сокет роли к консоли, не права хранилища), Н3 `rights --check`;
- P/06.5 Н2 `/manifest/<sub>/source` (`served`, `sha256`);
- V/12.4 Н1.2 шаг 5, Н1.3 шаги 2, 4.

**Счёт: Б 0, С 1, М 3.** Модель Quint по-прежнему не нужна: барьер стал строже, а не сложнее.

Принято:
- барьер без `match`: `leader_id` равен лидеру, `applied` ≥ `commit` лидера, прочитанного после перезапуска;
- `/v1/rights` члена по смыслу равен файлу из манифестов обхода — это сравнение, которое уже есть (`rights --check`), без новых полей;
- консоль — по `served` и `sha256` своей двери;
- одиночке — явный флаг;
- `W2C_HOLD` вместо `enabled: false`;
- один обход: сборка до обхода с плагином, считаемым включённым, а повторная пересборка даёт те же байты;
- `w2cctl rollout` с кодом шага, имя не `pass` — и всё это закрывает С1 (22).

## С

**С1. (23) п. 5: включение и выключение плагина — обход с перезапуском всех членов хранилища, хотя права хранилища не меняются.**
- Переключение пересобирает манифест `backend`, а разница там — в `door.pass.calls` (части `enabled`, `objects`). По P/02.5 `calls` — сокет роли и суд консоли (Н1.5), а не префиксы файла прав (Н1.4). Значит, `rights --check` у членов после переключения тот же, и перезапускать их незачем.
- Консоли поднимутся сами по метке строки `backend` (P/02.3 «Смена манифеста»).

Перезапуск каждого члена ради частого действия администратора — это предел (22) п. 2 (`LOST_AFTER`, переразмещение) без нужды.

Предложение: обход с перезапуском члена — только когда файл прав, собранный из новых манифестов, отличается от прежнего. Иначе `rollout` только кладёт файлы (`manifest get --sha256`) и сверяет консоли. Пусть `rollout` решает это сам: `rights --check` до перезапуска совпал — член не трогается.

Если `objects` всё же добавляет `backendworker` префиксы хранилища, сказать это и оставить обход.

## М

**М1. Ожидания V/12.4 в шаге (23) п. 3 (а).** Сборка до обхода ждёт `served` у изменённых манифестов (Н1.3 шаг 2 — «ожидание ревизии, как Н1.2 шаг 5») и подъём `backend` (шаг 4). Это закончится, только если консоли поднимутся по метке сами, до обхода. Для работающих подсистем так и есть (P/02.3). Для новой — `served` придёт лишь в (в), после перезапуска консоли обходом. Назвать прямо: в (а) ждать `served` работающих (`backend`, зависимых, владельцев); `served` новой — только в (в). Иначе реализация станет ждать в (а) то, что придёт после (б), и встанет по `PSIM_MANIFEST_WAIT`.

**М2. `backend` с `calls` нового плагина раньше консолей.** После (а) `backend` поднимается по метке с `calls`, где уже есть пути `psim-<id>` и часть `objects` (плагин считается включённым). Консоли, ещё не прошедшие обход, этих путей не знают. Вызовы `backend` к ним дадут `404` или `401` закрытого перечня, а описание вида покажет вид, строки которого не читаются. Это предел обхода рядом с (23) п. 4 (а) — назвать.

**М3. «Лидер — последним» исполняет кто.** `w2cctl rollout` запускается на каждом сервере отдельно. Назвать проверку в самой команде: на сервере, где член — лидер, `rollout` отказывает, пока у прочих членов `/v1/rights` не совпал с файлом обхода (та же сверка (24) п. 1). Иначе порядок держится на внимании оператора. На стенде и в V/12.4 порядок серверов тогда выводится, а не задаётся.
