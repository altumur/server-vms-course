## Находки

### И-1 (существенная; вопрос «Архитектору»). `rights` с границами не видит обычных английских «нет прав»

- **Место:** `VMS/10-assist/harness/words.json:19` (`37875e84a`):

  ```
  \bправ(?:а|ами|о|ом)?\b|нет\s+прав|недостаточно\s+прав|\bдоступ|\b(?:no|without)\s+(?:the\s+)?(?:right|permission|access)|\bnot\s+permitted\b
  ```
- **Проба** (node, `norm` и замена `\b` по V/10.5 Н1.2). Не подходят:
  - «You don't have permission to edit Gate-1»;
  - «The admin lacks edit rights on these cameras»;
  - «Insufficient permissions …»;
  - «Permission denied …»;
  - «You are not allowed to edit these units»;
  - «No edit rights on Gate-1» (между `no` и `rights` стоит слово);
  - «Нет разрешения на правку».

  Подходят «You have no rights …», «нет права», «недостаточно прав». Верный отказ «… правка невозможна» и «… not
  allowed» по `fixed` теперь принимается, и это хорошо.
- **Последствие.** Строки V/10.5 Н1.5 «отказ "нет прав", а права есть / единиц не найдено» — добавление v4.0. Пилот мерил
  его на английских ответах стенда 3: R08, R11, R13, M07, N06, M04, N04. Ложный отказ «You don't have permission …» при
  `can_edit: true` у всех найденных теперь принимается: админ видит неверный отказ.
- **Происхождение:** выражение — моё предложение в Н-3 (`5c78d2856`), разбор взял его дословно. Перечень английских форм
  был неполон.
- **Предложение.** Добавить формы:
  - `\b(?:do|does|did)\s*n[o']?t\s+have\s+(?:the\s+)?(?:\w+\s+)?(?:rights?|permissions?|access)\b`;
  - `\b(?:lacks?|insufficient|missing)\s+(?:\w+\s+)?(?:rights?|permissions?|access)\b`;
  - `\bno\s+(?:\w+\s+)?(?:rights?|permissions?)\b`;
  - `\b(?:permission|access)\s+denied\b`;
  - `\bnot\s+(?:allowed|authori[sz]ed|permitted)\s+to\s+(?:edit|change|modify|write)\b`;
  - `нет\s+разрешени`, `\bбез\s+прав\b`, `не\s+имеет\s+прав`.

  `fixed` с «not allowed» без «to edit» сюда не попадёт. Векторы V/10.5 Н5:
  - каждая форма при `can_edit: true` — не принят;
  - «… changing it is not allowed» по `fixed` — принят.

  Это данные харнеса, поэтому решение «Архитектора» и строка перечня «Правки после замера».

### И-2 (существенная). `admin` на `*` проверяется по `grants` напрямую: break-glass и `open` расходятся с `may` и сервером

- **Место:** `VMS/10-assist/spec/10.4-assist.norms.md` Н1.2 «Право»: «у манифеста с `rights.cluster_rows: true` — `admin`
  на `*` … `admin` на `*` — грант `admin` с областью `*` в `grants` сессии (`/session`)».
- **Контрпример.**
  - Аварийная сессия (break-glass, `grants: []`), подсистема `auto` (`auto.subsystem.yaml:158` `cluster_rows: true`).
  - `may` по P/07 Н1.5 даёт break-glass `true`, и сервер у аварийной сессии пишет (договор права, шаг 1, glass → allow).
  - Прямая сверка `grants` даёт `can_edit: false` у всех единиц `auto`.
  - Обзор, `find_units`, полнота и проверка `refuse` расходятся с тем, что запишет «Применить». Модель отказывает «нет
    прав», и проверка это примет (все найденные — `can_edit: false`).
  - То же при `open: true` без `grants`.
- **Источник:** ADR-0093 доп. (4) п. 4 («одно правило … `may` с возможностью двери записи»); P/07 Н1.5 `may` (break-glass,
  `open`).
- **Предложение:** «`admin` на `*` — как `may`: break-glass и `open` — да; иначе грант `admin` с областью `*`». Вектор
  V/10.4 Н5 — break-glass и `cluster_rows`.

### Мелкие

- **М-1.** Полярность (`words.json:13-17`) по `name_in` без форм не видит обычных русских слов (проба):
  - «включена» — подпись поля `cam.enabled` «Включена»;
  - «включите», «выключите», «отключите», «выключена»;
  - английское «turn it on» (фраза — «turn on»).

  Направление безопасное («ask the admin»), но такое `bool` в русских просьбах будет переспрашиваться. Предложение: формы
  в данные. Русские строки не мерены (пробел 2).
- **М-2.** Договор сторожевой и передачи (`Platform/common/contracts/gate-and-pass.md`) сам себе неоднозначен:
  - строка `need` (`:100`): «`PUT/DELETE → admin на единицу | по rights.routes`»;
  - таблица «Права по телу» (`:287`): «у строк единиц понижается только создание».

  V/10.4 Н1.2 следует таблице, ADR-0093 доп. (4) п. 4 («`admin`, если `rights.routes` не понижает») читается и так, и так.
  Это не дефект дельты. Предложение: вопрос владельцу договора о строке `:100`, а в V/10.4 — ссылка на `:287`.
- **М-3.** V/10.6 Н1.3: «После итога применения они живут, пока есть строки `pending` и `skipped` для «Повторить»». Это
  сверх слов ADR-0093 доп. (4) п. 1 («до её применения или сброса»). По смыслу оправдано: «Повторить» несёт метку.
  Предложение: в ADR — «до применения всех строк или сброса».
- **М-4.** По Н-2 разбор решил записать оставшиеся классы в пробелы замера. README пробел 9 говорит о них общими словами,
  без самих классов, которые остаются после `stop` и правила коротких слов:
  - «дней» — `retention_days` и `min_depth_days`;
  - «поток» — `profile`, `grid`, `full`, `live`;
  - слова поля связи `rec.cam` «камера, которую пишет запись» в правиле «как у связанной».

  Предложение: перечислить их в пробелах и в векторах «нарушено, но проходит».
- **М-5.** V/10.5 Н1.2 «Числа текста»: имена единиц для вырезания ищутся «по всем подсистемам». В перечне мест, где
  нечитаемая подсистема пропускается (V/10.4 Н1.2: подсказки, проверка `refuse`), этого места нет. Предложение: добавить
  — пропускается.

Вне решённого, для сведения: `not_found` по-прежнему не видит «нет такой камеры», а `all` — «весь / вся». Разбор этих
форм не заказывал.
