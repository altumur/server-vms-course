Вход: `origin/main` **bfd023f8f8f75c97846ed4afba0ca3b7ee8957a5**. Рассмотрены генераторы № 1–4 и № 6 (включая `gen_stagetests.py`), среды `doorrt`, судьи, тесты и сборка пакета Б. Итог: **Б 1, С 5, М 0**. Реализация требует исправлений; зелёный результат нынешних судей сам по себе недостаточен.

## Б1. Внешние судьи засчитывают отсутствие исполнения

**Место:** `tools/normgen/scenario_judge.py:41–59,76`; `door_judge.py:35–36,79`.

**Норма:** ADR-0125 доп. (4) п. 5: «пропущенный тест — красный»; п. 6: «Шаги проекции должны совпасть с шагами раннера на свидетеле». Доп. (1) п. 1 требует внешнего судьи двери.

`scenario_judge` подставляет `"missing"` с обеих сторон и проверяет только равенство. Если Go не собрался, JSONL пуст, а файл отчёта раннера не появился, каждый отсутствующий с обеих сторон шаг считается совпавшим. Проверено Python-пробой: опись из одного `translated`-шага, пустой JSONL, пустой каталог раннера → `matched 1/1 (green: runner 0, tests 0)`, **код 0**. Ошибка запуска обоих исполнителей превращается в подтверждение генератора.

У `door_judge` родственная проблема: отчёт `{"scenarios":{}}` даёт **`0/0 … PASS`, код 0**. Знаменатель строится из поступившего отчёта, а не из ожидаемой описи: исчезнувший сценарий также уменьшает меру, вместо того чтобы провалить её.

**Предложение:** до сравнения проверить наличие результатов для каждого ожидаемого шага, пригодность завершённых прогонов и привязку к источнику/свидетелю. `missing`, `skip`, ошибка подготовки — отдельный отрицательный исход, никогда не совпадение исполнений. Для двери строить ожидаемый набор из сценариев и правил проекции; отсутствие шага и нулевая мера — отказ. Добавить регрессии на пустой, обрезанный и отсутствующий отчёт, а также на незавершившийся Go-прогон.

## С1. Судья флагов принимает падение демона за успешный запуск

**Место:** `tools/normgen/flag_judge.py:519–548`.

**Норма:** ADR-0125 доп. (1) п. 1: «пробы запуска собранного демона: каждый флаг таблицы, чужой флаг, неверное значение»; в независимом входе `@store-start …` ожидается `ok`.

При ожидаемом запуске отвергается только код 2. Код 1, другой ненулевой код, завершение сигналом и немедленный выход 0 принимаются без проверки готовности. Python-проба `run(<python> -c "raise SystemExit(1)", …, expect="ok", stub=False)` вернула `None`, то есть успех. Так демон, который отказывает неверным флагам кодом 2, а на всех годных падает, может пройти этот суд. Это особенно ослабляет подтверждение на реальном демоне: режим заглушки проверяет больше, но её успешность не доказывает запуск реализации.

**Предложение:** различать разбор флагов заглушкой и запуск демона. Для демона требовать живой готовый процесс/оговорённый признак готовности, аварийный выход считать провалом. Если годная синтаксически проба заведомо не может запустить полноценный демон, отмечать её непроверенной, с причиной, вместо успеха. Сохранить явно оговорённое исключение `box_no_raft` отдельно.

## С2. Проверки свежести № 1 и № 2 доверяют шапке, а не актуальной генерации

**Место:** `tools/normgen/kit/build_kit.py:96–100,114–117,133–154`; паспорт — `:164–180`.

**Норма:** ADR-0125 доп. (1) п. 6 (а): «Сгенерированное входит в пакет Б только после своего судьи… SHA генератора и его судьи — в паспорте попытки». README normgen обещает: «Выход генератора, отставший от формы, — отказ сборки».

Для `checks.go` и `door.go` проверяется лишь присутствие хеша формы в первых трёх строках. Изменение генератора, ручных `runtime.go`/`prims.go`/`doorrt` при неизменной форме не выявляется: сборщик копирует прежние файлы из `out`. Более сильная сверка свежим `render()` уже есть у flags/refusals/vectors/stagetests, но не у этих двух частей.

Проверено без Go: во временную копию каталога checks внесена замена всех `hit == nil && isTrue(v)` на `false`, шапка сохранена. `build_kit.build()` успешно собрал пакет с отключёнными отказами. Это проба отсутствия сверки, а не утверждение, что такой дефект уже лежит в main.

Паспорт сохраняет хеш скопированного файла, однако это не связывает его с актуальным генератором/судом: `provenance` заполняется только для flags/refusals; у базового пакета он пуст. `commit` полезен для восстановления дерева, но не фиксирует, какой выход прошёл внешнего судью.

**Предложение:** сравнивать все копируемые выходы № 1 и № 2 со свежей генерацией, включая ручные копии; до записи каталога назначения проверять весь набор. Для каждой части хранить источники, генератор, ручную среду, судью и ссылку на результат суда именно этого выхода. Добавить пробы «изменилась только среда», «изменилась только логика генератора» и «изменён out при прежней шапке».

## С3. Допустимый `$ref`-алиас создаёт необъявленный Go-идентификатор

**Место:** `tools/normgen/gen_door.py:478–486,719–721,942–947`.

**Норма:** ADR-0125 основной текст п. 1, генератор № 2 — «типы, маршруты, методы, коды, тела отказов против OpenAPI»; `Spec.walk()` явно допускает `$ref`. Ограничение подмножества должно давать отказ генератора, а не некорректный код.

На копии текущего OpenAPI добавлена схема:

```yaml
AliasKey:
  $ref: '#/components/schemas/Key'
```

`Spec` и `build_go` завершаются успешно. Выход содержит `"AliasKey": chkAliasKey` в таблице, но **не содержит `func chkAliasKey(`**: `chk()` для чистого `$ref` возвращает `chkKey`, а внешний цикл игнорирует возвращённое имя и затем конструирует `chk<имя схемы>` самостоятельно. Даже неиспользуемый алиас ломает выход. Подтверждено чтением сгенерированного текста, без компиляции Go.

**Предложение:** сохранять возвращённое имя проверяющей функции для каждой схемы либо генерировать обёртку алиаса. Проверить также алиасы объектов/союзов в ответах; до поддержки отвергать их явно. Регрессия должна проверять не только приём схемы, но и пригодность полученного Go-пакета.

## С4. Генератор векторов не понимает утверждённый список gate

**Место:** `tools/normgen/gen_tests.py:104–120,248–251`.

**Норма:** ADR-0126 доп. (7) п. 3: «`gate` — список через `;`. Этап закрыт, когда держатся все».

`read_stages()` сопоставляет `vectors:<пакет>` со всей ячейкой через `re.fullmatch`, тогда как генератор сценариев уже разбирает элементы списка. Проверено на временной копии формы: замена `vectors:jcs` на допустимое `vectors:jcs;build` исключает jcs из карты, после чего `test_prefix()` отказывает: `no stage with gate vectors:jcs`. Добавление независимой проверки сборки делает корректную форму непригодной для генерации тестов векторов.

**Предложение:** общий разбор списка gate для генераторов, `check_spec` и цикла; в № 6 выбирать отдельные элементы `vectors:`. Сохранить проверку повторов и добавить тесты сочетаний `vectors:…;build`, порядка элементов и пробелов после разделителя.

## С5. Литерал `@` ошибочно обрывает проекцию сценария

**Место:** `tools/normgen/gen_stagetests.py:115–121,154–164`.

**Норма:** ADR-0125 доп. (4) п. 2: префикс кончается на «первом шаге, который процесс не исполняет: директива стенда, сокет роли без личности, сырой HTTP». Обычные строковые значения JSON не являются директивой стенда.

После удаления `@big(…)` генератор считает **любой** оставшийся `@` признаком неподдержанной директивы — в запросе и ожидании. Проба с обычным `POST /v1/write {"items":{"x":"a@b"}}` получила блокировщик `a request directive outside @big`; исправное ядро способно исполнить этот запрос. В непустом сценарии это молча исключит данный шаг и весь хвост; при первом шаге может отвергнуть весь этап как пустую проекцию. Аналогично теряется ожидание с адресом электронной почты.

**Предложение:** распознавать директивы по их грамматике и позиции, а строковые литералы оставлять данными. Добавить пробы `@` в ключах/значениях/ожидаемом теле, сочетания с `@big` и настоящими директивами.

## Переносимость и независимость: границы, которые нужно сохранить явно

Это не дополнительные находки сверх счёта: пилот ограничен P/01, но нынешний обвес ещё нельзя представлять как генератор произвольного урока.

- `gen_checks` переводит объявления и выражения формы, а среда CEL и примитивы заданы руками. Его внешний CEL-эталон действительно отделён от компилятора; это сильнее сравнения с тем же сгенерированным текстом. Словарь `writecheck.Limits`, вызов `Fns.Allowed`, JSON-глубина и договор тела — ручная часть P/01 в `kit/go`, не вывод таблицы.
- `gen_door.WRITECHECK = ("Cmd", "BatchCmd")` и `Spec.excluded()` требуют эти имена даже от другого OpenAPI. Без них генератор откажет до построения двери. Исключения схем следует передавать декларацией урока, а не переносить вместе с генератором. Толкование `integer` как записи без `.eE` также сознательно задано для P/01 и уже JSON Schema; переносить это правило автоматически нельзя.
- `gen_tests.PACKAGES` — открыто объявленная ручная выжимка провода трёх пакетов; пути, колонки и адаптеры jcs/rights заданы кодом. Новый пакет потребует кода, пока договор провода не станет формой.
- `gen_stagetests` и `scenario_judge.CHAPTER_REPORT` привязаны к движку главы 1.1. В движке руками зашиты права `acc/*`, пределы 1048576/524288, время T0, подготовка сценария `21-…` с конкретным ключом `other/21-rights/c9` и особое ожидание шага `22-…/1`. При переименовании сценария смысл этих двух исключений меняется, хотя его строки остаются теми же. Для следующего урока/изменения стенда нужны декларации подготовки, пределов и правил ожидания; швы сами по себе этого не выражают.
- У `flag_judge` модель CEL отдельная от генератора, но `loopback` берётся из общей Python-среды; у `refusal_judge` сверка каталога с таблицей и согласие с apidoor — проверки согласованности. Независимый вход здесь — сценарии приёмки/раннер, и его нельзя заменять этими сверками.
- `vector_judge` проверяет выход по `cases.tsv`, который строит тот же № 6. `test_gen_tests.fake_adapter()` получает ответы из самих векторов; его мутанты identity/allow полезны, но это не замена требуемым мутантам независимого свидетеля c-go. У тестов этапов есть адаптер свидетеля, однако его `cfg.Now` не подключён и судья намеренно исключает seams.tsv: подтверждение обычной проекции не распространяется на часы швов. Внешние серверные прогоны в этом ревью не повторялись.
