## Существенные находки

### С-4. Продолжение прерванного import/restore пересчитывает F1 по текущим часам — [кандидат]

- Норма: P/01.3-R151 («A partial replay MUST preserve the exact saved F1 row (items and index). A partial replay MUST NOT copy back the old floor. A partial replay MUST NOT raise F1 again. … The same input bytes MUST continue that attempt with the same floor»).
- Код: `internal/daemon/local_copy.go:70-108` — при существующем маркере `CopyStep` всё равно выполняется с `Now: float64(time.Now().Unix())`, а `writeStoreState` пишет свежие `writes` (новый `generation_at`, генерация по текущему часу); маркер при этом сохраняет старый `Floor`.
- Сценарий: import прерван после фазы floor; переход часа (или сдвиг часов); повтор той же команды с теми же байтами → в STORE.jsonl записан новый F1 (индекс/содержимое отличаются от сохранённого маркером), floor попытки фактически поднят дважды с разными значениями.
- Последствие: нарушение MUST-нормы на явно названном случае (interruption + continuation); при рестарте в R151 несогласованность маркера и состояния.

### С-5. `Transfer-Encoding: chunked` + `Content-Length`: CL не игнорируется — [кандидат]

- Норма: P/01.1-R054 (фрейминг RFC 9112 §6.3: «With Content-Length and Transfer-Encoding: chunked together the body is read as chunked»); приёмка 1 README: «a body with Content-Length and Transfer-Encoding: chunked together is read as chunked (§6.3)».
- Код: `internal/daemon/http_server.go:126-128` — в `readChunkedBody` передаётся `length` из Content-Length как начальное `decoded`; строка 396: `if size > uint64(math.MaxInt64-decoded) || int64(size) > maxBody-decoded` — при CL больше лимита немедленный 413.
- Сценарий: `POST /v1/write` с `TE: chunked`, `CL: 2000000`, chunked-телом 100 байт валидной команды → 413 вместо 200; операция не выполнена.
- Последствие: допустимый вход RFC 9112 отвергается; зонд приёмки главы 1.1 красный.

### С-6. JCS молча округляет целые числа вне ±2^53 — [кандидат]

- Норма: `vectors/jcs/README.md` + ADR-0072 (RFC 8785 канон в точности); P/01.1 N1 id (документы «compares and signs by bytes»).
- Код: `internal/jcs/jcs.go:59-62` — `case int64: return appendNumber(dst, float64(typed))`. Парсер хранит целые точно (`int64`), канонизатор сужает до binary64: `9007199254740993` → `9007199254740992`.
- Сценарий: вектор `canonical_json.tsv` с целым вне ±(2^53−1): канон и sha256 не совпадают с эталоном (проверить нельзя — таблица judge-only); то же для подписанных документов потребителей JCS.
- Последствие: для больших конечных целых каноническая форма меняет значение документа; альтернативы канона — точная сериализация int64 либо отказ (как для non-finite), что согласовалось бы с GUESSES #2.

## Мелкие находки

### М-7. Грамматика member id не проверена — [кандидат]

P/01.3-R017 (1–128 ASCII, первый буква/цифра, далее буквы/цифры/`_`/`.`/`-`); `internal/daemon/flags.go:610-620` (`validMemberID`) отклоняет только `<= ' '`, `/`, `@`: принимает `a:b`, не-ASCII, длину > 128. Старт с `-id 'a:b'` не отказан кодом 2. Тот же предикат в `-voters`/`-peers`.

### М-8. `duration` принимает многочастные значения — [кандидат]

P/01.3-R031 и шапка daemon-flags.tsv (`duration` = `<integer><unit>`, один unit): `internal/daemon/flags.go:546-566` пропускает `1h30m` через `time.ParseDuration`. Пере-принятие формы; старт, который MUST refuse, не отказан.

### М-9. Жёсткий потолок 512 KiB при загрузке состояния и валидации backup — [кандидат]

P/01.3-R145 (потолок проверки — эффективный `-max-value`): `internal/daemon/local_copy.go:212` (`loadStoreState` → `copyLimits(524288)`) и `internal/daemon/backup.go:121`. Хранилище, запущенное с `-max-value` > 512 KiB и строками больше 512 KiB, после рестарта не открывается (`start_config`); CLI backup отвергает валидную копию такого хранилища.

### М-10. Не заявлены бюджеты ввода/drain и механизм управления часами — [кандидат]

P/01.1-R147/R234 (значения — в описании, пункт 9 «Implementation decides»): в `internal/daemon/http_server.go:16-23` объявлены idle 30 с, header 5 с, body 15 с, drain 2 с, request-line 16384 (в профиле `keys.request_line_limit` ✓) — в пределах первых бюджетов (60/10/30/5 с), но в DESIGN.md/NOTES не записаны; управление часами для seam-сценариев `@clock` (acceptance/1 README «Seam normalization»: «the implementation chooses how it is controlled») не объявлено вовсе — seam-сценарии этапов store_core/durable некому выполнить.

### М-11. QUESTIONS.md отсутствует — [кандидат]

### М-12. GUESSES #2 частично расходится с кодом — [кандидат]
