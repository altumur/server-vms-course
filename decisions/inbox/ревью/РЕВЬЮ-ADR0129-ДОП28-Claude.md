# Независимое ревью ADR-0129 доп. (28), пп. 2–5 — review103-claude

**Вывод: с правками.** Счёт: Б 0 / С 3 / М 2.

Накопление расширений устранило многократный счёт, единица доли теперь общая. Новых ошибок три:

1. **С1.** Минимальна только начальная грамматика. Одно широкое расширение в первом эпизоде снова поглощает всю выборку.
2. **С2.** Доля «без грамматики» при вводе вырождена, и формулы такой владелец не принимал. Вопрос владельцу касается только снятия.
3. **С3.** Отсрочка `gen_admin` «до решения по `launch` на недельной мере» не имеет исхода, если мера `launch` не снимает.

Блокеров нет.

## Ответы на вопросы задания

**1. Однозначны ли ввод и счёт.** Порядок счёта однозначен: пример прошлого круга (E1 вводит `batch`, E2–E5 меняют данные) теперь даёт 1/5 и при вводе, и после. Не однозначны размер расширения (С1) и доля без грамматики (С2, М1).

**2. Верно ли решено условие по `launch`.** Зависимость указана верно: `launch.go` импортирует `admin` (`tools/normgen/launch/go/launch.go:26`) и вызывает `admin.Run` (`:98`), `build_kit.py:323` отказывает без `admin`. `gen_box` часть `launch` не импортирует и по этому условию не откладывается. Решение неполно: нет исхода (С3).

**3. Нет ли нового решения сверх необходимого.** Два: п. 4 распространил две доли на ввод (С2), п. 5 привязал снятие `gen_admin` к мере другого генератора (С3). Пп. 2 и 3 сверх необходимого не идут; объявление грамматики coord103-tools касается только оценки, а класс настоящей формы остаётся по ADR-0127 п. 3.

## Находки

**С1. Минимальность задана только для начальной грамматики.**
- Место: `:498`.
- Цитата: «вместе с расширениями, уже засчитанными более ранними эпизодами выборки; своё расширение идёт в числитель. Начальная грамматика минимальна».
- Контрпример: E1 требует одну новую операцию `batch`. Автор расширяет грамматику сразу общей операцией над списком с произвольными полями. E2–E5 укладываются в неё, доля 1/5 при любой истории. Тот же приём, что и подгонка начальной грамматики, только на шаг позже.
- Источник: цель доп. (27) п. 2; вопрос 1.
- Последствие: порог 1/5 снова проходит любой генератор, у которого хотя бы один эпизод требует расширения.
- Предложение: добавить: «Каждое расширение тоже минимально: только то, что нужно этому эпизоду».

**С2. Доля без грамматики при вводе вырождена и не имеет основания.**
- Место: `:498`, `:500`; `:216`, `:217`; `:246`.
- Цитата: `:500` «считаются обе доли, с грамматикой и без неё. Где решения совпадают, решение применяется; где расходятся, решение не принимается»; `:217` «(не по грамматике формы и не перевод)».
- Контрпример: при вводе п. 2 знает один вид неудачи — расширение грамматики. Без него числитель всегда 0, доля 0/N, «делать». Значит, при доле с грамматикой выше 1/5 решения расходятся и ни один такой кандидат не получает решения: ни «генератор», ни «прозой». Исключение грамматики было только в мере после ввода (`:217`). Оценка до ввода его не имела (`:216` «потребовала бы правки генератора»), и счёт 2 из 8, принятый при владельце, включал расширения `floor` и `batch` (`:228`, `:246`).
- Источник: доп. (8) пп. 2–3, доп. (10) п. 2; вопросы 1, 3.
- Последствие: до ответа владельца ввод любого места с долей выше 1/5 блокирован без исхода, хотя по принятому правилу это проза.
- Предложение: в п. 4 указать: «только для меры после ввода; ввод — по п. 2 и порогу 1/5».

**С3. Отсрочка `gen_admin` не имеет исхода.**
- Место: `:501`; `:253`, `:220`, `:261`.
- Цитата: `:501` «снятие `gen_admin` откладывается до решения по `launch` на недельной мере».
- Контрпример: недельная мера может только дать кандидата при доле выше 1/2. При меньшей доле или при меньше трёх эпизодах `launch` не снимается (`:263`), а часть описана как запуск демона хранилища P/01, история у неё короткая (эпизоды не считал). Решения «снять» тогда не наступит никогда, а `gen_admin` остаётся, хотя доп. (10) п. 4 снимает его не по доле, а за отсутствие формы команд (`:253`). Требование Т1 привязано к мере Т2 другого генератора. Эту формулировку рекомендовал мой отчёт С4; выхода в ней не было.
- Источник: доп. (10) п. 4; вопрос 2.
- Последствие: `gen_admin` остаётся в пакете бессрочно, без записанного решения.
- Предложение (вопрос Архитектору): рекомендую: «На первой недельной мере Архитектор решает по `launch` независимо от доли: либо `launch` и `gen_admin` снимаются вместе, либо оба остаются, и это записывается как исключение из доп. (10) п. 4 с причиной».

### Мелкие

**М1. Доля без грамматики при снятии: знаменатель и смешанный эпизод.** `:500` не говорит, остаётся ли грамматический эпизод в знаменателе. Пример: три эпизода, два грамматических, один нет: 1/3 при полном знаменателе, 1/1 при усечённом, разный исход. Доп. (8) п. 3 (`:217`) считает «против смысловых правок его входа», то есть полный знаменатель. Предложение: записать это; эпизод, менявший и грамматику, и код сверх неё, оставлять в числителе обеих долей.

**М2. Единица «урок» при вводе может заблокировать генератор констант.** `:499` переносит единицу на ввод, а `:263` при меньше трёх эпизодах запрещает ввод. Генератор констант P/01 владелец вернул прямо (`:219`), форма `Platform/01-store/forms/runtime-constants.tsv` имеет два коммита. Эпизоды места я не считал. Если их меньше трёх, возврат не исполнится, тогда как общая для уроков история могла бы дать три. Предложение: при оценке `3d` проверить и, если так, вынести Архитектору отдельно. Единицу «урок» рекомендовал мой отчёт С3.
