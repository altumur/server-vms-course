## Существенные

**С-1. `unit` триггера против `unit`/`of` строки журнала: форма сравнения не определена**
- **Место.**
  - `07.2-auto.norms.md:50-51`: «`unit` строки (или `of`) = `unit` триггера, каждое поле `match` равно полю строки строго
    (`"1"` ≠ `1`)».
  - Схема триггера (манифест `:55`): `unit: {type: [string, integer]}`.
  - Приёмка 1 шаг 1: `"unit": "12"`.
- **Источник:**
  - договор журнала событий: `unit` строки — полная ссылка `<sub>/<id>` (P/06.4: `unit: "console/<экземпляр>"`), `of` —
    `cam/<id>`;
  - V/04 приёмка 4: `/events?unit=cam/$c1`.
- **Контрпример:** триггер `{sub: cam, kind: io.input, unit: "12"}`, строка `{unit: "cam/12", …}`.
  - A сравнивает строку целиком: `"12" ≠ "cam/12"`, сценарий не срабатывает никогда.
  - B отрезает `<sub>/`.
  - C сравнивает и число `12`.
  - У триггера `det` — `unit: "7-linecross"` против `of: cam/7`.
- **Предложение:** `unit` триггера — id единицы подсистемы `sub`. Сравнение — с `<sub>/<unit>` строки или `of`; число —
  своей десятичной записью.

**С-2. `match` строгий, а тип поля `port` события `io.input` нигде не задан; отсчёт портов — тоже**
- **Место.**
  - `07.2:51`: «каждое поле `match` равно полю строки строго (`"1"` ≠ `1`)».
  - Приёмка 1 шаг 1: `"match": {"port": "1", "value": "closed"}`.
  - V/01.2 Н1.5: `io.input` — «порт — поле строки», без типа.
  - `07.3:39`, `:41`: «номер входа ≤ `rays`», «`port` ≤ `relays`». Отсчёт портов с 0 или с 1 не сказан ни здесь, ни в
    V/01.4.
- **Контрпример.**
  - Держатель A пишет `port: 1`, B — `port: "1"`. Сценарий приёмки срабатывает только у B.
  - `rays: 2`, вход 0 у устройства с отсчётом с 0: «≤ rays» пропускает 0..2 — три входа.
- **Предложение:** в V/01.2 Н1.5 — тип и отсчёт поля `port` (целое, с 1). В V/07.2 — правило сравнения числа и его
  десятичной записи либо требование писать `match` типом поля.

**С-3. `minutes`, `before`, `after` без границ; `before` < 0 — задача скана, которая не кончается**
- **Место:** схема `then` (манифест `:90`, `:99`, `:108-109`): `{type: [number, string]}` без границ. Норма `07.4:45`,
  `:59`, `:70` — `until = occurred + minutes × 60`, окно `[occurred − before, occurred + after)`.
- **Контрпример.**
  - `{action: scan, before: -120, after: 60}` — окно `[occurred + 120, occurred + 60)`, `from > to`. Это задача V/05 с
    `asked` < 0: итог не по схеме, задача вечна (V/05 С-2).
  - `minutes: -5` — `until` в прошлом: заказ сразу снят или удалён.
  - `minutes: "ten"` — строка разрешена схемой, смысл не назван.
- **Предложение:** `number`, `minimum` (`minutes` ≥ 1, `before`, `after` ≥ 0), `maximum` в схеме; строку — снять или
  назвать правило.

**С-4. Имя просьбы `auto.<сценарий>-<id события>-<i>` не умещается в 200 байт `rid`**
- **Место:** `07.4-auto.norms.md:35-37`: «Имя просьбы — по ключу подателя: `auto.<сценарий>-<id события>-<i>`».
- **Источник.**
  - Договор просьбы: `rid` «непустой, ≤ 200 байт UTF-8»; подстановка, давшая `rid` не по грамматике, — отказ подачи.
  - Договор журнала событий: `id` строки — `e1-<hexUTF8(дерево)>-<hexUTF8(единица)>-<эпоха>-<hexUTF8(экземпляр)>-<номер>`:
    дерево, единица и экземпляр — шестнадцатеричной записью, вдвое длиннее.
- **Контрпример:**
  - событие детектора `7-linecross` (22 hex) воркера `d-srv-a-1` (18 hex) — `id` ≈ 60 байт;
  - сценарий «Открыть ворота при номере на въезде грузовой зоны» (≈ 95 байт UTF-8);
  - `rid` ≈ 5 + 95 + 1 + 60 + 2 = 163 байта;
  - на 20 знаков длиннее — больше 200: подача отвергнута (`filings.refused`), ворота не откроются никогда.
  - Имя сценария — единица (до 1024 байт ключа). Чеклист: «для составного ключа измерен результат с префиксами».
- **Предложение:** ключ — хеш (`auto.<sha256(сценарий, id события, i)>` усечённый) или предел длины имени сценария со
  своим отказом у двери.

**С-5. Запись по сценарию на томе без `cam` — 409 у заказа** (следствие V/02 Б-1)
- **Место:** `07.4-auto.norms.md:70-71`: «`home` = `archive` действия (том; запись чужой камеры на карту — `must_match`,
  `creates.refused`)».
- **Контрпример:** `{action: record, cam: 7, archive: disk-a}` на томе `local` без поля `cam`. По договору проверки
  строки `must_match: {cam: cam}` у `home` — 409 (V/02 Б-1). Заказ `creates.refused` на каждом томе, кроме карты.
- **Предложение:** решается вместе с V/02 Б-1. До решения — норма V/07.4 называет исход.

**С-6. Просьбы между камерами склеиваются без события в ключе: вторая сработка теряется, поздний повтор исполняется
снова**
- **Место.**
  - `07.5-auto.norms.md:86`: «равная живая просьба (`by`, цель, действие) — тот же номер».
  - Исполнитель документа — «первый по имени слота живой вычислитель кластера», без эпохи и аренды (`:53`); курсор
    документа — в памяти (`:51`). Гонки (`:121-122`): «Два вычислителя кластера сочли себя первыми — оба исполняют …:
    просьбы равны (тот же номер у приёмника)».
- **Контрпример.**
  - Две разные машины у ворот за 10 с — две сработки. У приёмника — «равная живая просьба», одна, вторая теряется.
  - Два вычислителя сочли себя первыми, первая просьба исполнена (не живая). Второй, отставший, подаёт её снова — новая,
    ворота открываются дважды.
  - В кластере «ровно один вычислитель» даёт эпоха (`07.1:26-27`), здесь — ничто.
- **Предложение:** в ключ просьбы — имя сработки (`<сценарий>-<id события>`, как у сценария кластера). Исходы помнить по
  нему (`REMEMBER` 15 мин уже есть).

**С-7. Документ домена: `valid_for` с другой нижней границей при «том же имени»**

  - У сценария кластера `:120`: `0` или `5…600`; «пять секунд хотя бы — меньше короче дороги от события до устройства».
  - Норма `07.5:43`: «тем же именем, что у сценария кластера».
- **Контрпример:** `valid_for: 0.5` у сценария домена проходит форму; просьба на приёмнике истекает раньше, чем дойдёт
  (`expired`). `valid_for: 0` в домене — отказ формы, в кластере — умолчание.
- **Предложение:** одна граница (`0` или `5…600`) на обеих сторонах.
