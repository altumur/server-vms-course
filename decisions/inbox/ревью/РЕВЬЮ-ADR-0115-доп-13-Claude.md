# Ревью текста: ADR-0115 доп. (13) (Claude)

Доп. (13) на main 9e78a8f30. Сверено с:
- P/02.1 `tableName` — «целиком `[a-z][a-z0-9_-]{0,31}`», и перечнем запрещённых имён (`02.1-installer.norms.md:886`);
- ADR-0115 доп. (4) п. 2 (`<т>` ≤ 27 ради `<т>_seen`);
- доп. (10).

**Счёт: Б 0, С 0, М 2.** Кольцо `<т>_events` — путь без правки платформы: пишет владелец (`worker.writes`), читает зависимый (`worker.reads`), предел кольца назван.

## М

**М1. Имя и порядок кольца.**
- `<т>_events` длиннее `<т>_seen` на два знака. Чтобы оно влезло в `tableName`, `<т>` должна быть не длиннее 25 знаков, а не 27, как в доп. (4) п. 2. Совпадение `<т>_events` с именем другого вида — отказ генератора, как у `_seen`.
- Зависимый читает кольцо целиком и должен отличать новое от прочитанного. Ключ строки — монотонный номер (`<seq>`, ноли слева), перезапись по кругу — `seq mod PSIM_EVENTS_RING`, а в строке — сам `seq`. Иначе после перезапуска зависимый не знает, где остановился, и повторит или пропустит.
- Кольцо — для каждого вида или только для видов, которые назвал чужой `source`? Сборщик это знает (доп. (10) п. 1). Писать строку на каждое событие каждого вида без читателя — лишняя запись хранилища. Предлагаю: только виды из чужих `source`, пересборка добавляет.

**М2. М3 (10) — ответа по-прежнему нет.** П. 2 ссылается на доп. (10) п. 3: «сборщик пересобирает и по ревизии строк `plugin`». Но сборщик — шаг установки, он не работает между шагами. Запись `enabled` дверью администратора между ними пересборки не вызовет, пока шаг не запустят снова. Достаточно одного слова: «до следующего шага установки — предел (8) п. 2». Только М — в нормы без дополнения.
