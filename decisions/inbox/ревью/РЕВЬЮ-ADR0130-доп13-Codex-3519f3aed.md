## Б-01. Начало возраста id переносится раньше гарантированного первого применения

**Место:** Add13:226, п.13. Цитата: «Возраст памяти `id` считается по времени допуска, потому что переживает перезапуск».

**Нарушаемая опора:** `Platform/01-store/spec/01.1-store.norms.md:453–470,736–739`, R069/R070/R141; Add1 D2:87; `Platform/common/contracts/store-client.md:94–102`. R141 требует, чтобы возраст был строго больше существующего минимума **с первого применения**, и чтобы после него было достаточно применённых записей с id. Допуск назначается при помещении записи в лог; применение наступает позднее. Персистентность метки не делает события одинаковыми.

**Контрпример:** между допуском и первым успешным применением есть задержка. Затем достигнуто требуемое число последующих успешных id-применений. С допуска прошло больше минимума, с первого применения — ещё нет. Удаление по возрасту допуска разрешит забыть первый ответ раньше R141; допустимый replay может примениться вновь с новой версией. Скачок часов для этого не нужен, новое число или скорость не назначаются.

**Предложение Архитектору:** явно сохранить оба нижних условия R141, включая начало возрастной гарантии с первого успешного применения, и описать, как выбранный долговечный учёт это обеспечивает. Если намерение — изменить саму гарантию, назвать это отдельным изменением смысла, а не следствием сохранности admission metadata. Блокируется именно эквивалентность нынешним минимумам; выбор внутреннего формата состояния не предписывается.

## С-01. «Один сервер» неоднозначен для одноголосующей Raft-группы

**Место:** Add13:215. Цитата: «Отказ старта остаётся только для одного сервера. В группе узел стартует…».

**Опора:** `Platform/01-store/spec/01.3-store.norms.md:44–47,104–110,132–152,163–171`. Группа допускает одного голосующего. Box определяется отдельно как сборка **без Raft**; только ему дан offline-import в каталог остановленного демона.

**Контрпример:** import прерван в допустимой Raft-группе из одного голосующего. По числу серверов её старт запрещён; лидера и `admin.sock` нет. По признаку группы тот же старт разрешён. Намеченное устранение зависимости доступа остаётся неоднозначным.

**Предложение:** назвать режим: отказ на незавершённом offline-import остаётся для box без Raft; Raft-группа, включая одного голосующего, стартует для продолжения import с удержанием ordinary writers. Остальные отказы старта, владение каталогом и isolation сохраняются.

## С-02. Полный диск не отменяет фазовые ambiguous-исходы

**Место:** Add13:220. Цитата: «Заполненный диск: запись отказывает 503 `unavailable` без частичного результата».

**Опора:** Add1 D5:97; `01.1-store.norms.md:768–772`, R144; `production-acceptance.md:72–75`, F01–F04.

**Контрпример:** носитель уже получил полную восстанавливаемую операцию, затем отказал барьер. `ambiguous_barrier` требует целой публикации с согласованным id и неизвестного исхода для клиента; повтор завершает барьеры. Другой допустимый случай — medium activity без доказанного отсутствия recoverable результата. Тип ошибки ENOSPC не превращает их в определённое «операция не сделана». Отсутствие половины пакета не доказывает отсутствие целого эффекта.

**Предложение:** ограничить `unavailable` доказанным отказом до эффекта. Для уже начатой работы сохранить D5/R144: неизвестный medium/barrier результат, целостность операции/id и replay barriers. Не вводить новый отказ или обещание rollback при любом заполнении.

## С-03. Амплитуда скачка, разброс часов и admission_ahead — разные предикаты

**Место:** Add13:226. Цитаты: «Скачок вперёд сверх `CLOCK_SKEW` — нарушение посылки развёртывания»; «записи `expired`, пока часы не догонят, а оператор видит `admission_ahead`».

**Опора:** `01.1-store.norms.md:79–86,453–470`, R013/R070; `01.3-store.norms.md:91–97`.

**Контрпример:** все часы писателей синхронно сдвинулись вперёд, затем вернулись. Их попарный разброс остаётся нулевым, R013 не нарушен; общий откат прямо разрешён. Admission уже мог подняться и сохраняться после возврата. Сам forward без возврата не гарантирует `admission_ahead`: поле сравнивает сохранённый admission с **нынешними часами лидера**. Запись без `not_after` также не получает `expired` по этому основанию.

**Предложение:** нарушение связывать с фактическим межчасовым разбросом; последствия — с собственными условиями R070/N1.3. Admission не убывает; `expired` зависит от `not_after`; `admission_ahead` появляется лишь при заданном отставании текущих часов от сохранённого admission. Общий сдвиг, возврат, смена лидера и снимок — разные наблюдения. Новый маршрут/аларм/допуск не требуется.

## С-04. Сумма сроков не устраняет окно отдельной отправленной попытки

**Место:** Add13:224. Цитаты: «Суммарный срок попыток двери не меньше `-leader-wait`»; «лишний `ambiguous` убирается».

**Опора:** `01.3-store.norms.md:51,59,158–161`; действующие `runtime-constants.tsv:11–12` и `daemon-flags.tsv:37`; `store-client.md:38–39,80–102`. Историческая постановка — Claude С12:166–173 и поздний Kimi Q2:77.

**Контрпример на уже заданных defaults:** timeout2s + margin1s дают попытку3s; leader wait5s. Разрешённое объявленное число две попытки даёт суммарно6s≥5s, но первая отправленная запись всё равно теряет ответ через3s, пока голосующий ещё может ждать лидера. У записи id необязателен: агрегированный allowance не разрешает безопасно повторить неизвестный write без него. Это контрпример допустимого объявления, не предложение новых уставок.

**Предложение:** определить условие для **каждой отправленной попытки** с учётом оставшегося leader wait, единого сквозного остатка и F, либо честно сохранить консервативный `ambiguous`. Ни hop, ни retry не начинают бюджет заново. Count и общая сумма сами по себе обещанного устранения окна не обеспечивают. Фраза об отсутствии прежнего нарушения не прочитана как отрицание самого существования окна.

Common-owned TLS/клиентские повторы второй раз не пересчитываются.

## С-06. Recover после partial import требует определения судьбы F1

**Место:** Add13:215. Цитата: «При потере большинства выход — `recover`, норма называет его явно».

**Опора:** `01.3-store.norms.md:104–110,112–124,147–151,324–358`, R020/R021/R026/R027; разрешённый поздний Kimi Q1:76. Исходное Claude С1 в crosswalk — одна строка; здесь другое исправимое условие, чем термин box/один голосующий в С-01.

**Контрпример:** import опубликовал F1, перенёс только часть неизменного входа, затем большинство потеряно. Recover повышает floor до F2>F1. Replay прежней попытки обязан сохранять точно F1; понижать floor нельзя. Текст не выбирает, отменена ли прежняя попытка, какой floor теперь authoritative и как доводится полный вход. Просто допустить писателей после recover на частичном переносе также не исполняет Done.

**Вопрос Архитектору с рекомендацией:** выбрать судьбу старой попытки/F1, authoritative нового floor и последующий полный перенос либо назвать свежую группу отдельным путём. Сохранить isolation, надёжный upper/отказ при неизвестном, невозврат floor и полноту. Выбор recover не оспаривается; без стыковки его одного имени недостаточно. Модель recover как выход из group-import эту ветвь не проверяла — её результат не подставляется вместо выбора.

## М-01. Причину про atomic_only следует ограничить рассмотренной абстракцией

**Место:** Add13:216. Цитата: «Атомарная публикация не выбрана: модель показала, что она не держится, а отказ старта держится».

## Числа, применимость и D7 — вопросы 2–4

Add13 не задаёт новых фиксированных числовых уставок. Конечные положительные бюджеты объявляет реализация, а применение квалифицируется со входом среды; произвольная декларация не заменяет квалификацию и не отменяет уже выбранные limits. Фраза production-acceptance:13 «agree finite positive values» явно назначена к редакции и сама не посчитана новым дефектом. Числа2/1/5 в С-04 — существующие Source defaults, count2 — допустимый контрпример, не предлагаемая политика. Б-01 показывает, что отсутствие новой цифры ещё не сохраняет смысл прежнего минимума.

Порядок проверок и владельцы сохраняются: прочитанный корректный запрос при остановке не отменяет framing/identity precedence; unknown write не становится no-effect; исключение admin относится к ordinary saturation, не к неограниченным ресурсам. Copy до успешных headers сохраняет прежний отказ, после начала200 — обрыв, без второго отказа; чтение не получает write `ambiguous`. Пакетные исходы/идентичности сохраняются целыми.

Часы через D7 вместо `@clock` — правильное направление: Add11 и `Platform/common/acceptance/README.md:386–428` требуют actual identity/invoke, правильную capability/scope/phase, независимый observer, qualification и negative controls. Clock domain/unit и реальная consuming boundary отделены от монотонного deadline.
