## С1. `may()` не выполняет нынешний договор прав

**Место:** P/07-02, [Н1.5 `may`](../../../Platform/07-console-module/spec/07-console-module.norms.md), строки 116–124; [console.js](../../../Source/w2cplatform/console.js), 561–579; Н5 `module-may`.

**Цитаты нормы:** «admin: true … — true»; «elements of grants with role are role groups, counted by the tiers»; `console.may(cap, ref, sub?)`.

Реализация принимает два аргумента, проверяет только плоские cap/scope и не читает `admin`, `sub`, `role` или папки. Поэтому действительный администратор с пустыми grants лишается всех кнопок, чужая подсистема даёт ложную разрешающую подсказку, а `none` точного яруса роли не затеняет её общий edit. Три случая воспроизведены выше; серверная проверка не отменяет неверное поведение интерфейса. Существующий `module-may` проверяет только прежний плоский договор и не замечает эти нарушения.

**Предложение:** владельцу байтов реализовать нынешний договор (включая сбор/unknown цепочек папок), дополнить критерии Н5 случаями admin, sub, role tiers и folder/unknown. До исправления записать это явным долгом владельца, сохранив запрет переписывания модуля линией.

## С2. Мгновенный bool-переключатель обходит CAS формы

**Место:** P/07-04, Н1.5 `forms`, строки 109–111; [console.js](../../../Source/w2cplatform/console.js), 1370–1378 и 1537–1555.

**Цитата нормы:** «the unit form (unitForm) sends PUT and DELETE with ifMatch — the revision of the shown row, always».

Обычное сохранение и удаление используют shownRevision, но `wireSwitches()` отправляет PUT непосредственно, без четвёртого аргумента `api`. На форме revision 4 щелчок enabled даёт `{enabled:false}` без If-Match. При параллельной правке он может молча перезаписать чужое значение; 412 не появляется, хотя норма распространяется на все PUT формы. `module-form-if-match` не щёлкает bool.

**Предложение:** единый путь записи полей формы с показанной revision и экраном 412; проверить переключатель, два быстрых щелчка и конфликт revision. Отдельно запретить запись формы, если обязательная revision строки не прочитана: нынешний fallback `shownRevision=undefined` также снимает CAS.

## С3. Ручной повтор сохраняет ссылку на изменяемое тело

**Место:** P/07-02, Н1.5 `api`, строки 97–103; описание §7 п. 3; [console.js](../../../Source/w2cplatform/console.js), 411–413, 445–447, 721–729.

**Цитата нормы:** «the replays of this action keep the key and the original body».

`send` сериализует тело один раз для автоматических повторов, но при исчерпании сохраняет в `lastRetry` исходный объект по ссылке. Если оболочка меняет этот объект до щелчка «Повторить», новый `send` сериализует уже другие данные с прежним ключом. Проба: четыре отправки `{"name":"original"}`, затем пятая `{"name":"mutated"}`; ключ один. Дверь справедливо откажет по digest, а результат совершённого действия уже нельзя получить обещанным повтором. Договор не требует от оболочки замораживать объект после вызова.

**Предложение:** хранить неизменяемый снимок тела вместе с ключом до окончательного результата и повторять именно его; в Н5 `module-retry` добавить изменение исходного объекта после вызова, в том числе вложенного поля.

## С4. Тайм-аут заканчивается до чтения тела ответа

**Место:** P/07-02, Н1.5 `api`, строки 98–101; [console.js](../../../Source/w2cplatform/console.js), 419–426; Н5 `module-retry`.

**Цитата нормы:** «Network/timeout 20 s/5xx/409 in flight allow a replay only at these doors».

Таймер снимается сразу после `await fetch`; затем `await r.json()` находится вне его срока и вне обработки сетевой ошибки. Получить headers ещё не значит прочитать ответ: при зависшем body действие остаётся навсегда pending без предусмотренного повтора; при обрыве JSON тело превращается в null, и успешный HTTP-код закрывает действие как успешное. Проба с полученными headers и незавершающимся `json()` не получила ни abort, ни повтор. Тест проверяет только fetch, зависший **до** ответа.

**Предложение:** уточнить в норме якорь/охват 20 с: отдельная попытка до полного чтения ответа; держать abort/срок и обработку потери до конца body. Проверки: headers→stall, headers→обрыв; для POST единиц — тот же ключ/снимок тела, для PUT/таблиц — unknown и чтение без автоповтора.

## С5. Форма не понимает нормативную подпись `{key, text}`

**Место:** P/07-02, Н1.5 `words` и отсылка к P/06.5 Н1.2 (строка 162); [06.5-console.norms.md](../../../Platform/06-console/spec/06.5-console.norms.md), 129–130; [console.js](../../../Source/w2cplatform/console.js), 477–486, 1301–1304, 1328–1332.

**Цитата нормы P/06.5:** «a caption (unit, units, fields, field_help, options, kinds) — a string or {key, text} … the module displays text».

ManifestView отдаёт display как записан; однако `fieldTitle`, `unitWord`, `kindWord` и подсказки возвращают объект прямо в строковый шаблон. Допустимый label `{key:n,text:"Readable name"}` и такой же field_help дают `[object Object]` в подписи/tooltip. Проверки словаря используют только строковые display и потому зелёные.

**Предложение:** единый разбор label: строка либо `.text` объекта для всех перечисленных мест; языки `display.langs` по-прежнему принадлежат backend, не модулю. Добавить строковый и объектный варианты в критерии JS, включая enum и event kind.

## С6. `hidden` теряется до формы и не учитывается самой формой

**Место:** P/07-02, форма по манифесту; [P/06.5 Н1.2](../../../Platform/06-console/spec/06.5-console.norms.md), 142; [FieldView](../../../Platform/06-console/spec/06-console.api.openapi.yaml), 6849–6888; [console.js](../../../Source/w2cplatform/console.js), 1431–1440.

**Цитата нормы:** «hidden: true — the module does not display the field, the door writes and serves it like the others»; Н2 GET /manifest (строки 337–341) — «the other keys of the descriptor are as written».

У FieldView закрыты дополнительные свойства и нет `hidden`. По прозе остальные ключи должны передаваться как записаны; закрытая HTTP-схема этого не допускает. Если соблюсти FieldView, скрытое поле не отличить от обычного. Правило исключения скрытых полей из всего списка view тоже не задано. Если подать признак напрямую для проверки второго звена, `formCards` тоже его игнорирует и рисует input. В `display.form` такое поле можно указать явно, а при отсутствии form оно попадает во все поля автоматически. Это самостоятельный пропуск договора формы, не известный долг writes_via.

**Предложение:** определить полный путь признака: например, включить `hidden` в FieldView и его проекцию и исключить такие поля при построении формы, в том числе из явного `display.form`. Уточнить, не должны ли они вовсе исключаться из view вместо передачи флага; выбрать один способ в норме и OpenAPI. Проверить оба звена отдельно, не объявляя неподходящий к FieldView ответ допустимым.

## С7. Допустимое имя `__proto__` исчезает из каталога единиц

**Место:** P/07-01/P/07-02, Н1.4 `subsystems` и форма/дерево по манифесту; описание §10 «works on any manifest»; [console.js](../../../Source/w2cplatform/console.js), 2377–2382; [row-check](../../../Platform/common/contracts/row-check.md), 179–190.

**Цитата нормы:** «the value of a non-secret field of type string … MUST be non-empty»; закрытый список запрещённых значений/знаков именованного id не запрещает `__proto__`.

Загрузка объединяет configured и rows через `const by = {}; by[c.id] = …; Object.values(by)`. Присваивание id `__proto__` меняет прототип словаря вместо создания собственного элемента. Поэтому успешный ответ `/things` с такой живой единицей превращается в пустой список в модуле; обычный сосед виден. Поля и операции сервером не запрещены, а опубликованный общий модуль делает единицу невидимой для всех реализаций. Нынешние JS-фикстуры не покрывают специальные свойства JavaScript.

**Предложение:** словарь без прототипа или Map для внешних имён, с проверкой остальных подобных индексов; в критерии JS включить `__proto__`, `constructor`, `toString`. Алфавит допустимых id не сужать ради внутренней структуры JS.

## М2. Подпись платформенного события перекрывается чужим display

**Место:** P/07-02, Н1.5 `commands`/`words`; P/06.5 Н1.2 `kinds`; [console.js](../../../Source/w2cplatform/console.js), 486.
