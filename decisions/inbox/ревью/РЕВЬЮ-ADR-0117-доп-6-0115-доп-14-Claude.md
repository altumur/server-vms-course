# Ревью текста: ADR-0117 доп. (6) (Claude)

Доп. (6) на main 86d99efac. Сверено с P/04 (`unplaced`, `retire_when.delete_after`: строки таблицы с `about` не по id удаляются только с `made`, `04-controller.norms.md:155`), `worker.deletes` P/02.1 и моим отчётом к (5).

**Счёт: Б 0, С 0, М 1 — в нормы без дополнения.**

Чисто:
- П. 1 — уборку делает держатель через `worker.deletes: [parts]`, потому что у строки с `about` срок контроллера её не удалит. Пароль уходит вместе со строкой. Удаление заказа — просьбой. Строка части без держателя — предел.
- П. 3 закрывает С1 (5).
- П. 4 закрывает М1 (5).

**М1. Счёт `per_person`.** «Не меньше `EXPORT_CAMERAS_MAX` × `EXPORT_PERIODS_MAX` частей одного заказа»: часть — камера × запись, отрезки лежат списком в строке (доп. (4) п. 1). Значит, частей в заказе не больше `EXPORT_CAMERAS_MAX` (× записей камеры), а не 16 × 32 = 512. Предел нужен на все заказы человека разом: просьбы `cancel` и `delete` считаются вместе. Это `EXPORT_CAMERAS_MAX` × `EXPORT_ACTIVE_PER_USER` = 64 и больше, если у камеры несколько записей.
