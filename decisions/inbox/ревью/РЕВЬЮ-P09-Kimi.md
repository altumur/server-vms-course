## Findings

Одна причина — одна находка. Типы: contradiction / new meaning / missing normative input / proposal. Новых чисел нет везде.

**F1 (Б, contradiction).** Копия `stale` в контракте приёма противоречит владельцу текста. `Platform/common/contracts/accept.md` («The member's publication», повтор формы публикации P/09.1 N1.2 «without a change of behaviour»): «stale?: … heartbeats … that have not changed for longer than LOST_AFTER (45 s)». Владелец текста — `Platform/09-agent/spec/09.1-agent.norms.md` N1.2 `stale` (стр. 154–164): порог — `heartbeat.stale_after` манифеста (P/02.1, ≥30), `LOST_AFTER` 45 s только при отсутствии ключа, плюс book-stale расширение (слот с contribution без heartbeat); ту же семантику фиксирует ссылка P/08.1 N1.3. Контрпример: манифест с `heartbeat.stale_after = 120` — по норме владельца агент включает heartbeat в `stale` не раньше ~120 с, по копии контракта — через 45 с; на holder'е «accept» шаг 6 сравнивает списки `body.stale` и `mark.stale`, пороги сборщика (владелец P/09.1) и принимающей стороны, руководствующейся копией, расходятся ~75 с → ложная смена метки/поле и расхождение « freshness» у соседей. Предложение: в accept.md повторить «stale_after of the manifest, no key — LOST_AFTER» и book-stale правило, как у владельца.

**F2 (Б, missing normative input).** У агента как HTTPS-клиента нет публичного конечного бюджета установки соединения и чтения ответа к дверям holder/relay (пп. 1, 2, 12). В каноне есть: failover «connection refusal or 503 standby — next address» (09.2 N1.1), deadline 3 s только для follow `/api/held` (09.1 N3), потолок чтения ответа BATCH_LIMIT (accept.md), FORWARD_WAIT 5 s (forwarding.md, пересылка). Числа connect/read-фаз для `POST /api/member`, `GET /api/carry`, дверей relay нет ни в P/09, ни в peer.md, ни в lifecycle.md. Disposition по production-obligations.md: конечный бюджет объявляет реализация + проба среды; MissingBinding/NOTEXEC, не PASS; новых чисел не вводится.

**F3 (Б, missing normative input).** Нет публичных бюджетов остановки/отмены/завершения admitted work (п. 9): SIGTERM → сдать очередь → exit (09.1 N1.13), но дедлайн завершения, судьба in-flight публикации и предел ожидания admitted work не нормированы; `@stop agent` — «SIGTERM… wait for the exit» без числа. production-obligations.md требует конечные бюджеты «cancellation, shutdown and accepted-work completion» как required declarations. Disposition: объявляет реализация + проба среды (нативные cancellation/stop пробы из production-obligations «owner-native probe roster»).

**F4 (С, missing normative input).** Нет публичного предела ожидания ответа собственного хранилища внутри прохода агента (пп. 3, 12): turn.md «Races» прямо оговаривает «the answer term of an unavailable store is not bounded by this»; в P/09 есть исходы нечитаемых строк и «store did not answer → skip» (P1), но ни одна норма/seam не задаёт конечное ожидание сервиса store (только недоступность строк). Disposition: объявляет реализация + проба среды (dependency failure probe).
