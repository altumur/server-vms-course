## Существенные

**С-1. Бюджет прохода — «4 чтения», но чтение — кусок перечня, длина которого не ограничена**
- **Место.**
  - `06.2-detedge.norms.md:56-58`: «Байты — `GET <playback_url>?from=&to=` по куску перечня, порциями двери (`PLAYBACK_PIECE` ≤
    60 с, V/01.5 Н1.5); за проход — не больше `STRETCHES_PER_PASS` = 4 таких чтений на обход: при темпе устройства 0,5 окно
    в 600 с иначе держало бы проход до 20 минут без пульса».
  - Рубеж (`06.3:40`): «конец последнего **целиком** прочитанного куска».
- **Контрпример.** NVR перечисляет запись одним куском на час. Окно — 600 с, перечень даёт один кусок `[at, at+600)`.
  - «Чтение по куску перечня» — один `GET` на 600 с. Порции двери — внутри ответа (V/01.5 Н3: «сессия на кусок»).
  - При темпе устройства 0,5 этот `GET` идёт 20 минут — ровно то, чего бюджет обещал избежать.
  - Читать в проходе — проход без пульса, аренда истекает (`LEASE_TTL` 30 с).
  - Реализация B читает кусками ≤ 60 с — и рубеж «целого куска» у A и B разный.
- **Предложение:** «чтение» — `GET` не длиннее `PLAYBACK_PIECE` (60 с) медийного времени. Кусок перечня режется на такие
  чтения, рубеж — по концу последнего целого чтения. Либо чтение — вне потока прохода (как вызовы держателя, V/01.4
  Н1.3) со сроком.

**С-2. `pre`, `post`, `join` без границ**
- **Место:** манифест `detedge.subsystem.yaml:42-45`: `pre`, `post` — `{type: float, default: 5}`, `join` — `{type: float,
  default: 30}`, без `minimum`/`maximum`. Норма `06.1:44-45` и `06.4:29-31` их тоже не ограничивают.
- **Контрпример:**
  - `pre: -10, post: 5` — отрезок `[t + 10, t + 5)`, пустой и вывернутый: склейка и `∩` засчитанного не определены;
  - `join: -1` — склейка обратного порядка;
  - `pre: 86400` — каждая находка просит сутки (куски по суткам, `06.4:42`) — сохраняется весь архив вместо «нескольких
    процентов» (`06.4:7`, лекция);
  - дверь принимает всё.
- **Предложение:** `schema: {minimum: 0, maximum: …}` в каноне манифеста и строка Н4.

**С-3. `tick` обхода считает взгляды «в куске», а куски — свободная нарезка** (класс V/05 С-5, V/04 С-2)
- **Место:** `06.3-detedge.norms.md:56-57`: «событие на каждом третьем взгляде, поле `pass` — номер взгляда в куске (V/05.3
  Н1.3)».
- **Контрпример:** куски — перечень устройства, порции двери (С-1), прерванные проходы (рубеж по целому куску). Одно и
  то же окно архива даёт разные `t` событий `tick` у двух реализаций.
- **Предложение:** как V/05 С-5 — взгляды в моменты `t`, кратные `STEP`, событие по `⌊t⌋ mod 3`.

**С-4. На В7 не выражено: семей данных нет** (класс V/01 С-18)
- **Место:** `check_spec` — `family_schemas=0`.
- **Есть:** курсор — схема в манифесте (`:50-58`).

## Мелкие

- **М-1. README урока устарел.**
  - `:3` «Статус: **план перевода**» — урок переведён.
  - Пин `84958d6` во всех заголовках.
- **М-2.** Запас сессии (`06.2:52-53`): «`playbacks ≥ max_playbacks − 1` — не читать». У устройства с одной сессией
  (карта камеры — частый случай) `max_playbacks − 1 = 0`, и обход не читает никогда: вечное `waiting` «no spare
  session». Следствие правила верно, но не названо ни в норме, ни в лекции. Оператор узнает его по пульсу.
- **М-3.** Рубеж впереди архива: `at ≥ edge` — `caught_up` (`06.2:33`). Если у устройства сменилась карта или время
  ушло назад (`newest` < рубежа на часы), обход стоит в `caught_up`, пока архив не перерастёт прежний рубеж. Новые
  минуты не смотрятся, и молча. Нет правила «рубеж > `newest` + `SETTLE` — к `oldest` или `newest − SETTLE` со
  счётом».
- **М-4.** Приёмка 1 проверяет отказ перечня только для `start` (`scenarios.tsv:4`). Для `keep` (Н4 `06.1:92`) шага нет.
- **М-5.** `06.4-detedge.norms.md:44`: «Исход **задача** не ждёт» — в главе обхода; слово из V/05.
- **М-6.** Ряд `watches_running` — «читающие обходы» (`06.4:67`), он же `console.running`. В установившемся режиме
  обход почти всегда `caught_up`, и ряд показывает 0 у здорового кластера. Как его читает проверка здоровья консоли
  (P/06.5), не сказано.
- **М-7.** В инструкции нет разделов шаблона `instructions.md` (класс; вопрос 5 отчёта V/01).
