## Б

### Б-1. Продление `until` раз в час перезапускает запись каждой камеры

`VMS/01-cam/spec/01.6-cam.norms.md` Н1.7 «Продление»: «растёт только `until`». Но `Platform/03-worker/spec/03.6-worker.norms.md` шаг 4: «записать {…строка, …новые, revision + 1} … → extended». `Platform/03-worker/spec/03.3-worker.norms.md`: «revision вырос → … stop_unit … и start».

Ход. Сервер, 16 камер, у всех `cam-<cam>`. Раз в `EDGE_RENEW` каждая строка получает `revision + 1`, рантайм останавливает и запускает единицу: конвейер кончается, кольцо на удержании отбрасывается (`02.6` Н1.5), состояние `scan` не переживает новую `revision` (`02.8` Н1.5). Запись `always` у камеры-кластера получает разрыв каждый час. Основная упала в это окно — кольца 66 с нет, это то, ради чего заведена карта. У `auto` заказ живёт минуты, поэтому там это не было видно. У камеры-кластера нет другой записи.

Попутно: `version` камеры растёт раз в час (разбор это называет), `If-Match` формы и `expectedVersions` групповой операции ловят 412 без единой правки.

Правка: платформа: продление `ends` не даёт новой `revision` (норма P/03.6 Н1.6, договор проверки строки), или подсистема разбирает `restarting(id)` при неизменных полях и не трогает конвейер. Второй путь дешевле, но рантайм всё равно зовёт `stop_unit`, значит правка в P/03.3. `cam-<cam>` вынести из версии камеры (строка только для чтения).

## С

- **С-1. Потребитель: две нормы спорят.** `01.2:119`: «`when` не `offline`… резерв `when: offline` сам потребителем не бывает»; `01.2:124`: «Кольцо предзаписи — потребитель… в том числе `cam-<cam>`»; `02.6` Н1.4 «Основных нет, держатель потока в `idle` — тоже `standby`, кольца нет» и Н1.5 «на удержании поток открыт». Первая пришла закрытием ADR-0107, вторая — ADR-0108 п. 4. Камера без основной на карте `offline`: поток то открыт, то `idle`. Вдобавок `when` строки — копия, а слово тома меняется без неё: держатель читает строку. Правка: снять оговорку `:119`, судить `when` тома у `edge`, согласовать `02.6` Н1.4.
- **С-2. Одна строка на камеру: разрыв страховки при переезде и потерянный долг.** `01.6` Н1.7 «Строка с другим `home` — заказа нет, пока она не кончилась, не дольше `EDGE_UNTIL`». Сервер A умер, камера переехала на B: до 2 часов (сутки по ADR) у неё нет записи на карте B, ровно при сбое. Затем строка уходит на B, долг на карте A: «нет строки — нет копии», а новая строка уже с другим домом, копии с A не будет. ADR-0108 доп. (1) п. 4: «копия в основную идёт, пока они есть. Строка не снимается, пока долг есть»; разбор: «строка не держится долгом». Правка: ключ `{cam}-{home}`: поле в строке есть, разбор искал только `{cam}-{server}`; по строке на карту, каждая живёт своим сроком. Расхождение с ADR решить словом.
- **С-3. Толкатель без запасного пути.** `02.9:85`: толкатель — «регистратор карты, если у камеры есть запись на томе `edge` этого сервера, иначе первый по имени слота». Карта сломалась (`place_error refused`, `card.state: unavailable`), том никто не держит, держатель продлевает строку: толкателя нет, поток в кластер записи встал из-за карты, которая его только страхует. Правка: регистратор карты, держащий её и услышанный за `PEER_LOST_AFTER`, иначе первый по имени.
- **С-4. Порядок вытеснения внутри долга не задан.** `02.6` Н1.7: «старейшее из доставленного», «последним уходит то, чего у сервера нет», «сегменты записи без строки… вытесняются последними». Долг живой камеры и долг камеры без строки оба «последние». Камера снята оператором навсегда: её сегменты некому копировать (`нет строки — нет копии`), но они могут вытеснять свежий долг живых камер: общая карта, доли нет. И наоборот, одна камера с высоким битрейтом при обрыве съедает чужой долг. `evicted_owed` не называет камеру. Правка: внутри долга сначала записи без строки старше срока, потом старейшее по карте; счёт по записи.
