## Ответы на вопросы задания

1. **Совместимость.** Совместимо. Новая причина вписывается в общее правило refuse_start («all start refusals: code 2», N1.3 R006) и в `RestartPreventExitStatus=2`; отдельная строка каталога отказов (не `start_format`) корректна, т.к. `start_format` — иное предусловие (метка FORMAT), а сценарий 10 (чужой/немаркированный каталог без живого владельца) сохраняет свою ветку; отказ до записи FORMAT не конфликтует с `format` («empty → write FORMAT» условно намерением стартовать). Незавершённый импорт (C01-UNFINISHED-IMPORT-WRITERS-01) — ортогональная причина, обе код 2.
2. **Код 2 при перезапуске.** Безопасен. Штатно: прежний процесс освобождает владение при выходе → systemd стартует новый после `RestartSec=2` → владение свободно → старт проходит; пока старый жив, отказ второго — правильное поведение. Точная последовательность, если служба не поднялась: проверить, мёртв ли прежний процесс; если жив/завис — SIGTERM, по дедлайну менеджера SIGKILL (владение кончается с процессом, п. 4 + Цена) → `systemctl start`. Единственный риск — реализация, не снимающая владение смертью; она прямо запрещена Ценой («метка-файл без проверки живого владельца норме не удовлетворяет»).
3. **Два одновременных старта на пустом каталоге.** Исход определён в смысле: ровно один владелец, второй отказывает до готовности и до любой записи, включая FORMAT; победитель — кто атомарно захватил. Механизм свободен (п. 1 + «Implementation decides» п. 6 + Цена). Явное слово «атомарно/взаимное исключение захвата» в будущей норме усилит проверяемость — М1.
4. **Противоречие с import/restore в группе и R025.** Нет. `admin_ops` адресует import/restore в группе живому лидеру через его admin.sock — лидер и есть владелец своего `-dir`, операция легитимна; п. 3 запрещает локальные CLI import/restore/recover, нацеленные на чужой живой каталог. Для каталога без демона действуют прежние правила: одна попытка на установку, R025 (конкурентные recover/restore/import запрещены), взаимное исключение — «Implementation decides» п. 6, незавершённый импорт — refuse_start.
5. **SIGKILL и свобода реализации.** Требование сформулировано как свойство (блокировка, снимаемая смертью процесса), без мандата механизма: fcntl/flock/lockf-средства ОС гарантируют снятие ядром при SIGKILL. Свободу «Implementation decides» не сужает сильнее необходимого; метка-файл без проверки живого владельца обоснованно не принимается (иначе п. 4 не достижим).
6. **Достаточность для исполняемой пробы.** Достаточно на уровне решения: позитивные ветки (второй демон → код 2 с именем каталога и нетронутым каталогом; CLI import/restore/recover при живом владельце → отказ ≠ 0 без изменения данных; старт после SIGTERM/SIGKILL без ручной уборки) и отрицательные контроли (FORMAT не записан вторым; первый демон продолжает работать; владение не перехвачено) определены без догадок. Отсутствующий вход — сама публикация нормы и строки каталога (пишет spec103, вне предмета) и явный приоритет смежных отказов — М2.
7. **З-10.** Чисто: новая причина отказа, нет миграций, прежних идентификаторов и чтения старых состояний; «устаревшая отметка не блокирует» — отсутствие требования уборки, не поддержка старого формата; новых флагов/полей/чисел нет (п. 5).

## Находки

**М1 (мелкая, textprecision).** Место: `decisions/0130-боевая-пригодность-сгенерированного-кода.md` Addendum (2) п. 1–2 (строки 126–128 среза). Цитата: «Живой демон исключительно владеет своим каталогом данных… Отказ приходит до готовности и до любой записи в каталог, включая FORMAT». Контрпример-проба: два процесса, стартующие в один момент на пустом каталоге; без явного требования атомарности взаимного исключения при захвате формулировка опирается на «исключительно» + Цену. Источник: п. 1, п. 2, Цена решения. Последствие: слабая проверяемость пробы «два одновременных старта». Предложение: в норме spec103 потребовать явно «захват владения атомарен; ровно один процесс становится владельцем».

**М2 (мелкая).** Место: п. 2–3 против N1.3 `refuse_start`. Цитата: «Новая причина в перечне refuse_start… — all start refusals: code 2»; рядом действует «a directory with an unfinished import/restore attempt». Контрпример-проба: каталог живого демона с одновременно незавершённым импортом (краевой случай падения посреди импорта с мгновенным рестартом): обе причины дают код 2, каталог не меняется, поведение идентично — приоритет не наблюдаем. Источник: N1.3 R006. Последствие: неопределённость порядка диагностики, на наблюдаемое поведение не влияет. Предложение: не требовать приоритета либо назвать его в норме (оба исхода допустимы, журнал называет обе причины).
