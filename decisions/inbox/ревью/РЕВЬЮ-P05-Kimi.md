## Findings

Типы: contradiction / new meaning / missing normative input / proposal. Одна причина — одна находка. Severity: Б — отсутствующий нормативный вход на применимом пункте (закрывается нормой по disposition + пробой среды); С — существенный пробел пробы или неопределённая обязательная семантика; М — локальная неполнота пробы при действующей норме.

### Б1. missing normative input — штатная остановка ресурса: срок, отмена, судьба принятой работы, освобождение ресурсов (п. 9)

- Место: `Platform/05-resource/lifecycle.md:88-89` («**SIGTERM/SIGKILL** — the state is in the rows and files; after the server returns, the resource pulls its closed buckets…»); `Platform/05-resource/spec/05-resource.norms.md:368-371` (PULSE_LIMIT — «It is a diagnostic threshold, not a promise to stop a hung call or to wait for an answer»); `Platform/05-resource/spec/05-resource.norms.md:1080` («Implementation decides» п. 7 — только значение PULSE_LIMIT).
- Суть: ни в нормах, ни в формах, ни в lifecycle нет обязанности штатной остановки: дедлайн остановки, прекращение приёма новой работы, отмена/ограничение внешнего ввода-вывода, определённый исход принятой работы (in-flight запросы, открытые ожидания /events/wait, приём mirror-копии), освобождение соединений/дескрипторов/замков. Единственное приближение — отмена ожиданий (WAIT_DISCONNECT_WITHIN + s19) и срок приёма копии (408). Общий якорь требования бюджетов shutdown/cancellation/accepted-work completion есть (`Platform/common/contracts/production-obligations.md:9,11`, применим через P/05-R058, `norms.md:29`), но P/05-локальной нормы-носителя и пробы нет.
- Disposition (ADR-0130 доп. (5) п. 3): норма «конечный, объявленный реализацией бюджет остановки/отмены» + проба среды (входы от среды, новых чисел нет). Судьба принятой работы — через действующий словарь исходов урока (refusals.tsv), без новых слов.

### Б2. missing normative input — пределы файловых дескрипторов (п. 10)

- Место: перечень бюджетов урока — `runtime-constants.tsv` (14 скаляров: кеш, частоты, счётчики ожиданий/соединений, сроки проб/приёма; дескрипторов нет); `norms.md:1087-1089` (пределы соединений, не дескрипторов).
- Суть: для двери HTTP (соединения ≥ 64, на адрес ≥ 32), чтения бакетов/копий, ~lock-файлов, flock присутствия, restore/mirror-проходов нет нормы конечного бюджета дескрипторов и исхода при исчерпании. Память и диск нормированы (INDEX_CACHE_BYTES; usage/space/free_ask; 64 MiB), дескрипторы — нет.
- Disposition: конечный бюджет объявляет реализация + проба среды; новых чисел нет.

### Б3. missing normative input — стоимость записи и импорта, рост с объёмом (п. 6)

- Место: `norms.md:91-92` (temp+rename — устройство, не бюджет); `norms.md:323-326` (целая копия, без сборки); `norms.md:934` + `runtime-constants.tsv:16` (QUERY_NAMED_BUCKET_LIMIT — выбор кандидатов); пробы s64/s65.
- Суть: нет нормы стоимости записи объекта/копии/строки события и импорта (restore-проход, публикация копии) как функции от объёма хранилища и пакета: нормируемая стоимость, нагрузочные размеры, метод измерения, отделение стоимости входных байтов от числа уже сохранённых строк. D1 (ADR-0130 доп. (1)) — норма P/01; к P/05 не перенесена, и своей P/05-нормы нет. Растущие состояния и единицы объёма названы в матрице выше; бюджет роста индекса/очередей сверх констант не объявлен.
- Disposition: конечный бюджет объявляет реализация + проба среды (нагрузочный вход); новых чисел нет.

### Б4. missing normative input — бюджет ожидания замка записи объекта `<dir>/~lock` (п. 3)

- Место: `norms.md:91-92` («the write — temp + rename under the directory lock `<dir>/~lock`, flock(LOCK_EX)»); presence-flock ресурса non-blocking (`lifecycle.md:56-57`, `norms.md:340`).
- Суть: ожидание presence-флока исключено устройством (без ожидания), но блочирующий flock(LOCK_EX) каталожного замка при записи объекта/копии сериализует писателей семейства; срок ожидания этого замка, исход при превышении и отмена в P/05 не нормированы. Общий якорь «зависшая зависимость не держит общий замок сверх бюджета» (`production-obligations.md:11`) без P/05-носителя.
- Disposition: конечный бюджет объявляет реализация + проба среды (медленный писатель/получатель при записи).

### С5. new meaning / missing normative input — семантика обязательного счётчика `waits.held` не определена

- Место: `data/resource-heartbeat.schema.json:102,118` (`held` — required в `waits`); `norms.md:350` (инициализация `{waiting:0, held:0, full:0, replaced:0, max}`); `norms.md:515-517` (описание — «counters of the /events/wait waits», для held только границы целого); проба `seams.tsv:20` (s18: `held_waits:1` при `open_waits:1`); контекст «a held wait … does not take this lane» (`norms.md:942`).
- Суть: счётчик обязателен в каждом пульсе и наблюдается пробой, но норма не определяет, что именно он считает и чем `held` отличается от `waiting` (ожидание держит соединение до ответа — `norms.md:426-428`, т.е. при буквальном чтении held ≡ waiting; s18 их не различает). Реализации могут законно разойтись в наблюдаемом поле.
- Предложение (proposal-часть): определить `held` в N1.4/N1.6 (или снять поле в пользу одного счётчика) и зафиксировать в s18 наблюдение их расхождения.

### С6. норма есть — пробы нет: сбой барьера записи объекта (temp/rename/fsync) не пробуется (п. 4)

- Место: норма `norms.md:122`; пробы записи объекта — `seams.tsv:3-5` (s01–s03: равные часы, надгробие, нечитаемое надгробие); барьер строк событий — вне TSV (`acceptance/README.md:246`: «fsync is confirmed by a barrier»), контракт event-journal (общая единица).
- Суть: для объекта (и body-copy, и tombstone-перезапись) нет инъекции сбоя барьера/публикации: доказанный отказ до эффекта отделяется от неизвестной долговечности после rename (общий Q1/Q2 через R058), но P/05-проба отсутствует. Находка о пробе, не о неприменимости.

### С7. норма есть — пробы нет: отказ двери по пределу соединений (503 busy) не проверен прямой пробой (п. 1)

- Место: норма `norms.md:1087-1089` (сверх предела — 503 busy, Retry-After: 1); ближайшая проба `seams.tsv:20` (s18 — занятость вычислительной полосы /events, не предел соединений).
- Суть: s15/s46 проверяют полноту очереди ожиданий, s18 — полосу запросов; поведение «за пределом объявленной ёмкости соединений двери» (отказ нового соединения/запроса с Retry-After) прямой пробой не покрыто.

### М8. норма есть — пробы нет: 411 (blob PUT без Content-Length) (п. 7)

- Место: refusals.tsv row 10 (`blob_no_length`, 411); `api.openapi.yaml:256-261`; sc. 10 проверяет 400 без X-Written, 422, 405 — не 411.
- Суть: кадрирование пробуется обрывом тела (s10) и формой digest (s37), но отказ «нет длины» прямой посылкой без Content-Length не проверяется.
