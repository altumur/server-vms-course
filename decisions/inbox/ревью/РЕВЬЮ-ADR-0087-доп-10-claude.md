## П. 4 — сверка после перехода

### Б-1. Блокер. «Тот же провалившийся шаг с той же подробностью» не сравнивается
- **Место.** `0087…md:247-248` — «цель **сходится**, если её исход равен опорному; у красной *реализации* — тот же провалившийся шаг с той же подробностью».
- **Проба** — единственная красная цель опоры Go на 08:55, `out-2/acceptance/02/16/P-02.5-rights.txt`:
  ```
  variant v1-base          FAIL  0/43
      expect.tsv:0: variant: store did not open /var/folders/rj/0mbpl0_d5jg43d1vmv_83cx00000gn/T/m10v6-hl3psqzn/run/admin.sock
  ...
  scenarios 8/8, steps 67/67, variants 5/6 probes 50/93; run NOT green
  ```
- **Контрпример.** Подробность содержит каталог `mkdtemp` (`m10v6-hl3psqzn`). Повтор того же дефекта даст другой путь, и по букве п. 4 цель «не сходится». Пройдёт она по ветке «красный → красный на другом шаге» или вообще ни по какой — неясно.
- Провалился не шаг сценария (все 67/67 зелёные), а вариант `v1-base`, строка `expect.tsv:0`. «Шаг» п. 4 у раннера бывает тремя разными единицами: шаг сценария (`scenarios.tsv:N`), вариант (`expect.tsv:N`) и проба.
- **Нарушено.** Норма должна быть исполнимой (шкала «Блокер»). Две сессии, сверяющие по п. 4, на одном итоге разойдутся.
- **Предложение.**
  - Шаг — пара «источник:строка» из итога раннера (`scenarios.tsv:68`, `expect.tsv:0`, `verdicts.tsv:637`).
  - Подробность сравнивается после замены путей временных каталогов, PID, портов и времени на метки. Правило замены — в реестре, одно для опоры и повтора.

### Б-2. Блокер. «Те же пины смысла» для целей, чьи источники меняет переход, не наступают
- **Место.** `0087…md:247` — «повтор приёмки уроков 01–03 на тех же пинах смысла».
- **Расходится с доп. (7) правкой** `0087…md:191-192`: «раннер и сценарии приёмки P/02.1 переписываются по ответам 5–7 ADR-0092 … векторы `canonical`: имеющиеся байты не меняются, кроме строк 51, 53, 54 … набор пополняется (`c5_int_*`)».
- **Проба.** Сравнил `selected-plan.json` двух прогонов Go по `inputs[].sha256`: ночного `3963ef1` на `82283ce` и опоры `bf7a449` на `23d8e38`. Входы различаются ровно у четырёх целей: `P/02.1/load`, `P/02.1/inproc`, `P/02.1/put`, `P/02.2/vectors`. После перехода у этих же четырёх целей они изменятся снова — по доп. (7).
- **Контрпример.**
  - После перехода сценарии P/02.1 другие, поэтому «тот же шаг» не существует.
  - `P/02.2/vectors` с новыми строками 51, 53, 54 у верной реализации даст новый исход (набор Б). По п. 4 это расхождение с опорой.
- **Последствие.** Четыре цели, ровно там, где В7 действует, остаются без правила сверки.
- **Предложение.** Сверять по каждой цели механически по `inputs[].sha256` плана:
  - входы равны — п. 4;
  - входы различаются — по строкам: неизменённые строки сверяются с опорой, изменённые — с набором Б, новые остаются без опоры и проверяются только ожиданием.
- То же правило решает запасную опору Go `3963ef1` из правки п. 1. Её «пометка пина» по плану означает: опора для 57 целей из 61 и не опора для четырёх перечисленных.

### С-1. Существенная. Опора по первому провалившемуся шагу прячет непрогнанные шаги
- **Место.** `0087…md:240-241` — «у красной — первый провалившийся шаг, его подробность»; `:247-248` — «сходится … тот же провалившийся шаг».
- **Проба** (Б-1): `v1-base 0/43` — все 43 пробы варианта не исполнены («no store for the variant»). Это права контроллера P/02.5.
- **Нарушено.** Доп. (8) п. 1 `0087…md:201-202`: «урок 02 — с правами контроллера P/02.5 Н1.4». Ради этого условие (б) и вводилось.
- **Контрпример.** Перевод ломает проверку прав в пробе 20 из `v1-base`. После перехода `v1-base` по-прежнему падает на открытии хранилища. Тот же шаг и та же подробность — цель «сходится», а сломанная проба не видна ни в опоре, ни в повторе.
- Это маскировка чужой причиной: тот же класс, что 8 случаев п. 3 в наборе Б круга 1 (мой Б-1, `34c89231c`).
- **Предложение.**
  - Сверять вектор исходов по всем шагам, вариантам и пробам цели — раннер их даёт: `variants 5/6 probes 50/93`. Первый провал для этого не нужен.
  - Шаги, не исполненные в опоре, вносить в реестр «без опоры» с числом. У Go сейчас 43 пробы `v1-base`.
  - Для них опорой служит ночной `3963ef1`: там `P/02.5/rights` GREEN при равных входах (Б-2).

### С-3. Существенная. «Красный → GREEN без названной правки — как GREEN → красный» не даёт вердикта
- **Место.** `0087…md:250-252` — «иначе — как GREEN → красный: … это признак, что перевод изменил смысл».
- **Контрпример.** Опорная `P/02.5/rights` (С-2) после перехода зелёная, правки в реестре нет.
  - По п. 4 нужен дифференциальный повтор (доп. (9) п. 4). Но провалившегося шага в повторе нет; повторять можно только входы опорного шага — манифест `v1-base`.
  - Если эталон и библиотека совпадут (ожидаемо: отказ был «store did not open», это не чтение), по доп. (9) п. 4 итог — «дефект урока». Так дефектом урока объявлена цель, которая зелёная.
- **Последствие.** Ветка не различает три причины: «перевод ослабил проверку», «опорный провал был окружением» и «правка, не внесённая в реестр».
- **Предложение.** Для «красный → GREEN без правки» первым делом проверять, исполнялись ли теперь шаги, которые в опоре не исполнялись. Опорный провал не из чтения семей или манифеста (по месту шага) — это кандидат в «неустойчива» (С-2), а не дефект урока. Дифференциальный повтор — только для шагов чтения.

## П. 5 — неустойчивые цели

### С-2. Существенная. «Неустойчива» определено через повтор без изменений, которого нет
- **Место.** `0087…md:254-256` — «Цель, чей исход в опоре и в повторе без изменений расходится (гонка, время — класс load/time раннера), помечается в реестре «неустойчива»».
- **Проба 1. Класса load/time у раннера нет.**
  - В копии раннера `08dbd76` поле `classification` принимает только `implementation`, `runner`, `data`, `stand` — поиск по `runner/**/*.py` и `portable/*.py`.
  - `load_time` есть только как поле разбора в `SUMMARY.json` ночного прогона, его пишет сессия приёмки: «no failure of class load/time: both failures are implementation…».
- **Проба 2. Повтора без изменений правка п. 1 не допускает** («без доп. прогонов», `:262-263`). Повтор после перехода — с изменениями (В7), поэтому расхождение в нём по определению не «без изменений».
- **Живой пример.** `P/02.5/rights`:
  - ночью `3963ef1` — GREEN;
  - в опоре `bf7a449` — красная `implementation` («store did not open … admin.sock», 6 с, load1 после цели 17,3);
  - входы в планах равны.
- По двум наблюдениям не различить, что это: смена кандидата (`3963ef1` → `bf7a449`), смена раннера (`37200fb` → `08dbd76`) или окружение. П. 5 применить нельзя: опорного повтора нет. После перехода тоже нельзя: там всё «с изменениями».
- **Последствие.** Пометку «неустойчива» можно поставить только задним числом, по расхождению после перехода. Тогда она снимает равенство п. 4 с любой неудобной цели.
- **Предложение.**
  - Неустойчивость устанавливается только до перехода и только наблюдением на диалекте. Есть два источника.
    - (а) Два прогона на равных входах (`inputs[].sha256`) с разными исходами. Ночной `3963ef1` и опора `bf7a449` дают это без нового прогона для 57 целей. Сейчас под это подходят `P/02.5/rights` (GREEN → красный) и `P/01.3/daemon` (красный → GREEN); у второй — смена кандидата, её назовёт строка реестра.
    - (б) Повтор одной цели на кандидате опоры. Это не «прогон ради опоры», а разбор одной строки реестра — вопрос «Архитектору».
  - «Класс load/time раннера» заменить ссылкой на разбор окна (поле `load_time` итога) или на (а) и (б).

## Пп. 2–3 — реестр и правки до перевода

### С-4. Существенная. Правка п. 3 даёт предсказанный исход, а не наблюдённый
- **Место.** `0087…md:244-246` — «в реестре у такой строки — коммит правки и ожидаемый исход после неё»; правка п. 1 `:262-263` — «новых прогонов ради опоры не назначается».
- **Контрпример.**
  - Строка класса *корпус* исправлена коммитом X, ожидаемый исход — GREEN. Опора этот исход не наблюдала.
  - После перехода цель красная на другом шаге. Причин три: правка X неполна, правка X внесла дефект или перевод. П. 4 сравнивает с «ожидаемым исходом» как с опорным и отнесёт всё к переводу.
  - Кроме того, правка X сдвигает пин диалекта для этой цели, а это противоречит «тем же пинам смысла» (Б-2).
- **Предложение.**
  - У строк п. 3 опора — «предсказана, не наблюдена»: расхождение с ней разбирается дифференциальным повтором и не считается признаком перевода.
  - Либо после правки корпуса — одна цель на кандидате опоры и диалекте с правкой; это разбор строки, не прогон опоры.

### С-5. Существенная. Классов в реестре меньше, чем у раннера
- **Место.** `0087…md:241-242` — класс «*реализация*, *корпус* (тест, фикстура, вектор), *норма* (пробел или противоречие). Классы назначает «Архитектор» по итогу раннера (класс раннера — предложение)».
- **Проба.** Раннер даёт `implementation`, `runner`, `data`, `stand` (С-2).
  - `data` ложится на *корпус*.
  - `runner` и `stand` — дефект раннера или окружение — некуда.
  - Пример есть в самой опоре Go: попытка 1 `bf7a449` закончилась «launcher-failed … runner defect, not the candidate» (`laptop/ATTEMPTS.json`).
- **Последствие.** Красная цель класса «окружение» по п. 3 не исправляется (это не корпус и не норма). По п. 4 она должна сойтись «тем же шагом», хотя окружение не повторяется.
- **Предложение.** Четвёртый класс «*окружение / раннер*»: опорой не служит, сверяется по С-2 (а) или (б).

### С-6. Существенная. Пин раннера в «пинах смысла» не назван
- **Место.** `0087…md:247` — «на тех же пинах смысла»; правка п. 1 `:264` — «переносимый раннер `08dbd76`».
- **Проба** (`laptop/ATTEMPTS.json`): опора — попытка 2 (`out-2`) с операционной мерой «runner directories outside .git made read-only (chmod a-w) … driver fix to follow as a reviewed series». Повтор после перехода пойдёт:
  - на раннере с исправленным драйвером;
  - с переписанным P/02.1 (Б-2);
  - у Python — на раннере с привязкой коммитом `8f12bd4` (правка п. 1 `:267`).
- **Последствие.** Расхождение после перехода может быть следствием смены раннера. По п. 4 его отнесут к переводу или к уроку.
- **Предложение.**
  - В «пины смысла» входят спецификация, кандидат и раннер, опора — с номером попытки и каталогом (`out-2`).
  - Смена раннера между опорой и повтором допускается, если его фикстуры показали, что остальные цели не меняются, а для P/02.1 — по Б-2.

### С-7. Существенная. «Цели вне реестра — GREEN» при отсутствии прогона Python
- **Место.** `0087…md:243` — «строка на цель с исходом не GREEN; цели вне реестра — GREEN»; правка п. 1 `:267` — «Python — прогона раннером нет».
- **Контрпример.** У Python нет ни одного исхода цели, поэтому строк Python в реестре нет. По букве `:243` все 62 цели Python опоры — GREEN, включая `P/02.5/rights`.
- **Предложение.** Реестр — по реализациям. Для Python: «цели раннера — без опоры». Опора — строки векторов названных пакетов (С-8) с пином паспорта.
