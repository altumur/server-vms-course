## С3. После установки не поднимается контроллер подсистемы psim, необходимый автоматическому `/where`

**Место:** `runner/vms_targets.py:30` задаёт единственный контроллер `backend`; `runner/vms_stand.py:85`–90 запускает только этот список. `psim_step` (`:198`–229) копирует пакет и вызывает команду установки, но не запускает контроллер новой `psim-*`. В сценариях после установки нет такого старта.

**Норма:** V/12.1 Н1.1: «Размещение — одна единица, один процесс адаптера на плагин»; общий порядок P/04/P/05 требует назначений контроллера подсистемы для подъёма держателя ресурсом. V/12.4 Н1.2–Н1.3 описывает у команды установки генерацию, manifest put, запись plugin и сборку backend, но не обязанность команды запускать контроллеры стенда. Автоматический шаг **04-page/2** требует `GET /psim-security_controller/where/plugin → 200 {url, token}`.

**Проблема:** даже после исправления запуска backend из С2 у psim-плагина нет собственного контроллера/назначения держателя. Контроллер backend не заменяет контроллер psim-security_controller. Правильный ресурс сам не создаёт такое назначение; поэтому у `/where/plugin` нет живой двери адаптера и автоматический 200 не гарантирован. То, что проверка страницы/плагина дальше `@manual`, не делает ручным шаг `/where`. Фикстура, возвращающая подходящий URL без реального размещения, этого пробела не обнаруживает.

**Предложение:** добавить в подготовку/обработку успешной установки явный запуск контроллера установленной динамической подсистемы по общей команде владельца P/04 и согласованное обеспечение адаптера V/12; ожидать живость по нормативному признаку перед автоматическим `/where`. Либо согласованно изменить состав автоматических шагов с владельцем VMS. Не возлагать запуск неописанных процессов стенда на реализацию CLI `psim` молча.

## Что прошло чтение без новых замечаний

Подстановки `$имя` ограничены строками ожидания, не вводят связывание внутри строки и сохраняют формы `@…`; новые тесты проверяют неверный ответ, а не только успешный путь. Профиль команды `psim` принадлежит V12-psim, owner_command сохраняет его рабочий каталог. Значения `--secret` регистрируются до запуска и передаются stdin. Изменения прочих тестов в основном следуют перепину и составу целей; они не являются свидетельством прогона реализации. Смена бакета события по `t` проверена чтением с учётом оставшегося М3 Claude.
