# Разбор ADR-0110: цена вариантов А и Б (Claude)

ADR `265f13fec`, записка `cammeta-console` `9045412`. Платформа и VMS — `origin/main`, контракт — снимок consolem. Это цена, не вердикт. Всё чтением, числа объёма — оценка по размерам глав, а не счёт.

## Коротко

| Что считаем | А: домен consolem = домен P/08, `backend` на домене | Б: кластер записи + приписанные камеры-кластеры |
|---|---|---|
| Где `backend` | воркер на домене, роль `backenddomain`, один на домен | на кластере, как сейчас |
| `door.pass`, билет | передача есть, **обратного вызова на домене нет** (`P/10:290`, `gate-and-pass.md:17`) | работают; добавить записи `calls` к `/domain/*` |
| Сторожевая | только `domain/grants/domain`, гранты кластеров не судятся | как сейчас, для своего; приписанное судит процесс `domain` |
| Опора `backend` | пакет, операции, лента, папки, серверы, журнал — двери консоли кластера, на домене их нет | всё на месте |
| Смена держателя | всё в `state` резервной копии, билеты и ведущий теряются, новый адрес | своё не задето, стоит только приписанное |
| Держателя нет | consolem стоит для **всех** кластеров, вернуть может только `w2cctl domain move` | свои устройства работают, приписанные нет |
| Чтение члена | снимок для всего, что видит consolem | снимок только для камеры-кластера |
| Запись на молчащую коробку | хранимая правка, контракту нечем ответить | то же |
| Секрет | новый путь | тот же новый путь |
| `Device.id`, версии | все пересчитать: id кластера повторяются | только у приписанных |
| V/11 | почти целиком заново | добавка |
| Объём норм | ≈ 3000–4500 строк, уроки P/06, P/08, P/09, P/10, V/11 | ≈ 600–1000 строк, P/06.3, P/08.1, P/08.6, P/09, V/11 |

**Общий предел обоих:** `MEMBERS_MAX` = 500 (`08.10:54`), счёт строки `domain/members` под потолком 524288 байт. «Тысячи камер» в домен не входят ни при А, ни при Б. Снять — новая раскладка `domain/members`, `domain/member-list` и нагрузка держателя: 5000 членов с `REPORT_EVERY` 5 с — 1000 отчётов в секунду. Эта цена в таблице не сидит, она сверху и одна на оба варианта.

**Третья строка цены.** Держатель не обязан быть домом `backend`: пересылка 1–2–3 ведёт с любого кластера. Механизм Б с «приписаны все члены» даёт контракту один домен без работ по P/10 и P/08.8: `backend` на одном названном кластере. Ниже — А′, ≈ 900–1400 строк. Владелец его не рассматривал, поэтому только называю.

## 1. `backend` на консоли домена

**Что уже есть.** `door.pass` на домене: консоль домена передаёт воркеру на домене (`P/10` Н1.6), второй вид с билетом тоже: «билет вместо `Authorization`, заголовки, типы ответа, `refusals`, поток». Юнит `<dep>-<sub>domain.service` на каждом сервере с `w2c-domain`, активен один по слоту `domain/<sub>/worker`, пульс `domain/<sub>/heartbeat`, запасной берёт слот через 50 с (`P/03.7` Н1.6).

**Чего нет.**

- **Обратный вызов.** `P/10:290`: «Обратного вызова на домене пока нет… заголовок `X-W2C-Pass-Ticket` консоль домена принимает только для отказа, 401». А `backend` без него ничего не умеет: своих прав и состояния у него нет (`V/11.1` Н1.3).
- **Двери, которые он зовёт.** `calls` манифеста: `cam/cameras`, `cam/devices`, `cam/children`, `cam/device_units`, `rec/volumes`, `det/units`, `console/batch`, `changes`, `folders`, `backend/operations`, `GET manifest`, `GET servers`, `GET events`, `GET session`. На консоли домена из этого есть только чтение вида. `console/batch` — пакет одного хранилища, `/domain/batch` несёт только людей, группы, роли, гранты. Операции — 575 строк `P/06.9`, очередь и ведущий внутри кластера. Папки — 479 строк `P/06.8`, строки кластера.
- **Сторожевая.** На консоли домена гранты — только `domain/grants/domain` (`P/10:290`, Н1.5). Оператор с `view` на кластер там никто: `need` передачи — «любой грант», его нет, 403. Либо сторожевая домена учится грантам всех кластеров, либо всем людям заводятся строки домена, а они «прав в кластерах не дают» (`P/08.4` Н1.3в).
- **Свои таблицы.** `repeats`, `people`, `history`, `undo` живут в хранилище кластера. На домене это `domain.kept` + `domain.tables`, `service: true` на домене не описан, жнец `delete_after` — у консоли кластера.

**Смена держателя (`P/08.8`).**

- Резервная копия несёт `state`, в том числе «строки kept» (`08.8:120-129`). Значит `undo` и `repeats` войдут в копию и в каждую передачу. `opsteps` — строки консоли кластера, они туда не входят: новый механизм или потеря идущих операций.
- Билет — запись в памяти экземпляра консоли домена: передача и перенос рвут все запросы и потоки.
- Память повторов не успела в копию: повтор группового ключа после переноса исполняется второй раз. Сегодня она в хранилище кластера и этой гонки нет.
- Вход: члены пересылают `/domain/<sub>/…` держателю, поэтому адрес consolem может остаться на консоли кластера.
- Держателя нет: аварийный перенос — `POST /domain/move` или `w2cctl domain move` с файлом восстановления (`08.8` Н1.8). До него consolem не работает для всех кластеров домена. Сегодня авария домена настройку кластера не трогает.

**Режим без домена.** Сегодня `backend` живёт и на одиночном кластере. При А нужен домен всегда либо две ветки перевода. Приёмка стоит на `@domain m1`, но «домен из одного» придётся нормировать.

**Цена:** `P/10` Н1.5, Н1.6 + `P/06.3` Н1.9 + договор сторожевой — 150–250 строк; перенос пакета, операций, ленты, папок, серверов на домен — 800–1200 строк или отказ от них; `P/08.8`, `P/03.7` — 60–100 строк.

**При Б:** ничего из этого. Нужны записи `calls`: `GET domain/<s>/<rows>`, правка единиц; двери домена уже идут пересылкой с токеном человека (`P/06.3:104`, `P/10:201`). Правило `P/10:202` «записи по одной из `backend` не идут» надо смягчить. 20–40 строк.

## 2. Что `backend` читает с члена

**Прямого пути нет.** Переходы 1–3 ведут от члена к держателю, не обратно. Домен «в члены не пишет» (`08.6`). Агент сам ходит к держателю: `POST /api/member`, `GET /api/carry`. За NAT это единственная дорога, и нормы другой не знают. `url` члена есть только для членов с открытой дверью, у камеры-кластера её нет; `star` прямо говорит «до них не дотянется никто» (`08.3:103`).

**Значит только снимок и вид** (`P/08.1` Н1.4, `P/04` Н1.3а): отчёт агента раз в `REPORT_EVERY` 5 с, вид раз в 3 с. Задержка чтения 5–8 с. `every` держатель может опустить до 1 с (`accept.md:165`), это готовая ручка для интерактива.

Что надо вынести в снимок, сверх записки:

| Источник `mapping.tsv` | Строк | Сейчас в снимке |
|---|---|---|
| `cam/cameras` | 37 | 9 полей |
| `rec/volumes` | 30 | **нет: это таблица, не единица** |
| `cam/heartbeats`, `det/heartbeats`, `rec/heartbeats` | 16 | нет: `online`, `fault`, `serverId`, `units_down` |
| `cam/devices`, `cam/children`, `cam/child_settings` | 21 | нет |
| `cam/device_units` | 10 | нет |
| `det/units` | 9 | 5 полей |
| `rec/recordings` | 5 | 9 полей |

Снимок сегодня — про единицы. Таблицы и пульсы туда не входят, нужен новый вид строки отчёта. Ещё нужна маска секретов на стороне члена: снимок уходит из кластера.

**Камера за NAT.** Чтение работает, с задержкой и только по отчёту. Живых вопросов нет: `/devices/{id}/snapshot`, проверка связи, `probe` — только просьбой через `carry` и ответом следующим отчётом.

**Согласованность.** Ответ `GET` после своей правки старый, пока не пройдёт отчёт: контракт ждёт новую `version` сразу.

**Цена:** А — весь снимок, 150–250 строк `P/08.1`, `P/09`, манифесты, форма `view`. Б — тот же механизм, но для узкой формы камеры-кластера (поле `profile` уже в снимке `cam`): 60–120 строк.

## 3. Правка и секрет на молчащую коробку

**Путь есть:** `PUT /domain/<sub>/<rows>/<ref>` → `202 {kept, cluster, what, note}` → `domain/pending/<член>` → `carry` → агент зовёт дверь своей консоли с `If-Match` → `performed | conflict | refused` в `domain/outcomes`. Это верно для NAT.

**Что не сходится:**

| Место | Дыра |
|---|---|
| Только единицы | `<rows>` не `unit.rows` — 404 (`08.6` Н1.3). `rec/volumes`, `child_settings`, `device_units`, `policy` хранимой правкой не пишутся |
| Только `domain.edit` | `cam` — `enabled`, `rec` — `enabled`, `retention_days`. Расширение — по полю |
| Нет пакета | В `V/11.4` устройство — один пакет B9. Правка — одна строка на один `path`, связности `cam` + `rec` + `det` нет; `conflict` роняет следующие того же `path` (`08.6:173`) |
| Создание | Номер ставит член, в ответе `POST /devices` нужен `Device.id`. 202 id не несёт. `cam/next_id` с домена не прочитать |
| `KEPT_LIMIT` 50 | 51-я — 409 `kept_full` (`08.6:177`) |
| Отмены нет | Двери снятия ждущей правки нет. Сказали клиенту «не вышло», а коробка вернулась через неделю и применила |
| `base` | `revision` из копии: при старой копии `conflict`, и оператор решает заново |

**Ответ контракта.** `PATCH` ждёт 200 с записью и версией, 202 в контракте у него нет. В consolem слово есть только у шага операции: `fail SERVER_OFFLINE` (`api/server.js:741`); четыре теста в `profile-tests.tsv:35,37,50,63` сейчас вне профиля. Записка называет 409 на `PATCH`: в снимке consolem этого я не видел, значит вопрос к ним обязателен. Варианты с ценой:

- **Ждать.** Член `ok`, `every` 1 с, держим запрос до исхода, `wait` двери. 2–10 с, потолок ~30 с. Молчащий — отказ до приёма правки, по статусу вида. Гонка: член замолчал после приёма, ответа нет, правка стоит: нужна дверь отмены.
- **Только операции.** `POST /operations`, шаг ждёт исход, срок шага `OPS_STEP_WAIT` 30 с, `SERVER_OFFLINE` сразу. Честнее, но WebUI шлёт `PATCH` из карточки, и `undo` ADR-0106 надо провести через тот же путь.

**Секрет.** `08.6` Н1.3 `secrets`: 400 «a secret is set in the member's own cluster». Запрет двухслойный: `P/02.1` Н4 отвергает манифест.

Опора есть: конверт `m1` до агента и профиль `at_rest` (`domain-envelopes`, `password_secret` V/03.6). Новое: `backend` ключей не держит, а строка `domain/pending` лежит у держателя и уходит в резервную копию, поэтому запечатать надо **до** держателя, под ключ члена. Агент открывает и подаёт своей консоли, та запечатывает `cred_secret` по `P/06.2`. Плюс `bound_to`: смена адреса и пароля одной правкой; пароль стоит в очереди, пока коробка молчит; смена ключа члена, пока правка ждёт (`revoked_keys`); ADR-0106 шаг с секретом не откатывает.

**Цена:** правка 120–200 строк `P/08.6`, `P/09.1` у А, 80–150 у Б; секрет 80–120 строк и векторы у обоих; вопрос consolem один на обоих.

## 4. Что ломается при переходе

| Раздел | А | Б |
|---|---|---|
| **Id** | `device:cam/cameras/<id>`, `folder:platform/folders/<id>` повторяются между кластерами: UUID всех записей заново, с именем кластера; 559 строк приёмки V/11 с зашитыми UUID пересчитать | своё цело, приписанные получают свой префикс |
| **Версии** | Индекс — у хранилища, между кластерами не сравним, снимок несёт `revision`. Сборная версия `c17.r21-30.d44.h9.i` (`11.3`) меняется, `If-Match` становится `base` | только приписанные |
| **Поиск** | `cam/searches/<CLUSTER>` и `/domains/{id}/discovery` без сервера. Веер на всех членов через `carry`, находки назад через отчёт, новая книга; один поиск на домен шире. Для NAT-коробки смысла мало | не меняется |
| **Лицензии** | **Проще:** V/01.7 уже доменная, `GET /licenses` читает её прямо | как сейчас |
| **Права** | V/11.8 (325 строк): `GET /access`, `apply`. Право контракта — на домен, у нас `domain/grants/<кластер>`: веер на N строк, `folder:` локален. Фильтр перечня судила консоль, теперь судить некому: `backend` «прав не судит» | своё то же. Приписанная: дверь `/domain/*` требует `admin` по `domain/grants/domain`, оператору кластера этого не дано. Нужно правило на обоих вариантах |
| **Правила** | `/rules` сегодня `out` (`profile.tsv:55-63`, ADR-0094 доп. (7)): ломаться нечему. Если объявят — `auto` кластерный, V/07.5 только `preset`, реле | то же; «два слоя правил» из записки сегодня нулевая цена |
| **`Server`** | `/servers` — `P/06.6` одного кластера. Строится из `view.members`, `ip`, `role`, `online` заново | приписанные добавляются строками `Server` |
| **Лента, журнал** | `/changes` (V/11.5, 177 строк) и `/events` — кластерные. Сквозного курсора нет, `Last-Event-ID` меняется. У NAT-коробки события только по отчёту | своё то же; приписанные — смены вида без ленты |
| **Папки** | Общие на домен: нового вида | свои |
| **Откат ADR-0106** | Значения `after` из снимка, задержка, цепочка | только приписанные: откат через хранимую правку, новый случай |
| **Заменяемые решения** | ADR-0094 A6, ADR-0103 п. 5, доп. (1) п. 6, ADR-0109 доп. (1) п. 2; вопрос 21 сверки | добавка, A6 уточняется |

## 5. Что у Б проще

1. Вся V/11 для своих устройств не меняется: 41 операция, 559 строк приёмки, тесты consolem.
2. Ни одной работы по `P/10`, `P/06.8`, `P/06.9`, `P/08.8`.
3. Авария держателя не трогает настройку своих устройств.
4. Что приписано, уже почти записано: `domain/placement/rec/<ref>` с `cluster` = свой и `origin` = камера-кластер. Для камеры без записи на центре нужна ещё строка, например таблица `backend/attached`.
5. Снимок и правка узкие: форма камеры-кластера известна.

Что у Б хуже: второй вход на каждый кластер записи, в consolem камера-кластер видна только своему центру, общего дерева нет. Два центра — два домена consolem. Настройка приписанной всё равно зависит от держателя.

## Оценка объёма норм

Оценка, ± треть. База: V/11 — 2143 строки норм, 559 строк приёмки, `mapping.tsv` ~270 строк, из них ~130 с источником-таблицей.

| Работа | А | А′ | Б |
|---|---|---|---|
| `P/10`, сторожевая, `P/06.3` | 150–250 | 20–40 | 20–40 |
| Пакет, операции, лента, папки, серверы на домене | 800–1200 | 0 | 0 |
| `P/08.8`, `P/03.7` | 60–100 | 0 | 0 |
| Снимок, вид, `P/09` | 150–250 | 150–250 | 60–120 |
| `P/08.6`: таблицы, пакет, создание, отмена | 120–200 | 120–200 | 80–150 |
| Секрет | 80–120 | 80–120 | 80–120 |
| V/11 нормы и `mapping` | 1300–1800 | 300–450 | 200–300 |
| Приёмка V/11 | ~500 строк заново | 100–150 | 60–100 |
| Манифесты и V/01, V/02, V/04 | ~100 | ~50 | ~30 |
| Итого | **3000–4500** | **900–1400** | **600–1000** |

Сверху для всех: `MEMBERS_MAX`, если число камер-кластеров превысит 500; прогоны c-python, c-go по изменённым урокам платформы: при А это P/06, P/08, P/09, P/10, при Б — их узкие части.

## Что не читал и не считал

Нагрузку держателя и размер вида при широком снимке не мерил. Пределы размера отчёта агента не нашёл в нормах, что само требует решения. `P/08.7`, `P/06.6`, `P/06.8` читал по заголовкам и ссылкам. Отдельной цены интерфейса consolem нет.
