## RВ7-01 — существенная: разрешённые `\d`/`\w` исполняются Python шире стандарта

**Места:** `skills/lesson-spec/scripts/v7/regex.py:95–109`, `v7/stack.py:32–34`, `v7/spec.py:307–318` (все пути `v7/` здесь и ниже — относительно `skills/lesson-spec/scripts/`).

Цитата `regex.py:95`: «Подмножество — то, что ECMA-262 в режиме `u` и RE2 читают одинаково»; строка 108 разрешает `e in "dDwW"`. При исполнении `stack._pattern` вызывает `re.search(regex.python_full(patrn), instance)` без изменения семантики классов Python. Замена конечного `$` решает только полный матч.

**Контрпример:** две самодостаточные схемы `{"type":"string","pattern":"^(?:\\d)$"}` и `{"type":"string","pattern":"^(?:\\w)$"}`. У первой значение `١` (U+0661), у второй `я`. В обоих случаях:

- `regex.check(pattern)` → `None`, `spec.unportable(schema)` → `[]`;
- валидатор В7 Python → `True`;
- `new RegExp(pattern, "u").test(value)` в Node → `false`.

Иными словами, «проверка переносимости прошла» здесь не означает одинаковый язык значений. Это не только ранее замеченная недостающая компиляция: обе формы корректно компилируются, но Python исполняет `\d`, `\w` и их дополнения как Unicode-классы. Проба не доказывает, что нынешние сгенерированные схемы уже содержат эти сокращения; она доказывает ошибку обещанной проверки и исполнителя на **разрешённом самим проверяющим** pattern.

**Основание:** ADR-0092, Decision Outcome п. 14 — «`pattern` в схемах — ECMA-262 **в режиме `u`** … в пересечении с RE2»; слой 5 должен сохранять этот смысл, а не только положение `$`. План п. 1.3 требует проверять переносимость.

**Последствие:** при правке стандартной схемы разрешённым сокращением Python может построить неверные вердикты/ожидания семей, а реализация на стандартной семантике — получить отказ приёмки.

**Рекомендация:** согласовать исполнение этих четырёх классов с ASCII-смыслом ECMA/RE2 (включая классы внутри `[...]`), либо явно запретить их в подмножестве и писать диапазоны. Добавить отрицательные Unicode-контроли, отдельно для дополнений. Одна компиляция в двух движках эту причину не исправляет.

**Проба:** `probes.py`; точные команда и результат — `49-probes.{json,stdout,stderr}` в каталоге логов ниже.

## RВ7-02 — существенная: файл связей потерял проверку пути строки и класса

Проба без проверки текста также сохранена отдельно; основной контрпример — **64-rel-with-prose**, где текст действительно передан проверке. Неверный класс — дополнительное проявление той же отсутствующей проверки формата связей, не четвёртая находка.

**Основание:** план п. 1, строка 27: «Навык должен уметь всё, что `check_spec` делает сейчас из диалекта, — из стандартных файлов»; ADR-0087 доп. Отмена нормативности диагностических путей отказа загрузчика — другое решение: она не превращает несуществующий путь строки источника в допустимый.

**Последствие:** по сравнению с диалектом проверка принимает испорченный источник и строит ложную строку нормы. Зелёное покрытие CEL не доказывает согласованность адреса/класса/описания строки с её исполняемой частью.
