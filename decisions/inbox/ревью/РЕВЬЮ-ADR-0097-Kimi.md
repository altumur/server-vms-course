- Метод: `skills/platform-review/SKILL.md`; форма — `skills/lesson-spec/references/review-checklist.md`; правила `.cursor/rules/service-boundaries.mdc`, `data-consistency.mdc` (нарушений по ним нет — решение не делит компоненты и не вводит согласованности между сервисами)

## Вывод

Модель `sub` (третья ось строки, отсутствие `sub` = все подсистемы, совместимость со старыми строками) в базе верна и аккуратно сохраняет смысл выданных грантов; область `folder:<id>` с объединением членства единицы и about, неповторимым id и «не покрывает, не 503» согласована с ADR-0096 и с правилом `scope` договора сторожевой. Но решение в нынешнем виде нельзя писать в нормы: правило «все проверки одного запроса — с одним `sub`» невыполнимо на пакетной двери B9 (блокер), а ещё пять мест либо не определены (покрытие `folder:` записей папок, `sub` у `/marks`, путь записи грантов из `backend`), либо дают эскалацию (`sub = null` снимает фильтр подсистемы; `edit` на единицу + `admin` на папку = косвенная выдача прав). Находок: 1 блокер, 5 существенных, 4 мелких.

## Находки

### [Блокер] Б1 — Пакетная запись B9 несёт строки нескольких подсистем, а §2 требует один `sub` на запрос

Место: `decisions/0097-…:86` (§2 «Все проверки одного запроса — с одним `sub` действия») и таблица §2 (`:80`), где пакетной двери нет.

Цитата: «Все проверки одного запроса — с одним `sub` действия: и единица из пути, и единицы `rights.unit_of`, `reach`, `names`, `body_unit`.»

Контрпример: ADR-0094 доп. (9) п. 3 (`decisions/0094-…:353`–`356`): «запись устройства — один пакет: записываемые части с `cas` из снимка» — пакет `PATCH /devices` пишет строки `cam/cameras/7` (need: `admin` на единицу) и `rec/keeps/…` (`unit_of` → `cam/7`, `edit`) одним запросом. При любом выборе `sub` для этой двери:
- `sub = cam` (по корневой единице): строки `rec` проверяются как `edit`, `sub: cam`, на `cam/7` → человек с `admin sub: cam unit:cam/7` правит настройки архива **без всякого гранта `sub: rec`** — прямой обход заявленной цели ADR («разделить "архив — да, настройка камеры — нет"», `:21`–`22`); та же правка напрямую через дверь `rec/keeps` (`sub: rec`) ему отказана — две двери судят одну строку по-разному;
- `sub = rec`: строки `cam` не покрыты грантом `sub: cam` — пакет невозможен;
- `sub` по каждой строке: противоречит тексту §2.
Роль consolem `DEVICES_SETUP` + `ARCHIVES_SETUP` (§6) не может записать устройство одним пакетом ни при одном прочтении, кроме обходного. Две реализации по канону разойдутся в наблюдаемом поведении на допустимом входе.

Источник: ADR-0094 доп. (9) п. 2–3; `decisions/inbox/2026-10-29-план-ADR-0094-B-платформа.md:102`–`103` («права — по каждой строке»); договор сторожевой `need` (строки единиц PUT → `admin`; таблицы → `rights.routes`).

Предложение: дописать в §2 `sub` пакетной двери и шага операции ADR-0095 (например, `sub` корневой единицы пакета) и явно зафиксировать следствие: проверки частей идут с этим `sub`, т.е. «запись устройства — действие `cam`»; либо разрешить пакету проверять каждую строку с её `sub` и изменить формулировку «один `sub` на запрос». В Confirmation — вектор: пакет `cam`+`rec` под грантом `admin sub: cam` и под парой `sub: cam` + `sub: rec`.

### [Существенная] С1 — `POST /marks`: `sub` действия = «поле `sub` записи журнала», но отметку пишет консоль, и `console` в грамматике `sub` гранта невыразим

Место: `decisions/0097-…:83` (таблица §2, строка «события и метки (`/events`, `/marks`) — поле `sub` записи журнала»).

Цитата: «события и метки (`/events`, `/marks`) | поле `sub` записи журнала».

Контрпример: отметка оператора — строка в дереве `console/…` с `of` = единице тела, `user` — `operator` (P/06.4, сц. 03, `Platform/06-console/spec/06.4-console.norms.md:402`); у записи журнала двери `sub` — «подсистема двери» (`Platform/common/contracts/event-journal.md:83`), т.е. `console`. Грамматика `sub` строки гранта (§1, `:60`) — «имя манифеста … или `platform`»; `console` — запрещённое имя подсистемы (P/02.1 Н1.2, `02.1-installer.norms.md:226`). Человек с `edit sub: cam unit:cam/7` зовёт `POST /marks {unit: cam/7}`: шаг 5 отбрасывает его строку (`cam` ≠ `console`) → 403, хотя договор сторожевой требует лишь «`edit` на единицу тела» (`gate-and-pass.md:92`–`93`). Ни одна строка с `sub` метку поставить не может — только строки без `sub`.

Источник: P/06.4 Н1.2/Н2; договор журнала событий; договор сторожевой `need` (`/marks`).

Предложение: для `POST /marks` определить `sub` действия как `sub` единицы тела (`cam/7` → `cam`), а не `sub` записи; «поле `sub` записи журнала» оставить только фильтру видимости `GET /events`. Проверка в Confirmation: метка под `edit sub: cam unit:cam/7` — 200, под `edit sub: rec unit:cam/7` — 403.

### [Существенная] С2 — `sub = null` снимает фильтр подсистемы: грант «только `cam`» открывает кластерные двери (`GET /drain`, `POST /domain/move`)

Место: `decisions/0097-…:74` (§2 шаг 5) и `:82` (таблица: «чтение без подсистемы: `/session`, список папок, `GET /drain` — `null`»).

Цитата: «при `sub = null` — все строки».

Контрпример: `GET /drain` требует «`view` на `*`» (договор сторожевой `need`, `gate-and-pass.md:96`–`97`; «дренаж — состояние всего кластера, частичной видимости нет», C06-DRAIN-VISIBILITY-33-01). При `sub = null` шаг 5 пропускает строку `view sub: cam scope: *`, и шаг 7 покрывает `*` → человек с правами «только камеры» читает дренаж всего кластера. Хуже: `POST /domain/move` (`admin` на `*`, P/08.8 Н1.8) в таблице §2 вообще не назван; если реализация назначит ему `null`, строка `admin sub: cam *` даёт аварийный перенос домена; если `platform` — другая реализация откажет. Асимметрия внутри самой таблицы: `PUT /drain` — `sub: platform` (строка `:81`), `GET /drain` — `null`, т.е. писать дренаж грантом `sub: cam` нельзя, а читать — можно.

Источник: договор сторожевой `need`; P/06.7 Н1.9; C06-DRAIN-VISIBILITY-33-01.

Предложение: дверям, чья единица — `*` и которые не относятся к подсистеме, назначить `sub: platform` (как их записи), а не `null`; `null` оставить только шагу 6 (`view` без единицы: `/session`, список папок). Таблицу §2 дополнить всеми дверями `need` договора: `POST /domain/move`, `DELETE /<sub>/asked/*` (там `admin` на `*`, но `sub = s` по первой строке — стоит сказать явно), чтения `/manifest`, `/servers`, `/schema`, одиночное чтение папки (см. М1).

### [Существенная] С3 — Чем `folder:<id>` покрывает запись самой папки, не определено: §5 пользуется отношением, которого нет в §4

Место: `decisions/0097-…:99`–`100` (§4) против `:110`–`111` (§5).

Цитата: §4 — «Покрывает единицу, если она или её about-единица — член папки `<id>` или любой её подпапки»; §5 — «область покрывает папку: `*`, `folder:F` или `folder:<предок F>`».

Контрпример: папка `F` не является членом самой себя, поэтому по §4 `folder:F` запись папки `F` не покрывает вообще — а §5 требует ровно этого для её переименования. Обратно: покрывает ли `folder:X` запись подпапки `S` (для удаления `S`)? По тексту §5 «`folder:F` или `folder:<предок F>`» — да (предок), но это сказано только перечнем, а не правилом; про создание подпапки в `P` написано той же фразой с `F` (см. М4). Норму P/06 по этому ADR две реализации напишут по-разному.

Источник: ADR-0096 §2 (цепочка предков), §6 (стык с C3); договор `may` шаг 7 (перечень областей).

Предложение: в §4 или §5 — явное правило: «область `folder:X` покрывает запись папки `F`, если `X = F` или `X` — предок `F`; `*` покрывает всегда; иных областей запись папки не имеет» (включая поведение при удалённом предке: цепочка не читается — не покрывает, как у единиц). Векторы `covers.tsv` пополнить строкой «`folder:` у записи папки».

### [Существенная] С4 — Эскалация через членство: `edit` на единицу + `admin` на папку подставляет единицу под чужие гранты `folder:F`

Место: `decisions/0097-…:112`–`115` (§5, второй абзац).

Цитата: «Добавить единицу `U` в `F` … — ещё **`edit` на `U` в её подсистеме**. … Так нельзя "перетащить" чужую единицу к себе (нет права на `U`)».

Контрпример: у оператора грант `admin sub: rec folder:F` (управление архивами членов `F`). У монтажника — `edit sub: cam unit:cam/7` и `admin sub: platform folder:F`. Монтажник добавляет `cam/7` в `F` — §5 это разрешает (`edit` на `U` есть, `admin` на `F` есть). С этого мгновения оператор получает `admin rec` на `cam/7`, которого у него не было и которое монтажник выдать не вправе (выдача грантов — `admin` по `domain/grants/domain`, P/08.4 Н2/Н3). До ADR-0097 аналогичный фокус требовал `admin` на единицу (метки и состав правятся записью строки единицы: `need` PUT → `admin` на единицу); новая модель снижает порог до `edit`. Снятие защищено (`admin` на `G`), добавление — нет.

Источник: §5; договор сторожевой `need` (PUT строк единиц); ADR-0096 §1; P/08.4 Н2.

Предложение: добавление единицы в папку требовать `admin` на `U` (как запись её строки), либо решение о пороге `edit` записать решением владельца с явным перечнем последствия. Помечено как вопрос «Архитектору» (меняет решение, вопрос 1).

### [Существенная] С5 — Не назван путь записи грантов из `backend` (`POST /access/apply`) и перевод `RoleGlobal.ur`

Место: `decisions/0097-…:15` (Context: «`GET /access`, `POST /access/apply`; сейчас `NO_ROUTE`»), §6 (`:119`–`135`), §8 п. 5.

Цитата: «Потребитель первым — подсистема VMS `backend` (права consolem, `GET /access`, `POST /access/apply`…)».

Контрпример: гранты пишет только дверь `PUT /domain/grants/<кластер>` у процесса `domain` через консоль домена (P/08.4 Н2, Н1.9 `pass`). Перечень обратного вызова `backend` (ADR-0094 B1, `decisions/0094-…:104`) — двери консоли кластера и явно «без … грантов, людей, ключей»; пути от `backend` к консоли домена нет ни в одном ADR. Значит, применить переведённые строки `backend` не может — потребитель, ради которого решение написано, остаётся без транспорта записи. Далее, `RoleGlobal.ur` (`NO | DEV | ALL`, «права на права пользователей», `consolem.openapi.json:6012`–`6019`) — это и есть право менять гранты; в §6 оно не переведено и не названо среди непереводимых (`:133`–`135`), хотя именно оно определяет, кто через `/access/apply` вправе выдавать строку с `sub` (вопрос поручения «кто вправе выдавать грант с `sub`» в ADR без ответа: выдача — `admin` домена, а стык с consolem-правом `ur` не определён).

Источник: ADR-0094 B1; P/08.4 Н2; V/11.2 Н1.2 № 78, 88 (`VMS/11-backend/spec/11.2-backend.norms.md:127`, `:137`); `consolem.openapi.json` `RoleGlobal`.

Предложение: в §7 или §8 явным пунктом: транспорт `backend` → запись `domain/grants` (дверь консоли домена по билету второго вида, её перечень, право — `admin` по `domain/grants/domain`, проверки `last_admin`, `grant too wide`) — отдельное решение; `ur` добавить в таблицу §6 (перевод или в перечень непереводимого). Иначе приращение не достигает своего Context.

### [Мелкая] М1 — `sub` действия чтения одиночной папки не назван

Место: `decisions/0097-…:81`–`82`.

Цитата: «записи консоли: папки (`platform/folders`, `platform/memberof`) … — `platform`»; «чтение без подсистемы: `/session`, список папок, `GET /drain` — `null`».

Контрпример: `GET /folders/<id>` — не «запись» и не «список». Если ему `sub: platform`, человек с единственным грантом `view sub: cam` видит папку в списке (`null`, шаг 6), но открыть её не может (403) — модуль консоли строит дерево по одиночным чтениям и сломается; если `null` — согласовано со списком. ADR-0096 §6 («чтение — любая действующая строка») чтению одиночной папки отвечает, а таблица §2 ADR-0097 — нет.

Предложение: назвать чтения папок (список и одиночные) одной строкой таблицы с `null`.

### [Мелкая] М2 — Стоимость `may`: чтение членства и цепочек не ограничено условием «есть строка `folder:`»

Место: `decisions/0097-…:101`–`102` (§4).

Цитата: «Вход `may`: `unit` и `about` получают `folders: [<id>…]` … Консоль читает `platform/memberof/<ключ>` и цепочку `parent` до корня».

Контрпример: при отсутствии грантов `folder:` в документе каждая проверка права (а их несколько на запрос: путь + `unit_of` + `reach` + `names`) платит чтением `memberof` единицы и about и обходом до `FOLDERS_PER_UNIT_MAX` × `FOLDERS_DEPTH_MAX` строк. Consequences называют цену только «проверка `folder:`» (`:165`), а текст §4 читает всегда. Реализация, следующая тексту буквально, и реализация с ленивым чтением разойдутся по нагрузке на хранилище на каждом запросе.

Предложение: записать, что `folders` вычисляется, только если среди действующих строк шага 5 есть область `folder:`; предел числа чтений на одно решение — числом нормы рядом с `FOLDERS_PER_UNIT_MAX`/`FOLDERS_DEPTH_MAX` (как требует ADR-0096 §2 для записей).

### [Мелкая] М3 — Порядок `grants` в `GET /session` с `sub` не назван

Место: `decisions/0097-…:92` (§3).

Цитата: «`GET /session`: `grants: [{cap, sub?, scope}]`».

Контрпример: договор сторожевой «Права по телу» `session` задаёт порядок «по `(cap, scope)`» (`gate-and-pass.md:315`–`316`). С третьим полем порядок не определён; jsdom-модуль и две реализации отдадут разный порядок при равных `cap` и разных `sub`.

Предложение: «по `(cap, sub, scope)`, нет `sub` — пустая строка» (как порядок строк §1) или явно «порядок прежний, `sub` не участвует».

### [Мелкая] М4 — §5 смешивает `P` и `F`; §6 не показывает добавку `view cam`, обещанную §7.4

Место: `decisions/0097-…:110`–`111` и `:123`–`:144`.

Цитата: «Создать подпапку в `P`, переименовать или удалить `F` … — область покрывает папку: `*`, `folder:F` или `folder:<предок F>`».

Контрпример 1: для создания подпапки в `P` область должна покрывать `P`; текст пишет `F`. Буквальное чтение даёт проверку не той папки. Контрпример 2: §7.4 (`:144`–`145`) говорит, что «человеку с одним `sub: rec` нужно видеть список камер — решает перевод `backend` (§6)», но строки §6 для `cam: ONLY_ARCHIVE` — только `view rec` (`:129`): перевода в `view sub: cam` таблица не содержит, и `backend`, следующий таблице, список камер этому человеку не откроет.

Предложение: переформулировать первое предложение §5 двумя (создание — область покрывает родителя `P`; правка/удаление — `F`); в §6 строкой или примечанием показать добавку минимального `view sub: cam` к уровням камеры (со ссылкой на §7.4 как на основание).

## Проверено, находок нет

- Совместимость выданных грантов: строки без `sub` при отборе шага 5 действуют при любом `sub` входа (`:74`) и при `sub` каждой двери — смысл сегодняшней строки сохранён; `last_admin` — строка без `sub` (`:69`), приёмка «не считает строку с `sub`» названа (`:174`–`175`); переноса документов нет (ADR-0003 соблюдён).
- Пересечение `sub` с метками: `labels:` проверяется шагом 7 после отбора по `sub`, семантика меток не меняется; вариант «папка — метка» обоснованно отвергнут (размещение сверяет `labels-subset`, `cam.subsystem.yaml:173`–`179`).
- `platform` в `sub` коллизии не даёт: `platform` — запрещённое имя подсистемы (P/02.1 Н1.2, `02.1-installer.norms.md:226`).
- Удалённая папка: строки `folder:<id>` мертвы, id не повторяется (128 бит, ADR-0096 §1), права не воскресают; «не прочитано — не покрывает, не 503» совпадает с правилом `scope` для `labels:`/`unit:` about (`gate-and-pass.md:115`–`117`).
- Перенос единицы гранты не переписывает (гранты у держателя домена, папки в кластере) — драйвер выполнен; снятие члена при удалении единицы — прежним правом (ADR-0096 §4 «права следствий» сохранено, `:116`).
- Обход «увести единицу из-под чужих прав» закрыт: снятие из `G` требует `admin` на `G` (`:113`–`115`).
- Грамматика `sub` проверяется дверью, наличие манифеста — нет: как `<sub>` в `unit:` сегодня (P/08.4 Н1.3); строка про неустановленную подсистему ничего не открывает — записано Neutral.
- Порядок и повторы строк с `sub` (`:63`–`64`) согласованы с P/08.4 Н1.3 (вставка `sub` между `cap` и `scope`, `until` по числу последним); `domain/grants/domain` без `sub` — 400 (`:68`) согласовано с назначением этого документа.

1. (С4) Подтвердить порог права на добавление единицы в папку: `edit` на единицу (как написано) или `admin`? При `edit` держатель `admin folder:F` + `edit unit:` косвенно расширяет чужие гранты `folder:F` на эту единицу.
2. Видимость `GET /events` (и тревог): фильтр по `sub` записи журнала скрывает от человека с `admin sub: cam` события `rec`/`det` о его же камерах.
