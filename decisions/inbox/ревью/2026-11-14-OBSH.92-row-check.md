## Б1. must_match: элемент `""` против элемента `""` принят, договор требует 409

`code/row-check/refs.go:158-176` (`sameElements`): при обоих элементах present сравнение сводится к
`a == b` (refs.go:175), поэтому `"" == ""` → «равны» → отказа нет. Это касается и прямой пары
(directRefs, refs.go:56-60), и обратной (reverseRefs, refs.go:97-103).

Договор (`contracts/row-check.md:205-208`, раздел `ref_and_must_match`):
«with a live target the values are equal; otherwise 409 conflict, fault must_match; **an absent element of
the target is equal to nothing, and "" too**». Элемент `""` не равен ничему, в том числе другому `""`.

Сценарий: `create testsub2/tallies` с `{"name":"t1","of":"c1","shelf":"sh7","zone":""}` и строкой
`{"testsub2/shelves/sh7":{"name":"sh7","zone":""}}` в `rows` → код: `ok`; договор: 409, fault
`must_match`. Симметрично при edit (`R3`) и для обратной пары. Все прочие комбинации
(отсутствующий против `""`, `""` против значения) код ведёт как договор — расходится только `""`-против-`""`.

Почему векторы зелёные: `must_match_absent_element` (cases.tsv) — это absent против `""`, случая
`""`-против-`""` в корпусе нет. Исправление: в `sameElements` пустой текст элемента любой из сторон
делает сравнение неравным (или эквивалентное правило договора).

## Б2. «given» при создании засчитывает `null` у поля с inherit — P4 обходится

`code/row-check/prepare.go:85-95` (`prepareCreate`): `p.given[f.Name] = v != nil` (prepare.go:89) —
поле, переданное как `null` и имеющее `inherit`, помечается как данное, хотя значение не готовится
(preparedValue, prepare.go:104-105, возвращает nil по шагу 2 «Preparation of fields»).

Договор (`row-check.md:128-129`, шаг 2): «The field is not given **or is given as `null` and has
`inherit`** — do not create an element» — такое поле НЕ дано. Далее (`row-check.md:144-145`): «A required
field that was not given still gives the refusal P4». `requiredCheck` (check.go:166-177) из-за
`given=true` пропускает такое поле, и строка создаётся без элемента обязательного поля.

Сценарий: манифест с `unit.fields.<f>: {required: true, inherit: …}`; body `{…, "<f>": null}` → код:
`ok` без элемента `<f>`; договор: 400 `required` («a <sub> unit needs a <f>»). Вторая форма проявления:
источник именованного id обязателен и передан как `null` с inherit → `requiredCheck` пропускает,
`emptyIDCheck` (check.go:182-190) отказывает `bad_id` «is empty», а договор (row-check.md:241-243) для
не данного id обещает отказ P4 («needs a <field>»): «an empty or not given id P3 skips: the refusal
comes from P4».

Почему векторы зелёные: в testsub/testsub2 нет обязательного поля с inherit; `required_missing` и
`required_empty` — plain required. Исправление: `given` = «поле есть в body и не (null с inherit)».

## М1. Детализация `bad_url`: имена полей credentials против A15

`code/row-check/url.go:368-383` (`CredentialFields`). Договор адресов A15
(`contracts/url-credentials.md`): «A refusal of a parsed address by the section «Schemes» (a scheme not
from schemes, no host, no path) **is not A15**: the credentials do not give it» — код для таких отказов
всё же добавляет имена полей, если `findCredentials` что-то нашёл (checkURL, p2.go:109-113). И наоборот:
«a url that does not parse» по A15 шире, чем расширение кода `grammarProblem != "" || strings.Contains(why,
"port")` (url.go:371): например `https://[::1/x` отказывает «an IP literal without ]» (url.go:113-114)
без имени `credentials.secret`, хотя адрес не парсится. Текст `detail` судья не сравнивает
(vectors/row-check/README.md:25), поэтому векторы зелёные; расхождение с нормой A15 в содержимом
детализации. Само слово `bad_url` и решение об отказе не затронуты.

## М2. `not_number` для не-числовых видов при int/float

`code/row-check/values.go:62-71` (`isSafeInt`/`floatOf`): значение вида не Number (bool, array, object)
для поля `int`/`float` получает слово `not_number`. Таблица «Refusals» (row-check.md:295) читается так:
«for numbers `error: not_number`; otherwise `error: type`». Канон против этой буквальной читки уже
установлен вектором `int_as_string` (строка для int → `not_number`), код ему следует; для bool/array
кейса в корпусе нет, слово не определено каноном. Отметка для сессии доработки: либо вектор-кейс,
либо читка договора, чтобы обе стороны (дверь и библиотека) не разошлись молча.
