## С1. Заявленный охват форм не соответствует дереву и не следует из COUNTS

**Место:** таблица «Что показал пилот», строка «Формы урока» (строка 21).

**Цитата нормы:** «все уроки платформы, кроме P/07 […] `check_forms` судит грамматику всех».

На срезе ревью `forms/` есть у **P/01–P/06**. У **P/08, P/09, P/10 форм нет**, как и у P/07. Возможность собрать для них дверь/семейства/векторные тесты из OpenAPI, схем и пакетов векторов не означает наличия флагов, отказов и этапов в `forms/`. README normgen отдельно называет forms P/08–P/10 следующей работой.

COUNTS — агрегат обнаруженных форм, не матрица полноты по урокам: glob-поиск `flag_forms`, `refusal_forms` и остальных не добавляет отсутствующую форму урока. Более того, write-checks и YAML-автомат проверяются отдельными `check_tables` и `check_machines`, а не `check_forms`.

**Предложение:** исправить фактическую строку на P/01–P/06, показать для P/08–P/10 только существующие входы/части пакета; общий целевой охват оставить планом. Приложить матрицу «урок — класс формы — файл — проверяющий инструмент», чтобы PASS не выдавался за полноту отсутствующих входов. В п. 4 для ревью форм назвать общий `check_spec` и соответствующий предметный проверщик.

## С2. Доля готового кода пакета смешана с долей кода, выведенного из форм

**Место:** строки мер кода и тестов (24–25), прогноз (64–67); ADR-0120 (5) п. 2 (г).

**Цитаты нормы:** «19,6 тыс. сгенерировано, 11,2 тыс. своих — 64 %»; «подсчёт по `kit.manifest.json` и шапке “DO NOT EDIT”». Условия пилота требуют порознь «строки сгенерированные; строки ручные (примитивы, `#fn`, действия)».

Шапка DO NOT EDIT определяет право редактирования, а не происхождение. В пакет входят закрытые ручные runtime/примитивы. `build_kit.py` сохраняет для них `origin: handwritten`; общий `contracts` также прямо назван ручной средой «один раз на словарь». Их повторная доставка урокам не становится генерацией из формы.

Например, в трёх манифестах первой пробы ручной закрытый Go-код без тестов и vendor составляет **3339 + 2413 + 2461 = 8213 строк**. Проверка на HEAD `ec3ea7a2` по всем Go-файлам с тем же исключением vendor и с отнесением editable-файлов к реализации даёт: закрытый `generated` **10 090**, закрытый `handwritten` **8213**, остальное **12 498**; всего **30 801**. Поэтому ни заголовок, ни общий размер готового пакета сами по себе не воспроизводят заявленную меру генерации. Это не предложение заменить её иной оценкой без согласования границ: нужен явный алгоритм подсчёта.

**Предложение:** закрепить SHA реализаций и пакетов, список каталогов и исключение vendor; вывести отдельно (а) фактический generated, (б) доставленный ручной код пакета, (в) код модели, отдельно для тестов. Editable-заготовки учитывать по конечному содержимому. Если 64/83 % означают долю готового кода, предоставленного пакетом, так их назвать; прогноз механической генерации считать отдельной мерой. Приложить воспроизводимый подсчёт вместо объединения происхождения и запрета редактирования.

## С3. Итог не сводит обязательные независимые меры первоначального пилота

**Место:** Context, строка 15, пп. 4–5; ADR-0120 (5) п. 2 (б), (в), (е), доп. (6) п. 7.

**Цитаты нормы:** «мера формы получена на пробах Codex»; «Пилот закрыт». Условие (5): «Пилот кончается, когда есть все четыре: генератор таблицы сверен с оракулом; отчёт модели v120; прогон проб против свидетелей; исполнитель автомата с таймерами».

Время и LOC новой реализации с пакетом отвечают на вопрос о стоимости разработки. Они не заменяют независимый прогон **86 проб против замороженных c-python/c-go**, написанных по прозе, и сравнение модели по прозе с моделью по форме. Именно эта мера должна была показать, какие прочтения прозы форма уточнила. `test_gen_checks.py` сравнивает выход генератора с оракулом формы; это другая проверка. COUNTS и GREEN новых пакетных реализаций результата старых свидетелей не дают.

Отчёт v120 есть (`cammeta-quint/v120/REPORT.md`, `13791ee`, вход `ac7d00483`), но он предшествует правкам формы по ADR-0120 (5), (6): в нём ещё 17 ручных действий, отсутствующие в форме среда/судьи и три непойманных трассами мутанта. Доп. (6) п. 7 назначало перегонку после правок. В итоговой таблице нет ссылки ни на этот последующий результат, ни на результат проб свидетелей. Из этого не следует, что работы не выполнялись; представленный итог их не позволяет проверить.

**Предложение:** добавить четыре строки назначенной меры с входными SHA, артефактом результата и пределом; отдельно — наблюдения Codex о стоимости пакетов. Если владелец закрывает пилот с отменой оставшихся условий, явно перечислить отменённые условия и оставшиеся проверки. П. 5 сейчас снимает только меру MiniMax и не объясняет судьбу остальных.

## М1. В паре P/01 сравниваются разные виды времени, а пины пар не названы

**Место:** строка времени (23), вывод (28), предел (58); ADR-0125 (5), основание.

**Цитаты нормы:** «21 мин против ≈35»; «Выигрыш по времени есть […] Где время уходит на стенд и прогоны (P/02), его нет».

Основание ADR-0125 (5) называет ≈35 минут **чистой работой** линии без пакета. REPORT пакетной пробы считает стену до результата очереди, включая подготовку, исправления и ожидание. REPORT первоначальной P/01 также сохраняет прежнюю опору владельца **1 ч 19 мин**; переход к ≈35 в ADR-0127 не снабжён расчётом вычтенных интервалов. Пины различаются: линия без пакета сообщает `e3022b40`, P/02–P/03 первой пробы — `c9eaf7f0`, повтор P/02 — `9a21001d`.

**Предложение:** добавить паспорт пар: старт/финиш, включённые и вычтенные интервалы, пины спецификации/пакета/раннера, одинаковый критерий зачёта. В таблице разделить стену и чистую работу. Вывод о причинах времени P/02 оставить наблюдением этих проб до разложения времени; предел «три урока, одна модель» сам по себе разные метрики и пины не уравнивает.
