## Четыре места дельты

| Стенд | Где | Как |
|---|---|---|
| store главы 1.1 (`store1`, цели P/01 через `c_store`) | `c_store.instance_class`, подмена `harness.Instance` внутри `c_store` | `data`, `run`, затем `data/configstore` `mkdir(0o700)` и `chmod(0o700)` |
| store главы 1.2/1.3 и составной стенд | `stand.Stand.__init__`, `stand._second` | `store_directory(data)`: `mkdir(0o700)`, `chmod(0o700)` |
| группа | `store_group.Group.start` | `<член>/configstore`, если его нет, до шаблона |
| три сервера | `power_stand.Members.directory` | `<server>/configstore`, если его нет |

- `chmod` после `mkdir` снимает влияние umask. Право `0700` совпадает с P/02.4 N1.1.
- `@restart store` и restart члена повторяют сохранённую команду и каталог не пересоздают: `store_directory` вызывается только в `__init__` и `_second`, у группы — только при отсутствии каталога. Возврат питания у `power_stand` находит каталог существующим.
- `@foreign`: каталог теперь создаёт `_second`, а не сам `@foreign`; файлы `rows`/`FORMAT` пишутся в готовый каталог. Снимок `tree()` берётся после записи и до старта; режим каталога в него не входит, так что сравнение «дерево то же» не меняется. Каталог прежде создавался с правами по umask, теперь `0700` — для проверки отказа это безразлично.
- `@import`: импорт идёт в `_second("r")`, то есть в свежий `{data}` с пустым `configstore`. По P/01.3 импорт — «into a fresh directory of a stopped daemon». Пустой существующий каталог — тот же случай, что на коробке после установщика.
- `@backup … in-data`: файл `{data}/configstore/<имя>` у работающего store; каталог существовал и прежде.

## Находки

### С1. Два пути запуска store остаются без каталога

**Код:**
- `runner/store_probe_native.py:305–320` — `NativeStore.start`: создаёт `out/data` и `out/run` с `0700`, `configstore` не создаёт. Шаблон — `store1`, иначе `store` (`:134`). Путь работает для нативной пробы `07-framing` P/01 (`c_execute.py:523–525`).
- `runner/harness.py:303–318` — `harness.Instance` вне `c_store`: не создаёт даже `{data}`. Им пользуются цели P/02 с соседом `store1` через `c_installer.py:604`, а также старые `l02.py`, `canonical.py`.

**Норма:** общий README «One data directory» (`6379b8762`): «Before the first start of a store the stand creates the empty directory `{data}/configstore` with mode `0700` … on the stand of one store, …; the daemon does not create an absent `-dir`».

Store, который по норме не создаёт отсутствующий `-dir`, на этих путях не стартует. Проба `07-framing` и цели P/02 с `store1` уйдут в отказ старта, хотя продукт прав. Это прямое следствие решения: другие стенды каталог получили, эти — нет.
**Исправление:** создавать `{data}` и `{data}/configstore` с `0700` в `NativeStore.start` и в `harness.Instance` (или в общем помощнике, как `stand.store_directory`). Тест: поддельный store, отказывающий без каталога, на обоих путях.

### С2. Готовый `configstore` в стенде главы 1.1 противоречит свободе шаблона `store1`

**Код:** `c_store.instance_class` (`:70–74`) создаёт `{data}/configstore` и для `store1`. После С1 так же будут создавать `NativeStore` и `harness.Instance`.
**Норма:** PROFILE «Substitutions» закрепляет `-dir {data}/configstore` только за командой `store`. Для `store1` README главы 1 говорит лишь «consumes the assigned data directory», `-dir` шаблона не задан. P/01.3 N1.3 `format`: непустой каталог без `FORMAT` — отказ старта, код 2.

Реализация с законным шаблоном `store1`, где `-dir {data}`, получает непустой каталог без метки: в нём лежит `configstore`. Демон по норме отказывает с кодом 2. До дельты такой шаблон работал, так что это регресс для законной реализации.

**Исправление — в норме, не в коде.** Предлагаю закрепить в PROFILE «Substitutions» для `store1` то же правило `-dir {data}/configstore`, ровно один раз, как у `store`. Тогда каталог store одинаков во всех стендах, совпадает с `lifecycle.md` и раскладкой P/02.4, а созданный стендом каталог — это и есть `-dir`. Остальные флаги `store1` остаются выбором реализации. Нужно слово Архитектора, смысл новый. Без него раннер должен создавать каталог только для команды `store`, а у `store1` давать пустой `{data}`.

### М1. `harness.Instance` не создаёт `{data}`

**Код:** `harness.py:303–318`: создаются `run/` и `rights.json`, а `{data}` нет. Норма «One data directory» предполагает, что `{data}` есть. Это старое поведение, не внесённое дельтой; при исправлении С1 закрывается само.

## Совпадение с нормой

Для стендов, которые дельта затронула, раскладка совпадает с общим README (`6379b8762`): пустой `{data}/configstore`, `0700`, до первого старта; демон его не создаёт. Совпадает и с PROFILE для `store`, и с `lifecycle.md`. Расхождения — пути С1 и шаблон `store1` из С2.
