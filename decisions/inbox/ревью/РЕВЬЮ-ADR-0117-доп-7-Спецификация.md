# Ревью ADR-0117 доп. (7) — «Спецификация»

Второй ревьювер, main f349fa89c. Сверено с V/08.6 (поля части), V/08.7 Н1.2–Н1.5, `exp.subsystem.yaml` (`settings.area` — массив из четырёх чисел 0…1). Доли платформы в (7) нет: форму части судит загрузчик и консоль по схеме манифеста, а соотношения `x + w ≤ 1` схема не выражает. После ADR-0119 доп. (10) их судит один `backend` (`writes_via: [backend]`), обхода дверью строк нет.

**Счёт: Б 0, С 2, М 3.**

## С

**С1. Доли в пиксели и наименьший размер.** `w > 0` пропускает область меньше одного пикселя: `w = 0.0001` у кадра 1920 — это 0,19 пикселя, обрезка даст пустую картинку. Для видео H.264 нужны ещё и чётные стороны. Предлагаю нормой V/08.7:
- края — `x0 = floor(x·W)`, `x1 = ceil((x + w)·W)` (так же по `y`); у видео — до чётных внутрь кадра;
- сторона меньше 16 пикселей (меньше `settings.width` по схеме манифеста) — итог `failed` `bad_area` у держателя. Размер кадра до чтения неизвестен, поэтому `backend` этого не рассудит.

**С2. Порядок с маской и титрами.** Маска приватности задана в долях полного кадра камеры. Если сначала обрезать кадр, а потом наложить маску, маска сдвинется. Порядок должен быть таким: маска по полному кадру, затем обрезка `area`, затем масштаб `width` и `height`, затем титры по обрезанному кадру. Это строка V/08.7 Н1.4 и Н1.2, Н1.3.

## М

**М1. V/08.7 Н1.2 «Файл — `jpg` как есть»** противоречит п. 1. При `area` живой кадр декодируется. Без `area` «как есть» остаётся, и это стоит сказать прямо, чтобы перекодирование кадра не шло всегда.

**М2. `settings` частей одного заказа теперь различаются.** До (7) общие поля заказа копировались в каждую часть одинаково (V/08.6 Н1.1), а ведущая часть несла заказ. Теперь `settings.area` у каждой части — своей камеры. Две вещи надо сказать явно:
- `GET /exports/{id}` собирает `cameras[i].area` из частей, а не из ведущей;
- `retry_of` (повтор неудачных частей) берёт `area` из повторяемой части.

**М3. Проверка п. 3 и схема.** Схема манифеста уже держит `0 ≤ x, y, w, h ≤ 1` поштучно. `422` п. 3 добавляет `w > 0`, `h > 0` и суммы. В контракте V/11 полезно перечислить все условия одним списком у `/cameras/i/area`: и поштучные из схемы, и суммы. Тогда окно сможет назвать причину. Сравнение `x + w ≤ 1` — в двоичных числах без допуска. Проверила на 10⁵ случайных `x` с `w = 1 − x` и на всех долях с шагом 0,01: ложных отказов нет.
