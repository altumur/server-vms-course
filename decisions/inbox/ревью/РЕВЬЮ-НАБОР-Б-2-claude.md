## Н-1. Не согласен. `last-spaces` отказывает больше, чем закрывает дефект D16

**Где.** ADR-0092 доп. (2) п. 2: «последняя строка из пробелов без перевода строки (D16, L24T)» — среди обходов, которые
«держат закреплённые версии на норме YAML 1.2.2». `textv7.py` `check_bytes`: «last line of spaces without a line feed
(L24T)» — проверка по байтам всего файла, вне зависимости от узла.

**Прогон** (база `r38_unit_minimal` + `worker:`):

| вход | эталон | Python | Go |
|---|---|---|---|
| база + `"  "` в конце (без блочного скаляра) | ok | `refused:text` | `refused:text` |
| база + `display:⏎  unit: \|⏎    counter⏎  ` (блочный скаляр, затем пробелы без LF) | ok | `refused:text` | `refused:text` |
| база + `"  ⏎"` (пробелы с LF) | ok | ok | ok |

Дефект D16 — в значении блочного скаляра: парсер теряет конечный `\n`. Вне блочного скаляра строка из пробелов в конце
никакого значения не несёт. YAML 1.2.2 её принимает, Н1.1 тоже (эталон — `ok`). Правило отказывает её всегда. Это
**смена вердикта** `ok → refused:text` на входе, который человек оставит редактором, — а в Б её нет ни строкой, ни
случаем. Подпись «обход дефекта на норме YAML 1.2.2» её прячет.

**Предложение** (на выбор владельца):
- **(а)** сузить обход до сути дефекта. Перед разбором дописать LF, если последняя строка — только пробелы. Вердикт и
  значение тогда совпадают с YAML 1.2.2 и с эталоном, дельты нет. Проверить на L24T/01, 4RWC, JEF9/02 и на двух входах
  выше.
- **(б)** оставить отказ. Тогда — строка Б «`ok → refused:text`, основание: обход D16 сужает язык» и случай корпуса, а в
  доп. (2) правило — в п. 1 (норма текста), не в п. 2.

Рекомендую (а): отказ без причины в норме на типичном следе редактора — плохая цена за дефект в одном виде узла.

## Н-2. Дельта Б пропущена: `\<TAB>` в двойных кавычках

**Норма.** Н1.1 (`02.1-installer.norms.md`, `escape`): «в двойных кавычках — только `\\` `\"` `\/` `\t` **`\<TAB>`** `\n`
`\r` `\<пробел>` `\_` …».

**Прогон.**
- `display: {unit: "a\<TAB>b"}`: эталон `ok`, Python и Go — `refused:text` (правило `tab`, п. 4);
- `"a\tb"` — `ok` у всех трёх;
- `\x09`, `\u0009` — `ok` у всех трёх.

Прочие экранирования Н1.1 и YAML 1.2.2 сходятся у всех трёх:
- `ok` — `\_`, `\<пробел>`, `\/`, `\r`, `\n`;
- `refused:text` — `\0`, `\e`, `\N`, `\L`, `\'`, `\q`.

**Оценка.** Следствие п. 4 («TAB вне комментариев — отказ») верное, спорить не о чем: TAB в значении по-прежнему пишется
`\t`. Но это смена нормы: вход, который Н1.1 называет допустимым, становится отказом. Нужны:
- строка Б `ok → refused:text` (основание п. 4);
- случай;
- правка списка `escape` Н1.1 (убрать `\<TAB>`) в пакете перехода.
