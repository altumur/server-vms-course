# Ревью текста: ADR-0112 доп. (22) (Claude)

Доп. (22) на main 0ce6b53b3. Сверено с P/06.5 Н1.1 `module.opts` (`subsystems: [<из /mounts>]`, `06.5-console.norms.md:86`), P/07 (`order`: `/servers`, `/unplaceable` — после строк подсистем) и списком манифестов `VMS/*/*.subsystem.yaml`: `cam rec live det detjob detedge auto assist backend`.

**Счёт: Б 0, С 0, М 2 — в нормы без дополнения.** С1 (21) закрыт: `units` остаётся, строки подсистем VMS убраны через `opts.subsystems`.

**М1. В перечне нет `live` и `assist`.** Скобка — `cam`, `rec`, `det`, `auto`, `detjob`, `detedge`, `exp`, `psim-*`, `backend`. Манифестов VMS ещё два: `live` (`streams`, `accounts`) и `assist`. Их строки тоже пишет форк через `backend`. Лучше правило вместо перечня: «все подсистемы модуля VMS — каталог `VMS/*/`, `psim-*` и `exp`».

**М2. Остаётся пустой список, а его смысл не назван.** На кластере VMS все смонтированные подсистемы — VMS, так что `opts.subsystems` будет `[]`. P/06.5 даёт только форму `subsystems: [<из /mounts>]` с умолчанием «все». Пустой список реализация может прочесть как «не задано» — все. Назвать в доле P/07 («Спецификация»): `[]` — ни одной подсистемы, панель единиц показывает только серверы, `drain`, `unplaceable`. Плюс тест модуля на `[]`.
