# Второе ревью ADR-0115 доп. (2) (main a14d07bce) вместе с (0) и (1) («Спецификация»)

Сверено с P/02.1 (`unit`, `tables.<имя>`, `display`, `tableName`), P/02.5 Н1.4, P/03.6 Н1.7, P/06.1 Н3 «Общая проверка строки», договором проверки строки `ref_and_must_match`, договором журнала событий. Ревью доп. (1) «Спецификации» в main не вошло: ветку удалили до него. Его находки, которых (2) не решает, ниже — Б1, С1–С3.

**Счёт: Б 1, С 4, М 3.**

Чисто:
- п. 2 — имя подсистемы, `ref` вместо `about`;
- п. 3 — значения `display.*` в форме `строка | {key, text}` и `display.langs`;
- п. 4 — `*_secret`;
- `hidden` + `required` без `default` и `schema.enum` у `int` (п. 7);
- п. 8 — платформы не касается.

## Б

**Б1. `readonly` у прочих `object_type` (п. 1 при п. 2): `unit.state` есть только у единицы.**
Места: доп. (2) п. 1, п. 2; P/02.1 `tables.<имя>` (ключи `{key, fields, schema, service, stamp, journal, delete_after}` — `state` нет); P/02.5 Н1.4: консоли — `<s>/<таблица>/*` «кроме таблиц из `worker.writes`, у них — `delete:`».

П. 1 решает `readonly` для корневого вида. Прочие виды по п. 2 — таблицы. У таблицы нет состояния. Таблица бывает или консоли, или воркера. У SENSOR (`security_controller`) есть и поля оператора, и `readonly` плагина. В одной таблице это нельзя без нового правила «писатель по полю»: правка оператора и `ChangeUnit` соперничали бы на CAS одной строки.

Предлагаю без нового ключа и без правки платформы. У прочего вида с `readonly` две таблицы:
- `<т>` — пишет консоль;
- `<т>_seen` в `worker.writes` — поля `readonly`, ключ строки тот же, поле `ref` на `<т>`.

Строку `<т>_seen` снятого объекта снимает воркер. Описание вида сводит обе таблицы в одну схему, `x-readonly` берётся из `<т>_seen`. Вид без `readonly` — одна таблица.

## С

**С1. Подписи полей таблиц (п. 3 при п. 2).**
`display.fields`, `field_help`, `options` — «имя поля → подпись» для полей единицы. Ключа таблиц у `display` нет. Поля прочих видов — поля таблиц: подписям негде лежать. Одно имя у двух видов (`mode`) столкнётся.

Предлагаю `display.tables.<т>: {fields, field_help, options}` той же формы. Это пятый ключ P/02.1. Иначе — правило имени `<т>.<поле>` в `display.fields`, и загрузчик принимает такое имя.

**С2. Параметры плагина (`Configure`) и два корневых вида (п. 2).**
Доп. (1) п. 2 заменил п. 1.2 целиком, а с ним ушла «единица вида `<plugin>` с одним экземпляром». Корневой `object_type` — `unit`. Где лежат параметры `Configure`, нигде не сказано. Плагину с двумя видами без родителя `unit` на двоих не хватит.

Нужно правило. Например:
- параметры плагина — служебная таблица с одной строкой, ключ — имя плагина;
- второй корневой вид — таблица без `ref` на родителя.

**С3. События и права строк таблиц (п. 2).**
Бакет журнала и `of` события — единица `<sub>/<id>` (P/03.6, договор журнала событий). У строки таблицы журнала нет. Тревога датчика пишется в бакет корневой единицы. Нужно слово: событие несёт поле с ключом строки таблицы, например `object`; по нему форма и `backend` отбирают события объекта. Иначе — назвать пределом.

Право на строки таблиц даёт только `rights.unit_of: {<т>: <поле ref на корень>}`. Без него правка строк — `admin`. Генератор ставит его каждой таблице, у которой есть цепочка до корня; урок называет это.

**С4. `items.ref` трогает не только загрузчик (п. 5 и «Что меняется вне VMS-слоёв»).**
П. 5 говорит: «загрузчик судит `ref` у каждого элемента». Но ссылку значения судит консоль платформы, а не загрузчик. Это общая проверка строки P/06.1 Н3 и договор проверки строки `ref_and_must_match`: цель не читается — 409 `garbled`, проверка в обе стороны. Права чтения целей выводит P/02.5 Н1.4: «цели `ref` и `must_match` полей адресата `<ref>/*`».

С `items.ref` меняются, кроме загрузчика:
- договор проверки строки — цель каждого элемента — строка `<ref>/<элемент>`;
- P/06.1 Н3 — проверка по элементам;
- вывод прав P/02.5.

Абзац «Платформа — только загрузчик… консоль платформы — без правок» надо поправить: правка малая, но это консоль и права. Вариант без правки консоли — `items.ref` только подпись для формы, проверки значения нет («цели нет — не отказ» и так верно для `ref` без `must_match»). Тогда это и надо сказать.

## М

**М1. `events.kinds.<id>.label` повторяет `display.kinds`.** П. 3 даёт подпись вида события в `display.kinds`, п. 6 — ещё и `label` в `events.kinds`. Предлагаю `events.kinds: {<id>: {severity}}`, подпись — только `display.kinds`. И нужен закрытый перечень `severity` для загрузчика. Иначе — строка, которую загрузчик не судит; тогда перечень — у «Спецификации VMS» вместе со связью с классом.

**М2. Имена таблиц от `object_type`.** П. 2 задаёт грамматику только имени подсистемы. Имя таблицы — `tableName`: не из запрещённых имён (`events`, `state`, `commands`, `snapshot` и др.). Генератору нужно то же правило: нижний регистр, отказ при запрещённом имени или столкновении.

**М3. Где ставят `hidden` и `items.ref`.** Оба ключа — и у `unit.fields.<имя>`, и у `tables.<т>.fields.<имя>`: после п. 2 параметры прочих видов — поля таблиц. `items.ref` вместе с `ref` у одного поля — отказ. `must_match` при `items.ref` — отказ, пока его смысл для списка не задан.
