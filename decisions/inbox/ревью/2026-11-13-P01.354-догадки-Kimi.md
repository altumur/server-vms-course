## План реализации по этапам forms/stages.tsv (без кода)

Черновик порядка работ; выборы «Implementation decides» фиксируются в описании реализации (ARCHITECTURE), QUESTIONS.md — по догадкам Б ниже.

1. **model** — чистое ядро `write_model`: формы ключа/версии/cas/guard/id, вес, порядок проверок по `write-checks.tsv`; свои тесты + вектор `01-store/write-checks` (конверт probe-tables.tsv). Gate: vectors + code (C01–C04, C25, C29).
2. **launch** — каркас демона: флаги из `daemon-flags.tsv` (C05), FORMAT, плоские сокеты, одна дверь над Handler пустого ядра; клиентский разбор через общий модуль store-client (C27). Gate: accept 01-absent + code.
3. **jcs** — канонический JSON (RFC 8785) общего модуля `common/json` (C06–C08, C25); вектор `common/jcs`. Gate: vectors + code.
4. **store_core** — операции N3 в памяти: guard до cas, id-память, admission time, батч одной записью; машины `admission_step`, `journal_step` (C09–C12). Gate: accept 01-absent…37-batch-times + seams s1–s4, s7–s12 + code.
5. **http** — двери 1.1: разбор N2.1 (query, framing, лимиты, лон-суррогаты, JSON_DEPTH), карта отказов N4 (C13–C15). Gate: accept:1.1:* + code.
6. **rights_eval** — загрузчик файла прав и вычислитель по общему контракту (C16–C18, C26); вектор `common/rights-evaluator`. Gate: vectors + code.
7. **rights** — права на дверях: порядок N3, /v1/list, /v1/rights; роль-сокеты; заголовок форвардинга (`keys.role_header`). Gate: accept:1.2:* + code.
8. **daemon_doors** (when=true) — /v1/status, /metrics, служебные двери, сокеты (наследуемые и свои), rlimit-соединения. Gate: accept 04, 15, 16, 23, 24, 21 + seams s7–s9 + code.
9. **daemon_copy** (when=true) — backup/import/restore на box, FORMAT/чужой каталог, id-память в копиях; ядро `copy_core`/`copy_step` (C19–C21). Gate: accept 10–12, 14 + seams s10 + code.
10. **durable** — журнал, версии, барьеры durability, повреждённая строка, рестарт; `journal_step` (C22, C23). Gate: seams s5, s6, s9, s13–s19 + accept 08, 19, 20, 22, 30, 36 + code.
11. **group** (when=`keys.store_build != 'box'`) — hashicorp/raft v1.7.3 (C24): join/leave, recover, копия и батч в группе, дверь без голоса, TLS-проверки peer, векторы `common/revoked`, `common/crl`, `common/store-client`, `common/family-read`, `common/log-mask` (C28 — пин в go.mod отсутствует, см. долг ниже). Gate: accept 07, 17, 18, 25–29, 31–35 + seams s11 + code.

Интерфейсы профиля `01-store` (acceptance.yaml): `stand.store`, `stand.store1`, `stand.backup`, `stand.import`, `stand.store-op`, `stand.checkpoint` (или `none`), `stand.spoil-row`; ключи `request_line_limit`, `role_header`, `store_build`; `adapters.door` (optional); векторные команды 8 пакетов; карта `code` C01–C29. Черновики ответов «Implementation decides»: неразделимость — один мьютекс (box) / одна запись лога (group); версии — один uint64-счётчик, старт «1», import/restore — от `-index-base`/заголовка; диск — WAL с намерением батча + fsync файла и каталога, tmp+rename; replay — durable индекс + RAM-кэш, учебный не-durable режим отдельно; листинг — копия под замком; изолированный инстанс — команда старта с подстановками стенда; drain/лимиты парсинга — конечные значения в описании; линейное чтение — подтверждение лидером в пределах `-leader-wait`.
