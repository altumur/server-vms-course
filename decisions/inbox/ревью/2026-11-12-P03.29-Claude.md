## Находки

### Блокирующие: меняют норму

1. **Метка «Scope: production.» сузила обязательность для реализаций.**
   - Где: `spec/03.2-worker.norms.md:56` (R069) и `:60` (R071), перевод `ru/…:50, 52`.
   - Что было: абзац «The common production obligations apply to this owner. Q3: startup presence-lock … finite and cancellable; … refusal code `2` with a reason …» шёл без метки, то есть обязывал любую реализацию.
   - Почему это ошибка: по образцу P/01 (P/01.1-R302 и тот же абзац P/01.1-R149 без метки) пункт без метки обязателен всем, «also when only production acceptance … checks it».
   - Следствие: после правки Q3 и общие обязанности для воркера стали только боевыми, а шаг 2b (R200) по-прежнему требует бюджет без метки. Нормы противоречат друг другу.
   - Как исправить: снять обе метки.
2. **`restarting(id)` потерял «false во всех прочих случаях».**
   - Где: `spec/03.1-worker.norms.md:162` (R024), перевод тоже.
   - Что было: «true when … restart … on a growth of `revision`; outside it — at removal, a move and a stop of the worker — false».
   - Что стало: R024 называет false только для трёх перечисленных случаев.
   - Сценарий: `stop_unit` из-за отсечения, потери аренды или смены `born` не покрыт ни одним правилом.
3. **Запрет держать открытое значение секрета стал утверждением о конверте.**
   - Где: `spec/03.5-worker.norms.md:186` (R035), перевод тоже.
   - Что было: «in memory, the heartbeat and logs — the envelope», то есть открытого значения там нет.
   - Что стало: «retains the unit-secret envelope in memory and uses the envelope in the heartbeat and logs».
   - Следствие: запрета на открытый текст в памяти и журнале больше нет.
4. **Процентное кодирование ключа попало в пункт про `bool`.**
   - Где: `spec/03.6-worker.norms.md:438` (R089) и `:456` (R092), перевод тоже.
   - Что было: «… string, url — as is; int …; bool — true | false), then every UTF-8 byte … — %XX». «Then» относилось ко всем типам.
   - Что стало: R089 говорит «For `string` and `url`, this notation is the value as is», а %XX стоит только в R092 после `bool`.
   - Сценарий: строка `a-b` даёт `C-a-b` вместо `C-a%2Db`, и разные значения могут совпасть (R094).
5. **R059 и R060 потеряли условие `keep: true`.**
   - Где: `spec/03.7-worker.norms.md:322` (R059) и `:328` (R060), перевод тоже.
   - Что было: оба правила стояли внутри исключения «a kind with `keep: true`».
   - Что стало: «While the worker holds a token with `current`, it does not request another token» читается как общий запрет для любого вида.
6. **Условие strict стало двусмысленным.**
   - Где: `spec/03.2-worker.norms.md:206` (R258), перевод тоже.
   - Что было: «otherwise the place is foreign or of any box — with places.lease: strict it is held only within the window».
   - Что стало: «A foreign place or a place of any box with places.lease: strict is held only within the strict window» — условие strict читается только при «any box».
   - Сценарий: чужое нестрогое место попадает в строгое окно, а это противоречит R239.
   - Как исправить: «When places.lease is strict, …».
7. **Часть правила о таблицах воркера отделена от исключения.**
   - Где: `spec/03.4-worker.norms.md:796` (R183).
   - Что было: «the writer — the console; a table from worker.writes … is a worker table …: the worker writes the row whole».
   - Что стало: R183 говорит «the writer — the console» без исключения.
   - Следствие: R185–R188 (DELETE, PUT, «пишет заново») потеряли подлежащее «таблица воркера».
