# Ревью дополнения (18) к ADR-0119, Codex

Срез `origin/main` **5a25d371a**. Проверен текст (18) с действующими P/08.4 Н1.2а и Н1.10, договором сторожевой `verify`, отчётом **88680709b** и границами модели `cammeta-quint` **2a9d59f05**. Нового прогона модели не было: `plat_to=17`, перенос (18) в нормы ещё не выполнен.

**Счёт: Б 0, С 0, М 1.**

По смыслу Б1 закрывается: незавершённая проверка занимает место сразу в трёх бюджетах, допуск и резервирование атомарны; второй запрос при 4+1/19+1/9+1 не проходит в PBKDF2. `Retry-After: 1` задаёт определённый ответ для ограничения незавершёнными проверками, у которых ещё нет старейшего `401`. Остальные правила выбора ключа из (16) сохраняются: сначала вычисляется срок каждого сработавшего ключа, затем выбирается максимальный, при равенстве — `pair`, `name`, `author`.

## М1. Для `409 deposed` освобождение резерва не названо

**Место:** (18), п. 1, строка 159, перечисление исходов.

**Цитата решения:** «`401` — резерв становится отказом с временем; `200`, `503`, обрыв или тайм-аут — резерв снимается».

**Норма для сверки:** P/08.4 Н1.2а `check`, строка 148: «смещённый держатель — `409 deposed`; standby — `503`». `409` также объявлен у `/api/verify` и `/domain/verify`; это не `401` неверной пары и в бюджет не входит.

**Проблема:** решение не определяет завершение уже созданного резерва, если обработка заканчивается `409`. Если этот отказ судится до допуска, резерва ещё нет; если смещение выявлено после допуска, оставлять его занятым нельзя. Перечень очистки лучше не связывать только с двумя кодами ответа.

**Предложение:** при переносе в нормы записать общее правило: после созданного резерва только `401` неверной пары превращает его в отказ; любой иной окончательный исход, включая `409`, освобождает его без учёта неудачи. Проверки формы и допуска до резервирования ничего не освобождают, потому что ничего не заняли. Финализация однократная, под тем же замком: преобразование резерва в отказ атомарно с допуском других запросов, а поздний результат после финализации по тайм-ауту не снимает резерв повторно и не учитывает второй исход. Это уточнение жизненного цикла для норм, нового решения не требует.
