**По дополнению (7): Б 0, С 0, М 0. Новых замечаний нет.**

Проверены совместно следующие правила:

- Заголовок надзора присутствует всегда: список подсистем, `-` для отсутствия требования и `*` для неизвестного требования различимы. Отсутствие самого заголовка даёт 503 на `POST /exports`, поэтому сбой передачи не трактуется как разрешение экспорта без надзора. Входящий извне заголовок снимается согласно (6).
- Заголовок и `required` вычисляются одной функцией. При смене копии между передачей запроса и проверкой супервизора окончательный ответ проверки имеет приоритет; backend не объединяет результаты разных снимков собственным расчётом.
- Запись `supervision` отнесена к двери ролей и закрытой схеме; ключ — имя подсистемы, значение — имя роли. Доставка политики и отметок `unreadable` держателем/агентом сохраняет ранее принятое правило: неизвестность не снимает надзор.
- Нечитаемость целой копии не создаёт обхода надзора: заголовок `*`, а проверка не может разрешить экспорт по неполному результату. Правило (6) о 503 целиком и отсутствие частичного успеха сохраняются.
- Предел `VERIFY_UNITS_MAX = 256` и общий с входом потолок из (6) не изменены.

При переносе в нормы диагностическое `supervision.unreadable` из (7) п. 4 нужно сохранить в форме отказа, когда действующие (5)–(6) требуют 503, а не выдавать ради диагностики успешный 200. Это применение уже принятого правила отказа, отдельного дополнения не требует.

Результат относится к тексту решения; изменения схем, доставки и API ещё требуют проверки реализации.
