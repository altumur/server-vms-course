# Ревью текста: ADR-0115 доп. (3) (Claude)

Доп. (3) на origin/main 9e7f0f19f. Сверено с P/02.1 (`tables` по `tableName`, `:306`, `:330`), P/02.5 Н1.4, P/06.1 Н1.6 (дверь таблиц), ADR-0071.

**Счёт: Б 0, С 0, М 2.** Раскладка теперь цельная:
- единица — плагин, один экземпляр, `Configure` — поля `unit`;
- каждый `object_type` — таблица с `ref` на родителя, два корня — две таблицы;
- `readonly` вида — таблица воркера `<т>_seen`, плагина — `unit.state`, моё С1 (2) закрыто;
- события — бакет единицы с полем `object`;
- права — на плагин целиком, предел назван;
- `x_secret` туда и обратно, столкновение — отказ: М1 (2) закрыто.

Платформа меняется только в загрузчике. Только М — в нормы без дополнения.

**М1. Имя `<т>_seen` может не влезть или совпасть.** Генератор делает таблицу `<т>_seen` из имени вида. Нужно назвать два отказа генератора:
- `<т>_seen` длиннее предела `tableName` или в перечне запрещённых имён таблиц (P/02.1 `:330`);
- у плагина уже есть вид, чьё имя после грамматики даёт `<т>_seen`.

Иначе загрузчик откажет манифесту с причиной, которой автор плагина не поймёт.

**М2. `items.ref` — подсказка: запись мимо `backend` ссылку не судит.** П. 5: «ссылку судит `backend` при записи, не общая проверка строки консоли». Дверь таблиц консоли (P/06.1 Н1.6) пишет строки `<т>` и без `backend` — так делает оператор или установщик. Такая запись положит id несуществующего объекта, и плагин получит его в `ChangeUnit`. Назвать пределом: «запись дверью таблиц мимо `backend` ссылки `items.ref` не судит; плагин видит неизвестный id».
