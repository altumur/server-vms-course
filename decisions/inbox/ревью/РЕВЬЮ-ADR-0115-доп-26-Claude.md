# Ревью ADR-0115 доп. (26) (Claude)

main 7a1792cb2. **Счёт: Б 0, С 0, М 2.**

Б «Спецификации VMS» решён верно. Набор обхода у VMS всегда несёт изменённый `backend`, его прежний файл из пакета лежит на каждом сервере, и правило «иной — отказ» не пустило бы обход ни на одном. Защита — хеш оператора: прежний файл заменяют только байты, которые оператор назвал. Проверка прежнего (п. 2) ничего к ней не добавляет. Решение «повтор `<sub>` — провал `@traverse`» совпадает с `rollout`.

Пропуск в моём чтении серии раннера 5a9b63a (bf10fda0a): `manifest_get` стенда отказывает на ином файле. Под прежней нормой это было верно, теперь — нет. Раннеру — правка по (26), это доля стенда.

**М1. Замена набора не атомарна целиком.** Каждый файл переименовывается атомарно, а набор (`yaml`, `shell`, `files`) — по очереди. Обрыв между переименованиями оставит новый `yaml` с прежним `shell`. Это безвредно, если названо: повтор `get` с тем же хешем сводит набор (а `rollout` повторяем, Н1.9 `failure`). Строка в Н1.9: «набор заменяется по файлу; обрыв — повтор `get`». Порядок — `yaml` последним, чтобы `install` не увидел новый `yaml` с прежними `files`.

**М2. Файлы прежней ревизии, которых новая строка не называет.** «Не трогает» верно для чужих файлов `MANIFEST_DIR`. Но файл `files` прежней ревизии этой же подсистемы, снятый новой ревизией, останется рядом с манифестом. Сказать, что он ничего не значит (`install` берёт только названные строкой), или что `get` его не судит — предел.
