| Раздел | Что |

## Новые дыры

### До норм

- **Д-1. Чтение чужого не судится.** Доп. (4) п. 4 говорит «при правке». `GET /domain/<sub>/<rows>`, `GET /domain/grants`, `GET /domain/users` судятся `view` по `domain/grants/domain` (`P/10:137`, Н1.5). Человек с грантами только на кластеры получит 403, домен пуст. Чтение тоже нужно судить, и фильтром: вид выдаётся не целиком, а по кластерам и единицам. В `may` вход `grants` один документ; нужно считать по строке кластера каждой записи.
- **Д-3. Запись роли не вмещается в пакет.** `apply` — один `POST /domain/batch` (`11.8` Н1.5, п. 5), предел `BATCH_WRITES` 64, с ключом 63 (`08.4:612`). Больше 62 кластеров — несколько пакетов: половина кластеров с новой ролью, половина со старой, отказ посередине. Кроме того, `ROLES_TABLE_MAX` судится на каждого члена: один может отказать всем.
- **Д-5. Общие папки ломают пару «папка + членство».** `platform/folders/<id>` и `platform/memberof/…` «всегда пишет один пакет», это одно хранилище (`P/06.8`). Папка на домене, строка единицы на члене: пакета нет. Сторожевая члена считает `folder:` по цепочкам из своего хранилища: нужна копия папок у каждого члена, и она должна работать без связи. Что без связи: правка папки — отказ или расходится? `FOLDERS_MEMBERS_MAX` 1000, строка 65536 байт: на домен это мало. Копия всего дерева у камеры на флеше.
- **Д-6. Id зависит от входа.** Доп. (4) п. 1: своё напрямую, чужое из вида. `device:cam/cameras/7` есть у каждого кластера. П. 3 разрешает подключаться к любому `backend`, значит одна камера должна давать один UUID откуда угодно: имя с кластером для **всех** записей, своих тоже. Моя прошлая строка «своё цело» теперь неверна. `Server.id` так же: `server:<name>` не уникален между кластерами.

### В работе норм

- **Д-2. Суду по цели нужны данные, которых у домена нет.** У члена право считают `rights.routes`, `reach.group`, `reach.cluster`, `unit_of`, `names`, `body_unit`, `about`, цепочки. `may` у домена получит грант цели, но таблицы (`child_settings`, `device_units`, `volumes`) в вид не входят, цепочки тем более. Иначе дверь домена будет грубее консоли: другие ответы на одну правку через разные входы.
- **Д-4. Новому кластеру не из чего рассылать.** Строки роли лежат только в `domain/grants/<член>`, общего источника нет (`08.4:233`). Копировать с соседнего нельзя: они расходятся. Нужна новая строка «права роли на домен». Тогда правка гранта на странице консоли кластера расходится с ней: какой приоритет? `objectAccess` на камеру другого кластера расходиться не должен: «на все кластеры» верно только для `global`.
- **Д-7. Состояние `backend` — у входа.** `repeats`, `undo`, `history`, операции живут в кластере входа. Подключились к другому `backend`: операции не видно, откат другой, тот же `idempotencyKey` исполнится второй раз. Либо consolem привязан к одному входу, либо это предел. Откат ADR-0106 чужой записи идёт хранимой правкой: значения `after` из вида с задержкой.
- **Д-8. Вход закрыт человеку с правом только в чужом кластере.** `need` второго вида — «любой грант кластера» входа. Человек с `unit:` на кластере B, вошедший через A: 403, хотя это его домен. Доп. (4) п. 3 обещает любой вход.
- **Д-9. `backend` на камере.** Записка `9045412` говорила «места под `backend` на камере нет», памяти и флеша в нормах нет. `history`, `undo`, `repeats`, каталоги `device-catalog.json` — записи на флеш, а V/01.6 считает перезапись износом. Вид домена целиком идёт через канал камеры. Замер обязателен до нормы. V/09 камеру не описывает вообще.
- **Д-10. «Через ретранслятор нет» шире камеры.** `400 one hop` и `CLUSTERS` (`forwarding.md:41`) действуют на любой член с `via` или `star`. Кластер за ретранслятором тоже не увидит домен. Доп. (4) п. 3 говорит только о камере.
- **Д-11. Потеря связи: «скрыто» против ленты.** Чужое исчезает. `entity.deleted` слать нельзя, не слать — WebUI держит старое, что доп. (2) п. 2 и запрещает. Нужен отдельный сигнал контракта, вопрос к consolem.
- **Д-12. `MEMBERS_MAX` 500** остаётся, ADR это назвал. Поэтому цель «тысячи камер» этими строками не достигается.

Остаётся открытым с прошлого разбора: ответ `PATCH` молчащей коробке, дверь отмены хранимой правки, связка правок одного устройства, id при создании, путь секрета. Цена в таблице есть, решений нет.
