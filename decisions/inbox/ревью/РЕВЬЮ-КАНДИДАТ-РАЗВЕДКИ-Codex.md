### Б1. Объявленная Raft-группа заменена общим файлом рядом с комплектами сертификатов

**Код:** `acceptance.yaml:14` объявляет `store_build: raft`. `internal/daemon/group.go:95–120` выбирает корень `Abs(Dir(cfg.TLS))` и общие `.configstore-group.json/.lock`; `withJournal:201–230` читает этот файл под `flock`. `liveMembers:329` определяет живых участников по mtime файлов heartbeat в том же каталоге; `leaderLocked:345` выбирает первый отсортированный id. `initializeJournal:143` добавляет участника в этот же файл; `startupJoin:475` также только переписывает локальный журнал. `apply:386–417` применяет запись через новый локальный core и заменяет файл. Raft-слушатель в `group_tls.go:193–214` выполняет TLS handshake и закрывает соединение: обмена журналом в нём нет.

**Основание:** ce8 `Platform/01-store/spec/01.3-store.norms.md`, N1.3/R006: `group.join`, `batch` — одна Raft-запись с применением на всех серверах, `admission` — в журнале/снимке, `door` — пересылка лидеру; N1.3 `box` отдельно задаёт отказ групповых флагов для сборки без Raft. P/01.1 «Implementation decides», п. 1 требует журнал консенсуса для группы. Это уже нормы ce8; новый пин библиотеки не используется как основание.

**Статический контрпример:** три корректно настроенных сервера имеют каждый свой локальный каталог комплектов сертификатов и доступны по API/RAFT. На первом `-bootstrap -group-size 3`, на остальных `-join <api первого> -group-size 3`. В каждом локальном каталоге появляется собственный журнал только с местным участником. `startupJoin` не связывается с указанным партнёром; TLS Raft-соединение не переносит состояние. `quorumLocked` видит один местный heartbeat вместо двух необходимых. Сборка не может сформировать заявленную группу из этих серверов. Общий каталог на одном хосте способен скрыть этот разрыв, но он не является межсерверным консенсусом.

**Следствие:** групповые ответы через общий файл не доказывают Raft, перенос записи или сохранение свойств при разделении серверов. Это архитектурная подмена механизма, не найденная ветка по имени сценария. Сколько исторических шагов изменило бы исход, не установлено.

**Минимальная рекомендация:** реализовать заявленную сетевую группу с реплицируемым журналом и пересылкой либо честно объявить сборку `box` и соблюдать её отказы. Не засчитывать текущую групповую ветку как доказательство Raft.

### С2. Допустимая длительность `-leader-wait 2s` ведёт к выходу за границу строки

**Код:** `internal/daemon/flags.go:343–347` передаёт флаг в `parseDuration:582–610`. Регулярное выражение на строке 83 принимает `2s`. На строке 587 берутся всегда последние **два** символа; ветки `"s"/"m"/"h"` недостижимы для таких значений. Единица остаётся миллисекундой. На строке 597 вычисляется `value[:len(value)-len(unit.String())]`: для `2s` это отрицательная верхняя граница, потому что `time.Millisecond.String()` — `1ms`. Неиспользуемость переменной `digits` не устраняет вычисление среза. Для более длинного `20s` тот же код оставляет единицу ms и возвращает 20 ms вместо 20 s.

**Основание:** ce8 `01.3-store.norms.md`, N1.3/R007 и R031; `forms/daemon-flags.tsv`, строка `-leader-wait`: duration допускает `[1-9][0-9]*(ms|s|m|h)`. Вход с явными корректными `-dir`, `-id` и `-leader-wait 2s` достигает этого разбора до старта сети. Дефолт 5 s задаётся напрямую на строке 209, поэтому успешный запуск без явного флага эту ветку не проверяет.

**Следствие:** нормативно допустимый флаг не проходит обычный разбор; значение с односимвольной единицей либо вызывает panic, либо разбирается с неверной единицей. Это статическое следствие строк, не зарегистрированное здесь падение процесса. Отдельно, чтение присваивания `Config.LeaderWait` не доказывает реализацию самого тайм-аута группы.

**Минимальная рекомендация:** выделить фактический суффикс до числового разбора, удалить ошибочный срез и проверить безопасное преобразование длительности. Исправление здесь не выполнялось.

## Покрытие чтения и ограничения доказательства

Полностью прочитаны **26 производственных Go-файлов, 8071 строка**: все пять `cmd/*/main.go`, `internal/core/{core,durable}.go`, все 15 файлов `internal/daemon/*.go`, `internal/{model,rights,jcs,jsonx}`. Подробный список, SHA-256, числа строк, импорты и объявления функций — `PRODUCTION-COVERAGE.json`. Это текстовый разбор; Go AST, компилятор и линтер не запускались. Сырые хеши не названы AST-хешами.

Прочитаны декларации assembly/acceptance/SPEC_VERSION/go.mod и архитектурное описание, NOTES/PLAN, два вспомогательных shell-скрипта только как текст; go.sum зафиксирован по байтам. Ни shell-скрипты, ни их команды не выполнялись. В производственном замыкании импортов есть только стандартная библиотека Go и шесть локальных `internal`-пакетов. Внешние модули из go.mod не импортируются этими исходниками; их реализации и toolchain не исследованы. Три прочитанных `_test.go` служат только доказательством отделения тестовых таблиц от производственного пути; прочие тесты и их данные не проверены.

Source прочитан точечно: оба seams.tsv полностью, права/JCS README и нужные части wire, таблицы стадий/флагов, профиль write-checks и необходимые нормы admission/group/import/flags. Полные извлечённые файлы и Git mode/blob/size/SHA записаны до смыслового чтения в `GIT-IDENTITIES.jsonl`. Наличие полного снимка длинной нормы не означает полного аудита всех её положений. Полный wire.tsv не изучался: выбраны только строки P/01. Не читались приватные ключи, env, runtime/logs, `.git` кандидата, `.smoke`, `.repro*`, содержимое копий раннера/источника, текущие peer-отчёты и архивы модели.

Первый родительский поиск имён файлов показал также имена `.git` и файлов ключей в `.smoke`/`.repro*`: исключающий glob при абсолютном корне оказался слишком широким. Все исполнения кандидата, сборки, тесты, пробы, импорты проекта и диагностика Go/native: **0**. Все контрпримеры: **STATIC / NOT_EXECUTED**. Новых semantic kills: **0**. Несколько начальных утилит чтения собственных файлов свидетельства отражены в tool transcript, но не в CALLS; это не запуск или пропущенная ошибка кандидата.
