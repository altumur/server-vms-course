## М

**М1. ETag `/kinds` — по `served`, а тело — по `rev`.** P/06.5: «ETag `/kinds` у `backend` — набор **served** этих ответов». Но `manifest` в ответе — канонический вид строки, «прочитанной при запросе», то есть ревизии `rev`. Между `put` и перезапуском консоли `backend` строит `/kinds` из `rev` N+1 и помечает его ETag из `served` N. Тогда два разных тела ходят под одним ETag: клиент с кэшем N получит 304 и не узнает про N+1, пока консоль не перезапустится. Источник ETag должен совпадать с источником тела: либо ETag по `rev`, а `served` — только для ожидания установки, либо `backend` строит `/kinds` по `served` и не берёт вид новее него. Записать одно.
