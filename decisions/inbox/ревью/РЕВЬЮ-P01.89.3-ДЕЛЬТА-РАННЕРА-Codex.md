## Флаги и пути: закрытые границы

## Inventory, Git-root и paired route

Новый guard стоит **только в неактивном маршруте** `c_vector_packages.tables:221–229`. Он сравнивает realpath root с `git rev-parse --show-toplevel`; ошибка Git или несовпадение даёт `RunnerError`. Symlink root к собственному checkout допускается через realpath. Собственные проверки прошли для обычного checkout с пробелом/Unicode/апострофом, symlink, отдельного Git worktree с `.git`-файлом. Удаление опубликованного `mask_in.tsv` не сокращает список. Отсутствующий root, не-репозиторий и bare без выбранного private context дают ошибку, не успешный пустой inventory. Ошибка последующего `ls-tree` отдельно даёт ошибку раннера.

Собственный опыт со старой базой во вложенном export **вернул обе таблицы**, а не уменьшил список. Поэтому потеря таблиц именно на этом nested примере не воспроизведена. Контроль с именем `test_nested_foreign_checkout_is_not_silently_narrowed` фактически проверяет отказ чужого root; его имя само по себе не доказывает narrowing. Подтверждено более узкое изменение: прежде root использовал metadata внешнего enclosing Git без отказа, теперь такой вход остановлен. В сценарии после guard настоящий script mode тоже дал нужный отказ; перед отрицательным входом тот же код прочитал обе таблицы из нормального root.

Активный маршрут остаётся на строках 218–220 и вообще не выполняет checkout-root guard. `source_git.active/metadata_git/read_context` и весь `reader_runtime.py` побайтно одинаковы с базой. `metadata_git:48–59` требует точный tree и читает явно выбранный repo/pin; `read_context:30–45` возвращает прежний ContextVar в finally. `reader_runtime.execute_bound:269–272` читает выбранные строки внутри judge context; продолжение сохранения координат и accounting этим diff не менялось. Нет force-checkout и объединения источников.

В отдельном собственном контроле использован настоящий bare Git из двух собственных коммитов и два дерева без `.git`: выбранный J pin с поздней таблицей и M pin без неё. Исполнены реальные `read_context`, `active`, `metadata_git` и Git-чтение; root guard не навязан bare/archive metadata route. Физический файл в M не добавлен к отсутствующей в выбранном pin таблице; чужой root даёт `PairError`, после нормального и аварийного выхода контекст сброшен. **Происхождение pair здесь подменено**: `fresh_pair/parse` возвращали явно объявленную собственную фикстуру, чтобы проверить маршрутизацию. Реестр/квалификация private pair не исполнялись и не считаются PASS. Существующие строгие проверки типа/идентичности происхождения отдельно сохранены в неизменённом исходнике.

Перехват `ModuleNotFoundError` по-прежнему ограничен отсутствием самого пакета `runner`: новая авторская проверка отсутствующей внутренней зависимости успешно подтвердила её распространение. Для ошибок Git и собственного script-контроля подставлен только точный класс `c_targets.RunnerError`, извлечённый из текущего AST; broad `c_targets` не импортировался. Это предел полноты import-цепочки, а не ослабление production-кода. Авторский новый foreign-root метод с полной импортной цепочкой отдельно NOTEXEC; его цель проверена собственным ограниченным script-контролем.
