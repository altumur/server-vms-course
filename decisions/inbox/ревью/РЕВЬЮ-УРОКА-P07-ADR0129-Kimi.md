Предмет: урок P/07 (модуль консоли) по ADR-0129, **только пункт (а)** — места
догадок и двусмысленности нормы (доля поручения). Читался английский источник
`Platform/07-console-module/spec/` (norms 342 строки, README 70 строк); ru/ не
читался. Для проверки ссылок читались P/06.8 (правила If-Match папок и batch

Код и нормы не правились — только чтение.

**Итог: Б 0 / С 2 / М 3.**

## (а) Места догадок и двусмысленности нормы

- **А1 (С): противоречие `tree` ↔ `api` по If-Match папок.**
  N1.5 `tree` (строки 147–148): «a rename — one write PUT /folders/<id>
  {name}, with If-Match by index (P/06.8 N2)»; добавление/удаление юнита —
  PUT /folders/<id> {members}. Но N1.5 `api` (строки 87–95): `opts.ifMatch`
  допустим только у закрытого списка дверей (юниты, таблицы подсистем,
  /policy, /drain, /servers/<s>/labels, /schema, /domain/placement/…) —
  `/folders/<id>` в нём нет; «Another path … the call is refused before the
  request»; значение ifMatch — «an integer ≥ 1 (revision)», а у папки
  If-Match — непрозрачная строка индекса в кавычках (P/06.8 N2, строки
  203–204; OpenAPI 6404–6407: число получает «400 If-Match is a unit
  revision»); и прямо: «ifMatch does not carry the index: a page that needs
  the index writes by the batch door with cas». Итого: через `console.api`
  переименование папки с If-Match отказано до запроса дважды (путь не в
  списке, тип значения не тот); единственный согласованный путь — batch door
  с cas (P/06.8, строки 221–223), но `tree` предписывает «одну запись PUT».
  Генератору нужна догадка, какая из двух норм права. Правка нормы: либо
  добавить PUT/DELETE /folders/<id> в список дверей `api` с типом значения
  «индекс в кавычках» (расширение типа ifMatch), либо в `tree` заменить
  запись на batch door с cas (P/06.8 N2).
- **А2 (С): N1.6 `held` — не названы источники и правило сравнения.**
  Строки 194–197: модуль показывает «старая копия», когда пара {term, rev}
  члена «lags behind» паре держателя, и «держатель её больше не обновляет»,
  когда члена нет в `backup_holders`. Но: (1) `GET /api/held` даёт пару
  только этого члена — откуда модуль берёт пару держателя и список
  `backup_holders`, не сказано (они живут в виде /domain: `term.backup`,
  `term.backup_holders` — P/08.8 N1.3, строки 98–100; в норме P/07 это не
  названо); (2) порядок сравнения пар не определён нигде (grep по Platform:
  «старая копия» встречается только в этой строке и её ru-переводе;
  «comparable only by the pair» не говорит, что сравнивается сначала term,
  затем rev). Правка: фраза с источниками (вид /domain, поля term.backup и
  term.backup_holders) и правилом сравнения (term, затем rev).
- **А3 (М): двойное правило для отказа 412 в N1.5 `forms`.**
  Первый абзац (строки 104–108): отказ 400, 409, 412 с полем `field` тела
  показывается у поля формы. Абзац unitForm (строки 109–111): «The refusal
  412 — a screen instead of the text: in .pc-err the words W.rowMoved…».
  412 папки несёт `field: "/index"` (P/06.8, строка 204), 412 юнита несёт
  `body.row`; по первому правилу модуль искал бы элемент формы «index», по
  второму — рисовал экран. Приоритет не задан. Правка фразой: 412 с
  `body.row` — экран `W.rowMoved`; прочие отказы с `field` — у поля.
- **А4 (М): N1.4 `changes` — «at most once a second» без привязки.**
  Строка 56–57: «then holds the request /changes?after=<number>&wait=15, at
  most once a second». Запрос уже держится 15 с (`wait=15`); что ограничено
  разом в секунду — повторная выдача после немедленного возврата? после
  обрыва? Читается двояко. Правка фразой: «a new request is issued at most
  once a second (after an immediate return or a drop)».
- **А5 (М): дубль списка `objects` между N1.5 и N1.6.**
  N1.5 `objects` (строка 84) уже включает `member:<m>`, `domain`,
  `person:<name>`; N1.6 `objects` (строка 182) повторяет ровно их как поздний
  слой, «введённый уроками 8 и 10». Без конфликта, но утверждение о происхож-
  дении расходится с базовым списком, и читатель не понимает, какой список
  канон. Правка: оставить перечень в одном месте (N1.6 — ссылкой, или из
  N1.5 убрать доменные refs).

## Что проверено и сходится (в пределах п. (а))

  `record.md`, `forwarding.md` существуют; «the name of a platform door
  (P/02.1 N1.2a)» — отсылка к нормативному списку, не догадка.

  (строки 64–65).

  с N4 (отсылками к P/06.1).

  не покрытие нормой, а записанная зависимость; для линии генерации — ни PASS,
  ни FAIL, что соответствует решению «Архитектора» от 2026-11-05.
