## 1. Замечания к самим требованиям

Нового решения вне ADR для этого ревью не требуется. Т2 применяется в редакции устойчивости: ввод при доле ≤1/5, снятие существующего при доле >1/2; меньше трёх смысловых эпизодов — недостаточно данных. LOC служит справкой. Один эпизод с несколькими коммитами/файлами не превращается в несколько независимых правок.

Критерий дополнения (12) применён также к положительным векторам и машинным носителям, а не только к словам «legacy». Повреждённые данные по-прежнему требуют отрицательных проверок существующего `unreadable`. Это не основание удалять проверки неверного `gen`, `born`, времени или просроченной аренды. Версии хранилища остаются непрозрачными строками: точное копирование индекса вне binary64/int64 не является поддержкой старого формата.

Ошибку судьи отделяю от ошибки спецификации по `skills/lesson-spec/references/review-checklist.md`: ниже J1–J2, отдельная будущая поставка через coord103. Статический контрпример учёту мутантов не называется фактически исполненным мутантом.

## 2. Существенные находки к спецификации

### С1. Чтение поколений и эпох шире нынешней записи

Адреса: `Platform/03-worker/spec/03.2-worker.norms.md:143` — **P/03.2-R011**; `:483` — **R032**; `Platform/03-worker/forms/slot-capture.tsv:16`; `Platform/03-worker/forms/README.md:87`; `Platform/03-worker/data/epoch.schema.json:5` и `:821`; `Platform/03-worker/acceptance/2/seams.tsv:25`; `Platform/common/vectors/family-read/03.tsv:308`–309, случаи **03-0307/03-0308**. Основание — ADR-0129 (12) пп. 1–4.

R011 прямо требует принимать читаемые целые вне int64, затем выделяет `generation_exhausted` вместо нечитаемой строки. У `epoch` границы 1…2^53−1 находятся только в `$defs.writer`, тогда как reader-schema принимает, в частности, существующий `epoch = 2^53`. Корпус подтверждает расхождение: один и тот же текст `{"epoch":"9007199254740992"}` отвергается писателем и положительно принимается читателем. Швы требуют `gen_readable:true` для значения выше максимума; это не проверка исхода unreadable.

Минимальный контрпример: иначе корректная существующая строка с `gen = 9007199254740992`, свободная либо с точным разрешением захвата. Нынешний писатель такую строку не выпускает. Старые правила отправляют её в специальную ветвь исчерпания и сохраняют читаемой. Новое общее правило требует существующий исход нечитаемого поколения. Аналогичный свидетель — существующая строка эпохи с числом 2^53; отсутствие строки, которому соответствует начальный ноль, — другой вход.

Предложение: согласовать пределы чтения/записи в норме, schema/codec, машинных входах и ожиданиях соответствующих векторов/швов; не сужать число лишь при преобразовании в int. **Допустимый максимум 2^53−1 сохранить:** он читаем, хотя следующую генерацию/эпоху уже нельзя выдать. Убрать только положительный профиль сверх предела; отрицательные проверки повреждения и сохранности строки оставить. Изменение общих носителей согласовать с их владельцами, не подменять новым отказом или миграцией.

Доказательство: исходные нормативные строки и ожидания; дополнительно read-only проба стандартных JSON Schema keywords показала reader-accept/writer-reject для `epoch = 0` и 2^53. Это не исполнение полного family-reader с его codec/layers и не SDK.

### С2. Отсутствующий `born` превращается в действительную пустую жизнь

Адреса: `Platform/common/contracts/row-check.md:33`–36 — договор, импортированный **P/03.3-R008**, **P/03.6-R018/R029**; `Platform/03-worker/forms/row-write-bindings.md:19`; `Platform/03-worker/data/state.schema.json:5`–8; `Platform/common/vectors/family-read/03.tsv:2`–3, **03-0001/03-0002**. Основание — ADR-0129 (12).

Общий договор устанавливает `born` как 32 lowercase hex при каждом нынешнем создании, но отдельно сохраняет жизнь `""` для строки, созданной «before this norm». Форма accepted-start требует передавать пустой born при отсутствии; схема разрешает его и писателю состояния. Оба базовых вектора положительны с `born:""`. Это действующая совместимость, а не историческая справка.

Минимальный контрпример: строка единицы с id/revision, но без `born`, и состояние с `born:""`. По старому правилу они могут обозначать одну жизнь и давать действующее состояние; конструктор учит выпускать такой штамп. У нынешних создателей отсутствующего `born` нет.

Предложение: снять положительную пустую жизнь и преобразование «нет born → пустая строка» из действующего контракта/формы/схемы/корпуса. Сохранить существующие отрицательные исходы нечитаемой единицы/недействующего состояния, положительный случай с полноценным born и независимый шов **s5-state-start-born**. Не дописывать born старой строке, не вводить миграцию. Согласовать с владельцем общего row-check.

Связанное тестовое ожидание `tools/normgen/test_gen_row_writes.py:254` (`test_exact_versions_integers_and_empty_born`) — следствие нормы: его совместимую часть менять после источника. Проверку точных строк индексов сохранять отдельно.

### С3. Для пустого сервера требуется положительная ветвь, недостижимая нынешним запуском

Адреса: `Platform/03-worker/spec/03.4-worker.norms.md:78` — **P/03.4-R006**, `:161` — **R007**; `Platform/03-worker/spec/03.2-worker.norms.md:103` — **P/03.2-R008**; `Platform/03-worker/acceptance/2/README.md:205`; `Platform/03-worker/acceptance/4/README.md:74`; `Platform/03-worker/forms/daemon-flags.tsv:16`. Основание — ADR-0129 (12).

Норма сама говорит: `server:""` — только reader tolerance; нынешний воркер с пустым SERVER_NAME отказывается кодом 2 до presence lock. Одновременно R007 требует продолжать работу под своим слотом с неизвестным сервером, а два README предписывают получить такой работающий процесс, «не задав сервер».

Минимальный контрпример проверки: unset SERVER_NAME даёт short-hostname по форме, а явно пустой — отказ грамматики. Ни один способ не даёт требуемый heartbeat с пустым server, взятым именем и BOX_ID. Подмена готового объекта не является проверкой обычного запуска.

Предложение: убрать из нынешнего положительного профиля совместимую работу неизвестного сервера и зависимые требования `server_unsaid`/«все места strict», согласовав владельцев читателей. Сохранить положительный известный сервер и настоящий отказ пустого/неверного SERVER_NAME до побочных действий. Повреждённую публикацию проверять отрицательно существующим исходом; не создавать обход запуска или новый порт ради старой ветви.

### С4. Именованные числовые уставки не имеют единственного формального источника

Адреса: `Platform/03-worker/spec/03.2-worker.norms.md:58` — **P/03.2-R005**, `:174` — **R014**; `Platform/03-worker/spec/03.3-worker.norms.md:48` — **P/03.3-R005**; `Platform/03-worker/spec/03.4-worker.norms.md:182` — **P/03.4-R010**, `:227` — **R014**; `Platform/03-worker/forms/slot-capture.tsv:23` и `:37`. Основание — ADR-0129 (2) п. 4, (5) п. 1.

В P/03 нет `forms/runtime-constants.tsv`. Собственные именованные LEASE_TTL/MARGIN, CONTEND_EVERY, HEARTBEAT_EVERY, RETRY_MIN/MAX, BEAT_EVERY и дверные пределы заданы внутри прозы/fences. Значения повторены в выводах и действиях: TTL/MARGIN и окно 25; TORN_STILL=50 в машине при общем договоре срока; `wall + 45.0` в нескольких переходах. У общих SLOT_TERM/FOR/LOST_AFTER уже есть источники — их копия не становится ещё одной независимой константой. Действующий `check_constants.py` содержит предметные связи P/01/P/06/P/08, но не эти P/03 связи.

Минимальный контрпример сопровождению: меняется SLOT_TERM общего договора или LEASE_TTL в главе; выбранный машиной `wall + 45.0`/повторённое окно остаётся прежним, при этом каждый локальный носитель по своей грамматике корректен. Равенство не доказано простым совпадением чисел сейчас.

Предложение: свои конечные числовые уставки объявить существующим классом runtime-constants; общие — точными ссылками на владельца. Производные сроки описать через имена источников и прежние формулы, не менять их смысл округлением и не вводить новую DSL. Там, где тому же значению необходим второй машинный носитель, явно назвать пару и проверять равенство. Проза сохраняет причины, порядок и действия. Граничные числа в независимых тестовых примерах не считаются производственными дублями и не удаляются.

### С5. `lifecycle.md` ведёт второй реестр defaults процесса

Адреса: `Platform/03-worker/lifecycle.md:34`–50; `Platform/03-worker/forms/daemon-flags.tsv:19`, `:28`, `:31`, `:33`, `:35`. Связанные требования — **P/03.2-R037**, **P/03.4-R006**, **P/03.7-R009**. Основание — ADR-0129 (2) п. 4; класс уже разобран для других уроков, правило общее.

Форма объявлена описью входов процесса, но lifecycle повторяет значения, например PLATFORM_DIR `/data/platform`, AGENT_TOKEN_DIR `/run/w2c/domainagent`, BUILD `dev`, и производные defaults дверей/окружения. Ссылка в соседнем столбце не устраняет повторённое значение.

Минимальный контрпример — согласованная правка одного default формы без правки таблицы lifecycle: агент получает два текста с разными умолчаниями. Формальная проверка формы не проверяет согласие этой второй таблицы; сейчас значения в примерах совпадают, нового фактического default я не выбираю.

Предложение: lifecycle называет вход, смысл, фазу чтения и ссылку на строку формы/общий договор. Типы, defaults и обязательность в нём не пересказывать. В форме оставить ссылки на действительно внешние/производные правила. Приоритет env-файлов и различие запуска через runner и прямого SDK сохраняются.

### С6. Форма contender не ограничивает время, которое выбирает его политика

Адреса: `Platform/03-worker/spec/03.2-worker.norms.md:37` — **P/03.2-R002**, `:152` — **R012**; `Platform/03-worker/data/contenders.schema.json:37`–41; `Platform/03-worker/forms/contender-writer.machine.yaml:32` и `:41`; `Platform/common/vectors/family-read/03.tsv:720`–723, **03-0719…03-0722**. Общий договор — **P/01.1-R006…R011**.

Политика получает Unix wall-clock seconds и выдаёт `since`/`at`, а исходный текст называет их моментами входа в состояние/записи. Но в описи Time оба поля отсутствуют. В schema у них один description с прямой оговоркой «form of the time is not named», без типа/codec/ref. Корпус положительно принимает даже `{"since":"x"}` и `{"at":"x"}` в writer/reader. Таким образом, обычный family judge не выражает общий договор времени в этих полях.

Минимальный контрпример: иначе правильная свежая contender-публикация со строкой `at:"x"` или `since:[]`. Нынешняя политика таких значений не выдаёт; машинная форма их не запрещает, хотя общий договор времени запрещает. Нельзя считать отсутствие отказа схемы доказательством корректной метки. Freshness по версии не определяет тип отображаемого времени и не заменяет эту проверку.

Предложение: явно добавить оба поля в опись Time, связать форму с существующим общим типом времени и согласовать reader/writer по нынешнему правилу ADR-0129 (12). Уточнить обязательность полей полного публикуемого объекта; сохранить правило `since` внутри состояния и независимость freshness от часов писателя. Положительные wall-clock соседи и отрицательные неверный тип/нотация должны проверять именно эти поля, а не точную копию JSON IR политики.

## 4. Отдельные дефекты судей: не входят в Б/С/М спецификации

### J1 [С]. `test_gen_machine` засчитывает ошибки проверки как killed

`tools/normgen/test_gen_machine.py:437`–449, `MachineTests.test_mutants`; предмет — выборщик переходов **P/03.2-R022/R024**, общий класс также используется P/04. Основание — ADR-0129 (11) п. 7.

После отличия мутанта по независимому CEL-оракулу любой nonzero генератора увеличивает killed и завершает проверку этого мутанта. Причина не проверяется: комментарий «затенённая строка» не доказывает, что это именно отказ грамматики. После успешной генерации любой nonzero `go test` тоже засчитывается, без проверки штатного исполнения именованного полного отчёта.

Минимальный контрпример пути проверки: генератор возвращает I/O error для каждого неравносильного мутанта; killed растёт, и итоговый порог числа убийств может выполниться. Вторая ветвь — компиляционная ошибка после изменения формы, за которой следуют `returncode != 0` и killed++. Смысловой неверный результат в обоих случаях не наблюдался.

Предложение отдельной задачи: ожидаемое отклонение невалидной формы учитывать отдельно; ошибки генерации/сборки/старта/разбора/неполного отчёта — checking ERROR. Kill — после штатного исполнения полного ожидаемого набора и именованного смыслового расхождения. Оригинал/валидные соседи и ошибки среды проверять независимо. **В этом ревью Go и реальные мутанты не запускались; число реально убитых мутантов не установлено.**

### J2 [С]. Неполные ответы обходят независимое сравнение машин

`tools/normgen/test_gen_machine.py:267`–299 (`Judge.step`, `disagreements`), `:397`; `tools/normgen/test_gen_policy_machines.py:81`–85, `:136`–138. Требования, которые призваны судить эти проверки: **P/03.2-R022**, **P/03.2-R012/R047**, **P/03.7-R009**.

Оба драйвера требуют code 0 и разбирают имеющиеся строки stdout, но не требуют одну строку на каждый вход. Сравнение через `zip(cases, got)` / `zip(results, expected)` отбрасывает хвост. При нормальном code 0 и пустом stdout `disagreements` возвращает пустой список, а цикл независимого policy-сравнения вообще не делает утверждений. Частичный отчёт сравнивает только префикс. Наличие отдельно прошедших declared traces не доказывает исполнения случайных/граничных запросов другого метода.

Предложение: до смыслового сравнения требовать полную ожидаемую кардинальность и идентичность результатов, отвергать пропуск, лишний, дубликат и нулевой отчёт. Эти исходы — ошибки проверки, не успешный оракул и не killed mutant. Сравнение каждого исхода независимым оракулом сохранить. Доказательство здесь по потоку существующего кода; ни драйвер, ни модель не исполнялись.

Положительная граница: `test_gen_row_writes.py:232`–243 уже проверяет число ответов, panic/harness_error; compile-error там явно назван ошибкой проверки. Его семь семантических мутаций доходят по коду до скомпилированного executable и сравнения. Это оценка конструкции судьи, **не новый результат его запуска**.
