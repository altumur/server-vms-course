**М1. Барьер хранилища стенда — только права.** P/02.4 Н1.9 `barrier` для голосующего: `/v1/rights` ≡ файлу, `leader_id` равен лидеру, `applied` ≥ `commit`. У стенда один член: после перезапуска `/v1/rights` admin.sock может ответить раньше, чем член станет `Leader`. Тогда сверка консоли и подъём контроллеров пойдут в хранилище, которое ещё не пишет. Добавить в `barrier()` `GET /v1/status`: `state` `Leader`, `applied` ≥ `commit`.

**М2. Нечитаемый файл прав — сразу отказ, а не перезапуск.** В `traverse_rights` `ValueError` у `json.loads` даёт `new = old = None`. Дальше идут копия, перезапуск хранилища и 300 с ожидания барьера, который не сойдётся никогда (`new is None`). Нечитаемый кандидат (вывод команды прав) — отказ шага сразу с причиной. Нечитаемый прежний — тоже отказ.

**М3. Консоль перезапускается раньше, чем велит норма.** P/02.4 Н1.9 `steps` 4: если каждый `<sub>` набора отвечает (не `404`), консоль подхватит ревизию по метке сама — ждать барьер; перезапуск только при `404`. `traverse_console` перезапускает при первой же неудаче (в том числе `served` ≠ `rev`, пока метка ещё в пути). На стенде это безвредно, но так приёмка не проверяет путь «по метке без перезапуска», которым V/12.4 Н1.5 переключает плагин. Сделать как в норме: ответы есть — `traverse_wait` без перезапуска, `404` у хоть одного — перезапуск и барьер.
