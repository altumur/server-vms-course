# Ревью ADR-0119 доп. (9) (Claude)

main 7a5f0e917. Сверено с договором сторожевой «Надзор» (`required`, `header`, `limit`), P/06.1 Н1.6 `service`, Н2 «Пакетная дверь», «Двери тел и таблиц», P/06.3 Н1.9 `calls`, договором сторожевой (аварийный вход `w2c_glass`), V/11.8 Н1.5, Н1.6.

**Счёт: Б 0, С 3, М 2.**

Направление верное: надзор судится там, где пишется строка, а билет `backend` остаётся единственным путём для автора, которому надзор нужен. Так Б1 закрыт для любой подсистемы, а не только для `exp`. Модель Quint не нужна.

## С

**С1. «Только по билету подсистемы, который прошёл проверку» — непонятно, чей это билет и что консоль сверяет.**
- Части `exp` пишет `backend`, а не `exp`. Если читать «билет подсистемы» как билет подсистемы `s`, `backend` запись не пройдёт.
- «Прошёл проверку» консоль проверить не может. Звал ли воркер `/domain/verify` и что сделал с ответом — внутри воркера.

Предложение назвать: запись по живому билету воркера, чей закрытый перечень `calls` называет эту дверь записи (P/06.3 Н1.9). Надзор судит воркер по заголовку `X-W2C-Supervision`, консоль только пускает. Тогда видно, кто держит ответственность. Каждый воркер с такой записью в `calls` должен судить заголовок сам — это строка в V/11 и в договоре «Надзор».

**С2. Пока в `unreadable` хоть одна роль или пока копия не дошла (`*`), закрыты все записи строк сеансом. И аварийный вход тоже.**
- По договору `required` = `true` для любой подсистемы при `*`, независимо от человека. Одна испорченная строка роли домена закроет правки строк единиц во всех кластерах. Это раздел `units` модуля P/07 и всякая прямая дверь. Прежний предел (`limit` договора) говорил только о действиях с надзором; теперь стоит всякая прямая запись.
- Хуже с аварийным входом. Сеанс `w2c_glass` нужен, когда домена нет, а копия ролей у новой консоли тогда как раз «не дошла», то есть `*`. Оператор аварийного входа не запишет ни одной строки.

Предложение:
- (а) У аварийного сеанса надзора нет: ролей домена у него нет, а надзор — свойство роли домена. `required` = `false` при `glass: true`, и это тоже строка договора «Надзор».
- (б) Новую цену `*` назвать в `limit`: прямые записи строк всех подсистем стоят, пока строку не починят; чинят дверью ролей домена, её правило не трогает.

**С3. «`supervised_by` пишет только этот путь» платформа исполнить не может.**
- Имени `supervised_by` у платформы нет (доп. (5) п. 1 — без имён VMS). Правило консоли закрывает сеанс только тем, у кого `required`.
- Человек без надзора (`-`) с `edit` на `exp` пишет своим сеансом часть с `supervised_by: <любое имя>`. `export.made` назовёт подтвердившим того, кто не подтверждал. Это подделка следа без обхода права.

Предложение — одно из двух:
- (а) Слово манифеста для поля, которое пишется только по билету (например, `ticket_only: true` у поля единицы, P/02.1, P/06.1). Сеансом поле с этим словом — `403`.
- (б) Назвать пределом: `supervised_by` достоверно только у частей, записанных по билету. Тогда держатель не может отличить одно от другого, и след слабее.

Рекомендую (а). Слово общее, и тем же словом позже закрываются пределы «мимо `backend`» (маска, `EXPORT_TOTAL_MAX`).

## М

**М1. Охват «записи строк».** Назвать, что входит, иначе реализации разойдутся:
- `POST`, `PUT`, `DELETE` строки единицы;
- строка пакета `POST /<sub>/batch` и пакета консоли;
- объявленные таблицы подсистемы;
- просьбы `/<sub>/requests` (`cancel`, `delete` у `exp`).

Отдельно: доп. (5) п. 6 «надзор `exp` судится только при создании». Дверь же отвечает `403` на всякую запись сеанса, в том числе на просьбу `cancel` своей части. Это верно, если всё идёт через `backend`, но стоит сказать прямо.

**М2. `NOT_SUPPORTED` в V/11.8 судить только при смене `supervision`.** V/11.8 Н1.5 судит изменённую запись целиком. Роль, у которой `supervision.exp` уже стоит (записан дверью ролей домена мимо `backend`), снимок показывает с `export: true`. Правка её `comment` или назначений придёт с тем же `export: true`, получит `NOT_SUPPORTED` и до правки P/06.1 станет неправимой. Назвать: `NOT_SUPPORTED` — только когда `supervision` черновика отличается от снимка.
