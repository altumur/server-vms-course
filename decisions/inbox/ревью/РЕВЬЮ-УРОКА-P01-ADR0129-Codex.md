## Замечания к самим требованиям ADR-0129

### С1. Т2 не определяет воспроизводимый способ счёта

**Место:** decisions/0129-минимум-догадок-генератор-не-больше-кода.md:44, Т2; п. 4; tools/normgen/provenance/README.md:26.

**Цитата:** «Новые строки генератора (продюсер, без тестов и пустых строк) не больше строк кода, который он выдаёт, — по `origin-count`».

Origin-count считает физические строки конечного Git-снимка, включая пустые, с происхождением generated/handwritten/model. Он не считает новые строки продюсера относительно базы. Не названы база «новых», импортируемые производители, один выход против суммы уроков и место тестового выхода в знаменателе. Контрпример: flags P/01 содержит **766** непустых generated-строк и **692** строки копируемой ручной среды. Сравнение с продюсером **1036** меняет ответ, если принять шапку Code generated у копий за происхождение. Сумма flags всех checked-in уроков — **3954**: этот знаменатель опять меняет решение.

**Предложение Архитектору:** паспорт Т2 с базовым/конечным SHA, единицей поставки, перечнем производителя и новых зависимостей, перечнем generated-выхода и единым счётом непустых строк. Показывать полный размер и маржинальную дельту, отдельно производственный/тестовый выход, handwritten и судью. Общие зависимости учитывать один раз в названном объёме, не скрывать в wrapper. Для существующего генератора определить, судится ли один урок или весь обслуживаемый набор. До этого числа ниже — материал решения, не автоматическое разрешение удалить пакет.

### (а) Места догадок и двусмысленности — фраза, вектор или шов

#### С2. «State does not change» у replay не отделяет строки от admission metadata

**Место:** Platform/01-store/spec/01.1-store.norms.md:463, R070 (формула R069 выше); :503, R078; :654, R122.

**Цитаты:** «The admission time is part of the store state»; у успешного replay — «return its answer with again=true; the state does not change».

Для in-process/box обе фразы касаются состояния. Пусть A принята при T; часы переведены на T+100, принят её точный replay по id, затем часы возвращены на T. B с not_before=T+50 проходит, если принятый replay продвинул last admission time; получает early, если «state does not change» запрещает менять и метадату. Для отказов R088/R132 уже уточняют это различие, для replay формулировка остаётся шире отсутствия повторной бизнес-записи. Ранний ответ по кэшу без нового допуска нельзя молча смешивать с применением уже принятой записи.

**Предложение Архитектору/spec103:** сузить «state» до строк, выданных версий и прежнего результата/id-записи; для replay, прошедшего admission, явно сохранить R070 о last admission time. Если допускается ответ без нового admission, назвать границу этой ветви. Шов: clock +100 → принятый replay → clock -100 → B; варианты batch и reopen. Это уточнение текста, не форма алгоритма. Происхождение формулировки в истории не установлено.

#### М2. Lifecycle исключает SERVER_NAME из чтений самого демона

**Место:** Platform/01-store/lifecycle.md:24–33; spec/01.3-store.norms.md, R031.

**Цитаты:** «The daemon itself reads only the systemd environment — the passed sockets […] and the watchdog»; «-id outside a group defaults to SERVER_NAME».

Без -id, с SERVER_NAME=box1 перечень «only» подсказывает не читать переменную, а канон и таблица того же lifecycle требуют умолчание. Старшинство разрешает это в пользу R031, но указатель создаёт лишний выбор. **Предложение:** добавить SERVER_NAME к чтениям демона или сослаться на полный перечень без only. Configstore.env по-прежнему читает runner. Происхождение не установлено.

### (в) Формы, дублирующие прозу
