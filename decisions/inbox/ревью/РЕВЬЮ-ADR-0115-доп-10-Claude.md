# Ревью текста: ADR-0115 доп. (10) (Claude)

Доп. (10) на main ef52742b2. Сверено с:
- psim-sdk c3d9ebb `schema/plugin.schema.json` (`source.provider` — `enum: [platform_objects]`, `object_type` — тип `object_types[].type`);
- `security_controller/manifest/plugin.json`;
- `detjob.subsystem.yaml` (`worker.reads`, `requests: [rec]`);
- ADR-0115 доп. (6), (7), (8).

**Счёт: Б 0, С 0, М 3.** Связь по `source` верна. У psim нет имени плагина-владельца: `provider` — только `platform_objects`, тип глобален. Поэтому поиск владельца среди установленных нужен, и отказ при двух — честный. `worker.reads` и `worker.requests` к другой подсистеме уже есть у `detjob` (`requests: [rec]`). П. 2 — решения внутри ADR, возражений нет.

## М

**М1. Владельца нет и владелец второй.**
- Владелец не установлен. Тип из `source` (`CAM` у `security_controller`) назван, плагина камер нет. Установка отказывает или идёт с пустым перечнем? П. 1 говорит только «владелец установлен позже — пересборка». Значит, видимо, идёт — так и записать.
- Второй владелец. Отказ «владельцев двое» при какой установке? Если зависимый уже стоит, а второй плагин `CAM` ставится позже — отказывает установка второго (её `object_type` уже назван чужим `source`)? Назвать.
- Камеры VMS. У VMS свои камеры (`vms.cam`, `implements: [vms.camera/1]`, ADR-0116 (2) п. 6). Становятся ли они владельцем `CAM` для плагинов, или `source` видит только объекты psim? Для продукта это главный случай: контроллер СКУД с камерами VMS. Предел «только объекты psim» стоит назвать.

**М2. События владельца — какой дверью.** «Чтение… событий владельца» (`PullEvents`). `worker.reads` — префиксы хранилища, а журнал событий читается дверями `GET /events` (P/06.4) ресурса или консоли. Назвать путь, которым адаптер читает чужие события: по роли, через какую дверь, с каким правом.

**М3. Запись `enabled` мимо шага — кто запустит сборщик.** П. 3: «сборщик пересобирает и по ревизии строк `plugin`». Сборщик — шаг установки урока, а не постоянный процесс (доп. (6) п. 1, (8) п. 2). Запись `enabled` дверью администратора в произвольный момент его не будит: перечитывание ревизии поможет только следующему запуску. Назвать: пересборку выполнит следующий шаг установки, до него — прежний предел (8) п. 2. Или сборщик — процесс, который следит за строками `plugin`.
