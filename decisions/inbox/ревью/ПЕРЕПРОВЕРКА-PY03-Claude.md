## С-1 — закрыта на основном пути

**Что сделано.** Свой срок слота проверяется до записи эпохи в четырёх местах:
- `gates._check` — второе по порядку ворот, после «я никто»;
- `gates.begin`;
- `epochs.issue`;
- `epochs.ensure`.

Поставщик срока зовётся вне замков (`_term_moment`). Значение — `SlotManager.confirmed_at`, то есть `first_sent`
подтверждённого захвата или продления: момент отправки, как требует Н1.4. После потери имени поставщик отдаёт `None`
(`_lost`), и ворота закрыты.

**Проба P8.** Поставщик отдаёт 0, `begin` на 50 с → `Refusal(reason='NoSlot', detail='own slot term ended')`. Раньше было
`Attempt`. Тесты линии `OwnSlotTermTest` подтверждают то же для `issue` и `ensure`: в журнале хранилища ни одной записи.

**С-1′ (мелкая, остаток).** Два места:
1. **Повтор после конфликта пишет за сроком.** Срок проверяется один раз — до цикла `_issue`. Повтор после `conflict`
   (новые `id` и `t0`, Н3 «взять_эпоху») — это новая запись, и её срок не проверяется.
   - **Проба P9.** Поставщик отдаёт 1000. На 1044 первая запись получает `conflict`, ответ приходит к 1046. Повтор
     пишет на 1046 → `issued`. Моменты записей — `[1044.0, 1046.0]`: вторая — на 46-й секунде своего срока.
   - **Ожидается.** Проверять свой срок перед каждой новой отправкой цикла (`conflict`). Повтор тем же `id` после
     `ambiguous` — та же логическая запись: его можно оставить, но назвать в GUESSES.
2. **Без поставщика срок не проверяется.** Когда поставщика нет, ворота и выдача срок не проверяют (P8b:
   `GateController` без `set_slot_term` → `Attempt`). Поставщик подключает `Worker.__init__`, и только если у `slots`
   есть `confirmed_at`. Сборки процесса, которая создаёт `Worker`, в линии ещё нет — объекты собирают только тесты.
   - **Ожидается.** Сборка процесса обязана передать поставщик: обязательный параметр или отказ при старте. Это
     пункт перепроверки интеграции следующего кандидата — как в исходном отчёте.

## М-5 — не закрыта

**Что сделано.** Добавлено `report_gap`: разрыв между двумя отчётами о работе больше `report_gap` обрывает непрерывность.
Но по умолчанию `report_gap = stable_seconds = RETRY_MAX = 60 с`.

**Почему это не снимает М-5.** Сравнение `moment − last_report > report_gap` строгое. Два отчёта с разрывом ровно 60 с —
или 59 и 60 с — по-прежнему дают «60 с непрерывной работы», хотя между ними не было ни одного наблюдения. Граница 60 с
закрыла только пробу из моего отчёта (61 с), а не дефект. Работу цикл видит один раз за проход: `_apply_words` вызывает
`retry.worked` по статусу каждого прохода, проход идёт с паузой `POLL` около 2 с. Значит, разрыв больше нескольких
проходов уже означает пропущенные наблюдения.

**Проба P3** (пять неудач, затем отчёты о работе):

| отчёты | сброс | `failures` |
|---|---|---|
| 0 и 61 | нет | 5 — исправлено |
| 0 и 60 | **да** | 0 — 60 с тишины засчитаны работой |
| 0, 59, 60 | **да** на 60 | 0 |
| 0, 12,6, 25,2, 37,8, 50,4, 63 (каждый разрыв > `STALL`) | **да** на 63 | 0 |
| каждые 2 с (`POLL`) до 60 | да | 0 — норма, так и должно быть |

**Довод исполнителя** (GUESSES «Часть 10»): «более строгая граница изменила бы три зелёные проверки урока (отчёт через
60 с после отчёта — период продолжается)». Эти три проверки как раз закрепляют дефект: «отчёт через 60 с после отчёта —
период продолжается» и есть «разрыв засчитан работой». Норма (P/03.3 Н1.2 `retry`: «после `RETRY_MAX` **непрерывной**
устойчивой работы») шага отчёта не называет, но «непрерывная» не может значить «два отчёта за 60 с». И сам модуль говорит:
«простои и паузы повтора непрерывность не набирают».

**Ожидается.** Граница разрыва — от шага наблюдения, а не от срока сброса. Мой выбор — `STALL = 12,5 с` (P/03.4 Н1.2
`stand_in.STALL`). Это граница, за которой норма сама считает шаг застрявшим: проход, который не дал отчёта дольше
`STALL`, — не работа. Возможен и `k × POLL`, но `STALL` — число нормы, а не догадка. Три проверки урока с разрывом 60 с —
переписать: период должен начаться заново, а не продолжиться. Если линия хочет число из нормы, а не из соседней главы, —
вопрос «Спецификации» по Н1.2 `retry`: «какой разрыв между наблюдениями работы обрывает непрерывность».
