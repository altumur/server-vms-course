## С1. Существенная ошибка проверки: исходный архив обходит сверку ростера

**Место:** `skills/lesson-spec/scripts/export_lists.py:115`:

```python
if not (root / ".git").exists():
    return None
```

В `roster_coverage` на строках 130–132 это превращается в `return False`. В `assemble` на строках 243–249 остаётся только сравнение множеств M и J друг с другом. Файл common, отсутствующий одновременно в обоих фильтрах, снова не обнаруживается. Новый комментарий называет любое дерево без Git тестовой фикстурой, но таким деревом бывает полный источник курса.

**Сценарий:**

1. Распаковать полный `git archive 3c9f3f8584f734038755f07fe36b1ba09950acea` в собственный каталог без `.git`.
2. Удалить только записи с `path = Platform/common/qualification-input-filter.json` из `Platform/common/export-model-filter.json` и `Platform/common/acceptance/judge-input-filter.json`. Сам файл Q оставить на месте; остальные записи не менять.
3. Запустить в корне этого полного архива:

```sh
/home/pilot/venv-spec/bin/python -B skills/lesson-spec/scripts/check_spec.py --scope platform
```

**Факт:** `assemble` возвращает `errors=[]`, по 3575 записей M и J, без счётчика `export_roster_files`. Полный `check_spec` завершается с кодом 0 за 76.094 с:

```text
PASS structural checks only; semantic review and implementation acceptance remain separate
```

Ожидается отказ по отсутствующей классификации файла в M и J, как в Git-сценарии. Предыдущий и сданный модули одинаково принимают этот архив: дефект был раньше и исправлен только для Git-дерева.

**Источник и последствие:** цель OBSH.58 требует классификации каждого файла Platform в обоих фильтрах. `Platform/common/acceptance/tables.md:26` требует записи для каждого файла, а оператор P02.52 (`decisions/inbox/2026-11-11-P02.52-операторы/operator/b7_export_pair.py:292`) отвергает несовпадение классификации с ростером. Архив — используемый вход, а не гипотетическая фикстура: `decisions/inbox/2026-11-13-P01.299-пара-M8prime-J8prime/scripts/prepare_source.py:23` создаёт `archive-C`, строки 24–25 распаковывают `git archive`, строки 47–55 запускают в нём `check_spec`. Его зелёный результат всё ещё может расходиться с отказом оператора по той же причине, ради которой поставлена OBSH.58.

**Рекомендация:** обеспечить сверку покрытия и для полного исходного архива без `.git`; добавить отрицательный тест этого режима с общим файлом, отсутствующим в обоих фильтрах. Сохранить существующее различение отслеживаемых и неотслеживаемых файлов в Git-дереве.
