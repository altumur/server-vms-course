# Ревью ADR-0115, дополнение (5), Codex

**Счёт по (5): Б 0, С 3, М 0. Общий счёт отчёта: Б 0, С 3, М 0.**

Дополнительно сверены V/11.1 Н1.3, Н1.5, V/11.3, `backend.subsystem.yaml`, P/06.3 Н1.9, P/02.3 Н3, P/06.1 Н1.1 и Н3, договор проверки строки «Подготовка полей», П4 и раскладка P/03.1. Схема psim и пример `security_controller` прочитаны из ранее указанного клона только для чтения.

Прежний Б1 закрыт по выбранному механизму: генератор выдаёт конкретные вызовы, установка меняет манифест backend, происходит перезапуск. Прежние С1 и С2 закрыты: `ref_label`, предел `value_field: id` и пространство имён событий сохраняют необходимые данные. Фиксированный id и исключение создания/удаления вида плагина из общего CRUD закрывают соответствующую часть прежнего С3. Ниже — пробел в новом составе фрагмента вызовов и противоречия новых правил запуска и удаления.

## С1. Во фрагменте `calls` отсутствует строка самой единицы-плагина

**Место:** доп. (5) пп. 1 и 4.

**Цитаты решения:** фрагмент содержит «таблицы видов и `<т>_seen`, `requests`, `where` двери страницы»; «Вид плагина в `/units` — только `GET` и `PATCH`».

**Норма:** V/11.1 Н1.3: «Обратный вызов — только по билету и только на двери закрытого перечня, который объявляет манифест». P/06.3 Н1.9: «дверь вне `calls` на запросе — 401»; строки единиц и таблицы допускаются отдельными записями `<s>/<rows>` и `<s>/<t>`.

**Проблема:** параметры `Configure` теперь лежат в `unit`, а не в таблице вида. Перечисленные в п. 1 вызовы не покрывают `GET`/запись `<s>/<unit.rows>/plugin`. Таким образом, предложенная приёмка объектов может пройти, но страница настроек самого плагина не сможет ни прочитать параметры, ни сохранить их через `PATCH`. Допуск `requests` или `where` не даёт допуска к строке единицы.

**Предложение:** включить `<s>/<unit.rows>` с чтением и записью в обязательный фрагмент генератора; в приёмке отдельно проверить чтение и изменение параметра `Configure` через `/units` по билету. Это уточнение нового фрагмента, а не требование менять выбранный механизм установки.

## С2. Строку с незаданными обязательными параметрами нельзя создать обычной дверью единиц

**Место:** доп. (5) п. 4.

**Цитата решения:** «её строку создаёт установка плагина … Запускается, когда заданы обязательные `parameters` без `default`; до того — `unfit` с именами полей».

**Норма:** P/06.1 Н3, процедура создания, шаг 6: обязательные проверяются по П4, иначе 400 «needs a <поле>». Договор проверки строки, П4: «каждое required-поле передано клиентом и не `""`»; раздел «Подготовка полей»: «Непереданное required-поле по-прежнему даёт отказ П4». Даже подстановка `default` не считается его передачей клиентом. В `plugin.schema.json` у описания параметра нет признака `required`: обязательны ключи самого описателя `type`, `name_key`, `description_key`, а не значение параметра.

**Проблема:** для обещанного состояния «установлен, ожидает заполнения обязательных параметров» не определено представление. Если это `required: true` полей `unit`, создание строки без этих значений будет отвергнуто до размещения и `unfit`; форма с единственным `PATCH` ещё не получит существующего объекта. Если поля необязательны для платформы, нужно определить отдельно, откуда адаптер узнаёт обязательность для запуска: исходная схема psim такого флага не содержит. Правило «без default» само по себе не делает параметр обязательным.

**Предложение:** выбрать исполнимую последовательность. Например, установка принимает все обязательные значения и передаёт их при создании строки, а при их отсутствии не объявляет установку завершённой. Либо явно описать представление черновика с необязательными полями платформы и декларативным условием готовности, включая источник признака обязательности и автора `unfit`. Проверить установку с незаданным параметром и последующее заполнение через форму, а не только плагин без собственных параметров.

## С3. P/02.3 не определяет обещанное снятие подсистемы с удалением её таблиц

**Место:** доп. (5) п. 4, последние два предложения.

**Цитата решения:** «Удаление плагина — его снятие установкой (P/02.3); таблицы объектов и `<т>_seen` уходят вместе с подсистемой по правилу снятия подсистемы».

**Норма:** P/02.3 Н3 задаёт `manifest put`, запись новой ревизии и реакцию процессов на метку: «rev метки … или метки нет → как смена: остановиться с кодом 0; супервизор запускает заново». При отсутствии строки/метки новый старт отказывает. Описанная там уборка удаляет части статических файлов вне нового `files`, а не строки данных подсистемы. P/06.1 Н1.1 отдельно назначает писателей и удаление строк единиц и таблиц; снятие манифеста не названо операцией очистки этих семей.

**Проблема:** по указанной ссылке можно объяснить остановку процессов, но нельзя выполнить удаление плагина вместе с его данными. Нет названной процедуры снятия, порядка остановки держателя и очистки таблиц, удаления строк единицы, а также удаления фрагмента `calls` из backend. Простое удаление манифеста оставит данные; повторная установка того же имени может получить старые объекты и `_seen`, хотя по тексту они должны были исчезнуть. Очистку воркером после удаления манифеста обещать нельзя: он уже должен остановиться.

**Предложение:** определить процедуру удаления в уроке `VMS/12-psim` с конкретным исполнителем и порядком: прекратить новые операции, остановить держателя, очистить явно названные данные с допустимыми правами, убрать манифест и его фрагмент `calls` из backend. Отдельно решить судьбу служебных семей, которые по нормам платформы не удаляются, вместо обещания удалить весь префикс. Либо честно объявить предел этапа: снятие останавливает плагин, данные сохраняются, полное удаление пока не поддерживается. Приёмка — снять плагин с объектами, затем установить снова и проверить выбранную судьбу данных.

* П. 3 согласует удаление `_seen` с разделением писателей таблиц, устраняет столкновения подписей с путями `status` и служебного поля плагина с параметрами psim. Отображение важности в класс события оставлено нормам VMS явно.

Новое правило пересборки не добавляет в состав фрагмента из (5) доступ к `unit.rows` и не меняет порядок создания незаполненной строки. Упоминание снятия плагина как повода пересборки определяет судьбу его фрагмента `calls`, но не задаёт остановку и очистку данных. Поэтому С1–С3 по (5) не считаются закрытыми дополнением (6); повторно в счёт (6) они не включены.
