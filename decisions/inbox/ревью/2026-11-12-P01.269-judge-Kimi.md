## Блокеры

### Б-1. recover уничтожает сохранённый вход до снятия фазовой метки — повтор после аварии стирает восстановленное хранилище
- Норма: `01.3-store.norms.md:1267` (P/01.3-R266): «the implementation MUST NOT destroy the input until completion, so a repeat runs from the same input»; `:1264` (R398): «`recover` MUST remove the phase mark as its last step, after the barriers of the result»; `:1276` (R339): «while the mark stands, a repeat of `recover` MUST start over».
- Код: `internal/group/recover.go:315-316` — `os.RemoveAll(filepath.Join(j.Dir, "raft.recover-input"))` идёт ДО `os.Remove(RecoverMark(j.Dir))`; вход повтора выбирается по метке: `recover.go:70-79` (`inputDir`: при `Phase == "saved"` вход — `raft.recover-input`).
- Сценарий: recover завершил переписывание дампа (`finish`: swap `raft.new`→`raft`, member.json), затем авария между строками 315 и 316. Метка RECOVER стоит с phase `saved`, но вход удалён. Оператор повторяет recover (R339). `loadDump` (`recover.go:117-165`) по отсутствующему каталогу не ошибается: `raft.NewFileSnapshotStore` создаёт каталог, список снапшотов пуст; `OpenLogStore` (`logstore.go:54-57`, `os.MkdirAll`) открывает пустой лог; `first > last+1` ложно; проверки `check` проходят по пустому состоянию. `writeDump`+`finish` заменяют восстановленный `raft/` пустым снапшотом.
- Последствие: полная потеря строк хранилища на допустимой последовательности (авария в окне из двух вызовов + санкционированный повтор). Прямое нарушение R266; приёмка по канону принимает потерю данных.

### Б-2. Чужой join/leave по сети принимается без полномочий admin (relay и напрямую у лидера)
- Норма: `01.3-store.norms.md:977-978` (P/01.3-R214): «A change of another's membership MUST go only through `admin.sock` of the leader»; `:446-448` (R119): «When `leave` or `join` of oneself comes at a follower, the daemon MUST pass it to the leader by an internal operation of the group»; `:965-966` (R283): «`POST /v1/join` and `POST /v1/leave` are called only by `admin.sock` and a daemon of the group over mTLS of the role `configstore`».
- Код: `internal/daemon/voter.go:273` — проверка `c.Sock == rights.Admin && j.ID != v.n.ID()` есть только для admin.sock; сетевой вызовщик (`peer:configstore`, R283) с любым телом идёт в релей: `voter.go:276-277` (`toLeader` → `ServiceToLeader`). У лидера идентичность вызовщика не участвует: `voter.go:271` (`membership(v.n.JoinMember(j.ID, …))`); парсер тела не сверяет id с сертификатом: `internal/door/command.go:138-166`. `Caller.PeerServer` (сервер сертификата пира, `door.go:29`, `listen.go:265-281`) для join/leave не используется.
- Сценарий: член A (mTLS-роль `configstore`) шлёт `POST /v1/leave {"id":"b"}` follower'у C — релей своим сертификатом лидеру L → `LeaveMember("b")` → `RemoveServer`; или `POST /v1/join {"id":"x","raft":…,"api":…}` напрямую L → `AddVoter(x)`. Ожидаемое по R214: отказ/без изменений (чужое членство — только через admin.sock лидера). Кандидат выполняет изменение.
- Последствие: любой член группы может удалить любого voter'а (потеря кворума, вынужденный recover) или ввести произвольный raft-адрес; расхождение наблюдаемого поведения двух канон-реализаций на допустимом входе.

## Существенные

### С-1. Чтения во время удержания писателей импортом отвечают данными вместо 503
- Норма: `01.3-store.norms.md:614-615` (P/01.3-R302): «While writers are held, reads MUST answer as the store `file://` (R159)»; `:626-627` (R159): «the store `file://` in the process MUST answer writes and reads with 503 `unavailable`; the directory does not change».
- Код: `internal/daemon/voter.go:110-124` — `Get`/`List` идут через `v.read` к локальной FSM без проверки `Held()`; удержание проверяется только для записей: `internal/core/step.go:57-59` (`if c.Ordinary() && s.Held()` → `import_held`). У бокса held-каталог вообще не открывается адаптером: `internal/inproc/inproc.go:74-80` (ошибка открытия вместо ответов 503 по R159).
- Сценарий: групповой импорт опубликовал F1 и часть строк (фаза Transfer); читатель делает `GET /v1/get` — получает 200 со смесью импортированных и неимпортированных строк. Ожидаемое: 503 `unavailable` (как `file://` по R159, группа — «as the store file://» по R302).
- Последствие: пропущенный исход нормы; читатель видит неполную картину посреди переноса.

## Мелкие

### М-1. Текст 403 при отказе права на guard называет действие write, а не read
- Норма: `01.2-store.norms.md:389-390` (P/01.2-R086): «`error` names the role, the action and the key»; отказ по guard требует read guard-строки (wc-guard_rights).
- Код: `internal/door/door.go:261-262` (`text = role + " may not " + action(body) + " " + keyOf(body)`), `door.go:278-286` — `action()` смотрит только на `body.op` (`put` → «write»).
- Сценарий: `POST /v1/write` с guard на строку без read-права: ожидается «…may not read …», фактически «…may not write …». code/kind/поля по форме; только текст.

### М-2. Текст 403 при отказе прав батча не называет ключ отказанной строки
- Норма: R086 (тот же шаблон).
- Код: `internal/door/door.go:288-293` — `keyOf` возвращает `"a row of the batch"`, т.к. у тела `op:"batch"` нет поля `key`.
- Сценарий: batch, вторая строка без права: ожидается «…may not write acc/b», фактически «…may not write a row of the batch». Только текст.

### М-3. (условная) Нативная функция вектора rights-evaluator не даст allow роли configstore-door
- Норма: `vectors/rights-evaluator/README.md` (кто исполняет — эвализатор P/01.2 N1.3); `01.2-store.norms.md` R079: «`configstore-door` has only its own `platform/configstore-doors/<id>`».
- Код: `internal/vectors/vectors.go:120` — `rights.Decide(f, role, action, key, "")`: `doorServer` захардкожен пустым; `internal/rights/rights.go:243` — allow двери только при `doorServer != "" && key == DoorsPrefix+doorServer`.
- Сценарий: если в пакете появится строка `(configstore-door, write, platform/configstore-doors/d1, …)`, дверной исход (probe с сертификатом `d1`) даст allow, нативная функция — deny. Состав пакета в M строк про дверь не содержит; expect.tsv в экспорт не входит — находка условная.

### М-4. Отказ импорта на свежий каталог бокса оставляет FORMAT до полной предпроверки
- Норма: `01.3-store.norms.md:548-549` (P/01.3-R145): «`import` and `restore` MUST make a full preliminary check … a bad row, size, base, epoch — a refusal without changes».
- Код: `internal/cli/backup.go:138-147` — до записи FORMAT проверена только грамматика (`copycore.Read`, :142); потолок/эпохи/base проверяются внутри `Run` уже после `datadir.WriteMark(dir, ModeBox)` (:145-147).
- Сценарий: свежий каталог, вход с не-дecятичной эпохой: отказ `copy_input`, но FORMAT записан — строгое чтение «refusal without changes» нарушено. Функционально безвредно (повтор с исправленным входом работает).

### М-5. Любая ошибка владения каталогом названа `local_data_dir_owned`
- Норма: `forms/refusals.tsv` (`local_data_dir_owned` — «offline box import/restore or local recover on a live-owned directory»).
- Код: `internal/group/recover.go:46-49`, `internal/cli/backup.go:133-136` — любая ошибка `datadir.Acquire` (в т.ч. отсутствующий каталог, права) маппится в `local_data_dir_owned` с текстом «is owned by a live daemon».
- Сценарий: `configstore recover -dir /нет/такого` → в логе «owned by a live daemon». Неверная строка лога для случая, который норма не именует иначе; код выхода ≠ 0 соблюдён.

### М-6. `admin.sock` у неготового лидера получает `no_leader` вместо `admin_not_leader`
- Норма: каталог N4, имя `admin_not_leader` (для «не лидер для хранилища», R118).
- Код: `internal/daemon/voter.go:133-141` — лидер raft, чей barrier ещё не прошёл (`readyTerm` не выставлен, `node.go:248-273`), для admin.sock после истечения `WaitLeaderWithin` отвечает `noLeader()` (503 `no_leader` + `X-Configstore-No-Leader`).
- Сценарий: запись на admin.sock свежего лидера в окне до barrier: имя отказа из каталога — `no_leader`, а не `admin_not_leader`. Поведение иначе корректно (503, без изменений).

### М-7. Дедлайн двери не enforced между целями внутри одного раунда попыток
- Норма: P/01.3-R327/R395 (число попыток конечно; все попытки — в бюджете вызовщика).
- Код: `internal/doornv/doornv.go:230-247` — внутренний цикл по `targets()` вызывает `d.call(…, DOOR_REQUEST_TIMEOUT)` без сверки с `deadline`; проверка `time.Now().Before(deadline)` — после каждой цели и после раунда.
- Сценарий: 3 voter'а «висят»: раунд до 3×2 с = 6 с против объявленного бюджета max(leader-wait, 3 с). Ответ двери позже собственного объявленного бюджета; ретраи/ambiguous не страдают.

### М-8. Осечка чтения лога отключает ожидание применения у read fence
- Норма: граница ответственности адаптеров (`versions/README.md:24`); линеаризуемое чтение при исправном хранилище (R258).
- Код: `internal/group/ops.go:118-127` — `lastRelevant` при ошибке `GetLog` (например, `logstore: damaged entry`, `logstore.go:181-183`) возвращает 0; `waitApplied` с target=0 не ждёт ничего (`ops.go:100-107`).
- Сценарий: fence-ожидание `(from, ci]` наткнулось на повреждённую запись → чтение идёт по состоянию, где записи ≤ ci могут быть не применены, вместо отказа 503. Редкий защитный сценарий, не гонка.

### М-9. Фиксированный sleep как единственная синхронизация в тесте лимита соединений
- Норма: TASK.md: «tests that only check a stub are insufficient»; устойчивость тестов.
- Код: `itest/box_test.go:306` — `time.Sleep(100 * time.Millisecond)` после открытия двух held-соединений, затем ожидание 503.
- Сценарий: задержка планировщика >100 мс → flake (200 вместо 503). Остальные ожидания сьюта — poll-циклы с дедлайнами.

### М-10. `store-op` принимает `{tls}` и не использует его
- Норма: `PROFILE.md:87` — значение `dir`/`id`/`tls` фиксирует владеющий контракт приёмки; `runner-targets.tsv` — `store-op` обязателен для P/01.3/group.
- Код: `cmd/configstore-op/main.go:25-30` — `os.Args[4]` (tls) нигде не читается; подстановка объявлена: `acceptance.yaml:13` (`store-op: bin/configstore-op {socket} {dir} {id} {tls} {args}`).
- Сценарий: если владеющая приёмка требует передачи tls-кита административным операциям группы, команда его не получит (если только не приходит внутри `{args}`). Из допущенных файлов не проверяемо; риск задокументирован.

### М-11. Внутреннее противоречие NOTES: Done vs Open items
- Норма: не нарушена; `PROFILE.md:151` — «a missing profile entry, blocked target or unexecuted check is not success».
- Код: `NOTES.md:56` — family-read и log-mask (A1–A14) заявлены в «Shared vectors» (сделанным), `NOTES.md:63-66` — те же пункты открытыми (log mask A1–A15, family-read по обеим семействам).
- Сценарий: ревьюер/судья читает самоотчёт кандидата о себе. Расхождение только в отчётности; кандидат сам декларирует незакрытость.

### М-12. Копия без финального LF принимается импортом (догадка 9)
- Норма: `01.3-store.norms.md:326-327` (P/01.3-R093): «JSON Lines — UTF-8, a line is one JSON object, the line end is LF».
- Код: `internal/copycore/copy.go:68-71` — последняя строка без завершающего LF принимается.
- Сценарий: вход `…}` (без LF) прочтён так же, как `…}\n`. Либеральное прочтение формата против буквы R093 и заявленного в GUESSES.md предпочтения отказа; на conforming-записях (писатель всегда пишет LF) поведение не отличается.
