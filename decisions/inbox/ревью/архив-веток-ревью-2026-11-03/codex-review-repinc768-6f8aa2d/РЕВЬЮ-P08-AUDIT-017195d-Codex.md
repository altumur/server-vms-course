## P2-2 — preflight «данные» становится implementation на выходе драйвера

`runner/m11stand.py:1558–1565,1617–1620`; потребитель — `runner/c_execute.py:50–76`, bridge — `runner/c_store.py`.

Новый on_errors правильно отвергает неизвестное слово до Run/стенда. Но classification=data записана только в строки сценария. Итоговый JSON не несёт верхнеуровневой classification, а C bridge не добавляет её при отсутствии экземпляров Stand/контрольных отказов. `c_execute.classification` читает верхний уровень и затем ищет только признаки транспорта; классы строк data не учитывает. Отказ новой предварительной проверки при code=1 становится **implementation**.

Проба проводит `@on hold @pause domain#1` через настоящий `c_store.main → m11stand.main`, затем через настоящий `c_execute.classification`. Получено: code=1, создано Run/стендов 0, у строки `executed:false,classification:data`, у отчёта classification отсутствует, итоговый класс implementation. Команды профиля имеют маркер NEVER-EXECUTE и не исполняются. Это неверно возлагает дефект входных данных на реализацию, несмотря на верную строковую диагностику.

Нужно довести класс предварительного отказа до верхнего уровня/потребителя с принятым приоритетом классов и проверить весь экспортный путь, включая finalize, а не только on_errors. Нативные сравнения шагов менять не требуется.

## P2-3 — публичное имя domainconsole не поддержано у freeze/thaw

`runner/m11stand.py:1198–1203`; место регистрации процессов — `Bench.start_domain:466–469`. Общий README пина, строки 222–223: имя консоли домена — `domainconsole`, имена freeze/thaw — как у sigkill, включая `#n`.

Ветка sigterm/sigkill переводит `domainconsole#n` во внутреннее `domain-console#n`. Новая ветка freeze/thaw передаёт слово в Stand.directive без такого перевода. Stand.find ищет фактические стартовые имена `domain-console`, поэтому живой процесс не находится.

На двух настоящих зарегистрированных группах domain-console все три публичных формы `domainconsole`, `domainconsole#1`, `domainconsole#2` проходят on_errors, но freeze возвращает `freeze: no such live process`, thaw — `thaw: no such process`; процессы не останавливаются. Контрастный контроль: внутреннее `domain-console#1` тем же реальным dispatcher останавливает и продолжает первую группу; прежняя сигнальная ветка переводит публичное имя правильно. Имя/номер взяты из настоящего Stand._process_record по тем же стартовым (role,name), что использует Bench.start_domain.

Нужно единообразно разрешать публичное имя у всех четырёх действий, сохраняя номер копии и точный выбор группы. Тесты текущей серии проверяют только domain#1 и эту разницу не видят.
