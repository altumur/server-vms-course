Если векторов действительно нет, отсутствие фиксируется явно, свои тесты привязываются к пунктам договора и ограничение попадает в журнал догадок. Переименование каталогов векторов не требуется.

Промежуточный поиск только Markdown-заголовков дал 16 файлов, но такой критерий слишком узок: некоторые договоры называют пакеты отдельной строкой «Векторы — …», без заголовка `##`. Отсутствие именно `##` не считаю дефектом. Прежние два контрпримера не имели ни такого именованного блока, ни требуемого раздела; новое поручение их покрывает.

## Проверка новых правил

**Перечень чтения вместо раскрытия ссылок.** Пункт 1 теперь задаёт конечные категории, а не транзитивный обход. Из урока можно взять только прямо названные договором файлы данных и объявленный пакет векторов с его README. Ссылка из README пакета на приёмку или норму не расширяет список: лекции, README урока и приёмки, сценарии и нормы прямо исключены; дальнейшее раскрытие запрещено. Исключения `Platform/common/` по доп. (27) п. 2 сохраняются. Если требуемый источник не входит в категории, предусмотрена находка к договору, а не самостоятельное расширение доступа.

**Договоры без векторов.** Пункт 2 различает предоставленные векторы и собственные тесты по тексту. Свои тесты не объявляются независимыми векторами спецификации, а отсутствие входного пакета остаётся видимым для счёта. Это достаточное правило процедуры; полноту каждого будущего теста оно само по себе не доказывает.

**Смена внутреннего договора.** Пункт 3 связывает новую версию с дельтой, передачей common и потребителям и записью перехода. Поэтому потребитель не должен узнавать об изменении только по внезапной ошибке сборки. Требование доп. (31) п. 3 перевести код владельца на единственную готовую библиотеку остаётся в силе; новый пункт не разрешает оставить вторую реализацию формата.

**Фильтр внутреннего договора.** Пункт 4 требует до выдачи проверить содержание: форма, API, исходы и слова отказа; пересказ норм владельца возвращается автору. Для исполнения это фильтр всех копий договора, в том числе копии сессии common, которая реализует библиотеку по этому документу. Формат договора становится разрешённым публичным входом; частное повествование о поведении урока — нет. Из этой нормы не следует разрешение сначала передать непроверенный текст, а затем проверять уже отправленную копию.

**Общие файлы сборки.** Пункт 5 назначает одного писателя — ведущую через скрипт — и канал запроса от урока либо common. Это согласуется с доп. (30): ведущая пишет инструменты и общую сборочную конфигурацию, но не код продукта; сессии не правят корневую сборку каждая по своему усмотрению. Ограничение доп. (26) п. 3 на прямые и транзитивные импорты между микромодулями при этом не отменено.

Новых доказанных противоречий по этим пунктам не выявлено. В частности, решение не обещает, что старый контекст после очередного перехода становится новым независимым опытом: журналы продолжают одну генерацию, а отдельная вторая генерация сохраняет свою роль.
