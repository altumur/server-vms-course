# Воспроизведение P01.332

Обвязки готовят локальные артефакты пары и проверяют их. Они не выбирают пин, не доставляют входы,
не исполняют кандидата, модель или суд. Операторы пары, паспорта и J-входа берутся побайтно из принятых
P01.299/P01.277; копии и SHA-256 остаются в собственном каталоге доказательств.
Все команды исполняются `/home/pilot/venv-spec/bin/python -B`.

1. `prepare_source.py <новый каталог доказательств> <своё дерево> <C>` сохраняет точный архив C и квитанции
   приёма необходимых изменений, проверяет предшествование C и запускает полный check_spec архива.
   Затем выполняет проверки оператора до записи и семантическую дельту классификаций от C8′.
2. `bind_reviews.py <доказательства>` связывает каждую новую классификацию с фактическим ревью другого
   провайдера. Старые обзоры P01.329 сохраняются без изменения; два файла записи soak — с приёмом Архитектора.
3. `release_pair.py <доказательства>` выпускает исходную пару штатным оператором, затем выбирает узкий M
   через текущий pair_m точного C и обязательный COURSE_COMMIT. Штатные операторы строят паспорт M и J-вход.
4. `passport_controls.py <доказательства>` проводит девять отдельных контролей паспорта на своих копиях.
   `verify_exports.py <доказательства> <своё дерево>` проверяет ростеры, M⊂J, текущий pair_m, классификации,
   объекты, единственные ссылки, отсутствие родителей, паспорта и fsck. Независимый сканер J-входа сохраняется
   без изменений; его исключения ограничены точными принятыми путями P01.254, без новых исключений.
5. `delta_pair.py <доказательства> <каталог отчёта>` сравнивает все файлы/режимы/blob M/J/J-входа с P01.299.
6. `audit_changed_norms.py <своё дерево> <C> <паспорт M> <output.json>` сверяет каждый изменённый абзац
   и пункт перечня всего M с CHANGED-NORMS и историей. Смысл кратких формулировок проверяется чтением;
   изменённые файлы без собственной английской строки истории явно названы результатом аудита.
7. `audit_task.py <своё дерево> <доказательства>` разбирает первичные сохранённые результаты К01/К02,
   проверяет явные живые R-id списка, append-only журналы, неизменный logstore от Opus 8 и бюджет норм.
   Он также пересчитывает полный хеш входа Q по его текущей описи; метод записан в Q-INPUT-HASH.json.
8. `package_evidence.py <доказательства> <каталог отчёта>` копирует результаты и паспорта, строит манифесты.
   После окончательной правки отчёта хеши пакуются заново.

Штатный check_spec архива и точная проверка ростера оператором — отдельные свидетельства.
Проверка собственного итогового коммита сохраняется отдельно; SHA связывается внешней квитанцией сдачи.
