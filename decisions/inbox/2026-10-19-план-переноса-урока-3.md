# План переноса урока 3 «Воркер» в `Platform/03-worker` (стадия B)

Задача «Архитектора» 2026-10-19: план без правки байтов. Сам перенос — по его слову, после условий ADR-0083 доп. (7)
для уроков 3–5: выгрузка уроков 1–2 генераторам, сверка М10/3–5, ревью стадии A по 3–5 тремя ревьюверами и разбор.
Основание — `Platform/module-design.md` (таблица «Уроки», строка 3; «Порядок чтения» шаги 4, 6, 8, 15),
`Platform/common/id-map.tsv` (31 норма с `new` = `P/03.K-MM`), опыт переноса уроков 1 и 2 (`4604d9928`, `eecd1ce7d`,
`839d220a4`). Срез — `main` 2026-10-19 после `c06573f8c`.

## 1. Что такое урок P/03

Библиотека воркера на каждом языке, роль `<sub>worker` (ADR-0083 доп. (2) п. 1). Урок собирается не из одного
прежнего урока, а из шести: М10/3 (слоты, эпоха, аренда), М10/5 (воркер под слотом — целиком), М10/7 (открытие
конверта), М10/8 (исполнение просьб, запись событий), М10/10 (проверка схемы, таблицы `worker.writes`), М11/5 и М11/7
(поздний слой). Прежние уроки после переноса остаются: М10/3 — строкой единицы, id, заявками и дверью единиц (всё —
глава 6.1, переносится с уроком 6); М10/5 — пустеет целиком (см. п. 6).

## 3. Приёмка

- **М10/03** — все 14 сценариев проверяют дверь единиц консоли (глава 6.1): **не переезжают**. Слот, эпоха и аренда в
  приёмке урока 3 проверяются только чтением (таблица «Остальное проверяется чтением»: строки «слот», «эпоха и
  аренда») — эти строки переезжают в Н5 главы 3.2.
- **М10/05** — 16 сценариев на стенде «воркер и контроллер `testsub`» (директивы `@start`, `@sig*`, `@grow`). Деление
  по колонке «Нормы»:
  - главе 3.2: 01 (старт, строка слота), 04 (вторая копия — никто), 05 (SIGKILL — слот не отдан), 08 (две спеки — слоты
    без роста `gen`), 09 (имя не по грамматике), 13 (брошенный захват);
  - главе 3.4: 03 (SIGTERM — слот отдан);
  - главе 3.3 (цикл по назначению, после урока 4): 02, 06;
  - уроку 4 (размещение, заказ ADR-0084): 07, 11, 14, 15, 16 — остаются в М10/05 до переноса урока 4;
  - с ресурсом урока 8 (после урока 5): 10 (журнал `worker.name_taken` — 3.2 и 3.6), 12 (присутствие `gone`) — до урока 5.
- **Стенд.** Воркер без контроллера назначения не получает: сценариям 3.2–3.4 нужен контроллер реализации. Это сосед
  по контракту (каталог данных, `lifecycle.md` урока 4), а не нормы урока 4 — критерий самодостаточности ADR-0083
  доп. (5) не нарушен (вопрос В2).
- Свидетельства вне TSV (М10/5 Н5 «Свидетельства вне TSV») — по главам по номерам норм.
- Счёты: приёмка P/03 — по главам `acceptance/2`, `acceptance/3`, `acceptance/4` (сценарии с прежними номерами, как у
  уроков 1–2; `corrections.tsv` со строкой переноса); README приёмки, Н5 глав, «N сценариев / M шагов» урока и
  инструкции, id-map строки сценариев.

## 4. Контракты

- **OpenAPI.** Своей HTTP-двери у воркера нет (М10/5 Н2); дверь воркера по маршрутам `door.routes` и `door.pass` —
  урок 6 (6.5) и М10/11 Н1.8. Нужна строка `P/03 no-openapi` (разрешение «Архитектора»).
- **Договор библиотеки (3.1).** Шесть вызовов — договор языка, не HTTP. В раскладке `spec/03-worker.library.md`; если
  `check_spec` его не знает — глава 3.1 нормами (`03.1-worker.norms.md`, Н2 «Договор библиотеки») (вопрос В1).
- **Каталог данных.** owner переводится: `<sub>/slots/<имя>`, `<sub>/epoch/<id>`, `<sub>/holds/<место>`,
  `<sub>/contenders/<имя>/<коробка>` → P/03 (глава 3.2), `<sub>/heartbeats/<имя>` → P/03 (3.4); строки единиц,
  `next_id`, `idem` остаются за М10/3 (6.1). Абзацы «Данные» глав — по каталогу.
- **`lifecycle.md`** урока 3 уже есть (ADR-0083 доп. (2)); перенацелить его ссылки на главы 3.x.
- **Векторы.** Своих векторов у урока пока нет; кандидат — таблица захвата слота (переходы М10/3 Н3 «захватить») и
  порядок имён — сейчас «чтением» (вопрос В3).

## 6. Метод (уроки переноса 1–2)

- Главы — параллельными субагентами (каждый — свои файлы и фрагменты в scratchpad); общие файлы (лекция, инструкция,
  каталог, id-map, исключения, перенацеливание) — сама «Спецификация» после.
- Перенацеливание ссылок скриптом **по разделам** («М10/5 Н1.1» → «P/03.4 Н1.1»); id — **только перенесённые целиком**:
  разделённые id (`note`) и тексты «Соответствие прежним урокам», «Пункты … перенесены», «деление М10/x-NN» не
  переписывать (в уроке 2 скрипт переписал М10/7-01/-09 и левые части «старый → новый» — исправлено `5f2955eb8`).
- Голые «урок 3», «урок 5» — по контексту (в М11 «урок N» — урок М11); ссылки-определения `[М10/5]: путь` в
  `lifecycle.md` — отдельным проходом.
- Один коммит переноса; `check_spec` PASS со списком уроков `Platform/0[1-3]-*/0N-*.md`; отчёт «Архитектору», ХОД.

## 7. Вопросы «Архитектору» (с рекомендацией)

- **В1. 3.1 — `library.md` или нормы.** Рекомендую главу нормами (`03.1-worker.norms.md`, Н2 «Договор библиотеки»): тогда
  `check_spec` проверяет её как главу; `library.md` — когда у `check_spec` будет его форма.
- **В2. Стенд приёмки воркера с контроллером реализации.** Рекомендую принять: контроллер — сосед по контракту
  (каталог, `lifecycle.md`), сценарии проверяют нормы воркера; директивы стенда — общий README приёмки.
- **В3. Векторы захвата слота.** Рекомендую не вводить в переносе (без изменения поведения); кандидат после урока 4.
- **В4. Остаток приёмки М10/05.** Рекомендую оставить сценарии 07, 10–12, 14–16 в М10/05 до переноса уроков 4 и 5 (у
  урока нет норм, только приёмка — новый вид исключения `acceptance-only` или временная строка нормы-указателя).
- **В5. Новые id 3.1.** Рекомендую 2–3 id из частей М10/5-03, -05, -10 (вызовы цикла, вызов под слотом, вызовы
  остановки) со строками в id-map, как P/02.4-15.
