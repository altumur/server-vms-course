# Обвязки P01.355

Скрипты готовят локальные M11/J11 и J-вход по образцу принятой P01.346. Операторы P02.52, паспортов и независимый сканер J-входа сохранены побайтно. Меняются только обвязки доказательств этой задачи.

Интерпретатор: `/home/pilot/venv-spec/bin/python -B`. Каталог доказательств: `/home/pilot/P01.355-evidence`. Каждый скрипт вызывается из своего дерева; аргумент `<отчёт>` — каталог этой записки, `<дерево>` — `/home/pilot/wt-task-P01.355`.

1. `prepare_source.py <доказательства> <дерево> <C>` требует совпадения C со свежим origin/main. Сохраняет задачу, квитанции зависимостей и их предшествование C. OBSH.69 связана с тремя точными коммитами main: у задачи роли architect приёмщик owner, файла accepted нет. Скрипт создаёт собственные source.git и архив C, копирует неизменённые операторы, проверяет пару/J-вход с курсовыми оригиналами P02.52, запускает `check_spec --scope platform`, preflight и дельту фильтров к C пары M10.
2. `bind_reviews.py <доказательства>` связывает каждую добавленную/удалённую классификацию с принятой P01.350 или OBSH.70. Путь должен меняться в коммите автора, его итоговые роли должны совпадать с принятым коммитом. Provider автора — codex/OpenAI из задачи; window приёма совпадает с handle architect/Claude в реестре. Неизвестная или неоднозначная дельта останавливает выпуск. Прежние роли наследуются из принятой P01.346.
3. `release_pair.py <доказательства>` создаёт собственный SOURCE-CLOSURE и AUTHORIZATION после зелёной проверки и связывания ревью. Неизменённый P02.52 выпускает широкую пару; узкая M выбирается `m_form.pair_m` точного C с обязательным COURSE_COMMIT в независимое хранилище. Строятся паспорт M и J-вход. Argv, коды и потоки каждого вызова сохраняются.
4. `passport_controls.py <доказательства>` выполняет девять раздельных контролей. Затем `verify_exports.py <доказательства> <дерево>` сверяет полный ростер, режимы/blob, M⊂J, фильтры, паспорта и изоляцию объектов с fsck. Таблица зависимостей теперь ссылается на открытые цели производительности: прежней зависимости на qualification/README.md нет. Путь данных прав заменён принятым общим адресом. Неизменённый `verify_ji_raw.py` допускает только прежние точные исключения принятой P01.254.
5. `unpack_m.py <доказательства>` распаковывает финальную M в новый `M11/` без Git-метаданных. Сверяет пути/blob, снимает все биты записи (файлы 0444 либо 0555 для исполнимых, каталоги 0555) и проверяет готовое дерево неизменённым check_m_passport. Опись — UNPACKED-M11.json. Существующий каталог не заменяется.
6. `delta_pair.py <доказательства> <отчёт>` сравнивает M/J/J-вход с принятой P01.346: пути, режимы, blob, размеры и число строк; импортирует объекты только в собственный delta.git.
7. `audit_changed_norms.py <дерево> <C> <паспорт M> <output>` проверяет полноту CHANGED-NORMS.md: изменённые абзацы, пункты перечней и все файлы финальной M. Для новых пунктов без прежнего текста принимает добавленную строку истории вставки по точному адресу `#readiness-checklist`; изменённые пункты по-прежнему требуют id или дословного снятого текста. Для файлов без собственной новой английской истории сохраняет коммиты и хеш точного diff. Краткий смысл проверяется чтением.
8. `package_evidence.py <доказательства> <отчёт>` копирует паспорта и результаты, включая UNPACKED-M11, и строит манифесты отчёта и внешних доказательств. Его вызывают после последней правки отчёта. Проверка точного коммита сдачи и FINAL-RECEIPT создаются после коммита отдельно.

Связанные места: источники, переводы, формы, приёмка и списки выгрузки согласованы чтением и проверкой точного C; менять их эта задача не требует. Код продукта и данные спецификации не правились. Выбор пина, генерация и исполнение кандидата, движка или стенда в эти обвязки не входят. Дальнейший запуск выполняет представитель по отдельному поручению.
