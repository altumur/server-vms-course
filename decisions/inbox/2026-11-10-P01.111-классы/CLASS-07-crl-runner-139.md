# C07. crl: раннер выходит с кодом 139

**Суть.** На `P/01/vectors-crl` у `c36e6ac` процесс раннера завершается с кодом 139 (`SIGSEGV`). Движок даёт GREEN 22/22. В счёт попал прогон без отчёта раннера, отсюда 22 случая «движок GREEN, раннер нет».

**Случаев:** 22 (`engine_GREEN_runner_not|GREEN|None|absent`).

## Наблюдения
- Первый прогон, `out/c36e6ac/P_01_vectors-crl.first/`. Раннер записал отчёт: `runner/P-01-vectors-crl.txt` — «01-store vector-crl 22/22; GREEN», в `P-01-vectors-crl.json` `green: true`. Отчёт записан в 14:21:29, процесс вышел с rc=139 (`progress.txt:86`: «end runner c36e6ac P/01/vectors-crl rc=139 sec=4»). Движок на том же прогоне — GREEN 22 (`green_both 22` в `summary.json`).
- Повторный прогон, `out/c36e6ac/P_01_vectors-crl/` (15:17). Раннер упал без отчёта: в `runner/` только `inventory.json` и `preparation`.
- У `d9d15b0` цель красна у обоих: старый профиль, «required target dependencies are missing».

## Норма
Расхождения по норме нет: по первому прогону оба судьи дают 22/22 GREEN. Код 139 — дефект процесса раннера, не вердикт. По P/AC-R008 зелёная цель требует «all its processes were cleaned up». Аварийный выход самого судьи — «инструмент суда».

## Мнение представителя
**Раннер (инструмент суда).** Содержательного расхождения нет: вердикт раннера в отчёте первого прогона совпадает с движком. Раннер выведен (ADR-0135 доп. (8)), поэтому это только запись предела. В P01.93 (суд попытки 4 раннером) код 139 на crl надо читать по отчёту, а не по коду выхода.
