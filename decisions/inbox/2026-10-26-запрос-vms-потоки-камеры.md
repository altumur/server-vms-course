# Запрос: потоки камеры — пустое `about`, `about` на свою подсистему, группа на нескольких держателях

Решение владельца 2026-10-26: поток — единица `cam`, камера — единица основного потока (`main` пуст), прочий поток —
`main: <id>` и `about: {sub: cam, field: main}` (V/01.1 Н1.1а). Проверка п. 1.4 задела (принята «Архитектором»
2026-10-26): загрузчик `about` на свою подсистему допускает, гранты (`may` шаг 7, `gate-and-pass` `scope`) судят поток по
камере; три места платформа не нормирует.

## 1. Пустое значение поля `about`

**Норма и выгрузка.** P/02.1 Н1.2 (`about.field` — поле с `fixed: true`), договор права `may` (вход `unit.about?`),
`gate-and-pass` `scope` и `unresolved`, договор журнала событий шаг 2 (`of` из `about`), договор удержаний `addressee`,
дерево модуля (КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ §7) — `41d3ec8`. Что значит строка, у которой поле `about.field` пусто, нигде не
сказано; «пустой id — запись не называет» есть только у `rights.names`.

**Что нужно VMS.** Пустое (или отсутствующее) значение `about.field` — единица без `about`: `may` без `about`, `scope`
по самой единице, без `unresolved` → `*`; `of` в строке события нет; удержание «про» её не называет; модуль показывает её
как единицу без родителя.

**Пример.** `cam/cameras/7 {source: rtsp://10.0.0.20/ch/1, main: ""}` — камера; `cam/cameras/8 {source: …/ch/2, main: "7"}` —
её поток. Грант `labels:vlan:a` — по меткам строки 7 для обеих; событие строки 7 — без `of`, строки 8 — `of: cam/7`.

**Обход.** Допущение VMS «пусто = без `about`» в V/01.1 Н1.1а с пометкой; реализация платформы, читающая пустое значение
иначе (`unresolved`, `of: cam/`), сломает гранты на камеры — видно на стенде домена.

## 2. `about` на свою подсистему: дерево консоли

**Норма и выгрузка.** КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ §7 и строка `subsystems` («подсистема, чей манифест говорит `about`,
вкладывается узлами под единицы родителя; без `about` — своё дерево»), P/06.5 Н1.2 `display.tree.children`, P/07 Н1.5 —
`41d3ec8`. При `about.sub` = своё имя у подсистемы нет своего дерева (или вложение в саму себя) — случай не определён.

**Что нужно VMS.** `about.sub` = своё имя: у подсистемы своё дерево; единица с непустым значением `about.field`
вкладывается под единицу, которую оно называет (если та есть в дереве), единица с пустым значением — корень (с п. 1);
`children: false` — не вкладывать.

**Пример.** Дерево «Оборудование»: «Вход» (камера 7) → «сетка» (поток 8), «детекция» (поток 9); записи и детекторы
(`about` на `cam`) — под камерой 7, как сейчас.

**Обход.** Оболочка VMS подписывает поток его камерой (`addDecor`) и показывает потоки во вкладке «Потоки» камеры (V/08.1
Н1.5); вложить единицы под единицу оболочка не может (`addTreeNodes` — узлы, которые не единицы); что модуль сделает с
`cam` — до нормы не известно.

## 3. Группа `group_by` на нескольких держателях

**Норма и выгрузка.** P/04 Н1.3 `group_by` («размещается только целиком на одном воркере», ADR-0011), договор группы по
хосту, P/04 Н1.3 `constraint`, `near` — `41d3ec8`.

**Что нужно VMS.** Вариант (Б) задела: держатель потока — рядом с его потребителем (основной — у записи, сетка — у
шлюза, детекция — на GPU-сервере). Для этого группа устройства должна размещаться **не больше чем на N воркерах** (N —
предел сессий устройства), а не на одном; и поток без своих меток — по меткам своей `about`-единицы (`constraint:
labels-subset` над метками камеры), иначе поток уходит на сервер, из сетей которого адрес не виден.

**Пример.** `group_by: {field: source, cut_at: host, holders: 2}` — регистратор на 16 каналов держат не больше двух
воркеров; `constraint: labels-subset` у потока `cam/cameras/8` (`about` → 7) сверяет метки строки 7.

**Обход.** `group_by` в `cam` остаётся (V/01.1 Н1.3): все потоки устройства — у одного держателя, потребители идут к нему
своим `near` (`det`, `detedge` — `near: {sub: cam}`), запись тянет держателя к себе (`cam` `near: {sub: rec, of: cam}`). Цена
— поток сетки и поток детекции не на сервере потребителя; поток между серверами — через приёмник (V/02.9).

## Рекомендация

1 — норма в договоре права, `gate-and-pass`, договоре журнала и удержаний («пусто — без `about`»), одна строка в каждом;
2 — строка в §7 модуля и P/07 Н1.5 (своё дерево при `about.sub` = своё имя); 3 — ключ `group_by.holders` (целое ≥ 1,
умолчание 1 — нынешнее поведение) и чтение меток `about`-единицы в `labels-subset` для единицы с `about` своей подсистемы;
векторы `group-of`, `near-of` — по новому ключу.
