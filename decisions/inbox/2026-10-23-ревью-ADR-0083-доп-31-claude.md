## Вывод: с правками

Найдено 2 существенных и 3 мелких находки, блокеров нет.

Решение владельца доп. (30) (ведущая — диспетчер, сборка — скриптом) не оспаривается.

Находки повторного ревью доп. (29) закрыты по сути. Два новых правила дырявы на текущей выгрузке:
- замыкание по ссылкам с исключением «норм и README» приводит в чтение сессии `common` лекции всех десяти уроков
  и README приёмки (С-1);

## Существенные

### С-1. Замыкание по ссылкам приводит сессию `common` к лекциям всех уроков и к README приёмки

- **Место.** `decisions/0083-микромодули-платформы.md:719–722`.
- **Цитата.** «и всё, на что ссылаются договоры и векторы `common/`, кроме норм уроков (`*.norms.md`) и README уроков, —
  формы `data/`, векторы уроков, таблицы; замыкание по ссылкам строит скрипт рабочего места».
- **Контрпример.** Цепочка по выгрузке `e0b19be`:
  - `common/contracts/event-journal.md:138` ссылается на `05-resource/acceptance/README.md`;
  - тот на строке 35 — на лекцию `06-console/06-console.md` (75 КБ);
  - лекция 06 ссылается на лекции 01–05 и 07–10 (`NN-*/NN-*.md`, лекция 08 — 100 КБ), на `КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`
    и на OpenAPI уроков.

  Ни лекция, ни README приёмки не подпадают под исключение «`*.norms.md` и README уроков». В замыкание входят:
  - 10 лекций;
  - README приёмки уроков 03, 04, 05, 06 (сц. 1, 2, 7), 08 (сц. 1, 3, 6–10) и их вложения — 647 файлов только
    `02-installer/acceptance/`.

  README приёмки пересказывают нормы своих уроков и историю переноса, например «Сценарии перенесены из приёмки
  М10/08 …» в `05-resource/acceptance/README.md`. Лекции объясняют нормы.
- **Источник.**
  - Доп. (25) п. 3: у соседей — только `spec/*.openapi.yaml`, `vectors/`, `data/`, `lifecycle.md`. Лекции и README
    закрыты даже для сессий уроков.
  - Доп. (29) п. 1: «норм уроков она не читает».
  - Доп. (27): чтение держит устройство.
- **Последствие.**
  - Сессия `common` получает нормы уроков через лекции. Пробел договора закрывается знанием из лекции без догадки,
    а значит, дыра доп. (28) С-1 возвращается.
  - Список, построенный замыканием, меняется при каждой правке ссылки. По доп. (31) п. 6 исчезнувший из списка
    файл — это «сужение», и сессию `common` пришлось бы заменять от любой правки ссылки в договоре.
- **Предложение.**
  - Список строить по категориям, а не замыканием: `Platform/common/` поимённо, `Platform/README.md`,
    `НОРМАТИВНЫЕ-СЛОВА.md`, `Source/tests/testdata/` и у уроков только категории доп. (25) п. 3.
  - Ссылки из этих файлов идти только внутрь тех же категорий.
  - Лекции, README приёмки и README уроков в список не входят.
  - Регрессия рабочего места проверяет, что в нём нет `*.norms.md`, лекций `NN-*/NN-*.md` и `acceptance/**`.
  - Ссылки договоров на README приёмки (`event-journal` → 05, `local-token-door` → 08 сц. 7, `request-mark` → 03 сц. 6)
    «Спецификация» заменяет вектором или выносом в `common/`.

### С-2. У 9 из 28 договоров нет раздела «Векторы» — тестам библиотеки не из чего браться

- **Место.** `decisions/0083-микромодули-платформы.md:723`.
- **Цитата.** «Векторы договора — пакеты, которые называет раздел «Векторы» договора, а не каталог с тем же именем».
  Вместе с доп. (29) п. 1: «Тесты `common/<договор>` — из `common/vectors/<договор>`».
- **Контрпример.**
  - Заголовок «Векторы» есть у 12 договоров. Ещё у 7 есть фраза «Векторы — […]» (например, `group-of`, `sealing`).
  - Остальные 9 векторов не называют ни заголовком, ни фразой: `event-journal`, `forwarding`, `gate-and-pass`,
    `labels`, `local-token-door`, `observation`, `presence-lock`, `role-certificate`, `secret-files`.
  - При этом в `common/vectors/` есть `labels/`, `journal/`, `presence-room/`, `crl/`, `revoked/`. По п. 2 одноимённый
    каталог не в счёт, а раздела нет. Значит, у `labels` пропадают даже его одноимённые векторы.
- **Источник.** Доп. (29) п. 1. Доп. (31) п. 2.
- **Последствие.**
  - Для 9 договоров, среди них `role-certificate` и `presence-lock`, нужные урокам 01–05, у библиотеки `common` нет
    тестов.
  - Сессия либо пишет строку «договор молчит» о векторах, либо берёт каталог по догадке. Первое раздувает счёт,
    второе обходит п. 2.
- **Предложение.**
  - «Спецификация» дописывает каждому договору раздел «Векторы» с пакетами, а если векторов нет — «нет; проверяет
    приёмка уроков …».
  - До выгрузки с разделами сказать в п. 2: «раздел или фраза «Векторы —»; без них — строка `GUESSES.md`, тесты не
    пишутся по догадке».

## Мелкие

### М-1. Смена внутреннего договора после первой копии не имеет перехода

- **Место.** `:724–727`.
- **Суть.**
  - Скрипт копирует `NN-*/contracts/<имя>.md` и векторы сессии `common` и потребителям.
  - Переход (доп. (29) п. 4, (31) п. 6) привязан к `SPEC_VERSION` выгрузки. Внутренний договор живёт в репозитории
    генерации, и выгрузка его не меняет.
  - Если владелец формата правит `CONTRACT.md` по находке, не сказано, когда пересобирается копия, кто получает
    дельту и куда пишется запись перехода. До перевода владельца на библиотеку две реализации расходятся
    по старой копии.
- **Предложение.**
  - Правка внутреннего договора — коммит `NN-*/contracts/`.
  - Скрипт пересобирает копии.
  - Сессии `common` и потребителям идёт дельта по шаблону (31) п. 6 с id коммита вместо `SPEC_VERSION`, запись в
    их `TRANSITION`.

### М-2. Текст внутреннего договора попадает к сессии `common` мимо фильтра ведущей

- **Место.** `:724–726` и (30) п. 1 (`:705–708`: «пропускает входящее по шаблону»).
- **Суть.**
  - `CONTRACT.md` — свободный текст сессии урока, у которой в контексте все её нормы. Скрипт копирует его сессии
    `common` без фильтра.
  - Пересказ норм P/01 или P/02 в нём (C04-MANIFEST-SDK-01 прямо велит «слова отказа — как в P/02») ложится в
    контекст той же сессии, что пишет библиотеки публичных договоров.
- **Предложение.**
  - Регрессия по `NN-*/contracts/*.md`: нет ссылок на `*.norms.md` и id норм вне полей формата.
  - Или запись в `common/READING-AUDIT.md` на каждый внутренний договор.

### М-3. Корневые файлы сборки (`go.mod`) без писателя

- **Место.** (30) пп. 1–2 (`:705–713`).
- **Суть.**
  - Ведущая кода продукта не пишет. Скрипты — инструменты.
  - Один `go.mod` на язык (доп. (26) п. 3) меняют и сессия `common`, и сессии уроков при новой зависимости. Чей
    это файл, не сказано.
  - Правки из нескольких рабочих мест в один файл ведут к конфликтам.
- **Предложение.** Назвать: корневые файлы сборки — инструмент генерации (правит скрипт по запросу сессии) или
  файл сессии `common`.
