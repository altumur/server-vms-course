# ADR-0074: источник имён и грантов для собираемой книги

## Контекст

Основа `b85c47ae`. `DomainSection._names` допускает только `kept`-семьи; `DomainSection.read` запрещает
книге одновременно быть `kept`. Поэтому `names.stream-accounts/` для новой книги объявить нельзя.
`declared.refusal` ищет субъектов по именам строк, а у книги хвост строки — получатель, не учётка.
Проба `Source/tests/probes/adr0074_delivery.py` подтверждает оба отказа загрузчика на testsub.
Нужна точная связь `names` с книгой и источник полного множества субъектов: адресные копии неполны,
а конфликтующие записи `unique` вообще не входят в результат. Форму предлагаю до кода.

## Рекомендация

1. Разрешить `domain.names.<book>/` для **одноимённой книги с `from`**, без записи в `kept`.
   Существующая форма `{exclusive_with: domain/users, grant: view}` сохраняется. Имя субъекта — значение
   `key` вклада. Для переносимых книг без `from` правило не расширять. Чужую семью не угадывать по `from`.
2. Перед адресной проекцией платформенный сборщик строит общий индекс имён из всех корректных вкладов,
   включая конфликтующие `unique` и записи без разрешённого получателя. Издатель/воркер индекс не пишет.
   Рекомендую строку `domain/names/<sub>/<book>`: элемент `""` = JSON `{missing: [<member>, …]}`, остальные
   элементы `<key>` = JSON `{members: [<member>, …]}`. Списки отсортированы, без повторов; значений вклада
   и секретов здесь нет. Роль domain пишет индекс; роли, проверяющие имена, читают его. Это новое имя
   диска: добавить строку долга `# ADR-0074 «курс»` только вместе с реализацией после решения.
3. `exclusive_with` и потолок гранта проверять по индексу, а не по адресным строкам книги. Известное имя
   резервируется и при конфликте издателей. При `missing` сохранять прежние известные имена отсутствующего
   члена; отсутствие имени не доказывает свободу — создание/расширение прав отказывать как временно
   недоступное. При явном выходе/истечении `lost_after` исключать члена согласно ADR-0074. Индекс отсутствует
   или повреждён — также неизвестность. Удаление/отзыв прав не блокировать.
4. Доставка: поверх `to` нужен неистёкший грант субъекту `<key>` именно у получателя с capability,
   указанной `names.<book>/.grant`. Грант на конкретную единицу или labels также разрешает доставку
   учётки; его область продолжает ограничивать доступ в двери. Более широкий, повреждённый или истёкший
   грант доставку не разрешает. Повторно проверять на границе `carry.answer`, чтобы отзыв между сборкой и
   отправкой не выдал прежнюю копию. Недоставка заменяет результат, а не оставляет старую запись.
5. Создание учётки шлюзом проверяет этот индекс/полноту и людей. Два одновременных создания в разных
   кластерах могут пройти по прошлому полному виду; результат — конфликт `unique` и недоставка обеих,
   а не выбор победителя. Глобального атомарного резервирования текущая форма не даёт; не добавлять
   распределённую блокировку и не обещать отсутствие такого окна.

Приёмка на testsub/testsub2 до live: имя человека/учётки в обе стороны; конфликт двух издателей без
доставки; учётка без грантов всё ещё резервирует имя; scoped-грант, отзыв и expiry; отсутствующий и
повреждённый индекс; неизвестный/потерянный/удалённый член; перенос держателя. Индекс — производное
наблюдение, не новый источник полномочий. Сборку результатов и индекса сериализовать с проверками
держателя; не объявлять несколько строк одной атомарной транзакцией. Прошу согласовать эту форму.

## Решение
«Архитектор», 2026-10-12. Форма принята целиком, пять пунктов как написано, с тремя уточнениями.

1. `domain.names.<книга>/` — только для одноимённой книги с `from` (не `kept`); имя субъекта — значение `key` вклада;
   для переносимых книг без `from` правило не расширяется; семья `kept` для `stream-clients/` живёт до переезда
   записей одной пачкой (доп. 2 ADR-0074), двойного чтения нет.
2. Индекс имён `domain/names/<sub>/<книга>` — принят: элемент `""` = `{missing: […]}`, элементы `<key>` = `{members: […]}`,
   списки отсортированы, значений и секретов нет; пишет роль domain тем же проходом, что и результат, после него;
   это и есть «диагностика конфликта без полезной нагрузки» из доп. 1 — отдельной диагностической строки не будет.
   Новое имя диска: строка `# ADR-0074 «курс»` в обеих ведомостях вместе с реализацией.
3. Проверки `exclusive_with` и потолка гранта — по индексу; при `missing` прежние имена отсутствующего члена
   сохраняются, создание и расширение прав — отказ 503 «временно недоступно» с именами отсутствующих; потерянный по
   `lost_after` или снятый член исключается; индекс отсутствует или повреждён — неизвестность, тот же отказ;
   удаление и отзыв прав не блокируются. Уточнение: отказ называет, чего не хватает (члены), не «нет».
4. Доставка — `to` и неистёкший грант субъекту `<key>` у получателя с capability из `names.<книга>/.grant`; scoped-грант
   доставку разрешает, область остаётся у двери; повторная проверка на границе `carry.answer`; недоставка заменяет
   результат. Уточнение: более широкий грант, чем потолок `grant`, — не только «не разрешает доставку», но и отказ 400
   при записи гранта (ADR-0031), как сегодня.
5. Создание учётки шлюзом — по индексу, полноте и людям; одновременное создание в двух кластерах — конфликт `unique`,
   недоставка обеих, без победителя и без распределённой блокировки. Уточнение: конфликт виден оператору на обеих
   страницах по индексу (`members` длиннее одного) — и снимается удалением одной учётки.

Уходит дополнением в ADR-0074; файл снимается.
