## Разбор

1. **`{rights}` в команде векторов (отказ профиля).** Таблица подстановок `PROFILE.md` даёт векторам только `{input}`: ошибка модели. Повод в M: README пакета пишет `rights.json as {rights}`, а `wire.tsv`, куда README отсылает, в M нет; модель записала это догадкой № 2. Один неверный ключ снял весь суд.
2. **Группа, два независимых слоя.**
   - **Стенд и M.** Раннер дописывает к `stand.store` флаги `-dir`, `-sockets`, `-rights` (`runner/store_group.py:174`). `lifecycle.md` велит держать `-dir {data}/configstore` в команде, а норма P/01.3 требует отказывать на повторный флаг. Кандидат поступил по норме. Это скрытая норма стенда, класс «стенд, пробел M», а не реализация.
   - **Реализация.** Даже без этого группа не работает: `runRaftDaemon` нигде не вызывается, `daemon.Run` всегда поднимает одиночный режим, отказа `box_no_raft` нет, `recover` не реализован (`P01.16.2`, проверено Архитектором). Этап `group` закрылся по сборке и собственным тестам пакета.
3. **`daemon`, три шага.** `08-floor-replay`: кандидат отверг значение floor как неверное по форме (400 вместо 200). `15-service-doors`: 405 вместо 413. Класс раннера — реализация; с нормами отдельно не сверялись.
4. **Сборка.** Раннер собирает без `GOMODCACHE`, кандидат с зависимостями на суде не собирается. Дефект пути суда.

## Пределы

Стенд не изолирован. В копии суда вручную заменены две строки M на J. Вердикт как эталон ADR-0135 шага 8 годится только для целей диагностики и с её правками.

## Разбор по нормам (`P01.85`)

- **`08-floor-replay`, шаги 12–13 — реализация.** Норма P/01.3 N1.3 `floor` и таблица `/v1/write`: `floor` от 1 до 2^53 − 2^32 включительно. В шаге проверяется ровно верхняя граница, 9007194959773696, кандидат её отверг.
- **`15-service-doors`, шаг 4 — реализация.** P/01.3-07: порядок «кадр → маршрут → личность → тело», 413 раньше 405. Кандидат проверил метод раньше размера тела.
- **`family-read`, 20 случаев — пробел M, с долей реализации.**
  - 18 случаев: для отсутствующего обязательного поля таблица ждёт путь самого поля (`/floor`, `/seen_at`, `/generation_at`), а кандидат даёт корень `""` или корень вместе с полем. README пакета называет пути отказа указателями JSON Pointer, но для отсутствующего поля путь не определяет; JSON Schema 2020-12 сама относит ошибку `required` к объекту. Правка M: явно указать, что путь отсутствующего обязательного поля — указатель на это поле.
  - 2 случая (`01-0004` и подобный, корень `null` у читателя): README определяет исход строк пустого пути (стр. 13–16), кандидат его не выдал. Это реализация.

Пробел M по `family-read` добавлен в общую правку `P01.86`.

## По схеме ADR-0133 доп. (41)

Генерация шла без судьи (`generation_only`): ворота проверяли сборку, `vet`, свои тесты модели и полноту профиля. Поэтому ни одна находка суда не проверялась воротами, и модели по п. 2 не засчитана ни одна.

| Находка | Главная причина | Вторая | Модель |
|---|---|---|---|
| `{rights}` в команде векторов | цикл: проверка профиля не сверяет подстановки | спецификация: подстановки только таблицей в прозе, README пакета пишет `{rights}` | не доказано |
| группа не подключена ко входу, нет `box_no_raft`, нет `recover` | цикл: этап `group` закрыт сборкой и тестами пакета | — | не доказано |
| повторный `-dir` у стенда группы | спецификация: скрытая норма стенда | инструмент суда | — |
| граница `floor` | цикл: проверки не было | — | не доказано, норма однозначна |
| 413 раньше 405 | цикл: проверки не было | — | не доказано, норма однозначна |
| `family-read`, путь отсутствующего поля (18) | спецификация | — | — |
| `family-read`, исход пустого пути у читателя (2) | цикл: проверки не было | — | не доказано, норма однозначна |
| сборка без офлайн-кэша, `log-mask` | инструмент суда | — | — |

Вывод: по этому суду о пригодности модели ничего не следует. Отлаживать нужно цикл (ворота по данным урока, ADR-0133 доп. (39)) и названные места спецификации. Четыре находки, где норма однозначна, станут проверкой модели, когда цикл будет их проверять.
