## Вывод

39 пунктов: норма — 25, ошибка раннера — 8, случайность — 6. По разделам: 1 — 3, 2 — 9, 3 — 13, 4 — 2, 5 — 3, 6 — 1,

**Спека для этих модулей уже подробна.** `PROFILE.md` пересказывает `assembly.py` почти дословно (поля, ключи, владение
команд, подстановки, YAML-подмножество) — расхождений не найдено. «Store group stand» и «Three-server cluster stand» общего
README описывают `store_group.py` и `power_stand.py` до флагов запуска и выбора `-join`. `tls/README.md` — шаги TLS и ER до
ожиданий. Скрытое здесь — сроки, порядок обрыва сценария, разные правила в разных движках и сценарии TLS/ER, которые
существуют только кодом.

Главные находки:

1. **Наборы TLS и ER — код, а не данные** (8.21). `tls_stage.py` исполняет шаги `tls/README.md` (пп. 2, 7, 8, № 14, свой
   клиент, адреса по умолчанию, `TIMEZONE`, ER п. 9) как функции Python: пути запросов проб, заголовок `X-Operator`, сроки
   `@until 60`/`90`, порядок шагов. У `tls/` нет `scenarios.tsv`. По ADR-0135 код под урок — пробел спеки: общий движок такие
   шаги не исполнит.
2. **Ключ `Idempotency-Key` — три формы в трёх движках** (2.37): `l03` — `<сц>-<шаг>`, `console` — `<сц>-<шаг>-<pid>`,
   `l11` — `r<время>-<сц>-<шаг>`; README — `<run>-<scenario>-<step>`. Пункт 2.23 третьей описи — не единичный случай стенда
   домена.
3. **Судья P/06.1 берёт типы полей у подсудимого** (2.41): `l03.spec_fields` читает `GET /manifest` реализации, а README
   велит судить «по загруженному манифесту». Реализация, которая отдаёт неверные типы, проходит полную форму по своим же
   словам.
4. **Полная форма пустого тела на двери консоли и ресурса не судится** (2.40): `forms.check` выходит при `body is None`, а
   `store_group` прямо судит пустое тело схемой. README: «absence of a body for HEAD/204» — часть полной формы.
5. **Обрыв сценария после провала — разный** (3.47): группа хранилищ идёт дальше после любого провала, `l11` и `console`
   обрывают после `@spoil row`/`@backup`/`@import`, стенд домена — после любой директивы (6.8 третьей описи).
6. **`@server-start` стенда трёх серверов ждёт до 70 с, а README — «всё не позже 20 с»** (3.48): 20 с статуса члена,
   30 с сокетов ролей, 20 с ресурса — подряд.
7. **Старый путь не исполним на текущей спеке** (8.22): `stage_a` ищет `group-of`, `fault`, `values-by-type` по прежним
   путям, `m11` — урок `М11_Domain`, `mix` — ключ `spec-put`; `body_vectors` зовётся только из старого `all.py`.
8. **Сроки, которых нет в спеке** (раздел 7): клиент TLS группы 15 с, ожидание выхода члена 10 с и процессов сервера 30 с,
   бюджет сценария наборов процессов 900 с, HTTP движка P/01.3 60 с, ожидания TLS/ER 60 и 90 с; период опроса `@until` —
   1 с или 0,2 с (2.39).
9. **Корреляция ответа P/03.6 шире README** (2.42): раннер сверяет `queued`/`answered` на каждом `POST` двери просьб с 200/202
   во всей главе и выбирает вид дайджеста по пути, а не по `requests.key`; README называет шаг 05/5.
