# Сверка с P01.168 после собственной классификации

## Порядок и срез

Сначала записаны `independent.md`, реестр 145 red и проверка двух отсутствующих
машинных форм. SHA-256 независимой записки перед чтением P01.168:
`23b1fc0210d920311d1c54f870a5764ef5c1f35def20d013f46a7fbd76c7846a`.
Её текст после сверки не изменён.

Затем прочитан пакет P01.168 на коммите
`ef0f9cbdb4562efef9a4d5e20233675887c20100`, по его квитанции сдачи.
Ветка origin/task/P01.168 уже удалена: fetch отдельной ветки вернул отсутствие
ref. После `git fetch origin` тот же коммит доступен в origin/main через
слияние `b807a6d34`; сверка сделана `git show <точный SHA>:<путь>` без
переноса файлов в своё дерево. P01.168 принят architect в 13:19:29Z.

## Совпадения

Основной вывод P01.168 «все red диагностики — движок» на пересечении пяти
целей подтверждён независимо по всем 145 шагам. Его 146 включает ещё один
Claude inproc, который не является общим red двух кандидатов: у MiniMax
inproc отличается. Расхождения числа причин здесь нет.

| Эта проверка | P01.168 | Совпавшая причина |
|---|---|---|
| E1 | A1 | не учтено допустимое поле size |
| E2 | A2 | @header теряется |
| E3 | A3 | @rights не исполняется, роль подменяется |
| E4 daemon | B1 | директивы не вызваны |
| E4 import/spoil | B2 | безусловные ложные причины отсутствия |
| E5 | B3 | состояние проходит между сценариями |
| E6 и transport из E7 | C1 | группа не поднята по контракту |
| E7 expectation | C3 | admin участника уходит в общий сокет; @until однократен |
| E4 group | C4 | 49 операций заменены red stand |
| E8 | D2, также A4/B4 | строки дополнительных таблиц не исполняются |

Разбиение group различается только группировкой: P01.168 объединяет 7
store-start и 41 transport в C1 (48). Здесь 7 относятся к E6, а 41 вместе
с 28 expectation составляют E7 (69). Оба разбора называют transport
следствием неправильного запуска, а не самостоятельным дефектом кандидата.

Предупреждения P01.168 о ложных GREEN обоснованы. В частности старый
member в карте даёт GREEN повторному store-start без проверки живости
(`run_directives.go:67–69`). Даже при полностью совпавших красных нельзя
объявить остальное выполненным корректно. Швы без переданного моста имеют
законный MissingBinding; это не реализация операций кандидатом и не
доказанный дефект движка (P/AC-R030, R050).

## Расхождения и уточнения

1. **Фактическая ошибка D2.** В `CLASS-D2-extra-not-run.md`, раздел «Норма»,
   написано: «здесь сценарий есть у каждой из 16 проб». На том же J это
   неверно. У `extra-full-key-declared` (`extra.tsv:8`) и
   `extra-forwarded-list` (`:10`) сценариев нет. `collect.py` вычисляет
   разность имён непосредственно из Git J, результат сохранён в evidence.json.
   Исполнение 60 строк движком нужно, но оно закроет только 14 проб;
   оставшиеся две должны получить no_machine_form и требуют работы писателя
   приёмки. Это N1 независимой записки — дополнение к очереди правок спеки.
   Основную классификацию 145 red это не меняет.

2. **A1, вторичная «норма: правило size прозой».** Согласен, что правило
   желательно выразить общими машинными данными: P/AC-R002 запрещает ветви
   по имени урока и требует закрытого словаря. Но наличие прозы само по себе
   не доказывает неоднозначность требования продукта или неверность ответа
   кандидата. README главы уже точно задаёт проверку типа/байтов и исключение
   поля. Новую узнаваемую английскую фразу нельзя считать достаточной
   починкой: это ещё один неявный формат. В очередь спецификации — общая
   форма условной нормализации ответа, если существующий словарь не выражает
   правило; E1 остаётся причиной конкретного red. Лимит и ожидание не меняются.

3. **A3 и R033.** P01.168 называет поведение после неисполненной директивы
   неопределённым. В действующем R033 есть явная фраза «The other steps go
   on and are judged», а @rights не включён в список подготовки. Следовательно,
   нельзя выдать предлагаемое «всегда прерывать после любой неисполненной
   директивы» за уже действующий контракт. Исполнить @rights и убрать
   подмену роли нужно по существующей норме. В очередь спецификации —
   рассмотреть добавление @rights в список подготовки и зависимость шагов
   от неприменённого файла; изменение должно сохранить исполнения обычных
   шагов после несовпадения и границу R033. До решения не вводить универсальное
   правило обрыва самостоятельно. В собственном E6 отдельно установлен
   бесспорный дефект: даже уже перечисленный store-start при обработанном
   отказе обходит механизм прерывания из-за раннего continue.

4. **B2, вторичная причина R030.** Согласен с рекомендацией уточнить условия
   `stage_package_not_exported`: в R030 это голое слово без условия.
   Для `store_spoil_row_missing` условие уже есть в словаре, README:293;
   для `store_rights_template` — README:292. Их нужно связать ссылкой,
   не писать противоречащую вторую норму. Нет оснований считать отсутствие
   повтора этих условий в одном абзаце первичной причиной 57 неисполненных
   шагов: код не ищет ни команд, ни файлов. P01.168 дополнительно прочитал
   профиль Claude и нашёл обе команды; эта проверка этого чтения не повторяла
   и не переносит наличие команд автоматически на MiniMax. В обоих случаях
   unconditional reason движка остаётся доказанным дефектом.

5. **B3, довод о номерах версий.** Фраза «на свежем сторе … первая запись
   имела бы небольшую версию заново» не является нормативным критерием:
   версии непрозрачны и не обязаны начинаться с малого числа
   (`acceptance/1/README.md:34–37`). Утверждение о переносе состояния
   подтверждают сам код движка, предыдущий floor и отсутствие сброса;
   гипотеза о числовой величине версий для этого не нужна.

Выводы P01.168 о D1/D3, о прочитанном моделью, бюджете и причинах в обвязке
лежат вне общих пяти целей этой задачи. Здесь они не подтверждаются и не
опровергаются; журналы разговора с моделями и их секретное окружение не читались.

## Очередь на следующий круг

Движку: E1–E8, включая выполнение precondition extra, правильную адресацию,
повторы @until, fresh-состояние и явное ожидание @exit 2. Следует отдельно
проверить исполнение дополнительных process-таблиц door/daemon и таблиц
прав rights: механизм их пропуска совпадает с E8, а P01.168 A4/B4 уже
описывает эти 142 неисполненные строки. Ворота должны проверять вызов
операции, нужный процесс и изменение/сохранение состояния, иначе заглушка
может снова подтвердить ожидание на чужом запросе.

Спецификации: N1 (две отсутствующие формы extra), общая машинная форма
условной проверки size, условия stage_package_not_exported, точечное решение
об @rights в R033. Последние три — уточнения контракта судьи, а не повод
обвинить кандидатов или заменить корректные ожидания продукта.

Результаты после исправления движка ещё неизвестны. Зачёт, повтор суда и
вывод по ADR-0133 (47) эта записка не назначает.
