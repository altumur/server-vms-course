# P/09: владелец формы локального token POST 502

**Исправить отдельным исходным follow-up после текущего SOURCE15.** Локальный 502 `did not answer` операции `POST /api/tokens/{member}/{sub}/{kind}` должен ссылаться на существующий P/06 `DomainRefusal` с ограничением `error.const: did not answer`. Нынешний enum P/08 `Refusal` не содержит этого слова и описывает другой ответчик.

Это устранение найденного разрыва представления по существующим P/09.2 N2/N4 и договору forwarding. Новая форма, слово, статус, порт или поведение не вводятся; счёты сданных ревью не пересчитываются.

## Основание

База наблюдения — `05133c299b27ed76262cd074d1b09af3eb2aa26e`. [P/09.2 N2](../../Platform/09-agent/spec/09.2-agent.norms.md), строка 134, прямо задаёт локальный 502 `did not answer` токенной двери, как forwarding. Строки 152–153 отдельно сохраняют коды держателя как пришли: OpenAPI P/09 описывает собственные коды ретранслятора. [Договор forwarding](../../Platform/common/contracts/forwarding.md) различает владельцев собственных и передаваемых отказов.

В [OpenAPI P/09](../../Platform/09-agent/spec/09-agent.api.openapi.yaml) существующий локальный 502 ошибочно ссылается на P/08 `Refusal`: закрытый enum владельца-процесса не содержит `did not answer`. P/06 `DomainRefusal` уже описывает `{error, detail?}` собственного forwarding-отказа. Эта же существующая форма выбрана coord103-src для пяти новых GET502 по disposition `1a58487cf6795f160031cacaef0134e4618283df2bebef351fa54f1c3cc8ad7c`.

## Точная будущая правка

Только в `Platform/09-agent/spec/09-agent.api.openapi.yaml`, в узле

```text
/paths/~1api~1tokens~1{member}~1{sub}~1{kind}/post/responses/502/content/application~1json/schema
```

заменить ссылку на P/08 `Refusal` следующим Schema Object:

```yaml
allOf:
  - $ref: ../../06-console/spec/06-console.api.openapi.yaml#/components/schemas/DomainRefusal
  - properties:
      error:
        const: did not answer
```

Описание ответа и остальные поля этого response сохраняются. Остальные операции, статусы, заголовки, успех и ответы держателя не меняются. P/06/P/08 owner-узлы остаются только для чтения, enum P/08 не расширяется, местный alias не создаётся.

Исключение members N1.4 сохраняется: подтверждённая подписанная строка из памяти — 200, без строки — прежний 503. Его нельзя заменить общим локальным 502. Разрешение пяти новых GET502 не расширяется этим follow-up.

## Порядок

Текущий SOURCE15 по `178069601d92b8a061685c6ee1b3f5f5c4b895e9c5f8ff88860652056db3d510` идёт без этой правки; его прогнозные SHA и защита четырёх прежних PathItems сохраняются. После точной публикации SOURCE15 coord103-src объявляет отдельный normal child: конечный parent, before/after одного schema-узла, полный after-SHA файла и точные производные metadata-пути до записи. Во всех остальных частях прежние PathItems и компоненты остаются byte-equal этому parent.

Исходные snapshot, декларация56d9 и квитанции сохраняются как история. Нужная поправка own metadata не означает приёмки всего урока или запуска инструмента применения. Новые cases, швы, validators, CODE, render/Go/HTTP/SUT, модели или GATE этим решением не назначаются.

Прочитаны первичные нормы, существующие owner-схемы и точная disposition. Схемные программы, авторские проверки и runtime Архитектор не запускал. Уточнение не меняет RO-пины tools437/d034, статус ms, паузы Claude или таймеры.
