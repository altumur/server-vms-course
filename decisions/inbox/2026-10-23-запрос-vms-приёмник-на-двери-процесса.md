# Запрос: допуск по токену домена у маршрута двери процесса

**Какая норма мешает.** P/03.4 Н1.7 `door_admission` (`03.4-worker.norms.md:213–217`) знает два допуска маршрута
`door.routes`: имя — токен двери консоли (договор door-token), `{name, role}` — лист роли (класс `mixed` договора
сертификата роли). Приёмник регистратора (V/02.9 Н1.3) принимает трёх обращающихся: процессы своего кластера — по листу роли
(`recworker` — сосед и толкатель серверной камеры, `liveworker` — шлюз, V/03.2), камеру-кластер, ретранслятор и толкатель
другого кластера — по **токену домена** (`stream`, `poll`, `upstream`; P/03.7 Н1.5 «проверить у получателя»). Токена двери
консоли у них нет; маршрута, который пускает по токену домена, у двери процесса нет. ADR-0091 доп. (7): у процесса один
слушатель двери.

**Что нужно VMS.** Маршрут `ingest` двери регистратора: лист `recworker` или `liveworker` — допущен; токен домена вида
`stream` | `poll` | `upstream` с `cluster` — свой (функция `token` договора токена домена) — допущен, утверждения (`ref` —
камера обращения) сверяет подсистема; иное — 401/403 со словами договоров.

**Обход до решения.** V/02.9 Н1.3: приёмник — второй слушатель регистратора (транспорт — решает реализация, V/01.6): адрес
по P/03.4 Н1.7 `door_address` (норма покрывает любую дверь процесса в пульсе; схему называет урок), пределы — `door_limits`;
допуск подсистема делает сама теми же функциями платформы — `token` договора токена домена и проверка листа роли договора
сертификата роли (класс `mixed`: без комплекта — только петля, обращения по роли — 401 `no_role`). Строка долга в
`ХОД-Спецификация-VMS.md`.

**Рекомендация.** P/02.1 `door.routes[]` — третий вариант `{name, role?, domain: [<вид>…]}`; P/03.4 Н1.7 `door_admission`:
`domain` — токен домена одного из видов манифеста (`domain.tokens` любой подсистемы каталога) с `cluster` — свой, функция
`token`; при `role` — лист роли или токен домена; утверждения — подсистемы; без комплекта маршрут `domain` работает на петле
(как `token`). Транспорт не-HTTP (SRT) остаётся выбором реализации на отдельном слушателе с тем же допуском.

## Решение
Решён (2026-10-23, «Архитектор») ADR-0091 доп. (14): рекомендация принята — `door.routes[]` `{name, role?, domain?: [<вид>…]}`, допуск функцией `token` с `expect {kind, cluster: свой}`, утверждения — подсистеме, без комплекта — петля; не-HTTP транспорт — отдельный слушатель с тем же допуском. Нормы — «Спецификации» после ревью; обход (второй слушатель) снимается переходом VMS на выгрузку с нормой.
