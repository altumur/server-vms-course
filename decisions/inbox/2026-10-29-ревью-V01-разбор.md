## Вопросы ревьюеров — решения «Архитектора»

1. **`kind`** (Codex Q1, Claude С-5). Закрытое `enum: [video, io]` в каноне манифеста и в V/01.1 Н1.1. Камера `kind: io`
   держит только устройство (команды, события), без потока; её фаза — из существующих слов таблицы Н1.4 главы 2
   (новых слов фаз нет), `cam_cameras_running` считает только видео. Пара `io` + `live: on-demand` — `live`
   игнорируется, сказать явно. Приёмка: отрицательный случай (`"thermal"` → 400 по схеме) и положительные `video`, `io`.
2. **Доля кадров** (Codex Q2, Claude С-1). (а) Объект раздачи — свой у каждой эпохи держателя:
   `shm://<каталог доли>/<id>-<эпоха>.shm`; удаляет только его писатель; читатель берёт точный адрес из пульса
   (`live_shm`) и не строит его сам. (б) Формат файла кадров — «Решает реализация» (внутри одной реализации VMS,
   генерация одной линией Go); межреализационный стык — RTSP петли. В «Решает реализация» главы 2 — требование описать
   формат в README реализации. (в) Форма адреса — абсолютный путь: `shm:///run/…` (три косых).
3. **Каталог доли** (Claude С-2, вопрос 2). Норма — `/run/<dep>-cam-shm`, `<dep>` — `W2C_DEPLOYMENT` окружения юнита
   (умолчание `w2c`; у VMS — `vms` по V/09.1). Если платформа не передаёт `W2C_DEPLOYMENT` в окружение юнита воркера —
   «Спецификация VMS» пишет запрос к платформе (P/02.4), до ответа — текущее правило. На стенде — подстановка каталога
   доли (`{shm}`) в общем README приёмки VMS, ожидание приёмки 2 — через неё.
4. **Первый счёт давно истёкшей лицензии** (Codex Q3, Claude С-15). Подлинный документ с `expires + GRACE` в прошлом
   и без прежнего решения: `state: degraded`, набор `licensed: []` (пусто, никого предварительно не лицензировать).
   Прежнее решение после передачи слота — книга члена (`domain/cam/licence/…`), сказать явно.
5. **Семьи данных VMS на В7** (Codex Q4, Claude С-18, вопрос 4). Да, **до генерации VMS**, классом по всем урокам
   VMS: то, что манифест уже выражает (поля строк, тела просьб), остаётся манифестом; схемы `data/*.schema.json` с
   `*.layers.tsv`, `*.outcomes.tsv` и строки каталога `VMS/common/data/catalog.tsv` — для содержимого, которое читают
   другие процессы и подсистемы, а манифест не выражает: слова пульса (`live_url`, `live_shm`, `phase`, `can`,
   `coverage`, `taken_by`), элемент книги `sources`, решение `licence`, строка `devices` сверх манифеста. Исходы — по
   читателям (LAYERS § 6–7); векторы — положительные и отрицательные. Нового общего механизма не вводить; не хватает —
   запрос к платформе. README урока обещание сохраняет.
6. **Класс TLS двери камеры** (Codex Q5, R13). Класс `role` договора сертификата роли как есть: нет листа — `401
   no_role`, чужая роль — `403 wrong_role`, неподходящая подпись — `403 bad_chain`; отказ рукопожатия — только для
   цепочки, отвергнутой TLS. Фраза «чужая роль или нет сертификата — отказ рукопожатия» снимается; OpenAPI и приёмка —
   по этому классу. Отдельного строгого слушателя нет.
7. **Серийный номер** (Claude С-11, вопрос 3). Правило «серийный номер кластер не покидает» сужается до `identity`
   строки `devices`; у камеры-кластера `ref` и `name` — серийный номер сознательно (это её имя для домена), записать.
8. **Инструкции короче шаблона** (Codex R17, Claude М-12, вопрос 5). Долг перед генерацией: каждой инструкции VMS —
   короткие разделы шаблона «Входы и приоритет», «Что создать», «Ловушки», «Готово, когда», «При расхождении» со
   ссылками, без копирования норм. Классом по урокам VMS.
