Отчёты (предмет — `decisions/0097-гранты-по-подсистемам-и-папкам.md`, `proposed`, срез курса `2900d976a`):

- Kimi (`kimi/review-adr-0097`, e49f120b9, 10 находок 1/5/4, вопросы 1–6) — `decisions/inbox/ревью/РЕВЬЮ-ADR-0097-Kimi.md`;

  Конечная модель условий ADR и её доказательства остались в ветке Codex (`РЕВЬЮ-ADR-0097-Codex-model.py`,
  `РЕВЬЮ-ADR-0097-Codex-model-evidence.json`; прогон CT 103 `20261030T095250Z-rv-adr97-model`, exit 0).

Все три отчёта подтверждают выбранные варианты: поле `sub` строки (подсистема — третья ось рядом с рангом и областью) и
область `folder:<id>`. Все три проверили совместимость: строка без `sub` значит то же, что сегодня, переноса нет
(ADR-0003), `platform` не столкнётся с именем подсистемы (P/02.1). Находки — о механизме, а не о выборе.

Совпадения между отчётами:
- один `sub` на запрос невыполним у смешанных записей — Kimi Б1 и Codex 1 (оба блокер). Claude счёл правило
  последовательным («Что держится»); решение 1 этот вывод пересматривает;
- эскалация через членство — Claude Б-1 (блокер), Kimi С4, Codex вопрос 1: один и тот же случай у всех троих;
- `sub` события и отметки — Claude С-5, Codex 2, Kimi С1 и вопрос 2;
- лента B2 не знает смены членства — Codex 3, Claude С-4;
- стоимость `folder:` — Claude С-3, Kimi М2, Codex вопрос 3;
- как `folder:` покрывает саму папку — Claude С-2, Kimi С3 и М4;
- путь записи грантов из `backend` и право `ur` — Claude С-8, Kimi С5 и вопрос 6.

Правит ADR «Архитектор» по этому разбору; нормы — после правки ADR (ADR-0097 §8).

## Решения «Архитектора», принятые до разбора

1. **`sub` — у каждой проверки, а не один на запрос** (Kimi Б1, Codex 1). Каждый вызов `may` получает `sub` той строки
   или двери, которую он охраняет. Пакет и составной запрос проходят, только если проходят все проверки. Журнал пишет
   `sub` каждой проверки. Уточнения разбора (приняты):
   - фразу §2 «Все проверки одного запроса — с одним `sub` действия» заменить: «Ссылки одной проверки (`unit_of`,
     `reach`, `names`, `body_unit`) — с `sub` этой проверки». Пример `rec/keeps` (`unit_of` → `cam/7`, `sub: rec`) и
     пример сценария `auto` остаются: это ссылки внутри одной проверки;
   - пакет записи устройства (ADR-0094 доп. (9) п. 3) проверяет `cam/cameras/7` с `sub: cam`, а `rec/keeps/…` — с
     `sub: rec`. Строка `admin sub: cam unit:cam/7` без прав `rec` получает отказ всего пакета. Так одна строка `rec`
     судится одинаково через пакет и через свою дверь (Kimi Б1);
   - запись папки с членом: строка папки — `admin`, `sub: platform` на `F`; член — по решению 3;
   - шаг операции ADR-0095: строки цели — `sub` каждой строки; шаг `folderIds` — как запись папки с членом; служебные
     строки операции (итог, счётчики, занятость) — правом следствий ADR-0095, без проверки человека;
   - предпроверка до тела (`body_unit`: «грант `edit` на что-либо») — с `sub = null`, потому что подсистема тела ещё
     неизвестна; после тела — `sub` единицы тела;
   - Confirmation (Kimi, Codex): пакет `cam` + `rec` под `admin sub: cam` — 403, под парой `sub: cam` и `sub: rec` —
     200. Положительный случай Codex («`admin sub: platform folder:F` и `edit sub: cam unit:cam/7` добавляют `cam/7` в
     `F`») по решению 3 становится отказом; положительным он будет с `admin sub: cam unit:cam/7`.
2. **Платформенные двери и строки** (Kimi С2, Claude М-3, Kimi М1) имеют явное имя подсистемы `platform` в `sub`
   проверки: `/drain`, `/domain/*`, `/marks`, `/where`, папки `platform/folders`. Грант с `sub: X` совпадает только со
   строками подсистемы `X`. Грант без `sub` совпадает со всеми, включая `platform` (как сейчас). Грамматика имени
   `platform` и журнального `sub` консоли — в норме. Уточнения разбора (приняты):
   - таблицу §2 закрыть правилом умолчания, чтобы две реализации не расходились на неназванной двери:

     | дверь | `sub` проверки |
     |---|---|
     | двери под `/<s>/…`: строки единиц, таблицы, просьбы, `DELETE /<s>/asked/*`, `door.pass` | `s` |
     | записи консоли: папки и членство, метки серверов, вывод, `<s>/policy`, `drain`, `schema`; `GET /drain`; `POST /domain/move`; `/where`; `/marks` | `platform` |
     | чтение «любой грант» без единицы (`need` договора сторожевой): `/session`, список папок и одиночная папка (ADR-0096 В6), прочие `GET` без единицы | `null` |
     | `GET /events` | решение 4 |
     | прочие двери консоли | `platform` |

   - `GET /drain` уходит из `null` в `platform`: дренаж — состояние всего кластера, и строка `view sub: cam *` его больше
     не открывает (Kimi С2). Запись и чтение дренажа теперь судятся одной подсистемой;
   - `<s>/policy` — `platform`, а не `s`: политику размещения подсистемы ведёт платформа (Codex вопрос 4);
   - аварийная сессия (шаг 1 `may`) — без изменений.
3. **Эскалация через членство** (Claude Б-1, Kimi С4 и вопрос 1, Codex вопрос 1). Добавить единицу в папку `F` —
   `admin` на `F` **и** `admin` на эту единицу (в её `sub`), а не `edit`. Причина: членство подставляет единицу под все
   строки `folder:` папки и её предков. Перенос между папками — то же для обеих папок. Уточнения разбора (приняты):
   - право на единицу проверяется по составу **до** записи: целевая папка `F` и её предки во вход `may` для `U` не
     входят (Codex вопрос 2). Иначе запись дала бы право сама себе;
   - снятие из `G`, порядок членов, имя, подпапки — без права на единицу: эти записи только сужают права;
   - решение закрывает самоэскалацию «`edit` в одной подсистеме → `admin` во всех» (Claude, контрпример 1). Выдачу
     чужих прав другой подсистемы (Claude, контрпример 2; Codex вопрос 1, вторая половина) оно не закрывает — это А2;
   - Confirmation: оба контрпримера Claude по исходу, выбранному в А2.
4. **Источник `sub` события** (Codex 2, Claude С-5, Kimi вопрос 2). `sub` события — подсистема журнала (дерево писателя
   события), а не подсистема `about`. `/events` фильтрует по `sub` каждого события. Уточнения разбора (приняты):
   - обе стороны строки, `unit` и `of`, сверяются с этим `sub` (Claude С-5). Тревогу `det/5` с `of cam/7` видит
     `view sub: det unit:cam/7` и не видит `view sub: cam unit:cam/7`. Это задумано (ответ на вопрос Kimi 2): какие
     уровни камеры дают `view det`, решает перевод §6 (Г13, запрос «Консоли» п. 3);
   - деревья `console` и `audit` — `platform`. Поле `sub` строки `audit` и любое прикладное поле `sub` во вход `may` не
     идут: доверенный источник — только дерево (Codex 2);
   - P/06.4 «Кто видит строку»: быстрый путь «грант уже `view` на `*`» — только строка `view *` без `sub`; строка
     `view sub: cam *` — это фильтр по `sub`;
   - Confirmation: тревога `det` о `cam/7` против `view sub: cam` и `view sub: det`; строка `audit` против
     `view sub: rec *`; событие с прикладным полем `sub`.
5. **Лента B2** (Codex 3, Claude С-4). Смена членства папки меняет `view` подписчиков с грантом на эту папку — им
   `reset`, как при смене грантов, без попытки досылки. Уточнения разбора (приняты):
   - «грант на эту папку» — строка `folder:` на папку или на любого её предка: `folder:P` покрывает и членов подпапок;
   - удаление папки — `reset` подписчикам со строкой `folder:` на неё, её предков и потомков (поддерево сразу
     недостижимо, ADR-0096 §3); жнеца не ждать. Норма вправе взять проще: `reset` всем со строкой `folder:`;
   - члены через `about` отдельного правила не требуют: `reset` действует на подписчика целиком;
   - фильтр ленты — `may(view, …)` с `sub` подсистемы строки (решения 1, 2) и с `folder:` (цена — Г10);
   - B2 — в §8 «Порядок» и в Confirmation: добавление, снятие, перенос члена, удаление предка при неизменных грантах.

**Г4. Отдельная подсистема `folders`** (Claude С-6). Отклонить. Решение 2 даёт всем платформенным строкам одно имя
`platform`. Опасение Claude — строка «вести все папки» `admin sub: platform *` открывает и `drain`, и `schema`. Это
верно, но так задумано: такая строка и есть администратор кластера. Строки с областью `folder:F` дренаж и схему не
открывают никогда, потому что тем нужен `admin` на `*`. Какая функция consolem ведёт папки, контракт не говорит —
вопрос продукту (запрос «Консоли» п. 1). До ответа §6 называет форму: ведение папки `F` — `admin sub: platform folder:F`,
корня — `admin sub: platform *`, и выдаёт её только `unr`.

**Г8. Как `folder:` покрывает саму папку** (Claude С-2, Kimi С3, М4). Принять предложение Claude, в нём есть и правило
Kimi:
- запись папки `F` — вход `unit = {sub: platform, id: <F>, labels: [], folders: [F, предки F]}`;
- создание подпапки в `P` — та же форма над `P` (Kimi М4: в §5 сейчас `F` вместо `P`); создание корня — `unit = "*"`;
- `folder:X` покрывает папку, если `X` в её `folders` (то есть `X = F` или предок `F`); `*` покрывает всегда; `unit:` и
  `labels:` папку не покрывают;
- живость цепочки — по Г9: папка под удалённым предком не покрывается ничем, кроме `*`;
- `covers.tsv`: строки «`folder:` у записи папки», «у подпапки», «у папки под удалённым предком».

**Г9. Недостижимая папка до жнеца** (Claude С-1). Принять. В `folders` входит папка, только если вся её цепочка до корня
жива. Предок отсутствует или стоит надгробие — ни эта папка, ни её предки в `folders` не входят. Строка не покрывает,
это не 503. Причина: снаружи удаление поддерева атомарно (ADR-0096 §3), и права обязаны вести себя так же. Надгробие —
подтверждённое отсутствие, а не «чтение не удалось». Confirmation: член подпапки удалённой папки до прохода жнеца — не
покрыт.

**Г10. Стоимость `folder:`** (Claude С-3, Kimi М2, Codex вопрос 3). Принять:
- **лениво:** консоль читает `folders`, только если после шага 5 и отбора по рангу осталась строка `folder:`, а строки
  `*` и `unit:` не покрыли раньше. У человека без `folder:` цена нулевая;
- **память на запрос:** членство по ключу единицы и живость папки по id читаются один раз за запрос. Тогда на запрос не
  больше одного чтения членства на каждую различную единицу (с `about`) и одного чтения на каждую различную папку. Это
  тот же порядок, что чтение строк единиц для `labels:` сегодня (P/06.4), поэтому отдельный бюджет с исходом «исчерпан»
  не нужен;
- памяти между запросами нет: разрешение по устаревшему членству недопустимо;
- числа (наибольшее число чтений на решение) — в норме рядом с `FOLDERS_DEPTH_MAX` и `FOLDERS_PER_UNIT_MAX`;
- фразу Decision Outcome «как метки — одним чтением» заменить; Consequences «Bad» — назвать цену на списке, фильтре
  событий и ленте, а не только на записи.
Список предков в строке папки (Claude С-3 п. 3) — на выбор нормы: родитель неизменен (ADR-0096 §2), но живость предков
всё равно читается.

**Г12. Выдача грантов и `ur`** (Claude С-8, Kimi С5). Принять без вопроса:
- выдаёт гранты, в том числе с `sub` и `folder:`, только `admin` домена (P/08.4 Н3 «гранты» шаг 1). Это записать в §1:
  ни `admin sub: platform`, ни `admin` папки права выдавать не дают;
- `ur` consolem («права на права пользователей») — в перечень непереводимого §6: делегированной выдачи у платформы нет;
- инвариант consolem «остаётся хотя бы один `unr`» — проверка `backend` над `domain/grants/<кластер>` до записи, а не
  `last_admin` (тот считает только `domain/grants/domain`).
Чей и какой путь записи из `POST /access/apply` — А4.

**Г13. Перевод consolem** (Claude С-7, Kimi М4). Принять, норма — V/11 («Спецификация VMS»):
- повышающее `objectAccess` — строки `unit:`; умолчания `d*` — строки на `*` с `sub`;
- понижающее исключение и подпапка ниже предка — `NOT_SUPPORTED` у `/access/apply`. Строки только объединяются, запрета
  строкой нет, и буквальный перевод молча расширил бы права. ADR-0094 A уже требует: непереводимое — `NOT_SUPPORTED`;
- в §7 новый пункт «запреты строкой» (отказ, перекрывающий разрешение);
- §6 показывает добавку `view sub: cam` к уровням камеры, которую обещает §7.4 (Kimi М4), и `view det` там, где уровень
  показывает тревоги детекторов (решение 4; запрос «Консоли» п. 3).

**Г15. Книги и индекс имён** (Kimi вопрос 3, Codex вопрос 4). Принять, норма — P/08.5, «Спецификация домена»:
- доставка ключа по гранту (Н1.3 `grant`) и индекс имён (Н1.7) берут `sub` = подсистему книги (`<sub>` из
  `domain/names/<sub>/<книга>`), а не `null`. Иначе строка `admin sub: rec` доставляла бы ключи книги `cam`;
- `grant too wide` сравнивает только ранг: строка с `sub` уже строки без него и шире её не бывает;
- §3 ADR вместо «`sub = null`, если норма не скажет иначе» называет это правило.

**Г16. Сверка субъектов без имени и роли** (Kimi вопрос 5). Принять: в §7.1 записать, что ADR ролей и групп обязан
научить сверку субъектов без имени (P/08.4 Н3, C08-GRANTS-ORPHAN-01) новым видам субъекта. Иначе она снимет строки
ролей и групп.

**Г17. Мелкие** — принять:
- М-1 (Claude): Confirmation «`last_admin` не считает строку с `sub`» снять, потому что проверить его нечем. В §1
  написать: «`last_admin` не меняется: в `domain/grants/domain` поля `sub` нет»;
- М-2 (Claude): `folder:` в `domain/grants/domain` — тоже 400 bad line, потому что папки живут на кластере (ADR-0096 В5).
  Приёмка — рядом со случаем `sub`;
- М-5 (Claude): id папки — только 128 случайных бит. Причина: гранты у держателя домена переживают переустановку
  кластера (ADR-0096 В4), и счётчик дал бы старой строке `folder:17` новую чужую папку 17. Это сужает выбор формы,
  оставленный норме ADR-0096 Г18; норма P/06 обязана взять эту форму;
- М-6 (Claude): новые поля `sub` входа и `folders` у `unit` и `about` — в форму входа `may` и `covers` вместе с
  векторами кода 2 на поля не по форме. P/07: модуль консоли собирает `folders` единицы обратным обходом составов из
  `GET /folders`; это назвать в норме подсказки;
- М-7 (Claude): в Consequences — «Neutral, because `admin sub: auto` двигает камеры через воркер `auto` без прав `cam`;
  это политика, совпадающая с `PROGRAMMING_SETUP`»;
- М3 (Kimi): `grants` в `GET /session` — по `(cap, sub, scope)`, нет `sub` — пустая строка, как порядок строк §1.

## Вопросы, которые решает «Архитектор»

**А1. Отметки `/marks` — `platform`** (решение 2; Kimi С1, Claude С-5, Codex 2). Решение 2 относит `/marks` к
`platform`, решение 4 — дерево `console` к `platform`. Следствие: человек с одной строкой `edit sub: cam unit:cam/7`
отметку о камере 7 не поставит (403) и чужих отметок о ней не увидит. Kimi и Claude предлагают `sub` единицы тела.
Варианты:
- (а) оставить `platform` при записи и чтении. Кто ставит и видит отметки, решает перевод §6: строки
  `edit sub: platform` и `view sub: platform` с той же областью. Строка `edit sub: platform folder:F` сверх отметок
  открывает только чтения `platform` о членах `F` (`/where`): записям папок нужен `admin`, дренажу и схеме — `admin`
  на `*`;
- (б) запись — `sub` единицы тела; чтение — `sub` подсистемы `of` отметки (`of` ставит сама консоль после проверки).
  Это исключение из решения 4 для дерева `console`.
Рекомендация: (а). Правило «`sub` события — дерево писателя» остаётся без исключений, а цена — одна строка в переводе
§6. Confirmation: отметка под `edit sub: cam unit:cam/7` — 403, под `edit sub: platform unit:cam/7` — 200.

**А2. Чужие права другой подсистемы через членство** (Claude Б-1, контрпример 2; Codex вопрос 1). Решение 3 требует
`admin` на единицу в её `sub`. Б держит `admin sub: rec folder:F`; A держит `admin sub: platform folder:F` и
`admin sub: cam unit:cam/7` и добавляет камеру 7 в `F`. Б получает `admin` архива камеры 7, хотя у A прав на `rec` нет.
Варианты:
- (а) `admin` на единицу **без `sub`** (любой областью): кто добавляет, держит всё, что папка может раздать;
- (б) как в решении 3, и записать политику: составом папки распоряжаются те, кому администратор домена дал `admin` на
  папку; строка `folder:F` любой подсистемы значит «права на то, что лежит в `F`»;
- (в) `admin` на единицу в каждой подсистеме, которую называет какая-нибудь строка `folder:` папки или её предков. Право
  зависит от чужих грантов и меняется при каждой их правке.
Рекомендация: (б). Администратор домена, который пишет `admin sub: rec folder:F`, выдаёт права на содержимое `F`, а
`admin` на `F` он выдаёт сам и знает кому. При (а) настройщик устройств consolem (`admin sub: cam`) не мог бы класть
камеры в папки, то есть папки consolem перестали бы работать. Политику записать в Consequences и в вопрос владельцу В1.

**А3. Сторожить ли членство в записи по праву `folder:`** (Claude М-4, Codex вопрос 2). Запись единицы, разрешённая
только строкой `folder:F`, может лечь после того, как единицу сняли из `F`. Варианты:
- (а) записать окно допустимым: отзыв гранта и так действует не сразу (`GRANT_LIFETIME`);
- (б) если решение дала только строка `folder:`, консоль кладёт в пакет стражей строки членства единицы и её `about` по
  прочитанным индексам; цепочку предков не сторожит. Удаление предка до жнеца членство не меняет, это окно остаётся;
- (в) стражи членства и всей цепочки: переименование любого предка давало бы 412 записям единиц — ложные конфликты.
Рекомендация: (б). Два стража на запись, ложных конфликтов нет (имя и порядок папки строку членства не меняют), а
перенос единицы и запись по старому праву не расходятся (`data-consistency.mdc`).

**А4. Путь записи грантов из `backend`** (Claude С-8, вопрос 4; Kimi С5, вопрос 6). Перечень обратного вызова `backend`
(ADR-0094 B1) — без грантов; писать `domain/grants` может только процесс `domain` через консоль домена. Варианты:
- (а) вне этого ADR: в §7 пункт «путь записи грантов из `backend`» (дверь консоли домена по билету второго вида, личность,
  `last_admin`, `grant too wide`, инвариант `unr`); до него `GET /access` и `POST /access/apply` остаются `NO_ROUTE`
  (V/11.2);
- (б) в этом ADR: дверь записи грантов в перечне обратного вызова — правка ADR-0094 B1 и договора пересылки.
Рекомендация: (а). Цель ADR — модель строки; транспорт к держателю домена — отдельное решение со своей безопасностью
(запись прав чужой личностью). Context ADR дописать: «потребитель первым — `backend`, путь записи — §7».

**А5. Создать единицу сразу в папке** (Kimi вопрос 4). Область `folder:F` не покрывает ещё не созданную единицу, поэтому
роль с одним `folderAccess {F: {cam: FULL}}` камеру в `F` не создаст. Варианты:
- (а) у создания с `folderId` вход `may` новой единицы получает `folders: [F, предки F]` из того же пакета, а `need`
  создания (сейчас `admin` на `*`, договор сторожевой) проверяет `admin` на новую единицу с этим входом. Создание
  проходит по `admin sub: cam folder:F` и `admin sub: platform folder:F`. Существующие единицы это не затрагивает, и
  решению 3 не противоречит: чужие права на новую единицу дают строки той папки, на которую у создателя `admin`;
- (б) создание требует `*` в подсистеме (или понижения `rights.routes`); роль только по папкам устройств не создаёт, §6
  называет это.
Рекомендация: (а). Без неё положительный грант по папке у создания не работает, а consolem создаёт устройство в папке
одной операцией.

**Решения «Архитектора» по А1–А5 (2026-10-30).**
- **А1 — (а):** `/marks` — `platform`; кто ставит и видит отметки, задаёт перевод §6 строками `edit/view sub: platform`.
- **А2 — (б):** составом папки распоряжается тот, кому администратор домена дал `admin` на папку, при условии решения 3
  (`admin` на добавляемую единицу в её подсистеме); политика — на подтверждение владельцу (В1).
- **А3 — (б):** стражи — на строки членства единицы и её `about`, не на всю цепочку (без ложных 412).
- **А4 — (а):** путь записи грантов из `backend` — в §7 (следующим ADR), `/access` до того — `NO_ROUTE`.
- **А5 — (а):** вход `may` новой единицы получает папку и её предков из того же пакета; `need` создания — `admin` на новую
  единицу.

## Вопросы владельцу

**В1. Замена В6 ADR-0096 и политика состава папки.** В6 (ответ владельца 2026-10-30): «до C3 папки пишет `admin` на
`*`». ADR-0097 §5 заменяет его правами по папкам, решение 3 разбора их ужесточает: запись папки — `admin sub: platform`
на папку или предка; добавить единицу — ещё `admin` на единицу в её подсистеме. При рекомендации А2 (б) вводится
политика: «кому администратор домена дал `admin` на папку, тот распоряжается её составом, и строки `folder:` любой
подсистемы следуют за составом». Совместимость выданных грантов не меняется: строки без `sub` значат то же, `admin *`
по-прежнему пишет любую папку. Рекомендация: подтвердить замену В6 и политику.

Других вопросов владельцу нет: решения 1–5 и группы сужают только новые строки с `sub` и `folder:`, выданных строк не
трогают.
