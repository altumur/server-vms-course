### Что нужно, чтобы MiniMax писал урок нашим циклом (по порядку)

1. **Решение, одно на VMS** (не мне: ADR-0125 п. 3, ADR-0129 доп. (24) — слово владельца): открыть ли формы VMS и какие классы форм берём. Без него формы писать нельзя.
2. **`check_forms.py`, `check_spec` и `loop.py` должны видеть `VMS/*/forms/`** (сейчас глоб — `Platform/*`). Это инструменты («Архитектор»/coord103-tools); запрос файлом во входящих, когда решение (1) будет.
3. **`forms/stages.tsv` на урок** (моя доля, когда разрешено): этапы с вратами `tests/vectors/build/accept`. Минимум по уроку: V/10 — 4–5 этапов; V/04–V/06 — 4 этапа; V/01–V/03, V/07 — 6–9 этапов.
4. **Закрыть дыры приёмки**: 24 главы норм без `acceptance/K/` (см. таблицу). Для главы без приёмки врата `accept:` невозможны; остаются `own_tests`/`vectors`. Если часть глав «не проверяется стендом» — записать это в README приёмки с причиной.
5. **`lifecycle.md`** и (если решение (1) это допускает) `daemon-flags.tsv`, `refusals.tsv` из существующих `refusal-words.tsv`.
6. **Векторы**: V/02, V/03, V/05, V/06 векторов не имеют; нужны ли — решает отбор кандидатов по ADR-0129 (ворота В1–В4), не опись.
7. **Профили стенда**: названия профилей и ключей `stand.*` в README каждого урока (как `V12-psim`).
8. **Пин VMS** (`VMS/PLATFORM_PIN`, ADR-VMS-0002): VMS судится по платформе пина — без него `check_spec` по VMS нестабилен.

Рекомендуемый порядок для первой пробы: **V/10 → V/04 → V/05 → V/06**, затем V/03, V/07, V/01, V/02, V/12. V/10 имеет полную приёмку и не зависит от других подсистем; V/04–V/06 малы и идут одной цепочкой.

### `0117|1|п. 2` — закладка `moment|span` (строка 1278)

Текст строки: «закладка moment|span: P/06.4 (доп. (3) п. 2, «Спецификации»), затем V/02.7 и mapping». Вердикт — **устарела, норма есть**:

- P/06.4 (`POST /marks`, поле `to`, `Platform/06-console/spec/06.4-console.norms.md:283`) — норма есть.
- `VMS/11-backend/data/mapping.tsv:605–606` (`Bookmark`, `type`, `to`) и V/11.4 Н1.24 (`POST /units/{uid}/bookmarks`, 422 `field: /to`) — норма есть.
