# Ревью ADR-0091 доп. (24)

Прогон: повторное ревью доп. (24), срез main `261f5fa1f`.
Охват: доп. (24) пп. 1–6 (`ready` — обещание, версия целым; `card.closed` для карточек оболочки; `digest` вида
`worker` у обоих писателей при `requests.key` и в метке; `unknown` только необъявленной эпохи, сбой — `incomplete`,
доказательство свежим чтением; имя подсистемы не с `free-`; мелкие). Закрытие находок разбора
`inbox/2026-10-23-ревью-ADR-0091-доп-22-23-разбор.md`.
Нормы: `Platform/common/contracts/request-mark.md` («Просьба» `digest`, «Метка»),
`Platform/06-console/vectors/request-digest/README.md`, `Platform/05-resource/spec/05-resource.norms.md` Н1.3 и
`05-resource.api.openapi.yaml`, `Platform/07-console-module/spec/07-console-module.norms.md` Н1.5,
`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`, `Platform/02-installer/spec/02.1-installer.norms.md` Н1.2.

## Вывод

С правками: 1 существенная, 4 мелкие. Решения верны; главная дыра — норма `digest` в `request-mark.md` и P/06.4
не названа адресатом, а она теперь спорит с п. 3.

## Проверено без находок

- П. 1, версия: «следующее целое» согласовано с `КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md` (:58: несовместимое изменение — новая
  версия, старые не отдаются; модуль и оболочка публикуются вместе) — подъём при совместимом добавлении не запрещён
  и безопасен.
- П. 2: `ref` карточки оболочки `<имя оболочки>:<ключ>` — согласовано с Н1.5 `objects` (`<prefix>:<…>` оболочки,
  модуль только хранит); `tab` — `id` вкладки из `addTab(kind, {id, …})`, однозначно.
- П. 3, метка: «метка копирует `digest`» — уже норма request-mark.md «Метка» («`digest` и `unit` переносятся из
  строки просьбы»), повтор после `settle` по метке согласован с `kept`; вид `client` у цели без `requests.key` — как
  доп. (23) п. 1.
- П. 4: `unknown` только необъявленной подсистемы, сбой чтения объявленной — `incomplete` — согласовано с P/06.4 Н3
  «слияние» (неответ — `incomplete`); «свежим чтением для доказательства, с возрастом — для отбора» не противоречит
  доп. (23) п. 4 (держать прочитанными можно, доказательство требует свежего).
- П. 5: запрет `free-` в имени манифеста (проверка каталога, P/02.1 Н1.2) снимает столкновение с грамматикой `rid`;
  «случайный `rid` воркера — без точки» не пересекается с формой `<подсистема>.<ключ>`.

## Находки

### Существенные

**С-1. П. 3 — норма `digest` в request-mark.md и P/06.4 не названа адресатом и теперь спорит с решением.**
request-mark.md «Просьба» `digest`: «у поданной дверью — JCS тела клиента после схемы без полей сервера…; им
сравнивают повторы»; владелец векторов — P/06.4 (Н1.5 `digest`, Н3 «подать просьбу» шаг 1). Доп. (24) п. 3: у цели с
`requests.key` дверь пишет в строку и в метку `digest` вида `worker`. Названный адресат — только README векторов
(п. 6); строка нормы в request-mark.md и глава P/06.4 остаются с прежней формулой — после правки README договор и
урок будут противоречить друг другу.
Правило: ADR-0080 (договор — часть нормы); ADR-0091 доп. (24) п. 3.
Рекомендация: назвать адресатами request-mark.md («Просьба» `digest`, «Метка») и P/06.4 Н1.5/Н3 шаг 1; продлить
строки `digest.tsv` случаем «дверь у цели с `requests.key` — вид `worker`».

### Мелкие

**М-1. П. 1 — не сказано, что свойство `ready` вносится в Н1.5.** Доп. (22) п. 1 («в норму вносится») говорило о
вызове `ready()`; п. 1 (24) заменяет его свойством-обещанием `pc.ready` — но закрытый перечень контракта модуля
(Н1.5 `adds`) это свойство не получил; страница ждёт то, чего норма не даёт.
Рекомендация: записать «свойство `ready` — в Н1.5 `adds` вместо вызова `ready()`».

**М-2. П. 2 — `card.closed` по-прежнему без адресата в норме** (повтор незакрытой М-2 прошлого прогона): событие
расширено на карточки оболочки, но закрытый список `events:` Н1.5 (`on("select") | on("refresh") | on("logout")`)
его не содержит и адресат не назван.
Рекомендация: «`card.closed` вносится в `events` Н1.5».

**М-3. П. 4 — формулировки «`epoch_is` и `fenced` ставит консоль при слиянии» остаются.** P/05 Н1.3 (:150, :195,
:773) и description схемы OpenAPI: участником слияния теперь является и воркер (`events-merge`, доп. (21) п. 1);
п. 4 называет адресатами только перечень и схему.
Рекомендация: «ставит участник слияния (`events-merge`)» — в Н1.3 и description схемы.

**М-4. Приёмка не продлена.** Новые нормы без приёмки: `digest` вида `worker` от двери (строки `digest.tsv`),
`epoch_is: unknown` (вектор `events-merge`), `pc.ready` и `card.closed` карточек оболочки (jsdom-тесты модуля);
п. 6 называет только README и проверку `shell.may_not`.
Рекомендация: назвать строки векторов и jsdom-случаи приёмкой пп. 1–4.

## Счёт

- Блокеров: 0. Существенных: 1. Мелких: 4.

## Самые важные

1. С-1 — без правки request-mark.md и P/06.4 норма `digest` спорит с п. 3: договор и урок разойдутся.
2. М-4 — четыре новых поведения (24) без приёмки.
3. М-2 — `card.closed` второй прогон вне закрытого списка `events` Н1.5.
