# Вопросы М11/5 «Книги из строк членов»

Свидетели — курс (заморожен) и продукт. Взято без вопроса (ADR и прежние решения): `domain.books.<книга>: {from, key,
pick, to, show?}`; конверт секрета — `x25519:v1` урока 2; держатель отчитывается о себе подписанным отчётом (ответ на
записку п. 5); книга члену — в `sealed` ответа держателя (урок 3 Н1.5, конверт `m1`); индекс имён и гранты — урок 9.
Ниже — развилки с рекомендацией.

## 1. Вклады в отчёте и форма `from`

Курс — поле `rows` публикации (`{path: {items: {item: JSON-текст}, idx}}`), `from` из нескольких сегментов; продукт —
`objects` по ключу строки (`{item: объект}`), `from` — `<sub>/<строка>` или семья `<sub>/<строка>/` одним сегментом,
`to == key` — отказ загрузки.

**Рекомендация — продукт целиком:** вклад — объект `objects["<sub>/<строка>[/<писатель>]"] = {<item>: <объект>}` (урок 3
Н1.2 уже называет «строки вкладов» среди объектов), `from` — один сегмент, `to` ≠ `key`.

## 2. Живость строк вклада

Курс: фильтр по слоту у всех строк, `now < until`, слот перечитывается после строки; чистка при **каждом** захвате, в
том числе своего имени и предложения запасному. Продукт: только у семей, `now ≤ until`, без перечитки; чистка — когда
прежний держатель слота не этот экземпляр, у предложений запасному — нет.

**Рекомендация:** у семей (`<sub>/<строка>/<слот>`) — живость слота по М10/3 (держатель непуст, `released` нет,
`now ≤ until` по часам члена), слот перечитывается после строки (курс: дешёвая защита от гонки с освобождением);
одиночная строка `<sub>/<строка>` — без фильтра (у неё нет слота). Чистка при захвате, когда прежний держатель — не
этот экземпляр, **включая** захват по предложению запасному (иначе запасной начнёт с чужих строк).

## 3. Член не `ok` и испорченный вклад

ADR-0074 и записка: «член без свежего отчёта в окне `lost_after` хранит книгу, за окном — нет», «испорченный вклад снимает
весь вклад члена», «`missing` всегда». Курс: потерянный — не вкладывает и **не** в `missing`; испорченный — снят и в
`missing`. Продукт: потерянный — в `missing`; испорченный — снят, но **не** в `missing`.

**Рекомендация:** вкладывает член `ok` и `unseen` (копия есть, урок 1); `unseen`, `silent`, `never` — в `missing`
(ответ о нём неполон); испорченный вклад (не объект, нет `key`, плохой `to`, повтор `key` при `unique`, секрет не
открылся) — весь вклад члена снят **и** член в `missing` с причиной. Одно правило: «чего нет в книге из-за члена — тот в
`missing`».

## 4. Получатель не член

Курс — элемент пропускается целиком; продукт — элемент идёт принятым получателям, прочие считаются `undelivered`.

**Рекомендация — продукт:** элемент доставляется каждому принятому получателю из `to`; непринятые — в диагностике.

## 5. Дверь книги

Курс: консоль кластера показывает книгу этого члена (на держателе — его собственную строку), отдельная дверь консоли
домена сводит строки всех получателей. Продукт: только консоль кластера, на держателе — сводка всех членов без порядка,
элемент `""` пропущен.

**Рекомендация:** одна дверь `GET /domain/<sub>/books/<книга>` консоли кластера — книга **этого члена** (как ему
доставлена; у держателя — его строка), с `""` → `{missing}` и ключами `{entries: [{<поля show>, member, item}], missing}`
в порядке `(member, item)`; книга без `show` — 404 «carried and not shown». Сводка по всем членам — не дверь урока 5.

## 6. Учебный потребитель: кто пишет вклады `testsub2`

Ни курс, ни продукт строк `testsub2/notes/`, `rolls/`, `counts/` не пишут — только тесты. Без писателя книга на стенде
пуста.

**Рекомендация:** учебный писатель вкладов — обязанность стенда реализации, как обработчик дозаписи М10/8 Н5: воркер
`testsub2` под своим слотом `t-N` пишет для каждого счёта, который ведёт, элемент `<имя счёта>` в
`testsub2/notes/<слот>` `{ref: <name>, to: <to>, note_secret?: <note_secret>}` и в `testsub2/rolls/<слот>` `{ref, to}`,
и объект `testsub2/counts/<слот>` `{tallies: <число>}` (`domain.reports`). Байты `testsub2` получают поля счёта
`to: {type: list}` и `note_secret: {type: string}` (долг продукта — синхронизация). `show` у `notes` — `[ref]`, чтобы
дверь книги отвечала.

## 7. Приёмка

Стенд урока 3 (`hold`, `m1`, `m2`) с каталогом `testsub` + `testsub2` (их контроллеры и воркеры `testsub2` на каждом
члене) и чистая функция `assemble` (вход — копии членов, их состояния, список членов и каталог; вывод — строки книги
каждого получателя): `unique`-конфликт, испорченный вклад, `missing`, порядок, получатель не член — векторами;
доставка, секрет через `x25519:v1` и дверь книги — стендом.

Строки реестра (прошу):

```text
М11_Domain/05	acceptance-entry	inputs	входы команды assemble (копии членов с вкладами, состояния, список членов, тестовые ключи); проверяется по README приёмки
М11_Domain/05	scenarios-format	own	стенд нескольких кластеров с testsub2 (двери holder, member; директивы урока 3) и векторы assemble; проверяется по README приёмки
```

Если п. 1–7 — «да», пишу урок по ним.
