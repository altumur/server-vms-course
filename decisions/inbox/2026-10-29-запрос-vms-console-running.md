# Запрос: два определения ряда `<sub>_<console.running>` в P/06.5

**Какая норма мешает.** P/06.5, таблица выдач, строка «ряд `<sub>_<console.running>`»: «число единиц из прочитанных
пульсов воркеров, кроме элементов `phase: sealed` и `phase: unreadable`». Там же, Н3 «Ряды манифеста `metrics[]`», `agg:
count` с `equals`: «одна строка без меток источника: записи всех воркеров, чьё поле — слово из `equals` (ряд
`console.running` — так)». Манифесты VMS объявляют ряд `console.running` метрикой с `equals: running` (`det`, `detjob`,
`rec`, `detedge`): по второму правилу ряд считает только `phase: running`, по первому — все единицы, кроме `sealed` и
`unreadable`.

**Контрпример.** `detedge`: у воркера три обхода — `running` (читает), `caught_up` (догнал край), `waiting` (нет свободной
сессии). Ряд `detedge_watches_running` по таблице выдач — 3, по правилу `count`/`equals` — 1. Урок V/06.4 Н1.4 говорит
«читающие обходы» (1); консоль, написанная по таблице выдач, отдаст 3.

**Рекомендация.** Одно определение: ряд `<sub>_<console.running>` — метрика манифеста, которую называет `console.running`,
посчитанная по её объявлению (`from`, `agg`, `equals`, `live`) как любой ряд `metrics[]`; исключение `sealed` и
`unreadable` — для объявления без `equals` (или снять, если метрика его всегда задаёт). Строку таблицы выдач свести к
ссылке на Н3.

- Правит «Спецификация»: P/06.5 таблица выдач, приёмка `/metrics` (единица в фазе не из `equals`).
- Класс VMS: `det`, `detjob`, `rec`, `detedge` — ряды с `equals: running`; уроки остаются как есть.
