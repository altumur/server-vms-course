# Второй пилот: части кластера на общем состоянии — задача «Спецификации»

## Контекст
ADR-0083 доп. (2) п. 9. Отчёт — `/Users/murat/w2c/cammeta-interop2/REPORT.md`. Пары: Python `7640940` и Go `814481b` на
`9b30c06`. Двенадцать смешанных сборок, обе базы — 479/479 на уроках 03–11, и девять сценариев на общем состоянии.

- **Контроллер и консоль заменяемы по контракту.** 0 расхождений в обе стороны, в том числе:
  - смена контроллера посреди прохода, когда чужой intent доводится до `idle`;
  - просьбы и жнец;
  - снимок;
  - секреты: `enc:v2` и кольцо читаются другой реализацией.
- **Воркер и ресурс по отдельности не заменяемы.** Их связывают файлы коробки, которые спецификация отдаёт реализации:
  - **замок присутствия.** Мёртвый воркер держит единицы 900 с вместо `move` через 45 с, а живой считается `gone`;
  - **источник класса тревоги** — поле или дерево;
  - **кодирование имён файлов.**
- **Строк хранилища и дверей хватило целиком.** Несовместимо только «решает реализация» — файлы одной коробки и жизненный
  цикл процесса. Пилот подтверждает пять видов контракта ADR-0083.

## Решение «Архитектора»
1. **Н-1, присутствие — нормой**, снять «решает реализация» (М10/5 п. 3, М10/8 Н1.4, М10/11 п. 5).
   - Замок — `<корень событий>/.workers/<sub>/<экземпляр>.lock`, содержимое JSON `{instance, sub, worker, server, pid}`.
     Воркер держит исключающий `flock` всё время жизни.
   - Ресурс пробует `flock` без ожидания: взял — `gone`, занят — `runs`, не прочёлся — `unknown`. «Известные» воркеры —
     только по замкам.
   - Файловый контракт урока 5 (каталог данных: строка `file`, участники `append`/`put`).
   - Шаги урока 11: старт ресурса и воркера → `running`; `@sigkill` → `running: []`; повторный старт → снова `running`.
   - Шаг урока 5 с ресурсом: `@sigkill` → назначение снято за 60 с.
2. **Н-2, класс события — из поля `class` строки.** Индекс его не переопределяет. Раскладка `.alarms` — у писателя, для
   всех деревьев, включая `audit` и `console`. Директива `@put event` и шаг: тревога в `audit/…` → `class: alarm`.
3. **Н-3, кодирование имён в общих деревьях** (объекты, события) — вариант (а).
   - Знаки вне `[a-z0-9._-]` — `%XX` строчным hex по байтам UTF-8.
   - Компонент длиннее предела — `%h<sha256>` и файл-исходник рядом.
   - Это исполняет решение сверки 3–5 п. 14: любое имя по грамматике хранит любая реализация.
   - Шаг урока 8: отметка консоли с `:` в имени экземпляра → `unit` раскодирован.
4. **Н-4, каталог данных и канал настройки процесса** — в файлы жизненного цикла (ниже).
   - Процессы платформы настраиваются только окружением М10/11 Н1.2 и аргументом имени воркера. Собственных флагов путей
     нет.
   - Раскладка `PLATFORM_DIR`:
     - хранилище — `<PLATFORM_DIR>/configstore`;
     - объекты и события — свои корни;
     - замки присутствия — в корне событий;
     - кольцо — вне `PLATFORM_DIR`, корня объектов и корня событий.
   - README 01 «Стенд»: `{data}` — это `PLATFORM_DIR`, стенд переводит подстановки в окружение.
5. **Н-5** — `spec-put` уже нормирован и исполнен раннерами `7168959`. Ничего не делать.
6. **Н-6, права частей.** Сверь, что `06/variants` покрывает R2, R5, R9. Если нет — шаги:
   - `@as resource store GET …testsub/alarms_retention` → 200;
   - `@as testsub2worker … testsub/marks/x` → 403.
7. **Н-7, договор учебного обработчика `testsub`:**
   - слово счётчика в `status` — одно, выбери по спеке `testsub`;
   - причина `sealed` — поле `why`, как у остальных причин платформы (`fates.why`). Не `error`.
8. **Н-8** — профиль `file://` только для коробки одной реализации. Уже нормировано пилотом 1.

**Файлы жизненного цикла теперь не блокированы.** `NN-<процесс>/lifecycle.md` для 01–06 и 08–10 составляются по Н-4 и
§ 5.3 отчёта пилота — это готовые строки. Сюда же:
- первого пилота: `FORMAT`, флаги демона, копия;
- кольца и замка присутствия.

Дефекты Б1 (Python: замок не переписывается после SIGKILL) и Б2 (Go: при `EVENTS` замок и поиск в разных корнях)
уходят генераторам после нормы Н-1.
