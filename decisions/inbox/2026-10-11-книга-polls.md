# Путь опроса без записи: `polls`

## Контекст

В курсе `a31b0c59` `Source/vms/domainpart/crossing.py:412` создаёт `polls` только для камер,
которые держат опрос и никем не записываются. `_poll_home` учитывает ретранслятор, центр и держателя.
`CameraPusher` в `domainpart/ingest.py:1961` сначала читает `primaries`, затем `polls`; назначение опроса
не должно выглядеть как основная запись и выключать запись карты.

## Рекомендация

Рекомендую издателем обычный рекордер, хостящий выбранный ingest, а выбор кластера обслуживания выполнять
размещением, не `pick`. Передать книгу подсистеме `rec` для собственного входа; смена имени ниже требует
явного решения Архитектора. Камера получает `stream` токен сама по своей роли, вместо выпуска в domainpart.

| Звено | Предложение |
|---|---|
| Издатель | `RecWorker` выбранного узла опроса; публикует готовность своей двери для назначенной камеры. |
| Вход | `rec/polls`: `ref`, `urls`, `cluster`; токен не является наблюдением готовности двери. |
| Правило | В `rec.subsystem.yaml`: `polls: {from: rec/polls, key: ref, pick: unique}`. |
| Получатели | Только домашний кластер указанной камеры. |
| Читатель | Компонент опроса камеры после переноса `CameraPusher` из domainpart. |
| Результат | Предлагается `domain/rec/polls` с существующей схемой доставки по членам. |

Камера за ретранслятором получает доступный ретранслятор, не недостижимый центр. Выбор пути по топологии
выполняет предметный воркер в пределах назначенного размещения; платформа не знает камер и ingest.
Несколько процессов на выбранном кластере не должны все публиковать `ref`: право издателя связано с
назначением конкретной единицы. Не вводить дополнительный процесс или слот у держателя ради этой книги.

Не записываемая камера сейчас не имеет единицы записи `rec`. Поэтому до реализации нужно согласовать,
какая существующая единица/назначение даёт рекордеру право обслуживать её опрос. Рекомендую явное
назначение обслуживания без создания фиктивной записи; если имеющаяся модель его не выражает, отдельная
форма размещения обязательна. `unique` не решает этот недостаток и не выбирает одного из добровольцев.

При `missing`, конфликте или неготовой двери новый опрос не запускается по неподтверждённому адресу.
Существующий сеанс подчиняется сроку токена и действующему правилу работы без управления. Получение `polls`
никогда не означает `running` основной записи. При появлении записи старый вклад опроса снимается;
при исчезновении записи он восстанавливается только после готовности назначенной двери.

Новые пути: `rec/polls`, `domain/rec/polls` и экземпляры по членам. `ref` нужно добавить в объект входа.
Альтернатива — вклад VMS-воркера о чужой двери; не рекомендую, он не может подтвердить готовность ingest.

## Приёмка

- Камера без записи принимает команды через свой ретранслятор и продолжает писать карту.
- Появление/снятие основной записи переключает `primaries`/`polls`, не оставляет два спорящих назначения.
- Падение выбранного ingest не приводит к случайному выбору другого по времени или порядку обхода.
- Камера не получает адреса и токены другого получателя; после переезда прежний издатель отсечён.


## Отличие от принятой формы

Дополнение ADR-0074 сохраняет существующее имя результата. Смена подсистемы-владельца в этой записке
меняет полный путь результата и потому требует явного уточнения ADR Архитектором. До такого решения
действует прежний путь VMS. Это предложение, а не разрешение исполнителю переименовать книгу.

## Общие условия переноса

Это предложение до кода. Реализация начинается после шага 5 ADR-0070 и ответа Архитектора в этом файле.
Форма результата — утверждённые `entries[{member,item,value}]` и обязательный `missing`; принадлежность
ставит платформа, время полезной нагрузки не выбирает победителя. Потерянный по виду домена член за
`lost_after` исключается; член в окне без свежего отчёта входит в `missing`. Пустой вклад, отказ чтения и
незавершённый отчёт различаются. Удалённый вклад не возвращается от повторной доставки старого поколения.
Для пустой книги нужно отдельно подтвердить, где передаётся `missing`, если нет ни одного ключа результата.

Входная строка общая для кластера: каждый обычный воркер меняет только принадлежащие ему элементы, через
CAS с сохранением соседних. CAS сам по себе не отсекает прежнего владельца; право записи элемента должно
проверяться по действующему владению/epoch при публикации. Нельзя вводить отдельного доменного писателя
для сборки этой строки. Если действующий контракт этого не обеспечивает, форму общего механизма согласуем
до кода. Свежий агент не превращает оставшийся вклад умершего воркера в актуальный факт.

Адресная доставка не выражается `from/key/pick`. Указанные ниже получатели — требование к её отдельному
предложению, а не неявная реализация фильтра в платформе. До её утверждения книгу не переводим и не рассылаем
всем. Токены получает нуждающийся в них воркер через `tokens.<вид>.grant`; доступ к ключу подписанта не нужен.
Новые имена из этой записки не действуют до решения. После принятия — спека и долг `# ADR-0074 «курс»` одним
коммитом курса; код платформы, спеки и общие таблицы остаются в ветке до чтения diff Архитектором. Продукт не трогаем.
