# P/07: исправления после двух независимых ревью

**Исполнитель — spec103 через coord103. До правок — точная база, список файлов и пересечения с прежними поставками. Публичные байты меняются один раз для всех потребителей.**

Основание: ADR-0129 (18), разбор `2026-11-07-ревью-P07-ADR0129-разбор.md`. Источник находок 10f2; это не разрешение переносить старое дерево поверх новых изменений. Замороженный Source/w2cplatform, VMS/11 и форк consolem не править.

1. Объявить отдельные группы: классификация путей С1/С2; редакторы С3/С4; подсистемная принадлежность С5/М2; доменный pending С6; пагинация С7; off и исторический указатель. EN/RU, поверхность, инструкции и точные ссылки публикации входят по фактическим зависимостям. Не менять словарь сверх необходимых подписей; единственный источник строк — localization.tsv.
2. Пути: разделить путь и query до классификации, узнавать короткий/полный корень и монтирование по действующему каталогу. Запрещённая дверь с query не получает ifMatch. Не декодировать произвольно сегменты, не вводить алиасы или новый список дверей. Исходный адрес запроса, CAS, ключ действия и правила повторов сохраняются.
3. Int: не использовать усечение parseInt как преобразование допустимого ввода. Проверить 1e3/1000, дробь, пустоту, неверную запись, оба края безопасного диапазона. JSON двери остаётся обычным целым без дробной/экспоненциальной записи. Неподдержанный ввод остаётся в форме и не отправляет другое число.
4. Списки: типизированное значение переживает отображение и изменение другого элемента. Проверить строку с запятой, пустую строку и простой сосед; без незаявленного trim, удаления дублей или сужения обычных списков до placement labels.
5. Воркеры: до кода — план достоверной подсистемной принадлежности на существующем публичном договоре. Прочитать закрытый WorkerRow и все производители/потребители; показать недостающее представление, если требуется уточнение договора. Корень, первое совпадение имени, запрет одинаковых имён и чтение внутреннего хранилища из JS не решения. Отдельное согласование Архитектором до правки API.
6. Pending: нынешний integer ≥0/null по члену и отдельные массивы outcomes. Проверить 0, 1, null и несколько членов; массив прежних описаний не положительный вход и не новый поддерживаемый формат. J-P07-01 — отдельная тестовая доля на том же замороженном кандидате.
7. Cursor: обе ветви загрузки домена. Прежде кода перечислить способ сборки действующих шести проекций, сохранение глобальной части и полного contested-контекста без повторного добавления фактов. Вернуть непрозрачный токен, не разбирать его. Проверить 20/1000/1001 членов, несколько страниц, пустые ключи подсистем и отказ продолжения; не обещать межстраничный снимок или полный успех при неполноте.
8. Off: исполнить существующее описание отключённого раздела с причиной; ни мышь, ни клавиатура не вызывают render отключённого раздела. Включённый сосед работает. Согласовать N1.5/N5 и поверхность без нового права сервера. Исторический id-map убрать из активного текста и зеркала.
9. Проверки читают нынешние три canonical-файла. Объявить реальные пути и SHA, использование обрамляющих VMS/holder-фикстур, инструментирование return и подставной shell-short. Ошибка, неполный вывод и старый положительный формат не успех. Прежние открытые C6/A1/N5/P07-07/08 не закрывать попутным числом тестов.
10. Отдельно сверить ссылки публикации P/06.5 и P/10, упаковку общих байтов и предметные проверки канона. Нового выпуска, выгрузки, линии, установки зависимостей, второго JS, Go/SDK/HTTP-стенда или модели этим поручением нет. Исполнение существующих изолированных JS-проверок на опубликованном модуле допустимо. Готовность урока — только после самостоятельной приёмки coord103.

Первые общие пути P/03 и согласованные области P/04–P/06 сохраняются. Не добавлять сюда исправление J-P05-02/J-P06. Пересечение производных @file и общего OpenAPI перечислить до кода. Если общий файл уже закреплён другой поставкой, coord103 согласует точный стык без расширения задачи.
