# План урока P/02 (Manifest and installer) с учётом работ по P/01 — Архитектор, 2026-11-10

Поручение владельца: «сделай новый план урока 2 с учетом всех работ по 1». Прежние задачи P/02 (P02.5, P02.6, P02.B1) ждут вывода эксперимента по P/01 (слово владельца 2026-11-10, ADR-0134 доп. (34)); этот план их заменяет. Работа ведётся окнами под задачу (ADR-0134 доп. (34)).

## Что P/01 показал и что из этого следует для P/02

| Урок P/01 | Для P/02 |
|---|---|
| Без обратной связи по поведению модель закрывает этапы, не сделав главного (группа в попытках 3, 4); трассировка норм дала это поведение в попытке 5 (ADR-0133 доп. (43)) | Каждый пункт перечня норм на ровно одном этапе (`stages.tsv`, столбец `norms`), `check_spec` проверяет покрытие; трассировка включена с первой попытки |
| Проверки кода как данные (`code-rules.tsv`, ворота `code:*`) шли на всех этапах попытки 5 | Строки `code-rules.tsv` урока по словарю `common` до первой попытки |
| Фильтр путей M трижды отставал от состава M | Паспорт M (`P01.131`) с первой попытки, шаблоны путей не используются |
| Копия зависимостей в дереве через `replace` | Норма уже общая (`versions/README.md`, `requires_module`); для P/02 — строка `requires_module`, если урок тянет модули |
| Судья сгенерирован один на все уроки; «новый урок не требует нового кода» подтверждается только на втором уроке (ADR-0135 доп. (2) п. 10) | P/02 — эта проверка. У P/02 нет строк в реестре целей судьи (`targets.tsv`, `targets.routing.tsv`) — без них движок урок не судит |
| Расхождения судей разбирались по классам и превращались в механические правила (ворота, правки спеки) | Раннера больше нет (ADR-0135 доп. (10)); на P/02 точка калибровки — красный набор и ревью красноты по классам (окно judge Kimi) |
| Пробы прозой (extra) не исполнимы без кода под урок; машинная форма и закрытый словарь (`P01.142`) | Все пробы P/02 — данными в грамматике `scenarios.tsv`; новых слов — минимум, через общий README |
| Боевая проверка с D7 — этап системы (ADR-0130 Addendum (19)); минимальный набор без D7 — в функциональном суде (п. 7, `P01.149`) | Для P/02 — свой минимальный набор без D7, если у урока есть процессные пробы; иначе ничего |
| Смена входа посреди работы сбивала модель (`P01.146`); ворота должны называть источник (`P01.148`) | Пара выгрузок и J-вход фиксируются до старта; правки нормы — новой парой, не посреди попытки |

## Порядок

**Шаг 0. Навык.** `skills/lesson-spec` дополнен разделом «Готовность урока к варианту Б» (этот же коммит): список того, что урок обязан иметь до первой попытки. Им пользуются писатели и ревью P/02.

**Шаг 1. Аудит готовности P/02** (окно run, писатель спецификации; приём — окно judge). По списку навыка: что есть, чего нет, с местом. Известно уже: 79 пунктов перечней в пяти главах, 9 этапов, столбец `norms` без номеров пунктов, `code-rules.tsv` нет, строк в реестре целей судьи нет, двух строк в `consumers.tsv` — есть.

**Шаг 2. Правка спецификации P/02** по аудиту, частями (окна run, один писатель на участок; приём — окно judge):
- 2а пункты перечней → этапы в `stages.tsv` (каждый ровно раз);
- 2б `code-rules.tsv` урока (кандидаты: чистое ядро загрузки и канонизации манифеста, `table_driven` для `daemon-flags.tsv`, `operator-commands.tsv`, `refusals.tsv`, `exhaustive` для перечислений, форма шага для `rollout-poll`);
- 2в реестр целей судьи P/02: `targets.tsv` (M) и `targets.routing.tsv` (J), сценарии и векторы общего словаря, `consumers.tsv`;
- 2г пробы прозой → машинная форма; минимальные боевые пробы без D7 — если применимо;
- 2д ревью спецификации окном judge (Kimi), исходы «норма» — в ту же правку.

**Шаг 3. Движок на P/02 без нового кода.** Механические ворота движка на J-входе P/02; красное здесь — либо пробел общей приёмки (правка `common`), либо код движка под урок (дефект движка). Это проверка ADR-0135 доп. (2) п. 10.

**Шаг 4. Пара выгрузок P/02** с паспортом M; задание попытки (трассировка, ворота `code:*`, `stages.m_passport`).

**Шаг 5. Генерация P/02** — после вывода эксперимента по P/01 и слова владельца о варианте (ниже).

**Шаг 6. Суд движком, красный набор, пакеты и ревью красноты по классам** — как P01.126–P01.128.

Шаги 1–3 не ждут вывода по P/01 и могут идти сейчас; шаги 4–6 — после него.

## Вопрос владельцу (нужен до шага 4)

Как генерируется P/02:
- **(а) поверх кода P/01** — кандидат P/01 попытки 5 (если её суд зелёный) — вход модели, P/02 добавляется в тот же модуль (задача P02.7 «генерация с нуля поверх кода предыдущих уроков»);
- **(б) P/01 и P/02 вместе с нуля** — одна генерация двух уроков.

Рекомендация: (а) — она отвечает на вопрос «подходит ли модель для следующего урока» без повторной оплаты P/01 и проверяет, что кандидат P/01 пригоден как основа.
