# P01.319: источник давления шлюза и полные файлы стенда в Q

## Context and Problem Statement

Квалификатор получает PSI cgroup контейнера или systemd unit-а стенда и три ранее
пропущенных файла стенда целиком. Это исполнение вопросов 1–2 круга 1 P01.295 по
заданию P01.319, без новых норм кандидата. Источник находок —
`/home/pilot/owner-receipts/P01.295-qualifier-circles-20261113T0922Z/INDEX.md`.

Исходный срез — `aba38d58ba18b08111b65b13af9ee4fcd515adac` (`origin/main`).
Коммит спецификации — `b9b5518607391dc28589f9dae0108099918c46d9`.
Рабочий каталог — `/home/pilot/wt-task-P01.319`, ветка — `task/P01.319`.

Оба пробела были раньше: исходный Q P01.304
`1a6a67b47cb11a89bf1a360d6002cd11138f29bd` из C
`e7b04900c7ca9fcde3dd1b7821d547e75f0531f3` содержит прежний R021 без
источника PSI и опись без трёх файлов; то же подтверждено на исходном срезе задачи.
Неполная опись появилась при создании фильтра в
`2943ea698996171c96bdee81967bfaed8799b28f` (P01.294).
Момент появления неопределённости источника PSI до этого среза не установлен.

## Considered Options

1. Включить существующие файлы стенда целиком и дать ссылку на единый шлюз N3.3.
2. Пересказать нужные части этих файлов в README квалификации.

## Decision Outcome

Выполнен первый вариант, как требует задание: копий правил стенда нет.

- В `Platform/common/acceptance/spec/acceptance.norms.md`, P/AC-R021, N3.3,
  источник давления — cgroup контейнера или systemd unit-а стенда:
  `cpu.pressure`, `memory.pressure`, `io.pressure`. `/proc/pressure/*` записывается
  только в отчёт и не определяет исход шлюза. Пороги прежние: `some avg60` ниже 1
  для cpu и memory, ниже 5 для io на протяжении 180 с (ADR-0083 доп. (49) п. 1).
- `Platform/01-store/qualification/README.md` ссылается на N3.3; пороги там не
  повторяются. Оба русских зеркала приведены в соответствие источникам.
- `Platform/common/qualification-input-filter.json` дополнен ровно тремя
  записями `include`: `Platform/common/acceptance/stand.md`,
  `Platform/common/acceptance/forms/profile-substitutions.tsv`,
  `Platform/01-store/acceptance/3/README.md`. Их исходные байты не менялись.
  Существующие 27 записей сохранены, 30 путей уникальны и упорядочены по UTF-8.
- Происхождение записано в `decisions/journal/platform/common/history.tsv`,
  `decisions/journal/platform/01-store/history.tsv`; уточнение толкования приёмки —
  в `decisions/journal/platform/common/corrections-system.tsv`.

Поиск по всем `Platform/**/*.md` определений `pressure stall`, `avg60`,
`/proc/pressure`, `cpu.pressure` нашёл только общую норму и её русский перевод.
Других определений этого шлюза в уроках P/01–P/10 не найдено.
Класс пропуска зависимостей проверен на всём фильтре: старые записи не менялись,
три добавления сохранены целиком. Проверка не объявляет замыкание всех ссылок Q
и не расширяет задачу на другие зависимости.

### Consequences

- Good, because чужая нагрузка из `/proc/pressure` не решает шлюз стенда.
- Good, because квалификатор читает исходные определения запуска, подстановок и
  группового стенда, включая `SERVER_NAME`, `-id` и `{index_base}`.
- Bad, because три целых файла увеличивают Q; дальнейшие зависимости остаются
  явными записями описи и автоматически не добавляются.
