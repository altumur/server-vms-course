# Задача команде: зеркало окон 3 и 4 ADR-0075 в курсе (продукт — main 2e7bdf3); после окон 0–2

Форма — ADR-0075, дополнения 6 (окно 4 с уточнениями 1–5) и 7 (окно 3); код продукта не читать (правило 15). Делать после
задачи «зеркало окон 0–2».

## Окно 4 — TLS между кластерами
Запись члена `domain/members` получает `ca`: до двух sha256 (hex) DER-сертификата CA кластера, третий — отказ со словами;
член публикует отпечатки своим подписанным отчётом полем `tls_ca` (из `ca.pem` и `ca.next.pem` своего каталога TLS);
держатель пишет их в запись на проходе без ручного шага, журнал `domain.member.ca`; публикация без `tls_ca` запись не
чистит; за ретранслятором — под поручительство ретранслятора; `POST /domain/members/<м>/ca` (admin) — ручная замена при
краже; имя оператора — от гейта, не из заголовка. Держатель — в списке членов с первого срока (шаг прохода, свой ключ
члена, `ca` из комплекта; дефект ADR-0066 доп.), и запись держателя `domain/holder` несёт `ca` рядом с `url`
(подписант пишет при заявке и смене CA; одно происхождение, расхождение — ошибка шага). Отпечатки членов, как их знает
кластер: более поздняя по rev копия списка плюс запись держателя. Сверка чужого сервера: цепочка «лист + CA», CA с
отпечатком члена назначения, лист им подписан, роль по SAN URI, имя по SAN DNS, IP — отказ; без отпечатка — отказ
«чужая CA — окно 4» со счётчиком. Переключатели `SIGNER_TLS=1` (роль `domain`), `RELAY_TLS=1` (`domainagent`); первый
контакт — `DOMAIN_CA`/`RELAY_CA` от оператора только до первого уноса, `RELAY_MEMBER` обязателен при https-ретрансляторе;
после переезда данная дверь спрашивается только по `DOMAIN_CA`. Двери рекордера между кластерами — взаимный TLS, дверь
принимает свой CA и CA членов по отпечаткам, знает члена звонящего. Записи дорог (`IngestEntry`, `UpstreamEntry`,
`AskRoad`, книга опросов) — поле `cluster` рядом с `urls`; камера и форвардер звонят с членом по нему. Отдельный
слушатель ingest `RECORDER_INGEST_HOST/PORT/TLS` (TLS сервера, роль `recworker`); браузерная дверь без изменений. Смена
CA: `ca.next.pem` → два отпечатка → новые листы → один. Двери переезда — не окно 4. Домен между машинами с окна 4 требует
комплекта у каждого кластера.

## Окно 3 — консоли
Одна дверь консоли: `CONSOLE_TLS=1` (кластер) и `DOMAIN_CONSOLE_TLS=1` (домен), включено без комплекта — отказ старта;
сертификат роли `console`; клиентский сертификат по желанию — показан: своя CA или CA члена по отпечатку плюс роль, журнал
называет роль и члена один раз; не показан — браузер по токену; решают токены и подписи. `CLUSTERS` — `https://…`;
консоль → консоль члена и → консоль домена с членом по имени из `CLUSTERS` или держателю записи. CA кластера у
оператора в доверенных — строкой в описании; `/metrics` и агент → своя консоль по петле — вне окна.

## Приёмка
Тесты на двух тестовых CA: чужой CA с отпечатком — принят, без — отказ, чужая роль — отказ, два отпечатка — любой,
третий — отказ записи; консоль north → консоль south по `/domain/at` через `https://`, браузер по токену, чужой CA —
отказ. Учение: три кластера под TLS (`hold/north/south.localhost`, три CA) — подписант и ретранслятор, резерв и дозапись,
передача держателя, смена CA, консоли. Четыре набора зелёные; код платформы веткой; раздел «Сделано» здесь.
