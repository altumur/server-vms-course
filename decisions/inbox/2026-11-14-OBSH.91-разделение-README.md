## Публичная граница и сохранность

Публичная форма говорит о JSON-входе `chain`, `fingerprints`, `role`, `host`, `now` и настоящем JSON-выходе функции. Поля доверенного входа `fingerprints`, `role`, `host`, `now` обязательны; их отсутствие даёт нативный код 2, stdout не сравнивается. Полученная от сервера цепочка оценивается самой функцией: после проверки хоста нарушение формы цепочки даёт `bad_chain` с кодом 0. Пустой список отпечатков остаётся входом функции и проверяется после формы цепочки; порядок и словарь договора не менялись.

Определение сохранённого тела точное: исходный README разбивается по первым двум пустым строкам на заголовок, абзац метаданных и оставшиеся байты. Все оставшиеся байты, начиная с первого смыслового абзаца и до конца файла, находятся одним неизменённым блоком в соответствующем `README.cases.md`. Исходный абзац метаданных также сохранён дословно в разделе Source metadata / «Метаданные источника». Актуальная шапка файла случаев называет собственный путь перевода; равенство всего нового файла всему старому README не заявляется.

Поэтому вводная, история переноса, Run, центры и листы, таблица файлов с каждым соответствием, проверка оракулом и Vector wire не потеряли текста. Английское тело — 4948 байт, русское — 6243 байта; SHA-256 тел и метаданных записаны в [verify.log](2026-11-14-OBSH.91-доказательства/verify.log). Проверка сохранности не заменяет чтение публичного извлечения: отсутствие случаев в нём проверено отдельно.
