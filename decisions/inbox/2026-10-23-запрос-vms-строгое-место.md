# Запрос: строгое `affinity` — место только для связанных единиц; место без `server`; заказ воркера под место коробки камеры

**Какая норма мешает.** P/04 Н1.3 `affinity` (`04-controller.norms.md:143`): связывающая строка (`strict`) ведёт свою единицу
только к держателю своего места; несвязывающая — предпочтение; `admits` проверяется у фактического места. Не названо:
(1) может ли **чужая** единица (не связанная с этим местом) встать на воркера, держащего строгое место; (2) куда ведёт
связывающая строка, у которой `server_field` пуст (бакетный том); (3) P/04 Н3 «нехватка()» при `grows` по месту без держателя
— заказывает воркер на сервер места; у карты камеры (`edge`, `server` — коробка камеры) воркер на коробке камеры — тот ли
это заказ.

**Что нужно VMS.** Резервный том (`backup`) и карта камеры (`edge`) — места, на которые идут только записи с домом на них
(`affinity.strict: {kind: [backup, edge], enabled: true}`, манифест `rec`): резервная пишет на другом сервере, чем основная,
и основная не должна уехать на регистратор резервного тома (урок М10B/26: «на резервный том не идёт ничто другое»).

**Обход до решения.** V/02.6: регистратор, держащий место `backup` или `edge`, говорит в пульсе ёмкость только для записей с
домом на своём месте (прочие — `refused` воркера, отступ P/03.3) — правило подсистемы; бакетный `backup` без `server` —
предпочтение, не фильтр.

**Рекомендация.** P/04 Н1.3: у строгого места — держатель принимает только связанные единицы (чужая — не на него), как
`admits` для «чужих»; при пустом `server_field` строгость — по держателю места, без сервера; P/04 Н3 «нехватка()» — заказ
по месту на сервер места, в том числе коробку камеры, если там установлен воркер подсистемы.
