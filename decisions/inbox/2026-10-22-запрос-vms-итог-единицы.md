# Запрос: итог конечной единицы

**Что мешает.** Устойчивое `state`/`ended` строки задачи записать некому: воркеру `unit.rows` нельзя (P/02.5 Н1.4),
контроллеру — только размещение (P/04 Н1.3); `retire_when.field` — только поле строки (P/02.1 `placement.retire_when`);
пульс не годится: «факт нельзя хранить в канале, который сам этим фактом закрывается» (М10B/21:220).

**Что нужно VMS.** Задача `detjob` конечна: исполнитель сообщает `done`/`failed` (М10B/21:151–190); задача снимается
с размещения по итогу (`retire_when`), законченная удаляется через N дней после доказанного итога (`forget_finished`).
Итог относится к **исполнявшейся форме** задачи: при изменённом `to` прежний `done` новую не закрывает; старое сообщение,
перезапуск оператором, удаление не закрывают другую работу. Нетерминальные фазы (`fetching`, `running`) — прогресс
`detjob`, не предмет запроса.

**Рекомендация «Архитектора»** (к ревью): итог — в **собственной таблице исполнителя** (`worker.writes`,
`<sub>/<таблица>/<unit>` `{revision, state, ended}` — `revision` строки единицы, по которой работал). Расширить
`retire_when: {table, field, in, revision: match}`: действует, пока `revision` итога равна `revision` строки (правка
строки оператором снимает силу итога — задача пойдёт снова). `delete_after` для конечной единицы — от `ended` итога, а
не от часов отсутствия держателя. Один писатель на каждую строку сохраняется. Альтернатива на ревью: консоль переносит
`status.phase` пульса в поле строки по объявлению `unit.mirror` (только от воркера размещения при
`observed_revision == revision`) — второй писатель строки, поэтому не рекомендую.

**Обход до решения.** Урок `05-detjob` шаги итога не нормирует; продукт — строкой долга.
