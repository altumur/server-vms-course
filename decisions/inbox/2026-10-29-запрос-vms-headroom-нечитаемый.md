# Запрос: исход контроллера при нечитаемом `headroom` пульса

**Какая норма мешает.** P/04 Н1.3, таблица ключей `placement`: «`headroom: {from}` — запас — поле пульса; контроллер
суммирует по живым». Договор пула называет исход для `capacity`, если это не число: воркер не берёт новых единиц,
назначенные не снимаются, причина — `fates.<воркер>.why` «capacity is not a number». Для `headroom` исхода нет: ни для
поля не числом (строка, `null`, отрицательное), ни для пульса, где поля нет.

**Контрпример.** Шлюз `live` публикует `headroom: "12"`. Контроллер A пропускает этот шлюз в сумме (запас 0), контроллер B
считает весь пул без запаса, контроллер C считает «12». От этого зависит рост `grows` (P/04 Н3 «нехватка») и решение
о новых шлюзах.

**Рекомендация.** По образцу `capacity`: `headroom` есть, но не конечное целое ≥ 0 — запас этого воркера не считается
(0 в сумме), причина — `fates.<воркер>.why` «headroom is not a number»; поля нет — тоже 0, без причины. Тест контроллера
над пульсом с таким полем.

- Правит «Спецификация»: P/04 Н1.3 (строка `headroom`) или договор пула, тест контроллера.
- VMS: схема пульса шлюза `capacity` и `headroom` не судит — их судит контроллер платформы (решение «Архитектора»).
