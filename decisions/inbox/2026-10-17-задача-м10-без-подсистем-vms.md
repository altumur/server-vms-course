# Задача «Спецификации»: нормы и приёмка М10 без подсистем VMS

## Контекст
Решение владельца 2026-10-17: нормы и приёмка платформенного модуля называют только `testsub` и `testsub2`;
механизм платформы с единственным потребителем-подсистемой получает потребителя на учебном примере. Пункт
внесён в чеклист навыка `skills/lesson-spec/references/review-checklist.md` («Объём и источники»). Лекции могут
пользоваться примерами VMS. Проверка «Архитектора» на main нашла три места.

## Что исправить
1. **`07-secrets-and-sealing.norms.md:54`** — «воркеры, которым секрет нужен (камера, рекордер, шлюз)» в норме
   о держателях ключа: заменить общим «воркеры подсистем, в спеке которых есть секретные поля».
2. **`07-secrets-and-sealing.norms.md:288`** — «`secret_in.tsv` читается правилами полей `cam.source`
   и `rec.volumes.url` общих спек»: привести к README приёмки 07, где объявления этих двух полей — данные
   приёмки («читается правилами полей, объявленными в README приёмки»). Имена полей в таблице остаются.
3. **М10/8-19, дозапись ADR-0054** (`acceptance/08/README.md:125`: «чтением, затем стенд `rec`; testsub не имеет
   этого обработчика»). Умолчание: `testsub2` объявляет просьбы профиля дозаписи (минимальный обработчик учебного
   счётчика), норма М10/8-19 проверяется сценарием приёмки 08 на `testsub2`. Байты `testsub2.subsystem.yaml` общие
   с продуктом: форму объявления предлагает «Спецификация» здесь же, байты кладёт «Паритет» (команда курса) вместе
   с долгом внедрения после утверждения спецификаций; до этого М10/8-19 — «проверяется чтением» с этой причиной,
   без стенда `rec`.

Также просмотреть по новому пункту чеклиста ссылки вперёд в нормах М10: каждая называет интерфейс, на который урок
опирается; ссылки на непереведённые М11/М12/М13 и ADR вместо нормы — долг с адресом.
