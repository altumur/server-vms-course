## План по урокам

**М10/2 (загрузчик).** Ключ `offers` → `grows` (предложение, вопрос 1): bool, нет — `false`; смысл «роль растёт по
требованию: контроллер заказывает воркеры по серверам (М10/4 Н3 «заказать()»)». Байты `testsub2` и `spec_verdicts/*` —
правкой данных спецификации, долг продукта в ХОД.

**М10/3 (слоты).** Убрать `offer`, `offered_at`, `taken_at` из Н1.4; «Участники и допуск» (обычный/запасной, фильтр
набора, `SPARE_FOR`) и строки таблицы захвата с `offer`; шаг 3 «offer-поля как были», `taken_at`; Н4 строку «кандидат не
прошёл фильтр участника/offer». Грамматика имени: `<prefix>-<сервер>-<n>` — имя от юнита, n ≥ 1 (n ≥ 2 — заказ, вопрос 2);
`<prefix>-<n>` — имя, которое выдумывает захват без имени (стенд), «предлагает контроллер» — снять. Чеклист М10/3-11…15,
приёмка 03 README (строки 182–201 — таблица переходов запасного) — снять строки запасного; положительные соседние
переходы оставить.

**М10/4 (контроллер).**
- Н1.1: новая строка `<sub>/want/<сервер>` (форма — вопрос 3); `platform/doors/<сервер>` + поле `room` (форма —
  вопрос 4); строка «предложение» слота — снять.
- Н1.2 отчёт прохода: `short` остаётся; поле заказов `wants: [{server, want, why}]` и `withheld` с новыми словами; «не
  поднял» — `raise_failed: {<сервер>: since}`.
- Н1.5 intent: новый вид записи `want` под `placement_turn` (смена контроллера не даёт второго заказа).
- Н3: «нехватка()» — как сейчас (per, нужно, группы); «предложить()/отозвать» → «заказать()»: выбор сервера по правилам
  `выбрать` (метки, не дренируется, не выведен, ресурс не silent, `distinct`, `room` > 0, менее загружен — порядок и
  слова причины), `want + 1` записью с cas под стражем `placement_turn`, не больше одного заказа на кусок нехватки за
  проход (кусок — набор меток; вопрос 5); «снять заказ по сроку»: живых воркеров сервера меньше `want` дольше
  `WANT_GRACE` 90 с (прежний `OFFER_GRACE`) по часам контроллера от записи заказа → `want − 1`, сервер «не поднял» на
  `RAISE_QUIET` (вопрос 6), заказ — на следующем; «сократить()»: нехватки нет дольше `SHRINK_AFTER`, остальным
  хватает места → вывести из пула воркер с наибольшим номером n ≥ 2 (по слотовому порядку), переносить его единицы
  не больше `SHRINK_BUDGET` за проход (как `HOME_BUDGET`), при пустом назначении — `want − 1`, не ниже 1; «уходит»: новое
  основание «сокращение» с причиной `<w> is being retired: the role shrinks on <s>`.
- Тревога `spares.no_server` → `workers.no_server` (вопрос 7): нет сервера под заказ; новая `workers.raise_failed`.

## Вопросы (первое — моя рекомендация)

1. **Ключ спеки.** `offers` → `grows: true|false` («роль растёт по требованию»); держать `offers` с новым смыслом —
   имя врёт. Переименование без следов: 137 `spec_verdicts`, `testsub2`, загрузчик, продукт.
2. **Имя дополнительного воркера.** `<prefix>-<сервер>-<n>`, где `<сервер>` — то же, что `%l` юнита `-1` (короткое
   имя хоста), и `server` ряда `workers_wanted{server}` — `SERVER_NAME`; нужно сказать, что они равны (М10/11 Н1.2),
   иначе скрипт не найдёт свой ряд.
3. **Форма `<sub>/want/<сервер>`.** `{want, at, by, why}`: `want` — десятичное ≥ 1 (включая `-1`), `by` — экземпляр
   контроллера, `why` — причина; строки нет — `want` 1; снимается сокращением до 1 удалением строки. Читатели —
   `<s>controller`, `console` (ряд), не ресурс.
4. **Форма `room`.** Отдельные элементы строки двери `room.<sub>`: десятичное ≥ 0 (элементы строки — строки М10/1;
   JCS-объект в одном элементе хуже читается контролем прав и сверкой).
5. **«Кусок нехватки».** Набор меток (как сейчас `short` по наборам); за проход — не больше одного заказа на набор,
   даже если `нужно` > 1: следующий заказ — следующим проходом после того, как прежний поднят или снят по сроку.
6. **Константы.** `WANT_GRACE` 90 с (=прежний OFFER_GRACE); `RAISE_QUIET` 600 с — сервер «не поднял» не получает
   заказов; `SHRINK_AFTER` 300 с без нехватки; `SHRINK_BUDGET` — как `HOME_BUDGET` (единиц за проход).
7. **Тревоги.** `workers.no_server` (нет подходящего сервера), `workers.raise_failed` (сервер не поднял) — новыми
   словами, без `spares.*`.
8. **Скрипт и пользователь.** `w2c-workers.sh`, `w2c-workers.service/.timer`, пользователь `w2c-workers` без групп.
9. **Ряда нет** (консоль молчит, строки `want` нет) — скрипт процессы n ≥ 2 не трогает: молчание консоли не повод
   останавливать (страховка п. 7 — для рассинхрона, не для молчания); ряд есть и меньше — останавливает с наибольшего n.
10. **Директива.** `@grow <сервер>…` в словаре М10/01 (строка реестра — твоя): раннер исполняет ряд для названных серверов,
    раз в 5 с, до конца сценария.
11. **Стенд двух серверов для урока 4.** Сейчас воркеры стенда одного сервера `srv-a`; нужен `SERVER_NAME` на запуск
    (`@start worker <имя> on <сервер>`) — тоже строка словаря.
12. **Base-воркер `-1`.** Всегда один на сервер на роль (юнит включён установкой) — заказ считает его в `want`; на
    сервере без юнита роли заказ невозможен — такой сервер не кандидат (`room` роли нет).
