# ADR-0084 — план правок норм «Спецификации» (вторая редакция, по разбору ревью)

От «Спецификации» «Архитектору», 2026-10-19. Основание — ADR-0084 и доп. (1), разбор
`2026-10-19-ревью-ADR-0084-разбор.md` (Р1–Р12, ответы на 12 вопросов). Ход всех правок — «ADR-0084». До стадии B.

Объём: слова «запасн», `spare`, `offer`, `OFFER_GRACE`, `taken_at` — 92 раза в нормах М10 (по ADR); по файлам — М10/3, 4,
5, 9, 11, М10/2 (ключ `offers`), лекции М10/3, 4, 11, приёмка 03, 04, 06 (права), 09, каталог, `Platform/02-installer`,

## Слова и формы (общие для всех уроков)

- **Ключ спеки** `grows: true | false` (М10/2), умолчание `false`; заказ — только при `true` (вопрос 1).
- **Строка заказа** `<sub>/want/<сервер>` `{want, at, by, why, retiring?}` (вопрос 3, Р1, Р3, Р9):
  `want` — десятичное 1…99, абсолютная цель числа процессов роли на сервере, базовый `-1` входит (вопрос 12);
  строка есть всегда у установленной роли на сервере (создаёт контроллер при первом виде ресурса сервера с `room.<sub>`,
  `want = 1`); удаляют только вывод сервера и снятие роли; сокращение пишет `want = 1`, не удаляет;
  `retiring` — имя воркера, выбранного к сокращению; `by`, `at` — диагностика; полномочие — CAS со стражем `placement_turn`.
- **Место** `room.<sub>` — элементы строки двери `platform/doors/<сервер>` (вопрос 4): десятичное ≥ 0 и не больше
  свободных номеров `n` 2…99; ресурс считает файлы экземпляров присутствия `<events>/.workers/<sub>/*.lock` с живым
  flock, не агрегат `running`; поля нет, не читается или `unknown` — сервер не кандидат.
- **Имя** `<prefix>-<SERVER_NAME>-<n>`, `n` — целое без ведущих нулей, 1 — базовый, 2…99 — заказанные (вопрос 2, Р11);
  `%l` юнита ≠ `SERVER_NAME` — отказ старта, код 2; номер сравнивается как целое (Р4).
- **Сроки** `WANT_GRACE` 90 с, `RAISE_QUIET` 600 с, `SHRINK_AFTER` 300 с, `SHRINK_BUDGET` (как `HOME_BUDGET`) — стартовые
  значения политики; отсчёт — местные монотонные часы контроллера от первого наблюдения версии строки заказа, новый
  контроллер — с 0, повтор той же цели срок не продлевает, `at` — диагностика (Р5, ADR-0049). `SHRINK_AFTER` сверить
  с потолком длины сценария стенда (3 мин урока 5) — для стенда задаётся профилем, как 45/90 урока 11.
- **Тревоги** `workers.no_server`, `workers.raise_failed` `{server, labels, want, why}`; снимаются при восстановлении,
  не повторяются каждым проходом; отказы подряд — счётчик в отчёте, после N — повышенная важность (Р10, вопрос 7).
- **Ряд** `<sub>_workers_wanted{server}` — для каждой строки заказа (Р1).

## План по урокам

**М10/2.** Ключ `offers` → `grows` в таблице Н1.2 и всюду; байты `testsub2` и 137 `spec_verdicts/*` — правка данных
спецификации, долг продукта в ХОД.

**М10/3.** Снять из Н1.4 `offer`, `offered_at`, `taken_at`, комментарий «предлагает контроллер»; грамматика имени —
`<prefix>-<сервер>-<n>` от юнита, номер целым (Р4); снять «Участники и допуск», фильтр набора, `SPARE_FOR`, строки таблицы
захвата с `offer`, «offer-поля как были», `taken_at` шага 3, строку Н4 «фильтр участника/offer»; чеклист М10/3-11…15;
приёмка 03 README — строки 182–201 таблицы запасного, соседние положительные переходы оставить; лекция М10/3.

**М10/4.**
- Н1.1: строка `<sub>/want/<сервер>` (форма выше); у `platform/doors/<сервер>` — поле `room.<sub>`; строку «предложение»
  слота снять.
- Н1.2 отчёт прохода: `short` остаётся; `wants: [{server, want, live, retiring?, why}]`, `withheld`, `raise_failed:
  {<сервер>: {since, times}}`, счётчик отказов подряд.
- Н1.5 intent: вид записи `want` (цель и `retiring`) под `placement_turn`.
- Н3 «нехватка()»: как сейчас, но вычитает ёмкость в пути — по каждому серверу `want − живые` процессов, заказанных и не
  поднявшихся в пределах `WANT_GRACE` (Р2).
- Н3 «заказать()»: за проход покрыть всю нехватку набора, раскладывая по серверам: кандидаты — `grows`, метки, не
  дренируется и не выведен, ресурс не silent, базовый `-1` жив (Р6), `room.<sub>` минус резерв в пути > 0, `want` < 99
  (Р9), `servers: distinct` — по месту `place_by`, «уже есть воркер роли на сервере» запрещает только при
  `place_by: server` (Р8); порядок — менее загружен, затем имя; `want` = абсолютная цель (восстановление доводит, не
  прибавляет); один действующий логический заказ на кусок нехватки; поздний `start` после снятия — снимается
  сокращением (Р2); конкуренция подсистем за последнее место — допустимая задержка (Р2), общий потолок памяти по
  ролям — предел схемы (Р12).
- Н3 «снять заказ по сроку»: живых `n ≥ 2` меньше `want − 1` дольше `WANT_GRACE` (Р5, Р6) → `want` назад до живых,
  сервер «не поднял» на `RAISE_QUIET`, заказ — на следующем; нет живого базового — состояние «нет базового», не кандидат.
- Н3 «сократить()» — свой шаг: нехватки нет дольше `SHRINK_AFTER`, после переноса остаётся запас (гистерезис) и
  каждая единица жертвы проходит полное `выбрать(единица)` на оставшихся (Р3); жертва — наибольший номер `n ≥ 2` целым
  (Р4); `retiring` пишется в строку заказа, жертва исключена из пула всех шагов; перенос — не больше `SHRINK_BUDGET` за
  проход, первая неделимая группа может превысить (как бюджет достижимости); при пустом назначении — `want − 1`, `retiring`
  снят; нехватка вернулась до остановки — `retiring` снят.
- Н3 «уходит»: новое основание `retiring` с причиной; «вывести_сервер» и дренаж — `want = 1`, вывод — удалить строку (Р7).
- Тревога `spares.no_server` → `workers.no_server`, `workers.raise_failed`; Н4, Н5, чеклист, README урока; приёмка 04
  README — строки предложений; лекция М10/4.

**Приёмка.** Словарь М10/01: `@grow <сервер>…` — раннер раз в 5 с читает `<sub>_workers_wanted{server}` и для названных
серверов приводит число воркеров `n ≥ 2` к ряду (`@start`/`@sigterm`), сервер не назван — не исполняет; `@start worker
[<sub>] <имя> on <сервер>` — воркер с `SERVER_NAME`, два ресурса — раздельные деревья присутствия. Шаги (стенд урока 5
после урока 8, `testsub2` с `grows: true`, серверы `srv-a`, `srv-b`):
1. нехватка → `testsub2/want/srv-a` = 2, отчёт — сервер и причина; `@grow srv-a` → `t-srv-a-2` жив, единица на нём;
2. сервер не поднял (без `@grow`) → через 90 с `want/srv-a` назад, заказ на `srv-b`, тревога `workers.raise_failed`;
3. отказ запуска (процесс выходит с кодом 2) и поздний старт после снятия — снимается сокращением;
4. сокращение после выдержки: `retiring` в строке, единицы переезжают, `want` = 1, `@grow` останавливает `-2`;
5. SIGTERM при непустом назначении → слот отдан, единицы переезжают, новая эпоха.
polkit стенд не проверяет — тест юнита и политики (М10/11 Н5). Приёмка 03, 04 README — строки запасного и предложений.
