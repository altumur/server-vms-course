## Решение — урок 1
1. **`op: floor` на ролевом сокете — 403 forbidden** (урок 11 Н4). Урок 1 Н4 привести к нему. В порядок Н2.1 —
   «`op` → сокет для `floor`». Шаг сц. 17.
2. **Порядок внутри `guard`.** Сначала форма: объект, ровно `key` и `index`, типы, форма `index`, пустой ключ —
   `badrequest`. Затем правила ключа стража — `badkey`. Шаг сц. 20.
3. **Конец строки HTTP — только CRLF.** Одиночные LF и CR — 400. Проба README.
4. **Предел заголовков** — сумма длин строк полей без CRLF и без пустой строки конца, ≤ 65536. Отдельного предела числа
   строк нет. Проба «ровно на пределе — проходит, +1 — 400».
5. **Глубина JSON тела — одно число: 128.** Глубже — 400 `badrequest`. Проба 128/129.
6. **Цель запроса** — только байты 0x21–0x7E, без `#`, иначе 400. Шаги: сырой `\x00` → 400, `%00` → 200 (путь байт в
   байт, ключ из query по процент-декодированию, как уже нормировано).
7. **`Host` не проверяется** (дверь — unix-сокет). `HEAD` — 404 без тела.
8. **Рамка тела — по RFC 9112 §6–7:**
   - `Content-Length` — только цифры;
   - разные значения — 400 и закрытие;
   - переполнение числа — 413;
   - размер куска — только HEXDIG;
   - `Transfer-Encoding`, кроме ровно `chunked`, — 400;
   - оборванное тело (EOF раньше длины, нет последнего куска) не исполняется: ответа нет, запись не делается;
   - после ошибки рамки соединение закрывается.

   Пробы README: `+5`, два разных `Content-Length`, `0x5`, `gzip, chunked`, обрыв тела с полузакрытием → затем `GET`
   видит прежнее значение. Обрыв — серьёзный: одна реализация записывала строку из оборванного тела.
9. **Отказ в соединении** (переполнена очередь `accept`) — «ответ не пришёл». Повтор по Н2 тот же, что при обрыве.
   503 не нужен.

## Решение — урок 2
10. **Классы `domain.*`.** Н1.2а уже отдаёт их урокам М11 (выгрузка `475f29e`). Проверь, что в М10/2 не осталось общей
    фразы, которая с ними спорит. Расхождение было дефектом реализации.
11. **Класс отказа — в приёмку:** колонка `class` в `diagnostics.tsv` (или `classes.tsv`). Корпус проверяет вердикт,
    класс и путь, а не только вердикт. Сейчас 13 случаев зелёные у обеих при разном классе. Строки — C1–C7,
    `c3_about_sub_bad` (путь `about.sub`), `m59_keys_display_unknown_id` (`reference`, `display.keys.ledger`).
12. **Положительный случай с апострофом:** `c4_plain_apostrophe_ok` → ok. Сейчас `m59_keys_display_unknown_id`
    отказывается у одной реализации из-за апострофа в `the domain's ledger`, а не из-за ссылки.
13. **Структура YAML — в Н1.1** (случаи `c4_*` из `run/yaml*/`):
    - отступ блочного скаляра — по первой непустой строке, строка мельче — `text`;
    - TAB после отступа внутри блочного скаляра — содержимое;
    - `---` только с колонки 1 и не больше одного;
    - корень — с колонки 1, сдвинутый документ — `text`;
    - `#` начинает комментарий только после пробела или TAB, `]# c` и `"a"# c` — `text`;
    - `a:b` в потоке — одно слово;
    - `-   key:` — допустимый элемент-отображение;
    - indentless-список (`key:` и `- a` на том же отступе) — допустим;
    - одиночный CR — `text`;
    - `[a,,b]` — `text`.
14. **U+FFFE, U+FFFF** — в перечень отказа `text`, как `c-printable` YAML 1.2.
15. **Ключи отображений — всегда строки:** простой ключ `1`, `true`, `null` — строка своего исходного текста. Совпадение
    после этого (`{1: a, '1': b}`) — повтор ключа, `text`. Ключ-коллекция — `text`.
16. **Диагностика.**
    - Путь — до самого глубокого ключа с неверным значением.
    - Индекс списка — число.
    - Строка — строка этого ключа. Отсутствующий ключ — строка объемлющего объекта. Ошибка кодировки — строка байта.
    - В `diagnostics.tsv` — `blob_default`, `status_worker`, `unknown_multiple` (строка у каждого пути).
17. **Значения — выбери и запиши:**
    - `inherit` — из `enum`, если он есть;
    - обязателен ли `delete_after` внутри `unplaced`;
    - `requests.key` без `{…}`;
    - правило вложенных префиксов — и для `secrets.readers`;
    - класс числового ключа в `display.fields`;
    - `default:` без значения — по общему правилу «сказанный ключ без значения — `value`».
18. **Совпали без нормы — записать:**
    - indentless (п. 13);
    - корень потоком — отказ `text`;
    - `guard: null` — `badrequest`;
    - пустые строки перед строкой запроса — 400.

## Из журналов `cammeta-go`, уроки 4–6
19. **Урок 4: нечитаемый пульс ресурса и свежая строка двери.** Подходят и `unreachable`, и `silent` (описание `silent`
    включает нечитаемый пульс). Порядок правил — норма: первое совпавшее, сказать прямо. Нечитаемый пульс сам жизни не
    подтверждает. Сценарий с порчей пульса при живой двери.
20. **Уроки 2 и 5: `slot.name_env` против стенда.** `testsub` не задаёт `name_env`, значит имя из окружения не берётся,
    а стенд урока 1 передаёт имя через `WORKER_NAME` по умолчанию. Рекомендация:
    - стенд передаёт имя подстановкой `{name}` в команде `worker` (аргумент);
    - правило «из окружения — только по `name_env`» остаётся.

    Байты `testsub` не трогать.
21. **Урок 6: описание `RoleRights` в OpenAPI** говорит «нет `delete` — как `write`». Норма Н1.2 и решение `b60d983e` —
    пустой список. Строку привести к норме: это остаток прежней правки, класс — все описания `delete`.
