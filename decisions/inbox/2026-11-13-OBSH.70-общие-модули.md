# OBSH.70: общие модули кода и договоры во входе уроков

## Исполнение

Базис — `2fd1ac98e`, после вливания принятой P01.350 и P01.347. Задание OBSH.70, ADR-0133 доп. (115) пп. 1, 3 и ответ Архитектора от 2026-11-13T17:29:42Z разрешают общий перечень, `requires_module` из существующего `Platform/common/versions/go.mod` и вид `forbid_imports`. Нового поведения дверей, полей, отказов или пределов эта правка не вводит.

До правки на базисе не было перечня обязательных общих модулей, вида глобального запрета импортов и строк потребления этих модулей. В таблицах README отсутствовали публичные зависимости уже выбранных договоров предыдущих уроков. Класс пробела был раньше: это проверено на `2fd1ac98e`; перенос P01.350 общего кода не обещал. Сравниваются базис и diff этой задачи, а не даты первого обнаружения.

В `Platform/common/modules.md` — пять модулей: `json` (разбор и JCS), `rights-evaluator`, `store-client`, `log-mask`, `row-check`. У каждого есть имя Go `servervms.local/common/<имя>`, договор, существующие приёмочные входы, потребители и место пина: прямой `require` в `common/versions/go.mod`, хеши в `go.sum`. Пины не выбирались и байты этих файлов не менялись. Пока общего модуля с прошедшим квалификацию пином нет, генерация его потребителя не готова; фиктивных версий нет. Генерацию и пины выполняет OBSH.71.

Договор `common/contracts/json.md` связывает общий разбор и кодирование с правилами вызывающего. Он сохраняет различие `badkey`/`badrequest` для суррогата в полях P/01.1, игнорируемые лишние значения, предел глубины и отдельные требования подписанного документа. Одних положительных векторов JCS недостаточно для строгого разбора: отдельно названы существующие случаи JSON тела P/01.1 N5 и тесты общего разборщика. Отдельный новый язык исходов или новый векторный протокол не вводился.

В общем словаре `code-rules.tsv` определён `forbid_imports`: прямые импорты нетестовых файлов всех пакетов главного модуля, включая команды и импортированные пакеты, пропущенные маской `./...`; зависимости общих модулей снаружи этого охвата. Явное исключение `allow` называет пакет через отображение профиля, точные импорты и норму. В строках уроков исключений не понадобилось. Проверяется запрет `encoding/json`; запрета общих `strings`, `regexp` и серверного `net/http` нет: эти библиотеки нужны другим законным функциям уроков.

В уроках 1–6 добавлены 22 строки `requires_module` и шесть строк `forbid_imports`, с воротами `code:*` публичного `forms/stages.tsv`. Ранее существовавшие строки и их id сохранены. Урок 7 — библиотека байтов JS, общих Go-модулей и общих векторных назначений у неё нет; строк Go ей не приписано. Этот факт явно записан в перечне. План kit и его схемы не менялись; доказательство ворот относится к публичному `stages.tsv`.

Потребление сверено по `consumers.tsv` и договорам: вычисление прав — только урок 1; JCS — 1, 2, 3, 6; клиент и маска — 1–6; проверка строк — 3 и 6, состояние единицы — 3, 4, 6. Модуль `json` потребляется 1–6 для разбора/кодирования, но это не назначает контроллеру и ресурсу векторы JCS. Вывод прав установщиком не стал вычислением права на действие. Байты векторов, `wire.tsv` и назначения `consumers.tsv` не менялись.

## Выгрузка договоров

Правило M урока N записано в общем перечне и отражено таблицами зависимостей README уроков 1–7. Аудит начинает с собственных публичных файлов и названных зависимостей, проходит Markdown-ссылки, существующие пути в code spans и `$ref` схем/OpenAPI. Транзитивные публичные зависимости предыдущих уроков добавлены группами целых файлов; это включает формы, схемы и клиентские описания, например уставки и флаги из `common/contracts/store-client.md` и OpenAPI хранилища для контроллера.

`forms/export.json` по своему договору классифицирует только собственные файлы урока. Чужие файлы туда не добавлялись: их включение в узкий M выбирает таблица README при наличии публичной записи в собранном фильтре. Новые общие файлы и таблицы кода уроков 5–6 зарегистрированы в фильтрах M/J; переводы — вне обеих выгрузок. Закрытые сценарии и ожидания векторов не раскрывались.
