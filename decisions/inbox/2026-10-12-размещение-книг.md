# Primaries + sources: как воркер узнаёт назначение и получателей

## Контекст
Runtime принят b5bcbbf6, правка c4a9c109, окно в main a5a4e0ff. Перенос primaries + sources начат.
Сейчас Crossings.all() читает domain/vms/crossings у держателя; backups_of() обходит чужие rec/snapshot,
view.last_known(ref) находит домашний кластер. Агент не переносит ни размещение, ни эту связь к обычным
воркерам. Принятая форма задаёт to и требует выбрать основного по размещению; этих данных в локальных
хранилищах издателей пока нет. Одними входами sources/primaries задачу не закрыть без широковещания,
цикла первого запуска или отдельного кода подсистемы у держателя.

## Рекомендация
Сначала согласовать и доставить подписанное **платформенное назначение**, общее для любых подсистем.
Один источник выбора основного; доменная книга наблюдений не выбирает размещение. Не получать список
резервов обходом чужих хранилищ из воркера и не выбирать первую запись из entries. Предлагаю следующую
форму; она **до кода**, новая платформа и спеки останутся веткой до чтения diff.

### Предлагаемая форма размещения

- Запись `domain/placement/<sub>/<ref>` — существующее пространство платформенного размещения, новый
  однозначный ключ группы. `<sub>` — издатель наблюдений, в этом окне rec; ref — имя группы, здесь камеры.
- Обязательные `cluster`, `unit` — выбранный исполнитель; `origin: {member, unit}` — владелец источника;
  `copies: [{member, unit}, …]` — явно назначенные другие исполнители. Существующие reason/at/rev сохраняются.
  Все имена членов проверяются по принятому составу; unit — идентификатор единицы в своей подсистеме.
  Платформа хранит ссылки и выбранное размещение, не вычисляет смысл камеры, pull/push или when.
- Подписанный снимок назначений переносится агентом в локальную `domain/placement/` по уже действующим
  порядку term/rev, проверке ключей и корня. Пусть Архитектор закрепит точный конверт/путь подписанного
  объекта и права чтения до реализации; моё предпочтение — отдельный снимок размещения, а не новый
  документ настроек shared с дублированием того же выбора.
- Перенос и кража несут назначения платформой; domain/vms/crossings и его предметная дверь уходят в том
  же окне. Размещение сохраняет единственное место выбора основного. Старых форм и двойного чтения нет.

### Кто использует назначение

| Издатель / читатель | Действие |
|---|---|
| VmsWorker | По принадлежащей камере и origin получает ref; публикует vms/sources/<worker> с наблюдаемыми дверями, as_of и to = cluster + члены copies. Нет назначения — to: [], адреса не рассылаются. |
| RecWorker | По назначенным ему unit публикует rec/primaries/<worker> до разрешения источника: ref, один recording, enabled/running/starting, двери ingest/архива и покрытие. to = origin.member + cluster + члены copies. Нет назначения — адресной публикации нет. |
| Камера / резерв | Основного выбирают по (cluster, unit), а не порядку entries, when или давности. Отсутствующий факт основного не превращает резерв в основного. |
| Основной рекордер | Берёт источник из unique, архивы резервов — из отдельных all фактов, сверенных с copies. Выбор pull/push и reachable — локальная политика рекордера по топологии. |

Нет цикла запуска: назначение приходит до наблюдений; RecWorker сообщает starting и ingest, даже пока поток
не найден; камера получает назначения/ingest, затем начинает передачу. Токен камера просит сама, в all его нет.

### Приёмка формы

Камера, основной и два резерва: доставка только участникам; перестановка entries не меняет основного;
назначение до первого запуска; отсутствующий основной даёт выдержку карты; перенос назначения прекращает
новые подключения по старой группе; удалённый/непринятый член не становится получателем; секретов и адресов
в снимке назначения нет. Отдельно запрет запоздавшему владельцу публиковать строки под старым слотом.

Прошу закрепить форму назначения и подписанной доставки (или указать уже принятый контракт, который я
пропустил), затем продолжу включение издателей/читателей и спек одной пачкой. Пока не добавляю новые имена
на диск/провод. Независимо готовлю строгие читатели уже утверждённой оболочки книг с явным выбором основного.
