# Ассистент конфигурирования текстом

## Задача
Админ пишет в консоли обычным текстом: «включи запись по движению на камерах 3-го этажа, хранить 14 дней». Ассистент
находит единицы, предлагает правки, админ смотрит и подтверждает. Агент — Hermes Agent на локальной модели (Ollama,
Qwen3 8B или сопоставимая), без облака.

## Устройство

```
Админ → чат-панель оболочки консоли (браузер, сессия админа)
        → агент (Hermes + Ollama): только думает, своих прав нет
        ← вызовы инструментов — исполняет БРАУЗЕР дверями консоли с грантами админа
        → план правок → проверка схемой формы → diff «было → станет» → «Применить» админа
        → запись дверями консоли (CAS по прочитанной версии)
```

## Принципы
1. **У модели нет своих прав.** Чтение и запись делает браузер сессией админа: модель видит только видимое админу и
   не сделает больше, чем он. Отдельной роли «ассистента» с широкими грантами нет.
2. **Модель предлагает, не пишет.** Выход — план: список правок строк с полями и строкой «почему» у каждой. План проходит
   ту же проверку формы, что ручной ввод; админ видит diff и сам применяет.
3. **Запись — обычными дверями.** PUT с CAS по прочитанной версии, как у формы консоли; строка изменилась между планом и
   применением — отказ, план перестраивается. Нового пути записи в платформе нет.
4. **Секреты модели не уходят.** Маскирование консоли действует; запечатанные поля модель не видит. Пароль, заданный
   текстом, подставляет браузер в момент применения, не модель.
5. **Локально.** Модель — на сервере кластера; данные объекта наружу не уходят.

## Ложится на платформу
- **Подсистема `assist`** со своим манифестом: воркер — процесс модели (Ollama), размещение по метке (`labels: gpu`).
  Qwen3 8B в Q4 — около 5–6 ГБ памяти; на CPU работает, медленно.
- **Чат-панель — в оболочке**, не в модуле консоли (у модуля закрытый список вызовов P/07 Н1.4). Платформа не меняется.
- **Инструменты агента — двери консоли:** `/schema` и `display` манифеста (поля, подписи, варианты — словарь самой
  подсистемы), `GET` строк с фильтрами (поиск единиц), «предложить план».
- **Общий формат с массовой правкой** (задел 2026-10-25): план ассистента — пакет массовой правки; одна проверка, один
  экран diff. Ассистент — ещё один способ составить пакет.
- **MCP.** Инструменты над дверями консоли — MCP-сервер: подключается любой агент, не только Hermes (продукт «MCP и
  плагинная система», пункт «конфигурирование»).

## Риски
- **Качество малой модели:** простые правки — надёжно; запросы «все камеры, у которых…» с условиями по нескольким полям —
  ошибки (их ловят проверка формы и diff, но пользоваться неудобно). Нужен набор проверочных запросов для сравнения моделей.
- **Большие кластеры:** тысячи единиц в контекст не входят — поиск фильтрами дверей, не чтением всего.
- **Объяснимость:** у каждой правки плана — «почему» (по какому полю или метке единица попала в план).
- **Исполнение инструментов в браузере** держит права точными, но требует, чтобы чат жил, пока открыта страница; фоновых
  заданий ассистента без админа нет — и не нужно.

## Когда и как
После стадии C, вместе с массовой правкой (общий формат плана); решение — ADR с ревью тремя. До этого можно сделать
прототип вне курса: Hermes + Ollama, инструменты над дверями консоли, только чтение и план, без записи — оценить, как
модель понимает манифесты и запросы админа.

## Итоги пилота 2026-10-27 (`/Users/murat/w2c/assist-pilot`, REPORT.md `07d8d14`)
- **Модель и агент:** облачная MiniMax M3.1 Flash на своём тонком цикле (`agent/loop.py`, ~200 строк, OpenAI-совместимый
  API) с инструментами v3.1 — 18 верно, 2 частично, 0 неверно из 20; медиана хода 16 с; $0.05 за 20 запросов. К API — только
  демо через прокси со сторожем секретов и вычисткой сведений о машине.
- **Hermes Agent не берём:** минимум контекста 64k, инструменты MCP за мостом, ход живёт в шлюзе после ухода клиента,
  без спроса кладёт в промпт сведения о машине и git; на одной модели свой цикл — то же качество, вдвое быстрее и дешевле.
- **Локальные модели** на M1 Pro 32 ГБ рядом с обычной нагрузкой: gpt-oss-20b — ≈ 2 мин на ход (только фон), Qwen3 14B —
  ≈ 4 мин, Qwen3.6-27B и 35B-A3B уходят в своп. Локальный `assist` — только на отдельном сервере ≥ 48 ГБ.
- **Качество упирается в инструменты:** `display` у каждой подсистемы, значения меток (`field_values`), метки связанной
  единицы (`about.labels`), план с разделением «кого отбираем / кого правим» и подписями полей (v3) вытащили провалы
  всех моделей.
- **Дыры проверки плана** (подмена поля подобранным словом, `0 == false` в отборе, булевы строкой) — список правок v3.2
  в REPORT.md; проверка плана — главный предохранитель.
- Принцип задела «облака нет» пересматривается: облачная модель — только через прокси с вычисткой и только с данными,
  которые админ видит; решение — в ADR при проектировании `assist` после стадии C.


## Обобщение пилота 2026-10-27, вечер (REPORT.md `23a3e8d`)
Три набора: основной R01–R20 (промпт к нему подогнан), отложенный-1 H01–H08 и отложенный-2 K01–K08 — записаны до
прогонов, второй — до итогов правок, которые правили ошибки первого. Qwen исключён владельцем (35B только со свопом).

|---|---|---|---|

- **Опасное — правдоподобная подмена, не выдумка.** Недоступное действие модель делает правкой соседнего поля
  («перезапусти сервер» → выключить 8 счётов, H06; «удали счета» → «закрыть», K08; «высокий приоритет» → `tags`, R18),
  неназванное значение выбирает сама («другую полку» → `sh-c`, R16; «шаг побольше» → 2, K07). Ловят это только сверки
  плана с **текстом просьбы**: поле (v3.3) и значение (v3.5). Значит, текст просьбы должен быть у проверки (в `assist` —
  у браузера), а слой проверки — не ослабляемый принцип подсистемы, а не настройка.
- **Модели сравнялись на новых просьбах**; MiniMax склонна действовать (подмены выше), gpt-oss — переспрашивать (иногда
  с ответом на руках). Локальная gpt-oss-20b на v3.5 — 31–49 с на ход: годится не только в фон, если облако
  неприемлемо; MiniMax — для интерактива, только через прокси с вычисткой.
- **Остаток ◐ — один класс:** на отказе по правам или fixed модель сперва предлагает план. Средство — явные инструменты
  `ask_admin` и `refuse` с причиной и проверка прав до плана, а не разбор текста ответа (оценка подстрокой в пилоте
  хрупка, правки оценщика записаны в REPORT).
- **Дыры для v3.6** (не делались): `about.<поле>` без проверки поля связанной единицы; `eq ""` по полю-списку («пусто или
  не задано»); полнота отбора для списков сравнивает итог, а не изменение (ложное отклонение).
