# Запрос: путь, который получает воркер по `door.pass` от консоли кластера

**Какая норма мешает.** Договор сторожевой и передачи, правило `door.pass` (из P/06.5 Н1.8): консоль передаёт воркеру
«метод, путь, query, тело …». Для консоли домена путь назван: `/<сегмент>[/…]`. Для консоли кластера — только «путь».
При `CONSOLE_ROOT=live` клиент зовёт `/accounts/…`, при монтировании той же подсистемы — `/live/accounts/…`.

**Контрпример.** Две реализации консоли кластера: одна передаёт путь как пришёл (`/live/accounts/wall1`), другая —
без префикса монтирования (`/accounts/wall1`). Воркер шлюза, написанный под одну, отвечает другой `404`.

**Рекомендация** — одна строка договора: воркер получает `/<сегмент>[/…]` при любом корне и монтировании, как от консоли
домена; query — как пришёл. Тогда OpenAPI урока: у шлюза пути `/accounts…`, у консоли — `/accounts…` (корень) и
`/live/accounts…` (монтирование).

- Правит «Спецификация»: строка `rule` правила `door.pass`, приёмка P/06.5 (передача при монтировании).
