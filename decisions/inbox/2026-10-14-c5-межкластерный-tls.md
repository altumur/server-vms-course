# C5: граница TLS нового перехода консоли к держателю

## Контекст

Обратный клиент шлюза работает только через свою консоль. Для users/grants
консоли члена потребовался новый узкий fallback к консоли текущего держателя,
когда domain/view не содержит URL. Он использует общий RoleClient(console),
но доверяет только своему ca.pem. WithMember/PeerOf и перенос CA из окон3/4
ADR-0075 в Python ещё не зеркалированы. Новый тест покрывает общий CA.
Независимая проба подтвердила: общий CA →202, два CA →502 при TLS handshake,
HTTP handler держателя не вызван. Без явного решения нельзя назвать новый
межкластерный TLS-путь завершённым или молча отнести его к прежнему долгу.

## Рекомендация

Для узкого C5 подтвердить границу зеркала клиентской половины окна1 из
b2204ff6: новая цепочка работает в явно настроенном HTTP режиме коробки
или под одним CA; разные CA остаются закрытыми. Явно записать это ограничение
нового fallback и отдельную задачу зеркала окон3/4 ADR-0075 после C7,
не объявляя C5 полным зеркалом межкластерного TLS. Это не работа по урокам М10.
В C5 сохранить отказ TLS: без подстановки HTTP после ошибки, CERT_NONE,
системных корней, дописывания чужого CA в ca.pem или второго CA-loader.

Если межкластерный TLS обязателен для приёмки C5 уже сейчас, рекомендуем
до его слияния отдельным общим этапом реализовать принятую форму
WithMember/PeerOf, перенос CA и двухсторонние проверки по ADR-0075,
с тестами двух CA/отзыва/смены CA; не писать частный обход только для accounts.
Просим выбрать границу в разделе «Решение»; до ответа C5 не вливаем.
