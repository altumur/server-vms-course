# Разбор ревью ADR-0094 (`backend`, API consolem; платформа под неё)

Отчёт: Claude (`claude/review-adr-0094`, c46551362, 15 находок 1/10/4) — `decisions/inbox/ревью/РЕВЬЮ-ADR-0094-Claude.md`.
Kimi — в работе, дополнением. Codex — после сброса лимита (4 ноября).

## Вопросы — решения «Архитектора»

1. **Делегирование (Б-1, С-1…С-5, С-9).** Блокер принят: токен двери в нынешней форме у консоли — удостоверение человека
   в руках воркера на публичном сервере, против довода ADR-0093 доп. (1). Варианты:
   - А′ — консоль проксирует дверь `backend` и сама ставит личность. Отклоняется: `backend` переводит API consolem в
     двери консоли, ему всё равно нужно действовать от имени человека у консоли — либо он получает доверенный заголовок
     личности (делегирование без привязки — хуже), либо перевод уходит в консоль (это вариант Б, уже отклонённый).
   - **А″ — обмен (рекомендация «Архитектора», нужно «да» владельца):** браузер с сессией консоли получает у консоли
     **токен делегирования** — отдельный от токена двери: аудитория — консоль; закрытый перечень дверей (С-1: чтения,
     `PUT`/`POST`/`DELETE` строк `cam`, `rec`, `det`, `auto` и их таблиц; без `/where`, `/session`, `/domain/grants`,
     `/domain/users`, `/domain/revoke`, выдачи ключей и break-glass); права — пересечение грантов человека и перечня;
     привязка к предъявителю (С-2: лист роли `backend` того сервера, где стоит держатель единицы по пульсу); только из
     `Authorization`, не из `?t=`; только для сессии вида `person` (С-4: break-glass и `open` делегирования не получают);
     каждый запрос — свежая проверка `domain/disabled` и отзыва; срок — короткий, обновление — только новым обменом;
     длинный поток закрывается на сроке. Журнал (С-5): `user`, `via: backend/<экземпляр>`, единица; ряд
     `<sub>_delegated_total`. Поток браузера (С-3): WebUI отдаётся дверью `backend`, сессия консоли — у консоли;
     токен делегирования приходит в WebUI `postMessage` из окна консоли (не URL), CORS консоли для источника `backend` —
     нет. Это пересматривает довод ADR-0093 доп. (1) в ограниченной форме — дополнением к ADR-0093 со ссылкой на модель
     угроз этого разбора.
2. **Порядок (С-8).** Генерация V/01–V/10 — по ADR-0090 доп. (14), B не ждёт. `backend` (V/11) — после B и отдельного
   перепина VMS на выгрузку с B; это дополнение к ADR-0090 доп. (14) п. 3 (второй перепин — только для V/11).
3. **Лента (С-6).** Сообщение несёт ключ и ревизию, но не значение; клиент читает значение обычной дверью. Это
   отступление от ADR-0038 («ответ не несёт события») — записывается в ADR-0094 как своё, ADR-0038 для прочих мест не
   меняется. Одно перечисление префиксов на экземпляр консоли, раздача подписчикам; такт и потолок называет норма; ряды
   цены `w2c_changes_*`; смена грантов или меток в `view` подписчика — `reset` ему (ни «удалена», ни молчание).

**Вопрос 1 пересмотрен (С-11, АДАПТЕР-CONSOLEM.md §10).** Есть вариант без делегирования совсем — **перевод в браузере**,
по прецеденту `assist` (ADR-0093 доп. (1)): WebUI consolem отдаётся с источника консоли как оболочка подсистемы
`backend`; Service Worker на источнике консоли перехватывает `/backend/api/*` и `/stream` и переводит их в двери консоли
сессией человека (у consolem такая петля есть — `tests/loopback-sw.js`, HTTP и SSE). Воркер в консоль не ходит, новой
личности нет, ADR-0075 и ADR-0093 доп. (1) не задеты; B2–B6 остаются (они и делают перевод чистым преобразованием).
Цена: нужен HTTPS для Service Worker; браузер может усыпить его на долгом потоке — тогда `stream.reset` и перечитка;
отдельный процесс `backend` для перевода не нужен (остаются статика и, может быть, свои строки). **Рекомендация
«Архитектора» меняется: перевод в браузере вместо А″**; А″ — запасной, если перевод в браузере упрётся в ограничения
Service Worker. Решение — владельцу (меняет его решения 2 и 4).

## Второй круг — B1 второй редакции (Claude, `claude/review-adr-0094`, 42cf608d9, 11 находок 1/6/4)

Модель билета в границах запроса ревьюер признал верной. Решения «Архитектора»:

1. **Блокер — WebUI с адреса консоли через передачу.** Ответ `backend` с HTML/JS, отданный под источником консоли, исполняется
   с её кукой: скрипт захваченного `backend` зовёт любую дверь консоли мимо билета и перечня. Решение: **WebUI consolem
   `backend` не отдаёт.** Его отдаёт сама консоль — закреплённым набором байтов (коммит и SHA-256 сборки WebUI в уроке
   V/11, как канон оболочек VMS), со своей CSP. Через передачу `backend` идут только ответы API: тип — `application/json` или
   `text/event-stream`, консоль добавляет `X-Content-Type-Options: nosniff` и `Content-Security-Policy: sandbox`, иной тип —
   502. Отдельного источника не заводим.
2. **`/operations`** — из перечня убрать до ADR групповых операций (C).
3. **Учётки `live`** — на билет вместе с окном mTLS: до него передача идёт по сети к шлюзу, и проверить, что её отправила
   консоль, шлюзу нечем; до окна — нынешний `door.pass` (с `Authorization`), после — билет.
4. Перечень дверей пополняется чтениями, без которых API consolem не работает: `GET /manifest`, `/servers`, `/events`,
   `/session` (только чтение «кто я»).
5. Предел ожидания передачи (`PASS_WAIT` 5 с) — по объявленному маршруту: манифест называет свой предел для составной
   записи, с потолком в норме.
6. Потоковые маршруты — грамматика `door.pass` в P/02.1 получает объявление потока по маршруту (не один сегмент на всю
   подсистему) — «Спецификация».
7. После окна mTLS привязка билета — к экземпляру, которому консоль передала запрос: соединение обратного вызова должно
   прийти от листа этого сервера и роли и назвать экземпляр, совпадающий с адресатом передачи.
8. Мелкие — принять.

ADR-0094 правится по пп. 1–7; повторного чтения не нужно (ADR-0080 доп. 11) — закрывает Codex по сбросу лимита.
