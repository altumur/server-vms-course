# C6: закрыть образец существующего display.actions в testsub2

## Контекст

Полный unit с Python и JS на неизменном срезе1014 файлов C6:
2067/1/0, exit1. Единственный отказ `test_spec_rule` — `display.actions`
читается платформой, но не встречается в двух подсистемах или тестовой спеке.
Отдельный `test_spec_rule` на main также красный по этому ключу.
Это не работа по урокам М10; ожидаемый паритет platform_lists.tsv — другой отказ.

## Рекомендация

В текущей ветке C6 добавить в общий testsub2 под display строку
`actions: {add: добавить}`: add уже имя поля его запроса. Это образец
словаря существующего ключа, новых запросов и действий не вводит.
Проверку двух подсистем и WAITING не ослаблять; продукт не менять.
Общую fixture оставить в ветке для чтения diff перед итоговым слиянием C6.
Рекомендуем этот узкий образец вместо удаления поддерживаемого ключа.

## Доказательство

Вне репозитория:
`/Users/murat/w2c/course-book-merge-evidence/c6-hosts-unit.log`;
`/Users/murat/w2c/course-book-merge-evidence/c6-main-display-actions.log`.
Срез C6 перед прогоном и после него совпал по всем1014 файлам;
временная ссылка jsdom снята после фактического exit1.

## Решение («Архитектор», 2026-10-14)

**Не принимается.** `display.actions` снят уроком М10/9 как мёртвый ключ (ADR-0003); общая `testsub2` и все положительные случаи приёмки урока 2 его уже не несут, а отрицательный случай `display_actions_nested` ждёт отказа загрузчика. Вернуть ключ в `testsub2` — значит снова сделать его допустимым и сломать эту приёмку. Правильное действие — обратное: убрать `display.actions` из закрытого набора ключей загрузчика Python (`speckeys`) и из ожиданий теста «у каждого ключа есть образец» одним коммитом в C6; это не задача по урокам М10, а снятие мёртвого ключа по ADR-0003 вслед за общими байтами, которые вы уже везёте. Проверку «каждый ключ набора имеет образец в спеках» не ослаблять. Продукт сделает то же окном М10/9 по снятии паузы.
