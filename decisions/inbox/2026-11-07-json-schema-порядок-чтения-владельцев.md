# JSON Schema: порядок чтения владельцев и поздний слой

Уточнение Архитектора от 2026-11-07 к решению `architect-reviews/p08-schema-ref-treatment-fea/DECISION.md`, пп. 1 и 3. Основание — сохранение прежнего порядка чтения уроков при поддержке самостоятельных JSON Schema. Это не выбор wire-формы и не новое разрешение чтения произвольного позднего урока.

## Решение

**Ранний владелец разрешён.** Ссылка из Schema Object P/10 на схему данных раннего владельца P/09, включая JSON Pointer на поля alarms, допустима при всех остальных прежних проверках. Ограничение карты производителя только «свой/common» слишком узко: оно не должно запрещать прежнее направление к раннему владельцу.

**Поздний JSON-владелец подчиняется прежнему late-layer guard.** Исключение не ограничено суффиксом `.openapi.yaml`. Для самостоятельной `.schema.json` оно действует только на том же узком основании:

1. Ссылка находится в позиции Schema Object внутри `paths/<door>` исходного OpenAPI-документа. Ни файл целиком, ни `components` не получают разрешения по одной связи с такой дверью.
2. Описание этой двери указывает её позднюю главу прежним способом; заголовок нормативной главы объявляет, что её вводит целевой поздний урок. Номер цели должен входить именно в это объявление.
3. Все ограничения типа, диалекта, файлов/указателей, offline-доступа, границы Platform, объявленного и разрешённого по фактическому пути владельца, циклов и относительной базы сохраняются. Разрешение позднего слоя не ослабляет их.

Для самостоятельного JSON-документа нет собственной OpenAPI-двери: исходящая из него ссылка на более позднего владельца не получает late-layer допуска от вызывавшего его документа. Каждый переход проверяется по месту объявления и фактическому владельцу ресурса. Однажды разрешённое чтение или наличие документа в кэше не разрешает другой переход.

Самостоятельные схемы своего владельца и common сохраняют уже принятый допуск. Common ссылается только на common. Ссылки между OpenAPI-документами своего урока и локальные ссылки не получают дополнительных разрешений от этого уточнения; прежние правила остаются. JSON Schema по-прежнему нельзя подставить вместо Parameter, Response, PathItem или прикладного значения.

## Следствия для двух долей

- Политика core `cd365c175` / main `5ebd27bbeab769d8c391a67ac2fb5075e99d9296` в этом вопросе соответствует решению: в `cross_ref` проверка владельца/позднего слоя предшествует загрузке и кэшу схемы; отдельный тест проверяет отказ позднего JSON и допуск той же цели через late-layer door. Normal child только ради запрета позднего JSON не нужен. Это чтение соответствующих блоков, не новая полная приёмка core.
- Карту Docs/Bundle производителя уточнить до активации его кода: сохранить ранних владельцев и тот же контекстный поздний guard, а не вводить список строк или отдельный запрет по суффиксу. Точные блоки и независимые контроли ведёт coord103-tools в рамках существующего класса и З-12.
- Положительные и отрицательные соседи должны различать ранний P10→P09; позднюю цель под разрешённой дверью; ту же цель вне двери, без объявления главы или с другим целевым уроком; транзитивную ссылку из самостоятельной схемы; повтор после заполнения кэша. Прежние запреты Common→lesson, сети, смены базы, подмены владельца и ошибочной позиции сохраняются.

## Граница результата

Сообщённые tools 229 проверок с одним прежним пропуском, четыре фактические ссылки и scoped API без ошибок относятся к его двухфайловому core. Они не доказывают работу Docs/Bundle, не являются fullstrict/GATE и не принимают fea или P09 А. Архитектор прочитал квитанцию, код порядка разрешения и соответствующие тестовые случаи; прежние программы заново не запускал.

FORMAT-only 4a4687 и исходные P08/P10 компоненты остаются в своих областях. Текущие S08/J06 и ms, готовность уроков и паузы Claude этим уточнением не меняются. Новые классы форм, API/порты, wire-значения, Go/HTTP/SUT, модели и полная проверка не назначаются.
