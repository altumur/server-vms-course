# C2: как страница создаёт и удаляет запись на консоли члена

## Контекст
Чтение назначения и видимость книги согласованы; реализую их в ветке.
Следующий вызов страницы по C2 — POST rec/recordings в назначенном кластере,
при переносе DELETE старой записи. Курс сейчас передаёт через
/domain/at/<cluster>/ только GET where: member_forward отвергает любой
POST/DELETE и GET списка строк. Токен пользователя в HttpOnly cookie;
прямой fetch другой консоли не переносит эту сессию. Нельзя собрать
согласованный порядок PUT назначения → запись на консоли члена, не
уточнив форму доступа. Код продукта не читаю; нужен его фактический маршрут.

## Рекомендация
Закрепить фактическую форму продукта. Предлагаю расширить тот же однократный
переход /domain/at/<cluster>/<sub>/<rows> для объявленных unit.rows:
GET списка, POST создания и DELETE /<id>; остальные пути запрещены,
подсистема/семья определяются из каталога, без случая rec в платформе.
Личность/Authorization, Idempotency-Key передаются, гранты проверяет консоль
получателя; имена членов только из подтверждённого списка, второй переход
по-прежнему запрещён. Это управление строкой, байты видео туда не попадают.
Страница после PUT создаёт новую запись, только после успешного создания
удаляет прежнюю; частичный отказ явно показывает и не откатывает чужую
более новую запись назначения. Если у продукта другой маршрут/порядок,
принять его и описать до кода. До ответа не расширяю маршруты.

## Решение («Архитектор», 2026-10-13)
Расширение `/domain/at/<кластер>/…` на `POST`/`DELETE` отвергнуто — у продукта иной маршрут, и он по п. 6 ADR-0074:
строку записи заводит **правка домена** (`domain.edit`, применяет агент кластера; урок «правка для выключенного
кластера»), переход `/domain/at` остаётся только `GET where`. Порядок закреплён поправкой к форме C2: `GET` назначения →
`PUT` назначения (основная: `cluster: X, origin, copies без X`; резерв: `copies` + X при существующем назначении) →
при переносе `DELETE /domain/rec/recordings/<ref>?cluster=W` (отказ не останавливает) → `POST /domain/rec/recordings
{cluster: X, name, cam: "ref:<ref>", retention_days[, home][, when: offline]}`; `kept` — «заведёт со следующей
публикацией», 409 «уже есть» — не ошибка. Назначение первым: прежний рекордер по книге сразу не основной. Файл
снимаете слиянием окна.
