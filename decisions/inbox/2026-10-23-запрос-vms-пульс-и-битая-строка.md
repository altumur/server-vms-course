# Запрос: поля пульса воркера для рядов P/06.5; битая строка единицы у воркера; слова `LABELS`

**Какие нормы мешают.**
1. P/06.5 Н3 «/metrics» (`06.5-console.norms.md:402`) называет ряды `worker_store_errors{worker}`,
   `worker_pass_failures{worker}`, `worker_fenced{worker}`; P/03.4 Н1.1 (`03.4-worker.norms.md:33–116`, форма пульса)
   полей, из которых они строятся, не называет — у свидетеля это поля верха пульса `store_errors`, `pass_failures`,
   `was_fenced`. Так же без нормы: `unconfirmed` (число единиц под неподтверждённой арендой, ряд свидетеля
   `cam_worker_unconfirmed{worker}`), `passes`, `assignment_rev`, и в элементе `status[]` — `lease: "unconfirmed"`,
   `unconfirmed_s` (М10B/04 шаги 5, 7, 8: «больше минуты не ноль — хранилище недоступно»).
2. Битая строка единицы у воркера: P/03.3 Н3 шаг 2 читает строки своих единиц, но не говорит, что делает воркер, когда
   строка единицы не читается своим типом (у свидетеля: «шло — идёт», причина в статусе; ни разу не прочитанная целиком
   — не стартует; М10B/03 шаг 3).
3. `LABELS` (P/02.4 Н1.2) — слова меток сервера; у свидетеля воркер предупреждал о слове вне азбуки меток (М10B/03 шаг 1);
   кто проверяет азбуку `LABELS` и что делает со словом вне неё — не сказано.

**Что нужно VMS.** Держатель камеры (V/01.2) — первый потребитель всех трёх: оператор видит «хранилище молчит у этого
воркера» и «строка камеры испорчена» по пульсу и рядам, не по журналу процесса. Это знание платформы, не подсистемы:
V/01.2 Н1.4 эти поля словами `cam` не объявляет.

**Обход до решения.** V/01.2: держатель их не несёт как слова `cam`; ряды P/06.5 у VMS — как реализация платформы их
даст; битая строка — по P/03.3 как есть (единица не идёт).

**Рекомендация.**
1. P/03.4 Н1.1: верх пульса — `store_errors`, `pass_failures` (счётчики с запуска), `was_fenced` (bool, когда было),
   `unconfirmed` (число единиц с неподтверждённой арендой); `status[]` — `lease: unconfirmed` и `unconfirmed_s` (с
   точностью 0,1 с) при неподтверждённой аренде; ряды P/06.5 — из них, плюс `worker_unconfirmed{worker}`. `passes`,
   `assignment_rev` — по решению платформы (читатель — только страница).
2. P/03.3 Н3 шаг 2: строка своей единицы не читается — запущенная единица продолжает идти с последней прочитанной
   строкой, `why` «row unreadable: <причина>»; ни разу не прочитанная — не запускается; счёт `garbled_rows` пульса.
3. P/02.4 Н1.2 `LABELS`: слово вне азбуки меток (P/04 Н1.3) — громкая строка журнала при старте, слово не участвует в
   `labels-subset`; или отказ старта — как решит платформа.
