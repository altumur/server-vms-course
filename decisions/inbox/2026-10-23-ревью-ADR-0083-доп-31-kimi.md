## Проверено без находок

### Доп. (30)

1. **П. 1 (ведущая — диспетчер и фильтр)** — точное уточнение доп. (25) п. 2 и доп. (28) п. 3: «кода продукта
   не пишет, рабочих мест и кандидата руками не собирает» не противоречит «раздаёт задачи… собирает
   кандидата» прежних текстов — сборка отдана скриптам (п. 2). Чтение ведущей не расширено: связь с приёмкой —
   «чтение раннеров», уже разрешено доп. (26) п. 4. Потолок сессий — по доп. (29) п. 3, без изменений.
2. **П. 2 (сборка скриптами)** — ограниченное чтение не ослаблено: скрипт — «инструмент репозитория генерации,
   не код продукта», «норм уроков в код продукта не несёт»; ведущая чинит скрипты по их выводу, её собственный
   список чтения (доп. (25) п. 2) не растёт. «Ручная правка рабочего места или кандидата — только через
   скрипт» закрывает обходной путь, который устройство доп. (27) п. 1 оставляло неявным. Профили `format2` и
   `assembly.yaml` — существующий формат (доп. (26) п. 4).

### Доп. (31)

3. **П. 1 (чтение сессии `common`)** — расширение сформулировано закрыто: «поимённо по доп. (27) п. 2» плюс
   замыкание ссылок из договоров и векторов `common/` **кроме** норм (`*.norms.md`) и README уроков; замыкание
   строит скрипт рабочего места — проверяемо регрессией «нет пути к соседям» (доп. (27) п. 1). Это отвечает
   реальной нужде (договоры ссылаются на формы уроков, напр. `door-token.md` → `06-console/data/door-keys.*`),
   не открывая норм. Эскалация названа: «договор, которому нужна норма урока, — пробел: строка
   `common/<договор>/GUESSES.md`» — счёт догадок не теряется.
4. **П. 2 (векторы договора — по разделу «Векторы», не по имени каталога)** — устраняет неявное чтение
   одноимённых каталогов; согласовано с п. 1 (замыкание по ссылкам).
5. **П. 3 (внутренний договор реализации)** — путь назван (`NN-*/contracts/<имя>.md` + рядом `vectors/`),
   доставка — скриптом сессии `common` и потребителям, «до первого потребителя» держит порядок; «когда
   библиотека готова, владелец формата переводит свой код на неё — у генерации одна реализация формата»
   закрывает риск двух реализаций одного формата (временной, пока владелец не перевёл свой код, — принят
   явно сроком «когда готова»).
6. **П. 4 (после сжатия и передачи)** — замена фразы доп. (29) п. 6 «перечитывает свой список» на «перечитывает
   то, на что опираются открытые задачи `HANDOFF.md`; норму… берёт из рабочего места, не из сводки сжатия» —
   строже по смыслу (источник нормы назван) и исполнимее по объёму; требование к записке (id опор у каждой
   задачи) делает перечитывание проверяемым.
7. **П. 6 (дельта перехода)** — «добавленные, изменённые и удалённые файлы» (расширение доп. (29) п. 4, где
   добавленные не были названы); «место в коде — каждому изменённому id нормы, вектора, формы, операции» —
   тот же построчный уровень, что TRANSITION доп. (29) п. 4. Определение сужения («файл остался в выгрузке, но
   вышел из списка; удаление и перенос — не сужение») точное: при удалении/переносе файл исчезает из
   пересобранного рабочего места, замена сессии не нужна — правильно отличено от тихого сужения списка.
8. **П. 7 (сохраняемая сессия)** — критерий доп. (29) п. 7 стал проверяемым: «открыта первым `PROMPT-1.md` в
   рабочем месте, собранном скриптом — проверяется по коммиту `READ.txt` и `PROMPT-1.md`».
9. **П. 8 (адресаты доп. (29) п. 5)** — «ведущая читает текст находки, чтобы свести её к месту в списке
   сессии, и передаёт только шаблон»: чтение входящих от «Архитектора» — доверенный канал, не чтение
   репозитория; передача по-прежнему только шаблоном (доп. (29) п. 5) — утечки чужих норм сессиям нет.
   «Ошибка в `common/` без вектора на случай — пробел договора: находка „Архитектору", норма — „Спецификации"» —
   замыкает контур эскалации, согласован с п. 1 (GUESSES).
