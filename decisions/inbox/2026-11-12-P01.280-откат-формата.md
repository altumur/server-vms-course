## 3. Пункт 1: как сливать и сохранять адреса

### Правило абзаца и выбор id

Один абзац объединяет соседние условия одного наблюдаемого предмета: например, ограничения одной операции, режим запуска, один ключ данных или исход одной фазы. Соседство само по себе недостаточно. Не сливать через заголовок, смену роли/режима, фазу или границу `Scope: production.`. YAML остаётся данными; обязательные условия к его ключам остаются обычной прозой рядом. Отмена нарезки не отменяет условия, приоритет отказов и отдельную боевую область.

Для каждого объединяемого блока:

1. Найти его R-id, которые упоминаются **вне трёх файлов норм P/01**, в действующих M/JI. Если такие есть, оставить первый из них **в порядке текста**, как требует answered и доп. (94), а не наименьший номер.
2. Если внешних id несколько, остальные направить на выбранный id в карте. Если внешних нет, оставить первый действующий id блока. Новый номер ради уплотнения не выдавать.
3. Старый id попытки 6 предпочтителен только когда он уже является выбранным действующим id. Не восстанавливать снятые R014/R015/R021 и не назначать старый номер другому смыслу.
4. Внутри слитого абзаца убрать ставшие самоссылками перечисления частей. Действующие ссылки между разными абзацами должны разрешаться; короткие `RNNN` проверять в контексте главы. Index пересобрать отдельно.

Пример: нынешние части `01.3` про `group.identity` (R059, R286, R060, R061, R062; строки 170–183) можно собрать в абзац о транспорте и идентичности, сохранив все условия. Выбор якоря идёт по внешним ссылкам, а не автоматически по номеру R059. Правило `join` по размеру группы с этим абзацем не сливается.

### 2. Index

На срезе 66 строк и 38 012 байт, все три таблицы перечисляют много частей одного правила. Сначала применить карту слияния, убрать повторы id в ячейке, затем оценить число **разных мест**, а не число прежних меток. Один абзац с несколькими условиями — одно место; форма + норма, разные разделы или главы — несколько.

Сохраняются темы наподобие `check_order`, `floor`, `rights_check`, `group_stand`: они связывают несколько глав и форм. `listing`, `guard_read`, `rights_file_start` и подобные короткие темы пересмотреть после слияния, а не удалить по одному числу файлов: один файл может содержать несколько удалённых друг от друга правил. Не возвращать «See also» у каждого абзаца.

Файлы — три нормы и их переводы. ### 3. Два вида проверок кода — из M, J-словарь сохраняется

В общем `forms/code-rules.tsv:35–36` два вида занимают **832 байта**; определение `part` в строках 13–19 — ещё **1 035**. В строках 20–25 смешаны общий исход проверки и детали этих видов: весь блок удалять нельзя. В P/01 C01–C24 этих двух видов нет; они нужны строкам E02–E06 J-файла `engine-code-rules.tsv:20–24`.

Построчно скрыть два вида в M, оставив тот же путь в J, нельзя: фильтры целофайловые, M должен совпадать с соответствующими файлами полной J. Рекомендую оставить **старый J-словарь побайтно по старому пути**, перевести его запись M в `judge_only`, а для M дать отдельный публичный носитель той же существующей формы, например `common/acceptance/forms/product-code-rules.tsv`: прежние семь видов, без `listed_words`, `no_literals` и их определений. Это разделение носителя; новых видов, столбцов и поведения нет. JI новый публичный файл не нужен; полная J получит его вместе с M.

Публичные ссылки инструкции и шапки строк урока должны называть публичный словарь; J-словарь движка продолжает называть прежний. Регистрацию схемы/проверок существующей TSV-формы делает Архитектор, чтение публичного словаря циклом — представитель. Перед исполнением он подтверждает место загрузки словаря: его исходник здесь не проверен.

Если представитель подтвердит, что цикл не требует машинного словаря в M, более дешёвый носитель — уже существующий раздел P01.278 с полными определениями оставшихся видов. До этого подтверждения не планировать удаление всех определений. Ожидаемое уменьшение M от разделения — около 2 КиБ, не все 8 426 байт. ## 6. judge-only: сначала ссылки и обязанности, затем пометки

Числа доп. (94) 998 / 116 КБ — исходная оценка предыдущего среза. На текущем собранном M чтение строки `judge-only:` даёт **1 106 вхождений**. У P/01 — 180, у common — 52. P01.276 сначала доводит F24/F25/F26. Затем один писатель:

1. Убирает ненужные ссылки вне M, сохраняя правило прямо в видимой норме; исторические адреса уводит в историю. Не превращает скрытые сценарии в публичные примеры и не добавляет ожидания в M.
2. Убирает повторные пояснения «judge-only: sc. …; checks R…», когда весь абзац и без них однозначен. Условия, диапазоны, границы и различие функциональной/боевой приёмки сохраняет.
3. Повторно проверяет внешние ссылки **после сужения M**. Прежние «12» не являются полным списком для нового состава: появляются контекстные ссылки на исключённые уроки.

Закрытая ссылка в сохранённом общем договоре судьи допускается только как явное исключение, когда не задаёт поведение реализации P/01.

Оно почти отменяет сужение, но не доказывает необходимости этих требований для store. Общие формы и контракты остаются целиком; их обязанности для других владельцев не становятся обязанностями P/01. Системный стенд `system/05-power-pull` требует несколько реализаций; узкий M для написания P/01 не обещает обучить все его части.

### Какие записи менять

`export-model-filter.json` хранит записи common и ещё не перенесённых уроков; `forms/export.json` — перенесённых, в том числе P/01–P/03. Нельзя изменить только общий JSON и ожидать, что исчезнут записи model из списков уроков. Для пары P/01 оператор строит отбор: публичные P/01/common + эти 24 файла, затем исключения §§4–5. Сохраняется прежнее различие model_and_judge / judge_only, без отбора частей файла.

Сужение относится **к M пары P/01**, а не молча к будущим входам всех уроков. Рекомендую оператору применить явный список этой пары к собранному M; общекурсовые записи других уроков не объявлять навсегда закрытыми ради одного выпуска. Если реализация оператора допускает только один глобальный фильтр, стороне выгрузки надо оформить воспроизводимый фильтр именно этой пары из существующей формы, не добавляя новый столбец или вид. На сдаче — полный список выбранных путей и байтов, а не только маски каталогов.

`judge-input-filter.json` и разделы `judge` списков уроков **не сужаются вслед за M**. В частности, J сохраняет сценарии, все OpenAPI для таблицы fullform, маршрутизацию и чужие части системных целей. Проверки границы M/полной J и независимости JI выполняются отдельно. Новая пара получает новые паспорта; в начатую попытку вход не подменяется.

Промежуточный неадаптированный check_spec не служит основанием вернуть снятые метки или потерять историю.

Контроль сохранности: сравнить по карте каждый исходный фрагмент с абзацем, отдельно исход/условие/предел/роль/область; сравнить чек-лист и клетки `norms` stages побайтно. Будущие проверки автора: check_spec; адреса ссылок на живые R-id; замыкание выбранных определений M; M ⊂ полная J по байтам; недоступность сценариев и эталонов из M; неизменность машинных входов J по §7. У сухого разбора движка есть предел: он не доказывает исполнение сценария и правильность GREEN.

## 10. Находка и открытые условия исполнения

**М1 — J-шапка продолжает обещать отменённые ворота движка.** Место: `Platform/common/acceptance/forms/engine-code-rules.tsv:3–4,16`. Цитата: «The generation cycle of the engine checks the rows»; далее названы `tables, plan, own_tests, run_form`. Сценарий: автор нового движка читает J и принимает это за действующий порядок генерации, хотя ADR-0135 (22) прямо отменило эти ворота. Нарушенный источник: ADR-0135 (22), пп. 1, 4; (24) — удаление линии судьи из цикла. Последствие — неверное объяснение порядка, без наблюдаемого изменения суда снимка (семантического читателя этих строк нет). Происхождение: **было раньше**; обещание проверки циклом уже есть в `cf91a3876`, прежняя редакция stage там тоже была. Рекомендация: отдельной согласованной правкой объяснения J после .271 убрать обещание действующего исполнения; TSV-путь, столбцы и строки E01–E06 этим проектом не удалять. Если ограничение сохранения J требует побайтного словаря, оставить М1 явно отложенной, не править скрытно.

Открытые условия перед исполнением, не дефекты кандидата:

- Итоговые данные текущих задач должны быть приняты. Первая часть .271 и .273 уже учтены на конечном срезе (§11); .274/.276/.278 ещё не подставлены в расчёт. Эта записка их не принимает.
- Представитель подтверждает точное чтение словаря кода и отсутствие ошибки списка чтения на group при неизменном stages.tsv; его код в этой сессии не читался.
- Архитектор утверждает остаток правила judge-only для целиком сохранённых общих договоров и таблиц, а сторона выгрузки — воспроизводимый отбор конкретной пары. Это предусмотренные проектом работы, а не новое поле формата.
- Финальный счёт абзацев, полный список путей M и dry/parse появятся при исполнении на окончательном C. Ни один из этих результатов не выдан здесь за уже полученный.
