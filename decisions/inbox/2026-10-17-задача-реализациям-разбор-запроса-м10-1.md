# Задача реализациям: разбор запроса двери хранилища по М10/1 Н2.1 (сценарии 01/24–27)

## Контекст
Пилот чистой комнаты (ADR-0080 доп. 15, `windows/cleanroom-m10-1/`) нашёл пробелы урока М10/1; «Спецификация»
закрыла их разделом **Н2.1 «Разбор запроса»**, нормой М10/1-24 и сценариями приёмки 01/24–27 (`6e104278`, `aa777d29`).
Ни одна реализация эти сценарии не проходит. У курса на main снова красны оба `test_storage_m10` (через дверь
117/132 шагов, без двери 120/132), продукт покраснеет после `sync-course.sh`. Решение владельца 2026-10-17: чинить
сейчас, не дожидаясь переноса Python. Канон — `М10_Platform/spec/01-storage.norms.md` Н2.1, Н4 (строки 253–255),
`01-storage.api.openapi.yaml`, приёмка `Source/tests/testdata/acceptance/М10_Platform/01/` (README, сц. 24–27).

## Что расходится (по прогону приёмки «Архитектора» 2026-10-17 и `windows/cleanroom-m10-1/diffprobe.txt`)

| Вход | Канон | Курс сейчас |
|---|---|---|
| команда без `key`, `key` не строка; чтение без `key` | `400 badrequest` | `badkey` (сц. 24) |
| повтор `key`/`prefix` в query | `400 badrequest` | `200`, одно из значений (сц. 25) |
| `key` после декодирования не UTF-8 (`%FF`) | `400 badkey` | `200` (сц. 25) |
| `%` без двух hex-цифр (`%zz`) | остаётся как написан | — проверить (сц. 25 шаг 9) |
| повтор имени поля в теле JSON | `400 badrequest` | `200`, последнее значение (сц. 26) |
| одиночный суррогат в `key`/`guard.key` | `400 badkey`; в `items` — `badrequest` | `badrequest` в ключе (сц. 26) |
| неизвестный метод на известном пути (`PATCH /v1/get`), путь вне Н2 | `404 {kind: badrequest}` + `Fault` | `501` со страницей HTML (сц. 27) |
| запрос не разбирается как HTTP | `400 {kind: badrequest}` + `Fault` | проверить пробой на сырых байтах (README приёмки) |

## Курс — команда курса (окно сейчас, ветка от main)
Дверь хранилища (`Source/w2cplatform/configstore.py`, `_door`) и разбор команды (`storemachine`, `canonical`) —
по Н2.1; исполнитель без двери `NativeAPI` в `tests/storage_acceptance.py` — тот же разбор. Нормы, TSV и приёмку не
менять. Проверка: оба `test_storage_m10` зелёные на 27/27 сценариях во всех исполнителях; полный unit — единственный
отказ product-parity. Отчёт — раздел «Исполнение (курс)» здесь же; платформенный diff — к чтению «Архитектора».

## Продукт — «Сборка» (по ADR-0052, механизм контракта)
**Отложено (решение владельца 2026-10-17):** продукту задача ставится после завершения чистой комнаты М10
(ADR-0080 доп. 15) и финального утверждения спецификаций М10 — одним списком долга внедрения вместе с остальными
изменениями канона. До тех пор раздел ниже — заготовка, не поручение; приёмка 01/24–27 у продукта ожидаемо красная
после синхронизации.

Дверь `configstore` (`vmsworker/w2cplatform/configstore/node/door.go`, `doormode.go`, разбор в `wire.go`) — по Н2.1:
- query не через `url.ParseQuery`/`URL.Query()`: он отдаёт ошибку на `%zz`, молча берёт первый из повторов и не
  проверяет UTF-8; нужен разбор urlencoded по WHATWG с отказами Н2.1;
- повтор имени поля и одиночный суррогат в теле — проверка до `encoding/json` (он их принимает);
- маршрутизатор `http.ServeMux` с шаблонами `"GET /v1/get"` отвечает на чужой метод `405` — канон требует
  `404 {kind: badrequest}` с телом `Fault`.
Проверка: `testdata/acceptance/М10_Platform/01` после `sync-course.sh` зелёный в `configstore/node/acceptance_test.go`.
Отчёт — раздел «Исполнение (продукт)» здесь же (курс читает решения; запись — по правилам продукта и запись окна).
