## Решения «Архитектора»
1. **Общие поля у прочего потока — отказ, не «никто не читает»** (Codex RVS-01 блокер, Claude С-4). `ref`, метки и
   прочие общие поля платформа читает (снимок, домен, счёт лицензии, размещение), поэтому у строки с непустым `main` они
   **запрещены дверью**. Средство — словом манифеста (правило строки, если диалект его выражает); если не выражает —
   пункт запроса платформе после стадии C, а до него: держатель потока с непустым общим полем — `reason`, поток не
   открывается; домен и лицензия — по-прежнему по строке, поэтому до правила двери страница общих полей потоку не даёт и
   урок пишет это ограничение прямо.
2. **Подписка и толчок между серверами несут поток** (Codex RVS-02 блокер). Внутри кластера обращения приёмника
   V/02.9 Н2 (желание, подписка, толчок) несут `stream` (id потока) рядом с `ref` камеры; состояние приёмника — по
   (`ref`, `stream`); пусто — основной. Между кластерами — только основной поток (`ref`), как сейчас. Профиль не сужается.
3. **Имя раздачи нельзя занять грантом на другую камеру** (Codex RVS-03, Claude С-1). Id строки `live/streams` —
   составной из камеры и потока (основной — id камеры; прочий — `<cam>` и `<stream>` по грамматике имени, выбирает
   «Спецификация VMS»), `about` — `cam`; грант на камеру 7 не занимает имя раздачи потока камеры 9. Сценарий с двумя
   ограниченными пользователями — в приёмку V/03.
4. **Точка RTSP потока** (Claude С-3, Kimi С-2): грант судится по камере — строка `cam` с пустым `main` — она сама, иначе
   `main` строки потока; строки нет — точки нет; одна подписка шлюза на поток.
5. **Маска детектора при смене потока** (Claude С-2, Kimi С-4): маска хранит свой размер; кадр иного размера — маска
   масштабируется к кадру по каждой оси ближайшим соседом; детекция не останавливается. Правило одно для `det` и задач скана.
6. **Учётные данные** (Codex RVS-06, Kimi С-1). П. 1.2 задела («один раз в строке устройства») не исполняется: строка
   `devices` — находка держателя, писать в неё оператору — новый контракт. Принято: пароль — в строке **камеры** (`main`),
   прочие потоки берут его у своей камеры; поток на ином хосте — со своими `cred_*` открывается, без них — `refused`
   («пароль камеры чужому хосту не отдаётся»). Каналы одного NVR — разные камеры, пароль у каждой (две записи при смене —
   принятая цена). Задел исправить этой строкой.
7. **Текст и приёмка** (Codex RVS-04, RVS-05; Kimi С-3; Claude М-1…М-7, Kimi мелкие): общий контракт Н1.1а разделить —
   прямой выбор у `rec`/`det`/`live`, наследование потока записи у `detjob`, архив устройства у камеры для `detedge`;
   сценарии `det` со `stream` (свой — 201, чужой — 409), V/01 удаление камеры с потоками, V/03 чужой поток; мелкие — по
   предложениям ревьюверов.
8. **Долги «Сборке»** (Claude С-5) — сняты `80dc42d6c`.

Правки — «Спецификации VMS» на той же ветке; повторное ревью — только изменённых мест (пп. 1–3), тремя.

## Второй круг (узкое ревью `4ff8bec45`)

| Ревьювер | Ветка, коммит | Вывод |
|---|---|---|
| Codex | `codex/review-vms-streams-2` `4821f436e` (локальная) | с правками: 1 блокер, 1 существенная |
| Kimi | `kimi/review-vms-streams-2` `c9feb6c90` | годится: 2 мелкие |
| Claude | `claude/review-vms-streams-2` `8a22353a5` | не годно: 1 блокер, 3 существенные, 3 мелкие |

9. **Раздача — одна строка на камеру** (Claude Б-1, С-1). Составное имя раздачи не защищает: `name`, `cam` фиксированы,
   захват `{name:"9", cam:"7"}` оставляет надгробие с чужой `cam`, и законная раздача камеры 9 получает 400 навсегда.
   Решение без платформы: id строки `live/streams` = id камеры (`about` — по id, грант на камеру 7 не создаёт строку
   камеры 9; удаление неразмещённой — штатно, P/02.1); нужные потоки — **список** `streams` в строке (правится, CAS),
   шлюз раздаёт каждый поток списка этой камеры, чужой поток списка — `reason`, не раздаётся. Сценарий 02-two-viewers —
   на этой форме. Пп. 3 первого круга и «окно до прохода шлюза» — сняты.
10. **Общие поля потока — инертны, не отказ** (Claude С-2). Форма модуля (`display.form`) даёт их и потоку; отказ
    держателя гасил бы поток штатной правкой. Счёт лицензии и домен строки с `main` уже не считают (`domain.view`);
    поэтому держатель общие поля потока **не читает и поток не гасит**; метки потока действуют только как ограничение
    размещения, как у любой единицы (урок говорит это прямо); страница их потоку не предлагает. Меняет п. 1 первого круга
    в части «держатель не держит».
11. **Идентичность в обращениях приёмника внутри кластера — (`cam`, `stream`)** (Codex RVS2-01). `ref` может быть пуст
    у двух камер; внутри кластера желание, подписка, толчок и опрос V/02.9 несут местный id камеры `cam` и `stream`
    (пусто — основной), приёмник ведёт всё по паре (`cam`, `stream`); между кластерами — `ref` и только основной поток,
    как сейчас. Меняет п. 2 первого круга.
12. **Смена `stream` у детектора — перезапуск модели по ревизии** (Codex RVS2-02, P/03.3 Н3 шаг 2); смена размера
    кадра внутри того же потока — маска масштабируется заново, модель не останавливается. Фраза V/04.2 — разделить.
13. **Маска PGM** (Claude С-3 и мелкие): P5, `maxval` 255, без комментариев, один пробельный разделитель; ширина и
    высота ≤ 1024, файл ≤ 1 МиБ (меньше предела тела); масштаб к кадру — целочисленный ближайший сосед
    (`x_src = floor(x * w_mask / w_frame)`), векторы на масштаб и грамматику.
14. Мелкие Kimi (403 раньше 409 в Н1.2; два смысла директивы `holder` стенда домена VMS) и Claude — по предложениям.
15. **Уточнение п. 9** (вопрос «Спецификации VMS»: список `streams` в строке зритель править не может — PUT строки единицы
    требует `admin`, `rights.routes` понижает только создание): строка `live/streams/<cam>` — без списка; поток выбирается
    **на двери шлюза** — `POST /whep/<cam>?stream=<id>` (пусто — основной), токен — по `view` на камеру (`where/<cam>`);
    шлюз проверяет, что поток принадлежит этой камере (строка `cam` с пустым `main` — она сама, у потока `main = cam`),
    иначе 404 со словами; подписки — по (`cam`, `stream`), у каждой своя отсрочка. Захватывать нечего, надгробие всегда
    совпадает с камерой.
