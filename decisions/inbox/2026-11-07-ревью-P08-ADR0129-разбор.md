## Решения по источнику

1. **review103 С01, аварийная ревизия.** Принято. При включённой границе расхождения часов прежняя формула может дать равную ревизию. Сохранить TOKEN_SKEW и only_forward, исправить строгое целочисленное превышение: max(known_rev+1, floor(now)+TOKEN_SKEW+1). Единица — математический следующий целый, не новая настройка или допуск часов. Согласовать обычную/аварийную ветви, проверку формата и предела представления; непредставимый набор не публиковать, не насыщать и не оборачивать ревизию. Точный существующий исход у предела показать в плане, нового слова отказа не вводить.
2. **С02, deleting.** Принято. Writer должен представлять нынешние at/done, а не требовать пустую строку. Согласовать N3 с обязательным удержанием метки завершённого удаления до at+TOKEN_LIFETIME+TOKEN_SKEW. Испорченные метки без читаемого at, ещё читаемый users и незавершённый DELETE — отдельные нынешние случаи. Перед правкой процедуры нужна точная карта этих ветвей: не убрать восстановление, не освобождать имя до срока и не выдавать неисправную метку за нормальную.
3. **С03, members.** Принято. Удалить лишний writer-предел 500 элементов: он не задан процедурой. Сохранить байтовые MEMBERS_MAX/ENTRY_MAX, отдельный SERVERS_MAX, подпись и CAS. 501 камера ниже байтового потолка не получает выдуманного count-отказа. Этот ошибочный предел не переносить в reader по З-10.
4. **С04, ответы членства.** Принято. Достижимые закрытые Entry/MembersAnswer/MembersDoc согласовать с нынешними part, class, url, via и batch по их действительным условиям. Составить карту всех трёх ответных дверей и подписанного документа. Не открывать произвольные поля и не возвращать прежний ответ ради схемы.
5. **С05, Carry.** Принято. Topology содержит нынешний digest at/sha256, тело doc/via получается отдельной дверью. Folders выражает full и null удаления. Носитель исправляется по действующей процедуре; новых дверей или доставки нет. Anywhere не верхнее поле Carry: остаётся внутри sealed. Снятая авторская гипотеза не считается находкой.
6. **С06, knock.** Принято. Обе семьи view/view-rows согласовать с нынешним обязательным class и условным batch. Закрытость, типы и связь batch с классом/источником сохраняются. Удаление class у писателя не решение; сверить владельца accept и все физические копии.
7. **С07, siblings.** Принято. Соответствующие 409 допускают точный закрытый вариант siblings с ids. Сохранить отличия от executors, обязательность/типы ids и нынешний поиск id/cluster. Общий Refusal не открывать произвольным полям.
8. **С08, повреждённая папка.** Принято. DomainFolderView выражает отдельные читаемый и garbled-варианты. Повреждённый элемент {id,garbled:true} не исчезает и не превращается в нормальную папку с факультативными полями. Это нынешнее повреждение, а не поддержка старого формата.
9. **С09, token expect.** Принято. N5 ссылается на единственную нынешнюю закрытую форму expect с keep. Сохраняются типы, отсутствие keep, явный список и code 2 неизвестного поля. Общий точный договор не сужается под неполную копию N5.
10. **С10, З-10.** Принято. Удалить положительное чтение former installations с нормализацией существующей нечитаемой revision в 0 и записью 1. Согласовать все версионные семьи, исходы, условные записи и два legacy-шва. Законное отсутствие строки, создание revision=1, явное удаление повреждения и восстановление нынешних копий сохраняются. Чтение неизвестных полей opened sealed не оправдывать старым агентом: согласовать текущую форму с уже существующими исходами нечитаемости и сохранением копий, без нового отказа/миграции/прав. Точный стык с P/09 до правок.
11. **С11, пределы.** Принято. Reader/writer для pending/outcomes держателя имеют нынешний предел 50, для alarm-history — HISTORY_LINES=2000. Max+1 получает существующий unreadable; усечения при чтении и миграции нет. Копия outcomes=500 у агента — другой носитель, её смысл не менять. Равные пределы разных смыслов сохраняют своих владельцев; не объединять их только по числу. Каждый новый числовой носитель объявить для отдельного расширения существующего предметного судьи.
12. **М01, ключ.** Исправить отрицание P/08.6-R013: отсутствие Idempotency-Key даёт 400, присутствие запускает нынешние проверки. Ключ и повторы не меняются.
13. **М02, duplicate JSON name.** В 01-roll-delivered/3 поле missing у t1 остаётся единственным и ожидает @absent, как нынешняя N1.3 result: missing находится лишь в голове «». Удалить вторую missing:[] у t1, сохранив голову, остальные ожидания и запрос. Два одинаковых JSON-имени не считались двумя исполненными проверками. До изменения строки — точная декларация.
14. **Kimi С1, четыре числовые копии.** Убрать дубли значений SHADOW_STALL/SHADOW_CLEAN/REPORT_EVERY/BACKUP_HOLDERS из прозы/чеклистов, оставить ссылки на владельцев. Размер стенда «два члена», математические производные и фактические ожидания не подменяются настройкой. Значения и сценарные байты меняются только по явно принятому другому пункту.
15. **Kimi С2, порядок missing.** Не принято. Во входе cameras=m000…m299, остальные m300…m599 — server. Порядок сервера перед камерами и по имени даёт точно существующие 500 элементов. Архитектор независимо сравнил все 500 имён, не исполняя assemble. Ни вектор, ни порядок нормы менять не нужно.
16. **Kimi М1/М3/М4 и опечатка.** Исправить описательный счёт швов/векторов, шапку операций API и описание ghost-фикстуры по фактическим данным. Можно убрать вторичный счёт и сослаться на перечень. URI/operationId, фикстура и ожидания не меняются. Опечатка the33 в общем turn исправляется только после точного согласования пересечения с P/03.
17. **Kimi М2, anywhere.** Принято как уточнение ссылки и действующей неизвестности, не новая доставка. Общий envelopes уже задаёт held/anywhere; не исключать его. Нечитаемая нынешняя сводка — существующий held, отсутствие строки — отсутствие поля. Переполнение новой сборки оставляет прежнюю строку по N1.3; если она читаема, переносится прежний digest/as_of. Не вводить новое held только из этого примера и не освежать старую сводку. Точность {doc,as_of} и независимость от grants сохраняются.

## Судья и числовые носители

**J-P08-01.** Принят отдельный дефект механики test_gen_vectors_lessons.py. Python-инъекции доказывают допуск ошибочного отчёта, не 151 реальный pass и не фактическую Go-ошибку. До приёмки отдельно оценить влияние на прежние доказательства. Сам статический дефект не отзывает всё З-9 автоматически; найденная фактическая ошибка отзывает именно затронутое подтверждение.

Отдельная однофайловая доля через coord103/review103: полный ненулевой именованный состав текущих входов, нормальное завершение и связь отказа с затронутым мутантом. Exit0 соответствует полному pass; exit1 допустим при полном согласованном named fail. Compile/start/panic, неожиданное завершение/exit2, неполный/лишний/дублированный/неразобранный ответ — ошибка проверки, не обнаружение. Устойчивый мутант — пробел. Сравнение P/01 TestCommon можно исключать только после общей служебной проверки, без скрытия аварии. Ни >150, ни чужой fail не доказательство. Входы, оракул и смыслы мутаций прежние. Ограниченный фактический аудит прежнего судьи/драйверов — по точной области coord103, без нового SUT/модели/линии/общей генерации.
