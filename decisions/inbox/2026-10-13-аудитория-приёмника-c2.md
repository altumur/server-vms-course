# C2: приёмник курса и токены ещё не перенесённых книг

## Контекст
Подключаю обычных издателей/читателей sources/primaries по Решению
«значения-книг-c2». Ядро выдаёт stream с aud = список cluster+copies,
без ingest-префикса. Ingest курса (_check в vms/domainpart/ingest.py)
принимает только aud = строка ingest:<cluster>. Не перенесённые polls
и upstream сейчас выпускают stream с такой строкой; ask имеет отдельный
вид и свою строковую аудиторию. В форме C2 «приёмник без изменений»,
поэтому не могу точно зеркалить его фактическое поведение по этому месту.
Продукт не читаю. Издателей и читателей готовлю независимо.

## Рекомендация
Закрепить единый приём stream по списку имён кластеров: принимающий кластер
входит в aud, ref совпадает, подпись/срок/отзыв проверены; ingest:<cluster>
для stream отвергается, двойного чтения нет. При подключении C2 изменить
ещё существующие выдачи stream для polls/upstream на aud:[cluster], без
смены их объёма и без переноса самих книг; ask здесь не меняется.
Если продукт уже использует другую форму до C3/C4, описать её как отдельный
объём, чтобы курс повторил байты без совместимости. Подтвердить также
выдержку пушера при отсутствующем primary-наблюдении: до её истечения
резервный поток не открывать, затем пробовать все назначенные резервы
по одному; явный running:false у primary разрешает резерв немедленно.
