# Сохранённый вклад освобождённого слота не должен оживать со свежим отчётом агента

## Контекст
При подготовке C2 проверил сборщик курса на testsub: Worker.put_under_slot успешно
пишет testsub/counts/w-9, затем слот освобождён и истёк; свежая подписанная
publication агента всё ещё доставляет старый вклад. bookruntime.collect принимает
его как факт с missing: []. guard отсекает позднюю запись, но не помечает сохранённую
строку после освобождения. bookruntime.py читает только items входов, uplink.py
не переносит связь вклада со слотом. Это нарушает условие принятой схемы: свежий
агент не превращает вклад умершего воркера в актуальный факт. Продукт не читал
и не менял. Поправки C2 и ADR-0079 прочитаны; книги ещё не активированы.

## Рекомендация
Сохранить общий механизм в платформе, без хуков подсистем и без вычисления
медиа-полей. Предлагаю дополнить уже принятую форму guard: хранилище сохраняет
guard успешной записи вместе с целевой строкой атомарно; агент получает его как
метаданные строки и переносит рядом с items/idx в том же целостном отчёте.
Для строк входа from наличие guard обязательно. В том же отчёте фиксируется
соответствующая строка слота. Сборщик проверяет совпадение guard.index с индексом
слота, непустого держателя, released=false и срок слота относительно sent_at
члена. Нет доказательства, слот истёк/освобождён/сменился, связь повреждена —
вклад этого члена для книги missing, без выбора другого старого значения.
Пустой вклад живого писателя остаётся подтверждённо пустым. Обычный воркер пишет
через прежний put_under_slot; ни второго доменного исполнителя, ни самостоятельного
протокола владения у подсистемы не появляется.

Форма до кода: rows[<путь-входа>] получает guard: {key, index}; не меняем путей
вкладов, не вводим вторую строку указателя и не храним токены. Обновление слота
тем же владельцем сделает вклад временно неподтверждённым до новой публикации
воркера — безопасный отказ; цена по смыслу совпадает с уже принятым дополнительным
412 при обновлении слота. Предлагаю закрепить это дополнением 3 ADR-0074 и включить
в проверку C2 обеих сторон; отражение в локальном протоколе чтения/формате файла
хранилища также нужно утвердить до реализации. Альтернативу ограничиться сроком
самого отчёта не рекомендую: отчёт агента свежий при умершем воркере.

## Воспроизведение в курсе
На платформенном ядре ветки codex/course-primaries-sources, без VMS:

```python
import json
from tests.test_book_runtime import site, publish_all
from w2cplatform.domain import bookruntime
from w2cplatform.worker import Worker
with site() as e:
    s = e.specs[0]
    w = Worker(s.sub, None, e.north.vars, e.north.objects,
               wall=e.wall, clock=e.wall, spec=s)
    w.claim_slot('w-9')
    w.put_under_slot('testsub/counts/w-9',
                    {'i': json.dumps({'name': 'badge', 'to': 'south', 'n': 7})})
    slot = e.north.vars.get('testsub/slots/w-9')[0]
    slot.update(released='true', until='0')
    e.north.vars.put('testsub/slots/w-9', slot)
    e.north.vars.put('domain/grants/south', {'badge|view|': str(e.wall() + 500)})
    publish_all(e)
    result = bookruntime.collect(e.holder, s, 'counts')
    assert json.loads(result.rows['south']['badge'])['entries']
    assert 'north' not in result.missing
```
