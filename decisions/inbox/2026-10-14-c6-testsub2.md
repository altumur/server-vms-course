# C6: общий specimen scenario в testsub2

## Контекст

C5 слит c4e7f27d по cdd2c1f5. В C6 generic scenario реализуется на двух
независимых testsub/testsub2, без VMS. Чтобы test_spec_rule продолжал
проверять каждый ключ по настоящим YAML, нужна общая fixture нового scope.
Сейчас unit/placement представлены testsub, у testsub2 token kinds нет.
Прежде изменения общих байтов предлагаем форму; продукт не меняем.

## Рекомендация

У testsub2 дополнить domain существующим ref:name (name уже в snapshot),
документом shared.rules (json, array объектов) и видом tally2:

```yaml
domain:
  ref: name
  shared:
    - name: rules
      type: json
      schema:
        type: array
        items:
          type: object
          required: [name, when, then]
          properties:
            name: {type: string, minLength: 1}
            enabled: {type: boolean}
            when: {type: object}
            then: {type: object}
  tokens:
    tally2:
      lifetime: 60
      claims: [ref, by, acts, up, aud]
      grant: [testsub2worker]
      scenario: {doc: testsub2, items: rules, name: name, enabled: enabled,
        trigger: when.item, target: then.item, act: then, placement: testsub,
        ref_claim: ref, trigger_claim: by, acts_claim: acts, up_claim: up,
        audience_claim: aud}
```

Нынешние reports и witness сохранить. worker.writes не вводить.
Это независимый от VMS пример принятой формы C6; имя tally2 уже используется
в generic tests запросов токенов, но в общем YAML его ещё не было.
Предлагаем включить specimen в C6, до кода fixture подтвердить форму;
на чтении итогового C6 показать этот diff отдельно для sync-course.sh.
Ведомость продукта не трогаем. Если общему specimen нужна строка долга курса,
рекомендуем `testsub2:domain.tokens.tally2 # ADR-0074 «курс»` до sync;
spec parity сейчас сверяет VMS, поэтому не подмешивать эту строку в его
закрытый формат, а отметить долг общих байтов в записи окна C6.
Пока fixture не добавлена; ядро и две scoped test-фабрики проверяются отдельно.

## Решение («Архитектор», 2026-10-14)

**Форма принята с тремя уточнениями.** (1) Ключи объёма `scenario` — ровно по форме C6 продукта и поправке `scenario.placement` (ADR-0074): `{doc, items, name, enabled, trigger, target, act, placement?, ref_claim, trigger_claim, acts_claim, up_claim, audience_claim}` — ваш `tally2` им соответствует; `doc: testsub2` — свой общий документ, `placement: testsub` — чьи записи размещения называют дом цели. (2) Документ `shared.rules` — грамматика продукта (`domain.shared: [{name, type: json, schema}]`, как `auto.scenarios`): у элементов `additionalProperties: false` и `maxItems` у массива (закрытость, ADR-0012). (3) **Общий `testsub2` — один файл с обоими образцами объёмов.** У продукта в его `testsub2` уже есть образец объёма `placement`: `books: {notes: {from: testsub2/notes/, key: ref, pick: unique, to: to}, rolls: {from: testsub2/rolls/, key: ref, pick: all, to: to}}`, `names: {notes/: {exclusive_with: domain/users, grant: view}}`, `tokens.feed: {lifetime: 600, claims: [aud, ref], grant: [testsub2worker], placement: {sub: testsub2, caller: origin, ref_claim: ref, target_fields: [cluster, copies], audience_claim: aud}}` — перенесите его в курсовой `testsub2` рядом с `tally2`, чтобы после синка загрузчики обеих сторон проверялись одним YAML; `kept: [badges/]` с `names.badges/` **не** переносить — `kept`-форму снял шаг C5 (ADR-0074, доп. 2), у продукта это остаток (ему сказано). `worker.writes` не вводить. Долг общих байтов — в записи окна C6, не в ведомость паритета VMS. Итоговый diff `testsub2` при чтении C6 — отдельно, для `sync-course.sh`.
