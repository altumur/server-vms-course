# C6: общий specimen scenario в testsub2

## Контекст

C5 слит c4e7f27d по cdd2c1f5. В C6 generic scenario реализуется на двух
независимых testsub/testsub2, без VMS. Чтобы test_spec_rule продолжал
проверять каждый ключ по настоящим YAML, нужна общая fixture нового scope.
Сейчас unit/placement представлены testsub, у testsub2 token kinds нет.
Прежде изменения общих байтов предлагаем форму; продукт не меняем.

## Рекомендация

У testsub2 дополнить domain существующим ref:name (name уже в snapshot),
документом shared.rules (json, array объектов) и видом tally2:

```yaml
domain:
  ref: name
  shared:
    - name: rules
      type: json
      schema:
        type: array
        items:
          type: object
          required: [name, when, then]
          properties:
            name: {type: string, minLength: 1}
            enabled: {type: boolean}
            when: {type: object}
            then: {type: object}
  tokens:
    tally2:
      lifetime: 60
      claims: [ref, by, acts, up, aud]
      grant: [testsub2worker]
      scenario: {doc: testsub2, items: rules, name: name, enabled: enabled,
        trigger: when.item, target: then.item, act: then, placement: testsub,
        ref_claim: ref, trigger_claim: by, acts_claim: acts, up_claim: up,
        audience_claim: aud}
```

Нынешние reports и witness сохранить. worker.writes не вводить.
Это независимый от VMS пример принятой формы C6; имя tally2 уже используется
в generic tests запросов токенов, но в общем YAML его ещё не было.
Предлагаем включить specimen в C6, до кода fixture подтвердить форму;
на чтении итогового C6 показать этот diff отдельно для sync-course.sh.
Ведомость продукта не трогаем. Если общему specimen нужна строка долга курса,
рекомендуем `testsub2:domain.tokens.tally2 # ADR-0074 «курс»` до sync;
spec parity сейчас сверяет VMS, поэтому не подмешивать эту строку в его
закрытый формат, а отметить долг общих байтов в записи окна C6.
Пока fixture не добавлена; ядро и две scoped test-фабрики проверяются отдельно.
