# Запрос: `If-Match` у записи страницы через модуль консоли — `api(method, path, body, {ifMatch})`

**Какая норма мешает.** P/07 Н1.5 `api` (`07-console-module.norms.md:70`): `console.api(method, path, body)`. Заголовков
у вызова нет. P/06.5 Н1.1 `shell.may` (`06.5-console.norms.md:79–81`): оболочке разрешены вызовы библиотеки и свои двери
к держателю по `door` из `where()`, а прямого `fetch` к двери консоли нет. Дверь консоли CAS умеет: P/06.1 Н3 «править» —
`If-Match: <revision>` у `PUT` и `DELETE` необязателен, при несовпадении 412 `{error: "revision moved", revision}`. Но
страница до него не дотягивается. Без `If-Match` `PUT` накладывается на свежую строку, и «обе отвечают 200» (P/06.1 Н3).

**Что нужно VMS.** ADR-0093 п. 6, доп. (1) п. 6: план ассистента применяется по строке. Правки одной строки — одним `PUT`
с той `revision`, которую админ видел в diff. Строка изменилась между чтением и «Применить» — 412, строка не
применяется, план перестраивается. Без `If-Match` чужая правка, сделанная после чтения, молча затирается. Это та
подмена, от которой ассистент и защищает.

**Обхода нет.** «Прочитать, сравнить `revision`, `PUT`» оставляет гонку между чтением и записью — это не CAS, который
обещает ADR-0093. `revision` в теле `PUT` поменяла бы форму двери. Свой `fetch` к консоли оболочке не разрешён.

**Рекомендация** (одна возможность, версия модуля не меняется — образец ADR-0091 доп. (25) п. 1):

```
api:       console.api(method, path, body, opts?) → ответ | throw {status, body, retry}
           opts.ifMatch — целое revision (P/06.1 Н3) → заголовок If-Match у PUT и DELETE; у прочих методов — отказ вызова
           (throw до запроса); иных полей у opts нет, произвольных заголовков модуль не шлёт
           412 → throw {status: 412, body: {error: "revision moved", revision}, retry: false}; ошибки HTTP прежние
           повторы прежние: PUT и DELETE без памяти повторов автоматически не повторяются, при неизвестном исходе —
           сначала чтение (Н1.5)
features:  + "api.if-match"
```

- Правит «Спецификация»: P/07 Н1.5, опубликованные байты модуля и jsdom-тест `module-page-calls` (вызов с `ifMatch`, 412,
  отказ `ifMatch` у POST, `features`).
- Довод сверх VMS: форма модуля сама пишет без CAS, и тем же `ifMatch` два админа перестают затирать правки друг друга.
  Это довод, а не условие запроса.
- P/06.1 и OpenAPI урока 6 не меняются.

**Чего не прошу:** проекции ограничений поля (`schema`, `ref`, `must_match`) в `FieldView` — позже, по нужде (ADR-0093
доп. (1) п. 10, П2); фильтров у `GET /<rows>`, выборочной установки, подписей значений меток, `rights` в `ManifestView`
(П3–П6 — не просить).

**Что ждёт ответа.** V/10.6 пишется с `api(..., {ifMatch})` и проверкой `features` ("api.if-match"). Нет строки — панель
кнопку «Применить» не даёт и называет причину словами: применения без CAS у ассистента нет.
