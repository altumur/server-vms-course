# Факты рекордеров: `primaries`

## Контекст

В курсе `a31b0c59` `Source/vms/domainpart/crossing.py:312` собирает желаемое состояние из
`rec/snapshot/`, фактическое из `rec/heartbeats/` и добавляет адреса ingest с токенами. Камера получает полный
вариант; резервный кластер — факты без `ingest`. Читатели: `RecWorker.carried_primary` в `recworker.py`,
`CameraPusher` в `domainpart/ingest.py`, страница через `primaries.show`.

## Рекомендация

Рекомендую книгу наблюдений рекордеров с `pick: all`; основной и резервные издатели здесь нормальны,
поэтому `unique` по камере неверен. Основного определяет платформенное размещение, а не порядок массива.
Перенести владение книгой в `rec`: это отдельное предложение смены пространства имён, не уже принятое
следствие ADR-0074. Оно позволяет `from` оставаться в своей подсистеме и не выдавать рекордеру запись в VMS.

| Звено | Предложение |
|---|---|
| Издатель | Обычный `RecWorker`, по каждой принадлежащей ему записи; факт `running` сообщает сам исполнитель. |
| Вход | `rec/primaries`: объект с `ref`, `recording`, `enabled`, `running`, `starting`, адресами ingest/архива и доступным покрытием. |
| Правило | В `rec.subsystem.yaml`: `primaries: {from: rec/primaries, key: ref, pick: all}`. |
| Получатели | Кластер камеры, кластер основной записи и явно назначенные резервные кластеры этой камеры. |
| Читатель | Камера принимает решение о своей карте; резервный `RecWorker` — о покрытии; основной — о дозаписи; страница показывает факты. |
| Результат | Предлагается `domain/rec/primaries` вместо `domain/vms/primaries`; чтение на стороне VMS разрешается узко декларацией прав. |

`member` оболочки — кластер факта; `recording` — идентификатор одной записи, не склеенная через запятую строка.
Новый обязательный `ref` связывает её с камерой. Несколько записей одной камеры остаются отдельными `entries`.
`enabled`/`starting` требуют сопоставления назначения и запуска: непоявившийся воркер не может сообщить сам
о себе. Рекомендую читателю брать ожидаемую запись из размещения, отличать «ещё не сообщил» от «сообщил stopped»
и сохранять прежнюю выдержку перед записью карты. Нельзя объявлять её `running` из одного назначения.

Читатель собирает прежнее представление `recorded_by`, `recording`, `backups` из фактов и назначения.
При `missing` или устаревшем факте нельзя считать основную запись подтверждённой: карта/резерв включаются
по нынешним правилам покрытия; это не выдаёт новую эпоху основной записи. Публичное представление страницы
нужно согласовать вместе с заменой `show`, которое теперь относится к `value`, а не старому составному объекту.

Не помещать `token_secret` в общую запись наблюдений: резерву он не нужен. Камера запрашивает свой `stream`
токен для объявленного ingest. Если токен требуется доставить ей через книгу, это отдельная адресная проекция,
которую нельзя незаметно смешать с `all`. Для первичного обмена маршрутом не требуется уже работающий поток.

Новые пути на согласование: `rec/primaries`, `domain/rec/primaries` и его экземпляры по членам.
Альтернатива — оставить книгу VMS и дать `recworker` запись `vms/primaries`; не рекомендую: это чужой контракт
записи и отдельное межподсистемное право вместо владения собственными фактами. До решения старое имя не удаляем.

## Приёмка

- Основная и две резервные записи не конфликтуют при `all`; порядок доставки не выбирает основную.
- Переезд, ещё не запущенный рекордер, остановка и устаревший heartbeat дают прежние переходы карты и резервов.
- Резерв не получает токен камеры; страница показывает каждую резервную запись с её кластером и идентификатором.
- Результат не создаёт цикл: рекордер публикует назначение/состояние до разрешения источника, а камера узнаёт ingest до отправки.


## Отличие от принятой формы

Дополнение ADR-0074 сохраняет существующее имя результата. Смена подсистемы-владельца в этой записке
меняет полный путь результата и потому требует явного уточнения ADR Архитектором. До такого решения
действует прежний путь VMS. Это предложение, а не разрешение исполнителю переименовать книгу.

## Общие условия переноса

Это предложение до кода. Реализация начинается после шага 5 ADR-0070 и ответа Архитектора в этом файле.
Форма результата — утверждённые `entries[{member,item,value}]` и обязательный `missing`; принадлежность
ставит платформа, время полезной нагрузки не выбирает победителя. Потерянный по виду домена член за
`lost_after` исключается; член в окне без свежего отчёта входит в `missing`. Пустой вклад, отказ чтения и
незавершённый отчёт различаются. Удалённый вклад не возвращается от повторной доставки старого поколения.
Для пустой книги нужно отдельно подтвердить, где передаётся `missing`, если нет ни одного ключа результата.

Входная строка общая для кластера: каждый обычный воркер меняет только принадлежащие ему элементы, через
CAS с сохранением соседних. CAS сам по себе не отсекает прежнего владельца; право записи элемента должно
проверяться по действующему владению/epoch при публикации. Нельзя вводить отдельного доменного писателя
для сборки этой строки. Если действующий контракт этого не обеспечивает, форму общего механизма согласуем
до кода. Свежий агент не превращает оставшийся вклад умершего воркера в актуальный факт.

Адресная доставка не выражается `from/key/pick`. Указанные ниже получатели — требование к её отдельному
предложению, а не неявная реализация фильтра в платформе. До её утверждения книгу не переводим и не рассылаем
всем. Токены получает нуждающийся в них воркер через `tokens.<вид>.grant`; доступ к ключу подписанта не нужен.
Новые имена из этой записки не действуют до решения. После принятия — спека и долг `# ADR-0074 «курс»` одним
коммитом курса; код платформы, спеки и общие таблицы остаются в ветке до чтения diff Архитектором. Продукт не трогаем.

## Решение
«Архитектор», 2026-10-11, ночь. Принято, включая смену владельца: книга `rec`, результат `domain/rec/primaries`, прежнее `domain/vms/primaries` без алиаса (п. 1). `rec/primaries/` по рекордеру, `key: ref`, `all`; `recording` — один идентификатор; основного называет размещение; `token_secret` в книге нет; `to` — кластер камеры, основной и резервные.

Общие ответы на четыре вопроса всех шести файлов (владение книгой издателем, семья строк во `from` вместо общей строки с CAS, ключ `to` для адресной доставки без широковещания, `missing` в элементе с пустым именем) — в дополнении ADR-0074 «шесть книг». Файл снимается следующим коммитом (ADR-0073), текст остаётся в истории.
