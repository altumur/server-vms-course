# Запрос токена обычным воркером перед переключением primaries/sources

## Контекст
Diff назначений принят 3e4cba70 с поправкой 69f92ae4; исполнена в ветке
`codex/course-primaries-sources`, код ac689e82: агент пишет domain/placed/, запрет
!domain/placement* восстановлен. Следующий шаг — две книги одной пачкой. ADR-0074
п. 6 требует tokens.<вид>.grant роли и запрос stream самой камерой без token_secret
в primaries. Но spec.py:995 допускает только lifetime/claims, tokendoor.py:6–12 —
локальный сокет держателя, signer_service.py не принимает удалённый запрос токена.
CameraPusher сегодня получает готовый токен из старой книги. Новая форма запроса
пересекает провод; до ответа её не реализую. Продукт не менялся.

## Рекомендация
Принять общий платформенный запрос токена с авторизацией по спеке. Предлагаю
локальную дверь агента для воркера → подписанный запрос члена подписанту → ответ
только этому запросившему воркеру. Ключ члена остаётся у агента, ключ подписи — у
подписанта; обычному воркеру не выдаются ни тот, ни другой. Токен не попадает в
строку вклада, собранную книгу, отчёт члена, журнал или копию держателя.

Предлагаемая форма до кода:

- `domain.tokens.<kind>.grant: [<роль>…]`; отсутствие grant запрещает запрос
  обычного воркера. Локальная дверь проверяет роль по существующей личности
  процесса/выделенному сокету, а не по полю, присланному воркером.
- У подписанта `POST /api/tokens/<member>/<sub>/<kind>`: подписанное ключом
  принятого члена тело `{request_id, role, ref, target}`. `role` удостоверяет агент
  после локальной проверки. Идентификатор и целевой маршрут входят в проверяемые
  байты; проверку подписи и срока запроса строить на существующем механизме
  запросов carry, включая ретранслятор. Ретранслятор не становится автором.
- Ответ `{request_id, token}` — запечатан для запросившего члена существующим
  механизмом; агент отвечает только исходному локальному соединению. Таймаут
  отменяет соединение, повтор запрашивает заново; постоянной очереди ответов нет.
- Нельзя просто разрешить принятому члену произвольные subject/claims: декларация
  lifetime/claims ограничивает имена, но не полномочия. Для связи с назначением
  предлагаю `domain.tokens.<kind>.placement: {sub, caller, ref_claim,
  target_fields, audience_claim, audience_prefix}`. `caller` — одно поле строки
  назначения, `target_fields` — список её полей; закрытые допустимые значения
  ссылочных полей: cluster/origin/copies. Подписант читает свою domain/placement/,
  проверяет член-заявитель и target; claims формирует сам, ref из запроса,
  audience из проверенного target. Никаких предметных callback.
- Для VMS stream: `grant: [vmsworker]`, `placement: {sub: rec, caller: origin,
  ref_claim: ref, target_fields: [cluster, copies], audience_claim: aud,
  audience_prefix: "ingest:"}`. Subject — ref; получатель по-прежнему проверяет
  kind/ref/aud существующего токена. Если назначение отсутствует, повреждено,
  с непринятой ссылкой или член не совпал — токен не выдаётся.

Рекомендую ограничить это окно выдачей по назначению для primaries/sources.
Для polls/upstream/asks нужны отдельные декларации области полномочий по
топологии/сценарию в следующих окнах; не расширять право выдачи здесь на них.
Прошу подтвердить форму либо указать уже принятое решение, которое я пропустил.

окне двух книг. Издатели/спеки ещё не переключены; принятую промежуточную ветку
отдельно в main не вливать.

## Решение («Архитектор», 2026-10-12)
Форма принята с уточнениями — ADR-0074, дополнение 5 (52c19713). Уточнения: тело запроса `{request_id, role, ref}`
без `target` — объём считает подписант из записи назначения; `audience_prefix` нет, имена кластеров в `aud` как в
записи; ответ `{request_id, token, exp}`; `placement` — закрытый набор полей записи `cluster`, `origin`, `copies`.
Роль воркера — по личности процесса (сокет роли, ADR-0031), не по полю. Объём — только назначение, только
`primaries` + `sources`. Ключи `grant` и `placement` кладёт курс со строками `# ADR-0074 «курс»`, продукт зеркалит
окном C. Промежуточную ветку отдельно не вливать — верно. Файл снимаете при слиянии двух книг.
