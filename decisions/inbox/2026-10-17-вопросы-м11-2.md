# Вопросы М11/2 «Корень, набор ключей, ключ приёма книг, смена и отзыв без связи»

Свидетели (курс `Source/w2cplatform`, продукт `vmssubsystem`) расходятся в байтах почти всего, что урок нормирует.
Норма нужна одна (её читают `cammeta-*`); ниже — развилки, где ADR формы не задаёт или задаёт «у каждой стороны своё»,
с рекомендацией. Расхождение свидетеля с выбранным — долг «Сборке» (продукт) и строка ХОД (курс заморожен).

## 1. Что подписывает корень

- Курс: X.509-сертификат выпускающего держателя, набор `domain/keys`, записи срока (`term.found`, перенос).
- Продукт: набор `domain/keys` и JSON-удостоверение держателя (`{what: holder, issuing_pub, token_pub, term, …}`);
  запись срока подписывает ключ токенов держателя с цепочкой удостоверений; X.509 под корнем нет.

**Рекомендация.** Корень подписывает только набор `domain/keys`; запись срока и удостоверение держателя — урок 10
(интерфейс: `issuing[]` набора называет ключи, которыми держатель подписывает свои записи срока). X.509 под корнем домена
нет: TLS ролей — центр стенда/поставки (ADR-0075, М10/11 Н1.6), LDevID и регистратор М12A/06 — не в М11 (долг М13 по
ADR-0080 доп. 4, вместе с лицензией). Корень нужен: установка, перенос с кражей (урок 10), смена ключа приёма книг —
и больше никогда; держатель его не хранит (`domain/signer` без корня, `backup` корня не несёт).

## 2. Форма набора `domain/keys`

Обе стороны: `{"doc": <JSON>}`, подпись Ed25519 корня над JCS документа без `kid`/`sig`, `rev` — `max(прежняя + 1,
целые секунды стенных часов подписанта)`, `book_seal` обязателен. Различия: курс — `keys: {current, book_seal,
"key:<kid>", "retire:<kid>"}`, `revoked_ca`; продукт — плоско `current`, `keys {kid: hex}`, `until {kid: секунды}`,
`issuing`, `revoked_issuing`, `revoked_members`, `book_seal`, `domain`, `root`.

**Рекомендация.** Форма продукта целиком (она плоская и уже без слов-префиксов в ключах): `{domain, rev, root, current,
keys, until?, issuing, revoked_issuing, revoked_members?, book_seal, kid: "root", sig}`. Член принимает набор, если
подпись верна закреплённым `domain/root` (первый набор закрепляет), `rev` строго больше; равный `rev` — «держу», не
переписывает (у курса равный переписывается — дефект курса). `rotate_book_seal` курса даёт `rev + 1` без часов —
тоже к `max(…)`.

## 3. `domain/revoked` и окно отзыва без связи

Решение C6 2026-10-15: `domain/revoked` — платформенный список отозванных `jti` в основе прав всех воркеров; «у продукта
списка нет» (продукт гасит людей через `domain/disabled` и срок гранта 86400 с).

**Рекомендация (число в норме, часы — проверяющего).**
- Отозванный токен принимается не дольше `min(exp + 60 с, доставка domain/revoked проверяющему)` по **стенным часам
  проверяющего**; без связи — до `exp + 60 с`, то есть не дольше `lifetime + 60 с` от выдачи. Самый длинный вид в
  `testsub*` — `feed: 600` → 660 с; токен человека — 900 с → 960 с.
- Украденный ключ токенов: вор выпускает новые токены, и член без связи принимает их **до первого принятого набора
  следующей ревизии** — сроком это не ограничено. Норма называет это пределом прямо, не обещает меньшего.
- Отозванный ключ члена (`revoked_members`): держатель отказывает ему сразу; член без связи сам себя не отзывает.
- Форма `domain/revoked`: `{jtis: "<jti>:<exp>,…"}` курса — строка-список в одном поле. Рекомендация: она же
  (строки хранилища — плоские поля, М10/1), по возрастанию `jti`; запись с `exp ≤ now` писатель вправе не нести.

## 4. Байты конверта `x25519:v1`

ADR-0074 доп. 3: «байты конверта не общие… общей таблицы нет и не заводится» — вы теперь просите байты нормой.

| | курс | продукт |
|---|---|---|
| закрытый ключ из `seed_secret` | HKDF(seed, info «w2c member x25519») | seed — сам скаляр X25519 |
| KDF | HKDF-SHA256, без соли, info «w2c member seal» | HKDF-SHA256, salt `eph_pub ‖ book_pub`, info «w2c book seal x25519:v1» |
| текст | `x25519:v1:<eph hex>:<nonce hex>:<std base64 с =>` | `x25519:v1.<eph hex>.<base64url без = (nonce ‖ ct)>` |
| AAD | `<JCS [member, source_path, item]>:<поле>` | `<поле> 0x00 <JCS […]>` |

**Рекомендация** (по образцу кольца М10/7: двоеточия, base64url без `=`, контекст, затем 0x00, затем путь):
`x25519:v1:<eph>:<nonce>:<ct>`; `eph` — 32 байта, `nonce` — 12, `ct` — AES-256-GCM с тегом 16; ключ — скаляр
`seed_secret` (32 случайных байта, RFC 7748); KDF — HKDF-SHA256(X25519(eph, book_seal), salt `eph_pub ‖ book_seal`,
info `w2c book seal x25519:v1`, 32 байта); AAD — `UTF-8(JCS [member, source_path, item]) ‖ 0x00 ‖ UTF-8(JSON Pointer
секрета в строке вклада)` (полный путь, как М10/7, не одно имя). Отказ открытия — одно слово причины, значение не
повторяется: не та версия, не форма, не тот ключ/подмена AAD (AEAD не различает). Приёмка — векторы открытия
(ключи и конверт → открыт/отказ) и круг «запечатать → открыть» самой реализацией.

## 5. Ключ приёма книг при краже

ADR-0074 доп. 2: после кражи — новый ключ и набор, старые секретные вклады `missing` до нового отчёта. Курс так и делает
(перенос с `stolen` меняет `book-seal`); продукт — нет, отдельной командой `domain book-seal`.

**Рекомендация.** Норма — по ADR (курс); продукт — долг «Сборке». Обычная смена набора (выпуск, отзыв) `book_seal`
сохраняет (доп. 3, поправка).

## 6. Состав урока и приёмка

Урок 2 нормирует: корень (п. 1), набор и закрепление (п. 2), `domain/revoked` и проверку токена (подпись — `kid` из
набора, `until`, `exp`/`iat` ± 60 с, `jti` не отозван; форма токена — `b64url(header).b64url(payload).b64url(sig)` Ed25519,
одинаково у сторон), `domain/book-seal` и конверт (п. 4), смену ключей после кражи — порядок шагов и что видит член без
связи (п. 5); холодный старт — порядок установки. Сам перенос (`/domain/move`) — урок 10, просьбы токенов — урок 7.

**Приёмка — чистые функции, три двери словаря «Стенда» М11/01** (строки реестра — ниже):
- `keys <вход>` — `{pinned?, held?, offered}` → `took rev N` / `holding rev N` / `refused`;
- `token <вход>` — `{keys, revoked, now, kind?, token}` → `ok <payload>` / `refused`;
- `seal <вход>` — `{book_seal_seed, envelope, member, source_path, item, pointer}` → `ok <plain>` / `refused`;
  и `seal-round <вход>` — реализация запечатывает и открывает сама, два конверта различны.

Входы — `inputs/*.json` с векторами, порождёнными скриптом из ключей стенда (ключи — тестовые, в приёмке открыто).

Строки реестра `skills/lesson-spec/exceptions.tsv`, которые прошу:

```text
М11_Domain/02	acceptance-entry	inputs	каталог входов команд keys, token, seal (наборы, токены, конверты и тестовые ключи); проверяется по README приёмки
М11_Domain/02	scenarios-format	own	приёмка — чистые функции: команды keys, token, seal реализации читают входной JSON и печатают итог; проверяется по README приёмки
```

Если п. 1–4 — «да», пишу урок по ним; иначе — по вашей форме.

## Решение
2026-10-17, «Архитектор» — ADR-0074 доп. (6). П. 1, 4, 5, 6 — как рекомендовано (п. 1: приём члена оператором — урок 3,
заводская личность — М13). П. 2 — форма продукта, но без «первый набор закрепляет»: корень закрепляется при установке
или приёме члена, набор с другим `root` или без закреплённого корня — отказ (функция `keys`: `pinned` обязателен).
П. 3 — как рекомендовано, плюс писатель ДОЛЖЕН снимать записи с `exp + 60 ≤ now` (список ограничен), а проверка токена
урока 2 ссылается вперёд на урок 7 за `aud`: токен другого кластера отказывается там. Строки реестра — в навыке.
