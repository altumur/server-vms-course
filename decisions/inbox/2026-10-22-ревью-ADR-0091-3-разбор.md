# Ревью ADR-0091 (третья редакция) — разбор

Срез `9b46188e4`. Вариант (Г) не оспорен; блокер второй редакции (права по шаблону) закрыт всеми тремя. Новые блокеры —
в протоколе, не в выборе:
- **порядок уборки** (Codex R91.3-01, Claude Т-2). «Состояние, затем строка» теряет действующий итог: при обрыве между
  удалениями строка остаётся с тем же `born` без состояния, а отменённое удаление строки (правка, продление) оставляет
  строку без итога. Законченная задача размещается снова. Решение: **строка первой**, состояние — только после
  подтверждённого удаления строки, как осиротевшее;
- **повтор после физической уборки** (Codex R91.3-04, Kimi 1). CAS `""` означает «строки нет сейчас», а не «этого id не
  было»; после штатного удаления повтор события моложе `valid_for` создаёт задачу снова. Решение: горизонт уборки
  связан с горизонтом повтора — строку с `made` контроллер физически не удаляет раньше `made.keep` = время события +
  `valid_for` + 60 с допуска часов (предпосылка P/08.2:109, как `TOKEN_SKEW`); `valid_for` объявляется в
  `worker.creates`.

Четвёртая редакция этим коммитом.

| Находки | Решение (ADR-0091, четвёртая редакция) |

| Codex R91.3-02, Claude мелкое 4 | п. 3: смена `born` — новая жизнь: остановить единицу и взять эпоху заново (новые привязки `of`, ADR-0013); смена `revision` — перезапуск под прежней эпохой; состояние пишется с `born` запуска |
