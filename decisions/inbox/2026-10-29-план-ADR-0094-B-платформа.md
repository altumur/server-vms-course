# План правок по ADR-0094 B (доля «Спецификации»: P/02, P/03, P/06, P/07, common)

Каждый пункт — отдельной ветвью норм и одной выгрузкой с номером линиям и раннеру; приёмка — в той же ветви, что норма.
Порядок (принят «Архитектором»: B6 → B7 → B8 → B5 → B3 → B4 → B2 → B1) выбран так, чтобы ранние пункты не ждали ADR и окна mTLS, а B1 шёл последним.

## Шаг 0 — до GREEN (только тексты вне норм 01–10)
- Ничего в Platform/; готовлю черновики в ветке без выгрузки.
- «Архитектору» — предложение к дополнению ADR-0091 (вид `door.pass`), ниже, раздел B1.

## Шаг 1 — B6 `/session`: `server_time`, `timezone` (малый, независимый)
- P/06.3 Н2 `GET /session`: поля `server_time` (время по P/01.1 Н0) и `timezone` (IANA, настройка кластера).
- Договор файла окружения: переменная кластера `TIMEZONE` (умолчание `UTC`, грамматика IANA; пустое — не по форме);
  P/02.4 Н1.2 — строка переменной; установщик пишет её в `w2c.env`.
- OpenAPI 06: схема Session; приёмка 6.3 сц. 03 — поля есть (`@time`, слово зоны).
- P/10 (домен) — та же пара у `/api/session` консоли домена, если она отдаёт `/session` — «Спецификация домена».

## Шаг 1а — B7 статические файлы подсистемы (ADR-0094 доп. (1); независимый, в том же приращении)
- P/02.1 Н1.2 грамматика манифеста: ключ перечня файлов (предлагаю `console.files: [<путь>…]` — пути относительно
  каталога манифеста, без `..` и абсолютных, расширения из закрытого перечня `js`, `css`, `json`, `woff2`, `woff`, `ttf`);
  иное — отказ загрузки (P/02.1 Н4); P/02.2 — проекция ключа в канонический вид.
- P/02.3/02.4: `manifest put` кладёт файлы перечня рядом со строкой манифеста (где — строки хранилища или объекты:
  решу с весом и потолком строки; SHA-256 каждого в строке манифеста), установщик сверяет байты.
- P/06.5 Н2: дверь `GET /<sub>/<файл>` — только перечень манифеста, байт в байт, `Content-Type` по расширению,
  `X-Content-Type-Options: nosniff`, CSP страницы `script-src 'self'`; вне перечня — 404; порядок разрешения пути
  `/<sub>/<…>` против маршрутов смонтированной подсистемы (Mount, ADR-0061) — норма называет.
- Приёмка 6.5: файл перечня `testsub2` — 200 байт в байт с типом; вне перечня, `..`, чужой тип — 404/отказ загрузки.
- Потребители: V/10 `assist.js`, V/11 WebUI `backend` («Спецификация VMS»).

## Шаг 1б — B8 строгое размещение по полю (ADR-0094 доп. (2) п. 1; независимый, P/04 и P/02.1)
- P/02.1 Н1.2: `placement.home` — `{field, strict?: bool}` рядом с нынешней формой (строка поля или `near`); `strict`
  только с `field` (с `near` — отказ загрузки); P/02.2 — проекция (`strict: false` умолчанием формы).
- P/04 Н1.3 строка `home`: при `strict: true` — фильтр, а не предпочтение: подходят только живые воркеры, чей `server` равен
  значению поля; поля нет, оно пусто или такого живого воркера нет — единица неразмещена с причиной (слово в грамматике
  Н3 «причина», например «home server <s> has no live worker»); при `strict` возврат «домой» (HOME_BUDGET) не нужен —
  единица не уходит с дома; нехватка (`grows`) заказывает процесс на сервере из поля.
- Векторы: подбор (`pool`/`order`, если подбор с home там) — строки strict: свой сервер есть / нет / поле пусто.
- Приёмка P/04: сценарий строгого дома (воркер на другом сервере — неразмещена; на своём — размещена).
- Потребитель — V/11 `backend` («один на сервер»), «Спецификация VMS».

## Шаг 2 — B5 коды отказов: закрытый перечень `error` по дверям и `field`
- P/06.1 Н4, P/06.2 Н4, P/06.5 Н4, P/06.6 Н4: у 400, 409, 412 — поле `field` (путь поля, JSON Pointer RFC 6901) рядом с
  нынешними `detail`, `error`, `fault`; закрытый перечень слов `error` — таблицей по дверям (данные `06-console/data/`).
- Векторы `fault` не меняются (это слова `fault`); новый пакет не нужен — перечень `error` проверяется схемой OpenAPI
  (`enum`) и приёмкой (существующие шаги 400 получают `field` в ожидании подмножеством).
- P/07: модуль показывает ошибку у поля по `field` (jsdom-тест формы).

## Шаг 3 — B3 память повторов на PUT, DELETE и записях таблиц
- P/06.1 Н1.1, Н3 «править», «удалить», «таблица — записать/удалить»: ключ `(user, метод, путь, ключ)`; порядок
  «память повторов → `If-Match` → запись»; иное тело — 409 `key reused`; срок — как у POST (семья `<sub>/idem/*` —
  та же, ключ строки — с методом и путём: правка каталога и формы строки `idem`, `06-console/data/idem.*`).
- P/06.6: двери записи (`PUT /policy`, `POST`/`DELETE /drain`, метки, вывод сервера, `PUT /schema`) — тем же правилом
  (их писатель — человек).
- Приёмка 6.1: повтор PUT/DELETE тем же ключом — тот же ответ; иное тело — 409; порядок с `If-Match` (новые шаги сц. 14).

## Шаг 4 — B4 версия на всех записях людей
- P/06.1 Н1.6: `revision` у строк таблиц (как у единиц: 1 при создании, +1 на правку); форма строк таблиц
  (`02-installer/data/canonical-row`, схемы семей таблиц) — поле `revision`; P/03.x писатели таблиц (воркер по
  `worker.writes`) — тоже поднимают `revision`.
- P/01.1 Н1 `index` (условие (а) ADR-0094 доп. (2) п. 4): новое правило — версии одного хранилища строго растут в порядке
  записи (пропуски допустимы; сравнение по порядку — только в пределах одного хранилища; прежние вызывающие по-прежнему
  сравнивают на равенство). Механизмы обеих реализаций это уже дают (п. 2 «Решает реализация»: счётчик в файле коробки;
  индекс журнала + основание группы, `import -index-base` ≥ наибольшей версии), норма — нет: сейчас «непрозрачна, только
  равенство, не повторяется». Провод прежний (десятичное ≤ 20 цифр); (б) — version/ETag строкой сверх 2^53−1.
  (в) — правило урока V/11 («Спецификация VMS»): части сборной камеры не объявляют физической уборки (`unplaced.delete_after`,
  `retire_when.delete_after`, `ends`); платформа сама надгробий не убирает.
- `ETag` у ответа чтения строки/единицы — индекс хранилища строки (P/01.1 `index`; ADR-0094 доп. (2) п. 4: глобальный, только растёт, удаление — запись надгробия; версия сборной камеры V/11 — наибольший индекс частей); `If-Match` на всех дверях записи (единицы, таблицы, P/06.6 снимки настроек —
  `policy`, `drain`, метки сервера, схема); 412 с текущей строкой в теле (маска `*_secret`, только при `view`).
- P/07 (модуль): форма всегда шлёт `ifMatch`, экран 412 (перечитать, показать текущую) — закрывает ADR-0091 доп. (28) п. 3;
  jsdom-тест.
- `base_rev` у `PUT /domain/shared` — «Спецификация домена» (P/10): свести к `If-Match` или назвать причину двух.
- Приёмка 6.1 (таблицы), 6.6 (настройки) — 412 и `If-Match`.

## Шаг 5 — B2 лента `GET /changes`
- Новая дверь — P/06.1 Н2 (строки единиц и таблиц — её охват): SSE (`text/event-stream`) или длинный опрос; сообщение
  `{key, revision | deleted}` без значения; номер в пределах экземпляра; `reset` — чужой номер, перезапуск, смена
  грантов или меток в `view`; фильтр — `view` человека, у таблиц — право `view` на таблицу.
- Н3 «лента»: одно перечисление префиксов на экземпляр консоли за такт, раздача подписчикам; константы
  `CHANGES_TICK`, `CHANGES_SUBSCRIBERS_MAX` (значения — в норме); ряды `w2c_changes_*` — P/06.5 Н3.
- Отступление от ADR-0038 — ссылкой на ADR-0094 B2 в тексте двери.
- P/07: модуль переходит на `/changes` для строк вместо опроса; `/events` — курсор (P/06.4).
- Приёмка 6.1: подписка, правка — сообщение без значения, удаление, `reset` при перезапуске консоли и смене гранта.

## Шаг 6 — B1 `door.pass` второго вида (последним; после дополнения ADR-0091)
- Договор сторожевой и передачи «Передача `door.pass`»: передача без `Authorization` человека, заголовок билета
  (предлагаю `X-W2C-Pass-Ticket`), 128 бит; память билета у консоли `{user, вид сессии, внешний запрос}`; обратный вызов —
  проверки ADR-0094 B1 (экземпляр, открытый запрос, транспорт роли, перечень дверей, свежий `may`, только `person`);
  401 после закрытия; журнал `via`; поток для объявленных маршрутов (только чтения и `/changes`); ответ передачи только
  JSON или SSE, иначе 502; заголовки `nosniff`, `CSP: sandbox`.
- P/02.1 Н1.2 грамматика `door`: `pass` второго вида — объект `{routes: [<сегмент>…], calls: [<дверь>…], stream: [<сегмент>…],
  wait: <с>}` рядом с прежним списком (вид первый — до окна mTLS у `live`); потолок `wait` — норма.
- P/02.5: сокет роли воркера к консоли своего сервера (транспорт обратного вызова) — права и файл сокета.
- P/03.4: воркер с `calls` — клиент дверей консоли по сокету роли с билетом; SDK.
- P/06.5 Н1.8: какой воркер получает передачу (как сейчас) + ряд `<sub>_passed_calls_total`.
- P/06.3: сторожевая принимает обратный вызов по билету как отдельный путь личности (не кука, не токен).
- Приёмка 6.5: пункты Confirmation ADR-0094 (401 после закрытия, чужой транспорт, дверь вне перечня, выключенный человек,
  break-glass; поток закрывается с запросом; 502 не-JSON); стенду нужен тестовый воркер с дверью `door.pass` второго вида
  (запрос раннеру — до шага 6).

## К дополнению ADR-0091 (пишет «Архитектор»)
- Вид `door.pass`: второй — билет на запрос (предложение грамматики выше); первый остаётся для `live` до окна mTLS.
- Имя заголовка билета и запрет `Authorization` во втором виде.
- Перечень дверей обратного вызова — объявлением манифеста, проверка пересечением с закрытым перечнем платформы
  (ADR-0094 B1 «перечень дверей для backend»).
