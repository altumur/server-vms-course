# План правок по ADR-0094 B (доля «Спецификации»: P/02, P/03, P/06, P/07, common)

Каждый пункт — отдельной ветвью норм и одной выгрузкой с номером линиям и раннеру; приёмка — в той же ветви, что норма.
Порядок (принят «Архитектором»: B6 → B7 → B8 → B5 → B3 → B4 → B2 → B1; B8 снят доп. (6) п. 3; B9 — доп. (9), шаг 3а после B3: пакет опирается на память повторов и нужен B1) выбран так, чтобы ранние пункты не ждали ADR и окна mTLS, а B1 шёл последним.

## Шаг 1 — B6 `/session`: `server_time`, `timezone` (малый, независимый)
- P/06.3 Н2 `GET /session`: поля `server_time` (время по P/01.1 Н0) и `timezone` (IANA, настройка кластера).
- Договор файла окружения: переменная кластера `TIMEZONE` (умолчание `UTC`, грамматика IANA; пустое — не по форме);

- P/10 (домен) — та же пара у `/api/session` консоли домена, если она отдаёт `/session` — «Спецификация домена».

## Шаг 1а — B7 статические файлы подсистемы (ADR-0094 доп. (1); независимый, в том же приращении)
- P/02.1 Н1.2 грамматика манифеста: ключ перечня файлов (предлагаю `console.files: [<путь>…]` — пути относительно
  каталога манифеста, без `..` и абсолютных, расширения из закрытого перечня `js`, `css`, `json`, `woff2`, `woff`, `ttf`,
  `png`, `svg` — доп. (4) п. 2);
  иное — отказ загрузки (P/02.1 Н4); P/02.2 — проекция ключа в канонический вид.
- P/02.3/02.4: `manifest put` кладёт файлы перечня рядом со строкой манифеста (где — строки хранилища или объекты:
  решу с весом и потолком строки; SHA-256 каждого в строке манифеста), установщик сверяет байты.
- P/06.5 Н2: дверь `GET /<sub>/<файл>` — только перечень манифеста, байт в байт, `Content-Type` по расширению,
  `X-Content-Type-Options: nosniff`, CSP страницы `script-src 'self'`; `svg` — ещё `Content-Security-Policy: sandbox`
  (скрипт внутри при прямом открытии не исполняется под источником консоли), `png` — `nosniff` (доп. (4) п. 2); вне перечня — 404; порядок разрешения пути
  `/<sub>/<…>` против маршрутов смонтированной подсистемы (Mount, ADR-0061) — норма называет.
- Оболочка смонтированной подсистемы (доп. (3) п. 8): `/<sub>/` отдаёт `<sub>.shell.html`, если манифест её объявляет, — по
  правилам оболочки корня (байт в байт, CSP с хэшами своих скриптов, без `on…=`), с той же сессией; P/06.5 Н2, P/02.1 ключ.
  CSP оболочки — ровно минимум P/06.5 Н1.1 `page` (`script-src 'self' 'sha256-…'; object-src 'none'; base-uri 'none'`),
  реализация его не ужесточает: встроенные стили и `data:`-картинки разрешены (доп. (8) п. 1; у корня — как было).
  Оболочка `backend` — их `index.html` байтами по SHA-256, без встроенного кода (доп. (8) п. 3) — список `sha256-…` может
  быть пуст. Пространства `/<sub>/<файл>` (статика B7) и `/<sub>/api/…` (маршруты смонтированной подсистемы) не
  пересекаются (доп. (8) п. 2) — порядок разрешения норма называет: имя из перечня файлов — статика, иное — Mount.
  Имя файла в перечне `console.files` не начинается с `api/` — иначе отказ загрузки манифеста (P/02.1 Н4): пространство
  `/<sub>/api/` только у Mount, пересечения нет по построению (решение «Архитектора» 2026-10-29 к вопросу «Спецификации VMS»:
  в наборе consolem были `api/*.js`).
  Строка запроса у статики не судится: оболочка `backend` ссылается на файлы набора как `<файл>?v=<12 hex>` — консоль
  отдаёт файл по пути, query игнорирует (не 400, не 404), кэш — по пути и байтам («Архитектор» 2026-10-30).
- Приёмка 6.5: файл перечня `testsub2` — 200 байт в байт с типом; `svg` — с `sandbox`; оболочка `/<sub>/` — байт в байт; вне перечня, `..`, чужой тип — 404/отказ загрузки.
  Ещё: оболочка `/<sub>/` с относительным `<script src="app.js">` — CSP несёт `'self'`, скрипт грузится (ожидание сценария;
  P/06.5 Н1.1 page: `'self'` всегда — C06-CSP-SELF-ALWAYS-01, «Архитектор» по «Консоли» 2026-10-29).
- Потребители: V/10 `assist.js`, V/11 WebUI `backend` («Спецификация VMS»).

## Шаг 1в — срок дозаписи без держателя (запрос VMS «срок просьбы», принят «Архитектором» a8750cccb; независимый)
- P/06.4 Н1.5 `ttl` у дозаписи: «автоматическое завершение по возрасту вне этого профиля» заменяется — жнец закрывает
  дозапись без `fetched` старше объявленного `ttl` + `REAP_AFTER` меткой `expired`
  `{unit, digest, outcome: expired, ended_by: reaper, ended_at}` — вторая метка дозаписи после `gone`, однажды; `settle` —
  от первого подтверждённого чтения метки, затем строка снимается по `cas`, rid уходит из `asked` по `cas` (как у `gone`);
  поздний `fetched` держателя после `expired` безвреден — исход один, первый подтверждённый.
- P/06.4 Н3 жнец `sweep`: «Дозапись без fetched не закрывать … по одному возрасту» — исключение `ttl` + `REAP_AFTER`;
  ветвь рядом с `gone`.
- Договор просьбы и её метки «Состояния…»: у дозаписи две метки жнеца — `gone`, `expired`; форма `no_begun` уже допускает
  `{expired, reaper}` (OpenAPI 06 `NeverBegun` — тоже; сверить, что дозапись с `expired` проходит полную форму P/03.6).
- Векторы `reap`: строки дозаписи — возраст `ttl` + `REAP_AFTER` − ε (ничего), ровно на границе и после (метка `expired`),
  с `fetched` (не трогать), с меткой `gone` раньше (одна метка).
- Приёмка P/06.4: сценарий дозаписи без держателя по образцу сц. 04 обычного профиля (резерв `per_person` освобождён
  после `settle`).
- Потребитель: V/02.8 Н1.4 и Н4 — «Спецификация VMS» после нормы.

## Шаг 2 — B5 коды отказов: закрытый перечень `error` по дверям и `field`
- P/06.1 Н4, P/06.2 Н4, P/06.5 Н4, P/06.6 Н4: у 400, 409, 412 — поле `field` (путь поля, JSON Pointer RFC 6901) рядом с
  нынешними `detail`, `error`, `fault`; закрытый перечень слов `error` — таблицей по дверям (данные `06-console/data/`).
- Векторы `fault` не меняются (это слова `fault`); новый пакет не нужен — перечень `error` проверяется схемой OpenAPI
  (`enum`) и приёмкой (существующие шаги 400 получают `field` в ожидании подмножеством).
- P/07: модуль показывает ошибку у поля по `field` (jsdom-тест формы).

## Шаг 3 — B3 память повторов на PUT, DELETE и записях таблиц
- P/06.1 Н1.1, Н3 «править», «удалить», «таблица — записать/удалить»: ключ `(user, метод, путь, ключ)`; порядок
  «память повторов → `If-Match` → запись»; иное тело — 409 `key reused`; срок — как у POST (семья `<sub>/idem/*` —
  та же, ключ строки — с методом и путём: правка каталога и формы строки `idem`, `06-console/data/idem.*`).
- P/06.6: двери записи (`PUT /policy`, `POST`/`DELETE /drain`, метки, вывод сервера, `PUT /schema`) — тем же правилом
  (их писатель — человек).
- Память группового ключа `backend` (доп. (3) п. 4, доп. (5) п. 2) — строки самого `backend` `backend/idem/<h>` обратным
  вызовом по своему префиксу: норма B3 и грамматика таблиц P/02.1 не правятся; с моей стороны — только префикс `backend`
  в перечне дверей обратного вызова B1 (шаг 6); форма строки — V/11.4 («Спецификация VMS»).
- Приёмка 6.1: повтор PUT/DELETE тем же ключом — тот же ответ; иное тело — 409; порядок с `If-Match` (новые шаги сц. 14).

## Шаг 3а — B9 пакетная запись хранилища и дверь консоли (ADR-0094 доп. (9), решение владельца 54e0b8a0b)
Урок 01 зачтён: правка — обеим линиям, приёмка P/01 заново (доп. (9) п. 4).
- P/01.1 Н1–Н3: операция «пакет» — список записей (put/delete строк), у каждой записываемой свой `cas`; `guard` — список
  стражей `{key, index}` (прочитанные, не записываемые); всё или ничего; один индекс операции на весь пакет; ключ не
  повторяется в пакете, ключ записи не страж (иначе отказ формы). Пределы — нормой: число строк пакета (предлагаю 64) и
  вес — сумма тел ≤ потолка строки × … (решу по весу строки P/01.1 и `-max-body` P/01.3; вес пакета ≤ `-max-body`).
  Отказ: первый несовпавший `cas` или страж — `412` без записи, тело называет ключ (форма отказа P/01.1, без значений);
  права (P/01.2) — по каждой строке пакета, отказ одной — `403` всего пакета. Память повторов — один `Cmd.id` на пакет
  (B3, P/01.1 Н3), повтор отдаёт прежний итог. OpenAPI 01 — путь и схемы; векторы формы пакета.
- P/01.3: у группы raft — одна запись журнала (применение атомарно на всех); у коробки без демона — под одним замком
  (P/01.1 «Решает реализация» — как); дверь без голоса пересылает пакет целиком (роль `configstore-door` пакет не пишет).
- P/06.1: пакетная дверь консоли — строки единицы и её частей (форма пути и тела решу с B4 версиями и B3 памятью повторов),
  права — по каждой строке (P/06.1 Н1.2 и файл прав), отказ одной — отказ всего пакета без записи; `If-Match` строк — `cas`
  каждой.
- P/06.3: перечень обратного вызова `backend` по билету (B1) получает пакетную дверь (доп. (9) п. 2).
- Приёмка: P/01 — пакет всё-или-ничего (второй `cas` устарел — ни одна строка не записана, индекс не вырос), стражи,
  повтор `Cmd.id`, предел числа строк; P/06.1 — пакет с одной строкой без права — 403 и ни одной записи.
- Потребитель: V/11.4 Н1.2 (запись устройства одним пакетом) — «Спецификация VMS» после нормы.
- Уточнения «Спецификации VMS», приняты «Архитектором» 2026-10-30: (а) пакет несёт и создание (`cas: ""`), и снятие
  (delete с `cas`), не только правку; (б) `ref` и `must_match` строк пакета на строку того же пакета судятся по состоянию
  ПОСЛЕ пакета (цель создаётся или правится в нём же), на строку вне пакета — как сейчас; (в) пакетная дверь консоли —
  с памятью `Idempotency-Key` (B3): повтор после потери ответа отдаёт прежний итог, не ложный `412`.

- B9, ещё (разбор ревью V/11 5b1156cb4, раздел «Платформа»; «Архитектор» 2026-10-30): (6) пакет может нести строку счётчика `<s>/next_id` (с `cas`) вместе с новой единицей.

- B9, ещё (V/11 46c466087; «Архитектор» 2026-10-30): (а) пакет может нести строку таблицы подсистемы (`backend/repeats`) вместе с её строками единиц —
  итог шага пишется в пакете шага.

## Шаг 4 — B4 версия на всех записях людей
- P/06.1 Н1.6: `revision` у строк таблиц (как у единиц: 1 при создании, +1 на правку); форма строк таблиц
  (`02-installer/data/canonical-row`, схемы семей таблиц) — поле `revision`; P/03.x писатели таблиц (воркер по
  `worker.writes`) — тоже поднимают `revision`.
- P/01.1 не правится (доп. (4) п. 1 снял условия (а) «индекс строго растёт» и (б) потолок доп. (2) п. 4): индекс
  непрозрачен, сравнение только на равенство, не повторяется. (в) остаётся — правило урока V/11 («Спецификация VMS»,
  передаю с B): надгробия частей сборной камеры не убираются, пока камера жива; части не объявляют физической уборки
  (`unplaced.delete_after`, `retire_when.delete_after`, `ends`); платформа сама надгробий не убирает.
- `ETag` у ответа чтения строки/единицы — индекс хранилища строки (P/01.1 `index`, непрозрачная строка, только равенство;
  версия сборной камеры V/11 — склейка индексов частей, форма — V/11.4, доп. (4) п. 1); `If-Match` на всех дверях записи (единицы, таблицы, P/06.6 снимки настроек —
  `policy`, `drain`, метки сервера, схема); 412 с текущей строкой в теле (маска `*_secret`, только при `view`).
- Индекс надгробия (доп. (3) п. 9; P/06.1): `DELETE` отдаёт `ETag` — индекс надгробия; сообщение ленты об удалении (шаг 5)
  несёт его же; `GET` удалённой строки с надгробием — 404 с `ETag` надгробия, строки не было — 404 без `ETag`; `If-Match`
  с индексом надгробия годится для записи поверх него.
- Надгробия по `about` (доп. (5) п. 1; P/06.1, рядом с предыдущим): надгробие единицы хранит значение её поля `about`;
  дверь единиц — `GET /<rows>?deleted=1&about=<значение>` → `{deleted: [{id, index}]}`, только чтение, право `view` таблицы;
  снятие таких надгробий — не раньше снятия единицы `about` (доп. (2) п. 4 (в)); форма тела — OpenAPI 06, приёмка 6.1:
  удалить часть — найти её надгробие по `about`, без права `view` — 403.
- P/07 (модуль): форма всегда шлёт `ifMatch`, экран 412 (перечитать, показать текущую) — закрывает ADR-0091 доп. (28) п. 3;
  jsdom-тест.
- `base_rev` у `PUT /domain/shared` — «Спецификация домена» (P/10): свести к `If-Match` или назвать причину двух.
- Приёмка 6.1 (таблицы), 6.6 (настройки) — 412 и `If-Match`.

- B4, ещё (разбор ревью V/11 5b1156cb4, раздел «Платформа»; «Архитектор» 2026-10-30): (3) элементы `GET /<rows>` и таблиц несут индекс хранилища строки; «404 с ETag удалённой строки»
  (доп. (3) п. 9) снимается — двери одной строки нет, надгробие читается `?deleted=1&about=`.

## Шаг 5 — B2 лента `GET /changes`
- Новая дверь — P/06.1 Н2 (строки единиц и таблиц — её охват): SSE (`text/event-stream`) или длинный опрос; сообщение
  `{key, revision | deleted}` без значения; номер в пределах экземпляра; `reset` — чужой номер, перезапуск, смена
  грантов или меток в `view`; фильтр — `view` человека, у таблиц — право `view` на таблицу.
- Н3 «лента»: одно перечисление префиксов на экземпляр консоли за такт, раздача подписчикам; константы
  `CHANGES_TICK`, `CHANGES_SUBSCRIBERS_MAX` (значения — в норме); ряды `w2c_changes_*` — P/06.5 Н3.
- Отступление от ADR-0038 — ссылкой на ADR-0094 B2 в тексте двери.
- P/07: модуль переходит на `/changes` для строк вместо опроса; `/events` — курсор (P/06.4).
- Начало подписки (доп. (3) п. 6): без номера первым сообщением — текущая позиция; клиент читает строки после неё и
  применяет сообщения с позиции, отбрасывая ревизию не выше прочитанной; номер, вытесненный из истории, и переполнение
  подписчика — `reset` с полным перечитыванием.
- Приёмка 6.1: подписка, правка в промежутке начальной загрузки, возобновление после вытеснения истории, правка — сообщение без значения, удаление (с индексом надгробия), `reset` при перезапуске консоли и смене гранта.

- B2, ещё (V/11 b550d8bf2; «Архитектор» 2026-10-30): сообщение ленты `/changes` несёт время приёма строки хранилищем `at` (при досылке — прежнее,
  не время досылки); V/11 отдаёт его в `StreamMessage.at`.

## Шаг 6 — B1 `door.pass` второго вида (последним; после дополнения ADR-0091)
- Договор сторожевой и передачи «Передача `door.pass`»: передача без `Authorization` человека, заголовок билета
  (предлагаю `X-W2C-Pass-Ticket`), 128 бит; запись билета у консоли `{user, вид сессии, jti, kid, exp, открытый внешний
  запрос, экземпляр-адресат}`, воркеру — только 128 бит (доп. (3) п. 1); обратный вызов — проверки ADR-0094 B1 (экземпляр,
  открытый запрос, транспорт роли, перечень дверей, только `person`) плюс проверка токена двери (договор `domain-token`:
  отзыв `jti`, срок, ключ) и свежий `may` на каждом вызове; открытый поток по билету закрывается при отзыве `jti`,
  выключении человека и на `exp`; 401 после закрытия; журнал `via`; поток для объявленных маршрутов (только чтения и
  `/changes`).
- Ответ передачи (доп. (3) п. 2): типы `application/json`, `application/problem+json`, `text/event-stream` (с параметрами)
  и ответы без тела (204, 304) без `Content-Type`; иное — 502; `nosniff`, `CSP: sandbox`.
- Заголовки второго вида (доп. (3) п. 3): к воркеру — `Content-Type`, `Idempotency-Key`, `If-Match`, `Last-Event-ID`; к
  клиенту — `Content-Type`, `ETag`; удостоверения и прочее отсекаются.
- Полоса обратного вызова (доп. (3) п. 7): своя ограниченная полоса консоли, не общая; передачи потоком — отдельный
  предел (потолок — константа P/06.5 Н3); перечень дверей обратного вызова пополняется префиксом `backend` (шаг 3).
- P/02.1 Н1.2 грамматика `door`: `pass` второго вида — объект `{routes: [<сегмент>…], calls: [<дверь>…], stream: [<сегмент>…],
  wait: <с>}` рядом с прежним списком (вид первый — до окна mTLS у `live`); потолок `wait` — норма.
- TLS обратного вызова сразу (доп. (6) пп. 1–2, 5; P/06.3, договор `gate-and-pass`): консоль просит и проверяет
  сертификат клиента роли на маршрутах обратного вызова по билету — только эти маршруты, только роли с обратным вызовом
  в манифесте (узкий «сертификат по желанию»; проверка листа — договор сертификата роли `peer`); билет привязан к листу
  роли экземпляра, которому консоль передала запрос; иной лист (чужая роль, другой экземпляр) — 401.
- P/02.5: сокет роли воркера к консоли своего сервера — только профиль без комплекта (стенд, петля; доп. (6) п. 4);
  права и файл сокета.
- P/03.4: воркер с `calls` — клиент дверей консоли по сокету роли с билетом; SDK.
- P/06.5 Н1.8: какой воркер получает передачу (как сейчас) + ряд `<sub>_passed_calls_total`.
- P/06.3: сторожевая принимает обратный вызов по билету как отдельный путь личности (не кука, не токен).
- Приёмка 6.5: пункты Confirmation ADR-0094 (401 после закрытия, чужой транспорт, дверь вне перечня, выключенный человек,
  break-glass; поток закрывается с запросом; 502 вне типов, 204 удаления и 412 `problem+json` проходят; два токена,
  отозван один — билет первого 401, второго работает; стенд с TLS: лист чужой роли и лист другого экземпляра — 401; SSE с `Last-Event-ID`; общая полоса занята передачами — их обратные
  вызовы проходят); стенду нужен тестовый воркер с дверью `door.pass` второго вида
  (запрос раннеру — до шага 6).

## К дополнению ADR-0091 (пишет «Архитектор»)
- Вид `door.pass`: второй — билет на запрос (предложение грамматики выше); первый остаётся для `live` до окна mTLS.
- Имя заголовка билета и запрет `Authorization` во втором виде.
- Перечень дверей обратного вызова — объявлением манифеста, проверка пересечением с закрытым перечнем платформы
  (ADR-0094 B1 «перечень дверей для backend»).

## Согласовано со «Спецификацией домена» (2026-10-29, её план `2026-10-29-план-ADR-0094-доля-домена.md`)
