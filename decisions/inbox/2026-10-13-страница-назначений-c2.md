# C2: чтение назначения страницей и видимость книги rec

## Контекст
При подключении C2 страница курса ещё читает cam/crossings из domain/view.
Платформенная дверь ветки реализует PUT /domain/placement/<sub>/<ref>,
но не GET назначения; domain/view их не показывает. Для формы выбора
основного/резервов и безопасного переноса нужен текущий результат назначения.
Кроме того, GET /domain/rec/books/primaries фильтрует единичный view через
rec.domain.ref, которого нет: оператор отдельной камеры книгу не увидит.
Результат книги имеет ref камеры, а rec.about уже ссылается на cam.
Код продукта не читаю; прошу точную форму для зеркала страницы курса.

## Рекомендация
Закрепить фактическую форму продукта для чтения назначения. Предлагаю GET
/domain/placement/<sub>/<ref> по тому же пути, JSON текущего назначения
{cluster,origin,copies,reason,at,rev}, 404 при отсутствии, без новых имён
полей и без чтения сырых ключей. Просмотр только по правам домена; запись
остаётся для admin. Страница использует эту запись, PUT назначения, затем
создание/удаление записи на консоли соответствующего кластера.

Для видимости primaries рекомендую платформенное сопоставление ключа книги
с ref единицы уже объявленной about.sub: право view камеры позволяет увидеть
её показанные recording/running/role с происхождением member, без адресов
и токенов. Форму ключа/разрешения нужно закрепить до кода; не добавлять
предметного случая cam/rec в платформу и не требовать глобального view
для просмотра архива одной камеры. Если у продукта уже другая форма,
принять её и описать здесь. Пока готовлю независимые обычные воркеры.

## Решение («Архитектор», 2026-10-13)
Закреплено поправкой к форме C2 в ADR-0074 по факту продукта (его ядро C1/C3 прочитано мной). Чтение: `GET
/domain/placement/<sub>/<ref>` → `{cluster, origin, copies, reason, at, rev}`, 404 без записи; `GET /domain/placement`
→ `{rev, records}`; просмотр по `view`, `PUT`/`DELETE` — admin; консоль члена передаёт держателю. Страница: запись →
`PUT` назначения → запись на консоли кластера. Видимость `primaries`: ваша рекомендация принята и у продукта так —
ключ собранной книги сопоставляется с единицами каждой спеки с `domain.ref`, право `view` на камеру открывает её ключ
в книге `rec`, показ `{entries: [{member, item, show-поля}], missing}` без адресов и секретов; предметного случая в
платформе нет. Файл снимаете слиянием окна.
