# Запрос: правка навыка — реестр V/01 после главы V/01.5

**Какое правило мешает.** `skills/lesson-spec/exceptions.tsv`: (1) строка `V/01 no-openapi` — `check_spec` даёт `stale
exception no-openapi: the contract exists` (`VMS/01-cam/spec/01-cam.api.openapi.yaml` — дверь держателя, V/01.5);
(2) `VMS/01-cam/acceptance/5/scenarios.tsv` строки 3–10 — `unsupported request form`: директивы `@start worker`, `@until`
и дверь `holder <воркер>` из [общего README приёмки VMS](../../VMS/common/acceptance/README.md) (по слову «Архитектора»
2026-10-23 — общим правилом вместо строк по главам); `check_spec.stands()` (`check_spec.py`, `def stands`) читает пока
только `Platform/common/acceptance/README.md`.

**Рекомендация.** Снять `V/01 no-openapi`; `stands()` для урока VMS — плюс `VMS/common/acceptance/README.md` (его таблица
«Директивы и двери VMS» — формы запроса `@start worker <sub> <имя> on <сервер>`, `holder <воркер> <МЕТОД> <путь>`,
`resource …`), тогда строки `V/01 scenarios-format 2/own`, `4/own` снимаются и `5/own` не нужна; иначе — строка
`V/01 scenarios-format 5/own`.

## Решение
**Решён** (2026-10-23, «Архитектор»; навык — его, ADR-0080 доп. 14). `check_spec` для урока VMS читает формы запросов из
таблицы «Директивы и двери VMS» `VMS/common/acceptance/README.md` — одно правило для всех уроков VMS вместо строк реестра
по главам: директива из таблицы (`@start worker …` — ожидание `ok`; `@until <секунды> <запрос>` — вложенный запрос
проверяется той же грамматикой) и дверь из таблицы (`holder <воркер> <МЕТОД> <путь>`, `resource GET /v1/objects/<ключ>`,
`console …`) — с ожиданием «код и JSON-тело», как у консоли. Строки реестра `V/01 no-openapi`, `V/01 scenarios-format
2/own`, `4/own` сняты; `5/own` не нужна. Вызов по `Platform/` — без изменений (PASS, 59 исключений).

Остаётся содержимое урока («Спецификации VMS»): OpenAPI двери держателя `VMS/01-cam/spec/01-cam.api.openapi.yaml` —
у объектов `Refusal`, `Device`, `Device.can` не сказана открытость (`additionalProperties`).
