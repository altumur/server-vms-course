# Для слияния книг нужен завершённый снимок отчёта члена

Ответ Архитектора уже записан в дополнении 3 ADR-0074 (`9abd26c8`). Ниже исходная находка и проба;
повторное согласование не требуется.

## Контекст

Основа `e0c83de4`, после закрытия шага 5 ADR-0070. В `Source/w2cplatform/domain/uplink.py`
`take` меняет объекты и строки на прежних путях, затем пишет `reported`. `_CopyVars.get` проверяет
свежесть метки, но читает уже заменённые строки. Воспроизведение: пока первая строка нового отчёта
записана, а вторая ещё нет, `member_copy` возвращает `[new, old]` при неизменном `reported.seq == 1`.
Поэтому повторное чтение метки до/после само по себе не даёт ядру книг завершённый снимок.

## Рекомендация

До подключения слияния к отчётам утвердить публикацию неизменяемого поколения и атомарное переключение
указателя после полной записи. Читатель фиксирует один указатель и читает только это поколение; ошибка
или отсутствие его части — `missing`, не пустой вклад. Старое поколение удаляется лишь после безопасного
окна чтения. Рекомендую применить это к строкам вкладов книг первым, не менять остальные данные попутно.

Точные пути поколений, поле указателя, подтверждение завершённости и порядок защиты от повтора старого
отчёта прошу согласовать до кода отдельной формой после выбора механизма. Число поколения нельзя выводить
только из часов члена. Перенос держателя и ретрансляция обязаны сохранять его принадлежность и порядок.

Альтернатива — хранить все входные строки книг одного отчёта в одном атомарно заменяемом объекте с метаданными
того же отчёта. Она проще, но требует установленного предела размера и полного перезаписывания большого
снимка. Рекомендую поколения, потому что текущий протокол уже разбивает отчёт на отдельные объекты.
Цена — новые служебные пути и удаление старых поколений. Не предлагаю считать запись `reported` последней
доказательством атомарности и не добавляю чтение частичных данных как временное умолчание.

## Воспроизведение

Из `Source/`, Python окружения курса; хранилище в памяти позволяет остановить запись точно между двумя
строками, методы `take` и `member_copy` настоящие:

```python
from w2cplatform.domain.uplink import take, member_copy, base, REPORTED
from w2cplatform.domain.agent import ROOT_PATH, KEYS_PATH

class Store:
    def __init__(self): self.d, self.inspect = {}, False
    def get(self, k): return self.d.get(k)
    def list(self, p): return sorted(k for k in self.d if k.startswith(p))
    def delete(self, k): self.d.pop(k, None)
    def put(self, k, v):
        self.d[k] = v
        if self.inspect and k == base("a") + "v/" + ROOT_PATH:
            self.inspect = False
            mark = self.get(base("a") + REPORTED)
            view = member_copy("a", self, wall=lambda: 1000)
            assert [view.vars.get(p)[0]["v"] for p in (ROOT_PATH, KEYS_PATH)] == ["new", "old"]
            assert self.get(base("a") + REPORTED) == mark

def pub(v, t):
    return {"sent_at": t, "objects": {}, "rows": {
        p: {"items": {"v": v}, "idx": t} for p in (ROOT_PATH, KEYS_PATH)}}

s = Store()
take("a", pub("old", 1), s)
s.inspect = True
take("a", pub("new", 2), s)
```

Проба выполнена: смешанные версии прочитаны без отказа. Это пример на существующих переносимых строках,
без добавления книги в спеки и без исправления протокола. Ядро `bookmerge.collect` в рабочей ветке принимает
только готовый снимок и намеренно ещё не подключено к `_CopyVars`.

## Приёмка

Остановить публикацию после каждой записи/удаления части, читать одновременно: получить либо целое старое
поколение, либо целое новое, либо явную неполноту; никогда смесь. Проверить удаление последнего вклада,
падение перед переключением, возврат старого отчёта, повтор, два одновременных запроса, ретранслятор,
перезапуск/перенос держателя и очистку поколения во время чтения. Проверки — на testsub/testsub2 до VMS.
