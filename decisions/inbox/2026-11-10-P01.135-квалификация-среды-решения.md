# P01.135 — решения по неоднозначностям квалификации среды боевой приёмки (Архитектор, 2026-11-10)

Вход: квалификация ops103 `P01.133`, `/home/pilot/ops103-b11-providers/p01.133/QUALIFICATION.md` (30 пунктов: исполнимо 6, с условием 15, не исполнимо 9). Решения касаются боевой приёмки `P01.B2` (ADR-0130 строка 5), не генерации.

| № | Вопрос | Решение | Основание |
|---|---|---|---|
| Н1 | Обязательна ли изоляция `b11-call` | Нет. Обязательна изоляция судимых процессов по ADR-0133 доп. (6) п. 1: кандидат под своей учётной записью, без доступа к J, `acc/` и секретам, со своими `/tmp`; это держит и запуск вида `acceptance-check` под обёрткой судьи. `b11-call` — средство цикла генерации, где судья даёт модели обратную связь; боевая приёмка — суд, обратной связи модели нет. | доп. (6) пп. 1, 7; суды P01.66, P01.93 шли под обёрткой судьи |
| Н2 | 10 ядер `runs.slice` против 12 оболочки бюджетов | Пока бюджеты утверждены для 12 ядер, бюджетные пробы на 10 ядрах — `environment_undeclared`, не PASS; среда пишется в отчёт. Выход — утвердить бюджеты для фактической среды (10 ядер, 20 ГиБ, ext4 на тонком LVM) в `P01.134`. | оболочка бюджетов N6.2; слово владельца по бюджетам |
| Н3 | `clock`: сдвиг или реальное ожидание | Для `prod-id-age` и `RUN-W03` достаточно реального ожидания с независимым наблюдателем часов: норма судит возраст по часам времени допуска, края 120 с и 50000 записей достижимы без сдвига — пункты становятся «с условием». Для `prod-clock-group` (часы в группе) нужен раздельный ход часов узлов; на CT 103 его нет — остаётся «не исполнимо», вопрос хоста. | acceptance.norms.md: prod-id-age, prod-clock-group; production-acceptance.md «clocks in a group» |
| Н4 | Какой менеджер служб «фактический» | Менеджер среды, под которым стенд держит кандидата: systemd на CT 103; `manager.stop_deadline_seconds` — его настроенный срок (90 с), запас измеряется отдельно. Кандидат менеджера не объявляет. | acceptance.norms.md: вход `manager`; production-acceptance.md RUN-L03 «actual manager configuration» |
| Н5 | Годится ли tmpfs как `volume` | Нет: барьеры долговечности на tmpfs пусты, и это расходится с оболочкой «ext4»; результат `prod-disk-fd` на нём ничего не доказывает. `volume` — каталог ограниченного размера на объявленной файловой системе; на CT 103 его даёт только том хоста. | prod-disk-fd; оболочка бюджетов |

## Что остаётся за владельцем (хост Proxmox)

1. Том ограниченного размера на ext4 для `volume` (`pct set -mpN`) — `prod-disk-fd`.
2. Отказы хранилища: `/dev/mapper/control`, `/dev/loop*` или `/dev/fuse` в контейнере — `RUN-F01`–`F04`, `prod-fault-stage`; перехват через `LD_PRELOAD` для Go не работает.
3. Раздельные стенные часы узлов группы — `prod-clock-group`, `RUN-W03` при сдвиге.
4. Бюджеты N6.2 для фактической среды — `P01.134`.

Без пп. 1–3 эти пробы остаются `not_executed` с причиной D7 (`storage`, `fault`, `clock`), а не провалом кандидата.
