**4. store_core** — depends `1,2,3`; when `всегда`; weight 3. Источник: `Platform/01-store/forms/stages.tsv:27`.

Построить чистые state transitions read/list/put/delete/batch и `admission_step`. Shell даёт факт принятия и clock sample; core использует finite binary64 admitted=max(clock,last). В одной операции порядок таков: replay lookup и payload match → not_after → not_before → guards → CAS → одна новая версия → rows/id. Put/delete/batch имеют общий namespace id. Guards batch сравниваются по исходному list order, а fingerprint guards — как множество. Успешный replay отвечает again; mismatch сохраняет первоначальный id-answer.

Admission сохраняется отдельно от business effect: already-admitted refusal и replay удерживают новое время, включая длинную binary64 fraction. Pre-admission parsing/rights errors не занимают id. Delete отсутствующего row расходует версию, но read version остаётся пустой; строка version "0" не означает отсутствие. Read/list видят batch целиком, items копируются на входе и выходе. Пока строится memory state; формат durable effects проектируется сразу, чтобы потом не менять семантику.

План собственных проверок: две конкурентные CAS/create-once; guard race; rollback clock, equality и обе дробные стороны bounds; повтор после deadline; mismatch/replay admission; batch all-or-nothing и общая версия; изменение входной/выходной map; refused id reusable; version loss не превращается в отсутствие. **11. group** — depends `9,10`; when `keys.store_build != 'box'`; weight 5. Источник: `Platform/01-store/forms/stages.tsv:34`.

Взять pinned Hashicorp Raft v1.7.3; не писать новый consensus core. Слой урока реализует durable LogStore/StableStore, FSM, snapshots, mTLS transport и bounded lifecycle. Каждый put/delete/batch/floor несёт assigned admission; snapshot сохраняет last admission, ids и полный state. Snapshot persistence учитывает конкурентный FSM contract. Read/list требуют подтверждения current leader; follower admin read разрешён без forwarding admin request, но stale state при отсутствии fence не отдаётся. Raft Barrier не считается filesystem barrier.

Join/leave сериализуются; сохраняются membership/API addresses/how в member.json. Restart не делает join; forced evenness не разрешает превышать declared size. Last voter leave — 409. Peer mTLS меняет только собственное membership; чужое id — 403 до leader/phase/membership checks. Follower admin mutations — admin_not_leader после request/identity/body form, но до write-checks; собственный join/leave передаётся внутренней group operation. Admit только leader admin; door admit — nonzero.

Door не держит row replica и не голосует; forwarding whole batch по тем же правам, polling/seen_at по constants. Только собственный put seen_at без cas/guard разрешён роли configstore-door. Unknown sent-write answer остаётся ambiguous; retry только same id, без id нового retry нет. Leader-wait считается с потери leader, не с начала каждого запроса; attempts укладываются в end-to-end caller budget. Metrics каждого voter считают doors по собственной replica/clock.

Import/restore в group идут через leader admin, разрешая исходные door rows fresh group, но удерживая и их live updates до Done. После interruption group стартует, ordinary reads/writes дают 503 до продолжения; backup не выдаёт partial snapshot. Partial recover повторяется с начала; отменённый partial import требует нового полного import при held writers.
