# C5: точные ответы двери учёток до подключения

## Контекст
C4 слит e24dac95. C5 реализуем отдельно параллельно порученному М10/1;
продукт не читаем и не правим. В ADR заданы POST/reset/PUT/DELETE, но
нет имён полей ответов и GET списка; прежняя дверь имела clients/client.
Новый провод без формы не вводим. Core хранение/публикация готовится отдельно.

## Рекомендация
Закрепить GET /live/accounts → 200 {accounts:[{name,disabled,at,by}]},
без пароля; POST /live/accounts {name} и POST /live/accounts/<name>/password
→ 200 {account:<name>,password:<строка>}, пароль выдаётся только этим ответом;
PUT /live/accounts/<name> {disabled:<bool>} → 200 {account:<name>,disabled:<bool>};
DELETE → 200 {account:<name>,deleted:true,grants_changed:[<cluster>…]}.
Имена полей account/accounts вместо прежних client/clients, старые двери
удалить без алиасов. Форма doc на диске остаётся принятой C5. Просим дать
точную форму, если эти байты отличаются от уже принятого C5 продукта.
Проверка имени по копии книги частичная, как в ADR; неизвестность GET
/domain/users — 503, simultaneous creation разных кластеров — unique конфликт.

## Решение («Архитектор», 2026-10-14)

Принято как подано — байты совпадают с продуктом (`liveproc/accounts.go`): `GET /live/accounts → 200 {accounts: [{name, disabled, at, by}]}` (у продукта `disabled`, `at`, `by` опускаются при нуле — курс так же; без пароля); `POST /live/accounts {name}` и `POST /live/accounts/<имя>/password → 200 {account, password}` — пароль только этим ответом; `PUT /live/accounts/<имя> {disabled} → 200 {account, disabled}`; `DELETE → 200 {account, deleted: true, grants_changed: [<кластер>…]}`. Имена `account`/`accounts`; прежние `client`/`clients` и их двери уходят без алиасов (ADR-0003). Неизвестность `GET /domain/users` — 503; одновременное создание в двух кластерах — конфликт `unique`; проверка имени по копии книги частичная — как в ADR-0074.
