# C2: метки исходов теряются при переносе держателя

## Контекст
На e71e5a10 настоящий `DomainHolder.export()` не включает
`domain/outcomes/`: семьи нет в `PLATFORM_EXPORTED` (`domain/term.py:96`).
Воспроизведено: A завершена, export/restore, B с тем же ключом и другим
телом при прежних часах получает прежнюю `at`; агент возвращает исход A,
консоль не вызывается, B снимается. После обычного перезапуска без переноса
тест зелёный, поэтому прежняя приёмка этого не ловила. Полный unit e71 ещё
идёт; готовым к слиянию этот снимок не объявляем.

## Рекомендация
Включить уже существующую семью `domain/outcomes/` в штатный экспорт и
восстановление домена: дополнение 7 требует сохранённый исход для выдачи
различимой метки. Нового имени, журнала и формата нет. Исправление оставляем
в ветке C2 до итогового чтения; приёмка — завершение A → настоящий экспорт
→ восстановление нового держателя → B при тех же и откатившихся часах →
различимая метка и честный 422 консоли. Проверим красный тест до исправления
и зелёный после, затем повторим итоговые проверки исправленного дерева.

## Уточнение найденных последствий
Экспорт использует тот же список, что `stranded`; исход, пришедший после
последней копии, не должен становиться потерянным решением оператора.
Существующий тест закрытия правки при handover это проверяет. В ветке
исходы экспортируются, но исключены из `stranded`. Там же остался старый
разбор `Edit.rev`: `None == None` скрывал новую операцию с тем же id.
Он удалён: явная Edit неизменна, удаление означает завершение, отличающаяся
оставшаяся Edit показывается оператору. Нового поля и двойного чтения нет.

Оба дефекта подтверждены красными регрессиями, затем после исправлений
67 проверок ядра и полный Domain 228/0/0, exit 0 (отдельный worktree от
e71e5a10). Интегрированное дерево ещё проверяется; итоговый diff будет
единым. Рекомендуем читать обе связанные правки в C2 вместе, с сохранением
старой проверки «завершение при handover не stranded».
