## Решение — урок 3
1. **U5.** Сегмент id процент-декодируется после выбора маршрута. Результат не UTF-8 или не по грамматике id — 400
   `bad id`. Шаги: id `a b` → `PUT /counters/a%20b` — 200; `/%FF` — 400.
2. **U3.** Повтор заголовка, который читает дверь (`Idempotency-Key`, `If-Match`), — 400, как повтор параметра.
3. **U2, U4.** OWS по краям значения заголовка снимается (RFC 9112 §5.5). Пустой `If-Match` — 400.
4. **U9.** int — в пределах ±(2^53 − 1), иначе 400 `not_number`. Совместимость с JSON-клиентами любых языков.
5. **U7, U8.** Одиночный суррогат и число вне double (`1e400`) — 400 `not_json`, до заявки. Шаги в сц. 08, в том числе
   «тот же ключ с верным телом → 201».
6. **U10.** Поля проверяются в порядке объявления `unit.fields`, и `fields` в `GET /spec` — в том же порядке.
7. **U13.** Отсутствующий элемент цели не равен ничему: `must_match` — 409.
8. **U14.** «url нечитаем» — не по RFC 3986: `%zz`, управляющие знаки, `\` — `bad_url`. `mirror://local` без пути —
   выбери по `schemes` спеки и запиши.
9. **U15.** `-0` хранится как `0` (JCS).
10. **U17.** Элементы `status` с `id` не по грамматике или нецелыми `epoch`/`revision` в `rows` не входят. `worker` —
    из ключа пульса.
11. **U16.** Шаг приёмки: при живом воркере `GET /counters` → элемент с `phase: running`, `worker`, `worker_state: live`.
12. **U19.** Сторожевая читает доверие на каждом запросе. Неответ хранилища — 503 `denied` до разбора, кроме отказов
    формы, которые норма ставит раньше. Порядок назвать.
13. **U22, U23.** Иной отпечаток при живой чужой `pending` моложе 30 с — 409 `in flight`. Заявка не по форме — 503,
    заявку не трогать.
14. **U20, переносимость имён.** Любое имя, которое разрешает грамматика спеки, должна хранить любая реализация. Более
    узкий файловый профиль не допускается (снять разрешение `03:163`), реализация кодирует имена файлов сама. Иначе
    части разных реализаций над одними данными несовместимы.

## Решение — урок 4
15. **P4.** Пустое или отсутствующее значение `group_by` — не группа. Шаг: две единицы без значения и одна испорченная
    размещаются по отдельности.
16. **P6.** При `host: path` ссылка без хоста — не группа. Противоречие `02:152` с примером снять.
17. **P8.** Единицы сервера для дренажа — объединение назначения и `status[].id`. Шаг: `status: []` при назначенных —
    `safe: false`.
18. **P15, P16.** `fates` — только занятые неотданные слоты. `since` — момент входа в fate.
19. **P14, P19, P21, P26–P28, P30.** По рекомендациям отчёта:
    - типы в `decommissioned`;
    - intent не по форме — 503;
    - `server` из пульса, иначе из слота, иначе null;
    - retired не входят в ждущие для offers, и к ним применяется `delete_after`;
    - пульс с `worker` не по ключу не читается;
    - `among` — число пригодных.
20. **P25.** Предложения набора, у которого не осталось ждущих, отзываются.
21. **P33.** Присутствие процесса — только из живого пульса ресурса. Устаревший пульс `running` слот в hung не держит.
22. **Причина 404 у `/where`.** Урок 9 `:265` против урока 4 `:218-220`: канон — урок 4 (владелец двери), урок 9
    привести к нему.
23. **P22a.** Имя сервера в `POST /drain` — по грамматике имени сервера, иначе 400.

## Решение — урок 5
24. **Приёмка 05 на каталоге из двух спек** (`testsub` и `testsub2`), шаги `running` и `rows`. W1 тогда виден.
25. **W6.** Заданное имя не по грамматике или не с `slot.prefix` — отказ старта, код 2, метку не писать.
26. **W7.** На выведенном сервере метки соперника нет.
27. **W8.** Поле `place_by` пишет в пульс база (урок 5), если спека его объявила.
28. **W2.**
    - `worker.name_back` — в Н1.1 урока 8.
    - `worker.name_taken` — только при потере имени.
    - Шаг: после сц. 04 ровно одна тревога.
29. **Нечитаемый пол при подтверждении** (не проверено, кандидат): отсечь аренду, как отказ подтверждения. Не читать
    пол как 0.
