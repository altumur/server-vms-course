## P/02

1. **Ресурс и `<s>/holds/*`.** P/02.5 Н1.4 даёт `resource` чтение «таблицы `holds`»; свидетель (`cluster/rights.py:177`) и
   договор `holds.md` читают это как `<M>/<holds.table>/*` у манифеста с разделом `holds`. c-go и c-python дают ресурсу
   `<s>/holds/*` (семья места) даже у манифеста без `holds` и не дают `<M>/<holds.table>/*` (вариант v9, `vb/notches/*`).
   Попутно в `catalog.tsv`: у строк единиц (строка 22) ресурса нет среди читателей, хотя Н1.4 — «строки манифестов с
   `about`»; в колонке читателей таблиц — «таблица `events.holds.table`», а ключ манифеста — `holds.table`.
   Рекомендация: как свидетель и договор — `<M>/<holds.table>/*` только при `holds`; `<s>/holds/*` ресурсу не выдаётся;
   поправить `catalog.tsv` (строки единиц с `about` — читатель `resource`; «`holds.table`»).
2. **Лишние отрицания `domainconsole`.** Нужны ли `!domain/signer` и `!domain/signer-pending` при уже выданном
   `!domain/signer*`? P/02.5 Н3 шаг 4 «нечитателю, чьи права его достают, — `!образец`» — до вычета отрицаний или после?
   c-go даёт, c-python нет. `--check` сравнивает множества точно, поэтому без решения равный файл (v12 `same → 0`) не
   внести. Рекомендация: после вычета — лишних отрицаний нет (как c-python). Заготовка равного файла —
   `decisions/inbox/аудит-покрытия/gemini-P02-v12-same-candidate.rights` (вывод c-python без `va/holds/*` у ресурса).
3. **Шаблон команды `--check` у «Стенда».** Форма `check.tsv` (твоё решение) требует от раннера вызвать `rights --check
   <file>` на манифестах варианта; в общем README «Стенда» шаблона такой команды нет (есть `stand.rights`:
   `{manifests} {deployment} {file}` → файл). Рекомендация: ключ профиля `stand.rights-check` с теми же подстановками,
   исход — код (0 — смысл равен, иное — расходится); впишу в общий README по твоему слову.
4. **check_spec и формы `variants/`.** `refused`, `check.tsv`, `check/` проходят структурную проверку без сверки: каталог
   закрыт исключением `P/02 acceptance-entry 5/variants`. Нужна ли проверка формы — инструмент твой.

## P/07

1. **Повтор просьб.** Н1.5 `api` (`:77–79`) называет дверь просьб (P/06.4, с памятью повторов) среди повторяемых, а Н5

   единиц (вычеркнуть дверь просьб из Н1.5 `api`); `never` Н1.4 — о собственных вызовах модуля, не о вызовах страницы

## Решения «Архитектора» (2026-10-30)

Правило для вопросов, где норма молчит: поведение, которое видно снаружи и влияет на корректность, задаёт норма. По
умолчанию — как свидетель, если оно безопасно. Нечитаемое не расширяет. Что приёмка не видит и что на корректность не
влияет — «Решает реализация».

**P/02**
1. Да, как свидетель и договор `holds.md`: ресурсу — `<M>/<holds.table>/*` только у манифеста с `holds`; `<s>/holds/*`
   ресурсу не выдаётся. `catalog.tsv`: у строк единиц с `about` читатель `resource`; «`holds.table`». Дефект c-go и
   c-python — вариант v9.
2. После вычета: отрицание нечитателю пишется, только если после уже выданных отрицаний его права ещё достают образец.
   Лишних `!domain/signer`, `!domain/signer-pending` при `!domain/signer*` нет (как c-python). Равный файл v12 `same → 0` —
   по заготовке.
3. Да: ключ профиля «Стенда» `stand.rights-check` с подстановками `{manifests} {deployment} {file}`, исход — код (0 — смысл
   равен, иное — расходится). Впиши в общий README.
4. Сделано: `check_spec` проверяет форму `variants/` главы 2.5 (каталог `v<N>-<slug>`, манифесты с `name:`, ровно одно из
   `expect.tsv` / `refused` / `check.tsv`, `refused` — имя манифеста варианта, `check.tsv` — заголовок, `check/<файл>` есть,
   код `0` или `!0`, лишних файлов в `check/` нет). Смысл по-прежнему проверяет README; исключение `5/variants` остаётся.

**P/03**
1. Пульс держателя берущий читает, **только пока строка удержания действует** (держатель есть, не `released`, возраст
   < 50 с). Действующая строка и нечитаемый пульс — место не брать (неизвестно, нечитаемое не расширяет). Строка не
   действует — место свободно по строке, пульс не читается (C06-UNHELD-PULSE-UNREAD-01). Черновик G05c — по этому.
2. Как свидетель: `most_valid` раньше закрытия чужой `begun`, затем сроки.
3. Как свидетель. Если свидетель при отказе до вызова события `command.failed` не пишет — норма так и говорит: отказ виден
   исходом команды, события нет.
4. Сверку `W2C_MANIFEST_REV` делает программа при старте, если переменная задана; не задана (запуск не раннером
   `w2c-run.sh`) — не сверяет. Так у свидетеля; приёмка — системная (`@manual`), как сейчас.

**P/04**
1. Одно прочтение: `manifest_behind` — число строк этого прохода, запись которых отложена из-за отставшего манифеста;
   каждая строка — один раз за проход. Н1.2 и Н3 «страж» — одной формулировкой.
2. Как свидетель: у шарда ушедшего воркера `worker: null`; схема семьи `<sub>/snapshot/<воркер>` — `string | null`. Форма
   пустого шарда — как свидетель, одна для всех; сц. 40 сравнивает и её.
3. `ok: true` — проход дошёл до конца, все входы читались и ни одна запись не отказана; иначе `false`. Сц. 30 так и ждёт.
4. Как свидетель: запрос `platform/decommission/<s>` к отвечающему серверу стоит (`standing`) и исполняется, когда сервер
   перестал отвечать. Живой сервер не выводится.

**P/05**

2. «Решает реализация»: копия от себя ничего не ломает; приёмка не проверяет.
3. Нет: нечитаемый пульс воркера в `units` не входит (нечитаемое не расширяет).
4. Да. Строку `P/05 acceptance-entry inputs` вноси сама тем же коммитом, что `inputs/` и два отложенных сценария (без
   каталога исключение было бы неиспользуемым); текст — «объекты для @put object (дверь объектов `testsub2/tickets`,
   надгробие `.gone`; аудит покрытия Gemini P/05); проверяется по README приёмки». Счёт 54 → 55.
