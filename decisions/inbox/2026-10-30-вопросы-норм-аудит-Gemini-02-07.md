## P/02

1. **Ресурс и `<s>/holds/*`.** P/02.5 Н1.4 даёт `resource` чтение «таблицы `holds`»; свидетель (`cluster/rights.py:177`) и
   договор `holds.md` читают это как `<M>/<holds.table>/*` у манифеста с разделом `holds`. c-go и c-python дают ресурсу
   `<s>/holds/*` (семья места) даже у манифеста без `holds` и не дают `<M>/<holds.table>/*` (вариант v9, `vb/notches/*`).
   Попутно в `catalog.tsv`: у строк единиц (строка 22) ресурса нет среди читателей, хотя Н1.4 — «строки манифестов с
   `about`»; в колонке читателей таблиц — «таблица `events.holds.table`», а ключ манифеста — `holds.table`.
   Рекомендация: как свидетель и договор — `<M>/<holds.table>/*` только при `holds`; `<s>/holds/*` ресурсу не выдаётся;
   поправить `catalog.tsv` (строки единиц с `about` — читатель `resource`; «`holds.table`»).
2. **Лишние отрицания `domainconsole`.** Нужны ли `!domain/signer` и `!domain/signer-pending` при уже выданном
   `!domain/signer*`? P/02.5 Н3 шаг 4 «нечитателю, чьи права его достают, — `!образец`» — до вычета отрицаний или после?
   c-go даёт, c-python нет. `--check` сравнивает множества точно, поэтому без решения равный файл (v12 `same → 0`) не
   внести. Рекомендация: после вычета — лишних отрицаний нет (как c-python). Заготовка равного файла —
   `decisions/inbox/аудит-покрытия/gemini-P02-v12-same-candidate.rights` (вывод c-python без `va/holds/*` у ресурса).
3. **Шаблон команды `--check` у «Стенда».** Форма `check.tsv` (твоё решение) требует от раннера вызвать `rights --check
   <file>` на манифестах варианта; в общем README «Стенда» шаблона такой команды нет (есть `stand.rights`:
   `{manifests} {deployment} {file}` → файл). Рекомендация: ключ профиля `stand.rights-check` с теми же подстановками,
   исход — код (0 — смысл равен, иное — расходится); впишу в общий README по твоему слову.
4. **check_spec и формы `variants/`.** `refused`, `check.tsv`, `check/` проходят структурную проверку без сверки: каталог
   закрыт исключением `P/02 acceptance-entry 5/variants`. Нужна ли проверка формы — инструмент твой.

## P/07

1. **Повтор просьб.** Н1.5 `api` (`:77–79`) называет дверь просьб (P/06.4, с памятью повторов) среди повторяемых, а Н5
   («повтор только `POST /<rows>`, `/<sub>/<rows>`»), инструкция (README урока, стр. 48) и описание модуля (стр. 93) —
   только строки единиц; модуль повторяет только их. Н1.4 `never` перечисляет `/{sub}/requests`, а страница VMS шлёт
   `POST /rec/requests` через `console.api` (`cam.shell.html:628`). Рекомендация: модуль сам повторяет только строки
   единиц (вычеркнуть дверь просьб из Н1.5 `api`); `never` Н1.4 — о собственных вызовах модуля, не о вызовах страницы
   через `api`.
2. **`dialog` и `confirm`.** Ни норма, ни описание модуля (`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`) не говорят, что они
   возвращают: обещание значений (отмена — `null`), `ok` — надпись кнопки, `confirm` — ответ человека (`true`/`false`).
   Страница VMS опирается ровно на это; тест `module-page-adds` проверяет это поведение свидетеля. Рекомендация:
   вписать в описание модуля (публичный контракт) и в Н1.5 `adds`.
