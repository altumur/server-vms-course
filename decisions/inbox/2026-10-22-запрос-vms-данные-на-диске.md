# Запрос: данные подсистемы на диске и цель `/etc/<sub>`

**Что мешает.** P/02.4: «ни один юнит не монтирует корень целиком; всё изменяемое — под /data/platform»
(`02.4-installer.norms.md:110`); каталоги `/data/platform/…` перечислены закрыто (`:98–103`); `/etc/<sub>` — ссылка,
настоящий каталог — отказ установки (`:285`), цель ссылки не названа. ADR-0023 (дополнение 2026-10-22) снял
`/data/vms/etc`, `/etc/vms`, тома в `/data/vms/obsd`.

**Что нужно VMS.** Настройки подсистемы (`/etc/<sub>`); изменяемое состояние подсистемы вне хранилища (кэш движка
архива, служебные файлы части `rec-obsd`); тома архива — отдельные диски регистратора (свидетель:
`/data/vms/obsd/volume`, `Source/deploy`), их число и размер — свойство сервера. На А/Б-коробке переживает только
`/data` (ADR-0023).

**Рекомендация «Архитектора»** (к ревью), правка P/02.4 Н1.2 `dirs`:
- `/etc/<sub>` → `/data/platform/etc/<sub>` (как `/etc/w2c`), режим `0750 root:<dep>-<sub>`;
- состояние подсистемы — `/data/platform/<sub>` `0750 <dep>-<sub>:<dep>-<sub>`, установщик создаёт для каждого
  манифеста; юнит воркера монтирует только свой каталог;
- тома архива — не каталоги установки: точки монтирования устройства `/data/platform/<sub>/volumes/<n>`, объявление в
  манифесте (вид тома — P/04 места), установщик монтирований не создаёт, проверяет владельца при старте.
Вопрос на ревью: оставить ли тома вне `/data/platform` (отдельная точка `/srv/<sub>`) — тогда исключение из `:110`
словами нормы.

**Обход до решения.** Урок `09-deploy` пути данных не нормирует; свидетель — как есть.

## Решение
**Решён** (2026-10-22). ADR-0091 п. 4. Нормы — Т-правкой «Спецификации» одной выгрузкой
(`inbox/2026-10-22-поручение-Т-правка-ADR-0091.md`).
