## Инструкция ревьюеру
- По каждому классу — исход из закрытого списка: **движок / кандидат / норма**, со ссылкой на норму (файл J или M, строка). «Норма» — неоднозначна, противоречит себе или пробел; тогда — какой фразы не хватает.
- Причина для кандидата — по ADR-0133 доп. (41), (42), (44): спека / цикл / модель (без или при обратной связи), с четырьмя полями. Ворота попытки 5 (паспорт `p01-b-raft-d5bd29ddb2dd`, 16 раундов, 79,2 млн токенов из 150 млн, догадок нет): только `mech` (сборка, vet, тесты модели, трассировка норм) и `code:*`. Ни векторы, ни сценарии, ни стенд в воротах не исполнялись, поэтому ни один класс кандидата не получает метку «при обратной связи».
- Доп. (44) п. 5 («норма однозначна» — по тексту, который видела модель): попытка 5 читала M через b11-shell с обезличиванием `FS_PATH` (до P01.150). Для каждого класса кандидата сверено, скрывал ли `FS_PATH` текст его нормы.
- Единица — случай: шаг сценария, строка вектора, запись описи, проба.

## Что предлагается механическими правилами
- E1 — ворота линии судьи: профиль с полем `code` (и каждым необязательным полем PROFILE.md) принимается; уже назначено (P02.25).
- E2 — ворота линии судьи: ответ отказа заглушки содержит неназванное `error` в корне — шаг GREEN; `error` вне корня — red.
- E4 — ворота: каждый режим `compare` из `wire.tsv` (`set`, а также замена по столбцу `match`) исполняется на заглушке, верный ответ — GREEN.
- E5 — ворота: заглушка кандидата, которая падает на старте, даёт цели red `implementation`, а не `blocked`. Отказ команды вектора кандидата — red `implementation`, а не `stand`.
- E3 — правка спеки: подготовка сц. 21 — директивой (`@setup`/`admin` в таблице), не прозой README.cases.md.
- K1–K5 — правки кандидата не делаются (генерация с нуля); в разбор попытки — модель (без обратной связи), вторая — цикл (ворота попытки не исполняли векторы и стенд).
