# K2 — `"{input}"`: кандидат взял подстановку в двойные кавычки поверх одинарных кавычек движка

**Случаев:** 157 строк, все строки шести целей векторов, у всех `red implementation outer_form`, `response malformed`: jcs 17, rights-evaluator 37 (векторы урока), crl 22, revoked 21, log-mask 39, store-client 21 (общие пакеты). Ни одна строка не дошла до сравнения ответа по существу.

У Opus (P01.188) jcs и rights-evaluator зелёные: его профиль пишет `./bin/configstore-tool vector {input}` без кавычек.

## Норма
- `PROFILE.md:87` («Substitutions»): «The runner shell-quotes substituted paths and individual values. **Do not add shell quotes around a placeholder.**»
- `PROFILE.md:63`: команды профиля исполняет `/bin/sh`.
- «Unified vector command» (`PROFILE.md:123` и далее) — конверт в файле `{input}`, ответ — объект `exit_code`, `stdout_b64`, `stderr_b64`.

## Наблюдение
Профиль кандидата (`01-store/acceptance.yaml:21–28`): `01-store/jcs: ./bin/jcs "{input}"`, так же все восемь строк `vectors`. Движок подставляет `'<путь>'`, и оболочка получает `./bin/jcs "'<путь>'"`. Аргумент процесса — путь с буквальными одинарными кавычками.

Повтор окна (песочница окна, бинарники собраны из `77b90bef`, конверт по `run_vectors.go:145–152` — компактный JSON и LF):
- `sh -c "./bin/jcs \"'<путь>'\"" </dev/null` → код 2, stdout пуст (так видит движок);
- `sh -c "./bin/jcs '<путь>'" </dev/null` → код 0, `{"exit_code":0,"stdout_b64":"eyJjYW5vbmljYWwiOi…","stderr_b64":""}`;
- `vectors` и `rights-evaluator` с буквальными кавычками — тоже код 2.

## Код движка
- `internal/engine/run_stand.go:205–243`: `substituteTemplate` всегда вызывает `shellQuote`, а `shellQuote` всегда даёт `'…'`. Это `PROFILE.md:87`.
- `run_vectors.go:163–166`: ненулевой код команды → `valid=false`; `:99–105` → `Response = "malformed"`, `redVerdict(ClassImplementation, "outer_form")`. Класс `implementation` согласуется с R024 (несовпадение строки, `acceptance.norms.md:183`) и R038 (`stand` — только для команды самого стенда, `:196`). Движок прав. В P01.127 (E5) движок давал здесь `stand`; движок `ef7dcf9b` даёт `implementation` (ср. вопрос 2 E5).

## Код кандидата
`cmd/jcs/main.go:44–57` (и тот же `readRequest` в `cmd/vectors/main.go:50`, `cmd/rights-evaluator/main.go:43`):
- аргумент не начинается с `{` → `os.ReadFile(args[0])`;
- путь с кавычками не читается, ошибка проглатывается → `io.ReadAll(os.Stdin)`;
- stdin пуст (движок его не задаёт) → разбор конверта падает → `os.Exit(2)` (`:33`).

Тесты модели (`cmd/*/main_test.go`) зовут `execute` напрямую, мимо оболочки и профиля, и строку профиля не проверяют. Откат на stdin прячет причину: вместо отказа «нет файла» команда молча читает пустой stdin.

**K2б (скрыто, для P01.189).** `stand.store-op` того же профиля: `./bin/store-op -socket "{socket}" -dir "{dir}" -id "{id}" -tls "{tls}" -- {args}` — та же ошибка. Сейчас красное group у двух кандидатов одинаковое (store-op 15, stand), то есть его даёт общая причина.

## Что видела модель
- Раунд 3 (этап jcs), сообщение 10: модель сама выполнила `nl -ba "$SPECS/Platform/common/acceptance/PROFILE.md" | sed -n '1,115p'`. В ответе (сообщение 11) строка 87 цела: «The runner shell-quotes substituted paths and individual values. Do not add shell quotes around a placeholder.» Обезличивания `<path>` в выводе нет.
- Тот же раунд, сообщение 30: модель дописывает в профиль `01-store/jcs: ./bin/jcs "{input}"` по образцу уже стоявшей строки `write-checks`.
- PROFILE.md лежит в голове модели (`state.json`, `head_files`; строка 87 есть в тексте головы).
- **Ворота.** Ворота команд (`profile_probe.py`, доп. (47) п. 1 (1)) стояли в задании каждого раунда и вызывали каждую команду `vectors` на корректном конверте. Подстановку они делают так: `profile_probe.py:420` — `shlex.quote(f)`. `shlex.quote` не берёт в кавычки путь без особых знаков, поэтому ворота исполняли `./bin/jcs "<каталог>/envelope-0.json"`, и команда отвечала. Красного вида «profile command vectors.…» (`profile_probe.py`, `result`) нет ни в одном сохранённом раунде (1, 3, 5, 6, 8, 9, 10).
- Догадки на этом месте нет.

## Мнение окна
Исход — **кандидат**, движок прав. Норма однозначна, видна, модель её прочла в том же раунде, где нарушила.

Причина по доп. (44): **модель (без обратной связи)**. Ворота этим местом занимались, но ни разу не показали красного (условие 1.2 не выполнено). Вторая причина — **цикл**: ворота подставляли путь не так, как движок, и дали ложную зелень по всем объявленным командам `vectors` (по одному конверту на таблицу; суд же красит все 157 строк). По доп. (44) п. 3 «обратная связь была неверной» — признак цикла. Модель код под ворота не подгоняла, ворота лишь не поймали ошибку. Поэтому окно ставит цикл второй причиной, а не главной.

## Вопросы ревьюеру
1. Ложная зелень ворот по самому месту ошибки — это «модель (без обратной связи)» с второй причиной цикл, или главная причина — цикл? Окно выбрало первое: модель прочла запрет за 19 сообщений до нарушения.
2. Нужен ли в «Unified vector command» пример строки профиля без кавычек? Правило стоит в «Substitutions», за 36 строк до раздела векторов.
