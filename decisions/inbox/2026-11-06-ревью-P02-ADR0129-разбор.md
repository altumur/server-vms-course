## Подтверждённый блокер

Codex Б1 принят. P/02.3 N3 шаг 6a до первой записи требует полного конечного профиля удаления при фактических B/V хранилища. Приёмочный стенд задаёт B=1048576, V=524288. Даже один unit/claim при нулевых H/LF и прочих слагаемых даёт `12*524288+7=6291463 > 1048576`. Положительная установка `testsub` при этом требует код 0, rev 1. Нулевое текущее число unit не позволяет исключить разрешённую будущую процедуру из полного профиля.

spec103 согласует параметры положительного стенда и полный профиль с нормой, сохранив проверки старых потолков в отдельных случаях. Нельзя обходить шаг 6a, выдавать неполный профиль за полный или механически заменить ожидаемый успех отказом. Одно число 6291463 не является готовым достаточным B: остальные слагаемые и полный набор пакетов ещё должны быть учтены. Подтверждение блокера арифметическое; установщик и production-дескрипторы здесь не исполнялись.

## Четыре вопроса владельцу с рекомендациями

1. **Ручной `manifestrt/go`.** `gen_manifest.render()` копирует шесть файлов ручной среды, а не строит их алгоритмы из формы. Рекомендация: при следующей перегенерации/сборке пакета снять из выдаваемого пакета ручную реализацию loader; реализацию пишет линия по P/02. Исходники среды, которые нужны внутренним проверкам, не удалять автоматически. Изменения среды учитывать в паспорте зависимости, пока она остаётся. Это предлагаемый ответ на границу запрета ручных функций, не вывод о пороге Т2.
2. **Меньше трёх смысловых эпизодов.** Рекомендация: помечать «недостаточно данных»; новый генератор по такой оценке не вводить, существующий только из-за недостатка истории не снимать. Не подставлять фиктивный 0/5. Пороги ввода ≤1/5 и снятия >1/2 прежние.
3. **Граница места для Т2.** Рекомендация: до отбора истории фиксировать поведение и все зависимости продюсера, а не удобный файл/подраздел. Один смысловой эпизод считать один раз. Изменение канона в векторе/корпусе считать, если оно действительно меняет требуемое поведение; перевод/перенос/исправление ожидания без изменения нормы — не считать. `batch` нельзя исключить из истории отпечатка.
4. **Равенство формы и схем семейств.** Рекомендация: review103 добавляет предметные связи P/02 по образцу существующих равенств P/06/P/08: FILE_MAX и второй носитель `manifest-row`, целочисленные границы — по существующему месту/типу integer-place. Каждый путь и источник явны, мутант каждого из двух носителей обязан обнаруживаться. Не объявлять все числовые maximum одной константой и не ослаблять check_spec.

Решения владельца по этим четырём пунктам ещё не получены. После ответа — новое дополнение ADR-0129; выполнение внутри прежних ADR и обычные правки выше не зависят от изменения Т2.
