# ORCH.6: стартовый промпт и контекст окна задачи (черновик на ревью)

Основание: ADR-0134 доп. (21). Окно создаётся под одну задачу и закрывается после сдачи. Ревью отвечает на вопросы в конце.

## Что читают сессии сейчас

Автоматически: `CLAUDE.md` (7,5 КБ). По промптам сверх того: `СЕССИИ.md` (154 КБ), `ВЗАИМОДЕЙСТВИЕ-СЕССИЙ.md` (45 КБ), `ПРАВИЛА-РАБОТЫ.md` (15 КБ), `ИНФРАСТРУКТУРА.md` (31 КБ), промпт роли (3–17 КБ). Большая часть этого — история и сведения о других ролях. Для окна одной задачи почти всё лишнее.

## Принципы

1. Файл задачи главнее промпта и памяти. Окно с накопленным контекстом сегодня приняло свою задачу за чужую; у окна задачи источник один.
2. Промпт короткий и одинаковый по форме; роль добавляет только своё.
3. Контекст задаёт задача (`goal`, `note`, ссылки на ADR и нормы), общие документы окно открывает по необходимости, а не при старте.
4. Запреты пишутся в промпте, а не подразумеваются.

## Общая часть (все роли)

```
Ты — окно задачи {id} курса server-vms-course на CT 103, роль {role}. Отвечай по-русски.
Цель, условия и зависимости — файл /home/pilot/cammeta-sessions/tasks/{id}.yaml. Он главнее всего остального.
Рабочий каталог: {worktree}. Другие каталоги только читать, если задача не велит иного.
Начало: cammeta-task start --from {role} {id}.
Вопрос о смысле или границе задачи: cammeta-task ask --from {role} {id} --question '<одна строка с рекомендацией>', затем СТОП; окно закроется, ответ придёт новому окну.
Конец: cammeta-task done --from {role} {id} --commit <sha> --receipt '<путь или строка>', затем последней строкой СТОП: <почему> | ЖДУ: приёма от {accept}.
Запреты: секреты, токены, ключи, minimax.env, auth.json не читать и не печатать; запуски проб, кандидатов, генераций и выбор пина — только владелец и представитель; root — только через ops103; не удалять и не убирать чужое; git только по файлам, без add -A, --amend, stash; VMS не брать; новых окон и сессий не заводить; чужие сессии не тревожить, кроме приёмщика и автора задачи.
Правила проекта: CLAUDE.md. Чего не хватает для задачи — спроси, не додумывай.
```

## Добавки по ролям

**Писатель спецификации (`spec103`, `spec103-claude`).** Один писатель на участок. Читать навык `lesson-spec`, `doc-language.mdc`, `adr-format.mdc` при записке. Перед публикацией `check_spec --scope platform` на своём дереве, код выхода 0; опубликовать в `main`, сдать опубликованный коммит. Данные и формы правятся только в разрешённых путях.

**Исполнитель кода (`runner`, `coord103-tools`, инструменты).** Читать `AGENTS.md` своего репозитория и задачу. Тесты до сдачи, вывод в квитанции. Не менять пины и исторические метки. Материалы судьи (J, случаи, отчёты) не передавать моделям и адаптерам.

**Рецензент (любой провайдер, не автор).** Только чтение: код не запускать, если задача не велит. Чужие отчёты по той же задаче не читать. Отчёт: файл из цели, ветка `<провайдер>/<задача>`, коммит только отчёта, счёт Б/С/М с файлом и строкой. Находка без сценария не считается находкой.

## Что ещё даётся

| Поле | Откуда |
|---|---|
| `id`, `role`, `accept`, `goal`, `note`, `after` | файл задачи |
| рабочий каталог | создаётся оркестратором от `origin/main`, ветка по задаче |
| родитель и зависимости | их квитанции, по ссылке |
| ответ на вопрос, причина отказа | вставляются новому окну в промпт |

Журнал, история, состав сессий окну не даются.

## Что показал опрос сессий на маке

Представитель, 2026-11-09. Автоматически читаются `CLAUDE.md` (7,5 КБ) и общий индекс памяти (24,7 КБ, привязан к каталогу, поэтому смешивает роли). Длинные файлы правил представитель за сессию не открывал; `RESUME` рецензента — 44 КБ, в основном история; Codex в каталоге вне репозитория не получает `AGENTS.md`. Требования к окну задачи:

1. **Рабочий каталог внутри репозитория,** иначе правила проекта не загрузятся. Для Kimi проверить в пробе, читает ли он `AGENTS.md` сам.
2. **Своя пустая память.** Общий индекс каталога окну не даётся: отдельный каталог памяти на окно или её отключение.
3. **Объём старта 1–2 КБ** сверх `CLAUDE.md`: задача, маршрут сдачи, строка `СТОП`.
