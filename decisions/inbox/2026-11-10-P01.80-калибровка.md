## Красный набор

Пустую сборку и «отказ на всё» поймали оба. Раннер пропустил два мутанта: лишние 5 байт в `Content-Length` (`extra`) и порядок в `revoked`. Движок по существу поймал 5 мутантов из 12; на блокированных целях его красное ничего не различает.

## Выводы

1. Раннер не эталон: падение на `crl`, неполный `log-mask` и два пропущенных мутанта. Раннер выведен (ADR-0135 доп. (6)), чинить его не будем; его вердикты по этим местам доверия не дают.
2. Движку нужен один целевой круг доработки по двум главным причинам и мелким трём. Ворота механически проверяемы: без моста не блокируется вся цель; сокет роли находится по профилю, а не по первому имени; `box` даёт not_applicable.
3. Шаг 8 закрыт: каждое расхождение классифицировано.

## Поправки по пакетам P01.111 (2026-11-10)

Пакеты доказательств представителя (`/home/pilot/owner-receipts/P01.111-classes-20261110/`, 11 классов) уточнили классификацию в четырёх местах. Окончательный исход каждого класса — за ревью `P01.112`.

- **C06, `mask_in.tsv`:** ошибка движка, а не раннера. `consumers.tsv:137` назначает таблицу только `06-console`; для `01-store` раннер прав, лишний — движок.
- **C07, `crl`, код 139:** по существу судьи совпадают — первый прогон раннера записал отчёт 22/22 GREEN, потом упал. Дефект — выход процесса раннера (инструмент суда).
- **C10, мутант `revoked`:** не пропуск раннера, а вероятный пробел нормы. README `revoked:24` сравнивает множество серийных номеров, а `wire.tsv:75` требует `compare: value`.
- **C11, мутант `extra`:** раннер исполнил 3 группы проб из 15 строк `extra.tsv`, поэтому пропустил мутант `+5` — дефект раннера.
