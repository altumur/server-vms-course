# Изменения норм

## M11 → M12

Сравнены английские источники двух входов. Абзацы с R-id и пункты перечней M не изменились. Ниже перечислены все четыре изменённых файла M; состав файлов остался прежним.

| Файл относительно Platform | Изменение |
|---|---|
| `01-store/acceptance/3/README.md` | Для сценария 37 пояснено: после isolated recover единственного peer лидер — s1. Шаг 14 ждёт Leader, leader_id s1 и непустой leader через существующий маркер `@not("")`; шаги 15–18 сохраняют проверку строк и версий. Полный договор status продолжает действовать. |
| `common/acceptance/PROFILE.md` | Для stand.checkpoint каталог dir — ровно configstore выбранного экземпляра под его data. У plain store id и tls пусты; у члена id свой, tls — собственный комплект при TLS, иначе пусто. Комплект другого члена при запуске не меняет эту привязку. |
| `common/acceptance/README.md` | Подстановки значений @header выполняются до отправки по общим правилам; ошибочная подстановка не отправляется буквально. Для @together требуется доказанная полная запись обоих запросов до первого ответа, иначе stand. Запрещённое тело HEAD/204/304 проверяется по байтам после заголовков, включая буфер транспорта; отсутствие наблюдателя — stand. Успешная копия проверяется по полной форме владельца, включая Key и предел UTF-8 KEY_BYTES. Средство и конечный интервал наблюдения в бюджете шага, а также планирование отправок выбирает движок. |
| `common/acceptance/command-tables.md` | Триггеры @crash/@io-error обязаны выбирать нужный store по грамматике двери или операторской директивы; замена checkpoint — обычная HTTP-запись. Уточнён счёт объектов configstore, rename и дескрипторов после rename/unlink. Исследование заканчивается на триггере; сводка сохраняет все требуемые исполнения, ошибки и причины прерывания, намеренно отсутствующий suffix не считается пропуском. Доказанный crash оставляет экземпляр явно остановленным; offline operator не запускает демон. Контроль всех потоков исполняется текущим наблюдателем до оценки на существовавшем и новом нативных потоках одного процесса. Средства разрешения идентичности, трассировки, язык фикстуры и имена доказательств выбирает движок. |

Маркер COURSE_COMMIT изменён как служебная идентичность источника. Таблицы сценариев и ожидаемых векторов, а также процедуры боевой квалификации остаются вне M.

## J11 → J12

Четыре файла выше входят и в J-вход. Дополнительно изменились следующие английские файлы J-входа; их переводы входят в полную J, но не в J-вход.

| Файл относительно Platform | Изменение |
|---|---|
| `01-store/acceptance/3/scenarios.tsv` | Только leader в шаге 14 сценария 37: неподдержанная подстановка адреса в ожидании заменена на `@not("")`. State Leader, leader_id s1, строки, версии и остальные шаги сохранены. |
| `common/acceptance/spec/acceptance.norms.md` | P/AC-R017 различает неожиданный выход и доказанный сценарный stop/crash; restart ожидаемо остановленного экземпляра не посылает второй stop. P/AC-R055 проверяет идентичность выбранного store и HTTP-запись замены checkpoint до запуска. P/AC-R057 сохраняет исследование и каждый испытательный запуск в сводке исходных шагов. P/AC-R058 требует текущего контроля разных нативных потоков. Пункт «Implementation decides» перечисляет средства, которые выбирает движок, и наблюдаемые доказательства, которые судят. |
| `common/acceptance/forms/targets.routing.tsv` | В шапке free=size уточнены десятичный Content-Length с ведущими нулями, допустимое сведение одинаковых длин, отсутствие размера при неверной/противоречивой длине, приоритет chunked и размер 0 без framing. Собственная граница integer движка не становится пределом кандидата; необязательный size остаётся необязательным. Значения строк маршрутов не изменились. |

Новые слова словаря, поля профиля, сценарии, шаги и форматы не добавлены. Обновление входа не означает исполнения сценариев или подтверждения поведения кандидатов.
