## 1. `@on <кластер> @freeze` / `@on <кластер> @thaw` — требование к раннеру (не новая директива)

**Зачем (место в норме).** Н1.3 `pass` консоли домена: «срок — «Ожидание» строки договора пересылки; ответ — как пришёл;
**502 при обрыве и молчании**»; Н4: «слова договора пересылки `answer` — 502, передача процессу `domain` (Н1.3 `pass`): обрыв
и молчание»; чек-лист П/10-02: «… 502 при обрыве и молчании; срок и 502 — чтением». Обрыв и молчание дают одно и то же слово
отказа («did not answer»), и различаются они только тем, жив ли процесс: оборванный процесс не отвечает вовсе, молчащий —
не отвечает дольше срока «Ожидание» (5 с у `PUT /domain/topology`). Единственный способ получить молчание на стенде —
остановить живой процесс на паузу: SIGSTOP/SIGCONT всему процессу, все потоки стоят, сокеты на месте.

**Формы (приняты).** `@freeze <имя>[#n]` / `@thaw <имя>[#n]` — SIGSTOP/SIGCONT группе процесса, «Предел заморозки — 120 с»,
шаг — класс «данные», выхода не ждёт, ожидание `ok` (общий README приёмки, 9467a1bab и e1b8b60a5; решение «Архитектора»
2026-10-30). `@on <кластер> <директива>` на стенде домена допускает `@freeze`/`@thaw` (строка 405 общего README на `main`,
добавлена аудитом покрытия P/08, f02454106). Готовый пример — Platform/08-domain/acceptance/10/scenarios.tsv, сценарий 08:
`@on hold @freeze domain#1` … `@on hold @thaw domain#1`.

**Что требуется от раннера.** В текущей голове раннера приёмки (cammeta-acceptance, d3aacad) ветка `@on` в
`runner/m11stand.py` знает только `@start`, `@sigterm`, `@sigkill` и операции над объектами (`@put object`, `@spoil object`).
`@freeze`/`@thaw` под `@on` попадают в ветку «@sigterm» — процесс УБИВАЕТСЯ вместо заморозки. Починка раннера есть в ветке
cammeta-acceptance `p08-audit-99a63fe` (017195d):
- `runner/m11stand.py` — `if sub[0] in ("@start", "@freeze", "@thaw"): return st.directive(" ".join(sub), ACC, expect);`
- `runner/stand.py` — `freeze()`/`thaw()`: SIGSTOP/SIGCONT группе процесса, предел 120 с.

**Кто проверяет.** `черновики/P10/K03-forward-502-silent.tsv` (сценарий `k03-forward-502-silent`): процесс `domain` на
кластере hold заморожен (`@on hold @freeze domain`), дверь правки отвечает 502 «did not answer», после оживления
(`@on hold @thaw domain`) отвечает 200.

**Оговорка.** Без починки раннера сценарий не подменяет молчание обрывом, а падает: на шаге 2 процесс был убит, и шаг 4
(`@on hold @thaw domain`) не находит процесса — отказ раннера, а не «зелёный» прогон. Это лучше молчаливой подмены, но
до починки сценарий неисполним.

## 2. Отказ «not in the directory» — нужны данные стенда (манифест без `domain.ref`)

**Зачем (место в норме).** Н1.2а, дверь `/domain/<sub>/<rows>`: «404 {error: "not in the directory"} — у манифеста нет
`domain.ref`»; Н4: «not in the directory | 404 | манифест без `domain.ref`»; чек-лист П/10-01 называет этот отказ среди
отказов дверей вида.

**Почему недостижимо на стенде П/10.** Каталог подсистем стенда П/10 — только `testsub` (в раннере приёмки: `BASE` для уроков
П/08–П/10 — `specs: ("testsub",)`), а манифест `testsub` (Platform/02-installer/acceptance/2/puts/testsub.subsystem.yaml)
содержит `domain: {ref: name, view: [start], books: {tallies: {show: [n]}}, …}` — `domain.ref` есть. Манифест `testsub2` из
общих данных стенда `domain.ref` тоже содержит. Значит, на этом стенде дверь строк подсистемы до отказа «not in the
directory» не доходит.

**Что требуется.** Один манифест подсистемы без `domain.ref` (раздела `domain` без поля `ref` или вовсе без раздела
`domain`) в каталоге стенда П/10 — и включение его в перечень подсистем стенда (`specs` урока в раннере приёмки). Тогда
`GET /domain/<эта подсистема>/<её строки>` отвечает 404 {"error": "not in the directory"} — до проверки вида, как и в норме.

**Статус.** Решение владельца приёмки: нужно ли заводить такую подсистему ради одного отказа. До этого решения черновики
K01–K03 отказ «not in the directory» не утверждают — остальные отказы дверей вида (404 «no domain here» и 503 «unavailable»)
покрыты.

## 3. Пояснение: порча объекта вида — `@spoil object`, а не `@put object`

Задание черновика предлагало порчу объекта вида директивой `@on <кластер> @put object domain/view …`. Директива `@put
object <ключ> <файл>` требует ФАЙЛ с содержимым, путь — от каталога приёмки урока; новый файл вне `черновики/P10/` создавать
нельзя, а существующего файла с нечитаемым содержимым вида нет. Поэтому взята принятая директива `@spoil object <ключ>`:
портит байты объекта (пишет «{»), после чего чтение объекта — нечитаемо (П/05 Н1.1), то есть объект ЕСТЬ, но не читается, —
ровно то состояние, которое Н1.2а называет «объект есть, но не читается — 503 {error: "unavailable"}».

Оговорка README приёмки (строка про `@spoil object`): «процесс-писатель объекта до этого остановлен» — поэтому в черновике
K01 сначала останавливается процесс `domain` (`@on hold @sigterm domain`), и только потом портится объект; иначе процесс
перезаписал бы объект при следующем проходе.
