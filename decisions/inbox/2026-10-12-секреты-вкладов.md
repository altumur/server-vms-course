# ADR-0074: запечатывание входящего вклада до отправки отчёта

## Контекст

Продолжаю после принятия этапа отчётов (`9f8cdb11`, слияние `67ad7878`; основа `b85c47ae`).
`uplink.publication` ещё не включает `from`. Простого добавления недостаточно: секрет во входной строке
запечатан кольцом члена и привязан к её пути/элементу; держатель этого кольца не имеет. `carry.answer`
умеет открыть только своё кольцо и запечатать получателю. Перенос ciphertext в `entries[].value` ломает
также привязку. Проба `Source/tests/probes/adr0074_delivery.py` воспроизводит оба отказа.
Форма входящего шифрования в ADR не определена. Новые имена ниже — предложение, в runtime не введены.

## Рекомендация

Использовать существующий X25519-конверт `x25519:v1:…` и отдельный ключ приёма книг **домена**, который
переносится вместе с ним. Не использовать кольцо члена, ключ ретранслятора или временный ключ текущего
держателя: последние сделают сохранённые поколения нечитаемыми после переноса.

Предлагаемая форма до кода:

| Место | Форма и владелец |
|---|---|
| `domain/book-seal` | Строка `{seed_secret: <32 байта hex>}`; создаёт/читает только signer роли domain; кольцо держателя на диске. В резервной копии секрет перезапечатан ключом копии существующим механизмом. При восстановлении — кольцом нового держателя. |
| Подписанный корнем набор `domain/keys` | Дополнительный элемент `book_seal: <X25519 public hex>`; входит в подпись и ревизию набора. Агент использует только проверенный набор, не поле входящего ответа без проверки. |
| Значение `*_secret` во вкладе отчёта | Существующий конверт `x25519:v1:…`, `seal_to(book_seal, field, value, ctx)`. Контекст `ctx` — JCS-текст массива `[member, source_path, item]`; имя поля остаётся отдельной частью AAD существующего конверта. Остальная форма публикации и `entries` не меняется. |

Агент открывает локальное `enc:v1` по исходному пути/элементу и запечатывает для домена **до подписи
публикации**. Ретранслятор переносит байты; секрет не открывает. Держатель открывает конверт только при
сборке, после проверки происхождения, затем запечатывает результат своим кольцом под конечным
`domain/<sub>/<book>/<recipient>#<key>`. Доставка члену — прежний `carry.answer`.
Без проверенного ключа, с plaintext, неверным конвертом или чужим AAD вклад с секретом не доставляется;
ошибка не раскрывает значение. Исключений для локального пути не делать.

При плановом переносе ключ сохраняется. При переносе после кражи — новый ключ и новый подписанный набор;
старые секретные вклады дают `missing` до нового отчёта членов, а не открываются прежним ключом. Старый
держатель уже знал старые секреты; ротация самих учётных данных — отдельная операция. Принятые тела не
переписывать ради повторного шифрования. Без совместимости и двойного чтения.

Приёмка: разные кольца издателя/держателя/получателя; прямой путь и ретранслятор; подмена автора, строки,
элемента и поля; секрет не виден ретранслятору; обычный перенос открывает прежнее поколение, перенос после
кражи требует новое; отзыв гранта убирает доставку. Новые имена и формат AAD — в долг `# ADR-0074 «курс»`
одновременно с реализацией после решения. Прошу утвердить форму либо поправить её; продукт не меняю.
