# P01.259: правила из прозы в формы — выбор формы и значений

Задача P01.259 (ADR-0133 доп. (31а)), вход — ретро второго движка
(`/home/pilot/owner-receipts/ENGINE2-retro-20261112/RETRO-ENGINE-ANSWERS.md` §4) и сводка
`ENGINE2-retro-summary-20261112.md` §5. Срез: `origin/main` 5ca1fb3fc (в нём уже влита P01.256 со столбцом `role`).
Поведение не меняется: форма повторяет то, что сейчас сказано прозой, проза ссылается на форму.
Ниже то, что норма решает сама (делаю без вопроса), и то, где нужен выбор Архитектора.

## Решает норма — делаю так

**(2) Роль двери `store`.** Закрыта P01.256 (Б8, столбец `role`). В этой задаче не трогаю, ссылаюсь.

**(1) Особые правила сравнения главы 1.1.** Режим `whole` есть только у трёх целей P/01.1 (`door`, `extra`,
`inproc`); у прочих целей `subset`, и лишнее безымянное поле там не сравнивается вовсе. Поэтому беру столбец
маршрута `free` (безымянные поля корня тела, которые режим `whole` допускает): JSON-массив закрытых слов,
`[]` — нет таких полей.
- `error` — безымянное `error` в корне тела не сравнивается, его значение не нормировано (README 1.1, строка 20);
- `size` — безымянное `size` в корне тела ответа-отказа `413 toolarge` допускается, если это целое JSON-число,
  равное полному размеру отправленного тела в байтах; после проверки оно исключается из сравнения (README 1.1,
  строка 23).

Непустой `free` у строки с `body` не `whole` — ошибка данных. Почему столбец, а не форма главы: движок уже читает
режим тела из строки маршрута (`body`), и правило допуска — уточнение того же режима; вторая форма заставила бы
движок склеивать два источника. Цена — ячейка `[]` во всех строках маршрутов (см. вопрос В1).

**(4) Порядок манифестов стенда.** Новая общая форма `Platform/common/acceptance/forms/stand-manifests.tsv`:
`n manifest file beside` — номер установки, имя манифеста, путь файла, каталог, чьё содержимое кладётся рядом
с копией манифеста (`-` — ничего). Две строки: `testsub` → `testsub2` (рядом —
`Platform/06-console/acceptance/5/inputs/testsub2`). Абзац «Manifests» в `stand.md` ссылается на форму и
сохраняет причину порядка (манифесты ссылаются друг на друга, порядок из файлов не выводится). Каталог
`Platform/common/data/testsub/` не трогаю: его байты правит «Спецификация».

**(5) Транспорт write-checks.** Строка `wire.tsv` не подходит без правки грамматики и проверки
(`package` — путь под `vectors/`, `table` — файл пакета; ячеек из строк `#lim`/`#allow` в грамматике нет;
проверку `wire.tsv` держат скрипты навыка, их правит Архитектор). Беру форму «таблицы проб» —
`Platform/common/vectors/probe-tables.tsv`, одна строка на пакет, чья таблица проб лежит в формах урока:
`package table case cells skip native`. Ячейки — `{"column":…}` или новый конструктор только этой формы
`{"lines":"#lim","as":"object"}` / `{"lines":"#allow","as":"array"}` с тем смыслом, что сейчас в wire.md:146
(формулировка сверена с P01.256, G06: элемент `allow` — JSON-строка текста одной строки `#allow`, порядок
сохраняется). Раздел wire.md «P/01 write-checks transport» сокращается до ссылки на форму; слово `vector`
шапки маршрутов называет обе формы.

**(3), часть 1. Литерал «Role sockets» — файлом.** JSON из `stand.md` переезжает в файл
`Platform/01-store/acceptance/1/inputs/rights.json` (рядом с `acceptance/2/inputs/rights.json`, тот же вид входа
стенда), байты — те же. Абзац «Role sockets» ссылается на файл. Значение столбца для P/01.1 — этот путь, слово
`literal` не нужно.

## Нужен выбор Архитектора

**В1. Столбцы `rights` и `free` в общей шапке маршрутов.** Шапка общая, поэтому ячейку надо проставить во всех
строках маршрутов P/01, P/02, P/03 (80 строк), как P01.256 делала для `role`. Прошу то же разрешение: правка
чужих строк только этими двумя столбцами.

**В2. Значения `rights`.** Предлагаю столбец `rights`: `<путь файла от корня>` | `derived:<deployment>` (команда
вывода прав по манифестам стенда формы (4), `{deployment}` — это слово) | `none` (стенд без файла прав) | `-`
(у цели нет стенда со store). Значения по прозе:

| Цель | rights | Источник |
|---|---|---|
| P/01.1/door, extra, inproc | `Platform/01-store/acceptance/1/inputs/rights.json` | stand.md:78, «Role sockets» |
| P/01.2/rights, P/01.3/daemon, P/01.3/group | `Platform/01-store/acceptance/2/inputs/rights.json` | stand.md:78; 01/2 README:11; 01/3 README:22 |

Противоречие P/03.2–P/03.4: README глав 03/2:28, 03/3:21, 03/4:18 — «the store without a rights file … full rights
on `testsub/` and `testsub2/`» (`none`); stand.md:78 — у приёмок, чей стенд ставит манифесты, файл выводится
(`derived:dep`); P01.256 по решению 10:11 поставила им `role` = `console`, а без файла прав сокета `console.sock`
нет (stand.md «Role sockets»: без файла ждётся только `admin.sock`). Рекомендую `derived:dep` для всех четырёх
целей P/03 — тогда `role` P01.256 верна; строку README глав P/03 «without a rights file» поправит писатель P/03.
Иначе — `none`, и тогда `role` этих целей должна стать `-`/admin, что противоречит решению 10:11.

**В3. Потребности групп production (п. 6, S4/P4).** Сейчас у 17 групп `inputs: []`, а шапка отсылает к ячейке
таблицы «Case groups» (и называет «третий столбец», хотя наблюдатели стоят в четвёртом, «Binding and negative
