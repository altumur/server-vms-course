# Запрос: просьба → строка единицы адресата

**Что мешает.** Действие `elsewhere` жнец не исполняет и не метит: «действия (action), которые исполняет другой процесс
(жнец их не трогает)» (`Platform/common/contracts/request-mark.md:64`, `:114`, `:124`); исполнителя норма не называет.
Писать строки единиц воркеру нельзя (P/02.5 Н1.4: `worker.writes` = `unit.rows` запрещён), контроллеру — только
размещение и удаление (P/04 Н1.3), консоль проходов подсистем не крутит (ADR-0002). Метка `performed` требует
`instance`, `slot`, запрещает `ended_by` (P/06.4:174); `ended_by` — только `reaper | holder` (`request-mark.md:85`).
В профиле дозаписи `requests.outcome: fetched` тело с `action` из `elsewhere` — тоже дозапись (P/03.6:103–105).

**Что нужно VMS** (сегодня делал снимаемый `vmsjobs` ролью `console`): `record` → строка `rec/recordings/<cam>-auto
{until}`, повтор продлевает (М10B/25:436–512); `detect` → `det/units/<cam>-<kind>-auto`; `scan` → задача `detjob`
или расширение идущей по той же записи и модели (М10B/25:539–550, М10B/21:58). Правила над чужими строками: основа —
настройки детектора оператора на той же камере и модели, `params` заявки поверх, `mask` и `labels` наследуются; второй
детектор на камеру, которую уже смотрит ручной без конца, не заводится; скан камеры, которую никто не пишет, — отказ;
удалённую оператором строку повтор не возрождает (М10B/22:138–146). Исход — в метку просьбы; отказ — с причиной.
`scan_what_arrived` (М10B/22): окно `closed` пульса `rec` → задачи по каждому детектору камеры.

**Рекомендация «Архитектора»** (к ревью):
1. Исполнитель — воркер подсистемы-адресата (`<sub>worker`), держатель просьбы `elsewhere`. Объявление манифеста
   `worker.makes: [{rows: <таблица единиц>, id: "<шаблон>"}]`: запись и удаление строк единиц своей подсистемы **только
   дверью консоли** (`PUT`/`DELETE /<sub>/<rows>/<id>` — схема, `must_match`, `fixed`, `ref`, CAS) и **только id по
   шаблону** (`<cam>-auto` и т. п.) — один писатель на строку сохраняется: строки оператора исполнитель не пишет.
   Права P/02.5 выводятся из объявления.
2. Метка исхода — обычная `performed`/`refused` держателя: у воркера есть `instance`, `slot`; `ended_by` не нужен.
   Причины `refused` — словами манифеста адресата.
3. Правила над чужими строками и надгробие — код исполнителя: читает, что его роли можно читать; надгробие — в его
   собственной таблице (`worker.writes`).
4. `record` разводится с профилем дозаписи: действие `elsewhere` в профиле `outcome: fetched` — дозапись только при теле
   дозаписи (`unit`, `from`, `to`); иное тело — исполнителю `elsewhere` (правка P/03.6:103–105).
5. `scan_what_arrived` — два пути, выбор при переводе: `rec` подаёт просьбу `scan` на привезённый диапазон
   (`worker.requests: [det]` у `rec`, абсолютный диапазон в схеме `scan`), либо исполнитель `detjob` читает окно `closed`
   пульса `rec` сам (чтение пульса чужой подсистемы — есть ли право; если нет — часть этого запроса).

**Обход до решения.** Шаги уроков, зависящие от ответа, не нормируются; у продукта — `vms-jobs` строкой долга «Сборке».
