Все три подтверждают каркас:
- `none` только в строках ролей;
- прямая группа складывается, как сегодня;
- в группе роли — первый непустой ярус, внутри яруса наибольшее;
- между группами — наибольшее;
- одно приращение с ADR-0097 и ADR-0098 закрывает старого читателя.

Порядок ярусов однозначен, монотонность между группами доказуема (у Codex — 48 проверок). Находки касаются трёх мест:
перевода consolem (точка `*`, максимум уровней, общая подсистема `rec`), нечитаемых входов группы роли и записей, которые
выводят единицу из-под строки роли.

Совпадения между отчётами:
- корень домена и умолчание пишут в одну `*`, наибольшее отменяет понижение корнем — Codex 2, Kimi Б1, Claude Б-3 (а);
  все три — блокер;
- пропуск или нечитаемое внутри группы роли открывают более общий ярус — Codex 3 (строка не по форме), Codex 4 (метки и
  about), Claude Б-1 (все три ветки), Kimi М3 (звенья цепочки); вход `may` должен отличать «нет» от «неизвестно» —
  Codex вопрос 2;
- ответ при нечитаемом — Claude С-4 (403 против 503 ADR-0098 §4); Kimi принимает «не 503»;
- §4 о доставке ключей книги пуст — Claude М-1, Kimi М2;
- ничья `none` и положительной строки в одном ярусе — Kimi М1, вопрос 1; Claude («Что держится») и контроль Codex
  `same_tier_max` считают её `view`;
- соответствие consolem — Codex 1 (максимум уровней не переводится), Kimi С1 (прототип 11), Claude Б-3 (точка `*`).

**Смысл исключений решает владелец.** consolem выложили прототип 11 (их коммит `6bffe89`,
`index_11_isklyuchenie-vazhnee.html`). В нём исключение объекта из **любой** роли сильнее папок и умолчаний **всех**
ролей. ADR-0099 написан по `index.html` `9849d28`: исключение действует только внутри своей роли. «Консоль» рекомендует
прототип 11 (`cammeta-console` `deeeee9`). Ответа владельца нет. Поэтому разбор разделён:
- **(А)** — решения, которые нужны при любом смысле;
- **(Б)** — что меняет выбор смысла.

Файла прототипа 11 нет ни в одном локальном клоне (`Console`, `cammeta-console`). Смысл варианта 2 ниже взят из записи
«Консоли».

## (А) Решения «Архитектора», принятые до разбора

1. **Область `*` — одна точка** (Codex 2, Kimi Б1, Claude Б-3 (а)). По каждому полю вида значение точки `*` — значение
   корня домена (`folderAccess[<id домена>]`), если оно задано, иначе умолчание роли (`dCam`, …). Перевод не пишет двух
   строк одного яруса, чтобы взять из них наибольшее. Вектор V/11: `dCam = FULL` + корень `cam = ONLY_ARCHIVE` → на камере
   вне папок `ONLY_ARCHIVE` (`view cam`, `none live`, `view rec` на `*`). Уточнения разбора (приняты):
   - обратный вектор: `dCam = FORBID` + корень `cam = FULL` → `FULL` (Codex 2: «и обратный»);
   - **корень — звено каждой цепочки** (новое, в отчётах нет). У consolem `accGroups` кладёт корень первой строкой,
     `accChain` любой папки доходит до него. Поэтому значение корня участвует в «наибольшем из папок». Контрпример: корень
     `cam = ARCHIVE`, у папки `G` — `FORBID`, у `F` значения нет, камера 7 лежит в `F` и `G`. consolem: цепочка `F` дошла
     до корня (`ARCHIVE`), цепочка `G` дала `FORBID`, наибольшее — `ARCHIVE`. Перевод: корень ушёл в `*` (ярус 5), ярус 3
     — только `none folder:G`, итог — отказ. Это сужение, но «без потерь» нарушено. Правка перевода: если у корня задано
     значение поля, каждая папка первого уровня без своего значения получает строки корня. Папку первого уровня, созданную
     позже не через `backend`, перевод не знает. Её единицы сужаются до следующего перевода, но не расширяются;
   - экономия строк (Claude С-2 п. 1, Г8) не опускает строку папки, если её значение равно только `*`. Цепочка без строки
     `folder:` в ярус 3 ничего не даёт, поэтому наибольшее по цепочкам изменилось бы.
2. **Нечитаемое не расширяет** (Codex 3, 4; Claude Б-1, С-4; Kimi М3). Роль не опускается к менее точному ярусу, если
   его нельзя вычислить. Так бывает, когда нечитаема строка роли более точного яруса или нечитаемы `labels`, `about`,
   членство или звено цепочки, нужные для яруса. Тогда группа этой роли даёт «нечитаемо», а не результат `*`. Пропускать
   повреждённую ограничивающую строку запрещено. Уточнения разбора (приняты):
   - **перечень входов**: членство (`memberof`), звенья цепочки и их живость (Kimi М3); строка единицы — её `about` и
     метки (Codex 4, Claude Б-1 (б)); строка роли не по форме (Codex 3, Claude Б-1 (а));
   - **строка не по форме — разбор в две ступени** (Claude). Строка с субъектом `role:R` нечитаема → группа `R`
     «нечитаема». Если `sub` строки прочёлся — только в этой `sub`. Субъект не прочёлся → «нечитаемы» все группы ролей
     документа. Прямая группа не затронута: пропуск в ней только сужает, правило P/08.4 Н1.3 «пропускается» остаётся для
     неё. Признак неполноты передаётся в `may`, при фильтрации до `may` он не теряется (Codex 3);
   - **итог**: хоть одна группа разрешает → allow. Иначе 503 `unavailable`, если есть «нечитаемая» группа, которая могла
     бы разрешить: в ярусах, которые она смотрела бы, есть её строка с рангом не ниже `cap` (Claude С-4). Иначе 403.
     В списках — `withheld`, как метки в P/06.4. Это то же правило, что ADR-0098 §4 (разбор Г7) и «Нечитаемая строка»
     договора сторожевой. §2 ADR «группа не даёт ничего (не 503)» заменяется. Расхождение двух ADR (Claude С-4, вопрос 2)
     закрыто;
   - **вход `may` различает «нет» и «неизвестно»** (Codex вопрос 2): `about` нет или неизвестен; метки `[]` или
     неизвестны; цепочки `[]` или неизвестны. Подсказка P/07 получает ту же неизвестность, а не пустые массивы;
   - **цена** (Codex 4): «Ярус 1–2 — без чтений» неверно. Ярус 1 — без чтений. Ярусу 2 и ярусу 4 нужна строка единицы,
     если `about` и метки не пришли в запросе (как ADR-0097 §5). §3 править;
   - **стражи**: подтверждённое отсутствие строки членства тоже сторожится стражем отсутствующей строки (Codex,
     «Остальная проверка»);
   - Confirmation: роль `admin *` + `none unit:cam/7` с испорченным `until` у второй строки — 503, не allow; `edit *` +
     `none labels:private` при нечитаемой строке единицы — 503; `edit *` + `none unit:cam/7`, проверка `det/5` (about
     `cam/7`) при нечитаемой строке `det/5` — 503; `none folder:F` + `admin *` при нечитаемом предке в цепочке — 503;
     та же нечитаемость рядом с прямой строкой `admin *` — allow (прямая группа независима); у роли нет строки с рангом
     не ниже `cap` — 403.
3. **Перевод уровней consolem без потери максимума** (Codex 1, вопрос 1). Перевод в строки по `sub` должен давать тот же
   итог, что `accRoleLevel` и `accEffIn`, на всех парах уровней. Проверка — вектором по модели Codex. Что из модели
   следует:
   - перевод ADR-0097 §7: `FORBID` (0,0,0), `ONLY_ARCHIVE` (1,0,1), `MON` (1,1,0), `ARCHIVE` (1,1,1), `ARCH_MANAGE` (1,1,2),
     `FULL` (2,1,2) по `(cam, live, rec)`. Из 36 упорядоченных пар расходятся две, обе — пара **{`MON`, `ONLY_ARCHIVE`}**.
     consolem даёт `MON` (без архива), платформа — (1,1,1), то есть `ARCHIVE`. Остальные уровни образуют цепь, и для них
     T(max) = max(T): отдельный ранг не нужен;
   - `MON_PROT` («Просмотр на охране») в таблице ADR-0097 §7 нет. Если V/11 его переведёт как `MON`, пара с
     `ONLY_ARCHIVE` добавится. Вектор — по всем переводимым уровням (49 пар при семи);
   - **отдельный ранг** (поле порядка у строк роли: в ярусе побеждает точка с наибольшим уровнем consolem, затем её `cap`)
     чинит пару только внутри роли. Между ролями максимум по каждой `sub` остаётся: на нём держится монотонность и
     правило «между ролями — наибольшее». Поэтому ранг не вводить;
   - **`NOT_SUPPORTED` для сочетания.** `backend` проверяет итоговое состояние пакета `/access/apply` (роли, назначения,
     группы) до записи, как инвариант `unr`. Отказ — где наибольшее может встретить `MON` и `ONLY_ARCHIVE` одного поля
     на одной единице:
     - внутри роли — две папки с `MON` и `ONLY_ARCHIVE` (состав папок меняется позже, поэтому любые две папки роли);
     - между ролями одного человека (прямо или через группы, действующие назначения) — одна роль даёт `MON`, другая
       `ONLY_ARCHIVE` в любой точке. Исключение — две разные точки `unit:`: они одну единицу не покрывают;
   - **«Запрос продукту» п. 2**: `MON` ∨ `ONLY_ARCHIVE` = `MON` (добавление роли с живым видео убирает архив) — замысел
     или следствие линейного списка уровней? Если продукт ответит «объединение» (`ARCHIVE`), перевод станет гомоморфным и
     `NOT_SUPPORTED` снимается;
   - Confirmation V/11: для каждой упорядоченной пары переводимых уровней `(a, b)` T(max_consolem(a, b)) = max(T(a),
     T(b)) или пара в списке `NOT_SUPPORTED`. Пара проверяется дважды: две папки одной роли и две роли одного человека.
     Плюс вектор решения 1.

**Г8. Цена: перевод и отсечка** (Claude С-2). Принять обе правки, первую с поправкой:
- перевод не пишет строку точки `F` для `sub`, если она равна строке ближайшего предка-папки с заданным значением.
  Поправка: «или `*`, если предка нет» не принимается (решение 1, последний пункт). С переносом корня в папки первого
  уровня (решение 1) у цепочки всегда есть предок со строкой, если корень задан;
- отсечка в `may` (Claude п. 2): все строки `folder:` группы в `sub` с рангом не ниже `cap`, и ярус 4–5 разрешает —
  allow без чтения; все ниже `cap`, и ярус 4–5 не разрешает — deny без чтения. Чтения нет — нет ни стража, ни
  «нечитаемо» (решение 2). Правило §3 «разрешил ярус 4–5 при прочитанном членстве» остаётся там, где чтение нужно;
- число строк роли сверить с пределом документа `domain/grants/<кластер>` (норма; число — без замера не предлагать).

**Г9. Быстрый путь `/events`** (Claude С-3). Принять. Быстрый путь у группы роли — только если у неё нет строк точнее `*`
ни в одной подсистеме и нет строк `none`. «В этой `sub`» для запроса событий всех подсистем не определено.

**Г10. Функции и создание** (Claude С-5). Принять. Временное правило §5 («функция только там, где уровень даёт хоть что-то»)
оставить: оно сужает, а значит безопасно. Назвать в Consequences, что `DEVICES_SETUP` при `dCam = FORBID` не создаёт камеру
вне папок. В «Запрос продукту» п. 1 добавить случай создания.

**Г11. §4 о книгах** (Claude М-1, Kimi М2). Принять: «доставка ключей книги и индекс имён не меняются: строк ролей, а
значит и `none`, они не читают (ADR-0098 §4)». `grant too wide` — так же.

**Г12. Ничья в ярусе** (Kimi М1, вопрос 1). Принять «в ярусе — наибольшее»: `none` и `view` одной `(sub, scope)` в одной
роли дают `view`. Довод — смысл consolem:
- у consolem в одной точке одно значение поля, поэтому перевод такой ничьей не порождает;
- наибольшее в ярусе consolem берёт там, где ничья у него есть, — между папками объекта (ярус 3: `none folder:F` и
  `view folder:G` → `view`). Правило «`none` сильнее» пришлось бы отделять для одной области от одного яруса — лишнее
  правило без потребителя;
- 400 у двери на такую пару не вводить: форма строки и правило повторов P/08.4 Н1.3 остаются прежними.

§1 «действует только как самая точная строка своей группы» переписать: «`none` действует, когда его ярус — первый
непустой; в ярусе — наибольшее». Вектор `may`: `none` и `view` одной `(sub, scope)` в роли — allow.

**Г13. Неограниченная роль** (Claude М-5). Принять. Роль неограниченная (`unr`), если её единственная действующая строка —
`admin *` без `sub`. Роль, где рядом с `admin *` написаны и другие строки (руками), не `unr`. Правку внести в ADR-0099 и
в инвариант `unr` у `backend` (ADR-0098 §5, разбор решение 2). Нужно при любом смысле, а в варианте 2 раздела (Б) правило
«`unr` сильнее всего» опирается прямо на это определение.

**Г14. Мелкие** — принять:
- `unit = null` при `cap > view` покрывает только ярус 5, как `"*"` (Claude М-2);
- выбор папки в цепочке — по строкам, отобранным шагом 5 (субъект, срок, `sub`), без учёта ранга. Папка только с
  истёкшими строками пропускается (Claude М-3);
- §6 п. 3: P/07 получает цепочки и группы, а не набор `folders` (Claude М-6);
- в Confirmation назвать вход каждого вектора — форму `unit` и `sub`. Пример: живое видео камеры 7 —
  `unit = {sub: cam, id: 7}`, `sub: live`, ярус 1 (Kimi М4).

## Вопросы, которые решает «Архитектор»

**А1. Снятие из папки и удаление папки расширяют права** (Г4: Claude Б-2). Сегодня снять `U` из `G` можно по `admin` на
`G` без права на `U` (ADR-0097 §6: «снятие только сужает»). С `none` в ролях это неверно: администратор папки
«Секретно», у которого роль даёт `admin sub: cam *` и `none sub: cam folder:Секретно`, снимает камеру 7 из папки и
получает `admin` на неё. Удаление папки (ADR-0096 §3 — атомарно, с поддеревом) делает то же сразу для всех её членов.
Варианты:
- (а) **снятие требует права на единицу.** Снять `U` из `G` (и перенести из `G`) — ещё `admin` на `U` в её подсистеме по
  составу до записи, как при добавлении. Удаление папки, на которую или на потомка которой в копии грантов есть строка
  роли `folder:`, — `admin` на `*` в каждой `sub` таких строк. Обходить членов поддерева не нужно. Без строк ролей на
  поддереве — как сегодня;
- (б) **политика владельца** «администратор папки снимает и запреты на её членов». ADR-0099 сейчас принимает её молча.
  Но это переход из `sub: platform` в любую подсистему — то самое «`edit` в одной подсистеме → `admin` во всех», от
  которого ADR-0097 §6 закрывал добавление.

Рекомендация: (а). ADR-0097 §6 «снятие только сужает» — пометить «заменяется ADR-0099». В переводе consolem ведение
папок до ответа продукта есть только у `unr` (ADR-0097 §7), поэтому на пути `backend` (а) ничего не стоит. Confirmation:
снятие из папки с `none` без права на единицу — 403; удаление такой папки по `admin folder:G` — 403.

**А2. `labels:` в строках ролей** (Г5: Claude М-4, вопрос 5). Ярус 4 даёт две из найденных дыр: метки нечитаемы
(решение 2 их закрывает) и снятие метки с about-единицы открывает чужую подсистему (ветка «метки» Claude Б-2; для неё
нужно было бы правило, как А1, по всем подсистемам с `labels:`). consolem меток не знает, перевод `labels:` не пишет.
Строка `folder:` молча закрывает метку той же группы, даже когда метка уже папки. Варианты:
- (а) запретить `labels:` в строках ролей — 400 bad line у двери, пока не появится потребитель. Ярусов четыре;
- (б) оставить и дополнить А1 правом на каждую подсистему, где у роли есть `labels:` с этой меткой, при снятии метки.

Рекомендация: (а). Запрет потом снимается без поломки (новая форма строки ролей). (б) — правило без потребителя.

**А3. События с `of`** (Г6: Claude С-1, вопрос 4). P/06.4: строка события видна по гранту на её `unit` **или** на `of`.
Роль `view sub: auto *` + `none sub: auto unit:cam/7`: событие сценария `auto/s1` с `of cam/7` видно через сторону
`unit`, исключение на `of` ничего не прячет. Варианты:
- (а) стороны независимы, как сегодня. Исключение на `of` прячет только события, где разрешение даёт лишь сторона `of`;
- (б) у группы роли решает `of`, если он есть — как P/06.4 уже делает для меток. Прямая группа — как сегодня.

Рекомендация: (б). Исключение объекта в consolem прячет объект целиком, его события тоже. У прямой группы ничего не
меняется, монотонность между группами сохраняется: каждая группа считает сама, между ними — «или». Векторы — в P/06.4.

**А4. Архив и записи камер в одной `rec`; хранилище как ключ `objectAccess`** (Г7: Claude Б-3 (б), вопрос 3; Kimi
вопросы 2, 4). Сначала ответы на вопросы:
- **чем охраняется `rec/volumes`** (Claude вопрос 3; Kimi вопрос 4). Манифест `rec`: `rights.unit_of: {keeps: cam}`, у
  тома единицы нет («a volume declared by an administrator (`admin`, the default)»). Проверка тома идёт с `unit = null`,
  а её покрывает только `*` (договор `may` шаг 7). Поэтому строка `unit:rec/<id>` хранилища ничего не покрывает:
  `objectAccess` хранилища в `unit:` не переводится;
- **наследование через `about`** (Kimi вопрос 4). Записи (`rec/recordings`) — единицы с `about: cam`. Они наследуют
  папки камеры, и это совпадает с consolem: архив камеры у consolem даёт уровень `cam` камеры, а его consolem считает
  по папкам камеры. Хранилище (том) у consolem в папках не лежит (`ACC_NOFOLDER`), у платформы у тома нет единицы, а
  значит и папок. Расхождения нет;
- **поля в одну подсистему** (Kimi вопрос 2). `mic` и прочие устройства, кроме камер, не переводятся (V/11.3, «нет»),
  поэтому пары `cam` и `mic` нет. Настоящая пара — `arch` (хранилище → `rec/volumes`) и `cam` (записи → `rec`). «Наибольший
  ранг по всем полям» в точке `*` даёт неосознанное расширение: `dArch: FULL` при `dCam: MON` открывает записи всех
  камер (Claude Б-3 (б)). Функции и уровень в одной подсистеме (`DEVICES_SETUP` и `cam`) — другой случай, это «Запрос
  продукту» п. 1.

Варианты для `arch`:
- (а) поле `arch` (умолчание `dArch` и исключения хранилищ) переводится, только если в `rec` на `*` оно даёт не больше,
  чем уровень `cam` в точке `*`. Иначе — `NOT_SUPPORTED` у `/access/apply`. Что даёт `arch: FULL` в `rec`
  (`view`/`edit`/`admin` на `*`), задаёт V/11 — вопрос «Спецификации VMS»;
- (б) единица у тома в манифесте `rec`. Права хранилищ тогда отделяются от записей камер. Но это правка канона V/02 ради
  перевода, и `ARCHIVES_SETUP` (`admin rec`) её тоже коснётся;
- (в) `arch` не переводить вовсе (скрыть, как `tel`).

Рекомендация: (а). Ни одна роль consolem не получает больше, чем задумано. Частые роли, у которых `dArch` не выше
`cam`, переводятся. (б) — отдельный ADR, если (а) окажется частым отказом. Confirmation V/11: `dCam: MON`, `dArch: FULL`
— `NOT_SUPPORTED` (или ранг по V/11 не выше `cam`).

## (Б) Что меняет выбор смысла — ждёт владельца

Владелец выбирает, что считать смыслом consolem: `index.html` `9849d28`, по которому написан ADR (вариант 1), или
прототип 11 `6bffe89` (вариант 2). «Консоль» рекомендует вариант 2. Разбор рекомендации сверх этого не даёт. Решения 1–3 и
А1–А4 нужны при обоих вариантах.

**Вариант 1 — «исключение внутри своей роли» (ADR-0099 как есть).**
- `may`: группы — прямая и по одной на роль. Группа роли берёт первый непустой ярус (`unit:` → about → ближайшая папка →
  [`labels:`] → `*`), в ярусе — наибольшее. Итог — прямая группа разрешает **или** хоть одна группа роли даёт не ниже
  `cap`. `unr` выигрывает сам: его группа — `admin *`;
- закрывает: Kimi С1 после записи; Codex вопрос 1 частью — монотонность ролей сохраняется (добавить роль не сужает);
- остаётся: Codex 1 (решение 3); пример §2 и векторы — как есть. Пример Kimi С1: «Оператор» `none unit:cam/7 sub: live`
  + «Охрана» `view folder:Склад sub: live` → allow. «Итоговый доступ» прототипа 11 покажет здесь отказ — интерфейс и
  сервер разойдутся, если consolem выпустит прототип 11.

**Вариант 2 — «исключение объекта сильнее папок и умолчаний всех ролей» (прототип 11).**
- `may`, по проверке `(cap, unit, sub)`:
  1. неограниченная роль (Г13) → allow;
  2. ярус исключений по **всем** группам ролей: есть строки `unit:` (ярусы 1–2) хоть в одной роли → итог ролей —
     наибольшее из них по всем ролям, папки и `*` всех ролей не смотрятся;
  3. иначе — каждая роль по своим ярусам 3–5, между ролями — наибольшее;
  4. прямая группа не трогается: итог — она **или** итог ролей.
- надо решить дополнительно: ярус 1 и ярус 2 между ролями — единица своя в одной роли, about в другой (рекомендация
  разбора: первый непустой из 1–2 по всем ролям, как внутри роли);
- закрывает: Kimi С1 (смысл совпадёт с прототипом 11, а с ним и «Итоговый доступ»). У роли с исключением решение
  принимается без членства: чтений и стражей меньше;
- открывает:
  - монотонность ролей теряется: добавить роль с исключением может сузить права. Из Consequences убрать «Good, because
    … добавить роль никогда не сужает права»; контроль Codex `second_role_can_override_none` меняет знак; пример §2 и
    вектор «другая роль с `view unit:cam/7`» пересчитать (два исключения → наибольшее → allow);
  - решение 2 расширяется на **все** группы ролей. Нечитаемая строка `unit:` любой роли, нечитаемое назначение роли или
    `about` единицы делают «нечитаемым» итог ролей целиком, не одной группы: исключение пропавшей роли сняло бы его со
    всех остальных. ADR-0098 §4 (таблица нечитаема → прямые строки или 503) совместим;
  - срок назначения роли с исключением, наступив, поднимает права по другим ролям (как истёкший `none`, Neutral);
  - подсказка P/07 считает по строкам `unit:` всех ролей (в `/session` они есть);
- Codex 1 (решение 3) остаётся и в варианте 2: наибольшее между исключениями разных ролей встречает ту же пару
  {`MON`, `ONLY_ARCHIVE`}. А3 (события `of`) в варианте 2 ещё важнее: исключение одной роли должно прятать события
  объекта и от других ролей.

Правка ADR по любому варианту: Context, Decision Drivers, пример §2, Confirmation и Consequences называют, какой файл
consolem — эталон (коммит), и смысл между ролями.
