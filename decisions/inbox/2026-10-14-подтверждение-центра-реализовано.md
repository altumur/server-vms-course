# Привязка сохранённого подтверждения к центру — выполнено

Решение 2d6076ee и уточнение ADR-0074 2860fdda выполнены отдельным
окном после C3. Проверенная ветка `codex/course-upstream-kept`,
**af05c8739bf31c15d76107b6dbf9a7a2fee5e19d**; отдельное слияние
**16553c69ec27a161318c2ecd23ba258e57959951**.
C3 до этого слит по Вашему разрешению, **bf8fa4a0**.

Только три файла: VMS `domainpart/chain.py`, новый `test_upstream_kept.py`,
перенос двух fixture/ожиданий формы в `domainvms/test_lesson17_chain.py`.
Платформа, спеки, общие таблицы, новые уроки и приёмка не менялись.
Продукт и его ведомость не читались и не менялись; только штатная
автоматическая сверка спек. Строки долга нет по Вашему явному решению:
локальный формат реализации, ADR-0080 доп.3.

- Пишется только `{v:2,centre,heard,have?}` после ответа подтверждённого
  текущего центра; новая идентичность записывается сразу, независимо
  от обычной минутной выдержки повторного сохранения.
- Восстановление сверяет центр с текущим подтверждённым маршрутом,
  топологией и назначением; отложенное чтение повторно проверяет scope.
  При другом центре, снятом назначении/polls и неподтверждённой топологии
  старый have не выдаётся. Изменение URL того же центра допустимо.
- v1 и другие формы отвергаются без decoder/адаптера; неизвестные поля,
  неверные версии/типы, отрицательный have и истёкшие записи не принимаются.
- Ошибки чтения/сохранения/удаления повторяются. Неудачная запись не
  отмечается сохранённой, неудачное удаление — прочитанным навсегда.
  Истечение продолжает считаться один раз после успешного удаления.

Проверки по коду возврата: целевой unit **58/0/0**, затем окончательные
восемь новых регрессий **8/0/0**; Cluster policies/stand **22/0/0**;
полный Domain **228/0/0**, полный DomainVMS **164/0/0**, каждый exit 0.
Семь первоначальных регрессий до runtime-исправления **0/7**, exit 1.

Первый общий core 56/2 был красным из-за отсутствующего OBSD_BIN и
ошибки setup удаления строки без роли; окружение и setup исправлены,
красный лог не считается зелёным. Полный unit 1887/0/0 относится к C3,
а не к этому узкому окну; здесь выполнены перечисленные целевые проверки.
