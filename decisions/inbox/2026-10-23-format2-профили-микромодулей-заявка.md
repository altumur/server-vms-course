## Просьба

При обновлении `Platform/common/acceptance/README.md` прошу описать раскладку по процессам и сослаться на
опубликованный профильный контракт раннера. Сценарии и ожидания этим не меняются.

1. **Один профиль на микромодуль.** `acceptance.yaml` внутри каталога модуля, `module` — идентификатор из
   `Platform/lessons.tsv`; собственные `build`, необязательный `unit`, свои `stand`, `keys`, `adapters`,
   публичные результаты сборки `artifacts`. Поля `format: 2`, `implementation`, `spec_version` и правила формы —
   в новом разделе README раннера. Профиль не называет команды соседних процессов.
2. **Состав стенда.** Корневой `assembly.yaml` (`format: 1`, `modules`) — только карта модуль → файл профиля,
   без корневых команд и монолитной сборки. Стенд берёт соседей из явного состава; замена `--part` переносит
   целиком профиль части, её cwd, ключи и команды. Отсутствие нужной части — ошибка состава до запуска.
3. **Рабочие каталоги и фазы.** Команды исполняются из каталога собственного профиля. Сборка — отдельно до
   фиксации SHA; во время приёмки пересборки нет. Исходные профили, исходники и артефакты частей фиксируются
   в паспорте; совпадающие имена алгоритмов у разных потребителей не схлопываются в один ключ.
4. **Словарь стенда сохраняется.** Значения `PLATFORM_DIR`, сокетов ролей, портов, прав, кольца и общего
   `agent_tokens` выдаёт стенд по опубликованным lifecycle/договорам. Новые метаданные профиля не являются
   переменными окружения процессов, HTTP-дверями или дополнительным способом связи между модулями.
   Подстановки стадии C — `{manifest}`, `{manifests}`, команда — `manifest-put`; переименование остальных
   мест — по `manifest-rename.tsv`, без изменения слов о спецификации (`SPEC_VERSION`, `CAMMETA_SPECS`, `spec/`).
5. **Библиотеки.** P/03 — свой SDK и тестовый worker через команду профиля. P/07 — упаковка опубликованных
   `console.*`, без отдельного HTTP-процесса/TSV-приёмки; сборки 06/10 включают байты до фиксации входов,
   процесс не читает каталог выгрузки во время работы (lifecycle P/06). P/09.2 — режим агента того же модуля 09.
6. **Алгоритмы и адаптеры.** Профиль называет исполняемые обёртки собственных функций по опубликованным пакетам.
   Совпадающие Said/fresh-age и общие договоры сохраняют принадлежность потребителю. У новых `creates-key` и
   `near-of` раннер публикует передачу JSON-входа файлом `{input}` и сырой UTF-8 id в stdout без лишнего LF;
   отсутствие соседа — пустой stdout. Если эту форму следует назвать в README пакетов, прошу внести её там;
   байты векторов и смысл ожиданий не меняются.
