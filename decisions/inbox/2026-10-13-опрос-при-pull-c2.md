# C2: опрос назначенной камеры, которую рекордер забирает по RTSP

## Контекст
Утверждённый primaries.ingest отсутствует, когда push не просится.
Пушер курса теперь получает адреса только из таких наблюдений.
До C4 отдельная книга polls осталась у domainpart, но её издатель
обходит только unrecorded: назначенная камера туда не попадает.
Если источник с polls:true доступен по RTSP и первичный рекордер
не просит push, у камеры нет ни C2-адреса, ни polls-адреса: она
не опрашивает приёмник для asks и запросов диапазона карты. Карту
{ref:cluster} уже читаем из назначения. Нужна точная форма промежутка
C2→C4, не новое поле поверх ingest и не прежняя книга primaries.

## Рекомендация
До C4 публиковать в существующую polls также назначенные камеры с
опросом: цель — cluster назначения (либо центр звезды по текущему
правилу), затем poll_home для неназначенных. Форма старого polls
не меняется, stream.aud уже [cluster] по согласованному решению;
пушер опрашивает этот отдельный адрес для команд/диапазонов, когда
C2-ингестов нет. Новую передачу кадров он начинает только по
подтверждённому C2-наблюдению push/ingest, polls-путь для назначенной
RTSP-камеры не становится запасным источником управляющего решения.
Если продукт допускает здесь разрыв до C4 или уже сделал другой
мост, закрепить его; курс повторит. Новых имён на проводе не предлагаю.
