# Запрос: доступ воркера подсистемы к доле своей части

**Какая норма мешает.**
- P/02.1 Н1.4, `references.tsv` строка 91: `worker.uses[]` — `split(. "." 0) != @name`; доля своей подсистемы — отказ
  загрузчика (случай приёмки `a91_uses_self`, `refused`). Н1.2а: «`worker.uses[]` — `<подсистема>.<доля>` **другой**
  подсистемы».
- P/02.1 Н1.2а `shares.<имя>` — отображение `{kind}`: принадлежность доли части выразить нечем.
- P/02.4 Н1.1 (`02.4-installer.norms.md:71–73`, `users_groups`, `dirs`): «группы долей `worker.uses` … (доля части —
  группа пользователя части, иначе `<dep>-<A>-<доля>`)»; «у доли части отдельной группы нет — её группа — группа
  пользователя части»; каталог доли `/run/<dep>-<sub>-<доля>` `2750 <владелец>:<группа доли>`, «владелец — пользователь
  подсистемы или части». Правило «доля части» названо, но ни манифест, ни загрузчик не знают, какая доля — доля части, и
  потребитель такой доли — свой воркер — объявить её не может.

**Что нужно VMS.** Регистратор (`rec`, юнит `vms-recworker@`, пользователь `vms-rec`) говорит с движком архива —
частью `rec.parts.obsd` (служба `vms-rec-obsd.service`, пользователь и группа `vms-rec-obsd`, ADR-0091 п. 5) — через её
сокет. Свидетель: `obsd.service` с `RuntimeDirectory=vms-obsd`, сокет `/run/vms-obsd/obsd.sock` `0660 vms-obsd:vms-obsd`;
`vms-recworker` — `SupplementaryGroups=… vms-obsd` (`Source/deploy/obsd.service`, `recworker@.container`; М10B/06
шаг 1, М10B/17 шаг 5). По нормам `afb1c88` юнит `vms-recworker@` группы `vms-rec-obsd` не получает: своей доли в
`worker.uses` нет, а `shares` не говорит, что доля — часть. Регистратор к движку не подключится.

Попутно: если долю части назвать именем части (`shares.obsd`), каталог доли `/run/vms-rec-obsd` совпадает по строке с
именем пользователя и группы части `vms-rec-obsd`; правило `names` P/02.4 («совпадение двух любых» имён ОС и путей) не
говорит, сравниваются ли путь и имя.

**Пример из VMS.**
```yaml
# VMS/02-rec/rec.subsystem.yaml (будущее)
parts:  {obsd: {exec: "/usr/local/bin/obsd --socket /run/vms-rec-obsd/obsd.sock", volumes: true}}
shares: {obsd: {kind: socket}}        # чья доля — подсистемы или части obsd? сказать нечем
worker: {uses: [rec.obsd]}            # отказ: строка 91
```

**Обход до решения.** Урок 02-rec нормирует движок как часть и контракт сокета, доступ регистратора к сокету — ссылкой
на этот запрос, строкой долга в ХОД; приёмка доступа ждёт решения.

**Рекомендация.**
1. `shares.<имя>: {kind, part?: <часть>}` — `part` называет часть из `parts` той же подсистемы (иначе отказ
   загрузчика); доля с `part` — доля части: владелец каталога и сокета — пользователь части, группа — группа части
   (как уже сказано в P/02.4), своей группы `<dep>-<sub>-<доля>` у неё нет.
2. Строка 91 — `split(. "." 0) != @name` **или** доля `<имя>` объявлена с `part`: свой воркер объявляет доступ к своей
   части так же, как чужой (`worker.uses: [rec.obsd]`), и получает группу части в `SupplementaryGroups`. Доля своей
   подсистемы без `part` — по-прежнему отказ (своему воркеру она не нужна: каталог его же пользователя).
3. `names` P/02.4: путь каталога доли и имена пользователей и групп — разные пространства; совпадение строки
   `/run/<dep>-<sub>-<доля>` с именем части не столкновение. Либо, если совпадения нужно избегать, — правило «имя доли
   части ≠ имени части» в загрузчике.
4. Приёмка: `a91_uses_self` остаётся отказом для доли без `part`; новый положительный случай — своя доля с `part`;
   отрицательный — `part`, не названная в `parts`.

## Решение
**Решён** (2026-10-23, «Архитектор»). ADR-0091 доп. (2) пп. 4, 5, доп. (3) пп. 3, 5: `shares.<имя>.part`, своя доля с `part` в `worker.uses`, каталог доли в `ReadWritePaths` производителя, каталог состояния части `0700`, путь и имя ОС — разные пространства. Нормы — «Спецификации» по ADR; выгрузка — «Архитектор».
