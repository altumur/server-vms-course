# Запрос VMS: ассистент правил, итог пилота

2026-11-02, «Спецификация VMS», ветка `vms/assist-rules`. Глава V/10.7, харнес `harness/rules/`, каталог `data/rule-catalog.json`, векторы `rules-words`. Работой не проверено: чтение и структурная проверка.

## Почему своя глава

Главы 3–6 нормируют панель, канон `cam.shell.html`, с планом `{unit, field}`. У правил другой план, инструменты и запись, ход в `backend`; общие только дверь модели и цикл.

## Вопросы

1. **Поле типа у `AssistTurnRequest`.** Контракт `kind` не несёт, из WebUI `rules` не вызвать. Рекомендация: запрос «Консоли», `kind: config | rules`, нет поля — `config`.
2. **Место правил в `AssistEvent`.** `plan` несёт `items` устройств. Рекомендация: `rules: [{table, op, id?, ref?, body}]` на словах контракта, «Применить» шлёт их клиент.
3. **Форма плана.** Сейчас строка V/07 с контрактными словами входа, перевод V/11.3 Н1.3. Обратной проверки нет; `RuleCreate`, `RuleWrite` требуют все поля, `owner`, `purpose`, `serverId`, `runAsRoleId` строка не несёт. Рекомендация: оставить строку, поля — умолчания перевода, сверить вектором перевода при повторном замере.
4. **`PATCH /rules/{id}` в контракте нет.** Есть `PUT /rules/{ruleId}`, `RuleWrite` целиком. В норме `PUT` с `If-Match`, тело из чтения поверх изменённых полей.
5. **Изменение действующего правила.** Слово «Архитектора» о `log_only` — про заведение; норма не заводит наблюдения при изменении, человек видит разницу. Рекомендация: оставить, выпавший шаг изменения тоже виден только глазами: предел.
6. **Повторный замер.** Правки после замера не мерены: `check_plan`, `active`, `normal`, снятие `detect`, `scan`, обзор в `user`. Рекомендация: поручить пилоту после вопросов 1, 2.
7. **Панель страницы.** Тип `rules` нормирован только в `backend`. Рекомендация: панель не трогать.

## Что не сошлось

- `system.md` пилота называл `det detect`, `det scan`; в каталоге их не было: сняты, отказ.
- `PATCH` в слове «Архитектора» и `PUT` в контракте: вопрос 4.
- `words.json` без пометки `_note`: байты пилота.

ADR-0112 доп. (8) п. 4 в поправленной редакции: `det detect`, `det scan` выражаются формой, этап 6; отказ — пока, до замера Пилота, а не предел формы. Слово сверки и системный текст те же, снимется с замером.

## Разбор ревью e870b1556 (Б 0, С 4, М 4)

С1 `server`, `domain`, `exclude` судятся словами. С2 `update` только у правил, хотя двери `PUT /schedules/{id}`, `PUT /maintenance-windows/{id}` в контракте есть: случаев замера нет; окно заводится `enabled: false`, `windows.rules`, `windows.schedule` судятся. С3 лишняя фраза снята, имя датчика судит строка входа. С4 `switched_on`, у `create` поля отбрасываются. М1 `words` судит строку как есть. М2 условия, нет ключа — ошибка, `run_at.days` — предел. М3 страница названа. М4 векторы дополнены. Вопрос 3 ревью: `logOnlySince` назван.
