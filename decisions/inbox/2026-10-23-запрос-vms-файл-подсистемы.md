# Запрос: путь файла настроек подсистемы (`W2C_SUB_ENV`)

**Какая норма мешает.**
- P/02.4 Н1.2 (`02.4-installer.norms.md:168`): «`W2C_SUB_ENV` — файл настроек подсистемы — путь задаётся юнитом; без
  значения файл не подключается — юнит». Строка юнита `<dep>-<sub>worker@.service` в Н1.1 (`:63–76`) значения
  `W2C_SUB_ENV` не называет; юнит части (`:77–81`) — тоже.
- P/02.4 Н1.1 `dirs`: `/data/platform/etc/subsystems/<sub>` `0750 root:<dep>-<sub>` — каталог настроек есть, имени файла
  нет. Каталог читает группа `<dep>-<sub>`; пользователь части `<dep>-<sub>-<часть>` в неё не входит (`users_groups`).

**Что нужно VMS.** ADR-0090 доп. (5) п. 3: общего файла окружения продукта нет, у каждой подсистемы — свой файл, юниту
подключается один файл подсистемы. Опись разнесла переменные свидетельского `vms.env` по подсистемам (`inventory.md`
§ 3): `cam` — `MEDIA_DIR`, `SHM_DIR`, `PLAYBACK_PORT`, `RTP_BASE`, `COMMANDS_BEAT`; `rec` — `ARCHIVE_*`, `OBSD_*`,
`BACKFILL_*`, `SEQUENCE_FLUSH_MS`, `BLOCK_FLUSH_S`; `detjob` — `VISIBLE_LAG_SECONDS`; `auto` — `LONG_POLL`; каждой —
`LOG_LEVEL`. Без нормы пути урок 09-deploy не может сказать оператору, куда их писать, а генерации — что ставить в
юнит; в описи части — та же нужда для окружения движка `obsd` (запрос `2026-10-23-запрос-vms-остановка-и-окружение-части.md`).

**Пример из VMS.** Свидетель: `EnvironmentFile=/etc/vms/vms.env` у всех юнитов (`Source/deploy/*.container`,
`cluster/systemd/*.service`), раннер — `VMS_ENV` (`cluster/w2c-run.sh`). После доп. (5): `rec` пишет `ARCHIVE_QUOTA_BYTES`
в «файл подсистемы `rec`» — какой?

**Обход до решения.** 09-deploy называет файл словами «файл настроек подсистемы (P/02.4 Н1.2 `W2C_SUB_ENV`)» без пути,
строкой долга; уроки 01-cam, 02-rec перечисляют свои переменные без пути файла.

**Рекомендация.**
1. P/02.4 Н1.1: юнит воркера `<dep>-<sub>worker@` и юнит части `<dep>-<sub>-<часть>` ставят
   `W2C_SUB_ENV=/etc/<sub>/<sub>.env` (через ссылку — `/data/platform/etc/subsystems/<sub>/<sub>.env`); файл
   необязателен (нет файла — умолчания подсистемы), грамматика — та же, что у `w2c.env` (Н1.2); порядок подключения —
   Н1.2 (файл подсистемы после `w2c.env` и `roles/<роль>.env` или до — как решит платформа, лишь бы одинаково у всех).
2. Права: файл `0640 root:<dep>-<sub>`; пользователь части читает его — либо членством части в группе `<dep>-<sub>`
   (`users_groups`), либо каталог `0750 root:<dep>-<sub>` с ACL — решает платформа; без этого юнит части окружения
   подсистемы не прочтёт.
3. Процессы платформы (`w2c-controller@<sub>` и др.) файл подсистемы не подключают (ADR-0030, P/02.4 `users_groups` rule).
4. macOS (launchd): тот же путь относительно `W2C_BOX` (как `w2c.env`).
5. Приёмка: строка юнита воркера и части с `W2C_SUB_ENV`; отсутствующий файл — старт с умолчаниями.
