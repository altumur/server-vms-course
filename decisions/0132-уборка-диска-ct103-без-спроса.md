# Диск CT 103: что удаляется без спроса, кто убирает и когда тревога

## Context and Problem Statement

Класс системы: инфраструктура разработки CT 103. 2026-11-08 корень заполнился до 99,6 %, работа стала зависеть от срочного вопроса В-32. По словам владельца, причины — кэши Go в рабочих каталогах задач (16 и 1,6 ГБ), вторые копии (архив проверок в `cammeta-diff` и распакованные `results` рядом с `.tar.gz`, 18,5 ГБ), незагружаемая модель gpt-oss (13,8 ГБ), временные копии раннера в `/tmp` (5 ГБ), выходы проб `acc/` (около 5 ГБ). Монитор сообщил только на 99,6 %, а любое удаление ждало слова владельца.

## Decision Drivers

* Диск не должен останавливать работу, и уборка не должна ждать владельца.
* Удаление необратимо: доказательства, квитанции и пины не должны попасть под правило.
* Активная работа не должна терять файлы.

## Considered Options

* Закрытый список того, что удаляется без спроса, с условием на каждую строку.
* Удаление самого старого при нехватке места.
* Каждое удаление по слову владельца, как было.

## Decision Outcome

Выбран закрытый список. Всё, чего в нём нет, без прямого слова владельца не удаляется, какого бы размера ни было.

1. **Удаляется без спроса** только то, на что есть строка `release` (п. 3), при всех общих условиях из п. 2. Строки ниже — кандидаты, а не исключения из п. 4.

   | Что | Дополнительное условие |
   |---|---|
   | содержимое кэша Go закрытой задачи (каталог `GOCACHE`) | каталог имеет раскладку кэша Go; файл вне этой раскладки — весь каталог пропускается и попадает в отчёт. Родитель остаётся |
   | `/tmp/runner-*`, `/tmp/contracts-*`, `/tmp/generators-*` | самое новое изменение внутри старше 24 ч |
   | распакованное рядом с архивом | хеш архива совпал с записанным в квитанции. Потоковое сравнение без новой распаковки в обе стороны: одно и то же множество относительных путей, типы, режимы, цели символических ссылок, байты. Абсолютный путь, `..`, дубль или жёсткая ссылка — пропуск. Архив остаётся |
   | выходы `acc/` закрытой пробы | закрытие подтверждено существующей итоговой квитанцией пробы; сохраняемый перечень (итоговый судья, квитанции, траектории) задаёт владелец раннера файлом. Пока перечня нет, правило не действует. Неизвестное в `acc/` остаётся, `work/` не трогается |

2. **Общие условия.** Абсолютный канонический путь, настоящий каталог без подмены родительских ссылок; обход без выхода за файловую систему; нет открытых файлов, cwd и отображений в памяти; ни одно дерево `hold` не пересекается с кандидатом ни как родитель, ни как потомок. Непосредственно перед удалением тождество каталога и `hold` проверяются заново. Сомнение или нарушение условия — пропуск и строка в отчёте.
3. **Учёт.** `cammeta-sessions/disk-policy.tsv`: `kind` (`release` или `hold`), `path`, `rule` (строка п. 1), `who`, `task`, `at_utc`. `release` — положительное заявление владельца задачи о точном пути: задача закрыта, путь не нужен. Отсутствие `hold` закрытием не считается. Для проб владельца `release` пишет владелец или его представитель. `hold` пишет владелец данных, он сильнее любого правила, `release` его не снимает. Сузить `hold` может только поставивший его: отдельной строкой, заменив широкий `hold` исчерпывающими точными. Сразу вносятся `hold` на `coord103/z9-out-on-demand` и на доказательные каталоги незакрытых задач. Пути с неизвестным владельцем только попадают в список; старые сироты идут владельцу одним списком на одно слово.
4. **Никогда без слова владельца:** квитанции, доказательства, пакеты, пины, источник, рабочие деревья, модели, `work/` кандидатов, рабочие данные владельца, где бы они ни лежали, в том числе внутри кандидата п. 1. Полное равенство архиву этого запрета не отменяет: для защищённой реплики нужен отдельный статус и сохранённый авторитетный экземпляр. Точечное решение по gpt-oss — вне этого ADR.
5. **Исполнение.** ops103, таймер. Первый проход только составляет список; удаление включается после приёма этого списка Архитектором и двух ревью ADR. Журнал: путь, размер, правило, время. Освобождённый объём не обещается.
6. **Пороги.** ops103: 80 % — предупреждение, 90 % — тревога; Диспетчеру и владельцу сразу список, что выросло за сутки и у кого. Процент проверяется каждым проходом `ct103-health`. Раз в сутки сохраняется снимок размеров по владельцам и задачам, только метаданные, с ограниченной глубиной; хранятся текущий и предыдущий. Тревога сама удаления не расширяет.
7. **Кто пишет, тот убирает.** Закрытие задачи координатора включает уборку своего кэша и временного и строку `release`. Раннер убирает свой `/tmp` при выходе, обычном и по ошибке, сразу: это уборка автором своего черновика, а не правило п. 1, поэтому ни 24 ч, ни `release`, ни режим только списка её не задерживают. Удаляется только то, что этот запуск сам создал и записал по точному пути; чужое, прежнее и находящееся под `hold` не трогается. Доказательства и нужные для разбора сбоя записи выносятся из черновика до удаления; если вынести нельзя, черновик остаётся. Оставшееся после аварийного завершения идёт по п. 1.
8. **Общий `GOCACHE`** с пределом размера вместо кэша на задачу — для сборок координаторов и рецензентов под одним пользователем. У Go нет встроенного предела размера, предел держит таймер ops103. Сборки кандидатов модели в общий кэш не входят: кандидат — недоверенный код, его следы не смешиваются с доверенными сборками. У каждой пробы свой кэш, который удаляется при её закрытии; права на это проверяет ops103. Попадание в кэш результата `go test` не считается новым независимым исполнением: независимая проверка идёт с `-count=1` или на своём кэше. Кэш общей проверки tools остаётся до её завершения (ответ В-33: Б).
9. **Запас и Proxmox (слово владельца, ответ на В-34).** Расширение CT 103 с 158 до ~250 ГБ делает владелец. Токен на CT 103 не выпускается, доступа к Proxmox у CT 103 нет. Пороги п. 6 считаются по внутренним замерам ops103 (`df`). Снимки и ресурсы делаются с мака нынешним токеном: ops103 пишет строку в окно Сторожа или представителя владельца.

### Consequences

* Good, because уборка больше не ждёт владельца, а тревога приходит с запасом и сразу называет источник.
* Good, because закрытый список и `hold` защищают доказательства от правила по возрасту.
* Bad, because координаторы обязаны писать `release`; без строки кэш остаётся и занимает место.
* Bad, because холодная сборка после очистки общего кэша дольше.
* Bad, because `/tmp` без `release` остаётся на диске, пока владелец задачи не закроет её или владелец не даст слово по списку сирот.

### Confirmation

Журнал ops103 по каждому удалению; проход только списка принят; на контрольных каталогах с `hold` у родителя и у потомка, живым процессом, символической ссылкой, файлом вне раскладки кэша и без `release` удаления нет; предупреждение на 80 % пришло со списком роста.

## Разбор ревью

Первый круг: Kimi `334849329` (С 2, М 2), review103 текстом сообщения на срезе `0fd313722` (Б 1, С 3). Приняты Б-01 и С-01..С-03 review103, С1, С2, М1 Kimi. М2 Kimi принята в части: основание границы кэша переписано, утверждение о проверке записей кэша Go не принято, поскольку его не подтверждали. Владелец предлагал удалять `/tmp` по возрасту; Б-01 показал потерю входа у задачи, ждущей дольше суток без открытых файлов, поэтому правило сужено до `release`. Широкий `hold` tools над `go-cache` общей проверки сужается самим tools после её завершения, затем отдельный `release` только кэша.
