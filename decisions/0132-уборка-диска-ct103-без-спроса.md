# Диск CT 103: что удаляется без спроса, кто убирает и когда тревога

## Context and Problem Statement

Класс системы: инфраструктура разработки CT 103. 2026-11-08 корень заполнился до 99,6 %, работа стала зависеть от срочного вопроса В-32. По словам владельца, причины — кэши Go в рабочих каталогах задач (16 и 1,6 ГБ), вторые копии (архив проверок в `cammeta-diff` и распакованные `results` рядом с `.tar.gz`, 18,5 ГБ), незагружаемая модель gpt-oss (13,8 ГБ), временные копии раннера в `/tmp` (5 ГБ), выходы проб `acc/` (около 5 ГБ). Монитор сообщил только на 99,6 %, а любое удаление ждало слова владельца.

## Decision Drivers

* Диск не должен останавливать работу, и уборка не должна ждать владельца.
* Удаление необратимо: доказательства, квитанции и пины не должны попасть под правило.
* Активная работа не должна терять файлы.

## Considered Options

* Закрытый список того, что удаляется без спроса, с условием на каждую строку.
* Удаление самого старого при нехватке места.
* Каждое удаление по слову владельца, как было.

## Decision Outcome

Выбран закрытый список. Всё, чего в нём нет, без прямого слова владельца не удаляется, какого бы размера ни было.

1. **Удаляется без спроса** при всех общих условиях из п. 2:

   | Что | Условие |
   |---|---|
   | кэш сборки Go задачи: каталог, заданный её `GOCACHE` | задача закрыта строкой `release` (п. 3); удаляется только содержимое кэша, родитель остаётся |
   | `/tmp/runner-*`, `/tmp/contracts-*`, `/tmp/generators-*` | самое новое изменение внутри старше 24 ч |
   | распакованное рядом с архивом | хеш архива совпал с записанным в квитанции, и распакованное побайтно совпало с содержимым архива; архив остаётся |
   | выходы `acc/` закрытой пробы | у пробы есть итоговый `result.json`; остаются итоговый судья, квитанции и траектории. `work/` не трогается |

2. **Общие условия.** Настоящий каталог, не символическая ссылка; обход без выхода за файловую систему; нет открытых файлов, cwd и отображений в памяти; пути нет в строке `hold`. Нарушено любое условие — путь пропускается и попадает в отчёт.
3. **Учёт.** `cammeta-sessions/disk-policy.tsv`: `kind` (`release` или `hold`), `path`, `who`, `task`, `at_utc`. `release` пишет координатор при закрытии задачи. `hold` пишет любой владелец данных, он сильнее любого правила. Сразу вносятся `hold` на `coord103/z9-out-on-demand` и на доказательные каталоги незакрытых задач.
4. **Никогда без слова владельца:** квитанции, доказательства, пакеты, пины, источник, рабочие деревья, модели, `work/` кандидатов, рабочие данные владельца. Точечное решение по gpt-oss — вне этого ADR.
5. **Исполнение.** ops103, таймер. Первый проход только составляет список; удаление включается после приёма этого списка Архитектором и двух ревью ADR. Журнал: путь, размер, правило, время. Освобождённый объём не обещается.
6. **Пороги.** ops103: 80 % — предупреждение, 90 % — тревога; Диспетчеру и владельцу сразу список, что выросло за сутки и у кого. Для этого раз в сутки сохраняется снимок размеров каталогов, только метаданные. Тревога сама удаления не расширяет.
7. **Кто пишет, тот убирает.** Закрытие задачи координатора включает уборку своего кэша и временного и строку `release`. Раннер убирает свой `/tmp` при выходе.
8. **Общий `GOCACHE`** с пределом размера вместо кэша на задачу — для сборок координаторов и рецензентов под одним пользователем. У Go нет встроенного предела размера, предел держит таймер ops103. Сборки кандидатов модели в общий кэш не входят: кэш не защищён от подмены записей, поэтому у каждой пробы свой кэш, который удаляется при её закрытии. Кэш общей проверки tools остаётся до её завершения (ответ В-33: Б).
9. **Запас.** Расширение CT 103 в Proxmox с 158 до ~250 ГБ делает владелец. Токен Proxmox — отдельный вопрос В-N, этим ADR не решается.

### Consequences

* Good, because уборка больше не ждёт владельца, а тревога приходит с запасом и сразу называет источник.
* Good, because закрытый список и `hold` защищают доказательства от правила по возрасту.
* Bad, because координаторы обязаны писать `release`; без строки кэш остаётся и занимает место.
* Bad, because холодная сборка после очистки общего кэша дольше.
* Neutral, because `/tmp`-правило по возрасту может снять каталог зависшей задачи; защита — `hold`.

### Confirmation

Журнал ops103 по каждому удалению; проход только списка принят; на контрольных каталогах с `hold`, живым процессом и символической ссылкой удаления нет; предупреждение на 80 % пришло со списком роста.
