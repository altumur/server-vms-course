# Формы ADR-0113 до норм, третья версия

ADR-0113 с доп. (1)–(3); ревью `/private/tmp/ревью-adr-0113-формы-claude.md` (Б, С, М) и `…-формы-2-claude.md` (2Б, 2С, 2М). Нормы идут за этим файлом.

## 1. Раздел и список

```yaml
раздел:      первые 12 бит SHA-256(UTF-8 имени члена), 4 цифры, 0000…4095; функция, списка разделов нет
domain/member-rows/<раздел>: {doc: <текст {domain, part, rev, term, members, issuer, kid, sig}>}   # вид договора записи срока, те же шаги (2М3); part и domain в подписанном; читатель сверяет: хэш каждого имени = part
  свежесть:  меньшая (term, rev) не берётся, кроме срока меньше своего по цепочке записей срока (C08-STOLEN-TERM-BACK-01) (2С9); kid в revoked_issuing — строка не верна, ждёт переподписи
  предел:    ENTRY_MAX пересчитан: Entry с class, via 980 байт, url ≤ 256 — 1240; строка 524288: ≈ 420 Entry худшего размера; среднее при 250 000 — 61, хэш ровный, строка 18 КБ при 300 байт
             сверх — 409 «this name's row is full: pick another name» (С12): другое имя, а не «снять ушедших»
  имя:       уникально CAS этой строки; every_entry — по этой строке
  term:      claim новым держателем: переподписать все разделы, подъём rev, размазанно по REPORT_RATE; до переподписи строка прежнего срока верна по цепочке записей срока, как набор следования (С7)
domain/member-count: {servers, cameras}    # счёт; в голове копии; SERVERS_MAX 500 — отдельным счётом, приём сверх — 409 (С3)
Entry:       ещё class: server | camera; url?; via?; every? не в Entry, см. метку
domain/holder:  запись срока: ca уже есть, новое key? (нет у первого срока до первого отчёта: 2С1); смена центра или появление ключа — переиздание того же срока с большим at, at строго растёт; peer и выбор назначения читают ca записи срока, ступень how: holder в member-list снята (peer.md:44, 09.1:490)
domain/relay-members/<ретранслятор>: {rev, members: {<член>: <ключ>}}   # индекс, тем же пакетом, что Entry.via (С9); relay_for и keys идут, только если relay_rev пакета отстал (2С2); строка ≈ 5000 имён, сверх — приём 409 relay full (2М7)
domain/member-list/<раздел>: {doc, fetched_at}  # у члена: свой раздел и запрошенные; запрошенная старше часа или отказ TLS — метка «перечитать», снимает только новая строка (2С10); домена нет — живёт дальше, предел (С8)
publication.members_rev: {term, rev} своего раздела; carry.members: свой раздел, только если отстал
дверь:       GET /api/members/<член>/<раздел> с подписью агента; у ретранслятора та же дверь из памяти: строки подписаны (С8)
GET /domain/members?cursor=: идёт по непустым разделам (2С8); без cursor — первая страница и {count, knocking}
```

`CLUSTERS` остаётся для держателя и первого контакта.

## 2. Классы, период, отказ «позже»

```yaml
class:       server — кластер с серверами, every 5 с; camera; партия всегда camera (доп. (3) п. 4); стук без партии объявляет class, человек видит и подтверждает; смена — уход и приём
every:       camera: max(5, cameras / REPORT_RATE), не больше 3600; смещение прохода — от хэша имени; выше 720 000 камер бюджет не держится: предел
метка:       пишет сказанный every (С5); silent_after = 3 × сказанный every; SHADOW_STALL, ROAD_QUIET — то же у камеры (М3); server — прежние
счёт:        нет domain/member-count — поле every не слать, агент держит прежнее: «нет — без изменений» (С4, 2С6)
busy:        исход договора {retry_in}, после проверки подписи, считаются только члены, class server его не получает (2С4); все двери агента: POST /api/member, GET /api/carry, /api/members, /api/anywhere, /api/backup-part; retry_in в 404 стука; разброс от хэша имени
             у ретранслятора refused[член] = {reason: busy, retry_in}: публикация остаётся в памяти, up не забывается, повтор после retry_in, новый приход заменяет (2Б1)
             silent_after = 3 × max(сказанный every, retry_in), метка несёт оба
unseen:      после перезапуска держателя камера выходит из unseen по received_at метки, а не по следующему отчёту (М4)
relayed:     держатель отвечает только членам с телом в этом пакете (доп. (3), Б1); дверь ретранслятора держит POST камеры до ответа своего пакета, не дольше прохода плюс срок; не успел — ответ из памяти или 503: так камера читает свой ответ, а не прошлый (2С3)
```

## 3. Вид

```yaml
domain/view: {as_of, holder, url, term, complete, counts, knocking_count, …}   # голова, объект, раз в 3 с; holds, view.url читают его
domain/view-rows/<раздел>: {as_of, members, units, contested}   # объекты (М2); VIEW_MEMBERS 2000 членов в с: круг = члены / бюджет, раздел — единица работы (С10)
complete:    закрыт круг после последнего старта и все разделы полны; после смены держателя ложь, пока круг не закрыт (С11)
contested:   domain/ref-claims/<sub>/<sha16 ref>: {<член>: {as_of}}; снимает проход раздела, чей член заявку больше не даёт; дверь правки судит ref свежим чтением заявки, а не видом; исполнители — назначение своей заявки (С11); ложный спор при переезде камеры длится до её отчёта: предел
GET /domain: голова, в ней parts непустых разделов; ?cursor=: страница строк вида; фильтр P/10 — по строке; проход идёт по перечню непустых (2С8)
```

## 4. Снимки, папки, роли, сводка

- Снимки: `TABLES_MEMBER_MAX` server 8 МиБ, camera 64 КиБ, сверх — заглушка `refused`.
- Папки: `domain/folder-log` кольцо 1024; `carry.folders` — дельта от `rev`, дальше кольца — целиком; счётчик папки одной строкой `domain/folder-counts/<id>`, считает проход, строгий предел судит строка раздела (2С8).
- Роли: проход только по изменённым; `role_spread` — по разделам.
- `anywhere`: в ответе `{as_of, sha256}`, тело — `GET /api/anywhere/<член>` при смене; камера строку не держит: вход по `anywhere` у неё нет.
- `domain/topology`: `centre`, `star`; `via` в `Entry`.

## 5. Копия и перенос

```yaml
копия:       голова {term, rev, parts: {<раздел>: {sha256, rev, key_rev}}, counts, batches, …} и объекты domain/backups/part-<раздел>-<rev>; неизменённый раздел ссылается на прежний; смена ключа копии — все части заново (2С5)
             уборка: часть живёт, пока на неё ссылается одна из 5 голов или идёт докачка не старше BACKUP_FETCH 600 с; BACKUP_EVERY = max(30, байты / BACKUP_RATE), BACKUP_RATE 1 МиБ/с
доставка:    хранитель тянет дверью GET /api/backup-part/<член>/<раздел> с подписью, не в carry (Б5); только class server; восстановление — та же дверь у консоли хранителя (GET /api/backup части, 2С5); докачка голов не догоняет — переход на новую голову с разницей
передача:    цель докачивает до начала; HANDOVER_WAIT — от остатка, передача стартует, когда цель почти догнала; server ждут 6 × REPORT_EVERY, камеры догоняют через busy
из ничего:   пока стоит domain/from-nothing, раздел partial: 404 неизвестному несёт слово send-row, агент повторяет полем row публикации; слияние по имени: Entry нового срока главнее, остальные — из наибольшей подписанной строки; приём в partial — busy; исключённый после копии вернётся: предел, виден в журнале; конец — отчитались все разделы или оператор закрыл (доп. (3) п. 3, Б3, 2Б2)
             every в этом режиме не шлётся. Quint — до норм этого места
приём:       камера сверх 16 не принимается, пока хранителей меньше BACKUP_HOLDERS: 409 с объяснением; до 16 — предупреждение в виде: один сервер и пять камер остаются законной установкой (2С7, уточняет доп. (3) п. 3)
target:      цель передачи — только class server (2М6)
state:       + domain/batches с правилом объединения: отзыв не оживает, used — наибольший, refused — объединение множеств (С13, 2С11); domain/issued; без folder-counts и вида
```

## 6. Массовый приём (доп. (2), (3))

```yaml
domain/batches/<имя>: {pub, record?, via?, n, used, until, revoked?, refused: {<отпечаток>: at}, by, at}   # refused переполнен — партия отзывается сама; после until чистится (2С11)
токен:       закрытый Ed25519 партии, показан один раз; в строке открытый (уточняет доп. (2) п. 1, 2М2); коробка подписывает JCS {purpose: "batch-knock", domain, name, key} (2М5): секрет по сети не идёт, ретранслятор его не видит, к другому имени не подходит (С2)
via:         приём пишет его в Entry тем же пакетом с relay-members (Б4); поле record — кластер записи, слово не cluster
domain/knocks/<раздел>: {<имя>: {key, pinned, at, batch?, class}}  # всякий стук с подписью партии, годной или нет; неизвестная — память 64; пишется только первый стук, строка до потолка, сверх — память (С15, 2М4)
приём:       подпись верна, used < n, не отозвана, отпечатка нет в refused → Entry, used + 1 одним пакетом; журнал; 
исключение:  DELETE принятого партией вносит отпечаток в refused партии, имя партии — Entry.batch: вернуться тем же токеном нельзя (С14, 2С11)
сверх:       стук лежит, ждёт человека; отзыв закрывает новые, принятых не трогает
двери:       POST, GET /domain/batches, DELETE /domain/batches/<имя>; admin домена
```

## Читатели

`GET /domain`, `GET /domain/members` — постранично, малому домену обход 4096 частей не нужен: V/11.3, V/11.8, страница держателя. `domain/members` исчезает из каталога: 144 строки семей, 8 сценариев. Записать в ADR: ключ `domain/member-rows/<раздел>`, предел ≈ 1,4 млн вместо ≈ 2 млн, порог 16 камер, партия — ключом (М1, 2М1, 2М2).

## Не решено здесь

Каким центром камера проверяет чужую консоль (2 «не проверял»): `/domain/at` от камеры не ходит, поэтому пока не нужно. Quint: «из ничего» с разделами.
