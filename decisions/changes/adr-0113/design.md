# Формы ADR-0113 до норм

ADR-0113 с доп. (1), (2); замечания `decisions/inbox/2026-11-01-ADR-0113-замечания-спецификации.md`. Здесь формы и решения Спецификации, нормы пойдут за ревью этого файла.

## 1. Раздел и список

```yaml
раздел:      первые 9 бит SHA-256(UTF-8 имени члена), десятичное число тремя цифрами, 000…511; функция, списка разделов нет
domain/member-rows/<раздел>: {doc: {rev, term, members: {<член>: Entry}}, kid, sig}   # подпись держателя на строку; ключ, CAS — раздела
  предел:    строка 524288 байт: ≈ 590 Entry худшего размера 888 байт, ≈ 1750 по 300 байт; сверх — 409 too many members; MEMBERS_MAX — предел строки, не домена
  имя:       уникально CAS этой строки (C08-NAME-UNIQUE-01): оба приёма одного имени пишут одну строку
  every_entry: проверяет Entry этой строки, не домена
domain/member-count: {servers, cameras}     # пишет проход; приём его не ждёт: для периода точность не нужна
Entry:       ещё class: server | camera, url?, via?   # via уходит из domain/topology в Entry; url — из domain/servers (проверка P/08.1 Н1.4)
domain/member-list/<раздел>: {doc, kid, sig}   # у члена: строка как пришла, разделы: свой, держателя, запрошенные
publication.members_rev: {<раздел>: {term, rev}}  # разделы, которые член держит
carry.members: {<раздел>: {doc, kid, sig}}     # только отставшие из своего и держателя
дверь:       GET /api/members/<член>/<раздел> с подписью агента: чужая строка по запросу, peer и /domain/at, кэш с rev
GET /domain/members?part=<раздел>: одна строка; без part — {count, knocking}
```

`CLUSTERS` остаётся для держателя и первого контакта; адрес и `Entry.ca` чужого члена — из строки раздела. Запрос строки стоит раздел, а не домен.

## 2. Классы и период

```yaml
class:       server — кластер с серверами, every = REPORT_EVERY 5; camera — камера-кластер; объявляет агент в стуке, ставит приём (партия — ниже), смена — уход и приём
every:       camera: max(5, cameras / REPORT_RATE), REPORT_RATE 200 в с, не больше 3600; смещение прохода — от хэша имени, разброс на весь период; после падения держателя все не приходят разом
silent_after: server — LOST_AFTER 45; camera — 3 × every, в carry поле не нужно: считает держатель. MARK_REFRESH у камеры — раз в отчёт
SHADOW_STALL: у камеры 3 × every; HANDOVER_WAIT: 6 × REPORT_EVERY для server, камеры догоняют дорогой rebase по одной
отзыв:       server — секундами; camera — с периодом, предел (доп. (1) п. 3)
стражи:      правка чужой камере — сразу kept, V/11.4 Н1.13 без ожидания
```

## 3. Вид

```yaml
domain/view-head: {as_of, holder, url, term, complete_parts, counts, knocking_count, топология держателя}   # маленький, раз в 3 с; holds, view.url перехода 2 читают его
domain/view-rows/<раздел>: {as_of, members: [...], units: {<sub>: [Unit]}, contested}   # проход разделов: VIEW_RATE разделов в с, полный круг — не меньше 60 с
GET /domain:        head; GET /domain?part=<раздел>: строка вида; фильтр P/10 — по строке
complete:           все разделы последнего круга полны
contested:          ref у двух членов двух разделов: индекс domain/ref-claims/<sub>/<хэш ref> за круг, спор виден со сдвигом до круга: предел
```

Цена прохода стоит, растёт возраст: `age` члена уже несёт это.

## 4. Снимки таблиц, папки, роли, сводка

- Снимки: потолок на член `TABLES_MEMBER_MAX`: server 8 МиБ, camera 64 КиБ, сверх — заглушка `refused`; на домен считается по классу и числу, отдельного счётчика нет.
- Папки: `domain/folder-log` кольцо 1024 записей; `carry.folders` — дельта от `rev`, отстал дальше кольца — целиком. Счётчик из строки папки — `domain/folder-counts/<id>/<раздел>`.
- Роли: проход расхождения только по изменённым: `lines_at` или новый член; `role_spread` — по разделам, членов не читает.
- `anywhere`: в ответе только `{as_of, sha256}`, тело — `GET /api/anywhere/<член>` при смене. Строку `domain/anywhere` у камеры не держать: камера входа по `anywhere` не даёт.
- `domain/topology`: `centre`, `star` остаются; `via` в `Entry`.

## 5. Резервная копия

`state` по разделам: `domain/backups/rev-<rev>/<раздел>` и голова с прочим; объект ≤ 64 МиБ. Строки, которые восстановит проход, не входят: `domain/folder-counts`, `domain/member-count`, вид. Хранитель — только `class: server` (доп. (1) п. 4). Новый держатель: `rebase` по одному, без целых всех сразу: очередь по разделам с `REPORT_RATE`.

## 6. Массовый приём (доп. (2))

```yaml
domain/batches/<имя>: {sha256, cluster, n, used, until, revoked?, by, at}  # токен показан один раз, 7 дней
domain/knocks/<раздел>: {<имя>: {key, pinned, at, batch?}}   # стук партии строкой; прочие — память 64, как было
приём:    стук с токеном: годен, used < n → Entry той же записью, used + 1 CAS; журнал domain.member.admitted.batch {batch, name, fingerprint}
сверх:    обычный стук, ждёт человека; отзыв закрывает новые; принятых не трогает
двери:    POST, GET /domain/batches, DELETE /domain/batches/<имя>; admin домена
```

## Что ломается у читателей

- `GET /domain`, `GET /domain/members`: V/11.3, V/11.8, страница держателя, консоль: постранично.
- `domain/members` как строка исчезает из каталога: 144 строки семей и 8 сценариев приёмки переписать.
- P/10 фильтр идёт по строкам вида.
