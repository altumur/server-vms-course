# Нормы формы, семей данных и связей — стандартом JSON Schema 2020-12 и CEL; свой остаток — отдельными слоями (вариант В7)

Редакция 4 (2026-10-27) — по двум кругам ревью Claude, Codex, Kimi; изменения — в конце, «История редакций».

## Context and Problem Statement
Класс системы: платформенная система — строгий загрузчик манифеста (урок P/02, глава 2.1), схемы семей данных (каталог
`Platform/common/data/`, ADR-0088), связи манифеста (`references.tsv`), канонический вид (ADR-0089).

Форма манифеста и схемы семей записаны на своём диалекте (`DIALECT.md`, ADR-0087), связи — своим языком § 6, текст —
своим подмножеством YAML (Н1.1); каждая реализация пишет интерпретатор диалекта и свой разборщик YAML (ADR-0087 п. 4).
Правильность держится на корпусе и реализациях нашего ИИ; внешнего оракула нет. Примерно треть догадок стадии C (форма,
YAML, связи, канонический вид) — об этом слое.

Замеры (числа — чьи):
- **текст** — готовый парсер YAML 1.2 и тонкая проверка: записка и Claude — 626–627 из 630 (остаток — 11 мест, где Н1.1
  отступает от YAML 1.2.2, и дефекты парсеров); Kimi — 630 из 630 своим слоем, написанным со знанием этих 11 мест;
- **форма манифеста** в чистой JSON Schema 2020-12 — 545 из 557, со слоем «целый знак» 557 из 557 (записка, Kimi, Claude);
- **связи** — CEL: 112 из 121 строки (Kimi; Claude — и строки «с `flatten`» чистым CEL), 0 различий на 270 случаях;
- **семьи** — записка 10 828 экземпляров, Kimi 5 520 своим генератором — 0 расхождений; проба Claude (5 семей, 243
  экземпляра) — два вида расхождений, которых генераторы не строили: эталон принимает `null` вместо объекта семьи; Python
  `jsonschema` принимает строку с `\n` в конце под `^(?:…)$`.

## Decision Drivers
* внешний оракул: библиотеки JSON Schema и CEL проверены наборами сообщества (Bowtie, cel-spec), YAML — yaml-test-suite;
* меньше своего кода на каждом языке: нет интерпретатора диалекта (≈ 1 600 строк на Python) и своего разборщика YAML;
* слова значат то, что в стандарте (нет `integer`, `pattern`, `default` с другим смыслом);
* новые языки и продукт на Go — библиотеками;
* смена входного языка — осознанная, пакетом с перечнем дельт (п. «Объём смены нормы»).

## Considered Options
* В1 — как сейчас: диалект, свой YAML, свой язык связей
* В2–В5 (записка): чужая схема без своих слоёв — расходится с нормой (ADR-0085); свой генератор кода из диалекта (В5) —
  та же детерминированность, но эмиттер и рантайм на каждый язык держать самим
* В6 — диалект нормой, стандарт свидетелем
* В7 — стандарт для того, что он поддерживает; свой остаток — отдельными слоями

## Decision Outcome
Выбран **В7**: на корпусе и экземплярах семей он даёт вердикты диалекта (двумя независимыми стендами, с оговорками выше),
снимает интерпретатор и разборщик YAML с каждого языка и даёт внешний оракул. Ответы на вопросы записки:
1. **Вариант** — В7.
2. **Текст** — готовый парсер YAML 1.2 закреплённой версии и тонкая проверка: байты, **один документ — по байтам** (не по
   API парсера), корень — блочное отображение с колонки 1, отказ на якоре, псевдониме, `<<`, теге, повторе ключа, ключе-коллекции,
   глубине > 64, **TAB вне комментариев и `{k:}`** (п. 4); скаляры — по `scalars.tsv` **по стилю узла** (`"true"` — строка, `true` — bool). Правила Н1.1:95 и :46
   (потоковая коллекция и строка в кавычках на несколько строк, индикатор `|2`, сложный ключ `? …`, `...`, директива `%`)
   **остаются отказом** — правилами тонкой проверки, со случаями корпуса. yaml-test-suite — закреплённой версии,
   список отклонений ведёт «Спецификация», неожиданное отклонение — красное.
3. **11 отклонений Н1.1 от YAML 1.2.2** — принять YAML 1.2.2 (меньше своих правил; у трёх из них парсер отказывает то, что
   норма принимала, — свой слой там не помог бы).
4. **`{k:}` и TAB вне комментариев** — запретить нормой. Затронуты случаи `c3_tab_quoted_ok`, `c3_tab_block_ok`,
   `c4_block_tab_content_ok`, `c6_flow_map_empty_value` и строки векторов `canonical` 51, 53, 54 — в дельты.
5. **Пути и строки отказа загрузчика манифеста** — подсказка, не норма; строгими остаются вердикт и код выхода. **У семей
   путь отказа остаётся нормой** — он выбирает исход `outcomes.tsv` (ADR-0088 доп. (1) Р7).
6. **Класс отказа загрузчика** — тип по слою: `text`, `form`, `relations`, `catalogue`; форменные `value`/`key`/`name`
   становятся `form` (правка Н4 и до 126 строк `classes.tsv`); класс связи `value`/`reference` — колонка `references.tsv`.
7. **Корпус одной причины** — да: каждый отказ — мутация принятого соседа; файлы без `worker:` дополняются.
8. **«`4.0` не целое» в манифесте** — отменить: целое по значению, **`minimum: -9007199254740991` и
   `maximum: 9007199254740991`** у каждого целого места, и **приведение к целому в дереве** (`4.0` → `4`) — свой слой.
   Не задевает **целый знак семей**: `whole: true` у писателя **и читателя**, целое по точному десятичному значению записи
   (`codec.tsv`, OBS154-RAW-TIME-EXACT-01) — свой слой кодека.
9. **Чужой код** — критерий: стандарт, внешний набор тестов, закреплённая версия (в пине выгрузки, ADR-0083 доп. (37) п. 2),
   наш корпус на каждом языке, и **каждый известный дефект закреплённой версии — случай корпуса**, красный без своего слоя.
10. **Свидетель JSON Schema** — валидатор Go или Rust в приёмке сверяет форму.
11. **Случаи, утверждённые человеком** — да: ≈ 60 случаев формы и связей и таблица дельт (Confirmation), коммит человека.
12. **Источник** — один раз сгенерировать схему, CEL и слой проекции из диалекта генератором в навыке `lesson-spec`
    (немеханические места — точка `pattern` → `[\s\S]`, `name_not_pattern` дополняющим выражением — переводятся вручную и
    помечаются), проверить на корпусе; дальше нормой становятся стандартные файлы и таблицы своих слоёв.
13. **Корпус семей** — экземпляры с ожиданиями, утверждёнными человеком: по одному на строку `outcomes.tsv`, на слово вне
    стандарта, **корень `null`, хвостовой `\n` в полях с `pattern`, имена под `propertyNames` с исходом по пути**.
14. **Переносимые регулярные выражения** (норма В7): `pattern` в схемах — ECMA-262 **в режиме `u`** (Unicode; знаки вне BMP)
    в пересечении с RE2: без просмотра вперёд и назад, без обратных ссылок; знак — самим знаком в строке JSON; проверку
    держит `check_spec` (компиляция в обоих движках).
15. **Два режима схем семей** (писатель/читатель, ADR-0088 п. 3): один файл схемы; ограничения писателя — в `$defs.writer`,
    писатель проверяет `allOf: [схема, $defs.writer]`, читатель — схему.

**Свой остаток — полный перечень слоёв** (исполняет каждая реализация; машинно описан таблицами рядом со схемами):
1. тонкая проверка YAML (п. 2), включая правила Н1.1:95, :46;
2. целые манифеста: границы ±(2^53 − 1), если не в схеме, и приведение к целому в дереве (п. 8);
3. кодек строк семей: `items`, `time`, `max_bytes`, имена сверх `max_items`, `whole` писателя и читателя с точным
   десятичным значением записи;
4. **место отказа** для библиотек, которые его не дают (`propertyNames` у Go `santhosh-tekuri`, `uniqueItems` — второй из
   пары равных), — путь семей нормативен;
5. **полное совпадение `pattern`** (Python `jsonschema`: `$` перед последним `\n`; точка диалекта — `[\s\S]`);
6. **проекция канонического вида** — **полный действующий алгоритм P/02.2 Н1.1**: сахар, умолчания (статические — из
   аннотации `default` схемы; вычисляемые — `snapshot`, `tables.<т>.journal`, `display.form`, ADR-0089 доп. (1) Р10),
   преобразования П1–П5 (в том числе П5 `decoded`), `ordered` (перечень мест в таблице слоя), скаляры по типу узла;
   **связи CEL исполняются над деревом загрузчика, как сейчас у эталона**: отсутствующее значение `@путь` и проверка
   `has` берут **статическое** умолчание `default` формы, глубина — над значением с такими умолчаниями; вычисляемые
   умолчания, П1–П5 и `ordered` к дереву связей **не** применяются (замер 270 случаев — над этим деревом);
7. связи: три функции CEL (`depth`, `template`, `text`) — 9 строк; прочие строки — чистым CEL (`flatten` не нужен).

**Что заменяется и что остаётся:**
- ADR-0087 — заменяются п. 1 (три файла источника → стандартные файлы и таблицы слоёв), п. 2, п. 4, п. 5, п. 7 (схемы
  строк — тем же диалектом), доп. (2),
  доп. (3) Р2 — для загрузчика манифеста (у семей пути строги), доп. (4) В1, доп. (6) в части TSV источника; доп. (5)
  (слова решает «Архитектор») — переносится на расширения `x-*` и таблицы слоёв; п. 3 (раздел урока строится из
  источника) — остаётся, источник — стандартные файлы;
- ADR-0088 — заменяются п. 1 (источник семей — `.form.yaml` диалекта), п. 5, п. 7–8 (построитель), доп. (1) Р1 (слова
  диалекта); из доп. (2) **остаётся** только кодек строк и целый знак (слой 3); запрет `json_schema`, слово `writer: {…}`
  (заменено п. 15) и запись `\x{HHHH}` (заменена п. 14) — **заменяются**;
- ADR-0089 — заменяются п. 3 (схема строится тем же построителем) и п. 4 (`ordered` — словом диалекта); п. 1, п. 6
  (векторы `canonical` байт в байт) и доп. (1) Р10, Р14 — **остаются** слоем 6.

**Объём смены нормы** (пакет перехода, ADR-0087 доп. (7)): Н1.1 и Н4 урока 02; случаи корпуса, `verdicts.tsv`,
`classes.tsv`, `diagnostics.tsv`; набор принятых входов `canonical` и его ожидания; адаптеры и сравнения раннера.
Алгоритмы и векторы прочих пакетов не меняются **на прежней общей допустимой области**.

### Consequences
* Good, because форму и связи исполняют библиотеки с внешними наборами тестов; оракул корпуса — люди (пп. 11, 13).
* Good, because на каждом языке нет интерпретатора диалекта и своего YAML; новые языки и продукт — библиотеками.
* Good, because треть догадок стадии C теряет предмет.
* Bad, because свой остаток — семь слоёв (не «тонкий»), их держат таблицы и корпус.
* Bad, because меняется входной язык урока 02 (пп. 3–8): корпус, классы, диагностика, векторы `canonical`; урок 02
  подтверждается заново; общая библиотека чтения форм перегенерируется.
* Bad, because дефекты библиотек входят в загрузчик; держатся только тем, что каждый известный дефект — случай корпуса
  (п. 9), неизвестный — не держится.

### Confirmation
Два набора, оба с полным SHA в пине выгрузки:
- **А. неизменённый набор** — случаи, чей ожидаемый исход пп. 3–8 не меняют: стандартный стек на каждом языке совпадает с
  эталоном диалекта (вердикт; у семей — и исход по пути); векторы `canonical` прежних принятых входов — байт в байт;
- **Б. таблица намеренных дельт** «id → старый исход → новый исход → основание», утверждённая человеком (п. 11);
  стандартный стек даёт новый исход. Основание — пункт решения пп. 1–15 **или «дефект эталона»**: известные ошибки
  эталона диалекта (принимает `null` вместо объекта семьи; падает на `1e400` в JCS; читатель принимает `1e400`) — строками
  Б с верным исходом, не опровержением; сюда же векторы `canonical` 51, 53, 54 (входы с TAB, п. 4).
Плюс: отрицательная граница целого (случаи `int_below_min` — `-9007199254740992`, отказ; `int_at_min_ok` —
`-9007199254740991`, ok); правила Н1.1:95, :46;
каждый известный дефект закреплённой версии — красный без своего слоя; yaml-test-suite по списку отклонений; корпус семей п. 13.
**Критерий опровержения:** случай набора А, где стандартный стек со всеми слоями расходится с эталоном не по дефекту
библиотеки, учтённому слоем, и не по дефекту эталона, внесённому в Б, или случай, утверждённый человеком, противоречащий
ответу пп. 1–15, — переход не наступает,
решение возвращается владельцу. Числа исходного замера (626–627, 557, 270) — историческая проверка, не спецификация набора.

## Pros and Cons of the Options

### В1 — как сейчас
* Good, because ничего не меняется посреди стадии C.
* Bad, because свой интерпретатор и YAML на каждом языке; оракул — только наш ИИ.

### В6 — диалект нормой, стандарт свидетелем
* Good, because внешняя проверка без смены нормы.
* Bad, because два описания формы; интерпретатор диалекта остаётся на каждом языке.

### В7 — стандарт и отдельные слои
* Good, because см. Decision Outcome.
* Bad, because см. Consequences.

**Дополнение от 2026-10-29 — криптография в закреплённом стеке Python** (решение «Архитектора» по вопросу c-python-v7).
Стандартная библиотека Python не даёт AES-GCM, Ed25519/X25519, разбора и выпуска X.509 и CRL; у Go это в стандартной
библиотеке. В стек Python В7 (п. 9) входит `cryptography` закреплённой версией вместе с её зависимостями (`cffi`,
`pycparser`), колёса с хэшами для macOS arm64 и manylinux x86_64; строка в `Platform/common/versions/requirements.txt` —
«Спецификация». Критерий п. 9 выполнен: стандартные алгоритмы, внешний набор тестов проекта, закреплённая версия;
известные дефекты закреплённой версии — случаями корпуса. Реализация Python держит её только в общей части
`lib/w2cforms` по договорам `common/contracts` (sealing, role-certificate, secret-files, TLS/CRL); системный OpenSSL через
процессы не вызывается. Версия — выпущенная не позже чем за две недели до закрепления.
