# ADR-0133. Генерация с нуля своим циклом: этапы, адаптеры для судьи, профили по видам кода, судьи — наши

## Context and Problem Statement

Класс системы: платформенная система (процесс генерации реализаций по спецификации курса).

Слово владельца 2026-11-08: «эксперимент состоит в том, чтобы доказать или опровергнуть возможность полной генерации всего с нуля по текущим спекам через свой цикл и минимакс»; «Б — пусть модель пишет всё сама»; «возможно стоит подумать о своём цикле для каждого вида кода»; «да, начни со стенда и генераторов»; «давай это утвердим».

До этого пробы MiniMax (З-15, пробы 41–45b) шли с пакетом `tools/normgen` (каркас и тесты из генераторов) и с частными привязками автора задания. «Нуль» определён как вариант Б — без пакета, вход только выгрузка (ADR-0083 доп. (155)); пробелы выгрузки для Б разобраны в доп. (156).

Что показали пробы и пилоты 2026-11-08:
* Проба 44 (P/02) встала на цели `rights`: модель не реализовала одну команду стенда (`stand.ring`), а цикл не показал причину — раннер скрыл вывод, отчёт утопил сигнал в шуме. Общая диагностика цикла (`549a037`) называет нереализованную команду без знания ответа.
* Пилот генератора 46c встал на 1 из 7: эталон нёс постоянную прозу, невыводимую из описания; 46d с примером на каждый вид прошёл 7/7, скрытые 4/4 (`/srv/minimax-loop/runs/gen-refusals-46d-miniswe/result.json` на CT 103), но воспроизводил наш генератор по его выводу — это не «с нуля». Проза из кода убирается (ADR-0125 доп. (10), шаг 14 его плана идёт).
* Подсказка с ответом пробе 44 была отменена владельцем («так не пойдёт…», слово выше): положенный цикл файл ответов снят через 31 с, до записи состояния; копия — `/root/answers44-withdrawn.md` на CT 103; продолжение пробы — из состояния без подсказки, потолок 90M в копии задания `tasks/p02-go.ct103-44r-miniswe.json`.

Вопрос: как устроить процесс, чтобы его итог честно доказывал или опровергал генерацию с нуля.

## Decision Drivers

* Итог должен быть доказательным в обе стороны — и «доказано», и «опровергнуто»: ни подсказок с ответом, ни вывода существующих генераторов и реализаций на входе.
* Вердикт даёт судья, независимый от модели: модель не сдаёт экзамен, который сама составила, — и не может обойти судью через свои адаптеры.
* Без адаптеров судья ничего не проверит — их порядок задаёт порядок этапов.
* Разные виды кода судятся по-разному; один движок цикла дешевле нескольких.
* Пробел спеки, который модель не может вывести, — находка эксперимента, а не повод для подсказки.

## Considered Options

* **А. Один движок цикла, профили по видам кода, поэтапный процесс; судьи наши, адаптеры пишет модель по договору судьи.**
* Б. Отдельный цикл на каждый вид кода.
* В. Прежний цикл с пакетом и подсказками по месту.

## Decision Outcome

Выбран вариант «А», потому что он даёт доказательный вердикт (судья независим, вход только спека) при одном движке цикла, а виды кода различаются только профилем: чем судить, что дать на вход, как делить этапы.

1. **Вход** — только выгрузка спеки по пину: нормы, формы, векторы, сценарии, описание стенда, `Platform/common` (включая `versions/go.mod`). Не даются: пакет `tools/normgen`, вывод наших генераторов, реализации (`Source/`, прежние линии), частные привязки автора задания (ADR-0083 доп. (155)). Зависимости — только stdlib и модули из `Platform/common/versions/go.mod`; кэш модулей по `go.sum` даёт стенд как среду (доп. (156) п. 3).
2. **Судьи — наши:** раннер приёмки `cammeta-acceptance`, его сценарии, нагрузка, бюджеты и среда замера; корпус вердиктов спеки. Тесты, которые модель пишет сама, — только самопроверка; вердикт ими не даётся.
3. **Модель пишет всё остальное:** продукт и **адаптеры для судьи** — драйвер стенда (`stand.*`), команду векторов (`bin/vectors`), адаптер швов (по протоколу доп. (156) п. 1), тестовые привязки боевых проверок (по публичному договору ADR-0130 доп. (11); квалификация, идентичность поставщика и отрицательные контроли — на стороне судьи, как требует D7). Граница: этап 1 судит наличие и протокол адаптеров (команда объявлена, отвечает по договору), правильность продукта за ними — этапы 2–4.
4. **Адаптер не может подменить продукт.** Договор каждого адаптера задаёт судья (спека и раннер): адаптер только переводит вызов в продукт. Обязательны:
   * **отрицательный контроль на каждую цель:** раннер прогоняет те же адаптеры над сломанной сборкой продукта (пустой бинарник или «отказ на всё»); зелёное над сломанной сборкой — провал средства проверки, а не PASS;
   * **изоляция ожиданий:** во время суда процессы адаптеров не читают столбцы ожиданий (`vectors/**`, `acceptance/**`) — машинно на стенде;
   * **чтение кода адаптеров** ревьювером (не моделью и не ведущим цикла) до объявления «доказано».
5. **Этапы:**
   0. Подготовка (цикл, без модели): выгрузка по пину, опись обязательного из форм (команды стенда, флаги, отказы, двери, этапы), план, бюджет.
   1. Адаптеры для судьи: стенд, векторы, швы.
   2. Форма → код: флаги, отказы, двери по OpenAPI, статус и метрики, семьи; модель сама решает — код напрямую или свой генератор; судья — сборка, векторы форм, опись.
   3. Поведение по `stages.tsv` урока: выжимка нормы этапа, векторы, сценарии; судья — раннер по этапу и метки регрессий. Форма этапов читается без пакета: ворота `tests:` судятся как `accept:` на тех же сценариях, `:seams` — через адаптер швов (доп. (156) п. 1); грамматику оформляет Архитектор (ADR-0126) до новой выгрузки. У P/07 формы нет — этапы из целей раннера.
   4. Урок целиком и боевые свойства (ADR-0130, веха 2.4б): тестовые привязки D7, затем боевая приёмка раннером.
   5. Следующий урок — поверх своего же кода прошлых уроков.
6. **Цикл — один движок с профилями.** Описаны: стенд, форма → код (`PROFILES.md` в репозитории цикла `/srv/minimax-loop`, ветка `en-generic`, коммит записывается в паспорт пробы). Дальше: поведение, боевые, тесты через мутации, судьи через корпус, сборка и развёртывание, интерфейс.
7. **Разрешено циклу:** общие улучшения без знания ответа — видимость ошибок (секреты затёрты), опись «объявлено — реализовано», предполётные проверки, детектор застоя и свежий взгляд второго агента той же модели, деление этапов, бюджеты. **Правка цикла общая, если** не содержит имён уроков, целей и команд и применима без изменения к любому уроку; проверки и `require` стенда строятся машинно из выгрузки (таблица доп. (156) п. 2), а не подбираются по провалу; этапы делятся по форме или целям раннера, а не по месту провала. **Запрещено:** подсказки, знающие ответ; примеры из готового кода и генераторов; правка кода модели руками.
8. **Независимые читатели, не ведущий цикла:**
   * **классификацию провала** («модель» / «цикл» / «пробел спеки») утверждает Архитектор по тексту нормы; журнал пробелов отмечает, кто признал пробел;
   * **журнал пробы** (версии цикла по ходам, разница цикла между пробами, переданное модели содержимое) читает ревьювер другого провайдера, чем ведущий цикла, — до вывода «доказано» или «опровергнуто».
9. **Пробел спеки** (модель не может вывести ответ, Архитектор подтвердил) — чинится в норме общей формулировкой, без ссылки на пробу; следующая проба идёт на исправленной выгрузке **с пустого рабочего каталога**. Число кругов «пробел → новая выгрузка → новая проба» на урок ограничено (число — шаг 9 плана).
10. **Зачётная проба** — только при утверждённых до запуска бюджете, числе попыток, пределе кругов и правиле окончания, записанных в паспорт. В бюджет входит всё: повторы, `--resume`, второй агент, исправления цикла. Смена выгрузки, задания или профиля посреди пробы — новый зачётный срез. Пробы до утверждения — разведочные, с пометкой «без вывода доказано/опровергнуто».
11. **Точка сравнения:** пробы 44 (P/02) и 45b (P/01) с пакетом (вариант А доп. (155)) доводятся до конца на общих правках цикла и общем бюджете, без подсказок. Сравнение с Б — с указанием пинов, состава приёмки и версий цикла обеих сторон: без этого разница не отделяет пакет от изменений спеки.
12. **Кто что делает:** задание варианта Б — coord103-src (доп. (155)); проба Б идёт на выгрузке, собранной после починки известных пробелов (доп. (156), нормы З-21 по общим договорам, договор D7 доп. (11), форма `assembly.yaml`, грамматика ворот этапов, находки P/01 пп. 9–14, ADR-0125 доп. (10)) и зелёной полной проверки main — иначе уже известные пробелы запишутся как находки эксперимента; `d5e760` — только для черновой проверки задания; запуск и выбор пина — владелец (исполняет представитель, доп. (155) п. 3); цикл и профили — представитель; судьи, сценарии, нормы и пробелы — раннер, spec103, Архитектор по их ролям.

### Consequences

* Good, because вердикт доказателен в обе стороны: вход — только спека, судья независим, адаптер не может подменить продукт, итог читают не те, кто ведёт цикл.
* Good, because каждый провал раскладывается на «модель», «цикл» или «пробел спеки», и пробелы чинятся в норме для всех будущих генераций.
* Good, because один движок с профилями проще поддерживать, чем несколько циклов.
* Bad, because без пакета модель пишет заметно больше (каркас, адаптеры, тесты) — дольше и дороже, чем пробы 41–45b.
* Bad, because часть провалов будет пробелами спеки; до их починки проба стоит.
* Bad, because судье нужны новые средства (отрицательный контроль, изоляция ожиданий), а читателям — время.
* Bad, because без векторов и сценариев во входе (доп. (1)) модели труднее отлаживаться, а нормы, которые держались на векторах, всплывут пробелами; подгонку под опубликованное это снимает.
* Bad, because бюджет (доп. (2)) задан по опыту проб с пакетом (45b: 10 из 15 этапов P/01 за 38 млн токенов и ~3 ч); без пакета он может оказаться тесным — пересматривается только словом владельца и не во время зачётной пробы.

### Confirmation

* Задание варианта Б не содержит пакета, вывода генераторов и частных привязок: подготовка задания отказывает машинно при ключах `kit`, `seed_readonly`, `read_deny`, файлах `*-PRIVATE-BINDING.md` и готовом `acceptance.yaml`; список «дано / не дано» — `PROFILES.md` раздел 1 на коммите, записанном в паспорт.
* Паспорт пробы: версия цикла **на каждый ход**, разница цикла между ходами, бюджет, попытки, предел кругов, правило окончания, пин выгрузки и задания.
* Отрицательный контроль адаптеров на каждой цели: над сломанной сборкой — красное; иначе — ошибка средства, не PASS.
* Журнал пробелов спеки: что, кто признал (Архитектор), судьба (норма, коммит).
* Отчёт читателя журнала (ревьювер другого провайдера): подсказок с ответом нет, правки цикла общие по п. 7.
* Итог по уроку: пройдены ли этапы 1–4 раннером; токены и время по этапам; сравнение с 44/45b с пинами обеих сторон.
* Критерий итога эксперимента: **доказано**, если P/01, затем P/02–P/10, проходит этапы 1–4 включая боевую приёмку только по выгрузке в пределах бюджета (доп. (2): 150 млн входных токенов и 24 активных часа на урок), и читатели (п. 4, п. 8) не нашли подмены и подсказок; **опровергнуто**, если после починки подтверждённых пробелов спеки и общих правок цикла этап не проходит в пределах того же бюджета за (доп. (2)) и (доп. (2)).

## Pros and Cons of the Options

### А. Один движок, профили, этапы

* Good, because доказательно и экономно.
* Bad, because профили и средства судьи надо доделать постепенно.

### Б. Отдельный цикл на каждый вид кода

* Good, because каждый цикл проще сам по себе.
* Bad, because общая механика (судья, детектор застоя, учёт, видимость ошибок) копируется и расходится.

### В. Прежний цикл с пакетом и подсказками

* Good, because быстрее доходит до зелёного.
* Bad, because ничего не доказывает о генерации с нуля — это воспроизведение.

## Дополнение (1), 2026-11-08 — векторы и сценарии не идут во вход модели (слово владельца)

Довод владельца: «разве в спеке не написано, как должен работать код, почему при этом важно знать результат на вход». Заменяет п. 1 решения в части входа и ADR-0083 доп. (155) п. 1.

1. **Вход модели** — нормы, формы, схемы, договоры и протоколы. Векторы и сценарии — только у судьи. Отдельный скрытый набор не нужен.
2. **Отчёт судьи** сообщает модели имя случая, якорь нормы и класс расхождения, но не ожидаемый ответ.
3. **Вектор как единственное определение** (точные байты, порядок полей, текст отказа) — пробел нормы: правило переносится в текст нормы или форму. Явно названный пример в норме допустим.
4. **Страховка:** отрицательный контроль адаптеров и детектор литералов.
5. **Цена:** в первых пробах всплывёт больше пробелов; модели труднее отлаживаться. Бюджет, попытки и круги — доп. (2).
6. **Следствия:** выгрузка для варианта Б без векторов и сценариев; протокол отчёта судьи без ожиданий — раннер; перенос определяющих векторов в нормы — писатели.

## Дополнение (2), 2026-11-08 — бюджет и правило окончания зачётной пробы (слово владельца)

Слово владельца 2026-11-08: «да» на предложение представителя.

1. **Бюджет на урок:** 150 млн входных токенов (с кэшированными) и 24 активных часа работы модели и судьи. Входит всё: повторы, `--resume`, второй агент, ходы после правок цикла. Превышение — урок в этом круге не прошёл.
2. **Застрял этап:** 3 хода подряд без сдвига счёта судьи на этапе. Тогда Архитектор относит провал к модели, циклу или пробелу спеки (п. 8). Модель — урок в этом круге не прошёл; цикл — правка цикла общая, проба продолжается в том же бюджете; пробел спеки — круг заканчивается, норма чинится.
3. **Круги:** не более 3 кругов «пробел → новая выгрузка → проба с пустого `work/`» на урок; бюджет п. 1 — на каждый круг.
4. **Итог урока:** **доказано** — урок проходит этапы 1–4 включая боевую приёмку в бюджете одного круга, читатели (п. 4, п. 8) не нашли подмены и подсказок; **опровергнуто для урока** — после 3 кругов урок не прошёл. Итог эксперимента — по урокам P/01–P/10.
5. Пробы до утверждения всех условий п. 10 (паспорт, читатели, средства судьи) — разведочные; их итог не засчитывается.

## Дополнение (3), 2026-11-08 — пара выгрузок: модели и судьи (решение Архитектора на вопрос coord103-src)

По доп. (1) модель получает выгрузку без векторов и сценариев, а судье нужен полный набор. Это разные коммиты, даже из одного коммита курса C; раннер же сверяет `spec_version` и `SPEC_VERSION` с одним внешним пином (`runner/assembly.py`, функция `version`). Выдать одну выгрузку за другую или подставить C нельзя.

1. **Две неизменяемые выгрузки из одного C:** M — модели, без векторов и сценариев; J — судьи, полная. Пин пробы — пара. Паспорт записывает C, M, J и идентичность фильтра. Смена любой из них — новый зачётный срез (п. 10). Пару выбирает владелец (п. 12).
2. **Рабочий каталог и профиль привязаны к M** — действующая сверка раннера не меняется. J раннер принимает только для объявленной пары и проверяет её: тот же фильтр над J даёт дерево M, оба из C. Общего отката на один пин и подмены маркера нет.
3. **Отклонено:** один J и проекция для модели вне Git. Тогда в рабочем каталоге лежат не те файлы, на которые указывает `SPEC_VERSION`, и нужна отдельная идентичность проекции.
4. **Изоляция (к п. 4 решения).** В M нет объектов J, ссылок на него, перечня фильтра и хэшей случаев судьи. Никакой процесс, написанный моделью (адаптеры, стенд), не читает J, его Git, ожидания и сырые отчёты: он получает только вход своего случая, обратная связь — по доп. (1) п. 2.
5. **Следствия:** проверка пары и изоляция J — раннер (шаг 4), доставка двух выгрузок — coord103-src и ops103 (шаг 6). Имена флагов и форму объявления пары выбирает раннер; новых полей профиля это дополнение не задаёт. Фактической выгрузки до условий шага 6 нет.

## Дополнение (4), 2026-11-08 — уточнения пары выгрузок по ревью доп. (3) (решение Архитектора)

Три рецензента нашли, что фильтр и состав M не определены. Разбор: `decisions/inbox/ревью/2026-11-08-ADR-0133-доп3-разбор.md`. П. 6 заменяет первую фразу п. 4 доп. (3); остальное уточняет доп. (3).

1. **Фильтр** — один файл в курсе. Автор и выбор пути — coord103-src (доп. ADR-0083 (144)). Файл входит в J и не входит в M. Идентичность фильтра — его blob на C. Он меняется обычным коммитом с ревью другого провайдера. Смена фильтра — новый зачётный срез.
2. **Что делает фильтр.** Убирает только целые файлы и ничего не переписывает, поэтому M — точное подмножество J. Маркеры доставки, называющие собственный коммит выгрузки, перечислены в фильтре и в сравнение не входят.
3. **Состав M.** Критерий: файл идёт в M, если задаёт правило, и не идёт, если задаёт случай или ожидаемый ответ.

   | Вид файла | M |
   |---|---|
   | нормы, формы, схемы, договоры, `stages.tsv` | да |
   | `PROFILE.md`, README приёмки и `wire.md` | да, если без случаев |
   | договор адаптера, порождённый из `wire.tsv` | да |
   | таблицы случаев и фикстуры `vectors/**`, сценарии `acceptance/**`, `wire.tsv`, `*.cases.json`, корпус вердиктов | нет |

   Файл, где правило смешано со случаями: случаи выносятся, файл идёт в M; делает писатель по делению ADR-0083 (151). Спорный вид — к Архитектору. Имена и число случаев в нормах допустимы: модель и так получает имя случая (доп. (1) п. 2). Ожидаемые ответы недопустимы.
4. **Проверка пары (к п. 2 доп. (3)).** Раннер берёт фильтр из J и сверяет его blob с паспортом. Фильтр над J даёт дерево M. Маркер `COURSE_COMMIT` обеих выгрузок равен C. В M нет ни одной таблицы из перечня `wire.tsv` и ни одного сценария; фильтр, который ничего не убрал, здесь не проходит. Пара объявляется там же, где внешний пин, вне рабочего каталога модели. Проверка ловит ошибку подготовки, а не умысел выгружающей стороны: `cammeta-specs` модели недоступен.
5. **Адрес строк.** Профиль и `SPEC_VERSION` указывают на M. Строки, фикстуры и покрытие адресуются J, где они лежат. Паспорт пишет оба SHA. Текст `PROFILE.md` не меняется: «выгрузка» строки — та, где строка лежит.
6. **Граница объектов.** Общие файлы M и J — одни и те же объекты Git, это допустимо. Запрет действует на всё хранилище Git, доступное модели, и его ссылки: там нет файлов только для судьи, в том числе из прежних полных выгрузок. Родители M — только прежние M; ссылок, alternates и удалённого адреса J нет. Текстовая ссылка нормы на снятый файл нарушением не считается. Перечня фильтра и хэшей случаев в M нет.
7. **Кто не читает J.** Агент модели, второй агент, цикл и все процессы, написанные моделью. Цикл строит опись этапа 0 и `require` только по M. J доступна только учётной записи судьи, это держат права файлов, а не ключ задания. Судная сторона — раннер, права — ops103, цикл — представитель.
8. **Вход случая и вывод.** Для строки — входные столбцы. Для фикстуры — копия во временном каталоге, а не путь в J. Для сценария — аргументы текущего шага. Судимые процессы работают на копии кандидата; её файлы в `work/` не возвращаются. Модель получает поля доп. (1) п. 2 и ограниченный хвост stderr продукта с затёртыми секретами (п. 7 решения); предел выбирает раннер. Адаптер способен вынести вход через stderr; это закрывает чтение кода адаптеров (п. 4 решения) до вывода «доказано».
9. **Дефект пары** — не модель, не цикл и не пробел спеки. Проба на дефектной паре недействительна: итог не засчитывается, круг не тратится. Дефект признаёт Архитектор. Счёт кругов и бюджет доп. (2) не меняются.
10. **Confirmation.** Паспорт содержит C, M, J и blob фильтра. Раннер отказывает на несогласованной паре, на фильтре без изъятий и на M с таблицей случаев. Проверка прав подтверждает, что учётная запись модели не открывает J.

Цена: критерий п. 3 может оказаться слишком жёстким; нехватка правила в M всплывёт в пробе как пробел спеки.

## Дополнение (6), 2026-11-08 — изоляция судимых процессов, имена случаев, хвост stderr, дефект пары (решение Архитектора и слово представителя владельца)

Разбор трёх ревью пп. 8–9 доп. (4): `decisions/inbox/ревью/2026-11-08-ADR-0133-доп4-разбор.md`. Заменяет доп. (1) п. 2 в части имени случая, доп. (4) пп. 8, 9 и доп. (5) п. 3 там, где они расходятся с этим текстом.

1. **Три учётные записи.** Раннер с J; судимые процессы кандидата; оболочка модели. Судимые процессы не видят J и `acc/` и получают свои `/tmp`, `/var/tmp`, `/dev/shm`; копия кандидата создаётся на вызов и уничтожается после него. Причина: при одной учётной записи изоляция не держится правами.
2. **Имена случаев.** Правило: модель не узнаёт от судьи имён, которых нет в M. Имя случая только из J заменяется непрозрачным идентификатором, постоянным в пределах пробы; соответствие держит судья. Имена сценариев в воротах `stages.tsv` остаются: они уже в M. Судимый процесс получает непрозрачный `case` и копию только входных файлов своего случая под нейтральным именем. 3. **Вывод процессов.** Сырой вывод остаётся у судьи. Модель получает поля отчёта и хвост stderr по проваленным случаям, не больше 4 КиБ. Перед выдачей раннер вырезает из хвоста каждую подстроку от 8 байт, которая есть во входах, фикстурах и ожиданиях случая. Число вырезок пишется в паспорт и модели не показывается; ненулевое число — отметка читателю. Граница и способ затирания записываются в паспорт. Закодированный вынос эта вырезка не ловит, его ищет читатель.
4. **Дефект пары.** Закрытый перечень: повторённая на записанных C, M, J и blob фильтра проверка доп. (4) п. 4 не проходит; M несёт материал только для судьи; нарушена изоляция J. Повтор начинается с исходного снимка круга: для P/01 пустой `work/`, без кода, заметок, контекста агентов, ответов судьи и отметок этапов.
5. **Сбои и классы.** Собственный сбой раннера — дефект судьи, а не дефект пары: ход не идёт в счёт застоя, бюджет тратится (доп. (2) п. 1). Тайм-аут и сбой процесса кандидата — класс случая. Отдельный класс: «упала часть стенда вне кода кандидата», с названием части и кандидата-владельца, без путей J и ожиданий.
6. **Журнал для читателей.** На каждый раунд: отданный модели текст, хвост stderr, число вырезок, хэш дерева `work/`.
7. **Confirmation.** Канарейка: судимый процесс и команда модели пытаются открыть J и `acc/` и оставить файл, переживающий вызов; не выходит. Заглушка продукта пишет уникальный маркер входа в stderr; маркера нет в сообщениях модели. Ни одно имя случая только из J не встречается во входе и в обратной связи. Запись каждого дефекта пары: пункт перечня, артефакт, SHA, кто признал, расход.

Цена: модели труднее отлаживаться; это принято словом владельца в доп. (1).

## Дополнение (8), 2026-11-08 — средства проверки по итогам пробы Chiasmus (слово владельца)

Слово владельца «да» по итогам пробы Chiasmus 0.1.40 (Z3, SWI-Prolog, граф вызовов tree-sitter). Граф вызовов по Go оказался ненадёжен: он строит связи по голым именам, склеивает одноимённые функции и дал ложную достижимость. Z3 по формам работает: для строк 1–15 `write-checks.tsv` P/01 доказано, что `items` не меняет вердикт при `delete`.

1. **«Адаптер не обходит продукт» (шаг 4).** Главная гарантия — отрицательный контроль (п. 4 решения). В дополнение раннер применяет средства Go: `go list -deps` по пакетам адаптеров и граф вызовов по типам (SSA, `golang.org/x/tools`). Эта зависимость только у судьи и не входит в `Platform/common/versions/go.mod`, который ограничивает модель. Chiasmus в судью не включается.
2. **Z3 в проверке спеки — по выбору, для спорных таблиц условий с порядком** (`write-checks`, отказы, ворота): может ли X влиять на вердикт при Y, недостижимые строки, две строки с разным исходом. Z3 вызывается напрямую из Python, версия закреплена; Chiasmus необязателен. Перевод формы в SMT рецензирует другой провайдер и привязан к хэшу формы: изменилась форма — кодировка устарела. Обязательной частью `check_spec` Z3 не становится.

Цена: перевод одной формы вручную занимает 15–20 минут и требует ревью, поэтому Z3 применяется только к спорным формам.
