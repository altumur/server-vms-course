# Движок ObjectStorage развиваем сами в своём форке от `fed03dd`; наши патчи становятся его коммитами

## Context and Problem Statement

Класс системы: подсистема VMS — `obsd` (демон хранения) держит движок ObjectStorage и пишет архив регистратора.

До этого решения продукт собирал `obsd` из снимка монорепы NGP в `altumur/ObjectStorage`. Сборка копирует движок и 11 модулей NGP и накладывает на копию патчи 01–07. Переход на готовую библиотеку другой команды был принят 7 октября, но её PR 6 (`one/objectstorage`, ветка `mamuchiev/cpp_interfaces`) не содержит патчей 04–07.

Владелец решил дальше развивать движок сами, в своём продукте. Поэтому надо выбрать основу: перенести наши патчи на их отвязанную ветку или перенести их идеи в нашу копию.

## Decision Drivers

* движок нужен без чужих библиотек: снимок монорепы тянет 11 модулей NGP и 4197 файлов;
* патчи 01–07 нельзя потерять: ADR-0035 требует патч 07 для сетевых томов;
* в PR 6 есть исправления писателя и замка с тестами, которых нет в нашей копии;
* сборка нужна на macOS arm64, Linux arm64 и x86_64, armhf;
* формат на диске должен остаться тем, что читает VMS и что уже лежит на стендах.

## Considered Options

* форк от `fed03dd`, вершины PR 6, с переносом наших патчей;
* наша копия с переносом их исправлений и повторением отвязки;
* ждать, пока другая команда примет патчи 04–07.

## Decision Outcome

Выбран форк от `fed03dd`, потому что наши патчи переносятся на него дешевле, чем их отвязка и исправления переносятся на нашу копию.

Форк лежит в `/Users/murat/w2c/objectstorage-fork`, ветка `main`. Патчи 01–07 в нём стали семью обычными коммитами. Удалённый репозиторий для форка ещё не заведён: место выберет владелец, пока историю держит только этот каталог. Remote `upstream` смотрит на `one/objectstorage` и нужен, чтобы забирать их исправления вручную.

Запрет роли «DriverPack & ObjectStorage» править движок только патчами на этот форк не действует: движок правится обычными коммитами. Пока не выполнена проверка ниже, `obsd` и его сборка остаются в `altumur/ObjectStorage` и `standalone-build` работает как раньше.

Протокол `obsd`, Go-клиент и формат на диске это решение не меняет. ADR-0035 остаётся в силе: патч 07 теперь значит коммит форка `7901b81`.

### Consequences

* Good, because движок собирается без единого заголовка NGP, а сэмплы, логгер и потоки приходят от хоста через `api/`.
* Good, because `obsd` получает исправления писателя и замка из PR 6, например `dfe16cd`, `30b5abb`, `689639d`, `866c092`, и `38ba4a9` для S3.
* Good, because патчи больше не накладываются на копию при каждой сборке.
* Bad, because тесты движка в PR 6 собираются только внутри ngp: до своего тестового хоста форк не запускался ни разу.
* Bad, because `obsd` надо перевести на Host API: класс сэмпла и сериализатор, адаптер логгера, реактор на том.
* Bad, because исправления другой команды теперь переносим вручную, а файл-копию `src/FileIO` ведём сами.
* Bad, because совмещение патча 07 с их `ReleaseWriteLock` в `Shutdown` проверено только компиляцией.

### Confirmation

Решение выполнено, когда `standalone-build` снят, а до этого пройдены все шаги:

1. Движок форка собирается на macOS arm64 и Linux arm64 с S3 и Azure, на armhf без них. Сделано 2026-10-31 на `7901b81`, собрана только библиотека.
2. Тесты движка собраны на своём тестовом хосте и зелёные на macOS, Linux и armhf, включая стресс-тест замка `939aa0d`.
3. `obsd` работает на Host API, `obsd_ut` зелёный.
4. На стенде `obsd` читает существующие тома, а `WRITER_ABANDON` работает на двух хостах.

## Pros and Cons of the Options

### форк от `fed03dd`

* Good, because 21 отвергнутый ханк из семи патчей решён за один проход, часть из них уже была сделана в PR 6.
* Good, because отвязка от NGP уже сделана.
* Bad, because нужны свой тестовый хост и перевод `obsd`.

### наша копия с их исправлениями

* Good, because `obsd` и тесты работают на ней уже сейчас.
* Bad, because только исправления дают 31 отвергнутый ханк, если накладывать по порядку.
* Bad, because отвязку пришлось бы повторить: 83 файла движка и `src/FileIO`.

### ждать другую команду

* Good, because не надо вести движок самим.
* Bad, because противоречит решению развивать движок самим; сроков по патчам 04–07 нет.
