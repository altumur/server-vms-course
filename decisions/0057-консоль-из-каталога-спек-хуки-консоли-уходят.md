# Консоль из каталога спек (`cmd/console`); последние хуки консоли уходят в декларации

## Context and Problem Statement
Консоль продукта собирает подсистема (`vms.NewConsole`): корень vms, монтирует rec, live, auto и ставит им хуки
`ConsoleOptions`:
- `Page` — встроенная оболочка;
- `Media` — флаг `/spec.media`;
- `Extra` — свои маршруты: витрина `/servers/<s>/writes`, `/published`, тома и печати rec;
- `ServersExtra` — `volumes_missing` по серверу из биений рекордеров;
- `Writes` — проверки записи.

Ещё она ставит гейту `Needs` (`needsOf`, все пути зашиты). Платформенный бинарь консоли по каталогу спек (ADR-0014,
группа `w2c-console`; ГРАНИЦА §2.3, §3, §4) ставить хуки не может: каждый хук должен уйти в декларацию, в воркер или
в страницу (ADR-0002).

## Decision Drivers
* Консоль процесса — платформенная: спеки из `SPEC_DIR`, корень по `CONSOLE_ROOT`, как курсовой `host.build_console`.
* Смысл хука — в спеке, в воркере или на странице; ключ только если он нужен двум спекам или `testsub`.
* Правило перехода «старое → новое» схема поля не видит.

## Considered Options
* Оставить `vms.NewConsole` хостом консоли продукта.
* Платформенный `cmd/console`, а каждый хук — по месту его смысла, по окнам.

## Decision Outcome
Выбран второй вариант. Окна по порядку:
1. **Платформа, без решений.**
   - `Page` → файл `<root>.shell.html` рядом со спекой: его отдаёт только корень, иначе платформенная страница
     (контракт консоли §1).
   - `Media` и `/spec.media` уходят.
   - `Gate.Needs` → правило платформы по курсовому `needs` (`specNeed`).
   - `/servers/<s>/writes` и `/published` → маршруты `Mount` по каталогу спек.
2. **`Writes`** → `schema`, `ref`, `unique`, `enum` полей. Глубже проверяют воркеры, отказ говорится в биении
   (ГРАНИЦА, вопросы 2 и 3).
3. **`Extra` rec** → `tables:` спеки. Вычисляемое в виде томов делает оболочка. `verify` печати — через дверь
   рекордера (`/where`, ADR-0015).
4. **`ServersExtra`** → ключ `servers.status`.
5. **`cmd/console`** — после того как проходы vms из консоли ушли в свой воркер. Юнит `w2c-console`, пользователь
   `w2c`. `vmscam` пока свой хост.

Два решения «Архитектора»:
- **Уменьшение квоты тома без подтверждения** — правило воркера и страницы, ключа нет. Рекордер не применяет
  неподтверждённое уменьшение (`shrink_confirmed` должен говорить то же число, как курсовой
  `RecWorker._apply_quota`) и говорит об этом в биении; оболочка спрашивает второе слово. 409 консоли был лишним
  стражем продукта.
- **`servers.status: [{field, title}]`** рядом с `servers.show`. `/servers` кладёт в строку воркера названные поля
  его биения как есть; платформа их не понимает, свод по серверу делает оболочка (`volumes_missing`, «уменьшение не
  подтверждено»). Нужен rec и `testsub2`.

### Consequences
* Good, because консоль собирается из спек, а у консоли не остаётся хуков подсистемы.
* Good, because права консоли — одно правило платформы по спекам, а не список путей подсистемы.
* Bad, because пять окон, и в каждом половина «Сборки»: спеки vms, оболочка рядом со спекой, перенос проверок в
  воркеры и проходов консоли — в свой воркер.

### Confirmation
Тесты продукта:
- оболочка у корня и платформенная страница у маунта, нечитаемая оболочка — отказ загрузки;
- таблица правила `specNeed`;
- платформенные тесты гейта на правиле, а не на заглушке;
- далее по окнам — витрина и `/published` на `testsub`, `servers.status`, `cmd/console` на `testsub`.

Курс: `servers.status` в загрузчике и `/servers`; проверка соседа и прочее — по своим ADR.

**Добавление 2026-10-06, п. 3 («Архитектор»; разницы курса и продукта в проверке печати сохранённого).**
* **Печать ставится один раз и живёт не в таблице `keeps`.** Это запись подсистемы о своём архиве, как метка
  просьбы: своё семейство `rec/sealed/<keep>` в `objects.rows` спеки rec. Пишет его **рекордер тома incidents** —
  тот, кто держит копию и считает sha256, — своей ролью воркера, по CAS и один раз, когда копия у него целиком
  (уточнение того же дня: `objects.rows` даёт запись роли воркера, консоли только чтение; такт консоли был
  пересказом биения рекордера и ушёл). Дверь таблиц это семейство не обслуживает, и оператор записать печать не может по
  построению. Проверка на двери читает печать оттуда.
  * Почему не поле таблицы: необъявленный ключ в строке — строка не по спеке (ADR-0012), а «читатели пропускают
    неизвестное» прячет мусор; объявленное поле открыло бы печать любому с правом правки.
  * Печать привязана к интервалу: несёт `recordings: a=<sha>,…`, `from`, `to`, `sealed_at`. Оператор, переписавший
    строку сохранения, получает «не запечатано» по несовпадению интервала, и следующий такт печатает заново.
  * Байты `objects.rows: […, sealed/*]` в rec на обеих сторонах кладёт «Паритет»; новых ключей загрузчика нет.
    Продукт переносит `sealed`/`sealed_at` из строки в это семейство («Сборка»).
* **Испорченный интервал → 409** на любую нечитаемую часть, не только на конец. Хэш наполовину прочитанного
  интервала — догадка. Продукт приводится к курсу.
* **Ошибка хранилища — в форме продукта, без путей** (`StoreFault`): путь в ответе двери снаружи никому не нужен.

**Добавление 2026-10-06 («Архитектор»).** Всё, что `needsOf` vms делал сверх курсового правила, ложится в
существующие ключи спек (`rights.routes`, `rights.unit_of`, `rights.cluster_rows`, `rights.reach.group`) или в страницу
(`unit` в теле отметки). Смена тома записи (`home` у rec) — `rights.reach.cluster: [home]`: это решение о месте,
которое делят другие, и грант кластера — правда о том, кого оно касается. Ключа «смена поля достаёт до юнитов на
месте» нет: он нужен одной спеке. `?unit=` у места, если это не юнит подсистемы места, — 400 до вопроса о правах
(вопрос без ответа, ADR-0031).
`backupOfOthers` на создание не переносится: создание на разделяемый том спрашивает только свою камеру, место держат
квоты и рекордер («Архитектор» 2026-10-06; кто может лечь на место — `admits`/`strict` строки тома, ADR-0056).

**Добавление 2026-10-06, п. 1 («Архитектор»).** `GET /published?prefix=` удаляется без замены: вызывающих в дереве нет
(ни страница, ни инструменты, ни тесты), а дверь без читателя — поверхность без пользы (ADR-0003). Витрина
`GET /servers/<s>/writes` у `Mount` по каталогу:
- (а) не показывает ни одной строки с читателями секретов (`SecretReaders`): по `*_secret` отбора мало, туда попадал
  `door/signer`;
- (б) требует view на весь кластер (`Unit: "*"`): показывает строки всех юнитов; admin не нужен, а отбор по юниту не
  покрыл бы строк без юнита;
- (в) печатает значения так, как любая дверь, через правила секретов каталога (`*_secret` нет, адреса без паролей), а
  не сырыми байтами хранилища: витрина — аудит «кто что написал», а не вторая дверь к данным.

**Добавление 2026-10-06, п. 2** → ADR-0064 (`servers.status[].field` — путь к любому значению биения; `of: <таблица>`).
