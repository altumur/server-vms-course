# Держатель не возит членам гранты выключенного человека

## Context and Problem Statement
Платформенная система (домен — служба платформы, ADR-0024). Людей держит держатель домена (`domain/users/<имя>`,
запечатано ключом кластера); член видит только гранты своего кластера, которые привозит агент (`carry`). Выключенный
человек не может войти: держатель отказывает ему в токене. Но его гранты у членов остаются, и токен, выданный до
выключения, работает у членов до конца своего срока. На отладочном входе ADR-0050 то же: дверь, которая не читает
людей (консоль кластера, консоль домена), узнаёт человека по грантам и выключенного не отличит. Найдено при
отладочном входе 2026-10-05 («Платформа продукта», «Сборка»).

## Decision Drivers
* окно отзыва не больше периода carry плюс срока токена (ARCHITECTURE §1.8; шаг 7 части 2);
* член не читает людей и не должен: строки людей — секреты держателя;
* выключение обратимо: включённый снова человек получает гранты обратно без правки таблиц администратором.

## Considered Options
* член читает список людей домена;
* держатель стирает гранты выключенного из таблиц грантов;
* держатель не возит гранты выключенного: при сборке carry строки, чей субъект — выключенный человек, опускаются.

## Decision Outcome
Выбран третий вариант.
- Объявленные таблицы грантов (`domain/grants/<кластер>`) остаются как их написал администратор.
- Держатель при сборке carry для члена опускает строки, чей субъект — выключенный человек. При ближайшем carry член
  заменяет свои гранты привезёнными и выключенного забывает.
- Включённый снова человек возвращается со следующим carry.
- У кластера-держателя, который читает свои гранты там, где их пишет домен, действует то же правило. Домен публикует
  несекретный список выключенных имён, и доступ кластера на держателе их строки не засчитывает.
  - Писатель списка один — проход signer. Список — часть опубликованного вида или отдельная строка `domain/disabled`,
    не вторая истина в памяти консоли.
  - Секретов в списке нет: те же сведения член получает неявно, по отсутствию гранта.
- Это относится и к отладочному входу ADR-0050: дверь, узнающая человека по грантам, выключенного больше не найдёт.

### Consequences
* Good, because выключение действует у всех членов за период carry, и для живых токенов, и для отладочного входа.
* Good, because таблицы грантов не переписываются при выключении, и включение не требует их восстанавливать.
* Bad, because у держателя появляется ещё одна публикуемая строка — список выключенных имён — и её надо держать в
  согласии со строками людей.

### Confirmation
Выключенный человек с живым токеном получает отказ у члена после ближайшего carry. Включённый снова — снова
допущен после следующего carry. На кластере-держателе выключенный человек с живым токеном получает отказ сразу после
выключения — проверяется через консоль кластера-держателя, не через signer. Тесты на `testsub`/`testsub2` платформы; курс — тем же правилом в `Source/w2cplatform/domain`.
