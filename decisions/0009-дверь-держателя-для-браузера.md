# Дверь держателя для браузера: короткий токен, подпись ключевой парой

## Context and Problem Statement
Страница идёт за байтами на дверь держателя единицы (ADR-0002). Cookie сессии привязана к хосту консоли и не работает на другом сервере кластера; `<video>` и `<img>` не ставят заголовков.

## Decision Drivers
* ADR-0001: выдача токена, ключ, проверка подписи и CORS это платформа; содержимое маршрутов это воркер;
* `../ARCHITECTURE.md` §1.8: делегируй полномочие, никогда не раздавай секрет.

## Considered Options
* cookie сессии с `credentials: include`;
* общий HMAC-ключ у всех держателей;
* дверной токен, подписанный ключевой парой, который держатель проверяет открытым ключом.

## Decision Outcome
Выбран токен. `GET /where/<id>` отдаёт `door: {url, token, expires}`; токен на 120 с, продлевается через `/where`; несёт пользователя, единицу, id держателя и только читающие маршруты из `door: {routes: [...]}` спеки; выдаётся после проверки гранта пользователя на единицу; `?t=` только там, где заголовок невозможен, иначе Bearer; дверь маскирует `t` в логах; CORS только origins консолей кластера из конфигурации развёртывания; проверка подписи в платформенном пакете, который воркер импортирует. Платформа отвечает `/where` и за место (`/where/<table>/<place>` по `placement.places`), место без держателя даёт `X-Unreachable`.

### Consequences
* Good, because ни один воркер не держит секрета выдачи.
* Bad, because токен живёт короче сеанса просмотра, страница обязана продлевать его вовремя.

### Confirmation
Тесты двери: токен другого держателя, истёкший, на маршрут вне `door.routes`, без гранта на единицу отказываются; оболочка в jsdom ходит за байтами только на `door`.
