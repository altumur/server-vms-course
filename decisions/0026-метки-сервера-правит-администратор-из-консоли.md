# Метки сервера правит администратор из консоли; метки узла — первое значение и запасной вариант

## Context and Problem Statement
Класс системы: платформенная система (размещение).

Метка сервера говорит, до каких сегментов сети он дотягивается (`vlan:cctv`); контроллер ставит камеру только туда, где метки сервера покрывают метки камеры (`labels-subset`). Метки сервера задавались в настройке узла (`meta.labels` в `client.hcl` Nomad, потом `LABELS` в окружении), и, чтобы их поменять, администратор правил файл на сервере и перезапускал процессы. Метка камеры при этом правится в консоли.

## Decision Drivers
* метка — утверждение о физике сети, и правит его человек в одном месте, рядом с камерами того же формата;
* смена метки не должна требовать перезапуска воркеров;
* консоли не нужны права на узел и на оркестратор.

## Considered Options
* менять метаданные узла оркестратора из консоли (`nomad node meta apply`);
* строка меток сервера в хранилище, которую пишет консоль; метки узла остаются первым значением и запасным вариантом.

## Decision Outcome
Выбран второй вариант. Администратор правит метки сервера в консоли (`PUT /servers/<server>/labels`, `DELETE` возвращает метки узла), консоль пишет строку меток сервера в хранилище. Контроллер берёт метки сервера из строки, если она есть, иначе — из `LABELS` узла. Консоль показывает оба значения, когда они расходятся. При смене меток сервера или камеры контроллер переносит камеры, которые сервер больше не видит, ограниченно за проход (`EnsureReach`); если не видит никто — камера попадает в `/unplaceable`.

### Consequences
* Good, because метку меняют без перезапуска и без прав на узел; поведение одинаково при смене меток камеры и сервера.
* Bad, because у метки два источника (строка и узел), и консоли приходится показывать расхождение.

### Confirmation
Тесты продукта на правку меток сервера и переезд по `EnsureReach` (`vms/serverlabels*_test.go`); в курсе — `set_server_labels`, `ensure_reach` в `w2cplatform/spec.py` и `console.py`, записки `three-cameras` 4.1.

## Pros and Cons of the Options

### Метаданные узла из консоли
* Good, because один источник.
* Bad, because консоли нужно право на узел, работающий воркер новую метку не увидит без перезапуска, оркестратора в кластере больше нет (ADR-0021).

### Строка в хранилище
* Good, because без перезапуска и без прав на узел.
* Bad, because два источника.

## More Information
По ADR-0001 строка меток переезжает из `vms/servers/<server>` в `platform/servers/<server>` на шаге 7 плана `../ГРАНИЦА-ПЛАТФОРМЫ-И-ПОДСИСТЕМЫ.md`, одна на сервер.

**Добавление 2026-10-06 («Архитектор»; записала «Платформа продукта»).** Маршрут `GET/PUT/DELETE /servers/<server>/labels` стоит у корня консоли (`Mount`), как `/drain`, а не у подсистемы: строка одна на сервер, и метки — вопрос о сервере. Поэтому `would_move` и `will_move` — один список ссылок `<sub>/<id>` по всем спекам консоли, с фильтром по праву `view`, а `servers_known` считается по всем подсистемам и ресурсам. Чтение строк — курсовое (`server_labels`): нечитаемая строка держит прочитанное раньше; листинг без ответа и процесс, ни разу не читавший, говорят «не знаю», и `EnsureReach` ничего не переносит. Хуки продукта `ServerLabels`/`LabelsUnread` уходят. Курс на шаге 7 делает то же.
