# Конвейер ADR: ревью, нормы, пробы по стадиям, у каждой стадии виден ход

## Context and Problem Statement

Класс системы: порядок работы над спецификацией.

Сверка ADR-0102…0113 показала: пять ADR не проходили ревью текста, 15 пунктов остались без нормы, 43 строки расходятся с нормами. Дополнения шли быстрее проверки, а отчёт Сторожа брал статус из отстающего файла. Владелец: «все адр должны проходить ревью, после этого правится нормы, потом пробы (по обновленной схеме в несколько этапов с показом каждого этапа)»; «поручим Сторожу отслеживать и напоминать».

## Decision Drivers

* нормы не должны опережать проверенное решение;
* статус не ведётся по памяти сессии;
* новое дополнение нельзя потерять.

## Considered Options

* статус на ADR целиком: «прошёл ревью, нормы есть»;
* отметка стадии дополнением: номер последнего дополнения, прошедшего стадию.

## Decision Outcome

Выбрана отметка дополнением: у ADR-0113 25 дополнений, статус на весь ADR устаревает с каждым новым, а номер показывает отставание сам.

1. **Порядок.** ADR → ревью текста → разбор → нормы → ревью норм → проба. Нормы не вносятся до ревью текста. Дополнение идёт тем же путём; малое дополнение проходит ревью строкой, пачкой за день, но не пропускается.
2. **Стадии пробы** (ADR-0083, В-7): чтение с таблицей «шаг × сбой» (`read`), второй читатель и закрытие (`second`), инварианты (`invariants`), Quint для протоколов с обрывами и повторами (`quint`). Каждая видна отдельно.
3. **Источник.** `decisions/adr-pipeline.tsv`: строка на ADR, в колонке — номер последнего дополнения, прошедшего стадию, `0` — основной текст, `-` не проходил, `н/н` не нужно. Ведёт «Архитектор» при вливании разбора.
4. **Отставание считается само:** наибольшее `## Дополнение` файла против колонки. Руками ничего не пишется.
5. **Показ.** Отчёт Сторожа, раздел «Конвейер ADR»: таблица ADR × стадии, отставшая клетка красная с числом дополнений, у клетки ссылка на отчёт. Сводка сверху: сколько ADR на какой стадии.
6. **Напоминание.** Сторож раз в проход шлёт «Архитектору» строку: ADR, стадия, сколько часов стоит; норма вошла раньше ревью — отдельной строкой. Срок стадии без движения при идущей работе — сутки.
7. **Перечень пунктов.** `decisions/adr-norms.tsv`, пункт → норма или статус, суд в `check_spec`: новое дополнение без строки красно (план 4.14).

### Consequences

* Good, because отставание видно без памяти сессий, а норма не обгонит ревью.
* Bad, because на каждое дополнение есть ревью: скорость правок падает, пачка за день это смягчает.

### Confirmation

Раздел «Конвейер ADR» заполнен, Сторож напоминает об отставшей стадии, `check_spec` судит `adr-norms.tsv`.
