# Канонический JSON подписанных документов — RFC 8785 (JCS), одна таблица golden-векторов на обе стороны

## Context and Problem Statement
Класс системы: платформенная система.

Подписанные документы домена (записи держателя, наборы ключей, копии, просьбы членов) подписываются поверх
канонического JSON. Курс канонизирует `json.dumps(sort_keys=True, ensure_ascii=False)`, продукт — `json.Marshal`: Go
экранирует `<`, `>`, `&`, а `1.0` после разбора пишет как `1`. Внешнее ревью 2026-10-11 показало: документ, подписанный
курсом, продукт отвергает при `A&B <gate>` и при числе `1.0`. Пока курс и продукт не проверяют подписи друг друга в одном
домене, это не инцидент, но контракт провода один (ADR-0019, правило 5 СЕССИИ), и расхождение в байтах подписи — это
расхождение контракта.

## Decision Drivers
* одна форма байтов на обе стороны, проверяемая таблицей, а не чтением двух реализаций
* стандарт вместо своего канона: меньше решений, которые надо помнить
* числа, Unicode, экранирование и порядок ключей — каждое должно быть названо явно

## Considered Options
* RFC 8785 (JSON Canonicalization Scheme, JCS).
* Свой канон «как у курса» (сортировка по кодовым точкам, без экранирования, числа как написаны).
* Запретить в подписываемых документах всё спорное (HTML-символы, нецелые числа) и оставить две реализации.

## Decision Outcome
Выбран RFC 8785 целиком, без отступлений: объекты с ключами по порядку кодовых единиц UTF-16 (не кодовых точек:
для символов вне BMP порядок иной — векторы это ловят), без пробелов, строки в UTF-8 с экранированием только
управляющих, `"`, `\\` (без `\\uXXXX` для остального и без HTML-экранирования: в Go `SetEscapeHTML(false)` и свой
обход, в Python не `sort_keys`, а сортировка по UTF-16), числа — кратчайшая форма ES6 `Number.prototype.toString`
(`1.0` → `1`, `1e21` → `1e+21`, `-0` → `0`, `NaN`/`Infinity` — отказ). Таблица golden-векторов `testdata/canonical_json.tsv`
(вход → канон → sha256) — общая таблица паритета, байт в байт, обе стороны прогоняют её тестом; в ней обязательны:
`<>&`, `1.0`, `1e21`, `-0`, вложенность, ключ вне BMP, управляющие символы, пустые объект и список. Первым кладёт
продукт — у него подписи в поле; курс догоняет. Смена канона меняет байты подписи: подписанные записи домена на стенде
не читаются старым каноном — переподписание плановой передачей срока (ADR-0066) после выкладки, по учению; совместимости
со старым каноном нет (ADR-0003).

### Consequences
* Good, because подпись курса проверяется продуктом и наоборот, и это доказано таблицей.
* Good, because стандарт с готовыми тест-векторами и реализациями.
* Bad, because одна выкладка с переподписанием записей домена на стенде; старые подписанные документы невалидны.
* Bad, because сортировка по UTF-16 в Python — своя функция, а не `sort_keys`.

### Confirmation
Тест таблицы на обеих сторонах зелёный; подписанные фикстуры ревью (`review-2026-10-11/evidence/signed-documents.json`)
проверяются Go после смены канона; учение переподписания на стенде: все девять членов на новом сроке читают записи.
