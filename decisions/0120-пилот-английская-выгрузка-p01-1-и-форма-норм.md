# Пилот: английская выгрузка P/01.1 и форма норм (таблицы проверок, автомат опроса)

## Context and Problem Statement

Нормы курса — русская проза. Её прочтения расходятся: опрос `pre` в ADR-0115 переписан десять раз, с (28) по (37), и каждое ревью находило ещё одно неверное прочтение. Генераторы-модели читают русские нормативные слова как собственное соглашение курса, а русский текст стоит им больше токенов. Обвес MiniMax считает 2,9 знака на токен.

Нужно проверить мерой, а не верой, два хода:
- английская выгрузка в строгом синтаксисе требований;
- запись части норм в форме, из которой код выходит механически.

## Decision Drivers

* Мерило — одна и та же линия генерации (обвес MiniMax, ADR-0083 доп. (60) и далее) на одном уроке.
* Нормы курса остаются русскими (`doc-language.mdc`): английский текст — производный, номера норм совпадают один к одному.
* Форма — там, где проза уже подвела: порядок проверок команды и опрос голосующих.

## Considered Options

* Вся выгрузка по-английски сразу — дорого и без меры.
* Пилот на одной главе с мерой против русской версии — выбран.
* Декларативный язык на все нормы — после пилота формы, отдельным решением.

## Decision Outcome

Пилот из двух частей.

1. **Английская выгрузка P/01.1.**
   - (а) «Спецификация» пишет `Platform/01-store/spec/en/01.1-store.norms.en.md`. Требования — шаблонами EARS (When / If … then / While / The … shall), нормативные слова — по RFC 2119 и 8174 (MUST, MUST NOT, SHOULD, MAY), процедуры — нумерованными алгоритмами в стиле спецификаций WHATWG («1. Let … 2. If …, return …»). Номера норм, ссылки, коды и слова отказов — те же, что в русском тексте. OpenAPI, схемы, таблицы и векторы не меняются.
   - (б) `check_spec` сверяет русский и английский тексты: один набор номеров норм, одни ссылки, одни коды и слова отказов. Расхождение — отказ. Это доля «Спецификации».
   - (в) «Архитектор» добавляет в `tools/export.sh` вариант английской выгрузки: P/01.1 из `spec/en/`, остальное — как в русской, пин свой. Поиск утечек — как у русской.
   - (г) Мера — две попытки обвеса MiniMax на P/01, русская и английская, на одном обвесе. Сравниваются на целях P/01.1 (door, inproc, extra): число догадок в `GUESSES.md` по 01.1, пройденные проверки, токены на голову и на попытку (вход вне кэша, кэш, выход — порознь), находки ревью английского текста.
2. **Форма норм.**
   - (а) **Таблица проверок команды P/01.1 (Н2.1).** Порядок проверок — строки по порядку: номер, условие на CEL над телом команды и состоянием, исход (код, слово). Таблицу пишет «Спецификация» рядом с нормой. Норма ссылается на таблицу, а не повторяет её прозой.
   - (б) **Автомат опроса P/02.4 Н1.9 (`poll`).** Состояния, события (партия, ответ, срок, чтение цели), условия, действия из закрытого набора, таймеры. Пишет «Спецификация», модель Quint из автомата сверяет review-claude.
   - (в) Генератор `tools/normgen/` («Архитектор») строит из (а) код проверок на Go и Python и тесты по строкам таблицы, из (б) — каркас автомата и трассы для векторов. Примитивы (чтение с дедлайном, таймер, запись в хранилище) пишутся руками один раз на язык.
   - (г) Мера: сколько строк дал генератор; находки ревью таблицы и автомата против ревью прозы; проходит ли сгенерированное приёмку P/01.1 без правок. Код генератора в попытках MiniMax — только по варианту Б ADR-0083 доп. (62), который владелец ещё не выбрал. До этого пилот формы меряется отдельно от попыток.
3. По итогу пилота — отдельный ADR: язык выгрузки (вся по-английски или нет) и форма норм (на какие классы).

### Consequences

* Хорошо: мера на одной линии, нормы курса не трогаются, проза лекции остаётся.
* Плохо: два текста P/01.1 до итога пилота; сверка `check_spec` нужна до первой попытки на английском.
* Предел: одна глава и одна модель. Вывод на всю выгрузку пилот не даёт, он даёт только основание.
