# `vmsctl` не ставится на машины заказчика: это инструмент харнеса и стенда

## Context and Problem Statement
Класс системы: прикладной инструмент поверх хранилища платформы.

`vmsctl` пишет строки камер и записей прямо в хранилище кластера под именем консоли, без HTTP. Процессы продукта его не вызывают. Установка продукта вызывала только `vmsctl secrets new` (создать ключ секретов); остальное — ночной прогон, smoke-проверки, стенд (`scripts/nightly/*`, `scripts/*.ps1`, `scripts/linux/box/smoke.sh`, `vms-macos/bin/base-config.sh`). На машине заказчика `vmsctl` — второй путь записи в хранилище без проверки прав, без ключей идемпотентности и, если запущен без `SECRETS_KEY`, без запечатывания паролей.

## Decision Drivers
* оператор работает через консоль, аварийный доступ — `break-glass`;
* у второго пути записи нет ни одной защиты консоли;
* ключ платформы исполняет платформа (ADR-0013), а не утилита подсистемы.

## Considered Options
* оставить `vmsctl` в установке как аварийный инструмент администратора;
* убрать `vmsctl` из установки, оставить в репозитории для харнеса и стенда; ключ при установке создаёт `w2cctl`.

## Decision Outcome
Выбран второй вариант. Оба `install.sh` и образ не кладут `vmsctl` и убирают его со старой установки; ключ создаётся `w2cctl secrets new`. Харнес и стенд берут `vmsctl` из своей сборки. Советы оператору «заведите камеру через `vmsctl add`» (README, `vmscam`) заменены консолью.

### Consequences
* Good, because на машине заказчика один путь записи строк оператора — консоль с правами, идемпотентностью и запечатыванием.
* Bad, because у администратора нет инструмента записи строк, когда консоль недоступна; остаются только `break-glass` и правка через `configstore` с правами администратора.

### Confirmation
`deploy/units_test.go` в продукте проверяет, что в установке нет `vmsctl` и есть `w2cctl`; ночной прогон и smoke берут `vmsctl` из каталога сборки, а не из `/opt/w2c/bin`.

## Pros and Cons of the Options

### Оставить как аварийный инструмент
* Good, because работает без консоли.
* Bad, because обходит проверку прав и идемпотентность; без ключа пишет пароли открыто.

### Только харнес и стенд
* Good, because нет второго пути записи у заказчика.
* Bad, because аварийная правка строк — только через `break-glass` или администратора хранилища.

## More Information
Связано: ADR-0013, ADR-0024 (`w2cctl`). Ветка продукта `r23-domain`.
