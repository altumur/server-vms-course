# Веса единиц под `placement`: ёмкость, запас и бюджет памяти считаются по сумме весов, вес — поле строки единицы

## Context and Problem Statement
Класс системы: платформенная система, размещение.

Загрузка работника сегодня — число единиц: `Load(w)` = число назначений, свободное место = `capacity − load`, запас работника
`headroom = capacity − len(rows)`, бюджет памяти `base_mb + unit_mb · единицы` (ADR-0070 шаг 3). Камера 4K и камера 720p
весят одинаково: работник на 50 камерах 4K переполнен там, где 50 камер 720p — норма. Разрешения потока в статусе
работника и у хоста драйверов нет, вес из измерения брать не из чего. Владелец 2026-10-07: веса единиц (4K/720p) — ключ
спеки под `placement`, форма до кода. Форма «Сборки» 2026-10-12 принята.

## Decision Drivers
* платформа не знает ни камер, ни разрешений (ADR-0001): вес — число из строки единицы, его смысл — у подсистемы
* один ключ спеки вместо особых случаев в размещении; без ключа поведение прежнее
* безопасные умолчания: вес меньше единицы или не число — отказ, слишком тяжёлая единица не размещается молча

## Considered Options
* `placement.weight: {field, default}` — вес из поля строки единицы, всё размещение по сумме весов.
* Вес по измерению потока (разрешение в статусе работника).
* Оставить счёт единицами.

## Decision Outcome
Выбран первый вариант; второй — следующим шагом, когда работник будет говорить разрешение.
1. Ключ спеки `placement.weight: {field: <поле строки единиц>, default: <целое ≥ 1>}`; поле — `int` в `rows`, проверяется при
   загрузке; значение < 1 или не число — отказ правки со словами; неизвестный ключ — отказ загрузки (ADR-0012). Без ключа
   — вес 1 у всех, как сейчас.
2. Платформа: загрузка работника — Σ весов его единиц, ёмкость в тех же единицах; «most free capacity» и группы — по весу;
   `headroom` работника — `capacity − Σ весов` его строк; бюджет памяти — `base_mb + unit_mb · Σ весов`; причина размещения
   называет вес («most free capacity (12) among 3 worker(s); weight 4»); единица тяжелее ёмкости любого работника — в
   `unplaceable` со словами.
3. VMS: поле `cameras.weight` (`int`, по умолчанию 1); шкала — пиксели относительно 720p с округлением к ближайшему целому,
   не меньше 1: 720p = 1, 1080p = 2, 4K = 9; шкалу говорит описание поля, платформа её не знает. Источник веса — только
   поле строки (оператор, импорт, страница).
4. Паритет: продукт первым с разрешения (правило 15): «Сборка» называет точные пути ключей, «Архитектор» кладёт строки
   `product-only … # ADR-0078 «продукт»` в ведомость курса, продукт забирает байты; курс зеркалит задачей после отчёта
   продукта и снимает строки.

### Consequences
* Good, because ёмкость, запас и бюджет памяти говорят одно и то же и честны к тяжёлым камерам.
* Good, because платформа по-прежнему ничего не знает о разрешениях: число приходит из строки.
* Bad, because вес — слово оператора, пока работник не измеряет поток; неверный вес даёт неверное размещение.
* Bad, because `unit_mb` ADR-0070 измерен на камерах стенда одного разрешения; масштабирование весом — оценка до замера.

### Confirmation
Тесты платформы: работник ёмкостью 10 берёт две единицы веса 4 и одну веса 1, вторую веса 4 — нет; `headroom` и бюджет по
весу; единица тяжелее всех — `unplaceable`. Тест VMS: камера `weight: 9` на работнике ёмкостью 10. Стенд: четыре камеры
720p и одна `weight: 9` при `CAPACITY=12` — одна 4K и три 720p расходятся по работникам. Курс — те же тесты после зеркала.
