# Домен после 5b: проверки — декларации `domain:`, сокет signer — только у процесса токенов, ход курса без `SITE` и `DOMAIN_*`

## Context and Problem Statement
Платформенная система: домен — служба платформы (ADR-0024), вклад подсистемы — раздел `domain:` её спеки (ADR-0010). Шаг 5b записки о границе вынес VMS из `w2cplatform/domain`. Чтобы домен собрался без `vms`, агент 5b ослабил три проверки, которые раньше делал код VMS внутри домена. Ослабления записаны в PROVENANCE 91 продукта.

Ещё два места остались не по курсу. Сокет токенов signer открыт группе `w2c-store`. Продукт находит домен по `SITE`, `DOMAIN_FOUND`, `DOMAIN_CANDIDATES`, а курс — переносом оператором.

## Decision Drivers
* ADR-0001 и ADR-0002: платформа знает подсистему только по спеке; смысл хука уходит в спеку.
* ADR-0012: ослабление отсечения не держится даже временно.
* ADR-0003: переменные окружения уходят без алиасов.

## Considered Options
* Вернуть три проверки в код VMS внутри домена.
* Оставить проверки ослабленными до переписывания домена.
* Сделать проверки декларациями раздела `domain:`; исполняет их платформа.

## Decision Outcome
Выбран третий вариант, и с ним два решения о сокете и о ходе.

**Три проверки — декларации `domain:`.** Формы пишет «Сборка» в `domain:` спеки VMS и шлёт «Лекциям» и «Паритету». Проверки исполняет платформа, проверки воркера VMS снимаются.
* `names: {exclusive_with: domain/users}` у таблицы учёток: имя учётки RTSP не совпадает с именем человека домена.
* `tokens.stream: {grant: view}`: наибольший грант вида токена; выдача сверх него — отказ.
* `domain.edit: [enabled, retention_days]`: поля, которые дверь домена пропускает в правку строки члена.

**Сокет токенов signer.** Группу сокета получает только процесс, которому токены нужны (`vms-vmsdomain`). Группа `w2c-store` недопустима даже временно. Signer и консоль домена разносятся в отдельные процессы.

**Ход курса.** `SITE`, `DOMAIN_FOUND`, `DOMAIN_CANDIDATES` удаляются без алиасов. Продукт переходит на ход курса: перенос делает оператор, `domain install`, агент следует за держателем.

Порядок: всё после слияния 5b. Проверки и ход курса делает «Платформа продукта» в `w2cplatform/domain`; разнесение signer — её пункт сразу после текущего.

### Consequences
* Good, because домен не держит знаний о VMS, а три правила видны в YAML и сверяются с курсом.
* Good, because токены подписывает только процесс, которому они нужны.
* Bad, because до этих коммитов в main живут три ослабленные проверки и сокет signer у `w2c-store`; они записаны в PROVENANCE 91.
* Bad, because стенд и ночной прогон переходят с `SITE` и `DOMAIN_*` на ход курса разом (ADR-0003).

### Confirmation
* Тесты платформы на `testsub2`: каждая из трёх деклараций исполняется без строки кода в подсистеме; отказ при нарушении каждой.
* У группы двери токенов ровно один член — процесс, читающий токены (`vms-domainpart`); тест `deploy/signer_test.go`.
* В продукте нет `SITE`, `DOMAIN_FOUND`, `DOMAIN_CANDIDATES`; словарь границы и поиск по дереву.

## More Information
Группа двери токенов своя, отдельная от ролевых групп configstore. Имя выводит платформа по правилу `<deployment>-<sub>domaintokens` (на стенде `vms-domaintokens`), в коде руками не пишется (решение «Архитектора» 2026-10-05, шаг 2 «Платформы»).
