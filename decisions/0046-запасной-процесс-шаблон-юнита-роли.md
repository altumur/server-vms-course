# Запасной процесс — экземпляр шаблона юнита своей роли, с теми же учётными данными, ключами, пользователем и группами

## Context and Problem Statement

Класс системы: платформенная система — скрипт `w2c-spares.sh` по таймеру поднимает запасные воркеры и регистраторы под предложения контроллера.

Двенадцатое ревью (блокер 6) показало: скрипт запускал запасного как `systemd-run … w2c-run.sh worker` — от root, без ключа кластера, с раздачей на петле. Камера умершего сервера с запечатанным паролем не стартовала на том самом процессе, который ради неё подняли (`open_row` бросал `Sealed`); регистратор других серверов не доставал до раздачи; файлы в архиве событий получали хозяина root.

## Decision Drivers

* запасной должен уметь всё, что умеет штатный процесс роли, и ничего сверх;
* описание роли должно быть одно, иначе второе расходится молча;
* скрипт запасных не должен быть root и не должен уметь запускать что угодно.

## Considered Options

* `systemd-run` со списком свойств роли в скрипте;
* шаблон юнита роли (`vms-<роль>-spare@.service`) — тот же юнит без имени, который скрипт только запускает.

## Decision Outcome

Владелец решил: запасной запускается с теми же учётными данными, ключами, окружением, пользователем и группами, что юнит роли. Выбран шаблон юнита. Он отличается от юнита роли только тем, что нужно запасному: нет `WORKER_NAME`; набор меток — из файла `SPARE_FILE=/run/w2c-spares/%n.env`, из которого `w2c-run.sh` берёт одну строку `SPARE_FOR=` и сверяет с алфавитом меток (нет набора — выход 2, ничего не стартует); порты раздачи и двери даёт ОС. Скрипт работает под пользователем `w2c-spares` без групп; правило polkit разрешает ему только `start` шаблонов запасных.

### Consequences

* Good, because камера умершего сервера с запечатанным паролем стартует на запасном, а файлы архива событий получают правильного хозяина.
* Good, because тест держит шаблон строка в строку с юнитом роли: строку, добавленную роли и забытую у запасного, он не пропустит.
* Bad, because `w2c-spares` может запустить запасной с любым правильным набором меток, ограничен только `MAX_*`.
* Bad, because на macOS polkit нет, и скрипт запасных там работает под root; шаблонов запасных для шлюза и автоматизации пока нет.

## Pros and Cons of the Options

### `systemd-run` со списком свойств

* Good, because не нужен второй файл юнита.
* Bad, because список свойств в скрипте — второе описание роли, которое расходится молча; скрипту нужен root.

### Шаблон юнита роли

* Good, because `systemctl cat` показывает его оператору, `%d` раскрывается, тест сверяет с ролью.
* Bad, because на каждую роль — второй файл юнита.
