# Домен без процесса `domainpart`: вклад подсистемы — спека и строки её обычных воркеров, книги собирает платформа

## Context and Problem Statement
Класс системы: платформенная система, граница платформы и подсистемы.

Владелец спросил, для каких подсистем доменный режим потребовал отдельного кода и можно ли обойтись без него, чтобы
новая подсистема состояла только из кода воркера и спек. Разбор обоих деревьев 2026-10-11 (курс 2cfce43c, продукт
0c8a12b): платформенный домен (`w2cplatform/domain`, `trust`; в продукте и `cmd/domain`, `cmd/domainagent`) подсистему не
импортирует и не линкует, ветвлений по имени подсистемы нет, точки расширения декларативные (раздел `domain:` спеки, роль
`<sub>domain`, сокет токенов, свой юнит). Отдельный доменный код есть только у VMS: процесс `domainpart` (курс
`Source/vms/domainpart/` ≈5 800 строк, продукт `vms/domainpart/` ≈2 800 плюс дверь на порту 8096). У det, survey, live, rec,
auto своего доменного процесса нет, и они на домене работают: «воркер плюс спека» уже достаточно подсистеме без
междукластерной логики.

Состав `domainpart`: тракт данных (ingest, форвардер, пушер; в продукте уже в `recproc`/`campush`), поиск камеры в чужом
кластере (`crossing`, зовётся из рекордера), учебный материал уроков М12A 3/8/10 (`device`, `gateway`, `cloud` — только
курс), сценарии auto, превращённые в asks (`scenario`/`scenarios.go`), книга RTSP-учёток, и ядро — проход книг у
держателя (`books`/`cameras.go`/`crossing.go`/`roads.go`): один процесс считает `sources`, `primaries`, `polls`, `asks`,
`upstream` за весь домен. Только ядро требует процесса у держателя; остальное либо код обычных воркеров не в той папке,
либо не код продукта. ADR-0010 закрепил «публикация книг держателем — работа воркера VMS `vms/domainpart`»; это и есть
отменяемая часть.

## Decision Drivers
* новая подсистема = спека + воркеры; доменный вклад не должен требовать отдельного процесса и роли
* у держателя должно быть как можно меньше переезжающего: учения переноса (ADR-0066 доп.) ломали именно привязанное к держателю
* смысл спеки одной подсистемы не исполняет код другой (сценарии `auto` сегодня исполняет VMS)
* тесты платформенного домена не должны собираться на VMS (в курсе 12 из 25 файлов `tests/domain/` импортируют `vms.domainpart`)

## Considered Options
* Оставить `domainpart` как есть: воркер подсистемы у держателя, своя дверь, свой проход книг.
* Убрать процесс: логика расходится по обычным воркерам, книги — строки членов, переносимые платформой, слияние объявлено в спеке.
* Сделать `domainpart` платформенным с интерфейсом «подсистема даёт функцию книг» — хук, ADR-0002 запрещает.

## Decision Outcome
Выбран второй вариант. Порядок, курс первым (ADR-0073), продукт догоняет; начинать после шага 5 ADR-0070.

1. **Тракт данных по воркерам.** `ingest`, `chain`/форвардер, `crossing` переезжают в пакеты рекордера и шлюза без смены
   поведения (продукт: уже там, остаётся `crossing.go`/`roads.go`).
2. **Сценарии — в `autoworker`.** Он сам читает `domain/shared/auto` (документ `scenarios`) и пишет asks в своём кластере;
   код VMS сценарии не исполняет.
3. **Книги из строк членов.** Книгу пишут обычные воркеры своего кластера (рекордер — «я пишу `cam`», контроллер —
   источники, шлюз — учётки), платформенный агент переносит их, как уже переносит книги вслепую (ADR-0010). Слияние
   объявляется в спеке, форма до кода «Архитектору»: `domain.books.<книга>: {from: <строки>, key: <поле>, pick: <правило>}`;
   выбор кластера для единицы — платформенное размещение домена, не книга. Книга без `from` — как сегодня, переносимая.
4. **Учётки RTSP** — так же: строки члена `domain/vms/stream-accounts` пишет шлюз, платформа переносит.
5. **Учебный материал** `device`, `gateway`, `cloud` становится фикстурами уроков М12A на testsub; `tests/domain/` курса
   без импорта `vms`.
6. **Процесс уходит.** `domainpart` (юниты, `vms domainpart`, `python3 -m vms.domainpart`), роль `<sub>domain`, слот
   `domain/<sub>/worker`, биение `domain/<sub>/heartbeat`, дверь 8096 продукта и её маршруты в странице VMS удаляются
   без алиасов (ADR-0003). Страница читает строки книг платформенной дверью `/domain/<sub>/<строки>`, пишет через
   дверь домена под `domain.edit`. Токены `stream`/`ask` просит тот воркер, которому они нужны, по
   `tokens.<вид>.grant` своей роли.

Попутно: слово `stream` — в список «по смыслу» теста границы на обеих сторонах (платформа говорит им в комментариях и
строке `topology.go` о ретрансляторе); строка меняется на «данные членов».

### Consequences
* Good, because подсистема без междукластерной логики не пишет ни строки доменного кода, а с ней — только воркеры и ключи спеки.
* Good, because у держателя одним процессом и одной дверью меньше; переезд держателя не несёт состояния подсистемы.
* Good, because тесты платформенного домена собираются на testsub и доказывают независимость, а не предполагают её.
* Bad, because переписывание ядра книг на обеих сторонах и новая форма `domain.books.<книга>.from`.
* Bad, because слияние книг в спеке ограничено объявимыми правилами; что в них не ложится — повод вернуться к ADR, не к процессу.

### Confirmation
`ls Source/vms/domainpart` и `vms/domainpart` пусты; спеки без роли `domainpart`, без `domain/<sub>/worker` и
`domain/<sub>/heartbeat`; `tests/domain/` курса без импорта `vms`; тесты домена обеих сторон зелёные; учение переноса
(ADR-0066) проходит без процесса подсистемы у держателя; `live_streams_live`, книги `primaries`/`sources` на стенде
совпадают с прежними при тех же камерах.

## More Information
Отменяет часть ADR-0010 («публикация книг держателем — воркер VMS `vms/domainpart`»); ADR-0024 (`domain/<sub>/`),
ADR-0031 (сокет токенов), ADR-0065 (приёмник и форвардер в рекордере), ADR-0066 доп. (учения переноса), ADR-0073 (курс
первым). Решение владельца 2026-10-11 на вопрос «можем обойтись без domainpart?».

## Дополнение 2026-10-11 (ночь): форма слияния книг `from/key/pick` — принята с поправками
Предложение из входящих (`decisions/inbox/2026-10-11-слияние-книг.md`, коммит d9a254e4, автор «Лекции»; файл удалён
по ADR-0073, текст в истории). Форма: `domain.books.<книга>: {from: <sub>/<строка>, key: <поле>, pick: unique|all,
show: […]}` — три ключа обязательны вместе, частичная тройка, неизвестное правило, чужая подсистема, префикс, URL, `..`
во `from` — отказ загрузки (ADR-0012); `key` — одно непосредственное поле с непустой строкой; книга без `from` —
переносимая, как прежде, `key`/`pick` без `from` запрещены. Результат — существующее имя `domain/<sub>/<книга>` и
существующая доставка по членам, сегмента `books/` нет. Строка результата: ключ → `{entries: [{member, item, value}…],
missing: [<член>…]}`; `member` ставит платформа из проверенного происхождения отчёта, `item` — ключ элемента входа, `value`
— объект воркера как есть; порядок `(member, item)`, повтор поколения не даёт второго вклада. `unique` — ровно один
вклад на ключ, конфликт — ключ отсутствует и диагностика без полезной нагрузки и секретов; порча входа (JSON, нет `key`,
повтор ключа при `unique` в одном входе) снимает вклад члена целиком. Полнота: член, потерянный по виду домена (за
`lost_after`), книгу не держит; член в окне без свежего отчёта — держит; `missing` всегда присутствует, пустой — полная;
годность неполной книги решает читатель по своей спеке. Отвергнуты: выбор по `ts`, по порядку доставки, произвольный
`pick` в коде подсистемы (ADR-0002). Книга — наблюдение, не полномочие: писателя назначает размещение; `from` прав записи
не даёт, секреты запечатаны, `show` скрытого не раскрывает, широковещания по умолчанию нет. До переноса каждой книги —
файл во входящих «издатель → вход → правило → получатели → читатель»; адресная доставка — отдельным предложением.
Хвост долга `# ADR-0074 «курс»`. Приёмка: общие случаи на testsub/testsub2 первыми, затем VMS; до них ADR-0074 не
исполнен.

## Дополнение 2026-10-11 (ночь, 2): шесть книг VMS по форме `from/key/pick` — решения по файлам входящих
Шесть предложений «Лекций» (входящие `2026-10-11-книга-{sources,primaries,polls,asks,upstream,stream-accounts}.md`,
коммиты до 8050c00a; файлы сняты по ADR-0073, текст в истории). Четыре общих вопроса и ответы на них:

1. **Книга принадлежит издателю.** Поправка к первому дополнению: «прежнее имя» значило «без сегмента `books/`», а не
   «навсегда под `vms`». Книгу объявляет спека той подсистемы, чей воркер её пишет, результат —
   `domain/<sub-издателя>/<книга>`; прежнее `domain/vms/<книга>` уходит без алиаса (ADR-0003), читатели других
   подсистем получают чтение декларацией прав (`worker.reads`), как рекордер читает `domain/vms/*` сегодня. Итого:
   `sources` — `vms`; `primaries`, `polls`, `upstream` — `rec`; `asks` — `auto`; `stream-accounts` — `live`.
2. **Вход — семья строк, по строке на писателя.** `from: <sub>/<строка>/` с завершающей косой: каждый воркер пишет
   свою строку `<sub>/<строка>/<id воркера>` под своим слотом и его отсечением (ADR-0013: один писатель на строку);
   общей строки с CAS нескольких писателей нет, запоздавшего прежнего владельца отсекает существующий механизм слота.
   `item` оболочки — `<id писателя>/<элемент>`. `from` без косой — одна строка одного писателя, как в первом дополнении.
3. **Адресная доставка — ключ `to`.** `domain.books.<книга>: {from, key, pick, to: <поле>}`: поле объекта вклада, в
   котором издатель называет получателей — имя члена или список имён. Платформа доставляет ключ только названным
   принятым членам; имя не члена — вклад не доставляется и считается в диагностике; `to` обязателен для книги с `from`
   (книга без `to` не грузится, ADR-0012) — широковещания нет ни по умолчанию, ни по ошибке. Для семейств с
   `domain.names.<семья>.grant` платформа сверх того не доставляет члену без такого гранта. Секрет внутри `value`
   доставляется перезапечатанным для получателя существующим механизмом; подтверждается тестом до переноса учёток.
4. **`missing` у пустой книги.** Элемент строки результата с пустым именем держит `{missing: […]}` и присутствует всегда;
   пустое имя не сталкивается с ключами, потому что значение `key` — непустая строка.

По книгам (всё остальное в файлах принято как написано):
* **`sources`** (`vms`): издатель — воркер VMS, владеющий устройством; `vms/sources/` по воркеру, `key: ref`, `unique`;
  `to` — кластеры основной и резервных записей; pull/push, дозапись и `reachable` решает рекордер-получатель по виду
  домена; `road`, `backups`, подмена `live_url` на `ingest://` из книги уходят.
* **`primaries`** (`rec`): `rec/primaries/` по рекордеру, `key: ref`, `all`; `recording` — один идентификатор; основного
  называет размещение, не порядок `entries`; `token_secret` в книге нет — камера просит `stream` сама; `show` — к `value`;
  `to` — кластер камеры, основной и резервные.
* **`polls`** (`rec`): назначение обслуживания опроса — из топологии, не из фиктивной записи: дверь опроса камеры без
  записи держит кластер её `via` (для звезды — центр), в нём — рекордер, хостящий ingest кластера (ADR-0065); он и
  публикует `rec/polls/`, `key: ref`, `unique`, `to` — домашний кластер камеры. Новой единицы и слота у держателя нет.
* **`asks`** (`auto`): исполнение сценариев целиком у `autoworker` (п. 2 решения); `auto/asks/` по воркеру, `key: target`,
  `all`; идентификатор сценария — `name` единицы AUTO, в документе `shared.scenarios` поле `name` обязательно (схема
  спеки `auto`, курс первым); книга — каталог разрешённых путей, команды — семья `requests`; `to` — исполнитель и
  ретрансляторы пути; до переноса доказать доставку события AUTO от камеры за ретранслятором и `within` при обрыве.
* **`upstream`** (`rec`): `rec/upstream/` по рекордеру центра, `key: ref`, `unique`; `mode` считает форвардер по
  топологии; токен каждый ретранслятор просит свой; `to` — назначенные ретрансляторы камеры.
* **`stream-accounts`** (`live`): учётку владеет кластер её создания, пишет любой шлюз этого кластера своей строкой
  `live/stream-accounts/<шлюз>` (создание, отключение, смена пароля — через дверь шлюза, не записью страницы);
  `key: name`, `unique`; конфликт имени между кластерами — 409 при создании по собранной книге и по
  `domain.names.exclusive_with`; `to` — кластеры с грантом на учётку, издатель считает их по `domain/grants/*`,
  платформа сверяет по `names.<семья>.grant` (п. 3); отдельной единицы «учётка» и главного шлюза домена нет;
  записи `domain/vms/stream-clients/` переезжают одной пачкой с декларациями и правами.

Приёмка каждой книги — разделы «Приёмка» файлов, плюс общие случаи на testsub из первого дополнения. Порядок переноса:
`primaries` и `sources` вместе (одна проверка «карта и резерв»), затем `upstream`, `polls`, `stream-accounts`, `asks`
последним (тянет перенос исполнения сценариев). Код — после шага 5 ADR-0070, курс первым, хвост `# ADR-0074 «курс»`.

## Дополнение 2026-10-11 (ночь, 3): два вопроса ядра слияния — отсечение запоздавшего писателя и целостность отчёта члена
Два вопроса «Лекций» из ветки `codex/course-book-merge` (файлы входящих «отсечение вклада» и «целостность отчёта»,
с пробами на `e0c83de4`). Обе находки проверены по обоим деревьям и верны для обеих сторон: `put` хранилища несёт
только `op/key/items/cas` (курс `configstorevars.py`, продукт `configstore`), эпоха единицы отсекает тракт данных, а
не строки управления; отчёт члена держатель пишет по прежним путям и метку `reported` последней (курс `uplink.take`,
продукт `publish.go`), и читатель между двумя строками видит смесь поколений при неизменной метке.

**1. Отсечение: условие по чужой строке в одной операции — `guard`.** Форма операции хранилища (провод процесс ↔
хранилище, обе стороны байт в байт): `put`/`delete` принимают сверх `cas` поле `guard: {key: <строка слота>, index:
<её индекс>}`; хранилище атомарно проверяет индекс строки `key` вместе с CAS целевой строки и отказывает, если он
изменился, своим кодом, не кодом CAS: HTTP 412, тело `{"error": "guard", "key": <строка>, "index": <индекс сейчас>}`.
Дверь без голоса передаёт `guard` голосующему, как передаёт `cas`. Семантика одна у всех реализаций Variables
(FileVariables, память, configstore), запасного неатомарного пути нет; `guard` не расширяет права: право на целевую
строку проверяется как прежде, чтение строки `key` — по правам читателя. Общий метод `Worker` для вкладов книг (и любой
строки под слотом): перечитать слот, убедиться, что держатель — свой экземпляр, передать его индекс в `guard`; при 412
не повторять запись, а заново проверить владение; при `unconfirmed_max` управляющее состояние не публикуется.
Обновление слота тем же владельцем даёт лишний 412 и повтор — цена принята. Эпоха единицы остаётся отсечением тракта
данных; второй механизм не вводится. Альтернатива «неизменяемые поколения вкладов с указателем» отклонена для строк
вкладов: меняет принятую семью строк и требует уборки.

**2. Целостность отчёта: поколение — один объект.** Держатель хранит каждую принятую публикацию члена одним
неизменяемым объектом `domain/members/<член>/reports/<seq>` — байты подписанного тела как получены (канон ADR-0072,
sha256 как целостность и происхождение; ретранслятор переносит тело члена как есть, принадлежность сохраняется), —
и только после записи объекта одной операцией переключает метку `reported` → `{seq, sha256, sent_at, received_at,
via}`. `seq` — счётчик самого члена, уже идущий в публикации, не часы держателя; `seq` не выше текущего — отказ
(повтор старого отчёта). Читатели (`member_copy`/`_CopyVars`, вид домена, сборщик книг) фиксируют `reported.seq` и
читают только этот объект: метка без объекта или объект без части — `missing`/неизвестно, никогда смесь. Строки `v/<путь>`
по прежним путям держатель больше не пишет: проекции читатель строит из зафиксированного объекта. Держатель хранит два
последних поколения, старше убирает своим проходом; переезд держателя переносит объекты вместе с `domain/members/*`,
порядок — по `seq` в метке. Размер объекта ограничен уже существующим пределом тела двери. Альтернатива «поколения из
многих объектов с указателем» отклонена: тот же указатель, но лишние пути и уборка; «читать частичное как временное
умолчание» — отклонена.
