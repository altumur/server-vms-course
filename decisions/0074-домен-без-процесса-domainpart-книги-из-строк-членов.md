# Домен без процесса `domainpart`: вклад подсистемы — спека и строки её обычных воркеров, книги собирает платформа

## Context and Problem Statement
Класс системы: платформенная система, граница платформы и подсистемы.

Владелец спросил, для каких подсистем доменный режим потребовал отдельного кода и можно ли обойтись без него, чтобы
новая подсистема состояла только из кода воркера и спек. Разбор обоих деревьев 2026-10-11 (курс 2cfce43c, продукт
0c8a12b): платформенный домен (`w2cplatform/domain`, `trust`; в продукте и `cmd/domain`, `cmd/domainagent`) подсистему не
импортирует и не линкует, ветвлений по имени подсистемы нет, точки расширения декларативные (раздел `domain:` спеки, роль
`<sub>domain`, сокет токенов, свой юнит). Отдельный доменный код есть только у VMS: процесс `domainpart` (курс
`Source/vms/domainpart/` ≈5 800 строк, продукт `vms/domainpart/` ≈2 800 плюс дверь на порту 8096). У det, survey, live, rec,
auto своего доменного процесса нет, и они на домене работают: «воркер плюс спека» уже достаточно подсистеме без
междукластерной логики.

Состав `domainpart`: тракт данных (ingest, форвардер, пушер; в продукте уже в `recproc`/`campush`), поиск камеры в чужом
кластере (`crossing`, зовётся из рекордера), учебный материал уроков М12A 3/8/10 (`device`, `gateway`, `cloud` — только
курс), сценарии auto, превращённые в asks (`scenario`/`scenarios.go`), книга RTSP-учёток, и ядро — проход книг у
держателя (`books`/`cameras.go`/`crossing.go`/`roads.go`): один процесс считает `sources`, `primaries`, `polls`, `asks`,
`upstream` за весь домен. Только ядро требует процесса у держателя; остальное либо код обычных воркеров не в той папке,
либо не код продукта. ADR-0010 закрепил «публикация книг держателем — работа воркера VMS `vms/domainpart`»; это и есть
отменяемая часть.

## Decision Drivers
* новая подсистема = спека + воркеры; доменный вклад не должен требовать отдельного процесса и роли
* у держателя должно быть как можно меньше переезжающего: учения переноса (ADR-0066 доп.) ломали именно привязанное к держателю
* смысл спеки одной подсистемы не исполняет код другой (сценарии `auto` сегодня исполняет VMS)
* тесты платформенного домена не должны собираться на VMS (в курсе 12 из 25 файлов `tests/domain/` импортируют `vms.domainpart`)

## Considered Options
* Оставить `domainpart` как есть: воркер подсистемы у держателя, своя дверь, свой проход книг.
* Убрать процесс: логика расходится по обычным воркерам, книги — строки членов, переносимые платформой, слияние объявлено в спеке.
* Сделать `domainpart` платформенным с интерфейсом «подсистема даёт функцию книг» — хук, ADR-0002 запрещает.

## Decision Outcome
Выбран второй вариант. Порядок, курс первым (ADR-0073), продукт догоняет; начинать после шага 5 ADR-0070.

1. **Тракт данных по воркерам.** `ingest`, `chain`/форвардер, `crossing` переезжают в пакеты рекордера и шлюза без смены
   поведения (продукт: уже там, остаётся `crossing.go`/`roads.go`).
2. **Сценарии — в `autoworker`.** Он сам читает `domain/shared/auto` (документ `scenarios`) и пишет asks в своём кластере;
   код VMS сценарии не исполняет.
3. **Книги из строк членов.** Книгу пишут обычные воркеры своего кластера (рекордер — «я пишу `cam`», контроллер —
   источники, шлюз — учётки), платформенный агент переносит их, как уже переносит книги вслепую (ADR-0010). Слияние
   объявляется в спеке, форма до кода «Архитектору»: `domain.books.<книга>: {from: <строки>, key: <поле>, pick: <правило>}`;
   выбор кластера для единицы — платформенное размещение домена, не книга. Книга без `from` — как сегодня, переносимая.
4. **Учётки RTSP** — так же: строки члена `domain/vms/stream-accounts` пишет шлюз, платформа переносит.
5. **Учебный материал** `device`, `gateway`, `cloud` становится фикстурами уроков М12A на testsub; `tests/domain/` курса
   без импорта `vms`.
6. **Процесс уходит.** `domainpart` (юниты, `vms domainpart`, `python3 -m vms.domainpart`), роль `<sub>domain`, слот
   `domain/<sub>/worker`, биение `domain/<sub>/heartbeat`, дверь 8096 продукта и её маршруты в странице VMS удаляются
   без алиасов (ADR-0003). Страница читает строки книг платформенной дверью `/domain/<sub>/<строки>`, пишет через
   дверь домена под `domain.edit`. Токены `stream`/`ask` просит тот воркер, которому они нужны, по
   `tokens.<вид>.grant` своей роли.

Попутно: слово `stream` — в список «по смыслу» теста границы на обеих сторонах (платформа говорит им в комментариях и
строке `topology.go` о ретрансляторе); строка меняется на «данные членов».

### Consequences
* Good, because подсистема без междукластерной логики не пишет ни строки доменного кода, а с ней — только воркеры и ключи спеки.
* Good, because у держателя одним процессом и одной дверью меньше; переезд держателя не несёт состояния подсистемы.
* Good, because тесты платформенного домена собираются на testsub и доказывают независимость, а не предполагают её.
* Bad, because переписывание ядра книг на обеих сторонах и новая форма `domain.books.<книга>.from`.
* Bad, because слияние книг в спеке ограничено объявимыми правилами; что в них не ложится — повод вернуться к ADR, не к процессу.

### Confirmation
`ls Source/vms/domainpart` и `vms/domainpart` пусты; спеки без роли `domainpart`, без `domain/<sub>/worker` и
`domain/<sub>/heartbeat`; `tests/domain/` курса без импорта `vms`; тесты домена обеих сторон зелёные; учение переноса
(ADR-0066) проходит без процесса подсистемы у держателя; `live_streams_live`, книги `primaries`/`sources` на стенде
совпадают с прежними при тех же камерах.

## More Information
Отменяет часть ADR-0010 («публикация книг держателем — воркер VMS `vms/domainpart`»); ADR-0024 (`domain/<sub>/`),
ADR-0031 (сокет токенов), ADR-0065 (приёмник и форвардер в рекордере), ADR-0066 доп. (учения переноса), ADR-0073 (курс
первым). Решение владельца 2026-10-11 на вопрос «можем обойтись без domainpart?».

## Дополнение 2026-10-11 (ночь): форма слияния книг `from/key/pick` — принята с поправками
Предложение из входящих (`decisions/inbox/2026-10-11-слияние-книг.md`, коммит d9a254e4, автор «Лекции»; файл удалён
по ADR-0073, текст в истории). Форма: `domain.books.<книга>: {from: <sub>/<строка>, key: <поле>, pick: unique|all,
show: […]}` — три ключа обязательны вместе, частичная тройка, неизвестное правило, чужая подсистема, префикс, URL, `..`
во `from` — отказ загрузки (ADR-0012); `key` — одно непосредственное поле с непустой строкой; книга без `from` —
переносимая, как прежде, `key`/`pick` без `from` запрещены. Результат — существующее имя `domain/<sub>/<книга>` и
существующая доставка по членам, сегмента `books/` нет. Строка результата: ключ → `{entries: [{member, item, value}…],
missing: [<член>…]}`; `member` ставит платформа из проверенного происхождения отчёта, `item` — ключ элемента входа, `value`
— объект воркера как есть; порядок `(member, item)`, повтор поколения не даёт второго вклада. `unique` — ровно один
вклад на ключ, конфликт — ключ отсутствует и диагностика без полезной нагрузки и секретов; порча входа (JSON, нет `key`,
повтор ключа при `unique` в одном входе) снимает вклад члена целиком. Полнота: член, потерянный по виду домена (за
`lost_after`), книгу не держит; член в окне без свежего отчёта — держит; `missing` всегда присутствует, пустой — полная;
годность неполной книги решает читатель по своей спеке. Отвергнуты: выбор по `ts`, по порядку доставки, произвольный
`pick` в коде подсистемы (ADR-0002). Книга — наблюдение, не полномочие: писателя назначает размещение; `from` прав записи
не даёт, секреты запечатаны, `show` скрытого не раскрывает, широковещания по умолчанию нет. До переноса каждой книги —
файл во входящих «издатель → вход → правило → получатели → читатель»; адресная доставка — отдельным предложением.
Хвост долга `# ADR-0074 «курс»`. Приёмка: общие случаи на testsub/testsub2 первыми, затем VMS; до них ADR-0074 не
исполнен.
