# Консоль кластера передаёт `where` консоли члена: `GET /domain/at/<кластер>/<sub>/where/…`

## Context and Problem Statement
Класс системы: платформенная система.

Запись камеры может держать другой кластер домена. На стенде камера cam-demo пишет в relay-b. Камера смотрится на
консоли своего кластера, а дверь к записи выдаёт только консоль кластера, который запись держит, своим ключом
(ADR-0015). Страница одной консоли до этой двери не достаёт: двери выдаёт `/rec/where/…` той консоли, а у этой
консоли есть пересылка только на держателя домена (`/domain/*`). Домен до сих пор не звонил консолям членов: член
публикуется сам, и его дверь — дело площадки (`ParseMember`).

## Decision Drivers
* смотреть запись там, где смотрят камеру, без второй страницы
* дверь выдаёт только консоль того кластера, своим ключом; байты обходят обе консоли (ADR-0014, ADR-0015)
* права решает гейт того кластера по его грантам, которые домен носит членам
* один механизм пересылки, не два

## Considered Options
* `GET /domain/at/<кластер>/<sub>/where/…` тем же `ConsoleDoor.forward`, адрес члена из `CLUSTERS`.
* Отдельный маршрут `/members/<кластер>/…` с пересылкой своего кода.
* Страница сама ходит на консоль другого кластера (CORS, второй вход человека).

## Decision Outcome
Выбран первый вариант.

**Путь.** `GET /domain/at/<кластер>/<sub>/where/<id>` и `GET /domain/at/<кластер>/<sub>/where/<table>/<place>?unit=…`
передаются как `GET <консоль кластера>/<sub>/where/…` того же пути и запроса. Корневую подсистему той консоли путь
называет по имени: спеку знает этот процесс (`KnownSpec`). `/domain/members/…` занят правкой членства, поэтому `at`.

**Ограничения** (проверяет пересылающая консоль до звонка):
1. Только `GET` и только маршруты `where` спек, которые знает процесс. Остальное — 404 «not a route handed to a
   member». Правки идут через держателя, как прежде.
2. Кластер — член домена по носимому списку (`domain/member-list`) и не этот кластер. Иначе 404 словами.
3. Адрес — `CLUSTERS` деплоя. Нет строки — 404 «no console of <кластер> is known here (CLUSTERS)». Не `/api/held`:
   там адрес держателя. Консоль, не видная по сети (камера за NAT), — 502 словами: это сеть, не правило.
4. Один шаг. Пересланный запрос несёт `X-W2C-Via: <этот кластер>`; консоль, получившая `/domain/at/…` с ним, отвечает
   400 «one hop». Заголовок ставит пересылающая; входящий от человека снимается.
5. 5 с и лимит ответа — как у `forward`.
6. Гейт пересылающей спрашивает только, кто это (любой грант). Решает гейт того кластера.

**Дверь.** Её выдаёт только консоль того кластера своим ключом. Пересылающая не переподписывает и байтов не трогает:
ответ идёт странице как пришёл, и страница идёт к двери держателя напрямую.

**Журнал.** У пересылающей — `domain.forwarded {cluster, path, user, status}`, у принимающей — её `door.issued`.

### Consequences
* Good, because запись смотрится там, где камера, и права остаются у кластера, который её держит.
* Good, because механизм один — `ConsoleDoor.forward`, меняется только адрес.
* Bad, because консоль кластера теперь звонит консоли члена: нужен `CLUSTERS` с адресами, и член за NAT так недостижим.
* Bad, because ещё один путь, по которому идёт токен человека; он ограничен одним шагом, `GET` и `where`.

### Confirmation
* Продукт: тесты на testsub — передача `where` члену с токеном; отказ не-`GET`, не-`where`, не-члена, своего
  кластера, второго шага, без `CLUSTERS`; ответ как пришёл (403 словами того гейта); журнал.
* Курс: то же в уроке домена («Лекции»). Страница — «Консоль». Контракт модуля §2 — «Архитектор».


**Добавление 2026-10-06 («Архитектор»; вопросы «Лекций» при переносе в курс).**
1. **Держатель — член для пересылки.** Кластер держателя в `domain/member-list` не числится. Поэтому, кроме списка,
   принимается кластер, названный в носимой проверенной записи `domain/holder`. Иначе записи кластера-держателя не
   видны из других кластеров.
2. **Лимит ответа — 1 МиБ** на обе пересылки (к держателю и к члену) в обоих деревьях. Сверх него — 502
   «answer too large».
3. **Корень или маунт** у консоли члена — по раскладке своего процесса: корневая спека → `/where/…`, остальные →
   `/<sub>/where/…`. Раскладка консолей одна на развёртывание. Продукт читает её из `CONSOLE_ROOT` своего
   процесса — это то же самое.
4. **Заголовки.** Любой входящий `X-W2C-Via` на `/domain/at/…` → 400 «one hop». Пересылка передаёт только токен,
   `Idempotency-Key` и `X-Operator`.
5. **Не известно ≠ не член.** Нечитаемый список членов или молчащее хранилище → 503 словами. Нечитаемое значение
   `CLUSTERS` → 503 с его сообщением, а не падение процесса.
6. **Пересылка к держателю тоже отдаёт ответ как пришёл** (статус и байты, `X-Unreachable`), без разбора и
   заворачивания в `{"detail": …}`: одна функция — одно поведение.

## Pros and Cons of the Options

### `/domain/at/…` тем же `forward`
* Good, because один механизм и одно место в гейте.
* Bad, because `/domain/` теперь значит и «держатель», и «член по имени».

### Свой маршрут `/members/…`
* Good, because путь читается сам.
* Bad, because второй механизм пересылки рядом с первым.

### Страница ходит сама
* Good, because консоли ничего не передают.
* Bad, because второй вход человека на чужую консоль и CORS; гранты того кластера всё равно нужны.
