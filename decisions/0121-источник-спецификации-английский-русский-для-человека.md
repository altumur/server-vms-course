# Источник спецификации — английский; русский — для человека

## Context and Problem Statement

ADR-0120 п. 1 запускал пилот: английский P/01.1 против русского на одной линии генерации. Владелец решил без меры: источником всего, что читает генератор, служит английский текст, а русский остаётся для человека. Пилот языка (ADR-0120 п. 1 (г)) отменён. Пилот формы (п. 2) идёт.

## Decision Drivers

* Генератор читает один текст — английский. Двух прочтений одной нормы у него нет.
* Человек читает курс по-русски: лекции, ADR и правила остаются русскими.
* Переход не ломает действующие проверки: урок за уроком, каждый — со сверкой.

## Considered Options

* Сразу весь курс — нельзя проверить по шагам.
* Урок за уроком, раскладка P/01.1 — выбран.

## Decision Outcome

1. **Что становится английским источником** — всё, что читает генератор:
   - нормы уроков (`*.norms.md`);
   - README реализации урока (`spec/*.README.md`);
   - README приёмки и пакетов векторов;
   - общие договоры (`Platform/common/contracts/`, `VMS/common/`);
   - описания в OpenAPI и схемах;
   - комментарии-шапки таблиц данных;
   - формы ADR-0120.

   Раскладка — как у P/01.1: английский файл в `spec/en/` (у прочих каталогов — `en/` рядом) — источник. Русский на прежнем месте — производный, с пометкой «производный от en, руками не правится».
2. **Что остаётся русским и не переводится:** лекции уроков (повествование для человека, `NN-<имя>.md`, `lifecycle.md`), ADR, правила и записки курса, навыки, `GLOSSARY.md`, `ARCHITECTURE.md`. Ссылка из английского текста на русскую лекцию допустима как «для человека». Нормой она не служит.
3. **Сверка.** `check_spec` (`en_mirror`) сверяет каждую пару en ↔ ru: номера норм, ссылки, коды и слова отказов, вставки кода, таблицы. Урок считается переведённым, когда английский источник есть у всех его файлов п. 1. Только тогда генератор получает урок по-английски.
4. **Нормативные слова** в английском тексте — RFC 2119 и 8174. Требования — шаблонами EARS, процедуры — нумерованными алгоритмами (как в P/01.1). `НОРМАТИВНЫЕ-СЛОВА.md` получает таблицу соответствия русских слов английским для производного текста.
5. **Выгрузка.** Генератор получает английский источник. Из выгрузки уходят производные русские файлы тех уроков, что переведены целиком. Лекции и прочее для человека остаются. Пока урок не переведён, он выгружается как сейчас.
6. **Порядок и доли.**
   - Платформа: P/01 (01.2, 01.3, README, приёмка, векторы) → P/02 → … → P/10. Это «Спецификация».
   - VMS: V/01 → … → V/12, после платформы или параллельно, по силам. Это «Спецификация VMS». Её отказ от доли в ADR-0120 доп. (1) п. 3 этим решением снят.
   - Перевод — правка без смены смысла. Найденная по ходу неясность — вопрос «Архитектору», а не правка нормы попутно.
7. **Правила и навыки** — доля «Архитектора»:
   - `doc-language.mdc` — исключение для английского источника спецификации;
   - навык `lesson-spec` — порядок «правка в en → пересборка ru»;
   - проверки текста норм — на английских словах.
8. **Пауза ADR-0120 доп. (2) в силе для ревью.** Ревью перевода ждёт конца пилота формы. Перевод — работа, он идёт. Эксперимент MiniMax — по ADR-0120 доп. (4).

### Consequences

* Хорошо: один текст для генератора, строгий синтаксис требований, дешевле по токенам.
* Плохо: на время перехода два текста. Производный русский надо пересобирать при каждой правке. Ревью перевода — отдельная работа после пилота.
* Предел: смысл русской лекции и английской нормы может разойтись. Лекция не норма, сверка её не судит.

## Дополнение (2), 2026-11-04 — слово владельца: ревью норм — в новой форме, прежние — черновиками

Владелец 2026-11-04: «да» — на предложение «Архитектора» не доводить ревью норм в старой форме.

1. **Прерванные ревью норм сдаются черновиками.** Ревью норм ADR-0115 (28)–(37) с моделью v115p review-claude коммитит как есть, с пометкой «прервано» (черновик: Б 0 С 2 М 3). Модель v115p остаётся мерилом пилота ADR-0120 доп. (5) п. 2 (в). nrev_to и quint_to 0115 не двигаются.
2. **Смысловые находки переходят.** Перевод не меняет смысла (п. 6). Поэтому находки черновиков — вопросы к английскому тексту урока и форме. Их несёт ревью норм этого урока в новой форме.
3. **Ревью норм — один раз на урок в новой форме:** английский источник плюс таблицы и автоматы, после паузы ADR-0120 доп. (2). Колонки `nrev_to`, `quint_to` конвейера для уроков, которые переводятся, отсчитываются от этого ревью.
4. **Исключение — «Б».** Найденное «ломает» правится сразу, в любой форме.

## Дополнение (5), 2026-11-06 — остаток русского в источнике: номера разделов, текст норм, описания схем (слово владельца)

Владелец спросил: «урок 1 уже целиком английский?». На предложение «Архитектора» добрать остаток ответил «да».

1. **Номера разделов норм** `Н0`–`Н5`, `Н2.1` и подобные — идентификаторы. Они пишутся латиницей `N0`–`N5`, `N2.1`, как суффиксы шагов в доп. (3) п. 3, в источнике и в переводе одинаково. 3. **Описания схем данных** (`description`, `x-owner`, комментарии) в источнике — по-английски. Ключи `catalog.tsv` и ячейки исходов, которые читают генераторы, — только вместе с правкой генераторов в той же поставке, через coord103.

## Дополнение (12), 2026-11-06 — выход генераторов не хранится в Git (слово владельца, З-9)

Владелец: «убрать tools/normgen/out из git совсем — выход генераторов не хранить, а генерировать при проверке и сборке пакета (out/ в .gitignore)». Текущее поручение: «удалить out/ (155 файлов с кириллицей) и влить в main английские исходники генераторов одним срезом».

1. **Источник и выход.** В Git остаются исходники генераторов, формы, среды и проверки. Весь каталог `tools/normgen/out/` исключается из отслеживания, а не только файлы с кириллицей. Путь включается в `.gitignore`. При проверке и сборке пакета выход генерируется во временном каталоге из точного источника.
2. **Сначала все потребители.** coord103 находит судей, тесты, `build_kit`, `code_origin`, README, паспорта Т2 и остальные места, которые читают сохранённый в Git выход. Они переводятся на генерацию на лету. Если для какой-либо функции действительно необходимо хранить выход именно в Git, Архитектор сообщает владельцу конкретную причину до удаления. Наличие чтения старого пути само по себе входит в задачу переделки.
3. **Один срез.** coord103 сводит английские исходники генераторов, переделанные потребители, исключение каталога и полную проверку в одном кандидате. Исполнители — единственные Генераторы и review103 по своим долям. История, доказательства, теги и закреплённые версии сохраняются.
4. **Полная проверка.** Порядок — сгенерировать и проверить, не храня выход в Git. Нельзя заменить проверку наличием старого файла, ослабить свежесть или засчитать ошибку среды/неполный результат как успешную проверку. Происхождение результата связывается с точными исходниками, формами, средами, судьёй и хешами фактического временного выхода.
5. **Т2 и состав пакета.** Удаление производных файлов из Git не исключает зависимости из границы места и не меняет пороги ADR-0129 (11). Паспорта и учёт происхождения переводятся на новый порядок вместе с потребителями. Ранее принятые решения о составе выдаваемого пакета сохраняются.
6. **Замена доп. (11).** Ожидание сохранённого общего `out/` после всех ревью отменяется для этого перехода. Временная генерация для проверок и сборки нужна сейчас. Ревью уроков, готовность источника и отдельное назначение линии остаются самостоятельными стадиями; новый запуск реализации этим поручением не назначен.
7. **Ответ владельцу.** Ответ с меткой З-9 записывается в общий `messages.tsv`; итог — в `owner-journal.md` по правилу ясности. До завершения поставки не объявляется, что выход уже удалён или все проверки пройдены.

Цена: каждая проверка и сборка тратит время на генерацию; воспроизводимость результата должна опираться на исходники и доказательства, а не на сохранённый выход.
