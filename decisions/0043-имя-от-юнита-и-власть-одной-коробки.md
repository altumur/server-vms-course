# Имя от юнита: процесс берёт только своё имя; власть запускающего — власть одной коробки и только при старте; коробку называет `BOX_ID`

## Context and Problem Statement

Класс системы: платформенная система — воркеры берут слоты-имена по CAS, юнит systemd или оркестратор даёт процессу имя (`WORKER_NAME`, `<ROLE>_NAME`, `SLOT_INDEX`).

Два случая давали лишних писателей. Отсечённый процесс с именем от юнита на следующем проходе брал **другое** имя: `w-srv-a-1` становился `w-2` — вторым воркером на сервере, о котором юнит не знает, а контроллер давал ему единицы. И «кто запускает, тот и власть»: процесс с именем от рантайма забирал имя у живого держателя, с какой бы машины его ни запустили. Две машины из одного образа вычисляли одно имя (`w-%l-1`) и отнимали его друг у друга, а тринадцатое ревью (блокер 3, проба `n5`) показало, что процесс с коробки B забирал истёкшее имя зависшего воркера коробки A и с ним его единицы.

## Decision Drivers

* юнит — источник правды о том, какие процессы на сервере должны быть;
* власть запускающего распространяется только на его машину;
* машину нужно узнавать не по имени хоста: клоны одного образа зовутся одинаково.

## Considered Options

* отсечённый процесс берёт любое свободное имя («другой слот» для всех);
* процесс с именем от юнита просит только это имя; «другой слот» — только у процесса без имени; имя у держателя другой коробки — только по слову контроллера; коробку называет `BOX_ID`.

## Decision Outcome

Выбран второй вариант (в продукте то же, ветка `r24-names`). Процесс, которому имя дал юнит, запоминает его при старте (`Worker.given`) и просит только его, свободным или истёкшим (`steal=False`); пока имя держит живой экземпляр, процесс остаётся никем и говорит тревогу `worker.name_taken`. Забрать имя у держателя без вердикта контроллера можно только при старте и только если держатель на **этой** коробке (`_on_this_box`); держатель другой коробки или имени без коробки отдаёт имя только по вердикту контроллера (`_held`), до него — отказ `NameOnAnotherBox` и тревога `worker.name_conflict`. Экземпляр называется `<коробка>:<pid>:<6 hex>`, коробка — `BOX_ID` из юнита (`%m`) или задания оркестратора, иначе `/etc/machine-id`, иначе имя хоста; `INSTANCE_ID` без `BOX_ID` коробки не называет.

### Consequences

* Good, because на сервере ровно те воркеры, которые назвал юнит, и зомби не становится вторым воркером.
* Good, because клоны одного образа больше не отнимают имя друг у друга, а спор виден на `/servers` и в журнале.
* Bad, because процесс, чьё имя держит живой экземпляр, стоит без дела, пока тот не уйдёт; без юнита (имя не дано) процесс по-прежнему берёт любое свободное имя.
* Bad, because клон ВМ со скопированным `/etc/machine-id` для этого правила — та же коробка; отличить его может только `BOX_ID`, заданный руками.

## Pros and Cons of the Options

### Любое свободное имя

* Good, because процесс всегда что-то исполняет.
* Bad, because появляются воркеры, о которых юнит не знает; клоны отнимают имена.

### Только своё имя, власть одной коробки

* Good, because имя и машина совпадают с тем, что запущено.
* Bad, because процесс без свободного имени простаивает.
