# Поток просмотра выбирает `live`, разрешение — настройка потока

## Context and Problem Statement

Класс системы: подсистемы `cam`, `live`, перевод `backend`.

У камеры есть поля `grid`, `full`: поток сетки и поток полного экрана выбирает пользователь (решение владельца 2026-10-26). У `grid` нет читателя, на странице сетки нет. Разрешение потока можно задать только руками в адресе, хотя у всех 5548 `videoStreaming` в `.rep` есть список разрешений. Контракт consolem полей `grid`, `full` не знает, а `res`, `fps`, `codec` имеет. Владелец спросил, зачем это хранить, и согласился с предложением `cammeta-console/ПРЕДЛОЖЕНИЕ-ПОТОКИ-РАЗРЕШЕНИЕ-И-ВЫБОР.md` (cc42b6a): «согласен», 2026-11-01. Это отменяет решение 2026-10-26.

## Decision Drivers

* выбор потока зависит от окна зрителя, а не от настройки камеры;
* совместимость с consolem, ADR-0103;
* адрес разбирает только источник.

## Considered Options

* оставить `grid`, `full`;
* `live` выбирает по размеру из запроса.

## Decision Outcome

Выбрано: `live` выбирает.

1. **`grid`, `full` снимаются** из `cam/cameras`, V/01.1, V/03, V/08. `stream` у `rec`, `det` не меняется: там выбор зависит от задачи.
2. **`POST /whep/<cam>?width=&height=`:** самый мелкий поток не меньше запрошенного, кодек из оффера. Размер — `resolution` строки, иначе `size` пульса. Ничего не известно — основной; запрошено больше всех — самый крупный. `?stream=<id>` остаётся. Камера другого кластера — только основной.
3. **Поле `resolution`** строки потока и камеры, `<ширина>x<высота>`; держатель передаёт драйверу. Пусто — настройка устройства не трогается.
4. **Адрес и поле.** Одно значение в двух местах — отказ держателя со словом в статусе: дверь адрес не разбирает.
5. **Список разрешений.** Держатель пишет его в `cam/devices` для заведённых устройств: каталог на 5548 описаний в таблице не нужен. До первого описания и у `generic` — ввод руками.
6. **Расхождение.** `resolution` не совпал с `size` при `running` — `warning`: смена меняет настройку устройства, а не только строку.
7. **`fps`** — та же настройка. **`codec`** — только чтение из пульса: `rec` принимает только H.264 (V/02.4). `bitrate` остаётся `none`.
8. **V/11:** `res`, `fps` — `both`, `codec` — `read`. Варианты `res` на устройство — вопрос к consolem: `reference.deviceParams` даёт их на вид, а не на модель.

### Consequences

* Good, because на одну настройку меньше, а зритель получает поток по окну.
* Good, because `res`, `fps` совпадают с контрактом.
* Bad, because запись настройки на устройство — новое действие держателя.
* Bad, because нормы V/01, V/03, V/08 и страница меняются до прогона; работой не проверено.

### Confirmation

Приёмка V/03: выбор по размеру при двух потоках; V/01: дубль адреса и поля, `warning` расхождения. Ревью Claude после норм.
