# Цель — минимум догадок; генератор делается, если он не больше кода, который выдаёт; ADR-0128 и его пилот отменены

## Context and Problem Statement

Класс системы: платформенная система (курс и пакеты генераторов к нему).

Цель курса — спецификация, по которой модель реализует урок с минимумом догадок. Собственный цикл и пакеты нужны, чтобы информация, которую получает модель, была под контролем.

ADR-0127 и ADR-0128 оценивали кандидатов в генерацию по строкам и по точкам срыва MiniMax и усложняли урок: формы, генераторы и судьи растут быстрее, чем код, который они заменяют. Разбор ядра хранилища P/01.1 это показал: чтобы сгенерировать 245–465 строк, нужны генератор на 670–1180 строк и судья на 1180–1980. Ревью урока читает прозу, таблицы, OpenAPI и `check_forms` вместе.

Выигрыш пакета по времени у Codex скромный: P/01 21 мин против ≈35, P/02 49 против 51, P/03 1 ч 02 мин против 2 ч 00 (ADR-0127). Дешёвые классы форм уже введены; остались в основном алгоритмы.

## Decision Drivers

* Сложность урока ухудшает главную цель: ревью и чтение становятся дороже, двусмысленность растёт на стыках прозы и формы.
* Генератор окупается ускорением, только если сам не дороже кода, который выдаёт.
* Срыв слабой модели — не всегда дыра в спецификации: Codex пишет ядро хранилища из прозы, MiniMax без посева — ни разу.

## Considered Options

* А — оставить ADR-0128 и его пилот.
* Б — главная мера — догадки; генератор — по правилу «не больше кода»; ADR-0128 и пилот отменить.
* В — новых генераторов не делать вовсе.

## Decision Outcome

Выбран вариант «Б» по слову владельца.

1. **Главная мера — догадки.** Спецификация хороша, если модель реализует урок без угадывания. Меры:
   - догадки линии (`GUESSES.md`) и места, где модель спросила или ошиблась из-за двусмысленности нормы;
   - время до GREEN линии без пакета (ADR-0083 доп. (96)).
   Места, где модели угадывают или срываются, исправляются **в норме**: явная фраза, вектор или шов приёмки. Форма для этого не нужна.

2. **Генератор — ради ускорения, при пяти требованиях.** Все должны выполняться:
   - **Т1. Форма заменяет прозу.** Норма ссылается на строку формы и не пересказывает её; формы, дублирующей прозу, нет.
   - **Т2. Генератор не больше кода.** Новые строки генератора (продюсер, без тестов и пустых строк) не больше строк кода, который он выдаёт, — по `origin-count` или по оценке до написания. Повтор в нескольких уроках не требуется.
   - **Т3. Детерминизм и закрытая грамматика.** Выход однозначно задан нормой; грамматика формы судится `check_forms` (ADR-0127 п. 3).
   - **Т4. Независимый судья.** Векторы урока, швы приёмки, мутанты, модель Quint — не тесты из той же формы. Новый судья пишет review-claude (ADR-0127 доп. (5)); его размер записывается рядом с Т2.
   - **Т5. Не из запрещённого списка** ревью Codex по З-2: алгоритм по ожидаемым ответам, криптография по векторам, распределённая корректность по локальной машине.

3. **Алгоритмы — прозой.** Снимок, блокировки, атомарность, сохранность, консенсус, оценщик прав, время в строке пишет модель (ADR-0127 п. 2). Ручного кода алгоритмов в пакете («функция в пакете» ADR-0128) нет; уже поставленные общие договоры (`slotname.go`, `sealing.go`) остаются.

4. **Бюджет сложности урока.** Ревью урока отмечает:
   - форму, дублирующую прозу: оставить одно из двух;
   - генератор больше своего выхода: кандидат на снятие, решает «Архитектор»;
   - норму, которую ни форма, ни проза не задают однозначно: правка нормы.

5. **Ядро хранилища P/01.1 — прозой.** Предложенная форма «решения о записи над снимком» отклонена: генератор 670–1180 строк больше выхода 245–465 (Т2). Тонкие места разбора 517c1d2cd вносит в норму P/01.1 spec103 фразами и векторами или швами, где их нет:
   - отказ уже принятой записи продвигает время последнего приёма (R088, R132);
   - порядок проверки условий — порядок списка, а в отпечатке повтора условия — множество;
   - границы сроков сравниваются и входят в отпечаток как binary64;
   - версии — непрозрачные строки с точным сравнением, `"0"` не равно `""`;
   - удаление отсутствующей строки не оставляет видимой версии (R116).

6. **ADR-0128 отменён вместе с пилотом.** Попыток 40b, 40c, 41a, 41b не будет. Открытые шаги ADR-0127, переданные в ADR-0128, переходят сюда (план ниже). Починка цикла MiniMax (паспорт до сухой пробы) остаётся долгом «Архитектора» до следующего запуска цикла.

7. **Ревью уроков по этим требованиям.** Codex и Kimi проходят P/01–P/10 и пишут раздел «Соответствие ADR-0129» вместо «Кандидатов в генерацию» ADR-0127 доп. (4):
   - (а) места догадок и двусмысленности — правки нормы;
   - (б) кандидаты в генерацию по Т1–Т5 с оценкой строк генератора, выхода и судьи;
   - (в) формы, дублирующие прозу;
   - (г) существующие генераторы, которые больше своего выхода.
   Первый раздел каждого отчёта — замечания к самим требованиям. VMS — после паузы «Спецификации VMS».

8. **Линии** запускаются по готовности урока, как прежде (ADR-0083 доп. (110)).

### Consequences

* Good, because главная мера совпадает с целью курса.
* Good, because генератор не растит урок сильнее, чем экономит.
* Good, because уточнение нормы помогает любой линии, а не только линии с пакетом.
* Bad, because часть кода, которую можно было бы сгенерировать, пишет модель.
* Bad, because Т2 до написания — оценка; ошибка оценки обнаружится только по `origin-count`.
* Bad, because проверки срыва на слабой модели больше нет: MiniMax не мера.

### Confirmation

Отчёты ревью Codex и Kimi по P/01–P/10 с разделом «Соответствие ADR-0129» разобраны; правки норм по ядру хранилища P/01.1 влиты; у каждого нового генератора записаны строки генератора, выхода и судьи.

## Pros and Cons of the Options

### А — ADR-0128 и пилот
* Good, because мера срыва на слабой модели.
* Bad, because четыре попытки и поставка ради предсказуемого итога; урок усложняется.

### Б — минимум догадок, генератор не больше кода
* Good, because простое правило, проверяемое числом строк.
* Bad, because ускорение от дорогих генераторов теряется.

### В — без новых генераторов
* Good, because урок не растёт.
* Bad, because дешёвые генераторы, которые ускоряют, тоже теряются.
