# Число метрики печатается по значению, а не по написанию в биении

## Context and Problem Statement
`metrics:` спеки (шаг 6) переведены в платформу продукта (`4840405`). Курс печатает число так, как его написал
воркер (`metrics._as_said`): JSON-целое целым, JSON-дробное дробным, `61.0` остаётся `61.0`. Довод курса: «строка,
которую уже матчит дашборд». Продукт читает биения во float64 и `61` от `61.0` не отличает. Канонический JSON
продукта написание числа тоже не хранит. Возраст (`age`) продукт печатал с сохранённой формой `10.0`. Два дерева
печатали одно значение по-разному.

## Decision Drivers
* У Prometheus значение — float64: `61` и `61.0` одно число.
* Текст метрики не должен зависеть от того, как биение записало число.
* Одно правило в обоих деревьях, без исключения для отдельного агрегата.

## Considered Options
* Печатать по написанию в биении, как курс (`_as_said`); продукту для этого нужно хранить написание.
* Печатать по значению; курс меняет `_as_said` и фикстуры.

## Decision Outcome
Выбран второй вариант. Число в `/metrics` печатается по значению:
- целое значение — целым: `61`, и у `age` тоже `10`, не `10.0`;
- нецелое — кратчайшей записью, которая читается обратно в то же значение: `7.5`. Экспонента допустима
  (`1e+21`, `1e-07`), Prometheus её читает.

Правило одно для отсчёта, для `le` корзины и для слова, с которым сравнивают (`equals`). Курсовое «как сказал
воркер» — утечка написания биения в текст метрики, а не принцип.

### Consequences
* Good, because у одного значения один текст в обоих деревьях, и дашборд матчит одно.
* Good, because продукту не нужно хранить написание числа.
* Bad, because строки курса с `.0` (и фикстуры на них) меняются, и дашборд, который матчил `61.0`, надо поправить.

### Confirmation
Тест продукта `sampletext_internal_test.go`: `61` → `61`, `10` → `10`, `7.5` → `7.5`, `0.1` → `0.1`, `1e21` →
`1e+21`, `1e-7` → `1e-07`. Тест `metrics_test.go`: `age` печатается `10`. Курс: `_as_said` и фикстуры печатают по
значению.
