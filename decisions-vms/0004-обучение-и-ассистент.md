# ADR-VMS-0004. Обучение и ассистент: ассистент предлагает готовую главу учёбы, человек открывает её в отдельной учебной вкладке

## Context and Problem Statement

Класс системы: платформенная система (подсистема VMS `backend` и её оболочка).

Слово владельца 2026-11-08: «найди сессию консоль — поручи ей сделать предложения по интеграции обучения с ассистентом — с тебя ADR VMS».

Что есть сейчас (consolem upstream `cb728a4`, нормы VMS `ef7192b2d`; разбор «Консоли»):

* **«Учёба» consolem** — шесть тем готовых исполняемых туров (`assets/tour.js`, `tour-demos.js`): дерево, папки, детекторы, хранилища, мастера, правила. Тур идёт на встроенном сервере в памяти вкладки (`?demo`), рабочего API не трогает. Шаги — доверенный код поставки: функции `before`, селекторы DOM, нажатия. Устойчивых ID глав и шагов нет, ссылка — номер темы и позиция шага. Показ только на русском. Тур открывается в той же вкладке.
* **Ассистент consolem** — `POST /assist/turns` с событиями `progress`, `question`, `plan`, `refused`, `answer`, `found`, `error`; схемы закрыты для лишних полей. Ссылки на учебный материал в договоре нет; `answer.text` показывается как текст, не как ссылка.
* **Касаются они только предметно:** туры показывают формы и «Применить», с которыми работает и ассистент; поиск находит главы, рядом — вход в разговор. Связи «просьба → нужная глава» нет.
* **VMS:** V/10 — один шаг локальной модели без прав, веса локально. V/11 ведёт цикл, инструменты (закрытый набор V/11.10, V/11.13), проверку плана (V/11.11), показ (V/11.12). Оболочка V/11 собрана `--without-learn`: обучение в поставке w2c пока исключено (условия ответов consolem 093202Z, 103525Z не закрыты).
* **Риск, найденный разбором:** в автономном `?demo` адрес внешней демо-службы ассистента (`?assist=…` или метка `consolem-assist-public`) не запрещён — учебная вкладка может отправить просьбу и снимок учебных данных наружу. В сборке w2c это закрывает метка `consolem-api`, но учебный режим сам этого не запрещает.
* Прежнее слово владельца (2026-11-05, обсуждение с «Консолью»): от генерации показов моделью перейти к каталогу заранее подготовленных туров.

Вопрос: как связать обучение с ассистентом, не дав модели управления интерфейсом и не ослабив границу V/10, V/11.

## Decision Drivers

* Модель без прав (V/10) и запись только человеком через форму (V/11.11–11.13) не ослабляются.
* Учебное не попадает в рабочее и наоборот: данные, планы, `uid`, секреты, история.
* Работа без облака: модели нет — каталог и поиск остаются.
* Тур — проверенный код поставки; модель не сочиняет шаги, клики, URL.
* Меньше новой механики: платформа не меняется, договор consolem — одним согласованным запросом.

## Considered Options

* **А. Ассистент выбирает готовую главу.** Ответ несёт типизированную ссылку на главу проверенного каталога; человек открывает её кнопкой в отдельной учебной вкладке.
* **Б. Ассистент отвечает по материалам учёбы.** Локальный текстовый пакет курса, поиск кодом, ответ со ссылками на фрагменты.
* **В. Помощник текущего учебного шага.** Разговор с моделью изнутри учебной вкладки о текущем шаге.
* **Г. Учёба показывает работу ассистента.** Готовые главы о цепочке «просьба → вопрос → план → проверка → применение» на заглушке, без живой модели.

## Decision Outcome

Выбраны **А как интеграция и Г как учебное содержание** (рекомендация «Консоли»; ждёт слова владельца). Б — после появления пригодного текстового пакета, отдельным решением. В — отложен до отдельного решения об изоляции учебной вкладки и доказанной потребности.

1. **Учебная ветвь V/11.** Тип хода (рабочий или учебный) выбирает `backend`; нового поля `kind` в HTTP-запросе нет. В учебной ветви — только чтение утверждённого каталога и проверка выбранной ссылки; рабочих чтений (камеры, обзор кластера) и инструментов рабочего плана нет. Правила V/11.11–11.13 для рабочих планов не меняются; учебная ссылка не план и вместо плана не проходит.
2. **V/10 не меняется.** Учебная ветвь зовёт обычный шаг локальной модели с прежним допуском (`view` на строке модели).
3. **Каталог.** Один источник с турами: устойчивые ID тем и глав, версия или отпечаток каталога, язык, название, цель, учебный набор, доступность в сборке. Тексты не копируются во второй редактируемый файл. Поставка каталога и файлов обучения — в составе VMS с SHA (V/11.1), механизм платформы прежний.
4. **Модель возвращает только ID.** Ответ несёт ID каталога, темы, главы; адрес учебной страницы строит интерфейс из своей поставки. Неизвестный ID или чужая версия каталога ничего не запускают — интерфейс предлагает открыть каталог. URL, HTML, JavaScript, селекторы из ответа модели не исполняются.
5. **Запуск — человеком, отдельной вкладкой.** По кнопке, не по событию SSE; `noopener`, без управления рабочей вкладкой; рабочая вкладка продолжает получать тревоги, учебная предупреждает, что тревог в ней нет. Параметры рабочего адреса (`api`, `assist`, `fixture` и прочие) не наследуются.
6. **Изоляция учебного режима.** Внешняя служба ассистента в учебном режиме запрещена и из параметров, и из меток страницы, включая публичную метку по умолчанию. Учебные создание, удаление, «Применить», `ask`/`escalate` не вызывают рабочий API. Рабочие черновики, история и секреты в учебный контекст не попадают; если изоляцию хранилища обеспечить нельзя — показ не идёт.
7. **Без модели и без обучения.** Модели нет — каталог и обычный поиск. Сборка без обучения (`--without-learn`) — интерфейс не обещает урока.
8. **Г — главы об ассистенте.** На подготовленных ответах или заглушке, с явной подписью; учебное «Применить» не выдаётся за изменение рабочей системы, успех урока — не замер модели и не доказательство проверки плана V/11.11.
9. **Договор consolem — одним запросом** через «Консоль», после принятия этого ADR и с согласия владельца договора: каталог одной версии с турами; устойчивые ID глав; типизированные учебные ссылки в `answer` (предлагаемая форма, имена полей утверждает владелец договора); запуск отдельной вкладкой и закрытие внешних демо-адресов; поведение при неизвестной версии, без курса, без модели; главы об ассистенте и совместные проверки тура с панелью. Отправка запроса наружу — по отдельному «да» владельца.
10. **Оболочка V/11 остаётся без обучения,** пока не закрыты условия ответов 093202Z, 103525Z и не принят ответ consolem на запрос п. 9.

### Consequences

* Good, because оператор из вопроса «как настроить…» попадает в проверенный показ, а модель не получает ни интерфейса, ни рабочих данных.
* Good, because V/10 и платформа не меняются; правки — учебная ветвь V/11 и договор consolem.
* Good, because Г полезен и без модели: учит работать с ассистентом на честно подписанных примерах.
* Bad, because нужна работа на стороне consolem (каталог, ID глав, ссылки в `answer`, отдельная вкладка); срок задаёт владелец договора.
* Bad, because качество выбора главы моделью не известно; его надо мерить отдельно.
* Bad, because туры только на русском — при английском интерфейсе карточка должна это говорить.

### Confirmation

До включения в w2c (по разбору «Консоли», раздел 6):
* ссылки: известная, неизвестная, переставленная глава, чужая версия, сборка без обучения — неверная ничего не запускает;
* недоверенный ответ модели: URL, HTML, JavaScript, селекторы, несуществующие ID не исполняются;
* права: право на модель не даёт права на объект; урок не обходит отсутствие права на рабочую операцию;
* изоляция: учебные действия и разговор после «Попробовать самому» не зовут рабочий API; внешняя служба закрыта и меткой, и параметром;
* хранилище и секреты: перезагрузка, несколько вкладок, смена человека не переносят рабочее в учебное;
* рабочая вкладка сохраняет соединение и тревоги;
* поставка: воспроизводимая сборка, манифест и SHA, вход, CSP во всех поддерживаемых браузерах;
* без сети и без модели: каталог и туры доступны, наружу ничего не уходит;
* качество выбора: корпус вопросов с эталоном автора материала до прогона; пороги — после исходного замера `[TODO: пороги качества выбора главы — после первого замера]`.

## Pros and Cons of the Options

### А. Выбор готовой главы

* Good, because модель выбирает из закрытого списка, проверка ID — кодом.
* Bad, because нужны каталог и ID глав в consolem; средний объём.

### Б. Ответы по материалам

* Good, because объяснение со ссылками на источники.
* Bad, because материалы сейчас встроены в исполняемые туры, учебника нет; риск выдуманного пересказа; объём больше А.

### В. Помощник шага

* Good, because помощь прямо во время практики.
* Bad, because учебная вкладка начинает ходить к модели — новое исключение изоляции; закрытую схему `AssistTurnRequest` придётся расширять; большой объём.

### Г. Учёба об ассистенте

* Good, because малый объём, без новой механики и живой модели.
* Bad, because пример можно принять за гарантию поведения живого ассистента — нужна явная подпись.
