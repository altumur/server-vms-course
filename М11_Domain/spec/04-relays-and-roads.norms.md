# М11/4 — Ретранслятор и дороги: нормы

Канон урока. [Лекция](../04-relays-and-roads.md), [HTTP-контракт](04-relays-and-roads.api.openapi.yaml),
[инструкция](04-relays-and-roads.README.md), [приёмка](../../Source/tests/testdata/acceptance/М11_Domain/04/README.md).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../НОРМАТИВНЫЕ-СЛОВА.md). Порядок массивов вывода — урок 1 Н0 (общее М11).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](../../М10_Platform/spec/01-storage.norms.md#время-в-строке): `domain/topology` — `at`; объект `domain/reached` — `ts`.

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `domain/topology`, `domain/member-topology`, `domain/reached`, `domain/reaches`;
- пишет: `domain/view` (put);
- читает: `domain/members`, `domain/keys`.

Общее уроков 2 и 3 Н1 действует (hex, base64url, JCS, закрытые формы; публикация, поколение, метка, подпись агента,
ответ держателя — урок 3).

### Н1.1 Ретранслятор

```yaml
relay:        член домена, через агента которого держателю отчитываются другие члены — те, до кого держатель не
              дотягивается (камера в сети офиса); принят, как любой член (урок 3), со своим ключом и своим отчётом
door:         агент ретранслятора открывает дверь для членов за ним: RELAY=1, RELAY_HOST (умолчание 0.0.0.0),
              RELAY_PORT (умолчание 8446); член за ретранслятором вместо DOMAIN_URL получает RELAY_URL
not_author:   ретранслятор не автор чужого: несёт отчёты членов держателю и ответы держателя членам, секретное ответа
              (конверт m1, урок 3 Н1.5) открыть не может; просьбы токенов несёт байт в байт (урок 7)
one_hop:      между членом и держателем — не больше одного ретранслятора; держатель — ничей ретранслятор
```

### Н1.2 Топология

```yaml
domain/topology:   {doc: <JCS текст>}         # у держателя; писатель — процесс domain по двери Н2 (урок 3 Н1.8), CAS
  doc:             {rev, centre?, star, via, by?, at?}
    rev:           целое ≥ 0; 0 — «никогда не писали» (строки нет — так же); +1 на запись
    centre?:       член — центр домена: к нему тянутся звёздные ретрансляторы (уроки 7, 12)
    star:          [<член>…] — звёздные ретрансляторы: до них не дотянется никто, данные они берут у центра (уроки 7, 12);
                   по возрастанию, без повторов
    via:           {<член>: <ретранслятор>} — член отчитывается через ретранслятор; члена нет — отчитывается прямо
    by?, at?:      кто и когда (стенные секунды консоли) записал
  refusals:        (каждая — причиной в одном отказе 409, через «; »)
    - имя в centre, star, via (член или ретранслятор) — не член домена: «<что>: <имя> is not a cluster of this domain»
    - star без centre: «a star relay takes its members' data from the centre, and there is no centre»
    - centre в star: «<c> is the centre and cannot be a star relay»
    - держатель в star: «<h> is the domain holder: it reaches the domain in place and is no star relay»
    - член через себя: «<m> cannot reach the domain through itself»
    - цепочка: via[via[m]] есть — «… one relay between a member and the domain»
    - через держателя: «<m> through <h>: that is the domain holder itself»; держатель в via — «<h> is the domain holder:
      it reaches the domain in place, through nobody»
domain/member-topology: {doc}                # у члена: строка domain/topology из ответа держателя (поле topology) как есть
put_order:         PUT /domain/topology по порядку: 400 — нет base_rev или тело не по форме → 409 «the topology is at rev N;
                   this edit was made against rev M — look again» (ревизия раньше содержания) → отказы refusals одним 409
                   через «; » → запись по CAS (не больше 10 конфликтов); star пишется по возрастанию без повторов; via
                   с пустым ретранслятором — член уходит из via; by — имя, доказанное сторожевой (урок 9 Н1.5)
home:              ближайшая дверь члена к домену — via[член], иначе centre, иначе держатель (урок 7 `poll_home`)
```

Какой дорогой агент отчитывается, решает его окружение (`DOMAIN_URL` или `RELAY_URL`), не топология; топология
говорит держателю и ретранслятору, кого через кого **принимать**. Член, чей отчёт пришёл не той дорогой, отвергается
(Н3); прямой отчёт члена, которого топология ведёт через ретранслятор, держатель принимает — это вторая дорога (Н1.3).

### Н1.3 Дороги и порядок

```yaml
road:          прямо (via нет) или через ретранслятор R (via = R); дорогу публикации называет держатель, не член
one_road:      порядок задаёт дорога: последнее принятое на этой дороге — новее, даже если sent_at назад (урок 3 Н3)
two_roads:     между дорогами одного члена — по sent_at члена (одни часы на обеих): тело другой дороги со sent_at ниже
               метки не принимается (ignored), пока член слышен — heard_ago < ROAD_QUIET (урок 3 Н3 шаг 2а); равный
               sent_at — одно тело: те же байты — heard (повтор другой дорогой), другие — 409 same_sent_at (урок 3 Н3 шаг 2)
ROAD_QUIET:    15         # с, монотонные часы держателя: три прохода агента (REPORT_EVERY 5); дольше — прежняя дорога молчит
base:          у каждой дороги своя: ответ даёт rev метки только дороге метки, другой — 0 (шлёт целое)
signature:     метка прямого отчёта несёт подпись агента; через ретранслятор подпись члена не переносится — держатель
               верит подписи ретранслятора и топологии (ADR-0074; перенос подписи члена — долг, ответ на записку М11 п. 4)
bytes:         delta поколения через ретранслятор — запись relayed[<член>] пакета как получена (JCS этого значения)
```

### Н1.4 Пакет ретранслятора

```yaml
batch:         тело POST /api/relay/<ретранслятор> — JSON-объект {relayed, knocks?}, подпись агента ретранслятора (урок 3 Н1.4)
  relayed:     {<член>: <публикация урока 3 Н1.2>} — целое или изменение против rev, который держатель дал этой дороге
  knocks?:     {<имя>: {publication: <текст тела>, signature: <X-Agent-Signature как пришёл>}} — стуки незнакомцев
               к двери ретранслятора; держатель проверяет подпись ключом, который тело предъявило (урок 3 Н1.2 key), над
               POST /api/member/<имя> и телом; верная — стук (урок 3 Н1.1 knock), неверная или член — пропуск
answer:        {relay_for, relayed, refused, keys}
  relay_for:   [<член>…] — кого топология ведёт через этот ретранслятор, по имени
  relayed:     {<член>: <carry урока 3 Н1.5>} — ответ держателя каждому члену relay_for; rev — для дороги этого ретранслятора
  refused:     {<член>: <причина>} — что из relayed пакета не принято (топология, форма, 409 урока 3); стуки — не здесь
  keys:        {<член>: <hex ключа>} — принятые ключи членов relay_for; отозванный — пустая строка
BATCH_LIMIT:   64 MiB     # = 4 × BODY_LIMIT урока 3; пакеты — в порядке имён членов; член больше BODY_LIMIT — не шлётся (журнал)
KNOCKS:        32 незнакомца в памяти ретранслятора, тело не больше 256 KiB; последний от имени заменяет прежний;
               33-й незнакомец вытесняет самый старый стук (по времени приёма); вытесненный узнаёт это только по
               knocking держателя (урок 3 Н1.1) — нового отказа нет
domain_age:    поле, которое ретранслятор добавляет к ответу члену: секунды с последнего ответа держателя ретранслятору
domain/reached: {ts}      # объект у члена (М10/8 Н1.1): стенные секунды, когда агент последний раз дотянулся до домена:
                          # прямо — момент ответа; через ретранслятор — момент ответа минус domain_age; назад не уходит;
                          # тот же ts — не переписывается, новый — не чаще FRESH_EVERY (урок 12 Н1.2 fresh)
```

### Н1.5 Сети члена

```yaml
domain/reaches:  {networks: [<сеть>…]}       # объект члена, агент несёт его в отчёте (урок 3 Н1.2 member_objects)
  networks:      слова REACHES окружения агента (через запятую, например vlan:site-a), иначе сети интерфейсов
                 «net:<cidr>» без /31, /32 и туннельных, мостовых, контейнерных интерфейсов; по возрастанию, без повторов
use:             размещение доменом по достижимости — долг урока 6 (ответ на записку М11 п. 3); вид держателя хранит как есть
```

### Н1.6 Вид: поля урока 4

```yaml
domain/view.topology:     doc строки domain/topology, прочитанный проходом; нет строки — {rev: 0, star: [], via: {}}
domain/view.reports.<член>.via: дорога метки (урок 3 Н1.7)
domain/view.relay_refused: {<ретранслятор>: {<член>: <причина>}} — последние отказы пакетов этого процесса
```

## Н2 Двери

HTTP-контракт: [04-relays-and-roads.api.openapi.yaml](04-relays-and-roads.api.openapi.yaml). Разбор запроса — М10/1 Н2.1
с отступлениями М10/9 Н2.

Дверь ретранслятора и пакет `relayed` — класс `signed` серверной стороны TLS урока 8 Н1.6 `server`: сертификат клиента не требуется и прав не даёт, личность — подпись члена.

| Дверь | Кто отвечает | Успех | Отказы |
|---|---|---|---|
| POST `/api/relay/<ретранслятор>` | процесс `domain` держателя | 200 answer (Н1.4) | 413 больше BATCH_LIMIT; 400 не пакет; 404/403/401 — ретранслятор как член (урок 3 Н2); 409 `deposed` (урок 10 Н1.6); 503 `standby` (урок 12 Н1.7); отказ одного члена — в `refused`, не код |
| POST `/api/member/<член>` | дверь ретранслятора | 200 — carry держателя для члена (из памяти) с `rev` копии ретранслятора и `domain_age` | 413; 400; 403 «<член> does not reach the domain through this relay: the domain's topology says so, not the relay» (незнакомец с верной подписью своим ключом — запомнен стуком); 403 ключа нет (принят до ключей); 401 подпись (урок 3 Н1.4, ключ — из `keys`); 409 `rebase`; 503 «the relay has nothing from the domain for <член> yet» |
| GET `/api/carry/<член>` | дверь ретранслятора | 200 — carry из памяти с `domain_age` | 403, 401, 503 — как выше |
| POST `/api/tokens/<член>/…` | дверь ретранслятора | урок 7 | урок 7 |
| GET `/domain/topology` | консоль домена | 200 doc (Н1.2) | 404 `no domain here`; 401/403 — урок 9 |
| PUT `/domain/topology` `{base_rev, centre?, star?, via?}` | консоль домена → процесс `domain` (урок 3 Н1.8) | 200 doc после записи по CAS (не указанное поле — прежнее; `via` — целиком, пустой ретранслятор — член уходит из via) | 400 нет `base_rev`; 409 «the topology is at rev N; this edit was made against rev M — look again»; 409 отказы Н1.2; 409 «the topology kept changing; look again» после 10 конфликтов CAS |

Дверь ретранслятора принимает члена той же функцией «принять» урока 3 Н3 над своей памятью: у ретранслятора своя
целая копия каждого члена и свой `rev` для его дельт. Держатель видит только то, что ретранслятор поднял пакетом.

## Н3 Проход

### проход ретранслятора (в каждом проходе его агента, после своего отчёта)

```
1. взять из памяти принятые с прошлого прохода публикации членов (по члену — последняя) и стуки
2. для каждого члена: rev держателя для этой дороги известен (up[член]) → изменение против него (урок 3 Н1.2 change),
   иначе целое; база дельты — подтверждённая этой дорогой (урок 3 Н1.2 change); все поля публикации вне дельты (`stale`,
   `key`, `keys_rev`, `pinned` и поля поздних уроков: `outcomes`, `tls_ca`, `members_rev`, `sign_failures`, любые
   следующие) — из последней публикации члена как есть: правило, а не список
3. разложить по пакетам не больше BATCH_LIMIT в порядке имён; стуки — в первом
4. POST /api/relay/<я> каждый пакет; ответ → up[член] = relayed[член].rev для принятых, забыть up[член] для refused и
   неотвеченных (следующий раз — целое); relay_for, keys — заменить; ответы членов — в память (члены не из relay_for — забыть);
   heard = сейчас
5. нет ответа → вернуть невзятые публикации в память, если с тех пор не пришло новее; стуки — отбросить; heard не менять
```

Проход ретранслятора идёт, даже если его собственный отчёт держателю не прошёл (урок 3 Н3 шаг 5). Пакет уходит каждым
проходом, и пустой (`{relayed: {}}`): так ретранслятор без членов в памяти узнаёт `relay_for` и `keys`. Пока `relay_for`
не называет члена, его отчёт у двери ретранслятора — отчёт незнакомца: верная подпись своим ключом — стук в памяти и 403
(Н2), неверная — 401. До первого ответа держателя ретранслятор отвечает члену 503 (Н2), и член `domain/reached` не пишет.

### держатель на POST /api/relay/<ретранслятор>

```
1. подпись и ключ ретранслятора — как у члена (урок 3 Н2)
2. для каждого relayed[член]: член не в списке или via[член] ≠ ретранслятор → refused «<член> does not reach the domain
   through <ретранслятор>: the topology says <via или direct>»; key публикации ≠ key записи члена или отозван (revoked_keys,
   revoked_members набора) → refused «<член> presents another key than the one in the list, or it was revoked», ничего
   не записано; больше BODY_LIMIT → refused; иначе принять (урок 3 Н3)
   с via = ретранслятор и байтами relayed[член] (JCS); отказ принять → refused (слово урока 3)
3. стуки — Н1.4 knocks
4. ответ: relay_for по топологии, relayed — carry каждому члену relay_for (rev — для этой дороги), refused, keys
```

### агент члена за ретранслятором

Как урок 3 Н3, но дверь — `RELAY_URL`; `rev` ответа — копии ретранслятора; после ответа — `domain/reached` по
`domain_age` (Н1.4). Член за ретранслятором, которого ретранслятор не ведёт, получает 403 и остаётся без ответа: держатель
видит его молчащим (урок 1).

**Гонки.** Ретранслятор пишет память одним процессом; поздний ответ держателя на старый пакет не затирает более новую
публикацию члена (шаг 5). Член, переведённый топологией к другому ретранслятору, перестаёт получать ответы прежнего в его
следующем проходе (`relay_for`). Две дороги одного члена — правило Н1.3: держатель не смешивает их тела.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| пакет больше BATCH_LIMIT | 413 | ретранслятор: журнал | дробить пакеты (Н3) |
| тело не пакет Н1.4 | 400 | ретранслятор: журнал | дефект ретранслятора |
| ретранслятор не член / ключ / подпись | 404 / 403 / 401 (урок 3 Н2) | ретранслятор | принять ретранслятор членом |
| ключ публикации не ключ записи члена или отозван (держатель) | `refused[член]` «presents another key…» | ретранслятор; вид — `relay_refused` | принять заново |
| тело члена больше BODY_LIMIT (держатель) | `refused[член]` | ретранслятор | — |
| у двери ретранслятора: тело больше BODY_LIMIT, не публикация | 413 / 400 | агент члена | урок 3 Н4 |
| у двери ретранслятора: ключа нет (принят до ключей), подпись | 403 / 401 | агент члена | урок 3 Н4 |
| у двери ретранслятора: база не та | 409 `rebase` | агент члена | послать целое |
| процесс смещён; процесс `domain` — ждущий | 409 `deposed`, 503 `standby` (уроки 10, 12) | ретранслятор | урок 3 Н4 |
| член не через этот ретранслятор (держатель) | `refused[член]` | ретранслятор; вид — `relay_refused` | поправить топологию или окружение члена |
| член не через этот ретранслятор (дверь ретранслятора) | 403 | агент члена: журнал | то же |
| у ретранслятора нет ответа держателя для члена | 503 | агент члена | ждать прохода ретранслятора |
| тело другой дороги старше, член слышен | ignored (200, ничего не записано) | — | — |
| правка топологии: устаревший `base_rev`, отказы Н1.2, CAS («the topology kept changing; look again» после 10 конфликтов) | 409 | оператор | перечитать и править |
| правка без `base_rev` | 400 | оператор | назвать `base_rev` |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как агент ретранслятора открывает дверь** (`RELAY`, `RELAY_HOST`, `RELAY_PORT`; TLS — урок 8 Н1.6: роль `domainagent`, `RELAY_CA`, `RELAY_MEMBER`) и где хранит память
   копий, ответов и стуков (в процессе; после перезапуска пуста — члены шлют целое по 409 `rebase`);
2. **как агент считает сети** `domain/reaches` без `REACHES` (какие интерфейсы считает туннельными и мостовыми).
