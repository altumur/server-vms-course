# М11/10 — Передача держателя, копия и восстановление, хранители: инструкция для реализации

## Задача

Дать домену срок и запись срока, которую проверяет каждый член. Держать копию того, что решил домен, у хранителей.
Переносить домен по файлу восстановления и передавать его с живого держателя. Члены должны следовать за большим
сроком сами, а смещённый держатель — уступать и перечислять брошенное.

## Входы и их приоритет

Канон — [нормы](10-holder-transfer-and-keepers.norms.md). [HTTP-контракт](10-holder-transfer-and-keepers.api.openapi.yaml)
выражает формы дверей урока. Пересылку дверей к подписанту задаёт урок 8 Н1.9, ключи и смену после кражи — урок 2.
[Приёмка](../../Source/tests/testdata/acceptance/М11_Domain/10/README.md) — стенд урока 3 с подписантом и на `m1` и векторы
`record`, `follow`, `ask-sig`. [Лекция](../10-holder-transfer-and-keepers.md) объясняет причины. При противоречии записать
место и контрпример и передать «Спецификации»; инструкция не вводит новый отказ.

## Что создать

- Процесс `domain`:
  - запись срока и `claim`;
  - копия и указатели хранителей, `backup` в ответе агенту;
  - взгляд на своё хранилище и уступка, 409 `deposed`, `forgotten`, `domain/stranded`;
  - передача (заморозка, `prepare`, `take`) и приём передачи;
  - аварийный перенос.
- Установка (урок 2): `backup_key_secret` и `backup_key_rev` в `domain/signer`.
- Агент: следование по `/api/held` и 409 `deposed`, проверка `record`; хранение копии (`domain/backup`,
  `domain/backup-taken`), её объект в отчёте.
- Консоль кластера: `GET /api/held`, `GET /api/backup` с проверкой `ask-sig`.
- Консоль домена: `/domain/handover`, `/domain/stranded/apply`; вид `term`.
- Команды `record`, `follow`, `ask-sig`; `w2cctl domain move`.

## Порядок работы

1. `record`, `ask-sig`, `follow` по векторам.
2. Запись срока и `claim`; `/api/held`.
3. Копия: состав, ключ копии, ревизия по содержимому, хранители, агент хранителя, `/api/backup`.
4. Аварийный перенос: соседи, выбор копии, новый срок, ключи.
5. Смещение; плановая передача; брошенное.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н3 следовать | Идти за записью из ответа соседа без проверки | Только после `record` по своему набору; иначе — журнал, не идти. |
| Н3 следовать | Перейти на меньший срок, когда старый держатель вернулся | Назад не идти никогда: свой больший срок держать. |
| Н1.5 | Новая ревизия копии каждым проходом | Только при смене содержимого с открытыми секретами: печать даёт новый nonce, сравнивать надо открытое. |
| Н1.8 | Срок = срок умершего держателя + 1 | `1 + max` по записям и копиям всех ответивших: второй перенос не сравняется с первым. |
| Н1.8 | Восстановиться из той копии, что отдали, когда сосед объявил новее | 409 с перечнем: откат состояния молча — хуже отказа. |
| Н1.7 | Считать передачу безопасной против прежнего держателя | Ключи копируются; «забыл» — обещание. Не доверяешь прежнему — `stolen`. |
| Н1.6 | Уступить по слову соседа | Только по записи своего хранилища, проверенной своим набором. |

## Готово, когда

- Сценарии приёмки 01–07 проходят.
- Описание реализации называет команды и то, как раннер поднимает подписанта на другом кластере (`@start domain on`) и
  переносит домен (`@move`).

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением.
