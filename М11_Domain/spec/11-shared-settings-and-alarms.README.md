# М11/11 — Общие настройки и тревоги членов: инструкция для реализации

## Задача

Держать общие настройки домена одним подписанным документом за указателем и нести его каждому члену. Разрешать
значение домена при чтении, только для полей, которые объявила спека. Собирать тревоги членов из их отчётов, называть
молчащих и хранить неделю истории у держателя.

## Входы и их приоритет

Канон — [нормы](11-shared-settings-and-alarms.norms.md). [HTTP-контракт](11-shared-settings-and-alarms.api.openapi.yaml)
выражает формы дверей урока. Подпись и её проверку задаёт урок 10 (`record`), заморозку — урок 10, индекс событий —
М10/8. [Приёмка](../../Source/tests/testdata/acceptance/М11_Domain/11/README.md) — стенд урока 3 и векторы `resolve`, `alarms`;
[лекция](../11-shared-settings-and-alarms.md) объясняет причины. При противоречии записать место и контрпример и передать
«Спецификации»; инструкция не вводит новый отказ.

## Что создать

- Загрузчик: форма `domain.shared` и правило `merge` (случаи `m61_shared_*` урока 2).
- Процесс `domain`:
  - правка общего документа по порядку Н1.3, объект и указатель;
  - переподпись после переноса;
  - `shared` в ответе агенту;
  - история тревог в проходе.
- Консоль домена: `GET /domain/shared` (`doc`, `delivery`, `declared` со схемой), `GET /domain/alarms`; вид `shared`.
- Агент:
  - приём документа по Н3, отказ, строки в отчёте;
  - фронт тревог раз в секунду, страница и срочный отчёт.
- Консоль кластера: `GET /domain/shared/<sub>` с `resolve`.
- Команды `resolve` и `alarms`.

## Порядок работы

1. `resolve` и `alarms` по векторам.
2. Объявление `domain.shared` и `merge` в загрузчике.
3. Документ, указатель, правка, доставка, приём агентом.
4. Дверь значений у консоли кластера; доставлено скольким.
5. Страница тревог, фронт, список и история.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.5 | Записать значение домена в строки единиц | Только при чтении: строка не меняется, значение говорит, откуда оно. |
| Н1.4 | Взять документ с меньшим `(term, rev)` после восстановления держателя | Никогда назад: сравнить до загрузки. |
| Н1.4 | Проверить подпись набором, пришедшим вместе с документом | Только своим набором (`record` урока 10). |
| Н1.3 | Отказать первой причиной | Все причины содержания одним 400 через «; ». |
| Н1.7 | Собирать страницу тревог каждую секунду | Раз в секунду — только фронт (одна строка индекса); страница — при новой тревоге. |
| Н1.9 | Писать историю из запроса списка | Пишет только проход держателя; список читает. |
| Н1.8 | Выбросить тревоги молчащего члена | Тревоги последнего отчёта остаются, плюс строка молчания. |

## Готово, когда

- Сценарии приёмки 01–04 проходят; случаи `m61_shared_*` урока 2 дают свои вердикты.
- Описание реализации называет команды `resolve`, `alarms` и то, как агент читает фронт тревог.

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением.
