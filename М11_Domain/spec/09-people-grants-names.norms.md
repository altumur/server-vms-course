# М11/9 — Люди, гранты, имена: нормы

Канон урока. [Лекция](../09-people-grants-names.md), [HTTP-контракт](09-people-grants-names.api.openapi.yaml),
[инструкция](09-people-grants-names.README.md), [приёмка](../../Source/tests/testdata/acceptance/М11_Domain/09/README.md).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../НОРМАТИВНЫЕ-СЛОВА.md). Порядок массивов вывода — урок 1 Н0 (общее М11).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](../../Platform/01-store/spec/01.1-store.norms.md#время-в-строке): `domain/users/<имя>` — `at`; строка гранта — `until` (`0` — без срока); копия `domain/grants` — `as_of`.

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `domain/users/<имя>`, `domain/disabled`, `domain/grants/<кластер>`, `domain/grants`, `domain/break-glass/<кластер>`, `domain/names/<sub>/<книга>`, `domain/deleting/<имя>`;
- пишет: `domain/revoked` (put);
- читает: `domain/member`, `domain/keys`, `domain/revoked`, `domain/members`, `domain/signer`.

Общее уроков 1–8 Н1 действует. Люди живут у держателя; токен человека называет субъект и ничего больше (урок 2 Н1.6,
`kind: person`, без `aud`). Что человеку можно, решает каждый кластер по своим грантам, которые несёт агент; проверка —
локальное чтение без связи с доменом. Люди с паролями и аварийные пароли — операции процесса `domain` (подписант, ADR-0032),
он проверяет каждую сам; гранты пишет он же (урок 3 Н1.8: консоль домена правку передаёт). Решение «Архитектора» по вопросам М11/9.

### Н1.1 Человек

```yaml
domain/users/<имя>:  {name, how, pwhash_secret, disabled, at, by}      # у держателя; писатель — процесс domain
  name:        имя человека — 1–64 символа без пробельных, управляющих (U+0000–U+001F, U+007F) и : | ( ) " /;
               не ровно break-glass (имя аварийной сессии — break-glass(<who>), скобки и так запрещены) — 400 bad name;
               не субъект индекса имён (Н1.7)
  how:         "password"                       # иных способов входа урок не нормирует
  pwhash_secret: pbkdf2-sha256$600000$<соль: 32 hex>$<ключ: 64 hex> — PBKDF2-HMAC-SHA256 от UTF-8 пароля, соль —
               16 случайных байт, ключ — 32 байта; секрет по суффиксу (P/02.1 Н1.3а), запечатан кольцом держателя
  disabled:    true | false
  at, by:      стенные секунды и имя человека последней правки (доказанное сторожевой)
PASSWORD_MIN:  10          # символов
domain/disabled: {names: <текст JCS массива имён>}  # имена выключенных по возрастанию в байтах UTF-8, без повторов; нет —
               # "[]"; массив, не строка через «,»: имя может нести запятую (решение «Архитектора» по R41-11); писатель —
               # процесс domain при каждой правке disabled; секретов нет (ADR-0051)
delete:        удалить строку человека и снять его строки во всех domain/grants/* (Н1.3) — одной правкой на строку грантов;
               под меткой удаления ниже (Н3 «дверь людей» шаг 9)
domain/deleting/<имя>: {}    # метка удаления человека у держателя; писатель — процесс domain под стражем domain/signer-turn;
               # стоит с начала DELETE до снятия всех строк грантов с subject = <имя>; пока стоит — имя занято:
               # POST /domain/users — 409 exists, новая строка гранта с этим subject — 409 being deleted; сверка при
               # старте и каждым проходом урока 1 снимает по ней строки грантов и удаляет метку (журнал cammeta-go, М11-09 № 1; решение «Архитектора»)
               # метка — любая строка под domain/deleting/, что бы ни лежало в items; <имя> не по грамматике Н1.1 —
               # сверка удаляет метку с журналом domain.deleting.dropped {key, reason: "not a name"}, строк грантов не
               # ищет (subject таким не бывает); проход из-за неё не стоит (добавлено сверкой М11, P1)
unreadable:    строка человека, которая не читается (не по форме Н1.1 или name ≠ <имя> ключа), — пропускается и считается
               (диагностика процесса), остальные служат; domain/disabled она не снимает: имя её ключа остаётся там, если
               было; DELETE /domain/users/<имя> удаляет и её — снятие строк грантов и метка как у читаемой (добавлено
               сверкой М11, P2: иначе испорченная строка вернула бы выключенному старые токены)
```

### Н1.2 Вход, токен человека, отзыв

```yaml
door:          POST /api/login {user, password} у процесса domain; тело ≤ LOGIN_BODY (больше — 413 {error: "too large",
               detail}); оба поля — строки (иначе 400 {error: "bad body", detail}); дверь cookie не ставит и не читает
via:           страница ходит к своей консоли: POST /api/login — открытая строка таблицы пересылки урока 8 и open_routes
               P/06.3 Н1.3, консоль домена передаёт её процессу (урок 3 Н1.8); CORS нет — другой origin страница не зовёт
check:         предел Н1.10 → человек есть, не disabled, пароль сверился (сравнение постоянного времени) → токен;
               сверка PBKDF2 (и у аварийного входа Н1.6) не держит общего замка процесса: прочие двери её не ждут
               (добавлено сверкой М11, P21);
               нет человека или disabled — сверка по фиктивному хешу той же стоимости (600000): ответ неизвестному,
               выключенному и неверному неразличим и по коду, и по телу, и по времени
answer:        200 {token, until, user}; иначе 401 {error: "refused", detail: "wrong user or password"} — отказ в счёт
               предела Н1.10
token:         урок 2 Н1.6: payload {iss: <домен>, sub: <имя>, kind: "person", iat: now, exp: now + TOKEN_LIFETIME, jti},
               ключ токенов держателя (current набора); until = exp
TOKEN_LIFETIME: 900        # с
LOGIN_BODY:    16 KiB
revoke:        POST /domain/revoke {token} — строка таблицы пересылки урока 8; консоль домена передаёт её процессу domain
               (Н1.9 `pass`); токен проверяется функцией token урока 2 (не прошёл — 401 со словом token); jti и exp
               добавляются в domain/revoked (урок 2 Н1.6) — ответ 200 {revoked: <jti>}; отозвать токен может тот, кто
               его держит; страница зовёт дверь при выходе (P/06.3 Н1.3 DELETE /session — снимает cookie)
login_url:     P/06.3 Н1.3 (LOGIN_URL окружения, умолчание /api/login)
deposed:       смещённый держатель токенов не выдаёт — 409 deposed (урок 10 Н1.6)
```

### Н1.3 Гранты

```yaml
domain/grants/<кластер>:  {doc: <текст JCS {lines}>}   # у держателя; <кластер> — имя члена по грамматике урока 3
                                                       # (членом быть не обязан: гранты готовят до приёма) или domain;
                                                       # в пути двери — байт в байт, %-кодирование не декодируется:
                                                       # m%31 — не имя, 400 bad name (добавлено сверкой М11, P13)
  lines:       [line…] по (subject, cap, scope) в байтах UTF-8, затем until по числу, без повторов; until сравнивается
               по значению: 0 и 0.0 — одна строка, повтор (добавлено сверкой М11, P7, P9)
  line:        {subject, cap, scope, until, by}
    subject:   имя человека (Н1.1) или субъект индекса имён (Н1.7)
    cap:       view | edit | admin             # view < edit < admin
    scope:     * | unit:<sub>/<id> | labels:<метка>[,<метка>…]   # метки — азбука меток Platform/common/contracts/labels.md, без повторов;
               # <sub> — имя спеки (P/02.1), <id> — по грамматике идентификатора P/06.1 Н1.3; иначе строка не по форме
               # (у двери — 400 bad line; добавлено сверкой М11, P10)
    until:     0 — без срока; иначе стенные секунды — строка действует, пока now < until; у входа больше трёх знаков
               дроби — округление до тысячных от десятичной записи, половина от нуля (как урок 1 Н1.4 round): строка
               хранится и сравнивается округлённой (решение «Архитектора» по сверке М11, P8)
    by:        имя, доказанное сторожевой при записи; строка, совпавшая по (subject, cap, scope, until) с прежней, при
               записи строки целиком сохраняет свой by, новая — имя записавшего
  writer:      процесс domain — по двери Н2 консоли домена (урок 3 Н1.8; CAS по прочитанной версии) и снятием строк человека
               при удалении
domain/grants/domain: гранты двери домена (консоль домена и процесс domain); ни один агент их не несёт
last_admin:    правка domain/grants/domain или людей, после которой нет строки {cap: admin, scope: *, until: 0} человека,
               который есть и не disabled, — 409 last admin
carry:         ответ держателя агенту (урок 3 Н1.5) несёт в sealed поле grants (форма — договор конвертов домена «Содержимое
               sealed»; разбор ревью стадии A 8–10, № 12) — строка domain/grants/<член>
               без строк, чей subject в domain/disabled (ADR-0051); строки нет — поля нет
member_copy:   агент пишет у своего кластера точный ключ domain/grants {doc, as_of} — doc как пришёл, as_of — момент, когда
               держатель собрал ответ: стенные секунды приёма минус domain_age (урок 4; прямой ответ — 0), назад не уходит;
               doc сменился — записать сразу; тот же doc — освежить as_of не чаще FRESH_EVERY (урок 12 Н1.2 fresh); ответ
               из памяти ретранслятора as_of не двигает; поля нет в открывшемся конверте — строку удалить (урок 3 Н1.6
               sealed). Как domain/outcomes
               урока 6: копия члена — точный ключ, строки держателя — семья domain/grants/<кластер>; агенту —
               !domain/grants/* без !domain/grants (P/02.5 Н1.4)
holder_copy:   у кластера держателя копию domain/grants пишет его агент из ответа своего держателя, как у любого члена:
               одно правило чтения, второго писателя нет (ADR-0032); до первого ответа агенту строки нет — прав нет,
               вход — аварийный (Н1.6), как у члена до первого ответа
GRANT_LIFETIME: 86400      # с — копия члена старше as_of + GRANT_LIFETIME не даёт прав
unreadable:    строка, которая не читается, прав не даёт; строка lines, которая не по форме, — пропускается и считается
               диагностикой, остальные действуют
```

Окно отзыва у члена без связи — два предела, раздельно (решение «Архитектора» по R41-13 прогона 41):
- **уже выданный токен** выключенного человека или отозванный — `TOKEN_LIFETIME + TOKEN_SKEW` = 960 с от выдачи;
- **грант**, снятый у держателя, у члена без связи — `GRANT_LIFETIME` (сутки) от `as_of` копии: человек, которого не
  выключили, входит заново и с новым токеном пользуется прежней копией, пока она не стара.

Числа заявлены заранее (М12A/04 шаг 5).

### Н1.4 Право — функция `may`

изменения; номера шагов прежние; владелец P/08, глава 8.4; исполняют сторожевые P/06.3, 6.7, урок 10 и процесс `domain`;

### Н1.5 Сторожевая с грантами

```yaml
cluster:   P/06.3 Н1.3 identity шаг 3 (Bearer | кука w2c_token): токен — функция token урока 2 по набору и domain/revoked
           этого кластера с expect {kind: person, cluster: null} — договор токена домена «Токен» (решение «Архитектора»
           2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10); отказ — 401 {error: denied, detail:
           "token refused: <слово>"}, форма P/06.3; затем may (Н1.4) с
           grants = doc строки domain/grants (копия этого кластера), as_of — её as_of, disabled — domain/disabled этого
           хранилища (есть только у держателя), cap и unit — need P/06.3 Н1.3; deny — 403 {error: denied, detail:
           "<имя> may not <cap> <sub>/<id> | here"}; stale — detail «the grants this cluster holds are older than a day:
           its agent has not reached the domain»
domain:    консоль домена и процесс domain: токен — с тем же expect {kind: person, cluster: null}; may с
           grants = domain/grants/domain, as_of null; view — GET /domain*, /spec, /mounts и двери урока с GET; admin —
           остальные двери /domain/* (уроки 3, 4, 6, 8, 9); unit = "*" у admin;
           кроме POST /domain/revoke — без личности и гранта: удостоверение — токен в теле (Н1.2 revoke)
body_unit: need, чья единица в теле (P/06.3 Н1.3: /marks, POST /<sub>/requests), решается до чтения тела — unit = "*";
           у сторожевой домена действует эта предпроверка до тела, проверки P/06.3 после тела (rights.unit_of, reach,
           names) сохраняются (добавлено сверкой М11)
session:   GET /session доказанной личности (P/06.3 Н1.3) — grants: [{cap, scope}] — действующие строки этого человека
           (шаг 5 may) у этой консоли, по (cap, scope); у аварийной сессии — [] (её may — allow по glass)
loopback:  перенесено в P/06.3 Н1.8 (поздний слой, вводит урок 8.4; стадия B)
agent:     подпись агента своего кластера (урок 3 Н1.4) — двери единиц, как прежде
```

### Н1.6 Аварийный вход

```yaml
domain/break-glass/<кластер>: {pwhash_secret, set_at}    # у держателя; pwhash_secret — та же форма Н1.1
  writer:      процесс domain по двери PUT /domain/break-glass/<кластер> {password} (admin домена); пароль ≥ GLASS_MIN
GLASS_MIN:     12          # символов
carry:         sealed ответа агенту — поле break_glass (форма — договор конвертов домена «Содержимое sealed»; разбор ревью
               стадии A 8–10, № 12); у члена — domain/break-glass/<член>
               (секрет запечатан его кольцом); поля нет в открывшемся конверте — агент удаляет строку (не открылся —
               не трогает, урок 3 Н1.6 sealed). У кластера держателя строка
               domain/break-glass/<держатель> — его собственная (пишет процесс domain): агент держателя её не пишет и не
               удаляет, ответ себе поля break_glass не несёт
door:          POST /session/break-glass {who, why, password} у консоли кластера (P/06.3 Н1.3) — по порядку:
               1. консоль open — 400 {error: "open", detail: "this console is open: there is nothing to break into"}
               2. тело не {who, why, password} строками, who или why пусты — 400 bad body
               3. предел Н1.10                                         → 429
               4. нет domain/member — 403 {error: denied, detail: "no emergency account: its store names no member"};
                  нет строки domain/break-glass/<этот кластер> — 403 {error: denied, detail: "no emergency account: …"};
                  не открывается — 503 {error: "unavailable", detail: "the emergency account does not open"}
               5. пароль не сверился — 401 {error: denied, detail: "break-glass: wrong password"} (в счёт предела)
               5а. открытых сессий уже GLASS_SESSIONS_MAX — 429 форма RateLimited контракта P/06 (06-console.api.openapi.yaml), detail «too many
                  emergency sessions», Retry-After — секунды до конца самой ранней сессии; отказ в счёт предела Н1.10
                  не идёт (добавлено сверкой М11, P20)
               6. 200 {user: "break-glass(<who>)", until} + кука w2c_glass; сессия — в памяти процесса консоли,
                  GLASS_SESSION, токена нет
GLASS_SESSION: 900         # с
GLASS_SESSIONS_MAX: 256    # открытых аварийных сессий у консоли; истёкшие не считаются
journal:       access.break_glass.opened {who, why} | .refused {who, why, reason} | .limited; каждое действие под сессией
               сильнее view — access.break_glass {who, method, path}
```

### Н1.7 Индекс имён

```yaml
spec:      domain.names.<книга>/: {exclusive_with: domain/users, grant?: view | edit | admin}
           <книга> — книга той же спеки с from (урок 5 Н1.1); иначе, или exclusive_with нет либо другое, или grant
           не из слов, или иной ключ — refused:reference (P/02.1 Н4; случаи m59_names_* корпуса P/02.1)
subject:   значение key вклада этой книги
domain/names/<sub>/<книга>:   у держателя; писатель — процесс domain после сборки книг прохода (урок 5 Н3)
  items:   "" → JCS {missing: [<член>…]}; <key> → JCS {members: [<член>…]} — по возрастанию, из всех читаемых вкладов,
           включая спорные unique и недоставленные; значений и секретов нет
  missing: как missing книги урока 5 Н1.5 — члены, чьих вкладов нет из-за них (silent, never, no_copy, bad_contribution,
           secret_unopened); член unseen — не missing: его вклад в книге есть
known:     индекс есть, читается и его missing пуст
checks:    у дверей людей и грантов (процесс domain), по индексам всех names каталога:
           POST /domain/users с именем — subject индекса                    → 409 name taken
           новая строка гранта (нет в прежней строке) с subject индекса и rank(cap) > rank(grant) → 400 grant too wide;
             subject — человек домена — проверок индекса нет: человек сильнее ключа индекса; прежняя строка «шире»
             не проверяется (добавлено сверкой М11, P5, P6)
           новый человек или новая строка гранта (нет в прежней строке), чей subject не человек домена (нет в
             domain/users), а индекс не known → 503 names unknown, detail — «missing members: <члены>» или «index
             absent or damaged»;
           новая строка гранта, чей subject не человек домена, индексы known, а такого key нет ни в одном индексе →
             400 unknown subject; строки, что были в прежней строке, не проверяются (журнал cammeta-go, М11-09 № 1; решение «Архитектора»); строка гранта человека домена (и root) индекса не ждёт: имена исключают друг друга
             (exclusive_with), человек ключом индекса не бывает
           каталог без книг с domain.names — индексов нет: все known и пусты; новая строка гранта, чей subject не
             человек домена, — 400 unknown subject, не 503 (решение «Архитектора» по cammeta-python М11-09 № 21)
           удаление человека и снятие строк — никогда не ждут
reverse:   элемент книги с names, чей key — имя человека, не доставляется никому: поле вида view.books.<sub>/<книга>.person_names
           [<key>…] по возрастанию (урок 5 Н1.5, добавлено М11/9); в отчёте функции assemble урока 5 его нет — её вход без людей
delivery:  урок 5 Н1.3 grant — у получателя строка гранта с subject = key, rank(cap) ≥ rank(grant), действующая (Н1.4 шаг 5)
no_grant:  names без grant — ни предела ширины строки, ни условия доставки: ключ доставляется по to, как у книги без
           names; reverse действует
```

### Н1.8 Семьи ключей домена

```yaml
spec:      domain.keys: [{id, keys?: [<ключ>…], prefix?: <семья/>}] — id ^[a-z][a-z0-9_-]{0,31}$ без повторов; хотя бы
           одно из keys, prefix; ключи и семья — под domain/<sub>/; display.keys.<id> — слова только для объявленного id
           (иначе refused:reference); случаи m59_keys_* корпуса P/02.1
```

## Н3 Проход

### дверь людей (процесс domain) — по порядку

```
1. тело больше 1 МиБ                                                → 413 too large
2. токен (token урока 2, expect {kind: person, cluster: null}) и may по domain/grants/domain  → 401 / 403 {error: denied}
3. тело не по форме двери                                           → 400 bad body
4. имя не по Н1.1 (POST)                                            → 400 bad name
5. пароль короче PASSWORD_MIN (GLASS_MIN у break-glass)              → 400 bad password
5а. POST: стоит метка domain/deleting/<имя>                          → 409 exists (метка — раньше проверок имён;
    добавлено сверкой М11, P3)
6. проверки имён Н1.7                                               → 409 name taken / 503 names unknown
7. POST: человек есть или стоит метка domain/deleting/<имя> — 409 exists; PUT, DELETE: нет — 404 no such person
8. last_admin (Н1.3)                                                → 409 last admin
9. записать строку (CAS по прочитанной версии); disabled — затем domain/disabled; DELETE: записать метку
   domain/deleting/<имя> → удалить строку человека → снять строки subject = <имя> во всех domain/grants/* (CAS) →
   удалить метку; ответ — после снятия метки (журнал cammeta-go, М11-09 № 1; решение «Архитектора»); конфликт CAS строки
   грантов — перечитать её и повторить не больше трёх раз (как шаг 6 «гранты»); исчерпано — 503 {error: "unavailable",
   detail: "the grants kept changing; the deletion is finished by the next pass"}, метка остаётся, строки грантов
   доводит сверка ниже (разбор ревью стадии A 8–10, № 38)
```

Обрыв шага 9 между строкой человека и `domain/disabled` или строками грантов: вход человеку уже закрыт (строка), а члены
его ещё пускают. Процесс `domain` при старте и каждым проходом урока 1 сверяет: `domain/disabled` — по флагам строк людей;
для каждой метки `domain/deleting/<имя>` — снимает строки грантов с subject = `<имя>`, затем удаляет метку; индексов имён
не ждёт; расхождение живёт не дольше прохода. «Людей, которых нет» по отсутствию строки не ищет: субъект индекса имён тоже
не человек домена (журнал cammeta-go, М11-09 № 1; решение «Архитектора»).

### гранты (процесс domain, PUT /domain/grants/<кластер> через консоль домена) — по порядку

```
1. may по domain/grants/domain, admin                               → 401 / 403
2. кластер не по грамматике члена и не domain                        → 400 bad name
3. lines не по форме Н1.3 (cap, scope, until — число ≥ 0, subject по Н1.1), повтор строки → 400 bad line
3а. новая строка с subject, у которого стоит метка domain/deleting/ → 409 being deleted (метка — раньше проверок имён:
    человек удаляется, индекс о нём не спрашивают; добавлено сверкой М11, P3)
4. проверки имён Н1.7: шире grant — 400; новая строка не человека домена и индекс не known — 503; индекс known, а subject
   не человек и не key — 400 unknown subject
5. кластер = domain и last_admin                                     → 409 last admin
6. записать по CAS: lines по порядку Н1.3, by — доказанное имя; конфликт — перечитать и повторить с шага 4 не больше трёх раз
   (конфликт с DELETE возвращает к шагу 4, и он видит метку удаления)
```

**Гонки.** Человек выключен, а его токен жив: у кластера держателя отказ сразу (`domain/disabled`), у члена — со следующим
ответом агенту (ADR-0051). Отзыв гранта у члена без связи — не позже `GRANT_LIFETIME` от `as_of` копии (Н1.3); выданный токен — `TOKEN_LIFETIME +
`TOKEN_SKEW` от выдачи. Гранты пишет
один процесс `domain` — CAS строки. Одно имя создаётся человеком и вкладом в двух кластерах одновременно — индекс показывает
обоих, доставка элемента не идёт (Н1.7 reverse), распределённой блокировки нет.
