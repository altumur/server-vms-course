# М11/2 — Корень, набор ключей, ключ приёма книг, смена и отзыв без связи: инструкция для реализации

## Задача

Построить доверие домена: функцию принятия набора `domain/keys` (`keys`), проверку токена (`token`), запечатывание и
открытие конверта `x25519:v1`, установку домена и три смены ключей. Своих HTTP-дверей у урока нет.

## Входы и их приоритет

Канон — [нормы](02-root-keys-and-revocation.norms.md): формы строк — Н1, вход и вывод команд — Н5; своего HTTP-контракта
у урока нет. [Приёмка](../../Source/tests/testdata/acceptance/М11_Domain/02/README.md) —
векторы, [лекция](../02-root-keys-and-revocation.md) объясняет причины. При противоречии записать место и контрпример и
передать «Спецификации»; инструкция не вводит новый отказ. Внутренние типы и устройство — выбор реализации.

## Что создать

- Функции Н3 `keys`, `token`, открытие и запечатывание Н1.5 — одни и те же для агента, сторожевой, двери токенов и сборки
  книг (уроки 3, 5, 7, 9).
- Строки `domain/root`, `domain/keys`, `domain/signer`, `domain/book-seal`, `domain/revoked` по Н1.1–Н1.6; писатель —
  процесс `domain`, у члена — агент.
- Команду установки и вызовы смен Н3 (Решает реализация п. 2).
- Команды приёмки `keys`, `token`, `seal`, `seal-round` (Н5).

## Порядок работы

1. JCS (RFC 8785), base64url без `=`, hex — общие помощники; подпись набора — над JCS документа без `kid` и `sig`.
2. `keys` — шаги Н3 по порядку: первое сработавшее правило даёт слово.
3. `token` — шаги Н3 по порядку; часы — стенные часы проверяющего; граница `exp + 60` принимает.
4. Конверт Н1.5: зерно — скаляр X25519 как есть; HKDF с salt `eph ‖ book_seal`; AAD — JCS тройки, `0x00`, JSON Pointer.
5. Установка и смены Н3: файл восстановления первым, строка ключа приёма книг раньше набора.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.1 | Закрепить корень по первому пришедшему набору | Корень закрепляют только установка и приём (урок 3); без `pinned` — `no_pin`. |
| Н1.2 | Переписать набор при равном `rev` | Равный — `holding`, строка не меняется. |
| Н1.2 | Подписать `json.dumps` с пробелами или порядком вставки | Подпись — над JCS; порядок полей текста `doc` свободен. |
| Н1.5 | Вывести ключ X25519 из зерна через HKDF или хэш | Зерно — сам скаляр; библиотека зажимает его при умножении. |
| Н1.5 | base64 со `=` или стандартный алфавит | base64url без `=`; `=` в конверте — `not_an_envelope`. |
| Н1.5 | AAD из одного имени поля или `<JCS>:<поле>` | `JCS([member, source_path, item]) ‖ 0x00 ‖ JSON Pointer` целиком. |
| Н1.6 | Сравнивать `exp` с часами держателя или `>=` на границе | Часы проверяющего; `now > exp + 60` — отказ, равенство — `ok`. |
| Н1.6 | Нечитаемый `domain/revoked` считать пустым | `no_revocations`: проверить нечем; пусто — только когда строки нет. |

## Готово, когда

- Сценарии приёмки 01–11 проходят командами `keys`, `token`, `seal`, `seal-round`.
- Описание реализации называет команды приёмки, команду установки и вызовы смен.
- Нормативный чеклист закрыт; пункты «проверяется чтением» и стенд уроков 3 и 10 названы отдельно.

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного слова: вопрос «Спецификации» с входом и предложением. Закрытое решение
отражается в норме, а не в этой инструкции.
