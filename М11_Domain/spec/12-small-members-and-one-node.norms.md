# М11/12 — Сотни малых членов, кластер из одного, держатель на одном узле: нормы

Канон урока. [Лекция](../12-small-members-and-one-node.md), [инструкция](12-small-members-and-one-node.README.md),
[приёмка](../../Source/tests/testdata/acceptance/М11_Domain/12/README.md). Своей HTTP-двери у урока нет: его ответы —
у дверей уроков 3, 7, 9, 10 и в их контрактах с пометкой «добавлено М11/12».

## Н0 Словарь слов

Нормативные слова — по [общему канону Н0](../../М10_Platform/spec/01-storage.norms.md#н0-словарь-слов).

## Н1 Форма

Общее уроков 1–11 Н1 действует. Член отчитывается сам (урок 3): домен не открывает к нему соединений, молчание — возраст
метки по часам держателя. Новой формы члена урок не вводит. Он называет, во что обходится домен на сотнях малых членов,
ставит потолки и закрепляет один процесс `domain` у держателя. Решение «Архитектора» по вопросам М11/12.

### Н1.1 Кластер из одного

```yaml
form:      коробка М10/11: все процессы на одной коробке; хранилище file:// или в процессе без двери (М10/1-23);
           спека МОЖЕТ быть встроенной (М10/2 Н1.5 — процесс со встроенной спекой сам себе писатель строки и метки)
controller: есть, как у любого кластера: один писатель размещения (М10/4) и шарда снимка (М10/10 Н1.3); без шарда агент
           не отчитывается (урок 3 Н1.2 ready)
member:    для домена — член, как любой: приём, отчёт, ответ держателя, правки (уроки 3–11) без изменений
```

### Н1.2 Горячее и долговечное на коробке

```yaml
hot:       объекты <sub>/heartbeats/* (М10/5 Н1.1) и <sub>/snapshot/* (М10/10 Н1.3) на коробке МОГУТ жить в памяти
           хранилища объектов коробки — хранилище в процессе (М10/1-23) или tmpfs, — а не в памяти каждого писателя:
           читатели на той же коробке (консоль, агент, контроллер) видят их тем же чтением; после перезапуска коробки их
           нет, и это верно — пульс из прежней жизни говорит о прошлом
durable:   строки хранилища, эпоха (М10/3), строки, которые приносит агент, — на носителе, как прежде
home_write: агент пишет дома строку из ответа держателя (урок 3 Н1.6) только когда её значение отличается от
           прочитанного; ответ без изменений не пишет ничего (добавлено М11/12 в урок 3 Н1.6)
fresh:     метки свежести — as_of копии грантов (урок 9 Н1.3) и domain/reached (урок 4 Н1.4) — одно правило: при смене
           содержания пишутся сразу, а с тем же содержанием освежаются не чаще раза в FRESH_EVERY. Значение — момент, когда
           держатель собрал ответ: стенные секунды приёма минус domain_age ответа (урок 4; прямой ответ — 0); назад не
           уходит, поэтому ответ из памяти ретранслятора метку не освежает (решение «Архитектора» по R41-12 прогона 41)
FRESH_EVERY: 60          # с — около 1 440 записей каждой метки в сутки при сроке копии грантов GRANT_LIFETIME сутки
```

### Н1.3 Агент в процессе без mTLS

```yaml
where:     кластер из одного МОЖЕТ держать агента в процессе платформы без комплекта роли domainagent (М10/11 Н1.6)
client:    только к дверям держателя (POST /api/member, GET /api/carry, POST /api/tokens — уроки 3, 7) и ретранслятора
           (урок 4), только https:// с проверкой сервера функцией peer урока 8 по DOMAIN_CA / RELAY_CA / Entry.ca;
           сертификата клиента нет. Узкое исключение из М10/11 Н1.6 «https:// без комплекта — отказ»: другим клиентам
           этого процесса оно не даётся
identity:  личность агента здесь — только подпись X-Agent-Signature (урок 3 Н1.4); повтор тех же байт отсекает sent_at:
           приём того же sent_at с иным телом — 409 same_sent_at, с тем же — same (урок 3 Н3 «принять» шаг 2)
holder:    двери держателя для агентов сертификата клиента не требуют ни у кого: личность — подпись
tokens:    местная дверь токенов (урок 7 Н1.2) в процессе — вызов, а не дверь; роль просящего — роль, с которой его
           компонент запущен в процессе, а не слово запроса
rights:    тот же оценщик М10/6 по роли каждого компонента процесса: один процесс — не одна роль, у каждого ключа один
           писатель (ADR-0032)
```

### Н1.4 Список членов — только отставшему

```yaml
publication.members_rev?:  {term, rev} документа domain/member-list, который член держит (урок 3 Н1.1); нет строки — поля
                           нет; вне дельты: не входит в whole и не порождает поколения (как stale, tls_ca). Пара, а не номер:
                           номер без срока повторяется после переноса (урок 10), как у общего документа урока 11
carry.members:             держатель кладёт members, только когда members_rev публикации нет или ≠ (term, rev) его
                           domain/members;
                           равен — поля нет. Нет поля — «без изменений», не «удалить» (урок 3 Н1.6 и так не удаляет)
carry_without_body:        GET /api/carry (урок 3) публикации не несёт — members идёт всегда
```

Прочие поля ответа малы или только свои: `placement` — назначения этого члена (урок 6 Н1.2), `grants` — строка этого
члена (урок 9), `shared` — указатель всегда, документ — отставшему (урок 11 Н1.4).

### Н1.5 Потолки

```yaml
ENTRY_MAX:     820       # байт JCS Entry — худший случай профилей (решение «Архитектора» по R41-17 прогона 41): by — имя
                         # человека, 64 знака по 4 байта (256); key 64; ca 2 × 64; revoked_keys 4 × 64; how ≤ 43 («held the
                         # domain until term» и 16 цифр); since ≤ 24 знака числа JSON; ключи и разметка JCS. Запись, после
                         # которой Entry больше, не пишется: 409 «the entry of <член> would exceed 820 bytes»
MEMBERS_MAX:   500       # записей в domain/members, держатель в счёте; приём сверх — 409 (Н3 «принять члена»):
                         # 500 × (820 + 68 на имя члена и разметку) + 64 ≈ 444 КБ — под потолком строки 524288 байт (М10/1 Н1)
                         # с запасом 15 %, у держателя (domain/members) и у каждого члена (domain/member-list)
revoked_keys:  не больше 4 последних, старший вытесняется (отчёт его ключом и так 403 «ключа нет в записи или он не тот»,
               урок 3 Н2)
whole:         целое поколение (урок 3 Н1.3 whole') ≤ BODY_LIMIT (16 MiB): больше — 413 {error: "whole too large", detail},
               метка не трогается (Н3 «принять» шаг 4а)
body:          агент шлёт дельту всегда, когда base > 0; целое больше BODY_LIMIT агент не шлёт — причина в domain/agent
               (Н1.6 too_large) и журнал не чаще раза в SAY_EVERY; шлёт снова после изменения
SAY_EVERY:     600       # с — журнал одной причины агента
objects:       вид (урок 1) и история тревог (урок 11) — объекты: потолок объекта М10/8, не строки; книги (урок 5) — строки
               под потолком строки 524288 байт (М10/1 Н1); исход сборки книги больше потолка — долг урока 5 (ХОД)
```

### Н1.6 Строка агента дома и `sign_failures`

```yaml
publication.sign_failures?:  {domain?: n, console?: n} — n ≥ 1: запросы, которые агент с запуска не отправил, потому что
                             не смог их подписать (ключ члена domain/member-key не читается): domain — держателю или
                             ретранслятору, console — правка урока 6 своей консоли; нет ни одного — поля нет; вне дельты
domain/agent:   {sign_failures_domain?, sign_failures_console?, too_large?, at}   # у члена; писатель — агент
  sign_failures_<вид>: десятичное n
  too_large:    байты целого, которое агент не отправил (Н1.5 body); снимается следующим отправленным целым
  at:           стенные секунды агента записи; строка пишется только при изменении прочих полей
count:          domain — один на проход: проход без ключа не подписывает ни отчёт, ни GET /api/carry; console — одна на
                каждую правку урока 6, которую агент не отправил
key_unreadable: ключ члена не читается — агент не останавливается: проход идёт, запросы не шлются, счёт растёт, держатель
                видит члена silent (урок 1); строка дома видна всегда, счёт держателю — только в подписанной публикации
view:           domain/view.reports.<член>.sign_failures — из последней публикации (урок 3 Н1.7; добавлено М11/12)
```

### Н1.7 Один процесс `domain` у держателя

```yaml
turn:       domain/signer-turn — строка очереди процесса domain у кластера держателя; алгоритм — placement_turn
            контроллера М10/4 Н3 (TURN_TERM 45, TURN_RENEW 10, CAS своей версии, чужая неизменная ≥ TURN_TERM — взять);
            holder строки — экземпляр процесса <коробка>:<pid>:<6 hex> (форма экземпляра — М10/5 Н3 «старт()»)
release:    по SIGTERM активный процесс отдаёт очередь — holder "" по CAS своей версии, как контроллер в конце прохода
            (М10/4 Н3 шаг 6); ждущий берёт её следующим TURN_RENEW. Убитый (SIGKILL) очередь не отдаёт — её берут
            по TURN_TERM
guard:      каждая запись процесса domain в строку хранилища держателя — прохода, приёма отчёта, правки через консоль домена
            (урок 3 Н1.8), любого урока — идёт со стражем {key: domain/signer-turn, index: моя версия}; страж отказал —
            процесс перестаёт быть активным. Консоль домена строк держателя не пишет, строка очереди ей не нужна
objects:    у объектов М10/8 стража нет, и он не вводится:
            - объект с указателем-строкой пишется без стража, а действующим его делает указатель — строка под стражем:
              domain/shared-docs/rev-* — domain/shared (урок 11), резервные копии domain/backups/rev-* — domain/keepers/* (урок 10)
            - изменяемый объект без указателя-строки — domain/view (урок 1), метка reported с поколениями под ней (урок 3),
              domain/alarm-history/* (урок 11) — процесс пишет, только если подтвердил очередь (Н3 шаг 2 или 3) не раньше
              TURN_RENEW назад
window:     остаточное окно: смещённый процесс может переписать такой объект в пределах одного TURN_RENEW после потери
            очереди; следующий проход держателя очереди его исправляет (вид — пересчётом, метка — следующим приёмом,
            история — дописыванием)
standby:    процесс без очереди — ждущий: прохода не ведёт, каждая его дверь отвечает
            503 {error: "standby", detail: "the domain process of this cluster is <экземпляр>"} — до чтения тела, затем
            закрывает соединение
url:        url записи domain/holder (урок 10 Н1.1) у держателя из нескольких узлов — адрес, который доходит до любого узла
            кластера, а не одного сервера (добавлено М11/12 в урок 10 Н1.1)
agent:      503 standby — «держатель недоступен» на этот проход: не отказ, не повод искать другой срок (урок 10 follow);
            агент шлёт снова следующим проходом (добавлено М11/12 в урок 3 Н3)
term:       держатель на одном узле — «одна очередь», а не «один сервер»; смена узла внутри кластера — не перенос: срок
            не меняется
rights:     domain/signer-turn пишет только роль domain (её семья domain/*)
```

### Н1.8 Порты и юниты домена

Строки юнитов М10/11 Н1.1 (добавлено М11/12); общее юнитов (`Restart`, раннер, `ProtectSystem`) — оттуда.

```yaml
w2c-domain.service:          роль domain; w2c-run.sh signer; User=w2c; SupplementaryGroups=w2c-store w2c-events w2c-secrets;
                             SECRETS_KEY (credential); SIGNER_HOST/PORT 0.0.0.0:8445 — агенты членов ходят сюда (урок 3)
w2c-domain-console.service:  роль domainconsole; w2c-run.sh domainconsole; кольца нет, w2c-secrets нет;
                             DOMAIN_CONSOLE_HOST/PORT 0.0.0.0:8444 — консоли членов пересылают сюда (урок 8)
w2c-domainagent.service:     роль domainagent; w2c-run.sh domainagent; User=w2c; SupplementaryGroups=w2c-store w2c-events
                             w2c-secrets; SECRETS_KEY (credential) — ключ члена и конверты кольца (М10/7 holders); своего
                             порта нет; дверь ретранслятора — урок 4 (RELAY_PORT 8446)
local_door:  местная дверь агента (урок 7 Н1.2) — выбор реализации; если TCP — порты 8444–8447 не занимать, умолчание 8448
```

### Н1.9 Цена

Норма-описание по константам уроков 1, 3, 10, 11; новых правил в ней нет. Площадка — 300 членов, проход агента
`REPORT_EVERY` 5 с.

| Что | Сколько | Где |
|---|---|---|
| приёмы держателя | 300 / 5 = 60 в секунду: подпись, CAS метки или поколения, ответ | процесс `domain` |
| записи спокойной площадки | поколений нет (меняется только `ts`); метка — 300 / 22,5 ≈ 13 записей объекта в секунду | хранилище объектов держателя |
| изменение члена | поколение: 3 объекта (`reports/<rev>`, `.delta`, `reported`) и 2 удаления | там же |
| ответ держателя | единицы КБ; список членов (~300 Б на член, 90 КБ) — только отставшему (Н1.4) | канал к членам |
| вид | объект `domain/view` раз в `VIEW_EVERY` 3 с | держатель |
| резервная копия урока 10 | раз в `BACKUP_EVERY` 30 с, при изменении, у `BACKUP_HOLDERS` 2 хранителей | держатель, хранители |
| фронт тревог урока 11 | одно чтение строки индекса в секунду | у каждого члена, не у держателя |
| записи дома у члена | только при отличии (Н1.2); метки свежести (`as_of` грантов, `domain/reached`) — раз в `FRESH_EVERY` 60 с, около 1 440 каждой в сутки | хранилище члена |

## Н3 Проход

### очередь процесса domain (при старте и каждые TURN_RENEW)

```
1. прочитать domain/signer-turn; нечитаема → standby, журнал
2. holder — я: переписать по CAS своей версии; конфликт → standby
3. строки нет → CAS "" с holder = я; holder "" (отдана, Н1.7 release) → CAS прочитанной версии с holder = я;
   holder чужой, его версия не менялась ≥ TURN_TERM по моим монотонным часам → CAS прочитанной версии с holder = я;
   успех → активен: проход держателя (урок 1 Н3 и последующие) со стражем Н1.7 guard; иначе → standby
4. holder чужой и свежий → standby
5. SIGTERM у активного → holder "" по CAS своей версии (Н1.7 release), затем выход
```

Активный процесс, у которого страж записи отказал, сразу становится ждущим и не повторяет запись.

### дополнения к проходам урока 3

```
агент, шаг 1:   ключ члена не читается → запросы прохода не подписываются: счёт sign_failures, domain/agent (Н1.6)
агент, шаг 3:   целое больше BODY_LIMIT → не слать, domain/agent too_large; base > 0 — всегда дельта
агент, шаг 4:   публикация несёт members_rev (Н1.4) и sign_failures (Н1.6)
агент, шаг 5:   503 standby → следующий проход, last_rev не меняется; 413 whole too large → domain/agent too_large,
                last_rev = 0 (следующее изменение — целым)
агент, Н1.6:    строка дома пишется только при отличии (Н1.2)
принять, 4а:    JCS(whole') больше BODY_LIMIT → 413 whole too large; ничего не писать
принять члена, 5а: name не член и в domain/members уже MEMBERS_MAX записей → 409 refused «too many members: …»
ответ:          members — по Н1.4
```

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| в списке 500 членов | 409 `refused` «too many members» | администратор | снять ушедших |
| целое поколение больше 16 MiB | 413 `whole too large` | агент: `domain/agent too_large`, журнал | уменьшить член: меньше единиц или спек с `domain.ref` |
| ключ члена не читается | запросы не шлются | член: `domain/agent`; держатель: член `silent` | починить строку ключа (М10/7) |
| процесс `domain` — ждущий | 503 `standby` | агент — следующим проходом; человек — повтор | ждать активного или `TURN_TERM` |
| страж очереди отказал | процесс — ждущий | журнал процесса | — |

## Н5 Приёмка

Каталог `Source/tests/testdata/acceptance/М11_Domain/12/` ([README](../../Source/tests/testdata/acceptance/М11_Domain/12/README.md)):
стенд урока 3. Векторов нет: новых функций урок не вводит.

| № | Сценарий | Нормы |
|---|---|---|
| 01 | спокойный член: `reported.rev` стоит, `received_at` свежеет, индексы `domain/member-list` и `domain/keys` у члена не растут, `domain/agent` нет | Н1.2, Н1.9; урок 3 Н3 «принять» шаг 6 |
| 02 | `members_rev`: ответ без `members`; приём нового члена — копия списка у `m1` с ним; снова без `members` | Н1.4 |
| 03 | ключ члена `m1` испорчен: `domain/agent` со счётом, член `silent`; починен — снова `ok` | Н1.6 |
| 04 | второй процесс `domain` — 503 `standby`; первый остановлен — второй берёт очередь, отчёты принимаются | Н1.7 |
| 05 | `MEMBERS_MAX`: список засеян до 499 записей мимо приёма — 500-й член принят, 501-й — 409 `too many members` (мутационная проверка 2026-10-18) | Н1.5 |
| 06 | строка дома без изменений не переписывается (`domain/member-topology`), `as_of` копии грантов не чаще `FRESH_EVERY` (мутационная проверка 2026-10-18) | Н1.2 |

Чтением: Н1.1, `hot` Н1.2, Н1.3, `ENTRY_MAX` и `whole` Н1.5, Н1.8.

## Решает реализация

1. **какие компоненты живут в процессе кластера из одного** и с какими ролями (Н1.3);
2. **число записей на носитель коробки в сутки** без изменений — назвать в описании (Н1.2);
3. **транспорт местной двери агента** (урок 7) и её порт, если TCP (Н1.8).
