# М11/7 — Токены воркеров через агента: инструкция для реализации

## Задача

Построить путь токена воркера: местная дверь агента с личностью роли, дверь держателя с выдачей по области вида,
ответ в конверте `m1`, проверку у получателя по виду и аудитории.

## Входы и их приоритет

Канон — [нормы](07-worker-tokens.norms.md). [HTTP-контракт](07-worker-tokens.api.openapi.yaml) выражает формы обеих
дверей; приёмка — [P/08.7](../../Platform/08-domain/acceptance/7/README.md) и вектор [`issue`](../../Platform/08-domain/vectors/issue/README.md)
(каталог М11/07 снят переносом урока 8); формат токена и
проверка — урок 2 (`token` с `expect`); [лекция](../07-worker-tokens.md) объясняет причины. При противоречии записать место
и контрпример и передать «Спецификации»; инструкция не вводит новый отказ.

## Что создать

- Загрузчик: форма `domain.tokens` и отказы Н1.1 (случаи `m57_tokens_*` корпуса P/02.1).
- Агент: местная дверь `/tokens/<sub>/<вид>` с личностью роли; запрос держателю; открытие `m1`, проверка `request_id`, `exp`.
- Процесс `domain`: дверь `/api/tokens/…`, выдача, утверждения, подпись ключом токенов и команда `issue` — перенесено в [инструкцию P/08](../../Platform/08-domain/spec/08-domain.README.md) (глава 8.7; стадия B).
- У получателей — проверка `token` урока 2 с `expect` — [P/03.7 Н1.5, Н3](../../Platform/03-worker/spec/03.7-worker.norms.md) (стадия B).

## Порядок работы

1. `issue`, утверждения и подпись, дверь держателя — перенесено в [инструкцию P/08](../../Platform/08-domain/spec/08-domain.README.md) (глава 8.7; стадия B).
2. Местная дверь; конверт `m1` (P/08.3 Н1.5).
3. Проверка у получателя: `wrong_kind`, `wrong_audience` (урок 2 Н3) — P/03.7 Н1.5, Н3 (стадия B).

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.2 | Взять роль из тела запроса | Роль — личность соединения; поле `role` пишет только агент держателю. |
| Н3, Н1.4 | — | Ловушки выдачи — перенесено в [инструкцию P/08](../../Platform/08-domain/spec/08-domain.README.md) (глава 8.7; стадия B). |
| P/03.7 Н1.5 | Получатель не смотрит `aud` | `token` с `expect.cluster` — иначе токен годен любому члену. |

## Готово, когда

- Сценарии 01, 02 — приёмка [P/08.7](../../Platform/08-domain/acceptance/7/README.md), сц. 03 — вектор `issue` (стадия B); случаи `m57_tokens_*` корпуса P/02.1 дают свои вердикты; векторы `domain-token` (бывший сц. 12 приёмки М11/2) — тоже.
- Описание реализации: `issue` и вход раннера в местную дверь агента ролью — перенесено в [инструкцию P/08](../../Platform/08-domain/spec/08-domain.README.md) (глава 8.7; стадия B).

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением.
