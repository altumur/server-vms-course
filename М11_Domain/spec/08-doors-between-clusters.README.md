# М11/8 — Двери между кластерами: инструкция для реализации

## Задача

Сделать консоль кластера дверью кластера к домену: пересылка закрытого списка дверей `/domain/*` в консоль домена через
консоль кластера держателя, `where` другого члена по его имени, один переход. Отпечатки центров членов в записи члена и
проверка сервера другого кластера по ним. Двери страницы держателя.

## Входы и их приоритет

Канон — [нормы](08-doors-between-clusters.norms.md). [HTTP-контракт](08-doors-between-clusters.api.openapi.yaml)
выражает формы дверей урока и отказов пересылки; двери, которые пересылаются, — контракты их уроков (1, 3, 4, 6).
[Приёмка](../../Source/tests/testdata/acceptance/М11_Domain/08/README.md) — стенд урока 3 и векторы `peer`;
[лекция](../08-doors-between-clusters.md) объясняет причины. При противоречии записать место и контрпример и передать
«Спецификации»; инструкция не вводит новый отказ.

## Что создать

- Консоль кластера: таблица пересылки Н1.2, адрес Н1.3 (`view.url`, `CLUSTERS`, запись держателя в списке), одна функция
  пересылки Н1.4 и журнал `domain.forwarded`, `/domain/at/…` Н1.5, пересылка подписанту Н1.9 (тела — урок 10).
- Любая консоль: снятие пришедших `X-User`, `X-Operator`; признание `X-Operator: console` только у роли `console`.
- Процесс `domain`: поле вида `url` из `DOMAIN_CONSOLE_URL`; приём `tls_ca` в `Entry.ca` и `tls_ca_certs` в строку `domain/members/<член>/ca-certs` до неё (Н1.6 `on_accept`); объединение рукопожатия двери роли (Н1.6 `server.role`).
- Агент: `tls_ca` и `tls_ca_certs` из `ca.pem`/`ca.next.pem` каталога `W2C_TLS_DIR` в каждой публикации; `DOMAIN_CA`, `RELAY_CA`,
  `RELAY_MEMBER` при `https://`.
- Консоль домена: `POST /domain/members/<член>/ca`; `door.pass` на домене (Н1.7); страница держателя Н1.8.
- Клиент TLS между кластерами — проверка `peer` (Н3) и команда `peer`.

## Порядок работы

1. `peer` (чистая функция Н3): IP, цепочка, якорь по отпечатку, путь до якоря, сроки, роль, имя.
2. Разбор `CLUSTERS` и адрес Н1.3; таблица Н1.2 и отказ `not a domain route`.
3. Функция пересылки Н1.4: заголовки, тело, ответ как пришёл, пределы, журнал.
4. `/domain/at/…` по порядку Н3 «у члена».
5. `tls_ca` → `Entry.ca`, `tls_ca_certs` → `ca-certs` и дверь администратора; поле вида `url`.
6. Страница держателя и `door.pass` на домене.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.2 | Пересылать всё под `/domain/` | Только пары таблицы; прочее — 404 без звонка держателю. |
| Н1.4 | Обрезать тело по пределу | Больше предела — 413, никогда не обрезать. |
| Н1.4 | Нормализовать `Content-Type` ответа в JSON | Статус, `Content-Type`, `X-Unreachable` и тело — как пришли. |
| Н1.4 | Передать пришедший `X-Operator` или `X-User` | Снимаются всегда; `X-Operator: console` ставит пересылающая, признаёт только роль `console`. |
| Н3 | Нечитаемый список членов — «не член» | 503: «не знаю» — не «нет». |
| Н1.5 | Принять любой хвост после `where/` | Только `where/<id>` и `where/<places.table>/<место>` спеки каталога. |
| Н3 peer | Проверять цепочку до системных корней | Якорь — центр с отпечатком записи; выше якоря не проверять, системные корни не брать. |
| Н1.6 | Чистить `Entry.ca`, когда публикация без `tls_ca` | Не меняется; снимает только администратор. |

## Готово, когда

- Сценарии приёмки 01–06 проходят.
- Описание реализации называет команду `peer`, окружение стенда (`CLUSTERS`, `DOMAIN_CONSOLE_URL`) и перезапуск по `@env`.

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением.
