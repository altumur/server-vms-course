## Н1 Форма

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `<sub>/<spec:domain.books.from>`, `domain/<sub>/<spec:domain.books>`, `domain/<sub>/<spec:domain.books>/<член>`;
- пишет: `domain/view` (cas);
- читает: `<sub>/slots/<имя>`, `domain/book-seal`, `domain/members/<член>/reports/<rev>`.

Строки слота книги, переносимые книги, воркер и пульс на домене — во владении [P/03.7](../../Platform/03-worker/spec/03.7-worker.norms.md) (разбор ревью стадии B 3–5, № 35).

Общее уроков 2 и 3 Н1 действует. Книга — наблюдение, не власть: `from` прав записи не даёт, писателя назначает
размещение ([P/04](../../Platform/04-controller/spec/04-controller.norms.md)), секреты запечатаны, `show` скрытого не раскрывает, широковещания нет (ADR-0074).

### Н1.2 Вклад члена

```yaml
# source_row (entry, shared), writer, claim — P/03.7 Н1.2 (стадия B; сторона воркера)
liveness:     семья: строка <sub>/<строка>/<слот> идёт в отчёт, только пока слот <sub>/slots/<слот> держат — держатель
              непуст, released = false (не true и не taking, P/03.2 Н1.4), now ≤ until по стенным часам члена; агент читает слот, строку, затем слот снова —
              слот сменился между чтениями → строки нет в этом отчёте; одиночная строка — без фильтра (слота у неё нет);
              сегмент <слот> не по грамматике имени слота P/03.2 Н1.4 не делает строку чужой: она — семья, фильтр живости тот же
              (сверка М11, совпало у реализаций)
in_report:    объект публикации (урок 3 Н1.2 member_objects) objects["<sub>/<строка>[/<слот>]"] = {<item>: <объект входа>}
              — объект, не текст (элемент, который не текст JSON-объекта, агент несёт строкой как есть: решает сборка —
              bad_contribution, Н1.3); секрет — конверт x25519:v1 к book_seal набора (урок 2 Н1.5) с AAD [член, ключ строки,
              item] и JSON Pointer секрета в объекте входа; значение кольца член открывает перед этим; не открылось —
              агент несёт значение как есть (конверт кольца, не x25519:v1): решает сборка — secret_unopened (Н1.3)
seal_reuse:   агент помнит последний конверт каждого секрета (ключ строки, item, pointer), запечатанное им значение и kid
              book_seal, к которому он запечатан; то же значение к тому же book_seal — тот же конверт: неизменный вход не
              даёт нового поколения (урок 3 Н1.2 change); book_seal набора сменился — конверт новый, вклад идёт в отчёт
              (решение «Архитектора» по R41-08 прогона 41)
no_seal:      набора с book_seal нет, а во входе есть секрет → эта строка не идёт в отчёт (одна строка журнала на смену
              причины); остальные строки и отчёт идут
reports:      domain.reports: [<семья>/…] — объекты <sub>/<семья><имя> члена идут в отчёт как есть (урок 3 Н1.2); держатель
              хранит их в копии; книга их не читает
```

### Н1.3 Сборка у держателя

```yaml
inputs:       копия каждого члена списка (урок 3 Н3 «прочитать копию»), включая держателя (его подписанный отчёт), и его
              состояние вида (урок 1 Н1.3)
contributes:  член ok или unseen (копия есть); silent, never, копии нет — не вкладывает
missing:      [{member, why}] — по member; один на книгу; правило одной фразой: **чего нет в книге из-за члена — тот в
              missing**
  why:        unseen | silent | never | no_copy | bad_contribution | secret_unopened     # закрытый список слов
              # unseen и вкладывает, и в missing: ответ неполон, пока смена не увидена (урок 1)
              # у члена одна запись missing: unseen со снятым вкладом — why причины снятия (bad_contribution,
              # secret_unopened), не unseen (сверка М11, совпало у реализаций)
bad_contribution: вход не объект или не JSON, нет key или он не непустая строка, to не имя/список имён, повтор key у
              одного члена при unique → весь вклад члена в этой книге снят, член — в missing
secret_unopened: секрет вклада не открылся (урок 2 Н1.5; в том числе конверт кольца, который член не открыл, — not_v1)
              → весь вклад снят, член — в missing; значение не раскрывается
pick:
  unique:     ровно один вклад на key во всём домене; два и больше — key в книге отсутствует (конфликт, диагностика Н1.5)
  all:        все вклады
result:       строка у держателя domain/<sub>/<книга>/<получатель> для каждого члена списка (включая держателя):
  "":         текст JSON {missing}
  <key>:      текст JSON {entries: [{member, item, value}], missing} — только элементы, где получатель в to
    member:   член-вкладчик (из происхождения отчёта, не из входа)
    item:     <слот>/<item> для семьи, <item> для одиночной строки
    value:    объект входа как есть (секреты — открыты и запечатаны кольцом держателя, ниже)
  order:      entries — по (member, item) в байтах UTF-8; ключи элементов — произвольно (строка хранилища)
  at_rest:    секреты value — конверты кольца держателя enc:v2 (договор запечатывания), AAD: ключ строки 0x00 «/<item строки>» +
              JSON Pointer секрета в тексте JSON элемента
  write:      строку переписывать, только если открытое содержимое изменилось; строку бывшего члена — удалить;
              книга в пути двери и в ключе строки — байт в байт, без раскодирования процентов (сверка М11, B6)
recipient:    элемент доставляется каждому члену из to, который есть в списке членов; имя вне списка не получает ничего
              ни в каком виде — оно попадает только в диагностику Н1.5 (undelivered)
grant:        книга с domain.names.<книга>/.grant (урок 9 Н1.7) — ключ доставляется получателю, только если у него есть
              действующая строка гранта с subject = key и рангом не ниже grant (урок 9 Н1.4 шаг 5); без гранта
              получатель видит только "" (missing); ключ — имя человека — не доставляется никому (урок 9 Н1.7 reverse)
cadence:      сборка — в каждом проходе держателя (урок 1 Н3), после чтения копий
```

Договор запечатывания — [`Platform/common/contracts/sealing.md`](../../Platform/common/contracts/sealing.md) (конверт `enc:v2`, путь AAD, грамматика `kid`; дополнение Kimi к разбору ревью стадии A 6–7, SA67-Б4).

### Н1.4 Доставка члену

```yaml
carry:        ответ держателя (урок 3 Н1.5) несёт книги в sealed (конверт m1): {books: {<sub>: {<книга>: {<item>: <текст JSON>}}}}
              — строка domain/<sub>/<книга>/<член> держателя, секреты открыты кольцом держателя перед m1
member_row:   domain/<sub>/<книга> у члена — элементы как получены, секреты — конверты кольца члена (договор запечатывания); писатель —
              агент (P/02.5 Н1.4а domainagent); у кластера держателя копии нет: держатель в sealed себе книг не шлёт и свою
              книгу читает из строки domain/<sub>/<книга>/<себя> (ADR-0074, «собранные книги у держателя»)
mask:         значение секрета книги не попадает ни в дверь (Н2), ни в журнал, ни в вид (P/06.2 Н1.4)
```

### Н1.5 Вид: поле `books`

```yaml
domain/view.books:   {"<sub>/<книга>": {conflicts, dropped, undelivered}}   # каждая собираемая книга каталога
  conflicts:   [<key>…] — ключи unique с двумя вкладами и больше, по возрастанию
  dropped:     {<член>: bad_contribution | secret_unopened} — снятые вклады (без значений и секретов)
  undelivered: {<член-вкладчик>: [<имя вне списка членов>…]} — получатели to, которых нет в списке, по возрастанию
  person_names: [<key>…] — у книги с domain.names: ключи — имена людей, не доставлены (урок 9 Н1.7; добавлено М11/9)
```

## Н2 Двери

HTTP-контракт: [05-books-from-member-rows.api.openapi.yaml](05-books-from-member-rows.api.openapi.yaml).

| Дверь | Кто отвечает | Успех | Отказы |
|---|---|---|---|
| GET `/domain/<sub>/books/<книга>` | консоль кластера (члена и держателя) | 200 — книга **этого** члена: `""` → `{missing}`, каждый ключ → `{entries: [{<поля show>, member, item}], missing}`, entries по (member, item) | 404 `{error: "no such book shown", detail}`: спека не объявляет книгу или книга без `show` («carried and not shown»); 503 — хранилище не ответило; 405 — не GET; 401/403 — урок 9 |

Дверь читает книгу этого члена: кластер держит домен (урок 8 Н1.3 `holds`) — строку `domain/<sub>/<книга>/<CLUSTER>`,
иначе — копию `domain/<sub>/<книга>`. Строки книги у члена нет (домена нет, книга ещё не пришла) — 404 `{error: "no such book shown", detail: "not delivered
yet"}`: пустая книга — это `""` с пустым `missing`, а не отсутствие строки. Поля вне `show` и секреты в ответе не бывают.
Сегмент `<книга>` сравнивается с именем книги спеки байт в байт: `%72olls` — не `rolls`, 404 (добавлено сверкой М11, B6).

## Н3 Проход

### сборка книги (держатель, в проходе урока 1 Н3)

```
1. для каждой собираемой книги каталога: члены списка (урок 3 Н1.1) с их состоянием вида и копией
2. член silent | never | без копии → missing (why — состояние или no_copy), вклада нет; метка есть, а её поколение не
   читается (урок 3 Н3 «прочитать копию») — no_copy
3. член ok | unseen: объекты копии по from книги; unseen → в missing (why: unseen)
4. каждый вход: проверить форму Н1.2 у всех элементов вклада члена; ошибка → bad_contribution: весь вклад члена снят;
   затем секреты — открыть (урок 2 Н1.5, seed — domain/book-seal), не открылся → secret_unopened: весь вклад снят
   (форма раньше секретов: элемент с секретом, который не открылся, и элемент не по форме — bad_contribution; добавлено
   сверкой М11, B2)
5. ключи: unique — один вклад на key, иначе конфликт (ключа нет); all — все
6. для каждого члена списка: элементы, где он в to; гранты урока 9; строка domain/<sub>/<книга>/<член> по Н1.3 result
7. записать изменившиеся строки (секреты — кольцом держателя), удалить строки бывших членов; view.books — Н1.5
```

### доставка (держатель, в ответе агенту урока 3) и запись у члена (агент)

```
держатель: прочитать domain/<sub>/<книга>/<член> каждой книги каталога, открыть секреты кольцом → sealed.books (m1)
агент:     открыть m1 (урок 3 Н1.5); каждую книгу — в domain/<sub>/<книга> по CAS, секреты — кольцом члена; книги, которой
           нет в ответе, у члена не трогать (её отсутствие — не удаление)
```

**Гонки.** Сборка читает копии в разные моменты (урок 1): книга — наблюдение. Захват слота и запись воркера под стражем —
[P/03.2](../../Platform/03-worker/spec/03.2-worker.norms.md) Н3: поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости
агента. Две сборки одной книги не пересекаются: держатель один (урок 10). Обрыв на шаге 7 сборки — часть строк книги нового
прохода, часть прежнего, `view.books` прежний: следующий проход пересобирает из копий и дописывает отличия (запись только
при изменении); доставка до того несёт строку как есть — у члена книга одного из двух проходов, не смесь внутри строки.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| вход не по форме Н1.2, секрет не открылся | весь вклад члена снят; член в `missing`; `view.books.dropped` | читатель книги; оператор — вид | воркер члена — исправить вход |
| конфликт `unique` | ключа нет; `view.books.conflicts` | читатель; оператор | развести писателей (размещение) |
| получатель не член | не получает ничего; `view.books.undelivered` | оператор | принять члена или исправить `to` |
| набора с `book_seal` нет, вход с секретом | строка не идёт в отчёт; журнал агента | оператор | принять члена (урок 3) |
| книга не объявлена или без `show` | 404 `no such book shown` | вызывающий | — |
| строки книги у члена ещё нет | 404 `no such book shown`, `detail` «not delivered yet» | вызывающий | ждать доставки |
| хранилище не ответило | 503 | вызывающий | повторить |
| не `GET` | 405 | вызывающий | — |

## Н5 Приёмка

Каталог `Source/tests/testdata/acceptance/М11_Domain/05/` ([README](../../Source/tests/testdata/acceptance/М11_Domain/05/README.md)):
стенд урока 3 с каталогом `testsub` + `testsub2` и учебным писателем вкладов (ниже); команда `assemble` на входах `inputs/`.

**Учебный писатель вкладов** — обязанность стенда реализации (воркер `testsub2`), как обработчик дозаписи [P/03.6 Н5](../../Platform/03-worker/spec/03.6-worker.norms.md): под
своим слотом для каждого счёта, который ведёт, — элемент `<name>` в `testsub2/notes/<слот>` `{ref: <name>, to: <to>}` и в
`testsub2/rolls/<слот>` `{ref: <name>, to: <to>, note_secret: <note_secret>}` (поле без значения — нет; `note_secret`
счёта воркер открывает кольцом своего кластера и запечатывает заново к строке `rolls` с AAD Н1.2 — конверт единицы
привязан к ключу строки единицы; кольца нет — поля нет), объект
`testsub2/counts/<слот>` `{tallies: <число счетов>}`; пишет строку или объект, только когда изменилось открытое
содержимое, а не каждым проходом (добавлено сверкой М11, B7: иначе версия строки растёт впустую).

```yaml
assemble:   вход {catalog: [<sub>…], book: "<sub>/<книга>", members: [<член>…], book_seal_seed: <hex> | null,
                  copies: {<член>: {state: ok | unseen | silent | never, objects: {<ключ>: <объект>}} | null},
                  grants?: {<член>: {lines: [<строка гранта урока 9 Н1.3>…]}} | null, now?: <стенные секунды>}
            # grants — строки грантов каждого получателя для правила Н1.3 grant (действующая — урок 9 Н1.4 шаг 5 по now);
            # нет или null — правило грантов не применяется; получатель без записи в grants — строк нет (добавлено
            # сверкой М11, B1)
            # now обязателен, когда grants есть (не null): grants без now — вход не по форме, код 2 (доверенный вход
            # вызывающего, словарь М11/01; решение «Архитектора» по cammeta-go М11-05 № 7); шаг 06/17 — @exit 2
            вывод {rows: {<член>: {<item>: <объект>}}, report: {conflicts, dropped, undelivered}}
            # ключи copies — в точности members; иное — код 2
            # rows — строки книги по Н1.3 result до кольца (секреты открыты); copies[член] = null — копии нет
exit:       0 — вычислено; 2 — вход не по форме
```

| № | Сценарий | Нормы |
|---|---|---|
| 01 | `rolls`: счёт на `m1` с `to: [m2]` и `note_secret` — у `m2` в двери книги запись без секрета, у `m1` ключа нет; строка `m2` и держателя — секрет конвертом кольца, значения нет | Н1.2–Н1.4, Н2, урок 7 маска |
| 02 | `notes` (`unique`, имена урока 9): один ref на двух членах — `view.books.conflicts`; без грантов получатель видит только `""` | Н1.3, Н1.5 |
| 03 | молчащий вкладчик: `@cut` — его записей нет, `missing` `{member, why: silent}` | Н1.3 |
| 04 | живость: воркер убит — его строка не идёт в отчёт по сроку слота, записей нет, вкладчик не в `missing` | Н1.2 |
| 05 | получатель вне списка — `view.books.undelivered`, никто не получает | Н1.3, Н1.5 |
| 06 | `assemble`: порядок, `unique`-конфликт, `all`, испорченный вход и секрет (чужой `book_seal`, неоткрытый членом конверт кольца) — весь вклад снят и `missing`, `unseen` вкладывает и в `missing`, `silent`/`never`/`no_copy`, получатель вне списка; форма раньше секретов, `notes` с грантом, без гранта и без правила (сверка М11, B1, B2) | Н1.3 |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команду `assemble`** — шаблон с `{input}`; формы — Н5;
2. **как воркер `testsub2` пишет вклады** (учебный писатель Н5) и где агент хранит память конвертов (`seal_reuse`);
3. **порядок элементов** в строке хранилища — свободен; порядок `entries` и `missing` — норма Н1.3.
