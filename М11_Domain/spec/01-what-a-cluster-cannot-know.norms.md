## Н1 Форма

### Н1.1 Домен, член, держатель

```yaml
domain:      набор кластеров-членов под одним корнем доверия (урок 2); ни один raft не охватывает двух членов:
             у членов нет общей строки, слота, эпохи или объекта
member:      кластер М10 (одно хранилище строк, свой raft, свои процессы), принятый в список членов (урок 3 Н1 `member-list`);
             имя члена — `CLUSTER` его установки (М10/10 Н1.3 `cluster`), 1–64 знака [a-z0-9-], не пустое
holder:      ровно один член, на котором работают службы домена; держатель — роль члена, не вид кластера;
             какой член держатель — решение развёртывания (урок 10), не порядок установки
copy:        копия члена у держателя — то, что держатель принял от члена последним (урок 3 Н1: отчёт поколением и метка
             `reported`); домен читает члена только по его копии, к самому члену не ходит
```

**Чего кластер не знает.** Кластер отвечает о своих единицах и только о них. Три вопроса — уровень домена: где единица,
если этот кластер о ней не слышал («не у меня» ≠ «нигде»); в какой кластер ставить новую единицу (назначение — урок 6);
полон ли ответ. Поиск внутри кластера, размещение на воркер, перенос между воркерами — М10, домен их не повторяет и
воркер не пересекает границу кластера. Эпоха единицы монотонна в своём кластере (М10/3 Н1.5); домену выдающий эпох не нужен.

### Н1.2 Имя единицы в домене

```yaml
ref:         значение поля `domain.ref` строки единицы (сводная таблица М10/2 Н1.2а; у `testsub` и `testsub2` — `name`);
             номер единицы (`id`) принадлежит кластеру и в домене не ищется: id 1 есть в каждом члене
no_ref:      спека без `domain.ref` в каталоге домена не участвует: её единиц нет в виде, дверь `/domain/<sub>/<rows>` — 404
```

### Н1.3 Свежесть члена и единицы

```yaml
LOST_AFTER:  45                                  # с; тот же срок, что у пульса воркера (М10/4 Н1)
member_state:                                    # по монотонным часам держателя, «смена» — смена метки `reported` (урок 3 Н1)
  ok:        метка менялась на глазах держателя в последние LOST_AFTER; первый взгляд — свежая
  silent:    метка есть, но не менялась дольше LOST_AFTER
  never:     член принят, метки нет ни разу
unit_state:                                      # единица из копии члена
  live:      есть в `status[]` пульса воркера (М10/5 Н1.1), пульс менялся на глазах держателя в последние LOST_AFTER
  stale:     есть в пульсе, пульс не менялся дольше LOST_AFTER
  configured: есть только в шарде снимка (М10/10 Н1.3), ни один пульс её не ведёт
  silent:    член `silent`: единицы его последней копии остаются в виде с этим словом, не удаляются
```

Член `silent` или `never` — «не ответил», а не «ничего нет»: ответ, которому он нужен, неполон (Н1.5).

**Окно после старта и передачи держателя.** Монотонные часы держателя начинаются заново при каждом старте его процесса.
После перезапуска того же держателя метки членов остаются в его хранилище: первый взгляд на каждую — свежая смена, член
`ok` ещё LOST_AFTER без новой смены. Метка обновляется не реже LOST_AFTER/2 (урок 3 Н1), поэтому живой член подтверждает
себя до конца окна. После передачи держателя (урок 10) у нового держателя меток нет: поколения отчётов с передачей не едут
(урок 10 Н1), каждый член — `never` до первого отчёта новому держателю, вид неполон. Нового окна «по старой памяти» нет.

### Н1.4 Вид домена

```yaml
domain/view:                     # объект держателя (М10/8 Н1.1); писатель — проход держателя раз в VIEW_EVERY = 3 с
  as_of:     <стенные секунды держателя на конце прохода>
  holder:    <имя держателя>
  complete:  true | false        # true ⟺ каждый член `ok` и `contested` пуст
  members:   [{name, state: ok | silent | never, age}]   # age — секунды с последней смены метки по часам держателя,
                                                         # один знак после точки; у `never` — null; порядок — по name
  units:     {<sub>: [Unit]}     # каждая спека каталога с domain.ref (Н1.2), ключ есть и у пустой
  contested: {<sub>: {<ref>: [<член>…]}}   # ref, который заявляют два члена и больше; его единиц нет в units
  <поля других уроков>:          # trust — урок 2; member_list, knocking — урок 3; topology — урок 4; tables, workers — урок 5;
                                 # pending, outcomes — урок 6; term — урок 10; shared — урок 11; счётчики проходов — урок 3
Unit:        {sub, id, ref, cluster, worker?, server?, phase, age, state, view?}
  id:        id единицы в её кластере (строкой); ref — Н1.2; cluster — член
  worker, server: из пульса (`worker`, поле `server` пульса) или из строки шарда снимка; нет — поля нет
  phase:     `status[].phase` пульса (М10/5 Н1.1); у `configured` — "unobserved"
  age:       секунды: у live/stale — с последней смены пульса, у configured — с последней смены метки; один знак после точки
  view:      поля, названные `domain.view` спеки (М10/2 Н1.2а), из строки шарда; секретных полей нет (М10/7 Н1.4)
order:       units в каждой подсистеме — по (cluster, id) в порядке байтов UTF-8
```

### Н1.5 Полнота ответа

Ответ домена о единицах — сводка по копиям: частичная и устаревшая на ограниченную величину. Он ДОЛЖЕН нести свою
неполноту полем, а не отсутствием: `complete: false`, член `silent`/`never`, `contested`. Короткий список НЕ ДОЛЖЕН
выдаваться за полный. «Не найдено» при полном ответе — факт о домене; при неполном — факт о сети: отказ называет, кого не
было слышно (Н4). Каждое производное от копий (вид, книги урока 5, имена урока 9, тревоги урока 11) — наблюдение, а не
власть: оно не даёт права записи в члене и несёт свой список отсутствующих.

### Н1.6 Теневой отчёт

```yaml
shadow:                            # считает проход держателя вместе с видом, ничего не пишет в члены
  inputs:    назначения domain/placement/<sub>/<ref> {cluster} (урок 6 Н1); копии членов (Н1.3)
  claim:     элемент status[] пульса воркера в копии члена → (sub, ref, член, воркер, epoch, revision, observed_revision);
             ref — по id единицы из шарда снимка этого члена; элемент без ref (нет строки в шарде) — заявки нет
  kinds:
    lagging:     заявка с revision > observed_revision, observed_revision менялась в последние SHADOW_STALL      # норма
    stalled:     заявка с revision > observed_revision, observed_revision не менялась дольше SHADOW_STALL      # отказ
    orphaned:    назначение есть, ни одной действующей заявки этого ref в домене                              # отказ
    unmanaged:   действующая заявка ref без назначения                                                       # измерение
    conflict:    действующие заявки ref у двух членов; или у двух воркеров одного члена с равной эпохой;
                 или у члена, отличного от назначения                                                        # отказ
    stale_epoch: заявка с эпохой ниже наибольшей эпохи этого ref у того же члена; такая заявка не действующая  # отказ
  SHADOW_STALL:  60       # с, по монотонным часам держателя: время без смены observed_revision этой пары (член, воркер, ref)
  silent_member: заявки члена `silent`/`never` не действующие; назначение на такого члена — не orphaned, а неизвестно
                 (`unknown` в findings, в счёт отказов не входит)
  exit:          may_write ⟺ unmanaged == 0 ∧ нет отказов (stalled, orphaned, conflict, stale_epoch) ∧ clean_streak ≥ SHADOW_CLEAN
  SHADOW_CLEAN:  3        # проходов подряд без находок; любая находка или неизвестно обнуляет счёт
  report:        {counts: {lagging, stalled, orphaned, unmanaged, conflict, stale_epoch, unknown},
                  findings: [{kind, sub, ref, cluster?, worker?, detail}], clean_streak, may_write, why}
```

`may_write` — условие, при котором домену будет разрешено размещать единицы самому; в М11 домен сам не размещает
(назначение пишет оператор, урок 6; размещение доменом — долг в `ХОД-Спецификация.md`). Отчёт — измерение модели: каждая
`unmanaged` — единица, которую модель домена не описывает.

## Н2 Двери

HTTP-контракт: [01-what-a-cluster-cannot-know.api.openapi.yaml](01-what-a-cluster-cannot-know.api.openapi.yaml).
Двери — у консоли держателя; консоль члена пересылает их держателю без переписывания (урок 8 Н2 `Forwards`). Разбор
запроса — М10/9 Н2 «Разбор запроса консоли» (М10/1 Н2.1 с отступлениями консоли); своих отступлений нет. Личность и
гранты — урок 9 (`view` на чтение); до него консоль открыта только с петли (М10/9 Н1.3).

| Дверь | Успех | Отказы |
|---|---|---|
| GET `/domain` | 200 — объект `domain/view` (Н1.4) как есть плюс `age` — секунды с `as_of` по стенным часам консоли, один знак после точки | 404 `{error: "no domain here", detail}` — объекта нет или он не читается; 401/403 — урок 9 |
| GET `/domain/<sub>/<rows>[?cluster=<член>]` | 200 — `[Unit]` подсистемы из вида, с `cluster` — только этого члена | 404 `{error: "not in the directory"}` — у спеки нет `domain.ref`; 404 `{error: "no such member"}` — член не в списке; 404 — нет такой спеки или `rows` не её; 404 `{error: "no domain here"}` |
| GET `/domain/shadow` | 200 — теневой отчёт (Н1.6) последнего прохода | 404 `{error: "no domain here"}` |

Команда `view` реализации (Решает реализация п. 1): вход — файл проходов (Н5), выход — JSON `{view, shadow}` последнего
прохода; код 0 — вычислено, 2 — вход не по форме Н5. Это та же функция, что у прохода держателя, без хранилища.

## Н3 Проход

### проход держателя — вид и теневой отчёт (раз в VIEW_EVERY)

```
1. прочитать список членов (урок 3) и метку каждого члена; член без метки — never; смена метки на глазах — сброс возраста
2. для каждого члена не never: копия — отчёт поколения метки (урок 3 Н3 «прочитать копию»); не читается — член silent
3. для каждой спеки каталога с domain.ref: units из пульсов и шардов каждой копии (Н1.4); id уже из пульса — шард его не дублирует
4. ref, который дают два члена и больше → contested, единицы этого ref из units снять
5. complete = все члены ok ∧ contested пуст
6. теневой отчёт по Н1.6: прочитать назначения; заявки; виды; clean_streak и may_write
7. записать domain/view (put объекта); отчёт — в память прохода и в объект domain/shadow тем же проходом
```

**Гонки.** Копии членов читаются в разные моменты: вид — наблюдение, а не снимок. Член может поменять метку между шагами 1
и 2: проход берёт поколение прочитанной метки, следующий проход — новое. Два прохода держателя (держатель один, урок 10)
не пересекаются; после перезапуска держателя первый взгляд на метки — свежие, `clean_streak` — 0. Ошибка записи
`domain/view` не меняет прежний объект; дверь отдаёт прежний вид с его `as_of`.

## Н4 Отказы

| Причина | Исход | Тело | Что делает вызывающий |
|---|---|---|---|
| вид не построен или не читается | 404 | `{error: "no domain here", detail}` | ждать прохода держателя; на члене без держателя — консоль держателя |
| спека без `domain.ref` | 404 | `{error: "not in the directory"}` | единицы этой спеки домен не ищет |
| `?cluster=` не член | 404 | `{error: "no such member"}` | исправить имя |
| ref не найден, ответ неполный (член silent/never) | для дверей правки (урок 6) — 503 | `{error: "refused", detail}`: detail называет молчащих («not 'not anywhere'») | повторить, когда члены будут слышны |
| ref не найден, ответ полный | для дверей правки (урок 6) — 404 | `{error: "refused", detail: "<sub> <ref> is in no member of the domain"}` | — |
| ref в `contested` | для дверей правки (урок 6) — 503 | `{error: "refused", detail}`: называет членов | разобрать отказ размещения: два члена ведут одну единицу |
| вход команды `view` не по форме | код 2 | строка лога | исправить вход |

## Н5 Приёмка

Каталог `Source/tests/testdata/acceptance/М11_Domain/01/` ([README](../../Source/tests/testdata/acceptance/М11_Domain/01/README.md)):
команда `view` реализации на входах `inputs/<случай>.json` — без хранилища, сети и стенда домена. Вход — проходы держателя:
форма входа — `ViewInput`, вывода — `ViewOutput` в [HTTP-контракте](01-what-a-cluster-cannot-know.api.openapi.yaml)
(компоненты; норма урока, не выбор реализации). Вход — проходы держателя по порядку: `at` — монотонные секунды держателя
(не стенные), `members.<член>.mark` — `rev` метки `reported` (урок 3 Н1) или `null`, `objects` — объекты копии по ключам
М10/5 Н1.1 (`<sub>/heartbeats/<воркер>`) и М10/10 Н1.3 (`<sub>/snapshot/<шард>`), `placements` — `{<sub>: {<ref>: <член>}}`.
Смену метки и пульса держатель видит между проходами входа; первый проход — первый взгляд. Вызов команды — дверь `view`
словаря «Стенда» М11/01; сравнение — подмножество полей (словарь «Стенда» М10/01).

| № | Сценарий | Нормы |
|---|---|---|
| 01 | два члена, единица в каждом: вид полный, единицы по (cluster, id), `id` 1 у обоих, поиск по ref | Н1.2, Н1.4 |
| 02 | член молчит дольше LOST_AFTER: `silent`, его единицы `silent`, `complete: false` | Н1.3, Н1.5 |
| 03 | единица только в шарде — `configured`, фаза `unobserved`; пульс старше LOST_AFTER — `stale` | Н1.3, Н1.4 |
| 04 | один ref в двух членах: `contested`, единиц нет в `units`, `complete: false` | Н1.4 |
| 05 | теневой отчёт: unmanaged без назначений, `may_write: false` | Н1.6 |
| 06 | lagging → stalled за SHADOW_STALL без прогресса, снова lagging при прогрессе | Н1.6 |
| 07 | orphaned, conflict (член не тот), stale_epoch (две заявки одного ref) | Н1.6 |
| 08 | три чистых прохода подряд — `may_write: true`; находка обнуляет `clean_streak` | Н1.6 |

Команда `view` — не единственное доказательство: урок 3 Н5 повторяет сценарии 01–04 и 05 на стенде нескольких кластеров —
настоящие отчёты агентов в `domain/members/<член>/reports/<rev>` и дверь `GET /domain` держателя. Пересылка консолью члена —
урок 8; гранты — урок 9.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команду `view`** для приёмки — шаблон с `{input}`; её вызов и вывод — дверь `view` словаря «Стенда» М11/01, формы — Н5;
2. **как проход держателя хранит память теневого отчёта** (время последней смены `observed_revision` по паре, `clean_streak`) между проходами; после перезапуска она пуста;
3. **порядок полей JSON** вида — свободен; порядок элементов массивов — Н1.4.
