# М11/3 — Агент и отчёты поколениями: инструкция для реализации

## Задача

Построить агента члена, приём его отчётов держателем поколениями, ответ держателя и двусторонний приём члена: `join`
на члене и `POST /domain/members` у консоли домена.

## Входы и их приоритет

Канон — [нормы](03-agent-and-reports.norms.md). [HTTP-контракт](03-agent-and-reports.api.openapi.yaml) выражает формы
дверей, тела, метки и ответа; [приёмка](../../Source/tests/testdata/acceptance/М11_Domain/03/README.md) — стенд
нескольких кластеров и векторы; [лекция](../03-agent-and-reports.md) объясняет причины. При противоречии записать место и
контрпример и передать «Спецификации»; инструкция не вводит новый отказ. Внутренние типы и устройство — выбор реализации.

## Что создать

- Агент (роль `domainagent`): ключ члена, проход Н3, публикация Н1.2 целым или дельтой, подпись Н1.4, применение ответа Н1.6.
- У процесса `domain`: двери `POST /api/member/<член>`, `GET /api/carry/<член>`; функция «принять» Н3 с мьютексом на
  члена; стук `knock`; держатель в списке; поля вида `member_list`, `knocking`, `reports`.
- У консоли домена: `GET`/`POST /domain/members`, `DELETE /domain/members/<член>`.
- Команду `join` на члене и команды приёмки `agent-sig`, `seal-member`, `seal-member-round`, `accept`.

## Порядок работы

1. Подпись агента Н1.4 и её проверка (`agent-sig`): окно в обе стороны, путь без query.
2. Конверт `m1` Н1.5 (`seal-member`): бирациональное отображение ключа, SHA-512 зерна, HKDF, AAD.
3. «Принять» Н3 (`accept`): порядок шагов, 409 трёх видов, `heard` и MARK_REFRESH, порядок записей объекта, delta и метки.
4. Агент Н3: ready, целое после старта и после `rebase`, дельта без `ts`, `every` из ответа.
5. Приём члена Н3 и `join` Н1.1; держатель в списке.
6. Стенд: сценарии 01–09.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.1 | Закрепить корень по первому набору из ответа | Корень закрепляет только `join`; без него `keys` → `no_pin`. |
| Н1.2 | Считать изменённым пульс, у которого сменился только `ts` | Сравнение JCS без `ts`; только `ts` — не изменение. |
| Н1.3 | Записать метку раньше объекта поколения | Порядок: объект, затем `.delta`, затем метка. |
| Н1.4 | Подписать путь с query или окно только в прошлое | Путь без query; `|now − мс| ≤ окно`. |
| Н1.5 | Отдельный ключ X25519 или форма `m1.<hex>.<b64>` | Один ключ члена; текст `m1:<eph>:<nonce>:<ct>` base64url. |
| Н3 | Отказать отчёту с `sent_at` ниже метки | На той же дороге принимается сразу. |
| Н3 | Слать новое поколение по таймеру | Только при изменении; потеря памяти держателя — через 409 `rebase`. |

## Готово, когда

- Сценарии приёмки 01–13 проходят.
- Описание реализации называет команды приёмки, `join`, переменные агента и `W2C_WALL_OFFSET`.
- Нормативный чеклист закрыт; пункты «проверяется чтением» названы отдельно.

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением. Закрытое
решение отражается в норме, а не в этой инструкции.
