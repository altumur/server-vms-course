# М11/3 — Агент и отчёты поколениями: нормы

Канон урока. [Лекция](../03-agent-and-reports.md), [HTTP-контракт](03-agent-and-reports.api.openapi.yaml),
[инструкция](03-agent-and-reports.README.md), [приёмка](../../Source/tests/testdata/acceptance/М11_Domain/03/README.md).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../НОРМАТИВНЫЕ-СЛОВА.md). Порядок массивов вывода — урок 1 Н0 (общее М11).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](../../М10_Platform/spec/01-storage.norms.md#время-в-строке): `domain/members` — `Entry.since`; стук `knock` — `last`; метка приёма — `received_at` (`sent_at` — как пришёл в публикации, Н1.2).

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `domain/member-key`, `domain/members`, `domain/member-list`, `domain/member`, `domain/members/<член>/reports/<rev>`, `domain/members/<член>/reports/<rev>.delta`, `domain/members/<член>/reported`;
- пишет: `domain/keys` (cas), `domain/revoked` (cas), `domain/view` (put);
- читает: `domain/root`, `<sub>/heartbeats/<имя>`, `<sub>/snapshot/<воркер>`.

Общее урока 2 Н1 действует: hex строчный, base64url без `=`, JCS — RFC 8785, формы JSON закрыты, повтор ключа — форма не
та, порядок ключей объекта ничего не значит. «Стенные секунды» — часы процесса, который проверяет или пишет; «монотонные» —
его монотонные часы (урок 1 Н1.3).

### Н1.1 Член, ключ члена, приём

```yaml
agent:          процесс роли domainagent (М10/6), один на кластер-член, включая держателя; несёт отчёты члена держателю
                и ответ держателя домой; ключей домена не держит (урок 2 Н1.3)
domain/member-key: {seed_secret, pub}        # у члена; секрет — конверт кольца М10/7; читатели — domainagent и domain (М10/7 Н1.3)
  seed_secret:  hex 32 случайных байт — зерно Ed25519 ключа члена (RFC 8032)
  pub:          hex открытого ключа; ключ члена — один: им агент подписывает (Н1.4) и к нему держатель запечатывает (Н1.5);
                точка кривой Ed25519 не малого порядка ([8]A ≠ нейтраль, RFC 8032 §5.1.3): иной ключ подписи не даёт —
                agent-sig bad_signature, стук 401, приём 409 (добавлено сверкой М11, M1)
  readers:      domainagent — все подписи члена; domain — только подпись просьбы GET /api/backup при переносе (урок 10
                Н1.8 шаг 5, Н3 ask-sig); отчётов агента и иных подписей члена процесс domain не делает; писатель — агент
  born:         агент при первом старте, создание-однажды; при старте агент пишет в журнал строку
                «member key <отпечаток>» (отпечаток — урок 2 Н1.1)
join:           команда оператора на члене: имя домена и открытый ключ корня (их печатает установка урока 2 вместе с
                отпечатком корня, оператор сверяет отпечаток глазами) → domain/root {pub, domain} создание-однажды (урок 2 Н1.1)
  same:         уже закреплён тот же {pub, domain} — успех, ничего не меняется
  another:      закреплён другой — отказ, ничего не меняется; смена домена у члена — не этот урок (долг в ХОД)
domain/members: {doc: <текст JSON>}           # у держателя; писатель — процесс domain (Н1.8), CAS
  doc:          {rev, term, members: {<член>: Entry}}
  rev:          целое ≥ 1, +1 на каждую запись
  term:         срок держателя, записавшего строку (урок 10 Н1.1; установка — 1); пара (term, rev) называет список
                однозначно и после переноса (урок 12 Н1.4)
  Entry:        {how, since, by?, key?, revoked_keys?, ca?}   # ca — урок 8 Н1.6; how держателя — урок 10
    how:        "admitted" | "holder" | "held the domain until term <N>" — откуда член в списке (урок 10 Н1.2 — два
                последних); имя человека — только в by, не дублируется
    since:      стенные секунды держателя записи
    by:         человек, принявший члена (урок 9; до него — operator, М10/9 Н1.3); только у admitted
    key:        hex ключа члена, принятого по отпечатку; у holder — ключ из первого отчёта его агента (урок 10)
    revoked_keys: [<hex>…] — прежние ключи этого имени, отозванные (урок 2 Н3 «смена после кражи»); не больше 4 последних,
                  Entry ≤ ENTRY_MAX 820 байт JCS (урок 12 Н1.5; добавлено М11/12)
domain/member-list: {doc}                    # у члена: строка domain/members из ответа держателя как есть (Н1.5); писатель — агент
domain/member:  {cluster, pub}               # имя своего члена и hex его открытого ключа, несекретно: по pub консоль
                                             # кластера проверяет X-Agent-Signature своего агента (Н1.4), процесс domain —
                                             # по Entry.key; агент пишет создание-однажды, когда функция keys урока 2
                                             # приняла набор (took или holding), если строки нет — и у кластера держателя
knock:          {name, last, times, key, fingerprint, pinned, keys_rev}    # стучащийся: отчёт отвергнут 404 «не член»,
                                             # но подпись верна ключом key, который отчёт сам предъявил (Н1.2 key)
  last:         стенные секунды держателя последнего стука; times — число стуков этим ключом с первого, видимого этим
                процессом (новый ключ — снова с 1)
  pinned:       this | another | none — pinned тела против отпечатка domain/root держателя: равен — this, иной — another, нет — none
  forget:       стук принятого забывается проходом вида; ушедший (DELETE) стучится снова
  keys_rev:     rev набора, который член держит, или null
  limit:        не больше 64 стучащихся, в памяти процесса domain; старший по last вытесняется
```

**Приём — двусторонний.** На члене оператор закрепляет корень (`join`); на держателе — вносит ключ члена
(`POST /domain/members {name, fingerprint}`, Н2), сверив отпечаток с тем, что агент члена напечатал при старте. Порядок
сторон любой. Агент отчитывается и без закрепления — так держатель видит стучащегося, — но набор без закреплённого корня
не берёт (урок 2 Н3 `keys` → `no_pin`). Отпечаток ключа члена и корня — урок 2 Н1.1.

### Н1.2 Публикация: тело отчёта на проводе

```yaml
publication:    тело POST /api/member/<член> (Н2) — JSON-объект, закрытый набор:
  sent_at:      конечное число — стенные секунды агента в момент отправки
  objects:      {<ключ объекта>: <JSON-значение объекта>} — что изменилось против base (целое при base = 0)
  base?:        целое ≥ 0 — rev поколения у держателя, против которого изменения; нет или 0 — тело целое
  deleted?:     [<ключ объекта>…] — ключи, которых больше нет против base; только при base > 0
  key:          hex ключа члена — тот, что в domain/member-key
  keys_rev?:    rev набора domain/keys, который член держит (нет — набора нет)
  stale?:       [<ключ пульса>…] — пульсы <sub>/heartbeats/<воркер> копии, которые не менялись дольше LOST_AFTER (45 с)
                по монотонным часам агента; по возрастанию; нет — пусто. Вне дельты: не входит в whole и не порождает
                поколения; живость воркера — факт кластера (М10/4), домен наблюдает его (решение «Архитектора» по М11-03 № 5)
  pinned?:      отпечаток domain/root члена (нет — не закреплён)
  outcomes?:    {<id>: <исход>} — исходы правок домена, урок 6 Н1.5 (ключ ≠ id внутри исхода — исход не засчитывается, урок 6
                Н1.6 settle; сверка М11);   tls_ca?, tls_ca_certs? — урок 8 Н1.6;   sign_failures? — урок 12 Н1.6;
                members_rev? — урок 12 Н1.4 ({term, rev} списка, который член держит; вне дельты)
out_of_delta:   поле вне дельты (stale, tls_ca, tls_ca_certs, sign_failures, members_rev и поля поздних уроков) не по форме
                своего урока — поле не взято, журнал держателя, отчёт принимается, как tls_ca урока 8 Н1.6; stale — ключи
                без повторов, повтор — поле не взято (решение «Архитектора» по сверке М11, A3–A6, A9)
member_objects:                               # что агент несёт и что держатель хранит; прочее держатель отбрасывает молча
  <sub>/heartbeats/<воркер>:  пульс М10/5 Н1.1 каждой спеки каталога с domain.ref
  <sub>/snapshot/<шард>:      шард снимка М10/10 Н1.3 каждой такой спеки
  прочие семьи:               называют уроки 4 (domain/reaches), 5 (domain.reports, строки вкладов), 11 (witness, общие настройки, тревоги),
                              10 (domain/backup-taken — объект {term, rev, sha256}, term и rev целые, урок 10 Н1.5; сверка М11, X1)
ready:          агент не шлёт публикацию, пока у него нет ни одного шарда снимка каждой спеки каталога с domain.ref:
                такая публикация сказала бы «единиц нет» — полный ответ, которому домен поверил бы
change:         объект изменился — его JCS отличается от подтверждённой базы, без поля ts пульса (М10/5 Н1.1) и шарда
                снимка (М10/10 Н1.3); только ts — не изменение. Подтверждённая база — копия состояния, которое агент
                отправил запросом, принятым держателем последним (ответ 200, поколение carry.rev); агент держит её у себя.
                Запрос или ответ потерян — база прежняя: следующий проход шлёт дельту против той же базы с новым sent_at
                (решение «Архитектора» по R41-04 прогона 41)
fresh:          агент помнит по каждому пульсу, когда на его монотонных часах менялся объект целиком (с ts); пульс не
                менялся дольше LOST_AFTER — в stale
```

### Н1.3 Поколение и метка

```yaml
generation:     domain/members/<член>/reports/<rev>   # объект держателя (М10/8 Н1.1): целое поколение, JCS
  whole:        {sent_at, objects, key, keys_rev?, pinned?, outcomes?}   # objects — все объекты члена после применения
                изменения; outcomes — урок 6 Н1.5: смена исходов — новое поколение, агент шлёт поле в каждой
                публикации, пока строка domain/outcomes не пуста; нет поля — исходов нет
delta:          domain/members/<член>/reports/<rev>.delta     # байты тела публикации как получены — то, что подписал агент
reported:       domain/members/<член>/reported               # объект-метка; единственная граница принятого
                # две части (решение «Архитектора» по R41-05 прогона 41): поля поколения пишет только generation (Н3
                # шаг 7); поля последнего принятого запроса — каждый приём с записью метки (шаги 6, 7)
  # поля поколения
  rev:          целое ≥ 1 — номер поколения; выдаёт держатель: +1 на принятое изменение
  sha256:       hex sha256 байтов generation
  base:         rev, против которого пришло изменение; 0 — пришло целое
  delta_sha256: hex sha256 байтов delta (при base 0 — тела целого, как пришло)
  signature?:   заголовок X-Agent-Signature прямого отчёта, создавшего поколение, как пришёл (Н1.4); через ретранслятор
                поля нет (урок 4 Н1.3); via — поле последнего запроса, поэтому метка без signature и без via законна:
                поколение пришло через ретранслятор, затем прямой heard (решение «Архитектора» по сверке М11, A14)
  key, keys_rev?, pinned?: из публикации — по ним консоль домена принимает члена и показывает закрепление
  # поля последнего принятого запроса
  sent_at:      sent_at публикации; received_at — стенные секунды держателя приёма
  request_sha256: hex sha256 байтов тела этого запроса, как пришло; повтор узнаётся по (sent_at, request_sha256)
  via?:         ретранслятор — урок 4
  stale:        из публикации при каждом приёме, включая «слышал» (Н3 шаг 6); нет в публикации — []
  sign_failures?: из публикации при каждом приёме с записью метки, как stale; поколения не создаёт и метку само не
                освежает; нет в публикации — поля нет (урок 12 Н1.6; решение «Архитектора» по сверке М11, A7, W1)
keep:           два последних поколения и их delta; старше и выше метки — убираются следующим приёмом
REPORT_EVERY:   5           # с — проход агента; ответ держателя может назначить every (Н1.5), 1 … 3600
MARK_REFRESH:   22.5        # с = LOST_AFTER/2 (урок 1 Н1.3) по монотонным часам держателя
BODY_LIMIT:     16 MiB      # больше — 413, тело не читается дальше
```

Метка — граница принятого: объект с номером не выше `reported.rev` неизменяем; объект выше — ничей: не читается, не
переносится, не держит номер, следующий приём пишет поверх. Читатели (вид урока 1, сборщик книг урока 5, резервная копия урока 10)
берут `reported.rev` и читают только объект этого поколения; метка без объекта или объект не с её `sha256` — член
`silent` (урок 1 Н3 шаг 2), никогда не смесь.

### Н1.4 Подпись агента

```yaml
header:         X-Agent-Signature: <мс>.<sig>
  мс:           стенные миллисекунды Unix агента, десятичное целое без знака и ведущих нулей (0 — сам «0"), ≤ 16 знаков
  sig:          base64url 64 байт подписи Ed25519 ключом члена над UTF-8:
                <METHOD> "\n" <path> "\n" <мс> "\n" <hex sha256 байтов тела>     # тело GET — пустое: sha256 пустой строки
  path:         путь запроса без query, байт в байт как в строке запроса
window:         |now − мс/1000| ≤ окно, в обе стороны; now — стенные секунды проверяющего
  MEMBER_WINDOW: 300        # с — двери держателя (Н2) и ретранслятора (урок 4)
  UNIT_WINDOW:   60         # с — двери единиц консоли члена (М10/9 Н1.3 identity 2: агент правит единицы своего кластера, урок 6)
replay:         кэша повторов нет: те же байты в окне принимаются снова — норма называет это пределом; дверь отчёта
                идемпотентна по (sent_at, delta_sha256) (Н3), двери единиц — POST по Idempotency-Key, PUT и DELETE — по If-Match (М10/3: Idempotency-Key у PUT не читается)
```

Проверка — функция `agent-sig` (Н3), слова отказа: `no_signature` (заголовка нет или пуст), `not_a_signature` (нет `.`,
`мс` не по форме, `sig` не base64url без `=` или не 64 байта), `out_of_window`, `bad_signature` (и ключ малого порядка
или не точка кривой, Н1.1 pub). Другой формы подписи у
этих дверей нет: тройка `X-W2C-Member/Time/Signature` — у просьб без члена в пути (урок 10).

### Н1.5 Ответ держателя агенту и конверт `m1`

```yaml
carry:          ответ 200 на POST /api/member/<член> и GET /api/carry/<член> — JSON-объект:
  cluster:      имя члена
  rev:          rev метки этого члена после приёма (0 — поколения нет); агент шлёт следующее изменение против него
  every:        с — проход агента, 1 … 3600; вне — агент берёт ближайшую границу; держатель урока 3 даёт REPORT_EVERY (5)
  # в уроке 3 есть: cluster, rev, every, keys, revoked, members — каждая строка как есть, когда она есть у держателя;
  # sealed — нет (секретного члену до уроков 5 и 9 нет)
  keys?:        строка domain/keys держателя {doc} (урок 2 Н1.2)
  revoked?:     строка domain/revoked держателя {jtis} (урок 2 Н1.6)
  members?:     строка domain/members {doc} (Н1.1) — только отставшему: members_rev публикации нет или ≠ (term, rev)
                (урок 12 Н1.4; добавлено М11/12); у GET /api/carry — всегда
  holder?:      строка domain/holder держателя {doc} (урок 10 Н1.1)
  sealed?:      конверт m1 (ниже) с JSON-объектом секретного члену: grants — урок 9 Н1.3, break_glass — урок 9 Н1.6;
                books — урок 5; только когда секретное есть — пустого конверта нет (добавлено сверкой М11, D8)
  <поля уроков>: placement, pending — урок 6 Н1.2, Н1.4; topology — урок 4; shared — урок 11 Н1.4; backup — урок 10 Н1.5
envelope_m1:    m1:<eph>:<nonce>:<ct>             # как x25519:v1 урока 2 Н1.5: четыре части через «:», 2–4 — base64url без «=»
  recipient:    X25519 ключа члена: u = (1 + y)/(1 − y) mod 2^255 − 19 из y открытого Ed25519 (старший бит сброшен),
                little-endian (RFC 7748 §4.1); закрытый — первые 32 байта SHA-512(seed_secret) как скаляр X25519
  eph:          32 байта — одноразовый X25519; nonce — 12 случайных байт; ct — AES-256-GCM с тегом 16, не короче 16
  key:          HKDF-SHA256(ikm = X25519(eph, recipient), salt = eph ‖ recipient, info = "w2c carry to a member", L = 32)
  aad:          UTF-8("m1" + hex открытого ключа члена)
  plain:        UTF-8 текста JSON-объекта
```

Отказ открытия — слово, значение не повторяется: `not_m1` (текст не начинается с `m1:`), `not_an_envelope` (частей не
четыре, часть не base64url без `=`, `eph` не 32 байта, `nonce` не 12, `ct` короче 16, нулевой общий секрет),
`does_not_open` (AEAD не открылся или не UTF-8). Подбор иных форм запрещён.

### Н1.6 Что агент пишет дома

```yaml
from_carry:     keys → domain/keys через функцию keys урока 2 Н3 (отказ — строка прежняя, причина в журнал);
                revoked → domain/revoked как есть; members → domain/member-list как есть; набор принят и строки нет →
                domain/member {cluster}; прочие поля ответа (revoked, members, holder, sealed, поля уроков) применяются
                только после исхода took или holding функции keys над keys этого ответа; иной исход или keys нет — ответ
                не применяется, строки прежние, журнал (добавлено сверкой М11, R2: набор отвергнут — его ответу не верят);
                прочие поля — их уроки; каждая запись — только при отличии от прочитанного (урок 12 Н1.2; добавлено М11/12;
                метки свежести — as_of копии грантов, domain/reached — не чаще FRESH_EVERY, урок 12 Н1.2), CAS по
                прочитанному индексу, секретные поля — конверты кольца М10/7
holder_cluster: у кластера держателя агент не пишет строк, которые там пишет процесс domain (domain/keys, domain/revoked,
                domain/holder, своей domain/break-glass/<кластер>, указателя domain/shared), пока запись domain/holder своего
                хранилища проходит record и называет держателем этот кластер; условие агента — только по записи, domain/signer
                ему не открыт; точка смены — урок 10 Н1.6 switch
sealed:         конверт m1 не открылся (Н1.5: not_m1, not_an_envelope, does_not_open) — его поля «не взяты»: строки члена,
                которые они пишут, не трогаются; удалять строку — только когда поля нет в открывшемся конверте
                (решение «Архитектора» по находке 27 прогона 41)
rights:         роль domainagent (М10/6 Н1.4): пишет domain/* без строк держателя; читает своё по объявлениям
```

### Н1.7 Вид: поля урока 3

```yaml
domain/view.member_list:   {rev, members} — doc строки domain/members, прочитанный проходом (урок 1 Н3 шаг 1)
domain/view.knocking:      [knock…] — по name; поля Н1.1
```

## Н3 Проход

### проход агента (раз в every, умолчание REPORT_EVERY)

```
1. domain/member-key: нет — создать (Н1.1 born); ключ читать каждый проход, не прочитался — не подписывать (урок 12 Н1.6
   key_read; сверка М11, N1); прочитать pinned (domain/root), keys_rev (domain/keys);
   по каждому пульсу копии — момент последней его смены на своих монотонных часах → stale (Н1.2)
2. собрать member_objects (Н1.2); не ready → GET /api/carry/<член> (ключи и список без отчёта) и следующий проход
3. last_rev = 0 (старт процесса, после 409 rebase) → тело целое (base 0);
   иначе base = last_rev, objects — изменённые против подтверждённой базы (Н1.2 change), deleted — исчезнувшие из неё;
   ничего не изменилось → {sent_at, objects: {}, base, key, …}
4. подписать (Н1.4) и отправить POST /api/member/<член> на дверь держателя (DOMAIN_URL)
5. 200 → применить ответ (Н1.6); подтверждённая база := состояние этого запроса; last_rev = carry.rev; every = carry.every
   409 rebase → last_rev = 0 и сразу одна повторная отправка целым; 409 same_sent_at → следующий проход (новый sent_at)
   409 not_ready, 401, 403, 404 → журнал (одна строка на смену причины), следующий проход
   503 standby → держатель недоступен на этот проход: следующий проход, last_rev не меняется; не отказ и не повод искать
   другой срок (урок 12 Н1.7; добавлено М11/12); 413 whole too large → domain/agent too_large, last_rev = 0; то же целое не повторяется, пока объекты не изменятся
   (урок 12 Н1.5 body; сверка М11, N9)
   нет ответа → следующий проход; last_rev и подтверждённая база не меняются
```

Агент сам по времени нового поколения не шлёт: память держателя, потерянную при его сбое, агент узнаёт по 409 `rebase`
и шлёт целое.

### принять(mark, stored, body, via, heard_ago) — держатель, на POST /api/member/<член> после подписи

`via` — дорога: нет — прямо, иначе имя ретранслятора (урок 4 Н1.3); `heard_ago` — монотонные секунды с последнего
приёма этого члена по любой дороге (нет — не слышал); приём — исходы `generation`, `heard` (с записью метки или без) и
`same`; `ignored` и отказы приёмом не считаются.

```
0. приём одного члена — один за раз в процессе domain (мьютекс); подпись, член и ключ уже проверены (Н2)
1. body — не JSON-объект по форме Н1.2                                             → 400 not_a_publication
2. mark есть и body.sent_at = mark.sent_at (одни часы члена на всех дорогах, урок 4 Н1.3): sha256(body) ≠
   mark.request_sha256 → 409 same_sent_at; mark.via = via → same (ничего не писать, метку не освежать); иначе → heard
   (повтор другой дорогой: поколения нет, метка — по правилу освежения шага 6; добавлено М11/4)
2а. mark есть, mark.via ≠ via, body.sent_at < mark.sent_at и heard_ago < ROAD_QUIET (урок 4 Н1.3) → ignored
   (ничего не писать: прежняя дорога жива, а это тело старше по часам члена)
3. base > 0 и (mark нет, или mark.via ≠ via, или base ≠ mark.rev, или stored не читается или не с mark.sha256) → 409 rebase
4. objects' = (base > 0 ? объекты stored : {}) ∪ body.objects − body.deleted; объекты вне member_objects отбросить
4а. JCS(whole') больше BODY_LIMIT → 413 {error: "whole too large", detail}; ничего не писать (урок 12 Н1.5; добавлено М11/12)
5. нет шарда снимка какой-то спеки каталога с domain.ref                           → 409 not_ready
6. mark есть, stored читается и с mark.sha256, и whole' без sent_at = whole stored без sent_at (JCS) → heard
   (stored не читается или не с mark.sha256 — шаг 7: испорченное поколение заменяется новым; добавлено сверкой М11, A1):
   метку этот процесс не писал, или писал не меньше MARK_REFRESH назад (монотонные), или body.stale ≠ mark.stale
   (сравниваются отсортированные списки ключей; сверка М11, A8) →
   переписать метку: поля поколения прежние; поля последнего запроса — sent_at, received_at, request_sha256, via, stale,
   sign_failures — этого запроса; иначе ничего не писать
7. иначе → generation: rev = (mark ? mark.rev : 0) + 1; mark.rev = 2^53 − 1 → 503 {error: "refused", reason: "rev_exhausted",
   detail: "<член>'s generations reached 2^53 − 1: the mark cannot grow"}, ничего не меняется (добавлено сверкой М11, A18); записать reports/<rev> = JCS(whole'), затем reports/<rev>.delta = body,
   затем метку {rev, sha256, base, delta_sha256, signature?, key, keys_rev?, pinned?, sent_at, received_at,
   request_sha256 (= delta_sha256), via?, stale, sign_failures?};
   убрать reports/<rev−2> и его .delta и объекты выше rev
```

`sent_at` ниже `mark.sent_at` на той же дороге принимается: порядок на одной дороге задаёт дорога, часы члена, шагнувшие
назад, берутся сразу; между двумя дорогами — шаг 2а (урок 4). Ответ на шаги 2 (same, heard), 2а, 6, 7 — carry (Н1.5); его `rev` —
`rev` метки, если `mark.via` = дорога ответа, иначе 0 (другая дорога шлёт целое). Сбой между шагами 7: объект выше метки ничей (Н1.3), следующий приём пишет поверх.

### прочитать копию (урок 1 Н3 шаг 2; урок 5, урок 10)

```
прочитать reported; прочитать reports/<reported.rev>; sha256 не тот или объекта нет → копии нет (член silent в виде урока 1);
иначе копия — whole этого поколения; объекты выше метки не читаются
```

### принять члена (процесс domain, POST /domain/members через консоль домена — Н1.8)

```
1. name — держатель → 400; name = domain → 400 «domain is the name of the domain's own grants» (урок 9 Н1.9);
   name уже член: fingerprint = отпечаток его Entry.key → 200 без записи; иначе → 409 «<name> was admitted with another
   key: have it leave first» (член не стучится — «уже член» раньше knocking; решение «Архитектора» по сверке М11, D20);
   name нет в view.knocking → 404 «<name> is not knocking»
2. fingerprint ≠ отпечаток knock.key → 409 «<name> presents another key than the one compared: look again»;
   knock.key малого порядка или не точка кривой (Н1.1 pub) → 409 «<name> presents a key that signs nothing» (сверка М11, M1)
3. knock.pinned = another → 409 «<name> pinned another root than this domain's: join it again»
4. knock.key в revoked_members набора или в revoked_keys записи этого имени → 409 «this key was revoked»
5. (шаг «уже член» — в шаге 1)
5а. name не член, а в domain/members уже MEMBERS_MAX (500) записей → 409 «too many members: the list holds 500»
   (урок 12 Н1.5; добавлено М11/12)
6. записать domain/members по CAS: rev + 1, term — свой, Entry {how: "admitted", since, by, key}; любая Entry документа (урок 12 Н1.5 every_entry; сверка М11, N6) больше
   ENTRY_MAX (урок 12 Н1.5) — 409 «the entry of <name> would exceed 820 bytes»; конфликт CAS →
   перечитать и повторить с шага 4 не больше трёх раз, затем 409 «the list of members kept changing; look again»
```

### держатель в списке (процесс domain, при старте и при приёме отчёта своего агента)

```
1. имени держателя нет в domain/members, или его Entry не how: "holder" (после переноса и передачи: из копии — admitted,
   урок 10 claim) → записать по CAS Entry {how: "holder", since, key?} — key прежней Entry, если есть, иначе без key;
   by нет (форма Entry держателя одна — Н1.1)
2. отчёт агента держателя: Entry держателя без key → проверить подпись ключом, который отчёт предъявил (Н1.2 key),
   и вписать его в key по CAS; дальше — как у любого члена: другой ключ — 403
```

Держатель отчитывается о себе подписанным отчётом, как любой член (ответ на записку модуля, п. 5); отпечаток человек
не сверяет: процесс `domain` и агент — на одном кластере. Взятие срока и прежний держатель — урок 10.

`DELETE /domain/members/<член>`: держатель — 400; не член — 404; иначе убрать запись по CAS, `rev + 1`. Ушедший член
не читается следующим проходом вида (урок 1): его копия и стук забываются в тот же проход.

**Гонки.** Список пишет один процесс `domain` (Н1.8): правки людей, держатель в списке, `claim` и `Entry.ca` (уроки 8, 10)
— по CAS одной строки, конфликт — перечитать. Агент строк держателя не пишет.
Приём отчёта и проход вида — в одном процессе `domain`, вид читает метку и поколение не выше неё.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команды `agent-sig`, `seal-member`, `seal-member-round`, `accept`** — шаблоны с `{input}`; формы — Н5;
2. **команду `join`** (имя, аргументы) и запуск агента: переменные `CLUSTER`, `DOMAIN_URL` (дверь держателя), где
   `domain/member-key`; стенд вызывает их строками словаря; агент не уходит с `DOMAIN_URL` на `url` записи
   `domain/holder`, пока следование урока 10 Н3 не сказало идти (добавлено сверкой М11, Y3);
3. **`W2C_WALL_OFFSET`** — только для стенда: секунды, добавляемые к стенным часам процесса агента; при заданной
   переменной агент пишет громкую строку журнала при старте (как `W2C_DEBUG_PERSON` М10/9);
4. **порядок полей JSON** в теле и ответе — свободен; подпись — над байтами тела как отправлены.
