# М11/9 — Люди, гранты, имена: инструкция для реализации

## Задача

Завести людей у держателя и вход, выдающий токен человека. Нести гранты каждому кластеру и решать право локально
функцией `may`. Дать аварийный вход у кластера и общий предел попыток. Вести индекс имён книг с `domain.names` и
дверь семей ключей.

## Входы и их приоритет

Канон — [нормы](09-people-grants-names.norms.md). [HTTP-контракт](09-people-grants-names.api.openapi.yaml) выражает
формы дверей урока; аварийный вход и `/session` — контракт М10/9, форма токена и проверка — урок 2, пересылка — урок 8.
[Приёмка](../../Source/tests/testdata/acceptance/М11_Domain/09/README.md) — стенд урока 5 и векторы `may`;
[лекция](../09-people-grants-names.md) объясняет причины. При противоречии записать место и контрпример и передать
«Спецификации»; инструкция не вводит новый отказ.

## Что создать

- Процесс `domain`:
  - строки людей и `domain/disabled`;
  - `POST /api/login`, предел попыток;
  - двери людей, аварийных паролей и отзыва — с проверкой токена и грантов домена у себя;
  - команда `domain first-admin`;
  - индекс имён после сборки книг;
  - в ответе агенту — `grants` без выключенных и `break_glass` в `sealed`.
- Консоль домена:
  - `PUT`/`GET /domain/grants` по CAS с проверками имён;
  - передача дверей людей процессу `domain`;
  - сторожевая по `domain/grants/domain`.
- Агент: копия грантов с `as_of`, аварийная строка, снятие при отсутствии поля.
- Консоль кластера:
  - `may` в сторожевой, `/session` с грантами;
  - аварийный вход по порядку Н1.6 и предел Н1.10;
  - `GET /domain/keys`.
- Загрузчик: формы `domain.names` и `domain.keys`, слова `display.keys` (случаи `m59_*` урока 2).
- Сборщик книг: доставка по рангу гранта, `person_names` в виде.
- Команда `may`.

## Порядок работы

1. `may` (чистая функция Н1.4) по векторам.
2. Строка человека, хеш PBKDF2, вход и предел; неразличимость ответа.
3. Строки грантов, последний администратор, копия у члена и её срок.
4. Сторожевая консоли кластера и консоли домена; `/session` с грантами; «петля — operator» только в `open`.
5. Аварийный вход; индекс имён и его проверки; семьи ключей.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.2 | Сразу 401 на неизвестное имя | Сверка по фиктивному хешу той же стоимости: ответ и время неразличимы. |
| Н1.10 | Блокировать имя после неудач | Только адрес и общий потолок: блокировка имени выключала бы администратора. |
| Н1.3 | Читать копию грантов как вечную | Старше `as_of + GRANT_LIFETIME` — прав нет. |
| Н1.4 | Метки `labels:` брать с самой единицы, у которой есть `about` | Метки — с единицы, о которой речь (`about`). |
| Н1.4 | Право без единицы считать любым грантом для `edit` | Без единицы любая строка годится только для `view`; иначе — `*`. |
| Н1.7 | Нечитаемый индекс — «имени нет» | Неизвестность: 503 на создание и расширение, снятие не ждёт. |
| Н1.5 | Оставить «петлю — operator» в состоянии `on` | Только `open`; в `on` — вход и гранты. |

## Готово, когда

- Сценарии приёмки 01–07 проходят, случаи `m59_*` урока 2 дают свои вердикты.
- Стенды уроков 3–8 проходят с личностью `root`, которую раннер ставит по словарю М11/01.
- Описание реализации называет команды `may` и `domain first-admin`.

## При расхождении

Дефект реализации — вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел
нормы — вход, для которого норма не даёт однозначного исхода: вопрос «Спецификации» с входом и предложением.
