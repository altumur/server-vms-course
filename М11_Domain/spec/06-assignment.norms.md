## Н0 Словарь слов

Нормативные слова — по [общему канону Н0](../../М10_Platform/spec/01-storage.norms.md#н0-словарь-слов). Порядок массивов вывода — урок 1 Н0 (общее М11).

## Н1 Форма

Общее уроков 2 и 3 Н1 действует. Назначение пишет только оператор: размещение единиц доменом по достижимости — долг в
`ХОД-Спецификация.md` (ответ на записку М11 п. 3). Домен не пишет строк в члены: правку члена применяет агент члена через
дверь единиц своей консоли (М10/3).

### Н1.1 Назначение у держателя

```yaml
domain/placement/<sub>/<ref>:   строка хранилища держателя; элементы — строки (М10/1):
  cluster:   член-исполнитель; обязателен
  origin:    член-владелец источника; "" — нет
  copies:    текст JCS массива других исполнителей, по возрастанию, без повторов, без cluster; "[]" — нет
  reason:    слова оператора; "" — нет
  at:        стенные секунды процесса domain записи, десятичным текстом
  rev:       значение счётчика domain/placement этой записи, десятичным текстом
domain/placement:   {rev} — счётчик, +1 на каждую запись и удаление назначения
writer:     процесс domain по двери Н2 консоли домена (урок 3 Н1.8); агенту запрещено (М10/6 domainagent)
readers:    процесс domain (вид урока 1, теневой отчёт урока 1 Н1.6, ответ агенту — Н1.2); воркер на держателе — через
            чтение domain/placed/<sub>/ (М10/6 Н3 шаг 3 даёт и domain/placement/<sub>/)
executors:  исполнители ref — cluster и copies; origin — не исполнитель
ref:        не проверяется на существование: назначение может опередить единицу (теневой отчёт — orphaned через
            SHADOW_STALL)
```

### Н1.2 Копия у члена

```yaml
carry.placement:  {rev, records: {"<sub>/<ref>": {cluster, origin, copies: [<член>…], reason, at, rev}}}   # урок 3 Н1.5
  records:   только назначения, которые называют этого члена: он — cluster, origin или в copies (минимум знания;
             цена ответа при сотнях членов — урок 12 Н1.9)
  rev:       счётчик domain/placement держателя
  absent:    поле нет, пока счётчика нет (rev 0)
member:     domain/placed/<sub>/<ref> — элементы записи как у держателя (Н1.1); domain/placed {rev}
            агент: carry.placement.rev > domain/placed.rev → записать изменившиеся копии (CAS по прочитанной версии),
            удалить копии, которых нет в records, затем domain/placed {rev}; не больше — ничего (отката нет)
            держатель копий не пишет: его читатели берут запись (Н1.1 readers)
readers:    исполнитель на члене — по worker.reads `domain/placed/<sub>/` (М10/6); свою запись находит по (ref, cluster = я
            или я в copies)
```

### Н1.3 Правка единицы члена доменом

```yaml
doors:      POST /domain/<sub>/<rows> {cluster, <поля>}        — создать единицу на члене cluster
            PUT /domain/<sub>/<rows>/<ref>[?cluster=<член>]   — править поля
            DELETE /domain/<sub>/<rows>/<ref>[?cluster=<член>] — удалить
            Idempotency-Key обязателен у всех трёх (иначе 400); грант admin у двери домена — урок 9 Н1.5
fields:     только поля domain.edit спеки (М10/2 Н1.2а); платформенные (cluster, worker, server, placement, epoch,
            observed_revision, phase, revision) и поля вне domain.edit — 400; пустое тело PUT — 400; значения — по
            спеке (М10/3 Н3 шаг 4 формы) — 400; у POST — поле domain.ref спеки обязательно
secrets:    *_secret на любой глубине, адрес с учётными данными — 400 «a secret is set in the member's own cluster, never
            through a kept edit» (М10/7 Н1.4, Н4: domain.edit с секретом — отказ загрузки спеки; секрета через домен не передают)
order:      проверки тела по порядку: платформенные поля → секреты → поля вне domain.edit → пустое тело PUT → значения
find:       ref → член и id по виду домена (урок 1 Н1.4); ?cluster= — только этот член
refusals:   ровно урок 1 Н4:
  - ?cluster= не член списка                         → 404 {error: "no such member"}
  - ref в contested                                  → 503 {error: "refused", detail: называет членов}; так и при
    ?cluster= одного из спорящих — вид не держит единиц спорного ref; член вне спора — поиск только у него
  - ref не найден, кто-то не ok (unseen, silent, never) → 503 {error: "refused", detail: называет молчащих}
  - ref не найден, ответ полный                       → 404 {error: "refused", detail: "<sub> <ref> is in no member of the domain"}
  - POST: cluster не член                             → 404 {error: "no such member"}
kept:       найденная единица (в том числе у члена silent — по его последней копии) и POST → правка хранится (Н1.4) и ответ
            202 {kept, cluster, what, note}; домен в члены не пишет
```

### Н1.4 Хранимая правка

```yaml
domain/pending/<член>:   строка держателя; элемент <id> — текст JSON правки
  edit:     {id, seq, what, method, path, body, key, at, base?, asked}
    id:     "e-" + первые 12 знаков hex sha256(UTF-8(член) ‖ 0x00 ‖ UTF-8(Idempotency-Key))
    seq:    номер приёма — значение элемента seq этой строки после +1 при приёме, под тем же CAS; seq задаёт порядок ждущих
            правок члена: по нему назначается base (ниже) и выдаются правки (carry); at — только время для людей и исходов
            (решение «Архитектора» по R41-09 прогона 41)
    what:   имена полей тела по возрастанию через «,», у POST — с полем domain.ref, без cluster (DELETE — "")
    method: POST | PUT | DELETE;  path — путь двери единиц консоли члена: /<sub>/<rows> или /<sub>/<rows>/<id>
            (id — местный id единицы из копии члена); body — объект полей (DELETE — {})
    key:    Idempotency-Key запроса
    asked:  {method, path, body} — запрос двери домена, как его принял процесс: путь Н2 с ref и ?cluster=<член> у PUT и
            DELETE, тело с cluster у POST; по нему правку повторяют у нового держателя (урок 10 Н1.6 apply)
    at:     стенные секунды процесса domain; если по этому id уже записан исход (строка domain/outcomes/<член> держателя,
            Н1.6) — не меньше следующего за его kept_at
            числа (nextafter): новый приём того же ключа отличим от прежнего
    base?:  revision единицы в копии члена у держателя в момент приёма (PUT, DELETE); у POST нет; строки шарда с
            revision этой единицы в копии нет — base нет, правка идёт без If-Match; есть ждущая PUT того же
            path — base = base последней из них по seq + 1 (так применяется её результат, а не прежнее значение); ждущая DELETE того же path —
            новая правка этого path отказывается 409 {error: "unit is being deleted"}
            # ждущая правка не применилась (conflict) — следующие того же path тоже дадут conflict: оператор решает заново
writer:     процесс domain — приём (Н3, дверь консоли домена — урок 3 Н1.8) и снятие исполненной (Н3 «исход»); CAS строки
repeat:     тот же id и те же method, path, body — 202 с прежней записью, at прежний; иное — 422 {error: "this Idempotency-Key
            was used for another edit"}; нечитаемая прежняя запись этого id — 422 (ключ не переиспользуется)
KEPT_LIMIT: 50          # ждущих правок на члена; 51-я — 409 {error: "kept_full", detail: "<член> has 50 edits waiting"}
reply:      202 {kept: <id>, cluster: <член>, what, note: "kept; <член> applies it when it next reports"}
carry:      ответ держателя (урок 3 Н1.5) несёт pending: [<edit>…] этого члена по seq; элемент seq строки — счётчик, не правка
           (правки — элементы e-…; KEPT_LIMIT считает их)
```

### Н1.5 Применение агентом и исход

```yaml
apply:      для каждой правки ответа по порядку: исход с kept_at = at уже записан — не повторять; иначе запрос к двери
            единиц своей консоли: method, path, тело — JCS body, Idempotency-Key — key, X-Agent-Signature (урок 3 Н1.4,
            окно 60 с), If-Match: <base> при base (М10/3 Н3 «править», «удалить»)
outcome:    {id, status, result, error?, at, what, kept_at}
  status:   код ответа консоли
  result:   performed (2xx) | conflict (412: единицу на члене поменяли после приёма — правка не применена, единица не
            перезаписана) | refused (иной 4xx, в том числе 409, кроме «in flight» ниже)
  error:    detail ответа (нет detail — его error) при status ≥ 400, без значений секретов
  at:       стенные секунды агента;  kept_at — at правки
retry:      консоль не ответила, status ≥ 500, 409 «in flight» (М10/3) → исхода нет, повтор следующим проходом
domain/outcomes:  строка члена (агент): элемент <id> — текст JSON исхода; исход снимается, когда держатель перестал
                  называть правку в ответе
publication.outcomes:  поле публикации урока 3 Н1.2 — {<id>: <исход>}: элементы строки domain/outcomes члена, каждый
                  разобран в JSON-объект исхода (не текстом)
holder_self: держатель — член: его правки хранятся в domain/pending/<держатель>; его агент читает их из своего хранилища
             (без ответа) и применяет так же; исходы — в его отчёте
```

### Н1.6 Исходы у держателя и вид

```yaml
domain/outcomes/<член>:  строка держателя; элемент <id> — исход (Н1.5); OUTCOMES_LIMIT 50 — последние по (at, id) убывая
settle:     исход из копии члена принят, если правка с этим id ждёт, kept_at = at правки, what совпал; запись исхода —
            затем снятие правки по CAS, если она не менялась
domain/view.pending:   {<член>: <число ждущих правок>} — каждый член списка, 0 — ждущих нет
domain/view.outcomes:  {<член>: [<исход>…]} — строка domain/outcomes/<член> по (at, id) убывая
```

## Н2 Двери

HTTP-контракт: [06-assignment.api.openapi.yaml](06-assignment.api.openapi.yaml). Двери — консоли домена, правки она передаёт
процессу `domain` (урок 3 Н1.8); консоль члена пересылает их (урок 8 Н1.2). Разбор запроса — М10/1 Н2.1 с отступлениями М10/9 Н2.

| Дверь | Успех | Отказы |
|---|---|---|
| GET `/domain/placement` | 200 `{rev, records: {"<sub>/<ref>": Placement}}` | 401/403 — урок 9 |
| GET `/domain/placement/<sub>/<ref>` | 200 Placement | 404 нет записи; 404 нет спеки или без `domain.ref` |

## Н3 Проход

### принять правку (процесс domain, дверь консоли домена — урок 3 Н1.8)

```
1. Idempotency-Key есть; поля, секреты, значения — Н1.3                         → 400
2. найти (Н1.3 find, refusals)                                                  → 404 / 503
3. id = Н1.4; прочитать domain/pending/<член>: тот же id — repeat (202 / 422)
4. ждущих 50                                                                    → 409 kept_full
   ждёт DELETE того же path                                                       → 409 unit is being deleted
   base: копия члена; ждёт PUT того же path — base последней по seq + 1
5. seq строки + 1; edit {id, seq, what, method, path, body, key, at, base?, asked} → записать правку и seq одним CAS (конфликт — перечитать с шага 3, до 10 раз,
   затем 409 «the pending edits kept changing; ask again»)
6. 202
```

### исход (процесс domain, в проходе урока 1)

```
для каждого члена: исходы его копии (урок 3 Н3 «прочитать копию», поле outcomes публикации) → settle Н1.6:
записать domain/outcomes/<член> (обрезать до 50), затем снять правку из domain/pending/<член> по CAS
```

**Гонки.** Приём и снятие — в одном процессе `domain`, CAS строки `domain/pending/<член>`; снятие одного id — только
неизменённой правки. Локальная правка единицы на члене между приёмом и применением — `If-Match` даёт 412, исход `conflict`: молча не
перезаписывается. Агент, получивший правку дважды (повтор ответа), — `Idempotency-Key` двери единиц (М10/3) и правило
`kept_at`. Назначение и единица — разные строки: удаление назначения единицу не трогает.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| назначение: имя не член | 409 | оператор | принять члена (урок 3) |
| правка: ref не найден при полном ответе | 404 | оператор | — |
| правка: не найден, кто-то молчит; `contested` | 503, detail называет | оператор | ждать или разобрать спор |
| правка: поле вне `domain.edit`, платформенное, секрет, пустое тело | 400 | оператор | исправить тело |
| тот же ключ с иным телом | 422 | оператор | новый ключ |
| 50 ждущих | 409 `kept_full` | оператор | ждать члена |
| ждёт удаление этой единицы | 409 `unit is being deleted` | оператор | ждать исхода удаления |
| единица на члене поменялась после приёма | исход `conflict` (412) | оператор — вид `outcomes` | перечитать и решить заново |
| консоль члена не ответила или 5xx | исхода нет, повтор | — | — |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **порядок полей JSON** записей и ответов — свободен; порядок `records`, `pending`, `outcomes` — норма;
2. **как агент читает правки держателя у себя** (держатель — член, Н1.5 `holder_self`).
