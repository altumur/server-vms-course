# М11/2 — Корень, набор ключей, ключ приёма книг, смена и отзыв без связи: нормы

Канон урока. [Лекция](../02-root-keys-and-revocation.md), [инструкция](02-root-keys-and-revocation.README.md), [приёмка](../../Source/tests/testdata/acceptance/М11_Domain/02/README.md).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../НОРМАТИВНЫЕ-СЛОВА.md). Порядок массивов вывода — урок 1 Н0 (общее М11).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](../../Platform/01-store/spec/01.1-store.norms.md#время-в-строке): `domain/keys` — значения `until`. `exp` в `domain/revoked` — из токена, по Н1.6.

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `domain/keys`, `domain/root`, `domain/signer`, `domain/signer-pending`, `domain/book-seal`, `domain/revoked`, `<файл восстановления домена>`;
- пишет: `domain/view` (cas).

Общее для всех форм урока: hex — строчные `0-9a-f`; base64url — алфавит RFC 4648 §5 без `=`, запись каноническая: длина
≢ 1 (mod 4), лишние биты последнего знака — нули, повторное кодирование байтов даёт тот же текст; иначе — не base64url;
JCS — RFC 8785 (ADR-0072);
«стенные секунды» — секунды Unix по часам того процесса, который проверяет или подписывает. Ключи подписи — Ed25519
(RFC 8032), открытый ключ — 32 байта; ключ приёма книг — X25519 (RFC 7748), 32 байта.

Полнота форм. Каждая форма JSON урока — закрытая: поле вне списка — форма не та (что за этим следует, сказано у формы);
обязательное поле обозначено без `?`, необязательное — с `?`, отсутствие необязательного — его умолчание. Порядок ключей
объекта ничего не значит; порядок массивов — у формы, иначе урок 1 Н0. Повтор ключа в объекте JSON — форма не та. Число — число
JSON (не строка, не `true`/`false`); «целое» — число без дробной части по значению (`2` и `2.0` — одно целое; вывод пишет его без дроби) в пределах ±(2^53−1); «конечное» — не NaN и не
бесконечность. Строки — UTF-8 без нормализации.

### Н1.1 Корень домена

```yaml
root:          пара Ed25519 домена; одна на всю жизнь домена
recovery_file: JSON {domain, root_key, root_pub}       # закрытая половина корня — только здесь; все три обязательны;
                                                      # лишнее поле или иной тип — файл не читается
  domain:      имя домена, 1–64 знака [a-z0-9-]
  root_key:    hex 32 байт — зерно закрытого ключа Ed25519 (RFC 8032 §5.1.5)
  root_pub:    hex 32 байт — открытый ключ; не тот, что выводится из root_key, — файл не читается (отказ, ничего не меняется)
  place:       у оператора вне каталога платформы целиком (PLATFORM_DIR — в нём и кольцо, договор запечатывания) и вне каталогов хранилища,
               объектов и их копий; режим 0600; путь называет вызов операции (вне PLATFORM_DIR — добавлено сверкой М11, I2)
  mode:        режим проверяется при каждом чтении файла (смены Н3, перенос урока 10, любая команда, что берёт из него
               root_pub): шире 0600 — отказ, ничего не меняется (добавлено сверкой М11, I3)
signs:         только набор domain/keys (Н1.2); записи срока и удостоверение держателя подписывают ключи issuing[] набора (урок 10 Н1.1)
limit:         файл восстановления — всё: корень подписывает набор, а ключ резервной копии держателя выводится из зерна корня —
               украденный файл открывает и все резервные копии домена (урок 10 Н1.5); средства, кроме смены корня с новой установкой, нет
needed_for:    установка (Н3), плановая смена ключа токенов, смена ключа приёма книг, смена после кражи (Н3); иначе никогда
not_on:        держатель (domain/signer, его резервная копия урока 10), консоль, агент, воркер — корня не хранят и не читают
fingerprint:   hex(sha256(<32 байта открытого ключа>)[:8]) — 16 знаков; так корень и ключи называют люди и журналы
pin:           domain/root {pub, domain}       # у каждого члена, включая держателя; создание-однажды
  pub:         обязателен; hex открытого корня
  domain:      обязателен; имя домена
  not_a_pin:   строка не по форме (лишний элемент, нет поля, не hex) — закрепления нет: keys → no_pin; закрепление не чинится
               само, член принимается заново (урок 3)
  when:        держатель — при установке (Н3); член — при приёме оператором по отпечатку (урок 3); иначе не пишется
  never:       корень не закрепляется по первому пришедшему набору; закреплённый не заменяется — сменить корень = завести
               домен заново (новые установка и приём каждого члена)
```

X.509 под корнем домена нет: сертификаты TLS ролей выдаёт центр поставки (ADR-0075, P/02.4 Н1.6). Заводская личность
устройства и регистратор — М13; приём члена оператором — урок 3.

### Н1.2 Набор ключей `domain/keys`

Форма строки и документа набора (`row`, `doc`, `writer_forms`) и правило «только вперёд» (`only_forward`) — [договор набора
ключей домена](../../Platform/common/contracts/keys.md) «Набор `domain/keys`» (владелец P/08, глава 8.2; разбор ревью стадии A 8–10, № 13 / решение 2). Здесь —
`rev` писателя:

```yaml
rev:               обычная и плановая смена (ключ токенов, отзыв члена, book_seal) — max(rev набора, который держит
                   подписант, + 1, целые стенные секунды подписанта); rev + 1 больше стенных секунд — смена ждёт, пока
                   часы его не догонят: rev не обгоняет стенные часы подписанта
  emergency:       аварийная смена — после кражи (Н3) и перенос без прежнего держателя (урок 10 Н1.8) — max(наибольший
                   известный rev + 1, целые стенные секунды + 60)
  clocks:          предпосылка: стенные часы держателей домена расходятся не больше чем на 60 с (тот же допуск, что
                   TOKEN_SKEW); при ней аварийный набор старше любого, который выпустил прежний держатель
                   (ADR-0074 доп. 7)
```

Набор — то, чему член верит без связи: ключи токенов держателя, отзывы и ключ приёма книг. Без набора у члена нет
домена (сторожевая [P/06.3](../../Platform/06-console/spec/06.3-console.norms.md) Н1.3, Н1.8).

```yaml
domain/view.trust:   {rev, root, book_seal}   # поле вида урока 1 Н1.4: набор, которому верит держатель;
                                              # root и book_seal — отпечатки Н1.1; какой rev держит каждый член — урок 3
```

### Н1.3 Ключи держателя

```yaml
process:       domain (подписант, ADR-0032) — единственный процесс с ключами домена и единственный писатель строк держателя;
               domainconsole и консоль кластера ключей не держат, подписи не просят и строк держателя не пишут: правку
               консоль домена передаёт процессу domain (урок 3 Н1.8)
domain/signer: {kid, token_key_secret, serial, issuing_key_secret, backup_key_secret, backup_key_rev}   # у держателя; секреты — конверты кольца (договор запечатывания; P/06.2 Н1.2)
  token_key_secret:   hex 32 байт — зерно Ed25519 ключа токенов (current набора)
  issuing_key_secret: hex 32 байт — зерно Ed25519 выпускающего (его serial — в issuing набора; применение — урок 10)
  backup_key_secret:  hex 32 байт — ключ резервной копии (урок 10 Н1.5: HMAC-SHA256 от зерна корня), пишет установка (Н3) и перенос;
  backup_key_rev:     целое ≥ 1, при установке 1
  forgotten:          смещённый держатель заменяет строку на {forgotten: "deposed by term N"} (урок 10 Н1.6)
readers:       domain (общая таблица читателей секретов P/02.5 Н1.3 `platform_readers`)
domain/signer-pending:  {seed_secret} — подготовленный ключ X25519 плановой передачи у цели (урок 10 Н1.7); читатель тот же
  seed_secret:  hex 32 случайных байт — закрытый скаляр X25519, конверт кольца (договор запечатывания; P/06.2 Н1.2) (одно имя с domain/member-key,
                domain/book-seal; добавлено пилотом схем семей данных, Д4)
SIGNER_URL:    адрес двери процесса domain держателя; его знают консоль кластера держателя и запись срока (уроки 8, 10)
```

### Н1.4 Ключ приёма книг

```yaml
domain/book-seal:  {seed_secret}           # у держателя; конверт кольца (договор запечатывания; P/06.2 Н1.2); читатель — только domain; без rev
  seed_secret:     hex 32 случайных байт — закрытый скаляр X25519 как есть (RFC 7748 §5: зажим при умножении)
public:            book_seal набора = X25519(seed_secret, 9) — открытая половина, hex
born:              при установке (Н3) раньше набора rev 1; заменяется только сменой ключа приёма книг и сменой после кражи (Н3)
travels:           с резервной копией держателя и переносом (урок 10); в отчёты, книги и журналы не попадает
```

### Н1.6 Токены домена и `domain/revoked`

Форма токена (`token`: `header`, `payload`, `sig`) и константа `TOKEN_SKEW` — [договор токена домена](../../Platform/common/contracts/domain-token.md) «Токен» (урок — владелец договора; перенесено туда из этого подраздела, чтобы
перенесённые главы P/03.7 и P/06.3 не стояли на нормах М11; разбор ревью стадии B 3–5, В1). Здесь — отзывы и срок прежних
ключей:

Строка `domain/revoked` — форма, писатели, порядок, снятие `prune`, читатели — [договор набора ключей домена](../../Platform/common/contracts/keys.md)
«Отзывы `domain/revoked`» (разбор ревью стадии A 8–10, № 13 / решение 2). Здесь — срок прежних ключей:

```yaml
OLD_KEYS:      3600        # с — until прежнего current при плановой смене ключа токенов (Н3)
```

Кто проверяет токен и где отказывают вид и `aud` — [договор токена домена](../../Platform/common/contracts/domain-token.md) «Токен» (перенесено туда; В1).

### Н1.7 Окно отзыва без связи

Проверяющий решает по своему набору и своей копии `domain/revoked` по своим стенным часам; связи с держателем проверка не
требует. Поэтому отзыв доходит не мгновенно, и норма называет пределы числом:

| Что отозвано | Принимается не дольше | Чьи часы |
|---|---|---|
| токен (`jti` в `domain/revoked`) | `min(exp + TOKEN_SKEW, доставка domain/revoked проверяющему)`; без связи — `exp + 60`, то есть `lifetime + 60` от выдачи; в `testsub*` самый долгий вид — `testsub2` `feed: 600` → 660 с | стенные проверяющего |
| прежний ключ токенов после плановой смены | до `until` своего набора (`OLD_KEYS` = 3600 с от смены) | стенные проверяющего |
| украденный текущий ключ токенов (у current нет `until`) | **до первого принятого проверяющим набора, где этого ключа нет** (смена после кражи, Н3): вор выпускает новые токены, и член без связи их принимает; сроком это окно не ограничено | — |
| ключ члена (`revoked_members`) | держатель отказывает сразу после своего набора (урок 3); член без связи сам себя не отзывает | — |

Доставка у члена — с ответом держателя агенту (урок 3 Н3); у кластера держателя — запись в его же хранилище.

## Н3 Проход

### keys(pinned, held, offered) → took rev | holding rev | refused <слово>

Шаги 1–8 и отказ без изменения строки — [договор набора ключей домена](../../Platform/common/contracts/keys.md) «Функция `keys`» (перенесено туда без
изменения; номера шагов прежние; разбор ревью стадии A 8–10, № 13 / решение 2). Векторы —
[`common/vectors/keys`](../../Platform/common/vectors/keys/README.md).

### token(keys, revoked, now, token) → ok payload | refused <слово>

Шаги 1–11 (с `expect` получателя), граница `now = exp + 60` и поведение двери при нечитаемой `domain/revoked` — [договор токена домена](../../Platform/common/contracts/domain-token.md)
«Проверка» (перенесено туда без изменения; номера шагов прежние; разбор ревью стадии B 3–5, В1).

### seal(book_seal, plain, aad) и open(seed_secret, envelope, aad) → ok plain | refused <слово>

Запечатывание, открытие и порядок проверок открытия — [договор конвертов домена](../../Platform/common/contracts/domain-envelopes.md) «Конверт `x25519:v1`» (разбор ревью
стадии A 8–10, № 12).

### установка домена (команда оператора, один раз на домен)

```
1. хранилище кластера-держателя отвечает, кольцо (P/06.2 Н1.2) читается; иначе отказ, ничего не записано
2. domain/keys или domain/root уже есть                               → отказ, ничего не меняется (domain/root —
   добавлено сверкой М11, I1: установка поверх чужого закреплённого корня застряла бы)
3. новый корень; файл восстановления создаётся первым, только если пути нет, режим 0600,
   вне PLATFORM_DIR и каталогов хранилища (Н1.1 place) → иначе отказ, в хранилище ничего не записано
4. ключи держателя (ключ токенов, выпускающий) → domain/signer, секреты — конвертами кольца
5. новое зерно → domain/book-seal {seed_secret} конвертом кольца
6. набор rev 1 (keys = {kid: ключ токенов}, current, issuing = [serial], revoked_issuing = [], book_seal) подписан
   корнем → domain/keys создание-однажды
7. domain/root {pub, domain} создание-однажды (держатель — тоже член)
8. запись срока 1 — урок 10 Н1.1 `claim` (её подписывает выпускающий, не корень); ключ резервной копии — Н1.3 backup_key_secret
```

Интерфейс шага 8 до урока 10: установка уроков 2–9 исполняет шаги 1–7 и на этом успешно кончается; запись срока
(`domain/holder`) в уроках 2–9 никто не читает: держатель в списке членов — урок 3 Н3, ответ держателя без `holder` —
урок 3 Н1.5. Урок 10 добавляет шаг 8 к той же команде.

Установка, прерванная до шага 6, повторяется после того, как оператор уберёт файл восстановления: члены ещё ничему не
верят, строки шагов 4–5 перезаписываются. Процесс `domain` домена не основывает: без строки `domain/signer` он ждёт её, проверяя раз в VIEW_EVERY (3 с), и не берёт
роль держателя и пишет причину в журнал. Холодный старт — Н3 «холодный старт».

### холодный старт

```
хранилище каждого кластера поднято (своя установка P/02.4, свой TLS) → установка домена на держателе (выше)
→ процесс domain держателя стартует и читает свои ключи → оператор принимает членов, закрепляя корень (урок 3)
→ агенты членов уносят набор и пишут отчёты (урок 3) → вид домена полнеет (урок 1)
```

Между «хранилище поднято» и «набор у члена» каждый кластер работает сам (М10); домена у него нет, сторожевая — по
[P/06.3](../../Platform/06-console/spec/06.3-console.norms.md) Н1.8. Ни один шаг не зависит от другого кластера: подписант читает только своё хранилище и файл восстановления.

### плановая смена ключа токенов

```
1. корень из файла восстановления; новый ключ токенов → domain/signer (ключ подписи меняется с записью набора)
2. набор: keys = прежние ключи — прежний current (у него until нет) и те, чей until > now, — плюс новый; current = новый;
   until[прежний current] = now + OLD_KEYS, until прочих — прежний (фильтр «until > now» — только у ключей с until);
   issuing, revoked_issuing, revoked_members, book_seal — прежние; rev по Н1.2 → domain/keys
3. члены берут набор с ответом держателя (урок 3)
```

Токены нового ключа член, ещё не взявший набор, отказывает `unknown_key` — до доставки (урок 3). Прежние токены годны до
`until` и своего `exp`. Обрыв между шагами 1 и 2 (строка записана, набора нет): то же следствие — токены нового ключа члены
отказывают `unknown_key`; операция отвечает отказом (код ≠ 0), её повтор начинается с шага 1 — ещё один новый ключ, и
набор называет его (прежний новый ключ никто не принял).

### смена ключа приёма книг

```
1. корень из файла восстановления; новое зерно → domain/book-seal (сначала строка, затем набор: иначе держатель не открыл бы
   конверты к новому book_seal)
2. набор: всё прежнее, book_seal — новый; rev по Н1.2 → domain/keys
3. конверты к прежнему book_seal больше не открываются: секретные вклады таких членов — missing (урок 5) до их отчёта,
   запечатанного к новому; принятые тела не переписываются
```

Обычная смена набора (плановая смена ключа токенов, отзыв члена) `book_seal` сохраняет.

### смена после кражи (ключи держателя у вора)

```
1. оператор достаёт файл восстановления; перенос держателя — урок 10 (POST /domain/move {stolen: true}); до урока 10
   смена после кражи — операция подписанта над своим набором на том же держателе (шаги 2–3 и 5; вызов — Решает
   реализация п. 2), урок 10 вызывает те же шаги из переноса
2. новые ключ токенов, выпускающий и зерно приёма книг → domain/signer и domain/book-seal нового держателя
3. набор: keys = {новый} без until (прежних ключей токенов нет); current = новый; issuing = [новый serial];
   revoked_issuing = прежний revoked_issuing ∪ прежний issuing; revoked_members = прежний ∪ {ключ члена украденного
   держателя — Entry.key держателя в domain/members (урок 3 Н1.1); нет — отказ, ничего не меняется (добавлено сверкой
   М11, I4)}; book_seal = новый; rev — аварийный (Н1.2 emergency): max(наибольший rev набора у достижимых членов + 1,
   целые стенные секунды + 60) → domain/keys
   # до урока 10 (тот же держатель) — известный rev — rev набора держателя: члены держат его наборы; формула та же
4. запись срока — урок 10 Н1.1 (подпись нового выпускающего); общий документ переподписывается — урок 11 Н1.2 after_move
5. члены берут набор с ответом нового держателя (урок 3)
```

**Член, который был без связи.** Пока он держит прежний набор, он принимает токены украденного ключа (Н1.7) и
запечатывает вклады к прежнему `book_seal`. Вернувшись, он берёт новый набор: его `rev` больше любого прежнего при
предпосылке Н1.2 `clocks` — прежний держатель не выпускал `rev` больше своих стенных секунд, а аварийный не меньше
стенных секунд смены плюс 60. Часы держателей разошлись больше — гарантии нет: это предел, а не норма. С этого момента токены прежних ключей — `unknown_key`, записи срока прежнего
выпускающего — отказ (урок 10), а его вклады, запечатанные к прежнему `book_seal`, — missing до первого отчёта после
нового набора (урок 5).

**Гонки.** Набор пишет один процесс (`domain` держателя); у члена — один агент. Два набора с одним `rev` от разных
подписантов невозможны без корня; «держу» при равном `rev` не даёт перезаписать набор повтором. Смена посреди сборки
книги: держатель открывает тем зерном, что прочёл в начале сборки; вклад к другому `book_seal` — missing, не отказ всей книги.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| набор: нет закреплённого корня | `refused no_pin` | агент: журнал, набор не взят | принять члена оператором (урок 3) |
| набор: не по форме Н1.2 | `refused not_a_set` | журнал агента | ничего: держатель пришлёт верный |
| набор: kid не root или подпись не та | `refused bad_signature` | журнал агента | проверить путь до держателя (подмена) |
| набор: другой корень или домен | `refused another_root` | журнал агента; домен — урок 3 | член принят в другом домене: принять заново |
| набор без `book_seal` | `refused no_book_seal` | журнал агента | ошибка держателя: подписать набор полной формой |
| набор старше | `refused older` | журнал агента | ничего: держит новее |
| токен: `no_revocations`, `not_a_token`, `unknown_key`, `bad_signature`, `bad_claims`, `expired`, `future`, `revoked`, `wrong_kind`, `wrong_audience` | [договор токена домена](../../Platform/common/contracts/domain-token.md) «Слова отказа» (перенесено туда; В1) | | |
| конверт: `not_v1`, `not_an_envelope`, `does_not_open` | вклад не открыт — член missing в книге (урок 5) | держатель: причина без значения | член перезапечатывает следующим отчётом к своему набору |
| установка: хранилище или кольцо недоступны, `domain/keys` или `domain/root` есть, файл восстановления уже есть или путь в `PLATFORM_DIR` | отказ, код ≠ 0 | оператор, слова | исправить причину |
| файл восстановления не читается, режим шире 0600 или `root_pub` не от `root_key`; смена после кражи без `Entry.key` держателя | отказ операции, ничего не меняется | оператор | взять верный файл |

## Н5 Приёмка

Каталог `Source/tests/testdata/acceptance/М11_Domain/02/` ([README](../../Source/tests/testdata/acceptance/М11_Domain/02/README.md)):
команды `keys`, `token`, `seal`, `seal-round` реализации на входах `inputs/<случай>.json` — без хранилища, сети и стенда.
Ключи входов — тестовые, открыты в приёмке. Вызов — двери словаря «Стенда» М11/01; сравнение — подмножество полей.

```yaml

# (offered, revoked, token, envelope) — любое значение JSON: их проверяет сама функция и отвечает словом, не кодом 2.
keys:        вход {pinned: Pin | null, held: <doc по форме Н1.2, которому член верит> | null, offered: <строка domain/keys как пришла>}

             expect?: {kind: <строка>, cluster: <член> | null, audience_claim?: <имя поля — непустая строка, умолчание aud>}}
             # audience_claim пустой или не строка — вход не по форме, код 2 (добавлено сверкой М11, T4)
             вывод {result: ok, payload} | {result: refused, reason: no_revocations | not_a_token | unknown_key | bad_signature |
                   bad_claims | expired | future | revoked | wrong_kind | wrong_audience}
seal:        вход {seed: <hex 32 байт>, envelope: <как пришёл>, member, source_path, item, pointer: <строки>}   # open Н3
             вывод {result: ok, plain} | {result: refused, reason: not_v1 | not_an_envelope | does_not_open}

             вывод {result: ok, envelopes: [<конверт>, <конверт>], opened: [<plain>, <plain>], distinct: true | false}

Pin:         {pub, domain}                     # Н1.1; pinned во входе не по этой форме — код 2
output:      закрытые объекты выше; ключи — в любом порядке; payload — объект payload токена как есть
```

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команды `keys`, `token`, `seal`, `seal-round`** для приёмки — шаблоны с `{input}`; их вызов и вывод — двери словаря
   «Стенда» М11/01, формы — Н5;
2. **команду установки домена** и вызов плановых смен и смены после кражи до урока 10 (имя, аргументы, где файл
   восстановления, как команда узнаёт каталоги хранилища, объектов и их копий, внутри которых файл запрещён); стенд урока 3
   называет её строкой словаря (`@install domain`);
3. **генератор случайности** для зерён, `eph` и `nonce` — криптографический генератор ОС;
4. **порядок полей JSON** в `doc` и выводах — свободен; подпись — над JCS.
