## Н0 Словарь слов

Нормативные слова — по [общему канону Н0](../../М10_Platform/spec/01-storage.norms.md#н0-словарь-слов).

## Н1 Форма

Общее для всех форм урока: hex — строчные `0-9a-f`; base64url — алфавит RFC 4648 §5 без `=`, запись каноническая: длина
≢ 1 (mod 4), лишние биты последнего знака — нули, повторное кодирование байтов даёт тот же текст; иначе — не base64url;
JCS — RFC 8785 (ADR-0072);
«стенные секунды» — секунды Unix по часам того процесса, который проверяет или подписывает. Ключи подписи — Ed25519
(RFC 8032), открытый ключ — 32 байта; ключ приёма книг — X25519 (RFC 7748), 32 байта.

Полнота форм. Каждая форма JSON урока — закрытая: поле вне списка — форма не та (что за этим следует, сказано у формы);
обязательное поле обозначено без `?`, необязательное — с `?`, отсутствие необязательного — его умолчание. Порядок ключей
объекта ничего не значит; порядок массивов назван у формы. Повтор ключа в объекте JSON — форма не та. Число — число
JSON (не строка, не `true`/`false`); «целое» — число без дробной части по значению (`2` и `2.0` — одно целое; вывод пишет его без дроби) в пределах ±(2^53−1); «конечное» — не NaN и не
бесконечность. Строки — UTF-8 без нормализации.

### Н1.1 Корень домена

```yaml
root:          пара Ed25519 домена; одна на всю жизнь домена
recovery_file: JSON {domain, root_key, root_pub}       # закрытая половина корня — только здесь; все три обязательны;
                                                      # лишнее поле или иной тип — файл не читается
  domain:      имя домена, 1–64 знака [a-z0-9-]
  root_key:    hex 32 байт — зерно закрытого ключа Ed25519 (RFC 8032 §5.1.5)
  root_pub:    hex 32 байт — открытый ключ; не тот, что выводится из root_key, — файл не читается (отказ, ничего не меняется)
  place:       у оператора вне каталогов хранилища, объектов и их копий; режим 0600; путь называет вызов операции
signs:         только набор domain/keys (Н1.2); записи срока и удостоверение держателя подписывают ключи issuing[] набора (урок 10 Н1.1)
limit:         файл восстановления — всё: корень подписывает набор, а ключ копии держателя выводится из зерна корня — украденный
               файл открывает и все копии домена (урок 10 Н1.5); средства, кроме смены корня с новой установкой, нет
needed_for:    установка (Н3), плановая смена ключа токенов, смена ключа приёма книг, смена после кражи (Н3); иначе никогда
not_on:        держатель (domain/signer, его копия урока 10), консоль, агент, воркер — корня не хранят и не читают
fingerprint:   hex(sha256(<32 байта открытого ключа>)[:8]) — 16 знаков; так корень и ключи называют люди и журналы
pin:           domain/root {pub, domain}       # у каждого члена, включая держателя; создание-однажды
  pub:         обязателен; hex открытого корня
  domain:      обязателен; имя домена
  not_a_pin:   строка не по форме (лишний элемент, нет поля, не hex) — закрепления нет: keys → no_pin; закрепление не чинится
               само, член принимается заново (урок 3)
  when:        держатель — при установке (Н3); член — при приёме оператором по отпечатку (урок 3); иначе не пишется
  never:       корень не закрепляется по первому пришедшему набору; закреплённый не заменяется — сменить корень = завести
               домен заново (новые установка и приём каждого члена)
```

X.509 под корнем домена нет: сертификаты TLS ролей выдаёт центр поставки (ADR-0075, М10/11 Н1.6). Заводская личность
устройства и регистратор — М13; приём члена оператором — урок 3.

### Н1.2 Набор ключей `domain/keys`

```yaml
row:           domain/keys {doc: <текст JSON документа>}   # ровно один элемент doc, строка; иной состав — not_a_set;
                                                           # строка хранилища (М10/1); писатель у держателя — процесс domain,
                                                           # у члена — агент (урок 3) после функции keys (Н3); агент кластера
                                                           # держателя её не пишет, пока кластер держит срок (урок 10 Н1.6 switch)
doc:                                                       # закрытый набор полей; лишнее поле — not_a_set; массивы — без
                                                           # значения порядка, повтор элемента допустим; писатель — по возрастанию
  domain:          имя домена (Н1.1)
  rev:             целое 1 … 2^53−1
  root:            hex открытого корня
  current:         kid ключа токенов, которым держатель подписывает сейчас; ∈ keys; ∉ until
  keys:            {<kid>: <hex открытого ключа токенов>}, не пусто; kid — непустая строка
  until?:          {<kid>: <стенные секунды>} — ключ ещё принимается до этого момента включительно; kid ∈ keys
  issuing:         [<serial>…] — ключи выпускающего держателя (урок 10); serial — непустая строка
  revoked_issuing: [<serial>…] — отозванные ключи выпускающего; всегда массив, может быть пустым
  revoked_members?: [<hex ключа члена>…] — отозванные ключи членов (урок 3: приём и подпись члена сверяются с ним)
  book_seal:       hex открытого ключа приёма книг X25519 (Н1.4); обязателен: набор без него не читается
  kid:             "root"
  sig:             base64url подписи Ed25519 корня над UTF-8(JCS(doc без kid и sig))
writer_forms:      kid ключа токенов = первые 8 знаков hex его открытого ключа; serial = первые 16 знаков hex открытого
                   ключа выпускающего; читатель принимает любую непустую строку
rev:               новый набор — max(rev набора, который держит подписант, + 1, целые стенные секунды подписанта);
                   у каждой смены, включая смену book_seal
only_forward:      член держит один набор; набор с меньшим rev — отказ, с равным — «держу», не переписывается
```

Набор — то, чему член верит без связи: ключи токенов держателя, отзывы и ключ приёма книг. Без набора у члена нет
домена (сторожевая М10/9 Н1.3, Н1.8 ниже).

```yaml
domain/view.trust:   {rev, root, book_seal}   # поле вида урока 1 Н1.4: набор, которому верит держатель;
                                              # root и book_seal — отпечатки Н1.1; какой rev держит каждый член — урок 3
```

### Н1.3 Ключи держателя

```yaml
process:       domain (подписант, ADR-0032) — единственный процесс с ключами домена и единственный писатель строк держателя;
               domainconsole и консоль кластера ключей не держат, подписи не просят и строк держателя не пишут: правку
               консоль домена передаёт процессу domain (урок 3 Н1.8)
domain/signer: {kid, token_key_secret, serial, issuing_key_secret, backup_key_secret, backup_key_rev}   # у держателя; секреты — конверты кольца М10/7 Н1.2
  token_key_secret:   hex 32 байт — зерно Ed25519 ключа токенов (current набора)
  issuing_key_secret: hex 32 байт — зерно Ed25519 выпускающего (его serial — в issuing набора; применение — урок 10)
  backup_key_secret:  hex 32 байт — ключ копии (урок 10 Н1.5: HMAC-SHA256 от зерна корня), пишет установка (Н3) и перенос;
  backup_key_rev:     целое ≥ 1, при установке 1
  forgotten:          смещённый держатель заменяет строку на {forgotten: "deposed by term N"} (урок 10 Н1.6)
readers:       domain (общая таблица читателей секретов М10/7 Н1.3 `platform_readers`)
domain/signer-pending:  подготовленный ключ X25519 плановой передачи у цели (урок 10 Н1.7); читатель тот же
SIGNER_URL:    адрес двери процесса domain держателя; его знают консоль кластера держателя и запись срока (уроки 8, 10)
```

### Н1.4 Ключ приёма книг

```yaml
domain/book-seal:  {seed_secret}           # у держателя; конверт кольца М10/7; читатель — только domain; без rev
  seed_secret:     hex 32 случайных байт — закрытый скаляр X25519 как есть (RFC 7748 §5: зажим при умножении)
public:            book_seal набора = X25519(seed_secret, 9) — открытая половина, hex
born:              при установке (Н3) раньше набора rev 1; заменяется только сменой ключа приёма книг и сменой после кражи (Н3)
travels:           с копией держателя и переносом (урок 10); в отчёты, книги и журналы не попадает
```

### Н1.5 Конверт `x25519:v1`

Секретное поле (`*_secret`, М10/7 Н1.1) вклада члена в книгу едет к держателю конвертом к `book_seal`: агент запечатывает
до подписи отчёта (урок 3), ретранслятор несёт байты (урок 4), держатель открывает только при сборке книги (урок 5).

```yaml
envelope:      x25519:v1:<eph>:<nonce>:<ct>          # ровно пять частей через «:»; части 3–5 — base64url без «=»
  eph:         32 байта — открытый ключ X25519 одноразовой пары запечатывающего
  nonce:       12 случайных байт
  ct:          AES-256-GCM(key, nonce, plain, aad) с тегом 16 байт; не короче 16 байт
key:           HKDF-SHA256(ikm = X25519(eph_priv, book_seal), salt = eph ‖ book_seal, info = "w2c book seal x25519:v1", L = 32)
               # при открытии ikm = X25519(seed_secret, eph); book_seal — открытая половина seed_secret
aad:           UTF-8(JCS([member, source_path, item])) ‖ 0x00 ‖ UTF-8(pointer)
  member:      имя члена-вкладчика
  source_path: ключ строки-источника вклада в хранилище члена (урок 5: строка семьи domain.books.<книга>.from)
  item:        элемент этой строки — вклад
  pointer:     JSON Pointer секрета в JSON-документе элемента — по правилу пути М10/7 Н1.2 (`~0`, `~1`, индексы)
plain:         байты UTF-8 значения секрета как дано; пустое значение тоже запечатывается
seal:          новая пара eph и новый nonce на каждый конверт; два конверта одного значения различны
```

Отказ открытия — одно из трёх слов, значение не повторяется ни в причине, ни в журнале (М10/7 Н1.4):

| Слово | Когда |
|---|---|
| `not_v1` | текст не начинается с `x25519:v1:` (другая версия, другой конверт, не строка) |
| `not_an_envelope` | частей не пять; часть — не base64url без `=`; `eph` не 32 байта, `nonce` не 12, `ct` короче 16; X25519 даёт нулевой общий секрет |
| `does_not_open` | AEAD не открылся (не тот ключ приёма книг, иной member, source_path, item или pointer, испорченный `ct`) или открытые байты — не UTF-8 |

Подмена AAD и чужой ключ неразличимы — обе причины — `does_not_open`. Подбор иных AAD при открытии запрещён.

### Н1.6 Токены домена и `domain/revoked`

```yaml
token:         <b64url(header)>.<b64url(payload)>.<b64url(sig)>       # ровно три части
  header:      JSON-объект; обязательные alg — строка "EdDSA", kid — строка; прочие поля пропускаются (не отказ);
               выпускающий пишет ровно {alg, kid} в JCS
  payload:     JSON-объект; обязательные: iat, exp — конечные числа, стенные секунды; jti — строка 1–64 [A-Za-z0-9_-];
               kind — непустая строка: person у людей (урок 9), вид спеки у воркеров (урок 7); прочие поля этим уроком
               пропускаются, кроме поля аудитории вида (урок 7 Н1.1 audience_claim) при проверке получателем; выпускающий пишет
               JCS и jti — 16 знаков hex из случайных 8 байт
  sig:         Ed25519 ключа kid набора над ASCII «<header>.<payload>» как пришли
domain/revoked: {jtis: "<jti>:<exp>,…"}      # ровно один элемент jtis, строка; пусто — ""; строки нет — отзывов нет;
                                            # иной состав, запись не «<jti>:<число JSON>» (jti по грамматике токена) — не по форме:
                                            # token → no_revocations; повтор jti и порядок читатель не проверяет
  writer:      процесс domain при отзыве (урок 9: человек; урок 7: токен вида) и при каждом проходе держателя; у члена —
               агент (урок 3 Н1.6); агент кластера держателя её не пишет, пока кластер держит срок (урок 10 Н1.6 switch)
  order:       по возрастанию jti в байтах; exp — число JSON, exp отозванного токена
  prune:       записи с exp + TOKEN_SKEW ≤ now писатель ДОЛЖЕН снимать — список ограничен числом живых токенов
  readers:     консоль кластера, роли воркеров — платформенной основой прав (М10/6 Н1.2), агент (урок 3); у члена — копия
TOKEN_SKEW:    60          # с, допуск часов в обе стороны; часы — стенные часы проверяющего
OLD_KEYS:      3600        # с — until прежнего current при плановой смене ключа токенов (Н3)
```

Проверка токена — функция `token` (Н3) у каждой двери, которая принимает токены домена: сторожевая консоли (М10/9 Н1.3,
урок 9), дверь токенов воркера (урок 7). Вид токена и `aud` — урок 7: токен другого кластера или вида отказывается там,
после проверки этого урока.

### Н1.7 Окно отзыва без связи

Проверяющий решает по своему набору и своей копии `domain/revoked` по своим стенным часам; связи с держателем проверка не
требует. Поэтому отзыв доходит не мгновенно, и норма называет пределы числом:

| Что отозвано | Принимается не дольше | Чьи часы |
|---|---|---|
| токен (`jti` в `domain/revoked`) | `min(exp + TOKEN_SKEW, доставка domain/revoked проверяющему)`; без связи — `exp + 60`, то есть `lifetime + 60` от выдачи; в `testsub*` самый долгий вид — `testsub2` `feed: 600` → 660 с | стенные проверяющего |
| прежний ключ токенов после плановой смены | до `until` своего набора (`OLD_KEYS` = 3600 с от смены) | стенные проверяющего |
| украденный текущий ключ токенов (у current нет `until`) | **до первого принятого проверяющим набора, где этого ключа нет** (смена после кражи, Н3): вор выпускает новые токены, и член без связи их принимает; сроком это окно не ограничено | — |
| ключ члена (`revoked_members`) | держатель отказывает сразу после своего набора (урок 3); член без связи сам себя не отзывает | — |

Доставка у члена — с ответом держателя агенту (урок 3 Н3); у кластера держателя — запись в его же хранилище.

### Н1.8 Сторожевая и следы домена

Состояния `on`, `open`, `shut` сторожевой консоли — М10/9 Н1.3. «Ключи есть» — строка `domain/keys` читается и принимается
функцией `keys` с закреплённым корнем. «След домена» — любая из строк `domain/root`, `domain/member`, `domain/revoked`,
`domain/grants/*`, `domain/break-glass/*`, или этот процесс консоли уже видел ключи: тогда без ключей — `shut` (503), не `open`.

В состоянии `on` личность — порядком М10/9 Н1.3 `identity`: подпись агента — урок 3 Н1.4; токен — функция `token`
Н3 по набору этого кластера; гранты человека и вход — урок 9. Без личности — 401, не 503: 503 — только `shut`. В `on`
человек — только по входу и грантам (урок 9 Н1.5); «петля — operator» — только `open`; агент своего кластера проходит по
подписи (урок 3 Н1.4).

## Н2 Двери

Собственных HTTP-дверей у урока нет. Набор и запись срока отдаёт `GET /api/held` (консоль кластера отвечает сама — урок 8 Н1.9; форма — урок 10); член уносит

Команды реализации для приёмки (Решает реализация п. 1) — функции Н3 без хранилища: `keys`, `token`, `seal`, `seal-round`;

## Н3 Проход

### keys(pinned, held, offered) → took rev | holding rev | refused <слово>

Функция агента члена над набором из ответа держателя (урок 3) и процесса domain над своим набором при смене. Шаги — по
порядку; первое сработавшее правило даёт итог.

```
1. pinned нет                                                              → refused no_pin
2. offered не {doc: строка}; doc не JSON-объект или с повтором ключа, поле вне закрытого набора Н1.2, обязательного нет,
   тип или граница не по Н1.2 (кроме book_seal)                            → refused not_a_set
   # kid или sig не строка, root не hex 32 байт — здесь; пустой issuing допустим (непустота названа только у keys)
3. kid ≠ "root"                                                            → refused bad_signature
4. doc.root ≠ pinned.pub или doc.domain ≠ pinned.domain                    → refused another_root
5. подпись sig не проверяется ключом pinned.pub над JCS(doc без kid и sig) → refused bad_signature
   # sig — строка, но не base64url или не 64 байта — тоже здесь
6. book_seal нет или не hex 32 байт                                        → refused no_book_seal
7. held есть: doc.rev < held.rev → refused older (rev held); doc.rev = held.rev → holding (rev held)
8. иначе                                                                   → took (rev doc); строка domain/keys := offered
```

Отказ не меняет строку `domain/keys`; член продолжает верить прежнему набору и пишет причину в журнал (М13).

### token(keys, revoked, now, token) → ok payload | refused <слово>

```
1. revoked есть и не по форме Н1.6 (не {jtis: строка}; запись не «<jti>:<число>»)  → refused no_revocations
2. token не строка; не три части; часть не base64url; header или payload не JSON-объект или с повтором ключа;
   header.alg ≠ "EdDSA"; header.kid не строка                                     → refused not_a_token
3. kid ∉ keys.keys, или kid ∈ until и now > until[kid]                           → refused unknown_key
4. подпись не проверяется keys.keys[kid] над ASCII «<header>.<payload>»           → refused bad_signature
5. iat или exp не конечное число, jti не строка по грамматике Н1.6, kind не непустая строка → refused bad_claims
6. now > exp + TOKEN_SKEW                                                         → refused expired
7. now < iat − TOKEN_SKEW                                                         → refused future
8. jti в revoked                                                                  → refused revoked
9. expect есть и kind ≠ expect.kind                                              → refused wrong_kind
10. expect.cluster есть и поле expect.audience_claim (умолчание aud) не список строк или без expect.cluster
                                                                                  → refused wrong_audience
11. иначе                                                                         → ok payload
# expect — что ждёт получатель (урок 7 Н3 «проверить у получателя»): вид и свой кластер; у токенов людей кластер не
# задаётся (person без аудитории, урок 9)
```

Равенство на границе принимает: `now = exp + 60` — ещё `ok`. `revoked` отсутствует (строки нет) — отзывов нет. Дверь,
у которой `domain/revoked` есть, но не читается хранилищем, отвечает как при `no_revocations`: проверить нечем (503 у
сторожевой, М10/9 Н1.3), а не «токен годен».

### seal(book_seal, plain, aad) и open(seed_secret, envelope, aad) → ok plain | refused <слово>

Запечатывание и открытие — Н1.5; порядок проверок открытия: `not_v1` → `not_an_envelope` → `does_not_open`.

### установка домена (команда оператора, один раз на домен)

```
1. хранилище кластера-держателя отвечает, кольцо М10/7 читается; иначе отказ, ничего не записано
2. domain/keys уже есть                                              → отказ, ничего не меняется
3. новый корень; файл восстановления создаётся первым, только если пути нет, режим 0600,
   вне каталогов хранилища → иначе отказ, в хранилище ничего не записано
4. ключи держателя (ключ токенов, выпускающий) → domain/signer, секреты — конвертами кольца
5. новое зерно → domain/book-seal {seed_secret} конвертом кольца
6. набор rev 1 (keys = {kid: ключ токенов}, current, issuing = [serial], revoked_issuing = [], book_seal) подписан
   корнем → domain/keys создание-однажды
7. domain/root {pub, domain} создание-однажды (держатель — тоже член)
8. запись срока 1 — урок 10 Н1.1 `claim` (её подписывает выпускающий, не корень); ключ копии — Н1.3 backup_key_secret
```

Интерфейс шага 8 до урока 10: установка уроков 2–9 исполняет шаги 1–7 и на этом успешно кончается; запись срока
(`domain/holder`) в уроках 2–9 никто не читает: держатель в списке членов — урок 3 Н3, ответ держателя без `holder` —
урок 3 Н1.5. Урок 10 добавляет шаг 8 к той же команде.

Установка, прерванная до шага 6, повторяется после того, как оператор уберёт файл восстановления: члены ещё ничему не
верят, строки шагов 4–5 перезаписываются. Процесс `domain` домена не основывает: без строки `domain/signer` он ждёт её, проверяя раз в VIEW_EVERY (3 с), и не берёт
роль держателя и пишет причину в журнал. Холодный старт — Н3 «холодный старт».

### холодный старт

```
хранилище каждого кластера поднято (своя установка М10/11, свой TLS) → установка домена на держателе (выше)
→ процесс domain держателя стартует и читает свои ключи → оператор принимает членов, закрепляя корень (урок 3)
→ агенты членов уносят набор и пишут отчёты (урок 3) → вид домена полнеет (урок 1)
```

Между «хранилище поднято» и «набор у члена» каждый кластер работает сам (М10); домена у него нет, сторожевая — по
Н1.8. Ни один шаг не зависит от другого кластера: подписант читает только своё хранилище и файл восстановления.

### плановая смена ключа токенов

```
1. корень из файла восстановления; новый ключ токенов → domain/signer (ключ подписи меняется с записью набора)
2. набор: keys = прежние ключи с until > now плюс новый; current = новый; until[прежний current] = now + OLD_KEYS;
   issuing, revoked_issuing, revoked_members, book_seal — прежние; rev по Н1.2 → domain/keys
3. члены берут набор с ответом держателя (урок 3)
```

Токены нового ключа член, ещё не взявший набор, отказывает `unknown_key` — до доставки (урок 3). Прежние токены годны до
`until` и своего `exp`.

### смена ключа приёма книг

```
1. корень из файла восстановления; новое зерно → domain/book-seal (сначала строка, затем набор: иначе держатель не открыл бы
   конверты к новому book_seal)
2. набор: всё прежнее, book_seal — новый; rev по Н1.2 → domain/keys
3. конверты к прежнему book_seal больше не открываются: секретные вклады таких членов — missing (урок 5) до их отчёта,
   запечатанного к новому; принятые тела не переписываются
```

Обычная смена набора (плановая смена ключа токенов, отзыв члена) `book_seal` сохраняет.

### смена после кражи (ключи держателя у вора)

```
1. оператор достаёт файл восстановления; перенос держателя — урок 10 (POST /domain/move {stolen: true}); до урока 10
   смена после кражи — операция подписанта над своим набором на том же держателе (шаги 2–3 и 5; вызов — Решает
   реализация п. 2), урок 10 вызывает те же шаги из переноса
2. новые ключ токенов, выпускающий и зерно приёма книг → domain/signer и domain/book-seal нового держателя
3. набор: keys = {новый} без until (прежних ключей токенов нет); current = новый; issuing = [новый serial];
   revoked_issuing = прежний revoked_issuing ∪ прежний issuing; revoked_members = прежний ∪ {ключ члена украденного
   держателя}; book_seal = новый; rev = max(наибольший rev набора у достижимых членов + 1, целые стенные секунды) → domain/keys
   # до урока 10 (тот же держатель) — rev набора держателя + 1: члены держат его наборы
4. запись срока — урок 10 Н1.1 (подпись нового выпускающего); общий документ переподписывается — урок 11 Н1.2 after_move
5. члены берут набор с ответом нового держателя (урок 3)
```

**Член, который был без связи.** Пока он держит прежний набор, он принимает токены украденного ключа (Н1.7) и
запечатывает вклады к прежнему `book_seal`. Вернувшись, он берёт новый набор: его `rev` больше любого прежнего, потому
что не меньше стенных секунд смены. С этого момента токены прежних ключей — `unknown_key`, записи срока прежнего
выпускающего — отказ (урок 10), а его вклады, запечатанные к прежнему `book_seal`, — missing до первого отчёта после
нового набора (урок 5).

**Гонки.** Набор пишет один процесс (`domain` держателя); у члена — один агент. Два набора с одним `rev` от разных
подписантов невозможны без корня; «держу» при равном `rev` не даёт перезаписать набор повтором. Смена посреди сборки
книги: держатель открывает тем зерном, что прочёл в начале сборки; вклад к другому `book_seal` — missing, не отказ всей книги.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| набор: нет закреплённого корня | `refused no_pin` | агент: журнал, набор не взят | принять члена оператором (урок 3) |
| набор: не по форме Н1.2 | `refused not_a_set` | журнал агента | ничего: держатель пришлёт верный |
| набор: kid не root или подпись не та | `refused bad_signature` | журнал агента | проверить путь до держателя (подмена) |
| набор: другой корень или домен | `refused another_root` | журнал агента; домен — урок 3 | член принят в другом домене: принять заново |
| набор без `book_seal` | `refused no_book_seal` | журнал агента | ошибка держателя: подписать набор полной формой |
| набор старше | `refused older` | журнал агента | ничего: держит новее |
| токен: `no_revocations` | 503 у сторожевой; отказ двери токенов | вызывающий | ждать читаемой строки |
| токен: `not_a_token`, `unknown_key`, `bad_signature`, `bad_claims`, `expired`, `future`, `revoked` | 401 у сторожевой (М10/9); отказ двери токенов (урок 7) | вызывающий | войти заново / получить новый токен; `future` — проверить часы |
| конверт: `not_v1`, `not_an_envelope`, `does_not_open` | вклад не открыт — член missing в книге (урок 5) | держатель: причина без значения | член перезапечатывает следующим отчётом к своему набору |
| установка: хранилище или кольцо недоступны, `domain/keys` есть, файл восстановления уже есть | отказ, код ≠ 0 | оператор, слова | исправить причину |
| файл восстановления не читается или `root_pub` не от `root_key` | отказ операции, ничего не меняется | оператор | взять верный файл |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команды `keys`, `token`, `seal`, `seal-round`** для приёмки — шаблоны с `{input}`; их вызов и вывод — двери словаря

   восстановления, как команда узнаёт каталоги хранилища, объектов и их копий, внутри которых файл запрещён); стенд урока 3
   называет её строкой словаря (`@install domain`);
3. **генератор случайности** для зерён, `eph` и `nonce` — криптографический генератор ОС;
4. **порядок полей JSON** в `doc` и выводах — свободен; подпись — над JCS.
