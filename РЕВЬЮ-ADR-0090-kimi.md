## Что проверено без находок

- **Формат MADR у ADR-0090** — полный: шапка (`status`, `date`, `decision-makers`, `consulted`, `informed`), Context and Problem Statement, Decision Drivers, Considered Options (3 варианта), Decision Outcome, Consequences с тремя Bad (включая честное «Архитектор — узкое место»), Confirmation, Pros and Cons, More Information с датой пересмотра. Имя файла и сквозная нумерация соблюдены.
- **Противоречий ADR-0090 с ADR-0080 доп. 16 нет**: чтение платформы из выгрузки `cammeta-specs` на закреплённом коммите — тот же механизм, что у генераторов (`CAMMETA_SPECS`). С ADR-0086: старт п. 5 («после перехода на манифест и первой выгрузки стадии C») согласован с «одним переходом в стадии B»; на срезе стадия B завершена, `Platform/common/manifest-rename.tsv` существует. С СЕССИИ.md §1–§3 прямых противоречий нет: новые сессии («Спецификация VMS») в §2/§3 ещё не вписаны, но ADR сам откладывает это («Первые промпты — в СЕССИИ.md к старту», п. 1).
- **Доп. (18) — сверка с нормами и приёмкой**: правки `51aab5938` согласованы во всех четырёх местах — P/06.7 Н1.7 `server` (третий участник класса signed: лист роли `console` с EKU serverAuth, сертификата клиента не запрашивает), договор пересылки (таблица заголовков, `x_operator`, «Принять консолью» п. 2), договор сертификата роли (участники класса signed), P/10 Н1.4 `server.role` (клиент двери — консоль кластера держателя; снятие центра — не снятие членства). TLS-приёмка № 14 переписана под новое поведение (`967baf9ad`): отказ рукопожатием пробуется прямой пробой `holder` / `m2-console`, строка пересылки после снятия центра — `200`; ложный проход журнала закрыт `id: @not($positive_forward_id)` (`e7fe6d046`). Прав не признанный заголовок не даёт («признанный прав не даёт — сторожевая решает по Authorization», forwarding.md:60-61), журнал пересылающей пишет `user` из токена — права и журнал решение не ломает. Долг cammeta-go записан отдельной строкой в коммите; поведение Python не меняется. Решение отвечает на реальное расхождение реализаций (Go признавал `X-Operator` по `Entry.ca`, Python снимал) и выбирает способ, исполнимый на обеих сторонах (обоснование про `ssl` Python 3.12 и отсутствие сертификатов центров у не-держателя — проверяемое и верное по форме).

## Находки

### ADR-0090

**1. Существенная. Закрытость — чёрным списком: всё неперечисленное остаётся открытым, включая замороженный свидетель и файлы «Архитектора».**
Место: `decisions/0090-сессии-vms-без-права-на-платформу.md:44-48`.
Цитата: «Закрыты: `Platform/`, `Source/w2cplatform/` (в том числе `console.js`), `Source/tests/testdata/` платформы, `skills/`, `decisions/` кроме `decisions/inbox/`, `НОРМАТИВНЫЕ-СЛОВА.md`, `КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`. Закрытость держит проверка git … (хук, отказывающий коммиту с закрытым путём)».
Контрпример: сессия «Спецификация VMS» при переводе М10B правит `Source/vms/worker.py` (замороженный свидетель ADR-0080 доп. 16 п. 2: «старый Python заморожен») или `СЕССИИ.md` / `ГРАНИЦА-ПЛАТФОРМЫ-И-ПОДСИСТЕМЫ.md` (файлы владения «Архитектора», СЕССИИ.md §2) — ни один из этих путей не входит ни в открытые, ни в закрытые списки, хук коммит не отклоняет. Также открыты по умолчанию: `GLOSSARY.md`, `COURSE-PLAN.md`, `ХОД-*.md` чужих сессий, `Source/cluster/`, `Source/tests/` (кроме `testdata/`), `Source/deploy/`, `Source/traces/`, `.cursor/rules/`, `_notes-ru/`, `windows/`.
Нарушенный источник: собственный Decision Driver ADR-0090 — «граница платформы и подсистемы должна держаться устройством работы, а не просьбой в промпте»; СЕССИИ.md §1 п. 15 (писатели по каталогам).
Последствие: механизм, который должен держать границу, не держит её для всех неперечисленных путей; правка замороженного свидетеля или чужих ХОД пройдёт мимо хука, и Confirmation п. 2 это не поймает, если коммит без трейлера (находка 3).
Рекомендация: заменить чёрный список белым (хук отказывает любому пути вне перечня открытых) — это одно предложение в п. 3 и более простой хук.

**2. Мелкая. «Source/tests/testdata/ платформы» — неопределённый критерий для хука.**
Место: `decisions/0090-сессии-vms-без-права-на-платформу.md:45-46`.
Цитата: «Закрыты: … `Source/tests/testdata/` платформы …».
Контрпример: на срезе каталог содержит только платформенные файлы (`testsub.subsystem.yaml`, `testsub2.subsystem.yaml`, `spec_verdicts.tsv`, ведомости `*_debt.txt`), но слово «платформы» в правиле хука не формализовано: файл `Source/tests/testdata/<новое>.tsv`, нужный сессии VMS для её приёмки, — закрыт он или открыт, хук решить не может.
Нарушенный источник: adr-format.mdc «Достоверность» (не выдумывать; правило должно быть проверяемым); формат хука требует однозначного предиката.
Последствие: двусмысленное правило хука — споры или молчаливые обходы.
Рекомендация: закрыть `Source/tests/testdata/` целиком (сейчас там только платформенное), а данные VMS держать в каталогах модулей VMS, как уже записано в п. 3.

**3. Мелкая. Confirmation п. 2 «поиск по автору» не различает сессии.**
Место: `decisions/0090-сессии-vms-без-права-на-платформу.md:69-70`.
Цитата: «В истории курса после старта нет коммитов сессий VMS с закрытыми путями п. 3 (поиск по автору и путям на каждой вехе ХОД «Архитектора»)».
Контрпример: все сессии коммитят от git-идентичности владельца (см. коммиты среза: `Author: Murat Altuev`), сессия различима только по трейлеру `Co-Authored-By`; коммит сессии VMS без трейлера неотличим от коммита владельца или «Архитектора» — поиск по автору его не найдёт.
Нарушенный источник: adr-format.mdc — «решение без способа проверки не выполняется»; СЕССИИ.md §1 п. 4 (трейлер — дисциплина, не механизм).
Последствие: вторая строка Confirmation может формально выполняться при нарушенной границе.
Рекомендация: проверять по путям веток `*/<тема>` сессий VMS или по списку worktree, а не по автору; либо сделать трейлер обязательным для учёта.

**4. Мелкая. Форма запроса п. 4 не увязана с обязательной формой входящих.**
Место: `decisions/0090-сессии-vms-без-права-на-платформу.md:49-52`.
Цитата: «Запрос правки платформы — файл `decisions/inbox/<дата>-запрос-vms-<тема>.md`: какая норма мешает (адрес нормы и коммит выгрузки), что нужно, пример из VMS, обход, если есть».
Контрпример: `decisions/inbox/README.md` требует шапку `kind/adr/date/author` и раздел «Рекомендация» («файл без рекомендации возвращается»); запрос по п. 4 без этих полей формально подлежит возврату, хотя по смыслу полон.
Нарушенный источник: `decisions/inbox/README.md` «Форма».
Последствие: запросы VMS возвращаются по форме, теряется время — ровно то, чего боится Bad про длинный путь правки.
Рекомендация: в п. 4 добавить «по форме входящих (`kind: вопрос`, обход — в «Рекомендацию»)».

**5. Мелкая. Текст и размещение хука не определены.**
Место: `decisions/0090-сессии-vms-без-права-на-платформу.md:47-48`.
Цитата: «Закрытость держит проверка git в рабочих деревьях сессий VMS (хук, отказывающий коммиту с закрытым путём), не только промпт».
Контрпример: git-хук живёт в `.git/hooks` каждого worktree и в репозитории не версионируется; ADR не называет ни файл с текстом хука, ни того, кто его ставит и обновляет (при смене списка п. 3 все деревья расходятся молча).
Нарушенный источник: собственный Decision Driver «граница … устройством работы»; СЕССИИ.md §1 п. 16 (г): «новое правило … удаляет старое или показывает сэкономленное время» — здесь скорее полнота решения.
Последствие: хук в каждом дереве свой, правила разойдутся (сам ADR в Bad это предвидит для `СЕССИИ.md`, но не для хука).
Рекомендация: назвать файл хука в репозитории (например `skills/` или `decisions/inbox/`-видимое место) и правило установки при заведении worktree.

### ADR-0083 доп. (17)

**6. Существенная (вопрос «Архитектору», меняет решение). «Другой агент» не требует другого провайдера: коррелированные догадки занижают меру зрелости.**
Место: `decisions/0083-микромодули-платформы.md:400-401`.
Цитата: «тот же язык МОЖЕТ сгенерировать другой агент по той же выгрузке и с тем же ограниченным чтением (доп. (5) п. 1). Её цель — только сведения о догадках».
Контрпример: обе генерации делает одна модель (два агента одного провайдера): систематические слепые пятна модели совпадут, журналы догадок сойдутся, итог покажет «норма определена» там, где она допускает два прочтения — мера «зрелость спецификации по числу догадок» даёт ложную зрелость именно в самой опасной части (догадки, которых не видит ни одна из копий одной модели).
Нарушенный источник: по духу СЕССИИ.md §1 п. 16 (д) «Ревьюер — не на провайдере автора» и состав «Ревью спецификации» (§2: ревьюверы разных провайдеров) — тот же принцип независимости второго чтения; цель дополнения («прямая мера доп. (5)»).
Последствие: итог стадии C занижает число неопределённостей спецификации; находки к нормам не рождаются там, где нужнее всего.
Рекомендация: требовать вторую генерацию моделью другого провайдера (как состав ревью п. 17), либо явно записать, что мера не ловит коррелированные догадки (Bad).

**7. Мелкая. У второй генерации нет владельца, критерия итога и Confirmation.**
Место: `decisions/0083-микромодули-платформы.md:400-407`.
Цитата: «Итог — сравнение двух журналов и расхождений поведения, которые приёмка не различила. … после итога вторую генерацию снимают».
Контрпример: «другой агент» — не названа сессия (в СЕССИИ.md §2 её нет), «МОЖЕТ» делает генерацию необязательной без условия «когда», «итог» не имеет ни срока, ни формы записи (файл? дополнение?), Confirmation у дополнения отсутствует — проверить, что вторая генерация случилась и снята, нечем.
Нарушенный источник: adr-format.mdc — «Confirmation не пропускай: решение без способа проверки не выполняется».
Последствие: дополнение может остаться невыполненным или неснятым (вторая генерация продолжает жить и расходиться) без сигнала.
Рекомендация: одна строка — кто заводит вторую генерацию (сессия), где пишется итог и как проверяется снятие.

### ADR-0083 доп. (18)

**8. Существенная. Не определено, ставится ли `X-Operator: console` на пересылке в консоль домена своей коробки (переход 2): после доп. (18) единственный признающий потребитель заголовка может оказаться недостижим.**
Место: `Platform/common/contracts/forwarding.md:29` и `forwarding.md:51-59`; введено/обострено `decisions/0083-микромодули-платформы.md:424-425` (доп. (18)).
Цитаты: таблица заголовков — «`X-Operator: console` | консоль кластера при каждой пересылке (переход 1)»; `set: X-Operator: console; X-W2C-Via: <CLUSTER> — к консоли другого кластера (Н1.3)`; и «доказанная роль бывает только у двери роли консоли домена: консоль кластера, принимающая переход 1 … и X-Operator: console у неё снимается всегда (… ADR-0083 доп. (18))». При этом P/10 Н1.4 `server.role` (`10-domain-console.norms.md:198`) гласит: «приём консолью домена пересылки с X-Operator: console … по маршруту P/06.7 Н1.4 клиент этой двери — консоль кластера держателя».
Контрпример: член `m2` шлёт `GET /domain` (TLS-стенд, строка 1 № 14): его консоль ставит `X-Operator: console` на переходе 1 — консоль `hold` снимает его всегда (доп. (18)); консоль `hold` пересылает в консоль домена своей коробки (переход 2). Реализация A читает «при каждой пересылке» — ставит `X-Operator: console` и на этом шаге → дверь роли консоли домена признаёт его (роль `console` доказана сертификатом `hold`-console) → журнал принимающей помечает запрос как пересланный консолью (forwarding.md:60-61). Реализация B читает «(переход 1)» и «к консоли другого кластера» буквально — на переходе 2 заголовка нет → признание не срабатывает никогда и нигде: правило «Принять консолью» п. 2 в части «оставить для журнала» мертво, а P/10-10 («приём у консоли домена») проверяет то, чего нет.
Нарушенный источник: договор пересылки (младший) против P/10 Н1.4 и чеклиста P/10-10; старшинство источников расхождение не разрешает — обе стороны обновлены одним коммитом `51aab5938` и читаются взаимоисключающе.
Последствие: две реализации, следующие канону, расходятся в журнале принимающей консоли домена; норма о признании либо мертва, либо зависит от догадки — тот класс расхождения, который доп. (18) устраняло на переходе 1.
Рекомендация: одна правка договора — явно: «`X-Operator: console` ставится на каждой пересылке, в том числе в консоль домена своей коробки (переход 2); на переходе 1 приёмная сторона его всё равно снимает» — или снять заголовок с перехода 1 совсем (тогда ставит только консоль кластера держателя).

## Счёт по серьёзности

- Блокеров: 0
- Существенных: 3 (№ 1 — чёрный список путей; № 6 — провайдер второй генерации; № 8 — `X-Operator` на переходе 2)
- Мелких: 5 (№ 2, 3, 4, 5, 7)

## Три самые важные

1. **№ 1 (ADR-0090 п. 3)** — чёрный список вместо белого: граница «устройством работы» не держится ни для замороженного свидетеля (`Source/vms/*.py`, `Source/cluster/`), ни для файлов «Архитектора»; вся конструкция ADR-0090 опирается на этот список.
2. **№ 8 (доп. (18))** — двусмысленность `set: X-Operator` оставляет расхождение реализаций на переходе 2 там, где решение как раз вводило единственное место признания заголовка.
3. **№ 6 (доп. (17))** — без требования другого провайдера вторая генерация измеряет не зрелость спецификации, а повторяемость одной модели.
