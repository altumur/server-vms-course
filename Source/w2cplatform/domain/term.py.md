# term.py — Lesson 15: the domain held by a small box — a term, a signed backup beyond the holder, moving as an ordinary operation

**Role in the module.** On a site with no server the designated domain holder is a small box, and small boxes die. Moving the domain becomes ordinary, and three things follow: a TERM (the epoch one level up — a larger term wins, a returning holder steps down on its next read), STATE BEYOND THE HOLDER (what only the holder holds — Lesson 9's kept edits for a member that is off above all — published as a signed backup that chosen members' agents carry, like the shared settings), and NOTHING LOST SILENTLY (an old holder's un-backed-up changes listed for a person). The signer's key is never in the backup; it comes from where Lesson 7 put it.

## Module-level names
- `HOLDER = "domain/holder"` (a signed `{term, holder, at}` in the holder and in every member), `BACKUP = "domain/backup"` (per-member pointer `domain/backup/<member>` in the holder; the member's copy and document), `EXPORTED` — the prefixes the backup carries: pending, grants, crossings, sources, the settings pointer, topology, members, roads, placement, the licence; `EXPORTED_OBJECTS` — from the holder's object store, the week of alarm history (Lesson 14), which lives on the holder's card and would otherwise die with it.

## Functions
### `read_holder(vars_, keys, now)` — the verified holder record, or `None`. A key set with a root takes a record only from the root (step 9): a record the token key signed is what a stolen holder would write.
### `verified_record(doc, keys, now)` — the same check over a record as signed, wherever it came from (a console's `/api/held`, a target's answer to a handover).
### The cluster console's doors of a move (contract §10a; «Архитектор» 2026-10-06) — each cluster answers for what IT holds, nobody reads another cluster's store:
- `held(cluster, vars_)` — `GET /api/held`, no token: exactly `{cluster, holder, term, keys, backup: {rev}}` — the record and the key set this cluster holds, as signed, its term, and the NUMBER of the backup copy kept here (null — none); never the copy's content. What an agent follows the holder by (`agent.HolderFollower`), what a move reads the largest term and the keys by, and the one process door the console module reads on a person's page (contract §2).
- `backup_answer(cluster, vars_, objects, member, at, signature, now)` — `GET /api/backup`: the pointer, the backup object and the shared document, only to a member that signs `backup|<cluster>|<member>|<time>` (`backup_message`) with the key it was admitted with, as THIS cluster's copy of the list says it (`MEMBER_LIST = "domain/member-list"`, carried home by its agent): unsigned or another key 401, a name off the list or a revoked key 403, a clock more than `carry.SKEW` away 401.
- `prepare_message(cluster, at)` — what the holder of the current term signs to ask `cluster`'s signer to prepare a handover (`POST /api/prepare`).
- `AskedCluster(name, console, member, key)` — a neighbour as a move reads it, over its console: `/api/held` and `/api/backup` signed by this member's key, shaped as the `Cluster` a move reads; it writes nothing anywhere; a console that does not answer or refuses is `Unreachable`.
### `install(fed, name, domain_id, root, wall, objects) -> DomainHolder` — step 9's cold start: an issuing signer under `root`, key set rev 1 signed by the root, the root-signed record of term 1, claimed. The root is then the operator's recovery file.
### `carry_holder(domain_vars, member_vars, keys, now) -> str` — the agent's side: carry the record only if it verifies and its term is LARGER than the member's; never backwards. `take_record(member_vars, doc, keys, now)` — the same for a record as signed (the agent following the holder).
### `find_holder(fed, member_vars, keys, now) -> str | None` — the largest verified term among the member's own record and reachable members' claims about THEMSELVES; two holders with one term raise `TwoHolders`. A holder that is off stays the holder if nobody holds a larger term.
### `move_domain(fed, new, signer_backup, domain_id, objects_of, wall) -> (DomainHolder, report)` — restore the signer on `new`; among reachable members, the largest term carried and the newest backup that verifies; restore its state; publish keys; flag `new` as the domain holder; term = largest seen + 1; claim. It WRITES ONLY `new`'s stores (ADR 0001 §1.12): no member is told — each member's agent follows the holder by itself (`agent.HolderFollower`). A neighbour that answers its record but refuses its backup still counts for the term (`ignored` says it). The report names the term, the record claimed (`record`), the backup and its keeper, what was ignored, and says what is not there. Called by two operations of the signer and nothing else, both on the NEW holder: the move (`signer_service.Holder.move`, `POST /api/move`, `w2cctl domain move`) and the taking of a planned handover (`Holder.take`, `POST /api/take`).
### `stranded(old_vars, restored_state, signer=None) -> list` — every exported item on a returning old holder that differs from what the new term was restored from, compared by what the rows SAY (the old holder's opened with its ring, the restored state's with the backup key). A `*_secret` that differs is listed as `<secret: differs>` — the list is a plain row, and a value is never copied out of its ring.

## `class DomainHolder`
`claim()` (the record names `url`, where this holder's signer answers, when the holder knows it — ADR-0032: the view's `url` is the domain console's, the signer's address is the record's); `export()`; `export_objects()` (the `EXPORTED_OBJECTS` keys, as text — `move_domain` puts them back on the new holder); `backup(targets, objects) -> rev` (a deposed holder may not publish; a frozen one may — that is how it hands over); `check()` — False, and `deposed_by` set, if any reachable member carries a larger term (`depose(rec)`: the same for a record verified elsewhere — a handover's target's answer); `guard()` raises `Deposed` naming the new holder and term, or `Frozen` while `frozen_for` names the member a handover is moving the domain to.

## `class GuardedPending`
`PendingEdits` with the holder's guard in front of `add`: a kept edit is refused as `ApiError(503, reason)` while the holder is frozen or deposed. Everything else passes through.

## `handover(holder, to, objects_of, carry_to, take, wall) -> (DomainHolder | None, report)`
The planned move from a live holder: freeze; last backup to `to` (in the holder's own store); `carry_to()` runs `to`'s agent; if `to`'s pointer does not name that rev at this term (or `to` is unreachable) the handover is called off — `RuntimeError`, holder unfrozen, nothing claimed. Otherwise `take()` — `to`'s OWN move onto its own store (`move_domain` run by `to`: in the lessons in-process, in production `signer_service.asked_to_take` over `to`'s console, `/api/prepare` then `/api/take`); the outgoing holder writes no store but its own. It steps down by the record `to` claimed (`report["record"]`, verified, `depose`) or by `check()`; no larger term — called off. Then `stranded` against the restored state; the report adds `planned` and `stranded` and says *nothing stranded* only when that list is empty.

## Step 9 — the root off the holder
- `DomainHolder(..., record=None)`: the record the root signed for this term; `claim()` writes it instead of signing one. `check()` reads with the published key set (`ClusterTrust(self.vars)`, the root in it). Deposed, an issuing signer forgets its keys (`_forget_keys`: `domain/signer` ← `{forgotten: "deposed by term N"}`).
- `carry_holder` refuses a record not signed by the root when the member trusts one.
- `move_domain(..., stolen=False)`: from a recovery file, the new holder gets keys of its OWN (`Signer.issued`); `_trusted_keys` — the newest root-signed key set any reachable member holds, verified against the root in the file; `_next_key_set` — the new token key current, the old ones kept `OLD_KEYS_OVERLAP` (an hour) after a planned move, dropped after a theft with every issuing certificate so far revoked; `_sign_shared_again` — the shared document signed again at the new term (members check it on every read); the root signs the record of the new term; after a theft `reissue_ldevids` signs again each member's admitted key (`domain/members`, `key`) into `domain/ldevid/<member>`. The report adds `keys_rev`, `stolen`, `reissued`. From the signer's backup of Lessons 4–7, `stolen=True` is refused: it holds the stolen keys themselves.
- Tests: `tests/domain/test_lesson15_root.py` — the recovery file is the root and the holder holds none of it; a stolen holder can neither take the domain nor hand out keys of its own; after a theft the move drops the old keys and signs every LDevID again; a planned move gives the new holder keys of its own and the old ones live an hour; a key set only goes forward; the signer's backup cannot answer a theft.
- **The holder's member key** (feedback CC): `DomainHolder.member_key` (`install(member_key=)`, or the holder's own row after a move) travels in every backup as `holder_key`; `move_domain` writes it into the former holder's row when that row has none (`_keep_member_key`), so the next theft signs its LDevID again. After a theft `reissue_ldevids(skip=)` never signs the stolen holder's key: the thief has it.
