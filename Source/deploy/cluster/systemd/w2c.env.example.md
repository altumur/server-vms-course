# w2c.env.example — `/etc/w2c/w2c.env`, the platform's settings of a cluster server

**Role in the module.** Lesson 3. The product's split: this file the platform's (`SERVER_NAME`, `LABELS`, `PLATFORM_DIR`, `RESOURCE_ROOT` — the platform's events archive, `/data/platform/events`, `OBJECTS`, `RESOURCE_URL`, the store's `CONFIGSTORE_RAFT`/`CONFIGSTORE_API`/`CONFIGSTORE_JOIN`/`CONFIGSTORE_TUNING`, `W2C_TLS`, the spares' `CONSOLE`, `MAX_*` — what a spare runs is its role's template, not a line here), `/etc/vms/vms.env` the subsystem's. On the data partition (`/data/platform/etc`, `/etc/w2c` a link to it). No `PLATFORM_STORE`: on a cluster each unit names its own role's socket, and a process with none opens its verb's role's socket (`cluster/__main__.stores`). `CONFIGSTORE_JOIN` empty on the cluster's first server (a group of one), a member's door on every other. `install.sh` writes it from this example once, and never over an edited one.
