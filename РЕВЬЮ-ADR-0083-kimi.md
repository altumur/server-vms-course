# Ревью ADR-0083 доп. (34) — скорость генерации: SDK, выгрузки пачками, аудит раскладки

Срез: курс `dd740a9bd`. Охват: доп. (34) пп. 1–4; согласие с доп. (25) п. 5, доп. (28)–(33); риски снятия
независимой проверки промежуточных SDK и работы по решению до выгрузки. Проверки чтением: текст дополнений
ADR-0083, `cammeta-c-python/AGENTS.md` (действующий порядок SDK), README cammeta-acceptance.

## Вывод

Годно: 2 мелкие. Решение исполнимо, ослабление ограничено и ограничено явно; защита от расхождения «строка журнала
vs норма» уже существует (запись `TRANSITION-<spec>.md`, доп. (29) п. 4).

## Анализ по вопросам поручения

**Что теряется без независимой проверки промежуточных SDK; что ловит приёмка.**
У промежуточного выпуска остаются: все векторы договора через API и CLI (проверка автора — сессии `common`),
проверки потребителя, закрепление версий. Переносится на кандидата: независимая проверка точных архивов, режимы,
мутанты, пересборка. Теряется раннее обнаружение дефекта публикации: если кандидатная проверка красная, откат
затрагивает всех потребителей, уже закрепивших промежуточные версии (перевыпуск + перезакрепление). Приёмка это
**ловит** — независимая проверка у кандидата сохранена полной и по всем пакетам кандидата; независимая проверка —
это и есть проверка кандидата приёмки, то есть приёмочный контур не ослаблен. **Не ловит** приёмка только случай
«пакет не вошёл в кандидат» — см. М-2; корректность приёмки это не портит (пакет вне кандидата и не сдаётся),
теряется только своевременность.

**Согласие с доп. (25), (28)–(33).** «Не ослабляются: прогон всех векторов договора, закрепление версий, запрет
копий общего алгоритма» — согласовано с устройством доп. (28) п. 2 / (29) п. 1 (`common/` пишет одна сессия,
остальные читают как библиотеку) и фильтром `CONTRACT.md` доп. (32) п. 4 / (33) п. 4. Пачки выгрузок согласованы с
переходом доп. (29) п. 4: запись `TRANSITION-<spec>.md` обязана назвать место в коде каждой изменённой норме — она
не предполагает «одна выгрузка — одна норма». П. 4 (аудит) — чтение и список во входящих, исполнитель
«Спецификация» (владелец `Platform/`, СЕССИИ §2), решения — «Архитектор», нормы одной выгрузкой — согласовано с
п. 2; генерация не стоит (аудит только читает).

**Не открывает ли п. 3 угадывание.** Нет: основание работы — решение «Архитектора» строкой журнала, а не догадка
генератора; по старшинству `decisions/` выше выгрузки, счёт догадок чистой комнаты не портится (догадка решена, а
не угадана). Расхождение строки с поздней нормой ловит существующая обязанность: при переходе на выгрузку запись
`TRANSITION-<spec>.md` ставит каждой изменённой норме место в коде (доп. (29) п. 4). Остаточный риск — переделка,
если норма сформулирует деталь иначе строки; это цена скорости, а не пробел чистоты. `pending` ограничен случаем
«данных нет ни в выгрузке, ни до нормы» — формулировка достаточно узкая.

## Находки

### Мелкие

**М-1. «Подтверждает доп. (25) п. 5» — неверно, п. 3 его меняет.** Место:
`decisions/0083-микромодули-платформы.md:785` (доп. (34) п. 3). Доп. (25) п. 5 (:610): «решение идёт нормой и
выгрузкой, генератор переходит на неё сменой `SPEC_VERSION`» — работа после выгрузки. Доп. (34) п. 3 разрешает
работу по строке журнала **до** выгрузки — это уточнение/изменение, а не подтверждение; читатель, ищущий основание
в доп. (25) п. 5, найдёт противоположное.
Рекомендация: «уточняет доп. (25) п. 5: до смены `SPEC_VERSION` основание — решение строкой журнала».

**М-2. «Все пакеты SDK, вошедшие в кандидата» — щель для пакета вне кандидата.** Место:
`decisions/0083-микромодули-платформы.md:780–781` (доп. (34) п. 1). Пакет, чей урок-потребитель в `pending`
(п. 3) и не вошёл в кандидат, независимую проверку не получает, а его промежуточная версия у потребителя уже
закреплена. Следующий кандидат его накроет — но только если потребитель войдёт; формулировка не называет, что
каждый выпущенный пакет рано или поздно проходит независимую проверку.
Рекомендация: «по всем пакетам кандидата; пакет, выпущенный и не вошедший ни в один кандидат, проверяется при
первом вхождении — до приёмки урока-потребителя».
