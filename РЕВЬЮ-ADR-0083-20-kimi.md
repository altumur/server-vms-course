# РЕВЬЮ-ADR-0083-20 — ревью ADR-0083 доп. (20) «дверь процесса domain: предъявленный сертификат проверяется в рукопожатии»

- **Прогон:** ревью дополнения по правилу СЕССИИ.md §1 п. 17 (kimi).
- **Срез:** main `9ac51bc60`.
- **Дата:** 2026-10-22.
- **Охват:** `decisions/0083-микромодули-платформы.md` доп. (20) (строки 468–505). Сверено с: `Platform/common/contracts/role-certificate.md` (классы `signed`, `kit`, `revoke`), `Platform/common/contracts/peer.md` (функция peer, `revoke`), `Platform/02-installer/spec/02.4-installer.norms.md` (Н1.6 `ca`, `sig`, `client_cert`, `roles`; `w2c-ca.sh revoke`), `Platform/08-domain/spec/08.0`, 08.2, 08.3, 08.4, `Platform/09-agent/spec/09.1`, 09.2, `Platform/10-domain-console/spec/10` (Н1.4), `Platform/common/acceptance/tls/README.md` (п. 2, п. 8, № 14). Код реализаций не читался; доводы о стеках проверялись по документации библиотек.

**Вывод: с правками.** Решение верно по существу и согласовано со стеками и нормами; перечень правок норм полон. Две оговорки — отзыв листа и возобновление сессий — нужно дописать в норму, иначе реализации снова разойдутся ровно там, где ADR их сводит.

## Проверено без находок

- **Довод о стеках — верен во всех четырёх пунктах.** Python 3.12 `ssl` с `CERT_OPTIONAL`: сервер запрашивает сертификат клиента, предъявленный проверяется в рукопожатии (цепочка, срок, назначение `sslclient` — EKU `clientAuth`), отказ — alert; «принять без проверки и проверить после» стандартная библиотека действительно не умеет (обратного вызова проверки в `ssl` нет, с `CERT_NONE` сервер сертификат не запрашивает вовсе). OpenSSL `SSL_VERIFY_PEER` без `SSL_VERIFY_FAIL_IF_NO_PEER_CERT` — ровно описанное поведение. nginx `ssl_verify_client optional` — проверяет предъявленный (не проверяющий вариант — `optional_no_ca`, ADR его не путает). Go: `RequestClientCert` — запрос без проверки (проверка после рукопожатия возможна), `VerifyClientCertIfGiven` + `ClientCAs` — проверка в рукопожатии с EKU `clientAuth` и сроком. Вывод «Python уже alert, Go ok → правится Go» согласуется с результатом TLS-приёмки (Python 3/4, Go 4/4).
- **Полнота перечня правок норм.** Все места, говорящие о двери `domain` «сертификат клиента не требуется / предъявленный не проверяется», в перечне есть: договор сертификата роли «Серверная сторона: класс `signed`» (`role-certificate.md:74–76`, где процесс domain назван среди участников), P/02.4 Н1.6 `client_cert` (`02.4-installer.norms.md:232–235`), чеклист P/08.0-02 (`08.0-domain.norms.md:148`), TLS README п. 2 строка `signer` | `foreign-console` (`README.md:103`). Поиск по «предъявленн»/«не проверя» по всем `Platform/` других таких мест не дал. P/08.3 (сторона агента, отпечатки) и P/09 (агенты и ретрансляторы сертификата не шлют — 09.1 Н1.11, 09.2 Н1.6) правки не требуют — верно, что не в перечне. Указатели (`08.3:26` → глава 8.0; `08-domain.README.md:266` — «только на соединении роли domainconsole») остаются верными после правки.
- **Приёмка не теряет проверку правила.** Правило «предъявленный не проверяется» для дверей без запроса сертификата остаётся проверенным строкой № 14 (`README.md:172–180`: дверь `member m1 console`, клиент `foreign-console` → `{"handshake": "ok"}`, норма P/06.7 Н1.7). Строка `signer` | `null` (`README.md:102`: ok, личность по подписи) остаётся и покрывает «без сертификата — как было». Смена ожидания только у строки `signer` | `foreign-console` — точечная.
- **Confirmation исполнимо:** «TLS п. 2 у обеих реализаций 4/4 на выгрузке с правкой; строка — alert» — проверяемо стендом одной строкой.
- **Последствия названы верно.** Агенты и ретрансляторы сертификата не шлют (P/02.4 Н1.6 `client_cert`, P/09.1 Н1.11) — для них ничего не меняется. Лист своего центра без роли `domainconsole` — ok, прав не даёт (`X-W2C-Client` не читается) — согласовано с P/08.4 Н1.10 `address`. Ротация не задета — оба центра загружены (P/02.4 Н1.6 `rotation`, `client_cert`).
- **Не противоречит соседней норме о `sig`** (P/02.4 Н1.6: «в рукопожатии ограничивать не требуется — стеки этого не умеют одинаково»): там — алгоритм подписи (проверка после рукопожатия, 403 `bad_chain`), здесь — цепочка/срок/EKU, которые стеки проверяют одинаково. Разные свойства, конфликта нет.
- **Отвергнутые варианты** обоснованы: норма «ok для чужого центра» потребовала бы pyOpenSSL (спецификация многоязычна); отдельный адрес для `domainconsole` — новая норма P/02.4 ради одной строки приёмки.

## Находки

### 1. Существенная — норма не отвечает, действует ли отзыв листа (`revoked`/`crl.pem`) на этой двери

**Место:** `decisions/0083-….md:481–483`.

**Цитата:** «предъявленный проверяет в рукопожатии по своим `ca.pem`, `ca.next.pem` средствами стека — цепочка до центра, срок, EKU `clientAuth`; не прошёл — alert, HTTP нет».

**Что не так.** Список проверок закрыт, и отзыва в нём нет. При этом комплект роли включает `revoked | crl.pem` (договор сертификата роли `kit`, `role-certificate.md:21`), и норма обязывает: «серийники в `revoked` — копируются на каждый сервер; процессы перечитывают по содержимому» (`role-certificate.md:23`; `02.4:513` — «revoke → revoked/crl; скопировать на каждый сервер (процессы перечитывают)»). Сертификат `domainconsole` выпускает собственный центр установки (`w2c-ca.sh issue`), то есть отозванный лист своего центра на этой двери — реальный случай, а не экзотика. Стеки отзыв по умолчанию не проверяют: Go `VerifyClientCertIfGiven` CRL не смотрит, Python `ssl` — только при явно загруженном CRL и `VERIFY_CRL_CHECK_LEAF`. Значит, «средствами стека» отозванный лист пройдёт — но норма комплекта внушает обратное, и реализация, которая «проверяет как все процессы», настроит CRL, а другая нет: расхождение, которое ADR чинит, возникнет в соседней точке.

**Контрпример.** `w2c-ca.sh revoke <server>` для сервера консоли домена; лист в сроке, центр действующий. Go-реализация без CRL: рукопожатие ok, `X-W2C-Client` читается — отозванная консоль пересылает людей. Реализация с CRL: alert. Обе «по норме».

**Источник:** договор сертификата роли `kit`/`revoke`; ср. `peer.md:44` — для чужих кластеров вопрос закрыт прямой строкой («отзыв звонящему не виден; средство — смена центра»).

**Рекомендация:** в правку P/02.4 Н1.6 `client_cert` и договора добавить одну строку: «отзыв листа на двери процесса domain не проверяется; средство — смена центра (rotation)» (или «проверяется по `revoked`» — но тогда нельзя ссылаться на средства стека).

### 2. Мелкая — возобновление сессий на двери процесса domain не оговорено

**Место:** `decisions/0083-….md:481–484, 496–498`; ср. `Platform/common/acceptance/tls/README.md` п. 8 и P/10 Н1.4 `server.role` («сессий не возобновляет»).

**Что не так.** При возобновлении сессии сертификат клиента повторно не проверяется (и в Go, и в Python проверка — только полного рукопожатия). Для двери роли P/10 это закрыто нормой «сессий не возобновляет» и пунктом 8 TLS-приёмки («снять центр → новая проба alert, и с `resume_session` — alert»). Для двери процесса domain после доп. (20) то же свойство становится нужным (снятие центра должно давать alert), но ни норма, ни приёмка про возобновление на этой двери не говорят.

**Рекомендация:** добавить в норму «дверь процесса domain сессий не возобновляет» (или строку приёмки п. 8 для `signer`).

### 3. Мелкая — у двери ретранслятора правило «предъявленный не проверяется» остаётся без строки приёмки

**Место:** `decisions/0083-….md:479–481`; `Platform/common/acceptance/tls/README.md` (поиск по `relay`/«ретранслятор» — пусто).

**Что не так.** После деления класса `signed` по запросу участников без запроса сертификата двое — консоль кластера и ретранслятор (P/09.2 Н1.6). Для консоли кластера правило проверено строкой № 14; для двери ретранслятора строки с `foreign`-клиентом в TLS-приёмке нет (стенд дверь ретранслятора не поднимает). Правило остаётся в классе, но проверяется теперь только на одном из двух носителей.

**Рекомендация:** пометить у P/09.2-07 «проверяется чтением» (как `stand` в договоре) или добавить строку стенда, когда он научится дверь ретранслятора.

## Счёт

- Блокеров: 0. Существенных: 1 (№ 1). Мелких: 2 (№ 2–3).

## Три самые важные

1. **№ 1** — отзыв листа своего центра не назван в закрытом списке проверок: норма комплекта внушает, что `revoked` действует, «средства стека» его не проверяют — реализации разойдутся снова.
2. **№ 2** — возобновление сессий обходит новую проверку; для двери роли закрыто нормой «не возобновляет», для двери domain — нет.
3. **№ 3** — правило «предъявленный не проверяется» у ретранслятора после деления класса не проверяется нигде (у консоли кластера — строка № 14).
