# Модуль 12B — DomainVMS: VMS на домене платформы

[М12A](../М12A_Domain/README.md) построил домен платформы: каталог каталогов над кластерами, держатель со сроком, подписывающий с ключами домена, агент, который уносит домой своё, дверь держателя, общие настройки, тревоги со всех членов, перенос. В нём нет ни камеры, ни записи, ни приёмника, и он собирается на `testsub`. Этот модуль — о том, что на этом домене делает видеопродукт: поток камеры из другого кластера, камера, до которой не дотягивается никто, цепочка «объект — ретранслятор — центр», сценарии между камерами разных кластеров.

Четыре урока. Первый — граница: как VMS даёт домену всё, что домену о ней нужно знать, и не даёт ему ни строки своего кода. Три следующих — работа VMS поверх этой границы.

Полное проектное описание — в [`module-design.md`](module-design.md).

## Тезис

> **Домен знает подсистему по спеке и ни по чему больше.** Всё, что VMS приносит домену, — декларации раздела `domain:` её спек; работа — её собственный воркер у держателя со своими правами на `domain/vms/…`; показ — страница продукта (ADR 0002, ADR 0010). Платформа переносит объявленное, не зная, что в нём, и запечатывает секреты, не зная, зачем они (ADR 0024).

| | Платформа (М12A) | VMS (здесь) |
|---|---|---|
| Знает о другой стороне | только раздел `domain:` загруженных спек (`w2cplatform/domain/declared.py`) | имена своих строк — из той же спеки (`vms/domainpart/keys.py`) |
| Пишет у держателя | свои строки: члены, гранты, правки, топология, общие настройки, копия | `domain/vms/…`: книги для каждого члена и решения для всего домена |
| Ключи домена | у подписывающего, единственного процесса с ключами (ADR 0032) | нет; токены вида `stream` и `ask` просит у подписывающего через его сокет |
| Несёт книги членам | агент, через дверь держателя, по объявлению `domain.books`, не читая | — |
| Хранит и переносит | копия держателя: свои строки и всё объявленное в `domain.kept` | решает, что держать (`crossings`, `roads`) |
| Числа и формы | дверь держателя отдаёт только объявленное | дверь своего воркера: `/metrics`, `/catalog` |

## Демонстрация

Камера на сотовом канале, за NAT, пишет на свою карту; её пишет серверная в другом здании, а смотрят из центра, до которого тоже никто не дотягивается снизу вверх. Потом:

```bash
# stop the domain holder's services for six hours
```

Серверная продолжает писать камеру: регистратор никогда не спрашивал домен, он разрешает её по книге, которую агент принёс последней, и консоль показывает возраст этой книги. Камера толкает на приёмник серверной по ключу потока, который у неё уже есть, — до конца его суток. Зритель в центре открывает камеру — она начинает толкать через секунду, потому что желание дошло до неё долгим опросом, а не проходом агента. Домен возвращается — воркер VMS у держателя пересчитывает книги, агенты уносят их домой, и ни одна строка в хранилище камеры не написана никем, кроме неё самой.

## Что проверяется без железа

Почти всё: книги — это логика и строки, приёмник и передатчик — библиотеки, которые водят тесты. `Source/tests/domainvms/` — 136 тестов: уроки 2–4, граница VMS на домене и арифметика урока 8 М12A (`test_lesson8_cloud.py`), — поверх тех же кластеров М11 и тех же поддельных членов, что тесты домена платформы (`tests/domain/conftest.py`):

```bash
python3 tests/domainvms/run.py      # from Source/
python3 tests/domain/run.py         # the platform's domain; its testsub half, tests/test_domain_platform.py, runs in tests/run.py
```

В них: книга источников, перенесённая и разрешённая при выключенном домене (`test_lesson13_crossing.py`); камера с закрытой навсегда дверью, которая толкает, отвечает с карты и выполняет запросы сценариев (`test_lesson16_nobody_reaches.py`, `test_lesson16_card.py`, `test_lesson16_break.py`); два сервера одним потоком (`test_two_servers.py`); цепочка с ретранслятором и звездой (`test_lesson17_chain.py`); секреты книг, запечатанные во всех хранилищах трёх кластеров, и семьи ключей (`test_domain_secrets_vms.py`); учётки RTSP у держателя и их книга (`test_stream_clients.py`), а дверь RTSP шлюза — в `tests/test_rtsp_door.py`.

**Чего в курсе нет, и это сказано в уроках.** Процесса приёмника и процесса передатчика ретранслятора нет — `Ingest` и `Forwarder` живут в тестах, и `publish_polled` и `Forwarder.publish` периодически не зовёт никто (урок 3, шаг 6а). Регистратор курса не разрешает источник `ref:` по книге: `resolve` есть, шва в `RecWorker` нет (урок 2, шаг 3).

**Нужен стенд.** Настоящий приёмник на SRT, долгий опрос по HTTP через NAT сотового оператора, карта на SD с пропаданием питания, ретранслятор, которому мобильный оператор не открывает порт, — дорожка 2.
