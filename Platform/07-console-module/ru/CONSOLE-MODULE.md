# Платформенный модуль консоли: контракт

Текст производный от `CONSOLE-MODULE.md`, руками не правится: источник — английский [`CONSOLE-MODULE.md`](../CONSOLE-MODULE.md), правка идёт в него, русский пересобирается переводом.


Контракт публичный. Его читают курс (`Source/`) и продукт, по нему пишется страница любой подсистемы.

## 1. Что это

Платформа отдаёт один модуль, `GET /platform/console.js`. Модуль строит из манифеста и платформенных дверей всё, что у консоли общее для любой подсистемы:

- дерево единиц;
- вход и сессию;
- серверы;
- домен;
- права;
- журнал.

Страница подсистемы — это **оболочка**. Лежит она рядом с файлом манифеста подсистемы как `<sub>.shell.html` (у VMS `vms.shell.html` рядом с `vms.subsystem.yaml`): страницу отдаёт только корень консоли (`CONSOLE_ROOT`) для своей корневой подсистемы, если файл есть, иначе платформенную страницу; подсистемы из `/mounts` своих страниц не отдают, их показывает модуль на странице корня; исключение — манифест со словом `console.shell`: такая подсистема отдаёт свою оболочку на `/<sub>/` отдельной страницей, а файлы перечня `console.files` — на `/<sub>/<file>` (P/06.5 N1.1 `mounted`, N2 «Статические файлы»). Никакой опции `Page` в коде нет, страница это файл. Она подключает модуль, монтирует его разделы, добавляет свои и подписывается на выбор объекта. Платформенная страница `console.html` — та же оболочка в минимальном виде: модуль и больше ничего.

```
<script src="/platform/console.js?v=1"></script>
<div id="app"></div>
<script>PlatformConsole.mount(document.getElementById("app"))</script>
```

## 2. Чего модуль НЕ делает

- **Не называет подсистем.** В исходнике модуля нет ни имён подсистем, ни их предметных слов. Словарь запрещённых слов тот же, что у теста границы (§2.7 записки о границе): `vms`, `cam`, `camera`, `"\u043a\u0430\u043c\u0435\u0440"`, `rec`, `det`, `auto`, `live`, `archive`, `"\u0430\u0440\u0445\u0438\u0432"`, `footage`, `video`, `"\u0432\u0438\u0434\u0435\u043e"`, `rtsp`, `device`, `recorder`, `volume`, `whep`, `timeline`. Подписи для единиц и полей приходят из манифеста данными (§6).

  **`live` — правило по токену.** `live` как состояние — платформенное слово: живой пульс, `live` и `silent` в `/servers` и `/events`, гейджи `*_live`. Запрещено оно только как имя подсистемы живого видео: `live_url`, `LIVE_NAME` и любой `LIVE_…`, `/live/`, `livecontroller`, `liveworker`. Тест проверяет токены, а не подстроку: `live_url` в модуле не пройдёт, `state === "live"` пройдёт.
- **Не знает других маршрутов.** Модуль ходит только в двери закрытого списка [P/07 N1.4](spec/07-console-module.norms.md) (`reads`, `writes`, `never`, `order`; раздел домена — поздний слой P/07 N1.6). Любой другой маршрут — дело оболочки.
- **Не грузит ничего по адресам, которые ему не принадлежат.** Адрес двери держателя единицы (`/where` → `door`) модуль только отдаёт оболочке через `where()`. Сам он туда не ходит: ни таймлайна, ни кусков, ни WHEP.
- **Не держит свою сессию для оболочки.** Сессия одна, cookie платформы (§5). Оболочка свою не заводит.
- **Не перехватывает чужие разделы.** Карточки и разделы, которые добавила оболочка, модуль только размещает и не трогает их DOM.

## 3. Подключение и жизненный цикл

`PlatformConsole.mount(root, opts) → console` — модуль рисует каркас в `root`:
- полоса разделов;
- дерево;
- инспектор;
- строка состояния;
- окно входа.

Возвращает объект `console`, через который оболочка с ним разговаривает. Объект модуля один — `PlatformConsole`
`{version, features, mount}`; `pc`, `console` в примерах — имя переменной страницы (P/07 N1.5 `module`).

`console.ready` — обещание: разрешается объектом страницы после `mount` и первого прочитанного `/manifest`; ответ 401 —
ждёт входа и разрешается после него (`await pc.ready`; P/07 N1.5 `ready`).

Параметры `opts`, все необязательные:

| Параметр | Что |
|---|---|
| `sections` | какие платформенные разделы показывать и в каком порядке: `["units", "access", "journal"]` по умолчанию. Серверы и домен не разделы ленты, а вторая раскладка панели единиц, «По серверам», где домен — корень |
| `subsystems` | какие манифесты дают единицы в дерево: по умолчанию все из `/mounts`; `[]` — ни одной; неразмещённые раздел `unplaceable` читает у всех подсистем каталога, только на чтение (P/07 N1.4). Предел опубликованного канонического модуля [console.js](../module/console.js): он этого правила не исполняет (`[]` и неразмещённые — только по `opts.subsystems`), открытый долг закрывает владелец опубликованных байтов общего модуля по P/07 N5 и «Решает реализация» п. 6; линии генерации сохраняют опубликованные байты. Подсистема, чей манифест говорит `about` (§7), вкладывается узлами под единицы родителя; без `about` — своё дерево. Оболочка может сузить список |
| `lang` | Точное `"ru"` выбирает русские подписи платформы и формат времён/дат интерфейса; любое другое значение, включая отсутствие, выбирает английский. Слова материализуются из [data/localization.tsv](../data/localization.tsv) в существующую форму WORDS того же модуля. Язык браузера не выбирает язык; предметные подписи и значения протокола/данных сохраняются. |
| `poll_s` | период опроса страницы, 5 с по умолчанию; модуль опрашивает каждые `poll_s` (P/07 N1.4 `order`), своего периода в памяти браузера у него нет; правку строки он узнаёт раньше — по ленте `GET /changes` (P/07 N1.4 `changes`) и перечитывает данные сразу |

`console.version` — версия контракта, целое число, сейчас `1`. Несовместимое изменение — новая версия. Оболочка проверяет версию до вызовов (платформенная страница `console.html` — до `mount`; P/07 N1.5 `version`). `PlatformConsole.features` — список строк возможностей сверх первых вызовов версии 1: `"select.tab"`, `"card.closed"`, `"api.if-match"`; строки нет — нет возможности; версия от новых вызовов не меняется (P/07 N1.5 `features`). Модуль отдаётся как `/platform/console.js?v=<version>`; старые версии не отдаются: обратная совместимость не держится, пока система работает только на одной машине.

## 4. Объекты и выбор

Всё, что выбирается в дереве, — объект со ссылкой `ref`, строкой:

| `ref` | Объект |
|---|---|
| `unit:<sub>/<id>` | единица подсистемы `<sub>` (`<sub>` — имя манифеста) |
| `server:<s>` | сервер |
| `worker:<sub>/<w>` | воркер подсистемы |
| `member:<m>` | член домена |
| `domain` | домен целиком |
| `person:<name>` | человек домена |
| `<prefix>:<…>` | объект оболочки: префикс выбирает оболочка, модуль его только хранит и отдаёт |

API выбора:

- `console.select(ref, {tab?})` — выбрать: модуль подсвечивает узел дерева и открывает карточку; `tab` — id вкладки, данный `addTab` (`"general"` — карточка модуля); такой вкладки нет — карточка без смены вкладки (`features`: `"select.tab"`).
- `console.selected()` → `ref` или `null`.
- `console.on("select", (ref, obj) => …)` — после каждого выбора. `obj` — то, что модуль знает об объекте: строка единицы из `/<rows>`, строка сервера из `/servers`, строка члена домена.
- `console.on("refresh", data => …)` — после каждого кластерного опроса с подтверждённым нынешним чтением корневого `/servers`: `{units, servers, domain}` с точной корневой картой `d.servers`. Отказ чтения корня пропускает только эту кластерную публикацию; чтения, локальная перерисовка и следующий опрос продолжаются. Подтверждённая пустая, неизменённая и восстановленная после отказа та же карта дают обычное событие, без режима только по изменениям и воспроизведения пропущенного. Holder-only `{domain}`, access `{access}` (P/07 N1.6), остальные события и `ready` прежние.
- `console.on("logout", …)`.
- `console.on("session", ({user}) => …)` — при каждом чтении `/session` с известным `user`: при монтировании и после входа окном модуля, обычного и аварийного; подписка после чтения получает последнее значение сразу, `user` неизвестен — события нет; другой `user` — страница сбрасывает своё (`features`: `"session"`).
- `console.on("card.closed", ({ref}) => …)` — карточку убрали: выбор другого объекта, снятие выбора, уход со страницы; у карточки оболочки `ref` — её имя как есть (`streamaccounts:local`); перерисовка опроса не в счёт (`features`: `"card.closed"`).
- `console.dialog(title, fields, ok)` — диалог модуля для действий страницы; поле может быть `type: "file"`: значение — текст выбранного файла, модуль его не хранит. Возвращает обещание (`Promise`): по нажатию кнопки `ok` — значения полей `{<name>: <value>}`, по отмене — `null`; `ok` — надпись этой кнопки (P/07 N1.5 `adds`).
- `console.confirm(q, more)` — вопрос человеку с пояснением `more`; возвращает сразу его ответ `true` / `false` (значение, не обещание; P/07 N1.5 `adds`).

## 5. Сессия и запросы

- Вход — модуль: окно входа, `login_url` из `/session`, `POST /session {token}`, break-glass, выход. После входа модуль читает параметр `return` адреса страницы: ровно `/<sub>/` подсистемы своего каталога — переход туда, иное значение — на `/` (P/07 N1.5 `return`; защита от открытого перенаправления). Cookie сессии ставит платформа, она общая для всех дверей кластера (§6.1 записки о границе: тот же токен на двери воркера).
- **Виды команд.** `command` — «команда выполнена» / «a command was performed», `command.failed` — «команда не выполнена» / «a command was not performed». Слово и заметка модульные, `display.kinds` манифеста их не называет. Заметка: `action` · исход по `outcome` — `performed` «выполнена», `refused: <why>` «отказ: <why>», `expired` «истекла: никто не выполнил вовремя», `unknown` «неизвестно, выполнена ли» · «кто: `<by>`»; без `outcome` у `command.failed` — его `why` или `error`. Если событие несёт `late: true` (ответ устройства пришёл после срока, а просьба уже была отвечена «не ответило»), к исходу добавляется «поздно: после срока» / «late: after the deadline»: «выполнена поздно: после срока», «отказ: <why> поздно: после срока» и т. д.; без исхода — только «поздно: после срока». Ключей `display` не нужно. Поля платформы на верхнем уровне события: `outcome`, `action`, `by`, `late`, у `refused` и `unknown` — `error`. Ответ цели целиком под `reply` (словарь). Модуль показывает его как есть — «ключ: значение» через запятую, без слов — после исхода: `action` · исход · ответ цели · «кто: `<by>`». У `refused` почему берётся из `error` («отказ: `<error>`»), у `unknown` — «неизвестно, выполнена ли: `<error>`», если `error` есть.
- **Отладочный вход.** `/session` может отдать `{user, debug: true}`: дверь впустила человека без токена, потому что запрос пришёл с loopback-адреса соединения, а у процесса задан `W2C_DEBUG_PERSON` (только стенд). Права — его настоящие гранты. Модуль рисует в шапке у имени красную метку «отладка: вход без пароля» / «debug: no sign-in», пока `debug` истинно; «Выйти» в этом режиме не показывается.
- `console.api(method, path, body, opts?)` — запрос с сессией (P/07 N1.5 `api`). Вызов — одно логическое действие: его `POST` и `PUT` несут новый `Idempotency-Key`, повторы этого действия — тот же ключ и то же тело; новый вызов — новый ключ, даже с теми же байтами. Потерянный ответ (сеть, таймаут 20 с, 5xx, 409 «in flight») повторяется сам только у двери с памятью повторов владельца — `POST /<rows>`, `/<sub>/<rows>` (P/06.1); задержка — заголовок `Retry-After` ответа, без него 2, 3, 5 с; после третьего повтора — отказ `{status, body, retry}`. `PUT`, `DELETE`, таблицы и `POST` дверей без памяти (`/marks`, `/drain`, вывод сервера) сами не повторяются: исход неизвестен — модуль сначала перечитывает, потом говорит об этом. Окончательный ответ закрывает действие. Оболочка шлёт все свои записи через него, чтобы правило было одно. Четвёртый аргумент `opts` — только `{ifMatch: <revision, an integer ≥ 1>}`: модуль шлёт `If-Match` у `PUT` и `DELETE` строки единицы `/<rows>/<id>`; иной метод или путь, лишнее поле, нецелое значение — отказ вызова до запроса; ответ 412 — отказ `{status: 412, body, retry: false}` с телом как есть (возможность `"api.if-match"`). `opts.ifMatch` — целое `revision`, заголовок `If-Match` у дверей, которые его читают: строки единиц и таблиц, настройки главы 6.6 (P/07 N1.5 `api`). Форма единицы шлёт его всегда и показывает 412 экраном: ввод цел, рядом значения строки сейчас и кнопка «Перечитать» (P/07 N1.5 `forms`).
- Форма единицы и форма создания показывают отказ 400, 409, 412 у поля по `field` тела (JSON Pointer, P/06.1 N2 «Отказ: `error` и `field`»; P/07 N1.5 `forms`): контрол получает `aria-invalid="true"`, рядом — `.pc-field-err`; элемента нет или `field` нет — текст в общем `.pc-err`. Опубликованный модуль это делает (P/07 «Решает реализация» п. 4 — закрыт, ограниченная фикстура формы единицы в строке N5 P/07-R282).
- Подсистема, чей манифест несёт `unit.writes_via`, строки людям не даёт писать: модуль не показывает формы создания, а у формы единицы нет «сохранить» и «удалить» — поля только для чтения; таблица со словом `tables.<t>.writes_via` — без формы записи строки (P/07 N1.5 `writes_via`; P/06.1 N1.1a). Предел свидетеля: опубликованный модуль слова не знает, открытый долг из строки P/07-R285 в N5 закрывает владелец опубликованных байтов общего модуля; свидетельств закрытия нет; линии генерации сохраняют эти байты.
- `console.kindWord(e)` и `console.eventNote(e)` — слово и описание события: для платформенных видов (`server.*`, `worker.*`) из словаря модуля, для видов подсистемы из `display.kinds` её манифеста. Оболочка события платформы сама не называет.
- `console.where(ref)` → `{worker, server, door, reason}` — где единица и дверь её держателя: `door` — объект `{url, token, expires, routes}` или `null`, когда в ответе `/where` поля `door` нет (P/07 N1.5 `where`). Оболочка сама идёт на `door` за байтами, с той же cookie.
- 401 из любого запроса, модульного или оболочки через `api()`, открывает окно входа.
- **Права.** `/session` отдаёт гранты вызывающего: `none` / `view` / `edit` / `admin`, подсистему `sub`, роль `role` и скоупы (`unit:<sub>/<id>`, `labels:<…>`, `folder:<id>`, `*`), у администратора домена — `admin: true`. Модуль сам прячет правку и действия, на которые прав нет, и отдаёт `console.may(cap, ref, sub?)` → `true | false`, чтобы оболочка делала то же для своих вкладок. Действия: `view`, `edit`, `admin`. Правило одно и живёт в модуле (P/07 N1.5 `may`; договор права `Platform/common/contracts/may.md` шаги 6–7); оболочка его не повторяет: строка с рангом не ниже действия и скоупом, покрывающим единицу (`*`; `unit:<sub>/<id>` — сама единица или её about-единица; `labels:L` — все метки L у about-единицы, если она есть, иначе у самой); вне единицы — только `*`, `view` — любая строка. Аварийная сессия (`via: break-glass`, грантов `[]`) — да; без грантов да только у открытой консоли (`open: true`); закрытая или неизвестная сессия (`/session` не ответила) — нет. Сервер всё равно проверяет каждый запрос, а `may` только не показывает человеку то, в чём ему откажут.

## 6. Слова из манифеста: `display`

Модуль не знает, что единица — камера. Манифест может нести слова для показа:

```yaml
display:
  unit: камера
  units: камеры
  field_help:
    labels: сети, в которых виден адрес камеры (vlan:cctv-a)
    source: адрес устройства
```

Ещё ключи (все — слова и один флаг, без логики):

```yaml
display:
  section: Камеры            # подпись первого раздела ленты
  tree:
    group_title: Папки       # раскладка по group_by: заголовок и подсказка
    group_hint: по папкам камер
    filter: имя, адрес, метка  # подсказка фильтра
    no_group: без папки      # строка единиц без группы
    children: false          # не вкладывать в дереве единицы подсистем, чей about указывает на эту
    contents_title: Состав папки   # подписи карточки группы
    group_word: Папка
    no_group_suffix: без папки
    pick_note: выберите камеру в дереве   # пояснение обзора раздела, когда ничего не выбрано
    new_root: ＋ Папка           # и «Создать папку» в меню «без группы»
    new_sub: ＋ Подпапка         # и «Создать подпапку» в меню группы
    add_here: Добавить камеру сюда
    new_group_note: Папка создана — добавьте в неё камеру, иначе она не сохранится   # без него модуль пишет общее со словом из display.unit
  units_count: камер         # множественное в родительном падеже для счётчиков: «12 камер», «Камер внутри»
```

Создание единицы — кнопкой «＋ <unit>» в шапке обзора раздела и в шапке группы (из группы новая единица сразу в ней). Карточка может положить `<button class="pc-hdbtn">` сразу под свой `<h1>`, модуль переносит такие кнопки в шапку рядом с `addAction`; путь карточки — `<span class="pc-crumbs" data-crumbs='[[word, ref]]'>` внутри `<h1>`, модуль рисует его крошками. Членов домена модуль вкладывает в дерево сам по `topology.via`. Обзор «По серверам» — блок «Кластер»: счётчики, политика юнитов на сервере, версия раскладки из `/schema`.

Ключи карточки единицы (слова, раскладка и один флаг, без логики):

```yaml
display:
  general: Камера                    # подпись вкладки общей формы
  fields: {source: Адрес, live: Живой поток}   # подписи полей
  options: {live: {always: всегда, on-demand: по требованию}}   # слова значений; НАБОР значений — из schema.enum поля манифеста, не отсюда
  form:                              # блоки общей формы по порядку; поле вне блоков не показывается; без form — один блок со всеми полями
    - {title: Устройство, fields: [name, source, cred_username, cred_secret], state: true}   # state — значок состояния единицы
    - {title: Размещение, placement: true, note: "…"}   # placement — «Воркер · сервер», состояние, причина из /where, «Удалить»; note — пояснение под блоком
    - {title: Состояние, status: [{field: stream, since: stream_since, title: Поток}]}   # status — поля статуса воркера только для чтения, «с какого момента» из since; слова значений из options
  events: false                      # модуль не добавляет свою вкладку «События» (журнал единицы и отметки): их показывает страница
  tree: {not_in: "…", add_to: "Добавить в папку…", no_others: "…", new_group: "＋ Новая папка", remove: "…"}   # слова блока групп в форме; без них — общие
```

Карточке страницы (`addCard`) и её разделу (`addSection`) модуль даёт собственный вложенный контейнер: опоздавшая отрисовка после запроса страницы попадает в отсоединённый узел и не стирает карточку, выбранную позже.

Поведение карточки: карточка пишет `<h1>` и `nav.pc-tabs`, модуль переносит их в шапку (путь, звезда, «на весь экран», вкладки); разделы с `<h2>` модуль делает блоками `.card`; форму сохраняет подвал; логическое поле существующей единицы пишется сразу, как переключатель.

И два ключа:

```yaml
display:
  kinds:                 # виды строк журнала и событий единицы, словами
    camera.clock.step_forward: часы камеры скакнули вперёд
  tree:
    group_by: folders    # группировать дерево по полю-списку; модуль не знает, что это папки
```

Модуль берёт предметные подписи, подсказки полей и подписи видов из `display`, не переводя данные манифеста. При отсутствии подписей единицы платформенные умолчания используют ключи `unit` и `units` [localization.tsv](../data/localization.tsv): `unit`/`units` в английском по умолчанию, русские подписи таблицы только при явном `lang: "ru"`. Подпись пустого списка — `noRows` (`No rows` по-английски). Имя поля или вид без объявленной подписи остаётся как есть. `display` — только словарь: в нём нет логики, условий и маршрутов. Язык UI не меняет ключи, enum values, ошибки, исходы, данные журнала или умолчания протокола.

Таблица — единственный редактируемый источник слов платформы; WORDS опубликованного модуля строится из неё детерминированно. `n.<name>` привязан к существующему словарю `n`, `kinds.<event-kind>` — к словарю `kinds` с буквальным хвостом вида события, не произвольным путём по точкам. Русские значения — обычные строки JavaScript, записанные совместимыми с JSON Unicode-экранированиями. Загрузки таблицы locale или отдельного сервиса слов нет. Даты интерфейса используют явные `en-US`/`ru-RU` выбранного языка экземпляра с прежними параметрами, часовым поясом и значениями протокольного времени по P/07 N1.5. Синхронная выдача `/platform/console.js?v=1` и версия публичного договора не меняются.

## 7. Разделы модуля

| Раздел | Что в нём | Маршруты |
|---|---|---|
| `units` | дерево единиц по манифестам из `opts.subsystems`; подсистемы с `about` — узлами под единицами родителя (ниже); группировка по `display.tree.group_by`; избранное по `ref` (localStorage); карточка единицы: поля из манифеста, правка (секреты пустые, уходят только изменённые поля), вкл/выкл, удаление, где и почему (`/where`), события единицы и отметка | `/manifest`, `/<rows>`, `/where`, `/events`, `/marks` |
| `servers` (раскладка «По серверам» панели единиц) | дерево «домен → сервер → воркеры»; карточка сервера: ресурс, воркеры, метки (`platform/servers/<s>`), `servers.show` из манифеста (§8), вывод из эксплуатации, списание; карточка воркера: слот, аренда, зависание, конфликт имени, единицы воркера | `/servers`, `/servers/<s>/labels`, `/servers/<s>/decommission`, `/drain`, `/policy` |
| `domain` (корень раскладки «По серверам») | где держатель (`GET /api/held`), члены, ключи, топология, перенос («Перенести домен сюда» — диалог: файл восстановления текстом и «старый держатель украден» нет/да → `POST /domain/move {recovery[, stolen: true]}`; без файла запрос не уходит), тревоги (в карточке одна строка на вид и `of`: последняя, «×N (с …)», список членов, иначе `session.debug_open` от каждой двери на каждом старте хоронит настоящие), keys-view | `/domain/*` |
| `access` | люди, гранты, break-glass | `/domain/users`, `/domain/grants`, `/domain/break-glass` |
| `journal` | события всех подсистем, закрытые платформенные виды событий из `W.kinds`; остальные виды строк — из манифеста подсистемы события (`display.kinds`), без подмены закрытого платформенного вида | `/events` |

**`GET /api/held` в разделе `domain`** (поздний слой, P/07 N1.6) — единственная дверь процессов, которую читает модуль: подписанная публичная запись держателя `{cluster, holder, term, keys, backup: {term, rev}}` на консоли кластера (где держатель; содержимого бэкапа в ней нет). `backup` это указатель последней копии у этого члена, `{term, rev}`, сравниваемый сначала по term, при равном term — по rev (P/08.8, the largest (term, rev)); пара держателя и список берутся из `GET /domain`, `term.backup` и `term.backup_holders` (P/08.8 N1.3); карточка держателя (`term`) несёт `backup: {term, rev}` последней записанной копии рядом с `backup_holders` и `copies: {<member>: {term, rev}}` (указатели копий членов из опубликованных ими `domain/backup-taken`, бывших держателей копии тоже), так что сравнивать есть где: пометки ставятся на карточке домена, а `/api/held` члена знает только свой указатель; модуль показывает у члена «старая копия», когда его пара отстаёт от пары держателя, и «держатель её больше не обновляет», когда члена нет в `backup_holders`; старые копии у бывших держателей не бросаются (запасной путь переноса), числа показываются как есть.

### Что ещё модуль делает сам

1. **Создание единицы.** Кнопкой «＋ <unit>» в шапке обзора раздела и в шапке группы (из группы — сразу в ней); общая форма по типам для новой единицы с умолчаниями из манифеста, `POST /<rows>`. Номер numbered-подсистемы даёт сервер, новая единица выбирается. Немедленного создания с адресом-заглушкой нет: `source` обязателен и уникален, вторая заглушка была бы отказана.
2. **Пользователь, выход, аварийный вход.** Имя вошедшего и «Выйти» (`DELETE /session`) в меню шапки. В окне входа — аварийный вход: `POST /session/break-glass {who, why, password}`.
3. **«Повторить» у тоста.** Запись двери с памятью повторов, исчерпавшая повторы, показывается тостом с кнопкой. Кнопка — ещё один повтор того же действия: тот же метод, путь, тело и ключ (P/07 N1.5 `api`).
4. **Версия раскладки хранилища.** `/schema` показывается в блоке «Кластер»; подъём (`PUT /schema`) в контракт не входит.
5. **Неразмещённые.** Карточка «Не размещены» из `/unplaceable`: почему каждая единица без места и какие метки у серверов.
6. **Таблица.** Не делается: табличного вида с массовой правкой у модуля нет. Если владелец захочет, это новая функция модуля: вторая раскладка дерева с колонками из `display.tree.columns`, сортировкой и массовой правкой полей манифеста через общую форму.
7. **Папки.** Подсистема с `display.tree.folders: true` получает дерево из папок кластера (P/06.8; P/07 N1.5 `tree`). Узел папки — объект с `ref` `folder:<id>` и своей карточкой: имя, родитель, состав по порядку. Действия:
   - переименовать — одна собственная запись модуля `PUT /folders/<id> {name}` с `If-Match`, содержащим индекс хранилища в кавычках (P/06.8 N2): поле единиц не трогается;
   - создать папку и подпапку — `POST /folders`; пустая папка живёт на сервере, а не в браузере;
   - добавить единицу и снять её — собственная запись модуля `PUT /folders/<id> {members}` с тем же `If-Match` индексом в кавычках, состав целиком; новая единица встаёт в конец;
   - удалить — `DELETE /folders/<id>`: единицы остаются, подпапки исчезают сразу;
   - «без группы» — особый узел для единиц вне папок.

   Модуль этого ещё не делает: долг продукта «Сборке». Ниже — дерево подсистем без папок.

   **Группы.** Узел группы по `display.tree.group_by` — объект с `ref` `group:<sub>/<field>/<value>` и своей карточкой: значение, число единиц, список. Действия:
   - переименовать — перезаписать значение в поле-списке у всех единиц группы через `console.api`, одним ключом на операцию, с отчётом, что не удалось;
   - создать — значение появляется, когда его получает первая единица, а пустая группа — это только фильтр;
   - «без группы» — особый узел.

   Пустая группа («＋ Папка», «＋ Подпапка») живёт в браузере, пока её не получит единица; меню группы: создать подгруппу, переименовать, добавить единицу сюда; у «без группы» — создать группу. Всё это модуль, обобщённо для групп. В меню любой единицы модуль даёт «Удалить» по `may(admin)`. Значения групп без единиц из общих настроек домена модуль читает сам (`/domain/shared/<sub>`). Оболочка добавляет через `addCard`/`addMenu`/`addTab` только своё.

8. **Вид `session.debug_open`.** Платформа пишет его в журнал при старте процесса с заданным `W2C_DEBUG_PERSON`, с полем `person`. Слово вида модульное: «отладочный вход без пароля включён» / «debug sign-in without a password is on»; заметка — «как `<person>`».

Мелочи: тема светлая/тёмная вручную — модуль; выключенная вкладка «Детекторы», меню камеры («Смотреть видео», «Запись») и общие настройки домена — оболочка.

### Зависимые подсистемы: `about`

Шаг 2 записки о границе вводит в манифест `about: {sub: vms, field: cam}`: единицы этой подсистемы — про единицу подсистемы `vms`, связь по полю `cam`. Модуль использует это сам: записи, детекторы, сценарии одной камеры показываются узлами под этой камерой, словами из `display` своего манифеста, с карточкой по своему манифесту. Оболочке не нужно знать, что записи живут под камерами: это знание одно и лежит в манифесте. `addTreeNodes` (§9) остаётся для того, что не единица ни одной подсистемы: например, тома, которые хранятся в таблице, а не в единицах.

## 8. Таблицы подсистемы на карточке сервера: `servers.show`

Модуль рисует их всегда: это карточка сервера для подсистемы без своей страницы (платформенная страница, `testsub`). Страница продукта может закрыть то же место своим блоком (`addBlock`) с кнопками и состоянием; тогда таблица `servers.show` для этой таблицы не рисуется. Страница говорит об этом ключом `covers: "<sub>/<table>"` у `addBlock` (`addBlock("server", {id, covers: "rec/volumes", render})`). Модуль рисует таблицу блоком `.card` с заголовком `title`, строки `GET <base>/<table>` с `row[by] === server name`, колонки из `columns` с подписями из `display.fields` подсистемы (иначе имя поля; `columns` проверяются против полей таблицы в манифесте), секреты маской, пусто — «Нет строк».

```yaml
servers:
  show:
    - {table: volumes, by: server, title: тома, columns: [name, kind, quota_bytes]}
```

Модуль читает таблицу `<sub>/<table>` через `/<sub>/<table>` и показывает строки, у которых `by` равно имени сервера. Что такое том, он не знает: показывает колонки из `columns` и подпись из `title`.

## 9. Что добавляет оболочка

Модуль — библиотека платформы, оболочка — страница продукта, которая её вызывает. Вызовы ниже — это оболочка, обращающаяся к библиотеке внутри своей страницы, а не платформа, вызывающая подсистему; хуками в смысле записки о границе (§1.1) они не являются.

- `console.addSection({id, label, icon, after, off, render(host)})` — свой раздел в ленте: в продукте «Сценарии». `after` — id раздела, за которым он стоит; `off` — раздел виден, но выключен, с причиной в подсказке. Ни мышь, ни клавиатура не входят в раздел и не вызывают `render`; включённые соседи работают.
- `console.addBlock(kind, {id, render(host, ref, obj)})` (`kind` — `server`, `member`, `domain`) — свой блок на общей вкладке карточки объекта вида `kind`, после блоков модуля, в порядке добавления (в продукте: «Архивы сервера» и выключенный «Видеоускоритель» на обзоре сервера).
- `console.icon(name)` — разметка значка по имени (значка модуля или добавленного через `addIcons`), чтобы собственные строки страницы выглядели как строки модуля.
- `console.addAction(kind, (ref, obj) => [{label, run}])` — кнопки страницы в шапке карточки объекта вида `kind`, перед звездой (в продукте: «＋ Камеру в архив» у сервера).
- Подзаголовок карточки: `<p class="pc-hdsub">` сразу после `<h1>` модуль переносит в шапку под заголовок (модуль так пишет «Держатель домена — …»; у члена домена — вид сервера из `title` в `addDecor`).
- Семьи ключей домена на вкладке «Ключи» — НЕ вызов. Свои семьи модуль подписывает сам (члены, публикации членов, сети держателя, топология, правки в ожидании, итоги правок, вид домена); семьи подсистемы это декларация её части домена в манифесте (раздел `domain:` — что подсистема несёт в `domain/<sub>/…`, с словами в `display`), модуль читает их из `/manifest`: состав из `manifest.domain.keys` — `[{id, keys?, prefix?}]`, слова из `display.keys` — `{id: {title, about, absent?}}`, слитые по `id`; ключ вне семей — «Прочие ключи». Поле `domain` манифеста в `/manifest` и `/mounts` обеих дверей — `{keys, shared, edit, view}`: `edit` — поля единицы, которые держатель пропускает в правку (остальные отвергает 400), модуль по нему строит карточку единицы на держателе; `view` — поля вида, по которым подписывается список единиц по подсистемам. До появления раздела `domain:` в манифесте оболочка передаёт семьи временным параметром `opts`, и этот параметр удаляется вместе с его тестами, когда раздел появится.
- `console.manifest(name)` — копия манифеста подсистемы из `/manifest` для кода страницы (например, таблица мест из `manifest.places`); страница манифест не разбирает сама и не ходит за ним отдельно.
- `addGroupValues` нет: значения групп без единиц модуль читает сам из `/domain/shared/<sub>` по `domain.shared` манифеста.
- `console.addNote(kind, (ref, row) => text | [text])` — слова страницы о единице, которых манифест сказать не может, потому что за ними порог или логика (в продукте: «открытие не завершается дольше 15 с», «сбой устройства»); показываются предупреждениями под «Размещением».
- `console.addEventNote((e) => text)` — описание событий подсистемы словами (суммы, причины) везде, где модуль показывает события, включая «Журнал». Слово вида остаётся из `display.kinds`, события платформы модуль описывает сам; страница не зовёт модуль повторно для того же события (у оболочки защита от повторного входа).
- `console.addIcons({name: svg})` — значки страницы по имени: внутренность svg 16×16, это код страницы, не данные. Свои значки модуль рисует сам (разделы, сервер, воркер, домен, папка, человек, фильтр, поиск); имя, которого никто не нарисовал, показывается точкой. `addDecor().icon` и `addSection({icon})` называют значки по этим именам.
- `console.addTab(kind, {id, label, render(host, ref, obj), busy})` — своя вкладка на карточке объекта вида `kind` (`unit`, `server`, `worker`, `member`, `domain`). В продукте это:
  - вкладки «Видео» и «Архив» у `unit:/…`;
  - «Тома» у `server:…`, если их не покрыл `servers.show`.
  `busy()` — необязательная функция вкладки: пока она возвращает `true`, модуль не перерисовывает карточку по опросу (в продукте: пока идёт просмотр и согласование живого потока). Модуль не знает, что именно занято; это обычный вызов оболочки в библиотеку.
- `console.repaintTree()` — дерево заново по узлам оболочки: страница узнала новое, а данные модуля не сменились, опрос дерево не тронет; прокрутка цела, при нажатой кнопке ждёт отпускания (`features`: `"tree.repaint"`).
- `console.addTreeNodes(kind, (ref, obj) => [{ref, label, icon, count, kids, badge, tags, dot, title, off, open, after, replaces}])` (`count` — счётчик справа; `kids` — вложенные узлы той же формы; `badge` — значок; `tags: [text | {text, title}]`; `dot: [colour, word]`; `title` — подсказка; `off` — выключен; `open` — раскрыт, пока не свернули; `after` — ставится после членов за ретранслятором; `replaces` — узел стоит на месте строки члена домена, так сервер-камера становится своей камерой) — дочерние узлы своих объектов, которые не единицы ни одной подсистемы (единицы зависимых подсистем модуль вкладывает сам по `about`, §7): например, тома под сервером. Их `ref` с префиксом оболочки. Выбор такого узла приходит в `on("select")`, карточку рисует оболочка в `render` своего раздела.
- `console.addCard(prefix, render(host, ref))` — карточка объектов оболочки (их `ref` с её префиксом: `vol:<name>`, `rec:<record>`) в инспекторе модуля, на том же месте, со звездой и полным экраном; без этого карточку узла оболочки было негде рисовать, кроме как лезть в DOM модуля.
- `addTreeNodes` принимает и верхний уровень: `addTreeNodes("servers", () => [...])` — узлы оболочки на верхнем уровне дерева серверов, без родителя (объекты, которые ничьи и которые обслуживает любой сервер); `addTreeNodes("server", (ref, obj) => [...])` — узлы под конкретным сервером; виды `addTreeNodes` — `unit`, `servers`, `server`, `member`, `access` (P/07 N1.5).
- `console.addMenu(kind, (ref, obj) => [{label, run}])` — пункты контекстного меню узла.
- `console.addDecor(kind, (ref, obj) => ({icon, badge, title}))` — иконка, значок и подсказка узла дерева и заголовка карточки объекта вида `kind`. `icon` — имя значка из `addIcons` или из значков модуля; `badge` и `title` — текст, модуль его экранирует. Логики в модуле нет, это тот же вызов оболочки в библиотеку, что `addTab`. В продукте так приходят иконки серверов (центр, офисный, камера).

**Карточка единицы: общая форма и своя.** Общая форма модуля строится из `/manifest` по типам полей и обязана уметь всё, что из типов следует: поле `list` сохраняет типизированный массив при отображении и редактировании, включая запятые внутри строк, пустые строки, порядок и дубли, поле `group_by` — блоком групп, поле `secret` показывается пустым с подсказкой «задан» и правилом `bound_to`, поле `labels` подсказывает значения из меток серверов, «где и почему» берётся из `/where`. Это платформенная работа, и в оболочку она не уходит. Оболочке остаётся то, что из манифеста не следует, двумя вызовами:
- `console.addFieldEditor(kind, field, render(host, ref, obj, value, set))` — свой редактор одного поля внутри общей формы (в продукте: разбор `source` на адрес, производителя и модель); `set(value)` отдаёт значение форме, отправка остаётся за формой.
- `console.addTab(kind, {id: "general", label, render(host, ref, obj)})` — своя карточка вместо общей, когда нужна другая компоновка; внутри неё оболочка вставляет общую форму хелпером `console.unitForm(host, ref)` и не повторяет ни одного поля манифеста сама. Обязательства те же: правка через `console.api`, секреты пустые, `bound_to`, `may()`.
- **Поле типа `json`.** Общая форма показывает его текстом с отступами (`JSON.stringify(v, null, 2)`, во всю ширину, моноширинно; подпись «— JSON»). Перед отправкой модуль сам разбирает текст: не JSON — под полем «не JSON, ничего не отправлено: <error>», запрос не уходит, набранное остаётся; JSON — в тело кладётся значение (объект, список, число или строка); строка-документ пишется в кавычках и уходит строкой; пустое поле, как у прочих, не отправляется. Дверь строковый вход как JSON не разбирает. Ключей `display` не нужно. Общие настройки домена (§10a) читают `json` так же.

Правило выбора: если чего-то не хватает общей форме для любой подсистемы, это чинится в модуле; `general` берут только ради компоновки.

**Оформление.** Облик модуля — это облик консоли продукта, общий для всех страниц: шапка со счётчиками из гейджей манифеста и меню пользователя (тема, частота обновления, «Обновить», «Выйти»), лента разделов, панель дерева с раскладкой, фильтром, звездой и «⋯», изменяемая ширина, подвал «Отменить»/«Сохранить», карточки. Общие стили — канонический файл модуля [console.css](../module/console.css), отдаётся платформой рядом с `console.js`; классы в нём нейтральные, словарь §2 действует и на имена классов. Стили предметных вкладок (видео, архив, карточка камеры) остаются в странице продукта. Страница может переопределить тему, но ничего не обязана.

Всё, что оболочка добавила, модуль размещает и перерисовывает по своему опросу, вызывая `render` снова. Прокрутку и фокус внутри хоста сохраняет модуль (тот же `paintInto`, что сейчас в продукте).

## 10a. Страница держателя домена

Страница держателя домена — модуль: `PlatformConsole.mount(app, {sections: ["domain"]})` использует английский по умолчанию; `PlatformConsole.mount(app, {sections: ["domain"], lang: "ru"})` явно выбирает русские платформенные подписи (опция §3). Своих предметных подписей страница не добавляет. Замороженный опубликованный модуль сейчас при отсутствии lang выбирает язык браузера; соответствие английскому умолчанию и синхронизация подписей — явный долг владельца опубликованных байтов PlatformConsole, P/07. Эта правка нормы/таблицы долг не реализует. Консоль домена (P/10 N1.7) отдаёт те же пути, что консоль кластера:
- `GET /manifest` → `{"name": "", "rows": null}` (корня нет, нового ключа нет; режим держателя модуль узнаёт из `sections: ["domain"]` страницы и в нём не грузит единицы, `/servers` и `/unplaceable`, единицы по подсистемам берёт из вида `/domain`); `GET /mounts` → `{"root": "", "mounts": {<sub>: description}}` по `MANIFEST_DIR`, описание — общий `DescribeSpec` консоли кластера, без `media`;
- `GET|POST|DELETE /session`; `login_url` — `/api/login`;
- `GET /domain` (вид), `GET /domain/alarms`; `GET /domain/keys` — своя дверь консоли кластера (P/06.7 N1.11), к консоли домена не идёт;
- поле вида `trust` (на обеих дверях): `{installed, domain, rev, root, current, issuing, revoked_issuing, holder_has_keys, members: {<member>: {admitted_key, presented_key, keys_rev}}}` — отпечатки (`root`, `admitted_key`, `presented_key`), id ключа (`current`), серийные номера и ревизии, ни одного ключа и секрета; домен не установлен — `{installed: false}`;
- `POST /domain/members`, `DELETE /domain/members/<m>`, `PUT /domain/topology`;
- `GET|PUT /domain/shared` — `GET` отдаёт `{doc, delivery, declared: {<sub>: [{name, type, schema?}]}}` (объявленные поля из `domain.shared` манифестов и их типы; у документа `{name, type: json}` — и его `schema`, по ней страница строит форму — P/10 N1.2f; модуль строит её сам: объект по `properties`, список с «добавить»/«убрать», скаляры и `enum`, чего форма сказать не может — текст JSON на своём месте; P/07 N1.6 `schema`); `PUT {base_rev, shared: {<sub>: {<field>: value|null}}}`;
- `POST /domain/handover {to}`, `POST /domain/stranded/apply {path, key}` (применить заново правку, которую держал только заменённый держатель), аварийный перенос `POST /domain/move {recovery, stolen?, copy?, why?}` — не дверь консоли домена, а консоли кластера-цели: она передаёт его своему подписанту тем же путём, `/domain/move`, с личностью и грантом `admin` этого кластера (P/06.7 N1.8, P/08.8 N1.8; предел 90 с; кластер, который держит домен, отвечает 409); соседей цель берёт из `CLUSTERS`; стенду и учениям `w2cctl domain move <door> <file> [stolen]`; приём плановой передачи — маршрут процессов `POST /api/take {grant, keys_sealed}` у подписанта цели, людям не открыт;
- `GET /domain/users`, `/domain/grants`, `/domain/break-glass` и их правки;
- `/domain/<sub>/<rows>|<table>` по объявлению; `/domain/<sub>/…` на дверь воркера подсистемы (только настройки и строки; байты мимо консоли).

`/servers`, `/drain`, `/schema`, `/unplaceable`, `/metrics`, `/events` у держателя не нужны: модуль переживает их отсутствие. Одни пути буквально: консоль кластера пересылает `/domain/X` на `/domain/X` держателя без переписывания; той же пересылкой, но на адрес консоли члена из `CLUSTERS`, идёт `GET /domain/at/<cluster>/<sub>/where/<id>` и `GET /domain/at/<cluster>/<sub>/where/<table>/<place>?unit=<sub>/<id>`: так страница камеры берёт дверь записи, которую держит другой кластер домена; а всё под `/domain/<sub>/…`, что не строки подсистемы, не таблица `domain.tables` и не книги `domain.books`, консоль домена пересылает доменному воркеру этой подсистемы, объявленному манифестом (`domain.books`/`domain.kept`), по адресу из его биения у держателя: имён его маршрутов (`/state`, `/cameras`, `/scenarios`, …) платформа не знает и ответа не читает, права решает гейт двери воркера; это дверь по объявлению, как `where` у держателей, не хук; набор маршрутов не закрыт, пока у этой двери нет токена с маршрутами; только `GET` и только `where`, кластер из носимого списка членов и не этот, один шаг (`X-W2C-Via`), 5 с, гейт здесь только «кто это», решает гейт того кластера по носимым грантам, дверь выдаёт только та консоль своим ключом, ответ странице как пришёл, байты мимо обеих консолей; отказы словами: 403 того гейта, 404 «not a route handed to a member» / «no console of <cluster> is known here (CLUSTERS)», 502 для консоли члена, не видной по сети, 400 «one hop»; все людские маршруты держателя живут под `/domain/*` (`members`, `topology`, `users`, `grants`, `break-glass`, `pending/`, `shared`, `alarms`, `handover`, `stranded/apply`, `<sub>/<rows>`, `<sub>/<table>`), а `/api/*` остаётся процессам (`carry/`, `member/`, `relay/`, `tokens/`, `backup`, `take`, `held`, `prepare`) и входу `/api/login` (его консоль пересылает домену, [договор пересылки](../../common/ru/contracts/forwarding.md) «Двери домена»). Без токена консоль кластера отдаёт только подписанное и публичное: `GET /api/held` → `{cluster, holder, term, keys, backup: {term, rev}}` (`term` из подписанной записи держателя, `backup` — указатель копии парой `{term, rev}`, не содержимое); копия бэкапа домена только по `GET /api/backup` процессу, подписавшему запрос ключом члена из списка этого кластера; `POST /api/prepare` только по подписи ключом токенов текущего набора держателя ([P/08.8](../../08-domain/ru/spec/08.8-domain.norms.md) N1.7). Агент члена следует за держателем сам: опрашивает `/api/held` у консолей кластеров домена из объявления `CLUSTERS`, берёт запись из ответа держателя и из 409 `deposed` и идёт за проверенной записью с наибольшим сроком (P/09.1 N3 «следовать»); отдельного списка кандидатов нет, держатель членам о себе не сообщает. В модуле раздел `domain` показывает раскладку «По серверам» с доменом в корне; карточка домена несёт срок и передачу, «применить заново», единицы по подсистемам, общие настройки по `declared` и правки для кластеров (pending и outcomes).
