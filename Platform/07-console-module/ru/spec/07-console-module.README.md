# P/07 — инструкция для реализации

Текст производный от `spec/07-console-module.README.md`, руками не правится: источник — английский [`spec/07-console-module.README.md`](../../spec/07-console-module.README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Этот файл — для агента (или человека), который пишет или проверяет модуль консоли по уроку. Объяснение «зачем» —
`ru/07-console-module.md` (для человека, в выгрузку не входит).

## Задача

Модуль консоли — общий модуль: опубликованные файлы [P/06.5 N1.1](../../../06-console/ru/spec/06.5-console.norms.md) `module`, их
отдают байт в байт, а не пишут. Урок нормирует, что модуль зовёт (N1.4) и что он даёт оболочке (N1.5); реализация
консоли его не пишет, владелец спецификации держит его байты по нормам, генератор проверяет полноту договора
переписыванием (P/06.5 N1.1 `module`: проверка полноты контракта, не способ реализации). Нормы урока —
P/07-01…08.

Для линии генерации критерий завершения — упаковка опубликованных байтов без изменений и сценарий 01 приёмки 6.5 (`?v=1`). Линия не переписывает JavaScript и не имеет отдельного исполняемого профиля модуля. Три теста модуля и пункты готовности P/07-07 и P/07-08 — явный долг владельца опубликованных байтов общего модуля, для линии ни PASS, ни FAIL (решение Архитектора 2026-11-05 в пределах ADR-0112 и ADR-0119).

## Входы и их приоритет

Канон — [нормы](07-console-module.norms.md). Двери, которые модуль зовёт, — [контракт урока
P/06](../../../06-console/spec/06-console.api.openapi.yaml); публикацию модуля и версию `?v=1` наблюдает сц. 01 [приёмки главы
6.5](../../../06-console/ru/acceptance/5/README.md); лекция (`ru/07-console-module.md`, для человека, в выгрузку не входит) объясняет причины; описание поверхности —
[`CONSOLE-MODULE.md`](../../../../ru/CONSOLE-MODULE.md) (не норма; где расходится с N1.5 — прав урок). При
противоречии записать место и контрпример и передать Спецификации; инструкция не вводит новый отказ. Внутренние типы,
функции и устройство модуля остаются выбором его владельца.

## Что создать

За поведение ниже отвечает владелец байтов общего модуля; линия генерации упаковывает опубликованные файлы.

- Вызовы модуля только из закрытого списка N1.4 в порядке `order`; двери держателей — только оболочке через `where()`.
- Контракт с оболочкой N1.5: `version`, `objects`, `api`, `may`, `events`, `where`, `words`, `adds`, `cards`, `commands`.
- Раздел домена — поздний слой N1.6 (уроки 8, 10; двери — урок P/10 и глава 6.7).

## Порядок работы

1. Подключить закрытый may. Развести повтор одной заявки и новое действие; разрешать автоматический повтор только по
   памяти владельца. Для неизвестного PUT/таблицы сначала чтение (N1.5). Три состояния сессии, по которым судит `may`, —
   [глава 6.3](../../../06-console/ru/spec/06.3-console.norms.md) N1.3 `session`.
2. Отдельно проверить модуль/оболочку: jsdom-тест владельца спецификации `Source/tests/console` по предметам N5 (разбор
   ревью стадии A 6–7, № 31). jsdom-тесты N5 реализация не читает и не исполняет: они проверяют опубликованные байты
   модуля у владельца спецификации; доказательство реализации — байты модуля как есть и загрузка `?v=1` (сц. 01 приёмки
   главы 6.5; C07-F01).
3. Библиотека для оболочки преобразует отсутствующее поле `door` HTTP-ответа `Where` в `null` (N1.5 `where`). Проверить
   этот уровень отдельно от HTTP: `Where` без достоверной двери не имеет поля `door` — проверка двери в
   [инструкции P/06](../../../06-console/ru/spec/06-console.README.md), глава 6.5.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| N1.5 | Кэш ключа по method/path/body сливает два нажатия | Ключ на логическое действие; новый вызов независим. |

Опубликованный модуль держит ключ на действие и повторяет сам только `POST` единиц, а `may` без grants даёт `true` только
при `open: true` («Решает реализация» п. 1 норм закрыт, решение «Архитектора» 2026-10-21); свидетельства — jsdom-тесты по таблице N5.

## Проверки границ

Модуль не зовёт ничего вне N1.4 `reads`/`writes`; пути `never` (`/{sub}/requests`, `/api/backup`, `/resources`, таблицы вне
`servers.show`, двери держателей) не появляются среди перехваченных jsdom-тестом запросов ни при монтировании, ни при
опросе. Части списка, которые вводит домен, проверяются в режиме `domain` позднего слоя (N1.6).

## Готово, когда

Владелец общего модуля записывает конкретное свидетельство для всех id (`P/07-01…08`): jsdom-тест по предметам N5 или чтение с причиной. P/07-07 и P/07-08 остаются открытым долгом этого владельца до прохождения `module-unplaceable-all`, `module-subsystems-none` и `module-writes-via` на опубликованном модуле. Линия генерации записывает долг явно; её свидетельство завершения — проверка упаковки из «Задачи», а не отдельная реализация этих ветвей JavaScript.
Совместимость общего модуля консоли — отдельное сравнение байтов (сц. 01 приёмки главы 6.5) и чтение по нормам N1.4, N1.5.

При расхождении — сравнить норму, форму ответа и сценарий. Зафиксировать точный вход и исход; отличие реализации не
переносить молча в канон. Решение отражается в норме, контракте, инструкции и затронутой приёмке; происхождение ошибки и
проверка связанного класса — в журнале Спецификации.
