# P/07 — инструкция для реализации

Этот файл — для агента (или человека), который пишет или проверяет модуль консоли по уроку. Объяснение «зачем» —
[`../07-console-module.md`](../07-console-module.md).

## Задача

Модуль консоли — общий модуль: опубликованные файлы [P/06.5 Н1.1](../../06-console/spec/06.5-console.norms.md) `module`, их
отдают байт в байт, а не пишут. Урок нормирует, что модуль зовёт (Н1.4) и что он даёт оболочке (Н1.5); реализация
консоли его не пишет, владелец спецификации держит его байты по нормам, генератор проверяет полноту договора
переписыванием (P/06.5 Н1.1 `module`: проверка полноты контракта, не способ реализации). Нормы урока —
P/07-01…02.

## Входы и их приоритет

Канон — [нормы](07-console-module.norms.md). Двери, которые модуль зовёт, — [контракт урока
P/06](../../06-console/spec/06-console.api.openapi.yaml); публикацию модуля и версию `?v=1` наблюдает сц. 01 [приёмки главы
6.5](../../06-console/acceptance/5/README.md); [лекция](../07-console-module.md) объясняет причины; описание поверхности —
[`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`](../../../КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md) (не норма; где расходится с Н1.5 — прав урок). При
противоречии записать место и контрпример и передать Спецификации; инструкция не вводит новый отказ. Внутренние типы,
функции и устройство модуля остаются выбором его владельца.

## Что создать

- Вызовы модуля только из закрытого списка Н1.4 в порядке `order`; двери держателей — только оболочке через `where()`.
- Контракт с оболочкой Н1.5: `version`, `objects`, `api`, `may`, `events`, `where`, `words`, `adds`, `cards`, `commands`.
- Раздел домена — поздний слой Н1.6 (уроки 8, 10; двери — урок P/10 и глава 6.7).

## Порядок работы

1. Подключить закрытый may. Развести повтор одной заявки и новое действие; разрешать автоматический повтор только по
   памяти владельца. Для неизвестного PUT/таблицы сначала чтение (Н1.5). Три состояния сессии, по которым судит `may`, —
   [глава 6.3](../../06-console/spec/06.3-console.norms.md) Н1.3 `session`.
2. Отдельно проверить модуль/оболочку: jsdom-тест владельца спецификации `Source/tests/console` по предметам Н5 (разбор
   ревью стадии A 6–7, № 31).
3. Библиотека для оболочки преобразует отсутствующее поле `door` HTTP-ответа `Where` в `null` (Н1.5 `where`). Проверить
   этот уровень отдельно от HTTP: `Where` без достоверной двери не имеет поля `door` — проверка двери в
   [инструкции P/06](../../06-console/spec/06-console.README.md), глава 6.5.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.5 | Кэш ключа по method/path/body сливает два нажатия | Ключ на логическое действие; новый вызов независим. |

Опубликованный модуль держит ключ на действие и повторяет сам только `POST` единиц, а `may` без grants даёт `true` только
при `open: true` («Решает реализация» п. 1 норм закрыт, решение «Архитектора» 2026-10-21); свидетельства — jsdom-тесты по таблице Н5.

## Проверки границ

Модуль не зовёт ничего вне Н1.4 `reads`/`writes`; пути `never` (`/{sub}/requests`, `/api/backup`, `/resources`, таблицы вне
`servers.show`, двери держателей) не появляются среди перехваченных jsdom-тестом запросов ни при монтировании, ни при
опросе. Части списка, которые вводит домен, проверяются в режиме `domain` позднего слоя (Н1.6).

## Готово, когда

Для обоих id (`P/07-01…02`) приведено конкретное свидетельство: jsdom-тест по предметам Н5 или чтение с причиной.
Совместимость общего модуля консоли — отдельное сравнение байтов (сц. 01 приёмки главы 6.5) и чтение по нормам Н1.4, Н1.5.

При расхождении — сравнить норму, форму ответа и сценарий. Зафиксировать точный вход и исход; отличие реализации не
переносить молча в канон. Решение отражается в норме, контракте, инструкции и затронутой приёмке; происхождение ошибки и
проверка связанного класса — в журнале Спецификации.
