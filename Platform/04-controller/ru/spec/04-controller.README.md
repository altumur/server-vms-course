# P/04 — инструкция для реализации

Текст производный от `spec/04-controller.README.md`, руками не правится: источник — английский [`spec/04-controller.README.md`](../../spec/04-controller.README.md), правка идёт в него, русский пересобирается переводом.

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — `ru/04-controller.md` (для человека, в выгрузку не входит).

Модель не получает приёмочные сценарии, фикстуры и ожидаемые ответы. Ссылки `sc. NN` / `scenario NN` и имена швов CALL обозначают приёмочные доказательства; требуемое поведение задают открытые нормы и формы.

## Задача

Реализовать контроллер манифеста. Контроллер принимает решения строками; запуск процессов — юниты `w2c-controller@.service` и
`<dep>-<sub>worker@.service` [P/02.4](../../../02-installer/ru/spec/02.4-installer.norms.md) N1.1. Операторские двери политики,
дренажа, меток и вывода сервера — двери консоли ([P/06.6](../../../06-console/ru/spec/06.6-console.norms.md) N2).

## Входы и их приоритет

Канон — [нормы](04-controller.norms.md), включая N0. Лекция (`ru/04-controller.md`, для человека, в выгрузку не входит) объясняет механизм и не меняет норму. Своего HTTP-контракта у урока нет (`P/04 no-openapi`).
Формы единицы заданы в [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md), слота — в
[P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md), ключи манифеста — в [P/02.1](../../../02-installer/ru/spec/02.1-installer.norms.md),
пульс — в [P/03.4](../../../03-worker/ru/spec/03.4-worker.norms.md). Формы строк и объектов урока — схемы семей `data/*.schema.json`
(каталог данных). При расхождении зафиксировать места и контрпример, не выбирать поведение догадкой; порядок
эскалации — в разделе «При расхождении». Внутренние функции, типы и библиотеки выбирает реализация.

| `version`, `index` | Точная непрозрачная версия хранилища для CAS/guard; отличается от счётчиков ниже. P/04-R026, P/04-R094, P/04-R103. |

| `resource_state`, `presence`, `fate` | Свежесть ресурса, слово ресурса о процессе и суд этого контроллера над слотом — разные значения. P/04-R196, P/04-R197, P/04-R198, P/04-R040. |
| `at`, `ts`, `age` | at и ts — стенные отметки с заданным для каждого поля смыслом N1; возраст и сроки политики используют указанное местное наблюдение. P/04-R002, P/04-R039. |
| `live(s)`, `live.<sub>` | Наличие процессов по пульсам для нехватки и номера замков из двери для доли заказа. P/04-R329, P/04-R332. |
| `free`, `free(s)` | Ёмкость воркера после осторожного резерва и место процессов сервера после заказов в пути. P/04-R022, P/04-R332. |
| `home`, `near`, `affinity` | Предпочтения и ограничения места по-разному влияют на допуск. P/04-R157, P/04-R158, P/04-R159, P/04-R290. |
| `want`, `pending`, `decommission-pending` | Соответственно абсолютная цель числа процессов, счёт процессов в пути в отчёте и стойкий ход вывода сервера. P/04-R094, P/04-R107, P/04-R330. |
| `release`, `names_given` | Подтверждённая запись отдачи и точная версия разрешения захвата — разные результаты. P/04-R041, P/04-R310, P/04-R311, P/04-R042. |
| `pass`, `control part`, `cycle` | Управляющая часть кончается до попыток снимков и окончательного отчёта цикла. P/04-R142. |

## Что создать

- Проверку схемы хранилища первым шагом старта (N3 «старт контроллера — проверка схемы»).
- Чтение картины мира, эффективных меток и наблюдение свежести по своим часам; состояния ресурса и судьбы слота.
- Проход N3 с отдельными попытками шагов, выбором кандидатов и записью решений через cas.
- Сверку назначений, переезд, уход, заказ воркеров по серверам и сокращение, вывод сервера и защиту manifest_rev.
- Отчёт N1.2, снимок N1.3a после прохода и свидетельства выполнения 28 пунктов чеклиста, включая допуск N1.5.
- Описание выборов из раздела «Решает реализация». Внутренние функции, типы и библиотеки выбирает реализация.

## Порядок работы

1. Выписать строки и писателей. Различить решение placement, производное workers, команду оператора
   и отчёт прохода. Версия строки хранилища, rev и manifest_rev — разные значения.
2. Собрать картину мира: последние известные свойства отдельно от наблюдаемой свежести.
   Начать отсчёт с первого взгляда. Проверить нечитаемую строку меток, отсутствие строки и первый запуск.
3. Проверить выбор по порядку N3: пул, ограничения, предпочтения, свободная ёмкость.
   Группа требует места на всех ожидающих; предпочтение дома не обходит ограничение.
   Уже размещённая единица не становится новой из-за появления более свободного воркера.
   Для distinct применить слотовый порядок P/03.2 N1.4, включая w-a/w-b и равные номера w-01/w-1.
   При равной свободной ёмкости сохраняется отдельное сравнение по полному имени ASCII.
   Заказ воркеров: строка `<sub>/want/<host>` всегда, `want` — абсолютная цель, ёмкость в пути вычитается
   из нехватки; снятие по сроку, номер выше want, сокращение с `retiring` и бюджетом — N3 «shortage(), order()…»;
   векторы [`order`](../vectors/order/README.md), [`shrink-victim`](../vectors/shrink-victim/README.md) и
   [`shrink-allowed`](../vectors/shrink-allowed/README.md) (условие сокращения и порядок причин отказа).
   В пути — номера 2…want без живого процесса по пульсам; кандидат и доля — по строке двери (`room.<sub>`, `live.<sub>`
   одного снимка), свободно(s) считается один раз за проход и уменьшается на каждую долю; снятие по сроку — `want := 1 + |live
   numbers ∩ {2…want}|`; номер выше want — вне пула, его останавливает скрипт (want не поднимается); при `distinct` и месте
   из пульса — кандидат без живого подходящего без места и без пробы в пути, не больше одного пробного за проход, остаток
   withheld с `no free <place_by>`; проба на одном сервере не останавливает рост на другом. Проверить на векторах дыру в номерах, номера в двери не подряд, дверь без `live.<sub>`, набор без
   вычислимого `per`, повтор меток в наборе, вход не по форме — код 2 ровно по перечню README пакета.
4. Реализовать turn и intent по N1.5/N3: все изменения placement/workers защищены guard turn,
   а новое решение принимает свежую нагрузку с резервами. Группа получает одну цель, снятия всех
   предшествуют общему добавлению; незавершённый intent восстанавливается до следующего допуска.
   После неизвестного исхода сначала барьер версии turn, затем перечитка. Проверить два контроллера
   на разных единицах: capacity 1, одинаковый spread_by, разные home членов группы. Смена владельца
   не позволяет позднему писателю ни добавить в старое назначение, ни снять из нового.
5. Разобрать таблицу судеб по возрасту наблюдаемой версии слота: SLOT_TERM / (SLOT_TERM + LOST_AFTER), gone, hung, wait, unsure, два молчания.
   Сдвиг until писателя и перезапуск судьи проверяются отдельно; будущий конечный until не порча.
   Проверить names_given при продлении между суждением и захватом; неизвестное gen не заменять нулём.
   Отдача читаемой строки сохраняет holder/until/gen/server; порванная строка с читаемым gen пишется целиком отданной и
   ничьей: released "true", holder "", until 0, gen прочитанный, server — сохранить если читается по схеме поля, иначе опустить без заменителя; gen не читается —
   строку не менять, разрешения на захват не выдавать (N3 «запись release»).
6. Публиковать отдельные snapshot-шарды только после успешного чтения источника, маскировать адреса, исключать
   секреты/blob. Проверить пустой unplaced, ушедший воркер, отказ одного шарда (N1.3a, N3 «snapshot»). Перед публикацией
   проверить байты всей сериализации против предела L двери ресурса по P/05; max_bytes держит хранилище при put, его `TooLarge` — тот
   же исход; ровно предел / +1, пустой шард и прежний шард после отказа.
7. Выполнить приёмку по её README: полный состав сценариев и шагов в порядке файла (все — с ресурсом P/05 на
   сервере контроллера: объекты кластера контроллер читает через ресурс своего сервера; без ресурса — «unknown»).
   Повторный прогон очищает также заявки POST и память id.
8. Приложить свидетельства чтения по N5 для ненаблюдаемых на стенде ветвей. Стенд проверяет несколько случаев с
   воркером; он не заменяет гонки двух контроллеров и весь судья.

## Ловушки языка и библиотеки

| Предмет | Ловушка | Проверка |
|---|---|---|
| время | судить свежесть по ts чужого процесса | сдвинуть часы писателя, сохранить ритм наблюдаемых изменений |
| строки | считать отсутствие, нечитаемость и пустые метки одинаковыми | три разных исхода N1/N3 |
| вес | считать количество единиц вместо суммы весов | неодинаковые веса и группа, превышающая свободное место |
| порядок | нечисловое имя или равный номер не имеют определённого победителя | равная ёмкость: полное имя ASCII; distinct: слотовый порядок P/03.2 N1.4; проверить все допустимые формы |
| cas | после конфликта повторить готовое решение | перечитать и проверить мутатор и manifest_rev заново |
| guard | заменить страж turn версией отдельной placement | поздний A после смены держателя получает 412 на любом изменении назначения |
| допуск | перечитать workers, но сохранить прежнюю оценку свободного места | новый расчёт под turn с резервом всего intent, вместимость/spread_by/группа |
| прогноз | min пустого пула или деление на ноль | положительный default как оценка; без него withheld с объяснением; названный 0 не заменяется на default  |
| дверь | кандидат по `live` пульсов вместо `live.<sub>` двери; свободно пересчитано по текущему want в каждом наборе | `free(s)` по двери, один раз за проход, минус каждая доля  |
| метки | якорь $ пропускает конечный перевод строки | проверить a, vlan:a и a\n как разные случаи |
| счётчики | true принимается за 1 | JSON-булевы не числа |
| N1.3a | ошибка чтения обнуляет возраст/публикует пустой шард | сохранить неизвестность и последнее наблюдение; пустота только из успешного обхода |

## Готово, когда

Выполнены P/04-01…28, описаны выборы реализации, приёмка прошла с заявленным начальным состоянием,
а оставшиеся гарантии имеют свидетельства по N5.
Указать срез, команды/стенд, наблюдения и ограничения. Проверка документов не означает
прохождение реализации. Расхождение нормы и формы оформить с контрпримером по правилам проекта;
повторяемую ошибку приёмки записать в историю правок урока вне входа модели.

## При расхождении

Сверить норму и сценарий на одном точном входе. Зафиксировать места, начальное состояние,
вмешательство и ожидаемый/фактический результат; если источники расходятся, передать вопрос «Спецификации»
с рекомендацией и не переносить поведение реализации молча в канон. Исправление нормы затрагивает
приёмку; повторяемую ошибку приёмки записать в историю правок урока вне входа модели.

Необязательный план пакета — [forms/stages.tsv](../../forms/stages.tsv), входы, машины и нормализация тестов — [forms/README.md](../forms/README.md). Швы пакета дополняют свидетельства чтением и приёмку раннера, не заменяют их.
