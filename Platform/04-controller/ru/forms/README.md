# Формы P/04 и швы контроллера

Текст производный от `forms/README.md`, руками не правится: источник — английский [`forms/README.md`](../../forms/README.md), правка идёт в него, русский пересобирается переводом.
Формы выражают существующие нормы контроллера; HTTP-двери контроллера не появляется.

## Входы и отказы

[daemon-flags.tsv](../../forms/daemon-flags.tsv) имеет восемь колонок P/01 с написанием окружения/аргумента P/03: `$NAME` — окружение,
`<sub>` — аргумент подсистемы маршрута запускателя контроллера. Это настройки процесса, не новые CLI-флаги. `default` — литерал либо
`-`; `default_text` может сохранять вычисляемое умолчание, которое адаптер разрешает по `norm`, а не копирует как правило имени хоста или шаблон пути.
`number` конечен; форма не добавляет отсутствующих лексических отказов или границ. `required`/`bad` — CEL над картой точных имён `f` и `cmd`.
Парные имена проверяются до умолчаний. Пустая `bad` не отменяет проверки общих договоров. Файлы окружения разбирает запускатель, процесс получает значения.

Наблюдаемые отказы старта заданы в [lifecycle.md](../lifecycle.md#коды-выхода) и договоре файлов окружения: неверная форма файла окружения или SERVER_NAME, отсутствующий/несовпадающий W2C_ROLE и разные значения парных имён дают код 2; журнал называет источник или имена по соответствующему договору. Принятые входы наблюдаются по корням строк и объектов, полю отчёта hung_move_after, cluster снимка и действию политики из их норм. Числовая настройка без нормативного отказа не получает отрицательного случая только из своего типа; NOTIFY_SOCKET наблюдается на хосте по системному чек-листу.

[refusals.tsv](../../forms/refusals.tsv) имеет `chapter row name surface code kind fields headers log norm word cause outcome diagnostic caller`.
Разделитель — буквальный TAB без CSV-кавычек. Глава — `4`; четыре последние ячейки задают причину, исход, диагностику и действие вызывающего.
`start` — старт процесса, `call` — процедура контроллера, `peer` — договор двери консоли. Фиксированный код дополняет нормативный исход;
`-` не добавляет машинной проекции. `kind` — `-`: error консоли не становится HTTP Fault контроллера. N4 ссылается на форму без второй таблицы.
Для `call` исход называет наблюдаемые поля отчёта, строки хранилища или отсутствие изменения; это не HTTP-статус и не выход процесса. Исход `peer` проверяется через консоль, `start` — по выходу процесса. Адаптер шва записывает фактические эффекты по описанию ниже; одно внутреннее слово возврата их не заменяет.

## Машины

[slot-fate.tsv](../../forms/slot-fate.tsv) и [slot-release.tsv](../../forms/slot-release.tsv) имеют `n state condition action next norm`, грамматика захвата P/03:
закрытые состояния/действия, типизированные `#var`, `#const`, `#action`, условия/аргументы CEL; первая подходящая строка текущего состояния.
Части пакета названы по файлам: `slot-fate` и `slot-release`, вызываются из `core`. Нет совпадения — ожидание без эффекта. Действие `-` — YOURS по `norm`, не noop.
Судьба возвращает суждение и версию разрешения; разрешение release требует версии подтверждённого ответа CAS. Машина release получает
уже выбранную судьбу после всех более приоритетных правил; её таблица не должна самостоятельно судить свежий живой слот как gone.

Возраст входа — местное наблюдение той же версии, не `until`, ts пульса или `fates.since`. Исходы чтения и присутствие процесса берутся
из общих договоров; неизвестное чтение не является отсутствием. Повреждённое поколение не ноль. Действие CAS проверяет его, сохраняет
поля читаемой строки или пишет полную release-строку torn; слепого повтора с продлённой версией нет. blocked/error/unknown
не публикуют имени. Конкурирующее продление оставляет строку прежней; изменившуюся версию судит следующий проход. Очистка брошенного захвата,
пакеты decommission и процедуры очереди/намерения размещения остаются по исходным якорям, это не эффекты чистого выбора судьбы.

## Швы

Швы контроллера — тесты пакета отдельно от сценариев раннера процесса. Грамматика и сравнение JSON —
[README форм P/03](../../../03-worker/ru/forms/README.md) и [README форм P/02](../../../02-installer/ru/forms/README.md): CALL с одним значением
JSON, подмножество объекта, ровно пустые объекты/списки, новые корни сценария; без оболочки. Адрес единственной главы — `4`, без подкаталога приёмки.
Порты нормализуют тесты, не задают API реализации. Вызываются настоящие функции контроллера и записываются эффекты, готовый ответ из expect запрещён.

Адаптер дополняет допустимый синтетический фон перед вмешательством: схема/манифест, читаемая очередь/idle-намерение, единицы,
воркеры, живое владение и ёмкость. Используется манифест `testsub` с включённой возможностью размещения, если случай её называет. Всё состояние
получается запуском инициализации/предыдущего прохода той же реализации, не назначением приватных полей реализации.
Пропуск — не неответ; явный null — подтверждённое отсутствие. Непрозрачные версии — ответы управляемого клиента, числовые нормализованные
поля — декодированные значения; release_items — проводные строки хранилища. Нормальный отказ нельзя получать перехватом аварии или постороннего исключения.

Конфликт не даёт разрешения; next_observation запускает свежий проход. Нет slot_writes — не было попытки; нет confirmed_slot_writes — не было подтверждённого изменения. Пять свидетельств: gone/runs/unlisted без единиц, gone с единицами, конкурирующее продление. |

| `controller-complete-intent` | Допустимое активное намерение и назначения; возможен обрыв после первого подтверждённого удаления и смена держателя. Возобновление со всех удалений, добавление только после их подтверждения. Неизвестная запись требует барьера своей очереди; чужой держатель останавливает все поздние записи и новые допуски. |
| `controller-key-admission` | Читается настоящий объявленный предел ключа реализации; строится допустимая именованная единица, ключ которой помещается, а ключ placement превышает предел ровно на placement_key_over_by байтов (здесь один), ASCII-заполнение id. Наблюдаются отказ намерения/размещений всей группы и продвижение независимой единицы. |
| `controller-choose` | Допустимая неразмещённая единица и кандидаты; применяются названное ограничение и предпочтение дома. Дом, не прошедший ограничение, не выигрывает ранг. |
| `controller-delete-after` | Наблюдения снятия/возврата на виртуальных монотонных часах; возврат сбрасывает счёт. Перед ответом удаления читаются свежие единица/решение. Отказ CAS не трогает состояние/журнал. Store early сохраняет not_before без барьера и журнала. Now — часы контроллера; store early — управляемый ответ допуска, не те же часы. |
| `controller-state-sweep` | Сначала прочитать состояние и сохранить его CAS, затем свежо прочитать единицу и born. Null — единицы нет: guard единицы не передаётся. Для существующей единицы или надгробия записать точный guard версии. Удалять только прочитанное сиротское состояние по сохранённому CAS. | `controller-snapshot` | Настоящая сериализация/публикация объекта. serialized_bytes — цель фикстуры: допустимое строковое поле с ASCII-заполнением доводит полный настоящий сериализованный шард, включая оболочку/ts, до нужного размера. Подмена счёта байтов и обход сериализации запрещены. Ошибка чтения ничего не публикует; ровно предел допускается, сверх него отказ до put; store TooLarge даёт тот же отказ. |
| `controller-table-snapshot` | Допустимая публикация таблицы, затем изменившиеся/прежние объекты. Для размера — настоящая сериализация/заполнение как выше. Сверх предела таблицы строят заглушку too_large. Сравнивают cluster/refused/rows кандидата без ts по P/04-R174; равенство сохраняет прежний ts без записи. Свидетель с прежними строками сохраняет также cluster и refused; смена cluster или переход заглушки не означает прежнего объекта. |
| `controller-want` | Наблюдения want и живых номеров по монотонным моментам. Полностью поднятый заказ сбрасывает таймер полёта; позднее пропавший номер начинает новый таймер даже без смены версии want. Наблюдаются отзывы, текущая цель и in_flight_since. |
| `controller-pass` | Ошибка клиента названного независимого шага; следующие шаги продолжаются. Наблюдаются failures/ok и исполнение позднего шага. Сломанная очередь имеет своё правило и не подменяется этой независимой ошибкой. |

Свидетельства дополняют чтение и общие векторы; не закрывают гонку OS-процесса или сценарий, который не исполняют.
План — [stages.tsv](../../forms/stages.tsv); все сценарии раннера и назначенные общие таблицы остаются обязательными с выборками из README пакета.

### Составные свидетели

Составные свидетели используют прежний controller-pass. fixture задаёт допустимое окружение, не ответ и не API реализации. grows/per/capacity, места/wanted и поля полки — настоящий допустимый testsub2; номера живы по свежим пульсам, wanted_holder реально держит читаемое wanted-место, empty_workers не имеют назначений. no_shortage_for получают предыдущими настоящими проходами на виртуальных часах, не записью внутреннего таймера. Оставшаяся ёмкость удовлетворяет гистерезису. Проводят настоящий выбор/retiring/end и прежнее согласование P/02 workers-script; stopped — фактический план остановки скрипта, не утверждение об OS-kill. Поля наблюдений вычисляют по фактическим записям/назначениям/целям/плану скрипта, не по fixture или expect.

manifest_yaml is the exact supplied YAML input, independently accepted by the regular P/02 loader; the adapter loads these bytes through that loader. It is not an internal canonical tree.

### Возобновляемый вывод сервера

Тот же controller-pass использует fixture=decommission_resume. Обычным загрузчиком P/02 загрузить manifest_yaml. Создать slot_count читаемых слотов указанного сервера, цель want, допустимый стоящий запрос консоли и взятую очередь размещения. Сервер не слышен требуемое время наблюдения. Чтения источников полные. populate_all_book_contributions даёт каждому исходному слоту по читаемому вкладу в каждой объявленной книге, по её настоящей форме строки и полному префиксу. Это управляемые входы хранилища; pending изначально нет, его должна создать реализация. Готовый ожидаемый progress не подставляется.

Исполнить настоящую процедуру, записывая все запросы, ответы и сохранённое состояние. first_batch_index задаёт последовательность ответов хранилища, начинающуюся с указанной точной десятичной STRING; один подтверждённый batch даёт всем своим записям один index. Это не счётчик с плавающей точкой. Полностью заполнять каждый кусок не требуется. all_batches_within_limits проверяет у каждого настоящего запроса число всех writes, различных guards, вес строк и сериализованное тело по опубликованным пределам хранилища, включая приём плана, progress-only и финализацию; ключ guard не может быть ключом write. all_cleanup_guards_exact сравнивает каждый guard уборки с записанным index пакета release, также после перезаписи progress. final_mark_last_atomic требует попытку окончательной отметки и снятия pending одним условным пакетом только после отсутствия оставшихся отдач/уборки в записанном плане; отметка с первым куском условие не выполняет.

break_after_release останавливает контроллер после первого подтверждённого куска release до первого запроса уборки; хранилище сохранить, память контроллера отбросить, новый экземпляр проходит обычное взятие очереди и восстановление. Наблюдать настоящие чтения pending и отсутствие повторной отдачи слотов.

pending_removed_at_completion наблюдают лишь после подтверждённой финализации. Ошибка/неизвестность берётся из управляемых ответов и записанного IO, не из проглоченного исключения или bool из expect.

fixture=loader_reserved_name: точный manifest_yaml передать тому же обычному загрузчику контроллера, вернуть настоящий verdict/layer и пути диагностики как JSON Pointer.

Начинаются как перезапуск, затем намеренно портят сохранённый pending, сохраняя читаемость по схеме. duplicate_remaining_name даёт две ссылки с одним именем и разными index; cursor_past_chunk ставит slot_cursor в len(current); foreign_from_prefix сохраняет грамматику префикса, но называет чужую подсистему. Восстановление читает эту настоящую строку. Неверный внешний source JSON остаётся ошибкой формы, это иная, семантическая порча. Все поля наблюдений выводятся из настоящих эффектов/IO реализации; source-свидетели не объявляют исполненный runtime/SUT-прогон.

## Свои скалярные значения

Действующая [runtime-constants.tsv](../../forms/runtime-constants.tsv) имеет только name/value/unit/norm/meaning: положительное целое JSON до int64, единицы count/s/bytes. Это не новые environment options. Borrowed значения сохраняют владельцев common/P01/P05. Числовые носители SLOT_TERM/LOST_AFTER в slot-fate и maxItems в pending остаются literal с явной связью для независимого предметного судьи; нового symbolic alias нет.

## Нынешний отчёт и свидетели

Положительный background строится по нынешнему писателю: placement имеет manifest_rev и непустую reason, active intent — непустую reason, idle её не требует; report имеет три обязательных счётчика, snapshot — один массив unit.rows, включая []. Raw family-read не дополняется и не исправляется. Отсутствие объекта до первой публикации — не повреждённая оболочка. Восстановление идёт через pending после подтверждённого release, не через раннюю final mark; точные старые guards сохраняются.

Все s51–s63 используют существующий controller-pass. fixture и scripted replies задают действительные входы/ответы клиентов, не готовый результат и не API реализации. Адаптер не получает expect. Наблюдения вычисляются из реального исполнения функций и зарегистрированного store/object IO; логические имена fixtures не являются доказательством прохождения.

- short_weight: обычный current testsub manifest с целым полем веса w, placement.weight.field=w, заданной capacity и одним заполненным живым worker (free=0). Две читаемые действующие ждущие единицы имеют веса weights, каждый в прежней допустимой области; их id, born, строки и пульсы валидны. grows/room/want/live дают свободных кандидатов, без capacity in flight. До отчёта выполняется настоящий pass; short[].units — точная сумма, workers — точное округление деления вверх, не число записей.
- write_conflict_limit: последовательно подать target_replies одной логической записи. После каждого конфликта соблюсти прежний барьер собственной очереди и свежий read/plan/CAS, без подмены старой версии новой в старой команде. Считать настоящие попытки и подтверждённый результат; одиннадцатый ответ после десяти conflict не должен потребляться. stale_version_writes вычисляется по запросам и наблюдённым версиям.
- valid_final_mark: получить валидную final mark завершением нынешнего pending плана, оставить standing request. Имеющийся released slot с вкладом не разрешает новую уборку. Считать slot writes, contribution deletes и final mark writes.
- publication_cycles: сохранить один процесс между перечисленными cycles и выполнить его обычные passes. Для target_counter материализовать отдельную реальную порчу state/type поля snapshot либо реальную сериализацию сверх table ceiling. Следующий valid цикл исправляет именно источник. orphan_states создаёт настоящую осиротевшую state-строку для guarded sweep, не готовый счётчик. snapshot_read/put подменяют ответ клиента; commit_reply_lost сначала действительно сохраняет новый объект, затем теряет ответ. Внешний readback объекта — наблюдение persisted bytes, не заявление о подтверждении контроллером. Время/control ok/failures фиксируются при конце управления, turn отдаётся до снимков, единственный final report пишется после обеих попыток. Считать actual report writes и IO-порядок; не добавлять runtime counters/порты.

Чистые seams не доказывают OS/process recovery или SUT. Неподдержанная binding остаётся явным пробелом до поставки адаптера/независимой проверки, не canned PASS и не excluded execution.

## Проверки сокращения

Это упорядоченный выбор по P/04-R051. Первая истинная строка возвращает `why`; только `ok` разрешает сокращение. `victim_exists` — пригодный живой верхний номер `n = want(s) > 1` по правилам жертвы/нужного места, никогда номер выше want. `waiting` берёт прежний набор placeable; `distinct` и `placeless` заданы политикой места из пульса. `no_shortage_for` — один таймер всей роли по P/04-R563: секунды от первого прохода без ждущих в любом наборе меток, null при ждущих хотя бы в одном наборе; новый контроллер начинает наблюдение заново. `in_flight` — счёт отсутствующих по пульсам номеров `2…want`, без базового. `per` — прежняя положительная оценка ёмкости или null. `remaining_free_after_move` — свободная ёмкость пригодных живых после переноса единиц жертвы, без жертвы и номеров выше want; при distinct входят только хранители мест. Действуют прежние числовые формы и единицы; новой константы нет. Равенство `SHRINK_AFTER` даёт отказ; равенство `per` проходит.
