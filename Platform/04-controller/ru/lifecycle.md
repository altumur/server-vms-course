## Запуск

- **Юнит** — `w2c-controller@<sub>.service`, по экземпляру на манифест на каждом сервере; лидера нет ([P/02.4] N1.1,
  [P/04]).
- **Запуск** — через раннер `w2c-run.sh controller <sub>` с `W2C_ROLE=<sub>controller` ([P/02.4] N1.1, N1.9).
- **Порядок** — после `configstore.service` (`After`, не `Wants`); готовность хранилища, прав и манифеста контроллер ждёт
  сам ([P/02.4] N3 «старт сервера», шаг 3).

## Флаги

Нет: канал настройки — только окружение ([P/02.4] N1.2 «Канал настройки и раскладка `PLATFORM_DIR`»). Аргумент
команды раннера — имя подсистемы `<sub>`.

## Каталоги и файлы

- **Строки хранилища** — через сокет роли, права — файл прав [P/02.5] N1.4. Строки урока — [каталог], владелец `P/04`:
  `<sub>/placement/<id>`, `<sub>/workers/<name>`, `<sub>/want/<host>`, `<sub>/controller/placement_turn`,
  `<sub>/controller/placement_intent`, `<sub>/decommissioned/<host>`; участие в `<sub>/slots/<name>` (предложение) и `<sub>/<manifest:unit.rows>/<id>`
  (`delete_after`).
- **Объекты** в корне объектов: отчёт прохода `<sub>/controller/pass` ([P/04] N1.2), шарды снимка
  `<sub>/snapshot/<worker>`, `<sub>/snapshot/unplaced` ([P/04] N1.3a). Имена файлов — одно кодирование ([договор журнала событий](../../common/ru/contracts/event-journal.md) «Имена файлов в общих деревьях»).
- **Объекты кластера** (пульсы воркеров и ресурсов, отчёты) контроллер читает через ресурс своего сервера (дверь
  объектов [P/05](../../05-resource/ru/spec/05-resource.norms.md), `scope`); без ресурса на своём сервере при `cluster://` — «unknown», не «нет» ([договор клиента хранилища объектов](../../common/ru/contracts/object-client.md) `door`); стенд, которому нужны пульсы воркеров,
  ставит ресурс на сервер контроллера ([P/04] N3 «проход()» шаг 0).
- **Читает**: пульсы воркеров `<sub>/heartbeats/<name>`, пульс ресурса `platform/resources/<server>/heartbeat`,
  `platform/manifest/<sub>` и метку `/rev`, `platform/schema`, `platform/servers/*`, `platform/doors/*`,
  `platform/decommission/*`, `platform/drain`, слоты `<sub>/slots/<name>`, места `<sub>/holds/<place>` ([каталог]);
  очередь размещения и intent (`<sub>/controller/placement_turn`, `placement_intent`) он и пишет, и читает ([P/04] N1.5).
- **Слова сборки** (`BUILD`) у контроллера нет в выдаче: пульса он не пишет и в `processes` `/schema` не входит
  ([P/06.6] N2.3 `GET /schema`).
- **Не пишет** в корень событий, кроме своего журнала `audit/<sub>controller/e1/…` (договор журнала событий `journal`).

## Коды выхода

| Код | Когда | Норма |
|---|---|---|
| 0 | смена манифеста: метка `platform/manifest/<sub>/rev` выше запомненной или исчезла — стоп, супервизор запускает снова | [P/02.3] N3 «Смена манифеста» |
| 2 | метка манифеста не по форме у работающего — остановка, рестарт отказывает до исправления метки оператором | [P/02.3] N3 «Смена манифеста», N4 |
| 2 | схема хранилища выше своей или не число | [P/04] N3 «старт контроллера — проверка схемы» |
| 2 | нет строки или метки манифеста, чтение не подтверждено, `sha256` не тот, манифест или каталог отказаны | [P/02.3] N3 «Старт процесса» |
| 2 | файл окружения не по грамматике; `SERVER_NAME` не по грамматике; `W2C_ROLE` не роль команды | [P/02.4] N1.2, N4 |
| ≠ 0 | иной отказ старта — строка лога называет источник | [P/02.3] N3 «Старт процесса» |

`RestartPreventExitStatus` по источнику unit P/02.4: после кода 2 юнит не перезапускается до действия оператора ([P/02.4] N1.1).

## Сигналы и готовность

- **Готовность** — `Type=notify`: `READY=1` после проверки схемы и чтения манифеста, `WATCHDOG=1` на границах завершённых решений и прогресса прохода, не независимым таймером, чтобы зависший вызов не маскировался;
  `WatchdogSec` по источнику unit P/02.4 (СЛЕДУЕТ) ограничивает промежуток между уведомлениями, конечный бюджет прохода — отдельная существующая обязанность; без `NOTIFY_SOCKET` молчит ([P/02.4] N1.1 `notify`, `watchdog`).
- **Первые LOST_AFTER** после старта никого не судит: впервые увиденное — «только что изменилось» ([P/04] N3 «проход()» шаг 0, N1.4a
  `fresh_controller`).
- **SIGTERM** — упорядоченный выход; незавершённый intent доводит следующий держатель очереди
  ([P/04] N1.5, N3 «принять и довести решение»). **SIGKILL** — то же для соседа: состояние только в строках.
- **Перезапуск** — `Restart=always`, `RestartSec` по источнику unit P/02.4, кроме кода 2 ([P/02.4] N1.1).

## Стенд

Корни `{data}/config`, `objects`, `events` до старта процесса создаёт команда запуска роли профиля — [общий README
приёмки](../../common/ru/acceptance/README.md) «Стенд без root»; процесс корней не создаёт ([P/02.4](../../02-installer/ru/spec/02.4-installer.norms.md) N1.1 `dirs`).

- Команда «Стенда» с подстановкой `{sub}` (без `<sub>` — `testsub`); `{data}` — это `PLATFORM_DIR`, стенд переводит
  подстановки в окружение [P/02.4] N1.2 ([Стенд] «One data directory»).
- Команда печати отчёта прохода — шаблон с `{data}` и `{sub}` ([Стенд]).
- Права стенда приёмки — `{rights}` из манифестов стенда командой вывода прав ([Стенд]).

## Открыто

- Исход прохода, когда ресурс сервера нечитаем, контроллер выводит из пульса ресурса и замка присутствия (P/05 N1.4, [договор замка присутствия](../../common/ru/contracts/presence-lock.md));
  контроллер возобновляет работу из общего состояния; открытых строк жизненного цикла у него нет.
