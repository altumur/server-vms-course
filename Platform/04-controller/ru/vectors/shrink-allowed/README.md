## Привязка вектора к форме сокращения

Вектор использует свой объявленный вход и выбор жертвы ниже; поля или проверки исполнения он не добавляет. Переменные [проверок сокращения](../../forms/README.md#проверки-сокращения) связываются так (P/04-R051):

| Переменная формы | Вход вектора или вычисление |
|---|---|
| `victim_exists` | Жертва, выбранная прежними правилами `shrink-victim`, не null; пригодны только живые верхние `n = want(s) > 1`. |
| `distinct` | Вход `distinct`: servers: distinct и место из пульса. |
| `waiting` | Вход `waiting`, группа считается одной штукой. |
| `placeless` | Среди живых входных воркеров есть `placeless: true`; читается только при `distinct`. |
| `no_shortage_for`, `SHRINK_AFTER` | Входы `no_shortage_for`, `shrink_after`; null означает нехватку; равенство ещё не дольше срока. |
| `in_flight` | Сумма отсутствующих живых номеров в `2…want(s)` по серверам; базовый не входит. |
| `per` | Вход `per`, включая null при отсутствии оценки. |
| `remaining_free_after_move` | `Σ free − load(victims)`: сумма свободного пригодных живых воркеров без выбранной жертвы и номеров выше want их сервера, затем минус нагрузка жертвы. При `distinct` в сумму входят только воркеры с `holder: true`. |

Последняя строка — исходная проверка гистерезиса: `Σ free − load(victims) < per` даёт отказ; равенство проходит. Прежние предпосылки согласованности входа вектора сохраняются. Эта привязка не добавляет поле нужного места в закрытый вход; существующие случаи жертвы/защиты места и составные швы процесса сохраняют свой охват.

## Порядок причин

Первая совпавшая строка [проверок сокращения](../../forms/README.md#проверки-сокращения) выбирает `why` (P/04-R051). Вектор использует те же условия; `victim: null` только при `no_victim`.

**Жертва** — та же, что у [`shrink-victim`](../shrink-victim/README.md): наибольший номер `n` (целым, не по слотовому
порядку), при равенстве номеров на разных серверах — меньшее имя сервера в байтах UTF-8. Здесь пул — номера
только живые верхние `n = want(s) > 1` из `live`: номер выше want не в пуле (N3 «number above want») — жертвой не бывает, и его свободное в
гистерезис не входит; так же и у `shrink-victim`, вход которого несёт `want` каждого сервера.
Ёмкость остальных допустимых воркеров с номерами 1…want(s) учитывается по прежнему правилу гистерезиса.

## Вход не по форме

Исполнитель вектора отвечает кодом 2 (ячейка `expect` — `@exit 2`) ровно на вход из перечня: не JSON-объект; лишнее или
отсутствующее поле (входа, элемента `servers`, элемента `workers`); `prefix` или имя сервера не по грамматике (P/03.2
N1.4, P/02.4 N1.2); имя воркера не `<prefix>-<server>-<n>` сервера из `servers`, `n` — не целое 1…99 или с ведущим нулём;
повтор имени воркера, сервера или номера в `live`; `want` — не целое 1…99; число — не целое или < 0; `shrink_after` < 1;
`per` ≤ 0; `holder` — не bool (поле обязательно). Целое — по точному десятичному значению записи, как `x-integer` (LAYERS §3): `1.0`, `1e0` — 1; `1.5`, булево, строка, число вне binary64 — не целое; номер `n` в имени воркера — лексема строки, без ведущего нуля. Остальное — вне вектора: строки
держат вход согласованным — номер каждого воркера есть в `live` его сервера, жертва есть в `workers`, при `distinct`
хранитель места не без места.

## Кто исполняет

Кто исполняет — контроллер (`04-controller`: условие и жертва сокращения, P/04 N3 «shrink (step 9a)») — все строки. Только читают готовое: скрипт сервера (`02-installer`, останавливает номер выше `want`, P/02.4 N1.5) и воркер (`03-worker`, плановая остановка при `retiring`, P/03.4 N3 «остановка по SIGTERM») (строку исполняет роль, чья норма вызывает её функцию).

## Не покрыто

Чтением или шагом приёмки: дренаж (сокращение без выдержки и гистерезиса); перенос единиц жертвы и `SHRINK_BUDGET`;
`retiring` уже записан (одна жертва на роль; `end`, `cancel`); «each unit of the victim passes choose()» — шагом
приёмки; часы (первый проход без нехватки) — N1.4. Поля причины несокращения в отчёте прохода (N1.2) нет: порядок
