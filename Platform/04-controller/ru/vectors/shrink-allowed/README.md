## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Ячейка читается байт в
байт. Поля: `case`, `input` и `expect` — текст JSON, `note`. Строк 53: `ok` — 7, `no_victim` — 5, `placeless_with_waiting` —
2, `no_shortage_long_enough` — 7, `in_flight` — 3, `hysteresis` — 5, `@exit 2` — 24.

**Вход** — `{prefix, shrink_after, no_shortage_for, waiting, distinct, per, servers, workers}`:
- `prefix` — префикс имён роли (P/03.2 N1.4); `shrink_after` — `SHRINK_AFTER`, с, целое ≥ 1;
- `no_shortage_for` — с, сколько у набора нет нехватки (от первого прохода без нехватки, N1.4 сроки), целое ≥ 0;
  `null` — нехватка есть в этом проходе;
- `waiting` — ждущие единицы набора (группа — одна штука), целое ≥ 0;
- `distinct` — `servers: distinct` и место из пульса (R16′, R16‴);
- `per` — `per` набора (N3 «по набору меток»), целое ≥ 1; `null` — оценки нет (`no positive capacity estimate`);
- `servers` — `[{server, want, live}]`: `want` — `want(s)`, целое 1…99; `live` — номера живых процессов роли на `s` по
  пульсам (живые(s)), без повторов;
- `workers` — `[{name, free, load, placeless, holder}]`: живые подходящие набору воркеры, имя `<prefix>-<сервер>-<n>`
  сервера из `servers`; `free` — свободно (ёмкость − нагрузка), `load` — нагрузка (Σ весов его единиц), целые ≥ 0;
  `placeless` — живой без места (поле `place_by` пульса пусто), `holder` — хранитель места; оба — bool, смысл — только
  при `distinct` (решение «Архитектора» 2026-10-20).

**Выход** — `{shrink, why, victim}`: `shrink` — `true` только при `why: "ok"`; `victim` — имя жертвы, названное и при
отказе (кто был бы жертвой), `null` — только при `no_victim`. Сравнение — JSON по значению.

## Порядок причин

Проверка идёт по порядку, `why` — первая сработавшая причина (P/04 N3 «сократить (шаг 9a)», `condition`):

1. `no_victim` — нет живого верхнего `n = want(s) > 1` ни на одном сервере (только базовые; номер выше want не в пуле,
   R28); `victim: null`;
2. `placeless_with_waiting` — `distinct`, `waiting > 0` и есть живой без места: живые без места при ждущих не
   сокращаются (R16′, R16‴); без `distinct` `placeless` не читается;
3. `no_shortage_long_enough` — `waiting > 0` («нехватки нет» — нет ждущих), или `no_shortage_for` `null`, или
   `no_shortage_for ≤ shrink_after`: норма — «нехватки нет **дольше** SHRINK_AFTER», равенство ещё не «дольше»
   (решение «Архитектора» 2026-10-20);
4. `in_flight` — у какого-либо сервера `|{2…want(s)} ∖ live(s)| > 0`: в пути — номерами по пульсам, не счётом (R13′);
5. `hysteresis` — `per` `null` или `Σ free` воркеров без жертвы и без номеров выше want своего сервера `− load(victims) < per`:
   после переноса единиц жертвы у оставшихся свободно меньше `per` (R3); равенство `per` проходит; при `distinct` в `Σ free`
   входят только хранители мест (`holder: true`) — как «свободно у подходящих живых» N3 «по набору меток» (R16′; решение «Архитектора» 2026-10-20);
6. `ok` — сократить, `victim` — жертва.

**Жертва** — та же, что у [`shrink-victim`](../shrink-victim/README.md): наибольший номер `n` (целым, не по слотовому
порядку), при равенстве номеров на разных серверах — меньшее имя сервера в байтах UTF-8. Здесь пул — номера
только живые верхние `n = want(s) > 1` из `live`: номер выше want не в пуле (N3 «номер выше want», R28) — жертвой не бывает, и его свободное в
гистерезис не входит; так же и у `shrink-victim`, вход которого несёт `want` каждого сервера (разбор ревью стадии B 6–7, № 42;
чтение коммитов «cammeta-acceptance» 2026-10-20).
Ёмкость остальных допустимых воркеров с номерами 1…want(s) учитывается по прежнему правилу гистерезиса.

## Вход не по форме (R22)

Исполнитель вектора отвечает кодом 2 (ячейка `expect` — `@exit 2`) ровно на вход из перечня: не JSON-объект; лишнее или
отсутствующее поле (входа, элемента `servers`, элемента `workers`); `prefix` или имя сервера не по грамматике (P/03.2
N1.4, P/02.4 N1.2); имя воркера не `<prefix>-<server>-<n>` сервера из `servers`, `n` — не целое 1…99 или с ведущим нулём;
повтор имени воркера, сервера или номера в `live`; `want` — не целое 1…99; число — не целое или < 0; `shrink_after` < 1;
`per` ≤ 0; `holder` — не bool (поле обязательно, решение «Архитектора» 2026-10-20). Целое — по точному десятичному значению записи, как `x-integer` (LAYERS §3): `1.0`, `1e0` — 1; `1.5`, булево, строка, число вне binary64 — не целое; номер `n` в имени воркера — лексема строки, без ведущего нуля (C04-VECTOR-INT-VALUE-01). Остальное — вне вектора (ADR-0084 доп. (2) R22): строки
держат вход согласованным — номер каждого воркера есть в `live` его сервера, жертва есть в `workers`, при `distinct`
хранитель места не без места.

## Кто исполняет

Кто исполняет — контроллер (`04-controller`: условие и жертва сокращения, P/04 N3 «сократить (шаг 9a)») — все строки. Только читают готовое: скрипт сервера (`02-installer`, останавливает номер выше `want`, P/02.4 N1.5) и воркер (`03-worker`, плановая остановка при `retiring`, P/03.4 N3 «остановка по SIGTERM») (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Не покрыто

Чтением или шагом приёмки: дренаж (сокращение без выдержки и гистерезиса, R7); перенос единиц жертвы и `SHRINK_BUDGET`;
`retiring` уже записан (одна жертва на роль; `end`, `cancel`); «каждая единица жертвы проходит выбрать()» — шагом
приёмки; часы (первый проход без нехватки) — N1.4. Поля причины несокращения в отчёте прохода (N1.2) нет: порядок
причин и их слова держит этот вектор, отчёт прохода их не показывает (решение «Архитектора» 2026-10-20).

Ревью ADR-0127 P/04 C1: жертвой бывает только живой верхний n=want(s)>1 своего сервера. Два прежних случая приоритетов используют живой верхний номер3 и отсутствующий средний2; новые no-live-top-* сохраняют их прежние входы и требуют no_victim. Защита places.wanted проверяется отдельно в shrink-victim и составными s36/s37, не новым полем этой закрытой формы.
