## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Ячейка читается байт в
байт. Поля: `case`, `input` и `expect` — текст JSON, `note`.

**Вход** — `{prefix, want: {<server>: <want>}, workers: [{name, server, wanted?: bool}]}`: живые воркеры роли, имена
`<prefix>-<сервер>-<n>` (P/03.2 N1.4); `want` — цель строки заказа каждого сервера, на котором есть воркер (целое 1…99,
P/04 N1.4).
**Выход** — `{victim: <name> | null}`: на каждом сервере допустим только живой верхний заказанный `n = want(server) > 1`. Воркер с `wanted: true` держит место с читаемой строкой places.wanted: пропустить весь сервер, не брать меньший номер. Нет wanted — false. Выбрать наибольший оставшийся номер целым, не по слотовому порядку; базовый `-1` жертвой не бывает; живой номер выше want своего сервера — не жертва: его останавливает скрипт
, конец сокращения его не гасит; `null` — жертвы нет.
Сравнение — JSON по значению.

Равенство номеров на разных серверах — меньшее имя сервера в байтах UTF-8 первым, как порядок кандидатов (N3
«shrink», жертва). Не покрыто: проверка «each unit of the victim passes choose()» — шагом приёмки и чтением.

## Вход не по форме

Исполнитель вектора отвечает кодом 2 (ячейка `expect` — `@exit 2`) ровно на вход из перечня: не JSON-объект; `prefix` или
имя сервера не по грамматике (P/03.2 N1.4, P/02.4 N1.2); имя воркера не `<prefix>-<server>-<n>` своего элемента, `n` — не
целое 1…99 или с ведущим нулём; повтор имени; `want` не объект, не называет сервер воркера или его значение не целое
1…99; имеющееся wanted не bool. Целое — по точному десятичному значению записи, как `x-integer` (LAYERS §3): `1.0`, `1e0` — 1; `1.5`, булево, строка, число вне binary64 — не целое; номер `n` в имени воркера — лексема строки, без ведущего нуля. Остальное — вне вектора.

## Кто исполняет

Кто исполняет — контроллер (`04-controller`: жертва сокращения, P/04 N3 «shrink», `victim`) — все строки. Скрипт сервера (`02-installer`) жертву не выбирает: останавливает номера выше готового `want` своим правилом (P/02.4 N1.5 `rules` 3, векторы `workers-script`); воркер (`03-worker`) видит готовый `retiring` (строку исполняет роль, чья норма вызывает её функцию).

Составные швы s36/s37 также требуют: настоящий выбор жертвы, retiring/move/end и согласование прежнего скрипта сервера P/02 с наблюдением цели и фактически выбранного номера остановки. Одного чистого вектора выбора жертвы недостаточно.
