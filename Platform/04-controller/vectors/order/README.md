# Векторы: нехватка набора меток и заказ по серверам

Владелец — урок P/04 ([нормы](../../spec/04-controller.norms.md) Н3 «нехватка(), заказать(), снять заказ, сократить()»: `в пути`, `per`, `нужно`, `кандидат`,
`порядок`, `заказать`; ADR-0084 и доп. (1) Р2, Р6, Р9, доп. (2)–(3) Р13′–Р22; cammeta-go М10-04 № 5). Участник — `<s>controller`. Байты пишет
«Спецификация» (ADR-0083, стадия A, A6).

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Ячейка читается байт в
байт, ничего не раскрывается. Четыре поля: `case`, `input` и `expect` — текст JSON, `note` — зачем строка.

**Вход** — один набор меток; все серверы и воркеры входа ему подходят (метки, `requires` и ресурс — не предмет вектора;
`servers: distinct` — только полями `place_by` набора и `placeless` сервера ниже):
- `default` — `placement.capacity.default` манифеста (целое ≥ 0);
- `workers` — подходящие живые воркеры: `capacity` (целое или `null` — ёмкость не названа) и `free` (свободно);
- `waiting` — Σ весов ждущих, `groups` — групп, которым нигде нет места;
- `servers` — `{<сервер>: {want, live, room, base?, numbers?, door?, placeless?, drained?, quiet?}}`: `want` — строка заказа, `live` — живые(s)
  по пульсам (с базовым и жертвой), `room` — `room.<sub>`, `base` — базовый `-1` жив (нет поля — `true`), `drained` —
  дренаж или вывод, `quiet` — «не поднял» в окне `RAISE_QUIET`. `numbers` — номера живых процессов роли по пульсам
  (базовый `1`, если жив; их `live` штук); нет поля — подряд: `1…live` при `base: true`, иначе `2…live + 1`. `в пути(s)` =
  `|{2…want} ∖ numbers|` — номерами, не счётом (Р13′, ADR-0084 доп. (4) Р26; разбор ревью стадии A 3–5, № 6); при номерах подряд —
  `max(0, (want − 1) − заказанные)`. `door` — список `live.<sub>` строки двери: номера n ≥ 2 живых замков; нет поля —
  номера n ≥ 2 из `numbers` (дверь совпадает с пульсами), `null` — у двери нет `live.<sub>`: сервер не кандидат; `свободно(s)` = `room −
  |{2…want} ∖ door|`, один раз за проход, минус каждая доля (Р14′);
- `place_by` набора и `placeless` сервера — только при `servers: distinct` и месте из пульса: `place_by` — имя поля места,
  `placeless` — число подходящих живых процессов без места на этом сервере (нет поля — 0; их свободное в `workers` не
  входит: там только хранители); кандидат — сервер с `placeless` 0 и без пробы в пути (`в пути(s)` 0); прирост набора — не
  больше одного пробного процесса за проход; остаток — `withheld` с `why: "no free <place_by>"` (Р16′, ADR-0084 доп. (5) Р16‴).
  Оговорка: ёмкость процесса без места в `per` входит (Н3 `per` — по всем подходящим живым), а в `workers` вектора её нет;
  строки с `placeless` берут её не меньше `per` хранителей (равной `default`). Случай, где ёмкость воркера без места меньше
  ёмкостей хранителей и потому задаёт `per`, вектор не выражает — чтением (разбор ревью стадии B 3–5, № 14).

**Выход** — `{per, processes, in_flight, need, orders, withheld}`: `in_flight` — Σ `в пути(s)`, `need` — нужно,
`orders` — новый `want` серверов, которым досталась доля, `withheld` — остаток без кандидата, число процессов (как ряд
`workers_withheld{labels}` P/06.5). `in_flight` — сколько в пути набор взял: `min(Σ в пути, processes)` (Р18). Ёмкость
воркера без названной — `default`; `per` — наименьшая положительная по всем `workers`, названная или `default`; названный 0
не заменяется на `default` (Р19′). Без вычислимого `per` — элемент тех же полей: `{per: null, processes: 0, in_flight: 0,
need: 0, orders: {}, withheld: 0, why: "no positive capacity estimate"}` (Р20; `why` — слова `short.withheld` отчёта, Н1.2).

**Несколько наборов** — вход с `sets: [{labels, waiting, groups}]` вместо `waiting` и `groups`; все серверы и воркеры
входа подходят каждому набору. Набор меток — множество: каноническая запись — уникальные метки по возрастанию через
запятую, повтор схлопывается (Р21). Наборы идут в порядке байт UTF-8 канонической записи (пустой — первым); набор берёт свободное, `в пути` и `room` только до своей потребности, остаток — следующему (Н3
«порядок наборов», cammeta-go М10-04 № 7). Выход — `{sets: {<каноническая запись>: {per, processes, in_flight, need,
withheld}}, orders, withheld}`: `in_flight` набора — сколько ёмкости в пути он взял, `orders` — итоговый `want` серверов,
`withheld` — сумма по наборам.

**Сравнение** — JSON по значению; `orders` — объект, порядок ключей не важен.

## Вход не по форме (Р22)

Исполнитель вектора отвечает кодом 2 (ячейка `expect` — `@exit 2`) ровно на вход из перечня: не JSON-объект; поле не того
типа (числа — целые ≥ 0, `capacity` — целое ≥ 0 или `null`, `base`, `drained`, `quiet` — булевы, метки — строки по [азбуке
меток](../../../common/contracts/labels.md)); `want` вне 1…99; `live` вне 0…99; `door` — не список или `null`, в нём номер вне 2…99 или повтор;
имя сервера не по грамматике сервера (P/02.4 Н1.2); два набора с одной канонической записью; `placeless` у сервера без `place_by` набора;
`numbers` — не список целых 1…99, с повтором или не `live` штук. Вход по форме с недопустимой метрикой — не отказ: ёмкость пульса не числом (P/04 Н1.3) — воркер не
принимает единиц и в `workers` не входит; нечитаемая строка двери — `door: null`. Остальное — вне вектора.

## Кто исполняет

Кто исполняет — контроллер (`04-controller`: нехватка, `в пути`, `свободно(s)`, кандидаты и доли, P/04 Н3 «нехватка(), заказать()») — все строки. Только читают готовое: ресурс (`05-resource`, пишет `room`/`live` строки двери, P/05 Н1.4 `door_row`), скрипт сервера (`02-installer`, P/02.4 Н1.5) и консоль (`06-console`, ряды `workers_wanted`/`workers_withheld`, P/06.5 Н3 «/metrics — текст») (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Чего вектор не покрывает

Снятие по сроку (Р27),
номер выше want (Р28) и сокращение — по времени, шаги [приёмки P/04](../../acceptance/README.md) (сц. 14–17; разбор ревью стадии B 3–5, № 17).
