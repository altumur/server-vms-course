# Векторы: разрешено ли сокращение

Владелец — урок P/04 ([нормы](../../spec/04-controller.norms.md) Н3 «нехватка(), заказать(), снять заказ, сократить()»:
`сократить (шаг 9а)` — `условие`, `жертва`; `в пути(s)`, `номер выше want`; Н1.4 `SHRINK_AFTER`; ADR-0084 доп. (1) Р3,
доп. (3) Р13′, Р16′, доп. (4) Р28, доп. (5) Р16‴). Участник — `<s>controller`. Байты пишет «Спецификация» (ADR-0083;
решение «Архитектора» 2026-10-20, № 12 разбора ревью стадии B 3–5). Один случай — один набор меток роли в одном проходе
(как [`order`](../order/README.md)).

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Ячейка читается байт в
байт. Поля: `case`, `input` и `expect` — текст JSON, `note`. Строк 51: `ok` — 7, `no_victim` — 3, `placeless_with_waiting` —
2, `no_shortage_long_enough` — 7, `in_flight` — 3, `hysteresis` — 5, `@exit 2` — 24.

**Вход** — `{prefix, shrink_after, no_shortage_for, waiting, distinct, per, servers, workers}`:
- `prefix` — префикс имён роли (P/03.2 Н1.4); `shrink_after` — `SHRINK_AFTER`, с, целое ≥ 1;
- `no_shortage_for` — с, сколько у набора нет нехватки (от первого прохода без нехватки, Н1.4 сроки), целое ≥ 0;
  `null` — нехватка есть в этом проходе;
- `waiting` — ждущие единицы набора (группа — одна штука), целое ≥ 0;
- `distinct` — `servers: distinct` и место из пульса (Р16′, Р16‴);
- `per` — `per` набора (Н3 «по набору меток»), целое ≥ 1; `null` — оценки нет (`no positive capacity estimate`);
- `servers` — `[{server, want, live}]`: `want` — `want(s)`, целое 1…99; `live` — номера живых процессов роли на `s` по
  пульсам (живые(s)), без повторов;
- `workers` — `[{name, free, load, placeless, holder}]`: живые подходящие набору воркеры, имя `<prefix>-<сервер>-<n>`
  сервера из `servers`; `free` — свободно (ёмкость − нагрузка), `load` — нагрузка (Σ весов его единиц), целые ≥ 0;
  `placeless` — живой без места (поле `place_by` пульса пусто), `holder` — хранитель места; оба — bool, смысл — только
  при `distinct` (решение «Архитектора» 2026-10-20).

**Выход** — `{shrink, why, victim}`: `shrink` — `true` только при `why: "ok"`; `victim` — имя жертвы, названное и при
отказе (кто был бы жертвой), `null` — только при `no_victim`. Сравнение — JSON по значению.

## Порядок причин

Проверка идёт по порядку, `why` — первая сработавшая причина (P/04 Н3 «сократить (шаг 9а)», `условие`):

1. `no_victim` — нет живого с номером `2 ≤ n ≤ want(s)` ни на одном сервере (только базовые; номер выше want не в пуле,
   Р28); `victim: null`;
2. `placeless_with_waiting` — `distinct`, `waiting > 0` и есть живой без места: живые без места при ждущих не
   сокращаются (Р16′, Р16‴); без `distinct` `placeless` не читается;
3. `no_shortage_long_enough` — `waiting > 0` («нехватки нет» — нет ждущих), или `no_shortage_for` `null`, или
   `no_shortage_for ≤ shrink_after`: норма — «нехватки нет **дольше** SHRINK_AFTER», равенство ещё не «дольше»
   (решение «Архитектора» 2026-10-20);
4. `in_flight` — у какого-либо сервера `|{2…want(s)} ∖ live(s)| > 0`: в пути — номерами по пульсам, не счётом (Р13′);
5. `hysteresis` — `per` `null` или `Σ free` воркеров без жертвы и без номеров выше want своего сервера `− load(жертвы) < per`:
   после переноса единиц жертвы у оставшихся свободно меньше `per` (Р3); равенство `per` проходит; при `distinct` в `Σ free`
   входят только хранители мест (`holder: true`) — как «свободно у подходящих живых» Н3 «по набору меток» (Р16′; решение «Архитектора» 2026-10-20);
6. `ok` — сократить, `victim` — жертва.

**Жертва** — та же, что у [`shrink-victim`](../shrink-victim/README.md): наибольший номер `n` (целым, не по слотовому
порядку), при равенстве номеров на разных серверах — меньшее имя сервера в байтах UTF-8. Здесь пул — номера
`2 ≤ n ≤ want(s)` из `live`: номер выше want не в пуле (Н3 «номер выше want», Р28) — жертвой не бывает, и его свободное в
гистерезис не входит (у `shrink-victim` входа `want` нет — там все `n ≥ 2`).

## Вход не по форме (Р22)

Исполнитель вектора отвечает кодом 2 (ячейка `expect` — `@exit 2`) ровно на вход из перечня: не JSON-объект; лишнее или
отсутствующее поле (входа, элемента `servers`, элемента `workers`); `prefix` или имя сервера не по грамматике (P/03.2
Н1.4, P/02.4 Н1.2); имя воркера не `<prefix>-<server>-<n>` сервера из `servers`, `n` — не целое 1…99 или с ведущим нулём;
повтор имени воркера, сервера или номера в `live`; `want` — не целое 1…99; число — не целое или < 0; `shrink_after` < 1;
`per` ≤ 0; `holder` — не bool (поле обязательно, решение «Архитектора» 2026-10-20). Остальное — вне вектора (ADR-0084 доп. (2) Р22): строки
держат вход согласованным — номер каждого воркера есть в `live` его сервера, жертва есть в `workers`, при `distinct`
хранитель места не без места.

## Не покрыто

Чтением или шагом приёмки: дренаж (сокращение без выдержки и гистерезиса, Р7); перенос единиц жертвы и `SHRINK_BUDGET`;
`retiring` уже записан (одна жертва на роль; `конец`, `отмена`); «каждая единица жертвы проходит выбрать()» — шагом
приёмки; часы (первый проход без нехватки) — Н1.4. Поля причины несокращения в отчёте прохода (Н1.2) нет: порядок
причин и их слова держит этот вектор, отчёт прохода их не показывает (решение «Архитектора» 2026-10-20).
