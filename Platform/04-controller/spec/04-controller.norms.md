# P/04 — Контроллер: нормы

Канон урока. [Лекция](../04-controller.md), [инструкция](04-controller.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/README.md), векторы [`order`](../vectors/order/README.md) и
[`shrink-victim`](../vectors/shrink-victim/README.md). Своего HTTP-контракта у урока нет (`P/04 no-openapi`): двери, через
которые оператор говорит с контроллером, — двери консоли ([P/06.6](../../06-console/spec/06.6-console.norms.md) Н2; `/where` — [глава 6.5](../../06-console/spec/06.5-console.norms.md)). Урок перенесён из
М10/4 (стадия B, ADR-0083 доп. (1): без изменения поведения): Н1.1–Н1.5, Н3 контроллера, строки Н4 и Н5
контроллера; из М10/10 — снимок (Н1.3 без `age` и `metrics`, здесь Н1.3а; Н3 «снимок — после прохода») и сторона
контроллера Н3 «старт контроллера, воркера, ресурса или консоли — проверка схемы» (здесь Н3 «старт контроллера — проверка
схемы»); из М10/11 — сторона контроллера отказа сервера (Н1.4 `moves`, `fresh_controller`, здесь Н1.4а); из
приёмки М10/05 — сценарии 07, 11–16. Номера подразделов — прежние номера М10/4; подразделы М10/10 и
М10/11 с номерами, которые уже есть в М10/4, — с буквой «а» (Н1.3а, Н1.4а). Двери консоли (М10/4 Н2), их проходы и
отказы, нормы М10/4-14, -15, -20 и приёмка М10/04 перенесены в P/06 (главы 6.5, 6.6; перенос урока 6); `resource_state`,
свежесть и правило читателя решения — [договор наблюдения](../../common/contracts/observation.md); сторона консоли
«вывести_сервер» — P/06.6 (разбор ревью стадии A 6–7, № 2). «P/0N» — урок модуля, «P/0N.K» — его глава; «М10/N» без
адреса — прежний урок (история переноса). Id норм —
`P/04-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): `<sub>/placement/<id>` — `at`; `platform/doors/<сервер>` — `since`, `at`; `platform/drain` — `at`; `platform/decommission/<сервер>` — `at`; `<sub>/decommissioned/<сервер>` — `asked_at`, `at`; `<sub>/controller/placement_intent` — `at`; `<sub>/want/<сервер>` — `at`; объект `<sub>/controller/pass` — `at`, `last_success`; объект `<sub>/snapshot/<воркер>` — `ts`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `<sub>/placement/<id>`, `<sub>/workers/<имя>`, `<sub>/want/<сервер>`, `<sub>/decommissioned/<сервер>`, `<sub>/controller/placement_turn`, `<sub>/controller/placement_intent`, `<sub>/controller/pass`, `<sub>/snapshot/<воркер>`, `<sub>/snapshot/unplaced`;
- пишет: `<sub>/slots/<имя>` (cas), `<sub>/<spec:unit.rows>/<id>` (delete), `<корень событий>/audit/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append), `<корень событий>/audit.alarms/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append), `<корень событий или объектов>/<путь>/%h<sha256>.name` (create);
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `<sub>/heartbeats/<имя>`, `<sub>/slots/<имя>`, `<sub>/holds/<место>`, `<sub>/<spec:unit.rows>/<id>`, `platform/schema`, `platform/resources/<server>/heartbeat`, `<sub>/policy`, `platform/servers/<сервер>`, `platform/doors/<сервер>`, `platform/drain`, `platform/decommission/<сервер>`, `<sub>/<spec:tables>/<имя>`, `/etc/w2c/tls/<роль>/server.key`.

Таблицы мест и связей (`places.table`, `affinity.table`, Н1.3) контроллер читает строками `<sub>/<spec:tables>/<имя>`;
журнал `unit.unplaced_deleted` (Н3 «проход()», шаг 8) и тревоги (`workers.raise_failed` — Н1.4, hung/unsure — шаг 3) пишет в
`audit/<роль>` и `audit.alarms/<роль>`, файл `%h<sha256>.name` — по [договору журнала
событий](../../common/contracts/event-journal.md) (`journal`, `writer`, «Имена файлов»); ключ своего комплекта — для
дверей ресурса по HTTPS ([P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md) `roles`) (разбор ревью стадии B 3–5, № 10).

Строки `<sub>/policy`, `platform/servers/<сервер>`, `platform/drain`, `platform/decommission/<сервер>` (пишет консоль, P/06.6) и
`platform/doors/<сервер>` (пишет ресурс, P/05) в Н1.1 — форма, которую читает контроллер; владелец строки —
процесс-писатель (каталог).

### Н1.1 Строки контроллера

```yaml
<sub>/placement/<id>:                     # решение; писатель — контроллер
  worker:    <имя воркера> | ""           # "" — не размещена; при active intent действует общее решение Н1.5
  reason:    <строка для человека>        # непустая; грамматика — Н3 «причина»
  at:        <стенные секунды контроллера>
  rev:       <десятичное целое ≥ 1>       # +1 на каждую запись
  spec_rev:  <ревизия спеки, под которой принято решение>   # ДОЛЖЕН у реализации с хранением спеки в строке (P/02.3)
<sub>/workers/<имя>:                      # назначение; производное от строк размещения
  units:     <список id по правилу списка P/06.1 Н1.2 (через запятую, иначе массив JSON)>   # отсортирован
  rev:       <десятичное целое ≥ 1>       # +1 только при изменении списка
<sub>/policy:                             # писатель — консоль; читает контроллер
  servers:   shared | distinct            # иное значение или ключ при чтении — умолчание спеки; при записи — отказ
platform/servers/<сервер>:                # писатель — консоль (ADR-0026)
  labels:    <метки через запятую>        # "" — ни одной; строка побеждает метки узла
platform/doors/<сервер>:                  # писатель — ресурс сервера (ADR-0045); форма — P/05 Н1.4 door_row (семья doors)
  room.<sub>, live.<sub>:                 # читает контроллер — свободно(s) Н3 «нехватка()» (ADR-0084 доп. (3) Р14′); элемента
                                          # нет, не читается или unknown — сервер не кандидат в заказ
platform/drain:                           # писатель — консоль; одна строка на кластер
  server: <сервер>; at: <момент>
platform/decommission/<сервер>:           # писатель — консоль
  by: <кто>; at: <момент>; why: <слова>; gone: "true"?   # gone — подтверждение «сервера нет», когда ресурс никогда не слышали
<sub>/decommissioned/<сервер>:            # писатель — контроллер; снимается при отзыве запроса
  asked_at, at:  <стенные секунды запроса консоли и отметки контроллера>
  slots, units, holds:  <имена отданных слотов, id снятых единиц, места удержаний — по правилу списка P/06.1 Н1.2; "" — ни одного>
                 # элемент: slots — имя слота P/03.2 Н1.4, units — id единицы P/06.1 Н1.3, holds — имя места P/03.2 Н1.3;
                 # счёт («0») — не элемент (добавлено пилотом схем семей данных, Д7)
                 # имена, не числа (сверка python и go 2026-10-18)
<sub>/want/<сервер>:                      # писатель — контроллер, cas со стражем placement_turn (Н1.5); ADR-0084 и доп. (1)
  want:      <десятичное 1…99>            # абсолютная цель числа процессов роли на сервере, базовый <prefix>-<сервер>-1 входит
  at:        <момент записи>              # диагностика; сроки — по наблюдению версии строки (Н1.4 сроки)
  by:        <экземпляр контроллера>      # диагностика; полномочие — cas и страж placement_turn
  why:       <непустая причина>           # грамматика Н3 «нехватка(), заказать()…»
  retiring?: <имя воркера>                # выбран к сокращению (Н3 «сократить»)
  # строка есть всегда у установленной роли на сервере спеки с grows: true (Н3 «строка заказа»); удаляют только вывод
  # сервера и снятие роли; сокращение пишет want 1, не удаляет; читают контроллер и консоль (ряд workers_wanted P/06.5 Н3 «/metrics — текст»)
```

### Н1.2 Отчёт прохода

Объект `<sub>/controller/pass`, пишется в конце каждого прохода; читают консоль (ряды `<sub>_reconcile_last_pass_age_seconds`, `<sub>_reconcile_pass_seconds`, `<sub>_reconcile_failures`, `<sub>_units_unplaced`, `<sub>_units_diverged` — P/06.5 Н3 «/metrics — текст») и воркеры (`names_given`, `hung_move_after` — P/03.2). Поля ниже ДОЛЖНЫ быть; реализация МОЖЕТ добавлять свои счётчики.

```yaml
pass:
  at:                   <момент конца прохода>
  ok:                   bool;  error: <текст последней ошибки или "">;  failures: <число>;  last_success: <момент>
  seconds:              <длительность прохода>
  spec_rev:             <ревизия спеки контроллера>;  spec_behind: <строк, решённых более новой спекой>
  names_given:          {<имя слота>: <версия строки слота, при которой имя отдано>}
  hung_move_after:      <секунды предела зависания, действующего у этого контроллера>
  fates:                {<имя>: {fate, server, why, rev, since}}   # только занятые неотданные слоты: holder непуст, released
                        #   false (не true и не taking — P/03.2 Н1.4); since — момент входа слота в этот fate на часах контроллера
                        #   (смена fate — новый since), не первый взгляд на слот (сверка python и go 2026-10-18)
  diverged:             <назначений, исправленных sync>
  unplaced:             <единиц без воркера, кроме снятых с эксплуатации>
  garbled:              <строк единиц, которые не читаются>
  snapshot_rows_garbled: <строк единиц, не вошедших в шард снимка последнего прохода: поле snapshot: не читается
                        своим типом (Н1.3а garbled)>   # P/01.1 Н0 «Устойчивость выдачи»; решение «Архитектора»,
                        #   сверка python и go М10/6–11, T7
  reach_moves_total, slots_released_total, unplaced_deleted_total, servers_decommissioned_total,
  workers_hung, workers_hung_moved_total, workers_unsure_moved_total, name_conflicts: <числа>
  unplaceable:          {<id>: <why>}   # единицы без места этого прохода и непустая причина; из него консоль берёт why
                        #   /unplaceable и reason 404 /where/<id> у неразмещённой (Н2.2)
  short:                # только при placement.grows: true; элемент на каждый набор меток с ждущими
    - {labels: [<метки>], units: <ждущих единиц веса>, workers: <нужно процессов сверх живых и ёмкости в пути>,
       groups: <ждущих групп>, ordered: <заказано этим проходом>, withheld?: <слова, почему не заказано>}
                        #   labels — каноническая запись: уникальные метки по возрастанию, повтор схлопывается (Р21);
                        #   groups — всегда, 0 тоже (обязателен в форме — разбор ревью стадии B 3–5, № 13); свои счётчики элемента МОЖНО, приёмка сравнивает названные поля;
                        #   пустой набор в словах why — any labels; набор без вычислимого per — тот же элемент: workers 0,
                        #   ordered 0, withheld «no positive capacity estimate» (Р20); ряд <sub>_workers_withheld{labels}
                        #   (P/06.5 /metrics) — у каждого набора отчёта прохода, ноль тоже (ADR-0084 доп. (2) Р23)
  wants:                {<сервер>: {want, live, pending, retiring?, why, state}}   # только при grows: true; live — живые
                        #   процессы роли сервера, pending — в пути(s) по пульсам (Н3, Р13′); state: ok | raising |
                        #   raise_failed | no_base
  raise_failed:         {<сервер>: {since, times}}   # сервер «не поднял»: since — момент снятия заказа, times — подряд
```

### Н1.3 Ключи размещения и их смысл

Форма ключей — P/02.1 (Н1.2). Здесь — что каждый значит для контроллера и умолчание.

| Ключ | Смысл | Умолчание |
|---|---|---|
| `capacity: {from, default, unit_mb, base_mb}` | ёмкость — поле пульса `from`; поля нет — `default`; поле есть, но не число (слово, булево) — воркер не принимает новых единиц, пока пульс не исправлен, уже назначенные не снимаются, причина — в отчёте прохода, поле `fates.<воркер>.why` (Н1.2): «capacity is not a number» (как вес, R25); `unit_mb`/`base_mb` — бюджет памяти воркера при старте (P/03.4) | `from: capacity`; `default` обязателен |
| `headroom: {from}` | запас — поле пульса; контроллер суммирует по живым | `from: headroom` |
| `weight: {field, default}` | вес единицы — `int`-поле строки ≥ 1, при отсутствии поля — weight.default ≥ 1; неверное присутствующее значение не заменяется default: строка единицы нечитаема (`garbled` отчёта прохода), единица не размещается и не снимается, причина — в `unplaceable`; нагрузка = Σ весов (ADR-0078) | без ключа — вес 1 у всех |
| `constraint` | `none` \| `labels-subset`: метки единицы ⊆ меток воркера. Метки единицы — её поле `labels` типа `list` (поля нет — пустой набор, ограничение выполнено); метка — по [азбуке меток](../../common/contracts/labels.md); метки воркера — строка `platform/servers/<сервер>` или метки узла | `none` |
| `tie_break` | `most-free-capacity` — единственное слово | оно же |
| `servers` | `shared` \| `distinct`: при `distinct` на одно место нести единицы может один воркер — с наибольшей нагрузкой, при равенстве первый в слотовом порядке P/03.2 Н1.4; остальные простаивают | `shared`; строка `policy` переопределяет |
| `place_by` | что считать местом при `distinct`: сервер или поле пульса; значение `""` из пульса — места нет (как у `spread_by`): воркер без места не хранитель, общего места `""` не бывает, единицы `distinct` получает только хранитель непустого места (ADR-0084 доп. (2) Р15) | `server` |
| `places: {table, where, server_field, lease}` | таблица мест и строка удержания `<sub>/holds/<место>` (P/03.2 Н1.3); `lease: strict` — строгое место | — |
| `spread_by` | поле: две единицы с одним значением не на одном сервере; отсутствующее или пустое значение в разведении не участвует — единица без значения не ограничивает и не ограничивается (пара к `group_by`: пустое — не группа; сверка python и go М10/3–5, решение «Архитектора») | — |
| `group_by: {field, cut_at}` | группа — одно значение поля (для `url` — хост по `cut_at: host`); размещается только целиком на одном воркере (ADR-0011). Значения нет, оно пустое или не читается, у `url` хоста не прочесть (`schemes.<s>.none` P/02.1 Н1.3, в том числе при `host: path`) — единица не в группе и размещается одна; отказ источника по P/06.1 Н4 (`bad_url`: пароль в адресе, нечисловой порт, знак вне грамматики) группу по читаемому хосту не отменяет — читаемый хост даёт группу (ADR-0053; вектор [`group-of`](../vectors/group-of/README.md); ревью стадии A, SA1-20); общей «группы без значения» нет (сверка python и go 2026-10-18) | — |
| `near: {sub, by, of, prefer}` | предпочтение: рядом с держателем единицы соседней подсистемы, на которую ссылается `by`; `prefer` — порядок среди нескольких; сосед берётся из каталога спек | `none` |
| `home` | предпочтение: поле строки, называющее сервер (предпочтительны воркеры, чей `server` равен значению этого поля у первого члена в порядке UTF-8), или `near` — дом у соседа; следовать может лишь одна сторона пары | — |
| `affinity: {field, table, server_field, strict}` | фильтр: место из таблицы, которое принимает единицу; `admits: false` не берёт никого; связывающая строка ведёт единицу только на своё место. Место единицы — строка `table`, которую называет её `field` (значения нет или строки нет — affinity не действует). `strict` — предикат, который выбирает связывающие строки: строка связывающая, когда каждое поле `strict` равно значению или входит в список значений (И по полям, ИЛИ по списку). Связывающая строка ведёт единицу только на свой сервер (`server_field`); несвязывающая — предпочтение этого сервера, не фильтр. `admits` проверяется у фактического места единицы (журнал cammeta-go, урок 8 № 2) | — |
| `requires` | `none` \| `resource`: при `resource` воркер пригоден, только пока ресурс его сервера не молчит | `none` |
| `grows` | `true` — роль растёт по требованию: контроллер считает нехватку и заказывает процессы роли по серверам строкой `<sub>/want/<сервер>` (Н3 «нехватка(), заказать()…»; ADR-0084) | `false` |
| `retire_when: {field, in}` | единица со значением поля из `in` не размещается и снимается с причиной — значением | — |
| `rebalance: {dead_band}` | перебалансировка по запросу: пока разброс нагрузки меньше — не двигать | `0.10` |
| `unplaced: {delete_after}` | строку единицы, которую никто не держит дольше N с по часам контроллера, контроллер удаляет (ADR-0067); снятая по `retire_when` — тоже: её никто не держит. Свои строки единиц МОЖЕТ удалять и воркер подсистемы по ключу `worker.deletes` — удаление с `cas` без права записи (ADR-0067 доп. 2026-10-17; учебного потребителя пока нет — долг в ХОД-Спецификация) | без ключа — никогда |

### Н1.3а Снимок

```yaml
<sub>/snapshot/<воркер> | <sub>/snapshot/unplaced:     # объекты; писатель — контроллер; имя воркера unplaced — отказ
  {cluster, worker: <имя> | null, ts, <rows>: [{id, revision, <поля snapshot:>, worker, server}]}
cluster:  имя установки — CLUSTER окружения (P/02.4 Н1.2; имя члена домена, М11/1 Н1.1); не задано — "local" (вне домена)
fields:   snapshot: спеки (P/02.1): нет ключа — все поля кроме *_secret и blob; [] — ни одного поля (id, revision, worker, server
          остаются); авторское поле server также исключено по умолчанию; секрет, blob или server в явном списке — спека не грузится; адреса — с маской
          P/06.2 Н1.1а, той же, что в выдаче консоли (пароль → ***)
          объявленные поля единицы не включают platform_fields P/06.1 Н1.2, включая deleted/worker: отказ загрузки P/02.1;
          unit.rows не cluster/worker/ts: коллизия оболочки — отказ загрузки refused:value (P/02.1)
publish:  после каждого прохода контроллера (Н3 «проход()»), вне шагов его отчёта; шарды ушедших воркеров — пустые; без единиц — пустой unplaced
garbled:  строка единицы, чьё поле snapshot не читается своим типом по values_by_type P/06.1 Н1.2, в шард не входит;
          шард публикуется с остальными единицами, строка лога раз на серию и счёт `snapshot_rows_garbled` отчёта прохода
          Н1.2 (P/01.1 Н0 «Устойчивость выдачи») (сверка python и go М10/6–11, T7)

          Размер — число байтов полного сериализованного объекта, включая оболочку и пустые шарды, с фактической
          записью ts (её длина входит в размер) (сверка python и go М10/6–11, совпало без нормы).
          Ровно L разрешено; больше L → TooLarge до put_durable, прежний шард не заменять.
          Диагностика: «N units on <шард>; snapshot is B bytes, limit is L bytes»; увеличение OBJECTS не снимает предел двери
```

### Н1.5 Допуск размещения между контроллерами

У подсистемы один изменяющий размещение контроллер в каждый момент. Право задаётся строкой,
а не наличием процесса: поздние записи прежнего держателя отсекаются guard хранилища.
Новые служебные строки принадлежат роли контроллера; читают их также читатели размещения.
Двери хранилища и словарь операций остаются P/01.1.

```yaml
<sub>/controller/placement_turn:         # строка; писатель — контроллер
  holder: <уникальная метка попытки захвата> | ""  # новая попытка не повторяет метку прежней
  spec_rev: <ревизия спеки>              # не убывает; старый контроллер не захватывает новую ревизию
<sub>/controller/placement_intent:       # строка; после создания не удаляется
  state: active | idle
  spec_rev: <ревизия принятого решения>
  # только при active:
  members: <JSON-массив всех id решения; уникальны, отсортированы>
  target: <имя воркера> | ""             # одна цель всей группы; "" — снять размещение
  reason: <непустая причина>
  at: <стенные секунды принятия решения>
constants:
  TURN_TERM: 45                         # возраст неизменной версии на часах претендента
  TURN_RENEW: 10                        # продление между операциями; срок своего запроса — монотонный
```

Нечитаемая строка turn/intent — отказ изменения размещения с failures, не пустая строка. Строка intent не по форме
(`state` не `active`/`idle`; у active нет `members`, `target`, `reason`, `at` или они не по форме выше) — нечитаемая:
контроллер — отказ с failures, читатели (`/where`, `/unplaceable`, прогнозы меток) — 503 `unavailable`, не idle
(сверка python и go 2026-10-18).
Их исходное отсутствие допустимо; после создания обе строки не удаляются. Turn сохраняет
нижнюю границу spec_rev, idle сохраняется, чтобы версия intent не возвращалась к
версии отсутствия между двумя чтениями; это необходимо читателям ниже.

Active intent — принятое общее решение для members, пока отдельные placement и workers
доводятся до него. Для каждого его id решают target/reason/at/spec_rev intent; остальные id
решаются своими placement. Читатель (/where, unplaceable, прогнозы и контроллер) читает решение по
[договору наблюдения](../../common/contracts/observation.md) «Чтение решения: intent → placement → intent» (разбор
ревью стадии A 6–7, № 2). При idle все строки завершённого решения уже доведены.

Для допуска нагрузка цели считается консервативно: сумма весов уникальных id, уже назначенных
ей **или** направленных туда эффективным решением. Двойной учёт одного id у одного воркера
исключён; ещё не снятое старое назначение удерживает место у прежнего воркера. Та же совокупность
учитывается для spread_by. Active intent резервирует всех members у target ещё до workers.
Показатели фактического назначения по-прежнему считают workers; резерв — условие допуска,
а не утверждение, что единица уже работает. Перед новым допуском незавершённый intent доводится.

Группа принимается одним intent со всеми её членами из свежего взгляда и одной общей целью;
предпочтения выбираются по первому id в порядке UTF-8, ограничения и вес — по всем членам.
Воркеры никогда не получают назначения членов этой операции одновременно на разных целях:
сначала снимаются все прежние назначения всех members, затем добавляются на одну цель.
Промежуточное отсутствие части назначений допустимо и чинится; частичное решение о вместимости — нет.
Изменения полей единиц, состава группы, ёмкости, политики и жизни после взгляда обрабатываются
следующим проходом: они не атомарны с допуском. При неизменных входах конкуренция контроллеров
не превышает ёмкость, не нарушает spread_by и не расщепляет группу.
Если после изменения состава группа размещена лишь частично и целиком на прежнюю цель не
помещается, её сначала целиком снимают intent с target ""; она ждёт или выбирает новую общую
цель следующим решением. Размещённую полностью группу без причины ухода не пересматривают.

## Н3 Проход

delete_after применяется только к named id: numeric вместе с этим ключом отвергается загрузчиком P/02.1. Контроллер не заменяет физическое удаление надгробием и не уничтожает историю числовых выдач.

### получить и удерживать очередь размещения

```
1. прочитать placement_turn; нечитаема → отказ шага; spec_rev > моя → не менять, spec_behind
2. строки нет → cas ""; holder пуст → cas прочитанной версии;
   holder чужой и эта версия не менялась ≥ TURN_TERM по моим часам → cas прочитанной версии;
   иначе очередь занята, этот проход не меняет размещения; следующий попробует снова
3. записать {holder: новая уникальная метка этой попытки, spec_rev: моя} с выбранным cas;
   conflict → очередь не получена; подтверждено → запомнить версию turn и время отправки запроса
4. каждые TURN_RENEW, между операциями: переписать свою строку turn с cas своей версии;
   подтверждено → новый guard и начало своего срока от отправки; conflict/чужой holder → прекратить записи
5. пока свой подтверждённый запрос моложе TURN_TERM, каждая запись/удаление placement/*,
   workers/* и placement_intent, а также удаление строки единицы по delete_after имеет cas целевой строки И guard {key: placement_turn, index: моя версия};
   истёк свой срок → не писать до подтверждённого продления; 412 → прекратить текущую попытку
6. завершение прохода: записать holder: "" с cas своей версии; конфликт не повторять
```

Любой неответ, неизвестный исход, конфликт или 412 при изменении размещения прерывает
текущий план действий в памяти. Прежде чем продолжить, контроллер подтверждённо меняет версию
своего turn с cas (если holder уже чужой — останавливается), затем заново читает intent и строки.
Этот барьер отсекает и ещё летящую старую запись: она либо применена до барьера и видна чтению,
либо получает 412 после него. Неответ самого барьера запрещает продолжение. Нельзя просто
подставить более новую версию стража в прежнюю команду. Два изменяющих прохода одного процесса
тоже не идут одновременно под одним turn; продление не выполняется параллельно целевой записи.

**Гонки.** Из двух cas захвата проходит один. Новый держатель после захвата читает мир заново;
поздние placement/workers/intent и удаление по delete_after старого держателя отказаны стражем turn, даже если строка
самой единицы не менялась. Новый держатель успел разместить прежнюю версию единицы — старое удаление получает 412, строка сохраняется. Старый контроллер не продлевает и не освобождает чужой turn своим cas.
Новому наблюдателю чужой turn сначала свежий; ожидание не зависит от часов прежнего держателя.
Время отправки своего подтверждённого запроса — время первой отправки этой логической записи;
повтор с тем же id и ответ again его не сдвигают (то же правило у слота и аренды, P/03.2).
Пропавший контроллер задерживает изменения максимум до следующей успешной попытки после
окна наблюдения, но срок ответа недоступного хранилища этим не ограничивается.

### принять и довести решение(members, target, reason)

```
0. очередь моя; active intent → сначала довести его, новых решений пока не принимать;
   spec_rev intent > моя → не изменять его и размещения; сообщить spec_behind
1. для нового решения: свежо прочитать единицы, эффективные решения, назначения и свойства кандидатов;
   хотя бы одна placement members имеет spec_rev > моя → не принимать intent, spec_behind;
   проверить всю группу/единицу, свободную ёмкость с резервами Н1.5, spread_by и прочие ограничения;
   для оценки переезда собственные прежние резервы members не считаются второй копией на цели;
   проверяется конечный набор: прежние id без members + ВСЕ members, включая spread_by между
   членами самой группы и по всем воркерам сервера цели;
   нет общей цели → нового допуска нет (снятие использует target "")
   полный ключ <sub>/placement/<id> хотя бы одного из members длиннее предела ключа хранилища
   (P/01.1 Н1) → решения нет, intent не пишется; эти members — в unplaceable с why
2. записать active intent с cas прочитанного idle (или cas "" при исходном отсутствии) и guard turn;
   toolarge до подтверждённого active → отказ шага, placement/workers не менять, группу не делить
3. после подтверждённого intent свежо перечислить/прочитать ВСЕ workers;
   снять ВСЕ members из ВСЕХ назначений, включая target, каждой записью cas + guard turn;
   только подтверждённое завершение всех снятий разрешает идти дальше
4. каждой placement members присвоить target/reason/at/spec_rev intent с cas + guard turn,
   rev + 1; строка уже содержит эти поля → не переписывать; отсутствующая начинается с rev 1
5. target непуст → добавить ВСЕ members в его назначение одной записью cas + guard turn;
   target пуст → добавления нет; пока 3–4 не завершены, шаг 5 запрещён
6. только после подтверждения 3–5 записать intent {state: idle, spec_rev} с cas + guard turn
```

Каждая группа занимает одну запись intent; она не дробится ради потолка строки или назначения.
Вес обеих будущих строк (intent и полного назначения цели) проверяется до шага 2; превышение —
отказ шага с причиной и failures, без частичного размещения. До шага 2 так же проверяется, что
полный ключ `<sub>/placement/<id>` каждого из members представим в пределе ключа хранилища
(P/01.1 Н1): id, допустимый P/06.1 Н1.3 для строки единицы, может не поместиться в более длинный
ключ размещения. Непредставимый ключ — решения нет, intent не пишется, группа не делится;
эти members попадают в `unplaceable` с `why`, остальные решения прохода продолжаются. Поэтому
недоводимого из-за длины ключа intent не бывает, и одна такая единица не останавливает размещение
подсистемы. Неполное чтение также запрещает допуск.
При смене держателя active intent восстанавливается **с шага 3**; новое решение и другое направление
для его members до завершения запрещены. Состав, цель и правило зафиксированы в intent;
изменения входов после его принятия обрабатываются следующим решением после восстановления.
После доведения все новые расчёты делают свежий взгляд, поэтому резерв предыдущего решения уже виден.

**Гонки.** Два допуска разных единиц не используют один остаток: B получает turn после A и видит
решение/назначение A либо его active intent, который обязан сначала довести. При capacity=1
второй вес 1 не проходит; при spread_by занятое значение уже видно. Два разных первых члена
группы не создают разные решения: один active intent фиксирует всех и одну цель. После обрыва
посреди снятий добавления не начинаются; после обрыва посреди placement новый держатель
повторяет снятия и доводит ту же цель. До добавления на новую цель у старых нет ни одного
назначения members. Это гарантия строк/назначений, а остановку действий старых процессов
обеспечивают их сверка и аренды (P/03.3, P/03.2), а не одно изменение карты размещения.

### проход() — каждые 5 с

```
0. наблюдение: обновить память увиденных пульсов, слотов и ресурсов на своих часах; объекты кластера (пульсы воркеров
   и ресурсов, отчёты) читаются через ресурс своего сервера (дверь объектов P/05, `scope`); без ресурса на своём
   сервере — только свой каталог (ADR-0084 доп. (2) Р17);
   впервые увиденное = только что изменилось; получить очередь размещения по Н3 выше;
   занята → без изменяющего прохода, повтор через 5 с; моя → сначала довести active intent;
   затем свежий взгляд: единицы, размещения, назначения и свойства кандидатов;
   перед каждым новым решением взгляд обновляется, результаты предыдущего решения учитываются
1. ревизия: прочесть ревизию спеки; строки размещения без spec_rev — проштамповать своей (один раз)
2. вывод серверов: исполнить platform/decommission/*: отдать слоты, записать <sub>/decommissioned/<s>
3. судьба слотов (ниже); release → записать слот отданным; names_given; тревоги hung/unsure
4. разместить: снять удалённые (reason deleted) → снять retire_when → sync назначений с размещениями (diverged) →
   каждую неразмещённую единицу — выбрать (ниже), группу целиком у первого члена; каждая в своей попытке;
   порядок неразмещённых — по id в байтах UTF-8 (группа — по id первого члена); тот же порядок у переездов шагов 5–7
   (добавлено сверкой М11, cammeta-python 05 № 25)
5. достижимость: единицы, чей сервер больше не достаёт до их меток, — переезд в пределах REACH_BUDGET;
   группа — целиком, первая группа идёт и сверх бюджета; некуда — снять с причиной
6. уход: единицы воркеров, которые уходят (ниже), — переезд без бюджета; группа целиком или ждёт
7. дом: не больше HOME_BUDGET единиц — домой, если там есть место
8. неразмещённые дольше delete_after: под своим turn заново прочитать единицу и её эффективное размещение
   по Н1.5; есть назначение, intent active (при любой цели) или чтение не подтверждено → не удалять. Всё ещё неразмещена и срок подтверждён →
   удалить строку с cas её свежей версии И guard своей версии placement_turn (допуск шага 5 выше);
   conflict/412/неответ → барьер и новый план по правилу очереди, журнал unit.unplaced_deleted только при успехе
9. нехватка и заказ (grows: true): строки заказа, ёмкость в пути, short, заказать, снять по сроку
9а. сократить (grows: true): жертва, retiring, перенос не больше SHRINK_BUDGET, конец или отмена; дренаж — Н3 ниже
10. отчёт <sub>/controller/pass; освободить очередь
каждый шаг — в своей попытке: ошибка шага — failures + 1, остальные шаги идут
```

Определённый badkey полного ключа хранилища — ошибка соответствующего шага, а не отсутствие
строки; данные по такому чтению не подменяются пустыми. Если ошибка не позволяет довести
active intent, новое решение не принимается: действует правило восстановления Н1.5/Н3.
Проход проверяет размещение и назначения; `unique`/`ref`/`must_match` полей единиц проверяются
предварительно дверью единиц P/06.1. Фоновый аудит и журналирование нарушения этих ограничений после
гонки отдельных записей этот проход не гарантирует (P/06.1 Н3).

**Гонки.** Цель размещения/назначения изменяются только под очередью и через intent; один cas строки
единицы не заменяет общего допуска. Обрыв очереди/хранилища прекращает весь изменяющий проход,
а не только одну единицу; ошибки остальных независимых шагов учитываются обычным failures.
Следующий держатель сначала чинит незавершённое решение, затем принимает свои.
Штамп spec_rev без изменения цели — отдельная запись с cas и guard turn, intent ей не нужен.

### выбрать(единица) → воркер | нет

```
размещена (worker ≠ "")                                            → как есть; не пересматривать
retire_when                                                        → нет
живой воркер = пульс читается ∧ менялся в последние LOST_AFTER по часам контроллера (договор наблюдения; правка поведения
              разбора ревью стадии A 6–7, № 1: было «<», шаг на границе — после сверки свидетелей) ∧ слот читается, released = false (не отдан и
              не в захвате — P/03.2 Н1.4 taking), holder непуст;
              пульс, чьё worker ≠ имени в ключе (P/03.4 Н1.1), не читается: воркера нет в пуле
пул = живые − отданные слоты − дренируемый сервер − выведенные серверы − (requires: resource ∧ ресурс silent)
      − retiring строк заказа (Н3 «сократить»; ADR-0084)
      − процессы с номером больше want(s) своего сервера (Н3 «номер выше want»; ADR-0084 доп. (4) Р28)
      − (distinct: все кроме хранителя места; место `""` — не место, воркер без места не хранитель — Р15)
      хранитель: наибольшая нагрузка на месте, при равенстве — первый в слотовом порядке P/03.2 Н1.4
пригодные = пул ∩ constraint ∩ spread_by ∩ affinity ∩ (группа уже у воркера → только он)
группа из нескольких ждущих: пригодные ∩ {принимает всех ∧ свободно ≥ Σ весов}; пусто → ждать, сказать
порядок: дом → предпочтение → все; предпочтение — один ранг: воркер рядом с соседом (near) или на сервере
         несвязывающей строки affinity (Н1.3) — любое из двух, оба сразу ранг не поднимают (журнал cammeta-go, урок 4 № 4);
         внутри ранга — свободно = ёмкость − нагрузка с резервами Н1.5,
         свободно ≥ вес единицы ∧ строго больше прежнего лучшего; равенство — первый по имени (ASCII, P/03.2 Н1.4)
нашли → принять и довести решение для единицы или всей группы по Н3 выше;
         уже размещена за время получения очереди → не принимать прежний выбор, свежий взгляд
нет   → строка не пишется (или reason, почему), единица в unplaced; тяжелее любого — в unplaceable со словами
```

**Причина** (для человека, ДОЛЖНА быть непустой; СЛЕДУЕТ грамматике): `most free capacity (<свободно>) among <n> worker(s)` — `<n>` — число пригодных (после фильтров), не всех живых + `; weight <w>` — только у спеки с `placement.weight` + ` reaching <метки>` + `; on <сервер>` + `, whose resource is <state>` + пометка выбора (`, at home on <s>`, `, beside <их id> holding it`, ` (home <s> has no room)`, `; away from home <s>`). Уход: `slot <имя> released`, `slot <имя> capture did not finish`, `resource on <s> silent`, `server <s> draining`, `server <s> decommissioned`, `<w> holds no <place> now`, `<w>'s <place> admits no unit`. Достижимость: `<s> no longer reaches <метка>; …` / `; nothing live reaches it`. Группа: `with <id>, one <group_by>: <why>; on <s>`. Удалённая: `deleted`.

**Материализация и sync.** Они используют тот же intent и очередь. Даже если правильное решение
уже есть, починка сначала фиксирует его для единицы/группы, снимает прежние назначения и доводит
одну цель. Частичного добавления по снимку начала прохода нет. Единственный guard целевой
записи — версия turn; стабильность решения обеспечивает исключительное владение очередью,
свежая проверка и неизменяемый до завершения intent. Это заменяет прежний guard отдельного placement.

### переехать(единица, от, к) → ok | уже перевезли

```
1. очередь текущего прохода моя и подтверждена; вне прохода сначала получить её;
   заново захватывать уже удерживаемую очередь не нужно; довести прежний active intent;
   свежо прочитать эффективное размещение;
   worker != от → Moved, не трогать; у группы проверить всех членов и общую цель
2. проверить к по всем ограничениям и свободной ёмкости с резервами;
   принять intent для всей единицы/группы и довести его шагами 2–6 выше
```

**Гонки.** A задержался после решения w-2, B получил очередь и довёл его, затем перевёз на w-3.
Каждая поздняя запись A имеет старый guard turn и отказана. Она не может ни добавить в w-2,
ни снять из уже нового w-3. Если A успел добавить до захвата B, B видит назначение при свежем
снятии. У одной единицы не возникает двух назначений; у группы до добавления новой цели сняты
все старые назначения. Мгновение без назначения и отставание directory остаются допустимы.

Во всех ветвях hung/unsure/wait HUNG_MOVE_AFTER отсчитывается от первого наблюдения
этим судьёй неизменной версии слота (возраст 0), не от until, конца SLOT_TERM или входа
в fate. Диагностическое fates.since не переносит этот срок. Новый судья начинает наблюдение заново.

### судьба(слот) → fate — по часам контроллера

```
читаемый слот не менялся < SLOT_TERM на часах этого судьи                  → alive
ресурс live ∧ присутствие gone ∧ назначенных единиц нет                  → release (без запаса; запись — ниже)
ресурс live ∧ присутствие gone (процесс мёртв, сервер жив)              → move  (без запаса)
та же версия слота наблюдается < SLOT_TERM + LOST_AFTER                   → alive (запас)
пульс менялся в последние LOST_AFTER (договор наблюдения; № 1)            → alive
ресурс live ∧ процесс runs (ведёт единицы или держит замок присутствия)   → hung;   прошло ≥ HUNG_MOVE_AFTER → hung_moved
ресурс live ∧ о воркере ничего (полей нет ∨ unlisted)                    → wait;   дать имя через names_given — только
                                                                           после HUNG_MOVE_AFTER
ресурс live ∧ присутствие не прочлось (unknown)                          → unsure; прошло ≥ HUNG_MOVE_AFTER → unsure_moved
ресурс unreachable (resource_state Н1.4)                             → unsure; прошло ≥ HUNG_MOVE_AFTER → unsure_moved
ресурс silent (пульс и at не свежи или строки нет) ∧ воркер молчит       → move   (два молчания, ADR-0045);
                                                                           сервер — из пульса, иначе из Slot.server
сервер неизвестен вовсе                                                  → move   (два молчания)
единицы назначены ∧ ничего из выше                                       → move     (замыкающая строка)
нет назначенных единиц ∧ ничего из выше                                  → release  (замыкающая строка)
запись release: записать слот released (cas),
                                                                           holder/until/gen/server сохранить; порванную —
                                                                           целиком отданной и ничьей с сохранением читаемого gen;
                                                                           если gen не читается — строку не менять, разрешение
                                                                           на захват не выдавать (P/03.2 Н1.4)
names_given[имя] = версия строки слота, на которой имя берётся: для move, hung_moved, unsure_moved и wait ≥ HUNG_MOVE_AFTER —
                   версия в момент суждения (контроллер строку не пишет); для release — версия ПОСЛЕ записи отдачи (ответ
                   этой записи): отданный слот берут по ней, и как «свободный» он тоже кандидат (P/03.2 Н3 «захватить» шаг 2c)
```

Нечитаемое gen существующего слота не заменяется нулём при release;
такую строку сохраняют и не включают в names_given до восстановления поколения. Переназначение
единиц по судьбе не означает разрешения переписать повреждённое поколение слота.

**Переходы `release` (ADR-0080 доп. 12).** Ветвь `release` достижима строкой «gone без назначенных единиц»:
живой ресурс говорит о процессе одним из `runs`, `gone`, `unlisted`, `unknown` (P/05 Н1.4; `silent` — состояние ресурса,
не присутствие), и каждое слово, кроме этого случая, перехватывает строка выше. Две замыкающие строки делают
таблицу полной и при определениях Н1 не достигаются.

| Участник и состояние | Событие и условие | Действие | Новое состояние или результат |
|---|---|---|---|
| судья, слот не менялся ≥ SLOT_TERM, назначенных единиц нет | ресурс live, присутствие `gone` | записать `released` с `cas` прочитанной версии | слот отдан; `names_given` — по версии после записи |
| судья, то же | держатель продлил слот между чтением и записью | `cas` отказан | слот не меняется; на следующем проходе — `alive` |
| судья, слот не менялся ≥ SLOT_TERM, единицы назначены | ресурс live, присутствие `gone` | ничего не писать | `move` без запаса; `names_given` — по версии суждения |
| судья, назначенных единиц нет | ресурс live, присутствие `unlisted` или полей нет | ничего не писать | `wait` (ADR-0048): имя за держателем до HUNG_MOVE_AFTER |
| судья, назначенных единиц нет | ресурс live, присутствие `runs` | ничего не писать | `hung` |

Порядок правил нормативен: более определённое знание раньше менее определённого; запас раньше суждений. Контроллер не пишет слот ни при каком исходе, кроме `release` и вывода сервера.

**Гонки.** Держатель продлил слот между суждением и захватом имени новым процессом: `names_given` привязан к версии, захват с `cas` по ней не пройдёт — имя остаётся. Два контроллера могут иметь разные истории наблюдения и потому разные суждения (ADR-0049); каждый использует свой возраст версии по P/03.2 Н1.4. Записи `release` идут с `cas` прочитанной версии, поэтому два решения не перезаписывают продление или чужой захват. Сдвиг часов писателя при одинаковой истории наблюдения не меняет судьбу.

### уходит(воркер) → причина | нет

Первое из: слот отдан (released = true — сразу); брошенный захват (released = taking, версия неизменна SLOT_TERM на
часах контроллера — захватчик умер между записями; раньше — не уходит, захват довершится; добавлено пилотом Quint, F2);
ресурс сервера silent; не держит место (`distinct`); место не принимает; сервер дренируется; сервер выведен; исход из MOVED_FATES — его `why`. Единицы уходящего — переезд (шаг 6) по правилам выбора; группа целиком или остаётся с тревогой `units.left_on_leaving`; строка размещения не очищается, пока не найдено новое место, — кроме отданного слота и брошенного захвата: их единицы, которым некому достаться, снимаются записью `worker: ""`, причина `slot <w> released; nothing live can take it` (`slot <w> capture did not finish; nothing live can take it`) (воркер ушёл навсегда, строка с его именем говорила бы «размещена»; приёмка P/03.4, сц. 03). Молчание хранилища не двигает ничего.

**Гонки.** Уход и оживший воркер: решение — по снимку прохода; воркер, вернувшийся после переезда, читает назначение без единицы и останавливает её (P/03.3 Н3 «цикл()», шаг 2: ведомой нет в назначении → `stop_unit`); переезд не откатывается.

### нехватка(), заказать(), снять заказ, сократить() — при grows: true

```
сократить (шаг 9а):

             пульсам, Р13′), и после переноса единиц жертвы у оставшихся подходящих живых свободно ≥ per (гистерезис,
             Р3); «нехватки нет» — нет ждущих: при servers: distinct живые без места при ждущих не сокращаются

  жертва:    воркер роли с наибольшим номером n ≥ 2 (целым), при равенстве номеров на разных серверах — меньшее имя
             сервера в байтах UTF-8 первым, как порядок кандидатов (стадия A, A6); каждая её единица
             (группа — целиком) проходит выбрать(единица) на пуле без жертвы; иначе не сокращать, причина в отчёте
  retiring:  записать retiring = <жертва> в строку заказа её сервера (cas, guard turn); жертва — вне пула всех шагов

             без выдержки и гистерезиса (единицы и так уходят, «server <s> draining»), want − 1 при пустом назначении
             жертвы, до 1 (Р7)
вывод:       шаг 2 — строку заказа сервера удалить с cas и guard turn; новых заказов сервер не получает (Р7)
```

**Гонки.** Два контроллера пишут одну строку заказа: cas по версии и guard `placement_turn` пропускают одного, второй
перечитывает и пересчитывает от абсолютной цели. Отдельного вида записи в `placement_intent` заказ не имеет: абсолютная
цель под cas со стражем `placement_turn` и ёмкость в пути закрывают повтор прироста — повторный проход и новый
контроллер доводят цель, а не прибавляют (ADR-0084 доп. (1) Р2). Заказ против скрипта: скрипт читает ряд раз в минуту (P/02.4 Н1.5) и
отстаёт — процесс, поднятый после снятия заказа, с номером выше want не в пуле и останавливается скриптом (Р28); процесс,
остановленный скриптом при непустом назначении (рассинхрон), отдаёт слот штатно (P/03.4 Н3 «остановка»; ADR-0084 п. 7) —
это переезд, не потеря единиц. Сокращение и смена держателя очереди: `retiring` в строке, новый держатель продолжает
перенос, а не выбирает новую жертву. Дверь против пульсов: кандидат и доля считаются по `live.<sub>` двери, нехватка — по пульсам; остаток гонки —
процесс с номером больше want, поднятый после отметки двери, не дольше периода отметки (ALIVE_EVERY): его ловит проверка
памяти скрипта воркеров (P/02.4 Н1.5, потолок по памяти) (ADR-0084 доп. (3) Р14′).

**Пробный процесс при `distinct` (Р16‴).** Воркер без места единиц не несёт и на чужой сервер не уходит: место на его
сервере освобождается только уходом хранителя (Р8 не меняется), до того он простаивает. Новый процесс до первого пульса
со взятым местом несёт место `""` и в это окно — живой без места: его сервер в это окно не кандидат; пока он заказан и не
поднялся — тоже (проба в пути); задержанный старт не даёт серверу второй пробы; другие серверы набора — кандидаты, по
одному пробному процессу за проход (ADR-0084 доп. (3) Р16′, доп. (5) Р16‴; разбор ревью стадии A 3–5, № 13).

### снимок — после прохода

```
по воркеру: строки единиц его назначения → [{id, revision, поля snapshot (маска адресов), worker, server}];
строка, чьё поле snapshot не читается своим типом, — пропустить, строка лога раз на серию и счёт в
`snapshot_rows_garbled` отчёта прохода (Н1.2; Н1.3а garbled; сверка python и go М10/6–11, T7);
неразмещённые → unplaced; шард, который был и не заполнен → пустой; без единиц → пустой unplaced
сериализовать каждый шард; проверить размер по Н1.3а до записи; больше L → TooLarge, этот шард не писать;
допустимый шард записать; TooLarge хранилища → тот же отказ; ошибка публикации — одна строка лога на серию;
TooLarge до записи сохраняет прежний шард и его время; неизвестный исход записи не доказывает, что шард остался прежним.
При любой ошибке не публиковать пустой шард вместо непроверенных данных
```

**Гонки.** На одном сервере один контроллер спеки; разные серверы могут публиковать разные локальные копии одного логического ключа шарда. Выбор по written не создаёт общий момент чтения. Строки и шарды публикуются по отдельности: снимок — наблюдённая конфигурация, не согласованная резервная копия. Ошибка чтения строк/списка не разрешает публиковать пустой шард; ошибка одной записи не откатывает уже опубликованные. Потребитель проверяет revision и не выводит отсутствие из неполного набора.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **предел повторов при `conflict`** (10); период прохода — 5 с, норма (ADR-0030 доп. 2026-10-07 п. 5), не выбор;
2. **кэш между проходами** — что держится по версии строки, и как это не меняет решений (решают строки, не кэш);
3. **как ресурс сервера сообщает присутствие процесса** (форма поля `workers` пульса ресурса — P/05 Н1.4) и замок присутствия ([договор замка присутствия](../../common/contracts/presence-lock.md));
4. **откуда `HUNG_MOVE_AFTER`, `REACH_BUDGET`** (окружение) и их умолчания;
5. **как запрашивается перебалансировка** и кто её зовёт; бюджет;
6. **дополнительные поля отчёта** сверх Н1.2 и как из него делаются метрики (ряды `<sub>_reconcile_*`, `<sub>_units_unplaced`, `<sub>_units_diverged` — P/06.5 Н3 «/metrics — текст»);
7. **точные тексты** причин и отказов сверх грамматики Н3/Н4;
8. **что делает спека без `grows`** с нехваткой (ничего не считает) и где живёт скрипт сервера (`w2c-workers.sh`, P/02.4 Н1.5 `script`);
9. **команду печати отчёта прохода** `<sub>/controller/pass` для приёмки — по разделу «Стенд» общего README приёмки.
10. **как публикуется снимок** при отказе хранилища (лог раз на серию); период — после каждого прохода (Н1.3а `publish`), выбора нет;
11. ~~**откуда берётся `cluster` снимка**~~ — нормировано: `CLUSTER` окружения (Н1.3а; P/02.4 Н1.2), не задано — `local`.

## Чеклист готовности

Реализация соответствует уроку, когда выполнена каждая норма; id нормы `P/04-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/04-01** эффективное решение — active intent для members, иначе placement; назначение производное; `rev` растёт; `sync` чинит оборванное — сц. 01 [приёмки P/06.6](../../06-console/acceptance/6/README.md); sync и двойное чтение intent — проверяются чтением
- [ ] **P/04-02** решения и незавершённый intent сохраняются в хранилище; каждая запись с `cas`; изменения размещения проходят через общий turn с CAS/guard по Н1.5/Н3; локальная история наблюдения начинается заново после перезапуска и не заменяет чтение решения — проверяется чтением
- [ ] **P/04-03** порядок прохода Н3 и попытка на шаг — проверяется чтением
- [ ] **P/04-04** картина мира: ёмкость, сервер, метки узла — без срока; жизнь — по изменению пульса за 45 с по часам контроллера; впервые увиденное — только что изменилось — проверяется чтением (стенд P/03.3, сц. 02-unit; срок 45 с ни один сценарий не наблюдает)
- [ ] **P/04-05** метки сервера: строка побеждает узел, пустая — «ничего не достаёт», нечитаемая — последние и без суждения; азбука меток — сц. 05 приёмки P/06.6 (отказы формы); приоритет строки над узлом, пустой список, нечитаемая строка — проверяются чтением (на стенде приёмки P/06.6 (сц. 01–07) воркеров нет)
- [ ] **P/04-06** пул, ограничения, предпочтения в порядке Н3; размещённое не пересматривается — проверяется чтением;
  `affinity.strict` выбирает связывающие строки, несвязывающая полка — предпочтение: `tallies` на полке `plain` при
  `strict.kind: [reserve]` размещаются — сц. 07 [приёмки P/03.6](../../03-worker/acceptance/6/README.md)
