# P/04 — инструкция для реализации

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — [`../04-controller.md`](../04-controller.md).

## Задача

Реализовать контроллер спеки. Контроллер принимает решения строками; запуск процессов — юниты `w2c-controller@.service` и
`<dep>-<sub>worker@.service` [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н1.1. Операторские двери политики,
дренажа, меток и вывода сервера — двери консоли ([P/06.6](../../06-console/spec/06.6-console.norms.md) Н2).

## Входы и их приоритет

Канон — [нормы](04-controller.norms.md), включая Н0. [Приёмка](../acceptance/README.md) показывает наблюдаемые примеры;
[лекция](../04-controller.md) объясняет механизм и не меняет норму. Своего HTTP-контракта у урока нет (`P/04 no-openapi`).
Формы единицы заданы в [P/06.1](../../06-console/spec/06.1-console.norms.md), слота — в
[P/03.2](../../03-worker/spec/03.2-worker.norms.md), ключи спеки — в [P/02.1](../../02-installer/spec/02.1-installer.norms.md),
пульс — в [P/03.4](../../03-worker/spec/03.4-worker.norms.md). Формы строк и объектов урока — схемы семей `data/*.form.yaml`
(каталог данных, ADR-0088). При расхождении зафиксировать места и контрпример, не выбирать поведение догадкой; порядок
эскалации — в разделе «При расхождении». Внутренние функции, типы и библиотеки выбирает реализация.

## Что создать

- Проверку схемы хранилища первым шагом старта (Н3 «старт контроллера — проверка схемы»).
- Чтение картины мира, эффективных меток и наблюдение свежести по своим часам; состояния ресурса и судьбы слота.
- Проход Н3 с отдельными попытками шагов, выбором кандидатов и записью решений через cas.
- Сверку назначений, переезд, уход, заказ воркеров по серверам и сокращение (ADR-0084), вывод сервера и защиту spec_rev.
- Отчёт Н1.2, снимок Н1.3а после прохода и свидетельства выполнения 23 пунктов чеклиста, включая допуск Н1.5.
- Описание всех одиннадцати выборов реализации. Внутренние функции, типы и библиотеки выбирает реализация.

## Порядок работы

1. Выписать строки и писателей. Различить решение placement, производное workers, команду оператора
   и отчёт прохода. Версия строки хранилища, rev и spec_rev — разные значения.
2. Собрать картину мира: последние известные свойства отдельно от наблюдаемой свежести.
   Начать отсчёт с первого взгляда. Проверить нечитаемую строку меток, отсутствие строки и первый запуск.
3. Проверить выбор по порядку Н3: пул, ограничения, предпочтения, свободная ёмкость.
   Группа требует места на всех ожидающих; предпочтение дома не обходит ограничение.
   Уже размещённая единица не становится новой из-за появления более свободного воркера.
   Для distinct применить слотовый порядок P/03.2 Н1.4, включая w-a/w-b и равные номера w-01/w-1.
   При равной свободной ёмкости сохраняется отдельное сравнение по полному имени ASCII.
   Заказ воркеров (ADR-0084): строка `<sub>/want/<сервер>` всегда, `want` — абсолютная цель, ёмкость в пути вычитается
   из нехватки; снятие по сроку, номер выше want, сокращение с `retiring` и бюджетом — Н3 «нехватка(), заказать()…»;
   векторы [`order`](../vectors/order/README.md), [`shrink-victim`](../vectors/shrink-victim/README.md) и
   [`shrink-allowed`](../vectors/shrink-allowed/README.md) (условие сокращения и порядок причин отказа; решение «Архитектора» 2026-10-20, № 12 разбора ревью стадии B 3–5).
   В пути — номера 2…want без живого процесса по пульсам; кандидат и доля — по строке двери (`room.<sub>`, `live.<sub>`
   одного снимка), свободно(s) считается один раз за проход и уменьшается на каждую долю; снятие по сроку — `want := 1 + |живые
   номера ∩ {2…want}|`; номер выше want — вне пула, его останавливает скрипт (want не поднимается); при `distinct` и месте
   из пульса — кандидат без живого подходящего без места, не больше одного пробного за проход, остаток withheld с `no free
   <place_by>` (ADR-0084 доп. (2)–(4) Р13′–Р28). Проверить на векторах и дыру в номерах. Проверить на векторах: номера в двери не подряд, дверь без `live.<sub>`, набор без
   вычислимого `per`, повтор меток в наборе, вход не по форме — код 2 ровно по перечню README пакета.
4. Реализовать turn и intent по Н1.5/Н3: все изменения placement/workers защищены guard turn,
   а новое решение принимает свежую нагрузку с резервами. Группа получает одну цель, снятия всех
   предшествуют общему добавлению; незавершённый intent восстанавливается до следующего допуска.
   После неизвестного исхода сначала барьер версии turn, затем перечитка. Проверить два контроллера
   на разных единицах: capacity 1, одинаковый spread_by, разные home членов группы. Смена владельца
   не позволяет позднему писателю ни добавить в старое назначение, ни снять из нового.
5. Разобрать таблицу судеб по возрасту наблюдаемой версии слота: 45/90 с, gone, hung, wait, unsure, два молчания.
   Сдвиг until писателя и перезапуск судьи проверяются отдельно; будущий конечный until не порча.
   Проверить names_given при продлении между суждением и захватом; неизвестное gen не заменять нулём.
   Отдача сохраняет holder/until/gen/server, в том числе при восстановлении порванной строки с читаемым gen.
6. Публиковать отдельные snapshot-шарды только после успешного чтения источника, маскировать адреса, исключать
   секреты/blob. Проверить пустой unplaced, ушедший воркер, отказ одного шарда (Н1.3а, Н3 «снимок»). Перед публикацией
   проверить байты всей сериализации: min(положительный max_bytes, 64 МиБ), при max_bytes=0 — 64 МиБ; ровно предел / +1,
   пустой шард и прежний шард после отказа.
7. Выполнить приёмку по её README: 10 сценариев / 175 шагов в порядке файла (сц. 12, 14–17 — с ресурсом P/05 на
   сервере контроллера: объекты кластера контроллер читает через ресурс своего сервера, Р17).
   Повторный прогон очищает также заявки POST и память id.
8. Приложить свидетельства чтения по Н5 для ненаблюдаемых на стенде ветвей. Стенд проверяет несколько случаев с
   воркером; он не заменяет гонки двух контроллеров и весь судья.

## Ловушки языка и библиотеки

| Предмет | Ловушка | Проверка |
|---|---|---|
| время | судить свежесть по ts чужого процесса | сдвинуть часы писателя, сохранить ритм наблюдаемых изменений |
| строки | считать отсутствие, нечитаемость и пустые метки одинаковыми | три разных исхода Н1/Н3 |
| вес | считать количество единиц вместо суммы весов | неодинаковые веса и группа, превышающая свободное место |
| порядок | нечисловое имя или равный номер не имеют определённого победителя | равная ёмкость: полное имя ASCII; distinct: слотовый порядок P/03.2 Н1.4; проверить все допустимые формы |
| cas | после конфликта повторить готовое решение | перечитать и проверить мутатор и spec_rev заново |
| guard | заменить страж turn версией отдельной placement | поздний A после смены держателя получает 412 на любом изменении назначения |
| допуск | перечитать workers, но сохранить прежнюю оценку свободного места | новый расчёт под turn с резервом всего intent, вместимость/spread_by/группа |
| прогноз | min пустого пула или деление на ноль | положительный default как оценка; без него withheld с объяснением; названный 0 не заменяется на default (Р19′) |
| дверь | кандидат по `live` пульсов вместо `live.<sub>` двери; свободно пересчитано по текущему want в каждом наборе | `свободно(s)` по двери, один раз за проход, минус каждая доля (Р14′) |
| метки | якорь $ пропускает конечный перевод строки | проверить a, vlan:a и a\n как разные случаи |
| счётчики | true принимается за 1 | JSON-булевы не числа |
| Н1.3а | ошибка чтения обнуляет возраст/публикует пустой шард | сохранить неизвестность и последнее наблюдение; пустота только из успешного обхода |

## Готово, когда

Выполнены P/04-01…23, описаны выборы реализации, приёмка прошла с заявленным начальным состоянием,
а оставшиеся гарантии имеют свидетельства по Н5.
Указать срез, команды/стенд, наблюдения и ограничения. Проверка документов не означает
прохождение реализации. Расхождение нормы и формы оформить с контрпримером по правилам проекта;
повторяемую ошибку приёмки записать в corrections.tsv.

## При расхождении

Сверить норму и сценарий на одном точном входе. Зафиксировать места, начальное состояние,
вмешательство и ожидаемый/фактический результат; если источники расходятся, передать вопрос «Спецификации»
с рекомендацией и не переносить поведение реализации молча в канон. Исправление нормы затрагивает
приёмку; повторяемую ошибку приёмки записать в corrections.tsv.
