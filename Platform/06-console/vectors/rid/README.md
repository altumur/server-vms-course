# Векторы: грамматика `rid` просьбы

Владелец — глава P/06.4 ([нормы](../../spec/06.4-console.norms.md) Н1.5 `rid`: имя строки `<sub>/requests/<rid>` и метки
`objects/<sub>/commands/<rid>`; Н4 «просьба: неверный … rid»; ADR-0060). Участники — дверь просьб консоли
(`POST /<sub>/requests`: rid по шаблону `requests.key` или `r-<sha16(Idempotency-Key)>`; отказ — 400 RequestError, Н4) и
воркер, который пишет просьбу сам ([глава 3.6](../../../03-worker/spec/03.6-worker.norms.md) Н1.5, `worker.requests`: отказ —
`RequestRefused`, счёт `filings.refused`); форма элемента `rids` учёта `asked` ([семья `asked`](../../data/asked.form.yaml)).
Байты пишет «Спецификация» (ADR-0083, стадия B; правило — «Архитектор», 2026-10-06, после четырнадцатого ревью; запрет
`free-` — решение «Архитектора» 2026-10-18); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Пакет перенесён из `Source/tests/testdata/rid.tsv` (стадия A) вместе с уроком 6 (стадия B, ADR-0083 доп. (1)); байты
таблицы — те же, включая заголовок-комментарий (его «М10/8 Н1.5» — прежний адрес нормы, ныне [договор просьбы и её метки](../../../common/contracts/request-mark.md) `rid` (разбор ревью стадии B 6–7, № 24); копия продукта
сверяется с этими байтами).

## `rid.tsv`

UTF-8, LF, поля через TAB. Строки с `#` и пустые пропускаются; строки заголовка нет. Два поля:

| Поле | Значение |
|---|---|
| `rid` | имя просьбы — строка JSON; знак Cc, Zl, Zp записан экранированным (`\u0085`, ` `), прочие знаки — как есть |
| `verdict` | `ok` — имя принимается; `refused` — отказ |

## Правило

Не больше 200 **байт** UTF-8, не пусто, не `.` и не `..`; без `/ \ " '` и знаков Unicode Cc, Zl, Zp (управляющие, U+0085,
U+2028, U+2029); не начинается с `free-` — это семья просьб ресурса `<sub>/requests/free-<server>-<volume>`
([P/05](../../../05-resource/spec/05-resource.norms.md) Н1.4 `free_ask`). Регистр значим: `Free-a` — не `free-`.

Последняя строка таблицы — форма `rid` по ключу подателя `<подсистема подателя>.<ключ>` (договор просьбы `rid`; ADR-0091
доп. (23) п. 2): точка в имени допустима, грамматика та же.

## Команда стенда `rid`

Ключ `stand` профиля `06-console` (раздел «Раскладка по процессам» [общего README приёмки](../../../common/acceptance/README.md));
шаблон с `{input}` — путь файла с одним объектом JSON `{"rid": <ячейка rid как есть>}` (ячейка — строка JSON, раннер вставляет
её лексему без второго слоя кавычек и без повторного раскодирования); полей, кроме `rid`, нет. Ответ — `{"status": "ok"}` или
`{"status": "refused"}`, сверка с колонкой `verdict`; отказ имени — код 0 со `refused`, не код 2. Вход не по форме: не объект,
нет или повтор `rid`, незнакомое поле, `rid` не строка. stdout — ровно один JSON-объект и LF: первый байт `{`, после объекта — LF и конец; лишние поля, байты, CRLF, пробелы
вокруг — FAIL строки; форматирование внутри объекта допустимо; служебное — в stderr. Код 0 — вычислено; вход не по
форме — код 2, stdout пуст (догадка стадии C C06-F2-IO-01, решение «Архитектора» 2026-10-23).

## Прогон

Сторона раскодирует ячейку `rid` как строку JSON и проверяет вердикт своей проверкой имени — одной функцией у двери и у
воркера. Таблица проверяет грамматику, не подстановку шаблона `requests.key` (её отказ называет поле шаблона — Н1.5 `rid`,
шаги приёмки) и не вычисление `r-<sha16(Idempotency-Key)>`.
Кто исполняет — дверь просьб консоли (`06-console`: rid по шаблону и `r-<sha16>`, форма `rids` учёта `asked`; P/06.4 Н3 «подать просьбу» шаг 1, Н4) и воркер-податель (`03-worker`, P/03.6 Н1.5 `worker.requests`) — все строки одной проверкой имени (договор просьбы и её метки `rid`) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
