# Векторы: жнец над просьбой дозаписи и строкой ресурса

Владелец — глава P/06.4 ([нормы](../../spec/06.4-console.norms.md) Н3 «жнец», `gone`, `expired`) через [договор просьбы и её
метки](../../../common/contracts/request-mark.md) «Состояния исполняемой просьбы и её метки» (строки «жнец, дозапись, …»;
догадка стадии C C06-GONE-FETCHED-33-01, решение «Архитектора» 2026-10-25; запрос VMS «срок просьбы», решение «Архитектора»
2026-10-29). Участник — жнец консоли. Байты пишет
«Спецификация»; строки составлены по тексту договора, не кодом реализаций.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

**Вход** — объект JSON (решение одного прохода жнеца над одной строкой, чтения подменены входом):

| Поле | Значение |
|---|---|
| `profile` | `fetched` — дозапись ADR-0054 (`requests.outcome: fetched`); `resource` — строка ресурса `requests/free-<server>-<volume>` |
| `resource_state` | у `resource`: `resource_state` сервера-хозяина из ключа (`live`, `unreachable`, `unknown`, `silent`) или `noanswer` — хранилище не ответило |
| `settle`, `ttl` | ключи `requests` манифеста, секунды; ключа `ttl` может не быть. `REAP_AFTER` — константа 60 (P/06.4 Н1.5) |
| `row` | `{unit, digest}` строки просьбы, прочитанной подтверждённо |
| `row_age` | возраст строки (по правилу `ttl` договора), секунды |
| `unit` | чтение строки единицы-адресата: `present`, `absent` (строки нет или надгробие, подтверждено), `unknown` (не подтверждено) |
| `mark` | метка `objects/<sub>/commands/<rid>` как прочитана или `null` — нет |
| `mark_age` | возраст первого подтверждённого чтения метки, местные монотонные секунды, или `null` |
| `fetched_age` | возраст первого подтверждённого `fetched` держателя по этой строке или `null` — не было |

**Выход** — `{"write_mark": "gone" | "expired" | null, "remove_row": true | false}`: какую метку писать создание-однажды и снимать
ли строку (по CAS, с rid из `asked`) в этом проходе. Сравнение — JSON по значению.

38 строк: у `resource` — 10 (четыре состояния и неответ × возраст 3599 и 3600 при `ttl` 3600: снимать только `silent` ∧ ≥ `ttl`; C06-FREE-OWNER-33-01); у `fetched` — 28: `gone` к отсутствующей единице (создание, возраст 0, 29.999, 30 при `settle` 30, иной `digest`), неизвестное
чтение единицы, обычная дозапись без метки (по одному `ttl` не снимается; `fetched` и `settle`); срок дозаписи без держателя,
граница 3660 (`ttl` 3600 + `REAP_AFTER` 60) — 19 строк `expired-*` и `gone-after-expired`: возраст 3659.999 — ничего, 3660, 3661,
7200 — `expired`; `fetched` раньше — метки нет, снятие по его `settle`; `ttl` 0 и нет ключа — срока нет; единицы нет — `gone`, не
`expired`; чтение единицы не подтверждено — ничего; метка `gone` раньше и `expired` раньше — вторая не пишется; `settle` метки
`expired` (0, 29.999, 30), иной `digest`; поздний `fetched` не сдвигает `settle`.

## Прогон

Без стенда: сторона подаёт вход своему решению жнеца и сравнивает выход. Гонки CAS, повтор записи метки по `conflict` и
освобождение учёта — чтением договора; сценарий 07 приёмки главы 6.4 — `gone` на стенде, сценарий 11 — `expired` на стенде.
Кто исполняет — жнец консоли (`06-console`, оба профиля: P/06.4 Н3 «жнец» и снятие строки ресурса без живого хозяина по `ttl`; договор просьбы и её метки, строки «жнец …»). Вход пишут другие роли и решения жнеца не исполняют: `fetched` пульса — воркер-держатель (`03-worker`, P/03.6 Н3 «Дозапись»), строку `free-*` — ресурс (`05-resource`, P/05 Н1.4 `free_ask`; её снятие под отметкой — `relieve`, не жнец) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
