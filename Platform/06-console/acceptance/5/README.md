## Стенд сц. 01, 02, 04–12 (из М10/09), 18 и 19

До каждого автоматического сценария остановить процессы предыдущего, создать отдельные пустые строковое/объектное хранилища и очистить переменные/память повторов. Загрузить неизменённые testsub и testsub2 и третий манифест этого каталога `probe-x.subsystem.yaml` (имя с «-»: `metrics.prefix` — `probe_x`, мутационная проверка 7cecaf2 № 40); root — testsub, второй доступен под /testsub2, третья — под /probe-x; домена нет, обращения с петли. Фоновые controller/resource/worker до @start не работают. Сборка — схема 1; хранилище свежее и пустое — строки platform/schema нет, раннер её не пишет (чтение коммитов «cammeta-acceptance» 2026-10-20). Для каждого POST создания единицы раннер выдаёт свежий Idempotency-Key, сохраняемый только для повторов того же шага. POST таблицы не получает этим обещания памяти повторов.

Без воркеров размещения нет; счётчик c4 создаётся только в 04. Доменный вход, закрытые grants, CSP и повтор логического действия проверяются отдельным стендом/тестом модуля, не этим TSV.

- **Процессы.** Сц. 08–10 поднимают процессы директивами «Стенда» (`@start worker`, `@start resource`,
  `@start controller testsub2`); до `@start` фоновых процессов нет. Воркер — `w-1` подсистемы `testsub` на `srv-a`.
- **Дверь хранилища.** Сц. 07 пишет строку intent мимо контроллера: `@as testsubcontroller store` — сокет роли
  контроллера `testsub` по файлу прав установки (P/02.5). Контроллера `testsub` в сц. 07 нет, строку никто не
  перепишет.
- **Место без строки (сц. 19).** Воркер `t-1` подсистемы `testsub2` на `srv-a` (`@start worker testsub2 t-1 on srv-a`);
  его экземпляр — `holder` слота (`$t1`). Строки удержания `testsub2/holds/s9` (экземпляр `$t1`) и `s8` (чужой
  экземпляр `box:1:ffffff`) пишет ролью воркера `@as testsub2worker store` мимо воркера; строк `shelves/s9`, `s8` нет,
  кандидатами воркера они не становятся. Шаг 4 ждёт пульс `t-1` в `/testsub2/servers`. `s9` — действующее удержание:
  200, `server` — поле пульса; `s8` — экземпляр не тот, удержание не действует, строки места нет — 404 `s8@?`

- **Порча пульса.** Сц. 08 портит пульс директивой `@spoil object`: после неё пульс нечитаем (P/05 Н1.1). Воркер до

## Полная форма и воспроизводимость

Подмножество expect не заменяет проверку полной HTTP-формы [контракта урока](../../spec/06-console.api.openapi.yaml): проверить обязательные поля, типы, Content-Type, специальные заголовки и отсутствие тела у HEAD/204. В строках ожиданий `$имя` впервые связывается только после успешного совпадения всего ответа; следующие употребления сравнивают, запросы используют только уже связанные значения. Неудачная попытка @until не меняет переменные. @until повторяет чтение до указанного местного срока, не мутацию; после истечения — FAIL с последним ответом. @any допускает любое значение присутствующего поля, @absent требует отсутствия; они не подменяют типы полной схемы. JSON-объект сравнивается по подмножеству (`{}` на любом уровне — ровно пустой объект: словарь общего README, ACC-EMPTY-OBJECT-01), массив — по длине и порядку. Сырой HTML/текст сравнивается как байты UTF-8 с заданной подстрокой, не разбирается как JSON.

Успешный открытый /session содержит login_url (сценарий сессии — [приёмка главы 6.3](../3/README.md)).

## Дополнительная проверка чтением

R36-08: стабильный active intent направляет u на w-2 при placement=w-1 или его отсутствии — /where использует w-2; target="" даёт 404 с причиной intent. Чужой id/idle используют placement. Смена версии intent требует повторить чтение, неответ любого обязательного чтения — 503. Пульс читается после эффективного решения; отсутствие двери не превращается в null. Сценарий 04 проверяет только отсутствие размещения, active/перемежения в текущей TSV не исполняются.

Прогон 36 (Kimi): проверить оба исхода отсутствия v и смонтированные /servers, /unplaceable, /where, /metrics и страницу. Для where(table,place): неизвестная таблица 404 до unit; затем форма/view, подтверждённое удержание и пульс, ошибка чтения 503, отсутствие удержания 404 с X-Unreachable. door необязателен и появляется только при подтверждённом адресате/держателе/подписанте; выдача журналируется. Сц.04/6 видит пустые resources и не проверяет поля ResourceRow. (Петля, доверие, Origin и аварийный вход — [приёмка главы 6.3](../3/README.md).)

R37 (Codex): проверить каталоги root/mount: имя where не грузится; два отдельных корректных манифеста с mount b и семьёй root b не образуют допустимого каталога. Повторить для unit.rows и таблицы (включая списковую), оба направления пары и root каждого выбора. У GET/HEAD обеих mounted-страниц одинаковые наборы кодов, 200 отсутствует. Список делегирования не добавляет GET одной единицы владельцу (глава 6.1).

Это предмет ручной проверки спецификации и будущей проверки реализации. Подготовленные запросы, чтение и конечные модели автора не являются выполненным стендовым испытанием.
