# Приёмка P/06.8 — папки кластера (стенд)

Норма главы — [`06.8-console.norms.md`](../../spec/06.8-console.norms.md) Н5. Стенд, словарь директив и дверей — [общий README приёмки](../../../common/acceptance/README.md#словарь-директив-и-дверей).
Всего 12 сценариев / 180 шагов.

**Сухого прогона реализацией нет.** Сценарии составлены чтением норм и контракта; `index` и другие значения хранилища сценарий связывает из ответа, а не считает заранее. Глава входит в приращение прав и ждёт зачёта приращения B.

## Подготовка

Консоль с манифестами `testsub` (объявляет `display.tree.folders: true`) и `testsub2` (не объявляет: он стоит в сц. 03 как подсистема без папок), домена нет, запросы идут от одного вызывающего с нужными правами. Каждый сценарий начинается с
пустого хранилища на своём экземпляре: `GET /folders` сверяет весь список, поэтому чужая папка меняет ожидание. Дверь без префикса — консоль. Роль двери `store` — `console`: она читает `platform/*` и строки подсистем ([P/02.5](../../../02-installer/spec/02.5-installer.norms.md) Н1.4).

Жнец папок на стенде работает с периодом нормы `FOLDERS_REAP_EVERY` 60 с: сценарии 06 и 10 ждут его `@until 90`. Этот срок — верхняя граница: шаг кончается, как только признак есть. Снов (`@sleep`) нет.

## scenarios.tsv

Формат — [словарь директив и дверей](../../../common/acceptance/README.md#словарь-директив-и-дверей). Подмножество полей, `$имя`, `@any`, `@big(N)`, `@header`, `@key`, `@as`, `@until`, `ASSERT` — как там. Запись `{"items": null}` значит: строки нет.

- `$f`, `$g` и подобные связывают id папки из ответа `201`. Значение id сценарий не задаёт: 128 случайных бит выбирает консоль.
- `$i`, `$j` связывают `index`: сравниваются только на равенство. `index` ответа `PUT` равен индексу строки в хранилище — сц. 02 шаги 4–5.
- Сц. 03 шаги 11–14: ключ `testsub/counters/<1007 байт>` — ровно 1024 байта: строка единицы представима, ключ членства длиннее предела — `400 bad member`. Сосед на 989 байтах даёт ключ членства ровно 1024 байта и проходит.
- Сц. 04: цепочка из восьми папок — `FOLDERS_DEPTH_MAX`; девятая — `too deep`. Шаги 13–16: надгробие предка в середине цепочки.
- Сц. 05 шаг 8: запись поверх надгробия идёт пакетной дверью, потому что `PUT` и `DELETE` такой папки отвечают 404.
- Сц. 09: граница `FOLDERS_PER_UNIT_MAX`: восьмая папка проходит, девятая — 400, удаление единицы на границе снимает все восемь.
- Сц. 10 шаг 5: дверь хранилища снимает строку единицы мимо двери консоли, как контроллер по `placement.ends`: у `testsub` такого срока нет, поэтому запись делает сам сценарий, ролью `console`, как сц. 19 главы 6.1. До прохода жнеца член висит; сценарий ждёт только конца окна, потому что момент прохода стенду не подчинён.
- Сц. 11: пакет единицы с папкой. Шаги 6–7 и 12 — отказ по `no chain`, `no membership`, `parent gone`; `$ip` — индекс родителя, `$t` — индекс его надгробия.
- Сц. 12 шаги 12–14: строку с пустым `name` пишет дверь хранилища ролью `console`, мимо двери папки. Папка с этим id не живая и не мёртвая: `garbled` в списке, 503 по одной.

## Что проверяется чтением

| Предмет | Почему не сценарий |
|---|---|
| строгая гонка «чтение — запись»: стражи единицы и цепочки, страж отсутствия строки членства, `412 parent moved` | окно между чтением и пакетом HTTP-стенд не открывает; последовательные порядки — сц. 07, 08, 11 |
| права таблицы Н3 «права папки», права строки папки в пакете | нужен стенд домена с грантами и форма входа `may` с `folder:`: она вносится другой правкой этого приращения |
| `FOLDERS_MEMBERS_MAX`, `FOLDER_ROW_MAX`, числа Н1.3 | граница требует тысячи единиц; числа считаются |
| неподтверждённое чтение: 503, жнец ничего не снимает | нужен отказ хранилища на чтении конкретного ключа |
| лента `/changes`, индекс надгробия в сообщении | ADR-0094 B2 ещё не внесено |
| член из второй подсистемы | `testsub2` держит `display.tree.group_by`, а `display.tree.folders` рядом с ним запрещено; код один, различается только префикс ссылки |

План сценариев прав, когда норма `may` внесена (стенд домена, `@person`, строки грантов — как [приёмка главы 8.4](../../../08-domain/acceptance/4/README.md)):

1. человек с `edit` на единицу без `admin`, единица в папке: `DELETE` единицы — 200, папка без неё;
2. создание единицы со строкой папки без `admin` над папкой — 403, ничего не записано;
3. запись папки без `admin` над ней — 403; с `admin` на `folder:<предок>` — 200;
4. добавить и снять единицу с `admin` над папкой, без `admin` на единицу — 403;
5. удалить папку со строкой роли `folder:` на потомке без `admin` на `*` в `sub` этой строки — 403.
