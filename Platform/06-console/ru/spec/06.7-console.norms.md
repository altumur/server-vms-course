# P/06.7 — Консоль кластера в домене: нормы

Текст производный от `spec/06.7-console.norms.md`, руками не правится: источник — английский [`spec/06.7-console.norms.md`](../../spec/06.7-console.norms.md), правка идёт в него, русский пересобирается переводом.

Канон главы 6.7 урока P/06 «Консоль кластера» (модуль «Платформа»).
**Глава позднего слоя: вводят уроки 8 и 10** (читать после уроков 8–10); её соседи по контракту —
главы урока [P/08](../../../08-domain/ru/README.md) (процесс `domain`), агент [P/09](../../../09-agent/ru/README.md) и консоль домена
[P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md). Лекция (`ru/06-console.md`, для человека, в выгрузку не входит),
[контракт](../../spec/06-console.api.openapi.yaml), [инструкция](06-console.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/7/README.md). Здесь — консоль кластера как дверь кластера к домену: дверь книги этого члена;
пересылка `/domain/*` в консоль домена (переходы 1–2 [договора пересылки](../../../common/ru/contracts/forwarding.md)) и `where`
члена; клиент TLS консоли к другому кластеру (`peer`); пересылка подписанту дверей переноса; сессия с грантами (`may` по
копии грантов кластера) и аварийный вход; дверь семей ключей `GET /domain/keys`; `GET /api/held` и `GET /api/backup`;
значение общего поля при чтении (`resolve`, `GET /domain/shared/<sub>`).

Раздел с главой 6.3: форма `/session` и шаги
`identity` — [глава 6.3](06.3-console.norms.md) N1.3 и [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md)
(P/06.3-03); здесь — `may` по грантам у сторожевой, порядок двери аварийного входа, `GLASS_SESSIONS_MAX` и предел её
попыток. Таблица пересылки — [договор пересылки](../../../common/ru/contracts/forwarding.md) «Двери домена». Что консоль домена делает с пересылкой (приём, сторожевая по
`domain/grants/domain`, передача процессу) — урок [P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md); что
процесс `domain` исполняет — главы урока P/08. Ссылка «P/0N[.K]» — урок или глава модуля; «глава 6.K» — глава этого урока.
Id норм — `P/06.7-MM`.

## N1 Форма

**Время.** Строк и объектов со временем глава не пишет. Срок аварийной сессии `until` (N1.10) — время по [канону N0 P/01.1](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке). Строка журнала главы (`domain.forwarded`, `access.break_glass.*`, `domain.shared.refused`) — `t` по [договору журнала событий](../../../common/ru/contracts/event-journal.md).

Документы, которые двери отдают как прочитаны (`/api/held`, `/api/backup`), несут время своих владельцев.
**Данные** ([каталог](../../../common/data/catalog.tsv)):
- пишет: `domain/member-want/<part>` (create), `<events root>/audit/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `<sub>/heartbeats/<name>`, `domain/<sub>/<manifest:domain.books>/*`, `domain/<sub>/<manifest:domain.books>/*/<part>`, `domain/root`, `domain/anywhere`, `platform/manifest/<sub>`, `domain/view`, `domain/<sub>/<manifest:domain.books>/<member>`, `domain/<sub>/<manifest:domain.books>`, `domain/member-list/<part>`, `domain/member`, `domain/keys`, `domain/revoked`, `domain/grants`, `domain/roles`, `domain/disabled`, `domain/break-glass/<cluster>`, `domain/holder`, `domain/backup-taken`, `domain/backup`, `domain/shared`, `domain/shared-docs/rev-<rev>`.

Своих строк у главы нет.

Дверь книги читает строку держателя `domain/<sub>/<книга>/<CLUSTER>` у кластера, который держит
домен (`holds` — объект `domain/view`), иначе копию члена `domain/<sub>/<книга>` (N1.1).

Пересылка читает объект
`domain/view` (`holds`, `view.url`) и `domain/member-list/<part>` (запись держателя; `Entry.ca` назначения для `peer`) (N1.4,
N1.6, N1.7).

Сторожевая с грантами — копию `domain/grants` и `domain/disabled`, условие чтения — договор права (N1.9; токен — `domain/keys`,
`domain/revoked`, глава 6.3).

Аварийный вход — `domain/member` и `domain/break-glass/<этот кластер>` (N1.10).

`/domain/keys` —
строки под `domain/` этого хранилища и `domain/keys` (N1.11).

`/api/held` читает `domain/holder`, `domain/keys`,
`domain/backup-taken` (N1.12).

`/api/backup` читает `domain/member-list/<part>`, указатель `domain/backup-taken`, объекты
`domain/backup` и копия общего документа `domain/shared` (N1.13).

Значение при чтении — у члена объект `domain/shared`
(копия общего документа), у держателя — строка-указатель `domain/shared` и объект `domain/shared-docs/rev-<rev>`, который
она называет (N1.14).

Объекты консоль читает дверью объектов
[P/05](../../../05-resource/ru/spec/05-resource.norms.md) (чтение `/v1/objects` — любая роль с комплектом, P/05 N2 «Допуск к
дверям ресурса»), не строками прав ([P/02.5](../../../02-installer/ru/spec/02.5-installer.norms.md) N1.4).

Журнал консоль
дописывает в `audit/console` по договору журнала событий (участник `append`, владелец — P/05).

Строк вкладов `<sub>/<manifest:domain.books.from>` (владелец — [P/03.7](../../../03-worker/ru/spec/03.7-worker.norms.md)) нормы
главы не читают: дверь книги читает строки книги, а не вклады; сборка вкладов — у держателя (P/08.5) и агента (P/09.1).

### N1.1 Дверь книги этого члена

Дверь `GET /domain/<sub>/books/<книга>` — у консоли кластера, члена и держателя (N2). Дверь книги читает книгу этого члена: кластер держит домен (N1.4 `holds`) — строку `domain/<sub>/<книга>/<CLUSTER>`, иначе — копию `domain/<sub>/<книга>`. Строки книги у члена нет (домена нет, книга ещё не пришла) — 404 `{error: "no such book shown", detail: "not delivered yet"}`: пустая книга — это `""` с пустым `missing`, а не отсутствие строки.

Поля вне `show` и секреты в ответе двери книги не бывают.

Сегмент `<книга>` сравнивается с именем книги манифеста байт в байт: `%72olls` — не `rolls`, 404.

Раздел книги `to: "*"` дверь этого члена не отдаёт: копия приходит по просьбе, за обход. `GET /domain/<sub>/books/<книга>/*/<раздел>` — строка таблицы «Двери домена», консоль кластера пересылает держателю ([P/08.5](../../../08-domain/ru/spec/08.5-domain.norms.md) N2).

Объявление книги и `show` — [P/02.1 N1.2b](../../../02-installer/ru/spec/02.1-installer.norms.md); сборка у держателя и строка
`domain/<sub>/<книга>/<член>` — [P/08.5](../../../08-domain/ru/spec/08.5-domain.norms.md) N1.3; строка книги у члена —
[P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `member_row`.

Книга — наблюдение, не власть (P/08.5 N1).

### N1.2 Консоль кластера — дверь кластера к домену

Двери людей домена (`/domain/*`) живут у консоли домена — процесса `domainconsole` на коробке держателя (урок
[P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md); ключей у неё нет).

Двери процессов (`/api/*`) — у процесса
`domain` (урок P/08). Глава говорит, как до них доходят из любого кластера.

`door`: консоль кластера (P/06) — единственный адрес кластера для домена. `door`: консоль кластера — единственная дверь людей и процессов кластера к `/domain/*` домена: шлюз, воркер, страница идут через консоль своего кластера. `door`: шлюз и воркер — клиенты своего кластера: URL — `own_url`, проверка сервера — `own_client` договора сертификата роли, роль `console`. `door`: второго адреса консоли домена в записях и прямого пути процесса к ней нет.
- `process`: двери процессов `/api/*` (агент — P/09.1, ретранслятор — P/09.2, токены — P/08.7) идут своими адресами
  (`DOMAIN_URL`, `RELAY_URL`), не через консоль; кроме входа людей `POST /api/login` (P/08.4 N1.2) — строка таблицы N1.3:
  страница ходит к своей консоли.
`local`: консоль кластера отвечает сама только на: /domain/\<sub>/books/\<книга> (N1.1, книга этого члена); `/domain/at/…` (N1.6); двери переноса (N1.8, N1.12, N1.13); `GET /domain/keys` (N1.11); `GET /domain/shared/<sub>` (N1.14). `local`: /domain/\<sub>/books/\<книга> не GET — 405 (N4).
`forwarded`: пары (метод, путь) таблицы N1.3 — в консоль домена (N1.4, N1.5). `forwarded`: прочее под `/domain/` — 404 not a domain route, держатель не зовётся.

### N1.4 Адрес и один переход

- `holds`: этот кластер держит домен ⟺ объект `domain/view` его хранилища читается и `view.holder` = `CLUSTER` консоли.
`to`: `holds` → `view.url` (консоль домена своей коробки, N1.4 `view.url`). `to`: при `holds` переход 2 к `view.url` — клиент своего кластера, договор сертификата роли `own_client`. `to`: при `holds` host перехода 2 — `SERVER_NAME`, если хост `view.url` — литерал петли.
- `to`: когда этот кластер не держит домен (`holds` ложно), держатель — поле `holder` записи срока `domain/holder` этого хранилища (договор записи срока): копия `domain/member-list`
  здесь неполна, свой раздел и запрошенные (P/09.1 N1.1) → CLUSTERS[держатель] (консоль кластера держателя).
- `view.url`: поле `domain/view` (P/08.1 N1.4): `DOMAIN_CONSOLE_URL` окружения процесса `domain` — адрес двери
  его консоли домена; переменной нет — поля нет. Вид пишет держатель, поэтому адрес верен и после передачи.
`CLUSTERS`: окружение консоли кластера, для держателя и первого контакта; форма, «не читается» (503) и пустой список — договор файла окружения `CLUSTERS`. `CLUSTERS`: адрес прочего члена — `Entry.url` его строки раздела (N1.6).

Строка `via` (`X-W2C-Via`, один переход) — [договор пересылки](../../../common/ru/contracts/forwarding.md) «Один переход»
(владелец — этот урок).

### N1.6 Чтение у члена — `/domain/at/<кластер>/…`

```yaml
routes:    GET /domain/at/<кластер>/<sub>/where/<id>
           GET /domain/at/<кластер>/<sub>/where/<таблица>/<место>?unit=<id>
           GET /domain/at/<кластер>/<sub>/<имя>[/<id>]
           GET /domain/at/<кластер>/events
           GET /domain/at/<кластер>/<sub>/<маршрут>/<id>[/…][?place=<таблица>/<место>]
           GET /domain/at/<кластер>/<sub>/heartbeats
```

- `routes`: GET /domain/at/\<кластер>/events идёт с query двери журнала: `subsystem`, `unit` (журнал правила чужого кластера).
- `routes`: \<маршрут> — элемент `door.routes` манифеста без `role`.
- `routes`: GET /domain/at/\<кластер>/\<sub>/heartbeats — только у `<sub>` с `heartbeat.door`; имя `heartbeats` судится раньше \<имя>: зарезервировано (P/02.1), `unit.rows` и таблицей не бывает.
`routes`: `<sub>` — манифест каталога этой консоли. `routes`: \<таблица> — `places.table` этого манифеста (P/04 N1.3 `places`; дверь `/where/<table>/<place>` — P/06.5). `routes`: \<имя> — `unit.rows` или таблица манифеста, не `service: true`.
- `routes`: query идёт как пришёл.
`to`: \<адрес>/\<sub>/where/…, \<адрес>/\<sub>/\<имя>[/\<id>], \<адрес>/\<sub>/heartbeats, \<адрес>/\<sub>/\<маршрут>/\<id>[/…], \<адрес>/events — тот же хвост. `to`: адрес — `Entry.url` строки раздела кластера, нет поля или строки — CLUSTERS[кластер]. `to`: корень или маунт решает принимающая: консоль, чья корневая подсистема — `<sub>`, отвечает на `/<sub>/where/…` как на `/where/…`.
- `member`: кластер — не этот кластер и есть в строке domain/member-list/\<раздел имени> этого кластера; копия неполна (P/09.1 N1.1): строки раздела нет — член не судится, запрос идёт по `CLUSTERS`, клиент `peer` кладёт просьбу (договор peer `client`).
`answer`: как N1.5. `answer`: дверь в ответе выдала консоль члена своим ключом, пересылающая её не переподписывает.
`only`: этим путём идут только формы `routes`. `only`: только GET (и HEAD — как GET без тела, N1.3): правки идут через держателя (P/08.6); маршрут двери другим методом, POST сверки удержания тоже, этим путём не идёт: его судит и исполняет кластер записи у себя, читатель другого кластера получает предел.
`read`: чтение чужого сверх вида домена: право судит консоль цели своей сторожевой и своими грантами, токен человека идёт как у любой пересылки. `read`: консоль цели не слышна — отказ пересылки 502 или 503 как есть, данных нет. `read`: член за NAT: адреса нет — 404 no console known, читатель берёт вид домена (P/08.1 N1.4, N1.4a).
- `route`: консоль цели отвечает на этот хвост «Маршрутом двери» (P/06.3 N1.9) по токену человека: своя сторожевая, `view` на единицу `<sub>/<id>`, живой держатель, журнал `door.issued`.
`route`: билет дальше консоли отправителя не идёт. `route`: токен человека дальше консоли цели не идёт: воркеру цели — токен двери на этого человека.
- `route`: `?place` — держатель и токен места как /where/\<таблица>/\<место>?unit=\<id> (P/06.5 N3), воркеру не уходит.
`route`: маршрут двери у члена — только GET и HEAD. `route`: ответ маршрута двери у члена — JSON.
`route`: `AT_ROUTE_WAIT` вместо общего `PASS_WAIT`; это нормативный бюджет, не результат замера. `route`: `FORWARD_WAIT` этой пересылки — локальная строка `forms/runtime-constants.tsv`; это нормативный бюджет, не результат замера.
- `route`: дверь спрашивает соседей с общим `PASS_WAIT`.
`route`: предел: ответ больше `FORWARD_MAX` из N1.5 — 502 answer too large, читатель сужает окно; цена — на вызов одна пересылка и одна строка `door.issued` у цели. `route`: читатель без гранта у цели — 403 как есть. `route`: байты этим путём не идут: кусок — адрес клиенту, байты мимо консоли. `route`: член записи за NAT адреса не даёт, этот путь ему — 404 no console known.
`pulse`: `GET /<sub>/heartbeats` у консоли (у корневой подсистемы и `/heartbeats`; `view` без единицы, договор сторожевой `need`) → 200 `{rows: [{worker, server, ts, age, worker_state, fields}]}`: по элементу на пульс \<sub>/heartbeats/\<слот>. `pulse`: элементы `rows` — по `worker` в байтах UTF-8. `pulse`: `worker`, `server`, `age`, `worker_state`, нечитаемый пульс, неответ и 503 unavailable — как `rows` в `GET /{rows}` (P/06.1 N2). `pulse`: `ts` — поле пульса.
`pulse`: `fields` — только поля `heartbeat.door` манифеста (P/02.1 N1.2), какие в пульсе есть, как есть: прочие поля ключами называют единицы, а `view` здесь без единицы. `pulse`: `<sub>` без `heartbeat.door` — двери нет: 404 у самой двери, not a route handed to a member у `/domain/at`. `pulse`: `domain.ref` и `domain.view_pulse` дверь не читает: документ общий на домен, а его состояние лежит в пульсе подсистемы вне вида.

### N1.7 TLS между кластерами — сторона консоли кластера

Комплект роли, сертификат, центр и отзыв — [P/02.4 N1.6](../../../02-installer/ru/spec/02.4-installer.norms.md), [договор
сертификата роли](../../../common/ru/contracts/role-certificate.md): один центр на кластер. Отпечаток центра, публикация
`tls_ca`/`tls_ca_certs`, `Entry.ca`, строка `ca-certs`, `on_accept`, `relayed`, `admin` — [P/08.3 N1.6](../../../08-domain/ru/spec/08.3-domain.norms.md).

- `client`: клиент двери другого кластера по `https://` — договор peer (`Platform/common/contracts/peer.md`) «Клиент и
  первый контакт»; консоль кластера — клиент роли `console` к консоли члена или
  держателя (договор пересылки `tls`).
- `first`: `DOMAIN_CA`, `RELAY_CA` при первом контакте, `RELAY_MEMBER` — там же (агент, P/09.1 N1.7).
- `roles`: роли комплектов процессов домена — P/10 N1.4 `roles` (одно место; договор сертификата роли); консоль кластера —
  `console`.
- `revoke`: договор peer «Клиент и первый контакт» `revoke` (одно место).
`server`: серверная сторона дверей между кластерами — два класса: класс `role` — дверь роли консоли домена (договор сертификата роли «Серверная сторона: класс `role`», P/10-11); класс `signed` — договор сертификата роли «Серверная сторона: класс signed» (P/08.0-02, P/09.2-07). `server`: сервер обоих классов предъявляет лист своей роли с EKU serverAuth (договор сертификата роли `cert`).
`server`: класс `signed` — и консоль кластера: всё входящее из других кластеров на её слушателе (переход 1 — N1.4 и договор пересылки; `/domain/at/…` — N1.6; `/api/prepare`, `/api/take` — N1.8; `/api/held` — N1.12; `/api/backup`, `/api/backup-part` — N1.13). `server`: на этом слушателе консоль кластера предъявляет лист роли `console` с EKU serverAuth. `server`: на этом слушателе консоль кластера сертификата клиента не запрашивает. `server`: на этом слушателе консоль кластера в рукопожатии по центру не отказывает; пропускает запрос или нет — норма двери (сторожевая по `Authorization` — P/06.3, P/08.4; подпись — N1.8, N1.13; открытая — N1.12).
- `server`: `X-Operator: console` консоль кластера не признаёт; снимает всегда
  (договор пересылки `x_operator`, «Принять консолью» п. 2).
- `callback`: обратный вызов по билету — отдельный слушатель консоли с обязательным листом роли подсистемы (договор сертификата роли «Лист обратного вызова»); основной
  слушатель выше им не меняется.
- `stand`: проверяется чтением: TLS между кластерами на одной машине стенд не поднимает (P/02.4 N1.10; TLS-стенд —
  `common/acceptance/tls`).

### N1.8 Пересылка подписанту

`routes`: `POST /api/prepare`, `POST /api/take`, `POST /domain/move` у консоли кластера → дверь `SIGNER_URL` своей коробки (P/08.2 N1.3). `routes`: путь и тело идут подписанту как пришли; подписанные заголовки `X-W2C-Member`, `X-W2C-Time`, `X-W2C-Signature` и `Idempotency-Key` — как пришли. `routes`: пришедший от клиента `X-W2C-User` консоль снимает всегда.
- `order`, шаг 1 (шаги идут по порядку, шаги 1–5): пришёл `X-W2C-Via` — 400 one hop.
`order`, шаг 1a: `/domain/move` с `X-W2C-Time` или `X-W2C-Signature` (P/08.8 N1.8 `by_file`): не с петли договора сторожевой (определение там) или с заголовком `Forwarded`, `X-Forwarded-*`, `X-Real-IP` или `Via`: запрос пришёл через прокси — 403 denied. `order`, шаг 1a: у `/domain/move` с `X-W2C-Time` или `X-W2C-Signature`: заголовка нет, время не по форме или вне окна — 401 со словом, до чтения тела: тело закрыто подписью, поэтому сама подпись судится на шаге 3.
- `order`: отказы шагов 1a и 3 — журнал с пределом, P/08.8 N1.8 `journal`.
`order`: у `/domain/move` подпись сошлась — тревога по P/08.8 N1.8 `journal`, до пересылки, и строка исхода по ответу. `order`: сбой записи тревоги пересылку не останавливает.
- `order`, шаг 2: тело больше 1 МиБ — 413.
- `order`, шаг 3: `/domain/move` по подписи — сообщение move|\<кластер>|\<время>|\<sha256 тела> корнем `domain/root` своего кластера (договор подписи просьбы), строки нет — 403 denied: домена нет, не сошлось — 401 со словом, токен не спрашивается.
- `order`, шаг 3: иначе `/domain/move` — сторожевая по режиму консоли:
  личность и право администратора домена (N1.9; договор сторожевой `need`: шаг 1 или шаг 4a договора права по таблице ролей этого кластера) — 401 / 403.
- `order`, шаг 3: prepare и take доказывают
  себя подписью (договор подписи просьбы; P/08.8 N1.7), личности не спрашивают.
- `order`, шаг 4: нет `SIGNER_URL` — 404 (ниже).
`order`, шаг 5: переслать с `X-W2C-Via: <CLUSTER>`, у `/domain/move` — и с X-W2C-User: \<имя, доказанное шагом 3, по подписи — "recovery file"; у аварийного входа — имя сессии; у открытой консоли — operator: имя, которое сторожевая даёт петле в open (договор сторожевой open), как в прочих by консоли без домена> (`by` журнала `domain.moved`, P/08.8 N1.8; процесс верит ему только на соединении консоли своего кластера). `order`, шаг 5: сроки — 10 с у prepare, 90 с у take и move (P/08.8 N1.7, N1.8). `order`, шаг 5: к `https://` `SIGNER_URL` — клиент своего кластера договора сертификата роли `own_client`, роль `domain`.

### N1.14 Значение при чтении

Объявление `domain.shared` и `merge` — [P/02.1 N1.2b](../../../02-installer/ru/spec/02.1-installer.norms.md); общий документ,
подпись и указатель у держателя — [P/08.9](../../../08-domain/ru/spec/08.9-domain.norms.md) N1.2; копия у члена —
[P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.10.

Домен не знает ни одного поля подсистемы: что общее,
объявляет манифест, а значение домена разрешается **при чтении**, не записью в строки.

- `resolve`: функция N3 — значение поля для единицы: единица → домен → `inherit` манифеста.
- `door`: `GET /domain/shared/<sub>[?unit=<id>]` у консоли кластера (своя, не пересылается; `view`) →
  200 {sub, term, rev, fields: {\<имя>: \<запись>}} — по каждому элементу `domain.shared` этого манифеста.
`door.record`: поле — `{value, from, inherit, merge?}` (`merge` — только `union`). `door.record`: `group_by` — `{groups, from}`. `door.record`: документ — `{value, from}`.
`door.term`, `door.rev`: документа этого кластера: у члена — объект `domain/shared` (копия, взятая P/09.1 N3 «взять документ»), у держателя — объект, который называет указатель. `door.term`, `door.rev`: документа нет — `null`, значения — без домена. `door.term`, `door.rev`: у держателя указатель или объект документа, который он называет, не читается — 503 `{error: "unavailable"}`, не «документа нет».
- `refusals`: подсистема без `domain.shared` — 404 `{error: "no such shared settings", detail: "'<sub>' shares no field with the domain"}`.
`refusals`: `?unit=` пустой или повторён — 400 `{error: "refused", detail: "a unit id is required"}` (как урок P/10 у `?cluster=`, P/10-01). `refusals`: единицы нет — в том числе единица другого манифеста (её разрешает своя консоль) — или id не по грамматике P/06.1 N1.3 (в том числе `..` после декодирования) — 404 `{error: "no such unit"}`.
`refusals`: документ не проходит `record` — значения без домена. `refusals`: документ не проходит `record` — journal `domain.shared.refused`.

Проверка документа — функция `record` [договора записи срока](../../../common/ru/contracts/record.md) (вид «общий документ»;
консоль кластера — участник).

`door`: `POST /domain/verify {user, password, need?: {cap, sub, units}}` у консоли кластера — только по билету с записью `domain/verify` в `calls` (P/06.3 N1.9); сеанс человека (кука или токен без билета) — 403 denied. `door`: билет без человека — 403 denied.

- `journal`: audit консоли: `access.verify {by_sub, by_user, user, cap, sub, units, may, required, ok}` — без пароля.

## N3 Проход

### переслать (консоль кластера) — по порядку, первое правило даёт исход

```
1. (метод, путь) не в таблице N1.3 и не своё (books, at, keys, shared/<sub>, двери переноса), или в пути сегмент `.`/`..`
   (в том числе процент-формой, N1.3) → 404 not a domain route
   (шаги 1–2 — до личности: путь вне таблицы — 404 и без токена; сторожевая — шаг 3)
   (переходы — договор пересылки; X-Operator: console на обоих)
2. тело — предел консоли (P/06.3 N1.3 `body`)                                        → 413 / 400 / 408
3. сторожевая — кто звонит (N1.9), кроме открытых строк таблицы                → 401 / 403 N1.9
4. holds (N1.4):
     view.url нет                                                            → 503 domain console not known
     иначе — переслать на view.url (N1.5; переход 2: X-Operator: console, без X-W2C-Via)
5. пришёл X-W2C-Via                                                          → 400 one hop
6. domain/holder не читается, хранилище молчит                                → 503 the list of members does not read
7. записи domain/holder нет                                                  → 404 no domain here
7a. holder записи — этот кластер (holds ложно: вида нет)                       → 404 no domain here
8. CLUSTERS не читается                                                      → 503 CLUSTERS does not read
9. нет строки держателя                                                      → 404 no console known
10. переслать на CLUSTERS[держатель] (N1.5; переход 1: X-Operator: console, X-W2C-Via) → ответ как пришёл | 502
11. журнал domain.forwarded
```

### у члена (консоль кластера, /domain/at/…) — по порядку

```
1. пришёл X-W2C-Via                                                          → 400 one hop
2. не GET/HEAD, или путь не форма N1.6 манифеста каталога, или сегмент `.`/`..` (N1.3) → 404 not a route handed to a member
3. сторожевая — кто звонит                                                   → 401 / 403 N1.9
4. domain/member-list/<раздел имени> есть, но не читается, хранилище молчит            → 503 the list of members does not read
5. кластер = CLUSTER этой консоли                                            → 404 not another member
6. строка раздела есть, кластера в ней нет                                   → 404 no such member
7. нет Entry.url: CLUSTERS не читается / нет строки кластера                  → 503 CLUSTERS does not read / 404 no console known
8. переслать на адрес N1.6 to (N1.5) с X-W2C-Via                              → ответ как пришёл | 502
9. журнал domain.forwarded
```

### принять консолью (любая консоль, до сторожевой)

Шаги 1–2 (`X-User` — снять; `X-Operator: console` — только у доказанной роли `console`; консоль кластера — не признаёт; снимает всегда: всё входящее из других кластеров — класс `signed`, N1.7 `server`) — [договор пересылки](../../../common/ru/contracts/forwarding.md)
«Принять консолью».

Шаги 1–9 и абзац после них — [договор `peer`](../../../common/ru/contracts/peer.md) «Функция `peer`» (владелец P/09; участники 6.7, 8.8, 10). Векторы —

### resolve(field, unit, domain)

```
вход:   field {name, type, inherit?, merge?, group_by?, document?}; unit — значение строки единицы | отсутствует;
        domain — {term, rev, value} значения в документе | null
pre:    поле — по форме общего раздела P/02.1 N1.2b: поле без inherit, не document и не group_by — не по форме (загрузчик
        такое поле отвергает; merge без inherit запрещён): вход не по форме, код 2 (N5 exit)
label:  "domain term T rev R"
1. document              → {value: domain ? domain.value : null, from: domain ? label : "none"}
2. group_by              → {groups: domain ? domain.value : [], from: domain ? label : "none"}   # groups — в порядке domain.value
3. unit есть, merge union, domain есть → {value: sorted(unit ∪ domain.value), from: "unit + " + label}
                         # списки строк (type list); объединение без повторов, порядок — байты UTF-8
4. unit есть             → {value: unit, from: "unit"}
5. domain есть           → {value: domain.value, from: label}
6.                       → {value: field.inherit, from: "manifest"}
```

Векторы — [`resolve`](../vectors/resolve/README.md), [`key-families`](../vectors/key-families/README.md) (N1.11).

**Гонки.** Список членов или `CLUSTERS` меняются между проверкой и звонком — пересылка идёт по прочитанному; следующий
запрос читает заново.

Две пересылки одного запроса не склеиваются: ключ повтора (`Idempotency-Key`) несёт клиент, принимающая
дверь решает по нему (P/08.6).

Приём `tls_ca` и правка администратора одной записи → [P/08.3 N3](../../../08-domain/ru/spec/08.3-domain.norms.md) «Гонки».
