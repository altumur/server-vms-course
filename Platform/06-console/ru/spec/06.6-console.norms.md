## N0 Словарь слов

Нормативные слова — по [канону курса](../../../common/ru/NORMATIVE-TERMS.md). Правила модуля — [P/01.1 N0](../../../01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

## N1 Форма

**Время.** Поля времени строк главы — время по [канону N0 P/01.1](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке): `platform/drain` — `at`; `platform/decommission/<host>` — `at`; `platform/schema` — `at`.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `<sub>/policy`, `platform/servers/<host>`, `platform/drain`, `platform/decommission/<host>`, `platform/schema`;
- пишет: `<sub>/idem/<key>` (create), `platform/doors/<host>` (delete), `<events root>/audit/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `platform/manifest/<sub>`, `<sub>/heartbeats/<name>`, `<sub>/slots/<name>`, `platform/resources/<server>/heartbeat`, `platform/doors/<host>`, `<sub>/placement/<id>`, `<sub>/workers/<name>`, `<sub>/decommissioned/<host>`, `<sub>/controller/placement_intent`, `<sub>/controller/pass`, `<sub>/<manifest:unit.rows>/<id>`.

Журнал `audit` главы — виды `schema.raised`, `policy.changed`, `drain.*` и о выводе сервера `server.decommission_requested`,
`server.decommission_withdrawn` (N3 «вывести_сервер»). Двери меток сервера (`PUT`/`DELETE /servers/{server}/labels`) журнала не пишут;
`server.decommission_refused` и `server.decommissioned` — слова модуля консоли, не виды консоли P/06.

Строки «владеет» пишет консоль дверями N2 и подъёмом схемы (N3 «поднять_схему»); контроллер читает их по
[P/04 N1.1](../../../04-controller/ru/spec/04-controller.norms.md), прочие процессы — по каталогу. Строку двери
`platform/doors/<host>` (владелец — ресурс, [P/05 N1.4](../../../05-resource/ru/spec/05-resource.norms.md) `door_row`) консоль
удаляет у выведенного сервера (N3 «вывести_сервер»). Строки контроллера (`placement`, `workers`, `placement_intent`, отчёт
прохода) двери читают по [договору наблюдения](../../../common/ru/contracts/observation.md) «Чтение решения» и P/04 N1.2; пульсы
и слоты — для известности сервера (N2.1), дренажа (N1.2) и `/schema` (N2.3).

### N1.1 Строки консоли

Строки, которые пишет консоль (двери N2); контроллер читает их по P/04 N1.1.

```yaml
<sub>/policy:                             # писатель — консоль; читает контроллер
  servers:   shared | distinct            # иное значение или ключ при чтении — умолчание манифеста; при записи — отказ
  revision:  <целое ≥ 1>                  # N2.1 «Версия строки»; так же у platform/servers, platform/drain, platform/schema
platform/servers/<сервер>:                # писатель — консоль
  labels:    <метки через запятую>        # "" — ни одной; строка побеждает метки узла
  revision:  <целое ≥ 1>
platform/drain:                           # писатель — консоль; одна строка на кластер
  server: <сервер>; at: <момент>; revision: <целое ≥ 1>
platform/decommission/<сервер>:           # писатель — консоль
  by: <кто>; at: <момент>; why: <слова>; gone: "true"?   # gone — подтверждение «сервера нет», когда ресурс никогда не слышали
```

Строка двери сервера `platform/doors/<host>` (писатель — ресурс сервера) — форма
[P/05 N1.4](../../../05-resource/ru/spec/05-resource.norms.md) `door_row` (семья `doors`); консоль читает её для состояния
ресурса и известности сервера (N2.1) и удаляет у выведенного сервера (N3 «вывести_сервер»).

### N1.1a Схема

`platform/schema`, `SCHEMA`, `BUILD`, `schema` и `build` пульса, `check` — [договор схемы](../../../common/ru/contracts/schema.md) «Схема». Здесь — подъём схемы оператором:

```yaml
raise:    только оператор, PUT /schema?version=N по N3; назад — отказ; нынешние проверки SCHEMA, неизвестного пульса и подтверждённости чтения, затем CAS
```

Стороны проверки других процессов — [P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md) N3 «проверка схемы воркером»,
[P/04](../../../04-controller/ru/spec/04-controller.norms.md) N3 «старт контроллера — проверка схемы»,
[P/05](../../../05-resource/ru/spec/05-resource.norms.md) N3 «старт ресурса — проверка схемы».

### N1.2 Дренаж

```yaml
platform/drain:  {server: <сервер> | "", at, revision}   # один сервер за раз; писатель — консоль (admin); читает контроллер (P/04 N1.1)
state:
  draining:        <сервер> | ""
  safe:            все подсистемы safe
  would_strand:    {<sub>: [id…]}                      # проба без моделирования размещения: все единицы воркеров этого сервера
                                                         # и все неразмещённые (N2.2)
  subsystems:      {<sub>: {draining, subsystem, workers, units, pending_writes, pending_unsaid?, would_strand, safe}}
  safe(sub):       units == 0 ∧ pending_writes == 0 ∧ pending_unsaid пуст
  pending_writes:  Σ по воркерам сервера поля пульса pending_writes — целое JSON без дробной части и экспоненты,
                   0 ≤ x ≤ 2^53 − 1 (форма int [договора проверки строки](../../common/contracts/row-check.md) «Подготовка полей»: «Значение `int` на входе двери»): базовый воркер платформы (P/03.4 N1.1) пишет
                   в пульс 0 сам, если подсистема не сказала своё (подсистема с буфером на диске говорит своё число);
                   поля нет / слово / дробь, в том числе `0.0`, `1000.0`, `-0.0`, `1e3` / больше 2^53 − 1 / нечитаемый или
                   устаревший пульс → pending_unsaid (дренаж не safe)
  server_of:       воркер сервера — по полю server читаемого пульса; пульс не читается — по server его слота
                   `<sub>/slots/<name>` (P/03.2 N1.4): такой воркер — в pending_unsaid, единицы его назначения
                   `<sub>/workers/<name>` — в units и would_strand
journal:  drain.started {server, user}; drain.ended {server} — других видов журнала дренажа нет (`drain.cleared` нет)

          # журналы консоли этой главы (schema.raised, policy.changed, drain.*, server.decommission_*) — дерево audit/console (договор журнала событий `journal`,
          # роль console); журналы дверей единиц и таблиц (<t>.written/<t>.deleted, unit.changed) — глава 6.1
```

`GET /drain` отдаёт `DrainState` целиком, без фильтра по грантам: дренаж — состояние всего кластера, дверь требует `view` на
`*` ([договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) `need`), узкий грант — 403; `safe` — по всем
подсистемам (сценарий — приёмка главы 8.4, сц. 01 шаги 25–26).

Устаревший пульс — не свежий по [договору наблюдения](../../../common/ru/contracts/observation.md) «Свежесть»: версия не
менялась в последние LOST_AFTER.

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи. Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N2 Двери

Двери консоли, через которые оператор говорит с контроллером и платформой. HTTP-формы и закрытые наборы кодов —
[контракт урока](../../spec/06-console.api.openapi.yaml); у каждого `GET` есть `HEAD` — тот же код и заголовки без тела
([глава 6.5](06.5-console.norms.md) N2). Общие отказы консоли — глава 6.5 N4; это `{detail, error, field?}` (глава 6.1 N2 «Отказ: `error` и `field`»), а не Fault
хранилища. Состояние, права и выбранный вид id проверяются после статической формы. Новых дверей переезда и
перебалансировки нет.

### N2.1 Входы

Вход PUT /policy — закрытая PolicyInput только с servers (shared или distinct); revision не принимается. Policy с revision остаётся формой ответа.

Разбор запроса — [глава 6.5](06.5-console.norms.md) N2 «Разбор запроса консоли» (P/01.1 N2.1 с отступлениями консоли);
своих отступлений у дверей контроллера нет (повтор `server` у `POST /drain` — 400 по общему правилу).

`/policy`, `/unplaceable` и `/where/{id}` относятся к выбранной подсистеме; у корневой они
без префикса, у смонтированной — с `/<sub>`. `/drain` и `/servers/{server}/…` находятся
у корня консоли и охватывают все её манифесты. Префикс подсистемы не создаёт копии
кластерных строк. Права — роль `console` [P/02.5 N1.4](../../../02-installer/ru/spec/02.5-installer.norms.md); порядок сторожевой — [глава 6.3](06.3-console.norms.md) N1.3 `identity` и `need`. Стандартные servers у этих трёх path item
задают оба полных URL; общие /drain и /servers/{server}/… не наследуют префикс.
Имя sub явно выбирает загруженный манифест, включая CONSOLE_ROOT (глава 6.5 N2).

**Память повторов**. `PUT /policy`, `POST` и `DELETE /drain`, `PUT` и `DELETE /servers/{server}/labels`, `POST` и `DELETE /servers/{server}/decommission`,
`PUT /schema` читают необязательный `Idempotency-Key` по правилу [главы 6.1](06.1-console.norms.md) N3 «память повторов»: ключ `(user, method, path, key)`, порядок
«разбор запроса → заявка → проход двери → запись под стражем заявки → ответ в заявку», ответ `< 500` запоминается, срок — как у `POST`. Иное тело или иной вход query
под тем же ключом (`server` у `POST /drain`, `version` у `PUT /schema`) — 422 `key reused`; чужая pending моложе 30 с — 409 `in flight`; ключ не по форме — 400 `Idempotency-Key required`.
Заявка `PUT /policy` — `<sub>/idem/<key>` выбранной подсистемы; у кластерных дверей `/drain`, `/servers/{server}/…`, `/schema` — `<CONSOLE_ROOT>/idem/<key>`
([глава 6.5](06.5-console.norms.md) N1.1): своей семьи у них нет, путь в ключе различает двери. Без заголовка двери прежние.
Двери, которые пишут `revision`, держат в заявке намеченную `revision` до записи, как глава 6.1 N3 «править» шаг 5a. Перехвативший заявку смотрит цель раньше `If-Match`: у строки эта `revision` → записана этой заявкой, ответ шагом 9;
`DELETE` меток: строки нет → то же. Иначе проход заново поднял бы `revision` второй раз и отказал бы своей же записи `412`. Вывод сервера `revision` не пишет, его перехваченная заявка проходит дверь заново: он сходится.

**Версия строки**. Снимки настроек — `<sub>/policy`, `platform/servers/<host>`, `platform/drain`, `platform/schema` — несут `revision`: 1 при создании строки, +1 на каждую запись. Запись идёт с `cas` прочитанной версии (строки нет — `cas ""`):
без него две записи подняли бы `revision` до одного числа. Конфликт — перечитать и сверить условие снова, предел повторов исчерпан — 503 `unavailable`. Проход без записи (`POST /drain` того же сервера, `DELETE /drain` без дренажа, `DELETE` меток без строки)
`revision` не двигает. Снятые метки считают заново. Строка без читаемой `revision` читается с 0, следующая запись пишет 1.

`If-Match`, `ETag`, индекс и `412 revision moved` — [глава 6.1](06.1-console.norms.md) N2 «Версии», слова те же:

- `ETag` несут `GET /policy`, `GET /drain`, `GET /schema`, `GET /servers/{server}/labels` и ответы успеха `PUT /policy`, `POST` и `DELETE /drain`, `PUT` меток, `PUT /schema`, если строка есть. Строки нет — `ETag` нет; `DELETE` меток снимает строку — `ETag` нет.
- `If-Match` читают `PUT /policy`, `POST` и `DELETE /drain`, `PUT` и `DELETE` меток, `PUT /schema`. Вывод сервера не читает: это запрос, а не снимок настройки, и `PUT` не правит его поля.
- Порядок: разбор и форма `If-Match` → заявка → чтение строки → условие → проход двери → запись. Условие стоит раньше проверок двери: клиент судит о той строке, которую видел.
- Строки нет и `If-Match` есть — 412 с `revision: 0`, без `row`: условие называет версию, которой нет. Чтобы создать строку, клиент шлёт запрос без `If-Match`.
- `row` отказа 412: `{servers, revision}` у политики, `{labels, revision}` у меток, `{server, at, revision}` у дренажа, `{version, revision}` у схемы.

Во всех строках таблицы JSON-объекты закрыты: неуказанных полей нет. Успех `{}` содержит JSON-объект,
а не пустое HTTP-тело. Метка — по [азбуке меток](../../../common/ru/contracts/labels.md) (1–64 ASCII-знака: первая буква/цифра,
далее буква/цифра, `_`, `.`, `:`, `-`). Список query разбирается по запятым, без пустых элементов,
кроме целиком пустой строки; сервер в path/query — имя сервера: имя хоста RFC 1123 — метки через «.», метка 1–63
знака `[A-Za-z0-9-]`, не начинается и не кончается «-», всего не больше 253 байт (`..`, `.`, пробел, `/` — не имя);
иное — 400 до проверки существования. В `will_move` и
`would_move` попадают только ссылки, доступные вызывающему по `view`; список может быть пуст.
Прогноз меток `would_move` / `will_move` — множество единиц, которые с сервера s **уйдут**, а не придут на него: единица подсистемы с `constraint: labels-subset`, у которой воркер эффективного размещения
([договор наблюдения](../../../common/ru/contracts/observation.md) «Чтение решения: intent → placement → intent») свеж по тому
же договору и его пульс называет `server: s`, а метки единицы (её поле `labels`, [P/04 N1.3](../../../04-controller/ru/spec/04-controller.norms.md)
`constraint`) — не подмножество проверяемого набора: query `labels` или тело `PUT`; у `GET` без query — текущие
эффективные метки сервера (строка `platform/servers/<s>`, иначе метки узла — P/04 N1.3). Неразмещённые единицы, единицы
других серверов и единицы, которым набор подошёл бы на этом сервере, в прогноз не входят. Ссылки `<sub>/<id>` — без
повторов, по возрастанию байтов UTF-8 строки ссылки. Прогноз — выдача: неответ при чтении пульсов и размещений (и их листинга) —
`lapse` договора наблюдения, прогноз по памяти последних прочитанных версий; источник, не читанный ни
разу с запуска, — 503 `unavailable`, у `PUT` — до записи строки: записи без ответа нет. Запись строки меток `PUT` от пульсов
не зависит и допуском по наблюдениям не является.
Имя подсистемы в ссылке `<sub>/<id>`, ключах карт drain и поле `subsystem` следует P/02.1 N1.2,
включая весь закрытый список зарезервированных имён; грамматика самого id — [глава 6.1](06.1-console.norms.md) N1.3.
Существование сервера определяется всеми подсистемами и ресурсами консоли: сервер известен, если есть хотя бы
одно свидетельство — пульс ресурса этого сервера, строка `platform/doors/<host>`, поле `server` пульса воркера
или слота любой подсистемы, а для операций меток ещё строка `platform/servers/<host>`. Для всех трёх операций
меток и обоих методов вывода неизвестный сервер — 404. Ошибочная форма тела/меток — 400 до этой проверки.

### N2.2 Полные тела чтения

- **Unplaceable:** `{id, labels, workers_live, why?}`. `id` — строка; `labels` — массив меток;
  `workers_live` — целое ≥ 0; `why`, если есть, — непустая причина из поля `unplaceable` последнего
  отчёта прохода ([P/04 N1.2](../../../04-controller/ru/spec/04-controller.norms.md)): решает контроллер, консоль читает. Это единицы без места,
  в том числе при пустом пуле, и единицы, для которых ограничения не дают кандидата.
- **Where:** `{worker, server, reason, directory, scans, door?}` по [главе 6.5](06.5-console.norms.md) N3 «`/where/<id>`». `worker` — непустое
  имя назначения по грамматике слота P/03.2 N1.4; `server` — из пульса воркера, иначе из поля `server` его строки слота,
  иначе null; `reason` —
  непустая причина решения; `directory` — имя из последнего скана назначений либо null;
  `scans` — число завершённых сканов ≥ 0 с запуска консоли. Кэш directory может отставать от решения;
  частота скана назначений — «Решает реализация» п. 1. У неразмещённой единицы 404 `{reason}` берёт причину
  из поля `unplaceable` отчёта прохода, а без неё — `not placed: no worker holds it`.
  Необязательная `door` содержит `url`, `token` (непустые строки), `expires` (число стенных секунд)
  и `routes` (массив непустых строк); условия выдачи (`view` на единицу, журнал `door.issued`) и срок (TTL DOOR_TOKEN_TTL) — глава 6.5 N3 «`/where/<id>`», а не право, следующее из схемы.
- **DrainState:** `{draining, safe, would_strand, subsystems}`. `draining` — имя или `""`;
  `safe` — булево; `would_strand` — карта подсистема → массив id.
  Значение `subsystems[sub]`: `{draining, subsystem, workers, units, pending_writes, would_strand, safe, pending_unsaid?}`.
  `draining` — то же имя или `""`, `subsystem` равно ключу карты; `workers`, `units`,
  `pending_writes` — целые счётчики ≥ 0; `would_strand` — массив id; `pending_unsaid`, если есть,
  — массив имён воркеров по P/03.2 N1.4 без читаемого счётчика. `safe` считается по N1.2, не по пустоте
  `would_strand` — без моделирования размещения: все единицы воркеров этого сервера и все неразмещённые единицы
  подсистемы. Единицы воркера — объединение его назначения (`<sub>/workers/<name>`) и `status[].id` его пульса: пустой
  `status` при назначенных единицах не делает сервер пустым; и наоборот, пустое назначение при непустом status не делает его пустым. Один id в обоих источниках считается один раз для этого воркера; `units` — сумма размеров таких объединений воркеров. Без активного дренажа серверный набор пуст, счётчики 0, `safe: true`;
  проба неразмещённых единиц всё равно может дать непустой `would_strand`.
  Ключи двух карт совпадают и соответствуют видимым подсистемам; общий `safe` определяется всеми
  подсистемами, а не только видимыми, чтобы скрытые единицы не разрешали выключение сервера.

Если нужное чтение/запись хранилища не подтверждены, операция возвращает 503 `{detail, error: unavailable}`;
выдачи (`GET /drain`, `GET /schema`, `GET /unplaceable` — `workers_live`) при неответе в чтении наблюдений (пульсы, строки дверей, удержания, метки, их листинг) —
`lapse` договора наблюдения, ответ по памяти последней прочитанной версии с её возрастом; 503 — только если источник не
читался ни разу с запуска и ответ утверждал бы пустоту или ноль; записи и допуски (`PUT /schema` шаг 3, `POST /drain`, `POST /servers/{server}/decommission`) —
только по чтениям своего прохода: неответ — 503, записи нет; обязательные чтения, не наблюдения (строка `platform/schema`,
строки единиц и таблиц), — 503;
при неизвестном исходе записи клиент сначала перечитывает состояние или повторяет запрос с тем же `Idempotency-Key`. `busy` и `denied` имеют отдельные причины глав 6.3
и 6.5 (N4). Коды и тела общих отказов описаны у каждой операции контракта урока. Операционный 404 отличается от
`NoRoute`: у сервера — `{detail, error}`, у неразмещённой единицы — `{reason}`.
Отказ вывода 409 содержит `{detail, error: "server answers", server, may_confirm_gone}`;
`may_confirm_gone: true` разрешён только при никогда не слышанном ресурсе и отсутствии свежих
свидетельств воркера/слота/ресурса. При живом сервере `gone: true` не обходит отказ: любое свежее свидетельство —
409 с `may_confirm_gone: false`, и `gone: true` его не меняет. Свежесть свидетельства — «слышен в последние LOST_AFTER»
[договора наблюдения](../../../common/ru/contracts/observation.md) (N3 «вывести_сервер»).

### N2.3 Схема и дренаж

`/schema` и `/drain` — общие двери у корня консоли: префикс подсистемы к ним не добавляется (глава 6.5 N2). Разбор
запроса — [глава 6.5](06.5-console.norms.md) N2 «Разбор запроса консоли» (P/01.1 N2.1 с отступлениями консоли; повтор
`version` у `PUT /schema` — 400). Общие отказы консоли, `HEAD` и предел чтения — глава 6.5 N2, N4.

| Дверь | Полное успешное тело / особые отказы |
|---|---|
| GET `/schema` | `{version, understood, builds, can_raise_to, processes, schema_unknown?}`: version — целое ≥1; нет строки — равно understood; испорченная строка — null и `schema_unknown: true` (у читаемой строки поля нет); understood — схема консоли; builds — различные `build` своей сборки (BUILD) и всех процессов processes, по возрастанию байтов UTF-8 (`build: null` — не известно — не входит); processes — по пульсам (N1.1a heartbeat), ключ с пространством имён: воркер — `<sub>/<имя слота>` (`testsub/w-1`), ресурс — `resource/<сервер>` (`resource/srv-a`); так не сталкиваются слоты разных подсистем с одним `slot.prefix` и сервер с именем слота; контроллер и консоль пульса не пишут и в processes не входят; значение — `{schema: integer ≥1 or null, build, ts, live}`, live — пульс менялся на глазах консоли в последние LOST_AFTER ([договор наблюдения](../../../common/ru/contracts/observation.md) «Свежесть»); can_raise_to — минимум understood и схем живых, при неизвестной живой — 0. ## N3 Проход

### поднять_схему(N) — консоль, admin

```
1. строка N — только ASCII [1-9][0-9]* целиком (без знака, пробелов и ведущего нуля), значение ≥1 (N2.3)                                            → иначе 400 «a version is a whole number from 1»
   If-Match — форма; условие по прочитанной строке — раньше шага 2 (N2.1 «Версия строки»)
2. строка platform/schema: не число → 409 «mend the row first»; have > N → 409 «does not go back»
3. своя SCHEMA < N → 409; живые процессы (пульсы менялись на глазах читателя в последние LOST_AFTER — договор наблюдения):
   любой с неизвестной schema → 409 «still running: …»; чтение пульсов этого прохода не подтверждено
   (неответ, в том числе листинга) → 503 unavailable, записи нет: по памяти не решает, не пустой состав
4. записать {version: N, at, revision: прочитанная + 1} с cas; журнал schema.raised
```

Шаг 3: «живые» — по [договору наблюдения](../../../common/ru/contracts/observation.md) «Свежесть» (граница — вектор [`fresh-age`](../../../common/ru/vectors/fresh-age/README.md)). Подъём — запись: решает только по чтениям своего прохода; память наблюдения (`lapse`) ему не основание — по ней
пульс стареет за LOST_AFTER, процесс выпадает из «живых», и подъём прошёл бы вслепую.

Два admin всё равно защищены CAS: проигравший перечитывает состояние, не объявляет успех.

### старт консоли — проверка схемы

Общий блок всех четырёх процессов;
здесь — сторона консоли, внутри P/06.6-04. Сторона воркера —
[P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md) N3 «проверка схемы воркером», контроллера —
[P/04](../../../04-controller/ru/spec/04-controller.norms.md) N3 «старт контроллера — проверка схемы», ресурса —
[P/05](../../../05-resource/ru/spec/05-resource.norms.md) N3 «старт ресурса — проверка схемы».

Так же стартуют процессы домена — `domain`, агент, консоль домена ([P/02.4 N1.12](../../../02-installer/ru/spec/02.4-installer.norms.md)).

Проверка при старте и её граница — [договор схемы](../../../common/ru/contracts/schema.md) «Проверка при старте».

### дренаж — чтение состояния

```
для каждого манифеста: воркеры сервера (пульсы; пульс не читается — server слота, N1.2 server_of),
для каждого такого воркера w: ids(w) = set(assignment(w)) ∪ set(heartbeat(w).status[].id),
units = Σ |ids(w)|; id в обоих источниках считается один раз для этого воркера,
pending = Σ pending_writes (нет/слово/дробь/нечитаемый пульс → unsaid),
would_strand = все единицы воркеров сервера и все неразмещённые единицы подсистемы — без моделирования размещения (N2.2 `DrainState`)
safe = Σ units == 0 ∧ Σ pending == 0 ∧ unsaid пуст
```

Нечитаемый или неподтверждённый обязательный источник обрабатывается по прежним правилам N1.2 и N2 observation/lapse/unavailable, а не заменяется пустым множеством или нулём. В частности, нечитаемый пульс по-прежнему даёт unsaid, поэтому пустое назначение не делает safe истинным. Ответ — наблюдение; он не заменяет окно остановки писателей перед выключением сервера.

### дренаж — начать (`POST /drain?server=s`)

```
1. прочитать platform/drain (не подтверждено → 503); If-Match есть и не равен версии строки → 412 revision moved (N2.1 «Версия строки»); server строки = s → 200 {draining: s}, ничего не писать
2. server строки — иной непустой → 409 «<server> is already draining; one server at a time»
3. записать {server: s, at, revision: прочитанная + 1} с cas прочитанной версии (строки нет — cas ""); conflict → с шага 1;
   предел повторов при conflict исчерпан → 503 unavailable; успех → журнал drain.started, 200 {draining: s}
```

**Гонки.** Два одновременных `POST /drain` разных серверов: `cas` пропускает одну запись; проигравший перечитывает — видит
иной сервер и отвечает 409, свой — 200 без записи (прежде — вопрос «Архитектору»). Контроллер читает draining раз за проход; ранее назначенное может доехать позже. `safe` — вывод по наблюдённым размещениям и свежим известным пульсам, не атомарный снимок и не блокировка новых назначений. Перед выключением оператор прекращает новые записи/назначения на сервер, дожидается завершения начатых действий и повторно проверяет состояние. Не удалось подтвердить покой — выключение откладывается; одного `safe: true` недостаточно.

### вывести_сервер(s) — сторона консоли

Контроллер исполняет запрос по [P/04 N3](../../../04-controller/ru/spec/04-controller.norms.md) «вывести_сервер(s)».

```
запрос (POST /servers/{server}/decommission):
  «слышны» и «никогда не слышали» — только по чтениям этого прохода (пульсы ресурса, воркеров, слоты, строка двери,
  их листинг); неответ в них                                                            → 503 unavailable, строки и журнала нет
                                                     (неответ не заменяется памятью наблюдения)
  ресурс, воркер или слот сервера слышны в последние LOST_AFTER (договор наблюдения)  → 409 server answers
  ресурс никогда не слышали ∧ gone ≠ true                                              → 409, may_confirm_gone
  иначе строка platform/decommission/<s> уже стоит (повтор)                              → 202, строку не переписывать
                                                     (by, at, why, gone — первого запроса), журнала нет
  иначе записать platform/decommission/<s>                                              → 202, журнал server.decommission_requested
проход консоли (после отметки контроллера <sub>/decommissioned/<s> каждого манифеста): удалить platform/doors/<s> с cas
  по прочитанной версии (право delete:, P/02.5 N1.4); строка двери не читается — так же, cas по прочитанной версии:
  содержимое для удаления не нужно; ресурс выведенного сервера, пока стоит `platform/decommission/<s>`,
  свою дверь заново не пишет (P/05 N1.4 `door_row`)
отзыв (DELETE /servers/{server}/decommission): строка запроса снята → отметку снимает следующий проход контроллера;
  дверь ресурс пишет снова своим пульсом
journal:  server.decommission_requested {server, user, addr, why?, gone?} — при записи строки запроса (не при каждом 202:
          повтор при стоящей строке журнала не пишет); why — если сказан в теле,
          gone: true — если подтверждён; server.decommission_withdrawn {server, user, addr} — при отзыве, только если
          строка запроса была и снята; отказ 409 и отзыв без строки журнала не пишут (журнал — при записи строки);
          addr — адрес клиента (договор журнала событий `journal`)
```

«Слышны» — по [договору наблюдения](../../../common/ru/contracts/observation.md) «Свежесть» (возраст ровно LOST_AFTER — слышен, 409; граница — вектор
[`fresh-age`](../../../common/ru/vectors/fresh-age/README.md)); «никогда не слышали» — ресурс `unknown` того же договора.

**Гонки.** Запрос консоли и проход контроллера разделены строкой — повтор запроса идемпотентен (P/04 N3
«вывести_сервер», «Гонки»): проверки идут как обычно, а дошедший до записи повтор при стоящей строке отвечает 202, строку не переписывает (`at`
первого запроса контроллер уже перенёс в `asked_at`) и журнала не пишет.
