# Формы P/06 и швы консоли

Этот текст — производный от `forms/README.md`, руками не правится. Английский forms/README.md — источник; этот русский перевод предназначен людям, не входит в выгрузку. Формы выражают существующие нормы.

## HTTP-контракт по каталогу

[OpenAPI](../../spec/06-console.api.openapi.yaml) объявляет зависящие от каталога PathItem как стандартные `components.pathItems` ниже. Их привязки используют только загруженный каталог, уже принятый [загрузчиком P/02](../../../02-installer/ru/spec/02.1-installer.norms.md) и обслуживаемый при [старте процесса](../../../02-installer/ru/spec/02.3-installer.norms.md). Имена компонентов, карты доказательств и примеры значений `servers` не допускают маршрут или подсистему.

| Стандартный PathItem | Существующий источник в каталоге |
|---|---|
| `UnitsCollection`, `UnitItem` | `unit.rows` выбранной подсистемы |
| `TableCollection`, `TableItem` | каждая объявленная запись `tables` этой подсистемы с её существующими правилами полей и service |
| `PassRoot` | существующий список `door.pass` или его `routes`; сохраняются вид и объявленные `wait`, `stream`, `calls` и `refusals` |
| `ConsoleFile` | каждое полное буквальное имя в `console.files`, включая все сегменты пути |

Каждый применимый компонент конкретизируется для этих фактических записей каталога: короткие маршруты только для выбранного `CONSOLE_ROOT`, маршруты с явным именем подсистемы — для корня и смонтированных подсистем. У файла есть только его существующий маршрут с явным именем подсистемы. Сам компонент ещё не является достижимой дверью. Используется существующий каталог, а не дополнительный файл привязок, карта доказательств или новая грамматика входа.

Конкретизация удаляет только параметры `in: path`, уже заменённые буквальными значениями каталога, на обоих уровнях — PathItem и операции. Сохраняются все оставшиеся параметры и их декодирование, заголовки, query, тело, обязательность, ответ, условие безопасности и база ссылок. Буквальная подсистема присутствует в пути один раз: используется существующий контекст origin без повторного добавления той же подсистемы через `servers`. Ни пример серверной переменной, ни имя параметра не выбирают класс каталога. Логическая операция сохраняет происхождение и идентичность адаптера; изменение порядка обхода её не переименовывает.

`ConsoleFile` сопоставляет целиком объявленное конечное имя файла. `PassRoot` сохраняет существующий допущенный префикс, неограниченный сырой остаток и query для обоих видов передачи; этот остаток не является односегментным параметром OpenAPI. Существующий остаток route/id у `door.routes` и операции domain-at остаются у нынешних процедур, даже если параметр назван `rows`. Приоритет путей, выбор метода, неоднозначность, отсутствие fallback, порядок отказов, права и все существующие пределы не меняются. Это представление не добавляет операцию, URI, алиас, полномочие или настройку исполнения.

## Входы и константы

[daemon-flags.tsv](../../forms/daemon-flags.tsv) использует шапку P/01 `flag type default default_text required commands bad norm`. `$NAME` — окружение, не CLI-флаг. Процесс — console. `cleanup-window` — только логическое имя выбранной реализацией команды окна; настоящее имя/исполняемый файл остаются решением реализации P/06.1. Единственный CLI-флаг здесь — её существующий `--writers-stopped`. Разбор не отменяет проверки каталога, комплекта, роли, server/box, алиасов, положения кольца, часового пояса и активного listener по договорам. Неактивный callback и нечитаемое заданное кольцо судятся в нормативной точке активации/операции, не становятся новыми отказами запуска. Неправильный CLUSTERS — нечитаемый вход операции, не пустой список и не новый отказ запуска.

`$INSTANCE_ID` — уже существующая общая настройка экземпляра: отсутствие или пустота выбирает обычное вычисление из коробки/pid/случайного суффикса; заданное непустое значение принимается либо отвергается по договору экземпляра и сохраняется байт в байт. Это окружение, нового флага CLI или правила настройки нет.

[runtime-constants.tsv](../../forms/runtime-constants.tsv) — числовой источник 34 объявленных констант. Шапка `name value unit norm meaning`, literal TAB. Уникальный name `[A-Z][A-Z0-9_]*`; value — положительное целое JSON без кавычек; unit `count|s|bytes`; norm — существующий req-якорь главы-владельца; meaning — текст. Нового языка выражений и переменных окружения нет. Процедура владеет зависимыми формулами и условным применением: OPS_KEEP не меньше срока памяти приёмки подсистемы. Эти литералы можно выдавать с core; целиком сгенерированный этап этим не объявлен.

Числовой источник каждого ограничения папок — строка `runtime-constants.tsv`. JSON Schema — второй машинный носитель того же значения, не самостоятельное умолчание. Равенство судит `check_spec`; проза и зависимые формулы ссылаются на имя строки.

| Строка-источник | JSON-путь второго носителя |
|---|---|
| `FOLDERS_MEMBERS_MAX` | `data/folders.schema.json#/$defs/writer/properties/members/maxItems` |
| `FOLDERS_PER_UNIT_MAX` | `data/memberof.schema.json#/$defs/writer/properties/folders/maxItems` |

`AT_ROUTE_WAIT` и локальный `FORWARD_WAIT` действуют только в P/06.7 N1.6. Прочие сроки пересылки и `FORWARD_MAX` объявлены в [договоре пересылки](../../../common/ru/contracts/forwarding.md); `PASS_WAIT`, `GLASS_SESSION` и `GLASS_SESSIONS_MAX` — в [договоре сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md). Эти ссылки не копируют чужие константы в форму.


Та же существующая предметная проверка должна сопоставлять FOLDER_NAME_MAX с `data/folders.schema.json#/properties/name/x-max-bytes` в байтах UTF-8, CHANGES_HISTORY с `spec/06-console.api.openapi.yaml#/components/schemas/Changes/properties/changes/maxItems`, CHANGES_WAIT с максимумом wait у GET и HEAD `/changes`, VERIFY_UNITS_MAX с `VerifyInput.need.units.maxItems`, а SWEEP_LIMIT с `data/sweep.schema.json#/$defs/writer/properties/digests/maxItems` и действующей корневой ссылкой читателя. Корневые reader-ссылки folder/memberof сохраняют два существующих равенства выше.

CLAIM_TAKEOVER_AFTER, DONE_ANSWER_KEEP, SWEEP_GRACE, SWEEP_MARK_EVERY, DOOR_TOKEN_TTL и OPS_CONTROL_RETRIES имеют разные смыслы даже при совпадении с другой величиной. OPS_CONTROL_RETRIES считает повторы после исходного прохода. Четыре определяющие строки TTL/формулы общего договора door-token ссылаются на тот же DOOR_TOKEN_TTL.

## Отказы

[refusals.tsv](../../forms/refusals.tsv) использует `chapter row name surface code kind fields headers log norm word response_schema cause outcome diagnostic caller`. В ней 204 строки отказов N4 глав и 14 импортированных строк сторожевой (6.3), как 279 проекций. Строка несёт ячейки cause/outcome/diagnostic/caller своего отказа; строка главы 6.7 несёт ячейки word/outcome/cause, diagnostic/caller равны `-`. Row уникален в пределах исходного условия главы; проекции повторяют его. Альтернативы действуют при своих условиях N4; альтернативная схема не даёт операции произвольного выбора. Успешные строки и абстрактные исходы загрузки/процедур остаются в каталоге и не становятся новыми ошибками.

HTTP-тела ссылаются на компоненты урока; Fault.kind не вводится. `fields` — обязательные свойства, объявленные непосредственно компонентом; унаследованные/составные требования, условные поля, слова ошибок, динамические заголовки и журналирование остаются в полной OpenAPI и ячейках N4. `response_schema=-` означает отсутствие собственного JSON-тела; peer сохраняет форму импортированного владельца. Закрытые слова также есть в [data/refusal-words.tsv](../../data/refusal-words.tsv). Компонент схемы RevisionMoved также задаёт схему ответа components/responses/RevisionMoved; публичный ответ — components/responses/RevisionMoved.

## Швы и этапы

Каталоги приёмки глав сохраняют все свои сценарии и обязанности README. Швы используют CALL/JSON по [P/03](../../../03-worker/ru/forms/README.md) и [P/02](../../../02-installer/ru/forms/README.md). CALL принимает один JSON-вход и выдаёт одно нативное JSON-значение; рекурсивное подмножество объектов, точные массивы и пустые объекты. Порты нормализуют наблюдения настоящего кода консоли, не требуют от реализации частного API. Нельзя возвращать ожидаемый объект случая. Panic, посторонняя ошибка и неисполненный вызов — провал.

У каждого сценария новый временный корень, допустимые каталог, строки, личность, права и пределы до вмешательства. Неназванное значение — допустимый нейтральный фон, не неподтверждённое чтение. Слова фикстур выбирают подготовку и исход зависимости, не вычисленный заранее ответ функции. Версии/CAS настоящие и допустимые; читаемые ключи/билеты/cookie/конверты создаёт обычная криптография, охраны транзакций настоящие. Счётчики измеряют реальные вызовы, записи, байты и удаления. Управляемый store/транспорт вводит названный I/O-исход или гонку, решение принимает обычный код консоли. Фиктивный run или готовый успех его не заменяет.

| CALL-порт | Вмешательство и наблюдение |
|---|---|
| `console-repeat` | Обычная запись с ключом по настоящим pending/done строкам памяти; считать записи целевой семьи после повтора, отдельно от памяти/диагностики. Тела отличаются одним допустимым пользовательским полем. В случаях продолжения POST первая настоящая запись выполняется над указанным надгробием или отсутствующей строкой, ответ теряется и исполнение останавливается до done; другая консоль наблюдает прежнюю версию pending 30 s и перехватывает CAS. Намеченные revision/born читать настоящим кодеком заявки реализации, без новой публичной схемы. Поздний прежний исполнитель использует старый страж. При неизвестном сохранении намерения нет целевого вызова до подтверждённой своей перечитки; сравнить реальные байты цели с намерением. |

[stages.tsv](../../forms/stages.tsv) содержит 11 этапов, у всех kit `-`; 67 строк CALL-сценариев в девяти главах. Gates — помощь, не полный зачёт. Все назначения собственных/общих векторов, отдельные пробы и чтение обязательны. 77 HTTP-строк requests-body и 21 round-trip принятых json требуют настоящего судьи store+console; 52 нативных строки воркера не заменяют 77 консоли. Цель раннера P/06/vectors-requests-body — эта HTTP-обязанность; чистой native-команды консоли и function PASS пакета не выдумывается. Поздние процессные тесты домена требуют настоящих соседей 08–10 и не закрываются единичными фикстурами.

Случаи используют только те же порты. Состояние, которое называет случай, строить настоящими строками: pending-заявка, сохранённые резерв или намеченные revision/born, если они есть, и допустимая строка цели. Наблюдать неизменный pending объявленный срок допуска и перехватить обычным CAS-путём. Вход не обходит обычный кодек заявки, гейт или владение.

Для случаев удаления единицы выполнить настоящий пакет удаления единицы с читаемым допустимым членством в одной папке и действительными правами/CAS/стражами. `writes[0]` удаляет U, `writes[1]` — явная папка, когда она задана, `writes[2]` — явное членство, когда оно задано. Счётчики наблюдают настоящие целевые мутации unit/folder/memberof после подготовки, исключая подготовку/claim/журнал только из этих названных счётчиков. unique_target_keys проверяет настоящий выданный целевой пакет. Нынешние служебные/gone эффекты, допуск, полный размер и атомарность сохраняются. Ожидания адаптеру не передаются.

## Вычисляемое TLS-умолчание

При отсутствии W2C_TLS_DIR исполнить общий определитель окружения в профилях Linux и macOS: /etc/w2c/tls против <W2C_BOX>/tls. Переданный путь используется как есть, Given остаётся true; отсутствие остаётся Given=false и после определения. default=- формы daemon-flags означает вычисляемое значение, а не строку "-" и не безусловный путь Linux. Это проверки определителя и старта, не новые флаги и не правка общего договора env-file. VerifyUnavailable — только собственная форма verify503; свойства остальных ConsoleRefusal прежние.
