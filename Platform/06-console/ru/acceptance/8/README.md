## Статический профиль удаления и точные байты сущности

До установки профиля с папками использовать существующий вход manifest put P02.3 и фактические Status.max_body/max_value, затем его проверку конечного профиля до любой записи установки, включая unchanged. 13 собственных свидетелей формы/арифметики — `Platform/02-installer/forms/finite-profile.cases.json` (judge-only: свидетели конечного профиля); отрицательные случаи пропуска/H/кратности/provenance требуют отдельного судьи Архитектора и не становятся проходящими от одной JSON Schema. Полные описатели настоящей реализации и охват смешанных пакетов доказываются отдельно. Объявить достаточные существующие body_limit/row_ceiling настоящего стенда; ключ acceptance.yaml не выдумывается, AssemblyError не является отказом установщика.

6 свидетелей кодека в `../../forms/deletion-body-witnesses.json` (judge-only: свидетели кодека) считают целые компактные сущности UTF-8; достаточная проверка всего профиля отделена от размера одного выгодного пакета. Для доказательства IO проверять настоящие выдаваемые target/done/служебные запросы и Content-Length либо decoded chunk data; HTTP framing не входит. Проверка свидетелей кодека не исполняет прогон store/console; она не требует отдельной нативной команды и не определяет отказ DELETE при мутации.


Удаление единицы и явные строки folder/memberof в одном пакете должны согласовываться с последствиями удаления. Сохранённая удаляемая единица или восстановленное членство даёт прежний 400 no membership с field конфликтующей строки writes до целевой мутации. Согласованные явные строки используются один раз; недостающие автоматические последствия, их полный размер и стражи прежние. Молчаливой правки тела и полного обхода папок нет. Для строки, превышающей пределы своей семьи, действуют правила нечитаемой строки этой семьи.
