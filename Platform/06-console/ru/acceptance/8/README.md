## Подготовка

Консоль с манифестами `testsub` (объявляет `display.tree.folders: true`) и `testsub2` (не объявляет: он стоит в сц. 03 как подсистема без папок), домена нет, запросы идут от одного вызывающего с нужными правами. Каждый сценарий начинается с
пустого хранилища на своём экземпляре: `GET /folders` сверяет весь список, поэтому чужая папка меняет ожидание. Дверь без префикса — консоль. Роль двери `store` — `console`: она читает `platform/*` и строки подсистем ([P/02.5](../../../../02-installer/ru/spec/02.5-installer.norms.md) N1.4).

Жнец папок на стенде работает с периодом нормы `FOLDERS_REAP_EVERY` 60 с: сценарии 06 и 10 ждут его `@until 90`. Этот срок — верхняя граница: шаг кончается, как только признак есть. Снов (`@sleep`) нет.

## scenarios.tsv

Формат — [словарь директив и дверей](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей). Подмножество полей, `$name`, `@any`, `@big(N)`, `@header`, `@key`, `@as`, `@until`, `ASSERT` — как там. Запись `{"items": null}` значит: строки нет.

- `$f`, `$g` и подобные связывают id папки из ответа `201`. Значение id сценарий не задаёт: 128 случайных бит выбирает консоль.
- `$i`, `$j` связывают `index`: сравниваются только на равенство. `index` ответа `PUT` равен индексу строки в хранилище — сц. 02 шаги 4–5.
- Сц. 03 шаги 11–14: ключ `testsub/counters/<1007 байт>` — ровно 1024 байта: строка единицы представима, ключ членства длиннее предела — `400 bad member`. Сосед на 989 байтах даёт ключ членства ровно 1024 байта и проходит.
- Сц. 04: цепочка из восьми папок — `FOLDERS_DEPTH_MAX`; девятая — `too deep`. Шаги 13–16: надгробие предка в середине цепочки.
- Сц. 05 шаг 8: запись поверх надгробия идёт пакетной дверью, потому что `PUT` и `DELETE` такой папки отвечают 404.
- Сц. 09: граница `FOLDERS_PER_UNIT_MAX`: восьмая папка проходит, девятая — 400, удаление единицы на границе снимает все восемь.
- Сц. 10 шаг 5: дверь хранилища снимает строку единицы мимо двери консоли, как контроллер по `placement.ends`: у `testsub` такого срока нет, поэтому запись делает сам сценарий, ролью `console`, как сц. 19 главы 6.1. До прохода жнеца член висит; сценарий ждёт только конца окна, потому что момент прохода стенду не подчинён.
- Сц. 11: пакет единицы с папкой. Шаги 6–7 и 12 — отказ по `no chain`, `no membership`, `parent gone`; `$ip` — индекс родителя, `$t` — индекс его надгробия.
- Сц. 12 шаги 12–14: строку с пустым `name` пишет дверь хранилища ролью `console`, мимо двери папки. Папка с этим id не живая и не мёртвая: `garbled` в списке, 503 по одной.

| неподтверждённое чтение: 503, жнец ничего не снимает | нужен отказ хранилища на чтении конкретного ключа |
| член из второй подсистемы | `testsub2` держит `display.tree.group_by`, а `display.tree.folders` рядом с ним запрещено; код один, различается только префикс ссылки |

План сценариев прав, когда норма `may` внесена (стенд домена, `@person`, строки грантов — как [приёмка главы 8.4](../../../../08-domain/ru/acceptance/4/README.md)):

1. человек с `edit` на единицу без `admin`, единица в папке: `DELETE` единицы — 200, папка без неё;
2. создание единицы со строкой папки без `admin` над папкой — 403, ничего не записано;
3. запись папки без `admin` над ней — 403; с `admin` на `folder:<предок>` — 200;
4. добавить и снять единицу с `admin` над папкой, без `admin` на единицу — 403;
5. удалить папку со строкой роли `folder:` на потомке без `admin` на `*` в `sub` этой строки — 403.

## Статический профиль удаления и точные байты сущности (ADR-0127 C2)

До установки профиля с папками использовать существующий вход manifest put P02.3 и фактические Status.max_body/max_value, затем его проверку конечного профиля до любой записи установки, включая unchanged.13 собственных свидетелей формы/арифметики — Platform/02-installer/forms/finite-profile.cases.json; отрицательные случаи пропуска/H/кратности/provenance требуют отдельного судьи Архитектора и не становятся проходящими от одной JSON Schema. Полные описатели настоящей реализации и охват смешанных пакетов доказываются отдельно. Объявить достаточные существующие body_limit/row_ceiling настоящего стенда; ключ acceptance.yaml не выдумывается, AssemblyError не является отказом установщика.

6 свидетелей кодека в ../../forms/deletion-body-witnesses.json считают целые компактные сущности UTF-8:1048575/1048576/1048577, дополнительный LF, иное экранирование и свой контрпример1380972 байта. Случаи с заполнением используют V=1048576, не стандартный524288; достаточная проверка всего профиля отделена от размера одного выгодного пакета. Для доказательства IO проверять настоящие выдаваемые target/done/служебные запросы и Content-Length либо decoded chunk data; HTTP framing не входит. Эта правка источника не выполняет такой прогон store/console, не меняет прежние сценарии/швы или нативные команды и не вводит отказ DELETE при мутации.

## Общие пределы читателя и писателя (Z-10)

Схемы семей применяют свой прежний `$defs.writer` корневым `allOf` и к читателю: `folders.members` использует FOLDERS_MEMBERS_MAX, `memberof.folders` — FOLDERS_PER_UNIT_MAX. В существующей [таблице family-read](../../../../common/vectors/family-read/06.tsv) добавлены шесть граничных случаев `06-z10-*`; прежние `06-rights-8033` и `06-rights-8034` проверяют девять членств. У последнего reader-случая по ADR-0129 доп. (12) меняются лишь ожидаемые verdict/paths/outcome и пояснение; вход и идентификатор прежние.

Точная граница папки принимается в обоих режимах; лишний член делает строку нечитаемой в reader. Восемь членств принимаются; девять используют существующие исходы нечитаемости целой строки. Старые HTTP-сценарии и их счёт прежние: добавление векторов/источника не объявляет отдельный прогон жнеца или установщика. Чтения R013/R014/R016/R018 используют ту же проверку семьи и прежние исходы, без укорачивания и добавочного перехода/отказа. Б1 и исполнение восстановления P02 остаются открытыми.
