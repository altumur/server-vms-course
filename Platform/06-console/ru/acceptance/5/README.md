## Стенд сц. 01, 02, 04–12 (из М10/09), 18–33

До каждого автоматического сценария остановить процессы предыдущего, создать отдельные пустые строковое/объектное хранилища и очистить переменные/память повторов. Загрузить неизменённые testsub и testsub2 и третий манифест этого каталога `probe-x.subsystem.yaml` (имя с «-»: `metrics.prefix` — `probe_x`, мутационная проверка 7cecaf2 № 40) и четвёртый `probe-w.subsystem.yaml` (слово `writes_via`, сц. 33); root — testsub, второй доступен под /testsub2, третья — под /probe-x, четвёртая — под /probe-w; домена нет, обращения с петли. Фоновые controller/resource/worker до @start не работают. Сборка — схема 1; хранилище свежее и пустое — строки platform/schema нет, раннер её не пишет (чтение коммитов «cammeta-acceptance» 2026-10-20). Для каждого POST создания единицы раннер выдаёт свежий Idempotency-Key, сохраняемый только для повторов того же шага. POST таблицы не получает этим обещания памяти повторов.

Без воркеров размещения нет; счётчик c4 создаётся только в 04. Доменный вход, закрытые grants, CSP и повтор логического действия проверяются отдельным стендом/тестом модуля, не этим TSV.

- **Передача второго вида (сц. 32; ADR-0094 B1).** Шаг 1 запускает ресурс сервера консоли: наблюдения в `/metrics` требуют подтверждённого источника и без воркеров (глава 6.5 N4; G06-NO-RESOURCE-01). `probe-x` объявляет `door.pass` вторым видом, воркера у неё нет. Шаги 2–3 — отказ консоли по форме манифеста: `no worker…` становится `{code, message}`; шаг 4 — первый сегмент маршрута, а путь вне `api/v1`; шаг 5 — `apix`: сравнение целыми сегментами. Шаги 6–8 — билета с таким значением нет: консоль открыта, и всё равно личность только билет, 401; шаг 9 подтверждает, что единица не записана. Шаг 10 — открытый маршрут билета не читает. Шаги 11–12 — `probe_x_passed_calls_total 0` у `/probe-x/metrics` и общего `/metrics`: корень включает все подсистемы каталога (N2 «Outputs»). Шаг 13 исключает только собственную серию `testsub_passed_calls_total`: у `testsub` нет `door.pass` второго вида (N3). Живой билет — [стенд передачи второго вида](../../../../common/ru/acceptance/pass/README.md).

  `@start controller testsub2`); до `@start` фоновых процессов нет. Воркер — `w-1` подсистемы `testsub` на `srv-a`.

  контроллера `testsub` по файлу прав установки (P/02.5). Контроллера `testsub` в сц. 07 нет, строку никто не
  перепишет.
- **Место без строки (сц. 19).** Воркер `t-1` подсистемы `testsub2` на `srv-a` (`@start worker testsub2 t-1 on srv-a`);
  его экземпляр — `holder` слота (`$t1`). Строки удержания `testsub2/holds/s9` (экземпляр `$t1`) и `s8` (чужой

  `failovers_unmeasured` (N3 «/metrics — текст») считаются по полям пульса `started`, `previous_hb`, `previous_instance`

(10), (11)).** Шаг 1 запускает ресурс, чтобы итоговый список единиц мог подтвердить отсутствие воркеров (глава 6.5 N4; G06-NO-RESOURCE-01). `probe-w`: `unit.writes_via` и `tables.log.writes_via` — `[probe-x]` (P/06.1 N1.1a). ## Полная форма и воспроизводимость

Подмножество expect не заменяет проверку полной HTTP-формы [контракта урока](../../../spec/06-console.api.openapi.yaml): проверить обязательные поля, типы, Content-Type, специальные заголовки и отсутствие тела у HEAD/204. В строках ожиданий `$name` впервые связывается только после успешного совпадения всего ответа; следующие употребления сравнивают, запросы используют только уже связанные значения. Неудачная попытка @until не меняет переменные. @until повторяет чтение до указанного местного срока, не мутацию; после истечения — FAIL с последним ответом. @any допускает любое значение присутствующего поля, @absent требует отсутствия; они не подменяют типы полной схемы. JSON-объект сравнивается по подмножеству (`{}` на любом уровне — ровно пустой объект: словарь общего README, ACC-EMPTY-OBJECT-01), массив — по длине и порядку. Сырой HTML/текст сравнивается как байты UTF-8 с заданной подстрокой, не разбирается как JSON.

Успешный открытый /session содержит login_url (сценарий сессии — [приёмка главы 6.3](../3/README.md)).

## Дополнительная проверка чтением

R36-08: стабильный active intent направляет u на w-2 при placement=w-1 или его отсутствии — /where использует w-2; target="" даёт 404 с причиной intent. Чужой id/idle используют placement. Смена версии intent требует повторить чтение, неответ любого обязательного чтения — 503. Пульс читается после эффективного решения; отсутствие двери не превращается в null. Сценарий 04 проверяет только отсутствие размещения, active/перемежения в текущей TSV не исполняются.

Прогон 36 (Kimi): проверить оба исхода отсутствия v и смонтированные /servers, /unplaceable, /where, /metrics и страницу. Для where(table,place): неизвестная таблица 404 до unit; затем форма/view, подтверждённое удержание и пульс, ошибка чтения 503, отсутствие удержания 404 с X-Unreachable. door необязателен и появляется только при подтверждённом адресате/держателе/подписанте; выдача журналируется. Сц.04/6 видит пустые resources и не проверяет поля ResourceRow. (Петля, доверие, Origin и аварийный вход — [приёмка главы 6.3](../3/README.md).)

R37 (Codex): проверить каталоги root/mount: имя where не грузится; два отдельных корректных манифеста с mount b и семьёй root b не образуют допустимого каталога. Повторить для unit.rows и таблицы (включая списковую), оба направления пары и root каждого выбора. У GET/HEAD обеих mounted-страниц одинаковые наборы кодов, 200 отсутствует. Список делегирования не добавляет GET одной единицы владельцу (глава 6.1).

Это предмет ручной проверки спецификации и будущей проверки реализации. Подготовленные запросы, чтение и конечные модели автора не являются выполненным стендовым испытанием.

## Принятое ревью ADR-0127: каталог source до перезапуска

Для `GET /manifest/<sub>/source` принять изменённый манифест store после старта консоли. До перезапуска дверь source сохраняет rev, served, sha256, manifest и secret_defaults каталога запуска; новая установленная подсистема вне этого каталога остаётся404. Иная rev текущей строки store не создаёт своего503 и чтения store при каждом запросе. Перезапустить и сверить новый каталог запуска и served. Независимые обычные отказы busy/trust сохраняются; это не ответ по несовпадению ревизий. Для доказательства отсутствия чтения записать настоящие вызовы store. Замороженный модуль платформы и тринадцать исходных байтовых фикстур не меняются.
