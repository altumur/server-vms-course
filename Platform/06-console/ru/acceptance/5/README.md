Для каждого POST создания единицы раннер выдаёт свежий Idempotency-Key, сохраняемый только для повторов того же шага. POST таблицы не получает этим обещания памяти повторов.

Без воркеров размещения нет. Доменный вход, закрытые grants, CSP и повтор логического действия проверяются отдельным стендом/тестом модуля, не этим TSV.

## Полная форма и воспроизводимость

Подмножество expect не заменяет проверку полной HTTP-формы [контракта урока](../../../spec/06-console.api.openapi.yaml): проверить обязательные поля, типы, Content-Type, специальные заголовки и отсутствие тела у HEAD/204. В строках ожиданий `$name` впервые связывается только после успешного совпадения всего ответа; следующие употребления сравнивают, запросы используют только уже связанные значения. Неудачная попытка @until не меняет переменные. @until повторяет чтение до указанного местного срока, не мутацию; после истечения — FAIL с последним ответом. @any допускает любое значение присутствующего поля, @absent требует отсутствия; они не подменяют типы полной схемы. JSON-объект сравнивается по подмножеству (`{}` на любом уровне — ровно пустой объект: словарь общего README), массив — по длине и порядку. Сырой HTML/текст сравнивается как байты UTF-8 с заданной подстрокой, не разбирается как JSON.

Успешный открытый /session содержит login_url (сценарий сессии — [приёмка главы 6.3](../3/README.md)).

## Дополнительная проверка чтением

Стабильный active intent направляет u на w-2 при placement=w-1 или его отсутствии — /where использует w-2; target="" даёт 404 с причиной intent. Чужой id/idle используют placement. Смена версии intent требует повторить чтение, неответ любого обязательного чтения — 503. Пульс читается после эффективного решения; отсутствие двери не превращается в null.

Проверить оба исхода отсутствия v и смонтированные /servers, /unplaceable, /where, /metrics и страницу. Для where(table,place): неизвестная таблица 404 до unit; затем форма/view, подтверждённое удержание и пульс, ошибка чтения 503, отсутствие удержания 404 с X-Unreachable. door необязателен и появляется только при подтверждённом адресате/держателе/подписанте; выдача журналируется. (Петля, доверие, Origin и аварийный вход — [приёмка главы 6.3](../3/README.md).)

Проверить каталоги root/mount: имя where не грузится; два отдельных корректных манифеста с mount b и семьёй root b не образуют допустимого каталога. Повторить для unit.rows и таблицы (включая списковую), оба направления пары и root каждого выбора. У GET/HEAD обеих mounted-страниц одинаковые наборы кодов, 200 отсутствует. Список делегирования не добавляет GET одной единицы владельцу (глава 6.1).

Это предмет ручной проверки спецификации и будущей проверки реализации. Подготовленные запросы, чтение и конечные модели автора не являются выполненным стендовым испытанием.

## Каталог source до перезапуска

Для `GET /manifest/<sub>/source` принять изменённый манифест store после старта консоли. До перезапуска дверь source сохраняет rev, served, sha256, manifest и secret_defaults каталога запуска; новая установленная подсистема вне этого каталога остаётся404. Иная rev текущей строки store не создаёт своего503 и чтения store при каждом запросе. Перезапустить и сверить новый каталог запуска и served. Независимые обычные отказы busy/trust сохраняются; это не ответ по несовпадению ревизий. Для доказательства отсутствия чтения записать настоящие вызовы store. Замороженный модуль платформы и тринадцать исходных байтовых фикстур не меняются.


обычный GET /metrics должен выдавать все пять рядов w2c_changes_resets_total при нуле: foreign, evicted, rights, labels, folders. Настоящая смена состава папки или её удаление уже даёт reset5; наблюдать этот reset и счётчик folders через тот же обычный HTTP-путь. Вход векторов manifest metrics[] не содержит состояния этих глобальных счётчиков и не объявляется такой проверкой. HEAD на шести предписанных существующих путях сравнивает допуск/статус/заголовки GET и пустое тело; исполнение требует обычной настоящей подготовки, не готового ответа.
