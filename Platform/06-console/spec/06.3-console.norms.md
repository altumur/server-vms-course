## Н1 Форма

**Время.** Строк и объектов со временем глава не пишет; строка журнала (`access.denied`, правки под отладочной личностью) —
`t` по [договору журнала событий](../../common/contracts/event-journal.md).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- пишет: `<корень событий>/audit/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append), `<корень событий>/audit.alarms/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `platform/spec/<sub>`, `domain/keys`, `domain/grants`, `domain/root`, `domain/member`, `domain/revoked`, `domain/grants/<кластер>`, `domain/break-glass/<кластер>`, `domain/disabled`.

Тревогу `session.debug_open` (Н1.3 `identity` п. 4) консоль кладёт в `audit.alarms/console` (договор журнала событий
`class`); `domain/disabled` — вход `disabled` функции `may` у держателя (Н1.3 `identity` п. 3, М11/9 Н1.5 `cluster`;
поздний слой) (разбор ревью стадии B 3–5, № 10).

Своих строк у главы нет. Ключи `rights:` консоль читает из строки спеки; «ключи есть» — строка `domain/keys`, гранты
отладочной личности — `domain/grants` (Н1.3 `identity` п. 4); следы домена — строки `domain/root`, `domain/member`,
`domain/revoked`, `domain/grants/*`, `domain/break-glass/*` (Н1.8, поздний слой). Журнал отказа доступа и правок под
отладочной личностью консоль дописывает в `audit/console` по договору журнала событий (участник `append`, владелец — P/05).

### Н1.3 Сторожевая

Блок `gate` (состояния `on`, `open`, `shut`, `identity`, `x_user`, `caps`, `need`, `scope`, `csrf`, `body`, `refusal`),
`open_routes` и `session` — [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Сторожевая» (владелец —
этот урок, глава 6.3; участник — консоль домена, урок P/10; перенесено туда без изменения, имена полей прежние; разбор ревью
стадии A 8–10, № 14 / решение 3).

Разбор запроса консоли (P/01.1 Н2.1 с отступлениями консоли) — [глава 6.5](06.5-console.norms.md) Н2; предел тела `body`
читают все двери консоли (главы 6.1, 6.4, 6.6). Отладочная личность и `debug` — ADR-0050.

### Н1.5 Ключи `rights:` спеки — граница прав людей

Не права процессов: что консоль спрашивает у грантов человека (`view`/`edit`/`admin`, М11) при правке. Форма — [глава P/02.1](../../02-installer/spec/02.1-installer.norms.md); смысл одинаков у обеих реализаций:

| Ключ | Смысл |
|---|---|
| `routes: {view: [семьи], edit: [семьи]}` | записи семьи требуют меньше, чем `admin`: `view` или `edit`; у строк единиц понижается только создание |
| `cluster_rows: true` | любая запись строки единицы требует гранта на кластер |
| `unit_of: {таблица: поле}` | строка таблицы принадлежит единице из поля; запись требует права на единицу прежней и новой строки |
| `reach: {group: [поля], cluster: [поля], requests: [действия]}` | что меняет правка сверх единицы: поле группы — все единицы старой и новой группы; поле кластера — грант на кластер; просьба с действием — `edit` на всю группу (действие — поле `action` тела просьбы, [глава 6.4](06.4-console.norms.md) Н1.5 `action`; разбор ревью стадии A 6–7, № 14); `reach.group` требует `placement.group_by` |
| `names: [{field, unit, sub \| of}]` | единицы, которые строка называет внутри `json`-поля; их цели добавляются к досягаемости правки |

Права процессов на хранилище (роли, файл прав, оценщик) — [P/01.2](../../01-store/spec/01.2-store.norms.md); вывод прав
каждой роли из ключей спеки — [P/02.5](../../02-installer/spec/02.5-installer.norms.md); правило адреса без домена —
[P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md) `roles`.

### Н1.8 Поздний слой: следы домена у сторожевой — вводит урок P/08

Подраздел позднего слоя (как [P/02.1 Н1.2б](../../02-installer/spec/02.1-installer.norms.md)): нормы читаются после урока P/08
(P/08.2 — корень, ключи и токены; P/08.4 — люди и гранты), до его переноса — М11/2 и М11/9; сценарии — в приёмке М11 до
переноса уроков P/08–P/10. Перенесено из [М11/2](../../../М11_Domain/spec/02-root-keys-and-revocation.norms.md) Н1.8 (P/06.3-04,
вводит P/08.2) и строки `loopback` [М11/9](../../../М11_Domain/spec/09-people-grants-names.norms.md) Н1.5 (P/06.3-05, вводит P/08.4).

Состояния `on`, `open`, `shut` сторожевой консоли — Н1.3. «Ключи есть» — строка `domain/keys` читается и принимается
функцией `keys` ([договор набора ключей домена](../../common/contracts/keys.md); разбор ревью стадии A 8–10, № 13) с закреплённым корнем. «След домена» — любая из строк `domain/root`, `domain/member`, `domain/revoked`,
`domain/grants/*`, `domain/break-glass/*`, или этот процесс консоли уже видел ключи: тогда без ключей — `shut` (503), не `open`.

В состоянии `on` личность — порядком Н1.3 `identity`: подпись агента — [договор подписи агента](../../common/contracts/agent-signature.md); токен — функция `token`
[договор токена домена](../../common/contracts/domain-token.md) «Проверка» (владелец М11/2; разбор ревью стадии B 3–5, В1) по набору этого кластера с `expect {kind: person, cluster: null}` (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10); гранты человека и вход — М11/9. Без личности — 401, не 503: 503 — только `shut`. В `on`
человек — только по входу и грантам (М11/9 Н1.5); «петля — operator» — только `open`; агент своего кластера проходит по
подписи ([договор подписи агента](../../common/contracts/agent-signature.md); разбор ревью стадии A 8–10, № 13).

```yaml
loopback:  «петля — operator» — только состояние open (нет домена, Н1.3); в состоянии on — только М11/9 Н1.5
```

## Н3 Проход

Сторожевая исполняется на каждом запросе в порядке [главы 6.5](06.5-console.norms.md) Н3 «запрос → ответ (консоль)»:
доверие `gate` — чтением на каждом запросе, без кэша, до разбора пути и тела (шаг 3); `/session*` — процедура Н1.3 после
установления личности, с проверкой Origin до изменения сессии и кук (шаг 4); личность по Н1.3 `identity` (шаг 6); Origin
по куке, единицы из пути и требуемая возможность — грант или 403 с журналом (шаг 7); единицы тела по Н1.5 (`unit_of`,
`reach`, `names`) после ограниченного чтения тела, ни одного изменения до завершения всех проверок (шаг 8). Своего
прохода, кроме этого порядка, у главы нет.

## Н4 Отказы

| Причина | Код | Тело | Что делает вызывающий |
|---|---|---|---|
| аварийный вход: пароль не сверился | 401 | `{detail, error: denied}` | не создавать сессию; общий журнал отказа доступа; в счёт предела (М11/9 Н1.6) |
| аварийный вход: нет строки или члена (условия) | 403 | `{detail, error: denied}` | не создавать сессию; общий журнал отказа доступа |
| не личность | 401 | `{detail: "this console asks who is calling: …", error: denied}` | войти (login_url) |
| гранта нет | 403 | `{detail: "<кто> may not <cap> <единица \| here>", error: denied}`; журнал | — |
| нет домена, не петля | 403 | `{detail: "this cluster is in no domain … loopback", error: denied}` | подключить домен |
| ключи были, проверить нечем | 503 | `{detail: "…admits nobody", error: denied}` | восстановить доверие |
| чужой Origin на действующем запросе по куке | 403 | `{detail, error: denied}` | — |
| `/session POST` у открытой консоли | 400 | `{detail, error: "this console is open"}` | — |
| `/session GET` и `DELETE` у открытой консоли | 200 | GET — `{open: true, login_url}`; DELETE — `{out: true}` | — |
| аварийный вход: предел | 429 | `Retry-After` | ждать |

Отказ сторожевой не имеет побочных записей двери. Полоса, рамка, нет пути, метод, тело, общий предел входа консоли (429) —
[глава 6.5](06.5-console.norms.md) Н4.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/06.3-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/06.3-01** ключи `rights:` Н1.5 исполняются консолью при правке людьми — проверяется чтением: тест консоли реализации на `unit_of`/`reach`/`names` (предмет — Н1.5 построчно); причина — приёмка консоли (главы 6.3, 6.5) идёт без домена и грантов, стенд с грантами — М11
- [ ] **P/06.3-02** сторожевая Н1.3: открыта только с петли — раннер звонит с петли и получает `open: true` — сц. 03 шаг 1; порядок `identity`, `need` по пути до тела, `X-User` никогда, закрыта при потере доверия, `{detail, error: denied}`, журнал `access.denied` — проверяются чтением: стенд приёмки без домена и с петли, ветвей 401/403/503 не достигает (стенд М11) (разбор ревью стадии A 6–7, № 22)
- [ ] **P/06.3-03** `/session` Н1.3: форма у открытой консоли — `GET` `{open: true, login_url}`, `POST` 400, `DELETE` `{out: true}` и снятие кук `w2c_token`, `w2c_glass` — сц. 03 шаги 1–5; `grants` и `via` доказанной личности — чтением Н1.3 `session`; вызов `may` модуля — чтением до правки долга байтов ([P/07](../../07-console-module/spec/07-console-module.norms.md) «Решает реализация» п. 1; разбор ревью стадии B 6–7, № 28): гранты выдаёт домен (стенд М11/9, сц. 01), сценарии урока идут без домена (разбор ревью стадии A 6–7, № 22)
