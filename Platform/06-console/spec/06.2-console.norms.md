# P/06.2 — Запись секретов: нормы

Канон главы 6.2 урока P/06 «Консоль кластера» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../06-console.md),
[контракт](06-console.api.openapi.yaml), [инструкция](06-console.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/2/README.md). Конверт `enc:v2`, путь AAD, грамматика `kid` и форма файла кольца — общий
[договор запечатывания](../../common/contracts/sealing.md) (векторы [`common/vectors/sealing/`](../../common/vectors/sealing/README.md));
глава его не повторяет и нормирует сторону консоли: что секрет и где его нет, маску, пароль в адресе, запечатывание при
записи и перезапечатывание при старте, кто держит ключ, ротацию, режим без ключа и отпечаток. Правило имени `*_secret` и
отказ загрузки — [P/02.1 Н1.3а](../../02-installer/spec/02.1-installer.norms.md); секретные строки и читатели —
[P/02.5 Н1.3](../../02-installer/spec/02.5-installer.norms.md); команды `w2cctl secrets` и файл кольца —
[P/02.4 Н1.9](../../02-installer/spec/02.4-installer.norms.md); открытие получателем —
[P/03.5](../../03-worker/spec/03.5-worker.norms.md).

Глава перенесена из М10/7 (стадия B, ADR-0083 доп. (1): без
изменения поведения): весь остаток урока — Н1.1 без `rule` и `type`, Н1.1а, Н1.2 — сторона консоли, Н1.4, Н2, Н3
«создать/править строку единицы», «перезапечатать при старте», «Смена кольца», «прочитать_адрес», Н4, Н5 с приёмкой
М10/07, «Решает реализация». Номера подразделов — прежние номера М10/7. «Глава 6.K» — глава этого урока: дверь единиц и
таблиц (бывшие М10/3 и М10/10 Н1.4–Н1.6) — глава [6.1](06.1-console.norms.md), `GET /manifest` и токен двери (бывший М10/9) —
глава [6.5](06.5-console.norms.md); «P/0N.K» — глава перенесённого урока; «М11/N» — урок-источник М11 (снят переносами уроков 8–10; новые адреса — id-map).
Id норм — `P/06.2-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у главы нет.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- пишет: `<sub>/<manifest:unit.rows>/<id>` (cas), `<sub>/<manifest:tables>/<имя>` (cas), `door/signer` (cas);
- читает: `/etc/w2c/secrets/platform.key`, `platform/manifest/<sub>`, `<sub>/<manifest:unit.rows>/<id>`, `<sub>/idem/<key>`.

Файл кольца пишут команды установщика `w2cctl secrets new` и `rotate` — владелец P/02.4 (разбор ревью стадии A 6–7,
№ 5); консоль его читает по пути `SECRETS_KEY`. Строки единиц и таблиц — глава 6.1, `door/signer` — глава 6.5 (Н3
«`/where/<id>`», токен двери): консоль запечатывает в них секреты при записи (Н3 «создать/править») и перезапечатывает под текущий `kid`
при старте (`cas` по прочитанной версии, revision не растёт). Своих семей у главы нет.

### Н1.1 Что секрет

```yaml
secret_field:
  # rule (имя поля *_secret, без реестра) и type в манифесте — перенесены в P/02.1 Н1.3а (стадия B)
  where:  поля единицы, поля таблиц, строки платформы (P/08.2 Н1.3–Н1.4: domain/signer {token_key_secret, issuing_key_secret, …}, domain/book-seal {seed_secret}, door/signer
          {kid, seed_secret}, domain/member-key {seed_secret, …}, domain/break-glass/<к> {pwhash_secret, …}, …)
url_field:                                   # у поля type: url (форма — P/02.1 Н1.2а): credentials, secret_in, общий словарь
                                             # common_words и чтение адреса — [договор адреса](../../common/contracts/url-credentials.md) (W03-E07)
  bound_to: <поле> | [<поле>…]               # только у *_secret; одно имя — список из одного, /manifest отдаёт списком (глава 6.5 Н2 «GET /manifest»); поля той же строки, не секреты: адрес, к которому пароль
mask:   "***"                                # показ непустого секрета; пустой — пустой; в адресе — где стоит
mask_in: распознавание маски на входе — договор маски журнала `mask_in` (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, А-21) — отказ
```

### Н1.1а Адрес: где в нём логин и пароль

Правило поля (`credentials`, `secret_in`), общий словарь `common_words` и чтение адреса А1–А15 — [договор адреса](../../common/contracts/url-credentials.md) (перенесено без изменения поведения; догадка стадии C W03-E07, решение «Архитектора» 2026-10-23). Глава нормирует
сторону консоли: показ сохранённого адреса маской и отказ `bad_url` двери (Н4).

Публичные идентификаторы не являются каналом секретов: unit.id и каждый источник table.key/requests.key не оканчиваются на _secret; иначе отказ загрузки P/02.1 (P/02.1-19). Маска исходного поля не делает допустимой его открытую копию в id/name/rid, ключе или цели журнала.

### Н1.2 Конверт и кольцо

Конверт `enc:v2`, путь AAD, грамматика `kid` и форма файла кольца (`line`, `mode`) — общий
[договор запечатывания](../../common/contracts/sealing.md) (ревью стадии B 1–2, п. 4; векторы — [`common/vectors/sealing/`](../../common/vectors/sealing/README.md)).
Здесь — кто держит ключ, ротация, режим без ключа и отпечаток:

```yaml
ring_file:                                   # форма файла — договор запечатывания «Файл кольца»
  holders: группа w2c-secrets: консоль, воркеры подсистем, в манифесте которых есть секретные поля, подписант домена, агент
           домена; контроллер, ресурс, консоль домена — без ключа
rotate:    новая строка сверху → перезапуск держателей → консоль при старте перезапечатывает свои строки под текущий kid
           (cas, revision не растёт) → secrets seal дозапечатывает остальное → status; все старые ключи сохраняются
no_key:
  unset:        SECRETS_KEY не задан → режим разработки с громкой строкой лога; чтение/PUT открытых значений сохранены:
                PUT с непустым *_secret пишет значение открытым (сверка python и go М10/6–11, совпало);
                POST создания с переданным непустым *_secret на любой глубине запрещён до заявки (400, Н4);
                SECRETS_KEY="" (задан пустым) — не режим разработки, а unreadable ниже (сверка python и go М10/6–11, S11)
  unreadable:   задан, но не читается → все POST/PUT единиц отказываются 503 `unavailable` (Н4),
                включая тело без секретного поля: кольцо нужно также для HMAC памяти повторов. Это не режим без ключа; GET/DELETE этим отказом не блокируются
  open_without: P/03.5 Н1.2 (стадия B; сторона воркера)
  row_check:    те же три состояния у общей проверки строки — договор проверки строки «Подготовка полей», «Граница
                кольца» (состояние кольца — опция вызывающего; C06-ROWCHECK-DEV-01)
print:     отпечаток идемпотентности тела с секретом — HMAC исходного запроса под производным ключом кольца
           (hmac:<kid>:<hex>); при повторе — kid сохранённой заявки, не текущий ключ.
           Без кольца POST с непустым секретом вне профиля; маска и голый хэш секретного тела не заменяют HMAC
```

Сообщение open_without — [P/03.5 Н1.2](../../03-worker/spec/03.5-worker.norms.md) (стадия B).
Ротацию ведёт один оператор; обычные записи секретов остановлены на время смены кольца,
перезапечатывания и окончательной проверки `status`. Конкурирующие `rotate`, ручная правка
кольца исключены условиями обслуживания. Удаление прежних ключей целиком вне профиля
главы: ноль старых конвертов в status не разрешает удалить ключ. Он может быть нужен
живой pending/done-заявке с `hmac:<kid>:…` и копии, которую status не перечисляет.
Это сужение области команды, а не обещание транзакционного переключения всех процессов.
Переход к незаданному кольцу при сохранённых HMAC-заявках также вне профиля; режим
разработки без кольца начинают с новой пустой памятью заявок. Ротация не меняет уже
сохранённые отпечатки и не пытается восстановить исходный запрос из изменившейся единицы.

### Н1.4 Где секрета нет

При создании единицы непереданное строковое поле без default/inherit получает пустую
строку по главе 6.1 Н1.2. Это относится и к объявленному `*_secret`: пустая строка выдаётся
пустой, непустой секрет — маской. Отсутствие поля у таблицы — другое правило ниже.

```yaml
never:     где секрета нет (ответы, память повторов, снимок, домен, журнал, пульс, лог, argv, текст отказа) — договор маски
           журнала «Где действует» `never` (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, Б-30)
```

## Н2 Двери

Собственных путей у главы нет (ADR-0082 доп. 14). Используется дверь единиц [главы 6.1](06.1-console.norms.md) —
её пути в [контракте урока](06-console.api.openapi.yaml), — а для чтения строк —
[контракт хранилища P/01.1](../../01-store/spec/01-store.api.openapi.yaml). Здесь задаются правила полей
и отказов секретов поверх этих входов; новые маршруты и копия OpenAPI не создаются.

| Вход | Полное тело по контракту владельца | Ограничение этой главы |
|---|---|---|
| POST единицы, 201; PUT, 200 | CreatedUnit / UpdatedUnit | Непустые секреты маской; `id`, `revision` и прочие поля по главе 6.1; сохранённый ответ POST также с масками |
| GET списка единиц, 200 | UnitList (`rows`, `configured`) | Маска на любой глубине; таблица отдаётся без секретных полей, её дверь `GET /<table>` — глава 6.1 Н2 |
| POST/PUT, 400 | `{detail, error}`; при неверном url также `fault: bad_url` | Обе строки обязательны, значение секрета не повторяется; маска, конверт и смена bound_to не получают `bad_url`; только POST без кольца с непустым секретом — sealing key required без fault по Н4 |
| POST/PUT, 503 при нечитаемом кольце | SealingUnavailable: `{detail, error: "unavailable"}` | detail — `the sealing key is set and does not read`; без fault; общие отказы хранилища/полосы сохраняют собственные формы главы 6.1 |
| GET строки хранилища | Row либо ForbiddenFault P/01.1 | У читателя в items конверт; у нечитателя 403, значение не выдаётся |

Загрузка манифеста и правка члена через домен — входы своих уроков; HTTP-отказ домена не
выдаётся за ответ двери единиц. Формы успеха, прочие поля и общие коды транспорта берутся
из указанных контрактов, а не из сокращённых ожиданий TSV. Команды обслуживания `w2cctl secrets` перенесены в
[P/02.4 Н1.9](../../02-installer/spec/02.4-installer.norms.md) (стадия B).

## Н3 Проход

### создать/править строку единицы, в том числе с секретами (консоль; проход главы 6.1)

До шага 2 создания главы 6.1, после проверки заголовка и JSON-объекта, проверить профиль:
при незаданном кольце и переданном непустом *_secret на любой глубине POST даёт
400 без создания/снятия заявки, резервирования номера или записи единицы. Это проверка
входного тела, не маскированного ответа. При наличии кольца остаются порядок формы,
HMAC и владение заявкой главы 6.1; повторы проверяются под kid сохранённого отпечатка.
Заданное нечитаемое кольцо проверяется после разбора JSON-объекта и до HMAC/заявки/записи
для любого POST/PUT единицы; результат — 503 из Н4. Плохой framing/необъект до этого даёт свой 400.
Это более ранняя проверка того же условия, чем шаг запечатывания ниже; секретов в теле может не быть.

```
1. после ограниченного чтения и разбора JSON-объекта: ключ задан, но не читается → 503 unavailable (Н4),
   до HMAC, заявки и проверок полей; у PUT заявки нет — до проверок полей и записи; состояние своей заявки —
   по правилам 5xx главы 6.1 Н3, чужую не снимать
2. отказы формы (глава 6.1 Н3, шаг 4) раньше отказов значения секрета: сначала тип и url по правилу поля → bad_url, затем
   значение-конверт → 400, затем значение-маска → 400; первый отказ по этому порядку называет причину (сверка python и go М10/6–11, S14);
   вложенный *_secret — строка или null; иное (число, bool, объект, массив) → 400 до записи (сверка python и go М10/6–11, S13)
3. правка: пустое, null или отсутствующее *_secret верхнего уровня → прежнее значение; сменилось поле из bound_to при пустом секрете
   → 400 «must be given anew» — есть ли у хранимой строки секрет или нет; прежний секрет на новый адрес не уходит
   никогда (проверяется внутри cas против строки как хранится). Правило одно для двери единиц и двери таблиц
   (глава 6.1 Н3 «таблица — записать строку»: POST поверх строки с тем же именем — правка) (сверка python и go
   М10/6–11, S9, S10, T13)
   json-поле с вложенными *_secret правкой заменяется целиком: вложенный секрет пришедшего значения — его собственный,
   сохранения «по индексу» или по ключу из хранимого значения нет; вложенный *_secret, пришедший пустым, null или без
   ключа, — без секрета и хранится как пришёл (ответ — "", null или без ключа), но никогда не секрет соседнего или прежнего
   элемента; ответ на вложенный null — null (сверка python и go М10/6–11, S1, S20)
4. обойти непустые *_secret с полным путём от корня строки, в том числе внутри значения json-поля на любой глубине;
   запечатать с единственным AAD Н1.2 (ответ маскирует их на той же глубине, воркер открывает тем же путём);
   уже конверт — как есть, не переносить его на иной путь; массивы включают индекс
5. записать строку; ответ — с маской; копия для повтора — с маской
```

**Гонки.** Две правки одной строки: `cas` (глава 6.1); `bound_to` проверяется внутри мутатора против строки как хранится — смена поля и смена пароля в двух правках разом: одна проходит, вторая перечитывает, видит новое поле и без секрета получает 400 «must be given anew».

Открытие конверта воркером (`start_unit`) — [P/03.5 Н3 «открыть»](../../03-worker/spec/03.5-worker.norms.md) (стадия B).

### перезапечатать при старте (консоль)

Что делается с одним значением (обход полей, текущий и прежний kid, открытое, enc:v1, не по грамматике, неизвестный kid,
неоткрывающийся тег) — [договор запечатывания](../../common/contracts/sealing.md) «Перезапечатать значение» (векторы `reseal.tsv`;
C06-RESEAL-33-01); здесь — какие строки, `cas`, гонки.

```
для каждой строки единиц и таблиц всех манифестов каталога, где есть поля *_secret (это все строки, которые консоль пишет:
таблица воркера из worker.writes полей *_secret не объявляет — P/02.1 Н1.2а): *_secret на любой глубине, в том числе
внутри значения json-поля, в открытом виде или под старым kid → запечатать текущим (сверка python и go М10/6–11, S5), cas по прочитанной,
revision не менять; enc:v1 — не трогать и считать «?» (мёртвый формат, ADR-0003)
строка door/signer (глава 6.5 Н3 «`/where/<id>`»), если она есть: seed_secret в открытом виде или под старым kid → запечатать
текущим, тот же cas по прочитанной версии (разбор ревью стадии B 6–7, № 2)
строка, которая не читается (значение json-поля не JSON, строка не по форме) → пропустить: строка лога с ключом и
причиной, строка не меняется; остальные перезапечатываются, старт консоли этим не прерывается (сверка python и go М10/6–11, S8)
после прохода — свой kid подписанта в door/keys: глава 6.5 Н3 «`/where/<id>`» (разбор ревью стадии B 6–7, № 3)
```

**Гонки.** Две консоли перезапечатывают одно при старте: `cas` по строке — вторая видит новый `kid` и ничего не пишет; перезапечатывание против правки оператора — `cas`, проигравший перечитывает; `door/signer` против его создания при первой выдаче — `cas`, проигравший перечитывает.

### Смена кольца: состояния обслуживания

Условия допуска — Н1.2: один оператор, обычные записи секретов остановлены; CAS
перезапечатывания остаётся обязательным. Таблица не вводит новых полей на диске.

| Состояние | Действие | Результат и отказ |
|---|---|---|
| Прежнее кольцо доступно, обслуживание допущено | Проверить кольцо; rotate добавляет новый kN сверху, старые ключи сохраняет | Ошибка проверки оставляет файл прежним; прежние конверты читаются старыми ключами |
| Новый файл установлен, держатели могут иметь старую копию | Перезапустить держателей с новым кольцом; затем консоль | До готовности держателей перезапечатывание не начинать; ошибка перезапуска оставляет обслуживание незавершённым |
| Держатели знают оба ключа | Консоль при старте и seal обходят строки с CAS по Н3 | Конфликт — перечитать; ошибка чтения/записи или неизвестный исход не равны завершению |
| Обход завершён | status проверяет тот же охват | Все прежние ключи сохранить, в том числе для pending/done HMAC и копий; ноль конвертов не разрешает удаление |

После обрыва оператор продолжает с подтверждённого состояния, сохраняя старые ключи;
автоматическое восстановление процесса обслуживания в главу не входит.

### прочитать_адрес(значение, правило поля, каталог) → показ | отказ(поле)

Функция — [договор адреса](../../common/contracts/url-credentials.md) «прочитать_адрес»; у консоли показ — в ответах и копиях (Н1.4), отказ — 400 `fault: bad_url` (Н4).

**Гонки.** Две правки одной строки: `cas` главы 6.1; проверка привязки — внутри `cas` против строки как хранится, так что «прежний пароль остался у нового адреса» невозможно и при гонке. Смена ключа и держатели: держатели перезапускаются раньше консоли, иначе воркер со старым кольцом не откроет перезапечатанное.

## Н4 Отказы

| Причина | Код | Тело | Что делает вызывающий |
|---|---|---|---|
| значение `*_secret` начинается с `enc:` | 400 | `error` «a sealed value is not taken from outside — give the password itself» | прислать пароль |
| значение `*_secret` — маска | 400 | `error` «this is the mask a secret is shown as, not a secret — leave the field out … to keep» | убрать поле |
| поле из `bound_to` сменилось, секрет пуст (у хранимой строки секрет есть или нет; дверь единиц и дверь таблиц) | 400 | `error` «<поле> changed: <секрет> must be given anew» | прислать пароль к новому адресу |
| вложенный `*_secret` не строка и не null (Н3 шаг 2) | 400 | `error` с путём поля, без значения | прислать строку |
| пароль или логин в адресе (Н1.1а); url не разбирается, в том числе знак вне грамматики RFC 3986 (А2); пароль на месте порта; url в параметре глубже 3 | 400 | `fault: bad_url`, `error` без значения, с именами полей `credentials` — какие поля, по А15 | положить в поля |
| правка члена через домен с `*_secret` (P/08.6 Н1.3) | 400 | «a secret is set in the member's own cluster, never through a kept edit» | править в своём кластере |
| POST создания с непустым секретом, кольцо не задано | 400 | `{error: "sealing key required", detail: "a sealing key is required for POST with secrets"}`, без fault; заявка не создаётся и не меняется | настроить кольцо или подать тело без непустого секрета |
| ключ задан и не читается, любой POST/PUT единицы | 503 | `{error: unavailable, detail: "the sealing key is set and does not read"}`; 5xx не сохраняется как done, судьба pending по главе 6.1 Н3 | починить кольцо, повторить тем же ключом |
| чтение секретной строки не читателем | 403 | `forbidden` (P/01.2 Н1.3, P/02.5 Н1.3) | — |
| кольцо: нет записей ключей, неверная запись или встроенный комментарий | кольцо нечитаемо | диагностика без материала ключа; строка с первым непробельным # — комментарий, а не запись ключа | исправить файл до использования |

`secrets.readers`/`reads` — в [P/02.5 Н4](../../02-installer/spec/02.5-installer.norms.md), отказы команд `w2cctl secrets` — в [P/02.4 Н4](../../02-installer/spec/02.4-installer.norms.md) (стадия B); отказ открытия у воркера — [P/03.5 Н4](../../03-worker/spec/03.5-worker.norms.md) (стадия B).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **кто ещё держит ключ** сверх Н1.2 и как ключ попадает в процесс консоли (`LoadCredential`, монтирование, переменная); в процесс воркера — [P/03.5](../../03-worker/spec/03.5-worker.norms.md) «Решает реализация» п. 1 (стадия B);
2. **производный ключ отпечатка** идемпотентности и строку под HMAC; исходный запрос включает личность/метод/путь/тело по главе 6.1, маска не подменяет тело. Отпечаток живёт только в строке заявки своей консоли и ДОЛЖЕН быть устойчив при её перезапуске и при смене kid: повтор использует kid сохранённой заявки. Заявку с отпечатком, форму которого консоль не узнаёт (заявка консоли другой реализации), она не снимает и не сравнивает: повтор под тем же ключом получает 503 по правилам чужой заявки главы 6.1 Н3 всё время, пока заявка жива; две консоли разных реализаций на одном хранилище вне профиля, пока форма отпечатка не общая (сверка python и go М10/6–11, S15);
3. **как консоль открывает конверт `door/signer`**; форма `door/signer` и `door/keys` и байты токена двери — [глава 6.5](06.5-console.norms.md) Н3 «`/where/<id>`»
   (изменено журналом cammeta-go, урок 9 № 3);
4. **лог-маска**: какие ещё места текста маскируются сверх Н1.4;
5. **на платформах без групп** (macOS) — чем заменены `w2c-secrets` и `InaccessiblePaths`.

Поведение `secrets status`/`seal` без манифестов в хранилище и форма их вывода — [P/02.4](../../02-installer/spec/02.4-installer.norms.md)
«Решает реализация» пп. 5, 6 (стадия B; пп. 2, 7 М10/7).
