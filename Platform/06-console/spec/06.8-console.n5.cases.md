# Judge-only N5 case coverage

This English text is the source; the Russian translation `ru/spec/06.8-console.n5.cases.md` is derived from it (ADR-0121).

These case descriptions and their outcomes are judge-only data. The canonical normative chapter is [`06.8-console.norms.md`](06.8-console.norms.md). Generic rules and explicitly retained normative examples remain there.

### Case block 1

- [ ] **P/06.8-01** the folder and membership rows by the form of N1.1, the id — 128 random bits, lowercase hex, the caller does not set the id — sc. 01 steps 1–4, 8–13; the randomness — by reading: the stand sees only the form

### Case block 2

- [ ] **P/06.8-03** a member is only a unit of a subsystem with `display.tree.folders`, live, with a representable membership key; a repeat — 400 — sc. 03 steps 3–10, the key at the boundary — steps 11–14

### Case block 3

- [ ] **P/06.8-05** the folder tombstone, a write over it — refusal — sc. 05 steps 3–10

### Case block 4

- [ ] **P/06.8-06** a read gives out only live folders; a subfolder of a deleted one — 404 from the same index — sc. 06 steps 7–11; an unreadable row: the element `garbled`, 503 — sc. 12 steps 12–14; no answer of the store — by reading

### Case block 5

- [ ] **P/06.8-07** the chain to the root at every write, guards on each row of the chain; an ancestor deleted between the read and the write — 412 — by reading: the HTTP stand does not open the window between the read and the write; a refusal on a ready tombstone — sc. 04 steps 10–16, sc. 06 step 10

### Case block 6

- [ ] **P/06.8-08** edit: `If-Match`, 412 with the current row, a write without changes does not change the index — sc. 01 steps 5–7, sc. 02 steps 10–12

### Case block 7

- [ ] **P/06.8-09** the `Idempotency-Key` memory of the folder doors, `done` in the batch, the refusals of the chain and rights steps enter the memory — sc. 02 steps 13–16; a repeat after the deletion of the parent — by reading: a lost answer is needed

### Case block 8

- [ ] **P/06.8-10** folder deletion: the tombstone and the removal of the membership by one batch, the units remain, the subfolders — the reaper — sc. 06 steps 7–16

### Case block 9

- [ ] **P/06.8-11** a unit deletion by the door removes it from the folders by the same batch, the guard of the row's absence — sc. 07 steps 6–20, sc. 08 steps 1–16; a strict race of the read and the write — by reading: the HTTP stand does not open the window between them

### Case block 10

- [ ] **P/06.8-14** the reaper: removes unreachable rows and dangling members by a batch, does not remove on an unknown read — sc. 06 steps 14–16, sc. 10 steps 5–8; the unknown — by reading
