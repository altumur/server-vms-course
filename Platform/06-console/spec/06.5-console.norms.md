### N1.8 `door.pass`

<!-- req: P/06.5-R006 -->

The block `manifest`, `rule`, `codes` (from M10/11 N1.8) — [the gate and pass contract](../../common/contracts/gate-and-pass.md)

**Live worker with a door** (review of stage A 6–7, № 25 — the definition; the witnesses are reconciled, the debt row is in
the move report): a worker of the subsystem whose heartbeat `<sub>/heartbeats/<name>` reads (the outcomes of the heartbeat family

last `LOST_AFTER` by the console clock ([the observation contract](../../common/contracts/observation.md); the first
observation — fresh) — that is, `WorkerRow.state` is `live` (N2 «Outputs»), — and whose heartbeat field `url` is a non-empty
string (the door url, a platform row of P/03.4 N1.1). Of such workers of the subsystem — the smallest slot name (UTF-8
bytes); none — 503 `{error: denied, detail: "no worker of <sub> with a door is heard"}` (GP-L03, the decision of the Architect 2026-10-28). The slot and the lease
are not checked: the validity of the operation is checked by the worker with its own credentials and epoch.

**The second kind of `door.pass`** (ADR-0094 B1): which worker gets the pass — the same rule. The kind itself is the gate and pass contract «Pass of the second kind»: a ticket instead of a human credential, a list of headers and answer types, the form of refusals from the manifest, a pass as a stream. The worker cannot check a request of people with its own credentials, therefore the rights are decided by a fresh `may` on every callback ([chapter 6.3](06.3-console.norms.md) N1.9).

## N2 Doors

The doors of the platform console are a closed list; a subsystem has no doors of its own on the console, except the tables and requests from the manifest, `door.pass` (N1.8), the static files and the shell of a mounted subsystem (N1.1 `mounted`, N2 «Static files»). The catalogue-dependent entries are the standard `components.pathItems` `UnitsCollection`, `UnitItem`, `TableCollection`, `TableItem`, `PassRoot` and `ConsoleFile` of that contract. They are specialized from the same accepted loaded catalogue as described by the [forms](../forms/README.md); this changes only the representation. The complete finite names of `console.files`, both kinds of pass and their existing unbounded raw remainder and query remain governed below and by their current procedures. No new route, permission, fallback or one-segment tail is introduced.

**Console request parsing** — [the gate and pass contract](../../common/contracts/gate-and-pass.md) «Request parsing and the order of checks»
(moved there without a change; layout audit B-09, B-11, the decision of the Architect 2026-10-25); the numeric query
parameters — there as well, «Numeric query parameters»: URL decoding, then the reader grammar of their type of the
[row codec](../../common/data/codec.tsv), otherwise 400 with `detail` — the name of the parameter (C06-EVENTS-QUERY-LEXEME-162-01, the decision of the Architect 2026-10-27); the doors of other chapters refer here and name only their own deviations.

Common codes: an unknown path — `404 NoRoute`; a wrong method — `405 {detail: method, error: method}` without the header `Allow`

### Static files of a subsystem

<!-- req: P/06.5-R011 -->

`GET /<sub>/<file>` and `HEAD` (ADR-0094 addendum (1), (4) item 2): the console serves a file of the list `console.files` of the manifest `<sub>` of any
loaded subsystem, root included, byte for byte. There is no short path `/<file>`. This is how a subsystem connects its JS,
styles and fonts to the page; the console neither executes nor parses these bytes. The manifest of a subsystem and the shell are never files of the list.

**Order of path resolution.** First the subsystem is chosen by the first segment. The rest of the path is compared with the names of the list byte for
byte, without decoding (N3 step 5): a match — a static file; otherwise — the routes of the mounted subsystem (units, tables,
`door.pass`), then `404 NoRoute`. A name under `api/` is refused by the loader ([P/02.1](../../02-installer/spec/02.1-installer.norms.md)
N1.2a), therefore static files and routes under `/<sub>/api/` do not cross. A segment `..` cannot be in a name: `/<sub>/x/../app.js` is not
a name of the list, `404`.

**Gate** — as for any `GET` ([chapter 6.3](06.3-console.norms.md) N1.3 `need`: `view`, without a unit — any grant); a file and the shell of a mounted
subsystem do not become an open route. A method other than `GET` and `HEAD` on a name of the list — `405`.

**Login at the shell.** A mounted subsystem has no login of its own (ADR-0094 A4), and a browser would display JSON instead of a page. Therefore
`GET /<sub>/` and `GET /<sub>/index.html` of a shell with `console.shell`, where the gate would answer `401` «not an identity», answer `302`,
`Location: /?return=/<sub>/`, without a body. The login is the module window on the page `/`: `login_url` is a `POST` door without a page. After the login the module returns to `/<sub>/`, having checked the address
([P/07](../../07-console-module/spec/07-console-module.norms.md) N1.5 `return`). `HEAD` of the shell,
files and the other doors — the former `401`; a logged-in caller without a grant — the former `403`; `shut` — the former `503`.

**The query string is not judged.** The query is parsed as for an unread parameter (N2 «Common codes»): `<file>?v=<12 hex>`, a repeated
parameter and damage — the same file, not 400 and not 404. The shell refers to the files this way to reset the browser cache; the cache is by path and bytes.

**Answer 200** — the bytes of the whole file, the headers by extension:

| Extension | `Content-Type` | `X-Content-Type-Options` | `Content-Security-Policy` |
|---|---|---|---|
| `js` | `text/javascript; charset=utf-8` | `nosniff` | not required |
| `css` | `text/css; charset=utf-8` | `nosniff` | not required |
| `json` | `application/json` | `nosniff` | not required |
| `woff2` | `font/woff2` | `nosniff` | not required |
| `woff` | `font/woff` | `nosniff` | not required |
| `ttf` | `font/ttf` | `nosniff` | not required |
| `png` | `image/png` | `nosniff` | not required |
| `svg` | `image/svg+xml` | `nosniff` | `sandbox` |

`nosniff` keeps the browser from reading the bytes as another type. `sandbox` for `svg` is needed because `svg` executes its script when
opened directly, and its origin is the console. The files are connected by a page whose CSP (N1.1 `page`) allows `script-src 'self'`.

**Where the bytes come from.** The field `files` of the manifest row and the parts `platform/manifest/<sub>/files/<sha256>/<n>` ([P/02.3](../../02-installer/spec/02.3-installer.norms.md)
N1.5): the parts are glued in order, the size and SHA-256 are checked against the field `files` before the first byte of the answer. The name is not in `files`, the field
is unreadable, a part is absent, a part is unreadable (the family outcomes), the size or SHA-256 do not agree, the read is not confirmed — `503 {detail, error:
unavailable}`: the list promises the file, and `404` would pass damage off as its absence. Such a file is not served in part. A file refusal does not touch the other
doors, and the console start does not fail because of it. Keeping the checked bytes in memory is allowed: the key carries the digest, the bytes under it do not change.

### `door.pass`
