# P/06.5 — Наблюдения: нормы

Канон главы 6.5 урока P/06 «Консоль кластера» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../06-console.md),
[контракт](06-console.api.openapi.yaml), [инструкция](06-console.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/5/README.md). Одна дверь процесса — один контракт урока (план переноса урока 6, В6): глава
ссылается на свои пути `GET /spec`, `/mounts`, страницу и модуль, `/servers`, `/resources`, `/unplaceable`, обе формы
`/where`, `/metrics`, `/healthz` и маршруты `door.pass`.

Глава перенесена из М10/9 (стадия B, ADR-0083 доп. (1): без изменения
поведения): Н1.1, Н1.2, Н2 (с дверью `GET /spec`, перенесённой туда из М10/2 переносом урока 2), Н3, строки Н4 и Н5 о
них, пп. 1–3, 5–7 «Решает реализация»; из М10/10 —
сторона читателя снимка (Н1.3 `age`, `metrics`; писатель — [P/04 Н1.3а](../../04-controller/spec/04-controller.norms.md));
из М10/11 — `door.pass` (Н1.8, абзац Н2,
строки Н4). Номера подразделов — прежние номера источника (Н1.1, Н1.2 — М10/9; Н1.3 — М10/10; Н1.8 — М10/11).
Сторожевая, `/session` и личность (М10/9 Н1.3) — [глава 6.3](06.3-console.norms.md); закрытый список вызовов модуля и
контракт оболочки (М10/9 Н1.4, Н1.5) — [урок P/07](../../07-console-module/spec/07-console-module.norms.md) Н1.4, Н1.5. Как консоль судит
ресурс, живость по `LOST_AFTER`, первое наблюдение и чтение intent → placement → intent — [договор
наблюдения](../../common/contracts/observation.md) (разбор ревью стадии A 6–7, № 1, № 2). Правки поведения в главе —
по разбору ревью стадии A 6–7 (`decisions/inbox/2026-10-20-ревью-стадии-a-6-7-разбор.md`), каждая помечена номером:
№ 1 (граница `LOST_AFTER` — `≤`), № 13 (элемент пульса с нецелым `observed_revision`), № 25 (определение «живой воркер
с дверью»). Ссылка «М11/N» — урок М11 (`М11_Domain/`), ещё не перенесённый;
«глава 6.K» — глава этого урока; «P/0N[.K]» — урок или глава модуля. Id норм — `P/06.5-MM`; соответствие прежним id —
[`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у строк главы (`door/signer`, `door/keys`) нет. Время, которое глава читает, — по [канону Н0
P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): пульс воркера — `ts`, `previous_hb`
([P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.1), пульс ресурса — [P/05](../../05-resource/spec/05-resource.norms.md)
Н1.4, шард снимка — `ts` ([P/04 Н1](../../04-controller/spec/04-controller.norms.md) «Время»); `expires` токена двери —
стенные секунды выдачи + 120 (Н3 «Токен двери — байты»).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `door/signer`, `door/keys`;
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `<sub>/placement/<id>`, `<sub>/controller/placement_intent`, `<sub>/controller/pass`, `platform/doors/<сервер>`, `<sub>/heartbeats/<имя>`, `platform/resources/<server>/heartbeat`, `<sub>/slots/<имя>`, `<sub>/snapshot/<воркер>`, `<sub>/snapshot/unplaced`, `<sub>/holds/<место>`, `<sub>/<spec:unit.rows>/<id>`.

Строки управления (`platform/servers/<сервер>`, `platform/drain`, `platform/decommission/<сервер>`, `<sub>/policy`) консоль
пишет дверями [главы 6.6](06.6-console.norms.md); здесь они только показываются в `/servers`. Шарды снимка консоль читает
для возраста и рядов `/metrics` (Н1.3); писатель — контроллер, [P/04 Н1.3а](../../04-controller/spec/04-controller.norms.md).

### Н1.1 Три части

```yaml
console_process:                              # платформа; один на сервер; из каталога спек (строки platform/spec/*, P/02.3)
  root:     CONSOLE_ROOT — подсистема, чья оболочка отдаётся на /; остальные — /mounts, без страницы; задана пустой
            строкой или называет подсистему не из каталога — процесс не стартует, код 2 (сверка python и go М10/6–11, C36)
  shell:    поле shell строки спеки platform/spec/<sub> (P/02.3 Н1.5); пусто или нет поля — console.html платформы;
            файла рядом со спекой консоль не ищет: она читает каталог из хранилища; оболочка отдаётся байт в байт, как
            записана (CRLF не меняется, хэши CSP — от этих байт; сверка python и go М10/6–11, C32); оболочка с атрибутом on…= (запрет `page`
            ниже) не отдаётся: / и /index.html — 503 ConsoleRefusal {detail, error}, остальные двери работают (сверка python и go М10/6–11, C31)
  module:   /platform/console.js, /platform/console.css — один код у всех реализаций (байт в байт, ADR-0005, ADR-0019);
            файлы модуля — опубликованные данные спецификации Source/w2cplatform/console.js, console.css и
            console.html (страница платформы, shell выше; ADR-0080 доп. 16): реализация отдаёт их байт в байт и своего
            модуля не пишет; переписывание по контракту КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md — проверка полноты контракта,
            не способ реализации; файлы модуля поставляются вместе с консолью (в её сборке), а не читаются во время
            работы из каталога выгрузки спецификации (`$CAMMETA_SPECS` и подобных): без такого каталога консоль стартует и
            отдаёт те же байты (решение «Архитектора», сверка python и go М10/6–11, C37)
  version:  ?v=<n>; MODULE_VERSION = 1; v нет, повторён или не 1 — 404 {error: "no such version"}; console.version —
            целое, оболочка сверяет
  page:     CSP — минимум script-src 'self' 'sha256-…' (хэши встроенных скриптов страницы, от её текста при отдаче);
            object-src 'none'; base-uri 'none'; директивы сверх минимума — решает реализация, называет их;
            атрибутов on…= нет; экранирование h()
module:                                        # PlatformConsole.mount(root, opts) → console
  opts:     {sections: [units, access, journal] | [domain] (страница держателя — М11/8 Н1.8), subsystems: [<из /mounts>], lang: ru | en, poll_s: 5}
  never:    не называет подсистем (закрытый список запрещённых слов — тест границы, ADR-0001); не зовёт адресов вне своих;
            не трогает DOM оболочки; не держит сессии за оболочку; не показывает таблиц целиком
  calls:    закрытый список — урок P/07 Н1.4 (07-console-module.norms.md)
shell:                                         # подсистема
  may:      вызовы библиотеки (урок P/07 Н1.5); свои двери к держателю по door из where(); свои слова
  may_not:  хуки; чужой DOM; свой вход; байты через консоль (ADR-0015)
```

### Н1.2 `display`, `servers`, `console`

Форма — P/02.1 (закрытые ключи). Здесь — смысл каждого слова для модуля.

```yaml
display:
  unit, units, units_count:  слово единицы: одна, много, род. падеж множ. (для счётчиков); нет — «единица»
  section:                   подпись рейки раздела единиц
  general:                   заголовок первой вкладки; только раскладка
  fields:        {<поле>: <подпись>}            # поле строки, id, phase/worker/server/revision/observed_revision, поле status
  field_help:    {<поле>: <подсказка>}
  options:       {<имя>: {<значение>: <слово>}}                 # у поля с enum — значения из enum; у слова пульса из form.status[] — любые строки (подписи значений); иное — отказ (P/02.1 Н1.4)
  form:          [{title?, state?, placement?, fields?, note?, status?: [{field, since?, title?}]}]   # title необязателен
                 # блоки карточки по порядку; state — бейдж состояния; placement — воркер·сервер, причина из /where;
                 # status — поля, сказанные воркером, только чтение, с «с …» по since; поле вне блоков не показывается;
                 # без form — один блок со всеми полями
  events:        bool; false — у модуля нет вкладки журнала единицы; true и отсутствие — есть
  kinds:         {<вид события>: <слово>}        # слова видов подсистемы; виды платформы — словарь модуля
  keys:          {<id семьи ключей домена>: {title, about, absent?}}   # М11
  tree:
    group_by:    <поле> — чем группировать дерево; nested_by: <разделитель> — значение group_by с разделителем даёт вложенные группы;
                 columns: [{field, title, width}] — field: поле единицы или платформенное имя модуля (worker, server,
                 revision, observed_revision, phase, id; P/02.1 Н1.4); children: false — не вкладывать about-единицы
    group_title, group_hint, filter, no_group, contents_title, group_word, no_group_suffix, pick_note,
    new_root, new_sub, add_here, new_group_note, remove, not_in, add_to, no_others, new_group:   слова
  # display.actions — снят: модуль и оболочки его не читают (мёртвый ключ, ADR-0003)
servers:
  show:    [{table, by, title?, columns?}]       # строки таблицы table, у которых row[by] == сервер; заголовки — display.fields;
                                                 # секреты — маской; пусто — «Нет строк»; оболочка может накрыть addBlock(covers)
  status:  [{field, title?, of?}]                # field не называет ключ пульса, который читает платформа (перечень — P/02.1 Н1.2а, P/03.4 Н1.1); иначе refused:value при загрузке; значение пульса воркера по пути field — в строку сервера как есть (строка
                                                 # из heartbeat.strings, число, карта, список; слово на месте числа — garbled,
                                                 # пропуск); of — таблица, по которой страница сопоставляет ключи (ADR-0064)
console:
  running: <метрика спеки> → running_gauge: <sub>_<name>; workers_gauge: <sub>_workers_live
           # без console.running — running_gauge: null и metrics.running: null (Н2 «GET /spec»)
```

### Н1.3 Снимок — сторона читателя

Форма шарда (оболочка, `cluster`, `fields`, `publish`, `garbled`, `ceiling`) и писатель — [P/04 Н1.3а](../../04-controller/spec/04-controller.norms.md).
Здесь — сторона читателя, консоли (из М10/10 Н1.3):

```yaml
age:      читатель — консоль на /metrics; возраст шарда — время по её монотонным часам с последней смены его содержимого,
          увиденной ею (первый взгляд — 0; P/03.2 Н1.4 «возраст наблюдаемой версии»); ряд — максимум по шардам подсистемы;
          ошибка чтения не обновляет возраст и не означает свежий снимок; нет ни одного успешного наблюдения → -1 с диагностикой;
          шард не JSON или не объект шарда — пропущен и посчитан, /metrics — 200 с остальными (P/01.1 Н0 «Устойчивость
          выдачи»), не 503 (сверка python и go М10/6–11, T6)
metrics:  <sub>_snapshot_age_seconds (−1 — нет ни одного успешного наблюдения шарда: не публиковали или консоль не прочла); <sub>_snapshot_ahead_shards — шарды, чей ts больше стенных часов консоли + 60 с;
          <sub>_snapshot_garbled_shards — шарды подсистемы, которые последнее чтение консоли не прочло (сверка python и go М10/6–11, T6)
```

### Н1.8 `door.pass`

Из М10/11 Н1.8; грамматика `door.pass` в спеке — [P/02.1](../../02-installer/spec/02.1-installer.norms.md).

```yaml
spec:     door: {routes: […], pass: [<сегмент>…]}   # сегменты не повторяют routes, rows и where (P/02.1)
rule:     маршрут консоли, чей первый сегмент в pass, передаётся живому воркеру подсистемы с дверью (наименьшее имя):
          метод, путь, query, тело ≤ 1 МиБ, заголовки Authorization, Content-Type, Idempotency-Key, X-Operator;
          сторожевая консоли проверяет своё раньше; воркер проверяет учётные данные снова; ответ как есть (статус, Content-Type,
          тело ≤ 4 МиБ); клиент к воркеру — с сертификатом роли, если есть
codes:    503 «this console passes no route on to a worker» (клиента нет) | 503 «no worker of <sub> with a door is heard»
          | 400 тело не прочитано | 408 тело читается медленно | 413 тело больше предела (Н4) | 502 «<worker> did not answer»
```

**Живой воркер с дверью** (разбор ревью стадии A 6–7, № 25 — определение; свидетели сверяются, строка долга — в отчёте
переноса): воркер подсистемы, чей пульс `<sub>/heartbeats/<имя>` читается (исходы семьи пульса
[P/03.4](../../03-worker/spec/03.4-worker.norms.md)), имя ключа — по грамматике имени слота и `worker` пульса равен ему
(строка «пульс воркера в `/servers` и `/metrics`» Н2), версия пульса менялась в последние `LOST_AFTER` по часам консоли
([договор наблюдения](../../common/contracts/observation.md); первое наблюдение — свежее) — то есть `WorkerRow.state` —
`live` (Н2 «Выдачи»), — и поле пульса `url` — непустая строка (url двери, строка платформы P/03.4 Н1.1). Из таких воркеров
подсистемы — наименьшее имя слота (байты UTF-8); таких нет — 503 «no worker of `<sub>` with a door is heard». Слот и аренда
не проверяются: действительность операции проверяет воркер своими учётными данными и эпохой.

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## Н2 Двери

Двери консоли платформы — закрытый список; у подсистемы своих дверей на консоли нет, кроме таблиц и просьб из спеки и `door.pass` (Н1.8). Коды дверей единиц — [глава 6.1](06.1-console.norms.md), дверей управления (бывшие двери М10/4) — [глава 6.6](06.6-console.norms.md), событий и просьб — [глава 6.4](06.4-console.norms.md).

HTTP-контракт: [06-console.api.openapi.yaml](06-console.api.openapi.yaml).

**Разбор запроса консоли** — по P/01.1 Н2.1: query как `application/x-www-form-urlencoded` (`+`, `%XX`, пустые пары),
JSON тела по RFC 8259 (повтор имени поля, `NaN`/`Infinity`, BOM, не UTF-8, одиночный суррогат — отказ), путь байт в байт
без нормализации, HTTP по RFC 9112, ранний отказ. Отступления консоли, одни для всех её дверей (главы 6.1–6.6):
отказ разбора — 400 ConsoleRefusal `{detail, error}`, а не `Fault {kind}` P/01.1; нет маршрута — 404 NoRoute, метод — 405
(P/01.1 даёт 404 на оба); читаемый дверью параметр повторён — 400, кроме `v` модуля — 404 (Н1.1); тело `chunked` — 400
([глава 6.3](06.3-console.norms.md) Н1.3 `body`); глубина JSON тела — 64 ([глава 6.1](06.1-console.norms.md) Н1.4). Двери других глав ссылаются сюда и называют только свои отступления.

Общие коды: неизвестный путь — `404 NoRoute`; неверный метод — `405 {detail: method, error: method}` без заголовка `Allow`
(отступление консоли от RFC 9110 §15.5.6, как у обеих реализаций; сверка python и go М10/6–11); у страниц `/`, `/index.html`, `/<sub>/`,
`/<sub>/index.html` метод, кроме `GET`/`HEAD`, — 405, в том числе у смонтированной подсистемы (сверка python и go М10/6–11, C28); параметр query,
который дверь не читает, не разбирается: его порча (не UTF-8, битый `%XX`) — не отказ (сверка python и go М10/6–11); `/<rows>/<id>/<ещё>` — 404 `{detail: "a unit's path names one unit", error: "no such path"}`, кроме двери байтов `/<rows>/<id>/<blob_field>` [главы 6.1](06.1-console.norms.md) (иной метод, чем `PUT`, — 405); полоса занята — `503 busy`, `Retry-After: 1`; `/session`, `/healthz` — резервная полоса; `/metrics` — полоса монитора (у каждого маршрута одна полоса).

### Полные формы и границы Н2

Все JSON-ответы собственных дверей описаны компонентами OpenAPI. Каждый `GET` консоли — своих дверей и дверей других глав, которые консоль отдаёт (`/spec` — Н2 «GET /spec»; `/<rows>` — 6.1, одной единицы `GET` нет; `/policy`, `/drain`, `/unplaceable`, `/where/<id>` — 6.6; `/events` — 6.4; `/schema` — 6.6, `/<table>` — 6.1), — отвечает и на `HEAD`: тот же код и заголовки, без тела; каждый контракт, объявляющий такой URL, перечисляет `head`. HTML, JS, CSS и метрики — строки соответствующего media type, а не JSON. Успешный `/healthz` — ровно `{ok: true}`. `/mounts` — `{root, mounts: {имя подсистемы: SpecView}}`. `SpecView` — Н2 «GET /spec» (перенесён из М10/2 без ослабления).

`Servers` — `{policy, servers: {имя: ServerRow}, status?}`. `ServerRow` содержит обязательные `resource`, `resource_heard_at`, `resource_url`, `space`, `labels`, `labels_node`, `labels_source`, `draining`, `decommission`, `decommissioned`, `decommission_refusal`, `decommission_warning`, `decommissionable`, `lost`, `requires_resource`, `placeable`, `why`, `workers`. Неизвестные адрес/место/время/причина и отсутствующая просьба вывода представлены `null` по схеме. `lost` — массив `{unit, place?, worker?}`; `decommission` — `{at, by, gone?}`. Метки — массивы слов. `WorkerRow` требует `worker, load, capacity, labels, state, idle_by_policy, hung, name_conflict`; `name_conflict` — boolean. Необязательные детали и их типы закрыто перечислены в схеме. `status` выводит объявленные спецификацией значения JSON, не произвольные секретные поля.

`/resources` — объект по имени сервера с полными `ResourceRow`: обязательны `server, ts, url, schema, build, usage, usage_at, space, volumes, units, mirrors, short, state`; диагностические расширения перечислены в контракте. Это наблюдение пульсов ресурса, а не удостоверение доступности каждого объекта. `/where/<table>/<place>?unit=<id>` возвращает `{worker, place, server, door?}` либо 404 `{unreachable}` с одноимённым значением заголовка `X-Unreachable`. Неизвестная таблица — 404 до проверки `unit`, известная без `unit` — 400.

Общие отказы консоли — формы `ConsoleRefusal` (Н2 «GET /spec», перенесены из М10/2): `{detail, error}` с установленными значениями `error`; 503 включает `denied` при потере доверия и `busy` с `Retry-After: 1` при заполнении полосы. 429 имеет `Retry-After`. Специальные тела: `NoVersion` — `{error: "no such version"}`; `MountedPage` — `{detail, error: "is mounted"}`; `NotPlaced` — `{reason}`. 400/408/413 описывают отказ чтения; тело ограничено по реально принятым байтам, короткое даёт 400. `/session` GET анонимному даёт 200 с состоянием; плохая попытка POST — 401, открытый режим — 400, неверный аварийный вход — 403. DELETE снимает обе куки (процедура и отказы `/session` — [глава 6.3](06.3-console.norms.md)). Полоса, framing, доверие/петля, личность, Origin по куке, гранты и чтение проверяются в порядке Н3; отказ не имеет побочных записей двери.

Двери единиц, размещения, событий, таблиц и схемы принадлежат главам 6.1, 6.6, 6.4 (и [P/05](../../05-resource/spec/05-resource.norms.md) для `/events` ресурса), 6.1, 6.6. `/domain/*` и открытые `/api/*` — [М11/8](../../../М11_Domain/spec/08-doors-between-clusters.norms.md) (пересылка, Н1.2–Н1.5, Н1.9) и [М11/10](../../../М11_Domain/spec/10-holder-transfer-and-keepers.norms.md) (двери переноса); успешное тело пересылки принадлежит ему (глава позднего слоя 6.7 отложена до переноса уроков 8–10, разбор № 27). Они перечислены как зависимости, без фиктивной схемы «любой объект». Собственные маршруты этой главы `/spec`, `/servers`, `/unplaceable`, обе формы `/where` и `/metrics` также явно объявлены с префиксом `/<sub>`; префиксы делегированных дверей — у их владельцев; общие `/session`, `/mounts`, `/platform` не монтируются. Отсутствующий `v` или иная строка, включая нечисловую, — 404 `NoVersion`.

Короткие пути единиц, таблиц, blob-полей, /policy, /spec, /servers, /unplaceable,
/where и /metrics выбирают CONSOLE_ROOT; форма /{sub}/… явно выбирает загруженную
подсистему, включая root. В OpenAPI владельца полный URL может быть задан парой
стандартных servers + paths: origin консоли без завершающего / либо origin/{sub},
затем путь операции. Это исполнимое описание URL, а не пояснение x-mounting.
Общие /drain, /schema, /session, /mounts, /healthz, /resources, /platform/*,
/servers/{server}/labels и /servers/{server}/decommission не получают такой префикс.
События /events и отметки /marks следуют формам владельца (глава 6.4). Просьбы и учёт человека
всегда именуют подсистему: /{sub}/requests и /{sub}/asked/{sha16}, включая CONSOLE_ROOT; маршрут /{sub}/asked/…
есть только у спеки с requests.per_person, сегмент {sha16} — ровно 16 строчных hex, иначе 404 NoRoute (сверка python и go М10/6–11, C27);
короткие /requests и /asked/{sha16} вне профиля, неизвестный маршрут —404 по Н2/Н4.

Область монтирования допущена загрузчиком P/02.1: имя подсистемы не из 21 зарезервированных слов, а ни одно имя подсистемы не пересекает unit.rows/tables каталога, включая собственные. Недопущенный каталог не запускает консоль; приоритета, скрывающего одну из двух обещанных дверей, нет.

### GET /spec

Перенесено из М10/2 Н2 через М10/9 (стадия B, без изменения поведения; разбор ревью стадии A 6–7, № 12): подлинник двери
консоли `GET /spec` и схемы `SpecView` — здесь и в [контракте урока](06-console.api.openapi.yaml); у урока P/02 своего OpenAPI нет.

HTTP-контракт — [`06-console.api.openapi.yaml`](06-console.api.openapi.yaml) (OpenAPI 3.1). Он задаёт маршрут `GET /spec` (и `HEAD` — тот же код и заголовки без тела, Н2), схему `SpecView` и коды ответов. Процедура загрузки ([P/02.1](../../02-installer/spec/02.1-installer.norms.md) Н2) не является HTTP-дверью и в этот файл не входит.

Поля `unit.fields` в ответе — в порядке объявления спеки; в том же порядке дверь единиц проверяет поля ([глава 6.1](06.1-console.norms.md) Н3
«создать», шаг 4; сверка python и go М10/3–5, U10).

Раздел `domain` спеки входит в ответ только проекцией, которую читает модуль консоли (Н1.1 `module`):
`domain: {view, edit, shared, keys}` — `view`, `edit` как написаны, `shared` — имена его полей (у элемента-отображения —
`name`), `keys` — элементы `{id, keys, prefix?}` как написаны; несказанный список — `[]`; без раздела `domain` ключа нет.
Прочие ключи раздела (`ref`, `books`, `names`, `tokens`, `kept`, `tables`, `reports`, `witness`) — работа держателя
домена (М11), в `SpecView` их нет.

Разбор запроса `GET /spec` — Н2 «Разбор запроса консоли» (P/01.1 Н2.1 с отступлениями консоли); своих отступлений нет.

Ревизии спеки в ответе нет: консоль, прочитавшая другую ревизию, уже не работает ([P/02.3](../../02-installer/spec/02.3-installer.norms.md) Н3 «Смена спеки»).

Успех имеет форму `SpecView`. Имя следует P/02.1 Н1.2, а каждый описатель fields — P/02.1 Н1.3.
Раздел `console` необязателен: без `console.running` поля `running_gauge` и `metrics.running`
равны null (имени метрики нет), а `workers_gauge` присутствует всегда. `metrics.prefix` — имя подсистемы, в котором `-`
заменён на `_` (имя ряда — `<prefix>_<метрика>`, Н3 «/metrics — текст»: `-` в имени ряда недопустим); у `testsub` —
`testsub`, у `cam-x` — `cam_x`. Две подсистемы каталога с одним prefix (`a-b` и `a_b`) — `refused:catalogue` (P/02.1 Н3 «загрузить_каталог»).
В описателе всегда присутствуют name, type, default и required. Отсутствующий default передаётся
как null (у json это также допустимое явное значение); required по умолчанию false. Inherit отсутствует,
если не задан; при заданном inherit поле default равно null. Merge выдаётся только вместе с inherit.
Enum возможен только у string/bool и содержит значения соответствующего типа; blob всегда имеет
required:false, default:null, без inherit/enum. Остальные default/inherit имеют тип поля
(list — массив строк); null у default означает отсутствие и допускается для любого типа.
Наличие default в enum и ограничения между именами проверяются по загруженной спеке отдельно:
обычная JSON Schema не сравнивает значение одного свойства с массивом в другом.
Общие отказы консоли — JSON-объект ровно с `detail` и `error`
(оба строки), без диагностических полей загрузчика и без `kind` хранилища. Для неизвестного маршрута
это `404 {detail: "no such route", error: "no such path"}`, для неверного метода —
`405 {detail: "method", error: "method"}`. Остальные общие коды, условия и заголовки —
[Н4](#н4-отказы); они явно перечислены в контракте рядом с `200`.
Это отказы транспорта и сторожевой, а не попытка загрузить спеку запросом `GET /spec`.
У открытых путей действуют исключения сторожевой ([глава 6.3](06.3-console.norms.md) Н1.3); список кодов не делает их закрытыми.

### `door.pass`

Из М10/11 Н2. `door.pass` проверяет framing и фактические байты запроса до отправки, ограничивает чтение ответа 4 МиБ и не следует перенаправлению. Для этого профиля ответ буферизуется в пределах лимита до отправки заголовков клиенту: превышение/обрыв/таймаут — 502 `{detail, error}`; отсутствие клиента/живой двери — 503, ошибка тела запроса — 400/408/413 по Н4. Локальные отказы имеют форму ConsoleRefusal (Н2), успех/отказ воркера передаётся как получен (статус, Content-Type, тело), без новой схемы подсистемы в этом уроке. Не отправлять повторно автоматически; данные оператора не пересылаются по redirect. «Живой воркер с дверью» — Н1.8.

## Н3 Проход

### запрос → ответ (консоль)

```
1. полоса: резервная / монитора / общая; занята → 503 busy
2. X-User стереть; framing и предел по заголовку; chunked → 400
3. определить доверие gate — чтением на каждом запросе, без кэша: хранилище не ответило или доверие неизвестно →
   503 {error: denied} до разбора пути и тела (раньше — только шаги 1–2: полоса и рамка; сверка python и go М10/3–5, U19); домена нет и не петля → 403 ДЛЯ ВСЕХ путей,
   включая открытые и /session*; ни одна такая дверь ещё не исполнена
4. /session* → процедура главы 6.3 Н1.3: после установления личности, если запрос действует по куке,
   чужой Origin → 403 до изменения сессии/кук; иначе ответ процедуры
5. путь → дверь и что она требует (глава 6.3 Н1.3 need); пути нет → 404; путь сравнивается байт в байт (P/01.1 Н2.1):
   `/counters/`, `/where/` — не маршруты; query — по P/01.1 Н2.1, читаемый дверью параметр повторён → 400 {detail, error}
   (кроме `v` модуля — 404, Н1.1)
6. кто звонит, если дверь требует личность (глава 6.3 Н1.3 identity) → иначе 401
7. личность выбрана по куке и Origin чужой → 403; затем единицы из пути и требуемая возможность → грант или 403 + журнал
8. прочитать тело с фактическим пределом и таймаутом; если единица определяется телом, проверить её здесь;
   unit_of / reach / names добавляют проверки. Ни одного изменения до завершения всех проверок
9. дверь: единицы (глава 6.1), управление (глава 6.6), события и просьбы (глава 6.4), /spec, /mounts, /servers, /where, /metrics
   X-User = доказанное имя для журнала
```

**Гонки.** Два запроса одной сессии разом — независимы; запись и чтение одной строки — `cas` (глава 6.1); смена спеки — консоль останавливается с кодом 0 и перезапускается (P/02.3 Н3 «Смена спеки»), `SpecView` ревизии не несёт; модуль видит обрыв и перезагружает страницу.

### /servers — картина для человека

```
воркеры: пульсы семьи (любого возраста) → state live, если менялся в последние LOST_AFTER (≤ 45 с) по часам консоли
         (договор наблюдения; правка поведения: разбор ревью стадии A 6–7, № 1 — было «< 45 с»), иначе stale;
         слот → released, slot_taking, slot_until (null — нечитаем), slot_garbled; удержания → holds;
         судьба контроллера (отчёт прохода) → hung, hung_since, hung_why, presence_unknown; соперники → name_conflict;
         servers.status → status {поле: значение как есть}
серверы: ресурс (пульс + дверь) → resource по `resource_state` договора наблюдения, resource_heard_at, space;
         platform/servers/<s> → labels, labels_source console | node | unknown; дренаж; вывод и его отказ; достижимость
         (placeable, why — по меткам и requires); lost — единицы ушедшего
неизвестный сервер — "?": и в /servers, и в `unreachable` /where/<table>/<place> — `place@?` (сверка python и go М10/6–11, C14, C25); реестра машин нет
```

**Граница наблюдения.** Строки, пульсы и отчёт контроллера могут быть прочитаны в разные моменты. Ответ не является транзакционным снимком и не разрешает запись или остановку процесса. Возраст — от изменения, увиденного консолью, по её монотонным часам; первое наблюдение начинает возраст с нуля. Сбой обязательного чтения — 503; недоступный отдельный ресурс — `unknown`/`unreachable`, не пустые воркеры или доказательство отсутствия. Необязательная диагностика может отсутствовать, но обязательные поля ответа сохраняются.

### `/where/<id>`

```
прочитать intent → placement нужной единицы → intent по правилу чтения договора наблюдения; версия intent изменилась → повторить;
обязательное чтение не подтверждено → 503. При неизменном active и id в members взять target/reason intent,
иначе worker/reason строки placement; отсутствие placement не отменяет target активного intent.
эффективный worker "" или нет → 404 {reason: why единицы из поля unplaceable последнего отчёта прохода, без неё —
  «not placed: no worker holds it»} (глава 6.6 Н2.2 — владелец двери; изменено сверкой python и go 2026-10-18)
server — глава 6.6 Н2.2 (пульс воркера, иначе строка слота, иначе null); url двери (door.routes спеки) → door: {url, token (door1.<kid>…, Ed25519 ключом door/signer,
TTL 120 с, в токене user, unit, holder, routes только чтения), expires, routes}; token выдаётся по view на единицу,
каждая выдача — журнал door.issued; directory — где единицу видят (5 с кэш), scans
```

Токен двери — байты (журнал cammeta-go, урок 9 № 3):

```yaml
token:      door1.<kid>.<claims>.<sig> — ровно четыре части через «.», ASCII
  kid:      имя ключа подписи, 1–32 знака [a-z0-9-]; по нему проверяющий берёт открытый ключ из door/keys
  claims:   base64url без «=» байтов JCS (RFC 8785) объекта {user, unit, holder, routes, expires}: user — доказанное имя
            (глава 6.3 Н1.3), unit — "<sub>/<id>", holder — экземпляр держателя из его пульса (instance, P/03.4 Н1.1), routes — массив
            путей двери только чтения (door.routes спеки), expires — стенные секунды выдачи + 120
  sig:      base64url без «=» 64 байт подписи Ed25519 (RFC 8032) над байтами ASCII «door1.<kid>.<claims>»
door/signer: {kid, seed_secret} — seed_secret — 32 байта зерна Ed25519 в 64 строчных hex (секрет по суффиксу, конверт
            кольца — договор запечатывания, глава 6.2); писатель — консоль при первой выдаче, если строки нет (создание-однажды)
door/keys:  {<kid>: <64 строчных hex открытого ключа>} — несекретная строка; консоль добавляет свой kid при создании
            door/signer; проверяющий — P/03.4 Н3 «токен двери у держателя» (стадия B)
```

**Гонки.** Двойное чтение intent отсеивает смену принятого решения; при стабильном active целевой воркер берётся из него, даже до записи placement. Эффективное размещение и пульс читаются отдельно. Ответ называет наблюдённого держателя; переезд может завершиться до использования двери. Нельзя обещать один момент для всех полей. Нет достоверной двери — поле `door` отсутствует; null в HTTP-ответе не допускается; ошибка чтения назначения — 503, а не 404. Действительность операции повторно проверяет держатель по эпохе/аренде. Формы `Where`, `NotPlaced`, `Door` — точные формы владельца (глава 6.6 Н2.2).

### `/where/<table>/<place>?unit=<id>`

После общих framing/доверия/личности: таблица не объявлена или не таблица мест — 404
текстовым отказом; это проверяется до обязательности/формы unit. Затем unit обязателен,
имеет форму id единицы выбранной подсистемы (иначе 400); нужен view на эту единицу.
После гранта прочитать строку места, удержание `<sub>/holds/<place>` и пульс держателя
по P/03.4 Н1.1 и P/03.2 Н1.3 (логическое имя worker = hold.by, не экземпляр hold.holder). Неподтверждённое обязательное чтение — 503; достоверно нет действующего
удержания — 404 `{unreachable: place@server}` с X-Unreachable того же значения.
Есть удержание — `{worker, place, server}`. Достоверная дверь держателя с объявленными
door.routes, доступным подписантом и подтверждённым адресатом unit добавляет door:
тот же Ed25519-токен на 120 с, пользователь/unit/holder/читающие routes и door.issued,
что в проходе `/where/<id>`. Нельзя выдать токен иному или неподтверждённому держателю;
когда дверь подтвердить нельзя, поле отсутствует, не null, местоположение остаётся ответом.

**Гонки.** Удержание/пульс не общий снимок; ответ не продлевает аренду. Изменившийся
держатель после ответа отсекается проверкой эпохи/аренды у двери. Ошибка чтения не
объявляется отсутствием места, отсутствие токена не объявляется отсутствием удержания.

Сверка python и go М10/6–11 — проверяются чтением, с причиной:
- рамка раньше доверия при закрытом или неответившем хранилище (C4): стенд не останавливает хранилище посреди сценария и
  домена не имеет;
- `placeable` (C17), `decommissionable` (C18), поля слота (C19), знак skew (C23), `place@?` (C25): сервер с воркером
  на втором сервере и слот заданной формы стенд сц. 01–12 не собирает;
- полоса занята, 503 `busy` (C29): параллельных запросов TSV не шлёт;
- оболочка с `</script >` и `src = `, с `on…=`, с CRLF (C30, C31, C32): оболочка стенда — `console.html` платформы, своей
  оболочки в спеках стенда нет;
- журнал правки с `user` и `addr` (C35): журнал читается дверью `/events`, ресурса индекса у стенда до сц. 10 нет;
- пустой `CONSOLE_ROOT` (C36), поставка модуля без каталога выгрузки (C37): запуск консоли — команда «Стенда», её
  окружение сценарий не меняет; предмет — тест запуска реализации;
- ряды `w2c_requests_*` у спеки без `requests` (C39) — сц. 02 шаги 6–7: у `testsub` ряд есть, у `probe-x` (без `requests`) — нет (`<код> !contains` словаря «Стенда»).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как задаётся `CONSOLE_ROOT`**; пустой или не из каталога — норма Н1.1 (код 2); источник оболочки — норма Н1.1 (поле `shell` строки спеки);
2. **пределы**: тело (≥ 1 MiB), блоб, сессия (16 KiB), полосы и их размеры, таймауты, общий предел входа (429, Н4);
3. **кэши** `/where` (directory 5 с), эпох (3 с), `/domain` пересылки;
4. **дополнительные ряды `/metrics`** сверх Н3;
5. **пересылка `/domain/*`** держателю: заголовки, один переход (М11/8; глава позднего слоя 6.7 отложена, разбор № 27);
6. **CSP** сверх минимума Н1.1.

Отладочная личность и предел аварийного входа (п. 4 источника) — [глава 6.3](06.3-console.norms.md) «Решает реализация».
