**Replay memory**. `PUT /policy`, `POST` and `DELETE /drain`, `PUT` and `DELETE /servers/{server}/labels`, `POST` and `DELETE /servers/{server}/decommission`, `PUT /schema` read the optional `Idempotency-Key` by the rule of [chapter 6.1](06.1-console.norms.md) N3 «replay memory»: the key is `(user, method, path, key)` (user, method, path, key), the order is «parsing of the request → claim → pass of the door → write under the claim guard → answer into the claim», an answer `< 500` is remembered, the term is as at `POST`. ### drain — reading the state

<!-- req: P/06.6-R013 -->
```
for each manifest: the workers of the server (heartbeats; the heartbeat does not read — server of the slot, N1.2 server_of),
for each such worker w: ids(w) = set(assignment(w)) ∪ set(heartbeat(w).status[].id),
```
