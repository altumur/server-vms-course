# P/06.6 — Двери управления: нормы

Канон главы 6.6 урока P/06 «Консоль кластера» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../06-console.md),
[контракт](06-console.api.openapi.yaml), [инструкция](06-console.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/6/README.md). Двери, через которые оператор говорит с контроллером и платформой: политика,
дренаж, метки серверов, вывод сервера, `/unplaceable`, `/where/{id}`, строка схемы и её подъём, проверка схемы при старте
консоли.

Глава перенесена из М10/4 (стадия B, ADR-0083
доп. (1): без изменения поведения): строки консоли Н1.1, двери Н2 и их отказы Н4, свидетельства Н5, п. 9 «Решает
реализация», приёмка М10/04; из М10/10 — схема
(Н1.1, здесь Н1.1а), дренаж (Н1.2), двери `/schema` и `/drain` (Н2, здесь Н2.3), проходы «поднять_схему», «старт …
— проверка схемы» (общий блок и сторона консоли), «дренаж — чтение состояния», их строки Н4 и Н5, п. 5 «Решает
реализация», сц. 01, 02, 09, 12 приёмки М10/10; из приёмки М10/11 — сц. 03; из
[P/04](../../04-controller/spec/04-controller.norms.md) Н3 «вывести_сервер» — сторона консоли (разбор ревью стадии A 6–7,
№ 2). Свежесть пульса, состояние ресурса и чтение решения intent → placement → intent — общий
[договор наблюдения](../../common/contracts/observation.md); строки контроллера, которые двери читают, — P/04 Н1.1, Н1.2,
Н1.5. Номера подразделов — прежние номера М10/4; подраздел М10/10 с номером, который есть в М10/4, — с буквой «а»
(Н1.1а), двери М10/10 — Н2.3. «Глава 6.K» — глава этого урока; «P/0N.K» — глава перенесённого урока. Id норм —
`P/06.6-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Поля времени строк главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): `platform/drain` — `at`; `platform/decommission/<сервер>` — `at`; `platform/schema` — `at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `<sub>/policy`, `platform/servers/<сервер>`, `platform/drain`, `platform/decommission/<сервер>`, `platform/schema`;
- пишет: `platform/doors/<сервер>` (delete), `<корень событий>/audit/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `platform/spec/<sub>`, `<sub>/heartbeats/<имя>`, `<sub>/slots/<имя>`, `platform/resources/<server>/heartbeat`, `platform/doors/<сервер>`, `<sub>/placement/<id>`, `<sub>/workers/<имя>`, `<sub>/decommissioned/<сервер>`, `<sub>/controller/placement_intent`, `<sub>/controller/pass`, `<sub>/<spec:unit.rows>/<id>`.

Журнал `audit` главы — виды `schema.raised`, `policy.changed`, `drain.*`, `server.*` (разбор ревью стадии B 6–7, № 41).

Строки «владеет» пишет консоль дверями Н2 и подъёмом схемы (Н3 «поднять_схему»); контроллер читает их по
[P/04 Н1.1](../../04-controller/spec/04-controller.norms.md), прочие процессы — по каталогу. Строку двери
`platform/doors/<сервер>` (владелец — ресурс, [P/05 Н1.4](../../05-resource/spec/05-resource.norms.md) `door_row`) консоль
удаляет у выведенного сервера (Н3 «вывести_сервер»). Строки контроллера (`placement`, `workers`, `placement_intent`, отчёт
прохода) двери читают по [договору наблюдения](../../common/contracts/observation.md) «Чтение решения» и P/04 Н1.2; пульсы
и слоты — для известности сервера (Н2.1), дренажа (Н1.2) и `/schema` (Н2.3).

### Н1.1 Строки консоли

Строки, которые пишет консоль (двери Н2); контроллер читает их по P/04 Н1.1.

```yaml
<sub>/policy:                             # писатель — консоль; читает контроллер
  servers:   shared | distinct            # иное значение или ключ при чтении — умолчание спеки; при записи — отказ
platform/servers/<сервер>:                # писатель — консоль (ADR-0026)
  labels:    <метки через запятую>        # "" — ни одной; строка побеждает метки узла
platform/drain:                           # писатель — консоль; одна строка на кластер
  server: <сервер>; at: <момент>
platform/decommission/<сервер>:           # писатель — консоль
  by: <кто>; at: <момент>; why: <слова>; gone: "true"?   # gone — подтверждение «сервера нет», когда ресурс никогда не слышали
```

Строка двери сервера `platform/doors/<сервер>` (писатель — ресурс сервера, ADR-0045) — форма
[P/05 Н1.4](../../05-resource/spec/05-resource.norms.md) `door_row` (семья `doors`); консоль читает её для состояния
ресурса и известности сервера (Н2.1) и удаляет у выведенного сервера (Н3 «вывести_сервер»).

### Н1.1а Схема

```yaml
platform/schema:  {version: <целое ≥ 1>, at: <момент>}     # писатель — консоль (admin); нет строки = схема сборки (свежая установка)
SCHEMA:   число, которое понимает сборка; поле добавить — без нового номера; смысл поля сменить — новый номер
BUILD:    слово сборки для человека (env BUILD, умолчание dev); машина читает SCHEMA
heartbeat: каждый пульс воркера и ресурса несёт schema и build (P/03.4 Н1.1, P/05 Н1.4); schema — целое JSON без дробной
          части и экспоненты (форма int главы 6.1 Н1.2: «Значение `int` на входе двери»), ≥ 1; `1.0`, `1e0`, `-1`, строка, null — схема процесса неизвестна (null
          в `processes`, Н2.3) (сверка python и go М10/6–11, T3); build — строка; не строка — `""` (сверка python и go М10/6–11, T27)
check:    при старте контроллера, воркера, ресурса и консоли: version > SCHEMA → не стартовать; строка не число → не стартовать;
          сторона консоли — Н3 «старт консоли — проверка схемы»; сторона воркера (при старте и после продления слота) —
          P/03.2 Н3 «проверка схемы воркером»; сторона контроллера — P/04 Н3 «старт контроллера — проверка схемы»;
          сторона ресурса — P/05 Н3 «старт ресурса — проверка схемы»
raise:    только оператор, PUT /schema?version=N в окне обслуживания Н3; назад — отказ; своя сборка и все живые процессы понимают ≥ N
```

Стороны проверки других процессов — [P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3 «проверка схемы воркером»,
[P/04](../../04-controller/spec/04-controller.norms.md) Н3 «старт контроллера — проверка схемы»,
[P/05](../../05-resource/spec/05-resource.norms.md) Н3 «старт ресурса — проверка схемы».

### Н1.2 Дренаж

```yaml
platform/drain:  {server: <сервер> | "", at}          # один сервер за раз; писатель — консоль (admin); читает контроллер (P/04 Н1.1)
state:
  draining:        <сервер> | ""
  safe:            все подсистемы safe
  would_strand:    {<sub>: [id…]}                      # проба без моделирования размещения: все единицы воркеров этого сервера
                                                         # и все неразмещённые (Н2.2)
  subsystems:      {<sub>: {draining, subsystem, workers, units, pending_writes, pending_unsaid?, would_strand, safe}}
  safe(sub):       units == 0 ∧ pending_writes == 0 ∧ pending_unsaid пуст
  pending_writes:  Σ по воркерам сервера поля пульса pending_writes — целое JSON без дробной части и экспоненты,
                   0 ≤ x ≤ 2^53 − 1 (форма int главы 6.1 Н1.2: «Значение `int` на входе двери»): базовый воркер платформы (P/03.4 Н1.1) пишет
                   в пульс 0 сам, если подсистема не сказала своё (подсистема с буфером на диске говорит своё число);
                   поля нет / слово / дробь, в том числе `0.0`, `1000.0`, `-0.0`, `1e3` / больше 2^53 − 1 / нечитаемый или
                   устаревший пульс → pending_unsaid (дренаж не safe) (сверка python и go М10/6–11, T1, T3, T4)
  server_of:       воркер сервера — по полю server читаемого пульса; пульс не читается — по server его слота
                   `<sub>/slots/<имя>` (P/03.2 Н1.4): такой воркер — в pending_unsaid, единицы его назначения
                   `<sub>/workers/<имя>` — в units и would_strand (сверка python и go М10/6–11, T2)
journal:  drain.started {server, user}; drain.ended {server} — других видов журнала дренажа нет (`drain.cleared` нет)
          (сверка python и go М10/6–11, T22)
          # журналы консоли этой главы (schema.raised, drain.*) — дерево audit/console (договор журнала событий `journal`,
          # роль console); журналы дверей единиц и таблиц (<t>.written/<t>.deleted, unit.changed) — глава 6.1
```

Устаревший пульс — не свежий по [договору наблюдения](../../common/contracts/observation.md) «Свежесть»: версия не
менялась в последние LOST_AFTER (разбор ревью стадии A 6–7, № 2: свежесть — в одном месте).

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## Н2 Двери

Двери консоли, через которые оператор говорит с контроллером и платформой. HTTP-формы и закрытые наборы кодов —
[контракт урока](06-console.api.openapi.yaml); у каждого `GET` есть `HEAD` — тот же код и заголовки без тела
([глава 6.5](06.5-console.norms.md) Н2). Общие отказы консоли — глава 6.5 Н4; это `{detail, error}`, а не Fault
хранилища. Состояние, права и выбранный вид id проверяются после статической формы. Новых дверей переезда и
перебалансировки нет (ADR-0047).

### Н2.1 Входы

Разбор запроса — [глава 6.5](06.5-console.norms.md) Н2 «Разбор запроса консоли» (P/01.1 Н2.1 с отступлениями консоли);
своих отступлений у дверей контроллера нет (повтор `server` у `POST /drain` — 400 по общему правилу).

`/policy`, `/unplaceable` и `/where/{id}` относятся к выбранной подсистеме; у корневой они
без префикса, у смонтированной — с `/<sub>`. `/drain` и `/servers/{server}/…` находятся
у корня консоли и охватывают все её спеки (ADR-0026). Префикс подсистемы не создаёт копии
кластерных строк. Права — роль `console` [P/02.5 Н1.4](../../02-installer/spec/02.5-installer.norms.md); порядок сторожевой — [глава 6.3](06.3-console.norms.md) Н1.3 `identity` и `need`. Стандартные servers у этих трёх path item
задают оба полных URL; общие /drain и /servers/{server}/… не наследуют префикс.
Имя sub явно выбирает загруженную спеку, включая CONSOLE_ROOT (глава 6.5 Н2).

| Операция | Вход | Успех |
|---|---|---|
| GET /policy | без тела | 200 Policy: `{servers: shared \| distinct}`, эффективное значение |
| PUT /policy | обязательный объект только с `servers` | 200 Policy после записи; журнал policy.changed |
| GET /drain | без тела | 200 DrainState, снимок состояния по Н1.2 |
| POST /drain | обязательный непустой query `server`, без тела; нет `server`, он пуст, повторён или не по грамматике имени сервера — 400 `{detail, error}` по Н4 | 200 `{draining: server}`; повтор того же сервера идемпотентен, иной при активном дренаже — 409 |
| DELETE /drain | без тела | 200 `{draining: ""}`, в том числе если уже снят |
| GET /servers/{server}/labels | необязательный query `labels`: метки через запятую, пустая строка — пустой набор; пустой элемент (`a,,b`) — 400; повтор метки (`a,a`) — 400 (решение «Архитектора» 2026-10-20, разбор ревью стадии B 6–7) | 200 `{would_move: [<sub>/<id>…]}` — только единицы подсистем с `constraint: labels-subset`; с query — проба этого набора без записи, без query — проба текущих эффективных меток |
| PUT /servers/{server}/labels | обязательный объект только с `labels`: массив меток без повторов (повтор — 400; разбор ревью стадии B 6–7, № 40) | 200 `{will_move: [<sub>/<id>…]}` после записи строки; это прогноз следующего прохода, не подтверждение переезда |
| DELETE /servers/{server}/labels | без тела | 200 `{}` после снятия строки; снова действуют метки узла |
| POST /servers/{server}/decommission | необязательное тело; отсутствие равно `{}`; разрешены только `why` (строка) и `gone` (булево) | 202 `{}` либо `{warning: <непустая строка>}` при подтверждённом выводе никогда не слышанного ресурса |
| DELETE /servers/{server}/decommission | без тела | 200 `{}` после снятия запроса; отметку снимает следующий проход контроллера |
| GET /unplaceable | без тела | 200 массив Unplaceable |
| GET /where/{id} | id по главе 6.1, вид задаёт спека; пустой id (`/where/`) — не маршрут, 404 | 200 Where; не размещена — 404 `{reason: <непустая строка>}` |

Во всех строках таблицы JSON-объекты закрыты: неуказанных полей нет. Успех `{}` содержит JSON-объект,
а не пустое HTTP-тело. Метка — по [азбуке меток](../../common/contracts/labels.md) (1–64 ASCII-знака: первая буква/цифра,
далее буква/цифра, `_`, `.`, `:`, `-`). Список query разбирается по запятым, без пустых элементов,
кроме целиком пустой строки; сервер в path/query — имя сервера: имя хоста RFC 1123 — метки через «.», метка 1–63
знака `[A-Za-z0-9-]`, не начинается и не кончается «-», всего не больше 253 байт (`..`, `.`, пробел, `/` — не имя);
иное — 400 до проверки существования (сверка python и go 2026-10-18). В `will_move` и
`would_move` попадают только ссылки, доступные вызывающему по `view`; список может быть пуст.
Прогноз меток `would_move` / `will_move` — множество единиц, которые с сервера s **уйдут**, а не придут на него (разбор
ревью стадии B 6–7, № 33): единица подсистемы с `constraint: labels-subset`, у которой воркер эффективного размещения
([договор наблюдения](../../common/contracts/observation.md) «Чтение решения: intent → placement → intent») свеж по тому
же договору и его пульс называет `server: s`, а метки единицы (её поле `labels`, [P/04 Н1.3](../../04-controller/spec/04-controller.norms.md)
`constraint`) — не подмножество проверяемого набора: query `labels` или тело `PUT`; у `GET` без query — текущие
эффективные метки сервера (строка `platform/servers/<s>`, иначе метки узла — P/04 Н1.3). Неразмещённые единицы, единицы
других серверов и единицы, которым набор подошёл бы на этом сервере, в прогноз не входят. Ссылки `<sub>/<id>` — без
повторов, по возрастанию байтов UTF-8 строки ссылки.
Имя подсистемы в ссылке `<sub>/<id>`, ключах карт drain и поле `subsystem` следует P/02.1 Н1.2,
включая весь закрытый список зарезервированных имён; грамматика самого id — [глава 6.1](06.1-console.norms.md) Н1.3.
Существование сервера определяется всеми подсистемами и ресурсами консоли: сервер известен, если есть хотя бы
одно свидетельство — пульс ресурса этого сервера, строка `platform/doors/<сервер>`, поле `server` пульса воркера
или слота любой подсистемы, а для операций меток ещё строка `platform/servers/<сервер>`. Для всех трёх операций
меток и обоих методов вывода неизвестный сервер — 404. Ошибочная форма тела/меток — 400 до этой проверки.

### Н2.2 Полные тела чтения

- **Unplaceable:** `{id, labels, workers_live, why?}`. `id` — строка; `labels` — массив меток;
  `workers_live` — целое ≥ 0; `why`, если есть, — непустая причина из поля `unplaceable` последнего
  отчёта прохода ([P/04 Н1.2](../../04-controller/spec/04-controller.norms.md)): решает контроллер, консоль читает. Это единицы без места,
  в том числе при пустом пуле, и единицы, для которых ограничения не дают кандидата.
- **Where:** `{worker, server, reason, directory, scans, door?}` по [главе 6.5](06.5-console.norms.md) Н3 «`/where/<id>`». `worker` — непустое
  имя назначения по грамматике слота P/03.2 Н1.4; `server` — из пульса воркера, иначе из поля `server` его строки слота,
  иначе null (сверка python и go 2026-10-18); `reason` —
  непустая причина решения; `directory` — имя из последнего скана назначений либо null;
  `scans` — число завершённых сканов ≥ 0 с запуска консоли. Кэш directory может отставать от решения;
  частота скана назначений — «Решает реализация» п. 1. У неразмещённой единицы 404 `{reason}` берёт причину
  из поля `unplaceable` отчёта прохода, а без неё — `not placed: no worker holds it`.
  Необязательная `door` содержит `url`, `token` (непустые строки), `expires` (число стенных секунд)
  и `routes` (массив непустых строк); условия выдачи (`view` на единицу, журнал `door.issued`) и срок (TTL 120 с) — глава 6.5 Н3 «`/where/<id>`», а не право, следующее из схемы.
- **DrainState:** `{draining, safe, would_strand, subsystems}`. `draining` — имя или `""`;
  `safe` — булево; `would_strand` — карта подсистема → массив id.
  Значение `subsystems[sub]`: `{draining, subsystem, workers, units, pending_writes, would_strand, safe, pending_unsaid?}`.
  `draining` — то же имя или `""`, `subsystem` равно ключу карты; `workers`, `units`,
  `pending_writes` — целые счётчики ≥ 0; `would_strand` — массив id; `pending_unsaid`, если есть,
  — массив имён воркеров по P/03.2 Н1.4 без читаемого счётчика. `safe` считается по Н1.2, не по пустоте
  `would_strand` — без моделирования размещения: все единицы воркеров этого сервера и все неразмещённые единицы
  подсистемы. Единицы воркера — объединение его назначения (`<sub>/workers/<имя>`) и `status[].id` его пульса: пустой
  `status` при назначенных единицах не делает сервер пустым (сверка python и go 2026-10-18); `units` — их число. Без активного дренажа серверный набор пуст, счётчики 0, `safe: true`;
  проба неразмещённых единиц всё равно может дать непустой `would_strand`.
  Ключи двух карт совпадают и соответствуют видимым подсистемам; общий `safe` определяется всеми
  подсистемами, а не только видимыми, чтобы скрытые единицы не разрешали выключение сервера.

Если нужное чтение/запись хранилища не подтверждены, операция возвращает 503 `{detail, error: unavailable}`;
при неизвестном исходе записи клиент сначала перечитывает состояние. `busy` и `denied` имеют отдельные причины глав 6.3
и 6.5 (Н4). Коды и тела общих отказов описаны у каждой операции контракта урока. Операционный 404 отличается от
`NoRoute`: у сервера — `{detail, error}`, у неразмещённой единицы — `{reason}`.
Отказ вывода 409 содержит `{detail, error: "server answers", server, may_confirm_gone}`;
`may_confirm_gone: true` разрешён только при никогда не слышанном ресурсе и отсутствии свежих
свидетельств воркера/слота/ресурса. При живом сервере `gone: true` не обходит отказ: любое свежее свидетельство —
409 с `may_confirm_gone: false`, и `gone: true` его не меняет. Свежесть свидетельства — «слышен в последние LOST_AFTER»
[договора наблюдения](../../common/contracts/observation.md) (Н3 «вывести_сервер»).

### Н2.3 Схема и дренаж

`/schema` и `/drain` — общие двери у корня консоли: префикс подсистемы к ним не добавляется (глава 6.5 Н2). Разбор
запроса — [глава 6.5](06.5-console.norms.md) Н2 «Разбор запроса консоли» (P/01.1 Н2.1 с отступлениями консоли; повтор
`version` у `PUT /schema` — 400). Общие отказы консоли, `HEAD` и предел чтения — глава 6.5 Н2, Н4.

| Дверь | Полное успешное тело / особые отказы |
|---|---|
| GET `/schema` | `{version, understood, builds, can_raise_to, processes, schema_unknown?}`: version — целое ≥1; нет строки — равно understood; испорченная строка — null и `schema_unknown: true` (у читаемой строки поля нет); understood — схема консоли; builds — различные `build` своей сборки (BUILD) и всех процессов processes, по возрастанию байтов UTF-8; processes — по пульсам (Н1.1а heartbeat), ключ с пространством имён: воркер — `<sub>/<имя слота>` (`testsub/w-1`), ресурс — `resource/<сервер>` (`resource/srv-a`); так не сталкиваются слоты разных подсистем с одним `slot.prefix` и сервер с именем слота; контроллер и консоль пульса не пишут и в processes не входят; значение — `{schema: целое ≥1 или null, build, ts, live}`, live — пульс менялся на глазах консоли в последние LOST_AFTER ([договор наблюдения](../../common/contracts/observation.md) «Свежесть»; разбор ревью стадии A 6–7, № 1: было «< 45 с» — правка поведения на шаге границы, после сверки свидетелей); can_raise_to — минимум understood и схем живых, при неизвестной живой — 0. Нечитаемое хранилище — 503 |
| PUT `/schema?version=N` | 200 `{version: N}`; 409 `{detail, error}` при понижении, испорченной строке, своей/живой старой сборке или конфликте CAS. Версия — десятичная строка положительного целого без знака и ведущих нулей, без верхней границы формы: N больше своей SCHEMA — 409 (Н3 шаг 3), а не 400; строка `platform/schema` с таким числом — GET отдаёт его точным числом JSON (сверка python и go М10/6–11, совпало без нормы). N, равная version строки (или understood при её отсутствии), разрешена: проверки Н3 пройдены — строка переписывается с новым at (cas), журнал schema.raised |
| GET/POST/DELETE `/drain` | Точные `DrainState`, `DrainStarted`, `DrainCleared` и отказы Н2.1, Н2.2, Н4. После DELETE снят только дренаж: draining="", счётчики 0, safe=true; проба неразмещённых остаётся, would_strand не обязана быть пустой. Ключи would_strand/subsystems совпадают по Н2.2 |

## Н3 Проход

### поднять_схему(N) — консоль, admin

```
1. строка N — только ASCII [1-9][0-9]* целиком (без знака, пробелов и ведущего нуля), значение ≥1 (Н2.3)                                            → иначе 400 «a version is a whole number from 1»
2. строка platform/schema: не число → 409 «mend the row first»; have > N → 409 «does not go back»
3. своя SCHEMA < N → 409; живые процессы (пульсы менялись на глазах читателя в последние LOST_AFTER — договор наблюдения):
   любой со schema < N или неизвестной → 409 «still running: …»; ошибка чтения → 503, не пустой состав
4. записать {version: N, at} с cas; журнал schema.raised
```

Шаг 3: «живые» — по [договору наблюдения](../../common/contracts/observation.md) «Свежесть» (разбор ревью стадии A 6–7,
№ 1: было «< 45 с» — правка поведения на шаге границы; граница — вектор [`fresh-age`](../../common/vectors/fresh-age/README.md), разбор ревью
стадии B 6–7, № 20).

**Допуск.** Оператор запрещает старты и записи прежних сборок на всё окно, включая молчащие серверы; обновляет весь известный состав и оставляет одну совместимую консоль для подъёма. Пульсы — проверка наблюдённого состава, не доказательство отсутствия старого процесса. Без этого допуска конкурентный подъём вне профиля урока. После успешного CAS можно открывать старты только обновлённых сборок. Два admin всё равно защищены CAS: проигравший перечитывает состояние, не объявляет успех.

| Фаза | Допуск/переход | Отказ |
|---|---|---|
| Открытая установка | Оператор закрывает старты старых сборок, останавливает их писателей | Не удалось подтвердить остановку — не поднимать |
| Обслуживание | Полное чтение схемы и известных процессов; N допускается своей сборкой | Неизвестное чтение — 503; несовместимость — 409 |
| CAS | Зафиксировать версию; при обрыве перечитать | Не считать обрыв откатом |
| Завершено | Вернуть только совместимые сборки | Старая сборка отказывается стартовать |

### старт консоли — проверка схемы

Общий блок всех четырёх процессов (прежде М10/10 Н3 «старт контроллера, воркера, ресурса или консоли — проверка схемы»);
здесь — сторона консоли, внутри P/06.6-04 (В5 плана переноса урока 6). Сторона воркера —
[P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3 «проверка схемы воркером», контроллера —
[P/04](../../04-controller/spec/04-controller.norms.md) Н3 «старт контроллера — проверка схемы», ресурса —
[P/05](../../05-resource/spec/05-resource.norms.md) Н3 «старт ресурса — проверка схемы».

Так же стартуют процессы домена — `domain`, агент, консоль домена (М11/12 Н1.8).

```
первым шагом старта, до чтения спеки (P/02.3), у всех четырёх процессов:
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
  ошибка чтения → ждать доступности, не начиная работы; не стартовать — выход с кодом 2 и строкой лога
воркер: после продления слота — P/03.2 Н3 «проверка схемы воркером»
```

**Граница.** Демон строкового хранилища не толкует раскладку подсистемы и этой проверкой не блокируется: иначе нельзя было бы открыть хранилище для чтения/исправления схемы; его собственный формат — P/01.1 и P/01.3 Н1.3 (демон `configstore`: `member.json`, `backup`/`restore`). Проверка при продлении есть у воркера; она не доказывает безопасность всех остальных процессов. Их гонка со стартом исключена окном обслуживания выше. Сбой чтения — ждать доступности без работы; достоверно испорченная/слишком новая схема — отказ старта с кодом 2.

### дренаж — чтение состояния

```
для каждой спеки: воркеры сервера (пульсы; пульс не читается — server слота, Н1.2 server_of) → units = Σ назначений,
pending = Σ pending_writes (нет/слово/дробь/нечитаемый пульс → unsaid; сверка python и go М10/6–11, T2),
would_strand = все единицы воркеров сервера и все неразмещённые единицы подсистемы — без моделирования размещения (Н2.2 `DrainState`)
safe = Σ units == 0 ∧ Σ pending == 0 ∧ unsaid пуст
```

**Гонки.** Два одновременных `POST /drain` разных серверов: проверка «иной при активном дренаже — 409» и запись строки идут
без `cas` — нормой эта гонка не разобрана, вопрос «Архитектору» (разбор ревью стадии B 6–7, № 41). Контроллер читает draining раз за проход; ранее назначенное может доехать позже. `safe` — вывод по наблюдённым размещениям и свежим известным пульсам, не атомарный снимок и не блокировка новых назначений. Перед выключением оператор прекращает новые записи/назначения на сервер, дожидается завершения начатых действий и повторно проверяет состояние. Не удалось подтвердить покой — выключение откладывается; одного `safe: true` недостаточно.

### вывести_сервер(s) — сторона консоли

Перенесено из [P/04 Н3](../../04-controller/spec/04-controller.norms.md) «вывести_сервер(s) — запрос консоли, исполнение
контроллером» (сторона консоли; разбор ревью стадии A 6–7, № 2); исполнение контроллером — там же.

```
запрос (POST /servers/{server}/decommission):
  ресурс, воркер или слот сервера слышны в последние LOST_AFTER (договор наблюдения)  → 409 server answers
  ресурс никогда не слышали ∧ gone ≠ true                                              → 409, may_confirm_gone
  иначе записать platform/decommission/<s>                                              → 202, журнал
проход консоли (после отметки контроллера <sub>/decommissioned/<s> каждой спеки): удалить platform/doors/<s> с cas
  по прочитанной версии (право delete:, P/02.5 Н1.4); ресурс выведенного сервера, пока стоит platform/decommission/<s>,
  свою дверь заново не пишет (P/05 Н1.4 `door_row`)
отзыв (DELETE /servers/{server}/decommission): строка запроса снята → отметку снимает следующий проход контроллера;
  дверь ресурс пишет снова своим пульсом
```

«Слышны» — по [договору наблюдения](../../common/contracts/observation.md) «Свежесть» (разбор ревью стадии A 6–7, № 1:
было «< LOST_AFTER назад» — правка поведения на шаге границы: возраст ровно LOST_AFTER — слышен, 409; граница — вектор
[`fresh-age`](../../common/vectors/fresh-age/README.md), разбор ревью стадии B 6–7, № 20); «никогда не слышали» — ресурс `unknown` того же договора.

**Гонки.** Запрос консоли и проход контроллера разделены строкой — повтор запроса идемпотентен (P/04 Н3
«вывести_сервер», «Гонки»).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **частоту скана назначений** консоли для `Where.directory` и `scans`;
2. **способ ожидания между шагами обновления** (опрос, событие, срок); сам порядок обновления — норма P/02.4 Н1.7 `upgrade`, не выбор.
