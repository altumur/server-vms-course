## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0](../../01-store/spec/01.1-store.norms.md#время-в-строке): объект пульса `<sub>/heartbeats/<имя>` — `ts`, `started`, `previous_hb`, `stood_in.as_of`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `<sub>/heartbeats/<имя>`;
- пишет: `<sub>/slots/<имя>` (cas), `<sub>/holds/<место>` (guard), `<sub>/<manifest:tables>/<имя>` (cas);
- читает: `platform/manifest/<sub>`, `<sub>/epoch/<id>`, `platform/schema`, `door/keys`, `/etc/w2c/tls/<роль>/server.key`, `domain/member-list` и `domain/<sub>/<manifest:domain.books>` — по worker.reads (Н1.7 door_admission, cross_cluster: центры членов для проверки двери mixed другого кластера; копия книги назначения — для решений подсистемы, свежесть по её полю missing; ADR-0091 доп. (13) п. 5, доп. (15) п. 6, доп. (18) п. 2).

Ключ своего комплекта `/etc/w2c/tls/<роль>` воркер читает по `W2C_ROLE`/`W2C_TLS_DIR` ([P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md)
`roles`, [договор сертификата роли](../../common/contracts/role-certificate.md) `kit`): дверь держателя вне петли и
клиент `https://` (разбор ревью стадии B 3–5, № 10).

### Н1.1 Пульс

Объект `<sub>/heartbeats/<имя>` (объект, не строка; запись — `put` объектов P/05 Н1.1 `api`, чтение — `GET /v1/objects/{key}` P/05 Н2). Платформа читает `worker`, `ts`, `status[].id`, `status[].phase`, `status[].epoch`, `status[].revision`, `status[].observed_revision`, `server`, `instance`, `labels`, ёмкость и запас; остальное — слова подсистемы, которые платформа не читает (`heartbeat.strings` манифеста называет, какие из них — строки).

```yaml
heartbeat:
  worker:    <имя слота>                 # ДОЛЖЕН; равен имени в ключе
  ts:        <стенные секунды писателя>  # ДОЛЖЕН; для показа и расхождения часов, не для свежести (ADR-0049)
  status:    # ДОЛЖЕН; по элементу на единицу, которую воркер ведёт
    - {id, phase, epoch, revision, observed_revision, why?, lease?, unconfirmed_s?, …слова подсистемы}
    - {id, phase: sealed, why, revision}                                  # единица запечатана (глава 3.5 Н3 «открыть»):
                                                                          # эпоха не взята — epoch и observed_revision
                                                                          # отсутствуют и у впервые запечатанной, и у
                                                                          # бывавшей в работе; revision — прочитанной
                                                                          # строки; не заявка на единицу (P/08.1 Н1.6 claim)
                                                                          # и не «работает» (P/06.5) (W03-G02)
    - {id, phase: unreadable, why, revision?}                             # строка ни разу не прочитана своим типом (глава
                                                                          # 3.3 Н3 шаг 2): эпоха не взята — epoch и
                                                                          # observed_revision отсутствуют; why «row
                                                                          # unreadable: <причина>»; revision — если ревизия
                                                                          # строки читается; не заявка и не «работает» (W03-G05)
                                                                          # lease: unconfirmed и unconfirmed_s — секунды без
                                                                          # подтверждения аренды (глава 3.2 Н1.6 silent), с
                                                                          # точностью 0,1 с, — только пока аренда не подтверждена;
                                                                          # observed_revision — revision строки,
                                                                          # под которой единица сейчас запущена; why — причина
                                                                          # платформы, когда единица не идёт (sealed — глава 3.5
                                                                          # Н3 «открыть»), как fates.why P/04, не error
                                                                          # (второй пилот, Н-7)
    # учебный обработчик testsub: слово подсистемы одно — n, текущее значение счётчика (книга tallies манифеста testsub
    # показывает n); иных слов у элемента нет (второй пилот, Н-7)
  server:    <сервер> | ""               # ДОЛЖЕН; "" ровно когда сервер неизвестен (ADR-0029); "" — допуск читателя (ADR-0029): воркер этой платформы с SERVER_NAME по P/02.4 Н1.2 его не пишет — пустой SERVER_NAME не проходит грамматику, отказ старта кодом 2 до замка присутствия
                                         # (догадка стадии C W03-G01, решение «Архитектора» 2026-10-23)
  instance:  <экземпляр>                 # ДОЛЖЕН
  labels:    <метки узла через запятую>
  fetched:   <SaidID(rid) через запятую, без пробелов>   # просьбы, исход которых держатель сообщил (глава 3.6 Н3 «взгляд держателя»);
                                     # поля нет или пусто — ничего не сообщено; длину ограничивают FETCHED_COUNT/FETCHED_BYTES (договор отметки просьбы «fetched»)
  <capacity.from>:  <ёмкость>            # имя поля — из manifest.placement.capacity.from (умолчание capacity); когда известна
  <headroom.from>:  <запас = ёмкость − Σ весов назначения>                       # умолчание headroom; вес каждой единицы — по
                                     # договору пула weight, как у контроллера (аудит раскладки, решение «Архитектора» 2026-10-25, А-12): поле weight.field строки, прочитанной последней сверкой,
                                     # нет поля — weight.default, нет placement.weight — 1; поле не число — единица в сумму не входит
                                     # (контроллер её не размещает, P/04)
  <place_by>:  <место>                 # только когда манифест объявил place_by — поле пульса (P/02.1 Н1.2, P/04 «distinct»):
                                     # имя места, которое воркер держит (глава 3.2 Н3 «место»), "" — не держит; пишет база, не подсистема
  conflicts: <Σ конфликтов аренд + перенесённых>   # метрика <sub>_epoch_conflicts
  started:   <момент старта>
  previous_hb, previous_instance, previous_server:  # что воркер застал под своим именем при старте, если было: previous_hb —
                                         # число ts застанного пульса, previous_instance и previous_server — его instance и server
                                         # (журнал cammeta-go, урок 9 № 6: по ним консоль считает failover_seconds, P/06.5 Н3)
  fenced:    true                        # только пока отсечён и имя ещё моё; после отдать_имя пульс не пишется
  was_fenced:    true | false            # был ли этот экземпляр отсечён с запуска; ряд worker_fenced{worker} P/06.5
  store_errors:  <число>                 # запросов к хранилищу без ответа или с ошибкой с запуска (глава 3.2 Н4: store_errors + 1)
  pass_failures: <число>                 # проходов сверки (глава 3.3 Н3 шаг 2), оборванных ошибкой чтения, с запуска
  unconfirmed:   <число>                 # единиц, чья аренда сейчас не подтверждена (элементы status[] с lease: unconfirmed)
  garbled_rows:  <число>                 # чтений строк своих единиц, не прочитанных своим типом (глава 3.3 Н3 шаг 2), и строк
                                         # просьб и меток, не прочитанных своей формой держателем (глава 3.6 «взгляд держателя»; RM-G01), с запуска
  place_error:   {<место>: sealed | refused | wrong}   # место не взято или потеряно (глава 3.2 Н3 «место: взять», глава 3.5
                                         # «открыть»): sealed — секрет строки места не открылся, refused — отказ подсистемы,
                                         # wrong — строка места не по форме; закрытый перечень слов; запись снимается,
                                         # когда место взято или отпущено; записей не больше числа мест-кандидатов;
                                         # place_by — прежнее; смена строки держимого места — перечитать и открыть заново
                                         # (ADR-0091 доп. (10) п. 4; решения «Архитектора» по повторному ревью доп. (10), 2026-10-23)
  freeing:       {<том ресурса>: <байты, целое ≥ 0>}   # ответ воркера подсистемы с requests.free на просьбу ресурса своего
                                         # сервера <sub>/requests/free-<server>-<volume> (P/05 Н1.4 free_ask): пока строка стоит —
                                         # байты, которые он освобождает и которых ещё нет в used; 0 — ничего не освобождает;
                                         # что освобождать — подсистема; поля нет — 0 (запрос VMS freeing, решение «Архитектора» 2026-10-23)
                                         # пять полей выше базовый воркер пишет всегда, и при нуле; ряды P/06.5 — из них;
                                         # passes, assignment_rev нормой не вводятся (запрос VMS «пульс и битая строка», решение «Архитектора» 2026-10-23)
  schema, build, pending_writes:         # добавлено М10/10 (P/06.6 Н1.1а heartbeat: schema, build; Н1.2 pending_writes) —
                                         # базовый воркер пишет 0 сам, если подсистема не сказала своё; поля нет — дренаж не safe
  server_unsaid:  "this worker names no server of its own: every place it holds is let go when its hold goes unconfirmed"
                                         # ровно эта строка (ADR-0029); только когда сервер не назван, а манифест требует places.server_field
  stood_in:  {step, for, as_of}          # только в пульсе подмены (Н3); as_of — ts последнего пульса цикла, который подмена
                                         # повторяет (возраст состояния подсистемы), у следующих повторов тот же; ts пульса —
                                         # время этого повтора (журнал cammeta-go, урок 5 № 2)
  stand_in_renewals: <число>             # только когда > 0
  # счёты держателя и заказчика (ADR-0091 пп. 1, 6, 7; имена свидетеля); каждое поле — только когда в нём есть ненулевое:
  command_counts:  {performed, refused, expired, unknown}   # исходы вызовов действия этим экземпляром с его старта
                                         # (глава 3.6 Н3 «взгляд держателя»); метрика — command_counts.<outcome>
  commands_in_flight: <число>            # вызовов действия, ещё не вернувшихся (глава 3.6: не больше одного на группу)
  commands_reanswered: <число>           # исходов, записанных снова (поздний ответ после unknown — late)
  command_road:    {<by>: <гистограмма>} # дорога: от at строки просьбы до первого местного наблюдения её этим воркером (W03-E05; концы — решение «Архитектора» 2026-10-23);
                                         # by — operator или подсистема подателя
                                         # (первая часть штампа by «<sub>/<unit>» поданной воркером, глава 3.6 Н1.5)
  command_request: {<by>: <гистограмма>} # полное время: от at строки просьбы (время подачи) до исхода; из filed (строка экземпляра) время
                                         # не выводится (догадка стадии C W03-E05, решение «Архитектора» 2026-10-23)
  command_wait:    <гистограмма>         # ожидание у держателя: от первого местного наблюдения просьбы этим воркером до исхода, по
                                         # монотонным часам (W03-E05; концы — решение «Архитектора» 2026-10-23); command_request ≈ command_road + command_wait
  filings:         {filed, again, refused}   # подача просьб воркером (глава 3.6 Н1.5): подана; та же подана снова; не подана
  creates:         {<outcome>: <число>}  # заказ строк другой подсистемы (глава 3.6 Н1.6), закрытый перечень исходов:
                                         # created, extended, unchanged, taken, gone, expired, refused (Г-7)
  made_rows:       {<A>/<rows>: <число>} # заказчик: ключей под префиксом <A>/<rows>/<C>- по последнему перечислению (не чаще
                                         # раза в 60 с; надгробия и занятые строки входят) — остаток строк заказа у адресата
histogram:   # форма гистограммы пульса (имена свидетеля)
  buckets:   [<счёт>…]                   # по одному на границу ROAD_BUCKETS, счёт наблюдений не больше границы (накопительно)
  sum:       <сумма секунд>; count: <число наблюдений>
  ahead, behind: <число>                 # только у command_road, command_request: часы писателя впереди (секунды < 0 — в счёт 0)
                                         # и позади (подача «раньше» перечисления, которое её не видело, больше чем на 1 с)
  ROAD_BUCKETS: [0.1, 0.25, 0.5, 1, 2, 5, 10, 30, 60, 300]
stalled:     status[].stalled: true      # единица, чей отступ запуска дошёл до RETRY_MAX (глава 3.3 Н1.2 retry); иначе поля нет
said_id:     # имя просьбы в fetched — договор отметки просьбы «fetched» `said_id` (перенесено туда без изменения; аудит раскладки А-24, Б-02, решение «Архитектора» 2026-10-25)
phase:
  rule: слова подсистемы; платформа знает три — running (счётчик running, соседство near), sealed (W03-G02) и unreadable
        (W03-G05) — элементы выше
cadence:
  HEARTBEAT_EVERY: 10            # с; первый пульс — до первого прохода, последний — при остановке
  fresh_for: LOST_AFTER          # договор наблюдения «Свежесть» (значение там; аудит раскладки, решение «Архитектора» 2026-10-25, А-01); читатель судит по смене на своих часах
nobody: пульс не пишется, пока воркер — никто
platform_strings: [worker, server, url, instance, labels, fetched, events]   # heartbeat.strings их не называет;
                  # url — добавлено М10/9 (P/06.5 Н3 «/where/<id>»: url двери); fetched — добавлено М10/8 (глава 3.6 Н3 «взгляд держателя»)
```

Неизвестный сервер не препятствует работе под своим слотом. `server: ""` не разрешает считать
место своим; если задан places.server_field, пульс обязательно содержит server_unsaid; при places.lease: strict все
места считаются строгими по ADR-0029. При известном сервере server непустой, server_unsaid отсутствует.
BOX_ID и instance не подставляются вместо неизвестного сервера: это другие имена.

Любое имя слота по грамматике главы 3.2 (Н1.4) представимо: имена файлов кодирует реализация (договор журнала событий «Имена файлов в общих деревьях»), файлового профиля, который
сужает имена, нет. Заданное имя не по грамматике или без `slot.prefix` — отказ старта с кодом 2 ([глава 3.2](03.2-worker.norms.md) Н3 «старт()» шаг 2а).

### Н1.2 Сроки подмены и бюджет памяти

Часть Н1.2 источника: сроки подмены и бюджет памяти. `LEASE_TTL`, `LEASE_MARGIN` и прочие сроки аренды, метки соперника и
мест — [глава 3.2](03.2-worker.norms.md) Н1.2; сроки цикла (`loop`, `watchdog`) — [глава 3.3](03.3-worker.norms.md) Н1.2.

```yaml
stand_in:
  STALL:        (TTL − MARGIN) / 2 = 12.5           # с; шаг застрял, если идёт дольше
  WAKE:         ≤ (TTL − MARGIN) / 4 = 6.25         # с; как часто подмена смотрит
  FOR:          договор файла окружения «Константы и юниты» (значение там; аудит раскладки, решение «Архитектора» 2026-10-25, А-16)   # с; дольше не подменяет: единицы уходят
  BEAT_EVERY:   10                                  # с; повтор пульса подменой
memory:
  rule: CAPACITY × unit_mb + base_mb ≤ WORKER_MEMORY_MB, иначе процесс не стартует (ADR-0070); без unit_mb — не проверяется
        # одна формула бюджета на модуль: CAPACITY — ёмкость воркера в единицах веса (договор пула capacity),
        # unit_mb — МиБ на единицу веса, base_mb — МиБ процесса (нет — 0), WORKER_MEMORY_MB — окружение процесса
```

```yaml
rows:       <sub>/<t>/<имя>; писатель — консоль; таблица из worker.writes (P/02.5 Н1.4) — таблица воркера, без полей *_secret (P/02.1 Н1.2а): он пишет строку целиком с cas,

```

### Н1.7 Дверь процесса: пределы, адрес, допуск, CORS

Общая норма двери процесса подсистемы — двери держателя (Н3 «токен двери у держателя»), шлюза и прочих дверей, которые
слушает процесс подсистемы (запрос VMS № 13, решение «Архитектора» 2026-10-23). Дверь консоли кластера — своя норма (P/06.3, P/06.5), не эта.

```yaml
door_limits:
  CONNECTIONS:  32               # соединений двери одновременно
  PER_ADDRESS:  8                # из них с одного адреса клиента
  HEAD_WITHIN:  5                # с; строка запроса и заголовки целиком
  PACE_FLOOR:   64 KiB/s         # средний темп обмена с клиентом (приём тела и отдача ответа)
  PACE_AFTER:   30               # с; темп меряется от начала соединения после этой отсрочки
  BODY:         1 MiB            # тело запроса; больше — 413 до чтения, по заголовку
  busy:         соединение сверх CONNECTIONS или PER_ADDRESS — 503 {error: "busy"} с Retry-After: 1, без очереди
  slow:         строка и заголовки не пришли за HEAD_WITHIN или средний темп ниже PACE_FLOOR после PACE_AFTER — обрыв
                соединения, ответа нет
```

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## Н3 Проход

### старт() — шаг бюджета

```
1. манифест из каталога — обязателен (NoManifest иначе); бюджет памяти (Н1.2) → иначе не стартовать
```

Остальные шаги старта (схема, экземпляр, замок присутствия, имя, захват, `previous_*`, пульс сразу, запуск подмены и
цикла) — [глава 3.2](03.2-worker.norms.md) Н3 «старт()».

### подмена() — отдельный поток, каждые WAKE

```
шаг цикла идёт дольше STALL и меньше FOR, воркер не никто и writing_allowed:
  продлить слот первым записью с cas — только пока строка называет меня и не released (хранилище не ответило — всё ещё я;
  чужой holder или released → отсечь всё, как в шаге аренды, подмену прекратить; продлён → та же проверка схемы, что в
  шаге аренды, шаг 1); затем продлить каждую аренду —
  подтверждающим чтением строки эпохи (глава 3.2 Н3 «подтвердить»), ничего не пишется;
  продлить удержание строгого места записью с cas под стражем своего слота (разбор ревью стадии B 3–5, № 4), как на шаге аренды (глава 3.2 Н3 «место: взять, держать, отпустить»): чтением срок удержания
  не продлевается;
  пульс: повторить последний пульс цикла с новым ts, stood_in: {step, for, as_of}, stand_in_renewals —
  не чаще BEAT_EVERY и только если цикл сам не написал
шаг идёт дольше FOR: done; журнал «no longer standing in for it (FOR 300 s): its units go»;
  аренды, которые больше не могут действовать, — остановить их единицы по одной
подмена никогда не оживляет отсечённого и не зовёт watchdog
```

Шаг аренды и отсечение — [глава 3.2](03.2-worker.norms.md) Н3 «шаг_аренды()», «отсечь(почему)».

**Гонки.** Подмена и цикл продлевают одну строку слота: замок слота неблокирующий, кто не взял — пропускает; `cas` страхует от записи поверх чужого захвата. Цикл вернулся из застрявшего шага: `взять_эпоху` в нём отказано (шаг пережил подмену), пока цикл не прочтёт назначение заново.

### писать_под_слотом(key, items | удалить)

Условия и запись — глава 3.2 Н3 «писать_под_слотом»; здесь: кто зовёт — публикации вкладов, книг и служебных строк подсистемы; **удаления** таких строк — тоже под стражем. Ни аренда, ни потолок молчания не разрешают публиковать состояние управления: только живой свой слот.

**Гонки.** Глава 3.2: 412 `guard` требует перечитки владения. Собственное продление (в том числе подменой)
сохраняет holder/gen и имя; смена держателя или поколения — потеря. Подмена под слотом не пишет — только продлевает.

### остановка по SIGTERM

```
1. подмена — стоп; опрос — стоп
2. before_stop_all() (глава 3.1 Н2); остановить все единицы; затем закрыть писателей мест
3. пульс последний раз
4. отпустить место (глава 3.2 Н3 «место: взять, держать, отпустить» — под стражем своего слота, пока он мой), затем
   отдать слот (глава 3.2 Н3 «отдать») (разбор ревью стадии B 3–5, № 4)
5. after_stop() (глава 3.1 Н2)
непустое назначение — та же штатная отдача: единицы остановлены, слот отдан, контроллер переносит их по «уходит» P/04;
  плановая остановка скриптом сервера — только воркера с пустым назначением и retiring (P/04 Н3 «сократить()»), так
  что SIGTERM при единицах — рассинхрон скрипта и контроллера, он стоит переезда, а не потери единиц (ADR-0084 п. 7)
крах молчит: ни отдачи слота, ни последнего пульса — судит контроллер (P/04)
```

**Гонки.** Остановка против подмены: подмена останавливается первой, затем отпускание места и отдача слота. Место
отпускается до отдачи слота: под отданным слотом писать нельзя (глава 3.2 Н3 «писать_под_слотом»), и место, не
отпущенное до отдачи, держится до 45 + HOLD_SKEW (разбор ревью стадии B 3–5, № 4); остановка против шага аренды — шаг доводится до записи или прерывается до неё, отдача одна; SIGKILL — не пишется ничего (сц. 05 [приёмки главы 3.2](../acceptance/2/README.md)).

### токен двери у держателя

Форма токена `door1.<kid>.<claims>.<sig>`, строка `door/keys` и проверка у держателя двери с её «Гонками» — [договор токена двери](../../common/contracts/door-token.md) (владелец — урок P/06, глава 6.5;
перенесено туда из этого раздела; разбор ревью стадии B 3–5, В1). Выдаёт токен консоль — [P/06.5](../../06-console/spec/06.5-console.norms.md)
Н3 «`/where/<id>`». Держатель, у которого есть дверь, проверяет токен по договору (P/03.4-08): токен — из `Authorization: Bearer`, иначе из `?t=` (иная схема
`Authorization` — как отсутствующий заголовок; `t` дважды или токена нет — отказ; (решение «Архитектора» 2026-10-20, разбор ревью стадии B 6–7));
путь — путь URL без query (договор «Место токена и путь»; разбор ревью стадии B 6–7, № 9).

поэтому шаг TSV выбор «вес 1 без чтения» не отличит; строки таблиц воркера (Н1.6) — дверь консоли сц. 21 [приёмки P/06.1](../../06-console/acceptance/1/README.md), запись строки воркером заново — чтением; пределы двери процесса (Н1.7) — у стенда нет двери процесса подсистемы, чтением и тестом сервера двери реализации;
токен двери держателем (Н3) — у стенда нет двери держателя, которая проверяет токен (P/03.4-08).

### Свидетельства вне TSV

Строка epoch доказывает выданный номер, но не сам вызов stop_unit или прекращение внешней записи.
Пульсы и метки — объекты, которые текущий TSV не читает. Для них нужен отдельный наблюдатель/стенд
или чтение реализации её владельцем; авторский обзор документов этим свидетельством не является.

| Нормы | Предмет и вмешательство | Наблюдаемый результат |
|---|---|---|
| P/03.4-01, 02 | объект пульса до первого прохода, через 10 с, при SIGTERM и после потери имени | поля Н1.1, ритм, никто не пишет под прежним именем |
| P/03.4-03 | задержка шага через STALL и FOR, гонка подмены и цикла, возврат после FOR | ограниченная подмена, общий страж, нет watchdog из подмены, ворота до нового чтения |
| P/03.4-04, 07 | собственное продление, чужое поколение, ambiguous до/после истечения памяти id | своё продление не лишает имени; поздний ответ не восстанавливает владение |
| P/03.4-05, 06 | SIGTERM против подмены, SIGKILL, недостаточный/достаточный бюджет памяти | порядок остановки и отсутствие уборки при крахе; отказ до старта по бюджету |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **период подмены** в пределах Н1.2 (число повторов `cas` при продлении — [глава 3.2](03.2-worker.norms.md) «Решает реализация» п. 2; разбор ревью стадии B 3–5, № 11);
2. **дополнительные поля пульса** подсистемы и что из них строки (`heartbeat.strings`);
3. **`worker.stop_timeout`** манифеста (P/02.1, 20…50 с; юниту — `TimeoutStopSec`, P/02.4 Н1.1) — не меньше времени
   остановки единиц плюс отдачи слота; бюджет закрытия мест после SIGTERM считается от последнего подтверждения аренды:
   гарантировано не меньше `WRITE_WINDOW` − `RENEW_EVERY` (40 − 8,3 ≈ 31 с, P/03.2 Н1.2) (ADR-0091 доп. (3) п. 4).
