## N3 Procedures

### start() — the budget step

<!-- req: P/03.4-R017 -->

```
1. the manifest from the catalogue — mandatory (NoManifest otherwise); the memory budget (N1.2) → otherwise do not start
```

<!-- req: P/03.4-R018 -->

The other steps of the start (the schema, the instance, the presence lock, the name, the capture, `previous_*`, the heartbeat right away, launching the stand-in and the loop) — [chapter 3.2](03.2-worker.norms.md) N3 «start()».

### stand_in() — a separate thread, every WAKE

<!-- req: P/03.4-R019 -->

```
a step of the loop: STALL < age <= FOR, the worker is not nobody and writing_allowed:
  renew the slot first by a write with cas — only while the row names me and is not released (the store did not answer — still me;
  a foreign holder or released → fence everything, as in the lease step, stop the stand-in; renewed → the same schema check as in
  the lease step, step 1); then renew each lease —
  by a confirming read of the epoch row (chapter 3.2 N3 «confirm»), nothing is written;
  renew the hold of a strict place by a write with cas under the guard of its own slot, as in the lease step (chapter 3.2 N3 «place: take, hold, let go»): a read does not
  renew the hold term;
  heartbeat: repeat the last heartbeat of the loop with a new ts, stood_in: {step, for, as_of}, stand_in_renewals —
  not more often than BEAT_EVERY and only if the loop itself has not written
```

<!-- req: P/03.4-R110 -->

```
the step runs longer than FOR: done; the journal is "no longer standing in for it (FOR " + decimal(FOR) + " s): its units go";
  the leases that can no longer act — stop their units one by one
```

<!-- req: P/03.4-R111 -->

```
age <= STALL: no stand-in actions. the stand-in never revives a fenced one and does not call watchdog
```

<!-- req: P/03.4-R020 -->

The lease step and fencing — [chapter 3.2](03.2-worker.norms.md) N3 «lease_step()», «fence(why)».

<!-- req: P/03.4-R021 -->

**Races.** The stand-in and the loop renew one slot row: the slot lock is non-blocking, whoever did not take it skips; `cas` insures against a write over a foreign capture.

<!-- req: P/03.4-R112 -->

The loop has returned from a stuck step: `take_unit_epoch` is refused in it (the step outlived the stand-in) until the loop reads the assignment anew.

### write_under_slot(key, items | delete)

<!-- req: P/03.4-R199 -->

Every write of the worker that has a value carries `id`. After `ambiguous`, the worker repeats the write with the same `id`. After `unavailable`, the worker repeats the write as it is.

<!-- req: P/03.4-R022 -->

The conditions and the write — chapter 3.2 N3 «write_under_slot»; here: who calls it — the publications of contributions, books and service rows of the subsystem; **deletions** of such rows are also under the guard. Neither a lease nor the silence ceiling allows publishing the control state: only a live own slot.

<!-- req: P/03.4-R023 -->

**Races.** Chapter 3.2: 412 `guard` requires a reread of ownership. An own renewal (including one by the stand-in) keeps holder/gen and the name; a change of the holder or of the generation is a loss.

<!-- req: P/03.4-R115 -->

The stand-in publishes no subsystem contributions, books or state. The stand-in still renews the slot and permitted strict place and repeats the heartbeat by P/03.4-R019; its strict-place renewal remains a write under the slot guard.

### stop by SIGTERM

<!-- req: P/03.4-R198 -->

`worker.stop_timeout` of the manifest (P/02.1, 20…50 s; for the unit — `TimeoutStopSec`, P/02.4 N1.1) is not less than the time of stopping the units plus the hand-over of the slot.

<!-- req: P/03.4-R200 -->

The budget of closing the places after SIGTERM is counted from the last confirmation of the lease: guaranteed not less than `WRITE_WINDOW` − `RENEW_EVERY` (40 − 8.3 ≈ 31 s, P/03.2 N1.2).

<!-- req: P/03.4-R024 -->

```
1. the stand-in — stop; the polling — stop
```

<!-- req: P/03.4-R117 -->

```
2. before_stop_all() (chapter 3.1 N2); stop all units; then close the place writers
```

<!-- req: P/03.4-R118 -->

```
3. the heartbeat for the last time
```

<!-- req: P/03.4-R119 -->

```
4. let go of the place (chapter 3.2 N3 «place: take, hold, let go» — under the guard of its own slot, while it is mine), then
   give away the slot (chapter 3.2 N3 «release»)
```

<!-- req: P/03.4-R120 -->

```
5. after_stop() (chapter 3.1 N2)
```

<!-- req: P/03.4-R121 -->

```
a non-empty assignment — the same regular hand-over: the units are stopped, the slot is given away, the controller moves them by «leaving» of P/04;
  a planned stop by the server script is only of a worker with an empty assignment and retiring (P/04 N3 «shrink()»), so
  that SIGTERM with units is a desync of the script and the controller, it costs a move, not a loss of units
```

<!-- req: P/03.4-R122 -->

```
a crash is silent: neither a hand-over of the slot nor the last heartbeat — the controller judges (P/04)
```

<!-- req: P/03.4-R025 -->

**Races.** The stop against the stand-in: the stand-in stops first, then the place is let go and the slot is given away.

<!-- req: P/03.4-R123 -->

The place is let go before the slot is given away: one may not write under a given-away slot (chapter 3.2 N3 «write_under_slot»), and a place not let go before the hand-over is held up to LOST_AFTER + HOLD_SKEW; the stop against the lease step — the step is brought to the write or interrupted before it, the hand-over is one; SIGKILL — nothing is written.
