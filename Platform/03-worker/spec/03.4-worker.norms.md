### Н1.1 Heartbeat

<!-- req: P/03.4-R005 -->

The object `<sub>/heartbeats/<name>` (an object, not a row; the write — `put` of objects (the object store client contract `api`), the read — `GET /v1/objects/{key}` P/05 Н2). The platform reads `worker`, `ts`, `status[].id`, `status[].phase`, `status[].epoch`, `status[].revision`, `status[].observed_revision`, `server`, `instance`, `labels`, the capacity and the headroom; the rest are words of the subsystem that the platform does not read (`heartbeat.strings` of the manifest names which of them are strings).

<!-- req: P/03.4-R006 -->

```yaml
heartbeat:
  worker:    <slot name>                 # MUST; equal to the name in the key
  ts:        <wall seconds of the writer>  # MUST; for display and for the clock divergence, not for freshness (ADR-0049)
  status:    # MUST; one element per unit that the worker runs
    - {id, phase, epoch, revision, observed_revision, why?, lease?, unconfirmed_s?, …words of the subsystem}
    - {id, phase: sealed, why, revision}                                  # the unit is sealed (chapter 3.5 Н3 «open»):
                                                                          # no epoch is taken — epoch and observed_revision
                                                                          # are absent both at a unit sealed for the first time and at
                                                                          # one that has been running; revision — of the read
                                                                          # row; not a claim on the unit (P/08.1 Н1.6 claim)
                                                                          # and not «работает» (P/06.5) (W03-G02)
    - {id, phase: unreadable, why, revision?}                             # the row has never been read by its type (chapter
                                                                          # 3.3 Н3 step 2): no epoch is taken — epoch and
                                                                          # observed_revision are absent; why
                                                                          # «row unreadable: <reason>»; revision — if the revision
                                                                          # of the row is readable; not a claim and not «работает» (W03-G05)
                                                                          # lease: unconfirmed and unconfirmed_s — the seconds without
                                                                          # a confirmation of the lease (chapter 3.2 Н1.6 silent), with
                                                                          # a precision of 0.1 s, — only while the lease is not confirmed;
                                                                          # observed_revision — the revision of the row
                                                                          # under which the unit is running now; why — the reason
                                                                          # of the platform when the unit is not running (sealed — chapter 3.5
                                                                          # Н3 «open»), like fates.why of P/04, not error
                                                                          # (the second pilot, «N-7»)
    # the teaching handler testsub: the subsystem word is one — n, the current value of the counter (the book tallies of the manifest testsub
    # shows n); the element has no other words (the second pilot, «N-7»)
  server:    <server> | ""               # MUST; "" exactly when the server is unknown (ADR-0029); "" is a tolerance of the reader (ADR-0029): a worker of this platform with SERVER_NAME by P/02.4 Н1.2 does not write it — an empty SERVER_NAME does not pass the grammar, a start refusal with code 2 before the presence lock
                                         # (stage C guess W03-G01, the Architect's decision 2026-10-23)
  instance:  <instance>                  # MUST
  labels:    <node labels, comma-separated>
  fetched:   <SaidID(rid), comma-separated, without spaces>   # the requests whose outcome the holder has reported (chapter 3.6 Н3 «holder's look»);
                                     # no field or empty — nothing is reported; the length is bounded by FETCHED_COUNT/FETCHED_BYTES (the request mark contract «fetched»)
  <capacity.from>:  <capacity>            # the field name — from manifest.placement.capacity.from (default capacity); when known
  <headroom.from>:  <headroom>                # default name headroom; the base computes capacity − Σ of the assignment weights, the subsystem MAY say its own value, the base does not overwrite it, like schema, build; the controller does not read the field (C03-HEADROOM-SAY-01); the weight of each unit — by
                                     # the pool contract weight, as at the controller (layout audit, the Architect's decision 2026-10-25, «A-12»): the field weight.field of the row read by the last reconciliation,
                                     # no field — weight.default, no placement.weight — 1; the field is not a number — the unit does not enter the sum
                                     # (the controller does not place it, P/04)
  <place_by>:  <place>                 # only when the manifest declared place_by — a heartbeat field (P/02.1 Н1.2, P/04 «distinct»):
                                     # the name of the place that the worker holds (chapter 3.2 Н3 «место»), "" — holds none; written by the base, not by the subsystem
  conflicts: <Σ of lease conflicts + moved ones>   # the metric <sub>_epoch_conflicts
  started:   <the start moment>
  previous_hb, previous_instance, previous_server:  # what the worker found under its name at start, if there was anything: previous_hb —
                                         # the number ts of the found heartbeat, previous_instance and previous_server — its instance and server
                                         # (the cammeta-go journal, lesson 9 № 6: by them the console computes failover_seconds, P/06.5 Н3)
  fenced:    true                        # only while fenced and the name is still mine; after «отдать_имя» the heartbeat is not written
  was_fenced:    true | false            # whether this instance has been fenced since launch; the series worker_fenced{worker} of P/06.5
  store_errors:  <number>                # requests to the store without an answer or with an error since launch (chapter 3.2 Н4: store_errors + 1)
  pass_failures: <number>                # reconciliation passes (chapter 3.3 Н3 step 2) cut short by a read error, since launch
  unconfirmed:   <number>                # units whose lease is not confirmed now (the elements of status[] with lease: unconfirmed)
  garbled_rows:  <number>                # reads of the rows of its own units not read by their type (chapter 3.3 Н3 step 2), and of the rows
                                         # of requests and marks not read by their form by the holder (chapter 3.6 «holder's look»; RM-G01), since launch
  place_error:   {<place>: sealed | refused | wrong}   # the place is not taken or is lost (chapter 3.2 Н3 «место: взять», chapter 3.5
                                         # «open»): sealed — the secret of the place row did not open, refused — a refusal of the subsystem,
                                         # wrong — the place row is not by the form; a closed list of words; the record is removed
                                         # when the place is taken or let go; there are no more records than candidate places;
                                         # place_by — as before; a change of the row of the held place — reread and open anew
                                         # (ADR-0091 addendum (10) item 4; the Architect's decisions on the repeated review of addendum (10), 2026-10-23)

                                         # server <sub>/requests/free-<server>-<volume> (P/05 Н1.4 free_ask): while the row stands —
                                         # the bytes that it frees and that are not yet in used; 0 — frees nothing;
                                         # what to free — the subsystem; no field — 0 (VMS request freeing, the Architect's decision 2026-10-23)
                                         # the base worker writes the five fields above always, at zero too; the series of P/06.5 come from them;
                                         # passes, assignment_rev are not introduced by the norm (VMS request «пульс и битая строка», the Architect's decision 2026-10-23)
  schema, build, pending_writes:         # added by М10/10 (P/06.6 Н1.1а heartbeat: schema, build; Н1.2 pending_writes) —
                                         # the base worker writes 0 itself if the subsystem did not say its own; no field — the drain is not safe
  server_unsaid:  "this worker names no server of its own: every place it holds is let go when its hold goes unconfirmed"
                                         # exactly this string (ADR-0029); only when the server is not named and the manifest requires places.server_field
  stood_in:  {step, for, as_of}          # only in a stand-in heartbeat (Н3); as_of — ts of the last heartbeat of the loop that the stand-in
                                         # repeats (the age of the subsystem state), the same at the next repeats; ts of the heartbeat —
                                         # the time of this repeat (the cammeta-go journal, lesson 5 № 2)
  stand_in_renewals: <number>            # only when > 0
  # the tallies of the holder and of the orderer (ADR-0091 items 1, 6, 7; the witness names); each field — only when it holds a non-zero value:
  command_counts:  {performed, refused, expired, unknown}   # the outcomes of action calls by this instance since its start
                                         # (chapter 3.6 Н3 «holder's look»); the metric — command_counts.<outcome>
  commands_in_flight: <number>           # action calls not yet returned (chapter 3.6: not more than one per group)
  commands_reanswered: <number>          # outcomes written again (a late answer after unknown — late)
  command_road:    {<by>: <histogram>} # the road: from at of the request row to its first local observation by this worker (W03-E05; the ends — the Architect's decision 2026-10-23);
                                         # by — operator or the subsystem of the filer
                                         # (the first part of the stamp by «<sub>/<unit>» of a request filed by a worker, chapter 3.6 Н1.5)
  command_request: {<by>: <histogram>} # the full time: from at of the request row (the filing time) to the outcome; from filed (the instance row) the time
                                         # is not derived (stage C guess W03-E05, the Architect's decision 2026-10-23)
  command_wait:    <histogram>         # the wait at the holder: from the first local observation of the request by this worker to the outcome, by the
                                         # monotonic clock (W03-E05; the ends — the Architect's decision 2026-10-23); command_request ≈ command_road + command_wait
  filings:         {filed, again, refused}   # the filing of requests by the worker (chapter 3.6 Н1.5): filed; the same filed again; not filed
  creates:         {<outcome>: <number>}  # the ordering of rows of another subsystem (chapter 3.6 Н1.6), a closed list of outcomes:
                                         # created, extended, unchanged, taken, gone, expired, refused («G-7»)
  made_rows:       {<A>/<rows>: <number>} # the orderer: keys under the prefix <A>/<rows>/<C>- by the last listing (not more often
                                         # than once in 60 s; tombstones and taken rows are included) — the remainder of the order rows at the addressee
histogram:   # the form of a heartbeat histogram (the witness names)
  buckets:   [<count>…]                   # one per boundary of ROAD_BUCKETS, the count of observations not greater than the boundary (cumulative)
  sum:       <sum of seconds>; count: <number of observations>
  ahead, behind: <number>                # only at command_road, command_request: the clock of the writer ahead (seconds < 0 — counted as 0)
                                         # and behind (a filing «earlier» than the listing that did not see it, by more than 1 s)
  ROAD_BUCKETS: [0.1, 0.25, 0.5, 1, 2, 5, 10, 30, 60, 300]
stalled:     status[].stalled: true      # a unit whose launch backoff has reached RETRY_MAX (chapter 3.3 Н1.2 retry); otherwise there is no field
said_id:     # the request name in fetched — the request mark contract «fetched» `said_id` (moved there without change; layout audit «A-24», «B-02», the Architect's decision 2026-10-25)
phase:
  rule: words of the subsystem; the platform knows three — running (the counter running, the neighbourhood near), sealed (W03-G02) and unreadable
        (W03-G05) — the elements above
cadence:
  HEARTBEAT_EVERY: 10            # s; the first heartbeat — before the first pass, the last — at the stop
  fresh_for: LOST_AFTER          # the observation contract «Свежесть» (the value is there; layout audit, the Architect's decision 2026-10-25, «A-01»); the reader judges by the change on its own clock
nobody: no heartbeat is written while the worker is nobody
platform_strings: [worker, server, url, instance, labels, fetched, events]   # heartbeat.strings does not name them;
                  # url — added by М10/9 (P/06.5 Н3 «/where/<id>»: the url of the door); fetched — added by М10/8 (chapter 3.6 Н3 «holder's look»)
```

<!-- req: P/03.4-R007 -->

An unknown server does not prevent work under its own slot. `server: ""` does not allow counting a
place as its own; if places.server_field is set, the heartbeat necessarily contains server_unsaid; with places.lease: strict all
places are considered strict by ADR-0029. With a known server, server is non-empty and server_unsaid is absent.
BOX_ID and instance are not substituted for an unknown server: these are other names.

<!-- req: P/03.4-R008 -->

Any slot name by the grammar of chapter 3.2 (Н1.4) is representable: file names are encoded by the implementation (the event log contract «File names in shared trees»); there is no file profile that
narrows the names. A given name not by the grammar or without `slot.prefix` — a start refusal with code 2 ([chapter 3.2](03.2-worker.norms.md) Н3 «start()» step `2a`).

### Н1.2 Stand-in timings and the memory budget

<!-- req: P/03.4-R009 -->

The part of Н1.2 of the source: the stand-in timings and the memory budget. `LEASE_TTL`, `LEASE_MARGIN` and the other lease timings, the rival marks and
the places — [chapter 3.2](03.2-worker.norms.md) Н1.2; the loop timings (`loop`, `watchdog`) — [chapter 3.3](03.3-worker.norms.md) Н1.2.

<!-- req: P/03.4-R010 -->

```yaml
stand_in:
  STALL:        (TTL − MARGIN) / 2 = 12.5           # s; a step is stuck if it runs longer
  WAKE:         ≤ (TTL − MARGIN) / 4 = 6.25         # s; how often the stand-in looks
  FOR:          the environment file contract «Constants and units» (the value is there; layout audit, decision of the Architect 2026-10-25, «A-16»)   # s; it does not stand in longer: the units go
  BEAT_EVERY:   10                                  # s; the repeat of the heartbeat by the stand-in
memory:
  rule: CAPACITY × unit_mb + base_mb ≤ WORKER_MEMORY_MB, otherwise the process does not start (ADR-0070); without unit_mb, CAPACITY or WORKER_MEMORY_MB — not checked, the capacity — capacity.default: a worker on the domain has no role file, there are no values (C03-MEMORY-NO-ROLE-01)
        # one budget formula per module: CAPACITY — the capacity of the worker in weight units (the pool contract capacity),
        # unit_mb — MiB per weight unit, base_mb — MiB of the process (none — 0), WORKER_MEMORY_MB — the environment of the process
```

### Н1.7 The process door: limits, address, admission, CORS

<!-- req: P/03.4-R013 -->

The common norm of the process door of a subsystem — the holder doors (Н3 «the door token at the holder»), the gateway and the other doors that
the process of the subsystem listens on (VMS request № 13, the Architect's decision 2026-10-23). The console door of the cluster has its own norm (P/06.3, P/06.5), not this one.

<!-- req: P/03.4-R014 -->

```yaml
door_limits:
  CONNECTIONS:  32               # simultaneous connections of the door
  PER_ADDRESS:  8                # of them from one client address
  HEAD_WITHIN:  5                # s; the request line and the headers in full
  PACE_FLOOR:   64 KiB/s         # the average pace of the exchange with the client (receiving the body and sending the answer)
  PACE_AFTER:   30               # s; the pace is measured from the start of the connection after this delay
  BODY:         1 MiB            # the request body; larger — 413 before reading, by the header
  busy:         a connection beyond CONNECTIONS or PER_ADDRESS — 503 {error: "busy"} with Retry-After: 1, without a queue
  slow:         the line and the headers did not arrive within HEAD_WITHIN or the average pace is below PACE_FLOOR after PACE_AFTER — the connection
                is cut, there is no answer
  other:        a door that needs other values names them as constants of the lesson that owns the door; there is no manifest key
door_address:   # the address of any process door in the heartbeat (url and the addresses of the subsystem; ADR-0091 addendum (7), (8); the Architect's decisions on the repeated review 2026-10-23)
  kit:          with the role kit (P/02.4 Н1.6 kit) — listens on the addresses to which SERVER_NAME of this server resolves
                (several — all of them), and publishes https://SERVER_NAME:<port> (the role certificate by the name, SAN DNS, it matches);
                an explicit <DOOR>_HOST not among them — a start refusal, code 2; a temporary failure of resolution at load —
                waiting with a retry, not code 2 (ADR-0091 addendum (10) item 5)
  no_kit:       without a kit — only the loopback: the binding 127.0.0.1, the address http://127.0.0.1:<port>; there is no «loopback + https»;
                «no kit» and a partial kit (code 2) — the role certificate contract mixed kit_absent (RC-NOKIT)
  any:          0.0.0.0 and :: — a start refusal, code 2; the port — the actual one; the rule of the host and of the binding — for any process door in the
                heartbeat, the scheme of a non-HTTP door (rtsp, rtsps and the like) is named by the lesson that owns the door; there is no IP in the door address
  parts:        the doors of the parts of the subsystem (parts) are not covered by this norm: a part has no heartbeat and no w2c.env
door_admission: # the admission of a route — the class mixed of the role certificate contract; the routes — door.routes (P/02.1 Н1.3)
  token:        a route-name or {name} without role and domain — the door token (the door-token contract), otherwise 403 forbidden
                (P/02.1 Н1.3 door.routes; stage C guess W03-G08, decision of the Architect 2026-10-23)
  role:         a route {name, role} — a leaf of one of the roles; the words — 401 no_role, 403 wrong_role, 403 bad_chain (the role certificate contract, the class role refusal)
  domain:       a route {name, domain: [<kind>…]} — the role certificate contract, the class mixed domain (moved there without change; layout audit «B-20», decision of the Architect 2026-10-25)
  keep:         expect.keep — the kinds of the route for which the catalogue manifest that declared the kind in domain.tokens holds keep: true; the door manifest may leave the kind undeclared: the manifest of the kind is read, not that of the door (rec accepts stream declared by cam); a kind in no manifest of the catalogue — outside keep
  role_domain:  a route {name, role, domain} — the role certificate contract, the class mixed role_domain (ibid.)
  no_kit:       the role routes without a kit are closed — 401 no_role, at start a journal line; the process and the routes token and
                domain work on the loopback (a registrar without a kit writes; ADR-0091 addendum (14) item 3)
  cross_cluster: a client of another cluster goes to a mixed door without a leaf (as the row clients of a signed door chooses to whom to present a leaf):
                the mixed door breaks the handshake on a leaf that does not match the CA of its own cluster; the admission — the route
                domain; the client checks the door server by the peer contract (a row of the clients table): the member — the one named by
                the assignment or by the book of the subsystem, the role — the role of the door, the CA — Entry.ca of this member from the copy domain/member-list/<part>
                (read by worker.reads), the name — from the address by which it came (ADR-0091 addendum (18) item 2, addendum (19) item 2)
  refusal:      the refusal body — {error, detail}: error — the word of the contract (forbidden of the route token; no_role, wrong_role,
                bad_chain; the words of the function token); 503 {error: no_handler, detail} — the subsystem has no live handler of the
                route, detail — a constant text (ADR-0091 addendum (17) item 8, addendum (18) item 4)
  not_http:     a non-HTTP listener of the subsystem (SRT and the like) — a choice of the implementation on a separate listener: the address — door_address,
                the limits — door_limits, the journal — audit/<role>/e1, the admission — the rules role, domain, role_domain above; the transport
                and the refusal format — the lesson of the subsystem (ADR-0091 addendum (14) item 4, addendum (17) item 7)
pass_door:      # the door.pass routes of the second kind on the worker door (ADR-0094 B1; the gate-and-pass contract «Pass of the second kind»)
  kit:          the admission — a leaf of the role console, as a route {name, role: [console]} of the class mixed: no leaf 401 no_role, another role 403 wrong_role, bad_chain — 403; so a request
                with a ticket arrives only from the console (ADR-0094 addendum (12) item 6)

```

```
  renew the hold of a strict place by a write with cas under the guard of its own slot (review analysis of stage B 3–5, № 4), as in the lease step (chapter 3.2 Н3 «place: take, hold, let go»): a read does not
  renew the hold term;
  heartbeat: repeat the last heartbeat of the loop with a new ts, stood_in: {step, for, as_of}, stand_in_renewals —
  not more often than BEAT_EVERY and only if the loop itself has not written
the step runs longer than FOR: done; the journal «no longer standing in for it (FOR 300 s): its units go»;
  the leases that can no longer act — stop their units one by one
the stand-in never revives a fenced one and does not call watchdog
```

<!-- req: P/03.4-R020 -->

The lease step and fencing — [chapter 3.2](03.2-worker.norms.md) Н3 «lease_step()», «fence(why)».

<!-- req: P/03.4-R021 -->

**Races.** The stand-in and the loop renew one slot row: the slot lock is non-blocking, whoever did not take it skips; `cas` insures against a write over a foreign capture. The loop has returned from a stuck step: `взять_эпоху` is refused in it (the step outlived the stand-in) until the loop reads the assignment anew.

### write_under_slot(key, items | delete)

<!-- req: P/03.4-R022 -->

The conditions and the write — chapter 3.2 Н3 «write_under_slot»; here: who calls it — the publications of contributions, books and service rows of the subsystem; **deletions** of such rows are also under the guard. Neither a lease nor the silence ceiling allows publishing the control state: only a live own slot.

<!-- req: P/03.4-R023 -->

**Races.** Chapter 3.2: 412 `guard` requires a reread of ownership. An own renewal (including one by the stand-in)
keeps holder/gen and the name; a change of the holder or of the generation is a loss. The stand-in does not write under the slot — it only renews.

### stop by SIGTERM

<!-- req: P/03.4-R024 -->

```
1. the stand-in — stop; the polling — stop
2. before_stop_all() (chapter 3.1 Н2); stop all units; then close the place writers
3. the heartbeat for the last time
4. let go of the place (chapter 3.2 Н3 «place: take, hold, let go» — under the guard of its own slot, while it is mine), then
   give away the slot (chapter 3.2 Н3 «release») (review analysis of stage B 3–5, № 4)
5. after_stop() (chapter 3.1 Н2)
a non-empty assignment — the same regular hand-over: the units are stopped, the slot is given away, the controller moves them by «leaving» of P/04;
  a planned stop by the server script is only of a worker with an empty assignment and retiring (P/04 Н3 «сократить()»), so
  that SIGTERM with units is a desync of the script and the controller, it costs a move, not a loss of units (ADR-0084 item 7)
a crash is silent: neither a hand-over of the slot nor the last heartbeat — the controller judges (P/04)
```

<!-- req: P/03.4-R025 -->

**Races.** The stop against the stand-in: the stand-in stops first, then the place is let go and the slot is given away. The place
is let go before the slot is given away: one may not write under a given-away slot (chapter 3.2 Н3 «write_under_slot»), and a place not
let go before the hand-over is held up to 45 + HOLD_SKEW (review analysis of stage B 3–5, № 4); the stop against the lease step — the step is brought to the write or interrupted before it, the hand-over is one; SIGKILL — nothing is written (sc. 05 of [the acceptance of chapter 3.2](../acceptance/2/README.md)).
