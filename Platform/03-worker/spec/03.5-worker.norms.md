# P/03.5 — The key ring and opening: norms

This English text is the source; the Russian translation `ru/spec/03.5-worker.norms.md` (for people, not in the export) is derived from it.

The chapter canon. Lecture (`ru/03-worker.md`, for people, not in the export), [instructions](03-worker.README.md), [lifecycle](../lifecycle.md), [acceptance](../acceptance/5/README.md) (judge-only: SDK seams for the no-key and non-envelope branches of P/03.5-R025, P/03.5-R026, P/03.5-R033, P/03.5-R035; only the listed observations are checked; the heartbeat/log scan does not inspect memory).

The envelope, AAD, kid and ring-file grammar belong to the [sealing contract](../../common/contracts/sealing.md), with its [vectors](../../common/vectors/sealing/README.md) (judge-only: the sealing vectors; checks opening/AAD and ring-text parsing P/03.5-R005, P/03.5-R020, P/03.5-R028, P/03.5-R031, P/03.5-R034). This chapter defines recipient opening and ring reading. Console sealing, masks, keyless writing and fingerprints belong to [P/06.2](../../06-console/spec/06.2-console.norms.md). N5 distinguishes SDK seams from process acceptance.

The lesson has no separate HTTP contract (`P/03 no-openapi`); the process-door obligations are in chapter 3.4.

### N1.2 The envelope and the key ring: the worker's side

<!-- req: P/03.5-R005 -->

The worker opens an envelope by the sealing contract — the sections «[Envelope](../../common/contracts/sealing.md#envelope)» and
«[AAD path](../../common/contracts/sealing.md#aad-path)»: with the key `kid` of the envelope, with the single AAD of its place.

<!-- req: P/03.5-R020 -->

The worker reads the ring from the file `SECRETS_KEY` by the section «[Ring file](../../common/contracts/sealing.md#ring-file)».

<!-- req: P/03.5-R021 -->

Who holds the key
(`holders`) and a change of the ring (`rotate`) are [P/06.2 N1.2](../../06-console/spec/06.2-console.norms.md).

<!-- req: P/03.5-R022 -->

The worker no-key refusal is `open_without`. **`open_without`.** an envelope without a key / with a foreign kid → Sealed «sealed and this process has no key» / «sealed with key `<kid>`, which this process does not hold». **`open_without`.** When the unit envelope has no key or has a foreign `kid`, the unit is not started and the cause is in its status. In the message of open_without, `<kid>` is replaced by the name of the envelope's key; the key bytes are not output.

<!-- req: P/03.5-R034 -->

```
for each *_secret at any depth: an envelope → open with its kid key
and the single AAD of the sealing contract for the row key and full path; do not try old ways;
```

```
  no key (SECRETS_KEY not set) / a foreign kid / does not open    → Sealed: do not take the epoch, do not start the unit; the
```

```
for a unit secret supplied as an envelope under P/03.5-R034:
```
