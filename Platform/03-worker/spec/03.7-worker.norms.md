# P/03.7 — Поздний слой: вклады в книги, воркер на домене, токены: нормы

Канон главы 3.7 урока P/03 «Воркер» (ADR-0080; модуль «Платформа» — ADR-0083). **Глава позднего слоя: вводит урок 8**
([записка модуля](../../module-design.md), «Порядок чтения»: после уроков 8–10); до переноса уроков 8 и 9 её соседи по
контракту — уроки М11. [Лекция](../03-worker.md), [инструкция](03-worker.README.md), [жизненный цикл](../lifecycle.md).
Своего HTTP-контракта у урока нет (`P/03 no-openapi`). Каталога приёмки у главы нет (Н5).

Глава перенесена из [М11/5](../../../М11_Domain/spec/05-books-from-member-rows.norms.md) и
[М11/7](../../../М11_Domain/spec/07-worker-tokens.norms.md) (стадия B, ADR-0083 доп. (1): без изменения поведения). Из М11/5:
Н1.2 — сторона писателя вклада (`source_row` с `entry` и `shared`, `writer`, `claim`); Н1.6 целиком (воркер подсистемы на
домене, переносимые книги, `kept`, пульс). Из М11/7: абзац Н1 о токене у воркера (просьба через агента, только в памяти),
Н1.5, Н3 «проверить у получателя» с «Гонками», строка Н4 `wrong_kind`/`wrong_audience`, п. 2 «Решает реализация». Остаются в
М11 до переноса уроков 8 и 9: у вклада — живость слота с перечиткой (`liveness`), вклад в отчёте (`in_report`), `seal_reuse`,
`no_seal`, `reports` (агент, глава 9.1), сборка, доставка и дверь книги (глава 8.5); у токена — дверь держателя, выдача и утверждения (глава 8.7); объявления `domain.books`, `domain.kept`, `domain.tables`,
`domain.tokens` — [P/02.1 Н1.2б](../../02-installer/spec/02.1-installer.norms.md), права `<sub>domain` —
[P/02.5](../../02-installer/spec/02.5-installer.norms.md). Номера подразделов — прежние: Н1.2 и Н1.6 — М11/5, Н1.5 — М11/7.
Ссылка «М11/N» — урок М11 (`М11_Domain/`), ещё не перенесённый; «М10/N» — урок М10; «глава 3.K» — глава этого урока. Id норм —
`P/03.7-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).
Общее уроков М11/2 и М11/3 Н1 действует; книга — наблюдение, не власть ([М11/5 Н1](../../../М11_Domain/spec/05-books-from-member-rows.norms.md)).

## Н1 Форма

**Время.** Поля времени главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): пульс
воркера на домене `domain/<sub>/heartbeat` — как пульс воркера ([глава 3.4](03.4-worker.norms.md) Н1.1; Н1.6 `heartbeat`);
`exp` токена — [М11/7 Н1.4](../../../М11_Domain/spec/07-worker-tokens.norms.md).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `<sub>/<spec:domain.books.from>/<слот>`, `domain/<sub>/<spec:domain.kept>`, `domain/<sub>/<spec:domain.kept>/*`, `domain/<sub>/worker`, `domain/<sub>/heartbeat`;
- пишет: `<sub>/<spec:domain.books.from>` (guard), `domain/<sub>/<spec:domain.books>/<член>` (put);
- читает: `<sub>/slots/<имя>`, `domain/keys`, `domain/revoked`.

Набор `domain/keys` и отзывы `domain/revoked` своего кластера получатель читает для функции `token` М11/2 Н3 (Н3
«проверить у получателя») (разбор ревью стадии B 3–5, № 10).

Вклады — под своим слотом, удаление — при захвате чужого слота; свой слот читается перед первой записью вклада;
строки `domain/<sub>/…` пишет воркер подсистемы на домене (роль `<s>domain`): слот, пульс, `kept`, переносимая книга.

Владелец этих строк по каталогу — М11/5 (до переноса урока 8); своих семей у главы нет.

### Н1.2 Вклад члена: сторона писателя

Живость слота у агента (`liveness`), вклад в отчёте (`in_report`), `seal_reuse`, `no_seal`, `reports` —
[М11/5 Н1.2](../../../М11_Domain/spec/05-books-from-member-rows.norms.md) (глава 9.1).

```yaml
source_row:   строка хранилища члена по from: <sub>/<строка> или <sub>/<строка>/<слот>; элемент строки — вход книги:
              имя элемента — item (непустое), значение — текст JSON-объекта
  entry:      JSON-объект: поле key — непустая строка, поле to — имя члена или список имён; прочие поля — воркера;
              *_secret на любой глубине — секрет (P/06.2 Н1.1; и поле с именем ровно `_secret`, без префикса — сверка М11,
              совпало у реализаций), в строке члена — конверт кольца члена (договор запечатывания) с AAD
              профиля М11/5 Н1.3 at_rest: ключ строки, 0x00, «/<item>» и JSON Pointer секрета в тексте элемента
  shared:     одна строка from у нескольких книг: элемент — вход каждой из них, форма входа — конъюнкция: поле key и
              поле to каждой такой книги (добавлено описью семей; проверяется чтением — у стенда книги читают разные
              строки from)
writer:       воркер своей подсистемы под своим слотом (запись под слотом глава 3.2 Н3, глава 3.4 Н3); права — платформенная
              основа роли (P/02.5 Н1.4: «источники книг домена»); worker.writes не нужен
claim:        захват слота воркером, у которого прежний держатель слота — не этот экземпляр (в том числе по предложению
              запасному, P/04), до первой своей записи удаляет строки под этим слотом по каждому from загруженных спек:
              released := taking → удалить строки по стражу слота → released := false (глава 3.2 Н3); свой повторный захват
              строк не трогает
```

Запись под слотом — [глава 3.2](03.2-worker.norms.md) Н3 «писать_под_слотом» и [глава 3.4](03.4-worker.norms.md) Н3; слот и
`released` — глава 3.2 Н1.4; профиль AAD `at_rest` — [М11/5 Н1.3](../../../М11_Domain/spec/05-books-from-member-rows.norms.md);
конверт кольца — [договор запечатывания](../../common/contracts/sealing.md).

### Н1.5 Токен у воркера и проверка у получателя

Из [М11/7 Н1](../../../М11_Domain/spec/07-worker-tokens.norms.md): Токен воркера — токен домена ([договор токена домена](../../common/contracts/domain-token.md) «Токен», владелец М11/2; разбор ревью стадии B 3–5, В1) с `kind` вида спеки.
Ключ подписи держателя воркеру не выдаётся, ключ члена — тоже: токен просит воркер, которому он нужен, через агента своего
кластера (ADR-0074 доп. (5)). Токен живёт только в памяти воркера: ни в строке, ни в книге, ни в отчёте, ни в журнале, ни в
копии. Просьба — местной дверью агента: [договор местной двери токенов](../../common/contracts/local-token-door.md) (владелец
глава 9.1; сокет `<AGENT_TOKEN_DIR>/<W2C_ROLE>.sock`; разбор ревью стадии A 8–10, № 1 / решение 1).

Получатель — воркер или дверь члена, которому адресован токен. Проверка — функция `token` [договор токена домена](../../common/contracts/domain-token.md) «Проверка» с `expect` (разбор ревью стадии B 3–5, В1):
`kind` — вид, которого он ждёт, `cluster` — свой кластер, `audience_claim` — из объявления вида. Токен, в аудитории
которого нет кластера-получателя, — `wrong_audience`; чужой вид — `wrong_kind`. Дальше получатель сверяет свои
утверждения (`ref_claim` — своя единица, у `scenario` — `acts`); их смысл — подсистемы.

### Н1.6 Переносимые книги, `kept` и воркер подсистемы на домене

```yaml
domain_worker:   воркер подсистемы на держателе, роль <sub>domain (слово secrets.readers — domainworker, P/01.2 Н1.1);
                 один: слот domain/<sub>/worker (аренда — глава 3.2 Н1.4); есть у спеки, где есть kept или переносимая книга
carried_book:    domain.books.<книга>: {} | {show} — строки domain/<sub>/<книга>/<член> у держателя пишет воркер на домене;
                 строку бывшего члена (его нет в списке членов) удаляет процесс domain проходом, как у собираемой
                 (М11/5 Н1.4 write; разбор ревью стадии A 8–10, № 30); доставка, member_row и дверь — как у собираемой (М11/5 Н1.4, Н2)
kept:            domain.kept: [<имя>|<семья>/…] — строки domain/<sub>/<имя> у держателя, пишет воркер на домене; члену не
                 доставляются; domain.tables — какие из kept — таблицы (P/06.1 Н1.6)
door_pass:       /domain/<sub>/<сегмент door.pass> консоли домена → воркеру на домене (М11/8 Н1.7)
heartbeat:       объект domain/<sub>/heartbeat в хранилище объектов держателя (P/05 Н1.1), один на подсистему — пульс
                 воркера на домене формы главы 3.4 Н1.1 (worker, ts, server, url, instance, status …; время — Н0); worker —
                 ровно строка «domain/<sub>/worker», полный ключ его слота (грамматика имени слота главы 3.2 к нему не
                 применяется); пульс с иным worker — не по форме (добавлено сверкой М11, журнал cammeta-go М11-05 № 8;
                 проверяется чтением — стенд не несёт воркера на домене); пишет <sub>domain каждые HEARTBEAT_EVERY и
                 подменой (глава 3.4 Н3); читают domain и domainconsole — url двери door.pass (М11/8 Н1.7 address), пульс
                 не читается, не по форме или не свеж LOST_AFTER — «не слышно» (М11/8 Н1.7 absent); объекты под права
                 хранилища не входят (P/01.2) (стадия A, A3)
```

Учебного воркера на домене у `testsub` стенд не несёт: переносимая книга `tallies` и `kept` проверяются чтением (долг в
ХОД — потребитель стенда).

Слот `domain/<sub>/worker` — по [главе 3.2](03.2-worker.norms.md) Н1.4; пульс — [глава 3.4](03.4-worker.norms.md) Н1.1 и Н3
«подмена()»; доставка, `member_row` и дверь книги — [М11/5 Н1.4, Н2](../../../М11_Domain/spec/05-books-from-member-rows.norms.md);
`door.pass` и `absent` — [М11/8 Н1.7](../../../М11_Domain/spec/08-doors-between-clusters.norms.md); объект — [P/05 Н1.1](../../05-resource/spec/05-resource.norms.md).

## Н2 Двери

Своей двери у главы нет. Воркер пишет вклады и строки домена операциями хранилища
[P/01.1](../../01-store/spec/01.1-store.norms.md) под своим слотом; токен просит местной дверью агента
`POST /tokens/<sub>/<вид>` ([договор местной двери токенов](../../common/contracts/local-token-door.md); вводит глава 9.1); воркер на
домене принимает путь `door.pass` консоли домена ([М11/8 Н1.7](../../../М11_Domain/spec/08-doors-between-clusters.norms.md)).

## Н3 Проход

Захват слота и чистка строк прежнего держателя — Н1.2 `claim`; гонки вклада — [М11/5 Н3](../../../М11_Domain/spec/05-books-from-member-rows.norms.md)
«Гонки» (поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости агента).

### проверить у получателя

```
token (договор токена домена) с expect {kind: <вид>, cluster: <свой кластер>, audience_claim} → ok | refused (… | wrong_kind | wrong_audience)
```

Функция `token` и её шаги — [договор токена домена](../../common/contracts/domain-token.md) «Проверка» (владелец — [М11/2](../../../М11_Domain/spec/02-root-keys-and-revocation.norms.md); разбор ревью стадии B 3–5, В1).

**Гонки.** Назначение, топология или документ меняются после выдачи — токен живёт свой `lifetime`; отзыв — `domain/revoked`
М11/2. Два одинаковых запроса — два токена; память о выданных не нужна.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/03.7-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6). Глава позднего слоя: нормы вводит урок 8, сценарии — в приёмке М11 до его переноса.

- [ ] **P/03.7-01** вклад: строка под слотом, вход-объект, чистка при захвате чужого слота — сц. 01, 04 приёмки М11/05; чистка — чтением (гонка захвата) (часть М11/5-02 по `note` id-map: живость слота с перечиткой — агент, глава 9.1)
- [ ] **P/03.7-02** переносимые книги, `kept`, воркер на домене Н1.6 — проверяется чтением; потребителя стенда нет (долг) (части М11/5-09 по `note` id-map: `domain.kept`, `domain.tables` — P/02.1 Н1.2б; права `kept` — P/02.5)
- [ ] **P/03.7-03** у получателя `wrong_audience`/`wrong_kind` — сц. 01 приёмки М11/07; М11/2 сц. 12
- [ ] **P/03.7-04** токен только в памяти воркера, не в журнале; просит его воркер через агента своего кластера (местная дверь — глава 9.1) — чтением

## Соответствие прежним урокам

Перенесено из М11/5 (стадия B): строки `source_row` (с `entry`, `shared`), `writer`, `claim` Н1.2 (здесь Н1.2); Н1.6 с
абзацем об учебном воркере на домене. Из М11/7: абзац Н1 о токене воркера (со слов «Токен воркера — …»), Н1.5, Н3 «проверить у
получателя» с «Гонками», строка Н4 `wrong_kind`/`wrong_audience`, п. 2 «Решает реализация» (здесь п. 1). Id чеклиста
([id-map](../../common/id-map.tsv)): М11/5-02 → P/03.7-01 (сторона писателя), М11/5-09 → P/03.7-02, М11/7-06 → P/03.7-03,
М11/7-07 → P/03.7-04. Ссылки «урок N» перенесённого текста М11 записаны как «М11/N». Разбор ревью стадии B 3–5, В1: ссылки на М11/2 Н1.6 и Н3
`token` заменены ссылками на [договор токена домена](../../common/contracts/domain-token.md) (владелец — М11/2).
