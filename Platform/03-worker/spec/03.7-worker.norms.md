# P/03.7 — Поздний слой: вклады в книги, воркер на домене, токены: нормы

Канон главы 3.7 урока P/03 «Воркер» (ADR-0080; модуль «Платформа» — ADR-0083). **Глава позднего слоя: вводит урок 8**
([записка модуля](../../module-design.md), «Порядок чтения»: после уроков 8–10); её соседи по контракту — главы урока
[P/08](../../08-domain/README.md), [P/09](../../09-agent/README.md), глава [P/06.7](../../06-console/spec/06.7-console.norms.md) и урок [P/10](../../10-domain-console/spec/10-domain-console.norms.md). [Лекция](../03-worker.md), [инструкция](03-worker.README.md), [жизненный цикл](../lifecycle.md).
Своего HTTP-контракта у урока нет (`P/03 no-openapi`). Каталога приёмки у главы нет (Н5).

Глава перенесена из М11/5 и
М11/7 (стадия B, ADR-0083 доп. (1): без изменения поведения). Из М11/5:
Н1.2 — сторона писателя вклада (`source_row` с `entry` и `shared`, `writer`, `claim`); Н1.6 целиком (воркер подсистемы на
домене, переносимые книги, `kept`, пульс). Из М11/7: абзац Н1 о токене у воркера (просьба через агента, только в памяти),
Н1.5, Н3 «проверить у получателя» с «Гонками», строка Н4 `wrong_kind`/`wrong_audience`, п. 2 «Решает реализация». У вклада
живость слота с перечиткой (`liveness`), вклад в отчёте (`in_report`), `seal_reuse`, `no_seal`, `reports` — агент,
[глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.2; сборка и доставка — [P/08.5](../../08-domain/spec/08.5-domain.norms.md), дверь книги — [глава P/06.7](../../06-console/spec/06.7-console.norms.md)
Н1.1; у токена — дверь держателя, выдача и утверждения — [P/08.7](../../08-domain/spec/08.7-domain.norms.md) (перенос урока 8, стадия B); объявления `domain.books`, `domain.kept`, `domain.tables`,
`domain.tokens` — [P/02.1 Н1.2б](../../02-installer/spec/02.1-installer.norms.md), права `<sub>domain` —
[P/02.5](../../02-installer/spec/02.5-installer.norms.md). Номера подразделов — прежние: Н1.2 и Н1.6 — М11/5, Н1.5 — М11/7.
Ссылка «М11/N» — урок-источник М11 (снят переносами уроков 8–10; новые адреса — id-map); «М10/N» — урок М10; «глава 3.K» — глава этого урока. Id норм —

## Н1 Форма

**Время.** Поля времени главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): пульс
воркера на домене `domain/<sub>/heartbeat` — как пульс воркера ([глава 3.4](03.4-worker.norms.md) Н1.1; Н1.6 `heartbeat`);
`exp` токена — [P/08.7 Н1.4](../../08-domain/spec/08.7-domain.norms.md).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `<sub>/<spec:domain.books.from>`, `<sub>/<spec:domain.books.from>/<слот>`, `domain/<sub>/<spec:domain.kept>`, `domain/<sub>/<spec:domain.kept>/*`, `domain/<sub>/worker`, `domain/<sub>/heartbeat`;
- пишет: `domain/<sub>/<spec:domain.books>/<член>` (put), `<sub>/<spec:domain.witness.report>/<имя>` (put);
- читает: `<sub>/slots/<имя>`, `domain/keys`, `domain/revoked`.

Объект свидетеля `<sub>/<spec:domain.witness.report>/<имя>` (`{ts, cluster, units}`; объявление `domain.witness` спеки —
[P/02.1](../../02-installer/spec/02.1-installer.norms.md) Н1.2б) пишет воркер подсистемы своего кластера; протокол объекта
и его читатель — урок [P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.8 (список тревог; решение
«Архитектора» по планам переноса 8–10, ADR-0083 доп. (14) п. 8: писатель-воркер — участник). Набор `domain/keys` и отзывы `domain/revoked` своего кластера получатель читает для функции `token` [договора токена домена](../../common/contracts/domain-token.md) «Проверка» (Н3
«проверить у получателя») (разбор ревью стадии B 3–5, № 10).

Вклады — под своим слотом, удаление — при захвате чужого слота; свой слот читается перед первой записью вклада;
строки `domain/<sub>/…` пишет воркер подсистемы на домене (роль `<s>domain`): слот, пульс, `kept`, переносимая книга.

### Н1.2 Вклад члена: сторона писателя

Живость слота у агента (`liveness`), вклад в отчёте (`in_report`), `seal_reuse`, `no_seal`, `reports` —
[глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.2.

```yaml
source_row:   строка хранилища члена по from: <sub>/<строка> или <sub>/<строка>/<слот>; элемент строки — вход книги:
              имя элемента — item (непустое), значение — текст JSON-объекта
  entry:      JSON-объект: поле key — непустая строка, поле to — имя члена или список имён; прочие поля — воркера;
              *_secret на любой глубине — секрет (P/06.2 Н1.1; и поле с именем ровно `_secret`, без префикса — сверка М11,
              совпало у реализаций), в строке члена — конверт кольца члена (договор запечатывания) с AAD
              профиля P/08.5 Н1.3 at_rest: ключ строки, 0x00, «/<item>» и JSON Pointer секрета в тексте элемента
  shared:     одна строка from у нескольких книг: элемент — вход каждой из них, форма входа — конъюнкция: поле key и
              поле to каждой такой книги (добавлено описью семей; проверяется чтением — у стенда книги читают разные
              строки from)
writer:       воркер своей подсистемы под своим слотом (запись под слотом глава 3.2 Н3, глава 3.4 Н3); права — платформенная
              основа роли (P/02.5 Н1.4: «источники книг домена»); worker.writes не нужен
claim:        захват слота воркером, у которого прежний держатель слота — не этот экземпляр (в том числе по предложению
              запасному, P/04), до первой своей записи удаляет строки под этим слотом по каждому from загруженных спек:
              released := taking → удалить строки по стражу слота → released := false (глава 3.2 Н3); свой повторный захват
              строк не трогает
```

Запись под слотом — [глава 3.2](03.2-worker.norms.md) Н3 «писать_под_слотом» и [глава 3.4](03.4-worker.norms.md) Н3; слот и
`released` — глава 3.2 Н1.4; профиль AAD `at_rest` — [P/08.5 Н1.3](../../08-domain/spec/08.5-domain.norms.md);
конверт кольца — [договор запечатывания](../../common/contracts/sealing.md).

### Н1.5 Токен у воркера и проверка у получателя

Из М11/7 Н1: Токен воркера — токен домена ([договор токена домена](../../common/contracts/domain-token.md) «Токен», владелец P/08.2; разбор ревью стадии B 3–5, В1) с `kind` вида спеки.
Ключ подписи держателя воркеру не выдаётся, ключ члена — тоже: токен просит воркер, которому он нужен, через агента своего
кластера (ADR-0074 доп. (5)). Токен живёт только в памяти воркера: ни в строке, ни в книге, ни в отчёте, ни в журнале, ни в
копии. Просьба — местной дверью агента: [договор местной двери токенов](../../common/contracts/local-token-door.md) (владелец
глава 9.1; сокет `<AGENT_TOKEN_DIR>/<W2C_ROLE>.sock`; разбор ревью стадии A 8–10, № 1 / решение 1).

Получатель — воркер или дверь члена, которому адресован токен. Проверка — функция `token` [договор токена домена](../../common/contracts/domain-token.md) «Проверка» с `expect` (разбор ревью стадии B 3–5, В1):
`kind` — вид, которого он ждёт, `cluster` — свой кластер (ключ обязателен, не `null`: `null` — только у `kind: person` (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10)), `audience_claim` — из объявления вида. Токен, в аудитории
которого нет кластера-получателя, — `wrong_audience`; чужой вид — `wrong_kind`. Дальше получатель сверяет свои
утверждения (`ref_claim` — своя единица, у `scenario` — `acts`); их смысл — подсистемы.

### Н1.6 Переносимые книги, `kept` и воркер подсистемы на домене

```yaml
domain_worker:   воркер подсистемы на держателе, роль <sub>domain (слово secrets.readers — domainworker, P/01.2 Н1.1);
                 один: слот domain/<sub>/worker (аренда — глава 3.2 Н1.4); есть у спеки, где есть kept или переносимая книга
carried_book:    domain.books.<книга>: {} | {show} — строки domain/<sub>/<книга>/<член> у держателя пишет воркер на домене;
                 строку бывшего члена (его нет в списке членов) удаляет процесс domain проходом, как у собираемой
                 (P/08.5 Н1.3 write; разбор ревью стадии A 8–10, № 30); доставка, member_row и дверь — как у собираемой (P/08.5 Н1.4; P/09.1 Н1.4 member_row; дверь — P/06.7 Н1.1)
kept:            domain.kept: [<имя>|<семья>/…] — строки domain/<sub>/<имя> у держателя, пишет воркер на домене; члену не
                 доставляются; domain.tables — какие из kept — таблицы (P/06.1 Н1.6)
door_pass:       /domain/<sub>/<сегмент door.pass> консоли домена → воркеру на домене (P/10 Н1.6)
door_client:     дверь воркера на домене под TLS принимает door.pass только от клиента роли domainconsole: сертификат
                 клиента, выпущенный ca.pem или ca.next.pem кластера, роль из SAN — domainconsole (договор сертификата роли;
                 клиент — роль domainconsole, P/10 Н1.6); нет сертификата, иной центр или иная роль — 403
                 {"error": "forbidden"}, запрос не исполняется; людей воркер не проверяет — токен человека проверила
                 сторожевая консоли домена (договор токена домена: строки воркера на домене среди проверяющих нет); по HTTP
                 стенда роли нет — проверяется чтением, как X-W2C-Client (договор пересылки «Адрес клиента»)
                 (решение «Архитектора» 2026-10-20 по сверке 3.7)
heartbeat:       объект domain/<sub>/heartbeat в хранилище объектов держателя (P/05 Н1.1), один на подсистему — пульс
                 воркера на домене формы главы 3.4 Н1.1 (worker, ts, server, url, instance, status …; время — Н0); worker —
                 ровно строка «domain/<sub>/worker», полный ключ его слота (грамматика имени слота главы 3.2 к нему не
                 применяется); пульс с иным worker — не по форме (добавлено сверкой М11, журнал cammeta-go М11-05 № 8;
                 проверяется чтением — стенд не несёт воркера на домене); пишет <sub>domain каждые HEARTBEAT_EVERY и
                 подменой (глава 3.4 Н3); читают domain и domainconsole — url двери door.pass (P/10 Н1.6 address), пульс
                 не читается, не по форме или не свеж LOST_AFTER — «не слышно» (P/10 Н1.6 absent); объекты под права
                 хранилища не входят (P/01.2) (стадия A, A3)
```

Учебного воркера на домене у `testsub` стенд не несёт: переносимая книга `tallies` и `kept` проверяются чтением (долг в
ХОД — потребитель стенда).

Слот `domain/<sub>/worker` — по [главе 3.2](03.2-worker.norms.md) Н1.4; пульс — [глава 3.4](03.4-worker.norms.md) Н1.1 и Н3
«подмена()»; доставка — [P/08.5 Н1.4](../../08-domain/spec/08.5-domain.norms.md); `member_row` — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4, дверь книги — [P/06.7 Н1.1](../../06-console/spec/06.7-console.norms.md);
`door.pass` и `absent` — [P/10 Н1.6](../../10-domain-console/spec/10-domain-console.norms.md); объект — [P/05 Н1.1](../../05-resource/spec/05-resource.norms.md).

## Н3 Проход

Захват слота и чистка строк прежнего держателя — Н1.2 `claim`; гонки вклада — [P/08.5 Н3](../../08-domain/spec/08.5-domain.norms.md)
«Гонки» (поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости агента).

### проверить у получателя

```
token (договор токена домена) с expect {kind: <вид>, cluster: <свой кластер>, audience_claim} → ok | refused (… | wrong_kind | wrong_audience)
```

Функция `token` и её шаги — [договор токена домена](../../common/contracts/domain-token.md) «Проверка» (владелец — [P/08.2](../../08-domain/spec/08.2-domain.norms.md); разбор ревью стадии B 3–5, В1).

**Гонки.** Назначение, топология или документ меняются после выдачи — токен живёт свой `lifetime`; отзыв — `domain/revoked`
([договор набора ключей домена](../../common/contracts/keys.md) «Отзывы»). Два одинаковых запроса — два токена; память о выданных не нужна.
