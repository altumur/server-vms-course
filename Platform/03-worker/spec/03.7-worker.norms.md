### Н1.5 The token at the worker and the check at the recipient

<!-- req: P/03.7-R009 -->

The local policy selector is [`token-cache.machine.yaml`](../forms/token-cache.machine.yaml), with its [traces](../forms/token-cache.traces.tsv) and [effect boundary](../forms/README.md#worker-policy-machines). Capture, IO and cryptography still follow the ordinary procedures below.


From М11/7 Н1: A worker's token is a domain token ([domain token contract](../../common/contracts/domain-token.md) «Токен», owner P/08.2; review of stage B 3–5, V1) with `kind` of a kind of the manifest.
The holder's signing key is not handed to the worker, nor is the member's key: the token is requested by the worker that needs it, through the agent of its own
cluster (ADR-0074 addendum (5)). The token lives only in the worker's memory: not in a row, not in a book, not in a report, not in the log, not in a
copy. There is one exception — a kind with `keep: true` of the manifest (ADR-0110 addendum (9)): the worker also holds the token as the file `<worker state dir>/tokens/<kind>-<sha16(ref)>`, mode 0600, in an envelope of the sealing contract with the context of this path; the owner of the file is the kind, not the camera. At start it reads it, to work while the domain is silent. The term is judged by the receiver, not by the box clock: an expired file is not thrown away but is replaced after the refusal `expired`; the envelope did not open — as if there were no file. A new token replaces the file only after the first request accepted with it, until then both are in memory; while it holds a token with `current` it does not request; `unknown_key` on a token with `current` — it waits rather than requests (ADR-0110 addendum (10) items 5, 6). Such a token does not go into a row, a book, a report or the log either. The limit: theft of the box gives this token until revocation. The request is by the local door of the agent: [local token door contract](../../common/contracts/local-token-door.md) (owner
chapter 9.1; socket `<AGENT_TOKEN_DIR>/<W2C_ROLE>.sock`; review of stage A 8–10, № 1 / decision 1).

<!-- req: P/03.7-R010 -->

The recipient is the worker or the door of the member to which the token is addressed. The check is the function `token` of the [domain token contract](../../common/contracts/domain-token.md) «Проверка» with `expect` (review of stage B 3–5, V1):
`kind` — the kind it expects, `cluster` — its own cluster (the key is required, not `null`: `null` — only with `kind: person` (the Architect's decision of 2026-10-20, ADR-0083 addendum (14) item 7; review of stage A 8–10)), `audience_claim` — from the declaration of the kind. A token in whose audience
there is no recipient cluster is `wrong_audience`; a foreign kind is `wrong_kind`. Then the recipient checks its own
claims (`ref_claim` — its own unit, for `scenario` — `acts`); their meaning is the subsystem's.

### Data families (built from the standard files)

The form of the rows and objects that the chapter owns by the [catalog](../../common/data/catalog.tsv) is the JSON Schema 2020-12 of the family (ADR-0092). An instance of a row is `{key, row}`, of an object `{key, object}`; the key is the grammar of the column `key` of the catalog. The fields of `row` are the values of `items` after the [codec](../../common/data/codec.tsv): the writer checks the schema and its `$defs.writer`, the reader the schema (layer 3 — the words `x-*` of the schema). Unreadable — the row did not decode or did not pass the schema in the reader's mode; the outcome is by the table of outcomes of the family: the path is a prefix of the path of the refusal (empty — the whole row); with several paths of refusal the outcome of the least priority applies.

<!-- req: P/03.7-R018 -->

**Races.** The assignment, the topology or the document change after the issue — the token lives its `lifetime`; a kind with `keep: true` is revoked by `DELETE /domain/issued` through `domain/revoked`, a kind without `keep` lives until `exp`: the limit
([domain key set contract](../../common/contracts/keys.md) «Отзывы»). Two identical requests — two tokens; no memory of the issued ones is needed, except for a kind with `keep: true`: the row `domain/issued` (P/08.2 Н1.6а). On a refusal `revoked` to a token of such a kind the worker requests a new one with the word `revoked: <jti of this token>` (the local door contract), otherwise a circle of refusals for years. An answer with the same `jti` (the word is not executed: `REVOKED_WORDS`, the row `domain/revoked` at 80 %, P/08.2 Н1.6а) — the worker does not request again until the end of the day by its own clock, the log: the rule is common for a worker of any kind with `keep`, otherwise a worker outside `cam`, `rec` goes into the circle request → the same token → `revoked` (ADR-0110 addendum (23) item 2).
