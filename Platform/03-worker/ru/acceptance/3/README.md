## Стенд и шаги главы

Границы каждого сценария — границы [стенда процессов testsub](../../../../common/ru/acceptance/testsub-stand.md#стенд-процессов-testsub). Своё для главы:

- роль чтения хранилища имеет полные права на `testsub/` и `testsub2/` (выше); дверь `admin` готовит строки сц. 25 и 35 мимо их писателей;
- у каждого воркера коробка и сервер стенда; имя передаётся подстановкой `{name}` директивы (общий README приёмки, «Стенд»; разбор ревью стадии B 3–5, № 33);
- выбранные `CAPACITY`/`WORKER_MEMORY_MB` удовлетворяют N1.2 главы 3.4: убывающий бюджет памяти не провоцируется;
- `@start` подтверждает запуск процесса, не его жизнь; готовность слота проверяет следующий `@until`.

Сравнение — «Ожидание» [словаря](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей) с полной формой по
двери. Сценарии наблюдают строки и HTTP-ответы, не содержимое объектов пульса и не фактические внешние записи единицы;
смена эпохи или назначения сама не доказывает, что старый процесс перестал работать. Остальные свидетельства — N5 норм
главы, «Свидетельства вне TSV».

## Не судится в этом уроке

- Отсутствие роста счётчика 06-deleted между удалением и новым назначением: сценарий кончается новым назначением и
  epoch 2, а TSV не наблюдает внешних записей единицы; остановка удалённой единицы — порядок N3 цикла (шаг 2), и
  швы [главы](../../../acceptance/3/seams.tsv) его не исполняют; проверяется чтением N3 и N5 норм.

## Сны (`@sleep`, ADR-0080 доп. (17) п. 4)

Общий смысл `@sleep` и `@until` задан [общим протоколом стенда](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей). Шаги ожидания, длительности и причины конкретных сценариев хранятся в [инструкциях случаев только для судьи](sleeps.cases.md).

Тесты SDK над швами — [seams.tsv](../../../acceptance/3/seams.tsv); договор адаптера — [forms/README.md](../../forms/README.md). Они дополняют сценарии процесса, не меняют указанные выше счёты и не заменяют свидетельство чтением, которое не исполняют.
