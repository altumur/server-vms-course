## Предел соединений двери

Сценарий `38-door-per-address` (6 шагов) запускает ресурс и воркер `testsub2 t-1` с объявленной дверью `read/play`; контроллера и единиц нет. Дверь `worker t-1` — `url` из пульса этого процесса, а не дверь консоли и не подставной воркер. `@hold worker t-1 8` подтверждает восемь одновременно живых принятых сокетов этой группы процессов. Следующие два HTTP-запроса с того же адреса источника проверяют `503 {"error":"busy"}` и точное значение `Retry-After: 1`.

[Общие правила `@hold`](../../../../common/ru/acceptance/command-tables.md#удержание-соединений) действуют до и во время обоих запросов: потеря удерживаемого сокета или независимого наблюдения даёт `stand`, не расхождение реализации. Срок заголовков 5 с остаётся действующим; стенд не продлевает его. Предел 32 соединения не проверяется этим сценарием: у формата нет средства источника для нескольких адресов, а с одного адреса первым действует предел 8. Предел 32 проверяется чтением.

## Стенд и шаги главы

Границы каждого сценария — границы [стенда процессов testsub](../../../../common/ru/acceptance/testsub-stand.md#стенд-процессов-testsub), включая
остановку `@sigterm` и `@sigkill`: шаг совпадает только после выхода всей группы процессов. Своё для главы:

- роль чтения хранилища имеет полные права на `testsub/` и `testsub2/` (выше); дверь `admin` кладёт полку сц. 37;
- у каждого воркера коробка и сервер стенда; имя передаётся подстановкой `{name}` директивы (общий README приёмки, «Стенд»; разбор ревью стадии B 3–5, № 33);
- выбранные `CAPACITY`/`WORKER_MEMORY_MB` удовлетворяют N1.2 главы: убывающий бюджет памяти не провоцируется;
- `@start` подтверждает запуск процесса, не его жизнь; готовность слота проверяет следующий `@until`.

Сравнение — «Ожидание» [словаря](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей) с полной формой по
двери. Сценарии наблюдают строки, HTTP-ответы и названные поля пульса через дверь ресурса; сц. 38 также наблюдает принятые сокеты воркера. Фактические внешние записи единицы не наблюдаются.

## Швы SDK главы

Случаи, которым нужны скриптовые часы, порядок вызовов или ответы хранилища, — строки [seams.tsv](../../../acceptance/4/seams.tsv) и швов
[главы 3.1](../../../acceptance/1/seams.tsv) через порты [forms/README.md](../../forms/README.md#швы) (судья исполняет их по протоколу адаптера швов общего README приёмки):

| Предмет | Швы |
|---|---|
| порядок остановки по SIGTERM: единицы, закрытие писателей места, последний пульс, место отпущено до отдачи слота (сц. 37 видит только обе записи); падение ничего не пишет | `s1-stop-order`, `s2-crash-no-hooks` главы 3.1 |
| срок остановки (P/03.4-18): медленный `stop_unit` на скриптовых часах, запись, отдающая слот, отправлена не позже `WRITE_WINDOW` после момента отправки последнего подтверждённого запроса | `s3-stop-slow-unit`, `s4-stop-two-slow-units` главы 3.1 |
| подмена у соседей STALL и FOR, её строгое место, без оживления отсечённого держателя | `s1`, `s2`, `s7`–`s13` |
| бюджет памяти и базовый пульс | `s3`–`s6` |
| частота пульса (не больше ⌊seconds / HEARTBEAT_EVERY⌋ + 1 записей) и отсутствие записей у никого | `s14-lease-run-live`, `s15-lease-run-nobody` |
| повтор записи под слотом после `ambiguous` и после `unavailable` тем же id (P/03.4-07) | `s16-slot-write-ambiguous-replay`, `s17-slot-write-unavailable-replay` |

SDK-швы s8–s13 проверяют соседей STALL и FOR через прежний worker-stand-in. При age <= STALL нет действий подмены; при STALL < age <= FOR видны продление слота до подтверждения и повтор пульса без watchdog/выдачи эпох. После FOR больше нет такой подмены, действует прежнее done. s13 не запрещает записи штатной завершающей очистки: он наблюдает отсутствие продления-подтверждения, выдачи эпох и watchdog, не новый порт done.

## Не судится в этом уроке

- Содержимое пульса сц. 03 и его первая запись до первого прохода: сц. 03 не читает объект пульса; частота — шов
  `s14-lease-run-live`, последний пульс после остановки единиц — шов `s1-stop-order`, его `status: []` — шаги 05/14–15
  [приёмки главы 3.6](../6/README.md); первый пульс до первого прохода проверяется чтением N1.1 `cadence`.
- Допуск сервера до замка присутствия: как в [приёмке главы 3.2](../2/README.md#не-судится-в-этом-уроке).
- Вызов остановки, который не возвращается: процесс завершает менеджер юнитов по `worker.stop_timeout` (P/02.4 N1.1), этап системы;
  значение `worker.stop_timeout` — п. 3 «Решает реализация» норм.
