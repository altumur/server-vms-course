# Формы P/03 и швы SDK

Текст производный от `forms/README.md`, руками не правится: источник — английский [`forms/README.md`](../../forms/README.md), правка идёт в него, русский пересобирается переводом.
Формы выражают существующие нормы воркера. У SDK не появляется нового бинаря или HTTP API.

## Входы процесса

[daemon-flags.tsv](../../forms/daemon-flags.tsv) сохраняет восемь колонок P/01. `$NAME` — значение окружения, `<name>` — необязательный
аргумент имени слота обычного воркера; `commands` — `worker` и/или `domainworker`. У доменного воркера фиксированный слот по 3.7 N1.6, без этого аргумента. Адаптер читает динамическую переменную, названную в `slot.name_env` манифеста,
только при отсутствии аргумента. Форма не превращает её в фиксированное имя окружения или опцию команды.

Типы — словарь P/01 и `string`. `default` — литерал либо `-`, когда буквального значения нет; `default_text` сохраняет правило
вычисляемого значения, например короткое имя хоста или `file://<PLATFORM_DIR>/config`. Правило реализуется по `norm`, его нельзя копировать
как буквальное значение. Адаптер передаёт SDK вычисленные внешние умолчания. CEL `required` и `bad` используют карту `f` с точными именами
входов и строку `cmd`. Проверки парных имён выполняются над переданными значениями до умолчаний. Пустая `bad` не добавляет проверки CEL
и не заменяет проверку договора: экземпляр/коробка, метки, адреса, роль, ёмкость и динамическое имя проверяются по указанным нормам.
Тип пути или id члена не заменяет грамматику экземпляра. Файлы окружения читает запускатель; SDK не должен читать их повторно.

## Собственные скалярные уставки

[runtime-constants.tsv](../../forms/runtime-constants.tsv): name/value/unit/norm/meaning, положительное JSON integer до int64; единицы count/s/ms/bytes. WAKE_GAP_MS, PERFORM_GRACE_MS и REQUESTS_HOLD_MS переводятся в секунды точным /1000. Чужие значения — ссылки на владельцев, производные сроки — формулы, ROAD_BUCKETS остаётся типизированным списком в N1.1 главы 3.4; числа независимых граничных свидетелей не подставляются из тестируемой функции.

## Отказы

Колонки [refusals.tsv](../../forms/refusals.tsv): `chapter row name surface code kind fields headers log norm word cause outcome diagnostic caller`.
Разделитель — буквальный TAB, без CSV-кавычек. Первые десять колонок — P/01. `row` идёт подряд внутри главы, в порядке файла. Последние пять колонок — нормативные ячейки: строки из четырёх ячеек —
cause/outcome/diagnostic/caller, 3.7 — word/outcome/cause. Строки 1–11 главы 3.2 несут ячейку кода в outcome (длинное тире — кода нет)
и ячейку тела в diagnostic. Строка, в ячейке кода которой нет числового кода, остаётся отказом. `-` — нет ячейки или дополнительной машинной проекции.

`start` — отказ старта, `process` — работающий процесс, `call` — результат библиотеки, `peer` — договор чужой двери. `code` — фиксированный
HTTP-код, `exit N`, `exit !0` либо `-`; условный код остаётся в нормативной ячейке outcome. `kind` — `-`: чужой `error` не становится
схемой HTTP Fault воркера. Слово диагностики не вводит отсутствующий в норме формат stdout/stderr. N4 ссылается на форму без второй таблицы.

## Машина захвата

[slot-capture.tsv](../../forms/slot-capture.tsv) — машина 3.2 N3 «захватить». Шапка объявляет закрытые состояния и действия, типизированные
входы CEL и TORN_STILL. Выполняется только первая подходящая строка текущего состояния. Действие `-` — YOURS по `norm`, которое должно
закончиться до следующего события; это не отсутствие действия. Часть пакета `slot-capture` генерирует допуск и выбор перехода, вызывается из `core`. Перебор кандидатов, вывод
исходов чтения, проверка полного ключа, кодек items, id логической записи и очистка под guard — процедуры по их якорям. Неответ не является
отсутствием. Повторы одной логической операции сохраняют id и момент первой отправки. first_start_right — право, доступное на момент
подтверждённого чтения этого кандидата; расходование права не должно уничтожать проверяемое здесь исключение. Воссоединение его не восстанавливает.

## Швы

`acceptance/K/seams.tsv` (только для судьи: тесты швов SDK) имеет четыре колонки сценариев и последнюю строку шапки-комментария `# scenario TAB step TAB request TAB expect`.
Это stagetests пакета над SDK, отдельно от сценариев процесса `scenarios.tsv` главы (только для судьи: приёмка процесса); судья исполняет их по [протоколу адаптера швов](../../../common/ru/acceptance/seams.md#протокол-адаптера-швов). Каждый сценарий начинает настоящий SDK заново с управляемыми
клиентами хранилища/объектов, монотонными и настенными часами и записывающей подсистемой. Адаптер вызывает реализацию, нормализует результат
и записывает эффекты. Ответ из ожидаемого результата запрещён. Имена портов и JSON — нормализация тестов, не обязательный API SDK.

`CALL <name> <JSON>` принимает одно значение JSON; ожидание — по общим правилам приёмки JSON (пустой список пуст, `{}` — ровно пустой
объект). Проверяются только названные поля. Нормальный отказ нельзя получать перехватом panic или постороннего исключения. `@parallel K`,
`@clock +/-N`, `@file`, `@read`, если используются, — грамматика README форм P/02 и проверяющего кода курса. Оболочка не исполняется.

Адаптер дополняет фон до вызова SDK: допустимый манифест `testsub` с prefix `w` (порт открытия берёт опубликованный манифест testsub2 и допустимую строку tally по явному ключу testsub2), допустимая схема, слот, владение, назначение `u1` и
работающая аренда там, где они нужны порту. Явный вход заменяет фон; пропуск не означает неподтверждённое чтение. null слота — подтверждённое
отсутствие; `reply: unavailable` — неизвестный исход чтения. Частичные метки/строки заменяют поля допустимого фикстурного экземпляра своего
вида, а не подают нечитаемый JSON как случайную вторую ошибку. `self` — этот экземпляр. `slot` содержит проводной `{index,items}`;
остальные нормализованные числовые эпохи и поколения — декодированные значения. Версии непрозрачны. События подаются по порядку; их имена
не добавляют операций процесса. Счётчики наблюдаются с нового старта.

Нормализация фона относится только к SDK CALL: положительная обычная unit/tally fixture содержит id и нынешний 32-hex born. Частичные логические row/mark аргументы накладываются на неё; это не замена отсутствующего born в сырой строке. Явные wire-строки slot {index,items} полны: отсутствующее поле items остаётся отсутствующим. Текст family-read — также полный сырой вход, его не дополняют и не чинят.

Скриптовые ответы хранилища (`first_write_replies`, `final_write_replies`, `cleanup_replies`, `write_replies`, `issue_replies`, `reply`) — слова, по одному на каждый запрос, посланный этой операцией, по порядку; запрос сверх перечисленных слов получает `ok`. `ok` — запись применена, чтение отвечает фикстурой; `again` — повтор того же id отвечен его первым ответом (P/01.1, `again`); `guard` — 412 `guard`; `unavailable` — ответа нет; `ambiguous` — 503 `ambiguous`, исход неизвестен; `badkey` — 400 `badkey` P/01.1 N4, определённый отказ этой операции (P/03.2 N3 «Full keys and store refusal»). `replay_same_id` истинно, когда за каждым ответом `unavailable` или `ambiguous` одной логической записи следует хотя бы один повтор этой логической записи и каждый запрос, посланный после такого ответа, несёт id и сохраняет момент первой отправки этой логической записи (P/03.4-07, P/03.2 N1.6). Оно ложно, когда за таким ответом нет повтора, когда повтор несёт другой id или другой момент первой отправки и когда операция такого ответа не получила. Определённый ответ повтора не требует. Адаптер выводит эти наблюдения из записанного IO хранилища.

Швы дополняют свидетельства чтением. Они не снимают чеклист и не закрывают сценарий процесса, доменный стенд, случай открытия без ключа,
писателя места или гонку OS presence-lock, которые не исполняют. План этапов называет их тестами пакета; сценарии процесса урока остаются работой судьи.

### worker-reconcile JSON

Вход — объект. Поля ниже обязательны, если не названы необязательными. Частичные объекты единиц дополняют обычную фикстуру, описанную выше; перечисленные поля сохраняют переданные значения. Идентичность единицы, ревизия, эпоха и поведение аренды следуют P/03.2-R212, P/03.2-R213, P/03.2-R214, P/03.2-R215, P/03.2-R216, P/03.2-R217, P/03.2-R218, P/03.2-R044, P/03.2-R220, P/03.2-R045, P/03.2-R224, P/03.2-R226, P/03.2-R227, P/03.2-R229, P/03.2-R230, P/03.2-R231 и P/03.3-R033–P/03.3-R035.

| Поле входа | Тип JSON и смысл |
|---|---|
| `current` | Объект с `id` (строка), `born` (строка), `revision` (целое число) и `epoch` (целое число): работающая единица и идентичность её принятого старта. |
| `desired` | Объект с `id` (строка), `born` (строка) и `revision` (целое число): желаемая строка единицы. |
| `lease` | Строка `confirmed` или `silent`: подготовленное состояние аренды. |
| `assignment_confirmed` | Булево значение: желаемое назначение подтверждено успешным чтением. |
| `may_write`, `may_act` | Необязательные булевы значения, переопределяющие соответствующие предикаты скриптовой аренды; при отсутствии их задаёт подготовленная аренда. |

Результат — объект со всеми полями ниже. Адаптер записывает настоящие записи выдачи эпох и вызовы подсистемы; итоговую принятую ревизию и состояние аренды читает у реализации. Порядок массивов — порядок вызовов.

| Поле результата | Тип JSON и смысл |
|---|---|
| `epoch_issues` | Неотрицательное целое число: число новых выдач эпохи. |
| `stop_calls` | Неотрицательное целое число: число вызовов `stop_unit`. |
| `stop_restarting` | Массив булевых значений, по одному на вызов `stop_unit`: действует ли для этого вызова слово подсистемы `restarting(id)`. |
| `start_epochs` | Массив целых чисел: эпоха, переданная каждому принятому вызову `start_unit`. |
| `observed_revision` | Целое число: принятая ревизия после согласования. |
| `lease` | Строка `confirmed` или `silent`: итоговое состояние аренды. |

### worker-retry JSON

Вход — объект с обязательными полями `unit` (строка), `failure_count` (неотрицательное целое число), `at_max` (булево значение: начальная пауза повтора достигла RETRY_MAX) и `events` (упорядоченный массив строк). Закрытый словарь событий: `assignment-unavailable` (чтение назначения не получило ответа), `move` (единица перемещена), `fence` (единица отсечена), `name-change` (воркер сменил имя) и `assignment-absent-confirmed` (успешное чтение назначения подтверждает отсутствие единицы). Эти события проверяют классификацию и обнуление счёта по P/03.3-R025, P/03.3-R028; они не подменяют неудачи запуска.

Результат — объект с обязательными полями `counts_before_absence` (массив неотрицательных целых чисел), `failure_count` (неотрицательное целое число) и `stalled` (булево значение). `counts_before_absence` записывает счёт после каждого события до первого `assignment-absent-confirmed`, в порядке событий; если такого события нет — после каждого события. Само событие подтверждённого отсутствия и все последующие события в этот массив не входят. `failure_count` и `stalled` — итоговые наблюдаемые счёт и состояние повтора после всех событий. Адаптер читает эти значения из настоящего состояния повторов, не выводит их только из имён событий.

### worker-holder-group JSON

Вход — объект с обязательными полями `group` (строка) и `events` (упорядоченный массив строк). Фикстура готовит две иначе допустимые просьбы этой группы в одной эпохе процесса-держателя. Идентификатор просьбы — непустой остаток после первого двоеточия; та же строка обозначает ту же просьбу на всей трассе. Закрытые формы событий:

| Форма события | Вмешательство |
|---|---|
| `begin:<request>` | Допустить названную просьбу через настоящий путь держателя и оставить её вызов устройства незавершённым. |
| `timeout:<request>` | Доставить таймаут названного вызова, пока его вызов устройства остаётся незавершённым. |
| `observe:<request>` | Сделать названную допустимую просьбу видимой держателю. |
| `look` | Выполнить обычный взгляд держателя на видимые просьбы. У этого события нет двоеточия и остатка с просьбой. |
| `return:<request>` | Завершить названный незавершённый вызов устройства. |

Результат — объект с обязательными полями `calls_before_return` (массив строк: идентификаторы просьб, для которых настоящие вызовы устройства отправлены до первого `return:<request>`), `calls_after_return` (массив строк: отправленные после этого события) и `max_unfinished` (неотрицательное целое число: максимум одновременно незавершённых вызовов устройства). Каждый массив сохраняет порядок отправки вызовов. Таймаут оставляет вызов устройства незавершённым до `return:<request>`; адаптер измеряет настоящее перекрытие по P/03.6-R162, P/03.6-R163, P/03.6-R164, P/03.6-R165, P/03.6-R167, P/03.6-R168, P/03.6-R169, P/03.6-R170, P/03.6-R171, P/03.6-R172.


## Дополнительные границы швов

Границы ниже дополняют те же порты и [швы](../acceptance/2/seams.tsv) (только для судьи: тесты швов SDK главы 3.2); процессные команды или HTTP API не вводятся. Все остальные швы и процессные сценарии остаются обязательными.

Адаптер захвата получает gen_readable по кодеку/области самого поля поколения независимо от других полей слота, до сужения. row_readable отдельно проверяет слот целиком. Подтверждённое отсутствие — отдельный случай с операндом 0. Существующий gen в 1..9007199254740991 читаем, но gen_incrementable истинен лишь ниже максимума. Вне диапазона — существующий нечитаемый gen, исходные байты сохраняются. При false машинный gen=0 — неиспользуемая заглушка. generation_exhausted остаётся для читаемого максимума у иначе допустимого кандидата; допуски NameOnAnotherBox/torn-young не обходятся. Для нечитаемого поколения нового программного слова unreadable нет, поскольку word каталога не задан.

worker-grant сначала проверяет существующую epoch в нынешнем положительном диапазоне, с прежним EpochUnreadable для повреждения. В существующих CALL epoch=0 обозначает только подтверждённое отсутствие; stored-zero отдельно отрицателен в family-read. Floor читается по форме P/01.3 и сравнивается точно, в том числе за int64; его область не становится областью epoch. Невозможная следующая выдача даёт прежние issue_writes=0/launch_calls=0 до записи и без повтора заведомо недопустимого числа.

worker-base-heartbeat вызывает обычный построитель базового heartbeat без переопределений подсистемы. Возвращает декодированные schema/build/pending_writes, используя SCHEMA и BUILD, pending_writes нулевой. worker-stand-in с strict_place=true устанавливает настоящую фикстуру одного удерживаемого разрешённого strict-места и наблюдает её CAS под guard слота. Записи вкладов/состояния считаются отдельно; такие публикации не разрешаются.

worker-contribution-cleanup загружает два настоящих корректных манифеста разных подсистем с тем же именем слота. own_from задаёт каждый объявленный источник книг собственного манифеста (две реальные строки); foreign_from — живой чужой вклад. Исполняется обычный путь taking/уборки под guard/final-live. Результат считает чтения/удаления вкладов по подсистемам из записанного IO и напрямую проверяет чужую строку после прохода. Чтение каталога манифестов не является чтением чужого вклада. Заготовленный ответ или модель уборки не заменяют этот шов.

worker-holder-takeover запускает две эпохи процессов-держателей и настоящий заблокированный callback действия. Записываются настоящая трасса незавершённых вызовов и смены держателя/эпохи в полях old_call_unfinished_after_wait, cross_holder_exclusion_proven_by_wait и witness. Адаптер выводит наблюдения из управляемой трассы IO/callback, не возвращает константы. Шов не требует отправки B в самый ранний разрешённый момент: более сильный барьер/ограждение может отложить или отвергнуть её. Отмечается, почему одно фиксированное ожидание не даёт междержательного исключения; однодержательный s4 сохраняет максимум одного незавершённого вызова. Нового вида тревог/событий нет.

worker-token-cache различает локальный now и verification.now получателя. Считаются настоящие запросы нового токена и замены кеша, проверяется сохранение current. Проверка подписи сохранена; локальные часы не подменяют исход получателя.

## Автоматы политик воркера

Действующий класс машин используют [`contender-writer.machine.yaml`](../../forms/contender-writer.machine.yaml) с
[`contender-writer.traces.tsv`](../../forms/contender-writer.traces.tsv) (только для судьи: эталонные трассы) и [`token-cache.machine.yaml`](../../forms/token-cache.machine.yaml)
с [`token-cache.traces.tsv`](../../forms/token-cache.traces.tsv) (только для судьи: эталонные трассы). Поля norm называют P/03.2-R012, P/03.2-R121, P/03.2-R123, P/03.2-R125, P/03.2-R128, P/03.2-R233, P/03.2-R234 и
P/03.7-R009, P/03.7-R055, P/03.7-R056, P/03.7-R057, P/03.7-R058, P/03.7-R059, P/03.7-R060, P/03.7-R106, P/03.7-R107. Одна строка transitions — один упорядоченный переход; from/to ссылаются только на states, initial —
одно состояние, terminal — явное подмножество без исходящих переходов. Дополнительного KIT_PART нет.

Файлы объявляют типизированные events, переменные и аргументы действий. Аргументы действий записаны отображением имя → тип, позиционные аргументы вызова идут в порядке этих объявлений; payload события — отображение по именам. Замкнутые типы: bool, int (int64), double, number, string, dyn, null, object, array, `list<T>`, `map<string,T>`, объединение через | и объявленные в types записи. Внешнее событие имеет ровно названные
поля payload. Имена событий input и advance относятся к оболочке трассы, остальные объявлены в events.
const содержит только собственные конечные JSON-константы машины. timers у этих двух политик пуст: периодичность, чтение стенных
часов и вычисление собственного календарного дня — входы от обычного ядра. Таймеры и константы rollout не подразумеваются.
Общий исполнитель также принимает объявленные таймеры every/after от явного выражения часов (либо s0) и таймер
after_io явно названного IO-действия; payload типизированного события таймера задаётся CEL-выражениями. События таймеров
создаёт исполнитель, не внешняя трасса. Терминальное состояние останавливает все переходы и таймеры.

Действие без IO одновременно присваивает CEL-выражения объявленным переменным. Действия исполняются в порядке строки;
аргументы действия видят присваивания предыдущих действий этого перехода. Действие с io выбирает обычный
эффект ядра: эталонная трасса записывает io, объявленное имя действия и JSON-массив вычисленных аргументов.
Эталон не исполняет IO. Проверки io=[...] сравнивают полный упорядоченный список за шаг, в том числе пустой,
запрещающий непредусмотренный IO; `var.<name>=JSON` сравнивает переменную. TSV имеет literal TAB ячейки и LF строки;
Unicode U+2028 внутри JSON-строки — данные, а не граница строки.

Для contender-writer вызывающий передаёт настоящие исходы захвата/потери и NameOnAnotherBox. Форма выбирает
state/since/at и существующие события эпизода name_taken/name_back; она не захватывает слот и не строит
снимок держателя. Настоящий допуск захвата, расписание CONTEND_EVERY, полный объект претендента и его запись
остаются за обычным ядром и семьёй данных. since не начинается заново лишь от перевода стенных часов
назад. У формы 8 трасс: первый поиск, приоритет чужой коробки, отсутствие метки при выводе сервера, отсутствие записи
раньше due, смена состояний и повторные эпизоды потери/возврата.

Для token-cache охват — вид с keep:true и один ref работающего воркера. Handles и JTIs ссылаются на настоящие
разобранные токены, не помещая байты токена в форму или трассу. Заменой управляют ответы получателя, не локальный exp;
unknown_key ждёт, отозванный токен передаёт точный JTI, ответ с тем же JTI ждёт до конца этого собственного дня. Машина
выбирает persist лишь после первого принятого запроса с кандидатом. persist — намерение IO, не подтверждение
завершённой записи файла: sealing, путь/контекст, mode0600, ошибки IO, повторы и порядок записей остаются за
обычным писателем файла по норме. Это существующие эффекты и места вызова ядра; новая команда токена не объявляется.
У формы 12 трасс с положительным приёмом и отрицательными путями unknown-key, ранней записи, того же дня и устаревшего ответа.
