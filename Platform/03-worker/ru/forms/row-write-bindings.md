# Привязки записи строки состояния

Текст производный от `forms/row-write-bindings.md`, руками не правится: источник — английский [forms/row-write-bindings.md](../../forms/row-write-bindings.md); русский пересобирается переводом, для людей, в выгрузку не входит. [row-write-bindings.tsv](../../forms/row-write-bindings.tsv) — нормативная таблица конструктора P/03.6-R018, P/03.6-R128, P/03.6-R192.

## Грамматика

Шапка с буквальными TAB — write,key,field,source,value,guard_key,guard_version,norm. Строка связывает одно непосредственное свойство items. write соответствует [a-z][a-z0-9-]* и группирует конструктор; (write,field) уникально. key/guard_key/guard_version одинаковы во всех строках одного write. field — JSON Pointer RFC 6901 к одному непосредственному свойству схемы строки. Шаблон ключа выбирает ровно одно существующее семейство каталога; обязательные свойства покрыты, чужие запрещены. Кодеки свойств берутся из схемы и codec.tsv: конструктор не вводит кодеки и не переводит версию в binary64.

source — start | input | const. Для start/input value — непустой JSON Pointer с / в неизменяемый снимок старта или вход данного вызова. Для const value — одно строгое JSON-значение; например "" — пустая JSON-строка. Нет выражений, преобразований, fallback или повторного чтения. Отсутствующий указатель — ошибка вызова, не неявный ноль или null.

#start /pointer type и #input /pointer type объявляют пути источников на файл. Типы — string | boolean | integer | number | object | array | dyn. Это JSON-значения до кодека items; integer точен. В файле один контракт неизменяемого снимка старта; input его не заменяет. Ограничения полей сохраняются в схеме семейства и контракте снимка.

key и guard_key состоят из буквальных сегментов и {start:/pointer} / {input:/pointer}. Placeholder занимает целый сегмент и ссылается на объявленную строку. При вызове значение непусто и состоит из одного сегмента; URL-кодирования нет. Неизвестная ссылка, отсутствие, чужой тип или слэш в подставленном сегменте — ошибка до IO. Это не CEL и не shell-шаблон. guard_key может быть -.

guard_version — start:/pointer или input:/pointer к объявленной точной строковой версии P/01 либо -. Отсутствие guard означает - в обеих колонках guard_key и guard_version; иначе обе заполнены. Версия переносится точно, без арифметики и чтения текущей версии. norm — список существующих req-якорей урока через запятую.

## Конструктор state

[Четыре строки](../../forms/row-write-bindings.tsv) выбирают семейство `<sub>/state/<name>/<unit>`. start несёт принятый старт единицы: sub/unit, её born (нынешняя жизнь из 32 строчных hex, обязательная при принятом старте), revision, эпоху держателя и точный индекс строки эпохи, подтверждённый при взятии. input несёт одно объявленное имя состояния и значение. born/revision/epoch и обе ссылки guard обязаны происходить из start. Только value происходит из input и кодируется JCS по кодеку семейства state, после проверки `unit.state.<name>`. Имя и единица также сохраняют грамматику манифеста/ключа.

Результат — key/items/guard. Чтение прежней строки состояния, её CAS-версия, may_write, CAS/retry, отказ guard, синхронизация и подтверждение остаются обычными правилами IO P/03.6-R193 и P/03.6-R194. Конструктор ничего из этого не делает и хранилище не читает. epoch_index из нового чтения нарушает привязку, даже если строка версии допустима.

Независимый шов s5-state-start-born меняет строку единицы после старта: результат сохраняет born/revision/epoch и epoch_index старта, принимая новое input.value. Версия guard вне binary64 копируется точно. Обязательные отрицательные проверки — start заменён повторным чтением, epoch_index заменён текущей версией, чужой ключ/свойство и отсутствие обязательного свойства. Ошибка значения подсистемы остаётся ошибкой без записи.
