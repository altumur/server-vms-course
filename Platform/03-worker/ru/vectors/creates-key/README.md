# Векторы: id строки заказа (`worker.creates[].key`)

Владелец — глава P/03.6 ([нормы](../../spec/03.6-worker.norms.md) N1.6 `id`, `key`). Участник —
`<s>worker` заказчика (библиотека воркера). Запись значений по типам — [P/06.1](../../../../06-console/ru/spec/06.1-console.norms.md)
N1.2 `values_by_type` (векторы [`values-by-type`](../../../../common/ru/vectors/values-by-type/README.md)). Байты пишет «Спецификация».

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются; первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

| Поле | Значение |
|---|---|
| `case` | имя строки |
| `input` | JSON-объект: `customer` — имя подсистемы-заказчика; `key` — шаблон `worker.creates[].key`; `fields` — поле → `{type, value}`: тип поля адресата (`string`, `url`, `int`, `float`, `bool`) и значение JSON, как его даёт логика заказчика |
| `expect` | id строки заказа — байт в байт |
| `note` | правило |

## Прогон

Сторона строит id своим кодом библиотеки, без хранилища: каждое `{field}` шаблона — запись значения по `values_by_type`
(договор проверки строки `values_by_type`; `float` — его правило выбора), затем каждый байт UTF-8 вне `A–Z a–z 0–9 _ . ~` — `%XX` с hex-цифрами
верхним регистром; между подстановками — `-` шаблона; впереди — `<customer>-`. Результат сравнивается с `expect`.
Пары строк с одним `pair` в `note` проверяют, что разные значения дают разные id.
Кто исполняет — воркер-заказчик (`03-worker`: библиотека строит id, P/03.6 N1.6 `id`, `key`, N3 «заказать»). Консоль (`06-console`) id не строит: дверь проверяет только префикс заказчика и неизменность полей `key` у готовой строки (P/06.1 N1.6 `made_prefix`, `made_key`) (строку исполняет роль, чья норма вызывает её функцию).

## Команда стенда

`creates-key` — ключ `stand` профиля `03-worker` (раздел «Раскладка по процессам» [общего README приёмки](../../../../common/ru/acceptance/README.md)):
шаблон с `{input}` — путь файла, в который судья пишет ячейку `input` строки байт в байт; stdout — UTF-8 байты id ровно
как `expect`, без перевода строки в конце и без JSON-обёртки; код 0. Вход не по форме этого README — код 2 (`@exit 2`).
Иной код или лишние байты — FAIL строки.
