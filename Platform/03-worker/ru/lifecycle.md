# Воркер — жизненный цикл (урок P/03)

Контракт жизненного цикла процесса `<sub>worker` — SDK воркера на любом языке (ADR-0083 доп. (2) п. 1): запуск, имя,
окружение, замок присутствия, коды выхода, сигналы. Нормы здесь не пересказываются: каждая строка ведёт к своей норме.

Текст производный от `lifecycle.md`, руками не правится: источник — английский [`lifecycle.md`](../lifecycle.md), правка идёт в него, русский пересобирается переводом (ADR-0121; ADR-0124 доп. (1) п. 2).

Нормы: главы урока [3.2](spec/03.2-worker.norms.md) (N1.4 имя слота, N3 «старт()», «проверка схемы воркером», N4),
[3.3](spec/03.3-worker.norms.md) (N3 «цикл()»), [3.4](spec/03.4-worker.norms.md) (N1.1 пульс, N3 «старт() — шаг бюджета»,
«остановка по SIGTERM», N4), [3.5](spec/03.5-worker.norms.md) (N1.2 кольцо, N3 «открыть»), [3.6](spec/03.6-worker.norms.md)
(N1.2 события);
[P/02.4](../../02-installer/ru/spec/02.4-installer.norms.md) (N1.1 юниты, N1.2 окружение, N1.5
воркеры по заказу), [P/02.3](../../02-installer/ru/spec/02.3-installer.norms.md) (N3 «Старт процесса», «Смена
манифеста»), [P/06.6](../../06-console/ru/spec/06.6-console.norms.md) (N1.1a строка схемы),
[договор замка присутствия](../../common/ru/contracts/presence-lock.md), [договор журнала событий](../../common/ru/contracts/event-journal.md) (бакеты),
[договор местной двери токенов](../../common/ru/contracts/local-token-door.md) (просьба токена, глава 3.7).

## Запуск

| Что | Как | Норма |
|---|---|---|
| воркер | Шаблон юнита и аргумент имени слота, роль, notify/watchdog и проверка сервера — по владельцу; допуск до presence lock | P/02.4 N1.1; P/03.2 N3 start |
| имя слота | аргумент команды; нет — переменная `slot.name_env`, если манифест её объявил; иначе без имени | P/03.2 N3 «старт()» шаг 3 |
| воркер по заказу | Запуск/остановка скриптом workers по серии `<sub>_workers_wanted{server}`; имя и диапазон номера — по владельцу, захват обычный | P/02.4 N1.1, N1.5 |
| старт по шагам | схема → манифест → бюджет памяти → экземпляр → замок присутствия → имя → захват | P/03.2 N3 «старт()» шаги 0–3 (шаг 1 — P/03.4 N3 «старт() — шаг бюджета»), P/03.2 N3 «проверка схемы воркером» |

## Окружение

Окружение собирает раннер `w2c-run.sh worker <sub> <слот>` (воркер на домене — `domainworker <sub>`) в порядке P/02.4 N1.2,
том же, что у процессов платформы; раннер исполняет `worker.exec` строки манифеста и передаёт `W2C_MANIFEST_REV`
(ADR-0091 доп. (4)–(6)): значения юнита → `roles/<W2C_ROLE>.env` → `w2c.env` →
файл подсистемы, раньше прочитанное побеждает ([02-installer/lifecycle.md](../../02-installer/ru/lifecycle.md)).

Полный статический перечень, типы, обязательность и умолчания — [daemon-flags.tsv](../forms/daemon-flags.tsv). Ниже только смысл и фаза чтения; источник каждой строки — поле flag этой формы. Динамическое slot.name_env читается при отсутствии аргумента имени по P/03.2 N3 start. Повторное чтение кольца/соединения токенов определяется соответствующим общим договором.

## Коды выхода

| Код | Когда | Норма |
|---|---|---|
| 0 | метка манифеста сменилась — остановиться, супервизор запустит заново; упорядоченная остановка по SIGTERM | P/02.3 N3 «Смена манифеста», P/03.4 N3 «остановка по SIGTERM» |
| 2 | метка манифеста не по форме у работающего — остановка, рестарт отказывает до исправления метки оператором (P/02.3 N3 «Смена манифеста»; разбор ревью стадии A 6–7, B2) | P/02.3 N3, N4 |
| 2 | отказ старта: схема выше сборки или не число; нет строки или метки манифеста, sha256 не тот, манифест отказан; имя не по грамматике или не с `prefix`; замок присутствия: ошибка open, flock или записи содержимого (блокирующий flock ждёт, а не отказывает — разбор ревью стадии B 6–7, № 45); строка файла окружения не по грамматике; сервер в `%i` ≠ `SERVER_NAME` | P/03.2 N3 «проверка схемы воркером», P/02.3 N3, P/03.2 N3 «старт()» шаги 2a, 2b, P/02.4 N1.2, N1.5 |
| ≠ 0 | бюджет памяти превышен — не стартовать (`MemoryBudgetRefused`); свой код норма не задаёт | P/03.4 N3 «старт() — шаг бюджета», N4; P/02.4 N4 |
| 2 | после продления схема выше сборки — отсечь, отдать имя, выйти; слот не отдаётся | P/03.2 N3 «проверка схемы воркером», N4 |

## Сигналы и готовность

| Что | Как | Норма |
|---|---|---|
| SIGTERM | подмена и опрос — стоп; `before_stop_all`, единицы, писатели мест; последний пульс; отпустить место, затем отдать слот (разбор ревью стадии B 3–5, № 4); `after_stop`; `TimeoutStopSec` = `worker.stop_timeout` манифеста (ограничения/умолчание по форме владельца) | P/03.4 N3 «остановка по SIGTERM», P/02.4 N1.1 |
| SIGKILL | ничего не пишет: судит контроллер по молчанию и замку присутствия | P/03.4 N3 «остановка по SIGTERM», P/05 N1.4 |
| готовность | `READY=1` после захвата имени; `WATCHDOG=1` каждым оборотом цикла, не из подмены | P/02.4 N1.1 `notify`, `watchdog` |
| перезапуск | Политика supervisor по владельцу юнита; собственных копий сроков/умолчаний нет | P/02.4 N1.1 `common` |
| запечатанная единица | не запускается, эпохи не берёт, в `status` — `why` | P/03.5 N3 «открыть», P/03.4 N1.1 |

## Стенд

Корни `{data}/config`, `objects`, `events` до старта процесса создаёт команда запуска роли профиля — [общий README
приёмки](../../common/ru/acceptance/README.md) «Стенд без root»; процесс корней не создаёт ([P/02.4](../../02-installer/ru/spec/02.4-installer.norms.md) N1.1 `dirs`; STAND-ROOTS-CLEAR-01, решение «Архитектора» 2026-10-27).

«Стенд» — [общий README приёмки](../../common/ru/acceptance/README.md): `@start worker [<sub>]
<имя>` — имя подстановкой `{name}` (аргумент), `{sub}`; окружение от `{data}` (`PLATFORM_DIR`), `BOX_ID` стенда,
`SERVER_NAME`, `PLATFORM_STORE` сокета роли, переменная `slot.name_env`, если манифест её объявил; `@sigterm`, `@sigkill`;
воркеры по заказу — директива `@grow` (исполняет ряд `workers_wanted` вместо скрипта).
