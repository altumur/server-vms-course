### N1.2 Вклад члена: сторона писателя

Живость слота у агента (`liveness`), вклад в отчёте (`in_report`), `seal_reuse`, `no_seal`, `reports` —
[глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.2.

**`source_row`.** строка хранилища члена по from: `<sub>/<row>` или `<sub>/<row>/<slot>`. **`source_row`.** элемент строки — вход книги: имя элемента — item (непустое), значение — текст JSON-объекта

**`entry`.** форма входа — договор конвертов домена «Вклад» `entry`


**`shared`.** одна строка from у нескольких книг: элемент — вход каждой из них, форма входа — конъюнкция: поле key и
поле to каждой такой книги (проверяется чтением — у стенда книги читают разные
строки from)

**`same_key`.** строки двух слотов одного члена могут нести один key книги `unique`, пока слот прежнего писателя ещё держат: равные элементы — один вход, неравные снимают вклад члена (P/08.5 N3 шаг 4a)

**`writer`.** воркер своей подсистемы под своим слотом (запись под слотом глава 3.2 N3, глава 3.4 N3). **`writer`.** права — платформенная основа роли (P/02.5 N1.4: «domain book sources»). **`writer`.** worker.writes не нужен


**`claim`.** захват с чисткой — захват слота, у которого прежний держатель — не этот экземпляр (в том числе по предложению запасному, P/04), или строка которого при захвате была с released ≠ "false" ("true" — отдан выводом сервера или судьбой слота, "taking", поля нет), и тем же экземпляром: до первой своей записи удаляет строки под этим слотом по каждому from книг только собственного манифеста. **`claim`.** При этой чистке воркер не читает и не меняет вклады чужой подсистемы даже при том же имени слота: released := taking → удалить строки по стражу слота → released := false (глава 3.2 N3), затем подсистема пишет вклады заново, как при старте.


**`claim`.** После захвата с чисткой память записанных вкладов подсистемы сброшена: каждый вклад после захвата — первая запись, правило «a row only on change» сравнивает с пустой памятью. **`claim`.** После захвата с чисткой сбросить память подсистемы о записанных вкладах по этому правилу; без этого сброса живой, но отрезанный сервер после изъятия и отзыва вернул бы имя повторным захватом без вкладов.

**`claim`.** Строк вкладов не трогает только повторный захват тем же экземпляром строки слота с released = "false".

Запись под слотом — [глава 3.2](03.2-worker.norms.md) N3 «писать_под_слотом» и [глава 3.4](03.4-worker.norms.md) N3. Слот и `released` — глава 3.2 N1.4.

Профиль AAD `at_rest` — [P/08.5 N1.3](../../../08-domain/ru/spec/08.5-domain.norms.md).

### N1.5 Токен у воркера и проверка у получателя

Локальный выбор политики задаёт [`token-cache.machine.yaml`](../../forms/token-cache.machine.yaml) и [граница эффектов](../forms/README.md#автоматы-политик-воркера). Захват, IO и криптография остаются в обычных процедурах ниже.

Токен воркера — токен домена ([договор токена домена](../../../common/ru/contracts/domain-token.md) «The token», владелец P/08.2) с `kind` вида манифеста. Ключ подписи держателя воркеру не выдаётся, ключ члена — тоже: токен просит воркер, которому он нужен, через агента своего кластера.

За исключением `keep: true` (P/03.7-R053), токен живёт только в памяти воркера: ни в строке, ни в книге, ни в отчёте, ни в журнале, ни в
копии.

Исключение одно — вид с `keep: true` манифеста: воркер держит токен ещё и файлом `<каталог состояния воркера>/tokens/<вид>-<sha16(ref)>`, режим 0600, в конверте [договора запечатывания](../../../common/ru/contracts/sealing.md#путь-aad). Аргумент ключа строки — полный путь именно этого файла, аргумент JSON Pointer — `/token`; договор строит один AAD из этих аргументов для записи и чтения. Альтернативные или прежние контексты не перебираются. Хозяин файла токена `keep: true` — вид, не камера.

При старте воркер читает сохранённый файл токена `keep: true`, чтобы работать при молчащем домене.

Для сохранённого токена `keep: true` срок судит приёмник, не часы коробки: истёкший файл не выбрасывается, а заменяется после отказа `expired`.

Если конверт сохранённого файла токена не открылся, воркер считает, что файла токена нет.


Новый токен `keep: true` заменяет сохранённый файл только после первого принятого им обращения; до того в памяти старый и новый токены. После принятого обращения кандидат становится current в памяти независимо от успеха persist. Обычный писатель файла исполняет намерение persist последовательно и повторяет его только в объявленном конечном бюджете; исчерпание бюджета не гарантирует чтения нового токена при следующем старте. Ошибки IO или неопределённость используют существующую диагностику без байтов токена. Успех сохранения требует [барьеров секретного файла](../../../common/ru/contracts/secret-files.md): отказ до публикации сохраняет прежний файл, а неизвестный исход публикации нельзя объявлять сохранением прежнего файла.

Для вида с `keep: true`, пока воркер держит токен с `current`, он не просит другой токен.

Для вида с `keep: true`, при `unknown_key` на токене с `current` воркер ждёт, а не просит другой токен.

Токен `keep: true` тоже не идёт в строку, книгу, отчёт и журнал. Предел сохранения токена `keep: true`: кража коробки даёт этот токен до отзыва.


Воркер просит токен местной дверью агента: [договор местной двери токенов](../../../common/ru/contracts/local-token-door.md) (владелец
глава 9.1; сокет `<AGENT_TOKEN_DIR>/<W2C_ROLE>.sock`).

Получатель — воркер или дверь члена, которому адресован токен.


Проверка — функция `token` [договор токена домена](../../../common/ru/contracts/domain-token.md) «The check» с `expect`: `kind` — вид, которого он ждёт, `cluster` — свой кластер (ключ обязателен, не `null`: `null` — только у `kind: person`), `audience_claim` — из объявления вида. Токен, в аудитории которого нет кластера-получателя, — `wrong_audience`. Вид токена отличается от ожидаемого получателем — `wrong_kind`.

Дальше получатель сверяет свои утверждения (`ref_claim` — своя единица, у `scenario` — `acts`). Смысл собственных утверждений получателя (`ref_claim`, `acts`) задаёт подсистема.

### N1.6 Переносимые книги, `kept` и воркер подсистемы на домене

**`domain_worker`.** воркер подсистемы на держателе, роль `<sub>domain` (слово secrets.readers — domainworker, P/01.2 N1.1). **`domain_worker`.** один: слот `domain/<sub>/worker` (аренда — глава 3.2 N1.4). **`domain_worker`.** есть у манифеста, где есть kept или переносимая книга. **`domain_worker`.** юнит `<dep>-<sub>domain.service` — на каждом сервере с w2c-domain, активен один по слоту (P/02.4 N1.12).


**`domain_worker`.** смена умершего держателя: запасной захватывает слот cas по версии строки слота, не менявшейся LOST_AFTER + HOLD_SKEW на монотонных часах наблюдателя (HOLD_SKEW — договор наблюдения «Удержание места»), gen + 1 при читаемом gen. **`domain_worker`.** Захват после LOST_AFTER + HOLD_SKEW применим только к слоту воркера на домене; он не применим к слотам членов кластера.

**`carried_book`.** `domain.books.<book>`: {} | {show} — строки `domain/<sub>/<book>/<member>` у держателя пишет воркер на домене.

**`carried_book`.** строку бывшего члена (его нет в списке членов) удаляет процесс domain проходом, как у собираемой
(P/08.5 N1.3 write).

**`carried_book`.** доставка, member_row и дверь — как у собираемой (P/08.5 N1.4; P/09.1 N1.4 member_row; дверь — P/06.7 N1.1)

**`kept`.** domain.kept: `[<name>|<family>/…]` — строки `domain/<sub>/<name>` у держателя, пишет воркер на домене. **`kept`.** Строки kept не доставляются члену. **`kept`.** domain.tables — какие из kept — таблицы (P/06.1 N1.6)

**`door_pass`.** `/domain/<sub>/<door.pass segment>` консоли домена → воркеру на домене (P/10 N1.6)

**`door_client`.** дверь воркера на домене под TLS принимает door.pass только от клиента роли domainconsole (клиент —
P/10 N1.6).


**`door_client`.** Дверь воркера на домене запрашивает сертификат клиента необязательно и предъявленный проверяет в рукопожатии, как
слушатель SIGNER_URL: не сходится к ca.pem или ca.next.pem кластера, срок истёк, extendedKeyUsage без

сертификата, роль из SAN не domainconsole, подпись листа или центра вне списка sig, серийник в revoked —

**`door_client`.** по HTTP
стенда роли нет — проверяется чтением, как X-W2C-Client (договор пересылки «Адрес клиента»).

**`door_client`.** клиент — консоль домена — проверяет сервер этой двери как
клиент своего кластера (договор сертификата роли own_client, роль `<sub>domain`)

своего сервера нечитаема — имя не берётся, пока не прочтётся, журнал)

**`heartbeat`.** объект `domain/<sub>/heartbeat` в хранилище объектов держателя (P/05 N1.1), один на подсистему — пульс воркера на домене формы главы 3.4 N1.1 (worker, ts, server, url, instance, status …; время — N0). **`heartbeat`.** worker — ровно строка «`domain/<sub>/worker`», полный ключ его слота (грамматика имени слота главы 3.2 к нему не применяется). **`heartbeat`.** пульс с иным worker — не по форме (проверяется чтением — стенд не несёт воркера на домене). **`heartbeat`.** пишет `<sub>domain` каждые HEARTBEAT_EVERY и подменой (глава 3.4 N3).

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи. Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N3 Проход

Захват слота и чистка строк прежнего держателя — N1.2 `claim`. Гонки вклада — [P/08.5 N3](../../../08-domain/ru/spec/08.5-domain.norms.md) «Гонки» (поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости агента).

### проверить у получателя

```
token (договор токена домена) с expect {kind: <вид>, cluster: <свой кластер>, audience_claim, keep: <виды keep: true каталога>} → ok | refused (… | wrong_kind | wrong_audience)
```

Функция `token` и её шаги — [договор токена домена](../../../common/ru/contracts/domain-token.md) «The check» (владелец — [P/08.2](../../../08-domain/ru/spec/08.2-domain.norms.md)).

**Гонки.** Назначение, топология или документ меняются после выдачи — токен живёт свой `lifetime`.

Вид с `keep: true` отзывает `DELETE /domain/issued` через `domain/revoked`, вид без `keep` живёт до `exp`: предел
([договор набора ключей домена](../../../common/ru/contracts/keys.md) «Revocations»).

Два одинаковых запроса — два токена. Память о выданных не нужна, кроме вида с `keep: true`: строка `domain/issued` (P/08.2 N1.6a).

Отказ `revoked` токену вида с `keep: true` — воркер просит новый со словом `revoked: <jti этого токена>` (договор местной двери), иначе круг отказов на годы.

Ответ на просьбу замены P/03.7-R106 для вида с `keep: true`, с тем же `jti`, что у отозванного токена (слово не исполнено: `REVOKED_WORDS`, строка `domain/revoked` на 80 %, P/08.2 N1.6a) — воркер не просит заново до конца суток своих часов, журнал: правило общее для воркера любого вида `keep`, иначе воркер вне `cam`, `rec` уходит в круг просьба → тот же токен → `revoked`. Собственные сутки для этого ожидания — календарный день UTC по стенным часам воркера; day машины — порядковый номер этого дня. TIMEZONE не меняет границу; грамматика и отказы TIMEZONE по договору окружения сохраняются.
