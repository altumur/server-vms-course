## N2 Договор библиотеки

У воркера нет собственной двери в этом уроке: он пишет и читает хранилище (P/01.1) и объекты (P/05). Что о нём видно снаружи — пульс, слот, метка соперника, `/servers` консоли (P/06, глава 6.5). HTTP-контрактов своего урока нет. Формы ответов чтения/записи — [P/01.1](../../../01-store/spec/01-store.api.openapi.yaml), единиц — [P/06](../../../06-console/spec/06-console.api.openapi.yaml) (глава 6.1), объектов — [P/05](../../../05-resource/ru/spec/05-resource.norms.md#n2-двери). Пульс — форма [главы 3.4](03.4-worker.norms.md) N1.1, не HTTP-ответ воркера.

Подсистеме воркер даёт шесть вызовов, форма которых — дело языка (решает реализация):
```
start_unit(id, row, epoch)   — запустить единицу под эпохой
```

```
stop_unit(id)                — остановить единицу
```

```
status() → [status-элемент]  — доложить для пульса
```

```
reconcile_once()             — шаг сверки желаемого с текущим (глава 3.3 N3 «цикл()», шаг 2)
```


```
before_stop_all()            — упорядоченная остановка, до stop_unit всех единиц: подсистема готовится (сбросить буферы,
                               закончить начатое); по умолчанию ничего; ошибка — строка журнала, остановка продолжается
```

```
after_stop()                 — после отдачи слота и места: подсистема закрывает своих писателей; по умолчанию ничего;
                               ошибка — строка журнала, код выхода остановки по SIGTERM не меняется
```

Слово библиотеки `stalled(id)` — не вызов подсистемы, а её вопрос к библиотеке, форма — дело языка: единица застряла, отступ запуска дошёл до `RETRY_MAX`, пока счёт не обнулён ([глава 3.3](03.3-worker.norms.md) N1.2 `stalled`), то же значение, что `status[].stalled` пульса. Подсистема, которой нужно `stalled(id)`, спрашивает библиотеку из своих вызовов и своего счёта неудач не ведёт: он разошёлся бы с отступом.

Слово библиотеки `restarting(id)` — такой же вопрос подсистемы из `stop_unit`: истина, когда этот `stop_unit` — перезапуск той же единицы по росту `revision` ([глава 3.3](03.3-worker.norms.md) N3 «цикл()», шаг 2). При любом `stop_unit`, кроме перезапуска той же единицы по росту `revision`, `restarting(id)` ложно. Снятие, переезд и остановка воркера — примеры этого дополнения, а не его закрытый перечень.

Вызовы `before_stop_all` и `after_stop` зовутся только при упорядоченной остановке воркера (SIGTERM, [глава 3.4](03.4-worker.norms.md) N3).

При крахе воркера ни `before_stop_all`, ни `after_stop` не вызываются; по их отсутствию контроллер отличает крах от упорядоченного ухода (P/04).


Вызовы подсистемы воркером следуют правилу трёх мест; это не хуки платформы.

## N3 Проход

`before_stop_all`, `after_stop` — «остановка по SIGTERM» [главы 3.4](03.4-worker.norms.md) N3, шаги 2 и 5.
