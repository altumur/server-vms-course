## N0 Словарь слов

Нормативные слова — по [канону курса](../../../common/ru/NORMATIVE-TERMS.md). Правила модуля — [P/01.1 N0](../../../01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

### N1.2 Сроки аренды, соперника и мест

Сроки аренды, соперника и мест, которые используют процедуры этой главы. Сроки цикла и пульса (`HEARTBEAT_EVERY`, `POLL`, `WAKE_GAP`,
`PASS_SHARE`) и сторож (`watchdog`) — [глава 3.3](03.3-worker.norms.md) N1.2; подмена (`stand_in`) и бюджет памяти
(`memory`) — [глава 3.4](03.4-worker.norms.md) N1.2.

Независимые уставки — [runtime-constants.tsv](../../forms/runtime-constants.tsv); SLOT_TERM — договор слота, HOLD_SKEW и CONTENDER_FRESH — договор наблюдения. Равные нынешние значения разных владельцев не отождествляются.

```yaml
# LEASE_TTL, LEASE_MARGIN, CONTEND_EVERY — собственные строки runtime-constants.tsv.
loop:
  LEASE_EVERY: (LEASE_TTL - LEASE_MARGIN) / 3  # точно; от НАЧАЛА предыдущего шага
  again: продление слота без ответа или хоть одна аренда стала silent - следующий шаг сразу
contend:
  CONTENDER_FRESH: договор наблюдения, Свежесть метки соперника
places:
  HOLD_SKEW: договор наблюдения, Удержание места
  WRITE_WINDOW: SLOT_TERM - HOLD_SKEW  # подтверждённое окно строгого писателя
  CLOSE_BY: SLOT_TERM + HOLD_SKEW     # к этому моменту строгий писатель закрыт
```

### N1.4 Строка слота

```yaml
slot:                                     # раздел манифеста (P/02.1 N1.2); закрытый: два ключа
  prefix:   <1–8 строчных латинских>      # умолчание w; имя слота — <prefix>-<суффикс>
  name_env: <ИМЯ_ПЕРЕМЕННОЙ>              # ^[A-Z][A-Z0-9_]*$; переменная окружения, из которой воркер берёт предпочитаемое имя, когда его не дали аргументом (N3 «старт()», шаг 3); нет ключа — имя из окружения не берётся
<sub>/slots/<имя>:                        # имя: <prefix>-<суффикс>, суффикс ^[a-z0-9]+(-[a-z0-9]+)*$: числовой <n> — имена, которые
                                          # выдумывает захват без заданного имени; <сервер>-<n> — имя от юнита (P/02.4 N1.1: экземпляр
                                          # %i = <prefix>-<сервер>-<n> аргументом, P/02.4 N1.2; ADR-0043), <сервер> = SERVER_NAME (P/02.4 N1.2);
                                          # n — десятичное целое без ведущих нулей: 1 — базовый процесс роли на сервере, 2…99 —
                                          # заказанные контроллером (P/04 N3 «order()»; ADR-0084); выбор по номеру (сокращение
                                          # P/04, скрипт воркеров P/02.4 N1.5) сравнивает n целым, не слотовым порядком ниже
  holder:    <экземпляр> | ""              # экземпляр — договор экземпляра grammar (common/contracts/instance.md; аудит раскладки A-06, решение «Архитектора» 2026-10-25)
  until:     <Time>   # часы писателя + SLOT_TERM; показ/расхождение, не свежесть
  released:  "true" | "false" | "taking"     # taking — первая запись захвата (N3 «захватить» шаг 3; добавлено пилотом Quint, F2)
  gen:       <точное десятичное целое 1..9007199254740991> # начальный операнд отсутствующей строки 0; +1 при захвате
  server:    <непустой сервер держателя> # при каждом захвате/продлении после допуска SERVER_NAME до presence lock
states:    held, lapsed, released, taking, torn — договор слота «Состояния» (перенесено туда без изменения; аудит раскладки A-04, решение «Архитектора» 2026-10-25)
constants:
  SLOT_TERM, TORN_STILL: договор слота «Terms» (common/contracts/slot.md; перенесено туда без изменения; аудит раскладки A-04, решение «Архитектора» 2026-10-25)
  RENEW_EVERY: LEASE_EVERY # точная формула N1.2
```

**Порядок имён и следующий номер** — [договор имени слота](../../../common/ru/contracts/slot-name.md) (перенесено туда без изменения
поведения, POOL-ORDER-51-01; там же — имя процесса роли `<prefix>-<s>-<N>` и его номер). Имя проверяется по грамматике выше и prefix своего манифеста.
«По имени», слотовый порядок (цифровой суффикс — по числу без переполнения, затем прочие по имени) и следующий номер
`<prefix>-<max + 1>` — в договоре.

Возраст наблюдаемой версии — время на монотонных часах конкретного судьи с момента, когда он
впервые успешно прочёл текущую версию строки. Первый взгляд, новая версия или изменённые байты
дают возраст 0; повторное чтение того же состояния и неответ хранилища его не обнуляют.
Память наблюдения своя у каждого судьи; после перезапуска первый взгляд снова свежий (ADR-0049).
Поэтому held/lapsed — состояния относительно наблюдателя, а не сравнение until с его часами.
Судьи с разной историей могут временно расходиться. Запись по чужим часам не даёт права на захват:
это право — released/свободное имя или names_given с точной версией, плюс исключения N3.

Сам держатель для допуска своих записей помнит монотонный момент отправки последнего
подтверждённого захвата (завершающая запись released:false) или продления слота.
Свой срок кончается через SLOT_TERM от этого момента; время получения ответа и перечитка
его не продлевают. Поздний ответ, пришедший за этим пределом, не разрешает писать без нового
подтверждённого продления. Это локальный срок собственного запроса, отдельный от памяти судьи.
Для повтора одной записи с тем же id сохраняется момент её первой отправки; ответ again
не начинает новый срок. Новое продление — новая запись, не повтор прежнего подтверждения.

Подтверждённое отсутствие строки даёт начальный операнд поколения 0. Существующий `gen` ДОЛЖЕН быть точным десятичным целым в `1..9007199254740991`, по нынешнему писателю захвата. Отсутствующий, нулевой, отрицательный, сверх предела или иначе недопустимый gen — существующая строка каталога отказов `slot_gen_unreadable`: кандидата не переписывать, в том числе после `TORN_STILL` или разрешения контроллера; исходные байты сохраняются, обнуления и округления нет.

Максимум `9007199254740991` читаем. Перед разрешённым захватом проверяется возможность следующего поколения: у максимума отказ `generation_exhausted` до записи. Порча других полей при читаемом gen допускает первый захват после `TORN_STILL` только с точным gen+1 в области писателя. NameOnAnotherBox и допуски захвата по-прежнему обязательны. Вход машины `gen_readable` проверяется на исходных байтах до сужения; `gen_incrementable` истинен при подтверждённом отсутствии или читаемом gen ниже максимума. int gen — точный операнд либо неиспользуемая нулевая заглушка; широкий повреждённый gen не становится нулём. При отсутствии заданного имени отказ кандидата не мешает проверить следующие.

### N1.4a Метка соперника

Локальный выбор политики задаёт [`contender-writer.machine.yaml`](../../forms/contender-writer.machine.yaml), его [трассы](../../forms/contender-writer.traces.tsv) и [граница эффектов](../forms/README.md#автоматы-политик-воркера). Захват, IO и криптография остаются в обычных процедурах ниже.

Объект `<sub>/contenders/<name>/<box>`: `{name, state: refused | nameless | waiting, box, hostname, server, instance, holder, holder_box, since, at}`; `refused` — NameOnAnotherBox по таблице захвата N3 «захватить», включая занятую неотданную lapsed-строку другой коробки; `nameless` — своего прежнего захвата больше нет, воркер ждёт; `waiting` — своего захвата ещё не было и кандидата нет без NameOnAnotherBox. Приоритет refused выше двух остальных. На выведенном сервере (N3 «старт()» шаг 3) метки нет: воркер — никто без поиска имени, и соперником не является. При поиске без заданного имени `name` — `-`, `holder` — `""`; с заданным именем — искомое имя и его текущий держатель. Переписывается каждые `CONTEND_EVERY`; свежесть у читателя — [договор наблюдения](../../../common/ru/contracts/observation.md) «Свежесть метки
соперника» (`CONTENDER_FRESH`; C06-CONTENDER-FRESH-33-01, решение «Архитектора» 2026-10-25): старше `CONTENDER_FRESH` не учитывается; нечитаемая метка (не по форме) у читателя-воркера — как старше `CONTENDER_FRESH` (разбор ревью стадии B 3–5, № 5), у консоли свежая нечитаемая — конфликт с пометкой (исходы по читателю — [`contenders.outcomes.tsv`](../../data/contenders.outcomes.tsv); C03-CONTENDER-UNREADABLE-01); `since` сохраняется в пределах одного состояния.

Все десять перечисленных полей обязательны в нынешнем объекте; name/state соответствуют политике, server непустой. since и at — существующий Time, а не произвольное значение. Внутри одного состояния since переносится только из читаемого нынешнего объекта или корректной локальной памяти политики; непроверенное значение не переносится. Смена состояния задаёт новый since. Freshness остаётся по наблюдаемой версии, а не по at или since.

### N1.5 Строка эпохи

```yaml
<sub>/epoch/<id>:

```

### N1.6 Аренда

```yaml
lease:
  # Окно действия: LEASE_TTL - LEASE_MARGIN от отправки последнего подтверждённого запроса.
  states:
    confirmed:    выдача моей эпохи подтверждена или чтение несёт мой номер → last — наибольший момент отправки подтверждённых запросов
    fenced:       в строке другой номер, строка не читается или воркер отсечён → навсегда для этой эпохи
    silent:       хранилище не ответило, пока окно было открыто → unconfirmed считается от конца окна
    lost:         окно вышло без запроса (проспано), либо начальная выдача/запуск опоздали, либо эпоха ниже floor — не silent
  may_act:    not fenced and not lost and now − last < (LEASE_TTL - LEASE_MARGIN) and свой срок слота N1.4 не истёк
              # lost и срок слота — добавлено пилотом Quint (F3): при потере записей и живых чтениях старый держатель
              # перестаёт действовать до переезда — свой срок SLOT_TERM от отправки продления; переезд — по договору контроллера P/04
  may_write:  may_act or (silent and unconfirmed < unconfirmed_max)      # unconfirmed_max: off = 0, forever = ∞
  unconfirmed_max: из manifest.lease (P/02.1): forever | off | <целое ≥ 1 с>; умолчание off
```

Момент запроса — перед первой отправкой логического вызова. Сетевые повторы внутри него,
в том числе повтор записи с тем же id/ответ again, этот момент не сдвигают. Новый запрос
подтверждения имеет свой t0; last от уже подтверждённых запросов не убывает. При первой
выдаче эпохи last устанавливается по подтверждённой записи, затем применяется N3 «подтвердить».

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N3 Проход

### Полные ключи и отказ хранилища

Ветви воркера N3 «Полные ключи и отказ хранилища» (перенесены из М10/3) — выбор слота, захват после его начала, продление, запись под
стражем слота, выдача и подтверждение эпохи; ветвь двери единиц (`400 badkey`) — [глава P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N3 «Полные ключи и отказ хранилища», ветви
удержания места — N3 «место: взять, держать, отпустить» (разбор ревью стадии A 3–5, № 11).

Во всех операциях ниже правила ключа P/01.1 N1 применяются после сборки полного пути P/06.1 N1.1,
включая префикс, семейство и разделители; ключ стража проверяется так же. Грамматика UnitId,
WorkerName и 200-байтный предел компонента Idempotency-Key сохраняются. Схема компонента
не обещает вместимость полного ключа. Ключи не сокращаются и не хешируются при отказе.

Определённый `badkey` при чтении или записи — отказ этой операции, не отсутствие строки,
не CAS-conflict и не неответ. Применимые правила ключа можно проверить до вызова хранилища;
отказ меньшего объявленного предела файловой реализации обрабатывается тем же способом.

- При выборе слота badkey означает отказ кандидата до первой записи: заданное имя оставляет
  процесс никем, при поиске проверяется следующий; отказ нового вычисленного имени завершает
  поиск никем. После начала захвата отказ операции прерывает попытку без выдачи живого слота;
  уже подтверждённые записи не откатываются. На продлении имя теряется; на записи под стражем
  отказывается запись, сама ошибка целевого ключа не доказывает потерю слота.
- При выдаче эпохи badkey запрещает запуск, при подтверждении — fenced без продления окна.
  Отказ ни в одной ветви не подменяется успехом, пустым чтением или бесконечным повтором.

### захватить(имя?) → слот | никто

Вызов при первом старте экземпляра отличается от поиска имени после потери: исключение для своей
коробки ниже доступно только первому вызову из N3 «старт()». Повторный поиск, воссоединение
и продолжение после отсечения не восстанавливают это право; способ хранить признак выбирает реализация.
Первый вызов, ни одно чтение кандидата которого не подтвердило строку или её отсутствие (хранилище не ответило),
право не тратит: оно переходит к следующему поиску (N3 «никто и возврат имени», воссоединиться()), пока такое чтение не случится
(добавлено пилотом Quint).

**Таблица переходов захвата.** Нормативная машина — [forms/slot-capture.tsv](../../forms/slot-capture.tsv). Это локальные состояния попытки, не поля строки слота. Шапка объявляет входы и действия; строки проверяются по порядку, отказы прежде разрешений. Адаптер выводит входы из перечитанной версии по названным договорам. Порядок кандидатов и очистка остаются псевдокодом ниже. Действие `-` — явно негенерируемая процедура по якорю требования, а не пустое действие и не разрешение её пропустить. Воркер одного вида: дополнительный ролевой процесс на сервере — тот же юнит со своим именем и обычным захватом (ADR-0084).

Кандидат не захвачен — перейти к следующему; при заданном имени или исчерпанном списке вернуть никто.
Таблица не разрешает переход к другому имени для именованного процесса.

```
1. прочитать строки слотов и поле names_given объекта <sub>/controller/pass (P/04 N1.2; привязан к версии строки слота);
   неответ не считать пустым списком или отсутствием строки → никто
2. оставить только допустимые имена своего манифеста и кандидатов по таблице;
   порядок кандидатов (повторное имя пропустить):
   a. имя из окружения, если задано, — единственный кандидат (ADR-0043); к b–e не переходить
   b. имена, отданные контроллером, в порядке имён N1.4
   c. свободные читаемые строки — в слотовом порядке N1.4
   d. порванные с читаемым gen, простоявшие без изменений TORN_STILL, — в слотовом порядке
   e. только процесс без заданного имени: новое <prefix>-<max + 1> по N1.4
3. для кандидата: перечитать строку и снова применить таблицу;
   основание выбранной ветви должно сохраниться: версия names_given точна, свободное осталось свободным,
   порванное не изменилось, новое имя по-прежнему отсутствует; иначе следующий кандидат;
   для заданного имени заново проверить условия таблицы, включая holder и признак первого старта;
   записать {holder: я, until: now + SLOT_TERM, released: "taking", gen: gen + 1, server} с cas прочитанной версии; conflict → следующий кандидат. Слот захвачен, но не жив: контроллер и
   агенты его живым не читают, контроллер не принимает его за отдачу (N1.4 taking;
   добавлено пилотом Quint, F2), писать под ним нельзя (P/03.2-03); с этой записи страж предшественника недействителен —
   его поздняя запись вклада получает 412
4. перечислить вклады предшественника под этим именем (строки, которые собирают, — М11) — уже после шага 3, поэтому
   список полон; удалить каждую записью под стражем {key: слот, index: версия записи шага 3}; затем записать
   released: "false", until: часы писателя + 45 с cas по той версии → слот жив; версия этой записи = страж на дальше (ADR-0074 C2: ни одна строка
   предшественника не видна под живым слотом нового держателя). Вкладов нет — вторая запись всё равно делается
→ слот; все кандидаты не прошли → никто
```

**Гонки.** Два процесса на одно имя: `cas` пропускает одного, второй идёт к следующему кандидату или становится никем.
B при старте забрал имя у A на той же коробке; A после отсечения повторяет поиск → стартового исключения
у A больше нет, живое имя B остаётся за B. Порча `gen` между выбором кандидата и перечиткой → отказ
кандидата без записи; изменение после перечитки отсекается `cas`. Чистка против нового-нового владельца: страж по версии слота — тот, у кого слот переписали, получает `412 guard` и не стирает чужое. Контроллер отдаёт имя (P/04 N3 «судьба», `names_given`) между моим чтением и записью: `names_given` привязан к версии строки, моя запись с `cas` по той же версии проходит; по новой — конфликт и перечитка.

### продлить() → ещё мой | потерян

```
каждые RENEW_EVERY:
  прочитать слот; holder/gen не мои, released или слот нечитаем             → потерян: стать никем (N3 «никто и возврат имени», отдать_имя())
  записать {…строка, until: now + SLOT_TERM, server} с cas; conflict               → перечитать и снова проверить все условия
  хранилище не ответило                                                     → всё ещё мой (решает аренда единиц)
```

**Гонки.** Продление против разрешённого захвата другим экземпляром: `cas` по прочитанной версии пропускает одного; проигравший видит чужой `holder`/`gen` — потерян. Молчание хранилища не продлевает свой срок: до подтверждения нового продления записи под слотом разрешены лишь в оставшемся местном окне N1.4 и по условиям аренды единицы. Неподтверждённый запрос не меняет начало этого окна.

### отдать() — только при упорядоченной остановке

```
записать {…строка, released: "true", until: now} с cas; conflict — не повторять
```

**Гонки.** Отдача против захвата: `cas`; захват другим раньше отдачи — отдавать нечего (чужой `holder`), ничего не пишется. Отдача против подмены (глава 3.4 N3 «подмена()»): подмена перечитывает слот перед продлением и видит `released`.
Отдача против отпускания места: отдача — после отпускания места (глава 3.4 N3 «остановка по SIGTERM», шаг 4); под
отданным слотом место уже не отпустить (разбор ревью стадии B 3–5, № 4).

### писать_под_слотом(key, items) → index | отказ

```
перечитать слот; holder мой, gen мой, не отдан, читаем, свой подтверждённый срок N1.4 ещё не истёк,
разрешено писать (writing_allowed, N3 «старт()», шаг 5) → иначе не писать
записать(key, items, guard: {key: слот, index: версия перечитанного слота})
412 guard → запись не сделана; перечитать слот и заново проверить владение и условия
  тот же holder и gen, слот жив, запись разрешена → имя сохраняется; допустима новая попытка с новой проверкой
  чужой holder/gen, отданный или нечитаемый слот → потерян: стать никем
  хранилище не ответило или истёк свой подтверждённый срок → не писать; успех и потерю по одному 412 не объявлять
```

**Гонки.** Запись под стражем против смены слота: 412 `guard`, запись не делается, перечитка
показывает нового держателя — прежний становится никем. Собственное продление v1 → v2 сохраняет
holder и gen: запись с v1 получает 412, но перечитка подтверждает владение; новая попытка проверяет
все условия и использует v2. Слепого повтора со старым стражем нет. Две записи одной строки под
одним стражем — решает `cas` строки, страж пропускает обе. Строка удержания места (N3 «place») пишется этим же путём —
под стражем слота и с `cas` строки места: и взятие, и продление, и отпускание; поэтому при упорядоченной остановке
место отпускается до отдачи слота (глава 3.4 N3 «остановка по SIGTERM», шаг 4; разбор ревью стадии B 3–5, № 4).

### взять_эпоху(id) → epoch | отказ

```
условия: я кто-то (слот мой); единица в назначении, которое ответило последним; с тех пор не потеряна
прочесть <sub>/epoch/<id>: подтверждённо отсутствует → 0; существующая epoch не точное целое 1..9007199254740991 → EpochUnreadable, исходные байты не менять (не 0)
прочитать platform/epoch_floor: floor (нет → 0; не читается → отказ выдачи, пол не подменяется 0)
max(текущая, floor) >= 2^53 − 1 (сравнить читаемые целые точно до машинного преобразования) → отказ выдачи до записи: строка эпохи не меняется,
  единицу не запускать; заведомо недопустимую выдачу не повторять; журнал называет единицу и эпоху (как rev P/02.3 N1.5 на той же границе; разбор ревью стадии B 3–5, № 8)
t0 = now (монотонные, непосредственно перед отправкой записи)
записать {epoch: max(текущая, floor) + 1} с cas прочитанной версии;
  conflict → перечитать строку эпохи и пол и повторить с новым t0 для новой записи (пол — добавлено пилотом Quint, F1)
  исход не подтверждён → повтор тем же id по P/03.4-07, t0 — первая отправка (N1.6); не подтверждён и тогда — отказ,
                         новую аренду не выдавать
  подтверждено → last = t0; now − last ≥ (LEASE_TTL - LEASE_MARGIN) → lost, отказ запуска, не silent
перед start_unit — успешное «подтвердить» (ниже) с t0 после подтверждённой записи выдачи (порядок причинный: чтение
  отправлено после ответа записи; равные показания монотонных часов в одном тике допустимы; C03-POST-GRANT-SAME-TICK-01): эпоха ниже floor → lost,
  не запускать; иная или не читается → fenced; хранилище не ответило — не запускать, первый запуск silent не
  разрешает (добавлено пилотом Quint, F1)
→ epoch; аренда = новая с last = t0, только в оставшемся окне
```

**Гонки.** Два воркера на одну единицу (переназначение): оба поднимают эпоху, `cas` пропускает одного первым; второй перечитывает и берёт следующую — у каждого своя, старший отсекается на подтверждении. Пол поднялся между чтением и записью: `cas` по строке эпохи этого не видит, и чтение пола до записи от этого не защищает — строки не было (`cas ""`) или копия сохранила её версию, и запись со старым полом проходит; перечитка одной строки эпохи при conflict берёт старый пол. Защищает проверка после записи: пол перечитывается при conflict, а перед start_unit успешное «подтвердить» видит пол после записи — эпоха ниже пола `lost`, единица не запускается (добавлено пилотом Quint, F1). Восстановление, поднявшее пол (P/01.3 N3 «восстановить хранилище»), процессы не перезапускает: пол читается на каждом шаге аренды (N3 «шаг_аренды()», шаг 2), и единица с эпохой ниже пола теряет аренду (`lost`) — её писатель останавливается сам.

Задержанный ответ выдачи не начинает новое окно: отправка в 0, успешный ответ в 30 — эпоха могла
быть записана, но старт уже запрещён. Номер не откатывается и не удаляется; поздний ответ не даёт
silent или права по unconfirmed_max, даже forever. Следующая попытка требует нового успешного
чтения назначения и вновь проходит ворота N3 «take_unit_epoch(unit)». Перед самым start_unit ворота и may_act
проверяются ещё раз: пауза между возвратом выдачи и запуском не продлевает окно.

### подтвердить(id) — шаг аренды

```
t0 = now (монотонные); прочитать <sub>/epoch/<id> и platform/epoch_floor
  пол не читается             → fenced, как отказ подтверждения: пол не подменяется 0
  моя эпоха ниже floor       → lost (N1.6; Гонки выдачи)
  несёт мою эпоху            → окно вышло без запроса (t0 − last ≥ (LEASE_TTL - LEASE_MARGIN) и не silent — проспал) → lost, не оживлять: N3
                               «шаг_аренды()», шаг 4 останавливает единицу (stop_unit); иначе last = max(last, t0), в том числе после silent:
                               успешное чтение своей эпохи возвращает аренду в confirmed
  иную или не читается       → fenced: остановить единицу, запомнить потерю эпохи (N3 «шаг_аренды()», шаг 4; строка эпохи не меняется)
  хранилище не ответило      → аренда не была silent и окно ещё открыто (t0 − last < (LEASE_TTL - LEASE_MARGIN)) → silent с момента конца окна;
                               уже silent → остаётся silent (unconfirmed растёт до потолка); окно пропущено без запроса → lost
may_act / may_write — по N1.6
```

**Гонки.** Подтверждение и смена эпохи другим воркером: чтение видит либо мою, либо новую —
в первом случае окно продлено на LEASE_TTL - LEASE_MARGIN от t0, во втором — отсечён сразу. Срок переезда определяет
судьба слота, а не одно это чтение (P/03.2-08). При silent действия прекращаются к концу окна;
данные — по unconfirmed_max: при off тоже к концу окна, при конечном потолке — по его достижении,
при forever конечный срок остановки данных из молчания не следует. Данные разных попыток различимы эпохами.

Входы процесса перечислены в [forms/daemon-flags.tsv](../../forms/daemon-flags.tsv): окружение и необязательный аргумент имени, без новых CLI-флагов. Вычисляемые значения по умолчанию, динамическая `slot.name_env` и проверки общих договоров остаются правилами норм, названных в строках.

```
0. проверка схемы хранилища — N3 «проверка схемы воркером» (P/06.6 N3 «старт консоли — проверка схемы», общий блок; добавлено М10/10): первым шагом, до манифеста

   процесса; после каждого захвата имени (шаг 5, N3 «никто и возврат имени») — переписать содержимое заново под тем же

2a. заданное имя (аргумент или slot.name_env, шаг 3) не по грамматике имени слота или не с prefix своего манифеста (N1.4)

   «server <s> is decommissioned», имя не берётся, метки соперника нет (N1.4a); строка вывода есть, но не читается своей

```

**Гонки.** Две копии на одной коробке с одним именем: захват — `cas`, проигравший — никто (N3); старт против живого слота на другой коробке — `refused` (N1.4a).

### шаг_аренды()

```
1. продлить слот (N3 «продлить»):
     хранилище не ответило            → всё ещё я; again = true
     holder ≠ я или released ≠ false  → отдать_имя(); отсечь("slot <имя> is held by another instance now");
                                        вернуть все ведомые (они будут остановлены отсечением)
     продлён                          → проверка схемы при продлении (N3 «проверка схемы воркером», добавлено М10/10): хранилище
                                        переросло сборку → отсечь, отдать_имя(), выход с кодом 2 (N4)
2. прочитать platform/epoch_floor (раз за шаг); подтвердить каждую аренду чтением строки эпохи (N3 «подтвердить»;
   ничего не пишется): потеряны = те, у кого не may_write
   или эпоха единицы < пола (восстановление хранилища подняло `platform/epoch_floor` — P/01.3 N1.3 `floor`, N3 «восстановить хранилище»;
   процессы оно не перезапускает)
3. прочитать назначение; не ответило → прежний ответ, пометка «не отвечено»
4. для каждой потерянной: stop_unit; отпустить эпоху; запомнить «отпущена до следующего чтения»;
   журнал — одна строка на единицу с одной из причин: «<единица> stopped: a newer epoch was issued for it | unconfirmed
   for longer than its ceiling (N s) | the store did not confirm the lease in time | its epoch is below the floor»
   единица не отсечена, в назначении и may_write под потолком → не останавливать: «данные идут, команды ждут»
5. подтверждённые снова после молчания — одна строка журнала, ничего не остановлено
6. места (манифест объявил place_by): без места — взять_место(кандидаты подсистемы) после захвата слота и на каждом шаге
   аренды, не ожидая назначения: при servers: distinct назначение само ждёт места в пульсе (P/04 N3 «Пробный процесс при
   distinct»; договор пула «Keeper of a place with distinct» — воркер без места не хранитель); строгие места — держать (ниже)
   (решение «Архитектора» 2026-10-27; P/03.6 сц. 09 шаг 4)
```

**Гонки.** Переезд и отсечение экземпляра различаются только назначением: потерянная аренда при живом слоте — одна единица; потерянный слот — все. Молчание хранилища на шаге 1 и 2 одновременно — ничего не теряется до потолка.

### take_unit_epoch(unit) — ворота перед запуском

```
по порядку:
  я никто (слот потерян / ищу имя)                              → отказ NoSlot
  свой срок слота N1.4 истёк (новое продление не подтверждено)   → отказ NoSlot «own slot term ended»: запись выдачи
                                                                   эпохи — та запись, которой держатель с истёкшим сроком
                                                                   отсёк бы нового (C03-EPOCH-OWN-TERM-01)
  отсечён                                                        → отказ Fenced (причина — отсечь(почему))
  шаг длится дольше FOR (пережил подмену)                        → отказ NoSlot «until the loop has looked again»
  единица отпущена после последнего чтения назначения            → отказ NotReadThisPass
  назначение не отвечено                                         → отказ NotReadThisPass
  единицы нет в последнем отвеченном назначении                  → отказ NotReadThisPass
перед обращением за эпохой: зарегистрировать незавершённую попытку запуска для этой единицы
  и текущего владения именем; потеря имени, отсечение или отмена единицы необратимо отменяют попытку
→ эпоха и новая аренда = выдать по N3 «взять_эпоху(id)»; last — время отправки подтверждённой записи,
  не время возврата; поздний ответ или истечение окна до start_unit → lost, не запускать,
  пометить «отпущена до следующего успешного чтения назначения»
после выдачи — успешное N3 «подтвердить» с t0 после подтверждённой записи выдачи: эпоха ниже пола → lost, не
  запускать, «its epoch is below the floor» (добавлено пилотом Quint, F1);
после выдачи и непосредственно перед start_unit вновь проверить все ворота выше, may_act,
  что попытка не отменена и относится к тому же владению именем;
неответ выдачи новой аренды не создаёт; unconfirmed_max не разрешает этот первый запуск
любой отказ завершает/отменяет эту попытку; позднее завершение запроса не может её оживить
воркер, ни разу не читавший назначения, не держится ни за какой список
```

**Гонки.** N3 «взять_эпоху(id)»: `cas` по строке эпохи; пол, прочитанный до записи, от его подъёма не защищает — защищает подтверждение после записи перед start_unit; второй воркер той же единицы берёт следующую эпоху, старший отсекается на подтверждении.

Успешный ответ записи, отправленной в 0, получен в 30: номер уже мог вырасти, но start_unit
не вызывается и номер не откатывается. То же при ответе в 24 и паузе до запуска в 26 без нового
подтверждения. Если за время выдачи потерян слот или поменялись ворота, их повторная проверка
запрещает запуск даже при оставшемся времени аренды.

Последняя проверка и принятие запуска — один локальный переход, согласованный с отсечением,
отдачей имени и отменой единицы. Отсечение раньше этого перехода запрещает start_unit; позже —
видит также уже принятый, но ещё не завершённый запуск и отменяет/останавливает его. Позднее
завершение отменённого start_unit не публикует ведомую единицу заново. Возврат имени и новое
чтение назначения не оживляют старую попытку: нужен новый вызов ворот. Запросы хранилища и
длительный start_unit не удерживают блокировку, которая запрещала бы подмене закрыть допуск.
Внутренний механизм синхронизации — выбор реализации; наблюдаемый порядок обязателен.
Это относится ко всем вызовам start_unit, включая перезапуск по revision. У такого перезапуска
проверяются те же ворота и may_act, но выдачи эпохи нет и состояние прежней аренды не заменяется
новым. Молчание при ещё разрешённых данных откладывает изменение revision до подтверждения;
само ожидание перезапуска не переводит действующую silent-аренду в lost.

**Подъём под той же эпохой** (ADR-0091 п. 6; М10B/03:259, М10B/04:615). Подъём упавшего процесса единицы — локальный переход,
как перезапуск по revision, без новой выдачи эпохи, и разрешён, только когда всё сразу: запуск ранее принят в этом
экземпляре; та же `observed_revision` и её тело строки; `may_write`; единица в последнем прочитанном назначении этого
воркера и не отпущена (ворота выше целиком); аренда не lost и не fenced; место единицы, если оно есть, ещё в окне записи
(N3 «place»); при `NotReadThisPass` — тот же предикат. Молчание хранилища подъёма не запрещает, пока все условия держатся;
действия устройств разрешения через `may_write` не получают (глава 3.6 «Device action»). Эпоху, взятую ради действия,
запуск наследует без новой выдачи ([глава 3.3](03.3-worker.norms.md) N3 шаг 2).

### никто и возврат имени

```
отдать_имя(): отменить незавершённые попытки запуска; seeking = имя; slot = nil; назначение забыто; содержимое замка
              присутствия переписать заново под тем же замком, worker — "" (шаг 2b N3 «старт()»; решение «Архитектора»
              2026-10-20 по разбору ревью стадии B 3–5, № 23)
пока никто: продление → нет; подмена → нет; назначение → пусто, хранилище не спрашивать; взять_эпоху → NoSlot;
            пульс → не писать; отдать слот → ничего; удержание места → ждёт как все
искать_имя(): сервер выведен (как на старте, шаг 3) → остаться никем, метки нет;
              выбирать только по допуску и таблице N3 «захватить»; given задано → только это имя с тем же допуском и таблицей захвата
              NameOnAnotherBox (включая lapsed неотданной строки чужой коробки) → метка refused;
              иной случай «кандидата нет» → после потери прежнего захвата метка nameless,
              если своего захвата ещё не было — waiting. Метка каждые CONTEND_EVERY;
              worker.name_taken — только при потере имени (отдать_имя после отнятого захвата), раз за эпизод; успешный
              захват, первый поиск и waiting её не пишут. Приоритет refused выше waiting/nameless
              given нет → любое допущенное свободное/отданное или новое <prefix>-<max+1>
воссоединиться(): добавить счётчики конфликтов аренды забываемых единиц в conflicts_carried ровно один раз; прежний итог сохранить;
                  отпустить все эпохи, забыть эти единицы, отдать_имя,
              искать_имя; имя получено → writing_allowed = true, журнал «rejoined as <имя>», worker.name_back (договор журнала событий `journal`) — только после name_taken этого эпизода
```

**Гонки.** Имя вернулось двум ждущим: захват с `cas`, второй остаётся никем и ждёт дальше; возврат имени против его отдачи контроллером — `gen` и `released` решают (N1.4, N3 «захватить»).

### отсечь(почему)

```
флаг первым: writing_allowed = false (идемпотентно); все имеющиеся аренды — fenced;
отменить все незавершённые попытки запуска;
журнал «FENCED (почему). Stopping every unit.»;
остановить все единицы, включая принятые незавершённые запуски; эпохи отпускаются при воссоединении
```

**Гонки.** Отсечение и возврат выдачи эпохи/start_unit упорядочены локальным переходом ворот;
поздний ответ не сбрасывает флаг и не восстанавливает отменённую попытку. Пульс с причиной пишется,
только пока имя ещё моё (отсечение единиц при живом слоте); после `release_name` пульса нет
(никто — N3), причина — в журнале и в метке соперника N1.4a.

### место: взять, держать, отпустить

```
взять_место([кандидаты в порядке подсистемы]):     # когда — N3 «шаг_аренды()» шаг 6: без места, не ожидая назначения
  порванные — пропустить; сначала места, чьё by = моё имя (если слот мой); брать сразу только место, которое
  «следует за именем»: by = моё имя и строка места называет мой сервер (без server_field — прежний держатель с этой

  формой → место не брать, пока он не прочтётся, причина в журнал без значения: нечитаемый пульс — не «the heartbeat is not fresh»

  пульс не читается, и его нечитаемость взятию не мешает (C03-PLACE-PULSE-LIVE-ROW-01 к C06-UNHELD-PULSE-UNREAD-01, решение «Архитектора» 2026-10-30,
  вопросы норм аудита Gemini, P/03 п. 1);

  секреты строки места — глава 3.5 N3 «открыть» (место): Sealed → кандидат не берётся, place_error.<место>: sealed (глава 3.4
  N1.1); подсистема отказала — refused, строка места не по форме — wrong;

  местом (ADR-0091 доп. (9) пп. 5–6, доп. (10); решения «Архитектора» по повторному ревью доп. (10), 2026-10-23)
держать: смена строки держимого места (в том числе секрета) — место перечитывается и открывается заново (глава 3.5);

  хранилище молчит → держится
  в окне: строгое место (lease: strict и не своё) — пока подтверждено < WRITE_WINDOW, закрыть к CLOSE_BY;
  своё место и не строгое чужое (без lease: strict) — пока < WRITE_WINDOW + unconfirmed_max (forever — без предела):

отпустить: released: "true", until: now с cas под стражем своего слота — только упорядоченная остановка, до отдачи
```

**Гонки.** Два воркера за одно место: `cas` строки удержания; строгое окно — проигравший отпускает место и единицы на нём (N3); удержание против подмены — одна запись в момент, подмена перечитывает `holder`.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/03.2-MM` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

## Перечень урока системы

Пункты главы, которым нужны ОС, хост или несколько уроков (ADR-0130 доп. (19) п. 6): они не стоят ни на одном этапе
этого урока (`forms/stages.tsv`) и уходят в урок системы. Id — прежние id чеклиста готовности; часть, отделённая от пункта
чеклиста, получает новый id, и пункт с частью называют друг друга.
