Сторона воркера объявленных таблиц ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.6: форма таблицы, имена, штампы, двери консоли и журнал — там). Для таблицы воркера из `worker.writes` воркер пишет строку заново на следующем проходе, если ключ строки ещё принадлежит его единицам. В таблице воркера из `worker.writes` воркер не удаляет строки по сроку.

Секреты в описанных здесь строках таблиц запечатаны по P/06.2; исключение для полей `*_secret` таблицы воркера — P/03.4-R100.

**`revision`** — в строке целиком воркер ведёт поле платформы revision сам (P/06.1 N1.6): прочитанная + 1, строки нет или revision не читается — 1; При записи целой строки таблицы воркера поле платформы `revision` пишет база воркера; подсистема его не задаёт. При конфликте cas записи целой строки таблицы воркера перечитать строку и вычислить `revision` заново по этому правилу.

**`list_secret`** — запрет *_secret у таблицы воркера стоит потому, что кольцо консоли таких строк не видит: обход P/06.2 N3 «перезапечатать при старте» идёт по объявленным полям, записи у консоли нет, и смена кольца оставила бы строки под старым ключом. Исключение одно — таблица списочной формы (tables: [`<t>`], P/06.1 N1.6 list_form) из worker.writes: полей она не объявляет, дверей консоли у неё нет, читатель секрета назван в secrets.readers. Её *_secret запечатывает воркер при записи текущим kid и сам перезапечатывает при старте, под своим слотом: каждая строка таблицы — правилом договора запечатывания «Перезапечатать значение», cas по прочитанной, revision не меняется; При перезапечатывании таблицы воркера списковой формы на старте по этому правилу конфликт cas требует перечитки; второй воркер, увидев новый kid, не пишет. При перезапечатывании таблицы воркера списковой формы на старте по этому правилу нечитаемую строку пропустить со строкой журнала и продолжить старт. Таблица воркера с объявленными полями `*_secret` по-прежнему даёт отказ загрузки.

Уставки двери — [runtime-constants.tsv](../../forms/runtime-constants.tsv); числитель PACE_FLOOR задан в bytes за одну секунду. DOOR_* — независимые собственные строки runtime-constants.tsv.

**`door_limits.PACE_FLOOR`** — DOOR_PACE_FLOOR_BYTES за секунду — измеряется после DOOR_PACE_AFTER

**`door_limits.busy`** — соединение сверх DOOR_CONNECTIONS или DOOR_PER_ADDRESS - 503 {error: "busy"}, без очереди; Этот отказ busy двери процесса содержит `Retry-After` с задержкой DOOR_BUSY_RETRY_AFTER секунд.


**`door_limits.slow`** — неполные строка/заголовки к DOOR_HEAD_WITHIN или средний темп ниже PACE_FLOOR после DOOR_PACE_AFTER - закрыть соединение, без ответа

**`door_limits.body`** — DOOR_BODY_BYTES; Для двери процесса тело больше DOOR_BODY_BYTES даёт 413 до чтения тела, когда заголовок доказывает размер.

**`door_limits.other`** — другие уставки называет свой урок двери; У пределов двери процесса нет настройки манифеста; дверь с другими уставками называет их в своём уроке.

**Гонки.** Две записи одной строки таблицы: `cas` (P/06.1 N3 «таблица — записать строку»); таблица воркера — один писатель, строкой целиком; консоль её не пишет (P/06.1 N1.6).


Писатель здесь — роль `<s>worker`: два экземпляра одной подсистемы пишут одну строку целиком по `cas`, конфликт — перечитать, поля другого сохранить; второй роли правило не даёт.

## N3 Проход

### старт() — шаг бюджета

```
1. манифест из каталога — обязателен (NoManifest иначе); бюджет памяти (N1.2) → иначе не стартовать
```

Остальные шаги старта (схема, экземпляр, замок присутствия, имя, захват, `previous_*`, пульс сразу, запуск подмены и цикла) — [глава 3.2](03.2-worker.norms.md) N3 «старт()».

### подмена() — отдельный поток, каждые WAKE
```
шаг цикла: STALL < age <= FOR, воркер не никто и writing_allowed:
  продлить слот первым записью с cas — только пока строка называет меня и не released (хранилище не ответило — всё ещё я;
  чужой holder или released → отсечь всё, как в шаге аренды, подмену прекратить; продлён → та же проверка схемы, что в
  шаге аренды, шаг 1); затем продлить каждую аренду —
  подтверждающим чтением строки эпохи (глава 3.2 N3 «подтвердить»), ничего не пишется;
  продлить удержание строгого места записью с cas под стражем своего слота, как на шаге аренды (глава 3.2 N3 «место: взять, держать, отпустить»): чтением срок удержания
  не продлевается;
  пульс: повторить последний пульс цикла с новым ts, stood_in: {step, for, as_of}, stand_in_renewals —
  не чаще BEAT_EVERY и только если цикл сам не написал
```

```
шаг идёт дольше FOR: done; журнал "no longer standing in for it (FOR " + decimal(FOR) + " s): its units go";
  аренды, которые больше не могут действовать, — остановить их единицы по одной
```

```
подмена никогда не оживляет отсечённого и не зовёт watchdog
```

Шаг аренды и отсечение — [глава 3.2](03.2-worker.norms.md) N3 «шаг_аренды()», «отсечь(почему)».

**Гонки.** Подмена и цикл продлевают одну строку слота: замок слота неблокирующий, кто не взял — пропускает; `cas` страхует от записи поверх чужого захвата.

Цикл вернулся из застрявшего шага: `take_unit_epoch` в нём отказано (шаг пережил подмену), пока цикл не прочтёт назначение заново.

### писать_под_слотом(key, items | удалить)

Каждая запись воркера, которая имеет значение, несёт `id`. После `ambiguous` воркер повторяет запись с тем же `id`. После `unavailable` воркер повторяет запись как есть.

Условия и запись — глава 3.2 N3 «писать_под_слотом»; здесь: кто зовёт — публикации вкладов, книг и служебных строк подсистемы; **удаления** таких строк — тоже под стражем. Ни аренда, ни потолок молчания не разрешают публиковать состояние управления: только живой свой слот.


**Гонки.** Глава 3.2: 412 `guard` требует перечитки владения. Собственное продление (в том числе подменой) сохраняет holder/gen и имя; смена держателя или поколения — потеря.

Подмена не публикует вклады, книги или состояние подсистемы. Подмена по-прежнему продлевает слот и разрешённое строгое место и повторяет пульс по P/03.4-R019; её продление строгого места остаётся записью под стражем слота.

### остановка по SIGTERM

`worker.stop_timeout` манифеста (P/02.1, 20…50 с; юниту — `TimeoutStopSec`, P/02.4 N1.1) не меньше времени остановки единиц плюс отдачи слота.

Бюджет закрытия мест после SIGTERM считается от последнего подтверждения аренды: гарантировано не меньше `WRITE_WINDOW` − `RENEW_EVERY` (40 − 8,3 ≈ 31 с, P/03.2 N1.2).


```
1. подмена — стоп; опрос — стоп
```

```
2. before_stop_all() (глава 3.1 N2); остановить все единицы; затем закрыть писателей мест
```

```
3. пульс последний раз
```

```
4. отпустить место (глава 3.2 N3 «место: взять, держать, отпустить» — под стражем своего слота, пока он мой), затем
   отдать слот (глава 3.2 N3 «отдать»)
```

```
5. after_stop() (глава 3.1 N2)
```


```
непустое назначение — та же штатная отдача: единицы остановлены, слот отдан, контроллер переносит их по «уходит» P/04;
  плановая остановка скриптом сервера — только воркера с пустым назначением и retiring (P/04 N3 «shrink()»), так
  что SIGTERM при единицах — рассинхрон скрипта и контроллера, он стоит переезда, а не потери единиц
```

```
крах молчит: ни отдачи слота, ни последнего пульса — судит контроллер (P/04)
```

**Гонки.** Остановка против подмены: подмена останавливается первой, затем отпускание места и отдача слота.

Место отпускается до отдачи слота: под отданным слотом писать нельзя (глава 3.2 N3 «писать_под_слотом»), и место, не отпущенное до отдачи, держится до LOST_AFTER + HOLD_SKEW; остановка против шага аренды — шаг доводится до записи или прерывается до неё, отдача одна; SIGKILL — не пишется ничего.

### токен двери у держателя

Форма токена `door1.<kid>.<claims>.<sig>`, строка `door/keys` и проверка у держателя двери с её «Гонками» — [договор токена двери](../../../common/ru/contracts/door-token.md) (владелец — урок P/06, глава 6.5). Выдаёт токен консоль — [P/06.5](../../../06-console/ru/spec/06.5-console.norms.md) N3 «`/where/<id>`».

Держатель, у которого есть дверь, проверяет токен по договору (P/03.4-R026): токен — из `Authorization: Bearer`, иначе из `?t=` (иная схема `Authorization` — как отсутствующий заголовок; `t` дважды или токена нет — отказ); путь — путь URL без query (договор «Место токена и путь»).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **период подмены** в пределах N1.2 (число повторов `cas` при продлении — [глава 3.2](03.2-worker.norms.md) «Решает реализация» п. 2); стенд видит только границы STALL < age ≤ FOR и пульс со `stood_in` (P/03.4-03), а не период;
2. **дополнительные поля пульса** подсистемы и что из них строки (`heartbeat.strings`); стенд судит только поля N1.1 и те, что называет манифест, прочие поля не судятся;
3. **`worker.stop_timeout`** манифеста (P/02.1, 20…50 с; юниту — `TimeoutStopSec`, P/02.4 N1.1) — его значение; нижняя граница и
   бюджет закрытия мест после SIGTERM — P/03.4-R198, P/03.4-R200; стенд видит значение только в манифесте, а останов — через P/03.4-18.
