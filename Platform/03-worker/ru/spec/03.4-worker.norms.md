## N1 Форма

**Данные** ([каталог](../../../common/data/catalog.tsv)):

- пишет: `<sub>/slots/<name>` (cas), `<sub>/holds/<place>` (guard), `<sub>/<manifest:tables>/<name>` (cas);
- читает: `platform/manifest/<sub>`, `platform/doors/<host>` (клиент объектов при голом cluster:// — договор клиента хранилища объектов door), `platform/manifest/<sub>/rev` (метка: смена манифеста — P/02.3 N3), `platform/manifest/<sub>/canonical/<form>` (форма 1; раннер воркера берёт программу воркера — P/02.3 N3 «Программа воркера из строки»), `<sub>/epoch/<id>`, `platform/schema`, `door/keys`, `/etc/w2c/tls/<role>/server.key`, `domain/member-list/<part>` и `domain/<sub>/<manifest:domain.books>` — по worker.reads (N1.7 door_admission, cross_cluster: центры членов для проверки двери mixed другого кластера; копия книги назначения — для решений подсистемы, свежесть по её полю missing), `domain/holder`, `domain/shared`, `domain/shared-docs/rev-<rev>`, `domain/view`, `domain/member-topology`, `domain/topology` (по worker.reads подсистемы).

Ключ своего комплекта `/etc/w2c/tls/<роль>` воркер читает по `W2C_ROLE`/`W2C_TLS_DIR` ([P/02.4 N1.6](../../../02-installer/ru/spec/02.4-installer.norms.md)
`roles`, [договор сертификата роли](../../../common/ru/contracts/role-certificate.md) `kit`): дверь держателя вне петли и
клиент `https://`.

### N1.1 Пульс

Объект `<sub>/heartbeats/<name>` (объект, не строка; запись — `put` объектов (договор клиента хранилища объектов `api`), чтение — `GET /v1/objects/{key}` P/05 N2). Платформа читает `worker`, `ts`, `status[].id`, `status[].phase`, `status[].epoch`, `status[].revision`, `status[].observed_revision`, `server`, `instance`, `labels`, ёмкость и запас; остальное — слова подсистемы, которые платформа не читает (`heartbeat.strings` манифеста называет, какие из них — строки).

```yaml
heartbeat:
  worker:    <имя слота>                 # ДОЛЖЕН; равен имени в ключе
  ts:        <стенные секунды писателя>  # ДОЛЖЕН; для показа и расхождения часов, не для свежести
  status:    # ДОЛЖЕН; по элементу на единицу, которую воркер ведёт
    - {id, phase, epoch, revision, observed_revision, why?, lease?, unconfirmed_s?, …слова подсистемы}
    - {id, phase: sealed, why, revision}                                  # единица запечатана (глава 3.5 N3 «открыть»):
                                                                          # эпоха не взята — epoch и observed_revision
                                                                          # отсутствуют и у впервые запечатанной, и у
                                                                          # бывавшей в работе; revision — прочитанной
                                                                          # строки; не заявка на единицу (P/08.1 N1.6 claim)
                                                                          # и не «running» (P/06.5)
    - {id, phase: unreadable, why, revision?}                             # строка ни разу не прочитана своим типом (глава
                                                                          # 3.3 N3 шаг 2): эпоха не взята — epoch и
                                                                          # observed_revision отсутствуют; why «row
                                                                          # unreadable: <причина>»; revision — если ревизия
                                                                          # строки читается; не заявка и не «running»
                                                                          # lease: unconfirmed и unconfirmed_s — секунды без
                                                                          # подтверждения аренды (глава 3.2 N1.6 silent), с
                                                                          # точностью 0,1 с, — только пока аренда не подтверждена;
                                                                          # observed_revision — revision строки,
                                                                          # под которой единица сейчас запущена; why — причина
                                                                          # платформы, когда единица не идёт (sealed — глава 3.5
                                                                          # N3 «открыть»), как fates.why P/04, не error
    # учебный обработчик testsub: фаза единицы, которую он ведёт, — running; слово подсистемы одно — n, текущее значение счётчика (книга tallies манифеста testsub
    # показывает n); иных слов у элемента нет
  server:    <непустой сервер> # допуск SERVER_NAME до presence lock, по форме входов
  instance:  <экземпляр>                 # ДОЛЖЕН
  labels:    <метки узла через запятую>
  fetched:   <SaidID(rid) через запятую, без пробелов>   # просьбы, исход которых держатель сообщил (глава 3.6 N3 «взгляд держателя»);
                                     # поля нет или пусто — ничего не сообщено; длину ограничивают FETCHED_COUNT/FETCHED_BYTES (договор отметки просьбы «fetched»)
  <capacity.from>:  <ёмкость>            # имя поля — из manifest.placement.capacity.from (умолчание capacity); когда известна
  <headroom.from>:  <запас>                # умолчание имени headroom; база считает ёмкость − Σ весов назначения, подсистема МОЖЕТ сказать своё значение, база его не перезаписывает, как schema, build; контроллер поля не читает; вес каждой единицы — по
                                     # договору пула weight, как у контроллера: поле weight.field строки, прочитанной последней сверкой,
                                     # нет поля — weight.default, нет placement.weight — 1; поле не число — единица в сумму не входит
                                     # (контроллер её не размещает, P/04)
  <place_by>:  <место>                 # только когда манифест объявил place_by — поле пульса (P/02.1 N1.2, P/04 «distinct»):
                                     # имя места, которое воркер держит (глава 3.2 N3 «place»), "" — не держит; пишет база, не подсистема
  conflicts: <целое> # сумма конфликтов нынешних единиц + conflicts_carried забытых; без повторного учёта
  started:   <момент старта>
  previous_hb, previous_instance, previous_server:  # что воркер застал под своим именем при старте, если было: previous_hb —
                                         # число ts застанного пульса, previous_instance и previous_server — его instance и server
                                         # (по ним консоль считает failover_seconds, P/06.5 N3)
  fenced:    true                        # только пока отсечён и имя ещё моё; после отдать_имя пульс не пишется
  was_fenced:    true | false            # был ли этот экземпляр отсечён с запуска; ряд worker_fenced{worker} P/06.5
  store_errors:  <число>                 # запросов к хранилищу без ответа или с ошибкой с запуска (глава 3.2 N4: store_errors + 1)
  pass_failures: <число>                 # проходов сверки (глава 3.3 N3 шаг 2), оборванных ошибкой чтения, с запуска
  unconfirmed:   <число>                 # единиц, чья аренда сейчас не подтверждена (элементы status[] с lease: unconfirmed)
  garbled_rows:  <число>                 # чтений строк своих единиц, не прочитанных своим типом (глава 3.3 N3 шаг 2), и строк
                                         # просьб и меток, не прочитанных своей формой держателем (глава 3.6 «взгляд держателя»), с запуска
  place_error:   {<место>: sealed | refused | wrong}   # место не взято или потеряно (глава 3.2 N3 «place: take», глава 3.5
                                         # «открыть»): sealed — секрет строки места не открылся, refused — отказ подсистемы,
                                         # wrong — строка места не по форме; закрытый перечень слов; запись снимается,
                                         # когда место взято или отпущено; записей не больше числа мест-кандидатов;
                                         # place_by — прежнее; смена строки держимого места — перечитать и открыть заново
  freeing:       {<том ресурса>: <байты, целое ≥ 0>}   # ответ воркера подсистемы с requests.free на просьбу ресурса своего
                                         # сервера <sub>/requests/free-<server>-<volume> (P/05 N1.4 free_ask): пока строка стоит —
                                         # байты, которые он освобождает и освобождение которых ещё не отражено в used; 0 — ничего не освобождает;
                                         # что освобождать — подсистема; поля нет — 0
                                         # пять полей выше базовый воркер пишет всегда, и при нуле; ряды P/06.5 — из них;
                                         # passes, assignment_rev нормой не вводятся
  schema, build, pending_writes:         # (P/06.6 N1.1a heartbeat: schema, build; N1.2 pending_writes) —
                                         # базовый воркер пишет schema := SCHEMA и build := BUILD (по умолчанию dev); pending_writes := 0, если подсистема не дала его; поля pending_writes нет — дренаж не safe
  stood_in:  {step, for, as_of}          # только в пульсе подмены (N3); as_of — ts последнего пульса цикла, который подмена
                                         # повторяет (возраст состояния подсистемы), у следующих повторов тот же; ts пульса —
                                         # время этого повтора
  stand_in_renewals: <число>             # только когда > 0
  # счёты держателя и заказчика; каждое поле — только когда в нём есть ненулевое:
  command_counts:  {performed, refused, expired, unknown}   # исходы вызовов действия этим экземпляром с его старта, включая отметки refused и expired, записанные до вызова
                                         # (глава 3.6 N3 «взгляд держателя»); метрика — command_counts.<outcome>
  commands_in_flight: <число>            # вызовов действия, ещё не вернувшихся (глава 3.6: не больше одного на группу)
  commands_reanswered: <число>           # исходов, записанных снова (поздний ответ после unknown — late)
  command_road:    {<by>: <гистограмма>} # дорога: от at строки просьбы до первого местного наблюдения её этим воркером;
                                         # by — operator или подсистема подателя
                                         # (первая часть штампа by «<sub>/<unit>» поданной воркером, глава 3.6 N1.5)
  command_request: {<by>: <гистограмма>} # полное время: от at строки просьбы (время подачи) до исхода; из filed (строка экземпляра) время
                                         # не выводится
  command_wait:    <гистограмма>         # ожидание у держателя: от первого местного наблюдения просьбы этим воркером до исхода, по
                                         # монотонным часам; command_request ≈ command_road + command_wait
  filings:         {filed, again, refused}   # подача просьб воркером (глава 3.6 N1.5): подана; та же подана снова; не подана
  creates:         {<outcome>: <число>}  # заказ строк другой подсистемы (глава 3.6 N1.6), закрытый перечень исходов:
                                         # created, extended, unchanged, taken, gone, expired, refused
  made_rows:       {<A>/<rows>: <число>} # заказчик: ключей под префиксом <A>/<rows>/<C>- по последнему перечислению (не чаще
                                         # между листингами не менее MADE_ROWS_MIN_INTERVAL; верхнего срока нет; надгробия и taken учитываются
histogram:   # форма гистограммы пульса
  buckets:   [<счёт>…]                   # по одному на границу ROAD_BUCKETS, счёт наблюдений не больше границы (накопительно)
  sum:       <сумма секунд>; count: <число наблюдений>
  ahead, behind: <число>                 # только у command_road, command_request: часы писателя впереди (секунды < 0 — в счёт 0)
                                         # behind: запись «раньше» не видевшего её листинга строго более чем на COMMAND_BEHIND_TOLERANCE
  ROAD_BUCKETS: [0.1, 0.25, 0.5, 1, 2, 5, 10, 30, 60, 300]
stalled:     status[].stalled: true      # единица, чей отступ запуска дошёл до RETRY_MAX (глава 3.3 N1.2 retry); иначе поля нет
said_id:     # имя просьбы в fetched — договор отметки просьбы «fetched» `said_id`
phase:
  rule: слова подсистемы; платформа знает три — running (счётчик running, соседство near), sealed и unreadable — элементы выше
cadence:
  # HEARTBEAT_EVERY: runtime-constants.tsv; первый до первого прохода, последний при остановке
  fresh_for: LOST_AFTER          # договор наблюдения «Freshness» (значение там); читатель судит по смене на своих часах
nobody: пульс не пишется, пока воркер — никто
platform_strings: [worker, server, url, instance, labels, fetched, events]   # heartbeat.strings их не называет;
                  # url — (P/06.5 N3 «/where/<id>»: url двери); fetched — (глава 3.6 N3 «взгляд держателя»)
```

Нынешний worker разрешает SERVER_NAME по форме входов до presence lock. Пустое или неверное значение даёт прежний отказ старта кодом 2: нет замка, захвата и пульса этого запуска. Пульс работающего воркера несёт разрешённый непустой server; BOX_ID и instance — другие идентичности и сервер не заменяют.

Любое имя слота по грамматике главы 3.2 (N1.4) представимо: имена файлов кодирует реализация (договор журнала событий «Имена файлов в общих деревьях»), файлового профиля, который
сужает имена, нет. Заданное имя не по грамматике или без `slot.prefix` — отказ старта с кодом 2 ([глава 3.2](03.2-worker.norms.md) N3 «старт()» шаг 2a).

### N1.2 Сроки подмены и бюджет памяти

Часть N1.2 источника: сроки подмены и бюджет памяти. `LEASE_TTL`, `LEASE_MARGIN` и прочие сроки аренды, метки соперника и
мест — [глава 3.2](03.2-worker.norms.md) N1.2; сроки цикла (`loop`, `watchdog`) — [глава 3.3](03.3-worker.norms.md) N1.2.

```yaml
stand_in:
  STALL: (LEASE_TTL - LEASE_MARGIN) / 2 # шаг застрял строго после этого срока
  WAKE: <= (LEASE_TTL - LEASE_MARGIN) / 4 # верхняя граница, не обязательное равенство
  FOR:          договор файла окружения «Константы и юниты» (значение там)   # с; дольше не подменяет: единицы уходят
  # BEAT_EVERY: runtime-constants.tsv, повтор пульса подменой
memory:
  rule: CAPACITY × unit_mb + base_mb ≤ WORKER_MEMORY_MB, иначе процесс не стартует; без unit_mb, CAPACITY или WORKER_MEMORY_MB — не проверяется, ёмкость — capacity.default: воркеру на домене файла роли нет, значений нет
        # одна формула бюджета на модуль: CAPACITY — ёмкость воркера в единицах веса (договор пула capacity),
        # unit_mb — МиБ на единицу веса, base_mb — МиБ процесса (нет — 0), WORKER_MEMORY_MB — окружение процесса
```

### N1.6 Таблицы воркера

Сторона воркера объявленных таблиц ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.6:
форма таблицы, имена, штампы, двери консоли и журнал — там). Строка из N1.6 источника:

```yaml
rows:       <sub>/<t>/<имя>; писатель — консоль; таблица из worker.writes (P/02.5 N1.4) — таблица воркера, без объявленных полей *_secret (P/02.1 N1.2a; исключение — list_secret ниже): он пишет строку целиком с cas,
            консоль только читает (GET с полями), POST → 403 denied «written by its worker»; DELETE оператора → 200 с cas (P/06.1
            N1.6); строку, чей ключ ещё относится к его единицам, воркер пишет заново следующим проходом; удаления воркером по сроку
            нет; PUT → 405 как неподдержанный метод; секреты запечатаны (P/06.2)
revision:   в строке целиком воркер ведёт поле платформы revision сам (P/06.1 N1.6): прочитанная + 1, строки нет или revision не читается — 1; поле пишет база воркера, подсистема его не задаёт;
            конфликт cas — перечитать и посчитать заново
list_secret: запрет *_secret у таблицы воркера стоит потому, что кольцо консоли таких строк не видит: обход P/06.2 N3 «перезапечатать при старте» идёт по объявленным
            полям, записи у консоли нет, и смена кольца оставила бы строки под старым ключом. Исключение одно — таблица списочной формы (tables: [<t>], P/06.1 N1.6
            list_form) из worker.writes: полей она не объявляет, дверей консоли у неё нет, читатель секрета назван в secrets.readers. Её *_secret запечатывает воркер при записи
            текущим kid и сам перезапечатывает при старте, под своим слотом: каждая строка таблицы — правилом договора запечатывания «Перезапечатать значение», cas по прочитанной,
            revision не меняется; конфликт cas — перечитать, второй воркер видит новый kid и не пишет; нечитаемая строка — пропустить, строка лога, старт не прерывается.
            Таблица с объявленными полями *_secret — по-прежнему отказ загрузки
```

### N1.7 Дверь процесса: пределы, адрес, допуск, CORS

Общая норма двери процесса подсистемы — двери держателя (N3 «токен двери у держателя»), шлюза и прочих дверей, которые
слушает процесс подсистемы. Дверь консоли кластера — своя норма (P/06.3, P/06.5), не эта.

Уставки двери — [runtime-constants.tsv](../../forms/runtime-constants.tsv); числитель PACE_FLOOR задан в bytes за одну секунду.

```yaml
# DOOR_* — независимые собственные строки runtime-constants.tsv.
door_limits:
  PACE_FLOOR: DOOR_PACE_FLOOR_BYTES за секунду  # измеряется после DOOR_PACE_AFTER
  busy: соединение сверх DOOR_CONNECTIONS или DOOR_PER_ADDRESS - 503 {error: "busy"}, без очереди; Retry-After — process_busy в forms/refusals.tsv
  slow: неполные строка/заголовки к DOOR_HEAD_WITHIN или средний темп ниже PACE_FLOOR после DOOR_PACE_AFTER - закрыть соединение, без ответа
  body: DOOR_BODY_BYTES; больше - 413 до чтения, когда это доказано заголовком
  other: другие уставки называет свой урок двери; настройки манифеста нет
```

**Гонки.** Две записи одной строки таблицы: `cas` (P/06.1 N3 «таблица — записать строку»); таблица воркера — один писатель, строкой целиком; консоль её не пишет (P/06.1 N1.6). Писатель здесь — роль `<s>worker`: два экземпляра одной подсистемы пишут одну строку целиком по `cas`, конфликт — перечитать, поля другого сохранить; второй роли правило не даёт.

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

### подмена() — отдельный поток, каждые WAKE

```
шаг цикла: STALL < age <= FOR, воркер не никто и writing_allowed:
  продлить слот первым записью с cas — только пока строка называет меня и не released (хранилище не ответило — всё ещё я;
  чужой holder или released → отсечь всё, как в шаге аренды, подмену прекратить; продлён → та же проверка схемы, что в
  шаге аренды, шаг 1); затем продлить каждую аренду —
  подтверждающим чтением строки эпохи (глава 3.2 N3 «подтвердить»), ничего не пишется;
  продлить удержание строгого места записью с cas под стражем своего слота, как на шаге аренды (глава 3.2 N3 «место: взять, держать, отпустить»): чтением срок удержания
  не продлевается;
  пульс: повторить последний пульс цикла с новым ts, stood_in: {step, for, as_of}, stand_in_renewals —
  не чаще BEAT_EVERY и только если цикл сам не написал
шаг идёт дольше FOR: done; журнал "no longer standing in for it (FOR " + decimal(FOR) + " s): its units go";
  аренды, которые больше не могут действовать, — остановить их единицы по одной
подмена никогда не оживляет отсечённого и не зовёт watchdog
```

Шаг аренды и отсечение — [глава 3.2](03.2-worker.norms.md) N3 «шаг_аренды()», «отсечь(почему)».

**Гонки.** Подмена и цикл продлевают одну строку слота: замок слота неблокирующий, кто не взял — пропускает; `cas` страхует от записи поверх чужого захвата. Цикл вернулся из застрявшего шага: `take_unit_epoch` в нём отказано (шаг пережил подмену), пока цикл не прочтёт назначение заново.

### писать_под_слотом(key, items | удалить)

Условия и запись — глава 3.2 N3 «писать_под_слотом»; здесь: кто зовёт — публикации вкладов, книг и служебных строк подсистемы; **удаления** таких строк — тоже под стражем. Ни аренда, ни потолок молчания не разрешают публиковать состояние управления: только живой свой слот.

**Гонки.** Глава 3.2: 412 `guard` требует перечитки владения. Собственное продление (в том числе подменой)
сохраняет holder/gen и имя; смена держателя или поколения — потеря. Подмена не публикует вклады, книги или состояние подсистемы. Она по-прежнему продлевает слот и разрешённое strict-место и повторяет heartbeat по R019; продление strict-места — запись под слотом, не исключение из его guard.

### остановка по SIGTERM

```
1. подмена — стоп; опрос — стоп
2. before_stop_all() (глава 3.1 N2); остановить все единицы; затем закрыть писателей мест
3. пульс последний раз
4. отпустить место (глава 3.2 N3 «место: взять, держать, отпустить» — под стражем своего слота, пока он мой), затем
   отдать слот (глава 3.2 N3 «отдать»)
5. after_stop() (глава 3.1 N2)
непустое назначение — та же штатная отдача: единицы остановлены, слот отдан, контроллер переносит их по «уходит» P/04;
  плановая остановка скриптом сервера — только воркера с пустым назначением и retiring (P/04 N3 «shrink()»), так
  что SIGTERM при единицах — рассинхрон скрипта и контроллера, он стоит переезда, а не потери единиц
крах молчит: ни отдачи слота, ни последнего пульса — судит контроллер (P/04)
```

**Гонки.** Остановка против подмены: подмена останавливается первой, затем отпускание места и отдача слота. Место
отпускается до отдачи слота: под отданным слотом писать нельзя (глава 3.2 N3 «писать_под_слотом»), и место, не
отпущенное до отдачи, держится до LOST_AFTER + HOLD_SKEW; остановка против шага аренды — шаг доводится до записи или прерывается до неё, отдача одна; SIGKILL — не пишется ничего (сц. 05 [приёмки главы 3.2](../acceptance/2/README.md); только для судьи: сценарии главы 3.2).

### Свидетельства вне TSV

Строка epoch доказывает выданный номер, но не сам вызов stop_unit или прекращение внешней записи.

или чтение реализации её владельцем; авторский обзор документов этим свидетельством не является.

| Нормы | Предмет и вмешательство | Наблюдаемый результат |
|---|---|---|
| P/03.4-01, 02 | объект пульса до первого прохода, через 10 с, при SIGTERM и после потери имени | поля N1.1, ритм, никто не пишет под прежним именем |

| P/03.4-05, 06 | SIGTERM против подмены, SIGKILL, недостаточный/достаточный бюджет памяти | порядок остановки и отсутствие уборки при крахе; отказ до старта по бюджету |
