Уставки — [runtime-constants.tsv](../../forms/runtime-constants.tsv).

HEARTBEAT_EVERY, PASS_SHARE, RETRY_MIN, RETRY_MAX: runtime-constants.tsv

**`POLL`.** выбор реализации для паузы без событий или long polling; не фиксированный срок

**`WAKE_GAP`.** WAKE_GAP_MS / 1000. **`WAKE_GAP`.** Преобразование даёт точные секунды без округления. **`WAKE_GAP`.** ранний проход не раньше этой паузы

При long polling ранний проход идёт не чаще PASS_SHARE длительностей прохода


**`watchdog.notify`.** из цикла, не из подмены. **`watchdog.notify`.** WatchdogSec юнита — договор файла окружения «Константы и юниты»

**`retry`.** отступ повтора неудачного запуска единицы **`retry.rule`.** пауза растёт экспонентой от RETRY_MIN до RETRY_MAX с обязательным дрожанием (форма экспоненты и дрожания — «Решает реализация» п. 3).

**`retry.rule`.** считаются только неудачи запуска и работы единицы — переезд, отсечение и новое имя счёт не меняют. **`retry.rule`.** счёт обнуляется при любом из трёх: после RETRY_MAX непрерывной устойчивой работы, по слову подсистемы (её ответ «устойчива»), когда единицы подтверждённо нет в желаемом (назначении) — неподтверждённое чтение назначения не отсутствие. **`retry.rule`.** переезд неудачей не считается; ушедшая с воркера единица обнуляет счёт, когда подтверждено её отсутствие в назначении.


**`retry.stalled`.** пауза дошла до RETRY_MAX — status[].stalled: true в пульсе (глава 3.4 N1.1), пока счёт не обнулён. **`retry.stalled`.** подсистема спрашивает словом библиотеки stalled(id) (глава 3.1 N2)

## N3 Проход

### цикл() — один оборот

```
1. если никто или не writing_allowed: воссоединиться() (глава 3.2 N3 «никто и возврат имени»);
   имя не получено → только поиск/метка соперника и ожидание; шаги 2–5 не выполнять
```

```
2. проход сверки: прочитать назначение; назначенная единица без строки или с надгробием не запускается до следующего
   прохода (строка размещения — дело контроллера); для каждой назначенной единицы, которой нет: открыть секреты
   (глава 3.5 N3 «открыть»: не открылись — Sealed, эпоху не брать) → взять_эпоху →
   снова проверить ворота и may_act непосредственно перед start_unit; отказ → не запускать;
```

```
   ведомой нет в назначении → отменить её незавершённые запуски, stop_unit;
```

```
   revision вырос → при открытых воротах и may_act принять попытку перезапуска: stop_unit (подсистема узнаёт словом restarting(id), глава 3.1 N2) и start
   под той же эпохой/арендой через локальный переход главы 3.2 N3 «take_unit_epoch», без новой выдачи и без сброса last;
```

```
revision вырос и (ворота закрыты или may_act ложно) → изменение revision ждёт;
прежняя единица идёт лишь пока разрешает may_write;
```


```
   born сменился (строка удалена и создана заново — новая жизнь, договор проверки строки, born) → stop_unit, отпустить
   эпоху и взять её заново — новая выдача, новые привязки `of`, как у удалённой и созданной (сц. 06); состояние
   единицы новая жизнь пишет со своими born и revision (глава 3.6 N1.7);
```

```
   упавший процесс единицы (ответ подсистемы) → подъём под той же эпохой (глава 3.2 N3 «взять_эпоху(единица)», подъём)
   после паузы retry N1.2;
```


```
строка своей единицы не читается своим типом (договор проверки строки «Строка единицы») → запущенная единица идёт с последней прочитанной строкой,
   `why` элемента пульса — «row unreadable: <причина>»;
```

```
строка назначенной единицы не читается своим типом, и этот воркер ни разу не прочитал её этим типом
→ единица не запускается, эпоха не берётся;
элемент пульса — {id, phase: "unreadable", why: "row unreadable: <причина>", revision?},
без epoch и observed_revision; revision — ревизия строки, если та читается, иначе revision отсутствует (глава 3.4 N1.1);
```
