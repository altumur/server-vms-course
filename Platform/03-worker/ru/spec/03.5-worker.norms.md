## N1 Форма

**Время.** Полей времени у главы нет.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- читает: `/etc/w2c/secrets/platform.key`, `<sub>/<manifest:unit.rows>/<id>`.
Кольцо воркер находит по пути `SECRETS_KEY` (пишет установщик — [P/02.4 N1.9](../../../02-installer/ru/spec/02.4-installer.norms.md)).


Из строки единицы воркер читает конверты `*_secret`.

### N1.2 Конверт и кольцо: сторона воркера

Воркер открывает конверт по договору запечатывания — разделы «[Конверт](../../../common/ru/contracts/sealing.md#конверт)» и
«[Путь AAD](../../../common/ru/contracts/sealing.md#путь-aad)»: ключом `kid` конверта, с единственным AAD своего места.

Воркер читает кольцо из файла `SECRETS_KEY` по разделу «[Файл кольца](../../../common/ru/contracts/sealing.md#файл-кольца)».

Кто держит ключ
(`holders`) и смена кольца (`rotate`) — [P/06.2 N1.2](../../../06-console/ru/spec/06.2-console.norms.md).

Отказ воркера при отсутствии ключа — `open_without`. **`open_without`.** конверт без ключа / с чужим kid → Sealed «sealed and this process has no key» / «sealed with key `<kid>`, which this process does not hold». **`open_without`.** Когда для конверта единицы нет ключа или его `kid` чужой, единица не запускается, причина — в её статусе. В сообщении open_without `<kid>` заменяется именем ключа конверта, ключевые байты не выводятся.

## N3 Проход

### открыть (воркер, start_unit)

```
до взять_эпоху (глава 3.3 N3 «цикл», шаг 2): прочитать строку;
```

```
для каждого *_secret на любой глубине: не конверт → как есть
(значение записано нынешним development mode без SECRETS_KEY);
```

```
для каждого *_secret на любой глубине: конверт → открыть его ключом kid
с единственным AAD договора запечатывания для ключа строки и полного пути; старые способы не пробовать;
```


```
  нет ключа (SECRETS_KEY не задан) / чужой kid / не открывается    → Sealed: эпоху не брать, единицу не запускать; элемент
                                                                     status — {id, phase: "sealed", why, revision}: why "the
                                                                     password does not open: <причина>" (P/06.2 N1.4 heartbeat); epoch и
                                                                     observed_revision нет, revision — прочитанной строки
                                                                     (глава 3.4 N1.1)
```

Значение каждого `*_secret` строки единицы — переданное как есть (P/03.5-R033) или открытое (P/03.5-R034) — получает только его получатель (драйвер, клиент).

```
для секрета единицы, поданного конвертом по P/03.5-R034:
в памяти воркера, пульсе и логах — только конверт секрета единицы, а не открытое значение;
открытое значение секрета единицы получает только получатель (P/03.5-R026);
```


```
место (глава 3.2 N3 «place: take», держать): при взятии места и при смене строки держимого места — открыть *_secret
строки таблицы мест тем же правилом и тем же AAD договора запечатывания (ключ строки таблицы и полный путь), что строку
единицы;
```

```
Sealed → место не берётся (держимое — уходит с места, leave_place главы 3.2 N3 «hold»; released не пишется), place_error.<место>: sealed в пульсе (глава 3.4 N1.1),
причина — у места, не у единицы;
```

```
открытое значение секрета места → только в памяти и вызове подсистемы;
```

Шаг 2 цикла — [глава 3.3](03.3-worker.norms.md) N3 «цикл», `take_unit_epoch` — [глава 3.2](03.2-worker.norms.md) N3.

AAD —
[договор запечатывания](../../../common/ru/contracts/sealing.md) «Путь AAD».

`why` элемента `status` пульса — [глава 3.4](03.4-worker.norms.md)
N1.1 и [P/06.2 N1.4](../../../06-console/ru/spec/06.2-console.norms.md) `heartbeat`.

**Гонки.** Нет: чтение.


Кольцо сменилось между запечатыванием и открытием — `kid` конверта называет ключ: открывается им или `Sealed` с причиной.

Каталога приёмки у главы нет: воркера на стенде главы 6.2 нет. Швы SDK покрывают ветви без ключа и без конверта P/03.5-R025, P/03.5-R026, P/03.5-R033, P/03.5-R035; проверяются лишь перечисленные наблюдения; проверка пульса/журнала не читает память.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/03.5-MM` — то, на что ссылаются дельты решений,
находки и записи окон:

- [ ] **P/03.5-01** [test, reading] воркер открывает конверт `enc:v2` по [договору запечатывания](../../../common/ru/contracts/sealing.md) с единственным AAD своего места (ключ строки и полный путь), старые способы не пробует; переставленный между строками и полями конверт не открывается — векторы [`open.tsv`](../../../common/vectors/sealing/open.tsv) (только для судьи: векторы открытия для P/03.5-R005, P/03.5-R034) своей функцией открытия; открытие на строке единицы — чтением N3 «открыть» и теста реализации: воркера на стенде главы 6.2 нет (Требования: P/03.5-R005, P/03.5-R028, P/03.5-R034).
- [ ] **P/03.5-02** [test, reading] открывает получатель в последний момент — до `take_unit_epoch`, значение только получателю, в памяти, пульсе и логах — конверт; без ключа, с чужим `kid` или неоткрывающийся конверт — единица стоит с причиной (`Sealed`, `why` в статусе, ключевые байты не выводятся) — швы `s1-sealed-unit-no-epoch` (`Sealed` без эпохи и наблюдаемой ревизии, открытого текста в пульсе и журнале нет) и `s2-plain-unit` [главы](../../acceptance/5/seams.tsv) (`CALL worker-open-unit`; только для судьи: швы главы); прочее — проверяется чтением N3 «открыть»: воркера на стенде главы 6.2 нет (Требования: P/03.5-R022, P/03.5-R009, P/03.5-R025, P/03.5-R026, P/03.5-R033, P/03.5-R034, P/03.5-R035).
- [ ] **P/03.5-03** [reading] секрет строки места открывается при взятии места тем же правилом и AAD, Sealed — место не берётся, причина у места — стенд не готовит исключительного места и строки места с неоткрывающимся секретом — чтением; сценарии P/04 и P/03.2 — когда учебная подсистема получит такое место (долг) (Требования: P/03.5-R027, P/03.5-R036, P/03.5-R037).
