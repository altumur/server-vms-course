Стенд, словарь директив и дверей — [общий README приёмки](../../../common/acceptance/README.md#словарь-директив-и-дверей).
Норма главы — [`03.4-worker.norms.md`](../../spec/03.4-worker.norms.md) Н5. Сценарий перенесён из приёмки
М10/05 (стадия B, ADR-0083 доп. (1): без изменения
поведения); номер сценария и шагов — прежние. Один сценарий / 8 шагов.

Сценарий на стенде из процессов `testsub` реализации: хранилище, консоль `testsub`, контроллер `testsub` и воркеры `testsub` (учебный воркер счётчиков), которыми управляет раннер. Каталог стенда — две спеки, `testsub` и `testsub2`, в порядке раздела «Стенд» общего README приёмки (сверка python и go М10/3–5, п. 24). Наблюдение — строки через дверь хранилища P/01.1; пульс (объект) здесь не читается. Контроллер — сосед по контракту (каталог данных, `lifecycle.md` P/04), не нормы P/04 (план переноса урока 3, В2): шаг 8 видит, что размещение снято контроллером с причиной.

## Границы сценариев

Между сценариями раннер останавливает все процессы, которые запустил, сбрасывает хранилище (строки и объекты) и переменные `$имя`: каждый сценарий начинается с пустого хранилища, слота `w-1` нет, консоль перезапущена.

## Точная подготовка и завершение

Каждый сценарий получает новое изолированное хранилище, новую консоль, пустую память id хранилища
и пустые заявки POST, а также очищенные объекты пульсов/контроллера/соперников и переменные раннера.
Перед началом установлен каталог `testsub` и `testsub2` из общих testdata и служебные метки спек.
Нет чужих контроллеров, ресурсов, запасных процессов и таймеров запуска. Дверь консоли открыта с петли;
роль чтения хранилища имеет доступ к testsub/ и testsub2/. Подготовка использует отдельные административные права.

Все воркеры сценария имеют постоянную BOX_ID стенда и server = srv-a; каждая копия получает новый
instance. Имя передаётся подстановкой `{name}` директивы (README приёмки М10/01 «Стенд»). Убывающий бюджет памяти не провоцируется: выбранные
CAPACITY/WORKER_MEMORY_MB должны удовлетворять Н1.2 главы. Обычная конфигурация testsub использует
safe-умолчания; параметры подмены и сроков не ускоряются ради теста.

@start подтверждает запуск процесса, готовность слота проверяют следующие @until.
@sigterm посылает сигнал нужному процессу и **ждёт подтверждённого завершения**;
таймаут/неверный процесс — отказ раннера, а не ok.
После сценария раннер завершает и дожидается всех созданных процессов,
лишь затем удаляет состояние. Параллельный сценарий использует другие порты и каталоги.

## Точное сравнение и границы

Заголовок TSV и комментарии пропускаются. Номера шагов непрерывны внутри сценария.
@until повторяет только вложенный запрос и сравнение до предела; исчерпанный предел — FAIL.
Новые связи переменных каждой попытки сравнения сначала временные: они становятся общими только
после совпадения кода и всего expect. Неуспех любого поля, типа, элемента массива или кода отбрасывает все новые связи этой
попытки; уже общие связи не меняются. Порядок обхода полей результата не меняет.
@any требует наличия поля; @absent — отсутствия; ~текст — строкового вхождения.
JSON-типы точны, true не равно 1; объекты сравниваются по указанным полям рекурсивно,
массивы — по числу, порядку и значениям элементов. Ожидание одного кода не требует пустого тела.
Полный HTTP-ответ дополнительно соответствует контракту хранилища (P/01.1) или единиц (P/06, глава 6.1).

Сценарии наблюдают строки и HTTP-ответы, не содержимое объектов пульса и не фактические внешние записи
единицы. Остальные свидетельства — Н5 норм главы, включая первый/последний пульс, подмену и бюджет.

## Проверки вне TSV после прогона 25

Для unknown server оставить известные BOX_ID/instance и взятое имя, но не задавать сервер;
в отдельной спеке включить places.server_field и places.lease: strict. Прочитать пульс по двери объектов или проверить
формирование объекта чтением: server присутствует и равен "", server_unsaid содержит текст
ADR-0029, все места строгие. Отдельный вариант с известным сервером даёт непустой server и не
содержит server_unsaid. Подстановка BOX_ID вместо сервера не проходит. Обычный TSV задаёт srv-a
и эту ветвь не наблюдает.

## Дополнительная проверка класса ошибок прогона 36 (Kimi)

Сц. 03 не читает объект пульса и не доказывает его период (Н1.1 главы).

Это предмет ручной проверки спецификации и будущей проверки реализации. Подготовленные запросы, чтение и конечные модели автора не являются выполненным стендовым испытанием.
