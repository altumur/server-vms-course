# P/10 — инструкция для реализации

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — [`../10-domain-console.md`](../10-domain-console.md).

## Задача

Реализовать процесс `domainconsole` на коробке держателя на языке `<LANG>`; пройти приёмку Н5 и закрыть чеклист
готовности. Всего 15 норм: P/10-01…15; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv). Урок собран из
уроков М11/1, 3, 4, 6, 8, 9, 11, 12 (сторона консоли домена) (стадия B, ADR-0083 доп. (1), (14)). Процесс `domain` —
урок [P/08](../../08-domain/spec/08-domain.README.md), агент — урок [P/09](../../09-agent/spec/09-agent.README.md), пересылка
консоли кластера — глава P/06.7.

- Двери чтения `GET /domain`, `/domain/<sub>/<rows>`, `/domain/shadow`, `/domain/members`, `/domain/topology`,
  `/domain/placement*`, `/domain/grants`, `/domain/shared`, `/domain/alarms`.
- Передача правок, дверей людей и входа процессу `domain`.
- Дверь роли TLS и «принять консолью»; сторожевая по `domain/grants/domain`.
- Страница держателя и `door.pass` на домене.

## Входы и их приоритет

- Канон — [нормы](10-domain-console.norms.md), включая Н0, абзац «Данные», порядок Н3 и отказы Н4. Вход и вывод команды
  приёмки — Н5.
- [HTTP-контракт](10-domain-console.api.openapi.yaml) выражает формы своих дверей и коды перехода 2; ответы процесса
  `domain` — [OpenAPI урока P/08](../../08-domain/spec/08-domain.api.openapi.yaml) (ссылкой).
- Договоры: [пересылки](../../common/contracts/forwarding.md), [сторожевой и передачи](../../common/contracts/gate-and-pass.md),
  [токена домена](../../common/contracts/domain-token.md), [права](../../common/contracts/may.md), [сертификата
  роли](../../common/contracts/role-certificate.md), [`peer`](../../common/contracts/peer.md), [журнала
  событий](../../common/contracts/event-journal.md).
- [Приёмка](../acceptance/README.md) — стенд нескольких кластеров ([общий README
  приёмки](../../common/acceptance/README.md#стенд-домена), раздел «Стенд домена») и вектор
  [`alarms`](../vectors/alarms/README.md). Флаги, окружение, коды выхода — [`../lifecycle.md`](../lifecycle.md).
- [Лекция](../10-domain-console.md) объясняет причины.

Внутренние интерфейсы, типы и устройство — выбор реализации. Имя и шаблон вызова команды `alarms` — пункт «Решает
реализация» норм.

**При расхождении.** Назвать id нормы, вход, начальное состояние, ожидаемый и полученный исход. Дефект реализации —
вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел нормы — вход, для
которого норма не даёт однозначного исхода: записать место и контрпример и передать «Спецификации» с предложением.
Инструкция не вводит новый отказ. Изменение приёмки записать в `corrections.tsv` её каталога.

## Что создать

- Двери чтения Н1.2 и список тревог Н1.8 с функцией `alarms` (команда `alarms`).
- Передачу Н1.3: каждая строка списка дверей домена, кроме своих чтений и `door.pass`, — процессу `domain`
  (`SIGNER_URL`), ответ как пришёл; двери людей Н1.3а.
- Дверь роли Н1.4 (`server.role`) и «принять консолью»; сторожевую Н1.5 (шаги `identity` 3, 4; `may` по
  `domain/grants/domain`; `/session` с грантами).
- `door.pass` на домене Н1.6; страница держателя Н1.7.
- Старт Н1.1: сторона читателя строки спеки, проверка схемы, готовность — порт.

## Порядок работы

Это предлагаемый порядок, а не обязательное устройство кода.

1. `alarms` по вектору [`alarms`](../vectors/alarms/README.md).
2. Двери Н2 чтения и их отказы Н4.
3. Сторожевая консоли домена; `/session` с грантами.
4. Передача процессу; «принять консолью»; дверь роли.
5. Страница держателя и `door.pass` на домене.
6. Стенд: сценарии 02, 05 [приёмки урока](../acceptance/README.md) и сторона консоли домена в сценариях глав урока P/08
   (таблица соседей на стенде Н5).

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.8 | Выбросить тревоги молчащего члена | Тревоги последнего отчёта остаются, плюс строка молчания. |
| Н1.3 | Пересчитать `deposed`, `frozen`, `standby` процесса | Ответ процесса — как пришёл (P/08.0 Н1.8 `answers`). |
| Н1.2в | Отдать топологию из вида | Из строки `domain/topology`: новый `rev` сразу после PUT (T1). |
| Н1.4 | Возобновлять TLS-сессии у двери роли | Билеты и PSK выключены: каждое соединение — полное рукопожатие по текущему объединению. |
| Н1.4 | Передать пришедший `X-W2C-Client` | Снаружи пришедший снимается, как `X-User`; ставит консоль сама. |

## Проверки границ

Строк держателя консоль домена не пишет: правки передаёт процессу `domain` (Н1.3; права `domainconsole` — чтение
`domain/*`). Историю тревог пишет процесс `domain` (глава 8.9); список её только читает. Исполнение правок и проверка
личности у процесса — урок P/08; пересылка консоли кластера — глава P/06.7.

## Готово, когда

- Сценарии 02, 05 приёмки урока проходят; вектор `alarms` — 15 строк, строка 15 — код 2.
- Описание реализации называет команду `alarms`.
- Нормативный чеклист P/10-01…15 закрыт; пункты «проверяется чтением» (P/10-03, -10, -11, -15 и части прочих по Н5)
  названы отдельно.

Успех TSV подтверждает только наблюдаемые им ветви: TLS между кластерами, `door.pass` на домене и срок передачи он не
доказывает.
