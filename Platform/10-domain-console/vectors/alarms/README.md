# Векторы списка тревог

Векторы функции `alarms(input)` консоли домена — список тревог членов у держателя: состояние каждого члена (`ok`,
`silent`, `not_reporting`, `never`, `unreadable`), строка молчания, свидетели, часы домена у строк страницы, история без
повторов, окно и фраза `sentence`. Владелец — урок P/10 ([нормы](../../spec/10-domain-console.norms.md) Н1.8, Н3 `alarms`,
Н5 `alarms`; решение «Архитектора» по разбору ревью стадии A 8–10, № 8: функция `alarms` и её вектор — у консоли домена).
Историю, которую функция читает, пишет процесс `domain` ([P/08.9](../../../08-domain/spec/08.9-domain.norms.md) Н1.9);
страницу тревог члена — агент ([P/09.1](../../../09-agent/spec/09.1-agent.norms.md) Н1.10). Байты пишет «Спецификация»
(ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `alarms` приёмки М11/11 (`inputs/alarms-*.json`, сц. 04) без изменения байтов
значений: сняты только пробелы и переводы строк вне строк JSON; `case` — имя файла входа; ожидание `ok <JSON>` — ячейка
`expect` без пробелов вне строк, `@exit 2` — строкой (план переноса урока 10, § 3, В7; решение «Архитектора» по планам
8–10, ADR-0083 доп. (14) п. 17). Сценарий 04 приёмки М11/11 и его входы `alarms-*` снимаются переносом урока 10: таблица —
единственный источник этих случаев.

## Прогон

Без стенда: функция реализации (команда `alarms`, нормы «Решает реализация» п. 1) получает вход (колонка `input`) и
даёт вывод; `expect` — подмножество полей вывода (`@absent` — поля нет) или `@exit 2` (вход не по форме: нормы Н5
`exit`). Строка `@exit 2` в таблице одна — `alarms-15-lost-after-negative` (`lost_after` не > 0). Страница не по форме
P/09.1 Н1.10 — исход 0 `unreadable`, не код 2.

## Вход

- `now` = 1760000000, окно — сутки (`since` = `now` − 86400, `until` = `now`), `lost_after` 45 (кроме строки 15);
- члены: `last_report` и `received_at` — часы домена, `sent_at` — часы члена того же отчёта (у векторов — `page.to`, при
  `page` не объектом — `null`), `page` — страница P/09.1 Н1.10 (`"garbled"` — не читается; `null` — нет), `history` —
  объект истории P/08.9 Н1.9;
- `witnesses` — объекты свидетелей `{sub, name, ts, cluster, units}` (нормы Н1.8 `witness`).

Имена подсистем и единиц во входе (`testsub`, `testsub/c1`) — данные входа: от байтов спек каталога вектор не зависит.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки М11.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 15 строк: 14 вычислено, 1 `@exit 2` | `input` — вход команды `alarms` текстом JSON → `expect`: `{events, members, complete, sentence}` или его часть |

| Строки | Что проверяют |
|---|---|
| 01–10 | все ответили; шторм — `truncated`, тихий член виден; молчит — строка молчания и тревоги последнего отчёта; свидетель позже отчёта — `not_reporting`, раньше — `silent`; ни разу и не читается; история без повторов, `history_cut_before`; окно; поправка часов; два свидетеля |
| 11–14 | сверка М11 09–12: `cut_before` 0 — история с начала, `history_cut_before` нет (A13); строка страницы не `alarm` — страница `unreadable` (A15); повтор `same_line` в одной странице — первая (A16); ничья свидетелей по `alive_at` — меньший `alive_via` (A17) |
| 15 | `lost_after` −1 — вход не по форме, код 2 (H14) |

Векторы проверены прогонами реализаций приёмки М11/11 (прогон 41, сверка М11 09–12) и по тексту норм; при расхождении
прав норма, вектор правит «Спецификация».
