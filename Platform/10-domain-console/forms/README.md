# P/10 input and refusal forms

This English text is the source; ru/forms/README.md is its Russian translation for people, not in the export. These forms express the existing norms.

## Inputs and constants

[daemon-flags.tsv](daemon-flags.tsv) projects 20 existing environment inputs. The common header is flag,type,default,default_text,required,commands,bad,norm. $NAME remains environment; commands=domainconsole denotes the process. The setting channel stays environment-only. The launcher applies file precedence and role/instance/box/server validation. Alias equality, path resolution, TLS kits, listener admission, ports and own-client name checks retain their complete imported contracts, including the distinction between an implicit wildcard and an explicit address.

TIMEZONE uses exactly the IANA-name spelling of the environment contract: empty or out of form refuses start with code 2, but there is no zone-database lookup. W2C_DEBUG_PERSON retains every identity/credential/loopback guard of the gate contract; it creates no forwarding credential. DOMAIN_CONSOLE_HOST/PORT is the main door; this form introduces no callback listener or callback port.

[runtime-constants.tsv](runtime-constants.tsv) has the common header name,value,unit,norm,meaning and projects three owned positive integer limits. DOMAIN_PAGE_MEMBERS is the existing member bound of the aggregate view and member-list pages; RELAY_MEMBERS_MAX refers to the [P/08.3 writer limit](../../08-domain/forms/runtime-constants.tsv), without a second value row here. LOST_AFTER is the imported observation silence threshold; ALARMS_WINDOW is the existing default window, in seconds. They are not environment settings. Cursor contents, projections, complete/contested data, report clocks and witness calculations remain their source contracts.

## Refusal catalogue

[refusals.tsv](refusals.tsv) defines 16 N4 rows as 25 code projections. word/outcome/cause define the refusal word, outcome and condition; diagnostic/caller are absent (-) for those N4 rows. chapter=10 and row define stable addresses; a compound code yields several projections with the same row. Rows 17–23 project existing manifest/rights/schema startup admission, TIMEZONE, implicit-wildcard/kit admission, alias conflicts, the prohibited callback the trusted alarms input and unavailable pass policy. They do not add HTTP doors or startup refusal conditions.

The header is chapter,row,name,surface,code,kind,fields,headers,log,norm,word,response_schema,cause,outcome,diagnostic,caller, with literal TAB separators. HTTP response_schema names an OpenAPI component; fields lists directly required/directly declared properties. A composed or referenced schema still applies in full even when fields is -. The names GateDenied, ConsoleRefusal and DomainPassRefusal only reference existing published schemas. DomainPassRefusal includes the existing manifest-mapped ProblemRefusal of the second kind, so a catalogue row does not force error/detail on a code/message body. It does not rewrite a worker reply. The full pass contract also retains its independently specified deadline/status and dynamic headers.

The word cell is a source catalogue index, never a free choice of error for a condition. The transition-3 siblings/executors replies have surface=peer: they are passed as received from the domain writer and introduce no own HTTP failure. A TLS chain refused at the handshake has no HTTP status; row 1 retains this distinction. All other ordering, role/gate/body rules and exact conditional bodies remain in the catalogue cells and OpenAPI.

## Seams and stages

[stages.tsv](stages.tsv) declares 9 stages. Every stage is kit=-: no whole stage or ordinary process algorithm is claimed generated. The flags, refusals, door, vectors and stagetests parts assist only their declared material; no new KIT_PARTS or core part is introduced. Chapter 10 uses acceptance/ directly. The 82 CALL steps of 44 kit seam scenarios are kit assistance for the properties that the ordinary stand does not reach: the start, the role door without the TLS stand, door.pass without a worker on the domain, deadlines, breaks and the store reads that admin.sock cannot produce. All 16 ordinary scenarios / 163 steps, the vector alarms (the [current corpus](../vectors/alarms/README.md)), the common packages assigned by consumers.tsv, the neighbours on the P/08 stands, the TLS stand when it is ready and the items checked by reading remain mandatory. Build or these seams alone never give P/10 GREEN.

CALL/JSON uses [P/02 Non-HTTP seams](../../02-installer/forms/README.md): one strict JSON input and one result, recursive object subset, exact arrays and exact empty objects. The port table below is the machine-readable port declaration. The JSON fixture word selects the intervention described here, never a prepared expected answer. No public native command or application HTTP route is introduced.

Each scenario has its own temporary root, a valid neutral catalogue with the subsystem testsub, a built domain with the members hold, m1, m2, a real test kit (ca.pem, role leaves, the closed signature list sig) and readable confirmed rows unless its intervention changes them. Neutral is not unknown. Clocks, I/O failures, silence and breaks are controlled at the actual boundary (the store client, the TCP connection, the wall clock of the console); the adapter does not reimplement the decisions of the console. The process domain and the worker on the domain are controlled peers that record what reaches them. An unknown port, panic, unrelated failure, malformed JSON or unexecuted call fails. Counters refer to the named target effects and exclude incidental diagnostics.

## Effect fixtures

All CALL steps are selected by stages. The credential port's full contract is [the forwarding credential seams](../acceptance/README.md#forwarding-credential-seams), including actual first-hop P/06 paths; it remains mandatory. No whole stage is kit-generated. P/10 owns no data family, so the imported read schemas are checked by the read doors and fixtures, not advertised as a nonexistent own `families` output.

The following are interventions at real boundaries of the ports above, not ready-made decisions. All ordinary gates, schemas, signatures and routing run. An expected response is never passed to a port.

- `domainconsole-alarms`, `mixed_server_camera`: a server member and a camera member with confirmed marks. The camera mark has every=`camera_every`; its retry_in is not an input. Set the domain clock to `now`, run GET /domain/alarms, and observe both states, silence times and the per-member `silent_after` actually passed by the collector to alarms. No native input is substituted for collection.
- `witness_source_clock`: target m1 has last_report=`target_last_report`; m2's confirmed report is received at `source_received_at` and sent at `source_sent_at`. Its named witness object is the supplied `witness`, in a real generation matching the mark's sha256. `now` is the console wall clock. `witness_source_tie` uses the two supplied source reports and named witnesses, each with units[m2]=`unit_age`; m2 is the target. Observe normalized ts in call order (the `sources` array order), state, alive_at and alive_via after the ordinary collector and function. Never pre-normalize the report object or borrow the target's mark offset.
- `domainconsole-read`, `single_member_version`: the ordinary part locator places accepted m1 in its actual part with row rev/term and exact string store index from the input; read the named door, compare entry to that row and its ETag. `served_url_neighbours`: read an otherwise valid view first with the supplied string URL, then with no readable URL; observe those two actual served bodies. With the first valid served body, replace only url successively by the `url_values`, validate against the full ServedView in the published OpenAPI, and report one boolean for each. The stored View writer schema is not changed or used as the served schema. `folder_membership_own_read` uses actual live folder rows and the membership row of the fixture; count calls to the domain writer and worker.
- `domainconsole-pass`, `closed_route_owner_form`: form the request body from the valid neutral fixture of the named P/08 `owner_operation` (not an expected result). The controlled process domain returns a complete successful body valid for that operation, recording the actual method, target path and bytes. For verify the request comes through an actual cluster-console ticket path with its declared call, producing the ordinary trusted X-W2C-Ticket; it is not a callback at the domain console. Observe the ordinary console's dispatch, exact body, response validity against the owning operation and worker calls. `ordinary_platform_forward` uses a valid ordinary topology edit with controlled process silence or an oversized process response. Neither uses the domain-worker exception; no partial upstream body is exposed.
- `domainconsole-door-pass`, `composed_pass_hops`: run the ordinary member cluster console, holder cluster console and domain console handlers joined by real HTTP transports and real TLS kits as required at each hop. The domain worker is a controlled HTTP peer with a live slot/heartbeat. All three consoles have independently installed, validated, confirmed copies of the neutral testsub manifest, extended with second-kind routes api, no calls, wait api=`wait` (default PASS_WAIT when omitted), and stream api only when `stream=true`. The caller has an independently obtained real person session/token, valid CSRF when applicable and the needed grant. No fixture grants a successful guard or trusts a policy header.

For the composed port, `holder_wait` changes only the holder console's confirmed manifest; `holder_manifest_read=unknown` prevents confirmation there. `incoming_policy_spelling` sends an uppercase form of the correctly derived claim, two identical header fields, a comma list, or an embedded space; the adapter constructs the digest from the fixture's installed manifest, never from an expected answer. An absent claim remains absent at the external client. Capture the actual digest at every console boundary and the absence of that header at the worker. `policy_replaced` observes replacement of a received claim, not insertion for an absent claim. The path fixture changes only query on the second request; compare actual raw paths without percent-decoding/rewriting.

`worker_reply` controls the real HTTP peer: status, headers_at_s relative to admission, content_type (default application/json), body_b64, or chunks of the given repeated byte/count at at_s; close_at_s is a normal end, break_at_s drops the connection before completing a declared body. Stream peers use an allowed stream Content-Type and flushing; finite peers use a valid allowed finite type. Timers advance the actual clocks/scheduler and wait for the relevant task/transport barrier, not an unbounded sleep or a fabricated elapsed result. probe_at_s observes an actual still-pending client request; advance_to_s advances its controlled clock. `body_byte_equal`, delivered_bytes, body_b64, partial_worker_body_bytes and new_502_bodies describe the actual client bytes. The success, refusal, break and timeout cases all traverse the composed ordinary paths, with no replacement local pass algorithm.

`refusals`, when supplied to the composed fixture, installs exactly that declared second-kind map at each hop.
