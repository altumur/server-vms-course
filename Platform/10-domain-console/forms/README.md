# P/10 input and refusal forms

This English text is the source; ru/forms/README.md is its Russian translation for people, not in the export (ADR-0121). These forms express the existing norms under ADR-0125 addendum (5).

## Inputs and constants

[daemon-flags.tsv](daemon-flags.tsv) projects 20 existing environment inputs. The common header is flag,type,default,default_text,required,commands,bad,norm. $NAME remains environment; commands=domainconsole denotes the process. The setting channel stays environment-only. The launcher applies file precedence and role/instance/box/server validation. Alias equality, path resolution, TLS kits, listener admission, ports and own-client name checks retain their complete imported contracts, including the distinction between an implicit wildcard and an explicit address.

TIMEZONE uses exactly the IANA-name spelling of the environment contract: empty or out of form refuses start with code 2, but there is no zone-database lookup. W2C_DEBUG_PERSON retains every identity/credential/loopback guard of the gate contract; it creates no forwarding credential. DOMAIN_CONSOLE_HOST/PORT is the main door; this form introduces no callback listener or callback port.

[runtime-constants.tsv](runtime-constants.tsv) has the common header name,value,unit,norm,meaning and projects four existing positive integer limits. DOMAIN_PAGE_MEMBERS is the existing 1000-member bound of the aggregate view and member-list pages; RELAY_MEMBERS_MAX is the 5000-name relay bound. LOST_AFTER is the imported 45-second silence threshold; ALARMS_WINDOW is the existing one-day default window, in seconds. They are not environment settings. Cursor contents, projections, complete/contested data, report clocks and witness calculations remain their source contracts.

## Refusal catalogue

[refusals.tsv](refusals.tsv) preserves all 16 original Н4 rows as 25 code projections. word/outcome/cause contain the original three cells byte for byte; diagnostic/caller are absent (-) for those source rows. chapter=10 and row preserve the published addresses; a compound code yields several projections with the same row. Rows 17–22 project existing manifest/rights/schema startup admission, TIMEZONE, implicit-wildcard/kit admission, alias conflicts, the prohibited callback and the trusted alarms input. They do not add HTTP doors or startup refusal conditions.

The header is chapter,row,name,surface,code,kind,fields,headers,log,norm,word,response_schema,cause,outcome,diagnostic,caller, with literal TAB separators. HTTP response_schema names an OpenAPI component; fields lists directly required/directly declared properties. A composed or referenced schema still applies in full even when fields is -. The added names GateDenied, ConsoleRefusal and DomainPassRefusal only reference existing published schemas. DomainPassRefusal includes the existing manifest-mapped ProblemRefusal of the second kind, so a catalogue row does not force error/detail on a code/message body. It does not rewrite a worker reply. The full pass contract also retains its independently specified deadline/status and dynamic headers.

The word cell is a source catalogue index, never a free choice of error for a condition. The transition-3 siblings/executors replies have surface=peer: they are passed as received from the domain writer and introduce no own HTTP failure. A TLS chain refused at the handshake has no HTTP status; row 1 retains this distinction. All other ordering, role/gate/body rules and exact conditional bodies remain in the preserved source cells and OpenAPI.

## Seams and stages

[stages.tsv](stages.tsv) declares 9 stages. Every stage is kit=-: no whole stage or ordinary process algorithm is claimed generated. The flags, refusals, families, door, vectors and stagetests parts assist only their declared material; no new KIT_PARTS or core part is introduced. Chapter 10 uses acceptance/ directly. The 39 CALL steps of 25 scenarios in [acceptance/seams.tsv](../acceptance/seams.tsv) are kit assistance for the properties that the ordinary stand does not reach: the start, the role door without the TLS stand, door.pass without a worker on the domain, deadlines, breaks and the store reads that admin.sock cannot produce. All 16 ordinary scenarios / 163 steps, the vector alarms (27 rows), the common packages assigned by consumers.tsv, the neighbours on the P/08 stands, the TLS stand when it is ready and the items checked by reading remain mandatory. Build or these seams alone never give P/10 GREEN.

CALL/JSON uses [P/02 Non-HTTP seams](../../02-installer/forms/README.md): one strict JSON input and one result, recursive object subset, exact arrays and exact empty objects. The port table below is the machine-readable port declaration. The JSON fixture word selects the intervention described here, never a prepared expected answer. No public native command or application HTTP route is introduced.

Each scenario has its own temporary root, a valid neutral catalogue with the subsystem testsub, a built domain with the members hold, m1, m2, a real test kit (ca.pem, role leaves, the closed signature list sig) and readable confirmed rows unless its intervention changes them. Neutral is not unknown. Clocks, I/O failures, silence and breaks are controlled at the actual boundary (the store client, the TCP connection, the wall clock of the console); the adapter does not reimplement the decisions of the console. The process domain and the worker on the domain are controlled peers that record what reaches them. An unknown port, panic, unrelated failure, malformed JSON or unexecuted call fails. Counters refer to the named target effects and exclude incidental diagnostics.

| CALL port | Intervention and observation |
|---|---|
| `domainconsole-start` | Start the ordinary process over a store whose row platform/manifest/testsub has rev 2 and whose mark /rev is 1; then raise the mark to 2. Observe that the main door listens, the rev the process serves by, and restarts caused by the equal mark. |
| `domainconsole-read` | Serve the named request by the actual read door over controlled rows: domain/view with as_of in the past or in the future of the console wall clock; no row domain/placement and no placement records; a testsub manifest without domain.ref. Return the status, error and the observed body fields. |
| `domainconsole-gate` | Run the actual gate over a store with domain/root and without domain/keys, from the loopback without a token. Count the handlers of the door reached; for GET /session return the status and open. |
| `domainconsole-alarms` | Assemble the input of GET /domain/alarms from controlled rows and real report generations, then call the ordinary function alarms. The generation reports/rev of the mark has bytes whose sha256 differs from the mark; an object testsub/seen without a name, a named testsub/seen/a or testsub/seen/b with cluster m1 and a witness without ts are report objects of m1. Observe states, alive_via and the witnesses taken and discarded. |
| `domainconsole-pass` | Pass the named request to a controlled process domain at SIGNER_URL. The client sends a body, Authorization, Idempotency-Key, If-Match, an X-User and an X-W2C-Client from outside over a TCP peer of the loopback. The process answers frozen or deposed with its own Content-Type, ETag and body bytes, stays silent, or breaks after the headers inside a declared body. Compare what the process received and what the client received byte for byte; probe_at_s and advance_to_s move the controlled clock from the start of the passing. Count store writes. |
| `domainconsole-role` | Open real TLS connections to the role door of the domain console with the named client: no certificate; a leaf of the own ca.pem with the role domainagent, with two roles, with a signature outside sig, or with extendedKeyUsage without clientAuth; a leaf of a foreign center; a leaf of a member center in domain/members/m1/ca-certs whose sha256 stands in Entry.ca. member_rows_unreadable makes domain/member-rows unreadable; member_ca_then_entry_ca_removed removes the fingerprint from Entry.ca after the first connection and reconnects offering resumption. Observe whether the handshake completed, the HTTP answers, the gate calls, session tickets and resumed connections. |
| `domainconsole-accept` | Send the named request through the role door with the named client leaf, or through the loopback HTTP door without a kit (no_kit), with the given X-Operator, X-W2C-Client or X-W2C-Via-Worker, as a person without admin or with admin of the domain. Observe the status, the line of audit/domainconsole about the request (kind and the field role) and the headers that reached the controlled process domain. |
| `domainconsole-door-pass` | Pass the named request by door.pass of testsub to a controlled worker on the domain at the url of domain/testsub/heartbeat. The slot domain/testsub/worker holds another instance than the heartbeat, is released, or the heartbeat is older than LOST_AFTER; grants are admin on labels or on unit:testsub/u1 without a unit row; the second kind declares the routes api with a kit and an X-W2C-Pass-Console from outside, presents a ticket of an open record back to the domain console, or revokes the jti of an open stream before advance_s. Observe the worker calls, the path, client role and headers it received, the unit row reads, the status and the closing of the stream. |

The seams follow existing norm sentences, cited by requirement in the stage norms column: the start — P/10-R003 (P/02.3 Н3 «Process start» step 4); age, the absent counter and not in the directory — P/10-R004; the shut gate — P/10-R008 and the gate-and-pass contract; the alarm input — P/10-R011, P/10-R014; the passing, its wait and the answer — P/10-R005, P/10-R013 and the forwarding contract; the role door and accept by a console — P/10-R007, P/10-R006 and the role certificate contract; door.pass, its scope and the second kind — P/10-R009, P/10-R008 and the gate-and-pass contract.
