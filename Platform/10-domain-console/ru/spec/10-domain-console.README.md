# P/10 — инструкция для реализации

Текст производный от `spec/10-domain-console.README.md`, руками не правится: источник — английский [`spec/10-domain-console.README.md`](../../spec/10-domain-console.README.md), правка идёт в него, русский пересобирается переводом.

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — `ru/10-domain-console.md` (для человека, в выгрузку не входит).

Сценарии приёмки, фикстуры и эталонные результаты модели реализации не даны. Имена сценариев и «сц. NN» в N5 и чеклисте готовности называют данные случаев судьи; видимые нормы и формы содержат обязанности реализации.

## Задача

Реализовать процесс `domainconsole` на коробке держателя на языке `<LANG>`; пройти приёмку N5 и закрыть чеклист
готовности. Всего 17 норм: P/10-01…17; Процесс `domain` —
урок [P/08](../../../08-domain/ru/spec/08-domain.README.md), агент — урок [P/09](../../../09-agent/ru/spec/09-agent.README.md), пересылка
консоли кластера — глава P/06.7.

- Двери чтения `GET /domain`, `/domain/<sub>/<rows>`, `/domain/<sub>/tables/<таблица>`, `/domain/shadow`, `/domain/members`, `/domain/topology`,
  `/domain/placement*`, `/domain/grants`, `/domain/shared`, `/domain/alarms`.
- Передача правок, дверей людей и входа процессу `domain`.
- Дверь роли TLS и «принять консолью»; сторожевая по `domain/grants/domain`.
- Страница держателя и `door.pass` на домене.

## Входы и их приоритет

- Канон — [нормы](10-domain-console.norms.md), включая N0, абзац «Данные», порядок N3 и отказы N4. Вход и вывод команды
  приёмки — N5.
- [HTTP-контракт](../../spec/10-domain-console.api.openapi.yaml) выражает формы своих дверей и коды перехода 2; ответы процесса
  `domain` — [OpenAPI урока P/08](../../../08-domain/spec/08-domain.api.openapi.yaml) (ссылкой).
- Договоры: [пересылки](../../../common/ru/contracts/forwarding.md), [сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md),
  [токена домена](../../../common/ru/contracts/domain-token.md), [права](../../../common/ru/contracts/may.md), [сертификата
  роли](../../../common/ru/contracts/role-certificate.md), [`peer`](../../../common/ru/contracts/peer.md), [журнала
  событий](../../../common/ru/contracts/event-journal.md).
- [Приёмка](../acceptance/README.md) — стенд нескольких кластеров ([общий README
  приёмки](../../../common/ru/acceptance/domain-stand.md#стенд-домена), раздел «Стенд домена») и вектор
  [`alarms`](../vectors/alarms/README.md). Флаги, окружение, коды выхода — [`../lifecycle.md`](../lifecycle.md).
- Лекция (`ru/10-domain-console.md`, для человека, в выгрузку не входит) объясняет причины.

Внутренние интерфейсы, типы и устройство — выбор реализации. Имя и шаблон вызова команды `alarms` — пункт «Решает
реализация» норм.

**При расхождении.** Назвать id нормы, вход, начальное состояние, ожидаемый и полученный исход. Дефект реализации —
вывод не совпадает с ожиданием на входе приёмки. Дефект приёмки — ожидание расходится с нормой. Пробел нормы — вход, для
которого норма не даёт однозначного исхода: записать место и контрпример и передать «Спецификации» с предложением.
Инструкция не вводит новый отказ. Изменения приёмки фиксирует владелец источника в записи исправления урока.

## Глоссарий

Здесь различены значения слов действующих норм; глоссарий не добавляет поведения.

| Слово | Значение здесь | Норма |
|---|---|---|
| процесс / роль / комплект | `domainconsole` — процесс; одноимённая роль выбирает его комплект TLS. | P/10-R003; N1.1, N1.4 |
| держатель / член | Кластер-держатель запускает консоль домена; он же — член со своим агентом и отчётом. | P/10-R003, P/10-R036; N1 |
| переслать / передать | Консоль кластера пересылает сюда; консоль домена передаёт правки процессу `domain`, а `door.pass` — воркеру на домене. | P/10-R005, P/10-R007, P/10-R009 |
| строка / раздел / страница | Строка читается из хранилища; раздел группирует записи; страница HTTP ограничена бюджетом членов и может кончаться внутри раздела. | P/10-R004; N1.2a, N1.2b |
| версия / ревизия / индекс | Индекс строки хранилища — точная строка для ETag; `rev` или `revision` документа — отдельное поле. | N1.2; P/10-17 |
| вид / право view / видимость | `domain/view` — записанный сводный вид; `view` — действие гранта; видимость отбирает записи ответа. | P/10-R004, P/10-R008; N1.2, N1.5 |
| метка reported / отчёт / страница тревог | Подтверждённая метка указывает поколение отчёта; в нём может не быть страницы тревог либо страница может не читаться. | P/10-R011, P/10-R014; N1.8, N3 |
| свидетель / часы / silent | Исходный отчёт задаёт сдвиг часов свидетеля; `silent_after` свой у каждого члена; `silent` и `not_reporting` сохраняют последние известные тревоги. | P/10-R011, P/10-R014; N1.8, N3 |
| токен / билет / обратный вызов | Токен человека удостоверяет личность; передача второго вида использует билет открытого запроса; двери обратного вызова билета у этой консоли нет. | P/10-R008, P/10-R009; N1.5, N1.6 |
| отказ / нечитаемое / неподтверждённое | Отказ — опубликованный исход; неверная подтверждённая метка отчёта отличается от неподтверждённого чтения хранилища. | P/10-R014, P/10-R015; N3, N4 |

## Что создать

- Двери чтения N1.2 и список тревог N1.8 с функцией `alarms` (команда `alarms`).
- Передачу N1.3: каждая строка списка дверей домена, кроме своих чтений и `door.pass`, — процессу `domain`
  (`SIGNER_URL`), ответ как пришёл; двери людей N1.3a.
- Дверь роли N1.4 (`server.role`) и «принять консолью»; сторожевую N1.5 (шаги `identity` 3, 4; `may` по
  `domain/grants/domain`; `/session` с грантами).
- `door.pass` на домене N1.6; страница держателя N1.7.
- Старт N1.1: сторона читателя строки манифеста, проверка схемы, готовность — порт.

## Порядок работы

Это предлагаемый порядок, а не обязательное устройство кода.

1. `alarms` по вектору [`alarms`](../vectors/alarms/README.md).
2. Двери N2 чтения и их отказы N4.
3. Сторожевая консоли домена; `/session` с грантами.
4. Передача процессу; «принять консолью»; дверь роли.
5. Страница держателя и `door.pass` на домене.
6. Стенд: сценарии 02, 05–19 [приёмки урока](../acceptance/README.md) и сторона консоли домена в сценариях глав урока P/08
   (таблица соседей на стенде N5).

Машинный план этого порядка — [forms/stages.tsv](../../forms/stages.tsv), порты CALL — в [forms/README.md](../forms/README.md); швы пакета дополняют сценарии шага 6 и чтение, не заменяют их.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| N1.8 | Выбросить тревоги молчащего члена | Тревоги последнего отчёта остаются, плюс строка молчания. |
| N1.3 | Пересчитать `deposed`, `frozen`, `standby` процесса | Ответ процесса — как пришёл (P/08.0 N1.8 `answers`). |
| N1.2c | Отдать топологию из вида | Из строки `domain/topology`: новый `rev` сразу после PUT. |
| N1.4 | Возобновлять TLS-сессии у двери роли | Билеты и PSK выключены: каждое соединение — полное рукопожатие по текущему объединению. |
| N1.4 | Передать пришедший `X-W2C-Client` | Снаружи пришедший снимается, как `X-User`; ставит консоль сама. |

## Проверки границ

Строк держателя консоль домена не пишет: правки передаёт процессу `domain` (N1.3; права `domainconsole` — чтение
`domain/*`). Историю тревог пишет процесс `domain` (глава 8.9); список её только читает. Исполнение правок и проверка
личности у процесса — урок P/08; пересылка консоли кластера — глава P/06.7.

## Готово, когда

- Выбранные для завершения сценарии приёмки урока проходят; вектор `alarms` проходит.
- Описание реализации называет команду `alarms`.
- Нормативный чеклист P/10-01…17 закрыт; пункты «проверяется чтением» (P/10-03, -10, -11, -15, -16 и части прочих по N5)
  названы отдельно.

Успех TSV подтверждает только наблюдаемые им ветви: TLS между кластерами, `door.pass` на домене и срок передачи он не
доказывает.
