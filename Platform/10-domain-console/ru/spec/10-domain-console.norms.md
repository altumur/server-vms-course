## N1 Форма

[runtime-constants.tsv](../../forms/runtime-constants.tsv) разворачивает три собственных положительных целочисленных предела; RELAY_MEMBERS_MAX берётся из формы владельца P/08.3 с якорями требований; [грамматика формы](../forms/README.md#входы-и-константы) задаёт единицы и область действия. Это не дополнительные настройки окружения.

**Время.** Строк и объектов со временем урок не пишет; строка журнала роли — `t` по [договору журнала событий](../../../common/ru/contracts/event-journal.md).

`age` ответа `GET /domain` — секунды по стенным часам консоли, не время в строке (N1.2a);

время строк списка тревог — часы домена (N1.8 `clock`); объект истории — [глава 8.9](../../../08-domain/ru/spec/08.9-domain.norms.md) N1 «Время», страница тревог члена — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1 «Время».

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `<sub>/<manifest:domain.witness.report>/<name>`;
- пишет: `<events root>/audit/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append), `<events root>/audit.alarms/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `domain/relay-members/<relay>`, `domain/<sub>/<manifest:domain.kept>`, `domain/folder-units/<id>`, `domain/folder-units/<id>/<part>`, `domain/folder-counts/<id>`, `domain/view-rows/<part>`, `domain/anywhere`, `domain/folders/<id>`, `domain/memberof/<member>/<sub>/<manifest:unit.rows>/<id>`, `domain/members/<member>/tables/<sub>/<table>`, `domain/roles/<name>`, `domain/groups/<name>`, `platform/manifest/<sub>`, `platform/manifest/<sub>/rev` (метка: смена манифеста — P/02.3 N3), `platform/schema`, `/etc/w2c/tls/<role>/server.key`, `domain/view`, `domain/shadow`, `domain/holder`, `domain/keys`, `domain/root`, `domain/revoked`, `domain/member-rows/<part>`, `domain/members/<member>/ca-certs`, `domain/members/<member>/reports/<rev>`, `domain/members/<member>/reported`, `domain/topology`, `domain/<sub>/worker`, `domain/<sub>/heartbeat`, `domain/placement`, `domain/placement/<sub>/<ref>`, `domain/disabled`, `domain/grants/<cluster>`, `domain/shared`, `domain/shared-docs/rev-<rev>`, `domain/alarm-history/<member>`.

Строк держателя консоль домена не пишет: правки передаёт процессу `domain` (N1.3; приём — [P/08.0](../../../08-domain/ru/spec/08.0-domain.norms.md) N1.8), права `domainconsole` — чтение `domain/*` ([P/02.5](../../../02-installer/ru/spec/02.5-installer.norms.md) N1.4).

Семья объектов свидетеля `<sub>/<manifest:domain.witness.report>/<name>` — у этого урока по протоколу (N1.8 `witness`): пишет воркер подсистемы (участник), несёт агент в отчёте;

консоль домена читает свидетелей только из отчётов членов (`domain/members/<member>/reports/<rev>`; держатель — тоже член со своим агентом), схемы в `data/` у семьи нет (форма — объявление `domain.witness` манифеста, [P/02.1 N1.2b](../../../02-installer/ru/spec/02.1-installer.norms.md)).

Что читает каждая дверь: вид, теневой отчёт, список членов, топологию, назначения, гранты, общий документ — двери чтения N1.2 (формы строк — их главы урока P/08);

Что читает каждая дверь: `domain/keys`, `domain/root`, `domain/revoked`, `domain/disabled`, `domain/grants/<cluster>`, `domain/roles/<name>`, `domain/groups/<name>` — сторожевая (N1.5; ключи и токен — [договор токена домена](../../../common/ru/contracts/domain-token.md), `may` — [договор права](../../../common/ru/contracts/may.md));

Что читает каждая дверь: `domain/member-rows/<part>` и строки `domain/members/<member>/ca-certs` — дверь роли (N1.4 `server.role`; копию `domain/member-list/<part>` консоль домена не читает);

Что читает каждая дверь: `domain/<sub>/worker` и пульс `domain/<sub>/heartbeat` — `door.pass` на домене (N1.6);

Что читает каждая дверь: отчёт члена, метка `reported` (`received_at`, `sent_at`), история и `domain/member-rows/<part>` — список тревог (N1.8);

Что читает каждая дверь: строки манифеста и `platform/schema` — старт (N1.1);

Что читает каждая дверь: ключ сертификата сервера роли `domainconsole` — дверь роли TLS.

Журнал роли — `audit/domainconsole`, тревога `session.debug_open` (отладочная личность, N1.5) — `audit.alarms/domainconsole` ([договор журнала событий](../../../common/ru/contracts/event-journal.md), участник `append`, владелец — P/05).

Строки «журнал» двери роли — переход набора доверия в нечитаемый и возврат (договор сертификата роли, класс `role`, `unreadable`) и служба без комплекта (`no_kit`) — диагностика процесса (stderr), не события `audit/domainconsole`: видов для них нет и новые не вводятся, текст — реализации, приёмка его не сверяет.

### N1.1 Процесс и старт (P/02.4 N1.12)

Консоль домена — процесс `domainconsole` у кластера-держателя, рядом с процессом `domain`: юнит `w2c-domainconsole.service`, роль `domainconsole`, неявные умолчания адреса `DOMAIN_CONSOLE_HOST/PORT` из [daemon-flags.tsv](../../forms/daemon-flags.tsv) — только с комплектом роли, TLS — по комплекту ([P/02.4 N1.12](../../../02-installer/ru/spec/02.4-installer.norms.md)).

Как процессы платформы, она исполняет сторону читателя строки манифеста ([P/02.3](../../../02-installer/ru/spec/02.3-installer.norms.md) N3 «Старт процесса», «Смена манифеста»): встроенного манифеста у неё нет, шаги 0–4 «Старт процесса» — как там: шаг 0 — проверка схемы с `SCHEMA` сборки платформы ([договор схемы](../../../common/ru/contracts/schema.md) «Проверка при старте»); Старт процесса, шаг 1: проверить весь каталог. Старт процесса, шаг 2: проверить только `sha256` строки (сравнивать встроенные байты не с чем).

После проверок манифеста при старте процесса проверить окружение и комплект TLS, затем открыть порт. готовность — порт, `sd_notify` она не шлёт (P/02.4 N1.12; P/10-15).

Окружение процесса развёрнуто в [daemon-flags.tsv](../../forms/daemon-flags.tsv) по [грамматике формы](../forms/README.md#входы-и-константы); обязательны запускатель и перенесённые контекстные контракты. Окружение, коды выхода и юнит — [жизненный цикл](../lifecycle.md).

### N1.2 Двери чтения — отвечает сама

Разбор запроса — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Разбор запроса и порядок проверок» (P/01.1 N2.1 с отступлениями консоли); У консоли домена нет своих отступлений от этого разбора запроса.

Личность и гранты — N1.5 (`view` на чтение по `domain/grants/domain`; двери вида — «Суд по цели» [договора права](../../../common/ru/contracts/may.md)).

Каждая дверь — строка списка дверей домена [договора пересылки](../../../common/ru/contracts/forwarding.md) «Двери домена»; строка с `GET` покрывает и `HEAD` того же пути — тот же код и заголовки без тела (там же; P/06.5 N2).

**Версия строки у дверей чтения** ([P/08.0](../../../08-domain/ru/spec/08.0-domain.norms.md) N1.9 «Версии»). Двери одной строки — `GET /domain/members/<член>`, `GET /domain/topology`, `GET /domain/placement/<sub>/<ref>`, `GET /domain/shared` — отдают `ETag`: индекс этой строки (у общего документа — указателя) в двойных кавычках, из того же чтения, что значение. Строки нет — ответ без `ETag`: условию не о чем судить. `GET /domain/placement` несёт `index` в каждой записи, `GET /domain/grants` — поле `versions`: индекс и `revision` стоят при строке, потому что строк в ответе много. Значения годятся для `If-Match` дверей правок, которые консоль передаёт процессу (N1.3).

**N1.2a Вид.** Двери — у консоли домена; консоль кластера пересылает их без переписывания:

**GET `/domain[?cursor=]`**

**Успех** — ответ — голова `domain/view` и непустые разделы подряд до DOMAIN_PAGE_MEMBERS членов, поля `members`, `units`, `contested`, `reports`, `pending`, `outcomes` — слияние строк, `cursor` — следующая страница, `unread` — непрочитанные разделы; **Успех** — малый домен — одна страница (P/08.1 N1.4b);

**Успех** — у незрителя домена (договор права `wide`) — только `as_of`, `holder`, `complete`, `members` (`servers` и `url` — только у кластеров, где у него есть строка), `units` по записи, `outcomes` — исходы, где `by` — он сам, `contested` — ref, чей кластер он видит, `age`, `url`, `withheld: <число>`;

**Успех** — иначе 200 — объект `domain/view` ([P/08.1](../../../08-domain/ru/spec/08.1-domain.norms.md) N1.4) как есть плюс `age` — секунды с `as_of` по стенным часам консоли, `max(0, now − as_of)` (часы назад — 0), один знак после точки; **Успех** — поле `url` вида, которое не читается (не строка), — `null` в ответе

**Отказы** — 404 `{error: "no domain here", detail}` — объекта нет; **Отказы** — объект есть, но не читается — 503 `{error: "unavailable"}`, не 404; **Отказы** — 401/403 — N1.5

**Страницы `GET /domain`.** Предел жёсткий: не более DOMAIN_PAGE_MEMBERS элементов `members` на странице. Раздел — единица хранения/работы писателя, не неделимая страница HTTP; читаемый раздел с более чем DOMAIN_PAGE_MEMBERS членами делится по границе члена.

Непустые разделы обходятся по возрастанию четырёхзначного имени (0000…4095), члены внутри раздела — по имени в порядке байтов UTF-8. Выбирается до остатка бюджета страницы, при необходимости следующий запрос продолжается внутри того же раздела. Массив `members` каждой выданной страницы сам упорядочен по имени; последний отображённый элемент не обязан обозначать последний посещённый раздел.

Запрос без cursor начинает обход. Выданный cursor — непрозрачная строка с достаточным состоянием продолжения, например текущим разделом и последним посещённым членом. Кодировку выбирает реализация; клиент возвращает полученный токен как значение query без изменения. Cursor продолжает обход после выбранных членов, в том числе внутри раздела, а в конце отсутствует. На неизменных читаемых данных обход всех страниц возвращает каждого члена ровно один раз, без пропуска и повтора.

API обещает обычные чтения, не новый снимок на время конкурентных изменений.

Страница проецирует шесть полей по членам: `members` несёт выбранных членов; `units` сохраняет Unit с выбранным cluster; `reports`, `pending`, `outcomes` сохраняют ключи выбранных членов. Обязательные пустые ключи подсистем вида сохраняются.

Спорный ref — целый факт конфликта: сохраняется ref с выбранным участником, со всем исходным списком участников; список не обрезается границей страницы. Имена такого контекста не являются дополнительными элементами MemberState страницы. Поэтому спор может присутствовать на нескольких страницах, а сами члены не повторяются.

Глобальные поля головы остаются глобальными.

Прежние фильтры видимости и правила unread/incomplete сохраняются; сама пагинация не меняет полноту круга держателя.

Существующее поле читателя `unread` — необязательный `Part[]`; именованная типовая привязка — `ServedView.unread` в [OpenAPI владельца P/08](../../../08-domain/spec/08-domain.api.openapi.yaml), элементы ссылаются на Schema Object существующего параметра Part. Это не поле записанной головы или писателя.

В одной обычной последовательности пагинации в том же контексте итоговое поле отсутствует только при его отсутствии на всех страницах. Если хотя бы одна страница его передала, поле сохраняется, возможно как `[]`, а каждая литеральная Part-строка включается один раз в порядке первого появления, включая порядок внутри страницы. Позднее отсутствие или `[]` не стирает прежних наблюдений.

Нельзя разбирать, trim, дополнять, сортировать или нормализовать строки частей; сборщик не добавляет `uniqueItems` или иные границы отдельному ответу. Это наблюдение читателя не переписывает глобальные поля первой головы или шесть проекций, полный contested-контекст, пустые ключи подсистем, непрозрачный cursor или фильтры видимости.

Отсутствие из-за видимости не доказывает полноту. Валидные ответы `200` с `complete: false` или `unread`, в том числе поздней страницы, остаются обычными наблюдениями неполноты, а не автоматически транспортными ошибками или `domain: null`. Настоящий отказ HTTP/сети/чтения тела продолжения сохраняет существующий путь null/ошибки; межстраничный снимок или клиентский флаг полноты не добавляются.

Примеры на неизменных данных: один раздел с 1001 членом даёт страницы 1000 и 1; соседние разделы с 999 и 2 — страницы 1000 и 1 с продолжением внутри второго раздела. Спор между членами по разные стороны границы сохраняет оба имени участников везде, где включён этот спор. Нового предела размера раздела для P/08.1 N1.4b нет.

Признак пути — закрытый заголовок `X-W2C-Via-Worker: <sub>/<экземпляр>` ([договор пересылки](../../../common/ru/contracts/forwarding.md)): его ставит консоль кластера на пересылке по билету, консоль кластера держателя на переходе 1 пропускает как заявленный; консоль домена снимает его у внешнего запроса, принимает только с листа роли консоли кластера и передаёт процессу, а процесс верит ему только на соединении своей консоли. Правом и проверкой он не служит: только журнал и тревога. Журнал несёт `via: <sub>/<экземпляр>`.

### N1.5 Сторожевая консоли домена (P/08.4 N1.5 `domain`)

Консоль домена — участник [договора сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md): из раздела «Сторожевая» действуют `gate`, `identity`, `x_user`, `caps`, `scope`, `csrf`, `body`, `refusal` и `session` (таблица сторон договора).

Состояния `on`, `open`, `shut` и «след домена» — [P/06.3](../../../06-console/ru/spec/06.3-console.norms.md) N1.8.

Из шагов `identity` у консоли домена — шаги 3 и 4; шагов 1 и 2 у консоли домена нет — нет аварийной сессии и дверей единиц.

Шаг 3 — токен человека: функция `token` [договора токена домена](../../../common/ru/contracts/domain-token.md) «Проверка» по набору и `domain/revoked` своего хранилища с `expect {kind: person, cluster: null}`; Отказ этой проверки токена человека — 401 `{error: denied, detail: "token refused: <слово>"}` (форма P/06.3), кроме `no_revocations` и строки `domain/keys`, которая есть, но не читается (проверить токен нечем): правило «Нечитаемая строка» договора сторожевой и передачи (503 `{error: "unavailable"}`).

Двери вида, все двери хранимой правки, чтение людей, ролей, грантов и правка грантов кластера судятся по кластеру цели: «Суд по цели» [договора права](../../../common/ru/contracts/may.md). Прочие двери — строка `domain`.

Право — строка `domain` [P/08.4 N1.5](../../../08-domain/ru/spec/08.4-domain.norms.md) (одна строка для консоли домена и процесса `domain`; текст — там): `may` ([договор права](../../../common/ru/contracts/may.md)) по `domain/grants/domain` (есть, но не читается — правило «Нечитаемая строка» договора сторожевой и передачи, 503 `unavailable`), `need` view/admin по двери; вход `disabled` функции `may` — строка `domain/disabled` у держателя, условие чтения — договор права (P/06.3 N1.3 «Данные»; есть, но не читается — правило «Нечитаемая строка», 503 `unavailable`); вход `roles` — строки `domain/roles/*`, `domain/groups/*` держателя, `as_of` — `null` (P/08.4 N1.3b `roles_at_holder`; нечитаемая `domain/roles/admin` или группа из её `assigned` — 503, если прямые строки не разрешили); вход `iat` — токена.

Строка управляющего (P/08.4 N1.3c `manager`) служит сторожевой только у дверей `gives`: `/domain/users…`, `/domain/groups…`, `/domain/roles…`, `/domain/batch`, `GET /domain/grants`, `PUT /domain/grants/<кластер>`, а также `/domain/break-glass…`: у этой двери группа считается только затем, чтобы запрос дошёл до процесса и тот ответил 403 `admin only` (P/08.4 N1.5, N1.3c `denies`); У дверей вне этого списка группа строки управляющего в `may` не считается.

Подсистемы у дверей домена нет: `sub` — `null`.

Строки `body_unit` и `session` — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Права по телу». Строки `body_unit` и `session` — общие с консолью кластера ([P/06.7](../../../06-console/ru/spec/06.7-console.norms.md), глава позднего слоя), кроме предпроверки `body_unit` до тела и цели `door.pass` без `?unit=`: у консоли домена — `"*"`, у консоли кластера — грант на что-либо (договор, `body_unit`, `need` строка `door.pass`);

`/session` и `/healthz` консоли домена — как у консоли кластера (договор сторожевой и передачи `session`; N1.7) (P/10-13).

Цель `door.pass` с `?unit=<sub>/<id>` — `scope` договора сторожевой и передачи как есть: `*` и `unit:<sub>/<id>` самой единицы сверяются по имени без строки; `labels:…` и `unit:` about-единицы требуют строку единицы, а строк единиц членов консоль домена не читает (их нет в её «Данных», N1; вид и копии отчётов ею не служат) — такой грант не покрывает, ни один не покрыл — 403 по `refusal`; подстановки из вида или кластера нет.

### N1.6 `door.pass` на домене

**route** — /domain/\<sub\>/<сегмент>[/…], <сегмент> ∈ door.pass манифеста \<sub\> (P/06.5 N1.8) — консоль домена передаёт воркеру на домене этой подсистемы (P/03.7 N1.6: держатель слота domain/\<sub\>/worker, роль \<sub\>domain) путь /<сегмент>[/…] и query; **route** — заголовки, тело, ответ, коды — договор сторожевой и передачи «Передача `door.pass`»; **route** — клиент — роли domainconsole; **route** — путь с сегментом `.`/`..` воркеру не передаётся — 404 not a domain route (договор пересылки «Двери домена»)

**address** — url пульса воркера на домене — объект domain/\<sub\>/heartbeat (P/03.7 N1.6 heartbeat)

**holder** — слот domain/\<sub\>/worker консоль читает только как «держатель есть»: holder непуст и released = false (договор слота «Состояния»); **holder** — держателя нет — «не слышно» (absent ниже); **holder** — свежесть — только пульс (LOST_AFTER, P/03.7 N1.6 heartbeat); **holder** — совпадение instance пульса с holder слота и возраст версии слота (SLOT_TERM) консоль не судит — действительность операции проверяет воркер своими учётными данными и эпохой, как у консоли кластера (P/06.5 N1.8)

**absent** — воркера на домене этой подсистемы не слышно — 503 {error: "unavailable", detail: "no worker of \<sub\> with a door is heard"} (слова договора сторожевой и передачи, codes)

**member** — консоль кластера пересылает эти пути консоли домена строкой списка дверей домена договора пересылки Правило сопоставления (`books`, `placement`, `members`, `topology`, `shadow`, `at` на домене не передаются) — договор пересылки «Двери домена».

Что воркер на домене проверяет у пришедшего маршрута — [P/03.7](../../../03-worker/ru/spec/03.7-worker.norms.md) N1.6; консоль передаёт `Authorization` как пришёл.

**Второй вид `door.pass` на домене** ([договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Передача второго вида»). Манифест со вторым видом консоль домена передаёт так же: билет вместо `Authorization`, заголовки, типы ответа, `refusals`, поток.

Билет выдаёт экземпляр консоли домена и помнит `jti`, `kid`, `exp` токена человека; `user`, закрытие запроса и закрытие потока при отзыве `jti`, выключении человека и на `exp` — по договору.

Токен проверяется договором токена домена, а гранты — `domain/grants/domain` (N1.5).

Клиент к воркеру — роли `domainconsole`, адресат — роль `<sub>domain`.

Обратного вызова на домене пока нет: закрытый перечень [P/06.3](../../../06-console/ru/spec/06.3-console.norms.md) N1.9 не называет дверей `/domain/*`, поэтому заголовок `X-W2C-Pass-Ticket` консоль домена принимает только для отказа, 401; двери войдут в перечень с приращением прав.

**Все hop пересылки.** [Политика передачи доменному воркеру](../../../common/ru/contracts/forwarding.md#политика-hop-передачи-доменному-воркеру) обязательна на каждой консоли пути, включая держателя и члена: digest подтверждённой политики, конечные сроки с исполнением downstream и правила конечного буфера и потока из той же политики. Несовпадение — 503 без вызова воркера. После клиентских заголовков обрыв передаёт байты и закрытие, без нового тела `502`. Обычные платформенные пути сохраняют прежние пределы.

**Заголовок адреса обратного вызова.** У этой передачи исходящий `X-W2C-Pass-Console` отсутствует как с комплектом роли, так и без него. Такой заголовок, пришедший извне, удаляется по `to_worker` договора сторожевой и передачи. `CONSOLE_CALL_PORT` называет слушатель обратного вызова консоли кластера; ни его URL, ни основной адрес `DOMAIN_CONSOLE_HOST/PORT` не являются адресом обратного вызова этого экземпляра консоли домена.

Билет привязан к открытому запросу в памяти по договору выше; входящий `X-W2C-Pass-Ticket` в консоль домена получает отказ 401, как выше.

Формы запроса, успеха, условного 412, RepeatKey и отказы писателя — ссылки на владельцев P/08; консоль не изобретает иной схемы и не поглощает отказ писателя.

Путь с сегментом `.` или `..` (в том числе в процент-форме) — 404 `not a domain route` до сторожевой, до передачи процессу и воркеру на домене (договор пересылки «Двери домена»).

## N3 Проход

### принять пересылку и передать процессу (консоль домена)

Своего порядка проверок урок не вводит: каждое место задано своей нормой. «Принять консолью» — [договор пересылки](../../../common/ru/contracts/forwarding.md) «Принять консолью» (N1.4);

отказы двери роли — до сторожевой (N1.4 `server.role`);

путь с `.`/`..` — 404 до сторожевой (N2);

сторожевая — N1.5;

дальше — своя дверь чтения (N1.2, N1.8), `door.pass` (N1.6) или передача процессу `domain` (N1.3 `pass`): ответ процесса — как пришёл, обрыв и молчание — 502.

### alarms(input)

Фильтр — у двери, форма — у функции: дверь тревог собирает вход из хранилища и битого свидетеля (без ts и т. п.) отбрасывает со счётчиком до вызова — устойчивость;

вектор alarms получает уже собранный вход, и свидетель не по форме в нём — вход не по форме, код 2. Одно другому не противоречит.

Метка `domain/members/<member>/reported`, чтение которой хранилище не подтвердило, — 503 `unavailable` всей двери;

метка прочитана, но не по форме, — член входит в функцию с `reported: "garbled"`.

Вход собирается из хранилища держателя: `last_report` — `received_at` метки, `received_at` и `sent_at` — поля последнего запроса метки ([P/08.3](../../../08-domain/ru/spec/08.3-domain.norms.md) N1.3; часы домена), не возраст наблюдения консоли;

члены — строка `domain/member-rows/<part>`: её нет — 404 `no domain here` (как `GET /domain/members`, N1.2b), она не читается или чтение не подтверждено — 503 `unavailable` всей двери, не пустой список;

метка прочитана, а поколения `reports/<rev>` метки нет или оно не с её `sha256` — `page: "garbled"` (член `unreadable`, свидетели этого отчёта не берутся), не `page: null`: «страницы нет» — только у читаемого поколения без страницы.

Сборщик всегда передаёт `silent_after` каждого члена по принятому классу Entry и подтверждённой метке, как в N1.8.

Для принятой Entry класса camera подтверждённое отсутствие метки или подтверждённая целиком нечитаемая метка дают `silent_after = 3 * REPORT_EVERY` по прежнему владельцу периода отчёта. Сборщик не читает `every` частично из отвергнутой метки, не использует кэш, не подставляет серверный `LOST_AFTER` и не пропускает поле.

Это заполняет полную форму входа: подтверждённое отсутствие остаётся `never`;

целиком нечитаемая метка остаётся `unreadable` при 200 без silence/page, known_until и silent_since;

неподтверждённое чтение остаётся 503 `unavailable` всей двери.

Он переводит `ts` каждого свидетеля по сдвигу исходного отчёта до вызова функции; во входе нативной команды `ts` свидетеля уже по часам домена.

Функция повторно его не сдвигает.

```text
вход:   {now, since, until, lost_after, members: {<член>: {last_report: <часы домена> | null, received_at, sent_at, page: <P/09.1 N1.10> |
         "garbled" | null, history: <P/08.9 N1.9> | null, silent_after} | {reported: "garbled", page?, history?, silent_after}}, witnesses: [{sub, name, ts, cluster, units}]}
```

silent_after: обязательное конечное положительное JSON-число в обеих формах члена. Функция не выводит класс Entry из входа.

Полный известный вход, включая это поле, проверяется до шагов; отсутствующее или неверное значение — код 2, в том числе при reported = "garbled". Подстановки lost_after нет.

**1. Каждый член.**

reported = "garbled" (метка прочитана, не по форме) → unreadable; При reported = "garbled" строки молчания и строк страницы этого члена нет, known_until и silent_since нет.

last_report нет и page нет → never

last_report нет, а page есть → вход не по форме (код 2): страница приходит только с отчётом

page = "garbled" или не по форме P/09.1 N1.10 → unreadable; не по форме — и строка без id, class ≠ alarm, kind пустой, unit не строка, from > to

now − last_report > silent_after → silent;

Для молчащего члена свидетель с ts − units[член] > last_report — not_reporting.

иначе → ok

page = null при last_report — страницы нет: строк страницы нет, не unreadable

2. строки: страница (часы N1.8 clock) ∪ история (from_history, t как хранится) без повторов по same_line — есть в обеих, берётся строка страницы; повтор внутри одной страницы — первая по порядку страницы;

строка молчания — N1.8 silence_line; окно [since, until] — для всех строк, и для строки молчания

3. members: {<член>: {state, truncated?, known_until?, silent_since?, alive_at?, alive_via?, history_cut_before?}}; truncated: true — у читаемой страницы с truncated; known_until — last_report у silent/not_reporting; history_cut_before — у истории с cut_before > since

4. complete = все ok;

sentence — «every member answered» или фразы через «; », по членам (байты UTF-8), у члена — в порядке списка ниже:

```text
«<m> silent since <HH:MM> — its alarms from its last report, known up to <HH:MM> UTC; none known since»
«… — but <alive_via> heard of it at <HH:MM>: alive, and not reporting to the domain»
«<m> has never reported to the domain»; «<m>'s page of alarms does not read»
«<m> had more alarms than one page holds; showing its newest»
«<m> had an alarm storm: the domain keeps only its newest alarms, and what came before <HH:MM> UTC is not known in full»
```

(время — UTC часов домена)

`same_line`, повтор в странице и `cut_before` — [договор истории тревог](../../../common/ru/contracts/alarm-history.md).

**Гонки.** Член без связи и шторм тревог — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N3 «Гонки».
