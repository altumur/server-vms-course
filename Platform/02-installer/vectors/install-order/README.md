# Векторы: порядок первичной установки манифестов

Владелец — глава [P/02.4](../../spec/02.4-installer.norms.md) установщика (Н1.7 `install` `steps`, `order`; догадка стадии C
I02-INSTALL-ORDER, решение «Архитектора» 2026-10-23). Участник — установщик (`install.sh`, шаг `manifest put`). Байты пишет
«Спецификация».

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

**Вход** — `{manifests, installed}`: `manifests` — манифесты этой установки, у каждого `name` и то, что задаёт или не задаёт
порядок: `requests` (`worker.requests`), `near` (`placement.near.sub`), `creates` (подсистемы `worker.creates`), `uses`
(`worker.uses`); `installed` — имена подсистем, чьи манифесты уже в хранилище. `manifests`, `installed` и `name` элемента обязательны;
`requests`, `near`, `creates`, `uses` необязательны (нет — связи нет); пустые массивы допустимы; `null` вместо строки или
массива — не по форме: код 2, stdout пуст (догадка стадии C I02-G05, решение «Архитектора» 2026-10-23).

**Выход** — JSON-массив имён в порядке `manifest put`, либо `@exit 2` — отказ установки кодом 2 на предварительной проверке,
до изменений. Сравнение — JSON по значению.

## Команда стенда `install-order`

Ключ `stand` профиля `02-installer` (раздел «Раскладка по процессам» [общего README приёмки](../../../common/acceptance/README.md)),
по образцу `door-token-verify` ([векторы door-token](../../../common/vectors/door-token/README.md)): шаблон с `{input}` —
путь файла, в который раннер пишет байты ячейки `input` строки как есть. stdout — ровно один JSON-объект в UTF-8 и LF,
код 0: `{"result":"ok","order":[…]}` — сравнивается с `expect` по значению JSON, — или `{"result":"refused"}` (`expect` — `@exit 2`). Вход не по
форме (неверный тип, незнакомое или повторное поле, повторное имя в `manifests`) — код 2, stdout пуст; отказ правила на входе по форме — код 0, `{"result":"refused"}` (догадка стадии C I02-STAND-FORM, решение «Архитектора» 2026-10-23). Иной код, иной `result`, лишние поля или байты — FAIL строки (догадка стадии C I02-STAND, решение «Архитектора» 2026-10-23).

## Прогон

Сторона вычисляет порядок своим кодом установщика без хранилища и сравнивает с `expect`. Ребро вида токена домена
(объявитель `domain.tokens` раньше подсистемы, чей `door.routes[].domain` его называет; P/02.4 Н1.7 `order`,
C02-KIND-ORDER-33) вход не выражает — форма входа не расширяется: строки без видов его не задают, правило — чтением и
`puts.tsv` главы 2.3 (`door_domain_kind_other`, `door_domain_kind_missing`).

Порядок задаёт только `requests` (и вид, не выраженный входом); `near`, `creates`, `uses` во входе есть, но порядка не задают
(ADR-0091 доп. (26) п. 1, доп. (27) п. 4): `cycle` — цикл по `requests`; `requests-near-pair` — `requests` и `near`
навстречу — порядок по `requests`, не цикл; `near-only` — только `near`, порядка нет (по имени). Девять строк: восемь
порядков, один `@exit 2`.
Кто исполняет — установщик (`02-installer`: порядок `manifest put` и отказ при цикле, P/02.4 Н1.7 `order`, `refuse`); других исполнителей нет (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
