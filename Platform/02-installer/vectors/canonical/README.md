# Векторы: канонический вид манифеста

Владелец — глава [P/02.2](../../spec/02.2-installer.norms.md) установщика (Н1.1 проекция, P/02.2-07). Участники —
загрузчик [P/02.1](../../spec/02.1-installer.norms.md) (вид строится только из принятого манифеста, вердикт `ok`) и установщик
`manifest put` [P/02.3](../../spec/02.3-installer.norms.md) Н3 (пишет вид рядом со строкой). Вектор — байты манифеста → байты поля
`manifest` строки вида `platform/manifest/<sub>/canonical/1`; обёртка `{form, rev, sha256, manifest}` и `rev` — не векторы, а
[приёмка главы 2.2](../../acceptance/2/README.md) (ADR-0089 доп. (1) Р13). Обе реализации — байт в байт. Окно главы 2.2 —
`decisions/inbox/2026-10-20-окно-главы-2.2-канонический-вид.md` (раздел 5, решение «Архитектора» — п. 8).

## Состав

| Что | Где | Кто пишет |
|---|---|---|
| таблица случаев | `cases.tsv` | строки `corpus-*`, `course-*` — построитель; строки `example-*` — «Спецификация» |
| ожидаемые байты | `expect/<case>.json` — по файлу на строку | построитель (`python skills/lesson-spec/scripts/form_source/build_canonical.py vectors`), руками не правятся |
| входы строк-примеров | `inputs/<имя>.subsystem.yaml` | «Спецификация» |

Входы строк:
- `corpus-<случай>` — каждый принятый случай корпуса главы 2.1 (`acceptance/1/verdicts.tsv`, вердикт `ok`);
- `course-<имя>` — каждый манифест курса `Source/tests/testdata/*.subsystem.yaml`;
- `example-<правило>` — по строке на правило Н1.1 (записка умолчаний `decisions/inbox/2026-10-19-умолчания-канонического-вида.md`,
  раздел 5): раздел без умолчания и с умолчанием, вложенный ключ, сахар ×3, П1 (и сказанный `snapshot: []`), П2–П5,
  `ordered`. Вход строки-примера — маленький манифест, который меняет одно правило против минимального; что он показывает, —
  поле `note`.

Проба мутаций `check_spec` (ADR-0089 Confirmation): снятие каждого `default` и каждой пометки `ordered` в источнике формы
главы 2.1 и пропуск каждого шага урока 2 меняют байты хоть одного вектора.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` — пояснения, пустые пропускаются. Первая непропущенная строка — заголовок
`case<TAB>input<TAB>expect<TAB>note`, дальше — по строке на случай; ровно четыре поля.

- `case` — имя случая: `[A-Za-z0-9][A-Za-z0-9_.-]*`, уникально в файле;
- `input` — путь файла манифеста от корня раскладки (курс или выгрузка `cammeta-specs`): через `/`, без `..`, на
  `.subsystem.yaml`; загрузчик главы 2.1 его принимает;
- `expect` — ровно `expect/<case>.json`: байты вида — JCS ([ADR-0072](../../../../decisions/0072-канонический-json-подписанных-документов-rfc-8785.md)),
  UTF-8, без перевода строки в конце;
- `note` — что показывает строка (не сравнивается).

## Прогон

Для каждой строки сторона читает байты файла `input`, строит канонический вид по Н1.1 главы 2.2 (своим проходом по дереву
загрузчика или общим кодом — «Решает реализация» п. 1) и сравнивает байты с файлом `expect` целиком. Иной байт, лишний
перевод строки или отказ загрузки — расхождение строки.
Кто исполняет — установщик (`02-installer`: «построить вид» P/02.2 Н3 — для `manifest put`, P/02.3 Н3, и для кластера из одного со встроенным манифестом, P/02.4 Н1.10). Только читают готовое: раннер воркера (`worker.exec` из вида, P/02.3 Н3 «Программа воркера из строки») и читатели вида (P/02.2 Н3 «Читатель»: метка, `rev`, `sha256`, схема) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Чего вектор не покрывает

Обёртка строки вида, порядок записи строка — вид — метка, «без изменений» с видом, отказ `toolarge` вида — приёмка главы
[`acceptance/2/`](../../acceptance/2/README.md). Схема вида — раздел «Форма канонического вида» норм главы 2.2 (P/02.2-05;
`check_spec` проверяет, что вид каждого входа её проходит). Читатель вида — правками читателей (P/02.2-06).
