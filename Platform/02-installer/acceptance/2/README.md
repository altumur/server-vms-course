# Приёмка P/02.2 — канонический вид при установке `manifest put`

Стенд, словарь директив и дверей — [общий README приёмки](../../../common/acceptance/README.md). Норма главы —
[`02.2-installer.norms.md`](../../spec/02.2-installer.norms.md) Н5; запись вида — [глава 2.3](../../spec/02.3-installer.norms.md)
Н3 «Смена манифеста» (установщик). В `puts.tsv` 7 установок; файлы установок — `puts/`. Окно главы 2.2 —
`decisions/inbox/2026-10-20-окно-главы-2.2-канонический-вид.md`, раздел 4 и решение «Архитектора» (п. 8): вид строится до
любой записи, вид выше потолка — отказ установки целиком, порядок записи — строка, вид, метка последней. Байты вида —
векторы [`canonical`](../../vectors/canonical/README.md); здесь — обёртка, `rev`, «без изменений» и граница потолка вида.

## puts.tsv

Формат `puts.tsv` [главы 2.3](../3/README.md) с четвёртой колонкой `canonical` и директивами между файлами. Установка —
команда `manifest-put {socket} {file}` раздела «Стенд» общего README приёмки; хранилище — экземпляр «Стенда» с потолком строки
524288 байт (общий README, «Параметры каждого экземпляра»).

**Форма файла.** UTF-8, строки через LF, поля через TAB. Строки, начинающиеся с `#`, и пустые строки пропускаются. Первая
не пропущенная строка — заголовок `case<TAB>puts<TAB>expect<TAB>canonical`, дальше — по строке на случай; ровно четыре поля.

- `case` — имя случая: `[a-z0-9_]+`, уникально в файле;
- `puts` — через один пробел, по порядку: имена файлов `puts/<имя>.subsystem.yaml` и директивы `@view-delete`,
  `@view-spoil`; первым и последним — файл;
- `expect` — `<код> <rev>`: `<код>` — код возврата **последней** установки (`0` или `2`), `<rev>` — десятичное `rev` строки
  `platform/manifest/<name>` после неё, где `<name>` — `name` последнего файла; `-` — строки нет;
- `canonical` — имя случая [`vectors/canonical/cases.tsv`](../../vectors/canonical/cases.tsv), байты `expect/<case>.json`
  которого — ожидаемое поле `manifest` строки вида; `-` — строки вида нет.

**Директивы** (между установками, через `admin.sock` экземпляра — `{socket}` «Стенда», операции P/01.1; `<name>` — `name`
файла перед директивой):
- `@view-delete` — `delete` строки `platform/manifest/<name>/canonical/1`;
- `@view-spoil` — прочитать строку `platform/manifest/<name>/canonical/1` и записать её же с `cas` по прочитанной версии, но с
  полем `manifest`, равным `{}` (иной вид: не проекция манифеста); прочие поля — как были.

**Исполнение.** Случаи независимы, порядок строк не важен. Для **каждой строки** раннер берёт новое пустое хранилище
(P/01.1; ни одного манифеста) и исполняет `puts` по порядку: файл — отдельным вызовом установки, директиву — записью хранилища.
Все установки, кроме последней, ДОЛЖНЫ вернуть `0`, каждая директива — пройти: иное — несовпадение случая (подготовка не
удалась). После последней установки раннер сравнивает:

1. код возврата — с `<код>`;
2. при коде `2` — stderr называет файл последней установки и ключ вида `platform/manifest/<name>/canonical/1` (оба входят в
   текст; вес и потолок в тексте не сравниваются);
3. `rev` строки `platform/manifest/<name>` — с `<rev>`, как в главе 2.3 (дверь хранилища `GET /v1/get?key=…`, поле `rev` в
   `items`; `-` — `items: null`);
4. метку `platform/manifest/<name>/rev`: её `rev` — тот же `<rev>`, `sha256` — `sha256` строки; `-` — метки нет;
5. строку вида `platform/manifest/<name>/canonical/1` (`items` по кодеку [семьи `canonical-row`](../../data/canonical-row.schema.json)):
   `form` — `"1"`, `rev` — `<rev>`, `sha256` — `sha256` строки, `manifest` — байты `expect/<canonical>.json` вектора байт в
   байт; лишние поля не сравниваются; `canonical` = `-` — строки вида нет.

Пункты 4–5 сравнивают состояние после установки, не порядок записей во времени: порядок строка — вид — метка и повтор
вида после конфликта `cas` — чтением по Н5 главы.

## Случаи

| № | Случай | Что проверяет | Норма |
|---|---|---|---|
| 01 | `first` | первая установка `testsub`: строка, вид и метка rev 1; `manifest` — вектор `course-testsub` | P/02.2-04, P/02.3-01 |
| 02 | `same_twice` | тот же файл снова — «без изменений»: rev 1, вид прежний | P/02.3 Н3 «Смена манифеста» |
| 03 | `view_deleted` | вида нет, файл тот же — не «без изменений»: строка rev 2, вид и метка rev 2 | P/02.3 Н3 («строка та же, а вида нет»); окно 2.2, Р12 |
| 04 | `view_spoiled` | вид не равен проекции, файл тот же — вид переписан, rev 2 | там же |
| 05 | `view_over_ceiling` | вес строки вида 524289 — на байт выше потолка, строка манифеста (523609) помещается: отказ целиком, код 2; строка, вид и метка — прежние rev 1 от `probe` | P/02.2 Н3, Н4; P/02.3 Н4 (окно 2.2, п. 8) |
| 06 | `view_at_ceiling` | вес строки вида ровно 524288 — вид записан, строка и метка rev 2; граница области принимаемых манифестов | P/02.2 Н1.2 `ceiling` (ADR-0089 доп. (1) Р11) |
| 07 | `sugared` | сахар `tables`, `bound_to`, без `snapshot` и `display` — вид установщика равен вектору | P/02.2-02, P/02.2-03 |

Вес строки вида — сумма байтов имён и значений `items` (P/01.1 Н1): `form` `"1"`, `rev` из одной цифры, `sha256` 64 знака,
`manifest` — `87 +` длина вида. Файлы 05 и 06 отличаются одним байтом поля `display.unit` (после `worker.exec` поле укорочено на 49 байт: вид 06 — снова 524201); их строки манифеста — под потолком.

## Кандидат: потолок хранилища не по умолчанию

Потолок вида — `max_value` ответа `GET /v1/status` хранилища, а не число 524288 (решение «Архитектора» по вопросу Go P/02 № 4). Стенд его не
меняет: потолок экземпляра — параметр «Стенда» (общий README, «Параметры каждого экземпляра»), формат `puts.tsv` колонки
потолка не имеет. Кандидат — пара случаев на экземпляре с `{row_ceiling}` не по умолчанию, файл `probe` (строка манифеста
265 байт, метка 74, строка вида `87 + 890` = 977; числа — после `worker.exec`, ADR-0091 доп. (5), находка cammeta-c-go I02-G01):

| Потолок `{row_ceiling}` | Установка | Ожидание |
|---|---|---|
| 976 | `probe` | код 2, ничего не записано: строки, вида и метки нет; stderr называет файл и ключ вида |
| 977 | `probe` | код 0, rev 1, вид — вектор `example-sections` |

Строка войдёт в `puts.tsv`, когда стенд и формат выразят потолок экземпляра на случай; до того — чтением.

## corrections.tsv

Журнал исправлений ИИ (ADR-0080 доп. 1): `date`, `sample` (образец ошибки генерации), `fix` (какая строка главы уточнена),
`languages`. Строка 2026-10-23 — сдвиг границ веса после `worker.exec` (находка cammeta-c-go I02-G01).

## Проверки чтением

Порядок записей во времени (строка — вид — метка), повтор `cas` вида, кластер из одного процесса (P/02.4 Н1.10, Р15) и
читатель вида (P/02.2-06 — правками читателей) — чтением по Н5 главы.
