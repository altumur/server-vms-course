# Приёмка P/02.1 — вердикты загрузчика спек

Сценарии [норм главы 2.1](../../spec/02.1-installer.norms.md) Н5 (ADR-0080); стенд — [общий README приёмки](../../../common/acceptance/README.md). Дверь главы — сам загрузчик: файл подаётся один, как спека подсистемы, и ответ один из двух.

## verdicts.tsv

Табуляцией: `case`, `verdict`. Строки с `#` и пустые — не сценарии.

- `case` — файл `cases/<case>.subsystem.yaml`, загруженный **один** (без каталога других спек).
- `verdict` — `ok`: спека грузится; `refused`: отказ загрузки.

Раннер приёмки:

- грузит каждый файл штатным путём загрузки реализации (тем, которым читается спека из хранилища или файла, Н3 главы), не обходной функцией; способ вызова — команда загрузки одного файла, которую реализация назвала в описании (нормы главы, «Решает реализация» п. 3): код выхода 0 — спека, иной — отказ;
- `refused` засчитывается только как **отказ в словах, называющий файл** (имя файла входит в текст); аварийное завершение, исключение другого вида, частично загруженная спека — несовпадение;
- `ok` засчитывается, когда загрузка вернула спеку;
- проверяет, что множество файлов в `cases/` равно множеству строк таблицы: лишний файл или лишняя строка — несовпадение;
- для случаев из `diagnostics.tsv` дополнительно проверяет диагностические сведения по правилам ниже;
- СЛЕДУЕТ прогонять через путь установки спеки (`spec put` реализации, глава 2.3 Н3) выборку: все случаи с вердиктом `ok`, по одному отказу на каждый класс `refused:<класс>` из `classes.tsv` (первый по имени случая), три названных ниже принятых файла и все установки `puts.tsv` (глава 2.3); вердикты остальных случаев проверяет режим загрузки (решение ADR-0080 доп. (17) п. 2). Принятый файл ложится строкой `platform/spec/<name>`; отказанный не кладётся в хранилище, код возврата ненулевой. Установка проверяет кандидата в полном каталоге, а три принятых файла (`bound_to_string`, `blob_required_false`, `secrets_reader_domainconsole`) называют `worker.requests: [testsub]`; поэтому прогон через `spec put` ведётся в хранилище, где уже установлена `testsub` (`Source/tests/testdata/testsub.subsystem.yaml`). В пустом хранилище эти три файла верно получают `refused:catalogue`.

Правила, по которым расставлены вердикты, — нормы главы Н1 (текст, документ, поле, ссылки) и Н4; здесь их нет, чтобы не было двух версий одной нормы (ADR-0003). Происхождение: общая таблица `spec_verdicts.tsv` (ревью 14 и 15, вердикты «Архитектора» 2026-10-06), перенесённая сюда 2026-10-14 с восемью новыми случаями; прежнее место обе стороны снимают своими окнами.

## puts.tsv

Установка спеки `spec put` (`puts.tsv`, `puts/`) — [приёмка главы 2.3](../3/README.md).

## classes.tsv

Класс отказа Н4 у выбранных случаев: табуляцией `case`, `class` (`text`, `name`, `key`, `value`, `reference`,
`catalogue`). Каждый `case` есть в `verdicts.tsv` с `refused`; класс сравнивается с классом штатного отказа загрузчика,
извлечённым так же, как сведения `diagnostics.tsv` ниже. Верный вердикт с другим классом — несовпадение: в сверке python и
go 2026-10-18 13 случаев были зелёными у обеих при разном классе. Корпус проверяет вердикт, класс и путь.

## diagnostics.tsv

Дополнительные ожидания для выбранных отказов: табуляцией `case`, `paths`, `lines`. Заголовок с `#` и пустые
строки не являются случаями. Каждый `case` встречается один раз и имеет `refused` в `verdicts.tsv`.

- `paths` — JSON-массив путей; каждый путь — массив имён ключей от корня; индекс списка — целое число JSON (`0`), имя ключа — строка
  (`"0"`): это разные сегменты (Н4 «Диагностика»). Пути — множество: в таблице они записаны каноническим порядком —
  по байтам пути JSON Pointer (RFC 6901), номера строк — по возрастанию (ADR-0087 доп. (3) Р2); сравнивается множество
  названных в отказе путей, пропущенный или лишний путь — несовпадение. В `unknown_multiple` нужны
  все три пути в одном отказе, а не только первая найденная опечатка.
- `lines` — JSON-массив обязательных номеров строк исходного файла, начиная с 1. Пустой массив означает,
  что этот случай номера строк не проверяет; он не запрещает их в отказе. Для `dup_top_key_name` нужен номер
  второго объявления `name` — 36; ссылка только на первое объявление недостаточна.
- Раннер извлекает эти сведения из **штатного отказа загрузчика**: из уже предоставленных им сведений об
  ошибке или из текста в принятом реализацией формате. Он описывает способ извлечения; имя случая и входной
  файл не служат источником выдуманных путей или номеров для сравнения. Разделители пути, подписи номера строки
  и остальной текст сообщения остаются выбором реализации. Эта таблица задаёт значения для проверки,
  а не обязательный внутренний тип ошибки или дополнительную дверь загрузчика.
- Требование назвать источник из `verdicts.tsv` сохраняется. Например, `unknown_depth4.subsystem.yaml: ошибка`
  не проходит диагностику: нет пути `unit.fields.name.requried`. Отказ для `dup_top_key_name` без строки 36
  тоже не проходит, даже если имя файла и путь `name` названы.

У остальных случаев таблица вердиктов проверяет принятие/отказ и имя источника. Полнота их диагностики
проверяется чтением по Н5 норм: ожидаемые пути и строки для них здесь пока не заданы. Описание реализации
называет соответствующие ветви и места добавления этих сведений; зелёный `verdicts.tsv` их не подтверждает.

## Дополнительная проверка строковых имён полей (R36-01)

В минимальной корректной спеке отдельно для `unit.fields` и `tables.<t>.fields` ключи 1, true, null и 1.5 (без кавычек) дают `refused:text` по Н1.1 keys: простой ключ, который таблица `scalars` читает не строкой, — отказ слоя текста везде, в том числе в ключах значений `json` и `display.options` (`display_options_bool_plain_key`); путь и строка — по Н4 «Диагностика». Те же имена в кавычках — строки и проходят. Пара 1/"1" отказывается целиком (`text`), не преобразуется в одну строку с потерей поля. Эти входы добавлены как profile_unit_key_*/profile_table_key_* в verdicts.tsv и проверяются тем же штатным загрузчиком, что остальные случаи; чтение типов YAML-узлов само по себе не доказывает его соответствия.

Случаи profile_* покрывают положительные соседние значения и ограничения P/02.1-13…17,
а также типы ключей полей и принадлежность worker.writes (P/02.1-06/07, P/02.5-01).
Подготовленные вердикты — не результат запуска реализации: автор проверил данные и заявленный
канон, штатный загрузчик исполнения здесь не запускался.

## Проверка класса ошибок R37 (Codex)

Проверить не только изменённое поле сгенерированного входа, но и весь общий фон: lease off остаётся строкой, true/false не подменяют off/on при чтении другой YAML-библиотекой. Одиночные verdicts и проверка каталога — отдельные свидетельства. Во время установки разные имена спек меняет один оператор последовательно; две записи одной спеки разрешаются CAS. Перед первой записью кандидат проверяется в полном подтверждённом каталоге.

Это предмет проверки норм/данных и будущего стенда, не выполненное испытание реализации.

Границы :int по P/02.1: binary64, модуль не больше2^53−1; bool/null/строка/нечисловое/неfinite/выход за границу —400, не языковое приведение. Проверить±0.5,±7.9,±(2^53−1),1e16,1e21 и канонический десятичный результат без экспоненты.

Проверка каталога включает пересечение имени с собственными rows/tables: даже каталог из одной такой спеки отказывается. Это отдельный каталоговый отказ; одиночный разбор файла не объявляется проверкой непересечения.


## Полный перечень имён и проверка каталога (K38)

17 новых k38_sub_* — отказы остальных зарезервированных имён. Вместе с
name_reserved_platform и r37_sub_where/r37_sub_metrics/r37_sub_healthz проверяются
все21 слова; r37_sub_where2 остаётся допустимым соседом. Фон17 новых файлов сохранён
байт в байт, включая lease off; меняется только верхний name.

Непересечение проверяется чтением реализации загрузить_каталог, включая каталог
из ОДНОЙ спеки. Раннер verdicts вызывает загрузить, а не загрузить_каталог;
один файл не является автоматически каталогом из одного файла. Поэтому добавлять
refused для корректного одиночного разбора name=own rows/table здесь нельзя.
В описании реализации указываются ветвь каталоговой проверки и проверенные случаи:

| Состав каталога | Конфликтующая семья | Ожидание проверки каталога |
|---|---|---|
| A=B: одна спека name=b | unit.rows=b | refused:catalogue |
| A=B: name=b, unit.rows=b_rows | map tables содержит b | refused:catalogue |
| A=B: name=b, unit.rows=b_rows | list tables=[b] | refused:catalogue |
| A≠B: name=a и name=b | rows спеки a равно b | refused:catalogue |
| A≠B: name=a и name=b | map tables спеки a содержит b | refused:catalogue |
| A≠B: name=a и name=b | list tables спеки a содержит b | refused:catalogue |

Остальные части — корректный фон base; у второй спеки rows=b_rows, у первой a_rows,
кроме явно изменяемого rows. Положительный контроль каждой строки: изменить
конфликтующее имя семьи b на ledger (и ссылки на него), сохранив имена спек a/b;
эта проверка непересечения проходит. Для map остаётся корректное объявление таблицы,
для list — только имя семьи, без приписывания ей HTTP-дверей. Результат совпадает
при любом выборе root и перестановке двух спек. При отказе каталог не выдаётся
частично и установщик не выполняет первую запись.

Это назначенная проверка чтением с предметом и причиной по P/02.1-20, не выполненный
запуск загрузчика/каталога/установщика. Автор проверил норму и конечные примеры.

R38-02: три r38_unit_* без unit/rows/id должны отказать по обязательности с путём отсутствующего значения; r38_unit_minimal имеет rows=things/id=numeric без fields и должен загрузиться с пустым набором полей. Общий каталог не требуется; все прежние251 вход неизменны. Проверка вердиктов — штатный загрузчик, авторская проверка структуры YAML его не заменяет.

## Раздельная проверка формы и ссылки group_by (R39-03)

`group_by_unknown_field` содержит отображение `{field: nosuch}`: форма верна, но поле не объявлено. `r39_group_by_known_field` отличается от него только именем `name` и имеет вердикт ok. Прежний скаляр сохранён как `r39_group_by_scalar` с refused по форме; его отказ не доказывает проверку ссылки. Общий фон и строка lease off сохранены побайтно. Это подготовленные входы и ожидания; штатный загрузчик автором не запускался.

Авторская проверка класса A39-01: `fields_derived_items_unknown` отнесён в Н5 к неизвестным ключам Н1.2. `unit.derived` не входит в грамматику уроков; отказ этого файла не подтверждает проверку ссылки items. Два display_tree_*_unknown проверяют ссылки, а display_tree_word_erase — неизвестный ключ erase; в Н5 они также отнесены к соответствующим группам. Входы и вердикты сохранены, новая форма derived не вводится.
