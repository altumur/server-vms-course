## puts.tsv

Установка манифеста `manifest put` реализации (Н3 «Смена манифеста», имя и форма команды — «Решает реализация» п. 3); раннер зовёт её
командой `manifest-put {socket} {file}` раздела «Стенд» общего README приёмки (пилот хранилища, А6).

**Форма файла.** UTF-8, строки через LF, поля через TAB. Строки, начинающиеся с `#`, и пустые строки пропускаются. Первая
не пропущенная строка — заголовок `case<TAB>puts<TAB>expect`, дальше — по строке на случай; ровно три поля.

- `case` — имя случая: `[a-z0-9_]+`, уникально в файле;
- `puts` — имена файлов `puts/<имя>.subsystem.yaml` через один пробел, по порядку установки, и директивы `@rev-max`,
  `@shell-put <имя>` между ними; первым и последним — файл; оболочки подсистемы рядом с манифестом нет, пока её не
  положит `@shell-put` (Н1.5 `shell`: нет файла — поле не пишется);
- `expect` — `<код> <rev>`: `<код>` — код возврата **последней** установки (`0` или `2`), `<rev>` — десятичное значение поля
  `rev` строки `platform/manifest/<name>` после неё, где `<name>` — `name` последнего файла; `-` — строки нет.

**Директивы** (только эта глава; через `admin.sock` экземпляра — `{socket}` «Стенда»; `<name>` — `name` файла перед директивой):
- `@rev-max` — прочитать строку `platform/manifest/<name>`, метку `platform/manifest/<name>/rev` и вид
  `platform/manifest/<name>/canonical/1` и записать каждую с `cas` по прочитанной версии, где `rev` = `9007199254740991`
  (2^53 − 1), прочие поля — байт в байт прежние: состояние, как после честной установки с такой ревизией (Н1.5 `rev`);
- `@shell-put <имя>` — положить рядом с манифестом `<name>` оболочку `<name>.shell.html` с байтами `puts/<имя>.shell.html`
  (прежнюю — заменить); она действует для следующих установок строки; рабочая копия — своя у каждой строки.

**Исполнение.** Случаи независимы, порядок строк не важен. Для **каждой строки** раннер берёт новое пустое хранилище
(P/01.1; ни одного манифеста, в том числе `testsub`) и ставит файлы этой строки по порядку в одно и то же хранилище командой
установки, каждый отдельным вызовом. Все установки, кроме последней, ДОЛЖНЫ вернуть `0`: иное — несовпадение случая
(подготовка не удалась). После последней раннер сравнивает:

1. код возврата — с `<код>`;
2. при коде `2` — stderr называет файл последней установки (имя файла входит в текст), как у `verdicts.tsv`; отказ по атрибуту
   `on…=` в оболочке — файл оболочки `<name>.shell.html` (P/02.3 Н4: «stderr называет файл и атрибут»; имя атрибута — чтением);
3. `rev` строки `platform/manifest/<name>` — с `<rev>`: строка читается дверью хранилища (`GET /v1/get?key=platform/manifest/<name>`,
   поле `rev` в `items`) или командой `manifest show` реализации; `-` — `items: null` / строки нет.

Больше ничего не сравнивается: ни метка `/rev`, ни текст отказа сверх имени файла. Случаи `self_*`, `other_*`,
`prefix_clash` — проверки каталога (глава 2.1 Н3 `загрузить_каталог`: «A=B», совпадение `metrics.prefix`): одиночная загрузка этих
файлов даёт `ok`, отказ — только у установки в каталоге. `same_twice` — тот же файл дважды: «без изменений», rev 1;
`changed` — изменённый тем же именем: rev 2. Случаи `creates_*`, `uses_*`, `os_name_clash` (ADR-0091) — проверки каталога
главы 2.1 Н3 для `worker.creates`, `worker.uses` и имён ОС: каждый отказной случай отличается от `creates_ok` или `uses_ok`
одной причиной; `creates_nested_prefix` ставит двух заказчиков, отказ — у второго (`cust-x`). Адресата или владельца доли в каталоге ещё нет — проверка ждёт его установки (`creates_no_target`, `uses_no_owner` — 0);
`target_after_customer_mismatch` — отказ у установки адресата после несовместимого заказчика. Случаи `kind_dup`,
`door_domain_*` (ADR-0091 доп. (14), (17), (18) п. 6) — виды токена домена: тот же вид у второй подсистемы — отказ; вид
маршрута `door.routes[].domain` объявлен другой подсистемой каталога или своей — принят; вида нет — отказ (отсрочки нет).
Случаи `near_*` (ADR-0091 доп. (26) п. 2) — отсрочка `near`: подсистемы `near.sub` нет — клиент принят, проверка полей
ждёт; адресат после несовместимого клиента — отказ у установки адресата.

## Проверки чтением

Строка и метка манифеста в хранилище, все причины отказа старта, допустимая отставшая метка, остановка при смене метки и ветвь
`toolarge` установщика — чтением по Н5 главы: `puts.tsv` сравнивает только код последней установки, имя файла в stderr и
`rev` строки.
