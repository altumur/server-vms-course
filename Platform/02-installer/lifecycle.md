# Манифест и установщик — жизненный цикл (урок P/02)

Контракт жизненного цикла установщика `w2cctl` и его команд (ADR-0083 доп. (2) п. 1): установка и обновление, установка манифеста,
вывод прав, центр сертификатов, скрипт воркеров по заказу. Стадия A — поверх нынешних норм М10 и М11. Нормы здесь не
пересказываются: каждая строка ведёт к своей норме.

Нормы: [P/02.4](spec/02.4-installer.norms.md) (Н1.1 юниты, Н1.2 окружение, Н1.5 воркеры по заказу, Н1.6 сертификаты,
Н1.7 установка, Н1.9 команды и `w2cctl secrets`, Н1.10 кластер из одного, Н4), [P/02.3](spec/02.3-installer.norms.md)
(Н1.5 строка манифеста, Н3 «Смена манифеста», Н4), [P/02.5](spec/02.5-installer.norms.md) (Н2 инструмент прав,
Н3 «сгенерировать», «установить»); поздние главы — [P/02.4](spec/02.4-installer.norms.md) Н1.12 порты и юниты домена,
Н3 «установка домена» (перенос урока 8, стадия B).

## Запуск

Установщик — не служба, а команды оператора; повтор установки — обновление.

| Команда | Что | Норма |
|---|---|---|
| `install.sh` | установка и обновление: код, пользователи и группы, каталоги, манифесты, окружение и файлы ролей (никогда поверх), ключ секретов, юниты, центр, файл прав, `manifest put`, `enable` | P/02.4 Н1.7 `install` |
| обновление сервера за сервером | `POST /drain` → `safe: true` → остановить, обновить, запустить → `DELETE /drain`; последним — подъём схемы | P/02.4 Н1.7 `upgrade`, P/06.6 Н2.3, Н3 «поднять_схему» |
| `w2cctl manifest put <файл>` | установка одного манифеста: загрузка, полный каталог, строка, затем метка `/rev` | P/02.3 Н3 «Смена манифеста» |
| `w2cctl manifest status [-rights]` | состояние строк манифестов; с `-rights` — и файла прав | P/02.4 Н1.9, P/02.5 |
| `w2c-run.sh <роль>` | раннер процессов: `configstore`, `controller <sub>`, `console`, `resource`, `domain`, `domainconsole`, `domainagent`, `worker <sub> <слот>`, `domainworker <sub>` (исполняют `worker.exec` строки манифеста, `W2C_MANIFEST_REV`), `workers`, `rights`, `part <sub> <часть>` (часть подсистемы: значения юнита и файл подсистемы, без `W2C_ROLE`); окружение — значения юнита → `roles/<W2C_ROLE>.env` → `w2c.env` → файл подсистемы (раньше прочитанное побеждает), файлы — разбором, не `source`; `W2C_ROLE` не той роли — код 2 | P/02.4 Н1.2, Н1.9 |
| `w2cctl rights -deployment <имя> [--check <файл>]` | вывод прав из `MANIFEST_DIR`; `--check` — по смыслу | P/02.5 Н2, Н3 |
| `w2c-ca.sh init \| issue \| revoke \| crl \| own` | центр и комплекты ролей | P/02.4 Н1.6 |
| `w2cctl secrets new \| seal \| rotate \| status` | кольцо ключей | [договор запечатывания](../common/contracts/sealing.md), P/02.4 Н1.9 |
| `w2cctl mirror \| space \| retention \| tls status \| domain move` | строки оператора и проверки | P/02.4 Н1.9 |
| `w2c-workers.sh` | скрипт воркеров по заказу: `w2c-workers.service` (`Type=oneshot`, `Restart=no`, `User=w2c-workers` без групп, один на сервер) и `.timer` (`OnBootSec` 1–2 мин, `OnUnitActiveSec` 1 мин); ряды `<sub>_workers_wanted{server}` → `start`/`stop` экземпляров `<prefix>-<SERVER_NAME>-<n>`, n 2…99 (ADR-0084) | P/02.4 Н1.1, Н1.5 |
| кластер из одного со встроенным манифестом | процесс коробки сам пишет строку манифеста и метку — правом `admin`, как установщик | P/02.3 Н1.5, P/02.4 Н1.10 |

| `W2C_BOX` | корень установки | `/opt/w2c` | P/02.4 Н1.2 |
| `W2C_ENV` | файл общих настроек; `roles/` — рядом | `/etc/w2c/w2c.env` | P/02.4 Н1.2 |

| `SECRETS_KEY` | путь кольца: по раскладке `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c` — ссылка), вне каталога хранилища, корня объектов и корня событий | — (раскладка установщика: юниту — `<PLATFORM_DIR>/etc/secrets/platform.key`; не задан у процесса — режим разработки, разбор ревью стадии A 6–7, № 19) | P/06.2 Н1.2, P/02.4 Н1.1 `dirs`, Н1.2 |

## Флаги

Нет: команды оператора берут свои аргументы (выше), процессы платформы — только окружение (P/02.4 Н1.2 «Канал
настройки»).

## Каталоги и файлы

| Путь | Что | Норма |
|---|---|---|
| `/etc/w2c` → `/data/platform/etc`, `/etc/<sub>` | ссылки; настоящий каталог на их месте — отказ установки | P/02.4 Н1.1 `dirs`, Н1.7 `install.refuse` |
| `/etc/w2c/w2c.env`, `/etc/w2c/roles/<роль>.env`, `<W2C_SUB_ENV>`, `/etc/w2c/configstore.env` | файлы окружения: создаются, никогда не переписываются; грамматика — [договор файла окружения](../common/contracts/env-file.md), разбор, не `source` | P/02.4 Н1.2, Н1.7 |
| `/etc/w2c/configstore-rights.json` | файл прав, по смыслу равный выводу; иначе установка отказана | P/02.5 Н3 «установить» |
| строки `platform/manifest/<sub>`, `platform/manifest/<sub>/rev` | строка манифеста и метка | [каталог](../common/data/catalog.tsv), P/02.3 Н1.5 |
| `/etc/w2c/tls/ca.pem`, `ca.next.pem`, `revoked`, `crl.pem`, `<роль>/server.pem`, `<роль>/server.key` | центр и комплекты ролей | [каталог](../common/data/catalog.tsv), P/02.4 Н1.6 |
| `/etc/w2c/secrets/platform.key` | кольцо: `secrets new` создаёт, `rotate` дописывает сверху | [каталог](../common/data/catalog.tsv), [договор запечатывания](../common/contracts/sealing.md) «Файл кольца» |
| юниты Н1.1 и юниты сокетов `configstore-*.socket` | пишет `install.sh` | P/02.4 Н1.1 |

## Коды выхода

| Код | Когда | Норма |
|---|---|---|
| 0 | установка или обновление прошли; `manifest put` положила или «без изменений» | P/02.4 Н1.7, P/02.3 Н3 |
| 2 | `manifest put`: файл отказан загрузчиком, полный каталог отказан, `toolarge`, оболочка с `on…=` | P/02.1 Н4, P/02.3 Н4 |
| ≠ 0 | установщик: отказ до изменений или после начала записи — с фазой и путём, новые службы не включаются | P/02.4 Н1.7 `failure`, Н4 |
| ≠ 0 | `rights --check`: файл по смыслу не равен выводу; вывод отказан на непредставимом объявлении | P/02.5 Н4 |

Скрипт воркеров, который у роли ничего не запустил и не остановил (нет файла роли — роль пропущена, обход идёт
дальше; ряда нет или он не читается; консоль молчит; polkit отказал), пишет строку лога; код выхода для этого норма
не задаёт (P/02.4 Н1.5 rules, Н4).

## Сигналы и готовность

Команды — однократные. Скрипт воркеров — `Type=oneshot`, повтор задаёт таймер; останавливает только экземпляры с n ≥ 2 сверх ряда, с
наибольшего номера (P/02.4 Н1.5 rules 3).

## Стенд

«Стенд» — [общий README приёмки](../common/acceptance/README.md) (разбор ревью стадии B 3–5, № 33):
- команда загрузки одного файла манифеста — `{file}` (P/02.1, корпус `verdicts.tsv`);
- `manifest-put {socket} {file}` — через `admin.sock`, манифесты стенда по одному до первого `@start`;
- команда вывода прав — `{manifests}`, `{deployment}` (`dep`), `{file}`: `{rights}` приёмок, перенесённых из М10/4–11 (разбор ревью стадии B 3–5, № 34), и варианты главы 2.5.
