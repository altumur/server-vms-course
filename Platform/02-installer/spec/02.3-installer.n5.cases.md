### Case block 2

A removed mark — «unchanged» brings it up; a mark not by the form — `manifest put` refuses, writes nothing — the acceptance of chapter 2.2
(`rev_deleted`, `rev_spoiled`; Gemini audit of P/02, the Architect's forms). Checked by reading the implementation: the row and the mark of the manifest in the store, an unreadable row at `manifest put`, all causes of the start refusal from N4 and the admissible lagging mark, the stop on a change of the mark, the stop with code 2 on a mark not by the form at a running process, and an unconfirmed read of the mark is not a change ([system stand](../../common/acceptance/system/README.md); the stand does not spoil the mark under a running process; analysis of review of stage A 6–7, B2).
The two start codes are checked by reading as well: a confirmed unfitness — code 2 without a restart; a read that is not confirmed during `START_WAIT` — code 1,
the supervisor restarts. The test of the implementation for it: the store answers the schema check, then stops answering before the read of the manifest row
and answers again within `START_WAIT` — the process starts by the row without a refusal; if the store stays silent longer, the process exits with code 1.
The seams of the lesson have no directive that breaks the store between two reads of a process, so this test is not a seam.

### Case block 3

Static files and the declared shell (ADR-0094 B7): a list with the files next to it is accepted — all extensions, a nested segment, a name
that only starts with `api`, an empty file; the same file twice — «unchanged» (`files_ok`, `files_same_twice`); no file — code 2,
the row is the previous one or there is none (`files_missing`, `files_missing_second`); `console.shell: true` without a shell — code 2, with a shell — accepted
(`shell_declared_missing`, `shell_declared_ok`); removal and appearance of the list — a new revision (`files_dropped`, `files_added`). The forms of the row `files` and of the parts — 6.5 sc. 26;
the file bytes changed with the same manifest and the removal of parts — by reading: `puts.tsv` does not change files between installations. Ceilings
(`@file-fill`): a file one byte above `FILE_MAX` and a sum one byte above `FILES_TOTAL_MAX` — code 2, the row is the previous one (`files_file_over`,
`files_total_over`), exactly `FILE_MAX` — accepted (`files_file_max`); exactly `FILES_TOTAL_MAX` — by reading: the case would run through the store
43 MiB of rows for the sake of one comparison. The bound of the field `size` — also the vectors `family-read`.

### Case block 4

The bound of `rev`: with `rev` of the row 2^53 − 1 the same manifest — «unchanged», code 0, a new revision — a refusal before any write,
code 2 (N4) — `puts.tsv` `rev_max_same`, `rev_max_changed` (the directive `@rev-max`; coverage audit of P/02, B02); `toolarge`
of the main row — `toolarge_row` (B01); a shell with `on…=`, «unchanged» and a change of the shell by bytes — `shell_onclick`,
`shell_same_twice`, `shell_changed` (`@shell-put`; B03); the names of the key, `rev` and the attribute in stderr — by reading by N4.
