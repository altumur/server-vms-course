# P/02.4 — Установщик: нормы

Канон главы. [Лекция](../02-installer.md), [инструкция](02-installer.README.md), [жизненный цикл](../lifecycle.md),
[векторы скрипта воркеров](../vectors/workers-script/README.md). Своего HTTP-контракта у урока нет: дверей у установщика
нет. Каталога приёмки у главы нет (Н5). Глава перенесена из М10/11
(стадия B, ADR-0083 доп. (1): без изменения поведения): Н1.1, Н1.2, Н1.5, Н1.7, Н1.9, сторона выпуска Н1.6, проходы
«старт сервера» и «выпустить и отозвать сертификат», строки Н2, Н4 и Н5 установщика, раннера и скрипта воркеров; из
М11/12 — Н1.1 и `hot`, `durable` Н1.2 (здесь Н1.10,
Н1.11); из М10/7 — команды `w2cctl secrets` (Н2 там, здесь
Н1.9 «Команды `w2cctl secrets`»); из М10/6 — правило адреса и сертификат
роли (Н1.6 «Правило адреса»). Номера подразделов Н1.1–Н1.9 — прежние номера М10/11. Отказ сервера (Н1.4) и проход «вырвать питание» — [P/04](../../04-controller/spec/04-controller.norms.md) Н1.4а, Н3;
`door.pass` (Н1.8) — [P/06.5](../../06-console/spec/06.5-console.norms.md) Н1.8; юниты и порты домена (Н1.12, из
М11/12 Н1.8) и установка домена (Н3 «установка домена», из
М11/2 Н3) — поздний слой главы, вводят главы
[8.10](../../08-domain/spec/08.10-domain.norms.md) и [8.2](../../08-domain/spec/08.2-domain.norms.md) (перенос урока 8,
стадия B). Ссылка «P/0N[.K]» — урок или глава модуля;
«уроки 8.K» — главы позднего слоя урока P/08; «глава 2.K» — глава этого урока; «P/01.K» — глава урока 1. Id норм — `P/02.4-MM`; соответствие прежним id —
[`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у строк и файлов главы нет.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `platform/mirror`, `platform/space`, `<sub>/retention`, `<sub>/alarms_retention`, `/etc/w2c/roles/<роль>.env`, `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/ca.next.pem`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem`, `/etc/w2c/tls/<роль>/server.pem`, `/etc/w2c/tls/<роль>/server.key`, `/etc/w2c/secrets/platform.key` (разбор ревью стадии A 6–7, № 5), `<файл восстановления домена>` (разбор ревью стадии A 8–10, № 29; перенос урока 8, стадия B);
- пишет: `<sub>/<manifest:unit.rows>/<id>` (cas), `<sub>/<manifest:tables>/<имя>` (cas), `door/signer` (cas), `domain/signer` (cas), `domain/signer-pending` (cas), `domain/book-seal` (cas), `domain/member-key` (cas), `domain/users/<имя>` (cas), `domain/break-glass/<кластер>` (cas), `domain/keys` (create), `domain/root` (create);
- читает: `platform/manifest/<sub>`, `platform/manifest/<sub>/rev`, `/etc/w2c/configstore-rights.json`.

Строки `domain/keys` (набор rev 1, подписанный корнем) и `domain/root` пишет установка домена — поздний слой главы
(Н3 «установка домена», вводит глава 8.2; разбор ревью стадии B 3–5, № 10). Строки `domain/signer`, `domain/signer-pending`, `domain/book-seal`, `domain/member-key`, `domain/users/<имя>`,
`domain/break-glass/<кластер>` пишет `w2cctl secrets seal`: умолчание префиксов — `domain/` (Н1.9 «Команды
`w2cctl secrets`»), конверты `*_secret` перезапечатываются `cas` по прочитанной версии (исходы значения — [договор запечатывания](../../common/contracts/sealing.md) «Перезапечатать значение»; `cas` и код — здесь, C06-RESEAL-33-01); владельцы строк — главы урока
[P/08](../../08-domain/README.md) (каталог) (разбор ревью стадии B 3–5, № 10). Файл восстановления домена создаёт
установка домена (Н3 «установка домена» шаг 3) и читают команды смен; его форма и правила чтения —
[договор основания домена](../../common/contracts/domain-founding.md) «Корень и файл восстановления» (`recovery_file`, `place`, `mode`) (разбор ревью стадии A 8–10, № 29;
перенос урока 8, стадия B).

```yaml
  rule: ни один юнит не монтирует корень целиком; всё изменяемое — под /data/platform
```

Юниты `w2c-domain.service`, `w2c-domainconsole.service`, `w2c-domainagent.service` — поздний слой главы: вводит урок 8
(глава [8.10](../../08-domain/spec/08.10-domain.norms.md)); их строки — Н1.12 «Порты и юниты домена» (P/02.4-13; перенос
урока 8, стадия B: строки Н1.1 сведены в Н1.12 без повтора).

### Н1.2 Контракт окружения

Файлы окружения, порядок их чтения раннером и юнитом части, `W2C_ROLE` юнита и команды — [договор файла
окружения](../../common/contracts/env-file.md) «Файлы и порядок чтения» (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, Б-26).

Файлы окружения (`w2c.env`, `roles/*.env`, файл подсистемы, `configstore.env`) читаются разбором, не `source`, по
[договору файла окружения](../../common/contracts/env-file.md) (грамматика `KEY=VALUE` и края B19 перенесены туда без
изменения поведения; догадка стадии C C04-ENV-01, решение «Архитектора» 2026-10-23); строка не по грамматике — отказ запуска с кодом 2 и строкой лога, которая
называет файл и номер строки; файла нет — пропуск, файл не читается — отказ запуска, код 2 (договор, «Файла нет»; W03-G07).

Переменные окружения процессов — форма, смысл, умолчание, кто ставит — [договор файла окружения](../../common/contracts/env-file.md)
«Переменные окружения» (таблица перенесена туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, А-07, А-09).

**Канал настройки и раскладка `PLATFORM_DIR`** (решение «Архитектора», второй пилот, Н-4):
- процессы платформы — консоль, контроллер, воркер, ресурс, процессы домена — настраиваются только переменными
  [договора файла окружения](../../common/contracts/env-file.md) «Переменные окружения» и аргументом имени воркера (экземпляр `%i` юнита); собственных флагов путей и адресов у них нет; флаги есть только у
  демона хранилища ([P/01.3](../../01-store/spec/01.3-store.norms.md) Н1.3 «Флаги демона»);
- хранилище — `<PLATFORM_DIR>/configstore` (`-dir` юнита Н1.1);
- объекты — корень `OBJECTS` / `PLATFORM_OBJECTS`, по умолчанию `<PLATFORM_DIR>/objects`;
- события — корень `RESOURCE_ROOT` / `EVENTS`, по умолчанию `<PLATFORM_DIR>/events`; замки присутствия — в корне
  событий ([договор замка присутствия](../../common/contracts/presence-lock.md) `presence_lock`);
- кольцо — `SECRETS_KEY`, по раскладке Н1.1 — `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c/secrets` — ссылка), вне каталога хранилища, корня объектов и корня событий: оно не уходит ни с копией хранилища, ни с
  объектами, ни с зеркалом событий ([договор запечатывания](../../common/contracts/sealing.md) «Файл кольца»).

### Н1.5 Воркеры по заказу

```yaml
order:        число процессов роли на сервере задаёт контроллер — строка <sub>/want/<сервер> (P/04 Н1.1; ADR-0084):
              want — абсолютная цель 1…99, базовый <prefix>-<SERVER_NAME>-1 в неё входит; консоль отдаёт ряд
              <sub>_workers_wanted{server} для каждой строки заказа (P/06.5 Н3 «/metrics — текст»)
extra_unit:   дополнительный воркер — экземпляр того же юнита роли <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>, n 2…99
              (Н1.1): те же учётные данные, ключи, пользователь и группы; захват слота обычный (P/03.2 Н3); особого юнита,
              файла и переменной нет
script:       w2c-workers.sh, раз в минуту таймером, User=w2c-workers без групп; один на сервер — все роли сервера;
              polkit: только start и stop, только пользователем w2c-workers, только полные имена
              <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>.service ролей этого сервера, n — [2-9]|[1-9][0-9] без ведущих
              нулей; базовый -1, чужой сервер, иные юниты и глаголы — отказ (ADR-0084 доп. (1) Р11)
rules:
  1. читает свои ряды <sub>_workers_wanted{server=<SERVER_NAME>} всех ролей сервера из /metrics консоли, ряды других
     серверов не читает, команд не исполняет; URL консоли — own_url договора сертификата роли (CONSOLE_HOST,
     CONSOLE_PORT w2c.env; https при ca.pem в W2C_TLS_DIR, иначе http), проверка сервера — клиент своего кластера
     own_client того же договора, роль console (Н1.6 roles; ADR-0075 доп. 2026-10-26 (4) п. 3, (5) пп. 1–2)
  2. ряда роли нет, он не читается (значение не по форме метрики P/06.5 Н3 — целое без ведущих нулей, знака и дроби: `02`,
     `2.0`, `+2` — ряда нет, стадия A, A6 — или вне 1…99; строка не по формату текста — пропущена с
     диагностикой, прочие ряды прохода считаются, P/01.1 Н0 «Устойчивость выдачи»), консоль молчит (сбор /metrics не
     удался, последний успешный сбор старше минуты по местным монотонным часам скрипта) или ряд
     <sub>_reconcile_last_success_age_seconds (P/06.5 Н3 «/metrics — текст») больше 60 или −1 → у этой роли ничего не
     запускать и не останавливать: молчание — не повод (Р1)
  3. цель роли — ровно номера {2…want}: недостающие в этом множестве запустить (наименьшие первыми), работающие с номером
     больше want остановить (наибольшие первыми); номер сравнивается как целое, не по порядку строк (Р4); базовый -1
     скрипт не трогает (ADR-0084 доп. (4) Р26: номера, не счёт)
  4. перед запуском — память: потолок = floor(HOST_MEMORY_MB / WORKER_MEMORY_MB) из roles/<роль>.env (разбор, не source;
     нет файла — роль пропуск); оба бюджета — положительные целые, CAPACITY — целое > 0; unit_mb и base_mb скрипт не
     читает — это вход старта воркера (memory ниже, P/03.4 Н1.2; добавлено ревью стадии A 2); значение не по форме или
     ноль делителя → роль пропустить с диагностикой; потолок — число процессов роли на сервере, каждый с WORKER_MEMORY_MB: работающие, базовый -1 и
     зарезервированные старты считаются (добавлено ревью стадии A 2); общий потолок памяти сервера по всем ролям не
     делится — предел схемы (Р12)
  5. проходы сериализованы; номер резервируется до start; неопределённый исход start или stop остаётся занятым до сверки
     systemd; второй проход при той же цели новых не запускает и лишних не останавливает
  6. ровно один механизм исполняет ряды на установке: таймер или рука; на стенде — директива @grow (общий README приёмки; разбор ревью стадии B 3–5, № 33)
stop:         остановка — systemctl stop: воркер отдаёт слот штатно (P/03.4 Н3 «остановка по SIGTERM»); у воркера с непустым
              назначением это переезд единиц, не потеря (ADR-0084 п. 7); контроллер уменьшает want после пустого
              назначения сокращаемого воркера (P/04 Н3 «сократить()») или снятием заказа по сроку WANT_GRACE (P/04 Н3
              «снять по сроку», ADR-0084 доп. (4) Р27): тогда номер выше want скрипт останавливает и с непустым назначением —
              единицы переезжают (разбор ревью стадии B 6–7, № 43)
memory:       воркер не стартует, если CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB (ADR-0070); GOMEMLIMIT = WORKER_MEMORY_MB
```

### Н1.6 Сертификаты: сторона выпуска

Форма сертификата и одна роль (`cert`), закрытый список подписей (`sig`), комплект (`kit`), `revoke`, `rotation` — общий
[договор сертификата роли](../../common/contracts/role-certificate.md) (ревью стадии B 1–2, п. 4); сторона проверяющего
TLS-пира у демона хранилища и роли демонов `configstore`, `configstore-door` — [P/01.3 Н1.6](../../01-store/spec/01.3-store.norms.md)
(деление М10/11-11). Строки ниже — центр, выпуск, комплекты прочих ролей и их двери.

```yaml
ca:           один центр на установку; w2c-ca.sh init | issue <server> <роль> | revoke <server|pem> | crl | own <dir> <роль> [группа]
  center:     init — самоподписанный; basicConstraints critical CA:true без pathLen; keyUsage critical keyCertSign, cRLSign;
              notAfter = notBefore + 3650 × 86400 с («центр 10 лет» договора cert — эти секунды, не календарь)
  leaf:       issue — basicConstraints CA:false; keyUsage critical digitalSignature (у ключа RSA ещё keyEncipherment);
              extendedKeyUsage serverAuth, clientAuth; notAfter = notBefore + 825 × 86400 с; профиль — правило выпуска:
              проверяющий его сверх договора peer шагов 2–5 и класса signer не требует (договор сертификата роли cert;
              догадка стадии C RC-03, решение «Архитектора» 2026-10-23)
  crl:        crl — по блоку X509 CRL v2 на каждый центр из ca.pem, ca.next.pem, подписан этим центром; без delta,
              indirect и ограничения issuingDistributionPoint; форма и чтение — договор сертификата роли revoke crl (RC-02)
sig:          список — договор сертификата роли `sig`; иная подпись — цепочка не проверяется (договор peer common/contracts/peer.md шаг 4 — bad_chain); у двери роли
              P/10 Н1.4 список проверяется после рукопожатия шагом peer — 403 bad_chain, в рукопожатии ограничивать не требуется
              (стеки этого не умеют одинаково); добавлено сверкой М11, D14, cammeta-python М11-08 № 21
client_cert:  слушатель процесса domain (SIGNER_URL, P/08.2 Н1.3) — все его маршруты — запрашивает сертификат клиента
              необязательно; предъявленный проверяет в рукопожатии по своим ca.pem, ca.next.pem: лист сходится к центру,
              срок действует, нет extendedKeyUsage без clientAuth — иначе alert, HTTP нет; не предъявлен — рукопожатие ok
              (договор сертификата роли «Серверная сторона: класс signed» signer); роль domainconsole из SAN при подписях
              в списке sig и серийнике не в revoked открывает чтение X-W2C-Client (P/08.4 Н1.10 address), иначе — адрес
              TCP-пира; клиенты из других кластеров — агенты и ретрансляторы — лист этому слушателю не предъявляют
              (P/09.1 Н1.7, P/09.2 Н1.6; договор сертификата роли clients) (добавлено сверкой М11, cammeta-python М11-09
              № 22; ADR-0083 доп. (20), доп. (21))
roles:        configstore, configstore-door — P/01.3 Н1.6 `roles`; resource, console, domain, domainconsole, domainagent (и дверь
              ретранслятора: это агент — P/09.2 Н1.1, Н1.6),
              <sub>controller (читает объекты и события дверью ресурса по HTTPS; журнал cammeta-go, урок 11 № 2),
              <sub>worker — комплект по W2C_ROLE/W2C_TLS_DIR; нет комплекта → дверь на петле, клиент только к http://;
              https:// без комплекта — отказ с причиной (ADR-0075 доп.3); узкое исключение — клиент агента в процессе
              кластера из одного, только к дверям держателя и ретранслятора, с проверкой сервера (P/09.1 Н1.11); второе
              узкое исключение — скрипт воркеров (Н1.5): без комплекта, только GET публичной /metrics консоли, с проверкой
              сервера клиентом своего кластера (договор сертификата роли own_client: peer с отпечатками ca.pem и
              ca.next.pem каталога W2C_TLS_DIR, роль console, host по порогу петли, затем отзыв); своего ключа и групп у него нет (журнал cammeta-go,
              урок 11 № 5)
```

```yaml
address:

  process:  дверь процесса без комплекта (договор сертификата роли kit_absent: «комплекта нет») — только петля (no_kit);

  console:  консоль с комплектом — TLS и на петле, HTTP при комплекте не открывается; привязка — CONSOLE_HOST как задан в
```

### Н1.7 Обновление и установка

```yaml
upgrade:                                       # сервер за сервером
  1. POST /drain?server=<s>; ждать GET /drain safe: true (P/06.6 Н2.3, Н1.2)
  2. подтвердить покой по P/06.6 Н3 «дренаж — чтение состояния», остановить сервер, обновить, запустить; DELETE /drain;
     достаточно здоровых назначений; возврата домой не ждать
  3. следующий сервер
  4. последним — окно подъёма схемы P/06.6 Н3 «поднять_схему» (включая молчащие старые сборки), затем PUT /schema?version=N; назад не идёт
  rule: новая сборка на старой раскладке работает; старая сборка на новой — не стартует (видимо)
install:                                       # install.sh; повтор установки = обновление
  os:      ОС выпуска: Linux/systemd — install apply обязателен; macOS — обязательны сборка, юнит-тесты и артефакты launchd
           (plist с ExitTimeOut и т. п., Н1.1), нативное применение на macOS МОЖЕТ быть, без него — отказ кодом 2 до
           записи; системный хост стенда не трогается (догадка стадии C I02-G03, решение «Архитектора» 2026-10-23)
  w2c_env: установка пишет в w2c.env CONSOLE_HOST и CONSOLE_PORT (умолчание 127.0.0.1, 8080) — один адрес консоли,
           который читают все процессы коробки (URL своей консоли — own_url договора сертификата роли); юнит консоли
           их не задаёт (ADR-0075 доп. 2026-10-26 (5) п. 2)
  warn:    RESOURCE_URL с IP-литералом вне петли (порог петли договора сертификата роли loopback: ip) — предупреждение
           на предварительной проверке, установка идёт: у https:// клиенты этой двери откажут ip_address, у http:// —
           ошибка настройки, видимая отказом соединения (ADR-0075 доп. 2026-10-26 (4) п. 6, (6) п. 2);
           SERVER_NAME каждого сервера platform/servers не разрешается или разрешается не в адрес привязки дверей процессов
           этого сервера (P/03.4 Н1.7 door_address) — предупреждение на предварительной проверке, установка идёт (ADR-0091 доп. (7), (8));
           сверка не подтвердилась — в том числе при первом запуске, когда пульса с адресом двери ещё нет, — предупреждение
           со словом unconfirmed до записи, установка продолжается (догадка стадии C I02-G04, решение «Архитектора» 2026-10-23);
           placement.near.sub манифеста установки называет подсистему, которой нет ни в установке, ни в хранилище, —
           строка вывода «near.sub <имя> нет в каталоге — сродство ждёт», установка идёт (P/02.1 Н3 отсрочка near;
           ADR-0091 доп. (27) п. 6);
           предпосылка развёртывания, не механизм платформы: имена серверов кластера разрешаются друг у друга (DNS или
           файл хостов оператора), рабочее место оператора разрешает их и доверяет центру кластера (ca.pem) — иначе
           страничные маршруты дверей процессов недоступны; ход к двери через консоль — не в этом решении
  refuse:  /etc/w2c или /etc/<sub> — настоящий каталог, не ссылка (цель /etc/<sub> — /data/platform/etc/subsystems/<sub>);
           W2C_DEPLOYMENT не по грамматике Н1.2; цикл worker.requests / вида domain.tokens среди манифестов установки (near цикла не даёт),
           ещё не стоящих в хранилище (order ниже) — код 2;
           файл прав не равен сгенерированному (глава 2.5); имена ОС каталога не проходят users_groups names
  steps:   код атомарно (Source.new → Source) → раннер и скрипты → пользователи и группы → /data и ссылки → манифесты → окружение
           и файлы ролей (никогда поверх существующих) → режимы каталогов → ключ секретов, если нет → юниты (+ скрипт воркеров, polkit)
           → tmpfiles.d каталогов долей → центр: own для configstore, файл прав, drop-in групп → manifest put в хранилище →
           enable: хранилище, ресурс, части подсистем, воркеры, контроллеры, консоль, домен (с юнитами воркеров на домене
           Н1.12 там, где w2c-domain), таймер скрипта воркеров (части
           — вместе с воркерами: юнит части никто не тянет Wants, без enable он не стартовал бы; ADR-0091 доп. (3) п. 1)
```

#### Н1.9 Команды `w2cctl secrets`

Перенесено из М10/7 Н2 (команды обслуживания, стадия B);
конверт, кольцо и AAD — [договор запечатывания](../../common/contracts/sealing.md) (векторы `Platform/common/vectors/sealing/`).

```
w2cctl secrets new [<путь>]        — создать кольцо (O_EXCL, 0640; путь внутри хранилища — отказ)
w2cctl secrets seal [<префикс>…]   — запечатать/перезапечатать открытые и старые по cas (исходы значения — договор запечатывания «Перезапечатать значение», C06-RESEAL-33-01); код 1, если что-то осталось
w2cctl secrets rotate [<путь>]     — новый ключ сверху
w2cctl secrets status [<префикс>…] — clear / current / older / ?; код 1, если есть открытое при наличии кольца или ? > 0
умолчание префиксов: domain/, identity/ и строки единиц и таблиц всех манифестов
```

`status` и `seal` обходят `*_secret` на любой глубине, в том числе внутри значения json-поля. Конверт считается
`current` или `older`, только если открывается ключом своего kid с AAD своего места (договор запечатывания). Известный kid, который не
открывает (конверт перенесён на чужое место, испорчен), — `?`, как чужой kid (сверка python и go М10/6–11, S7). `seal` на таком
конверте не обрывает обход: он доводит его до конца и отвечает кодом 1 — что-то осталось (сверка python и go М10/6–11, S6).
Пустое значение `*_secret` в счёт не входит; нестроковое значение (число, объект, массив, bool) — в счёт `?`; `status` при `?` > 0
— код 1, как `seal` с оставшимися `?`; обход продолжается, значений в выводе нет (догадка стадии C I02-G02, решение «Архитектора» 2026-10-23).
Известные формы `seal` — строки `domain/*` и строки единиц и таблиц манифестов каталога: их значения — по пункту
«Перезапечатать значение» договора запечатывания, один общий обход. Строка под префиксом без известной формы
(произвольная `identity/…`, семья без формы) — полей не угадывать: строку не трогать (байт в байт), строка журнала
«`<ключ>` unknown-row-form» без значения, обход продолжается, итог — код 1, что-то осталось (C02-RESEAL-UNKNOWN-FORM-93, решение «Архитектора» 2026-10-25).
Строка известной семьи, которая не читается (исход её семьи, `<семья>.outcomes.tsv`), у `seal` и `status` — так же: строку не
трогать (байт в байт), строка журнала «`<ключ>` unreadable» без значения, обход продолжается, итог — код 1; это одно
правило для всех семей, которые обходит команда (В7 п. 3, решение «Архитектора» 2026-10-28, П4).
Обход `status` и `seal` — по семьям [каталога](../../common/data/catalog.tsv), где писатель — `admin(w2cctl secrets seal …)`; строки
`domain/<sub>/<manifest:domain.kept>[/…]` (писатели `<s>domain` и `domain`) — вне обхода: не unknown-row-form, на код не
влияют, `status` их не считает (C02-SECRET-KEPT-FORM-93, решение «Архитектора» 2026-10-25).

Коды `seal`/`status` выше относятся к названным исходам; форма их текстового вывода остаётся
реализации. `new`/`rotate`: успех — 0, отказ — ненулевой код и причина без ключевого материала.
Отказ `new` при существующем файле его не меняет; отказ проверки кольца у `rotate` сохраняет
прежний файл. При недоступности обхода `seal`/`status` не заявляют успешное завершение и не
считают непрочитанные строки отсутствующими. Эта проверка не охватывает резервные копии:
вывод status не является разрешением удалять ключи — в профиле урока они сохраняются,
включая ключи конвертов, копий и отпечатков живых заявок. Вывод из обращения ключей требует
отдельной процедуры и в эту команду не входит (копии — P/08.8 Н1.5).

#### Н1.9 Команда `w2cctl tls status`

Решение «Архитектора» по ADR-0075 (п. 6 «Операции», Confirmation: ночной прогон, стенд «без петля/открыто» у дверей между
серверами):

```
w2cctl tls status        — вход нет; право admin (admin.sock), только чтение: ничего не пишет
  читает: пульсы ресурсов кластера (поле door двери процесса — {addr, mode, cert_until}, слова mode — loopback | mtls
          по ADR-0075; пишет ресурс, P/05 Н1.4; разбор ревью стадии B 3–5, № 28) и комплекты W2C_TLS_DIR своего сервера (Н1.6 kit)
  вывод: строка на дверь — сервер, роль, адрес, режим, cert_until; форма строки — реализации (как у secrets status),
         нормативны набор строк, поля и коды; роль с комплектом на своём сервере без живого процесса (нет пульса) —
         двери нет: строка по комплекту без адреса, с режимом и cert_until; истёкший сертификат такого комплекта — код 1
         (роль не поднимется) (решение «Архитектора» по догадке Go, 2026-10-20)
  код:   0 — нет двери loopback с адресом вне петли и нет истёкшего cert_until; 1 — есть такая дверь или истёкший
         cert_until двери или комплекта (разбор ревью стадии B 3–5, № 28); 2 — чтение не подтверждено (хранилище или пульс не ответили, комплект не читается)
```

## Н3 Проход

### старт сервера

```
1. configstore: member.json есть → рестарт (не join); нет → -bootstrap (первый) | -join (остальные); сокеты ролей по файлу прав;
   без -rights — только admin.sock; адрес вне петли без -tls → не стартовать
2. ресурс: пульс сразу, поток пульса; restore (P/05 Н1.4) в своей попытке; строка двери platform/doors/<s> с at (P/05 Н1.4)
3. контроллеры манифестов: манифест из строки хранилища (глава 2.3); первые 45 с никого не судят
4. консоль: манифесты из строк, оболочка root, перезапечатывание секретов (P/06.2 Н3), жнец просьб и отметки тел;
   удаление тел — только в отдельном окне обслуживания P/06.1 Н2
5. части подсистем (parts), затем воркеры: манифест, бюджет памяти, захват имени (P/03.2); на Linux порядок даёт After=
   юнита воркера (Н1.1), на macOS launchd порядка не гарантирует — воркер ждёт долю своей части сам, с паузой, до
   первого действия с ней (ADR-0091 доп. (3) пп. 1, 4)
6. скрипт воркеров по таймеру: ряды workers_wanted из /metrics → start/stop экземпляров n ≥ 2 в пределах потолка (Н1.5)
шаги 2–5: первым действием каждого процесса платформы и воркера (не части) — проверка схемы (P/06.6 Н3 «старт консоли — проверка схемы», общий блок), до чтения манифеста
```

**Гонки.** `After` задаёт порядок запуска, но не готовность хранилища, прав или манифеста. Каждый процесс ждёт достоверного чтения до своего первого действия; временная недоступность — ожидание с паузой, ошибочная конфигурация/схема — выход 2. Один экземпляр юнита не исключает другой юнит/ручной процесс; единственность писателя обеспечивают слоты и роли, не systemd.

### выпустить и отозвать сертификат

```
issue: w2c-ca.sh issue <server> <роль> → комплект; own <dir> <роль> → режимы; скопировать на сервер; процесс читает по W2C_ROLE
revoke: w2c-ca.sh revoke <server> → revoked/crl; скопировать на каждый сервер (процессы перечитывают); configstore leave <server>
        у лидера; сервер без комплекта — дверь на петле
```

**Гонки.** Изменения состава выполняет один оператор последовательно; force допускает только временную чётность в пределах объявленного максимума. Сертификат и leave распространяются разными действиями: до доставки отзыва всем узлам нельзя утверждать, что он везде действует. Запуск и остановка скрипта воркеров сериализованы по Н1.5; отсутствие пульса не освобождает зарезервированный номер.

### установка домена

Команда оператора, один раз на домен. Перенесено из М11/2 Н3
«установка домена» (поздний слой главы, вводит глава [8.2](../../08-domain/spec/08.2-domain.norms.md); разбор ревью стадии
A 8–10, № 17; перенос урока 8, стадия B). Корень, файл восстановления (`recovery_file`, `place`, `mode`), закрепление
`domain/root` (`pin`), набор `domain/keys`, ключи держателя `domain/signer` и ключ приёма книг `domain/book-seal` — формы
[P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н1.1–Н1.4.

Порядок шагов 1–8, шаг 8 до главы 8.8, повтор прерванной установки и окно оператора (параллельная команда — код 2 `busy`) — [договор основания домена](../../common/contracts/domain-founding.md)
«Установка домена» (решение «Архитектора» 2026-10-23 по находке «Спецификации» I02-FOUND).

## Н5 Приёмка

Каталога приёмки у главы нет: ни один сценарий модуля и М11/12 не исполняет юниты, окружение, перезапуск, установку и

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как объявляются пользователи, группы и каталоги** (`sysusers`/`tmpfiles`, `useradd` в установщике, launchd на macOS) и их числовые id; каталоги долей в `/run` — нормой tmpfiles.d установщика (Н1.1 `dirs`), на macOS — способ реализации при той же раскладке;
2. ~~**как демон получает группы ролей или обходится setgid**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита `configstore-<роль>.socket` (Н1.1, P/01.3 Н1.3 `sockets`; пилот хранилища, А4);
3. **форму доставки** сверх systemd/launchd (Quadlet, Nomad) и чем она отличается (группы, порты);
4. ~~**порты домена** и его юниты~~ — нормированы: Н1.12 (строки юнитов Н1.1 выше);
5. **как ведёт себя `status`/`seal`** без манифестов в хранилище;
6. **форму вывода `secrets status` и `seal`**: она ДОЛЖНА называть счёты clear, current, older и `?` по названным
   префиксам; остальное — выбор реализации;
7. **комплект сертификатов роли**: где лежит, кто выпускает (договор сертификата роли `kit` `/etc/w2c/tls/<роль>/`, выпуск — Н1.6 `w2c-ca.sh issue <server> <роль>`);
8. **команду установки домена** (Н3 «установка домена»: имя, аргументы, где файл восстановления, как команда узнаёт каталоги
   хранилища, объектов и их копий, внутри которых файл запрещён); стенд главы 8.3 называет её строкой словаря
   (`@install domain`); вызов плановых смен и смены после кражи — [P/08.2](../../08-domain/spec/08.2-domain.norms.md)
   «Решает реализация» п. 2 (из М11/2 «Решает реализация» п. 2; перенос урока 8, стадия B).

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/02.4-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6). Номера P/02.4-10 и P/02.4-13 — поздний слой главы (М11/2-10, М11/12-08; вводят
главы 8.2 и 8.10; перенос урока 8, стадия B).

- [ ] **P/02.4-01** правило адреса Н1.6: демон вне петли только с TLS; дверь процесса без комплекта — петля; signer и relay вне петли без комплекта — только по явному адресу, с громкой строкой лога; resource без комплекта — только петля (ADR-0075 доп. 2026-10-26 (6) п. 2); на умолчании процесса `0.0.0.0` — отказ старта, код 2 (ADR-0075 доп. 2026-10-26 (5) п. 4); консоль вне петли без комплекта — отказ старта; консоль с комплектом — TLS и на петле (Н1.6 `console`); клиент своей коробки — договор сертификата роли `own_client`, порог петли — векторы `loopback`; шаги ADR-0075 доп. 2026-10-26 (4) п. 7 — TLS-стенд «Клиент своей коробки и умолчания адресов» ([`tls/`](../../common/acceptance/tls/README.md)); условных ослаблений нет — проверяется чтением ([системный стенд](../../common/acceptance/system/README.md); Н1.6 `roles`: нет комплекта — дверь на петле); прочего сценария в приёмке нет
