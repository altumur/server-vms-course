# P/02.4 — Установщик: нормы

Канон главы. [Лекция](../02-installer.md), [инструкция](02-installer.README.md), [жизненный цикл](../lifecycle.md),
[векторы скрипта воркеров](../vectors/workers-script/README.md). Своего HTTP-контракта у урока нет: дверей у установщика
нет. Каталога приёмки у главы нет (Н5). Глава перенесена из [М10/11](../../../М10_Platform/spec/11-the-platform-on-a-box-and-a-cluster.norms.md)
(стадия B, ADR-0083 доп. (1): без изменения поведения): Н1.1, Н1.2, Н1.5, Н1.7, Н1.9, сторона выпуска Н1.6, проходы
«старт сервера» и «выпустить и отозвать сертификат», строки Н2, Н4 и Н5 установщика, раннера и скрипта воркеров; из
[М11/12](../../../М11_Domain/spec/12-small-members-and-one-node.norms.md) — Н1.1 и `hot`, `durable` Н1.2 (здесь Н1.10,
Н1.11); из [М10/7](../../../М10_Platform/spec/07-secrets-and-sealing.norms.md) — команды `w2cctl secrets` (Н2 там, здесь
Н1.9 «Команды `w2cctl secrets`»); из [М10/6](../../../М10_Platform/spec/06-rights.norms.md) — правило адреса и сертификат
роли (Н1.6 «Правило адреса»). Номера подразделов Н1.1–Н1.9 — прежние номера М10/11. Отказ сервера (Н1.4), `door.pass`
(Н1.8) и проход «вырвать питание» остаются в М10/11; юниты и порты домена (М11/12 Н1.8) и установка домена (М11/2 Н3) —
поздний слой главы, вводят уроки 8.10 и 8.2, остаются в М11. Ссылка «урок N» без главы — урок М10 (`М10_Platform/`), ещё не
перенесённый; «глава 2.K» — глава этого урока; «P/01.K» — глава урока 1. Id норм — `P/02.4-MM`; соответствие прежним id —
[`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у строк и файлов главы нет.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `/etc/w2c/roles/<роль>.env`, `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/ca.next.pem`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem`, `/etc/w2c/tls/<роль>/server.pem`, `/etc/w2c/tls/<роль>/server.key`;
- пишет: `platform/mirror` (put), `platform/space` (put), `<sub>/retention` (put), `<sub>/alarms_retention` (put), `/etc/w2c/secrets/platform.key` (create), `<sub>/<spec:unit.rows>/<id>` (cas), `<sub>/<spec:tables>/<имя>` (cas), `door/signer` (cas);
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `/etc/w2c/configstore-rights.json`.

### Н1.1 Процессы и юниты

```yaml

  common:    долгоживущие службы (все, кроме w2c-workers.service, Type=oneshot): Restart=always; RestartPreventExitStatus=2 (отказ старта по спеке, правам, схеме — глава 2.3: без перезапуска, до
             действия оператора); RestartSec=2; After=configstore.service (не Wants: хранилище не тянут); запуск через раннер
             (w2c-run.sh) с umask 0007; ProtectSystem=strict, PrivateTmp, NoNewPrivileges
  configstore.service:    User=configstore; UMask=0077; -dir /data/platform/configstore (0700); -sockets /run/configstore;
                          -rights /etc/w2c/configstore-rights.json; -tls /etc/w2c/tls; -group-size; TimeoutStopSec 20–30;
                          сокеты — от юнитов configstore-*.socket (P/01.3 Н1.3 sockets)

                          ListenStream=/run/configstore/admin.sock | /run/configstore/<роль>.sock; FileDescriptorName=admin |
                          <роль>; SocketUser=root; у admin SocketMode=0600, SocketGroup=root; у роли SocketMode=0660,
                          SocketGroup=<группа роли> (users_groups ниже); Service=configstore.service (пилот хранилища, А4, А10)
  w2c-resource.service:   User=w2c; SupplementaryGroups=w2c-store w2c-events; RESOURCE_HOST/PORT 127.0.0.1:8090
  w2c-controller@.service: User=w2c; роль <sub>controller, группа w2c-<sub>controller; W2C_ROLE; Type=notify; NotifyAccess=main;
                          WatchdogSec=360 (СЛЕДУЕТ)

                          команда воркера получает
                          его аргументом — один канал со стендом (подстановка {name} README приёмки М10/01); переменную

                          OnUnitActiveSec 1 мин

  rule: процесс платформы — никогда от пользователя подсистемы и не в её группах (ADR-0030); демон хранилища — не в группах
        подсистем: группу сокета роли задаёт SocketGroup= его юнита, демон получает сокет готовым (P/01.3 Н1.3 sockets;
        пилот хранилища, А4)
dirs:                                         # /data/platform; /etc/w2c → /data/platform/etc (ссылка)

  /data/platform/etc/tls       0751 root:root         (проход всем ролям; ca.pem, revoked — 0644)
  /data/platform/etc/tls/<роль> 0750 root:<группа роли> (комплект роли; server.pem 0644, server.key 0640 — читает только своя группа)
  /data/platform/configstore   0700 configstore
  /data/platform/config        2770 w2c:w2c-store      (коробка)
  /data/platform/objects       2770 w2c:w2c-store
  /data/platform/events        2770 w2c:w2c-events
  /run/configstore             0755 root               (плоско, без подкаталогов: сокеты юнитов configstore-*.socket —
```

### Н1.2 Контракт окружения

Порядок чтения раннера: значения юнита → файл роли `roles/<W2C_ROLE>.env` → `w2c.env` → файл подсистемы; раньше прочитанное побеждает. Каталог `roles/` лежит рядом с `w2c.env` (каталог файла `W2C_ENV`, по умолчанию `/etc/w2c/roles/`); другого места нет. `W2C_ROLE` юнита, который не совпадает с ролью команды раннера (`w2c-run.sh <команда>`, Н1.9), — отказ запуска с кодом 2 (сверка python и go М10/6–11, B20).

Файлы окружения (`w2c.env`, `roles/*.env`, файл подсистемы, `configstore.env`) читаются разбором, не
`source`: строка `KEY=VALUE`, `KEY` — `[A-Za-z_][A-Za-z0-9_]*`; необязательный префикс `export `; значение в парных `"…"`
или `'…'` — без кавычек, подстановок нет; пустая строка и строка, чей первый непробельный знак `#`, пропускаются. Иная
строка — отказ запуска с кодом 2 и строкой лога, которая называет файл и номер строки.

На краях (сверка python и go М10/6–11, B19): строки разделяет LF; знак CR в строке, BOM в начале файла, пробел или табуляция до или после
`=` и в имени — строка не по грамматике; `export` — ровно одно слово и один пробел перед `KEY`, `export` без `KEY=` — не по
грамматике; значение без кавычек — всё после `=` до конца строки как есть, без обрезки пробелов, `#` внутри значения —
часть значения, не комментарий; пустое значение (`KEY=`) — пустая строка; непарная кавычка — не по грамматике.

**Канал настройки и раскладка `PLATFORM_DIR`** (решение «Архитектора», второй пилот, Н-4):
- процессы платформы — консоль, контроллер, воркер, ресурс, процессы домена — настраиваются только переменными таблицы
  выше и аргументом имени воркера (экземпляр `%i` юнита); собственных флагов путей и адресов у них нет; флаги есть только у
  демона хранилища ([P/01.3](../../01-store/spec/01.3-store.norms.md) Н1.3 «Флаги демона»);
- хранилище — `<PLATFORM_DIR>/configstore` (`-dir` юнита Н1.1);
- объекты — корень `OBJECTS` / `PLATFORM_OBJECTS`, по умолчанию `<PLATFORM_DIR>/objects`;
- события — корень `RESOURCE_ROOT` / `EVENTS`, по умолчанию `<PLATFORM_DIR>/events`; замки присутствия — в корне
  событий (урок 8 Н1.4 `presence_lock`);
- кольцо — `SECRETS_KEY`, по раскладке Н1.1 — `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c/secrets` — ссылка), вне каталога хранилища, корня объектов и корня событий: оно не уходит ни с копией хранилища, ни с
  объектами, ни с зеркалом событий ([договор запечатывания](../../common/contracts/sealing.md) «Файл кольца»).

### Н1.5 Воркеры по заказу

```yaml
order:        число процессов роли на сервере задаёт контроллер — строка <sub>/want/<сервер> (М10/4 Н1.1; ADR-0084):
              want — абсолютная цель 1…99, базовый <prefix>-<SERVER_NAME>-1 в неё входит; консоль отдаёт ряд
              <sub>_workers_wanted{server} для каждой строки заказа (М10/9 Н3 «/metrics — текст»)
extra_unit:   дополнительный воркер — экземпляр того же юнита роли <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>, n 2…99
              (Н1.1): те же учётные данные, ключи, пользователь и группы; захват слота обычный (М10/3 Н3); особого юнита,
              файла и переменной нет
script:       w2c-workers.sh, раз в минуту таймером, User=w2c-workers без групп; один на сервер — все роли сервера;
              polkit: только start и stop, только пользователем w2c-workers, только полные имена
              <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>.service ролей этого сервера, n — [2-9]|[1-9][0-9] без ведущих
              нулей; базовый -1, чужой сервер, иные юниты и глаголы — отказ (ADR-0084 доп. (1) Р11)
rules:
  1. читает свои ряды <sub>_workers_wanted{server=<SERVER_NAME>} всех ролей сервера из /metrics консоли, ряды других
     серверов не читает, команд не исполняет; по HTTPS — клиентом без комплекта с проверкой сервера (Н1.6 roles)
  2. ряда роли нет, он не читается (значение не по форме метрики М10/9 — целое без ведущих нулей, знака и дроби: `02`,
     `2.0`, `+2` — ряда нет, стадия A, A6 — или вне 1…99; строка не по формату текста — пропущена с
     диагностикой, прочие ряды прохода считаются, P/01.1 Н0 «Устойчивость выдачи»), консоль молчит (сбор /metrics не
     удался, последний успешный сбор старше минуты по местным монотонным часам скрипта) или ряд
     <sub>_reconcile_last_success_age_seconds (урок 9 Н3 «/metrics — текст») больше 60 или −1 → у этой роли ничего не
     запускать и не останавливать: молчание — не повод (Р1)
  3. цель роли: работающих экземпляров с n ≥ 2 — want − 1; меньше — запустить наименьшие свободные номера, больше —
     остановить наибольшие; номер сравнивается как целое, не по порядку строк (Р4); базовый -1 скрипт не трогает
  4. перед запуском — память: потолок = floor(HOST_MEMORY_MB / WORKER_MEMORY_MB) из roles/<роль>.env (разбор, не source;
     нет файла — роль пропуск); оба бюджета — положительные целые, CAPACITY — целое > 0; unit_mb и base_mb скрипт не
     читает — это вход старта воркера (memory ниже, М10/5 Н1.2; добавлено ревью стадии A 2); значение не по форме или
     ноль делителя → роль пропустить с диагностикой; потолок — число процессов роли на сервере, каждый с WORKER_MEMORY_MB: работающие, базовый -1 и
     зарезервированные старты считаются (добавлено ревью стадии A 2); общий потолок памяти сервера по всем ролям не
     делится — предел схемы (Р12)
  5. проходы сериализованы; номер резервируется до start; неопределённый исход start или stop остаётся занятым до сверки
     systemd; второй проход при той же цели новых не запускает и лишних не останавливает
  6. ровно один механизм исполняет ряды на установке: таймер или рука; на стенде — директива @grow (README приёмки М10/01)
stop:         остановка — systemctl stop: воркер отдаёт слот штатно (М10/5 Н3 «остановка»); у воркера с непустым
              назначением это переезд единиц, не потеря (ADR-0084 п. 7); контроллер уменьшает want только после пустого
              назначения сокращаемого воркера (М10/4 Н3 «сократить()»)
memory:       воркер не стартует, если CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB (ADR-0070); GOMEMLIMIT = WORKER_MEMORY_MB
```

### Н1.6 Сертификаты: сторона выпуска

```yaml

client_cert:  дверь процесса domain (SIGNER_URL, М11/2 Н1.3) запрашивает сертификат клиента необязательно и доверяет только
```

### Н1.7 Обновление и установка

```yaml
upgrade:                                       # сервер за сервером
  1. POST /drain?server=<s>; ждать GET /drain safe: true (урок 10)
  2. подтвердить покой по М10/10 Н3, остановить сервер, обновить, запустить; DELETE /drain;
     достаточно здоровых назначений; возврата домой не ждать
  3. следующий сервер
  4. последним — окно подъёма схемы М10/10 (включая молчащие старые сборки), затем PUT /schema?version=N; назад не идёт
  rule: новая сборка на старой раскладке работает; старая сборка на новой — не стартует (видимо)
install:                                       # install.sh; повтор установки = обновление
  refuse:  /etc/w2c или /etc/<sub> — настоящий каталог, не ссылка; файл прав не равен сгенерированному (глава 2.5)
  steps:   код атомарно (Source.new → Source) → раннер и скрипты → пользователи и группы → /data и ссылки → спеки → окружение
           и файлы ролей (никогда поверх существующих) → режимы каталогов → ключ секретов, если нет → юниты (+ скрипт воркеров, polkit)
           → центр: own для configstore, файл прав, drop-in групп → spec put в хранилище → enable: хранилище, ресурс, воркеры,
           контроллеры, консоль, домен, таймер скрипта воркеров
  failure: до изменения файлов проверить все доступные входы, пути, права, спеки и генерацию. Ошибка — ненулевой
           выход с фазой/путём; не enable/start новые службы. После начала записи возможен частичный результат:
           не обещать общий rollback; сохранить уже установленные файлы и журнал фаз, повторить после исправления.
           spec put имеет собственный порядок и отказы глав 2.1, 2.3; существующие чужие файлы не перезаписываются
  not:     сертификаты серверов, CONFIGSTORE_JOIN — рука оператора
```

#### Н1.9 Команды `w2cctl secrets`

Перенесено из [М10/7 Н2](../../../М10_Platform/spec/07-secrets-and-sealing.norms.md) (команды обслуживания, стадия B);
конверт, кольцо и AAD — [договор запечатывания](../../common/contracts/sealing.md) (векторы `Platform/common/vectors/sealing/`).

```
w2cctl secrets new [<путь>]        — создать кольцо (O_EXCL, 0640; путь внутри хранилища — отказ)
w2cctl secrets seal [<префикс>…]   — запечатать/перезапечатать открытые и старые по cas; код 1, если что-то осталось
w2cctl secrets rotate [<путь>]     — новый ключ сверху
w2cctl secrets status [<префикс>…] — clear / current / older / ?; код 1, если есть открытое при наличии кольца
умолчание префиксов: domain/, identity/ и строки единиц и таблиц всех спек
```

`status` и `seal` обходят `*_secret` на любой глубине, в том числе внутри значения json-поля. Конверт считается
`current` или `older`, только если открывается ключом своего kid с AAD своего места (договор запечатывания). Известный kid, который не
открывает (конверт перенесён на чужое место, испорчен), — `?`, как чужой kid (сверка python и go М10/6–11, S7). `seal` на таком
конверте не обрывает обход: он доводит его до конца и отвечает кодом 1 — что-то осталось (сверка python и go М10/6–11, S6).

Коды `seal`/`status` выше относятся к названным исходам; форма их текстового вывода остаётся
реализации. `new`/`rotate`: успех — 0, отказ — ненулевой код и причина без ключевого материала.
Отказ `new` при существующем файле его не меняет; отказ проверки кольца у `rotate` сохраняет
прежний файл. При недоступности обхода `seal`/`status` не заявляют успешное завершение и не
считают непрочитанные строки отсутствующими. Эта проверка не охватывает резервные копии:
вывод status не является разрешением удалять ключи — в профиле урока они сохраняются,
включая ключи конвертов, копий и отпечатков живых заявок. Вывод из обращения ключей требует
отдельной процедуры и в эту команду не входит (копии — М11).

## Н3 Проход

### старт сервера

```
1. configstore: member.json есть → рестарт (не join); нет → -bootstrap (первый) | -join (остальные); сокеты ролей по файлу прав;
   без -rights — только admin.sock; адрес вне петли без -tls → не стартовать
2. ресурс: пульс сразу, поток пульса; restore (М10/11 Н1.4) в своей попытке; строка двери platform/doors/<s> с at (урок 4)
3. контроллеры спек: спека из строки хранилища (глава 2.3); первые 45 с никого не судят
4. консоль: спеки из строк, оболочка root, перезапечатывание секретов (урок 7), жнец просьб и отметки тел;
   удаление тел — только в отдельном окне обслуживания М10/10
5. воркеры: спека, бюджет памяти, захват имени (урок 3)
6. скрипт воркеров по таймеру: ряды workers_wanted из /metrics → start/stop экземпляров n ≥ 2 в пределах потолка (Н1.5)
шаги 2–5: первым действием каждого процесса — проверка схемы (урок 10 Н3 «старт … — проверка схемы»), до чтения спеки
```

**Гонки.** `After` задаёт порядок запуска, но не готовность хранилища, прав или спеки. Каждый процесс ждёт достоверного чтения до своего первого действия; временная недоступность — ожидание с паузой, ошибочная конфигурация/схема — выход 2. Один экземпляр юнита не исключает другой юнит/ручной процесс; единственность писателя обеспечивают слоты и роли, не systemd.

### выпустить и отозвать сертификат

```
issue: w2c-ca.sh issue <server> <роль> → комплект; own <dir> <роль> → режимы; скопировать на сервер; процесс читает по W2C_ROLE
revoke: w2c-ca.sh revoke <server> → revoked/crl; скопировать на каждый сервер (процессы перечитывают); configstore leave <server>
        у лидера; сервер без комплекта — дверь на петле
```

**Гонки.** Изменения состава выполняет один оператор последовательно; force допускает только временную чётность в пределах объявленного максимума. Сертификат и leave распространяются разными действиями: до доставки отзыва всем узлам нельзя утверждать, что он везде действует. Запуск и остановка скрипта воркеров сериализованы по Н1.5; отсутствие пульса не освобождает зарезервированный номер.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как объявляются пользователи, группы и каталоги** (`sysusers`/`tmpfiles`, `useradd` в установщике, launchd на macOS) и их числовые id;
2. ~~**как демон получает группы ролей или обходится setgid**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита `configstore-<роль>.socket` (Н1.1, P/01.3 Н1.3 `sockets`; пилот хранилища, А4);
3. **форму доставки** сверх systemd/launchd (Quadlet, Nomad) и чем она отличается (группы, порты);
4. ~~**порты домена** и его юниты~~ — нормированы: М11/12 Н1.8 (строки юнитов Н1.1 выше);
5. **как ведёт себя `status`/`seal`** без спек в хранилище;
6. **форму вывода `secrets status` и `seal`**: она ДОЛЖНА называть счёты clear, current, older и `?` по названным
   префиксам; остальное — выбор реализации;
7. **комплект сертификатов роли**: где лежит, кто выпускает (договор сертификата роли `kit` `/etc/w2c/tls/<роль>/`, выпуск — Н1.6 `w2c-ca.sh issue <server> <роль>`).

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/02.4-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6). Номера P/02.4-10 и P/02.4-13 — поздний слой главы (М11/2-10, М11/12-08; вводят
уроки 8.2 и 8.10), остаются в М11.

- [ ] **P/02.4-01** правило адреса Н1.6: демон вне петли только с TLS; дверь процесса без комплекта — петля; signer, relay, resource вне петли — МОЖЕТ, с громкой строкой лога, или отказ старта; консоль вне петли без комплекта — отказ старта; условных ослаблений нет — проверяется чтением (стенд урока 11; Н1.6 `roles`: нет комплекта — дверь на петле); сценария в приёмке нет
- [ ] **P/02.4-02** сертификат роли Н1.6 `doors` (SAN URI `urn:w2c:role:<роль>`, CN `<роль>.<сервер>`) и равенство роли процессу Н1.6 `cert` (ADR-0075) — проверяется чтением
- [ ] **P/02.4-03** набор юнитов Н1.1 на каждом сервере, пользователи и группы, процесс платформы не в группах подсистемы (ADR-0030), каталоги и режимы — проверяется чтением: структурный тест юнитов реализации против Н1.1 (предмет — каждая строка таблицы); причина — на стенде юниты не исполняются
- [ ] **P/02.4-04** имя и сокет — из юнита; настройки сервера — из файла; имя сервера в `%i` — `SERVER_NAME`, иначе код 2; порядок чтения Н1.2 — проверяется чтением: тест раннера реализации (предмет — Н1.2 построчно); причина — файлы и приоритет окружения раннера не исполняются HTTP-TSV
- [ ] **P/02.4-05** `Restart=always` у долгоживущих (у `w2c-workers.service` — `Restart=no`, повтор таймером), `RestartSec=2`, `TimeoutStopSec ≥ 20`, `WatchdogSec=360` у воркеров, `After` без `Wants`, `RestartPreventExitStatus=2` у всех юнитов платформы и подсистем — проверяется чтением: тест юнитов реализации; причина — реальные unit-файлы systemd не запускаются в этой приёмке
- [ ] **P/02.4-06** воркеры по заказу Н1.5: экземпляр юнита роли с номером n 2…99, скрипт без групп, шесть правил (ряда нет — ничего; старт наименьшего, стоп наибольшего номера), потолок по памяти, polkit start/stop полных имён своего сервера (ADR-0084) — проверяется чтением: тест скрипта воркеров реализации (предмет — шесть правил Н1.5 и правило polkit) и стенд урока 5 (`@grow`)
- [ ] **P/02.4-07** сертификаты Н1.6: форма, одна роль, комплекты по `W2C_ROLE` (и `<sub>controller`), клиент скрипта воркеров без комплекта, отзыв по содержимому — проверяется чтением: тесты центра сертификатов реализации на тестовой CA (предмет — Н1.6: без сертификата, чужая CA, отозванный, чужая роль, своя); причина — CA и файловые права не меняются HTTP-TSV; сторона проверяющего TLS-пира у демона хранилища — [P/01.3-09](../../01-store/spec/01.3-store.norms.md) (стадия B)
- [ ] **P/02.4-08** порядок обновления Н1.7 и установка с отказом на устаревшем файле прав — чтением; сц. 03 [приёмки М10/11](../../../Source/tests/testdata/acceptance/М10_Platform/11/README.md)
- [ ] **P/02.4-09** команды оператора Н1.9 — закрытый набор — чтением; причина — операторские команды и их внешние инструменты не исполняются TSV
- [ ] **P/02.4-11** кластер из одного Н1.10 — чтением (стенд М11/3 — коробки по кластеру, отдельной формы нет)
- [ ] **P/02.4-12** горячее в памяти хранилища коробки Н1.11 — чтением (стенд не считает записей носителя); запись дома только при отличии — М11/12-02 (сц. 01 приёмки М11/12)
- [ ] **P/02.4-14** `w2cctl secrets new|seal|rotate|status` — векторы `Platform/common/vectors/sealing/` (конверт, AAD, файл кольца) и чтением договора запечатывания и описания команд реализации («Решает реализация» п. 6): операторские команды TSV не исполняет; обход на любой глубине и `?` у неоткрывающегося конверта (Н1.9 «Команды `w2cctl secrets`») — чтением по той же причине
- [ ] **P/02.4-15** жизненный цикл (сверка python и go М10/6–11; часть 2.4 М10/11-18 по `note` id-map, жизненный цикл хранилища — [P/01.3-08](../../01-store/spec/01.3-store.norms.md)): грамматика окружения на краях, место `roles/`, `W2C_ROLE` ≠ команде — чтением: тест раннера (Н1.2 построчно); цель по ряду `workers_wanted` (старт наименьшего, стоп наибольшего номера, ряда нет — ничего), разбор `/metrics` скриптом — чтением: тест скрипта воркеров (Н1.5); на стенде скрипт не исполняется, его ряд исполняет `@grow`

«старт сервера» и «выпустить и отозвать сертификат», строки Н4 и Н5 установщика, раннера и скрипта воркеров, пп. 1, 2, 6, 7

(раннер и скрипт воркеров; здесь P/02.4-15). Из М11/12: Н1.1 и `hot`, `durable` Н1.2 (М11/12-01, часть -02). Из М10/7:
команды `w2cctl secrets` — Н2 «команды обслуживания», их строки Н4, пп. 2, 7 «Решает реализация» (здесь — пп. 5, 6),
P/02.4-14. Из [М10/6](../../../М10_Platform/spec/06-rights.norms.md): Н1.1 `identity.doors`, Н1.6, строки Н4 об адресе и
сертификате, строка «Проверяются чтением» Н5 о них, «Решает реализация» п. 7 (здесь — п. 7); id: М10/6-11 → P/02.4-01,
М10/6-12 → P/02.4-02. М10/11 нормировал то, что рассказывали `М10A_Platform/21-Platform-on-the-Box.md` (вход, хранилища, юниты
