### Н1.2 The environment contract

The environment files, the order in which the runner and the part unit read them, `W2C_ROLE` of the unit and the command — the [environment
file contract](../../common/contracts/env-file.md) «Files and reading order» (moved there without change; the layout audit, the Architect's decision 2026-10-25, `B-26`).

The environment files (`w2c.env`, `roles/*.env`, the subsystem file, `configstore.env`) are read by parsing, not by `source`, by
the [environment file contract](../../common/contracts/env-file.md) (the grammar `KEY=VALUE` and the edges B19 are moved there without
a change of behaviour; guess of stage C C04-ENV-01, the Architect's decision 2026-10-23); a line not by the grammar — a start refusal with code 2 and a log line that
names the file and the line number; no file — skipped, the file is not readable — a start refusal, code 2 (the contract, «No file»; W03-G07).

The environment variables of the processes — form, meaning, default, who sets them — the [environment file contract](../../common/contracts/env-file.md)
«Environment variables» (the table is moved there without change; the layout audit, the Architect's decision 2026-10-25, `A-07`, `A-09`).

**The setting channel and the layout of `PLATFORM_DIR`** (the Architect's decision, the second pilot, `N-4`):
- the platform processes — the console, the controller, the worker, the resource, the domain processes — are configured only by the variables
  of the [environment file contract](../../common/contracts/env-file.md) «Environment variables» and by the worker name argument (the instance `%i` of the unit); they have no own flags of paths and addresses; flags exist only at
  the store daemon ([P/01.3](../../01-store/spec/01.3-store.norms.md) Н1.3 «Daemon flags»);
- the store — `<PLATFORM_DIR>/configstore` (`-dir` of the unit of Н1.1);
- the objects — the root `OBJECTS` / `PLATFORM_OBJECTS`, by default `<PLATFORM_DIR>/objects`;
- the events — the root `RESOURCE_ROOT` / `EVENTS`, by default `<PLATFORM_DIR>/events`; the presence locks — in the event
  root ([presence lock contract](../../common/contracts/presence-lock.md) `presence_lock`);
- the ring — `SECRETS_KEY`, by the layout of Н1.1 — `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c/secrets` is a link), outside the store directory, the object root and the event root: it leaves neither with a store copy, nor with
  the objects, nor with the event mirror ([sealing contract](../../common/contracts/sealing.md) «Ring file»).

#### Н1.9 The commands `w2cctl secrets`

Moved from М10/7 Н2 (maintenance commands, stage B);
the envelope, the ring and AAD — the [sealing contract](../../common/contracts/sealing.md) (vectors `Platform/common/vectors/sealing/`).

```
w2cctl secrets new [<path>]        — create the ring (O_EXCL, 0640; a path inside the store — a refusal)
w2cctl secrets seal [<prefix>…]    — seal/reseal the open and old ones by cas (the outcomes of a value — the sealing contract «Reseal a value», C06-RESEAL-33-01); code 1 if something is left
w2cctl secrets rotate [<path>]     — a new key on top
w2cctl secrets status [<prefix>…]  — clear / current / older / ?; code 1 if there is an open one while a ring exists, or ? > 0
the default of the prefixes: domain/, identity/ and the rows of units and tables of all manifests
```

`status` and `seal` walk `*_secret` at any depth, including inside the value of a json field. An envelope counts as
`current` or `older` only if it opens with the key of its kid with the AAD of its place (the sealing contract). A known kid that does not
open (the envelope is moved to a foreign place, spoiled) is `?`, like a foreign kid (reconciliation of python and go М10/6–11, S7). `seal` on such an
envelope does not break off the walk: it brings it to the end and answers with code 1 — something is left (reconciliation of python and go М10/6–11, S6).
An empty value of `*_secret` is not counted; a non-string value (a number, an object, an array, a bool) is counted as `?`; `status` with `?` > 0
— code 1, like `seal` with remaining `?`; the walk continues, there are no values in the output (guess of stage C I02-G02, the Architect's decision 2026-10-23).
The known forms of `seal` are the rows `domain/*` and the rows of units and tables of the manifests of the catalogue: their values are by the item
«Reseal a value» of the sealing contract, one common walk. A row under a prefix without a known form
(an arbitrary `identity/…`, a family without a form) — do not guess the fields: do not touch the row (byte for byte), a log line
«`<ключ>` unknown-row-form» without the value, the walk continues, the result is code 1, something is left (C02-RESEAL-UNKNOWN-FORM-93, the Architect's decision 2026-10-25).
A row of a known family that is not readable (the outcome of its family, `<семья>.outcomes.tsv`), at `seal` and `status` — the same: do not
touch the row (byte for byte), a log line «`<ключ>` unreadable» without the value, the walk continues, the result is code 1; this is one
rule for all families that the command walks (V7 item 3, the Architect's decision 2026-10-28, P4).
The walk of `status` and `seal` is by the families of the [catalogue](../../common/data/catalog.tsv) where the writer is `admin(w2cctl secrets seal …)`; the rows
`domain/<sub>/<manifest:domain.kept>[/…]` (the writers `<s>domain` and `domain`) are outside the walk: not unknown-row-form, they do not
affect the code, `status` does not count them (C02-SECRET-KEPT-FORM-93, the Architect's decision 2026-10-25).

The codes of `seal`/`status` above refer to the named outcomes; the form of their text output is left
to the implementation. `new`/`rotate`: success — 0, a refusal — a non-zero code and a reason without key material.
A refusal of `new` with an existing file does not change it; a refusal of the ring check at `rotate` keeps
the former file. When the walk is unavailable, `seal`/`status` do not declare a successful completion and do not
count unread rows as absent. This check does not cover backups:
the output of status is not a permission to delete keys — in the profile of the lesson they are kept,
including the keys of envelopes, copies and fingerprints of live claims. Taking keys out of circulation requires
a separate procedure and is not part of this command (copies — P/08.8 Н1.5).

## Н3 Procedures

### server start

```
1. configstore: member.json exists → a restart (not join); none → -bootstrap (the first) | -join (the others); role sockets by the rights file;
   without -rights — only admin.sock; an address off the loopback without -tls → do not start
2. the resource: a heartbeat at once, the heartbeat stream; restore (P/05 Н1.4) in its own attempt; the door row platform/doors/<s> with at (P/05 Н1.4)
3. the controllers of the manifests: the manifest from the store row (chapter 2.3); the first 45 s they judge nobody
4. the console: the manifests from the rows, the shell root, resealing of the secrets (P/06.2 Н3), the reaper of requests and the marks of bodies;
   deleting bodies — only in a separate maintenance window of P/06.1 Н2
5. the parts of subsystems (parts), then the workers: the manifest, the memory budget, capturing the name (P/03.2); on Linux the order is given by After=
   of the worker unit (Н1.1), on macOS launchd does not guarantee an order — the worker waits for the share of its part itself, with a pause, until
   the first action with it (ADR-0091 addendum (3) items 1, 4)
6. the workers script by the timer: the series workers_wanted from /metrics → start/stop of the instances n ≥ 2 within the ceiling (Н1.5)
steps 2–5: the first action of each platform process and worker (not a part) is the schema check (P/06.6 Н3 «console start — schema check», the common block), before reading the manifest
```

**Races.** `After` sets the start order, but not the readiness of the store, the rights or the manifest. Each process waits for a reliable read before its first action; a temporary unavailability — waiting with a pause, an erroneous configuration/schema — exit 2. One instance of a unit does not exclude another unit/a manual process; the uniqueness of a writer is ensured by slots and roles, not by systemd.

### issue and revoke a certificate

```
issue: w2c-ca.sh issue <server> <role> → a kit; own <dir> <role> → modes; copy to the server; the process reads by W2C_ROLE
revoke: w2c-ca.sh revoke <server> → revoked/crl; copy to each server (the processes reread); configstore leave <server>
        at the leader; a server without a kit — a door on the loopback
```

**Races.** Membership changes are performed by one operator sequentially; force admits only a temporary evenness within the declared maximum. The certificate and leave propagate by different actions: until the revocation is delivered to all nodes, one cannot claim that it acts everywhere. The start and stop of the workers script are serialised by Н1.5; the absence of a heartbeat does not release a reserved number.

### domain installation

An operator command, once per domain. Moved from М11/2 Н3
«domain installation» (the late layer of the chapter, introduced by chapter [8.2](../../08-domain/spec/08.2-domain.norms.md); review analysis of stage
A 8–10, № 17; the move of lesson 8, stage B). The root, the recovery file (`recovery_file`, `place`, `mode`), the pinning of
`domain/root` (`pin`), the set `domain/keys`, the holder keys `domain/signer` and the book acceptance key `domain/book-seal` are the forms of
[P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н1.1–Н1.4.

The order of steps 1–8, step 8 before chapter 8.8, the repeat of an interrupted installation and the operator window (a parallel command — code 2 `busy`) — the [domain founding contract](../../common/contracts/domain-founding.md)
«domain installation» (the Architect's decision 2026-10-23 on the finding of the Specification I02-FOUND).
