# P/02.3 — Строка спеки и сторона читателя: нормы

Канон главы 2.3 урока P/02 «Спека и установщик» (ADR-0080; модуль «Платформа» — ADR-0083). Повествование для человека —
[`../02-installer.md`](../02-installer.md), оно не норма. Как по этим файлам писать реализацию —
[`02-installer.README.md`](02-installer.README.md). Приёмка — [`../acceptance/3/`](../acceptance/3/README.md). Своего
OpenAPI у урока нет: HTTP-дверей у главы нет.

Глава перенесена из М10/2 (стадия B, ADR-0083 доп. (1): без изменения поведения): Н1.5, Н3 «Старт процесса» и «Смена
спеки», строки Н4 старта, смены и `spec put`, `puts.tsv` Н5, пп. 3–7 «Решает реализация». Сторона читателя (старт,
метка, остановка при смене) — контракт главы для процессов-потребителей (уроки 3–6, 8–10; [записка модуля](../../module-design.md));
хранилище и установщик его не исполняют. Загрузка байтов — [глава 2.1](02.1-installer.norms.md). Номера подразделов —
прежние номера М10/2. Ссылка «урок N» без главы — урок М10 (`М10_Platform/`), ещё не перенесённый; «глава 2.K» — глава
этого урока. Id норм — `P/02.3-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н1 Форма

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `platform/spec/<sub>`, `platform/spec/<sub>/rev`.

### Н1.5 Строка спеки в хранилище

Форма строки и метки — раздел «Семьи данных» ниже, построенный из схем [`data/spec-row.form.yaml`](../data/spec-row.form.yaml),
[`data/spec-rev.form.yaml`](../data/spec-rev.form.yaml) и исходов нечитаемой строки `*.outcomes.tsv` рядом (ADR-0088 п. 7;
ревью стадии B 1–2, п. 5; построенный раздел заменил блок формы, задача «Архитектора» по 495cc7833). Метка
`platform/spec/<sub>/rev` пишется ПОСЛЕ строки, её читает работающий процесс. Правила писателя и читателя (`rules`):

- rev строго растёт; метка никогда не понижается.
- Одинаковые yaml и shell — «без изменений», rev не растёт; shell сравниваются по байтам, отсутствие равно пустому.
- Писатель строки и метки — только установщик (и кластер из одного процесса со встроенной спекой — сам себе) — правом
  admin: процесс коробки ставит встроенную спеку как установщик (решение «Архитектора» 2026-10-18, каталог данных).
- Писатель пишет ровно поля `yaml`, `sha256`, `rev`, `shell` (если есть) строки и `rev`, `sha256` метки; читатель лишних
  полей не читает и ими не отказывает (нынешнее поведение записано ревью стадии A 2).
- Рядом со строкой установщик пишет канонический вид `platform/spec/<sub>/canonical/<форма>` — [глава 2.2](02.2-installer.norms.md)
  Н1.2; порядок записи — строка, вид, метка последней (окно 2.2, решение «Архитектора», п. 8).
- `spec put` при нечитаемой строке или метке этой подсистемы (хранилище не ответило, `rev` — не десятичное целое от 1 до
  2^53 − 1, `sha256` не по форме, `yaml` не загружается; разбор ревью стадии A 6–7, Б3, Б4) отказывает, ничего не пишет, код ≠ 0; строку чинит оператор (нынешнее поведение записано
  ревью стадии A 2; проверяется чтением — сценария нет).

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `platform/spec/<sub>` — строка

Схема — [`spec-row.form.yaml`](../data/spec-row.form.yaml), исходы — [`spec-row.outcomes.tsv`](../data/spec-row.outcomes.tsv); версия формы 1; норма — P/02.3 Н1.5.

| Ключ | Тип и границы | Обязательность | Урок | Смысл |
|---|---|---|---|---|
| `yaml` | строка | обязателен |  | байты файла спеки как есть; загружаются по главе 2.1 (Н3 «загрузить») |
| `sha256` | строка; целиком `[0-9a-f]{64}` | обязателен |  | дайджест байтов yaml; читатель сравнивает запись как есть — иная запись (заглавные) не совпадает: «sha256 не совпадает», не старт (Н4; ревью стадии A 2) |
| `rev` | целое; ≥ 1; ≤ 9007199254740991; целый знак и у читателя (whole) | обязателен |  | десятичное целое ≥ 1 — ревизия правила; первая установка — 1, затем +1 записью с cas по строке |
| `shell` | строка | необязателен |  | страница подсистемы (урок 9 Н1.1) или пусто; источник — файл `<sub>.shell.html` рядом с файлом спеки, файла нет — поле не пишется; отсутствие поля и пустое — одно «страницы нет»; МОЖЕТ отсутствовать у реализации без страниц |

## Н3 Проход

`загрузить` и `загрузить_каталог` — глава 2.1 Н3.

### Старт процесса

```
0. проверка схемы хранилища — урок 10 Н3 «старт контроллера, воркера, ресурса или консоли — проверка схемы» (добавлено М10/10): первым шагом, до шага 1
1. прочитать строку platform/spec/<sub> и метку /rev (все — для процессов, которым нужен весь каталог;
   прочий процесс проверяет на шаге 3 каталог из одной своей спеки: пересечение имени со своими rows и таблицами;
   межспековые проверки сделал установщик на полном каталоге, Н3 «Смена спеки»)
                                                                                            → нет строки/метки или их чтение не подтверждено: не стартовать (код 2)
2. sha256 байт yaml равен записанному; у процесса со встроенной спекой — встроенные байты равны строке
                                                                                            → иначе не стартовать
3. загрузить(yaml, "platform/spec/<sub>") и загрузить_каталог                              → отказ: не стартовать
4. запомнить rev строки; служить. Метка ниже строки на старте (установщик между записями) — не отказ: процесс служит по
   строке, а метку сверяет со своей rev, только когда та стала не ниже неё (первая равная — «догнала», без перезапуска)
```

«Не стартовать» — завершиться с ненулевым кодом и строкой лога, называющей источник и путь. Процесс НЕ ДОЛЖЕН служить без отказанной подсистемы или с прежней спекой.

**Гонки.** Установщик пишет строку, потом метку. Процесс, стартовавший между ними, прочёл новую строку (rev 2) и прежнюю метку (rev 1): он служит по строке и, пока метка ниже его rev, не считает её сменой (шаг 4). Когда установщик доведёт метку до того же числа, перезапуска не будет; сменой считается метка с rev, отличной от запомненной и **не ниже** её. Процесс, прочитавший старую строку до записи новой, перезапустится после чтения новой метки. Один период обнаружения смены отсчитывается **от публикации новой метки**, при успешном чтении хранилища. Если установщик умер после записи строки, но до метки, старые процессы ещё видят прежнюю метку, а новые могут стартовать по новой строке. Их работа по разным ревизиям не ограничена этим периодом: метку доводит следующий `spec put`, срок его вызова не задан (гонки смены ниже).

### Смена спеки

```
установщик spec put <файл>:
  загрузить(байты, файл)                                → отказ: файл не кладётся, код возврата 2
  shell (файл <sub>.shell.html) с атрибутом on…= в любом теге       → отказ: код возврата 2, stderr называет файл
                                                           и атрибут; до чтения каталога (урок 9 Н1.1 page; сверка python и
                                                           go М10/6–11, C31)
  прочитать полный подтверждённый каталог; подставить кандидат по его name и загрузить_каталог
                                                         → ошибка чтения/отказ: код 2, до первой записи строки и метки
  построить вид (глава 2.2 Н3) для новой строки        → toolarge вида: отказ установки целиком, ничего не записано, код 2;
                                                           stderr называет файл, ключ вида, вес и потолок (окно 2.2, п. 8)
  прочитать строку, вид текущей формы и метку
  строка есть, те же yaml и shell, и вид текущей формы есть, читается и равен проекции
                                                         → «без изменений»; метки нет или она ниже строки → довести (ниже); выход 0
  строка та же, а вида нет или он иной                  → как «строка есть» ниже: строка с rev + 1, вид, метка (глава 2.2 Н1.2)
  строки нет                                           → новая rev := 1; условие cas := "" (создать, пока строки нет)
  строка есть, прежняя rev = 2^53 − 1 (не «без изменений»)
                                                         → отказ до любой записи: код 2, stderr называет ключ строки и rev
                                                           (класс «не положено» Н4; решение «Архитектора» по догадке Go, 2026-10-20)
  строка есть                                          → новая rev := прежняя rev + 1; условие cas := прочитанная версия строки
  записать строку {yaml, shell (если страницы есть), sha256: sha256(yaml), rev: новая rev} с этим cas
                                                         → конфликт: перечитать и повторить
                                                         → toolarge: прекратить установку, код 2; stderr называет файл,
                                                           ключ platform/spec/<sub>, вес строки и потолок;
                                                           этот вызов не меняет строку и не переходит к записи метки
  записать вид {form, rev: новая rev, sha256, spec} с cas по прочитанной версии вида или ""
                                                         → конфликт: перечитать вид и повторить; метка не двигается, пока
                                                           вид не записан
  довести метку: метки нет → записать {rev, sha256} строки с cas ""; есть и rev метки < rev строки → записать с cas по её версии
                                                         → конфликт: перечитать метку и повторить, пока она ниже строки; не ниже — ничего
работающий процесс, на каждом проходе и не реже чем раз в 30 с (ADR-0068):
  прочитать метку; rev метки ≥ запомненной и не равен ей, или метки нет → как смена: остановиться с кодом 0; супервизор запускает
  заново; метка ниже запомненной (установщик ещё не довёл её) — не смена, ждать;
  метка не по форме (Н1.5: rev не десятичное целое от 1 до 2^53 − 1, sha256 не 64 строчные hex) → как на старте: остановиться с
  диагностикой (refused, имя строки), код 2; рестарт отказывает, пока оператор не исправит метку (admin-запись
  хранилища по rev строки, P/01.3; разбор ревью стадии A 6–7, Б1); чтение не
  подтверждено (хранилище не ответило) — не смена, продолжать (решение «Архитектора» по пробелу Go P/02 № 1)
старт процесса: строки/метки нет, их чтение не подтверждено, sha256 не тот, спека/каталог отказаны, встроенная не совпала (кластер из одного процесса)
                                                         → не старт, код 2, без перезапуска (ADR-0068)
```

**Гонки.** Профиль установки допускает одновременное изменение только одного имени спеки: разные имена меняет один оператор последовательно. Это условие окна, а не атомарность нескольких строк; при неподтверждённом чтении каталога запись не выполняется. Два установщика одного имени разом: `cas` по строке пропускает одного, второй перечитывает и либо видит «без изменений», либо кладёт свою ревизию поверх; первое создание с `cas: ""` выдаёт rev 1, каждое последующее изменение поднимает rev на один. Метка только поднимается: её запись обусловлена `cas` и условием «ниже строки», поэтому отставший установщик (записал строку rev 2, задержался, другой успел положить rev 3 и метку 3) метку не понизит — его запись не проходит. Метка выше строки невозможна: пишется после строки и из неё. После смерти установщика между строкой и меткой метка остаётся позади, пока следующий `spec put` не доведёт её (в том числе в ветке «без изменений»); автоматического доведения этим проходом нет, срока следующего вызова нет. `spec status` только показывает расхождение (ADR-0068). Срок обнаружения смены работающими процессами начинается после публикации метки, а не после записи основной строки.

## Н4 Отказы

| Причина | Класс | Кто и как видит | Что делает вызывающий |

| `spec put` отказанного файла | не положено | код возврата 2, отказ на stderr | править файл |
| `spec put`: новая ревизия при `rev` строки = 2^53 − 1 (Н1.5; та же спека — «без изменений», код 0) | не положено | код возврата 2, отказ до любой записи — строка, вид и метка прежние; stderr называет ключ строки и `rev` | новой ревизии у этого имени нет — вне профиля урока (решение «Архитектора» по догадке Go, 2026-10-20) |
| `spec put`: оболочка `<sub>.shell.html` с атрибутом `on…=` | не положено | код возврата 2; stderr называет файл и атрибут | убрать обработчик из оболочки (урок 9 Н1.1; C31) |
| `spec put`: канонический вид выше потолка строки хранилища для ключа вида (глава 2.2 Н1.2; окно 2.2, п. 8) | не положено | код возврата 2; ничего не записано — ни строка, ни вид, ни метка; stderr называет файл, ключ вида, вес и потолок | уменьшить спеку |
| `spec put`: строка с исходными `yaml`, `shell` (если есть), `sha256`, `rev` и именами полей выше потолка хранилища (`toolarge`) | не положено | код возврата 2; stderr называет файл, ключ строки, её вес и потолок; вызов не меняет основную строку и не пишет метку | уменьшить исходник/страницу или выбрать хранилище с подходящим потолком; неизменный ввод не повторять |

## Н5 Приёмка

Каталог [`../acceptance/3/`](../acceptance/3/README.md): `puts.tsv` — 7 установок `spec put` по порядку в свежее хранилище: код последней и rev строки спеки (Н3 «Смена спеки», `загрузить_каталог` главы 2.1). Раннер зовёт установку командой `spec-put {socket} {file}` раздела «Стенд» [общего README приёмки](../../common/acceptance/README.md).

| Группа случаев | Что проверяет | Нормы |
|---|---|---|
| `puts.tsv` | `spec put`: тот же файл дважды — rev 1 («без изменений»), изменённый — rev 2; A=B каталога: имя = свои rows или своя таблица, имя = rows или таблица другой спеки, совпавший `metrics.prefix` (`a-b` и `a_b`) — код 2, строки нет (№ 11, 12, 40) | Н3 |

Проверяются чтением реализации: строка и метка спеки в хранилище, все причины отказа старта из Н4 и допустимая отставшая метка, остановка при смене метки, остановка с кодом 2 при метке не по форме у работающего и неподтверждённое чтение метки — не смена (стенд урока 11; стенд не портит метку под работающим процессом; разбор ревью стадии A 6–7, Б2).

Граница `rev` проверяется чтением: при `rev` строки 2^53 − 1 та же спека — «без изменений», код 0, новая ревизия — отказ до
любой записи, код 2 (Н4); `puts.tsv` ставит установки в свежее хранилище и `rev` до границы не доводит (решение «Архитектора» по догадке Go, 2026-10-20).

Отказ установщика сверх потолка проверяется чтением ветви `toolarge` в Н3: она заканчивает команду кодом 2
с диагностикой Н4 до доведения метки; не является конфликтом для повтора. Причина отдельной проверки —
таблица `verdicts.tsv` главы 2.1 вызывает загрузку одного документа и не задаёт хранилище установщика или его потолок.
Контрпример для чтения: к принятому `base.subsystem.yaml` корпуса главы 2.1 добавить комментарий из `#` и 524288 байт `x`.
Разобранная спека та же, но при потолке 524288 байт одна сохранённая строка `yaml` уже не помещается;
предыдущая основная строка и метка не меняются этим вызовом. В описании реализации указываются места
обработки этого отказа и формирования диагностики; прохождение загрузчика не выдаётся за эту проверку.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **форма строки лога** при остановке по смене метки (период не реже 30 с и код 0 — норма Н3, ADR-0068);
2. **форма строки лога** при отказе старта (код 2 — норма Н3, ADR-0068);
3. **имя и форму команды установщика** (`spec put`, `spec status`), где лежит исходный файл и как из него делаются права (P/02.5 Н2: `w2cctl rights -deployment <имя>`, `--check`);
4. **предел размера** строки спеки;
5. **способ хранения встроенной спеки** у процесса, который не читает хранилище при старте (кластер из одного процесса), и как он сверяет её с строкой.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/02.3-MM` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/02.3-01** спека кластера — строка `platform/spec/<sub>` и метка `/rev` по Н1.5; пишет только установщик; первая установка — `rev: 1` с `cas: ""`, тот же файл снова — «без изменений» (rev 1), дальнейшее изменение поднимает `rev` на один — puts.tsv same_twice/changed; канонический вид (глава 2.2) пишется после строки и до метки, «без изменений» — только с видом текущей формы, равным проекции, вид выше потолка — отказ целиком (окно 2.2, решение «Архитектора», п. 8) — приёмка главы 2.2 после формата, до неё чтением; метка не понижается; `toolarge` основной строки завершает установку до метки — проверяется чтением по Н5; жизненный цикл — проверяется чтением (стенд урока 11); отказ загрузки или `toolarge` при `spec put` — код 2 и stderr по Н4, вызов не публикует спеку и метку — проверяется чтением по Н5 (часть P/02.1-12)
- [ ] **P/02.3-02** старт процесса: строка читается из хранилища и проходит `загрузить`; любой отказ строки «старт» Н4 — процесс не стартует, код 2, без перезапуска (ADR-0068); частичной службы нет — проверяется чтением всех причин Н4 и допустимой отставшей метки Н3, поскольку одиночный файл verdicts не задаёт хранилище и состояние процесса
- [ ] **P/02.3-03** смена спеки — смена метки: процесс читает метку на каждом проходе и не реже раза в 30 с, останавливается с кодом 0 (метки нет — то же) и перезапускается супервизором; период обнаружения отсчитывается от публикации метки при успешном чтении; метка только поднимается (`cas` и условие «ниже строки»), отставшую или отсутствующую метку доводит следующий `spec put`, срок его вызова не задан; живой перечитки нет — проверяется чтением; метка не по форме у работающего — остановка, код 2, рестарт отказывает до исправления метки оператором, неподтверждённое чтение — не смена (решение «Архитектора» по пробелу Go P/02 № 1, 22fae38ff; разбор ревью стадии A 6–7, Б1, Б2) — проверяется чтением
