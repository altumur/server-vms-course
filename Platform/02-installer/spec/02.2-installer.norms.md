### Н1.1 Projection

The canonical view of a manifest is the JCS bytes ([ADR-0072](../../../decisions/0072-канонический-json-подписанных-документов-rfc-8785.md)) of the value that
is obtained from the tree of the accepted manifest (the loader of chapter 2.1, verdict `ok`) by the rules below, in order. The view depends only on the
bytes of the manifest and the standard files of chapter 2.1 (the schema `02.1-installer.schema.json`, the layer table `02.1-installer.layers.tsv`).

```yaml
sugar:      a closed list of reductions to one form (before defaults):
  tables:   a list of names [a, b] → {a: {}, b: {}}
  bound_to: for a unit field and a table field, a single name "x" → ["x"]
  in:       for an element of secret_in of the regex kind, a single word "query" → ["query"]
defaults:   every key with the annotation `default` of the schema of chapter 2.1 is present explicitly — only inside a present parent or a parent with
            its own default (ADR-0089 addendum (1) Р10); an absent section without default stays absent
computed:   a closed list of the steps of lesson 2 (after defaults):
  П1 snapshot:            no key — the names of unit.fields in author order without *_secret, without type: blob and without server, then
                          state.<name> of each unit.state, except cursor, in author order (ADR-0091 item 3); [] — []
  П2 tables.<t>.journal:  absent — {written: "<t>.written", deleted: "<t>.deleted"}; one key given — the second likewise
  П3 display.form:        absent — [{fields: [<names of unit.fields in author order>]}], without title
  П4 descriptor default:  for a unit field and a table field — the value said; not said or inherit said — null
                          (for all types, blob included; ADR-0089 addendum (2))
  П5 decoded:             for an element of secret_in of the regex kind without decoded — true (P/06.2 Н1.1, А13)
not:        not substituted: events.suppress.<kind>.by, display.section, display.general (ADR-0089 addendum (2)), keys without
            the annotation `default` in the schema (the defaults note, section 4)
ordered:    maps with the mark `x-ordered` of the layer table (unit.fields, tables.<t>.fields) — an array {"name": <key>, …value} in author
            order; other maps — objects, the order — JCS; a reader does not rely on author order outside ordered
            (ADR-0089 addendum (1) Р14)
scalars:    JSON values by the type of the schema place (integer — a number, an integer place — an integer after the reduction of layer 2: `4.0` → `4`;
            string — a string, boolean — true/false)
notes:      the view has no comments, no source text and no `x-*` marks
```

### Н1.2 View row

```yaml
platform/manifest/<sub>/canonical/<форма>:   # one row per subsystem and view form; the writer is the installer (Н3)
  form:    the number of the view form, a decimal integer ≥ 1; now 1 (key …/canonical/1)
  rev:     rev of the manifest row platform/manifest/<sub> from which the view is built (chapter 2.3 Н1.5)
  sha256:  sha256 of the manifest row (its field sha256)
  manifest: the bytes of the view (Н1.1) as text — JCS, UTF-8, without a final newline
ceiling:   the ceiling of a store row of P/01.1 Н1 for this key; the sum of the manifest row and the view is not limited (ADR-0089
           addendum (1) Р11); the source is the actual ceiling of the store: max_value of the answer of GET /v1/status (P/01.3 Н2,
           OpenAPI 01 StatusResponse); 524288 is only the default of the daemon flag -max-value, not a constant of the installer;
           the installer has no ceiling setting of its own (the Architect's decision on the Go question P/02 № 4)
window:    a change of the view form is a new form next to it (…/canonical/<form + 1>); during the change window the installer writes both forms
           (ADR-0083 item 3)
```

The form of `manifest` itself is the view schema [`02.2-installer.view.schema.json`](02.2-installer.view.schema.json) (JSON Schema 2020-12;
the marks `x-step` — a projection step, `x-default` — the key is required by a default of the form, `x-unique-by` — the key of the elements of `ordered`;
[layers В7](../../common/LAYERS.md) § 3): it is closed where the form is; keys with `default` are required; `ordered` is an array with a
unique `name`. The view form section below and the `canonical` vectors are built by the builder of the skill `lesson-spec` (ADR-0092 item 12).

### Форма канонического вида (построена из стандартных файлов)

Значение `manifest` строки `platform/manifest/<sub>/canonical/1` — JSON (JCS, ADR-0072) этой формы: JSON Schema 2020-12 `02.2-installer.view.schema.json` (ADR-0089 п. 3, ADR-0092 слой 6). Отображение без имён автора закрыто: ключа вне таблицы нет. «Есть всегда» — ключ с умолчанием формы манифеста (`default` `02.1-installer.schema.json`) или шагом проекции; «есть, если сказан в манифесте» — ключ без умолчания, его отсутствие и есть значение. Отображение `x-ordered` формы манифеста — список объектов `{name, …}` в порядке автора. Правил и связей формы манифеста здесь нет: принятый манифест проверил установщик.

## Н3 Procedures

### build view(manifest bytes) → bytes | refusal

1. Load the bytes by chapter 2.1. If the load refuses, return that refusal of the load (the view is not built).
2. Let bytes be the result of sugar, defaults, computed, ordered, scalars of Н1.1, applied in order, encoded by JCS.
3. If the view row {form, rev, sha256, manifest} is heavier than the ceiling of Н1.2 (`max_value` read by the caller),
   return `toolarge` of the view (Н4).
4. Return bytes.

### installer `manifest put` — writing the view (the Architect's decision on window 2.2, item 8)

The view is built before any write. The order of the steps is [chapter 2.3](02.3-installer.norms.md) Н3 «Manifest change» (the installer):

1. Read the ceiling: `GET /v1/status` → `max_value`. If the store did not answer, answered not 200, or answered without
   `max_value`, refuse the whole installation: nothing is written, exit code 2 (chapter 2.3 Н4; the Architect's decision on
   the Go question P/02 № 4).
2. Build the view (above) for the new rev. On `toolarge` of the view, refuse the whole installation: nothing is written,
   exit code 2; stderr names the file, the view key, the weight and the ceiling.
3. «Unchanged» means: the row is the same (yaml, shell) AND the view of the current form is present, readable and equal to
   the projection; otherwise write.
4. The order of writes: the manifest row → the view (`cas` by the version of the view read, or `""`) → the mark last.
5. If the view is not written because of a `cas` conflict, re-read the row and the view:
   1. If the rev of the row is mine, repeat the `cas` of the view.
   2. If the rev of the row is already another one (another installer wrote a newer one), run the procedure again from
      reading the row (my file — a new rev or «unchanged»); the view of the former rev is not written: the view always
      carries the rev of the current row (C02-VIEW-CAS-RESTART-01).
   3. If the row is already written, the mark does not move until the view is written.

A cluster of one process with a built-in manifest writes the view by the same rule ([P/02.4](02.4-installer.norms.md) Н1.10;
ADR-0089 addendum (1) Р15).

### Reader

A reader of the view (a process that has moved over by its own change of behaviour, ADR-0089 item 7):

1. Read the mark, then the view of its own form.
2. If the view is absent, is not readable, its rev or sha256 ≠ the mark's, or manifest does not pass the built schema, act
   as for an unreadable manifest (chapter 2.3 Н3 «Process start»): do not start, exit code 2; for a running process — as
   for a mark not in form.
3. Otherwise the reader's manifest is the value of manifest; the YAML loader is not needed.

Until its own change, the reader runs the loader by chapter 2.3 Н3; it does not read the view.

**Races.** The view is written after the row and before the mark: running processes see the change by the mark, when the row
and the view are already written; a starting process, having read the mark, reads the row and the view of the same `rev`
(otherwise — Н3 «Reader»: `rev` ≠ the mark). Two installers of one name — the `cas` of the row (chapter 2.3 «Races»), then
the `cas` of the view; the loser re-reads.
