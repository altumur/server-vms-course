# P/02.2 — Канонический вид спеки: нормы

Канон главы 2.2 урока P/02 (ADR-0080; модуль «Платформа» — ADR-0083). Повествование — [`../02-installer.md`](../02-installer.md),
инструкция — [`02-installer.README.md`](02-installer.README.md). Своего HTTP-контракта у главы нет: вид — строка хранилища
рядом со строкой спеки. Глава — правка поведения после переноса урока 2 (ADR-0083 доп. (1); ADR-0089 с доп. (1)–(2);
окно — `decisions/inbox/2026-10-20-окно-главы-2.2-канонический-вид.md`, решение «Архитектора» — его п. 8): установщик пишет
канонический вид — проекцию принятой спеки по правилам [источника формы главы 2.1](02.1-installer.norms.md); читатели
переходят на него своими правками (Н3 «Читатель»), до того — загрузчик ([глава 2.3](02.3-installer.norms.md) Н3). Имена
ключей — до перехода ADR-0086 (`platform/spec/…`). Id норм — `P/02.2-MM` (новые нормы окна).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Непомеченное предложение нормативного раздела
читается как ДОЛЖЕН.

## Н1 Форма

**Время.** Полей времени у строки вида нет.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `platform/spec/<sub>/canonical/<форма>`.

### Н1.1 Проекция

Канонический вид спеки — байты JCS ([ADR-0072](../../../decisions/0072-канонический-json-подписанных-документов-rfc-8785.md)) значения, которое
получается из дерева принятой спеки (загрузчик главы 2.1, вердикт `ok`) по правилам ниже, по порядку. Вид зависит только от
байтов спеки и источника формы главы 2.1.

```yaml
sugar:      закрытый перечень приведений к одной форме (до умолчаний):
  tables:   список имён [a, b] → {a: {}, b: {}}
  bound_to: у поля единицы и поля таблицы одно имя "x" → ["x"]
  in:       у элемента secret_in вида regex одно слово "query" → ["query"]
defaults:   каждый ключ с default в источнике есть явно — только внутри присутствующего родителя или родителя со
            своим default (ADR-0089 доп. (1) Р10); отсутствующий раздел без default — отсутствует
computed:   закрытый перечень шагов урока 2 (после defaults):
  П1 snapshot:            нет ключа — имена unit.fields в порядке автора без *_secret, без type: blob и без server; [] — []
  П2 tables.<т>.journal:  нет — {written: "<т>.written", deleted: "<т>.deleted"}; дан один ключ — второй так же
  П3 display.form:        нет — [{fields: [<имена unit.fields в порядке автора>]}], без title
  П4 default описателя:   у поля единицы и поля таблицы — сказанное значение; не сказано или сказан inherit — null
                          (у всех типов, включая blob; ADR-0089 доп. (2))
  П5 decoded:             у элемента secret_in вида regex без decoded — true (урок 7 Н1.1, А13)
not:        не подставляются: events.suppress.<вид>.by, display.section, display.general (ADR-0089 доп. (2)), ключи без
            default в источнике (записка умолчаний, раздел 4)
ordered:    отображения с пометкой ordered (unit.fields, tables.<т>.fields) — массив {"name": <ключ>, …значение} в порядке
            автора; прочие отображения — объекты, порядок — JCS; читатель на порядок автора вне ordered не опирается
            (ADR-0089 доп. (1) Р14)
scalars:    значения JSON по типу узла источника (integer — число, string — строка, boolean — true/false)
notes:      комментариев, исходного текста и пометок источника в виде нет
```

### Н1.2 Строка вида

```yaml
platform/spec/<sub>/canonical/<форма>:   # одна строка на подсистему и форму вида; писатель — установщик (Н3)
  form:    номер формы вида, десятичное целое ≥ 1; сейчас 1 (ключ …/canonical/1)
  rev:     rev строки спеки platform/spec/<sub>, из которой вид построен (глава 2.3 Н1.5)
  sha256:  sha256 строки спеки (её поле sha256)
  spec:    байты вида (Н1.1) текстом — JCS, UTF-8, без перевода строки в конце
ceiling:   потолок строки хранилища P/01.1 Н1 для этого ключа; сумма строки спеки и вида не ограничивается (ADR-0089
           доп. (1) Р11)
window:    смена формы вида — новая форма рядом (…/canonical/<форма + 1>); в окно смены установщик пишет обе формы
           (ADR-0083 п. 3)
```

Форма самого `spec` — схема, построенная из источника главы 2.1 (ADR-0089 п. 3): закрыта там же, где форма; ключи с
`default` обязательны; `ordered` — массив с уникальным `name`; руками не пишется. Раздел формы вида и схема для читателей —
построитель формы (ADR-0087).

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `platform/spec/<sub>/canonical/<форма>` — строка

Схема — [`canonical-row.form.yaml`](../data/canonical-row.form.yaml), исходы — [`canonical-row.outcomes.tsv`](../data/canonical-row.outcomes.tsv); версия формы 1; норма — P/02.2 Н1.2.

| Ключ | Тип и границы | Обязательность | Урок | Смысл |
|---|---|---|---|---|
| `form` | строка; целиком `[1-9][0-9]*` | обязателен |  | номер формы вида; сейчас 1 |
| `rev` | целое; ≥ 1; ≤ 9007199254740991; целый знак и у читателя (whole) | обязателен |  | rev строки спеки, из которой вид построен (P/02.3 Н1.5) |
| `sha256` | строка; целиком `[0-9a-f]{64}` | обязателен |  | sha256 строки спеки |
| `spec` | строка | обязателен |  | байты вида текстом — JCS, UTF-8 (P/02.2 Н1.1); проверяется построенной схемой вида |
| `.<имя>` | любое значение | необязателен |  | лишние поля: читатель их не читает и ими не отказывает, писатель их не пишет (терпимый читатель, как строка спеки P/02.3 Н1.5) |

Исходы нечитаемой строки:

| Путь отказа | Исход | Приоритет | Единица | Норма |
|---|---|---|---|---|
| `/rev` | как вид целиком: читатель — не старт, код 2 (у работающего — остановка, код 2); spec put — вид переписывается (не «без изменений») | 0 | строка | P/02.2 Н3 «Читатель», «spec put» |
| `/sha256` | как вид целиком: читатель — не старт, код 2; spec put — вид переписывается | 0 | строка | P/02.2 Н3 «Читатель», «spec put» |
| `/spec` | как вид целиком: читатель — не старт, код 2 (spec не по построенной схеме — то же); spec put — вид переписывается | 0 | строка | P/02.2 Н3 «Читатель», «spec put» |
| строка целиком | вид целиком нечитаем: читатель — как нечитаемая спека, не старт, код 2 (у работающего — остановка, код 2); spec put — вид переписывается и rev поднимается (не «без изменений») | 1 | строка | P/02.2 Н3 «Читатель», «spec put»; P/02.3 Н3 |

## Н3 Проход

### построить вид(байты спеки) → байты | отказ

```
1. загрузить(байты) по главе 2.1                         → отказ: отказ загрузки (вид не строится)
2. sugar, defaults, computed, ordered, scalars Н1.1 по порядку; JCS
3. строка вида {form, rev, sha256, spec} тяжелее потолка Н1.2 → toolarge вида (Н4)
```

### установщик `spec put` — запись вида (решение «Архитектора» по окну 2.2, п. 8)

Вид строится до любой записи. Порядок шагов — [глава 2.3](02.3-installer.norms.md) Н3 «Смена спеки» (установщик):

```
построить вид (выше) для новой rev                      → toolarge вида: отказ установки целиком, ничего не записано,
                                                          код 2; stderr называет файл, ключ вида, вес и потолок
«без изменений» — строка та же (yaml, shell) И вид текущей формы есть, читается и равен проекции; иначе запись
порядок записи: строка спеки → вид (cas по прочитанной версии вида или "") → метка последней
вид не записан из-за конфликта cas                      → перечитать вид и повторить; строка уже записана — метка не
                                                          двигается, пока вид не записан
```

Кластер из одного процесса со встроенной спекой пишет вид тем же правилом ([P/02.4](02.4-installer.norms.md) Н1.10;
ADR-0089 доп. (1) Р15).

### Читатель

Читатель вида (процесс, перешедший своей правкой поведения, ADR-0089 п. 7):

```
прочитать метку, затем вид своей формы
вид нет, не читается, rev или sha256 ≠ метки, spec не проходит построенную схему
                                                        → как нечитаемая спека (глава 2.3 Н3 «Старт процесса»): не старт,
                                                          код 2; у работающего — как метка не по форме
иначе                                                   → спека читателя — значение spec; загрузчик YAML не нужен
```

До своей правки читатель прогоняет загрузчик по главе 2.3 Н3; вид он не читает.

**Гонки.** Вид пишется после строки и до метки: работающие процессы видят смену по метке, когда строка и вид уже записаны;
стартующий процесс, прочитав метку, читает строку и вид той же `rev` (иначе — Н3 «Читатель»: `rev` ≠ метки). Два
установщика одного имени — `cas` строки (глава 2.3 «Гонки»), затем `cas` вида; проигравший перечитывает.

## Н4 Отказы

| Причина | Код / исход | Запись | Что делает вызывающий |
|---|---|---|---|
| `spec put`: вид выше потолка строки хранилища для ключа вида | код 2, ничего не записано | stderr называет файл, ключ `platform/spec/<sub>/canonical/<форма>`, вес и потолок | уменьшить спеку (класс `toolarge` главы 2.3 Н4) |
| читатель: вида своей формы нет, не читается, `rev`/`sha256` ≠ метки, `spec` не по схеме | не старт, код 2 (у работающего — остановка, код 2) | диагностика с именем ключа | `spec put` заново (глава 2.3) |

## Н5 Приёмка

Векторы `canonical` (`../vectors/canonical/` — пакет вводит окно после генератора ожиданий построителя) и приёмка главы — установки `spec put` с колонкой вида (`acceptance/2/`, формат главы 2.3 —
поддержка `check_spec`) — вводятся с частями построителя (решение «Архитектора» по окну 2.2, п. 8). До них предметы главы
проверяются чтением:

| Предмет | Что должно быть проверено | Почему шагов пока нет |
|---|---|---|
| проекция Н1.1 | байты вида каждой принятой спеки корпуса и спек курса | векторы `canonical` — после генератора ожиданий |
| строка вида и порядок записи Н1.2, Н3 | вид до записи, отказ `toolarge` вида целиком, «без изменений», порядок строка — вид — метка | приёмка главы — после формата `puts.tsv` с колонкой вида |
| читатель Н3 | сверка с меткой, схема, отказ как нечитаемая спека | читатели переходят своими правками |

## Решает реализация

1. Как построить вид (свой проход по дереву загрузчика или общий код) — байты обязаны совпасть с векторами `canonical`.
2. Когда читатель переходит на вид — его правка поведения; до неё — загрузчик.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/02.2-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6).

- [ ] **P/02.2-01** проекция Н1.1: умолчания внутри присутствующего родителя, `ordered` — массив `{"name", …}` в порядке автора, скаляры по типу, JCS, без пояснений — векторы `canonical` (после генератора ожиданий); до них — чтением
- [ ] **P/02.2-02** сахар Н1.1 `sugar` — закрытый перечень трёх приведений — векторы `canonical`; до них — чтением
- [ ] **P/02.2-03** вычисляемые умолчания П1–П5, неподставляемые ключи `not` — векторы `canonical`; до них — чтением
- [ ] **P/02.2-04** строка вида Н1.2 `{form, rev, sha256, spec}`, ключ `…/canonical/<форма>`, свой потолок, окно формы — приёмка главы (после формата); до неё — чтением
- [ ] **P/02.2-05** схема вида строится из источника главы 2.1 — `check_spec` (построитель); чтением у реализации: вид проходит схему
- [ ] **P/02.2-06** читатель Н3: сверка с меткой, схема, отказ как нечитаемая спека — правками читателей; до них — чтением
- [ ] **P/02.2-07** `spec put` Н3: вид до записи, отказ `toolarge` вида целиком, «без изменений» с видом, порядок строка — вид — метка — приёмка главы (после формата); до неё — чтением
