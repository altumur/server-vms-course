### Н1.3 Секретные строки и читатели

Перенесено из М10/7 Н1.3 (стадия B).

```yaml
secrets:                                     # раздел спеки (форма — глава 2.1)
  readers: {<строка или префикс>: [<роль>…]} # свои секретные строки и кто их читает
  reads:   [<строка или префикс>…]           # чужие строки, которые читает воркер этой спеки: ДОБАВЛЯЕТ <B>worker к читателям,
                                             # ничего не отнимает; секретной строку делает только readers (своей спеки или
                                             # другой) или platform_readers — необъявленная семья остаётся у своих ролей (Н1.4)
roles:     [console, controller, worker, domainworker, domain, domainagent, resource, domainconsole]   # закрыто; domainworker, domain, domainagent, domainconsole — роли домена (М11); domainworker — слово платформы для роли <sub>domain воркера на домене (Н3 шаг 1, у спеки с kept или переносимой книгой; P/03.7 Н1.6), спеки подсистем его не включают
platform_readers:                            # векторы platform-lists (vectors/platform-lists/cases.tsv); строки domain/* — урок P/08 и М11 (signer, signer-pending, book-seal — P/08.2 Н1.3–Н1.4)
  domain/break-glass/: [console, domain, domainagent]
  domain/signer:       [domain]
  domain/signer-pending: [domain]           # точное имя, не покрыто `domain/signer`
  domain/book-seal:    [domain]
  domain/users/:       [domain]
  domain/member-key:   [domainagent, domain]            # форма — P/09.1 Н1.1 (domain — только подпись GET /api/backup, P/08.8 Н1.8 шаг 5); открытый ключ — несекретно в domain/member и Entry.key
                                            # резервные копии P/08.8 Н1.5 — объекты, не строки-секреты: в списке их нет
  door/signer:         [console]             # добавлено М10/9 (подписант токена P/06.5 Н3 «/where/<id>»); консоль читает его всегда — выдача токена
                                            # (P/06.5) и перезапечатывание при старте (P/06.2) — не завися от secrets.readers спеки; объявление спеки
                                            # читателей добавляет, консоль не отнимает (разбор ревью стадии B 6–7, № 36)
rule:      объявления secrets.readers/reads не содержат буквальный `*`, не начинаются с `!` или `delete:`;
           непредставимое объявление отвергается загрузчиком/генератором до выдачи файла, не экранируется и не усекается.
           Ограничение относится к объявлениям прав, не к общему ключу хранилища P/01.1.
           Ключ с `/` на конце — префикс, без него — точный ключ (`domain/<sub>/<книга>` не закрывает `domain/<sub>/<книга>/*` — потому они названы отдельно);
           книга домена у члена — точное имя `domain/<sub>/<книга>`, её строки по кластерам у держателя — префикс `domain/<sub>/<книга>/` (спека называет оба);
           объявления не пересекаются по закрываемым строкам: два префикса, где один — начало другого (`a/` и `a/b/`), — отказ
           загрузчика; точное имя и префикс с тем же началом (`domain/signer` и `domain/signer-pending`,
           `domain/<sub>/<книга>` и `domain/<sub>/<книга>/`) не пересекаются — точное имя закрывает одну строку,
           префикс — строки под `/`; потому «самого длинного совпавшего» нет: у строки ровно одно объявление; объявленная секретной строка без читателя не читается никем, кроме admin;
           файл прав не генерируется, если читатели ≠ способные прочесть (Н3 шаг 4)
```

### Н1.4 Вывод прав из спеки

Положительные списки ниже — исходные права, не обход P/01.2 Н1.3: never применяется ко всем,
включая admin; отрицания секретных читателей Н1.3 вычитаются из read.

Писатели семей — [P/06.1](../../06-console/spec/06.1-console.norms.md) и P/03 (строки единиц, слоты, эпохи), [P/04](../../04-controller/spec/04-controller.norms.md), P/05; [договор просьбы и её метки](../../common/contracts/request-mark.md) и P/06.4 Н1.5 (`<s>/requests/*`, `<s>/asked/*`; разбор ревью стадии B 6–7, № 24); P/06.6 Н1.1а, Н1.2 (`platform/schema`, `platform/drain`), P/06.1 Н1.5, Н1.6 (`<s>/sweep`, `<s>/<таблица>/*`); здесь сводка того, что генератор выводит для каждой роли из ключей спеки. Права чтения — положительные списки, выведенные так же; секретные строки читают только объявленные читатели (Н1.3).

Общие правила вывода действуют на каждую строку таблицы, строка их не повторяет:

- в `read` каждой роли входит `platform/spec/*` — спеки кластера, по которым она работает (ADR-0068), если его
  не покрывает уже `platform/*`;
- в `read` входят все положительные образцы её `write`; образцы только удаления (`delete:…`) и отрицания `write`
  в `read` не входят;
- отрицания `!<s>/idem/*` и `!<s>/asked/*` (заявки и учёт людей — только консоль) получают только роли, чьи чтения
  их достают (образец, покрывающий `<s>/*`); файл прав для одних входов байт-стабилен;
- слова `secrets.readers`: `controller` и `worker` — роли объявляющей спеки (`<s>controller`, `<s>worker`),
  остальные — платформенные роли как есть, `domainworker` — по P/01.2 Н1.1; `secrets.reads` спеки `B` ДОБАВЛЯЕТ `Bworker`
  к читателям названной строки и ничего не отнимает; отрицания `!<образец>` прочим генератор выдаёт только для строк,
  объявленных секретными — в `secrets.readers` спеки каталога или в векторах [`platform-lists`](../vectors/platform-lists/README.md) (`../vectors/platform-lists/cases.tsv`; Н1.3);
  семья, названная в `secrets.reads`, но не объявленная секретной (строки единиц другой спеки — `testsub/counters/` у
  `testsub2`), даёт только чтение `Bworker`: её роли-владельцы читают её по своим правам, как без объявления;
- образец объектов `objects/<s>/commands/*` выдаётся в файл как есть образцом `write` (а с ним, по общим правилам, `read`
  и удаление) роли `<s>worker` у спеки с разделом `requests`: метки просьб пишет, закрывает и убирает держатель —
  воркер (договор просьбы и её метки, «Метка» mark; разбор ревью стадии B 6–7, № 24); строк хранилища он не касается, оценщик строк его не встречает (журнал cammeta-go, урок 8 № 4).

Объявления, переводимые в образцы (`worker.reads`, `secrets.readers`, `secrets.reads`), не содержат буквальный `*` и не начинаются с `!`/`delete:`; непредставимое объявление — отказ загрузки/генерации до файла. Это не запрет такого ключа в самом хранилище. Проверять не только читателей самого секрета, но и неизменность прав соседних обычных строк.

Правила генератора: роль удаляет то, что пишет (кроме меток команд у консоли и двух сохраняемых строк допуска у контроллера); образец `delete:<…>` даёт только удаление без записи (консоль — `platform/doors/*` выведенного сервера, контроллер — строки единиц при `delete_after`, воркер — строки своих единиц при `worker.deletes`, удаление с `cas` по прочитанной версии); `worker.writes` ДОЛЖЕН называть объявленную собственную таблицу; имя `unit.rows` и необъявленное имя дают отказ загрузки `refused:reference` (глава 2.1). Строки единиц остаются за консолью и удалением контроллера по допуску; исключение таблицы воркера не даёт ему прав на `unit.rows`; семьи `<s>/idem/*` и `<s>/asked/*` — отрицание `!` всем, кроме консоли; секретные строки (объявленные в `secrets.readers` или `platform_lists.tsv`) — читателям по `secrets.readers` и `secrets.reads`, прочим с досягающим правом — `!<образец>`; `secrets.reads` без такого объявления только добавляет чтение `Bworker` (Н1.4), где образец — ключ как объявлен: префикс с `/` → `<префикс>*`, точный ключ — без `*` (Н1.3); генератор отказывается выдать файл, если множество объявленных обычных читателей секрета не равно множеству обычных ролей, которые его прочтут. Внутренний admin проверяется по особому правилу P/01.2 Н1.3, а не включается в объявление читателей.

### Н1.4а Роли домена — глава позднего слоя

## Н3 Проход

### сгенерировать_права(каталог спек, развёртывание) → файл

```
1. роли: console, resource, domain, domainconsole, domainagent (М11); на каждую спеку — <s>controller, <s>worker
   и <s>domain — у спеки с domain.kept или переносимой книгой (воркер подсистемы на домене, P/03.7 Н1.6; ADR-0074 C7
   п. 2, доп. 5); группы по P/01.2 Н1.1
2. для каждой роли — write по Н1.4 из ключей спеки; delete = write, минус все права «только write» Н1.4:
   метки команд у консоли, <s>/controller/placement_turn и <s>/controller/placement_intent у контроллера;
   плюс все delete-only из Н1.4: delete:platform/doors/* у консоли, delete:<s>/<rows>/* у контроллера при delete_after и
   у воркера по worker.deletes; список delete выдаётся явно,
   чтобы отсутствие поля не вернуло исключённые права через умолчание P/01.2 Н1.2
3. read по Н1.4; worker.reads: ключ с `/` на конце → префикс; domain/placed/<sub>/ дополнительно даёт domain/placement/<sub>/; исходное domain/placed/<sub>/ сохраняется
4. сначала проверить представимость всех объявлений Н1.4; отказ → файла нет;
   секреты: секретная строка — объявленная в secrets.readers спеки каталога или в векторах platform-lists; её читатели — по
   secrets.readers/reads (и платформенные читатели, Н1.3); secrets.reads на необъявленную строку — только +Bworker, без !;
   образец — ключ как объявлен (Н1.3): префикс с `/` на конце → <префикс>*, точный ключ → сам ключ без `*`
   (`domain/<sub>/<книга>` не закрывает `domain/<sub>/<книга>/*`); объявления не вкладываются (Н1.3) — отрицание одного не
   задевает другого; читателю — образец, если его чтения его не достают; нечитателю, чьи права его достают, — !<образец>
   множество объявленных обычных читателей ≠ множество обычных ролей, способных прочесть → отказ генерации;
   внутренний admin не сравнивается с этим множеством (его исключение — P/01.2 Н1.3 и Н1.3)
5. выдать JSON с отсортированными образцами (байт-стабильно); «generated — do not edit» —
   поле comment либо сопроводительный текст вне JSON. Не писать комментарии синтаксиса // или /* */.
   Для одинаковых входов форма и текст пометки стабильны; --check сравнивает по смыслу (Н3 «установить»), не байты
```

**Гонки.** Вход — неизменный каталог по P/01.2 Н1.2. Две генерации с одинаковыми входами дают файл
байт в байт. Разные входы могут давать одинаковые права; проверка не доказывает неизменность
исходных файлов, а только совпадение файла прав с результатом генерации.

### установить(файл прав)

```
rights --check <файл> против SPEC_DIR                          → расходится: установка отказана
  сравнение по смыслу: одинаковый набор ролей; у каждой роли равны group и множества образцов read, write, delete
  (порядок и повторы в списке не важны; нет delete — пустое множество, как у оценщика P/01.2 Н1.2); comment, порядок
  ключей и пробелы не сравниваются; файл не по форме P/01.2 Н1.2 — расходится
  (пилот хранилища, А5)
юниты: SupplementaryGroups=<группа роли>; PLATFORM_STORE=configstore:///run/configstore/<роль>.sock
демон: сокет на роль, 0660, группа роли — SocketGroup= юнита configstore-<роль>.socket (глава 2.4 Н1.1); admin.sock 0600
```

---

**Гонки.** Установка выполняется одним установщиком по неизменному каталогу; параллельная
установка и правка `SPEC_DIR` исключены из этого урока. Работающий демон сохраняет прежние
права до перезапуска. Перед стартом с новым файлом установка выполняет `--check`; при
расхождении демон с этим файлом не запускают. Живого переключения прав и атомарного
переключения всего кластера урок не обещает.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **флаги инструмента генерации** сверх `-deployment` и `--check` (сам инструмент — Н2), путь файла по умолчанию (`/etc/w2c/configstore-rights.json`), путь сокетов на не-Linux;
2. ~~**как демон попадает в группы ролей или обходится setgid-каталогами**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита сокета, демон в группы ролей не входит (глава 2.4 Н1.1, P/01.3 Н1.3 `sockets`; пилот хранилища, А4);

4. **дословный текст пометки `comment`** сверх обязательного содержания (P/01.2 Н1.2).
