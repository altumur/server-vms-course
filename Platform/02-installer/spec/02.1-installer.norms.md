### Н1.1 Текст манифеста

Манифест — текст в кодировке UTF-8 по синтаксису YAML 1.2.2 в рамках правил ниже (ADR-0092 пп. 2–4, доп. (2)). Текст
разбирает готовый парсер YAML 1.2 закреплённой версии; сверху — тонкая проверка слоя 1 ([слои В7](../../common/LAYERS.md)):
правила `text` ниже, ничего сверх них. Простые скаляры распознаёт таблица скаляров [раздела «Форма»](#форма-построена-из-стандартных-файлов)
по стилю узла — норма этой главы, не схема core YAML 1.2 (core читает `0x10` и `0o7` целыми, а bool — только `true`,
`True`, `TRUE`; добавлено пилотом JSON Schema). Загрузчик ДОЛЖЕН принимать ровно этот текст и ДОЛЖЕН отказывать всему за
его пределами (`refused:text`, Н4).

```yaml
text:
  bytes:    UTF-8; без BOM: U+FEFF первым знаком файла — отказ, дальше — обычный знак (`a﻿b` — слово); без C0, кроме
            TAB, LF и CR, без DEL и C1 (включая U+0085 NEL), U+FFFE, U+FFFF, U+2028 и U+2029 — отказ; те же знаки в
            значении после экранирования (`\x07`, ` `, суррогаты) — отказ; одиночный CR — отказ, CRLF читается как LF
  tab:      литеральный TAB — только в комментарии (после `#`); в отступе, после `:` или `-`, внутри простого слова, в
            строке в кавычках, в блочном скаляре и в потоке `{…}`/`[…]` — отказ (ADR-0092 п. 4); `\t` и `\<TAB>` в
            двойных кавычках — экранирование, допустимо
  document: ровно один документ — по байтам, не по ответу парсера: начальный `---` с колонки 1 до всякого содержимого
            допустим; второй `---`, `---` не с колонки 1, `...` и директива `%` — отказ; корень — блочное отображение с
            колонки 1: сдвинутый документ, корень потоком `{…}`, список, скаляр, пустой файл — отказ
  refused:  якорь `&`, псевдоним `*`, тег `!…`, ключ слияния `<<`; ключ-отображение и ключ-список; простой ключ, который
            таблица скаляров читает не строкой (int, float, bool, null, `~`: `1:`, `1.5:`, `true:`, `null:`) — везде, в том
            числе внутри значений `type: json`; в кавычках (`'1'`, `'true'`) — строка, `0x10`, `0o7` — слова; ключ, сказанный
            дважды в одном отображении (и в потоковом `{a: 1, a: 2}`); вложенность глубже 64 (корень — уровень 1, каждое
            отображение и список, блочные и потоковые одинаково, — ещё уровень, скаляр уровня не добавляет)
  rare:     что библиотеки YAML читают по-разному — потоковая коллекция на несколько строк, строка в кавычках на несколько
            строк, явный указатель отступа (`|2`), сложный ключ (`? …`) — отказ словами, а не «как получится»
  flow:     ключ потокового отображения с `:` и без значения (`{unconfirmed_max:}`) — отказ (ADR-0092 п. 4); одиночный `-`
            простым скаляром в потоке (`[-, a]`, `[-]`, `a: [x, -]`, `{k: -}`) — отказ: YAML 1.2.2 простой скаляр с `-` в потоке
            не начинает (yaml-test-suite G5U8, YJV2; V7-FLOW-DASH-01)
  escape:   в двойных кавычках — только `\\` `\"` `\/` `\t` `\<TAB>` `\n` `\r` `\<пробел>` `\_` (U+00A0) `\xXX` `\uXXXX`
            `\UXXXXXXXX`; знак результата подчиняется `bytes`; результат — скалярное значение Unicode: суррогат D800–DFFF
            (`\ud800`, `\U0000d800`, и парой `😀` — YAML пары не склеивает, знак вне BMP пишется `\UXXXXXXXX`) —
            отказ; `\0` `\a` `\b` `\v` `\f` `\e` `\N` `\L` `\P` и незнакомое (`\q`) — отказ; в одинарных кавычках
            экранирований нет, кроме `''`
  comment:  `#` вплотную после закрывающей кавычки, `]` или `}` (`"a"# c`, `]# c`) — отказ; `#` после пробела —
            комментарий, `#` внутри простого слова (`a#b`, `counter# c`) — часть слова (YAML 1.2.2)
  block:    после `|` или `>` и указателя (`-`, `+`) — пробел или конец строки; начальные пустые строки блочного скаляра не
            глубже его первой непустой строки — иначе отказ
  parser:   ошибка парсера YAML — отказ (`[ - , a ]`, неявный ключ длиннее 1024 знаков — YAML 1.2.2 § 7.4.2); пустой элемент
            потока в начале или в середине (`[a,,b]`, `[,a]`, `{a: 1,, b: 2}`) — ошибка разбора; висячая запятая в конце
            потока (`[a, b, ]`, `{k: v, }`) — допустима (YAML 1.2.2; решение «Архитектора» 2026-10-28 по ADR-0092 доп. (1), yaml-test-suite UDR7)
```

Что YAML 1.2.2 читает сам, читается по нему: значение на строке ниже ключа (слово, кавычки, поток), скаляр ниже голого
`-`, `?x` ключом и значением, ` # c` в строке продолжения простого слова — комментарий; одиночный `-` значением в блоке —
индикатор элемента списка, не слово (`unit: -` над ключом того же отступа — ошибка разбора), в потоке `[-, a]` — отказ (`flow`)
(ADR-0092 п. 3: 11 отступлений прежней нормы сняты, 12-е — висячая запятая в потоке, решение «Архитектора» 2026-10-28 по ADR-0092 доп. (1), yaml-test-suite UDR7). Скаляры: простой — по таблице скаляров, в кавычках и
блочный — всегда строка; пустое значение (`key:` без значения) — не строка и не отображение: где месту нужно значение,
отказ формы (`refused:form`), явное «нет» пишется словом `null` или `~`.

Числа float в принятом манифесте конечны и по модулю не больше предела таблицы скаляров (`float_max`) — после прочтения в binary64:
запись, которая округляется до этого числа (`1.7976931348623158e308`), принимается; запись ненулевого числа, которая
читается нулём (потеря значимости, `1e-400`), — `refused:form` (добавлено опытом слоя текста).
NaN, обе бесконечности (в любом допускаемом YAML написании) и переполнение этого диапазона —
`refused:form` с путём значения; они не превращаются в строку или null.
Это правило действует во всём документе, включая default/inherit и вложенные числа JSON и непрозрачных мест.
Непрозрачность отменяет проверку имён внутренних ключей, но не общие требования к числам и JSON.

### Н1.2 Документ

Корень — отображение с закрытым набором разделов; форма каждого раздела, обязательность, умолчания и урок, где ключ
получает смысл, — [раздел «Форма»](#форма-построена-из-стандартных-файлов). Уроки-владельцы дают смысл ключей и на форму ссылаются сюда; при расхождении
формы прав источник. Незнакомый ключ на любом уровне — отказ (Н4). Раздел, отсутствующий в файле, значит умолчание
своего урока, если оно определено. Отсутствие обязательного — `refused:form`; null не
заменяет отображение или строку. Профиль подсистемы без единиц не входит в эту главу; `unit.rows` и numeric/named
загрузчик за автора не выбирает. Места с именами автора (в разделе «Форма» — «имена автора») и непрозрачные места («opaque») — места схемы без закрытого
набора ключей ([слои В7](../../common/LAYERS.md)): у непрозрачного места форма (Н3 шаг 2) не проверяет набор ключей, но ссылки Н1.4 на его ключи и
значения проверяются, а числа — по Н1.1. Целое место (места `x-integer-place` таблицы слоёв: `capacity.default`, сроки, ширина
колонки и подобные) — число с целым значением: `4.0`, `4e0`, `1e1` — целые и в дереве становятся `4`, `4`, `10`; дробная часть (`4.5`) и значение вне
±(2^53 − 1) — `refused:form` (ADR-0092 п. 8; слой 2, слово `x-integer-place` таблицы слоёв). Целый знак семей данных —
иной слой (кодек строк, слой 3) и этим не меняется.

### Н1.2а Сводная таблица ключей

Таблица ключей — [раздел «Форма»](#форма-построена-из-стандартных-файлов) (корень и определения). Сказанный ключ без значения — `refused:form` (и `default:`
без значения: явный `null` — «нет умолчания», пустое значение — не сказанное); класс отказа — слой (Н4); пометки
`x-class` таблицы слоёв — только для сверки набора А с прежними классами (ADR-0092 Confirmation), не норма класса. Пересечение имени таблицы с именами подсистем
каталога — `refused:catalogue` (Н3).

### Н1.2б Раздел `domain` — глава позднего слоя: вводит урок 8 (P/08.K); корпус держит загрузчик целиком

Формы разделов `domain.*` — [раздел «Форма»](#форма-построена-из-стандартных-файлов) (`domain`, `book`, `token`). Смысл разделов вводит урок 8: `domain.ref`, `domain.view` —
[P/08.1](../../08-domain/spec/08.1-domain.norms.md) Н1.2, Н1.4; `domain.edit` — [P/08.6](../../08-domain/spec/08.6-domain.norms.md) Н1.3; книги —
[P/08.5](../../08-domain/spec/08.5-domain.norms.md), виды токенов — [P/08.7](../../08-domain/spec/08.7-domain.norms.md) (вычисляемые `computed` — P/08.7 Н1.1),
общий документ — [P/08.9](../../08-domain/spec/08.9-domain.norms.md) Н1.2; имена (`domain.names`, случаи `m59_names_*`) — P/08.5 Н1.7;
`domain.kept`, `domain.tables` — [P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.6. `domain.reports` — [P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.2 `reports`
(P/09.1-17). Свидетели `domain.witness` — [P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.8 `witness`, семьи
ключей (`domain.keys`, случаи `m59_keys_*`) — [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.11, `merge` при чтении — P/06.7 Н1.14. Перенесено из М11/5 Н1.1,
М11/7 Н1.1, М11/11 Н1.1 и отказа `domain.witness.member_field` М11/11 Н1.8. Вид токена в двух манифестах каталога —
`refused:catalogue` (Н3). Отказ объявления `domain.shared` называет путь под `domain.shared[<i>]` (сам элемент или
глубже; повтор — второе вхождение) и одну из причин:

- «is not {name, type: json, schema} — a document the domain holds is JSON, and what it may be is its schema»
- «is not a name, or is a secret — the shared document is signed, not sealed»
- «is not a field of the unit»
- «is a field of the unit — a document the domain holds whole is no unit's: name it apart»
- «neither inherits nor is the field the page groups by (display.tree.group_by) — a domain value it would have nowhere to go»
- «names one thing twice»

`merge` не по форме — «merge is override or union (a list's) — said of a field that inherits»; `domain.witness.member_field`
не fixed-поле — «'<поле>' is no fixed field of the unit: a witness names a member by a field that does not change».

### Н1.3 Поле

Грамматика поля единицы (`unit.fields.<имя>`, определение `unitField`) и поля таблицы (`tables.<т>.fields.<имя>`,
`tableField`) — [раздел «Форма»](#форма-построена-из-стандартных-файлов). Смысл поля в строке — [P/06.1](../../06-console/spec/06.1-console.norms.md) Н1.2 (`<sub>/<rows>/<id>`), в форме — [P/06.5](../../06-console/spec/06.5-console.norms.md) Н1.2
(`display.form`), в домене — [P/08.1](../../08-domain/spec/08.1-domain.norms.md) Н1.4 (вид) и [P/08.6](../../08-domain/spec/08.6-domain.norms.md) Н1.3 (правка); здесь — что проверяет загрузчик и в каком порядке:

- имя из `platform_fields` P/06.1 Н1.2 в `unit.fields` — `refused:form` до проверки и
  материализации значения, включая `default`/`inherit`; запрет не переносится на поля таблицы; поле `state` при
  объявленном `unit.state` — тоже `refused:form` (ключ `state` единицы — её состояние, P/06.1 Н1.2; ADR-0091 п. 3);
- поле blob — только в `unit.fields`: дайджест приходит дверью байтов `PUT /<rows>/<id>/<blob_field>` после создания
  единицы (P/06.1 Н3 «положить_тело»), при создании поле всегда `""` — умолчание или наследование писали бы дайджест в
  строку мимо неё; `unit.fields.bytes` рядом с blob — отказ: это поле ответа `BlobWritten` двери байтов (P/06.1 Н1.5);
- поле таблицы `name` — только string при `key: name` (P/06.1 Н1.6); `held_by`, `garbled`, `by`, `at`, `made_at` —
  вычисляемые значения и штампы, полями таблицы не бывают независимо от `stamp`;
- имя поля — только строковый ключ YAML (Н1.1 keys); преобразование имени в строку запрещено;
- `{id}` в умолчании: у поля `string` единицы с `unit.id: numeric` `default` МОЖЕТ содержать `{id}` — дверь подставляет
  десятичную запись выданного id при создании ([P/06.1](../../06-console/spec/06.1-console.norms.md) Н1.2 шаг 3), правка
  значение не пересчитывает; `{id}` при `unit.id`, равном полю, а не `numeric` (строка 122 `relations.json`), `{id}` в умолчании поля иного
  типа (строка 123) и любые иные `{`, `}` в умолчании поля `string` при `unit.id: numeric` (строка 124; экранирования
  нет) — `refused:relations`; у поля таблицы и у поля единицы при `unit.id` — поле `{`, `}` без `{id}` в умолчании — знаки как есть (запрос VMS
  № 1, решение «Архитектора» 2026-10-23).

### Н1.3а Секрет в манифесте

Перенесено из М10/7 (Н1.1 `secret_field`, Н1.4 `never` — часть загрузчика); запись, маска, конверт и строки
платформы — [глава P/06.2](../../06-console/spec/06.2-console.norms.md). Секрет — поле, имя которого оканчивается на `_secret`, и только оно: реестра нет, `secret_note` — не

ссылок); такой манифест не грузится.

### Н1.4 Ссылки между ключами

Ключ, называющий поле, таблицу, метрику или маршрут, ДОЛЖЕН называть то, что объявлено в **этой же** манифесте; иначе
отказ при загрузке, а не на странице и не на проходе. Строки ссылок и отношений между значениями — [раздел «Форма»](#форма-построена-из-стандартных-файлов)
(«Связи», источник `02.1-installer.relations.json`, номера строк — поле `no`); проходят только по чистой форме (Н3:
форма раньше связей). Сверх строк:

- шаблон `requests.key` называет свойства `requests.schema.properties` — поля тела просьбы `POST /<sub>/requests`
  ([P/06.4](../../06-console/spec/06.4-console.norms.md) Н1.5): `{имя}` — только строка без преобразования, `{имя:int}` — конечное binary64-число (как в JCS) с модулем
  ≤ 2^53−1, усечение к нулю и десятичная запись без знака `+` и ведущих нулей (`7.9` → `7`, `-7.9` → `-7`, `-0.5` →
  `0`); bool не число. Отсутствующее значение, иной тип или число вне этой границы — 400 при подаче, не при загрузке.
  Поля единицы здесь ни при чём. Тот же шаблон у `tables.<т>.key`;
- `display.options.<поле>` у поля `bool`: ключ — текст значения в кавычках (`'true'`, `'false'`); простой `true:` —
  `text` по Н1.1 keys; у слова пульса из `display.form[].status[]` — любые строки (подписи значений);
- `display.fields.<имя>`, `display.field_help.<имя>`, `display.form[].fields[]`, `display.tree.columns[].field` из
  платформенных имён принимают только `worker`, `server`, `revision`, `observed_revision`, `phase`, `id` (их показывает
  модуль — P/06.5 Н1.2): `display.fields.epoch` отказан, `display.fields.seen` при `status[].field: seen` принят;
- `worker.requests[]` — другая подсистема; что она принимает просьбы, и `placement.near.sub`, `.of`, `.prefer` —
  проверка каталога (Н3); подсистемы `near.sub` ещё нет в каталоге — проверка `near.of`, `near.prefer` откладывается до её
  появления, сродство не действует (ADR-0091 доп. (26) п. 2);
- `worker.creates[]` — другая подсистема (`sub`), не больше одного элемента на неё; `key` — подстановки `{поле}`
  через `-`, без `:int` и иного литерала; адресат, его `unit.rows` и поля `key` — проверка каталога (Н3); смысл —
  [P/03.6](../../03-worker/spec/03.6-worker.norms.md) Н1.6 (ADR-0091 п. 1);
- `worker.uses[]` — `<подсистема>.<доля>` другой подсистемы; что она объявила эту долю в `shares` — проверка каталога
  (Н3); своя доля — только объявленная в `shares` с `part` (группа части в `SupplementaryGroups` воркера), своя без
  `part` — отказ (строка 91); `shares.<доля>.part` — часть из `parts` этой подсистемы (строка 121); `shares`, `parts` —
  имена по грамматике `name`; юниты, группы и каталоги — [P/02.4](02.4-installer.norms.md) Н1.1 (ADR-0091 пп. 4, 5,
  доп. (2) п. 4);
- `worker.exec` — обязателен у каждого манифеста (раздел `worker` обязателен: `unit` обязателен у всех) — программа
  воркера (P/02.4 Н1.1, Н1.12; источник у раннера — P/02.3 Н3); `worker.exec` и `parts.<часть>.exec` — одна грамматика
  (`execLine`): слова через один пробел U+0020, пустых слов нет, первое — абсолютный путь, в словах — печатные ASCII без
  `"` `'` `\` `%` `$` `` ` `` `;` `|` `&` `<` `>` `*` `?` `(` `)` `{` `}` `[` `]` `~` `#` `!`; argv — разбиение по пробелу; нет ключа
  или нарушение грамматики — `refused:form` (Н3 шаг 2) (векторы
  [`exec`](../vectors/exec/README.md); ADR-0091 доп. (4)–(6));
- `door.routes[]` — имя маршрута (допуск `token`, договор токена двери) или `{name, role?: [<роли>], domain?: [<виды>]}`
  (допуск по сертификату роли, класс `mixed` договора сертификата роли; `domain` — по токену домена одного из видов,
  P/03.4 Н1.7 `door_admission`; оба — маршрут допускает любое; `{name}` без них — то же, что строка-имя: допуск `token`;
  ADR-0091 доп. (14) п. 1); умолчание — `token`: нынешние
  манифесты переходят без правки; имена обеих форм уникальны (строка 82), `door.pass` их не называет (строка 83)
  (ADR-0091 доп. (7)–(9), (14)); вид в `domain` — непустой список без повторов по грамматике вида `domain.tokens`; вид,
  которого нет в `domain.tokens` ни одной подсистемы каталога, — `refused:catalogue` (Н3 «загрузить_каталог»; ADR-0091
  доп. (14) п. 1); имена видов `domain.tokens` уникальны в каталоге, поэтому вид маршрута называет одну подсистему, а его
  `audience_claim` — её объявление (ADR-0091 доп. (17) п. 5);
- `worker.stop_timeout` — целое от 20 до 50, умолчание 20 (верх — одно правило для всех воркеров); `parts.<часть>.stop_timeout` — целое
  ≥ 1, умолчание 20; вне границ — `refused:form`; юниты — P/02.4 Н1.1 (ADR-0091 доп. (2) п. 1, доп. (3) п. 4);
- `unit.state` — имя → схема строки состояния (`jsonSchemaLite`, глубина ≤ 32); `snapshot[]` вида `state.<имя>`,
  `placement.retire_when.state` называют имя `unit.state`, `retire_when.field` при `state` — свойство схемы этого
  состояния; `placement.ends.field` — поле `int` или `float` (смысл — [P/04](../../04-controller/spec/04-controller.norms.md)
  Н1.3, P/03.6 Н1.7; ADR-0091 пп. 2, 3);
- `placement.unplaced.delete_after` больше не требует отсутствия `fixed`-полей и `about` по id (правила 46–47 сняты,
  поправка ADR-0067 доп. 2026-10-10 решением ADR-0091 п. 1): у таблицы с такими полями контроллер физически удаляет только
  строки с `made` (P/04 Н1.3), ручные — снимает, не удаляя; `numeric` с `delete_after` — по-прежнему отказ.

Правила:

- `unit.fields.<имя>`: если есть `default`: запрещены `inherit` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если нет `inherit`: запрещены `merge` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если нет `ref`: запрещены `must_match` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если `type` не `list`: `merge` — ещё и любое значение; не из: `union`.
- `unit.fields.<имя>`: если `type` — `list`: запрещены `unique` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если `type` не `url`: `unique` — ещё и любое значение; не из: `canonical`.
- `unit.fields.<имя>`: если `type` — `string` (или ключа нет — умолчание): `default` — ещё и строка или null; `enum` — ещё и список, элемент — строка.
- `unit.fields.<имя>`: если `type` — `int`: `default` — ещё и целое или null; целое по значению (`4.0` — `4`, x-integer-place).
- `unit.fields.<имя>`: если `type` — `float`: `default` — ещё и число или null.
- `unit.fields.<имя>`: если `type` — `bool`: `default` — ещё и bool или null; `enum` — ещё и список, элемент — bool.
- `unit.fields.<имя>`: если `type` — `list`: `default` — ещё и список, элемент — строка или null.
- `unit.fields.<имя>`: если `type` — `url`: `default` — ещё и строка или null.
- `unit.fields.<имя>`: если `type` — `blob`: запрещены `default` (путь — запрещённый ключ); `required` — ещё и одно из: `false`.
- `unit.fields.<имя>`: если `type` — `int`, `float`, `list`, `json`, `url`, `blob`: запрещены `enum` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если `type` не `url`: запрещены `credentials`, `secret_in`, `schemes` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если `type` — `string`, `url` (или ключа нет — умолчание): `inherit` — ещё и строка или null.
- `unit.fields.<имя>`: если `type` — `int`: `inherit` — ещё и целое или null; целое по значению (`4.0` — `4`, x-integer-place).
- `unit.fields.<имя>`: если `type` — `float`: `inherit` — ещё и число или null.
- `unit.fields.<имя>`: если `type` — `bool`: `inherit` — ещё и bool или null.
- `unit.fields.<имя>`: если `type` — `list`: `inherit` — ещё и список, элемент — строка или null.
- `unit.fields.<имя>`: если `type` — `blob`: запрещены `inherit` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если имя целиком `[\s\S]*_secret`: `type` — ещё и одно из: `string`.
- `unit.fields.<имя>`: если имя не целиком `[\s\S]*_secret`: запрещены `bound_to` (путь — запрещённый ключ).
- `unit.fields.<имя>`: если имя не целиком `[A-Za-z_][A-Za-z0-9_]{0,63}` и `type` — `blob`: отказ: имя blob — 1–64 ASCII [A-Za-z_][A-Za-z0-9_]*.

#### Таблица скаляров (Н1.1)

## Н2 Двери

У загрузчика две двери: процедура загрузки, которой пользуются все процессы и установщик, и `GET /manifest` консоли, которым
модуль консоли (урок P/07) узнаёт форму подсистемы; вторая — в [главе P/06.5](../../06-console/spec/06.5-console.norms.md)
Н2 «GET /manifest».

### Процедура загрузки

Не HTTP: вход реализации, который получает байты и имя источника и отвечает манифестом или отказом. Все пути чтения манифеста — файл, строка хранилища, встроенный манифест — ДОЛЖНЫ проходить через неё.

```
загрузить(байты, источник) → манифест | отказ(источник, путь_ключей, причина)
загрузить_каталог([манифест…])  → каталог | отказ(источник, путь_ключей, причина)     # проверки между манифестами
```

## Н3 Проход

### загрузить(байты, источник) → манифест | отказ

```
1. текст:     байты — парсер YAML 1.2.2 закреплённой версии и тонкая проверка Н1.1 (слой 1)  → иначе refused:text
2. форма:     дерево — схема `02.1-installer.schema.json` (JSON Schema 2020-12) и слова `x-*` таблицы слоёв
              `02.1-installer.layers.tsv`: имя (Н1.2), закрытый набор ключей каждого уровня, в местах имён автора —
              любые имена по своей грамматике, в непрозрачных местах набор ключей не проверяется; типы, грамматика поля
              (Н1.3), перечни, обязательные ключи (`capacity.default`); числа — по Н1.1, в том числе в непрозрачных
              местах; целое место — границы ±(2^53 − 1), значение с целым значением — целое и в дереве приводится к целому
              (`4.0` → `4`; слой 2)                                                        → иначе refused:form
3. связи:     только при чистой форме: каждая строка связей (CEL, `02.1-installer.relations.json`) над деревом
              загрузчика; отсутствующее значение и `has` берут статическое умолчание `default` формы (Н1.4)
                                                                                          → иначе refused:relations
4. умолчания: заполнить отсутствующее умолчаниями уроков-владельцев; ослабляющие — только сказанные (Н1.2 lease,
              unplaced, places)
→ манифест
```

Порядок слоёв нормативен (ADR-0092): текст → форма → связи; связи проверяются только при чистой форме — манифест с
отказом формы отказывается классом `form`, даже если неверна и связь (добавлено корпусом главы 2.1). Порядок внутри
формы и внутри связей — решает реализация; путь и строка отказа — подсказка (Н4).

**Гонки.** Нет: загрузка чистая, без состояния и без хранилища.

### загрузить_каталог([манифест…]) → каталог | отказ

Проверки, которым нужен не один манифест: `worker.requests` называет подсистему каталога, принимающую просьбы; `near.of` и `near.prefer` — поля подсистемы `placement.near.sub`; `metrics.prefix` двух подсистем не совпадает (`GET /manifest`, P/06.5 Н2). Подсистемы `near.sub` ещё нет в каталоге — проверка `near.of` и `near.prefer` ждёт её установки, как у `worker.creates` ниже: сродство до неё не действует (единица размещается без него, P/04 Н1.3 `near`); установка `near.sub` при несовместимых полях — отказ каталога; подсистема есть, а полей нет — отказ каталога, как прежде (ADR-0091 доп. (26) п. 2). Отсрочка `near` не задаёт порядка установки (P/02.4 Н1.7 `order`; доп. (26) п. 1).

`worker.creates[]` подсистемы C (ADR-0091 п. 1; Г-8 — уточнение «Архитектора» 2026-10-22):

1. `sub` — подсистема A, `rows` — её `unit.rows`; `unit.id` у A не `numeric` (резерв `next_id` заказчику не
   даётся). Пока A нет в каталоге, проверки 1–4 ждут её установки: каталог проверяется целиком при каждой установке, и
   установка A при несовместимом заказчике — отказ каталога (заказчик и адресат МОГУТ ссылаться друг на друга —
   `testsub` заказывает `testsub2`, `testsub2` просит `testsub`; поставить их по одному иначе нельзя);
2. каждая подстановка `{f}` в `key` — поле `unit.fields` A с `required: true`, типа `string`, `url`, `int`, `float` или
   `bool`, не `*_secret` и не поле-источник id A (`unit.id`: его библиотека заполняет готовым id);
3. `key` называет каждое `fixed`-поле A, кроме поля-источника id, и поле `about.field` A, если оно не `unit.id`;
4. у A нет поля `*_secret` с `required: true` или с `default`: библиотека заказчика секретов не пишет (P/03.6 Н1.6),
   строка без них не создалась бы;
5. два заказчика одной таблицы — имена C и D, где `C-` — начало `D-` (`rec` и `rec-x`), — отказ: префиксы их id
   вложены.

`worker.uses[]` — `<подсистема>.<доля>`: подсистема, если она в каталоге, объявила `shares.<доля>`; пока её нет — та же
отсрочка, что у `worker.creates` (группы доли нет, юнит воркера её не получает — P/02.4 Н1.1). Имена ОС и пути всех подсистем
каталога — пользователи, группы, юниты, каталоги долей и частей ([P/02.4](02.4-installer.norms.md) Н1.1) — строятся все
вместе: любое совпадение двух имён и имя длиннее 32 знаков — отказ каталога (ADR-0091 п. 5). Каталог — все манифесты кластера (все строки `platform/manifest/*`); отказ одного манифеста каталога — отказ каталога. Для любых подсистем A и B, включая A=B, имя B не совпадает с unit.rows или именем любой таблицы A, включая списковые tables. Иначе refused:catalogue с именами обеих манифестов и конфликтующей семьёй, до выдачи каталога/первой записи установщика; это исключает пересечение root-двери и mount при любом выборе root.

Виды токена домена (Н1.2б; ADR-0091 доп. (14) п. 1, доп. (17) п. 5): имя вида `domain.tokens` объявлено в каталоге один раз —
тот же вид у двух подсистем — отказ каталога; каждый вид в `door.routes[].domain` подсистемы C объявлен в `domain.tokens`
подсистемы каталога (в том числе самой C), иначе — отказ каталога. Отсрочки, как у `worker.creates`, у вида маршрута нет:
подсистема, объявляющая вид, ставится раньше двери, которая его называет.

**Гонки.** Проверка каталога получает готовый набор загруженных манифестов; две проверки не меняют входы друг друга.
Чтение источников до неё не обещает атомарного снимка всех файлов или строк. Если файл меняется во время чтения,
могут быть получены прежние, новые либо смешанные байты: допустимый документ загружается, недопустимый даёт отказ
по Н1. Сам факт изменения файла чистая процедура по байтам не обнаруживает. Неразрешённая связь между принятыми
манифестами даёт отказ каталога; при любом таком отказе частичный каталог не выдаётся.

Строку манифеста, старт процесса и смену манифеста задаёт [глава 2.3](02.3-installer.norms.md) Н3.

## Н4 Отказы

Закрытый список. У загрузчика один вид ответа «не манифест» — отказ в словах, называющий источник (файл или ключ хранилища) и путь ключей; классы ниже различают причину для читателя и приёмки, не код.

Путь ключей и строка файла в отказе — подсказка, не норма: строги вердикт и код выхода (ADR-0092 п. 5); приёмка пишет
их в отчёт без провала (Н5). Подсказка — как сверены python и go 2026-10-18 (СЛЕДУЕТ): путь — до самого глубокого ключа с неверным значением; индекс списка в пути —
число; строка — строка этого ключа; отсутствующий ключ — путь с его именем и строка объемлющего отображения; повтор
ключа — путь повторного ключа и строка второго объявления; ошибка кодировки — строка байта, без пути; отказ слоя текста —
строка виновного знака или конструкции (маркер, открывающая кавычка, незакрытый поток, строка без ключа), не
следующая и не конец файла (добавлено опытом слоя текста). У правила на два
ключа путь — ключ, который правило запрещает рядом с другим: `merge: union` у поля не `list` — `…fields.<поле>.merge`;
`bytes` рядом с blob — `unit.fields.bytes`; поле `name` таблицы не по форме — `tables.<т>.fields.name`; `delete_after`
при `numeric` id — `placement.unplaced.delete_after` (добавлено пилотом JSON Schema). У правил на присутствие путь —
«A запрещён без B» — сам A (`merge` без `inherit`, `must_match` без `ref`, `login` без `param`, `in` без `regex`); «A требует
B» — недостающий B (`per_person` и `free: true` → `ttl`, `free: false` → `valid_for`, `most_valid`; `from` → `key`, `pick`,
`to`) (добавлено пилотом варианта C, П4). У ссылки Н1.4, которая требует другой ключ (`requests.stamp: group` и `rights.reach.group` без `placement.group_by`, `requests.outcome: fetched` без `requests.key`, `placement.home: near` без `placement.near`), путь — сам ссылающийся ключ (добавлено корпусом главы 2.1). У правила над набором (`unique`, `prefix_free`, глубина `schema`) путь — сам набор; у повтора элемента списка — второе вхождение, как у повтора ключа (добавлено корпусом главы 2.1). ## Решает реализация

Реализация обязана назвать в своём описании:

1. **библиотеки стека** ([раздел «Форма»](#форма-построена-из-стандартных-файлов)) для шагов 1–3 прохода: парсер YAML 1.2, валидатор JSON Schema 2020-12, CEL — закреплённые версии, и свои слои (`LAYERS.md`); сами стандартные файлы — норма, не выбор;
2. **сколько ошибок формы называет один отказ** (первую или все) — путь и строка в отказе — подсказка (Н4);
3. **команду загрузки одного файла для приёмки** по разделу «Стенд» общего README приёмки: раннер вызывает её на каждом файле `verdicts.tsv`; код выхода 0 — манифест, иной — отказ, текст отказа называет файл.
4. **внутренний договор API манифеста**: прочитать строку `platform/manifest/<sub>` в канонический вид
   ([P/02.2](02.2-installer.norms.md)), собрать и проверить каталог, `rev`, исходы и отказы (слова — как в P/02, без
   пересказа норм) — API библиотеки, не перенос P/02 в `common/`. Описание пишет в репозитории реализации владелец урока 02
   до библиотеки; процессы 03–10 читают только договор и API; смесь языков — через хранилище: канонический вид строки —
   норма P/02.2 (догадка стадии C C04-MANIFEST-SDK-01, ADR-0087 доп. (12) п. 7).

- [ ] **P/02.1-01** текст манифеста — YAML 1.2.2 в рамках Н1.1 (парсер и тонкая проверка слоя 1); всё вне — `refused:text` — вердикты группы 1 и набора Б таблицы Н5; путь и строка — подсказка `diagnostics.tsv` (`dup_top_key_name`)
