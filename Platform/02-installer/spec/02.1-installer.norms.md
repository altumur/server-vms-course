### Н1.1 Текст спеки

Спека — текст в кодировке UTF-8, читаемый как подмножество синтаксиса YAML 1.2; простые скаляры распознаёт своя таблица `scalars` ниже — норма этой главы, не схема core YAML 1.2 (core читает `0x10` и `0o7` целыми, а bool — только `true`, `True`, `TRUE`; добавлено пилотом JSON Schema). Загрузчик ДОЛЖЕН принимать ровно это подмножество и ДОЛЖЕН отказывать всему за его пределами, называя путь ключей и строку файла.

```yaml
text:
  encoding: UTF-8; без BOM: U+FEFF первым знаком файла — отказ, дальше — обычный знак (`a\ufeffb` — слово; в начале
            строки он начинает слово, как любой знак) (добавлено опытом слоя текста); без NUL и иных управляющих: C0, кроме TAB, LF и CR, DEL и C1, включая U+0085 (NEL, который YAML 1.2 допускает), — отказ со строкой файла;
            не-знаки U+FFFE и U+FFFF (вне `c-printable` YAML 1.2) — отказ;
            отступы пробелами (табуляция в отступе — отказ); перевод строки LF или CRLF (`\r` перед `\n` отрезается);
            одиночный CR где угодно, и в комментарии, — отказ;
            TAB допустим только внутри строки в кавычках и внутри блочного скаляра: после `:` или `-`, внутри простого
            слова, перед комментарием и в потоковых `{…}`/`[…]` — отказ; внутри комментария (после `#`) TAB допустим:
            комментарий не читается; U+2028 и U+2029 (переводы строки, которые
            читатели YAML понимают по-разному) — отказ где угодно, в том числе в кавычках
  document: ровно один документ: один начальный `---` с колонки 1 до всякого содержимого допустим (на его строке — только
            комментарий); второй `---`, `---` не с колонки 1, `...` или директива `%` — отказ; корень — блочное
            отображение с колонки 1: сдвинутый документ, корень потоком `{…}`, список, скаляр, пустой файл — отказ
  comment:  `#` начинает комментарий только после пробела (или в начале строки); `]# c`, `"a"# c`, `слово# c` — не
            комментарий, а строка, не отнесённая ни к какому ключу (отказ)
  keys:     ключ отображения — строка: простой ключ, который таблица `scalars` ниже читает не строкой (int, float,
            bool, null, `~`: `1`, `1.5`, `true`, `TRUE`, `null`), — отказ `text` везде, в том числе внутри значений
            `type: json`; `0x10`, `0o7` — слова и ключом допустимы; в кавычках (`'1'`, `'true'`) — строка;
            ключ-коллекция — отказ (решение «Архитектора», изменено 2026-10-18); простой ключ с `?` в начале (`?x`, `? x`)
            — отказ `text`; длину ключа текст не ограничивает: предела 1024 знаков неявного ключа YAML 1.2 нет, длину
            задаёт грамматика имени своего места, где она есть (добавлено пилотом JSON Schema)
  refused:  якорь `&`, псевдоним `*`, ключ слияния `<<`, любой тег `!…`; ключ, сказанный дважды в одном отображении
            (и в потоковом `{a: 1, a: 2}`); ключ-отображение и ключ-список; вложенность глубже 64 (корень —
            уровень 1, каждое отображение и список, блочные и потоковые одинаково, — ещё уровень, скаляр уровня
            не добавляет); ключ без `:` в потоковом отображении (`{a, b: 1}`; `a:b` без пробела — одно слово, так что
            `{a:b}` — ключ без `:`) и пара `k: v` в потоковом списке (`[a: 1]`); пустой элемент потока (`[a,,b]`, `[a,]`);
            ключ потокового отображения с `:` и без значения (`{unconfirmed_max:}`) — не пустой элемент потока, а
            сказанный ключ без значения: `refused:value` (scalars null; добавлено пилотом варианта C, П7);
            строка файла, которую читатель не смог отнести ни к какому ключу
  scalars:
    # таблица скаляров — норма этой главы, не ссылка на core YAML 1.2 (добавлено пилотом JSON Schema)
    bool:   только `true` / `false` в любом регистре (`tRuE` — bool); `On`, `Off`, `yes`, `No` — слова
    null:   `null`, `Null`, `NULL`, `~`; иной регистр (`nULL`) — слово; пустое значение (`key:` без значения) — не
            null, а «сказанный ключ без значения»: `refused:value` везде (Н1.2а), в том числе у `default:`; явное «нет»
            пишется словом `null` или `~` (добавлено пилотом JSON Schema)
    int:    десятичные цифры, со знаком; `010` — десять; `0x10`, `0o7`, `1_000`, `1:30` — слова;
            по модулю не больше 2^53 − 1; больше — текст читается как целое, отказ `refused:value` на шаге 4;
            в месте, где норма ждёт целое, запись float (`4.0`, `4.`, `4e0`, `4E0`, `4e+0`, `1e2`) — `refused:value`,
            даже если значение целое (добавлено пилотом JSON Schema)
    float:  десятичная запись с точкой или показателем: `1.5`, `1e308`, `.5`, `4.`, `4.0`, `4e0`; `.inf`/`.nan`
            распознаются как float, но отказываются на шаге значений Н3
    string: всё остальное; слово в кавычках — слово, даже если похоже на число; одиночный `-` и `-x` в значении
            (`unit: -`) — слова; простое слово с `?` в начале (`?x`) — отказ `text`, ключом и значением (добавлено пилотом JSON Schema)
    escape: в двойных кавычках — только `\\` `\"` `\/` `\t` `\<TAB>` `\n` `\r` `\<пробел>` `\_` (U+00A0) `\xXX` `\uXXXX`
            `\UXXXXXXXX`; знак результата подчиняется encoding (`\x07`, `\u0000`, `\u2028` — отказ); результат — скалярное
            значение Unicode: суррогат D800–DFFF (`\ud800`, `\U0000d800`, и парой `\ud83d\ude00` — YAML пары не
            склеивает, знак вне BMP пишется `\UXXXXXXXX`) — отказ `text` (добавлено пилотом JSON Schema); `\0` `\a` `\b` `\v` `\f`
            `\e` `\N` `\L` `\P` и незнакомое (`\q`) — отказ; в одинарных кавычках экранирований нет, кроме `''`
  blocks:   отображения и списки отступом; элемент списка `-` с любым числом пробелов до содержимого (`-   key: v` —
            элемент-отображение, его ключи — с колонки содержимого); список без отступа под своим ключом (`key:` и
            `- a` с одной колонки) допустим; потоковые `{a: b}` и `[a, b]` в одну строку; блочные скаляры `|` и `>`
            (с `-` или `+`): отступ тела — по первой непустой строке, непустая строка мельче — отказ, TAB после
            отступа — содержимое; простое слово, перенесённое на строки глубже своего ключа: строки склеиваются
            одним пробелом, пустая строка внутри — переводом строки (`\n`, как свёртка YAML); строка продолжения с `: `
            внутри, с `:` в конце, с комментарием (` #` внутри) или начинающаяся с `[`, `{`, кавычки, `&`, `*`, `!`, `|`, `>`
            (они открыли бы иную конструкцию; `]`, `}`, `-`, `?`, `,` ничего не открывают и склеиваются как знаки
            слова), как и продолжение после комментария в первой строке, — строка, не отнесённая ни к какому ключу
            (отказ); строка, начинающаяся с `#` после отступа любой глубины, — комментарий (comment): она завершает
            простое слово, не отказ (добавлено опытом слоя текста); значение ключа на следующей строке — только блочное (отображение
            или список отступом): простое слово, слово в кавычках или потоковая `{…}`/`[…]` под ключом с пустым
            значением — тоже строка, не отнесённая ни к какому ключу, отказ `text` (добавлено пилотом JSON Schema);
            так же скаляр на строке ниже голого `-` элемента списка — отказ `text` (отображение или список ниже `-`
            допустимы) (добавлено опытом слоя текста)
```

Что одна библиотека YAML читает, а другая нет — потоковая коллекция на несколько строк, строка в кавычках на несколько строк, явный указатель отступа (`|2`), сложный ключ (`? …`) — отказывается словами, а не читается «как получится».

Числа float в принятой спеке конечны и по модулю не больше `1.7976931348623157e308` — после прочтения в binary64:
запись, которая округляется до этого числа (`1.7976931348623158e308`), принимается; запись ненулевого числа, которая
читается нулём (потеря значимости, `1e-400`), — `refused:value` (добавлено опытом слоя текста).
NaN, обе бесконечности (в любом допускаемом YAML написании) и переполнение этого диапазона —
`refused:value` с путём значения на шаге 4; они не превращаются в строку или null.
Это правило действует во всём документе, включая default/inherit и вложенные числа JSON/opaque.
Непрозрачность отменяет проверку имён внутренних ключей, но не общие требования к числам и JSON.

### Н1.2 Документ

Корень — отображение с закрытым набором разделов. Незнакомый ключ на любом уровне — отказ (Н4). Раздел, отсутствующий в файле, значит умолчание своего урока, если оно определено. Обязательны без умолчаний `name`, отображение `unit` с явно заданными `unit.rows` и `unit.id`, а также `placement.capacity.default`. Отсутствие любого из них — `refused:value` с путём отсутствующего значения; null не заменяет отображение/строку. `unit.fields` без объявления — пустое отображение. Профиль подсистемы без единиц не входит в эту главу; rows и numeric/named не выбираются загрузчиком за автора.

```yaml
spec:
  name:        # ДОЛЖЕН: строка по грамматике ^[a-z][a-z0-9_-]{0,31}$; не из зарезервированных:
               #   platform, spec (хранилище, урок P/02); policy, drain, servers, where, unplaceable (двери, добавлено М10/4);
               #   console, audit (деревья событий), events, marks, requests, asked (двери; добавлено М10/8);
               #   session, mounts, healthz, metrics, resources (двери, добавлено М10/9); schema (дверь, добавлено М10/10);
               #   domain, api (пути домена, М11); имя — первый
               #   сегмент всех ключей подсистемы `<name>/…` и её места на домене
  unit:        # ДОЛЖЕН: отображение с обязательными rows и id; fields по умолчанию {}; грамматика поля Н1.3; смысл — урок 3
  placement:   # размещение — урок 4; здесь: capacity.default ДОЛЖЕН быть целым ≥ 0; unplaced.delete_after —
               #   целое ≥ 1, только с named id (не numeric), без fixed-полей кроме id и about только по id (ADR-0067)
  tables:      # таблицы подсистемы — урок 10; поле таблицы по Н1.3 без fixed, inherit, merge, unique
  requests:    # просьбы — урок 8
  holds:       # удержания — урок 8
  events:      # события — урок 8
  about:       # родитель единицы {sub, field} — урок 8 Н1.2; field — поле с fixed: true (урок 3)
  snapshot:    # поля, уходящие из кластера — урок 10; отсутствует = все, кроме секретов, blob и авторского server;
               #   `snapshot:` без значения — отказ; секрет, blob и server в списке — отказ
  rights:      # права — урок 6
  secrets:     # секреты — урок 7
  worker:      # что пишет, читает и просит воркер — уроки 5 и 6
  slot:        # слот — урок 3
  lease:       # аренда — урок 3; форма: {unconfirmed_max: forever | off | <целое ≥ 1>} и ничего иного;
               #   `lease:` без значения, с иным ключом, `0`, строка, дробь, булево — отказ
  heartbeat:   # слова биения — урок 5; `worker` — слово платформы, объявлять нельзя
  objects:     # семьи объектов — урок 8; rows не называет платформенную семью
  door:        # двери воркера — урок 9; routes — каждый маршрут один раз
  servers:     # страница серверов — урок 9; status[].of называет таблицу этой спеки
  display:     # слова консоли — урок 9; закрыт по разделам, внутри словарей — строки
  console:     # {running: <метрика этой спеки>} — урок 9
  metrics:     # метрики — урок 9 (/metrics)
  domain:      # вклад в домен — М11
closed_key_set:
  rule: на каждом уровне допустимы только ключи, которые читает платформа: на верхнем уровне и в заголовках разделов — Н1.2
        этой главы, внутри разделов — сводная таблица Н1.2а; ключ вне неё — отказ. Уроки-владельцы дают смысл ключей
        и на форму ссылаются сюда
  named:   # уровни, где ключи — имена автора (поля, таблицы, виды токенов, книги, виды, слова опций):
    [unit.fields, tables, tables.*.fields, display.keys, display.options, display.kinds,
     display.fields, display.field_help, domain.books, domain.names, domain.tokens, events.suppress, secrets.readers,
     *.schemes]
  opaque:  # уровни, где шаг 3 не проверяет набор ключей (содержимое — другой стандарт или другой урок);
           # ссылки Н1.4 на ключи и значения этих уровней проверяются:
    [*.schema (JSON Schema: имена свойств не проверяются, но ключевые слова — только из перечня урока 3 Н1.2;
     иное ключевое слово — refused:value на шаге 4), unit.fields.*.default и inherit при type json, ключи *.must_match, metrics.where,
     metrics.unless.where, metrics.labels, placement.near.prefer, placement.affinity.strict, placement.places.where,
     rights.unit_of, display.options.*]
```

Грамматика имён `unit.rows` и таблиц и один перечень запрещённых имён — в Н1.2а. Область named не отменяет
эту грамматику; остальные авторские имена ею автоматически не ограничиваются.

### Н1.2а Сводная таблица ключей

Одно место формы ключей спеки: ключ → тип и границы → обязательность и умолчание → урок, где ключ получает смысл.
Уроки-владельцы дают смысл и ссылаются сюда; при расхождении формы права эта таблица. Общие правила:
ключ вне таблицы — `refused:key`, кроме уровней внутри `domain.*`: там класс любого отказа, и незнакомого ключа, задаёт
урок М11 этого раздела (книга — `value`, Н1.2б; имя — `reference`, М11/9 Н1.7; общий документ — `value`, Н1.2б);
сказанный ключ без значения — `refused:value` (и `default:` без значения: явный
`null` — «нет умолчания», пустое значение — не сказанное; c4_default_without_value); null не заменяет отображение
или строку; числа — по Н1.1 и внутри opaque. «named» — ключи уровня суть имена автора; «opaque» — шаг 3 не
проверяет набор ключей, но ссылки Н1.4 на ключи и значения этого уровня проверяются. «Слово: a, b» — строка
из закрытого перечня, иное — `refused:value`. «Поле» — поле единицы, а у ключа таблицы — поле этой таблицы.

**Верх и `unit`**

| Ключ | Тип и границы | Обязательность / умолчание | Смысл |
|---|---|---|---|
| `name` | строка `^[a-z][a-z0-9_-]{0,31}$`, не из 21 зарезервированного слова Н1.2 | обязателен | 2.1 Н1.2 |
| `unit` | отображение `{rows, id, fields}` | обязателен | 3 Н1.1 |
| `unit.rows` | имя: 1–32 ASCII, первая a-z, далее a-z, 0-9, `_`, `-`; не из перечня запрещённых имён (ниже) | обязателен | 3 Н1.1 |
| `unit.id` | `numeric` или имя несекретного поля типа string (Н1.4) | обязателен | 3 Н1.3 |
| `unit.fields` | отображение, named; имя — строковый ключ YAML, не из `platform_fields` урока 3 | нет — `{}` | 3 Н1.2 |

**Поле** — `unit.fields.<имя>.*` и `tables.<т>.fields.<имя>.*` (Н1.3; у поля таблицы нет `fixed`, `inherit`,
`merge`, `unique` — `refused:key`)

| Ключ | Тип и границы | Обязательность / умолчание | Смысл |
|---|---|---|---|
| `type` | слово: `string`, `int`, `float`, `bool`, `list`, `json`, `url`, `blob`; поле `*_secret` — только string | нет — `string` | 3 Н1.2 |
| `required` | bool; у blob `true` запрещён | нет — `false` | 3 Н3 |
| `fixed` | bool; только у поля единицы | нет — `false` | 3 Н1.3 |
| `default` | одно значение типа поля; у float допустимо целое; list — список строк; json — любое JSON (opaque); null — нет умолчания; из `enum`, если он есть; не вместе с `inherit`; у blob запрещён | необязателен | 3 Н1.2 |
| `inherit` | как `default`, в том числе из `enum`, если он есть; только у поля единицы | необязателен | 3 Н1.2 |

```yaml
    from:  <sub>/<строка> — одиночная строка, или <sub>/<строка>/ — семья строк под слотами (<sub>/<строка>/<слот>);
           <sub> — своя подсистема, <строка> — один сегмент по грамматике имени Н1.2; иное — отказ
    key:   имя несекретного поля входа: значение — непустая строка, ключ книги
    pick:  unique | all
    to:    имя несекретного поля входа, не key: член или список членов — получатели элемента
    show?: [<поле входа>…] — что видит дверь (М11/5 Н2); непусто, без повторов, без *_secret
refusals:                     # отказ загрузки refused:value с путём (Н4)
  - from, key, pick, to — не все четыре вместе; key/pick/to без from
  - from — чужая подсистема, не один сегмент, `..`, URL; key или to — секрет или не имя; to = key; pick вне перечня
  - show — пусто, повтор, секрет; неизвестный ключ в объявлении
  - книга и строка kept одного имени (одна строка — один писатель, одна форма)
```

### Н1.3 Поле

Грамматика поля единицы (`unit.fields.<имя>`) и поля таблицы (`tables.<т>.fields.<имя>`). Смысл поля в строке — урок 3 Н1.2, в форме — урок 9 Н1.2 (`display.form`), в домене — М11; здесь — что проверяет загрузчик.

```yaml
field:
  type:       string | int | float | bool | list | json | url | blob      # закрыто; отсутствует = string
  required:   bool                        # только true/false; `yes`, `"true"` — отказ
  fixed:      bool                        # только у поля единицы
  # list — список строк; произвольные значения/структуры принадлежат типу json
  default:    одно значение типа поля     # json — любое значение JSON; отображение у string — отказ
  inherit:    одно значение типа поля     # только у поля единицы; последнее звено цепи наследования
  merge:      union | override            # только у поля единицы и только с inherit; union — только у type: list (Н1.2а)
  enum:       [значения типа поля]        # только у string (строки) и bool (true/false); у int, float, list, json, url, blob — отказ (как Н1.2а; добавлено пилотом варианта C, П5); default ДОЛЖЕН быть из enum
  unique:     true | canonical            # только у поля единицы; canonical — сравнение по канонической форме URL (урок 3 Н1.3)
  ref, bound_to, must_match, schema, schemes, credentials, secret_in:   # формы: ref, must_match — урок 3 Н1.3; schema — урок 3 Н1.2,
                                                                        #   глубина — урок 10 Н1.4; bound_to, credentials, secret_in, schemes — урок 7 Н1.1
rules:
  - unit.fields не объявляет id, revision, deleted, worker, placement, epoch, phase, observed_revision (platform_fields М10/3); refused:value с путём unit.fields.<имя> до проверки/материализации значения, включая default/inherit; запрет не переносится на поля таблицы
  - default и inherit на одном поле — отказ
  - поле таблицы с fixed, inherit, merge или unique — refused:key: этих ключей нет в наборе поля таблицы (шаг 3)
  - blob допустим только в unit.fields; имя — 1–64 ASCII, первый A-Z/a-z/_, остальные A-Z/a-z/0-9/_; пустое/непредставимое имя и blob в таблице — refused:value с путём поля (дверь байтов PUT /<rows>/<id>/<blob_field>, М10/10 Н1.5)
  - blob с required: true, с default или с inherit — отказ (дайджест приходит дверью байтов PUT /<rows>/<id>/<blob_field> после создания единицы, урок 10 Н3 «положить_тело»; при создании поле всегда ""; умолчание или наследование писали бы дайджест в строку мимо неё)
  - unit.fields.bytes при наличии любого unit-поля type: blob — отказ загрузки refused:value (поле bytes ответа BlobWritten двери байтов, М10/10 Н1.5); без blob обычное поле bytes допустимо
  - snapshot не включает поле server: нет snapshot — server исключается вместе с секретами/blob; явно названный server — отказ загрузки refused:value (М10/10 Н1.3)
  - таблица: held_by/garbled/by/at/made_at запрещены как поля (вычисляемые значения и штампы, независимо от наличия stamp); name допустимо только с типом string (явным или по умолчанию) и key: name (М10/10 Н1.6), иначе refused:value
  - имя поля unit.fields и tables.*.fields — только строковый ключ YAML; простой ключ не строкой по Н1.1 scalars (числовой, bool, null) — refused:text по Н1.1 keys, как везде, в том числе у ключей значений json и display.options (изменено 2026-10-18); преобразование имени в строку запрещено
  - значение поля в строке хранилища — урок 3 Н1.2 (<sub>/<rows>/<id>)
```

## Н2 Двери

У загрузчика две двери: процедура загрузки, которой пользуются все процессы и установщик, и `GET /spec` консоли, которым
модуль консоли (урок 9) узнаёт форму подсистемы; вторая — временно в [М10/9](../../../М10_Platform/spec/09-the-console.norms.md)
Н2 «GET /spec» (до переноса урока 6, глава 6.5).

### Процедура загрузки

Не HTTP: вход реализации, который получает байты и имя источника и отвечает спекой или отказом. Все пути чтения спеки — файл, строка хранилища, встроенная спека — ДОЛЖНЫ проходить через неё.

```
загрузить(байты, источник) → спека | отказ(источник, путь_ключей, причина)
загрузить_каталог([спека…])  → каталог | отказ(источник, путь_ключей, причина)     # проверки между спеками
```

## Н3 Проход

### загрузить(байты, источник) → спека | отказ

```
1. текст:    прочитать байты как подмножество YAML (Н1.1)              → иначе отказ(источник, путь, строка файла)
             корень — отображение                                       → иначе отказ
2. имя:      name есть, по грамматике, не зарезервировано (Н1.2)        → иначе отказ(источник, "name")
3. ключи:    обойти документ как написан; каждый ключ на каждом уровне из закрытого набора своего места;
             в named — любые имена, в opaque — не заглядывать (Н1.2)    → иначе отказ со всеми путями, которых нет
4. значения: все числа конечны и в диапазоне Н1.1, в том числе в opaque;
             раздел за разделом: типы, грамматика поля (Н1.3), слова из закрытых перечней, обязательные ключи
             (capacity.default)                                          → иначе отказ(источник, путь, причина)
5. ссылки:   каждая ссылка Н1.4 — на объявленное в этой спеке          → иначе отказ(источник, путь, причина)
6. умолчания: заполнить отсутствующее умолчаниями уроков-владельцев; ослабляющие — только сказанные (Н1.2 lease,
             unplaced, places)
→ спека
```

Порядок шагов 1–5 нормативен: до проверки значений завершена проверка всех ключей; незнакомый ключ отказывается раньше, чем неверное значение в соседнем; значения (шаг 4) проверяются раньше ссылок (шаг 5) — спека с отказом значения отказывается классом `value`, даже если неверна и ссылка (добавлено корпусом главы 2.1). Порядок внутри шагов 4–5 — решает реализация.

**Гонки.** Нет: загрузка чистая, без состояния и без хранилища.

### загрузить_каталог([спека…]) → каталог | отказ

Проверки, которым нужна не одна спека: `worker.requests` называет подсистему каталога, принимающую просьбы; `placement.near.sub` называет подсистему каталога, а `near.of` и `near.prefer` — её поля; `metrics.prefix` двух подсистем не совпадает (`GET /spec`, М10/9 Н2). Каталог — все спеки кластера (все строки `platform/spec/*`); отказ одной спеки каталога — отказ каталога. Для любых подсистем A и B, включая A=B, имя B не совпадает с unit.rows или именем любой таблицы A, включая списковые tables. Иначе refused:catalogue с именами обеих спек и конфликтующей семьёй, до выдачи каталога/первой записи установщика; это исключает пересечение root-двери и mount при любом выборе root.

**Гонки.** Проверка каталога получает готовый набор загруженных спек; две проверки не меняют входы друг друга.
Чтение источников до неё не обещает атомарного снимка всех файлов или строк. Если файл меняется во время чтения,
могут быть получены прежние, новые либо смешанные байты: допустимый документ загружается, недопустимый даёт отказ
по Н1. Сам факт изменения файла чистая процедура по байтам не обнаруживает. Неразрешённая связь между принятыми
спеками даёт отказ каталога; при любом таком отказе частичный каталог не выдаётся.

Строку спеки, старт процесса и смену спеки задаёт [глава 2.3](02.3-installer.norms.md) Н3.

## Н4 Отказы

Закрытый список. У загрузчика один вид ответа «не спека» — отказ в словах, называющий источник (файл или ключ хранилища) и путь ключей; классы ниже различают причину для читателя и приёмки, не код.

Диагностика (сверка python и go 2026-10-18): путь — до самого глубокого ключа с неверным значением; индекс списка в пути —
число; строка — строка этого ключа; отсутствующий ключ — путь с его именем и строка объемлющего отображения; повтор
ключа — путь повторного ключа и строка второго объявления; ошибка кодировки — строка байта, без пути; отказ слоя текста —
строка виновного знака или конструкции (маркер, открывающая кавычка, незакрытый поток, строка без ключа), не
следующая и не конец файла (добавлено опытом слоя текста). У правила на два
ключа путь — ключ, который правило запрещает рядом с другим: `merge: union` у поля не `list` — `…fields.<поле>.merge`;
`bytes` рядом с blob — `unit.fields.bytes`; поле `name` таблицы не по форме — `tables.<т>.fields.name`; `delete_after`
при `numeric` id — `placement.unplaced.delete_after` (добавлено пилотом JSON Schema). У правил на присутствие путь —
«A запрещён без B» — сам A (`merge` без `inherit`, `must_match` без `ref`, `login` без `param`, `in` без `regex`); «A требует
B» — недостающий B (`per_person` и `free: true` → `ttl`, `free: false` → `valid_for`, `most_valid`; `from` → `key`, `pick`,
`to`) (добавлено пилотом варианта C, П4). ## Решает реализация

Реализация обязана назвать в своём описании:

1. **как реализация держит сводную таблицу Н1.2а** для шага 3 прохода (таблица в коде или данных); сама таблица — норма, не выбор;
2. **сколько ошибок значений называет один отказ** (первую или все); незнакомые ключи называются все — норма Н3 шага 3, не выбор;
3. **команду загрузки одного файла для приёмки** по разделу «Стенд» общего README приёмки: раннер вызывает её на каждом файле `verdicts.tsv`; код выхода 0 — спека, иной — отказ, текст отказа называет файл.
