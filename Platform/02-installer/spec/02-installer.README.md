# P/02 — инструкция для реализации

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — [`../02-installer.md`](../02-installer.md).

## Задача

Реализовать установщик урока P/02 на языке `<LANG>` по четырём главам: строгую загрузку манифеста и каталога манифестов (глава 2.1),
чтение и смену манифеста в хранилище (глава 2.3), юниты, раннер, установщик и операторские процедуры (глава 2.4), генерацию
прав из каталога манифестов (глава 2.5). Пройти приёмку Н5 глав и закрыть их чеклисты готовности.

- **2.1.** Реализовать строгую загрузку манифеста и каталога манифестов по Н1–Н4 [главы 2.1](02.1-installer.norms.md). Пройти
  приёмку Н5 штатным путём загрузки и закрыть весь [чеклист готовности](02.1-installer.norms.md#чеклист-готовности).
  Основной вход главы — процедура `загрузить(байты, источник)`, не HTTP-дверь.
- **2.2.** Канонический вид манифеста по [главе 2.2](02.2-installer.norms.md): проекция Н1.1 (сахар, умолчания, шаги П1–П5,
  `ordered`, JCS), строка вида Н1.2 и запись `manifest put` по Н3 — вид до записи, больше потолка — отказ целиком, порядок
  строка — вид — метка. Пройти векторы [`canonical`](../vectors/canonical/README.md) байт в байт и приёмку главы
  [`acceptance/2/`](../acceptance/2/README.md) (окно 2.2, п. 8: векторы и приёмка).
- **2.3.** Чтение и смену манифеста в хранилище по Н1.5 и Н3 [главы 2.3](02.3-installer.norms.md); закрыть её
  [чеклист готовности](02.3-installer.norms.md#чеклист-готовности).
- **2.4.** Подготовить процессы/юниты, раннер, установщик и операторские процедуры Н1 [главы 2.4](02.4-installer.norms.md).
- **2.5.** Генерировать права из каталога манифестов по [главе 2.5](02.5-installer.norms.md). Оценщик прав, форма файла и дверь
  `/v1/rights` — глава [P/01.2](../../01-store/spec/01.2-store.norms.md) и её шаги инструкции
  [01-store.README.md](../../01-store/spec/01-store.README.md). Настройка пользователя, групп, сокетов и сертификатов
  связана с главой 2.4: юниты Н1.1 (`User=`, `SupplementaryGroups=`), сокеты — P/01.3 Н1.3 `sockets`, комплект Н1.6 `kit` и
  выпуск `w2c-ca.sh`.

Своего HTTP-контракта у урока нет: дверь `GET /manifest` и форма `ManifestView` — у главы P/06.5
([нормы](../../06-console/spec/06.5-console.norms.md), [инструкция](../../06-console/spec/06-console.README.md), [контракт](../../06-console/spec/06-console.api.openapi.yaml)).

## Что создать

Обязательное поведение — в каноне. Внутренние типы, функции, устройство ошибок и выбор библиотек остаются
реализации; названия процедур в Н2–Н3 обозначают их смысл, а не обязательные сигнатуры конкретного языка.

Глава 2.1:

1. **Загрузку одного манифеста** из байтов с именем источника: проверка текста, имени, ключей, значений и ссылок,
   затем заполнение умолчаний в порядке Н3. Результат — целый манифест либо отказ с нужными сведениями по Н4. После проверки ключей отказать NaN, бесконечности и переполнению float, включая вложенные числа opaque/default/inherit; все принятые значения представимы JSON.
2. **Загрузку каталога** с проверками `worker.requests` и `placement.near` по Н3. Приёмка одного файла
   не подменяет проверку каталога; в раннер таблицы не добавляются не названные ею соседние манифесты.
3. **Прогон общей таблицы** штатным путём загрузки согласно README приёмки. Выборку README приёмки (все `ok` и по отказу
   на класс) СЛЕДУЕТ прогнать через установку манифеста (`manifest put`, глава 2.3), как указано в Н5
   и P/02.1-12.

Глава 2.3:

4. **Чтение и установку манифеста в хранилище** по Н1.5 и Н3: первая строка с `rev: 1` и `cas: ""`, метка,
   дайджест, растущая ревизия, запись с `cas`, доведение метки, старт и остановка процессов.
   Неверный файл не устанавливается. При `toolarge` основной строки команда заканчивается кодом 2
   с диагностикой Н4 и не переходит к метке; при подсчёте веса учитываются исходные байты YAML и страница,
   а не только разобранные значения. Период обнаружения смены отсчитывается от публикации метки.

Глава 2.4:

5. Описанные Н1 службы и unit-файлы, группы, каталоги, права, сокеты и конфигурацию установки.
6. Раннер и установщик с проверками до записи и диагностикой частичного результата при отказе.

Глава 2.5:

7. Генератор и проверку `--check`; исполнитель сценариев под разными ролями. Механизм выдачи сертификатов и генератор
   юнитов — глава 2.4.

Всем главам:

8. **Описание реализации** с ответами на 23 пункта «Решает реализация» (2.1 — четыре, 2.2 — два, 2.3 — пять, 2.4 — восемь, 2.5 —
   четыре; зачёркнутые пункты уже нормированы — ответ ссылкой) и указателями для тех пунктов чеклиста, которые
   проверяются чтением.

## Порядок работы

Это возможный порядок, а не дополнительная норма об устройстве кода.

### Главы 2.1 и 2.3 — манифест

1. *(2.1)* Прочитать нормы целиком. Выписать границы закрытых, именованных и непрозрачных уровней из Н1.2,
   их уроки-владельцы и выборы реализации. Проверить обязательные unit/rows/id: загрузчик не придумывает семью или вид id; отсутствие unit.fields означает пустое отображение.
2. *(2.1)* Настроить чтение байтов и разбор текста по Н1.1: парсер YAML 1.2 закреплённой версии и тонкая проверка слоя 1
   ([слои В7](../../common/LAYERS.md) § 4, обходы D13, D16). Проверки, которым нужен исходный текст или список ключей до
   превращения в отображение, выполнить до потери этих сведений библиотекой; один документ — по байтам.
3. *(2.1)* Выполнить проход загрузки Н3 по слоям: текст → форма (схема JSON Schema 2020-12 и слова `x-*`, целое место —
   слой 2) → связи (CEL, только при чистой форме). Заполнение умолчаний не скрывает ошибочный вход.
4. *(2.1)* Прогнать `verdicts.tsv`: один файл — одна загрузка. Сверить множество файлов с таблицей;
   отказ засчитывать по правилам README, а не по любому исключению или ненулевому коду процесса.
   Сравнить класс `classes.tsv`; пути и строки `diagnostics.tsv` — подсказка в отчёт без провала (ADR-0092 п. 5).
5. *(2.1 — каталог; 2.3 — хранение и смена)* Проверить каталог, затем хранение и смену манифеста: повтор установки без изменений, конфликт `cas`,
   отставшая и отсутствующая метка, все причины отказа старта Н4 (включая неподтверждённое чтение строки/метки и несовпадение встроенного манифеста), старт между двумя записями установщика, `toolarge` основной строки
   до записи метки. Для каталога не приписывать чтению атомарный снимок или обязательный отказ при любом
   изменении файла: проверяются фактически полученные байты и связи. Предметы проверки — Н3, Н5 и чеклист.

### Глава 2.4 — установщик

1. Сопоставить роли, группы, каталоги, права, сокеты и окружение каждой строке Н1.1–Н1.2. Проверить приоритет значений и отсутствие source для данных; After не считать готовностью (Н3).
2. Спроектировать предварительную проверку и точки записи установщика. Принудительно отказать на каждой фазе: до записи нет изменений, после начала допускается частичный результат с диагностикой и без enable/start новых служб (Н1.7).
3. Проверить скрипт воркеров по заказу: бюджеты, резервирование до start, номера 2…99 (старт наименьшего, стоп наибольшего), ряда нет — ничего, неизвестный исход запуска и устаревшую консоль, polkit start/stop полных имён своего сервера (ADR-0084). Сертификаты — отдельная тестовая CA, отзыв до вывода о полном отсечении (Н1.5–Н1.6).
4. Сертификат роли (SAN URI `urn:w2c:role:<роль>`, CN `<роль>.<сервер>`, ключ 0640 root:<группа пользователя юнита>) и
   правило адреса (демон вне петли — только с TLS; дверь процесса без комплекта — петля; signer и relay — по явному
   адресу с громкой строкой лога, на умолчании процесса `0.0.0.0` — отказ старта, код 2; resource без комплекта — только петля, ADR-0075 доп. 2026-10-26 (6) п. 2; ADR-0075 доп. 2026-10-26 (5) п. 4) подтвердить структурным тестом юнитов и тестами центра (Н5) либо
   явно оставить без свидетельства исполнения: стенда с TLS в приёмке нет, проверяется чтением ([системный стенд](../../common/acceptance/system/README.md)).

### Глава 2.5 — вывод прав

1. Зафиксировать набор манифестов и развёртывание на время генерации/установки. Сверить
   производные имена ролей с P/01.2 Н1.1: ограничение имени манифеста уже обеспечивает их длину.
2. Вывести таблицу Н1.4 по манифесту, затем применить читателей секретов из Н1.3 (`secrets.readers`, `secrets.reads`, `platform_readers`).
   Проверить точное имя против префикса и эффективное множество читателей, а не
   только присутствие строки в списке. До преобразования отвергать буквальный * и начальные !/delete: в объявлениях; не менять ключ. Проверить соседние vault, vault2, vault/nested: точное объявление vault не меняет их обычных прав. Поле delete генератор выдаёт явно.
3. Проверить две строки допуска контроллера по Н5: read/write разрешены, delete
   запрещён; остальные разрешённые удаления не исчезли. Сверить обе стороны
   boundary консоль/контроллер/воркер, не меняя протокол размещения [P/04](../../04-controller/spec/04-controller.norms.md).
4. Подготовить стенд по README приёмки: отдельный экземпляр для каждого сценария,
   пустые данные и память повторов, тот же файл прав, фоновые писатели остановлены.
   Выполнить все шаги.
5. Проверить все пункты канонического чеклиста. Сокеты, права файлов, TLS и сертификаты
   подтвердить структурным тестом юнитов и тестами центра (глава 2.4 Н5) либо явно оставить без свидетельства
   исполнения: стенда с TLS в приёмке нет, проверяется чтением ([системный стенд](../../common/acceptance/system/README.md)).

Всем главам: завершить описание реализации и чеклисты; проверку таблицы не объявлять проверкой всего жизненного цикла манифеста.

## Ловушки, которые зависят от языка и библиотеки

| Норма | Ловушка | Как проверить |
|---|---|---|
| текст по Н1.1 (2.1) | YAML-библиотека принимает больше конструкций, чем разрешено уроком, или знает свои дефекты | правила тонкой проверки Н1.1 по одному; обходы и случаи дефектов — `LAYERS.md` § 4, перечень дефектов навыка `lesson-spec`; пакет `yaml-suite` |
| повторные ключи запрещены (2.1 Н1.1) | библиотека уже заменила первое значение последним | обнаруживать повторы до потери пар ключ–значение, включая потоковые отображения |
| скаляры по Н1.1 (2.1) | `Off` стал булевым, `010` восьмеричным, а строка в кавычках — числом | сверять вид исходного скаляра с правилами Н1.1; не приводить строку к числу по ожиданию поля |
| целое — не булево (2.1 Н1.2, Н1.3) | язык или приведение считает `true` единицей | различать JSON/YAML-типы до числовой проверки |
| предел целого 2^53 − 1 (2.1 Н1.1) | преобразование в число с плавающей точкой уже округлило вход | проверять точное значение целого до преобразования, которое может потерять разряды |
| отсутствие и сказанный ключ без значения различаются (2.1 Н1.2) | `null`, пустое отображение и отсутствие сведены к одному умолчанию | сохранять различие и применять правило конкретного раздела |
| именованные и непрозрачные уровни (2.1 Н1.2) | один обход либо запрещает имена автора, либо пропускает незнакомые ключи поля | менять способ проверки только на уровнях из перечней Н1.2 |
| незнакомые ключи раньше значений (2.1 Н3) | декодирование в типизированную структуру останавливается на первом неверном значении | сначала завершить проверку ключей и собрать все неизвестные пути |
| `blob` без `required: true`, `default`, `inherit` (2.1 Н1.3) | общее описание поля допускает свойства, запрещённые этому типу | применить ограничения типа после проверки общей формы поля |
| дайджест исходных байтов (2.3 Н1.5, Н3) | YAML разобран и записан заново перед вычислением SHA-256 | вычислять дайджест байтов `yaml`, хранящихся как есть |
| метка после строки, только вверх (2.3 Н3) | задержавшийся установщик записывает старую ревизию поверх новой; период чтения ошибочно считают от записи строки | следовать проверкам ревизии и `cas`; ветка «без изменений» тоже доводит метку; после обрыва установки это зависит от следующего `manifest put`, срок которого не задан |
| скрипт воркеров (2.4 Н1.5) | NaN, ноль делителя или два прохода обходят бюджет | Проверять конечность/диапазон до деления, сериализовать резервирование запуска. |
| читатели секретов (2.5 Н1.3) | Точное имя секрета трактуют как префикс | Префикс только с конечным `/`; сверить эффективных читателей с Н1.4 |

## Готово, когда

- [ ] *(2.1)* Все 680 файлов дают вердикт из таблицы: 141 `ok`, 539 `refused`; множества файлов и случаев совпадают.
- [ ] *(2.3)* Все 7 установок `puts.tsv` дают код и rev из таблицы.

## При расхождении кода и норм

| Ситуация | Действие |
|---|---|
| Вердикт не совпал, норма однозначна | исправить загрузчик или его штатный путь, затем повторить случай |
| Таблица противоречит норме | передать автору норм дефект приёмки; не менять вердикт ради зелёного прогона |
| Норма неполна или противоречива | описать вопрос с входным файлом и ссылкой на раздел; согласовать правку канона |
| Исход прав расходится с нормой | сопоставить вход и исход с Н1–Н4 главы 2.5, затем с файлом приёмки; сообщить «Спецификации» место, контрпример и предлагаемое решение |
| После исправления ИИ выявлено повторяющееся неверное толкование | записать образец и уточнение в `corrections.tsv` своей главы по ADR-0080 |
