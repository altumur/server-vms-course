## N1 Форма

**Время.** Полей времени у строки вида нет.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `platform/manifest/<sub>/canonical/<form>`.

### N1.1 Проекция

Канонический вид манифеста — байты JCS значения, которое
получается из дерева принятого манифеста (загрузчик главы 2.1, вердикт `ok`) по правилам ниже, по порядку. Вид зависит только от байтов манифеста и стандартных файлов главы 2.1 (схема
`02.1-installer.schema.json`, таблица слоёв `02.1-installer.layers.tsv`).

```yaml
sugar:                       # до умолчаний
  tables:   "[a, b] → {a: {}, b: {}}"
  bound_to: '"x" → ["x"]'
  in:       '"query" → ["query"]'
defaults:   default          # аннотация схемы главы 2.1
computed:                    # после умолчаний
  P1 snapshot:            [<unit.fields>, state.<name>]
  P2 tables.<t>.journal:  {written: "<t>.written", deleted: "<t>.deleted"}
  P3 display.form:        [{fields: [<имена unit.fields>]}]
  P4 descriptor default:  null
  P5 decoded:             true
not:        [events.suppress.<kind>.by, display.section, display.general]
ordered:    x-ordered        # пометка таблицы слоёв
scalars:    [integer, string, boolean]
notes:      []
```

`sugar` — закрытый перечень приведений к одной форме, до умолчаний. `sugar.tables`: список имён `[a, b]` становится `{a: {}, b: {}}`. `sugar.bound_to`: у поля единицы и поля таблицы одно имя `"x"` становится `["x"]`. `sugar.in`: у элемента `secret_in` вида regex одно слово `"query"` становится `["query"]`.

`defaults`: каждый ключ с аннотацией `default` схемы главы 2.1 есть явно — только внутри присутствующего родителя
  или родителя со своим default. `defaults`: отсутствующий раздел без default — отсутствует.

- `computed` — закрытый перечень шагов урока 2, после умолчаний.

- `P1 snapshot`: когда ключа `snapshot` нет, его значение — имена `unit.fields` в порядке автора без `*_secret`, без
  `type: blob` и без `server`, затем `state.<name>` каждого `unit.state`, кроме `cursor`, в порядке автора; сказанный
  `[]` остаётся `[]`.

- `P2 tables.<t>.journal`: когда его нет, он — `{written: "<t>.written", deleted: "<t>.deleted"}`; когда дан один
  ключ, второй вычисляется так же.

- `P3 display.form`: когда его нет, он — `[{fields: [...]}]` с именами `unit.fields` в порядке автора, без `title`.

- `P4 descriptor default`: у поля единицы и поля таблицы `default` описателя — сказанное значение; когда он не сказан
  или сказан `inherit` — `null` (у всех типов, включая `blob`).

- `P5 decoded`: у элемента `secret_in` вида regex без `decoded` значение `decoded` — `true` (P/06.2 N1.1).

- `not`: не подставляются `events.suppress.<kind>.by`, `display.section`, `display.general` и ключи без аннотации
  `default` в схеме.

`ordered`: отображения с пометкой `x-ordered` таблицы слоёв (`unit.fields`, `tables.<t>.fields`) — массив
  `{"name": <key>, …value}` в порядке автора. `ordered`: прочие отображения — объекты; их порядок — JCS. `ordered`: читатель на порядок автора вне `ordered` не опирается.

- `scalars`: значения JSON — по типу места схемы (integer — число, целое место — целое после приведения слоя 2:
  `4.0` → `4`; string — строка, boolean — `true`/`false`).

- `notes`: комментариев, исходного текста и пометок `x-*` в виде нет.

### N1.2 Строка вида

```yaml
platform/manifest/<sub>/canonical/<form>:   # строка вида
  form:     decimal integer  # номер формы вида
  rev:      rev              # строки манифеста platform/manifest/<sub>
  sha256:   sha256           # строки манифеста (её поле sha256)
  manifest: text             # байты вида (N1.1)
ceiling:    max_value        # ответа GET /v1/status
window:     …/canonical/<form + 1>
```

Строка вида — одна на подсистему и форму вида; писатель — установщик (N3). `form` — номер формы вида, десятичное целое ≥ 1; сейчас 1 (ключ `…/canonical/1`). `rev` — rev строки манифеста `platform/manifest/<sub>`, из которой вид построен (глава 2.3 N1.5). `sha256` — sha256 строки манифеста (её поле `sha256`). `manifest` — байты вида (N1.1) текстом — JCS, UTF-8, без перевода строки в конце.

`ceiling`: потолок строки вида — потолок строки хранилища P/01.1 N1 для этого ключа; сумма строки манифеста и вида
  не ограничивается. `ceiling`: его источник — фактический потолок хранилища: `max_value` ответа `GET /v1/status` (P/01.3 N2,
  OpenAPI 01 `StatusResponse`); 524288 — только умолчание флага `-max-value` демона, не константа установщика; своей
  настройки потолка у установщика нет.

`window`: смена формы вида — новая форма рядом (`…/canonical/<form + 1>`). `window`: в окно смены установщик пишет обе формы.

Форма самого `manifest` — схема вида [`02.2-installer.view.schema.json`](../../spec/02.2-installer.view.schema.json) (JSON Schema 2020-12;
пометки `x-step` — шаг проекции, `x-default` — ключ обязателен умолчанием формы, `x-unique-by` — ключ элементов `ordered`;
[слои V7](../../../common/ru/LAYERS.md) § 3). Схема вида закрыта там же, где форма. В схеме вида ключи с `default` обязательны.

- В схеме вида `ordered` — массив с уникальным `name`.

### Форма канонического вида (построена из стандартных файлов)

Значение `manifest` строки `platform/manifest/<sub>/canonical/1` — JSON (JCS, RFC 8785) этой формы: JSON Schema 2020-12 `02.2-installer.view.schema.json`. Отображение без имён автора закрыто: ключа вне таблицы нет. «Есть всегда» — ключ с умолчанием формы манифеста (`default` `02.1-installer.schema.json`) или шагом проекции; «есть, если сказан в манифесте» — ключ без умолчания, его отсутствие и есть значение. Отображение `x-ordered` формы манифеста — список объектов `{name, …}` в порядке автора. Правил и связей формы манифеста здесь нет: принятый манифест проверил установщик.

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи. Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N3 Проход

### построить вид(байты манифеста) → байты | отказ

1. Загрузить байты по главе 2.1. Если загрузка отказала, вернуть этот отказ загрузки (вид не строится).

2. Пусть bytes — результат sugar, defaults, computed, ordered, scalars N1.1, применённых по порядку, в кодировке JCS.

3. Если строка вида {form, rev, sha256, manifest} тяжелее потолка N1.2 (`max_value`, прочитанный вызывающим),
   вернуть `toolarge` вида (N4).    `rev` — окончательная новая rev, выбранная вызывающим (глава 2.3 N3, шаг 14a), а не прежняя оценка.

4. Вернуть bytes.

### установщик `manifest put` — запись вида

Вид строится до любой записи.

Порядок шагов — [глава 2.3](02.3-installer.norms.md) N3 «Смена манифеста» (установщик):

1. Прочитать потолок: `GET /v1/status` → `max_value`.    Если хранилище не ответило, ответило не 200 или ответило без
   `max_value` — отказ установки целиком: ничего не записано, код 2 (глава 2.3 N4).

2. Построить вид (выше) для новой rev. Сначала окончательно выбрать новую rev (после чтения строки, глава 2.3 N3, шаги 9–14a), затем
   проверить вес строки вида ровно с этой rev, затем писать части и строку.    При `toolarge` вида — отказ установки
   целиком: ничего не записано, код 2; stderr называет файл, ключ вида, вес и потолок.    Конфликт `cas`, меняющий новую rev, повторяет эту проверку до любой следующей записи.

3. «Unchanged» — строка та же (yaml, shell, files по значению) И вид текущей формы есть, читается и равен
   проекции; иначе запись.

4. Порядок записи: строка манифеста → вид (`cas` по прочитанной версии вида или `""`) → метка последней.

5. Если вид не записан из-за конфликта `cas`, перечитать строку и вид:    1. Если rev строки — моя, повторить `cas` вида.    2. Если rev строки уже иная (другой установщик записал новее), пройти проход заново с
      чтения строки (мой файл — новая rev или «unchanged»; новая rev — с проверкой веса п. 2 для этой rev).       Вид прежней rev не пишется: вид всегда несёт rev текущей строки.    3. Если строка уже записана, метка не двигается, пока вид не записан.

Кластер из одного процесса со встроенным манифестом пишет вид тем же правилом ([P/02.4](02.4-installer.norms.md) N1.10).

### Читатель

Читатель вида — процесс, перешедший на вид своей правкой поведения; он действует так:

1. Прочитать метку, затем вид своей формы. 2. Если вида нет, или он читается и его rev ≠ rev метки, это окно установки (вид записан с rev N, метка ещё
   N − 1, или вид новой rev ещё не записан): повторить шаг 1 с паузой 1 с, в пределах `START_WAIT` главы 2.3 N3 «Старт процесса».    Неподтверждённое чтение метки или вида (хранилище не ответило) повторяется так же.    Если к концу `START_WAIT` они всё ещё не совпали: отказ «not published» — не старт, код 1; супервизор
   перезапускает процесс (временный исход главы 2.3 N3 «Старт процесса»).

3. Если вид не читается (не по форме своей семьи), или его rev равна rev метки, а sha256 ≠ sha256
   метки, или manifest не проходит построенную схему: отказ «corruption» — как нечитаемый манифест (глава 2.3 N3
   «Старт процесса»): не старт, код 2, без перезапуска.

   У работающего процесса отказ «corruption» действует как метка не по форме.

4. Иначе манифест читателя — значение manifest; загрузчик YAML не нужен.

Между «not published» и «corruption» читатель выбирает до открытия своих дверей. Пока читатель повторяет, он ничего не обслуживает.

До своей правки читатель прогоняет загрузчик по главе 2.3 N3; вид он не читает.

**Гонки.** Вид пишется после строки и до метки: работающие процессы видят смену по метке, когда строка
и вид уже записаны.

Стартующий процесс, прочитав метку, читает строку и вид той же `rev`
(иначе повторяет по N3 «Читатель», пока у метки не станет rev вида).

Два установщика одного имени: `cas` строки (глава 2.3 «Гонки»), затем
`cas` вида; проигравший перечитывает.
