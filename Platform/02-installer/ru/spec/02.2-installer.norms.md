### N1.1 Проекция

Канонический вид манифеста — байты JCS (ADR-0072, для человека) значения, которое
получается из дерева принятого манифеста (загрузчик главы 2.1, вердикт `ok`) по правилам ниже, по порядку. Вид зависит только от
байтов манифеста и стандартных файлов главы 2.1 (схема `02.1-installer.schema.json`, таблица слоёв `02.1-installer.layers.tsv`).

```yaml
sugar:      закрытый перечень приведений к одной форме (до умолчаний):
  tables:   список имён [a, b] → {a: {}, b: {}}
  bound_to: у поля единицы и поля таблицы одно имя "x" → ["x"]
  in:       у элемента secret_in вида regex одно слово "query" → ["query"]
defaults:   каждый ключ с аннотацией `default` схемы главы 2.1 есть явно — только внутри присутствующего родителя или родителя со
            своим default (ADR-0089 доп. (1) R10); отсутствующий раздел без default — отсутствует
computed:   закрытый перечень шагов урока 2 (после defaults):
  P1 snapshot:            нет ключа — имена unit.fields в порядке автора без *_secret, без type: blob и без server, затем
                          state.<имя> каждого unit.state, кроме cursor, в порядке автора (ADR-0091 п. 3); [] — []
  P2 tables.<т>.journal:  нет — {written: "<т>.written", deleted: "<т>.deleted"}; дан один ключ — второй так же
  P3 display.form:        нет — [{fields: [<имена unit.fields в порядке автора>]}], без title
  P4 default описателя:   у поля единицы и поля таблицы — сказанное значение; не сказано или сказан inherit — null
                          (у всех типов, включая blob; ADR-0089 доп. (2))
  P5 decoded:             у элемента secret_in вида regex без decoded — true (P/06.2 N1.1, A13)
not:        не подставляются: events.suppress.<вид>.by, display.section, display.general (ADR-0089 доп. (2)), ключи без
            аннотации `default` в схеме (записка умолчаний, раздел 4)
ordered:    отображения с пометкой `x-ordered` таблицы слоёв (unit.fields, tables.<т>.fields) — массив {"name": <ключ>, …значение} в порядке
            автора; прочие отображения — объекты, порядок — JCS; читатель на порядок автора вне ordered не опирается
            (ADR-0089 доп. (1) R14)
scalars:    значения JSON по типу места схемы (integer — число, целое место — целое после приведения слоя 2: `4.0` → `4`;
            string — строка, boolean — true/false)
notes:      комментариев, исходного текста и пометок `x-*` в виде нет
```

### N1.2 Строка вида

```yaml
platform/manifest/<sub>/canonical/<форма>:   # одна строка на подсистему и форму вида; писатель — установщик (N3)
  form:    номер формы вида, десятичное целое ≥ 1; сейчас 1 (ключ …/canonical/1)
  rev:     rev строки манифеста platform/manifest/<sub>, из которой вид построен (глава 2.3 N1.5)
  sha256:  sha256 строки манифеста (её поле sha256)
  manifest: байты вида (N1.1) текстом — JCS, UTF-8, без перевода строки в конце
ceiling:   потолок строки хранилища P/01.1 N1 для этого ключа; сумма строки манифеста и вида не ограничивается (ADR-0089
           доп. (1) R11); источник — фактический потолок хранилища: max_value ответа GET /v1/status (P/01.3 N2,
           OpenAPI 01 StatusResponse); 524288 — только умолчание флага -max-value демона, не константа установщика;
           своей настройки потолка у установщика нет (решение «Архитектора» по вопросу Go P/02 № 4)
window:    смена формы вида — новая форма рядом (…/canonical/<форма + 1>); в окно смены установщик пишет обе формы
           (ADR-0083 п. 3)
```

Форма самого `manifest` — схема вида [`02.2-installer.view.schema.json`](../../spec/02.2-installer.view.schema.json) (JSON Schema 2020-12;
пометки `x-step` — шаг проекции, `x-default` — ключ обязателен умолчанием формы, `x-unique-by` — ключ элементов `ordered`;
[слои V7](../../../common/ru/LAYERS.md) § 3): закрыта там же, где форма; ключи с `default` обязательны; `ordered` — массив с
уникальным `name`. Раздел формы вида ниже и векторы `canonical` строит построитель навыка `lesson-spec` (ADR-0092 п. 12).

### Форма канонического вида (построена из стандартных файлов)

Значение `manifest` строки `platform/manifest/<sub>/canonical/1` — JSON (JCS, ADR-0072) этой формы: JSON Schema 2020-12 `02.2-installer.view.schema.json` (ADR-0089 п. 3, ADR-0092 слой 6). Отображение без имён автора закрыто: ключа вне таблицы нет. «Есть всегда» — ключ с умолчанием формы манифеста (`default` `02.1-installer.schema.json`) или шагом проекции; «есть, если сказан в манифесте» — ключ без умолчания, его отсутствие и есть значение. Отображение `x-ordered` формы манифеста — список объектов `{name, …}` в порядке автора. Правил и связей формы манифеста здесь нет: принятый манифест проверил установщик.

#### Шаги урока 2

Закрытый перечень: сахар — до умолчаний формы, вычисляемые умолчания — после них, до `ordered`.

| Шаг | Норма | Когда | Что в виде |
|---|---|---|---|
| `tables` | P/02.2-02 | `tables` списком имён | `{<имя>: {}}` на каждое имя, по порядку списка |
| `bound_to` | P/02.2-02 | `bound_to` одним именем (поля единицы и таблиц) | список из одного имени |
| `in` | P/02.2-02 | `in` элемента `secret_in` одним словом | список из одного слова |
| P1 | P/02.2-03 | нет `snapshot` | имена `unit.fields` в порядке автора без `*_secret`, полей `type: blob` и `server`, затем `state.<имя>` каждого `unit.state` в порядке автора, кроме `cursor` (ADR-0091 п. 3); явный `[]` остаётся |
| P2 | P/02.2-03 | нет `tables.<т>.journal` или одного из его ключей | `written` — `"<т>.written"`, `deleted` — `"<т>.deleted"`; сказанный ключ остаётся |
| P3 | P/02.2-03 | нет `display.form` | `[{"fields": [<имена unit.fields в порядке автора>]}]` |
| P4 | P/02.2-03 | нет `default` у описателя поля (единицы и таблиц) | `null` (и у `blob`, и при `inherit`) |
| P5 | P/02.2-03 | нет `decoded` у элемента `secret_in` с `regex` | `true` |

## N3 Проход

### построить вид(байты манифеста) → байты | отказ

```
1. загрузить(байты) по главе 2.1                         → отказ: отказ загрузки (вид не строится)
2. sugar, defaults, computed, ordered, scalars N1.1 по порядку; JCS
3. строка вида {form, rev, sha256, manifest} тяжелее потолка N1.2 (max_value, прочитанный вызывающим) → toolarge вида (N4);
   rev — окончательная новая rev, выбранная вызывающим (глава 2.3 N3 «проверить вес вида»), не прежняя оценка
```

### установщик `manifest put` — запись вида (решение «Архитектора» по окну 2.2, п. 8)

Вид строится до любой записи. Порядок шагов — [глава 2.3](02.3-installer.norms.md) N3 «Смена манифеста» (установщик):

```
прочитать потолок: GET /v1/status → max_value           → не ответил, не 200 или без max_value: отказ установки целиком,
                                                          ничего не записано, код 2 (глава 2.3 N4; решение «Архитектора» по вопросу Go P/02 № 4)
построить вид (выше) для новой rev: сначала окончательно выбрать новую rev (после чтения строки, глава 2.3 N3), затем
проверить вес строки вида ровно с этой rev, затем писать части и строку
                                                        → toolarge вида: отказ установки целиком, ничего не записано,
                                                          код 2; stderr называет файл, ключ вида, вес и потолок; конфликт cas,
                                                          меняющий новую rev, повторяет эту проверку до любой следующей записи
«unchanged» — строка та же (yaml, shell, files по значению) И вид текущей формы есть, читается и равен проекции; иначе запись
порядок записи: строка манифеста → вид (cas по прочитанной версии вида или "") → метка последней
вид не записан из-за конфликта cas                      → перечитать строку и вид: rev строки — моя → повторить cas вида; rev
                                                          строки уже иная (другой установщик записал новее) → проход заново с
                                                          чтения строки (мой файл — новой rev с проверкой веса вида для неё
                                                          или «unchanged»), вид прежней
                                                          rev не пишется: вид всегда несёт rev текущей строки (C02-VIEW-CAS-RESTART-01);
                                                          строка уже записана — метка не двигается, пока вид не записан
```

Кластер из одного процесса со встроенным манифестом пишет вид тем же правилом ([P/02.4](02.4-installer.norms.md) N1.10;
ADR-0089 доп. (1) R15).

### Читатель

Читатель вида (процесс, перешедший своей правкой поведения, ADR-0089 п. 7):

```
прочитать метку, затем вид своей формы
вида нет, или он читается и его rev ≠ rev метки         → окно установки (вид записан с rev N, метка ещё N − 1, или вид новой
                                                          rev ещё не записан): повторять чтение метки и вида с паузой 1 с, в
                                                          пределах START_WAIT главы 2.3 N3 «Старт процесса»; неподтверждённое
                                                          чтение метки или вида (хранилище не ответило) повторяется так же
                                                        → к концу START_WAIT не совпали: отказ «not published» — не старт,
                                                          код 1; супервизор перезапускает процесс (временный исход главы 2.3
                                                          N3 «Старт процесса»)
вид не читается (не по форме своей семьи), или его rev равна rev метки, а sha256 ≠ sha256 метки, или manifest не проходит
построенную схему                                       → отказ «corruption» — как нечитаемый манифест (глава 2.3 N3 «Старт
                                                          процесса»): не старт, код 2, без перезапуска; у работающего — как
                                                          метка не по форме
иначе                                                   → манифест читателя — значение manifest; загрузчик YAML не нужен
```

Между «not published» и «corruption» читатель выбирает до открытия своих дверей; пока он повторяет, он ничего не обслуживает.

До своей правки читатель прогоняет загрузчик по главе 2.3 N3; вид он не читает.

**Гонки.** Вид пишется после строки и до метки: работающие процессы видят смену по метке, когда строка и вид уже записаны;
стартующий процесс, прочитав метку, читает строку и вид той же `rev` (иначе повторяет по N3 «Читатель», пока у метки не станет rev вида). Два
установщика одного имени — `cas` строки (глава 2.3 «Гонки»), затем `cas` вида; проигравший перечитывает.
