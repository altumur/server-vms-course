# P/02.4 — Установщик: нормы

Текст производный от `spec/02.4-installer.norms.md`, руками не правится: источник — английский [`spec/02.4-installer.norms.md`](../../spec/02.4-installer.norms.md), правка идёт в него, русский пересобирается переводом.

Канон главы. Лекция (`ru/02-installer.md`, для человека, в выгрузку не входит), [инструкция](02-installer.README.md), [жизненный цикл](../lifecycle.md),
[векторы скрипта воркеров](../vectors/workers-script/README.md). Своего HTTP-контракта у урока нет: дверей у установщика

роли (N1.6 «Правило адреса»). Отказ сервера (N1.4) и проход «вырвать питание» — [P/04](../../../04-controller/ru/spec/04-controller.norms.md) N1.4a, N3;

## N1 Форма

**Время.** Полей времени у строк и файлов главы нет.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `platform/mirror`, `platform/space`, `<sub>/retention`, `<sub>/alarms_retention`, `/etc/w2c/roles/<role>.env`, `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/ca.next.pem`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem`, `/etc/w2c/tls/<role>/server.pem`, `/etc/w2c/tls/<role>/server.key`, `/etc/w2c/secrets/platform.key`, `<domain recovery file>`;
- пишет: `domain/join` (create), `<sub>/<manifest:unit.rows>/<id>` (cas), `<sub>/<manifest:tables>/<name>` (cas), `door/signer` (cas), `domain/signer` (cas), `domain/signer-pending` (cas), `domain/book-seal` (cas), `domain/member-key` (cas), `domain/users/<name>` (cas), `domain/break-glass/<cluster>` (cas), `domain/keys` (create), `domain/root` (create);
- читает: `platform/manifest/<sub>`, `platform/manifest/<sub>/rev`, `/etc/w2c/configstore-rights.json`.

Строки `domain/keys` (набор rev 1, подписанный корнем) и `domain/root` пишет установка домена — поздний слой главы
(N3 «установка домена», вводит глава 8.2).

Строки `door/signer`, `domain/signer`, `domain/signer-pending`, `domain/book-seal`, `domain/member-key`, `domain/users/<name>`,
`domain/break-glass/<cluster>` пишет `w2cctl secrets seal` (какие строки он обходит — N1.9 «Команды

Владельцы строк — главы урока [P/08](../../../08-domain/ru/README.md) (каталог).

Форма файла восстановления домена и правила его чтения — [договор основания домена](../../../common/ru/contracts/domain-founding.md) «Корень и файл восстановления» (`recovery_file`, `place`, `mode`).

Юниты `units` стоят на каждом сервере; имена — платформа `w2c`, подсистема своим префиксом.

`common` действует у долгоживущих служб: у всех юнитов, кроме `w2c-workers.service` (`Type=oneshot`). `RestartPreventExitStatus=2`: отказ старта по манифесту, правам, схеме — подтверждённая непригодность (глава 2.3) — без перезапуска, до действия оператора. Выход 1 — чтение не подтверждено за `START_WAIT` (глава 2.3) — перезапускается.

`After=configstore.service`, не `Wants`: хранилище не тянут. Долгоживущая служба запускается через раннер (`w2c-run.sh`) с umask 0007.

`configstore.service`: `W2C_ROLE=configstore` — для порядка файлов окружения раннера; в файле прав такого имени нет; `roles/configstore.env` нет — пропуск. `configstore.service`: сокеты — от юнитов `configstore-*.socket` (P/01.3 N1.3 sockets).

`configstore-admin.socket`, `configstore-<role>.socket`: по юниту на admin и на каждую роль файла прав; `<role group>` — `users_groups`.

`w2c-resource.service` — роль resource; `RESOURCE_HOST`/`PORT` юнит не пишет — умолчание процесса
127.0.0.1:8090 (lifecycle P/05); переменная из `w2c.env` — явный адрес (N1.6 process).

`w2c-controller@.service`: роль `<sub>controller`, группа `w2c-<sub>controller`. `w2c-controller@.service`: `WatchdogSec=360` (СЛЕДУЕТ).

`w2c-console.service` — роль console; `CONSOLE_HOST`/`PORT` юнит не задаёт — `w2c.env` (install `w2c_env` N1.7).

`<dep>-<sub>worker@.service`: `w2c-secrets` в `SupplementaryGroups` — у держателей секретов.

`<dep>-<sub>worker@.service`: экземпляр `%i` — имя слота `<prefix>-<SERVER_NAME>-<n>`: `<prefix>` —
`slot.prefix` манифеста (P/03.2 N1.4), умолчание `w`; `SERVER_NAME` — N1.2; `n` — целое без ведущих нулей. `<dep>-<sub>worker@.service`: `n` 1 — базовый, его включает установка; 2…99 — по заказу, их запускает скрипт N1.5. `<dep>-<sub>worker@.service`: часть `%i` между `<prefix>-` и `-<n>` ≠ `SERVER_NAME` — отказ старта, код 2.

`<dep>-<sub>worker@.service`: `ExecStart=` — `w2c-run.sh worker <sub> %i` (N1.9): раннер читает окружение по N1.2 и исполняет
`worker.exec` из строки манифеста (P/02.3 N3 «Worker program from the row») с последним
аргументом — именем слота, `W2C_MANIFEST_REV` — rev этой строки. `<dep>-<sub>worker@.service`: строка exec в юнит не попадает; на стенде — команда профиля реализации с подстановкой `{name}` (общий README приёмки).

`<dep>-<sub>worker@.service`: переменную окружения с именем юнит ставит, только если
манифест объявил `slot.name_env`, — эту и тем же `%i`.

`<dep>-<sub>worker@.service`: группы долей `worker.uses` — `SupplementaryGroups` += группа каждой доли
`<A>.<share>`, объявленной в `shares` подсистемы A каталога (доля части — группа пользователя части,
иначе `<dep>-<A>-<share>`; своя доля — только с `part`, группа части). `<dep>-<sub>worker@.service`: A нет в каталоге — группы нет.

`<dep>-<sub>worker@.service`: `ReadWritePaths` — свой каталог состояния `/data/platform/subsystems/<sub>` и
каталог каждой своей доли без `part` `/run/<dep>-<sub>-<share>` (воркер — её производитель), не `/run`
целиком. `<dep>-<sub>worker@.service`: доля из `worker.uses` — проход и подключение по группе, без `ReadWritePaths`. `<dep>-<sub>worker@.service`: `W2C_SUB_ENV=/etc/<sub>/<sub>.env` (N1.2); `EnvironmentFile=` не используется.

`<dep>-<sub>worker@.service`: у подсистемы с parts — `After=` юнита каждой своей части, без `Wants` и `Requires`: перезапуск воркера
часть не трогает, пропажа части воркер не останавливает.

`<dep>-<sub>worker@.service`: `TimeoutStopSec` = `worker.stop_timeout` манифеста
(20…50, умолчание 20; P/02.1); macOS — `ExitTimeOut` launchd тем же числом.

`<dep>-<sub>-<part>.service` — часть подсистемы со своей службой (`parts.<part>` манифеста). `<dep>-<sub>-<part>.service`: запуск — `w2c-run.sh part <sub> <part>` (N1.9), раннер исполняет
`parts.<part>.exec` файла манифеста, установленного в `MANIFEST_DIR` (установочный источник, P/02.3
«Установочный источник»; строку манифеста из хранилища не читает). `<dep>-<sub>-<part>.service`: без `W2C_ROLE`, без `roles/` и `w2c.env` — только `W2C_SUB_ENV=/etc/<sub>/<sub>.env` по
грамматике N1.2, `EnvironmentFile=` не используется; общие правила `common`.

`<dep>-<sub>-<part>.service`: `TimeoutStopSec` = `parts.<part>.stop_timeout` (≥ 1, умолчание 20; macOS — `ExitTimeOut` тем же числом). `<dep>-<sub>-<part>.service`: установка включает юнит вместе с воркерами (N1.7 enable), старт сервера поднимает части раньше
воркеров (N3 «старт сервера»).

`<dep>-<sub>-<part>.service`: `ReadWritePaths` — свой каталог
`/data/platform/subsystems/<sub>/<part>` и каталог каждой доли с `part: <part>` — `/run/<dep>-<sub>-<share>`
(часть — её производитель).

`<dep>-<sub>-<part>.service`: при `parts.<part>.volumes` — при старте проверяет: каждый
смонтированный `…/<part>/volumes/<n>` принадлежит пользователю части, иначе отказ старта, код 2. Том части монтирует оператор, установщик не монтирует, число томов — свойство сервера.

`w2c-workers.service/.timer` исполняет скрипт воркеров по заказу (N1.5); `Restart=no` — повтор задаёт таймер (systemd
не допускает `Restart=always` у oneshot). `w2c-workers.service`: `User=w2c-workers` без групп, один на сервер — все роли сервера.

`w2c-domain.service`, `w2c-domainconsole.service`, `w2c-domainagent.service`: юниты процессов домена — N1.12 (поздний слой
главы, вводит урок 8).

`w2c-domainagent-token-<role>.socket`: по юниту на каждую роль воркеров каталога манифестов (`<role>` — `<sub>worker`); `<role group>` — `users_groups`. `w2c-domainagent-token-<role>.socket`: умолчание каталога `AGENT_TOKEN_DIR` — `/run/w2c/domainagent`; тот же `AGENT_TOKEN_DIR` — у юнита
агента и юнита воркера ([договор местной двери токенов](../../../common/ru/contracts/local-token-door.md)
«Сокет роли»).

`watchdog`: `WatchdogSec` — договор файла окружения «Константы и юниты». `watchdog`: notify — из цикла, не из подмены (P/03.3 N1.2 watchdog).

`notify`: датаграмма sd_notify на `NOTIFY_SOCKET`: контроллер шлёт `READY=1` после проверки схемы и чтения манифеста (N3 «старт
сервера» шаг 3), воркер — после захвата имени.

`notify`: воркер — `WATCHDOG=1` каждым оборотом своего цикла, контроллер — по каденции [P/04](../../../04-controller/ru/lifecycle.md) «Сигналы и готовность»: на границах завершённых решений и прогресса.

`notify`: нет `NOTIFY_SOCKET` — молчат.

`Type=notify` — только у контроллера и воркера: хранилище, консоль, ресурс и процессы домена sd_notify не шлют,
их готовность — сокет или порт.

`users_groups`: id — решает реализация; имена — норма.

`users_groups`: у доли части отдельной группы нет — её группа — группа пользователя части.

`users_groups` `names`: все имена ОС и пути каталога манифестов — пользователи, группы, юниты, каталоги долей и частей всех подсистем —
строятся вместе: совпадение двух в одном пространстве (пользователи и группы, юниты, пути), имя пользователя или
группы и основа имени юнита (без `.service`, `@.service`) длиннее 32 знаков — отказ каталога (P/02.1 N3
«загрузить_каталог»). `users_groups` `names`: путь `/run/<dep>-<sub>-<share>`, равный имени пользователя или группы, — не столкновение. `users_groups` `names`: одноимённые пользователь и его основная группа (`<dep>-<sub>`, `<dep>-<sub>-<part>`) — одна сущность ОС, не два
имени. `users_groups` `names`: совпадение с именами платформы (`w2c`, `w2c-store` и т. п.) ловит та же проверка.

`users_groups` `dep`: `<dep>` — `W2C_DEPLOYMENT` строки `w2c.env`; строки нет — окружения установщика (N1.2), умолчание `w2c`.

`users_groups` `rule`: процесс платформы — никогда от пользователя подсистемы и не в её группах.

`users_groups` `rule`: демон хранилища — не в группах
подсистем: группу сокета роли задаёт `SocketGroup=` его юнита, демон получает сокет готовым (P/01.3 N1.3 sockets).

`dirs`: каталоги — под `/data/platform`. `dirs`: процесс роли корней не создаёт: корня нет — отказ старта, код 2, лог с путём (корни ставит установка; на стенде —
команда запуска роли профиля, общий README приёмки «Стенд без root»).

`dirs` `/data/platform/etc/secrets`: ключ 0640; договор запечатывания.

`dirs` `/data/platform/etc/tls`: проход всем ролям; `ca.pem`, `ca.next.pem`, `revoked`, `crl.pem` — 0644: их читает и скрипт воркеров без групп, клиент своего кластера, договор сертификата роли `own_client`.

`dirs` `/data/platform/etc/tls/<role>`: комплект роли; группа — N1.6 `identity.doors`, не группа ролевого
сокета; `server.pem` 0644, `server.key` 0640 — читает только эта группа — либо 0600 пользователю
юнита, договор сертификата роли `kit`.

`dirs` `/data/platform/events`: корень событий; `RESOURCE_ROOT`, заданный иначе, — тот же объект, те же
2771 w2c:w2c-events. `dirs` `/data/platform/events`: проход прочим без чтения — к замкам `.workers` скрипта воркеров без групп;
подкаталоги и файлы бакетов — договор журнала событий bucket modes.

`dirs` `/run/configstore`: плоско, без подкаталогов: сокеты юнитов `configstore-*.socket`.

`dirs` `/run/w2c/domainagent`: плоско: сокеты юнитов `w2c-domainagent-token-*.socket`.

`dirs`: на А/Б-коробке переживает только `/data`.

`dirs` `/data/platform/etc/subsystems/<sub>`: настройки подсистемы: `/etc/<sub>` — ссылка сюда, как `/etc/w2c`;
проход без перечня. `dirs` `/data/platform/etc/subsystems/<sub>`: файл подсистемы `<sub>.env` читают все пользователи коробки, секретов в нём нет — секреты в
хранилище, P/06.2.

`dirs` `/data/platform/subsystems/<sub>`: состояние подсистемы вне хранилища; создаёт установщик.

`dirs` `/data/platform/subsystems/<sub>/<part>`: состояние части: группа части,
которую потребители доли получают в `SupplementaryGroups`, открывает им
только долю.

`dirs` `/data/platform/subsystems/<sub>/<part>/volumes/<n>`: тома части (`parts.<part>.volumes`): точки монтирования владельца-писателя
— пользователя части; установщик их не создаёт и не монтирует.

`dirs` `/run/<dep>-<sub>-<share>`: каталог доли `shares`; владелец — пользователь подсистемы или
части при `part`. `dirs` `/run/<dep>-<sub>-<share>`: читатель подменить сокет доли не может. `dirs` `/run/<dep>-<sub>-<share>`: `/run` — tmpfs: каталоги долей создаёт
при каждой загрузке до юнитов tmpfiles.d установщика; `RuntimeDirectory=`
не годится — каталог жил бы и снимался с одним юнитом.

`dirs` `rule`: ни один юнит не монтирует корень целиком. `dirs` `rule`: всё изменяемое — под `/data/platform`.

Юниты `w2c-domain.service`, `w2c-domainconsole.service`, `w2c-domainagent.service` — поздний слой главы: вводит урок 8
(глава [8.10](../../../08-domain/ru/spec/08.10-domain.norms.md)); их строки — N1.12 «Порты и юниты домена» (P/02.4-R053, P/02.4-R434, P/02.4-R435, P/02.4-R437, P/02.4-R440, P/02.4-R441, P/02.4-R445, P/02.4-R453, P/02.4-R454, P/02.4-R505).

### N1.2 Контракт окружения

Файлы окружения, порядок их чтения раннером и юнитом части, `W2C_ROLE` юнита и команды — [договор файла
окружения](../../../common/ru/contracts/env-file.md) «Файлы и порядок чтения». Файлы окружения (`w2c.env`, `roles/*.env`, файл подсистемы, `configstore.env`) читаются разбором, не `source`, по
[договору файла окружения](../../../common/ru/contracts/env-file.md) (грамматика `KEY=VALUE` и края). Строка файла окружения не по грамматике — отказ запуска с кодом 2 и строкой лога, которая
называет файл и номер строки. Файла окружения нет — пропуск, файл не читается — отказ запуска, код 2 (договор, «Файла нет»).

Переменные окружения процессов — форма, смысл, умолчание, кто ставит — [договор файла окружения](../../../common/ru/contracts/env-file.md)
«Переменные окружения».

**Канал настройки и раскладка `PLATFORM_DIR`**: процессы платформы — консоль, контроллер, воркер, ресурс, процессы домена — настраиваются только переменными
  [договора файла окружения](../../../common/ru/contracts/env-file.md) «Переменные окружения» и аргументом имени воркера (экземпляр `%i` юнита); собственных флагов путей и адресов у них нет; флаги есть только у
  демона хранилища ([P/01.3](../../../01-store/ru/spec/01.3-store.norms.md) N1.3 «Флаги демона»);

- хранилище — `<PLATFORM_DIR>/configstore` (`-dir` юнита N1.1);

- объекты — корень `OBJECTS` / `PLATFORM_OBJECTS`, по умолчанию `<PLATFORM_DIR>/objects`;

- события — корень `RESOURCE_ROOT` / `EVENTS`, по умолчанию `<PLATFORM_DIR>/events`; замки присутствия — в корне
  событий ([договор замка присутствия](../../../common/ru/contracts/presence-lock.md) `presence_lock`);

- кольцо — `SECRETS_KEY`, по раскладке N1.1 — `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c/secrets` — ссылка), вне каталога хранилища, корня объектов и корня событий: оно не уходит ни с копией хранилища, ни с
  объектами, ни с зеркалом событий ([договор запечатывания](../../../common/ru/contracts/sealing.md) «Файл кольца»).

### N1.5 Воркеры по заказу

```yaml
order:        <sub>/want/<сервер>; want 1…99; <sub>_workers_wanted{server}
extra_unit:   <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>, n 2…99
script:       w2c-workers.sh; таймер, раз в минуту; User=w2c-workers
  polkit:     start, stop; User w2c-workers; <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>.service, n [2-9]|[1-9][0-9]
rules:        1–6
stop:         systemctl stop
memory:       CAPACITY, unit_mb, base_mb, WORKER_MEMORY_MB; GOMEMLIMIT
```

`order`: число процессов роли на сервере задаёт контроллер — строка `<sub>/want/<host>` (P/04 N1.1). `order`: `want` — абсолютная цель 1…99, базовый `<prefix>-<SERVER_NAME>-1` в неё входит.

`order`: консоль отдаёт ряд `<sub>_workers_wanted{server}` для каждой строки заказа (P/06.5 N3 «/metrics — текст»).

`extra_unit`: дополнительный воркер — экземпляр того же юнита роли `<dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>`, n 2…99
(N1.1): те же учётные данные, ключи, пользователь и группы; захват слота обычный (P/03.2 N3). `extra_unit`: особого юнита, файла и переменной у дополнительного воркера нет.

`script`: `w2c-workers.sh`, раз в минуту таймером, `User=w2c-workers` без групп; один на сервер — все роли сервера.

`script` `polkit`: только start и stop, только пользователем `w2c-workers`, только полные имена
`<dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>.service` ролей этого сервера, n — `[2-9]|[1-9][0-9]` без ведущих
нулей. `script` `polkit`: базовый -1, чужой сервер, иные юниты и глаголы — отказ.

`rules` 1: скрипт читает свои ряды `<sub>_workers_wanted{server=<SERVER_NAME>}` всех ролей сервера из `/metrics` консоли, ряды других
серверов не читает, команд не исполняет. `rules` 1: URL консоли — `own_url` договора сертификата роли (`CONSOLE_HOST`,
`CONSOLE_PORT` `w2c.env`; https при `ca.pem` в `W2C_TLS_DIR`, иначе http). `rules` 1: проверка сервера — клиент своего кластера
`own_client` того же договора, роль console (N1.6 roles).

`rules` 2: ряда роли нет, он не читается, консоль молчит или ряд
`<sub>_reconcile_last_success_age_seconds` (P/06.5 N3 «/metrics — текст») больше 60 или −1 → у этой роли ничего не
запускать и не останавливать: молчание — не повод. `rules` 2: ряд не читается, когда его значение не по форме метрики P/06.5 N3 — целое без ведущих нулей, знака и дроби: `02`,
`2.0`, `+2` — ряда нет — или вне 1…99. `rules` 2: строка не по формату текста — пропущена с
диагностикой, прочие ряды прохода считаются (P/01.1 N0 «Устойчивость выдачи»). `rules` 2: консоль молчит — сбор `/metrics` не
удался, последний успешный сбор старше минуты по местным монотонным часам скрипта.

`rules` 3: цель роли — ровно номера {2…want}: недостающие в этом множестве запустить (наименьшие первыми), работающие с номером
больше want остановить (наибольшие первыми). `rules` 3: номер сравнивается как целое, не по порядку строк. `rules` 3: базовый -1 скрипт не трогает.

`rules` 4: перед запуском — память: потолок = floor(`HOST_MEMORY_MB` / `WORKER_MEMORY_MB`) из `roles/<role>.env` (разбор, не source;
нет файла — роль пропуск). `rules` 4: оба бюджета — положительные целые, `CAPACITY` — целое > 0; значение не по форме или
ноль делителя → роль пропустить с диагностикой. `rules` 4: `unit_mb` и `base_mb` скрипт не
читает — это вход старта воркера (`memory` ниже, P/03.4 N1.2). `rules` 4: потолок — число процессов роли на сервере, каждый с `WORKER_MEMORY_MB`: работающие, базовый -1 и
зарезервированные старты считаются. `rules` 4: общий потолок памяти сервера по всем ролям не
делится — предел схемы.

`rules` 5: проходы сериализованы. `rules` 5: номер резервируется до start; неопределённый исход start или stop остаётся занятым до сверки
systemd. `rules` 5: второй проход при той же цели новых не запускает и лишних не останавливает.

`rules` 6: ровно один механизм исполняет ряды на установке: таймер или рука; на стенде — директива `@grow` (общий README приёмки).

`stop`: остановка — `systemctl stop`: воркер отдаёт слот штатно (P/03.4 N3 «остановка по SIGTERM»); у воркера с непустым
назначением это переезд единиц, не потеря. `stop`: контроллер уменьшает want после пустого
назначения сокращаемого воркера (P/04 N3 «shrink()») или снятием заказа по сроку `WANT_GRACE` (P/04 N3
«withdraw by deadline»): тогда номер выше want скрипт останавливает и с непустым назначением —
единицы переезжают.

`memory`: воркер не стартует, если `CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB`. `memory`: `GOMEMLIMIT = WORKER_MEMORY_MB`.

### N1.6 Сертификаты: сторона выпуска

Форма сертификата и одна роль (`cert`), закрытый список подписей (`sig`), комплект (`kit`), `revoke`, `rotation` — общий
[договор сертификата роли](../../../common/ru/contracts/role-certificate.md).

Сторона проверяющего
TLS-пира у демона хранилища и роли демонов `configstore`, `configstore-door` — [P/01.3 N1.6](../../../01-store/ru/spec/01.3-store.norms.md). Строки ниже — центр, выпуск, комплекты прочих ролей и их двери.

```yaml
ca:           w2c-ca.sh init | issue <server> <роль> | revoke <server|pem> | crl | own <dir> <роль> [группа]
  center:     init; basicConstraints critical CA:true без pathLen; keyUsage critical keyCertSign, cRLSign;
              notAfter = notBefore + 3650 × 86400 с
  leaf:       issue; basicConstraints CA:false; keyUsage critical digitalSignature (RSA: keyEncipherment);
              extendedKeyUsage serverAuth, clientAuth; notAfter = notBefore + 825 × 86400 с
  crl:        crl; X509 CRL v2, по блоку на каждый центр из ca.pem, ca.next.pem
sig:          договор сертификата роли `sig`
client_cert:  domain (SIGNER_URL)
roles:        configstore, configstore-door; resource, console, domain, domainconsole, domainagent,
              <sub>controller, <sub>worker
```

`ca`: один центр на установку. `ca` `center`: init — самоподписанный. `ca` `center`: «center 10 years» договора `cert` — эти секунды, не календарь.

`ca` `leaf`: у ключа RSA ещё `keyEncipherment`. `ca` `leaf`: профиль — правило выпуска:
проверяющий его сверх договора peer шагов 2–5 и класса signer не требует (договор сертификата роли `cert`).

`ca` `crl`: каждый блок подписан своим центром; без delta,
indirect и ограничения issuingDistributionPoint; форма и чтение — договор сертификата роли `revoke` `crl`.

`sig`: иная подпись — цепочка не проверяется (договор peer `common/contracts/peer.md` шаг 4 — `bad_chain`). `sig`: у двери роли
P/10 N1.4 список проверяется после рукопожатия шагом peer — 403 `bad_chain`, в рукопожатии ограничивать не требуется
(стеки этого не умеют одинаково).

`client_cert`: слушатель процесса domain (`SIGNER_URL`, P/08.2 N1.3) — все его маршруты — запрашивает сертификат клиента
необязательно.

`client_cert`: предъявленный проверяет в рукопожатии по своим `ca.pem`, `ca.next.pem`: лист сходится к центру,
срок действует, нет extendedKeyUsage без clientAuth — иначе alert, HTTP нет.

`client_cert`: не предъявлен — рукопожатие ok
(договор сертификата роли «Server side: class signed» signer).

`client_cert`: роль domainconsole из SAN при подписях
в списке `sig` и серийнике не в `revoked` открывает чтение `X-W2C-Client` (P/08.4 N1.10 address), иначе — адрес
TCP-пира.

`client_cert`: клиенты из других кластеров — агенты и ретрансляторы — лист этому слушателю не предъявляют
(P/09.1 N1.7, P/09.2 N1.6; договор сертификата роли clients).

`roles`: configstore, configstore-door — P/01.3 N1.6 `roles`.

`roles`: дверь ретранслятора — роль domainagent: это агент — P/09.2 N1.1, N1.6.

`roles`: `<sub>controller` читает объекты и события дверью ресурса по HTTPS.

`roles`: `<sub>worker` — комплект по `W2C_ROLE`/`W2C_TLS_DIR`; нет комплекта → дверь на петле, клиент только к http://. `roles`: https:// без комплекта — отказ с причиной.

`roles`: узкое исключение — клиент агента в процессе
кластера из одного, только к дверям держателя и ретранслятора, с проверкой сервера (P/09.1 N1.11).

`roles`: второе
узкое исключение — скрипт воркеров (N1.5): без комплекта, только GET публичной `/metrics` консоли, с проверкой
сервера клиентом своего кластера (договор сертификата роли `own_client`: peer с отпечатками `ca.pem` и
`ca.next.pem` каталога `W2C_TLS_DIR`, роль console, host по порогу петли, затем отзыв); своего ключа и групп у него нет.

#### N1.6 Правило адреса

```yaml
identity:
  doors:    SAN URI urn:w2c:role:<роль>, CN <роль>.<сервер>, SAN DNS <сервер>; /etc/w2c/tls/<роль>; ключ 0640 root:<группа пользователя юнита>
```

`identity.doors`: сертификат роли: SAN URI `urn:w2c:role:<role>`, CN `<role>.<server>`, SAN DNS `<server>`; комплект
`/etc/w2c/tls/<role>`. `identity.doors`: ключ 0640 `root:<unit user group>` (`w2c` у юнитов платформы, `configstore` у `configstore.service`, `<subsystem user>` у воркера — N1.1; каталог комплекта 0750 root: та же группа, N1.1 `dirs`), не группы ролевого сокета. `identity.doors`: роль берётся из `W2C_ROLE` процесса.

```yaml
address:
  store:    -tls
  process:  loopback; SIGNER_HOST, RELAY_HOST
  console:  CONSOLE_HOST (умолчание 127.0.0.1); DOMAIN_CONSOLE_HOST (умолчание 0.0.0.0); CONSOLE_CALL_PORT
  defaults: AUTH, X-User, X-Operator
  cert:     одна роль на сертификат
```

`address` `store`: демон хранилища (raft, `-api`, дверь без голоса) вне петли — только с `-tls`; иначе отказ старта, код 2 (P/01.3 N4).

`address` `process`: дверь процесса без комплекта (договор сертификата роли `kit_absent`: «no kit») — только петля (`no_kit`).

`address` `process`: частичный комплект — отказ старта, код 2 (`kit_absent`).

`address` `process`: адрес вне петли без комплекта — отказ старта, код 2.

`address` `process`: исключение: signer и relay без комплекта слушают вне петли
только по явному адресу — переменная адреса задана (`SIGNER_HOST`, `RELAY_HOST`) — и ДОЛЖНЫ при старте написать в лог строку «<роль> listens on <адрес> without a certificate
kit: anyone who reaches it may call it».

`address` `process`: ресурс из исключения снят — без комплекта только петля, вне петли — отказ старта, код 2.

`address` `process`: переменной адреса нет — умолчание процесса
(0.0.0.0 у signer и relay) не явный адрес: без комплекта — отказ старта, код 2.

`address` `console`: консоль с комплектом — TLS и на петле, HTTP при комплекте не открывается. `address` `console`: привязка — `CONSOLE_HOST` как задан в
`w2c.env` (умолчание 127.0.0.1; ::1 — только явной записью).

`address` `console`: `DOMAIN_CONSOLE_HOST` — умолчание 0.0.0.0 (N1.12):
без комплекта — отказ старта, код 2, правилом `process`.

`address` `console`: клиенты своей коробки — договор сертификата роли «Клиент двери своего кластера».

`address` `console`: слушатель обратного вызова (`CONSOLE_CALL_PORT`) — только с комплектом, договор
сертификата роли «Лист обратного вызова».

`address` `defaults`: условных ослаблений нет: `AUTH=0` нет, `X-User` / `X-Operator` без аутентификации не принимаются.

`address` `cert`: одна роль на сертификат. `address` `cert`: роль в сертификате ДОЛЖНА равняться роли процесса, иначе отказ рукопожатия
или 403 с ролью и маршрутом.

### N1.7 Обновление и установка

```yaml
upgrade:      1, 2, 3, 3a, 4; rule
add:          why; 0, 1, 2; resume; others
install:      install.sh
  os:         Linux/systemd: install apply; macOS: сборка, юнит-тесты, артефакты launchd
  w2c_env:    CONSOLE_HOST, CONSOLE_PORT (умолчание 127.0.0.1, 8080); CONSOLE_CALL_PORT (умолчание 8081); TIMEZONE (умолчание UTC);
              W2C_DEPLOYMENT; W2C_HOLD; DOMAIN_SERVER (yes | no); CONSOLE_ROOT
  warn:       RESOURCE_URL; SERVER_NAME; unconfirmed; DOMAIN_SERVER=no; placement.near.sub; разрешение имён
  refuse:     /etc/w2c, /etc/<sub>; W2C_DEPLOYMENT; CONSOLE_ROOT; DOMAIN_SERVER; TIMEZONE; цикл; кандидат прав; имена ОС
  steps:      код → раннер и скрипты → пользователи и группы → /data и ссылки → манифесты → окружение и файлы ролей
              → режимы каталогов → ключ секретов → юниты → tmpfiles.d → центр → enable: хранилище → manifest put → enable
  order:      manifest put: worker.requests, domain.tokens; по имени
  failure:    ненулевой выход с фазой/путём
  files:      MANIFEST_DIR: <sub>.shell.html, console.files; /etc/<sub>/<sub>.env; /etc/w2c/roles/<роль>.env; /etc/<sub>/<имя>
  not:        сертификаты серверов, CONFIGSTORE_JOIN
```

`upgrade`: сервер за сервером.

`upgrade` 1: `POST /drain?server=<s>`; ждать `GET /drain` `safe: true` (P/06.6 N2.3, N1.2). `upgrade` 1: единицы без другого места (строгий дом, кластер из одного) `safe` не дадут: оператор принимает простой явно, по `would_strand`, срока нет.

`upgrade` 2: подтвердить покой по P/06.6 N3 «дренаж — чтение состояния», остановить сервер, обновить, запустить; `DELETE /drain`;
достаточно здоровых назначений; возврата домой не ждать.

`upgrade` 3: следующий сервер.

`upgrade` 3a: все серверы обновлены — манифест новой ревизии: `w2cctl manifest put`. `upgrade` 3a: раньше нельзя: метку видят все, незнакомый ключ — отказ старта старой сборки (P/02.3, P/02.1); новая сборка работает на прежнем манифесте.

`upgrade` 4: последним — `PUT /schema?version=N` по P/06.6 N3 «поднять_схему»: нынешние проверки запроса, `SCHEMA`, пульса и подтверждённости чтения, затем CAS; назад не идёт.

`upgrade` `rule`: новая сборка на старой раскладке работает. `upgrade` `rule`: старая сборка на новой раскладке не стартует (видимо).

`add`: подсистема на работающем кластере, манифест — не из пакета развёртывания. `add` `why`: права хранилища и каталог консоли берутся только на старте процесса (P/01.2 N1.2: новый файл прав — перезапуск демона;
P/06.5 N2: консоль служит каталогом запуска). `add` `why`: поэтому добавление — перезапусками по одному серверу; живого
перечитывания нет.

`add` 0: до обхода — `manifest put` всех манифестов, которые меняет шаг, ради которого обход (у VMS — сборка V/12.4 N1.3: новая
подсистема, зависимые, владельцы, backend). `add` 0: каждый put выводит sha256 строки — это хеши обхода. `add` 0: затем ждать, пока консоль каждого сервера служит новыми ревизиями уже работающих манифестов обхода (backend, зависимые,
владельцы): они подхватываются по метке без обхода (P/02.3 N3 «Смена манифеста»), барьер консоли `rollout` это и сверяет. `add` 0: `served` новой подсистемы — обычно после обхода (её нет в каталоге запуска консолей); по метке
backend, чьи calls её называют, — и раньше (N1.9 `rollout` `barrier`).

`add` 1: обход — `w2cctl rollout <sub>=<sha256>…` (N1.9) на каждом сервере по очереди, сервер члена-лидера — последним. `add` 1: код 0 — шаг
сервера сделан, иначе обход стоит: кластер работает на прежних правах и каталоге, новая подсистема не включена.

`add` 2: после всех серверов: `install` без `W2C_HOLD` на каждом — повтор = обновление: файлы, права и строки те же, шаг enable включает
юниты подсистем обхода. `add` 2: до этого ни один процесс подсистем обхода не стартует, поэтому ни один не встречает член без своих прав.

`add` `resume`: повтор обхода — те же команды с теми же хешами с первого сервера: `rollout` на пройденном сервере находит барьер
выполненным и выходит 0 без перезапусков (N1.9 `rollout` `done`).

`add` `others`: контроллеры и воркеры прочих подсистем не перезапускаются.

`add` `others`: консоль сервера недоступна на время своего перезапуска, кворум
цел, потому что по одному.

`add` `others`: воркеры сервера ходят к своему члену — его перезапуск дольше `LOST_AFTER` (45 с) переразмещает
их единицы по общим правилам (P/04), это предел обхода.

`add` `others`: пока обход идёт, процессы на непройденных серверах живут со
старыми правами — переходные отказы новых чтений там — предел.

`add` `others`: backend с calls нового плагина раньше, чем консоли ему служат, —
переходные 404 и 401 — предел.

`install`: `install.sh`; повтор установки = обновление.

`install` `os`: ОС выпуска: Linux/systemd — install apply обязателен; macOS — обязательны сборка, юнит-тесты и артефакты launchd
(plist с `ExitTimeOut` и т. п., N1.1). `install` `os`: нативное применение на macOS МОЖЕТ быть, без него — отказ кодом 2 до
записи. `install` `os`: системный хост стенда не трогается.

`install` `w2c_env`: установка пишет в `w2c.env` `CONSOLE_HOST` и `CONSOLE_PORT` (умолчание 127.0.0.1, 8080) — один адрес консоли,
который читают все процессы коробки (URL своей консоли — `own_url` договора сертификата роли). `install` `w2c_env`: юнит консоли `CONSOLE_HOST` и `CONSOLE_PORT` не задаёт.

`install` `w2c_env`: `CONSOLE_CALL_PORT` (умолчание 8081) — порт слушателя обратного вызова, значение не по форме — отказ установки (`refuse` ниже).

`install` `w2c_env`: `TIMEZONE` (значение окружения установщика, умолчание UTC) — настройка кластера, которую отдаёт `GET /session` (договор файла
окружения «Переменные окружения»). `install` `w2c_env`: значение `TIMEZONE` не по форме — отказ установки (`refuse` ниже), старт консоли
сверяет форму и сам.

`install` `w2c_env`: `W2C_DEPLOYMENT` — строкой `w2c.env` при первой установке, повтор берёт оттуда.

`install` `w2c_env`: `W2C_HOLD` — значение окружения установщика; имена подсистем через запятую, каждое по грамматике P/02.1 name; не по форме —
отказ установки. `install` `w2c_env`: юниты подсистем `W2C_HOLD` ставятся и держатся выключенными — шаг enable их не включает и не запускает, а уже
поставленные и выключенные при повторе с `W2C_HOLD` остаются выключенными. `install` `w2c_env`: включает их только `install` без `W2C_HOLD` (порядок
`add` шаг 2). `install` `w2c_env`: `W2C_HOLD` в `w2c.env` не пишется — значение
действует на один вызов (порядок `add` выше, ставит его `rollout` N1.9).

`install` `w2c_env`: `DOMAIN_SERVER` (значение окружения установщика; yes | no; нет значения — строка `w2c.env`, нет её — no) — этот сервер держит домен или стоит запасным. `install` `w2c_env`: первая установка пишет строку `DOMAIN_SERVER` в `w2c.env`, как `TIMEZONE`, и только при yes включает `w2c-domain`, `w2c-domainconsole` и юниты воркеров на домене. `install` `w2c_env`: повтор берёт строку `DOMAIN_SERVER` существующего `w2c.env`: значение окружения установщика, расходящееся с ней (строки нет — no), — отказ до изменений (`refuse` ниже), оператор правит строку `DOMAIN_SERVER` в `w2c.env` руками и повторяет. `install` `w2c_env`: оба перехода `DOMAIN_SERVER` идут через файл: no → yes — шаг enable включает юниты домена, yes → no — шаг enable их не включает и не выключает и не останавливает включённые раньше, вывод называет каждый из них (`warn` ниже).

`install` `w2c_env`: `CONSOLE_ROOT` (значение окружения установщика) — в юнит консоли: файлом его не задать, значения юнита читаются первыми. `install` `w2c_env`: `CONSOLE_ROOT` не задано — прежнее значение юнита, у первой установки пусто.

`install` `w2c_env`: существующий `w2c.env` установка не переписывает и значения не переносит. `install` `w2c_env`: строки `TIMEZONE` нет —
действует умолчание UTC, иной пояс оператор вписывает в файл руками (lifecycle).

`install` `warn`: `RESOURCE_URL` с IP-литералом вне петли (порог петли договора сертификата роли `loopback`: ip) — предупреждение
на предварительной проверке, установка идёт: у https:// клиенты этой двери откажут `ip_address`, у http:// —
ошибка настройки, видимая отказом соединения.

`install` `warn`: `SERVER_NAME` каждого сервера `platform/servers` не разрешается или разрешается не в адрес привязки дверей процессов
этого сервера (P/03.4 N1.7 `door_address`) — предупреждение на предварительной проверке, установка идёт. `install` `warn`: сверка не подтвердилась — в том числе при первом запуске, когда пульса с адресом двери ещё нет, — предупреждение
со словом unconfirmed до записи, установка продолжается.

`install` `warn`: `DOMAIN_SERVER=no`, а юниты домена (`w2c-domain`, `w2c-domainconsole`, юниты воркеров на домене) стоят включёнными
от прежней установки, — установка их не выключает и не останавливает, вывод называет каждый такой юнит, установка
идёт. `install` `warn`: оператор выключает юниты домена руками, когда сервер уходит из домена (`w2c_env` выше).

`install` `warn`: `placement.near.sub` манифеста установки называет подсистему, которой нет ни в установке, ни в хранилище, —
строка вывода «near.sub <имя> нет в каталоге — сродство ждёт», установка идёт (P/02.1 N3 отсрочка near).

`install` `warn`: предпосылка развёртывания, не механизм платформы: имена серверов кластера разрешаются друг у друга (DNS или
файл хостов оператора), рабочее место оператора разрешает их и доверяет центру кластера (`ca.pem`) — иначе
страничные маршруты дверей процессов недоступны.

`install` `warn`: ход к двери через консоль здесь не нормируется.

`install` `refuse`: `/etc/w2c` или `/etc/<sub>` — настоящий каталог, не ссылка (цель `/etc/<sub>` — `/data/platform/etc/subsystems/<sub>`) — код 2.

`install` `refuse`: `W2C_DEPLOYMENT` не по грамматике N1.2 или значение окружения установщика расходится со строкой `w2c.env` — код 2. `install` `refuse`: `CONSOLE_ROOT` не по грамматике имени подсистемы (P/02.1 name) — код 2. `install` `refuse`: `DOMAIN_SERVER` не yes и не no или при повторе значение окружения установщика расходится со строкой `w2c.env` (строки нет — no; вывод называет оба значения и просит править строку руками, `w2c_env` выше) — код 2. `install` `refuse`: `TIMEZONE` окружения установщика пустое или не по грамматике договора файла окружения — код 2.

`install` `refuse`: цикл `worker.requests` / вида `domain.tokens` среди манифестов установки (near цикла не даёт),
ещё не стоящих в хранилище (`order` ниже), — код 2.

`install` `refuse`: генерация кандидата прав отказывает (глава 2.5 N3 «установить» п. 1). `install` `refuse`: отличие установленного файла прав от кандидата
не отказ: это штатная замена старых прав новыми, шаг «файл прав» ниже.

`install` `refuse`: имена ОС каталога не проходят `users_groups` `names`.

`install` `steps`: код атомарно (Source.new → Source) → раннер и скрипты → пользователи и группы → /data и ссылки → манифесты → окружение
и файлы ролей → режимы каталогов → ключ секретов, если нет → юниты (+ скрипт воркеров, polkit)
→ tmpfiles.d каталогов долей → центр: own для configstore, файл прав, drop-in групп → enable: хранилище, ждать его ответа `GET /v1/status`
→ manifest put в хранилище →
enable: ресурс, части подсистем, воркеры, контроллеры, консоль, домен, таймер скрипта воркеров. `install` `steps`: окружение и файлы ролей — никогда поверх существующих.

`install` `steps`: файл прав (глава 2.5 N3 «установить» п. 1): кандидат
`/etc/w2c/configstore-rights.json.new` генерируется из `MANIFEST_DIR`, `rights --check` кандидата, затем атомарное переименование
кандидата поверх установленного `/etc/w2c/configstore-rights.json`. `install` `steps`: файл прав: расхождение на `rights --check` — отказ, установленный файл цел.

`install` `steps`: enable хранилища: без его ответа `GET /v1/status` — отказ (глава 2.3).

`install` `steps`: manifest put в хранилище: строка манифеста есть — не меняется (`upgrade` шаг 3a).

`install` `steps`: enable домена: агент — всегда; `w2c-domain`, консоль домена и юниты воркеров на домене
N1.12 — при `DOMAIN_SERVER=yes` (`w2c_env` выше).

`install` `steps`: enable частей
— вместе с воркерами: юнит части никто не тянет `Wants`, без enable он не стартовал бы.

`install` `order`: manifest put — адресаты раньше клиентов: топологический порядок по `worker.requests` (его проверка каталога
P/02.1 N3 требует адресата в каталоге) и по виду токена домена — подсистема, объявившая вид в
`domain.tokens`, раньше подсистемы, чей `door.routes[].domain` его называет. `install` `order`: вид маршрута без объявителя в
каталоге — отказ каталога (P/02.1 N3). `install` `order`: среди готовых — по имени, байтами.

`install` `order`: связь к подсистеме,
уже стоящей в хранилище, порядка не задаёт. `install` `order`: связь к себе порядка не задаёт и цикла не даёт: подсистема сама объявляет вид и называет его в своём `door.routes[].domain`. `install` `order`: `placement.near.sub`, `worker.creates` и `worker.uses` порядка не задают
(их проверки ждут адресата, P/02.1 N3). `install` `order`: цикл — отказ установки кодом 2 на предварительной проверке, до изменений (векторы
[install-order](../../vectors/install-order/README.md)).

`install` `failure`: до изменения файлов проверить все доступные входы, пути, права, манифесты и генерацию. `install` `failure`: ошибка — ненулевой
выход с фазой/путём; не enable/start новые службы. `install` `failure`: после начала записи возможен частичный результат:
не обещать общий rollback; сохранить уже установленные файлы и журнал фаз, повторить после исправления. `install` `failure`: manifest put имеет собственный порядок и отказы глав 2.1, 2.3. `install` `failure`: существующие чужие файлы не перезаписываются.

`install` `files`: шаг «манифесты» кладёт в `MANIFEST_DIR` рядом с манифестом и его оболочку `<sub>.shell.html`, и файлы `console.files` под их
путями. `install` `files`: `MANIFEST_DIR` — единственный источник байтов manifest put (глава 2.3 N3 «Смена манифеста»); пакет развёртывания приносит их
рядом с манифестом.

`install` `files`: пакет развёртывания приносит и `<sub>.env` → `/etc/<sub>/<sub>.env`, `roles/<role>.env` → `/etc/w2c/roles/<role>.env` и каталог `<sub>/` с файлами настроек подсистемы, `<sub>/<name>` → `/etc/<sub>/<name>`: шаг «окружение и файлы ролей», после пользователей и
групп, кладёт их, режимы — N1.1, никогда поверх существующих: сам пакет этого не может, настоящий каталог `/etc/<sub>` — отказ, а групп до этого шага нет. `install` `files`: исключение одно — файлы вендора `<sub>/vendor/<name>` → `/etc/<sub>/<name>`, без подкаталога, оператор их не правит: при новом пакете заменяются атомарно. `install` `files`: при одном имени у файла вендора и файла настроек берётся файл вендора.

`install` `not`: сертификаты серверов, `CONFIGSTORE_JOIN` — рука оператора, до шага enable хранилища второго сервера.

### N1.9 Команды оператора

**Аргументы команд**

Нормативная таблица опций — [`forms/daemon-flags.tsv`](../../forms/daemon-flags.tsv); id команд, исполняемые файлы, постоянные префиксы argv и число позиционных аргументов — [`forms/operator-commands.tsv`](../../forms/operator-commands.tsv). Общее имя файла сохранено, но у P/02 аргументы операторских команд, а флагов демона нет. Таблица здесь не повторяется; процедуры ниже объясняют действие и нормы владельцев. Команда `operator-commands.tsv`, чьи опции вне этой формы — опция вне таблицы или другой команды, повторённая опция, `bool` со значением, опция без значения, значение вне своего `type`, невыполненное `required` или истинное `bad`, — ДОЛЖНА отказать с `command_options` [каталога отказов](../../forms/refusals.tsv): код 2, до любого действия (в хранилище ничего не записано, ни один файл не создан и не изменён), и её строка журнала в stderr называет опцию.

Грамматики делегированных команд остаются у владельцев: configstore admin_ops — [P/01.3 N1.3](../../../01-store/ru/spec/01.3-store.norms.md), `w2cctl domain move` — [P/08.8 N1.8](../../../08-domain/ru/spec/08.8-domain.norms.md); `install.sh` исполняет N1.7 выше.

Строки, которые пишут команды `w2cctl mirror`, `space` и `retention` (форма — раздел «Семьи данных» ниже):

```yaml
platform/space:          {enabled: true | false, high: 0.85, low: 0.75}   # доли; w2cctl space -high -low | -off
platform/mirror:         {enabled, copies}                                 # w2cctl mirror on|off; copies — целое ≥ 0
<sub>/retention:         {days}                                            # w2cctl retention <sub> -days N
<sub>/alarms_retention:  {days}                                            # w2cctl retention <sub> -alarms N
```

Единственный писатель строк `platform/space`, `platform/mirror`, `<sub>/retention`, `<sub>/alarms_retention` — admin, ресурс и консоль их
только читают; владелец строки — процесс-писатель.

Смысл этих строк и умолчания при чтении — [P/05](../../../05-resource/ru/spec/05-resource.norms.md) N1.3 `retention`, N1.4
`space`, `mirror`.

#### N1.9 Команда `w2cctl manifest get`

Перенос файлов манифеста на прочие серверы — и новой подсистемы, и изменённых
манифестов уже стоящих (backend, зависимые, владельцы): у них на сервере лежит прежний файл из пакета (порядок `add` N1.7, шаг
rollout `get`).

```yaml
get:       w2cctl manifest get <sub> --sha256 <хеш>; admin.sock; platform/manifest/<sub>
write:     MANIFEST_DIR: <sub>.subsystem.yaml, <sub>.shell.html, файлы files
check:     sha256(yaml), sha256 и size каждого файла; код 2
replace:   files и shell, yaml последним; <sub>.shell.html.old
untouched: файлы MANIFEST_DIR, которых строка не называет
not:       строка, метка, права, юниты
```

`get`: `w2cctl manifest get <sub> --sha256 <hash>` — `admin.sock` своего сервера; читает строку `platform/manifest/<sub>` (форма — глава
2.3 N1.5). `get`: `<hash>` — тот, что вывел manifest put первого сервера: сверка строки самой с собой ничего не доказывает.

`write`: в `MANIFEST_DIR`: `<sub>.subsystem.yaml` — байты `yaml` строки; `<sub>.shell.html` — байты `shell`, если есть (строка без `shell` — карантин прежней оболочки, ниже). `write`: файлы `files` — каждый
путь из части `platform/manifest/<sub>/files/<sha256>/<n>` (части по n от 0, склеенные), под своим путём рядом с манифестом.

`check`: все файлы, которые называет строка, пишутся во временные имена рядом с целью. `check`: sha256(yaml) и sha256 строки равны `<hash>`,
sha256 и size каждого файла — записи `files`. `check`: несовпадение, нет строки, нечитаемая строка или часть, ошибка записи — отказ,
код 2, временные удаляются, прежние файлы целы.

`replace`: после всех сверок — замена прежних названных строкой файлов, каждого своим атомарным переименованием временного поверх
цели: сначала `files` и `shell`, `yaml` последним. `replace`: строка без `shell` (поля нет или оно пустое, глава 2.3 N1.5): вместо замены
оболочки прежний `<sub>.shell.html`, если есть, переносится атомарным переименованием в карантин — `<sub>.shell.html.old` рядом
(прежний `.old` заменяется), имя, которого manifest put и install не читают: иначе следующий put прочёл бы прежнюю оболочку
и вернул страницу в ревизию без неё (глава 2.3 N3 «Смена манифеста» п. 3). `replace`: обрыв между файлами оставляет часть новых при прежнем `yaml`. `replace`: повтор get с тем
же хешем сходится: файл, уже равный байтам строки, не трогается, остальные заменяются, оставшаяся при строке без `shell`
прежняя оболочка уходит в карантин, `yaml` снова последним. `replace`: хеш
оператора и есть защита: прежний файл заменяется только байтами, которые оператор назвал.

`untouched`: файлы `MANIFEST_DIR`, которых строка не называет, get не трогает, кроме прежней оболочки выше: её имя неявное,
put читает `<sub>.shell.html` без объявления. `untouched`: при отказе get (`check` выше) ничего не переносится, прежняя оболочка тоже. `untouched`: файл `files` прежней ревизии, который новая снимает,
остаётся на месте, не возвращается и ничего не значит: install и manifest put читают только пути `files` своего манифеста (N1.7 `files`;
глава 2.3 N3 «Смена манифеста»); убирает его оператор, если хочет.

`not`: get строку не меняет и метку не двигает; права и юниты — дело install.

#### N1.9 Команда `w2cctl rollout`

Шаг обхода одного сервера (порядок `add` N1.7). Запускает оператор на каждом сервере по очереди.

```yaml
rollout:   w2cctl rollout <sub>=<sha256>… [-allow-downtime] [-last]
mode:      GET /v1/status admin.sock: Leader | Follower — голосующий; Door — дверь без голоса
done:      «already done», код 0
pre:       кворум — ⌊voters / 2⌋ + 1; живых ≥ кворум + 1; ROLLOUT_WAIT
  leader:  -last
poll:      Platform/02-installer/forms/rollout-poll.machine.yaml
  why:     обоснование
  other_order: иной порядок чтений
  bound:   пределы опроса
steps:     1 manifest get; 2 install с W2C_HOLD; 3 права; 4 консоль
barrier:   хранилище; консоль
  limit:   пределы оператора
  console: CONSOLE_HOST, CONSOLE_PORT; W2C_TOKEN
  wait:    ROLLOUT_WAIT; раз в 1 с
ROLLOUT_WAIT: 300 с
failure:   ненулевой код с именем шага
not:       юниты, строки хранилища
unproven:  пределы модели
```

`rollout`: `w2cctl rollout <sub>=<sha256>… [-allow-downtime] [-last]` — все манифесты обхода, каждый со своим хешем (N1.7 `add` шаг 0). `rollout`: `<sub>` по грамматике P/02.1 name, `<sha256>` — 64 строчные hex, повтор `<sub>` — отказ, код 2, до любых действий.

`mode`: по своему члену — `GET /v1/status` `admin.sock` (P/01.3 N2): state Leader или Follower — голосующий; Door — дверь без голоса
(P/01.3 N1.3 door); иное — отказ, код 2.

`done`: шаг 1 (get всех манифестов обхода) и сверка консоли идут всегда, и на пройденном сервере: иначе сервер со старым файлом
манифеста в `MANIFEST_DIR` (backend, у которого сменились только calls, — права те же) следующим install вернул бы прежние
байты. `done`: барьер (ниже, хранилища и консоли) судится всегда, и при «already done». `done`: после get права равны и барьер выполнен —
вывод «already done», код 0, ни член, ни консоль не перезапускаются. `done`: права равны, а барьер не выполнен (член отстаёт, лидера
нет) — ждать барьер, как после перезапуска, код 0 только по нему; так повтор обхода находит первый непройденный сервер.

`pre`: голосующий — перед действиями и ещё раз перед перезапуском члена: опрос (`poll` ниже); проход — первая партия, где живых
≥ кворум + 1 (кворум — ⌊voters / 2⌋ + 1). `pre`: прохода к сроку `ROLLOUT_WAIT` нет — отказ, код 2, «not enough live voters», отказ только по
сроку: у трёх голосующих с одним мёртвым перезапуск одного терял бы кворум.

`pre`: голосующих не больше двух —
только с `-allow-downtime`, кластер недоступен на время перезапуска члена (у двух теряется кворум 2 из 2), и опроса нет. `pre`: два голосующих без флага — отказ по сроку выше, названный предел.

`pre`: число голосующих
и флаг судятся до выбора между `pre` и проверкой `-last` (`leader` ниже), и у лидера. `pre`: два голосующих с `-last` и
без `-allow-downtime` — счёт `pre`, а не `-last`, поэтому опрос не проходит никогда: отказ по сроку, «not enough live voters».

`pre`: два голосующих с флагом — опроса нет, и с `-last`.

`pre`: один голосующий судится до автомата (его вход — ≥ 2 голосующих): с
`-allow-downtime` опроса нет; без флага — отказ сразу, код 2, «not enough live voters», до действий.

`pre`: при трёх голосующих
и больше `-allow-downtime` ничего не меняет.

`pre`: дверь в счёт голосующих не входит, её перезапуск кворума не трогает: у двери `pre` нет.

`pre` `leader`: свой член — лидер, голосующих больше одного — только с `-last`: оператор подтверждает, что прочие серверы пройдены, — права
других членов с сервера лидера не видны, `admin.sock` не пересылается. `pre` `leader`: что видно, команда проверяет сама: с `-last` и ≥ 3 голосующих оба `pre`
заменяет проверка `-last` (перед действиями и перед перезапуском своего члена); её проход — первая партия, где жив каждый прочий голосующий, а не
кворум + 1. `pre` `leader`: прохода проверки `-last` к сроку `ROLLOUT_WAIT` нет — отказ, код 2, «-last: voters not live».

`pre` `leader`: лидерство своего
члена судится при `mode` и в каждой партии каждого опроса, отказ сразу, не по сроку.

`pre` `leader`: с `-last` свой член не
Leader или его `leader_id` — не свой id — код 2, «-last: not the leader».

`pre` `leader`: без `-last` свой член Leader, голосующих больше одного — код 2, «leader goes last».

`poll`: норма опроса — автомат [`rollout-poll.machine.yaml`](../../forms/rollout-poll.machine.yaml): опрос
(`pre` перед действиями, `pre` перед перезапуском члена, проверка `-last` — каждый заново, со своими целями), партии статусов
по часам, ответ своего члена (лидер партии по `leader_id`, сверка состава по нему и по ответу лидера партии — «voters changed», лидерство — «-last: not the leader»,
«leader goes last»), живой ответ, цель и её чтение, разрыв, суд партии, срок `ROLLOUT_WAIT`, таймеры и порядок событий
одного мига (env) — там. `poll`: где проза и автомат расходятся,
действует автомат; проза даёт только обоснование (`why`), иной порядок (`other_order`), пределы (`bound`) и непроверенное (`unproven`).

`poll`: голосующие — `voters` статуса своего члена при `mode`, адреса — `members` того же ответа. `poll`: голосующего
без записи в `members` (нет `-api`) не опрашивают: ответа нет, следующая партия ставит ему разрыв, как любому чтению без ответа (`send_status`). `poll`: живой ответ
сравнивается с ответом своего члена по `leader_id`, адрес `leader` нужен только для чтения цели.

`poll`: повтор `rollout` начинает с
нового `mode` и нового состава, повтор обхода находит первый непройденный сервер (`barrier`).

`poll` `why`: HTTP-ответ не значит «в группе»: член с закрытым портом `-raft` отвечает, а журнала не получает — живой ответ требует
state Leader или Follower и того же `leader_id`. `poll` `why`: цель — commit, прочитанный после живого
ответа: голосующий, лежавший при чтении, иначе засчитался бы по старому. `poll` `why`: без разрыва цель не
двигается: иначе здоровый кластер под непрерывной записью отказывал бы по сроку. `poll` `why`: разрыв снимает цель: иначе упавший посреди опроса и поднявшийся отстающим засчитывался бы по старой.

`poll` `why`: партии по часам, срок чтения — до следующей партии, чтение цели отдельно и не задерживает партию: так два
наблюдения голосующего не дальше 2 с врозь. `poll` `why`: счёт — по ответам одной партии: засчитанного тоже
опрашивают, иначе его разрыв не виден. `poll` `why`: состав сверяет каждый полученный ответ своего члена, и без
leader: иначе join или leave посреди опроса дали бы перезапуск без кворума; и ответ лидера партии: свой член-ведомый может применить join позже лидера.

`poll` `other_order`: иной порядок чтений допустим, если цель каждого голосующего не ниже commit, прочитанного после первого живого ответа
голосующего после его последнего разрыва (или после начала опроса), и без разрыва цель в опросе не двигается. `poll` `other_order`: порядок такого
опроса реализация называет явно («Решает реализация»).

`poll` `bound`: пределы опроса ниже названы; правила для них нет. `poll` `bound`: голосующий, отрезанный от группы после последнего чтения его статуса или меньше
чем за срок выборов до него, показывает прежние state и `leader_id` — то же, что упавший после проверки; отрезание короче 2 с плюс срок выборов опрос может не увидеть. `poll` `bound`: граница наблюдения падения —
два наблюдения одного голосующего (миги ответов соседних партий) разделены не больше чем 2 с, падение и подъём короче 2 с
опрос может не увидеть. `poll` `bound`: перезапуск члена по `RestartSec=2` держит его лежащим 2 с плюс время запуска и попадает хотя бы в
одну партию.

`poll` `bound`: `voters` и `members` своего члена могут отставать от лидера, пока свой член не
применил смену состава, поэтому состав сверяет и ответ лидера партии. `poll` `bound`: смена состава после ответов своего члена и лидера в партии прохода.

`steps` 1: `manifest get <sub> --sha256 <hash>` для каждого (выше).

`steps` 2: install с `W2C_HOLD` — имена всех `<sub>` обхода, чьи юниты на
сервере не включены (новые подсистемы обхода; и при повторе `rollout`, когда юниты уже поставлены выключенными: иначе повтор
включил бы их до конца обхода; N1.7 `w2c_env`).

`steps` 3: права: `GET /v1/rights` своего члена по смыслу
равен файлу, собранному из `MANIFEST_DIR` (то же сравнение, что `rights --check`, P/02.5 N3 «установить») — члена не
перезапускать. `steps` 3: иначе `pre` ещё раз и перезапуск члена configstore (рестарт по `member.json`, не join; N3 «старт сервера» шаг
1). `steps` 3: в обоих случаях — барьер хранилища.

`steps` 4: консоль: у каждого `<sub>` обхода `/manifest/<sub>/source` отвечает — консоль служит им и подхватит новую ревизию по метке
сама (P/02.3 N3 «Смена манифеста»), ждать барьер консоли. `steps` 4: хоть один — 404 (подсистемы нет в каталоге запуска) — перезапуск
консоли этого сервера, затем барьер консоли. `steps` 4: переключение плагина, которое меняет у работающих подсистем только
`door.pass.calls` (P/02.5 N1.5, не префиксы файла прав N1.4), обычно кончается без перезапусков.

`barrier`: хранилище — голосующий: `GET /v1/rights` своего члена ≡ файлу обхода (как шаг 3), его `leader_id` равен `leader_id` из `GET
/v1/status` лидера (адрес `leader` своего статуса), его `applied` ≥ `commit` лидера, прочитанного после шага 3 (после перезапуска,
если он был).

`barrier`: хранилище — дверь: `GET /v1/rights` ≡ файлу обхода и чтение строки метки `platform/manifest/<sub>/rev` первого `<sub>` обхода через
сокет роли console своей двери — 200: пересылка к группе работает. `barrier`: `applied` двери всегда 0 и не сравнивается.

`barrier`: консоль — `GET /manifest/<sub>/source` своей консоли (P/06.5 N2) у каждого `<sub>`
обхода: `source.sha256` равен хешу обхода и `source.served` равен rev строки `platform/manifest/<sub>` хранилища (её читает
rollout через `admin.sock` своего члена). `barrier`: равенство `served` и `rev` внутри одного ответа `/source` не проверяется — они в нём
всегда равны (P/06.5 N2 «served = rev»). `barrier`: `served` новой подсистемы может прийти и до обхода этого сервера — по метке backend, чьи calls её называют: допустимо,
барьер консоли это не отменяет.

`barrier`: новых полей у хранилища и консоли нет.

`barrier` `limit`: два rollout одновременно — на одном сервере или на разных — предел оператора: команда это не судит, порядок «по одному»
держит оператор. `barrier` `limit`: состав хранилища (join, leave, admit; P/01.3 N1.3) во время rollout не меняют — тоже
предел оператора, команда это не судит, кроме сверки состава в каждой партии (`poll`).

`barrier` `console`: запрос к своей консоли — `CONSOLE_HOST` и `CONSOLE_PORT` `w2c.env` (N1.7 `w2c_env`). `barrier` `console`: консоль без домена открыта с петли (P/06.3
N1.3 open); с доменом — токен администратора на "*" из значения окружения `W2C_TOKEN`.

`barrier` `wait`: барьер ждёт не дольше `ROLLOUT_WAIT`, опрос раз в 1 с. `barrier` `wait`: не дождался — код 2, вывод называет невыполненную часть барьера
(`leader_id`, `applied`, права, чтение через дверь, sha256 или served `<sub>`); обход стоит, следующий сервер оператор не трогает.

`failure`: любой шаг — ненулевой код с именем шага, без отката. `failure`: повтор той же командой безвреден: get с теми же файлами — 0, install
повтором — обновление, перезапуск и барьер — снова.

`not`: rollout юниты подсистем обхода не включает (N1.7 `add` шаг 2), строк хранилища не пишет.

`unproven`: что модель обхода не доказала — принято как предел: барьер «всегда» проверен только симулятором, исчерпывающая проверка
не доходит; цель опроса исчерпывающе — одна конфигурация и один судья,
прочее — симулятором; часть `-last` моделью не проверена (её мутант не пойман);
повтор обхода и второй сервер; падение голосующего посреди опроса и висящее чтение статуса — внешнее
событие, судья цели опроса его не судит. Не доказаны также: безопасность и порядок опроса во всякой конфигурации,
два мутанта опроса не пойманы; `-allow-downtime` с одним голосующим; связь двух `pre` с барьером;
висящее `admin.sock` как отдельный вид; запись без кворума у отрезанного лидера. `unproven`: порядок обхода в реализации не судит ни один автоматический прогон: P/02.4-22
«реализацией не прогнано», сц. 09 системной приёмки — @manual.

#### N1.9 Команды `w2cctl secrets`

Конверт, кольцо и AAD — [договор запечатывания](../../../common/ru/contracts/sealing.md).

```
w2cctl secrets new [<путь>]
w2cctl secrets seal [<префикс>…]
w2cctl secrets rotate [<путь>]
w2cctl secrets status [<префикс>…]
```

`new` — создать кольцо (O_EXCL, 0640); путь внутри хранилища — отказ.

`seal` — запечатать/перезапечатать открытые и старые по `cas` (исходы значения — договор запечатывания «Перезапечатать значение»); код 1, если что-то осталось.

`rotate` — новый ключ сверху.

`status` — clear / current / older / ?; код 1, если есть открытое при наличии кольца или ? > 0.

Префиксы `seal` и `status`, их умолчание D и обходимые строки — «Обход» ниже. `status` и `seal` обходят `*_secret` на любой глубине, в том числе внутри значения json-поля.

Конверт считается
`current` или `older`, только если открывается ключом своего kid с AAD своего места (договор запечатывания). Известный kid, который не
открывает (конверт перенесён на чужое место, испорчен), — `?`, как чужой kid.

`seal` на конверте, который не открывается, не обрывает обход: он доводит его до конца и отвечает кодом 1 — что-то осталось.

Пустое значение `*_secret` в счёт не входит. Нестроковое значение `*_secret` (число, объект, массив, bool) — в счёт `?`. `status` при `?` > 0
— код 1, как `seal` с оставшимися `?`; обход продолжается, значений в выводе нет.

**Обход.** Это одно правило называет строки, которые обходят `status` и `seal`; на него ссылаются перечень Data в N1, список команд выше и строки
14–16 главы 2.4 в [`refusals.tsv`](../../forms/refusals.tsv); семьи — семьи вида `row`
[каталога данных](../../../common/data/catalog.tsv):

```yaml
prefixes:  P — argv; D — domain/, identity/, <sub>/<manifest:unit.rows>/<id>, <sub>/<manifest:tables>/<name>
selected:  строки хранилища под P
kept:      domain/<sub>/<manifest:domain.kept>[/…]
walked:    door/signer, domain/signer, domain/signer-pending, domain/book-seal, domain/member-key, domain/users/<name>,
           domain/break-glass/<cluster>, <sub>/<manifest:unit.rows>/<id>, <sub>/<manifest:tables>/<name>
other:     domain/keys, domain/root, door/keys, …
join:      domain/join
unknown:   identity/x, domain/<неизвестное имя>, <sub>/<неизвестное имя>
```

`prefixes`: P — префиксы из argv, каждый — простой префикс ключа строки. `prefixes`: без префиксов — умолчание D: строки под `domain/`,
строки под `identity/` и строки семей `<sub>/<manifest:unit.rows>/<id>` и `<sub>/<manifest:tables>/<name>`
каждого манифеста в хранилище (`platform/manifest/<sub>`).

`selected`: строки хранилища под P (для D — строки, названные в D).

`kept`: выбранная строка `domain/<sub>/<manifest:domain.kept>[/…]` (писатели `<s>domain` и domain) выходит из выбора: она не
читается, не считается, не unknown-row-form и на код не влияет — одинаково под D и под заданным префиксом.

`walked`: выбранная строка строковой семьи каталога данных, у которой писатель — `admin(w2cctl secrets seal …)`: `door/signer`,
`domain/signer`, `domain/signer-pending`, `domain/book-seal`, `domain/member-key`, `domain/users/<name>`,
`domain/break-glass/<cluster>`, строки единиц и таблицы манифестов. `walked`: обходимая строка читается по схеме своей семьи, её
значения — по «Перезапечатать значение» договора запечатывания; `status` считает только эти строки, `seal` пишет только их. `walked`: `door/signer` вне D — его выбирает только заданный префикс (`door/`).

`other`: выбранная строка другой строковой семьи каталога данных (`domain/keys`, `domain/root`, `door/keys`, …) не обходится: она
не считается, не пишется и на код не влияет.

`join`: `domain/join` несёт `seed_secret`, но её писатель — только join (create): она не обходится — `seal` её не перезапечатывает,
`status` её не считает; исключение названо здесь, писателя admin нет.

`unknown`: выбранная строка, не подходящая ни к одной строковой семье каталога данных (`identity/x`, `domain/<unknown name>`, под заданным
префиксом `<sub>/<unknown name>`), перечисляется, а не пропускается: unknown-row-form ниже, код 1 у `status` и у `seal`. Неизвестная строка — полей не угадывать: строку не трогать (байт в байт), строка журнала «`<object-key>` unknown-row-form» без
значения, обход продолжается, итог — код 1, что-то осталось.

Обходимая строка, которая не читается (исход её семьи, `<family>.outcomes.tsv`), у `seal` и `status` — так же: строку не
трогать (байт в байт), строка журнала «`<object-key>` unreadable» без значения, обход продолжается, итог — код 1; это одно
правило для всех семей, которые обходит команда. Хранимые строки выходят из выбора
(«Обход» `kept`). Коды `seal`/`status` выше относятся к названным исходам; форма их текстового вывода остаётся
реализации.

`new`/`rotate`: успех — 0, отказ — ненулевой код и причина без ключевого материала.

Отказ `new` при существующем файле его не меняет.

Отказ проверки кольца у `rotate` сохраняет
прежний файл.

При недоступности обхода `seal`/`status` не заявляют успешное завершение и не
считают непрочитанные строки отсутствующими.

Проверка `status` не охватывает резервные копии:
вывод status не является разрешением удалять ключи — в профиле урока они сохраняются,
включая ключи конвертов, копий и отпечатков живых заявок. Вывод из обращения ключей требует
отдельной процедуры и в команду `status` не входит (копии — P/08.8 N1.5).

#### N1.9 Команда `w2cctl tls status`

```
w2cctl tls status
  читает: пульсы ресурсов кластера (door: {addr, mode, cert_until}; mode: loopback | mtls); комплекты W2C_TLS_DIR
  вывод:  строка на дверь — сервер, роль, адрес, режим, cert_until
  код:    0 | 1 | 2
```

`w2cctl tls status`: входа нет; право admin (`admin.sock`), только чтение: ничего не пишет.

Читает: пульсы ресурсов кластера (поле `door` двери процесса — `{addr, mode, cert_until}`, слова `mode` — `loopback | mtls`; пишет ресурс, P/05 N1.4) и комплекты `W2C_TLS_DIR` своего сервера (N1.6 `kit`).

Вывод: строка на дверь — сервер, роль, адрес, режим, `cert_until`; форма строки — реализации (как у `secrets status`),
нормативны набор строк, поля и коды. Вывод: роль с комплектом на своём сервере без живого процесса (нет пульса) —
двери нет: строка по комплекту без адреса, с режимом и `cert_until`. Вывод: истёкший сертификат комплекта без двери — код 1
(роль не поднимется).

Код: 0 — нет двери `loopback` с адресом вне петли и нет истёкшего `cert_until`; 1 — есть такая дверь или истёкший
`cert_until` двери или комплекта; 2 — чтение не подтверждено (хранилище или пульс не ответили, комплект не читается).

### N1.10 Кластер из одного

```yaml
form:      коробка этой главы (N1.1–N1.9); хранилище file:// или в процессе без двери (P/01.1-22)
controller: один
member:    для домена — член, как любой
boot:      /etc/w2c/boot-rows.json — [{key, fields}…]
doors:     503 {error: "not_ready"}
```

`form`: все процессы на одной коробке; хранилище file:// или в процессе без двери (P/01.1-22). `form`: манифест МОЖЕТ быть встроенным (глава 2.3 N1.5 — процесс со встроенным манифестом сам себе писатель строки и метки). `form`: встроенный манифест — канонического вида тем же правилом (глава 2.2 N3). `form`: части файлов `console.files` — тем же правилом: источник байтов — файлы рядом со встроенным манифестом или в той же сборке
(глава 2.3 N1.5).

`controller`: есть, как у любого кластера: один писатель размещения (P/04) и шарда снимка (P/04 N1.3a).

`controller`: без шарда агент
не отчитывается (P/09.1 N1.2 ready).

`member`: для домена — член, как любой: приём, отчёт, ответ держателя, правки без изменений.

`boot`: `/etc/w2c/boot-rows.json` — `[{key, fields}…]` строк единиц и таблиц: загрузочная запись без человека (камера: `cam/cameras/1`, `rec/volumes/card`, `backend/instances/main`; бюджет памяти backend на камере — замером после генерации). `boot`: консоль при старте до открытия дверей пишет те, которых нет, тем же путём «создать» (P/06.1 N3), by — boot. `boot`: строка есть — не трогает, файл правкой строки не служит. `boot`: файл не по форме — отказ старта, код 2, строка лога называет ключ. `boot`: файл не прочитан или запись не удалась (таблица, карта, обрыв) — старт идёт, журнал, строка на следующей загрузке: иначе коробка без человека теряет дверь и `/api/held`.

`doors`: двери процессов кластера из одного (консоль, дверь держателя и прочие двери процессов) до первой публикации —
пока нет шарда снимка каждого манифеста каталога с `domain.ref`, как ready агента (P/09.1 N1.2), — отвечают 503
`{error: "not_ready"}`. `doors`: слушать порт раньше МОЖНО.

### N1.11 Горячее и долговечное на коробке

Запись дома только при отличии (`home_write`) и метки свежести (`fresh`, `FRESH_EVERY`) — [P/09.1 N1.4](../../../09-agent/ru/spec/09.1-agent.norms.md).

```yaml
hot:       <sub>/heartbeats/*, <sub>/snapshot/*, <sub>/snapshot-tables/*
durable:   строки хранилища, эпоха, строки, которые приносит агент; as_of копии domain/grants
```

`hot`: объекты `<sub>/heartbeats/*` (P/03.4 N1.1), `<sub>/snapshot/*` (P/04 N1.3a) и `<sub>/snapshot-tables/*` (N1.3b) на коробке МОГУТ жить в памяти
хранилища объектов коробки — хранилище в процессе (P/01.1-22) или tmpfs, — а не в памяти каждого писателя. `hot`: читатели на той же коробке (консоль, агент, контроллер) видят горячие объекты тем же чтением. `hot`: после перезапуска коробки горячих объектов
нет, и это верно — пульс из прежней жизни говорит о прошлом.

`durable`: строки хранилища, эпоха (P/03.2), строки, которые приносит агент, — на носителе, как прежде. `durable`: одно освежение
`as_of` копии `domain/grants` — на носитель не чаще раза в час, в памяти — раз в `FRESH_EVERY` (P/09.1 N1.4 fresh,
`AS_OF_STORE_EVERY`; для любого кластера).

### N1.12 Порты и юниты домена

Поздний слой главы, его вводит глава [8.10](../../../08-domain/ru/spec/08.10-domain.norms.md).

Общее юнитов (`Restart`, раннер, `ProtectSystem`) — N1.1 (строки юнитов домена — здесь).

Процессы
домена — `domain`, агент (и в режиме ретранслятора), консоль домена — исполняют сторону читателя строки манифеста

`w2c-domain.service` — роль domain; `SIGNER_HOST`,
`SIGNER_PORT` юнит не пишет: умолчание процесса 0.0.0.0:8445 (lifecycle P/08) — не явный адрес,

`w2c-domainagent.service`: на каждом сервере кластера-члена активен один — очередь `domain/agent-turn` (P/09.1 N1.13). `w2c-domainagent.service` — роль domainagent; `SECRETS_KEY` (credential) — ключ члена и конверты кольца (P/06.2 N1.2 holders). `w2c-domainagent.service`: своего
порта нет; дверь ретранслятора — P/09.2 N1.1 `door`. `w2c-domainagent.service`: `RELAY_HOST`, `RELAY_PORT` юнит не пишет: умолчание процесса

`<dep>-<sub>domain.service`: воркер подсистемы на домене (P/03.7 N1.6 `domain_worker`) — на каждом сервере, где установлен

манифеста тем же порядком, что `worker <sub> <slot>`, без аргумента слота, `W2C_MANIFEST_REV`
(P/02.3 N3). `<dep>-<sub>domain.service`: `TimeoutStopSec` —
`worker.stop_timeout` манифеста (N1.1).

`local_door`: местная дверь агента — договор local-token-door «Сокет роли»: Unix-сокет `<AGENT_TOKEN_DIR>/<role>.sock`,
юниты `w2c-domainagent-token-<role>.socket`.

`local_door`: порты 8444–8447

## N3 Проход

### старт сервера

1. configstore: `member.json` есть → рестарт (не join); нет → `-bootstrap` (первый) | `-join` (остальные). Шаг 1: сокеты ролей по файлу прав; без `-rights` — только `admin.sock`. Шаг 1: адрес вне петли без `-tls` → не стартовать.

2. ресурс: пульс сразу, поток пульса; restore (P/05 N1.4) в своей попытке; строка двери `platform/doors/<s>` с `at` (P/05 N1.4).

3. контроллеры манифестов: манифест из строки хранилища (глава 2.3). Шаг 3: первые 45 с контроллеры никого не судят.

4. консоль: манифесты из строк, оболочка root, перезапечатывание секретов (P/06.2 N3), жнец просьб и отметки тел. Шаг 4: удаление тел — только в отдельном окне обслуживания P/06.1 N2.

5. части подсистем (parts), затем воркеры: манифест, бюджет памяти, захват имени (P/03.2). Шаг 5: на Linux порядок даёт `After=`
юнита воркера (N1.1). Шаг 5: на macOS launchd порядка не гарантирует — воркер ждёт долю своей части сам, с паузой, до
первого действия с ней.

6. скрипт воркеров по таймеру: ряды `workers_wanted` из `/metrics` → start/stop экземпляров n ≥ 2 в пределах потолка (N1.5).

Шаги 2–5: первым действием каждого процесса платформы и воркера (не части) — проверка схемы (P/06.6 N3 «старт консоли — проверка схемы», общий блок), до чтения манифеста.

**Гонки.** `After` задаёт порядок запуска, но не готовность хранилища, прав или манифеста. Каждый процесс ждёт достоверного чтения до своего первого действия. Временная недоступность — ожидание с паузой до `START_WAIT` (P/02.3 N3 «Старт процесса»), затем выход 1, который супервизор перезапускает. Ошибочная конфигурация/схема — выход 2 без перезапуска (`RestartPreventExitStatus=2`, N1.1).

Один экземпляр юнита не исключает другой юнит/ручной процесс; единственность писателя обеспечивают слоты и роли, не systemd.

### выпустить и отозвать сертификат

issue: `w2c-ca.sh issue <server> <role>` → комплект; `own <dir> <role>` → режимы; скопировать на сервер; процесс читает по `W2C_ROLE`.

revoke: `w2c-ca.sh revoke <server>` → revoked/crl; скопировать на каждый сервер (процессы перечитывают); `configstore leave <server>`
у лидера. revoke: сервер без комплекта — дверь на петле.

**Гонки.** Изменения состава выполняет один оператор последовательно. Force допускает только временную чётность в пределах объявленного максимума.

Сертификат и leave распространяются разными действиями: до доставки отзыва всем узлам нельзя утверждать, что он везде действует.

Запуск и остановка скрипта воркеров сериализованы по N1.5. Отсутствие пульса не освобождает зарезервированный номер.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как объявляются пользователи, группы и каталоги** (`sysusers`/`tmpfiles`, `useradd` в установщике, launchd на macOS) и их числовые id; каталоги долей в `/run` — нормой tmpfiles.d установщика (N1.1 `dirs`), на macOS — способ реализации при той же раскладке; числовые id и способ объявления не судятся: имена — норма (P/02.4-R062), юниты, пользователи, группы и каталоги N1.1 проверяет P/02.4-03;
2. ~~**как демон получает группы ролей или обходится setgid**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита `configstore-<роль>.socket` (N1.1, P/01.3 N1.3 `sockets`);
3. **форму доставки** сверх systemd/launchd (Quadlet, Nomad) и чем она отличается (группы, порты); юниты N1.1 проверяет P/02.4-03, иная форма доставки не судится;
4. ~~**порты домена** и его юниты~~ — нормированы: N1.12 (строки юнитов N1.1 выше);
5. **как ведёт себя `status`/`seal`** без манифестов в хранилище; наблюдаемое следует «Обходу»: без манифестов D по умолчанию — строки под `domain/` и `identity/` (P/02.4-R386), коды — по P/02.4-R372 и P/02.4-R374;
6. **форму вывода `secrets status` и `seal`**: она ДОЛЖНА называть счёты clear, current, older и `?` по названным
   префиксам; остальное — выбор реализации;
7. **комплект сертификатов роли**: где лежит, кто выпускает (договор сертификата роли `kit` `/etc/w2c/tls/<роль>/`, выпуск — N1.6 `w2c-ca.sh issue <server> <роль>`);
8. **команду установки домена** (N3 «установка домена»: имя, аргументы, где файл восстановления, как команда узнаёт каталоги
   хранилища, объектов и их копий, внутри которых файл запрещён); стенд главы 8.3 называет её строкой словаря
   (`@install domain`); вызов плановых смен и смены после кражи — [P/08.2](../../../08-domain/ru/spec/08.2-domain.norms.md)
   «Решает реализация» п. 2.
