### N1.3 Секретные строки и читатели

```yaml
secrets:                                     # раздел манифеста (форма — глава 2.1)
  readers: {<строка или префикс>: [<роль>…]} # свои секретные строки и кто их читает
  reads:   [<строка или префикс>…]           # чужие строки, которые читает воркер этого манифеста: ДОБАВЛЯЕТ <B>worker к читателям,
                                             # ничего не отнимает; секретной строку делает только readers (своего манифеста или
                                             # другой) или platform_readers — необъявленная семья остаётся у своих ролей (N1.4)
roles:     [console, controller, worker, domainworker, domain, domainagent, resource, domainconsole]   # закрыто; domainworker, domain, domainagent, domainconsole — роли домена (M11); domainworker — слово платформы для роли <sub>domain воркера на домене (N3 шаг 1, у манифеста с kept или переносимой книгой; P/03.7 N1.6), манифесты подсистем его не включают
platform_readers:                            # векторы platform-lists (vectors/platform-lists/cases.tsv); строки domain/* — урок P/08 и M11 (signer, signer-pending, book-seal — P/08.2 N1.3–N1.4)
  domain/break-glass/: [console, domain, domainagent]
  domain/signer:       [domain]
  domain/signer-pending: [domain]           # точное имя, не покрыто `domain/signer`
  domain/book-seal:    [domain]
  domain/users/:       [domain]
  domain/member-key:   [domainagent, domain]            # форма — P/09.1 N1.1 (domain — только подпись GET /api/backup, P/08.8 N1.8 шаг 5); открытый ключ — несекретно в domain/member и Entry.key
                                            # резервные копии P/08.8 N1.5 — объекты, не строки-секреты: в списке их нет
  door/signer:         [console]             # (подписант токена P/06.5 N3 «/where/<id>»); консоль читает его всегда — выдача токена
                                            # (P/06.5) и перезапечатывание при старте (P/06.2) — не завися от secrets.readers манифеста; объявление манифеста
                                            # читателей добавляет, консоль не отнимает
rule:      объявления secrets.readers/reads не содержат буквальный `*`, не начинаются с `!` или `delete:`;
           непредставимое объявление отвергается загрузчиком/генератором до выдачи файла, не экранируется и не усекается.
           Ограничение относится к объявлениям прав, не к общему ключу хранилища P/01.1.
           Ключ с `/` на конце — префикс, без него — точный ключ (`domain/<sub>/<книга>` не закрывает `domain/<sub>/<книга>/*` — потому они названы отдельно);
           книга домена у члена — точное имя `domain/<sub>/<книга>`, её строки по кластерам у держателя — префикс `domain/<sub>/<книга>/` (манифест называет оба);
           объявления не пересекаются по закрываемым строкам: два префикса, где один — начало другого (`a/` и `a/b/`), — отказ
           загрузчика; точное имя и префикс с тем же началом (`domain/signer` и `domain/signer-pending`,
           `domain/<sub>/<книга>` и `domain/<sub>/<книга>/`) не пересекаются — точное имя закрывает одну строку,
           префикс — строки под `/`; потому «самого длинного совпавшего» нет: у строки ровно одно объявление; объявленная секретной строка без читателя не читается никем, кроме admin (у манифеста такой строки нет: список читателей `secrets.readers` не пуст — форма P/02.1, `[]` — отказ загрузки);
           файл прав не генерируется, если читатели ≠ способные прочесть (N3 шаг 4)
```

### N1.4 Вывод прав из манифеста

Положительные списки ниже — исходные права, не обход P/01.2 N1.3: never применяется ко всем,
включая admin, независимо от файла прав (P/01.2 N1.3 never — ровно три: delete строки `<x>/epoch/<y>` — один сегмент `<y>`
после «`<x>/epoch/`», в том числе пустой, `x` ≠ `platform`; delete под `domain/` не ролью домена — `domain`, `domainagent`, `<sub>domain`;
write и delete `platform/epoch_floor`); отрицания секретных читателей N1.3 вычитаются из read.

Писатели семей — [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) и P/03 (строки единиц, слоты, эпохи), [P/04](../../../04-controller/ru/spec/04-controller.norms.md), P/05; [договор просьбы и её метки](../../../common/ru/contracts/request-mark.md) и P/06.4 N1.5 (`<s>/requests/*`, `<s>/asked/*`); P/06.6 N1.1a, N1.2 (`platform/schema`, `platform/drain`), P/06.1 N1.5, N1.6 (`<s>/sweep`, `<s>/<таблица>/*`); здесь сводка того, что генератор выводит для каждой роли из ключей манифеста. Права чтения — положительные списки, выведенные так же; секретные строки читают только объявленные читатели (N1.3).

Общие правила вывода действуют на каждую строку таблицы, строка их не повторяет:

- в `read` каждой роли входит `platform/manifest/*` — манифесты кластера, по которым она работает, если его
  не покрывает уже `platform/*`;
- в `read` входят все положительные образцы её `write`; образцы только удаления (`delete:…`) и отрицания `write`
  в `read` не входят;
- отрицания `!<s>/idem/*` и `!<s>/asked/*` (заявки и учёт людей — только консоль) получают только роли, чьи чтения
  их достают (образец, покрывающий `<s>/*`); объявление, прямо называющее строку или префикс внутри `<s>/idem/` или
  `<s>/asked/` для роли, кроме консоли (`worker.reads`, `secrets.reads`, `secrets.readers` с иным читателем), — отказ
  генерации до файла, не вычитание и не доступ; файл прав для одних входов байт-стабилен;
- слова `secrets.readers`: `controller` и `worker` — роли объявляющего манифеста (`<s>controller`, `<s>worker`),
  остальные — платформенные роли как есть, `domainworker` — по P/01.2 N1.1; `secrets.reads` манифеста `B` ДОБАВЛЯЕТ `Bworker`
  к читателям названной строки и ничего не отнимает; отрицания `!<образец>` прочим генератор выдаёт только для строк,
  объявленных секретными — в `secrets.readers` манифеста каталога или в векторах [`platform-lists`](../vectors/platform-lists/README.md) (`../vectors/platform-lists/cases.tsv`; только для судьи: случаи платформенных списков; проверяет P/02.5-04; N1.3);
  семья, названная в `secrets.reads`, но не объявленная секретной (строки единиц другого манифеста — `testsub/counters/` у
  `testsub2`), даёт только чтение `Bworker`: её роли-владельцы читают её по своим правам, как без объявления;
- образец объектов `objects/<s>/commands/*` выдаётся в файл как есть образцом `write` (а с ним, по общим правилам, `read`
  и удаление) роли `<s>worker` у манифеста с разделом `requests`: метки просьб пишет, закрывает и убирает держатель —
  воркер (договор просьбы и её метки, «Mark» mark); строк хранилища он не касается, оценщик строк его не встречает.

Объявления, переводимые в образцы (`worker.reads`, `secrets.readers`, `secrets.reads`), не содержат буквальный `*` и не начинаются с `!`/`delete:`; непредставимое объявление — отказ загрузки/генерации до файла. Это не запрет такого ключа в самом хранилище. Проверять не только читателей самого секрета, но и неизменность прав соседних обычных строк.

Правила генератора: роль удаляет то, что пишет (кроме меток команд у консоли и двух сохраняемых строк допуска у контроллера); образец `delete:<…>` даёт только удаление без записи (консоль — `platform/doors/*` выведенного сервера и строки таблиц `worker.writes`, контроллер — строки единиц при `delete_after`, воркер — строки своих единиц при `worker.deletes`, удаление с `cas` по прочитанной версии); `worker.writes` ДОЛЖЕН называть объявленную собственную таблицу; имя `unit.rows` и необъявленное имя дают отказ загрузки `refused:reference` (глава 2.1). Строки единиц остаются за консолью и удалением контроллера по допуску; исключение таблицы воркера не даёт ему прав на `unit.rows`; семьи `<s>/idem/*` и `<s>/asked/*` — отрицание `!` всем, кроме консоли; секретные строки (объявленные в `secrets.readers` или `platform_lists.tsv`) — читателям по `secrets.readers` и `secrets.reads`, прочим, чьё право достаёт его и после уже выданных отрицаний, — `!<образец>` (N3 шаг 4); `secrets.reads` без такого объявления только добавляет чтение `Bworker` (N1.4), где образец — ключ как объявлен: префикс с `/` → `<префикс>*`, точный ключ — без `*` (N1.3); генератор отказывается выдать файл, если множество объявленных обычных читателей секрета не равно множеству обычных ролей, которые его прочтут. Внутренний admin проверяется по особому правилу P/01.2 N1.3, а не включается в объявление читателей.

## N3 Проход

### сгенерировать_права(каталог манифестов, развёртывание) → файл

```
1. роли: console, resource, domain, domainconsole, domainagent (M11); на каждый манифест — <s>controller, <s>worker
   и <s>domain — у манифеста с domain.kept или переносимой книгой (воркер подсистемы на домене, P/03.7 N1.6);
   группы по P/01.2 N1.1
2. для каждой роли — write по N1.4 из ключей манифеста; delete = write, минус все права «только write» N1.4:
   метки команд у консоли, <s>/controller/placement_turn и <s>/controller/placement_intent у контроллера;
   плюс все delete-only из N1.4: delete:platform/doors/* у консоли, delete:<s>/<rows>/* у контроллера при delete_after и
   у воркера по worker.deletes; список delete выдаётся явно,
   чтобы отсутствие поля не вернуло исключённые права через умолчание P/01.2 N1.2
3. read по N1.4; worker.reads: ключ с `/` на конце → префикс; domain/placed/<sub>/ дополнительно даёт domain/placement/<sub>/; исходное domain/placed/<sub>/ сохраняется;
   копия своей книги domain/<sub>/<книга> в worker.reads (или secrets.reads) дополнительно даёт точный ключ domain/<sub>/<книга>/<CLUSTER> —
   свою строку книги у кластера-держателя, где копии нет (P/08.5 N1.4); у члена строки нет, право пустое; воркер — секретный читатель
   этой одной строки, если копия — в его secrets.reads, без !образца префикса domain/<sub>/<книга>/ (шаг 4 его не выдаёт: чтения воркера
   достают лишь эту строку); префикс domain/<sub>/<книга>/ манифест воркеру не выводит и не расширяет;
   книга to: "*" объявляется префиксом domain/<sub>/<книга>/ (голова и разделы, P/08.5 N1.4): правило не срабатывает, строки <CLUSTER> у такой книги нет, а префикс уже покрывает свои ключи — точного ключа в файле нет, иначе вывод двух реализаций разошёлся бы на --check
4. сначала проверить представимость всех объявлений N1.4; отказ → файла нет;
   секреты: секретная строка — объявленная в secrets.readers манифеста каталога или в векторах platform-lists; её читатели — по
   secrets.readers/reads (и платформенные читатели, N1.3); secrets.reads на необъявленную строку — только +Bworker, без !;
   образец — ключ как объявлен (N1.3): префикс с `/` на конце → <префикс>*, точный ключ → сам ключ без `*`
   (`domain/<sub>/<книга>` не закрывает `domain/<sub>/<книга>/*`); объявления не вкладываются (N1.3) — отрицание одного не
   задевает другого; и через манифесты: элемент secrets.reads, который строго вкладывается в объявленную секретную строку
   или префикс (secrets.readers любого манифеста каталога, platform_readers) либо содержит её, непредставим — отказ
   генерации (равный ключ — обычное +Bworker; отрицание побеждает везде, P/01.2, — часть секрета без расширения доступа
   не выразить); читателю — образец, если его чтения его не достают; нечитателю, чьи права его достают, — !<образец>,
   но после вычета: только если после уже выданных ему отрицаний (строка роли N1.4, N1.4a и общие правила вывода)
   его права ещё достают образец; лишних нет — у domainconsole при !domain/signer* нет !domain/signer и
   !domain/signer-pending
   множество объявленных обычных читателей ≠ множество обычных ролей, способных прочесть → отказ генерации;
   внутренний admin не сравнивается с этим множеством (его исключение — P/01.2 N1.3 и N1.3)
5. выдать JSON с отсортированными образцами (байт-стабильно); «generated — do not edit» —
   поле comment либо сопроводительный текст вне JSON. Не писать комментарии синтаксиса // или /* */.
   Для одинаковых входов форма и текст пометки стабильны; --check сравнивает по смыслу (N3 «установить»), не байты
```

**Гонки.** Вход — неизменный каталог по P/01.2 N1.2. Две генерации с одинаковыми входами дают файл
байт в байт. Разные входы могут давать одинаковые права; проверка не доказывает неизменность
исходных файлов, а только совпадение файла прав с результатом генерации.

### установить(файл прав)

```
файл прав: установленный — /etc/w2c/configstore-rights.json, кандидат — /etc/w2c/configstore-rights.json.new рядом с ним
порядок: rights генерирует кандидата из MANIFEST_DIR после шага «манифесты» (P/02.4 N1.7 steps; отказ генерации —
  кандидата нет, предварительная проверка P/02.4 N1.7 выполняет ту же генерацию по манифестам установки до изменений) →
  rights --check <кандидат> против MANIFEST_DIR                    → расходится: установка отказана, кандидат удалён, установленный файл цел →
  атомарное переименование кандидата поверх установленного файла; установленный файл с кандидатом до замены не сравнивается:
  отличие (новая подсистема, новая роль, изменённый манифест) — штатная замена старых прав новыми, не отказ;
  работающий демон берёт новый файл только при перезапуске (P/01.2 N1.2; гонки ниже)
  сравнение по смыслу: одинаковый набор ролей; у каждой роли равны group и множества образцов read, write, delete
  (порядок и повторы в списке не важны; нет delete — пустое множество, как у оценщика P/01.2 N1.2); comment, порядок
  ключей и пробелы не сравниваются; файл не по форме P/01.2 N1.2 — расходится
юниты: SupplementaryGroups=<группа роли>; PLATFORM_STORE=configstore:///run/configstore/<роль>.sock

```

**Гонки.** Установка выполняется одним установщиком по неизменному каталогу; параллельная
установка и правка `MANIFEST_DIR` исключены из этого урока. Работающий демон сохраняет прежние
права до перезапуска; подсистема, добавленная на работающий кластер, получает права тем же построением из файла манифеста в `MANIFEST_DIR` и перезапуском члена по одному серверу (P/02.4 N1.7 `add`, N1.9 `rollout`); барьер обхода сравнивает `GET /v1/rights` члена с файлом обхода тем же сравнением, что `--check` (N3 «установить»). Перед стартом с новым файлом установка выполняет `--check` кандидата (N3 «установить» п. 1); при
расхождении кандидат не заменяет установленный файл и демон с ним не запускают. Живого переключения прав и атомарного
переключения всего кластера урок не обещает.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **внутренний API инструмента генерации** (сам инструмент — N2; публичные argv — [`operator-commands.tsv`](../../forms/operator-commands.tsv)), путь файла по умолчанию (`/etc/w2c/configstore-rights.json`), путь сокетов на не-Linux;
2. ~~**как демон попадает в группы ролей или обходится setgid-каталогами**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита сокета, демон в группы ролей не входит (глава 2.4 N1.1, P/01.3 N1.3 `sockets`);
3. **внутренний API записи admin в `platform/mirror`, `platform/space`, `<s>/retention` и `<s>/alarms_retention`** (публичные argv `w2cctl mirror|space|retention` заданы `operator-commands.tsv`, глава 2.4 N1.9; ресурс и консоль их только читают — N1.4) и **как консоль удаляет `platform/doors/<s>` при выводе сервера** (`delete:` в N1.4);
4. **дословный текст пометки `comment`** сверх обязательного содержания (P/01.2 N1.2).
