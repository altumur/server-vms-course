## N0 Словарь слов

Нормативные слова — по RFC 2119 и RFC 8174 (MUST, MUST NOT, SHOULD, MAY), как их отображает
[канон курса](../../../common/ru/NORMATIVE-TERMS.md); требования записаны шаблонами EARS (When … / If … then … / While … /
The …) со словом RFC вместо «shall». Непомеченное предложение нормативного раздела читается как ДОЛЖЕН.

Пометки этого текста. «(только для судьи: …)» называет файл, его строку или случай, которых нет в выгрузке, которую
читает реализация (M); требование, которое они проверяют, названо в M по id в том же месте. Имя случая (`base`,
`name_*`, `c8_ref<N>_*`) — случай таблицы вердиктов главы 2.1 или, где место называет главу 2.3, строка установки этой
главы, тоже только для судьи. `sc. NN` («сц. NN», «сц. NN главы K», «сц. NN» приёмки, которую называет место) —
сценарий NN, строки `NN-…` файла `acceptance/K/scenarios.tsv` той главы или того урока, только для судьи; шов —
сценарий файла `acceptance/K/seams.tsv`, тоже только для судьи.

Требование, абзац которого начинается меткой «**Охват: боевой.**» (у пункта чеклиста — сразу после его id), относится
только к боевой квалификации по [общим боевым обязательствам](../../../common/ru/contracts/production-obligations.md):
вердикты, строки установки, швы и сценарии этого урока её не устанавливают, а нет там исполняемого, контекста, сбоя,
бюджета или привязки ёмкости — MissingBinding/NOTEXEC, а не успех. Требование без метки обязательно для каждой
реализации, даже если его проверяет только чтение или настоящий стенд.

Метки чеклиста готовности и перечня урока системы. Сразу после id (после метки «**Охват: боевой.**», если она у
пункта есть) пункт чеклиста называет в квадратных скобках, чем он закрывается: `test` — исполнением реализации: её
собственным тестом и/или случаем таблицы вердиктов, строкой установки, швом, сценарием или вектором приёмки; `reading` —
только чтением кода или описания реализации, тест его не закрывает; `stand` — только настоящим стендом вне собственных
тестов реализации: боевой приёмкой и пробами настоящего хоста (пункт, которому нужны ОС или хост). Несколько слов —
через запятую, `[test, reading]`; каждое слово называет ту часть пункта, которую закрывает.

### N1.1 Текст манифеста

Манифест — текст в кодировке UTF-8 по синтаксису YAML 1.2.2 в рамках правил ниже. Текст разбирает готовый парсер YAML 1.2 закреплённой версии; сверху — тонкая проверка слоя 1
([слои V7](../../../common/ru/LAYERS.md)): правила `text` ниже, ничего сверх них. Простые скаляры распознаёт таблица скаляров [раздела «Форма»](#форма-построена-из-стандартных-файлов)
по стилю узла — норма этой главы, не схема core YAML 1.2 (core читает `0x10` и `0o7` целыми, а bool — только `true`,
`True`, `TRUE`). Загрузчик ДОЛЖЕН принимать ровно этот текст и ДОЛЖЕН отказывать всему за
его пределами (`refused:text`, N4).

```yaml
text:       # правила слоя 1: каждый ключ называет свои правила, пункты под блоком
  bytes:    кодировка и знаки
  tab:      литеральный TAB
  document: один документ и его корень
  refused:  запрещённые конструкции и ключи, глубина
  rare:     конструкции, которые библиотеки YAML читают по-разному
  flow:     потоковые коллекции
  escape:   экранирования в кавычках
  comment:  знак `#`
  block:    заголовок блочного скаляра
  parser:   ошибки парсера и запятые потока
```

`bytes`: UTF-8. `bytes`: без BOM: U+FEFF первым знаком файла — отказ, дальше — обычный знак (`a﻿b` — слово). `bytes`: без C0, кроме TAB, LF и CR, без DEL и C1 (включая U+0085 NEL), U+FFFE, U+FFFF, U+2028 и U+2029 — отказ. `bytes`: те же знаки в значении после экранирования (`\x07`, ` `, суррогаты) — отказ. `bytes`: одиночный CR — отказ, CRLF читается как LF.

`tab`: литеральный TAB — только в комментарии (после `#`); в отступе, после `:` или `-`, внутри простого слова, в
  строке в кавычках, в блочном скаляре и в потоке `{…}`/`[…]` — отказ. `tab`: `\t` и `\<TAB>` в двойных кавычках — экранирование, допустимо.

`document`: ровно один документ — по байтам, не по ответу парсера: начальный `---` с колонки 1 до всякого
  содержимого допустим; второй `---`, `---` не с колонки 1, `...` и директива `%` — отказ. `document`: корень — блочное отображение с колонки 1: сдвинутый документ, корень потоком `{…}`, список, скаляр,
  пустой файл — отказ.

`refused`: якорь `&`, псевдоним `*`, тег `!…`, ключ слияния `<<`. `refused`: ключ-отображение и ключ-список. `refused`: простой ключ, который таблица скаляров читает не строкой (int, float, bool, null, `~`: `1:`, `1.5:`,
  `true:`, `null:`) — везде, в том числе внутри значений `type: json`; в кавычках (`'1'`, `'true'`) — строка, `0x10`,
  `0o7` — слова. `refused`: ключ, сказанный дважды в одном отображении (и в потоковом `{a: 1, a: 2}`).

- `refused`: вложенность глубже 64 (корень — уровень 1, каждое отображение и список, блочные и потоковые одинаково, —
  ещё уровень, скаляр уровня не добавляет).

- `rare`: что библиотеки YAML читают по-разному — потоковая коллекция на несколько строк, строка в кавычках на
  несколько строк, явный указатель отступа (`|2`), сложный ключ (`? …`) — отказ словами, а не «как получится».

`flow`: ключ потокового отображения с `:` и без значения (`{unconfirmed_max:}`) — отказ. `flow`: одиночный `-` простым скаляром в потоке (`[-, a]`, `[-]`, `a: [x, -]`, `{k: -}`) — отказ: YAML 1.2.2 простой
  скаляр с `-` в потоке не начинает (yaml-test-suite G5U8, YJV2).

`escape`: в двойных кавычках — только `\\` `\"` `\/` `\t` `\<TAB>` `\n` `\r` `\<space>` `\_` (U+00A0) `\xXX`
  `\uXXXX` `\UXXXXXXXX`; `\0` `\a` `\b` `\v` `\f` `\e` `\N` `\L` `\P` и незнакомое (`\q`) — отказ. `escape`: знак результата подчиняется `bytes`. `escape`: результат — скалярное значение Unicode: суррогат D800–DFFF (`\ud800`, `\U0000d800`, или пара
  `\ud83d\ude00` — YAML суррогатные пары не склеивает) — отказ; скалярный знак Unicode вне BMP допустим живым знаком
  `😀` или как `\U0001F600`.

- `escape`: в одинарных кавычках экранирований нет, кроме `''`.

`comment`: `#` вплотную после закрывающей кавычки, `]` или `}` (`"a"# c`, `]# c`) — отказ. `comment`: `#` после пробела — комментарий, `#` внутри простого слова (`a#b`, `counter# c`) — часть слова (YAML 1.2.2).

`block`: после `|` или `>` и указателя (`-`, `+`) — пробел или конец строки, иначе отказ. `block`: начальные пустые строки блочного скаляра не глубже его первой непустой строки — иначе отказ.

`parser`: ошибка парсера YAML — отказ (`[ - , a ]`, неявный ключ длиннее 1024 знаков — YAML 1.2.2 § 7.4.2). `parser`: пустой элемент потока в начале или в середине (`[a,,b]`, `[,a]`, `{a: 1,, b: 2}`) — ошибка разбора. `parser`: висячая запятая в конце потока (`[a, b, ]`, `{k: v, }`) — допустима (YAML 1.2.2; yaml-test-suite UDR7).

Что YAML 1.2.2 читает сам, читается по нему: значение на строке ниже ключа (слово, кавычки, поток), скаляр ниже голого
`-`, `?x` ключом и значением, ` # c` в строке продолжения простого слова — комментарий. Одиночный `-` значением в блоке — индикатор элемента списка, не слово (`unit: -` над ключом того же отступа — ошибка
разбора), в потоке `[-, a]` — отказ (`flow`).

Скаляры: простой — по таблице скаляров, в кавычках и блочный — всегда строка. Пустое значение (`key:` без значения) — не строка и не отображение: где месту нужно значение, отказ формы
(`refused:form`), явное «нет» пишется словом `null` или `~`.

Числа float в принятом манифесте конечны и по модулю не больше предела таблицы скаляров (`float_max`) — после прочтения
в binary64: запись, которая округляется до этого числа (`1.7976931348623158e308`), принимается. Запись ненулевого числа, которая читается нулём (потеря значимости, `1e-400`), — `refused:form`. NaN, обе бесконечности (в любом допускаемом YAML написании) и переполнение этого диапазона —
`refused:form` с путём значения; они не превращаются в строку или null.

Эти правила чисел действуют во всём документе, включая default/inherit и вложенные числа JSON и непрозрачных мест.
Непрозрачность отменяет проверку имён внутренних ключей, но не общие требования к числам и JSON.

### N1.2 Документ

Корень — отображение с закрытым набором разделов; форма каждого раздела, обязательность, умолчания и урок, где ключ
получает смысл, — [раздел «Форма»](#форма-построена-из-стандартных-файлов). Уроки-владельцы дают смысл ключей и на форму ссылаются сюда; при расхождении формы прав источник. Незнакомый ключ на любом уровне — отказ (N4). Раздел, отсутствующий в файле, значит умолчание своего урока, если оно определено. Отсутствие обязательного — `refused:form`; null не заменяет отображение или строку.

Профиль подсистемы без единиц не входит в эту главу; `unit.rows` и numeric/named загрузчик за автора не выбирает.

Места с именами автора (в разделе «Форма» — «author names») и непрозрачные места («opaque») — места схемы без закрытого
набора ключей ([слои V7](../../../common/ru/LAYERS.md)): у непрозрачного места форма (N3 шаг 2) не проверяет набор
ключей, но ссылки N1.4 на его ключи и значения проверяются, а числа — по N1.1.

Целое место (места `x-integer-place` таблицы слоёв: `capacity.default`, сроки, ширина колонки и подобные) — число с целым
значением: `4.0`, `4e0`, `1e1` — целые и в дереве становятся `4`, `4`, `10`; дробная часть (`4.5`) и значение вне
±(2^53 − 1) — `refused:form` (слой 2, слово `x-integer-place` таблицы слоёв). Целый знак семей данных — иной слой (кодек строк, слой 3) и этим не меняется.

- «is not {name, type: json, schema} — a document the domain holds is JSON, and what it may be is its schema»

  `refused:relations`; у поля таблицы и у поля единицы при `unit.id` — поле `{`, `}` без `{id}` в умолчании — знаки как есть.

### N1.4 Ссылки между ключами

Ключ, называющий поле, таблицу, метрику или маршрут, ДОЛЖЕН называть то, что объявлено в **этом же** манифесте; иначе
отказ при загрузке, а не на странице и не на проходе. Строки ссылок и отношений между значениями — [раздел «Форма»](#форма-построена-из-стандартных-файлов)
(«Связи», источник `02.1-installer.relations.json`, номера строк — поле `no`); проходят только по чистой форме (N3:
форма раньше связей). Сверх строк:

шаблон `requests.key` называет свойства `requests.schema.properties` — поля тела просьбы `POST /<sub>/requests`
  ([P/06.4](../../../06-console/ru/spec/06.4-console.norms.md) N1.5); поля единицы здесь ни при чём; `requests.key`: `{name}` — только строка без преобразования; `requests.key`: `{name:int}` — конечное binary64-число (как в JCS) с модулем ≤ 2^53−1, усечение к нулю и десятичная
  запись без знака `+` и ведущих нулей (`7.9` → `7`, `-7.9` → `-7`, `-0.5` → `0`); bool не число; `requests.key`: отсутствующее значение, иной тип или число вне этой границы — 400 при подаче, не при загрузке; тот же шаблон у `tables.<т>.key`;

`display.options.<поле>` у поля `bool`: ключ — текст значения в кавычках (`'true'`, `'false'`); простой `true:` —
  `text` по N1.1 keys; `display.options.<поле>` у слова пульса из `display.form[].status[]` — любые строки (подписи значений);

- `display.fields.<имя>`, `display.field_help.<имя>`, `display.form[].fields[]`, `display.tree.columns[].field` из
  платформенных имён принимают только `worker`, `server`, `revision`, `observed_revision`, `phase`, `id` (их показывает
  модуль — P/06.5 N1.2): `display.fields.epoch` отказан, `display.fields.seen` при `status[].field: seen` принят;

`door.pass` — вид первый, список первых сегментов пути, или вид второй, объект `{routes, calls?, stream?, wait?, refusals?, operations?}` (`operations` — [P/06.9](../../../06-console/ru/spec/06.9-console.norms.md) N1.1; смысл — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Передача второго вида»); `door.pass`: `routes`, `stream` и ключи `wait` — пути из сегментов `name` через `/`; `door.pass`: `stream` и ключи `wait` лежат под элементом `routes` целыми сегментами (строки 128, 129); `door.pass`: первый сегмент `routes` не повторяет `door.routes`, `unit.rows` и `where` (строка 127);

## N2 Двери

У загрузчика две двери: процедура загрузки, которой пользуются все процессы и установщик, и `GET /manifest` консоли, которым
модуль консоли (урок P/07) узнаёт форму подсистемы; вторая — в [главе P/06.5](../../../06-console/ru/spec/06.5-console.norms.md)
N2 «GET /manifest».

### Процедура загрузки

Не HTTP: вход реализации, который получает байты и имя источника и отвечает манифестом или отказом. Все пути чтения манифеста — файл, строка хранилища, встроенный манифест — ДОЛЖНЫ проходить через неё.

```
загрузить(байты, источник) → манифест | отказ(источник, путь_ключей, причина)
загрузить_каталог([манифест…])  → каталог | отказ(источник, путь_ключей, причина)     # проверки между манифестами
```

## N3 Проход

### загрузить(байты, источник) → манифест | отказ

1. Текст: разобрать байты парсером YAML 1.2.2 закреплённой версии и тонкой проверкой N1.1 (слой 1); если не проходят,
   вернуть `refused:text`.

2. Форма: проверить дерево схемой `02.1-installer.schema.json` (JSON Schema 2020-12) и словами `x-*` таблицы слоёв
   `02.1-installer.layers.tsv`: имя (N1.2), закрытый набор ключей каждого уровня, в местах имён автора — любые имена по
   своей грамматике, в непрозрачных местах набор ключей не проверяется; типы, грамматика поля (N1.3), перечни,
   обязательные ключи (`capacity.default`); числа — по N1.1, в том числе в непрозрачных местах; целое место — границы
   ±(2^53 − 1), значение с целым значением — целое и в дереве приводится к целому (`4.0` → `4`; слой 2). Если дерево не
   проходит, вернуть `refused:form`.

3. Связи: только при чистой форме проверить каждую строку связей (CEL, `02.1-installer.relations.json`) над деревом
   загрузчика; отсутствующее значение и `has` берут статическое умолчание `default` формы (N1.4). Если строка не
   выполняется, вернуть `refused:relations`.

4. Умолчания: заполнить отсутствующее умолчаниями уроков-владельцев; ослабляющих умолчаний нет у
   `lease.unconfirmed_max`, `placement.unplaced.delete_after` и `placement.places.server_field` (N1.2 «Форма»,
   одноимённые свойства).

5. Вернуть манифест.

Порядок слоёв нормативен: текст → форма → связи; связи проверяются только при чистой форме — манифест с
отказом формы отказывается классом `form`, даже если неверна и связь. Порядок внутри формы и внутри связей — решает реализация; путь и строка отказа — подсказка (N4).

**Гонки.** Нет: загрузка чистая, без состояния и без хранилища.

### загрузить_каталог([манифест…]) → каталог | отказ

Проверки, которым нужен не один манифест: `worker.requests` называет подсистему каталога, принимающую просьбы.

`near.of` и `near.prefer` — поля подсистемы `placement.near.sub`.

`metrics.prefix` двух подсистем не совпадает (`GET /manifest`, P/06.5 N2).

Подсистемы `near.sub` ещё нет в каталоге — проверка `near.of` и `near.prefer` ждёт её установки, как у `worker.creates` ниже: сродство до неё не действует (единица размещается без него, P/04 N1.3 `near`). Установка `near.sub` при несовместимых полях — отказ каталога; подсистема есть, а полей нет — отказ каталога.

Отсрочка `near` не задаёт порядка установки (P/02.4 N1.7 `order`).

`worker.creates[]` подсистемы C:

1. `sub` — подсистема A, `rows` — её `unit.rows`; `unit.id` у A не `numeric` (резерв `next_id` заказчику не
   даётся);

2. каждая подстановка `{f}` в `key` — поле `unit.fields` A с `required: true`, типа `string`, `url`, `int`, `float` или
   `bool`, не `*_secret` и не поле-источник id A (`unit.id`: его библиотека заполняет готовым id);

3. `key` называет каждое `fixed`-поле A, кроме поля-источника id, и поле `about.field` A, если оно не `unit.id`;

4. у A нет поля `*_secret` с `required: true` или с `default`: библиотека заказчика секретов не пишет (P/03.6 N1.6),
   строка без них не создалась бы;

5. два заказчика одной таблицы — имена C и D, где `C-` — начало `D-` (`rec` и `rec-x`), — отказ: префиксы их id
   вложены.

Пока A нет в каталоге, проверки 1–4 `worker.creates[]` ждут её установки: каталог проверяется целиком при каждой
установке. Установка A при несовместимом заказчике — отказ каталога. Заказчик и адресат МОГУТ ссылаться друг на друга — `testsub` заказывает `testsub2`, `testsub2` просит `testsub`;
поставить их по одному иначе нельзя.

`worker.uses[]` — `<подсистема>.<доля>`: подсистема, если она в каталоге, объявила `shares.<доля>`. Пока подсистемы `worker.uses[]` нет в каталоге — та же отсрочка, что у `worker.creates` (группы доли нет, юнит воркера
её не получает — P/02.4 N1.1).

Имена ОС и пути всех подсистем каталога — пользователи, группы, юниты, каталоги долей и частей
([P/02.4](02.4-installer.norms.md) N1.1) — строятся все вместе: любое совпадение двух имён — отказ каталога. Имя ОС каталога длиннее 32 знаков — отказ каталога.

Каталог — все манифесты кластера (все строки `platform/manifest/*`). Отказ одного манифеста каталога — отказ каталога.

Для любых подсистем A и B, включая A=B, имя B не совпадает с unit.rows или именем любой таблицы A, включая списковые tables. Иначе refused:catalogue с именами обоих манифестов и конфликтующей семьёй, до выдачи каталога/первой записи установщика; это исключает пересечение root-двери и mount при любом выборе root.

Виды токена домена (N1.2b): имя вида `domain.tokens` объявлено в каталоге один раз — тот же вид у двух подсистем —
отказ каталога. Каждый вид в `door.routes[].domain` подсистемы C объявлен в `domain.tokens` подсистемы каталога (в том числе самой C),
иначе — отказ каталога. Отсрочки, как у `worker.creates`, у вида маршрута нет: подсистема, объявляющая вид, ставится раньше двери, которая его
называет.

`door.pass.calls[]` подсистемы C: запись `<s>/<имя>` чужой подсистемы `<s>`, если она в каталоге, называет её `unit.rows`, таблицу формы отображения, `policy`, `next_id`, маршрут `door.routes` или сегмент первого вида её `door.pass`: сегмент второго вида и сегмента нет в её списке — отказ каталога. `door.pass.calls[]`: `GET <s>/where` и `<s>/requests` — у любой подсистемы каталога (`<s>/requests` — подача P/06.3 N1.9; подсистема без `requests` отвечает на неё 404, P/06.4 «подать просьбу» шаг 0). `door.pass.calls[]`: `GET <s>/heartbeats` и `GET domain/at/<s>/heartbeats` — только у `<s>` с `heartbeat.door`, иначе отказ каталога. `door.pass.calls[]`: `<s>/operations` — только своя подсистема при `door.pass.operations` (связь 133), иначе — отказ каталога. Пока `<s>` из `door.pass.calls[]` нет — отсрочка, как у `worker.creates`: подсистема перечня может стоять не в каждом кластере, а двери её тогда просто нет.

`domain.kept_read`: каждый элемент — строка `domain.kept` этого манифеста точным именем, не семья с `/`; иначе отказ каталога. Запись `GET domain/<s>/kept/<имя>` в `door.pass.calls[]` называет элемент `domain.kept_read` подсистемы `<s>`, иначе отказ каталога; пока `<s>` нет — отсрочка. Таблица или `unit.rows` с именем `kept` при `domain.kept_read` — отказ каталога: сегмент занят дверью.

Книга всем: `domain.books.<книга>.to` равно `"*"` ([P/08.5](../../../08-domain/ru/spec/08.5-domain.norms.md) N1.3 `to_all`) при `domain.names.<книга>/.grant` — отказ каталога: в одной строке на всех нет ничего на получателя. Книга всем при `pick: unique` — тоже отказ каталога: строка не хранит проигравшего вклада. Секрет такого входа манифест не называет: его судит сборка, `bad_contribution`.

**Гонки.** Проверка каталога получает готовый набор загруженных манифестов; две проверки не меняют входы друг друга. Чтение источников до неё не обещает атомарного снимка всех файлов или строк. Если файл меняется во время чтения,
могут быть получены прежние, новые либо смешанные байты: допустимый документ загружается, недопустимый даёт отказ
по N1. Сам факт изменения файла чистая процедура по байтам не обнаруживает.

Неразрешённая связь между принятыми
манифестами даёт отказ каталога; при любом таком отказе частичный каталог не выдаётся.

Строку манифеста, старт процесса и смену манифеста задаёт [глава 2.3](02.3-installer.norms.md) N3.

## N4 Отказы

Закрытый список. У загрузчика один вид ответа «не манифест» — отказ в словах, называющий источник (файл или ключ хранилища) и путь ключей. Классы ниже различают причину для читателя и приёмки, не код.

Путь ключей и строка файла в отказе — подсказка, не норма: строги вердикт и код выхода; приёмка пишет
их в отчёт без провала (N5). Подсказка (СЛЕДУЕТ): путь — до самого глубокого ключа с неверным значением; индекс списка в пути —
число; строка — строка этого ключа. Подсказка (СЛЕДУЕТ) отсутствующего ключа — путь с его именем и строка объемлющего отображения. Подсказка (СЛЕДУЕТ) повтора ключа — путь повторного ключа и строка второго объявления.

Подсказка (СЛЕДУЕТ) ошибки кодировки — строка байта, без пути. Подсказка (СЛЕДУЕТ) отказа слоя текста — строка виновного знака или конструкции (маркер, открывающая кавычка,
незакрытый поток, строка без ключа), не следующая и не конец файла.

Подсказка (СЛЕДУЕТ) правила на два
ключа: путь — ключ, который правило запрещает рядом с другим: `merge: union` у поля не `list` — `…fields.<поле>.merge`;
`bytes` рядом с blob — `unit.fields.bytes`; поле `name` таблицы не по форме — `tables.<т>.fields.name`; `delete_after`
при `numeric` id — `placement.unplaced.delete_after`. Подсказка (СЛЕДУЕТ) правил на присутствие «A запрещён без B»: путь — сам A (`merge` без `inherit`, `must_match` без `ref`, `login` без
`param`, `in` без `regex`). Подсказка (СЛЕДУЕТ) правил на присутствие «A требует B»: путь — недостающий B (`per_person` и `free: true` → `ttl`, `free: false` →
`valid_for`, `most_valid`; `from` → `key`, `pick`, `to`). Подсказка (СЛЕДУЕТ) ссылки N1.4, которая требует другой ключ (`requests.stamp: group` и `rights.reach.group` без `placement.group_by`, `requests.outcome: fetched` без `requests.key`, `placement.home: near` без `placement.near`): путь — сам ссылающийся ключ.

Подсказка (СЛЕДУЕТ) правила над набором (`unique`, `prefix_free`, глубина `schema`): путь — сам набор. Подсказка (СЛЕДУЕТ) повтора элемента списка: путь — второе вхождение, как у повтора ключа.

Форма значения ключа (`worker.reads[]`, `secrets.reads[]` — `<семья>/<имя>`) —
класс `form`, а не связь N1.4.

Класс отказа — слой, где отказ:
`text`, `form`, `relations`, `catalogue`; слово отказа — `refused:<класс>`; класс проверяет приёмка (`classes.tsv`; только для судьи: класс каждого случая, проверяет P/02.1-R213 и P/02.1-R155, N5).

Нормативный каталог отказов главы — [`forms/refusals.tsv`](../../forms/refusals.tsv). Колонки `chapter` и `row` — устойчивый адрес отказа; коды, фиксированные слова, предметы диагностики, условия и действия вызывающего заданы формой. Второй каталог здесь не повторяется.

Предупреждений нет. Списка «принимаю и игнорирую» нет. Частично загруженного манифеста нет.

Размер файлов `console.files` загрузчик не судит: он видит только байты манифеста. Потолки `FILE_MAX`, `FILES_TOTAL_MAX` — [глава 2.3](02.3-installer.norms.md) N1.5, N4.
