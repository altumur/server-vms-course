# Покрытие случаев N5 только для судьи

Этот русский текст — производный от `spec/02.3-installer.n5.cases.md`, руками не правится.

Описания случаев и их исходы — данные только для судьи. Каноническая нормативная глава — [`02.3-installer.norms.md`](02.3-installer.norms.md). Общие правила и явно сохранённые нормативные примеры остаются там.

### Блок случаев 1

| Группа случаев | Что проверяет | Нормы |
|---|---|---|
| `puts.tsv` | `manifest put`: тот же файл дважды — rev 1 («unchanged»), изменённый — rev 2; A=B каталога: имя = свои rows или своя таблица, имя = rows или таблица другого манифеста, совпавший `metrics.prefix` (`a-b` и `a_b`) — код 2, строки нет (№ 11, 12, 40); `worker.creates` к адресату — принят (`creates_ok`), заказчик без адресата и адресат после него — приняты (`creates_no_target`, `target_after_customer`), адресат после несовместимого заказчика — код 2 (`target_after_customer_mismatch`); `worker.uses` без владельца — принят (`uses_no_owner`); не его `rows`, адресат `numeric`, `key` без `fixed`-поля, с необязательным полем, с полем-источником id, с полем `list`, адресат с обязательным секретом, вложенные префиксы двух заказчиков; `worker.uses` без доли; имя пользователя подсистемы, совпавшее с группой доли, — код 2, строки нет (глава 2.1 N3 «загрузить_каталог»); виды токена домена: вид маршрута двери у другой подсистемы и свой — приняты (`door_domain_kind_other`, `door_domain_kind_own`), вида нет в каталоге — код 2 (`door_domain_kind_missing`), тот же вид у двух подсистем — код 2 (`kind_dup`); `near`: адресат раньше и позже клиента, клиент без адресата — приняты (`near_ok`, `near_target_after`, `near_no_target`), поле `near.prefer`, которого у адресата нет, — код 2 при адресате раньше (`near_bad_field`) и у установки адресата после клиента (`near_target_after_mismatch`) | N3 |

### Блок случаев 2

Метка снята — «unchanged» её доводит; метка не по форме — `manifest put` отказывает, ничего не пишет — приёмка главы 2.2
(`rev_deleted`, `rev_spoiled`). Проверяются чтением реализации: строка и метка манифеста в хранилище, все причины отказа старта из N4 и допустимая отставшая метка, остановка при смене метки, остановка с кодом 2 при метке не по форме у работающего и неподтверждённое чтение метки — не смена ([системный стенд](../../../common/ru/acceptance/system/README.md); стенд не портит метку под работающим процессом).
Два кода старта тоже проверяются чтением: подтверждённая непригодность — код 2 без перезапуска; чтение, не подтверждённое за `START_WAIT`, — код 1,
супервизор перезапускает. Тест реализации на это: хранилище отвечает на проверку схемы, затем перестаёт отвечать до чтения строки манифеста
и снова отвечает в пределах `START_WAIT` — процесс стартует по строке без отказа; если хранилище молчит дольше, процесс выходит с кодом 1.
У швов урока нет директивы, которая обрывает хранилище между двумя чтениями процесса, поэтому этот тест — не шов.

### Блок случаев 3

Статические файлы и объявленная оболочка: перечень с файлами рядом принят — все расширения, вложенный сегмент, имя,
которое только начинается с `api`, пустой файл; тот же файл дважды — «unchanged» (`files_ok`, `files_same_twice`); файла нет — код 2,
строка прежняя или её нет (`files_missing`, `files_missing_second`); `console.shell: true` без оболочки — код 2, с оболочкой — принят
(`shell_declared_missing`, `shell_declared_ok`); снятие и появление перечня — новая ревизия (`files_dropped`, `files_added`). Формы строки `files` и частей — 6.5 сц. 26;
байты файла сменились при том же манифесте и уборка частей — чтением: `puts.tsv` файлы между установками не меняет. Потолки
(`@file-fill`): файл на байт выше `FILE_MAX` и сумма на байт выше `FILES_TOTAL_MAX` — код 2, строка прежняя (`files_file_over`,
`files_total_over`), ровно `FILE_MAX` — принят (`files_file_max`); ровно `FILES_TOTAL_MAX` — чтением: случай прогнал бы через хранилище
43 МиБ строк ради одного сравнения. Граница поля `size` — ещё векторы `family-read`.

### Блок случаев 4

Граница `rev`: при `rev` строки 2^53 − 1 тот же манифест — «unchanged», код 0, новая ревизия — отказ до любой записи,
код 2 (N4) — `puts.tsv` `rev_max_same`, `rev_max_changed` (директива `@rev-max`); `toolarge`
основной строки — `toolarge_row`; оболочка с `on…=`, «unchanged» и смена оболочки по байтам — `shell_onclick`,
`shell_same_twice`, `shell_changed` (`@shell-put`); имена ключа, `rev` и атрибута в stderr — чтением по N4.

### Блок случаев 5

`worker.requests` — адресат с `requests` принят, адресата
нет, адресат без `requests` и снявший их при обновлении — код 2 (`requests_*`); правило 4 `worker.creates` с `default` у
`*_secret` (`creates_target_secret_default`, `creates_target_after_secret_default`); `near.of`, которого у адресата нет
