# P/02 — инструкция для реализации

Текст производный от `spec/02-installer.README.md`, руками не правится: источник — английский [`spec/02-installer.README.md`](../../spec/02-installer.README.md), правка идёт в него, русский пересобирается переводом.

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — `ru/02-installer.md` (для человека, в выгрузку не входит).

Конкретные сценарии, фикстуры и ожидаемые ответы не входят в M; судья получает их отдельно. Публичные README приёмки определяют интерфейсы и охват проверок, а нормы и публичные формы — обязательное поведение.

## Задача

Реализовать установщик урока P/02 на языке `<LANG>` по четырём главам: строгую загрузку манифеста и каталога манифестов (глава 2.1),
чтение и смену манифеста в хранилище (глава 2.3), юниты, раннер, установщик и операторские процедуры (глава 2.4), генерацию
прав из каталога манифестов (глава 2.5). Пройти приёмку N5 глав и закрыть их чеклисты готовности.

- **2.1.** Реализовать строгую загрузку манифеста и каталога манифестов по N1–N4 [главы 2.1](02.1-installer.norms.md). Пройти
  приёмку N5 штатным путём загрузки и закрыть весь [чеклист готовности](02.1-installer.norms.md#чеклист-готовности).
  Основной вход главы — процедура `load(bytes, source)`, не HTTP-дверь.
- **2.2.** Канонический вид манифеста по [главе 2.2](02.2-installer.norms.md): проекция N1.1 (сахар, умолчания, шаги P1–P5,
  `ordered`, JCS), строка вида N1.2 и запись `manifest put` по N3 — вид до записи, больше потолка — отказ целиком, порядок
  строка — вид — метка. Пройти векторы [`canonical`](../vectors/canonical/README.md) байт в байт и приёмку главы
  [`acceptance/2/`](../acceptance/2/README.md).
- **2.3.** Чтение и смену манифеста в хранилище по N1.5 и N3 [главы 2.3](02.3-installer.norms.md); закрыть её
  [чеклист готовности](02.3-installer.norms.md#чеклист-готовности).
- **2.4.** Подготовить процессы/юниты, раннер, установщик и операторские процедуры N1 [главы 2.4](02.4-installer.norms.md).
- **2.5.** Генерировать права из каталога манифестов по [главе 2.5](02.5-installer.norms.md). Оценщик прав, форма файла и дверь
  `/v1/rights` — глава [P/01.2](../../../01-store/ru/spec/01.2-store.norms.md) и её шаги инструкции
  [01-store.README.md](../../../01-store/ru/spec/01-store.README.md). Настройка пользователя, групп, сокетов и сертификатов
  связана с главой 2.4: юниты N1.1 (`User=`, `SupplementaryGroups=`), сокеты — P/01.3 N1.3 `sockets`, комплект N1.6 `kit` и
  выпуск `w2c-ca.sh`.

Своего HTTP-контракта у урока нет: дверь `GET /manifest` и форма `ManifestView` — у главы P/06.5
([нормы](../../../06-console/ru/spec/06.5-console.norms.md), [инструкция](../../../06-console/ru/spec/06-console.README.md), [контракт](../../../06-console/spec/06-console.api.openapi.yaml)).

## Что создать

Обязательное поведение — в каноне. Внутренние типы, функции, устройство ошибок и выбор библиотек остаются
реализации; названия процедур в N2–N3 обозначают их смысл, а не обязательные сигнатуры конкретного языка.

Глава 2.1:

1. **Загрузку одного манифеста** из байтов с именем источника: проверка текста, имени, ключей, значений и ссылок,
   затем заполнение умолчаний в порядке N3. Результат — целый манифест либо отказ с нужными сведениями по N4. После проверки ключей отказать NaN, бесконечности и переполнению float, включая вложенные числа opaque/default/inherit; все принятые значения представимы JSON.
2. **Загрузку каталога** с проверками `worker.requests` и `placement.near` по N3. Приёмка одного файла
   не подменяет проверку каталога; в раннер таблицы не добавляются не названные ею соседние манифесты.
3. **Прогон общей таблицы** штатным путём загрузки согласно README приёмки. Установку судят отдельно, `puts.tsv` главы 2.3
   (N5; только для судьи: последовательности установок главы 2.3); корпус через `manifest put` не прогоняется.

Глава 2.3:

4. **Чтение и установку манифеста в хранилище** по N1.5 и N3: первая строка с `rev: 1` и `cas: ""`, метка,
   дайджест, растущая ревизия, запись с `cas`, доведение метки, старт и остановка процессов.
   Неверный файл не устанавливается. При `toolarge` основной строки команда заканчивается кодом 2
   с диагностикой N4 и не переходит к метке; при подсчёте веса учитываются исходные байты YAML и страница,
   а не только разобранные значения. Период обнаружения смены отсчитывается от публикации метки.

Глава 2.4:

5. Описанные N1 службы и unit-файлы, группы, каталоги, права, сокеты и конфигурацию установки.
6. Раннер и установщик с проверками до записи и диагностикой частичного результата при отказе.

Глава 2.5:

7. Генератор и проверку `--check`; исполнитель сценариев под разными ролями. Механизм выдачи сертификатов и генератор
   юнитов — глава 2.4.

Всем главам:

8. **Описание реализации** с ответами на 25 пунктов «Решает реализация» (2.1 — четыре, 2.2 — два, 2.3 — шесть, 2.4 — восемь, 2.5 —
   пять; зачёркнутые пункты уже нормированы — ответ ссылкой) и указателями для тех пунктов чеклиста, которые
   проверяются чтением.

## Порядок работы

Этапы реализации — [`forms/stages.tsv`](../../forms/stages.tsv): цели, проверки конца, веса, части пакета и зависимости. Это возможный план, не дополнительная норма поведения. Советы ниже дополняют таблицу; обязанности, требующие чтения, установки ОС или стенда процессов, остаются в чеклистах готовности.

### Главы 2.1 и 2.3 — манифест

1. *(2.1)* Выписать границы закрытых, именованных и непрозрачных уровней из N1.2,
   их уроки-владельцы и выборы реализации. Проверить обязательные unit/rows/id: загрузчик не придумывает семью или вид id; отсутствие unit.fields означает пустое отображение.
2. *(2.1)* Настроить чтение байтов и разбор текста по N1.1: парсер YAML 1.2 закреплённой версии и тонкая проверка слоя 1
   ([слои V7](../../../common/ru/LAYERS.md) § 4, обходы D13, D16). Проверки, которым нужен исходный текст или список ключей до
   превращения в отображение, выполнить до потери этих сведений библиотекой; один документ — по байтам.
3. *(2.1)* Выполнить проход загрузки N3 по слоям: текст → форма (схема JSON Schema 2020-12 и слова `x-*`, целое место —
   слой 2) → связи (CEL, только при чистой форме). Заполнение умолчаний не скрывает ошибочный вход.
4. *(2.1)* Прогнать `verdicts.tsv` (только для судьи: таблица корпуса): один файл — одна загрузка. Сверить множество файлов с таблицей;
   отказ засчитывать по правилам README, а не по любому исключению или ненулевому коду процесса.
   Сравнить класс `classes.tsv`; пути и строки `diagnostics.tsv` — подсказка в отчёт без провала (только для судьи: `classes.tsv`).
5. *(2.1 — каталог; 2.3 — хранение и смена)* Проверить каталог, затем хранение и смену манифеста: повтор установки без изменений, конфликт `cas`,
   отставшая и отсутствующая метка, все причины отказа старта N4 (включая неподтверждённое чтение строки/метки и несовпадение встроенного манифеста), старт между двумя записями установщика, `toolarge` основной строки
   до записи метки. Для каталога не приписывать чтению атомарный снимок или обязательный отказ при любом
   изменении файла: проверяются фактически полученные байты и связи. Предметы проверки — N3, N5 и чеклист.

### Глава 2.4 — установщик

1. Сопоставить роли, группы, каталоги, права, сокеты и окружение каждой строке N1.1–N1.2. Проверить приоритет значений и отсутствие source для данных; After не считать готовностью (N3).
2. Спроектировать предварительную проверку и точки записи установщика. Принудительно отказать на каждой фазе: до записи нет изменений, после начала допускается частичный результат с диагностикой и без enable/start новых служб (N1.7).
3. Проверить скрипт воркеров по заказу: бюджеты, резервирование до start, номера 2…99 (старт наименьшего, стоп наибольшего), ряда нет — ничего, неизвестный исход запуска и устаревшую консоль, polkit start/stop полных имён своего сервера. Сертификаты — отдельная тестовая CA, отзыв до вывода о полном отсечении (N1.5–N1.6).
4. Сертификат роли (SAN URI `urn:w2c:role:<роль>`, CN `<роль>.<сервер>`, ключ 0640 root:<группа пользователя юнита>) и
   правило адреса (демон вне петли — только с TLS; дверь процесса без комплекта — петля; signer и relay — по явному
   адресу с громкой строкой лога, на умолчании процесса `0.0.0.0` — отказ старта, код 2; resource без комплекта — только петля) подтвердить структурным тестом юнитов и тестами центра (N5) либо
   явно оставить без свидетельства исполнения: стенда с TLS в приёмке нет, проверяется чтением ([системный стенд](../../../common/ru/acceptance/system/README.md)).

### Глава 2.5 — вывод прав

1. Зафиксировать набор манифестов и развёртывание на время генерации/установки. Сверить
   производные имена ролей с P/01.2 N1.1: ограничение имени манифеста уже обеспечивает их длину.
2. Вывести таблицу N1.4 по манифесту, затем применить читателей секретов из N1.3 (`secrets.readers`, `secrets.reads`, `platform_readers`).
   Проверить точное имя против префикса и эффективное множество читателей, а не
   только присутствие строки в списке. До преобразования отвергать буквальный * и начальные !/delete: в объявлениях; не менять ключ. Проверить соседние vault, vault2, vault/nested: точное объявление vault не меняет их обычных прав. Поле delete генератор выдаёт явно.
3. Проверить две строки допуска контроллера по N5: read/write разрешены, delete
   запрещён; остальные разрешённые удаления не исчезли. Сверить обе стороны
   boundary консоль/контроллер/воркер, не меняя протокол размещения [P/04](../../../04-controller/ru/spec/04-controller.norms.md).
4. Подготовить стенд по README приёмки: отдельный экземпляр для каждого сценария,
   пустые данные и память повторов, тот же файл прав, фоновые писатели остановлены.
   Выполнить все шаги.
5. Проверить все пункты канонического чеклиста. Сокеты, права файлов, TLS и сертификаты
   подтвердить структурным тестом юнитов и тестами центра (глава 2.4 N5) либо явно оставить без свидетельства
   исполнения: стенда с TLS в приёмке нет, проверяется чтением ([системный стенд](../../../common/ru/acceptance/system/README.md)).

Всем главам: завершить описание реализации и чеклисты; проверку таблицы не объявлять проверкой всего жизненного цикла манифеста.
