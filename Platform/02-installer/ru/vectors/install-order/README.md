Текст производный от `vectors/install-order/README.md`, руками не правится: источник — английский [`vectors/install-order/README.md`](../../../vectors/install-order/README.md), правка идёт в него, русский пересобирается переводом.

Владелец — глава [P/02.4](../../spec/02.4-installer.norms.md) установщика (N1.7 `install` `steps`, `order`). Участник — установщик (`install.sh`, шаг `manifest put`). Байты пишет
«Specification».

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

**Вход** — `{manifests, installed}`: `manifests` — манифесты этой установки, у каждого `name` и то, что задаёт или не задаёт
порядок: `requests` (`worker.requests`), `near` (`placement.near.sub`), `creates` (подсистемы `worker.creates`), `uses`
(`worker.uses`); `installed` — имена подсистем, чьи манифесты уже в хранилище. `manifests`, `installed` и `name` элемента обязательны;
`requests`, `near`, `creates`, `uses` необязательны (нет — связи нет); пустые массивы допустимы; `null` вместо строки или
массива — не по форме: код 2, stdout пуст.

**Выход** — JSON-массив имён в порядке `manifest put`, либо `@exit 2` — отказ установки кодом 2 на предварительной проверке,
до изменений. Сравнение — JSON по значению.

Нативная форма команды и отображение отказа правила заданы формой провода ниже. Вход не по форме — код 2 без stdout; отказ правила на входе по форме — вычисленный исход, а не ошибка транспорта. Это не меняет отказ установки или загрузчика, названный выше.

## Прогон

Сторона вычисляет порядок своим кодом установщика без хранилища и сравнивает с `expect`. Ребро вида токена домена
(объявитель `domain.tokens` раньше подсистемы, чей `door.routes[].domain` его называет; P/02.4 N1.7 `order`) вход не выражает — форма входа не расширяется: строки без видов его не задают, правило — чтением и
`puts.tsv` главы 2.3 (`door_domain_kind_other`, `door_domain_kind_missing`; только для судьи: последовательности установок главы 2.3; они проверяют P/02.4-R233, P/02.4-R241, P/02.4-R253, P/02.4-R259, P/02.4-R496, P/02.4-R506, P/02.4-R511).

Порядок задаёт только `requests` (и вид, не выраженный входом); `near`, `creates`, `uses` во входе есть, но порядка не задают: `cycle` — цикл по `requests`; `requests-near-pair` — `requests` и `near`
навстречу — порядок по `requests`, не цикл; `near-only` — только `near`, порядка нет (по имени). Девять строк: восемь
порядков, один `@exit 2`.
Кто исполняет — установщик (`02-installer`: порядок `manifest put` и отказ при цикле, P/02.4 N1.7 `order`, `refuse`); других исполнителей нет (строку исполняет роль, чья норма вызывает её функцию).
