главы 2.1 и пропуск каждого шага урока 2 меняют байты хоть одного вектора.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` — пояснения, пустые пропускаются. Первая непропущенная строка — заголовок
`case<TAB>input<TAB>expect<TAB>note`, дальше — по строке на случай; ровно четыре поля.

- `case` — имя случая: `[A-Za-z0-9][A-Za-z0-9_.-]*`, уникально в файле;
- `input` — путь файла манифеста от корня раскладки (курс или выгрузка `cammeta-specs`): через `/`, без `..`, на
  `.subsystem.yaml`; загрузчик главы 2.1 его принимает;
- `expect` — ровно `expect/<case>.json`: байты вида — JCS,
  UTF-8, без перевода строки в конце;
- `note` — что показывает строка (не сравнивается).

## Прогон

Для каждой строки сторона читает байты файла `input`, строит канонический вид по N1.1 главы 2.2 (своим проходом по дереву
загрузчика или общим кодом — «Решает реализация» п. 1) и сравнивает байты с файлом `expect` целиком. Иной байт, лишний
перевод строки или отказ загрузки — расхождение строки.
Кто исполняет — установщик (`02-installer`: «построить вид» P/02.2 N3 — для `manifest put`, P/02.3 N3, и для кластера из одного со встроенным манифестом, P/02.4 N1.10). Только читают готовое: раннер воркера (`worker.exec` из вида, P/02.3 N3 «Worker program from the row») и читатели вида (P/02.2 N3 «Читатель»: метка, `rev`, `sha256`, схема) (строку исполняет роль, чья норма вызывает её функцию).

## Чего вектор не покрывает

Обёртка строки вида, порядок записи строка — вид — метка, «unchanged» с видом, отказ `toolarge` вида — приёмка главы
[`acceptance/2/`](../../acceptance/2/README.md). Схема вида — раздел «Форма канонического вида» норм главы 2.2 (P/02.2-R036, P/02.2-R039;
`check_spec` проверяет, что вид каждого входа её проходит). Читатель вида — правками читателей (P/02.2-R062, P/02.2-R064, P/02.2-R067, P/02.2-R068, P/02.2-R069, P/02.2-R070, P/02.2-R072).
