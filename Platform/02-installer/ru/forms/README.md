# Формы и швы P/02 для пакета генераторов

Текст производный от `forms/README.md`, руками не правится: источник — английский [`forms/README.md`](../../forms/README.md), правка идёт в него, русский пересобирается переводом.

Формы выражают существующие нормы P/02; собственной HTTP-двери установщику не добавляют.

## Аргументы команд

`daemon-flags.tsv` сохраняет восемь колонок P/01: `flag`, `type`, `default`, `default_text`, `required`, `commands`, `bad`, `norm`.
`commands` — id из [`operator-commands.tsv`](../../forms/operator-commands.tsv) через запятую. Типы: `string`, конечное `number`, `file`, `bool`; `required` и `bad` — CEL над переданными опциями `f` и id команды `cmd`. Нет умолчания — `-`; отсутствующий bool — false, переданный — true. Это аргументы команд, не флаги демона и не переменные окружения.

Колонки `operator-commands.tsv`: `command`, `process`, `prefix`, `positionals`, `norm`. `prefix` — JSON-массив постоянных слов argv; `positionals` — JSON Schema 2020-12 для остальных позиционных слов после разбора опций. Форма не задаёт shell-разбор, формат вывода, код для неоговорённого входа или новый интерфейс чужой команды.

## Каталог отказов

Колонки [`refusals.tsv`](../../forms/refusals.tsv) по порядку (разделитель TAB, 15 ячеек):

```text
chapter row name surface code kind fields headers log norm word cause outcome diagnostic caller
```
 Строки `#` — комментарии, первая прочая — шапка. `name` — уникальный snake_case, `chapter` — `2.K`, `row` — номер строки в её главе с 1 (адрес «N4 row N» столбца `norm`), не id нормы.

`surface`: `call` — чистая процедура, `cli`, `start`, `process` — работающий процесс, `peer` — проверка другого урока. `code`: трёхзначный код HTTP только у `peer`, либо `exit N`, целое N >= 0, `exit !0` — любой ненулевой код, включая 2, `-` — числовой код здесь не задан. `kind`, `fields`, `headers` — `-`: своей HTTP-схемы P/02 нет. `word` — фиксированный токен в обратных кавычках либо `-` без кавычек; разделители не входят в токен; `log` — предметы диагностики через запятую либо фрагменты в «…», `-` — без требования. Неоговорённый вид stdout/stderr это не фиксирует.

Последние четыре колонки несут нормативную прозу отказа целиком: условие, исход, диагностику и действие вызывающего. Генератор не выводит из этой прозы дополнительные проверки. N4 ссылается на форму и второй каталог не повторяет. Проверка — ссылки всех глав, последовательные адреса `(chapter,row)`, уникальные имена, соответствие закрытых ячеек сохранённым исходным. Точный код/слово не расширяется из-за прозаической записи. Примеры: ``2.1 / 1 / load_text / call / - / word `refused:text` ``; `2.3 / 2 / manifest_changed / process / exit 0`; ``2.4 / 14 / secrets_unknown_family / cli / exit 1 / word `unknown-row-form` ``. Штатный выход 0 при изменении манифеста — не неудачная установка.

## Внутренний конечный профиль удаления

`finite-profile.schema.json` — точная внутренняя типизированная запись, не ключи манифеста, флаги или acceptance.yaml. P/02.3 N3 проверяет её после шага6 установки до шага7/всех записей (включая unchanged) и при Process start до дверей. Отсутствующие/нечитаемые лимиты сохраняют прежний отказ; недостаточный профиль — `refused:form`.

`finite-profile.cases.json` (только для судьи: свидетели профиля; они проверяют P/02.3 N3 «Внутренний конечный профиль удаления», «Старт процесса» шаг 3a и «Смена манифеста» шаг 6a — P/02.3-R048, P/02.3-R053, P/02.3-R094, P/02.3-R141, P/02.3-R145, P/02.3-R146, P/02.3-R149, P/02.3-R151, P/02.3-R153, P/02.3-R157, P/02.3-R159, P/02.3-R163, P/02.3-R164) связывает свидетелей с этими существующими входами. owned_context — независимая конечная синтетическая вселенная форм пакетов и доказательств скелетов метаданных; полноту production процедур она не аттестует. Судья источника отвергает пропущенные/повторные пакеты, заниженные H/кратности, неизвестную provenance и неверные фактические лимиты. Принятие схемой и свободные строки этого не доказывают. Настоящие описатели дополнительно покрывают каждый выдаваемый пакет, смешанные пакеты и прочие служебные семьи. Ожидаемые ответы/границы во вход реализации не попадают. Проверки источника/формы/кодека — не установщик/native/SUT или обновление пина. Число свидетелей, граница вселенной и границы кодека — в [данных случаев только для судьи](README.cases.md) (только для судьи: данные случаев свидетелей профиля; они проверяют P/02.3 N3 «Внутренний конечный профиль удаления» — P/02.3-R141, P/02.3-R145, P/02.3-R146, P/02.3-R149, P/02.3-R151, P/02.3-R153, P/02.3-R157, P/02.3-R159, P/02.3-R163, P/02.3-R164).

Кодировка метаданных, байтовые доказательства и размеры скелетов собственного контекста судьи — в [данных случаев только для судьи](README.cases.md) (только для судьи: данные случаев свидетелей профиля; они проверяют P/02.3 N3 «Внутренний конечный профиль удаления» — P/02.3-R141, P/02.3-R145, P/02.3-R146, P/02.3-R149, P/02.3-R151, P/02.3-R153, P/02.3-R157, P/02.3-R159, P/02.3-R163, P/02.3-R164).

## Точная грамматика швов без HTTP

`acceptance/K/seams.tsv`: последняя строка шапки `# scenario<TAB>step<TAB>request<TAB>expect`; шаги подряд с 1, новый адаптер и временные корни. Исполнение раннером следует [общему протоколу адаптера швов](../../../common/ru/acceptance/seams.md#протокол-адаптера-швов); kit stagetests остаются вспомогательными проверками, не процессной приёмкой. Путь стенда — `$data/`, `$run/` или `$manifest/`, внутри корня сценария, без `..`. `inputs/…` — фикстура относительно каталога приёмки. Shell не вызывается.

- `RUN <process> <word>… [<<inputs/<file> | <<$<name>]`: слова через один ASCII-пробел; слово без пробелов/кавычек либо JSON-строка, декодируемая в один argv. Последний stdin-суффикс передаёт байты файла/связанной строки и в argv не входит. Тест вызывает функцию команды в процессе. Пример: `RUN w2cctl manifest put $manifest/bad.subsystem.yaml`.
- Ожидание `exit N`, затем необязательные `; stdout <JSON>`, `; stdout-text <JSON string>`, `; stderr ~<JSON string>` в этом порядке. N — десятичное неотрицательное целое. stdout JSON — по подмножеству, `{}` точно пустой; stdout-text — точные UTF-8 байты; stderr — подстрока. Пример: `exit 2; stderr ~"bad.subsystem.yaml"`. Авария не считается отказом. Где норма задаёт лишь ненулевой код, CALL `command` ниже не выдумывает точный код.
- `CALL <name> <JSON>`: имя `[a-z][a-z0-9-]*`, JSON до конца строки. Ожидание — JSON по общим правилам (объекты по подмножеству, `{}` точно пустой, строковые переменные/маркеры) либо опубликованный `@absent` / `@exit 2`. Новых маркеров непредусмотренной функции грамматика не добавляет. Это нормализация теста, не API реализации.
- `@file <stand path> inputs/<file>` либо `@file <stand path> <JSON string>` пишет точные байты фикстуры/декодированную UTF-8 строку, сперва создав
  недостающие каталоги пути стенда. Ожидает `ok`.
- `@read <stand path>`: JSON — разобранный JSON-файл, `text <JSON string>` — точные UTF-8 байты, `@absent` — отсутствие. Ошибка чтения красная. `text "$name"` сначала связывает байты, затем сравнивает прежние; JSON-режим разбирает содержимое, text — нет. Отсутствие/IO-ошибка не пустое значение.
- `@parallel K` (K >= 2) — следующий RUN/CALL, ожидает `ok`; следующий ожидает `each <expect>` или `one <expect>; rest <expect>`. K вызовов разделяют адаптер/корни и заканчиваются до следующего шага. Новые переменные связывает только `one`. Каждый вложенный expect — по грамматике своего RUN/CALL. Проекция обрывается на неподдержанном шаге, все исключения в описи; пустая проекция — ошибка.

Фикстуры — собственные синтетические данные. Неоговорённый вид вывода команды тест не сужает.

### Раскладка сценария

Команда, вызванная RUN или CALL, получает раскладку P/02.4 N1.2 с `PLATFORM_DIR` = `$data`: раскладку стенда
[общей приёмки](../../../common/ru/acceptance/README.md) с `{data}` = `$data`. Для проверки размещения по
[договору секретных файлов](../../../common/ru/contracts/secret-files.md) (`forbidden`, `layout`) запретных каталогов ровно два:
каталог хранилища `$data/configstore` и корень объектов `$data/objects`; каталоги копий не заданы. Адаптер обеспечивает эти два
каталога до вызова команды (создаёт пустыми, существующий оставляет) и называет их команде по этой раскладке; других запретных
каталогов он не ищет. Шов никогда не требует от команды создать каталог: каждый каталог пути цели существует до вызова — корень,
один из этих двух каталогов или каталог, созданный более ранним шагом `@file` того же сценария. Отсутствующий каталог пути —
отказ команды (`refuse` договора), а не фикстура, которую надо чинить.

### Нормализация CALL

- `command`: `{argv:[<process>,<argument>,…]}` — функция команды в процессе, пути стенда раскрывает адаптер. Итог `{success:<exit code == 0>}`, необязательный `exit_code`. Только штатный возврат; panic/исключение/сигнал не превращаются в отказ. Используется, где норма задаёт 0 против ненулевого, без точного кода отказа.
- `load`: `{source: string, text: string}` — штатный загрузчик этих байтов. Успех `{verdict:"ok", name:<loaded name>}`, отказ `{verdict:"refused", class:<text|form|relations>}`, без частичного манифеста.
- `load-catalogue`: `{manifests:[{source:string,text:string},…]}` — тот же загрузчик и проверка всего набора. Успех `{verdict:"ok", names:[…]}` (сортирует только адаптер), отказ `{verdict:"refused", class:<text|form|relations|catalogue>}`, без имён/частичного каталога. Неявный testsub не добавляется.
- `rollout-poll`: `{input:<machine input>, events:[{t:<seconds>,event:<trace event string>},…]}`. Имена, синтаксис, timers и необязательный `input.const` — из [`rollout-poll.machine.yaml`](../../forms/rollout-poll.machine.yaml) и [`rollout-poll.traces.tsv`](../../forms/rollout-poll.traces.tsv) (только для судьи: исходные трассы машины опроса; они проверяют P/02.4-R321). Новый опрос с t=0, перед событием — движение виртуальных часов, при равенстве timers раньше; `advance` двигает только часы. Итог `{state:<polling|passed|refused>, result:null|{code:<integer>,word:<string>}}`; лишние наблюдения допустимы. Адаптер вызывает опрос реализации, не подменяет его интерпретатором курса. Во входе нет ожидаемых состояний/вердиктов/выходов.

Полную машину судят исходные трассы. Выборка швов не доказывает раскатку ОС, доступность состава или все барьеры.
