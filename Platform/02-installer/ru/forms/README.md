# Формы и швы P/02 для пакета генераторов

Текст производный от `forms/README.md`, руками не правится: источник — английский [`forms/README.md`](../../forms/README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Формы выражают существующие нормы P/02 (ADR-0125 доп. (5)); собственной HTTP-двери установщику не добавляют.

## Аргументы команд

`daemon-flags.tsv` сохраняет восемь колонок P/01: `flag`, `type`, `default`, `default_text`, `required`, `commands`, `bad`, `norm`.
`commands` — id из `operator-commands.tsv` через запятую. Типы: `string`, конечное `number`, `file`, `bool`; `required` и `bad` — CEL над переданными опциями `f` и id команды `cmd`. Нет умолчания — `-`; отсутствующий bool — false, переданный — true. Это аргументы команд, не флаги демона и не переменные окружения.

Колонки `operator-commands.tsv`: `command`, `process`, `prefix`, `positionals`, `norm`. `prefix` — JSON-массив постоянных слов argv; `positionals` — JSON Schema 2020-12 для остальных позиционных слов после разбора опций. Форма не задаёт shell-разбор, формат вывода, код для неоговорённого входа или новый интерфейс чужой команды.

## Каталог отказов

Колонки `refusals.tsv` по порядку: `chapter row name surface code kind fields headers log norm word cause outcome diagnostic caller` (разделитель TAB, 15 ячеек). Строки `#` — комментарии, первая прочая — шапка. `name` — уникальный snake_case, `chapter` — `2.K`, `row` — прежняя строка Н4 с 1, не новый id нормы.

`surface`: `call` — чистая процедура, `cli`, `start`, `process` — работающий процесс, `peer` — проверка другого урока. `code`: `exit N`, целое N >= 0, `exit !0` — любой ненулевой код, включая 2, `-` — числовой код здесь не задан. `kind/fields/headers` — `-`: своей HTTP-схемы нет. `word` — фиксированное слово или `-`; `log` — предметы диагностики через запятую либо фрагменты в «…», `-` — без требования. Неоговорённый вид stdout/stderr это не фиксирует.

Последние четыре колонки сохраняют прежнюю таблицу целиком: условие, исход, диагностику и действие вызывающего. Генератор не выводит из этой прозы дополнительные проверки. Н4 ссылается на форму и второй каталог не повторяет. Проверка — ссылки всех глав, последовательные адреса `(chapter,row)`, уникальные имена, соответствие закрытых ячеек сохранённым исходным. Точный код/слово не расширяется из-за прозаической записи. Примеры: `2.1/1 load_text call - word refused:text`; `2.3/2 manifest_changed process exit 0`; `2.4/14 secrets_unknown_family cli exit 1 word unknown-row-form`. Штатный выход 0 при изменении манифеста — не неудачная установка.

## Gates этапов

`stages.tsv` — план (ADR-0126). `verdicts:2.1:*` выбирает первую колонку `verdicts.tsv`, `puts:2.2:*` и `puts:2.3:*` — `puts.tsv`, `accept` — только `scenarios.tsv`. Имена через запятую — точный выбор, `*` — полная цель с опубликованными вариантами. `tests:2.K:<scenario,...>:seams` — швы ниже. `build` подтверждает сборку; установка ОС, units, TLS, клиенты и операторские окна судятся методами чеклиста, исполненными этим не становятся.

## Точная грамматика швов без HTTP

`acceptance/K/seams.tsv`: `scenario<TAB>step<TAB>request<TAB>expect`; шаги каждого сценария подряд с 1, новый адаптер и временный корень. Раннер швы не читает. Слово — непустое без ASCII-пробельных; путь относительный, без `..`; `inputs/…` — файл относительно приёмки главы. Shell, подстановки и исполнение строки команды отсутствуют.

- `RUN <process> <word>… [<<inputs/<file> | <<$<name>]` — вызов функции команды в процессе с argv; завершающий stdin-суффикс передаёт точные байты файла или прежней строковой переменной и в argv не входит. Пример: `RUN w2cctl secrets new keys/ring.json`.
- Ожидание: `exit <N|!0>`, затем необязательные ` stdout <JSON>` и ` stderr ~<fragment>` в этом порядке. N — десятичное без знака. Проверяется только названный поток. JSON читается декодером до конца значения, затем узнаётся `stderr ~`; объекты — по подмножеству, `{}` — точно пустой. Пример: `exit 2 stderr ~ring.json`. Команда возвращает штатно; авария не становится отказом лишь по ненулевому коду.
- `CALL <name> <JSON>` — функция адаптера урока; JSON занимает остаток запроса. Ожидание — JSON по тем же правилам. Это нормализация теста, не обязательный публичный API реализации. Примеры и типы ниже.
- `@file <path> inputs/<file>` — точные байты фикстуры во временный корень, каталоги создаются, ожидается `ok`.
- `@read <path>` — UTF-8 байты файла как JSON-строка, даже для файла JSON. Ожидание — строка, `"$name"` (первое связывание, затем точное сравнение) или некавыченный `@absent`. Нечитаемый файл не пустая строка. Для не-UTF-8 нужен явный кодек.
- `@parallel K` (K >= 2) — только следующий RUN/CALL, ожидается `ok`; у следующего `each <expect>` или `one <expect>; rest <expect>`. K вызовов разделяют адаптер/корень и завершаются до следующего шага. Переменные связывает только `one`, прочие ссылаются на прежние. Проекция обрывается на неподдержанном запросе целиком, исключение — в описи; пустая выбранная проекция — ошибка.

JSON-строка со знаками маркера — значение файла, не маркер. Фикстуры — собственные синтетические данные. Открытый нормой вид вывода команды тест не сужает.

### Нормализация CALL

- `load`: `{source:string,text:string}` — штатный загрузчик этих байтов. Успех `{verdict:"ok",name:<имя>}`, отказ `{verdict:"refused",class:<text|form|relations>}`, без частичного манифеста.
- `load-catalogue`: `{manifests:[{source:string,text:string},…]}` — тот же загрузчик и проверка всего набора. Успех `{verdict:"ok",names:[…]}` (сортирует только адаптер), отказ `{verdict:"refused",class:<text|form|relations|catalogue>}`, без имён/частичного каталога. Неявный testsub не добавляется.
- `rollout-poll`: `{input:<вход машины>,events:[{t:<секунды>,event:<событие трассы>},…]}`. Имена, синтаксис, timers и необязательный `input.const` — из `rollout-poll.machine.yaml` и `rollout-poll.traces.tsv`. Новый опрос с t=0, перед событием — движение виртуальных часов, при равенстве timers раньше; `advance` двигает только часы. Итог `{state:<polling|passed|refused>,result:null|{code:<целое>,word:<строка>}}`; лишние наблюдения допустимы. Адаптер вызывает опрос реализации, не подменяет его интерпретатором курса. Во входе нет ожидаемых состояний/вердиктов/выходов.

Полную машину судят исходные трассы. Выборка швов не доказывает раскатку ОС, доступность состава или все барьеры.
