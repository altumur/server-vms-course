# Приёмка P/02.1 — вердикты загрузчика манифестов

Текст производный от `acceptance/1/README.md`, руками не правится: источник — английский [`acceptance/1/README.md`](../../../acceptance/1/README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Сценарии [норм главы 2.1](../../spec/02.1-installer.norms.md) N5 (ADR-0080); стенд — [общий README приёмки](../../../../common/ru/acceptance/README.md). Дверь главы — сам загрузчик: файл подаётся один, как манифест подсистемы, и ответ один из двух.

## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. `stand.load` загружает один `{file}` штатным загрузчиком: успех — нулевой выход; отказ называет исходный файл и следует правилам исхода главы. Необязательный `adapters.load` предоставляет тот же загрузчик постоянным транспортом путь/JSON-строка общего договора без шаблонных подстановок. `keys.path_style` объявляет `json` или `dotted` для передачи собственных путей диагностики загрузчика; её сила остаётся по правилам подсказок ниже. Ни один адаптер не выдаёт ответ по имени случая и не подменяет штатный загрузчик.

## verdicts.tsv, classes.tsv, diagnostics.tsv

Три таблицы исполняет слово движка `verdicts` по форме «[Вердикты загрузчика](../../../../common/ru/acceptance/README.md#вердикты-загрузчика)» общего README приёмки: вызов, что считается манифестом и отказом, называющим файл, строгий вердикт, класс `refused:<класс>` и подсказка диагностики определены там. Интерфейс вызова — `stand.load` или `adapters.load` выше. Здесь — только данные главы.

Правила, по которым расставлены вердикты, — нормы главы N1 (текст, документ, поле, ссылки) и N4; здесь их нет, чтобы не было двух версий одной нормы (ADR-0003). Происхождение: общая таблица `spec_verdicts.tsv` (ревью 14 и 15, вердикты «Архитектора» 2026-10-06), перенесённая сюда 2026-10-14 с восемью новыми случаями; прежнее место обе стороны снимают своими окнами.

**`classes.tsv`.** Класс — слой отказа N4 (ADR-0092 п. 6): `text`, `form`, `relations`, `catalogue`. Переход на В7: прежние классы `name`, `key`, `value` стали `form`, `reference` — `relations` (дельты — таблица дельт набора «Б» навыка `lesson-spec`).

**`diagnostics.tsv`.** Пути и строки отказа загрузчика — подсказка, не норма (ADR-0092 п. 5). Индекс списка в пути — целое JSON (`0`), имя ключа — строка (`"0"`): это разные сегменты (N4 «Диагностика»). Пути строки записаны в каноническом порядке — по байтам пути JSON Pointer (RFC 6901), номера строк по возрастанию (ADR-0087 доп. (3) R2). Пустой `lines` значит, что случай номера строк не ищет; в отказе он их не запрещает. В `unknown_multiple` подсказка называет все три пути, а не только первую найденную опечатку; в `dup_top_key_name` — строку 36, второе объявление `name`. Требование назвать исходный файл остаётся — это норма: `unknown_depth4.subsystem.yaml: error` проходит вердикт, а отчёт отметит, что нет пути `unit.fields.name.requried`. У остальных случаев реализации СЛЕДУЕТ давать путь и строку по N4 норм — подсказкой.

## Выборки установки нет

Корпус не прогоняется через `manifest put`. Форма «Последовательности установок» ставит только файлы `puts/` своего каталога, а загрузка и установка судятся раздельно: вердикты этого каталога судят загрузчик; установку, проверки каталога и отказанную установку — строки [`../3/puts.tsv`](../../../acceptance/3/puts.tsv) и шов `s1-put-invalid-source` из [`../4/seams.tsv`](../../../acceptance/4/seams.tsv). Поэтому прежняя выборка СЛЕДУЕТ (все случаи `ok`, по одному отказу на класс) в суд не входит. Шесть принятых файлов корпуса называют `testsub` в отношениях каталога (`bound_to_string`, `blob_required_false`, `secrets_reader_domainconsole`, `m49_table_shelf_log_ok`, `c6_secrets_reads_with_slash_ok`, `c3_near_by_ok`); загруженные одни, они `ok`, в каталоге без `testsub` — `refused:catalogue` (ревью стадии B 1–2, п. 13).

## Дополнительная проверка строковых имён полей (R36-01)

В минимальном корректном манифесте отдельно для `unit.fields` и `tables.<t>.fields` ключи 1, true, null и 1.5 (без кавычек) дают `refused:text` по N1.1 `refused`: простой ключ, который таблица `scalars` читает не строкой, — отказ слоя текста везде, в том числе в ключах значений `json` и `display.options` (`display_options_bool_plain_key`); путь и строка — подсказка по N4. Те же имена в кавычках — строки и проходят. Пара 1/"1" отказывается целиком (`text`), не преобразуется в одну строку с потерей поля. Эти входы добавлены как profile_unit_key_*/profile_table_key_* в verdicts.tsv и проверяются тем же штатным загрузчиком, что остальные случаи; чтение типов YAML-узлов само по себе не доказывает его соответствия.

Случаи profile_* покрывают положительные соседние значения и ограничения P/02.1-13…17,
а также типы ключей полей и принадлежность worker.writes (P/02.1-06/07, P/02.5-01).
Подготовленные вердикты — не результат запуска реализации: автор проверил данные и заявленный
канон, штатный загрузчик исполнения здесь не запускался.

## Класс ошибок R37 (Codex)

Общий фон входит в данные: `lease` — строка `off` в кавычках в каждом файле фона, и `true`/`false` не заменяют `off`/`on`; вердикты этих файлов судят это штатным загрузчиком. Одиночные вердикты и проверка каталога — разные доказательства: проверка каталога — «Пересечение каталога» ниже, включая каталог из одного манифеста.

Значение `{name:int}` (P/02.1 N1.4, P/02.1-21) преобразуется, когда дверь строит ключ из тела запроса, а не при загрузке манифеста. Загрузчик судит только шаблон: случаи `r37_requests_plain_*`, `r37_requests_int_*`, `r37_table_key_bool`, `r37_table_template_bool`, `r37_table_int_template`. Границы преобразования (binary64, модуль не больше 2^53−1, каноническая десятичная запись без экспоненты; bool, null, строка или неконечное число — 400) в этом уроке не судятся: это исход двери, применяющей шаблон.

Две записи одного манифеста двумя установщиками разрешает `cas` (P/02.3 N3); конфликту двух установщиков нужно хранилище другого урока, в этом уроке он не судится (ADR-0130 Addendum (19) п. 7).

## Пересечение каталога

Непересечение имени манифеста с семьями каталога (P/02.1 N3 «load_catalogue», P/02.1-20) судят строки [`../3/puts.tsv`](../../../acceptance/3/puts.tsv): каждая установка грузит кандидата в полном подтверждённом каталоге, и отказ приходит до первой записи.

| Каталог | Конфликтующая семья | Отказ (`refused:catalogue`, код 2) | Положительный контроль | Обратный порядок |
|---|---|---|---|---|
| A=B: один манифест `name=b` | `unit.rows=b` | `self_rows` | `self_rows_renamed` | — |
| A=B: `name=b` | map `tables` содержит `b` | `self_table` | `self_table_renamed` | — |
| A=B: `name=b` | list `tables=[b]` | `self_table_list` | `list_tables_ok` | — |
| A≠B: `name=a` и `name=b` | `rows` манифеста `a` равно `b` | `other_rows` | `other_rows_renamed` | `other_rows_swap` |
| A≠B: `name=a` и `name=b` | map `tables` манифеста `a` содержит `b` | `other_table` | `other_table_renamed` | `other_table_swap` |
| A≠B: `name=a` и `name=b` | list `tables` манифеста `a` содержит `b` | `other_table_list` | `other_table_list_renamed` | `other_table_list_swap` |

Положительный контроль отличается от своего отказа только именем конфликтующей семьи; имена манифестов те же.

## Раздельная проверка формы и ссылки group_by (R39-03)

`group_by_unknown_field` содержит отображение `{field: nosuch}`: форма верна, но поле не объявлено. `r39_group_by_known_field` отличается от него только именем `name` и имеет вердикт ok. Прежний скаляр сохранён как `r39_group_by_scalar` с refused по форме; его отказ не доказывает проверку ссылки. Общий фон и строка lease off сохранены побайтно. Это подготовленные входы и ожидания; штатный загрузчик автором не запускался.

Авторская проверка класса A39-01: `fields_derived_items_unknown` отнесён в N5 к неизвестным ключам N1.2. `unit.derived` не входит в грамматику уроков; отказ этого файла не подтверждает проверку ссылки items.
