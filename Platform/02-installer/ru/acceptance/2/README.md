[`02.2-installer.norms.md`](../../spec/02.2-installer.norms.md) N5; запись вида — [глава 2.3](../../spec/02.3-installer.norms.md)

## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. Пакет функции канонизации использует `stand.canonical` с `{input}`: путь называет входной манифест пакета, stdout содержит ровно канонические байты его [формы провода](../../../../common/vectors/wire.tsv). Пробы установки ниже используют `stand.manifest-put` с `{socket}`, `{file}`; своя команда выполняет штатную установку, а не только печатает канонический вид. Параметры запуска хранилища принадлежат выбранному профилю `01-store`. Объявление команд не доказывает полного positive-profile provider, достаточности B/V и исполнения восстановления.

## puts.tsv и puts-ceiling.tsv

Обе таблицы исполняет слово движка `puts` по форме «[Последовательности установок](../../../../common/ru/acceptance/command-tables.md#последовательности-установок)» общего README приёмки: четыре или пять колонок, директивы `@view-delete`, `@view-spoil`, `@rev-delete`, `@rev-spoil`, исполнение в свежем хранилище на строку и сравнение кода, stderr, `rev`, метки и вида определены там. Декларация `# canonical:` обеих таблиц называет пакет векторов [`canonical`](../../vectors/canonical/README.md): байты `expect/<canonical>.json` — ожидаемое поле `manifest` строки вида (только для судьи: ожидаемые виды пакета; они проверяют P/02.2-R027 и P/02.2-R043). Установка — `stand.manifest-put` выше. `puts.tsv` идёт с потолком строки по умолчанию 524288 байт; `puts-ceiling.tsv` задаёт потолок каждой строки в колонке `ceiling`, и судья подтверждает его до строки (та же форма; только для судьи: таблицы установок главы; они проверяют P/02.2-R009, P/02.2-R015, P/02.2-R017, P/02.2-R027, P/02.2-R032, P/02.2-R044, P/02.2-R051, P/02.2-R054, P/02.2-R055, P/02.3-R016, P/02.3-R031, P/02.3-R103 и P/02.3-R123).

Потолок вида — `max_value` ответа `GET /v1/status` хранилища, а не число 524288. Установщик проверяет вес с окончательной новой rev до любой записи (глава 2.3 N3 шаг 14a), поэтому отказ выше потолка приходит раньше частей, строки и метки.

Случаи другого потолка и их ожидаемые исходы — в [данных случаев только для судьи](README.cases.md) (только для судьи: они проверяют P/02.2-R032, P/02.2-R044, P/02.2-R051).

## Случаи

Случаи и их ожидаемые исходы — в [данных случаев только для судьи](README.cases.md) (только для судьи: они проверяют P/02.2-R009, P/02.2-R015, P/02.2-R017, P/02.2-R027, P/02.2-R032, P/02.2-R051, P/02.2-R054, P/02.3-R031 и P/02.3-R103). Они покрывают такие правила:

| Что проверяет | Норма |
|---|---|
| первая установка пишет строку, вид и метку с одной ревизией; `manifest` — назначенный вектор | P/02.2-R027, P/02.3-R016 |
| тот же файл снова — «unchanged»: ревизия и вид прежние | P/02.3 N3 «Смена манифеста» |
| вида нет, файл тот же — не «unchanged»: новая ревизия строки, вида и метки | P/02.3 N3 («same row, missing view») |
| вид не равен проекции, файл тот же — вид переписан с новой ревизией | там же |
| вес строки вида выше потолка, строка манифеста помещается — отказ целиком, код 2; строка, вид и метка прежние | P/02.2 N3, N4; P/02.3 N4 |
| вес строки вида ровно равен потолку — вид записан; граница области принимаемых манифестов | P/02.2 N1.2 `ceiling` |
| сахар `tables`, `bound_to`, отсутствие `snapshot` и `display` — вид установщика равен назначенному вектору | P/02.2-R009, P/02.2-R015, P/02.2-R017 |
| метки нет, файл тот же — «unchanged»: строка и вид прежние, метка доведена с ревизией и `sha256` строки | P/02.3 N3 «Смена манифеста» («missing mark … → bring up to date»), P/02.3-R103 |
| метка не по форме, файл тот же — отказ, код 2, ничего не записано: строка, вид и метка прежние | P/02.3 N1.5 `rules`, [`manifest-rev.outcomes.tsv`](../../../data/manifest-rev.outcomes.tsv) (читатель `admin`), P/02.3-R031 |
Вес строки вида — сумма байтов имён и значений `items` (P/01.1 N1): `form` `"1"`, `rev` из одной цифры, `sha256` 64 знака,
`manifest` — `87 +` длина вида.

## В этом уроке не судится

- Порядок записей во времени (строка — вид — метка) и повтор вида после конфликта `cas`: таблицы сравнивают состояние после установки; порядок проверяется чтением по N5 главы.
- Потолок, достигнутый через конфликт `cas` двух установщиков, и любой конфликт двух установщиков: им нужно хранилище другого урока, они относятся к этапу системы; таблицы ставят последовательно.
- Кластер из одного процесса (P/02.4 N1.10) и читатель вида (P/02.2-R062, P/02.2-R064, P/02.2-R067, P/02.2-R068, P/02.2-R069, P/02.2-R070, P/02.2-R072 — правками читателей): чтением по N5 главы.
- Нечитаемая строка `platform/manifest/<name>`: по [`manifest-row.outcomes.tsv`](../../../data/manifest-row.outcomes.tsv) читатель `admin` отказывает `manifest put` и ничего не пишет; её строки — `row_spoiled_yaml` и `row_spoiled_sha256` в [`../3/puts.tsv`](../../../acceptance/3/puts.tsv) (только для судьи: таблица установок главы 2.3; они проверяют P/02.3-R031; три столбца: испорченный `sha256` сам по себе развёл бы вид п. 5 со строкой).

## Метка `/rev`

Метку проверяют директивы `@rev-delete`,
`@rev-spoil` и случаи 08 `rev_deleted` и 09 `rev_spoiled`.
Код отказа по нечитаемой метке — `2`: N1.5 главы 2.3 говорит «code ≠ 0», таблица `expect` знает `0` и `2`, отказы
`manifest put` N4 главы 2.3 — код 2.
