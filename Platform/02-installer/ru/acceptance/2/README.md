## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. Пакет функции канонизации использует `stand.canonical` с `{input}`: путь называет входной манифест пакета, stdout содержит ровно канонические байты его [формы провода](../../../../common/vectors/wire.tsv). Пробы установки ниже используют `stand.manifest-put` с `{socket}`, `{file}`; своя команда выполняет штатную установку, а не только печатает канонический вид. Параметры запуска хранилища принадлежат выбранному профилю `01-store`. Объявление команд не доказывает полного positive-profile provider, достаточности B/V и исполнения восстановления.

## puts.tsv и puts-ceiling.tsv

Обе таблицы исполняет слово движка `puts` по форме «[Последовательности установок](../../../../common/ru/acceptance/README.md#последовательности-установок)» общего README приёмки: четыре или пять колонок, директивы `@view-delete`, `@view-spoil`, `@rev-delete`, `@rev-spoil`, исполнение в свежем хранилище на строку и сравнение кода, stderr, `rev`, метки и вида определены там. Декларация `# canonical:` обеих таблиц называет пакет векторов [`canonical`](../../vectors/canonical/README.md): байты `expect/<canonical>.json` — ожидаемое поле `manifest` строки вида. Установка — `stand.manifest-put` выше. `puts.tsv` идёт с потолком строки по умолчанию 524288 байт; `puts-ceiling.tsv` задаёт потолок каждой строки в колонке `ceiling`, и судья подтверждает его до строки (та же форма).

Потолок вида — `max_value` ответа `GET /v1/status` хранилища, а не число 524288 (решение «Архитектора» по вопросу Go P/02 № 4). Установщик проверяет вес с окончательной новой rev до любой записи (глава 2.3 N3 шаг 14a), поэтому отказ выше потолка приходит раньше частей, строки и метки.

Случаи другого потолка и их ожидаемые исходы — в [данных случаев только для судьи](README.cases.md).

## Случаи

Случаи и их ожидаемые исходы — в [данных случаев только для судьи](README.cases.md). Они покрывают такие правила:

| Что проверяет | Норма |
|---|---|
| первая установка пишет строку, вид и метку с одной ревизией; `manifest` — назначенный вектор | P/02.2-04, P/02.3-01 |
| тот же файл снова — «unchanged»: ревизия и вид прежние | P/02.3 N3 «Смена манифеста» |
| вида нет, файл тот же — не «unchanged»: новая ревизия строки, вида и метки | P/02.3 N3 («same row, missing view»); окно 2.2, R12 |
| вид не равен проекции, файл тот же — вид переписан с новой ревизией | там же |
| вес строки вида выше потолка, строка манифеста помещается — отказ целиком, код 2; строка, вид и метка прежние | P/02.2 N3, N4; P/02.3 N4 (окно 2.2, п. 8) |
| вес строки вида ровно равен потолку — вид записан; граница области принимаемых манифестов | P/02.2 N1.2 `ceiling` (ADR-0089 доп. (1) R11) |
| сахар `tables`, `bound_to`, отсутствие `snapshot` и `display` — вид установщика равен назначенному вектору | P/02.2-02, P/02.2-03 |
| метки нет, файл тот же — «unchanged»: строка и вид прежние, метка доведена с ревизией и `sha256` строки (аудит Gemini P/02, свойство 13) | P/02.3 N3 «Смена манифеста» («missing mark … → bring up to date»), P/02.3-03 |
| метка не по форме, файл тот же — отказ, код 2, ничего не записано: строка, вид и метка прежние (свойство 14) | P/02.3 N1.5 `rules`, [`manifest-rev.outcomes.tsv`](../../../data/manifest-rev.outcomes.tsv) (читатель `admin`), P/02.3-01 |
Вес строки вида — сумма байтов имён и значений `items` (P/01.1 N1): `form` `"1"`, `rev` из одной цифры, `sha256` 64 знака,
`manifest` — `87 +` длина вида.

## В этом уроке не судится

- Порядок записей во времени (строка — вид — метка) и повтор вида после конфликта `cas`: таблицы сравнивают состояние после установки; порядок проверяется чтением по N5 главы.
- Потолок, достигнутый через конфликт `cas` двух установщиков, и любой конфликт двух установщиков: им нужно хранилище другого урока (ADR-0130 Addendum (19) п. 7), они относятся к этапу системы; таблицы ставят последовательно.
- Кластер из одного процесса (P/02.4 N1.10, R15) и читатель вида (P/02.2-06 — правками читателей): чтением по N5 главы.
- Нечитаемая строка `platform/manifest/<name>`: по [`manifest-row.outcomes.tsv`](../../../data/manifest-row.outcomes.tsv) читатель `admin` отказывает `manifest put` и ничего не пишет; строки для неё в этих таблицах пока нет: проверка формы спецификации ещё не принимает общее слово `@row-spoil`.
