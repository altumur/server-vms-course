## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. `stand.rights` принимает `{manifests}`, `{deployment}` и выходной `{file}` и выводит файл прав алгоритмом главы; отказы и отсутствие файла — как ниже. `stand.rights-check` получает те же манифесты/развёртывание и существующий сравниваемый `{file}`, не пишет его; ноль — семантическое равенство, ненулевой исход — расхождение. `stand.ring` и `stand.manifest-put` готовят прежний общий стенд по его назначению; процесс хранилища и ролевые сокеты принадлежат выбранному профилю `01-store`. Реализация выбирает команды и флаги этих интерфейсов. Отсутствующее покрытие сравнения остаётся неисполненным, не заменяется сгенерированным результатом.

## scenarios.tsv

Формат — [словарь директив и дверей общего README приёмки](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей): дверь без префикса — хранилище P/01.1, шаг идёт от роли `@as <роль>`; ожидание `<код> <JSON>` — подмножество полей, и каждый ответ судится ещё и полной формой двери хранилища (P/01): `403` — ровно строки `{kind: "forbidden", error}`, 200 — форма `Row` или `Written` P/01.1. Связывания и порядок массивов — по тому же словарю.

Роли сценариев: `console`, `testsubcontroller`, `testsubworker`, `testsub2controller`, `testsub2worker`, `resource`;
а также роли домена `testsubdomain` и `domainagent` (роль домена `<s>domain` есть только у манифеста с `domain.kept` или переносимой
книгой, P/02.5 N1.4).

Сверка python и go M10/6–11 (R1–R5, R7) входит в эти сценарии.

## Изоляция

Каждый сценарий, включая повторный запуск, получает отдельный экземпляр с пустыми
прикладными строками и памятью повторов id. Очистка префиксов не подменяет очистку этой
памяти. Связывания `$name` сбрасываются, роль задаётся первым `@as`; файл прав одинаков
во всех сценариях. Параллельные запуски не разделяют экземпляр.

Фоновые консоли, контроллеры, воркеры и ресурс в эти строки не пишут. Данные разрешений
готовит судья через генератор и настройку экземпляра, а каждый шаг выполняет только
названная роль. Право чтения проверяется без создания строки:
разрешённое чтение отсутствующей строки возвращает Row с items null по главе P/01.1.

Каталоги `variants/<вариант>/` исполняет слово движка `variants` по форме «[Варианты прав](../../../../common/ru/acceptance/README.md#варианты-прав)» общего README приёмки: файлы варианта, `expect.tsv`, `refused`, `check.tsv` с `check/`, вызовы `stand.rights` и `stand.rights-check` с развёртыванием `dep` и что считается `allow` и `deny`, определены там. ## В этом уроке не судится

- Проверки `/v1/rights`, формы файла прав, оценщика, `never`, пересылки и внутреннего admin (P/01.2 N1.3: admin — не роль файла прав, в `secrets.readers` его не добавляют) — в приёмке P/01.2 (стадия B).
- Роли имени манифеста в 19–32 знака: такой каталог отказан при установке по именам ОС (P/02.4 N1.1 `users_groups` names; строка `os_name_sub_len_33` приёмки главы 2.3), поэтому вывод прав над ним проверяется чтением функции, без имён ОС (C02-NAME32-ROLES-01).
- Объявления `<s>/vault*`, `<s>/va*ult/`, `!<s>/vault` и `delete:<s>/vault` прогона 32 — отказ загрузки по форме `secrets.readers` (P/02.1 N1, P/02.5 N1.3 `rule`, N4 строка 3); это случаи `r32_secrets_readers_*` корпуса главы 2.1. Сами ключи хранилища могут содержать литеральную `*` (P/01.1 Key/Listing).
- Неравенство секретных читателей (из манифестов каталога его не построить: читатели выводятся из тех же объявлений) и `CLUSTER=` (вход окружения, не каталога варианта).
- TLS-ключ принадлежит пользователю юнита либо root с группой пользователя юнита (ADR-0075 доп. 3), группа сокета роли не даёт доступа к ключу; режимы сокетов и сертификат — этап системы.

Проверка R36-05 (с 2026-10-30 — случаи приёмки главы 2.1; аудит покрытия P/02, B06): worker.writes с именем собственного unit.rows даёт refused:reference, без генерации прав. Объявленная таблица воркера допустима, console для неё только читает; это не распространяется на строку единицы. Сверить все общие манифесты и все пути генератора, включая списковую форму tables; в текущей TSV нет запуска загрузчика на таком изменённом манифесте.

Генератор сохраняет обе семьи `domain/placed` и `domain/placement` (`v10-worker-domain-reads`) и отдельное `delete:platform/doors/*` консоли (`v1-base`). Метки просьб `objects/<s>/commands/*` (P/06.4 N1.5 mark): воркер манифеста с `requests` пишет, читает и удаляет свою, чужого манифеста — 403, контроллер — 403 (N1.4; журнал cammeta-go, урок 8 № 4) — сценарий 11 и `v2-requests`.

## Аудит покрытия P/02, второй проход (Gemini)

Отчёт the coverage audit Gemini P02 (for people) (ветка gemini/audit-coverage, c698f3291): вывод прав, что прежде проверялся чтением, —
варианты `v8-worker-writes-deletes` (G04), `v9-asked-free-resource` (G05), `v10-worker-domain-reads` (G06),
`v11-controller-cross-tables` (G07; отдельный вариант — манифесты `v6-near-about-ref` не меняются). Предметы вариантов выше.
`--check` и отказы генератора до файла используют формы «Архитектора» `check.tsv` и `refused` (выше). Файл, равный выводу прав по N1.4 после решений «Архитектора» 2026-10-30 (вопросы норм аудита Gemini, P/02), сравнивается как равный: ресурсу — `<M>/<holds.table>/*`
только у манифеста с `holds`, `<s>/holds/*` не выдаётся (п. 1, C02-RESOURCE-HOLDS-TABLE-01); отрицание секрета нечитателю — только
если после уже выданных отрицаний его права ещё достают образец (п. 2, C02-NONREADER-DENY-AFTER-01); метки
`objects/<s>/commands/*` консоли — только у манифеста с `requests` (как у воркера). Чтением остаются: неравенство
читателей секрета (из манифестов каталога не построить: читатели выводятся из тех же объявлений) и `CLUSTER=` (вход
окружения, не каталога варианта).
