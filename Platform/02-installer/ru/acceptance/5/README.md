## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. `stand.rights` принимает `{manifests}`, `{deployment}` и выходной `{file}` и выводит файл прав алгоритмом главы; отказы и отсутствие файла — как ниже. `stand.rights-check` получает те же манифесты/развёртывание и существующий сравниваемый `{file}`, не пишет его; ноль — семантическое равенство, ненулевой исход — расхождение. `stand.ring` и `stand.manifest-put` готовят прежний общий стенд по его назначению; процесс хранилища и ролевые сокеты принадлежат выбранному профилю `01-store`. Реализация выбирает команды и флаги этих интерфейсов. Отсутствующее покрытие сравнения остаётся неисполненным, не заменяется сгенерированным результатом.

- **Команда сверки прав** (P/02.5 N2 `--check`, N3 «установить») — ключ `stand.rights-check` профиля `02-installer`, шаблон с
  теми же подстановками, что у команды вывода прав (`stand.rights`): `{manifests}` — каталог манифестов, `{deployment}`, `{file}` —
  файл прав, который сверяется (не пишется); исход — код: 0 — файл по смыслу равен выводу прав из манифестов, иной — расходится.
  Варианты приёмки P/02.5 с `check.tsv` (только для судьи: таблица случаев варианта) зовут её на каждый случай с каталогом манифестов варианта, `{deployment}` = `dep` и
  `{file}` = `check/<case>.rights`; код сравнивается с колонкой `code` (`0` | `!0`). Нет ключа в профиле — случаи `check.tsv` (только для судьи: таблица случаев варианта)
  не исполнены (не GREEN и не исход реализации). Подстановки `{specs}` в словаре стенда нет.

## scenarios.tsv

Формат — [словарь директив и дверей общего README приёмки](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей): дверь без префикса — хранилище P/01.1, шаг идёт от роли `@as <роль>`; ожидание `<код> <JSON>` — подмножество полей, и каждый ответ судится ещё и полной формой двери хранилища (P/01): `403` — ровно строки `{kind: "forbidden", error}`, 200 — форма `Row` или `Written` P/01.1. Связывания и порядок массивов — по тому же словарю.

Роли сценариев: `console`, `testsubcontroller`, `testsubworker`, `testsub2controller`, `testsub2worker`, `resource`;
а также роли домена `testsubdomain` и `domainagent` (роль домена `<s>domain` есть только у манифеста с `domain.kept` или переносимой
книгой, P/02.5 N1.4).

## Изоляция

Каждый сценарий, включая повторный запуск, получает отдельный экземпляр с пустыми
прикладными строками и памятью повторов id. Очистка префиксов не подменяет очистку этой
памяти. Связывания `$name` сбрасываются, роль задаётся первым `@as`; файл прав одинаков
во всех сценариях. Параллельные запуски не разделяют экземпляр.

Фоновые консоли, контроллеры, воркеры и ресурс в эти строки не пишут. Данные разрешений
готовит судья через генератор и настройку экземпляра, а каждый шаг выполняет только
названная роль. Право чтения проверяется без создания строки:
разрешённое чтение отсутствующей строки возвращает Row с items null по главе P/01.1.

## Варианты манифестов (`variants/`)

Вывод прав по смыслу на манифестах вне стенда. Каталоги `variants/<вариант>/` исполняет слово движка `variants` по форме «[Варианты прав](../../../../common/ru/acceptance/command-tables.md#варианты-прав)» общего README приёмки: файлы варианта, `expect.tsv`, `refused`, `check.tsv` с `check/`, вызовы `stand.rights` и `stand.rights-check` с развёртыванием `dep` и что считается `allow` и `deny`, определены там (только для судьи: `expect.tsv`, `check.tsv` и `check/` каждого варианта). Сравнение `check.tsv` (только для судьи: `check.tsv` варианта `v12-check-rights`) по смыслу — N3 «установить»: множество ролей, у каждой `group` и множества шаблонов `read`, `write`, `delete` (нет `delete` — пустое множество); `comment`, порядок, повторы и пробелы не сравниваются; файл не по форме P/01.2 N1.2 расходится.

## В этом уроке не судится

- Проверки `/v1/rights`, формы файла прав, оценщика, `never`, пересылки и внутреннего admin (P/01.2 N1.3: admin — не роль файла прав, в `secrets.readers` его не добавляют) — в приёмке P/01.2.
- Роли имени манифеста в 19–32 знака: такой каталог отказан при установке по именам ОС (P/02.4 N1.1 `users_groups` names; строка `os_name_sub_len_33` приёмки главы 2.3), поэтому вывод прав над ним проверяется чтением функции, без имён ОС.
- Объявления `<s>/vault*`, `<s>/va*ult/`, `!<s>/vault` и `delete:<s>/vault` — отказ загрузки по форме `secrets.readers` (P/02.1 N1, P/02.5 N1.3 `rule`, N4 строка 3); это случаи `r32_secrets_readers_*` корпуса главы 2.1. Сами ключи хранилища могут содержать литеральную `*` (P/01.1 Key/Listing).
- Неравенство секретных читателей (из манифестов каталога его не построить: читатели выводятся из тех же объявлений) и `CLUSTER=` (вход окружения, не каталога варианта).
- TLS-ключ принадлежит пользователю юнита либо root с группой пользователя юнита, группа сокета роли не даёт доступа к ключу; режимы сокетов и сертификат — этап системы.

Случаи приёмки главы 2.1 проверяют: worker.writes с именем собственного unit.rows даёт refused:reference, без генерации прав. Объявленная таблица воркера допустима, console для неё только читает; это не распространяется на строку единицы. Сверить все общие манифесты и все пути генератора, включая списковую форму tables; в текущей TSV нет запуска загрузчика на таком изменённом манифесте.

Генератор сохраняет обе семьи `domain/placed` и `domain/placement` (`v10-worker-domain-reads`) и отдельное `delete:platform/doors/*` консоли (`v1-base`). Метки просьб `objects/<s>/commands/*` (P/06.4 N1.5 mark): воркер манифеста с `requests` пишет, читает и удаляет свою, чужого манифеста — 403, контроллер — 403 (N1.4) — сценарий 11 и `v2-requests`.

## Свойства вариантов v8–v11

Вывод прав, который проверяют варианты `v8-worker-writes-deletes`, `v9-asked-free-resource`, `v10-worker-domain-reads`,
`v11-controller-cross-tables` (отдельный вариант — манифесты `v6-near-about-ref` не меняются). Предметы вариантов выше.
`--check` и отказы генератора до файла используют формы `check.tsv` и `refused` (выше; только для судьи: `check.tsv` и `refused` вариантов `v12-check-rights`, `v13-refused-idem-read`, `v14-refused-secrets-reads-nested`). Файл, равный выводу прав по N1.4, сравнивается как равный: ресурсу — `<M>/<holds.table>/*`
только у манифеста с `holds`, `<s>/holds/*` не выдаётся; отрицание секрета нечитателю — только
если после уже выданных отрицаний его права ещё достают образец; метки
`objects/<s>/commands/*` консоли — только у манифеста с `requests` (как у воркера). Чтением остаются: неравенство
читателей секрета (из манифестов каталога не построить: читатели выводятся из тех же объявлений) и `CLUSTER=` (вход
окружения, не каталога варианта).
