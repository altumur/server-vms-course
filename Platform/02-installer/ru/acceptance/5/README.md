## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. `stand.rights` принимает `{manifests}`, `{deployment}` и выходной `{file}` и выводит файл прав алгоритмом главы; отказы и отсутствие файла — как ниже. `stand.rights-check` получает те же манифесты/развёртывание и существующий сравниваемый `{file}`, не пишет его; ноль — семантическое равенство, ненулевой исход — расхождение. `stand.ring` и `stand.manifest-put` готовят прежний общий стенд по его назначению; процесс хранилища и ролевые сокеты принадлежат выбранному профилю `01-store`. Реализация выбирает команды и флаги этих интерфейсов. Отсутствующее покрытие сравнения остаётся неисполненным, не заменяется сгенерированным результатом.

## scenarios.tsv

Формат — [словарь директив и дверей «Стенда» общего README приёмки](../../../../common/ru/acceptance/README.md#словарь-директив-и-дверей): дверь без префикса — хранилище, `@as <роль>`, `@header` перед методом, `$name`, `ASSERT`;
ожидание — подмножество полей, `index` может быть опущен. Своё:

- `expect` без тела у кода `403` — полная форма `{kind: forbidden, error: …}`. Для отказа операции над строкой error называет роль, действие и ключ.

Отсутствующее тело ожидания 200 не означает пустой ответ. Его форму проверяют по контракту
входа главы P/01.1; 403 — ровно строки kind/error без полей консоли. `$name` связывается только
после совпадения всего шага; повтор переменной сравнивается с прежним значением. Порядок
ключей в list остаётся порядком хранилища, раннер не сортирует фактический ответ.

Роли сценариев: `console`, `testsubcontroller`, `testsubworker`, `testsub2controller`, `testsub2worker`, `resource`;
сц. 12 — ещё `testsubdomain` и `domainagent` (роли домена файла прав `testsub`: у `testsub` есть `kept` и переносимая
книга `tallies`, у `testsub2` книги только собираемые — роли `testsub2domain` нет и сокета нет).

Сверка python и go M10/6–11 (R1–R5, R7) входит в эти сценарии.

## Изоляция

Каждый сценарий, включая повторный запуск, получает отдельный экземпляр с пустыми
прикладными строками и памятью повторов id. Очистка префиксов не подменяет очистку этой
памяти. Переменные раннера сбрасываются, роль задаётся первым `@as`; файл прав одинаков
во всех сценариях. Параллельные запуски не разделяют экземпляр.

Фоновые консоли, контроллеры, воркеры и ресурс в эти строки не пишут. Данные разрешений
готовит раннер через генератор и настройку экземпляра, а каждый шаг выполняет только
названная роль. Право чтения проверяется без создания строки:
разрешённое чтение отсутствующей строки возвращает Row с items null по главе P/01.1.

## Варианты манифестов (`variants/`)

Вывод прав по смыслу на манифестах вне стенда (сверка python и go M10/6–11: R2–R8, R10, R12; строка реестра e31e5c28).
Каталог `variants/<вариант>/` — файлы `*.subsystem.yaml` (каталог манифестов варианта, загружаются по главе 2.1) и ровно
одно из: `expect.tsv` (вывод прав и пробы), `refused` (ожидаемый отказ генерации), `check.tsv` с каталогом `check/` (сверка
`--check`); формы `refused` и `check.tsv` — решение «Архитектора» по вопросу формы (аудит Gemini P/02, свойства 24, 25).

**`expect.tsv`:** UTF-8, LF, поля через TAB; строки с `#` пропускаются; заголовок `role	action	key	expect`; дальше по
строке на пробу: роль файла прав (P/01.2 N1.1), действие `read` | `write` | `delete`, ключ строки, `allow` | `deny`.

**Исполнение.** Для каждого варианта раннер:
1. зовёт инструмент вывода прав реализации (N2, «Решает реализация» п. 1) на каталоге варианта с развёртыванием `dep` —
   командой вывода прав «Стенда» общего README приёмки; код ≠ 0 — несовпадение варианта;
2. запускает свежий экземпляр хранилища с этим файлом (`{rights}`);
3. на каждую строку звонит сокетом роли: `read` — `GET /v1/get?key=<ключ>`, `write` — `put` с `items: {"p": "1"}`, `delete`
   — `delete`, без `cas` и стража. Правило — как у вектора оценщика (`Platform/01-store/vectors/rights-evaluator`):
   `allow` — только подтверждённый успех: у чтения 200 формы `Row` (у отсутствующей строки — `{items: null, index: ""}`,
   глава P/01.1 N2), у записи и удаления 200 `Written`; `deny` — 403 `forbidden`; сокета роли нет — то же, что 403 (роли нет в
   файле: «роль не в файле → нет», P/01.2 N1.3); 5xx, ошибка транспорта и иной ответ — неопределённый исход: проба не
   засчитана ни как `allow`, ни как `deny`, прогон варианта не зелёный (ревью стадии A, RA1-16).

Порядок строк не важен: каждая проба — своё действие одного свежего экземпляра. Так проверяется смысл файла прав (P/01.2 N1.3 и
`never`), а не его байты: порядок образцов, `comment`, лишние эквивалентные образцы (R18) и группы не сверяются.

**`refused`:** UTF-8, LF; строки с `#` пропускаются; ровно одна прочая строка — `name` манифеста варианта, чьё объявление
отказано. Раннер зовёт команду вывода прав, как в п. 1 выше: код ДОЛЖЕН быть `2`, файла прав по пути `{file}` нет (отказ
генерации до файла, N4), stderr называет этот манифест — его `name` или его файл (N4: «declaration name and manifest»);
текст сверх этого не сравнивается. Хранилище не запускается, проб нет.

**`check.tsv`:** UTF-8, LF, поля через TAB; строки с `#` пропускаются; заголовок `case	file	code`; дальше по строке на
случай: `case` — `[a-z0-9_]+`, уникально; `file` — `check/<case>.rights`, файл прав; `code` — `0` (файл по смыслу
равен сгенерированному) или `!0` (любой код, кроме 0). Раннер на каждую строку зовёт сверку прав реализации (`rights --check
<file>`, N2, N3 «установить») — командой `stand.rights-check` профиля `02-installer` ([общий README приёмки](../../../../common/ru/acceptance/README.md),
«Rights comparison command»): `{manifests}` — каталог манифестов варианта, `{deployment}` = `dep`, `{file}` — `check/<case>.rights`;
исход — код, сравнивается с колонкой `code`. Нет ключа в профиле — случаи `check.tsv` не исполнены (не GREEN и не исход
реализации) (решение «Архитектора» 2026-10-30, вопросы норм аудита Gemini, P/02 п. 3; C02-RIGHTS-CHECK-STAND-01). Сравнение по смыслу
— N3 «установить»: набор ролей, у каждой `group` и множества образцов `read`, `write`, `delete` (нет `delete` — пустое
множество); `comment`, порядок, повторы и пробелы не сравниваются; файл не по форме P/01.2 N1.2 — расходится.

## Проверки вне сценарного файла

- Проверки `/v1/rights`, формы файла прав, оценщика, `never` и пересылки — в приёмке P/01.2 (стадия B).
- Проверить вывод ролей с коротким и предельным 32-значным именем манифеста: роли файла прав (грамматика P/01.2) сохраняют
  полное имя и суффикс — функцией вывода прав над манифестом, без имён ОС; полный каталог с таким именем — отказ каталога по
  именам ОС длиннее 32 знаков (P/02.4 N1.1 `users_groups` names; C02-NAME32-ROLES-01). `--check` использует неизменный каталог.
  Негативный пример формы файла не содержит вручную расширенных прав.
- По N5 сверить эффективные read/write/delete обеих строк допуска контроллера и
  сохранность остальных удалений. Секретные читатели сравниваются среди обычных ролей;
  admin имеет отдельное исключение, его не добавляют в secrets.readers.

Это предметы отдельного чтения/структурного теста, а не дополнительные исполненные
сценарии. Режимы сокетов, пересылка и сертификат требуют соответствующего стенда.

Пробы прогона 32: объявления testsub/vault*, testsub/va*ult/, !testsub/vault и delete:testsub/vault отвергаются до файла. Для допустимого точного testsub/vault соседние vault2 и vault/nested сохраняют обычные права; testsub/vault/ обозначает только семью под слешем. Общие Key/Listing главы P/01.1 по-прежнему допускают буквальный * как данные.

Проверка R36-05 (с 2026-10-30 — случаи приёмки главы 2.1; аудит покрытия P/02, B06): worker.writes с именем собственного unit.rows даёт refused:reference, без генерации прав. Объявленная таблица воркера допустима, console для неё только читает; это не распространяется на строку единицы. Сверить все общие манифесты и все пути генератора, включая списковую форму tables; в текущей TSV нет запуска загрузчика на таком изменённом манифесте.

## Дополнительная проверка класса ошибок прогона 36 (Kimi)

Чтением: TLS-ключ принадлежит пользователю юнита либо root с группой пользователя юнита (ADR-0075 доп.3), группа ролевого сокета доступа к ключу не даёт. Итоговое множество прав вычислять с never и отрицаниями секретных читателей: положительный baseline не возвращает запрещённый доступ. Генератор сохраняет обе семьи domain/placed и domain/placement и отдельный console delete:platform/doors/*.

Это предмет ручной проверки спецификации и будущей проверки реализации. Подготовленные запросы, чтение и конечные модели автора не являются выполненным стендовым испытанием.

Метки просьб `objects/<s>/commands/*` (P/06.4 N1.5 mark): воркер манифеста с `requests` пишет, читает и
удаляет свою, чужого манифеста — 403, контроллер — 403 (N1.4; журнал cammeta-go, урок 8 № 4).

## Аудит покрытия P/02, второй проход (Gemini)

Отчёт the coverage audit Gemini P02 (for people) (ветка gemini/audit-coverage, c698f3291): вывод прав, что прежде проверялся чтением, —
варианты `v8-worker-writes-deletes` (G04), `v9-asked-free-resource` (G05), `v10-worker-domain-reads` (G06),
`v11-controller-cross-tables` (G07; отдельный вариант — манифесты `v6-near-about-ref` не меняются). Предметы вариантов выше.
`--check` и отказы генератора до файла используют формы «Архитектора» `check.tsv` и `refused` (выше). Файл, равный выводу прав по N1.4 после решений «Архитектора» 2026-10-30 (вопросы норм аудита Gemini, P/02), сравнивается как равный: ресурсу — `<M>/<holds.table>/*`
только у манифеста с `holds`, `<s>/holds/*` не выдаётся (п. 1, C02-RESOURCE-HOLDS-TABLE-01); отрицание секрета нечитателю — только
если после уже выданных отрицаний его права ещё достают образец (п. 2, C02-NONREADER-DENY-AFTER-01); метки
`objects/<s>/commands/*` консоли — только у манифеста с `requests` (как у воркера). Чтением остаются: неравенство
читателей секрета (из манифестов каталога не построить: читатели выводятся из тех же объявлений) и `CLUSTER=` (вход
окружения, не каталога варианта).
