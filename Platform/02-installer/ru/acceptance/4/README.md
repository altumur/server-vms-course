У каждого сценария новые временные корни; входы файлов кольца — собственные строки, реальных ключей нет. RUN вызывает функцию команды; CALL `command` наблюдает 0 против ненулевого кода без выдуманного точного кода/формы вывода. Авария — не отказ. Исходные [машина](../../../forms/rollout-poll.machine.yaml) и [трассы](../../../forms/rollout-poll.traces.tsv) — канон: во входах швов только вход и внешние события со временем, без ожидаемых утверждений. Адаптер наблюдает опрос реализации, один интерпретатор курса реализацию не подтверждает.

Исходные трассы судят всю машину; семь выбранных сценариев — меньшая регрессия реализации. Они не доказывают настоящую раскатку, get/install, барьеры store/консоли, ОС/службы, TLS, отзыв, операторские окна и клиентов. Их проверки остаются в нормах/чеклисте. 946 файлов загрузчика, прежние puts и права — отдельные проверки. При подготовке швов реализация не запускалась.

## Входы

[`inputs/seam-bad.subsystem.yaml`](../../../acceptance/4/inputs/seam-bad.subsystem.yaml) — собственная фикстура `s1-put-invalid-source`: YAML-документ только с `name`, без обязательной структуры манифеста. Сценарий копирует его через `@file`, вызывает штатный `manifest put` и проверяет отказ и неизменность исходных байтов. Это намеренно не принятый файл корпуса манифестов. Остальные файловые входы — собственные строки в таблице швов.

## Группы сокетов ролей платформы

Структурная проверка юнитов включает группу сокета роли в SupplementaryGroups у resource, console, `<sub>controller`, domain, domainconsole и domainagent (P/02.5 Н3 п. 2). Она добавляется к прежним группам store/events/secrets, не заменяет их. Общему пользователю w2c не выдаются сразу все группы ролей. В частности domainconsole по-прежнему без w2c-secrets.

Добавленный шов `CALL installer-role-unit-groups <JSON>` исполняет обычный построитель/писатель юнитов установщика с валидным каталогом testsub, развёртыванием w2c и включёнными юнитами домена во временный корень вывода. Разбирает настоящие service/socket юниты; сравнивает эффективные SupplementaryGroups сервиса с SocketGroup сокета его роли и SocketMode=0660. `checked` считает шесть действительно сопоставленных ролей, `missing` — роли без нужной дополнительной группы, `mismatched_socket_groups` — несоответствия групп сокетов, `domainconsole_secrets` — наличие w2c-secrets. Возвращаются наблюдения построенных юнитов, не копия входа/ожидания. Шов структуры не требует запуска сервиса, root и изменения групп ОС; настоящий системный стенд остаётся отдельной обязанностью.

## Выбор обхода секретов

Швы `s12-secrets-walk-unknown` и `s13-secrets-walk-kept` проверяют выбор P/02.4 Н1.9 «Обход». Вход
`CALL secrets-walk <JSON>` — `{argv:["w2cctl","secrets","status"|"seal",<prefix>,…], rows:{<key>:<row>,…}}`, строка — объект
строковых элементов. Адаптер готовит новое хранилище сценария (хранилище P/01 с дверью полных прав, в процессе или
временным демоном под `$data/configstore`), ставит собственный манифест [`testsub`](../../../acceptance/2/puts/testsub.subsystem.yaml)
штатным `manifest put`, пишет ровно данные строки через `cas ""`, кольца не задаёт (`SECRETS_KEY` не задан) и вызывает функцию
команды с argv над этим хранилищем. Возвращает `{exit_code:<integer>, unknown:[…], untouched:<bool>}`: `unknown` — ключи
строк журнала «`<ключ>` unknown-row-form» этого вызова, отсортированные, каждый по одному разу; `untouched` — у каждой данной строки после вызова
те же байты и версия. В `s12` (умолчание D) `identity/x` не подходит ни к одной строковой семье: она перечислена, код 1; хранимые строки
`domain/testsub/ledger` и `domain/testsub/badges/b1` (testsub `domain.kept: [ledger, badges/]`) не перечислены. В `s13` (заданный
префикс `domain/`, только хранимые строки) обходить нечего: код 0. Оба шва вне ворот стадии
[`stages.tsv`](../../../forms/stages.tsv): у построенного пакета пока нет функции адаптера для этого CALL, и исполненными швы не объявлены.
