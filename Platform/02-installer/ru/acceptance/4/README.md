# P/02.4 — дополнительные швы команд и опроса для пакета

Текст производный от `acceptance/4/README.md`, руками не правится: источник — английский [`acceptance/4/README.md`](../../../acceptance/4/README.md), правка идёт в него, русский пересобирается переводом.

Каталог передаёт [`seams.tsv`](../../../acceptance/4/seams.tsv) (только для судьи: таблица швов) тестам пакета. HTTP-стенда не добавляет. Таблицу исполняет слово движка `run` по протоколу адаптера швов общего README приёмки; сценарии используют грамматику и нормализацию CALL из [`forms/README.md`](../../forms/README.md).

Обязанности этих сценариев — P/02.3 N3 «Смена манифеста» шаг 1 и N4, P/02.4 N1.9 `secrets` и «Обход» (P/02.4-R371, P/02.4-R383, P/02.4-R386, P/02.4-R388, P/02.4-R394, P/02.4-R400, P/02.4-R401), P/02.4 N1.9 poll (P/02.4-R305, P/02.4-R307, P/02.4-R319, P/02.4-R321, P/02.4-R324, P/02.4-R330, P/02.4-R332); предметы сценариев — в данных судьи о случаях.

У каждого сценария новые временные корни; входы файлов кольца — собственные строки, реальных ключей нет. RUN вызывает функцию команды; CALL `command` наблюдает 0 против ненулевого кода без выдуманного точного кода/формы вывода. Авария — не отказ. Исходные [машина](../../../forms/rollout-poll.machine.yaml) и [трассы](../../../forms/rollout-poll.traces.tsv) (только для судьи: исходные трассы автомата опроса) — канон: во входах швов только вход и внешние события со временем, без ожидаемых утверждений. Адаптер наблюдает опрос реализации, один интерпретатор курса реализацию не подтверждает.

Исходные трассы судят всю машину; семь выбранных сценариев — меньшая регрессия реализации. Они не доказывают настоящую раскатку, get/install, барьеры store/консоли, ОС/службы, TLS, отзыв, операторские окна и клиентов. Их проверки остаются в нормах/чеклисте. 951 файл загрузчика, прежние puts и права — отдельные проверки. При подготовке швов реализация не запускалась.

## Интерфейс профиля

[Общий договор профиля](../../../../common/ru/acceptance/PROFILE.md) не превращает эти generated CALL-швы в новую публичную цель стенда. Векторные интерфейсы `02-installer` `stand.workers-script`, `stand.platform-lists`, `stand.exec`, `stand.install-order`, `stand.env-line` получают `{input}` с точными нативными входом и исходом по своим строкам [формы провода](../../../../common/vectors/wire.tsv) и README пакета. Они вызывают собственные функции реализации. `stand.ring` создаёт кольцо в `{file}` существующей secrets-командой; это не право заменить существующий файл. Конверт `vectors` используется только на явно объявленной формой поверхности, без придуманного алиаса нативной stand-команды. Эти объявления не подключают и не исполняют иначе непривязанные швы.

## Группы сокетов ролей платформы

Структурная проверка юнитов включает группу сокета роли в SupplementaryGroups у resource, console, `<sub>controller`, domain, domainconsole и domainagent (P/02.5 N3 п. 2). Она добавляется к прежним группам store/events/secrets, не заменяет их. Общему пользователю w2c не выдаются сразу все группы ролей. В частности domainconsole по-прежнему без w2c-secrets.

Добавленный шов `CALL installer-role-unit-groups <JSON>` исполняет обычный построитель/писатель юнитов установщика с валидным каталогом testsub, развёртыванием w2c и включёнными юнитами домена во временный корень вывода. Разбирает настоящие service/socket юниты; сравнивает эффективные SupplementaryGroups сервиса с SocketGroup сокета его роли и SocketMode=0660. `checked` считает шесть действительно сопоставленных ролей, `missing` — роли без нужной дополнительной группы, `mismatched_socket_groups` — несоответствия групп сокетов, `domainconsole_secrets` — наличие w2c-secrets. Возвращаются наблюдения построенных юнитов, не копия входа/ожидания. Шов структуры не требует запуска сервиса, root и изменения групп ОС; настоящий системный стенд остаётся отдельной обязанностью.

## Выбор обхода секретов

Швы `s12-secrets-walk-unknown` и `s13-secrets-walk-kept` проверяют выбор P/02.4 N1.9 «Обход». Вход
`CALL secrets-walk <JSON>` — `{argv:["w2cctl","secrets","status"|"seal",<prefix>,…], rows:{<key>:<row>,…}}`, строка — объект
строковых элементов. Адаптер готовит новое хранилище сценария (хранилище P/01 с дверью полных прав, в процессе или
временным демоном под `$data/configstore`), ставит собственный манифест [`testsub`](../../../acceptance/2/puts/testsub.subsystem.yaml) (только для судьи: фикстура манифеста главы 2.2)
штатным `manifest put`, пишет ровно данные строки через `cas ""`, кольца не задаёт (`SECRETS_KEY` не задан) и вызывает функцию
команды с argv над этим хранилищем. Возвращает `{exit_code:<integer>, unknown:[…], untouched:<bool>}`: `unknown` — ключи
строк журнала «`<ключ>` unknown-row-form» этого вызова, отсортированные, каждый по одному разу; `untouched` — у каждой данной строки после вызова
те же байты и версия. По P/02.4 N1.9 «Walk» строка, не подходящая ни к одной строковой семье, перечислена, код 1; хранимая строка манифеста (`domain.kept`) не перечислена и на код не влияет. Оба шва исключены из суда: они не стоят ни в одних воротах
[`stages.tsv`](../../../forms/stages.tsv), не засчитываются для P/02.4-14 (этап 8 закрывает его швами `s2`–`s4`), и цель, исполняющая эту таблицу, их не выбирает. Причина: CALL `secrets-walk` нужен адаптер, который готовит хранилище P/01 и ставит манифест, а в протоколе адаптера швов такой функции пока нет.
