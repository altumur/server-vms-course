## Интерфейс профиля

Используется [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `02-installer`. `stand.manifest-put` принимает подготовленные административный `{socket}` и кандидат `{file}`, выполняет штатную установку манифеста с прежними правилами каталога, файлов, порядка записи и неизменённого состояния. Нативный исход установки описан ниже; подстановки deployment и строки ожидания команда не получает. Создание хранилища принадлежит выбранному профилю `01-store`. Реализация выбирает обёртку и флаги для существующего договора команды. Явно непривязанное обязательство восстановления ниже остаётся неисполненным.

## puts.tsv

Таблицу исполняет слово движка `puts` по форме «[Последовательности установок](../../../../common/ru/acceptance/README.md#последовательности-установок)» общего README приёмки с тремя колонками: директивы `@rev-max`, `@shell-put <source>`, `@file-fill <путь> <байтов>`, исполнение в свежем хранилище на строку и сравнение кода, имени файла в stderr и `rev` строки определены там; метка `/rev` и вид не сравниваются. Установка — `stand.manifest-put` выше (имя команды и argv `manifest put` — [`operator-commands.tsv`](../../../forms/operator-commands.tsv), N3 «Смена манифеста»).

Декларация `# beside:` таблицы кладёт всё содержимое [`06-console/acceptance/5/inputs/testsub2/`](../../../../06-console/acceptance/5/inputs/testsub2) рядом с рабочей копией каждой установки — те же файлы, что у `testsub2` на стенде (общий README, «Manifests»); P/02.3 N3 читает их рядом с файлом манифеста. До `@shell-put` у строки нет оболочки рядом с манифестом (N1.5 `shell`: нет файла — поле не пишется). Размеры `@file-fill` — потолки N1.5, поэтому файлы в 8 МиБ не являются данными приёмки.

Предметы строк (правила — нормы главы и главы 2.1 N3):

Проверки каталога (глава 2.1 N3 `load_catalogue`: «A=B», совпадение `metrics.prefix`) при одиночной загрузке такого файла дают `ok`, отказ — только у установки в каталоге. Тот же файл снова — «unchanged»; изменённый файл с тем же именем получает новую ревизию.
Проверки каталога главы 2.1 N3 действуют для `worker.creates`, `worker.uses` и имён ОС (ADR-0091). Адресата или владельца доли в каталоге ещё нет — проверка ждёт его установки; адресат после несовместимого заказчика — отказ у установки адресата.
Виды токена домена (ADR-0091 доп. (14), (17), (18) п. 6): тот же вид у второй подсистемы — отказ; вид маршрута `door.routes[].domain` объявлен другой подсистемой каталога или своей — принят; вида нет — отказ (отсрочки нет).
Статические файлы и объявленная оболочка (ADR-0094 B7): все расширения, вложенные сегменты, `api.js` и `apis/…` рядом с запретом `api/`, пустой файл и файл в две части — принятые имена; указанный в перечне файл, которого нет, — код 2, stderr называет файл манифеста и путь; `console.shell: true`, оболочки нет — код 2; тот же манифест без этого слова при наличии оболочки — новая ревизия с объявлением; файл выше `FILE_MAX` или сумма выше `FILES_TOTAL_MAX` — код 2 до записи, ревизия прежняя; ровно `FILE_MAX` — принят.
Отсрочка `near` (ADR-0091 доп. (26) п. 2): подсистемы `near.sub` нет — клиент принят, проверка полей ждёт; адресат после несовместимого клиента — отказ у установки адресата.

## В этом уроке не судится

- Старт процесса по строке: метка, все причины отказа старта и два кода старта, допустимая отстающая метка, остановка при смене метки (N3 «Старт процесса», N4 строки 1–3). Им нужны процессы поздних уроков: перечень урока системы и этап системы.
- Место ветви `toolarge` в коде установщика (N5): чтением. Её исход — строка `toolarge_row`.
- Значение `rev` в stderr после `@rev-max` (N4 строка 5): чтением по N4. Ключ строки, атрибут `on…=`, пути `console.files` и ключ при `toolarge` судят `@stderr` их строк.
