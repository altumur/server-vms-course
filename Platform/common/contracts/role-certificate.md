# Договор сертификата роли: форма, подписи, комплект, отзыв

Общий договор модуля «Платформа» (ADR-0083 доп. (5); решение «Архитектора» по ревью стадии B 1–2, п. 4). Владелец — урок
[P/02](../../02-installer/spec/02.4-installer.norms.md), глава 2.4 Н1.6 (центр, комплекты ролей, правило адреса; ADR-0083 доп. (29) п. 9: строка называет урок-владельца нормы; библиотеку по договору пишет сессия `common` генерации). Выпускает
сертификаты установщик ([P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md): центр, `w2c-ca.sh`, комплекты ролей,
правило адреса); проверяет пира каждая дверь между процессами — демон хранилища
([P/01.3 Н1.6](../../01-store/spec/01.3-store.norms.md)), двери ролей ([P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md)
`doors`) и домена (уроки P/08–P/10; разбор ревью стадии B 8–10, № 22); серверная сторона дверей
между кластерами класса `signed` — раздел «Серверная сторона: класс `signed`» (участники — процесс `domain`, глава P/08.0,
ретранслятор, [P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.6, P/09.2-07, и консоль кластера — всё входящее из других
кластеров на её слушателе, [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.7 `server`; ADR-0083 доп. (18), доп. (19) п. 2; класс делится по
слушателю: слушатель `SIGNER_URL` процесса `domain` сертификат клиента запрашивает необязательно и предъявленный
проверяет, прочие участники его не запрашивают — ADR-0083 доп. (20), доп. (21)). Перенесено из P/01.3 Н1.6
(прежде М10/11 Н1.6) без изменения поведения: какие роли допускает каждая дверь, остаётся в норме этой двери.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

```yaml
cert:         CN <роль>.<server>; SAN DNS <server>; SAN URI urn:w2c:role:<роль> — ровно одна роль; serverAuth + clientAuth;
              825 дней; центр 10 лет; роли configstore и configstore-door — ни с какой другой; профиль расширений
              центра и листа и сроки в секундах — правило выпуска P/02.4 Н1.6 ca; проверяющий их сверх договора peer шагов 2–5
              и класса signer не требует (догадка стадии C RC-03, решение «Архитектора» 2026-10-23)
sig:          подписи сертификатов центра, промежуточных и листов — закрытый список: ECDSA P-256 и P-384 с SHA-256 или
              SHA-384, RSA ≥ 2048 бит — PKCS#1 v1.5 и PSS с SHA-256 или SHA-384, Ed25519; иная подпись —
              цепочка не проверяется (добавлено сверкой М11, D14, cammeta-python М11-08 № 21)
kit:          /etc/w2c/tls/ca.pem, revoked | crl.pem, <роль>/server.pem, <роль>/server.key (ключ 0600 владельцу-пользователю юнита либо 0640 root:<группа пользователя юнита> по ADR-0075 доп.3; каталог 0750)
              # /etc/w2c/tls — корень W2C_TLS_DIR на Linux (раздел «Комплект кластера…» ниже; разбор ревью стадии B 8–10, № 4)
revoke:       серийники в revoked — копируются на каждый сервер; процессы перечитывают по содержимому; configstore leave у лидера
  file:       revoked — текст UTF-8, строки через LF; строка — один серийник сертификата: hex-цифры (0–9, a–f, A–F) без «0x»,
              знака и разделителей; регистр не важен; сравнение по целому значению — ведущие нули не значимы (00ff и FF —
              один серийник); десятичной записи нет (123 — это серийник 0x123); пустая строка и строка, которая начинается
              с «#», — пропуск; последняя строка МОЖЕТ быть без LF; повтор серийника — не ошибка (векторы
              common/vectors/revoked; догадка стадии C S01, решение «Архитектора» 2026-10-23)
  bad_file:   любая иная строка (пробел, «0x», «:», CR, знак вне hex, не UTF-8) делает файл неверным целиком: прежнее
              содержимое не используется; новые соединения, где revoked решает допуск, отвергаются — отказ закрыт (дверь
              хранилища P/01.3 Н1.6, дверь роли — класс role ниже, дверь воркера на домене P/03.7 Н1.6); где revoked решает только
              чтение X-W2C-Client (слушатель SIGNER_URL, signer ниже), заголовок не читается; строка лога и счёт неверных
              перечитываний (место счёта — урок двери); правильный файл снова читается без перезапуска — по содержимому,
              как всякое перечитывание revoked
  absent:     нет ни revoked, ни crl.pem (kit: «revoked | crl.pem») — как неверный файл: отказ закрыт; при crl.pem
              отсутствие revoked не ошибка — отзыв по crl.pem (решение «Архитектора» 2026-10-23 по вопросу «Спецификации»)
  crl:        crl.pem — PEM, один или два блока X509 CRL v2, по одному на центр из ca.pem и ca.next.pem; блок подписан
              своим центром алгоритмом закрытого списка sig; серийник листа сверяется с CRL его издателя — серийники
              уникальны только у издателя, лист другого центра с тем же серийником по этому CRL не отозван (догадка
              стадии C RC-05); нет блока центра — не ошибка, листы этого центра сверяются только с revoked; файл неверен,
              как bad_file (отказ закрыт новым соединениям, строка лога и счёт), только при дефекте формы (не PEM, не
              X509 CRL), подписи (издатель не из ca.pem и ca.next.pem, чужая подпись, подпись вне sig), лишнем блоке
              (второй блок того же центра), delta CRL, indirect CRL, области, ограниченной issuingDistributionPoint, и
              неизвестном критическом расширении; даты CRL отказа не дают: нет nextUpdate, now позже nextUpdate или
              thisUpdate позже now более чем на 60 с — строка лога и счёт, список действует (у revoked срока нет; отказ
              по дате закрыл бы все двери кластера); выпуск — P/02.4 Н1.6 ca crl (векторы common/vectors/crl; догадки
              стадии C RC-02, S03, RC-06 — оба генератора, решение «Архитектора» 2026-10-23 по справке «Спецификации»)
  both:       есть и revoked, и crl.pem — отозванные — объединение: лист отозван, если его серийник в revoked (глобально,
              по целому значению) или в CRL его издателя (crl); неверный любой из двух — отказ закрыт, как bad_file (догадки стадии C RC-01, RC-05, решение «Архитектора» 2026-10-23)
rotation:     ca.next.pem рядом — следующий центр, которому уже верят
```

`Entry.ca` — поле записи члена `domain/members`: `Platform/08-domain/data/members.form.yaml`, `Platform/08-domain/data/members.outcomes.tsv`; поля `tls_ca`, `tls_ca_certs` публикации `POST /api/member` — `Platform/08-domain/spec/08-domain.api.openapi.yaml`, `Platform/09-agent/spec/09-agent.api.openapi.yaml` (аудит раскладки, В-55, В-56; решение «Архитектора» 2026-10-25). ## Комплект кластера, роли домена, центр между кластерами

Из P/02.4 Н1.2 (`W2C_TLS_DIR`), P/02.4 Н1.6 `roles`, P/10 Н1.4 `roles` и P/08.3 Н1.6 (`fingerprint`, `tls_ca`,
`tls_ca_certs` — сторона члена, `Entry.ca` — форма) без изменения поведения: разбор ревью стадии A 8–10, № 15; разбор
ревью стадии B 8–10, № 4 (ADR-0083 доп. (15)) — урок P/09 берёт их из договора, не из норм 8.x и урока P/10 (шаг 13
порядка чтения). Владельцы текста остаются прежними и ссылаются сюда; сторона держателя (`form`, `on_accept`, строка
`ca-certs`, дверь `admin`) — [P/08.3 Н1.6](../../08-domain/spec/08.3-domain.norms.md).

```yaml
W2C_TLS_DIR:  корень комплектов kit (выше): Linux /etc/w2c/tls, macOS <W2C_BOX>/tls (ADR-0075; договор файла окружения «Переменные окружения»); пути kit —
              от него: <W2C_TLS_DIR>/ca.pem, ca.next.pem, revoked | crl.pem, <роль>/server.pem, <роль>/server.key
domain_roles: роли комплектов процессов домена: процесс domain — domain; консоль домена — domainconsole; агент и дверь
              ретранслятора (P/09.2: это агент) — domainagent; консоль кластера — console (P/02.4 Н1.6 roles; P/10 Н1.4 roles)
peer_role:    ожидаемая роль сервера — аргумент role функции peer (договор peer) у агента члена и ретранслятора: дверь
              держателя (процесс domain, класс signed ниже) — domain; дверь ретранслятора — domainagent. Это роль сервера, не
              роль клиента: клиенты из других кластеров (агент члена, ретранслятор) свой лист двери signed не
              предъявляют — слушатель SIGNER_URL держателя проверил бы его по своим центрам: alert, член молчит
              (signer, clients ниже; ADR-0083 доп. (20), доп. (21) п. 6)
fingerprint:  отпечаток центра — sha256 hex (64 знака, строчные) DER-сертификата центра
tls_ca:       поле публикации члена (договор приёма отчёта «Публикация члена»): [<отпечаток>…] по возрастанию, без повторов —
              ca.pem и ca.next.pem каталога W2C_TLS_DIR кластера (rotation выше); каталога или ca.pem нет — поля нет; каждый
              файл — ровно один сертификат центра (CA:true): файл есть, но не читается, блоков не один или не центр — поля
              нет (агент пишет причину в журнал; добавлено сверкой М11, D13); вне дельты (не входит в whole, поколения не
              порождает); идёт в каждой публикации
tls_ca_certs: поле публикации рядом с tls_ca: [<PEM>…] — сертификаты тех же центров в том же порядке; элемент — ровно
              один блок CERTIFICATE (как договор peer «Функция peer» шаг 2) с CA:true (лист под своим отпечатком — не центр;
              добавлено сверкой М11, D12), sha256(DER) элемента — отпечаток tls_ca на том же месте; есть только вместе с
              tls_ca; вне дельты; идёт в каждой публикации (решение «Архитектора» по cammeta-python М11-08 № 19). Форма
              публикации закрыта: держатель прежней сборки отчёт с полем отвергает — реализации переходят одновременно
Entry.ca:     поле записи члена в domain/members и в копии domain/member-list члена: [<отпечаток>…], 1–2, по возрастанию, без
              повторов; нет — отпечатков нет; пишет держатель (P/08.3 Н1.6 on_accept, admin); форма копии у члена —
              Platform/09-agent/data/member-list.form.yaml (исходы — `Platform/09-agent/data/member-list.outcomes.tsv`), member-list.outcomes.tsv (C04-DEP-OBS-HEARTBEAT-01)
```

## Клиент двери своего кластера

Решения «Архитектора» ADR-0075 доп. 2026-10-26 (2) п. 3, (3), (4), (5) — где расходятся, действует (5). Клиент двери своего кластера
проверяет сервер той же функцией `peer`, что клиент другого кластера: отдельного «набора своей коробки» нет; меняются
только аргументы — свои центры и `host` по порогу петли — и после `peer` идёт отзыв.

```yaml
own_client:   любой клиент двери своего кластера по https:// (ревью норм ADR-0075, Claude fd85ea8cc, С-1: перечень — примеры, не закрытый список);
              среди них — агент к своей консоли (P/09.1 Н1.5, Н1.10), скрипт воркеров к /metrics консоли (P/02.4 Н1.5),
              консоль кластера к консоли домена своей коробки — переход 2 по view.url (P/06.7 Н1.4) и в пересылке
              подписанту по SIGNER_URL (P/06.7 Н1.8), консоль домена к SIGNER_URL своей коробки (P/10 Н1.3 pass, роль
              domain) и к двери воркера на домене (P/03.7 door_client, роль <sub>domain), воркер и шлюз подсистемы к
              консоли своего кластера (P/06.7 Н1.2 door, роль console, URL — own_url ниже), клиент двери ресурса по
              RESOURCE_URL и url строки двери (договор клиента объектов, роль resource); к https:// каждый зовёт peer(chain, fingerprints, role, host, now) договора peer шагами
              1–9, затем отзыв по revoke выше: лист сервера отозван, файла отзыва нет или он неверен — отказ (закрыт)
              (доп. (5) п. 1)
  fingerprints: отпечатки (fingerprint выше) ca.pem и ca.next.pem каталога W2C_TLS_DIR (rotation); у скрипта воркеров
              комплекта роли нет — центр того же каталога (доп. (4) п. 2)
  role:       роль двери, к которой клиент звонит: console — консоль кластера, domainconsole — консоль домена (переход 2),
              domain — слушатель SIGNER_URL, <sub>domain — дверь воркера на домене, resource — дверь ресурса
  host:       хост URL; хост — литерал петли (loopback ниже) — SERVER_NAME своего w2c.env, подставленный до шага 1 peer;
              SNI — тот же host; соединение — с адресом URL, не с SERVER_NAME (доп. (2) п. 3, доп. (4) п. 2)
  outcomes:   исход — первый отказ peer по его шагам, затем отзыв; слова по топологии (туннель, проброс порта, localhost)
              договор не обещает: wrong_name — только когда шаги 1–7 прошли, а host нет в SAN DNS листа; IP-литерал вне
              петли у https:// — ip_address (шаг 1); localhost и запись v4 с ведущими нулями — имена, проверяются как имена
              (SERVER_NAME=localhost допустим и с листом localhost проходит); две коробки разных кластеров с одним именем
              сервера и взаимно доверенным центром клиент не различает — допустимо (ADR-0075 доп. 2026-10-26 (6) п. 1; ревью Codex
              a87ae5c00 R75D4-02, a377e0dd2 N75-01)
loopback:     порог петли — чистая функция {url} → loopback | name | ip над записью хоста URL, до DNS (доп. (3) п. 1, доп.
              (4) п. 1); запись хоста — подстрока URL после «//» и необязательного userinfo@ до «:порт», «/» или конца, как
              записана, без нормализации разборщиком URL (127.0.0.01, 0x7f.0.0.1, LOCALHOST, точка в конце — не
              переписываются; ревью норм ADR-0075, Claude fd85ea8cc, М-2): loopback — v4 из четырёх десятичных частей 0–255 без ведущих нулей с первой 127 или v6 (в
              скобках URL) со значением ::1 в любой записи без зоны; ip — иной IP-литерал шага 1 peer (в том числе v6 с
              зоной, ::ffff:127.0.0.1, 0.0.0.0, ::); name — иначе (localhost, 127.1, 127.0.0.01); векторы —
              common/vectors/loopback
  bad_url:    URL не по форме (нет схемы и «//», пустой хост): из окружения (SIGNER_URL, RESOURCE_URL, own_url над
              CONSOLE_HOST) — отказ старта процесса-клиента, код 2; из строки хранилища (view.url, url строки двери) — как
              поля нет, по исходам своей строки (ревью норм ADR-0075, Claude fd85ea8cc, М-3)
own_url:      URL клиента своей консоли (агент, скрипт воркеров, воркер и шлюз) — из CONSOLE_HOST и CONSOLE_PORT w2c.env
              (договор файла окружения «Переменные окружения»); порог петли — над https://<CONSOLE_HOST> (v6 — в скобках;
              в w2c.env CONSOLE_HOST пишется без скобок, со скобками — URL не по форме, bad_url) (ревью норм ADR-0075, Claude fd85ea8cc, М-4):
              литерал петли — https://<литерал>:<порт> ([::1] у v6); 0.0.0.0 — https://127.0.0.1:<порт>; :: —
              https://[::1]:<порт>; иной (IP вне петли или имя, в том числе localhost) — https://<SERVER_NAME>:<порт>;
              консоли домена в таблице нет — переход 2 берёт view.url (доп. (4) п. 3, доп. (5) п. 3)
  scheme:     https, если в W2C_TLS_DIR есть ca.pem, иначе — та же таблица со схемой http; консоль без комплекта при
              ca.pem на коробке — отказ соединения, видимый (доп. (5) п. 2)
```

## Серверная сторона: класс `signed`

Из М11/8 Н1.6 `server` (вводная) и `signed` без изменения поведения (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14)
п. 6; разбор ревью стадии A 8–10, № 21). Участники — процесс `domain` ([P/08.0](../../08-domain/spec/08.0-domain.norms.md)
Н1.6, P/08.0-02), ретранслятор ([P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.6, P/09.2-07) и консоль кластера — всё входящее из
других кластеров на её слушателе ([P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.7 `server`; ADR-0083 доп. (18), доп. (19) п. 2). Класс `role` — дверь консоли домена,
раздел «Серверная сторона: класс `role`» ниже (C10-SDK-ROLE83, решение «Архитектора» 2026-10-25).

```yaml
server:       серверная сторона дверей между кластерами — два класса (журнал cammeta-go, М11-08 № 5; решение «Архитектора»);
              сервер обоих классов предъявляет лист своей роли с EKU serverAuth (cert выше;
              разбор ревью стадии A 8–10, № 35) и центр, который этот лист выпустил: цепочка рукопожатия — лист, затем
              его центр из ca.pem или ca.next.pem своего кластера (kit: server.pem — лист, центр сервер добавляет сам);
              так же — каждая дверь процесса с комплектом роли, к которой ходит own_client (классы signed, role, mixed,
              дверь ресурса P/05 при mtls, консоль кластера и консоль домена для клиентов своего кластера) (ревью норм ADR-0075, Claude fd85ea8cc, С-2);
              без центра в chain[1:] клиент не найдёт якорь (договор peer шаг 3 — foreign_ca) (уточнение по вопросу
              «cammeta-acceptance» 2026-10-20; совпадает с cammeta-go):
  signed:     двери между кластерами, где личность — по норме маршрута (подпись, токен, пароль), а не сертификат
              клиента: сертификата клиента не требуют, прав он не даёт; первый стук незнакомца — только по подписи
              (договор подписи агента agent-signature.md; P/09.2 Н1.6). Класс делится по слушателю, не по маршруту
              (ADR-0083 доп. (20), доп. (21) п. 2):
  signer:     слушатель SIGNER_URL процесса domain держателя (юнит — P/02.4-13) — все его маршруты (сводная таблица
              P/08.0 Н2: POST /api/member/<член>, GET /api/carry/<член>, пакет ретранслятора — P/08.3; prepare, take,
              move — P/08.8; двери людей, которые передаёт консоль домена, — P/08.0 Н1.8); TLS с сертификатом сервера
              роли domain (P/10 Н1.4 roles); сертификат клиента запрашивает необязательно, предъявленный проверяет в
              рукопожатии закрытым набором: лист сходится к своим ca.pem или ca.next.pem, срок действует, нет
              extendedKeyUsage без clientAuth (слова класса role ниже, refusal); иначе — alert, HTTP нет; лист вне договора
              cert (keyUsage, размер ключа, строгие расширения) рукопожатие МОЖЕТ отказать; не предъявлен — рукопожатие
              ok. После рукопожатия роль из SAN, список sig и revoked решают только чтение X-W2C-Client (P/02.4 Н1.6
              client_cert; договор пересылки «Адрес клиента»), отказа HTTP здесь нет. Смену ca.pem, ca.next.pem,
              revoked видят новые соединения без перезапуска; сессий не возобновляет (билеты и PSK выключены) — как
              дверь роли (класс role ниже; ADR-0083 доп. (20), доп. (21) пп. 3–5); норма — поведение, не версия: TLS ≥ 1.2
              у обеих сторон, клиенты обязаны уметь 1.2; возобновления сессий нет — ни билетов, ни PSK, ни кеша id
              сессии; версия 1.3 — по возможности реализации при том же поведении (догадка стадии C RC-09, решение
              «Архитектора» 2026-10-23)
  unasked:    дверь и пакет ретранслятора (P/09.2 Н1.6) и консоль кластера — всё входящее из других кластеров на её
              слушателе (переход 1 договора пересылки, /domain/at/…, /api/prepare, /api/take, /api/held, /api/backup;
              P/06.7 Н1.7 server) — сертификата клиента не запрашивают (без запроса клиент листа не шлёт); консоль
              кластера — лист роли console, в рукопожатии по центру не отказывает, пропускает запрос норма двери;
              X-Operator: console — не признаёт; снимает всегда (решение «Архитектора» 2026-10-21, ADR-0083 доп. (18),
              доп. (19) п. 2; TLS № 14)
  clients:    клиенты из других кластеров — агент члена, ретранслятор — свой лист слушателю SIGNER_URL держателя не
              предъявляют (P/09.1 Н1.7, P/09.2 Н1.6, peer_role выше): лист своего центра получил бы alert; лист
              предъявляют клиенты своего кластера — консоль домена (domainconsole) и консоль кластера при пересылке
              подписанту своей коробки (ADR-0083 доп. (20), доп. (21) п. 6)
  stand:      проверяется чтением: TLS между кластерами на одной машине стенд не поднимает (P/02.4 Н1.10)
```

## Серверная сторона: класс `role`

Из [P/10 Н1.4](../../10-domain-console/spec/10-domain-console.norms.md) `server.role` (прежде М11/8 Н1.6) без изменения
поведения; P/10 и [договор `peer`](peer.md) — ссылкой сюда (C10-SDK-ROLE83, решение «Архитектора» 2026-10-25). Участник — консоль домена (дверь приёма
пересылки на переходе 2, урок-владелец двери — P/10); нормативный клиент — консоль кластера держателя
([P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.4 `holds`). Где P/10 молчал (набор доверия при нечитаемых
строках), — решение «Архитектора» 2026-10-25 (строка `unreadable`).

```yaml
role:         двери, где важна роль: приём консолью домена пересылки с X-Operator: console на переходе 2 (договор
              пересылки «Принять консолью»). Нормативный клиент двери — консоль кластера держателя (P/06.7 Н1.4 holds;
              её центр — свои ca.pem, ca.next.pem — в объединении всегда); прямого пути к двери от консоли члена нормы не
              открывают, объединение центров членов ниже — защита прямого соединения (так его пробует TLS-приёмка № 14);
              снятие центра члена снимает доверие TLS к нему, а не членство: пересылка члена с действующим токеном идёт
              по-прежнему (решение «Архитектора» 2026-10-21, ADR-0083 доп. (18), доп. (19) п. 2; разбор ревью ADR-0090,
              № 24, 27). Дверь запрашивает сертификат клиента и в рукопожатии доверяет объединению центров
              принятых членов: сертификаты строки domain/members/<член>/ca-certs, чей sha256 стоит в текущем Entry.ca
              этого члена (domain/members), и свои ca.pem, ca.next.pem кластера держателя (W2C_TLS_DIR); смена списка
              или строки — новые соединения видят новый набор; сертификат, не сходящийся ни к одному из них (центр
              чужой, цепочка или срок не те), — рукопожатие отказано (TLS alert), ответа HTTP нет; так же отказано листу
              клиента, у которого есть extendedKeyUsage без clientAuth (разбор ревью стадии A 8–10, № 35); член без
              Entry.ca (до отчёта с tls_ca) или только с отпечатками без сертификатов в объединение не входит. Сертификат сошёлся —
              шаги 6–7 функции peer (договор peer) над листом с role: console и проверка закрытого списка подписей sig выше у
              листа и центра (вне списка — 403 bad_chain; в рукопожатии не ограничивается; добавлено сверкой М11,
              cammeta-python М11-08 № 21), проверка имени (wrong_name) у сервера не делается;
              отказ — до сторожевой: сертификата клиента нет — 401 no_role; no_role, wrong_role, bad_chain — 403 с этим словом
              (P/10 Н4). Слова foreign_ca у двери роли нет: чужой центр отказан рукопожатием (ssl Python 3.12 проверяет
              сертификат клиента в рукопожатии без обратного вызова; два исхода разошлись бы у смешанных сборок).
              «Новые соединения» включают возобновлённые: дверь роли сессий не возобновляет — билеты сессий и PSK
              выключены, каждое соединение — полное рукопожатие с проверкой сертификата клиента по текущему объединению
              (иначе билет прошлой сессии пропустил бы центр, уже снятый из Entry.ca; решение «Архитектора»
              2026-10-19); двери класса signed без запроса сертификата (unasked класса signed выше) это не
              затрагивает; слушатель SIGNER_URL — так же: смену видят новые соединения, сессий не возобновляет
              (signer класса signed выше; ADR-0083 доп. (20), доп. (21) п. 5)
trust_set:    набор доверия двери роли — функция над прочитанным: свои ca.pem, ca.next.pem кластера держателя (W2C_TLS_DIR)
              ∪ сертификаты строки domain/members/<член>/ca-certs каждого члена, чей sha256 (fingerprint выше) стоит в
              текущем Entry.ca этого члена в domain/members; член без Entry.ca (до отчёта с tls_ca) или только с
              отпечатками без сертификатов — не входит; сертификат строки ca-certs, чьего отпечатка нет в Entry.ca, — не
              входит; повтор — один (копию domain/member-list консоль домена не читает — P/10 Н1 «Данные»)
unreadable:   domain/members нечитаема — в наборе только свои центры; строка ca-certs члена нечитаема или его Entry.ca не
              по форме — член не входит: доверия меньше — безопасно (C10-SDK-ROLE83, решение «Архитектора» 2026-10-25);
              журнал — по смене: строка при переходе входа в нечитаемый и при возврате, не на каждое рукопожатие
              (C10-ROLE-LOG-C47, решение «Архитектора» 2026-10-25)
refusal:      тело отказа — {error, detail?}, error — слово договора peer: no_role (сертификата клиента нет — 401; роли в SAN
              листа нет ровно одной — 403), wrong_role (роль не console — 403), bad_chain (подпись листа или центра вне
              sig — 403); до сторожевой; цепочка не по набору доверия — отказ рукопожатия, ответа HTTP нет (P/10 Н4;
              схема RoleRefusal OpenAPI урока P/10; ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 27)
stand:        проверяется чтением: TLS между кластерами на одной машине стенд не поднимает (P/02.4 Н1.10); набор
              доверия — векторы trust-set
```

## Серверная сторона: класс `mixed`

Дверь процесса подсистемы ([P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.7) служит процессам других подсистем и
странице в браузере, у которой листа нет: один слушатель, допуск — по маршруту `door.routes` манифеста ([P/02.1](../../02-installer/spec/02.1-installer.norms.md)
Н1.3) (ADR-0091 доп. (7), (8); решения «Архитектора» по повторному ревью 2026-10-23).

```yaml
mixed:        как signed целиком: TLS сервера роли процесса (cert, server выше), без возобновления сессий, TLS ≥ 1.2 (класс
              signer); сертификат клиента запрашивается необязательно — CertificateRequest несёт certificate_authorities:
              центры кластера (ca.pem, ca.next.pem), чтобы браузер без таких листов не спрашивал человека; предъявленный
              лист проверяется в рукопожатии, как у signer (сходится к центру, срок, нет EKU без clientAuth — иначе alert);
              sig, revoked и роль из SAN — после рукопожатия
  routes:     маршрут-имя или {name} без role и domain (W03-G08) — допуск token: токен двери (договор door-token), нет или неверен — 403 forbidden; маршрут
              {name, role} — допуск по сертификату роли: листа нет — 401 no_role, роль не из role — 403 wrong_role, подпись
              вне sig или серийник в revoked — 403 bad_chain (слова класса role выше, refusal); маршруты {name, domain} и
              {name, role, domain} — допуск по токену домена и по предъявленному: domain, role_domain ниже (ADR-0091 доп. (14))
  no_kit:     дверь без комплекта (только петля, P/03.4 Н1.7) маршрутов role не обслуживает: они закрыты — 401 no_role,
              при старте строка журнала; процесс и маршруты token и domain работают — на петле (ADR-0091 доп. (14) п. 3)
  kit_absent: «комплекта нет» — нет каталога W2C_TLS_DIR или в нём нет ca.pem; ca.pem есть, а лист или ключ роли
              (<роль>/server.pem, server.key) отсутствуют или неверны — частичный комплект: не переход на HTTP, отказ
              старта, код 2 — тихого понижения нет (догадка стадии C RC-NOKIT, решение «Архитектора» 2026-10-23)
# из P/03.4 Н1.7 door_admission domain, role_domain и cors — без изменения (аудит раскладки Б-20, решение «Архитектора» 2026-10-25; читают дверь процесса и domain)
  domain:     маршрут {name, domain: [<вид>…]} — токен домена в Authorization: Bearer; один вызов функции token договора
              токена домена с expect {kind: [<виды маршрута>], cluster: <свой кластер>, audience_claim: {<вид>: <поле
              аудитории из объявления вида, P/02.1 Н1.2б>}}; шаги 1–8 — прежние, истёкший или с чужой подписью — 401 раньше
              вида; вид не из списка — 403 wrong_kind, аудитория без своего кластера — 403 wrong_audience; нет заголовка
              или не Bearer — токена нет: 401 not_a_token; прочие слова шагов 1–8 — 401 со словом, no_revocations — 503
              (ADR-0091 доп. (14) п. 2, доп. (17) п. 3, доп. (18) п. 1, доп. (19) п. 1); утверждения прочитанного токена
              (ref и прочие) платформа передаёт обработчику подсистемы — их смысл сверяет подсистема; поле аудитории — по
              виду токена (договор токена домена «Проверка» шаг 10: отображение audience_claim по виду, совпавшему на шаге 9;
              W03-G10); нет принятого набора ключей domain/keys, своего члена (domain/member) или объявления вида у
              манифеста каталога — 503 {error: "unavailable", detail: accepted key set unreadable | own member unknown |
              kind declaration unreadable}, обработчик не вызывается (W03-G09, решение «Архитектора» 2026-10-25)
  role_domain: маршрут {name, role, domain} — по предъявленному (ADR-0091 доп. (18) п. 3, доп. (19) п. 3): лист в
              рукопожатии проверен и его роль — роль маршрута — допуск; лист другой роли: есть Bearer — исход domain,
              нет — 403 wrong_role; листа нет: есть Bearer — исход domain, нет — 401 no_role; отказ листа в рукопожатии (центр,
              срок, EKU — mixed выше) — alert, до выбора между листом и Bearer дело не доходит; лист нужной
              роли с sig вне списка или серийником в revoked — после рукопожатия 403 bad_chain, без перехода к Bearer
              (W03-ROLE-DOMAIN-CHAIN-01, решение «Архитектора» 2026-10-25); исход domain — правило domain выше, с его 503
  cors:       # страница консоли в браузере (P/03.4 Н1.7)
    origins:      разрешённые источники — CONSOLE_ORIGINS из w2c.env (договор файла окружения «Переменные окружения»): точные схема://хост[:порт], сравнение
                байт в байт; иной источник — без заголовков CORS
    preflight:    OPTIONS разрешённого источника отвечается до допуска маршрута (у preflight нет ни листа, ни токена)
    allow:        методы GET, HEAD, POST, PUT, DELETE; заголовки запроса Authorization, Range, Content-Type;
                Access-Control-Expose-Headers: Content-Range, Accept-Ranges, Content-Length, Location; Vary: Origin;
                Access-Control-Max-Age: 600 на preflight; куки нет (Access-Control-Allow-Credentials не ставится)
                (ADR-0091 доп. (16) п. 1, доп. (18) п. 5)
    every:        разрешённому источнику заголовки CORS ставятся на все ответы двери — успешные и отказы (400, 401, 403, 404,
                405, 409, 413, 503 и busy): иначе странице не прочесть отказ (ADR-0091 доп. (19) п. 4)
    no_rights:    CORS прав не даёт: допуск маршрута (token, role, domain) тот же; метод, которого маршрут не принимает, — 405;
                куки у двери нет, запрос со страницы без Authorization допуска не получает (ADR-0091 доп. (16) пп. 1–2)
```

## Соответствие прежним урокам

Из P/01.3 Н1.6 (стадия B; прежде М10/11 Н1.6, деление М10/11-11): блоки `cert`, `sig`, `kit`, `revoke`, `rotation`;
у P/01.3 остаются роли, которые допускает демон хранилища (`roles`), и проверка пира на `-raft` и `-api`.
Из М11/8 Н1.6 — строки `server` (вводная) и `signed` (здесь «Серверная сторона: класс `signed`»; решение «Архитектора»
2026-10-20, ADR-0083 доп. (14) п. 6); строка `stand` — в части класса `signed`; класс `role` — из P/10 Н1.4 `server.role` (здесь «Серверная сторона: класс `role`»; C10-SDK-ROLE83, решение «Архитектора» 2026-10-25).
Раздел «Комплект кластера, роли домена, центр между кластерами» — копии строк P/02.4 Н1.2 (`W2C_TLS_DIR`), P/02.4 Н1.6 и
P/10 Н1.4 `roles`, P/08.3 Н1.6 `fingerprint`, `tls_ca`, `tls_ca_certs`, `Entry.ca` (из М11/8 Н1.6) и строка `peer_role`
— прочтение М11/8 Н3 `peer(…, role, …)` для дверей держателя и ретранслятора (разбор ревью стадии A 8–10, № 15; разбор
ревью стадии B 8–10, № 4).
