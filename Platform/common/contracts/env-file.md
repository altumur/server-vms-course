# Договор файла окружения: грамматика `KEY=VALUE`

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): общий алгоритм нескольких процессов — договор, а не копии
в главах; догадка стадии C C04-ENV-01, решение «Архитектора» 2026-10-23). Владелец — глава
[P/02.4](../../02-installer/spec/02.4-installer.norms.md) установщика (Н1.2: переменные, файлы, порядок чтения). Участники —
все процессы, которые читают файлы окружения сами: раннер `w2c-run.sh` и процессы ролей (lifecycle уроков P/02, P/04, P/05,
P/06 и прочих: «разбором, не `source`»). Перенесено из P/02.4 Н1.2 вместе с краями B19 без изменения поведения; файлы и порядок чтения, переменные, `CLUSTERS` и
константы юнитов — разделы ниже (аудит раскладки, решение «Архитектора» 2026-10-25, А-07, А-09, А-16, А-17, Б-26).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Грамматика

Файлы окружения (`w2c.env`, `roles/*.env`, файл подсистемы, `configstore.env`) читаются разбором, не
`source`: строка `KEY=VALUE`, `KEY` — `[A-Za-z_][A-Za-z0-9_]*`; необязательный префикс `export `; значение в парных `"…"`
или `'…'` — без кавычек, подстановок нет; пустая строка и строка, чей первый непробельный знак `#`, пропускаются. Иная
строка — отказ запуска с кодом 2 и строкой лога, которая называет файл и номер строки.

На краях (сверка python и go М10/6–11, B19): строки разделяет LF; знак CR в строке, BOM в начале файла, пробел или табуляция до или после
`=` и в имени — строка не по грамматике; `export` — ровно одно слово и один пробел перед `KEY`, `export` без `KEY=` — не по
грамматике; значение без кавычек — всё после `=` до конца строки как есть, без обрезки пробелов, `#` внутри значения —
часть значения, не комментарий; пустое значение (`KEY=`) — пустая строка; непарная кавычка — не по грамматике.

Ещё на краях (догадка стадии C ENV-G01, решение «Архитектора» 2026-10-23): «пробельный» перед `#` комментария — только пробел и табуляция (U+00A0 и прочие — нет);
строка только из пробелов — не по грамматике; знак NUL в строке — не по грамматике; последняя строка без LF принимается;
повтор имени в одном файле — побеждает первое вхождение. Файл — строго UTF-8: строка с неверной последовательностью UTF-8 —
не по грамматике (код 2, строка лога называет файл и номер строки; догадка стадии C ENV-F01, решение «Архитектора»
2026-10-23).

## Файла нет

Для всех файлов окружения (файл роли, `w2c.env`, файл подсистемы, `configstore.env`; путь явный или по умолчанию): файла нет —
пропуск, не ошибка (как `W2C_SUB_ENV` [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н1.2); файл есть, но не читается
(права, ошибка ввода-вывода) — отказ запуска с кодом 2 и строкой лога, которая называет файл (догадка стадии C W03-G07, решение «Архитектора» 2026-10-23).

## Файлы и порядок чтения

Перенесено из [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н1.2 без изменения (аудит раскладки, решение «Архитектора» 2026-10-25, Б-26).

Порядок чтения раннера: значения юнита → файл роли `roles/<W2C_ROLE>.env` → `w2c.env` → файл подсистемы; раньше прочитанное побеждает. Юнит части (`w2c-run.sh part`, Н1.9) читает только значения юнита и файл подсистемы `W2C_SUB_ENV` (ADR-0091 доп. (3) п. 2). Каталог `roles/` лежит рядом с `w2c.env` (каталог файла `W2C_ENV`, по умолчанию `/etc/w2c/roles/`); другого места нет. `W2C_ROLE` юнита, который не совпадает с ролью команды раннера (`w2c-run.sh <команда>`, Н1.9), — отказ запуска с кодом 2 (сверка python и go М10/6–11, B20); у `w2c-run.sh worker <sub>` роль команды — `<sub>worker`, у `domainworker <sub>` — `<sub>domain`: одна программа в обеих ролях видит окружение одним правилом (ADR-0091 доп. (4), (5); решения «Архитектора» по повторному ревью 2026-10-23).

`W2C_ENV` и `W2C_SUB_ENV` берутся из окружения юнита один раз на проход чтения: тот же ключ в загружаемом файле не
применяется (перенаправления нет), строка журнала без значения, не отказ. `W2C_ROLE` юнита обязательна и равна роли
команды: нет или не равна — отказ старта, код 2 (ENV54-01/02, решение «Архитектора» 2026-10-25).


## Константы и юниты

Одно место значений, которые читают юнит установщика и процессы (аудит раскладки, решение «Архитектора» 2026-10-25, А-16, А-17); роль каждой — в уроке.

```yaml
FOR:              300   # с; подмена воркера дольше не подменяет: единицы уходят (роль — P/03.4 Н1.2)
HUNG_MOVE_AFTER:  900   # с; возраст наблюдаемой версии слота до предела hung/unsure/wait; переменная HUNG_MOVE_AFTER
                        # окружения контроллера, умолчание 900 (роль — P/04 Н1.4)
REACH_BUDGET:     10    # единиц за проход на переезды по достижимости; переменная REACH_BUDGET, умолчание 10 (P/04 Н1.4)
SHRINK_AFTER:     300   # с; без нехватки — сокращение (P/04 Н3 «сократить»); только у стенда — W2C_SHRINK_AFTER (таблица выше)
watchdog:         WatchdogSec юнита воркера — между FOR и HUNG_MOVE_AFTER: 360 (СЛЕДУЕТ; P/02.4 Н1.1); notify — из цикла,
                  не из подмены (P/03.3 Н1.2 watchdog)
```
