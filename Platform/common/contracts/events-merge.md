# Договор слияния журнала событий: живые ресурсы, слияние, эпохи, полнота

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): общий алгоритм нескольких процессов — договор, а не копии в
главах). Владелец — урок P/06, [глава 6.4](../../06-console/spec/06.4-console.norms.md) Н1.3, Н3 «слияние» (перенесено сюда без
изменения поведения консоли, ADR-0091 доп. (21) п. 1). Участники — консоль кластера (дверь `GET /events`, P/06.4 Н2) и воркер
подсистемы, который сливает журнал сам: читает `GET /events` ресурсов ([P/05](../../05-resource/spec/05-resource.norms.md) Н1.3,
допуск — раздел «Участник» `admission`) и строки эпох подсистем, объявленные в `worker.reads` (`<sub>/epoch/`;
[P/02.5](../../02-installer/spec/02.5-installer.norms.md) Н1.4); дверь консоли воркеру не открывается, её TLS, `open`/`shut` и
пределы не меняются (ADR-0091 доп. (21) п. 1, доп. (23) пп. 3–5, доп. (24) п. 4, доп. (25) п. 4, доп. (27) п. 2). Индекс —
P/05 Н1.3; форма строки и ответа — раздел «Форма», запрос и обрезка `cut` — «Запрос и ответ ресурса» ниже; подсказка `/events/wait` — у ресурсов (P/05 Н1.6), у консоли её нет.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Строка события и ответ ресурса на `GET /events` — схемы `EventRow`, `ResourceEventRow`, `ResourceEvents` контракта
`Platform/05-resource/spec/05-resource.api.openapi.yaml` ([OpenAPI урока P/05](../../05-resource/spec/05-resource.api.openapi.yaml));
ответ консоли — `ConsoleEvents` и `ConsoleEventRow` контракта `Platform/06-console/spec/06-console.api.openapi.yaml`
([OpenAPI урока P/06](../../06-console/spec/06-console.api.openapi.yaml)). Оба файла входят в чтение `common` (ADR-0083
доп. (33) п. 1; EM-READ-33-01). Строки эпох `<sub>/epoch/<id>` — семья `epoch`: `Platform/03-worker/data/epoch.form.yaml`,
`Platform/03-worker/data/epoch.outcomes.tsv`; строки дверей `platform/doors/<s>` (раздел «Живые ресурсы») — семья `doors`:
`Platform/05-resource/data/doors.form.yaml`, `Platform/05-resource/data/doors.outcomes.tsv` (аудит раскладки, В-18, В-19, Б-18;
решение «Архитектора» 2026-10-25).

## Запрос и ответ ресурса

Перенесено из P/05 Н1.3 (`query`, `cut`, `answer` и абзацы о `by`, копиях, `truncated`, `partial`) без изменения поведения: ресурс
исполняет их у себя, сливающий — над ответами (EM-READ-33-01). Грамматика параметров запроса и их отказы — дверь ресурса,
P/05 Н1.3 (ниже этого блока) и Н2; у двери консоли `from`, `to`, `limit` — грамматика читателя
[договора сторожевой и передачи](gate-and-pass.md) «Числовые параметры query» (C06-EVENTS-QUERY-LEXEME-162-01, решение «Архитектора» 2026-10-27).

```yaml
query:       from, to (секунды; умолчание 0..1e12), kind, subsystem, unit (<sub>/<id>; голый id — отказ), limit (1000; предел
             10000), keep (newest | oldest; умолчание newest), class (нет — оба класса), by (t | occurred; умолчание t; occurred
             читает на 3600 с дальше); limit ограничивает и каждый ресурс, и итог сливающего; сливающий спрашивает ресурсы тем же
             запросом
by:          by=occurred — строка без occurred использует t и при фильтре, и при сортировке
cut:         до обрезки дубли по id убрать; сначала alarm, затем observation; внутри класса по by (newest — убывание, oldest —
             возрастание), при равном времени id лексикографически по байтам UTF-8; первые limit строк
from_mirror: копии .mirror/<сервер>/ ресурс читает вместе со своим деревом: тот же бакет — дубль, отвечает под именем хозяина
             (поле server строки — хозяин); у сливающего копии бакетов silent-ресурса в ответах других дают state «; <s> from
             mirror» (раздел «Слияние» шаг 2)
truncated:   у ресурса — подходящие уникальные по id целые строки, не вошедшие в его локальный limit (число кандидатов после
             дедупликации минус число выданных); у сливающего — сумма truncated ответивших плюс кандидаты, не вошедшие в общий
             limit после дедупликации; копии, пропущенные разными источниками, могут учитываться несколько раз — это счётчик
             пропусков на стадиях, не число разных потерянных событий и не число пропусков у молчащих источников;
             дополнительного чтения скрытых строк для точного счёта нет
partial:     partial: true — хотя бы один бакет читался с порванной последней строкой (она не отдана и в truncated не
             считается); сливающий переносит partial от ответившего ресурса, если true
answer:      ресурс — {events, state, truncated, partial?, lines_garbled?}, state у ресурса всегда live; сливающий — раздел «Ответ»
```

## Участник

```yaml
participant:  консоль — читает строки эпох <sub>/epoch/* всех подсистем каталога (права консоли, P/02.5 Н1.4);
              воркер <s>worker — строки эпох подсистем, объявленных в его worker.reads (<sub>/epoch/), и только их
epochs_age:   строки эпох участник МОЖЕТ держать прочитанными с возрастом по договору наблюдения и не перечитывать на каждый
              опрос — для отбора; строку, которую он отдаёт как доказательство ограждения (epoch_is: fenced), он сверяет со
              свежим чтением эпохи (ADR-0091 доп. (23) п. 4, доп. (24) п. 4)
policy:       older_epochs манифеста подсистемы (P/06.4 Н1.2): fenced | earlier-run, умолчание fenced
admission:    дверь ресурса /events* допускает роли console, resource и <sub>worker манифестов каталога; ресурс с TLS проверяет
              клиента: цепочка до центра, серийник не в revoked (договор сертификата роли revoke), ровно одна роль из строки
              маршрута, CN = <роль>.<SAN DNS>; иначе отказ рукопожатия или 403 ResourceDenied с ролью и маршрутом; клиент
              сверяет роль resource и SAN DNS сервера с хостом адреса; IP при TLS — отказ клиента (перенесено из P/05 Н2
              «Допуск к дверям ресурса» для участника; аудит раскладки, решение «Архитектора» 2026-10-25, Б-18)
```

## Живые ресурсы

Живые ресурсы — строки дверей `platform/doors/<s>`, чья версия менялась в последние `LOST_AFTER` по часам участника
([договор наблюдения](observation.md) `fresh`; первый взгляд — как свежий); пульс ресурса слияние не читает: живость ресурса
здесь — только по строке двери (разбор ревью стадии B 6–7, № 35). Граница одна, `≤ LOST_AFTER` — вектор
[`fresh-age`](../vectors/fresh-age/README.md). Ресурс с несвежей строкой двери (`silent`) не спрашивается.

## Слияние

```
1. живых ресурсов спросить параллельно (8 полос, 3 с) тем же запросом (`query` выше); у консоли с фильтром видимости (грант
   вызывающего уже view на *, шаг 5а) — с limit = предел 10000, общий limit — после фильтра (C06-EVENTS-VIEW-33-01)
2. не ответил → incomplete[<сервер>] = did not answer; сказал не live → said <state>; несвежая строка двери → silent;
   у каждого из них state получает «; <s> unreachable»; копии бакетов silent-ресурса в ответах других ресурсов
   отдаются, и тогда state ещё «; <s> from mirror» (сверка python и go М10/6–11, E23)
3. строка ответа ресурса не по форме EventRow → пропустить, счесть в lines_garbled сливающего (P/05 Н1.3; E24);
   lines_garbled ответа — сумма lines_garbled ответивших плюс пропуски шага 3; partial: true, если у ответившего true
4. дубли по id → одна
5. эпохи (раздел «Эпохи» ниже): epoch_is и fenced у каждой строки
5а. фильтр видимости — только консоль (воркер сливает своё без фильтра): строку видит вызывающий, чей грант view охватывает её
   unit или единицу of (scope договора сторожевой: unit:<sub>/<id>; labels: — по меткам единицы of, если of есть, иначе unit);
   метки единицы — поле labels её строки <sub>/<unit.rows манифеста>/<id> ([договор проверки строки](row-check.md) «строка единицы»), объявленное в unit.fields списком (то же поле, что
   вход unit.labels функции may и метки размещения); поля не объявлено или в строке его нет — меток нет ([]); строка единицы
   нечитаема или её чтение не подтверждено — метки неизвестны: строки этой единицы видит грант на саму единицу (или на of) и
   на *, грант по меткам — нет; это не 503 двери — одна единица не роняет выдачу; вызывающему с грантом view по меткам такие
   единицы, чьи строки среди кандидатов поэтому скрыты, — в withheld ответа (без повторов, по возрастанию байтов; нет — поля
   нет); у гранта на единицу и на * withheld нет (C06-EVENTS-LABEL-SOURCE-138-07, решение «Архитектора» 2026-10-26);
   строку без единицы подсистемы и без of (журнал audit, метка консоли без of) — только view на *; невидимая строка выпадает
   до обрезки; complete и incomplete фильтр не меняет; «первая видимая» — в окне предела ресурса: видимых меньше limit и
   truncated > 0 — могут быть ещё (счётчик, как ниже), complete этим не меняется; при view на * фильтра нет, запрос — тот же
   (C06-EVENTS-VIEW-33-01, решение «Архитектора» 2026-10-25)
6. упорядочить по `cut` выше; оставить первые limit (у консоли — из видимых);
   truncated = сумма truncated ответивших ресурсов + число кандидатов (у консоли — видимых), не вошедших в общий limit;
   дедупликация, разметка эпох и фильтр видимости в этот счётчик не входят
7. с unit: запрос без ограждения, затем разметка по эпохам — строка прежней эпохи отдаётся с fenced: true, не выбрасывается
   (сверка python и go М10/6–11, E21)
```

**Гонки.** Источники и эпохи могут изменяться между чтениями: общего снимка нет. Счёт относится к наблюдённым ответам:
локальная обрезка может скрыть копии и строки, которые позже отсекаются по эпохе; результат не обещает глобальный top-k всех
файлов. Ответивший позже таймаута ресурс отмечается в `incomplete` этого ответа и может ответить на следующий; поздний ответ не
дописывается в уже отданное.

## Эпохи

```yaml
epoch_is:     current | fenced | earlier-run | unknown       # ставит сливающий — консоль или воркер; у ресурса строк с ним нет
read:         эпоха подсистемы строки прочитана: эпоха строки < current_epochs[единица] → политика (fenced | earlier-run),
              иначе current; строки эпохи единицы нет — current; fenced: true тогда и только тогда, когда epoch_is: fenced
unknown:      только у воркера и только для подсистемы, чьих строк эпох он не объявил в worker.reads: epoch_is: unknown,
              fenced: false — не доказательство; complete от этого не меняется (ADR-0091 доп. (24) п. 4, доп. (27) п. 2)
failed:       нужная эпоха (подсистемы, чьи строки пришли в ответах) не прочитана — хранилище не ответило или строка не
              читается: incomplete[<sub>/epoch] = did not answer, строки этой подсистемы — без поля epoch_is, fenced: false
              (не доказательство); правило одно у консоли и у воркера; у консоли unknown не бывает — она читает все эпохи
              (ADR-0091 доп. (25) п. 4, доп. (27) п. 2)
```

## Ответ

`{events, state, truncated, partial?, lines_garbled?, complete, incomplete, withheld?}`: `withheld` — только у консоли (шаг 5а); `events` — строки P/05 Н1.3 с `epoch_is` (кроме
`failed`) и `fenced`; `state` — `live[; <s> unreachable][; <s> from mirror]`; `incomplete` — `{<сервер> | <sub>/epoch: did not
answer | silent | said <state>}`; `complete` — `incomplete` пуст: это полнота ответивших источников и прочитанных эпох, а не
отсутствие обрезки по `limit`. У консоли это тело `GET /events` (схема `ConsoleEvents` OpenAPI урока 6); у воркера — его
собственный результат той же формы, `complete` воркера совпадает с консольным при тех же ответах и эпохах.

## Векторы

Пакет [`events-merge`](../vectors/events-merge/README.md): функция слияния без стенда — дубли, порядок `cut`, `truncated`,
`fenced`/`earlier-run`/`current`, неответ, `silent`, `said`, эпоха не прочитана, воркер с объявленной, необъявленной и не
прочитанной эпохой, `partial`, `lines_garbled` (ADR-0091 доп. (21) п. 3); фильтр видимости консоли — грант по меткам и
нечитаемая единица (`withheld`), грант на единицу и на `*`, метки по `of`, метки `[]` (C06-EVENTS-LABEL-SOURCE-138-07). Живость строки двери — пакет [`fresh-age`](../vectors/fresh-age/README.md) (граница `LOST_AFTER`, раздел «Живые ресурсы»);
`from mirror`, гонки и поздние ответы — чтением.

## Соответствие прежним урокам

Из P/06.4 Н1.3 `merge` и Н3 «слияние (консоль)» (прежде М10/8): алгоритм и абзац о свежести строки двери — целиком; у P/06.4 —
ссылка сюда. Новое: участник-воркер, `unknown`, сбой чтения эпохи (ADR-0091 доп. (20)–(27)).
