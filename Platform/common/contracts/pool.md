# Договор пула: живой воркер, пул, хранитель места, пригодность сервера

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13), доп. (30): общий алгоритм нескольких процессов — договор, а не
копии в главах; догадка стадии C C06-SERVER-POLICY-33-01, решение «Архитектора» 2026-10-25). Владелец — урок
[P/04](../../04-controller/spec/04-controller.norms.md) (Н3 «выбрать»: контроллер размещает единицы только на воркеры пула).
Участник — консоль кластера ([P/06.5](../../06-console/spec/06.5-console.norms.md) Н2: `WorkerRow.idle_by_policy`,
`ServerRow.placeable`, `why`): тот же расчёт по своим чтениям и своим часам.

Перенесено из P/04 Н3 «выбрать» (строки «живой воркер», «пул», «хранитель») без изменения поведения контроллера; для взгляда
консоли, о котором P/04 молчал, — четыре ответа «Архитектора» 2026-10-25 (разделы ниже, помечены). Что единица требует
сверх пула (`constraint`, `spread_by`, `affinity`, группа, дом, ёмкость и порядок) — по-прежнему P/04 Н3 «выбрать», строка
«пригодные» и ниже.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Строки и объекты, которые читает расчёт пула, — по формам и исходам их семей (аудит раскладки, В-42–В-44, Б-07; решение «Архитектора» 2026-10-25): пульс `<sub>/heartbeats/<имя>`
— `Platform/03-worker/data/heartbeats.form.yaml`, `Platform/03-worker/data/heartbeats.outcomes.tsv`; слот `<sub>/slots/<имя>` —
`Platform/03-worker/data/slots.form.yaml`, `Platform/03-worker/data/slots.outcomes.tsv`; назначение `<sub>/workers/<имя>` —
`Platform/04-controller/data/workers.form.yaml`, `Platform/04-controller/data/workers.outcomes.tsv`; строка заказа
`<sub>/want/<сервер>` — `Platform/04-controller/data/want.form.yaml`, `Platform/04-controller/data/want.outcomes.tsv`; решение
`<sub>/controller/placement_intent` — `Platform/04-controller/data/placement-intent.form.yaml`,
`Platform/04-controller/data/placement-intent.outcomes.tsv`; вывод `<sub>/decommissioned/<сервер>` —
`Platform/04-controller/data/decommissioned.form.yaml`, `Platform/04-controller/data/decommissioned.outcomes.tsv`; дренаж
`platform/drain` — `Platform/06-console/data/drain.form.yaml`, `Platform/06-console/data/drain.outcomes.tsv`; запрос вывода
`platform/decommission/<сервер>` — `Platform/06-console/data/decommission.form.yaml`,
`Platform/06-console/data/decommission.outcomes.tsv`.

## Живой воркер

```yaml
live:      пульс <sub>/heartbeats/<имя> читается и менялся в последние LOST_AFTER по часам читающего (договор наблюдения
           «Свежесть»; граница — вектор fresh-age) ∧ строка слота <sub>/slots/<имя> читается, released = false (не отдан и не в
           захвате taking — slots.form.yaml), holder непуст; пульс, чьё worker ≠ имени в ключе (heartbeats.form.yaml), не читается —
           воркера нет
```

## Пул

```yaml
pool:      живые воркеры
           − отданные слоты
           − воркеры дренируемого сервера (platform/drain, drain.form.yaml) и выведенных серверов (P/04 Н3 «вывести_сервер»)
           − при requires: resource — воркеры сервера, чей ресурс silent (resource_state договора наблюдения; unknown — не
             факт, воркер проходит)
           − retiring строк заказа <sub>/want/<сервер> (поле retiring, want.form.yaml; ADR-0084)
           − процессы роли с номером больше want своего сервера (имя и номер — договор имени слота «Имя процесса роли и его
             номер»; ADR-0084 доп. (4) Р28)
           − воркеры с нечитаемой строкой назначения <sub>/workers/<имя> (P/04 Н4 «пульс/слот/назначение не читается»;
             у консоли — так же, ответ (3))
           − при servers: distinct — все, кроме хранителя своего места (раздел ниже)
want_rule: retiring и «номер выше want» применяются только при grows: true и только к процессам сервера, чья строка заказа
           <sub>/want/<сервер> читается: grows: false — не применяются; строки заказа сервера нет — не применяются к его
           процессам; строка нечитаема — не применяются (скрипт сервера по ней не останавливает — P/02.4 Н1.5; контроллер —
           ошибка шага 9, P/04 Н4); retiring — только из читаемой строки (POOL-WANT-33-01, решение «Архитектора» 2026-10-25)
```

## Хранитель места при `distinct`

```yaml
place:     место воркера — по place_by (P/04 Н1.3): сервер или поле пульса; значение "" — места нет, общего места "" не
           бывает (ADR-0084 доп. (2) Р15)
keeper:    у каждого непустого места — один хранитель среди воркеров пула до вычитания distinct: наибольшая нагрузка, при
           равенстве — первый в слотовом порядке (договор имени слота); воркер без места не хранитель
load:      нагрузка — одно определение со «свободно» P/04 Н3: сумма весов уникальных id, назначенных воркеру (строка
           <sub>/workers/<имя>) или направленных к нему эффективным решением (резерв active intent, P/04 Н1.5); строки
           назначения нет — нагрузка 0; не число единиц (ответ (2))
weight:    вес id — поле placement.weight.field его строки единицы, целое ≥ 1 (P/04 Н1.3); поля нет — weight.default; у
           манифеста без placement.weight — 1; строки единицы нет, она нечитаема или поле не целое ≥ 1 — 0 (C06-POOL-FACTS-33-01,
           решение «Архитектора» 2026-10-25)
count:     счёт — число всех назначенных id (с резервом intent), читаемы их строки или нет
```

## `idle_by_policy` (ответ (1))

```yaml
idle_by_policy: true — при servers: distinct живой воркер пула до вычитания distinct, который не хранитель своего места,
           и живой воркер без места (""); иначе false — в том числе у воркера, который не живой, и всегда при shared
```

## Пригодность сервера: `placeable`, `why` (ответ (4))

```yaml
placeable: true — на сервере есть живой воркер пула (пул уже вычитает requires: resource при silent, дренаж и вывод
           сервера, отданные слоты, retiring, номер выше want, distinct); метки — свойство единицы и в placeable не входят;
           ёмкость не входит
why:       при placeable: false — «no eligible live worker»; при true — поля нет
```

## Векторы

Пакет [`pool`](../vectors/pool/README.md): вход — пульсы (кто живой), слоты, назначения, строки единиц, серверы (дренаж,
вывод, заказ), ресурсы, манифест; выход — пул, хранители, `idle_by_policy`, `placeable`/`why`, нагрузка и счёт. Живость пульса по истории — пакет
[`fresh-age`](../vectors/fresh-age/README.md) и [`resource-state`](../vectors/resource-state/README.md); `constraint`,
`spread_by`, `affinity`, порядок выбора — P/04, сценарии и чтение. Участник: пакет [`slot-name`](../vectors/slot-name/README.md)
(слотовый порядок — хранитель при равенстве нагрузки; В-44).

## Соответствие прежним урокам

Из P/04 Н3 «выбрать» (строки «живой воркер», «пул», «хранитель»), P/06.5 Н2 (строки `WorkerRow.idle_by_policy`,
`ServerRow.placeable`, `why`); у них — ссылки сюда. Ответы «Архитектора» 2026-10-25 (C06-SERVER-POLICY-33-01): (1) `idle_by_policy`
— среди живых пула, место `""` не место; (2) нагрузка хранителя — одно определение со «свободно»; (3) нечитаемое назначение — вне
пула и у консоли; (4) `placeable` — живой воркер пула, без меток и ёмкости. Свидетель курса в (1), (2), (4) расходился с нормой
(все пульсы, число единиц, проверка только сервера) — норма здесь, свидетель не образец.
