# Договор размещения файлов секретов

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): одно правило нескольких процессов — договор, а не копии
в главах; догадки стадии C S-005, DF-G01, решение «Архитектора» 2026-10-23). Владелец — урок
[P/02](../../02-installer/spec/02.4-installer.norms.md), глава 2.4 (раскладка Н1.1, команды `w2cctl secrets` Н1.9 и «установка
домена» Н3 — оба файла кладёт установщик; ADR-0083 доп. (29) п. 9: строка называет урок-владельца нормы; библиотеку по договору пишет сессия `common` генерации). Одно правило размещения для всех файлов
секретов на коробке: файл кольца ([договор запечатывания](sealing.md) «Файл кольца» `mode`, `link`) и файл восстановления
домена ([договор основания домена](domain-founding.md) «Корень и файл восстановления» `place`, `mode`). Где каждому файлу
быть и какой у него режим — в договоре этого файла; здесь — как читающий и пишущий проверяют размещение.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

```yaml
file:      файл секрета — обычный файл; сам файл — символьная ссылка или специальный файл (каталог, сокет, устройство,
           FIFO): отказ, файл не читается и не пишется
dirs:      символьные ссылки в каталогах пути разрешаются до проверки размещения: правило «вне каталога …» и «НЕ внутри …»
           договора файла сравнивает разрешённый путь с разрешёнными путями запретных каталогов
refuse:    каталог пути, который не разрешается (нет, нет доступа, цикл ссылок), или разрешённый путь в запретном каталоге —
           отказ, ничего не читается и не меняется
mode:      режим и владелец — договор файла; проверяются по самому файлу при каждом чтении, где договор файла так велит
forbidden: полный перечень запретных каталогов («вне …», «НЕ внутри …» договора файла) задаёт вызывающая установка —
           команда, что читает или пишет файл, называет их разрешёнными путями своей раскладки (PLATFORM_DIR, каталоги
           хранилища, объектов и их копий); перечень пуст или запретный каталог не разрешается — отказ без чтения и без
           изменения цели; раскладка считается неизменной на время одной операции (догадка стадии C SF-G01/G02, решение «Архитектора» 2026-10-23)
write:     запись публикуется целиком — временный файл в том же каталоге, затем rename; существующая цель проверяется
           правилами file и refuse до записи; «создать однажды» (файл восстановления, ключ кольца new) существующую цель не
           заменяет — отказ; новая версия файла создаётся сразу с режимом договора файла (кольцо 0640, файл восстановления
           0600), а не меняет режим после записи (догадка стадии C SF-G01/G02, решение «Архитектора» 2026-10-23)
  once:    «создать однажды» — атомарное переименование без замены (renameat2 RENAME_NOREPLACE на Linux, renamex_np
           RENAME_EXCL на macOS); ОС, ядро или ФС его не поддерживают — отказ без изменения цели, временный файл удаляется;
           обходов через обычный rename или link нет (догадка стадии C SF-G04, решение «Архитектора» 2026-10-23)
  temp:    временный файл создаётся сразу с режимом договора файла (0640/0600); владелец и umask исправляются до записи
           секретных байтов; после записи права не расширяются (SF-G04)
```
