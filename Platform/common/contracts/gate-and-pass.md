# Договор сторожевой и передачи: кто звонит консоли, `/session`, передача `door.pass` воркеру

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): контракт, который исполняют несколько
процессов, лежит в `Platform/common/`; разбор ревью стадии A 8–10, № 14 / решение 3). Владелец — урок
[P/06](../../06-console/spec/06.3-console.norms.md) (главы 6.3 — сторожевая и сессия, 6.5 — `door.pass`): консоль кластера
спрашивает личность и грант у каждой двери и передаёт маршруты `door.pass` воркеру. Участник — урок P/10, консоль домена
(до переноса — [М11/8](../../../М11_Domain/spec/08-doors-between-clusters.norms.md) Н1.7, Н1.8, [М11/9](../../../М11_Domain/spec/09-people-grants-names.norms.md)
Н1.5): та же сторожевая перед дверями `/domain/*` и та же передача маршрутов `door.pass` воркеру на домене.

| Что | Консоль кластера (P/06) | Консоль домена (P/10) |
|---|---|---|
| сторожевая (раздел «Сторожевая») | целиком; гранты — копия `domain/grants` этого кластера (М11/9 Н1.5 `cluster`) | `gate`, `identity`, `x_user`, `caps`, `scope`, `csrf`, `body`, `refusal`; гранты — `domain/grants/domain`, `need` — М11/9 Н1.5 `domain`, `body_unit` |
| `/session`, `/healthz` (раздел «Сторожевая» `session`) | да | да (М11/8 Н1.8 `session`; `grants` — М11/9 Н1.5 `session`) |
| следы домена, «петля — operator» | [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.8 (поздний слой) | P/06.3 Н1.8 (10 lifecycle «Открыто») |
| передача `door.pass` (раздел «Передача») | живому воркеру подсистемы с дверью ([P/06.5](../../06-console/spec/06.5-console.norms.md) Н1.8 «Живой воркер с дверью») | воркеру на домене этой подсистемы по его пульсу (М11/8 Н1.7 `route`, `address`, `absent`) |
| пересылка `/domain/*` в другой процесс | договор пересылки | договор пересылки |

Перенесено из P/06.3 Н1.3 (блок `gate`, `open_routes`, `session` целиком) и P/06.5 Н1.8 (блок `spec`, `rule`, `codes`) без
изменения поведения; в главах-источниках — указатели. Что значат гранты и вход людей домена — урок P/08 (до переноса —
М11/9); разбор запроса консоли и порядок проверок на запросе — [P/06.5](../../06-console/spec/06.5-console.norms.md) Н2, Н3
«запрос → ответ (консоль)»; ключи `rights:` спеки — P/06.3 Н1.5; отказы сторожевой — P/06.3 Н4; отказы передачи — P/06.5 Н4.
Ссылки «Н1.x» в перенесённом тексте — главы-источника (Н1.5, Н1.8 — P/06.3; Н4 — P/06.5); «глава 6.K» — глава урока P/06.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Сторожевая

Из P/06.3 Н1.3:

```yaml
gate:
  on:       в хранилище есть domain/keys → каждая дверь, кроме открытых, спрашивает личность и грант
  open:     ключей нет и следов домена нет → консоль открыта: только с петли (иначе 403), имя — operator
  shut:     ключи были или след домена есть, а проверить нечем / хранилище не ответило → 503, не открыта
            # «ключи есть» и «след домена» — Н1.8 ниже (поздний слой)
  identity: # по порядку
    1. кука аварийного входа w2c_glass (сессия в памяти, 15 мин)
    2. X-Agent-Signature — агент домена: только двери единиц и GET /events?class=alarm (фронт и страница тревог — М11/11 Н1.7; форма и окно UNIT_WINDOW 60 с — договор подписи агента common/contracts/agent-signature.md; разбор ревью стадии A 8–10, № 13)
    3. Authorization: Bearer <токен> | кука w2c_token → домен: {user, until, grants} (токен — договор токена домена «Проверка», владелец М11/2 — разбор ревью стадии B 3–5, В1; гранты и may — М11/9 Н1.4–Н1.5)
    4. отладочная личность (ADR-0050): задан W2C_DEBUG_PERSON=<имя>, запрос без токена и без куки, адрес TCP-соединения
       127.0.0.1 или ::1 (заголовки адреса не читаются) → этот человек со своими grants из domain/grants; человека нет
       или он выключен — как без входа; с другого адреса — как без переменной; доверенный прокси на петле и заданная
       переменная → процесс не стартует; видно: /session отдаёт debug: true, при старте тревога session.debug_open,
       каждая правка — в журнал с debug: true
    5. иначе 401
  x_user:   заголовок X-User стирается всегда; вписывается доказанное имя
  caps:     view < edit < admin
  need:     # что требует дверь; решается по пути ДО чтения тела
    GET/HEAD                         → view (на единицу из пути или ?unit=; без единицы — любой грант)
    /marks, POST /{sub}/requests     → edit на единицу тела
    DELETE /{sub}/asked/*            → admin на *
    метки сервера, вывод, policy, drain, schema PUT → admin на *
    POST /domain/move                → admin на * (аварийный перенос домена сюда, М11/10 Н1.8)
    строки единиц: POST → admin на * | по rights.routes view/edit на единицу about | cluster_rows → *
                   PUT/DELETE        → admin на единицу | по rights.routes
    таблицы                          → по rights.routes (view | edit | admin)
    по телу — rights.unit_of, reach, names добавляют единицы (Н1.5); у сторожевой домена до тела — предпроверка
    unit = "*" (М11/9 Н1.5 body_unit), эти проверки после тела сохраняются (добавлено сверкой М11)
  scope:    грант на * | unit:<sub>/<id> | labels:<…>; грант на единицу или на её about-единицу
  csrf:     действующий запрос по куке с чужим Origin → 403
  body:     предел тела (≥ 1 MiB; blob PUT /<rows>/<id>/<blob_field> — 32 МиБ, потолки главы 6.1 Н1.4); chunked → 400; медленно → 408; больше → 413
            (ответ раннего отказа — P/01.1 Н2.1)
  refusal:  {detail, error: denied}; 403 → журнал access.denied
open_routes: [/, /index.html, /platform/console.js, /platform/console.css, /metrics, /healthz, /session, /session/break-glass,
              /api/held, /api/backup, /api/prepare, /api/take, /api/login]   # /api/login — вход людей через консоль (М11/9 Н1.2)
session:
  GET  /session  → открыта: {open: true, login_url}; закрыта анонимному: {open: false, login_url};
                   доказанной личности: {open: false, login_url, user, until, via, grants: [{cap, scope}], debug?}
  POST /session {token} → {user, until} + кука w2c_token (HttpOnly, SameSite=Strict, Secure за https)
  DELETE /session → {out: true}; POST /session/break-glass {who, why, password} → {user, until} + кука w2c_glass; 429 по пределу
  login_url: дверь домена /api/login (М11/9 Н1.2) — консоль пересылает её домену (open_routes, М11/8 таблица пересылки);
             консоль токенов людей не выдаёт; значение — LOGIN_URL окружения (P/02.4 Н1.2), не задано — "/api/login"
             (строка, не null, и у открытой консоли)
  via:       шаг identity, которым доказана личность этой сессии: break-glass — кука аварийного входа (п. 1; grants — [],
             право — по аварийной сессии, М11/9 Н1.5 session); token — токен домена заголовком Authorization или кукой
             w2c_token (п. 3); debug — отладочная личность (п. 4, вместе с debug: true); подпись агента (п. 2) сессии не
             даёт (разбор ревью стадии A 6–7, № 6: слово и его значения — здесь, по сверке со свидетелями при переносе;
             пустое `via` у токена — расхождение, правка поведения)
```

## Передача `door.pass`

Из P/06.5 Н1.8; грамматика `door.pass` в спеке — [P/02.1](../../02-installer/spec/02.1-installer.norms.md):

```yaml
spec:     door: {routes: […], pass: [<сегмент>…]}   # сегменты не повторяют routes, rows и where (P/02.1)
rule:     маршрут консоли, чей первый сегмент в pass, передаётся живому воркеру подсистемы с дверью (наименьшее имя):
          метод, путь, query, тело ≤ 1 МиБ, заголовки Authorization, Content-Type, Idempotency-Key, X-Operator;
          сторожевая консоли проверяет своё раньше; воркер проверяет учётные данные снова; ответ как есть (статус, Content-Type,
          тело ≤ 4 МиБ); клиент к воркеру — с сертификатом роли, если есть
codes:    503 «this console passes no route on to a worker» (клиента нет) | 503 «no worker of <sub> with a door is heard»
          | 400 тело не прочитано | 408 тело читается медленно | 413 тело больше предела (Н4) | 502 «<worker> did not answer»
```

Какой воркер получает маршрут — у стороны (таблица выше). Консоль домена передаёт путь `/<сегмент>[/…]` и query клиентом
роли `domainconsole`; воркера на домене не слышно — 503 со словами строки `codes` (М11/8 Н1.7).
