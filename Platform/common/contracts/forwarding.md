# Договор пересылки: заголовки между процессами, пересылка одной функцией, отказы по переходам

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13); разбор ревью стадии A 8–10, № 23, № 14 /
решение 3). Путь двери людей домена проходит до трёх процессов: консоль кластера (пересылка, глава 6.7 позднего слоя урока
P/06), консоль домена (приём пересылки и передача процессу, урок P/10), процесс `domain` (исполнение, урок P/08). Переходы —
одна нумерация во всех нормах (ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 20): **переход 1** — консоль кластера
члена, не держащего домен, → консоль кластера держателя (`CLUSTERS`, `X-W2C-Via`); **переход 2** — консоль кластера
держателя → консоль домена своей коробки (`holds`, `view.url`); **переход 3** — консоль домена → процесс `domain`. Запрос к
консоли кластера держателя начинается с перехода 2. Коды по сторонам — раздел «Отказы по переходам». Владелец — урок P/06, [глава 6.7](../../06-console/spec/06.7-console.norms.md)
(Н1.4, Н1.5, Н3 «принять консолью» — указатели сюда): пересылка — функция консоли кластера. Участники — консоль домена (P/10: приём
пересылки, передача процессу — [нормы урока P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.3 `pass`, Н1.4) и
процесс `domain` (P/08: приём и ответы — [P/08.0](../../08-domain/spec/08.0-domain.norms.md) Н1.8 `pass`, `answers`; чтение
`X-W2C-Client` — P/08.0 Н1.8; предел по адресу — [P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н1.10 `address`).

Перенесено из М11/8 Н1.3 (строка `via`), Н1.4 (блок целиком), Н3 «принять консолью» и М11/9 Н1.10 (строка `header`) без
изменения поведения; раздел «Отказы по переходам» — решение «Архитектора» 2026-10-20 (решение 3: каждый OpenAPI несёт
только свои коды), коды в нём — из норм переходов, новых нет. Таблица пересылки — раздел «Двери домена» ниже; адрес (`holds`, `to`, `view.url`,
`CLUSTERS`), `where` члена и пересылка подписанту — нормы владельца (P/06.7 Н1.4, Н1.6, Н1.8); TLS между кластерами —
P/06.7 Н1.7, `peer` — [договор `peer`](peer.md); сторожевая — [договор сторожевой и передачи](gate-and-pass.md). Ссылки в перенесённом тексте: «Н1.x»,
«Н3» — урока М11/8 (у строки `header` — М11/9); «урок N» — урок М11/N. Их адреса теперь (стадия B, урок 10): М11/8 Н1.2 —
«Двери домена» ниже, Н1.3 — P/06.7 Н1.4, Н1.4 — «Пересылка — одна функция» ниже, Н1.5 — P/06.7 Н1.6, Н1.6 — P/06.7 Н1.7 (`server.role` — P/10 Н1.4), Н1.7 — P/10 Н1.6, Н1.9 —
P/06.7 Н1.8; «урок 9 Н1.5» — P/06.7 Н1.9; «урок 2 Н1.8» — P/06.3 Н1.8; «урок 3 Н1.8 pass» — P/10 Н1.3; «урок 10» (сроки
переноса) — P/08.8 Н1.7, Н1.8.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Файлы, по которым работает договор (аудит раскладки, В-20–В-22; решение «Архитектора» 2026-10-25):

- вид домена `domain/view` (`holds`, `view.url` перехода 2; 503 `domain console not known`) — семья `view`:
  `Platform/08-domain/data/view.schema.json`, `Platform/08-domain/data/view.outcomes.tsv`;
- копия списка членов `domain/member-list` (503 `the list of members does not read`; `Entry.ca` назначения для `tls`) —
  семья `member-list`: `Platform/09-agent/data/member-list.schema.json`, `Platform/09-agent/data/member-list.outcomes.tsv`;
- тело отказа сторожевой `Denied` (401/403 на переходах 1 и 2) — `Platform/common/contracts/gate-and-pass.api.openapi.yaml`.

## Заголовки между процессами

| Заголовок | Ставит | Читает | Раздел |
|---|---|---|---|
| `X-W2C-Via: <CLUSTER>` | консоль кластера при пересылке в консоль другого кластера (переход 1) | принимающая консоль кластера: пришёл — в другой кластер не пересылает (400 `one hop`) | «Один переход» |
| `X-Operator: console` | консоль кластера при каждой пересылке — переход 1 и переход 2 (ADR-0083 доп. (19) п. 2, № 20) | консоль домена на переходе 2 — только у соединения с доказанной ролью `console` (дверь роли, P/10 Н1.4 `server.role`); консоль кластера на переходе 1 — не признаёт; снимает всегда (класс `signed`, P/06.7 Н1.7 `server`; ADR-0083 доп. (18)) | «Пересылка», «Принять консолью» |
| `X-W2C-Client: <адрес>` | консоль домена при передаче процессу `domain` (переход 3) | процесс `domain` — только на соединении роли `domainconsole` | «Адрес клиента» |
| `X-User` | никто: пришедший снимается всегда | — | [договор сторожевой и передачи](gate-and-pass.md) `x_user` |

### Один переход

Из М11/8 Н1.3:

```yaml
via:          X-W2C-Via: <CLUSTER> ставит каждая пересылка в консоль другого кластера; «пришёл X-W2C-Via» — заголовок
              есть, в том числе пустой (добавлено сверкой М11, D7); консоль, получившая X-W2C-Via,
              в консоль другого кластера не пересылает (400 one hop); в консоль домена своей коробки (holds) — пересылает
```

### Пересылка — одна функция

Из М11/8 Н1.4:

```yaml
request:      метод, путь и query как пришли; сегменты пути раскодируются один раз, %2F уровня маршрута не создаёт, принятые
              закодированные путь и query передаются как пришли (догадка стадии C FW-G03, решение «Архитектора» 2026-10-23); тело ≤ предела тела консоли ([договор сторожевой и передачи](gate-and-pass.md) «Сторожевая» `body`, 1 МиБ): больше — 413, chunked —
              400, медленно — 408 (P/06.5 Н4); тело никогда не обрезается
pass:         Authorization, Content-Type, Idempotency-Key — как пришли
set:          X-Operator: console — на каждой пересылке: переход 1 и переход 2 (ADR-0083 доп. (19) п. 2; разбор ревью
              ADR-0090, № 20); X-W2C-Via: <CLUSTER> — только к консоли другого кластера (переход 1, Н1.3)
never:        прочие пришедшие заголовки; пришедшие X-User, X-Operator, X-W2C-Via дальше не идут никогда
x_operator:   принимающая консоль признаёт X-Operator: console (значение байт в байт: `Console` — не оно; добавлено
              сверкой М11, D16) только у соединения с доказанной ролью console (сертификат роли P/02.4 Н1.6, Н1.6 ниже).
              Такое соединение бывает только у двери роли консоли домена на переходе 2 (соединение без роли там отказано
              раньше — договор сертификата роли «Серверная сторона: класс `role`»). Консоль кластера на переходе 1 и у всего входящего из других кластеров — не
              признаёт; снимает всегда (класс signed, P/06.7 Н1.7 server; решение «Архитектора» 2026-10-21, ADR-0083
              доп. (18), доп. (19) п. 2; разбор ревью ADR-0090, № 21, 27). Непризнанный X-Operator снимается до
              сторожевой, как любой пришедший X-Operator и X-User (ADR-0075 п. 3); признанный прав не даёт — сторожевая
              решает по Authorization (урок 9), он называет в журнале принимающей, что запрос переслан консолью: строки
              audit/domainconsole о таком запросе несут общее поле role: "console" (договор журнала событий,
              door_journal); без признанного заголовка поля нет; нового вида и поля нет (C10-XOPERATOR-JOURNAL-01)
answer:       статус, Content-Type, X-Unreachable и тело как пришли, без разбора и обёртки (ADR-0061 доп. п. 6);
              тело больше FORWARD_MAX — 502 answer too large, из тела не уходит ничего; нет ответа за FORWARD_WAIT или
              сеть — 502 did not answer (и отказ рукопожатия сервером, TLS alert двери роли Н1.6 на переходе 2 — рукопожатие не
              состоялось: сеть, без слова peer); ответ оборвался — 502 answer broke off
FORWARD_MAX:  1 МиБ
FORWARD_WAIT: столбец «Ожидание» строки таблицы Н1.2 (умолчание 5 с); двери переноса — свои сроки: пересылка подписанту своей
              коробки — 10 с у /api/prepare, 90 с у /api/take и /domain/move (P/06.7 Н1.8 order шаг 5; P/08.8 Н1.7, Н1.8);
              /domain/handover — 100 с (таблица ниже), больше 90 с ответа процесса domain (P/08.8 Н1.7 door) (аудит раскладки Б-19, решение «Архитектора» 2026-10-25)
gate:         сторожевая пересылающей консоли спрашивает только, кто звонит (любой грант этого кластера, урок 9 Н1.5; петля
              operator — договор сторожевой и передачи «Сторожевая» `open`), и не спрашивает у открытых строк таблицы (Личность «—»); что можно, решает сторожевая
              консоли домена или члена
tls:          к https:// — клиент роли console (P/02.4 Н1.6) с проверкой сервера peer (Н1.6) по члену назначения:
              консоль кластера держателя — держатель, консоль члена — имя из CLUSTERS (переход 1: host — из URL); консоль
              домена своей коробки (переход 2, view.url) — клиент своего кластера договора сертификата роли own_client:
              peer с отпечатками своих ca.pem и ca.next.pem, роль domainconsole, host — SERVER_NAME, если хост view.url —
              литерал петли, затем отзыв (ADR-0075 доп. 2026-10-26 (5) пп. 1, 3)
journal:      domain.forwarded {cluster, path, user, status} у пересылающей: cluster — куда, path — пришедший путь,
              user — имя, доказанное сторожевой (до урока 9 — operator), не X-User; status — код ответа или отказа (отказ рукопожатия
              двери роли — 502, как сеть)
```

### Принять консолью

Из М11/8 Н3 «принять консолью (любая консоль, до сторожевой)»:

```
1. X-User — снять ([договор сторожевой и передачи](gate-and-pass.md) «Сторожевая» `x_user`)
2. X-Operator: console (байт в байт) и соединение с доказанной ролью console — оставить для журнала; иначе снять
   (консоль домена на переходе 2 — дверь роли, договор сертификата роли «Серверная сторона: класс `role`»; консоль кластера на переходе 1 — не признаёт;
   снимает всегда: класс signed, P/06.7 Н1.7 server; ADR-0083 доп. (18), доп. (19) п. 2)
```

### Адрес клиента

Из М11/9 Н1.10 `address` (строка `header`; что процесс считает по адресу — предел попыток входа, [P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н1.10):

```yaml
  header:  X-W2C-Client: <адрес TCP-пира клиента> — ставит консоль домена при передаче процессу domain; процесс верит ему
           только на соединении роли domainconsole (P/02.4 Н1.6), на прочих — не читает; роль доказывает сертификат
           клиента: слушатель процесса domain (SIGNER_URL) под TLS запрашивает его необязательно и предъявленный
           проверяет в рукопожатии по своим ca.pem, ca.next.pem кластера — чужой центр, срок, EKU без clientAuth —
           alert (P/02.4 Н1.6 client_cert; договор сертификата роли signer); агенты и ретрансляторы других кластеров
           его не предъявляют (договор сертификата роли clients); рукопожатие прошло, роль из SAN — domainconsole,
           подписи в списке sig, серийник не в revoked → заголовок читается; иначе (нет сертификата, иная роль, подпись
           вне sig, отозван, HTTP стенда) — не читается, предел считает адрес TCP-пира (ADR-0083 доп. (20), доп. (21) п. 4); на стенде без TLS заголовок не доверяется никогда — долг стенда, не нормы (добавлено
           сверкой М11, cammeta-python М11-09 № 22); пришедший снаружи X-W2C-Client
           консоль снимает, как X-User (урок 3 Н1.8 pass; решение «Архитектора» по сверке М11, P16)
```

владелец — этот договор (P/06), участники — процесс `domain` (глава [P/08.0](../../08-domain/spec/08.0-domain.norms.md)) и
консоль домена ([урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н2); глава 6.7 и Н2 урока P/10 — ссылкой. «урок N» в таблице — урок М11/N.

Строка с `GET` покрывает и `HEAD` того же пути: пересылается как `HEAD`, ответ — тот же код и заголовки без тела ([P/06.5](../../06-console/spec/06.5-console.norms.md) Н2;
прогон 41). То же у `/domain/at/…` (М11/8 Н1.5): `HEAD` — как `GET` формы `where`, без тела (добавлено сверкой М11, D2).

Путь с сегментом `.` или `..`, в том числе в процент-форме (`%2e`, `%2E`, `.%2e`, `%2e%2e` и подобные), — 404 `not a domain
route` до сторожевой, до пересылки и до передачи воркеру на домене (Н1.7); сегменты не нормализуются (добавлено сверкой
М11, D4: путь `/domain/<sub>/<сегмент>/../members` иначе ушёл бы мимо таблицы).

Сопоставление по порядку: `books` (своя: дверь книги `GET /domain/<sub>/books/<книга>`, [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.1; аудит раскладки Б-19, решение «Архитектора» 2026-10-25), `at` (своя), строки таблицы сверху вниз; `<sub>` — подсистема каталога
этой консоли; сегмент `door.pass`, совпавший с `books`, `placement`, `members`, `topology`, `shadow`, `at`, на домене не
передаётся.

## Отказы по переходам

Решение «Архитектора» 2026-10-20 (разбор ревью стадии A 8–10, решение 3): ответ дальнего перехода ближний отдаёт как
пришёл (Н1.4 `answer`; [P/08.0](../../08-domain/spec/08.0-domain.norms.md) Н1.8 `answers` — «консоль их не пересчитывает»), поэтому клиент видит коды всех переходов, а
каждый OpenAPI несёт только коды своего перехода и на коды чужого ссылается сюда, не перечисляя их. Коды названы по
стороне (ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 20): «коды переходов 1–2» — пересылающей консоли кластера,
«коды перехода 2» — принимающей консоли домена (с передачей процессу по переходу 3), «коды перехода 3» — процесса `domain`.

| Переход (сторона) | Процесс, OpenAPI | Свои коды и слова | Норма |
|---|---|---|---|
| 1–2 — пересылка `/domain/*` (пересылающая) | консоль кластера; [OpenAPI урока P/06](../../06-console/spec/06-console.api.openapi.yaml) (пути главы 6.7) | 404 `not a domain route`; 413 / 400 / 408 тело; 401 / 403 сторожевая — кто звонит; 503 `domain console not known`; 400 `one hop`; 503 `the list of members does not read`; 404 `no domain here`; 503 `CLUSTERS does not read`; 404 `no console known`; 502 `did not answer`, `answer too large`, `answer broke off`; у `/domain/at/…` — 404 `not a route handed to a member`, `not another member`, `no such member`; у подписанта — 404 `no signer here`, 502 `did not answer` | [P/06.7](../../06-console/spec/06.7-console.norms.md) Н3 «переслать», «у члена», Н1.8, Н4 |

Локальный отказ стороны — по схеме отказа OpenAPI её урока: у консоли кластера `ConsoleRefusal` `{detail, error}`, оба
обязательны (не `{error}` один), у консоли домена — схема урока P/10; `detail` — постоянный текст реализации; ответ
дальнего перехода — неизменён (догадка стадии C FW-G01, решение «Архитектора» 2026-10-23).
