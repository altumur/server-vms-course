# Договор пересылки: заголовки между процессами, пересылка одной функцией, отказы по переходам

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13); разбор ревью стадии A 8–10, № 23, № 14 /
решение 3). Путь двери людей домена проходит до трёх процессов: консоль кластера (переход 1 — пересылка, глава 6.7 позднего
слоя урока P/06), консоль домена (переход 2 — приём пересылки и передача процессу, урок P/10), процесс `domain` (переход 3 —
исполнение, урок P/08). Владелец — урок P/06, глава 6.7 (до переноса — [М11/8](../../../М11_Domain/spec/08-doors-between-clusters.norms.md)
Н1.3, Н1.4, Н3 «принять консолью»): пересылка — функция консоли кластера. Участники — консоль домена (P/10: приём
пересылки, передача процессу — [М11/3](../../../М11_Domain/spec/03-agent-and-reports.norms.md) Н1.8 `pass`, `answers`) и
процесс `domain` (P/08: чтение `X-W2C-Client` — [М11/9](../../../М11_Domain/spec/09-people-grants-names.norms.md) Н1.10
`address`).

Перенесено из М11/8 Н1.3 (строка `via`), Н1.4 (блок целиком), Н3 «принять консолью» и М11/9 Н1.10 (строка `header`) без
изменения поведения; раздел «Отказы по переходам» — решение «Архитектора» 2026-10-20 (решение 3: каждый OpenAPI несёт
только свои коды), коды в нём — из норм переходов, новых нет. Таблица пересылки, адрес (`holds`, `to`, `view.url`,
`CLUSTERS`), `where` члена и пересылка подписанту — нормы владельца (М11/8 Н1.2, Н1.3, Н1.5, Н1.9); TLS между кластерами и
`peer` — М11/8 Н1.6; сторожевая — [договор сторожевой и передачи](gate-and-pass.md). Ссылки в перенесённом тексте: «Н1.x»,
«Н3» — урока М11/8 (у строки `header` — М11/9); «урок N» — урок М11/N.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Заголовки между процессами

| Заголовок | Ставит | Читает | Раздел |
|---|---|---|---|
| `X-W2C-Via: <CLUSTER>` | консоль кластера при пересылке в консоль другого кластера (переход 1) | принимающая консоль кластера: пришёл — в другой кластер не пересылает (400 `one hop`) | «Один переход» |
| `X-Operator: console` | консоль кластера при каждой пересылке (переход 1) | принимающая консоль (кластера или домена) — только у соединения с доказанной ролью `console`; иначе снимает | «Пересылка», «Принять консолью» |
| `X-W2C-Client: <адрес>` | консоль домена при передаче процессу `domain` (переход 2) | процесс `domain` — только на соединении роли `domainconsole` | «Адрес клиента» |
| `X-User` | никто: пришедший снимается всегда | — | [договор сторожевой и передачи](gate-and-pass.md) `x_user` |

### Один переход

Из М11/8 Н1.3:

```yaml
via:          X-W2C-Via: <CLUSTER> ставит каждая пересылка в консоль другого кластера; «пришёл X-W2C-Via» — заголовок
              есть, в том числе пустой (добавлено сверкой М11, D7); консоль, получившая X-W2C-Via,
              в консоль другого кластера не пересылает (400 one hop); в консоль домена своей коробки (holds) — пересылает
```

### Пересылка — одна функция

Из М11/8 Н1.4:

```yaml
request:      метод, путь и query как пришли; тело ≤ предела тела консоли (P/06.3 Н1.3 `body`, 1 МиБ): больше — 413, chunked —
              400, медленно — 408 (P/06.5 Н4); тело никогда не обрезается
pass:         Authorization, Content-Type, Idempotency-Key — как пришли
set:          X-Operator: console; X-W2C-Via: <CLUSTER> — к консоли другого кластера (Н1.3)
never:        прочие пришедшие заголовки; пришедшие X-User, X-Operator, X-W2C-Via дальше не идут никогда
x_operator:   принимающая консоль признаёт X-Operator: console (значение байт в байт: `Console` — не оно; добавлено
              сверкой М11, D16) только у соединения с доказанной ролью console (у консоли
              домена соединение без неё отказано раньше — Н1.6 server.role)
              (сертификат роли P/02.4 Н1.6, Н1.6 ниже); иначе снимает его до сторожевой, как любой пришедший X-Operator
              и X-User (ADR-0075 п. 3); признанный прав не даёт — сторожевая решает по Authorization (урок 9), он
              называет в журнале принимающей, что запрос переслан консолью
answer:       статус, Content-Type, X-Unreachable и тело как пришли, без разбора и обёртки (ADR-0061 доп. п. 6);
              тело больше FORWARD_MAX — 502 answer too large, из тела не уходит ничего; нет ответа за FORWARD_WAIT или
              сеть — 502 did not answer (и отказ рукопожатия сервером, TLS alert двери роли Н1.6 — рукопожатие не
              состоялось: сеть, без слова peer); ответ оборвался — 502 answer broke off
FORWARD_MAX:  1 МиБ
FORWARD_WAIT: столбец «Ожидание» строки таблицы Н1.2 (умолчание 5 с); двери переноса Н1.9 — свои сроки урока 10
gate:         сторожевая пересылающей консоли спрашивает только, кто звонит (любой грант этого кластера, урок 9 Н1.5; петля
              operator, урок 2 Н1.8), и не спрашивает у открытых строк таблицы (Личность «—»); что можно, решает сторожевая
              консоли домена или члена
tls:          к https:// — клиент роли console (P/02.4 Н1.6) с проверкой сервера peer (Н1.6) по члену назначения:
              консоль кластера держателя — держатель, консоль члена — имя из CLUSTERS; консоль домена своей коробки —
              своя CA
journal:      domain.forwarded {cluster, path, user, status} у пересылающей: cluster — куда, path — пришедший путь,
              user — имя, доказанное сторожевой (до урока 9 — operator), не X-User; status — код ответа или отказа (отказ рукопожатия
              двери роли — 502, как сеть)
```

### Принять консолью

Из М11/8 Н3 «принять консолью (любая консоль, до сторожевой)»:

```
1. X-User — снять (P/06.3 Н1.3 `x_user`)
2. X-Operator: console (байт в байт) и соединение с доказанной ролью console — оставить для журнала; иначе снять
```

### Адрес клиента

Из М11/9 Н1.10 `address` (строка `header`; что процесс считает по адресу — предел попыток входа, М11/9 Н1.10):

```yaml
  header:  X-W2C-Client: <адрес TCP-пира клиента> — ставит консоль домена при передаче процессу domain; процесс верит ему
           только на соединении роли domainconsole (P/02.4 Н1.6), на прочих — не читает; роль доказывает сертификат
           клиента: дверь процесса domain (SIGNER_URL) под TLS запрашивает его необязательно (агенты и ретрансляторы
           класса signed урока 8 его не шлют), доверяет только своим ca.pem, ca.next.pem кластера; предъявлен и роль из
           SAN — domainconsole → заголовок читается; иначе (нет сертификата, иная роль, HTTP стенда) — не читается, предел
           считает адрес TCP-пира; на стенде без TLS заголовок не доверяется никогда — долг стенда, не нормы (добавлено
           сверкой М11, cammeta-python М11-09 № 22); пришедший снаружи X-W2C-Client
           консоль снимает, как X-User (урок 3 Н1.8 pass; решение «Архитектора» по сверке М11, P16)
```

## Отказы по переходам

Решение «Архитектора» 2026-10-20 (разбор ревью стадии A 8–10, решение 3): ответ дальнего перехода ближний отдаёт как
пришёл (Н1.4 `answer`; М11/3 Н1.8 `answers` — «консоль их не пересчитывает»), поэтому клиент видит коды всех переходов, а
каждый OpenAPI несёт только коды своего перехода и на коды чужого ссылается сюда, не перечисляя их.

| Переход | Процесс, OpenAPI | Свои коды и слова | Норма |
|---|---|---|---|
| 1 — пересылка `/domain/*` | консоль кластера; OpenAPI урока М11/8 (при переносе — урок P/06, глава 6.7) | 404 `not a domain route`; 413 / 400 / 408 тело; 401 / 403 сторожевая — кто звонит; 503 `domain console not known`; 400 `one hop`; 503 `the list of members does not read`; 404 `no domain here`; 503 `CLUSTERS does not read`; 404 `no console known`; 502 `did not answer`, `answer too large`, `answer broke off`; у `/domain/at/…` — 404 `not a route handed to a member`, `not another member`, `no such member`; у подписанта — 404 `no signer here`, 502 `did not answer` | М11/8 Н3 «переслать», «у члена», Н1.9, Н4 |
| 2 — приём и передача | консоль домена; при переносе — OpenAPI урока P/10 | отказ рукопожатия двери роли (ответа HTTP нет); 401 `no_role`, 403 `no_role`, `wrong_role`, `bad_chain`; 401 / 403 / 503 сторожевая; 404 `not a domain route` (сегмент `.`/`..`); `door.pass` — коды «Передачи» договора сторожевой; передача процессу — 502 при обрыве и молчании (как Н1.4 `answer`) | М11/8 Н1.6 `server.role`, Н1.2, Н1.7; М11/3 Н1.8 `pass`; [договор сторожевой и передачи](gate-and-pass.md) |
| 3 — исполнение | процесс `domain`; при переносе — OpenAPI урока P/08 | коды своей двери (Н3 и Н4 уроков М11); 409 `deposed`; 503 `frozen`; 503 `standby` | уроки М11 по двери; М11/10 Н1.6, Н1.7; М11/12 Н1.7 |

Пока уроки 8–10 не перенесены, двери `/domain/*` описывают OpenAPI уроков М11 по своим дверям: в них ответ `Forwarded`
ссылается на этот раздел и коды переходов 1 и 2 не перечисляет; слова перехода 1 несёт OpenAPI урока М11/8 (`Refusal`).

## Соответствие прежним урокам

Из М11/8 (разбор ревью стадии A 8–10, № 23 / решение 3): Н1.3 — строка `via` (здесь «Один переход»; `holds`, `to`,
`view.url`, `CLUSTERS` остались); Н1.4 целиком (здесь «Пересылка — одна функция»; в М11/8 — указатель); Н3 «принять
консолью» (здесь «Принять консолью»). Из М11/9 Н1.10 — строка `header` (здесь «Адрес клиента»). Правило
`X-W2C-Client` повторено в М11/3 Н1.8 `pass`; ту же строку правит № 2 пакета «до», указатель туда — после неё. Части норм М11/8-03, -04, -05,
-06 (глава 6.7) и М11/9-09 — по `note` [id-map](../id-map.tsv).
