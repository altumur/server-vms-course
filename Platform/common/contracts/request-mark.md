# Договор просьбы и её метки: строка просьбы, ключи `requests`, метка, состояния, `kept`

Общий договор модуля «Платформа» (ADR-0083 доп. (5) и доп. (11): контракт, который читают и пишут несколько процессов,
лежит в `Platform/common/`; разбор ревью стадии B 3–5, В1). Владелец — глава [P/06.4](../../06-console/spec/06.4-console.norms.md)
(консоль): строку просьбы она создаёт дверью и снимает жнецом, учёт `asked` ведёт сама, в метке она — участник (жнец пишет
`no_begun` `expired` и `unknown` по индексу; P/06.4 Н3 «подать просьбу», «жнец»). Читают и пишут: воркер-держатель — метку
`begun` и исход, уборку метки после `kept`, подачу строки по `worker.requests` (глава
[P/03.6](../../03-worker/spec/03.6-worker.norms.md) Н1.5, Н3 «взгляд держателя», «Исполнение и уборка метки»); пульс
держателя с `fetched` — глава [P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.1. Перенесено из P/06.4 (прежде М10/8)
Н1.5 (блоки `<sub>/requests/<rid>`, `action`, `rid`, `manifest`, `mark` и абзац о векторах), Н1.6 (абзац о формах метки),
Н3 «Состояния исполняемой просьбы и её метки» (целиком) и «Гонки» прохода «жнец» без изменения поведения. Учёт человека
(`ledger`), `holds`, константы жнеца, двери консоли, подача `POST /<sub>/requests` и проход жнеца — в нормах владельца
(P/06.4 Н1.5, Н2, Н3); константы держателя — P/03.6 Н1.5; форма ключей `requests` в манифесте и отказы их загрузки —
[P/02.1](../../02-installer/spec/02.1-installer.norms.md) Н1.4, Н4. Форма строк — семьи владельца
[`requests`](../../06-console/data/requests.form.yaml) (`<sub>/requests/<rid>`) и
[`commands`](../../06-console/data/commands.form.yaml) (`objects/<sub>/commands/<rid>`) с таблицами исходов рядом
([каталог](../data/catalog.tsv)). Ссылка «P/0N[.K] НM» — норма урока или главы модуля.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Просьба

```yaml
<sub>/requests/<rid>:                        # строка; создание-однажды; писатель — консоль (дверь) или воркер (worker.requests);
                                             # free-<server>-<volume> — не эта форма: её пишет и перезаписывает ресурс (free_ask, P/05 Н1.4; ADR-0059),
                                             # без unit, digest и requests.schema
  unit:        <id>                          # ДОЛЖЕН; у просьбы ресурса (ADR-0059, free_ask) отсутствует; просьбу ресурса различают по семье ключа
                                             # requests/free-<server>-<volume> (каталог, P/05 Н1.4), не по отсутствию unit (разбор ревью стадии B 6–7, № 37)
  <поля тела>: по requests.schema, текстом: строка — как есть, иное значение — канонический JSON (JCS, ADR-0072)
  valid_until: <секунды>                     # время писателя P/01.1 Н0 (присланное — усечение вниз до мс, отрицательное — 0, P/06.4 Н3 шаг 1);
                                             # когда у манифеста valid_for или клиент прислал свой срок; 0 и прошедшее — срок,
                                             # уже вышедший (expired), а не «без срока» (сверка python и go М10/6–11, E52)
  digest:      <sha256 hex>                  # ДОЛЖЕН у всякой исполняемой просьбы (не у просьбы ресурса): у поданной дверью — JCS тела клиента после схемы без
                                             # полей сервера (вид client); у поданной воркером — JCS объекта из полей тела строки как записаны (текстом), без unit,
                                             # valid_until и штампов (вид worker); воркер считает его сам при записи (P/03.6 Н1.5); им сравнивают повторы;
                                             # у цели с requests.key — вид worker у обоих писателей: одно имя rid дают и дверь, и воркер, повтор сверяется
                                             # одной формулой — digest вида worker плюс явная сверка unit; вид client — повторы одного клиента по
                                             # Idempotency-Key у цели без requests.key (векторы request-digest, третье правило; ADR-0091 доп. (23) п. 1,
                                             # доп. (24) п. 3, доп. (25) п. 3)
  by, at, group, <about-поле>:               # по requests.stamp; by — человек у поданной дверью, `<sub>/<unit>` подателя у поданной
                                             # воркером (P/03.6 Н1.5; ADR-0091 п. 7); about-поле — значение единицы-адресата у обеих
  filed:       <экземпляр воркера>           # ДОЛЖЕН у поданной воркером (worker.requests) — кто подал; у поданной дверью отсутствует
action:     действие просьбы — значение строкового поля action тела (по requests.schema манифеста); requests.elsewhere и
            rights.reach.requests (P/06.3 Н1.5) называют действия этими значениями; у тела без поля action действия нет
            (разбор ревью стадии A 6–7, № 14: нынешнее поведение свидетелей; правка поведения — отдельный пункт коммита урока 6);
            поле action метки (раздел «Метка») — это же значение; у тела без action в метке поля action нет (разбор ревью
            стадии B 6–7, № 16)
rid:        непустой, ≤ 200 байт UTF-8; без / \ " ' и знаков Cc, Zl, Zp (вектор rid; разбор ревью стадии B 6–7, № 35); не `.` и не `..` (сегмент ключа метки, P/01.1 Н1); не начинается с `free-`
            (это семья просьб ресурса P/05 Н1.4; решение «Архитектора» 2026-10-18, каталог данных); по requests.key — шаблон {поле}; иначе у двери консоли —
            r-<sha16(Idempotency-Key)> (заголовок обязателен, P/06.4 Н2); у воркера (worker.requests, P/03.6 Н1.5) без requests.key цели — по ключу
            подателя <подсистема подателя>.<ключ> в этой грамматике (ключ — детерминированно из данных подателя; в именах подсистем точки
            нет и они не начинаются с free- — разбор однозначен, форма двери r-<16 hex> не возникает) или случайный, без точки, — только у
            просьбы, повтор которой подателю не нужен (ADR-0091 доп. (20) п. 2, доп. (21) п. 2, доп. (23) п. 2, доп. (24) п. 5)
            # подстановка шаблона, давшая rid не по этой грамматике (длина или запрещённый знак в значении поля),
            # — определённый 400 RequestError, detail называет поле шаблона (например unit); повтор того же входа
            # даёт тот же отказ: это объявленное сужение области id единицы для просьб по шаблону
manifest:                                    # requests: (форма — P/02.1)
  schema:      JSON Schema тела
  valid_for:   секунд до срока; обязателен без free
  most_valid:  потолок valid_for; обязателен с valid_for; ≥ valid_for
  per_person:  предел зарезервированных/неотвеченных rid одного человека (без домена человек — operator, P/06.3 Н1.3); требует ttl; резерв после отказа может
               консервативно занимать место до завершения повтора или обслуживания, но не теряется у принятой просьбы
  settle:      конечное число секунд ≥0 до снятия отвеченной строки; умолчание 60; местный монотонный возраст первого подтверждения исхода по правилу ниже
  ttl:         срок обычной строки без valid_until и строки ресурса без хозяина; обязателен с free и per_person; 0 — без предела.
               Возраст строки — now − её at (stamp, стенные часы), если at есть и читается; иначе местный монотонный возраст первого
               наблюдения этой версии строки консолью; перезапуск начинает его заново: неизвестный возраст не считается
               истёкшим (журнал cammeta-go, урок 8 № 6). У дозаписи без fetched один ttl не разрешает снять строку/непустой учёт: автоматическое завершение по возрасту вне этого профиля
  key:         шаблон rid по P/02.1 Н1.4: {поле} только строка, {поле:int} только конечное binary64-число |x|≤2^53−1 с усечением к нулю; *_secret запрещён как источник
  outcome:     mark (умолчание) | fetched — чем держатель сообщает итог (ADR-0054 доп. 2026-10-17); mark — метка begun/исхода (обычный профиль);
               fetched — дозапись: только слово fetched в пульсе, метки нет; fetched без key — отказ загрузки P/02.1 Н1.4
  stamp:       [by, at, group, about]       # about — поле about.field манифеста (у testsub2 — of) со значением единицы-адресата (E56)
  journal:     вид строки журнала; нет ключа — request.asked (сверка python и go М10/6–11, E58)
  elsewhere:   действия (action), которые исполняет другой процесс (жнец их не трогает)
  free:        принимает просьбы ресурса освободить место
```

Учёт человека `ledger` (`<sub>/asked/<sha16(имя)>`), раздел манифеста `holds` и константы жнеца (`CLEAR_EVERY`, `SWEEP_EVERY`,
`REAP_AFTER`) — [P/06.4 Н1.5](../../06-console/spec/06.4-console.norms.md); константы держателя (`PERFORM_TIMEOUT`,
`PERFORM_GRACE`, `REQUESTS_HOLD`, `COMMANDS_PER_LOOK`) — [P/03.6 Н1.5](../../03-worker/spec/03.6-worker.norms.md).

## Метка

```yaml
mark:       objects/<sub>/commands/<rid>      # обычный профиль; у дозаписи ADR-0054 метки нет. Строка-объект, создание-однажды
  begun:     {instance, slot, unit, of?, at, digest, valid_until?}        # до вызова; digest — копия элемента `digest` строки просьбы
             # (раздел «Просьба» выше: вид client или worker — по правилу digest), тот же unit; им сравнивают повторы, и после settle — той же формулой
             # (ADR-0091 доп. (24) п. 3)
  answer:    + {outcome, action?, ended_at, error (≤ 200 — ДОЛЖЕН у refused и unknown, нет у performed), late?: true}   # action — значение поля action тела
             # просьбы (раздел «Просьба» `action`), не имя обработчика: у тела с action ДОЛЖЕН при performed/refused после вызова, при unknown
             # необязателен; у тела без action в метке поля нет (разбор ревью стадии B 6–7, № 16)
             # запись начавшего держателя — по индексу прочитанной метки, conflict → перечитать и повторить только запись,
             # без повтора действия; late — по метке, чей индекс принял запись (ADR-0054; W03-E06); закрытие чужой begun — по индексу, с ended_by
  no_begun:  {unit, digest, outcome: expired | refused | gone, ended_by: reaper | holder, ended_at, error (≤ 200 — ДОЛЖЕН у refused)}   # метка без begun (срок вышел, отказ до вызова,
             # единица-адресат отсутствует — gone, только ended_by: reaper; ADR-0091 доп. (11) п. 4):
             # digest и unit переносятся из строки просьбы — повтор после удаления строки сравнивает digest и здесь
  outcome:   performed | refused | unknown | expired | gone                # закрыто (ADR-0054; gone — ADR-0091 доп. (11) п. 4)
  ended_by:  reaper | holder                                               # кто закрыл чужую или безначальную просьбу: reaper — expired/unknown от жнеца; holder — expired/refused до вызова
             # (no_begun) и unknown, которым другой держатель закрыл чужую begun за сроком; у answer от начавшего поля нет
  kept:      max(60, ttl) от момента, когда держатель увидел, что строки просьбы больше нет (его монотонные часы), и не
             раньше valid_until, если он есть: гарантия повтора переживает строку просьбы (снятую по settle) не меньше этого
             срока; без подтверждённого конечного исхода метка не удаляется. ttl 0 («без предела» у строки) или ключа ttl
             нет — kept 60: max(60, ttl) считается по числу, 0 здесь не «без предела» (решение «Архитектора», разбор ревью
             стадии B 6–7, № 5)
```

`unit` и `digest` метки `begun` — те же, что в строке просьбы (раздел «Просьба»): комментарий блока выше говорит о
поданной дверью; у поданной воркером `digest` — JCS полей тела строки без `unit`, `valid_until` и штампов (разбор ревью стадии B 6–7, № 35).

Предел `error` метки (`answer` и `no_begun`) — 200 кодовых точек Unicode, не байт и не единиц UTF-16 (как `maxLength`
OpenAPI). Текст длиннее писатель усекает до 199 кодовых точек и дописывает «…» (U+2026) — всего 200; текст в пределе
пишется как есть (разбор ревью стадии B 6–7, № 31).

### Три формы метки

Из P/06.4 Н1.6 (форма `answered` двери консоли — содержимое метки):

`answered` — содержимое метки-строки (раздел «Метка» выше): строковые значения, включая времена, error и
late="true"; описание `{queued:rid}` не допускает замены rid объектом. Метка без начала
не содержит instance/slot/at/action/late; закрытие чужой begun сохраняет её поля, добавляет
unknown/ended_by/ended_at/error. Ответ начавшего не содержит ended_by. Эти три формы
различаются в AnsweredMark; begun без исхода возвращается как queued, не answered.

## Состояния исполняемой просьбы и её метки

Таблица применяется к обычной просьбе с unit, исполняемой держателем через метку.
Из неё исключены строки ресурса (семья ключа `free-*`), действия elsewhere и дозапись ADR-0054
(семья просьб манифеста с `requests.outcome: fetched`: ключ из данных, например `<unit>-<from>-<to>`, исполнение идемпотентно по данным).
Строка ресурса — по семье ключа `requests/free-<server>-<volume>` (каталог; строка этой семьи без `unit` — её форма, а строка
семьи `requests/<rid>` без `unit` — нечитаема по семье `requests`, жнец её не метит и не снимает); класс прочих строк —
объявленной формой/действием манифеста (`outcome`, `free`, `elsewhere`; действие — раздел «Просьба» `action`), не одним текстом
rid (разбор ревью стадии B 6–7, № 37).
Дозапись: консоль снимает строку по CAS после fetched и settle и освобождает её rid в asked
по CAS. Сторона держателя дозаписи — [глава P/03.6](../../03-worker/spec/03.6-worker.norms.md) Н3 «Дозапись ADR-0054».
Признак дозаписи — `requests.outcome: fetched` (ADR-0054 доп. 2026-10-17); учебный потребитель — просьбы `testsub2`
(форма — README [приёмки главы 3.6](../../03-worker/acceptance/6/README.md), обработчик — P/03.6 Н5). Жнец такую строку не метит и не снимает по одному `ttl`; сценарий 07 приёмки главы 3.6.
Строки ресурса и elsewhere остаются у своих владельцев; жнец их не метит и не
переводит в протокол обычной просьбы. Elsewhere закрывает/снимает её владелец — в обычном профиле; в профиле дозаписи тело с
`action` из `elsewhere` — дозапись: держатель сообщает fetched, консоль снимает строку после settle (P/03.6 Н3; (решение «Архитектора» 2026-10-20, разбор ревью стадии B 6–7)).

Для обычной просьбы подтверждение исхода — успешное чтение терминальной метки
с теми же unit/digest. Для дозаписи — подтверждённый fetched держателя по её строке: rid или SaidID(rid) в поле `fetched`
пульса `<sub>/heartbeats/*` любого воркера её манифеста ([глава P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.1; чужих rid воркер не называет).
С этого первого наблюдения консоль считает settle местными монотонными часами;
при возрасте <settle строка не снимается ни clear, ни sweep. Равенство разрешает
попытку CAS, не обещает немедленного удаления. Повторное наблюдение и поздняя
замена unknown на performed не сдвигают начало для той же строки/unit/digest;
новая версия строки начинает новое наблюдение. После рестарта или
утраты памяти наблюдения возраст начинается заново, ended_at/fetched не служат
чужими часами. Неизвестное чтение не даёт удалить строку; перед CAS подтверждается
её текущая версия и основание снятия. Учёт отвеченной просьбы может освободиться
раньше удаления строки: settle ограничивает строку, не удержание per_person.
Для обычного профиля сначала проверяется существующая метка, затем срок/допуск; имя rid не определяет класс строки.
Каждое чтение даёт состояние только на момент чтения: конфликт возвращает к таблице.

| Участник / состояние | Условие | Действие | Исход |
|---|---|---|---|
| подача, метка с исходом | тот же unit и digest | вернуть метку, не создавать строку/учёт | 200 answered |
| подача, begun без исхода | тот же unit и digest | не создавать новую просьбу | 202 queued |
| подача, резерв rid уже есть, метки нет | учёт успешно прочитан | резерв не дублировать; обязательно продолжить к записи/проверке строки и метки (шаги 4–5) | сам резерв не даёт 202 |
| подача, чужое содержимое | иной unit или digest у строки/метки | ничего чужого не менять | 409 exists/spent |
| держатель, метка с исходом | любой исход | не вызывать действие | пропуск |
| держатель, своя begun | действие уже вызвано этим экземпляром | не вызывать снова | ждать результат |
| другой держатель, begun | at + timeout + grace ещё не позади | не менять | пропуск |
| другой держатель, begun | срок ожидания позади | unknown по прочитанному индексу | conflict → перечитать, итог не затирать |
| держатель, метки нет | срок вышел / нет допуска | put_new expired/refused, без вызова | conflict → перечитать |
| держатель, метки нет | допуск есть, срок не вышел | put_new begun; только подтверждённый успех разрешает вызов | begun → один вызов |
| начавший держатель, begun/unknown | ответ/таймаут | записать полный исход по индексу прочитанной метки (conflict — перечитать, повторить запись), сохранив begun-поля | performed/refused/unknown; поздний ответ — late |
| жнец, метки нет | строка просрочена по P/06.4 Н3 | put_new expired | conflict → перечитать метку |
| жнец, begun без исхода | брошенная просьба | unknown по индексу | conflict → перечитать; итог не затирать |
| жнец, метка с исходом | любой исход, возраст подтверждения ≥settle | метку не менять; можно снять строку по её CAS | исход сохраняется |
| clear обычной просьбы | подтверждены строка и метка с исходом для тех же unit/digest; возраст ≥settle | удалить эту версию строки; учёт — CAS | conflict → не удалять новую версию |
| держатель, уборка метки | строки просьбы уже нет и выдержан kept | удалить по индексу проверенной метки | conflict/неизвестное чтение → оставить |

Строки «держатель …», «другой держатель …», «начавший держатель …» и «держатель, уборка метки» — сторона [главы P/03.6](../../03-worker/spec/03.6-worker.norms.md)
(Н3 «взгляд держателя», «Исполнение и уборка метки»); здесь они стоят, потому что таблица — одна на просьбу. Строки
«подача …» — дверь консоли (P/06.4 Н3 «подать просьбу», шаги — там), «жнец …» и «clear …» — проход жнеца (P/06.4 Н3 «жнец»).

## Гонки меток

Из «Гонок» прохода «жнец» P/06.4 Н3: два держателя одной единицы: `put_new` метки пропускает одного; второй держатель закрывает чужую `begun` за сроком словом `unknown` по индексу — начавший, получив поздний ответ, перечитывает метку и пишет исход по её индексу поверх, `late: true`, как и после жнеца. Жнец против держателя, который начал в последнюю секунду: метка `begun` уже есть — жнец пишет `unknown` по индексу, держатель, получив ответ, пишет исход по индексу прочитанной метки; conflict — перечитать и повторить только запись: жнец и второй держатель пишут однажды, поэтому повтор держателя кончается его словом поверх `unknown` — побеждает держатель (ADR-0054), `late: true` у исхода после `unknown` (догадка стадии C W03-E06, решение «Архитектора» 2026-10-23); жнец пишет только по прочитанному индексу и слово держателя не затирает. Повтор подачи тем же rid: `cas ""` — второй получает «есть»; совпали unit/digest — queued без исхода, answered с исходом; чужое содержимое — exists/spent.
