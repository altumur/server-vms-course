# Договор журнала событий: строка, id, бакет, имена файлов, писатели, запись строки

Общий договор модуля «Платформа» (ADR-0083 доп. (5): контракт, который читают и пишут несколько процессов, лежит в
`Platform/common/`; разбор ревью стадии A 3–5, № 9). Владелец — ресурс [P/05](../../05-resource/spec/05-resource.norms.md):
он читает бакеты (индекс P/05 Н1.3), копирует закрытые (P/05 Н1.4 `mirror`), убирает по сроку и тянет назад
(P/05 Н3 «проход ресурса», Н1.4 «Восстановление бакетов»); порядок записи строки — раздел «Запись строки» ниже (перенесено
из P/05 Н3 «записать событие»; разбор ревью стадии B 3–5, В1). Дописывают строки
(`append`): воркер — события подсистемы по `observe` (глава [P/03.6](../../03-worker/spec/03.6-worker.norms.md)),
консоль — журнал и отметки оператора (глава [P/06.4](../../06-console/spec/06.4-console.norms.md)),
каждый процесс платформы — журнал `audit` своей роли; кодирование имён файлов исполняет каждый процесс, кладущий файл в
корень событий или объектов. Перенесено из М10/8 Н1.1 (абзац «Имена файлов в общих деревьях») и Н1.2 (блоки `line`,
`bucket`, `class`, `journal`, `writer`, абзац об id) без изменения поведения: подавление повторов (`suppress`) — глава
P/03.6 Н1.2; `older_epochs` и отметки оператора (`marks`) — глава P/06.4 Н1.2. Векторов нет — норма формы.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Строка и бакет

```yaml
line:                                        # одна строка JSON в файле бакета
  t:        <секунды стенных часов писателя, когда записали>      # ДОЛЖЕН; выбирает бакет
  kind:     <вид>                                                  # ДОЛЖЕН
  id:       e1-<hexUTF8(дерево)>-<hexUTF8(единица)>-<эпоха>-<hexUTF8(экземпляр)>-<номер>                   # ДОЛЖЕН; уникален; по нему убирают дубли копий
  of:       <sub>/<id>                                             # единица, про которую; ставит платформа из about;
                                                                   # своё of — только деревья console и audit
  class:    alarm                                                  # только у тревоги; observation не пишется
  occurred: <секунды>                                              # когда произошло; необязателен
  # t и occurred — время common.time, как все времена (P/01.1 Н0 «Время в строке»): писатель пишет строго (кодек
  # Platform/common/data/codec.tsv time: число, до трёх знаков дроби), читатель читает терпимо (число или строка по
  # кодеку читателя); форма строки — семья events P/05 (Platform/05-resource/data/events.form.yaml, Platform/05-resource/data/events.outcomes.tsv); векторы чтения —
  # common/vectors/journal bucket.tsv t-* (догадка стадии C EJ-G07, решение «Архитектора» 2026-10-23)
  <поля>:   слова подсистемы                                       # v не пишется: отсутствие = версия 1; v — положительное
                                                                   # целое по форме, v = 2 сохраняется, выбора поведения по v
                                                                   # нет (EJ-L04); v — дополнительное
                                                                   # поле, читатель его терпит, писатель пишет строго по форме
                                                                   # без v (догадка стадии C EJ-G10)
  depth:    глубина строки целиком (объект строки, в том числе extra и значения names) — не больше JSON_DEPTH = 128
            (P/01.1 Н2.1; счёт уровней там же: вложенные объекты и массивы, корневой объект — 1); писатель строку глубже
            не пишет — отказ вызывающему, ничего не записано; читатель (ресурс, сливающий — консоль и воркер) — строка
            нечитаема: пропуск и счёт garbled (lines_garbled, P/05 Н1.3), как прочие не по форме (EJ-DEPTH-BASELINE33, решение «Архитектора» 2026-10-25)
bucket:
  path:     <root>/<дерево>/<unit>/e<epoch>/<YYYYMMDDTHHMMSSZ>.events.jsonl    # root: RESOURCE_ROOT | <PLATFORM_DIR>/events;
                                                                          # дерево — <sub> подсистемы, console или audit (разбор ревью стадии B 6–7, № 35)
  alarms:   <root>/<дерево>.alarms/<unit>/e<epoch>/…                              # своё дерево у каждого дерева
  span:     600 с; начало = floor(t / 600) × 600 по UTC; закрыт, когда end ≤ now; катится только по часам
  years:    год имени бакета — четыре цифры, 0001–9999 (снизу время ограничено t ≥ 0, P/01.1 Н0); t позже 9999 года — отказ
            записи до выделения id (векторы common/vectors/journal years.tsv; догадка стадии C EJ-G06)
  durable:  тревога и журнал — fsync строки и каталогов до корня; наблюдение — нет
  modes:    группа деревьев событий — w2c-events (P/02.4 Н1.1 users_groups; корень событий — RESOURCE_ROOT (P/02.4 Н1.2; умолчание
            <PLATFORM_DIR>/events, тот же объект; EJ-G12) — 2771 w2c:w2c-events:
            проход прочим без чтения, путь к замкам присутствия .workers — договор замка присутствия modes, догадка стадии C PL-G03, решение «Архитектора» 2026-10-23,
            Н1.1 dirs); каталог, в котором пишет или удаляет больше одного пользователя группы (дерево, <unit>, e<эпоха>:
            создаёт писатель, закрытые бакеты удаляет ресурс P/05), — 2770; каталог одного пишущего пользователя — 2750;
            файл бакета — 0660, если его пишут процессы разных пользователей группы, иначе 0640; писатели и читатели —
            участники группы по юнитам P/02.4 (воркеры, консоль, контроллеры, ресурс, процессы домена); прочим — ничего;
            0755/0644 для всех — нет (догадка стадии C EJ-L02/L03/L04, решение «Архитектора» 2026-10-23);
            существующий каталог или бакет с иными правами или группой — дописывание отказывается до записи, строка
            лога и счёт; существующие объекты писатель сам не меняет (chmod/chown — дело установки, P/02.4), новые
            создаёт с правами и группой нормы (догадка стадии C EJ-G11, решение «Архитектора» 2026-10-23)
  torn:     последний фрагмент без LF — даже разбираемый JSON — не строка: пропуск и счёт torn (писатель может дописывать);
            полная строка с LF, не разобранная формой line (объект JSON: t — время, kind и id — строки; глубина — line depth), — пропуск этой
            строки и счёт garbled, бакет читается дальше, не отказ бакета; повтор id в бакете — первая строка побеждает,
            следующие отбрасываются со счётом duplicate (журнал — «хотя бы один раз», догадка стадии C EJ-L06, решение «Архитектора» 2026-10-23) (векторы common/vectors/journal bucket.tsv;
            догадка стадии C EJ-G03, решение «Архитектора» 2026-10-23)
class:      [alarm, observation]             # закрыто; класс строки — её поле class: alarm — тревога, поля нет —
                                             # observation; индекс берёт класс из поля, дерево его не переопределяет;
                                             # раскладка .alarms — у писателя: тревогу он кладёт в <дерево>.alarms любого
                                             # дерева, в том числе audit.alarms и console.alarms (срок alarms_retention)
                                             # (решение «Архитектора», второй пилот, Н-2; меняет выбор сверки М10/6–11 E18)
```

## Журнал и писатели файла

```yaml
journal:    дерево audit/<роль>/e1/…: строки платформы о себе (unit.created|changed|deleted, door.issued, schema.raised,
            events.removed, policy.changed, drain.*, server.*, worker.name_taken (alarm), door.keys_conflict (alarm; P/06.5 Н3 «/where/<id>»; решение «Архитектора» 2026-10-20, разбор ревью стадии B 6–7), worker.name_back (observation; глава P/03.2 Н3 «воссоединиться»), worker.hung, clock.skew, free_ask.key_taken, …);
            поля: о чём строка — sub и target (единица; не subsystem/unit), адрес клиента у строк о двери — addr;
            второго имени у этих полей нет (ADR-0069)
door_journal: журнал двери процесса подсистемы (P/03.4 Н1.7 journal) — строки видов двери в audit/<роль>/e1 своим писателем
            журнала (writer ниже); общие поля: user (имя из токена двери) или role (роль листа), sub (подсистема двери),
            target, of, bytes (отданные байты тела), status (код ответа), addr (адрес клиента); виды и их поля сверх
            общих называет урок-владелец двери (archive.read — V/02) (ADR-0091 доп. (7) п. 4, доп. (8) п. 9)
writer:     консоль — отдельный процесс; журнал и отметки она пишет в корень событий своего сервера (тот же, что
            у ресурса этого сервера), ресурс индексирует их как свои бакеты; у файла один писатель, кроме журнала:
            в audit/<роль>/e1 пишут все процессы этой роли на сервере (путь экземпляра не несёт, единица журнала — роль);
            строка дописывается целиком под исключительной блокировкой файла (flock(2) LOCK_EX, как замок присутствия; разбор ревью стадии B 6–7, № 35), строки разных процессов не перемешиваются,
            их различает id (экземпляр в нём); бакет — тот же по t у всех писателей (журнал cammeta-go, урок 8 № 5)
```

## Id события и экземпляр писателя

`hexUTF8` — строчные hex-пары байтов UTF-8 без префикса, разделителей и нормализации.
Дерево и единица — непустые компоненты пути бакета (для журнала audit/роль, для отметок
console/экземпляр). Эпоха — каноническое десятичное целое ≥0, номер — ≥1, без ведущих нулей.
Номер атомарно выделяется общим счётчиком экземпляра на каждую новую публикуемую строку,
включая итог подавления; не переиспользуется при смене единицы, дерева, эпохи или бакета.
Итог подавления получает новый id, а не id первой строки окна. Зеркало/повторная выдача
сохраняют id исходной строки. При исчерпании счётчика новые строки не публикуются до нового
уникального экземпляра; оборачивание счётчика запрещено.
Экземпляр писателя — непустая строка, уникальная с учётом коробок и перезапусков (`INSTANCE_ID`, `BOX_ID` — [P/02.4 Н1.2](../../02-installer/spec/02.4-installer.norms.md); грамматика и вычисление — [договор экземпляра](instance.md)); локального PID
недостаточно, повтор прежнего INSTANCE_ID новым процессом вне профиля. Экземпляр — один
компонент пути: не `.`/`..`, без `/`, `\`, `|`, `"`, запятой, Cc/Zl/Zp. Это условие
профиля действует и на INSTANCE_ID из окружения, и на вычисленное значение; проверяется
до старта/первой публикации вместе с файловой представимостью («Имена файлов в общих деревьях» ниже). Нарушение — отказ
старта с диагностикой имени экземпляра, без усечения/нормализации. Hex-компоненты
не содержат разделитель `-`, поэтому разные допустимые кортежи не склеиваются в один id.
Поля платформы
в строке/ответе не перезаписываются произвольными полями подсистемы. Числа JSON конечны.
`of` платформенной строки без единицы-адресата — пустая строка; у строки подсистемы
адресат определяется манифестом.

## Имена файлов в общих деревьях

**Имена файлов в общих деревьях** — одно кодирование для всех реализаций: объекты и деревья событий (P/05 Н1.1, Н1.2,
Н1.4) пишут процессы разных реализаций на одной коробке (решение «Архитектора», второй пилот, Н-3; исполняет сверку python и go
М10/3–5 п. 14 и U20). Любой логический ключ, который разрешают грамматика [P/01.1](../../01-store/spec/01.1-store.norms.md), грамматики id ([P/06.1](../../06-console/spec/06.1-console.norms.md) Н1.3) и слота ([P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н1.4) и предел
полного ключа, представим на диске. Раскладка каталогов — по логическому ключу, компонент за компонентом (между `/`):

- байт компонента из `[a-z0-9._-]` пишется как есть, любой другой байт UTF-8 — `%` и две строчные hex-цифры (`A` —
  `%41`, `:` — `%3a`, `%` — `%25`, `я` — `%d1%8f`); компонент `.` — `%2e`, `..` — `%2e%2e`;
- порог — по полному имени файла или каталога: закодированный компонент, суффикс нормы составного компонента (ниже:
  `.alarms`, `.lock`) и запас временного имени `TEMP_RESERVE` = 16 байт вместе длиннее 255 байт — компонент пишется
  как `%h<sha256 hex байтов исходного компонента>` (суффикс нормы — после него: `%h<sha256>.lock`), рядом файл
  `%h<sha256>.name` с исходным компонентом (байты UTF-8, без перевода строки); временное имя писателя (temp + rename)
  — окончательное имя, `~` и не больше 15 байт (вместе с `~` не больше `TEMP_RESERVE`; ADR-0083 доп. (16)), так что ни
  окончательное, ни временное имя не получает ENAMETOOLONG (разбор ревью стадии B 3–5, № 20; ADR-0083 доп. (11));
- файл `.name`: писатель — файла нет — пишет его (содержимое задано ключом); есть и совпадает — оставляет; есть и не
  совпадает — отказ записи без перезаписи (порча, не коллизия); читатель — `sha256` содержимого `.name` равен имени и
  закодированный исходный компонент проходит порог «длиннее 255» выше — иначе запись пропускается со счётом, как
  нечитаемая; `.name` нет — так же (векторы common/vectors/journal names.tsv; догадка стадии C EJ-G04, решение
  «Архитектора» 2026-10-23);
- раскодирование — обратное; усечение и нормализация ключа запрещены, разные ключи — разные пути, файлового профиля уже
  грамматики нет;
- служебное имя содержит `~` (ADR-0083 доп. (16)): кодирование байт `~` сырым не пишет (`%7e`), поэтому служебное имя с
  ключом не совпадёт. Замок каталога корня объектов (P/05 Н1.1 `disk`) — файл `<каталог>/~lock` в каталоге
  записываемого объекта, `flock(LOCK_EX)` на время записи; файл не удаляется. Временное имя — пунктом выше. Обход
  дерева пропускает имена с `~`; прочее неканоническое имя — по прежней норме;
- кодируются компоненты, взятые из имён и ключей: `<sub>`, дерево, `<unit>`, роль, экземпляр, `<server>`, сегменты ключа
  объекта; компоненты, форму которых задаёт сама норма, пишутся как есть — имя бакета `<YYYYMMDDTHHMMSSZ>.events.jsonl`,
  `e<эпоха>`, суффикс `.alarms`, каталоги `.workers`, `.mirror`, `.gone`, окончания `.lock`, `.name`, служебные `~lock` и хвост временного имени с `~` (`T` и `Z` имени
  бакета — не `%54`, `%5a`); составной компонент — закодированное имя плюс суффикс нормы: `testsub.alarms`,
  `<экземпляр>.lock` (журнал cammeta-go, урок 8 № 10; решение «Архитектора»). Шаг — сц. 08 шаги 12–16 [приёмки P/05](../../05-resource/acceptance/README.md): бакет, который
  раннер пишет мимо писателя под именем нормы, ресурс читает.

## Запись строки

Из P/05 Н3 «записать событие (платформа, по observe подсистемы)» (разбор ревью стадии B 3–5, В1): сторона владельца
файлового контракта — шаги, которые исполняет каждый писатель строки (воркер по `observe` — глава
[P/03.6](../../03-worker/spec/03.6-worker.norms.md) Н1.2, консоль — глава [P/06.4](../../06-console/spec/06.4-console.norms.md)
Н1.2, журнал `audit` — процесс роли); отказы записи — [P/05 Н4](../../05-resource/spec/05-resource.norms.md).

```
1. строка глубже JSON_DEPTH (line depth) — отказ, ничего не записано (EJ-DEPTH-BASELINE33); class ∈ {alarm, observation}; поле class в полях подсистемы — отказ (класс пишет писатель: alarm — полем class строки,
   observation — без поля; разбор ревью стадии B 6–7, № 35); occurred не число — отказ; v — отказ
2. of: из about манифеста (<sub>/<id>); строка подсистемы со своим of → отказ «of is the platform's to write»;
   деревья console и audit — своё of
3. подавление (events.suppress.<kind>) — только у писателя событий подсистемы (воркер по observe, глава P/03.6 Н1.2);
   журнал консоли (дерево console) и audit не подавляются: каждая строка пишется (решение «Архитектора», разбор ревью
   стадии B 6–7, № 34)
4. бакет по t: <root>/<дерево>/<unit>/e<эпоха>/<start>Z.events.jsonl; новый каталог — барьер каталога
5. дописать строку; тревога/журнал — fsync строки и каталогов до корня; файл не кончается LF (хвост прежнего писателя
   без LF) — сначала LF, затем строка, лишних байтов нет: хвост становится полной строкой — полный разбираемый JSON —
   обычной строкой со своим id, повреждённый — garbled (EJ-G03); усечения нет; поэтому журнал — «хотя бы один раз»:
   событие, записанное перед сбоем без LF, может стоять рядом со своим повтором, читатель берёт первую по id (догадка стадии C EJ-L06, решение «Архитектора» 2026-10-23); ошибка ввода-вывода — без автоматического повтора, ошибка вызывающему (догадка стадии C EJ-L02/L03/L04, решение «Архитектора» 2026-10-23)
```

**Гонки.** Один писатель на бакет (P/05 Н1.1; журнал — под блокировкой файла, `writer` выше): дописывание не конкурирует; два процесса одного `of` (переезд, эпоха) пишут в разные пути — путь несёт эпоху — и не смешиваются; ротация бакета по `t` — закрытие старого и открытие нового в одном писателе.
