# Договор токена домена: форма, `TOKEN_SKEW`, проверка `token` с `expect`, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (5) и доп. (11): общий договор может появиться раньше переноса
урока-владельца, если на него опирается уже перенесённый урок; разбор ревью стадии B 3–5, В1). Владелец — урок P/08,
глава 8.2 ([нормы](../../08-domain/spec/08.2-domain.norms.md)):
процесс `domain` выпускает токены и ведёт набор `domain/keys` и отзывы `domain/revoked` (P/08.2 Н1.2, Н1.3, Н1.6), смысл
и выдача остаются у владельца. Читают: сторожевая консоли кластера — личность по токену
([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3, Н1.8), воркер и дверь члена — получатель токена вида (глава
[P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.5, Н3 «проверить у получателя»), дверь токенов воркера ([глава 8.7](../../08-domain/spec/08.7-domain.norms.md)),
процесс `domain` — двери людей и `/domain/revoke` ([глава 8.4](../../08-domain/spec/08.4-domain.norms.md) Н1.2, Н3
«дверь людей»), консоль домена — сторожевая по [договору сторожевой и передачи](gate-and-pass.md) ([урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.5) (разбор
ревью стадии A 8–10, № 16). Перенесено из М11/2 Н1.6 (строка `token` с `header`,
`payload`, `sig`, константа `TOKEN_SKEW`, абзац о том, кто проверяет), Н3 «`token(keys, revoked, now, token)`» (шаги с
`expect` и абзац о границе) и строк Н4 о токене без изменения поведения. Общее для форм главы 8.2 (hex, канонический
base64url, JCS — RFC 8785, ADR-0072, «стенные секунды», Ed25519 — RFC 8032, полнота форм JSON, повтор ключа) —
[P/08.2 Н1](../../08-domain/spec/08.2-domain.norms.md#н1-форма) «Общее для всех форм главы»; набор `domain/keys`
(`keys`, `until`), форма строки `domain/revoked`, её писатели и `prune` — [договор набора ключей домена](keys.md) (разбор
ревью стадии A 8–10, № 13); окно отзыва без связи — P/08.2 Н1.7. Вид токена воркера
и `audience_claim` — объявление вида [P/02.1](../../02-installer/spec/02.1-installer.norms.md) Н1.2б (поздний слой),
утверждения токена — [глава 8.7](../../08-domain/spec/08.7-domain.norms.md). Ссылка «урок N»
в перенесённом тексте — урок М11/N, их адреса теперь: «урок 7» (токен воркера) — P/08.7, «урок 9» (токен человека) —
P/08.4 (разбор ревью стадии B 8–10, № 22); «Н1.x» в шагах — главы P/08.2 (прежде урока М11/2; номера подразделов прежние).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Токен

Из М11/2 Н1.6:

```yaml
token:         <b64url(header)>.<b64url(payload)>.<b64url(sig)>       # ровно три части
  header:      JSON-объект; обязательные alg — строка "EdDSA", kid — строка; прочие поля пропускаются (не отказ);
               выпускающий пишет ровно {alg, kid} в JCS
  payload:     JSON-объект; обязательные: iat, exp — конечные числа, стенные секунды; jti — строка 1–64 [A-Za-z0-9_-];
               kind — непустая строка: person у людей (урок 9), вид манифеста у воркеров (урок 7); прочие поля этим уроком
               пропускаются, кроме поля аудитории вида (P/02.1 Н1.2б audience_claim; разбор ревью стадии B 6–7, № 24) при проверке получателем; выпускающий пишет
               JCS и jti — 16 знаков hex из случайных 8 байт
  sig:         Ed25519 ключа kid набора над ASCII «<header>.<payload>» как пришли
TOKEN_SKEW:    60          # с, допуск часов в обе стороны; часы — стенные часы проверяющего
person:        токен человека: выпускающий (процесс domain при входе, P/08.4 Н1.2) пишет ровно {iss: <домен>, sub: <имя
               человека>, kind: "person", iat, exp, jti}, без aud; exp = iat + TOKEN_LIFETIME; проверяющий прочие поля
               пропускает (п. payload), sub проверяет по форме имени P/08.4 Н1.1 — 1–64 знака без пробельных (White_Space
               Unicode 15.0.0), управляющих и : | ( ) " /, не break-glass — иначе 401 у сторожевой
               (догадка стадии C GP-L01, решение «Архитектора» 2026-10-23)
```

Проверка токена — функция `token` (раздел «Проверка» ниже) у каждой двери, которая принимает токены домена; каждая
такая дверь ДОЛЖНА передавать `expect` ниже, кроме названной без него (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10):

| Проверяющий | Где | `expect` |
|---|---|---|
| сторожевая консоли кластера | [договор сторожевой и передачи](gate-and-pass.md) «Сторожевая» `identity` п. 3; [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3, [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.9 `cluster` | `{kind: person, cluster: null}` |
| сторожевая консоли домена (P/10 Н1.5; право — строка `domain` P/08.4 Н1.5) | тот же договор, `identity` п. 3 | `{kind: person, cluster: null}` |
| процесс `domain`, двери людей | [P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н3 «дверь людей» шаг 2 | `{kind: person, cluster: null}` |
| получатель токена вида — воркер или дверь члена | [P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.5, Н3 «проверить у получателя» | `{kind: <вид>, cluster: <свой кластер>, audience_claim: <из объявления вида>}` |
| процесс `domain`, `POST /domain/revoke` | P/08.4 Н1.2 `revoke` | без `expect`: токен в теле — удостоверение самого себя |
| дверь процесса подсистемы, маршрут с `domain` | [P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.7 `door_admission` `domain`, `role_domain` | `{kind: [<виды маршрута>], cluster: <свой кластер>, audience_claim: {<вид>: <поле из объявления вида>}}` (ADR-0091 доп. (17) п. 9, доп. (18) п. 1, доп. (19) п. 1) |

Дверь токенов воркера (урок 7) токены выдаёт, а не проверяет. Воркер подсистемы на домене токен человека пришедшего
`door.pass` не проверяет: людей проверяет сторожевая консоли домена, источник запроса воркер принимает по роли
`domainconsole` клиента TLS ([P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.6 `door_client`; решение «Архитектора» 2026-10-20 по сверке 3.7). Вид токена и `aud` — урок 7: токен другого кластера или вида
отказывается у получателя, шагами 9–10 этого договора.

## Проверка: `token(keys, revoked, now, token) → ok payload | refused <слово>`

Из М11/2 Н3; `keys` — принятый набор ([договор набора ключей домена](keys.md) «Набор»), `revoked` — строка
`domain/revoked` как прочитана (форма — [договор набора ключей домена](keys.md) «Отзывы»), `now` — стенные секунды
проверяющего:

```
1. revoked есть и не по форме Н1.6 (не {jtis: строка}; запись не «<jti>:<число>»; число — конечное, по грамматике
   JSON без пробелов: `0123`, `1e400`, `+1` — не по форме; добавлено сверкой М11, T2, T3) → refused no_revocations
2. token не строка; не три части; часть не base64url; header или payload не JSON-объект или с повтором ключа;
   header.alg ≠ "EdDSA"; header.kid не строка                                     → refused not_a_token
3. kid ∉ keys.keys, или kid ∈ until и now > until[kid]                           → refused unknown_key
4. подпись не проверяется keys.keys[kid] над ASCII «<header>.<payload>»           → refused bad_signature
5. iat или exp не конечное число, jti не строка по грамматике Н1.6, kind не непустая строка → refused bad_claims
6. now > exp + TOKEN_SKEW                                                         → refused expired
7. now < iat − TOKEN_SKEW                                                         → refused future
8. jti в revoked                                                                  → refused revoked
9. expect есть и kind ≠ expect.kind (строка) или kind не из expect.kind (список)   → refused wrong_kind
10. expect есть, expect.cluster не null и поле аудитории (expect.audience_claim; у списка видов — значение
    отображения для вида, совпавшего на шаге 9; нет записи или нет audience_claim — aud) не список строк или без
    expect.cluster                                                                → refused wrong_audience
11. иначе                                                                         → ok payload
# expect — что ждёт проверяющий (таблица «Токен» выше): вид и свой кластер; у токенов людей кластер — null
# (person без аудитории, урок 9): аудитория не проверяется
```

«Н1.6» в шагах 1 и 5 — М11/2 Н1.6 (теперь P/08.2 Н1.6): форма `domain/revoked` (шаг 1; теперь — [договор набора ключей домена](keys.md) «Отзывы») и грамматика `jti` (раздел «Токен» выше, шаг 5). Форма
`expect` — вход команды `token` ([P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н5): `expect?: {kind: <строка> | [<строка>…], cluster: <член> | null, audience_claim?: <имя
поля — непустая строка, умолчание aud> | {<вид>: <имя поля>}}`. `kind` строкой — один вид, `audience_claim` при нём — строка;
`kind` списком — непустой, без повторов, без `person`, `audience_claim` при нём — отображение, ключи — виды из списка (вид без
записи — `aud`); иное сочетание, `person` в списке, ключ отображения не из списка — не по форме, код 2 (ADR-0091 доп. (18)
п. 1, доп. (19) п. 1). Ключ `cluster` обязателен; `null` допустим только при `kind: person` строкой. `expect`
без ключа `cluster` или с `cluster: null` при ином `kind` — не по форме: это ошибка вызывающего, а не слово отказа
(команда `token` — код 2, P/08.2 Н5). `expect` — закрытая форма `{kind, cluster, audience_claim?}`: незнакомый ключ — тоже
не по форме, код 2 (опечатка `audience_clam` иначе молча вернула бы проверку к `aud`; догадка стадии C DT-G03, решение «Архитектора» 2026-10-23). Умолчания «без `cluster` — аудитория не проверяется» нет: оно ослабляло бы
отсечение по аудитории (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10).

Равенство на границе принимает: `now = exp + 60` — ещё `ok`. `revoked` отсутствует (строки нет) — отзывов нет. Дверь,
у которой `domain/revoked` есть, но не читается хранилищем, отвечает как при `no_revocations`: проверить нечем (503 у
сторожевой, [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3), а не «токен годен».

## Слова отказа

Из М11/2 Н4 (строки о токене):

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токен: `no_revocations` | 503 у сторожевой; отказ двери токенов | вызывающий | ждать читаемой строки |
| токен: `not_a_token`, `unknown_key`, `bad_signature`, `bad_claims`, `expired`, `future`, `revoked`, `wrong_kind`, `wrong_audience` | 401 у сторожевой ([P/06.3](../../06-console/spec/06.3-console.norms.md)); отказ двери токенов (урок 7) | вызывающий | войти заново / получить новый токен; `future` — проверить часы |

У получателя токена вида (P/03.7 Н4) — `wrong_kind`, `wrong_audience` (шаги 9–10). У двери процесса подсистемы, маршрут с
`domain` (P/03.4 Н1.7, Н4): слова шагов 1–8 — 401 (`no_revocations` — 503), нет токена — 401 `not_a_token`; `wrong_kind`,
`wrong_audience` — 403; тело `{error, detail}` (ADR-0091 доп. (14) п. 2, доп. (17) пп. 3, 8).

## Векторы

Пакет [`domain-token`](../vectors/domain-token/README.md) (владелец P/08.2; перенос урока 8): 42 строки — 29 входов команды
`token` приёмки М11/2 (`inputs/token-*.json`, сц. 04–07, 12 — ключ и `until`, форма, граница `exp + 60` и `iat − 60`,
отзыв, `expect`) без изменения байтов; сценарии и входы сняты переносом урока 8 — таблица единственный источник этих
случаев; 3 строки формы `expect` и 10 строк списка видов (ADR-0091 доп. (18) п. 1, доп. (19) п. 1) — по тексту договора.
Реализация проходит их своей функцией, без стенда.

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../../01-store/vectors/jcs/README.md)
урока P/01 (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).

## Соответствие прежним урокам

Из М11/2 (разбор ревью стадии B 3–5, В1): Н1.6 — строка `token` (`header`, `payload`, `sig`), `TOKEN_SKEW` и абзац
«Проверка токена — функция `token`…» (здесь «Токен»; `domain/revoked` — теперь [договор набора ключей домена](keys.md) «Отзывы», `OLD_KEYS` — P/08.2 Н1.6); Н3
«`token(keys, revoked, now, token)`» — шаги 1–11 с комментарием `expect` и абзац о границе (здесь «Проверка»); Н4 — строки
о токене (здесь «Слова отказа»). Часть нормы М11/2-05 (порядок проверки) и М11/2-06 (нечитаемая строка отзывов —
«проверить нечем») — теперь P/08.2-05, P/08.2-06 — по `note` [id-map](../id-map.tsv); читатели — P/03.7-03, P/06.3 Н1.3. Шаги ссылаются на нормы М11/2
(«Н1.6», теперь P/08.2 Н1.6) как на владельца: ссылки и номера шагов прежние, на них ссылаются P/03.7 Н4 и векторы
[`domain-token`](../vectors/domain-token/README.md) (прежде приёмка М11/2 сц. 12).
Правка поведения после переноса: обязательный ключ `cluster` в `expect` (`null` — только при `kind: person`), шаг 10 при
`cluster: null`, таблица проверяющих с их `expect` (сторожевые консолей кластера и домена прежде звали `token` без
`expect`) (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 7; разбор ревью стадии A 8–10).
