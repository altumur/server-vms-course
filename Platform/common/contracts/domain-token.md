# Договор токена домена: форма, `TOKEN_SKEW`, проверка `token` с `expect`, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (5) и доп. (11): общий договор может появиться раньше переноса
урока-владельца, если на него опирается уже перенесённый урок; разбор ревью стадии B 3–5, В1). Владелец — урок М11/2
([нормы](../../../М11_Domain/spec/02-root-keys-and-revocation.norms.md); до переноса — М11/2, после — урок модуля о корне,
ключах и токенах, P/08.2 по записке модуля): процесс `domain` выпускает токены и ведёт набор `domain/keys` и отзывы
`domain/revoked` (М11/2 Н1.2, Н1.3, Н1.6), смысл и выдача остаются у владельца. Читают: сторожевая консоли кластера —
личность по токену ([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3, Н1.8), воркер и дверь члена — получатель
токена вида (глава [P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.5, Н3 «проверить у получателя»), дверь токенов
воркера (М11/7). Перенесено из М11/2 Н1.6 (строка `token` с `header`, `payload`, `sig`, константа `TOKEN_SKEW`, абзац о том,
кто проверяет), Н3 «`token(keys, revoked, now, token)`» (шаги с `expect` и абзац о границе) и строк Н4 о токене без
изменения поведения. Общее для форм М11/2 (hex, канонический base64url, JCS — RFC 8785, ADR-0072, «стенные секунды»,
Ed25519 — RFC 8032, полнота форм JSON, повтор ключа) — [М11/2 Н1](../../../М11_Domain/spec/02-root-keys-and-revocation.norms.md)
«Общее для всех форм урока»; набор `domain/keys` (`keys`, `until`), форма строки `domain/revoked`, её писатели
и `prune` — [договор набора ключей домена](keys.md) (до переноса — М11/2 Н1.2, Н1.6; разбор ревью стадии A 8–10, № 13); окно отзыва без связи — М11/2 Н1.7. Вид токена воркера и `audience_claim` — М11/7 Н1.1. Ссылка
«урок N» в перенесённом тексте — урок М11/N.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Токен

Из М11/2 Н1.6:

```yaml
token:         <b64url(header)>.<b64url(payload)>.<b64url(sig)>       # ровно три части
  header:      JSON-объект; обязательные alg — строка "EdDSA", kid — строка; прочие поля пропускаются (не отказ);
               выпускающий пишет ровно {alg, kid} в JCS
  payload:     JSON-объект; обязательные: iat, exp — конечные числа, стенные секунды; jti — строка 1–64 [A-Za-z0-9_-];
               kind — непустая строка: person у людей (урок 9), вид спеки у воркеров (урок 7); прочие поля этим уроком
               пропускаются, кроме поля аудитории вида (М11/7 Н1.1 audience_claim; разбор ревью стадии B 6–7, № 24) при проверке получателем; выпускающий пишет
               JCS и jti — 16 знаков hex из случайных 8 байт
  sig:         Ed25519 ключа kid набора над ASCII «<header>.<payload>» как пришли
TOKEN_SKEW:    60          # с, допуск часов в обе стороны; часы — стенные часы проверяющего
```

Проверка токена — функция `token` (раздел «Проверка» ниже) у каждой двери, которая принимает токены домена: сторожевая консоли ([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3,
урок 9), дверь токенов воркера (урок 7). Вид токена и `aud` — урок 7: токен другого кластера или вида отказывается там,
после проверки этого урока.

## Проверка: `token(keys, revoked, now, token) → ok payload | refused <слово>`

Из М11/2 Н3; `keys` — принятый набор (М11/2 Н1.2), `revoked` — строка `domain/revoked` как прочитана (форма — М11/2 Н1.6),
`now` — стенные секунды проверяющего:

```
1. revoked есть и не по форме Н1.6 (не {jtis: строка}; запись не «<jti>:<число>»; число — конечное, по грамматике
   JSON без пробелов: `0123`, `1e400`, `+1` — не по форме; добавлено сверкой М11, T2, T3) → refused no_revocations
2. token не строка; не три части; часть не base64url; header или payload не JSON-объект или с повтором ключа;
   header.alg ≠ "EdDSA"; header.kid не строка                                     → refused not_a_token
3. kid ∉ keys.keys, или kid ∈ until и now > until[kid]                           → refused unknown_key
4. подпись не проверяется keys.keys[kid] над ASCII «<header>.<payload>»           → refused bad_signature
5. iat или exp не конечное число, jti не строка по грамматике Н1.6, kind не непустая строка → refused bad_claims
6. now > exp + TOKEN_SKEW                                                         → refused expired
7. now < iat − TOKEN_SKEW                                                         → refused future
8. jti в revoked                                                                  → refused revoked
9. expect есть и kind ≠ expect.kind                                              → refused wrong_kind
10. expect.cluster есть и поле expect.audience_claim (умолчание aud) не список строк или без expect.cluster
                                                                                  → refused wrong_audience
11. иначе                                                                         → ok payload
# expect — что ждёт получатель (P/03.7 Н3 «проверить у получателя»): вид и свой кластер; у токенов людей кластер не
# задаётся (person без аудитории, урок 9)
```

«Н1.6» в шагах 1 и 5 — М11/2 Н1.6: форма `domain/revoked` (шаг 1; теперь — [договор набора ключей домена](keys.md) «Отзывы») и грамматика `jti` (раздел «Токен» выше, шаг 5). Форма
`expect` — вход команды `token` приёмки М11/2 Н5: `expect?: {kind: <строка>, cluster: <член> | null, audience_claim?: <имя
поля — непустая строка, умолчание aud>}`.

Равенство на границе принимает: `now = exp + 60` — ещё `ok`. `revoked` отсутствует (строки нет) — отзывов нет. Дверь,
у которой `domain/revoked` есть, но не читается хранилищем, отвечает как при `no_revocations`: проверить нечем (503 у
сторожевой, [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3), а не «токен годен».

## Слова отказа

Из М11/2 Н4 (строки о токене):

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токен: `no_revocations` | 503 у сторожевой; отказ двери токенов | вызывающий | ждать читаемой строки |
| токен: `not_a_token`, `unknown_key`, `bad_signature`, `bad_claims`, `expired`, `future`, `revoked`, `wrong_kind`, `wrong_audience` | 401 у сторожевой ([P/06.3](../../06-console/spec/06.3-console.norms.md)); отказ двери токенов (урок 7) | вызывающий | войти заново / получить новый токен; `future` — проверить часы |

У получателя токена вида (P/03.7 Н4) — `wrong_kind`, `wrong_audience` (шаги 9–10).

## Векторы

Пакета векторов в `Platform/` нет: случаи — входы команды `token` приёмки М11/2
([README](../../../Source/tests/testdata/acceptance/М11_Domain/02/README.md), `inputs/token-*.json`; сц. 04–07, 12 —

## Соответствие прежним урокам

«Проверка токена — функция `token`…» (здесь «Токен»; `domain/revoked` и `OLD_KEYS` остаются в М11/2 Н1.6); Н3
«`token(keys, revoked, now, token)`» — шаги 1–11 с комментарием `expect` и абзац о границе (здесь «Проверка»); Н4 — строки
о токене (здесь «Слова отказа»). Часть нормы М11/2-05 (порядок проверки) и М11/2-06 (нечитаемая строка отзывов —
«проверить нечем») по `note` [id-map](../id-map.tsv); читатели — P/03.7-03, P/06.3 Н1.3. Шаги ссылаются на нормы М11/2
(«Н1.6») как на владельца: ссылки и номера шагов прежние, на них ссылаются P/03.7 Н4 и приёмка М11/2 сц. 12.
