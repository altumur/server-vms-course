# Договор записи срока и подписи выпускающего: `domain/holder`, функция `record`, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): общий алгоритм нескольких процессов — договор, а
не копии в главах; разбор ревью стадии A 8–10, № 13 / решение 2). Владелец — урок P/08, глава [8.8](../../08-domain/spec/08.8-domain.norms.md) (перенесено из
М11/10 Н1.1, Н3 «record»): процесс `domain` держателя
подписывает выпускающим ключом запись своего срока, документ резервной копии и грант передачи. Проверяют функцией `record`:

| Кто | Где | Виды |
|---|---|---|
| агент члена ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md)) | следование за держателем (P/09.1 Н3 «следовать»), проверка резервной копии хранителем (Н3 «проверить резервную копию»), условие кластера держателя (P/09.1 Н1.4 `holder_cluster`) | запись срока, документ резервной копии |
| процесс `domain` (8.8) | смещение (P/08.8 Н1.6), передача (P/08.8 Н1.7: запись цели, грант), перенос (P/08.8 Н1.8) | три вида |
| консоль кластера ([P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.14; векторы `resolve`) и агент (9.1) | общий документ ([P/08.9](../../08-domain/spec/08.9-domain.norms.md) Н1.2 `document`; Н3 «взять документ» шаг 4 — [P/09.1](../../09-agent/spec/09.1-agent.norms.md)) | общий документ |
| выдача токенов (8.7) | общий документ сценария ([P/08.7](../../08-domain/spec/08.7-domain.norms.md) Н3 шаг 5) | общий документ, проверенный агентом |

Перенесено из М11/10 Н1.1 (строка `domain/holder` и блок `doc`), Н3 «`record(keys, row, виды)`» (абзац о видах и шаги
1–6) и Н4 (слова `record`) без изменения поведения. У владельца остаются: `claim` и `check` записи срока (Н1.1), формы
документа резервной копии (Н1.5) и гранта (Н1.7), выпускающий ключ (`issuing_key_secret`, [P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н1.3), вид «общий
документ» ([P/08.9](../../08-domain/spec/08.9-domain.norms.md) Н1.2 `document`, `signature`). Ссылки в перенесённом тексте: «Н1.x», «Н3» — урока М11/10 (Н1.1, Н1.5, Н1.7 — те же номера главы P/08.8; Н3 «следовать» —
P/09.1 Н3 «следовать», «проверить резервную копию»); «урок N» — урок М11/N, их адреса теперь: «урок 3» (агент носит
отчёты) — P/09.1 Н3 и P/08.3 Н2, «урок 11» (общий документ) — P/08.9 Н1.2 (разбор ревью стадии B 8–10, № 22; Kimi
SB810-07); `keys` — принятый набор ([договор набора ключей домена](keys.md)). Общее для форм — [договор основания домена](domain-founding.md)
«Общие правила форм» (аудит раскладки, Б-03).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Виды документа: закрытый набор резервной копии — `Platform/08-domain/data/backups.form.yaml`, `Platform/08-domain/data/backups.outcomes.tsv`; `Platform/09-agent/data/backup.form.yaml`, `Platform/09-agent/data/backup.outcomes.tsv`; общий документ — `Platform/08-domain/data/shared-docs.form.yaml`, `Platform/08-domain/data/shared-docs.outcomes.tsv`; `Platform/09-agent/data/shared-copy.form.yaml`, `Platform/09-agent/data/shared-copy.outcomes.tsv`; доверенный набор `keys` — `Platform/08-domain/data/keys.form.yaml`, `Platform/08-domain/data/keys.outcomes.tsv`. Времена — `Platform/common/data/codec.tsv`, строка `time` (аудит раскладки, В-46…В-48, Б-27; решение «Архитектора» 2026-10-25).

## Запись срока `domain/holder`

Из М11/10 Н1.1 (форма семьи — `Platform/08-domain/data/holder.form.yaml` (исходы — `Platform/08-domain/data/holder.outcomes.tsv`), `holder.outcomes.tsv`; C04-DEP-OBS-HEARTBEAT-01 — файлы данных, названные договором, в чтении `common`, ADR-0083 доп. (32) п. 1):

```yaml
domain/holder:   {doc: <текст JCS документа>}       # у держателя — пишет процесс domain (claim); у члена — агент (Н3 «следовать»)
  doc:           {domain, term, holder, url, ca?, at, restored_from?, issuer, kid, sig}   # закрытый набор
    domain:      имя домена (P/08.2 Н1.1)
    term:        целое ≥ 1
    holder:      имя члена-держателя
    url:         адрес двери процесса domain держателя — SIGNER_URL окружения этого процесса, без него
                 http://localhost:8445 (стенд одной машины) — туда агенты носят отчёты (урок 3); у
                 держателя из нескольких узлов — адрес, который доходит до любого узла кластера, а не одного сервера
                 (очередь процесса domain — P/08.10 Н1.7; добавлено М11/12)
    ca?:         [<отпечаток>…], 1–2 — центр держателя (P/08.3 Н1.6; ADR-0075 уточнение 2)
    at:          стенные секунды подписи
    restored_from?: {term, rev} — резервная копия, из которой восстановлен этот срок (Н1.5); срок 1 — без поля
    issuer:      hex открытого ключа выпускающего (P/08.2 Н1.3 issuing_key_secret)
    kid:         serial выпускающего — первые 16 знаков hex issuer
    sig:         base64url без «=» подписи Ed25519 выпускающего над UTF-8(JCS(doc без kid и sig))
```

Документ резервной копии (Н1.5) и грант (Н1.7) подписываются так же: `issuer`, `kid`, `sig` — по строкам выше.

## Точка смены `switch`

Перенесено из [P/08.8](../../08-domain/spec/08.8-domain.norms.md) Н1.6 `switch` без изменения поведения (аудит раскладки, решение «Архитектора» 2026-10-25, Б-04):
условие читают процесс `domain` держателя и агент его кластера (договор набора ключей: строки `domain/keys` и
`domain/revoked` агент кластера держателя не пишет, пока кластер держит срок).

```yaml
switch:      у кластера держателя строки domain/keys, domain/revoked, domain/holder, своя domain/break-glass/<кластер> и
             указатель domain/shared пишет процесс domain, а агент этого кластера их не пишет — пока запись domain/holder
             своего хранилища проходит record по набору следования агента (договор набора ключей «Набор следования»; добавлено моделью Quint М11,
             G1) и называет держателем этот кластер (P/09.1 Н1.4 holder_cluster). Условие агента —
             только по записи: «domain/signer не forgotten» — условие процесса domain, domain/signer агенту не открыт; forget
             наступает только после записи чужого большего срока (P/08.8 Н1.6 yields), потому запись «держатель — этот кластер» и забытые
             ключи вместе не бывают. Точка смены одна — запись domain/holder большего срока, прошедшая record: при плановой
             передаче её пишет процесс прежнего держателя (P/08.8 Н1.7 шаг 6), при переносе — агент «следованием» (его
             единственная запись в эти строки до точки). С неё процесс уступает и этих строк больше не пишет, агент пишет
             их как у любого члена. Процесс видит точку при первой своей проверке после неё (проверка — на каждом проходе и
             каждом запросе): окно — до следующей проверки, не дольше прохода; его правки в окне попадают в stranded
             (добавлено моделью Quint М11, SW). У цели — зеркально: claim нового срока (P/08.8 Н1.1) — точка, с неё агент цели их не пишет
             (запись, называющая цель, пришла раньше claim — агент уже не пишет эти строки, их пишет процесс с claim)
```

## Закрытые наборы видов и имя члена

Из P/08.8 Н1.5 `document`, Н1.7 шаг 5 `grant` и P/08.1 Н1.1 `member` без изменения поведения — проверяющему функцией
`record` (шаг 1) нужны закрытые наборы всех трёх видов и грамматика имени члена (разбор ревью стадии B 8–10, № 4; Claude
С-7). Владельцы текста — P/08.8 Н1.5, Н1.7 и P/08.1 Н1.1; смысл полей (`state`, `objects`, секреты, ключ резервной копии)
— там же.

```yaml
backup_doc:   документ резервной копии — JCS {term, rev, holder, at, members, state, objects, raw?, backup_key_rev,
              holder_member_key?, issuer, kid, sig}   # закрытый набор; подпись — как запись срока
grant_doc:    грант передачи — {doc: JCS {grant: "handover", domain, to, from, term, rev, at, issuer, kid, sig}}   # закрытый набор
member_name:  имя члена — CLUSTER его установки: 1–64 знака [a-z0-9-], не пустое; holder, to, from и элементы members —
              имена по этой грамматике
```

## Функция `record`

Из М11/10 Н3 «`record(keys, row, виды)` — запись срока или документ с подписью Н1.1, по порядку»:

`виды` — закрытый набор видов документа, который принимает вызывающий. Этот урок вызывает record с тремя видами шага 1;
глава 8.9 — с одним видом «общий документ» (P/08.9 Н1.2 document; Н3 «взять документ» шаг 4 — P/09.1). Шаги 2–5 общие
(добавлено описью семей).

Предел вложенности JSON — 64, одно число на платформу (глубина JSON тела двери консоли, P/06.1 Н1.4): строка `row` и
текст `doc` разбираются каждый со своим пределом; уровень — объект или массив (скаляр — 0, пустой объект или массив — 1,
как `depth` DIALECT § 6); глубже 64 — `not_a_record` (шаг 1), у доверенного `keys` — вход не по форме, выход 2 (догадка стадии C REC-G02, решение «Архитектора» 2026-10-23).

```
1. row не {doc: <текст>}, doc не JSON-объект закрытого набора одного из видов `виды`; виды этого урока — запись срока
   Н1.1, документ резервной копии Н1.5, грант Н1.7 (вид — по набору ключей; иной документ, в том числе общий документ
   урока 11, — не запись) с типами: term — целое ≥ 1, at — число, holder — имя члена, url — непустая строка, ca — 1–2
   отпечатка без повторов, restored_from — {term, rev}, issuer — hex 32 байт; у документа резервной копии rev —
   целое ≥ 1, members — список имён членов без повторов, state — {<ключ строки>: {<элемент>: <текст>}}, objects —
   объект, raw — {<ключ>: строка base64 RFC 4648 §4 с дополнением} (C08-BACKUP-JSON-99, решение «Архитектора» 2026-10-26), backup_key_rev — целое ≥ 1,
   holder_member_key — hex 32 байт; у гранта grant — "handover", to и from —
   имена членов, rev — целое ≥ 1 (виды и типы — добавлено сверкой М11, H9, H11, H12); у записи срока с term 1 — поле
   restored_from; domain, kid и sig шаг 1 не проверяет по содержимому (любой JSON-тип domain — шаг 2; kid — любая
   строка, sig — любая строка: шаги 3–5) — одно правило для всех видов, в том числе общего документа (догадка стадии C REC-G01, решение «Архитектора» 2026-10-23)
                                                                                 → not_a_record
2. doc.domain ≠ keys.domain, в том числе domain иного JSON-типа (у документа с domain; документ резервной копии его не несёт —
   к домену его привязывает выпускающий, шаги 3–5)                               → another_domain
3. doc.kid ∈ keys.revoked_issuing                                                → revoked_issuer
4. doc.kid ∉ keys.issuing                                                        → unknown_issuer
5. doc.kid ≠ первые 16 hex doc.issuer, или подпись не сходится                   → bad_signature
6.                                                                               → ok {term, holder}
   (у гранта holder — его from: держатель, выдавший грант; у общего документа урока 11 holder нет — ok {term})
```

Доверенный `keys` функция проверяет только формой (поля и типы набора договора набора ключей), без содержимого `kid`, `sig`
и подписи корня — набор уже принят функцией `keys`; не по форме — выход 2 команды `record`, не отказ документа (P/08.8 Н5
`exit`; догадка стадии C REC-G01, решение «Архитектора» 2026-10-23).

## Слова отказа

Из М11/10 Н4: слова `record`: `not_a_record`, `another_domain`, `revoked_issuer`, `unknown_issuer`, `bad_signature`. Что
делает вызывающий с отказом (не следовать, журнал `domain.follow.refused`, `domain.shared.refused`, уступить) — нормы
вызывающего (P/08.8 Н1.6; P/09.1 Н3 «следовать», «взять документ»).

## Векторы

Пакет [`record`](../vectors/record/README.md) (разбор ревью стадии A 8–10, № 13): `shared.tsv` — 8 строк вида «общий
документ» (REC-G01); `cases.tsv` — 31 строка: 3 по C08-BACKUP-JSON-99 (`raw` документа резервной копии: байты `ff7b` — `/3s=`; без дополнения и base64url — `not_a_record`), 1 по C137-SCHEMA-TIME-01 (`until` сверх binary64 — код 2), 3 по REC-TRUSTED-TIME73 (время `until` доверенного набора по канону P/01.1 Н0: строка записи принята, −1 и «1e9» — код 2), 4 по REC-G02 (вложенность 64/65 текста `doc`, строки и `keys`), 3 по REC-G01 (срок 1 с `restored_from`, `domain` числом, `kid` не hex) и 17 — входы команды `record`
приёмки М11/10 (сц. 05) без изменения байтов: три вида документа, чужой домен, отозванный и неизвестный выпускающий,
`kid` ≠ `issuer`, подмена, формы и типы; одна строка — вход не по форме (`@exit 2`; разбор ревью стадии B 8–10, № 22); сценарий и входы сняты переносом
урока 8 — таблица единственный источник этих случаев. Форма функции и коды выхода команды — копия
[P/08.8](../../08-domain/spec/08.8-domain.norms.md) Н5 `record`, `exit` (аудит раскладки, решение «Архитектора» 2026-10-25, Б-14):

```yaml
record:    вход {keys: <документ набора>, row: {doc}}; вывод {result: ok, term, holder} | {result: refused, reason}
exit:      0 — вычислено; 2 — вход не по форме; коды выхода — по принципу словаря «Стенда домена» («Коды выхода команд-векторов»: 2 — форма
           доверенного входа, 0 со словом — документ другого кластера; решение «Архитектора» по сверке М11, H14):
           keys у record — доверенный документ набора главы 8.2 Н1.2 закрытой формы: поля нет (revoked_issuing,
           sig, domain), issuing не список, keys null — 2; подпись набора проверена при записи (функция keys договора набора
           ключей домена), функция её не проверяет — испорченный sig не отказ; у record нет row, лишнее поле, вход не объект — 2; row (null, строка,
           {}, doc не JSON или числом, лишнее поле row) — 0 not_a_record
```
 Участник: пакет
[`follow`](../../09-agent/vectors/follow/README.md) — пакет урока-владельца P/09 (глава 9.1), исполняет он; договор записи срока
там — потребитель: следование зовёт `record` (аудит раскладки, В-49; CM-RECORD-VECTORS-128, решение «Архитектора» 2026-10-25). Пакет `resolve` урока P/06 `record` не зовёт
(вход — значение домена `{term, rev, value}`) — в «Векторах» не числится.

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../../01-store/vectors/jcs/README.md)
урока P/01 (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).
