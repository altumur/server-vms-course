# Договор замка присутствия: файл, кто держит, кто читает, счёт `room`

Общий договор модуля «Платформа» (ADR-0083 доп. (5); разбор ревью стадии A 3–5, № 9). Владелец — ресурс
[P/05](../../05-resource/spec/05-resource.norms.md): он читает замки своей коробки, выводит из них присутствие процессов
воркеров (P/05 Н1.4 `workers`, `running`, `unknown`, `presence`) и счёт `room.<sub>` строки двери (P/05 Н1.4
`door_row`). Держит замок воркер — сторона воркера: глава [P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3
«старт()», шаг 2б; число `room.<sub>` читает контроллер ([P/04](../../04-controller/spec/04-controller.norms.md) Н3
«заказать()»); раскладка корня событий — [P/02.4 Н1.2](../../02-installer/spec/02.4-installer.norms.md) «Канал настройки
и раскладка `PLATFORM_DIR`». Перенесено из М10/8 Н1.4 (`presence_lock`, `room`) и М10/11 Н1.4 (`presence`) без изменения
поведения; вывод слов присутствия из полей пульса ресурса — P/05 Н1.4 `presence`.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Замок

```yaml
presence_lock:  <корень событий>/.workers/<sub>/<экземпляр>.lock   # компоненты — по кодированию имён договора журнала событий
             # («Имена файлов в общих деревьях», event-journal.md); решение «Архитектора», второй пилот, Н-1
             содержимое: JSON {instance, sub, worker, server, pid} — экземпляр, подсистема, имя слота, сервер, pid процесса
             воркер: при старте, до захвата имени (глава P/03.2 Н3 «старт()»), открывает свой файл, пишет содержимое заново (не
             дописывает) и держит исключающий flock всё время жизни процесса; замок отпускает только выход процесса
             ресурс: «известные» воркеры — только по файлам замков, ключ <sub>/<worker> из содержимого; на каждый файл —
             flock без ожидания: взял — процесс мёртв, gone (замок сразу отпустить); занят — runs; файл не читается или
             содержимое не по форме — unknown; у одного <sub>/<worker> несколько файлов — runs, если хоть один занят;
             файл gone ресурс МОЖЕТ удалить, держа его flock; иного источника присутствия (pid-файлы, kill(pid, 0)) нет
presence:   ресурс говорит о процессах своей коробки полями пульса P/05 Н1.4 (`workers`, `running`, `unknown`; слова и их
            вывод — там же, судьба — P/04); как узнаёт — замок присутствия выше
            (<корень событий>/.workers/<sub>/<экземпляр>.lock, flock; второй пилот, Н-1); нечитаемое → unknown (слово
            закрытого перечня P/04: контроллер ждёт его), никогда «ушёл»
```

## Счёт `room`

```yaml
room:      элемент room.<sub> каждой подсистемы каталога, чей файл роли roles/<sub>worker.env (P/02.4 Н1.2) есть на
           коробке, пишется каждой отметкой двери — сколько ещё процессов роли поднимет этот сервер (ADR-0084 п. 2):
           десятичное min(floor(HOST_MEMORY_MB / WORKER_MEMORY_MB) − живые, 98 − живые с номером n ≥ 2), не меньше 0;
           живые — файлы замков присутствия <sub> (presence_lock выше) с занятым flock, по файлам экземпляров, не по
           агрегату running; номер — n имени <prefix>-<сервер>-<n> из содержимого замка (P/03.2 Н1.4, n 2…99 — заказанные);
           файла роли нет — элемента нет; файл роли не разбирается или замок роли unknown — "unknown"; контроллер
           сервер без числа в room.<sub> не выбирает (P/04 Н3 «заказать()») и сам вычитает резервы своих заказов
           (свободно(s), P/04 Н3 «нехватка()»);
           предел схемы: room у каждой роли считается от всей памяти сервера, общий потолок по ролям не делится
           (ADR-0084 доп. (1) Р12)
live:      рядом с каждым room.<sub> — элемент live.<sub>: номера n ≥ 2 живых замков роли, по которым посчитан room.<sub>,
           десятичные через запятую по возрастанию, без повторов, из того же снимка замков; замок без номера (имя не
           <prefix>-<сервер>-<n>) входит в room, не в список; пустой список — ""; room.<sub> "unknown" — live.<sub> нет;
           контроллер без live.<sub> сервер не выбирает (P/04 Н3 «свободно(s)»; ADR-0084 доп. (3) Р14′; разбор ревью
           стадии A 3–5, № 3, 19)
```

## Соответствие прежним урокам

Из М10/8 Н1.4 (стадия B, разбор ревью стадии A 3–5, № 9): `presence_lock` целиком и `room` (у P/05 Н1.4 `room` —
ссылка сюда); из М10/11 Н1.4 — `presence`. Часть нормы М10/8-10 (замок и счёт `room`; P/05-07) — по `note`
[id-map](../id-map.tsv); сторона воркера (шаг 2б «старт()» М10/5) — глава P/03.2, часть М10/5 по id-map урока 3.
