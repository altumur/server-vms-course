# Договор подписи агента: заголовок `X-Agent-Signature`, окна, проверка `agent-sig`, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): общий алгоритм нескольких процессов — договор, а
не копии в главах; разбор ревью стадии A 8–10, № 13 / решение 2). Владелец — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) урока P/09 (Н1.3; источник —
М11/3 Н1.4): агент члена подписывает свои запросы ключом члена
`domain/member-key` (P/09.1 Н1.1). Проверяют:

| Кто проверяет | Двери | Окно |
|---|---|---|
| держатель — процесс `domain` ([P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н2, [P/08.7](../../08-domain/spec/08.7-domain.norms.md) Н1.3) | `POST /api/member/<член>`, `GET /api/carry/<член>`, `POST /api/tokens/<член>/…` | `MEMBER_WINDOW` |
| ретранслятор ([P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н2) | двери ретранслятора для членов за ним; пакет ретранслятора держателю подписан им же | `MEMBER_WINDOW` |
| консоль кластера своего члена ([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3 `identity` шаг 2) | двери единиц, `GET /events?class=alarm` | `UNIT_WINDOW` |

Перенесено из М11/3 Н1.4 (блок `header`, `window`, `replay` и абзац о проверке и словах отказа) без изменения поведения.
Ключ члена, его рождение и закрепление в записи члена — P/09.1 Н1.1 `pub`, `born` (P/09.1-01); что дверь делает после
проверки (стук, 403 ключа, 401) — нормы проверяющих дверей. Ссылки в перенесённом тексте: «Н1.1 pub», «Н2», «Н3» — урока
М11/3; «урок N» — урок М11/N. Их адреса теперь (разбор ревью стадии B 8–10, № 22; Claude М-1, С-7): «Н1.1 pub» — P/09.1
Н1.1 `pub`, малый порядок и «не точка кривой» определены здесь же («Проверка и слова отказа»); «Н2» — P/08.3 Н2; «Н3» у
`agent-sig` — функция этого договора, у `replay` (идемпотентность отчёта) — [договор приёма отчёта](accept.md) шаг 2;
«урок 4» — P/09.2; «урок 6» — P/09.1 Н1.5; «урок 10» — [договор подписи просьбы](ask-sig.md) (P/08.8).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Ключ подписи члена — `domain/member-key`: `Platform/09-agent/data/member-key.form.yaml`, `Platform/09-agent/data/member-key.outcomes.tsv`. Двери, где заголовок проверяют, — OpenAPI `Platform/08-domain/spec/08-domain.api.openapi.yaml` (`POST /api/member`, `GET /api/carry`, `POST /api/tokens`), `Platform/09-agent/spec/09-agent.api.openapi.yaml` (двери ретранслятора), `Platform/06-console/spec/06-console.api.openapi.yaml` (двери единиц, `GET /events?class=alarm`) (аудит раскладки, В-05, В-06; решение «Архитектора» 2026-10-25).

## Подпись

Из М11/3 Н1.4:

```yaml
header:         X-Agent-Signature: <мс>.<sig>
  мс:           стенные миллисекунды Unix агента, десятичное целое без знака и ведущих нулей (0 — сам «0"), ≤ 16 знаков
  sig:          base64url 64 байт подписи Ed25519 ключом члена над UTF-8:
                <METHOD> "\n" <path> "\n" <мс> "\n" <hex sha256 байтов тела>     # тело GET — пустое: sha256 пустой строки
  path:         путь запроса без query, байт в байт как в строке запроса
window:         |now − мс/1000| ≤ окно, в обе стороны; now — стенные секунды проверяющего
  MEMBER_WINDOW: 300        # с — двери держателя (Н2) и ретранслятора (урок 4)
  UNIT_WINDOW:   60         # с — двери единиц консоли члена (P/06.3 Н1.3 identity 2: агент правит единицы своего кластера, урок 6)
replay:         кэша повторов нет: те же байты в окне принимаются снова — норма называет это пределом; дверь отчёта
                идемпотентна по (sent_at, delta_sha256) (Н3), двери единиц — POST по Idempotency-Key, PUT и DELETE — по If-Match (P/06.1 Н2: Idempotency-Key у PUT не читается)
```

## Проверка и слова отказа

Из М11/3 Н1.4:

Проверка — функция `agent-sig` (Н3), слова отказа: `no_signature` (заголовка нет или пуст), `not_a_signature` (нет `.`,
`мс` не по форме, `sig` не base64url без `=` или не 64 байта), `out_of_window`, `bad_signature` (и ключ малого порядка
или не точка кривой, Н1.1 pub). `sig` — каноническое base64url без `=`: ненулевые неиспользованные биты последнего знака —
`not_a_signature` (одна подпись — одна запись заголовка). Тело GET — пустое: GET с непустым телом — `bad_signature` всегда,
какой бы ни была подпись (над пустым телом или над пришедшим), после проверки окна (догадки стадии C AS-01/02, решение «Архитектора» 2026-10-23). Проверки идут по порядку, отказ — первое сработавшее слово: `no_signature` →
`not_a_signature` → `out_of_window` → `bad_signature`; окно раньше криптографии — подпись чужим ключом вне окна даёт
`out_of_window` (решение «Архитектора», разбор ревью стадии B 8–10, № 3, ADR-0083 доп. (15)). Ключ малого порядка — точка `A` открытого ключа, у которой `[8]A` — нейтральный
элемент кривой Edwards25519; не точка кривой — 32 байта, которые не декодируются в точку (RFC 8032 §5.1.3). Другой формы подписи у
этих дверей нет: тройка `X-W2C-Member/Time/Signature` — у просьб без члена в пути (урок 10).

Форма функции — колонка `input` пакета [`agent-sig`](../vectors/agent-sig/README.md) (прежний вход команды `agent-sig`
приёмки М11/3 Н5; сц. 10 снят переносом урока 8): `{key, method, path, body, header, now, window}` →
`{result: ok}` | `{result: refused, reason}`; `path` с «?» — вход не по форме. Тройка урока 10 — [договор подписи
просьбы](ask-sig.md).

## Векторы
