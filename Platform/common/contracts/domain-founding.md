# Договор основания домена: корень, файл восстановления, закрепление, установка, запись срока 1

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): общий алгоритм нескольких процессов — договор, а не копии
в главах; решение «Архитектора» 2026-10-23 по находке «Спецификации» I02-FOUND). Владелец — урок P/08: глава [8.2](../../08-domain/spec/08.2-domain.norms.md) (корень, формы, ключи держателя
и приёма книг) и глава [8.8](../../08-domain/spec/08.8-domain.norms.md) (запись срока). Участники: установщик — команда
«установка домена» ([P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н3) и команды смен, что читают файл
восстановления; процесс `domain` держателя — запись срока 1; агент члена — закрепление при `join`
([P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.1). Перенесено из P/08.2 Н1 («Общее для всех форм главы», «Полнота
форм»), P/08.2 Н1.1 (`recovery_file`, `pin`) и P/02.4 Н3 «установка домена» без изменения поведения; уточнено одно —
куда установка кладёт ключ резервной копии (шаг 4, строка `domain/signer`: её создаёт только установка).

Формы строк, которые этот договор называет, — в семьях урока P/08 (`Platform/08-domain/data/*.form.yaml`) и в общих
договорах, не здесь: `domain/root` — семья `root`; `domain/signer` — `signer`; `domain/book-seal` — `book-seal`;
`domain/keys` — семья `keys` и [договор набора ключей домена](keys.md); `domain/holder` — семья `holder` и [договор записи
срока](record.md). Векторы — [`../vectors/domain-founding/`](../vectors/domain-founding/README.md).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Общие правила форм

Общее для всех форм главы (и глав урока, договоров домена, которые на него ссылаются): hex — строчные `0-9a-f`; base64url
— алфавит RFC 4648 §5 без `=`, запись каноническая: длина ≢ 1 (mod 4), лишние биты последнего знака — нули, повторное
кодирование байтов даёт тот же текст; иначе — не base64url; JCS — RFC 8785 (ADR-0072); «стенные секунды» — секунды Unix
по часам того процесса, который проверяет или подписывает. Ключи подписи — Ed25519 (RFC 8032), открытый ключ — 32 байта;
ключ приёма книг — X25519 (RFC 7748), 32 байта.

Полнота форм. Каждая форма JSON главы — закрытая: поле вне списка — форма не та (что за этим следует, сказано у формы);
обязательное поле обозначено без `?`, необязательное — с `?`, отсутствие необязательного — его умолчание. Порядок ключей
объекта ничего не значит; порядок массивов — у формы, иначе P/01.1 Н0. Повтор ключа в объекте JSON — форма не та. Число —
число JSON (не строка, не `true`/`false`); «целое» — число без дробной части по значению (`2` и `2.0` — одно целое; вывод
пишет его без дроби) в пределах ±(2^53−1); «конечное» — не NaN и не бесконечность. Строки — UTF-8 без нормализации.

## Корень и файл восстановления

Корень — пара Ed25519 домена, одна на всю жизнь домена; что он подписывает, чем опасна кража и кто его не хранит — P/08.2
Н1.1 (`signs`, `limit`, `needed_for`, `not_on`); отпечаток — P/08.2 Н1.1 `fingerprint` (копия — договор набора ключей).

```yaml
recovery_file: JSON {domain, root_key, root_pub}       # закрытая половина корня — только здесь; все три обязательны;
                                                      # лишнее поле или иной тип — файл не читается
  domain:      имя домена, 1–64 знака [a-z0-9-]
  root_key:    hex 32 байт — зерно закрытого ключа Ed25519 (RFC 8032 §5.1.5)
  root_pub:    hex 32 байт — открытый ключ; не тот, что выводится из root_key, — файл не читается (отказ, ничего не меняется)
  place:       у оператора вне каталога платформы целиком (PLATFORM_DIR — в нём и кольцо, договор запечатывания) и вне каталогов хранилища,
               объектов и их копий; режим 0600; путь называет вызов операции (вне PLATFORM_DIR — добавлено сверкой М11, I2);
               обычный файл, не символьная ссылка, ссылки в каталогах пути разрешаются до проверки «вне …», неразрешимый
               каталог — отказ: [договор размещения файлов секретов](secret-files.md) (догадка стадии C DF-G01)
  mode:        режим проверяется при каждом чтении файла (смены Н3, перенос главы 8.8, любая команда, что берёт из него
               root_pub): шире 0600 — отказ, ничего не меняется (добавлено сверкой М11, I3)
```

## Закрепление корня

```yaml
pin:           domain/root {pub, domain}       # у каждого члена, включая держателя; создание-однажды
  pub:         обязателен; hex открытого корня
  domain:      обязателен; имя домена
  not_a_pin:   строка не по форме (лишний элемент, нет поля, не hex) — закрепления нет: keys → no_pin; закрепление не чинится
               само, член принимается заново (глава 8.3)
  when:        держатель — при установке (P/02.4 Н3); член — при приёме оператором по отпечатку (глава 8.3; join — глава 9.1); иначе не пишется
  never:       корень не закрепляется по первому пришедшему набору; закреплённый не заменяется — сменить корень = завести
               домен заново (новые установка и приём каждого члена)
```

## Установка домена

Команда оператора, один раз на домен (владелец команды — P/02.4 Н3 «установка домена»; имя и аргументы — P/02.4 «Решает
реализация» п. 8).

```
1. хранилище кластера-держателя отвечает, кольцо (P/06.2 Н1.2) читается; иначе отказ, ничего не записано
2. domain/keys или domain/root уже есть                               → отказ, ничего не меняется (domain/root —
   добавлено сверкой М11, I1: установка поверх чужого закреплённого корня застряла бы)
3. новый корень; файл восстановления создаётся первым, только если пути нет, режим 0600,
   вне PLATFORM_DIR и каталогов хранилища (place — «Корень и файл восстановления») → иначе отказ, в хранилище ничего не записано
4. ключи держателя (ключ токенов, выпускающий) и ключ резервной копии при backup_key_rev 1 ([договор ключа резервной копии
   домена](domain-backup-key.md)) → domain/signer, секреты — конвертами кольца (форма — семья signer)
5. новое зерно → domain/book-seal {seed_secret} конвертом кольца
6. набор rev 1 (keys = {kid: ключ токенов}, current, issuing = [serial], revoked_issuing = [], book_seal) подписан
   корнем → domain/keys создание-однажды
7. domain/root {pub, domain} создание-однажды (держатель — тоже член)
8. запись срока 1 — «Запись срока 1» ниже (её подписывает выпускающий, не корень; пишет процесс domain держателя)
```

Интерфейс шага 8 до главы 8.8: установка без главы 8.8 исполняет шаги 1–7 и на этом успешно кончается; запись срока
(`domain/holder`) без главы 8.8 никто не читает: держатель в списке членов — [P/08.3](../../08-domain/spec/08.3-domain.norms.md)
Н3 «держатель в списке», ответ держателя без `holder` — P/08.3 Н1.5. Глава [8.8](../../08-domain/spec/08.8-domain.norms.md)
добавляет шаг 8: запись срока 1 пишет процесс `domain` держателя после установки («Запись срока 1»).

Установка, прерванная до шага 6, повторяется после того, как оператор уберёт файл восстановления: члены ещё ничему не
верят, строки шагов 4–5 перезаписываются. Процесс `domain` домена не основывает — [P/08.2](../../08-domain/spec/08.2-domain.norms.md)
Н3 «процесс `domain` домена не основывает»; холодный старт — P/08.2 Н3 «холодный старт».

## Запись срока 1

```yaml
claim_1:     процесс domain держателя при первом старте после установки пишет domain/holder {doc} (P/08.8 Н1.1 claim;
             писатель строки — только domain, установщик её не пишет): doc {domain, term: 1, holder, url, ca?, at, issuer,
             kid, sig} по договору записи срока — domain из domain/root, holder — имя члена-держателя, url — SIGNER_URL
             (без него http://localhost:8445), ca — отпечатки центра держателя (P/08.3 Н1.6), at — стенные секунды подписи,
             restored_from нет; issuer, kid, sig — выпускающий из domain/signer (issuing_key_secret); равная лежащей не
             пишется; затем держатель вносит себя в список членов (P/08.3 Н3 «держатель в списке»)
```
