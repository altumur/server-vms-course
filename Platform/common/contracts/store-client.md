# Договор клиента хранилища: адрес, запрос, ответ, исходы и что делать с каждым

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): клиент хранилища — у всех процессов платформы, договор,
а не копии в главах; догадка стадии C SC-WIRE78-G01 / C08-SDK-06, решение «Архитектора» 2026-10-25). Владелец — глава
[P/01.1](../../01-store/spec/01.1-store.norms.md). Участники — все процессы, которые говорят с хранилищем дверью P/01.1:
консоль, контроллер, воркер, ресурс, процессы домена, агент, установщик.

Перенесено из P/01.1 (сторона вызывающего: Н1, Н2, Н2.1, Н3, Н4 «Что делает вызывающий») без изменения поведения; сторона
сервера (разбор, порядок проверок, операции, память повторов, коды) остаётся в P/01.1 и [P/01.3](../../01-store/spec/01.3-store.norms.md),
P/01.1 — ссылкой сюда.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Провод — контракт двери хранилища `Platform/01-store/spec/01-store.api.openapi.yaml`
([OpenAPI](../../01-store/spec/01-store.api.openapi.yaml); входит в чтение `common` по ADR-0083 доп. (33) п. 1): маршруты
`GET /v1/get?key=`, `GET /v1/list?prefix=`, `POST /v1/write` (`Cmd`: `put` | `delete`), схемы `Key`, `Row`, `Listing`,
`Cmd`, `Written`, `Fault`. Строка, условие `cas`, страж `guard`, условия времени `not_after`/`not_before` и `id` записи —
схемы `Row` и `Cmd` того же OpenAPI (P/01.1 Н1; клиент пишет по ним; аудит раскладки, Б-05).

## Адрес

```yaml
address:   PLATFORM_STORE процесса (договор файла окружения «Переменные окружения»): configstore:///run/configstore/<роль>.sock — HTTP/1.1 с JSON-телами через
           Unix-сокет роли; личность — сокет, в который пришло соединение (P/01.2 Н1.1 identity); file:// и memory:// —
           хранилище в процессе той же реализации (профиль «вся коробка — одна реализация»), семантика та же, провода нет;
           иных адресов у клиента нет — http(s) не вводится (SC-WIRE78-G01, ответ «Архитектора» 2026-10-25 (1))
```

## Запрос

```yaml
query:     key и prefix — application/x-www-form-urlencoded (P/01.1 Н2.1): «+» ключа передаётся как %2B, «%» — как %25;
           параметр — один раз; prefix перечисления СЛЕДУЕТ кончать на «/» (testsub/count совпал бы и с testsub/counters/…)
id:        клиенту СЛЕДУЕТ ставить id на каждую запись — 32 шестнадцатеричных знака случайности (1–64 строчных hex, P/01.1
           Н1); null — не по форме (не равен отсутствию)
cas:       нет поля или null — безусловно; "" — только пока строки нет; <версия> — только пока версия ровно эта
guard:     {key, index}: index "" — страж отсутствует; права на строку-страж — права чтения вызывающего
time:      not_after, not_before — числа JSON записью «Время в строке» (Platform/common/data/codec.tsv строка time; P/01.1 Н0), конечные, ≥ 0
limits:    ключ — не больше 1024 байт UTF-8 полного ключа (реализация на файлах МОЖЕТ меньше — её описание); вес items —
           не больше 524288 байт (сумма длин ключей и значений); тело POST /v1/write — не больше предела чтения тела,
           названного в описании реализации хранилища (у демона — -max-body, умолчание 1 МиБ, P/01.3 Н1.3)
```

## Ответ

```yaml
forms:     формы ответов закрыты (P/01.1 Н2; контракт — раздел «Форма»): читаемая строка {items, index}; отсутствующая {items: null, index: ""};
           повреждённая {items: null, index, unreadable: true}; перечисление {keys}; запись или удаление {index, again?};
           отказ Fault {kind, error, поля своей строки P/01.1 Н4}
index:     версия непрозрачна: клиент сравнивает её только на равенство, не разбирает и не упорядочивает; провод —
           десятичное число без знака и ведущих нулей, до 20 цифр, строкой JSON
unreadable: повреждённая строка существует и имеет версию: cas по этой версии и страж по ней проходят (P/01.1-17); это не
           отсутствие строки
again:     again: true — ответ сохранённого повтора того же id: запись уже была применена, состояние не менялось
```

## Исходы и что делает клиент

Слова и коды — P/01.1 Н4 (закрытый список); текст `error` не нормируется.

| Исход | Код, `kind` | Что делает клиент |
|---|---|---|
| ключ не по правилам; запрос не по форме; нет маршрута | 400 `badkey`, 400 `badrequest`, 404 `badrequest` | ничего: ошибка кода |
| личность не допускается; прав нет | 403 `forbidden` | исправить личность или доверие; прав нет — ошибка развёртывания |
| версия не та, что в `cas` | 409 `conflict`, `index` — версия сейчас | перечитать, применить своё поверх, повторить |
| время приёма позже `not_after` | 409 `expired` | не повторять той же записью; новую решает вызывающий по своей норме |
| время приёма не позже `not_before` | 409 `early` | не повторять той же записью; новая запись — на следующем шаге |
| страж не на той версии | 412 `guard`, `key`, `index` | не повторять: перечитать условие (слот) и заново решить, есть ли право писать |
| служебная `op: floor` (только admin-сокет, P/01.3 Н2): новое значение не больше нынешнего | 409 `refused` | ничего: пол уже не ниже (P/01.3 Н1.3); исход — `refused` по форме операции (C01-REFUSED-OUTCOME-01) |
| строка тяжелее потолка; тело больше предела | 413 `toolarge`, `limit`, `size?` | ничего: тяжёлое — в объект (blob); тело — уменьшить, сравнивать с пределом тела |
| операция не сделана (нет лидера, блокировка, предел соединений) | 503 `unavailable`, `Retry-After?` | повторить на следующем шаге цикла (при `Retry-After` — не раньше срока); держать, что держишь |
| исход записи неизвестен | 503 `ambiguous` | повторить только с тем же `id`; кому важно — сначала прочитать |

```yaml
outcome:   исход(операция, ответ) для клиента: ответ по закрытой форме своей операции — читаемая строка → row,
           отсутствующая → absent, повреждённая → unreadable, перечисление → listing, запись или удаление → written
           (again: true — тоже written); Fault — его kind; no_reply ниже — unavailable (get, list) | ambiguous (write)
no_reply:  обрезанный, нечитаемый (не по закрытой форме ответа) или не пришедший ответ, отказ в соединении — для чтения и
           перечисления: unavailable, для записи и удаления: ambiguous; не «нет» и не исключение, роняющее цикл
wait:      предел чтения ответа и срок ожидания ответа — решает реализация клиента и называет их в своём описании; предел —
           не меньше наибольшего ответа, который хранилище вправе отдать по P/01: P/01 числа не называет (строка — вес items
           до 524288 байт, в JSON с экранированием больше; перечисление числом строк не ограничено), поэтому предел
           клиента не меньше ответа чтения строки на потолке веса и перечисления его хранилища; превышение предела или
           срока — no_reply: исход неизвестен, запись повторяется только тем же id (SC-WIRE78-G01, ответ «Архитектора» 2026-10-25 (2))
retry:     после ambiguous повтор безопасен только с тем же id: применилась первая — повтор отвечает её ответом (again);
           нет — применяется как первая; повтор тем же id с иным содержимым — 400 badrequest
memory:    хранилище помнит id не меньше двух минут и не меньше 50 000 записей с id (P/01.1 Н3 «Повтор по идентификатору»);
           забытый повтор применяется как новая запись — поэтому cas у каждой записи, которая имеет значение
```

## Векторы

## Соответствие прежним урокам

Из P/01.1 Н1 (поля `id` note, `index` note, `cas`, `guard`), Н2 (адрес, формы ответов, повреждённая строка), Н2.1
(кодирование query), Н3 «перечислить» (prefix на «/»), «записать» (порядок для вызывающего, повтор), «Повтор по
идентификатору», Н4 (столбец «Что делает вызывающий», абзац об обрыве); у них — ссылки сюда.
