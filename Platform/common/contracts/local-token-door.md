# Договор местной двери токенов агента: сокет роли, личность соединения, тело, ответ, отказы

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): общий договор может появиться раньше переноса
урока-владельца; разбор ревью стадии A 8–10, № 1 / решение 1). Владелец — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) урока P/09 (Н1.6,
P/09.1-10; источник — М11/7 Н1.2): агент члена слушает местную дверь и передаёт просьбу
держателю. Участник — воркер, глава [P/03.7](../../03-worker/spec/03.7-worker.norms.md) Н1.5: он просит токен этой дверью.
Юниты сокетов — [P/02.4 Н1.1](../../02-installer/spec/02.4-installer.norms.md); переменная `AGENT_TOKEN_DIR` — в жизненных
циклах [агента](../../09-agent/lifecycle.md) и [воркера](../../03-worker/lifecycle.md). Дверь держателя, выдача и
утверждения токена — глава [P/08.7](../../08-domain/spec/08.7-domain.norms.md) (Н1.3, Н1.4, Н3); форма токена — [договор токена домена](domain-token.md).

Перенесено из М11/7 Н1.2 (блок `door`, `body`, `request`, `TOKEN_BODY`, `answer`, `no_queue`, `TOKEN_WAIT`) и строк Н4 «у
агента» без изменения поведения. Раздел «Сокет роли» — правка поведения (решение «Архитектора» 2026-10-20, ADR-0083 доп.
(13)): прежде транспорт и порт были выбором реализации (М11/12 Н1.8 `local_door`, М11/12 «Решает реализация» п. 3, М11/7
«Решает реализация» п. 1). ADR-0080 п. 2 («механика стороны» решает реализация) для этой двери не действует: дверь
соединяет процессы разных реализаций на одной коробке, и свидетели уже расходятся в имени сокета.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Сокет роли

Решение «Архитектора» 2026-10-20 (разбор ревью стадии A 8–10, решение 1):

```yaml
transport:   на коробке — Unix-сокет потока (SOCK_STREAM), по нему HTTP/1.1 двери «Дверь» ниже; другого транспорта на
             коробке нет
address:     <AGENT_TOKEN_DIR>/<роль>.sock — по сокету на каждую роль воркеров каталога манифестов (<роль> — <sub>worker);
             плоско, подкаталогов нет
AGENT_TOKEN_DIR: каталог сокетов местной двери; умолчание /run/w2c/domainagent; задают юнит агента и юнит воркера одним
             значением (P/02.4 Н1.1, Н1.2); на стенде — раннер
identity:    роль соединения — роль сокета, в который оно пришло; другой личности у местной двери нет (роль в теле не
             называется, Н1.2 ниже)
group:       сокет <роль>.sock — режим 0660, владелец root, группа — группа роли воркера (<dep>-<роль>, P/02.4 Н1.1
             users_groups); группу задаёт SocketGroup= юнита сокета, агент получает сокет готовым и в группах ролей
             воркеров не состоит — как демон хранилища (P/01.3 Н1.3 sockets, P/02.4 Н1.1 users_groups rule)
units:       w2c-domainagent-token-<роль>.socket — по юниту на роль: ListenStream=<AGENT_TOKEN_DIR>/<роль>.sock;
             FileDescriptorName=token-<роль>; SocketUser=root; SocketMode=0660; SocketGroup=<группа роли>;
             Service=w2c-domainagent.service (P/02.4 Н1.1)
inherit:     унаследованные сокеты (протокол sd_listen_fds: LISTEN_FDS, LISTEN_FDNAMES) агент берёт по FileDescriptorName;
             сокет, которого не передали, агент создаёт сам: <AGENT_TOKEN_DIR>/<роль>.sock, режим 0660, группа процесса
client:      воркер соединяется с <AGENT_TOKEN_DIR>/<W2C_ROLE>.sock своего юнита; другого адреса не ищет
in_process:  агент в процессе платформы у кластера из одного — вызов, а не дверь (P/09.1 Н1.11 tokens; раздел «Вызов в
             процессе»): сокета нет
```

**Открытый вопрос — воркер на другом сервере кластера.** Местная дверь по TCP с сертификатом роли (ADR-0075) для воркера,
у которого агент своего кластера — на другом сервере, до стенда не нормируется; место — [P/09.1 Н5](../../09-agent/spec/09.1-agent.norms.md#открыто)
«Открыто» (план переноса урока 9, В1). Пока вопрос открыт, порты 8444–8447 домена такой двери не занимает ([P/02.4 Н1.12](../../02-installer/spec/02.4-installer.norms.md)).

## Дверь

Из М11/7 Н1.2:

```yaml
door:       POST /tokens/<sub>/<вид> у агента своего кластера; личность соединения — роль воркера одним из способов
            P/02.4 Н1.6: сокет роли на коробке или сертификат роли (ADR-0075) в кластере; роль в теле не называется
body:       {request_id, ref, by?} — request_id 1–64 [A-Za-z0-9_-]; ref, by — непустые строки; больше TOKEN_BODY — 413
request:    заголовок Transfer-Encoding в запросе (в том числе chunked вместе с Content-Length) — 400; <sub> пути не манифест
            каталога — 404 у агента, к держателю запрос не идёт (вид не объявлен манифестом — решает держатель, 403
            not_granted); добавлено сверкой М11, T7, T8
TOKEN_BODY: 4 KiB          # предел тела клиента у местной двери агента; меряются байты тела, как пришли
answer:     200 {request_id, token, exp} — только этому соединению; иное — код и тело держателя как пришли
no_queue:   агент держит запрос, пока держатель не ответил (не дольше TOKEN_WAIT); не ответил — 503 {error: "unavailable"};
            дорога через ретранслятор: ретранслятор ответил 502 did not answer (держатель ему не ответил) или сам не ответил —
            тоже 503 {error: "unavailable"}, не 502 ретранслятора (решение «Архитектора» 2026-10-20 по вопросу коммита 9)
            (Н2: до держателя не дотянуться), воркер просит заново; очереди ответов нет
TOKEN_WAIT: 10          # с
```

«Сертификат роли в кластере» строки `door` — открытый вопрос раздела «Сокет роли»; «Н2» строки `no_queue` — P/09.1 Н2.
HTTP-форма двери — [OpenAPI урока 9](../../09-agent/spec/09-agent.api.openapi.yaml), тег `local-door`, `/tokens/{sub}/{kind}`.

## Отказы

Из М11/7 Н4 (строки «у агента»):

| Слово | Код | Когда |
|---|---|---|
| — | 401 / 404 / 400 | у агента: личности роли нет / нет маршрута / тело не по форме Н1.2 |
| `invalid token reply` | 502 | у агента: `m1` не открылся, не тот `request_id`, `exp ≤ now` |
| `unavailable` | 503 | у агента: вверх не ответили за TOKEN_WAIT — держатель или ретранслятор; 502 `did not answer` ретранслятора — тоже 503 (`no_queue`; решение «Архитектора» 2026-10-20 по вопросу коммита 9) |

413 местной двери (тело больше `TOKEN_BODY`) — строка [P/08.7](../../08-domain/spec/08.7-domain.norms.md) Н4 о 413 (общая с дверью держателя); код и тело держателя,
переданные «как пришли», — P/08.7 Н4. Ответ держателя открывает агент ([P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.6 `agent`; `m1` — [P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н1.5 и [договор конвертов домена](domain-envelopes.md)).

## Вызов в процессе

Из М11/12 Н1.3 `tokens` (норма — [P/09.1 Н1.11](../../09-agent/spec/09.1-agent.norms.md), P/09.1-14; решение «Архитектора»
по планам переноса 8–10, п. 4: договора библиотеки у агента нет). Строки `call`, `differs` — прочтение М11/12 Н1.3 «в
процессе — вызов, а не дверь»: прежний хвост «без очереди, TOKEN_WAIT и 503 …» читался и как снятие отказов двери
(разбор ревью стадии B 8–10, № 2):

```yaml
in_process:  кластер из одного МОЖЕТ держать агента в процессе платформы без комплекта роли domainagent (P/09.1 Н1.11 where);
             местная дверь токенов тогда — вызов, а не дверь: сокета нет («Сокет роли» in_process)
role:        роль просящего — роль, с которой его компонент запущен в процессе, а не слово запроса; другой личности у
             вызова нет (как identity «Сокета роли»: роль в теле не называется)
call:        тело, ответ и отказы вызова — те же, что у двери: тело {request_id, ref, by?}, больше TOKEN_BODY — 413
             («Дверь» body); ответ 200 {request_id, token, exp} — только этому вызову, иное — код и тело держателя как
             пришли (answer); вверх не ответили за TOKEN_WAIT — 503 {error: "unavailable"}, очереди ответов нет (no_queue);
             ответ держателя не открылся, не тот request_id, exp ≤ now — 502 invalid token reply («Отказы»)
differs:     отличие от двери одно — нет сокета и нет личности соединения (ни сокета роли, ни сертификата роли): роль
             просящего — роль его компонента (role выше)
rights:      тот же оценщик P/01.2 по роли каждого компонента процесса: один процесс — не одна роль, у каждого ключа один
             писатель (ADR-0032)
participant: воркер-компонент того же процесса — участник, как у двери (P/03.7 Н1.5); какие компоненты живут в процессе и с
             какими ролями — P/09.1 «Решает реализация» п. 9
```

## Соответствие прежним урокам

Из М11/7 (разбор ревью стадии A 8–10, № 1 / решение 1): Н1.2 целиком (здесь «Дверь»; в М11/7 — указатель) и строки Н4
«у агента» — 401/404/400, 502 `invalid token reply`, 503 `unavailable` (здесь «Отказы»). Из М11/12 Н1.8 — строка
`local_door` (порты 8444–8447 не занимать; здесь «Открытый вопрос»); прежние «выбор реализации» и умолчание TCP `8448`
сняты решением 1. Норма — P/09.1-10 (М11/7-02; `note` [id-map](../id-map.tsv)); участник — P/03.7-04. Из М11/12
Н1.3 `tokens` — раздел «Вызов в процессе» (решение «Архитектора» по планам переноса 8–10, п. 4).
Векторов у договора нет: дверь проверяют сц. 01, 02 [приёмки главы 8.7](../../08-domain/acceptance/7/README.md) (М11/7-02 → P/09.1-10).
