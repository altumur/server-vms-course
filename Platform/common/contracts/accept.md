# Договор приёма отчёта: функция «принять» (`accept`) — поколение, метка, дороги

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): общий алгоритм нескольких процессов — договор, а
не копии в главах; разбор ревью стадии A 8–10, № 13 / решение 2). Владелец — урок P/08, [глава 8.3](../../08-domain/spec/08.3-domain.norms.md): процесс `domain` держателя принимает
публикацию члена на `POST /api/member/<член>` после подписи. Участник — ретранслятор
([P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н2): его дверь принимает члена этой функцией над своей
памятью; пакет ретранслятора держатель принимает ею же с `via` = ретранслятор ([P/08.3](../../08-domain/spec/08.3-domain.norms.md)
Н3 «держатель на POST /api/relay»).

Перенесено из М11/3 Н3 «`принять(mark, stored, body, via, heard_ago)`» (абзац о `via` и `heard_ago`, шаги 0–7, абзац о
`sent_at`, ответе и сбое) без изменения поведения. Формы, на которые функция опирается, повторены здесь, чтобы держатель,
ретранслятор и агент исполняли договор без норм 8.x (разбор ревью стадии B 8–10, № 4, № 6; ADR-0083 доп. (15); Claude
С-3, С-4, С-6, П-2; Kimi SB810-01): поколение, метка, `MARK_REFRESH`, `BODY_LIMIT` — раздел «Поколение, метка, пределы»
(из [P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н1.3, Н1.3а); публикация, `member_objects`, поля вне дельты,
`ready` — раздел «Публикация члена» (из [P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.2 и P/08.3 Н1.6 `form`);
поле `every` ответа — раздел «Ответ `carry`: `every`» (из P/08.3 Н1.5); форма функции, вывод и код выхода 2 — раздел
«Форма функции» (из М11/3 Н5, М11/4 Н5). Владельцы текста остаются прежними (P/08.3, P/09.1) и ссылаются сюда; значения
не меняются. Прочие поля ответа `carry` — раздел «Ответ `carry`»; потолок целого `whole` — [P/08.10](../../08-domain/spec/08.10-domain.norms.md)
Н1.5. Ссылки в перенесённом тексте: «Н1.2» — раздел «Публикация члена» (P/09.1 Н1.2); «Н1.3» — раздел «Поколение, метка,
пределы» (P/08.3 Н1.3); «Н1.5» — раздел «Ответ `carry`»; «Н2» — P/08.3 Н2; «урок 4 Н1.3» — раздел «Поколение, метка, пределы»
`ROAD_QUIET` (P/08.3 Н1.3а).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Поколение, метка, пределы

Из P/08.3 Н1.3 (`generation`, `whole`, `delta`, `reported`, `MARK_REFRESH`, `BODY_LIMIT`) и Н1.3а (`ROAD_QUIET`) без
изменения поведения; `REPORT_EVERY` — раздел «Ответ `carry`: `every`»:

```yaml
generation:     domain/members/<член>/reports/<rev>   # объект держателя (P/05 Н1.1): целое поколение, JCS
  whole:        {sent_at, objects, key, keys_rev?, pinned?, outcomes?}   # objects — все объекты члена после применения
                изменения; outcomes — P/09.1 Н1.5: смена исходов — новое поколение, агент шлёт поле в каждой
                публикации, пока строка domain/outcomes не пуста; нет поля — исходов нет
delta:          domain/members/<член>/reports/<rev>.delta     # байты тела публикации как получены — то, что подписал агент
reported:       domain/members/<член>/reported               # объект-метка; единственная граница принятого
                # две части: поля поколения пишет только generation (шаг 7); поля последнего принятого запроса — каждый
                # приём с записью метки (шаги 6, 7)
  # поля поколения
  rev:          целое ≥ 1 — номер поколения; выдаёт держатель: +1 на принятое изменение
  sha256:       hex sha256 байтов generation — sha256 от JCS целого whole
  base:         rev, против которого пришло изменение; 0 — пришло целое
  delta_sha256: hex sha256 байтов delta (при base 0 — тела целого, как пришло)
  signature?:   заголовок X-Agent-Signature прямого отчёта, создавшего поколение, как пришёл; через ретранслятор поля нет;
                via — поле последнего запроса, поэтому метка без signature и без via законна: поколение пришло через
                ретранслятор, затем прямой heard
  key, keys_rev?, pinned?: из публикации
  # поля последнего принятого запроса
  sent_at:      sent_at публикации; received_at — стенные секунды держателя приёма
  request_sha256: hex sha256 байтов тела этого запроса, как пришло; повтор узнаётся по (sent_at, request_sha256)
  via?:         ретранслятор — дорога запроса
  stale:        из публикации при каждом приёме, включая «слышал» (шаг 6); нет в публикации — []
  sign_failures?: из публикации при каждом приёме с записью метки, как stale; поколения не создаёт и метку само не
                освежает; нет в публикации — поля нет
keep:           два последних поколения и их delta; старше и выше метки — убираются следующим приёмом
MARK_REFRESH:   22.5        # с = LOST_AFTER/2 по монотонным часам держателя
BODY_LIMIT:     16 MiB      # предел тела двери держателя и ретранслятора: больше — 413, тело не читается дальше; он же —
                            # предел JCS целого шага 4а и целого, которое агент не шлёт (P/09.1 Н1.2 body)
ROAD_QUIET:     15          # с, монотонные часы держателя: три прохода агента (REPORT_EVERY 5); дольше — прежняя дорога молчит
```

Метка — граница принятого: объект с номером не выше `reported.rev` неизменяем; объект выше — ничей: не читается, не
переносится, не держит номер, следующий приём пишет поверх. Читатели берут `reported.rev` и читают только объект этого
поколения; метка без объекта или объект не с её `sha256` — член `silent`, никогда не смесь (читатели — P/08.1, P/08.5,
P/08.8).

## Публикация члена

Из P/09.1 Н1.2 (`publication`, `out_of_delta`, `member_objects`, `ready`) и P/08.3 Н1.6 `form` без изменения поведения
(разбор ревью стадии B 8–10, № 4; Claude С-6): тело `POST /api/member/<член>`, которое агент шлёт (P/09.1), а держатель и
ретранслятор принимают функцией «принять». Как агент собирает объекты (`change`, `fresh`, вклады в книги, предел тела
агента) — P/09.1 Н1.2; формы `tls_ca`, `tls_ca_certs` у члена — [договор сертификата роли](role-certificate.md); их
приём держателем (`on_accept`) — P/08.3 Н1.6; `members_rev` — раздел «Список членов отставшему»; `sign_failures` — P/09.1 Н1.12.

```yaml
publication:    тело POST /api/member/<член> — JSON-объект, закрытый набор:
  sent_at:      конечное число — стенные секунды агента в момент отправки
  objects:      {<ключ объекта>: <JSON-значение объекта>} — что изменилось против base (целое при base = 0)
  base?:        целое ≥ 0 — rev поколения у держателя, против которого изменения; нет или 0 — тело целое
  deleted?:     [<ключ объекта>…] — ключи, которых больше нет против base; только при base > 0
  key:          hex ключа члена — тот, что в domain/member-key
  keys_rev?:    rev набора domain/keys, который член держит (нет — набора нет)
  stale?:       [<ключ пульса>…] — пульсы <sub>/heartbeats/<воркер> копии, которые не менялись дольше LOST_AFTER (45 с)
                по монотонным часам агента; по возрастанию; нет — пусто. Вне дельты: не входит в whole и не порождает
                поколения
  pinned?:      отпечаток domain/root члена (нет — не закреплён)
  outcomes?:    {<id>: <исход>} — исходы правок домена, P/09.1 Н1.5 (ключ ≠ id внутри исхода — исход не засчитывается,
                P/08.6 Н1.6 settle);   tls_ca?, tls_ca_certs? — договор сертификата роли;
                sign_failures?: {domain?: n, console?: n}, n — целое платформы 1 … 9007199254740991 (потолок целого P/08.10),
                целым числом JSON; составное или неизвестное имя, иное n — не по форме (догадки стадии C ACC-FORM-31-01,
                ACC-G01-COUNTER-31-01, решение «Архитектора» 2026-10-23) (запросы, которые агент с запуска не отправил, не
                смог подписать: domain — держателю или ретранслятору, console — правка своей консоли; нет ни одного — поля нет;
                P/09.1 Н1.12; догадка стадии C ACC-G01, решение «Архитектора» 2026-10-23);
                members_rev? — раздел «Список членов отставшему» ({term, rev} списка, который член держит; вне дельты)
out_of_delta:   поле вне дельты — закрытый перечень формы публикации: stale, tls_ca, tls_ca_certs, sign_failures, members_rev;
                поля, которого нет в публикации P/09.1 Н1.2, — тело не по форме, 400 not_a_publication (ответ «Архитектора» 2026-10-25 (аудит раскладки, вопрос T5a)); поле вне дельты не по форме
                своей нормы — поле не взято, журнал держателя, отчёт принимается, как tls_ca ниже; stale — ключи
                без повторов, повтор — поле не взято
tls_ca_form:    в форме публикации tls_ca и tls_ca_certs — списки строк любой длины; не список строк — поле не взято
                (out_of_delta); всё прочее — длина, повтор, не 64 строчных hex, не PEM, не CA:true, не сходится — проверка
                держателя on_accept (P/08.3 Н1.6): ничего не меняется, журнал domain.member.ca.refused, отчёт принимается
member_objects:                               # что агент несёт и что держатель хранит; прочее держатель отбрасывает молча;
                                              # ключ сравнивается с перечнем точно, не по началу и не подстрокой
  <sub>/heartbeats/<воркер>:  пульс P/03.4 Н1.1 каждого манифеста каталога с domain.ref
  <sub>/snapshot/<шард>:      шард снимка P/04 Н1.3а каждого такого манифеста
  прочие семьи (догадка стадии C ACC-G01, решение «Архитектора» 2026-10-23; P/09.1 — откуда перенесено):
    reports:                  domain.reports: [<семья>/…] манифеста (элемент — префикс семьи с конечной «/») — объекты
                              <sub>/<семья><имя> члена как есть; книга их не читает (P/09.1 Н1.2)
    вклады:                   objects["<sub>/<строка>[/<слот>]"] = {<item>: <объект входа>} — строки вкладов книг domain.books
                              (P/02.1 Н1.2б); что агент берёт в отчёт (фильтр живости слота, конверты секретов) — P/09.1 Н1.2
                              liveness, in_report; держатель хранит как есть, решает сборка (P/08.5 Н1.3)
    domain/reaches:           {networks: [<сеть>…]} (P/09.1 Н1.7)
    witness:                  объекты <sub>/<report>/<имя> свидетелей domain.witness (P/02.1 Н1.2б); <sub>/<report> без имени —
                              не свидетель (P/09.1 Н1.10, P/10 Н1.8)
    domain/shared, domain/shared-refused: значение — разобранный doc строки: {term, rev, sha256} | {term, rev, reason, at};
                              у кластера держателя domain/shared — {term, rev, sha256, object}; term и rev — целые JSON (P/09.1 Н1.10)
    domain/alarms:            страница тревог (P/09.1 Н1.10, P/10 Н1.8)
    domain/backup-taken:      {term, rev, sha256}, term и rev — целые JSON (P/09.1 Н1.9, P/08.8 Н1.5 in_report)
ready:          агент не шлёт публикацию, пока у него нет ни одного шарда снимка каждого манифеста каталога с domain.ref:
                такая публикация сказала бы «единиц нет» — полный ответ, которому домен поверил бы
```

«Прочие семьи» `member_objects` — перечень выше; держатель хранит их как есть и отбрасывает только то, чего перечень не
называет (шаг 4).

## Ответ `carry`

Перенесено из [P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н1.5 без изменения поведения (аудит раскладки, решение «Архитектора» 2026-10-25, Б-12); граница `every` —
раздел ниже.

```yaml
carry:          ответ 200 на POST /api/member/<член> и GET /api/carry/<член> — JSON-объект:
  cluster:      имя члена
  rev:          rev метки этого члена после приёма (0 — поколения нет); агент шлёт следующее изменение против него
  every:        с — проход агента, 1 … 3600; вне — агент берёт ближайшую границу; держатель М11/3 даёт REPORT_EVERY (5)
  # в М11/3 есть: cluster, rev, every, keys, revoked, members — каждая строка как есть, когда она есть у держателя;
  # sealed М11/3 не было (секретного члену до М11/5 и М11/9 не было); в P/08 — sealed? ниже (разбор ревью стадии B 8–10, № 22: М-9)
  keys?:        строка domain/keys держателя {doc} (договор набора ключей домена «Набор domain/keys»)
  revoked?:     строка domain/revoked держателя {jtis} (договор набора ключей домена «Отзывы domain/revoked»)
  members?:     строка domain/members {doc} (P/08.3 Н1.1) — только отставшему: members_rev публикации нет или ≠ (term, rev)
                (раздел «Список членов отставшему»; добавлено М11/12); у GET /api/carry — всегда
  holder?:      строка domain/holder держателя {doc} (P/08.8 Н1.1; договор записи срока)
  sealed?:      конверт m1 с JSON-объектом секретного члену — договор конвертов домена «Содержимое sealed» (разбор ревью
                стадии A 8–10, № 12)
  <поля уроков>: placement — P/08.6 Н1.2 (назначение — P/08.6 Н1.1), pending — P/08.6 Н1.4; topology — P/08.3 Н1.2;
                shared — P/08.9 Н1.4; backup — P/08.8 Н1.5
```

## Ответ `carry`: `every`

Из P/08.3 Н1.3 `REPORT_EVERY` и Н1.5 `carry.every` без изменения поведения (разбор ревью стадии B 8–10, № 4; Claude С-3):

```yaml
REPORT_EVERY:   5           # с — проход агента; ответ держателя может назначить every, 1 … 3600
every:          поле ответа carry (P/08.3 Н1.5): с — проход агента, 1 … 3600; держатель даёт REPORT_EVERY (5); значение вне
                1 … 3600 агент не отвергает — ответ принимается, агент берёт ближайшую границу (1 или 3600; P/09.1 Н3
                «проход агента» шаг 5). Граница 1 … 3600 схемы Carry.every `Platform/08-domain/spec/08-domain.api.openapi.yaml` — то, что шлёт держатель, а не
                повод агенту отвергать ответ (поведение М11/3 Н1.6)
```

## Функция «принять»

Из М11/3 Н3 «принять(mark, stored, body, via, heard_ago) — держатель, на POST /api/member/<член> после подписи»:

`via` — дорога: нет — прямо, иначе имя ретранслятора (урок 4 Н1.3); `heard_ago` — монотонные секунды с последнего
приёма этого члена по любой дороге (нет — не слышал); приём — исходы `generation`, `heard` (с записью метки или без) и
`same`; `ignored` и отказы приёмом не считаются.

```
0. приём одного члена — один за раз в процессе domain (мьютекс); подпись, член и ключ уже проверены (раздел «Проверка члена и ключа»)
1. body — не JSON-объект по форме Н1.2                                             → 400 not_a_publication
2. mark есть и body.sent_at = mark.sent_at (одни часы члена на всех дорогах, урок 4 Н1.3): sha256(body) ≠
   mark.request_sha256 → 409 same_sent_at; mark.via = via → same (ничего не писать, метку не освежать); иначе → heard
   (повтор другой дорогой: поколения нет, метка — по правилу освежения шага 6; добавлено М11/4)
2а. mark есть, mark.via ≠ via, body.sent_at < mark.sent_at и heard_ago < ROAD_QUIET (урок 4 Н1.3) → ignored
   (ничего не писать: прежняя дорога жива, а это тело старше по часам члена)
3. base > 0 и (mark нет, или mark.via ≠ via, или base ≠ mark.rev, или stored не читается или не с mark.sha256) → 409 rebase
4. objects' = (base > 0 ? объекты stored : {}) ∪ body.objects − body.deleted; объекты вне member_objects отбросить
4а. JCS(whole') больше BODY_LIMIT → 413 {error: "whole too large", detail}; ничего не писать (P/08.10 Н1.5; добавлено М11/12)
5. нет шарда снимка какого-то манифеста каталога с domain.ref                           → 409 not_ready
6. mark есть, stored читается и с mark.sha256, и whole' без sent_at = whole stored без sent_at (JCS) → heard
   (stored не читается или не с mark.sha256 — шаг 7: испорченное поколение заменяется новым; добавлено сверкой М11, A1):
   метку этот процесс не писал, или писал не меньше MARK_REFRESH назад (монотонные), или body.stale ≠ mark.stale
   (сравниваются отсортированные списки ключей; сверка М11, A8) →
   переписать метку: поля поколения прежние; поля последнего запроса — sent_at, received_at, request_sha256, via, stale,
   sign_failures — этого запроса; иначе ничего не писать
7. иначе → generation: rev = (mark ? mark.rev : 0) + 1; mark.rev = 2^53 − 1 → 503 {error: "refused", reason: "rev_exhausted",
   detail: "<член>'s generations reached 2^53 − 1: the mark cannot grow"}, ничего не меняется (добавлено сверкой М11, A18); записать reports/<rev> = JCS(whole'), затем reports/<rev>.delta = body,
   затем метку {rev, sha256, base, delta_sha256, signature?, key, keys_rev?, pinned?, sent_at, received_at,
   request_sha256 (= delta_sha256), via?, stale, sign_failures?};
   убрать reports/<rev−2> и его .delta и объекты выше rev
```

`sent_at` ниже `mark.sent_at` на той же дороге принимается: порядок на одной дороге задаёт дорога, часы члена, шагнувшие
назад, берутся сразу; между двумя дорогами — шаг 2а (урок 4). Ответ на шаги 2 (same, heard), 2а, 6, 7 — carry (Н1.5); его `rev` —
`rev` метки, если `mark.via` = дорога ответа, иначе 0 (другая дорога шлёт целое). Сбой между шагами 7: объект выше метки ничей (Н1.3), следующий приём пишет поверх.

## Форма функции

Из М11/3 Н5 `accept`, `exit` и М11/4 Н5 (поля `via`, `heard_ago`) без изменения поведения: вход и вывод строк пакета
[`accept`](../vectors/accept/README.md) (сценарии сняты переносом урока 8; разбор ревью стадии B 8–10, № 6, Claude П-2;
№ 4, Claude С-4):

```yaml
input:          {catalog: [<sub>…], mark: <метка> | null, stored: <whole> | null, body: <текст>, refreshed_ago: <с> | null,
                 via?: <ретранслятор> | null, heard_ago?: <с> | null}       # нет via, heard_ago — null
  catalog:      имена манифестов каталога держателя; какие из них с domain.ref — по байтам самих манифестов (шаги 4, 5)
  mark:         метка reported по форме «Поколение, метка, пределы» или null — метки нет
  stored:       целое whole поколения mark.rev, как его прочёл держатель, или null — не читается
  body:         текст тела запроса как получен (байты — UTF-8 этого текста)
  refreshed_ago: монотонные с с тех пор, как этот процесс писал метку; null — не писал
  via:          дорога запроса: null — прямо, иначе имя ретранслятора
  heard_ago:    монотонные с с последнего приёма этого члена по любой дороге; null — не слышал
output:         {result: generation, rev, base, whole, sign_failures?} | {result: heard, refresh, sign_failures?} | {result: same}
                | {result: ignored}
                | {result: refused, status, reason: not_a_publication | same_sent_at | rebase | not_ready | whole_too_large
                   | rev_exhausted}
  whole:        целое whole' нового поколения (шаг 7) — объект, JCS которого записан в reports/<rev>
  refresh:      true — метка переписана (шаг 6 или повтор другой дорогой шага 2), false — ничего не записано
  sign_failures: у generation и heard с refresh: true — поле sign_failures, как оно записано в метку; нет поля — в метку
                не взято (нет в публикации или не по форме, out_of_delta); у heard с refresh: false поля нет (догадки
                стадии C ACC-FORM-31-01, ACC-G01-COUNTER-31-01, решение «Архитектора» 2026-10-23: форма вывода расширена)
  status:       код ответа двери: 400 not_a_publication (шаг 1); 409 same_sent_at (шаг 2), rebase (шаг 3), not_ready
                (шаг 5); 413 whole_too_large (шаг 4а; у двери — {error: "whole too large", detail}); 503 rev_exhausted (шаг 7)
exit:           0 — вычислено (в том числе отказ словом); 2 — вход не по форме (метка — строго «Поколение, метка, пределы»:
                stale есть всегда; signature необязательна и у метки без via); лишнее поле входа, метки или stored — 2;
                имена полей сравниваются точно (догадка стадии C ACC-FORM-31-01, решение «Архитектора» 2026-10-23)
```

## Пакет ретранслятора: пределы

Перенесено из [P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.4 (`BATCH_LIMIT`, `KNOCKS`) без изменения; пределы
читают ретранслятор (пишет пакет, P/09.2 Н3) и держатель (принимает, [P/08.3](../../08-domain/spec/08.3-domain.norms.md)
Н3 «держатель на POST /api/relay/<ретранслятор>», Н4) — у них ссылки сюда (C08-G05, решение «Архитектора» 2026-10-25).

```yaml
BATCH_LIMIT:   64 MiB     # = 4 × BODY_LIMIT (раздел «Поколение, метка, пределы»); тело POST /api/relay/<ретранслятор>
                          # больше — 413 до разбора; пакеты — в порядке имён членов; член больше BODY_LIMIT — не шлётся (журнал)
KNOCKS:        32 стука, тело стука не больше 256 KiB; у ретранслятора — 32 незнакомца в памяти, последний от имени
               заменяет прежний; 33-й незнакомец вытесняет самый старый стук (по времени приёма); вытесненный узнаёт это
               только по knocking держателя (раздел «Стук») — нового отказа нет
holder:        у держателя стуков в пакете больше 32 — сверх первых 32 по имени пропускаются без записи; стук с телом
               больше 256 KiB — пропуск без записи (как стук не по форме, P/08.3 Н3 шаг 3); пакет живёт; 413 — только
               целый пакет больше BATCH_LIMIT
```

## Векторы

Пакет [`accept`](../vectors/accept/README.md) (разбор ревью стадии A 8–10, № 13): 62 строки — входы команды `accept`
приёмки М11/3 (сц. 13, 26 строк) и М11/4 (сц. 06, 9 строк — дороги) без изменения байтов (сценарии и входы сняты переносом
урока 8 — таблица единственный источник этих случаев), 2 строки двери ретранслятора и 25 строк стадии C: прочие семьи
`member_objects`, лишние поля и `@exit 2`, форма `sign_failures`, форма метки — `sign_failures` {} и время `received_at` (ACC-FORM172, ACC-TIME172; README пакета). Реализация держателя и
ретранслятора проходит их своей функцией, без стенда. Строки на шаг 4а (`whole_too_large`) нет — кандидат пакета
(README пакета, «Кандидаты»; разбор ревью стадии B 8–10, № 6). Пределы пакета ретранслятора (граница 64 MiB, 33-й стук,
стук больше 256 KiB) функция «принять» не выражает — чтением (C08-G05).

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../../01-store/vectors/jcs/README.md)
урока P/01 (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).
