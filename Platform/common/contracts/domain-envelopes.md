# Договор конвертов домена: `x25519:v1`, `m1`, содержимое `sealed`

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): контракт, который пишет один процесс и читают
другие, лежит в `Platform/common/`; разбор ревью стадии A 8–10, № 12). Владелец — урок P/08: ключ приёма книг и его
конверт — глава 8.2 ([P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н1.4, Н1.5), ответ
держателя члену — глава 8.3 ([P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н1.5). Участники:

| Конверт | Запечатывает | Несёт | Открывает |
|---|---|---|---|
| `x25519:v1` вклада в книгу | агент члена (глава 9.1) до подписи отчёта | ретранслятор (9.2) — байты, открыть не может | держатель при сборке книги ([8.5](../../08-domain/spec/08.5-domain.norms.md)) |
| `x25519:v1` ключей передачи (`keys_sealed`) | прежний держатель ([8.8](../../08-domain/spec/08.8-domain.norms.md) Н1.7 шаг 5) | — | цель передачи (8.8) |
| `m1` ответа `carry` | держатель (8.3) | ретранслятор (9.2) — байты | агент члена (9.1) |
| `m1` ответа двери токенов | держатель ([8.7](../../08-domain/spec/08.7-domain.norms.md) Н1.3) | ретранслятор (9.2) | агент члена (9.1, [договор местной двери токенов](local-token-door.md)) |

Перенесено из М11/2 Н1.5 (абзац, блок, таблица отказов, абзац о подборе AAD), М11/2 Н3 «seal / open» (порядок проверок),
М11/3 Н1.5 (блок `envelope_m1` и абзац отказов), формы полей `sealed` из М11/3 Н1.5 `sealed?`, М11/5 Н1.4 `carry`, М11/9
Н1.3 `carry` и Н1.6 `carry` без изменения поведения. Ключ приёма книг (`domain/book-seal`, `book_seal` набора), его
рождение и смены — у владельца (P/08.2 Н1.2, Н1.4, Н3); что агент делает с открытым содержимым — М11/3 Н1.6 `sealed` и уроки
полей. Ссылки «урок N» в перенесённом тексте — урок М11/N; «урок 2 Н1.5» в разделе `m1` — раздел «Конверт `x25519:v1`»
этого договора. Путь JSON Pointer — по [договору запечатывания](sealing.md) «Путь AAD».

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Конверт `x25519:v1`

Из М11/2 Н1.5:

Секретное поле (`*_secret`, [P/02.1](../../02-installer/spec/02.1-installer.norms.md) Н1.3а) вклада члена в книгу едет к держателю конвертом к `book_seal`: агент запечатывает
до подписи отчёта (урок 3), ретранслятор несёт байты (урок 4), держатель открывает только при сборке книги (урок 5).

```yaml
envelope:      x25519:v1:<eph>:<nonce>:<ct>          # ровно пять частей через «:»; части 3–5 — base64url без «=»
  eph:         32 байта — открытый ключ X25519 одноразовой пары запечатывающего
  nonce:       12 случайных байт
  ct:          AES-256-GCM(key, nonce, plain, aad) с тегом 16 байт; не короче 16 байт
key:           HKDF-SHA256(ikm = X25519(eph_priv, book_seal), salt = eph ‖ book_seal, info = "w2c book seal x25519:v1", L = 32)
               # при открытии ikm = X25519(seed_secret, eph); book_seal — открытая половина seed_secret
aad:           UTF-8(JCS([member, source_path, item])) ‖ 0x00 ‖ UTF-8(pointer)
  member:      имя члена-вкладчика
  source_path: ключ строки-источника вклада в хранилище члена (урок 5: строка семьи domain.books.<книга>.from)
  item:        элемент этой строки — вклад
  pointer:     JSON Pointer секрета в JSON-документе элемента — по правилу пути договора запечатывания (`~0`, `~1`, индексы)
plain:         байты UTF-8 значения секрета как дано; пустое значение тоже запечатывается
seal:          новая пара eph и новый nonce на каждый конверт; два конверта одного значения различны; book_seal малого
               порядка (X25519(eph_priv, book_seal) — нулевой общий секрет) — конверта нет, отказ not_an_envelope
               (добавлено сверкой М11, S1)
```

Отказ открытия — одно из трёх слов, значение не повторяется ни в причине, ни в журнале ([P/06.2](../../06-console/spec/06.2-console.norms.md) Н1.4):

| Слово | Когда |
|---|---|
| `not_v1` | текст не начинается с `x25519:v1:` (другая версия, другой конверт, не строка) |
| `not_an_envelope` | частей не пять; часть — не base64url без `=`; `eph` не 32 байта, `nonce` не 12, `ct` короче 16; X25519 даёт нулевой общий секрет |
| `does_not_open` | AEAD не открылся (не тот ключ приёма книг, иной member, source_path, item или pointer, испорченный `ct`) или открытые байты — не UTF-8 |

Подмена AAD и чужой ключ неразличимы — обе причины — `does_not_open`. Подбор иных AAD при открытии запрещён.

Из М11/2 Н3 «`seal(book_seal, plain, aad)` и `open(seed_secret, envelope, aad)`»: запечатывание и открытие — Н1.5 (здесь —
блок выше); порядок проверок открытия: `not_v1` → `not_an_envelope` → `does_not_open`.

Тот же конверт с другим контекстом AAD — ключи передачи держателя `keys_sealed` (к `seal` цели, AAD `take|<to>`; форма
открытого текста и отказ — [P/08.8 Н1.7](../../08-domain/spec/08.8-domain.norms.md) шаг 5).

## Конверт `m1`

Из М11/3 Н1.5:

```yaml
envelope_m1:    m1:<eph>:<nonce>:<ct>             # как x25519:v1 урока 2 Н1.5: четыре части через «:», 2–4 — base64url без «=»
  recipient:    X25519 ключа члена: u = (1 + y)/(1 − y) mod 2^255 − 19 из y открытого Ed25519 (старший бит сброшен),
                little-endian (RFC 7748 §4.1); закрытый — первые 32 байта SHA-512(seed_secret) как скаляр X25519
  eph:          32 байта — одноразовый X25519; nonce — 12 случайных байт; ct — AES-256-GCM с тегом 16, не короче 16
  key:          HKDF-SHA256(ikm = X25519(eph, recipient), salt = eph ‖ recipient, info = "w2c carry to a member", L = 32)
  aad:          UTF-8("m1" + hex открытого ключа члена)
  plain:        UTF-8 текста JSON-объекта
```

Отказ открытия — слово, значение не повторяется: `not_m1` (текст не начинается с `m1:`), `not_an_envelope` (частей не
четыре, часть не base64url без `=`, `eph` не 32 байта, `nonce` не 12, `ct` короче 16, нулевой общий секрет),
`does_not_open` (AEAD не открылся или не UTF-8). Подбор иных форм запрещён.

## Содержимое `sealed`

Поле `sealed` ответа держателя агенту (`carry`, [P/08.3](../../08-domain/spec/08.3-domain.norms.md) Н1.5) —
конверт `m1` с JSON-объектом секретного члену. Из М11/3 Н1.5 `sealed?`, М11/5 Н1.4 `carry`, М11/9 Н1.3 `carry` и Н1.6 `carry`:

```yaml
sealed:         конверт m1 с JSON-объектом секретного члену; только когда секретное есть — пустого конверта нет
                (добавлено сверкой М11, D8)
  grants?:      {doc} — строка domain/grants/<член> (P/08.4 Н1.3 carry)
  break_glass?: {pwhash_secret, set_at} (P/08.4 Н1.6 carry)
  books?:       {<sub>: {<книга>: {<item>: <текст JSON>}}} — строка domain/<sub>/<книга>/<член> держателя, секреты открыты
                кольцом держателя перед m1 (P/08.5 Н1.4 carry)
```

Что пишет агент из открывшегося конверта и что делает с неоткрывшимся — М11/3 Н1.6 `sealed` и уроки полей (5 Н1.4, 9 Н1.3,
9 Н1.6). Конверт `m1` ответа двери токенов держателя несёт текст JSON `{request_id, token, exp}` (P/08.7 Н1.3 `answer`).

## Векторы

Пакет [`domain-envelopes`](../vectors/domain-envelopes/README.md) (разбор ревью стадии A 8–10, № 12): открытие
`x25519:v1` (`x25519-open.tsv`) и `m1` (`m1-open.tsv`), круги `seal-round` (`x25519-round.tsv`) и `seal-member-round`
(`m1-round.tsv`). Строки — входы команд-векторов приёмки М11/2 (`seal`, `seal-round`) и М11/3 (`seal-member`,
`seal-member-round`) без изменения байтов; сценарии и входы сняты переносом урока 8 — таблицы единственный источник этих
случаев. Реализация проходит их своей функцией, без стенда. `keys_sealed` и содержимое
`sealed` векторов не имеют — кандидаты (README пакета).

## Соответствие прежним урокам

Из М11/2 (разбор ревью стадии A 8–10, № 12): Н1.5 целиком (здесь «Конверт `x25519:v1`»; в М11/2 — указатель) и строка Н3
«`seal` / `open`» (порядок проверок). Из М11/3: блок `envelope_m1` и абзац отказов Н1.5 (здесь «Конверт `m1`»), строка
`sealed?` ответа (здесь «Содержимое `sealed`»; в `carry` М11/3 — указатель). Из М11/5 Н1.4 и М11/9 Н1.3, Н1.6 — формы полей
`books`, `grants`, `break_glass` (в источниках — указатель, смысл поля остаётся там). Части норм М11/2-08, М11/2-09 и
М11/3-09 — по `note` [id-map](../id-map.tsv); векторы — строки id-map договора и пакета.
