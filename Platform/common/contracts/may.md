# Договор права: функция `may`, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (13) и доп. (14): общий алгоритм нескольких процессов — договор, а не
копии в главах; решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 1; разбор ревью стадии A 8–10). Владелец — урок
P/08, [глава 8.4](../../08-domain/spec/08.4-domain.norms.md) (Н1.4 — указатель сюда): люди, гранты и
право по грантам. Функцию `may` исполняют:

| Кто | Где | `grants`, `as_of`, `disabled` |
|---|---|---|
| консоль кластера ([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3 `identity` шаг 3, `need`; глава 6.7 — сессия с грантами) | [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.9 `cluster`, `session` (действующие строки — шаг 5) | копия `domain/grants` этого кластера и её `as_of`; `domain/disabled` этого хранилища |
| консоль домена ([урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.5) и процесс `domain` (8.4) | [P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н1.5 `domain`; Н3 «дверь людей» шаг 2, «гранты» шаг 1 | `domain/grants/domain`, `as_of` — `null`; `roles` — из строк ролей и групп держателя (P/08.4 Н1.3 `roles_at_holder`) |

Откуда у консоли кластера вход `roles` — копия таблицы ролей `domain/roles` и связь с копией грантов: [P/06.7](../../06-console/spec/06.7-console.norms.md) Н1.9 `cluster`, [договор сторожевой и передачи](gate-and-pass.md) «Сторожевая с грантами» (ADR-0098 §4).

Шаг 5 (действующие строки) читают ещё доставка книги по гранту ([P/08.5](../../08-domain/spec/08.5-domain.norms.md)
Н1.3 `grant`) и индекс имён (P/08.5 Н1.7 `delivery`): `sub` — подсистема книги, только прямая группа, строки `role:` и
таблица ролей не участвуют (ADR-0097 §4, ADR-0098 §4); модуль консоли считает подсказку по тем же группам и ярусам
([P/07](../../07-console-module/spec/07-console-module.norms.md) Н1.5 `may`), сервер проверяет всегда.

Шаги 1–8 перенесены из М11/9 Н1.4 (вход, вывод) и Н4 (слова `may`); номера шагов прежние, шаги 4а, 7а–7в добавлены ADR-0098–ADR-0100. У
владельца остаются: строка гранта ([P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н1.3: `lines`, `line`, ранги `cap` — `none < view < edit < admin`, `sub`, `scope`,
`until`, `GRANT_LIFETIME`, `unreadable` — значение и правило входа повторены ниже, «Функция `may`»; копия члена — [P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4), проверка у процесса
`domain` и что дверь отвечает на `deny` (P/08.4 Н1.5: 403 `denied`, `detail` у `stale`), аварийная учётка у держателя
(P/08.4 Н1.6); сторожевая с грантами и аварийный вход у консоли кластера — P/06.7 Н1.9, Н1.10, у консоли домена — P/10 Н1.5. Ссылка
«Н1.6» в перенесённом тексте — М11/9 Н1.6, теперь P/06.7 Н1.10 (аварийная сессия консоли); `rank` — порядок `cap`
P/08.4 Н1.3; метки — [договор азбуки меток](labels.md).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Входы функции: `grants` — копия `domain/grants` члена и `domain/grants/domain` у консоли домена и процесса `domain` — `Platform/09-agent/data/grants.schema.json`, `Platform/09-agent/data/grants.outcomes.tsv`; `Platform/08-domain/data/grants.schema.json`, `Platform/08-domain/data/grants.outcomes.tsv`; `disabled` — строка `domain/disabled`: `Platform/08-domain/data/disabled.schema.json`, `Platform/08-domain/data/disabled.outcomes.tsv` (аудит раскладки, В-36, В-37; решение «Архитектора» 2026-10-25); `roles` у консоли кластера — копия `domain/roles` члена: `Platform/09-agent/data/roles.schema.json`, `Platform/09-agent/data/roles.outcomes.tsv`; у консоли домена и процесса `domain` — строки `domain/roles/<имя>` и `domain/groups/<имя>`: `Platform/08-domain/data/roles.schema.json`, `Platform/08-domain/data/groups.schema.json` с их таблицами исходов.

## Функция `may`

Из М11/9 Н1.4 «Право — функция `may`»:

```yaml
input:     {grants: <doc {lines}> | null, as_of: <число> | null, disabled: [<имя>…], user, glass, cap, unit, now,
            sub?, roles?, unread?, iat?}
  unit:    null — дверь без единицы; "*" — право на всё; {sub, id, labels: [<метка>…], about?, chains?}
  about:   {sub, id, labels, chains?} — about-единица; "unknown" — about нужен, но неизвестен (строка единицы нечитаема или
           чтение не подтверждено); поля нет — about у единицы нет
  chains:  [[F, родитель F, …, корневая папка]…] — по одной цепочке на каждое членство, только живые: звено без надгробия и вся
           цепочка до корня жива (ADR-0097 §5, ADR-0099 §2); [] — подтверждено, что папок нет; "unknown" или поля нет — членство,
           звено цепочки или его живость не прочитаны
           папка как объект записи — unit {sub: platform, id: <F>, labels: [], chains: [[F, предки F]]}; unit: и labels: её не
           покрывают, только ярусы 3 и 4 (ADR-0097 §5); создание корневой папки — unit "*"
  glass:   true — сессия аварийного входа (Н1.6); вызывающий для неё grants и disabled не читает (шаг 1 решает раньше) —
           их нечитаемость её не останавливает (C06-GLASS-UNREADABLE-01, решение «Архитектора» 2026-10-28)
  until:   until строки гранта — та же проверка конечности, что now и as_of (канон времени P/01.1 Н0: значение конечно в
           binary64); не помещается — вход не по форме, код 2, раньше шага 1 (glass); у читателя документа грантов —
           строка гранта не по форме, исход семьи grants (MAY-UNTIL-D8-01, решение «Архитектора» 2026-10-25)
  sub:     имя подсистемы (грамматика P/02.1 Н1.2 name), platform или null; поля нет — null. Подсистема проверки — не единицы:
           проверка подсистемы testsub2 над единицей testsub — unit {sub: testsub, id: c1}, sub: testsub2. Кто и как её называет — договор сторожевой и передачи
           «Подсистема проверки»; null — только предпроверка до тела и чтение «любой грант» (ADR-0097 §2)
  roles:   таблица {<имя>: [{role, until, at}…]}, раскрытая вызывающим до указателя «человек → роли»; null или поля нет —
           таблицы у члена нет: строки ролей не действуют, это проверенное отсутствие; "unreadable" — копия таблицы не читается,
           отпечаток не совпал или as_of таблицы не прошёл шаг 4 (ADR-0098 §4). Одна роль у человека дважды (прямо и через
           группу) — один элемент: более поздний until (0 — позже всех) (ADR-0098 §4)
    at:    с какого момента действует назначение admin: у консоли кластера — admin_at таблицы, у держателя — то же правило (P/08.4 Н1.3б);
           у прочих ролей 0, их at никто не читает
  unread:  какие группы ролей видел вызывающий неполными: [{role: <R>, sub?: <S>}…] — строка этой роли не по форме, субъект
           прочёлся (sub — если прочёлся и он: тогда только в этой sub); "all" — у строки не прочёлся субъект: неполны все
           группы ролей документа; поля нет — []. Вызывающий отбрасывает нечитаемую строку (lines_in), но признак не теряет (ADR-0099 §2)
  iat:     iat токена запроса; на пути билета и шага операции — iat записи билета, токен тот же (договор сторожевой и передачи «Передача второго вида»); null — только сессии без токена: glass, отладочная личность; поля нет — null; нужно только шагу 4а:
           токен, выпущенный раньше at назначения admin, шагу 4а не служит (ADR-0100 §3); сравнение — по целым секундам: at несёт до
           трёх знаков дроби, iat токена — любое конечное число
output:    {result: allow} | {result: deny, reason: disabled | stale | no_grant} | {result: unavailable}
           unavailable — дверь отвечает 503 unavailable, а не 403 (правило «Нечитаемая строка» договора сторожевой и передачи)
```

```
1. glass                                                                → allow
2. user ∈ disabled                                                      → deny disabled
3. grants = null                                                        → deny no_grant
4. as_of ≠ null и now − as_of > GRANT_LIFETIME                          → deny stale
4а. в roles[user] есть {role: admin, until: t, at}, t = 0 или now < t, и iat = null или ⌊iat⌋ ≥ ⌊at⌋ → allow
5. отбор: строка действует, если until = 0 или now < until, и sub строки нет, или равен sub входа, или sub входа = null.
   прямая группа — действующие строки subject = user;
   группы ролей — по одной на каждый {role: R, until: t} из roles[user], R ≠ admin, t = 0 или now < t: действующие строки
   subject = role:R; строки роли не из roles[user] не действуют (ADR-0097 §2, ADR-0098 §4, ADR-0099 §2)
6. unit = null и cap = view: хоть одна строка прямой группы или группы роли, чей cap ≠ none  → allow
7. прямая группа: строка с rank(cap строки) ≥ rank(cap) и область покрывает unit → allow
   * — любую (и "*"); unit:<s>/<i> — unit с (sub, id) = (s, i) или его about с (s, i); labels:L — все метки L у about, если
   about есть, иначе у самого unit; folder:<id> — id в цепочке chains у unit или у about;
   null и "*" ни одна область, кроме *, не покрывает; папку-объект (unit.sub = platform) unit: и labels: не покрывают;
   about "unknown" и chains "unknown" — строка, которой они нужны, не покрывает, проверяется следующая (не 503)
7а. группа роли даёт уровень ≥ rank(cap) (уровень группы — ниже)        → allow
7б. roles = "unreadable"                                                → unavailable
7в. есть «нечитаемая» группа роли, которая могла бы разрешить (ниже)    → unavailable
8.                                                                      → deny no_grant
```

**Уровень группы роли** по проверке `(cap, unit, sub)` (ADR-0099 §2). Группа берёт **первый ярус**, где у неё есть строка,
покрывающая единицу; уровень — наибольший `cap` строк этого яруса (`none < view`). `none` и положительная строка одного яруса,
в том числе одной области, дают положительную. Цепочка без строки группы в ярус 3 ничего не даёт.

| Ярус | Строки |
|---|---|
| 1 | `unit:` — сама единица |
| 2 | `unit:` — её about-единица |
| 3 | `folder:` — ближайшие папки: в каждой цепочке `unit.chains` и `about.chains` первая папка, на которую у группы есть строка из отбора шага 5 (ранг при выборе не смотрится); ярус — строки этих папок по всем цепочкам |
| 4 | `*` |

`unit = "*"` и `unit = null` покрывает только ярус 4; папка-объект — ярусы 3 и 4 по её цепочке. Ни один ярус не покрывает — группа
уровня не даёт. Истёкшая строка в отбор не попала и в ярусе не участвует: истёк `none` на единицу — действует ярус папки.

**Нечитаемая группа** (ADR-0099 §2). Группа роли не опускается к менее точному ярусу, если более точный нельзя вычислить. Группа
«нечитаема» с яруса `k`:
- `k = 1` — роль названа в `unread` (без `sub` или с `sub` входа) или `unread = "all"`;
- `k = 2` — ярус 1 пуст, `about` = `"unknown"`, у группы есть строка `unit:`;
- `k = 3` — ярусы 1–2 пусты, у группы есть строка `folder:`, а `unit.chains` неизвестны, или `about.chains` неизвестны, или `about` = `"unknown"`.

Такая группа уровня не даёт. Могла бы разрешить (шаг 7в) — есть её строка из отбора шага 5 с рангом ≥ `cap` в ярусах от `k` и
ниже: для `k = 1` — любая; для `k = 2` — `unit:`, `folder:`, `*`; для `k = 3` — `folder:`, `*`.

**Отсечка** (ADR-0099 §2): ярус `k = 3` не «нечитаем», если результат от членства не зависит. Все строки `folder:` группы
в отборе с рангом ≥ `cap`, а ярус 4 даёт уровень ≥ `cap` — шаг 7а разрешает; все ниже `cap`, а ярус 4 не разрешает — группа не
разрешает и в шаге 7в не считается. Вызывающий тогда членство не читает.

Прямая группа строки только складывает, в ней исключений нет. `none` бывает только в строках ролей. Роль `admin` строк не имеет
(шаг 4а) и групп не образует: исключения других ролей на неё не действуют (ADR-0100 §1). Шаг 7б — и при отсутствии подходящих строк
`role:`: нечитаемая таблица могла нести назначение `admin` (ADR-0100 §1). Списки вместо `unavailable` дают `withheld` (P/06.4).

Постоянная и вход строк (из P/08.4 Н1.3 `GRANT_LIFETIME`, `unreadable` и Н5 `exit` без изменения поведения; владелец
текста — P/08.4; разбор ревью стадии B 8–10, № 4, Claude С-7):

```yaml
GRANT_LIFETIME: 86400   # с — шаг 4: копия члена старше as_of + GRANT_LIFETIME не даёт прав
lines_in:       функция получает только строки lines по форме P/08.4 Н1.3 (файлы семьи — Platform/09-agent/data/grants.schema.json,
                grants.outcomes.tsv; C04-DEP-OBS-HEARTBEAT-01): нечитаемую строку отбрасывает вызывающий до
                вызова — пропуск с диагностикой у двери члена над копией из ответа держателя (P/08.4 Н1.3 unreadable;
                копия — P/09.1 Н1.4 member_copy, holder_copy); строка не по форме во входе функции — вход не по форме, код
                выхода 2, не пропуск (P/08.4 Н5 exit). Противоречия «пропускается» (Н1.3) и «2, не пропуск» (Н5) нет: пропуск
                — у вызывающего, код 2 — у функции
```

Какой вход не по форме (строки `grants` — доверенный вход) — README векторов [`may`](../vectors/may/README.md) «Форма входа команды `may`» (MAY-G01/G02); коды выхода команды `may` — копия [P/08.4](../../08-domain/spec/08.4-domain.norms.md) Н5 `exit` (аудит раскладки, решение «Архитектора» 2026-10-25, Б-14):

```yaml
exit:      0 — вычислено; 2 — вход не по форме; коды выхода — по принципу словаря «Стенда домена» («Коды выхода команд-векторов»: 2 — форма
           доверенного входа, 0 со словом — документ другого кластера; решение «Архитектора» по сверке М11, H14):
           строки grants у may — доверенный вход (копия, уже разобранная по Н1.3), поэтому строка не по форме — 2, не пропуск
```

## Слова отказа

Из М11/9 Н4: слова `may`: `disabled`, `stale`, `no_grant`. Исход `unavailable` — не слово отказа `may`: дверь отвечает 503 `{error: "unavailable"}`.

## Векторы

Пакет [`may`](../vectors/may/README.md): 106 строк: may-27…may-106 — ADR-0097–ADR-0100 (`sub`, `folder:`, роли, ярусы, шаг 4а); из первых 26: 24 — входы команды `may` приёмки М11/9 (сц. 07) без изменения значений, кроме `labels: []` у единицы

источник этих случаев. Там же `covers.tsv` — 19 строк функции `covers(scope, ref, row)` сторожевой ([договор
сторожевой](gate-and-pass.md) `scope`; C06-EVENTS-QUERY-UNKNOWN-138-10).
