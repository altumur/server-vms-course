# Договор набора ключей домена: строка `domain/keys`, функция `keys`, отзывы `domain/revoked` и их снятие

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (11) и доп. (13): общий алгоритм нескольких процессов — договор, а
не копии в главах; разбор ревью стадии A 8–10, № 13 / решение 2, № 3). Владелец — урок P/08, глава 8.2
([нормы](../../08-domain/spec/08.2-domain.norms.md)): процесс `domain`
держателя подписывает набор корнем и ведёт отзывы. Участники:

| Кто | Что делает по договору |
|---|---|
| агент члена ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4 `from_carry`) | функцией `keys` принимает набор из ответа держателя и пишет `domain/keys`; объединяет `domain/revoked` ответа со своей строкой и снимает записи `prune` |
| ретранслятор ([P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.4 `keys`) | читает принятый набор своего кластера (id-map М11/2-04) |
| консоль кластера ([P/06.3](../../06-console/spec/06.3-console.norms.md) «Ключи есть») | принимает набор функцией `keys` с закреплённым корнем |
| проверяющие токен домена ([договор токена домена](domain-token.md)) | читают принятый набор и `domain/revoked` |
| процесс `domain` при переносе и следовании ([глава 8.8](../../08-domain/spec/08.8-domain.norms.md) Н1.8; «следовать» — P/09.1 Н3 шаг 1а) | принимает наборы ответов `/api/held` функцией `keys` |

Перенесено из М11/2 Н1.2 (строки `row`, `doc`, `writer_forms`, `only_forward`), Н1.6 (блок `domain/revoked`: форма,
`writer`, `order`, `prune`, `readers`), Н3 «`keys(pinned, held, offered)`» (шаги 1–8 и абзац об отказе) и строки
`from_carry` P/09.1 Н1.4 о `revoked` без изменения поведения. У владельца остаются: корень и его закрепление (P/08.2 Н1.1),
`rev` писателя, аварийный `rev` и предпосылка часов (P/08.2 Н1.2 `rev`, `emergency`, `clocks`), ключи держателя и `OLD_KEYS`
(P/08.2 Н1.3, Н1.6), смены набора (P/08.2 Н3; установка — [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н3),
окно отзыва без связи (P/08.2 Н1.7). Общее для форм — [P/08.2 Н1](../../08-domain/spec/08.2-domain.norms.md#н1-форма)
«Общее для всех форм главы» (hex, канонический base64url, JCS — RFC 8785, Ed25519 — RFC 8032, X25519 — RFC 7748, полнота
форм JSON, повтор ключа, «целое»). Ссылки в перенесённом тексте: «Н1.x», «Н3» — главы P/08.2 (прежде урока М11/2; номера
подразделов прежние); «урок N» — урок М11/N, их адреса теперь: «урок 3» (агент, приём и подпись члена) — P/09.1 и P/08.3,
«урок 3 Н1.6 from_carry» — P/09.1 Н1.4 `from_carry`, «урок 7» (токен вида) — P/08.7, «урок 9» (отзыв человека) — P/08.4,
«урок 10» (выпускающий держатель) — P/08.8 (разбор ревью стадии B 8–10, № 22; Kimi SB810-07).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Набор `domain/keys`

Из М11/2 Н1.2:

```yaml
row:           domain/keys {doc: <текст JSON документа>}   # ровно один элемент doc, строка; иной состав — not_a_set;
                                                           # строка хранилища (P/01.1); писатель у держателя — процесс domain,
                                                           # у члена — агент (урок 3) после функции keys (Н3); агент кластера
                                                           # держателя её не пишет, пока кластер держит срок (P/08.8 Н1.6 switch)
doc:                                                       # закрытый набор полей; лишнее поле — not_a_set; массивы — без
                                                           # значения порядка, повтор элемента допустим; писатель — по возрастанию
  domain:          имя домена (Н1.1)
  rev:             целое 1 … 2^53−1
  root:            hex открытого корня
  current:         kid ключа токенов, которым держатель подписывает сейчас; ∈ keys; ∉ until
  keys:            {<kid>: <hex открытого ключа токенов>}, не пусто; kid — непустая строка
  until?:          {<kid>: <стенные секунды>} — ключ ещё принимается до этого момента включительно; kid ∈ keys
  issuing:         [<serial>…] — ключи выпускающего держателя (урок 10); serial — непустая строка
  revoked_issuing: [<serial>…] — отозванные ключи выпускающего; всегда массив, может быть пустым
  revoked_members?: [<hex ключа члена>…] — отозванные ключи членов (урок 3: приём и подпись члена сверяются с ним)
  book_seal:       hex открытого ключа приёма книг X25519 (Н1.4); обязателен: набор без него не читается; точка малого
                   порядка (X25519 с любым скаляром даёт нулевой общий секрет, RFC 7748 §6.1) — набор не читается
                   (добавлено сверкой М11, S1)
  kid:             "root"
  sig:             base64url подписи Ed25519 корня над UTF-8(JCS(doc без kid и sig))
writer_forms:      kid ключа токенов = первые 8 знаков hex его открытого ключа; serial = первые 16 знаков hex открытого
                   ключа выпускающего; читатель принимает любую непустую строку
only_forward:      член держит один набор; набор с меньшим rev — отказ, с равным — «держу», не переписывается
```

`rev` нового набора у писателя (обычная, плановая и аварийная смена) — [P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н1.2 `rev`, `emergency`, `clocks`.

## Отпечаток ключа

Из P/08.2 Н1.1 `fingerprint` без изменения поведения (владелец текста — P/08.2 Н1.1; здесь — для урока P/09, который
печатает отпечаток ключа члена, P/09.1 Н1.1 `born`; разбор ревью стадии B 8–10, № 4, Claude С-1):

```yaml
fingerprint:   hex(sha256(<32 байта открытого ключа>)[:8]) — 16 знаков; так корень и ключи называют люди и журналы:
               отпечаток корня (установка домена, join), ключа члена (строка журнала агента «member key <отпечаток>»,
               приём оператором — P/08.3 Н1.1, поле knock.fingerprint)
not_serial:    отпечаток — не serial (writer_forms выше: первые 16 знаков hex самого открытого ключа, без sha256) и не
               отпечаток центра TLS (sha256 hex DER-сертификата, 64 знака — договор сертификата роли `fingerprint`)
```

## Функция `keys`

Из М11/2 Н3 «`keys(pinned, held, offered) → took rev | holding rev | refused <слово>`»:

Функция агента члена над набором из ответа держателя (урок 3) и процесса domain над своим набором при смене. Шаги — по
порядку; первое сработавшее правило даёт итог.

```
1. pinned нет                                                              → refused no_pin
2. offered не {doc: строка}; doc не JSON-объект или с повтором ключа, поле вне закрытого набора Н1.2, обязательного нет,
   тип или граница не по Н1.2 (кроме book_seal)                            → refused not_a_set
   # kid или sig не строка, root не hex 32 байт — здесь; пустой issuing допустим (непустота названа только у keys)
3. kid ≠ "root"                                                            → refused bad_signature
4. doc.root ≠ pinned.pub или doc.domain ≠ pinned.domain                    → refused another_root
5. подпись sig не проверяется ключом pinned.pub над JCS(doc без kid и sig) → refused bad_signature
   # sig — строка, но не base64url или не 64 байта — тоже здесь
6. book_seal нет, не hex 32 байт или точка малого порядка (Н1.2)            → refused no_book_seal
7. held есть: doc.rev < held.rev → refused older (rev held); doc.rev = held.rev → holding (rev held)
8. иначе                                                                   → took (rev doc); строка domain/keys := offered
```

Отказ не меняет строку `domain/keys`; член продолжает верить прежнему набору и пишет причину в журнал (М13).

«Н1.2» в шагах 2 и 6 — раздел «Набор `domain/keys`» выше; `pinned` — `{pub, domain}` строки `domain/root` (P/08.2 Н1.1).
Форма функции — вход команды `keys` ([P/08.2](../../08-domain/spec/08.2-domain.norms.md) Н5).

## Отзывы `domain/revoked`

Из М11/2 Н1.6:

```yaml
domain/revoked: {jtis: "<jti>:<exp>,…"}      # ровно один элемент jtis, строка; пусто — ""; строки нет — отзывов нет;
                                            # иной состав, запись не «<jti>:<число JSON>» (jti по грамматике токена) — не по форме:
                                            # token → no_revocations; повтор jti и порядок читатель не проверяет
  writer:      процесс domain при отзыве (урок 9: человек; урок 7: токен вида) и при каждом проходе держателя; у члена —
               агент объединением ответа держателя со своей строкой (урок 3 Н1.6 from_carry; добавлено моделью Quint М11,
               RV): у члена запись снимает только prune; агент кластера держателя её не пишет, пока кластер держит срок (P/08.8 Н1.6 switch)
  order:       по возрастанию jti в байтах; exp — число JSON, exp отозванного токена
  repeat:      повтор jti в одной строке (своей или ответа) при слиянии и чистке — для jti берётся наибольший exp, затем prune:
               повтор не сокращает отзыв (x:100,x:200 при now = 161 — остаётся x:200; догадка стадии C KEYS-G01, решение «Архитектора» 2026-10-23)
  prune:       записи с exp + TOKEN_SKEW < now, строго, писатель ДОЛЖЕН снимать — список ограничен числом живых токенов;
               при now = exp + 60 токен ещё годен (Н3 token шаг 6), и его отзыв стоит (ADR-0074 доп. 7)
  readers:     консоль кластера, роли воркеров — платформенной основой прав (P/02.5 Н1.4), агент (урок 3); у члена — копия
```

Из М11/3 Н1.6 `from_carry` (агент члена, поле `revoked` ответа держателя; ныне P/09.1 Н1.4 `from_carry`):

```yaml
merge:          revoked → объединение с своей строкой domain/revoked: записи ответа ∪ свои по jti (при равном jti — больший
                exp); снимает только prune урока 2 Н1.6 (exp + TOKEN_SKEW < now) — отзыв ответом не отменяется (добавлено
                моделью Quint М11, RV: после аварийного переноса ответ из копии иначе снял бы отзыв последних BACKUP_EVERY)
```

`TOKEN_SKEW` и «Н3 token шаг 6» — [договор токена домена](domain-token.md) «Токен», «Проверка»; «prune урока 2 Н1.6» —
строка `prune` выше. Когда агент применяет поле `revoked` (после исхода `took` или `holding` функции `keys` над набором того
же ответа) — P/09.1 Н1.4 `from_carry`.
