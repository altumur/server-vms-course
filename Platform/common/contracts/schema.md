# Договор схемы хранилища: `platform/schema`, `SCHEMA`, проверка при старте

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): проверку схемы при старте исполняют все процессы
платформы — договор, а не копии в главах; аудит раскладки А-02, решение «Архитектора» 2026-10-25). Владелец — глава
[P/06.6](../../06-console/spec/06.6-console.norms.md) (Н1.1а «Схема», Н3 «поднять_схему»). Участники: консоль (P/06.6),
контроллер ([P/04](../../04-controller/spec/04-controller.norms.md) Н3 «старт контроллера — проверка схемы»), воркер
([P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3 «проверка схемы воркером»), ресурс
([P/05](../../05-resource/spec/05-resource.norms.md) Н3 «старт ресурса — проверка схемы»), процессы домена — `domain`,
агент, консоль домена ([P/02.4 Н1.12](../../02-installer/spec/02.4-installer.norms.md); консоль домена —
[P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.1); шаг 0 старта процесса — [P/02.3](../../02-installer/spec/02.3-installer.norms.md)
Н3 «Старт процесса».

Перенесено из P/06.6 Н1.1а (строки `platform/schema`, `SCHEMA`, `BUILD`, `heartbeat`, `check`) и общего блока «старт
контроллера, воркера, ресурса или консоли — проверка схемы» (P/06.6, P/03.2, P/04, P/05 Н3; прежде М10/10 Н3) без
изменения поведения; у них — ссылки сюда. Подъём схемы оператором (`raise`, `PUT /schema`, окно обслуживания) — у
владельца, P/06.6 Н1.1а, Н3 «поднять_схему».

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Строка `platform/schema` — семья `schema`: форма `Platform/06-console/data/schema.schema.json`, исходы
`Platform/06-console/data/schema.outcomes.tsv` ([форма](../../06-console/data/schema.schema.json),
[исходы](../../06-console/data/schema.outcomes.tsv)). Поле `schema` пульса — формы пульсов
`Platform/03-worker/data/heartbeats.schema.json` (исходы — `Platform/03-worker/data/heartbeats.outcomes.tsv`) и `Platform/05-resource/data/resource-heartbeat.schema.json` (исходы — `Platform/05-resource/data/resource-heartbeat.outcomes.tsv`) (и их
`.outcomes.tsv`).

## Схема

```yaml
platform/schema:  {version: <целое ≥ 1>, at: <момент>}     # писатель — консоль (admin); нет строки = схема сборки (свежая установка)
version:  точное целое ≥ 1 без верхней границы и без машинного переполнения (как номер слота, договор имени слота): больше
          SCHEMA сборки — «схема новее» (too new: отказ старта, код 2, в журнале точное N); не по форме — только не целое, < 1
          (C06-SCHEMA-WIDE-32-01, решение «Архитектора» 2026-10-25)
SCHEMA:   число, которое понимает сборка; поле добавить — без нового номера; смысл поля сменить — новый номер; для нынешней
          спецификации SCHEMA = 1 и schema пульса = 1; повышение SCHEMA — только решением с переходом (догадка стадии C W03-E02, решение «Архитектора» 2026-10-23)
BUILD:    слово сборки для человека (env BUILD, умолчание dev); машина читает SCHEMA
heartbeat: каждый пульс воркера и ресурса несёт schema и build (P/03.4 Н1.1, P/05 Н1.4); schema — целое JSON без дробной
          части и экспоненты (форма int главы 6.1 Н1.2: «Значение `int` на входе двери»), ≥ 1; `1.0`, `1e0`, `-1`, строка, null — схема процесса неизвестна (null
          в `processes`, P/06.6 Н2.3) (сверка python и go М10/6–11, T3); build — строка; не строка — `null` (не известно; сверка python и go М10/6–11, T27; В7 п. 3, решение «Архитектора» 2026-10-28, П1; строка 14 списка)
check:    при старте контроллера, воркера, ресурса и консоли: version > SCHEMA → не стартовать; строка не число → не стартовать;
          так же стартуют процессы домена — domain, агент, консоль домена (P/02.4 Н1.12); воркер проверяет и при продлении
          слота (P/03.2 Н3 «проверка схемы воркером»)
```

## Проверка при старте

```
первым шагом старта, до чтения манифеста (P/02.3), у всех четырёх процессов:
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
  ошибка чтения → ждать доступности, не начиная работы; не стартовать — выход с кодом 2 и строкой лога
воркер: после продления слота — P/03.2 Н3 «проверка схемы воркером»
```

**Граница.** Демон строкового хранилища не толкует раскладку подсистемы и этой проверкой не блокируется: иначе нельзя было бы открыть хранилище для чтения/исправления схемы; его собственный формат — P/01.1 и P/01.3 Н1.3 (демон `configstore`: `member.json`, `backup`/`restore`). Проверка при продлении есть у воркера; она не доказывает безопасность всех остальных процессов. Их гонка со стартом исключена окном обслуживания P/06.6 Н3 «поднять_схему». Сбой чтения — ждать доступности без работы; достоверно испорченная/слишком новая схема — отказ старта с кодом 2.

## Векторы

Пакет [`schema`](../vectors/schema/README.md): функция `check` — строка `platform/schema` и SCHEMA сборки → старт с версией,
«схема новее» с точным N или «не по форме» (C06-SCHEMA-WIDE-32-01, решение «Архитектора» 2026-10-25). Ошибка чтения и продление слота воркером — сценариями приёмки
участников (P/06.6) и чтением.
