# Договор `peer`: клиент о сервере другого кластера, первый контакт центра, слова отказа

Общий договор модуля «Платформа» (ADR-0083 доп. (13) и доп. (14): общий алгоритм нескольких процессов — договор, а не
копии в главах; решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 2; разбор ревью стадии A 8–10, № 7; разбор ревью
стадии A 6–7, № 28; разбор ревью стадии B 6–7, № 25). Владелец — урок P/09, [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.7 (P/09.1-27; первый договор — агент к `https://`;
источник — М11/8 Н1.6 `client`, `first`, Н3 «peer»).
Функцией `peer` клиент двери другого кластера по `https://` принимает сервер:

| Кто | Кому звонит | Где |
|---|---|---|
| агент члена ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.7), ретранслятор ([9.2](../../09-agent/spec/09.2-agent.norms.md); урок 4: это агент) | держатель, ретранслятор | «Клиент и первый контакт»; агент в процессе — P/09.1 Н1.11 `client` |
| консоль кластера ([глава 6.7](../../06-console/spec/06.7-console.norms.md) Н1.7) | консоль члена или держателя | [договор пересылки](forwarding.md) `tls` |
| процесс `domain` (8.8) | консоли соседей при переносе и передаче | [P/08.8](../../08-domain/spec/08.8-domain.norms.md) Н1.7, Н1.8 |
| консоль домена ([урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.4) | — (сервер двери роли: шаги 6–7 над листом клиента с `role: console`) | [договор сертификата роли](role-certificate.md) «Серверная сторона: класс `role`» (C10-SDK-ROLE83) |
| клиент другого кластера к двери процесса `mixed` (процесс подсистемы, [P/03.4](../../03-worker/spec/03.4-worker.norms.md) Н1.7 `cross_cluster`) | дверь процесса члена, которого называет назначение или книга подсистемы | лист не предъявляет, допуск — маршрут `domain` токеном домена; сервер — пир члена назначения: роль — роль двери, отпечатки — `Entry.ca` этого члена из копии `domain/member-list` (читает по `worker.reads`), имя — из адреса; договор сертификата роли не меняется (ADR-0091 доп. (18) п. 2, доп. (19) п. 2) |

Перенесено из М11/8 Н1.6 (строки `client`, `first`; строка `revoke` — сторона клиента, решение «Спецификации» при
переносе урока 10), Н3 «peer(chain, fingerprints, role, host, now)» (шаги 1–9 и абзац
после них) и Н4 (слова `peer`) без изменения поведения; номера шагов прежние. Отпечаток
центра, поля публикации `tls_ca`, `tls_ca_certs`, форма `Entry.ca`, `W2C_TLS_DIR`, роли процессов домена и ожидаемая

роли](role-certificate.md) «Комплект кластера, роли домена, центр между кластерами» (`fingerprint`, `tls_ca`,
`tls_ca_certs`, `Entry.ca`, `domain_roles`, `peer_role`; разбор ревью стадии B 8–10, № 4); серверная сторона класса
`signed` — там же; запись `Entry.ca` у держателя (`on_accept`, строка `ca-certs`, `admin`) — сторона держателя, P/08.3
Н1.6. Класс `role` (`server.role`) — участник, [договор сертификата роли](role-certificate.md) «Серверная сторона: класс `role`» (таблица выше); ответ пересылки на отказ — P/06.7 Н4
`did not answer`. Ссылки в перенесённом тексте: «Н1.x», «Н3» —
урока М11/8 (Н1.6 — P/06.7 Н1.7 и строки этого договора, Н3 — P/06.7 Н3); «урок N» — урок М11/N; подписи —

`{chain: [<PEM>…], fingerprints: [<hex>…], role, host, now}` → `{result: ok}` | `{result: refused, reason}`.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Клиент и первый контакт

Из М11/8 Н1.6:

```yaml
client:       клиент двери другого кластера по https:// знает член назначения и принимает сервер, когда peer = ok:
              консоль члена — имя из CLUSTERS; консоль кластера держателя и подписант — держатель; ретранслятор —
              RELAY_MEMBER; отпечатки — Entry.ca члена назначения в domain/member-list этого кластера (форма копии —
              Platform/09-agent/data/member-list.form.yaml (исходы — `Platform/09-agent/data/member-list.outcomes.tsv`), исходы — member-list.outcomes.tsv; C04-DEP-OBS-HEARTBEAT-01)
first:        DOMAIN_CA=<отпечаток> рядом с DOMAIN_URL, RELAY_CA=<отпечаток> рядом с RELAY_URL — действует, только пока
              запись члена назначения не называет ca; ни записи, ни отпечатка — отказ foreign_ca: доверия при первом
              контакте нет; RELAY_URL на https:// без RELAY_MEMBER — агент не стартует, код выхода 2 — отказ настройки
              (P/02.4 Н1.1 common; решение «Архитектора» по планам переноса 8–10, ADR-0083 доп. (14) п. 10; план 9 В8)
revoke:       отзыв сертификата чужого кластера звонящему не виден; средство — смена центра (rotation)
```

## Функция `peer`

Из М11/8 Н3 «peer(chain, fingerprints, role, host, now) — клиент о сервере другого кластера, по порядку»:

```
1. host — IP-адрес (v4 или v6, в том числе v6 с зоной `%<зона>`; добавлено сверкой М11, D15) → ip_address
   # запись вида `127.1` — не IP-адрес, а имя (совпало у реализаций, записано сверкой М11)
2. chain — не непустой список читаемых PEM-сертификатов: элемент — ровно один блок CERTIFICATE, base64 строгий,
   DER разбирается целиком; иначе — до поиска якоря                          → bad_chain
3. fingerprints пуст, или в chain[1:] нет сертификата центра (CA:true) с отпечатком из fingerprints → foreign_ca
   якорь — первый такой сертификат по порядку chain
4. нет пути chain[0] → … → якорь по соседним элементам chain: chain[i] подписан ключом chain[i+1] алгоритмом закрытого списка
   договор сертификата роли `sig` (добавлено сверкой М11, D14), следующий — CA:true; pathLen и keyUsage не читаются, лист с
   CA:true — лист (совпало у реализаций, записано сверкой М11)
   порядок chain — порядок сервера (лист, затем центр; договор сертификата роли server); элементы не переставляются и
   не перебираются (решение «Архитектора», разбор ревью стадии B 8–10, № 10, ADR-0083 доп. (15))
                                                                             → bad_chain
5. now вне [notBefore, notAfter] какого-либо сертификата пути (листа и якоря включительно) → expired
6. у листа SAN URI вида urn:w2c:role:<роль> с непустой ролью не ровно один (`urn:w2c:role:` — роли нет; схема и
   префикс — байт в байт; добавлено сверкой М11, D15)                          → no_role
7. роль листа ≠ role (байт в байт)                                           → wrong_role
8. host не среди SAN DNS листа — сравнение байт в байт: регистр значим, wildcard не раскрывается, точка в конце не
   снимается (совпало у реализаций, записано сверкой М11)                      → wrong_name
9.                                                                           → ok
```

Выше якоря цепочка не проверяется: якорь назначен отпечатком записи (стоит ли он корнем или промежуточным — всё равно);
отзыв чужого кластера не проверяется (строка `revoke` выше; прежде М11/8 Н1.6). Клиент с отказом `peer` закрывает соединение; пересылка отвечает
502 `did not answer` со словом отказа в `detail`.

## Слова отказа

Из М11/8 Н4: слова `peer`: `ip_address`, `bad_chain`, `foreign_ca`, `expired`, `no_role`, `wrong_role`, `wrong_name`.
