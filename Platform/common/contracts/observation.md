# Договор наблюдения: свежесть, состояние ресурса, чтение решения

Общий договор модуля «Платформа» (ADR-0083 доп. (5): контракт, который читают несколько процессов, лежит в
`Platform/common/`; решение «Архитектора» по разбору ревью стадии A 6–7, № 1, № 2). Владелец — урок
[P/04](../../04-controller/spec/04-controller.norms.md) (Н1.4: константа `LOST_AFTER` и судья; блоки перенесены оттуда; разбор ревью стадии B 6–7, № 35). Читают: контроллер — пул, судья
слота, вывод сервера ([P/04](../../04-controller/spec/04-controller.norms.md) Н1.4, Н3), консоль — выдачи наблюдений
(глава [P/06.5](../../06-console/spec/06.5-console.norms.md): `/servers`, `/resources`, `/where`, `/unplaceable`,
`/metrics`), двери управления (глава [P/06.6](../../06-console/spec/06.6-console.norms.md): вывод сервера, `/schema`,
подъём схемы, дренаж, прогнозы меток), живые ресурсы слияния `/events` (глава
[P/06.4](../../06-console/spec/06.4-console.norms.md)) и метки соперников (`name_conflict` P/06.5; раздел «Свежесть метки соперника»). Перенесено из P/04 Н1.4 (`resource_state`) и Н1.5 (сторона
читателя решения) без изменения поведения, кроме одного: граница свежести — одно отношение `≤` у всех наблюдателей
(«Свежесть» ниже; разбор ревью стадии A 6–7, № 1). Что наблюдатель делает с состоянием (судьба слота, пул, отказ вывода,
`live` процесса в `/schema`, `state` воркера в выдаче) — в нормах читающих уроков; форма наблюдаемых строк и объектов — у
их владельцев ([каталог](../data/catalog.tsv)).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Пульс ресурса `platform/resources/<s>/heartbeat` наблюдатель читает по форме и исходам семьи его писателя — файлам
`Platform/05-resource/data/resource-heartbeat.schema.json` и `Platform/05-resource/data/resource-heartbeat.outcomes.tsv`
([форма](../../05-resource/data/resource-heartbeat.schema.json), [исходы](../../05-resource/data/resource-heartbeat.outcomes.tsv));
строку двери `platform/doors/<s>` — по смене версии, её форма — `Platform/05-resource/data/doors.schema.json`, исходы —
`Platform/05-resource/data/doors.outcomes.tsv` ([форма](../../05-resource/data/doors.schema.json)). Названные файлы данных входят в чтение `common`
(ADR-0083 доп. (32) п. 1; C04-DEP-OBS-HEARTBEAT-01). Исходы — по `outcomes.tsv`: поле не по своей форме, у которого есть
строка исхода поля (`build`, `schema`, `retention_garbled`, `retention_withheld`), действует его исход, пульс остаётся
читаемым; нечитаемым пульс делает только исход «объект целиком» (в том числе поле вне закрытой формы).

Прочие формы, по которым читают наблюдатели (аудит раскладки, В-38–В-40, Б-16; решение «Архитектора» 2026-10-25): строка удержания места `<sub>/holds/<place>` —
`Platform/03-worker/data/holds.schema.json`, `Platform/03-worker/data/holds.outcomes.tsv`; пульс воркера `<sub>/heartbeats/<имя>`
— `Platform/03-worker/data/heartbeats.schema.json`, `Platform/03-worker/data/heartbeats.outcomes.tsv`; метка соперника
`<sub>/contenders/<имя>/<коробка>` — `Platform/03-worker/data/contenders.schema.json`,
`Platform/03-worker/data/contenders.outcomes.tsv`; строки решения `<sub>/controller/placement_intent` и `<sub>/placement/<id>`
— `Platform/04-controller/data/placement-intent.schema.json`, `Platform/04-controller/data/placement-intent.outcomes.tsv`,
`Platform/04-controller/data/placement.schema.json`, `Platform/04-controller/data/placement.outcomes.tsv`. Версия объекта
(раздел «Наблюдение версии» changed: заголовки `X-Server`, `X-Written`, в листинге `server`, `written`) — контракт двери
ресурса `Platform/05-resource/spec/05-resource.api.openapi.yaml` ([OpenAPI урока P/05](../../05-resource/spec/05-resource.api.openapi.yaml)).

## Наблюдение версии

```yaml
observer:  процесс-читатель со своей памятью наблюдения и своими монотонными часами; память не общая между
           наблюдателями и после перезапуска начинается заново (ADR-0049)
changed:   «менялся» — смена версии строки или объекта на глазах наблюдателя (индекс строки P/01.1 Н1, версия объекта
           P/05 Н1.1), а не значение поля времени в нём (`ts`, `at`, `until`): часы писателя свежесть не доказывают;
           версия объекта — пара (server, written), как её отдаёт дверь ресурса (заголовки X-Server, X-Written; в листинге
           — server, written): written — отметка ресурса при записи, строго растущая по ключу (P/05 Н1.1 written), не
           поле тела; та же пара — та же версия, иная — новая, даже при тех же байтах (догадка стадии C
           C06-OBJECT-VERSION-33-01, решение «Архитектора» 2026-10-23)
age:       возраст наблюдаемой версии — время по часам наблюдателя с момента, когда он впервые успешно прочёл текущую
           версию ([P/03.2 Н1.4](../../03-worker/spec/03.2-worker.norms.md) «возраст наблюдаемой версии»); первый
           взгляд, новая версия или изменённые байты — возраст 0; повторное чтение того же состояния и неответ хранилища
           возраст не обнуляют
first:     первое наблюдение — свежее: впервые увиденное «только что изменилось» (возраст 0); поэтому новый наблюдатель
           первые LOST_AFTER никого не считает молчащим (P/04 Н1.4а `fresh_controller`)
lapse:     неответ хранилища или подтверждённое отсутствие строки (объекта), прежде читавшейся, — не новая версия: возраст
           последней прочитанной версии и факт прежнего наблюдения не стираются и не обнуляются; вернулась та же версия —
           возраст идёт от её первого прочтения (догадка стадии C OBS-001 (Go), решение «Архитектора» 2026-10-23);
           суждение — по последней прочитанной версии, и по той, чьё тело не читается своей семьёй (garbled): неответ после
           неё держит garbled, строк прежней читаемой версии не воскрешает; возраст и жизнь — только по читаемым версиям:
           нечитаемая возраст не обнуляет и жизни не подтверждает (`live`, `unknown` ниже), возраст идёт от первого прочтения
           последней читаемой версии (C06-PULSE-LAPSE-GARBLED-01, решение Спецификации, уточнено по c-go 2026-10-29)
```

## Свежесть: `LOST_AFTER`

```yaml
LOST_AFTER:  45             # с; одна граница свежести у всех наблюдателей; литерал — здесь, уроки ссылаются (P/04 Н1.4 —
                            # и запас после SLOT_TERM у судьи; разбор ревью стадии B 6–7, № 46; аудит раскладки, решение «Архитектора» 2026-10-25, А-01, Б-01)
fresh:       источник свеж (слышен) — его версия менялась в последние LOST_AFTER: возраст наблюдаемой версии ≤ LOST_AFTER;
             возраст > LOST_AFTER — не свеж (молчит, устарел). Одно отношение у всех наблюдателей и выдач
             (разбор ревью стадии A 6–7, № 1)
```

Отношение одно для всех мест, где норма говорит «менялся в последние LOST_AFTER», «слышен», «живой» по пульсу, «свежий»
или «устаревший» пульс: `resource_state` ниже; живой воркер в выдаче консоли (`worker_state` строки `GET /{rows}`,
`WorkerRow.state` `/servers`); живые процессы `/schema` и подъёма схемы, «слышны» вывода сервера, свежесть пульса
дренажа (глава 6.6); ряд `w2c_resources_live` (глава 6.5); живые ресурсы слияния `/events` (глава 6.4). Прежние записи
«`< 45 с`», «`< LOST_AFTER`» у дверей консоли читаются по этому договору; где выдача давала `<`, это правка поведения на
одном шаге — возраст ровно LOST_AFTER: свеж. Граница проверяется вектором [`fresh-age`](../vectors/fresh-age/README.md):
чистая функция «возраст → свеж» со строками `LOST_AFTER − 1`, `= LOST_AFTER`, `+ 1` и дробными около границы (разбор
ревью стадии B 6–7, № 20: вектор вместо шага приёмки на границе, которого стенд без управляемых часов не делает).

## Удержание места

Перенесено из P/03.2 Н1.4 `places` (`HOLD_SKEW`) и P/03.7 (`domain_worker`) — у них ссылки сюда; суждение для читателя места
(консоль, `/where/<table>/<place>` P/06.5 Н3) — то же отношение к границе, что у берущего место (P/03.2 Н3 «взять_место»:
«простояло без изменений 45 + HOLD_SKEW») (догадка стадии C C06-WHERE-PLACE-HOLD-33-01, решение «Архитектора» 2026-10-25).

```yaml
HOLD_SKEW: 5          # с; запас к LOST_AFTER у удержания места и у слота воркера на домене (P/03.7)
active:    действующее удержание места — строка <sub>/holds/<place> по форме (holds.schema.json, раздел «Форма»), released ≠ true, holder непуст,
           возраст её наблюдаемой версии на монотонных часах наблюдателя < LOST_AFTER + HOLD_SKEW (при 50 — уже свободно),
           и пульс воркера by свеж (≤ LOST_AFTER, раздел «Свежесть») и называет экземпляр holder (поле instance); первое
           наблюдение — возраст 0 (раздел «Наблюдение версии» first); иначе удержание не действует
unknown:   строка удержания есть, но не читается (исход семьи holds), или пульс воркера by не читается — удержание не известно:
           ни действующим, ни снятым его не считают; консоль — /where/<table>/<place> 503 unavailable, held_by null, ряд unheld
           место свободным не считает (В7 п. 3, решение «Архитектора» 2026-10-28, П1; строка 27; класс строки 23 списка)
```

## Состояние ресурса (`resource_state`)

Ресурс сервера — одно определение для всех наблюдателей (контроллер, консоль), по их монотонным часам; «менялся» — смена
версии на глазах наблюдателя (раздел «Наблюдение версии»), первый взгляд — свежий; правила — по порядку, первое
совпавшее (сверка python и go 2026-10-18).

```yaml
resource_state:
  live:         пульс ресурса platform/resources/<s>/heartbeat читается и менялся в последние LOST_AFTER; нечитаемый
                пульс жизни не подтверждает, и его смена — тоже; последнее чтение пульса — неответ или подтверждённое
                отсутствие — live не даёт (lapse; OBS-001)
  unreachable:  пульс не live (в том числе нечитаемый), строка двери platform/doors/<s> менялась в последние LOST_AFTER —
                ресурс есть, пульсов нет; прежде прочитанная строка двери при неответе или подтверждённом отсутствии
                остаётся основанием до той же границы — возраст её последней версии ≤ LOST_AFTER, нового отсчёта нет
                (lapse; OBS-001)
  unknown:      наблюдатель не видел ни читаемого пульса, ни строки двери ни разу: нечитаемый пульс увиденным не
                считается (сверка python и go М10/6–11, C13); прочитанное прежде и пропавшее — увидено (lapse)
  silent:       иначе; исключает и двигает только silent
ALIVE_EVERY:    15           # с; ресурс переписывает at своей строки двери platform/doors/<s> (P/05 Н1.4 door_row) — так
                             # строка двери меняется и при молчащем пульсе (перенесено из P/04 Н1.4; аудит раскладки, решение «Архитектора» 2026-10-25, А-10)
```

Нечитаемый пульс — по форме его писателя (раздел «Форма» выше; [P/05 Н1.4](../../05-resource/spec/05-resource.norms.md)); строку двери
наблюдатель судит по смене её версии, не по полям (семья `doors` P/05). Что значит каждое состояние для судьбы слота и
пула — [P/04 Н3](../../04-controller/spec/04-controller.norms.md) «судьба», «выбрать»; для выдачи `ServerRow.resource` —
глава 6.5; для отказа вывода сервера — глава 6.6. Состояние по истории наблюдения — векторы
[`resource-state`](../vectors/resource-state/README.md).

## Свежесть члена домена

Перенесено из [P/08.1](../../08-domain/spec/08.1-domain.norms.md) Н1.3 `member_state` без изменения (аудит раскладки, решение «Архитектора» 2026-10-25, А-15); читатели —
процесс `domain` (вид, P/08.1) и консоль домена (P/10 Н3 `alarms`: `silent` по последнему отчёту и `LOST_AFTER`).

```yaml
member_state:                                    # по монотонным часам держателя, «смена» — смена байтов метки `reported`
                                                 # (P/08.3 Н1.3): новый rev или освежение того же rev (received_at)
  ok:        смену метки этот процесс держателя видел, последняя — в пределах LOST_AFTER
  unseen:    метка есть, но смены этот процесс держателя ещё не видел и с первого взгляда прошло не больше LOST_AFTER;
             живой член выходит в ok не позже LOST_AFTER/2 (метка обновляется не реже, P/08.3 Н1.3)
  silent:    смена была и не повторялась дольше LOST_AFTER, или смены нет дольше LOST_AFTER с первого взгляда; или метка,
             которую этот процесс видел, пропала — сразу silent с прежней копией (её единицы — silent), возраст — с
             последней виденной смены; вернувшаяся метка — как любая: байты отличны от последних виденных — смена
  never:     член принят, метки этот процесс не видел ни разу (пропавшая после виденной — silent, не never)
  leave:     член ушёл из списка (P/08.3 Н2 DELETE) — процесс забывает его память (метку, копию, первый взгляд, пульсы);
             вернувшийся — первый взгляд заново (unseen)
  # пропажа, never и уход — добавлено сверкой М11 (V1–V3)
```

## Чтение решения: intent → placement → intent

Эффективное размещение единицы читается по строкам контроллера `<sub>/controller/placement_intent` и `<sub>/placement/<id>`
(форма — семьи `placement-intent`, `placement`: `Platform/04-controller/data/placement-intent.schema.json`,
`Platform/04-controller/data/placement.schema.json` и их `.outcomes.tsv`, раздел «Форма»; сторона писателя — [P/04](../../04-controller/spec/04-controller.norms.md) Н1.5).
Правило одно для всех читателей: контроллера, `/where`, `/unplaceable`, прогнозов меток, дренажа.

```
прочитать intent → нужные placement → снова intent; версия intent изменилась → повторить чтение;
только одинаковые версии intent дают результат
нужные placement при active — все строки placement, которые читатель запросил для ответа, читаются между двумя
  чтениями intent; подтверждённое отсутствие строки допустимо; неподтверждённое чтение или нечитаемая строка —
  исход unavailable (догадка стадии C OBS-002, решение «Архитектора» 2026-10-23)
active intent и id в members → решают target/reason/at/manifest_rev intent; отсутствие placement не отменяет target активного
  intent; иначе — worker/reason строки placement
обязательное чтение не подтверждено → результата нет (у дверей консоли — 503 unavailable); неподтверждённое чтение не
  означает idle
строка intent не по форме (state не active/idle; у active нет members, target, reason, at или они не по форме) —
  нечитаемая: читатели — 503 unavailable, не idle; контроллер — отказ с failures (P/04 Н1.5, Н4)
```

Одним HTTP-чтением не обещан атомарный снимок всей подсистемы: эффективное размещение и пульс держателя читаются
отдельно, ответ называет наблюдённого держателя. Idle сохраняется писателем, чтобы версия intent не возвращалась к версии
отсутствия между двумя чтениями (сторона писателя — P/04 Н1.5).

## Свежесть метки соперника: `CONTENDER_FRESH`

Перенесено из P/03.2 Н1.2, Н1.4а (у них ссылка сюда); `CONTEND_EVERY` — как часто писатель переписывает свою метку —
остаётся у писателя (P/03.2 Н1.2). Читатель — консоль: `WorkerRow.name_conflict` `/servers`, ряд `name_conflicts`
([P/06.5](../../06-console/spec/06.5-console.norms.md) Н2, Н3) (C06-CONTENDER-FRESH-33-01, решение «Архитектора» 2026-10-25).

```yaml
CONTENDER_FRESH: 300   # с; граница свежести метки соперника
contender: метка соперника <sub>/contenders/<имя>/<коробка> (contenders.schema.json, раздел «Форма») свежа — возраст её наблюдаемой версии
           (раздел «Наблюдение версии» age) на монотонных часах читателя ≤ CONTENDER_FRESH; первый взгляд — возраст 0
```
