# Договор очереди писателя: строка очереди, сроки, страж, барьер

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): один изменяющий писатель в каждый момент — у контроллера
подсистемы и у процесса `domain` держателя, один алгоритм — договор, а не копии в главах; аудит раскладки А-03, решение
«Архитектора» 2026-10-25). Владелец — урок [P/04](../../04-controller/spec/04-controller.norms.md) (Н1.5 «Допуск размещения
между контроллерами», Н3 «получить и удерживать очередь размещения»). Участники: контроллер — строка
`<sub>/controller/placement_turn` (P/04); процесс `domain` у держателя — строка `domain/signer-turn`
([P/08.10](../../08-domain/spec/08.10-domain.norms.md) Н1.7, Н3).

Перенесено из P/04 Н1.5 (`TURN_TERM`, `TURN_RENEW`) и Н3 «получить и удерживать очередь размещения» (шаги, барьер,
«Гонки») без изменения поведения; P/04 и P/08.10 — ссылкой сюда. Что у каждого участника своё — ключ строки, метка
`holder`, какие записи идут под стражем, когда очередь отдаётся, — у участника (P/04 Н1.5, Н3; P/08.10 Н1.7).

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Форма

Строка очереди контроллера — семья `placement-turn`: форма `Platform/04-controller/data/placement-turn.form.yaml`, исходы
`Platform/04-controller/data/placement-turn.outcomes.tsv`; строка очереди процесса `domain` — семья `signer-turn`:
`Platform/08-domain/data/signer-turn.form.yaml`, `Platform/08-domain/data/signer-turn.outcomes.tsv`. Операции `cas` и
`guard` — [договор клиента хранилища](store-client.md).

## Сроки

```yaml
TURN_TERM: 45                         # возраст неизменной версии на часах претендента
TURN_RENEW: 10                        # продление между операциями; срок своего запроса — монотонный
```

## Получить и удерживать очередь

Шаги — как у контроллера (P/04 Н3); `<turn>` — строка очереди участника, «изменяющая запись» — записи, которые участник
ведёт под стражем (у контроллера — P/04 Н3 «получить и удерживать очередь размещения» шаг 5, у процесса `domain` — P/08.10
Н1.7 `guard`):

```
1. прочитать <turn>; нечитаема → отказ шага; manifest_rev > моя → не менять, manifest_behind (manifest_rev — только у
   очереди подсистемы placement_turn; у domain/signer-turn ревизии нет и не проверяется; TURN-FORM-32-01, решение «Архитектора» 2026-10-25)
2. строки нет → cas ""; holder пуст → cas прочитанной версии;
   holder чужой и эта версия не менялась ≥ TURN_TERM по моим часам → cas прочитанной версии;
   иначе очередь занята, этот проход не меняет размещения; следующий попробует снова
3. записать {holder: новая уникальная метка этой попытки, manifest_rev: моя} с выбранным cas (domain/signer-turn — только
   {holder}, TURN-FORM-32-01, решение «Архитектора» 2026-10-25);
   conflict → очередь не получена; подтверждено → запомнить версию turn и время отправки запроса
4. каждые TURN_RENEW, между операциями: переписать свою строку turn с cas своей версии;
   подтверждено → новый guard и начало своего срока от отправки; conflict/чужой holder → прекратить записи
5. пока свой подтверждённый запрос моложе TURN_TERM, каждая изменяющая запись имеет cas целевой строки И
   guard {key: <turn>, index: моя версия};
   истёк свой срок → не писать до подтверждённого продления; 412 → прекратить текущую попытку
6. завершение прохода: записать holder: "" с cas своей версии; конфликт не повторять
```

## Различия очередей

Сроки (`TURN_TERM`, `TURN_RENEW`), `cas`, страж, отдача и барьер — общие; различия (TURN-FORM-32-01, решение «Архитектора» 2026-10-25):

| | Очередь подсистемы | Очередь процесса `domain` |
|---|---|---|
| строка | `<sub>/controller/placement_turn` (P/04 Н1.5) | `domain/signer-turn` (P/08.10 Н1.7) |
| форма | `{holder, manifest_rev}` | `{holder}` — ревизии нет и не проверяется |
| `holder` | новая уникальная метка каждой попытки | экземпляр процесса ([договор экземпляра](instance.md)); свою строку переписывает CAS прочитанной версии (P/08.10 Н3 шаг 2) |
| шаг 1 `manifest_rev > моя` | не менять, `manifest_behind` | не применяется |
| под стражем | запись и удаление `placement/*`, `workers/*`, `placement_intent`, удаление строки единицы по `delete_after` (P/04 Н3) | каждая запись процесса в строку хранилища держателя (P/08.10 Н1.7 `guard`) |
| отдача | в конце прохода (шаг 6) | по SIGTERM активным процессом (P/08.10 Н1.7 `release`) |
| не получена | проход не меняет размещения | процесс ждущий, `standby` (P/08.10 Н3) |

## Барьер

Любой неответ, неизвестный исход, конфликт или 412 при изменении размещения прерывает
текущий план действий в памяти. Прежде чем продолжить, контроллер подтверждённо меняет версию
своего turn с cas (если holder уже чужой — останавливается), затем заново читает intent и строки.
Этот барьер отсекает и ещё летящую старую запись: она либо применена до барьера и видна чтению,
либо получает 412 после него. Неответ самого барьера запрещает продолжение. Нельзя просто
подставить более новую версию стража в прежнюю команду. Два изменяющих прохода одного процесса
тоже не идут одновременно под одним turn; продление не выполняется параллельно целевой записи.

**Гонки.** Из двух cas захвата проходит один. Новый держатель после захвата читает мир заново;
поздние изменяющие записи старого держателя отказаны стражем turn, даже если целевая строка не менялась. Старый держатель
не продлевает и не освобождает чужой turn своим cas. Новому наблюдателю чужой turn сначала свежий; ожидание не зависит от
часов прежнего держателя. Время отправки своего подтверждённого запроса — время первой отправки этой логической записи;
повтор с тем же id и ответ again его не сдвигают (то же правило у слота и аренды, P/03.2). Пропавший держатель задерживает
изменения максимум до следующей успешной попытки после окна наблюдения, но срок ответа недоступного хранилища этим не
ограничивается.

## Векторы

Пакет [`turn`](../vectors/turn/README.md) (C08-TURN-SELF-99, решение «Архитектора» 2026-10-26): последовательности событий
одной стороны над строкой очереди и её действия — взять пустую или отданную, своя строка процесса `domain` (`held`, не
`busy`), чужая живая — занята, чужая старше `TURN_TERM` — взять, `manifest_rev` (шаг 1), продление, страж, 412, барьер при
неизвестном исходе, отдача `holder ""`; оба вида очереди. Гонки двух претендентов и поздние записи старого держателя —
сценарии приёмки участников (P/04, P/08.10) и чтение.
