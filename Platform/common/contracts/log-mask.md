# Договор маски журнала: свободный текст лога с маской

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): маску пишут в журнал все процессы платформы — консоль,
воркер, ресурс, процессы домена, — договор, а не копии в главах; догадка стадии C C06-LOG-MASK-33-01, решение
«Архитектора» 2026-10-25). Владелец — глава [P/06.2](../../06-console/spec/06.2-console.norms.md) консоли (Н1.4 `never`
`log`). Участники — все процессы платформы, которые пишут лог (id-map: М10/7-08 → P/06.2-05, «все процессы»). Разбор
адреса, пар и правила поля — [договор адреса](url-credentials.md) (А1–А15); здесь — функция маски свободного текста
целиком.

Перенесено из P/06.2 Н1.4 `log` и строк договора адреса о свободном тексте (А1, А2) без изменения поведения; P/06.2 и
договор адреса — ссылкой сюда.

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md).

## Функция

```yaml
mask_log:  маска(текст, каталог) → текст: вход — свободный текст, не значение поля (строка лога, ошибка, документ JSON,
           строка подключения); выход — тот же текст, где учётные данные заголовков, значения пар с секретным именем и
           пароли в адресах заменены маской "***"; прочее — байт в байт
rule:      правило каталога — объединение правил (credentials, secret_in) всех полей type: url каталога манифестов
           процесса с общим словарём common_words (договор адреса «Правило поля и общий словарь»): имена, которые
           добавляет манифест, — секретные имена тоже
```

## Что маскируется

```yaml
header:    заголовки Authorization и Proxy-Authorization (имя заголовка — без учёта регистра) со схемой Basic или Bearer
           (схема — без учёта регистра): учётные данные после схемы → "***" (ревью стадии A, SA1-18, SA1-23); иная схема
           (Digest) остаётся как есть; учётные данные тянутся до первого пробельного знака (space ниже) или конца строки:
           прилипшее к ним (запятая, кавычка вплотную) маскируется вместе — перемаскировать безопасно, недомаскировать
           нет (C06-LOG-MASK-33-01, ответ «Архитектора» 2026-10-25 (1))
pair:      пара `имя=значение` с секретным именем — по договору адреса А1 (имя — буквы, цифры, `_ . - %` и знаки вне ASCII
           перед `=`; значение — до `&`, `;`, `,` или пробела), А5 (секрет раньше логина), А6 (значение пары секрета
           маскируется до конца значения, адрес в нём — тоже, `<` значение не обрывает), А7 (пара, скрытая экранированием,
           — значение целиком; имя, раскодированное в пары, уходит со значением); пустое значение остаётся пустым
json:      пара JSON `"имя": значение` с секретным именем (пробелы вокруг `:` допустимы): скаляр значения, строка — до её
           закрывающей неэкранированной кавычки, заменяется на "***"; пустая строка остаётся пустой; скаляр — одна лексема
           JSON (число, true, false, null), знак за ней остаётся: {"password": 1234;} → {"password": "***";} (сверка python
           и go М10/6–11, S18)
address:   адрес в тексте — по договору адреса А1–А15 (пароль в userinfo, в паре, в голове, во вложенном адресе — маска там,
           где стоит; логин показывается как написан); в свободном тексте адрес кончается на пробеле, кавычке, `\`, `<`
           или `>` (А2)
space:     «пробел» в концах адреса (А2) и значения пары (А1) в маске журнала — любой знак со свойством White_Space
           Unicode 15.0.0 (U+0009–U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F,
           U+3000), как mask_in P/06.2 Н1.1 и имя человека P/08.4 Н1.1 (C06-LOG-MASK-33-01, ответ «Архитектора» 2026-10-25 (2))
```

## Что остаётся как есть

Всё, что не учётные данные заголовка Basic/Bearer, не значение пары с секретным именем и не пароль адреса: логин, пустое
значение, хэш Digest, пары без секретного имени, адрес без пароля — байт в байт.

## Где действует

Каждая строка журнала (лога) процесса платформы — P/06.2 Н1.4 `never` `log`. Журнал `audit`, пульс, снимок, argv и текст
отказа значений не содержат вовсе (P/06.2 Н1.4 `never`) — это правило мест записи, не маска.
