## Ключ по шаблону (V7-FAMILY-KEY-PLACEHOLDER-01)

[`key-placeholders.tsv`](../../data/key-placeholders.tsv) — канонический типизированный вход читателей и генераторов; первая таблица ниже представляет те же грамматики и примеры. Словарь перевода для человека в `ru/placeholders.tsv` не является входом генерации. `<host>` и `<server>`, а также `<object-key>` и `<key>` сохраняют разные грамматики.

Колонка `key` каталога — шаблон ключа: литералы и плейсхолдеры `<…>` (и `*` — любой ключ под префиксом). Ключ
экземпляра принадлежит семье, если совпадает с шаблоном целиком: литералы — точно, плейсхолдер — полным совпадением
грамматики первой таблицы ниже на подстроке ключа, которую он занимает (переносимое выражение `^(?:…)$`, [LAYERS.md](../LAYERS.md)
§ 3 «Expression»; `/` — только если грамматика его берёт). У плейсхолдера, чья норма своей грамматики не даёт, —
непустой компонент `[^/]+`, у корня — абсолютный путь, у пути и ключа объекта — непустые компоненты (выбор генератора,
принятый «Архитектором»). Где плейсхолдер значит разное по семьям (`<name>`, `<id>`), ключ судится объединением, а
писатель пишет по норме своей семьи (вторая таблица). Ограничения, которых переносимое выражение не держит
(зарезервированные слова, `free-…`, длина в байтах), ключом не судятся — их держит норма писателя.

`<manifest:X>` — значение ключа `X` манифеста подсистемы `<sub>`; ключ судится грамматикой значения, манифест не
читается. Ключ не по шаблону — отказ на пустом пути `""`, значение не судится ([LAYERS.md](../LAYERS.md) § 6). Пример —
подстановка, которой векторы [`family-read`](../vectors/family-read/README.md) строят столбец `key` строк с ключом по
шаблону.
