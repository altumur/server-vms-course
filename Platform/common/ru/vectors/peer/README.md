# Векторы `peer`

Текст производный от `vectors/peer/README.md`, руками не правится: источник — английский [`vectors/peer/README.md`](../../../vectors/peer/README.md), правка идёт в него, русский пересобирается переводом.

[Договор `peer`](../../contracts/peer.md) задаёт функцию, которой клиент принимает сервер двери `https://`: отпечаток якоря, путь подписей, сроки сертификатов, роль листа и имя хоста. Владелец — P/09.

## Прогон

Вход функции — объект JSON `{chain: [<PEM>…], fingerprints: [<hex>…], role, host, now}`. `chain` — цепочка сертификатов, полученная от сервера, в порядке сервера, начиная с листа. `fingerprints` содержит доверенные отпечатки центров: sha256 hex DER сертификата центра. `role` — ожидаемая роль листа; `host` — имя адресата; `now` задаёт время проверки сроков сертификатов вместо часов процесса.

Адаптер проверяет форму входа перед вызовом. Поля доверенного входа `fingerprints`, `role`, `host` и `now` обязательны; при отсутствии обязательных полей нативный код выхода — 2, stdout не сравнивается. Это следует правилу доверенного входа в [командах-векторах домена](../../acceptance/domain-stand.md#команды-векторы-домена).

Полученный `chain` оценивает функция, а не отвергает как ошибку формы доверенного входа. Действует порядок договора: сначала проверка хоста; затем цепочка, которая не является непустым списком читаемых сертификатов PEM, даёт `bad_chain` с нативным кодом выхода 0. Каждый элемент — ровно один блок CERTIFICATE со строгим base64 и целиком разобранным DER. Пустой список `fingerprints` — вход функции; договор проверяет его после формы цепочки.

Нативный вывод при коде выхода 0 — объект JSON `{"result":"ok"}` или `{"result":"refused","reason":<word>}`. Словарь отказов: `ip_address`, `bad_chain`, `foreign_ca`, `expired`, `no_role`, `wrong_role`, `wrong_name`. Проверка нативной формы проверяет настоящий объект JSON, который вернула реализация. Судья сравнивает подмножество его полей; ожидаемый ответ не является входом функции.

## Кто исполняет

Функцию исполняют клиенты другого кластера: агент и ретранслятор (`09-agent`), консоль кластера (`06-console`) и процесс `domain` (`08-domain`). Консоль домена (`10-domain-console`) как сервер класса `role` исполняет проверки роли листа, шаги 6–7, над листом клиента. Роль исполняет проверки функции, которые вызывает её норма.
