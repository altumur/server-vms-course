# Форма провода векторов

Текст производный от `vectors/wire.md`, руками не правится: источник — английский [`vectors/wire.md`](../../vectors/wire.md); перевод — для человека, не в выгрузке (ADR-0121; ADR-0124).

Норма — [`wire.tsv`](../../vectors/wire.tsv) вместе с `wire.cases.tsv`, по решению Архитектора в рамках ADR-0125 доп. (1) п. 5 и доп. (5): одна форма в двух файлах с одной грамматикой. В `wire.cases.tsv` — строки, чьи ячейки несут значения из таблиц случаев стороны судьи, например имена случаев или входные значения этих таблиц; он на стороне судьи. Ссылка на поле строки по имени столбца или слово закрытого словаря пакета — не такое значение: строка, где есть только такие ссылки, остаётся в `wire.tsv` (ответ «Архитектора» по ревью P01.87). Тройка `(package,table,surface)` единственна по обоим файлам (ответ «Архитектора» по P01.86). Начальный срез охватывает таблицы векторов P/01 и P/02; последующие объявленные строки расширяют реестр. Нет объявления — нет объявленного адаптера, а не выполненная проверка. Пробы write-checks в формах P/01 судятся своей таблицей проверок и грамматикой проб, через конверт [провода write-checks P/01](#провод-write-checks-p01) ниже — строку формы [`probe-tables.tsv`](../../vectors/probe-tables.tsv); строки в этой форме у них нет. В README пакета остаются алгоритм, обязанность потребителя, смысл входов и нативных полей, чтение и стендовые проверки за пределами функции. Провод задаётся ссылкой на форму, без второго объявления.

## Строки и источники

```text
package	table	surface	header	inputs	files	expect	compare	markers	native	norm
```

Колонки разделены literal TAB без CSV-кавычек. UTF-8 и LF; пустые строки и строки с `#` в начале пропускаются; первая прочая строка — шапка. Тройка `(package,table,surface)` уникальна. `package` — путь от Platform без vectors/; `table` — имя существующего TSV в пакете. `norm` — путь существующего источника `.md` от Platform, необязательно с `#` и существующим якорем заголовка.

`surface` — `vectors`, `stand:<key>` профиля процесса или `layout`. Последнее явно исключено из исполнения функции: `inputs`, `expect`, `markers` — `[]`, `files` — `{}`, `compare` и `native` — `-`. Это не доказывает проверку раскладки и не становится PASS функции.

`header` — имена колонок в исходном порядке через запятую. Без исходной шапки первый элемент — `-`, за ним позиционные имена, например `-,raw,masked,note`. Реальная шапка либо число позиционных полей должны совпадать. Кавычка в ячейке исходного TSV — байт ячейки, не синтаксис CSV.

`inputs`, `files`, `expect`, `markers` и `native` вне layout — строгий JSON в одной ячейке. Повторы ключей JSON, BOM, NaN и Infinity — ошибки. Кадр единой команды и существующие шаблоны stand остаются по [общему README приёмки](../acceptance/README.md).

## Выбор входов и группы

```text
{"variant":"","when":"true","case":"case","cells":{"input":{"column":"input"}}}
```

`inputs` — непустой массив объявлений. В каждом строковый `variant` (пустой, read, write либо другое опубликованное имя), необязательный булев CEL `when` (по умолчанию true), необязательный `case` и ровно одно из `cells` или `arg_file`. Входы CEL — `row: map<string,string>` и `owner: string`, расширение strings. Исходные ячейки сохраняют точные строки. `owner` — каталог урока. Для common он должен быть назначен в `consumers.tsv`; условие не добавляет чужого потребителя. Форму входа нативной функции проверяет адаптер, не селектор.

Множество потребителей — явные строки consumers.tsv в объединении с уроком-владельцем каталога пакета урока. Колонка package — полный путь `(common|NN-name)/name` от Platform без vectors/, ровно как в wire.tsv; NN-name обязан быть каталогом урока из lessons.tsv. У common нет неявного урока. Повтор (package, table, lesson), неизвестный урок, пакет или таблица — ошибка формы. Условие when не может добавить чужого потребителя. Межурочные строки JCS, rid, request-digest и requests-body записывают уже опубликованные обязанности README, новых функций не назначают. У requests-body нативная привязка функции — только строки request воркера; полная отдельная обязанность HTTP-стенда консоли сохраняется.

Выбор — на вариант: строку выбирает не более одного входного объявления данного варианта. У выбранного варианта ровно одно ожидание и нативное объявление. Направление both может выбрать два варианта; чужой владелец или направление — ни одного, и этой строки нет в описи цели: закрытого исхода для исключённой строки нет. Нет объявления — не PASS. Варианты идут в порядке объявлений в вызовах и описи; это не приоритет алгоритма.

`case` — имя колонки, `{"line":true}` для физического `line-<number>` либо `{"literal":"name"}`. По умолчанию — колонка case, затем id, иначе физическая строка. Идентичность вызова `(owner,package,table,surface,variant,case)` уникальна: дубли — ошибка, без добавления суффикса номера строки. Это не вход алгоритма.

Для `vectors` отображение `cells` задаёт ячейки провода ровно через `{"column":"name"}` либо `{"literal":"string"}`. Каждый результат — строка: исходная ячейка или литерал без разбора, повторного кодирования и ожиданий. В частности rotate — строка `"true"`.

Для `stand:<key>` значение `arg_file` — ровно `{"column":"name"}`, `{"literal":"text"}` либо `{"path_column":"input","base":"root"}`. Первые два пишут точные UTF-8-байты во временный файл; последнее разрешает существующую фикстуру. Шаблон профиля получает её путь в `{input}`. `files` этой поверхности — `{}`: дополнительный транспорт не подразумевается. Shell-команд в форме нет.

Необязательный `group_by` — массив имён колонок: нет ключа — на строку; `["list"]` группирует равные list; `[]` даёт одну группу выбранной таблицы. Сначала фильтр входного when, затем группы, затем один вызов на группу и вариант. Ключи групп сортируются по UTF-8; строки сохраняют исходный порядок. Все построчные вычисления `when` в ожидании, native или файле должны совпадать на каждой строке группы. Ячейка, case либо подстановка пути из колонки должны быть постоянны в группе. Неявного выбора первой строки нет.

Опись групповых вызовов — [P/AC-R008](../acceptance/spec/acceptance.norms.md#n14-вердикт-цели); поверхности целей и вызываемые интерфейсы — [P/AC-R006](../acceptance/spec/acceptance.norms.md#n13-реестр-целей) и [форма целей](../acceptance/runner-targets.README.md).

## Фикстуры и значения

```text
{"in.yaml":{"base":"package","path":"inputs/{id}.yaml","when":"true"}}
```

`files` отображает имена фикстур на объекты с `base`, `path` и необязательным `when`. База `package` — каталог пакета, `root` — корень выгрузки. В пути разрешена подстановка `{column}`. Допустим только разрешённый путь внутри выгрузки, включая относительный переход к родителю, остающийся внутри неё. Нет файла, нечитаемый файл, абсолютный путь или выход из выгрузки — ошибка preflight. Байты фикстуры копируются точно. Фикстуры ожиданий сюда не попадают.

`expect` — массив объявлений с `variant`, необязательным `when`, `code` (целый нативный код 0..255), `value` и необязательным `assert`. Код — декодированный exit_code для vectors и код команды для stand; внешний wrapper vectors по-прежнему выходит с 0. У ValueExpr ровно один конструктор из следующего закрытого списка.

```text
{"column":"expect","decode":"cell|json|text"}
{"literal":<JSON value>}
{"object":{"field":<ValueExpr>}}
{"array":[<ValueExpr>]}
{"file":{"base":"package|root","path":"expect/{case}.json"},"decode":"bytes|text|json"}
{"file":{"base":"package|root","path_column":"expect"},"decode":"bytes|text|json"}
{"group":{"column":"word","decode":"text|json|cell"}}
{"groups":{"by":"list","column":"word","decode":"text|json|cell"}}
{"suffix":true,"decode":"text|json|cell"}
{"omit":true}
{"at":{"value":<ValueExpr column или literal>,"pointer":"/tags"},"decode":"json"}
```

`text` сохраняет ячейку строкой. `json` требует ровно одно строгое JSON-значение. `cell` читает строгий JSON, если он является JSON, иначе исходную строку. Text обязателен для строковых областей: hex ключей, seed или имён без кавычек, похожих на JSON. Смесь JSON и сырых слов разрешается опубликованной нативной формой со сверкой type/schema, а не универсальным угадыванием преобразования.

`file` — фикстура ожидания на стороне судьи с теми же правилами путей; bytes — точные байты файла, text — строгий UTF-8, json — строгий JSON. `group` собирает значения текущей группы; `groups` строит объект по колонке by. Оба требуют group_by. `suffix` — только остаток совпавшего префикса маркера. `omit` — только отсутствие поля object, не корневое значение и не null. Конструкторы читают данные и не вычисляют алгоритм реализации.

## Сравнение и утверждения

Закрытый список `compare` — `value|subset|raw|set|object-sets|lines-value|lines-subset|turn`; `-` — только layout. Это одна строка либо объект от имён вариантов к таким строкам. Value сравнивает JSON по значению с сохранением типов (числовое 1 равно 1.0, bool не число). Subset рекурсивно сравнивает поля объекта; пустой объект на любой глубине ровно пуст, а не любой объект. Raw сравнивает нативные байты либо UTF-8-байты декодированной нативной JSON-строки. Set сравнивает массив как множество JSON-значений без порядка и повторов. Object-sets требует ровно ожидаемые ключи объекта и сравнивает каждый массив как set. Lines-value и lines-subset сравнивают полные JSON Lines по порядку с обязательным конечным LF.

```text
{"pointer":"/row","test":"prefix","value":{"literal":"enc:v2:"}}
{"pointer":"/plaintext","test":"absent"}
{"pointer":"/text","test":"no-leak","value":{"array":[{"literal":"fixture-password"}]},"min_bytes":4,"whole":true}
{"pointer":"/row","decode":"json","compare":"value","value":<ValueExpr>}
```

`assert` — массив над нативным ответом. Pointer — JSON Pointer. Закрытый список `test` — `prefix|absent|no-leak`. Prefix требует строку с точным префиксом; absent — отсутствия указателя. Без test значение по указателю сравнивается по указанному compare, по умолчанию — сравнению объявления без lines. Необязательный decode json разбирает JSON внутри строкового поля, не кадр провода. Нет указателя — провал, кроме absent. Утверждения не попадают во вход SUT. Утверждение no-leak по решению Архитектора имеет `pointer`, `test` со значением no-leak, `value` (строка либо массив секретных строк) и `min_bytes` (целое не меньше 1). В UTF-8 текста по pointer нет ни одной подстроки любого секрета длиной не меньше min_bytes байт. Необязательный boolean `whole` (по умолчанию false) допустим только у no-leak: false запрещает любой такой фрагмент; true — вхождение целого секрета, только если его полная длина UTF-8 не меньше min_bytes (короче — не судится). Secret-in P/03 и P/06 используют whole true по README Run п. 3. Это утверждение над ответом, не секретный вход реализации.

## Маркеры и нативный кадр

```text
{"variant":"","column":"expect","match":"@exit 2","code":2,"ignore_stdout":true}
{"variant":"write","column":"row","match":"@refuse ","prefix":true,"code":0,"compare":"subset","value":{"object":{"status":{"literal":"refused"},"fault":{"suffix":true,"decode":"text"}}}}
```

`markers` — массив в порядке проверки. Match — по сырой колонке и точному варианту до разбора; по умолчанию вся ячейка, prefix true — точный префикс с остатком suffix. Первое совпадение может переопределить code, ignore_stdout, value, compare и assert. Маркер в JSON-кавычках — обычные данные. Без явного объявления слово с at-знаком не угадывается как код выхода. В частности refusal/bad/skip могут быть нативными JSON-строками. ignore_stdout true отключает содержимое stdout, frame и schema, сохраняя проверку нативного кода.

```text
{"type":"object|array|string|number|boolean|null|value|bytes","frame":"json|json-lf|raw","schema":<optional Draft 2020-12 JSON Schema>}
```

`native` — дескриптор либо массив дескрипторов с variant/when; для выбранного входа подходит ровно один. Type — одно слово списка либо массив слов JSON-типов; value — любое JSON-значение. Bytes требует raw без schema. Json разрешает JSON-пробелы вокруг одного значения. Json-lf требует отсутствие байтов перед значением и ровно LF с концом после него (объект поэтому начинается открывающей фигурной скобкой); внутреннее форматирование JSON разрешено. Разбор строгий, без BOM, NaN/Infinity и повторов ключей. Для vectors это декодированный payload stdout_b64, не внешний wrapper. Необязательная schema всегда проверяет полный фактический нативный ответ, также при subset и lines-subset. Статическая проверка полного ожидаемого значения может прямо применить schema; ожидание-подмножество не обязано содержать неупомянутые required поля ответа. Статически проверяются только объявленные поля и утверждения там, где их значения известны. Schema — данные, не алгоритм. Игнорируемый stdout не разбирается.

## Примеры первого среза

Настоящие строки — исполняемые объявления: log-mask сохраняет masked как декодированную JSON-строку и сравнивает байты; family-read сравнивает paths как set, массивы reader outcome — как множества; sealing ring добавляет rotate только установщику на rotate-случаях; yaml-suite передаёт in.yaml и судит только layer1; canonical разрешает существующий манифест и сравнивает байты файла ожидания. Stand-объявления exec и install-order используют json-lf и различают отказ нативной формы и успешный объект отказа правила. У platform-lists два независимых объявления: vectors группирует по list и возвращает массив на группу; stand:platform-lists группирует всю таблицу и возвращает объект множеств. Journal modes — layout.

## Конструкторы транспорта P/06

Эти расширения — решение Архитектора по ADR-0125 доп. (5). Списки argument/file и ValueExpr выше дополнены только объявленным здесь; прочие ключи и конструкторы остаются закрытыми.

У stand `arg_file` также допускает ровно `{"json": <ValueExpr>}`. Выражение вычисляется как JSON-значение, в файл аргумента пишется один документ JSON. В этом конструкторе ValueExpr допускает только column (text/json/raw-json), literal, object и array; file/group/groups/map/suffix/omit/at запрещены. Только внутри этого конструктора исходная входная колонка может иметь `decode: "raw-json"`: проверить один строгий документ JSON и вставить его исходную JSON-лексему как фрагмент, без нормализации и decode/re-encode. Проверяется синтаксис JSON, не допустимая форма нативной функции: нестроковый rid по-прежнему доходит до неё. Колонка ожидания не попадает в файл аргумента. Обычный decode json даёт разобранное значение; raw-json запрещён вне этого конструктора, в том числе в ожиданиях и фикстурах.

```text
{"json":{"object":{"rid":{"column":"rid","decode":"raw-json"}}}}
{"json":{"object":{"sender":{"column":"sender","decode":"text"},"input":{"column":"input","decode":"text"}}}}
{"map":{"key":"word","value":{"column":"status","decode":"json"}}}
```

ValueExpr `at` имеет ровно value и pointer внутри at и необязательный внешний decode. Value — только ValueExpr column или literal по существующим правилам их декодирования; вложенный at и все прочие конструкторы запрещены. Pointer — непустой JSON Pointer RFC 6901, начинается с `/`; неверные escape-последовательности и отсутствие выбранного пути — ошибки данных формы. Из разобранного источника выбирается это значение, затем может применяться внешний `decode: "json"`: выбранное значение обязано быть строкой и содержать ровно один строгий JSON-документ. Другой внешний decode запрещён. Конструктор допустим только в ожиданиях, assert и маркерах, никогда во входных cells или arg_file.json. Если value — колонка, статическая проверка формы также разрешает pointer по фактическим строкам таблицы. Например, ожидание row-check выбирает JSON-строку по `/tags` из колонки row без копирования второго золотого массива:

```text
{"at":{"value":{"column":"row","decode":"json"},"pointer":"/tags"},"decode":"json"}
```

ValueExpr `map` имеет ровно key (исходная колонка) и value (ValueExpr), требует group_by. На каждой строке текущей группы сырая ячейка key даёт ключ объекта, value вычисляется на этой строке. Повтор ключа — ошибка данных даже при равном значении. Порядок объекта не значим; конструктор не исполняет алгоритм реализации.

Ожидание и assert без test могут объявить `ignore: [<JSON Pointer>…]` (непустой массив). Ignore применяется к ожиданию и факту до выбранного сравнения; native schema сначала проверяет полный фактический выход. Отсутствующий путь допустим. Пустой/корневой, повторный или пересекающийся pointer — ошибка формы; assert с test и прямое свойство marker.ignore запрещены; assert без test внутри маркера подчиняется обычному правилу ignore. Пути разрешаются над каждым исходным значением, поэтому удаление элемента массива не сдвигает смысл другого pointer. У pool консоли ignore ровно ["/fates"], compare value; прочие ключи остаются строгими.

Только CEL when также предоставляет `json(string) -> dyn`, один строгий JSON-документ: без BOM, дублей, NaN и Infinity. Ошибка разбора — ошибка данных формы, не false и не молча пропущенный тест. Селектор выбирает операцию потребителя по входным полям, не по результату реализации; cells сохраняют исходные строки. Условие группы по-прежнему одинаково на каждой её строке. Пример: `owner == "06-console" && !("salt" in json(row["input"]))`.

Привязка requests-body консоли остаётся surface layout: исключена из native/function-генерации, но обязанность не закрыта. Отдельная опубликованная и установленная C-цель `P/06/vectors-requests-body` должна прогнать настоящий HTTP-стенд store+console по всем 77 строкам и 21 round-trip принятых json по README пакета. 52 нативные строки воркера их не покрывают; чистая native-команда консоли и вымышленная HTTP-поверхность не вводятся.

Колонка входа может также использоваться ожиданием: например, json — исходный вход write и ожидаемый plaintext после настоящего открытия конверта, а в другом варианте — ожидание read. Запрещены золотые выходные данные как аргумент алгоритма, не такое совпадение ссылок. Роли данных определяет норма пакета и вариант, не объединение колонок ожидания. Ни literal, ни cells {} не задают группировку: без group_by остаётся один вызов на строку. У fault явно group_by [] задаёт один вызов на всю таблицу. Проверка формы не доказывает исполнение внешней HTTP-цели.

## Сравнение turn

`compare=turn` допустим только в строках, которые называет для него форма [`compare-scope.tsv`](../../vectors/compare-scope.tsv) (только для судьи: область слов сравнения), сейчас `(common/turn,cases.tsv,vectors)`; судья читает область из этой формы, а не из имени пакета. Вход — точная ячейка `input`; ожидание разбирается из `expect` и не передаётся нативной функции. Нативный выход — один JSON-массив действий. Длина и порядок массива, типы действий, наборы ключей объектов и все обычные значения точны; ничто не игнорируется. Между идентичностями signer и operations нет преобразования.

Только ожидаемая метка holder `@new` или `@same` имеет опубликованную семантику свежести пакета. `@new` требует непустую настоящую строку, отличную от всех меток holder, ранее выданных этой стороной в этом случае; она становится меткой этой попытки. `@same` требует ровно эту строку текущей попытки. Новый случай сбрасывает состояние сравнения. Нативный литерал `@new` или `@same` — не настоящий holder и не проходит. Пустой holder остаётся ровно пустым. Пропущенные/лишние поля, неверный cas/version/guard, стабильный holder signer вместо метки operations, повтор прежней метки или неразрешённый placeholder не проходят. Собственный адаптер подставляет метку текущей попытки вместо placeholder чтения до вызова обычного алгоритма, не передавая ожидаемые действия. Это уже опубликованное правило пакета, не runtime alias.

Выбор только такой: placement для04-controller; signer для08-domain и09-agent; operations для06-console. И `owner`, и разобранный `kind` входа должны совпасть с точным CEL в `wire.tsv`. Чужой owner/kind не выбирает вызов, и этой строки нет в описи цели; испорченный вход — ошибка формы, не ложный селектор. Форма не выводит из результата turn исполнение operations-epoch, двух лидеров, generation/ticket или позднего IO. Судью поставляет Архитектор в совместном срезе; одно объявление источника — не wire GREEN.

## Границы среза P/06

Объявления P/06 покрывают каждую таблицу, назначенную 06-console в consumers.tsv, и собственные таблицы урока. Journal modes и requests-body — layout, отдельные обязанности процесса и HTTP сохраняются. Совместимые привязки stand и vectors называют независимые поверхности и не утверждают, что раннер публикует обе. Другим владельцам достаются лишь явно выбранные в этих строках проекции; срез не закрывает их уроки целиком или необъявленные таблицы. Native.schema проверяет полный фактический ответ до исключения полей при сравнении. Только явный маркер ignore_stdout true отключает проверки содержимого stdout, кадра и схемы, сохраняя проверку нативного кода выхода.

## Провод write-checks P/01

Таблица проб, которая лежит в формах урока, а не в `vectors/`, и часть ячеек которой берётся из строк параметров таблицы, строки в этой форме не имеет. Её конверт [единой команды векторов](../acceptance/PROFILE.md#единая-команда-векторов) — строка формы [`probe-tables.tsv`](../../vectors/probe-tables.tsv); шапка формы задаёт её столбцы и закрытые источники ячеек, и судья читает конверт из этой строки.

В форме одна строка — пакет `01-store/write-checks`. Он вычисляет [`write-checks.tsv`](../../../01-store/forms/write-checks.tsv) собственной функцией реализации (P/01.1 N2.1, порядок проверок команды и пачки) над таблицей проб `Platform/01-store/forms/write-checks.probes.tsv` (только для судьи: пробы таблицы; P/01.1-R255). Её строка говорит:

- `package` — `01-store/write-checks`, `table` — `write-checks.probes.tsv` (столбец `table` строки; столбец `source` — путь таблицы проб, это имя её файла), `case` — `line-<physical source line>`, `variant` — `""`, `files` — `{}`;
- `cells` — ровно `sock`, `body`, `lim` и `allow`, строки, как их описывает P/01.1 N2.1: `sock` и `body` — ячейки строки; `lim` — один текст JSON-объекта для всех строк, из строк `#lim` проб; `allow` — один текст JSON-массива для всех строк: каждый элемент — одна JSON-строка, текст одной строки `#allow` после слова `#allow` и одного пробела (`#allow writer read acc/` даёт `"writer read acc/"`), в порядке строк;
- исполняется каждая строка, кроме строки случая `nopair`, у которой тело — проза;
- нативный выход — один JSON-объект, сравнение по значению: `{"n": 0}` или `{"n", "code", "kind"}` с кодом и видом строки `n` таблицы `write-checks.tsv`.

Профиль `01-store` объявляет запись `vectors` `01-store/write-checks`; без неё цель не исполнена.
