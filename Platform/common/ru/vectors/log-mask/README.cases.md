## UTF-8 в конце секрета regex

Пометки `utf8-regex-*` в `cases.tsv` обозначают случаи с существующим regex пути `cam.source` для `/password/<secret>` из переданного `fields.yaml`. Объявления полей и маршруты потребителей не меняются. Эти строки проверяют [A13 и A14](../../contracts/url-credentials.md#адрес-где-в-нём-логин-и-пароль) через [функцию маски журнала](../../contracts/log-mask.md#функция).

Искусственные секреты `é`, `€` и `😀` заканчиваются символами UTF-8 из двух, трёх и четырёх байтов. Каждый записан буквально, через percent-encoding и с дополнительным экранированием каждого знака процента. В любом представлении весь секрет становится `***`; декодирование до неподвижной точки не оставляет часть символа или его экранирования. Смешанный секрет `aé` с продолжением `/live?channel=1` также проверяет последний символ более длинного совпадения и сохранение окружающего текста журнала байт в байт. Путь с теми же символами Unicode вне секрета остаётся прежним.

Это векторы функции с переданным каталогом, в том числе у потребителя P/01. Они не утверждают, что демон хранилища загружает этот каталог или что утечка из журнала демона воспроизведена. Добавление строк не исполняет кандидата и не квалифицирует его адаптер векторов.

Конец данных случаев только для судьи.
