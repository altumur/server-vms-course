# Векторы: общая проверка строки: случаи и покрытие

Текст производный от `vectors/row-check/README.cases.md`, руками не правится: источник — английский [`vectors/row-check/README.cases.md`](../../../vectors/row-check/README.cases.md), правка идёт в него, русский пересобирается переводом.

Владелец — глава P/06.1 консоли через [договор проверки строки](../../contracts/row-check.md) (догадка стадии C W03-E07,
решение «Архитектора» 2026-10-23). Участники — дверь единиц консоли ([P/06.1](../../../../06-console/ru/spec/06.1-console.norms.md)
N3 «создать», «править») и библиотека заказчика воркера ([P/03.6](../../../../03-worker/ru/spec/03.6-worker.norms.md) N1.6,
N3 «заказать»): одна таблица для обеих сторон. Байты пишет «Спецификация». Случаи взяты из норм договора и шагов
приёмки P/06.1 (сц. 15, 16, 18, 20 — в колонке `note`).

Манифесты — `testsub` и `testsub2` (`Platform/common/data/testsub/*.subsystem.yaml`), загруженные вместе: каталог манифестов
из обоих. `testsub2/tallies` — таблица, которую заказывает библиотека `testsub` (`worker.creates`), поэтому большинство
случаев — на ней. Во входе единой команды `vectors` манифесты — `files` с ключами
`testsub.subsystem.yaml` и `testsub2.subsystem.yaml` (байты этих файлов выгрузки); `cells` — `unit`, `op`, `body`,
`stored`, `rows` (опись C04/C06-NEXT-167, решение «Архитектора» 2026-10-27).

Входная колонка `manifest` выбирает байты под ключом `testsub2.subsystem.yaml`. Обычные строки выбирают
`Platform/common/data/testsub/testsub2.subsystem.yaml`. Строки, которым нужны required с inherit, целый вес без default
или единица как цель ссылки, выбирают отдельную [фикстуру](../../../vectors/row-check/fixtures/testsub2.subsystem.yaml). Имя подсистемы и таблица единиц остаются
`testsub2/tallies`; поля `name` и `of` обязательны и имеют inherit, у `weight` нет default и оно объявлено как
`placement.weight.field`, поля `link` единицы и таблицы ссылаются на таблицу единиц. Фикстура — только вход судьи; общие манифесты не меняются.
`manifest` выбирает входные байты в проводе и не передаётся как ячейка алгоритма. Ожидания не выбирают байты фикстур.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются; первая строка без `#` — заголовок. Четырнадцать полей:

| Поле | Значение |
|---|---|
| `case` | имя случая, уникально |
| `unit` | `<подсистема>/<rows>` — таблица единиц манифеста, или `<подсистема>/<таблица>` — таблица манифеста (строка таблицы: P1 по `table_platform_fields`, подготовка — «Строка таблицы» договора) |
| `op` | `create` — создание (P1–P5 договора), `edit` — правка (R1–R3) |
| `body` | переданные поля — объект JSON; числа — лексемы как записаны (`1e2`, `-0`) |
| `stored` | у `edit` — прочитанная строка; у `create` — надгробие, над которым создают; пусто — строки нет. Объект JSON в форме строки единицы (элементы — строки) |
| `rows` | прочие строки хранилища, которые проверка читает: объект JSON `{key: row}`; `"@garbled"` вместо строки — строка не читается своей формой |
| `expect` | `ok` или `refused` |
| `word` | у `refused` — `fault` из словаря [`../fault/`](../fault/README.md), если отказ его несёт; иначе класс строки «Отказы» договора: `platform_field`, `unknown_field`, `blob`, `enum`, `type`, `labels`, `bad_id`, `fixed`, `required`; у `ok` пусто |
| `field` | поле, которое называет отказ (первое по порядку договора); у `unknown_field` — все незнакомые имена по возрастанию байтов через запятую (RC-10) |
| `step` | шаг договора, на котором отказ |
| `row` | у `ok` — часть подготовленной строки, которую сравнивают: объект JSON `{element: text}`, `"@absent"` — элемента нет; пусто — не сравнивается. Текст списка в форме массива JSON сравнивается по значению JSON (как `@json` векторов [`values-by-type`](../values-by-type/README.md)) |
| `manifest` | входной путь от корня выгрузки к манифесту под ключом `testsub2.subsystem.yaml`; выбирает байты `files`, не ячейку алгоритма |
| `credential_fields` | необязательное ожидание: JSON-массив имён credential-полей у `bad_url`; сравнивается как множество; `[]` требует отсутствия имён; пустая ячейка оставляет список без проверки |
| `note` | правило договора или шаг приёмки P/06.1 |

116 случаев: 36 `ok`, 80 `refused`. Прежние случаи повтора метки и пустого unique сохраняют входные значения и исходы.

| Граница | Случаи и наблюдение |
|---|---|
| Пустые сравниваемые элементы | `must_match_empty_both_*` и `reverse_must_match_empty_both_*`: прямая и обратная проверки отказывают пустому против пустого при создании и правке; контроли с равными непустыми проходят |
| Обязательное наследуемое поле | `required_inherit_{name,of}_{null,missing}`: отсутствующее и переданное как null наследуемое поле не дано; P4 отказывает, включая отсутствующий источник именованного id; `required_inherit_given` проходит |
| Поля отказа URL | `url_{scheme,no_host,no_path}_credentials`: отказ разобранному адресу по Schemes даёт `credential_fields: []`, несмотря на найденные credentials; `url_a15_*` покрывают секрет, логин, оба и неразбираемый адрес |
| Отказ числового типа | `{int,float}_as_{bool,array,object}` получают `type`; `float_as_numeric_string` получает `not_number`, как прежние случаи строки-числа и лексемы/диапазона int |
| Нечитаемые ссылающиеся строки | `reverse_garbled`, `direct_before_reverse_garbled`, `reverse_key_*` и `reverse_unit_*`: нечитаемость обнаруживается на проверке ссылающегося семейства по RC-15, после прямых проверок; конкурирующие ошибки отличают порядок ключей строк и единицы раньше таблиц |
| Наличие веса | `weight_absent_empty_form`: отсутствующий вес без default готовится как `"0"` и проходит; `weight_explicit_zero` отказывает, `weight_explicit_one` проходит |
| Диапазон числа состояния | `state.tsv`: положительное и отрицательное переполнение в result и переполнение в cursor нечитаемы; контроли с большим конечным числом действуют |

## Прогон

Сторона исполняет свою общую проверку строки: подготовка полей и проверки P1–P5 (`create`) или R1–R3 (`edit`) над
`body`, `stored` и `rows`. Сравнивается исход, класс или `fault`, поле и, у `ok`, элементы `row`. У двери класс читается
из отказа: слово `error` по P/06.1 N2 «Отказ: `error` и `field`» (класс `unknown_field` — слово `unknown field`; у строки таблицы
`platform_field` — тоже `unknown field`), поле — `field` без начального `/` (у `unknown_field` — первое имя); текст `detail` не сравнивается; у библиотеки — исход `refused`
вместе с причиной, которую библиотека пишет в лог. Библиотека подаёт поля своего заказа: поле-источник id — готовым id
(P/03.6 N1.6), `born` и `made` ставит сама и проверке их не передаёт.
Кто исполняет: дверь единиц консоли (`06-console`) — все строки; библиотека заказчика (`03-worker`) — строки с `unit`
`testsub2/tallies` (`create` и `edit`): это таблица, которую заказывает `testsub` (`worker.creates`), иных таблиц
библиотека не пишет (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-26).

Нативный исход `cases.tsv` — код 0 и один JSON-объект: `ok` — `{"result": "ok", "row": {…}}`, `row` — подготовленная строка
`{element: text}` (элемента нет — ключа нет); `refused` — `{"result": "refused", "word": "<fault или класс>", "field": "<поле>"}`
(поля нет — ключа `field` нет). Сравниваются `result`, `word`, `field` и у `ok` — элементы, названные в колонке `row`
(`@absent` — ключа нет; список в форме массива JSON — по значению). У `bad_url` нативный массив `credential_fields` называет поля по A15; при отказе по Schemes он пуст. Его сравнивают как множество только при непустой ячейке ожидания; прежние случаи оставляют его без проверки. Колонка `step` не сравнивается — она для человека: шаг
договора (C06-VECTOR-ROWCHECK-WIRE-168-11, решение «Архитектора» 2026-10-27; вход и алгоритм не меняются).

## `state.tsv`

Состояние единицы — договор проверки строки «Состояние единицы» (`acts`, `unreadable`); форма строки — [`state.schema.json`](../../../../03-worker/data/state.schema.json), исходы — [`state.outcomes.tsv`](../../../../03-worker/data/state.outcomes.tsv)
(STATE169-VECTORS-01, решение «Архитектора» 2026-10-27). UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются;
первая строка без `#` — заголовок `case<TAB>name<TAB>unit<TAB>state<TAB>expect<TAB>note`.

| Поле | Значение |
|---|---|
| `name` | имя состояния — строка JSON: `result` или `cursor` из `unit.state` манифеста `testsub2` (единица — `testsub2/tallies`) |
| `unit` | строка единицы, как прочитана: объект элементов (`born`, `revision`; `deleted: "true"` — надгробие) или `"@absent"` — строки нет |
| `state` | строка `testsub2/state/<name>/<id>`, как прочитана: объект элементов (`born`, `revision`, `epoch`, `value` — текст JSON) или `"@absent"` |
| `expect` | `{acts, unreadable}` и у действующего `value` — разобранное значение; JSON по значению |
| `note` | правило договора |

Ожидания — судья семьи `state` в режиме читателя по тексту строки (`x-encoding: jcs` — JCS проверяет только писатель),
затем `value` по схеме `unit.state.<name>` манифеста; `acts` — строка единицы живая, `born` равны, `revision` равны (у `cursor`
не сверяется: договор `acts`, P/03.6 N1.7 `cursor`; C170-STATE-CURSOR-01), эпоха не сверяется. 29 строк: 8 действуют, 15 нечитаемы, 6 читаемы и не действуют. Строгий разбор JSON в `value` отказывает числам вне конечного binary64, даже когда схема допускает число; терпимость читателя к пробелам вне JCS не ослабляет этот диапазон.
Вход единой команды `vectors` — `cells` `name`, `unit`, `state`; `files` — `testsub2.subsystem.yaml` (схемы `unit.state`).
Нативный исход — код 0 и объект `expect` (общее правило «Векторы» общего README приёмки).

Кто исполняет — каждый, чья норма судит «состояние действует»: держатель единицы (`03-worker`, P/03.6 N1.7 — пишет заново
недействующее), контроллер (`04-controller`, P/04 N1.3 `retire_when`, N1.3a `state` и счёт `snapshot_state_garbled`) и
консоль (`06-console`, P/06.1 N2 «Состояние в ответе») — все строки (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

born нынешнего состояния — обязательные 32 строчные hex. born-empty-both и born-empty-state-only сохраняют свои входные байты и получают существующий unreadable/nonacting, без дополнения жизни пустой строкой.

## Чего вектор не покрывает

Наличие и порог веса, прямой и обратный `must_match` (включая единицы-цели) и проверенные границы первого отказа RC-15
покрыты выше. Полный порядок имён подсистем, имён таблиц и полей манифеста RC-15 и ссылка строки на саму себя (RC-16)
остаются проверкой чтением или сценариями P/06.1. Заявка, номер, запись и коды HTTP двери — приёмка P/06.1; `made_prefix`, `made_key` и секреты двери — тоже. Строка таблицы
(договор, «Подготовка полей» — «Строка таблицы») и граница кольца (там же) — чтением и сценариями P/06.1 (таблицы) и
P/06.2: строки таблицы — `table_*` (`testsub2/shelves`: подготовка и платформенные поля таблицы, C06-ROWCHECK-TABLE-FIELDS-707-01),
полная замена и секреты таблицы, состояния кольца — чтением: во входе их нет (C06-ROWCHECK-TABLE-33-01, C06-ROWCHECK-DEV-01).
Поле таблицы с именем из `platform_fields` единицы — чтением: у таблиц `testsub`/`testsub2` такого поля нет.

## Провод векторов

Провод `cases.tsv`, `state.tsv` задают строки `common/row-check` [единой формы](../../../vectors/wire.tsv); [грамматика](../wire.md). Форма — источник шапки, выбранных входов, фикстур, кадра нативного ответа и сравнения. Смысл входов и выходов, обязанности потребителей, проверка нативной формы и проверки вне функции остаются здесь. Layout — исключение из вызовов функции, а не доказательство отдельной приёмки.
