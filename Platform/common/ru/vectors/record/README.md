# Векторы записи срока и подписи выпускающего

Текст производный от `vectors/record/README.md`, руками не правится: источник — английский [`vectors/record/README.md`](../../../vectors/record/README.md), правка идёт в него, русский пересобирается переводом (ADR-0121; ADR-0124 доп. (1) п. 4).

Векторы [договора записи срока](../../contracts/record.md): функция `record(keys, row, kinds)` — проверка документа,
подписанного выпускающим ключом держателя (запись срока, документ резервной копии, грант). Владелец — урок P/08, глава 8.8;
функцию исполняют агент члена (9.1), процесс `domain` (8.8) и консоль кластера (6.7, общий документ [главы 8.9](../../../../08-domain/ru/spec/08.9-domain.norms.md)) (разбор
ревью стадии A 8–10, № 13 / решение 2; ADR-0083 доп. (13)). Байты пишет «Спецификация» (ADR-0083); соответствие продукта —
его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `record` приёмки М11/10
(`inputs/record-*.json`, сц. 05) без изменения байтов; `case` — имя файла входа. Сценарий 05 приёмки М11/10 и его входы
сняты переносом урока 8 (ADR-0083 доп. (14) п. 17; журнал — приёмка главы P/08.8 (`Platform/08-domain/journal/corrections-8.tsv`, журнал, в выгрузку не входит)):
таблица — единственный источник этих случаев.

## Прогон

Без стенда: функция реализации с четырьмя видами (три главы [P/08.8](../../../../08-domain/ru/spec/08.8-domain.norms.md) и строка членов) получает вход (колонка `input`) и даёт вывод; `expect` —
подмножество полей вывода или `@exit 2` (вход не по форме P/08.8 N5 `exit`: доверенный набор `keys` не по форме). Подпись
самого набора функция не проверяет: набор доверенный (P/08.8 N5).
Кто исполняет (таблица участников договора): `cases.tsv` — процесс `domain` (`08-domain`, четыре вида) все строки; `record-member-row-*` и [`take.tsv`](../../../vectors/record/take.tsv) исполняет ещё агент члена; агент
члена (`09-agent`, виды «запись срока» и «документ резервной копии») — все строки, кроме документа гранта (`doc.grant`:
`record-12-grant-tampered` — у агента это иной документ, не его вид); `shared.tsv` — консоль кластера (`06-console`,
P/06.7 N1.14) и агент члена (`09-agent`) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-26).

## Ключи

Ключи выпускающего и набор — байтами во входах (`keys.issuing`, `doc.issuer`). Зёрна — `sha256("w2c test <слово>")`
(перенесено из README приёмки М11/10 «Входы»): корень `root 1`, ключи токенов `token key 1` (`t1`) и `token key 0` (`t0`, строки 25–27); выпускающие `issuing key 1` (в
`issuing` набора), `issuing key 0` (в `revoked_issuing`), `issuing key 9` (чужой); члены `member m1`, `member m2`. Набор
`keys` у всех строк один: `domain: acme`, `rev: 2`, подпись корня; у строк 25–27 к нему добавлены `t0` и `until` (подпись набора функция не проверяет).

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](../../../vectors/record/cases.tsv), 46 строк: 14 `ok`, 27 отказов, 5 `@exit 2` (`record-member-row-gathered` — признак строки сбора; `record-holder-with-key` — запись срока с `key`; `record-member-row-*` — вид «строка членов», ADR-0113; 28 — `until` сверх binary64, C137-SCHEMA-TIME-01; 29–35 — поле `raw` документа резервной копии: байты `ff7b` объекта, что не JSON, — `/3s=`, объект в 0 байт — `""`, JSON не по форме « [ 1.00 ] » — `IFsgMS4wMCBdIA==` (не значением), объект по форме — в `objects` значением; без дополнения, алфавит base64url и ключ и в `objects`, и в `raw` — `not_a_record`, C08-BACKUP-JSON-99) (строки 18–20 — REC-G01, 21–24 — вложенность 64/65, REC-G02; 25–27 — время `until` доверенного набора по канону P/01.1 N0: строка «1700000000.5» принята, −1 и «1e9» — `@exit 2`, REC-TRUSTED-TIME73; ключ токенов `t0` — зерно `token key 0`) | `input` — вход команды `record` текстом JSON (`keys` — документ набора, `row` — `{doc}` как прочитана) → `expect`: `{"result":"ok","term":…,"holder":…}` (запись срока, восстановленный срок, документ резервной копии) или `{"result":"refused","reason":<слово>}`: `another_domain`, `revoked_issuer`, `unknown_issuer`, `bad_signature` (`kid` ≠ `issuer`, подмена записи, документа резервной копии, гранта), `not_a_record` (не строка, лишнее поле, общий документ главы 8.9, `holder` документа резервной копии, повтор в `members` и `ca`); `@exit 2` — `keys` не набор |
| [`take.tsv`](../../../vectors/record/take.tsv), 9 строк | `input` — `{keys, row, part, have}` → `expect`: `take`, `same`, `older` или отказ словом; граница свежести строки членов |
| [`shared.tsv`](../../../vectors/record/shared.tsv), 8 строк: 1 `ok`, 7 отказов | вход тот же; функция с одним видом «общий документ» (P/08.9 N1.2 document) → `expect` — подмножество `{result, term?, reason?}`; `kid` и `sig` вне формы писателя — шаги 3–5, не `not_a_record` (REC-G01) |

Векторы проверены эталонными Ed25519 (RFC 8032) и JCS (RFC 8785) по тексту договора (подписи и шаги 2–5), не по коду
реализаций; при расхождении прав договор, вектор правит «Спецификация».

## Провод векторов

Провод `shared.tsv` задают строки `common/record` [единой формы](../../../vectors/wire.tsv); [грамматика](../wire.md). Форма — источник шапки, выбранных входов, фикстур, кадра нативного ответа и сравнения. Смысл входов и выходов, обязанности потребителей, проверка нативной формы и проверки вне функции остаются здесь. Layout — исключение из вызовов функции, а не доказательство отдельной приёмки.
