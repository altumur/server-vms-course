# Реестр целей приёмки

Этот русский текст — производный от `acceptance/forms/targets.README.md`, руками не правится.

[`targets.tsv`](../../../acceptance/forms/targets.tsv) — реестр целей приёмки. Форма едина для всех уроков. В этом файле шапка; строки целей урока — в `forms/targets.tsv` этого урока с этой шапкой, их строки маршрутов — в `forms/targets.routing.tsv` этого урока, и реестр собирается из них ([реестр целей и списки выгрузки, собранные из уроков](../tables.md#реестр-целей-и-списки-выгрузки-собранные-из-уроков)). Заполнены строки P/01 ([`Platform/01-store/forms/targets.tsv`](../../../../01-store/forms/targets.tsv)), P/02 ([`Platform/02-installer/forms/targets.tsv`](../../../../02-installer/forms/targets.tsv)) и P/03 ([`Platform/03-worker/forms/targets.tsv`](../../../../03-worker/forms/targets.tsv)), с теми же ячейками, что у их строк в [`runner-targets.tsv`](../../../acceptance/runner-targets.tsv). Цели P/04 объявлены в [`Platform/04-controller/forms/targets.tsv`](../../../../04-controller/forms/targets.tsv); их маршруты — в `forms/targets.routing.tsv` этого урока (только для судьи: маршруты), в `runner-targets.tsv` их дублей нет. Строки `P/01/production`, `P/02.1/seams`, `P/02.4/seams` и `P/02.5/variants` есть только в реестре: в той таблице их нет. В строке маршрута одно слово движка, поэтому швы P/02.1 и P/02.4 и варианты прав P/02.5 — отдельные цели рядом с вердиктами P/02.1 и сценариями P/02.5. У P/02 `P/02/vectors-canonical` и `P/02/vectors-workers-script` — это строки `P/02.2/vectors` и `P/02.4/vectors` той таблицы, названные по своим пакетам, как остальные `P/02/vectors-*`; условие `rights_check` строки `P/02.5/rights` той таблицы в реестре стоит у `P/02.5/variants`: её `check.tsv` вызывает `stand.rights-check`. Строка `P/02.1/put` той таблицы — не цель: у P/02.1 нет выборки через установку ([приёмка P/02.1](../../../../02-installer/ru/acceptance/1/README.md#выборки-установки-нет)). У P/03 семь целей швов `P/03.1/seams` … `P/03.7/seams` есть только в реестре; у швов P/03.2, P/03.3, P/03.4 и P/03.6 слово движка `seams`: в их каталоге лежит и `scenarios.tsv` цели `P/03.K/stand` (только для судьи: таблица сценариев). `P/03/vectors-creates-key` вызывает команду стенда `creates-key` своего пакета — единственную поверхность его строки провода — вместо записи `vectors` той таблицы. Стенды `P/03.2/stand`, `P/03.3/stand`, `P/03.4/stand` и `P/03.6/stand` требуют интерфейс порчи только по его условию и только там, где портит сценарий каталога: `object_spoil` у P/03.2 и P/03.4, `row_spoil` у P/03.2; ни один сценарий P/03 не кладёт объект, поэтому условие `object_put` той таблицы не перенесено.

## Форма таблицы

UTF-8, строки по физическим LF, ячейки разделены TAB. Первая строка, не являющаяся заметкой (`#`), — заголовок, столбцы читаются по его именам ([шапка таблицы и столбцы по имени](../tables.md#шапка-таблицы-и-столбцы-по-имени)):

```text
id\towner\tstand_commands\tstand_addresses\tkeys\trequirements\tnorm_anchors\tflags
```

`id` и `owner` — строки; все остальные ячейки — компактные значения JSON. `id` уникален.

| Столбец | Смысл |
|---|---|
| `id` | Имя цели: область договора, а не выбор реализации или входов. |
| `owner` | Модуль, отвечающий за цель. |
| `stand_commands`, `stand_addresses`, `keys`, `requirements`, `norm_anchors` | Те же формы и смысл ячеек, что у одноимённых столбцов в [требованиях к целям](../runner-targets.README.md). |
| `flags` | JSON-массив слов-флагов из закрытого списка ниже; пустой, если флагов нет. |

| Флаг | Смысл |
|---|---|
| `optional` | Профиль, не объявивший интерфейс цели, оставляет цель неисполненной. Без этого флага отсутствующий интерфейс блокирует цель. Ключ профиля из столбца `keys` — не интерфейс: без него цель не исполняется с именем ключа, с флагом и без него (P/AC-R030; только для судьи: нормы судьи). У `P/01/production` флаг относится только к функциональному вердикту (N6.1 норм судьи). |

Эти столбцы не добавляют поля профиля, команды, подстановки, адреса или параметра.
