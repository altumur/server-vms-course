# Публичные требования к целям и стенду

Этот русский текст — производный от `acceptance/runner-targets.README.md`, руками не правится.

`runner-targets.tsv` объявляет публичные интерфейсы и результаты сборки, необходимые
для выбранной цели. Имя цели обозначает область договора; оно не выбирает
реализацию или набор входов. Каждая команда сохраняет своего владельца.
Реализация выбирает имена своих исполняемых файлов и обёртки.

## Форма таблицы

Таблица записана в UTF-8 с физическими строками LF и ячейками, разделёнными TAB. Первая строка содержит следующие поля (`\t` обозначает TAB):

```text
target\towner\tstand_commands\tstand_addresses\tkeys\trequirements\tnorm_anchors
```

`target` и `owner` — строки. Каждая прочая ячейка — компактное значение JSON.
Описанные ниже поля объектов закрыты и обязательны. Массивы могут быть пустыми;
повторяющиеся элементы недопустимы. Имена целей уникальны.

| Колонка | Публичный смысл |
|---|---|
| `target` | Имя цели. |
| `owner` | Владелец цели. |
| `stand_commands` | Обязательные вызываемые интерфейсы, каждый `{owner,section,key}`. |
| `stand_addresses` | Обязательные адреса, каждый `{owner,key}`. |
| `keys` | Обязательные существующие параметры профиля, каждый `{owner,key}`. |
| `requirements` | Владельцы результатов сборки, альтернативы и условные требования, описанные ниже. |
| `norm_anchors` | Ссылки на публичные нормативные документы относительно корня репозитория, с фрагментами заголовков. |

Поле `section` вызываемого интерфейса равно ровно `stand`, `vectors` или `adapters`:
оно обозначает существующую карту в профиле владельца. `key` — существующее имя
команды, пакета или адаптера в этой карте. Например,
`{"owner":"01-store","section":"stand","key":"store"}` обозначает `stand.store`
владельца хранилища. Колонка вызываемых интерфейсов объединяет эти интерфейсы,
не превращая вектор или адаптер в ключ `stand`. Одинаковые имена у двух владельцев
сохраняют два отдельно принадлежащих им интерфейса. Эти поля таблицы не добавляют
поле профиля, команду, подстановку, адрес или параметр.

Адрес — не команда оболочки. В частности, `token-door` владельца `09-agent`
сохраняет опубликованную форму адреса. Значения параметров и допустимые подстановки
команд остаются такими, как их задают публичный профиль и протокол владельца.

## Условные требования

`requirements` содержит ровно четыре поля:

- `artifacts`: имена владельцев, чьи публичные результаты сборки нужны в обычной
  области цели. Библиотека может предоставлять результаты сборки, не предоставляя команду.
- `any_of`: ссылки на вызываемые интерфейсы в той же форме `{owner,section,key}`.
  Если массив непуст, обязателен хотя бы один указанный интерфейс; объявить оба допустимо.
  Альтернативы не становятся одновременными безусловными требованиями.
- `when`: объекты `{condition,require}`. `require` — одна ссылка на вызываемый интерфейс.
- `replace`: объекты ровно с полями `condition`, `stand_commands`,
  `stand_addresses`, `keys` и `artifacts`. Применимая замена задаёт полный набор
  зависимостей по командам, адресам, параметрам и результатам сборки для этой области
  вместо обычного набора. Она не добавляется к набору полной цели.

Конечный словарь условий описывает исполняемую операцию:

| Условие | Когда применяется требование |
|---|---|
| `row_spoil` | Операция использует опубликованный интерфейс повреждения долговечной строки, тела или индекса. |
| `object_put` | Операция использует опубликованный интерфейс записи объекта. |
| `object_spoil` | Операция использует опубликованный интерфейс повреждения объекта. |
| `join_batch` | Операция использует опубликованный интерфейс пакетного присоединения. |
| `rights_check` | Выбранная операция проверки прав требует интерфейс проверки прав. |
| `console_only_pass` | Выбрана только консольная область PASS, а не полная область PASS из нескольких владельцев; применяется указанная полная замена. |

Первые пять условий встречаются только в `when`; `console_only_pass` встречается
только в `replace` цели PASS. Условия описывают существующие обязанности,
а не новые слова команд или переключатели конфигурации. Исполняемая операция
определяет применимое условие. Неиспользуемый необязательный интерфейс не становится
безусловной зависимостью. Операция, которая его использует, всё равно требует его
объявления: без него зависимая операция остаётся неисполненной, а требование
не считается выполненным. Требования `when` продолжают действовать для операций,
которые используют эти интерфейсы.

Для замены только консольной области владельцы результатов сборки — владельцы
перечисленных в ней интерфейсов и параметров, включая владельца цели. Замена
не требует результатов сборки прочих владельцев из полной области PASS.

## Нормативные интерфейсы

Канонический [договор профиля](PROFILE.md#владение-командами-и-результаты-сборки)
задаёт владение командами и публичные результаты сборки. Его
[подстановки](PROFILE.md#подстановки),
[формы параметров](PROFILE.md#параметры-keys),
[исполняемые адаптеры](PROFILE.md#исполняемые-адаптеры) и
[команда векторов](PROFILE.md#единая-команда-векторов) сохраняют прежний смысл.
Ссылки таблицы заданы относительно корня репозитория, чтобы каждая разрешалась
в том же дереве публичных документов. Идентичность содержимого файла не заменяет норму.

Публичные договоры операций и интерфейсов цели определяют её входы и исходы.
Эта таблица описывает зависимости; она не определяет алгоритмы или ожидаемые выходы.
