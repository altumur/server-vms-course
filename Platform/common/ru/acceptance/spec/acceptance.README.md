# P/AC — инструкция для движка судьи

Текст производный от `acceptance/spec/acceptance.README.md`, руками не правится: источник — английский [`acceptance/spec/acceptance.README.md`](../../../acceptance/spec/acceptance.README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Этот файл — для агента (или человека), который пишет общий движок судьи по этому уроку.

## Задача

Написать один движок, который исполняет цели реестра по данным спецификации: таблицам, входам и протоколам стенда. В движке нет литеральных имён уроков, целей и пакетов, и он не знает внутреннего API ни одной реализации.

## Входы и их приоритет

- Канон — [нормы](acceptance.norms.md).
- [Общий стенд](../README.md) даёт стенд, словарь директив и дверей, протокол швов и формы ожиданий.
- [Договор профиля](../PROFILE.md) даёт форму `acceptance.yaml`, `assembly.yaml`, владение командами, подстановки, адаптеры и конверт векторов.
- [Форма провода векторов](../../vectors/wire.md) и `wire.tsv` дают строки векторов; `consumers.tsv` — их владельцев.
- [Реестр целей](../forms/targets.README.md) даёт цели и их требования; `forms/targets.routing.tsv` — семейство движка, каталоги приёмки, выбор сценариев, режим тела, начальную роль, допущенные неназванные поля и файл прав хранилища стенда каждой цели.
- README приёмки главы даёт её подготовку и особые правила сравнения.
- [Шаг изменения формы](../command-tables.md#шаг-изменения-формы) даёт отдельные испытания ячеек вшитых форм, внешние наблюдатели, нормализацию и классы находок.
- [Боевая квалификация хранилища](../../../../01-store/ru/qualification/README.md) даёт группы, бюджеты и измерения N6 норм.

Вход генерации движка не содержит кода продуктов и существующего судьи, описи его поведения, корпуса вердиктов и мутантов.

## Что создать

Один движок с такими частями: читатели таблиц; план с сухим перечнем; исполнитель стенда по словарю; вызов адаптеров и команды векторов; отдельный шаг изменения формы (N3.5 норм); пробы боевой квалификации (N6 норм); классификация итогов; отчёт.

## Порядок работы

1. Сначала прочитать таблицы: таблицы сценариев, формы векторов и реестр. Таблицу вне формы отвергнуть до запуска любого стенда.
2. Построить план и сухой перечень по реестру; опись, которую он печатает, — то, с чем сравнивается итог.
3. Запустить стенд по словарю и профилям. Применить правило готовности общего стенда; останавливать всю группу процессов; после цели не оставлять процессов.
4. Исполнить каждый шаг по его строке словаря и судить его по формам ожиданий; исход шага — несовпадение или класс N4, а не догадка.
5. Не выпускать секретное в отчёт.

## Результаты и механические проверки

Движок даёт итог по цели и отчёт (N1.4, N1.5 норм). N5 норм называет механические проверки, которые применяет цикл генерации; их прохождение не доказывает правильности: её доказывают код-ревью и сверка вердиктов.
