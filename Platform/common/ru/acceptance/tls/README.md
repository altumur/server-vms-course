## Комплекты: [`stand.json`](../../../acceptance/tls/stand.json)

Раннер материализует комплекты по описанию в момент `@tls-setup` (до создания стенда), по своим часам: готовых ключей в
курсе нет, сроки всегда годятся реальному времени. Ключи — только тестовые, в отчёт прогона не попадают.

| Поле | Смысл |
|---|---|
| `version` | форма описания, `1` |
| `server` | имя сервера всех кластеров стенда (`localhost`): кластеры различаются именем, центром, портами и каталогами |
| `defaults.ca` | центр кластера: ключ (`ec-p256`), подпись (`sha256` — ECDSA с SHA-256), `not_before` — секунды от момента выпуска (отрицательное — в прошлом), `days` — срок от `not_before`; `CA:true`, `keyCertSign`, `cRLSign`; самоподписан |
| `defaults.leaf` | лист роли по договору сертификата роли `cert`: CN `<роль>.<server>`, SAN DNS `<server>`, SAN URI `urn:w2c:role:<роль>` — ровно одна, EKU `serverAuth` + `clientAuth`, `days` 825; подпись центром своего кластера |
| `clusters` | кластер → роли его комплекта: центр кластера и лист на каждую роль; раскладка — договор `kit` (`ca.pem`, `<роль>/server.pem`, `<роль>/server.key`) в `W2C_TLS_DIR` кластера; `revoked` пуст, `ca.next.pem` нет |
| `foreign` | роли комплекта «чужого» центра: свой центр, который ни один кластер не публикует (`tls_ca`) и не держит |
| `named` | комплект одной коробки с иным именем сервера (ADR-0075 доп. 2026-10-26 (4) п. 7): свой центр, листы ролей `roles` с CN `<роль>.<server>` и SAN DNS `server` (`box-n`), не `localhost`; раскладка — договор `kit`; другие кластеры его центру не верят. Им пользуется только `@kit-start` |
| `negative` | клиентские листы для проб: `issuer` — кластер, чей центр подписывает; `role` — роль листа; прочие поля заменяют умолчание листа: `uri: null` — без SAN URI, `eku` — свой набор, `sig` — подпись листа (`sha512` — ECDSA с SHA-512, вне закрытого списка договора `sig`), `not_before`, `days` — свой срок |

Отпечаток центра — sha256 hex DER ([P/08.3 N1.6](../../../../08-domain/ru/spec/08.3-domain.norms.md) `fingerprint`). Раннер называет каждому кластеру его каталог комплекта
(`W2C_TLS_DIR`) и начальный отпечаток держателя (`DOMAIN_CA` рядом с `DOMAIN_URL`, [договор `peer`](../../contracts/peer.md) «Клиент и первый контакт» `first`). Публикация
`tls_ca`/`tls_ca_certs` — дело реализации по норме: стенд их не подставляет.

## Двери и клиенты пробы `@tls`

| Дверь | Что | Класс (договор сертификата роли «Серверная сторона»; `role` — P/10 N1.4 `server.role`) |
|---|---|---|
| `holder` | консоль домена на `hold` — приём пересылки с `X-Operator: console`; по маршруту P/06.7 N1.4 её клиент — консоль кластера `hold`, прямое соединение консоли члена — проба `@tls` (ADR-0083 доп. (18)) | `role` |
| `signer` | процесс `domain` на `hold` — `POST /api/member/<член>`, `GET /api/carry/<член>` | `signed`, слушатель `SIGNER_URL`: сертификат клиента запрашивает необязательно, предъявленный проверяет в рукопожатии (договор сертификата роли `signer`; ADR-0083 доп. (20), доп. (21)) |
| `member <кластер> console` | консоль кластера (`/domain/at/…`, пересылка) | `signed` для входящих из других кластеров: сертификата клиента не запрашивает, `X-Operator: console` снимает ([P/06.7](../../../../06-console/ru/spec/06.7-console.norms.md) N1.7 `server`; ADR-0083 доп. (18)) |
| `callback <кластер>` | слушатель обратного вызова консоли кластера, порт `{cport}` | обязательный лист роли подсистемы, договор сертификата роли «Лист обратного вызова»; основной слушатель выше не меняется (ADR-0094 доп. (16)); пробы — директивой `@pass-call` [стенда передачи второго вида](../pass/README.md), комплекты — его `stand.json` |

`@tls-kit <кластер> console <комплект>` — замена комплекта одной консоли кластера (форма согласована «Архитектором» с
TLS-этапом «cammeta-acceptance» 2026-10-21; ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 22). Раннер останавливает только консоль кластера
`<кластер>` и запускает её снова с прежними портом, данными и окружением, кроме своего каталога комплекта
(`W2C_TLS_DIR` этого процесса); процессы `domain`, `domainconsole`, агент и опубликованные `Entry.ca`, `ca-certs` не
меняются. Комплект `<кластер>` — исходный комплект кластера (возврат). Комплект `foreign` — ротация к чужому центру
(договор сертификата роли `rotation`): `ca.pem` и `revoked` — исходные кластера, `ca.next.pem` — центр `foreign`,
`console/server.pem`, `console/server.key` — лист роли `console` центра `foreign` (договор `cert`). Так консоль
по-прежнему проверяет консоль домена своей коробки своим `ca.pem` (договор пересылки `tls`), а сама предъявляет лист
чужого центра; сервер отдаёт лист и его центр из `ca.next.pem` (договор сертификата роли «Серверная сторона»). Пока стоит
`foreign`, клиент стенда проверяет сервер этой консоли (дверь `member <кластер> console`) по центрам комплекта (`ca.pem`
и `ca.next.pem`), прочие двери — как прежде; другие кластеры к этой консоли в эти шаги не ходят. Ожидание — `ok`: консоль
слушает снова; неверная форма директивы — класс «данные», остановка, запуск и инструмент — класс «стенд».

Клиент — имя листа: `<кластер>-<роль>` (`m2-console`, `m2-domainagent`, `foreign-console`) или ключ `negative`
(`m2-no-role`, …); `null` — без сертификата клиента. Клиент пробы предъявляет указанный лист на любой запрос сертификата
сервером, независимо от списка центров в запросе; сервер сертификата не запросил — лист не шлёт (ADR-0083 доп. (20), доп. (21) п. 9).
Клиент проверяет сервер по центру кластера двери (`client` договора `peer`);
ошибка этой проверки — исход инструмента, не TLS alert.

## Исход пробы — закрытая форма

```json
{"handshake": "ok" | "alert", "version": "TLSv1.2" | "TLSv1.3" | null, "reused": true | false,
 "session_available": true | false, "http": null | {"status": <код>, "body": <JSON | текст>}}
```

- `handshake: ok` — рукопожатие завершено, `http` — ответ двери на `request` пробы (полная форма — контракт двери).
- `handshake: alert` — сервер отказал рукопожатием (TLS alert): `http: null`; `version` — выбранная версия или `null`, если
  отказ раньше выбора; `reused: false`, `session_available: false`.
- `reused` — сессия предъявлена и сервер её возобновил; `session_available` — сервер выдал пригодную сессию (билет или
  идентификатор) за это соединение.
- Отказ соединения, обрыв, таймаут, ошибка проверки сервера клиентом и ошибка инструмента — класс «стенд»: исходом
  пробы не являются и не удовлетворяют ни одному ожиданию. Текст библиотеки и номер alert — диагностика, не слово
  реализации.

Ожидание в строке сценария — `ok <JSON>` (словарь «Стенда домена», `@tls`); JSON сравнивается подмножеством полей поверх закрытой формы.

## Ожидания

Точные JSON выбранных проб — в [данных случаев только для судьи](README.cases.md).

Подготовка всех проб: `@clusters hold m1 m2 m3` (п. 9 — четвёртый кластер; для пп. 2, 7, 8 достаточно `hold m1 m2`),
`@tls-setup …/stand.json`, `@domain m1 m2` (или `m1 m2 m3`), затем `@until` записи члена: у `m2` — `Entry.ca` с
отпечатком центра `m2` и строка `domain/members/m2/ca-certs` (`on_accept`, приём отчёта с `tls_ca`, `tls_ca_certs`).

**П. 7 — рукопожатие по `ca-certs`** ([P/08.3 N1.6](../../../../08-domain/ru/spec/08.3-domain.norms.md) `on_accept`; [P/10 N1.4](../../../../10-domain-console/ru/spec/10-domain-console.norms.md) `server.role`): после строки `ca-certs` и `Entry.ca`
пересылаемый запрос консоли члена с `X-Operator: console` у двери роли проходит рукопожатие; ответ
двери — по сторожевой (не 401/403 со словами `no_role`, `wrong_role`, `bad_chain`).

**П. 2 — серверная сторона** (строки двери `signer` — класс `signed`, слушатель `SIGNER_URL`: P/08.0-02, P/02.4 N1.6
`client_cert`, договор сертификата роли `signer`; ADR-0083 доп. (20), доп. (21) п. 9; строки
`holder` — класс `role`, P/10 N1.4 `server.role`):

- Дверь класса `role` (договор сертификата роли `refusal`): центр члена в объединении проходит рукопожатие, в ответе нет слов `no_role`, `wrong_role`, `bad_chain`; нет сертификата клиента — 401 `no_role` после рукопожатия; шаги 6–7 peer, роль не `console` — 403 `wrong_role`; лист без роли — 403 `no_role`; подпись вне закрытого списка `sig` — 403 `bad_chain` после рукопожатия; центр вне объединения, просроченный лист, EKU без `clientAuth`, член вне объединения — отказ рукопожатием, ответа HTTP нет.
- Дверь класса `signed` (слушатель `SIGNER_URL`): сертификат клиента не требуется, ответ — по подписи запроса (не 401 `no_role`); предъявленный лист своего центра проходит рукопожатие, ответ — как без сертификата (`X-W2C-Client` стенд не наблюдает); лист центра из `ca.next.pem` — так же (ротация; **долг стенда** — ниже); подпись вне `sig` — после рукопожатия, только `X-W2C-Client` (стенд не наблюдает); просроченный лист, EKU без `clientAuth`, центр не свой, центр другого кластера (его клиенты лист сюда не предъявляют, договор сертификата роли `clients`) — отказ рукопожатием, ответа HTTP нет.

Долг стенда (ADR-0083 доп. (20), доп. (21) п. 9): описание комплектов `version` 1 следующего центра не выпускает (`ca.next.pem` у
кластеров нет), поэтому строка «лист следующего центра `hold`» не исполняется и исполненной не объявляется; закрывается
формой описания со следующим центром кластера — данные «Спецификации», директива — TLS-этап «cammeta-acceptance».

Смена объединения видна новым соединениям: после `POST /domain/members/<member>/ca {"ca": []}` (грант admin; агент остановлен — его отчёт с `tls_ca` вернул бы центр, [P/08.3 N1.6](../../../../08-domain/ru/spec/08.3-domain.norms.md) `on_accept`; решение «Архитектора» 2026-10-21, как № 14) следующая проба консоли члена получает отказ рукопожатием; возврат `ca` и `ca_certs` снова её пропускает.

**П. 8 — возобновление** (P/10 N1.4 `server.role`: сессий не возобновляет; решение «Архитектора» 2026-10-20 — проходят
оба исхода):

Положительный контроль до пробы: контрольный сервер оснастки выдаёт сессию, клиент предъявляет её и получает `reused: true`. Нет — проверка не исполнена (стенд), не провал реализации. Сессия сохраняется `save_session` и предъявляется `resume_session`; предъявленная сессия — полное рукопожатие (`reused: false`), при `session_available` или без него. После снятия центра (без перезапуска сервера; агент остановлен — его отчёт с `tls_ca` вернул бы центр, [P/08.3 N1.6](../../../../08-domain/ru/spec/08.3-domain.norms.md) `on_accept`; решение «Архитектора» 2026-10-21, как № 14) новое соединение и предъявление сессии получают отказ рукопожатием: возобновления нет, билет прошлой сессии центр не возвращает. Без пригодной сессии (`session_available: false`) предъявление не исполняется и исполненным не объявляется.

**Пересылка через дверь роли и ветки `admin`** (разбор ревью стадии B 8–10, № 14; разбор ревью стадии A 8–10, № 36).
Данные «Спецификации»; шаги и сценарий пишет TLS-этап «cammeta-acceptance»; до того — долг стенда. Подготовка — как у п. 2.
Нормы: [договор пересылки](../../contracts/forwarding.md) «Пересылка — одна функция» `answer`, `journal`, `tls`;
[P/06.7 N1.7](../../../../06-console/ru/spec/06.7-console.norms.md) `server` (переход 1 — класс `signed`);
[P/08.3 N1.6](../../../../08-domain/ru/spec/08.3-domain.norms.md) `admin`, N4; [P/10 N1.4](../../../../10-domain-console/ru/spec/10-domain-console.norms.md) `server.role`.

- Пересылаемый запрос при центре члена в объединении: ответ консоли домена как пришёл (не 401/403 со словами `no_role`, `wrong_role`, `bad_chain`; ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 27): `answer`, `tls`.
- После снятия центра члена прямое соединение консоли этого члена с дверью роли держателя — отказ рукопожатием: `server.role`, центр вне объединения.
- Пересылка этого члена всё так же даёт ответ консоли домена как пришёл, и журнал пересылающей консоли записывает `domain.forwarded {cluster, path, user, status}`: снятие центра — не снятие членства: переход 1 — класс `signed`, к двери роли идёт консоль кластера держателя (P/10 N1.4 `server.role`); `journal`.
- `POST /domain/members/<member>/ca {"ca": []}`, затем с отпечатком и без `ca_certs`: оба приняты; строки `ca-certs` нет (снята `[]`), и проба этого члена получает отказ рукопожатием — член вне объединения, пока сертификатов под отпечатками нет (`admin`: «без ca_certs строка не меняется»).
- Сертификат в `ca_certs`, не совпадающий с отпечатком, — 400; `Entry.ca` и строка `ca-certs` не меняются (`admin`, N4: sha256 не сходится); лист вместо центра — 400 — лист не центр (`admin`: «в том числе CA:true (иначе 400)»); те же `ca`, `ca_certs` дважды — новая запись, `rev` + 1 (`admin`: «тот же ca снова — новая запись»).

Агент члена при снятии остановлен (его отчёт вернул бы центр в объединение). Журнал пересылающей консоли читается штатной дверью ресурса, без новой директивы: `GET /events?kind=domain.forwarded&unit=audit/console&keep=newest&limit=1` → `200`, `events[0]` — запись `domain.forwarded` ([P/05](../../../../05-resource/ru/spec/05-resource.norms.md) N1.3 `query`, `row`); две пересылки с равным `status` различаются по `id` записи (словарь «Стенда домена» `$name`, `@not`).

**№ 14, отказ рукопожатия двери роли на переходе 2** (ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 22; данные — «Спецификация», директива
`@tls-kit` — «cammeta-acceptance»). Норма: договор пересылки `answer` — отказ рукопожатия двери роли на переходе 2 —
сеть, `502 did not answer` без слова `peer`; `journal` — `status: 502`. Вход — консоль кластера `hold` прямо из стенда:
запрос идёт по переходу 2 к двери роли своей коробки. Журнал — `@until 30 member hold resource GET
/events?kind=domain.forwarded&unit=audit/console&keep=newest&limit=1` (дальше — «журнал hold»); `<имя>` — имя токена
стенда.

**№ 14, класс `signed` у консоли кластера** (ADR-0083 доп. (19) п. 2; разбор ревью ADR-0090, № 23). Норма: [P/06.7 N1.7](../../../../06-console/ru/spec/06.7-console.norms.md)
`server` — всё входящее из других кластеров на слушателе консоли кластера: сертификата клиента не запрашивает, по центру
в рукопожатии не отказывает, `X-Operator: console` — не признаёт; снимает всегда (договор пересылки `x_operator`).

## Клиент своей коробки и умолчания адресов (ADR-0075 доп. 2026-10-26 (4) п. 7, (5) п. 4)

Нормы: [договор сертификата роли](../../contracts/role-certificate.md) «Клиент двери своего кластера» (`own_client`,
`loopback`); [P/02.4 N1.6](../../../../02-installer/ru/spec/02.4-installer.norms.md) `process`, `console`; N1.12 и lifecycle
P/08, P/10 (умолчания адресов). Директива `@kit-start` — словарь «Стенда домена» общего README (форма согласована
«cammeta-acceptance» 2026-10-26). Подготовка — `@tls-setup …/stand.json` (комплект `named`); шаги не требуют
`@domain` и кластеров стенда домена: процесс стартует один, на коробке стенда с его хранилищем и манифестами.

Проба `@tls` с дверью `kit` — к процессу последнего `@kit-start`: вход `{door: "kit", url, client, request}`, `url` — адрес
соединения с подстановкой `{port}` (порт двери этого процесса). Клиент стенда проверяет сервер как клиент своего
кластера (`own_client`): отпечаток центра комплекта, роль процесса, `host` — `server` комплекта, если хост `url` —
литерал петли (порог `loopback`), иначе хост `url`; затем отзыв (`revoked` комплекта пуст). Исход — закрытая форма выше
с полем `peer`: `"ok"` или слово договора `peer`; при слове рукопожатие клиент закрывает — `handshake: "ok"` (сервер не отказывал), `http: null`, `version` может быть `null`. Сервер отказал рукопожатием — `handshake: "alert"`, `peer: null`, `http: null`. Отказ проверки
сервера у двери `kit` — исход пробы, не класс «стенд» (у прочих дверей — как прежде). Клиент судит шаги `peer` над цепочкой рукопожатия: лист без центра в `chain[1:]` — `foreign_ca` (шаг 3). Из слов таблица называет `wrong_name`; прочие слова приёмкой не судятся, кроме `peer: "ok"`.

- Консоль с комплектом слушает на `CONSOLE_HOST` умолчания `127.0.0.1` (P/02.4 N1.6 `console`: TLS и на петле).
- `own_client`: при литерале петли в `url` `host` — `server` комплекта; `localhost` — имя и проверяется как имя (`loopback`): лист, который его не несёт, даёт слово `wrong_name`, без ответа HTTP; системный хост стенда не трогается.
- `DOMAIN_CONSOLE_HOST` умолчание `0.0.0.0` без комплекта — отказ старта (`@exit 2`; N1.6 `console`, `process`); без `SIGNER_HOST` умолчание процесса `0.0.0.0` не явный адрес — отказ старта без комплекта ((5) п. 4); явный адрес вне петли без комплекта — старт с громкой строкой (N1.6 `process`).
- [Договор файла окружения](../../contracts/env-file.md) `TIMEZONE` (ADR-0094 B6; P/06.3-06): пустое значение или значение вне грамматики — отказ старта (`@exit 2`), значение по форме принимается; сверяется только форма, консоль базы поясов не читает; у консоли на петле комплект не нужен.

## Четвёртый кластер — ветви ER (п. 9; [P/08.8 N1.8](../../../../08-domain/ru/spec/08.8-domain.norms.md) шаг 6)

Подготовка: `@until` резервной копии у хранителей `BACKUP_HOLDERS` (порядок по убыванию sha256 «hold/<член>», подтверждается на живом состоянии строками `domain/keepers/<member>` держателя, [P/08.8 N1.5](../../../../08-domain/ru/spec/08.8-domain.norms.md)); только затем — приём цели теми же шагами, что `@domain`: `@start agent <member>`, приём по отпечатку из `knocking` (`POST /domain/members`), `@join <member>`, `@until` цель — `ok` и держит набор держателя. Так цель не бывает хранителем ни на один проход и своей резервной копии не имеет; копию у члена не выбрасывает никто (P/08.8 N1.5; без `copy` перенос восстановил бы её — N1.8 шаг 6 — вместо отказа). Затем `@until` у цели записи срока ≥ 1 (следование, [P/09.1](../../../../09-agent/ru/spec/09.1-agent.norms.md) N3) и резервной копии у хранителей; затем `@stop domain`.

- **«Сосед не ответил»** (ER, добавлено моделью Quint M11): когда ни один сосед не отвечает (`@cut-route` всех соседей; держатель держит свою копию `domain/backups/rev-N` и иначе отдал бы её), перемещение без `copy` и `why` получает отказ 409, `detail` называет не ответившего соседа, нового срока нет; перемещение с `why` на **другом экземпляре** той же подготовки идёт «из ничего», с `restored_from: null`, срок — прежний + 1.
- **«Копии нет нигде, все ответили»** (без `why` — 409, с `why` — «из ничего») и **«нет ни записи, ни копии»** (шаг 6,
  `nothing to restore from`): на публичных дверях стенда недостижимы детерминированно — первая резервная копия делается
  первым проходом держателя, держатель и хранители её отдают; член без записи срока не получает и грантов (личность
  переноса). Снять копии подготовкой стенда тоже нельзя: резервные копии — объекты (`domain/backup` у хранителя,
  `domain/backups/rev-*` у держателя; P/08.8 N1.5), admin-операции хранилища удаляют строки (снять можно лишь указатель
  `domain/backup-taken`), общего договора удаления объектов нет; частные файлы реализации стенд не трогает (согласовано с
  «cammeta-acceptance», решение «Архитектора» 2026-10-20). Проверка чтением — [P/08.8 N5](../../../../08-domain/ru/spec/08.8-domain.norms.md) («Проверяются чтением», шаг 6
  переноса), как п. 3; README приёмки [главы 8.8](../../../../08-domain/ru/acceptance/8/README.md), сц. 03.
