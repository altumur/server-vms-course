# Стенд процессов testsub

Этот русский текст — производный от `acceptance/testsub-stand.md`, руками не правится.

Тема [общего README приёмки](README.md): директивы и двери — его [словарь](README.md#словарь-директив-и-дверей).

Стенд ролевых процессов на одном сервере над манифестами стенда `testsub` и `testsub2`: одно хранилище, одна консоль и контроллеры, воркеры и ресурсы, которые запускают шаги. README урока, который пользуется этим стендом, ссылается на этот раздел и пишет только свою подготовку, роли и исключения. Раздел не вводит норм продукта.

- **Каждый сценарий на свежем стенде.** Перед первым шагом сценария судья останавливает все процессы предыдущего сценария и ждёт завершения каждого, в том числе прежней копии имени и процесса, который остановили и запустили снова; только после этого удаляет их состояние. Сценарий получает новый каталог данных `{data}` и новые порты, поэтому строк, объектов, событий, замков присутствия и кэшей предыдущего сценария не остаётся: новое хранилище с пустой памятью id, новая консоль без заявок POST, нет связанных имён `$name` и ключей повтора судьи. Судья запускает хранилище, ставит манифесты стенда с их служебными метками командой `manifest-put` в порядке «Манифесты» [стенда](stand.md#раскладка-по-процессам-стадия-c), затем запускает консоль; их двери готовы до первого шага. Подготовка не переносит состояние предыдущего сценария и не проверяет установщик. README урока, который сохраняет хранилище между сценариями одной таблицы, говорит об этом в своих границах (P/06.2).
- **Нет чужих процессов.** Нет контроллеров, воркеров, ресурсов, запасных процессов и таймеров старта, которых не запускают шаги сценария; роль, запущенную до первого шага, называет README урока (ресурс P/03.6).
- **Одна коробка.** У каждого процесса коробка стенда `BOX_ID` и `SERVER_NAME=srv-a`, кроме слов `on <сервер>` и `<ИМЯ>=<значение>` у `@start`; каждый запуск — новый экземпляр. Параметры и сроки манифестов стенда — значения манифестов: судья не ускоряет их ради теста.
- **Остановка.** `@sigterm` и `@sigkill` посылают сигнал группе процессов названного живого процесса сценария и совпадают с `ok` только после выхода всей группы, по N3.2 [норм](spec/acceptance.norms.md) (R017; только для судьи: нормы судьи). Остановка с истёкшим сроком или имя, не называющее живого процесса сценария, — несовпадение шага, а не `ok`.
- **Время сценария.** README урока не задаёт бюджета сценария: бюджет — сумма ожиданий его шагов плюс запас судьи (N3.3, R036), и судья не заканчивает сценарий, пока ожидания его шагов не истекли.
- **Параллельные сценарии.** Сценарии, идущие одновременно, берут каждый свои каталоги данных и порты.
