**Коды выхода команд-векторов M11.** Код 2 — нарушена форма того, что вызывающий берёт из своего
доверенного состояния: `keys`, `pub`, `cluster`, `field`, `domain`, `now`, `lost_after`, имена членов, `history`, строки
`grants`. Код 0 со словом — плох документ, который функция по норме сама оценивает, потому что он пришёл от другого
кластера: `row` и `held` (через `record`), `answers.<кластер>`, `page`. Доверенный вход функция не перепроверяет сверх
формы (например, подпись набора `keys` проверена при записи — P/08.2 N3 keys). Ожидание кода — `@exit 2` ([словарь](README.md#словарь-директив-и-дверей));
случаи без шага перечисляет N5 урока.

## Стенд нескольких кластеров

**Кластеры** (M11/3). Кластеры `hold` (держатель), `m1`, `m2` — каждый со своим хранилищем, `{data}`,
сокетами ролей, портами и кольцом (README приёмки [главы 8.3](../../../08-domain/ru/acceptance/3/README.md), «Подготовка каждого
сценария»). Подстановки: `{domain}` — `acme`, `{recovery}` — файл восстановления установки в каталоге экземпляра. Между
агентом каждого кластера и дверью держателя раннер держит свой TCP-посредник: `DOMAIN_URL` агента указывает на него.

Подстановки команд стенда домена (их шаблоны называет описание реализации, [P/08.3](../../../08-domain/ru/spec/08.3-domain.norms.md) и [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) «Решает реализация»): у команд процессов
кластера — `{data}` и `{socket}` своего кластера, `{port}` — порт двери этого процесса; у установки и `join` — `{domain}` и
`{recovery}` (у `@join <кластер> <файл>` `{recovery}` — названный файл). Файл восстановления раннер отдаёт копией с режимом
0600: git хранит `inputs/*.json` с 0644, а реализация проверяет режим при чтении (P/08.2 N1.1 `mode`). Агент
получает окружение `CLUSTER`, `DOMAIN_URL` (посредник) или `RELAY_URL` (P/09.1), при `@clock` — `W2C_WALL_OFFSET`.

**Ретранслятор** (P/09.2): четвёртый кластер стенда `relay`; его агент всегда открывает дверь ретранслятора
(`RELAY=1`, `RELAY_HOST=127.0.0.1`, `RELAY_PORT` — порт `{relay_port}` копии), посредник раннера стоит и перед ней. Копии ретранслятора стартуют раньше членов за ним: `@start agent <кластер> via relay` до копий ретранслятора — ошибка данных, вторая копия ретранслятора при живом члене `via relay` — сбой стенда. `@cut relay` рвёт дорогу ретранслятора
к держателю; двери членов к ретранслятору — свои посредники (`@cut <член>` рвёт дорогу члена, какой бы она ни была).

**Окружение пересылки** (M11/8; `@env` — [P/06.7](../../../06-console/ru/spec/06.7-console.norms.md) «Решает реализация» п. 2): консоль каждого кластера получает `CLUSTERS` — адреса консолей всех кластеров стенда
(`hold=<url>,m1=<url>,m2=<url>[,relay=<url>]`, без посредников; на стенде с комплектом TLS или у сценария с `@cut-route` значения — адреса посредников дорог раннера); процесс `domain` — `DOMAIN_CONSOLE_URL`, адрес двери
консоли домена; `SIGNER_URL` — только консоли `hold`. Комплекта TLS у стенда нет: двери на петле по `http://`
(P/02.4 N1.6). `Idempotency-Key` у `POST`, `PUT`, `DELETE` пути `/domain/…` двери `member <кластер> console` раннер
ставит, как у двери `holder`.

**Ожидания** стенда домена — формы [словаря](README.md#словарь-директив-и-дверей): `<код> <JSON>` подмножеством, `$name`, `@spoil($name)`, `@any`/`@absent`,
`@not`, `@time`, `~text` (например `~enc:v2:` — конверт кольца члена), `!contains`, `@exit`; у команд-векторов и `@carry` —
`ok <JSON>`, у `@join` — `ok` или `refused`, у `@move` — `<код> <JSON>` ответа двери. Сны (`@sleep`) с причинами — в README
приёмки главы.
