### Словарь директив и дверей

Одно определение на модуль. README урока ссылается на этот словарь и пишет только своё: подготовку, роли и
особые правила сравнения. Колонка «Урок» — урок, который ввёл директиву: число — прежний урок M10/N,
`P/NN` — урок модуля, `M11/N` — урок M11, `-` — форма без урока; урок, вводящий новую,
добавляет строку сюда. Директиву или дверь, которой пользуется только один урок, определяет README приёмки этого урока; её строка здесь называет урок и ссылается на определение.

**Строка `scenarios.tsv`** (только для судьи: таблиц сценариев уроков нет в M) — ровно четыре ячейки `scenario`, `step`, `request`, `expect` через табуляцию. Ячейка не содержит ни TAB, ни LF и не знает экранирования; таблица с объявлением `# cell-json:` оборачивает названные ячейки по [форме исходных ячеек](../contracts/source-cells.md), которая декодируется один раз. Пустые строки, строки из пробелов и строки, начинающиеся с `#`, — заметки, они пропускаются; строка, первая ячейка которой ровно `scenario`, — заголовок и тоже пропускается, поэтому таблица может записать заголовок и заметкой `#`. `expect` пуст только у шага `ASSERT` (он может написать и `ok`). Шаги сценария нумеруются с 1 подряд (1). Строка вне этой формы или вне форм этого словаря — ошибка данных таблицы, она находится до запуска стенда и не считается исходом реализации.

**Двери** — префикс `request`. Без префикса запрос идёт в дверь урока: хранилище в P/01 (главы 1.1, 1.2) и P/02.5, консоль в главах P/06 6.1, 6.3, 6.5, 6.6.

Связанные правила: [P/AC-R006](spec/acceptance.norms.md#n13-реестр-целей) и [P/AC-R020, P/AC-R024](spec/acceptance.norms.md); двери с аргументами определены в [стенде домена](domain-stand.md#стенд-домена) и [стенде pass](pass/README.md). Адреса store: [подстановка заголовка роли](../../../01-store/ru/acceptance/2/README.md#проверки-вне-сценарного-файла) (P/01.2-R017), [порядок имён list](../../../01-store/ru/acceptance/1/README.md#scenariostsv) (P/01.1-R065), [закрытые исходы TLS](tls/README.md#исход-пробы--закрытая-форма) (P/01.3-R059) и [полная форма контрактов ответов](#полная-форма-по-дверям) (P/01.3-R211).

| Дверь | Договор полной формы |
|---|---|
| `store`, `admin`, `restored`, `store@<id>`, `admin@<id>` | P/01: схема ответа операции (метод и путь) и статуса в [`01-store.api.openapi.yaml`](../../../01-store/spec/01-store.api.openapi.yaml) |
| `console`, `console2`, `member <кластер> console`, `member <кластер> console2`: пути `/api/…` и `/domain…`; на стенде, кроме стенда домена, — любой путь | P/06 |
| `console` на пересланном пути `/domain/at/<кластер>/…` успешного ответа | P/06 пересланного пути |
| `worker <имя>` | P/03.4 N1.7 для отказа `busy` двери процесса; для прочих ответов — договор вызываемого маршрута |
| `resource`, `resource#<имя>` | P/05 |
| `holder`, `holder@<кластер>` | P/10, затем P/08: первый договор, называющий операцию |
| `signer`, `signer2` | P/08 |
| `token <кластер>` | P/09 |
| любая из дверей выше с отказом `deposed`, `frozen` или `standby` | `Refusal` из P/08 |

На стенде без комплекта `no_role`, `wrong_role` или `bad_chain` от `holder` по простому HTTP — несовпадение (P/10 `no_kit`). Полная форма не судится для двери `socket`, для пути консоли стенда домена, кроме `/api/…` и `/domain…`, и для тела не в JSON, если строка его двери этого не требует.

Тело ответа, сравниваемое как JSON, разбирается строго: повтор имени объекта на любом уровне или не-JSON константа числа (`NaN`, `Infinity`) — несовпадение шага.
