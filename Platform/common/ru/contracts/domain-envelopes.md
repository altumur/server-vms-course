## Конверт `x25519:v1`

Из M11/2 N1.5:

Секретное поле (`*_secret`, [P/02.1](../../../02-installer/ru/spec/02.1-installer.norms.md) N1.3a) вклада члена в книгу едет к держателю конвертом к `book_seal`: агент запечатывает
до подписи отчёта (урок 3), ретранслятор несёт байты (урок 4), держатель открывает только при сборке книги (урок 5).

```yaml
envelope:      x25519:v1:<eph>:<nonce>:<ct>          # ровно пять частей через «:»; части 3–5 — base64url без «=»
  eph:         32 байта — открытый ключ X25519 одноразовой пары запечатывающего
  nonce:       12 случайных байт
  ct:          AES-256-GCM(key, nonce, plain, aad) с тегом 16 байт; не короче 16 байт
key:           HKDF-SHA256(ikm = X25519(eph_priv, book_seal), salt = eph ‖ book_seal, info = "w2c book seal x25519:v1", L = 32)
               # при открытии ikm = X25519(seed_secret, eph); book_seal — открытая половина seed_secret
aad:           UTF-8(JCS([member, source_path, item])) ‖ 0x00 ‖ UTF-8(pointer)
  member:      имя члена-вкладчика
  source_path: ключ строки-источника вклада в хранилище члена (урок 5: строка семьи domain.books.<книга>.from)
  item:        элемент этой строки — вклад
  pointer:     JSON Pointer секрета в JSON-документе элемента — по правилу пути договора запечатывания (`~0`, `~1`, индексы)
plain:         байты UTF-8 значения секрета как дано; пустое значение тоже запечатывается
seal:          новая пара eph и новый nonce на каждый конверт; два конверта одного значения различны; book_seal малого
               порядка (X25519(eph_priv, book_seal) — нулевой общий секрет) — конверта нет, отказ not_an_envelope
               (добавлено сверкой M11, S1)
```

Отказ открытия — одно из трёх слов, значение не повторяется ни в причине, ни в журнале ([P/06.2](../../../06-console/ru/spec/06.2-console.norms.md) N1.4):

| Слово | Когда |
|---|---|
| `not_v1` | текст не начинается с `x25519:v1:` (другая версия, другой конверт, не строка) |
| `not_an_envelope` | частей не пять; часть — не base64url без `=`; `eph` не 32 байта, `nonce` не 12, `ct` короче 16; X25519 даёт нулевой общий секрет |
| `does_not_open` | AEAD не открылся (не тот ключ приёма книг, иной member, source_path, item или pointer, испорченный `ct`) или открытые байты — не UTF-8 |

Подмена AAD и чужой ключ неразличимы — обе причины — `does_not_open`. Подбор иных AAD при открытии запрещён.

Из M11/2 N3 «`seal(book_seal, plain, aad)` и `open(seed_secret, envelope, aad)`»: запечатывание и открытие — N1.5 (здесь —
блок выше); порядок проверок открытия: `not_v1` → `not_an_envelope` → `does_not_open`.

Тот же конверт с другим контекстом AAD — ключи передачи держателя `keys_sealed` (к `seal` цели, AAD `take|<to>`; форма
открытого текста и отказ — [P/08.8 N1.7](../../../08-domain/ru/spec/08.8-domain.norms.md) шаг 5).

## Конверт `m1`

Из M11/3 N1.5:

```yaml
envelope_m1:    m1:<eph>:<nonce>:<ct>             # как x25519:v1 урока 2 N1.5: четыре части через «:», 2–4 — base64url без «=»
  recipient:    X25519 ключа члена: u = (1 + y)/(1 − y) mod 2^255 − 19 из y открытого Ed25519 (старший бит сброшен),
                little-endian (RFC 7748 §4.1); закрытый — первые 32 байта SHA-512(seed_secret) как скаляр X25519
  eph:          32 байта — одноразовый X25519; nonce — 12 случайных байт; ct — AES-256-GCM с тегом 16, не короче 16
  key:          HKDF-SHA256(ikm = X25519(eph, recipient), salt = eph ‖ recipient, info = "w2c carry to a member", L = 32)
  aad:          UTF-8("m1" + hex открытого ключа члена)
  plain:        UTF-8 текста JSON-объекта
```

Отказ открытия — слово, значение не повторяется: `not_m1` (текст не начинается с `m1:`), `not_an_envelope` (частей не
четыре, часть не base64url без `=`, `eph` не 32 байта, `nonce` не 12, `ct` короче 16, нулевой общий секрет),
`does_not_open` (AEAD не открылся или не UTF-8). Подбор иных форм запрещён.

## Вклад

Перенесено из [P/03.7](../../../03-worker/ru/spec/03.7-worker.norms.md) N1.2 (`source_row` `entry`) без изменения поведения: форму
входа пишет воркер (P/03.7), несёт агент (P/09.1 N1.2 `in_report`), проверяет сборка книги держателя (P/08.5 N1.3, N3 шаг 4)
(аудит раскладки A-22, решение «Архитектора» 2026-10-25). Строка вклада — `<sub>/<строка>` или `<sub>/<строка>/<слот>`, элемент — вход книги: имя элемента — `item`,
значение — текст JSON-объекта (P/03.7 N1.2 `source_row`).

```yaml
entry:       JSON-объект: поле key — непустая строка, поле to — имя члена, список имён или "servers" — все члены class server этого прохода: копия списка у воркера только свои разделы, перечислить всех он не может (ADR-0113 доп. (8) п. 4, доп. (9) п. 2); имя servers занято: P/08.3 N3 «принять члена» шаг 1. Адресат «все» — объявление книги to: "*" в манифесте, P/08.5 N1.3 to_all: поле to такого входа не читается, а "*" во входе обычной книги — bad_contribution; прочие поля — воркера;
             *_secret на любой глубине — секрет (P/06.2 N1.1; и поле с именем ровно `_secret`, без префикса — сверка M11,
             совпало у реализаций), в строке члена — конверт кольца члена (договор запечатывания) с AAD
             профиля P/08.5 N1.3 at_rest: ключ строки, 0x00, «/<item>» и JSON Pointer секрета в тексте элемента
```

## Содержимое `sealed`

Поле `sealed` ответа держателя агенту (`carry`, [P/08.3](../../../08-domain/ru/spec/08.3-domain.norms.md) N1.5) —
конверт `m1` с JSON-объектом секретного члену. Из M11/3 N1.5 `sealed?`, M11/5 N1.4 `carry`, M11/9 N1.3 `carry` и N1.6 `carry`:

```yaml
sealed:         конверт m1 с JSON-объектом секретного члену; только когда секретное или held есть — пустого конверта нет
                (добавлено сверкой M11, D8)
  grants?:      {doc} — строка domain/grants/<член> (P/08.4 N1.3 carry)
  anywhere?:    {as_of, sha256} — сводка P/08.4 N1.3 anywhere; тело по двери при смене; не зависит от grants
                sha256 именует всё значение {doc, as_of} тела 200 по P/08.4 N1.3 carry (G09-ANYWHERE-HASH-01); as_of входит в хеш
  held?:        [<имя поля>…] из "grants", "roles", "anywhere", "break_glass" — не послано в этом проходе, копии не трогать (P/08.4 N1.3, N1.6 carry): строка нечитаема, сборка не сошлась, таблица сверх предела;
                отсутствие поля без его имени в held значит «строки нет»
  roles?:       {doc_sha256, groups, assigned, admin_at} — таблица ролей этого члена (P/08.4 N1.3b); идёт всегда вместе с grants, только с ним;
                пустая — {doc_sha256, groups: {}, assigned: {}, admin_at: {}}; посредник (P/09.2) назначений не видит (ADR-0098 §4)
  break_glass?: {pwhash_secret, set_at} (P/08.4 N1.6 carry)
  books?:       {<sub>: {<книга>: {<item>: <текст JSON>}}} — строка domain/<sub>/<книга>/<член> держателя, секреты открыты; книга to: "*" здесь не идёт: carry.book_rev (P/08.5 N1.4)
                кольцом держателя перед m1 (P/08.5 N1.4 carry)
```

Открытое содержимое `sealed` имеет нынешнюю закрытую форму выше. Неизвестное поле делает это содержимое нечитаемым; пропуск поля не означает принятия. Копии, их метки свежести и связанные записи сохраняются по прежнему пути непринятого содержимого P/09.1 N1.4. Криптографическая функция открытия m1 и её исторические байтовые свидетели не меняются. Что пишет агент из открывшегося конверта и что делает с неоткрывшимся — [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 (`sealed`, `member_row`,
`member_copy`, `break_glass`). Конверт `m1` ответа двери токенов держателя несёт текст JSON `{request_id, token, exp}` (P/08.7 N1.3 `answer`).

## Векторы

Пакет [`domain-envelopes`](../vectors/domain-envelopes/README.md) (разбор ревью стадии A 8–10, № 12): открытие
`x25519:v1` (`x25519-open.tsv`) и `m1` (`m1-open.tsv`), круги `seal-round` (`x25519-round.tsv`) и `seal-member-round`
(`m1-round.tsv`). Строки — входы команд-векторов приёмки M11/2 (`seal`, `seal-round`) и M11/3 (`seal-member`,
`seal-member-round`) без изменения байтов; сценарии и входы сняты переносом урока 8 — таблицы единственный источник этих
случаев. Реализация проходит их своей функцией, без стенда. `keys_sealed` и содержимое
`sealed` требуют публичных последовательностей проб содержимого [эксплуатационных обязанностей](../vectors/production-obligations/README.md); исполняемые привязки принадлежат раннеру и остаются NOTEXEC до поставки.

Команда `seal-member` принимает `{seed, sealed}` и возвращает `{result: ok, plain}` или `{result: refused, reason}`. Команда `seal-member-round` принимает `{key, seed, plain}` и возвращает `{result: ok, sealed: [<m1>, <m1>], opened: [<plain>, <plain>], distinct}`.

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../vectors/jcs/README.md)
общего договора JCS (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).
