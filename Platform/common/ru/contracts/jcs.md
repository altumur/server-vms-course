# Канонический JSON (JCS, RFC 8785)

Текст производный от `contracts/jcs.md`, руками не правится: источник — английский [`contracts/jcs.md`](../../contracts/jcs.md), правка идёт в него, русский пересобирается переводом.

Текст JSON, который договор платформы подписывает или сравнивает байтами, использует RFC 8785 целиком, без отступлений.

## Каноническая форма

- Ключи объекта упорядочены по кодовым единицам UTF-16, а не по кодовым точкам Unicode. Различие касается ключей со знаками вне основной многоязычной плоскости.
- В выходе нет пробелов между токенами. Строки кодируются в UTF-8; экранируются только управляющие знаки, `"` и `\`. У остальных знаков нет экранирования `\uXXXX` или HTML: `<`, `>` и `&` остаются буквальными.
- Числа используют кратчайшую запись ES6 `Number.prototype.toString`: `1.0` становится `1`, `1e21` — `1e+21`, а `-0` — `0`. `NaN` и `Infinity` отказаны.

SHA-256 канонического текста JSON считается по байтам UTF-8 этой формы.

## Потребители и векторы

Общий пакет [`jcs`](../vectors/jcs/README.md) задаёт форму таблицы, провод команды и роли, исполняющие векторы. Вызывающий приводит к канону значение JSON, названное его собственным договором; этот договор не расширяет поля или документы, которые подписывает вызывающий.
