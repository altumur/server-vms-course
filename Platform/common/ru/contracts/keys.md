## Набор `domain/keys`

Форма строк семей — `Platform/08-domain/data/keys.schema.json`, `keys.outcomes.tsv` и
`Platform/08-domain/data/revoked.schema.json`, `revoked.outcomes.tsv` (C04-DEP-OBS-HEARTBEAT-01: файлы данных, названные договором, — в чтении `common`, ADR-0083 доп. (32) п. 1).

Из M11/2 N1.2:

```yaml
row:           domain/keys {doc: <текст JSON документа>}   # ровно один элемент doc, строка; иной состав — not_a_set;
                                                           # строка хранилища (P/01.1); писатель у держателя — процесс domain,
                                                           # у члена — агент (урок 3) после функции keys (N3); агент кластера
                                                           # держателя её не пишет, пока кластер держит срок (договор записи срока «Точка смены `switch`»)
doc:                                                       # закрытый набор полей; лишнее поле — not_a_set; массивы — без
                                                           # значения порядка, повтор элемента допустим; писатель — по возрастанию
  domain:          имя домена (N1.1)
  rev:             целое 1 … 2^53−1
  root:            hex открытого корня
  current:         kid ключа токенов, которым держатель подписывает сейчас; ∈ keys; ∉ until
  keys:            {<kid>: <hex открытого ключа токенов>}, не пусто; kid — непустая строка
  until?:          {<kid>: <стенные секунды>} — ключ ещё принимается до этого момента включительно; kid ∈ keys
  keep_until?:     {<kid>: <стенные секунды>} — ключ ещё принимается для видов keep (договор токена шаг 5a; ADR-0110 доп. (10)); kid ∈ keys и kid ∈ until: ключ с keep_until хранит и истёкший until, иначе шаг 5a молчал бы и ключ принимался бы всем видам; без этого — not_a_set (ADR-0110 доп. (12) п. 1); истёкший until снимается только вместе с keep_until; не больше 8 живых, старший снимается, журнал domain.keys.keep_dropped
  issuing:         [<serial>…] — ключи выпускающего держателя (урок 10); serial — непустая строка
  revoked_issuing: [<serial>…] — отозванные ключи выпускающего; всегда массив, может быть пустым
  revoked_members?: [<hex ключа члена>…] — отозванные ключи членов (урок 3: приём и подпись члена сверяются с ним)
  stolen_issuing?: [<serial>…] — выпускающие, отозванные кражей и всё прошлое до неё (P/08.2 N3 шаг 3), подмножество revoked_issuing, иначе not_a_set; нет — пусто; переходит в каждый следующий набор; источники сбора «из ничего» — revoked_issuing без них (P/08.8 N1.8a; ADR-0113 доп. (16) п. 2)
  thefts?:         целое 1 … 2^53−1 — счёт смен после кражи (P/08.2 N3 шаг 3); нет — 0; переходит в каждый следующий набор
  book_seal:       hex открытого ключа приёма книг X25519 (N1.4); обязателен: набор без него не читается; точка малого
                   порядка (X25519 с любым скаляром даёт нулевой общий секрет, RFC 7748 §6.1) — набор не читается
                   (добавлено сверкой M11, S1)
  kid:             "root"
  sig:             base64url подписи Ed25519 корня над UTF-8(JCS(doc без kid и sig))
writer_forms:      kid ключа токенов = первые 8 знаков hex его открытого ключа; serial = первые 16 знаков hex открытого
                   ключа выпускающего; читатель принимает любую непустую строку
only_forward:      член держит один набор; набор с меньшим rev — отказ, с равным — «держу», не переписывается
```

`rev` нового набора у писателя (обычная, плановая и аварийная смена) — [P/08.2](../../../08-domain/ru/spec/08.2-domain.norms.md) N1.2 `rev`, `emergency`, `clocks`.

## Отпечаток ключа

Из P/08.2 N1.1 `fingerprint` без изменения поведения (владелец текста — P/08.2 N1.1; здесь — для урока P/09, который
печатает отпечаток ключа члена, P/09.1 N1.1 `born`; разбор ревью стадии B 8–10, № 4, Claude S-1):

```yaml
fingerprint:   hex(sha256(<32 байта открытого ключа>)[:8]) — 16 знаков; так корень и ключи называют люди и журналы:
               отпечаток корня (установка домена, join), ключа члена (строка журнала агента «member key <отпечаток>»,
               приём оператором — P/08.3 N1.1, поле knock.fingerprint)
not_serial:    отпечаток — не serial (writer_forms выше: первые 16 знаков hex самого открытого ключа, без sha256) и не

```

## Функция `keys`

Из M11/2 N3 «`keys(pinned, held, offered) → took rev | holding rev | refused <слово>`»:

Функция агента члена над набором из ответа держателя (урок 3) и процесса domain над своим набором при смене. Шаги — по
порядку; первое сработавшее правило даёт итог.

```
1. pinned нет                                                              → refused no_pin
2. offered не {doc: строка}; doc не JSON-объект или с повтором ключа, поле вне закрытого набора N1.2, обязательного нет,
   тип или граница не по N1.2 (кроме book_seal)                            → refused not_a_set
   # kid или sig не строка, root не hex 32 байт — здесь; пустой issuing допустим (непустота названа только у keys)
3. kid ≠ "root"                                                            → refused bad_signature
4. doc.root ≠ pinned.pub или doc.domain ≠ pinned.domain                    → refused another_root
5. подпись sig не проверяется ключом pinned.pub над JCS(doc без kid и sig) → refused bad_signature
   # sig — строка, но не base64url или не 64 байта — тоже здесь
6. book_seal нет, не hex 32 байт или точка малого порядка (N1.2)            → refused no_book_seal
7. held есть: doc.rev < held.rev → refused older (rev held); doc.rev = held.rev → holding (rev held)
8. иначе                                                                   → took (rev doc); строка domain/keys := offered
```

Отказ не меняет строку `domain/keys`; член продолжает верить прежнему набору и пишет причину в журнал (M13).

`held = null` — у агента без доверенного набора в памяти и с нечитаемой своей строкой (после старта): шаг 7 не судит, набор принимается от закреплённого корня; предел отката — [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `from_carry` (ADR-0110 доп. (28)).

«N1.2» в шагах 2 и 6 — раздел «Набор `domain/keys`» выше; `pinned` — `{pub, domain}` строки `domain/root` ([договор основания домена](domain-founding.md) «Закрепление корня»; форма — «Форма» выше).
Форма функции — вход команды `keys` ([P/08.2](../../../08-domain/ru/spec/08.2-domain.norms.md) N5).

Копия из P/08.2 N5 (аудит раскладки, решение «Архитектора» 2026-10-25, B-14):

```yaml
# Входы — закрытые объекты: все поля обязательны, кроме помеченных «?» (null — где назван), лишнее или иного типа поле — код 2.
keys:        вход {pinned: Pin | null, held: <doc по форме «Набор domain/keys», которому член верит> | null, offered: <строка domain/keys как пришла>}
             вывод {result: took | holding, rev} | {result: refused, reason: no_pin | not_a_set | bad_signature |
                   another_root | no_book_seal | older, rev?}            # rev при older — rev held
held:        не по форме «Набор domain/keys» (включая book_seal) — код 2: это набор, которому член уже верит
Pin:         {pub, domain}                     # pinned во входе не по этой форме — код 2
output:      закрытые объекты выше; ключи — в любом порядке
exit:        0 — вычислено (в том числе отказ словом); 2 — вход не по этой форме
```

## Отзывы `domain/revoked`

Из M11/2 N1.6:

```yaml
domain/revoked: {jtis: "<jti>:<exp>,…"}      # ровно один элемент jtis, строка; пусто — ""; строки нет — отзывов нет;
                                            # иной состав, запись не «<jti>:<число JSON>» (jti по грамматике токена) — не по форме:
                                            # token → no_revocations; повтор jti и порядок читатель не проверяет
  writer:      процесс domain при отзыве (урок 9: человек; урок 7: токен вида) и при каждом проходе держателя, CAS по прочитанной версии: иначе проход
               затёр бы отзыв той же минуты; конфликт отзыва — перечитать, не больше 3 раз, затем 503 unavailable; конфликт прохода — следующий проход
               (C08-REVOKED-CAS-01); у члена —
               агент объединением ответа держателя со своей строкой (урок 3 N1.6 from_carry; добавлено моделью Quint M11,
               RV): у члена запись снимает только prune; агент кластера держателя её не пишет, пока кластер держит срок (договор записи срока «Точка смены `switch`»)
  order:       по возрастанию jti в байтах; exp — число JSON, exp отозванного токена
  repeat:      повтор jti в одной строке (своей или ответа) при слиянии и чистке — для jti берётся наибольший exp, затем prune:
               повтор не сокращает отзыв (x:100,x:200 при now = 161 — остаётся x:200; догадка стадии C KEYS-G01, решение «Архитектора» 2026-10-23)
  prune:       записи с exp + TOKEN_SKEW < now, строго, писатель ДОЛЖЕН снимать — список ограничен числом живых токенов;
               при now = exp + 60 токен ещё годен (N3 token шаг 6), и его отзыв стоит (ADR-0074 доп. 7)
  readers:     консоль кластера, роли воркеров — платформенной основой прав (P/02.5 N1.4), агент (урок 3); у члена — копия
```

Из M11/3 N1.6 `from_carry` (агент члена, поле `revoked` ответа держателя; ныне P/09.1 N1.4 `from_carry`):

```yaml
merge:          revoked → объединение с своей строкой domain/revoked: записи ответа ∪ свои по jti (при равном jti — больший
                exp); снимает только prune урока 2 N1.6 (exp + TOKEN_SKEW < now) — отзыв ответом не отменяется (добавлено
                моделью Quint M11, RV: после аварийного переноса ответ из копии иначе снял бы отзыв последних BACKUP_EVERY);
                так и после переноса без stolen. Исключение — смена после кражи: агент, записавший domain/keys набором с thefts
                выше, чем у доверенного набора своей памяти (P/09.1 N1.4 from_carry; не из строки — доп. (25) п. 1), любым путём —
                ответом держателя (from_carry) или следованием (запись domain/holder с набором, «Набор следования»), — тем же
                пакетом ставит domain/revoked := {jtis: ""}, а набор из ответа — {jtis: ""} ∪ отзывы этого ответа. Памяти нет и
                своя domain/keys не читается — строку не трогает до ответа держателя, затем сливает (ADR-0110 доп. (25) п. 2, доп. (26)).
                Любое слияние больше ceiling (413) — заменяет строкой ответа, журнал domain.revoked.replaced; бывает в основном
                после очистки кражей, тогда строка держателя ничего не потеряла (доп. (27) п. 1; предел — P/09.1 N1.4 from_carry).
                Держатель строку очистил (P/08.2 N3 шаг 3b): её отзывы — токенам прежних ключей,
                шаг подписи их больше не пропускает; отзывы после смены приходят обычным слиянием. Иначе полная строка держалась бы
                годами, новые отзывы вывели бы её за ceiling, запись агента — 413, и отозванный после смены токен у члена проходил бы;
                член обычно берёт аварийный набор следованием раньше отчёта, ответ тогда holding, поэтому правило — по записи набора,
                а не по ответу (ADR-0110 доп. (22), доп. (24) — заменяет «ответом заменяет» доп. (22));
                своя строка не читается — агент, единственный писатель у члена, перезаписывает её CAS по прочитанной
                версии записями ответа, причина в журнал без значения (V7 п. 3, решение «Архитектора» 2026-10-28, P2; строка 44 списка)
```

`TOKEN_SKEW` и «N3 token шаг 6» — [договор токена домена](domain-token.md) «Токен», «Проверка»; «prune урока 2 N1.6» —
строка `prune` выше. Когда агент применяет поле `revoked` (после исхода `took` или `holding` функции `keys` над набором того
же ответа) — P/09.1 N1.4 `from_carry`.

## Набор следования

Перенесено из [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N3 «следовать» шаг 1a без изменения поведения (аудит раскладки, решение «Архитектора» 2026-10-25,
A-08). Набор следования — память агента члена; им проверяются записи срока шагов 2–4 «следовать» (P/09.1) и записи
переноса (набор переноса — тем же правилом, P/08.8 N1.8 шаг 5, начало прохода для него — начало шага 5; отличие набора переноса: своя domain/keys, которую не
подтверждает своя domain/holder, прошедшая record этим набором (своя запись испорчена, нечитаема или её нет; обрыв переноса такой строки не оставляет, P/08.8 N1.8 шаг 8): набор переноса начинается не
с неё, а с null (закреплённый корень), а служит она, только если ни один сосед набора не дал; её rev входит в наибольший
известный rev аварийного rev (P/08.2 N1.2 emergency); набор следования агента — прежнее правило
(C08-MOVE-UNCONFIRMED-KEYS-01, -02)); точка смены по нему — договор записи срока «Точка смены
`switch`».

```
keys ответов /api/held — функцией keys (договор набора ключей домена) по закреплённому корню в набор следования — память агента, с
начала — строка domain/keys своего хранилища (перенос без stolen меняет выпускающий: новый набор приходит так, раньше
ответа нового держателя); набор ответа берётся, только если запись срока того же ответа проходит record этим набором и
её срок не меньше своей записи (SET_GUARD; срок своей записи — своей domain/holder, прошедшей record по набору следования начала
прохода; считается один раз за проход: взятый в проходе набор её не перепроверяет и границу не снимает, иначе второй кандидат с большим rev уводит срок назад, а исход зависит от порядка CLUSTERS (Quint M12 N2; C09-SET-GUARD-OWN-02); своей проверенной записи в начале прохода нет — сравнивать не с чем; C09-SET-GUARD-OWN-01,
```

## Эксплуатационные обязанности

Разрушающая уборка MUST соблюдать квалификацию часов и монотонные сроки [журнала событий](event-journal.md), Q6 ADR-0130 Addendum (10). Неопределённый скачок настенных часов откладывает удаление; обязательное состояние безопасности и повторов сохраняется при конечных бюджетах ресурсов и допуска.

## Векторы

Пакет [`keys`](../vectors/keys/README.md) (разбор ревью стадии A 8–10, № 13): 29 строк — 21 вход команды `keys` приёмки
M11/2 (сц. 01–03) без изменения байтов, две строки поля `thefts`, четыре строки поля `keep_until` и две строки поля `stolen_issuing`; сценарии и входы сняты переносом урока 8 — таблица единственный источник этих
случаев. Объединение и снятие `domain/revoked` у члена (`merge`, `repeat`, `prune`) — `revoked.tsv` того же пакета (7 строк;

приёмки M11/2) через функцию `token`.

Строка `revoked.tsv` проверяет объединение и снятие у члена: вход — объект JSON `{own, answer, now}`: `own` — собственная строка `jtis` члена, `answer` — `jtis` ответа держателя или `null` (записей ответа нет: к `own` применяются `repeat` и `prune`), `now` — настенные секунды; выход — `jtis` строки, которую пишет агент, строкой JSON.

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../vectors/jcs/README.md)
общего договора JCS (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).
