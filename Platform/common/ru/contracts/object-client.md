# Договор клиента хранилища объектов: адрес, операции, ответ двери ресурса, исходы

Общий договор модуля «Платформа» (ADR-0083 доп. (5), доп. (13): объекты пишут и читают все процессы платформы — договор,

[P/05](../../../05-resource/ru/spec/05-resource.norms.md) (N1.1 «Объект», N2). Участники: воркер (пульсы, метки соперника — P/03.2,
P/03.4), контроллер (снимок, отчёт прохода — P/04), консоль (тела — P/06.1), ресурс (свои объекты и дверь объектов),
процессы домена (`domain/*`), установщик — значение адреса (P/02.4 N1.2; [договор файла окружения](env-file.md)
«Переменные окружения»). Образец — [договор клиента хранилища](store-client.md).

Перенесено из P/05 N1.1 (`api`, `ops`, `cluster`, `written`, ключ и префикс, листинг и надгробия) и N2 (ответы двери
объектов, `scope`, отказы) без изменения поведения; сторона двери (разбор запроса, допуск, раскладка на диске, пределы) — в
P/05, P/05 — ссылкой сюда.

Нормативные слова — по [канону курса](../NORMATIVE-TERMS.md).

## Форма

Провод двери объектов ресурса — `Platform/05-resource/spec/05-resource.api.openapi.yaml`
([OpenAPI](../../../05-resource/spec/05-resource.api.openapi.yaml); входит в чтение `common` по ADR-0083 доп. (33) п. 1):
`GET /v1/objects` (`ObjectListing`), `GET /v1/objects/{key}` (байты, заголовки `X-Written`, `X-Server`, `X-Missing`),
отказы `ResourceError`, `ResourceDenied`. Надгробия `.gone/<object-key>` — [договор надгробий](tombstone.md). Строка двери
`platform/doors/<host>` (адрес двери чтения при голом `cluster://`, раздел «Адрес» `door`) — форма
`Platform/05-resource/data/doors.schema.json`, исходы `Platform/05-resource/data/doors.outcomes.tsv`
([форма](../../../05-resource/data/doors.schema.json), [исходы](../../../05-resource/data/doors.outcomes.tsv); P/05 N1.4 `door_row`).

## Адрес

```yaml
address:   OBJECTS / PLATFORM_OBJECTS процесса (договор файла окружения «Переменные окружения»; пишет установщик в w2c.env,
           P/02.4 N1.2): file://<абсолютный путь> — каталог объектов коробки; cluster://[<имя>][?resource=<url>] — объекты
           кластера через дверь объектов ресурса своего сервера (P/05 N1.4 «Объекты кластера — через ресурс своего сервера»);
           корень по умолчанию — <PLATFORM_DIR>/objects (P/02.4 N1.2)
parse:     (C10-OBJECT-ADDRESS-32, ответ «Архитектора» 2026-10-25) голый file:// — <PLATFORM_DIR>/objects; file://<не абсолютный путь> — отказ старта, код 2;
           cluster:// — часть до «?» пусто или имя кластера, не толкуется; без resource=<url> (голый cluster://, в том числе
           умолчание при configstore — договор файла окружения) — допустим: дверь чтения — ресурс своего сервера по строке
           двери (door ниже; P03-OBJECTS-DEFAULT-1FD, решение «Архитектора» 2026-10-26);
           resource — ровно один, непустой после percent-декодирования; пустой или повторённый — отказ старта, код 2;
           значение после декодирования — транспорту как есть (OBJECT135-URL-01, решение «Архитектора» 2026-10-25); явный
           resource перекрывает строку двери — её не читают;
           иная схема — отказ старта, код 2
door:      (P03-OBJECTS-DEFAULT-1FD, решение «Архитектора» 2026-10-26) при cluster:// без resource адрес двери чтения — поле url строки двери platform/doors/<SERVER_NAME>
           (P/05 N1.4 door_row; форма и исходы — раздел «Форма»); строка читается при каждом обращении к объектам кластера,
           адрес на старт не запоминается; строки нет, строка не читается (исходы формы), хранилище не ответило — чтение
           объектов кластера «не известно», не «нет», не отказ старта и не отказ записи в свой каталог
cluster:   при cluster:// запись — в свой каталог <PLATFORM_DIR>/objects (объект на сервере писателя, P/05 N1.1 cluster),
           чтение объектов кластера — через дверь ресурса resource (раздел «Чтение объектов кластера»)
tls:       дверь ресурса по https:// — клиент своего кластера договора сертификата роли own_client, роль resource: host —
           SERVER_NAME, если хост адреса — литерал петли; IP-литерал вне петли у https:// — ip_address; http:// вне петли —
           ошибка настройки, видимая отказом соединения (ADR-0075 доп. 2026-10-26 (4) п. 6, (5) п. 1, (6) п. 2)
```

## Операции

```yaml
api:       put(key, bytes) | get(key) → bytes | null | list(prefix) → [key] (отсортировано, без служебных имён с `~` —
           ADR-0083 доп. (16)) | delete(key) | put_new(key, bytes) → conflict, если есть (создание-однажды) | get_at/put_at
           (запись по прочитанному индексу)
rule:      целиком или никак; последний писатель побеждает; по ключу не ищут; размер — предел хранилища (0 = без)
ops:       put_new — «записать, если нет» (conflict, когда есть); get_at — чтение с индексом объекта; put_at — запись по
           прочитанному индексу (иной индекс → conflict, как cas строки); put_durable — запись тела целиком с барьером
           долговечности до публикации (строка ссылается на тело только после ответа — P/06.1 N1.5 write); delete_at —
           удаление по прочитанному индексу (иной индекс → conflict, объект не тронут); append — дописать строку события в
           открытый бакет (только его писатель, договор журнала событий); иных атомарностей нет
writer:    один каталог — один писатель; запись — в каталог объектов своего сервера (P/05 N1.1 cluster: файл на сервере
           писателя); ошибка ФС после допуска — не успех и не «файла нет»; фаза публикации определяет отказ или неизвестную долговечность (Q1 ниже)
key:       непустой относительный путь: непустые сегменты, без точных `.`/`..`, обратной косой черты и управляющих знаков;
           prefix — начало такого ключа, также пустота или конец `/`; это не полный ключ
```

## Чтение объектов кластера

```yaml
scope:     у GET /v1/objects и /v1/objects/{key}: local (умолчание) — только каталог объектов сервера ресурса; cluster —
           объекты кластера: свежая копия по written побеждает, при равном written — сервер с лексикографически большим
           именем; иное значение — 400
written:   отметка ресурса-хранителя при записи ключа (X-Written, written листинга), не поле времени тела; строго растёт
           по ключу; новая запись тех же байтов — новая версия, тот же (server, written) — та же версия (договор
           наблюдения «changed»)
missing:   сервер, который не ответил, — missing (X-Missing), а не отсутствие объекта; 404 — «нет среди ответивших»: при
           неполном опросе X-Missing обязателен, полнота из самого кода 404 не выводится
listing:   закрытая форма ObjectListing; только ключи семей двери под prefix — фильтр, а не отказ; удалённые объекты —
           надгробия .gone/<ключ>: обычный листинг их не показывает, prefix=.gone/ — листинг надгробий только для чтения
```

При `scope=cluster` ресурс опрашивает свой локальный сервер и все чужие серверы подтверждённого перечня дверей без фильтра живости. Известный неответивший сервер или нечитаемая дверь — missing: доступный в остальном листинг возвращает 200 с missing, чтение ключа при неполноте несёт X-Missing. Неподтверждённый состав серверов или сбой локального чтения/листинга даёт прежний 503, не полный результат. Конечный срок ожидания зависимости реализация объявляет по общим эксплуатационным обязанностям.

## Исходы и что делает клиент

| Исход | Код | Что делает клиент |
|---|---|---|
| ключ не по грамматике (не UTF-8, Cc, Zl, Zp, `.`/`..`, пустой сегмент); `prefix` не UTF-8; `scope` иной | 400 `ResourceError` | ничего: ошибка кода |
| ключ или префикс вне семей двери; роль не допущена | 403 `ResourceError` / `ResourceDenied` | ничего: ошибка кода или развёртывания |
| объекта нет среди ответивших | 404 `ResourceError` | без `X-Missing` — объекта нет; с `X-Missing` — не известно, не «нет» |
| объект превышает Content-Length.maximum [HTTP-формы P/05](../../../05-resource/spec/05-resource.api.openapi.yaml) | 413 `ResourceError` | ничего: предел двери |
| полоса занята; дверь недоступна | 503 `ResourceError`, `Retry-After: 1` | повторить на следующем шаге |
| условие `put_at`, `put_new` или `delete_at` не совпало (не произвольная ошибка файловой системы) | conflict | перечитать и решить заново |
| дверь ресурса не ответила (обрыв, неответ, отказ в соединении) | — | чтение — не известно, не «нет» (как договор клиента хранилища `no_reply`; C10-OBJECT-ADDRESS-32, ответ «Архитектора» 2026-10-25) |
| голый `cluster://`: строки двери `platform/doors/<SERVER_NAME>` нет, она не читается, хранилище не ответило | — | чтение — не известно, не «нет»; при следующем обращении строка читается заново (P03-OBJECTS-DEFAULT-1FD, решение «Архитектора» 2026-10-26) |

## Эксплуатационные обязанности

ADR-0130 Addendum (10), Q1: доказанный отказ до публикации сохраняет прежний объект. После `rename` сбой барьера долговечности или потеря ответа оставляет долговечность неизвестной: это существующий исход `unknown`, а не доказательство отсутствия или успешной записи. Откат опубликованных байтов или памяти не обещается. Для `put_new` сохраняются точные ключ, задуманные байты и условие создания-однажды. Один `conflict` успеха не доказывает: сравниваются существующий индекс или версия операции (включая `(server, written)` где применимо), ключ и байты; одинаковые байты сами не доказывают принадлежности объекта этой попытке. Для разрешения квалифицированное чтение должно установить точную идентичность задуманного объекта и требуемую долговечность; отсутствующий, иной, нечитаемый или неквалифицированный результат оставляет исход неизвестным. Новый HTTP Fault локальной операции не назначается. Действующие формы двери `ResourceError` и `ResourceDenied` сохраняются.
