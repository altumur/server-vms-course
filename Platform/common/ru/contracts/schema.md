платформы — договор, а не копии в главах; аудит раскладки A-02, решение «Архитектора» 2026-10-25). Владелец — глава

контроллер ([P/04](../../../04-controller/ru/spec/04-controller.norms.md) N3 «старт контроллера — проверка схемы»), воркер
([P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md) N3 «проверка схемы воркером»), ресурс
([P/05](../../../05-resource/ru/spec/05-resource.norms.md) N3 «старт ресурса — проверка схемы»), процессы домена — `domain`,
агент, консоль домена ([P/02.4 N1.12](../../../02-installer/ru/spec/02.4-installer.norms.md); консоль домена —
[P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md) N1.1); шаг 0 старта процесса — [P/02.3](../../../02-installer/ru/spec/02.3-installer.norms.md)

контроллера, воркера, ресурса или консоли — проверка схемы» (P/06.6, P/03.2, P/04, P/05 N3; прежде M10/10 N3) без

## Форма

Строка `platform/schema` — семья `schema`: форма `Platform/06-console/data/schema.schema.json`, исходы
`Platform/06-console/data/schema.outcomes.tsv` ([форма](../../../06-console/data/schema.schema.json),
[исходы](../../../06-console/data/schema.outcomes.tsv)). Поле `schema` пульса — формы пульсов
`Platform/03-worker/data/heartbeats.schema.json` (исходы — `Platform/03-worker/data/heartbeats.outcomes.tsv`) и `Platform/05-resource/data/resource-heartbeat.schema.json` (исходы — `Platform/05-resource/data/resource-heartbeat.outcomes.tsv`) (и их
`.outcomes.tsv`).

## Схема

```yaml
platform/schema:  {version: <целое ≥ 1>, at: <момент>, revision?: <целое ≥ 1>}     # revision — P/06.6 N2.1 «Версия строки», читает только консоль; писатель — консоль (admin); нет строки = схема сборки (свежая установка)
version:  точное целое ≥ 1 без верхней границы и без машинного переполнения (как номер слота, договор имени слота): больше
          SCHEMA сборки — «схема новее» (too new: отказ старта, код 2, в журнале точное N); не по форме — только не целое, < 1
          (C06-SCHEMA-WIDE-32-01, решение «Архитектора» 2026-10-25)
SCHEMA:   число, которое понимает сборка; поле добавить — без нового номера; смысл поля сменить — новый номер; для нынешней
          спецификации SCHEMA = 1 и schema пульса = 1; повышение SCHEMA — только решением с переходом (догадка стадии C W03-E02, решение «Архитектора» 2026-10-23)
BUILD:    слово сборки для человека (env BUILD, умолчание dev); машина читает SCHEMA
heartbeat: каждый пульс воркера и ресурса несёт schema и build (P/03.4 N1.1, P/05 N1.4); schema — целое JSON без дробной
          части и экспоненты (форма int [договора проверки строки](row-check.md) «Подготовка полей»: «Значение `int` на входе двери»), ≥ 1; `1.0`, `1e0`, `-1`, строка, null — схема процесса неизвестна (null
          в `processes`, P/06.6 N2.3) (сверка python и go M10/6–11, T3); build — строка; не строка — `null` (не известно; сверка python и go M10/6–11, T27; V7 п. 3, решение «Архитектора» 2026-10-28, P1; строка 14 списка)
check:    при старте контроллера, воркера, ресурса и консоли: version > SCHEMA → не стартовать; строка не число → не стартовать;
          так же стартуют процессы домена — domain, агент, консоль домена (P/02.4 N1.12); воркер проверяет и при продлении
          слота (P/03.2 N3 «проверка схемы воркером»)
```

## Проверка при старте

```
первым шагом старта, до чтения манифеста (P/02.3), у всех четырёх процессов:
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
  ошибка чтения → ждать доступности, не начиная работы, с паузой, до START_WAIT = 60 с от старта процесса
    (P/02.3 N3 «Старт процесса» шаг 0); всё ещё не подтверждено — не стартовать с кодом 1, супервизор перезапускает процесс;
  не стартовать (не число, версия выше SCHEMA) — выход с кодом 2 и строкой лога, без перезапуска
воркер: после продления слота — P/03.2 N3 «проверка схемы воркером»
```

**Граница.** Демон строкового хранилища не толкует раскладку подсистемы и этой проверкой не блокируется: иначе нельзя было бы открыть хранилище для чтения/исправления схемы; его собственный формат — P/01.1 и P/01.3 N1.3 (демон `configstore`: `member.json`, `backup`/`restore`). Проверка при продлении есть у воркера; она не доказывает безопасность всех остальных процессов. При нынешнем SCHEMA = 1 эта запись не меняет понимаемую раскладку; переход требует отдельного решения. Сбой чтения — ждать доступности без работы; достоверно испорченная/слишком новая схема — отказ старта с кодом 2.

## Векторы

Пакет [`schema`](../vectors/schema/README.md): функция `check` — строка `platform/schema` и SCHEMA сборки → старт с версией,
«схема новее» с точным N или «не по форме» (C06-SCHEMA-WIDE-32-01, решение «Архитектора» 2026-10-25). Ошибка чтения и продление слота воркером — сценариями приёмки
участников (P/06.6; ошибка чтения у ресурса — сц. 18 приёмки P/05, отказ старта — сц. 17) и чтением.
