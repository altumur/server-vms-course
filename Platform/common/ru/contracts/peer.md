## Клиент и первый контакт

Из M11/8 N1.6:

```yaml
client:       клиент двери другого кластера по https:// знает член назначения и принимает сервер, когда peer = ok:
              консоль члена — имя из CLUSTERS; консоль кластера держателя и подписант — держатель; ретранслятор —
              RELAY_MEMBER; агент у двери DOMAIN_URL — держатель, по порядку: carry.holder последнего доверенного ответа
              этой дороги (запись deposed); до первого ответа после старта — своя читаемая domain/holder; нет — DOMAIN_CA (first ниже, первый контакт); ничего —
              foreign_ca; новых слов и переменных нет (fail-closed, P1; C09-PEER-DEST-MEMBER-01); отпечатки держателя — ca записи срока domain/holder (договор записи срока; ADR-0113 доп. (3) п. 2);
              прочего члена — Entry.ca его строки domain/member-list/<раздел> этого кластера; строки нет, её fetched_at старше MEMBER_ROW_AGE (3600 с) или peer отказал по ней foreign_ca — клиент кладёт просьбу domain/member-want/<раздел> (P/09.1 N1.4 member_want), этот запрос идёт по тому, что есть, без строки — foreign_ca (форма копии — Platform/09-agent/data/member-list.schema.json,
              исходы — `Platform/09-agent/data/member-list.outcomes.tsv`; C04-DEP-OBS-HEARTBEAT-01)
first:        DOMAIN_CA=<отпечаток> рядом с DOMAIN_URL, RELAY_CA=<отпечаток> рядом с RELAY_URL — действует, только пока
              запись члена назначения не называет ca; ни записи, ни отпечатка — отказ foreign_ca: доверия при первом
              контакте нет; RELAY_URL на https:// без RELAY_MEMBER — агент не стартует, код выхода 2 — отказ настройки
              (P/02.4 N1.1 common; решение «Архитектора» по планам переноса 8–10, ADR-0083 доп. (14) п. 10; план 9 V8)
revoke:       отзыв сертификата чужого кластера звонящему не виден; средство — смена центра (rotation)
```

## Функция `peer`

Из M11/8 N3 «peer(chain, fingerprints, role, host, now) — клиент о сервере другого кластера, по порядку»:

```
1. host — IP-адрес (v4 или v6, в том числе v6 с зоной `%<зона>`; добавлено сверкой M11, D15) → ip_address
   # запись вида `127.1` — не IP-адрес, а имя (совпало у реализаций, записано сверкой M11)
2. chain — не непустой список читаемых PEM-сертификатов: элемент — ровно один блок CERTIFICATE, base64 строгий,
   DER разбирается целиком; иначе — до поиска якоря                          → bad_chain
3. fingerprints пуст, или в chain[1:] нет сертификата центра (CA:true) с отпечатком из fingerprints → foreign_ca
   якорь — первый такой сертификат по порядку chain
4. нет пути chain[0] → … → якорь по соседним элементам chain: chain[i] подписан ключом chain[i+1] алгоритмом закрытого списка
   договор сертификата роли `sig` (добавлено сверкой M11, D14), следующий — CA:true; pathLen и keyUsage не читаются, лист с
   CA:true — лист (совпало у реализаций, записано сверкой M11)
   порядок chain — порядок сервера (лист, затем центр; договор сертификата роли server); элементы не переставляются и
   не перебираются (решение «Архитектора», разбор ревью стадии B 8–10, № 10, ADR-0083 доп. (15))
                                                                             → bad_chain
5. now вне [notBefore, notAfter] какого-либо сертификата пути (листа и якоря включительно) → expired
6. у листа SAN URI вида urn:w2c:role:<роль> с непустой ролью не ровно один (`urn:w2c:role:` — роли нет; схема и
   префикс — байт в байт; добавлено сверкой M11, D15)                          → no_role
7. роль листа ≠ role (байт в байт)                                           → wrong_role
8. host не среди SAN DNS листа — сравнение байт в байт: регистр значим, wildcard не раскрывается, точка в конце не
   снимается (совпало у реализаций, записано сверкой M11)                      → wrong_name
9.                                                                           → ok
```

Клиент двери своего кластера зовёт ту же функцию со своими центрами и `host` по порогу петли, затем проверяет отзыв —
[договор сертификата роли](role-certificate.md) «Клиент двери своего кластера» (`own_client`; ADR-0075 доп. 2026-10-26 (5) п. 1); функция
и её векторы от этого не меняются.

Выше якоря цепочка не проверяется: якорь назначен отпечатком записи (стоит ли он корнем или промежуточным — всё равно);
отзыв чужого кластера не проверяется (строка `revoke` выше; прежде M11/8 N1.6). Клиент с отказом `peer` закрывает соединение; пересылка отвечает
502 `did not answer` со словом отказа в `detail`.

## Слова отказа

Из M11/8 N4: слова `peer`: `ip_address`, `bad_chain`, `foreign_ca`, `expired`, `no_role`, `wrong_role`, `wrong_name`.
