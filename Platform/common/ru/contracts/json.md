# Разбор и кодирование JSON

Русский текст — производный от `contracts/json.md`, руками не правится; перевод английского источника для человека, вне выгрузки.

Общий модуль `json` даёт разбор и кодирование, включая [JCS](jcs.md). Вызывающий выбирает правила своего существующего договора. Разбор сохраняет сведения, нужные этим правилам: имена полей до потери повторов, лексемы чисел до преобразования и экранирование строк до замены неверного символа. Модуль не выбирает платформенный отказ и не вводит общий предел размера.

## Правила вызывающего

[Правила тела JSON хранилища](../../../01-store/ru/spec/01.1-store.norms.md#n21-разбор-запроса) определяют повторы имён, BOM, UTF-8, числа вне JSON и глубину вложенности. Поля сохраняют разное толкование: одиночный суррогат в ключе — `badkey`, в items — `badrequest`, а лишние поля не читаются. Длина или числовой диапазон проигнорированного лишнего значения не становятся новым отказом. Глубина считается и в лишних полях. [Уставки](../../../01-store/forms/runtime-constants.tsv) и [порядок проверок](../../../01-store/forms/write-checks.tsv) принадлежат вызывающему.

Остальные вызывающие применяют собственные схемы, формы полей и исходы отказов. Ограничения I-JSON подписанного документа и каноническая форма JCS остаются по договору документа; толкование лишних полей хранилищем не ослабляет подписанный документ. Разбор записи вне формы семьи использует существующий исход нечитаемости этой семьи. Кодирование следует форме писателя и применяет JCS только где этого требует договор.

## Приёмочные входы

Пакет `common/jcs` проверяет канонические байты и их хеш по существующему [договору JCS](jcs.md). Существующие случаи тела JSON из P/01.1 N5 проверяют выбор хранилища при разборе через его дверь (judge-only: случаи JSON из `Platform/01-store/acceptance/1/scenarios.tsv`). Это проверки вызывающего, а не новое общее соответствие исходов. Тесты модуля проверяют разборщик, которым пользуются эти вызывающие; одних векторов JCS для строгого разбора недостаточно.
