# Кодирование строк TSV только в источнике

<!-- производный от `contracts/source-cells.md`, руками не правится -->

ADR-0121 доп. (6), решение Архитектора, 2026-11-06. Форма источника общая для читателей генераторов и раннера. Новых native-команд, runtime-алиасов и значений протокола нет.

## Объявление

У таблицы может быть ровно одна строка объявления, перед шапкой и первой строкой данных. Точная грамматика:

```text
declaration = "# cell-json: " name *( "," name )
name = ( ALPHA / "_" ) *( ALPHA / DIGIT / "_" )
ALPHA = %x41-5A / %x61-7A
DIGIT = %x30-39
```

Объявление занимает всю физическую строку. После двоеточия ровно один пробел ASCII, вокруг запятых пробелов нет, отступов и пробелов в конце нет. Имена уникальны и обозначают существующие колонки. Повтор имени в шапке таблицы недопустим. Первая непустая строка, не комментарий, — шапка обычной таблицы. Таблица без шапки получает имена из прежнего поля `header` в [wire.tsv](../../vectors/wire.tsv): начальный `-` означает отсутствие шапки и колонкой не является. Первая строка данных сохраняется. Новая шапка не вставляется.

У приёмочного `scenarios.tsv` прежняя форма источника задаёт `scenario`, `step`, `request`, `expect` в таком порядке. Прежняя шапка-комментарий не является данными; первый сценарный шаг сохраняется. Та же форма допускает обычную шапку. Эти прежние имена колонок передаются общему читателю до декодирования источника; маркер не выводит форму из внутреннего payload.

## Ячейки и декодирование

Каждая ячейка данных каждой объявленной колонки — строгая JSON-строка ASCII, включая пустое значение как `""`. Символ вне ASCII записывается Unicode-escape JSON; символ вне основной многоязычной плоскости — правильной суррогатной парой. Неверный JSON, значение JSON другого типа, суррогат без пары, повтор объявления или колонки, неизвестное имя или неверная ширина строки — ошибка формы. Нельзя кодировать лишь некоторые ячейки объявленной колонки. Прочие колонки прежние.

Общий читатель декодирует каждую объявленную ячейку источника ровно один раз, до толкования wire, CEL или native, и кодирует полученную строку как UTF-8. Рекурсивного декодирования нет. Например, источник `"\\u0436"` даёт шесть буквальных символов ASCII `\u0436`; источник `"\u0436"` даёт один Unicode scalar. Последующий разбор JSON по прежней wire-форме колонки сохраняется и отделён от этого шага источника. Комментарии — не данные, маркер реализации не посылается. Декодирование не меняет просьбы, идентификаторы случаев и физические номера строк источника.

Физические строки таблицы разделяет только LF, ячейки — только TAB. U+2028 и U+000B внутри необъявленной ячейки остаются частью той же ячейки и физической строки. Чтение файла не нормализует универсальные переводы строк: необъявленный U+000D тоже сохраняется. Другой Unicode-разделитель строк границей строки источника не является.

## Сохранность и проверки

[cell-json-sha256.tsv](../../data/cell-json-sha256.tsv) покрывает каждую объявленную ячейку данных ровно один раз по пути таблицы, физической строке и колонке. `before_sha256` — хеш прежних байтов UTF-8 ячейки на указанной базе; `decoded_sha256` — хеш байтов UTF-8 после единственного декодирования источника. Хеши равны друг другу и хешу декодированной ячейки. Пропуск, повтор и лишняя строка доказательства — ошибка формы. Поэтому сырой текст JSON, JCS, AAD, вход подписи, конверты и ожидаемые выходы сохраняют прежние байты.

[Проверочные векторы](../../vectors/source-cells/cases.json) задают правильные и неверные объявления и ячейки, позиционный вход, сохранение первой строки, суррогатные пары и однократное декодирование. Они проверяют форму источника, новой runtime-поверхности не вводят. `en_mirror` и `check_spec` судят форму и полное доказательство байтов; читатели генераторов и раннера используют то же правило источника.

[unmarked-sha256.tsv](../../vectors/source-cells/unmarked-sha256.tsv) задаёт идентичность текста источника и равные хеши UTF-8 до и после декодирования для регрессий U+2028 и U+000B. В каждой одна строка данных на физической строке 3; необъявленная ячейка прежняя.
