## Запись срока `domain/holder`

Из M11/10 N1.1 (форма семьи — `Platform/08-domain/data/holder.schema.json` (исходы — `Platform/08-domain/data/holder.outcomes.tsv`); C04-DEP-OBS-HEARTBEAT-01 — файлы данных, названные договором, в чтении `common`, ADR-0083 доп. (32) п. 1):

```yaml
domain/holder:   {doc: <текст JCS документа>}       # у держателя — пишет процесс domain (claim); у члена — агент (N3 «следовать»)
  doc:           {domain, term, holder, url, ca?, key?, at, restored_from?, issuer, kid, sig}   # закрытый набор
    domain:      имя домена (P/08.2 N1.1)
    term:        целое ≥ 1
    holder:      имя члена-держателя
    url:         адрес двери процесса domain держателя — SIGNER_URL окружения этого процесса, без него
                 http://localhost:8445 (стенд одной машины) — туда агенты носят отчёты (урок 3); у
                 держателя из нескольких узлов — адрес, который доходит до любого узла кластера, а не одного сервера
                 (очередь процесса domain — P/08.10 N1.7; добавлено M11/12)
    ca?:         [<отпечаток>…], 1–2 — центр держателя (P/08.3 N1.6; ADR-0075 уточнение 2)
    key?:        hex ключа члена-держателя; у срока 1 до первого отчёта его агента поля нет (ADR-0113 доп. (3) п. 2)
    at:          стенные секунды подписи; смена центра или появление ключа — переиздание того же срока с большим at: at строго растёт, часы назад — прежнее + 0.001
    restored_from?: {term, rev} — резервная копия, из которой восстановлен этот срок (N1.5); срок 1 — без поля
    issuer:      hex открытого ключа выпускающего (P/08.2 N1.3 issuing_key_secret)
    kid:         serial выпускающего — первые 16 знаков hex issuer
    sig:         base64url без «=» подписи Ed25519 выпускающего над UTF-8(JCS(doc без kid и sig))
```

Документ резервной копии (N1.5), грант (N1.7) и строка членов `domain/member-rows/<part>` (P/08.3 N1.1) подписываются так же: `issuer`, `kid`, `sig` — по строкам выше; вид строки членов сверяет ещё `part` и раздел каждого имени (функция `record` шаг 1; раздел «Строка членов»).

## Точка смены `switch`

Перенесено из [P/08.8](../../../08-domain/ru/spec/08.8-domain.norms.md) N1.6 `switch` без изменения поведения (аудит раскладки, решение «Архитектора» 2026-10-25, B-04):
условие читают процесс `domain` держателя и агент его кластера (договор набора ключей: строки `domain/keys` и
`domain/revoked` агент кластера держателя не пишет, пока кластер держит срок).

```yaml
switch:      у кластера держателя строки domain/keys, domain/revoked, domain/holder, своя domain/break-glass/<кластер> и
             указатель domain/shared пишет процесс domain, а агент этого кластера их не пишет — пока запись domain/holder
             своего хранилища проходит record по набору следования агента (договор набора ключей «Набор следования»; добавлено моделью Quint M11,
             G1) и называет держателем этот кластер (P/09.1 N1.4 holder_cluster). Условие агента —
             только по записи: «domain/signer не forgotten» — условие процесса domain, domain/signer агенту не открыт; forget
             наступает только после записи чужого большего срока (P/08.8 N1.6 yields), потому запись «держатель — этот кластер» и забытые
             ключи вместе не бывают, кроме кражи: вор подписывает больший срок с именем действующего держателя, процесс уступает по ней, вреда сверх кражи нет (Quint M12 N11). Точка смены одна — запись domain/holder большего срока, прошедшая record (смена после кражи бывает и меньшего, P/08.8 N1.6 yields): при плановой
             передаче её пишет процесс прежнего держателя (P/08.8 N1.7 шаг 6), при переносе — агент «следованием» (его
             единственная запись в эти строки до точки). С неё процесс уступает и этих строк больше не пишет, агент пишет
             их как у любого члена. Процесс видит точку при первой своей проверке после неё (проверка — на каждом проходе и
             каждом запросе): окно — до следующей проверки, не дольше прохода; его правки в окне попадают в stranded
             (добавлено моделью Quint M11, SW). У цели — зеркально: claim нового срока (P/08.8 N1.1) — точка, с неё агент цели их не пишет
             (запись, называющая цель, пришла раньше claim — агент уже не пишет эти строки, их пишет процесс с claim)
```

## Функция `record`

Из M11/10 N3 «`record(keys, row, kinds)` — запись срока или документ с подписью N1.1, по порядку»:

`kinds` — закрытый набор видов документа, который принимает вызывающий. Этот урок вызывает record с тремя видами шага 1; агент, держатель и ретранслятор — ещё с видом «строка членов» (раздел «Строка членов»);
глава 8.9 — с одним видом «общий документ» (P/08.9 N1.2 document; N3 «взять документ» шаг 4 — P/09.1). Шаги 2–5 общие
(добавлено описью семей).

Предел вложенности JSON — 64, одно число на платформу (глубина JSON тела двери консоли, P/06.1 N1.4): строка `row` и
текст `doc` разбираются каждый со своим пределом; уровень — объект или массив (скаляр — 0, пустой объект или массив — 1,
как `depth` связей, [слои V7](../LAYERS.md) § 5); глубже 64 — `not_a_record` (шаг 1), у доверенного `keys` — вход не по форме, выход 2 (догадка стадии C REC-G02, решение «Архитектора» 2026-10-23).

```
1. row не {doc: <текст>}, doc не JSON-объект закрытого набора одного из видов `виды`; виды этого урока — запись срока
   N1.1, документ резервной копии N1.5, грант N1.7 (вид — по набору ключей; иной документ, в том числе общий документ
   урока 11, — не запись) с типами: term — целое ≥ 1, at — число, holder — имя члена, url — непустая строка, ca — 1–2
   отпечатка без повторов, restored_from — {term, rev}, issuer — hex 32 байт; у документа резервной копии rev —
   целое ≥ 1, members — список имён членов без повторов, state — {<ключ строки>: {<элемент>: <текст>}}, objects —
   объект, raw — {<ключ>: строка base64 RFC 4648 §4 с дополнением, "" — 0 байт}, ключ raw не ключ objects (C08-BACKUP-JSON-99, решение «Архитектора» 2026-10-26), backup_key_rev — целое ≥ 1,
   holder_member_key — hex 32 байт, parts — {<раздел>: {sha256, rev, key_rev}}, counts — {servers, cameras} (P/08.8 N1.5a); у гранта grant — "handover", to и from —
   имена членов, rev — целое ≥ 1 (виды и типы — добавлено сверкой M11, H9, H11, H12); у строки членов part — четыре цифры 0000…4095, rev — целое ≥ 1, members — {<имя члена>: объект}, раздел каждого имени (P/08.3 N1.1) равен part, gathered — {term, rev}, целые ≥ 1, или null, new — список имён из members; у записи срока key — hex 32 байт; у записи срока с term 1 — поле
   restored_from; domain, kid и sig шаг 1 не проверяет по содержимому (любой JSON-тип domain — шаг 2; kid — любая
   строка, sig — любая строка: шаги 3–5) — одно правило для всех видов, в том числе общего документа (догадка стадии C REC-G01, решение «Архитектора» 2026-10-23)
                                                                                 → not_a_record
2. doc.domain ≠ keys.domain, в том числе domain иного JSON-типа (у документа с domain; документ резервной копии его не несёт —
   к домену его привязывает выпускающий, шаги 3–5)                               → another_domain
3. doc.kid ∈ keys.revoked_issuing                                                → revoked_issuer
4. doc.kid ∉ keys.issuing                                                        → unknown_issuer
5. doc.kid ≠ первые 16 hex doc.issuer, или подпись не сходится                   → bad_signature
6.                                                                               → ok {term, holder}
   (у гранта holder — его from: держатель, выдавший грант; у общего документа урока 11 holder нет — ok {term})
```

Доверенный `keys` функция проверяет только формой (поля и типы набора договора набора ключей), без содержимого `kid`, `sig`
и подписи корня — набор уже принят функцией `keys`; не по форме — выход 2 команды `record`, не отказ документа (P/08.8 N5
`exit`; догадка стадии C REC-G01, решение «Архитектора» 2026-10-23).

## Строка членов

Читатель строки — член (P/09.1 N1.4 `member_list_take`), ретранслятор пересылает её как есть, держатель проверяет только свои строки из копии (P/08.8). Ретранслятор строку подменить не может: подпись выпускающего, `part` и `domain` внутри подписанного.

```
take(keys, row, раздел, have):
1. record(keys, row, {строка членов}) не ok                                → отказ тем же словом: прежняя копия остаётся
   (revoked_issuer — строка ждёт переподписи новым сроком, P/08.3 N1.1)
2. doc.part ≠ раздел                                                        → another_part
3. have нет, или (doc.term, doc.rev) больше have лексикографически          → взять
4. равна have                                                                → same: ничего не писать
5. record(keys, have, {строка членов}) — revoked_issuer: своя копия границей не служит, срок после кражи бывает меньше (C08-STOLEN-TERM-BACK-01) → взять
6.                                                                           → older: прежняя копия остаётся
```

`have` — копия этого раздела или её нет; в шагах 3, 4 — её `(term, rev)`. Вход команды `take` — `{keys, row, part, have}`, `have` — строка `{doc}` или `null`; вывод `{result: take | same | older}` или `{result: refused, reason}`; пакет — [`record/take.tsv`](../../vectors/record/take.tsv), граница свежести.

## Слова отказа

Из M11/10 N4: слова `record`: `not_a_record`, `another_domain`, `revoked_issuer`, `unknown_issuer`, `bad_signature`; `take` — ещё `another_part`, `older`, `same`. Что
делает вызывающий с отказом (не следовать, журнал `domain.follow.refused`, `domain.shared.refused`, уступить) — нормы
вызывающего (P/08.8 N1.6; P/09.1 N3 «следовать», «взять документ»).

## Векторы

Пакет [`record`](../vectors/record/README.md) включает `shared.tsv` с 8 строками и `cases.tsv` с 47 строками. Он проверяет объявленные виды документов, доверенный вход, raw-поля резервной копии, границы Time и вложенности. Подробные входы именованных случаев и привязки ответов остаются в пакете только для судьи. Форма функции и смысл кодов выхода ниже — прежняя копия [P/08.8](../../../08-domain/ru/spec/08.8-domain.norms.md) N5 `record`, `exit` (аудит раскладки, решение «Архитектора» 2026-10-25, B-14):

```yaml
record:    вход {keys: <документ набора>, row: {doc}}; вывод {result: ok, term, holder} | {result: refused, reason}
exit:      0 — вычислено; 2 — вход не по форме; коды выхода — по принципу словаря «Стенда домена» («Коды выхода команд-векторов»: 2 — форма
           доверенного входа, 0 со словом — документ другого кластера; решение «Архитектора» по сверке M11, H14):
           keys у record — доверенный документ набора главы 8.2 N1.2 закрытой формы: поля нет (revoked_issuing,
           sig, domain), issuing не список, keys null — 2; подпись набора проверена при записи (функция keys договора набора
           ключей домена), функция её не проверяет — испорченный sig не отказ; у record нет row, лишнее поле, вход не объект — 2; row (null, строка,
           {}, doc не JSON или числом, лишнее поле row) — 0 not_a_record
```
 Участник: пакет
[`follow`](../../../09-agent/ru/vectors/follow/README.md) — пакет урока-владельца P/09 (глава 9.1), исполняет он; договор записи срока
там — потребитель: следование зовёт `record` (аудит раскладки, V-49; CM-RECORD-VECTORS-128, решение «Архитектора» 2026-10-25). Пакет `resolve` урока P/06 `record` не зовёт
(вход — значение домена `{term, rev, value}`) — в «Векторах» не числится.

Канонический JSON (RFC 8785, ADR-0072), на который опирается договор, — пакет [`jcs`](../vectors/jcs/README.md)
общего договора JCS (`canonical_json.tsv`: вход → форма RFC 8785 → sha256; ADR-0083 доп. (33) п. 2).
