# Стенд передачи второго вида

Сценарии `door.pass` второго вида: билет, обратный вызов, поток, лист роли (ADR-0094 B1, Confirmation; нормы — [договор сторожевой и передачи](../../contracts/gate-and-pass.md) «Передача второго вида», [P/06.3](../../../06-console/spec/06.3-console.norms.md) Н1.9, [P/06.5](../../../06-console/spec/06.5-console.norms.md) Н1.8, [договор сертификата роли](../../contracts/role-certificate.md) «Лист обратного вызова», [P/02.5](../../../02-installer/spec/02.5-installer.norms.md) Н1.5). Что проверяется без живого воркера, идёт в главах: сц. 46 [приёмки 6.1](../../../06-console/acceptance/1/README.md), сц. 32 [приёмки 6.5](../../../06-console/acceptance/5/README.md).

10 сценариев / 136 шагов. Воркера играет раннер: сценарию нужно держать запрос открытым, видеть, что дошло до воркера, и звать консоль обратно с билетом и листом, а тестовый воркер реализации этого не даёт и проверял бы сам себя. Манифесты — [`probe-p`](probe-p.subsystem.yaml) и дверь первого вида [`probe-f`](probe-f.subsystem.yaml) (сц. 10), комплекты сц. 08 — [`stand.json`](stand.json) в форме [TLS-стенда](../tls/README.md), с одним новым полем: `server` листа в `negative` — лист с иным именем сервера. Обратный вызов с листом идёт на отдельный слушатель консоли, подстановка `{cport}` ([ADR-0094 доп. (16)](../README.md#подставной-воркер-передачи-второго-вида)).

| № | Сценарий | Нормы |
|---|---|---|
| 01 | билет живёт с запросом: удостоверения не уходят, дверь перечня работает, запись по билету; вне перечня, запись `/session`, чужая подсистема, без билета, по TCP — 401; ответ отдан — билет мёртв; ряд и журнал `pass.called` | `ticket`, `journal`, `counter`, P/06.3 Н1.9 |
| 02 | заголовки к воркеру и клиенту; 412 `problem+json`, 204, тип вне перечня — 502; `nosniff`, `sandbox`; предел `wait` — 504 | `to_worker`, `to_client`, `types`, `timeout` |
| 03 | свежий `may` — 403; два токена, отозван один: билет первого 401, второго работает; выключенный человек на члене: билет жив, `grants: []`, поток закрыт | `ticket` шаг 5, `close` |
| 04 | консоль открыта: билет есть, обратного вызова вид сессии не даёт | `ticket` шаг 3 |
| 05 | поток: чтения и `/changes`, запись — 401, `Last-Event-ID`, ответ по мере прихода; поток закрывается с запросом и при отзыве токена | `stream`, `close`, `ticket` шаг 4 |
| 06 | таблица `service: true` по билету: человек без прав читает и пишет своё, строка в пакете; строка вне перечня — 401 всего пакета; без билета дверь закрыта; лента по билету: строка своего `user` приходит и при снятии, чужая и без поля `user` — нет | `service`, P/06.3 Н1.9 «Строки пакета», P/06.1 Н1.6, Н2 «Лента изменений» |
| 07 | общая полоса занята передачами, их обратные вызовы проходят | P/06.5 Н2, договор `order` шаг 1 |
| 08 | слушатель обратного вызова: своя роль и сервер — да; без билета, чужая роль, другой сервер — 401; без листа, чужой центр, срок, EKU — отказ рукопожатия; основной слушатель билета не принимает; серверный лист не роли адресата — передачи нет, тело не ушло | `callback_transport`, `transport`, «Лист обратного вызова» |
| 09 | выключенный человек у держателя: билет 401, поток закрыт по `domain/disabled` | `ticket` шаг 5, `close` |
| 10 | запись первого вида: воркер двери получает токен человека в `Authorization`, адресат билета его не видит, заголовка билета у двери нет; дверь вне перечня — 401 | `first_kind`, P/06.3 Н1.9 |

Чтением, с причиной: сокет чужой роли — стенд ставит одну подсистему с `door.pass.calls`, сокета другой роли нет (лист чужой роли — сц. 08); break-glass и отладочная личность — тот же шаг 3 порядка `ticket`, что сц. 04; запрос по куке стенд не ведёт. Маршрут двери подсистемы ([P/06.3](../../../06-console/spec/06.3-console.norms.md) Н1.9) — подставной воркер держателем не служит. `X-W2C-Loopback` без петли и `PASS_STREAMS_MAX` — все клиенты стенда на петле, 256 потоков TSV не откроет. `PASS_TICKET_CHECK` — только верхней границей шага 16 сц. 05. Дверь воркера с листом `console` и клиент SDK — P/03.4-15, тест реализации: подставной воркер их не проверяет.

## Исполнимость

Сц. 01–09 раннер исполняет: директивы словаря, дверь `socket`, подстановка `{cport}`, ключ `keys.pass_stand`; проба реализации прошла их сухим прогоном 124/124 на пине 36c2531, прогон не зачётный. Сц. 10 и `probe-f` реализацией не прогонялись.

## Сроки

`probe-p` объявляет `wait: {api/x: 300}`: запрос сценария держит билет живым, предел не маскирует проверки отзыва и выключения (`PASS_WAIT` 5 с снял бы билет сам). Предел 504 судит `api/slow` 2 с. Сон сц. 05 шаг 13, 7 с: поток переживает `PASS_WAIT`, у потока предела нет; `PASS_WAIT` + 2 с запаса стенда.
