# Векторы: логин и пароль в адресе (`secret_in`)

Владелец — глава [P/06.2](../../../06-console/spec/06.2-console.norms.md) консоли (Н1.1 `url_field`, `common_words`, `mask`; Н1.1а А1–А15;
Н3 «прочитать_адрес»; Н4 строка «пароль или логин в адресе»). Участники — загрузчик [P/02.1](../../../02-installer/spec/02.1-installer.norms.md)
(объявления `credentials` и `secret_in` поля `type: url`, Н1.2а) и [P/02.4](../../../02-installer/spec/02.4-installer.norms.md)
(разбор адреса). Байты пишет «Спецификация»; соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16,
ADR-0083). Перенесено из `Source/tests/testdata/secret_in.tsv` байт в байт (стадия B, перенос урока 6, решение
«Архитектора» по В8 плана урока 6); шапка файла — английская, как была: `М10/7 Н1.1а` в ней — прежний адрес главы P/06.2 Н1.1а.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` — пояснения, пустые пропускаются. Заголовка нет. Ячейка читается байт в байт
между TAB, ничего не раскрывается: `\t`, `\n` в ячейке — два знака. Пять полей:

| Поле | Значение |
|---|---|
| `field` | чьим правилом читается строка: `cam.source` или `rec.volumes.url`; поле, которого читатель не знает, — неверная строка, а не пропуск |
| `raw` | адрес как записан |
| `masked` | показ (Н1.1а А14): каждый пароль — `***` там, где стоит; логин — как написан |
| `fault` | отказ значения как значения поля (А15): пусто — учётные данные его не отказывают; иначе — поле `credentials`, которое называет отказ (`cred_secret`, `access_secret` — пароль; `cred_username`, `access_key` — только логин) |
| `note` | зачем строка |

Объявления двух полей — данные векторов, а не ссылка на каталог VMS (ADR-0001): файл
[`fields.yaml`](fields.yaml) рядом (перенесён из приёмки главы 6.2 байт в байт; догадка стадии C URLC-SOURCE-01, решение «Архитектора» 2026-10-23; ключ — имя из столбца `field`, значение — объявление
поля по форме P/02.1 Н1.2а). Правило каталога для вложенных адресов (А8) — объединение правил этих двух полей с общим
словарём Н1.1 `common_words`.

## Прогон

Сторона читает каждую строку правилом названного поля:
1. показ равен `masked`, байт в байт;
2. отказ пуст или называет поле из `fault`;
3. текст отказа не содержит значения пароля: Н4, отказ значение не повторяет. Значение пароля строки — подстрока `raw`,
   которую `masked` закрывает `***` (у нескольких — каждая); пароль короче 4 байт этим пунктом не проверяется — такие
   знаки текст отказа может нести и без утечки (чтение коммитов «cammeta-acceptance» 2026-10-20).

Пакет проверяет показ и отказ учётными данными (`fault` — поле `credentials` или пусто), в том числе отказ адреса, не
разбираемого по RFC 3986 (знак вне грамматики А2, нечисловой порт), — он называет `credentials.secret` (А15). Вне пакета —
только отказы разобранного адреса по «Схемам» [договора адреса](../../contracts/url-credentials.md) (схема не из `schemes`,
хоста нет, при `host: path` нет пути): учётные данные их не дают, `bad_url` — шаг url проверки строки; у такой строки
`fault` пуст (догадка стадии C URLC-VECTORS-02, уточнение, решение «Архитектора» 2026-10-23).

Строка лога, не являющаяся значением поля, — векторы [`../log-mask/`](../log-mask/README.md) ([договор маски журнала](../../contracts/log-mask.md)).
Кто исполняет — по пунктам прогона: показ (п. 1) — консоль (`06-console`, P/06.2 Н3 «прочитать_адрес», Н1.4) и контроллер (`04-controller`, P/04 Н1.3а — адреса снимка с той же маской); отказ (пп. 2–3) — дверь единиц консоли (`06-console`, P/06.1, P/06.2 Н4) и библиотека заказчика (`03-worker`, P/03.6 Н1.6 — шаг url проверки строки); находка пароля в адресе — процесс `domain` (`08-domain`, P/08.9 Н1.3 «Правка» шаг 4: п. 2 — пуст ли `fault`, слово отказа у него своё). Загрузчик (`02-installer`, P/02.1 Н1.2а) проверяет только объявления полей и строк не исполняет (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Нативный исход

По общему правилу «Векторы» [общего README приёмки](../../acceptance/README.md) (две колонки ожидания — объект;
C06-VECTOR-SECRETIN-WIRE-168-12, решение «Архитектора» 2026-10-27). Вход единой команды — `cells` `field`, `raw` (ячейки
как записаны), `files` `fields.yaml`. Исход — код 0 и объект JSON:

- `masked` — показ строкой (п. 1), байт в байт с колонкой `masked`;
- `fault` — поле `credentials`, которое называет отказ, или `""` — учётные данные значение не отказывают (п. 2), равно
  колонке `fault`;
- `text` — текст отказа, как его выдаёт сторона (у двери — `error` ответа 400, у библиотеки — причина в логе); только при
  непустом `fault`, иначе ключа нет. Раннер проверяет п. 3 по этому полю: `text` не содержит ни одного значения пароля
  строки (подстроки `raw`, которые `masked` закрывает `***`, длиной от 4 байт); сам текст с таблицей не сравнивается.

Сторона выдаёт поля своих пунктов «Кто исполняет» (ниже): показ — `masked`; отказ — `fault` и `text`; процесс `domain`
— `fault`, сравнивается только пуст он или нет (слово отказа у него своё), и `text`. Поле, которого строка стороны не
исполняет, раннер не сравнивает; лишних ключей нет.

## Чего вектор не покрывает

Отказ на двери единиц (400 `fault: bad_url`, порядок отказов Н3 шаг 2) — сценарий 04 [приёмки главы 6.2](../../../06-console/acceptance/2/README.md);
грамматику самого url (схемы, хост) — [P/02.1 Н1.2а](../../../02-installer/spec/02.1-installer.norms.md) `schemes` и векторы
[`group-of`](../group-of/README.md).
