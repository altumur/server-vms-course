# Векторы: словарь `fault` отказов дверей

Владелец — глава P/06.1 ([нормы](../../../06-console/spec/06.1-console.norms.md) Н2: ответ-отказ `{detail, error, fault?}`; Н4: причины
с `fault` — `not_json`, `not_number`, `too_long`, `bad_url`, `unique`, `must_match`, `garbled`). Участники — двери, которые
говорят этими словами: дверь таблиц (P/06.1 Н4 «Тела, таблицы…»), дверь просьб ([глава 6.4](../../../06-console/spec/06.4-console.norms.md);
вектор [`requests-body`](../../../06-console/vectors/requests-body/README.md)), запечатывание консолью ([глава 6.2](../../../06-console/spec/06.2-console.norms.md): `bad_url` у адреса с
паролем), контроллер ([P/04](../../../04-controller/spec/04-controller.norms.md) `group_by`: вектор
[`group-of`](../group-of/) берёт `bad_url` отсюда), двери домена (уроки 8–10). Байты пишет
«Спецификация» (ADR-0083, стадия B; решение «Архитектора» 2026-10-06 о закрытом словаре); соответствие продукта — его
приёмкой по этой таблице (ADR-0080 доп. 16).

Пакет перенесён из `Source/tests/testdata/fault.tsv` (стадия A) вместе с уроком 6 (стадия B, ADR-0083 доп. (1)); байты
таблицы — те же, включая заголовок-комментарий (его «lesson 03 Н4» — прежний адрес нормы, ныне P/06.1 Н4; копия продукта
сверяется с этими байтами).

## `fault.tsv`

UTF-8, LF, поля через TAB. Строки с `#` и пустые пропускаются; строки заголовка нет. Два поля:

| Поле | Значение |
|---|---|
| `word` | слово `fault` — то, что отказ двери говорит машине и тесту рядом с `detail` для человека |
| `status` | HTTP-код, с которым слово приходит: 400 — неверно само тело; 409 — отказ зависит от стоящих строк (ADR-0031): `garbled` — строка, на которую указывает `ref`, не читается; неответ хранилища — ошибка хранилища, не это слово |

## Правила

- Словарь закрыт: новое слово появляется **сначала** здесь, затем в коде обеих сторон. Слово `error` двери не сравнивается.
- Таблицы, которые называют `fault` (`requests_body.tsv` — колонка 4, вектор `group-of` — колонка 3), берут слова только
  отсюда.
- `fault` бывает только у причин Н4 главы 6.1; `409 conflict` его обязательно несёт; `exists`, `in flight`, `key reused`
  его не добавляют (P/06.1 Н2).

## Прогон

Сторона читает таблицу и проверяет: (1) каждое слово `fault`, которым говорят её двери, есть в таблице и приходит с кодом
из колонки `status`; (2) таблицы-участники называют только слова этой таблицы.
Кто исполняет: консоль (`06-console`) — всю таблицу (команда `fault` ниже); прочие участники — строки слов, которыми
говорят их двери и функции: контроллер (`04-controller`) — `bad_url` (`group_by`, вектор `group-of`), двери домена
(`08-domain`, `09-agent`, `10-domain-console`) — слова своих отказов (Н4 уроков 8–10) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-26).

## Команда стенда `fault`

Ключ `stand` профиля `06-console` (раздел «Раскладка по процессам» [общего README приёмки](../../../common/acceptance/README.md));
шаблон с `{input}` — путь файла с объектом ровно `{}`. Один вызов на таблицу: ответ — полная карта собственного словаря
отказов `{<слово>: <код HTTP>}`, код — целое JSON (не строка, не bool); множество слов и каждый код равны `fault.tsv`,
порядок полей не важен; слово сверх таблицы или недостающее — FAIL. Вход не по форме: не объект или непустой объект.
stdout — ровно один JSON-объект и LF: первый байт `{`, после объекта — LF и конец; лишние поля, байты, CRLF, пробелы вокруг — FAIL строки; форматирование внутри объекта допустимо; служебное — в stderr. Код 0 — вычислено; вход не по форме — код 2, stdout пуст. Конверта `result` нет (догадка стадии C C06-F2-IO-02, решение «Архитектора» 2026-10-23).
