# Векторы: бакет журнала событий и имена `%h<sha256>`

Владелец — [договор журнала событий](../../contracts/event-journal.md): `bucket` `torn`, форма `line` и «Имена файлов в
общих деревьях» (догадки стадии C EJ-G03, EJ-G04, EJ-G06, EJ-G07, EJ-L03, EJ-L06, решение «Архитектора» 2026-10-23); форма строки — семья events
P/05 (`05-resource/data/events.form.yaml`). Участники — писатели и читатели
деревьев событий и объектов: воркер, консоль, контроллер, ресурс ([P/05](../../../05-resource/spec/05-resource.norms.md)
Н1.1, Н1.2, Н1.4). Байты пишет «Спецификация».

## `bucket.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются; первая непропущенная — заголовок `case<TAB>file<TAB>expect<TAB>note`.

| Поле | Значение |
|---|---|
| `case` | имя строки |
| `file` | содержимое файла бакета — строка JSON (`\n` — LF) |
| `expect` | JSON-объект: `ids` — поле `id` прочитанных строк по порядку файла, `torn` — 1, если последний фрагмент без LF (иначе 0), `garbled` — число полных строк, не разобранных формой `line` (времена `t`, `occurred` — кодеком читателя: число или строка; строки `t-*`), `duplicate` — число отброшенных повторов `id` (первая строка побеждает; EJ-L06) |
| `note` | правило |

## `names.tsv`

Те же правила файла; заголовок `case<TAB>input<TAB>expect<TAB>note`. Строки `read-*` — чтение: `input` —
`{entry, suffix, name_file}`: имя записи каталога, суффикс нормы составного компонента (`""`, `.lock`, `.alarms`) и
содержимое файла `<entry без суффикса>.name` строкой или `null` — файла нет; `expect` — исходный компонент строкой JSON
или `@skip` — запись пропускается со счётом, как нечитаемая. Строки `write-*` — запись: `input` — `{component,
name_file}`: исходный компонент и нынешнее содержимое `.name` (`null` — нет); `expect` — `write` (писатель пишет
`.name`), `keep` (совпадает — оставить), `refuse` (не совпадает — отказ без перезаписи).

## `years.tsv`

Те же правила файла; заголовок `case<TAB>t<TAB>expect<TAB>note`. `t` — время записи числом JSON; `expect` — имя бакета
`<YYYYMMDDTHHMMSSZ>.events.jsonl` или `@refuse` — отказ записи до выделения id.

## `append.tsv`

Те же правила файла; заголовок `case<TAB>file<TAB>line<TAB>expect<TAB>note`: `file` — содержимое бакета до записи,
`line` — новая строка без LF, `expect` — содержимое после записи (строки JSON). Хвост без LF дописывается LF, усечения нет
(EJ-L03); прочитанный после записи бакет `no-final-lf` даёт `garbled` 1, а `json-tail` — три обычные строки (`tail-json-appended` в `bucket.tsv`; EJ-L06).

## Прогон

Сторона читает `file` своим кодом чтения бакета и сравнивает `ids`, `torn`, `garbled` с `expect`; для `names.tsv` — своим
кодом раскладки имён, без файловой системы или во временном каталоге; для `years.tsv` — своим кодом выбора бакета.
