# Векторы токена домена

Векторы [договора токена домена](../../contracts/domain-token.md): функция `token(keys, revoked, now, token)` — проверка
токена домена по принятому набору `domain/keys` и строке `domain/revoked` по стенным часам проверяющего, с `expect`
получателя (вид и свой кластер). Владелец — урок P/08, глава 8.2; функцию исполняют сторожевая консоли кластера
([P/06.3](../../../06-console/spec/06.3-console.norms.md) Н1.3, Н1.8), получатель токена вида — воркер и дверь члена
([P/03.7](../../../03-worker/spec/03.7-worker.norms.md) Н3 «проверить у получателя»), процесс `domain` у дверей людей
([глава 8.4](../../../08-domain/spec/08.4-domain.norms.md)) и консоль домена (урок P/10). Байты пишет «Спецификация»
(ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `token` приёмки М11/2
(`inputs/token-*.json`, сц. 04–07, 12) без изменения байтов: сняты только пробелы и переводы строк вне строк JSON; `case` —
имя файла входа (перенос урока 8, план переноса урока 8 § 3, решение «Архитектора» по плану, п. 17; строка «Векторы»
договора). Сценарии М11/02 сц. 04–07, 12 и их входы сняты переносом урока 8 (журнал — «Журнал источника» ниже): таблица —
единственный источник этих случаев.

## Прогон

Без стенда: функция реализации получает вход (колонка `input`) и даёт вывод; `expect` — подмножество полей вывода. Код
выхода 0 — вычислено (в том числе отказ словом); `@exit 2` — вход не по форме: код выхода 2, вывод не сравнивается
(словарь «Стенда» [общего README приёмки](../../acceptance/README.md)); таких строк семь — `token-30`, `token-31`, `token-32`, `token-39`…`token-42` (ниже).
Кто исполняет — каждый проверяющий токен, все строки одной функцией (`expect` — вход): сторожевая консоли кластера (`06-console`, P/06.3 Н1.3 `identity` шаг 3), получатель токена вида и дверь процесса (`03-worker`, P/03.7 Н1.5; P/03.4 Н1.7 `door_admission`), процесс `domain` у дверей людей (`08-domain`, P/08.4) и сторожевая консоли домена (`10-domain-console`, P/10 Н1.5). Агент члена (`09-agent`) функцию не вызывает: ответ местной двери токенов проверяет по `request_id` и `exp` (P/08.7 Н3) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Ключи

Ключи входов главы [P/08.2](../../../08-domain/spec/08.2-domain.norms.md) (пакеты `keys`, `domain-token`,
`domain-envelopes`; ключ приёма книг — и пакет `assemble`) тестовые и открыты: зерно каждого — `sha256("w2c test
<слово>")`, слова — `root 1` (корень домена `acme`),
`root 2` (чужой корень), `token key 1…3` (ключи токенов `t1…t3`), `book seal 1`, `book seal 2` (ключи приёма книг),
`member m1` (ключ члена в `revoked_members`), `eph 1…3` (одноразовые пары конвертов векторов; `nonce` — байты 0…11).
Векторы конвертов запечатаны с этими `eph` и `nonce` только ради воспроизводимости; реализация при запечатывании берёт
случайные ([P/08.2](../../../08-domain/spec/08.2-domain.norms.md) Н1.5, [договор конвертов домена](../../contracts/domain-envelopes.md)). Открытые ключи:

```text
root 1      34dc3424ca1fc497170b49eef38222db60fbcaa887852645d7c73bedcc9f7684
book seal 1 bcd5fdec0a3585c7b8793b352a0322a72c6aa1801c1874dac9e7cebfc2c8f970
book seal 2 57bf48000f17919375a83a26f7b2064ade5a0b8ee1c29f9a3bbdd87c28434603
```

`token-*`: момент `now` = 1760000000 (кроме случаев границ), токен — `iat = now − 10`, `exp = now + 890`,
`jti = 0123456789abcdef`, `sub = alice`; набор rev 3: `current = t2`, `t1` с `until = now + 100`. `keys-15` и `token-15` —
набор после кражи (rev 1760000000, ключ `t3`, `revoked_issuing = [i1]`, новый `book_seal`). У токенов входов есть `kind`
(`person`; вид у каждого токена домена); сц. 12 — проверка получателем (у входов, кроме `token-21`, — вид `tally` с полем аудитории; `expect`: вид и свой кластер, [P/08.7](../../../08-domain/spec/08.7-domain.norms.md), [P/03.7](../../../03-worker/spec/03.7-worker.norms.md)).
`seal-round` сверяется по `opened` и `distinct`; форма двух `envelopes` — по договору конвертов домена.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 43 строки: 11 `ok`, 25 отказов, 7 `@exit 2` | `input` — вход команды `token` текстом JSON (`keys` — документ набора, `revoked` — `{jtis}` как прочитана или `null`, `now`, `token`, `expect?` — `{kind, cluster, audience_claim?}`, `kind` — строка или список видов) → `expect` — `{"result":"ok","payload":{…}}` (подмножество полей `payload`) или `{"result":"refused","reason":<слово>}`: `unknown_key` (прежний ключ после `until`, ключа нет в наборе, украденный ключ после нового набора), `bad_signature` (подмена `payload`), `not_a_token` (две части, `alg` не `EdDSA`, повтор ключа в `header`), `bad_claims` (нет `jti`, `jti` не по грамматике, нет `kind`, `exp` строкой), `expired`, `future`, `revoked`, `no_revocations` (`jtis` не строка, `exp` записи — слово, ведущий ноль, не конечное), `wrong_kind`, `wrong_audience` (чужой кластер, поле аудитории `audience_claim`) |

Границы: `now = exp + 60` — `ok`, `exp + 61` — `expired`; `now = iat − 60` — `ok`, `iat − 61` — `future`; `expect` с
`cluster: null` (`person`) — аудитория не проверяется.

Форма `expect` ([договор](../../contracts/domain-token.md) «Проверка», `expect`; п. 7 записки о планах 8–10, правка
`0c9521c66`): ключ `cluster` обязателен, `null` — только при `kind: person`. Строки `token-30-expect-no-cluster` (вход
`token-18` без ключа `cluster`) и `token-31-null-cluster-not-person` (вход `token-18` с `cluster: null` при `kind: tally`) —
`@exit 2`; токен и прочие поля входа — байты `token-18` (разбор ревью стадии B 8–10, № 13). `expect` — закрытая форма:
`token-32-expect-unknown-key` (вход `token-18` с лишним ключом `audience_clam`) — `@exit 2` (DT-G03).

Список видов (ADR-0091 доп. (18) п. 1, доп. (19) п. 1; маршрут `domain` двери процесса, P/03.4 Н1.7): `token-33`…`token-38` —
вид из списка — `ok`, не из списка — `wrong_kind`, истёкший токен чужого вида — `expired` раньше вида, поле аудитории —
вида, совпавшего на шаге 9 (отображение `audience_claim`; вид без записи — `aud`); токен вида `probe` строк 36–38 подписан
ключом `t2` (`token key 2`), `aud` — `[m9]`, `for` — `[m1]`. `token-43` — токен вида `tally` с тем же отображением, что у `token-36` (поле аудитории — по виду токена, W03-G10). `token-39`…`token-42` — `@exit 2`: `person` в списке, список при
`audience_claim` строкой, ключ отображения не из списка, пустой список.

## Кандидаты

- нечитаемая хранилищем строка `domain/revoked` у двери («проверить нечем», договор «Проверка») — свойство двери, не
  функции: проверяется стендом;
- вход не по форме команды (`audience_claim` пустой, набор `keys` не по форме) — код 2: строк нет, кандидат пакета (форма
  `expect.cluster` — строки `token-30`, `token-31`).

Векторы проверены эталонным Ed25519 (RFC 8032) и разбором JSON с запретом повтора ключа по тексту договора (шаги 1–11
«Проверки»), не по коду реализаций: все 29 ожиданий совпали с выводом оракула; строки `token-30`, `token-31`, `token-32` (`@exit 2`) и `token-33`…`token-43`
добавлены по тексту договора, `expect` (подпись строк 36–38 — эталонным Ed25519 ключом `t2`). При расхождении прав договор, вектор
правит «Спецификация».
