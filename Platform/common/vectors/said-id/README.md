# Векторы: SaidID — имя просьбы в `fetched`

Владелец — [договор отметки просьбы](../../contracts/request-mark.md) «fetched» `said_id` (перенесено из главы
[P/03.4](../../../03-worker/spec/03.4-worker.norms.md) Н1.1; аудит раскладки А-24, Б-02); поле `fetched` пульса — P/03.4 Н1.1: воркер
пишет в пульс SaidID просьб, исход которых он сообщил ([глава 3.6](../../../03-worker/spec/03.6-worker.norms.md) Н3
«взгляд держателя»). Участник — [глава 6.4](../../../06-console/spec/06.4-console.norms.md): жнец консоли читает
`fetched` и снимает строку дозаписи, когда её rid сообщён (Н3 «жнец» `clear`;
до переноса — М10/8). Пакет — общий: алгоритм читают два процесса (решение «Архитектора» по разбору ревью стадии A 6–7, № 2).
Байты пишет «Спецификация» (ADR-0083); соответствие продукта — его приёмкой по этим таблицам (ADR-0080 доп. 16).

## Правило (P/03.4 Н1.1 `said_id`)

- **plain** — rid как есть, если в нём не больше 40 символов Unicode (кодовых точек), он не начинается с «#», в нём нет
  «,», «"», «\» и каждый символ печатный — буква, метка, цифра, пунктуация, символ (общие категории L, M, N, P, S) или
  пробел U+0020;
- **hashed** — иначе «#» и первые 20 знаков hex sha256(UTF-8 rid), строчными;
- **read** — `fetched` разбить по «,»; rid сообщён, если среди имён есть rid или SaidID(rid).

Вход векторов — rid по его грамматике ([P/06.4](../../../06-console/spec/06.4-console.norms.md) Н1.5 `rid`, вектор [`rid`](../../../06-console/vectors/rid/README.md): ≤ 200 байт UTF-8, не пустой, не `.`/`..`, без
`/ \ " '` и Cc, Zl, Zp, не начинается с `free-`). Категории — по Unicode 15.0.0 (как `common.form.yaml`); символы векторов
выбраны так, что их категория в версиях 15.x не менялась.

## `said.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Четыре поля:

| Поле | Значение |
|---|---|
| `case` | имя строки; `plain-…` — SaidID равен rid, `hashed-…` — хэш |
| `rid` | rid — строка JSON; символ, который не печатный по правилу выше, и метка (M) записаны экранированием `\uXXXX` (вне BMP — суррогатной парой), прочие — как есть |
| `said` | ожидаемый SaidID — строка JSON |
| `note` | зачем строка |

Границы: 40 и 41 кодовая точка у ASCII, кириллицы (2 байта), символов вне BMP (4 байта, две единицы UTF-16) и букв с
комбинируемым знаком (точки, не графемы); «#» первым и внутри; запятая; пробел U+0020 и NBSP; Cf, Co, Cn; цифра вне
ASCII; пунктуация и символы ASCII; наибольший rid в 200 байт.

## `read.tsv`

Пять полей: `case`; `fetched` — значение поля пульса, строка JSON; `rid` — строка JSON; `reported` — `true` или
`false`: сообщён ли rid; `note`. Сравнение имени — целиком, байт в байт, без снятия пробелов; пустой элемент — не имя.

## Команды стенда

Ключ `stand` профилей `03-worker` и `06-console` (раздел «Раскладка по процессам» [общего README
приёмки](../../acceptance/README.md)); шаблон с `{input}` — путь файла входа строки;
код 0 — вычислено, 2 — вход не по форме; stdout сравнивается с ожиданием как JSON по значению; конверта `result` нет
(догадка стадии C W03-G03, решение «Архитектора» 2026-10-23):

- `said-id` — в файл пишется ячейка `rid` байт в байт (строка JSON); stdout — SaidID строкой JSON и LF; ожидание —
  ячейка `said`;
- `said-read` — в файл пишется `{"fetched": <ячейка fetched>, "rid": <ячейка rid>}` (ячейки — байт в байт); stdout —
  `true` или `false` и LF; ожидание — ячейка `reported`.

## Прогон

Сторона реализует SaidID и чтение `fetched` своей функцией (воркер — запись, консоль — чтение) и сверяет каждую строку: `said.tsv` — SaidID(`rid`) равен `said` байт в байт; `read.tsv` — исход чтения
равен `reported`. Векторы выведены из нормы; при расхождении прав норма, вектор правит «Спецификация».
Кто исполняет — по таблице: `said.tsv` — воркер (`03-worker`, пишет SaidID в `fetched`, P/03.4 Н1.1, P/03.6 Н3) и консоль (`06-console`, жнец считает SaidID(rid) при чтении, P/06.4 Н3 «жнец» `clear`); `read.tsv` — консоль (`06-console`); воркер `fetched` не читает (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
