# Векторы: текстовые формы значений по типам (`values_by_type`)

Владелец — глава P/06.1 ([нормы](../../../06-console/spec/06.1-console.norms.md) Н1.2 `values_by_type`, `absent`; Н2 — значения JSON-ответа;
Н4 — отказы типа). Участники — все, кто читает или пишет строки единиц и таблиц по манифесту: `<s>controller`, `<s>worker`,
`<s>domain`, `domain`, `domainagent` (читатели строки единицы по [каталогу](../../data/catalog.tsv)), кодек схем
семей [`codec.tsv`](../../data/codec.tsv) (типы `string`, `integer`, `number`, `boolean`, `array`, `null` — то
же правило), строки таблиц (P/06.1 Н1.6: значения и штампы — по `values_by_type`), строка `sweep` (P/06.1 Н1.5: `at`).
Байты пишет «Спецификация» (ADR-0083, стадия B; разбор ревью стадии A 6–7, № 33); соответствие продукта — его приёмкой
по этой таблице (ADR-0080 доп. 16).

## `cases.tsv`

UTF-8, LF, поля через TAB. Строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Шесть полей:

| Поле | Значение |
|---|---|
| `case` | имя строки |
| `type` | тип поля манифеста: `string`, `url`, `int`, `float`, `bool`, `list`, `json`, `blob`; `secret` — строковое поле с суффиксом `_secret`; `list:labels` — поле меток размещения (`placement.constraint: labels-subset`, азбука меток — [договор](../../contracts/labels.md)); `int:inherit` — поле `int` с `inherit` |
| `dir` | `write` — значение JSON на входе двери → элемент строки; `read` — элемент строки → значение JSON ответа; `both` — оба направления |
| `json` | значение JSON (текст JSON) — как в теле запроса (`write`) или ответа (`read`); `@unset` — поле не передано (`write`) / в ответе поля нет (`read`); `@unreadable` — элемент не читается своим типом (`read`) |
| `row` | элемент строки хранилища — **строка JSON** с текстом элемента (`"5"` — текст `5`, `""` — пустой текст); `@absent` — элемента нет; `@refuse` — запись отказана, 400 у двери (Н4), `@refuse <слово>` — с этим `fault` ([словарь](../fault/README.md)); `@json <текст JSON>` — элемент — текст массива JSON, равный по значению; `@sealed` — конверт `enc:v2:…` ([договор запечатывания](../../contracts/sealing.md)) |
| `note` | откуда строка: правило нормы или шаг приёмки P/06.1 (сц. — номер сценария [приёмки главы](../../../06-console/acceptance/1/README.md)) |

## Прогон

Сторона берёт загруженный манифест с полем нужного типа (у `testsub2` есть поля всех типов, `int:inherit` — `keep_days`;
`list:labels` — `testsub.labels`) и проверяет строки своим кодом преобразования, без HTTP:

1. **`write`, `both`** — из `json` получает элемент строки: текст байт в байт равен `row`; `@absent` — элемента нет;
   `@refuse` — преобразование отказано как отказ типа Н4 (при `@refuse <слово>` — с этим `fault`); `@json X` — текст
   начинается с `[`, разбирается как массив JSON и равен `X` по значению (пробелы внутри текста норма не задаёт);
   `@sealed` — текст начинается с `enc:v2:` и открывается ключом кольца в исходное значение.
2. **`read`, `both`** — из `row` получает значение ответа: равно `json` по значению JSON (`1` = `1.0`; строка, булево и
   `null` числу не равны); `@unset` — поля в ответе нет; `@unreadable` — элемент не читается своим типом (у строки
   таблицы — `{name, garbled: true}`, P/06.1 Н2); вход `@json X` подаётся текстом `X` как записан в ячейке; вход `@sealed`
   — любой конверт, ответ — маска `"***"`.

Отказы `@refuse` наблюдает и дверь: те же значения в `POST`/`PUT` дают 400 до записи (сценарии, названные в `note`).

## Команда стенда `values-by-type`

Ключ `stand` профиля `06-console` (раздел «Раскладка по процессам» [общего README приёмки](../../../common/acceptance/README.md));
шаблон с `{input}` — путь файла с одним JSON-объектом. Строку `both` раннер подаёт двумя независимыми вызовами `write` и
`read`; `both` во входе не бывает; ожидаемого результата команда не получает.

- **Запись** — ровно `{type, direction, json}`, все строки, `direction` = `write`, `type` — слово колонки `type` (в том числе
  `list:labels`, `int:inherit`); `json` — исходный текст ячейки `json` строкой JSON (лексема не перевыводится: `1`, `1.0`,
  `1e0`, `-0` различимы) либо ровно `@unset` — поле не передано (строка JSON `"@unset"` передаётся текстом с кавычками и
  с маркером не совпадает). Ответ — один из закрытых: `{"status": "ok", "row": <текст элемента строкой>}` (пустой текст —
  тоже `ok`); `{"status": "absent"}` — элемента нет (`@absent`); `{"status": "refused"}` или `{"status": "refused",
  "fault": <слово>}` — отказ типа (`@refuse <слово>` требует этого `fault`; голое `@refuse` поле не требует и не
  запрещает). У секрета — `{"status": "ok", "row": <конверт>, "plaintext": <значение>}`: команда запечатывает своей
  штатной процедурой на временном тестовом кольце и тем же кольцом штатно открывает полученный конверт; `plaintext` —
  итог открытия, не копия входа; поле `plaintext` бывает только у конверта секрета. Сверка: `row` — байт в байт с текстом
  ячейки `row`; `@json X` — `row` начинается с `[` и равен `X` по значению; `@sealed` — `row` начинается с `enc:v2:`,
  `plaintext` равен значению `json`.
- **Чтение** — ровно `{type, direction, present, sealed, row}`, `direction` = `read`: ячейка-строка JSON — `present: true`,
  `sealed: false`, `row` — её текст, раскодированный один раз; `@json X` — `row` — текст `X` как записан; `@absent` —
  `present: false`, `sealed: false`, `row: null`; `@sealed` — `present: true`, `sealed: true`, `row: null`: только `secret`,
  команда сама готовит конверт своей процедурой запечатывания и подаёт его в штатное чтение («любой конверт» пункта 2
  выше). Ответ — `{"status": "ok", "value": <значение JSON>}` (`value: null` — поле есть со значением `null`),
  `{"status": "absent"}` (`@unset`) или `{"status": "unreadable"}` (`@unreadable`; нечитаемый текст — вход по форме, код 0).
  Сверка `value` с колонкой `json` — по значению JSON, как в пункте 2.

Вход не по форме: неизвестный `type`, `direction` не `write`/`read`, отсутствующее, лишнее или повторное поле, неверный
тип поля, `json` не одно значение JSON и не `@unset`, иное сочетание `present`/`sealed`/`row`. Отказ значения по норме —
код 0 с `refused`, не код 2. Преобразование и выбор поля по типу — функция стороны, не раннера. stdout — ровно один JSON-объект и LF: первый байт `{`, после объекта — LF и конец; лишние поля, байты, CRLF, пробелы вокруг — FAIL строки; форматирование внутри объекта допустимо; служебное — в stderr. Код 0 — вычислено; вход не по форме — код 2, stdout пуст. Конверта `result` нет (догадка стадии C C06-F2-IO-02, решение «Архитектора» 2026-10-23).

## Чего вектор не покрывает

Подготовку состава полей при создании (переданное, `inherit`, `default`, пустая форма — Н1.2, сц. 01, 02, 10), порядок
отказов (Н3 шаг 4), потолок `json`-поля 4000 байт (Н1.4, сц. 16), разбор адреса и пароль в нём (глава 6.2 Н1.1а, векторы
`secret-in`), байты конверта (векторы [`common/vectors/sealing/`](../sealing/README.md)), `fixed`,
ссылки и `unique` (Н1.3). Межъязыковая запись `float` за пределами примеров — по правилу Н1.2 («кратчайшая,
восстанавливающая число, без экспоненты»), не по этой таблице.
