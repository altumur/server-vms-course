# Векторы: хэш пароля

Владелец — глава P/08.4 через [договор хэша пароля](../../contracts/password-hash.md) (догадка стадии C GP-G06, решение
«Архитектора» 2026-10-23). Участники — процесс `domain` (пишет и проверяет) и консоль кластера (аварийный вход). Байты пишет
«Спецификация»; ожидания посчитаны двумя независимыми реализациями PBKDF2-HMAC-SHA256.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются; первая строка без `#` — заголовок. Четыре поля: `case`;
`input` — объект JSON: `{password, salt}` (хэш: соль — 32 строчных hex) или `{hash, password}` (проверка); `expect` — значение
JSON: строка хэша или `true`/`false`; `note`.

13 случаев: 3 хэша, 10 проверок (3 `true`, 7 `false`, из них 6 — строка не по форме).

## Команда стенда `password-hash`

Ключ `stand` профилей `08-domain` и `06-console` (раздел «Раскладка по процессам» [общего README
приёмки](../../acceptance/README.md)), по общему правилу команд векторов: шаблон с `{input}` — путь файла, в который раннер
пишет ячейку `input` байт в байт; stdout — значение JSON и LF (строка хэша или `true`/`false`), сравнивается с `expect` по
значению; код 0 — вычислено, 2 — вход не по форме (не один из двух объектов, соль не 32 строчных hex), stdout пуст.
