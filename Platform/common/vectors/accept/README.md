# Векторы приёма отчёта

Векторы [договора приёма отчёта](../../contracts/accept.md): функция «принять» (`accept`) — поколение, метка, `same`,
`heard`, `ignored`, отказы, дороги. Владелец — урок P/08, глава 8.3 (держатель); участник — ретранслятор (9.2), который
принимает члена той же функцией над своей памятью (разбор ревью стадии A 8–10, № 13 / решение 2; ADR-0083 доп. (13)). Байты
пишет «Спецификация» (ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `accept` приёмки
М11/3 (`inputs/accept-*.json`, сц. 13) и
М11/4 (`inputs/accept-*.json`, сц. 06 — дороги) без
изменения байтов; `case` — имя файла входа (номера урока 4 начинаются заново, имена различны), `note` — урок, сценарий и
шаг. Сценарии М11/03 сц. 13 и М11/04 сц. 06 и их входы сняты переносом урока 8 (ADR-0083 доп. (14) п. 17; журнал —
[приёмка главы P/08.3](../../../08-domain/acceptance/3/corrections.tsv)): таблица — единственный источник этих случаев.

## Прогон

Без стенда: функция реализации получает вход (колонка `input`) и даёт вывод; `expect` — подмножество полей вывода по
словарю «Стенда» ([общий README приёмки](../../acceptance/README.md)): `"@absent"` — поля нет, `"@any"` — поле есть с любым
значением. Форма входа и вывода, смысл полей (`catalog`, `refreshed_ago`, `refresh`, `whole`, `status`) и код выхода 2 —
[договор](../../contracts/accept.md) «Форма функции»; метка `mark` — по форме договора «Поколение, метка, пределы», её
`sha256` — от JCS `stored`, кроме `accept-05-rebase-stored-not-mark` и `accept-20-whole-over-broken-stored` урока 3: там
`stored` нарочно не с `mark.sha256` (разбор ревью стадии B 8–10, № 22, Claude М-18).

Входы зависят от байтов манифеста каталога (P/08.3 Н5; разбор ревью стадии A 8–10, № 37; разбор ревью стадии B 8–10, № 22,
Kimi SB810-06): у строк уроков 3 и 4 `catalog` — `["testsub"]`, ключи объектов — `testsub/*`; у строк семей `reports`,
свидетелей и вкладов (`accept-36`…`accept-39`) — `["testsub", "testsub2"]` (`domain.reports`, `domain.witness`,
`domain.books` с `from` есть только у `testsub2`); `domain.ref` манифеста решает шаги 4 (`member_objects`) и 5 (`not_ready`):

| Манифест | Файл | sha256 |

| `testsub2` | [`Source/tests/testdata/testsub2.subsystem.yaml`](../../../../Source/tests/testdata/testsub2.subsystem.yaml) | `af4ff2fff234f2ed7bb172048252c700c3cf7fe90124de9ef20daf15b5d9d3b2` |

Смена этих байтов — повод перепроверить таблицу.
Кто исполняет — держатель (`08-domain`, процесс `domain`: P/08.3 Н3 «принять» на `POST /api/member/<член>` и пакет ретранслятора с `via`) и ретранслятор (`09-agent`, дверь над своей памятью, P/09.2 Н2) — все строки. Только читают готовое: агент члена (сторона P/09.1 — ответ `carry` и 409 держателя, Н3 «проход агента») и консоль домена (`10-domain-console` — метку `reported`, P/10 Н3 `alarms`) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Строки стадии C

Решение «Архитектора» 2026-10-23 (ADR-0083 доп. (33) п. 8: ошибка `common` без вектора — пробел договора):

- `accept-31`…`accept-38` (ACC-OBJECTS-31-01) — по строке на каждую прочую семью `member_objects` (`domain/shared`,
  `domain/shared-refused`, `domain/reaches`, `domain/alarms`, `domain/backup-taken`, `reports`, свидетель, вклад книги):
  объект сохраняется в `whole` как есть; `accept-39` — ключи вне перечня, в том числе с тем же началом (`domain/sharedx`,
  `domain/shared/x`) и свидетель без имени, отбрасываются молча, отчёт принят;
- `accept-40`…`accept-47` (ACC-FORM-31-01) — имена сравниваются точно: лишнее поле оболочки входа, метки, `stored` —
  `@exit 2`; лишнее поле тела публикации — `not_a_publication`; `sign_failures` не по форме (составное или неизвестное
  имя, `0`, дробное) — поле не взято (`out_of_delta`), отчёт принят;
- `accept-48`…`accept-50` (ACC-G01-COUNTER-31-01) — `n` — целое платформы: `9007199254740991` — по форме;
  `9007199254740992`, `1e20` — не по форме, отчёт принят;
- `accept-52`…`accept-55` (ACC-FORM172, ACC-TIME172; пробел покрытия, нормы прежние) — форма метки на входе: `sign_failures`
  {} — не по форме (`member-reported.schema.json` и OpenAPI: хотя бы одно имя), `@exit 2`; `received_at` строкой канона
  P/01.1 Н0 (`"1700000000.5"`) — читается, вывод как у `accept-09`; отрицательное и с экспонентой — не по форме, `@exit 2`.

Взято ли поле `sign_failures` в метку, показывает поле `sign_failures` вывода `generation` и `heard` с `refresh: true`
(договор «Форма функции»; решение «Архитектора» 2026-10-23): `accept-48` — `{"domain": 9007199254740991}`, остальные
строки 44–50 — `"@absent"`; `accept-51` — `heard` с `refresh: true` и взятым полем.

## Кандидаты

Разбор ревью стадии B 8–10, № 6 (Claude П-2):

- **шаг 4а, `whole_too_large`** (`{"result":"refused","status":413,"reason":"whole_too_large"}`) — строки нет: вход должен
  дать JCS целого `whole'` больше `BODY_LIMIT` (16 MiB). Тело больше предела отсекает дверь до функции (413 тела), а
  объекты вне `member_objects` отбрасываются, поэтому вход — мегабайты: большое `stored` при `base > 0` (`mark` с его
  `sha256`) и малая дельта; ячейка `input` такого размера в таблице непригодна. Нужна форма входа пакета, которой нет: вход
  из файла рядом с таблицей или правило порождения входа (повтор объекта до размера) — решение «Спецификации» по форме
  пакета; затем `mark.sha256` — sha256 JCS этого `stored`. Решение «Архитектора» 2026-10-20: строка остаётся кандидатом
  пакета, причина — вход больше 16 MiB (вопрос 1 по разбору ревью стадии B 8–10);
- **код выхода 2, метка без `stale`** — строки нет (лишнее поле входа, метки и `stored` — `accept-40`…`accept-42`).

Векторы уроков 3 и 4 — входы приёмки, прошедшей у двух реализаций-свидетелей; строки стадии C составлены по договору;
эталонной пересборкой не проверялись (поколение и метка
опираются на разделы договора «Поколение, метка, пределы» и «Публикация члена»; владельцы текста — P/08.3 Н1.3,
[P/09.1](../../../09-agent/spec/09.1-agent.norms.md) Н1.2). При расхождении прав договор, вектор правит «Спецификация».
