# Векторы подписи агента

Векторы [договора подписи агента](../../contracts/agent-signature.md): проверка заголовка `X-Agent-Signature` функцией
`agent-sig`. Подписывает агент члена (владелец — урок P/09, глава 9.1); проверяют держатель (главы 8.3, 8.7), ретранслятор
(9.2) и консоль кластера ([P/06.3](../../../06-console/spec/06.3-console.norms.md) Н1.3 `identity` шаг 2). Пакет — общий:
одну подпись проверяют три процесса (разбор ревью стадии A 8–10, № 13 / решение 2; ADR-0083 доп. (13)). Байты пишет
«Спецификация» (ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `agent-sig` приёмки
М11/3 (`inputs/agent-sig-*.json`, сц. 10) без
изменения байтов; `case` — имя файла входа. Сценарий М11/03 сц. 10 и его входы сняты переносом урока 8 (ADR-0083 доп. (14)
п. 17; журнал — [приёмка главы P/08.3](../../../08-domain/acceptance/3/corrections.tsv)): таблица — единственный источник этих случаев.

## Прогон

Без стенда: функция проверки реализации получает вход (колонка `input`) и даёт исход (колонка `expect`); сравнение — подмножество полей вывода, как у прочих доменных пакетов (чтение коммитов «cammeta-acceptance» 2026-10-20). Время — входом
`now` (стенные секунды проверяющего), не часами процесса.
Кто исполняет — каждый проверяющий подпись, все строки (окно — вход `window`): консоль кластера (`06-console`, двери единиц и `GET /events?class=alarm`, P/06.3 Н1.3 `identity` шаг 2), держатель (`08-domain`, P/08.3 Н1.4, Н2; P/08.7 Н3 «выдать» шаг 1) и ретранслятор (`09-agent`, P/09.2 Н1.3, Н2). Агент члена подписывает (P/09.1 Н1.3) и проверки не вызывает; у консоли домена (`10-domain-console`) шага 2 `identity` нет (P/10 Н1.5) (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).

## Ключи

Ключ подписи — ключ члена `m1`: зерно `sha256("w2c test member m1")` =
`c27e2aa35b5905de643148195bc7c476e5c8dabaf63a2e9bb2dd17ac6d5cac39`, открытый Ed25519
`b7b1b2708888b80495bdee35906cdbf0143b649eb92b6cf1f95d8108a3533b62`; чужой ключ (строка `agent-sig-07-other-key`) — члена
`m2`, `88cae557b9e5d4285769289b5af9d27cfdee0092823f38993912feae4b0c92c7`. Ключ малого порядка (строка
`agent-sig-19-small-order-key`) — точка `0100…00`.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 22 строки: 3 `ok`, 19 отказов (строка 20 — порядок проверок: чужой ключ вне окна → `out_of_window`, разбор ревью стадии B 8–10, № 3; 21 — `sig` с ненулевыми хвостовыми битами, 22 — GET с телом и подписью над ним, AS-01/02) | `input` — вход команды `agent-sig` текстом JSON (`key`, `method`, `path`, `body`, `header`, `now`, `window`; лексемы чисел — как в файле входа) → `expect` — `{"result":"ok"}` или `{"result":"refused","reason":<слово>}`: `out_of_window` (граница `now` = `мс`/1000 + окно — `ok`, на 0,001 с дальше и в другую сторону — отказ; окно 60 у двери единиц), `bad_signature` (чужой ключ, изменены тело, путь, метод; GET с телом — с подписью над пустым и над пришедшим; ключ малого порядка), `not_a_signature` (нет «.», `мс` не цифры, с ведущим нулём, 17 знаков; `sig` с «=», 63 байта, ненулевые хвостовые биты), `no_signature` (пустой заголовок) |

Векторы проверены эталонным Ed25519 (RFC 8032) и SHA-256 по тексту договора, не по коду реализаций; при расхождении прав
договор, вектор правит «Спецификация».
