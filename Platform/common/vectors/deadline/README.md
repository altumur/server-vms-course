# Векторы: запись присланного срока `valid_until`

Владелец — [договор просьбы и её метки](../../contracts/request-mark.md) «Просьба» `valid_until` (владелец договора — глава P/06.4;
[нормы](../../../06-console/spec/06.4-console.norms.md) Н3 «подать просьбу» шаг 1; догадки стадии C C06-DEADLINE-PRECISION-33-01,
C47-DEADLINE-VECTORS-01, решения «Архитектора» 2026-10-25). Участник — дверь просьб консоли. Байты пишет «Спецификация»;
строки — по тексту нормы.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

| Поле | Значение |
|---|---|
| `input` | текст значения `valid_until` из тела просьбы — одно значение JSON, как прислано |
| `expect` | `{"written": <текст>}` — элемент строки просьбы по писателю времени P/01.1 Н0: усечение вниз до миллисекунд (к −∞), отрицательное — `0`, целое — без дробной части; или `{"status": 400, "error": "bad deadline"}` — значение не конечное число JSON (отказ шага 1, P/06.4 Н4 RequestError) |

13 строк: 8 записей (`0`, отрицательные, `1e-12`, усечение `1000.1234` и `1.2349`, целое `1000` и `1e3`), 5 отказов (`null`, строка,
bool, список, переполнение `1e400`).

## Прогон

Без стенда: сторона подаёт значение своему переводу срока двери и сравнивает итог — JSON по значению целиком
(`written` — строка байт в байт). Проверка `too far` (по значению как
прислано, против `now` и `most_valid`) — не здесь: приёмка главы 6.4, сц. 04 и 06.
Кто исполняет — консоль (`06-console`: дверь просьб переводит присланный срок, P/06.4 Н3 «подать просьбу» шаг 1). Воркер (`03-worker`) перевода не делает: читает готовый `valid_until` из строки просьбы (P/03.6 Н3), своя подача — без присланного клиентом срока (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
