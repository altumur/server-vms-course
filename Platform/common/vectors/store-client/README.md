# Векторы: исход ответа хранилища для клиента

Владелец — [договор клиента хранилища](../../contracts/store-client.md) (глава P/01.1; догадка стадии C SC-WIRE78-G01 /
C08-SDK-06, решение «Архитектора» 2026-10-25). Участники — все процессы, которые говорят с хранилищем дверью P/01.1. Байты
пишет «Спецификация»; строки — по тексту договора и P/01.1 Н2, Н4.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

**Вход** — `{op, reply}`: `op` — `get` | `list` | `write` (запись и удаление — `write`); `reply` — `{status, body}` (код HTTP
и тело JSON) или `"@none"` (ответ не пришёл), `"@truncated"` (обрезан), `"@refused"` (отказ в соединении).

**Выход** — строка JSON: `row`, `absent`, `unreadable`, `listing`, `written` или `kind` отказа (`conflict`, `guard`,
`unavailable`, `ambiguous`, …) — договор, раздел «Исходы и что делает клиент» (`outcome`, `no_reply`). Сравнение — JSON по
значению.

16 строк: формы ответа чтения (строка, отсутствующая, повреждённая, не по форме), перечисление, запись и повтор `again`,
версия не по форме провода, нет ответа, обрыв и отказ в соединении у чтения и записи, отказы `conflict`, `guard`,
`ambiguous`, `unavailable`.

## Прогон

Без стенда: сторона подаёт вход своей функции разбора ответа клиента хранилища (провод подменён входом). Провод — приёмка
урока 01.
