# Векторы права по грантам

Векторы [договора права](../../contracts/may.md): функция `may` — право человека по строкам грантов (ранг, область,
срок строки, давность копии, выключенный, аварийная сессия). Владелец — урок P/08, глава 8.4; исполняют сторожевые консоли
кластера ([P/06.3](../../../06-console/spec/06.3-console.norms.md) Н1.3, глава 6.7) и консоли домена (урок 10) и процесс
`domain` (8.4) (решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 1; разбор ревью стадии A 8–10). Байты пишет
«Спецификация» (ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `may` приёмки М11/9 (`inputs/may-*.json`, сц. 07) без изменения значений: JSON
входа — одной строкой, порядок ключей и лексемы чисел — как в файле; `case` — имя файла входа. Одно исключение —
`may-24-unit-id-not-grammar`: у единицы входа добавлено `"labels": []` (решение «Архитектора» 2026-10-20): единица
`{sub, id}` без `labels` — сама вход не по форме (`unit` — `{sub, id, labels, about?}`), и `@exit 2` не отличал бы id
области `unit:` не по грамматике от единицы без меток. Сц. 07 приёмки М11/9 и её входы сняты переносом урока 8 (решение
«Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 17): таблица — единственный источник этих случаев; журнал — [приёмка главы 8.4](../../../08-domain/acceptance/4/corrections.tsv).

## Форма входа команды `may`

Вход — один объект JSON (колонка `input`); функция и её шаги — [договор права](../../contracts/may.md) «Функция `may`».
Форма перенесена сюда из [P/08.4](../../../08-domain/spec/08.4-domain.norms.md) Н5 `exit` вместе с выборами журнала
(догадки стадии C MAY-G01/G02, решение «Архитектора» 2026-10-23): общий алгоритм — общая форма.

```yaml
input:     объект JSON; обязательны все восемь полей grants, as_of, disabled, user, glass, cap, unit, now; поля сверх них
           не читаются (не отказ)
grants:    null | ровно {lines: [line…]}
line:      ровно {subject, cap, scope, until, by} — доверенный вход (копия, уже разобранная по P/08.4 Н1.3): строка не по
           форме — вход не по форме, код 2, не пропуск
  subject: по форме P/08.4 doc.lines[].subject — непустая, 1–64 знака без пробельных (White_Space Unicode 15.0.0),
           управляющих и : | ( ) " /, не break-glass; subject "" — вход не по форме, код 2 (догадка стадии C MAY-G03, решение «Архитектора» 2026-10-23)
  cap:     view | edit | admin
  scope:   "*" | "unit:<sub>/<id>" | "labels:<метка>[,<метка>…]"; <sub> — имя манифеста [a-z][a-z0-9_-]{0,31} (P/02.1),
           <id> — по договору проверки строки «Идентификатор и ограничения полей» named (`unit:testsub/a,b` — 2),
           метка — по договору азбуки меток
  until:   время — 0 или неотрицательное число JSON; читается терпимо, как время в строке (P/01.1 Н0 «Время в строке»),
           без округления читателем (округление до тысячных — у писателя строки, P/08.4 Н1.3 until); значение конечно в
           binary64, как now и as_of: не помещается — вход не по форме, код 2, раньше разбора glass (MAY-UNTIL-D8-01, решение «Архитектора» 2026-10-25)
  by:      строка
as_of:     null | конечное число JSON
disabled:  [строка…]
user:      строка без одиночных суррогатов; "" — по форме (шаг 8: deny no_grant, код 0)
glass:     true | false
cap:       view | edit | admin
unit:      null | "*" | ровно {sub, id, labels, about?}: sub, id — строки (id единицы двери грамматикой не проверяется:
           `"a,b"` — код 0), labels — [строка…]; about — ровно {sub, id, labels} той же формы
now:       конечное число JSON
repeats:   повторы в disabled, labels, lines и в метках области labels: — не ошибка формы
order:     вся форма проверяется до шагов 1–2 (glass, disabled): вход не по форме — код 2 и при glass: true
exit:      0 — вычислено (вывод — договор права output); 2 — вход не по форме (P/08.4 Н5 exit)
```

Примеры кода 2 (P/08.4 Н5): `until` строкой, строка без `by`, `lines` не список, неизвестный `cap`, `labels` строкой, суррогат
в `user`, `as_of` строкой, нет `now`, `glass` не `true | false`, `disabled` не список, `about` не объект, лишнее поле
строки `lines`, `unit` или `about`.

## Прогон

Без стенда: функция реализации получает вход (колонка `input`) и даёт вывод; `expect` — подмножество полей вывода или
`@exit 2` (вход не по форме [P/08.4](../../../08-domain/spec/08.4-domain.norms.md) Н5 `exit`: строки `grants` — доверенный вход, строка не по форме — 2, не пропуск). Время —
входом `now`, не часами процесса.

## Единицы

`c1` `testsub` с метками `east`, `ground`; `c2` без меток; `t1` `testsub2` с меткой `west` и `about` — `c1`. `now` —
1760000000; давность копии — `GRANT_LIFETIME` ([P/08.4](../../../08-domain/spec/08.4-domain.norms.md) Н1.3).

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 26 строк: 11 `allow`, 12 `deny`, 3 `@exit 2` (may-26 — `until` не помещается в binary64, MAY-UNTIL-D8-01) | `input` — вход команды `may` текстом JSON → `expect`: `{"result":"allow"}` (аварийная сессия без грантов, копия ровно суточной давности, строка держателя без `as_of`, `view` без единицы — любая строка, `*`, `unit:` своя и через `about`, `labels:` все метки, метки `about`, ранг выше, срок строки впереди) или `{"result":"deny","reason":<слово>}`: `disabled` (выключенный при гранте), `stale` (копия старше суток), `no_grant` (строки нет, `edit` без единицы не по `*`, чужая единица, одной метки нет, метки самой единицы при `about`, ранг ниже, истёкшая строка, `"*"` не по `*`, строка другого субъекта, единица без меток); `@exit 2` — область `unit:` с id не по грамматике [P/06.1](../../../06-console/spec/06.1-console.norms.md) Н1.3; `subject` "" строки гранта (`may-25`, MAY-G03) |

Векторы проверены оракулом по тексту договора (шаги 1–8) и форме входа [P/08.4](../../../08-domain/spec/08.4-domain.norms.md) Н1.3, Н5 `exit`, не по коду реализаций; при
расхождении прав договор, вектор правит «Спецификация».
