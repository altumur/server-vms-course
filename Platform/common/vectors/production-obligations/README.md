# Public production obligation vectors

This English text is the source; the Russian translation `ru/vectors/production-obligations/README.md` (for people, not in the export) is derived from it by translation and is not edited by hand.

These are public input/observable sequences for [production obligations](../../contracts/production-obligations.md), ADR-0130 Addendum (10), not executable results or a new public DSL. Runner will bind its internal named OBS checks in runner/common_contract_probes.py to the committed source bytes. Only the named owner can supply the executable/context/fault/budget/capacity binding. All ten are NOTEXEC until that binding and execution exist; missing inputs are MissingBinding. No declaration promotes the existing qualification groups or supplies numeric budgets.

## Decision sequences

**Q1** — P/05; [object-client.md](../../contracts/object-client.md). Before rename inject write failure: previous exact bytes remain, refusal. After rename inject barrier failure and lose the answer: unknown. Repeat put_new with the same key/bytes/condition; a conflict with other bytes stays unknown. Exact identity plus qualified durability readback alone resolves success. Negative control: turn conflict into success or claim rollback after rename.

**Q2** — P/02.4; [secret-files.md](../../contracts/secret-files.md). Start with a valid existing ring/recovery target. Inject failure at temporary write, file fsync, rename and directory barrier; crash/restart at each boundary. Before publication the old target survives; after publication uncertainty uses non-zero code without key material, never false rotation success. Positive control completes both barriers before code 0. Negative control omits either barrier.

**Q3** — P/03.2; P/05; [presence-lock.md](../../contracts/presence-lock.md). Hold the check lock, start a worker, cancel or exhaust its declared startup budget; observe exit 2 and no readiness/slot/contender/heartbeat or holder mutation. Also unlink between open and flock: inode mismatch retries consume the same budget. Positive control releases contention within budget; negative control blocks forever or rewrites the old inode.

**Q4** — P/01; all clients; [store-client.md](../../contracts/store-client.md), [forwarding.md](../../contracts/forwarding.md). Delay dependency replies through ordinary hops, then lose a write answer. Measure the total first-attempt budget including queues/backoff/jitter and existing F reserve. Exactly one retry owner repeats identical id/cas/guard within qualified retention. Negative controls multiply retries, reset deadlines or choose a new id; streaming/pass keep their own rules.

**Q5** — P/03; P/05; P/06; [request-mark.md](../../contracts/request-mark.md), [tombstone.md](../../contracts/tombstone.md). Retain a needed expired append mark and an unacknowledged tombstone with a silent peer. Drive declared capacity/admission saturation: existing visible refusal/backpressure, no deletion or repeated side effect. Separately prove eligibility, interrupt cleanup and resume within declared work/completion budgets. Negative controls delete on age alone, waive the silent peer or accumulate eligible state forever.

**Q6** — P/05; all writers; [event-journal.md](../../contracts/event-journal.md), [keys.md](../../contracts/keys.md). Append, move wall time backwards, restart and append again: t never decreases, monotonic deadlines do not move. Move wall time forward with qualification uncertain: retain security/replay records and buckets, visibly defer prune under capacity policy. Negative controls reset the watermark or prune from the jump alone.

**MB1** — P/05; P/06.1; [tombstone.md](../../contracts/tombstone.md). Owner deletes a body. Neighbour acknowledges 404 while an older neighbour-sourced copy is in flight; deliver it after acknowledgement and after tombstone maturity. It cannot resurrect the body or clear the tombstone. Positive control admits a genuine newer owner publication. Negative control relays a neighbour copy or accepts an equal/old source stamp.

**MB2** — P/08.3; P/09.2; [accept.md](../../contracts/accept.md). Publish generations 1 through 5 in whole/delta/mark order, interrupt cleanup at each deletion and restart. At mark 5 keep generations 4 and 5 with deltas; eventually remove ALL 1, 2 and 3 with deltas, not just 3. Before mark publication, higher objects remain uncommitted by the existing rule. Negative control deletes only rev−2 or deletes generation 4.

**MB3** — P/08.1; P/08.3; P/08.5; P/08.8; P/10; [accept.md](../../contracts/accept.md). Read a marker, advance publication/cleanup so its object is gone, reread the marker once and read its newly named object. A valid exact fresh generation succeeds. An unchanged marker plus missing/mismatched object retains silent. A changed marker whose fresh object cannot be read exactly remains temporarily unconfirmed: defer derived snapshot, requiring door 503 unavailable. Negative controls omit reread, loop indefinitely or publish silent from the moving race.

**MB4** — P/04; P/06.9; P/08.10; P/09.1; [turn.md](../../contracts/turn.md). Pause a holder, let another acquire/renew the turn, resume the old holder: its store mutation with the old guard gets 412. An external effect is qualified only with that effect owner's independent fence. Without the external binding report MissingBinding/NOTEXEC for that claim. Negative control treats the lease alone as external exclusion.

## Existing norm probe sequences

The `whole_too_large` function case uses the existing accept input and output forms. Generate a valid stored generation with its exact JCS hash, a matching mark and a small valid delta at `base > 0` that makes reconstructed JCS whole cross `BODY_LIMIT` after filtering to `member_objects`. Keep the transport body within its separate limit and all other checks valid. At the boundary a valid whole fits; beyond it the existing output is `{"result":"refused","status":413,"reason":"whole_too_large"}`, with no mark or object writes. The negative control omits the reconstructed-whole check; rejecting the transport body alone does not detect it. Generate bytes in the future Runner fixture, without a megabyte TSV cell or a new function field.

For `keys_sealed`, use the existing target/AAD and the current closed transfer-key plaintext of [domain envelopes](../../contracts/domain-envelopes.md) and P/08.8 N1.7: a valid envelope succeeds, an unknown plaintext field or wrong recipient/AAD takes the existing refusal path and does not install keys. For `sealed`, create an existing valid member envelope, then a cryptographically valid envelope whose opened content has one extra field: the current closed composition is unreadable; copies, freshness marks and related writes remain unchanged by P/09.1 N1.4. A crypto-only rejection is not this content probe. Positive controls retain allowed composition, held fields and key lifecycle; do not mutate historical cryptographic byte witnesses. Runner must bind the existing owner refusal words, real open/content observations and negative controls; absent binding remains MissingBinding/NOTEXEC.

For pure-budget qualification, independently stall each applicable input/output, lock, dependency and cancellation/stop phase; grow each declared byte/record/id/mark/tombstone/generation/bucket/queue unit to its qualified capacity. Observe finite completion or the owner's existing refusal/backpressure within its declared positive budget and no unsafe deletion. Record admitted versus pending work, output completeness, resources released and retained replay/side-effect state. A generic memory number or a successful unrelated phase does not qualify the missing phase. Native fault/clock/capacity/observable inputs are required independently for each applicable check.
