# Векторы: свежесть — возраст наблюдаемой версии → свеж

Владелец — [договор наблюдения](../../contracts/observation.md) «Свежесть: `LOST_AFTER`» (общий договор модуля
«Платформа»). Участники — все наблюдатели, которые судят «менялся в последние LOST_AFTER»: контроллер — живой воркер пула,
судьба слота, `resource_state` ([P/04](../../../04-controller/spec/04-controller.norms.md) Н3); консоль — `worker_state`
и `WorkerRow.state` ([глава 6.1](../../../06-console/spec/06.1-console.norms.md) Н2,
[глава 6.5](../../../06-console/spec/06.5-console.norms.md)), `w2c_resources_live` (глава 6.5), живые ресурсы слияния
`/events` ([глава 6.4](../../../06-console/spec/06.4-console.norms.md) Н3 «слияние»), `live` `/schema`, «живые» подъёма
схемы и «слышны» вывода сервера ([глава 6.6](../../../06-console/spec/06.6-console.norms.md)). Пакет заменяет «шаг
приёмки на границе», которого стенд без управляемых часов не делает (решение «Архитектора» по разбору ревью стадии B 6–7,
№ 20; граница `≤` — разбор ревью стадии A 6–7, № 1). Байты пишет «Спецификация» (ADR-0083); соответствие продукта — его
приёмкой по этой таблице (ADR-0080 доп. 16).

## Правило (договор наблюдения «Свежесть»)

- `LOST_AFTER` = 45 с (значение — договор наблюдения «Свежесть»; роль в сроках судьи — [P/04](../../../04-controller/spec/04-controller.norms.md) Н1.4);
- **свеж** — возраст наблюдаемой версии ≤ `LOST_AFTER`; **не свеж** — возраст > `LOST_AFTER`. Отношение одно у всех
  наблюдателей и выдач.

Функция чистая: вход — возраст в секундах (число, дробное допустимо), выход — свеж или нет. Как возраст получается
(монотонные часы наблюдателя, первый взгляд — 0, повторное чтение того же состояния и неответ хранилища возраст не
обнуляют) — договор, раздел «Наблюдение версии»; векторы его не проверяют — это история наблюдения, она проверяется
чтением и шагами приёмки читающих уроков. Отрицательного возраста по определению нет (часы монотонные, отсчёт от момента
чтения), строк с ним в таблице нет.

## `fresh.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок. Четыре поля:

| Поле | Значение |
|---|---|
| `case` | имя строки; `zero`, `below-…` — меньше границы, `equal-…` — ровно граница, `above-…` — больше |
| `age` | возраст наблюдаемой версии в секундах — число JSON (`45` и `45.0` — одно число) |
| `fresh` | `true` — свеж, `false` — не свеж |
| `note` | зачем строка |

Границы: 0; `LOST_AFTER − 1` (44), `= LOST_AFTER` (45, 45.0), `LOST_AFTER + 1` (46); дробные около границы — 44.9, 45.1 и
превышение на микросекунду (45.000001): точность часов наблюдателя не огрубляется до целых секунд.

## Команда стенда `fresh-age`

Ключ `stand` профилей `04-controller` и `06-console` (раздел «Раскладка по процессам» [общего README
приёмки](../../acceptance/README.md)), по общему правилу команд векторов: шаблон с `{input}` — путь файла, в который раннер
пишет ячейку `age` байт в байт (число JSON); stdout — `true` или `false` и LF; сравнение — JSON по значению с колонкой
`fresh`; код 0 — вычислено, 2 — вход не по форме (не число JSON), stdout пуст (догадка стадии C C04-VECTOR-01, решение «Архитектора» 2026-10-23).

## Прогон

Сторона реализует суждение о свежести своей функцией (та, что стоит за всеми местами выше) и сверяет каждую строку:
свеж(`age`) равен `fresh`. Сравнение — над числом возраста как есть, без округления: выдача `age` с одним знаком после
точки (глава 6.1 Н2) — отображение, не вход суждения. Векторы выведены из договора; при расхождении прав договор, вектор
правит «Спецификация».
