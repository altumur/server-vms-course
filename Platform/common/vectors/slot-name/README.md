# Векторы: имя слота

Владелец — [договор имени слота](../../contracts/slot-name.md) (глава P/03.2 Н1.4; догадка стадии C POOL-ORDER-51-01, решение
«Архитектора» 2026-10-25). Участники — захват слота, контроллер, договор пула, скрипт воркеров, консоль. Байты пишет
«Спецификация»; строки — по тексту договора.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>op<TAB>input<TAB>expect<TAB>note`.

| `op` | Вход → выход |
|---|---|
| `order` | `{prefix, names}` → допустимые имена в слотовом порядке (массив) |
| `next` | `{prefix, names}` → следующее имя `<prefix>-<max+1>` (строка) |
| `role` | `{prefix, name, server}` (`server` — поле пульса воркера или `null` — пульса нет) → `{server, n}` (`n` — строка десятичных цифр, без переполнения) или `"not_role"` |

17 строк: 3 `order`, 4 `next`, 10 `role`. Сравнение — JSON по значению.

## Прогон

Без стенда: сторона подаёт вход своим функциям порядка, следующего номера и разбора имени процесса роли.
Кто исполняет — по `op`: `order` — захват слота (`03-worker`) и хранитель места договора пула (`04-controller`,
`06-console`); `next` — захват слота (`03-worker`); `role` — «номер выше want» и жертва сокращения (`04-controller`,
`06-console` по договору пула); скрипт воркеров номера берёт из своих экземпляров юнита и пульс не читает — `role`
не исполняет (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-26).
