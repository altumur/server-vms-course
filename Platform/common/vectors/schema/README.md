# Векторы: проверка схемы при старте

Владелец — [договор схемы](../../contracts/schema.md) (глава P/06.6; C06-SCHEMA-WIDE-32-01, решение «Архитектора»
2026-10-25). Участники — процессы, которые проверяют схему при старте: контроллер, воркер, ресурс, консоль, процессы домена.
Байты пишет «Спецификация»; строки — по тексту договора.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>input<TAB>expect<TAB>note`.

**Вход** — `{SCHEMA, row}`: `SCHEMA` — число сборки (в векторах 3, чтобы различать 1, SCHEMA и SCHEMA + 1; у нынешней
спецификации SCHEMA = 1); `row` — элементы строки `platform/schema` текстом (`{version, at}`) или `null` — строки нет.
**Выход** — `{start: true, version}` (старт; версия десятичной строкой) или `{refuse: "too_new", n}` (схема новее; `n` —
точное N десятичной строкой) или `{refuse: "not_a_form"}`; отказ — код 2. Сравнение — JSON по значению.

9 строк: 1, SCHEMA, SCHEMA + 1, 2^63 (без переполнения), 0, 1.5, строки нет; `at` порядка 1e308 — читается, сверх binary64 — не по форме (C137-SCHEMA-TIME-01).

## Прогон

Без стенда: сторона подаёт вход своей функции проверки схемы (чтение строки подменено входом). Ошибка чтения (ждать
доступности) и проверка воркером после продления слота — чтением и сценариями приёмки участников.
Кто исполняет — каждый процесс, чья норма проверяет схему при старте: воркер (`03-worker`, P/03.2 Н3 «проверка схемы воркером»), контроллер (`04-controller`, P/04 Н3 «старт контроллера — проверка схемы»), ресурс (`05-resource`, P/05 Н3 «старт ресурса — проверка схемы»), консоль (`06-console`, P/06.6 Н3 «старт консоли — проверка схемы»), процесс `domain` (`08-domain`) и агент (`09-agent`) — по P/02.4 Н1.12, консоль домена (`10-domain-console`, P/10 Н1.1). Модуль консоли (`07-console-module`) берёт `/schema` готовым (ACC-VECTORS-CONNECT-03: строку исполняет роль, чья норма вызывает её функцию; решение «Архитектора» 2026-10-27).
