# Векторы: набор доверия двери роли и сверка листа

Владелец — [договор сертификата роли](../../contracts/role-certificate.md) «Серверная сторона: класс `role`» (`trust_set`,
`unreadable`; догадка стадии C C10-SDK-ROLE83, решение «Архитектора» 2026-10-25). Участник — консоль домена (дверь роли,
урок P/10). Байты пишет «Спецификация»; строки — по тексту договора.

Сертификаты в векторах заменены их отпечатками: sha256 hex DER сертификата (договор `fingerprint`); вместо DER — строки
`sha256("w2c test ca <слово>")`. Сторона сверяет свою функцию набора над отпечатками; разбор PEM и рукопожатие — договор
`peer` и чтение.

## `cases.tsv`

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок `case<TAB>op<TAB>input<TAB>expect<TAB>note`.

| `op` | Вход → выход |
|---|---|
| `set` | `{own, members, ca_certs}`: `own` — отпечатки своих `ca.pem`, `ca.next.pem`; `members` — `{<член>: {ca?: [<отпечаток>…]} \| "@garbled"}` (`ca` — Entry.ca из `domain/members`; `"@garbled"` у члена — Entry.ca не по форме) или `"@garbled"` (строка `domain/members` нечитаема); `ca_certs` — `{<член>: [<отпечаток сертификата строки ca-certs>…] \| "@garbled"}` (нет записи — строки нет) → отпечатки набора доверия по возрастанию, без повторов |
| `check` | `{set, leaf_ca}` — набор и отпечаток центра, к которому сходится лист клиента → `"trusted"` или `"refused"` |

Сравнение — JSON по значению. 12 строк: 9 `set` (только свои; член с Entry.ca и сертификатом; сертификат вне Entry.ca;
член без Entry.ca; отпечатки без сертификатов; повтор — один; `domain/members` нечитаема; `ca-certs` члена нечитаема;
Entry.ca не по форме), 3 `check` (свой центр, центр члена, чужой).

## Прогон

Без стенда: сторона подаёт вход своей функции набора доверия (чтения строк подменены входом) и сверке листа.
