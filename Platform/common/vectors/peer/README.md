# Векторы `peer`

Векторы [договора `peer`](../../contracts/peer.md): функция `peer` — клиент двери другого кластера по `https://` о сервере
(отпечаток якоря, путь подписей по закрытому списку `sig`, сроки, роль и имя листа). Владелец — урок P/09 (первый договор —
агент к `https://`); участники — консоль кластера (6.7), процесс `domain` (8.8) и консоль домена (урок P/10) (решение
«Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 2; разбор ревью стадии A 8–10, № 7). Байты пишет «Спецификация»
(ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080 доп. 16).

Строки переложены из входов команды `peer` приёмки М11/8
(`inputs/peer-*.json`, сц. 06) без изменения значений: JSON входа — одной строкой (PEM — строкой JSON с `\n`), порядок
ключей и лексемы чисел — как в файле; `case` — имя файла входа. Сценарий 06 приёмки М11/8 и его
входы сняты переносом урока 9 (ADR-0083 доп. (14) п. 17), каталог М11/08 — переносом урока 10: таблица — единственный
источник этих случаев.

## Прогон

Без стенда: функция реализации получает вход (колонка `input`) и даёт вывод; `expect` — подмножество полей вывода или
`exit 2` (вход не по форме М11/8 Н5 `exit`; таких строк в пакете нет). Время — входом `now`, не часами процесса.

## Центры и листы

Как в README приёмки М11/8 «Входы»: центры A (`w2c test ca north`), его промежуточный AI и B (`w2c test ca south`), EC
P-256; листы роли `console` с SAN DNS `m2.w2c.test`; якоря RSA-2048, Ed25519 и P-384 с SHA-384 (сверка М11, D14). Отпечаток
— sha256 hex DER центра ([P/08.3 Н1.6](../../../08-domain/spec/08.3-domain.norms.md) `fingerprint`). `now` — 1760000000.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок; `note` — сценарий и шаг
приёмки.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 25 строк: 7 `ok`, 18 отказов | `input` — вход команды `peer` текстом JSON → `expect`: `{"result":"ok"}` (прямо, якорь промежуточный, якорь корень через промежуточный, два отпечатка — любой, якорь RSA, Ed25519, P-384) или `{"result":"refused","reason":<слово>}`: `foreign_ca` (отпечатков нет, центр чужой, в цепочке только лист), `bad_chain` (лист не от якоря, промежуточного нет, лист не от названного центра, промежуточный не центр, не PEM), `expired` (лист, якорь, лист ещё не действует), `no_role` (SAN URI нет, ролей две, роль пустая), `wrong_role`, `wrong_name`, `ip_address` (IPv4, IPv6 с зоной) |

Векторы проверены оракулом по тексту договора (шаги 1–9; подписи — закрытый список договора сертификата роли `sig`;
библиотека `cryptography`), не по коду реализаций; при расхождении прав договор, вектор правит «Спецификация».
