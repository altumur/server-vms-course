# Слои В7: стандарт и свой остаток

Форму манифеста (P/02.1), канонический вид (P/02.2) и формы семей данных (каталог `Platform/common/data/`) курс
записывает стандартными файлами: JSON Schema 2020-12 — форма, CEL — связи манифеста. Что стандарт не выражает, держат
семь своих слоёв; их исполняет каждая реализация, места — таблицы слоёв рядом со схемами (ADR-0092 «Свой остаток»). Этот
файл заменяет `DIALECT.md` (ADR-0087; снят переходом на В7, за меткой `dialect-reference-dc94d0fd1`). Новое слово `x-*`
и новое правило слоя решает «Архитектор» (ADR-0087 доп. (5), ADR-0092 «Что заменяется»); описание пишет «Спецификация».

## 1. Файлы

| `02.1-installer.scalars.tsv` | таблица простых скаляров манифеста (P/02.1 Н1.1) | рядом с формой манифеста |

Файлы `*.tsv` — таблицы: UTF-8 без BOM, перевод строки LF, TAB — разделитель колонок, строка с `#` — комментарий, первая
строка без `#` — заголовок, набор колонок закрыт. Разделы норм «Форма», «Форма канонического вида», «Семьи данных»
строятся из этих файлов и стоят в нормах байт в байт (ADR-0087 п. 3; построитель — навык `lesson-spec`, `v7/sections.py`).

## 3. Слова схемы

Стандарт — словами JSON Schema 2020-12 в их смысле (`type`, `enum`, `pattern`, `properties`, `additionalProperties`,
`patternProperties`, `propertyNames`, `required`, `items`, `minimum`, `maximum`, `allOf`, `anyOf`, `if`/`then`, `not`,
`$ref`, `$defs`, `default` — аннотация статического умолчания, `description`). Пометки своих слоёв:

| Слово | Слой | Что исполняет реализация |
|---|---|---|
| `x-integer-place` | 2 | целое место манифеста: целое по значению, границы ±(2^53 − 1), приведение к целому |
| `x-time` | 3 | время по канону P/01.1 Н0: запись писателя строгая, читателя терпимая |
| `x-whole` | 3 | целый знак — и у писателя, и у читателя: целое по точному десятичному значению записи |
| `x-integer` | 3 | целое по точному десятичному значению записи |
| `x-max-bytes` | 3 | предел байтов значения в записи |
| `x-max-names` | 3 | предел числа имён вне `properties` |
| `x-encoding` | 3 | `json` или `jcs`: значение места — разбор текста JSON (у писателя `jcs` — каноническая запись RFC 8785) |
| `x-codec` | 3 | типы полей строки по порядку — кодек `items` |
| `x-file` | 3 | экземпляр семьи — файл: корень — разбор текста файла UTF-8 |
| `x-opaque` | 2, 6 | непрозрачное место: набор ключей не проверяется, проекция и обход дерева внутрь не идут; числа — по общим правилам |
| `x-ordered` | 6 | проекция: порядок автора у списка или имён |
| `x-step` | 6 | у схемы вида: шаг проекции, давший ключ |
| `x-default` | 6 | у схемы вида: ключ обязателен умолчанием формы манифеста |
| `x-unique-by` | 6 | у схемы вида: у списка `ordered` — ключ, по которому элементы не повторяются |
| `x-complement-of` | 5 | выражение — дополнение названного (переведено вручную, ADR-0092 п. 12) |
| `x-implied-by` | 7 | строка связей следует из названных строк (`[16, 17]`): отдельно не проверяется, групповая мутация — да |
| `x-owner`, `x-default-text` | — | справочные пометки раздела нормы (урок-владелец, умолчание словами); проверки не дают |
| `x-class` | — | класс отказа прежнего диалекта — только для сверки набора А; класс отказа нормой — слой (P/02.1 Н4) |

**Выражение** (`pattern`, `patternProperties`) — переносимое подмножество: ECMA-262 в режиме `u` в пересечении с RE2 — без
просмотра вперёд и назад, без обратных ссылок; знак пишется самим знаком в строке JSON (не `\x{HHHH}`). Совпадение —
полное: выражение читается как `^(?:…)$`, `$` не совпадает перед последним `\n` (`"w\n"` не проходит `^(?:w)$`); точка —
любой знак (`[\s\S]`). Компиляцию в обоих движках держит `check_spec` (ADR-0092 п. 14).

**Писатель и читатель семей** — один файл схемы: ограничения писателя — в `$defs.writer`; писатель проверяет
`allOf: [схема, $defs.writer]`, читатель — схему (ADR-0092 п. 15). Писатель пишет строго, читатель читает терпимо.

## 4. Слой 1: тонкая проверка текста

Правила — P/02.1 Н1.1 `text` (ADR-0092 доп. (2): перечень закрыт, у каждого правила — случай корпуса): `bytes`, `tab`,
`document`, `refused`, `rare`, `flow`, `escape`, `comment`, `block`, `parser`. Один документ считается по байтам, не по
ответу парсера.

Обходы дефектов закреплённых парсеров — не правила (исход как у нормы YAML 1.2.2, своего отказа не дают):
- **D13** (`go.yaml.in/yaml/v3`): `\/` в двойных кавычках парсер отказывает, YAML 1.2.2 и Н1.1 допускают — слой 1 на Go
  до разбора заменяет `\/` на `/` в двойных кавычках;
- **D16** (оба парсера): последняя строка из пробелов без перевода строки после блочного скаляра даёт значение без
  конечного `\n` — слой 1 дописывает LF в конец текста без LF до разбора.

Прочие известные дефекты закреплённых версий и их обходы — `DEFECTS.tsv` навыка `lesson-spec` (ADR-0092 п. 9): каждый —
случай теста, красный без обхода.

**Пакет `yaml-suite`** ([`vectors/yaml-suite/`](vectors/yaml-suite/README.md)) — исход слоя 1 на каждом тесте
yaml-test-suite `data-2022-01-17` (входы в пакете, приёмка без сети); `layer1` сверяется строго, правило — сведение.

## 5. Связи (CEL)

Строка `relations.json` — выражение CEL над деревом загрузчика: отсутствующее значение и `has` берут статическое
умолчание `default` формы; вычисляемые умолчания, П1–П5 и `x-ordered` к дереву связей не применяются (ADR-0092 слой 6).
Связи проверяются только при чистой форме; отказ — `refused:relations` (P/02.1 Н3, Н4). Строка — одно выражение над
переменной `doc` (дерево загрузчика), результат — список нарушений `{p: путь}`, вложенный по числу перебираемых
сегментов пути строки. Расширения CEL — стандартные `strings` и `two-var-comprehensions`; свои функции —
`depth(dyn) → int` (глубина значения), `template(dyn, list, list, bool) → bool` (подстановки шаблона),
`text(list) → list` (значения текстом). Ошибка исполнения CEL — не «связь держится»: реализация отказывает словами, а не
пропускает строку (`DEFECTS.tsv` D5).

**Порядок перебора отображения** (D18): CEL порядка перебора map не задаёт — выражение не опирается на порядок или номера
элементов перебора `keys()`; наборы сравниваются подсчётом и по значению (`filter(…).size() == 1`).

## 6. Семьи данных

Схема семьи — форма одной строки, объекта или файла каталога `Platform/common/data/catalog.tsv` (колонка `schema`).
Экземпляр — `{key, row}` у строки, `{key, object}` у объекта, `{key, file}` у файла; форма `row` — объект `items` после
кодека (`codec.tsv`). Ключ проверяется грамматикой колонки `key` каталога. Подписанное — до терпимости: кодек и схема
читателя работают на разобранной копии, подпись, `sha256` и пересылка — по исходным байтам.

**Нечитаемо** — строка не раскодировалась или не прошла схему в режиме читателя; ответ — множество путей отказа (JSON
Pointer). Путь семей нормативен: он выбирает исход (§ 7); где библиотека места не даёт — слой 4.

## 7. Исходы нечитаемого (`<семья>.outcomes.tsv`)

Строка: `path<TAB>reader<TAB>outcome<TAB>priority<TAB>unit<TAB>norm`.
- `path` — префикс пути отказа JSON Pointer, пустой — строка целиком; сегмент `*` — любое имя вне ключей `properties`
  того же места или любой элемент списка;
- `reader` — роль, чей исход в строке (имя процесса по `lessons.tsv`: `console`, `<s>worker`, `domain`, …); у пустого
  пути — строка на каждого читателя семьи (`readers` каталога и участники `cas`, `guard`), `*` нельзя; у пути поля `*` —
  все читатели; пара `(path, reader)` не повторяется;
- `outcome` — что делает этот читатель, встретив нечитаемое (словами нормы урока-владельца);
- `priority` — целое, меньше раньше: при нескольких путях действует исход с наименьшим;
- `unit` — единица нечитаемости (`строка`, `поле`, `элемент`): отказ ниже неё не делает нечитаемым содержащий узел;
- `norm` — адрес нормы.

Нечитаемое не подменяется отсутствием (правило DF-OUTCOMES-109); у сторожевой консоли — правило «Нечитаемая строка»
[договора сторожевой и передачи](contracts/gate-and-pass.md).

## 8. Таблица скаляров манифеста (`scalars.tsv`)

Строка: `kind<TAB>pattern<TAB>norm`; первая совпавшая сверху, только у простого скаляра (в кавычках и блочный — строка).
`kind`: `null`, `true`, `false`, `int`, `float`, `nonfinite`, `string`. Строки `limit<TAB>int_max=N` и
`limit<TAB>float_max=X` — пределы: вне них и `nonfinite` — `refused:form` на пути значения (P/02.1 Н1.1).
