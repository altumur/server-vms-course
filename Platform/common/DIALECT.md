# Диалект формы

Диалект — язык, которым курс один раз записывает форму манифеста подсистемы (урок 2) и форму строк и объектов
хранилища (схемы семей данных). Из записи построители делают проверку для реализаций Python и Go и раздел урока
(ADR-0087 п. 1, 5; ADR-0088 п. 1, 7). Слово вне этого описания — отказ построителя. Словарь заморожен: новое слово
решает «Архитектор» (ADR-0087 п. 2, доп. (5)). Построители и `check_spec` пишет «Архитектор», это описание —
«Спецификация».

## 1. Файлы

| Файл | Что | Где |
|---|---|---|
| `*.form.yaml` | дерево узлов формы: `dialect`, `root`, `defs` | урок-владелец: форма манифеста — урок 2, схема семьи — `NN-<процесс>/data/<семья>.form.yaml` |
| `*.references.tsv` | ссылки и отношения между значениями (§ 6) | рядом с формой манифеста |
| `*.scalars.tsv` | таблица простых скаляров (§ 7) | рядом с формой манифеста |
| `common/data/common.form.yaml` | общие определения схем семей; ссылка — `ref: common.<имя>` | `Platform/common/data/` |
| `common/data/codec.tsv` | кодек строк хранилища: логический тип → запись в `items` | `Platform/common/data/` |
| `<семья>.outcomes.tsv` | исходы нечитаемой строки или объекта (§ 9) | рядом со схемой семьи |

**Чтение.** `*.form.yaml` читается тем же слоем текста, что манифест (урок 2 Н1.1): одна грамматика YAML в курсе
(ADR-0087 доп. (4) В1). Файлы `*.tsv` — таблицы: UTF-8 без BOM, перевод строки LF, TAB — разделитель колонок, строка с
`#` — комментарий, первая строка без `#` — заголовок, набор колонок закрыт; YAML к ним не применяется. Ячейка отношения
разбирается грамматикой § 6, ячейка значения скаляра — по своей колонке (ADR-0087 доп. (6) Р1).

`dialect:` — `m10-form/1` у формы манифеста, `data-form/1` у схем семей и `common.form.yaml`.

## 2. Узел

Узел — отображение из слов:

| Слово | Смысл |
|---|---|
| `ref: имя` | узел — `defs.имя` своего файла; `ref: common.<имя>` — определение `common.form.yaml` (ADR-0088 доп. (2) С3). Рядом допустимы только пометки (`description`, `owner`, `default`, `default_text`, `x-class`, `whole`). Рекурсия `defs` допустима для «любого JSON» |
| `type` | слово или список из `object`, `array`, `string`, `integer`, `number`, `boolean`, `null`, `any`, `time`. `integer` — целое (не bool); `number` — целое или дробное; `any` — любое; `time` — время урока P/01.1 Н0 «Время в строке», две записи — писателя и читателя (кодек, § 8; С1). Нет `type` — тип не проверяется |
| `enum` / `not_enum` | значение из перечня / не из него; сравнение с типом: числа равны по значению (`1` = `1.0`), bool не равен числу, строка — ничему, кроме строки |
| `pattern` / `not_pattern` | строка совпадает / не совпадает с выражением целиком (§ 4) |
| `minimum`, `maximum`, `exclusive_minimum` | границы числа |
| `max_bytes: n` | строка не длиннее n байт UTF-8 (С6) |
| `properties: {ключ: узел}` | закрытый набор ключей отображения: иной ключ — отказ `key` |
| `names: {key: узел, value: узел}` | имена автора: имя проверяет `key` (отказ — `value`), значение — `value`; имя не по форме — значение не проверяется; вместе с `properties` — ключи из `properties` идут своим узлом, прочие — `names` |
| `opaque: true` | отображение без проверки набора ключей и значений (числа проверяются, § 5) |
| `required: [ключ…]` | ключ обязателен: нет — отказ с путём этого ключа |
| `items: узел`, `min_items: n`, `max_items: n`, `unique_items: true` | список: каждый элемент; не короче n; не длиннее n; без повторов (путь — второе вхождение). `max_items` у отображения с `names` — не больше n имён (С5) |
| `variants: [узел…]` | выбор по типу значения: применяется первый вариант, чей `type` (после снятия `ref`) совпал; вариант без `type` — любое значение; ни один — отказ типа на пути значения |
| `ordered: true` | отображение имён автора, порядок которого значим: в каноническом виде — массив `{name, …значение}` (ADR-0089 п. 1, доп. (1) Р14: `unit.fields`, `tables.<т>.fields`) |
| `encoding: json` / `encoding: jcs` | в `items` строки лежит текст JSON; узел ниже — его разбор. `jcs` — текст обязан быть JCS (ADR-0072); проверка только в режиме писателя (С2, С4) |
| `whole: true` | у узла `integer`: целый знак и у читателя (`1.0`, `1e0`, `-0.0` — не целое); без пометки читатель строк принимает целое по значению (ADR-0088 доп. (1) Р1, доп. (2) С9) |
| `writer: {слова…}` | ограничения только режима писателя; читатель их не проверяет (С10) |
| `rules: [правило…]` | правила над ключами этого отображения (§ 3) |
| `default` | умолчание ключа: значение условий `is`/`is_not`, `@путь` отношений и канонического вида, когда ключа нет. Подставляется, только если родитель есть в принятом дереве или сам родитель имеет умолчание (ADR-0089 доп. (1) Р10) |
| `default_text`, `description`, `owner` | только для урока: умолчание словами, пояснение, урок-владелец смысла |
| `x-class` | класс всех отказов внутри узла, в том числе незнакомого ключа (урок 2 Н1.2а: `name`, `domain.*`) |

У отображения есть ровно одно из `properties`, `names`, `opaque` (или `properties` вместе с `names`). `x-class` и
`default` у ссылки важнее, чем у определения.

## 3. Правила

`{when: {…}, <действие>…, x-class?}`; правило `{ref: имя}` вставляет `rules` из `defs.имя`. Условие — И всех частей:
`present: [k…]`, `absent: [k…]` (ключ со значением `null` — есть), `is: {k: [v…]}`, `is_not: {k: [v…]}`,
`name_pattern: re`, `name_not_pattern: re` (имя, под которым отображение стоит в `names`).

`is`/`is_not` берут значение ключа, а если ключа нет — `default` узла этого ключа в `properties` отображения, к которому
приложено правило, в том числе под `names` и через `ref`. Ключ со значением `null` — `is` ложно; нет ни ключа, ни
умолчания — `is` ложно, `is_not` истинно.

| Действие | Отказ и путь (урок 2 Н4) |
|---|---|
| `require: [k…]` | нет ключа — путь `…k` |
| `forbid: [k…]` | ключ есть — путь `…k` (ключ, который правило запрещает рядом с другим) |
| `one_of: [k…]` | ровно один: нет ни одного — путь отображения; больше одного — путь второго по списку правила |
| `any_of: [k…]` | хотя бы один, иначе путь отображения |
| `check: {k: узел}` | ключ есть — проверить ещё и этим узлом (путь — внутри `k`) |
| `reject: текст` | условие истинно — отказ с путём отображения |

Правила узла, прошедшего свою форму, вычисляются, даже если отказы формы есть ниже него (ADR-0087 доп. (3) Р1).
Пути правил сверяются с формой при построении (доп. (1) Р2).

## 4. `pattern`

Совпадение всей строки. Разрешено: печатные знаки ASCII, `.`, классы `[…]` и `[^…]` с диапазонами, код знака
`\x{HHHH}` (от 2 до 6 hex-цифр) в классе и вне его (С7), группы `(…)`, `|`, повторы `* + ? {m} {m,n}` (n и m не больше
1000 — предел RE2), экранирование `\` перед знаком пунктуации. Нет: `^ $` вне класса, `\s \d \w \b`, просмотра,
обратных ссылок, флагов, ленивых повторов, категорий `\p{…}` (диапазоны категорий выписываются один раз через `\x{…}` в
`common.form.yaml` по Unicode 15.0.0; ADR-0088 доп. (2) С8). Построитель проверяет выражение по этой грамматике и
переводит его для Python (`re.fullmatch`, флаг `S`, `\x{…}` → `\U…`) и Go (RE2 `^(?:p)$`, флаг `s`).

## 5. Слои, классы, путь

Порядок (урок 2 Н3): текст → имя → ключи → значения → ссылки; значения проверяются раньше ссылок.

1. **Текст** — слой текста урока 2 Н1.1 отдаёт дерево, `numbers` (пути чисел вне `scalars.tsv`), `empties` (пути
   пустых значений) и карту строк ключей; при отказе текста — строку, путь (если есть) и причину (ADR-0087 доп. (3) Р4).
2. **Форма** — обход `root` по дереву: все отказы с путём и классом. Класс отказа — `x-class` ближайшего узла на его
   пути (своего правила), иначе `key` у незнакомого ключа и `value` у прочих. Каждый путь из `numbers` и `empties` —
   отказ формы на своём пути, где бы ни остановился обход; класс — `x-class` ближайшего пройденного предка, иначе
   `value`.
3. **Класс файла** — первый непустой из `name`, `key`, `value`, `reference`; пути ответа — отказы этого класса.
4. **Ссылки** (`references.tsv`) — только если форма чиста; класс файла — `value`, если есть отказ `value`, иначе
   `reference`.

Путь — по уроку 2 Н4: самый глубокий ключ с неверным значением; индекс списка — число JSON. Пути отказа — множество: в
выводе, в ожидаемом и в `diagnostics.tsv` — каноническим порядком по байтам пути JSON Pointer (RFC 6901); проверки
сравнивают так же (ADR-0087 доп. (3) Р2). У правила над набором (`unique`, `prefix_free`, `depth`) путь — сам набор.

## 6. Отношения (`references.tsv`)

Строка: `path<TAB>relation<TAB>class<TAB>norm`; `class` — `reference` или `value`.

**Путь строки** — сегменты через `.`: имя; `*` — значение каждого ключа; `$x` — то же и имя ключа в переменной `x`;
`{}` — имя каждого ключа (значение строки — само имя); `имя[]` — каждый элемент списка; `имя[$i]` — то же с номером.
Строка применяется к каждому найденному значению, кроме `null`; проверки сравнения и членства — только к скалярам.

**Отношение**: `[when <усл> {& <усл>} :] <проверка>`.

| Проверка / условие | Смысл |
|---|---|
| `t in S`, `t not in S` | значение есть / нет в наборе; нет значения — `in` ложно, `not in` истинно |
| `t = u`, `t != u`, `t <= u` | равенство с типом (числа — по значению); `<=` — числа; нет значения — `=` и `<=` ложно, `!=` истинно |
| `t ~ "re"`, `t !~ "re"` | совпадение целиком (§ 4); выражение — всегда строка в кавычках, без кавычек — отказ построения (ADR-0087 доп. (4) В2); у не-строки `~` ложно, `!~` истинно |
| `exists t`, `absent t` | путь есть / нет в дереве (`default` не учитывается) |
| `empty S` | набор пуст |
| `unique S` | в наборе нет повторов |
| `prefix_free S` | ни один элемент с `/` в конце не начало другого элемента набора |
| `depth t <= n` | вложенность отображений и списков не больше n: скаляр — 0, пустое отображение или список — 1 |
| `template t plain S int S [bare]` | каждое `{имя}` — из первого набора, `{имя:int}` — из второго; после `:` только `int`; незакрытая `{` или `{` внутри открытой — отказ; `bare` — строка без `{` целиком из первого набора |

Термы `t`, `u`: `.` — значение строки; `$x` — переменная; `@путь` — значение по абсолютному пути (переменные
подставляются, не перебираются; ключа нет — его `default` из формы, а у узла под `variants` — `default` варианта,
выбранного по значению дерева; построитель отказывает строке `@путь` в узел под `variants`, если у источника нет
случая, который это проверяет); слово (`true`, `false` — bool, иное — строка) или `"строка"`;
`split(t "sep" n)` — n-я часть строки по разделителю; номер вне частей или не строка — нет значения.

Наборы `S` — объединение через `|`: `keys(путь [? фильтр])` — имена ключей отображения (у списка — его строки);
`values(путь)` — скаляры по пути (`null` и не-скаляры пропускаются); `text(путь)` — они же каноническим текстом (JCS:
`1e0` → `"1"`, bool строчными; ADR-0087 доп. (4) В3); `{t, u…}` — перечень (терм без значения выпадает). Фильтр — И
частей над каждым ключом: `name ~ "re"`, `name !~ "re"`, `name != t`, `a = t`, `a != t` (нет значения — истинно),
`a in S`, `has a` (`a` — ключ значения, с `default` формы).

## 7. Таблица скаляров (`scalars.tsv`)

Строка: `kind<TAB>pattern<TAB>norm`; первая совпавшая сверху. `kind`: `null`, `true`, `false`, `int`, `float`,
`nonfinite`, `string`. Строки `limit<TAB>int_max=N` и `limit<TAB>float_max=X` — пределы: целое по модулю больше
`int_max`, дробное вне `float_max` и `nonfinite` — отказ `value` на пути значения. Набор — core YAML 1.2.2 и отклонения
урока 2 Н1.1 (ADR-0087 доп. (1) Р3).

## 8. Схемы семей данных

Схема семьи (`dialect: data-form/1`) — форма одной строки или объекта каталога данных `Platform/common/data/catalog.tsv`;
колонка `schema` каталога называет файл (ADR-0088 п. 1). Область — строки `row` и JSON-объекты `object`; у `file` и
бинарного объекта схемы нет (доп. (1) Р2).

- **Экземпляр** — `{key, row}` для строки и `{key, object}` для объекта; `root` схемы — форма `row` (объект строк `items`
  после кодека) или `object`. Ключ проверяется грамматикой колонки `key` каталога (п. 2).
- **Кодек** — `codec.tsv`: логический тип узла → запись в `items` и в JSON; два режима: писатель (строгий) и читатель
  (терпимый). Подписанное — до терпимости: кодек и схема читателя работают на разобранной копии, подпись, `sha256` и
  пересылка — по исходным байтам (доп. (1) Р6).
- **«Нечитаемо»** — строка не раскодировалась или не прошла схему в режиме читателя; ответ — множество путей отказа
  (п. 4, доп. (1) Р7).
- **Семьи манифеста** (`<spec:…>` в ключе) — оболочка платформы в схеме урока-владельца и закрытый перечень правил
  порождения в его нормах; построитель исполняет их над каноническим видом манифеста (доп. (1) Р3, доп. (2) С16).
- **Окно версий** — колонка `version` каталога; схемы обеих версий рядом, выбор по объявленной версии (доп. (1) Р8).

## 9. Исходы нечитаемого (`<семья>.outcomes.tsv`)

Строка: `path<TAB>outcome<TAB>priority<TAB>unit<TAB>norm` (ADR-0088 доп. (2) С11). `path` — префикс пути отказа JSON
Pointer, пустой — строка целиком; `outcome` — что делает читатель (словами нормы урока-владельца); `priority` — целое,
меньше раньше: при нескольких путях действует исход с наименьшим; `unit` — единица нечитаемости (`строка`, `поле`,
`элемент`): отказ ниже неё не делает нечитаемым содержащий узел; `norm` — адрес нормы. Путь, исход которого норма не
называет, записывается нынешним поведением с пометкой; менять его — правкой поведения (доп. (1) Р7).
