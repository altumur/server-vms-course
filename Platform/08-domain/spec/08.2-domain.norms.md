# P/08.2 — Корень, набор ключей, ключ приёма книг, смена и отзыв без связи: нормы

Канон главы 8.2 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
приёмка — векторы (Н5). Здесь — доверие домена со стороны процесса `domain`: корень и файл восстановления,
закрепление корня, набор `domain/keys` и `rev` его писателя, ключи держателя и ключ приёма книг, отзывы и срок прежних
ключей, окно отзыва без связи, «процесс `domain` домена не основывает», холодный старт и три смены ключей. Общие алгоритмы
главы — договоры, глава — их владелец: [договор набора ключей домена](../../common/contracts/keys.md) (строка
`domain/keys`, функция `keys`, отзывы `domain/revoked`), [договор токена домена](../../common/contracts/domain-token.md)
(форма токена, `TOKEN_SKEW`, функция `token`), [договор конвертов домена](../../common/contracts/domain-envelopes.md)
«Конверт `x25519:v1`».

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из
М11/2 — Н1 «Общее для всех форм», Н1.1–Н1.7 (Н1.2 без
поля вида `trust`, Н1.5 и часть Н1.6 — ссылкой на договоры), Н2, Н3 «холодный старт», три смены и из Н3 «установка
домена» — абзац «процесс `domain` домена не основывает», Н4 (без строки установки), Н5, «Решает реализация» пп. 1, 3, 4 и

## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`domain/keys` — значения `until`. `exp` в `domain/revoked` — из токена, по [договору токена домена](../../common/contracts/domain-token.md)
«Токен».

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/keys`, `domain/root`, `domain/signer`, `domain/signer-pending`, `domain/book-seal`, `domain/revoked`;
- читает: `domain/members` (Entry.key держателя — Н3 «смена после кражи» шаг 3, I4).

Строку `domain/root` пишет только `admin`: установка у держателя ([P/02.4](../../02-installer/spec/02.4-installer.norms.md)
Н3 «установка домена») и `join` у члена ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.1); владелец — эта глава по
протоколу (форма — Н1.1 `pin`; решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 8). У `domain/keys`, `domain/signer`,
`domain/book-seal` второй писатель — `admin` (установка; у `domain/signer`, `domain/signer-pending`, `domain/book-seal` —
и `w2cctl secrets seal`); у `domain/keys` и `domain/revoked` у
члена — агент (участник по [договору набора ключей домена](../../common/contracts/keys.md)). Файл восстановления домена —
строка каталога [P/02.4](../../02-installer/spec/02.4-installer.norms.md) (пишет и читает команда установки и смен,
`proc:02-installer`); процесс `domain` его не читает (Н1.1 `not_on`).

Общее для всех форм главы (hex, base64url, JCS, стенные секунды, Ed25519, X25519; полнота форм) — [договор основания
домена](../../common/contracts/domain-founding.md) «Общие правила форм» (владелец текста — эта глава; решение «Архитектора» 2026-10-23 по находке «Спецификации» I02-FOUND).

### Н1.1 Корень домена

```yaml
root:          пара Ed25519 домена; одна на всю жизнь домена
recovery_file: форма, place, mode — договор основания домена «Корень и файл восстановления»
signs:         только набор domain/keys (Н1.2); записи срока и удостоверение держателя подписывают ключи issuing[] набора (глава 8.8 Н1.1)
limit:         файл восстановления — всё: корень подписывает набор, а ключ резервной копии держателя выводится из зерна корня —
               украденный файл открывает и все резервные копии домена (глава 8.8 Н1.5); средства, кроме смены корня с новой установкой, нет
needed_for:    установка (P/02.4 Н3), плановая смена ключа токенов, смена ключа приёма книг, смена после кражи (Н3); иначе никогда
not_on:        держатель (domain/signer, его резервная копия главы 8.8), консоль, агент, воркер — корня не хранят и не читают
fingerprint:   hex(sha256(<32 байта открытого ключа>)[:8]) — 16 знаков; так корень и ключи называют люди и журналы
pin:           domain/root — форма строки семья root (08-domain/data/root.form.yaml); not_a_pin, when, never — договор основания
               домена «Закрепление корня»
```

X.509 под корнем домена нет: сертификаты TLS ролей выдаёт центр поставки (ADR-0075, P/02.4 Н1.6). Заводская личность
устройства и регистратор — М13; приём члена оператором — глава 8.3.

### Н1.2 Набор ключей `domain/keys`

Форма строки и документа набора (`row`, `doc`, `writer_forms`) и правило «только вперёд» (`only_forward`) — [договор набора
ключей домена](../../common/contracts/keys.md) «Набор `domain/keys`» (владелец — эта глава; разбор ревью стадии A 8–10,
№ 13 / решение 2). Здесь — `rev` писателя:

```yaml
rev:               обычная и плановая смена (ключ токенов, отзыв члена, book_seal) — max(rev набора, который держит
                   подписант, + 1, целые стенные секунды подписанта); rev + 1 больше стенных секунд — смена ждёт, пока
                   часы его не догонят: rev не обгоняет стенные часы подписанта
  emergency:       аварийная смена — после кражи (Н3) и перенос без прежнего держателя (глава 8.8 Н1.8) — max(наибольший
                   известный rev + 1, целые стенные секунды + 60)
  clocks:          предпосылка: стенные часы держателей домена расходятся не больше чем на 60 с (тот же допуск, что
                   TOKEN_SKEW); при ней аварийный набор старше любого, который выпустил прежний держатель
                   (ADR-0074 доп. 7)
```

Набор — то, чему член верит без связи: ключи токенов держателя, отзывы и ключ приёма книг. Без набора у члена нет
домена (сторожевая [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3, Н1.8).

Поле вида `domain/view.trust` (набор, которому верит держатель: `rev`, отпечатки `root` и `book_seal` по Н1.1) —
[глава 8.1](08.1-domain.norms.md) Н1.2а (P/08.1-11; перенесено туда из этого подраздела, разбор ревью стадии A 8–10, № 21).

### Н1.3 Ключи держателя

```yaml
process:       domain (подписант, ADR-0032) — единственный процесс с ключами домена и единственный писатель строк держателя;
               domainconsole и консоль кластера ключей не держат, подписи не просят и строк держателя не пишут: правку
               консоль домена передаёт процессу domain (глава 8.0)
domain/signer: {kid, token_key_secret, serial, issuing_key_secret, backup_key_secret, backup_key_rev}   # у держателя; секреты — конверты кольца (договор запечатывания; P/06.2 Н1.2)
  token_key_secret:   hex 32 байт — зерно Ed25519 ключа токенов (current набора)
  issuing_key_secret: hex 32 байт — зерно Ed25519 выпускающего (его serial — в issuing набора; применение — глава 8.8)
  backup_key_secret:  hex 32 байт — ключ резервной копии (глава 8.8 Н1.5: HMAC-SHA256 от зерна корня), пишет установка (P/02.4 Н3) и перенос;
  backup_key_rev:     целое ≥ 1, при установке 1
  forgotten:          смещённый держатель заменяет строку на {forgotten: "deposed by term N"} (глава 8.8 Н1.6)
readers:       domain (общая таблица читателей секретов P/02.5 Н1.3 `platform_readers`)
domain/signer-pending:  {seed_secret} — подготовленный ключ X25519 плановой передачи у цели (глава 8.8 Н1.7); читатель тот же
  seed_secret:  hex 32 случайных байт — закрытый скаляр X25519, конверт кольца (договор запечатывания; P/06.2 Н1.2) (одно имя с domain/member-key,
                domain/book-seal; добавлено пилотом схем семей данных, Д4)
SIGNER_URL:    адрес двери процесса domain держателя; его знают консоль кластера держателя и запись срока (глава 6.7 — пересылка подписанту, OpenAPI урока 6; глава 8.8)
```

### Н1.4 Ключ приёма книг

```yaml
domain/book-seal:  {seed_secret}           # у держателя; конверт кольца (договор запечатывания; P/06.2 Н1.2); читатель — только domain; без rev
  seed_secret:     hex 32 случайных байт — закрытый скаляр X25519 как есть (RFC 7748 §5: зажим при умножении)
public:            book_seal набора = X25519(seed_secret, 9) — открытая половина, hex
born:              при установке (P/02.4 Н3) раньше набора rev 1; заменяется только сменой ключа приёма книг и сменой после кражи (Н3)
travels:           с резервной копией держателя и переносом (глава 8.8); в отчёты, книги и журналы не попадает
```

### Н1.6 Токены домена и `domain/revoked`

Форма токена (`token`: `header`, `payload`, `sig`) и константа `TOKEN_SKEW` — [договор токена домена](../../common/contracts/domain-token.md)
«Токен» (глава — владелец договора; перенесено туда из этого подраздела, чтобы перенесённые главы P/03.7 и P/06.3 не стояли
на нормах М11; разбор ревью стадии B 3–5, В1). Здесь — отзывы и срок прежних ключей:

Строка `domain/revoked` — форма, писатели, порядок, снятие `prune`, читатели — [договор набора ключей домена](../../common/contracts/keys.md)
«Отзывы `domain/revoked`» (разбор ревью стадии A 8–10, № 13 / решение 2). Здесь — срок прежних ключей:

```yaml
OLD_KEYS:      3600        # с — until прежнего current при плановой смене ключа токенов (Н3)
```

Кто проверяет токен и где отказывают вид и `aud` — [договор токена домена](../../common/contracts/domain-token.md) «Токен»
(перенесено туда; В1). Векторы функции `token` — [`common/vectors/domain-token`](../../common/vectors/domain-token/README.md).

### Н1.7 Окно отзыва без связи

Проверяющий решает по своему набору и своей копии `domain/revoked` по своим стенным часам; связи с держателем проверка не
требует. Поэтому отзыв доходит не мгновенно, и норма называет пределы числом:

| Что отозвано | Принимается не дольше | Чьи часы |
|---|---|---|
| токен (`jti` в `domain/revoked`) | `min(exp + TOKEN_SKEW, доставка domain/revoked проверяющему)`; без связи — `exp + 60`, то есть `lifetime + 60` от выдачи; в `testsub*` самый долгий вид — `testsub2` `feed: 600` → 660 с | стенные проверяющего |
| прежний ключ токенов после плановой смены | до `until` своего набора (`OLD_KEYS` = 3600 с от смены) | стенные проверяющего |
| украденный текущий ключ токенов (у current нет `until`) | **до первого принятого проверяющим набора, где этого ключа нет** (смена после кражи, Н3): вор выпускает новые токены, и член без связи их принимает; сроком это окно не ограничено | — |
| ключ члена (`revoked_members`) | держатель отказывает сразу после своего набора (глава 8.3); член без связи сам себя не отзывает | — |

Доставка у члена — с ответом держателя агенту (глава 8.3; применяет агент — глава 9.1); у кластера держателя — запись в
его же хранилище.

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `domain/keys` — строка

Схема — [`keys.form.yaml`](../data/keys.form.yaml), исходы — [`keys.outcomes.tsv`](../data/keys.outcomes.tsv); версия формы 1; норма — P/08.2 Н1.2; договор набора ключей домена «Набор domain/keys».

| Ключ | Тип и границы | Обязательность | Урок | Смысл |
|---|---|---|---|---|
| `doc` | отображение `{domain, rev, root, current, keys, until?, issuing, revoked_issuing, revoked_members?, book_seal, kid, sig}`; в `items` — текст JSON (encoding: json) | обязателен |  | текст JSON документа набора; ровно один элемент строки; закрытый набор полей — лишнее поле: not_a_set; массивы — без значения порядка, повтор элемента допустим; писатель кладёт массивы по возрастанию |
| `doc.domain` | строка; целиком `[a-z0-9-]{1,64}` | обязателен |  | имя домена, 1–64 знака [a-z0-9-] (P/08.2 Н1.1) |
| `doc.rev` | целое; ≥ 1; ≤ 9007199254740991 | обязателен |  | ревизия набора, целое 1 … 2^53 − 1; только вперёд (договор only_forward; rev писателя — P/08.2 Н1.2) |
| `doc.root` | строка; целиком `[0-9a-f]{64}` | обязателен |  | hex открытого корня (32 байта Ed25519) |
| `doc.current` | строка; не из: `""`; только у писателя: целиком `[0-9a-f]{8}` | обязателен |  | kid ключа токенов, которым держатель подписывает сейчас; ∈ keys; ∉ until (писатель: первые 8 знаков hex открытого ключа) |
| `doc.keys` | отображение `{}` имена автора: имя — строка; не из: `""`; только у писателя: целиком `[0-9a-f]{8}`, значение — строка; целиком `[0-9a-f]{64}` | обязателен |  | `{<kid>: <hex открытого ключа токенов>}`, не пусто |
| `doc.keys.<имя>` | строка; целиком `[0-9a-f]{64}` | необязателен |  | имя: kid — непустая строка (писатель: первые 8 знаков hex открытого ключа токенов, writer_forms); hex открытого ключа токенов Ed25519 (32 байта) |
| `doc.until` | отображение `{}` имена автора: имя — строка; не из: `""`, значение — время (P/01.1 Н0 «Время в строке») | необязателен |  | `{<kid>: <стенные секунды>}` — срок прежних ключей токенов; нет — у ключей срока нет |
| `doc.until.<имя>` | время (P/01.1 Н0 «Время в строке») | необязателен |  | имя: kid ∈ keys; стенные секунды — ключ ещё принимается до этого момента включительно |
| `doc.issuing` | список, элемент — строка; не из: `""`; только у писателя: целиком `[0-9a-f]{16}` | обязателен |  | ключи выпускающего держателя (P/08.8); пустой массив допустим (непустота названа только у keys) |
| `doc.issuing[]` | строка; не из: `""`; только у писателя: целиком `[0-9a-f]{16}` | необязателен |  | serial — непустая строка (писатель: первые 16 знаков hex открытого ключа выпускающего) |

## Н3 Проход

### keys(pinned, held, offered) → took rev | holding rev | refused <слово>

Шаги 1–8 и отказ без изменения строки — [договор набора ключей домена](../../common/contracts/keys.md) «Функция `keys`»
(перенесено туда без изменения; номера шагов прежние; разбор ревью стадии A 8–10, № 13 / решение 2). Векторы —
[`common/vectors/keys`](../../common/vectors/keys/README.md).

### token(keys, revoked, now, token) → ok payload | refused <слово>

Шаги 1–11 (с `expect` получателя), граница `now = exp + 60` и поведение двери при нечитаемой `domain/revoked` —
[договор токена домена](../../common/contracts/domain-token.md) «Проверка» (перенесено туда без изменения; номера шагов
прежние; разбор ревью стадии B 3–5, В1). Векторы — [`common/vectors/domain-token`](../../common/vectors/domain-token/README.md).

### seal(book_seal, plain, aad) и open(seed_secret, envelope, aad) → ok plain | refused <слово>

Запечатывание, открытие и порядок проверок открытия — [договор конвертов домена](../../common/contracts/domain-envelopes.md)
«Конверт `x25519:v1`» (разбор ревью стадии A 8–10, № 12).

### установка домена

Перенесено в главу позднего слоя [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н3 «установка домена» (P/02.4-10,
вводит 8.2): шаги 1–8, интерфейс шага 8, прерванная установка (разбор ревью стадии A 8–10, № 17). Сторона процесса —
ниже.

### процесс `domain` домена не основывает

Процесс `domain` домена не основывает: без строки `domain/signer` он ждёт её, проверяя раз в VIEW_EVERY (3 с), и не берёт
роль держателя и пишет причину в журнал. Домен основывает установка ([P/02.4](../../02-installer/spec/02.4-installer.norms.md)
Н3 «установка домена»). Холодный старт — Н3 «холодный старт».

### холодный старт

```
хранилище каждого кластера поднято (своя установка P/02.4, свой TLS) → установка домена на держателе (P/02.4 Н3)
→ процесс domain держателя стартует и читает свои ключи → оператор принимает членов, закрепляя корень (глава 8.3)
→ агенты членов уносят набор и пишут отчёты (главы 8.3, 9.1) → вид домена полнеет (глава 8.1)
```

Между «хранилище поднято» и «набор у члена» каждый кластер работает сам (уроки P/01–P/07); домена у него нет, сторожевая
— по [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.8. Ни один шаг не зависит от другого кластера: подписант
читает только своё хранилище и файл восстановления.

### плановая смена ключа токенов

```
1. корень из файла восстановления; новый ключ токенов → domain/signer (ключ подписи меняется с записью набора)
2. набор: keys = прежние ключи — прежний current (у него until нет) и те, чей until > now, — плюс новый; current = новый;
   until[прежний current] = now + OLD_KEYS, until прочих — прежний (фильтр «until > now» — только у ключей с until);
   issuing, revoked_issuing, revoked_members, book_seal — прежние; rev по Н1.2 → domain/keys
3. члены берут набор с ответом держателя (глава 8.3; агент — глава 9.1)
```

Токены нового ключа член, ещё не взявший набор, отказывает `unknown_key` — до доставки (глава 8.3). Прежние токены годны
до `until` и своего `exp`. Обрыв между шагами 1 и 2 (строка записана, набора нет): то же следствие — токены нового ключа
члены отказывают `unknown_key`; операция отвечает отказом (код ≠ 0), её повтор начинается с шага 1 — ещё один новый ключ,
и набор называет его (прежний новый ключ никто не принял).

### смена ключа приёма книг

```
1. корень из файла восстановления; новое зерно → domain/book-seal (сначала строка, затем набор: иначе держатель не открыл бы
   конверты к новому book_seal)
2. набор: всё прежнее, book_seal — новый; rev по Н1.2 → domain/keys
3. конверты к прежнему book_seal больше не открываются: секретные вклады таких членов — missing (глава 8.5) до их отчёта,
   запечатанного к новому; принятые тела не переписываются
```

Обычная смена набора (плановая смена ключа токенов, отзыв члена) `book_seal` сохраняет.

### смена после кражи (ключи держателя у вора)

```
1. оператор достаёт файл восстановления; перенос держателя — глава 8.8 (POST /domain/move {stolen: true}); до главы 8.8
   смена после кражи — операция подписанта над своим набором на том же держателе (шаги 2–3 и 5; вызов — «Решает
   реализация» п. 2), глава 8.8 вызывает те же шаги из переноса
2. новые ключ токенов, выпускающий и зерно приёма книг → domain/signer и domain/book-seal нового держателя
3. набор: keys = {новый} без until (прежних ключей токенов нет); current = новый; issuing = [новый serial];
   revoked_issuing = прежний revoked_issuing ∪ прежний issuing; revoked_members = прежний ∪ {ключ члена украденного
   держателя — Entry.key держателя в domain/members (глава 8.3 Н1.1); нет — отказ, ничего не меняется (добавлено сверкой
   М11, I4)}; book_seal = новый; rev — аварийный (Н1.2 emergency): max(наибольший rev набора у достижимых членов + 1,
   целые стенные секунды + 60) → domain/keys
   # до главы 8.8 (тот же держатель) — известный rev — rev набора держателя: члены держат его наборы; формула та же
4. запись срока — глава 8.8 Н1.1 (подпись нового выпускающего); общий документ переподписывается — глава 8.9 Н1.2 after_move
5. члены берут набор с ответом нового держателя (глава 8.3; агент — глава 9.1)
```

**Член, который был без связи.** Пока он держит прежний набор, он принимает токены украденного ключа (Н1.7) и
запечатывает вклады к прежнему `book_seal`. Вернувшись, он берёт новый набор: его `rev` больше любого прежнего при
предпосылке Н1.2 `clocks` — прежний держатель не выпускал `rev` больше своих стенных секунд, а аварийный не меньше
стенных секунд смены плюс 60. Часы держателей разошлись больше — гарантии нет: это предел, а не норма. С этого момента
токены прежних ключей — `unknown_key`, записи срока прежнего выпускающего — отказ (глава 8.8), а его вклады, запечатанные
к прежнему `book_seal`, — missing до первого отчёта после нового набора (глава 8.5).

**Гонки.** Набор пишет один процесс (`domain` держателя); у члена — один активный агент (очередь `domain/agent-turn`,
[P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.13). Два набора с одним `rev` от разных
подписантов невозможны без корня; «держу» при равном `rev` не даёт перезаписать набор повтором. Смена посреди сборки
книги: держатель открывает тем зерном, что прочёл в начале сборки; вклад к другому `book_seal` — missing, не отказ всей книги.

| набор: не по форме Н1.2 | `refused not_a_set` | журнал агента | ничего: держатель пришлёт верный |
| набор: kid не root или подпись не та | `refused bad_signature` | журнал агента | проверить путь до держателя (подмена) |
| набор: другой корень или домен | `refused another_root` | журнал агента; домен — глава 8.3 | член принят в другом домене: принять заново |
| набор без `book_seal` | `refused no_book_seal` | журнал агента | ошибка держателя: подписать набор полной формой |
| строка `domain/signer` есть, но не читается | процесс `domain` роль держателя не берёт, не подписывает, домен заново не основывает | журнал раз в VIEW_EVERY, без значения | восстановить строку (DF-OUTCOMES-109, решение «Архитектора» 2026-10-25) |
| строка `domain/book-seal` есть, но не читается | держатель конверты `x25519:v1` не открывает, секретные вклады — `missing`, строку новым зерном не переписывает | журнал раз в VIEW_EVERY, без значения | восстановить строку (DF-OUTCOMES-109, решение «Архитектора» 2026-10-25) |
| набор старше | `refused older` | журнал агента | ничего: держит новее |
| токен: `no_revocations`, `not_a_token`, `unknown_key`, `bad_signature`, `bad_claims`, `expired`, `future`, `revoked`, `wrong_kind`, `wrong_audience` | [договор токена домена](../../common/contracts/domain-token.md) «Слова отказа» (перенесено туда; В1) | | |
| конверт: `not_v1`, `not_an_envelope`, `does_not_open` | вклад не открыт — член missing в книге (глава 8.5) | держатель: причина без значения | член перезапечатывает следующим отчётом к своему набору |
| файл восстановления не читается, режим шире 0600 или `root_pub` не от `root_key`; смена после кражи без `Entry.key` держателя | отказ операции, ничего не меняется | оператор | взять верный файл |

Отказы установки (хранилище или кольцо недоступны, `domain/keys` или `domain/root` есть, файл восстановления уже есть или
путь в `PLATFORM_DIR`) — [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н4 (перенесено с установкой).

## Н5 Приёмка

Сценариев стенда у главы нет: приёмка — векторы функций Н3 (пакеты ниже; ключи входов и журнал источника — [README пакета
`domain-token`](../../common/vectors/domain-token/README.md)). Команды
`keys`, `token`, `seal`, `seal-round` реализации на входах векторов — без хранилища, сети и стенда. Ключи входов —
тестовые, открыты в README пакетов. Вызов — двери словаря «Стенда домена» [общего README приёмки](../../common/acceptance/README.md);
сравнение — подмножество полей.

# (offered, revoked, token, envelope) — любое значение JSON: их проверяет сама функция и отвечает словом, не кодом 2.

                   another_root | no_book_seal | older, rev?}            # rev при older — rev held

             expect?: {kind: <строка> | [<строка>…], cluster: <член> | null, audience_claim?: <имя поля — непустая строка,
                       умолчание aud> | {<вид>: <имя поля>}}}
             # kind списком — непустой, без повторов, без person; audience_claim при нём — отображение с ключами из списка
             # (вид без записи — aud); иное сочетание — вход не по форме, код 2 (договор токена домена «Проверка» expect;
             # ADR-0091 доп. (18) п. 1, доп. (19) п. 1)

             # cluster — обязательный ключ expect; null — только при kind: person; без ключа или null при ином kind —
             # вход не по форме, код 2 (договор токена домена «Проверка» expect; разбор ревью стадии B 8–10, № 22: М-2)

             # свой конверт не открылся — {result: refused, reason: <слово открытия Н1.5>}
held:        не по форме Н1.2 (включая book_seal) — код 2: это набор, которому член уже верит
Pin:         {pub, domain}                     # Н1.1; pinned во входе не по этой форме — код 2
output:      закрытые объекты выше; ключи — в любом порядке; payload — объект payload токена как есть

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команды `keys`, `token`, `seal`, `seal-round`** для приёмки — шаблоны с `{input}`; их вызов и вывод — двери словаря
   «Стенда домена» [общего README приёмки](../../common/acceptance/README.md), формы — Н5;
2. **вызов плановых смен и смены после кражи** до главы 8.8 (имя, аргументы, где файл восстановления, как команда узнаёт
   каталоги хранилища, объектов и их копий, внутри которых файл запрещён); команду установки домена называет
   [P/02.4](../../02-installer/spec/02.4-installer.norms.md) «Решает реализация» (перенесено с установкой; стенд главы 8.3
   называет её строкой словаря `@install domain`);
3. **генератор случайности** для зёрен, `eph` и `nonce` — криптографический генератор ОС;
4. **порядок полей JSON** в `doc` и выводах — свободен; подпись — над JCS.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/08.2-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/08.2-01** корень только в файле восстановления, подписывает только набор; держатель, консоль, агент, воркер корня не держат — проверяется чтением Н1.1 и прав [P/02.5](../../02-installer/spec/02.5-installer.norms.md) Н1.4а (строки домена); режим файла 0600 при каждом чтении (Н1.1 `mode`, сверка М11, I3) и «процесс `domain` домена не основывает» (Н3) — чтением (из пункта М11/2-10, разбор ревью стадии A 8–10, № 17); стенд — глава 8.3 (сц. 01)
- [ ] **P/08.2-02** набор: закрытая форма, подпись корня над JCS, `book_seal` обязателен — векторы [`keys`](../../common/vectors/keys/README.md) (М11/02 сц. 02, 03); поле вида `trust` — чтением (P/08.1-11; разбор ревью стадии A 8–10, № 21)
- [ ] **P/08.2-03** закрепление корня только при установке и приёме; без него и с другим корнем — отказ — векторы `keys` (М11/02 сц. 02); приём — глава 8.3, `join` у члена — глава 9.1
- [ ] **P/08.2-04** только вперёд: older, holding при равном rev, took; rev = max(+1, стенные секунды) — векторы `keys` (М11/02 сц. 01); правило писателя — чтением Н1.2 и Н3
- [ ] **P/08.2-05** проверка токена по порядку договора токена домена «Проверка»: формы, ключ и until, подпись, claims, ±60 по часам проверяющего, отзыв — векторы [`domain-token`](../../common/vectors/domain-token/README.md) (М11/02 сц. 04–07)
- [ ] **P/08.2-06** `domain/revoked`: форма, порядок, снятие при `exp + 60 < now` (строго, ADR-0074 доп. 7), нечитаемая строка — «проверить нечем» — векторы `domain-token` (М11/02 сц. 07); писатель (у члена — объединение с ответом, RV) — чтением договора набора ключей домена «Отзывы»
- [ ] **P/08.2-07** окно отзыва без связи названо числом и часами (Н1.7); украденный current — до набора без него — векторы `domain-token` (`token-15`, М11/02 сц. 04); стенд — глава 8.8
- [ ] **P/08.2-08** конверт `x25519:v1`: байты, AAD, три слова отказа, без подбора AAD — векторы [`domain-envelopes`](../../common/vectors/domain-envelopes/README.md) `x25519-open` (М11/02 сц. 08–10)
- [ ] **P/08.2-09** запечатывание недетерминировано и открывается своей же функцией — векторы `domain-envelopes` `x25519-round` (М11/02 сц. 11)
- [ ] **P/08.2-10** смены: плановая (until = now + 3600), ключа приёма книг (строка раньше набора), после кражи (порядок и состав набора; ключ члена украденного держателя из `Entry.key`, нет — отказ без изменения — сверка М11, I4, из пункта М11/2-10, разбор ревью стадии A 8–10, № 17); член без связи — Н3 — проверяется чтением; кража на стенде — глава 8.8 Н5
