# P/08.4 — Люди и гранты: нормы

Канон главы 8.4 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/4/README.md). Здесь — люди домена у держателя: строка человека, вход и токен человека, отзыв;
строки грантов и последний администратор; право по грантам — [договор права](../../common/contracts/may.md) (функция
`may`, владелец — эта глава) ссылкой; проверка личности и гранта у дверей процесса `domain`; аварийная учётка кластера у
держателя (строка, дверь `PUT`, `GLASS_MIN`, форма `pwhash_secret`); двери людей и первый администратор; предел попыток
`POST /api/login`. Глава читается после глав 8.0, 8.2, 8.3 и 8.1 ([записка модуля](../../module-design.md), «Порядок
чтения»).

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из
М11/9 — Н1.1, Н1.2; Н1.3 без строк `member_copy`, `holder_copy`
(копия члена — агент, [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4; `note` id-map М11/9-04); Н1.4 (указатель на договор права); строка `domain` Н1.5 (сторона
процесса `domain`); Н1.6 — строка `domain/break-glass/<кластер>`, `writer`, `GLASS_MIN`, `carry` (разбор ревью стадии
A 8–10, № 22); Н1.9; Н1.10; строки Н2 дверей процесса и журнал; Н3 «дверь людей», «гранты», «Гонки»; строки Н4 процесса;
Н5 — блок `may`/`exit` и сценарии 01, 02, 04, 08, 09, 10; «Решает реализация» пп. 1–3. Номера подразделов — прежние
номера М11/9. Остальное М11/9 — у соседей: индекс имён Н1.7 — [глава 8.5](08.5-domain.norms.md); сторожевая консоли
кластера с грантами и `/session` (Н1.5 `cluster`, `session`, `body_unit`), аварийный вход у консоли кластера (Н1.6 `door`,
`GLASS_SESSION`, `GLASS_SESSIONS_MAX`, журнал) и дверь `GET /domain/keys` (Н1.8) — консоль кластера (поздний слой урока
P/06; контракт — [OpenAPI урока 6](../../06-console/spec/06-console.api.openapi.yaml), [договор сторожевой и
передачи](../../common/contracts/gate-and-pass.md); решение «Архитектора» 2026-10-20 по планам 8–10, п. 12); передача
дверей людей консолью домена (Н1.9 `pass`, сторона консоли) и `GET /domain/grants` — урок
[P/10](../../10-domain-console/spec/10-domain-console.norms.md) (Н1.3а, Н1.2д); копия грантов и аварийной строки у члена — агент, урок
[P/09](../../09-agent/README.md). Ссылка «P/0N[.K]» — урок или глава модуля; «М11/N» — урок-источник М11 (снят переносами уроков 8–10; новые адреса — id-map);
«глава 8.K» — глава этого урока. Id норм — `P/08.4-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов)
(в том числе порядок массивов вывода, область — уроки 8–10).

## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`domain/users/<имя>` — `at`, `expires` (`0` — без срока); строка гранта — `until` (`0` — без срока); `domain/break-glass/<кластер>` — `set_at`;
`domain/groups/<имя>` — `at`, значения `joined`; `domain/roles/<имя>` — `at`, `assigned[].until`, `assigned[].at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/users/<имя>`, `domain/deleting/<имя>`, `domain/disabled`, `domain/grants/<кластер>`, `domain/break-glass/<кластер>`, `domain/groups/<имя>`, `domain/roles/<имя>`;
- пишет: `domain/revoked` (put), `<корень событий>/audit.alarms/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `domain/keys`, `domain/revoked`, `domain/signer`, `domain/signer-turn`, `domain/names/<sub>/<книга>`.

Токен человека и отзыв — [договор токена домена](../../common/contracts/domain-token.md) и [договор набора ключей
домена](../../common/contracts/keys.md) «Отзывы» (строки `domain/keys`, `domain/revoked` — [глава 8.2](08.2-domain.norms.md)
Н1.6); ключ токенов держателя — строка `domain/signer` (глава 8.2 Н1.3); страж записей — `domain/signer-turn` ([глава
8.10](08.10-domain.norms.md) Н1.7); индексы имён для проверок дверей людей и грантов — `domain/names/<sub>/<книга>`
([глава 8.5](08.5-domain.norms.md) Н1.7). Копию `domain/grants` `{doc, as_of}` у члена пишет агент ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4 `member_copy`); форма
`doc` у неё и у строки держателя — одна (`common.grants_doc`, решение «Архитектора» 2026-10-20 по планам 8–10, п. 3).

Общее Н1 глав 8.0–8.3, 8.5–8.7 действует ([P/08.2 Н1](08.2-domain.norms.md) «Общее для всех форм главы»; пересылка —
[договор пересылки](../../common/contracts/forwarding.md)). Люди живут у держателя; токен человека называет субъект и ничего больше ([договор токена
домена](../../common/contracts/domain-token.md) «Токен», `kind: person`, без `aud`). Что человеку можно, решает каждый
кластер по своим грантам, которые несёт агент; проверка — локальное чтение без связи с доменом. Люди с паролями и
аварийные пароли — операции процесса `domain` (подписант, ADR-0032), он проверяет каждую сам; гранты пишет он же ([глава
8.0](08.0-domain.norms.md) Н1.8: консоль домена правку передаёт). Решение «Архитектора» по вопросам М11/9.

### Н1.1 Человек

```yaml
domain/users/<имя>:  {name, how, pwhash_secret, disabled, title?, email?, expires?, pw_by?, at, by, revision}   # у держателя; писатель — процесс domain
  name:        имя человека — форма и пробельные знаки — договор имени человека common/contracts/person-name.md `name`,
               `white_space` (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, А-20); не по форме — 400 bad name
  how:         "password"                       # иных способов входа урок не нормирует
  pwhash_secret: форма, хэш и проверка — договор хэша пароля common/contracts/password-hash.md (перенесено; догадка стадии C GP-G06, решение «Архитектора» 2026-10-23);
               секрет по суффиксу (P/02.1 Н1.3а), запечатан кольцом держателя
  disabled:    true | false
  title:       отображаемое имя, строка 0..200 знаков; поля нет — ""
  email:       строка 0..254 знаков; форму адреса платформа не проверяет, писем не шлёт; поля нет — ""
  expires:     0 — без срока; иначе стенные секунды; now ≥ expires — человек «выключен по сроку»; поля нет — 0
  pw_by:       имя того, кто последним задал пароль (доказанное сторожевой; у first-admin — сам заводимый); пишется при first-admin,
               POST /domain/users, смене пароля; поля нет — «задал не администратор» (ADR-0100 §3)
  at, by:      стенные секунды и имя человека последней правки (доказанное сторожевой)
  revision:    глава 8.0 Н1.9 «Версии»: 1 при создании, +1 на каждую запись строки
  # писатель поле со значением по умолчанию (title, email, expires) не пишет: строку читает и процесс прежней версии (ADR-0098 §3)
PASSWORD_MIN:  10          # символов
domain/disabled: {names: <текст JCS массива имён>}  # имена выключенных по возрастанию в байтах UTF-8, без повторов; нет —
               # "[]"; массив, не строка через «,»: имя может нести запятую (решение «Архитектора» по R41-11); писатель —
               # процесс domain при каждой правке disabled и сверкой каждым проходом (Н3 «срок»); имя здесь, если disabled = true или
               # now ≥ expires: выключен по сроку = выключен, вход (Н1.2 check), may шаг 2 и carry судят по domain/disabled и полю
               # disabled, expires напрямую не читают; окно «срок наступил, прохода ещё не было» — не дольше прохода; секретов нет (ADR-0051, ADR-0098 §3)
delete:        удалить строку человека и снять его строки во всех domain/grants/* (Н1.3) — одной правкой на строку грантов;
               под меткой удаления ниже (Н3 «дверь людей» шаг 9)
domain/deleting/<имя>: {}    # метка удаления человека у держателя; писатель — процесс domain под стражем domain/signer-turn;
               # стоит с начала DELETE до снятия всех строк грантов с subject = <имя>; пока стоит — имя занято:
               # POST /domain/users — 409 exists, новая строка гранта с этим subject — 409 being deleted; сверка при
               # старте и каждым проходом главы 8.1 снимает по ней строки грантов и удаляет метку (журнал cammeta-go, М11-09 № 1; решение «Архитектора»)
               # ключ метки <x>: имя человека по Н1.1 или role: и имя роли (Н1.3а); role:<R> — метка удаления роли, Н3 «роли»
               # метка — любая строка под domain/deleting/, что бы ни лежало в items; <x> не по грамматике — ни то ни другое —
               # сверка удаляет метку с журналом domain.deleting.dropped {key, reason: "not a name"}, строк грантов не
               # ищет (subject таким не бывает); проход из-за неё не стоит (добавлено сверкой М11, P1)
unreadable:    строка человека, которая не читается (не по форме Н1.1 или name ≠ <имя> ключа), — пропускается и считается
               (диагностика процесса), остальные служат; domain/disabled она не снимает: имя её ключа остаётся там, если
               было; DELETE /domain/users/<имя> удаляет и её — снятие строк грантов и метка как у читаемой (добавлено
               сверкой М11, P2: иначе испорченная строка вернула бы выключенному старые токены)
```

### Н1.2 Вход, токен человека, отзыв

```yaml
door:          POST /api/login {user, password} у процесса domain; тело ≤ LOGIN_BODY (больше — 413 {error: "too large",
               detail}); оба поля — строки (иначе 400 {error: "bad body", detail}); дверь cookie не ставит и не читает
via:           страница ходит к своей консоли: POST /api/login — открытая строка списка дверей домена договора пересылки
               и open_routes договора сторожевой (P/06.3 Н1.3), консоль домена передаёт её процессу (глава 8.0 Н1.8);
               CORS нет — другой origin страница не зовёт
check:         предел Н1.10 → человек есть, не disabled и имени нет в domain/disabled, пароль сверился (сравнение постоянного времени) → токен;
               сверка PBKDF2 (и у аварийного входа Н1.6) не держит общего замка процесса: прочие двери её не ждут
               (добавлено сверкой М11, P21);
               нет человека или disabled — сверка по фиктивному хешу той же стоимости (600000): ответ неизвестному,
               выключенному и неверному неразличим и по коду, и по телу, и по времени;
               строка domain/users/<имя> есть, но не читается — 503 {error: "unavailable"}, не 401 (исход семьи users;
               различимость имени здесь допустима — Г-42)
answer:        200 {token, until, user}; иначе 401 {error: "refused", detail: "wrong user or password"} — отказ в счёт
               предела Н1.10
token:         договор токена домена «Токен», строка person (поля токена человека; GP-L01): iat — now, ключ токенов
               держателя (current набора); until = exp
TOKEN_LIFETIME: 900        # с
LOGIN_BODY:    16 KiB
revoke:        POST /domain/revoke {token} — строка списка дверей домена договора пересылки; консоль домена передаёт её
               процессу domain (Н1.9 `pass`); токен проверяется функцией token договора токена домена «Проверка» (не
               прошёл — 401 со словом token; no_revocations — 503 unavailable, Н1.5); jti и exp добавляются в domain/revoked (глава 8.2 Н1.6; договор набора
               ключей домена «Отзывы») — ответ 200 {revoked: <jti>}; отозвать токен может тот, кто его держит; страница
               зовёт дверь при выходе (P/06.3 Н1.3 DELETE /session — снимает cookie)
login_url:     P/06.3 Н1.3 (LOGIN_URL окружения, умолчание /api/login)
deposed:       смещённый держатель токенов не выдаёт — 409 deposed (глава 8.8 Н1.6)
```

Ссылки блока: список дверей домена и пересылка — [договор пересылки](../../common/contracts/forwarding.md); `open_routes`,
`login_url`, `/session` — [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Сторожевая»
([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3); токен и `token` — [договор токена
домена](../../common/contracts/domain-token.md).

### Н1.3 Гранты

```yaml
domain/grants/<кластер>:  {doc: <текст JCS {lines}>, revision}   # у держателя; <кластер> — имя члена по грамматике главы 8.3
                                                       # (членом быть не обязан: гранты готовят до приёма) или domain;
                                                       # в пути двери — байт в байт, %-кодирование не декодируется:
                                                       # m%31 — не имя, 400 bad name (добавлено сверкой М11, P13)
  lines:       [line…] по (subject, cap, sub, scope) в байтах UTF-8, нет sub — пустая строка, затем until по числу, без повторов по
               (subject, cap, sub, scope, until); until сравнивается по значению: 0 и 0.0 — одна строка, повтор (добавлено сверкой М11, P7, P9)
  line:        {subject, cap, sub?, scope, until, by}
    subject:   имя человека (Н1.1) | субъект индекса имён (глава 8.5 Н1.7) | role:<имя роли> (Н1.3а, до 69 знаков; знак : грамматика
               имени человека не пропускает, поэтому имя роли с человеком не сталкивается)
    cap:       none | view | edit | admin      # none < view < edit < admin; none разрешения не даёт, бывает только у строки роли
               # (ADR-0099 §1); у строки человека или ключа индекса — не по форме, 400 bad line
    sub:       имя манифеста (грамматика P/02.1 Н1.2 name) или platform; нет поля — строка действует во всех подсистемах и в
               platform; наличие манифеста не проверяется: гранты готовят до приёма (ADR-0097 §1)
    scope:     * | unit:<sub>/<id> | labels:<метка>[,<метка>…] | folder:<id>   # метки — азбука меток Platform/common/contracts/labels.md, без повторов;
               # <sub> — имя манифеста (P/02.1), <id> — по грамматике идентификатора P/06.1 Н1.3; folder:<id> — id папки P/06.8 Н1.1
               # (32 строчные hex-цифры); иначе строка не по форме (у двери — 400 bad line; добавлено сверкой М11, P10);
               # labels: у строки роли — не по форме (ADR-0099 §1, А2)
    until:     0 — без срока; иначе стенные секунды — строка действует, пока now < until; у входа больше трёх знаков
               дроби — округление до тысячных от десятичной записи, половина от нуля (как глава 8.1 Н1.4 round): строка
               хранится и сравнивается округлённой (решение «Архитектора» по сверке М11, P8); положительное until, которое
               так округлилось бы в 0, пишется 0.001 — смысл «просрочен» тот же, 0 — только «без срока» (вход PUT и
               переписывание; решение «Архитектора» 2026-10-29, C08-UNTIL-REWRITE-01)
               переписывая строку целиком (правка другого subject, снятие строк при удалении, сверка), процесс domain —
               писатель: until оставшихся строк — формой писателя P/01.1 «Время в строке» (число JSON, дробь не длиннее
               трёх знаков) тем же округлением; запись, которую принял только читатель (строка, дробь длиннее), не
               переносится как есть; совпадение (subject, cap, scope, until) и by — после округления (C08-UNTIL-REWRITE-01)
    by:        имя, доказанное сторожевой при записи; строка, совпавшая по (subject, cap, scope, until) с прежней, при
               записи строки целиком сохраняет свой by, новая — имя записавшего; совпадение — и по sub
  rewrite:     переписывая документ внутри процесса (удаление человека, снятие строк роли, сверка), строку lines не по форме процесс
               переносит байт в байт, а не теряет; целая запись администратора (PUT) заменяет документ присланным (ADR-0098 §2)
  writer:      процесс domain — по двери Н2 консоли домена (глава 8.0 Н1.8; CAS по прочитанной версии) и снятием строк человека
               при удалении
  revision:    рядом с doc, не внутри: глава 8.0 Н1.9 «Версии», +1 на каждую запись строки; агент несёт только doc, форма копии прежняя
domain/grants/domain: гранты двери домена (консоль домена и процесс domain); ни один агент их не несёт. Полей sub нет, области folder: нет,
               строк ролей нет — 400 bad line; исключение одно — строка управляющего {subject: role:<R>, cap: admin, scope: *, until},
               R ≠ admin (Н1.3в «управляющий»; ADR-0097 §1, ADR-0098 §2, ADR-0100 §3)
last_admin:    доказанный администратор (ADR-0100 §2) — человек, у которого: строка domain/users читается; disabled = false; expires = 0;
               имени нет в domain/disabled; метки domain/deleting/<имя> нет; есть бессрочное (until = 0) назначение admin — прямо или
               через читаемую группу — либо прямая строка {cap: admin, scope: *, until: 0} в domain/grants/domain. Нечитаемая
               domain/roles/admin — администраторов по роли нет. Только бессрочные: администратор со сроком учётной записи или
               назначения не считается, иначе домен запирался бы сам, по истечении
               проверка двери — после каждой правки, которая может убрать доказанного администратора: человек (disabled, expires,
               DELETE), группа (members, DELETE), роль admin (assigned), domain/grants/domain; нет ни одного — 409 last admin, ничего не
               записано; дверь пакета судит итоговое состояние пакета; нечитаемая строка человека (Н1.1 unreadable) — «есть» для
               сверки грантов, но админом не считается: войти под ней нельзя (Н1.2 check — 503) (C08-LAST-ADMIN-UNREADABLE-01)
               стражи доказательства: запись, прошедшая проверку, несёт в пакете P/01.1 (op: batch, guards) стражей строк, доказывающих
               хотя бы одного оставшегося администратора: его domain/users; domain/disabled; отсутствие domain/deleting/<имя>
               (index ""); domain/roles/admin и строку группы, через которую идёт назначение, либо domain/grants/domain для прямой
               строки; записываемая строка стражем не идёт (её условие — cas). Конфликт стража или cas — вся проверка с начала по
               свежему чтению, не больше GUARD_RETRIES; исчерпано — 503 {error: "unavailable"}
               без администратора: доказанных может не остаться после восстановления (P/08.8 Н1.8) или аномалии; домен работает, журнал
               domain.no_admin раз в проход; путь назад — команда grant-admin (Н1.9)
GUARD_RETRIES: 3
carry:         ответ держателя агенту (глава 8.3 Н1.5) несёт в sealed поля grants и roles (форма — договор конвертов домена «Содержимое
               sealed»; разбор ревью стадии A 8–10, № 12): grants — строка domain/grants/<член> без строк, чей subject в domain/disabled
               (ADR-0051); roles — таблица этого члена, Н1.3б. Строки нет: у роли admin есть действующие назначения — grants {doc: {lines: []}},
               иначе поля нет. Строка не читается, сборка не сошлась или таблица сверх предела — не «нет»: в sealed вместо полей идёт held: ["grants", "roles"], «не послано, копии не
               трогать»; копия стареет по шагу 4 договора права. Отсутствие поля без held по-прежнему значит «строки нет». roles идёт всегда вместе с grants и только с ним
# member_copy, holder_copy — копия domain/grants {doc, as_of} у члена и у кластера держателя: пишет агент из ответа своего
# держателя — P/09.1 Н1.4 member_copy, holder_copy; у кластера держателя до первого ответа
# агенту строки нет — прав нет, вход — аварийный (Н1.6)
GRANT_LIFETIME: 86400      # с — копия члена старше as_of + GRANT_LIFETIME не даёт прав
unreadable:    строка, которая не читается, прав не даёт; строка lines, которая не по форме, — у прямой группы пропускается и считается
               диагностикой, остальные действуют; разбор такой строки — в две ступени: субъект прочёлся как role:R — неполна группа R (если
               прочёлся и sub — только в этой sub), субъект не прочёлся — неполны все группы ролей документа; признак доходит до may
               (вход unread договора права; ADR-0099 §2)
```

Азбука меток — [договор азбуки меток](../../common/contracts/labels.md); грамматика идентификатора —

конверты — [договор конвертов домена](../../common/contracts/domain-envelopes.md) «Содержимое `sealed`».

### Н1.3а Группы и роли (ADR-0098)

```yaml
  name:        имя — договор имени человека; не по форме — 400 bad name. Пространство имён своё: группа может называться как человек или
               роль, в строки грантов группа не входит

               person раньше group; until — как until строки гранта; person — человек домена, group — группа домена, иначе 400 unknown member
    at:        когда элемент начал действовать: совпавший по (вид, имя) с действующим прежним сохраняет at, иначе время записи; телом двери не задаётся
  # права роли — строки grants с subject role:<имя> в domain/grants/<кластер>: форма, cap, sub, scope, until, by — как у строки человека
GROUP_TITLE_MAX: 200       # знаков; ROLE title — то же
COMMENT_MAX:   2000        # знаков
unreadable:    строка группы или роли, которая не читается, прав через себя не даёт, ссылки в ней «есть»: свободу имени она не доказывает (Н3)
roles_now:     роль R действует у человека u, если в assigned роли есть {person: u, until} или {group: G, until} с u в members группы G,
               и until = 0 или now < until. Срок строки role:R и срок назначения действуют оба. Одна роль у человека дважды — более поздний
               until (0 — позже всех). Назначения действуют по всему домену
```

### Н1.3б Таблица ролей члена (ADR-0098 §4)

```yaml
table:         {doc_sha256, groups: {<группа>: [<человек>…]}, assigned: {<роль>: [{person|group, until}…]}, admin_at: {<человек>: <at>}}
  assigned:    только роли, у которых есть строки в domain/grants/<член>, и всегда admin; элементы — как assigned строки роли, без at
  groups:      только группы из assigned этих ролей; члены — как members строки группы
  admin_at:    момент назначения admin каждому человеку с действующим назначением (Н1.3в «токены»): значение пути с наибольшим until (0 — наибольший), при равных — наименьшее
               из значений путей; значение прямого пути — at элемента, пути через группу — наибольшее из at элемента и joined человека
  doc_sha256:  hex SHA-256 UTF-8 текста doc поля grants этого ответа, после фильтра carry (без строк выключенных): отпечаток того, что поехало к члену
  filter:      без людей из domain/disabled (ни в groups, ни в assigned, ни в admin_at); нечитаемая роль в таблицу не идёт, нечитаемая группа
               ролей своим людям не даёт (сужение)
ROLES_TABLE_MAX: 262144    # байт JCS-текста таблицы одного члена; назначения admin (и группы только из них) в счёт не идут (ADR-0100 §1), их держит ADMIN_TABLE_MAX (Н1.3в)
limit:         держатель проверяет предел до приёма правки ролей, групп, людей и domain/grants/<член>: превышение — 409 roles table too large,
               ничего не записано; превышен всё же (восстановление) — этому члену held (carry), журнал domain.roles.too_large {member} раз в проход
assemble:      согласованным чтением: держатель читает строки-источники члена (domain/grants/<член>, роли с его строками, роль admin, группы из их
               assigned, domain/disabled), собирает doc и таблицу, затем перечитывает версии источников. Совпали — пара согласована. Нет —
               повтор, не больше трёх; затем этому члену в этом проходе held (carry), журнал domain.roles.unsettled {member}
               раз в проход. Хранимой строки «таблица» у держателя нет
roles_at_holder: вход roles функции may у процесса domain и консоли домена — из строк ролей и групп держателя, as_of = null; at — правило admin_at, у прочих ролей 0; нечитаемая
               domain/roles/admin или группа из её assigned — roles = "unreadable" (шаг 7б: 503, если прямые строки не разрешили)
```

### Н1.3в Встроенная роль `admin` и управляющий пользователями (ADR-0100)

Слова: *действующее назначение `admin`* — элемент `assigned` роли `admin` напрямую или через группу с `until = 0` или `now < until`;
*действующая прямая строка* — `{cap: admin, scope: *}` в `domain/grants/domain` с `until = 0` или `now < until`; *администратор
домена* — человек с действующим назначением `admin` или с действующей прямой строкой.

```yaml

               строка гранта subject role:admin в любом документе — 400 bad line: прав строками у роли нет, ослабить её нечем

ADMIN_TABLE_MAX: 131072    # байт JCS-текста части таблицы про admin: assigned.admin, группы из него с членами, admin_at, без фильтра disabled: верхняя граница, поэтому
               # включение человека предела не обходит; проверка на записи, а не на доставке:
               # PUT /domain/roles/admin и правка группы с действующим назначением admin сверх предела — 409 admin table too large. С ROLES_TABLE_MAX

               установки её не пишут
manager:       строка роли одной формы в domain/grants/domain: {subject: role:<R>, cap: admin, scope: *, until} — без sub, без folder:, R ≠ admin
               gives:  «управляющий пользователями»: двери людей, групп, ролей, чтение грантов и PUT /domain/grants/<кластер>, контактные поля людей.

target:        статус цели «admin only» — по исходным строкам (domain/roles/admin, группы из её assigned, domain/grants/domain), а не по

               читаются, и ни одна не даёт), — разрешено в пределах роли; иначе — 503 unavailable, ничего не записано. Запись несёт стражей

batch_diff:    дверь пакета применяет перечень к каждой строке, которую пакет меняет: цель защищена до пакета или станет защищённой после него;
```

### Н1.5 Проверка у процесса `domain`

Из М11/9 Н1.5 «Сторожевая с грантами» — строка `domain`, сторона процесса `domain` (проверка у дверей процесса; `note`
id-map М11/9-13: «проверка — 8.4»). Строки `cluster`, `session`, `body_unit`, `agent` — консоль кластера (поздний слой
урока P/06; [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Сторожевая», [договор
права](../../common/contracts/may.md)); сторожевая консоли домена по той же строке `domain` — [урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.5 (P/10-13); строка
`loopback` — [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.8.

Строка `domain` (право у дверей `/domain/*` консоли домена и процесса `domain`) — [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Права по телу»
(перенесена без изменения поведения; догадка стадии C GP-G05, решение «Архитектора» 2026-10-23).

Личность у дверей процесса — токен (функция `token` [договора токена домена](../../common/contracts/domain-token.md)
«Проверка», `expect {kind: person, cluster: null}` — разбор ревью стадии B 8–10, № 22: М-2; Н3 «дверь людей» шаг 2, «гранты» шаг 1); без токена или не прошёл — 401, `may` — `deny` —
403, форма `{error: denied, detail}` ([P/06.3](../../06-console/spec/06.3-console.norms.md), Н4 `denied`). Проверить нечем —
503 `{error: "unavailable"}`, не 401 и не 403: строка `domain/keys` есть, но не читается (проверить токен нечем), токен —
`no_revocations` (`domain/revoked` есть, но не читается), строка `domain/grants/domain` или вход `disabled` функции `may` —
`domain/disabled` — есть, но не читается (В7 п. 3, строки 32, 33; правило «Нечитаемая строка» договора сторожевой и передачи; 401/403 — только «проверено — нельзя»; решение «Архитектора» 2026-10-28), а также выход `unavailable` функции `may` (Н1.3б `roles_at_holder`).

Группа строки управляющего (Н1.3в `manager`) в `may` считается только у дверей `gives`; дверь `denies` при действующем только ей праве — 403 `{error: "admin only"}`, а не `denied`.

```yaml
           domain/grants/domain ({lines: []}), если его нет; прямой строки домена не пишет (ADR-0100 §5). Люди есть — отказ, код ≠ 0
           пакет записан целиком или не записан: повтор после обрыва (люди ещё пусты) доводит; строка человека есть (в том числе
           нечитаемая) — люди не пусты, отказ;
           пароль — stdin целиком как UTF-8 без одного конечного LF или CRLF (прочие пробелы и знаки — часть пароля); не
           UTF-8 — отказ, код ≠ 0 (C08-FIRST-ADMIN-01)
           имя — по Н1.1 (форма), проверок индексов имён (глава 8.5 Н1.7 checks) у команды нет: она идёт при установке, до
           первого прохода, индексов ещё нет и пустыми они не считаются; позже ключ индекса, совпавший с именем человека, —
           правило reverse главы 8.5 Н1.7 (C08-FIRST-ADMIN-02)
grant_admin: команда держателя domain grant-admin <имя> (через admin.sock держателя, как first-admin): только при нуле доказанных
           администраторов (Н1.3 last_admin), иначе отказ, код ≠ 0; человек есть (строка читается) и метки domain/deleting/<имя> нет, иначе отказ, код ≠ 0; одним пакетом назначает
           роль admin бессрочно ({person: <имя>, until: 0, at: now}; строки роли нет или она нечитаема — пишет её заново) и снимает с человека
           disabled, expires и имя в domain/disabled; журнал domain.admin.granted {name}
member:    имя domain — не имя члена: приём члена (глава 8.3 Н3 «принять члена») — 400 «domain is the name of the domain's own grants»
```

Передачу (`pass`, сторона консоли домена) нормирует урок P/10 (Н1.3а, P/10-05); здесь — что передаётся и что процесс проверяет
сам (Н1.5).

| PUT `/domain/grants/<кластер>` `{lines: [{subject, cap, sub?, scope, until?}]}` | консоль домена → `domain` | admin; `domain` — администратору домена | 200 `{cluster, lines, revision}` после CAS, `ETag`; `until` нет — 0 | 400 bad line (форма, повтор, имя); 400 grant too wide; 400 unknown subject; 403 admin only; 409 being deleted; 409 last admin; 409 roles table too large; 409 «the grants kept changing; look again» после трёх конфликтов CAS (`refused`); 401/403 — Н1.5; 413 too large; 503 names unknown; 503 standby (глава 8.10) |
| GET `/domain/break-glass` | `domain` | view; управляющему — 403 admin only | 200 `{clusters: {<кластер>: {set_at, revision, index}}}`; строка нечитаема — ключ кластера без полей, `{}` (C08-BREAK-GLASS-UNREAD-KEY-01) | 401/403 |
| PUT `/domain/break-glass/<кластер>` `{password}` | `domain` | admin домена, не управляющий | 200 `{cluster, set: true, revision}`, `ETag` | 400 bad body, bad password, bad name; 401/403 — Н1.5, 403 admin only; 412 `revision moved`; 413 too large; 503 standby (глава 8.10) |
| POST `/domain/revoke` `{token}` | `domain` | — | 200 `{revoked}` | 400 bad body; 401 слово `token`; 413 too large; 503 standby (глава 8.10); 503 unavailable — проверить токен нечем: нечитаемая `domain/keys`, `no_revocations` (Н1.2 revoke, Н1.5) |

**Группы и роли.** Право — по `domain/grants/domain`, как у дверей людей: чтение — `view`, запись — `admin`; строка `manager` (Н1.3в) им служит. `members` и
`assigned` пишутся целиком, CAS по прочитанной версии и стражи ссылок (Н3), три повтора. `assigned` телом — элементы без `at`.

**Пакетная дверь** `POST /domain/batch` (ADR-0098 §6, ADR-0094 доп. (12) пп. 4, 9): люди, группы, роли и гранты одного снимка — одна запись
P/01.1 `op: batch` по CAS всех затронутых строк; `last_admin` судится по итоговому состоянию: нынешние строки с разницей пакета, а не по шагам.

```yaml
body:      {writes: [{kind: user | group | role | grants, op: put | delete, name, cas, fields?}]}
  name:    имя человека, группы, роли или кластера по грамматике своей семьи
  cas:     индекс хранилища, который дал GET этой строки (index элемента списка; у grants — versions ответа GET /domain/grants, P/10 Н1.2д); "" — создание; обязателен
  fields:  у put — поля тела соответствующей двери PUT или POST (без name), у grants — {lines}; у delete — нет
delete:    op: delete у user, group, role несёт каскад Н3 в том же пакете: снятие из members и assigned, строки грантов; метка domain/deleting не ставится, пакет атомарен; строки каскада идут в BATCH_WRITES
order:     те же проверки, что у одиночных дверей, над итоговым состоянием пакета: форма → права и Н1.3в batch_diff → ссылки и имена → last_admin →
           ROLES_TABLE_MAX, ADMIN_ASSIGNED_MAX, ADMIN_TABLE_MAX → запись; обрабатывает порядок записей, ссылки внутри пакета судятся по состоянию после него
unchanged: строка, которую запись не меняет, в пакет не пишется, её cas идёт стражем; written — число изменённых строк (ADR-0100 §3 «строки снимка»); изменённых нет — записи нет,
           cas сверяются чтением: разошёлся — 412 conflict, иначе 200 {written: 0}
limit:     строк, которые пакет пишет, с каскадом и строкой заявки ≤ BATCH_WRITES (P/01.1): с ключом изменённых остаётся 63; элементы writes без изменений в этот счёт не идут, их держит вес; неизменённые строки пакет нести не обязан: вызывающий шлёт снимок или разницу по прочитанному; всё тело ≤ -max-body хранилища; числа стражей предел не держит; сверх — 413 {error: "batch too large"}, ничего не записано
repeat:    Idempotency-Key необязателен (глава 8.0 Н1.9): с ключом повтор отдаёт прежний итог; без ключа у каждой записи свой cas, поэтому повтор после потери ответа —
           412 conflict без записи; вызывающий перечитывает строки и сверяет: 412 здесь значит «снимок устарел», а не «ничего не изменилось»
holder:    запись идёт под стражем domain/signer-turn; смена держателя — 503 standby, вызывающий перечитывает строки; при передаче дверь заморожена (P/08.8 Н1.7)
```

`ETag`, `If-Match` и `Idempotency-Key` этих дверей записи — [глава 8.0](08.0-domain.norms.md) Н1.9. Индекс в перечнях — из чтения этой строки, не из перечисления ([P/06.1](../../06-console/spec/06.1-console.norms.md) Н2 «Версии»).

Строки М11/9 Н2 других дверей: `GET /domain/grants` (консоль домена, view) — урок P/10 (Н1.2д); `POST /session/break-glass` и
`GET /domain/keys` (консоль кластера) — [OpenAPI урока 6](../../06-console/spec/06-console.api.openapi.yaml) (поздний слой
урока P/06).

Журнал: `domain.user.created`, `.password`, `.disabled`, `.deleted {grants_changed}` — процесс `domain`; `domain.group.created`, `.changed {added, removed}`,
`.deleted`; тревога `domain.rights_via_backend {by, via, what}` — журнал тревог процесса `domain` `audit.alarms/domain` на сервере держателя; администраторам домена доходит как всякая строка класса alarm: страница отчёта агента держателя (P/09.1 Н1.10) и `GET /domain/alarms` (P/10 Н1.8) (Н1.3в `via_backend`); `domain.role.created`, `.assigned {added, removed}`, `.deleted {grants_changed}`; `domain.user.expiry_kept {name}`, `domain.no_admin`, `domain.admin.granted {name}`; `domain.grants.changed
{cluster, added, removed, by}` — процесс `domain`, `added` и `removed` — массивы объектов `{subject, cap, scope, until}` в
порядке строк Н1.3 (решение «Архитектора» по сверке М11, P17); `domain.break_glass.set {cluster, by}` — процесс `domain`. Паролей и хешей в
строках журнала нет.

## Н3 Проход

### дверь людей (процесс domain) — по порядку

```
1. тело больше 1 МиБ                                                → 413 too large
2. токен (token договора токена домена, expect {kind: person, cluster: null}) и may по domain/grants/domain → 401 / 403 {error: denied}; проверить нечем — 503 unavailable (Н1.5)
2а. заголовки и память повторов (глава 8.0 Н1.9; тело не JSON-объект — 400 bad body здесь) → 400 / 409 / 422 / прежний ответ
3. тело не по форме двери                                           → 400 bad body
4. имя не по Н1.1 (POST)                                            → 400 bad name
5. пароль короче PASSWORD_MIN (GLASS_MIN у break-glass)              → 400 bad password
5а. POST: стоит метка domain/deleting/<имя>                          → 409 exists (метка — раньше проверок имён;
    добавлено сверкой М11, P3)
5б. управляющий (Н1.3в): PUT, DELETE — статус цели target           → 403 admin only / 503 unavailable
6. проверки имён (глава 8.5 Н1.7)                                   → 409 name taken / 503 names unknown
7. POST: человек есть или стоит метка domain/deleting/<имя> — 409 exists; PUT, DELETE: нет — 404 no such person; строка человека
   есть, но не читается — PUT: 503 unavailable, не 404 (правке нужно прочитанное содержимое; неизвестное — не «нет»);
   DELETE удаляет и нечитаемую строку — способ убрать испорченную (сц. 13 приёмки 8.4; C08-PUT-USER-UNREADABLE-01, -02)
7а. POST: в domain/grants/* есть строка с subject = <имя> (грант прежнего субъекта без имени, сверка его ещё не сняла) или имя стоит в
    members группы либо assigned роли (ADR-0098 §5) — 409 exists: имя свободно только после снятия; строка грантов, группы или роли не
    читается — 503 unavailable (П1) (C08-GRANTS-ORPHAN-01)
7б. PUT, DELETE человека, PUT break-glass: If-Match не равен версии строки (глава 8.0 Н1.9; у break-glass строки нет — revision 0) → 412 revision moved
8. last_admin (Н1.3); expires ≠ 0 у последнего бессрочного — тоже     → 409 last admin
8а. ROLES_TABLE_MAX (Н1.3б)                                          → 409 roles table too large
9. записать строку (CAS по прочитанной версии, revision + 1, стражи Н1.3 last_admin и Н1.3в target); disabled или expires — затем domain/disabled; DELETE: записать метку
   domain/deleting/<имя> → удалить строку человека → снять строки subject = <имя> во всех domain/grants/* (CAS) и имя из members всех групп и assigned всех ролей (CAS) →
   удалить метку; строка группы или роли не читается — 503, метка остаётся, доводит сверка; ответ — после снятия метки (журнал cammeta-go, М11-09 № 1; решение «Архитектора»); конфликт CAS строки
   грантов — перечитать её и повторить не больше трёх раз (как шаг 6 «гранты»); исчерпано — 503 {error: "unavailable",
   detail: "the grants kept changing; the deletion is finished by the next pass"}, метка остаётся, строки грантов
   доводит сверка ниже (разбор ревью стадии A 8–10, № 38)
```

С ключом целевая запись шага 9 (глава 8.0 Н1.9 `write`) — строка человека или аварийной учётки; у `DELETE` — снятие метки: ответ называет `grants_changed`, а метка снимается последней. `domain/disabled` идёт после пакета, как и без ключа: расхождение доводит сверка ниже.

Обрыв шага 9 между строкой человека и `domain/disabled` или строками грантов: вход человеку уже закрыт (строка), а члены
его ещё пускают. Процесс `domain` при старте и каждым проходом главы 8.1 (Н3 «проход держателя») сверяет: `domain/disabled`
— по флагам строк людей; для каждой метки `domain/deleting/<имя>` — снимает строки грантов с subject = `<имя>`, затем
удаляет метку; индексов имён не ждёт; расхождение живёт не дольше прохода. Строку человека сверка не трогает: метка при
ещё читаемой `domain/users/<имя>` (обрыв шага 9 до её удаления, метка записана прямо — сц. 09) — сняты только гранты и
метка, человек остаётся без грантов, удаление доводит повторный `DELETE` (C08-DELETING-USER-ROW-01). «Людей, которых нет» по отсутствию строки не
ищет: субъект индекса имён тоже не человек домена (журнал cammeta-go, М11-09 № 1; решение «Архитектора»).

Субъект без имени (C08-GRANTS-ORPHAN-01; решение «Архитектора» 2026-10-29 по запросу VMS, разбор V/03, вопрос 2). Тем же проходом, после индексов имён прохода (глава 8.5 Н3
«сборка книги»), процесс `domain` снимает строки грантов во всех `domain/grants/*`, чей `subject` не человек домена (строки
`domain/users/<subject>` нет) и не ключ ни одного индекса имён, — только когда все индексы known (глава 8.5 Н1.7; каталог без
книг с `domain.names` — все known и пусты) и перечень людей прочитан: индекс не known, перечень людей или строка индекса не
прочитаны (хранилище не ответило) — сверка этого прохода субъектов без имени не ищет (П1). Строка человека есть, но
нечитаема, — человек есть: его гранты не снимаются. Строка грантов не читается — пропускается, причина в журнал. Снятие —
CAS строки грантов по прочитанной версии; конфликт — перечитать и повторить не больше трёх раз, остаток — следующим
проходом; журнал без значений. Пока строка такого субъекта стоит, имя для `POST /domain/users` занято (шаг 7а двери людей):
новый человек с этим именем грантов прежнего субъекта не получает. Субъекты, которые нормы снимают сами (метка `domain/deleting/`), — как прежде.

Новые виды (ADR-0098 §5). Тем же проходом процесс снимает строки грантов `role:R`, если строки `domain/roles/R` нет; элементы `members` и
`assigned` с человеком, которого нет, и `assigned` с группой, которой нет. Правило прохода прежнее: перечни людей, групп и ролей
прочитаны целиком и успешно — иначе этот проход ничего не ищет (П1); строка есть, но нечитаема, — «есть», ничего не снимается; CAS,
три повтора, остаток — следующим проходом; журнал без значений. **Пока восстановление или перенос домена не завершены, сверка новых
видов ничего не снимает**: пустой перечень после неполного восстановления — не основание.

**Срок** (ADR-0098 §3, ADR-0100 §2). Каждым проходом процесс пишет в `domain/disabled` имена с истёкшим `expires`, кроме случая: после этого не
останется ни одного доказанного администратора (Н1.3) или доказательство неизвестно (нечитаемые строки). Тогда человек остаётся
включённым, журнал `domain.user.expiry_kept {name}` раз в проход. Доказанный администратор бессрочен, поэтому в штатном состоянии
правило не срабатывает: это защита от аномалии.

**Сверка роли `admin`** (ADR-0100 §1). Проход пишет `domain/roles/admin` только при подтверждённом отсутствии строки и непустых `domain/users` (до `first-admin` строку не пишет); нечитаемую строку не
трогает, журнал раз в проход. Создавая её, один раз назначает роль (`until: 0`) каждому человеку с действующей бессрочной прямой строкой;
строку ему оставляет. Нет доказанных администраторов — журнал `domain.no_admin` раз в проход.

### гранты (процесс domain, PUT /domain/grants/<кластер> через консоль домена) — по порядку

```
1. may по domain/grants/domain, admin                               → 401 / 403; проверить нечем — 503 unavailable (Н1.5)
1а. заголовки и память повторов (глава 8.0 Н1.9)                     → 400 / 409 / 422 / прежний ответ
2. кластер не по грамматике члена и не domain                        → 400 bad name
3. lines не по форме Н1.3 (cap, scope, until — число ≥ 0, subject по Н1.1), повтор строки → 400 bad line;
   затем условие: If-Match не равен версии строки (глава 8.0 Н1.9; строки нет — revision 0) → 412 revision moved
3а. новая строка с subject, у которого стоит метка domain/deleting/ → 409 being deleted (метка — раньше проверок имён:
    человек удаляется, индекс о нём не спрашивают; добавлено сверкой М11, P3); у subject role:R — метка domain/deleting/role:R
3б. кластер = domain: строка с sub или folder:, строка role: не формы manager (Н1.3в), none → 400 bad line; строка role:admin в любом документе, none
    у строки не роли, labels: у строки роли → 400 bad line
3в. кластер = domain и запрашивающий — управляющий                   → 403 admin only
4. новая строка role:R — только наличие роли R: нет — 400 unknown subject; проверки индексов имён к ней не относятся, 503 names unknown она не
   получает. Прочие — проверки имён (глава 8.5 Н1.7): шире grant — 400 (grant too wide — только по рангу, none ниже всех); новая строка
   не человека домена и индекс не known — 503; индекс known, а subject не человек и не key — 400 unknown subject
5. кластер = domain и last_admin                                     → 409 last admin
5а. ROLES_TABLE_MAX (Н1.3б), кластер ≠ domain                         → 409 roles table too large
6. записать по CAS: lines по порядку Н1.3, by — доказанное имя, revision + 1; конфликт — перечитать, сверить условие и повторить с шага 4 не больше трёх раз
   (конфликт с DELETE возвращает к шагу 4, и он видит метку удаления)
```

### группы и роли (процесс domain, двери Н2) — по порядку

```
1. may по domain/grants/domain (Н3 «дверь людей» шаги 1–2)            → 401 / 403; проверить нечем — 503 unavailable
1а. заголовки и память повторов (глава 8.0 Н1.9 order)                → 400; прежний ответ; 409 in flight; 422 key reused
2. тело не по форме → 400 bad body; имя → 400 bad name; admin: title, comment, DELETE → 409 builtin; POST с именем admin → 409 exists
3. управляющий: PUT /domain/roles/admin; состав группы с действующим назначением admin; DELETE такой группы; DELETE роли со строкой в
   domain/grants/domain → 403 admin only; статус не установить — 503 unavailable (Н1.3в target)
4. POST: строка есть или имя ещё стоит в assigned (группа), стоит метка или строка role:<имя> (роль) → 409 exists; строка группы или роли
   не читается → 503 unavailable; PUT, DELETE: нет — 404 no such group / no such role
4а. PUT, DELETE: If-Match не равен версии строки (глава 8.0 Н1.9)      → 412 revision moved
5. members и assigned: каждый человек и группа есть, иначе 400 unknown member (метка удаления человека — 409 being deleted); стражи ссылок на
   версии их строк; assigned роли admin сверх ADMIN_ASSIGNED_MAX → 409 too many admins
6. Н1.3в password, только добавленные элементы: pw_by не он сам и не администратор домена → 409 password set by a non-admin
7. last_admin (правка группы и роли admin) → 409 last admin; ROLES_TABLE_MAX → 409 roles table too large; ADMIN_TABLE_MAX (роль admin, группа с действующим назначением admin) → 409 admin table too large
8. записать одним пакетом (cas строки, revision + 1, стражи ссылок, стражи Н1.3 и Н1.3в, страж domain/signer-turn); тело тяжелее -max-body хранилища → 413 too large; конфликт — перечитать и с шага 4, условие снова, не больше GUARD_RETRIES;
   исчерпано — 503 unavailable
```

DELETE группы: строка удаляется, затем `{group: <имя>}` снимается из `assigned` всех ролей (CAS, три повтора); обрыв доводит сверка
субъектов. DELETE роли: метка `domain/deleting/role:<имя>` → строка роли → строки `subject = role:<имя>` во всех `domain/grants/*`
(CAS, три повтора) → метка; пока стоит метка или строка `role:<имя>` — `POST` роли с этим именем 409 `exists`. Сверка по метке `role:<имя>`
удаляет строку роли, если она осталась, снимает её строки грантов и удаляет метку, как по метке человека; метку такой формы мусором не считает.

**Гонки.** Человек выключен, а его токен жив: у кластера держателя отказ сразу (`domain/disabled`), у члена — со следующим
ответом агенту (ADR-0051). Отзыв гранта у члена без связи — не позже `GRANT_LIFETIME` от `as_of` копии (Н1.3); выданный токен — `TOKEN_LIFETIME +
`TOKEN_SKEW` от выдачи. Снятие назначения, выход из группы, правка строк роли, выключение по сроку доходят до члена со следующим ответом агенту; у члена без связи —
не позже `GRANT_LIFETIME` от `as_of`: срок учётной записи у него действует до `GRANT_LIFETIME` позже `expires` (ADR-0098 §4). Гранты пишет
один процесс `domain` — CAS строки. Одно имя создаётся человеком и вкладом в двух кластерах одновременно — индекс показывает
обоих, доставка элемента не идёт (глава 8.5 Н1.7 reverse), распределённой блокировки нет.

Проверяются чтением, с причиной:
- равное время ответа неизвестному, выключенному и неверному (Н1.2 `check`) — стенд не меряет время ответа;
- адрес клиента от консоли домена, а не её TCP-пир
  (Н1.10 `address`, `X-W2C-Client`) и PBKDF2 без общего замка (Н1.2 `check`) — стенд их не различает (сверка М11, P16, P21);
- обрыв `DELETE /domain/users` после строки человека (Н3 «дверь людей» шаг 9 и сверка) — стенд не прерывает `DELETE`
  (решение владельца ADR-0083 доп. (9)); три
  конфликта CAS — 503 `unavailable` (разбор ревью стадии A 8–10, № 38) — стенд не создаёт конфликт;
- правка `PUT` нечитаемой строки человека (Н1.1 `unreadable` называет вход, `disabled` и `DELETE`; исход правки — нет);
- порядок по числу (Н1.3 `lines`), форма `added`/`removed` журнала (P17) — сверка М11, P9, P17 (`until` по значению — сц. 16);
  журнал приёмка не сравнивает (кластер в пути без %-декодирования, P13, — сц. 15);
- отказ приёма члена с именем `domain` (Н1.9 `member`) — стенд не ставит кластер с именем `domain`;
- первый администратор (Н1.9 `first`) — подготовкой стенда (`@admin`), не шагом;
- два параллельных снятия из разных групп — одно 200, другое 409 (Н1.3 стражи доказательства) — стенд не создаёт гонку; условие — стражи, модель ревью ADR-0100;
- сборка таблицы при одновременной правке (Н1.3б `assemble`), обрыв `DELETE` роли и доведение меткой `role:` (Н3), сверка новых видов при непрочитанном перечне, сверка роли `admin` у прежней установки, `expiry_kept` при нуле доказанных, команда `grant-admin` — стенд не прерывает двери, не задаёт прежнюю установку и не вызывает команду; ревью — чтением (ADR-0083 доп. (9));
- тревога `domain.rights_via_backend` и `X-W2C-Via-Worker` — чтением: до тестового воркера стенда;
- токен старше `at` назначения `admin` — вектор `may-101`, на стенде нет директивы времени токена;
- `ROLES_TABLE_MAX`, `ADMIN_ASSIGNED_MAX`, `ADMIN_TABLE_MAX` — стенд не строит таблицу такого веса; ревью — чтением;
- пакет больше `BATCH_WRITES` элементов с малым числом изменений — чтением: стенду пришлось бы завести и связать индексы 65 строк;
- стражи правки большой группы сверх `BATCH_GUARDS` — стенд не заводит сотню людей: граница роли `domain` — сц. 14 [приёмки главы 1.2](../../01-store/acceptance/2/README.md).
- обрыв `DELETE /domain/users` с ключом (глава 8.0 Н1.9) — стенд не прерывает `DELETE`, как выше.

## Решает реализация

1. **команду `may`** — шаблон с `{input}` (векторы `common/vectors/may`); **команду `domain first-admin`** — для директивы
   `@admin` словаря «Стенда домена» общего README приёмки;
2. **как раннер входит человеком** — дверь `signer` и директива `@person` словаря «Стенда домена»;
3. **библиотеку PBKDF2** и сравнение постоянного времени — лишь бы форма Н1.1 и неразличимость Н1.2 сохранялись.
