# P/08.4 — Люди и гранты: нормы

Канон главы 8.4 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/4/README.md). Здесь — люди домена у держателя: строка человека, вход и токен человека, отзыв;
строки грантов и последний администратор; право по грантам — [договор права](../../common/contracts/may.md) (функция
`may`, владелец — эта глава) ссылкой; проверка личности и гранта у дверей процесса `domain`; аварийная учётка кластера у
держателя (строка, дверь `PUT`, `GLASS_MIN`, форма `pwhash_secret`); двери людей и первый администратор; предел попыток
`POST /api/login`. Глава читается после глав 8.0, 8.2, 8.3 и 8.1 ([записка модуля](../../module-design.md), «Порядок
чтения»).

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из
М11/9 — Н1.1, Н1.2; Н1.3 без строк `member_copy`, `holder_copy`
(копия члена — агент, [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4; `note` id-map М11/9-04); Н1.4 (указатель на договор права); строка `domain` Н1.5 (сторона
процесса `domain`); Н1.6 — строка `domain/break-glass/<кластер>`, `writer`, `GLASS_MIN`, `carry` (разбор ревью стадии
A 8–10, № 22); Н1.9; Н1.10; строки Н2 дверей процесса и журнал; Н3 «дверь людей», «гранты», «Гонки»; строки Н4 процесса;

P/06; контракт — [OpenAPI урока 6](../../06-console/spec/06-console.api.openapi.yaml), [договор сторожевой и

[P/09](../../09-agent/README.md). Ссылка «P/0N[.K]» — урок или глава модуля; «М11/N» — урок-источник М11 (снят переносами уроков 8–10; новые адреса — id-map);

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов)

## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`domain/users/<имя>` — `at`; строка гранта — `until` (`0` — без срока); `domain/break-glass/<кластер>` — `set_at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/users/<имя>`, `domain/deleting/<имя>`, `domain/disabled`, `domain/grants/<кластер>`, `domain/break-glass/<кластер>`;
- пишет: `domain/revoked` (put);
- читает: `domain/keys`, `domain/revoked`, `domain/signer`, `domain/signer-turn`, `domain/names/<sub>/<книга>`.

Токен человека и отзыв — [договор токена домена](../../common/contracts/domain-token.md) и [договор набора ключей
домена](../../common/contracts/keys.md) «Отзывы» (строки `domain/keys`, `domain/revoked` — [глава 8.2](08.2-domain.norms.md)
Н1.6); ключ токенов держателя — строка `domain/signer` (глава 8.2 Н1.3); страж записей — `domain/signer-turn` ([глава
8.10](08.10-domain.norms.md) Н1.7); индексы имён для проверок дверей людей и грантов — `domain/names/<sub>/<книга>`
([глава 8.5](08.5-domain.norms.md) Н1.7). Копию `domain/grants` `{doc, as_of}` у члена пишет агент ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4 `member_copy`); форма
`doc` у неё и у строки держателя — одна (`common.grants_doc`, решение «Архитектора» 2026-10-20 по планам 8–10, п. 3).

Общее Н1 глав 8.0–8.3, 8.5–8.7 действует ([P/08.2 Н1](08.2-domain.norms.md) «Общее для всех форм главы»; пересылка —
[договор пересылки](../../common/contracts/forwarding.md)). Люди живут у держателя; токен человека называет субъект и ничего больше ([договор токена
домена](../../common/contracts/domain-token.md) «Токен», `kind: person`, без `aud`). Что человеку можно, решает каждый
кластер по своим грантам, которые несёт агент; проверка — локальное чтение без связи с доменом. Люди с паролями и
аварийные пароли — операции процесса `domain` (подписант, ADR-0032), он проверяет каждую сам; гранты пишет он же ([глава
8.0](08.0-domain.norms.md) Н1.8: консоль домена правку передаёт). Решение «Архитектора» по вопросам М11/9.

### Н1.1 Человек

```yaml
domain/users/<имя>:  {name, how, pwhash_secret, disabled, at, by}      # у держателя; писатель — процесс domain
  name:        имя человека — 1–64 символа без пробельных (свойство White_Space Unicode 15.0.0: U+0009–U+000D, U+0020,
               U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000; решение «Архитектора» 2026-10-20 по вопросам сборки урока 8, п. 3),
               управляющих (U+0000–U+001F, U+007F) и : | ( ) " /;
               не ровно break-glass (имя аварийной сессии — break-glass(<who>), скобки и так запрещены) — 400 bad name;
               не субъект индекса имён (глава 8.5 Н1.7)
  how:         "password"                       # иных способов входа урок не нормирует
  pwhash_secret: форма, хэш и проверка — договор хэша пароля common/contracts/password-hash.md (перенесено; догадка стадии C GP-G06, решение «Архитектора» 2026-10-23);
               секрет по суффиксу (P/02.1 Н1.3а), запечатан кольцом держателя
  disabled:    true | false
  at, by:      стенные секунды и имя человека последней правки (доказанное сторожевой)
PASSWORD_MIN:  10          # символов
domain/disabled: {names: <текст JCS массива имён>}  # имена выключенных по возрастанию в байтах UTF-8, без повторов; нет —
               # "[]"; массив, не строка через «,»: имя может нести запятую (решение «Архитектора» по R41-11); писатель —
               # процесс domain при каждой правке disabled; секретов нет (ADR-0051)
delete:        удалить строку человека и снять его строки во всех domain/grants/* (Н1.3) — одной правкой на строку грантов;
               под меткой удаления ниже (Н3 «дверь людей» шаг 9)
domain/deleting/<имя>: {}    # метка удаления человека у держателя; писатель — процесс domain под стражем domain/signer-turn;
               # стоит с начала DELETE до снятия всех строк грантов с subject = <имя>; пока стоит — имя занято:
               # POST /domain/users — 409 exists, новая строка гранта с этим subject — 409 being deleted; сверка при
               # старте и каждым проходом главы 8.1 снимает по ней строки грантов и удаляет метку (журнал cammeta-go, М11-09 № 1; решение «Архитектора»)
               # метка — любая строка под domain/deleting/, что бы ни лежало в items; <имя> не по грамматике Н1.1 —
               # сверка удаляет метку с журналом domain.deleting.dropped {key, reason: "not a name"}, строк грантов не
               # ищет (subject таким не бывает); проход из-за неё не стоит (добавлено сверкой М11, P1)
unreadable:    строка человека, которая не читается (не по форме Н1.1 или name ≠ <имя> ключа), — пропускается и считается
               (диагностика процесса), остальные служат; domain/disabled она не снимает: имя её ключа остаётся там, если
               было; DELETE /domain/users/<имя> удаляет и её — снятие строк грантов и метка как у читаемой (добавлено
               сверкой М11, P2: иначе испорченная строка вернула бы выключенному старые токены)
```

### Н1.2 Вход, токен человека, отзыв

```yaml
door:          POST /api/login {user, password} у процесса domain; тело ≤ LOGIN_BODY (больше — 413 {error: "too large",
               detail}); оба поля — строки (иначе 400 {error: "bad body", detail}); дверь cookie не ставит и не читает
via:           страница ходит к своей консоли: POST /api/login — открытая строка списка дверей домена договора пересылки
               и open_routes договора сторожевой (P/06.3 Н1.3), консоль домена передаёт её процессу (глава 8.0 Н1.8);
               CORS нет — другой origin страница не зовёт
check:         предел Н1.10 → человек есть, не disabled, пароль сверился (сравнение постоянного времени) → токен;
               сверка PBKDF2 (и у аварийного входа Н1.6) не держит общего замка процесса: прочие двери её не ждут
               (добавлено сверкой М11, P21);
               нет человека или disabled — сверка по фиктивному хешу той же стоимости (600000): ответ неизвестному,
               выключенному и неверному неразличим и по коду, и по телу, и по времени
answer:        200 {token, until, user}; иначе 401 {error: "refused", detail: "wrong user or password"} — отказ в счёт
               предела Н1.10
token:         договор токена домена «Токен», строка person (поля токена человека; GP-L01): iat — now, ключ токенов
               держателя (current набора); until = exp
TOKEN_LIFETIME: 900        # с
LOGIN_BODY:    16 KiB
revoke:        POST /domain/revoke {token} — строка списка дверей домена договора пересылки; консоль домена передаёт её
               процессу domain (Н1.9 `pass`); токен проверяется функцией token договора токена домена «Проверка» (не
               прошёл — 401 со словом token); jti и exp добавляются в domain/revoked (глава 8.2 Н1.6; договор набора
               ключей домена «Отзывы») — ответ 200 {revoked: <jti>}; отозвать токен может тот, кто его держит; страница
               зовёт дверь при выходе (P/06.3 Н1.3 DELETE /session — снимает cookie)
login_url:     P/06.3 Н1.3 (LOGIN_URL окружения, умолчание /api/login)
deposed:       смещённый держатель токенов не выдаёт — 409 deposed (глава 8.8 Н1.6)
```

Ссылки блока: список дверей домена и пересылка — [договор пересылки](../../common/contracts/forwarding.md); `open_routes`,
`login_url`, `/session` — [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Сторожевая»
([P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.3); токен и `token` — [договор токена
домена](../../common/contracts/domain-token.md).

### Н1.3 Гранты

```yaml
domain/grants/<кластер>:  {doc: <текст JCS {lines}>}   # у держателя; <кластер> — имя члена по грамматике главы 8.3
                                                       # (членом быть не обязан: гранты готовят до приёма) или domain;
                                                       # в пути двери — байт в байт, %-кодирование не декодируется:
                                                       # m%31 — не имя, 400 bad name (добавлено сверкой М11, P13)
  lines:       [line…] по (subject, cap, scope) в байтах UTF-8, затем until по числу, без повторов; until сравнивается
               по значению: 0 и 0.0 — одна строка, повтор (добавлено сверкой М11, P7, P9)
  line:        {subject, cap, scope, until, by}
    subject:   имя человека (Н1.1) или субъект индекса имён (глава 8.5 Н1.7)
    cap:       view | edit | admin             # view < edit < admin
    scope:     * | unit:<sub>/<id> | labels:<метка>[,<метка>…]   # метки — азбука меток Platform/common/contracts/labels.md, без повторов;
               # <sub> — имя манифеста (P/02.1), <id> — по грамматике идентификатора P/06.1 Н1.3; иначе строка не по форме
               # (у двери — 400 bad line; добавлено сверкой М11, P10)
    until:     0 — без срока; иначе стенные секунды — строка действует, пока now < until; у входа больше трёх знаков
               дроби — округление до тысячных от десятичной записи, половина от нуля (как глава 8.1 Н1.4 round): строка
               хранится и сравнивается округлённой (решение «Архитектора» по сверке М11, P8)
    by:        имя, доказанное сторожевой при записи; строка, совпавшая по (subject, cap, scope, until) с прежней, при
               записи строки целиком сохраняет свой by, новая — имя записавшего
  writer:      процесс domain — по двери Н2 консоли домена (глава 8.0 Н1.8; CAS по прочитанной версии) и снятием строк человека
               при удалении
domain/grants/domain: гранты двери домена (консоль домена и процесс domain); ни один агент их не несёт
last_admin:    правка domain/grants/domain или людей, после которой нет строки {cap: admin, scope: *, until: 0} человека,
               который есть и не disabled, — 409 last admin
carry:         ответ держателя агенту (глава 8.3 Н1.5) несёт в sealed поле grants (форма — договор конвертов домена «Содержимое
               sealed»; разбор ревью стадии A 8–10, № 12) — строка domain/grants/<член>
               без строк, чей subject в domain/disabled (ADR-0051); строки нет — поля нет
# member_copy, holder_copy — копия domain/grants {doc, as_of} у члена и у кластера держателя: пишет агент из ответа своего
# держателя — P/09.1 Н1.4 member_copy, holder_copy; у кластера держателя до первого ответа
# агенту строки нет — прав нет, вход — аварийный (Н1.6)
GRANT_LIFETIME: 86400      # с — копия члена старше as_of + GRANT_LIFETIME не даёт прав
unreadable:    строка, которая не читается, прав не даёт; строка lines, которая не по форме, — пропускается и считается
               диагностикой, остальные действуют
```

Азбука меток — [договор азбуки меток](../../common/contracts/labels.md); грамматика идентификатора —
[P/06.1](../../06-console/spec/06.1-console.norms.md) Н1.3; имя манифеста — [P/02.1](../../02-installer/spec/02.1-installer.norms.md);
конверты — [договор конвертов домена](../../common/contracts/domain-envelopes.md) «Содержимое `sealed`».

Окно отзыва у члена без связи — два предела, раздельно (решение «Архитектора» по R41-13 прогона 41):
- **уже выданный токен** выключенного человека или отозванный — `TOKEN_LIFETIME + TOKEN_SKEW` = 960 с от выдачи;
- **грант**, снятый у держателя, у члена без связи — `GRANT_LIFETIME` (сутки) от `as_of` копии: человек, которого не
  выключили, входит заново и с новым токеном пользуется прежней копией, пока она не стара.

Числа заявлены заранее (М12A/04 шаг 5).

### Н1.5 Проверка у процесса `domain`

Из М11/9 Н1.5 «Сторожевая с грантами» — строка `domain`, сторона процесса `domain` (проверка у дверей процесса; `note`
id-map М11/9-13: «проверка — 8.4»). Строки `cluster`, `session`, `body_unit`, `agent` — консоль кластера (поздний слой
урока P/06; [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Сторожевая», [договор
права](../../common/contracts/may.md)); сторожевая консоли домена по той же строке `domain` — [урок P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.5 (P/10-13); строка
`loopback` — [P/06.3](../../06-console/spec/06.3-console.norms.md) Н1.8.

Строка `domain` (право у дверей `/domain/*` консоли домена и процесса `domain`) — [договор сторожевой и передачи](../../common/contracts/gate-and-pass.md) «Права по телу»
(перенесена без изменения поведения; догадка стадии C GP-G05, решение «Архитектора» 2026-10-23).

Личность у дверей процесса — токен (функция `token` [договора токена домена](../../common/contracts/domain-token.md)
«Проверка», `expect {kind: person, cluster: null}` — разбор ревью стадии B 8–10, № 22: М-2; Н3 «дверь людей» шаг 2, «гранты» шаг 1); без токена или не прошёл — 401, `may` — `deny` —
403, форма `{error: denied, detail}` ([P/06.3](../../06-console/spec/06.3-console.norms.md), Н4 `denied`).

### Н1.6 Аварийная учётка у держателя

Из М11/9 Н1.6 «Аварийный вход» — сторона держателя (разбор ревью стадии A 8–10, № 22; `note` id-map М11/9-08). Дверь
`POST /session/break-glass` по порядку, сверка хеша, сессия `GLASS_SESSION`, потолок `GLASS_SESSIONS_MAX` и журнал
`access.break_glass.*` — консоль кластера (поздний слой урока P/06; контракт — [OpenAPI урока
6](../../06-console/spec/06-console.api.openapi.yaml) `POST /session/break-glass`);
предел попыток её двери — свой счёт по Н1.10.

```yaml
domain/break-glass/<кластер>: {pwhash_secret, set_at}    # у держателя; pwhash_secret — та же форма Н1.1
  writer:      процесс domain по двери PUT /domain/break-glass/<кластер> {password} (admin домена); пароль ≥ GLASS_MIN
GLASS_MIN:     12          # символов
carry:         sealed ответа агенту — поле break_glass (форма — договор конвертов домена «Содержимое sealed»; разбор ревью
```

## Н3 Проход

### дверь людей (процесс domain) — по порядку

```
1. тело больше 1 МиБ                                                → 413 too large
2. токен (token договора токена домена, expect {kind: person, cluster: null}) и may по domain/grants/domain → 401 / 403 {error: denied}
3. тело не по форме двери                                           → 400 bad body
4. имя не по Н1.1 (POST)                                            → 400 bad name
5. пароль короче PASSWORD_MIN (GLASS_MIN у break-glass)              → 400 bad password
5а. POST: стоит метка domain/deleting/<имя>                          → 409 exists (метка — раньше проверок имён;
    добавлено сверкой М11, P3)
6. проверки имён (глава 8.5 Н1.7)                                   → 409 name taken / 503 names unknown
7. POST: человек есть или стоит метка domain/deleting/<имя> — 409 exists; PUT, DELETE: нет — 404 no such person
8. last_admin (Н1.3)                                                → 409 last admin
9. записать строку (CAS по прочитанной версии); disabled — затем domain/disabled; DELETE: записать метку
   domain/deleting/<имя> → удалить строку человека → снять строки subject = <имя> во всех domain/grants/* (CAS) →
   удалить метку; ответ — после снятия метки (журнал cammeta-go, М11-09 № 1; решение «Архитектора»); конфликт CAS строки
   грантов — перечитать её и повторить не больше трёх раз (как шаг 6 «гранты»); исчерпано — 503 {error: "unavailable",
   detail: "the grants kept changing; the deletion is finished by the next pass"}, метка остаётся, строки грантов
   доводит сверка ниже (разбор ревью стадии A 8–10, № 38)
```

Обрыв шага 9 между строкой человека и `domain/disabled` или строками грантов: вход человеку уже закрыт (строка), а члены
его ещё пускают. Процесс `domain` при старте и каждым проходом главы 8.1 (Н3 «проход держателя») сверяет: `domain/disabled`
— по флагам строк людей; для каждой метки `domain/deleting/<имя>` — снимает строки грантов с subject = `<имя>`, затем
удаляет метку; индексов имён не ждёт; расхождение живёт не дольше прохода. «Людей, которых нет» по отсутствию строки не
ищет: субъект индекса имён тоже не человек домена (журнал cammeta-go, М11-09 № 1; решение «Архитектора»).

### гранты (процесс domain, PUT /domain/grants/<кластер> через консоль домена) — по порядку

```
1. may по domain/grants/domain, admin                               → 401 / 403
2. кластер не по грамматике члена и не domain                        → 400 bad name
3. lines не по форме Н1.3 (cap, scope, until — число ≥ 0, subject по Н1.1), повтор строки → 400 bad line
3а. новая строка с subject, у которого стоит метка domain/deleting/ → 409 being deleted (метка — раньше проверок имён:
    человек удаляется, индекс о нём не спрашивают; добавлено сверкой М11, P3)
4. проверки имён (глава 8.5 Н1.7): шире grant — 400; новая строка не человека домена и индекс не known — 503; индекс known,
   а subject не человек и не key — 400 unknown subject
5. кластер = domain и last_admin                                     → 409 last admin
6. записать по CAS: lines по порядку Н1.3, by — доказанное имя; конфликт — перечитать и повторить с шага 4 не больше трёх раз
   (конфликт с DELETE возвращает к шагу 4, и он видит метку удаления)
```

**Гонки.** Человек выключен, а его токен жив: у кластера держателя отказ сразу (`domain/disabled`), у члена — со следующим
ответом агенту (ADR-0051). Отзыв гранта у члена без связи — не позже `GRANT_LIFETIME` от `as_of` копии (Н1.3); выданный токен — `TOKEN_LIFETIME +
`TOKEN_SKEW` от выдачи. Гранты пишет
один процесс `domain` — CAS строки. Одно имя создаётся человеком и вкладом в двух кластерах одновременно — индекс показывает
обоих, доставка элемента не идёт (глава 8.5 Н1.7 reverse), распределённой блокировки нет.

Шаги сценариев 01, 02 у консоли кластера (`/session` с грантами, чтение и запись единицы под токеном, 401 без токена) и
шаг 02/23 (`GET /domain/grants` у консоли домена) — соседи на стенде: консоль кластера, урок P/10.

Проверяются чтением, с причиной:
- равное время ответа неизвестному, выключенному и неверному (Н1.2 `check`) — стенд не меряет время ответа;
- общий потолок предела (Н1.10 `ceiling`) — 20 отказов стенд не набирает; адрес клиента от консоли домена, а не её TCP-пир
  (Н1.10 `address`, `X-W2C-Client`) и PBKDF2 без общего замка (Н1.2 `check`) — стенд их не различает (сверка М11, P16, P21);
- обрыв `DELETE /domain/users` после строки человека (Н3 «дверь людей» шаг 9 и сверка) — стенд не прерывает `DELETE`
  (решение владельца ADR-0083 доп. (9)); три
  конфликта CAS — 503 `unavailable` (разбор ревью стадии A 8–10, № 38) — стенд не создаёт конфликт;
- нечитаемая строка человека (Н1.1 `unreadable`) — стенд не портит строку человека;
- `until` по значению и порядок по числу (Н1.3 `lines`), кластер в пути без %-декодирования (P13), форма `added`/`removed`
  журнала (P17) — сверка М11, P7, P9, P13, P17; журнал приёмка не сравнивает;
- отказ приёма члена с именем `domain` (Н1.9 `member`) — стенд не ставит кластер с именем `domain`;
- первый администратор (Н1.9 `first`) — подготовкой стенда (`@admin`), не шагом.
