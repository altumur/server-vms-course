# P/08.0 — Двери процесса: нормы

Канон главы 8.0 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md). Каталога
приёмки у главы нет (Н5). Здесь — дверь процесса `domain` (`SIGNER_URL`) в целом: кто пишет строки держателя, как процесс
принимает правки, которые передаёт консоль домена (`X-W2C-Client` — только на соединении роли `domainconsole`), ответы
процесса `deposed`, `frozen`, `standby`, которые никто по дороге не пересчитывает, серверная сторона дверей класса
`signed`, сводная таблица дверей процесса, версии и память повторов дверей правок.

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из

## Н1 Форма

**Время.** Поля времени строк главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`domain/idem/<key>` — `at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/idem/<key>`;
- читает: `/etc/w2c/tls/<роль>/server.key`.

Своя строка у главы одна — заявка памяти повторов (Н1.9). Прочие строки держателя пишет только процесс `domain` (Н1.8 `writer`): каждую —
глава-владелец урока по каталогу, со стражем очереди ([глава 8.10](08.10-domain.norms.md) Н1.7 `guard`). Ключ
сертификата сервера роли `domain` — комплект `/etc/w2c/tls/<роль>` ([P/02.4](../../02-installer/spec/02.4-installer.norms.md)):
двери класса `signed` процесс отдаёт по TLS этим сертификатом (Н1.6).

### Н1.6 Серверная сторона дверей класса `signed`

Серверная сторона слушателя процесса `domain` (`SIGNER_URL`) — класс `signed`, строка `signer`: [договор сертификата
роли](../../common/contracts/role-certificate.md) «Серверная сторона: класс `signed`» (перенесено туда из М11/8 Н1.6 `server`, `signed` без изменения; одно место для
P/08.0-02 и ретранслятора [P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.6; решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 6; разбор ревью стадии A
8–10, № 21). Комплект роли процесса — `domain` ([P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md); роли
процессов — P/10 Н1.4 `roles`). Класс `role` (дверь консоли домена) — [договор сертификата роли](../../common/contracts/role-certificate.md)
«Серверная сторона: класс `role`». Класс делится по слушателю, не по маршруту: все маршруты сводной таблицы Н2 — двери держателя для
агентов [главы 8.3](08.3-domain.norms.md), пакет ретранслятора, двери переноса главы 8.8 и двери людей, которые передаёт
консоль домена (Н1.8), — один слушатель; личность — по норме маршрута (подпись, токен, пароль). Сертификат клиента
слушатель под TLS запрашивает необязательно и предъявленный проверяет в рукопожатии: лист сходится к своим `ca.pem` или
`ca.next.pem`, срок действует, нет extendedKeyUsage без `clientAuth`; иначе — alert, HTTP нет; не предъявлен —
рукопожатие `ok`. Роль `domainconsole` — только для `X-W2C-Client` (Н1.8; [договор пересылки](../../common/contracts/forwarding.md)
«Адрес клиента»; [P/02.4](../../02-installer/spec/02.4-installer.norms.md) Н1.6 `client_cert`); клиенты из других
кластеров лист не предъявляют (договор сертификата роли `clients`; ADR-0083 доп. (20), доп. (21)).

### Н1.8 Приём правок консоли домена — процесс `domain`

```yaml
writer:    строки держателя пишет только процесс domain (ADR-0032; глава 8.2 Н1.3): правки людей, приём отчётов, проход;
           кроме строк воркера на домене (P/03.7 Н1.6: kept и переносимые книги — их писатель он)
pass:      сторона процесса: двери /domain/*, которые передаёт консоль домена (список дверей домена — договор пересылки
           «Двери домена», решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 5; передача — урок
           P/10, P/10-02), и POST /api/login (глава 8.4) приходят процессу domain (SIGNER_URL своей коробки): метод, путь
           с query, тело, Authorization, Idempotency-Key, If-Match как пришли; X-W2C-Client — адрес TCP-пира клиента:
           ставит консоль домена, когда, кому верит процесс и что снимается снаружи — договор пересылки
           Platform/common/contracts/forwarding.md «Адрес клиента» (разбор ревью стадии A 8–10, № 23; там же история:
           сверка М11, cammeta-python М11-09 № 22, P16); процесс проверяет личность и грант сам (глава 8.4) и исполняет
           Н3 двери
answers:   отказы процесса — его: 409 deposed, 503 frozen (глава 8.8), 503 standby (глава 8.10); консоль их не пересчитывает
```

Ответ процесса консоль домена отдаёт как пришёл (урок P/10 Н1.3; [договор пересылки](../../common/contracts/forwarding.md)
«Отказы по переходам», переход 3 — исполнение).

### Н1.9 Версии и память повторов дверей правок

Правки людей у процесса держат те же обещания, что двери записи консоли кластера: версию строки и память повторов (ADR-0094 B3, B4).
Форма значений и слова — [P/06.1](../../06-console/spec/06.1-console.norms.md) Н2 «Версии», Н3 «память повторов». Здесь — двери процесса и единственное отличие от консоли кластера: у строк держателя
один писатель ([глава 8.10](08.10-domain.norms.md) Н1.7), поэтому заявке не нужны `pending` и перехват.

| Дверь | Строка версии | `revision` | `ETag` успеха |
|---|---|---|---|
| `POST /domain/members`, `DELETE /domain/members/<член>`, `POST /domain/members/<член>/ca` | `domain/members` | `doc.rev` | да |
| `PUT /domain/topology` | `domain/topology` | `doc.rev`; строки нет — 0 | да |
| `POST /domain/users` | — | поле `revision` новой строки | да |
| `PUT /domain/users/<имя>` | `domain/users/<имя>` | поле `revision` | да |
| `DELETE /domain/users/<имя>` | `domain/users/<имя>` | поле `revision` | нет: строки больше нет |
| `PUT /domain/grants/<кластер>` | `domain/grants/<кластер>` | поле `revision` | да |
| `PUT /domain/break-glass/<кластер>` | `domain/break-glass/<кластер>` | поле `revision` | да |
| `POST /domain/groups`, `POST /domain/roles` | — | поле `revision` новой строки | да |
| `PUT /domain/groups/<имя>` | `domain/groups/<имя>` | поле `revision` | да |
| `DELETE /domain/groups/<имя>` | `domain/groups/<имя>` | поле `revision` | нет: строки больше нет |
| `PUT /domain/roles/<имя>` | `domain/roles/<имя>` | поле `revision` | да |
| `DELETE /domain/roles/<имя>` | `domain/roles/<имя>` | поле `revision` | нет: строки больше нет |
| `POST /domain/batch` | строки `writes`: условие — `cas` каждой, `If-Match` не читается | поле `revision` каждой строки | нет: строк много |
| `PUT /domain/placement/<sub>/<ref>` | `domain/placement/<sub>/<ref>` | `rev` | да |
| `DELETE /domain/placement/<sub>/<ref>` | `domain/placement/<sub>/<ref>` | `rev` | нет: строки больше нет |
| `PUT /domain/shared` | `domain/shared` | `doc.rev` указателя; строки нет — 0 | да |

Хранимая правка ([глава 8.6](08.6-domain.norms.md) Н1.3, Н1.4) в таблицу не входит: её ключ обязателен, повтор — правило `repeat`, условие несёт `base`. Двери `/api/login`,
`/domain/revoke` и двери переноса (глава 8.8) версии и памяти не читают: вход и отзыв строк с версией не правят, а порядок переноса держит запись срока.

#### Версии

- **`revision`** — счётчик правок, как P/06.1 Н2 «Версии». Поле `revision` строк `domain/users/<имя>`, `domain/grants/<кластер>`, `domain/break-glass/<кластер>`, `domain/groups/<имя>`, `domain/roles/<имя>`: 1 при создании, +1 на каждую запись процесса `domain`,
  кто бы её ни вызвал: дверь, снятие строк при удалении человека, сверка прохода, `first-admin`. Строка без поля или с нечитаемым полем — `revision` 0, следующая запись пишет 1: строки прежних установок читаются (исходы семей).
  Копия у члена поля не несёт: агенту уходит `doc` гранта и поля `break_glass`, как прежде.
- **`ETag`** — индекс строки в двойных кавычках (P/06.1 Н2 «Версии»). Его несут ответы успеха по таблице и двери чтения консоли домена ([P/10](../../10-domain-console/spec/10-domain-console.norms.md) Н1.2).
  Перечни `GET /domain/users`, `GET /domain/groups`, `GET /domain/roles`, `GET /domain/break-glass`, `GET /domain/placement`, `GET /domain/grants` заголовка не несут: у них строк много, индекс и `revision` стоят при строке. Тела дверей записи индекса не несут: он становится известен только после пакета (ниже).
- **`If-Match`** необязателен; форма значения — две формы P/06.1 Н2 «Версии»: `<revision>` числом или индекс в кавычках. Иное значение — 400 `If-Match is a unit revision` до чтения строки. Двери `POST /domain/users`, `/domain/groups`, `/domain/roles` его не читают: строки ещё нет, условию не о чем судить. Дверь `POST /domain/batch` не читает: условие строки — её `cas`.
  Нуль — не форма: условие называет строку, которая есть, поэтому первую запись топологии и общего документа несёт `base_rev: 0` (ниже).
- **Условие** судится на первом чтении строки двери: после памяти и формы тела, раньше содержания правки. После конфликта `cas` — снова, по перечитанной строке. Дверь, которой нужна строка (`PUT`, `DELETE` человека, группы, роли, `DELETE` назначения, `DELETE` члена),
  отвечает своим 404 раньше условия; дверь, которая строку создаёт, — 412 с `revision: 0`. Строка есть, а её `revision` не читается: `<revision>` не совпадает ни с чем, индекс сравнивается.
- **`412 revision moved`** — условие не выполнено, ничего не записано: `{detail, error: "revision moved", field: "/revision", revision, row?}`, форма P/06.1 Н2 «Версии». Двери таблицы требуют права выше `view`, поэтому `row` есть, если есть строка и она читается. Секретов `row` не несёт:

| Строка | `row` |
|---|---|
| `domain/members` | `{rev, term?, members}` |
| `domain/topology` | документ `doc` |
| `domain/users/<имя>` | элемент `GET /domain/users`; `pwhash_secret` в нём нет |
| `domain/grants/<кластер>` | `{lines, revision, index}` |
| `domain/break-glass/<кластер>` | `{set_at, revision, index}` |
| `domain/groups/<имя>` | элемент `GET /domain/groups` |
| `domain/roles/<имя>` | элемент `GET /domain/roles` |
| `domain/placement/<sub>/<ref>` | `Placement` с `index` |
| `domain/shared` | указатель `{term, rev, sha256, object}` |

**`base_rev`** у `PUT /domain/topology` и `PUT /domain/shared` — прежний вход (решение «Архитектора» 2026-10-29 по плану доли домена, В3). `If-Match` — основной. Дверь читает `base_rev`, только если заголовка нет, и тогда отказ прежний: 409 ревизии.
Есть оба: `<revision>` равен `base_rev` — дверь судит `If-Match`; не равен или рядом с `base_rev` стоит индекс — 400 `refused`, `field: /base_rev`: счётчик и индекс без строки не сравнить, а правку с двумя разными условиями дверь не угадывает.
Нет ни того, ни другого — прежние 400: у этих дверей неуказанное поле остаётся прежним, поэтому правка без условия не пишется.

#### Память повторов

```yaml
header:    Idempotency-Key необязателен: нет — проход двери прежний, повтор есть новая запись; есть — дверь идёт под памятью
key:       (user, метод, путь, ключ) → строка domain/idem/<key>; <key> — hex sha256 по P/06.1 Н3 «память повторов», 64 строчных знака;
           user — имя, доказанное токеном (глава 8.4 Н1.5); путь — путь двери целиком, /domain/…, сегменты процент-декодированы
form:      значение заголовка — P/06.1 Н2 (без OWS, дважды — 400); ключ не по форме — 400 Idempotency-Key required
print:     отпечаток — кто, метод, путь, тело как значение JSON; тела нет — как {}; If-Match не входит: повтор после потери ответа
           несёт прежнее условие, его не судят; значение — HMAC print главы P/06.2 Н1 под кольцом держателя: в теле дверей людей пароль,
           голый хэш открыл бы перебор мимо PBKDF2; кольцо не читается — 503 unavailable
row:       domain/idem/<key>: {print, code, body, index?, at}
  code:    код ответа, ниже 500; body — тело ответа текстом; at — стенные секунды записи
  index:   индекс ETag ответа, если эта запись цель не писала (то же содержимое, отказ не несёт); поля нет — индекс самой строки
order:     отказы Н3 (standby, deposed, frozen) и личность с грантом — они не запоминаются → тело JSON-объект, форма ключа, форма If-Match →
           память → проход двери: форма тела, условие, содержание → запись → ответ
memory:    строки нет — проход двери; тот же отпечаток — прежний ответ; иной отпечаток — 422 key reused; строка не читается или чтение
           не подтверждено — 503 unavailable, строка не трогается
in_flight: тот же <key> уже в работе этого процесса — 409 in flight; смена процесса работы не оставляет: цель и ответ ложатся одним пакетом
write:     успех — одним пакетом P/01.1 (op: batch): целевая запись двери с её условием и строка заявки с cas ""; guards — domain/signer-turn
           моей версии и стражи двери (ссылок, доказательства администратора, статуса цели; глава 8.4 Н1.3, Н1.3в, Н3) тем же пакетом; что записано раньше целевой (объект документа, строка ca-certs, метка удаления), повторяется без вреда — Н3 двери
refusal:   ответ < 500 без целевой записи, в том числе 400, 404, 409, 412, — строка заявки одна, с cas "" и стражем очереди; 5xx не запоминается
replay:    код и тело байт в байт; ETag — по таблице: поле index, иначе индекс самой строки заявки: все строки пакета получают одну версию (P/01.1 Н1);
           повтор ничего не пишет, журнала нет
weight:    строка заявки тяжелее потолка хранилища — 413 row too large, цель не пишется, отказ не запоминается; 412 с row — сначала без row (P/06.1 Н2 «Версии»)
```

Заявке консоли кластера нужны `pending`, перехват и страж своей версии, потому что консолей несколько, а цель и ответ пишутся разными операциями. Здесь писатель один, а цель и ответ ложатся одним пакетом: пакет лёг целиком или его не было, поэтому продолжать нечего.
Обрыв до пакета оставляет только записи, которые повторяются без вреда. Повтор идёт проходом заново и судит по состоянию: `DELETE /domain/users/<имя>`, чей прежний проход снял строку человека, отвечает 404, а строки грантов доводит сверка (глава 8.4 Н3). Неизвестный исход пакета — барьер (глава 8.10 Н1.7): ответ 503, повтор находит строку заявки или идёт проходом.

Срок и потолок — глава 8.10 Н1.5 `idem`. Перенос держателя памяти не несёт: `domain/idem/*` нет в `state` резервной копии (глава 8.8 Н1.5). Новый держатель встречает ключ как новый, условие `If-Match` при этом остаётся.

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `domain/idem/<key>` — строка

Схема — [`idem.schema.json`](../data/idem.schema.json), исходы — [`idem.outcomes.tsv`](../data/idem.outcomes.tsv); версия формы 1; норма — P/08.0 Н1.9; P/08.10 Н1.5 idem.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| процесс смещён | 409 `deposed` с `holder` — запись нового держателя (глава 8.8 Н1.6): правки и отчёты | агент; человек — через консоль как пришло | идти за новым держателем (глава 8.8) |
| процесс `domain` — ждущий | 503 `standby` (глава 8.10 Н1.7) | агент; человек — через консоль как пришло | агент — следующий проход (P/09.1-19); человек — повтор |
| идёт плановая передача | 503 `frozen` (глава 8.8 Н1.7) | человек — через консоль как пришло | — |
| правка по ref у двух исполнителей и больше без `?cluster=` | 409 `executors` с `clusters` (глава 8.6 Н3 «принять правку» шаг 2а; глава 8.1 Н4) | человек — через консоль как пришло | повторить с `?cluster=<исполнитель>` (ADR-0091 доп. (15) п. 4) |
| дверь Н1.9: `If-Match` не по форме; ключ не по форме | 400 `If-Match is a unit revision`, `Idempotency-Key required` | человек | исправить заголовок |
| дверь Н1.9: `If-Match` не равен версии строки | 412 `revision moved` с `revision`, `row?` | человек | перечитать и решить заново |
| дверь Н1.9: тот же ключ в работе; иное тело под тем же ключом | 409 `in flight`, 422 `key reused` | человек | дождаться; новая правка — новый ключ |
| дверь Н1.9: строка заявки тяжелее потолка хранилища | 413 `row too large` | человек | повторить без ключа или уменьшить правку |
| дверь Н1.9: заявка не читается, кольцо не читается, чтение не подтверждено, потолок `IDEM_MAX` (глава 8.10 Н1.5) | 503 `unavailable` | человек | повторить; у потолка — повторить без ключа |

Тело этих отказов — их слово в `error`, не `refused`: 409 `deposed` с `holder` (глава 8.8 Н1.6), 503 `frozen` (глава 8.8
Н1.7), 503 `standby` (глава 8.10 Н1.7), 409 `executors` — `{error, detail, clusters}`, `clusters` по возрастанию байтов
(глава 8.6 Н1.3); формы — [OpenAPI урока](08-domain.api.openapi.yaml).

Отказ дверей процесса — `{error, detail?, reason?, field?}` (ADR-0094 B5). Клиент выбирает действие по слову и ставит ошибку у поля
по `field`, не разбирая текст для человека.

- `error` — слово закрытого перечня [`refusal-words.tsv`](../data/refusal-words.tsv): постоянная строка без имён и значений; дверь говорит
  только слова своих строк и строк `*` с тем же кодом. Слова нынешних Н4 остаются, переименования нет.
- `detail` — фраза для человека. Фразы в кавычках таблиц Н4 — `detail` слова `refused`, если строка не называет их словом `error`.
- `field` — путь поля тела, формат — [P/06.1](../../06-console/spec/06.1-console.norms.md) Н2 «Отказ: `error` и `field`». Он есть только у 400, 409 и 412 и
  только у строк перечня, где колонка `field` не `-`; отказ не о поле — без него. Код 412 дают только двери Н1.9; исход
  `conflict` (412) применения хранимой правки виден в `outcomes` (глава 8.6 Н4).

## Н5 Приёмка

Каталога приёмки у главы нет: своего исхода у главы нет — исходы дверей проверяют сценарии их глав. Проверяются:
- приём правок процессом и один писатель строк держателя (Н1.8 `writer`, `pass`) — сц. 01, 02 [главы 8.3](08.3-domain.norms.md)
  (приём и уход члена пишет процесс; прежде М11/3 сц. 01, 02);
- `X-W2C-Client` только на соединении роли `domainconsole` — чтением: на стенде без TLS заголовок не доверяется никогда
  (договор пересылки «Адрес клиента» — долг стенда, не нормы);
- ответы `deposed`, `frozen`, `standby` (Н1.8 `answers`, Н4) — стенды глав 8.8 и 8.10; что консоль домена их не
  пересчитывает — урок P/10 (Н1.3);
- версии и память повторов (Н1.9) — сц. 27 главы 8.3, сц. 23, 37 главы 8.4, сц. 16 главы 8.6, сц. 09 главы 8.9; `ETag` дверей чтения и пересылка заголовков — сц. 17 приёмки урока P/10;
- серверная сторона класса `signed` (Н1.6) — чтением: TLS между кластерами на одной машине стенд не поднимает; TLS-стенд
  ([`common/acceptance/tls/`](../../common/acceptance/tls/README.md)) п. 2, строки двери `signer` (без сертификата, свои
  листы, чужой центр, срок, EKU — ADR-0083 доп. (20), доп. (21) п. 9) — сценарии глава
  получает, когда стенд готов (ADR-0083 доп. (9)).

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/08.0-MM` — то, на что ссылаются дельты
решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/08.0-01** приём правок консоли домена по `SIGNER_URL` Н1.8, один писатель строк держателя — сц. 01, 02 главы 8.3 (приём и уход пишет процесс); `X-W2C-Client` только на соединении роли `domainconsole` — чтением (стенд без TLS); ответы `deposed`, `frozen`, `standby` — стенды глав 8.8, 8.10 (часть 8.0 строки М11/3-12; разбор ревью стадии A 8–10, № 18)
- [ ] **P/08.0-02** серверная сторона дверей класса `signed` Н1.6 ([договор сертификата роли](../../common/contracts/role-certificate.md)): TLS сертификатом сервера роли; сертификат клиента не требуется и прав не даёт, предъявленный проверяется в рукопожатии (чужой центр, срок, EKU — alert; ADR-0083 доп. (20), доп. (21)) — чтением; TLS-стенд п. 2, строки двери `signer` — когда стенд готов (ADR-0083 доп. (9)) (часть М11/8-08; разбор ревью стадии A 8–10, № 21)

- [ ] **P/08.0-03** версии дверей правок Н1.9 (ADR-0094 B4): `ETag`, `If-Match` двух форм, 412 `revision moved` с `row`, `base_rev` без заголовка, оба и разные — 400 — сц. 27 главы 8.3, сц. 23, 37 главы 8.4, сц. 16 главы 8.6, сц. 09 главы 8.9; «Условие снова после конфликта `cas`» — чтением (гонку стенд не ставит)
- [ ] **P/08.0-04** память повторов дверей правок Н1.9 (ADR-0094 B3): ключ, строка `domain/idem/<key>`, порядок «память → `If-Match` → запись», иное тело — 422 `key reused`, сохранённый отказ — сц. 27 главы 8.3, сц. 23, 37 главы 8.4, сц. 16 главы 8.6, сц. 09 главы 8.9; цель и ответ одним пакетом, `in flight`, вес строки заявки, неизвестный исход — чтением (стенд не обрывает проход и не ставит гонку)
