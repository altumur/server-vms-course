## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`domain/members` — `Entry.since`; стук `knock` — `last`; метка приёма — `received_at` (`sent_at` — как пришёл в
публикации, P/09.1 Н1.2); `domain/topology` — `at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/members`, `domain/members/<член>/reports/<rev>`, `domain/members/<член>/reports/<rev>.delta`, `domain/members/<член>/reported`, `domain/members/<член>/ca-certs`, `domain/topology`;
- читает: `domain/root`, `domain/keys`, `domain/revoked`, `domain/holder`, `domain/view`, `platform/manifest/<sub>`.

Строки и объекты главы пишет только процесс `domain` (ADR-0032; глава 8.0), каждую запись — под стражем очереди
`domain/signer-turn` (глава 8.10 Н1.7). `domain/root` — отпечаток своего корня для `pinned` стука (Н1.1 `knock`);
`domain/keys` и `domain/revoked` — набор и отзывы держателя: `revoked_members` при приёме (Н3 «принять члена» шаг 4,
двери Н2) и поля `keys`, `revoked` ответа (Н1.5); `domain/holder` — поле `holder` ответа; `domain/view` — `knocking` и
`member_list` вида (глава 8.1) при приёме члена (Н3 шаг 1); строки манифестов — каталог с `domain.ref` для `not_ready` и
`member_objects` ([договор приёма отчёта](../../common/contracts/accept.md) шаги 4, 5). Общее урока: hex строчный,
base64url без `=`, JCS — RFC 8785, формы JSON закрыты, повтор ключа — форма не та, порядок ключей объекта ничего не
значит ([договор токена домена](../../common/contracts/domain-token.md); [P/08.2 Н1](08.2-domain.norms.md) «Общее для всех
форм главы»). «Стенные секунды» —
часы процесса, который проверяет или пишет; «монотонные» — его монотонные часы (глава 8.1 Н1.3).

### Н1.1 Член, ключ члена, приём (сторона держателя)

Агент члена (роль `domainagent`), ключ члена `domain/member-key` (`pub` — точка кривой Ed25519 не малого порядка),
команда `join` и копии члена `domain/member-list`, `domain/member` — сторона члена: [P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.1.
Отпечаток ключа члена и корня — [глава 8.2](08.2-domain.norms.md) Н1.1.

```yaml
domain/members: {doc: <текст JSON>}           # у держателя; писатель — процесс domain (глава 8.0), CAS
  doc:          {rev, term, members: {<член>: Entry}}
  rev:          целое ≥ 1, +1 на каждую запись
  term:         срок держателя, записавшего строку (глава 8.8 Н1.1; установка — 1); пара (term, rev) называет список
                однозначно и после переноса (Н1.4а)
  Entry:        {how, since, by?, key?, revoked_keys?, ca?}   # ca — Н1.6; how держателя — глава 8.8
    how:        "admitted" | "holder" | "held the domain until term <N>" — откуда член в списке (глава 8.8 Н1.2 — два
                последних); имя человека — только в by, не дублируется
    since:      стенные секунды держателя записи
    by:         человек, принявший члена (глава 8.4; до него — operator, P/06.3 Н1.8 `loopback`); только у admitted
    key:        hex ключа члена, принятого по отпечатку; у holder — ключ из первого отчёта его агента (глава 8.8)
    revoked_keys: [<hex>…] — прежние ключи этого имени, отозванные (глава 8.2 Н3 «смена после кражи»); не больше 4 последних,
                  Entry ≤ ENTRY_MAX 820 байт JCS (глава 8.10 Н1.5; добавлено М11/12)
knock:          стучащийся — [договор приёма отчёта](../../common/contracts/accept.md) «Стук» (перенесено туда без изменения;
                аудит раскладки, решение «Архитектора» 2026-10-25, Б-12)
```

**Приём — двусторонний.** На члене оператор закрепляет корень (`join`, [P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.1); на держателе — вносит
ключ члена (`POST /domain/members {name, fingerprint}`, Н2), сверив отпечаток с тем, что агент члена напечатал при
старте. Порядок сторон любой. Агент отчитывается и без закрепления — так держатель видит стучащегося, — но набор без
закреплённого корня не берёт ([договор набора ключей домена](../../common/contracts/keys.md) «Функция `keys`» →
`no_pin`). Отпечаток ключа члена и корня — [глава 8.2](08.2-domain.norms.md) Н1.1.

### Н1.2 Топология

```yaml
domain/topology:   {doc: <JCS текст>}         # у держателя; писатель — процесс domain по двери Н2 (глава 8.0), CAS
  doc:             {rev, centre?, star, via, by?, at?}
    rev:           целое ≥ 0; 0 — «никогда не писали» (строки нет — так же); +1 на запись
    centre?:       член — центр домена: к нему тянутся звёздные ретрансляторы (глава 8.7; М11/12); в PUT centre "" или null
                   снимает центр, как пустой ретранслятор в via (добавлено сверкой М11, T2)
    star:          [<член>…] — звёздные ретрансляторы: до них не дотянется никто, данные они берут у центра (глава 8.7;
                   М11/12); по возрастанию, без повторов
    via:           {<член>: <ретранслятор>} — член отчитывается через ретранслятор; члена нет — отчитывается прямо
    by?, at?:      кто и когда (стенные секунды консоли) записал
  refusals:        (каждая — причиной в одном отказе 409, через «; »; причины — в порядке этого списка, внутри одной
                   строки — по имени в байтах UTF-8; цепочка — одна причина на пару (m, via[m]); via[m] = m — только
                   «through itself», без цепочки; добавлено сверкой М11, T3, T4)
    - имя в centre, star, via (член или ретранслятор) — не член домена: «<что>: <имя> is not a cluster of this domain»
    - star без centre: «a star relay takes its members' data from the centre, and there is no centre»
    - centre в star: «<c> is the centre and cannot be a star relay»
    - держатель в star: «<h> is the domain holder: it reaches the domain in place and is no star relay»
    - член через себя: «<m> cannot reach the domain through itself»
    - цепочка: via[via[m]] есть — «… one relay between a member and the domain»
    - через держателя: «<m> through <h>: that is the domain holder itself»; держатель в via — «<h> is the domain holder:
      it reaches the domain in place, through nobody»
put_order:         PUT /domain/topology по порядку: 400 — нет base_rev или тело не по форме → 409 «the topology is at rev N;
                   this edit was made against rev M — look again» (ревизия раньше содержания) → отказы refusals одним 409
                   через «; » → запись по CAS (не больше 10 конфликтов); star пишется по возрастанию без повторов; via
                   с пустым ретранслятором — член уходит из via; by — имя, доказанное сторожевой (P/08.4 Н1.5)
home:              ближайшая дверь члена к домену — via[член], иначе centre, иначе держатель (P/08.7 Н1.1 `poll_home`)
```

Копия у члена `domain/member-topology` — поле `topology` ответа держателя (Н1.5) как есть: сторона агента,
[P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.4.

Какой дорогой агент отчитывается, решает его окружение (`DOMAIN_URL` или `RELAY_URL`), не топология; топология
говорит держателю и ретранслятору, кого через кого **принимать**. Член, чей отчёт пришёл не той дорогой, отвергается
(Н3 «держатель на POST /api/relay»; дверь ретранслятора — [глава 9.2](../../09-agent/spec/09.2-agent.norms.md) Н2); прямой отчёт члена, которого топология ведёт через
ретранслятор, держатель принимает — это вторая дорога (Н1.3а).

### Н1.3 Поколение и метка

То, что из этого подраздела нужно агенту (метка — `sha256` от JCS целого, `MARK_REFRESH`, `BODY_LIMIT`), — также [договор приёма отчёта](../../common/contracts/accept.md) «Поколение, метка, пределы» (разбор ревью стадии B 8–10, № 4: урок 9 читает договор, эта глава — владелец текста).

```yaml
generation:     domain/members/<член>/reports/<rev>   # объект держателя (P/05 Н1.1): целое поколение, JCS
  whole:        {sent_at, objects, key, keys_rev?, pinned?, outcomes?}   # objects — все объекты члена после применения
                изменения; outcomes — P/09.1 Н1.5: смена исходов — новое поколение, агент шлёт поле в каждой
                публикации, пока строка domain/outcomes не пуста; нет поля — исходов нет
delta:          domain/members/<член>/reports/<rev>.delta     # байты тела публикации как получены — то, что подписал агент
reported:       domain/members/<член>/reported               # объект-метка; единственная граница принятого
                # две части (решение «Архитектора» по R41-05 прогона 41): поля поколения пишет только generation (договор
                # приёма отчёта, шаг 7); поля последнего принятого запроса — каждый приём с записью метки (шаги 6, 7)
  # поля поколения
  rev:          целое ≥ 1 — номер поколения; выдаёт держатель: +1 на принятое изменение
  sha256:       hex sha256 байтов generation
  base:         rev, против которого пришло изменение; 0 — пришло целое
  delta_sha256: hex sha256 байтов delta (при base 0 — тела целого, как пришло)
  signature?:   заголовок X-Agent-Signature прямого отчёта, создавшего поколение, как пришёл (Н1.4); через ретранслятор
                поля нет (Н1.3а); via — поле последнего запроса, поэтому метка без signature и без via законна:
                поколение пришло через ретранслятор, затем прямой heard (решение «Архитектора» по сверке М11, A14)
  key, keys_rev?, pinned?: из публикации — по ним консоль домена принимает члена и показывает закрепление
  # поля последнего принятого запроса
  sent_at:      sent_at публикации; received_at — стенные секунды держателя приёма
  request_sha256: hex sha256 байтов тела этого запроса, как пришло; повтор узнаётся по (sent_at, request_sha256)
  via?:         ретранслятор — Н1.3а
  stale:        из публикации при каждом приёме, включая «слышал» (договор приёма отчёта, шаг 6); нет в публикации — []
  sign_failures?: из публикации при каждом приёме с записью метки, как stale; поколения не создаёт и метку само не
                освежает; нет в публикации — поля нет (Н1.6а; P/09.1 Н1.12; решение «Архитектора» по сверке М11, A7, W1)
keep:           два последних поколения и их delta; старше и выше метки — убираются следующим приёмом
REPORT_EVERY:   5           # с — проход агента; ответ держателя может назначить every (Н1.5), 1 … 3600
MARK_REFRESH:   22.5        # с = LOST_AFTER/2 (глава 8.1 Н1.3) по монотонным часам держателя
BODY_LIMIT:     16 MiB      # больше — 413, тело не читается дальше
```

Метка — граница принятого: объект с номером не выше `reported.rev` неизменяем; объект выше — ничей: не читается, не
переносится, не держит номер, следующий приём пишет поверх. Читатели (вид — глава 8.1, сборщик книг — глава 8.5,
резервная копия — глава 8.8) берут `reported.rev` и читают только объект этого поколения; метка без объекта или объект
не с её `sha256` — член `silent` (глава 8.1 Н3 шаг 2), никогда не смесь.

Публикация — тело `POST /api/member/<член>` (закрытая форма, `member_objects`, поля вне дельты, `ready`, `change`) —
[P/09.1](../../09-agent/spec/09.1-agent.norms.md) Н1.2; схема тела двери — [контракт урока](08-domain.api.openapi.yaml).

### Н1.3а Дороги и порядок

`ROAD_QUIET` и порядок дорог для агента и ретранслятора — также [договор приёма отчёта](../../common/contracts/accept.md) «Поколение, метка, пределы» (разбор ревью стадии B 8–10, № 4: урок 9 читает договор, эта глава — владелец текста).

```yaml
road:          прямо (via нет) или через ретранслятор R (via = R); дорогу публикации называет держатель, не член
one_road:      порядок задаёт дорога: последнее принятое на этой дороге — новее, даже если sent_at назад (договор приёма отчёта)
two_roads:     между дорогами одного члена — по sent_at члена (одни часы на обеих): тело другой дороги со sent_at ниже
               метки не принимается (ignored), пока член слышен — heard_ago < ROAD_QUIET (договор приёма отчёта, шаг 2а); равный
               sent_at — одно тело: те же байты — heard (повтор другой дорогой), другие — 409 same_sent_at (там же, шаг 2)
ROAD_QUIET:    15         # с, монотонные часы держателя: три прохода агента (REPORT_EVERY 5); дольше — прежняя дорога молчит
base:          у каждой дороги своя: ответ даёт rev метки только дороге метки, другой — 0 (шлёт целое)
signature:     метка прямого отчёта несёт подпись агента; через ретранслятор подпись члена не переносится — держатель
               верит подписи ретранслятора и топологии (ADR-0074; перенос подписи члена — долг, ответ на записку М11 п. 4)
bytes:         delta поколения через ретранслятор — запись relayed[<член>] пакета как получена (JCS этого значения)
```

### Н1.4 Подпись агента

Перенесено в [договор подписи агента](../../common/contracts/agent-signature.md) (владелец — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.3;
проверяют 8.3, 8.7, 9.2, P/06.3): заголовок `X-Agent-Signature`, байты подписи, окна `MEMBER_WINDOW` 300 и `UNIT_WINDOW` 60,

(`MEMBER_WINDOW`); что дверь делает после проверки (стук, 403 ключа, 401) — Н2.

### Н1.4а Список членов — только отставшему

```yaml
members_rev:               [договор приёма отчёта](../../common/contracts/accept.md) «Список членов отставшему» (перенесено туда без
                           изменения; аудит раскладки, решение «Архитектора» 2026-10-25, Б-12)
```

Прочие поля ответа малы или только свои: `placement` — назначения этого члена ([P/08.6 Н1.2](08.6-domain.norms.md)),
`grants` — строка этого члена ([P/08.4 Н1.3](08.4-domain.norms.md)), `shared` — указатель всегда, документ — отставшему
([P/08.9 Н1.4](08.9-domain.norms.md)).

### Н1.6 Отпечатки центра члена: `tls_ca` → `Entry.ca`

Публикация `tls_ca`, `tls_ca_certs` и отпечаток центра для агента — также [договор сертификата роли](../../common/contracts/role-certificate.md) «Комплект кластера, роли домена, центр между кластерами» (разбор ревью стадии B 8–10, № 4: урок 9 читает договор, эта глава — владелец текста).

Комплект роли, сертификат, центр и отзыв — [P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md),
[договор сертификата роли](../../common/contracts/role-certificate.md): один центр на кластер. Доверие между кластерами —
по отпечатку центра, который кластер-член публикует подписанным отчётом (ADR-0075 доп. (6), уточнения 1–3).

```yaml
fingerprint:  sha256 hex (64 знака, строчные) DER-сертификата центра
tls_ca:       поле публикации (P/09.1 Н1.2): [<отпечаток>…] по возрастанию, без повторов — ca.pem и ca.next.pem
              каталога W2C_TLS_DIR кластера (договор сертификата роли `rotation`); каталога или ca.pem нет — поля нет; каждый файл —
              ровно один сертификат центра (CA:true): файл есть, но не читается, блоков не один или не центр — поля нет
              (агент пишет причину в журнал; добавлено сверкой М11, D13); вне дельты
              (не входит в whole, поколения не порождает); идёт в каждой публикации
tls_ca_certs: поле публикации рядом с tls_ca: [<PEM>…] — сертификаты тех же центров в том же порядке; элемент — ровно
              один блок CERTIFICATE (как договор peer «Функция peer» шаг 2) с CA:true (лист под своим отпечатком — не центр; добавлено
              сверкой М11, D12), sha256(DER) элемента — отпечаток tls_ca на том же месте; есть
              только вместе с tls_ca; вне дельты; идёт в каждой публикации (решение «Архитектора» по cammeta-python
              М11-08 № 19). Форма публикации закрыта (P/09.1 Н1.2): держатель прежней сборки отчёт с полем отвергает —
              реализации переходят одновременно
form:         в форме публикации tls_ca и tls_ca_certs — списки строк любой длины; не список строк — поле не взято (P/09.1
              Н1.2 out_of_delta); всё прочее — длина, повтор, не 64 строчных hex, не PEM, не CA:true, не сходится —
              проверка on_accept: ничего не меняется, журнал domain.member.ca.refused, отчёт принимается (решение
              «Архитектора» по сверке М11, D10)
Entry.ca:     поле записи члена (Н1.1): [<отпечаток>…], 1–2, по возрастанию, без повторов; нет — отпечатков нет
domain/members/<член>/ca-certs: {certs: JCS [<PEM>…]}   # у держателя; писатель — процесс domain; сертификаты центров
              члена в порядке его Entry.ca; Entry, ENTRY_MAX (глава 8.10 Н1.5) и подпись списка их не несут — член их не
              читает: peer ищет якорь в цепочке сервера по отпечатку (договор peer); в state резервной копии (глава 8.8 Н1.5)
on_accept:    держатель, после исхода same, heard или generation приёма (договор приёма отчёта, шаги 2, 6, 7), если body.tls_ca
              есть, непусто и (≠ Entry.ca или строка ca-certs не та): больше двух — ничего не меняется, журнал
              domain.member.ca.refused {member, reason: "more than two"}; повтор или не 64 строчных hex — так же, reason:
              "not fingerprints" (сверка М11, D10); tls_ca_certs нет, не той длины, элемент не PEM по договору peer шаг 2, не
              CA:true или sha256 не сходится — ничего не меняется, журнал domain.member.ca.refused {member,
              reason: "certificates do not match"}; иначе сначала строка ca-certs (put), затем Entry.ca = tls_ca по CAS
              domain/members (rev + 1; Entry.ca уже тот — без записи), журнал domain.member.ca {member, ca}; tls_ca нет
              или [] — ничего не меняется (снимает только администратор); отпечатки не по возрастанию — держатель и дверь
              admin записывают их отсортированными, сертификаты — в том же новом порядке (не отказ)
relayed:      отпечатки члена за ретранслятором — из пересланной публикации (Н1.3а; P/09.2 Н1.4): то же доверие, что к ней
admin:        POST /domain/members/<член>/ca {ca: [<отпечаток>…], ca_certs?: [<PEM>…]} у консоли домена → процесс domain
              (глава 8.0), грант admin (глава 8.4): заменить Entry.ca; ca_certs — проверка как у tls_ca_certs, в том числе
              CA:true (иначе 400); тот же ca снова — новая запись, rev + 1 (совпало у реализаций, записано сверкой М11),
              строка ca-certs пишется до Entry.ca; без ca_certs строка не меняется, и член вне объединения рукопожатия,
              пока сертификатов под новыми отпечатками нет;
              [] — снять Entry.ca и удалить строку ca-certs; журнал domain.member.ca {member, ca, by}; by — доказанное
              сторожевой имя
```

Кто читает отпечатки и сертификаты: клиент двери другого кластера — [договор `peer`](../../common/contracts/peer.md)
(владелец P/09; первый контакт `DOMAIN_CA`, `RELAY_CA`, `RELAY_MEMBER` — там же); дверь роли консоли домена
(объединение центров принятых членов в рукопожатии, запрет возобновления сессий) — [договор сертификата роли](../../common/contracts/role-certificate.md)
«Серверная сторона: класс `role`» (набор доверия `trust_set`). Роли комплектов домена — [договор сертификата роли](../../common/contracts/role-certificate.md); серверная сторона
класса `signed` — [глава 8.0](08.0-domain.norms.md) и тот же договор (разбор ревью стадии B 8–10, № 22: М-9); TLS между кластерами на одной машине стенд не поднимает (Н5).

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. ## Н3 Проход

### принять(mark, stored, body, via, heard_ago) — держатель, на POST /api/member/<член> после подписи

Абзац о `via` и `heard_ago`, шаги 0–7 и абзац о `sent_at`, ответе и сбое — [договор приёма отчёта](../../common/contracts/accept.md) «Функция
«принять»» (владелец P/08, глава 8.3; участник — ретранслятор 9.2; перенесено туда без изменения, номера шагов прежние;
разбор ревью стадии A 8–10, № 13 / решение 2). Векторы — [`common/vectors/accept`](../../common/vectors/accept/README.md).
Держатель исполняет её на `POST /api/member/<член>` и для каждого члена пакета ретранслятора (Н3 «держатель на POST
/api/relay»); ответ — carry (Н1.5).

### прочитать копию (глава 8.1 Н3 шаг 2; главы 8.5, 8.8)

```
прочитать reported; прочитать reports/<reported.rev>; sha256 не тот или объекта нет → копии нет (член silent в виде главы 8.1);
иначе копия — whole этого поколения; объекты выше метки не читаются
```

### принять члена (процесс domain, POST /domain/members через консоль домена — глава 8.0)

```
1. name — держатель → 400; name = domain → 400 «domain is the name of the domain's own grants» (глава 8.4 Н1.9);
   name уже член: fingerprint = отпечаток его Entry.key → 200 без записи; иначе → 409 «<name> was admitted with another
   key: have it leave first» (член не стучится — «уже член» раньше knocking; решение «Архитектора» по сверке М11, D20);
   name нет в view.knocking → 404 «<name> is not knocking»
2. fingerprint ≠ отпечаток knock.key → 409 «<name> presents another key than the one compared: look again»;
   knock.key малого порядка или не точка кривой (договор подписи агента — ключ малого порядка; P/09.1 Н1.1 pub; разбор ревью стадии B 8–10, № 22: М-1) → 409 «<name> presents a key that signs nothing» (сверка М11, M1)
3. knock.pinned = another → 409 «<name> pinned another root than this domain's: join it again»
4. knock.key в revoked_members набора или в revoked_keys записи этого имени → 409 «this key was revoked»
5. (шаг «уже член» — в шаге 1)
5а. name не член, а в domain/members уже MEMBERS_MAX (500) записей → 409 «too many members: the list holds 500»
   (глава 8.10 Н1.5; добавлено М11/12)
6. записать domain/members по CAS: rev + 1, term — свой, Entry {how: "admitted", since, by, key}; любая Entry документа (глава 8.10 Н1.5 every_entry; сверка М11, N6) больше
   ENTRY_MAX (глава 8.10 Н1.5) — 409 «the entry of <name> would exceed 820 bytes»; конфликт CAS →
   перечитать и повторить с шага 4 не больше трёх раз, затем 409 «the list of members kept changing; look again»
```

### держатель в списке (процесс domain, при старте и при приёме отчёта своего агента)

```
1. имени держателя нет в domain/members, или его Entry не how: "holder" (после переноса и передачи: из копии — admitted,
   глава 8.8 Н1.1 claim) → записать по CAS Entry {how: "holder", since, key?} — key прежней Entry, если есть, иначе без key;
   by нет (форма Entry держателя одна — Н1.1)
2. отчёт агента держателя: Entry держателя без key → проверить подпись ключом, который отчёт предъявил (P/09.1 Н1.2 key),
   и вписать его в key по CAS; дальше — как у любого члена: другой ключ — 403
```

Держатель отчитывается о себе подписанным отчётом, как любой член (ответ на записку модуля, п. 5); отпечаток человек
не сверяет: процесс `domain` и агент — на одном кластере. Взятие срока и прежний держатель — глава 8.8.

`DELETE /domain/members/<член>`: держатель — 400; не член — 404; иначе убрать запись по CAS, `rev + 1`. Ушедший член
не читается следующим проходом вида (глава 8.1): его копия и стук забываются в тот же проход.

### держатель на POST /api/relay/<ретранслятор>

```
1. ретранслятор, ключ и подпись — по порядку строки Н2 POST /api/relay (C08-G06)
2. для каждого relayed[член]: имя не по грамматике имени члена → refused[<имя как пришло>] и пропуск (пакет живёт:
   решение «Архитектора» по сверке М11, H1); член не в списке или via[член] ≠ ретранслятор → refused «<член> does not reach the domain
   through <ретранслятор>: the topology says <via или direct>»; key публикации ≠ key записи члена или отозван (revoked_keys,
   revoked_members набора) → refused «<член> presents another key than the one in the list, or it was revoked», ничего
   не записано; больше BODY_LIMIT → refused; иначе принять (договор приёма отчёта)
   с via = ретранслятор и байтами relayed[член] (JCS); отказ принять → refused (слово договора приёма отчёта)
3. стуки — P/09.2 Н1.4 knocks; стук не по форме P/09.2 Н1.4 — пропуск без записи, пакет живёт (решение «Архитектора» по сверке М11, H2);
   стуков больше KNOCKS — сверх первых 32 по имени пропуск без записи, тело стука больше 256 KiB — пропуск без записи
   (договор приёма отчёта «Пакет ретранслятора: пределы»; C08-G05)
4. ответ: relay_for по топологии, relayed — carry каждому члену relay_for (rev — для этой дороги), refused, keys
```

Пакет ретранслятора (`relayed`, `knocks`), ответ (`relay_for`, `relayed`, `refused`, `keys`) —
[P/09.2](../../09-agent/spec/09.2-agent.norms.md) Н1.4; `BATCH_LIMIT` и `KNOCKS` — [договор приёма отчёта](../../common/contracts/accept.md) «Пакет ретранслятора: пределы»; схема тела двери и ответа — [контракт урока](08-domain.api.openapi.yaml). Стук из пакета
держатель проверяет подписью ключом, который тело предъявило, над `POST /api/member/<имя>` и телом: верная — стук
(Н1.1 `knock`), неверная или член — пропуск (P/09.2 Н1.4 `knocks`).

**Гонки.** Список пишет один процесс `domain` (глава 8.0): правки людей, держатель в списке, `claim` и `Entry.ca` (Н1.6;
глава 8.8) — по CAS одной строки, конфликт — перечитать. Агент строк держателя не пишет. Приём отчёта и проход вида — в
одном процессе `domain`, вид читает метку и поколение не выше неё. Приём `tls_ca` и правка администратора одной записи —
CAS `domain/members` (Н3 «принять члена»). Две дороги одного члена — правило Н1.3а: держатель не смешивает их тела.
