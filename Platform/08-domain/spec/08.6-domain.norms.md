# P/08.6 — Назначение и правки: нормы

Канон главы 8.6 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/6/README.md). Здесь — два действия держателя над единицами членов: назначение (кто исполняет
единицу, счётчик `domain/placement`, ответ агенту только с записями, которые называют члена) и хранимая правка единицы
члена (отказы по виду домена, строка ждущих `domain/pending/<член>`, исходы и `settle`, секрет в правке — 400).

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из
М11/6 — сторона держателя: Н1 «Время», «Данные» и абзац общего, Н1.1,
из Н1.2 — ответ держателя `carry.placement` (фильтр `records`; разбор ревью стадии A 8–10, № 20), Н1.3, Н1.4, Н1.6,
строки Н2 дверей, которые консоль домена передаёт процессу, Н3 «записать назначение» с абзацем о мьютексе и подъёме
счётчика при старте, «принять правку», «исход», «Гонки», Н4, сц. 01, 02, 03, 05, 09 приёмки М11/06 и их строки Н5, п. 1
«Решает реализация». Остальное М11/6: копия у члена (Н1.2 `member`, `readers`), применение агентом и исход
(Н1.5 `apply`, `outcome`, `retry`, `same_path`, `domain/outcomes`, `publication.outcomes`, `holder_self`) и п. 2 «Решает
реализация» — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) урока P/09 (Н1.5, «Решает реализация» п. 6); двери `GET /domain/placement`,
`GET /domain/placement/<sub>/<ref>` отвечает консоль домена сама — урок P/10 ([Н1.2г](../../10-domain-console/spec/10-domain-console.norms.md); список дверей — [договор пересылки](../../common/contracts/forwarding.md) «Двери домена»); теневой
отчёт с исполнителями назначения — [глава 8.1](08.1-domain.norms.md) (P/08.1-10). Номера подразделов — прежние номера
источника (М11/6). Ссылка «P/0N[.K]» — урок или глава модуля; «М11/N» — урок-источник М11 (снят переносами уроков 8–10; новые адреса — id-map); «глава 8.K» —
глава этого урока. Id норм — `P/08.6-MM`; соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [P/01.1 Н0](../../01-store/spec/01.1-store.norms.md#н0-словарь-слов)
(в том числе порядок массивов вывода, область — уроки 8–10).

## Н1 Форма

**Время.** Поля времени строк главы — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): `domain/placement/<sub>/<ref>` — `at`; правка в `domain/pending/<член>` — `at`; исход в `domain/outcomes/<член>` — `at`, `kept_at`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/placement`, `domain/placement/<sub>/<ref>`, `domain/pending/<член>`, `domain/outcomes/<член>`;
- пишет: `domain/view` (cas);
- читает: `domain/members`, `<sub>/<spec:unit.rows>/<id>`.

Поля `pending` и `outcomes` объекта `domain/view` (владелец — [глава 8.1](08.1-domain.norms.md)) процесс пишет в
проходе вида (Н1.6). Копии назначений `domain/placed`, `domain/placed/<sub>/<ref>` и строку исходов члена
`domain/outcomes` пишет агент члена — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md)
Н1.5. Формы записи назначения и исхода общие у держателя и агента — определения `common.domain_placement` и
`common.domain_outcome` [общих определений семей](../../common/data/common.form.yaml) (решение «Архитектора» по планам
переноса 8–10, п. 3).

Общее [глав 8.2](08.2-domain.norms.md) и [8.3](08.3-domain.norms.md) Н1 действует. Назначение пишет только оператор:
размещение единиц доменом по достижимости — долг в `ХОД-Спецификация.md` (ответ на записку М11 п. 3). Домен не пишет
строк в члены: правку члена применяет агент члена ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.5) через дверь единиц своей
консоли ([P/06.1](../../06-console/spec/06.1-console.norms.md)).

### Н1.1 Назначение у держателя

```yaml
domain/placement/<sub>/<ref>:   строка хранилища держателя; элементы — строки (P/01.1):
  cluster:   член-исполнитель; обязателен
  origin:    член-владелец источника; "" — нет
  copies:    текст JCS массива других исполнителей, по возрастанию, без повторов, без cluster; "[]" — нет
  reason:    слова оператора; "" — нет
  at:        стенные секунды процесса domain записи, десятичным текстом
  rev:       значение счётчика domain/placement этой записи, десятичным текстом
domain/placement:   {rev} — счётчик, +1 на каждую запись и удаление назначения
writer:     процесс domain по двери Н2 консоли домена (глава 8.0 Н1.8); агенту запрещено (P/02.5 Н1.4а domainagent)
readers:    процесс domain (вид главы 8.1, теневой отчёт главы 8.1 Н1.6, ответ агенту — Н1.2); воркер на держателе — через
            чтение domain/placed/<sub>/ (P/02.5 Н3 шаг 3 даёт и domain/placement/<sub>/)
executors:  исполнители ref — cluster и copies; origin — не исполнитель
ref:        не проверяется на существование: назначение может опередить единицу (теневой отчёт — orphaned через
            SHADOW_STALL); в пути — остаток после <sub>/ байт в байт, процент-формы не декодируются (`a%20b` — ref
            «a%20b»); не по грамматике имени P/06.1 Н1.3 named (в том числе с `/`: `/domain/placement/testsub/a/b`) — 400
            (добавлено сверкой М11, A7)
form:       cluster — непустая строка: "" — 400, не 409 (добавлено сверкой М11, A6)
```

### Н1.2 Ответ держателя: назначения члена

```yaml
carry.placement:  {rev, records: {"<sub>/<ref>": {cluster, origin, copies: [<член>…], reason, at, rev}}}   # глава 8.3 Н1.5
  records:   только назначения, которые называют этого члена: он — cluster, origin или в copies (минимум знания;
             цена ответа при сотнях членов — глава 8.10 Н1.9)
  rev:       счётчик domain/placement держателя
  absent:    поле нет, пока счётчика нет (rev 0)
```

Ответ строится под тем же мьютексом, что запись назначения, и после подъёма счётчика при старте (Н3 «записать
назначение»). Копия у члена (`domain/placed/<sub>/<ref>`, `domain/placed`) — что агент пишет по этому полю, без отката, и
её читатели — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.5 `member`,
`readers`; держатель копий не пишет: его читатели берут запись (Н1.1 readers).

### Н1.3 Правка единицы члена доменом

```yaml
doors:      POST /domain/<sub>/<rows> {cluster, <поля>}        — создать единицу на члене cluster
            PUT /domain/<sub>/<rows>/<ref>[?cluster=<член>]   — править поля
            DELETE /domain/<sub>/<rows>/<ref>[?cluster=<член>] — удалить; тело — пустое или {}, иное — 400 (добавлено
            сверкой М11, A1)
            Idempotency-Key обязателен у всех трёх (иначе 400); грант admin у двери домена — урок P/10 (Н1.5;
            функция — договор права common/contracts/may.md)
            <sub> не из каталога (спеки нет или она без domain.ref, глава 8.1 Н1.2 no_ref) — 404, до разбора тела, у всех
            трёх (добавлено сверкой М11, A5)
            POST: cluster нет, не строка или пустая строка — 400, до поиска (добавлено сверкой М11, A4)
fields:     только поля domain.edit спеки (P/02.1 Н1.2а); платформенные (cluster, worker, server, placement, epoch,
            observed_revision, phase, revision) и поля вне domain.edit — 400; пустое тело PUT — 400; значения — по
            спеке (P/06.1 Н3 «создать» шаг 4 формы) — 400; POST дополнительно принимает обязательное поле domain.ref спеки, даже
            если его нет в domain.edit (у testsub edit — [start, labels], ref — name); у PUT исключения нет: ref — в пути
            (добавлено сверкой М11)
secrets:    *_secret на любой глубине, адрес с учётными данными — 400 «a secret is set in the member's own cluster, never
            through a kept edit» (P/06.2 Н1.4, P/02.1 Н4: domain.edit с секретом — отказ загрузки спеки; секрета через домен не передают)
order:      проверки тела по порядку: платформенные поля → секреты → поля вне domain.edit → пустое тело PUT → значения
find:       ref → член и id по виду домена (глава 8.1 Н1.4); ?cluster= — только этот член
refusals:   ровно глава 8.1 Н4 (М11/1 Н4):
  - ?cluster= не член списка                         → 404 {error: "no such member"}
  - ref в contested                                  → 503 {error: "refused", detail: называет членов}; так и при
    ?cluster= одного из спорящих — вид не держит единиц спорного ref; член вне спора — поиск только у него
  - ref не найден, кто-то не ok (unseen, silent, never) → 503 {error: "refused", detail: называет молчащих}
  - ref не найден, ответ полный                       → 404 {error: "refused", detail: "<sub> <ref> is in no member of the domain"}
  - POST: cluster не член                             → 404 {error: "no such member"}
kept:       найденная единица (в том числе у члена silent — по его последней копии) и POST → правка хранится (Н1.4) и ответ
            202 {kept, cluster, what, note}; домен в члены не пишет
```

### Н1.4 Хранимая правка

```yaml
domain/pending/<член>:   строка держателя; элемент <id> — текст JSON правки
  edit:     {id, seq, what, method, path, body, key, at, base?, asked}
    id:     "e-" + первые 12 знаков hex sha256(UTF-8(член) ‖ 0x00 ‖ UTF-8(Idempotency-Key))
    seq:    номер приёма — значение элемента seq этой строки после +1 при приёме, под тем же CAS; seq задаёт порядок ждущих
            правок члена: по нему назначается base (ниже) и выдаются правки (carry); at — только время для людей и исходов
            (решение «Архитектора» по R41-09 прогона 41)
    what:   имена полей тела по возрастанию через «,», у POST — с полем domain.ref, без cluster (DELETE — "")
    method: POST | PUT | DELETE;  path — путь двери единиц консоли члена: /<sub>/<rows> или /<sub>/<rows>/<id>
            (id — местный id единицы из копии члена); body — объект полей (DELETE — {})
    key:    Idempotency-Key запроса
    asked:  {method, path, body} — запрос двери домена, как его принял процесс: путь Н2 с ref и ?cluster=<член> у PUT и
            DELETE, тело с cluster у POST; по нему правку повторяют у нового держателя (глава 8.8 Н1.6 apply);
            path нормализован: у PUT и DELETE — /domain/<sub>/<rows>/<ref>?cluster=<член найденный>, даже если запрос
            ?cluster= не нёс; у POST — /domain/<sub>/<rows> без query; прочий query запроса в path не входит
            (добавлено сверкой М11, A3)
    at:     стенные секунды процесса domain; если по этому id уже записан исход (строка domain/outcomes/<член> держателя,
            Н1.6) — не меньше следующего за его kept_at
            числа (nextafter): новый приём того же ключа отличим от прежнего
    base?:  revision единицы в копии члена у держателя в момент приёма (PUT, DELETE); у POST нет; строки шарда с
            revision этой единицы в копии нет — base нет, правка идёт без If-Match; есть ждущая PUT того же
            path — base = base последней из них по seq + 1 (так применяется её результат, а не прежнее значение), у
            последней base нет — base нет и у новой; ждущая DELETE того же path —
            новая правка этого path отказывается 409 {error: "unit is being deleted"}
            # ждущая правка не применилась (conflict) — следующие того же path тоже дадут conflict: оператор решает заново
writer:     процесс domain — приём (Н3, дверь консоли домена — глава 8.0 Н1.8) и снятие исполненной (Н3 «исход»); CAS строки
repeat:     тот же id и те же method, path, body — 202 с прежней записью, at прежний; иное — 422 {error: "this Idempotency-Key
            was used for another edit"}; нечитаемая прежняя запись этого id — 422 (ключ не переиспользуется)
KEPT_LIMIT: 50          # ждущих правок на члена; 51-я — 409 {error: "kept_full", detail: "<член> has 50 edits waiting"}
reply:      202 {kept: <id>, cluster: <член>, what, note: "kept; <член> applies it when it next reports"}
carry:      ответ держателя (глава 8.3 Н1.5) несёт pending: [<edit>…] этого члена по seq; элемент seq строки — счётчик, не правка
           (правки — элементы e-…; KEPT_LIMIT считает их)
```

### Н1.6 Исходы у держателя и вид

Исход — форма агента ([глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.5
`outcome`): `{id, status, result, error?, at, what, kept_at}`; копия члена несёт исходы полем `outcomes` публикации
(там же, `publication.outcomes`).

```yaml
domain/outcomes/<член>:  строка держателя; элемент <id> — исход (P/09.1 Н1.5); OUTCOMES_LIMIT 50 — последние по (at, id) убывая
settle:     исход из копии члена принят, если правка с этим id ждёт, kept_at = at правки, what совпал; запись исхода —
            затем снятие правки по CAS, если она не менялась; исход, чей ключ в publication.outcomes ≠ его id внутри, не
            засчитывается: журнал держателя domain.outcome.ignored {member, key, id}, правка ждёт (решение «Архитектора»
            по сверке М11 05–08)
domain/view.pending:   {<член>: <число ждущих правок>} — каждый член списка, 0 — ждущих нет; считает проход вида (глава 8.1
                       Н3, раз в VIEW_EVERY), не дверь в момент ответа (решение «Архитектора» по сверке М11, A8)
domain/view.outcomes:  {<член>: [<исход>…]} — строка domain/outcomes/<член> по (at, id) убывая
```

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `domain/placement` — строка

Схема — [`placement.form.yaml`](../data/placement.form.yaml), исходы — [`placement.outcomes.tsv`](../data/placement.outcomes.tsv); версия формы 1; норма — P/08.6 Н1.1, Н3 «записать назначение».

| Ключ | Тип и границы | Обязательность | Урок | Смысл |
|---|---|---|---|---|
| `rev` | целое; ≥ 1; ≤ 9007199254740991 | обязателен |  | счётчик domain/placement — rev последней записи или удаления назначения (Н1.1); ответ агенту несёт его в carry.placement.rev (Н1.2) |

Исходы нечитаемой строки:

| Путь отказа | Исход | Приоритет | Единица | Норма |
|---|---|---|---|---|
| строка целиком | строка целиком нечитаема: процесс domain — запись и удаление назначения берут r = rev + 1 (Н3 «записать назначение» шаг 3), ответ агенту несёт rev (Н1.2 `carry.placement`), подъём при старте — +1 к rev (Н3); исход нечитаемого счётчика норма не называет: нечитаемое не подменяется отсутствием (rev 0 — только «строки нет», Н1.2 absent) (нынешнее поведение по тексту норм; норма исхода не называет; долг сверки свидетелей: сверить с реализациями и записать нынешнее поведение по DIALECT §9 до выпуска (разбор ревью стадии B 6–7, № 39)) | 0 | строка | P/08.6 Н1.1, Н1.2, Н3 «записать назначение» |

Схема — [`placement-record.form.yaml`](../data/placement-record.form.yaml), исходы — [`placement-record.outcomes.tsv`](../data/placement-record.outcomes.tsv); версия формы 1; норма — P/08.6 Н1.1.

| Ключ | Тип и границы | Обязательность | Урок | Смысл |

| `origin` | строка; целиком `([a-z0-9-]{1,64})?` | обязателен |  | член-владелец источника; "" — нет; origin — не исполнитель (P/08.6 Н1.1 executors) |
| `copies` | список, без повторов, элемент — строка; целиком `[a-z0-9-]{1,64}`; в `items` — текст JSON, у писателя — JCS (encoding: jcs) | обязателен |  | текст JCS массива других исполнителей, по возрастанию, без повторов, без cluster; "[]" — нет (порядок и «без cluster» — правила урока, не формы) |

| `rev` | строка; целиком `[1-9][0-9]*` | обязателен |  | значение счётчика domain/placement этой записи, десятичным текстом (P/08.6 Н1.1 rev) |

Исходы нечитаемой строки:

| Путь отказа | Исход | Приоритет | Единица | Норма |
|---|---|---|---|---|
| строка целиком | строка целиком нечитаема: читатели записи — процесс domain (теневой отчёт главы 8.1 Н1.6, ответ агенту Н1.2 `carry.placement`, сравнение «то же содержимое» Н3 «записать назначение» шаг 2) и воркер на держателе (P/02.5 Н3 шаг 3) — исход норма не называет; запись назначения дверью PUT пишет строку поверх, DELETE удаляет (Н3 шаг 3) (нынешнее поведение по тексту норм; норма исхода не называет; долг сверки свидетелей: сверить с реализациями и записать нынешнее поведение по DIALECT §9 до выпуска (разбор ревью стадии B 6–7, № 39)) | 0 | строка | P/08.6 Н1.1, Н1.2, Н3 «записать назначение» |

## Н3 Проход

### записать назначение (процесс domain, PUT и DELETE `/domain/placement/<sub>/<ref>`)

```
1. форма, спека, имена — по порядку Н2                                          → 400 / 404 / 409
2. PUT: то же содержимое, что в строке                                          → 200 без новой rev
3. r = domain/placement.rev + 1; PUT — записать строку domain/placement/<sub>/<ref> с rev = r и at; DELETE — удалить
   строку (её нет — 404)
4. domain/placement := {rev: r} по CAS (конфликт — перечитать и повторить шаги 3–4, до 8 попыток, затем 503)
5. 200
```

Ответ агенту (Н1.2) строится тем же процессом под тем же мьютексом, что запись: промежуточного состояния ответ не видит.
Обрыв между шагами 3 и 4 — строка новая, счётчик прежний: процесс `domain` при старте, до первого ответа агенту, поднимает
счётчик на 1 — члены перечитывают записи и сходятся (копии пишутся только при отличии —
[глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.5).

### принять правку (процесс domain, дверь консоли домена — глава 8.0 Н1.8)

```
1. Idempotency-Key есть; поля, секреты, значения — Н1.3                         → 400
2. найти (Н1.3 find, refusals)                                                  → 404 / 503
3. id = Н1.4; прочитать domain/pending/<член>: тот же id — repeat (202 / 422)
4. ждущих 50                                                                    → 409 kept_full
   ждёт DELETE того же path                                                       → 409 unit is being deleted
   base: копия члена; ждёт PUT того же path — base последней по seq + 1
5. seq строки + 1; edit {id, seq, what, method, path, body, key, at, base?, asked} → записать правку и seq одним CAS (конфликт — перечитать с шага 3, до 10 раз,
   затем 409 «the pending edits kept changing; ask again»)
6. 202
```

### исход (процесс domain, в проходе главы 8.1)

```
для каждого члена: исходы его копии (глава 8.3 Н3 «прочитать копию», поле outcomes публикации) → settle Н1.6:
записать domain/outcomes/<член> (обрезать до 50), затем снять правку из domain/pending/<член> по CAS
```

**Гонки.** Приём и снятие — в одном процессе `domain`, CAS строки `domain/pending/<член>`; снятие одного id — только
неизменённой правки. Локальная правка единицы на члене между приёмом и применением — `If-Match` даёт 412, исход `conflict`: молча не
перезаписывается. Агент, получивший правку дважды (повтор ответа), — `Idempotency-Key` двери единиц ([P/06.1](../../06-console/spec/06.1-console.norms.md)) и правило
`kept_at`. Назначение и единица — разные строки: удаление назначения единицу не трогает. Обрыв агента между применением
и записью исхода в `domain/outcomes`: правка ещё ждёт и применяется снова — `POST` даёт прежний ответ по `Idempotency-Key`
([P/06.1](../../06-console/spec/06.1-console.norms.md)), `PUT` с `If-Match` — 412 и исход `conflict`, `DELETE` — 404 и исход `refused`; такой исход допустим: значение уже
применено, оператор видит его, перечитав единицу. Повтор ключа после исхода — новая правка (at — Н1.4); её base берётся
из копии члена, а шард снимка может отставать от значения, уже применённого прежней правкой, поэтому возможен 412 и исход
`conflict` — допустимо, оператор решает заново (совпало у реализаций, записано сверкой М11). Применение агентом —
[глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.5.
