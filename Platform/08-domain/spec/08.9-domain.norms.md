### Н1.2 The shared document

<!-- req: P/08.9-R003 -->

```yaml
document:        the holder's object domain/shared-docs/rev-<rev> — JCS {domain, term, rev, at, by, shared, issuer, kid, sig}
  shared:        {<sub>: {<имя>: <значение>}} — only what is declared by P/02.1 Н1.2б; subsystems and names ascending (JCS)
  term, rev:     the holder's term (P/08.8) and the number of the edit; the order — (term, rev), term is senior
  by:            the name proven by the gate; after a move — "domain"
  signature:     the issuing key, as the term record (term record contract, record.md; the check — the function record); an unsigned one
                 is never accepted
pointer:         domain/shared {doc: JCS {term, rev, sha256, object}} at the holder; sha256 — hex sha256 of the text of the object;
                 object — the key of this object, the string "domain/shared-docs/rev-<rev>" with rev of the pointer (review of stage A 8–10, № 26)
write:           first the object, then the pointer by CAS (two edits at once — one gets 409); the holder keeps
                 the last 5 objects. The process executes the edits of the shared document one at a time (the steps of Н1.3 order 3–6 — one
                 edit at a time). The revision object — by the order G6, as the objects without a pointer (P/08.10 Н1.7 objects): a snapshot
                 of the pointer domain/shared (by it the object is recognised as nobody's) → get_at of the revision object → the confirmation of its own
                 turn domain/signer-turn → a write by the index of THIS get_at (object store client contract «Operations» ops): there was no object — put_new;
                 it exists with the same bytes — do not write; it exists with other bytes — the pointer does not name it (rev of the object is higher than
                 rev of the pointer: the former edit broke off between the object and the pointer), the object is nobody's — put_at over it
                 (the Architect's decision of 2026-10-20 on the questions of the assembly of lesson 8, item 2; the Architect's decision, review of stage B 8–10, № 1, ADR-0083 addendum (15)); the turn is lost between
                 the read and the confirmation — 503 to the edit by P/08.10 Н1.7, the object is not touched; put_new or put_at got
                 conflict — the object changed after get_at, another edit or another process writes it: 409 to the edit «the shared
                 settings changed while this edit was made — look again», the object is not touched — the losing edit does not
                 overwrite the object of the winning one (added by the reconciliation of М11, A1)
after_move:      the new holder (P/08.8 Н1.8 step 8; the sum matched at no copy — it does not re-sign; at the exception of step 3 the pointer goes in the batch of step 8, C08-SHARED-SPLIT-BATCH-01) re-signs the same content as rev + 1, by "domain" — it has another
                 issuing key; at a planned handover the issuing key is the same, the document does not change
readers:         the process domain, the domain console, the subsystem worker on the domain (the role <sub>domain) — the pointer domain/shared
                 (the exact name) and the objects domain/shared-docs/rev-* (the family domain/* of the object door of P/05); the cluster console — the row domain/shared (the exact name: at the holder
                 the pointer, at a member the copy row, Н1.4; P/02.5 Н1.4 console, added by М11/11); the subsystem worker by worker.reads domain/shared — at a member the copy row and the object domain/shared,
                 at the holder's cluster the pointer and the object by its field object; it checks the sum and the signature itself, a mismatch — the former value (C08-CATALOG-SHARED-WORKER-01); there are no projections by subsystems (C6)
```

### Н1.3 Edit

<!-- req: P/08.9-R004 -->

```yaml
door:            PUT /domain/shared {base_rev?, shared: {<sub>: {<имя>: <значение> | null}}} and If-Match at the domain console (admin, P/08.4;
                 lesson P/10 Н1.3) → the process domain by the same path (ADR-0032; chapter 8.0); the body ≤ 1 MiB (otherwise 413 {error: "refused"})
order:           1. freeze, deposition — P/08.8 (503 frozen, 409 deposed)
                 1а. the headers and the repeat memory (chapter 8.0 Н1.9)
                 2. the body is not {base_rev?: integer ≥ 0, shared: object, every shared.<sub> — object}, neither If-Match nor base_rev, or they
                    differ (chapter 8.0 Н1.9 «base_rev») — 400 (shared.<sub> not
                    an object — also here, before base_rev; added by the reconciliation of М11, A9) {error: "refused", detail: "the edit is {base_rev:
                    <the revision it was made against>, shared: {<sub>: {<field>: value or null}}}"}
                 3. the revision before the content: If-Match is not equal to the version of the pointer — 412 revision moved; no header and
                    base_rev ≠ rev of the pointer (0 — no document) — 409 {error: "refused", detail: "the shared settings are at
                    rev N; the edit was made against rev M — look again"}
                 4. the content — all refusals in one 400 joined by «; »: «shared settings for '<sub>': no subsystem on the domain
                    shares a field by that name»; «'<имя>' is not in its domain.shared [<the names of domain.shared of the manifest joined by «, », ascending>]»; the type of the field — the same check
                    of the form as at the unit door (P/06.1 Н3 «create» step 4), on this one field, the refusal word — its; the value of a document
                    against its schema (the words of the schema); a value the console would seal (P/06.2 Н3) (a name *_secret at any depth,
                    a password found in an address by P/06.2 Н1.1а), — «'<имя>': the shared document is signed, not sealed» (reconciliation of М11, A6)
                 5. the new document: the former shared, over it — the values of the edit; null — remove the name; an empty subsystem —
                    remove; rev + 1, term — its own, at, by; the former document (the object the pointer names) does not read
                    or is not with its sha256 — 503 {error: "refused", detail: "the shared document at rev N does not read: nothing
                    is written"}, nothing is written: an edit over an empty one would lose the former values (reconciliation of М11, A7)
                 6. write (Н1.2 write); the target write is the pointer, the object goes before it and is repeated without harm (chapter 8.0 Н1.9 write);
                    CAS failed — 409 «the shared settings changed while this edit was made — look again»
answer:          200 {term, rev, by}, ETag — the index of the pointer; the log domain.shared.edited {term, rev, by}
```

**Races.** Two edits of the shared document — CAS of the pointer, the second gets 409. The holder is moved — the new one re-signs the
document (`rev + 1`), the members take it as new. A break between the object and the pointer (Н1.2 write): the object above the pointer

of this get_at). A change of the turn between the reads: the active A writes the object N+1, the deposed S read the index before the write of A — its
put_at gets conflict (409); S read the index after the write of A — the confirmation of the turn of S does not pass (503), the object of A is intact
(the Architect's decision, review of stage B 8–10, № 1, ADR-0083 addendum (15); the schedule of Codex R-B810-01, Claude Р-1). A member without a connection and an alarm storm — [chapter 9.1](../../09-agent/spec/09.1-agent.norms.md) Н3 «Races» and lesson P/10 (Н3
