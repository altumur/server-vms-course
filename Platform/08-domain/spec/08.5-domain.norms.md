# P/08.5 — Книги и индекс имён: нормы

Канон главы 8.5 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/5/README.md). Здесь — сторона держателя книг: сборка книги в проходе держателя, строки
`domain/<sub>/<книга>/<член>`, поле вида `books`, доставка книги в ответе агенту, маска секрета книги; индекс имён
`domain/names/<sub>/<книга>`, его проверки у дверей людей и грантов и доставка ключа по гранту.

Глава перенесена (стадия B, ADR-0083 доп. (1): без изменения поведения) из
М11/5: вводный абзац Н1, Н1.3 целиком, из Н1.4 — `carry` и
`mask` (сторона держателя), Н1.5 целиком, Н3 «сборка книги», строка держателя Н3 «доставка» и «Гонки», строки Н4 сборки,

и часть пункта 2 «Решает реализация»; из М11/9: Н1.7 целиком и
сценарий 05 Н5. Номера подразделов — прежние: Н1.3–Н1.5 — М11/5, Н1.7 — М11/9. Чего здесь нет и где оно:
- объявления `domain.books` и `domain.names` и их отказы загрузки (случаи `m51_books_*`, `m59_names_*`) —
  [P/02.1 Н1.2б](../../02-installer/spec/02.1-installer.norms.md) (глава позднего слоя 2.1, вводит эта глава; М11/5-01 →
  P/02.1-27);

- двери людей и грантов, которые исполняют проверки индекса имён, и их отказы — глава 8.4 (М11/9 Н2–Н4).

## Н1 Форма

**Время.** Полей времени у строк главы нет. Время, которое глава читает, — по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`until` строки гранта (правило Н1.3 `grant`; [P/08.4 Н1.3](08.4-domain.norms.md)) против стенных часов держателя.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/<sub>/<spec:domain.books>/<член>`, `domain/names/<sub>/<книга>`;
- пишет: `domain/view` (cas), `<корень объектов>/<каталог>/~lock` (create);
- читает: `domain/members`, `domain/members/<член>/reported`, `domain/members/<член>/reports/<rev>`, `domain/book-seal`, `domain/grants/<кластер>`, `domain/users/<имя>`, `domain/signer-turn`, `/etc/w2c/secrets/platform.key`.

Строки «владеет» пишет процесс `domain` проходом держателя (Н3 «сборка книги») под стражем очереди `domain/signer-turn`
([P/08.10 Н1.7](08.10-domain.norms.md)): строки собираемой книги — только при изменении открытого содержимого, строки бывших членов
собираемой и переносимой книги — удаляет (Н1.3 `write`); строки переносимой книги пишет воркер подсистемы на домене
([P/03.7 Н1.6](../../03-worker/spec/03.7-worker.norms.md) `carried_book`) — протокол строки задаёт эта глава. Поле `books`
вида `domain/view` (владелец объекта — глава 8.1) — Н1.5. Члены и их копии — список `domain/members`, метка
`…/reported` и поколение `…/reports/<rev>` (глава 8.3); ключ приёма книг — `domain/book-seal` ([P/08.2 Н1.4](08.2-domain.norms.md));
строки грантов получателей — `domain/grants/<кластер>`, люди домена — `domain/users/<имя>` (глава 8.4). Копию книги у
члена `domain/<sub>/<книга>` пишет агент (глава 9.1). Секреты строк единиц в доставке процесс открывает кольцом `/etc/w2c/secrets/platform.key` (владелец
файла — [P/02.4](../../02-installer/spec/02.4-installer.norms.md); Н3 «доставка»).

Общее Н1 урока P/08 ([P/08.2 Н1](08.2-domain.norms.md) «Общее для всех форм главы», [P/08.3 Н1](08.3-domain.norms.md)) действует. Книга — наблюдение, не власть: `from` прав
записи не даёт, писателя назначает размещение ([P/04](../../04-controller/spec/04-controller.norms.md)), секреты
запечатаны, `show` скрытого не раскрывает, широковещания нет (ADR-0074).

### Н1.3 Сборка у держателя

```yaml
inputs:       копия каждого члена списка (P/08.3 Н3 «прочитать копию»), включая держателя (его подписанный
              отчёт), и его состояние вида (глава 8.1 Н1.3)
contributes:  член ok или unseen (копия есть); silent, never, копии нет — не вкладывает
missing:      [{member, why}] — по member; один на книгу; правило одной фразой: **чего нет в книге из-за члена — тот в
              missing**
  why:        unseen | silent | never | no_copy | bad_contribution | secret_unopened     # закрытый список слов
              # unseen и вкладывает, и в missing: ответ неполон, пока смена не увидена (глава 8.1)
              # у члена одна запись missing: unseen со снятым вкладом — why причины снятия (bad_contribution,
              # secret_unopened), не unseen (сверка М11, совпало у реализаций)
bad_contribution: вход не объект или не JSON, нет key или он не непустая строка, to не имя/список имён, повтор key у
              одного члена при unique → весь вклад члена в этой книге снят, член — в missing
secret_unopened: секрет вклада не открылся (договор конвертов домена «Конверт x25519:v1»; в том числе конверт кольца,
              который член не открыл, — not_v1) → весь вклад снят, член — в missing; значение не раскрывается
pick:
  unique:     ровно один вклад на key во всём домене; два и больше — key в книге отсутствует (конфликт, диагностика Н1.5)
  all:        все вклады
result:       строка у держателя domain/<sub>/<книга>/<получатель> для каждого члена списка (включая держателя):
  "":         текст JSON {missing}
  <key>:      текст JSON {entries: [{member, item, value}], missing} — только элементы, где получатель в to
    member:   член-вкладчик (из происхождения отчёта, не из входа)
    item:     <слот>/<item> для семьи, <item> для одиночной строки
    value:    объект входа как есть (секреты — открыты и запечатаны кольцом держателя, ниже)
  order:      entries — по (member, item) в байтах UTF-8; ключи элементов — произвольно (строка хранилища)
  at_rest:    секреты value — конверты кольца держателя enc:v2 (договор запечатывания), AAD: ключ строки 0x00 «/<item строки>» +
              JSON Pointer секрета в тексте JSON элемента
  write:      строку переписывать, только если открытое содержимое изменилось; строку бывшего члена — удалить;
              книга в пути двери и в ключе строки — байт в байт, без раскодирования процентов (сверка М11, B6)
recipient:    элемент доставляется каждому члену из to, который есть в списке членов; имя вне списка не получает ничего
              ни в каком виде — оно попадает только в диагностику Н1.5 (undelivered)
grant:        книга с domain.names.<книга>/.grant (Н1.7) — ключ доставляется получателю, только если у него есть
              действующая строка гранта с subject = key и рангом не ниже grant (договор права, шаг 5); без гранта
              получатель видит только "" (missing); ключ — имя человека — не доставляется никому (Н1.7 reverse)
cadence:      сборка — в каждом проходе держателя (глава 8.1 Н3), после чтения копий
```

Договор запечатывания — [`Platform/common/contracts/sealing.md`](../../common/contracts/sealing.md) (конверт `enc:v2`, путь AAD, грамматика `kid`; дополнение Kimi к разбору ревью стадии A 6–7, SA67-Б4).
Открытие секрета вклада — [договор конвертов домена](../../common/contracts/domain-envelopes.md) «Конверт `x25519:v1`»
(ключ приёма книг — `domain/book-seal`, глава 8.2); действующая строка гранта и ранг — [договор права](../../common/contracts/may.md)
шаг 5 и строка гранта [P/08.4 Н1.3](08.4-domain.norms.md). Форма входа (`entry`: `key`, `to`, секреты `*_secret`) — [P/03.7 Н1.2](../../03-worker/spec/03.7-worker.norms.md);
вход в отчёте — объект (`in_report`, P/09.1 Н1.2).

### Н1.4 Доставка члену

```yaml
carry:        ответ держателя (P/08.3 Н1.5) несёт книги в sealed (конверт m1) полем books — форма: договор
              конвертов домена «Содержимое sealed» (разбор ревью стадии A 8–10, № 12)
mask:         значение секрета книги не попадает ни в дверь (дверь книги консоли кластера, OpenAPI урока 6), ни в журнал, ни в вид
              (P/06.2 Н1.4)
```

Строка книги у члена (`member_row`: элементы как получены, секреты — конверты кольца члена; писатель — агент; у кластера
держателя копии нет: держатель в `sealed` себе книг не шлёт и свою книгу читает из строки
`domain/<sub>/<книга>/<себя>`, ADR-0074) — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) (Н1.4
`member_row`). Конверт `m1` — [договор конвертов домена](../../common/contracts/domain-envelopes.md) «Конверт `m1`».

### Н1.5 Вид: поле `books`

```yaml
domain/view.books:   {"<sub>/<книга>": {conflicts, dropped, undelivered}}   # каждая собираемая книга каталога
  conflicts:   [<key>…] — ключи unique с двумя вкладами и больше, по возрастанию
  dropped:     {<член>: bad_contribution | secret_unopened} — снятые вклады (без значений и секретов)
  undelivered: {<член-вкладчик>: [<имя вне списка членов>…]} — получатели to, которых нет в списке, по возрастанию
  person_names: [<key>…] — у книги с domain.names: ключи — имена людей, не доставлены (Н1.7; добавлено М11/9)
```

Объект `domain/view` и прочие его поля — [P/08.1 Н1.4](08.1-domain.norms.md).

### Н1.7 Индекс имён

```yaml
spec:      domain.names.<книга>/: {exclusive_with: domain/users, grant?: view | edit | admin}
           <книга> — книга той же спеки с from (P/02.1 Н1.2б); иначе, или exclusive_with нет либо другое, или grant
           не из слов, или иной ключ — refused:reference (P/02.1 Н4; случаи m59_names_* корпуса P/02.1)
subject:   значение key вклада этой книги
domain/names/<sub>/<книга>:   у держателя; писатель — процесс domain после сборки книг прохода (Н3 «сборка книги»)
  items:   "" → JCS {missing: [<член>…]}; <key> → JCS {members: [<член>…]} — по возрастанию, из всех читаемых вкладов,
           включая спорные unique и недоставленные; значений и секретов нет
  missing: как missing книги Н1.5 — члены, чьих вкладов нет из-за них (silent, never, no_copy, bad_contribution,
           secret_unopened); член unseen — не missing: его вклад в книге есть
known:     индекс есть, читается и его missing пуст
checks:    у дверей людей и грантов (процесс domain), по индексам всех names каталога:
           POST /domain/users с именем — subject индекса                    → 409 name taken
           новая строка гранта (нет в прежней строке) с subject индекса и rank(cap) > rank(grant) → 400 grant too wide;
             subject — человек домена — проверок индекса нет: человек сильнее ключа индекса; прежняя строка «шире»
             не проверяется (добавлено сверкой М11, P5, P6)
           новый человек или новая строка гранта (нет в прежней строке), чей subject не человек домена (нет в
             domain/users), а индекс не known → 503 names unknown, detail — «missing members: <члены>» или «index
             absent or damaged»;
           новая строка гранта, чей subject не человек домена, индексы known, а такого key нет ни в одном индексе →
             400 unknown subject; строки, что были в прежней строке, не проверяются (журнал cammeta-go, М11-09 № 1; решение «Архитектора»); строка гранта человека домена (и root) индекса не ждёт: имена исключают друг друга
             (exclusive_with), человек ключом индекса не бывает
           каталог без книг с domain.names — индексов нет: все known и пусты; новая строка гранта, чей subject не
             человек домена, — 400 unknown subject, не 503 (решение «Архитектора» по cammeta-python М11-09 № 21)
           удаление человека и снятие строк — никогда не ждут
reverse:   элемент книги с names, чей key — имя человека, не доставляется никому: поле вида view.books.<sub>/<книга>.person_names
           [<key>…] по возрастанию (Н1.5, добавлено М11/9); в отчёте функции assemble его нет — её вход без людей
delivery:  Н1.3 grant — у получателя строка гранта с subject = key, rank(cap) ≥ rank(grant), действующая (договор права, шаг 5)
no_grant:  names без grant — ни предела ширины строки, ни условия доставки: ключ доставляется по to, как у книги без
           names; reverse действует
```

Двери людей и грантов, где стоят `checks`, их порядок шагов (проверки имён — шаг 6 «двери людей», шаг 4 «грантов») и
строки Н4 `name taken`, `grant too wide`, `unknown subject`, `names unknown` — [P/08.4 Н3, Н4](08.4-domain.norms.md); `rank` — порядок
`cap` строки гранта ([P/08.4 Н1.3](08.4-domain.norms.md)); человек и `domain/users` — [P/08.4 Н1.1](08.4-domain.norms.md).

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../common/data/codec.tsv): писатель пишет строго, читатель читает терпимо (DIALECT § 8). Ключ вне таблицы — отказ `key`, иной отказ — `value`. Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи (DIALECT § 9): путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

#### `domain/<sub>/<spec:domain.books>/<член>` — строка

Схема — [`book.form.yaml`](../data/book.form.yaml), исходы — [`book.outcomes.tsv`](../data/book.outcomes.tsv); версия формы 1; норма — P/08.5 Н1.3; P/03.7 Н1.6.

|---|---|---|---|---|

| `"".missing` | список, элемент — отображение `{member, why}` | обязателен |  | кого не хватает в книге — [{member, why}] по member в байтах UTF-8, один на книгу (P/08.5 Н1.3 missing); порядок и «один на член» — правило урока, не форма |
| `"".missing[]` | отображение `{member, why}` | необязателен |  |  |
| `"".missing[].member` | строка; целиком `[a-z0-9-]{1,64}` | обязателен |  | член, из-за которого в книге чего-то нет |
| `"".missing[].why` | строка; одно из: `unseen`, `silent`, `never`, `no_copy`, `bad_contribution`, `secret_unopened` | обязателен |  | закрытый список слов (P/08.5 Н1.3 why); у члена одна запись |

| `.<имя>.entries[].item` | строка; целиком `.+` | обязателен |  | `<слот>/<item>` для семьи, `<item>` для одиночной строки |
| `.<имя>.entries[].value` | отображение, opaque | обязателен |  | объект входа как есть; секреты *_secret — конверты кольца (enc:v2), AAD — ключ строки 0x00 «/<item строки>» + JSON Pointer секрета (Н1.3 at_rest) |
| `.<имя>.missing` | список, элемент — отображение `{member, why}` | обязателен |  | кого не хватает в книге — [{member, why}] по member в байтах UTF-8, один на книгу (P/08.5 Н1.3 missing); порядок и «один на член» — правило урока, не форма |

## Н3 Проход

### сборка книги (держатель, в проходе главы 8.1 Н3)

```
1. для каждой собираемой книги каталога: члены списка (P/08.3 Н1.1) с их состоянием вида и копией
2. член silent | never | без копии → missing (why — состояние или no_copy), вклада нет; метка есть, а её поколение не
   читается (P/08.3 Н3 «прочитать копию») — no_copy
3. член ok | unseen: объекты копии по from книги; unseen → в missing (why: unseen)
4. каждый вход: проверить форму входа (P/03.7 Н1.2 entry; объект в отчёте — P/09.1 Н1.2 in_report) у всех
   элементов вклада члена; ошибка → bad_contribution: весь вклад члена снят;
   затем секреты — открыть (договор конвертов домена «Конверт x25519:v1», seed — domain/book-seal), не открылся →
   secret_unopened: весь вклад снят
   (форма раньше секретов: элемент с секретом, который не открылся, и элемент не по форме — bad_contribution; добавлено
   сверкой М11, B2)
5. ключи: unique — один вклад на key, иначе конфликт (ключа нет); all — все
6. для каждого члена списка: элементы, где он в to; гранты (Н1.3 grant, Н1.7); строка domain/<sub>/<книга>/<член> по Н1.3 result
7. записать изменившиеся строки (секреты — кольцом держателя), удалить строки бывших членов; view.books — Н1.5
```

После сборки книг прохода — индекс имён каждой книги с `domain.names` (Н1.7 `domain/names/<sub>/<книга>`).

### доставка (держатель, в ответе агенту главы 8.3)

```
держатель: прочитать domain/<sub>/<книга>/<член> каждой книги каталога, открыть секреты кольцом → sealed.books (m1)
```

Запись у члена (агент: открыть `m1`, каждую книгу — в `domain/<sub>/<книга>` по CAS, книги, которой нет в ответе, не
трогать) — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) (Н3 «запись у члена»).

**Гонки.** Сборка читает копии в разные моменты (глава 8.1): книга — наблюдение. Захват слота и запись воркера под стражем —
[P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3: поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости
агента. Две сборки одной книги не пересекаются: держатель один ([P/08.8](08.8-domain.norms.md)). Обрыв на шаге 7 сборки — часть строк книги нового
прохода, часть прежнего, `view.books` прежний: следующий проход пересобирает из копий и дописывает отличия (запись только
при изменении); доставка до того несёт строку как есть — у члена книга одного из двух проходов, не смесь внутри строки.
