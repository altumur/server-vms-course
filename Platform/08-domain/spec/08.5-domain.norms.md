Канон главы 8.5 урока P/08 «Процесс domain» (ADR-0080; модуль «Платформа» — ADR-0083). [Лекция](../08-domain.md),
[контракт](08-domain.api.openapi.yaml), [инструкция](08-domain.README.md), [жизненный цикл](../lifecycle.md),
[приёмка](../acceptance/5/README.md). Здесь — сторона держателя книг: сборка книги в проходе держателя, строки
`domain/<sub>/<книга>/<член>`, поле вида `books`, доставка книги в ответе агенту, маска секрета книги; индекс имён
`domain/names/<sub>/<книга>`, его проверки у дверей людей и грантов и доставка ключа по гранту.

## Н1 Форма

**Время.** Полей времени у строк главы нет. Время, которое глава читает, — по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке):
`until` строки гранта (правило Н1.3 `grant`; [P/08.4 Н1.3](08.4-domain.norms.md)) против стенных часов держателя.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/book-keys/<sub>/<manifest:domain.books>/<раздел>`, `domain/<sub>/<manifest:domain.books>/*`, `domain/<sub>/<manifest:domain.books>/*/<раздел>`, `domain/folder-units/<id>`, `domain/folder-units/<id>/<раздел>`, `domain/folder-log`, `domain/folder-counts/<id>`, `domain/folders/<id>`, `domain/memberof/<член>/<sub>/<manifest:unit.rows>/<id>`, `domain/folder-rev`, `domain/<sub>/<manifest:domain.books>/<член>`, `domain/names/<sub>/<книга>`;
- пишет: `domain/view` (cas), `<корень объектов>/<каталог>/~lock` (create);
- читает: `domain/member-rows/<раздел>`, `domain/members/<член>/reported`, `domain/members/<член>/reports/<rev>`, `domain/book-seal`, `domain/grants/<кластер>`, `domain/users/<имя>`, `domain/signer-turn`, `/etc/w2c/secrets/platform.key`.

Строки «владеет» пишет процесс `domain` проходом держателя (Н3 «сборка книги») под стражем очереди `domain/signer-turn`
([P/08.10 Н1.7](08.10-domain.norms.md)): строки собираемой книги — только при изменении открытого содержимого, строки бывших членов
собираемой и переносимой книги — удаляет (Н1.3 `write`); строки переносимой книги пишет воркер подсистемы на домене
([P/03.7 Н1.6](../../03-worker/spec/03.7-worker.norms.md) `carried_book`) — протокол строки задаёт эта глава; воркер на
домене пишет её CAS по прочитанной версии, свою нечитаемую строку переписывает целиком своим содержимым, причина в
журнал без значения (В7 п. 3, решение «Архитектора» 2026-10-28, П2; строка 37 списка). Поле `books`
вида `domain/view` (владелец объекта — глава 8.1) — Н1.5. Члены и их копии — список `domain/member-rows/<раздел>`, метка
`…/reported` и поколение `…/reports/<rev>` (глава 8.3); ключ приёма книг — `domain/book-seal` ([P/08.2 Н1.4](08.2-domain.norms.md));
строки грантов получателей — `domain/grants/<кластер>`, люди домена — `domain/users/<имя>` (глава 8.4). Копию книги у
члена `domain/<sub>/<книга>` пишет агент (глава 9.1). Секреты строк единиц в доставке процесс открывает кольцом `/etc/w2c/secrets/platform.key` (владелец
файла — [P/02.4](../../02-installer/spec/02.4-installer.norms.md); Н3 «доставка»).

Общее Н1 урока P/08 ([P/08.2 Н1](08.2-domain.norms.md) «Общее для всех форм главы», [P/08.3 Н1](08.3-domain.norms.md)) действует. Книга — наблюдение, не власть: `from` прав
записи не даёт, писателя назначает размещение ([P/04](../../04-controller/spec/04-controller.norms.md)), секреты
запечатаны, `show` скрытого не раскрывает, широковещания нет (ADR-0074).

### Н1.3 Сборка у держателя

```yaml
inputs:       копия каждого члена списка (P/08.3 Н3 «прочитать копию»), включая держателя (его подписанный
              отчёт), и его состояние вида (глава 8.1 Н1.3)
contributes:  член ok или unseen (копия есть); silent, never, копии нет — не вкладывает; первые LOST_AFTER от `at` записи срока, взятого переносом или передачей (term ≥ 2; now − at ≤ LOST_AFTER по стенным часам процесса, `at` перезапуск не меняет, глава 8.8 Н1.1 `claim`), сборки нет: строки книг и индекс имён Н1.7 не пишутся, `view.books` пуст; never значит «ещё не слышал», и книга без вкладов заменила бы у читателей полную (C08-BOOKS-AFTER-TAKE-01, C08-BOOKS-WINDOW-01)
missing:      [{member, why}] — class server первыми, внутри по member; один на книгу; правило одной фразой: **чего нет в книге из-за члена — тот в
              missing**
  why:        unseen | silent | never | no_copy | bad_contribution | secret_unopened     # закрытый список слов
              # unseen и вкладывает, и в missing: ответ неполон, пока смена не увидена (глава 8.1)
              # у члена одна запись missing: unseen со снятым вкладом — why причины снятия (bad_contribution,
              # secret_unopened), не unseen (сверка М11, совпало у реализаций)
bad_contribution: вход не объект или не JSON, нет key или он не непустая строка, to не имя, не список имён и не "servers", у книги to: "*" — поле *_secret на любой глубине, неравные элементы
              одного key у одного члена при unique (равные — один вход, Н3 шаг 4а) → весь вклад члена в этой книге снят, член — в missing
secret_unopened: секрет вклада не открылся (договор конвертов домена «Конверт x25519:v1»; в том числе конверт кольца,
              который член не открыл, — not_v1) → весь вклад снят, член — в missing; значение не раскрывается
pick:
  unique:     ровно один вклад на key во всём домене; два и больше — key в книге отсутствует (конфликт, диагностика Н1.5)
  all:        все вклады
result:       строка у держателя domain/<sub>/<книга>/<получатель> для каждого члена списка (включая держателя):
  "":         текст JSON {missing, missing_count}: missing — первые MISSING_SHOWN 500: class server первыми (Entry, нет поля — server), внутри по member, missing_count — все: читатели судят серверы, режутся камеры; держать равным SERVERS_MAX 500 (P/08.10 Н1.5), иначе молчащий сервер уйдёт за список. Только здесь и с обрезкой: на каждом ключе и без обрезки он множил строку на число ключей, а при ~11 000 молчащих один "" был бы больше потолка у всех членов (разбор этапа 8, «Условие»). Читатель: missing_count больше длины missing — о члене вне списка не знает
  <key>:      текст JSON {entries: [{member, item, value}]} — только элементы, где получатель в to
    member:   член-вкладчик (из происхождения отчёта, не из входа)
    item:     <слот>/<item> для семьи, <item> для одиночной строки
    value:    объект входа как есть (секреты — открыты и запечатаны кольцом держателя, ниже)
  order:      entries — по (member, item) в байтах UTF-8; ключи элементов — произвольно (строка хранилища)
  at_rest:    секреты value — конверты кольца держателя enc:v2 (договор запечатывания), AAD: ключ строки 0x00 «/<item строки>» +
              JSON Pointer секрета в тексте JSON элемента
  write:      строку переписывать, только если открытое содержимое изменилось; строку бывшего члена — удалить;
              собранная строка больше потолка строки 524288 байт (P/01.1 Н1) не пишется: прежняя остаётся, журнал domain.books.too_large
              {sub, book, member} раз в проход и view.books.too_large (Н1.5), прочие строки, книги и проход идут дальше (C08-BOOK-CEILING-01);
              книга в пути двери и в ключе строки — байт в байт, без раскодирования процентов (сверка М11, B6)
recipient:    элемент доставляется каждому члену из to, который есть в списке членов; "servers" — членам списка этого прохода, чья Entry class server (нет поля — server), камера не получает ничего и в undelivered не идёт; имя вне списка не получает ничего
              ни в каком виде — оно попадает только в диагностику Н1.5 (undelivered)
grant:        книга с domain.names.<книга>/.grant (Н1.7) — ключ доставляется получателю, только если у него есть
              действующая строка гранта с subject = key и рангом не ниже grant (договор права, шаг 5, sub — подсистема книги: строка
              admin sub: testsub не доставляет ключ книги testsub2, ADR-0097 §4; только прямые строки: строки role: и таблица ролей не участвуют,
              ключ role:ops не доставляется никому, ADR-0098 §4, ADR-0099 §6; вход assemble таблицы не получает); без гранта
              получатель видит только "" (missing); ключ — имя человека — не доставляется никому (Н1.7 reverse)
cadence:      сборка — в каждом проходе держателя (глава 8.1 Н3), после чтения копий
to_all:       манифест объявляет книгу всем: domain.books.<книга>.to = "*" (P/02.1 Н1.2б); поле to входа не читается (ADR-0113 доп. (9) п. 1, доп. (11) п. 1)
  parts:      строка на раздел ключа: domain/<sub>/<книга>/*/<раздел>, раздел — 12 бит SHA-256(UTF-8 key), как у членов (P/08.3 Н1.1); <key> — {entries}, "" — {missing: [], missing_count: 0, term, rev}; ≈ 500 ключей на раздел: предел, сверх потолка строки — write выше. На получателя в строке нет ничего, поэтому секрета и гранта у такой книги нет
  head:       строка domain/<sub>/<книга>/* — только "": {missing, missing_count, term, rev, stale?, stale_count?}, полнота книги; missing и missing_count — как в result: иначе молчащие камеры переполнили бы строку; пишется по концу круга, при отличии; первая голова срока — по концу круга, начатого не раньше at записи срока + every срока + TURN_TERM: камера отчитывается раз в every, круг короче, и не слышанный ещё член лишил бы читателей живых дорог, а раздел, обойдённый до срока, терял бы отчёты после него; TURN_TERM 45 с (договор очереди) — окно готовности: слот в окне 503 standby не теряет дорогу. every срока считается один раз при взятии срока, формулой P/08.3 Н1.1а из domain/member-count, взятого переносом; пока сбор «из ничего» не закрыт и без счёта — 3600: счёт растёт вместе с отчётами, и срок на момент круга не держал бы ничего; перезапуск считает тем же правилом. Срок, а не полнота: молчащий голову не держит, копии держит first (ADR-0113 доп. (23) пп. 2, 4). Камера с retry_in больше every, потерянный отчёт и смена фазы до 1,5 every к сроку могут не успеть: при 250 000 камер около 1 % дорог на круг, предел; rev растёт только при смене «missing пуст / не пуст» и при смене состава class server в missing: состав молчащих камер поднимал бы всех читателей на каждый круг, а упавший сервер без этого в голове не виден, missing в живом домене почти всегда не пуст; серверов до 500, падают редко (ADR-0113 доп. (28) п. 1). Предел: падение одной записи в живом широком члене заметно за 45–320 с по окну BOOK_PARTS_SHOWN
  stale:      книга с domain.books.<книга>.stale (P/02.1 Н1.2б): голова несёт stale — <член>/<сервер>, у которых pulse.<sub>.stale вида (P/08.1 Н1.4), <sub> — подсистема книги, у членов ok и unseen; первые MISSING_SHOWN 500 по байтам UTF-8, stale_count — все. По подсистеме, а не по серверу: на сервере живой cam при мёртвом rec; сервер мёртв вместе с агентом — член молчит, он в missing (ADR-0113 доп. (27)). rev головы растёт при смене множества, и голова пишется сразу при смене, вне круга, а не по его концу: иначе при 250 000 камер около 3 мин против кольца 66 с; до первой головы срока — по правилу first (ADR-0113 доп. (31)–(33)). Предел: смерть видна с задержкой отчёта члена и LOST_AFTER агента; пульс, не дошедший до держателя, делает воркер молчащим и при живом
  version:    (term, rev) у каждой строки: term — срок записи, rev + 1 на записи, у головы — head; пара, а не номер: после переноса строки собираются заново
  круг:       сборка идёт кругом разделов вида (P/08.1 Н1.4б), не проходом: для каждого члена раздела снимает ключи из domain/book-keys и кладёт ключи новой копии, в строках их разделов; молчащий снимается так же; ушедший — круг идёт и по разделам семьи book-keys: имя, которого нет в строке раздела членов, снимается; строки устаревают на круг: предел
  book-keys:  domain/book-keys/<sub>/<книга>/<раздел члена>: {"": {term}, <член>: [<ключ>…]} — какие ключи член дал, term — срок записи строки; раздел ключа по имени члена не найти, а память процесса старт не переживает; вне копии, пересобирается, как строки
  unique:     книга to: "*" при pick: unique — отказ каталога (P/02.1 Н1.4): строка не хранит проигравшего вклада, ключ мигал бы по кругу
  first:      пока голова /* текущего срока не записана, book_stale раздела не называет, а дверь отвечает 503 unavailable: копия держится; иначе новый держатель снимал бы копии всех читателей, книга без вкладов снова заменяла бы полную (C08-BOOKS-AFTER-TAKE-01). Голова, а не complete: молчащий член держал бы дверь закрытой навсегда, а малый домен закрывал бы круг раньше первой сборки. Предел: пока головы нет, новый читатель без копии получает 503, новая камера без дорог; это every, окно готовности и до двух кругов, при 250 000 камер до 1545 с, после сбора «из ничего» около часа
  first_pass: пока голова текущего срока не записана, круг строит с нуля: book-keys со term меньше текущего не читается, своего срока читается, строка книги пишется целиком; с записью головы строки со term меньше текущего удаляются: у нового держателя под теми же ключами лежат копии, а снять их ключи нечем. Предел: читатели кластера нового держателя видят неполные строки до записи головы
  order:      сначала строки разделов, book-keys последней: падение между ними повторяет снятие вхолостую, а обратный порядок потерял бы его. Пока голова текущего срока не записана, наоборот, book-keys раньше строк: снимать там нечего, а ключ строки без book-keys снять нечем до следующего переноса, одного term мало (ADR-0113 доп. (23) п. 1)
  ceiling:    строка book-keys больше потолка 524288 байт (около 10 тыс. ключей) не пишется: вклад члена, переполнившего её, снят, он в missing со словом bad_contribution, журнал domain.books.too_large
```

### Н1.4 Доставка члену

```yaml
carry:        ответ держателя (P/08.3 Н1.5) несёт книги в sealed (конверт m1) полем books — форма: договор
              конвертов домена «Содержимое sealed» (разбор ревью стадии A 8–10, № 12)
mask:         значение секрета книги не попадает ни в дверь (дверь книги консоли кластера, OpenAPI урока 6), ни в журнал, ни в вид
              (P/06.2 Н1.4)
```

Книга `to: "*"` идёт не в `sealed` и без просьбы до члена не доходит (ADR-0113 доп. (11) п. 1). Читатель объявляет `domain/<sub>/<книга>/` в `worker.reads` и кладёт просьбу `domain/book-want/<sub>/<книга>/<раздел>`; агент держит копии этих разделов под тем же ключом `domain/<sub>/<книга>/*/<раздел>`, копию растит правила члена, а не домен. Публикация называет `book_parts` — версии того, что он держит, и `null` просьбы без копии, `carry.book_stale` — что устарело или появилось: сравнение как у `members_rev`, версия на всю книгу подняла бы всех читателей на каждую смену. Широкий член несёт окно `BOOK_PARTS_SHOWN` 64 раздела по кругу, судятся только они: цена постоянна, отставание широкого члена — минуты; после переноса устарели все разделы, 4096 при `BOOK_PARTS_PASS` 8 за проход — около 43 мин: предел. Просьба живёт сроком: читатель обновляет `at` раз в `BOOK_WANT_EVERY` 86400 с, пока раздел нужен, агент считает её снятой при `now − at > BOOK_WANT_TTL` 259200 с и снимает строку сам: читатели делят строку раздела, поэтому снимать её никому из них нельзя. Берёт агент дверью `GET /api/book/<член>/<sub>/<книга>[/<раздел>]` ([глава 8.3](08.3-domain.norms.md) Н2), без раздела — голову; секретов в них нет. Читатель кладёт просьбу на любом кластере; агент кластера держателя её не исполняет: ключи те же, читается строка держателя. Смена срока от читателя ничего не требует: строки бывшего держателя становятся копиями, судятся через `book_parts`, строки без просьбы агент снимает. Читатель кладёт просьбы и при своём старте: часы агента, прыгнувшие вперёд, снимают просьбы сразу, это предел.

Строка книги у члена (`member_row`: элементы как получены, секреты — конверты кольца члена; писатель — агент; у кластера
держателя копии нет: держатель в `sealed` себе книг не шлёт и свою книгу читает из строки
`domain/<sub>/<книга>/<себя>`, ADR-0074) — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) (Н1.4
`member_row`). Конверт `m1` — [договор конвертов домена](../../common/contracts/domain-envelopes.md) «Конверт `m1`».

             (exclusive_with), человек ключом индекса не бывает

### Н1.8 Общие папки (ADR-0110 доп. (5) п. 3, ADR-0111 п. 13)

Папка — одна на домен, гранты `folder:<id>` живут у всех кластеров. Строка единицы стоит на члене, поэтому пары «папка + членство» одним пакетом нет: строка папки и строка членства — у держателя, цель членства судится стражем, копия у члена только для чтения. Без связи с доменом папку и членство не правят: отказ, а не расхождение, которое потом пришлось бы сливать.

```yaml
domain/folders/<id>:      {name, parent, deleted?, at, by, revision}   # у держателя; писатель — процесс domain
  id, name, parent, deleted: как P/06.8 Н1.1, Н1.2: родитель задаётся при создании, запись поверх надгробия — отказ; "" — корень домена
  counts:   из строки вынесено: domain/folder-counts/<id>: {<член>: <число>}, считает проход, строгий предел — строка раздела индекса domain/folder-units (ADR-0113)
domain/memberof/<член>/<sub>/<rows>/<id>: {folders: [<id папки>…]}                                 # у держателя; писатель — процесс domain
domain/folder-units/<id>/<раздел>: {units: [<член>/<sub>/<rows>/<uid>…]}    # индекс папки по единицам, раздел — 12 бит SHA-256(UTF-8 ссылки), по возрастанию; у держателя; писатель — процесс domain, тем же пакетом, что domain/memberof: domain/memberof ключевана членом, обратного пути нет
domain/folder-units/<id>: {parts: [<раздел>…]}    # голова: непустые разделы папки, иначе обход 4096 пустых; пишется тем же пакетом, только при переходе раздела пуст ↔ непуст: числа — у domain/folder-counts; строка раздела не вмещает ссылку — 409 too many members; конфликт CAS — перечитать, до 3 раз
domain/folder-rev:        {term, rev}   # пара: растёт с каждой записью двух семей, term — срок держателя; равенство копии — обе части, после переноса копия заведомо устарела
state:    три семьи — в state резервной копии (P/08.8 Н1.5): у членов дерева целиком нет, копии источником не служат; индекс domain/folder-units собирает восстановление Н1.8 шаг 7 из строк domain/memberof
doors:    GET /domain/folders → 200 {rev, folders: [{id, name, parent, index}…]} по id, index — для If-Match; вход — договор права gate; консоль домена отвечает сама; счётчики не выдаются
          POST /domain/folders {name, parent?} → 201; PUT /domain/folders/<id> {name} → 200; DELETE /domain/folders/<id> → 200 {deleted: <id>}
          GET /domain/memberof/<член>/<sub>/<rows>/<id> → 200 {folders, index}, строки нет — {folders: [], index: ""}: нужно составу папок (deviceIds) чужой единицы; консоль домена отвечает сама, право — view target этой единицы;
          PUT /domain/memberof/<член>/<sub>/<rows>/<id> {folders} → 200 {folders, revision}; пустой список снимает строку
          GET /domain/folders/<id>/units[?cursor=&limit=] → 200 {units: [{cluster, sub, rows, id}…], cursor?}: порядок сервера, limit до 1000, умолчание 200; cursor — <раздел>:<ссылка> места, правки между страницами его не сбивают; страница читает голову и не больше 8 строк разделов; консоль домена отвечает сама; страницу целиком судит только wide договора права, зритель домена: грант на папку лежит у одного кластера, а строка unit: закрывает единицу и под ним; иначе view target каждой единицы, как GET /domain/memberof, не больше UNITS_PAGE_CHECKS 200 проверок на страницу, недоступные отсеиваются, исчерпание — короткая страница с cursor; страница бывает короче limit и пустой при непустой папке: конец — только отсутствие cursor; плохой cursor — 400; папки нет — 404
          Idempotency-Key, If-Match — как у дверей домена (P/08.0 Н1.9), отказы и слова — P/06.8 Н4
rights:   дерево (POST, PUT, DELETE папки): wide договора права с cap = admin. Папка общая на все кластеры, строка одного кластера не решает за другие; администратор кластера дерево не правит: предел.
          Членство: на U — target с кластером <член>, cap admin; над F и G — may по domain/grants/<член>, unit — папка-объект; chains — из этих строк; таблица P/06.8 Н3 «права папки» в этой части
member:   цель: член в domain/member-rows/<раздел>, <sub>/<rows> — манифест с display.tree.folders: true, каждая папка жива (стражи строк папок и цепочки), не больше
          FOLDERS_PER_UNIT_MAX; есть ли единица, домен не знает: снимает связь gone ниже
limits:   FOLDERS_MEMBERS_MAX и FOLDER_ROW_MAX — на папку и член: столько несёт строка копии, судит domain/folder-counts с отставанием прохода: предел; строгий предел — потолок строки раздела индекса, 409 too many members; по домену предела членов нет.
          DOMAIN_FOLDERS_MAX: 4000 живых папок; больше — 409 too many folders. Дерево идёт ответом агенту целиком: предел, 4000 папок — около 500 КиБ каждому отставшему на правку
carry.gone_seen: [<ссылка>…]  # часть gone принятой копии, у держателя строк нет; поля нет, если пусто
domain/folder-log:  кольцо 1024 записей {rev, op, id?, ref?}: что менялось; carry.folders — дельта от rev копии, копия старше кольца — целиком (ADR-0113 п. 4)
carry.folders: {rev: {term, rev}, full?, folders: {<id>: {name, parent} | null}, memberof: {"<sub>/<rows>/<id>": [<id папки>…]}}   # дельта или целиком при full; null — папка снята; форма — контракт, Carry
  when:   в принятой копии члена есть domain/folders-state, его rev ≠ domain/folder-rev, own в нём нет или поднят; иначе поля нет. GET /api/carry без копии поля не несёт
  scope:  chains — только папки цепочек единиц этого члена (камера, DOMAIN_FOLDERS=chains); иначе всё дерево; memberof — только этого члена
domain/folders-state:     объект члена {rev, scope: all | chains, gone: [<sub>/<rows>/<id>…], own?}    # агент несёт в отчёте (P/09.1 Н1.5)
  gone:   единицы, снятые на члене: проход держателя снимает строки с индексом и уменьшает folder-counts; rev растёт, только если строка была снята; ссылки, которых у него больше нет, идут члену в carry.gone_seen, без rev: молчащий член других не тревожит; пока подтверждения нет, ссылка в gone.
          Предел: единицу удалили, создали с тем же id и положили в папку раньше прохода — запоздалый gone снимает новое членство
  own:    {folders: [{id, name, parent}], memberof: {<ссылка>: [<id папки>…]}} — папки кластера до входа в домен, не больше OWN_MAX = 1 МиБ; больше или сверх DOMAIN_FOLDERS_MAX — не поднято, журнал, carry.folders члену не идёт, папки не теряются, а двери /folders работают по-прежнему: уменьшить их можно;
          проход держателя заводит строки, которых нет: id случайны, столкновений нет; поднято — carry.folders идёт, в ней эти строки уже есть
reap:     проход держателя, по кругу разделов: строка членства, чья папка не жива, — снять тем же пакетом с индексом, domain/folder-counts/<id> уменьшить; уход члена (P/08.3 Н2 DELETE) — снять его строки и его ключ в folder-counts; оборвалось — следующий проход
leave:    вышедший кластер хранит копию только для чтения, запись закрыта: предел до снятия следа домена
```

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). ## Н3 Проход

### сборка книги (держатель, в проходе главы 8.1 Н3)

```
1. для каждой собираемой книги каталога: члены списка (P/08.3 Н1.1) с их состоянием вида и копией
2. член silent | never | без копии → missing (why — состояние или no_copy), вклада нет; метка есть, а её поколение не
   читается (P/08.3 Н3 «прочитать копию») — no_copy, хотя вид зовёт такого члена silent: причина ближе — копии нет
   (функция assemble: copies[член] = null — no_copy, вектор assemble-08-states; C08-MARK-NO-COPY-01)
3. член ok | unseen: объекты копии по from книги; unseen → в missing (why: unseen)
4. каждый вход: проверить форму входа (договор конвертов домена «Вклад» entry; объект в отчёте — P/09.1 Н1.2 in_report) у всех
   элементов вклада члена; ошибка → bad_contribution: весь вклад члена снят;
   затем секреты — открыть (договор конвертов домена «Конверт x25519:v1», seed — domain/book-seal), не открылся →
   secret_unopened: весь вклад снят
   (форма раньше секретов: элемент с секретом, который не открылся, и элемент не по форме — bad_contribution; добавлено
   сверкой М11, B2)
4а. при unique — элементы одного key у одного члена: равенство по JCS значения с открытыми секретами (конверты одного значения различны): равные — один вход, item наименьший в байтах UTF-8; неравные → bad_contribution: весь вклад снят. Один key под двумя слотами — обычное дело: новый первый воркер пишет, пока слот прежнего ещё держат, и снимать за это вклад незачем; предел: значение сменилось в этом окне — вклад снят, пока строка прежнего слота не уйдёт (C08-BOOK-SAME-ITEM-01, решение «Архитектора» 2026-11-01, Quint V/03.6 В1)
5. ключи: unique — один вклад на key, иначе конфликт (ключа нет); all — все
6. для каждого члена списка: элементы, где он в to; гранты (Н1.3 grant, Н1.7); строка domain/<sub>/<книга>/<член> по Н1.3 result
7. записать изменившиеся строки (секреты — кольцом держателя), удалить строки бывших членов; view.books — Н1.5, too_large — по исходу этого шага
```

После сборки книг прохода — индекс имён каждой книги с `domain.names` (Н1.7 `domain/names/<sub>/<книга>`).

### доставка (держатель, в ответе агенту главы 8.3)

```
держатель: прочитать domain/<sub>/<книга>/<член> каждой книги каталога, открыть секреты кольцом → sealed.books (m1);
           секрет не открылся — как нечитаемая строка: эту книгу этому члену в этом проходе не нести, причина в журнал без значения, прочие книги идут (C08-BOOK-SECRET-UNOPENED-01)
```

Запись у члена (агент: открыть `m1`, каждую книгу — в `domain/<sub>/<книга>` по CAS, книги, которой нет в ответе, не
трогать) — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) (Н3 «запись у члена»).

**Гонки.** Сборка читает копии в разные моменты (глава 8.1): книга — наблюдение. Захват слота и запись воркера под стражем —
[P/03.2](../../03-worker/spec/03.2-worker.norms.md) Н3: поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости
агента. Две сборки одной книги не пересекаются: держатель один ([P/08.8](08.8-domain.norms.md)). Обрыв на шаге 7 сборки — часть строк книги нового
прохода, часть прежнего, `view.books` прежний: следующий проход пересобирает из копий и дописывает отличия (запись только
при изменении); доставка до того несёт строку как есть — у члена книга одного из двух проходов, не смесь внутри строки.
