## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0](../../01-store/spec/01.1-store.norms.md#время-в-строке): объект `domain/view` — `as_of`.

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `domain/view`, `domain/shadow`;
- читает: `domain/members/<член>/reported`, `domain/members/<член>/reports/<rev>`, `domain/placement/<sub>/<ref>`, `domain/members`, `domain/topology`, `domain/keys`.

Вид и теневой отчёт пишет только процесс `domain` проходом держателя (Н3); объекты — по правилу очереди
[главы 8.10](08.10-domain.norms.md) Н1.7 `objects`. Поля вида других глав (`books`, `pending`, `outcomes`, `term`,
`shared`) процесс пишет тем же проходом, их форма и смысл — в главах-владельцах (шапка главы). `domain/keys` проход
читает для поля `trust` (Н1.2а; владелец строки — [глава 8.2](08.2-domain.norms.md)), `domain/topology` — для поля
`topology` (Н1.6а; владелец — глава 8.3), `domain/members` — список членов и поле `member_list` (Н1.7; владелец — глава
8.3), копии членов — по метке `reported` и поколению ([P/08.3 Н1.3](08.3-domain.norms.md) и Н3 «прочитать копию»), назначения — для
теневого отчёта (Н1.6; владелец — глава 8.6).

### Н1.1 Домен, член, держатель

```yaml
domain:      набор кластеров-членов под одним корнем доверия (глава 8.2); ни один raft не охватывает двух членов:
             у членов нет общей строки, слота, эпохи или объекта
member:      кластер М10 (одно хранилище строк, свой raft, свои процессы), принятый в список членов (`domain/members` у держателя — глава 8.3 Н1.1, `domain/member-list` у члена — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) Н1.1);
             имя члена — `CLUSTER` его установки (P/04 Н1.3а `cluster`), 1–64 знака [a-z0-9-], не пустое
holder:      ровно один член, на котором работают службы домена; держатель — роль члена, не вид кластера;
             какой член держатель — решение развёртывания (глава 8.8), не порядок установки
copy:        копия члена у держателя — то, что держатель принял от члена последним (глава 8.3 Н1.3: отчёт поколением и метка
             `reported`); домен читает члена только по его копии, к самому члену не ходит
```

**Чего кластер не знает.** Кластер отвечает о своих единицах и только о них. Три вопроса — уровень домена: где единица,
если этот кластер о ней не слышал («не у меня» ≠ «нигде»); в какой кластер ставить новую единицу (назначение — глава 8.6);
полон ли ответ. Поиск внутри кластера, размещение на воркер, перенос между воркерами — М10, домен их не повторяет и
воркер не пересекает границу кластера. Эпоха единицы монотонна в своём кластере ([P/03.2 Н1.5](../../03-worker/spec/03.2-worker.norms.md)); домену выдающий эпох не нужен.

### Н1.2 Имя единицы в домене

```yaml
ref:         значение поля `domain.ref` строки единицы (сводная таблица P/02.1 Н1.2а; у `testsub` и `testsub2` — `name`);
             номер единицы (`id`) принадлежит кластеру и в домене не ищется: у манифеста с `unit.id: numeric` id 1 есть в каждом
             члене (векторы Н5 — такие); у `testsub` id — имя (P/06.1 Н1.3), поиск — всё равно по ref
no_ref:      манифест без `domain.ref` в каталоге домена не участвует: его единиц нет в виде, дверь `/domain/<sub>/<rows>` — 404
no_value:    строка единицы без значения поля `domain.ref` (поля нет или "") — не единица домена: в `units` её нет, заявки
             теневого отчёта она не даёт (ни `unmanaged`, ни `conflict`), полноты вида не отнимает, `may_write` из-за неё не
             меняется; пульс такой единицы в отчёт члена идёт как прежде (ADR-0091 доп. (12) п. 2, доп. (13) п. 4)
```

### Н1.3 Свежесть члена и единицы

```yaml
LOST_AFTER:  договор наблюдения «Свежесть» (значение там)   # тот же срок, что у пульса воркера (аудит раскладки, решение «Архитектора» 2026-10-25, А-01)
member_state: договор наблюдения «Свежесть члена домена» (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, А-15)
unit_state:                                      # единица из копии члена
  live:      есть в `status[]` пульса воркера (P/03.4 Н1.1), и пульса нет в `stale` метки члена (публикация — P/09.1 Н1.2; метка — глава 8.3 Н1.3)
  stale:     есть в пульсе, и пульс — в `stale` метки: агент члена не видел его смены дольше LOST_AFTER по монотонным
             часам члена (живость воркера — факт кластера, P/04; домен её наблюдает, а не выводит из прихода копии)
  configured: есть только в шарде снимка (P/04 Н1.3а), ни один пульс её не ведёт
  silent:    член не `ok` (`unseen`, `silent`): единицы его последней копии остаются в виде с этим словом, не удаляются
  # смена пульса — смена его JCS (глава 8.2 Н1): `1` и `1.0` в любом поле — не смена (добавлено сверкой М11, V6)
  # live и stale — только у члена ok; первый взгляд этого процесса на пульс — смена при любом состоянии члена (возраст
  # пульса — с него); у silent — phase, worker, server и age по происхождению единицы: из пульса — его фаза и возраст,
  # из шарда — "unobserved" и возраст метки (cammeta-python М11-01 № 2, 3)
```

Член `unseen`, `silent` или `never` — «не подтвердился», а не «ничего нет»: ответ, которому он нужен, неполон (Н1.5).

**Окно после старта и передачи держателя.** Монотонные часы держателя начинаются заново при каждом старте его процесса.
После перезапуска того же держателя метки членов остаются в его хранилище, но первый взгляд на метку — не смена: член с
меткой — `unseen`, вид неполон, пока процесс не увидит смену. Живой член обновляет метку не реже LOST_AFTER/2 (глава 8.3 Н1.3)
и выходит в `ok` не позже этого срока; член, умерший до перезапуска, через LOST_AFTER становится `silent`. Так он не выглядит
живым после перезапуска, и правка главы 8.6 по его единице отвечает 503 «не слышно», а не 404 «нигде». После передачи держателя (глава 8.8) у нового держателя меток нет: поколения отчётов с передачей не едут
(глава 8.8), каждый член — `never` до первого отчёта новому держателю, вид неполон. Нового окна «по старой памяти» нет.

### Н1.4 Вид домена

```yaml
domain/view:                     # объект держателя (P/05 Н1.1); писатель — проход держателя раз в VIEW_EVERY = 3 с
  as_of:     <стенные секунды держателя на конце прохода>
  holder:    <имя держателя>
  complete:  true | false        # true ⟺ каждый член `ok` и `contested` пуст
  members:   [{name, state: ok | unseen | silent | never, age}]   # age — секунды с последней смены метки, которую видел
                                                         # этот процесс, без смены — с первого взгляда; один знак после
                                                         # точки (Н1.4 round); у `never` — null; порядок — по name
  units:     {<sub>: [Unit]}     # каждый манифест каталога с domain.ref (Н1.2), ключ есть и у пустого
  contested: {<sub>: {<ref>: [<член>…]}}   # ref, который заявляют два члена и больше, кроме ref исполнителей (executors
                                         # ниже); его единиц нет в units;
                                         # ключ есть у каждого манифеста с domain.ref, без спорных — {}
  <поля других глав>:            # trust — Н1.2а; member_list, knocking — Н1.7; topology, relay_refused — Н1.6а;
                                 # books — глава 8.5; pending, outcomes — глава 8.6; url — договор пересылки; term — глава 8.8;
                                 # shared — глава 8.9; reports — Н1.7
Unit:        {sub, id, ref, cluster, worker?, server?, phase, age, state, view?}
  id:        id единицы в её кластере (строкой); ref — Н1.2; cluster — член
  worker, server: из пульса (`worker`, поле `server` пульса) или из строки шарда снимка; нет — поля нет; worker пульса
             без поля worker — имя из ключа пульса `<sub>/heartbeats/<имя>` (добавлено сверкой М11, V9)
  phase:     `status[].phase` пульса (P/03.4 Н1.1); у `configured` — "unobserved"
  age:       секунды: у live/stale — с последней смены пульса, у configured — с последней смены метки; один знак после точки
round:       «один знак после точки» — округление точного десятичного значения секунд (не двоичной дроби) до 0.1,
             половина — от нуля: 0.25 → 0.3, 60.05 → 60.1 (добавлено сверкой М11, V4)
  view:      поля, названные `domain.view` манифеста (P/02.1 Н1.2а), из строки шарда; секретных полей нет (P/06.2 Н1.4)
order:       units в каждой подсистеме — по (cluster, id, worker) в порядке байтов UTF-8; единица в пульсах двух воркеров
             одного члена — два элемента (её ведут оба; теневой отчёт разбирает, кто из них действует)
duplicate:   id в двух шардах снимка одного члена — строка с большей revision; при равной — из первого шарда по ключу
             в порядке байтов UTF-8 (добавлено сверкой М11, V5)
no_ref:      элемент пульса, у id которого нет строки в шарде своего члена, в units не входит (у Unit нет ref) и не заявляет;
             так же строка шарда без значения domain.ref (Н1.2 no_value)
executors:   ref, все члены которого — исполнители его назначения ({cluster} ∪ copies, глава 8.6 Н1.1; origin члена в это
             множество не добавляет и из него не исключает), не contested: единицы всех исполнителей — в units; роль исполнителя
             (основной или резерв) — забота подсистемы, вид её не показывает; член вне множества, давший тот же ref, —
             contested; назначения прохода не прочитаны (Н3 шаг 3а) — исключения нет: ref у двух членов и больше — contested;
             полнота вида — по Н3 шаг 5 (ADR-0091 доп. (12) п. 1, доп. (13) пп. 1–2, доп. (15) пп. 1–2)
as_of:       у команды view — стенные секунды её процесса на конце прохода входа; приёмка его не сравнивает
```

Исходы семьи пульсов (`heartbeats`, [P/03.4](../../03-worker/spec/03.4-worker.norms.md)) применяет живой читатель объекта из
хранилища — проход держателя, читающий объекты копии члена: пульс, нечитаемый целиком, в вид не попадает. Чистая функция
вида (команда `view`, вектор [`view`](../vectors/view/README.md)) получает уже прочитанное: форма её входа — `ViewInput`
(`worker` может прийти из ключа, `instance` не обязателен), не семья; заявки теневого отчёта — по строгому `status.items`
(Н1.6 `claim`) (решение «Архитектора» 2026-10-20 (Go М11-01 № 7; семья heartbeats, разбор ревью стадии B 6–7, № 14, № 15)).

### Н1.5 Полнота ответа

Ответ домена о единицах — сводка по копиям: частичная и устаревшая на ограниченную величину. Он ДОЛЖЕН нести свою
неполноту полем, а не отсутствием: `complete: false`, член `unseen`/`silent`/`never`, `contested`. Короткий список НЕ ДОЛЖЕН
выдаваться за полный. «Не найдено» при полном ответе — факт о домене; при неполном — факт о сети: отказ называет, кого не
было слышно (Н4). Каждое производное от копий (вид, книги главы 8.5, имена главы 8.5, тревоги урока P/10) — наблюдение, а не
власть: оно не даёт права записи в члене и несёт свой список отсутствующих.

### Н1.6 Теневой отчёт

```yaml
shadow:                            # считает проход держателя вместе с видом, ничего не пишет в члены
  inputs:    назначения domain/placement/<sub>/<ref> {cluster, copies} (глава 8.6 Н1.1), прочитанные проходом один раз (Н3 шаг 3а):
             исполнители ref — {cluster} ∪ copies; origin множество не меняет (origin = cluster — исполнитель как cluster;
             ADR-0091 доп. (15) п. 1); копии членов (Н1.3)
  claim:     элемент status[] пульса воркера в копии члена → (sub, ref, член, воркер, epoch, revision, observed_revision);
             ref — по id единицы из шарда снимка этого члена; элемент без ref (нет строки в шарде) — заявки нет;
             элемент не по форме P/03.4 Н1.1 (epoch, revision, observed_revision — не целые и т. п.) — заявки нет
             (добавлено сверкой М11, V14); элемент phase: sealed (эпоха не взята, P/03.4 Н1.1, P/03.5 Н3) — заявки нет
             (W03-G02); элемент phase: unreadable (эпоха не взята, P/03.3 Н3 шаг 2) — заявки нет (W03-G05); единица без
             значения domain.ref (Н1.2 no_value) — заявки нет: ни unmanaged, ни conflict (ADR-0091 доп. (13) п. 4);
             действующая заявка — только из пульса единицы в состоянии live (Н1.3): последний пульс умершего воркера
             устаревает и заявлять перестаёт сам
  kinds:
    lagging:     заявка с revision > observed_revision, observed_revision менялась в последние SHADOW_STALL      # норма
    stalled:     заявка с revision > observed_revision, observed_revision не менялась дольше SHADOW_STALL      # отказ
    orphaned:    назначение есть, действующей заявки ref от его cluster нет дольше SHADOW_STALL — с появления назначения или с
                 пропажи последней действующей заявки; раньше находки нет (контроллер члена ещё не разместил)  # отказ
    unmanaged:   действующая заявка ref без назначения                                                       # измерение
    conflict:    действующие заявки ref у двух членов, не все из которых — исполнители назначения ref; или у двух
                 воркеров одного члена с равной эпохой; или у члена, который не исполнитель назначения        # отказ
    stale_epoch: заявка из живого пульса с эпохой ниже наибольшей эпохи этого ref среди заявок из живых пульсов того же
                 члена в состоянии ok; такая заявка не действующая; равная наибольшая у двух воркеров — conflict  # отказ
    unknown:     назначение на члена не ok или на имя вне списка членов (detail называет состояние или «not a member»)
  facts:     назначенный не заявляет (orphaned) и заявляет неназначенный (conflict) — два разных факта: назначение c → m2
             при действующей заявке только у m1 даёт обе находки
  grain:     lagging, stalled, unmanaged, stale_epoch — находка на заявку (cluster, worker); conflict — одна на ref
             (cluster — лишний член, если он один; у двух воркеров одного члена с равной эпохой — этот член, добавлено
             сверкой М11, V11); orphaned, unknown — на назначение (cluster назначения);
             lagging и stalled — только у действующих заявок
  orphaned_from: первый проход без действующей заявки назначенного ref или первый взгляд на назначение; назначение —
                 тройка (sub, ref, cluster): смена цели и возврат к прежней — новое назначение, отсчёт заново
                 (решение «Архитектора» по сверке М11, V10)
  unread:    назначения прохода не прочитаны (Н3 шаг 3а) — отчёт этого прохода не строится: domain/shadow не переписывается
             (остаётся прежний), clean_streak не растёт и не сбрасывается, отсчёты orphaned_from и SHADOW_STALL не начинаются
             и не сбрасываются (ADR-0091 доп. (15) п. 3, доп. (17) п. 2)
  findings_order: по порядку видов в counts, затем (sub, ref, cluster, worker) в байтах UTF-8
  SHADOW_STALL:  60       # с, по монотонным часам держателя: время без смены observed_revision этой пары (член, воркер, ref)
                          # и время без действующей заявки назначенного ref; оба отсчёта — с первого взгляда этого
                          # процесса на пару или назначение, при любом состоянии члена
  silent_member: заявки члена не `ok` (`unseen`, `silent`, `never`) не действующие; назначение на такого члена — не orphaned, а неизвестно
                 (`unknown` в findings, в счёт отказов не входит)
  exit:          may_write ⟺ unmanaged == 0 ∧ нет отказов (stalled, orphaned, conflict, stale_epoch) ∧ clean_streak ≥ SHADOW_CLEAN
  SHADOW_CLEAN:  3        # проходов подряд без находок; любая находка или неизвестно обнуляет счёт
  report:        {counts: {lagging, stalled, orphaned, unmanaged, conflict, stale_epoch, unknown},
                  findings: [{kind, sub, ref, cluster?, worker?, detail}], clean_streak, may_write, why}
```

`may_write` — условие, при котором домену будет разрешено размещать единицы самому; в модуле домен сам не размещает
(назначение пишет оператор, глава 8.6; размещение доменом — долг в `ХОД-Спецификация.md`). Отчёт — измерение модели: каждая
`unmanaged` — единица, которую модель домена не описывает.

### Семьи данных (построены из источника)

Форма строк и объектов, которыми глава владеет по [каталогу](../../common/data/catalog.tsv), — из схем семей на [диалекте](../../common/DIALECT.md) (ADR-0088). ## Н2 Двери

Своих дверей у главы нет. Вид и теневой отчёт отдаёт консоль домена дверями `GET /domain`, `GET /domain/<sub>/<rows>`,
`GET /domain/shadow` — урок P/10 (P/10-01; [Н1.2а](../../10-domain-console/spec/10-domain-console.norms.md)): объект `domain/view` как есть плюс `age`, единицы подсистемы из вида, отчёт последнего прохода; содержимое — Н1.4,

прохода (`shadow` — отчёт последнего прохода, который его строил, Н1.6 `unread`; ни один не строил — `null`); код 0 —

## Н3 Проход

### проход держателя — вид и теневой отчёт (раз в VIEW_EVERY)

```
1. прочитать список членов (глава 8.3) и метку каждого члена; член без метки — never, если этот процесс его метки не видел,
   иначе silent с прежней копией (Н1.3); ушедший из списка — забыть (Н1.3 leave); смена метки на глазах — сброс возраста;
   первый взгляд процесса на метку — не смена (unseen, Н1.3)
2. для каждого члена не never: копия — отчёт поколения метки (глава 8.3 Н3 «прочитать копию»), у пропавшей метки — прежняя
   копия процесса; не читается — член silent
3. для каждого манифеста каталога с domain.ref: units из пульсов и шардов каждой копии (Н1.4); id уже из пульса — шард его не дублирует;
   строка без значения domain.ref — не единица (Н1.2 no_value)
3а. прочитать назначения domain/placement/<sub>/* — один раз на проход: это чтение служит шагу 4 и теневому отчёту (шаг 6);
   не прочитаны — назначений этого прохода нет (ADR-0091 доп. (13) п. 1)
4. ref, который дают два члена и больше → contested, единицы этого ref из units снять; кроме ref, все члены которого —
   исполнители его назначения шага 3а (Н1.4 executors): его единицы остаются в units
5. complete = все члены ok ∧ contested пуст
6. теневой отчёт по Н1.6: назначения шага 3а; заявки; виды; clean_streak и may_write; назначения не прочитаны — отчёт
   этого прохода не строится (Н1.6 unread)
7. записать domain/view (put объекта); отчёт — в память прохода и в объект domain/shadow тем же проходом; не построен —
   domain/shadow и память отчёта прежние
```

**Гонки.** Копии членов читаются в разные моменты: вид — наблюдение, а не снимок. Член может поменять метку между шагами 1
и 2: проход берёт поколение прочитанной метки, следующий проход — новое. Два прохода держателя (держатель один, глава 8.8)
не пересекаются; после перезапуска держателя члены `unseen` до первой увиденной смены, `clean_streak` — 0. Ошибка записи
`domain/view` не меняет прежний объект; дверь отдаёт прежний вид с его `as_of`. Обрыв между записью вида и теневого
отчёта — вид нового прохода, отчёт прежнего: следующий проход пишет оба; расхождение одного прохода допустимо.

| стенд | 15 | теневой отчёт по назначениям: исполнители из `copies` — не `conflict`; назначение без единицы — `orphaned` после SHADOW_STALL | Н1.6, глава 8.6 Н1.1 |

Векторы `view` — не единственное доказательство: стенд главы повторяет векторы 01–05 с настоящими отчётами членов.
Пересылка консолью члена — [договор пересылки](../../common/contracts/forwarding.md) (переходы 1–2 — консоль кластера, приём перехода 2 — урок P/10); гранты — глава 8.4.

Проверяются чтением, с причиной: Н1.1 — двери главы 8.3 (членов домен не опрашивает); worker из ключа пульса, заявка не
по форме, `cluster` у `conflict` одного члена, `mark` ≤ 2^53 − 1 — входов таких нет; окно после передачи держателя — стенд
главы 8.8; поля вида `trust`, `topology`, `relay_refused` (Н1.2а, Н1.6а) — стенд их не сравнивает; вход команды `view` не
по форме (код 2) — случаев `@exit 2` в векторах нет; «Гонки» Н3 — стенд не обрывает процесс между записями; назначения не
прочитаны (Н3 шаг 3а): объект `domain/shadow` не переписан, отсчёт `orphaned_from` не начат и не сброшен — стенд не
обрывает чтение назначений (вектор `10-placements-unread` — `contested` и прежний `clean_streak`); строка без значения
`domain.ref` у живого члена на стенде — векторами (`10-no-ref-row`).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команду `view`** для приёмки — шаблон с `{input}`; её вызов и вывод — дверь `view` словаря «Стенда домена», формы — Н5;
2. **как проход держателя хранит память теневого отчёта** (время последней смены `observed_revision` по паре, время появления назначения или пропажи последней действующей заявки, `clean_streak`) между проходами; после перезапуска она пуста;
3. **порядок полей JSON** вида — свободен; порядок элементов массивов — Н1.4 и Н0.
