# Векторы сборки книги

Текст производный от `vectors/assemble/README.md`, руками не правится: источник — английский [`vectors/assemble/README.md`](../../../vectors/assemble/README.md), правка идёт в него, русский пересобирается переводом.

Векторы функции `assemble` [главы P/08.5](../../spec/08.5-domain.norms.md): сборка одной книги у держателя без
хранилища, сети и стенда — вход — копии членов списка и их состояние вида, вывод — строки книги каждого члена до кольца
(секреты открыты) и отчёт вида `{conflicts, dropped, undelivered}` (N1.3, N1.5, N3 «сборка книги»; N5 «`assemble`»).
Владелец — урок P/08, глава 8.5; функцию исполняет процесс `domain` (проход держателя раз в `VIEW_EVERY`). Байты пишет
«Спецификация»; соответствие продукта — его приёмкой по этой таблице.

`case` — имя случая, `note` — примечание к строке.
Вход — текст JSON одной строкой: сняты только незначащие пробелы вне строк; порядок ключей, лексемы чисел и значения
сохранены как есть. Ожидание записано, как в шаге стенда после `ok `; `@exit 2` — `@exit 2`. Таблица — единственный источник этих случаев.

## Прогон

Без стенда: команда `assemble` реализации получает вход (колонка `input`) и печатает JSON `{rows, report}`; `expect` —
подмножество полей вывода по словарю «Стенда» ([общий README приёмки](../../../../common/ru/acceptance/README.md), `<код>
<JSON>`: названные поля есть и равны, `"@absent"` — поля нет, массив — по длине, порядку и элементам) или `@exit 2` (вход
не по форме N5: ключи `copies` — не в точности `members`; `grants` без `now`). Каждая строка — отдельный запуск.

## Входы, ключи и манифесты

Вход — N5 главы: `book` — `testsub2/notes` (`pick: unique`, индекс имён `notes/` с `grant: view`) или `testsub2/rolls`
(`pick: all`), `members` — список членов, `book_seal_seed` — `seed_secret` ключа приёма книг (`book seal 1`,
проверочные данные `domain-token` «Ключи»), `copies` — состояние и объекты копии
каждого члена (`null` — копии нет), `grants` и `now` — строки грантов получателей для правила N1.3 `grant`. Секреты
входов — конверты `x25519:v1` к `book seal 1`, `eph 1`, `nonce` 0…11
([договор конвертов домена](../../../../common/ru/contracts/domain-envelopes.md) «Конверт `x25519:v1`», AAD — `[member, row key,
item]` и JSON Pointer секрета).

Ожидания зависят от байтов манифестов каталога: `domain.books` (`from`, `key`, `pick`, `to`) и
`domain.names` манифеста `testsub2` из данных спецификации.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок.

| Файл | Вход → ожидание |
|---|---|
| случаи векторов, 23 строки: 22 вычислено, 1 `@exit 2` | `input` — вход `assemble` текстом JSON → `expect`: строки `rows` (доставка только членам из `to`, порядок `entries` по (member, item), `missing` с закрытыми словами, ключ конфликта `unique` и недоставленный по гранту — `"@absent"`, открытый секрет в `value`) и `report` (`conflicts`, `dropped` — `bad_contribution`, `secret_unopened`, `undelivered`); `@exit 2` — `grants` без `now` |

Векторы проверены оракулом по тексту норм (N1.3, N3 «сборка книги», N5; открытие секрета — эталонными X25519, HKDF-SHA256
и AES-256-GCM по договору конвертов домена; действующая строка гранта — [договор права](../../../../common/ru/contracts/may.md)
шаг 5), не по коду реализаций: вывод оракула содержит ожидание каждой строки. При расхождении прав текст нормы, вектор
правит «Спецификация».
