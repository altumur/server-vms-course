## Прогон

Без стенда: команда `view` реализации получает вход (колонка `input`) и печатает JSON `{view, shadow}`; `expect` —
подмножество полей вывода по словарю «Стенда» ([общий README приёмки](../../../../common/ru/acceptance/README.md), `<код>
<JSON>`: названные поля есть и равны, массив — по длине, порядку и элементам, число — по значению) или `@exit 2` (вход не
по форме `ViewInput`). Каждая строка — отдельный запуск на свежем состоянии: память теневого отчёта между строками не
переходит. `as_of` вывода — стенные секунды процесса команды, не сравнивается.

## Входы и манифесты

Форма входа — `ViewInput`, вывода — `ViewOutput` ([контракт урока](../../../spec/08-domain.api.openapi.yaml)): `manifests` — манифесты каталога,
`holder` — имя держателя, `passes` — проходы; в проходе `at` — монотонные секунды держателя, `members.<член>` —
`{mark, stale?, objects}` (`mark` — `rev` метки `reported` или `null`, `stale` — поле `stale` метки, `objects` — пульсы
`<sub>/heartbeats/<воркер>` и шарды `<sub>/snapshot/<шард>` копии), `placements` — назначения
`{<sub>: {<ref>: <член> | {cluster, copies?, origin?}}}` или `null` — назначения этого прохода не прочитаны (P/08.1 N3
шаг 3a). `shadow` вывода — отчёт последнего прохода, который его строил (P/08.1 N1.6 `unread`). Смену метки и пульса держатель видит между проходами входа; первый проход
— первый взгляд.

Вход — пульсы после чтения по семье `heartbeats` (P/03.4): форма входа — эта, не семья; пульс без `instance` или с
`worker` из ключа — положительный вход, строки с ним остаются положительными (P/08.1 N1.4).

Ожидания зависят от байтов манифестов каталога: `domain.ref`, `domain.view`, `unit.rows` и
`unit.id` манифестов `testsub` и `testsub2` из данных спецификации.

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок.

| Файл | Вход → ожидание |
|---|---|
| случаи векторов, 51 строка: 20 только `view`, 19 только `shadow`, 8 оба, 4 `@exit 2` | `input` — вход команды `view` текстом JSON → `expect` — подмножество `{view, shadow}` |

Нативный вход камеры. В `ViewInput` явно переданный `silent_after` выбирает свежесть камеры для этого прохода; без него вход моделирует сервер. Это абстракция команды для `Entry.class` и `received_at` метки, которых её закрытый вход не несёт. При первом взгляде на существующую метку камеры команда задаёт время её приёма монотонным `at` этого прохода: член `ok`, пока метка существует и возраст с этого приёма или последней наблюдённой смены метки не больше `silent_after`, и `silent`, когда больше. Ни разу не виденная метка — `never`; исчезнувшая — `silent`, как в N1.3. Сервер сохраняет обычное первое `unseen` до наблюдённой смены метки. Эта абстракция не меняет работающего держателя: класс берётся из принятой записи участника, время приёма — из настоящей метки, не из времени heartbeat. Ни класс, ни поле приёма не выводятся из объектов копии.
