## Подготовка

Как подготовка стенда главы 8.3 ([приёмка главы 8.3](../3/README.md), «Стенд», «Подготовка каждого сценария») с
отличиями: каталог каждого кластера — `testsub` и `testsub2` (порядок — «Стенд» общего README приёмки); на каждом кластере
работают контроллеры обеих, воркер `w-1` манифеста `testsub`, воркер `t-1` манифеста `testsub2` (с учебным писателем вкладов, N5
главы) и ресурс своего сервера `srv-<кластер>`; до шагов в хранилище каждого кластера есть счётчик `testsub` `c1-<кластер>`
(свой ref у каждого: общий `c1` был бы спорным, и `@domain` не дождался бы `complete: true`) и полка `testsub2` `sh1`
`{zone: z1, server: srv-<кластер>}`: оба создаются через дверь консоли кластера (`POST /counters {"name": "c1-<кластер>"}` и `POST /testsub2/shelves {"name": "sh1", "zone": "z1", "server": "srv-<кластер>"}` с ключами `prep-<кластер>-counters` и `prep-<кластер>-testsub2-shelves`), и статус не 201 — сбой стенда. `console2` у `member` — префикс `/testsub2`.

Сценарии с людьми:
- человек `root` с паролем `w2c test root password` заводится при `@install domain` (`domain first-admin`, директива
  `@admin`); раннер ходит им по умолчанию: `admin` `*` у двери домена и в строке грантов каждого кластера стенда;
- двери людей и грантов `holder` (глава 8.4, урок P/10 — соседи на стенде), директива `@stop agent` — словарь домена.
