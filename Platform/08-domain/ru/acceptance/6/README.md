## Подготовка

Как README приёмки [главы 8.3](../3/README.md) («Стенд», «Подготовка каждого
сценария»): раннер поднимает на одной машине три кластера — `hold`, `m1`, `m2`; у каждого своё
пустое хранилище, свой `{data}`, свои сокеты ролей и порты консоли и ресурса, своё кольцо (P/06.2 N1.2), каталог манифестов —
только `testsub` (`domain.edit: [start, labels]`, `domain.ref: name`); консоль, контроллер и воркер `w-1` `testsub`, ресурс
своего сервера (`srv-hold`, `srv-m1`, `srv-m2`). Единиц нет. Домена нет: его ставит директива `@domain` первого шага каждого
сценария. Имя домена — `acme`; файл восстановления — `{recovery}` в каталоге экземпляра.

- `store` у `member <кластер>` — дверь хранилища кластера через `admin.sock` (наблюдение строк домена:
  `domain/placed*` членов, `domain/pending/m1` держателя).
- Часы не ускорять: LOST_AFTER 45 с, REPORT_EVERY 5 с, MARK_REFRESH 22,5 с, VIEW_EVERY 3 с; сроки `@until` взяты с запасом.
- У двери `holder` раннер ставит `Idempotency-Key` и у `PUT`/`DELETE`; `@key(N)` повторяет ключ шага `N`.

## scenarios.tsv

Формат — словарь «Стенда» и словарь домена; ожидание — подмножество полей. `$id` — id хранимой правки из ответа 202 на правку.

Отдельные шаги наблюдают и сторону агента члена (копии `domain/placed*`, применение правки
через дверь единиц) — пункты [главы 9.1](../../../../09-agent/ru/spec/09.1-agent.norms.md) (P/09.1-07, -08) ссылаются на них; исход сценария — назначение и правка держателя.

## Счётчик назначений после старта

Процесс `domain` при старте и при каждом новом взятии очереди `domain/signer-turn` — до первого ответа агенту — поднимает
счётчик `domain/placement` на 1 (P/08.6 N3).
