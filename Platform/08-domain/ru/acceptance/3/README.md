## Стенд

**Подготовка каждого сценария** (из README приёмки M11/03, «Подготовка каждого сценария 01–09»). Раннер поднимает на
одной машине три кластера — `hold`, `m1`, `m2`: у каждого своё пустое хранилище, свой `{data}`, свои сокеты ролей и
порты консоли и ресурса, своё кольцо (P/06.2 N1.2), каталог манифестов — только `testsub`; консоль, контроллер и воркер `w-1`
`testsub`, ресурс своего сервера (`srv-hold`, `srv-m1`, `srv-m2`). Единиц нет. Домена нет: его ставят шаги сценария
(`@install domain`, `@start domain`, `@start agent`) или директива `@domain`. Имя домена — `acme`; файл восстановления
установки — `{recovery}` в каталоге экземпляра.

- `store` у `member <кластер>` — дверь хранилища кластера через `admin.sock` (подготовка и наблюдение строк домена).
- `resource` без префикса — дверь ресурса `hold`: через неё читаются объекты держателя `domain/members/<член>/…`.
- Часы не ускорять: LOST_AFTER 45 с, REPORT_EVERY 5 с, MARK_REFRESH 22,5 с; сроки `@until` взяты с запасом.

**Сценарии 15, 16** (из README приёмки M11/04), **21 и 25**: кластеров четыре — `hold`, `m1`, `m2`, `relay`. Агент `relay` всегда
открывает дверь ретранслятора (`RELAY=1`, `{relay_port}`); директивы `@domain <кластеры>`, `@start agent <кластер> via
relay`, `@stop agent`. Топология пуста до шага, который её пишет.

**Сценарий 04** (из README приёмки M11/08): агенту `m1` даётся каталог TLS `inputs/kit-m1-one/` (только `ca.pem`
центра A), затем `inputs/kit-m1-two/` (`ca.pem` A и `ca.next.pem` B), затем переменная снимается (`@env m1
W2C_TLS_DIR=…`, `@env m1 W2C_TLS_DIR`; значение `inputs/…` — путь от этого каталога). Двери стенда TLS не говорят: агент
лишь публикует отпечатки и сертификаты центров (N1.6 `tls_ca`, `tls_ca_certs`). Отпечатки в ожиданиях — sha256 DER этих
файлов: A — `d72f9e5e…68a6`, B — `6fefd57b…e217`. Шаг 4 — строка `domain/members/m1/ca-certs` записана до `Entry.ca` (шаг
3 уже видит отпечаток), шаг 18 — снятие администратором удалило её. Шаги 10–11 проверяют, что правка администратора без
смены центров у члена переписывается его следующим отчётом. Шаги 14–16 — два прохода агента (`REPORT_EVERY` 5 с) без
`tls_ca`: отпечатки не снимаются. Как раннер передаёт окружение и перезапускает консоль и агента кластера с переменной
(`@env`) — словарь «Стенда домена» [общего README приёмки](../../../../common/ru/acceptance/README.md), `@env` и «Окружение
пересылки» (разбор ревью стадии B 8–10, № 22: M-16).

## scenarios.tsv

Формат — словарь «Стенда» общего README приёмки и раздел «Стенд домена». `$fp1`, `$fp2` — отпечатки, которые раннер
связывает из `knocking` и подставляет в приём: так стенд повторяет то, что делает человек, сверяя отпечаток с журналом
агента; `$kr` (сц. 20) — `rev` набора из `trust` вида; `$k` (сц. 29) — закрытый ключ партии из ответа `POST /domain/batches`, раннер отдаёт его команде `join` директивой `@join m2 batch=b1 $k`. Всего 21 сценарий / 218 шагов.

Потерю памяти держателя (409 `rebase`) стенд не вызывает: её проверяют векторы `accept` и чтение договора приёма отчёта.

Сц. 03 не зависит от момента резервной копии (глава 8.8: `first`, `BACKUP_EVERY`): член `m1` — хранитель, и
`domain/backup-taken` в его отчёте даёт своё поколение в любой момент прогона. Поэтому шаг 5 ждёт у `m1` сам объект
`testsub/snapshot/w-1` (размещение `c3`), шаги 6–9 — две смены отметки круга отчёта `sent_at`, связанной после снимка
(два прохода агента: одна смена может принадлежать кругу, бывшему в полёте), и только шаг 10 берёт последнее поколение: в
нём снимок есть при любом числе поколений между ними (поколение несёт все объекты члена, N1.3).

## Сны (`@sleep`, ADR-0080 доп. (17) п. 4)

Ожидание события — `@until`: сц. 03 шаги 6–9 ждут двух кругов отчёта после снимка (`sent_at` сменился дважды; по `rev`
поколение не различить — ревью стадии B 1–2, п. 1); сц. 17 шаги 2 и 8 — списка членов у `m1`; сц. 20 шаг 5, сц. 21
шаги 5, 9, 11, сц. 22 шаг 4 — следующего прохода вида (`VIEW_EVERY` 3 с). Оставшиеся сны:

| Сц./шаг | Сон | Причина |
|---|---|---|
| 03/2 | 20 с | время перед действием: отчёты после `@domain` затихли — `$r1` и шаг 3 читают одно поколение (тишину не наблюдать) |
| 03/14 | 20 с | время перед действием: тишина отчётов перед связыванием `$r3` — шаг 16 ждёт повторной отправки того же поколения; счётчик `c3` заведён с `step: 0` (шаг 4): учебный обработчик пишет `n` в `status` пульса (P/03.4 N1.1), а сравнение вклада исключает только `ts` (P/09.1 N1.2 `change`) — тикающий счётчик законно давал бы новое поколение каждый круг (C08-REPORT-STEADY-COUNTER-01) |
| 04/15 | 12 с | отсутствие: без каталога `W2C_TLS_DIR` поле `ca` члена не снимается — два прохода агента (`REPORT_EVERY` 5 с) |
| 05/3 | 60 с | домен полон и отсутствие: часы `m1` на 100 с позади не делают его молчащим за срок (не одно событие — `@until` прошёл бы до первого отчёта с этими часами) |
| 14/5 | 10 с | отсутствие: стук без верной подписи не принят — агент стучится раз в `REPORT_EVERY` 5 с, два прохода |
| 17/3, 17/9 | 10 с | время перед действием, круг не наблюдаем: `@carry` читает ответ того же круга — держатель узнаёт из следующего отчёта `m1`, что список у него свежий (`REPORT_EVERY` 5 с и проход); шаги 2 и 8 ждут списка у `m1` (`@until`) |

## Свидетельства вне TSV

Проверяются чтением (норма главы, N5): CAS приёма члена, сбой между записями поколения, `delta` и метки, `sign_failures`
в метке и виде, несходящиеся сертификаты `tls_ca_certs`, объединение рукопожатия у двери роли (урок P/10 N1.4). Стук и проверки
держателя на пакете ретранслятора — сц. 02, 03 [приёмки главы 9.2](../../../../09-agent/ru/acceptance/2/README.md).
