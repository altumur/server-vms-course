## N1 Форма

**Время.** Полей времени у строки главы нет: давность очереди — монотонные часы процесса над версией строки
`domain/signer-turn` (N3 «очередь процесса domain» шаг 3).

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/signer-turn`;
- пишет: `domain/member-rows/<part>` (cas), `domain/view` (cas), `domain/members/<member>/reported` (cas), `domain/members/<member>/tables/<sub>/<table>` (cas), `domain/alarm-history/<member>` (cas);
- читает: `domain/signer`.

Строку очереди пишет только процесс `domain` (N1.7 `rights`). Потолки N1.5 проверяет каждая запись `domain/member-rows/<part>`
(владелец строки — [глава 8.3](08.3-domain.norms.md)); объекты `domain/view` ([глава 8.1](08.1-domain.norms.md)), метка
`reported` (глава 8.3) и `domain/alarm-history/<member>` ([глава 8.9](08.9-domain.norms.md)) процесс пишет по правилу N1.7
`objects`; `domain/signer` (ключи держателя, [глава 8.2](08.2-domain.norms.md)) ставший активным перечитывает перед
каждой подписью (N1.7 `active`).

Член отчитывается сам ([глава 8.3](08.3-domain.norms.md)): домен не открывает к нему соединений, молчание — возраст
метки по часам держателя. Новой формы члена глава не вводит. Она называет, во что обходится домен на сотнях малых членов,
ставит потолки и закрепляет один процесс `domain` у держателя. Решение «Архитектора» по вопросам M11/12.

### N1.5 Потолки

```yaml

                         # человека, 64 знака по 4 байта (256); key 64; ca 2 × 64; revoked_keys 4 × 64; how ≤ 43 («held the
                         # domain until term» и 16 цифр); since ≤ 24 знака числа JSON; ключи и разметка JCS. Запись, после
                         # которой Entry больше, не пишется: 409 «the entry of <член> would exceed ENTRY_MAX bytes»
ENTRY_MAX новый: forms/runtime-constants.tsv; байт с class, url ≤ 256, via, batch; в строку 524288 байт входит ≈ 420 Entry худшего размера; среднее при 250 000 членов — 61
MEMBERS_MAX:   предел строки раздела, а не домена: потолок P/01.1 N1; домен — ≈ 1,4 млн при среднем 350 в строке (ADR-0113 доп. (4)); SERVERS_MAX — отдельным счётом domain/member-count, держатель в счёте (P/08.3 N1.1a); держать равным MISSING_SHOWN (P/08.5 N1.3 result): поднятый один, он уведёт молчащие серверы за обрезанный список, а читатели судят серверы
revoked_keys:  не больше 4 последних, старший — первый в массиве — вытесняется (глава 8.3 N1.1; отчёт его ключом при записи с key — 403 «ключа нет в записи или он не тот»,
               глава 8.3 N2, при записи без key — стук, приём отказывает revoked_members набора, глава 8.3 N3 шаг 4)
every_entry:   любая запись domain/member-rows/<раздел> (приём, уход, держатель в списке, claim, Entry.ca, правка администратора)
               проверяет все Entry этой строки, не только изменённую: revoked_keys каждой — не больше 4 последних,
               затем Entry больше ENTRY_MAX — 409 «the entry of <член> would exceed ENTRY_MAX bytes», ничего не записано
               (добавлено сверкой M11, N6: засеянная мимо приёма большая Entry иначе осталась бы в списке); у Entry.ca после
               принятого отчёта (глава 8.3 N1.6 on_accept) — не 409: отчёт принят, ничего не меняется, журнал (C08-CA-ENTRY-MAX-01)
whole:         целое поколение (глава 8.3 N1.3 whole') ≤ BODY_LIMIT (16 MiB): больше — 413 {error: "whole too large", detail},
               метка не трогается (договор приёма отчёта «принять» шаг 4a)
objects:       вид (глава 8.1) и история тревог (глава 8.9) — объекты: потолок объекта P/05, не строки; книги (глава 8.5) — строки
               под потолком строки 524288 байт (P/01.1 N1); исход сборки книги больше потолка — глава 8.5 N1.3 `write`
idem:          память повторов дверей правок (глава 8.0 N1.9): строки domain/idem/<key> под этими двумя числами
  IDEM_KEEP:   forms/runtime-constants.tsv     # с — столько строка живёт самое меньшее, как P/06.1 N1.3 «Срок done-заявки»: новая правка берёт новый ключ
                         # (ADR-0094 доп. (14)); снимает проход держателя (глава 8.1 N3) со стражем очереди, по местному монотонному
                         # возрасту от первого наблюдения версии строки; новый процесс считает заново: срок только длиннее;
                         # нечитаемая строка снимается так же
  IDEM_MAX:    forms/runtime-constants.tsv      # строк: правка раз в 21 с круглые сутки; счёт — перечисление прохода плюс свои записи после него; на потолке
```

### N1.7 Один процесс `domain` у держателя

```yaml
turn:       domain/signer-turn — строка очереди процесса domain у кластера держателя; алгоритм — договор очереди писателя
            common/contracts/turn.md (TURN_TERM, TURN_RENEW; аудит раскладки A-03, решение «Архитектора» 2026-10-25); своя — CAS прочитанной версии (N3 шаг 2), чужая неизменная
            ≥ TURN_TERM — взять;
            holder строки — экземпляр процесса <коробка>:<pid>:<6 hex> (форма экземпляра — договор экземпляра, common/contracts/instance.md)
release:    по SIGTERM активный процесс отдаёт очередь — holder "" по CAS своей версии, как контроллер в конце прохода
            (договор очереди шаг 6); ждущий берёт её следующим TURN_RENEW. Убитый (SIGKILL) очередь не отдаёт — её берут
            по TURN_TERM
guard:      каждая запись процесса domain в строку хранилища держателя — прохода, приёма отчёта, правки через консоль домена
            (глава 8.0 N1.8), любой главы — идёт со стражем {key: domain/signer-turn, index: моя версия}; страж отказал —
            процесс перестаёт быть активным. Консоль домена строк держателя не пишет, строка очереди ей не нужна
objects:    у объектов P/05 стража нет, и он не вводится:
            - объект с указателем-строкой пишется без стража, а действующим его делает указатель — строка под стражем:
              domain/shared-docs/rev-* — domain/shared (глава 8.9), резервные копии domain/backups/rev-* — domain/keepers/* (глава 8.8); rev-* копии пишется put_new: смещённый объект нового активного не перепишет, объект есть — конфликт (C08-BACKUP-PUT-NEW-01)
            - изменяемый объект без указателя-строки — domain/view, domain/view-rows/*, domain/shadow и domain/members/<член>/tables/* (глава 8.1; C08-SHADOW-GUARD-01), метка reported с поколениями под ней (глава 8.3),
              domain/alarm-history/* (глава 8.9) — каждая запись такого объекта, и прохода, и двери приёма (поколение, дельта, метка — каждая): процесс подтвердил
              очередь не раньше TURN_RENEW назад (`fresh_turn`) и пишет put_at по индексу объекта (договор клиента хранилища объектов «Операции» ops) порядком: get_at объекта →
              своя CAS подтверждения очереди на эту запись, свежесть её не заменяет (C08-MARK-TURN-CAS-01) → put_at по индексу, прочитанному ДО подтверждения; новый активный записал объект
              после нашего подтверждения — наш put_at получает conflict: не писать, перечитать очередь; до нашего
              подтверждения — не проходит само подтверждение (добавлено моделью Quint M11, G6: get_at после подтверждения
              оставил бы окно — пауза между ними дала бы индекс уже записи нового активного, и put_at её переписал бы)
window:     остаточное окно: объект, который новый активный ещё не трогал, put_at смещённого процесса пропустит — такая
            запись и так последняя, следующий проход держателя очереди её исправляет (вид — пересчётом, метка — следующим
            приёмом, история — дописыванием); поверх записи нового активного put_at не пишет (G6)
standby:    процесс без очереди — ждущий: прохода не ведёт, каждая его дверь отвечает
            503 {error: "standby", detail: "the domain process of this cluster is <экземпляр>"} — до чтения тела, затем
            закрывает соединение; <экземпляр> — свой, ответившего ждущего (договор экземпляра): держатель очереди в detail
            не называется — при нечитаемой или отданной очереди он неизвестен (C08-STANDBY-DETAIL-01)
no_signer:  очередь — весь процесс и без условия domain/signer: процесс берёт и подтверждает domain/signer-turn и без
            строки подписанта (цель передачи и переноса — кластер без ключей держателя, глава 8.8). Без читаемой
            domain/signer (нет или нечитаема) он не берёт роль держателя (глава 8.2 «процесс domain домена не основывает»,
            исходы domain/signer): прохода держателя нет; POST /api/prepare, /api/take и /domain/move отвечают по
            существу своим порядком (глава 8.8 N1.7, N1.8: корень, набор, подпись, record — проверки самих дверей),
            их записи — под стражем очереди (guard); прочие двери процесса — 503 standby, как у ждущего (C08-TURN-WITHOUT-SIGNER-01)
fresh_turn: дверь процесса domain отвечает по существу, только если он подтвердил очередь (N3 шаг 2 или 3) не раньше
            TURN_RENEW назад; иначе — подтвердить её сейчас (N3 шаг 2) или ответить 503 standby; так процесс,
            замёрзший дольше TURN_TERM (SIGSTOP) и проснувшийся, не отвечает 200 рядом с новым активным (добавлено
            сверкой M11, N4). Предел: процесс, остановленный между проверкой и ответом, может ответить 200 после потери
            очереди — окно ответа двери не ограничено; ключи те же, вред — «двое отвечают» (добавлено моделью Quint M11, G6)
active:     ждущий, ставший активным, перечитывает domain/signer (ключи держателя, глава 8.2 N1.3; forget главы 8.8 N1.6) перед
            каждой подписью — на каждом проходе и каждом запросе; прочитанное при старте не держит (добавлено моделью
            Quint M11, AC)
url:        url записи domain/holder (глава 8.8 N1.1) у держателя из нескольких узлов — адрес, который доходит до любого узла
            кластера, а не одного сервера (добавлено M11/12 в урок 10 N1.1)
term:       держатель на одном узле — «одна очередь», а не «один сервер»; смена узла внутри кластера — не перенос: срок
            не меняется
rights:     domain/signer-turn пишет только роль domain (её семья domain/*)
```

Строка `agent` (503 `standby` у агента — «держатель недоступен на этот проход», следующим проходом) — сторона агента,
P/09.1-19 ([глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.12 `agent`).
Ответ ждущего у каждой двери процесса — сводная таблица [главы 8.0](08.0-domain.norms.md) N2.

### N1.9 Цена

Норма-описание по константам глав 8.1, 8.3, 8.8, 8.9 и урока P/09; новых правил в ней нет. Площадка — 300 членов,
проход агента `REPORT_EVERY` 5 с.

| Что | Сколько | Где |
|---|---|---|
| приёмы держателя | 300 / 5 = 60 в секунду: подпись, CAS метки или поколения, ответ | процесс `domain` |
| записи спокойной площадки | поколений нет (меняется только `ts`); метка — 300 / 22,5 ≈ 13 записей объекта в секунду | хранилище объектов держателя |
| изменение члена | поколение: 3 объекта (`reports/<rev>`, `.delta`, `reported`) и 2 удаления | там же |
| ответ держателя | единицы КБ; список членов (~300 Б на член, 90 КБ) — только отставшему (глава 8.3, P/08.3-10) | канал к членам |
| вид | голова `domain/view` раз в `VIEW_EVERY` с, строки `domain/view-rows/<part>` кругом `VIEW_MEMBERS` | держатель |
| резервная копия главы 8.8 | раз в `BACKUP_EVERY` с, при изменении, у `BACKUP_HOLDERS` хранителей | держатель, хранители |
| фронт тревог главы 8.9 | одно чтение строки индекса в секунду | у каждого члена, не у держателя |
| записи дома у члена | только при отличии ([P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `home_write`, `fresh`); метки свежести (`as_of` грантов, `domain/reached`) — раз в `FRESH_EVERY` с, около 1 440 каждой в сутки | хранилище члена |

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи (ADR-0092). Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N3 Проход

### очередь процесса domain (при старте и каждые TURN_RENEW)

```
1. прочитать domain/signer-turn; нечитаема → standby, журнал
2. holder — этот экземпляр: переписать по CAS прочитанной версии (под именем экземпляра пишет только он сам; добавлено
   моделью Quint M11, T6); конфликт → standby
3. строки нет → CAS "" с holder = я; holder "" (отдана, N1.7 release) → CAS прочитанной версии с holder = я;
   holder чужой, его версия не менялась ≥ TURN_TERM по моим монотонным часам → CAS прочитанной версии с holder = я;
   успех → активен: проход держателя (глава 8.1 N3 и последующие) со стражем N1.7 guard; иначе → standby
4. holder чужой и свежий → standby
5. SIGTERM у активного → holder "" по CAS своей версии (N1.7 release), затем выход
```

Активный процесс, у которого страж записи отказал, сразу становится ждущим и не повторяет запись. Запись со стражем без
ответа (неизвестный исход) — как барьер [договора очереди писателя](../../../common/ru/contracts/turn.md) «Барьер»: успехом не считается, проход прерывается; процесс перечитывает
`domain/signer-turn` и решает заново по шагам 1–4 — очередь его (holder — этот экземпляр) → CAS прочитанной версии
(шаг 2), успех → активен, прерванное делает следующий проход по прочитанному заново; иначе → ждущий. Неизвестный исход
записи самой строки очереди (взятие или продление применено, ответ потерян) — так же: строка называет этот экземпляр с
версией, которой он не знал, и шаг 2 по прочитанной версии её подтверждает; единственный процесс не остаётся ждущим
(добавлено моделью Quint M11, T6).

**Гонки.** Два процесса после отдачи очереди берут её CAS одной прочитанной версии: проходит один, второй — ждущий.
SIGTERM активного между продлением и записью со стражем: запись несёт страж его версии и либо принята до отдачи, либо
отказана после (версия сменилась) — двух писателей нет. Ждущий стал активным, пока летит запись прежнего: она несёт
страж прежней версии и отказывает (N1.7 guard). Объекты без стража пишутся только после подтверждения очереди (N1.7).
