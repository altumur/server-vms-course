Строки манифестов — каталог с `domain.ref` для `not_ready` и
`member_objects` ([договор приёма отчёта](../../../common/ru/contracts/accept.md) шаги 4, 5).

### N1.1 Член, ключ члена, приём (сторона держателя)

Агент члена (роль `domainagent`), ключ члена `domain/member-key` (`pub` — точка кривой Ed25519 не малого порядка), команда `join` и копии члена `domain/member-list/<part>`, `domain/member` — сторона члена: [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.1. Отпечаток ключа члена и корня — [глава 8.2](08.2-domain.norms.md) N1.1.

```yaml
part:           0000…4095
domain/member-rows/<part>: {doc: <текст JSON>}
  doc:          {domain, part, rev, term, members: {<член>: Entry}, gathered?, new?, issuer, kid, sig}
  part:         <раздел>
  rev:          целое ≥ 1
  term:         <срок>
  freshness:    take
  re-signing:   REPORT_RATE строк в секунду
  Entry:        {how, since, class?, by?, key?, revoked_keys?, ca?, url?, via?, batch?}
    class:      server | camera
    url:        <адрес входа>
    via:        <ретранслятор>
    batch:      <партия>
    how:        "admitted" | "holder" | "held the domain until term <N>"
    since:      стенные секунды
    by:         <человек>
    key:        <hex>
    revoked_keys: [<hex>…]
knock:          стучащийся
```

`part` — первые 12 бит SHA-256(UTF-8 имени члена), десятичное число четырьмя цифрами, 0000…4095. `part` — функция имени, списка разделов нет.

`domain/member-rows/<part>` — у держателя; писатель — процесс domain (глава 8.0), CAS этой строки. `domain/member-rows/<part>` — список — объединение строк.

- `domain/member-rows/<part>.doc` — подпись и проверка читателем — договор записи срока «Строка членов»; gathered, new — глава 8.8 N1.8a.

- `domain/member-rows/<part>.part` — раздел этой строки; раздел каждого имени равен part, иначе строка не верна.

- `domain/member-rows/<part>.rev` — целое ≥ 1, +1 на каждую запись этой строки.

`domain/member-rows/<part>.term` — срок держателя, записавшего строку (глава 8.8 N1.1; установка — 1). `domain/member-rows/<part>.term` — пара (term, rev) называет строку однозначно и после переноса (N1.4a).

`domain/member-rows/<part>.freshness` — читатель — договор записи срока «Строка членов» take. `domain/member-rows/<part>.freshness` — kid в revoked_issuing — строка не верна, ждёт переподписи.

- `domain/member-rows/<part>.re-signing` — новый срок переподписывает все непустые разделы с подъёмом rev, не быстрее REPORT_RATE строк в секунду.

- `domain/member-rows/<part>.Entry` — ca — N1.6; how держателя — глава 8.8.

`Entry.class` — server — кластер с серверами | camera — камера-кластер: N1.1a. `Entry.class` — нет поля — server: так читаются записи держателя и прежнего держателя. `Entry.class` — смена — уход и новый приём.

- `Entry.url` — адрес входа из объекта domain/servers после проверки (глава 8.1 N1.4), не длиннее 256 байт.

- `Entry.via` — ретранслятор члена (N1.2).

- `Entry.batch` — партия приёма.

`Entry.how` — откуда член в списке (глава 8.8 N1.2 — два последних). `Entry.how` — имя человека — только в by, не дублируется.

- `Entry.since` — стенные секунды держателя записи.

- `Entry.by` — человек, принявший члена (глава 8.4; до него — operator, P/06.3 N1.8 `loopback`); только у admitted.

- `Entry.key` — hex ключа члена, принятого по отпечатку; у holder — ключ из первого отчёта его агента (глава 8.8).

`Entry.revoked_keys` — прежние ключи этого имени, отозванные (глава 8.2 N3 «смена после кражи» шаг 3a), в порядке отзыва: старший первым, форма называет порядок сама (общее правило массивов не действует). `Entry.revoked_keys` — не больше 4 последних.

- `Entry` — Entry ≤ ENTRY_MAX байт JCS (глава 8.10 N1.5).

- `knock` — стучащийся — [договор приёма отчёта](../../../common/ru/contracts/accept.md) «Стук».

**Приём — двусторонний.** На члене оператор закрепляет корень (`join`, [P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.1); на держателе — вносит ключ члена (`POST /domain/members {name, fingerprint}`, N2), сверив отпечаток с тем, что агент члена напечатал при старте. Порядок сторон любой.

Агент отчитывается и без закрепления — так держатель видит стучащегося, — но набор без
закреплённого корня не берёт ([договор набора ключей домена](../../../common/ru/contracts/keys.md) «Функция `keys`» →
`no_pin`).

Отпечаток ключа члена и корня — [глава 8.2](08.2-domain.norms.md) N1.1.

### N1.1a Класс члена и период

```yaml
class:       server | camera
domain/member-count: {servers, cameras}
every:       camera: min(3600, max(5, ⌈cameras / REPORT_RATE⌉))
mark:        every
busy:        договор приёма отчёта «Занято»
revocation:  server | camera
```

`class` — объявляет агент в стуке (P/09.1 N1.1 domain/join), приём ставит в Entry, человек подтверждает его принятием. `class` — партия приёма — всегда camera.

- `class` — server — every REPORT_EVERY; camera — бюджет домена.

`domain/member-count` — все Entry списка, держатель в servers (нет class — server). `domain/member-count` — пишет процесс domain той же записью, что строка раздела. `domain/member-count` — пока поле partial есть — итог кругом (глава 8.8 N1.8a счёт). `domain/member-count` — в голове резервной копии.

`every` — период камеры — min(3600, max(5, ⌈cameras / REPORT_RATE⌉)), cameras — из `domain/member-count`. `every` — REPORT_RATE в секунду на домен, статус измерения: не измерено. `every` — смещение прохода — P/09.1 N1.2a, разброс на весь период. `every` — выше 720 000 камер бюджет не держится: предел.

- `every` — счёта нет — поля every в ответе нет, агент держит прежнее.

`mark` — несёт сказанный every (договор приёма отчёта, поле every). `mark` — сказанный retry_in — память процесса domain («Занято»). `mark` — срок молчания камеры — silent_after = 3 × max(every, retry_in), server — LOST_AFTER. `mark` — SHADOW_STALL и road_quiet — глава 8.1 N1.3, договор приёма отчёта.

`revocation` — server — секундами; camera — с периодом: предел. `revocation` — выключение (domain/disabled) — так же, как отзыв: у сервера — секундами; у камеры — с периодом, предел.

### N1.1b Партия приёма

```yaml
domain/batches/<name>: {pub, via?, n, used, until, revoked?, refused: {<fingerprint>: <at>}, by, at}
token:       закрытый ключ Ed25519 партии
knock:       publication.batch
domain/knocks/<part>: {<name>: {key, pinned, at, batch, class}}
admission:   договор приёма отчёта «Стук партии»
via:         ретранслятор партии
revocation:  revoked: true
doors:       POST /domain/batches {name, via?, n}, GET /domain/batches, DELETE /domain/batches/<name>
state:       state резервной копии
```

- `domain/batches/<name>` — у держателя; писатель — процесс domain.

`token` — закрытый ключ Ed25519 партии, срок 7 дней, показан один раз. `token` — в строке открытый pub. `token` — токен кладётся на коробку при подготовке рядом с закреплением корня (P/09.1 N1.1 join).

`knock` — подпись, поле publication.batch — договор приёма отчёта «Стук партии». `knock` — секрет по сети не идёт, ретранслятор его не видит, к другому имени подпись не подходит.

`domain/knocks/<part>` — стук с верной подписью партии, не принятый сразу. `domain/knocks/<part>` — пишется только первый стук, строка до потолка, сверх — память. `domain/knocks/<part>` — прочие стуки — память KNOCKS.

- `admission` — шаги договора приёма отчёта «Стук партии»; иначе — стук лежит, ждёт человека: N3 «принять члена» шаг 1.

- `via` — ретранслятор партии; входит в Entry тем же пакетом: иначе коробка за ретранслятором молчала бы.

`revocation` — закрывает новые, принятых не трогает. `revocation` — DELETE принятого партией вносит отпечаток в refused партии Entry.batch: вернуться тем же токеном нельзя. `revocation` — refused переполнен — партия отзывается сама. `revocation` — после until партия чистится.

`doors` — admin домена. `doors` — POST: name — грамматика имени члена, n — 1…2^53 − 1, via — имя члена, лишний ключ — 400 refused. `doors` — POST: живая строка с этим именем (until не прошёл) — 409 refused «batch exists». `doors` — POST: 201 {name, token, until}.

- `doors` — GET: {batches: {\<имя>: строка как есть}}, нечитаемая — {unreadable: true}.

`doors` — DELETE: 200 {batches: {\<имя>: строка с revoked: true}}, повтор — тот же ответ. `doors` — DELETE: нет строки — 404 refused; строка не читается — 503 unavailable.

- `doors` — формы дверей — OpenAPI урока.

`state` — семья в state копии. `state` — объединение при восстановлении: отзыв не оживает, used — наибольший, refused — объединение.

**Физическое переполнение списка refused.** Если добавление отпечатка исключённого члена превысило бы действующий потолок строки, самоотзыв может записать `revoked: true` и `refused: {}`. При этом самоотзыве сохранить `pub, n, used, until, by, at` и наличие/значение `via`; квота, ключ и срок не сбрасываются. Очистка refused допускается только вместе с этим отзывом: revoked закрывает каждый новый автоматический приём, в том числе исключённого отпечатка; принятые члены не затрагиваются. При этом самоотзыве используются обычные CAS и guard очереди.

Отзыв действует только после подтверждённой записи; неподтверждённое чтение, неизвестный исход записи или посторонняя ошибка не доказывают ни переполнения, ни сохранённого отзыва. Если сокращённую строку тоже нельзя записать, сохраняется обычная обработка отказа/неизвестного исхода, без сообщения о сохранённом отзыве.

Восстановление сохраняет прежнее правило, что отзыв не оживает; очистка refused не разрешает сбрасывать revoked.

### N1.2 Топология

```yaml
domain/topology:   {doc: <текст JCS>}
  doc:             {rev, centre?, star, relays?, by?, at?}
    rev:           целое ≥ 0
    centre?:       <член>
    star:          [<член>…]
    relays?:       [<член>…]
    by?, at?:      <имя>, <стенные секунды>
  via:             Entry.via
  carry:           topology: {at, sha256}
  refusals:        409
domain/relay-members/<relay>: {rev, members: {<член>: <ключ>}}
put_order:         PUT /domain/topology
home:              via[член] | centre | держатель
```

- `domain/topology` — у держателя; писатель — процесс domain по двери N2 (глава 8.0), CAS.

- `domain/topology.doc.rev` — 0 — «никогда не писали» (строки нет — так же); +1 на запись.

`domain/topology.doc.centre` — член — центр домена: к нему тянутся звёздные ретрансляторы (глава 8.7). `domain/topology.doc.centre` — в PUT centre "" или null снимает центр, как пустой ретранслятор в via.

`domain/topology.doc.star` — звёздные ретрансляторы: до них не дотянется никто, данные они берут у центра (глава 8.7). `domain/topology.doc.star` — по возрастанию, без повторов.

`domain/topology.doc.relays` — кто ведёт хотя бы одного члена: значения Entry.via по возрастанию, нет — никого. `domain/topology.doc.relays` — ведёт держатель тем же пакетом, что Entry.via, приём и уход. `domain/topology.doc.relays` — PUT поля не принимает.

- `domain/topology.doc.relays` — читатели — воркеры (V/02.9 N1.8): сводного via им не нужно.

- `domain/topology.doc.by`, `domain/topology.doc.at` — кто и когда (стенные секунды консоли) записал.

`domain/topology.via` — поле Entry строки раздела: член отчитывается через ретранслятор; нет поля — отчитывается прямо. `domain/topology.via` — via[m] ниже — Entry.via члена m. `domain/topology.via` — сводного via нет: на этом размере строка топологии его не держит. `domain/topology.via` — копия члена несёт doc и via только этого члена: {\<член>: \<ретранслятор>}.

- `domain/topology.via` — GET /domain/topology и вид — doc, via читается Entry дверями списка.

`domain/topology.carry` — в ответе (N1.5) только topology: {at, sha256} — at строки, sha256 — hex SHA-256 JCS тела {doc, via} этого члена. `domain/topology.carry` — тело — GET /api/topology/\<член> при новом sha256: подпись агента и отказы — как GET /api/anywhere (P/08.4 N1.3), 200 {doc, via}, 429 busy. `domain/topology.carry` — doc растёт с доменом (relays), а ответ идёт каждым проходом, поэтому версия и ссылка, как anywhere.

`domain/relay-members/<relay>` — индекс, тем же пакетом, что Entry. `domain/relay-members/<relay>` — строка RELAY_MEMBERS_MAX имён, сверх — 409 relay full. `domain/relay-members/<relay>` — чтение превышающей предел строки даёт прежний unavailable, без усечения. `domain/relay-members/<relay>` — нет строки — relay_for пуст, rev 0.

- `domain/topology.refusals` — имя в centre, star, via (член или ретранслятор) — не член домена: «\<что>: \<имя> is not a cluster of this domain».

- `domain/topology.refusals` — star без centre: «a star relay takes its members' data from the centre, and there is no centre».

- `domain/topology.refusals` — centre в star: «\<c> is the centre and cannot be a star relay».

- `domain/topology.refusals` — держатель в star: «\<h> is the domain holder: it reaches the domain in place and is no star relay».

- `domain/topology.refusals` — член через себя: «\<m> cannot reach the domain through itself».

- `domain/topology.refusals` — цепочка: via[via[m]] есть — «… one relay between a member and the domain».

- `domain/topology.refusals` — через держателя: «\<m> through \<h>: that is the domain holder itself»; держатель в via — «\<h> is the domain holder:
  it reaches the domain in place, through nobody».

`domain/topology.refusals` — каждая — причиной в одном отказе 409, через «; ». `domain/topology.refusals` — причины — в порядке списка отказов выше (P/08.3-R375, P/08.3-R376, P/08.3-R377, P/08.3-R378, P/08.3-R379, P/08.3-R380, P/08.3-R381), внутри одной строки — по имени в байтах UTF-8. `domain/topology.refusals` — цепочка — одна причина на пару (m, via[m]); via[m] = m — только «through itself», без цепочки.

- `put_order` — PUT /domain/topology по порядку: сначала заголовки и память повторов (глава 8.0 N1.9).

- `put_order` — затем 400 — тело не по форме, нет ни
  If-Match, ни base_rev, либо они расходятся (глава 8.0 N1.9 «base_rev»).

- `put_order` — затем 503 {error: "unavailable"} —
  строка есть, но не читается, ничего не записано.

- `put_order` — затем ревизия раньше содержания:
  If-Match не равен версии строки — 412 revision moved; заголовка нет и base_rev ≠ rev — 409 «the topology is at rev N;
  this edit was made against rev M — look again».

`put_order` — затем отказы refusals одним 409 через «; » по слитому документу: не указанное поле — прежнее. `put_order` — на этапе отказов (после ревизии, до пакета CAS) via правки называет только меняющихся членов, не больше VIA_EDIT_MAX: у каждого строка раздела и два индекса, плюс строка topology — 61 запись, предел BATCH_WRITES P/01.1 64; сверх — 409 «a via edit names at most 20 members: send the rest again». `put_order` — на этапе отказов судятся названные члены.

- `put_order` — уход члена снимает его из индекса тем же пакетом, Entry члена за ушедшим ретранслятором живёт, её снимает правка via.

- `put_order` — затем один пакет CAS: строка topology, строки разделов названных членов, индексы domain/relay-members (не больше 10 конфликтов; после конфликта условие снова).

`put_order` — star пишется по возрастанию без повторов. `put_order` — via с пустым ретранслятором — член уходит из via.

- `put_order` — by — имя, доказанное сторожевой (P/08.4 N1.5).

`home` — ближайшая дверь члена к домену — via[член], иначе centre, иначе держатель (P/08.7 N1.1 `poll_home`). `home` — держатель читает Entry.via строки раздела этого члена.

Копия у члена `domain/member-topology` — тело `GET /api/topology/<член>` (N1.2 `carry`) как есть, взятое при новом `sha256` поля `topology` ответа держателя: сторона агента,
[P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4.

Какой дорогой агент отчитывается, решает его окружение (`DOMAIN_URL` или `RELAY_URL`), не топология; топология
говорит держателю и ретранслятору, кого через кого **принимать**.

Член, чей отчёт пришёл не той дорогой, отвергается
(N3 «держатель на POST /api/relay»; дверь ретранслятора — [глава 9.2](../../../09-agent/ru/spec/09.2-agent.norms.md) N2).

Прямой отчёт члена, которого топология ведёт через
ретранслятор, держатель принимает — это вторая дорога (N1.3a).

### N1.3 Поколение и метка

То, что из этого подраздела нужно агенту (метка — `sha256` от JCS целого, `MARK_REFRESH`, `BODY_LIMIT`), — также [договор приёма отчёта](../../../common/ru/contracts/accept.md) «Поколение, метка, пределы» (урок 9 читает договор, эта глава — владелец текста).

```yaml
generation:     domain/members/<член>/reports/<rev>
  whole:        {sent_at, objects, key, keys_rev?, pinned?, outcomes?}
delta:          domain/members/<член>/reports/<rev>.delta
reported:       domain/members/<член>/reported
  # поля поколения
  rev:          целое ≥ 1
  sha256:       hex sha256 байтов generation
  base:         <rev> | 0
  delta_sha256: hex sha256 байтов delta
  signature?:   X-Agent-Signature
  key, keys_rev?, pinned?: из публикации
  # поля последнего принятого запроса
  sent_at:      sent_at публикации
  received_at:  стенные секунды
  request_sha256: hex sha256 байтов тела этого запроса
  via?:         <ретранслятор>
  stale:        [<…>]
  sign_failures?: из публикации
  every?:       с
keep:           два последних поколения и их delta
REPORT_EVERY:   forms/runtime-constants.tsv
MARK_REFRESH:   22.5
BODY_LIMIT:     forms/runtime-constants.tsv
```

- `generation` — объект держателя (P/05 N1.1): целое поколение, JCS.

- `generation.whole` — objects — все объекты члена после применения
  изменения.

- `generation.whole` — outcomes — P/09.1 N1.5: смена исходов — новое поколение.

`generation.whole` — агент шлёт поле исходов правок, ещё названных держателем (OUTCOME_HOLD), в каждой публикации, пока строка domain/outcomes не пуста. `generation.whole` — outcomes: нет поля — исходов нет.

- `delta` — байты тела публикации как получены — то, что подписал агент.

`reported` — объект-метка; единственная граница принятого. `reported` — две части: поля поколения пишет только generation (договор приёма отчёта, шаг 7); поля последнего принятого запроса — каждый приём с записью метки (шаги 6, 7).

- `reported.rev` — целое ≥ 1 — номер поколения; выдаёт держатель: +1 на принятое изменение.

- `reported.sha256` — hex sha256 байтов generation — sha256 от JCS целого whole.

- `reported.base` — rev, против которого пришло изменение; 0 — пришло целое.

- `reported.delta_sha256` — hex sha256 байтов delta (при base 0 — тела целого, как пришло).

`reported.signature` — заголовок X-Agent-Signature прямого отчёта, создавшего поколение, как пришёл (N1.4). `reported.signature` — через ретранслятор поля нет (N1.3a). `reported.signature` — via — поле последнего запроса, поэтому метка без signature и без via законна: поколение пришло через ретранслятор, затем прямой heard.

- `reported.key`, `reported.keys_rev`, `reported.pinned` — из публикации — по ним консоль домена принимает члена и показывает закрепление.

- `reported.sent_at` — sent_at публикации.

- `reported.received_at` — стенные секунды держателя приёма.

`reported.request_sha256` — hex sha256 байтов тела этого запроса, как пришло. `reported.request_sha256` — повтор узнаётся по (sent_at, request_sha256).

- `reported.via` — ретранслятор — N1.3a.

- `reported.stale` — из публикации при каждом приёме, включая «слышал» (договор приёма отчёта, шаг 6); нет в публикации — [].

`reported.sign_failures` — из публикации при каждом приёме с записью метки, как stale. `reported.sign_failures` — поле sign_failures поколения не создаёт и метку само не освежает. `reported.sign_failures` — нет в публикации — поля нет (N1.6a; P/09.1 N1.12).

- `reported.every` — с — период, сказанный члену последним ответом с записью метки (N1.5; договор приёма отчёта «Ответ `carry`: `every`»); нет — REPORT_EVERY.

`keep` — два последних поколения и их delta. `keep` — старше и выше метки — повтор уборки при следующей попытке cleanup (приём, дошедший до шага 7), а не каждом запросе.

`REPORT_EVERY` — с — проход агента. `REPORT_EVERY` — ответ держателя может назначить every (N1.5), 1 … 3600.

- `MARK_REFRESH` — с = LOST_AFTER/2 (глава 8.1 N1.3) по монотонным часам держателя.

`BODY_LIMIT` — предел тела двери держателя и ретранслятора: больше — 413, тело не читается дальше. `BODY_LIMIT` — BODY_LIMIT — также предел JCS целого шага 4a договора приёма отчёта и целого, которое агент не шлёт (P/09.1 N1.2 body).

Метка — граница принятого: объект с номером не выше `reported.rev` неизменяем. Объект выше `reported.rev` — ничей: не читается, не переносится, не держит номер, следующий приём пишет поверх.

Читатели (вид — глава 8.1, сборщик книг — глава 8.5,
резервная копия — глава 8.8) берут `reported.rev` и читают только объект этого поколения.

При метке без объекта или объекте
не с её `sha256` читатели до `silent` применяют ограниченную перечитку метки общего договора accept (глава 8.1 N3 шаг 2), никогда не смесь.

Публикация — тело `POST /api/member/<член>` (закрытая форма, `member_objects`, поля вне дельты, `ready`, `change`) —
[P/09.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.2; схема тела двери — [контракт урока](../../spec/08-domain.api.openapi.yaml).

### N1.3a Дороги и порядок

`ROAD_QUIET` и порядок дорог для агента и ретранслятора — также [договор приёма отчёта](../../../common/ru/contracts/accept.md) «Поколение, метка, пределы» (урок 9 читает договор, эта глава — владелец текста).

```yaml
road:          прямо | через ретранслятор R
one_road:      последнее принятое на этой дороге — новее
two_roads:     по sent_at члена
ROAD_QUIET:    forms/runtime-constants.tsv
base:          у каждой дороги своя
signature:     подпись агента | нет
bytes:         relayed[<член>]
```

`road` — прямо (via нет) или через ретранслятор R (via = R). `road` — дорогу публикации называет держатель, не член.

- `one_road` — порядок задаёт дорога: последнее принятое на этой дороге — новее, даже если sent_at назад (договор приёма отчёта).

`two_roads` — между дорогами одного члена — по sent_at члена (одни часы на обеих). `two_roads` — тело другой дороги со sent_at ниже метки не принимается (ignored), пока член слышен — heard_ago < ROAD_QUIET (договор приёма отчёта, шаг 2a). `two_roads` — равный sent_at — одно тело: те же байты — heard (повтор другой дорогой), другие — 409 same_sent_at (там же, шаг 2).

`ROAD_QUIET` — с, монотонные часы держателя: три прохода агента (REPORT_EVERY (forms/runtime-constants.tsv)); дольше — прежняя дорога молчит. `ROAD_QUIET` — у class camera — road_quiet = max(15, 3 × mark.every) (P/08.3 N1.1a).

- `base` — у каждой дороги своя: ответ даёт rev метки только дороге метки, другой — 0 (шлёт целое).

`signature` — метка прямого отчёта несёт подпись агента. `signature` — через ретранслятор подпись члена не переносится — держатель верит подписи ретранслятора и топологии.

- `bytes` — delta поколения через ретранслятор — запись relayed[\<член>] пакета как получена (JCS этого значения).

### N1.6 Отпечатки центра члена: `tls_ca` → `Entry.ca`

Публикация `tls_ca`, `tls_ca_certs` и отпечаток центра для агента — также [договор сертификата роли](../../../common/ru/contracts/role-certificate.md) «Комплект кластера, роли домена, центр между кластерами» (урок 9 читает договор, эта глава — владелец текста).

Комплект роли, сертификат, центр и отзыв — [P/02.4 N1.6](../../../02-installer/ru/spec/02.4-installer.norms.md), [договор сертификата роли](../../../common/ru/contracts/role-certificate.md): один центр на кластер. Доверие между кластерами — по отпечатку центра, который кластер-член публикует подписанным отчётом.

```yaml
fingerprint:  sha256 hex (64 знака, строчные) DER-сертификата центра
tls_ca:       [<отпечаток>…]
tls_ca_certs: [<PEM>…]
form:         списки строк
Entry.ca:     [<отпечаток>…]
domain/members/<member>/ca-certs: {certs: JCS [<PEM>…]}
on_accept:    domain.member.ca, domain.member.ca.refused
relayed:      отпечатки члена за ретранслятором
admin:        POST /domain/members/<член>/ca {ca: [<отпечаток>…], ca_certs?: [<PEM>…]}
```

`tls_ca` — поле публикации (P/09.1 N1.2): [\<отпечаток>…] по возрастанию, без повторов — ca.pem и ca.next.pem каталога W2C_TLS_DIR кластера (договор сертификата роли `rotation`). `tls_ca` — каталога или ca.pem нет — поля нет. `tls_ca` — каждый файл — ровно один сертификат центра (CA:true): файл есть, но не читается, блоков не один или не центр — поля нет (агент пишет причину в журнал). `tls_ca` — вне дельты (не входит в whole, поколения не порождает); идёт в каждой публикации.

`tls_ca_certs` — поле публикации рядом с tls_ca: [\<PEM>…] — сертификаты тех же центров в том же порядке. `tls_ca_certs` — элемент — ровно один блок CERTIFICATE (как договор peer «Функция peer» шаг 2) с CA:true (лист под своим отпечатком — не центр). `tls_ca_certs` — sha256(DER) элемента — отпечаток tls_ca на том же месте. `tls_ca_certs` — есть только вместе с tls_ca; вне дельты; идёт в каждой публикации.

- `tls_ca_certs` — форма публикации закрыта (P/09.1 N1.2).

`form` — в форме публикации tls_ca и tls_ca_certs — списки строк любой длины; не список строк — поле не взято (P/09.1 N1.2 out_of_delta). `form` — всё прочее в tls_ca и tls_ca_certs, если это списки строк, — длина, повтор, не 64 строчных hex, не PEM, не CA:true, не сходится — проверка on_accept: ничего не меняется, журнал domain.member.ca.refused, отчёт принимается.

- `Entry.ca` — поле записи члена (N1.1): [\<отпечаток>…], 1–2, по возрастанию, без повторов; нет — отпечатков нет.

`domain/members/<member>/ca-certs` — у держателя; писатель — процесс domain. `domain/members/<member>/ca-certs` — сертификаты центров члена в порядке его Entry.ca. `domain/members/<member>/ca-certs` — Entry, ENTRY_MAX (глава 8.10 N1.5) и подпись списка их не несут — член их не читает: peer ищет якорь в цепочке сервера по отпечатку (договор peer). `domain/members/<member>/ca-certs` — в state резервной копии (глава 8.8 N1.5).

`on_accept` — держатель, после исхода same, heard или generation приёма (договор приёма отчёта, шаги 2, 6, 7), если body.tls_ca есть, непусто и (≠ Entry.ca или строка ca-certs не та): больше двух — ничего не меняется, журнал domain.member.ca.refused {member, reason: "more than two"}. `on_accept` — после исхода same, heard или generation приёма, если body.tls_ca есть, непусто и (≠ Entry.ca или строка ca-certs не та): повтор или не 64 строчных hex — ничего не меняется, журнал domain.member.ca.refused {member, reason: "not fingerprints"}. `on_accept` — после исхода same, heard или generation приёма, если body.tls_ca есть, непусто и (≠ Entry.ca или строка ca-certs не та): tls_ca_certs нет, не той длины, элемент не PEM по договору peer шаг 2, не CA:true или sha256 не сходится — ничего не меняется, журнал domain.member.ca.refused {member, reason: "certificates do not match"}. `on_accept` — после исхода same, heard или generation приёма, если body.tls_ca есть, непусто и (≠ Entry.ca или строка ca-certs не та), и ни один из случаев P/08.3-R240 не подошёл: сначала строка ca-certs (put), затем Entry.ca = tls_ca по CAS domain/member-rows/\<раздел> (rev + 1; Entry.ca уже тот — без записи), журнал domain.member.ca {member, ca}.

- `on_accept` — после исхода same, heard или generation приёма tls_ca нет
  или [] — ничего не меняется (снимает только администратор).

- `on_accept` — отпечатки не по возрастанию — держатель и дверь
  admin записывают их отсортированными, сертификаты — в том же новом порядке (не отказ).

- `on_accept` — проверка every_entry
  (глава 8.10 N1.5) — до записи строки ca-certs (P/08.3-R240), над новым документом: Entry этого или иного члена больше
  ENTRY_MAX — ничего не меняется (ни ca-certs, ни Entry.ca), журнал domain.member.ca.refused {member, reason:
  "the entry of \<член> would exceed ENTRY_MAX bytes"}, отчёт принят — ответ carry, не 409 (в пакете ретранслятора —
  не refused).

- `relayed` — отпечатки члена за ретранслятором — из пересланной публикации (N1.3a; P/09.2 N1.4): то же доверие, что к ней.

`admin` — у консоли домена → процесс domain (глава 8.0), грант admin (глава 8.4): заменить Entry.ca. `admin` — ca_certs — проверка как у tls_ca_certs, в том числе CA:true (иначе 400). `admin` — тот же ca снова — новая запись, rev + 1. `admin` — строка ca-certs пишется до Entry.ca.

`admin` — без ca_certs строка ca-certs не меняется, и член вне объединения рукопожатия, пока сертификатов под новыми отпечатками нет. `admin` — [] — снять Entry.ca и удалить строку ca-certs. `admin` — журнал domain.member.ca {member, ca, by}; by — доказанное сторожевой имя.

Кто читает отпечатки и сертификаты: клиент двери другого кластера — [договор `peer`](../../../common/ru/contracts/peer.md)
(владелец P/09; первый контакт `DOMAIN_CA`, `RELAY_CA`, `RELAY_MEMBER` — там же); дверь роли консоли домена
(объединение центров принятых членов в рукопожатии, запрет возобновления сессий) — [договор сертификата роли](../../../common/ru/contracts/role-certificate.md)
«Серверная сторона: класс `role`» (набор доверия `trust_set`).

Роли комплектов домена — [договор сертификата роли](../../../common/ru/contracts/role-certificate.md); серверная сторона
класса `signed` — [глава 8.0](08.0-domain.norms.md) и тот же договор.

TLS между кластерами на одной машине стенд не поднимает (N5).

### N1.6a Вид: поле `sign_failures`

view:           domain/view.reports.<член>.sign_failures

`view` — из метки reported: поле последнего принятого запроса (N1.3, как stale). `view` — пишется каждым приёмом с записью метки, поколения не создаёт (P/08.1 N1.7 — поле reports вида).

## N3 Проход

### принять(mark, stored, body, via, heard_ago) — держатель, на POST /api/member/\<член> после подписи

Абзац о `via` и `heard_ago`, шаги 0–7 и абзац о `sent_at`, ответе и сбое — [договор приёма отчёта](../../../common/ru/contracts/accept.md) «Функция
«принять»» (владелец P/08, глава 8.3; участник — ретранслятор 9.2).

Векторы — [`common/vectors/accept`](../../../common/ru/vectors/accept/README.md) (только для судьи: векторы проверки функции «принять»; они проверяют P/08.3-R016, P/08.3-R078, P/08.3-R161, P/08.3-R166, P/08.3-R167, P/08.3-R169, P/08.3-R170, P/08.3-R171, P/08.3-R180, P/08.3-R182, P/08.3-R183, P/08.3-R191, P/08.3-R202, P/08.3-R203, P/08.3-R206, P/08.3-R208, P/08.3-R233).

Держатель исполняет её на `POST /api/member/<член>` и для каждого члена пакета ретранслятора (N3 «держатель на POST
/api/relay»); ответ — carry (N1.5).

Вход функции читает держатель; что не известно — не «нет». Метка `reported` не читается или её чтение, как и чтение поколения `reports/<mark.rev>`, неполно — объекта нет среди ответивших или он найден при `X-Missing`, дверь ресурса не ответила ([договор клиента объектов](../../../common/ru/contracts/object-client.md) «missing»): найденное при неполном опросе может быть не свежим, — функция не вызывается, 503 `{error: "unavailable"}`, ничего не записано, журнал без значения; подмена отсутствием дала бы ложный rebase или поколение поверх.

Запись шага 7 не прошла до
записи метки — то же 503 `{error: "unavailable"}`: принято ничего, объекты выше метки ничьи.

Метка записана, а уборка шага 7 (ВСЕ `reports/<g>` при g < rev−1,
его `.delta`, объекты выше `rev`) не прошла — отчёт принят: ответ carry, сбой уборки — диагностика процесса, остаток
повторно убирается следующей попыткой cleanup (`keep`, шаг 7).

Точный same или heard, вернувшийся до шага 7, уборки не обещает. Сбой уборки не отменяет принятую метку.

Двери агентов (`POST /api/member/<член>`, `GET /api/carry/<член>`) читают строки, которые ответ утверждает:
`domain/member-rows/<part>` (член, его ключ и отзыв ключа), `domain/keys` и `domain/revoked` (поля carry) — до проверок члена и
ключа (в порядке строки N2 и договора приёма отчёта «Проверка члена и ключа»).

Двери агентов читают метку `reported` (у carry — `rev`
дороги, N1.5) после успешной подписи, перед «принять» или ответом carry: незнакомец получает свой 404, 403 или 401 и при
нечитаемой метке.

У дверей агентов строка, которую они читают (`domain/member-rows/<part>`, `domain/keys`, `domain/revoked`, метка `reported`), есть, но не читается, или чтение не подтверждено (неполный опрос,
хранилище не ответило) — 503 `{error: "unavailable"}`: не 404, не 401, не `rev` 0 или прежний, не поле опущено; стука,
приёма и записи нет, журнал без значения.

Поле carry, чьей строки нет, —
опускается по N1.5.

Запись дверей агентов (поколение и метка — договор приёма отчёта шаги 6, 7; держатель в списке шаг 2; `on_accept` — строка
`ca-certs` и `Entry.ca`) со стражем без ответа — неизвестный исход — барьер (глава 8.10 N1.7): успехом не считается,
обработка прерывается, ответ — 503 `{error: "unavailable"}`, у пакета ретранслятора — всему пакету.

При барьере неизвестного исхода записи принятое до него не
откатывается: повтор агента с тем же `sent_at` — same или heard, ответ carry.

Страж записи дверей агентов отказал — процесс ждущий, ответ —
503 `standby` (всему пакету).

Подтверждённый сбой записи после метки (`on_accept`, не неизвестный исход и не отказ стража) — отчёт принят: ответ carry, сбой — диагностика процесса без значения, `on_accept` повторит запись при следующем принятом отчёте (`tls_ca` ≠ `Entry.ca`). Подтверждённый сбой записи до метки — 503 `unavailable`.

### прочитать копию (глава 8.1 N3 шаг 2; главы 8.5, 8.8)

- Прочитать reported и названное им поколение; при отсутствии объекта или несовпадении хеша перечитать reported ровно один раз и прочитать названное этой меткой поколение.

- Точное новое поколение — копия.

- Стабильная метка с отсутствующим или несовпадающим объектом сохраняет silent.

Изменившаяся метка без точного нового поколения временно не подтверждена: отложить производный снимок; требующая подтверждения дверь даёт существующий 503 unavailable. Не смешивать поколения, не зацикливаться и не читать объекты выше метки.

### принять члена (процесс domain, POST /domain/members через консоль домена — глава 8.0)

Имя кластера (`CLUSTER`) уникально на весь домен: от него строятся ключи `domain/*/<член>`, id записей `<кластер>/<ключ>` и адреса. Держит это приём: шаг 1 — имя уже члена с другим ключом — 409, имя держателя — 400; шаг 2 — второй ключ под тем же стучащимся именем — 409: стук не занимает имя, занимает только приём. Переименования нет: другое имя — уход и новый приём.

0. сбор «из ничего» не закрыт (глава 8.8 N1.8a) → 429 `{error: "busy", retry_in: 60}`, имя не занято. На шаге 0 условие: If-Match не равен версии строки раздела этого имени (глава 8.0 N1.9) → 412 revision moved. На шаге 0 строка, которая нужна приёму, есть, но не читается: строка раздела этого имени, `domain/knocks/<part>`, а при knock.pinned — `domain/root` (отпечаток своего корня, N1.1 knock) → 503 `{error: "unavailable"}`, ничего не записано, журнал без значения.

1. name — держатель → 400. На шаге 1 name = domain → 400 «domain is the name of the domain's own grants» (глава 8.4 N1.9). На шаге 1 name = servers → 400 «servers is a word of a book's to: pick another name» (договор конвертов домена «Вклад»). На шаге 1 запись name без key с revoked_keys (машина после кражи, глава 8.2 шаг 3a) — как не член, дальше по шагам.

На шаге 1 name уже член: fingerprint = отпечаток его Entry.key → 200 без записи (ETag — индекс прочитанной строки); иначе → 409 «\<name> was admitted with another key: have it leave first» (член не стучится — «уже член» раньше knocking). На шаге 1 name нет в view.knocking и в `domain/knocks/<part>` → 404 «\<name> is not knocking».

2. fingerprint ≠ отпечаток knock.key → 409 «\<name> presents another key than the one compared: look again». На шаге 2 knock.key малого порядка или не точка кривой (договор подписи агента — ключ малого порядка; P/09.1 N1.1 pub) → 409 «\<name> presents a key that signs nothing».

3. knock.pinned = another → 409 «\<name> pinned another root than this domain's: join it again».

4. knock.key в revoked_members набора или в revoked_keys записи этого имени → 409 «this key was revoked».

5. Шаг «уже член» — не шаг 5: он в шаге 1.

5a. name не член и записи этого имени нет (шаг 6 её перезапишет, строка не растёт): строка с Entry больше потолка P/01.1 N1 → 409 «this name's row is full: pick another name»: снятие ушедших не поможет, поможет другое имя. На шаге 5a class server и `domain/member-count.servers` = SERVERS_MAX → 409 «too many servers» (глава 8.10 N1.5). На шаге 5a class server и в разделе name строка `domain/book-keys/<sub>/<book>/<part>` какой-либо книги больше NEAR_CEILING (глава 8.5 N1.3 ceiling) → 409 «this name's section is near the book ceiling: pick another name»: другое имя — другой раздел.

5b. class camera, cameras ≥ 16 и взявших копию меньше BACKUP_HOLDERS (глава 8.8 N1.5 new_camera) → 409 «a domain of this size needs \<n> backup holders: add a server first». На шаге 5b строка `domain/relay-members/<via>` не влезает → 409 relay full (N1.2).

6. записать строку раздела по CAS, подпись: rev + 1, term — свой, Entry `{how: "admitted", since, class, by, key, via?, batch?}` — class стука, via и batch стука партии, revoked_keys прежней записи остаются. На шаге 6 тем же пакетом `domain/member-count` или счёт раздела (глава 8.8 N1.8a счёт), `domain/relay-members/<via>` при via, снятие стука из `domain/knocks`. На шаге 6 used + 1 партии — при приёме человеком нет. На шаге 6 любая Entry документа (глава 8.10 N1.5 every_entry) больше ENTRY_MAX (глава 8.10 N1.5) — 409 «the entry of \<name> would exceed ENTRY_MAX bytes».

   - На шаге 6 конфликт CAS →
     перечитать и повторить с шага 1 («уже член» — по перечитанному списку) не больше трёх раз, затем 409 «the list of members kept changing; look again».

### держатель в списке (процесс domain, при старте и при приёме отчёта своего агента)

Конфликт CAS — перечитать, не больше 8 раз.

При старте двери нет: исчерпание или сбой — журнал без значения, запись повторит следующий отчёт своего агента.

На дороге отчёта шаги идут по порядку договора приёма отчёта `order`: исчерпание или сбой — 503 `unavailable`, агент повторит.

1. имени держателя нет в `domain/member-rows/<part>`, или его Entry не how: "holder" (после переноса и передачи: из копии — admitted, глава 8.8 N1.1 claim) → записать по CAS Entry `{how: "holder", since, key?}` — key прежней Entry, если есть, иначе без key. На шаге 1 by нет (форма Entry держателя одна — N1.1). На шаге 1 записи не было — тем же пакетом `domain/member-count` или счёт раздела (глава 8.8 N1.8a счёт).

2. отчёт агента держателя: Entry держателя без key → проверить подпись ключом, который отчёт предъявил (P/09.1 N1.2 key), и что это pub своей `domain/member-key`: иной ключ, строки нет или она нечитаема — 403, дверь открыта всем, иначе чужой впишет свой ключ. На шаге 2 ключ в её revoked_keys или в revoked_members набора — 403 отозван, ничего не записано. На шаге 2 ключ, который отчёт предъявил, — pub своей `domain/member-key` и не отозван ни в её revoked_keys, ни в revoked_members набора → вписать этот ключ в key Entry держателя по CAS. На шаге 2 дальше — как у любого члена: другой ключ — 403.

Держатель отчитывается о себе подписанным отчётом, как любой член; отпечаток человек не сверяет: процесс `domain` и агент — на одном кластере. Взятие срока и прежний держатель — глава 8.8.

`DELETE /domain/members/<член>`: держатель — 400; не член — 404; `If-Match` не равен версии строки раздела — 412.

`DELETE /domain/members/<член>`: если ни один отказ P/08.3-R335 не подошёл, убрать запись по CAS, `rev + 1`, не больше трёх конфликтов, затем 409 «the list of members kept changing; look again».

У `DELETE /domain/members/<член>`, пока идёт сбор «из ничего», — тем же пакетом имя в `removed` и счёт раздела (глава 8.8 N1.8a).

У `DELETE /domain/members/<член>` метка `reported` члена с `rev` = 2^53 − 1 снимается вслед за записью списка: иначе приём заново снова упрётся в `rev_exhausted`. Ушедший член не читается следующим проходом вида (глава 8.1): его копия и стук забываются в тот же проход.

### держатель на POST /api/relay/\<ретранслятор>

0. строки пакета — `domain/member-rows/<part>`, `domain/keys`, `domain/revoked`, `domain/topology` — есть, но не читаются или чтение не
   подтверждено → 503 `{error: "unavailable"}` всему пакету до шага 1: топология не подменяется direct, обхода и записей
   нет, журнал без значения (как N3 «принять»).

1. ретранслятор, ключ и подпись — по порядку строки N2 POST /api/relay.

2. для каждого relayed[член]: имя не по грамматике имени члена → refused[\<имя как пришло>] и пропуск (пакет живёт). На шаге 2 идёт сбор «из ничего» (глава 8.8 N1.8a): публикация с row — подпись, затем merge, член не в списке или с другим ключом — refused[член] = {reason: send_row}. На шаге 2 член не в списке или via[член] ≠ ретранслятор → refused «\<член> does not reach the domain through \<ретранслятор>: the topology says \<via или direct>». На шаге 2 key публикации ≠ key записи члена или отозван (revoked_keys, revoked_members набора) → refused «\<член> presents another key than the one in the list, or it was revoked», ничего не записано.

   - На шаге 2 relayed[член] больше BODY_LIMIT → refused.

На шаге 2 член, к которому не подошёл ни один случай P/08.3-R343, P/08.3-R345, → принять (договор приёма отчёта) с via = ретранслятор и байтами relayed[член] (JCS). На шаге 2 отказ принять → refused (слово договора приёма отчёта). На шаге 2 метка или поколение этого члена не читаются или чтение неполно (N3 «принять») → refused[член] = "unavailable", этому члену carry нет, прочие члены исполняются.

   - На шаге 2 отказ одного члена — в refused, не код.

3. стуки — P/09.2 N1.4 knocks, с полем batch — договор приёма отчёта «Стук партии», с полем row — merge главы 8.8 N1.8a, отправитель — имя стука. На шаге 3 стук не по форме P/09.2 N1.4 — пропуск без записи, пакет живёт. На шаге 3 стук с pinned в теле при нечитаемом или не подтверждённом `domain/root` — пропуск без записи, пакет живёт. На шаге 3 стуков больше KNOCKS — сверх первых 32 по имени пропуск без записи.

   - На шаге 3 тело стука больше 256 KiB, с полем row — больше 768 KiB — пропуск без записи
     (договор приёма отчёта «Пакет ретранслятора: пределы»).

4. ответ: collecting: true, пока идёт сбор. На шаге 4 relay_for и keys из `domain/relay-members/<relay>`, только если relay_rev пакета ≠ rev строки: после переноса rev бывает и меньше. На шаге 4 relayed — carry только членам с телом в этом пакете (rev — для этой дороги: метки, если её via — этот ретранслятор, иначе 0), refused, keys.

Пакет ретранслятора (`relayed`, `knocks`), ответ (`relay_for`, `relayed`, `refused`, `keys`) —
[P/09.2](../../../09-agent/ru/spec/09.2-agent.norms.md) N1.4; `BATCH_LIMIT` и `KNOCKS` — [договор приёма отчёта](../../../common/ru/contracts/accept.md) «Пакет ретранслятора: пределы»; схема тела двери и ответа — [контракт урока](../../spec/08-domain.api.openapi.yaml).

Стук из пакета
держатель проверяет подписью ключом, который тело предъявило, над `POST /api/member/<имя>` и телом: верная — стук
(N1.1 `knock`), неверная или член, кроме записи без key с revoked_keys (N3 «принять члена» шаг 1), — пропуск.

Машина с записью без key с revoked_keys и `via` на двери ретранслятора получает 403 и возвращается после снятия `via` правкой топологии (P/09.2 N1.4 `knocks`).

Стук (N1.1 `knock`, договор приёма отчёта «Стук») с `pinned` в теле сравнивается с отпечатком `domain/root`. У стука с `pinned` в теле, если строка `domain/root` есть, но не читается, или чтение не подтверждено, — стук не записывается (`pinned` не подменяется на `none` или `another`), журнал без значения. У стука с `pinned` в теле при нечитаемой или не подтверждённой `domain/root` ответ двери не меняется — прямой `POST /api/member` незнакомца отвечает 404 «не член» (список членов прочитан, ответ верен), в пакете ретранслятора этот стук пропускается, пакет живёт. Без `pinned` в теле корень не нужен — стук `none` пишется как всегда.

**Гонки.** Список пишет один процесс `domain` (глава 8.0): правки людей, держатель в списке, `claim` и `Entry.ca` (N1.6;
глава 8.8) — по CAS одной строки, конфликт — перечитать.

Агент строк держателя не пишет.

Приём отчёта и проход вида — в
одном процессе `domain`, вид читает метку и поколение не выше неё.

Приём `tls_ca` и правка администратора одной записи — CAS `domain/member-rows/<part>` (N3 «принять члена»). Две дороги одного члена — правило N1.3a: держатель не смешивает их тела.
