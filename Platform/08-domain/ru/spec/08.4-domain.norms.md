## N1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону N0](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке):

`domain/groups/<name>` — `at`, значения `joined`; `domain/roles/<name>` — `at`, `assigned[].until`, `assigned[].at`.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/anywhere`, `domain/users/<name>`, `domain/deleting/<name>`, `domain/disabled`, `domain/grants/<cluster>`, `domain/break-glass/<cluster>`, `domain/groups/<name>`, `domain/roles/<name>`;
- пишет: `domain/revoked` (cas), `<events root>/audit.alarms/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `domain/keys`, `domain/revoked`, `domain/signer`, `domain/signer-turn`, `domain/names/<sub>/<book>`.

Токен человека и отзыв — [договор токена домена](../../../common/ru/contracts/domain-token.md) и [договор набора ключей
домена](../../../common/ru/contracts/keys.md) «Отзывы» (строки `domain/keys`, `domain/revoked` — [глава 8.2](08.2-domain.norms.md)
N1.6).

Ключ токенов держателя — строка `domain/signer` (глава 8.2 N1.3).

Страж записей — `domain/signer-turn` ([глава
8.10](08.10-domain.norms.md) N1.7).

Индексы имён для проверок дверей людей и грантов — `domain/names/<sub>/<book>`
([глава 8.5](08.5-domain.norms.md) N1.7).

Копию `domain/grants` `{doc, as_of}` у члена пишет агент ([глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `member_copy`).

Форма
`doc` у копии члена и у строки держателя — одна (`common.grants_doc`).

Общее N1 глав 8.0–8.3, 8.5–8.7 действует ([P/08.2 N1](08.2-domain.norms.md) «Общее для всех форм главы»; пересылка —
[договор пересылки](../../../common/ru/contracts/forwarding.md)).

Люди живут у держателя.

Токен человека называет субъект и ничего больше ([договор токена
домена](../../../common/ru/contracts/domain-token.md) «Токен», `kind: person`, без `aud`).

Что человеку можно, решает каждый
кластер по своим грантам, которые несёт агент; проверка — локальное чтение без связи с доменом.

Люди с паролями и
аварийные пароли — операции процесса `domain` (подписант), он проверяет каждую сам.

Гранты пишет тоже процесс `domain` ([глава
8.0](08.0-domain.norms.md) N1.8: консоль домена правку передаёт).

### N1.1 Человек

```yaml
domain/users/<name>:  {name, how, pwhash_secret, disabled, title?, email?, expires?, pw_by?, at, by, revision}   # у держателя
  name:        имя человека
  how:         "password"
  pwhash_secret: хэш пароля
  disabled:    true | false
  title:       отображаемое имя
  email:       строка
  expires:     0 | стенные секунды
  pw_by:       имя того, кто последним задал пароль
  at, by:      стенные секунды и имя человека последней правки
  revision:    счётчик правок
PASSWORD_MIN:  forms/runtime-constants.tsv          # знаков
domain/disabled: {names: <текст JCS массива имён>}
delete:        строка человека и его строки грантов
domain/deleting/<name>: {at, done?}    # метка удаления человека
unreadable:    строка человека, которая не читается
```

`domain/users/<name>` — у держателя; писатель — процесс `domain`.

`name`: имя человека — форма и пробельные знаки — договор имени человека common/contracts/person-name.md `name`,
`white_space`; не по форме — 400 `bad name`.

`how`: иных способов входа урок не нормирует.

`pwhash_secret`: форма, хэш и проверка — договор хэша пароля common/contracts/password-hash.md.

`pwhash_secret` — секрет по суффиксу (P/02.1 N1.3a), запечатан кольцом держателя.

`title`: отображаемое имя, строка до `GROUP_TITLE_MAX` знаков; поля нет — `""`.

`email`: строка 0..254 знаков; поля нет — `""`.

`email`: форму адреса платформа не проверяет, писем не шлёт.

`expires`: 0 — без срока; иначе стенные секунды; поля нет — 0.

`expires`: now ≥ expires — человек «выключен по сроку».

`pw_by`: имя того, кто последним задал пароль (доказанное сторожевой; у first-admin — сам заводимый); поля нет — «задал не администратор».

`pw_by` пишется при first-admin,
`POST /domain/users`, смене пароля.

`at`, `by`: стенные секунды и имя человека последней правки (доказанное сторожевой).

`revision`: глава 8.0 N1.9 «Версии»: 1 при создании, +1 на каждую запись строки.

Писатель `domain/users/<name>` поле со значением по умолчанию (`title`, `email`, `expires`) не пишет.

`PASSWORD_MIN` считает знаки: кодовые точки Unicode, не байты.

`domain/disabled`: имена выключенных по возрастанию в байтах UTF-8, без повторов; нет —
`"[]"`; массив, не строка через «,»: имя может нести запятую.

`domain/disabled`: писатель —
процесс `domain` при каждой правке `disabled` и сверкой каждым проходом (N3 «срок»).

`domain/disabled`: имя здесь, если `disabled = true` или
now ≥ `expires`: выключен по сроку = выключен.

`domain/disabled`: вход (N1.2 `check`), `may` шаг 2 и `carry` судят по `domain/disabled` и полю
`disabled`, `expires` напрямую не читают.

`domain/disabled`: окно «срок наступил, прохода ещё не было» — не дольше прохода.

`domain/disabled` секретов не несёт.

`delete`: удалить строку человека и снять его строки во всех `domain/grants/*` (N1.3) — одной правкой на строку грантов.

`delete` идёт под меткой удаления ниже (N3 «дверь людей» шаг 9).

`domain/deleting/<name>`: метка удаления человека у держателя; писатель — процесс `domain` под стражем `domain/signer-turn`.

`domain/deleting/<name>`: метка стоит с начала `DELETE` до снятия всех строк грантов с `subject = <name>` и ещё до `at + TOKEN_LIFETIME + TOKEN_SKEW`: токен удалённого
живёт столько, новый человек этого имени за него не отвечает.

`domain/deleting/<name>`: `at` — момент записи метки; `done` — строки сняты.

`domain/deleting/<name>`: `at` нет или не читается, в том числе у метки роли, — срока нет.

`domain/deleting/<name>`: пока метка стоит, имя занято:
`POST /domain/users` — 409 `exists`, новая строка гранта с этим subject — 409 `being deleted`.

`domain/deleting/<name>`: сверка при
старте и каждым проходом главы 8.1 снимает по ней строки грантов и удаляет метку, когда строк нет и срок вышел.

`domain/deleting/<x>`: ключ метки `<x>`: имя человека по N1.1 или `role:` и имя роли (N1.3a); `role:<R>` — метка удаления роли, N3 «роли».

`domain/deleting/<x>`: метка — любая строка под `domain/deleting/`, что бы ни лежало в `items`.

`domain/deleting/<x>`: `<x>` не по грамматике — ни то ни другое —
сверка удаляет метку с журналом `domain.deleting.dropped {key, reason: "not a name"}`, строк грантов не
ищет (subject таким не бывает); проход из-за неё не стоит.

`unreadable`: строка человека, которая не читается (не по форме N1.1 или `name` ≠ `<name>` ключа), пропускается и считается
(диагностика процесса), остальные служат.

`unreadable`: строка человека, которая не читается, `domain/disabled` не снимает: имя её ключа остаётся там, если
было.

`unreadable`: `DELETE /domain/users/<name>` удаляет и строку человека, которая не читается, — снятие строк грантов и метка как у читаемой
(иначе испорченная строка вернула бы выключенному старые токены).

**Ключевой контекст писателя метки.** Прежний ключ `domain/deleting/role:<name>` выбирает пустые items писателя `{}`, без `at`, `done` и срока токена человека.

Ключ человека в `domain/deleting/` выбирает `{at,done?}`, где `at` обязателен; `{}` не является положительной writer-формой метки человека.

Два локальных определения `person_writer` и `role_writer` схемы deleting требуют выбора по ключу до раскодирования и проверки писателя; объединение без ключа не доказывает условия.

У читателей `domain/deleting/` прежние присутствие/запреты/восстановление сохраняются и при повреждённом содержимом метки.

Общий предел имён писателя считается с полями выбранного по ключу профиля: обязательный person `at` не становится универсальным.

Нынешняя привязка потребителя без ключа — явная зависимость, не разрешительный fallback.

### N1.2 Вход, токен человека, отзыв

```yaml
door:          POST /api/login {user, password}
via:           POST /api/login через консоль домена
check:         предел N1.10 → человек → пароль → токен
answer:        200 {token, until, user} | 401 {error: "refused", detail: "wrong user or password"}
token:         токен человека
TOKEN_LIFETIME: forms/runtime-constants.tsv        # с
LOGIN_BODY:    forms/runtime-constants.tsv
revoke:        POST /domain/revoke {token}
login_url:     P/06.3 N1.3
deposed:       409 deposed
```

`door`: `POST /api/login {user, password}` у процесса `domain`.

`door`: тело ≤ `LOGIN_BODY` (больше — 413 `{error: "too large", detail}`).

`door`: оба поля — строки (иначе 400 `{error: "bad body", detail}`).

`door`: дверь cookie не ставит и не читает.

`via`: страница ходит к своей консоли: `POST /api/login` — открытая строка списка дверей домена договора пересылки
и `open_routes` договора сторожевой (P/06.3 N1.3), консоль домена передаёт её процессу (глава 8.0 N1.8).

`via`: CORS нет — другой origin страница не зовёт.

`check`: предел N1.10 → человек есть, не disabled и имени нет в `domain/disabled`, пароль сверился (сравнение постоянного времени) → токен.

`check`: сверка PBKDF2 (и у аварийного входа N1.6) не держит общего замка процесса: прочие двери её не ждут.

`check`: нет человека или disabled — сверка по фиктивному хешу той же стоимости (`PBKDF2_ITERATIONS`): ответ неизвестному,
выключенному и неверному неразличим и по коду, и по телу, и по времени.

`check`: строка `domain/users/<name>` есть, но не читается — 503 `{error: "unavailable"}`, не 401 (исход семьи users;
различимость имени здесь допустима).

`answer`: 200 `{token, until, user}`; иначе 401 `{error: "refused", detail: "wrong user or password"}` — отказ в счёт
предела N1.10.

`token`: договор токена домена «Токен», строка person (поля токена человека).

`token`: `iat` — `credential_at`, зафиксированное при подтверждённом чтении credential до проверки пароля без общей блокировки.

`token`: ключ токенов
держателя (current набора); `until` = `exp`.

`revoke`: `POST /domain/revoke {token}` — строка списка дверей домена договора пересылки; консоль домена передаёт её
процессу `domain` (N1.9 `pass`).

`revoke`: токен проверяется функцией `token` договора токена домена «Проверка» с `expect {kind: person, cluster: null}`.

`revoke`: токены видов с `keep` отзывает `DELETE /domain/issued`, вид без `keep` живёт до `exp`, закрывает его смена ключа: предел; иначе член обходил бы счёт и запас слова `revoked`.

`revoke`: токен не
прошёл, в том числе `wrong_kind`, — 401 со словом `token`.

`revoke`: `no_revocations` — 503 `unavailable` (N1.5).

`revoke`: строка `domain/revoked` полна — 409 `too many revocations`, ничего не записано (глава 8.2 N1.6a limit).

`revoke`: `jti` и `exp` добавляются в `domain/revoked` (глава 8.2 N1.6; договор набора
ключей домена «Отзывы») — ответ 200 `{revoked: <jti>}`.

`revoke`: отозвать токен может тот, кто его держит.

`revoke`: страница
зовёт дверь при выходе (P/06.3 N1.3 `DELETE /session` — снимает cookie).

`login_url`: P/06.3 N1.3 (`LOGIN_URL` окружения, умолчание `/api/login`).

`deposed`: смещённый держатель токенов не выдаёт — 409 `deposed` (глава 8.8 N1.6).

Ссылки блока: список дверей домена и пересылка — [договор пересылки](../../../common/ru/contracts/forwarding.md); `open_routes`,
`login_url`, `/session` — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Сторожевая»
([P/06.3](../../../06-console/ru/spec/06.3-console.norms.md) N1.3); токен и `token` — [договор токена
домена](../../../common/ru/contracts/domain-token.md).

**Начало времени login.** При подтверждённом чтении включённого credential зафиксировать стенные `credential_at` и монотонное начало до PBKDF2 без общей блокировки.

Успех токена человека использует `iat = credential_at`, `exp = credential_at + TOKEN_LIFETIME`, ответ `until = exp`; подпись, более позднее чтение или повтор не обновляют начало.

После проверки пароля и непосредственно перед выдачей, если монотонная длительность не меньше TOKEN_LIFETIME либо стенные now не меньше exp, вернуть 401 `{error: "refused", detail: "login took too long; try again"}` без токена; новый запрос заново читает свой credential.

Задержка после последней проверки времени всё равно не продлевает iat или exp.

Поэтому DELETE и последующее создание того же имени не превращают приостановленную проверку старого пароля в новый токен нового человека.

Обычный login прежний; это начало времени login не меняет выдачу keep/kind токенов.

### N1.2a Проверка учётных данных без входа

Подтверждение действия вторым человеком (у VMS — супервизор экспорта): пароль сверяется, как при входе, но токена, куки и сеанса нет.

```yaml
door:          POST /api/verify {user, password}
ticket:        X-W2C-Ticket: <sub>
check:         сверка N1.2 check
answer:        200 {user} | 401 {error: "refused", detail: "wrong user or password"}
journal:       domain.verify, domain.verify.limited
```

`door`: `POST /api/verify {user, password}` у процесса `domain` — ровно эти два поля-строки, тело ≤ `LOGIN_BODY` (иначе 400 `bad body`,
413 `too large`, как у входа).

`door`: путь от кластера — `POST /domain/verify` (договор пересылки «Двери домена»; глава 6.7 N1.3).

`ticket`: только запрос по билету: `X-W2C-Ticket: <sub>` (договор пересылки «Билет на пересылке») процесс читает только на
соединении роли `domainconsole`; нет его или он не прочитан — 403 `{error: "denied", detail: "by a ticket only"}`.

`ticket`: автор —
user токена человека пересылки (договор токена домена «Проверка», kind person); токена человека нет — 403 `denied`.

`check`: та же сверка, что N1.2 `check`: предел (N1.10 `verify`: допуск с резервом по трём ключам) → человек есть, не disabled, имени нет в `domain/disabled`, пароль сверился
(постоянное время, фиктивный хеш той же стоимости неизвестному и выключенному).

`check`: строка `domain/users/<name>` не читается —
503 `unavailable`.

`check`: смещённый держатель — 409 `deposed`.

`check`: standby — 503 (глава 8.10 N1.7).

`answer`: 200 `{user}`; иначе 401 `{error: "refused", detail: "wrong user or password"}` — в счёт предела N1.10 `verify`.

`answer`: токена нет,
`Set-Cookie` нет.

`answer`: право проверенного здесь не судится — его судит консоль кластера (глава 6.7 N1.3 «проверка без входа»).

`journal`: audit процесса `domain`: `domain.verify {by_sub, by_user, user, outcome: ok | refused | unavailable}` — без пароля.

`journal`: отказ предела — `domain.verify.limited {by_user, user, limit: pair | author | name}` — сработавший ключ (N1.10
`verify` `answer`).

`journal`: отказ формы (400, 413) — без строки.

### N1.3 Гранты

```yaml
domain/grants/<cluster>:  {doc: <JCS text {lines}>, revision}   # у держателя
  lines:       [line…]
  line:        {subject, cap, sub?, scope, until, by}
    subject:   имя человека | субъект индекса имён | role:<имя роли>
    cap:       none | view | edit | admin
    sub:       имя манифеста | platform
    scope:     * | unit:<sub>/<id> | labels:<label>[,<label>…] | folder:<id>
    until:     0 | стенные секунды
    by:        имя, доказанное сторожевой
  rewrite:     переписывание документа внутри процесса
  writer:      процесс domain
  revision:    счётчик правок, рядом с doc
domain/grants/domain: гранты двери домена
last_admin:    доказанный администратор
GUARD_RETRIES: forms/runtime-constants.tsv
carry:         sealed ответа агенту: grants, roles
anywhere:      строка domain/anywhere {doc: {<person>: <until>}, as_of}
carry:         {as_of, sha256} сводки
ANYWHERE_MAX:  forms/runtime-constants.tsv    # байт JCS doc
```

`last_admin`, стражи доказательства: запись, прошедшая проверку, несёт в пакете P/01.1 (`op: batch`, `guards`) стражей строк, доказывающих

`carry`: для `anywhere` подтверждённое отсутствие убирает поле и его имя из held; нечитаемая сводка даёт `held: ["anywhere"]`.

`carry`, для `anywhere`: если прежнюю сводку прочитать нельзя, `carry` указывает `anywhere` в held.

`carry` для `anywhere`: камера строку не держит: вход по `anywhere` у неё не действует, чужой человек через камеру не входит: предел.

`carry` для `anywhere`: `sha256` — lowercase hex SHA-256(UTF-8(JCS({doc, as_of}))) всего JSON-значения тела 200 `GET /api/anywhere/<member>`; `as_of` входит. Хеш не от одного `doc` и не от сырых байтов HTTP.

`carry` для `anywhere`: HTTP-тело — строковая форма `HolderAnywhereBody` OpenAPI владельца: хеш до разбора внутреннего `doc` и преобразования времени его тела.

`unreadable`: строка, которая не читается, прав не даёт.

`unreadable`: строка `lines`, которая не по форме, у прямой группы пропускается и считается

`unreadable`: разбор такой строки — в две ступени: субъект прочёлся как `role:R` — неполна группа R (если
прочёлся и `sub` — только в этой `sub`), субъект не прочёлся — неполны все группы ролей документа; признак доходит до `may`
(вход `unread` договора права).

### N1.3a Группы и роли

```yaml
domain/groups/<name>:  {name, title, comment, members, joined, source, at, by, revision}   # у держателя
  name:        имя группы
  title:       строка
  comment:     строка
  members:     [<имя человека>…]
  joined:      {<name>: <at>}
  source:      local
  at, by:      как у человека
domain/roles/<name>:   {name, title, comment, assigned, lines?, lines_at?, lines_by?, at, by, revision}        # у держателя
  name:        грамматика имени человека (1–64 знака)
  assigned:    [{person: <name>, until, at} | {group: <name>, until, at}…]
    at:        когда элемент начал действовать
  lines:       [{cap, sub?, scope, until}…]
  lines_at, lines_by: когда и кем записаны
  supervision: {<sub>: <роль супервизоров>}
  referenced:  DELETE роли, на которую ссылается supervision
spread:        проход держателя (раз в VIEW_EVERY)
role_at:       {<role>: <at>}
GROUP_TITLE_MAX: forms/runtime-constants.tsv       # знаков
COMMENT_MAX:   forms/runtime-constants.tsv        # знаков
unreadable:    строка группы или роли, которая не читается
roles_now:     роль R действует у человека u
```

`domain/groups/<name>` — у держателя; писатель — процесс `domain`.

`name` группы: имя — договор имени человека; не по форме — 400 `bad name`.

`name` группы: пространство имён своё: группа может называться как человек или
роль, в строки грантов группа не входит.

`title` группы: строка до `GROUP_TITLE_MAX` знаков.

`comment` группы: строка до `COMMENT_MAX` знаков.

`members`: по возрастанию в байтах UTF-8, без повторов.

`members`: каждый — человек домена, иначе 400 `unknown member`.

`joined`: `{<name>: <at>}` — когда каждый член вошёл в группу (время записи, в которой имя появилось); ключи — ровно `members`; нужно N1.3c «токены».

`source`: `local`; иное — 400 `bad body`.

`domain/roles/<name>` — у держателя; писатель — процесс `domain`.

`assigned`: без повторов по (вид, имя); порядок — (вид, имя) в байтах UTF-8; вид
person раньше group.

`assigned`: until — как until строки гранта.

`assigned`: person — человек домена, group — группа домена, иначе 400 `unknown member`.

`assigned[].at`: когда элемент начал действовать: совпавший по (вид, имя) с действующим прежним сохраняет `at`, иначе время записи.

`assigned[].at` телом двери не задаётся.

Права роли — строки grants с `subject role:<name>` в `domain/grants/<cluster>`: форма, cap, sub, scope, until, by — как у строки человека.

`lines`: права роли на весь домен, источник расхождения по кластерам; нет поля — роль кластерная.

`lines`: scope только `*` или `folder:<id>`: `labels:` запрещены у любой строки роли, включая общую роль; `unit:` дал бы права на разные единицы в разных кластерах — 400 `bad line`.

`lines_at`, `lines_by`: когда и кем записаны; телом не задаются.

`lines_at`: те же lines второй раз — запись без новых `lines_at`: повтор двери не перекрывает слово `local`.

`supervision`: `{<sub>: <supervisor role>}` — действие автора с этой ролью над подсистемой `<sub>` требует подтверждения человеком роли
супервизоров.

`supervision`: платформа хранит и судит членство, смысла подсистемы не знает; нет поля — надзора нет.

`supervision`: ключ — по грамматике имени подсистемы (P/02.1 N1.2), значение — по грамматике имени роли, иначе 400 `bad body`.

`supervision`: роли
супервизоров нет — 400 `unknown role`.

`supervision`: своя роль супервизоров допустима.

`supervision`: у роли admin — 409 `builtin`.

`referenced`: `DELETE` роли R, на которую ссылается supervision другой роли, — 409 `role referenced`, пока ссылка стоит.

`referenced`: ссылка роли на
саму себя уходит вместе с ней и удалению не мешает.

`spread`: проход держателя (раз в `VIEW_EVERY`, N3 «расхождение роли»): lines каждой роли — в `domain/grants/<member>` каждого члена, отдельной записью на кластер, а не
одним пакетом: отказ одного не откатывает прочие, предела числа кластеров нет.

`spread`: новый член получает строки тем же проходом, отдельного шага при входе нет.

`spread`: предел: до `VIEW_EVERY` после приёма у нового кластера нет строк доменных ролей, человек с правом только через роль домена его не видит.

`role_at`: `{<role>: <at>}` элемент строки `domain/grants/<member>`: когда строки этой роли на кластере записаны в последний раз, проходом или дверью грантов.

`role_at`: последнее слово по at: правка на кластере новее `lines_at` — кластер остаётся как есть, слово `local`; lines новее — проход перезаписывает.

`GROUP_TITLE_MAX` считает знаки; `title` роли — то же.

`unreadable`: строка группы или роли, которая не читается, прав через себя не даёт, ссылки в ней «есть»: свободу имени она не доказывает (N3).

`roles_now`: роль R действует у человека u, если в `assigned` роли есть `{person: u, until}` или `{group: G, until}` с u в `members` группы G,
и until = 0 или now < until.

`roles_now`: срок строки `role:R` и срок назначения действуют оба.

`roles_now`: одна роль у человека дважды — более поздний
until (0 — позже всех).

`roles_now`: назначения действуют по всему домену.

Строка `domain/roles/admin` — встроенная роль, N1.3c.

**Публичный supervision.** POST `/domain/roles` и PUT `/domain/roles/{name}` принимают закрытое необязательное поле `supervision: {<sub>: <role>}`; GET `/domain/roles` возвращает его, когда поле хранится.

В POST `/domain/roles` отсутствие `supervision` или `{}` означает отсутствие надзора.

В PUT `/domain/roles/{name}` отсутствие `supervision` сохраняет прежнюю карту, `{}` снимает её (поле из строки удаляется), непустая карта заменяет целиком; `null` — 400 bad body.

Те же правила действуют для `fields.supervision` записи role put в POST `/domain/batch` по конечному снимку.

Отсутствующая роль надзирающих, кроме самой роли, — 400 unknown role; нечитаемая роль ссылки — 503 unavailable.

Самоссылка `supervision` разрешена и при создании: прежняя собственная строка ей не нужна.

На прочие роли, на которые ссылается `supervision`, ставятся guards прочитанных версий.

Установка или снятие supervision у встроенной admin — 409 builtin.

Ссылка из другой роли запрещает DELETE с 409 role referenced; самоссылка снимается с самой ролью.

Чтение и запись `supervision` — обычные операции ролей с прежними правами, CAS, счётчиками и памятью повторов; ручная правка хранилища для установки или снятия надзора не требуется.

```yaml
roles_at_holder: вход roles функции may у процесса domain и консоли домена
```

`table.assigned`: роли, у которых есть строки в `domain/grants/<member>`, всегда `admin` и всегда — каждая роль с `supervision` и каждая её роль
супервизоров, даже без строк этого кластера; элементы — как `assigned` строки роли, без `at`.

`table.groups`: только группы из `assigned` этих ролей; члены — как `members` строки группы.

`table.supervision`: supervision каждой роли домена, у которой оно есть; нет таких — поля нет.

`table.unreadable`: нечитаемые строки ролей домена и групп из `assigned` ролей с надзором и их ролей супервизоров — отметкой вместо пропуска:
у такой роли supervision и состав неизвестны, консоль судит надзор в пользу надзора (договор
сторожевой и передачи «Надзор»); нет таких — поля нет.

`table.unreadable` не пуст — проход держателя пишет журнал и тревогу
`domain.roles.unreadable {role | group}` (class alarm) раз в проход на каждую такую строку: она останавливает всякое действие с
надзором во всём домене (договор сторожевой и передачи «Надзор» limit).

`table.admin_at`: момент назначения admin каждому человеку с действующим назначением (N1.3c «токены»): значение пути с наибольшим until (0 — наибольший), при равных — наименьшее
из значений путей.

`table.admin_at`: значение прямого пути — `at` элемента, пути через группу — наибольшее из `at` элемента и `joined` человека.

`table.doc_sha256`: hex SHA-256 UTF-8 текста `doc` поля `grants` этого ответа, после фильтра `carry` (без строк выключенных): отпечаток того, что поехало к члену.

`table.filter`: без людей из `domain/disabled` (ни в `groups`, ни в `assigned`, ни в `admin_at`).

`table.filter`: нечитаемая роль в `assigned` не идёт, нечитаемая группа
ролей своим людям не даёт (сужение) — обе ещё и в `unreadable` (выше).

`ROLES_TABLE_MAX` считает байты JCS-текста таблицы одного члена; назначения admin (и группы только из них) в счёт не идут, их держит `ADMIN_TABLE_MAX` (N1.3c).

`limit`: держатель проверяет предел до приёма правки ролей, групп, людей и `domain/grants/<member>`: превышение — 409 `roles table too large`,
ничего не записано (как у отзывов, P/08.2 N1.6a limit).

`limit`: правка роли с supervision, её роли супервизоров или группы из их
`assigned` идёт в таблицу каждого члена — предел проверяется по таблицам всех членов, не уже проверки выше.

`limit`: превышен всё же (восстановление) — этому члену `held` (`carry`), журнал `domain.roles.too_large {member}` раз в проход.

`assemble`: согласованным чтением: держатель читает строки-источники члена (`domain/grants/<member>`, роли с его строками, роль admin, группы из их
`assigned`, роли с supervision и их роли супервизоров с группами, `domain/disabled`), собирает `doc` и таблицу, затем перечитывает версии источников. Совпали — пара согласована.

`assemble`: версии источников не совпали —
повтор, не больше трёх; затем этому члену в этом проходе `held` (`carry`), журнал `domain.roles.unsettled {member}`
раз в проход.

`assemble`: хранимой строки «таблица» у держателя нет.

`roles_at_holder`: вход `roles` функции `may` у процесса `domain` и консоли домена — из строк ролей и групп держателя, `as_of = null`; `at` — правило `admin_at`, у прочих ролей 0.

`roles_at_holder`: нечитаемая
`domain/roles/admin` или группа из её `assigned` — `roles = "unreadable"` (шаг 7b: 503, если прямые строки не разрешили).

Копия у члена `domain/roles` — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `member_roles`; связь с копией грантов и раскрытие — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Сторожевая с грантами» `roles_in`.

### N1.3c Встроенная роль `admin` и управляющий пользователями

Слово: *действующее назначение `admin`* — элемент `assigned` роли `admin` напрямую или через группу с `until = 0` или `now < until`.

Слово: *действующая прямая строка* — `{cap: admin, scope: *}` в `domain/grants/domain` с `until = 0` или `now < until`.

Слово: *администратор
домена* — человек с действующим назначением `admin` или с действующей прямой строкой.

```yaml
admin_role:    строка domain/roles/admin
ADMIN_ASSIGNED_MAX: forms/runtime-constants.tsv     # элементов assigned роли admin
ADMIN_TABLE_MAX: forms/runtime-constants.tsv    # байт JCS-текста части таблицы про admin
right:         действующее назначение admin
direct_line:   прямая строка {admin, *} в domain/grants/domain
manager:       строка роли одной формы в domain/grants/domain
               gives:  «управляющий пользователями»
               denies: 403 {error: "admin only"}
target:        статус цели «admin only»
batch_diff:    строки, которые пакет меняет
tokens:        токен человека и at его назначения admin
password:      назначение admin и pw_by
via_backend:   правка, пришедшая по пути backend
```

`admin_role`: строка `domain/roles/admin` есть всегда; пишет её first-admin (N1.9), у установки без этой строки — сверка прохода (N3 «сверка роли admin»).

`admin_role`: имя `admin` занято: `POST /domain/roles` с ним — 409 `exists`.

`admin_role`: меняется только `assigned`; правка `title`, `comment` и `DELETE` — 409 `builtin`.

`admin_role`: строка гранта `subject role:admin` в любом документе — 400 `bad line`: прав строками у роли нет, ослабить её нечем.

`ADMIN_ASSIGNED_MAX` считает элементы `assigned` роли `admin`; сверх — 409 `too many admins`.

`ADMIN_TABLE_MAX` считает байты JCS-текста части таблицы про admin: `assigned.admin`, группы из него с членами, `admin_at`, без фильтра disabled: верхняя граница, поэтому
включение человека предела не обходит.

`ADMIN_TABLE_MAX`: проверка на записи, а не на доставке:
`PUT /domain/roles/admin` и правка группы с действующим назначением admin сверх предела — 409 `admin table too large`.

`ADMIN_TABLE_MAX`: с `ROLES_TABLE_MAX`
таблица остаётся в потолке строки P/01.1; превышен всё же (восстановление) — `held`, как N1.3b `limit`.

`right`: действующее назначение admin — разрешено всё: шаг 4a договора права; в домене — все двери процесса `domain` и консоли домена.

`direct_line`: прямая строка `{admin, *}` в `domain/grants/domain` остаётся действующей формой: даёт двери домена и считается в `last_admin`.

`direct_line`: новые
установки её не пишут.

`manager`: строка роли одной формы в `domain/grants/domain`: `{subject: role:<R>, cap: admin, scope: *, until}` — без `sub`, без `folder:`, R ≠ admin.

`manager` `gives`: «управляющий пользователями»: двери людей, групп, ролей, чтение грантов и `PUT /domain/grants/<cluster>`, контактные поля людей.

`manager` `gives`: строка управляющего прав в кластерах не даёт.

`manager` `gives`: строка служит только этим дверям: у прочих дверей процесса и консоли домена её группа в `may` не считается;
топология, члены, размещение и передача — только администратору домена.

`manager` `denies`: 403 `{error: "admin only"}` (двери — только администратору домена):
назначать и снимать admin (`PUT /domain/roles/admin`); менять, выключать, удалять администратора домена, менять ему
пароль, срок, имя; менять состав группы с действующим назначением admin, удалять её; писать `domain/grants/domain`;
`DELETE /domain/roles/R`, если у R есть строка в `domain/grants/domain`; двери `/domain/break-glass…`.

`target`: статус цели «admin only» — по исходным строкам (`domain/roles/admin`, группы из её `assigned`, `domain/grants/domain`), а не по
отфильтрованной таблице `may`.

`target`: доказано, что цель — администратор домена, — 403 `admin only`; доказано, что нет (все эти строки
читаются, и ни одна не даёт), — разрешено в пределах роли; иначе — 503 `unavailable`, ничего не записано.

`target`: запись несёт стражей
этих строк, в том числе подтверждённого отсутствия (index `""`); конфликт — как N1.3 `last_admin`.

`batch_diff`: дверь пакета применяет перечень к каждой строке, которую пакет меняет: цель защищена до пакета или станет защищённой после него;
пакет меняет `assigned` роли admin, `domain/grants/domain` или строку аварийной учётки.

`batch_diff`: любая такая строка у управляющего —
403 `admin only` на весь пакет.

`batch_diff`: строки, которые пакет не меняет, не проверяются.

`tokens`: токен человека, выпущенный раньше `at` его действующего назначения admin (`at` элемента; через группу — наибольшее из него и `joined`
человека), шагу 4a и дверям `admin only` не служит: вход `iat` договора права.

`tokens`: прямая строка сравнения не требует.

`password`: назначение admin человеку, у которого `pw_by` — не он сам и не администратор домена, — 409 `password set by a non-admin`; то же при
включении такого человека в группу с назначением admin и при назначении admin группе с таким членом.

`password`: судятся только добавленные
элементы `assigned` и добавленные members; элемент с истёкшим `until` считается добавленным, как в правиле `at`.

`via_backend`: правка класса `admin only` и пароля человека, пришедшая по пути backend, поднимает тревогу `domain.rights_via_backend`
(администраторам домена, журнал audit домена) и пишет `via` в журнал.

`via_backend`: признак пути — заявленный заголовок `X-W2C-Via-Worker: <sub>/<instance>`, правом не служит.

`via_backend`: процесс верит заголовку `X-W2C-Via-Worker` только на
соединении своей консоли домена (договор пересылки; P/10 N1.3a).

N1.3; сессия с грантами — поздний слой урока P/06) и консоли домена (урок P/10 N1.5) и процесс `domain` (N1.5)).

### N1.5 Проверка у процесса `domain`

Из строк сторожевой с грантами глава владеет строкой `domain`: это сторона процесса `domain` (проверка у дверей процесса; форма — договор сторожевой и передачи «Права по телу», ниже).

Строки `cluster`, `session`, `body_unit`, `agent` сторожевой с грантами — консоль кластера (поздний слой
урока P/06; [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Сторожевая», [договор
права](../../../common/ru/contracts/may.md)).

Сторожевая консоли домена по той же строке `domain` — [урок P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md) N1.5 (P/10-13).

Строка
`loopback` сторожевой с грантами — [P/06.3](../../../06-console/ru/spec/06.3-console.norms.md) N1.8.

Строка `domain` (право у дверей `/domain/*` консоли домена и процесса `domain`) — [договор сторожевой и передачи](../../../common/ru/contracts/gate-and-pass.md) «Права по телу».

Личность у дверей процесса — токен (функция `token` [договора токена домена](../../../common/ru/contracts/domain-token.md)
«Проверка», `expect {kind: person, cluster: null}`; N3 «дверь людей» шаг 2, «гранты» шаг 1).

У дверей процесса: без токена или токен не прошёл — 401.

У дверей процесса: `may` — `deny` —
403, форма `{error: denied, detail}` ([P/06.3](../../../06-console/ru/spec/06.3-console.norms.md), N4 `denied`).

У дверей процесса: проверить нечем —
503 `{error: "unavailable"}`, не 401 и не 403: строка `domain/keys` есть, но не читается (проверить токен нечем), токен —
`no_revocations` (`domain/revoked` есть, но не читается), строка `domain/grants/domain` или вход `disabled` функции `may` —
`domain/disabled` — есть, но не читается (правило «Нечитаемая строка» договора сторожевой и передачи; 401/403 — только «проверено — нельзя»), а также выход `unavailable` функции `may` (N1.3b `roles_at_holder`).

Группа строки управляющего (N1.3c `manager`) в `may` считается только у дверей `gives`.

Дверь `denies` при праве, действующем только через группу строки управляющего, — 403 `{error: "admin only"}`, а не `denied`.

### N1.6 Аварийная учётка у держателя

Договор сторожевой и передачи «Аварийный вход» — сторона держателя.

Дверь
`POST /session/break-glass` по порядку, сверка хеша, сессия `GLASS_SESSION`, потолок `GLASS_SESSIONS_MAX` и журнал
`access.break_glass.*` — консоль кластера (поздний слой урока P/06; контракт — [OpenAPI урока
6](../../../06-console/spec/06-console.api.openapi.yaml) `POST /session/break-glass`).

Предел попыток двери `POST /session/break-glass` — свой счёт по N1.10.

```yaml
domain/break-glass/<cluster>: {pwhash_secret, set_at, revision}    # у держателя
  writer:      процесс domain по двери PUT /domain/break-glass/<cluster> {password}
GLASS_MIN:     forms/runtime-constants.tsv          # знаков
carry:         sealed ответа агенту — поле break_glass
```

`domain/break-glass/<cluster>` — у держателя; `pwhash_secret` — та же форма, что N1.1.

`writer`: процесс `domain` по двери `PUT /domain/break-glass/<cluster> {password}` (admin домена); пароль ≥ `GLASS_MIN`.

`writer`: `revision` — глава 8.0 N1.9 «Версии», у копии члена её нет.

`GLASS_MIN` считает знаки: кодовые точки Unicode.

`carry`: `sealed` ответа агенту — поле `break_glass` (форма — договор конвертов домена «Содержимое sealed»);
у члена — `domain/break-glass/<member>`
(секрет запечатан его кольцом).

`carry`: строки нет — поля нет, агент удаляет строку.

`carry`: строка не читается — не «нет»: в `sealed` идёт
`held` с именем `break_glass`, «не послано, копии не трогать»: аварийная учётка нужна как раз в аварии.

`carry`: конверт не открылся — агент его не трогает (урок 3 N1.6 sealed).

`carry`: у кластера держателя строка
`domain/break-glass/<holder>` — его собственная (пишет процесс `domain`): агент держателя её не пишет и не
удаляет, ответ себе поля `break_glass` и этого имени в `held` не несёт.

В строке `carry` сторона агента (запись и удаление строки у члена; «урок 3 N1.6 sealed» — P/09.1 N1.4 `sealed`) —
[глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.4 `break_glass` (P/09.1-29); сторона держателя — поле `break_glass` в `sealed` ответа (глава 8.3 N1.5) и
своя строка кластера держателя.

### N1.9 Двери людей и первый администратор

```yaml
pass:      the doors /domain/users…, /domain/groups…, /domain/roles…, /domain/batch, /domain/break-glass…, /domain/grants/…, /domain/revoke → the process domain
first:     команда держателя domain first-admin <name>
grant_admin: команда держателя domain grant-admin <name>
member:    имя domain — не имя члена
```

`pass`: двери `/domain/users…`, `/domain/groups…`, `/domain/roles…`, `/domain/batch` и `/domain/break-glass…` при любом методе, и GET, правки
`/domain/grants/…` и `/domain/revoke` консоль домена передаёт процессу `domain` по главе 8.0 N1.8.

`pass`: процесс проверяет
токен и `domain/grants/domain` сам.

`first`: команда держателя `domain first-admin <name>` (пароль — stdin, N1.1 `PASSWORD_MIN`): только пока `domain/users` пуст —
пишет одним пакетом P/01.1 (`op: batch`) человека с `pw_by = <name>`, `domain/roles/admin` с `{person: <name>, until: 0, at: now}` и пустой
`domain/grants/domain` (`{lines: []}`), если его нет.

`first`: прямой строки домена не пишет.

`first`: люди есть — отказ, код ≠ 0.

`first`: пакет записан целиком или не записан: повтор после обрыва (люди ещё пусты) доводит; строка человека есть (в том числе
нечитаемая) — люди не пусты, отказ.

`first`: пароль — stdin целиком как UTF-8 без одного конечного LF или CRLF (прочие пробелы и знаки — часть пароля); не
UTF-8 — отказ, код ≠ 0.

`first`: имя — по N1.1 (форма), проверок индексов имён (глава 8.5 N1.7 checks) у команды нет: она идёт при установке, до
первого прохода, индексов ещё нет и пустыми они не считаются.

`first`: позже ключ индекса, совпавший с именем человека, —
правило `reverse` главы 8.5 N1.7.

`grant_admin`: команда держателя `domain grant-admin <name>` (через `admin.sock` держателя, как first-admin): только при нуле доказанных
администраторов (N1.3 `last_admin`), иначе отказ, код ≠ 0.

`grant_admin`: человек есть (строка читается) и метки `domain/deleting/<name>` нет, иначе отказ, код ≠ 0.

`grant_admin`: одним пакетом назначает
роль admin бессрочно (`{person: <name>, until: 0, at: now}`; строки роли нет или она нечитаема — пишет её заново) и снимает с человека
`disabled`, `expires` и имя в `domain/disabled`.

`grant_admin`: журнал `domain.admin.granted {name}`.

`member`: имя `domain` — не имя члена: приём члена (глава 8.3 N3 «принять члена») — 400 «domain is the name of the domain's own grants».

Передачу (`pass`, сторона консоли домена) нормирует урок P/10 (N1.3a, P/10-05); здесь — что передаётся и что процесс проверяет
сам (N1.5).

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи. Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

**Группы и роли.** Право — по `domain/grants/domain`, как у дверей людей: чтение — `view`, запись — `admin`; строка `manager` (N1.3c) им служит.

`members` и

`assigned` телом — элементы без `at`.

**Пакетная дверь** `POST /domain/batch`: люди, группы, роли и гранты одного снимка — одна запись.

Суд по строке у пакетной двери: `kind: grants` с кластером ≠ `domain` — договор права `target`, `admin` на `*` этого кластера, как дверь грантов (N3 «гранты» шаг 1); прочие строки — `domain/grants/domain`.

Администратор кластера пишет пакетом только гранты своего кластера; отказ одной строки — 403 всего пакета.

До тела пакета консоль домена требует строку `domain`, в том числе группу управляющего (`gives`, N1.3c), или `admin` на `*` хоть в одном кластере.

Пакетная дверь — P/01.1 `op: batch` по CAS всех затронутых строк.

У пакетной двери `last_admin` судится по итоговому состоянию: нынешние строки с разницей пакета, а не по шагам.

```yaml
body:      {writes: [{kind: user | group | role | grants, op: put | delete, name, cas, fields?}]}
  name:    имя человека, группы, роли или кластера
  cas:     индекс хранилища
  fields:  поля тела
delete:    op: delete и каскад N3
order:     проверки над итоговым состоянием пакета
unchanged: строка, которую запись не меняет
limit:     строки, которые пакет пишет, ≤ BATCH_WRITES
repeat:    Idempotency-Key
holder:    страж domain/signer-turn
```

`body.name`: имя человека, группы, роли или кластера по грамматике своей семьи.

`body.cas`: индекс хранилища, который дал GET этой строки (index элемента списка; у grants — versions ответа `GET /domain/grants`, P/10 N1.2e); `""` — создание; обязателен.

`body.fields`: у put — поля тела соответствующей двери PUT или POST (без name), у grants — `{lines}`; у delete — нет.

`delete`: `op: delete` у user, group, role несёт каскад N3 тем же пакетом: снятие из `members` и `assigned`, строки грантов.

`delete`: у user строка метки `{at, done: true}` идёт тем же пакетом и держит имя на срок токена, у group и role метки нет.

`delete`: пакет атомарен; строки каскада считаются в `BATCH_WRITES`.

`order`: те же проверки, что у одиночных дверей, над итоговым состоянием пакета: форма → права и N1.3c `batch_diff` → ссылки и имена → `last_admin` →
`ROLES_TABLE_MAX`, `ADMIN_ASSIGNED_MAX`, `ADMIN_TABLE_MAX` → запись.

`order`: обрабатывает порядок записей, ссылки внутри пакета судятся по состоянию после него.

`unchanged`: строка, которую запись не меняет, в пакет не пишется, её cas идёт стражем; written — число изменённых строк.

`unchanged`: изменённых нет — записи нет,
cas сверяются чтением: разошёлся — 412 `conflict`, иначе 200 `{written: 0}`.

`limit`: строк, которые пакет пишет, с каскадом и строкой заявки ≤ `BATCH_WRITES` (P/01.1): с ключом изменённых остаётся 63.

`limit`: элементы `writes` без изменений в этот счёт не идут, их держит вес; неизменённые строки пакет нести не обязан: вызывающий шлёт снимок или разницу по прочитанному.

`limit`: всё тело ≤ `-max-body` хранилища; числа стражей предел не держит.

`limit`: сверх — 413 `{error: "batch too large"}`, ничего не записано.

`repeat`: `Idempotency-Key` необязателен (глава 8.0 N1.9): с ключом повтор отдаёт прежний итог.

`repeat`: без ключа у каждой записи свой cas, поэтому повтор после потери ответа —
412 `conflict` без записи; вызывающий перечитывает строки и сверяет: 412 здесь значит «снимок устарел», а не «ничего не изменилось».

`holder`: запись идёт под стражем `domain/signer-turn`; смена держателя — 503 `standby`, вызывающий перечитывает строки.

`holder`: при передаче дверь заморожена (P/08.8 N1.7).

`ETag`, `If-Match` и `Idempotency-Key` этих дверей записи — [глава 8.0](08.0-domain.norms.md) N1.9.

Индекс в перечнях — из чтения этой строки, не из перечисления ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N2 «Версии»).

Двери других владельцев: `GET /domain/grants` (консоль домена, view) — урок P/10 (N1.2e); `POST /session/break-glass` и
`GET /domain/keys` (консоль кластера) — [OpenAPI урока 6](../../../06-console/spec/06-console.api.openapi.yaml) (поздний слой
урока P/06).

Журнал: `domain.user.created`, `.password`, `.disabled`, `.deleted {grants_changed}` — процесс `domain`; `domain.group.created`, `.changed {added, removed}`,
`.deleted`.

Тревога `domain.rights_via_backend {by, via, what}` — журнал тревог процесса `domain` `audit.alarms/domain` на сервере держателя; администраторам домена доходит как всякая строка класса alarm: страница отчёта агента держателя (P/09.1 N1.10) и `GET /domain/alarms` (P/10 N1.8) (N1.3c `via_backend`).

Журнал: `domain.role.created`, `.assigned {added, removed}`, `.deleted {grants_changed}`; `domain.user.expiry_kept {name}`, `domain.no_admin`, `domain.admin.granted {name}`.

Журнал: `domain.grants.changed
{cluster, added, removed, by}` — процесс `domain`, `added` и `removed` — массивы объектов `{subject, cap, scope, until}` в
порядке строк N1.3.

Журнал: `domain.break_glass.set {cluster, by}` — процесс `domain`.

## N3 Проход

### дверь людей (процесс domain) — по порядку

Дверь людей процесса `domain` идёт по порядку:

1. Тело больше 1 МиБ → 413 `too large`.

2. Токен (`token` договора токена домена, `expect {kind: person, cluster: null}`) и `may` по `domain/grants/domain` → 401 / 403 `{error: denied}`.

На шаге 2 проверить нечем — 503 `unavailable` (N1.5).

2a. Заголовки и память повторов (глава 8.0 N1.9) → 400 / 409 / 422 / прежний ответ.

На шаге 2a тело не JSON-объект — 400 `bad body` здесь.

3. Тело не по форме двери → 400 `bad body`.

4. Имя не по N1.1 (POST) → 400 `bad name`.

5. Пароль короче `PASSWORD_MIN` (`GLASS_MIN` у break-glass) → 400 `bad password`.

5a. POST: стоит метка `domain/deleting/<name>` → 409 `exists` (метка — раньше проверок имён).

5b. Управляющий (N1.3c): PUT, DELETE — статус цели `target` → 403 `admin only` / 503 `unavailable`.

6. Проверки имён (глава 8.5 N1.7) → 409 `name taken` / 503 `names unknown`.

7. POST: человек есть или стоит метка `domain/deleting/<name>` — 409 `exists`; PUT, DELETE: нет — 404 `no such person`.

На шаге 7 строка человека есть, но не читается — PUT: 503 `unavailable`, не 404 (правке нужно прочитанное содержимое; неизвестное — не «нет»).

На шаге 7 DELETE удаляет и нечитаемую строку человека — способ убрать испорченную (сц. 13 приёмки 8.4; только для судьи: сц. 13 главы 8.4; он проверяет P/08.4-R395 и P/08.4-R073).

7a. POST: в `domain/grants/*` есть строка с `subject = <name>` (грант прежнего субъекта без имени, сверка его ещё не сняла) или имя стоит в
`members` группы либо `assigned` роли — 409 `exists`: имя свободно только после снятия.

На шаге 7a строка грантов, группы или роли не читается — 503 `unavailable`.

7b. PUT, DELETE человека, PUT break-glass: `If-Match` не равен версии строки (глава 8.0 N1.9; у break-glass строки нет — revision 0) → 412 `revision moved`.

8. `last_admin` (N1.3); `expires` ≠ 0 у последнего бессрочного — тоже → 409 `last admin`.

8a. `ROLES_TABLE_MAX` (N1.3b) → 409 `roles table too large`.

9. Записать строку (CAS по прочитанной версии, revision + 1, стражи N1.3 `last_admin` и N1.3c `target`); `disabled` или `expires` — затем `domain/disabled`.

На шаге 9 DELETE: записать метку
`domain/deleting/<name>` → удалить строку человека → снять строки `subject = <name>` во всех `domain/grants/*` (CAS) и имя из `members` всех групп и `assigned` всех ролей (CAS) →
записать метке `done: true`, её срок снимает сверка.

На шаге 9 DELETE: строка группы или роли не читается — 503, метка остаётся, доводит сверка.

На шаге 9 DELETE: ответ — после записи `done`.

На шаге 9 конфликт CAS строки
грантов — перечитать её и повторить не больше трёх раз (как шаг 6 «гранты»); исчерпано — 503 `{error: "unavailable",
detail: "the grants kept changing; the deletion is finished by the next pass"}`, метка остаётся, строки грантов
доводит сверка ниже.

С ключом целевая запись шага 9 (глава 8.0 N1.9 `write`) — строка человека или аварийной учётки; у `DELETE` — запись метке `done: true`: ответ называет `grants_changed`, и эта запись последняя.

С ключом `domain/disabled` идёт после пакета, как и без ключа: расхождение доводит сверка ниже.

Обрыв шага 9 доводится при старте и каждым проходом держателя.

Сверка шага 9: `domain/disabled` пересобирается по читаемым строкам людей.

Сверка шага 9: для каждой метки человека по прочитанным версиям снимаются соответствующие строки грантов и ссылки в members групп и assigned ролей.

Сверка шага 9: нечитаемый вход, неизвестное чтение/запись или незавершённый повтор CAS оставляют метку следующему проходу, без объявления завершения.

Строку человека сверка не удаляет.

При ещё читаемой строке человека (включая сценарий 09; только для судьи: сц. 09 главы 8.4; он проверяет P/08.4-R413) человек остаётся без снятых грантов: после очистки удаляется прямо записанная или прерванная метка; повторный `DELETE` доводит удаление человека.

Когда отсутствие человека подтверждено и очистка закончена, читаемый `at` удерживает метку до `at + TOKEN_LIFETIME + TOKEN_SKEW`, независимо от уже истинного `done` или записи завершения сейчас.

При равенстве с `at + TOKEN_LIFETIME + TOKEN_SKEW` удержание метки кончено.

Отсутствующий или нечитаемый `at` — метка без временного удержания, не синтезированное текущее время: после очистки действует прежнее удаление сценариев 09/10 (только для судьи: сц. 09, 10 главы 8.4; они проверяют P/08.4-R416 и P/08.4-R065).

Неизвестное или нечитаемое состояние человека не доказывает ни одну ветвь: метка сохраняется до повторной сверки.

Ключ вне грамматики человека/роли сохраняет прежнее удаление метки с журналом.

Проход не ждёт индексов имён для очистки метки удаления; отдельная сверка бесхозных субъектов по-прежнему ждёт свои полные входы.

Метка роли `domain/deleting/role:<name>` использует отдельную прежнюю ветвь восстановления (N3 «роли»): удалить оставшуюся строку роли, снять строки грантов с `subject = role:<name>`, затем удалить метку.

Исключение о сохранении строки человека выше не сохраняет строку роли.

Для метки роли действуют нынешние CAS по прочитанной версии и правила повторов.

Если необходимые входы очистки метки роли не читаются, наличие или версия не подтверждены, исход записи неизвестен либо очистка не завершена, метка роли остаётся для повтора; нового предусловия читаемости payload у прежнего удаления строки роли не возникает.

Пока стоит метка роли или соответствующая строка гранта, создание роли с этим именем по-прежнему даёт 409 `exists`.

У метки роли нет срока токена человека; items писателя этой метки — ровно `{}`: без `at` и `done`.

Субъект без имени. Тем же проходом, после индексов имён прохода (глава 8.5 N3
«сборка книги»), процесс `domain` снимает строки грантов во всех `domain/grants/*`, чей `subject` не человек домена (строки
`domain/users/<subject>` нет) и не ключ ни одного индекса имён, — только когда все индексы known (глава 8.5 N1.7; каталог без
книг с `domain.names` — все known и пусты) и перечень людей прочитан.

Для субъектов без имени: индексы этого прохода не построены (сбой части прохода, глава 8.1 «Гонки»; окно после взятого срока, глава 8.5 N1.3), индекс не known, перечень людей или строка индекса не
прочитаны (хранилище не ответило) — сверка этого прохода субъектов без имени не ищет.

Для субъектов без имени: строка человека есть, но
нечитаема, — человек есть: его гранты не снимаются.

Для субъектов без имени: строка грантов не читается — пропускается, причина в журнал.

Для субъектов без имени: снятие —
CAS строки грантов по прочитанной версии; конфликт — перечитать и повторить не больше трёх раз, остаток — следующим
проходом; журнал без значений.

Пока строка субъекта без имени стоит, имя для `POST /domain/users` занято (шаг 7a двери людей):
новый человек с этим именем грантов прежнего субъекта не получает.

Субъекты, которые нормы снимают сами (метка `domain/deleting/`), — по своим правилам.

Новые виды. Тем же проходом процесс снимает строки грантов `role:R`, если строки `domain/roles/R` нет; элементы `members` и
`assigned` с человеком, которого нет, и `assigned` с группой, которой нет.

Для новых видов правило прохода то же, что выше: перечни людей, групп и ролей
прочитаны целиком и успешно — иначе этот проход ничего не ищет.

Для новых видов: строка есть, но нечитаема, — «есть», ничего не снимается.

Для новых видов: CAS,
три повтора, остаток — следующим проходом; журнал без значений.

**Пока восстановление или перенос домена не завершены, сверка новых
видов ничего не снимает**: пустой перечень после неполного восстановления — не основание.

**Срок**. Каждым проходом процесс пишет в `domain/disabled` имена с истёкшим `expires`, кроме случая: после этого
не останется ни одного доказанного администратора (N1.3) или доказательство неизвестно (нечитаемые строки).

Срок, в исключённом случае: человек остаётся
включённым, журнал `domain.user.expiry_kept {name}` раз в проход.

Доказанный администратор бессрочен, поэтому в штатном состоянии
правило этого исключения не срабатывает: это защита от аномалии.

**Сверка роли `admin`**. Проход пишет `domain/roles/admin` только при подтверждённом отсутствии строки и непустых `domain/users` (до `first-admin` строку не пишет).

Сверка роли `admin` нечитаемую строку не
трогает, журнал раз в проход.

Создавая строку `domain/roles/admin`, проход один раз назначает роль (`until: 0`) каждому человеку с действующей бессрочной прямой строкой;
строку ему оставляет.

Нет доказанных администраторов — журнал `domain.no_admin` раз в проход.

### гранты (процесс domain, PUT /domain/grants/<кластер> через консоль домена) — по порядку

1. `may` по `domain/grants/domain`, admin, или кластер ≠ `domain` и `may` по `domain/grants/<cluster>`, admin, unit = `"*"` (договор права `target`) → 401 / 403.

На шаге 1 проверить нечем — 503 `unavailable` (N1.5).

1a. Заголовки и память повторов (глава 8.0 N1.9) → 400 / 409 / 422 / прежний ответ.

2. Кластер не по грамматике члена и не `domain` → 400 `bad name`.

3. `lines` не по форме N1.3 (cap, scope, until — число ≥ 0, subject по N1.1), повтор строки → 400 `bad line`.

Затем, на шаге 3, условие: `If-Match` не равен версии строки (глава 8.0 N1.9; строки нет — revision 0) → 412 `revision moved`.

3a. Новая строка с subject, у которого стоит метка `domain/deleting/` → 409 `being deleted` (метка — раньше проверок имён:
человек удаляется, индекс о нём не спрашивают); у subject `role:R` — метка `domain/deleting/role:R`.

3b. Кластер = `domain`: строка с `sub` или `folder:`, строка `role:` не формы manager (N1.3c), `none` → 400 `bad line`.

На шаге 3b: строка `role:admin` в любом документе, `none`
у строки не роли, `labels:` у строки роли → 400 `bad line`.

3c. Кластер = `domain` и запрашивающий — управляющий → 403 `admin only`.

4. Новая строка `role:R` — только наличие роли R: нет — 400 `unknown subject`; проверки индексов имён к ней не относятся,
503 `names unknown` она не получает.

На шаге 4 прочие строки — проверки имён (глава 8.5 N1.7): шире grant — 400 (`grant too wide` — только по рангу, none ниже всех).

На шаге 4, проверки имён: новая строка
не человека домена и индекс не known — 503.

На шаге 4, проверки имён: индекс known, а subject не человек и не key — 400 `unknown subject`.

5. Кластер = `domain` и `last_admin` → 409 `last admin`.

5a. `ROLES_TABLE_MAX` (N1.3b), кластер ≠ `domain` → 409 `roles table too large`.

6. Записать по CAS: `lines` по порядку N1.3, `by` — доказанное имя, `role_at[R]` = now у каждой роли, чьи строки кроме scope `unit:` изменились, revision + 1.

На шаге 6 конфликт — перечитать, сверить условие и повторить с шага 4 не больше трёх раз
(конфликт с DELETE возвращает к шагу 4, и он видит метку удаления).

### расхождение роли (процесс domain, проход держателя)

Расхождение роли сначала проверяет каждую роль с lines: нечитаемая роль или строка с `labels:` либо иной запрещённой областью — refused, журнал без значений, не рассылать; не создавать невалидный грант роли.

Расхождение роли идёт по каждой читаемой роли с допустимыми lines, по каждому члену списка, только изменённые: новый `lines_at`, новый член, смена строки члена.

При 250 000 членов расхождение роли идёт кругом вида, `role_spread` — по разделам.

Расхождение роли, для члена: строка `domain/grants/<member>` не читается → слово `refused`, строку не трогать.

Расхождение роли, для члена: `role_at[R] > lines_at` → слово `local`, строку не трогать: правка на кластере новее.

Расхождение роли, для члена: `role_at[R] = lines_at` → слово `ok`.

Расхождение роли, для члена, иначе: заменить строки `subject = role:R`, кроме scope `unit:`, на `lines`: `unit:` — права этого кластера, в `lines` их не бывает, `by = lines_by`, `role_at[R] = lines_at`, revision + 1.

Расхождение роли, для члена, иначе: `ROLES_TABLE_MAX` → слово `refused`, журнал `domain.roles.too_large {member}`, строку не трогать.

Расхождение роли, для члена: записать по CAS со стражем `domain/signer-turn`, конфликт — следующим проходом, слово `pending`.

Вид: `role_spread {<role>: {<member>: local | pending | refused}}` — только не ok; роль без расхождений — ключа нет.

### группы и роли (процесс domain, двери N2) — по порядку

1. `may` по `domain/grants/domain` (N3 «дверь людей» шаги 1–2) → 401 / 403.

На шаге 1 проверить нечем — 503 `unavailable`.

1a. Заголовки и память повторов (глава 8.0 N1.9 `order`) → 400; прежний ответ; 409 `in flight`; 422 `key reused`.

2. Тело не по форме → 400 `bad body`; имя → 400 `bad name`.

На шаге 2 `admin`: `title`, `comment`, `supervision`, `DELETE` → 409 `builtin`; POST с именем `admin` → 409 `exists`.

3. Управляющий: `PUT /domain/roles/admin`; состав группы с действующим назначением admin; `DELETE` такой группы; `DELETE` роли со строкой в
`domain/grants/domain` → 403 `admin only`.

На шаге 3 статус не установить — 503 `unavailable` (N1.3c `target`).

4. POST: строка есть или имя ещё стоит в `assigned` (группа), стоит метка или строка `role:<name>` (роль) → 409 `exists`.

На шаге 4 строка группы или роли
не читается → 503 `unavailable`.

На шаге 4 PUT, DELETE: нет — 404 `no such group` / `no such role`.

4a. PUT, DELETE: `If-Match` не равен версии строки (глава 8.0 N1.9) → 412 `revision moved`.

5. `members` и `assigned`: каждый человек и группа есть, иначе 400 `unknown member` (метка удаления человека — 409 `being deleted`).

На шаге 5 стражи ссылок на
версии их строк.

На шаге 5 `assigned` роли `admin` сверх `ADMIN_ASSIGNED_MAX` → 409 `too many admins`.

5a. `supervision` роли (N1.3a): форма → 400 `bad body`; у `admin` → 409 `builtin`.

На шаге 5a роль супервизоров, кроме самой этой, есть, иначе 400 `unknown role` —
страж её версии.

На шаге 5a DELETE роли: `supervision` другой роли называет её → 409 `role referenced` (чтение всех строк ролей; нечитаемая — 503 `unavailable`).

6. N1.3c `password`, только добавленные элементы: `pw_by` не он сам и не администратор домена → 409 `password set by a non-admin`.

7. `last_admin` (правка группы и роли `admin`) → 409 `last admin`.

На шаге 7 `ROLES_TABLE_MAX` → 409 `roles table too large` (правка роли с надзором, её ролей супервизоров
или их групп — по таблицам всех членов, N1.3b `limit`).

На шаге 7 `ADMIN_TABLE_MAX` (роль `admin`, группа с действующим назначением admin) → 409 `admin table too large`.

8. Записать одним пакетом (cas строки, revision + 1, стражи ссылок, стражи N1.3 и N1.3c, страж `domain/signer-turn`).

На шаге 8 тело тяжелее `-max-body` хранилища → 413 `too large`.

На шаге 8 конфликт — перечитать и с шага 4, условие снова, не больше `GUARD_RETRIES`;
исчерпано — 503 `unavailable`.

DELETE группы: строка удаляется, затем `{group: <name>}` снимается из `assigned` всех ролей (CAS, три повтора); обрыв доводит сверка
субъектов.

DELETE роли: метка `domain/deleting/role:<name>` → строка роли → строки `subject = role:<name>` во всех `domain/grants/*`
(CAS, три повтора) → метка.

Пока стоит метка или строка `role:<name>` — `POST` роли с этим именем 409 `exists`.

Сверка по метке `role:<name>`
удаляет строку роли, если она осталась, снимает её строки грантов и удаляет метку, как по метке человека; метку такой формы мусором не считает.

**Гонки.** Человек выключен, а его токен жив: у кластера держателя отказ сразу (`domain/disabled`), у члена — со следующим
ответом агенту.

Отзыв гранта у члена без связи — не позже `GRANT_LIFETIME` от `as_of` копии (N1.3); выданный токен — `TOKEN_LIFETIME + TOKEN_SKEW` от выдачи.

Снятие назначения, выход из группы, правка строк роли, выключение по сроку доходят до члена со следующим ответом агенту; у члена без связи —
не позже `GRANT_LIFETIME` от `as_of`: срок учётной записи у него действует до `GRANT_LIFETIME` позже `expires`.

Гранты пишет
один процесс `domain` — CAS строки.

Одно имя создаётся человеком и вкладом в двух кластерах одновременно — индекс показывает
обоих, доставка элемента не идёт (глава 8.5 N1.7 reverse), распределённой блокировки нет.
