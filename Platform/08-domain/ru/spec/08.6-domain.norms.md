## Н1 Форма

**Время.** Поля времени строк главы — время по [канону Н0 P/01.1](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке): `domain/placement/<sub>/<ref>` — `at`; правка в `domain/pending/<член>` — `at`; исход в `domain/outcomes/<член>` — `at`, `kept_at`.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/placement`, `domain/placement/<sub>/<ref>`, `domain/pending/<член>`, `domain/outcomes/<член>`;
- пишет: `domain/view` (cas);
- читает: `domain/member-rows/<раздел>`, `<sub>/<manifest:unit.rows>/<id>`.

Поля `pending` и `outcomes` объекта `domain/view` (владелец — [глава 8.1](08.1-domain.norms.md)) процесс пишет в
проходе вида (Н1.6). Копии назначений `domain/placed`, `domain/placed/<sub>/<ref>` и строку исходов члена
`domain/outcomes` пишет агент члена — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md)
Н1.5. Формы записи назначения и исхода общие у держателя и агента — определения `common.domain_placement` и
`common.domain_outcome` [общих определений семей](../../../common/data/common.schema.json) (решение «Архитектора» по планам
переноса 8–10, п. 3).

Общее [глав 8.2](08.2-domain.norms.md) и [8.3](08.3-domain.norms.md) Н1 действует. Назначение пишет только оператор:
размещение единиц доменом по достижимости — долг в `ХОД-Спецификация.md` (ответ на записку М11 п. 3). Домен не пишет
строк в члены: правку члена применяет агент члена ([глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) Н1.5) через дверь единиц своей
консоли ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md)).

### Н1.1 Назначение у держателя

```yaml
domain/placement/<sub>/<ref>:   строка хранилища держателя; элементы — строки (P/01.1):
  cluster:   член-исполнитель; обязателен
  origin:    член-владелец источника; "" — нет
  copies:    текст JCS массива других исполнителей, по возрастанию, без повторов, без cluster; "[]" — нет
  reason:    слова оператора; "" — нет
  at:        стенные секунды процесса domain записи, десятичным текстом
  rev:       значение счётчика domain/placement этой записи, десятичным текстом
domain/placement:   {rev} — счётчик, +1 на каждую запись и удаление назначения
writer:     процесс domain по двери Н2 консоли домена (глава 8.0 Н1.8); агенту запрещено (P/02.5 Н1.4а domainagent)
readers:    процесс domain (вид главы 8.1, теневой отчёт главы 8.1 Н1.6, ответ агенту — Н1.2); воркер на держателе — через
            чтение domain/placed/<sub>/ (P/02.5 Н3 шаг 3 даёт и domain/placement/<sub>/)
executors:  исполнители ref — множество {cluster} ∪ copies; поле origin ни добавляет члена в это множество, ни исключает из
            него (origin = cluster — исполнитель как cluster); член вне множества, давший тот же ref, — спор (глава 8.1 Н1.4
            executors); роль исполнителя (основной или резерв) — забота подсистемы (ADR-0091 доп. (12) п. 1, доп. (13) п. 2,
            доп. (15) п. 1)
ref:        не проверяется на существование: назначение может опередить единицу (теневой отчёт — orphaned через
            SHADOW_STALL); в пути — остаток после <sub>/ байт в байт, процент-формы не декодируются (`a%20b` — ref
            «a%20b»); не по грамматике имени P/06.1 Н1.3 named (в том числе с `/`: `/domain/placement/testsub/a/b`) — 400
            (добавлено сверкой М11, A7)
form:       cluster — непустая строка: "" — 400, не 409 (добавлено сверкой М11, A6)
class:      cluster — только class server (Entry; нет поля — server): камера-кластер основным исполнителем не бывает; copies и origin не судятся: камера с картой — законная копия, источник может быть камерой
```

### Н1.2 Ответ держателя: назначения члена

```yaml
carry.placement:  {rev, records: {"<sub>/<ref>": {cluster, origin, copies: [<член>…], reason, at, rev}}}   # глава 8.3 Н1.5
  records:   только назначения, которые называют этого члена: он — cluster, origin или в copies (минимум знания;
             цена ответа при сотнях членов — глава 8.10 Н1.9)
  rev:       счётчик domain/placement держателя
  absent:    поле нет, пока счётчика нет (rev 0)
```

Ответ строится под тем же мьютексом, что запись назначения, и после подъёма счётчика при старте и при новом взятии
очереди (Н3 «записать назначение»; C08-PLACEMENT-BUMP-TURN-01). Копия у члена (`domain/placed/<sub>/<ref>`, `domain/placed`) — что агент пишет по этому полю, без отката, и
её читатели — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) Н1.5 `member`,
`readers`; держатель копий не пишет: его читатели берут запись (Н1.1 readers).

### Н1.3 Правка единицы члена доменом

```yaml
doors:      POST /domain/<sub>/<rows> {cluster, <поля>}        — создать единицу на члене cluster
            PUT /domain/<sub>/<rows>/<ref>[?cluster=<член>]   — править поля
            DELETE /domain/<sub>/<rows>/<ref>[?cluster=<член>] — удалить; тело — пустое или {}, иное — 400 (добавлено
            сверкой М11, A1)
            POST /domain/<sub>/<таблица> {cluster, <поля>}      — записать строку таблицы domain.edit_tables на члене cluster
            DELETE /domain/<sub>/<таблица>/<имя>?cluster=<член> — снять строку; PUT таблицы нет, как у двери члена (P/06.1 Н1.6)
            POST /domain/edits {cluster, writes}                — связка правок: Н1.3б
            Idempotency-Key обязателен у всех шести (иначе 400) и по пределу двери владельца P/06.1 (200 байт UTF-8, один
            сегмент — иначе 400): ключ уходит агенту и его консоли как есть (P/09.1 Н1.5 apply) (C08-KEPT-EDIT-BOUNDS-01); право у двери домена — договор права common/contracts/may.md
            «Суд по цели» `write`, по кластеру цели: <cluster> тела или член из find (ADR-0110)
            <sub> не из каталога (манифеста нет или он без domain.ref, глава 8.1 Н1.2 no_ref) — 404, до разбора тела, у всех
            трёх дверей единицы (добавлено сверкой М11, A5); у таблицы domain.ref не нужен: манифест каталога с этим ключом domain.edit_tables; <rows> не unit.rows манифеста и не ключ domain.edit_tables — 404 {error: "refused", detail: "<sub> <rows> is not a family of
            the domain"}, до разбора тела; порядок: Idempotency-Key → <sub> → <rows> → тело (C08-EDIT-DOOR-ORDER-01)
            POST: cluster нет, не строка или пустая строка — 400 (добавлено сверкой М11, A4); у POST поиска нет: из refusals ниже действует
            только «cluster не член», новая единица ищет не ref, а место (C08-POST-NO-FIND-01)
fields:     только поля domain.edit манифеста (P/02.1 Н1.2а), у таблицы — domain.edit_tables.<таблица>, секреты — Н1.3а; у единицы платформенные (cluster, worker, server, placement, epoch,
            observed_revision, phase, revision), у таблицы только table_platform_fields (P/06.1 Н4: by, at, made_at, held_by, garbled, revision, index), её поле server — поле автора, и поля вне списка — 400; пустое тело PUT — 400; значения — по
            манифесту (P/06.1 Н3 «создать» шаг 4 формы) — 400; POST дополнительно принимает обязательное поле domain.ref манифеста, даже
            если его нет в domain.edit (у testsub edit — [start, labels], ref — name); у PUT исключения нет: ref — в пути
            (добавлено сверкой М11)
            граница «значений» (C08-KEPT-EDIT-BOUNDS-01): договор проверки строки R1 — проверки значений P2 над переданными полями, без
            заполнения умолчаний, у POST и PUT; у POST ещё P3 над полем domain.ref (раздел «Идентификатор»); P4 (required),
            P5 и R2–R3 (fixed, ref, must_match, unique по строкам) домен не проверяет — строк члена у него нет: их
            проверяет консоль члена при применении, отказ — исход refused (P/09.1 Н1.5)
secrets:    *_secret на любой глубине, кроме полей domain.edit_secrets (Н1.3а), адрес с учётными данными — 400 «a secret is set in the member's own cluster, never
            through a kept edit» (P/06.2 Н1.4, P/02.1 Н4: domain.edit с секретом — отказ загрузки манифеста; секрет идёт только полем domain.edit_secrets, Н1.3а)
            тело — {error: «a secret is set in the member's own cluster, never through a kept edit»}: текст — в error, не
            refused с detail (как строки P/06.2 Н4 «Тело»; приёмка 8.6 сц. 02 шаг 8) (C08-SECRET-REFUSAL-FORM-01)
order:      проверки тела по порядку: платформенные поля → секреты → поля вне domain.edit → пустое тело PUT → значения
find:       ref судится свежей строкой domain/ref-claims (глава 8.1 Н1.4б), id — её члена по строке вида; у таблицы поиска нет: член — ?cluster= или cluster тела, обязателен, нет — 400; ref → член и id по виду домена (глава 8.1 Н1.4); ?cluster= — только этот член; ref в units у двух исполнителей и
            больше (глава 8.1 Н1.4 executors) и запрос без ?cluster= — ранний повтор, затем 409 executors (Н3 «принять
            правку» шаг 2a); с ?cluster=<исполнитель> — правка у этого члена (ADR-0091 доп. (13) п. 3, доп. (17) п. 1);
            ref у нескольких единиц одного члена (глава 8.1 Н1.2 siblings): нужен ?id=<id единицы>, нет — 409 {error: "siblings", detail, ids: [<id>…]} по возрастанию байтов, без правки;
            с ?id= — эта единица, id вне этого ref — 404 refused; связка (Н1.3б) — поле id строки writes, то же правило; id читатель берёт из Unit вида
refusals:   ровно глава 8.1 Н4 (М11/1 Н4):
  - ?cluster= не член списка                         → 404 {error: "no such member"}
  - ref в contested                                  → 503 {error: "refused", detail: называет членов}; так и при
    ?cluster= одного из спорящих — вид не держит единиц спорного ref; член вне спора — поиск только у него
  - ref не найден, кто-то не ok (unseen, silent, never) → 503 {error: "refused", detail: называет молчащих}
  - ref не найден, ответ полный                       → 404 {error: "refused", detail: "<sub> <ref> is in no member of the domain"}
  - POST: cluster не член                             → 404 {error: "no such member"}
  - PUT, DELETE без ?cluster=: ref у двух исполнителей и больше, раннего повтора нет → 409 {error: "executors", detail,
    clusters: [<кластер>…]} по возрастанию байтов, без правки (ADR-0091 доп. (13) п. 3, доп. (15) п. 4)
kept:       найденная единица (в том числе у члена silent — по его последней копии) и POST → правка хранится (Н1.4) и ответ
            202 {kept, cluster, what, note}; домен в члены не пишет
view:       ref ищется свежим чтением domain/ref-claims/<sub>/<sha16 ref> (P/08.1 Н1.4б), единица — строкой вида раздела заявившего члена: строки заявки нет при complete головы — ref нигде; головы или строки вида нет (круг их ещё не собрал), complete ложь — ответ неполон: 503 {error:
            "refused", detail: "the domain view is not built yet: ask again in a few seconds"}, не 404; не читается — 503
            {error: "unavailable"}, ничего не записано (P1; исходы domain/view) (C08-KEPT-EDIT-BOUNDS-01)
```

### Н1.3а Секрет в правке (ADR-0111 п. 16)

```yaml
declare:    domain.edit_secrets: {<rows или таблица>: [<поле *_secret>…]} (P/02.1, связи 148, 149); только верхний уровень тела: вложенный *_secret — прежний 400
seal:       процесс domain при приёме заменяет значение конвертом m1 к ключу члена цели (договор конвертов домена «Конверт m1», ключ — Entry.key
            domain/member-rows/<раздел>): plain — JSON {edit: <id правки>, field: <поле>, value: <секрет>}, поле в теле правки — текст конверта;
            открытого значения нет ни в domain/pending, ни в asked, ни в журнале, ни в view.pending
open:       агент перед применением открывает ключом члена и сверяет edit и field; не открылось или не сошлось — исход refused, error — слово
            отказа конверта, дверь не зовётся (P/09.1 Н1.5)
repeat:     поля domain.edit_secrets в сравнении Н1.4 repeat не участвуют: конверты одного значения различны. Предел: иной секрет под тем же ключом — 202 с прежней правкой,
            новое значение не применится; новый секрет — новый ключ
stranded:   обычная дверь запечатывает любое значение, с приставкой m1: тоже. Конверт как есть принимает только POST /domain/edits/stranded (глава 8.8 Н1.6 apply), дверь admin домена:
            тело {asked, by?, iat?}, Idempotency-Key — key; значение не конверт — 400. Шаг суда — wide, человек правки сохраняется: by, iat — из тела
path:       открытое значение проходит консоль входа и консоль держателя и живёт в памяти процесса domain до шага 4a Н3: предел, в строки и журнал оно не попадает
```

### Н1.3б Связка правок (ADR-0111 п. 16)

```yaml
door:       POST /domain/edits {cluster, writes: [{op: put | delete, sub, rows, ref?, id?, name?, create?, new?, fields?}…]}, Idempotency-Key обязателен
            1 … BATCH_WRITES (P/01.1 Н1), у связки с new — на одну меньше; правка одного устройства — один элемент domain/pending/<член>, применяется всё или ничего
  rows:     unit.rows или ключ domain.edit_tables манифеста sub; у единицы поля — domain.edit
  ref:      единица, id? — выбор среди единиц одного ref: Н1.3 find только у cluster; не найден — 404 refused, как Н1.3
  name:     строка таблицы; у delete обязателен, у put — либо он, либо вычислен по tables.<t>.key из fields
  id:       адрес единицы: с ref — выбор среди единиц одного ref (Н1.3 find); без ref — строка (cluster, id) прямо, поиска по виду нет: так правят единицы без ref и манифесты вне каталога вида; при create — имя новой;
            base — revision строки шарда копии по id, иначе строки снимка таблиц, если rows в domain.view_tables; иначе base нет: предел, такая правка затирает локальную.
            contested этот адрес не касается: спор — об имени ref, а (cluster, id) однозначен, домен цель не угадывает
  put:      правило только единицы: без create и new единица правится только по живой строке: агент видит, что строки нет или она надгробие, — исход refused, дверь не зовётся; без ref, id, create, new у единицы — 400 bad batch.
            Строка таблицы — put по name или tables.<t>.key, строки нет — создаётся, как POST таблицы (P/06.1 Н1.6): cas ""
  согласие: unit.rows манифеста с domain.ref или с непустым domain.edit, иначе 404; op: delete единицы манифеста без domain.ref — только при domain.edit_delete: true, иначе 404: автор решает, что домен снимает
  create:   true — создание единицы с unit.id: name: поиска нет, id обязателен; в пакете revision 0: живая строка — 412 revision moved, исход conflict; надгробие — создание
  new:      true — создание единицы с unit.id: numeric; не больше одной на связку, номер выдаёт агент, ниже; подстрока $id в id, name и строковых значениях fields всех строк связки — этот номер
            (<id>-<том> записи — "$id-disk-a"); $id без new — 400 bad batch
  fields:   у put обязателен, {} — можно: строка-якорь (P/06.1 Н2) без правки; проверки — Н1.3 fields, secrets, order, номер строки в detail; секреты — Н1.3а, field — "<номер>/<поле>"
  отказы:   ключ дважды — 400 bad batch; часть с about без строки единицы-якоря в writes — 400 no anchor: то, что всё равно откажет у члена, отказывается сразу
  суд:      каждая строка — договор права write своей sub; отказ одной — 403 всей связки
edit:       method POST, path /console/batch, what — ключи строк по возрастанию через «,»; body {writes: [{op, key, fields?, base?}], new?: {sub, rows}}: key — <sub>/<rows>/<id> или <sub>/<таблица>/<имя>; base — Н1.4 base по строке
apply:      агент (P/09.1 Н1.5) читает строки writes из своего хранилища (право чтения, надгробие — его индекс, чтение не удалось — без исхода, повтор); cas — прочитанный индекс, строки нет — "";
            revision строки пакета — base, у create и new — 0; агент сам конфликт не судит и всегда зовёт дверь: заявка стоит раньше сверки (P/06.1 Н3 «пакет» шаги 4, 5), поэтому повтор после потери ответа
            получает прежний ответ, а не ложный конфликт; 412 revision moved — исход conflict; 412 row moved — повтор следующим проходом, cas устарел; иной 4xx — refused
new_id:     предел: счётчик сдвинули между вызовами — 400 bad_id, исход refused. При new агент до первого вызова читает <sub>/next_id, берёт n + 1 и пишет его в строку domain/edit-ids элементом <id правки> (cas): повтор берёт тот же номер, отпечаток прежний;
            в пакет идёт строка <sub>/next_id {n: номер}; элемент снимается вместе с исходом (OUTCOME_HOLD)
size:       правка лежит дважды, body и asked; связка в 64 строки — около 50 КиБ, в строку входит 10 таких: честный отказ row_full
```

### Н1.4 Хранимая правка

```yaml
domain/pending/<член>:   строка держателя; элемент <id> — текст JSON правки
  edit:     {id, seq, what, method, path, body, key, at, base?, by?, iat?, asked}
    id:     "e-" + первые 12 знаков hex sha256(UTF-8(член) ‖ 0x00 ‖ UTF-8(Idempotency-Key))
    seq:    номер приёма — значение элемента seq этой строки после +1 при приёме, под тем же CAS; seq задаёт порядок ждущих
            правок члена: по нему назначается base (ниже) и выдаются правки (carry); at — только время для людей и исходов
            (решение «Архитектора» по R41-09 прогона 41)
    what:   имена полей тела по возрастанию через «,», у POST — с полем domain.ref, без cluster (DELETE — ""); у связки — Н1.3б edit
    keys:   строки, которые правка задевает: <sub>/<rows>/<id>, <sub>/<таблица>/<имя> (имя строки POST таблицы — по tables.<t>.key), у связки — все key её writes; поля нет, это вывод из path и body.
            Правила ниже (base, ждущая DELETE, same_path агента) идут по keys, а не по path: две двери одной строки таблицы и связка видят друг друга
    method: POST | PUT | DELETE;  path — путь двери консоли члена: /<sub>/<rows>, /<sub>/<rows>/<id>, /<sub>/<таблица>, /<sub>/<таблица>/<имя>
            или /console/batch (Н1.3б) (id — местный id единицы из копии члена); body — объект полей (DELETE — {})
    by, iat: человек и iat его токена, если дверь пропустила его строкой кластера цели, а не domain/grants/domain (договор права `write`):
            консоль члена судит его по своим грантам при применении (P/09.1 Н1.5 apply). Зрителю домена полей нет: суд домена окончателен
    key:    Idempotency-Key запроса
    asked:  {method, path, body} — запрос двери домена, как его принял процесс: путь Н2 с ref и ?cluster=<член> у PUT и
            DELETE, тело с cluster у POST; по нему правку повторяют у нового держателя (глава 8.8 Н1.6 apply);
            path нормализован: у PUT и DELETE — /domain/<sub>/<rows>/<ref>?cluster=<член найденный>, даже если запрос
            ?cluster= не нёс, при ?id= — ещё &id=<id>; у POST — /domain/<sub>/<rows> без query; прочий query запроса в path не входит
            (добавлено сверкой М11, A3)
    at:     (строка domain/outcomes/<член> целиком нечитаема — любой приём у этого члена 503 unavailable: id мог быть
            исполнен, нечитаемая строка отсутствия не подтверждает; исходы domain/outcomes; C08-KEPT-EDIT-BOUNDS-01)
            стенные секунды процесса domain; если по этому id уже записан исход (строка domain/outcomes/<член> держателя,
            Н1.6) — не меньше следующего за его kept_at
            числа (nextafter): новый приём того же ключа отличим от прежнего; исход, вытесненный из последних 50, границы не даёт:
            приём идёт со стенными секундами, совпасть с прежним kept_at он может только при откате часов, это предел (C08-KEPT-AT-EVICTED-01);
            в форме писателя (дробь не длиннее трёх знаков) это не меньше kept_at, округлённого до тысячных, + 0.001:
            следующее за kept_at число округлилось бы обратно в kept_at и совпало с ним (C09-KEPT-AT-PRECISION-01)
            граница считается точно в десятичной записи; если binary64 значения round(kept_at) + 0.001 не больше binary64
            round(kept_at) (шаг binary64 там крупнее 0.001), at — не меньше наименьшего значения формы писателя (дробь не
            длиннее трёх знаков), чьё binary64 больше binary64 round(kept_at): у 4503599627370496 — 4503599627370497;
            такого конечного нет (kept_at — наибольшее конечное binary64) — приём 503 {error: "unavailable"}, ничего не
            записано. Без исхода по id граница не действует: at — стенные секунды в форме писателя, перевод часов в три
            знака (отсечение или округление) — реализации (C08-KEPT-AT-BOUND-01)
    base?:  revision единицы в копии члена у держателя в момент приёма (PUT, DELETE), у строки таблицы — из объекта domain/members/<член>/tables, если таблица в domain.view_tables; у POST единицы нет; строки шарда с
            revision этой единицы в копии нет — base нет, правка идёт без If-Match; есть ждущая запись той же строки по keys
            (PUT, POST таблицы, put связки) — base = base последней из них по seq + 1 (так применяется её результат, а не прежнее значение), у
            последней base нет — base нет и у новой; ждущее снятие той же строки (DELETE, delete связки) —
            новая правка этой строки отказывается 409 {error: "unit is being deleted"}
            # ждущая правка не применилась (conflict) — следующие того же path тоже дадут conflict: оператор решает заново
writer:     процесс domain — приём (Н3, дверь консоли домена — глава 8.0 Н1.8) и снятие исполненной (Н3 «исход»); CAS строки
repeat:     тот же id и тот же asked (метод, путь, тело, без полей Н1.3а) — 202 с прежней записью, at прежний; иное — 422 {error: "this Idempotency-Key
            was used for another edit"}; нечитаемая прежняя запись этого id — 422 (ключ не переиспользуется)
cancel:     отмены нет: принятая правка применяется или получает исход; откат — новая правка (ADR-0111 п. 16)
KEPT_LIMIT: forms/runtime-constants.tsv          # ждущих правок на члена; 51-я — 409 {error: "kept_full", detail: "<член> has 50 edits waiting"}
row_full:   строка domain/pending/<член> с этой правкой не влезает в потолок строки 524288 байт (P/01.1 Н1): строка из seq и одной этой правки в форме записи больше потолка — 413 {error: "too large"};
            иначе 409 {error: "kept_full", detail: "<член>'s waiting edits fill the row"}: ждать, пока член применит (C08-PENDING-ROW-01)
reply:      202 {kept: <id>, cluster: <член>, what, note: "kept; <член> applies it when it next reports"}
carry:      ответ держателя (глава 8.3 Н1.5) несёт pending: [<edit>…] этого члена по seq; элемент seq строки — счётчик, не правка
           (правки — элементы e-…; KEPT_LIMIT считает их)
           pending есть всегда, когда строка domain/pending/<член> прочитана; строки нет или правок в ней нет — pending: [];
           поля нет только при нечитаемой строке (исходы domain/pending): «неизвестно», не «пусто» (C09-PENDING-ABSENT-01)
```

### Н1.6 Исходы у держателя и вид

```yaml
domain/view.outcomes:  {<член>: [<исход>…]} — строка domain/outcomes/<член> по (at, id) убывая
```

## Н3 Проход

### записать назначение (процесс domain, PUT и DELETE `/domain/placement/<sub>/<ref>`)

```
0. заголовки и память повторов (глава 8.0 Н1.9)                                   → 400 / 409 / 422 / прежний ответ
1. форма, манифест, имена — по порядку Н2                                          → 400 / 404 / 409
1a. If-Match не равен версии строки: у PUT строки нет — 412 с revision 0, у DELETE — 404 Н2  → 412 revision moved
2. PUT: то же содержимое, что в строке                                          → 200 без новой rev
3. r = domain/placement.rev + 1; PUT — записать строку domain/placement/<sub>/<ref> с rev = r и at; DELETE — удалить
   строку (её нет — 404)
4. domain/placement := {rev: r} по CAS (конфликт — перечитать и повторить шаги 3–4, до 8 попыток, затем 503)
5. 200
```

С ключом шаги 3–4 — одна целевая запись: строка, счётчик и строка заявки ложатся одним пакетом (глава 8.0 Н1.9 `write`), конфликт счётчика — те же 8 попыток с шага 1a. Поэтому повтор не находит своей записи с прежним счётчиком и не получает ложный 412.
Шаг 2 ничего не пишет, поэтому строка заявки несёт `index` прочитанной записи.

Ответ агенту (Н1.2) строится тем же процессом под тем же мьютексом, что запись: промежуточного состояния ответ не видит.
Обрыв между шагами 3 и 4 — строка новая, счётчик прежний: процесс `domain` при старте и при каждом новом взятии очереди
`domain/signer-turn` (ждущий стал активным, [глава 8.10](08.10-domain.norms.md) Н1.7) — до первого ответа агенту в этом
владении — поднимает счётчик: оборваться мог и другой процесс, владевший очередью (C08-PLACEMENT-BUMP-TURN-01). То же при взятии срока переносом или передачей. Подъём: на сроке 1 — `rev + 1`; иначе max(rev + 1, целые стенные секунды + 60), строки нет — rev 0: счётчик пришёл из копии или его нет, члены держат `domain/placed.rev` прежнего держателя, а агент назад не идёт (C08-PLACEMENT-AFTER-MOVE-01).

Предел срока 1: откат хранилища держателя на этом сроке (`restore`, `import`, `recover`, P/01.3) не лечится: счётчик уходит вместе с прочим состоянием, `rev + 1` остаётся ниже `placed.rev` членов. Выход — передача: срок 2 поднимет счётчик по max. Цена закрытия хода — связанные значения вместо точных `rev` во всей приёмке срока 1; она больше редкости хода.

Предел прочих сроков: подъём старше прежних значений, пока прежний счётчик меньше целых стенных секунд нового держателя + 60. У счётчика нет инварианта набора «`rev` не обгоняет стенные часы», поэтому запас от первого такого подъёма — 0 с: счётчик идёт на 60 выше стенных часов. Прошедшая секунда прибавляет к запасу единицу; каждая запись и каждый подъём ветвью `rev + 1` отнимают единицу; отставание часов нового держателя отнимает столько же. Равенство запаса нулю — уже отказ: агенту нужно строго больше. Запас исчерпан — член не получает правок, пока счётчик не обгонит его `placed.rev`.

После подъёма члены перечитывают записи и сходятся (копии пишутся только при отличии —
[глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) Н1.5).

Подъём этого владения не подтверждён — CAS счётчика не прошёл за 8 попыток, запись отвергнута или ответа нет
(неизвестный исход): ответ агенту — без `rev`, как при нечитаемом счётчике (исходы `domain/placement`): поле
`carry.placement` опускается целиком, как Н1.2 `absent` (форма `CarryPlacement` требует `rev` и `records`); прежний `rev` не
выдаётся, дверь агента не отвечает 503 — прочие поля carry идут. Перед каждым следующим ответом агенту в этом владении
подъём повторяется. Неизвестный исход — как барьер [договора очереди писателя](../../../common/ru/contracts/turn.md) «Барьер»
(глава 8.10 Н1.7): успехом не считается, процесс перечитывает очередь и счётчик и поднимает его по прочитанной версии.
Подтверждённый CAS счётчика этим владением в записи назначения (шаг 4) — тоже подъём (C08-PLACEMENT-BUMP-FAIL-01).

Повтор шагов 3–4 после конфликта CAS: строка, которую этот проход уже записал или удалил, — его; DELETE не отвечает 404
из-за своего удаления (404 — только строки нет до первого шага 3), повторяется CAS счётчика по перечитанному `rev`; PUT
переписывает строку с новым r. Восемь конфликтов — 503, правка остаётся, а счётчик — в долгу подъёма этого владения, как
неподтверждённый подъём выше: ответ агенту без `rev`, пока подъём не подтверждён (C08-PLACEMENT-EDIT-RETRY-01).

### принять правку (процесс domain, дверь консоли домена — глава 8.0 Н1.8)

```
1. Idempotency-Key есть                                                         → 400
1a. <sub> из каталога, <rows> — unit.rows его манифеста или ключ domain.edit_tables   → 404
1b. поля, секреты, значения — Н1.3                                               → 400
2. PUT, DELETE: найти (Н1.3 find, refusals); POST: cluster — член                  → 404 / 503
2a. PUT, DELETE без ?cluster=, ref в units у двух исполнителей и больше (ранний повтор, ADR-0091 доп. (15) п. 4, доп. (17)
   п. 1): для каждого исполнителя — id по Н1.4 (id зависит от члена) и строка domain/pending/<член>; запись этого id
   есть ровно у одного — repeat (202 / 422) у него; у двух и больше — 409 executors (нужен ?cluster=); ни у кого —
   409 executors                                                                 → 202 / 422 / 409
   с ?cluster= — шаги ниже у названного члена, как прежде
3. id = Н1.4; прочитать domain/pending/<член>: тот же id — repeat (202 / 422)
3a. секреты Н1.3а → конверты m1; ключа члена нет — 503 {error: "unavailable"}, ничего не записано: дальше меряется уже строка с конвертами
4. ждущих 50                                                                    → 409 kept_full
   строка с этой правкой больше потолка (Н1.4 row_full)                            → 413 too large / 409 kept_full
   ждёт DELETE того же path                                                       → 409 unit is being deleted
   base: копия члена; ждёт PUT того же path — base последней по seq + 1
5. seq строки + 1; edit {id, seq, what, method, path, body, key, at, base?, by?, iat?, asked} → записать правку и seq одним CAS (конфликт — перечитать с шага 3, до 10 раз,
   затем 409 «the pending edits kept changing; ask again»)
6. 202
```

### исход (процесс domain, в проходе главы 8.1)

```
для каждого члена: исходы его копии (глава 8.3 Н3 «прочитать копию», поле outcomes публикации) → settle Н1.6:
записать domain/outcomes/<член> (обрезать до 50), затем снять правку из domain/pending/<член> по CAS
```

**Гонки.** Приём и снятие — в одном процессе `domain`, CAS строки `domain/pending/<член>`; снятие одного id — только
неизменённой правки. Локальная правка единицы на члене между приёмом и применением — `If-Match` даёт 412, исход `conflict`: молча не
перезаписывается. Агент, получивший правку дважды (повтор ответа), — `Idempotency-Key` двери единиц ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md)) и правило
`kept_at`. Назначение и единица — разные строки: удаление назначения единицу не трогает. Обрыв агента между применением
и записью исхода в `domain/outcomes`: правка ещё ждёт и применяется снова — `POST`, `PUT` и `DELETE` дают прежний ответ по `Idempotency-Key`
([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) Н3 «память повторов»; ADR-0094 B3). Новая правка берёт новый ключ (at — Н1.4; ADR-0094 доп. (14)): дверь члена помнит ключ 86400 с, прежний ключ там даёт прежний ответ, а с иным телом — 422 `key reused` и исход `refused`. Base новой правки берётся
из копии члена, а шард снимка может отставать от значения, уже применённого прежней правкой, поэтому возможен 412 и исход
`conflict` — допустимо, оператор решает заново (совпало у реализаций, записано сверкой М11). Применение агентом —
[глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) Н1.5.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/08.6-MM` — то, на что ссылаются дельты решений,
находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/08.6-01** назначение пишет только оператор дверью Н2; запись, счётчик, отказы, то же содержимое без новой `rev` — сц. 01; нечитаемая запись — `PUT` поверх, `DELETE` удаляет, нечитаемый счётчик — 503 — сц. 14 (аудит покрытия P/08, второй проход Gemini); ответ агенту несёт только записи, которые называют члена (фильтр `records`, Н1.2) — сц. 01 шаг 13 (у непричастного `m2` копии `c2` нет); ответ строится под мьютексом записи и счётчик поднимается на 1 при старте до первого ответа агенту (Н3 «записать назначение») — чтением: стенд не обрывает процесс между шагами 3 и 4 (часть М11/6-02 по `note` id-map, разбор ревью стадии A 8–10, № 20; копия у члена — P/09.1-07)
- [ ] **P/08.6-02** отказы правки — глава 8.1 Н4 — сц. 02; формы тела и пути, `ref` назначения байт в байт — сц. 09 (сверка М11); исполнители назначения `{cluster} ∪ copies`, 409 `executors` и ранний повтор (Н3 шаг 2a) — сц. 10; повтор у двух исполнителей сразу (409 `executors` после раннего повтора) — чтением: стенд не держит одну правку двумя ключами у двух членов (ADR-0091 доп. (12)–(19))
- [ ] **P/08.6-03** хранимая правка: id, `what`, повтор, 422, предел 50, 202 — сц. 03, 05; `asked.path` нормализован — сц. 09; хранимый `POST` (`what` с `domain.ref`, `asked.path` без query) — сц. 12; ждёт `DELETE` — 409 `unit is being deleted` — сц. 13; нечитаемый элемент — 422 своему ключу, приём прочих, нечитаемый `seq` — 503 — сц. 15 (аудит покрытия P/08, второй проход Gemini)
