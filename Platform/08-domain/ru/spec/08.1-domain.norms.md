## N0 Словарь слов

Нормативные слова — по [канону курса](../../../common/ru/NORMATIVE-TERMS.md). Правила модуля — [P/01.1 N0](../../../01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов)
(в том числе [порядок массивов вывода](../../../01-store/ru/spec/01.1-store.norms.md#порядок-массивов-вывода), область — уроки

Здесь действуют [общие эксплуатационные обязанности](../../../common/ru/contracts/production-obligations.md) и выбранные правила MB3 общих договоров (ADR-0130 Addendum (10)). Перед silent метка перечитывается ровно один раз: изменённая метка без точного нового поколения временно не подтверждена; производный снимок откладывается, требующая подтверждения дверь даёт существующий 503 unavailable, нового состояния члена нет.

## N1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону N0](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке): объект `domain/view` — `as_of`.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/view`, `domain/view-rows/<part>`, `domain/ref-claims/<sub>/<sha16>`, `domain/shadow`, `domain/members/<member>/tables/<sub>/<table>`;
- читает: `domain/members/<member>/reported`, `domain/members/<member>/reports/<rev>`, `domain/placement/<sub>/<ref>`, `domain/member-rows/<part>`, `domain/topology`, `domain/keys`.

Вид и теневой отчёт пишет только процесс `domain` проходом держателя (N3); объекты — по правилу очереди
[главы 8.10](08.10-domain.norms.md) N1.7 `objects`. Поля вида других глав (`books`, `pending`, `outcomes`, `term`,
`shared`) процесс пишет тем же проходом, их форма и смысл — в главах-владельцах (шапка главы). `domain/keys` проход
читает для поля `trust` (N1.2a; владелец строки — [глава 8.2](08.2-domain.norms.md)), `domain/topology` — для поля
`topology` (N1.6a; владелец — глава 8.3), `domain/member-rows/<part>` — список членов (владелец — глава
8.3), копии членов — по метке `reported` и поколению ([P/08.3 N1.3](08.3-domain.norms.md) и N3 «прочитать копию»), назначения — для
теневого отчёта (N1.6; владелец — глава 8.6).

### N1.1 Домен, член, держатель

```yaml
domain:      набор кластеров-членов под одним корнем доверия (глава 8.2); ни один raft не охватывает двух членов:
             у членов нет общей строки, слота, эпохи или объекта
member:      кластер M10 (одно хранилище строк, свой raft, свои процессы), принятый в список членов (`domain/member-rows/<part>` у держателя — глава 8.3 N1.1, `domain/member-list/<part>` у члена — [глава 9.1](../../09-agent/spec/09.1-agent.norms.md) N1.1);
             имя члена — `CLUSTER` его установки (P/04 N1.3a `cluster`), 1–64 знака [a-z0-9-], не пустое
holder:      ровно один член, на котором работают службы домена; держатель — роль члена, не вид кластера;
             какой член держатель — решение развёртывания (глава 8.8), не порядок установки
copy:        копия члена у держателя — то, что держатель принял от члена последним (глава 8.3 N1.3: отчёт поколением и метка
             `reported`); домен читает члена только по его копии, к самому члену не ходит
```

**Чего кластер не знает.** Кластер отвечает о своих единицах и только о них. Три вопроса — уровень домена: где единица,
если этот кластер о ней не слышал («не у меня» ≠ «нигде»); в какой кластер ставить новую единицу (назначение — глава 8.6);
полон ли ответ. Поиск внутри кластера, размещение на воркер, перенос между воркерами — M10, домен их не повторяет и
воркер не пересекает границу кластера. Эпоха единицы монотонна в своём кластере ([P/03.2 N1.5](../../../03-worker/ru/spec/03.2-worker.norms.md)); домену выдающий эпох не нужен.

### N1.2 Имя единицы в домене

```yaml
ref:         значение поля `domain.ref` строки единицы (сводная таблица P/02.1 N1.2a; у `testsub` и `testsub2` — `name`);
             номер единицы (`id`) принадлежит кластеру и в домене не ищется: у манифеста с `unit.id: numeric` id 1 есть в каждом
             члене (векторы N5 — такие); у `testsub` id — имя (P/06.1 N1.3), поиск — всё равно по ref
siblings:    у одного члена один ref могут нести несколько единиц: основная и прочие записи камеры (ADR-0111 п. 3). Это не спор: ref — имя для людей и назначения, строку адресует пара (cluster, id).
             Какая из них основная, домен не судит: это слово подсистемы; правка выбирает единицу явно, глава 8.6 N1.3 find
no_ref:      манифест без `domain.ref` в каталоге домена не участвует: его единиц нет в виде, дверь `/domain/<sub>/<rows>` — 404
no_value:    строка единицы без значения поля `domain.ref` (поля нет или "") — не единица домена: в `units` её нет, заявки
             теневого отчёта она не даёт (ни `unmanaged`, ни `conflict`), полноты вида не отнимает, `may_write` из-за неё не
             меняется; пульс такой единицы в отчёт члена идёт как прежде (ADR-0091 доп. (12) п. 2, доп. (13) п. 4)
```

### N1.3 Свежесть члена и единицы

```yaml
LOST_AFTER:  договор наблюдения «Свежесть» (значение там)   # тот же срок, что у пульса воркера (аудит раскладки, решение «Архитектора» 2026-10-25, A-01)
member_state: договор наблюдения «Свежесть члена домена» (перенесено туда без изменения; аудит раскладки, решение «Архитектора» 2026-10-25, A-15)
unit_state:                                      # единица из копии члена
  live:      есть в `status[]` пульса воркера (P/03.4 N1.1), и пульса нет в `stale` метки члена (публикация — P/09.1 N1.2; метка — глава 8.3 N1.3)
  stale:     есть в пульсе, и пульс — в `stale` метки: агент члена не видел его смены дольше порога подсистемы
             (P/09.1 N1.2 stale: heartbeat.stale_after, нет ключа — LOST_AFTER; ADR-0113 доп. (47) п. 4) по монотонным часам члена (живость воркера — факт кластера, P/04; домен её наблюдает, а не выводит из прихода копии)
  configured: есть только в шарде снимка (P/04 N1.3a), ни один пульс её не ведёт
  silent:    член не `ok` (`unseen`, `silent`): единицы его последней копии остаются в виде с этим словом, не удаляются
  # смена пульса — смена его JCS (глава 8.2 N1): `1` и `1.0` в любом поле — не смена (добавлено сверкой M11, V6)
  # live и stale — только у члена ok; первый взгляд этого процесса на пульс — смена при любом состоянии члена (возраст
  # пульса — с него); у silent — phase, worker, server и age по происхождению единицы: из пульса — его фаза и возраст,
  # из шарда — "unobserved" и возраст метки (cammeta-python M11-01 № 2, 3)
```

Член `unseen`, `silent` или `never` — «не подтвердился», а не «ничего нет»: ответ, которому он нужен, неполон (N1.5).

**Окно после старта и передачи держателя.** Монотонные часы держателя начинаются заново при каждом старте его процесса.
После перезапуска того же держателя метки членов остаются в его хранилище, но первый взгляд на метку — не смена: член с
меткой — `unseen`, вид неполон, пока процесс не увидит смену. Живой член обновляет метку не реже LOST_AFTER/2 (глава 8.3 N1.3)
и выходит в `ok` не позже этого срока; член, умерший до перезапуска, через LOST_AFTER становится `silent`. Так он не выглядит
живым после перезапуска, и правка главы 8.6 по его единице отвечает 503 «не слышно», а не 404 «нигде». После передачи держателя (глава 8.8) у нового держателя меток нет: поколения отчётов с передачей не едут
(глава 8.8), каждый член — `never` до первого отчёта новому держателю, вид неполон. Нового окна «по старой памяти» нет.

### N1.4 Вид домена

```yaml
domain/view:                     # форма целого вида: её считает команда view; раскладка на объектах — N1.4b, голова раз в VIEW_EVERY с
  as_of:     <стенные секунды держателя на конце прохода>
  holder:    <имя держателя>
  complete:  true | false        # команда view: true ⟺ каждый член `ok` и `contested` пуст; у прохода — круг, N1.4b complete
  members:   [{name, state: ok | unseen | silent | never, age, class?, url?, servers?}]   # age — секунды с последней смены метки, которую видел
                                                         # этот процесс, без смены — с первого взгляда; один знак после
                                                         # точки (N1.4 round); у `never` — null; порядок — по name
                                                         # url — адрес входа члена из объекта domain/servers копии: держатель берёт его, только если это https с хостом, без учётных данных и фрагмента, иначе поля нет, журнал:
                                                         # значение идёт в браузер, а коробка стоит на улице; нет — член за NAT, ссылка не строится (ADR-0111 п. 11);
                                                         # servers — [{name, online?, labels?, pulse?}] по name в байтах UTF-8: имена из объекта
                                                         # domain/servers копии, поля server её пульсов и строк шардов; online — есть пульс
                                                         # этого сервера: true, если член ok и пульс свеж (N1.3), иначе false; пульсов нет —
                                                         # поля нет: о сервере без воркера неизвестно; labels — из domain/servers;
                                                         # pulse — {<sub>: {<поле>: <значение>}}: поля domain.view_pulse манифеста из пульса
                                                         # воркера этого сервера, из первого по ключу в байтах UTF-8, *_secret срезаны;
                                                         # pulse.<sub>.stale: true — ключ этого пульса в stale последней публикации члена
                                                         # (P/09.1 N1.2: не менялся дольше LOST_AFTER по часам агента), по подсистеме; нет — поля нет (ADR-0113 доп. (33));
                                                         # слово сервера, а не единицы (ADR-0111 п. 2);
                                                         # нет копии или ни одного имени — поля нет
  units:     {<sub>: [Unit]}     # каждый манифест каталога с domain.ref (N1.2), ключ есть и у пустого
  backup_short?: {have, need}    # есть камеры, а взявших копию меньше BACKUP_HOLDERS: have — взявших, need — BACKUP_HOLDERS (глава 8.8 N1.5 new_camera; ADR-0113 доп. (4) п. 4)
  contested: {<sub>: {<ref>: [<член>…]}}   # ref, который заявляют два члена и больше, кроме ref исполнителей (executors
                                         # ниже); его единиц нет в units;
                                         # ключ есть у каждого манифеста с domain.ref, без спорных — {}
  <поля других глав>:            # trust — N1.2a; knocking — N1.7; topology, relay_refused — N1.6a;
                                 # books — глава 8.5; pending, outcomes — глава 8.6; url — договор пересылки; term — глава 8.8;
                                 # shared — глава 8.9; reports — N1.7; role_spread — глава 8.4
Unit:        {sub, id, ref, cluster, revision, labels?, about?, worker?, server?, phase, age, state, view?, status?}
  id:        id единицы в её кластере (строкой); ref — N1.2; cluster — член
  revision:  версия строки единицы из строки шарда, та, что взята правилом duplicate; непрозрачна для читателя; у чужой записи
             это версия для правки (ADR-0110)
  worker, server: из пульса (`worker`, поле `server` пульса) или из строки шарда снимка; нет — поля нет; worker пульса
             без поля worker — имя из ключа пульса `<sub>/heartbeats/<name>` (добавлено сверкой M11, V9)
  phase:     `status[].phase` пульса (P/03.4 N1.1); у `configured` — "unobserved"
  age:       секунды: у live/stale — с последней смены пульса, у configured — с последней смены метки; один знак после точки
round:       «один знак после точки» — округление точного десятичного значения секунд (не двоичной дроби) до 0.1,
             половина — от нуля: 0.25 → 0.3, 60.05 → 60.1 (добавлено сверкой M11, V4)
  labels, about: поле labels и значение поля about.field манифеста из строки шарда; поля нет в снимке или значение пусто — поля нет;
             служат суду по цели (договор права), чтобы вид фильтровался не грубее консоли
  view:      поля, названные `domain.view` манифеста (P/02.1 N1.2a), из строки шарда; секретных полей нет (P/06.2 N1.4)
  status:    поля, названные `domain.view_status` манифеста, из элемента status[] пульса этой единицы, ключи *_secret внутри срезаны
             на любой глубине (P/06.2 N1.4); элемента нет
             (`configured`), списка нет или ни одного поля нет — поля status нет; пульс нечитаем — как элемента нет
order:       units в каждой подсистеме — по (cluster, id, worker) в порядке байтов UTF-8; единица в пульсах двух воркеров
             одного члена — два элемента (её ведут оба; теневой отчёт разбирает, кто из них действует)
duplicate:   id в двух шардах снимка одного члена — строка с большей revision; при равной — из первого шарда по ключу
             в порядке байтов UTF-8 (добавлено сверкой M11, V5)
no_ref:      элемент пульса, у id которого нет строки в шарде своего члена, в units не входит (у Unit нет ref) и не заявляет;
             так же строка шарда без значения domain.ref (N1.2 no_value)
executors:   ref, все члены которого — исполнители его назначения ({cluster} ∪ copies, глава 8.6 N1.1; origin члена в это
             множество не добавляет и из него не исключает), не contested: единицы всех исполнителей — в units; роль исполнителя
             (основной или резерв) — забота подсистемы, вид её не показывает; член вне множества, давший тот же ref, —
             contested; назначения прохода не прочитаны (N3 шаг 3a) — исключения нет: ref у двух членов и больше — contested;
             полнота вида — по N3 шаг 5 (ADR-0091 доп. (12) п. 1, доп. (13) пп. 1–2, доп. (15) пп. 1–2)
as_of:       у команды view — стенные секунды её процесса на конце прохода входа; приёмка его не сравнивает
```

Исходы семьи пульсов (`heartbeats`, [P/03.4](../../../03-worker/ru/spec/03.4-worker.norms.md)) применяет живой читатель объекта из
хранилища — проход держателя, читающий объекты копии члена: пульс, нечитаемый целиком, в вид не попадает. Чистая функция
вида (команда `view`, вектор [`view`](../vectors/view/README.md)) получает уже прочитанное: форма её входа — `ViewInput`
(`worker` может прийти из ключа, `instance` не обязателен), не семья; заявки теневого отчёта — по строгому `status.items`
(N1.6 `claim`) (решение «Архитектора» 2026-10-20 (Go M11-01 № 7; семья heartbeats, разбор ревью стадии B 6–7, № 14, № 15)).

### N1.4a Таблицы вида

Чужому кластеру нужны не только единицы с `ref`: консоль видит настройки и тома члена, манифесты без `domain.ref` и единицы без значения `ref`, а правила и права стоят на таблицах (ADR-0110, разбор: «снимок домена короткий»). Таблицы в `domain/view` не входят: вид пишется каждые 3 с, а таблицы меняются редко. Спор `ref` (`contested`) строк таблиц не снимает: строка адресована кластером и ключом.

```yaml
domain/members/<член>/tables/<sub>/<таблица>:   # объект держателя; писатель — проход держателя, N3 шаг 3b
  {cluster, ts, refused?, rows}                 # снимок P/04 N1.3b из копии члена как есть; cluster равен имени члена
manifest:  domain.view_tables: {<таблица>: [<поле>…]} — объявленная таблица, не service: true, не из domain.kept, или unit.rows; поля — из её fields
           или unit.fields, не *_secret, не blob, held_by — только у таблицы мест (P/02.1, связи 137–143); domain.view_status — N1.4 Unit status
refused:   таблица не вошла, строк нет; читатель показывает, что данных нет, а не что таблица пуста
stale:     объект — наблюдение: ts — часы члена; молчащий член — прежний объект, живость читатель берёт из members[].state вида,
           после смены держателя — так же: член unseen, пока не пришёл отчёт
leave:     проход, увидев уход члена (N3 шаг 1), снимает его объекты; ошибка снятия — следующий проход; вернувшийся член с тем же именем
           чужих строк не видит: дверь отвечает по списку членов, объекты сняты раньше приёма
versions:  ключа нет у манифеста члена, а у манифеста держателя есть, — объекта нет: дверь 404 not reported yet, то же, что отчёт ещё не пришёл;
           различать незачем, данных нет в обоих случаях
move:      объекты не входят в резервную копию домена: новый держатель пишет их тем же шагом из принятых копий
```

### N1.4b Вид по разделам (ADR-0113 п. 4)

### N1.5 Полнота ответа

Ответ домена о единицах — сводка по копиям: частичная и устаревшая на ограниченную величину. Он ДОЛЖЕН нести свою
неполноту полем, а не отсутствием: `complete: false`, член `unseen`/`silent`/`never`, `contested`. Короткий список НЕ ДОЛЖЕН
выдаваться за полный. «Не найдено» при полном ответе — факт о домене; при неполном — факт о сети: отказ называет, кого не
было слышно (N4). Каждое производное от копий (вид, книги главы 8.5, имена главы 8.5, тревоги урока P/10) — наблюдение, а не
власть: оно не даёт права записи в члене и несёт свой список отсутствующих.

### N1.6 Теневой отчёт

```yaml
shadow:                            # считает проход держателя вместе с видом, ничего не пишет в члены
  inputs:    назначения domain/placement/<sub>/<ref> {cluster, copies} (глава 8.6 N1.1), прочитанные проходом один раз (N3 шаг 3a):
             исполнители ref — {cluster} ∪ copies; origin множество не меняет (origin = cluster — исполнитель как cluster;
             ADR-0091 доп. (15) п. 1); копии членов (N1.3)
  claim:     элемент status[] пульса воркера в копии члена → (sub, ref, id, член, воркер, epoch, revision, observed_revision);
             ref — по id единицы из шарда снимка этого члена; элемент без ref (нет строки в шарде) — заявки нет;
             элемент не по форме P/03.4 N1.1 (epoch, revision, observed_revision — не целые и т. п.) — заявки нет
             (добавлено сверкой M11, V14); элемент phase: sealed (эпоха не взята, P/03.4 N1.1, P/03.5 N3) — заявки нет
             (W03-G02); элемент phase: unreadable (эпоха не взята, P/03.3 N3 шаг 2) — заявки нет (W03-G05); единица без
             значения domain.ref (N1.2 no_value) — заявки нет: ни unmanaged, ни conflict (ADR-0091 доп. (13) п. 4);
             действующая заявка — только из пульса единицы в состоянии live (N1.3): последний пульс умершего воркера
             устаревает и заявлять перестаёт сам
  kinds:
    lagging:     заявка с revision > observed_revision, отсчёт SHADOW_STALL не вышел                         # норма
    stalled:     заявка с revision > observed_revision, отсчёт SHADOW_STALL вышел                            # отказ
    orphaned:    назначение есть, действующей заявки ref от его cluster нет дольше SHADOW_STALL — с появления назначения или с
                 пропажи последней действующей заявки; раньше находки нет (контроллер члена ещё не разместил)  # отказ
    unmanaged:   действующая заявка ref без назначения                                                       # измерение
    conflict:    действующие заявки ref у двух членов, не все из которых — исполнители назначения ref; или у двух
                 воркеров одного члена с равной эпохой по одной единице (тот же id; N1.2 siblings); или у члена, который не исполнитель назначения        # отказ
    stale_epoch: заявка из живого пульса с эпохой ниже наибольшей эпохи этой единицы (ref и id) среди заявок из живых пульсов того же
                 члена в состоянии ok; такая заявка не действующая; равная наибольшая у двух воркеров по одной единице (тот же id) — conflict; разные id одного ref — разные единицы (N1.2 siblings), не спор  # отказ
    unknown:     назначение на члена не ok или на имя вне списка членов (detail называет состояние или «not a member»)
  facts:     назначенный не заявляет (orphaned) и заявляет неназначенный (conflict) — два разных факта: назначение c → m2
             при действующей заявке только у m1 даёт обе находки
  grain:     lagging, stalled, unmanaged, stale_epoch — находка на заявку (cluster, worker); conflict — одна на ref
             (cluster — лишний член, если он один; у двух воркеров одного члена с равной эпохой — этот член, добавлено
             сверкой M11, V11); orphaned, unknown — на назначение (cluster назначения);
             lagging и stalled — только у действующих заявок
  orphaned_from: первый проход без действующей заявки назначенного ref или первый взгляд на назначение; назначение —
                 тройка (sub, ref, cluster): смена цели и возврат к прежней — новое назначение, отсчёт заново
                 (решение «Архитектора» по сверке M11, V10); отсчёт идёт и при члене не `ok`: находка пока `unknown`, член снова `ok`
                 без заявки и срок вышел — `orphaned` в том же проходе, заявка вернулась — отсчёт снят (C08-ORPHAN-SILENT-01)
  unread:    назначения прохода не прочитаны (N3 шаг 3a) — отчёт этого прохода не строится: domain/shadow не переписывается
             (остаётся прежний), clean_streak не растёт и не сбрасывается, отсчёты orphaned_from и SHADOW_STALL не начинаются
             и не сбрасываются (ADR-0091 доп. (15) п. 3, доп. (17) п. 2)
  findings_order: по порядку видов в counts, затем (sub, ref, cluster, worker) в байтах UTF-8
  SHADOW_STALL:  forms/runtime-constants.tsv       # с, у class camera — max(60, 3 × every метки) (P/08.3 N1.1a), по монотонным часам держателя: время отставания без смены observed_revision этой пары
                          # (член, воркер, ref) — от позднейшего из: последней смены observed_revision, начала отставания
                          # (проход с revision > observed_revision после прохода, где заявка пары не отставала; единица,
                          # долго стоявшая без отставания, с новым revision — lagging, не сразу stalled, C08-SHADOW-STALL-LAG-01);
                          # и время без действующей заявки назначенного ref; оба отсчёта — с первого взгляда этого
                          # процесса на пару или назначение, при любом состоянии члена
  silent_member: заявки члена не `ok` (`unseen`, `silent`, `never`) не действующие; назначение на такого члена — не orphaned, а неизвестно
                 (`unknown` в findings, в счёт отказов не входит)
  exit:          may_write ⟺ unmanaged == 0 ∧ нет отказов (stalled, orphaned, conflict, stale_epoch) ∧ clean_streak ≥ SHADOW_CLEAN
  SHADOW_CLEAN:  forms/runtime-constants.tsv        # проходов подряд без находок; любая находка или неизвестно обнуляет счёт
  report:        {counts: {lagging, stalled, orphaned, unmanaged, conflict, stale_epoch, unknown},
                  findings: [{kind, sub, ref, cluster?, worker?, detail}], clean_streak, may_write, why}
```

`may_write` — условие, при котором домену будет разрешено размещать единицы самому; в модуле домен сам не размещает
(назначение пишет оператор, глава 8.6; размещение доменом — долг в журнале работы Спецификации (для человека)). Отчёт — измерение модели: каждая
`unmanaged` — единица, которую модель домена не описывает.

## N2 Двери

Своих дверей у главы нет. Вид и теневой отчёт отдаёт консоль домена дверями `GET /domain`, `GET /domain/<sub>/<rows>`,
`GET /domain/shadow` — урок P/10 (P/10-01; [N1.2a](../../../10-domain-console/ru/spec/10-domain-console.norms.md)): объект `domain/view` как есть плюс `age`, единицы подсистемы из вида, отчёт последнего прохода; содержимое — N1.4,
N1.6 этой главы.

Команда `view` реализации (Решает реализация п. 1): вход — файл проходов (N5), выход — JSON `{view, shadow}` последнего
прохода (`shadow` — отчёт последнего прохода, который его строил, N1.6 `unread`; ни один не строил — `null`); код 0 —
вычислено, 2 — вход не по форме N5. Это та же функция, что у прохода держателя, без хранилища.

Нативный вход камеры (G08-VIEW-CAMERA-INPUT-01). В `ViewInput` явно переданный `silent_after` выбирает свежесть камеры для этого прохода; без него вход моделирует сервер. Это абстракция команды для `Entry.class` и `received_at` метки, которых её закрытый вход не несёт. При первом взгляде на существующую метку камеры команда задаёт время её приёма монотонным `at` этого прохода: член `ok`, пока метка существует и возраст с этого приёма или последней наблюдённой смены метки не больше `silent_after`, и `silent`, когда больше. Ни разу не виденная метка — `never`; исчезнувшая — `silent`, как в N1.3. Сервер сохраняет обычное первое `unseen` до наблюдённой смены метки. Эта абстракция не меняет работающего держателя: класс берётся из принятой записи участника, время приёма — из настоящей метки, не из времени heartbeat. Ни класс, ни поле приёма не выводятся из объектов копии.

## N3 Проход

### проход держателя — вид и теневой отчёт (голова раз в VIEW_EVERY, разделы кругом N1.4b)

Шаги идут по разделам круга над их членами: шаг 7 пишет строку раздела при отличии, голову — раз в VIEW_EVERY, шаг 5 — `complete` N1.4b; шаги 3a, 6 — раз в круг (N1.4b `shadow`).

```
1. прочитать список членов (глава 8.3) и метку каждого члена; член без метки — never, если этот процесс его метки не видел,
   иначе silent с прежней копией (N1.3); ушедший из списка — забыть (N1.3 leave); смена метки на глазах — сброс возраста;
   первый взгляд процесса на метку — не смена (unseen, N1.3; камера — N1.4b stale); `domain/member-rows/<part>`, `domain/keys` или `domain/topology` есть, но
   не читаются — прохода нет: domain/view и domain/shadow не переписываются, clean_streak и отсчёты — как у `unread` (N1.6),
   журнал без значения: нечитаемое не подменяется пустым списком (C08-PASS-UNREADABLE-01)
2. для каждого члена не never: копия — отчёт поколения метки (глава 8.3 N3 «прочитать копию»), у пропавшей метки — прежняя
   копия процесса; не читается — член silent
   (метка читается, поколения нет или sha256 не тот: silent и при первом взгляде процесса, не unseen; reports — поля
   этой метки, как у любого члена с меткой, N1.7; C08-MARK-NO-COPY-01)
3. для каждого манифеста каталога с domain.ref: units из пульсов и шардов каждой копии (N1.4); id уже из пульса — шард его не дублирует;
   строка без значения domain.ref — не единица (N1.2 no_value)
3b. для каждого манифеста с domain.view_tables и каждой копии: поколение копии сменилось с прошлого прохода или процесс её ещё не
   разбирал — для каждой таблицы взять объект <sub>/snapshot-tables/<таблица>; нет в копии или не по семье или cluster не имя члена — не
   трогать, журнал без значения; иначе rows или refused отличается от записанного → записать domain/members/<член>/tables/<sub>/<таблица>
   (глава 8.10 N1.7 objects); ошибка записи или очередь не подтверждена — копия не считается разобранной, следующий проход повторит
   независимо от поколения; вид пишется независимо (N1.4a)
3a. прочитать назначения domain/placement/<sub>/* — один раз на проход: это чтение служит шагу 4 и теневому отчёту (шаг 6);
   не прочитаны — назначений этого прохода нет (ADR-0091 доп. (13) п. 1)
4. ref, который дают два члена и больше → contested, единицы этого ref из units снять; кроме ref, все члены которого —
   исполнители его назначения шага 3a (N1.4 executors): его единицы остаются в units
5. complete — N1.4b: круг закрыт, все разделы полны (член ok, contested пуст)
6. теневой отчёт по N1.6: назначения шага 3a; заявки; виды; clean_streak и may_write; назначения не прочитаны — отчёт
   этого прохода не строится (N1.6 unread)
7. записать domain/view (put объекта); отчёт — в память прохода и в объект domain/shadow тем же проходом; не построен —
   domain/shadow и память отчёта прежние
```

**Гонки.** Копии членов читаются в разные моменты: вид — наблюдение, а не снимок. Член может поменять метку между шагами 1
и 2: проход берёт поколение прочитанной метки, следующий проход — новое. Два прохода держателя (держатель один, глава 8.8)
не пересекаются; после перезапуска держателя члены `unseen` до первой увиденной смены, `clean_streak` — 0. Ошибка записи
`domain/view` не меняет прежний объект; дверь отдаёт прежний вид с его `as_of`. Обрыв между записью вида и теневого
отчёта — вид нового прохода, отчёт прежнего: следующий проход пишет оба; расхождение одного прохода допустимо. Сбой чтения или записи части прохода
прерывает этот проход: записанное остаётся, остальное делает следующий; сверка людей ([глава 8.4](08.4-domain.norms.md) N3: `domain/disabled`, метки удаления, срок, новые виды, роль `admin`, у каждой своё условие) и резервная копия — свои работы, они идут (C08-PASS-PART-01).

## N5 Приёмка

Каталог [`../acceptance/1/`](../acceptance/1/README.md): стенд нескольких кластеров (`hold`, `m1`, `m2`; раздел «Стенд
домена» [общего README приёмки](../../../common/ru/acceptance/README.md)) — 6 сценариев / 39 шагов: настоящие отчёты агентов в
`domain/members/<member>/reports/<rev>` и дверь `GET /domain` держателя. Номера сценариев и шагов — прежние номера приёмок
M11/03 (04, 06–09) и M11/06 (06 → 15, номер 06 занят; решение «Архитектора» 2026-10-20, ADR-0083 доп. (14) п. 14).

Векторы [`../vectors/view/`](../vectors/view/README.md): команда `view` реализации на входах — без хранилища, сети и стенда
домена. Канонические состав и счёты случаев — в README векторов. Вход — проходы держателя: форма входа —
`ViewInput`, вывода — `ViewOutput` в [контракте урока](../../spec/08-domain.api.openapi.yaml) (компоненты; норма главы, не выбор
реализации). Вход — проходы держателя по порядку: `at` — монотонные секунды держателя (не стенные),
`members.<член>.mark` — `rev` метки `reported` (глава 8.3 N1.3) или `null`, `members.<член>.stale` — поле `stale` метки
(нет — пусто), `objects` — объекты копии по ключам [P/03.4 N1.1](../../../03-worker/ru/spec/03.4-worker.norms.md)
(`<sub>/heartbeats/<воркер>`) и [P/04 N1.3a](../../../04-controller/ru/spec/04-controller.norms.md) (`<sub>/snapshot/<шард>`),
`placements` — `{<sub>: {<ref>: <член> | {cluster, copies?, origin?}}}` (глава 8.6 N1.1): обе формы; `copies` нет — пусто;
`placements: null` — назначения этого прохода не прочитаны (N3 шаг 3a); иное поле или тип — вход не по форме (код 2). Смену метки и пульса держатель видит между проходами входа; первый проход — первый
взгляд. Сравнение — подмножество полей (словарь «Стенда» [общего README приёмки](../../../common/ru/acceptance/README.md)).
Ожидания зависят от байтов манифестов `testsub` и `testsub2` (README векторов называет их sha256; разбор ревью стадии A 8–10,
№ 37).

Пересылка консолью члена — [договор пересылки](../../../common/ru/contracts/forwarding.md) (переходы 1–2 — консоль кластера, приём перехода 2 — урок P/10); гранты — глава 8.4.

Проверяются чтением, с причиной: N1.1 — двери главы 8.3 (членов домен не опрашивает); worker из ключа пульса, заявка не
по форме, `cluster` у `conflict` одного члена — входов таких нет (`mark` 2^53 у команды `view` — вектор `17-exit-mark-2pow53`,
метку с `rev` 2^53 у прохода держателя проверяет сц. 22 приёмки главы 8.3); окно после передачи держателя — стенд главы 8.8;
вход команды `view` не по форме (код 2) — векторы `17-exit-*`, иные нарушения формы — чтением; «Гонки» N3 — стенд не обрывает процесс между записями; назначения не
прочитаны (N3 шаг 3a): объект `domain/shadow` не переписан, отсчёт `orphaned_from` не начат и не сброшен — стенд не
обрывает чтение назначений (вектор `10-placements-unread` — `contested` и прежний `clean_streak`); строка без значения
`domain.ref` у живого члена на стенде — векторами (`10-no-ref-row`).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **команду `view`** для приёмки — шаблон с `{input}`; её вызов и вывод — дверь `view` словаря «Стенда домена», формы — N5;
2. **как проход держателя хранит память теневого отчёта** (начало отсчёта SHADOW_STALL по паре, время появления назначения или пропажи последней действующей заявки, `clean_streak`) между проходами; после перезапуска она пуста;
3. **порядок полей JSON** вида — свободен; порядок элементов массивов — N1.4 и N0.

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/08.1-MM` — то, на что ссылаются дельты
решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/08.1-01** домен, член, держатель, копия; ни одного общего raft; домен читает члена только по копии — проверяется чтением N1.1 (предмет — двери главы 8.3: членов домен не опрашивает); сторона члена — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md)
- [ ] **P/08.1-02** имя единицы в домене — `domain.ref`; манифест без него вне каталога; id кластера не ищется — вектор `01-two-members`; дверь 404 — чтением (дверь — урок P/10); загрузка `domain.ref` — P/02.1 N1.2b (поздний слой)
- [ ] **P/08.1-03** свежесть члена (ok/unseen/silent/never) и единицы (live/stale/configured/silent) по монотонным часам держателя, LOST_AFTER — векторы `02-*`, `03-configured-and-stale`, стенд сц. 04, 07, 08; окно после старта держателя — вектор `02-unseen`, стенд сц. 07 (первый проход — `unseen`); после передачи — глава 8.8; пропажа метки, уход и возврат, JCS пульса, округление и дубль id — векторы `12-*`…`16-*` (сверка M11), дубль id при равной `revision` — вектор `18-duplicate-equal-revision`; `never` с `age: null` — вектор `11-never`; метка с `rev` сверх 2^53 − 1 у прохода держателя — член `silent` — сц. 22 [приёмки главы 8.3](../acceptance/3/README.md); `mark` 2^53 и иной вход не по форме у команды `view` — векторы `17-exit-*` (код 2); worker из ключа пульса, заявка не по форме, `cluster` у `conflict` одного члена — чтением
- [ ] **P/08.1-04** вид: форма, порядок, `complete`, `contested` — векторы `01-two-members`, `04-contested`, `11-pulse-without-row` (no_ref); `revision`, `status`, `servers` — вектор `11-view-revision-status-servers`; таблицы N1.4a — чтением до шага 11 разбора ADR-0110; стенд сц. 06, 09; исполнители назначения не `contested`, строка без значения `domain.ref` вне вида, назначения раз на проход (N1.2 no_value, N1.4 executors, N3 шаги 3a–5; ADR-0091 доп. (12)–(19)) — векторы `10-*`, сц. 10 [приёмки главы 8.6](../acceptance/6/README.md)
- [ ] **P/08.1-05** неполнота — полем, не отсутствием; «не найдено» при неполном ответе называет молчащих — вектор `02-unseen`, `02-member-silent`; отказы дверей правки — глава 8.6
- [ ] **P/08.1-06** теневой отчёт: шесть видов, `unknown`, SHADOW_STALL (forms/runtime-constants.tsv), заявка только из живого пульса, orphaned после SHADOW_STALL, исполнители назначения (`cluster`, `copies`) — векторы `05-unmanaged`, `06-*`, `07-faults`, `09-zombie`, `10-*`, `11-unknown-member`, `11-two-workers-one-member`; стенд сц. 06; отсчёт SHADOW_STALL после прогресса — векторы `20-stall-after-progress-*`, от начала отставания — `22-stall-from-lag-*`, `orphaned_from` при смене цели (V10) — `21-orphan-retarget-*`, элементы `sealed`/`unreadable` без заявки — `19-sealed-unreadable-no-claim` (аудит покрытия P/08, второй проход)
