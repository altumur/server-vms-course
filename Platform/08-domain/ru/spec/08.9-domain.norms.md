## N1 Форма

Время объекта страницы `domain/alarms` (`from`, `to`) — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1 «Время».

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/shared`, `domain/shared-docs/rev-<rev>`, `domain/alarm-history/<member>`;
- пишет: `<events root>/audit/<role>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl` (append);
- читает: `platform/manifest/<sub>`, `domain/holder`, `domain/member-rows/<part>`, `domain/view`, `domain/signer`, `domain/signer-turn`, `domain/members/<member>/reports/<rev>`, `domain/members/<member>/reported`.

Строка `domain/shared` — указатель у держателя (N1.2) и строка копии у члена.

Протокол строки `domain/shared` задаёт держатель; агент — участник `cas` ([глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N1.10).

Объект `domain/shared` у члена (копия документа) — семья агента.

Объекты `domain/shared-docs/rev-<rev>` и `domain/alarm-history/<member>` пишет только процесс `domain`.

Документ `domain/shared-docs/rev-<rev>` процесс пишет без стража, раньше указателя.

Указатель `domain/shared` процесс пишет по CAS прочитанной версии со стражем `domain/signer-turn` ([P/08.10 N1.7](08.10-domain.norms.md)).

Историю `domain/alarm-history/<member>` процесс пишет по CAS, `put_at` по индексу объекта ([P/08.10 N1.7](08.10-domain.norms.md) `objects`).

Манифесты каталога (`domain.shared`, схема документа) процесс читает строками `platform/manifest/<sub>` (N1.3 шаг 4).

Процесс подписывает выпускающим ключом строки `domain/signer` ([договор записи срока](../../../common/ru/contracts/record.md), `issuing_key_secret`).

Срок процесс читает из записи `domain/holder` (глава 8.8).

Членов процесс читает из списка `domain/member-rows/<part>`, их состояние — из вида `domain/view` (глава 8.1).

Копии членов (`domain/shared`, `domain/shared-refused`) и страницу тревог процесс читает из объектов отчёта `domain/members/<member>/reports/<rev>`,
а `received_at` и `sent_at` отчёта — из метки `…/reported` (глава 8.3).

Журнал `domain.shared.edited` (N1.3 `answer`) процесс
дописывает в `audit/domain` по [договору журнала событий](../../../common/ru/contracts/event-journal.md) (участник `append`,
владелец — P/05).

Общее N1 урока P/08 ([P/08.2 N1](08.2-domain.norms.md) «Общее для всех форм главы», [P/08.3 N1](08.3-domain.norms.md)) действует.

Домен не знает ни одного поля подсистемы: что общее, объявляет манифест, а значение домена разрешается **при чтении**, не записью в строки.

Тревоги членов домен собирает из их отчётов: к члену он соединений не открывает.

### N1.2 Общий документ

```yaml
document:        объект держателя domain/shared-docs/rev-<rev> — JCS {domain, term, rev, at, by, shared, issuer, kid, sig}
  shared:        {<sub>: {<name>: <value>}}
  term, rev:     срок держателя (P/08.8) и номер правки
  by:            имя, доказанное сторожевой
  signature:     выпускающий ключ
pointer:         domain/shared {doc: JCS {term, rev, sha256, object}} у держателя
write:           объект, затем указатель
after_move:      rev + 1, by "domain"
readers:         процесс domain, консоль домена, воркер подсистемы, консоль кластера
```

`document.shared` несёт только объявленное P/02.1 N1.2b; подсистемы и имена идут по возрастанию (JCS).

Порядок документов — (term, rev), term старше.

После переноса `document.by` — "domain".

`document.signature`: документ подписан выпускающим ключом, как запись срока (договор записи срока, record.md); проверка — функция record.

Неподписанный документ не принимается никогда.

В `pointer` `sha256` — hex sha256 текста объекта.

В `pointer` `object` — ключ этого объекта, строка `"domain/shared-docs/rev-<rev>"` с rev указателя.

`write`: сначала объект, затем указатель по CAS (две правки одновременно — одна получает 409).

Держатель хранит последние SHARED_OBJECTS_KEEP объектов.

Правки общего документа процесс исполняет по одной (шаги N1.3 order 3–6 — одна правка за раз).

Объект ревизии пишется порядком объектов без указателя (P/08.10 N1.7 objects): снимок
указателя domain/shared (по нему объект признаётся ничьим) → get_at объекта ревизии → подтверждение своей
очереди domain/signer-turn → запись по индексу ЭТОГО get_at (договор клиента хранилища объектов «Операции» ops).

При записи объекта ревизии: объекта не было — put_new.

При записи объекта ревизии: есть с теми же байтами — не писать.

При записи объекта ревизии: есть с другими байтами — указатель его не называет (rev объекта выше
rev указателя: прежняя правка оборвалась между объектом и указателем), объект ничей — put_at поверх.

При записи объекта ревизии: очередь потеряна между чтением и подтверждением — правке 503 по P/08.10 N1.7, объект не тронут.

При записи объекта ревизии: put_new или put_at получил conflict — объект сменился после get_at, его пишет другая правка или другой процесс: правке 409 «the shared
settings changed while this edit was made — look again», объект не трогается — проигравшая правка не
перезаписывает объект выигравшей.

`after_move`: новый держатель (P/08.8 N1.8 шаг 8) переподписывает то же содержимое как rev + 1, by "domain" — у него другой
выпускающий.

После переноса, когда сумма не совпала ни у одной копии, новый держатель не переподписывает (P/08.8 N1.8 шаг 8).

После переноса на исключении шага 3 указатель идёт пакетом шага 8 (P/08.8 N1.8).

При плановой передаче выпускающий тот же, документ не меняется.

`readers`: процесс domain, консоль домена, воркер подсистемы на домене (роль `<sub>domain`) читают указатель domain/shared
(точное имя) и объекты domain/shared-docs/rev-* (семья domain/* двери объектов P/05).

Консоль кластера читает строку domain/shared (точное имя: у держателя
указатель, у члена строка копии, N1.4; P/02.5 N1.4 console).

Воркер подсистемы по worker.reads domain/shared читает у члена строку копии и объект domain/shared,
у кластера держателя — указатель и объект по его полю object.

Воркер подсистемы сверяет сумму и подпись сам; не сошлось — прежнее значение.

Проекций общего документа по подсистемам нет.

### N1.3 Правка

```yaml
door:            PUT /domain/shared {base_rev?, shared: {<sub>: {<name>: <value> | null}}} and If-Match
order:           1, 1a, 2, 3, 4, 5, 6
answer:          200 {term, rev, by}, ETag
```

`door`: дверь `PUT /domain/shared` — у консоли домена (admin, P/08.4;
урок P/10 N1.3) → процесс domain тем же путём (глава 8.0).

Тело `PUT /domain/shared` ≤ 1 МиБ (иначе 413 {error: "refused"}).

Шаги `order`:

1. Заморозка, смещение — P/08.8 (503 frozen, 409 deposed).

1a. Заголовки и память повторов (глава 8.0 N1.9).

2. Тело не `{base_rev?: integer ≥ 0, shared: object, every shared.<sub> — object}`, нет ни If-Match, ни base_rev либо они
   расходятся (глава 8.0 N1.9 «base_rev») — 400
   `{error: "refused", detail: "the edit is {base_rev: <the revision it was made against>, shared: {<sub>: {<field>: value or null}}}"}`.

   На шаге 2 `shared.<sub>` не объект — отказ тоже здесь, до base_rev.

3. Ревизия раньше содержания: If-Match не равен версии указателя — 412 revision moved.

   На шаге 3 заголовка нет и base_rev ≠ rev указателя (0 — документа нет) — 409 {error: "refused", detail: "the shared settings are at
   rev N; the edit was made against rev M — look again"}.

4. Содержание — все отказы одним 400 через «; ».

   На шаге 4 отказ содержания: «`shared settings for '<sub>': no subsystem on the domain shares a field by that name`».

   На шаге 4 отказ содержания: «`'<name>' is not in its domain.shared [<the names of domain.shared of the manifest joined by «, », ascending>]`».

   На шаге 4 тип поля — та же проверка
   формы, что у двери единиц (P/06.1 N3 «создать» шаг 4), на одном этом поле, слово отказа — её.

   На шаге 4 значение документа проверяется против его schema (слова схемы).

   На шаге 4 значение, которое консоль запечатала бы (P/06.2 N3) (имя *_secret на любой глубине,
   находка пароля в адресе по P/06.2 N1.1a), — «`'<name>': the shared document is signed, not sealed`».

5. Новый документ: прежний shared, поверх — значения правки; rev + 1, term — свой, at, by.

   На шаге 5 null — снять имя.

   На шаге 5 пустая подсистема — снять.

   На шаге 5 прежний документ (объект, который называет указатель) не читается
   или не с его sha256 — 503 {error: "refused", detail: "the shared document at rev N does not read: nothing
   is written"}, ничего не пишется: правка поверх пустого потеряла бы прежние значения.

6. Записать (N1.2 write); целевая запись — указатель, объект идёт раньше него и повторяется без вреда (глава 8.0 N1.9 write).

   На шаге 6 CAS не прошёл — 409 «the shared settings changed while this edit was made — look again».

`answer`: 200 {term, rev, by}, ETag — индекс указателя.

С ответом — журнал domain.shared.edited {term, rev, by}.

### N1.4 Доставка члену — сторона держателя

```yaml
carry:           shared: {pointer: {term, rev, sha256}, doc?: <text>}
holder_self:     указатель domain/shared и объект domain/shared-docs/rev-<rev>
```

`carry`: ответ держателя агенту (P/08.3 N1.5) несёт `shared`.

`carry.doc` отправляется только когда domain/shared из копии члена ≠ указателю или копия несёт поле object: это строка бывшего держателя (P/08.3 N3 «прочитать копию»).

`holder_self`: у кластера держателя строка domain/shared — указатель (N1.2), а документ — объект `domain/shared-docs/rev-<rev>`.

Агент держателя документа не берёт.

Консоль держателя читает указатель (дверь
GET /domain/shared/{sub} OpenAPI урока 6).

Сторона агента — `member` (взять документ по порядку, объект и строка `domain/shared`, отказ — строка
`domain/shared-refused`) и `in_report` (строки `domain/shared` и `domain/shared-refused` — объекты отчёта) — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md)
(N1.10, N3 «взять документ»).

Держатель читает эти объекты из отчёта члена для доставки (N1.6).

### N1.6 Доставлено скольким

```yaml
domain/view.shared:  {term, rev, holding, behind, refused, silent, sentence}       # P/08.1 N1.4
  holding:     [<member>…]
  behind:      {<member>: {term, rev}}
  refused:     {<member>: <reason>}
  silent:      [<member>…]
  sentence:    «rev R on H of T members[; not taken yet: …][; not answering: …][; refused by: <member> (<reason>), …]»
  before:      term 0, rev 0, holding [], behind {}, refused {}, silent, sentence «rev 0 on 0 of T members»
```

`holding`: копия члена ≥ (term, rev) указателя; держатель включён.

`behind`: член, который держит старее, со своими {term, rev}.

В `behind` член без копии — {term: 0, rev: 0}, не null.

`refused`: domain/shared-refused члена с (term, rev) указателя.

`silent`: член не ok по виду (глава 8.1); это правило — раньше прочих правил.

`before`: до первого документа (указателя нет) значение — term 0, rev 0, holding [], behind {}, refused {}, silent — по виду,
sentence «rev 0 on 0 of T members» с теми же хвостами.

Поле view.shared есть с первого прохода держателя — до первого документа значением before.

Дверь `GET /domain/shared` у консоли домена (`view`) → `200 {doc, delivery, declared}`: `delivery` — `view.shared` выше.

`doc` (документ как подписан — объект N1.2 | `null`) и `declared` (элементы `domain.shared` манифестов каталога со `schema` у
документа) двери `GET /domain/shared` — урок P/10 ([N1.2f](../../../10-domain-console/ru/spec/10-domain-console.norms.md), P/10-14).

### N1.9 История тревог

История члена у держателя (`history`, `cut`, `HISTORY_DAYS`, `HISTORY_LINES`, `writer`, `in_copy`), равенство строк
`same_line` и повтор в странице — [договор истории тревог](../../../common/ru/contracts/alarm-history.md).

Пишет историю только проход держателя этой главы.

Читатель и писатель применяют HISTORY_LINES к events; превышение даёт прежний исход нечитаемой истории целиком, без усечения.

### Семьи данных (построены из стандартных файлов)

Форма строк и объектов, которыми глава владеет по [каталогу](../../../common/data/catalog.tsv), — JSON Schema 2020-12 семьи. Экземпляр строки — `{key, row}`, объекта — `{key, object}`; ключ — грамматика колонки `key` каталога. Поля `row` — значения `items` после [кодека](../../../common/data/codec.tsv): писатель проверяет схему и её `$defs.writer`, читатель — схему (слой 3 — слова `x-*` схемы). Нечитаемо — строка не раскодировалась или не прошла схему в режиме читателя; исход — по таблице исходов семьи: путь — префикс пути отказа (пустой — строка целиком), при нескольких путях отказа действует исход с наименьшим приоритетом.

## N3 Проход

Своих проходов, кроме порядка правки (N1.3 `order`) и писателя истории (N1.9 `writer`), у главы нет.

«Взять документ»
(агент члена) — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N3, `resolve(field, unit, domain)` — консоль кластера (векторы `resolve`, глава P/06.7), `alarms(input)` —
[урок P/10](../../../10-domain-console/ru/spec/10-domain-console.norms.md) N3 `alarms`.

**Гонки.** Две правки общего документа — CAS указателя, вторая — 409.

Держатель перенесён — новый переподписывает
документ (`rev + 1`), члены берут его как новый.

Обрыв между объектом и указателем (N1.2 write): объект выше указателя
ничей, указатель прежний; следующая правка пишет поверх (N1.2 write: get_at → подтверждение очереди → put_at по индексу
этого get_at).

Смена очереди между чтениями: активный A пишет объект N+1, смещённый S прочитал индекс до записи A — его
put_at получает conflict (409).

Смена очереди между чтениями: S прочитал индекс после записи A — подтверждение очереди S не проходит (503), объект A цел.

Член без связи и шторм тревог — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) N3 «Гонки» и урок P/10 (N3
«Гонки»).
