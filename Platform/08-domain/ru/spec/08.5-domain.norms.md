## N1 Форма

**Время.** Полей времени у строк главы нет.

Время, которое глава читает, — по [канону N0 P/01.1](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке):
`until` строки гранта (правило N1.3 `grant`; [P/08.4 N1.3](08.4-domain.norms.md)) против стенных часов держателя.

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `domain/book-keys/<sub>/<manifest:domain.books>/<part>`, `domain/<sub>/<manifest:domain.books>/*`, `domain/<sub>/<manifest:domain.books>/*/<part>`, `domain/folder-units/<id>`, `domain/folder-units/<id>/<part>`, `domain/folder-log`, `domain/folder-counts/<id>`, `domain/folders/<id>`, `domain/memberof/<member>/<sub>/<manifest:unit.rows>/<id>`, `domain/folder-rev`, `domain/<sub>/<manifest:domain.books>/<member>`, `domain/names/<sub>/<book>`;
- пишет: `domain/view` (cas), `<objects root>/<dir>/~lock` (create);
- читает: `domain/member-rows/<part>`, `domain/members/<member>/reported`, `domain/members/<member>/reports/<rev>`, `domain/book-seal`, `domain/grants/<cluster>`, `domain/users/<name>`, `domain/signer-turn`, `/etc/w2c/secrets/platform.key`.

Строки «владеет» пишет процесс `domain` проходом держателя (N3 «сборка книги») под стражем очереди `domain/signer-turn`
([P/08.10 N1.7](08.10-domain.norms.md)): строки собираемой книги — только при изменении открытого содержимого.

Строки бывших членов собираемой и переносимой книги процесс `domain` удаляет (N1.3 `write`).

Строки переносимой книги пишет воркер подсистемы на домене
([P/03.7 N1.6](../../../03-worker/ru/spec/03.7-worker.norms.md) `carried_book`) — протокол строки задаёт эта глава.

Воркер на домене пишет строку переносимой книги CAS по прочитанной версии, свою нечитаемую строку переписывает целиком своим содержимым, причина в
журнал без значения.

Поле `books` вида `domain/view` (владелец объекта — глава 8.1) — N1.5.

Члены и их копии — список `domain/member-rows/<part>`, метка
`…/reported` и поколение `…/reports/<rev>` (глава 8.3); ключ приёма книг — `domain/book-seal` ([P/08.2 N1.4](08.2-domain.norms.md));

Секреты строк единиц в доставке процесс открывает кольцом `/etc/w2c/secrets/platform.key` (владелец
файла — [P/02.4](../../../02-installer/ru/spec/02.4-installer.norms.md); N3 «доставка»).

Общее N1 урока P/08 ([P/08.2 N1](08.2-domain.norms.md) «Общее для всех форм главы», [P/08.3 N1](08.3-domain.norms.md)) действует.

Книга — наблюдение, не власть: `from` прав

### N1.3 Сборка у держателя

```yaml
inputs:           <копия каждого члена списка>, <его состояние вида>
contributes:      ok | unseen
missing:          [{member, why}]
  why:            unseen | silent | never | no_copy | bad_contribution | secret_unopened
bad_contribution: → missing
secret_unopened:  → missing
pick:
  unique:         один вклад на key
  all:            все вклады
result:           domain/<sub>/<книга>/<получатель>
  "":             текст JSON {missing, missing_count}
  <key>:          текст JSON {entries: [{member, item, value}]}
    member:       <член>
    item:         <слот>/<item> | <item>
    value:        <объект входа>
  order:          entries по (member, item)
  at_rest:        enc:v2
  write:          rewrite | remove
recipient:        <член> | "servers"
grant:            domain.names.<книга>/.grant
cadence:          <каждый проход держателя>
to_all:           domain.books.<книга>.to = "*"
  parts:          domain/<sub>/<книга>/*/<раздел>
  head:           domain/<sub>/<книга>/*
  stale:          [<член>/<сервер>…], stale_count
  version:        (term, rev)
  round:          <круг разделов вида>
  book-keys:      domain/book-keys/<sub>/<книга>/<раздел члена>: {"": {term}, <член>: [<ключ>…]}
  unique:         pick: unique → отказ каталога
  first:          503 unavailable
  first_pass:     <с нуля>
  order:          <строки разделов>, <book-keys>
  ceiling:        524288 байт; NEAR_CEILING
```

`inputs`: копия каждого члена списка (P/08.3 N3 «прочитать копию»), включая держателя (его подписанный
отчёт), и его состояние вида (глава 8.1 N1.3).

`contributes`: член ok или unseen (копия есть) вкладывает; silent, never, копии нет — не вкладывает.

`contributes`: первые LOST_AFTER от `at` записи срока, взятого переносом или передачей (term ≥ 2; now − at ≤ LOST_AFTER по стенным часам процесса, `at` перезапуск не меняет, глава 8.8 N1.1 `claim`), сборки нет: строки книг и индекс имён N1.7 не пишутся, `view.books` пуст; never значит «ещё не слышал», и книга без вкладов заменила бы у читателей полную.

`missing`: правило одной фразой: **чего нет в книге из-за члена — тот в
missing**.

`missing`: class server первыми, внутри по member.

`missing`: один на книгу.

`missing.why`: закрытый список слов.

`missing.why`: unseen и вкладывает, и в missing: ответ неполон, пока смена не увидена (глава 8.1).

`missing.why`: у члена одна запись missing: unseen со снятым вкладом — why причины снятия (bad_contribution,
secret_unopened), не unseen.

`bad_contribution`: вход не объект или не JSON, нет key или он не непустая строка, to не имя, не список имён и не "servers", у книги to: "*" — поле *_secret на любой глубине, неравные элементы
одного key у одного члена при unique (равные — один вход, N3 шаг 4a) → весь вклад члена в этой книге снят, член — в missing.

`secret_unopened`: секрет вклада не открылся (договор конвертов домена «Конверт x25519:v1»; в том числе конверт кольца,
который член не открыл, — not_v1) → весь вклад снят, член — в missing.

`secret_unopened`: значение не раскрывается.

`pick.unique`: ровно один вклад на key во всём домене; два и больше — key в книге отсутствует (конфликт, диагностика N1.5).

`result`: строка у держателя domain/\<sub>/<книга>/<получатель> для каждого члена списка (включая держателя).

`result.""`: missing — первые MISSING_SHOWN: class server первыми (Entry, нет поля — server), внутри по member, missing_count — все: читатели судят серверы, режутся камеры.

`result.""`: MISSING_SHOWN держать равным SERVERS_MAX (P/08.10 N1.5), иначе молчащий сервер уйдёт за список.

`result.""`: missing — только здесь и с обрезкой: на каждом ключе и без обрезки он множил строку на число ключей, а при ~11 000 молчащих один "" был бы больше потолка у всех членов.

`result.""`: читатель: missing_count больше длины missing — о члене вне списка не знает.

`result.<key>`: только элементы, где получатель в to.

`result.<key>.member`: член-вкладчик (из происхождения отчёта, не из входа).

`result.<key>.item`: <слот>/\<item> для семьи, \<item> для одиночной строки.

`result.<key>.value`: объект входа как есть (секреты — открыты и запечатаны кольцом держателя, ниже).

`result.order`: entries — по (member, item) в байтах UTF-8; ключи элементов — произвольно (строка хранилища).

`result.at_rest`: секреты value — конверты кольца держателя enc:v2 (договор запечатывания), AAD: ключ строки 0x00 «/\<item строки>» +
JSON Pointer секрета в тексте JSON элемента.

`result.write`: строку переписывать, только если открытое содержимое изменилось.

`result.write`: строку бывшего члена — удалить.

`result.write`: собранная строка больше потолка строки 524288 байт (P/01.1 N1) не пишется: прежняя остаётся, журнал domain.books.too_large
{sub, book, member} раз в проход и view.books.too_large (N1.5), прочие строки, книги и проход идут дальше.

`result.write`: книга в пути двери и в ключе строки — байт в байт, без раскодирования процентов.

`recipient`: элемент доставляется каждому члену из to, который есть в списке членов.

`recipient`: "servers" — членам списка этого прохода, чья Entry class server (нет поля — server), камера не получает ничего и в undelivered не идёт.

`recipient`: имя вне списка не получает ничего
ни в каком виде — оно попадает только в диагностику N1.5 (undelivered).

`grant`: книга с domain.names.<книга>/.grant (N1.7) — ключ доставляется получателю, только если у него есть
действующая строка гранта с subject = key и рангом не ниже grant (договор права, шаг 5, sub — подсистема книги: строка
admin sub: testsub не доставляет ключ книги testsub2; только прямые строки: строки role: и таблица ролей не участвуют,
ключ role:ops не доставляется никому; вход assemble таблицы не получает).

`grant`: у книги с domain.names.<книга>/.grant без гранта получатель видит только "" (missing).

`grant`: у книги с domain.names.<книга>/.grant ключ — имя человека — не доставляется никому (N1.7 reverse).

`cadence`: сборка — в каждом проходе держателя (глава 8.1 N3), после чтения копий.

`to_all`: манифест объявляет книгу всем: domain.books.<книга>.to = "*" (P/02.1 N1.2b).

`to_all`: поле to входа не читается.

`to_all.parts`: строка на раздел ключа: domain/\<sub>/<книга>/*/<раздел>, раздел — 12 бит SHA-256(UTF-8 key), как у членов (P/08.3 N1.1); \<key> — {entries}, "" — {missing: [], missing_count: 0, term, rev}.

`to_all.parts`: ≈ 500 ключей на раздел: предел, сверх потолка строки — write выше.

`to_all.parts`: на получателя в строке нет ничего, поэтому секрета и гранта у такой книги нет.

`to_all.head`: строка domain/\<sub>/<книга>/* — только "": {missing, missing_count, term, rev, stale?, stale_count?}, полнота книги.

`to_all.head`: missing и missing_count — как в result: иначе молчащие камеры переполнили бы строку.

`to_all.head`: голова пишется по концу круга, при отличии, а при смене состава class server в missing — проходом держателя, не дожидаясь конца круга: по концу круга упавший кластер виден резерву через 175–300 с при 250 000 камер против кольца 66 с, проходом — около 53 с при любом домене.

`to_all.head`: первая голова срока — по концу круга, начатого не раньше at записи срока + every срока + TURN_TERM: камера отчитывается раз в every, круг короче, и не слышанный ещё член лишил бы читателей живых дорог, а раздел, обойдённый до срока, терял бы отчёты после него.

`to_all.head`: TURN_TERM 45 с (договор очереди) — окно готовности: слот в окне 503 standby не теряет дорогу. Предел: этот запас делят окно 503 и отставание счёта копии, после копии около 9000 камер съедают его, и их дороги теряются на круг, около 2,5 %.

`to_all.head`: every срока считается один раз при взятии срока, формулой P/08.3 N1.1a из domain/member-count, взятого переносом; пока сбор «из ничего» не закрыт и без счёта — 3600: счёт растёт вместе с отчётами, и срок на момент круга не держал бы ничего; перезапуск считает тем же правилом.

`to_all.head`: срок, а не полнота: молчащий голову не держит, копии держит first.

`to_all.head`: камера с retry_in больше every, потерянный отчёт и смена фазы до 1,5 every к сроку могут не успеть: при 250 000 камер около 1 % дорог на круг, предел.

`to_all.head`: rev растёт только при смене «missing пуст / не пуст», при смене состава class server в missing и, у книги со stale, при смене множества stale (stale ниже): состав молчащих камер поднимал бы всех читателей на каждый круг, а упавший сервер без этого в голове не виден, missing в живом домене почти всегда не пуст; серверов до 500, падают редко.

`to_all.head`: предел: падение одной записи в живом широком члене заметно за 175–450 с при 250 000 камер, с кругом и отчётом; 45 с — обход 576 разделов, широким член считается с 65 разделов.

`to_all.stale`: книга с domain.books.<книга>.stale (P/02.1 N1.2b): голова несёт stale — <член>/<сервер> по ключам \<sub>/heartbeats/<слот> в stale публикации члена (P/09.1 N1.2; так же ставится pulse.\<sub>.stale вида, P/08.1 N1.4), \<sub> — подсистема книги, у членов ok и unseen.

`to_all.stale`: <сервер> — поле server элемента вклада этого слота в копии (у rec — rec/receivers/<слот>): у слота без пульса имени сервера в пульсе нет.

`to_all.stale`: элемент без строкового server — в stale не идёт, журнал без значения.

`to_all.stale`: первые MISSING_SHOWN по байтам UTF-8, stale_count — все.

`to_all.stale`: по подсистеме, а не по серверу: на сервере живой cam при мёртвом rec; сервер мёртв вместе с агентом — член молчит, он в missing.

`to_all.stale`: rev головы растёт при смене множества, и голова пишется сразу при смене, вне круга, а не по его концу: иначе при 250 000 камер около 3 мин против кольца 66 с; до первой головы срока — по правилу first.

`to_all.stale`: предел: смерть видна с задержкой отчёта члена и LOST_AFTER агента; пульс, не дошедший до держателя, делает воркер молчащим и при живом.

`to_all.version`: (term, rev) у каждой строки: term — срок записи, rev + 1 на записи, у головы — head; пара, а не номер: после переноса строки собираются заново.

`to_all.round`: сборка идёт кругом разделов вида (P/08.1 N1.4b), не проходом: для каждого члена раздела снимает ключи из domain/book-keys и кладёт ключи новой копии, в строках их разделов.

`to_all.round`: молчащий член снимается так же.

`to_all.round`: ушедший член — круг идёт и по разделам семьи book-keys: имя, которого нет в строке раздела членов, снимается.

`to_all.round`: строки устаревают на круг: предел.

`to_all.book-keys`: какие ключи член дал, term — срок записи строки; раздел ключа по имени члена не найти, а память процесса старт не переживает.

`to_all.book-keys`: вне копии, пересобирается, как строки.

`to_all.unique`: книга to: "*" при pick: unique — отказ каталога (P/02.1 N1.4): строка не хранит проигравшего вклада, ключ мигал бы по кругу.

`to_all.first`: пока голова /* текущего срока не записана, book_stale раздела не называет, а дверь отвечает 503 unavailable: копия держится; иначе новый держатель снимал бы копии всех читателей, книга без вкладов снова заменяла бы полную.

`to_all.first`: голова, а не complete: молчащий член держал бы дверь закрытой навсегда, а малый домен закрывал бы круг раньше первой сборки.

`to_all.first`: предел: пока головы нет, новый читатель без копии получает 503, новая камера без дорог; это every, окно готовности и до двух кругов, при 250 000 камер до 1545 с, после сбора «из ничего» около часа.

`to_all.first_pass`: пока голова текущего срока не записана, круг строит с нуля: book-keys со term меньше текущего не читается, своего срока читается, строка книги пишется целиком.

`to_all.first_pass`: с записью головы строки со term меньше текущего удаляются: у нового держателя под теми же ключами лежат копии, а снять их ключи нечем.

`to_all.first_pass`: предел: читатели кластера нового держателя видят неполные строки до записи головы.

`to_all.order`: сначала строки разделов, book-keys последней: падение между ними повторяет снятие вхолостую, а обратный порядок потерял бы его.

`to_all.order`: пока голова текущего срока не записана, наоборот, book-keys раньше строк: снимать там нечего, а ключ строки без book-keys снять нечем до следующего переноса, одного term мало.

`to_all.ceiling`: строка book-keys больше потолка 524288 байт не пишется такой: потолок — на раздел членов, около 10 тыс. ключей всех его членов вместе.

`to_all.ceiling`: вклады снимаются с конца, по имени члена в байтах UTF-8 от большего, пока строка не вместится, обычно один: снятый — в missing со словом bad_contribution, журнал domain.books.too_large {sub, book, member} на каждого снятого, резервы пишет только его кластер.

`to_all.ceiling`: порядок по имени, а не по размеру: тот же член снимается на каждом круге.

`to_all.ceiling`: порог: строка book-keys больше NEAR_CEILING байт (80 % потолка) — журнал domain.books.near_ceiling {sub, book, part, bytes} раз в проход и view.books near_ceiling (N1.5).

`to_all.ceiling`: приём сервера в раздел, чья строка book-keys больше NEAR_CEILING, — 409 (глава 8.3 N3 «принять члена» шаг 5a).

`to_all.ceiling`: рост уже принятого кластера назначениями дверь /domain/placement не останавливает: отказ назначения оставил бы камеры без записи; переполнение — предел.

Договор запечатывания — [`Platform/common/contracts/sealing.md`](../../../common/ru/contracts/sealing.md) (конверт `enc:v2`, путь AAD, грамматика `kid`).

Открытие секрета вклада — [договор конвертов домена](../../../common/ru/contracts/domain-envelopes.md) «Конверт `x25519:v1`»
(ключ приёма книг — `domain/book-seal`, глава 8.2).

Действующая строка гранта и ранг — [договор права](../../../common/ru/contracts/may.md)
шаг 5 и строка гранта [P/08.4 N1.3](08.4-domain.norms.md).

Форма входа (`entry`: `key`, `to`, секреты `*_secret`) — [договор конвертов домена](../../../common/ru/contracts/domain-envelopes.md) «Вклад».

Вход в отчёте — объект (`in_report`, P/09.1 N1.2).

### N1.4 Доставка члену

```yaml
carry:        sealed.books (m1)
mask:         значение секрета книги
```

`carry`: ответ держателя (P/08.3 N1.5) несёт книги в sealed (конверт m1) полем books — форма: договор
конвертов домена «Содержимое sealed».

`mask`: значение секрета книги не попадает ни в дверь (дверь книги консоли кластера, OpenAPI урока 6), ни в журнал, ни в вид
(P/06.2 N1.4).

Книга `to: "*"` идёт не в `sealed` и без просьбы до члена не доходит.

Читатель книги `to: "*"` объявляет `domain/<sub>/<книга>/` в `worker.reads` и кладёт просьбу `domain/book-want/<sub>/<книга>/<раздел>`.

Агент держит копии разделов просьб `domain/book-want/<sub>/<книга>/<раздел>` под тем же ключом `domain/<sub>/<книга>/*/<раздел>`, копию растят правила члена, а не домен.

Публикация называет `book_parts` — версии того, что агент держит, и `null` просьбы без копии, `carry.book_stale` — что устарело или появилось: сравнение как у `members_rev`, версия на всю книгу подняла бы всех читателей на каждую смену.

Широкий член несёт окно `BOOK_PARTS_SHOWN` раздела по кругу, судятся только они: цена постоянна, отставание широкого члена — минуты.

После переноса устарели все разделы, 4096 при `BOOK_PARTS_PASS` за проход — около 43 мин: предел.

Просьба живёт сроком: читатель обновляет `at` раз в `BOOK_WANT_EVERY` с, пока раздел нужен.

Агент считает просьбу снятой при `now − at > BOOK_WANT_TTL` с и снимает строку сам: читатели делят строку раздела, поэтому снимать её никому из них нельзя.

Берёт агент разделы дверью `GET /api/book/<член>/<sub>/<книга>[/<раздел>]` ([глава 8.3](08.3-domain.norms.md) N2), без раздела — голову; секретов в них нет.

HTTP-формы владельца `HolderBookHeadBody` и `HolderBookPartBody` двери `GET /api/book` несут под items сырые строки KV без разбора или нормализации внутреннего JSON; правила ключей и содержимого семей не меняются.

Читатель кладёт просьбу на любом кластере.

Агент кластера держателя просьбу не исполняет: ключи те же, читается строка держателя.

Смена срока от читателя ничего не требует: строки бывшего держателя становятся копиями, судятся через `book_parts`, строки без просьбы агент снимает.

Читатель кладёт просьбы и при своём старте: часы агента, прыгнувшие вперёд, снимают просьбы сразу, это предел.

Строка книги у члена (`member_row`: элементы как получены, секреты — конверты кольца члена; писатель — агент) — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) (N1.4
`member_row`).

У кластера держателя копии книги (`member_row`) нет: держатель в `sealed` себе книг не шлёт и свою книгу читает из строки
`domain/<sub>/<книга>/<себя>`.

Конверт `m1` — [договор конвертов домена](../../../common/ru/contracts/domain-envelopes.md) «Конверт `m1`».

### N1.5 Вид: поле `books`

```yaml
domain/view.books:   {"<sub>/<книга>": {conflicts, dropped, undelivered}}
  conflicts:   [<key>…]
  dropped:     {<член>: bad_contribution | secret_unopened}
  undelivered: {<член-вкладчик>: [<имя вне списка членов>…]}
  person_names: [<key>…]
  too_large:   [<член>…]
  too_large_count: <число>
  near_ceiling: [<раздел>…]
  near_ceiling_count: <число>
```

`domain/view.books`: каждая собираемая книга каталога.

`domain/view.books`: too_large, too_large_count, near_ceiling, near_ceiling_count — только при непустом.

`view.books.<sub>/<книга>.conflicts`: ключи unique с двумя вкладами и больше, по возрастанию.

`view.books.<sub>/<книга>.dropped`: снятые вклады (без значений и секретов).

`view.books.<sub>/<книга>.undelivered`: получатели to, которых нет в списке, по возрастанию.

`view.books.<sub>/<книга>.person_names`: у книги с domain.names: ключи — имена людей, не доставлены (N1.7).

`view.books.<sub>/<книга>.too_large`: члены, чья строка больше потолка и не записана, застыла прежняя (N1.3 write), первые MISSING_SHOWN, class server первыми; у книги to: "*" — */<раздел>; иначе причины не видно администратору.

`view.books.<sub>/<книга>.too_large_count`: все такие строки.

`view.books.<sub>/<книга>.near_ceiling`: у книги to: "*" разделы членов, чья строка book-keys больше NEAR_CEILING (N1.3 ceiling), первые MISSING_SHOWN по возрастанию; тревога администратору до переполнения: рост назначениями не останавливается.

`view.books.<sub>/<книга>.near_ceiling_count`: все такие разделы.

Объект `domain/view` и прочие его поля — [P/08.1 N1.4](08.1-domain.norms.md).

### N1.7 Индекс имён

```yaml
manifest:  domain.names.<книга>/: {exclusive_with: domain/users, grant?: view | edit | admin}
subject:   <key>
domain/names/<sub>/<книга>:
  items:   "" → JCS {missing: [<член>…], missing_count}; <key> → JCS {members: [<член>…]}
  missing: [<член>…]
known:     missing_count 0
checks:    409 name taken | 400 grant too wide | 503 names unknown | 400 unknown subject
reverse:   view.books.<sub>/<книга>.person_names
delivery:  rank(cap) ≥ rank(grant)
no_grant:  domain.names.<книга>/ без grant
```

`manifest`: <книга> — книга того же манифеста с from (P/02.1 N1.2b); иначе, или exclusive_with нет либо другое, или grant
не из слов, или иной ключ — refused:reference (P/02.1 N4; случаи m59_names_* корпуса P/02.1 (только для судьи: случаи корпуса вердиктов P/02.1; проверяют P/08.5-R145)).

`subject`: значение key вклада этой книги.

`domain/names/<sub>/<книга>`: у держателя; писатель — процесс domain после сборки книг прохода (N3 «сборка книги»).

`domain/names/<sub>/<книга>.items`: \<key> → {members} — по возрастанию, из всех читаемых вкладов,
включая спорные unique и недоставленные.

`domain/names/<sub>/<книга>.items`: значений и секретов нет.

`domain/names/<sub>/<книга>.missing`: как missing книги N1.3 — члены, чьих вкладов нет из-за них (silent, never, no_copy, bad_contribution,
secret_unopened).

`domain/names/<sub>/<книга>.missing`: член unseen — не missing: его вклад в книге есть.

`domain/names/<sub>/<книга>.missing`: обрезка как у книги (N1.3 result): первые MISSING_SHOWN, class server первыми, missing_count — все: без неё стена около 26 000 молчащих.

`known`: индекс есть, читается и его missing_count 0.

`checks`: у дверей людей и грантов (процесс domain), по индексам всех names каталога.

`checks`: POST /domain/users с именем — subject индекса → 409 name taken.

`checks`: новая строка гранта (нет в прежней строке) с subject индекса и rank(cap) > rank(grant) → 400 grant too wide;
subject — человек домена — проверок индекса нет: человек сильнее ключа индекса; прежняя строка «шире»
не проверяется.

`checks`: новый человек или новая строка гранта (нет в прежней строке), чей subject не человек домена (нет в
domain/users), а индекс не known → 503 names unknown, detail — «missing members: <члены>» или «index
absent or damaged».

`checks`: новая строка гранта, чей subject не человек домена, индексы known, а такого key нет ни в одном индексе →
400 unknown subject; строки, что были в прежней строке, не проверяются.

`checks`: строка гранта человека домена (и root) индекса не ждёт: имена исключают друг друга
(exclusive_with), человек ключом индекса не бывает.

`checks`: каталог без книг с domain.names — индексов нет: все known и пусты; новая строка гранта, чей subject не
человек домена, — 400 unknown subject, не 503.

`checks`: удаление человека и снятие строк — никогда не ждут.

`reverse`: элемент книги с names, чей key — имя человека, не доставляется никому: поле вида view.books.\<sub>/<книга>.person_names
[\<key>…] по возрастанию (N1.5).

`reverse`: person_names нет в отчёте функции assemble — её вход без людей.

`reverse`: человек здесь — имя из списка domain/users, нечитаемая строка человека тоже человек.

`reverse`: список domain/users не прочитан — книга с names в
этом проходе не собирается, её строки и person_names прежние, журнал без значения: имя человека не уходит членам.

`delivery`: N1.3 grant — у получателя строка гранта с subject = key, rank(cap) ≥ rank(grant), действующая (договор права, шаг 5, sub — подсистема
книги, из domain/names/\<sub>/<книга>; только прямые строки).

`delivery`: grant too wide сравнивает только ранг: строка с sub уже строки без него.

`no_grant`: names без grant — ни предела ширины строки, ни условия доставки: ключ доставляется по to, как у книги без
names; reverse действует.

Двери людей и грантов, где стоят `checks`, их порядок шагов (проверки имён — шаг 6 «двери людей», шаг 4 «грантов») и
строки N4 `name taken`, `grant too wide`, `unknown subject`, `names unknown` — [P/08.4 N3, N4](08.4-domain.norms.md).

`rank` — порядок
`cap` строки гранта ([P/08.4 N1.3](08.4-domain.norms.md)).

Человек и `domain/users` — [P/08.4 N1.1](08.4-domain.norms.md).

### N1.8 Общие папки

Папка — одна на домен, гранты `folder:<id>` живут у всех кластеров.

Строка единицы стоит на члене, поэтому пары «папка + членство» одним пакетом нет: строка папки и строка членства — у держателя, цель членства судится стражем, копия у члена только для чтения.

Без связи с доменом папку и членство не правят: отказ, а не расхождение, которое потом пришлось бы сливать.

```yaml
domain/folders/<id>:      {name, parent, deleted?, at, by, revision}
  id, name, parent, deleted: P/06.8 N1.1, N1.2
  counts:   domain/folder-counts/<id>: {<член>: <число>}
domain/memberof/<член>/<sub>/<rows>/<id>: {folders: [<id папки>…]}
domain/folder-units/<id>/<раздел>: {units: [<член>/<sub>/<rows>/<uid>…]}
domain/folder-units/<id>: {parts: [<раздел>…]}
domain/folder-rev:        {term, rev}
state:    P/08.8 N1.5
doors:    GET /domain/folders → 200 {rev, folders: [{id, name, parent, revision, index}…]}
          POST /domain/folders {name, parent?} → 201 DomainFolderView, ETag; PUT /domain/folders/<id> {name} → 200 DomainFolderView, ETag; DELETE /domain/folders/<id> → 200 {deleted: <id>}, ETag
          GET /domain/memberof/<член>/<sub>/<rows>/<id> → 200 {folders, index}
          PUT /domain/memberof/<член>/<sub>/<rows>/<id> {folders} → 200 {folders, index}
          GET /domain/folders/<id>/units[?cursor=&limit=] → 200 {units: [{cluster, sub, rows, id}…], cursor?}
          Idempotency-Key, If-Match
rights:   wide, cap = admin; target, may
member:   FOLDERS_PER_UNIT_MAX
limits:   FOLDERS_MEMBERS_MAX, FOLDER_ROW_MAX, DOMAIN_FOLDERS_MAX
carry.gone_seen: [<ссылка>…]
domain/folder-log:  [{rev, op, id?, ref?}…]
carry.folders: {rev: {term, rev}, full?, folders: {<id>: {name, parent} | null}, memberof: {"<sub>/<rows>/<id>": [<id папки>…]}}
  when:   domain/folders-state
  scope:  chains | all
domain/folders-state:     {rev, scope: all | chains, gone: [<sub>/<rows>/<id>…], own?}
  gone:   [<sub>/<rows>/<id>…]
  own:    {folders: [{id, name, parent}], memberof: {<ссылка>: [<id папки>…]}}
reap:     <проход держателя>
leave:    <копия только для чтения>
```

`domain/folders/<id>`: у держателя; писатель — процесс domain.

`domain/folders/<id>`: id, name, parent, deleted — как P/06.8 N1.1, N1.2.

`domain/folders/<id>.parent`: родитель задаётся при создании.

`domain/folders/<id>.deleted`: запись поверх надгробия — отказ.

`domain/folders/<id>.parent`: "" — корень домена.

`domain/folders/<id>.counts`: из строки вынесено: domain/folder-counts/\<id>: {<член>: <число>}, считает проход.

`domain/folders/<id>.counts`: строгий предел — строка раздела индекса domain/folder-units.

`domain/memberof/<член>/<sub>/<rows>/<id>`: у держателя; писатель — процесс domain.

`domain/folder-units/<id>/<раздел>`: индекс папки по единицам, раздел — 12 бит SHA-256(UTF-8 ссылки), по возрастанию.

`domain/folder-units/<id>/<раздел>`: у держателя; писатель — процесс domain, тем же пакетом, что domain/memberof: domain/memberof ключевана членом, обратного пути нет.

`domain/folder-units/<id>`: голова: непустые разделы папки, иначе обход 4096 пустых.

`domain/folder-units/<id>`: голова пишется тем же пакетом, только при переходе раздела пуст ↔ непуст: числа — у domain/folder-counts.

`domain/folder-units/<id>`: строка раздела не вмещает ссылку — 409 too many members.

`domain/folder-units/<id>`: конфликт CAS — перечитать, до 3 раз.

`domain/folder-rev`: пара: растёт с каждой записью двух семей, term — срок держателя.

`domain/folder-rev`: равенство копии — обе части, после переноса копия заведомо устарела.

`state`: три семьи — в state резервной копии (P/08.8 N1.5): у членов дерева целиком нет, копии источником не служат.

`state`: индекс domain/folder-units собирает восстановление P/08.8 N1.8 шаг 7 из строк domain/memberof.

`doors`: GET /domain/folders → 200 {rev, folders: [{id, name, parent, revision, index}…]} по id, index — для If-Match.

`doors`: GET /domain/folders: вход — договор права gate.

`doors`: GET /domain/folders: консоль домена отвечает сама.

`doors`: GET /domain/folders: счётчики не выдаются.

`doors`: POST /domain/folders {name, parent?} → 201 DomainFolderView, ETag.

`doors`: PUT /domain/folders/\<id> {name} → 200 DomainFolderView, ETag.

`doors`: DELETE /domain/folders/\<id> → 200 {deleted: \<id>}, ETag надгробия.

`doors`: DomainFolderView — {id, name, parent, revision, index}, без внутренних counts.

`doors`: GET /domain/memberof/<член>/\<sub>/\<rows>/\<id> → 200 {folders, index}, строки нет — {folders: [], index: ""}: нужно составу папок (deviceIds) чужой единицы.

`doors`: GET /domain/memberof/<член>/\<sub>/\<rows>/\<id>: консоль домена отвечает сама.

`doors`: GET /domain/memberof/<член>/\<sub>/\<rows>/\<id>: право — view target этой единицы.

`doors`: PUT /domain/memberof/<член>/\<sub>/\<rows>/\<id> {folders} → 200 {folders, index}, без ETag.

`doors`: PUT /domain/memberof/<член>/\<sub>/\<rows>/\<id>: пустой список снимает строку и возвращает index "".

`doors`: PUT /domain/memberof/<член>/\<sub>/\<rows>/\<id>: только индекс хранилища, без счётчика revision.

`doors`: GET /domain/folders/\<id>/units[?cursor=&limit=] → 200 {units: [{cluster, sub, rows, id}…], cursor?}: порядок сервера, limit до 1000, умолчание 200.

`doors`: GET /domain/folders/\<id>/units: cursor — <раздел>:<ссылка> места, правки между страницами его не сбивают.

`doors`: GET /domain/folders/\<id>/units: страница читает голову и не больше 8 строк разделов.

`doors`: GET /domain/folders/\<id>/units: консоль домена отвечает сама.

`doors`: GET /domain/folders/\<id>/units: страницу целиком судит только wide договора права, зритель домена: грант на папку лежит у одного кластера, а строка unit: закрывает единицу и под ним; иначе view target каждой единицы, как GET /domain/memberof, не больше UNITS_PAGE_CHECKS проверок на страницу, недоступные отсеиваются, исчерпание — короткая страница с cursor.

`doors`: GET /domain/folders/\<id>/units: страница бывает короче limit и пустой при непустой папке: конец — только отсутствие cursor.

`doors`: GET /domain/folders/\<id>/units: плохой cursor — 400; папки нет — 404.

`doors`: Idempotency-Key — необязательная память повторов на всех четырёх пишущих операциях папок/членства.

`doors`: If-Match — игнорируется POST создания; обычный optional revision/index у PUT/DELETE папки, только optional-index у PUT членства (P/08.0 N1.9).

`doors`: устаревшее условие ничего не пишет: папки — 412 RevisionMoved, членство — 412 IndexMoved.

`doors`: повтор судится раньше старого условия.

`doors`: DELETE папки пишет надгробие и revision + 1, а не удаляет строку.

`doors`: прочие отказы и слова — P/06.8 N4.

`rights`: дерево (POST, PUT, DELETE папки): wide договора права с cap = admin.

`rights`: папка общая на все кластеры, строка одного кластера не решает за другие; администратор кластера дерево не правит: предел.

`rights`: членство: на U — target с кластером <член>, cap admin; над F и G — may по domain/grants/<член>, unit — папка-объект; chains — из этих строк; таблица P/06.8 N3 «права папки» в этой части.

`member`: цель: член в domain/member-rows/<раздел>, \<sub>/\<rows> — манифест с display.tree.folders: true, каждая папка жива (стражи строк папок и цепочки), не больше
FOLDERS_PER_UNIT_MAX.

`member`: есть ли единица, домен не знает: снимает связь gone ниже.

## N3 Проход

### сборка книги (держатель, в проходе главы 8.1 N3)

1. Для каждой собираемой книги каталога: члены списка (P/08.3 N1.1) с их состоянием вида и копией.

2. Член silent | never | без копии → missing (why — состояние или no_copy), вклада нет.

   На шаге 2 метка есть, а её поколение не читается (P/08.3 N3 «прочитать копию») — no_copy, хотя вид зовёт такого члена silent: причина ближе — копии нет
   (функция assemble: copies[член] = null — no_copy, вектор assemble-08-states (только для судьи: строка таблицы вектора `vectors/assemble/cases.tsv`; проверяет P/08.5-R263, P/08.5-R264, P/08.5-R266 и P/08.5-R038)).

3. Член ok | unseen: объекты копии по from книги.

   На шаге 3 unseen → в missing (why: unseen).

4. Каждый вход: проверить форму входа (договор конвертов домена «Вклад» entry; объект в отчёте — P/09.1 N1.2 in_report) у всех
   элементов вклада члена; ошибка → bad_contribution: весь вклад члена снят.

   На шаге 4 затем секреты — открыть (договор конвертов домена «Конверт x25519:v1», seed — domain/book-seal), не открылся →
   secret_unopened: весь вклад снят.

   На шаге 4 форма раньше секретов: элемент с секретом, который не открылся, и элемент не по форме — bad_contribution.

4a. При unique — элементы одного key у одного члена: равенство по JCS значения с открытыми секретами (конверты одного значения различны): равные — один вход, item наименьший в байтах UTF-8; неравные → bad_contribution: весь вклад снят.

   На шаге 4a один key под двумя слотами — обычное дело: новый первый воркер пишет, пока слот прежнего ещё держат, и снимать за это вклад незачем; предел: значение сменилось в этом окне — вклад снят, пока строка прежнего слота не уйдёт.

5. Ключи: unique — один вклад на key, иначе конфликт (ключа нет); all — все.

6. Для каждого члена списка: элементы, где он в to; гранты (N1.3 grant, N1.7); строка domain/\<sub>/<книга>/<член> по N1.3 result.

7. Записать изменившиеся строки (секреты — кольцом держателя), удалить строки бывших членов.

   На шаге 7 view.books — N1.5, too_large — по исходу этого шага.

После сборки книг прохода — индекс имён каждой книги с `domain.names` (N1.7 `domain/names/<sub>/<book>`).

### доставка (держатель, в ответе агенту главы 8.3)

Держатель: прочитать domain/\<sub>/<книга>/<член> каждой книги каталога, открыть секреты кольцом → sealed.books (m1).

Держатель: секрет не открылся — как нечитаемая строка: эту книгу этому члену в этом проходе не нести, причина в журнал без значения, прочие книги идут.

Запись у члена (агент: открыть `m1`, каждую книгу — в `domain/<sub>/<книга>` по CAS, книги, которой нет в ответе, не
трогать) — [глава 9.1](../../../09-agent/ru/spec/09.1-agent.norms.md) (N3 «запись у члена»).

**Гонки.** Сборка читает копии в разные моменты (глава 8.1): книга — наблюдение.

Захват слота и запись воркера под стражем —
[P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md) N3: поздняя запись бывшего держателя отсекается стражем, пережившая строка — чисткой при захвате и фильтром живости
агента.

Две сборки одной книги не пересекаются: держатель один ([P/08.8](08.8-domain.norms.md)).

Обрыв на шаге 7 сборки — часть строк книги нового
прохода, часть прежнего, `view.books` прежний: следующий проход пересобирает из копий и дописывает отличия (запись только
при изменении); доставка до того несёт строку как есть — у члена книга одного из двух проходов, не смесь внутри строки.
