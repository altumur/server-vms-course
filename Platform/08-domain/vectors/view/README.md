# Векторы вида домена и теневого отчёта

Векторы функции `view` [главы P/08.1](../../spec/08.1-domain.norms.md): проход держателя без хранилища, сети и стенда —
вход — проходы держателя по порядку, вывод — вид домена и теневой отчёт последнего прохода (Н1.3–Н1.6, Н3 «проход
держателя»; Н2 «Команда `view`»). Владелец — урок P/08, глава 8.1; функцию исполняет процесс `domain` (проход раз в
`VIEW_EVERY`). Байты пишет «Спецификация» (ADR-0083); соответствие продукта — его приёмкой по этой таблице (ADR-0080
доп. 16).

Строки переложены из шагов приёмки М11/01
(сц. 01–16, 28 шагов; команда `view` на `inputs/*.json`) при переносе урока 8 (план переноса урока 8, § 3 и В1; решение
«Архитектора» 2026-10-20, ADR-0083 доп. (14)). `case` — имя файла входа, `note` — сценарий и шаг приёмки М11/01. Вход —
JSON файла одной строкой: сняты только незначащие пробелы вне строк; порядок ключей, лексемы чисел (`1.0`, `100.25`) и
значения — как в файле. Ожидание — подмножество шага приёмки как есть (после `ok `). Сценарии М11/01 и их входы сняты
переносом урока 8 (каталог М11/01 снят): таблица — единственный источник этих случаев.

## Прогон

Без стенда: команда `view` реализации получает вход (колонка `input`) и печатает JSON `{view, shadow}`; `expect` —
подмножество полей вывода по словарю «Стенда» ([общий README приёмки](../../../common/acceptance/README.md), `<код>
<JSON>`: названные поля есть и равны, массив — по длине, порядку и элементам, число — по значению) или `@exit 2` (вход не
по форме `ViewInput`). Каждая строка — отдельный запуск на свежем состоянии: память теневого отчёта между строками не
переходит. `as_of` вывода — стенные секунды процесса команды, не сравнивается.

## Входы и манифесты

Форма входа — `ViewInput`, вывода — `ViewOutput` ([контракт урока](../../spec/08-domain.api.openapi.yaml)): `manifests` — манифесты каталога,
`holder` — имя держателя, `passes` — проходы; в проходе `at` — монотонные секунды держателя, `members.<член>` —
`{mark, stale?, objects}` (`mark` — `rev` метки `reported` или `null`, `stale` — поле `stale` метки, `objects` — пульсы
`<sub>/heartbeats/<воркер>` и шарды `<sub>/snapshot/<шард>` копии), `placements` — назначения
`{<sub>: {<ref>: <член> | {cluster, copies}}}`. Смену метки и пульса держатель видит между проходами входа; первый проход
— первый взгляд.

Вход — пульсы после чтения по семье `heartbeats` (P/03.4): форма входа — эта, не семья; пульс без `instance` или с
`worker` из ключа — положительный вход, строки с ним остаются положительными (P/08.1 Н1.4; решение «Архитектора» 2026-10-20 (Go М11-01 № 7; семья heartbeats, разбор ревью стадии B 6–7, № 14, № 15)).

Ожидания зависят от байтов манифестов каталога (разбор ревью стадии A 8–10, № 37): `domain.ref`, `domain.view`, `unit.rows` и
`unit.id` манифестов `testsub` и `testsub2` из данных спецификации:

## Файлы

UTF-8, LF, поля через TAB; строки с `#` и пустые пропускаются, первая непропущенная — заголовок.

| Файл | Вход → ожидание |
|---|---|
| [`cases.tsv`](cases.tsv), 28 строк: 15 только `view`, 11 только `shadow`, 2 оба | `input` — вход команды `view` текстом JSON → `expect` — подмножество `{view, shadow}`: члены `ok`/`unseen`/`silent`/`never` и `age` (LOST_AFTER 45/46, пропажа и возврат метки, уход и возврат члена, округление 0.25 → 0.3), единицы `live`/`stale`/`configured`/`silent`, `contested`, `complete`, дубль id, смена пульса по JCS, элемент пульса без строки шарда; находки `lagging`, `stalled` (SHADOW_STALL 60/61), `orphaned`, `unmanaged`, `conflict` (исполнители `cluster` и `copies`, два воркера одного члена), `stale_epoch`, `unknown`, `clean_streak` и `may_write` |

Случаев `@exit 2` в таблице нет (их не было в приёмке М11/01); вход не по форме — чтением Н5 главы.

Векторы проверены оракулом по тексту норм главы 8.1 (Н1.3 `member_state`, `unit_state`; Н1.4; Н1.6; Н3), не по коду
реализаций: все 28 ожиданий — подмножество его вывода. При расхождении прав норма, вектор правит «Спецификация».
