## Подготовка

Как README приёмки [главы 8.3](../3/README.md) («Стенд», «Подготовка каждого
сценария»; прежде — README приёмки М11/03): раннер поднимает на одной машине три кластера — `hold`, `m1`, `m2`; у каждого своё
пустое хранилище, свой `{data}`, свои сокеты ролей и порты консоли и ресурса, своё кольцо (P/06.2 Н1.2), каталог спек —
только `testsub` (`domain.edit: [start, labels]`, `domain.ref: name`); консоль, контроллер и воркер `w-1` `testsub`, ресурс
своего сервера (`srv-hold`, `srv-m1`, `srv-m2`). Единиц нет. Домена нет: его ставит директива `@domain` первого шага каждого
сценария. Имя домена — `acme`; файл восстановления — `{recovery}` в каталоге экземпляра.

- `store` у `member <кластер>` — дверь хранилища кластера через `admin.sock` (наблюдение строк домена:
  `domain/placed*` членов, `domain/pending/m1` держателя).
- Часы не ускорять: LOST_AFTER 45 с, REPORT_EVERY 5 с, MARK_REFRESH 22,5 с, VIEW_EVERY 3 с; сроки `@until` взяты с запасом.
- У двери `holder` раннер ставит `Idempotency-Key` и у `PUT`/`DELETE`; `@key(N)` повторяет ключ шага `N`.

## scenarios.tsv

Формат — словарь «Стенда» и словарь домена; ожидание — подмножество полей. `$id` — id хранимой правки из ответа 202.

| № | Сценарий | Шагов | Что |
|---|---|---|---|
| 01 | `placement` | 19 | назначение: пусто; отказы 404/409/400; запись; то же — без новой `rev`; копии у `cluster` и у члена из `copies`, у непричастного — нет (фильтр `records`); удаление — копии сняты; повтор удаления — 404; копия у члена из `origin` |
| 02 | `edit-refusals` | 15 | правка: нет единицы при полном ответе — 404; поле вне `domain.edit`, пустое тело, платформенное поле — 400; секрет — 400; `?cluster=` не член — 404; `contested` — 503; не найдена при молчащем — 503 |
| 03 | `kept-and-applied` | 16 | правка выключенному члену: 202 `kept`, повтор — тот же id, иное тело — 422, `view.pending`; после возврата — применена, исходы `performed`, ждущих 0; `DELETE` двери правки — исход `performed`, единицы нет |
| 05 | `kept-full` | 56 | 50 правок одной единицы ждут выключенного члена, 51-я — 409 `kept_full`; `view.pending` — 50 |
| 09 | `forms-of-edits` | 16 | формы (сверка М11 05–08): `POST` без `cluster` или с числом — 400; `<sub>` не из каталога — 404; `DELETE` с телом — 400; назначение `cluster: ""` — 400, `ref` с `/` — 400, `a%20b` — ref буквально; `asked.path` хранимой правки — с `?cluster=<член>` |

Сц. 09: шаг 14 ставит `Idempotency-Key: a3-asked`, поэтому id правки известен заранее — `e-a5231d61506d`
(`sha256("m1" ‖ 0x00 ‖ "a3-asked")`, Н1.4 id), и шаг 15 читает её `asked.path` в строке `domain/pending/m1`.

Сц. 01 шаги 10–16, 19 и сц. 03 шаги 11–16 наблюдают и сторону агента члена (копии `domain/placed*`, применение правки
через дверь единиц) — пункты главы 9.1 урока P/09 ссылаются на них; исход сценария — назначение и правка держателя
(ADR-0083 доп. (13)).
