# P/08 forms and process seams

This English text is the source; `ru/forms/README.md` is its Russian translation for people, not in the export. Forms express the existing norms.

## Shared holder HTTP forms

The six holder GET replies use only the standard parameter, schema and response components in [the owner OpenAPI](../spec/08-domain.api.openapi.yaml). `Member` and `AgentSignature` are unchanged; `Part`, `BookSub` and `Book` extract the existing exact parameters, and `BackupPartRevision` imports the existing P/06 query form. Keep their original levels, requiredness, headers, decoding, rights, refusal order and holder statuses. A book subsystem string is not silently narrowed to another `Sub` form.

The success components `HolderMembersBody`, `HolderAnywhereBody`, `HolderTopologyBody`, `HolderBackupPartBody`, `HolderBookHeadBody` and `HolderBookPartBody` are the sole HTTP body forms for those operations, with `application/json`. Members uses the existing string `doc` row wrapper, not `MembersDoc` or `MembersAnswer`; topology retains the complete nested body already described by the member copy; the backup is the existing part object. Anywhere and book carry the selected raw KV strings: no decoded alternative or conversion of body `as_of` into a JSON number. Their internal logical values are still checked by their current family codec and procedures.

For anywhere, JCS and SHA-256 apply to the complete parsed outer JSON value with those strings, before parsing the internal `doc` text. Outer HTTP whitespace, key order and equivalent JSON escaping do not change it; different text inside a string can change it even when that text parses to the same inner JSON. The sealed advertisement retains its existing type and meaning. P/09 forwards or copies this same owner wire and later refers to these components; it does not define another set of holder body types. Reference resolution keeps the original owner document base. These source forms do not claim actual HTTP, cryptography, copy IO or generator execution.

## Inputs and constants

[daemon-flags.tsv](daemon-flags.tsv) declares 20 environment inputs and the existing first-admin positional name with the common header. `$NAME` stays environment; commands=domain is the process role. The complete launcher, aliases, catalogue, instance, ring, TLS and address contracts still apply. Operation-time unknown inputs keep their own outcomes. A missing signer row makes the process wait; this form does not turn waiting into a start failure. The logical first-admin invocation denotes the implementation-chosen operator command, with its required person name; it fixes no executable spelling. Its password still comes from stdin under P/08.4 N1.9 (whole UTF-8, remove at most one final LF/CRLF), never from a new flag or environment value.

[runtime-constants.tsv](runtime-constants.tsv) declares 51 positive integer literals, with the common header `name value unit norm meaning`. Units are count, s and bytes. Count means Unicode code points where the meaning says characters. KiB/MiB are converted to exact bytes. Conditional camera formulas, the agent report period and dependent bounds stay in their owning sections; MARK_REFRESH = LOST_AFTER/2 remains a derived fractional duration, without rounding. These constants are not environment settings.

The form is the sole source of locally owned fixed values. VIEW_MEMBERS, REPORT_RATE and BACKUP_RATE have measurement status unmeasured, not a promise of measured throughput. BACKUP_EVERY is max(BACKUP_EVERY_MIN, changed bytes / BACKUP_RATE); MEMBERS_MAX denotes the actual P/01 section-row byte ceiling, never a fixed member count. REVOKED_WORDS selects REVOKED_WORDS_CAMERA or REVOKED_WORDS_SERVER by member class. FOLDER_NAME_MAX, FOLDERS_PER_UNIT_MAX, FOLDERS_MEMBERS_MAX and FOLDER_ROW_MAX are owned by the [P/06 form](../../06-console/forms/runtime-constants.tsv). LOST_AFTER and MARK_REFRESH use the [observation contract](../../common/contracts/observation.md); HISTORY_LINES uses the [alarm history contract](../../common/contracts/alarm-history.md). JSON Schema numeric constraints remain checked carriers of the same values.

Foreign timing and token limits use [the turn contract](../../common/contracts/turn.md), [the local token door contract](../../common/contracts/local-token-door.md), and [P/09 runtime constants](../../09-agent/forms/runtime-constants.tsv) for FRESH_EVERY and SAY_EVERY. A name such as ENTRY_MAX or SERVERS_MAX in a diagnostic template denotes the unpadded decimal form value; its identifier is never emitted as a new wire word. The diagnostic bytes at the current values are unchanged.

In the password hash format, `<PBKDF2_ITERATIONS>` is a closed metavariable bound to exactly one row of this form. It and the hash operand of the [password hash contract](../../common/contracts/password-hash.md) use the value as unpadded ASCII decimal digits; the identifier is never a wire literal, new alias or additional accepted cost.

## Refusal catalogue

[refusals.tsv](refusals.tsv) has 184 rows: the refusals of N4 of the chapters and two explicit first-admin operator failures from N1.9; each row is the projection of one condition onto one operation. The columns cause, outcome, diagnostic and caller carry the text of the norm; where the norm gives only word, outcome and cause (chapters 8.4, 8.7, 8.8 and 8.9), diagnostic and caller are `-`. Word is a normative cell: its indexed tokens are not an arbitrary choice of error or reason. A projection applies under the condition and operation of its norm.

HTTP schemas name existing lesson components. Fields list directly declared required properties; inherited/composed and conditional requirements remain the full OpenAPI and the norms of the row. Native form refusals and operator exits keep the exit rules of their norms. A per-member relay refusal or a later kept-edit outcome is not a new HTTP error. The older-road success has the direct Carry and relay RelayAnswer envelopes selected by the actual operation. Dynamic Retry-After and conditional detail/reason/field remain their complete owning norms, not invented fixed header values. The existing closed error vocabulary remains data/refusal-words.tsv. Norm is a comma-separated nonempty list of existing req anchors of this lesson that state the condition and the outcome of the row.

## Versioned doors

[versioned-doors.tsv](versioned-doors.tsv) is the source of the P/08.0 N1.9 version table: 24 operation projections, including role lines, folders and membership. Its closed header is `method path row revision etag if_match absent_revision norm`, literal TAB. A pair method/path is unique and is an existing operation of the lesson OpenAPI. Every OpenAPI operation declaring ETag or If-Match has a row. The batch row is retained even though it declares neither header. Norm is a comma-separated nonempty list of existing req anchors of this lesson.

Row has three kinds. A literal or template selects the existing version row by its family; a `<name>` placeholder is a capture of this operation's OpenAPI path. The sole exception `<part>` is the member-list shard computed by the ordinary core, not a new door parameter. `-` means no pre-existing version row at creation. `writes[]` means each individual row of a batch, never a store key. Revision is closed to doc.rev, revision, rev or `-`. The value `-` means there is no revision counter, never an implicit zero. The other values name the logical version field of the norm's decoded family, not an arbitrary expression language. Row resolution, missing/unreadable fields and all reference guards remain the ordinary family/core procedure.

Etag is true or false. True means the success ETag is the result index in double quotes, never the revision counter. The actual write/repeat procedure supplies this index; creation with row=- still gives the success header. False means there is no ETag header. DELETE of a member keeps the ETag of its changed member-list row; DELETE of a person/group/role/placement and POST batch do not. The table, not a generic rule by method, selects presence.

If_match is optional, ignored, base-rev or optional-index. Optional validates and judges the optional header by P/08.0-R053, P/08.0-R058, P/08.0-R060 and P/08.0-R064. Ignored does not read it at the creation POSTs or POST batch. Base-rev gives If-Match priority and uses base_rev only without that header; if both are present and incompatible, the existing refusal applies (400 refused, field /base_rev); an index next to base_rev is incompatible as in the norm (P/08.0-R077). These rows must include P/08.0-R006 in norm. The ordinary identity, repeat-memory, row-existence and condition order stays P/08.0-R091, P/08.0-R058 and P/08.0-R060, including a replay that does not judge the former condition anew (P/08.0-R086).

Optional-index accepts an absent header or a double-quoted store index only; `""` matches confirmed absence. An unquoted number is 400 `If-Match is a store index`. It requires revision=`-` and absent_revision=`-`; 412 is IndexMoved with field `/index`, current index (`""` for confirmed absence) and optional current row, without a revision counter. Membership PUT returns `{folders,index}` without ETag; an empty list deletes the membership row and returns index `""`. Unknown reads never become absence. Replay is checked before the former condition, as for the other doors.

Absent_revision is the closed value 0 or `-`. Zero supplies revision 0 only for a confirmed absent selected row, including the first topology/shared write and the other creating/version-counter paths declared by their rows. `-` supplies no absent-row counter: the operation's own creation or missing-row rule applies. A transport error or an unconfirmed read never becomes revision 0. For writes[] this policy is per write. Row=- and writes[] are distinct even when If-Match is ignored.

The metadata belongs to core; there is no new KIT_PARTS value.

## Seams and stages

[stages.tsv](stages.tsv) declares 13 stages: foundation, trust, turn, people, admission, view, books, edits, issuing, move, shared, process proof and full acceptance. Every stage is kit=-: none is declared wholly generated. The 49 CALL seams in acceptance/0…10/seams.tsv assist the kit, not lesson acceptance. Chapter norms and ordinary scenarios, all assigned own/common vectors, extra probes and reading remain mandatory. The full domainstand needs the actual processes 08–10; independent algorithms and process 08 may be built before neighbours, but there is no P/08 GREEN before full acceptance.

CALL/JSON is [P/02](../../02-installer/forms/README.md): one JSON input, one JSON result; recursive object subset, exact arrays and exact empty objects. Ports adapt ordinary implementation functions, HTTP and commands; they create no new public API. Never return the expected object as a canned result. A panic, unrelated failure or unexecuted call fails a seam.

Each case has a new temporary root and valid neutral background: catalogue, domain/members/rights, keys and cryptographic proofs, confirmed rows and owned turn unless the intervention changes those facts. Neutral input is not unknown. Fixture words select real data and controlled I/O/clocks/races; ordinary core decisions are not substituted. Counters measure real effects on named target keys, excluding incidental diagnostics. Secrets are test data; expose comparison results, never secret bytes.

The seams `domain-role-http` and `domain-person-login` below and the additional operations of `domain-versioned-edit` use the same actual implementation paths. `domain-versioned-edit` also runs role-lines and folder/membership HTTP operations, reads actual store indexes, and retries the same saved request after a committed lost answer; it never synthesizes revision for membership. Folder deletion is verified against the actual tombstone and its ETag.

`domain-role-http` invokes ordinary authenticated role POST/PUT/GET/DELETE and batch handlers, the real spread pass, the real member copy receiver and its local `may`. Fixtures seed valid neutral users/groups/roles, live folders and confirmed member rows. No fixture bypasses the tested door. Read back actual supervision after each write. Counters observe actual target writes, not only response codes.

`domain-person-login` invokes the real person login and PBKDF2/signature code. An intervention pauses a request after its confirmed credential read, without a common process lock, changes people through ordinary doors and moves both clocks; the real verification then resumes. Output verified iat/exp and flags only, never passwords or JWT bytes.

Handover fixtures use real trusted, signed and sealed backups. Actual restore I/O is suspended and store conflicts are injected at their real boundaries while the process and its ordinary turn renewals remain live; source call-off/disconnect is not a target completion. Observe the I/O history and actual rows/keys/signer. No canned claim, crypto verdict, expected state or lock flag replaces these effects.

Cleanup fixtures fail an actual obsolete-object delete at its real boundary and count real deletion attempts.
