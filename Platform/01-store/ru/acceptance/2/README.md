## Интерфейс профиля

Используется тот же [формат профиля](../../../../common/ru/acceptance/PROFILE.md) `01-store`. `stand.store` запускает хранилище с подготовленным `{rights}` и административным и ролевыми сокетами общего стенда. `keys.role_header` называет заголовок пересылки роли для проб главы. Глава использует готовый файл прав по форме P/01.2-R007 и P/01.2-R008 и не требует команды генерации прав `02-installer`. Своя команда хранилища и флаги предоставляют эти существующие интерфейсы, а не заранее запущенную неизолированную дверь.

## scenarios.tsv

Сценарный файл (только для судьи: `scenarios.tsv` этого каталога, сц. 05–08, 10–16) проверяет P/01.2-R006, P/01.2-R007, P/01.2-R008, P/01.2-R010, P/01.2-R014, P/01.2-R015, P/01.2-R017, P/01.2-R019, P/01.2-R020, P/01.2-R021, P/01.2-R022, P/01.2-R023, P/01.2-R024, P/01.2-R030, P/01.2-R122, P/01.2-R124, P/01.2-R127, P/01.2-R130, P/01.1-R020 и P/01.1-R315. Формат — словарь директив и дверей общего README приёмки: дверь без префикса — хранилище, `@as <роль>`, `@header` перед
методом, `$name`, `ASSERT`; ожидание — подмножество полей, `index` может быть опущен. Своё:

- `expect` без тела у кода `403` — полная форма `{kind: forbidden, error: …}`. Для отказа операции над строкой error называет роль, действие и ключ; в пакете пара — любые действие и ключ из его записей или стражей; у операции со стражем отказ может вместо этого назвать `read` и ключ стража. На `/v1/rights` error называет роль и ещё причину или маршрут: одной роли мало. Для отказа личности — роль сокета и причина запрета заголовка роли (допустимо указать маршрут); ключ строки не требуется, навязанная роль не заменяет роль сокета.

Отсутствующее тело ожидания 200 не означает пустой ответ. Его форму проверяют по контракту
входа главы 1.1; 403 — ровно строки kind/error без полей консоли. `$name` связывается только
после совпадения всего шага; повтор переменной сравнивается с прежним значением. Порядок
ключей в list остаётся порядком хранилища, раннер не сортирует фактический ответ.

Пакет `op: batch` по ролям (P/01.1 N1 `batch`, ADR-0094 B9): роль `console` не знает предела `BATCH_WRITES`, прочие
роли знают; строка и страж без права — ничего не записано; `never` у admin судит каждую строку пакета.

Роли сценариев: `console`, `testsubcontroller`, `testsubworker`, `testsub2worker`, `admin`; роли домена `domain`, `domainagent`, `testsubdomain` (через файл прав, который их называет).

## Изоляция

Каждый сценарий, включая повторный запуск, получает отдельный экземпляр с пустыми
прикладными строками и памятью повторов id. Очистка префиксов не подменяет очистку этой
памяти. Переменные раннера сбрасываются, роль задаётся первым `@as`; файл прав одинаков
во всех сценариях. Параллельные запуски не разделяют экземпляр.

Фоновые консоли, контроллеры, воркеры и ресурс в эти строки не пишут. Данные разрешений
готовит раннер файлом прав стенда по форме P/01.2-R007 и P/01.2-R008 и настройкой экземпляра, а каждый шаг выполняет только
названная роль.

## Проверки вне сценарного файла

- Сверить весь JSON `/v1/rights` с загруженным файлом под admin; иной роли — 403, без
  загруженного файла — 404. Проверить грамматику роли, отсутствие внутренних ролей,
  обязательные массивы, неизвестные поля, delete отсутствует / [] / отдельный список.
  comment отсутствует либо является строкой и возвращается как загружен; число/null/объект
  вместо comment — отказ. Изменение только comment не меняет эффективных прав; --check
  сравнивает по смыслу (P/02.5 N3 «установить»): comment и порядок образцов не сравниваются. Проверить также установленный файл прав реализации.
- Проверить отрицание перед и после разрешения, точный ключ и префикс, звёздочку в
  середине, неизвестную роль, never для admin и обычной роли, отдельное право чтения стража.
  У list нет проверки read; доверие личности остаётся обязательным.
  Для admin и обычных ролей проверить отдельно write/delete platform/epoch_floor;
  соседний обычный ключ не должен попасть в never. Доверенная пересылка admin без файла
  разрешена вне never; с загруженным файлом отказана. Недоверенная пересылка запрещена
  в обоих режимах, включая list. Это отдельные пробы, TSV их не исполняет.
- Нестроковый `comment` — отказ старта, строковый возвращается `GET /v1/rights`; соседние
  с эпохой ключи (`platform/epoch/<y>`, два сегмента после `epoch/`, `<x>/epoch` без `/`) вне `never` у admin.

Это предметы отдельного чтения/структурного теста, а не дополнительные исполненные
сценарии. Режимы сокетов, пересылка и сертификат требуют соответствующего стенда.

Имя X-Configstore-Role в сценариях (только для судьи: `scenarios.tsv`, сц. 08 и 12) — обозначение заголовка доверенной пересылки роли.
Перед прогоном подставить имя из описания реализации (N3/«Решает реализация», п. 3);
значение заголовка и роль сокета не менять. Это не нормативное имя заголовка. При отсутствии
такой настройки подготовка прогона не завершена. Считать запрещённую подмену личности,
а не последующий отказ записи ключа.

## Свойства сц. 11–13

Свойства, проверяемые сц. 11–13 (только для судьи: сц. 11–13 `scenarios.tsv`):
- `never` (N1.3): у консоли 403 неотличим от отказа по правам, поэтому различающая роль — admin: его права
  «всё, кроме never», и без `never` эти записи прошли бы. Чтение пола admin — 200: отказ относится к действию.
- Заголовок пересылки роли у `GET /v1/list` (N3 «проверить»): имя заголовка — обозначение.
- Файл прав (N1.2, N4) директивой `@rights store` (общий README): без файла — `GET /v1/rights` 404; неизвестное поле роли, внутренняя роль
  и неверное имя роли — отказ старта, код 2.
- Не принято: строки вектора `rights-evaluator` (только для судьи: `expect.tsv` пакета) для роли вне файла — сокета роли, которой нет в файле, хранилище не
  открывает, и дверь отказа оценщика не видит; остаётся чтением (P/01.2-04; P/01.2-R010).

## Свойства сц. 14–15

Свойства, проверяемые сц. 14–15 (только для судьи: сц. 14–15 `scenarios.tsv`):
- Края `never` (N1.3) у admin (права «всё, кроме `never`»): `platform/epoch/<y>`, два сегмента после `epoch/`
  и `<x>/epoch` без `/` после `epoch` — не строки эпохи, их
  удаление — 200; реализация, у которой `never` шире нормы, здесь отказывает. Для ролей домена `domain`, `domainagent` и `<sub>domain` (своя семья
  `domain/<sub>/`) `never` сам не запрещает удаление под `domain/`; решают обычные шаблоны `allowed` роли (N1.3, N3); у admin запрет остаётся.
- `comment` файла прав (N1.2): число вместо строки — отказ старта, код 2;
  `GET /v1/rights` admin возвращает строковый `comment` (N2).
