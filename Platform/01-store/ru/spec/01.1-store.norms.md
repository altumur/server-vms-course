# P/01.1 — Словарь операций хранилища: нормы

Канон главы 1.1 урока P/01 «Хранилище» (ADR-0080; модуль «Платформа» — ADR-0083). Повествование для человека —
`ru/01-store.md` (для человека, в выгрузку не входит), оно не норма. Контракт двери — [`01-store.api.openapi.yaml`](../../spec/01-store.api.openapi.yaml). Как по этим
файлам писать реализацию — [`01-store.README.md`](01-store.README.md). Приёмка — [`../acceptance/1/`](../acceptance/1/README.md).
Id норм — `P/01.1-MM`; соответствие прежним id — [`id-map.tsv`](../../../common/id-map.tsv).
Текст производный от `spec/01.1-store.norms.md`, руками не правится: источник P/01.1 — английский [`spec/01.1-store.norms.md`](../../spec/01.1-store.norms.md), правка нормы идёт в него, русский пересобирается переводом (ADR-0120 доп. (1)).

## N0 Словарь слов

Нормативные слова — по канону курса [NORMATIVE-TERMS.md](../../../../ru/NORMATIVE-TERMS.md). Ниже — общие правила M10 и M11,
каждое в своей области (порядок массивов вывода — уроки 8–10).

### Устойчивость выдачи

Общее правило курса (решение «Архитектора» 2026-10-18, сверка python и go M10/6–11: E19, T6, C2, C3). Ответ, который
собирается из многих записей — строк бакета событий, шардов снимка, пульсов, отчётов, строк семьи, — не падает из-за
одной нечитаемой записи. Такая запись пропускается, ответ — 200 с остальными, пропуск считается в поле или ряду, которое
называет урок (`lines_garbled`, `garbled`, `rows_garbled`). 503 или обрыв соединения из-за одной записи — нарушение.

- Нечитаемая запись — не JSON, не объект, не по форме записи урока или не на своём месте.
- Исключение — запись, без которой ответ ложен; урок называет её прямо (например, метка, которая решает исход).
- Урок, который собирает такой ответ, называет счётчик пропусков и даёт шаг: одна испорченная запись — 200 и счётчик.

### Время в строке

Общее правило курса для всех уроков, в том числе M11 (решение «Архитектора» 2026-10-18, пилот хранилища). Время в строке
или объекте хранилища, в строке файла событий и в JSON-тексте внутри строки — **секунды стенных часов Unix** (от
1970-01-01T00:00:00Z) в десятичной записи: целая часть — цифры без ведущих нулей, за ней необязательно точка и цифры
дробной части; без знака, экспоненты и пробелов.

- **Писатель** пишет дробную часть не длиннее 3 знаков: `^(0|[1-9][0-9]*)(\.[0-9]{1,3})?$`. Поле, чья форма —
  `float` [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.2 (штампы таблиц, `sweep.at` там же), пишется ещё и кратчайшей записью.
- **Читатель** принимает любую запись этой формы, с дробной частью любой длины: `^(0|[1-9][0-9]*)(\.[0-9]+)?$`
  (ADR-0083 п. 3: строгий писатель, терпимый читатель).
- В строке хранилища время — строка этой записи. В JSON (объект, текст JCS в строке) писатель пишет число JSON этой записи,
  если форма поля не назвала строку; читатель принимает и число, и строку этой записи.
- Запись не этой формы — поле не по форме; что тогда делает читатель, говорит правило поля. Значение записи конечно в
  binary64: запись этой формы, чьё значение в binary64 не помещается (переполнение), — тоже не по форме; длина дробной
  части по-прежнему любая (MAY-UNTIL-D8-01, решение «Архитектора» 2026-10-25).
- Поля времени каждого урока перечислены в начале его N1 («Time»). В каталоге данных ADR-0083 это общий тип «time».
- Правило не касается чисел во входах и ответах дверей (`sent_at` публикации, `iat` и `exp` токена, `expires` двери,
  `at` в `TableRow`), заголовков (`X-W2C-Time`), меток подписи в миллисекундах и монотонных часов: их форму задаёт своя
  норма. Значение, которое строка лишь переносит из такого входа как есть (`exp` в `domain/revoked`, `sent_at` метки
  приёма), — тоже по своей норме.

### Часы кластера

Предпосылка кластера (ADR-0091 п. 1): стенные часы его писателей — лидера хранилища, контроллера, двери консоли,
воркеров и писателя события, о котором пишет воркер, — расходятся между собой не больше чем на `CLOCK_SKEW` = 60 с.
Нормы опираются на неё (сроки строк с `made` — [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.1
`platform_fields`, [P/03.6](../../../03-worker/ru/spec/03.6-worker.norms.md), [P/04](../../../04-controller/ru/spec/04-controller.norms.md)),
но не проверяют её: синхронизация часов — дело развёртывания, как у держателей домена
([P/08.2](../../../08-domain/ru/spec/08.2-domain.norms.md) `rev.clocks`). Общий ход всех часов назад предпосылку не нарушает:
порядок записей с условиями времени держит время приёма хранилища (N3 «Время приёма»), а не часы писателей.

### Порядок массивов вывода

Область — уроки P/08–P/10 (прежде — модуль M11, все уроки); перенесено из M11/1 N0 без изменения поведения
(разбор ревью стадии A 8–10, № 19 / решение 4).

Порядок массивов вывода — общее правило уроков P/08–P/10 (прежде — модуля M11, всех его уроков; (разбор ревью стадии B 8–10, № 22)): массив имён — членов, кластеров, ключей,
`kid`, `ref`, отпечатков, слов — по возрастанию байт UTF-8, если форма прямо не называет иной ключ; массив объектов — по
ключу, который назван у формы. Порядок отбора (например, хранители [P/08.8](../../../08-domain/ru/spec/08.8-domain.norms.md) N1.5) — не порядок вывода. Вывод — вид,
ответы дверей, функции N5, записанные строки и объекты.

## N1 Форма

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: строк нет — урок задаёт операции хранилища над любыми строками; строки демона хранилища — глава 1.3;
- читает: `/etc/w2c/configstore-rights.json` (права ролей на каждую операцию, P/01.2 N1.2), `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/<role>/server.pem`, `/etc/w2c/tls/<role>/server.key`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem` (дверь вне петли, P/01.3 N1.6).

```yaml
# Строка хранилища. Хранилище — отображение ключ → строка; других сущностей у него нет.
row:
  key:                       # имя строки
    type: string
    rules:
      - not empty
      - does not start with "/"
      - no segment (between "/") equals ".."
      - at most 1024 bytes                     # у двери; реализация на файлах МОЖЕТ отказать раньше (ниже)
    note: одно написание — одно место; ключ, нарушающий правило, — отказ badkey, не починка
    compare: по байтам UTF-8, без нормализации — a//b, a/./b, a/b/ и формы NFC и NFD одного текста — разные ключи
  items:                     # содержимое
    type: map                # string → string; порядок полей не имеет значения
    rules:
      - every key and every value is a string
      - weight (sum of byte lengths of every key and every value) at most the store's ceiling
    ceiling: 524288          # 512 КиБ; тот же потолок — в сводке P/06.1 N1.4 (строка «store row»); иного объявления потолка P/06.1 не вводит
  index:                     # версия
    type: string             # непрозрачна: сравнивается только на равенство
    rules:
      - handed out by the store on every write; never the same twice within one store
      - 'one version per operation: a batch (N3 «записать пакет») hands out one version, and every row it writes gets it; "never the same twice" counts operations, not rows'
      - '"never the same twice" is about versions handed out: a version a write or a delete hands out is not handed out again; a row carried in by import or restore keeps the copy''s version — not handed out by this store, it may equal one handed out before the transfer (P/01.3 N1.3 import; C01-VERSION-ISSUED-01)'
      - '"" names an absent row and is no version'
    wire: десятичное число без знака и ведущих нулей, до 20 цифр, как строка JSON
    note: "форма провода — норма двери (так хранилище выдаёт версии); непрозрачность — норма вызывающего (не разбирает версию, сравнивает только на равенство); хранилище с иной формой версии подошло бы с иной N2, не с иным клиентом"

# Условие записи.
cas:
  absent (поля нет или null): безусловно — пишется поверх того, что есть
  "":                          только пока строки нет (создание; первый выигрывает)
  <версия>:                    только пока версия строки ровно эта

# Условие по другой строке (ADR-0074 доп. 1).
guard:
  key:   string              # строка-страж: обычно слот писателя; те же правила ключа
  index: string              # её версия, "" — страж отсутствует
  note: проверяется в той же операции, что и cas; права на строку-страж — права чтения вызывающего: allowed(role, read, guard.key) (P/01.2 N1.3 guard, N3 «проверить»)

# Условия времени приёма (ADR-0091 п. 1, ред. 11) — у put и delete; время приёма — N3 «Время приёма».
not_after:
  type: number               # секунды Unix; число JSON, сравнивается по значению
  rules: [finite, at least 0]  # finite — конечно в binary64, как время кодека (codec.tsv time; MAY-UNTIL-D8-01): 1e400 — badrequest;
                               # значение, сравнение и отпечаток повтора — по значению binary64 (C01-TIME-NUMBER-EXACT-01)
  meaning: запись журнала применяется, только если её время приёма не позже not_after; иначе expired (N4)
  null: не по форме — badrequest (как id); строка, bool, отрицательное — тоже badrequest
not_before:
  type: number               # секунды Unix; число JSON, сравнивается по значению
  rules: [finite, at least 0]
  meaning: запись журнала применяется, только если её время приёма строго позже not_before; иначе early (N4)
  null: не по форме — badrequest; строка, bool, отрицательное — тоже badrequest
  note: "оба условия МОГУТ стоять в одной записи; писатель пишет число записью «Время в строке» N0"

# Идентификатор записи.
id:
  type: string
  rules: [1 to 64 lowercase hex digits]
  null: не по форме — badrequest; в отличие от cas, null не равен отсутствию поля
  note: "необязателен; клиенту СЛЕДУЕТ ставить его на каждую запись (32 шестнадцатеричных знака случайности): после ответа «неизвестно» безопасен только повтор с тем же id (N4; воркер — P/03.4-07: всякая его запись со значением несёт id, после ambiguous — повтор тем же id)"

# Пакет (ADR-0094 B9, доп. (12) п. 1): отдельная операция, одиночная запись и её guard не меняются.
batch:
  op:      batch
  writes:                    # записи; порядок значим; ключ встречается один раз
    - op:    put | delete
      key:   string          # те же правила ключа
      items: map             # у put обязателен, форма и потолок — row.items на каждую строку; у delete не читается
      cas:   как cas записи  # условие этой строки; поля нет или null — безусловно
  guards:                    # необязателен; поля нет — как []; порядок значим; ключ встречается один раз, и не в writes (условие записываемой строки — её cas)
    - {key, index}           # форма guard
  id:      как id записи     # один на пакет
  not_after, not_before:     # как у записи, одно условие на пакет
  rules:
    - writes не пуст, в нём не больше BATCH_WRITES элементов; в guards не больше BATCH_GUARDS (кроме ролей console и domain, ниже)
    - элемент writes закрыт — ровно поля op, key, items, cas; элемент guards — ровно поля key, index
BATCH_WRITES: forms/runtime-constants.tsv             # предел записей пакета; ровно на пределе — проходит, на один больше — badrequest
BATCH_GUARDS: forms/runtime-constants.tsv             # предел стражей; FOLDERS_DEPTH_MAX + 1 ≤ BATCH_GUARDS (P/06.8 N1.3)
```

У роли `domain` предела `BATCH_GUARDS` нет, остаётся вес тела: стражи ссылок и доказательства растут с составом групп ([P/08.4](../../../08-domain/ru/spec/08.4-domain.norms.md) N3). Пределы `BATCH_WRITES` и `BATCH_GUARDS` — у вызывающих двери, кроме роли `console`: консоль сама держит предел своей пакетной двери
([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N2 «Пакетная дверь») и дописывает к пакету свои строки, а её внутренние
пакеты ограничены весом и пределом тела, не числом строк (ADR-0095 § 2, разбор A1). Вес считается по строкам `writes`, каждая —
против потолка строки; стражи веса не имеют; сумма не сравнивается с потолком, её держит предел тела N2.

Реализация на файлах, где строка — файл с именем из ключа, МОЖЕТ отказать и ключу, который проходит предел двери, если его кодированное имя не помещается в имя файла; свой предел, меньший 1024 байт UTF-8, она называет в своём описании (решает реализация).

Предел относится к **полному ключу** в UTF-8, включая имя подсистемы, семейство и разделители,
и одинаково действует на целевой ключ и ключ стража. Предел отдельного компонента не является
пределом полученного пути: например, имя единицы из 1000 байт даёт `testsub/counters/…` длиной
1017 байт. Общего предела платформенных ключей в 200 байт нет. Допустимая грамматика компонентов
не гарантирует, что полный ключ помещается в выбранное хранилище; отказ — `400 badkey`
по N4, без изменения строки. Применение этого отказа дверью единиц — [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N3–N4, воркером — [P/03.2](../../../03-worker/ru/spec/03.2-worker.norms.md).

## N2 Двери

Сторона клиента — адрес, запрос, формы ответа для вызывающего, исходы и что делать с каждым, обрыв и повтор — [договор
клиента хранилища](../../../common/ru/contracts/store-client.md) (SC-WIRE78-G01 / C08-SDK-06); здесь — сторона двери.
Процесс говорит с хранилищем своего сервера по HTTP с JSON-телами через unix-сокет; на коробке без группы хранилище МОЖЕТ быть открыто в процессе без двери — профиль `file://` «вся коробка — одна реализация» (P/02.4 N1.2), — но его семантика та же, и приёмка гоняется через дверь. Кто такой вызывающий, говорит сокет роли `/run/configstore/<роль>.sock` (P/01.2 N1.1 `identity`).

Контракт двери — файл [`01-store.api.openapi.yaml`](../../spec/01-store.api.openapi.yaml) рядом (OpenAPI 3.1; проверяется загрузкой инструментом). Маршруты: `GET /v1/get?key=`, `GET /v1/list?prefix=`, `POST /v1/write` (`Cmd`: put | delete; `BatchCmd`: batch; `floor` — только на admin-сокете лидера, добавлено P/01.3 N2); схемы `Key`, `Row`, `Listing`, `Cmd`, `BatchCmd`, `Written`, `Fault`; коды — по N4.

Формы ответов закрыты: выдаются только поля соответствующего исхода. `error` обязателен у отказа,
хотя приёмка обычно не сравнивает его текст. Версия в ответе имеет форму N1, а не произвольной строки.

| Ответ | Обязательные поля | Необязательные поля |
|---|---|---|
| читаемая строка | `items` — объект строк, `index` — непустая версия | нет |
| отсутствующая строка | `items: null`, `index: ""` | нет |
| повреждённая строка | `items: null`, `index` — её непустая версия, `unreadable: true` | нет |
| перечисление | `keys` — объект ключ → непустая версия; порядок по байтам | нет |
| запись, удаление или пакет | `index` — выданная непустая версия (у пакета — одна на все его строки) | `again: true` только у сохранённого повтора |
| отказ | `kind`, `error` и поля своей строки N4 | только `size` в отказе тела по правилу ниже |

Схемы ответов привязаны к коду и операции: например, чтение не возвращает `ambiguous`,
а `409` не может иметь `kind: guard`; `conflict` пакета несёт ещё `key` — строку, чей `cas` разошёлся, у одиночной записи `key` нет. Размер `size > limit`, фактические байты и порядок `keys`
проверяются отдельно: одна JSON Schema этих отношений не доказывает.

Повреждённая строка существует и имеет версию: перечисление выдаёт эту версию, страж сравнивает с ней,
запись и удаление с `cas` по ней проходят (P/01.1-17). Версия строки хранится так, что порча тела её не теряет (как —
п. 5 «Решает реализация»); потеря самой версии — порча хранилища, не строки: чтение этого ключа и перечисление, которое
его задевает, — 503 `unavailable` с журналом до починки, не отсутствие и не пропуск (C01-ROW-INDEX-LOST-01, решение «Архитектора» 2026-10-29).

Схема `Key` задаёт написание ключа для чтения, `Cmd.key` и `guard.key`. Байтовый предел N1
проверяется отдельно после кодирования в UTF-8. Отсутствие или нестроковый тип `Cmd.key`,
`guard.key` и параметра `key` чтения — нарушение формы, `badrequest`; пустой `guard.key` — тоже
`badrequest`. Строка, нарушающая правила ключа N1, — `badkey`: у целевого ключа, у ключа чтения
и у непустого ключа стража (N4). Внутри `guard` сначала проверяется форма целиком — объект, ровно поля `key` и
`index`, их типы, форма `index`, пустой `key` — `badrequest`; и только затем правила ключа стража — `badkey`
(`{key: "/x", index: "x"}` — `badrequest`). `guard: null` — не по форме, `badrequest`. Элементы `writes` и `guards` пакета
проверяются так же: `key` записи и стража — форма, затем правила ключа; `guards: null` — не по форме, `badrequest`.

У `POST /v1/write` есть отдельный предел чтения тела — положительное целое число байтов, названное
в описании реализации. Считаются байты HTTP-тела, без заголовков, до разбора JSON; предел не равен
по определению потолку веса `items`. Тело не больше предела проходит к разбору JSON и проверкам N3.
Превышение предела — `413 toolarge` до вызова операции хранилища: строка, версия и память `id` не меняются.
`limit` в этом отказе — предел тела; при превышении веса строки — потолок строки.
Если полный размер тела известен, отказ тела МОЖЕТ содержать `size` с этим размером в байтах;
если неизвестен, `size` отсутствует. `key` при отказе тела не выдаётся: JSON ещё не разбирался.
Настройки приёмки заданы в N5; способ задания предела — выбор реализации.

Лишние поля верхнего уровня команды `POST /v1/write` (вне `op`, `key`, `items`, `cas`, `guard`, `not_after`,
`not_before`, `id`)
принимаются и не читаются независимо от JSON-типа; они не влияют на запись и отпечаток повтора.
Их байты входят в общий размер HTTP-тела. Это правило не распространяется на содержимое
`guard`: его форма закрыта по N1; `items` у put проверяется по N1, у delete не читается по N3.
У `op: batch` лишние поля верхнего уровня — вне `op`, `writes`, `guards`, `id`, `not_after`, `not_before`; среди них и `key`,
`items`, `cas`, `guard` одиночной записи: они принимаются и не читаются. Элементы `writes` и `guards` закрыты (N1).

Маршрут, которого нет, — `404 {kind: badrequest}`. Список кодов и видов закрыт: новый — только правкой этого урока.

### N2.1 Разбор запроса

Разбор одинаков у всех реализаций: на одном входе они дают один код и один вид отказа.

- **Query.** Строка после `?` разбирается как `application/x-www-form-urlencoded`
  ([WHATWG URL, разбор urlencoded](https://url.spec.whatwg.org/#urlencoded-parsing)): пары через `&`, имя и значение
  через первое `=`, `+` — пробел, `%XX` — байт; `%` без двух шестнадцатеричных цифр за ним остаётся как написан.
  Разбор целиком по этому алгоритму: пустые пары (`&&`) пропускаются, параметр без `=` имеет значение `""` —
  `?key` даёт пустой ключ, `badkey` (N1). Клиент передаёт `+` ключа как `%2B`, `%` — как `%25`.
- Порядок проверок query: сначала форма (повтор, отсутствие параметра) — `badrequest`, затем UTF-8 и правила
  ключа N1 — `badkey`.
- Повтор `key` у чтения или `prefix` у перечисления — `400 badrequest`: запрос не по форме. Отсутствие `key` —
  `400 badrequest` (выше); отсутствие `prefix` — пустой префикс, все строки.
- Байты `key` после декодирования не UTF-8 — `400 badkey`: ключ — строка N1. `prefix` — байты после декодирования,
  UTF-8 не требуется (N3 «перечислить»).
- Прочие параметры query, query у `POST /v1/write` и тело у `GET` не читаются; `Content-Type` не проверяется.
- **Тело `POST /v1/write`** — JSON по [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259): повтор имени поля
  в любом объекте тела (§4), `NaN`, `Infinity`, BOM и байты не UTF-8 (§8.1) — `400 badrequest`. Одиночный суррогат
  (`\ud800`) в `key` или `guard.key`, у пакета — в `key` элемента `writes` или `guards` — `400 badkey`: строку не закодировать в UTF-8 и не измерить по N1; в имени
  или значении `items` — `400 badrequest`; в лишних полях он не читается. Числа и строки лишних полей не читаются
  при любой длине. Глубина вложенности — одно число для всех реализаций: `JSON_DEPTH` ([runtime-constants.tsv](../../forms/runtime-constants.tsv)) вложенных объектов и
  массивов от корня, корневой объект — 1, в любом поле, и в лишнем; 129 — `400 badrequest`.
- Тело в `Transfer-Encoding: chunked` меряется по декодированным байтам; превышение предела — `413 toolarge`
  без `size`.
- **Ранний отказ.** Дверь, которая отказывает до чтения всего тела (`Content-Length` больше предела — `413`; любой иной
  отказ до тела), отправляет полный ответ с `Connection: close`, затем читает и отбрасывает присланное, не разбирая, до
  заявленной длины, но не больше объёма и не дольше срока слива, и только после этого закрывает соединение: клиент,
  который ещё шлёт тело, получает ответ, а не сброс соединения. Правило одно для всех HTTP-дверей модуля (консоль —
  [P/06.5](../../../06-console/ru/spec/06.5-console.norms.md) N2 «Разбор запроса консоли», дверь байтов — P/06.1 N2, дверь ресурса — P/05 N2 «Разбор запроса»); объём и срок слива — п. 9 «Решает реализация».
- **Путь** сравнивается с маршрутами N2 байт в байт, без процент-декодирования и нормализации: `/v1/%67et`,
  `/v1/get/`, `//v1/get` и цель в абсолютной форме (`http://host/v1/get`) — не маршруты N2, `404 badrequest`.
- **Метод и HTTP.** Метод или путь вне N2 — `404 {kind: badrequest}` с телом `Fault`, в том числе неизвестный метод
  на известном пути (`PATCH /v1/get`); `HEAD` — тоже `404`, без тела (RFC 9110 §9.3.2). `Host` не проверяется: дверь —
  unix-сокет, и отсутствие, повтор или любое значение `Host` не отказ.
- **Строка запроса и заголовки.** Конец строки — только CRLF: одиночный LF или CR — `400 badrequest`. Пустые строки
  перед строкой запроса — `400 badrequest` (не пропускаются). Цель запроса — только байты 0x21–0x7E без `#`; иной байт
  (в том числе сырой `\x00`) — `400 badrequest`; `%00` — три допустимых байта: путь сравнивается байт в байт, а ключ
  query после процент-декодирования содержит U+0000 и по N1 допустим. Предел заголовков — `HEADER_BYTES` ([runtime-constants.tsv](../../forms/runtime-constants.tsv)):
  сумма длин строк полей без их CRLF и без пустой строки конца; ровно на пределе — разбирается, на 1 байт больше —
  `400 badrequest`; отдельного предела числа строк нет.
- **Рамка тела** — по RFC 9112 §6–7: `Content-Length` — только цифры (`+5`, пробел внутри — `400`); несколько
  `Content-Length` с разными значениями — `400` и закрытие соединения; число длины больше, чем реализация может
  представить, — `413 toolarge` (оно заведомо больше предела тела, `size` нет); размер куска chunked — только HEXDIG
  (`0x5` — `400`); `Transfer-Encoding`, кроме ровно `chunked`, — `400` (`gzip, chunked` и две строки TE — тоже).
  Оборванное тело — EOF раньше `Content-Length` или нет последнего куска chunked — не исполняется: ответа нет,
  записи нет, память `id` не меняется. После любой ошибки рамки дверь закрывает соединение. Строка запроса, заголовки и рамка тела разбираются по
  [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112): obs-fold и пробел перед двоеточием заголовка — нарушение
  разбора (§5.1–5.2); при `Content-Length` и `Transfer-Encoding: chunked` вместе тело читается как chunked (§6.3). Запрос, который не разбирается как HTTP/1.1 или HTTP/1.0 (нет версии, неверная
  строка запроса или заголовок, строка запроса или заголовки длиннее предела п. 9), — `400 {kind: badrequest}`
  с телом `Fault`. Коды 414, 431, 501, 505 и страницы сервера по умолчанию в закрытый список не входят.
- **Порядок проверок команды и пакета** при нескольких нарушениях — таблица
  [`write-checks.tsv`](../../forms/write-checks.tsv) (ADR-0120 п. 2 (а)): строки по порядку, первая нарушенная строка даёт
  код, вид и поля отказа; её входы — [`write-checks.probes.tsv`](../../forms/write-checks.probes.tsv). Таблица читает тело,
  разобранное как JSON по этому разделу, и не читает состояния хранилища (`cas` и `guard` по значению, память `id` — N3).

- **Целое тела** — целое по записи числа: `-?(0|[1-9][0-9]*)`, без дробной части и порядка; `20.0` и `2.0e1` — не целые: отказ формы, 400 `badrequest` (P/01.3 N4 `floor`; ADR-0125 доп. (2)).

## N3 Проход

Словарь, которым написаны все проходы курса. Операция — одно неделимое действие хранилища: между её шагами никто не приходит; всё, что приходит, приходит до или после. В группе серверов «неделимо» значит «одна запись журнала, применённая каждым сервером одинаково»; на одной коробке — «под одной блокировкой» (решает реализация, см. ниже). Пакет, кроме того, неделим и против потери питания: «записать пакет», «Атомарность».

### прочитать(key) → (items, index)

1. Если ключ не проходит проверки N1, вернуть `badkey`.
2. Если у вызывающего нет права на чтение, вернуть `forbidden` (P/01.2 N3 «проверить»: `allowed(role, read, key)`).
3. Если строки `key` нет, вернуть (null, "").
4. Если строка есть, но не читается (N2), вернуть (null, index, `unreadable: true`).
5. Вернуть (копию items, index).

Чтение линеаризуемо: отдаёт состояние не старше последней сделанной записи, которую видел любой вызывающий. В группе это значит, что чтение проходит через лидера текущего срока (продление аренды — чтение, и ведомый, отрезанный от группы, не должен подтверждать эпоху, которую остальные уже сдвинули; [P/03.2 N3 «продлить()» и «подтвердить(id)»](../../../03-worker/ru/spec/03.2-worker.norms.md)). Механизм — решает реализация.

**Гонки.** Чтение между двумя записями видит либо первую, либо вторую, никогда половину. Нет других.

### перечислить(prefix) → {key: index}

1. Для каждой строки, чей ключ начинается с prefix (сравнение байт), выдать её index.
2. Упорядочить ключи по байтам.

`prefix` — любая строка байт, не ключ: правила ключа N1 к нему не применяются, сегмент `..` ничего не значит, пустой префикс — все строки; проверка prefix не даёт 400, кроме повтора параметра (N2.1), и не проверяет право read; перечисление отдаёт все строки под префиксом, в том числе вне прав чтения роли. Личность проверяется до операции по P/01.2 N3 «проверить»: подмена роли или недоверенная пересылка дают 403 forbidden. N2 двери: 200, 403 личности, 404 нет маршрута, 503. Перечисление не требует прав на чтение значений: оно называет имена и версии, не содержимое (ADR-0021). Префиксу СЛЕДУЕТ кончаться на `/`: `testsub/count` совпал бы и с `testsub/counters/…`, и с `testsub/countdown`.

**Гонки.** Запись во время перечисления: строка либо в списке со своей версией, либо нет; перечисление не блокирует запись. Нет других.

### Время приёма

Каждая запись журнала (put, delete, batch, служебная `floor` P/01.3) получает **время приёма** — секунды Unix (ADR-0091 п. 1):

```
admitted := max(часы лидера при приёме записи в журнал, время приёма предыдущей записи журнала)
```

Лидер назначает его, принимая запись в журнал, и хранит в самой записи журнала. Условия `not_after` и `not_before`
проверяются при **применении** записи — по этому хранимому времени, а не по часам применяющего сервера: исход один у
всех серверов группы и не зависит от того, когда запись дошла до применения. Время приёма по журналу не убывает: новый
лидер и перезапущенный демон продолжают от времени приёма последней записи своего журнала (в том числе пришедшей
снимком). Хранилище без журнала — коробка (`box` P/01.3 N1.3) и хранилище в процессе — назначает время тем же правилом
от своего последнего времени приёма и хранит его так же прочно, как строки: под той же блокировкой и тем же барьером
долговечности, что запись (п. 3 «Решает реализация»). Время приёма — часть состояния хранилища и его снимка (P/01.3 N1.3
`admission`); копия `copy` P/01.3 его не несёт: группа после `import` или `restore` начинает от часов своего лидера.
Ответ записи его не выдаёт. Часы лидера, ушедшие вперёд, поднимают время приёма, и записи с `not_after` получают
`expired`, пока часы не догонят; это видно признаком `admission_ahead` (P/01.3 N2 `/v1/status`).
Если часы дают дробные секунды Unix, назначение, хранение и восстановление времени приёма, `max` и сравнения с
`not_after` и `not_before` ДОЛЖНЫ сохранять эту дробную часть. Часы, предыдущее время приёма и границы НЕЛЬЗЯ
округлять до целых секунд для этих операций. Точность или разрешение физического источника часов этим не задаются.

Уже принятый повтор сохраняет вновь назначенное время приёма по этому правилу, даже когда память id возвращает первый ответ без записи бизнес-строки, новой выданной версии или изменения записи памяти применённого id. Оно переживает обычное закрытие/открытие как последние метаданные приёма; откат физических часов его не отменяет.
При времени приёма A условие `not_after` допускает A <= граница и отказывает при A > граница; `not_before` допускает
A > граница и отказывает при A <= граница, в том числе на дробных границах (N1).

**Гонки.** Удаление с `not_before` = T и запись с `not_after` = T одной строки в любом порядке прихода: удаление принято
только при времени приёма > T; всякая запись журнала после него имеет время приёма не меньше, то есть > T, — `expired`;
запись, принятая раньше удаления, стоит в журнале раньше и удалением снимается (её CAS по версии удаления не пройдёт).
Общий ход стенных часов назад порядка не меняет: время приёма не убывает.

### записать(key, items, cas?, guard?, not_after?, not_before?, id?) → index

1. Если ключ или форма cas, guard, id, not_after или not_before не проходит проверки N1, вернуть `badkey` / `badrequest`.
2. Если вес items больше потолка, вернуть `toolarge` (ничего не записано).
3. Если у вызывающего нет права на запись key, вернуть `forbidden` (P/01.2 N3 «проверить»: `allowed(role, write, key)`).
4. Если guard задан, а права на чтение guard.key у вызывающего нет, вернуть `forbidden`.
5. Остальные шаги идут одной операцией, при применении записи журнала.
6. Пусть admitted — время приёма этой записи (выше, «Время приёма»).
7. Если id задан и уже применялся:
   1. Если та запись была иной (op, key, items, cas, guard, not_after, not_before), вернуть `badrequest`.
   2. иначе вернуть его ответ с again=true; бизнес-строки, выданные версии и запись памяти применённого id не меняются. Последнее время приёма всё же продвигается по N3 «Время приёма» (R070), с той же сохранностью, даже когда ответ берётся из этой памяти.
8. Если not_after задан и admitted > not_after, вернуть `expired`; ничего не записано.
9. Если not_before задан и admitted ≤ not_before, вернуть `early`; ничего не записано.
10. Пусть current — версия строки key ("" если строки нет).
11. Если guard задан:
    1. Пусть at — версия строки guard.key ("" если строки нет).
    2. Если at ≠ guard.index, вернуть `guard` {key: guard.key, index: at}; ничего не записано.
12. Если cas задан и cas ≠ current, вернуть `conflict` {index: current}; ничего не записано.
13. Пусть index — новая версия, ранее не выдававшаяся этим хранилищем; порядок версий непрозрачен.
14. Записать в строку key (копию items, index).
15. Если id задан, запомнить (id → эта запись, ответ).
16. Вернуть index.

Порядок проверок внутри операции нормативен: память `id`, затем `not_after` и `not_before`, затем страж, затем CAS;
при нескольких нарушениях ответ — по первому (ADR-0091 п. 1). Повтор применённой записи получает её ответ и после
`not_after` — в том числе повтор, пришедший, пока первая копия ещё не применена: первой применяется первая, повтор
отвечает её ответом. Отказ `expired` и `early`, как `conflict` и `guard`, записи не делает и `id` не занимает, но время приёма отказанной
записи остаётся последним временем приёма (в группе — запись журнала; коробка и хранилище в процессе хранят его так же
прочно, как строки; C01-ADMITTED-ON-REFUSAL-01). Только `expired` сохраняет тот же отказ при том же deadline и неубывающем времени приёма. `early`, `conflict` и `guard` не занимают `id`: та же команда с тем же `id` проверяется заново по текущему времени приёма и состоянию и может пройти. Вызывающий по-прежнему перечитывает условие и заново принимает решение перед следующей попыткой (N4). Страж раньше CAS. Отказ стража означает несовпадение наблюдаемой версии и отсутствие этой записи. Вызывающий перечитывает условие и заново решает, имеет ли право повторять; несовпадение версии само по себе не доказывает потерю владения. Отказ CAS также требует перечитки перед новой попыткой. Страж по отсутствующей строке (`index: ""`) держит, пока строки нет.

Отсутствие бизнес-эффектов отличается от метаданных приёма: уже принятая put или delete при любом из этих четырёх отказов обновляет последнее время приёма значением `admitted` этой записи (оно может равняться прежнему). Эти метаданные не откатываются вместе с отказанными эффектами строки/id/версии. Правило сохранности то же, что у приёма успешной записи (N3 Время приёма). Это утверждение об уже принятой записи, не о запросе, отказанном до приёма.

Версия выдаётся только сделанной записи: отказ версии не тратит. Items копируются: хранилище не делит память с вызывающим ни на входе, ни на выходе.

«Иная запись» повтора сравнивается по значениям полей отпечатка, а не по байтам тела: `cas: null` равно отсутствию
`cas`, порядок полей `items` и способ экранирования строк JSON значения не имеют; `not_after` и `not_before` — по
конечным числовым значениям binary64, как в N1 (`10` и `10.0` — одно), отсутствие не равно никакому числу. Разные написания JSON-чисел, округляющиеся в одно значение binary64, равны при сравнении и в отпечатке границы; точное сравнение десятичных рациональных чисел и сырое написание не являются областью границ. Это числовое правило не относится к версиям: они остаются точными строками, `"0"` не равно `""`.

**Гонки.**
- Два писателя с одним `cas` на одну строку: проходит ровно один, второй получает `conflict` с версией первого.
- Два создания с `cas: ""`: проходит ровно одно.
- Запись под стражем и смена стража (новый захват слота) в любом порядке: либо запись сделана до смены, либо отказана `guard` с новой версией стража; состояния «записано после смены» нет.
- Повтор записи с тем же `id` после ответа «неизвестно»: если первая применилась — повтор отвечает её ответом и ничего не меняет; если нет — применяется как первая. Вызывающий не различает эти случаи и не должен.
- Повтор с тем же `id`, но иным содержимым (другое `items`, `cas` или `guard`): отказ `badrequest`, ничего не записано — идентификатор принадлежит одной записи.
- Смена лидера между приёмом и применением: вызывающий получает `ambiguous`; см. выше.
- Запись с `not_after` и её повтор с тем же `id` после `not_after`: если первая применилась — повтор отвечает её ответом;
  если нет — повтор применяется как первая и получает `expired` (ADR-0091 п. 1).

### удалить(key, cas?, guard?, not_after?, not_before?, id?) → index

Поле `items`, если прислано, не читается независимо от его JSON-типа; его наличие не является отказом.

1. Если ключ или форма cas, guard, id, not_after или not_before не проходит проверки N1, вернуть `badkey` / `badrequest`.
2. Если у вызывающего нет права на удаление key, вернуть `forbidden` (P/01.2 N3 «проверить»: never N1.3, `allowed(role, delete, key)`).
3. Если guard задан, а права на чтение guard.key у вызывающего нет, вернуть `forbidden`.
4. Остальные шаги идут одной операцией, при применении записи журнала.
5. Пусть admitted — время приёма этой записи.
6. Повтор по id: сличить (op, key, cas, guard, not_after, not_before); items не читается и не входит в отпечаток,
   даже если прислано с другим JSON-типом. Если совпало, вернуть прежний ответ с again=true; иначе
   вернуть `badrequest`.
7. Если not_after задан и admitted > not_after, вернуть `expired`.
8. Если not_before задан и admitted ≤ not_before, вернуть `early`.
9. Пусть current — версия строки key ("" если строки нет).
10. Если guard задан и версия guard.key ≠ guard.index, вернуть `guard`.
11. Если cas задан и cas ≠ current, вернуть `conflict` {index: current}.
12. Убрать строку key (отсутствующая строка — не ошибка).
13. Пусть index — новая версия (удаление тратит версию).
14. Если id задан, запомнить.
15. Вернуть index.

Удаление тратит версию, чтобы устаревший `cas` на удалённую и созданную заново строку не прошёл. Удаление отсутствующей строки — сделано: повтор сделанного удаления — то же удаление.

**Гонки.** Как у записи. Удаление и запись одной строки с одним `cas` по **существующей** версии: проходит одно — удаление тратит версию. С `cas ""` у отсутствующей строки удаление ничего не меняет (строки как не было, так и нет; версия чтения остаётся `""`), и последующая запись с `cas ""` проходит — победителя здесь выбирать не из чего.

### записать пакет(writes, guards?, not_after?, not_before?, id?) → index

1. Если форма пакета не проходит проверки N1 (порядок — N2.1), вернуть `badkey` / `badrequest`.
2. Для каждой put по порядку writes: если вес её items больше потолка, вернуть `toolarge` {key, size, limit} этой строки; ничего не записано.
3. Права по порядку writes: `allowed(role, write | delete, key)`; затем по порядку guards: `allowed(role, read, key)`;
   если какого-то нет, вернуть `forbidden` на весь пакет (P/01.2 N3 «проверить»); ничего не записано.
4. Остальные шаги идут одной операцией, при применении записи журнала.
5. Пусть admitted — время приёма этой записи (выше, «Время приёма»).
6. Если id задан и уже применялся:
   1. Если та запись была иной (отпечаток ниже), вернуть `badrequest`.
   2. иначе вернуть его ответ с again=true; бизнес-строки, выданные версии и запись памяти применённого id не меняются. Последнее время приёма всё же продвигается по N3 «Время приёма» (R070), с той же сохранностью, даже когда ответ берётся из этой памяти.
7. Если not_after задан и admitted > not_after, вернуть `expired`; ничего не записано.
8. Если not_before задан и admitted ≤ not_before, вернуть `early`; ничего не записано.
9. Для каждого стража по порядку guards: пусть at — версия строки key ("" если строки нет); если at ≠ index стража,
   вернуть `guard` {key, index: at}; ничего не записано.
10. Для каждой записи по порядку writes: пусть current — версия строки key ("" если строки нет); если cas задан и
    cas ≠ current, вернуть `conflict` {key, index: current}; ничего не записано.
11. Пусть index — новая версия, ранее не выдававшаяся этим хранилищем, — одна на пакет.
12. Для каждой записи по порядку writes: put → записать в строку key (копию items, index); delete → убрать строку key
    (отсутствующая строка — не ошибка).
13. Если id задан, запомнить (id → этот пакет, ответ).
14. Вернуть index.

Порядок нормативен (ADR-0094 доп. (12) п. 1): форма → вес → права → память `id` → сроки → стражи по порядку списка → `cas` по порядку
списка → применение; ответ — первое нарушение. Страж на записываемый ключ — отказ формы: условие такой строки — её `cas`.

Отказы `expired`, `early`, `guard`, `conflict` записи не делают, `id` не занимают и версии не тратят; время приёма отказанного пакета
остаётся последним временем приёма, как у записи. Отказ называет строку, но не значение: `412 guard {key, index}`,
`409 conflict {key, index}` — версия этой строки сейчас.

Отказанный пакет всё же обновляет последнее время приёма значением `admitted` этой записи (оно может равняться прежнему), с той же сохранностью, что у приёма успешного пакета. Ноль изменений бизнес-строк, незанятый `id` и невыданная версия не означают отката этих метаданных. Это относится к каждому из четырёх названных отказов после приёма, не к запросу, отказанному до приёма.

Одна версия на операцию: все строки put получают `index` пакета; delete тратит ту же версию. Удаление отсутствующей строки — сделано.

**Отпечаток повтора** — `writes` по порядку (`op`, `key`, `cas`, у put — `items`), множество `guards`, `not_after`, `not_before`. Значения сравниваются,
как у записи: `cas: null` равно отсутствию, порядок полей `items` значения не имеет; порядок элементов `guards` значения не имеет,
отсутствие `guards` равно `[]`; порядок элементов `writes` значим; `items` у delete не читается и не входит. Память `id` одна на
записи и пакеты, срок — раздел ниже, пакет считается одной записью: `id`, занятый put, у пакета — `badrequest`, и наоборот.

**Атомарность** (ADR-0094 доп. (12) п. 2). Пакет становится видимым целиком или не становится: чтение и перечисление видят все его
строки или ни одной. После потери питания в любой точке, в том числе при отказе барьера, виден весь пакет или ни одной его
строки; память `id` долговечна вместе с ним: повтор не доводит половину пакета, потому что половины нет. Ветвь `ambiguous` N4
(ошибка носителя, отказ барьера, смена лидера) — на пакет целиком: повтор тем же `id` отвечает первым ответом или применяет
пакет как первый. В группе пакет — одна запись журнала; способ у коробки и хранилища в процессе — п. 3 «Решает реализация».

**Гонки.**
- Два пакета с общей строкой и одним `cas`: проходит ровно один, второй получает `conflict` с версией первого; ни одна его строка не записана.
- Пакет под стражем и смена стража в любом порядке: либо пакет сделан до смены, либо отказан `guard` с новой версией; состояния «часть записана после смены» нет.
- Два чтения двух строк пакета — две операции: первое может быть до пакета, второе после. Целиком пакет видит одна операция; вызывающий сверяет версии: у строк одного пакета версия одна.
- Повтор с тем же `id` разом с первым применением: как у записи, первой применяется первая копия.

### Повтор по идентификатору — память хранилища

Хранилище ДОЛЖЕН отвечать повтору тем же ответом, пока не выполнены оба условия: после первого применения прошло больше двух минут **и** после него применено не меньше 50 000 записей с идентификатором; когда выполнены оба — МОЖЕТ забыть. Забытый повтор применяется как новая запись — поэтому `cas` у каждой записи, которая имеет значение.

**Гонки.** Два повтора одного `id` разом: применяется один (под блокировкой или в журнале), второй получает тот же ответ с `again: true`; повтор и новая запись с тем же `id`, но иным содержимым — первой применяется та, что раньше, вторая получает 400.

## N4 Отказы

Каталог этих отказов — [`forms/refusals.tsv`](../../forms/refusals.tsv) (ADR-0125): форма — единственный источник кода, kind, полей, заголовков и проекции журнала. Схемы отказов OpenAPI и порядок проверок сохраняют свои формы; причины, приоритет и действия ниже ссылаются на устойчивые имена отказов, не повторяя ячейки исходов.

Закрытый список. Текст `error` — для человека, не нормируется; нормируются код, `kind` и поля.

- `key_rules`: ключ не по правилам N1 (пустой, с `/` в начале, с сегментом `..`, длиннее предела) — целевой; у строки-стража — непустой ключ не по правилам (пустой ключ стража — `badrequest`: не по форме `guard`); байты `key` чтения после декодирования не UTF-8; одиночный суррогат в `key` или `guard.key` (N2.1). Действие вызывающего: ничего: ошибка кода.
- `body_form`: тело не JSON-объект или не JSON по N2.1 (повтор имени поля, `NaN`, `Infinity`, BOM, не UTF-8, глубже предела); повтор `key` или `prefix` в query; запрос не разбирается как HTTP (N2.1); `op` не `put`, `delete`, `batch` или `floor` (`floor` — P/01.3 N2); одиночный суррогат в `items`; `key` команды, `guard.key` или параметр `key` чтения отсутствует или не строка; `items` не объект строк у `put`; `cas`, `guard`, `id`, `not_after` или `not_before` не по форме (N1); `id` уже принадлежит иной записи; пакет не по форме N1: `writes` нет, пуст, не массив или длиннее `BATCH_WRITES`, `guards` не массив или длиннее `BATCH_GUARDS`, элемент не по закрытой форме, ключ дважды в `writes` или в `guards`, страж на ключ из `writes`. Действие вызывающего: ничего: ошибка кода.
- `no_route`: нет маршрута или метода на нём (N2.1). Действие вызывающего: ничего.
- `identity`: личность не допускается по P/01.2 N3 «проверить» (включая list): заголовок роли на ролевом сокете, недоверенная пересылка или запрещённый пересланный admin; `op: floor` не на admin-сокете (P/01.3 N4). Действие вызывающего: исправить личность/доверие; отсутствие read само по себе list не запрещает.
- `rights`: прав нет (чтение, запись, удаление, чтение стража). Действие вызывающего: ничего: ошибка развёртывания или чужой процесс (P/01.2 N4, строки «… without permission»).
- `cas_mismatch`: версия строки не та, что в `cas`. Действие вызывающего: перечитать, применить своё поверх, повторить.
- `expired`: время приёма позже `not_after` (N3 «Время приёма»; ADR-0091 п. 1). Действие вызывающего: не повторять той же записью: срок записи прошёл; новую решает вызывающий по своей норме (заказ — [P/03.6](../../../03-worker/ru/spec/03.6-worker.norms.md)).
- `early`: время приёма не позже `not_before` (ADR-0091 п. 1). Действие вызывающего: не повторять той же записью; новая запись — на следующем шаге (удаление строки с `made` — [P/04](../../../04-controller/ru/spec/04-controller.norms.md), P/03.6).
- `guard_mismatch`: строка-страж не на той версии (у пакета — первая по порядку `guards`). Действие вызывающего: не повторять: перечитать слот и заново проверить владение ([P/03.2 N3 «писать_под_слотом»](../../../03-worker/ru/spec/03.2-worker.norms.md); воркер — [P/03.4 N4](../../../03-worker/ru/spec/03.4-worker.norms.md) «write under slot: `412 guard`»).
- `weight`: строка тяжелее потолка (у пакета — первая по порядку `writes`, ничего не записано). Действие вызывающего: ничего: то, что делает строку тяжёлой, — в объект: поле `type: blob`, байты дверью `PUT /<rows>/<id>/<blob_field>` (P/06.1 N1.5, N2).
- `body_limit`: тело больше предела чтения N2; операция хранилища не вызвана. Действие вызывающего: уменьшить тело; сравнивать его размер именно с пределом тела.
- `no_leader_wait`, `lock_wait`, `connection_limit_doors`: лидера не нашлось за срок ожидания или истёк срок ожидания местной блокировки (п. 1 «Решает реализация»), либо соединений больше объявленного предела двери (добавлено M10/11: `-max-conns` N1.3, строка N4); операция **не сделана** — у записи, чтения и перечисления. Действие вызывающего: повторить на следующем шаге цикла (при `Retry-After` — не раньше срока); держать, что держишь.
- `floor_not_higher`: (добавлено M10/11) служебная `op: floor` на admin-сокете (только P/01.3 N2): новое значение не больше нынешнего. Действие вызывающего: ничего: нижняя граница эпох уже не ниже (P/01.3 N1.3).
- `ambiguous_leader`: запись дошла до лидера, исход **неизвестен**. Действие вызывающего: повторить только с тем же `id`; кому важно — сначала прочитать.
- `ambiguous_medium`: ошибка носителя до публикации строки, и реализация не может доказать, что после перезапуска запись не применится (п. 7 «Решает реализация»); если может — `unavailable`. Действие вызывающего: повторить только с тем же `id`.
- `ambiguous_barrier`: барьер долговечности (п. 3 «Решает реализация») отказал, когда байты записи уже на носителе: строка публикуется (после перезапуска она вернётся), исход для вызывающего **неизвестен** — и на одной коробке. Действие вызывающего: повторить только с тем же `id`: повтор довершает барьеры и отвечает первым ответом (`again: true`), новой версии не выдаёт; барьер отказал снова — снова `ambiguous`.


Отказ не цитирует вызывающему присланное, кроме ключа: ответ не становится больше от большей ошибки. Обрезанный, нечитаемый или не пришедший ответ и отказ в соединении (переполнена очередь `accept`; отдельного 503 нет) — у клиента: [договор клиента хранилища](../../../common/ru/contracts/store-client.md) `no_reply` (перенесено туда без изменения; SC-WIRE78-G01). Столбец «Что делает вызывающий» — там же, раздел «Исходы и что делает клиент».

## N5 Приёмка

Сценарии — [`../acceptance/1/scenarios.tsv`](../../acceptance/1/scenarios.tsv), прогоняются через дверь N2 любой реализации ролью с полными правами на префикс `acc/`; формат — в `README.md` рядом. Путь к двери (unix-сокет или стенд с той же дверью) — параметр раннера, не норма урока. Журнал исправлений ИИ — `journal/corrections-1.tsv` урока.

Для этой приёмки раннер подготавливает дверь с пределом тела **1048576 байт (1 МиБ)** и хранилище
с потолком строки **524288 байт (512 КиБ)**. Это фиксированные параметры стенда, а не универсальный
предел тела всех реализаций. Раннер сверяет их поведением на пробном экземпляре до сценариев: тело ровно
на пределе доходит до разбора JSON, на 1 байт больше — `413` с пределом тела в `limit`; вес `items` ровно
на потолке записывается, на 1 байт больше — `413` с потолком строки. Как получить изолированный экземпляр
с этими параметрами, реализация называет в описании (п. 10 «Решает реализация»). Если параметры не обеспечены
или сверка не сошлась, прогон не выполнен и не считается зелёным.
Сценарий 15 проверяет вес `items` после разбора тела, сценарий 22 — отказ до разбора тела по N2.
Сравнение необязательного `size` во втором случае задано в README приёмки.

Реализации, у которой хранилище открывается в процессе без двери (файлы, память), СЛЕДУЕТ (не ДОЛЖЕН: приёмка нормирует поведение двери, внутренний API — выбор реализации, п. «Решает реализация») гонять те же сценарии
и через свой API, отображая отказы на коды N4: так порядок «страж раньше CAS» и формы проверены во всех её хранилищах,
а не только за дверью (проба мутаций 2026-10-14: за дверью 39 % мутантов выжили, в хранилищах без двери — все).

Неразбираемый HTTP (N2.1) TSV не выражается: его проверяет проба README приёмки на сырых байтах.

Время приёма в сц. 28 — только его край: `not_after` = 1 (1970) уже прошёл, `not_after`/`not_before` = 4102444800
(2100) ещё не настал при любых часах стенда; граница равенства, неубывание по журналу при смене лидера, перезапуске и
ходе часов назад, повтор после `not_after` до применения первой копии и `admission_ahead` — проверяются чтением:
дверь не двигает часы лидера и не держит запись между приёмом и применением.

Обрыв питания посреди пакета проверяется чтением раздела «Решает реализация» п. 3 и кода: стенд питание не обрывает; перезапуск после
пакета и повтор — сц. 30 главы 1.3, одна запись журнала в группе и пересылка дверью без голоса — сц. 31 главы 1.3. Отказ тела пакета сверх
предела — общий отказ тела до разбора JSON (сц. 22). Предел числа строк роли `console` — сц. 16 главы 1.2.

Проверяются чтением (дверями не воспроизводятся детерминированно): `ambiguous` при смерти лидера — ветвь P/01.3 N1.3 `leader_wait` (`unavailable` без кворума — сц. 17 главы 1.3, стенд группы); `unavailable` при истечении срока ожидания местной блокировки — ветка отказа до записи; память повторов по времени; линеаризуемость чтения.

Независимость памяти `items` на входе и выходе проверяется чтением реализации операций: переданный вызывающим
словарь и словарь, возвращённый чтением, не делят изменяемую память с хранилищем. Причина: HTTP-сериализация
скрывает общую память, а сц. 03 только записывает и читает значение. Прогон тех же двух шагов через API в процессе
без последующего изменения переданного или возвращённого словаря тоже не проверяет копирование.

## Решает реализация

Каждая реализация называет в своём описании:
1. **механизм неделимости** на одной коробке (блокировка файла, мьютекс) и в группе (журнал консенсуса; пакет — одна запись журнала) и срок ожидания блокировки — что вызывающий получает по его истечении (как `unavailable`);
2. **как выдаётся версия**: счётчик в файле, индекс журнала плюс основание группы — лишь бы не повторялась; с какого числа начинается;
3. **раскладку на диске** и **барьеры долговечности**. Порядок одной записи: байты на носитель, барьер, публикация и ответ; удаление переживает потерю питания. Если барьер отказал, когда байты уже на носителе, строка публикуется и ответ — `ambiguous` (N4); повтор с тем же `id` повторяет барьер. Режим без барьеров допустим только по флагу команды «Стенда» приёмки; переменной окружения или флага эксплуатации, которые выключают барьеры, нет (P/01.3 N1.3 `durability`; пилот хранилища, A10). **Пакет:** как он становится видимым целиком и после потери питания остаётся целым или не становится вовсе (N3 «записать пакет», «Атомарность») — журнал намерения с барьером до публикации строк или иной способ; замка мало: замок не переживает питание, а строки разных файлов ложатся на носитель порознь;
4. **предел длины ключа** реализации на файлах, если он меньше 1024;
5. **как хранилище, которое может прочитать свою строку не полностью** (повреждённый файл), сообщает об этом: форма ответа — норма (N2 `Row.unreadable`, P/01.1-17); здесь — как реализация обнаруживает порчу и что пишет в лог, и как хранит версию строки, чтобы порча тела её не теряла (потеря версии — 503, N2; C01-ROW-INDEX-LOST-01, решение «Архитектора» 2026-10-29);
6. **срок и объём памяти повторов** сверх минимума N3;
7. **как дверь отличает «не добавлено в журнал» от «неизвестно»**; срок ожидания лидера перед `unavailable` — 5 с от потери лидера, норма P/01.3 N1.3, не выбор.
8. **предел чтения HTTP-тела** у хранилища в процессе без демона; у демона он задан флагом `-max-body` (P/01.3 N1.3 «Флаги демона», умолчание 1 МиБ) отдельно от потолка строки `-max-value`; значение и смысл `limit` — по N2, параметры приёмки — по N5 (журнал cammeta-python, урок 11 № 24).
9. **пределы разбора запроса**: длина строки запроса HTTP (в байтах, без завершающего CRLF); превышение — `400 badrequest` по N2.1; длина строки размера куска chunked с расширениями (без CRLF) — превышение — ошибка рамки: `400 badrequest` и закрытие соединения (C01-CHUNK-LINE-LIMIT-01); объём и срок слива после раннего отказа (N2.1). Предел заголовков (`HEADER_BYTES` 65536) и глубина JSON (`JSON_DEPTH` 128) — нормы N2.1, не выбор (сверка python и go 2026-10-18);
10. **как раннер получает изолированный экземпляр** с параметрами приёмки N5: команду запуска с подстановками по разделу «Стенд» README приёмки этого урока — он общий для приёмки M10; внутреннего API урок не нормирует;
11. **как перечисление снимает список** (копия под блокировкой, снимок версии); гарантия «Гонок» N3 сохраняется.
