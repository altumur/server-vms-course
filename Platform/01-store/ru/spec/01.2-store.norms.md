## N1 Форма

**Данные** ([каталог](../../../common/data/catalog.tsv)):
- владеет: `/etc/w2c/configstore-rights.json` (форма — N1.2; пишет вывод прав [P/02.5](../../../02-installer/ru/spec/02.5-installer.norms.md) N3 «сгенерировать_права»);
- пишет: строк нет;
- читает: строк нет — оценщик отвечает о любых строках по образцам файла прав.

### N1.1 Роли

```yaml
roles:
  per_manifest:                              # из каждого манифеста каталога
    <sub>controller:     контроллер манифеста
    <sub>worker:         воркер манифеста
  platform:              [resource, console, domain, domainconsole, domainagent] # console одна на кластер, пишет строки оператора всех манифестов; domain, domainconsole, domainagent — роли домена (M11; domain — подписант с ключами, domainconsole без ключей — P/08.2 N1.3)
  store_internal:        [admin, configstore (peer), configstore-door]     # в файле прав не называются; configstore-door — дверь без голоса (добавлено P/01.3 N1.3)
  reader_word_only:      [domainworker]    # (P/03.7 N1.6: воркер подсистемы на домене) слово платформы в secrets.readers (P/02.5 N1.3; решение C7
                                         # role-name decision (2026-10-15, C7; for people)): роли в файле прав не даёт —
                                         # отображается в роль <sub>domain манифеста, где есть domain.kept или переносимая книга
                                         # (P/03.7 N1.6; ADR-0074 C7 п. 2 и доп. 5: платформенная способность, не снятый процесс
                                         # domainpart) — и в сравнение «объявленные = способные прочесть» не входит
name:      ^[a-z][a-z0-9_-]{0,63}$       # имя роли; <sub> — по грамматике имени манифеста (P/02.1)
group:
  platform role:         w2c-<роль>      # console, resource, domain* (M11), и каждый <sub>controller (ADR-0030)
  subsystem role:        <развёртывание>-<роль>   # только <sub>worker: контроллер — платформенная роль w2c-<sub>controller (ADR-0030); развёртывание: ^[a-z][a-z0-9]*$
identity:
  cluster:  сокет /run/configstore/<роль>.sock (0660, группа роли — SocketGroup= юнита сокета, P/02.4 N1.1); admin.sock (0600, root)
  box:      имя писателя у хранилища файлов/памяти + тот же список прав; дверь коробки тоже открывает сокет на роль;
            доверенных отправителей пересылки на коробке нет: заголовок роли на любом сокете, включая admin.sock, —
            403 с ролью сокета
  doors:    сертификат роли — P/02.4 N1.6 `doors`; форма — договор сертификата роли (`Platform/common/contracts/role-certificate.md`)
```

### N1.2 Файл прав

Файл — объект JSON с обязательным полем `roles` и необязательным строковым `comment`.
`comment` — пометка генератора; она не участвует в выдаче прав. Пометка обязательно называет, что файл сгенерирован,
развёртывание, исходные манифесты и «не править вручную»; для одних входов её текст один и тот же (P/02.5-01). У каждой роли обязательны `group`
(непустая строка), `read` и `write` (массивы строк); `delete` — необязательный массив строк.
Неизвестные поля отвергаются. Имена ролей проверяются целиком, включая конец строки;
внутренние роли хранилища в файл не входят. Полная статическая форма — `RightsFile` в N2.

```yaml
configstore-rights.json:
  comment:  <пометка генератора>      # необязательно; только строка, не права
  roles:
    <роль>:
      group:  <группа сокета>
      read:   [<образец>…]
      write:  [<образец>…]
      delete: [<образец>…]            # генератор пишет у каждой роли всегда: = write, если манифест не разнёс их через
                                      # delete:; у оценщика отсутствие — пустой список: удалять нельзя (минимум прав)
pattern:
  exact:    "testsub/next_id"            # равенство ключу
  prefix:   "testsub/counters/*"         # * последним знаком — префикс; * не последним — буквальный знак (literal ниже)
  deny:     "!domain/signer*"            # ! только первым знаком; отрицание побеждает везде в списке
  literal:  "", "!", "!*", "p/!x", "a*b"  # допустимы в файле и совпадают по правилам выше: "" — только пустой ключ,
                                          # "!" — отрицание пустого ключа, "!*" — отрицание всего, "!" не первым и "*" не
                                          # последним — буквальные знаки (сверка python и go M10/6–11: обе так; журнал
                                          # cammeta-go, урок 6 № 2; вектор Platform/01-store/vectors/rights-evaluator)
rules:
  - файл не называет admin, configstore, configstore-door; неверная форма — файл отказан целиком
  - генерируется из каталога манифестов (MANIFEST_DIR) и имени развёртывания; руками не правится
  - загружается при старте демона (-rights); без файла открывается только admin.sock; живой перезагрузки нет
  - установщик отказывается ставить файл, по смыслу не равный сгенерированному (--check, P/02.5 N3 «установить»)
  - файл показывается дверью только admin
```

Имена производных ролей помещаются в N1.1: имя манифеста ограничено 32 знаками
(P/02.1 N1.2), суффикс controller добавляет 10, worker — 6. Имя не усекается. Предела имени развёртывания глава не
ставит: группа `<dep>-<s>worker` бывает длиннее 32 знаков, генератор её не усекает и не отказывает (сверка python и go
M10/6–11: обе так); создаёт ли её ОС — установщик, P/02.4 «Решает реализация» п. 1.
Сравнение `--check` относится к одному неизменному каталогу; публикация манифестов во время
генерации и установки в этой главе исключена условиями обслуживания, а не обнаруживается автоматически.

### N1.3 Оценщик

```yaml
allowed(role, action, key):
  action ∈ {read, write, delete}
  role не в файле                                        → нет
  любой !образец роли для action совпал                  → нет
  любой образец роли для action совпал                   → да
  иначе                                                  → нет
never:                                                   # и для admin
  - delete строки <x>/epoch/<y> — ровно один сегмент <y> после «<x>/epoch/», в том числе пустой (`t/epoch/`), x ≠ platform
    (строка эпохи P/03.2 <sub>/epoch/<id>) (сверка python и go M10/6–11, R12)
  - delete под domain/ не ролью домена (domain, domainagent, <s>domain — в своих семьях по договору вывода прав P/02.5 N1.4, N1.4a)
    роль домена — имя domain, domainagent или <sub>domain (<sub> — грамматика имени подсистемы P/02.1, `[a-z][a-z0-9_-]{0,31}`);
    never проверяет только это; «свои семьи» задают образцы delete файла прав, выведенного генератором (P/02.5, сверка --check),
    хранилище их не перепроверяет по каталогу (C01-NEVER-DOMAIN-ROLE-01, решение Спецификации)
  - write и delete platform/epoch_floor (только операция восстановления, P/01.3)
list:   имена и версии под префиксом — любой роли; значения — нет
guard:  запись со стражем требует права read на строку-страж; страж права не расширяет (ADR-0074 доп. 3)
batch:  пакет (P/01.1 N3 «записать пакет») судится по каждой строке: write или delete каждой строки writes, read каждого стража, never — и у admin; отказ одной — отказ всего пакета (ADR-0094 B9)
admin:  всё, кроме never; peer (другой демон) — ничего своего; configstore-door — только свою platform/configstore-doors/<id> (P/01.3 N1.3; не platform/doors/* ресурсов)
```

## N2 Двери

Двери прав — двери хранилища главы 1.1, за сокетом роли; разбор запроса — глава 1.1 N2.1, у `GET /v1/rights` query не читается. Дополнительно:

HTTP-контракт: [01-store.api.openapi.yaml](../../spec/01-store.api.openapi.yaml).

`GET /v1/rights` возвращает загруженный объект `RightsFile` целиком, без оболочки;
если в нём есть comment, поле также возвращается. При отсутствии загруженного файла маршрут отвечает `404 badrequest`;
пустой объект `roles` не подменяет отсутствие файла. Доступ проверяется по личности admin,
до выдачи файла. Успешный `GET /v1/list` использует `Listing` главы 1.1: без значений строк,
с версиями и порядком имён по UTF-8-байтам. Наличие пути и доверие личности проверяются
также для list; отсутствие права read не препятствует перечислению.

Формы всех ответов двух маршрутов заданы в OpenAPI. Отказы `400` (`/v1/list` не по форме главы 1.1 N2.1), `403`, `404`, `503` —
ровно `{kind, error}` строками, соответственно `badrequest`, `forbidden`, `badrequest`, `unavailable`;
никаких `detail`/`fault` консоли. Для отказа операции над строкой `error` называет роль,
действие и ключ; для отказа самой личности или `/v1/rights` — роль и причину/маршрут.
При заголовке роли на ролевом сокете называется роль сокета,
а не навязываемая заголовком роль; разбирать ключ операции ради диагностики не требуется.

## N3 Проход

### проверить(роль, действие, ключ) — в каждом хранилище перед действием

1. Пусть роль — роль из сокета (кластер) или из имени писателя (коробка). Если заголовок с ролью пришёл на сокет роли,
   вернуть `403` до разбора тела (тело не по форме с таким заголовком — тоже `403`; сверка
   python и go M10/6–11: обе так).
2. Если роль пересланная, сначала проверить доверие демону группы и запрет пересланного admin (шаг 9).
3. Если операция — list, после проверки личности вернуть имена и версии без проверки права read.
4. Если выполняется never (N1.3), вернуть `403 forbidden`.
5. Если роль — admin, после never разрешить операцию; внутренние роли — только по исключениям N1.3.
6. Для остальных ролей: если не `allowed(role, action, key)` по N1.3, вернуть `403 forbidden`, до записи в журнал.
7. Для записи со стражем: если не `allowed(role, read, guard)`, вернуть `403`.
8. Для пакета: проверки выше идут по порядку writes, затем стражи — по каждой строке; если одна отказана, вернуть `403`
   на весь пакет, до записи в журнал (admin читает страж по своему разрешению N1.3).
9. В группе: проверяет принявший демон и ещё раз лидер под пересланной ролью; пересылке верят только от демона
   группы — голосующего или двери без голоса `configstore-door` (P/01.3 N1.3), по роли в SAN сертификата; пересланный
   admin при наличии файла прав — отказ.

Условия пересылки применяются и к list, и к /v1/rights до выдачи данных. Локальный
admin из admin.sock и доверенный пересланный admin без файла доходят до особых правил
N1.3; при загруженном файле пересланный admin отказывается раньше операции.
Отсутствие файла не отключает never и проверку доверия отправителю.

**Гонки.** Нет: права не меняются на ходу — новый файл = перезапуск демона.

## N4 Отказы

Каталог этих отказов — [`forms/refusals.tsv`](../../forms/refusals.tsv) (ADR-0125): форма — единственный источник кода, kind, полей, заголовков и проекции журнала. Схемы отказов OpenAPI и порядок проверок сохраняют свои формы; причины, приоритет и действия ниже ссылаются на устойчивые имена отказов, не повторяя ячейки исходов.

- `list_form`: `/v1/list` не по форме главы 1.1 N2.1 (повтор `prefix`). Действие вызывающего: исправить запрос.
- `rights_no_route`, `rights_store_unavailable`: нет маршрута; хранилище недоступно (`/v1/list`, `/v1/rights`). Действие вызывающего: —.
- `read_forbidden`: чтение без права. Действие вызывающего: ошибка развёртывания или чужой процесс.
- `write_forbidden`: запись/удаление без права. Действие вызывающего: то же.
- `guard_read_forbidden`: страж на строку без права чтения. Действие вызывающего: то же.
- `never`: удаление строки эпохи; удаление под `domain/` не ролью домена; запись и удаление `platform/epoch_floor`. Действие вызывающего: никогда.
- `role_header`: заголовок роли на сокете роли. Действие вызывающего: ошибка клиента.
- `forwarding_untrusted`: пересылка не от демона группы (голосующего или двери без голоса); пересланный `admin` при загруженном файле прав. Действие вызывающего: —.
- `rights_not_admin`: `/v1/rights`: личность не admin после проверки допустимости пересылки. Действие вызывающего: —.
- `rights_not_loaded`: `/v1/rights`: файл не загружен. Действие вызывающего: настроить файл и перезапустить.
- `rights_file_form`: файл прав не по форме; называет `admin`/`configstore`/`configstore-door`; роль не по грамматике. Действие вызывающего: перегенерировать.


Не отказ: демон без `-rights` открывает только `admin.sock` — дать ему файл (флаг `-rights`, P/01.3 N1.3; ADR-0125 доп. (2) п. 7).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как раннер и тесты звонят ролью на одной коробке** (имя писателя, тестовый сокет);
2. **точный текст** `error` сверх «<роль> may not <действие> <ключ>» (имя файла, демона);
3. **пересылка роли внутри группы демонов** (заголовок, проверка голосующего).
