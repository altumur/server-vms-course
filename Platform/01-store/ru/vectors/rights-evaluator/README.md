# Оценщик прав — вектор

Текст производный от `vectors/rights-evaluator/README.md`, руками не правится: источник — английский [`vectors/rights-evaluator/README.md`](../../../vectors/rights-evaluator/README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Владелец — урок P/01, глава 1.2: P/01.2 N1.2 `pattern`, N1.3 «Оценщик». Входная фикстура — `rights.json` (только для судьи: байты фикстуры). Столбцы случая — `role action key expect`, где `expect` равен `allow` или `deny`.

**Прогон.** Раннер запускает свежее хранилище с `rights.json` (только для судьи: байты фикстуры) как `{rights}` («Стенд» [общего README приёмки](../../../../common/ru/acceptance/README.md)) и на
каждую строку делает пробу сокетом роли: `read` — `GET /v1/get?key=<key>`, `write` — `POST /v1/write` `put`, `delete` —
`POST /v1/write` `delete` (без `cas`; отсутствующая строка удаляется успешно, M10/1 N3). Исход пробы:
- `deny` — `403 forbidden`;
- `allow` — только подтверждённый успех: у чтения 200 формы `Row` (в том числе `{items: null, index: ""}`), у записи и
  удаления 200 `Written`;
- 5xx, ошибка транспорта и иной ответ — неопределённый исход: проба не засчитана ни как `allow`, ни как `deny`, прогон
  не зелёный.

Проверяется смысл оценщика, а не байты файла.

**Что покрыто:**
- точный образец, префикс (`*` только последним знаком);
- буквальные знаки: `*` не последним, `!` не первым;
- конечная звёздочка после буквальной (P/01.2-R008);
- `!` — отрицание пустого ключа, ничего не отнимает; `!*` — отрицание всего;
- отрицание побеждает независимо от места в списке;
- права одного действия не дают другого (`write`, `delete`): `delete` — свой список, у оценщика нет `delete = write`;
  пустой или отсутствующий `delete` — удалять нельзя (P/01.2 N1.2).

## Кто исполняет

Кто исполняет — хранилище (`01-store`: оценщик P/01.2 N1.3, и у хранилища в процессе, P/01.1-22) — все строки, через дверь своих сокетов ролей. Не исполняют: агент в процессе (`09-agent`, P/09.1 N1.11 `rights`) — права его компонентов проверяет хранилище в процессе; генератор прав установщика (`02-installer`, P/02.5 N3 «сгенерировать_права» шаг 4) — своё правило покрытия образцов секретных строк, не оценщик действий; консоль (`06-console`, P/06.3) только ссылается на P/01.2 (строку исполняет роль, чья норма вызывает её функцию).

## Провод векторов

Провод вектора задают строки `01-store/rights-evaluator` в [единой форме](../../../../common/vectors/wire.tsv); [грамматика](../../../../common/ru/vectors/wire.md). Форма — источник шапки, выбранных входов, фикстур, нативного исхода и сравнения. Смысл алгоритма и обязанность потребителя остаются здесь.

`{rights}` в «Прогоне» выше — подстановка команды `stand.store` этого прогона стенда ([подстановки](../../../../common/ru/acceptance/PROFILE.md#подстановки)), а не имя команды векторов. Цель векторов пакета отдельная: запись профиля `vectors` `01-store/rights-evaluator` получает только `{input}`, а файл прав приходит к её нативной функции фикстурой `rights.json` (только для судьи: байты фикстуры) в `files` конверта ([единая команда векторов](../../../../common/ru/acceptance/PROFILE.md#единая-команда-векторов)). Её нативный выход — одна JSON-строка, `allow` или `deny`.
