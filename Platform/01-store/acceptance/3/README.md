Стенд, словарь директив и дверей — [общий README приёмки](../../../common/acceptance/README.md#словарь-директив-и-дверей).

## Стенд

Хранилище стенда — как у приёмки М10/11: схема 1, манифесты `testsub` и `testsub2` положены `manifest-put` через `admin.sock`
(общий README), файл прав `{rights}` — готовый вход главы 1.2 [`../2/inputs/rights.json`](../2/inputs/rights.json), раннер кладёт его до запуска хранилища. Шагам главы из него нужны только сокет роли
`console` без прав `admin` (`@as console`: сц. 08 шаг 8, сц. 15 шаги 1–2) и строки манифестов `testsub`, `testsub2` (сц. 11
шаги 9–10: копия `backup` несёт строки манифестов). Ресурс, контроллер, консоль и воркеры главе не нужны. Хранилище стенда главы —
одиночный участник коробки без `-api` (Н1.3 `-api`: флаг не обязателен; партнёров у коробки нет): сц. 16 на этом стоит.

## Чужой каталог (сц. 10)

Метка формата хранилища (глава 1.3 Н1.3 `format`; пилот хранилища, А1): второй экземпляр хранилища на непустом каталоге без
`FORMAT` и на каталоге с чужой меткой не стартует (код 2) и ничего в каталоге не меняет. Хранилище стенда сценарий не
трогает. Первая запись метки в пустой каталог и старт на своём — каждый запуск стенда и `@restart store` сц. 08.

P/03.2 Н1.5), `testsub/counters/1` `{n: "1"}`, `testsub/next_id` `{n: "2"}` по возрастанию ключа;
строк манифестов (`platform/manifest/*`) во входе нет: копия манифестов не знает, `import` переносит строку любой семьи (глава 1.3 Н1.3
`import`; журнал cammeta-go, урок 11 № 10) — сц. 11 шаги 1–3; `copy-ok-unordered.jsonl` — строки единиц в обратном порядке, без строки пола (читатель порядка не требует). `bad-*.jsonl` — по одному отказу

## Сверка python и go М10/6–11 (сц. 08 шаги 10–12, сц. 14, 15)

- Сц. 08 шаги 10–12: `floor` не целым JSON (`2.0e1`) — 400 до записи, а не 409 «только вверх»; наибольший uint64 —
  допустимый пол (Н1.3 floor `form`; B5).
- Сц. 14: память повторов `id` в копию не входит (Н1.3 `copy`). Запись с `id` `b1` на хранилище стенда, копия, перенос:
  повтор того же `id` у перенесённого — новая запись без `again`, следующий повтор — `again` (B10). Ключ `other/b10` —
  вне семей стенда, его пишет `admin`.
- Сц. 15: служебные двери (Н2). Шаги 1–2 — `@as console`: `join` и `leave` с сокета роли — 403 раньше состава (B1); шаги
  3–4 — тело `@big(1048577)` больше предела 1 МиБ — 413, у `PUT /v1/status` раньше 405 (рамка → маршрут, B2, B3); шаг 6 —
  пустые `raft`/`api` — 400 (B4); шаги 7–8 — `HEAD`. Шаг 9 сц. 15 (`door.pass` `testsub2` без воркера с дверью — 503,
  B26) перенесён шагом 1 сц. 15 [приёмки главы 6.5](../../../06-console/acceptance/5/README.md): ему нужна консоль.

## Участник без `-api` (сц. 16)

C01-STATUS-MEMBERS-NOAPI (решение «Архитектора» 2026-10-26): участник без `-api` в `members` `/v1/status` не входит,
карта одиночного участника коробки — `{}` (Н1.3 `-api`, `box`; Н2 `GET /v1/status`); `leader` — пуст. Ожидание `members`
`{}` — ровно пустая карта (словарь общего README, строка `<код> <JSON>`; ACC-EMPTY-OBJECT-01); `{"<id>": ""}` — не по форме OpenAPI урока
(`minLength: 1`) и шаг не проходит.

## Группа хранилища (сц. 07, 17, 18, 25–29)

Стенд группы — раздел «Стенд группы хранилища» общего README: члены `s1`…`s5`, `d1`, `d2` на петле, комплекты —
[`inputs/group.json`](inputs/group.json) (один центр, имя сервера листа — `<id>` члена), роль сценария у дверей `store@<id>` — `console`
(файл прав стенда). Хранилище стенда главы этим сценариям не нужно. Прежде сц. 07 было учением `@manual` на настоящем
кластере; по ПРАВИЛА-РАБОТЫ.md § 4 оно и учения пунктов чеклиста главы (дверь, размер и состав, пол эпох, ряд дверей) стали сценариями (план
`decisions/inbox/2026-10-30-план-сценарии-группы-автоматом.md`, принят «Архитектором» 2026-10-30; шаги на классы дефектов
сравнения пилота — `decisions/inbox/ревью/РЕВЬЮ-СРАВНЕНИЕ-P01-Claude.md`, П-1…П-6, где они видны снаружи). Нормы не
меняются. Лидер после `-bootstrap` и вступлений — `s1` (шаг 5 каждого сценария это и проверяет). Сборка 1→2→3: второй член вступает с `-force` (группа из двух — переходная чётность, P/01.3 Н1.3 `join`), третий — без него (C01-GROUP-BOOTSTRAP-EVEN-01). Сборка хранилища коробки
(`keys.store_build: box`, P/01.3 Н1.3 `box`) группы не имеет: сц. 07, 17, 18, 25–29 для неё — not_applicable, не красные; без
признака — не исполнены (общий README, «Стенд группы хранилища»).

- **Сц. 07 — размер и дверь без голоса.** Группа из трёх; вступление четвёртого — 409 `refused` и без `force`, и с
  `force` (сверх объявленного размера `-force` не берёт; Н1.3 `join`). Дверь `d1` (`-door -voters`): `state` `Door`, запись
  через неё — тем же файлом прав (пересылка лидеру, видна у ведомого `s2`), строка `platform/configstore-doors/d1` с
  `seen_at` не позже 40 с (каждые 30 с), ряд `configstore_doors 1` у лидера. Дверь `d2` с листом `d1` — отказ старта
  (`-id` не сервер своего листа, C01-DOOR-ID-CN-01). Пробы `door-row-*` (`inputs/`): лист двери `d1` пишет у лидера чужую
  строку `platform/configstore-doors/d2` — 403, свою — 200 (П-4; Н1.3 `door` «своя»); заголовок пересылки роли в пробе —
  обозначение, имя — из описания реализации, как в приёмке главы 1.2 сц. 08.
- **Сц. 17 — состав, перезапуск, смена лидера, кворум.** Размер 2 и 4 — отказ старта; `leave` остановленного `s3`, его
  `join` до `admit` — 403, `admit` повторяем (код 0), после него `join` тем же адресом — 200, иным адресом Raft — 409,
  `leave` неизвестного — 409 (Н1.3 `leave`, `repeat`); `s3` перезапускается и снова ведомый.
  П-1: три записи без `cas` через разных членов, перезапуск ведомого, затем всей группы — у каждого та же версия `$r3`,
  и запись с `cas` `$r3` через ведомого проходит (журнал не применяется повторно; версии одинаковы у всех).
  П-2: запись, `@sigkill` лидера — чтение у обоих оставшихся сразу после выборов видит её версию `$w`, вернувшийся `s1` —
  тоже (чтение линеаризуемо, P/01.1 Н3). П-3: дверь `d1` и один голосующий `s1` без двух других — запись через дверь и
  через `s1` — 503 `unavailable` после `leader_wait` 5 с (`@sleep 6` — срок нормы): дверь в кворум не входит.
- **Сц. 18 — `import` в группу и `recover`.** `import` копии `copy-ok.jsonl` (`index` 7) с `-index-base 7` в свежую
  группу на лидере; повтор завершённого — отказ (Н1.3 `admin_ops`, B12). П-5: перенесённые строки сохраняют версии копии — `testsub/next_id` `3`, `testsub/counters/1` `5`, и `cas` по ним проходит (P/01.3 Н1.3 `import`, Н3 «копия переигрывается ровно в те строки и версии»; C01-IMPORT-VERSIONS-01): реализация, что переписывает перенос обычными `put` с новыми малыми версиями, здесь падает. Что новые версии после переноса выше `-index-base`, сценарий числами не судит (строки сравниваются только `==`/`!=`) — чтением. Строка эпохи
  `testsub/epoch/u1` `429496729600005` (100000 << 32 | 5); большинство потеряно (`s2`, `s3` убиты, `s1` остановлен);
  `recover` без `-isolated` и с `-upper` ниже вычисленного — отказ до изменений; с `-isolated` — пол
  `100001 << 32 = 429501024567296` (поколение — upper строки эпохи, часов с 2026-01-01 меньше 100001), строки и эпоха
  сохранены (П-6: upper — из всех строк эпох). Прежние `s2`, `s3` со старыми каталогами не возвращаются (Н3 шаг 0);
  вступают новые `s4` (`-force` — переходная чётность) и `s5` из пустых каталогов, пол виден у нового ведомого.
- **П-3, лист двери на `-raft`** (C01-RAFT-DOOR-LEAF-01, решение «Архитектора» 2026-10-30): сц. 07, последний шаг —
  проба `inputs/door-on-raft.json`: лист двери `d1` на raft-порту `s1` — `handshake: alert` (P/01.3 Н1.6 `raft`).
- **Аудит покрытия P/01** (audit-kimi 2026-10-30, коммит 399e4783b): сц. 07 — проба `inputs/forwarded-admin.json`: лист
  голосующего `s2` с заголовком пересылки роли `admin` у лидера при загруженном файле прав — 403 (P/01.2 Н3, A08); сц. 17
  шаги 6–7 — ряды `/metrics` лидера и ведомого (имена Н1.3 `metrics`, состояние строчными по ADR-0070, число голосов 3;
  подстрока «3» допускает запись «3.0»; A10); сц. 17 — `@cut store@s3` (посредник на raft-порту члена рвёт входящие
  соединения; исходящие члена идут прямо): после записи через `s1` чтение у `s3` — новая версия или 503, не прежняя
  (П-2), после `@mend` — новая (NEW-DIRECTIVES § 3; кто лидер — шаги не предполагают).
- **Аудит покрытия P/01, второй проход** (Gemini 2026-10-30, коммит 6a5817f88, G06; сборка группы — шаги 1–5, как в
  сц. 07): сц. 25 — `/v1/status` двери `d1` целиком по Н2: `Door`, `role` `door`, `term`, `commit`, `applied` — 0;
  сц. 26 — пробы листа `d1` у лидера: своя строка с `cas: ""` (`inputs/door-row-with-cas.json`), с лишним элементом
  `extra` (`door-row-extra-item.json`) и её удаление (`door-row-delete.json`) — 403, своя по форме — 200 (Н1.3 `door`:
  только `put` без `cas` и `guard`, единственный `seen_at`); сц. 27 — живая дверь написала свою строку (`@until 40`),
  `import` копии `copy-ok.jsonl` с `-index-base 4` (ниже версий 5 и 6 копии) — отказ, строк нет; с `-index-base 7` —
  перенесено, версия копии сохранена (C01-IMPORT-DOOR-ROWS-01: строка двери свежести не отменяет); сц. 28 — большинство
  потеряно, `recover -peers` без своего `s1`, без адреса `api`, с повтором `s1` — отказ; `-upper 429496729700000`
  (`429496729700000 >> 32` = 100000) выше вычисленного (строк эпох и пола нет, upper 0) — пол `100001 << 32 =
  429501024567296`; сц. 29 — `import` `copy-future-floor.jsonl` (`generation_at` пола входа — 2100) без `-force` — отказ,
  ничего не перенесено, с `-force` — перенесено, пол поднят (Н1.3 `floor` `when`, «Флаги демона» `-force`).
- **Чтением остаются**: полный разрыв члена в обе стороны (исходящие соединения члена на одной машине не режутся);
  ветвь `ambiguous` (запись ушла лидеру без ответа); писатели во время `import` (окно между полом и «Готово»); лист двери
  на `-raft` теперь не чтением: сц. 07, последний шаг (ниже); нечитаемая строка двери вне `configstore_doors` (Н1.3
  `door`) — запрос TSV не несёт текущего времени для свежего `seen_at`, а строку с давним `seen_at` реализация вправе
  не считать видимой дверью по сроку (дверь пишет её каждые 30 с): шаг не отличил бы нечитаемую строку от несвежей; `recover` при часах раньше
  `generation_at` пола — стенд не ставит пол с будущим `generation_at` в группу (`op: floor` пишет часы лидера).

## Хранилище стенда: перезапуск, копия с эпохой, порча строки, память повторов, служебные двери (сц. 12, 19–24)

- Сц. 12 шаги 23–26 (A07): `import` входа со строкой эпохи `testsub/epoch/u1` `{"epoch": "abc"}` (`inputs/bad-epoch.jsonl`) и
  со строкой пола `{"floor": "12.5"}` (`inputs/bad-floor.jsonl`) — upper не достоверен, отказ всего входа, ничего не
  перенесено (Н1.3 `import`, В7 п. 3).
- Сц. 19 (A01): версия после перезапуска демона на том же каталоге — прежняя строка с прежней версией, новые версии
  отличны от неё (P/01.1 Н1 `index`); недолговечное учебное хранилище сц. 19 не исполняет, как сц. 08.
- Сц. 20 (A05): `@spoil row` / `@spoil row-index` (общий README) — порча мимо двери командой профиля `spoil-row`
  при остановленном хранилище, затем запуск: тело нечитаемо — `items: null`, версия цела, `cas` по ней заменяет строку;
  версия потеряна — 503 у чтения и задетого перечисления (P/01.1 Н2, C01-ROW-INDEX-LOST-01). Без команды профиля —
  not_executed.
- Сц. 21 (A02): память повторов `id` (P/01.1 Н3) держится не меньше двух минут — повтор через `@sleep 121` (срок нормы
  с запасом) отдаёт прежний `index` и `again`; право забыть после 2 мин и 50 000 записей — чтением. Здесь, а не в главе 1.1:
  её формат директив не несёт.
- Второй проход аудита покрытия (Gemini, G05, G06): сц. 12 шаги 27–32 — ключ строки с `..`, `generation_at` пола не
  время, часы стенда раньше `generation_at` пола входа (без `-force` директивы `@import store`) — отказ всего входа
  (Н1.3 `import`, `floor`; исходы семьи `epoch_floor`). Сц. 22 — повреждённая строка существует для стража и удаления
  (P/01.1 Н2): страж `""` — 412 с её версией, по версии — держит; удаление с `cas: ""` — 409, с `cas` по версии — строки
  нет; без команды профиля `spoil-row` — not_executed. Сц. 23 — служебные двери (Н2): лишнее поле в `join`, `leave` и
  `op: floor` и `id` участника `_bad` — 400; шаг 6 — новый пол с иным `id` проходит, значит пол шага 5 не записан
  (иначе — 409 `refused`). Сц. 24 — 405 у `POST /metrics`, `GET /v1/join`, `GET /v1/leave` (Н4).

## Полная форма и воспроизводимость (2026-10-16)

До каждого автоматического сценария остановить процессы предыдущего, создать отдельные пустые строковое/объектное хранилища и очистить переменные/память повторов. Загрузить неизменённые testsub и testsub2; root — testsub, второй доступен под /testsub2; домена нет, обращения с петли. Фоновые controller/resource/worker до @start не работают. Сборка — схема 1; отсутствие platform/schema подтверждено чтением. Для каждого POST создания единицы раннер выдаёт свежий Idempotency-Key, сохраняемый только для повторов того же шага. POST таблицы не получает этим обещания памяти повторов.

Подмножество expect не заменяет проверку полной HTTP-формы OpenAPI урока: проверить обязательные поля, типы, Content-Type, специальные заголовки и отсутствие тела у HEAD/204. В строках ожиданий `$имя` впервые связывается только после успешного совпадения всего ответа; следующие употребления сравнивают, запросы используют только уже связанные значения. Неудачная попытка @until не меняет переменные. @until повторяет чтение до указанного местного срока, не мутацию; после истечения — FAIL с последним ответом. @any допускает любое значение присутствующего поля, @absent требует отсутствия; они не подменяют типы полной схемы. JSON-объект сравнивается по подмножеству (`{}` на любом уровне — ровно пустой объект: словарь общего README, ACC-EMPTY-OBJECT-01), массив — по длине и порядку. Сырой HTML/текст сравнивается как байты UTF-8 с заданной подстрокой, не разбирается как JSON.
