## scenarios.tsv

Формат — словарь директив и дверей общего README приёмки: дверь без префикса — хранилище, `@as <роль>`, `@header` перед
методом, `$имя`, `ASSERT`; ожидание — подмножество полей, `index` может быть опущен. Своё:

- `expect` без тела у кода `403` — полная форма `{kind: forbidden, error: …}`. Для отказа операции над строкой error называет роль, действие и ключ. Для отказа личности в сценарии 08 — роль сокета `testsubworker` и причина запрета заголовка роли (допустимо указать маршрут); ключ строки не требуется, навязанная роль console не заменяет роль сокета.

Отсутствующее тело ожидания 200 не означает пустой ответ. Его форму проверяют по контракту
входа главы 1.1; 403 — ровно строки kind/error без полей консоли. `$имя` связывается только
после совпадения всего шага; повтор переменной сравнивается с прежним значением. Порядок
ключей в list остаётся порядком хранилища, раннер не сортирует фактический ответ.

Роли сценариев: `console`, `testsubcontroller`, `testsubworker`, `testsub2worker`, `admin`.

Сверка python и go М10/6–11 (R12): сц. 05 шаги 8–10 — `never` и пустой `<y>`; сц. 08 шаг 2 — заголовок роли раньше тела.

## Изоляция

Каждый сценарий, включая повторный запуск, получает отдельный экземпляр с пустыми
прикладными строками и памятью повторов id. Очистка префиксов не подменяет очистку этой
памяти. Переменные раннера сбрасываются, роль задаётся первым `@as`; файл прав одинаков
во всех сценариях. Параллельные запуски не разделяют экземпляр.

Фоновые консоли, контроллеры, воркеры и ресурс в эти строки не пишут. Данные разрешений
готовит раннер файлом `inputs/rights.json` и настройкой экземпляра, а каждый шаг выполняет только
названная роль.

## Проверки вне сценарного файла

- Сверить весь JSON `/v1/rights` с загруженным файлом под admin; иной роли — 403, без
  загруженного файла — 404. Проверить грамматику роли, отсутствие внутренних ролей,
  обязательные массивы, неизвестные поля, delete отсутствует / [] / отдельный список.
  comment отсутствует либо является строкой и возвращается как загружен; число/null/объект
  вместо comment — отказ. Изменение только comment не меняет эффективных прав; --check
  сравнивает по смыслу (P/02.5 Н3 «установить»): comment и порядок образцов не сравниваются. Проверить также установленный файл прав реализации.
- Проверить отрицание перед и после разрешения, точный ключ и префикс, звёздочку в
  середине, неизвестную роль, never для admin и обычной роли, отдельное право чтения стража.
  У list нет проверки read; доверие личности остаётся обязательным.
  Для admin и обычных ролей проверить отдельно write/delete platform/epoch_floor;
  соседний обычный ключ не должен попасть в never. Доверенная пересылка admin без файла
  разрешена вне never; с загруженным файлом отказана. Недоверенная пересылка запрещена
  в обоих режимах, включая list. Это отдельные пробы, TSV их не исполняет.

Это предметы отдельного чтения/структурного теста, а не дополнительные исполненные
сценарии. Режимы сокетов, пересылка и сертификат требуют соответствующего стенда.

В сценарии 08 имя X-Configstore-Role — обозначение заголовка доверенной пересылки роли.
Перед прогоном подставить имя из описания реализации (Н3/«Решает реализация», п. 3);
значение console и роль сокета не менять. Это не нормативное имя заголовка. При отсутствии
такой настройки подготовка прогона не завершена. Считать запрещённую подмену личности,
а не последующий отказ записи ключа.
