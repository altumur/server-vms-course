Канон главы. [Лекция](../01-store.md), [контракт](01-store.api.openapi.yaml), [инструкция](01-store.README.md),
[приёмка](../acceptance/3/README.md). Глава перенесена из М10/11

воркеры по заказу, выпуск сертификатов, установка и команды оператора перенесены в [P/02.4](../../02-installer/spec/02.4-installer.norms.md) (стадия B); отказ сервера — в [P/04](../../04-controller/spec/04-controller.norms.md) Н1.4а, `door.pass` — в
[P/06.5](../../06-console/spec/06.5-console.norms.md) Н1.8 (перенос урока 6). «Глава 1.K» — глава этого урока. Id норм — `P/01.3-MM`;
соответствие прежним id — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля — [глава 1.1 Н0](01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Поля времени строк и объектов главы — время по [канону Н0 главы 1.1](01.1-store.norms.md#время-в-строке): `platform/configstore-doors/<id>` — `seen_at`; пол `platform/epoch_floor` — [P/03.2](../../03-worker/spec/03.2-worker.norms.md).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `platform/configstore-doors/<id>`, `platform/epoch_floor`;
- читает: `<sub>/epoch/<id>` (upper пола, Н1.3 floor), `/etc/w2c/configstore-rights.json` (флаг -rights, [глава 1.2](01.2-store.norms.md) Н1.2), `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/ca.next.pem`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem`, `/etc/w2c/tls/<роль>/server.pem`, `/etc/w2c/tls/<роль>/server.key` (флаг -tls, Н1.6).

### Н1.3 Хранилище

```yaml
daemon:
  flags:   закрытый набор — таблица «Флаги демона» ниже; -socket снят: путь сокетов один — -sockets (пилот хранилища, А3)
  refuse_start: -bootstrap с -join; group-size не из {1,3,5}; адрес вне петли без -tls; сертификат двери у голосующего;
           нет -dir; нет -id при -join, -door или -group-size 3 | 5; метка FORMAT не своя (format ниже) — все отказы старта: код 2
           (RestartPreventExitStatus=2 — ошибку конфигурации не перезапускать; ревью стадии B 1–2, п. 9)
  tuning:  lan — пульс 500 мс, выборы 500 мс, аренда лидера 250 мс; слово оператора в configstore.env
group:
  sizes:   1 | 3 | 5 — одинаково на всех серверах
  join:    демон стартует первым, потом вступает: спросить /v1/status, стартовать с партнёрами, POST /v1/join;
           чётная — 409 refused без -force (с -force — переходное состояние пересборки); больше объявленной — 409 refused и с -force; member.json помнит партнёров и how — рестарт не вступление
  leave:   выход; вышедший не принимается назад (403 / raft) до admit <id> на admin.sock лидера
  identity: демоны — mTLS сертификатами центра (CN configstore.<server>, SAN DNS <server>, URI urn:w2c:role:configstore);
           сертификат несёт одну роль; -api и -join только с -tls; дополнительный секрет транспорта — решает реализация
leader_wait: 5 с от потери лидера (не на запрос) → 503 unavailable; запись, ушедшая лидеру без ответа → ambiguous (глава 1.1)
sockets:   плоско: <-sockets>/admin.sock и <-sockets>/<роль>.sock, подкаталогов нет (пилот хранилища, А3);
           унаследованные (протокол sd_listen_fds: LISTEN_FDS, LISTEN_FDNAMES) демон берёт по FileDescriptorName=admin |
           <роль>: режим и группу задал юнит (P/02.4 Н1.1); имя не admin и не роль файла прав — отказ старта, код 2, лог
           называет имя; сокет, которого не передали, демон создаёт сам в -sockets: admin.sock 0600, <роль>.sock 0660
           с группой процесса (пилот хранилища, А10);
           admin.sock 0600 (root; всё кроме never главы 1.2; не пересылается); <роль>.sock 0660 группа роли;
           заголовок роли на сокете роли → 403; пересылке лидеру верят только от демона группы — голосующего или двери без голоса — по роли в SAN (глава 1.2 Н3)
door:      -door -id -voters a@h:p,…: без голоса; те же сокеты и права; к лидеру или любому голосующему (попытка 2 с, запас 1 с);
           состав группы — каждые 5 с; строка platform/configstore-doors/<id> {seen_at} каждые 30 с (не под platform/doors/ — там двери серверов, P/05 Н1.4);
           её пишет сама дверь: запросом лидеру по mTLS своей ролью configstore-door (пересылка ролей главы 1.2 Н3), командой
           put своей строки без cas и guard, единственный элемент seen_at; иная запись от роли configstore-door — 403;
           admin.sock дверь не трогает и его запросов не пересылает (журнал cammeta-go, урок 11 № 3); считается в
           configstore_doors; все голосующие недоступны → 503 unavailable; join/leave не делает
format:    в -dir — файл FORMAT, JSON-объект {format, version, impl} (строка, целое, строка): format и version — формат
           на диске этой реализации, impl — имя реализации, только для лога; демон пишет его первым в пустой каталог
           (tmp + rename), до любой другой записи; старт: каталог пуст → записать FORMAT; format и version — те, что
           читает эта сборка → старт; иначе (каталог не пуст, а FORMAT нет; чужие format или version; FORMAT не по
           форме) → отказ старта, код 2, лог называет каталог и найденную метку; в каталоге ничего не пишется и не
           удаляется. Смена реализации — только копией (copy ниже) в свежий каталог (пилот хранилища, А1)
copy:      копия backup и вход import/restore — один формат для всех реализаций, JSON Lines: UTF-8, строка — один
           JSON-объект, конец строки LF; первая строка — заголовок
           {"format": "w2c-configstore-copy", "version": 1, "index": <версия>}: index — версия хранилища (Version главы 1.1),
           на которой снята копия, не меньше index любой строки копии; дальше — по строке на ключ: {key, items, index}
           (items и index — как Row главы 1.1) или {key, items: null, index, unreadable: true} — повреждённая строка как
           прочитана (Row главы 1.1); писатель кладёт ключи по возрастанию байтов UTF-8, читатель порядка не требует;
           platform/epoch_floor — обычная строка; память повторов id (глава 1.1 Н3) в копию не входит; копия манифестов не знает —
           строки любых семей, проверка семей у import не нужна (import ниже);
           другие format или version, лишнее или недостающее поле, строка не JSON или не по Row, повтор ключа, index
           строки выше index заголовка — отказ всего входа до первой записи (Н4); строка unreadable во входе — тоже
           отказ (Н4). Копия одной реализации восстанавливается другой (пилот хранилища, А2)
admission: время приёма записи (глава 1.1 Н3 «Время приёма») — в каждой записи журнала raft и в снимке raft вместе со
           строками: снимок несёт время приёма последней вошедшей в него записи, и демон, поднятый из снимка, продолжает от
           него; на коробке (`box` ниже) — в каталоге данных тем же барьером, что строки. Копия copy его не несёт
           (глава 1.1 Н3). admission_ahead — в /v1/status лидера (и коробки): на сколько секунд время приёма последней
           записи впереди его часов, если больше CLOCK_SKEW 60 с (глава 1.1 Н0 «Часы кластера»); иначе поля нет; у
           ведомого и двери без голоса поля нет. Пока признак стоит, записи с not_after по часам писателей получают
           expired — часы лидера ушли вперёд и вернулись (ADR-0091 п. 1)
durability: переменной окружения или флага эксплуатации, которые выключают барьеры долговечности (глава 1.1 «Решает
           реализация» п. 3), нет; стенд приёмки, которому нужна скорость, говорит это флагом своей команды «Стенда»
           (общий README приёмки), юниты P/02.4 Н1.1 его не ставят; учебное хранилище без долговечности называет это в
           описании («Решает реализация» п. 2) (пилот хранилища, А10)
admin_ops: status | join [-force] | leave [id] | admit <id> | backup <файл> (0600, tmp + rename) | restore --from [-force]
           | import --from <копия> [-index-base N] [-force] | recover -id -dir -peers … -isolated [-upper N] [-force] | rights [-groups]
           import/restore/floor в группе (raft) — только на admin.sock лидера, до первой строки; на коробке (`box` ниже) —
           в свежий каталог остановленного демона; recover — локально на остановленном демоне (лидера нет,
           большинства нет — Н3 «восстановить»), не через сокет; status/backup/leave себя — у любого;
           backup <файл>: путь файла (после разрешения ссылок) вне -dir демона, иначе отказ до записи, код ≠ 0, каталог
           данных не тронут: копия в собственный журнал живого демона портит его (сверка python и go М10/6–11, B8);
           import в каталог, где прежний import уже завершён (Н3 фаза «Готово»), — отказ, код ≠ 0, ничего не меняется;
           незавершённую попытку повтор продолжает (import ниже) (сверка python и go М10/6–11, B12)
floor:                                        # platform/epoch_floor {floor, generation_at}
  generation: max((upper >> 32) + 1, целых часов UTC с 2026-01-01); floor = generation << 32;
              upper — максимум из floor строки platform/epoch_floor и epoch каждой строки <sub>/epoch/<id> (P/03.2 Н1.5)
              во всём проверенном входе и в сохранённом состоянии демона (у свежей группы его нет); ни одной строки — 0;
              пример в 2026-10-17T12:30Z (6948 целых часов): upper 5 → generation max(1, 6948) = 6948, floor 29841432772608;
              upper 30064771072005 (7000 << 32 | 5) → generation max(7001, 6948) = 7001, floor 30069066039296;
              оператор должен подтвердить, что выше upper прежняя установка ничего не выдавала (например, копия после
              остановки писателей);
              upper ≥ текущего floor и всех сохранённых epoch. Нет достоверной границы потерянного хвоста — отказ восстановления
  when:    restore, import — до первой строки: в группе только op: floor на admin.sock лидера, на коробке — первой записью
           в каталог остановленного демона (`box`); recover — локально в дампе остановленного
           демона (сокета нет, Н3 «восстановить» шаг 1); строка не
           пишется put/delete; только растёт; часы раньше generation_at → отказ без -force; force разрешает только
           часы назад, но не повтор/понижение поколения, переполнение uint64 или параллельное восстановление
  form:    floor в op: floor — целое JSON без дроби и экспоненты (`20`, не `2.0e1` и не `20.0`), 1 … 2^53 − 2^32; иное — 400
           badrequest до записи (сверка python и go М10/6–11, B5); эпохи — целые JSON < 2^53 (ADR-0070), поэтому пол
           оставляет над собой 2^32 номеров: generation ≤ 2^21 − 1 (часов с 2026-01-01 хватит на ~239 лет); generation,
           которая дала бы больше, — отказ восстановления, как переполнение (добавлено пилотом схем семей данных, Д6)
  issue:   next_epoch = max(текущая, floor) + 1 (P/03.2); выдача, прочитавшая пол до подъёма, может записать номер
           ниже floor — такую эпоху воркер не запускает: подтверждение после записи (P/03.2 Н3 «взять_эпоху(id)»; добавлено
           пилотом Quint, F1)
import:    из неизменяемой копии (copy выше) в свежую группу: -index-base ≥ наибольшей версии; полная предварительная
           проверка до изменения пола/любой строки: форма copy (строка Row, ключ по главе 1.1 Н1, размер не выше потолка
           строки), версии (база, index заголовка) и эпохи — строка <s>/epoch/<id> с epoch не десятичным целым или
           platform/epoch_floor с floor не десятичным — upper не достоверен; копия манифестов не знает: семьи строк import не
           проверяет, строка любой семьи переносится (журнал cammeta-go, урок 11 № 10). Плохая строка, размер, база,
           эпоха — без изменений.
           После публикации пола отказ может оставить часть строк; повтор продолжает ту же попытку с тем же полом,
           новая попытка — новое поколение. Обычные писатели до завершения не допускаются
metrics:   configstore_raft_term, _state{state}, _elections_total, _index{kind=last|commit|applied}, _last_contact_seconds,
           _voters, _voters_expected, configstore_doors; тревоги: состав ≠ объявленному, ведомый отстал > 1000, выборов > 3 за 10 мин
box:       хранилище коробки — сборка без raft, один голосующий: -group-size 3 или 5 и -join — отказ старта с кодом 2
           («this build has no raft»); /v1/status — state Leader, term 1, leader — его адрес -api (пусто без -api),
           leader_id — его id, voters [<id>],
           members {<id>: <api>} (без -api — {}, C01-STATUS-MEMBERS-NOAPI); /metrics — ряды выше значениями одного участника (term 1, elections_total 1, last_contact 0,
           voters 1, voters_expected 1, doors 0); join своего id — 200 {}, чужого — 409 refused и с -force; leave — 409 refused
           («the last voter»); admit — отказ, код ≠ 0; recover — отказ, код 2 («this build has no raft»): у коробки нет
           группы, восстановить её нечем, копия — import (сверка python и go М10/6–11, B15); import/restore на коробке — в свежий каталог остановленного демона,
           не через admin.sock (в группе — admin.sock лидера, `admin_ops` выше): пол первой записью, затем строки; restore
           совпадает с import (соседей нет)
repeat:    операции состава повторяемы: admit уже допущенного верного id — код 0, состав и строки не меняются; повтор join
           того же id с тем же адресом Raft — обновляет адрес API; join id с иным адресом Raft и leave неизвестного id —
           409 refused, без изменений (догадка стадии C CL-03, решение «Архитектора» 2026-10-23)
```

**Флаги демона** — закрытый набор (пилот хранилища, А3, А8). Флаг вне таблицы — отказ старта, код 2.

| Флаг | Тип | Умолчание | Смысл |
|---|---|---|---|
| `-dir` | путь | нет: обязателен, без него отказ старта, код 2 | каталог данных демона; метка `FORMAT` (`format` выше) |
| `-id` | id участника (Н2) | в группе (`-join`, `-door`, `-group-size 3` или `5`) нет: обязателен; иначе — `SERVER_NAME` (P/02.4 Н1.2) | имя участника в `members`, `voters`, `leader_id` |
| `-sockets` | путь каталога | `/run/configstore` | каталог сокетов, плоско (`sockets` выше) |
| `-rights` | путь файла | нет: без него — только `admin.sock` (глава 1.2 Н1.2) | файл прав |
| `-tls` | путь каталога | нет: без него адрес вне петли — отказ старта | корень комплектов сертификатов (Н1.6), mTLS `-raft` и `-api` |
| `-raft` | `host:port` | нет | адрес raft, который демон называет партнёрам |
| `-raft-bind` | `host:port` | `-raft` | адрес, на котором демон слушает raft, если он отличается от названного |
| `-api` | `host:port` | нет: без него служебной HTTP-двери для партнёров нет | адрес служебных дверей Н2 для партнёров; значение `members` и `leader` в `/v1/status`; без `-api` участника в `members` нет (карта может быть `{}`; C01-STATUS-MEMBERS-NOAPI, решение «Архитектора» 2026-10-26) |
| `-bootstrap` | без значения | выключен | первый сервер группы (`join` выше); с `-join` — отказ старта |
| `-join` | `host:port` | нет | адрес `-api` участника группы, через которого демон вступает (`join` выше) |
| `-group-size` | `1` \| `3` \| `5` | `1` | объявленный размер группы, одинаковый на всех серверах |
| `-force` | без значения | выключен | вступление при переходной чётности (`join` выше); у `restore`, `import`, `recover` — только отказ по часам |
| `-isolated` | без значения | выключен | только у `recover`, обязателен: оператор подтверждает, что прежняя группа и писатели изолированы и выше upper ничего не выдавалось (Н3 шаг 0); без него `recover` — отказ до изменений (догадка стадии C S02, решение «Архитектора» 2026-10-23) |
| `-upper` | целое 0 … 2^53 − 1 | нет | только у `recover`: известная оператору граница потерянного хвоста эпох; только поднимает вычисленный upper (`floor.generation`): upper := max(вычисленный, N); N ниже вычисленного — отказ до изменений (догадка стадии C S02, решение «Архитектора» 2026-10-23) |
| `-peers` | список `id@<raft host:port>/<api host:port>` через запятую | нет: у `recover` обязателен | только у `recover`: восстановленный состав — оставшиеся участники, восстанавливаемый (`-id`) среди них; id и оба адреса у каждого обязательны: raft — адрес состава raft, api — значение `members` в `/v1/status`; иная запись — отказ до изменений (догадка стадии C S03, решение «Архитектора» 2026-10-23) |
| `-door` | без значения | выключен | дверь без голоса (`door` выше) |
| `-voters` | список `id@host:port` через запятую | нет | голосующие для двери без голоса: id и адрес `-api` |
| `-tuning` | `default` \| `lan` \| `slow` | `default` | профиль сроков raft (`tuning` выше) |
| `-leader-wait` | срок | `5s` | ожидание лидера (`leader_wait` выше) |
| `-max-value` | байты, > 0 (`0` и не число — отказ старта, код 2; сверка python и go М10/6–11, B7) | `512KiB` | потолок строки (глава 1.1 Н4, `{row_ceiling}` «Стенда») |
| `-max-body` | байты, > 0 (как `-max-value`) | `1MiB` | предел чтения HTTP-тела `POST /v1/write` (глава 1.1 Н2, `{body_limit}` «Стенда»), отдельно от потолка строки `-max-value` (журнал cammeta-python, урок 11 № 24) |
| `-max-conns`, `-api-conns`, `-api-per-address` | целое > 0 | 64, 32, 8 | пределы соединений (ниже) |
| `-index-base` | целое ≥ 0 | 0 | у `import`: база версий (`import` выше) |

Числа max-conns=64, api-conns=32, api-per-address=8 — умолчания профиля, не скрытый
выбор каждой реализации. Развёртывание может задать другие положительные пределы до
начала прогона и назвать их в описании; предел соединений даёт 503 `unavailable` с `Retry-After: 1` (глава 1.1 Н4).

### Н1.6 Сертификаты: сторона проверяющего пира

Демон хранилища проверяет TLS-пира на `-raft` и `-api` (деление М10/11-11, `id-map.tsv`: CN и SAN, роль `configstore`
или `configstore-door`, алгоритмы подписи цепочки, доверие `ca.pem` и `ca.next.pem`, отзыв без перезапуска). Строки ниже —
прежние строки М10/11 Н1.6 в части,
которую исполняет проверяющий демон; выпуск, центр, комплекты прочих ролей и их двери — [P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md) (стадия B).

Форма сертификата, закрытый список подписей, комплект, отзыв и следующий центр — общий [договор сертификата роли](../../common/contracts/role-certificate.md)
(`cert`, `sig`, `kit`, `revoke`, `rotation`; ревью стадии B 1–2, п. 4). Демон проверяет пира по нему; роли демона:

```yaml
roles:        configstore, configstore-door (демоны — всегда с -tls)
```

## Н2 Двери

Двери главы — у демона хранилища (глава 1.1: `/v1/get`, `/v1/list`, `/v1/write`) и его служебные:

HTTP-контракт: [01-store.api.openapi.yaml](01-store.api.openapi.yaml).

Все собственные JSON-ответы имеют полные схемы, метрики — text/plain, без фиктивного пустого JSON вместо текста.

| HTTP-дверь | Полная форма / правило |
|---|---|
| GET `/v1/status` | `{id, state, leader, leader_id, term, commit, applied, voters, members, tls, max_value}`; optional `base, again, role, last_snapshot, out, admission_ahead` (Н1.3 `admission`; ADR-0091 п. 1). Индексы — точные uint64, state — Leader/Follower/Candidate/Shutdown/Door; voters/out — массив id, members — карта id → адрес `-api`, без `-api` участника в `members` нет (карта может быть `{}`; значение пустым не бывает — `minLength: 1` OpenAPI; C01-STATUS-MEMBERS-NOAPI, решение «Архитектора» 2026-10-26); `leader` — адрес `-api` лидера (пусто, если лидер неизвестен или запущен без `-api`), `leader_id` — id лидера (пусто, если лидер неизвестен) (пилот хранилища, А7). Door требует role=door и term/commit/applied=0. Это локальное наблюдение, не подтверждение большинства |
| POST `/v1/join` | `{id, raft, api, force?}`, успех 200 `{}`; 409 `{kind: refused, error}` — недопустимый состав; 403 — `ForbiddenFault` главы 1.1: зовут только `admin.sock` и демон группы по mTLS роли `configstore` (Н1.3 `identity`); сокет роли (`console.sock` и прочие) — 403 до разбора состава (сверка python и go М10/6–11, B1); пустые `raft`, `api` — 400 до состава (B4) |
| POST `/v1/leave` | `{id}` (пустая строка — себя), успех 200 `{}`; сокет роли — 403, как у join (B1); изменение чужого состава — только административный допуск Н1.3; у коробки без raft выход последнего голоса — 409 `{kind: refused, error}` «the last voter» (Н1.3 `box`) |
| GET `/v1/rights` | Точная форма и отказы главы 1.2, доступность admin/роль/пересылка по её Н3 |
| POST `/v1/write` | Обычный Cmd главы 1.1 либо `{op: floor, floor: целое 1 … 2^53 − 2^32, id: 1–64 строчных hex}` на admin.sock лидера. Повтор floor с тем же id возвращает сохранённый исход — память повторов та же, что у записи с id (глава 1.1 Н3 «Повтор по идентификатору»): в хранилище, с его долговечностью и теми же сроками — долговечное переживает перезапуск демона, недолговечное учебное («Решает реализация» п. 2) теряет при перезапуске и пол, и память, и говорит это в описании; другой payload с этим id — отказ 400 badrequest главы 1.1 (не конфликт CAS); новый id с floor ≤ нынешнего — 409 refused (строка главы 1.1 Н4). Успех — Written главы 1.1. Обычная запись floor через put/delete запрещена |
| GET `/metrics` | Перечень текстовых рядов Н1.3; корректное экранирование меток |

Идентификатор участника — 1–128 ASCII-символов: первый буква/цифра, дальше буквы/цифры/`_`/`.`/`-`. Это профиль входов данного урока. Разбор запроса служебных дверей — глава 1.1 Н2.1 (query, JSON тела, путь байт в байт, HTTP, ранний отказ); отступления ниже. Порядок проверок: рамка (framing, предел тела 1 МиБ — 413) → маршрут и метод (404, 405) → личность (403) → тело и состав (400, 409): лишнее тело больше предела у чужого метода — 413 раньше 404/405 (сверка python и go М10/6–11, B3). `HEAD` служебным дверям не метод: `/v1/status`, `/v1/join`, `/v1/leave`, `/metrics` — 405, `/v1/write` и `/v1/rights` — 404 по владельцам — главам 1.1 и 1.2 (обе реализации, совпало без нормы). Тела служебных POST — один объект JSON; unknown fields отвергаются; предел чтения 1 МиБ, фактический счёт байтов, лишний JSON/framing/обрыв — 400, превышение — 413, время чтения ограничено реализацией. 400/404/405 — `BadRequestFault`, 403 — `ForbiddenFault`, 413 — `BodyTooLargeFault` главы 1.1. Для собственных status/join/leave/write/metrics 503 — `UnavailableFault` до отправки, `AmbiguousFault` после отправки изменения; при пределе соединений — `UnavailableFault` с `Retry-After: 1` (глава 1.1 Н4). После неизвестного join/leave оператор читает status; автоматического доказательства успеха из таймаута нет. Пол сохраняет память повторов главы 1.1.

CLI `backup` читает согласованное состояние хранилища строк — копия переигрывается ровно в те строки и версии, что видел демон на одном индексе в момент копии (способ — «Решает реализация» п. 4), — создаёт 0600 временный файл и публикует rename; отказ не заменяет прежнюю копию. `restore/import` принимают неизменяемый вход, из которого вычисляется upper по Н1.3, работают по фазам Н3; результат — код 0 только после полной проверки переноса, иначе ненулевой с фазой и путём. `recover` — локальная процедура остановленного демона, не HTTP: обязательный `-isolated` и необязательный `-upper N` (Н1.3 «Флаги демона», Н3 шаг 0). `admit <id>` — административная команда лидера для ранее вышедшего; 0 после подтверждения, ненулевой/неизвестный исход требует чтения состава. Текст stdout этих CLI не является машинным JSON-контрактом.

## Н3 Проход

### восстановить хранилище (большинства нет)

```
0. один оператор изолирует все прежние демоны и писателей (включая отключённые узлы от последующего возврата);
   сохраняет исходные каталоги/копию, проверяет upper и весь вход. Подтверждение изоляции — флаг -isolated команды recover:
   нет его — отказ до изменений, код ≠ 0; известная оператору граница потерянного хвоста — -upper N, только поднимает
   вычисленный upper, ниже вычисленного — отказ до изменений (догадка стадии C S02, решение «Архитектора» 2026-10-23); взаимное исключение запусков recover/restore/
   import — «Решает реализация» п. 6
1. на одном остановленном демоне: configstore recover -id <я> -dir … -peers <оставшиеся> -isolated [-upper N] [-force при часах назад]
   → дамп и журнал переписаны, строки членов отсутствующих сняты, platform/epoch_floor поднят на поколение
2. стартовать только объявленный восстановленный состав; остальные вступают последовательно из новых пустых каталогов
   после сохранения старых (второй/четвёртый — с -force при переходной чётности, не сверх объявленного размера)
3. ушедшие навсегда — leave у лидера; вернувшиеся после leave — admit
4. процессы, читавшие другую ревизию манифеста, перезапускаются (P/02.3); воркеры читают пол на шаге аренды (P/03.2 Н3 «шаг_аренды()»): единица с
   эпохой ниже пола теряет аренду и запускается заново выше пола (P/03.2) — перезапуск процессов для этого не нужен
```

**Гонки: допуск и переходы восстановления.** Ручное действие само по себе не исключает двух операторов. В уроке разрешена только одна попытка на установку, с подтверждённым отсечением прежней группы; конкурентные recover/restore/import запрещены.

| Фаза | Что разрешено | Что сохраняется при отказе |
|---|---|---|
| Изоляция | Остановить/отсечь старых участников, зафиксировать неизменяемый вход и upper | Старые данные; новая группа ещё не запускается |
| Проверка | Проверить все строки (форма, ключ, размер), базу, эпохи и upper, границы uint64; семьи строк — только `recover` своего дампа: у всех строк — конверт строки, ключ по каталогу, версия, размер; схемы — только семей самого хранилища (P/01) и upper; содержимое прочих семей не толкуется и сохраняется как есть — схемы дело их владельцев (догадка стадии C S04, решение «Архитектора» 2026-10-23); копия `copy` манифестов не знает (Н1.3 `import`) | Ни пол, ни строки не изменены |
| Новый пол | Один раз прочно поднять floor выше upper; op: floor имеет свой id повтора | При неизвестном ответе повторить тем же id, не вычислять новое поколение |
| Перенос | Записывать строки той же попытки; прочный прогресс для продолжения | Возможен частичный перенос; обычные писатели запрещены |
| Готово | Проверить полноту, разрешить обновлённый состав/писателей | Прежняя группа остаётся отсечённой; запускаются только эпохи не ниже floor — выданная со старым полом lost (P/03.2 Н3 «взять_эпоху(id)») |

Переполнение поколения/uint64 — отказ до изменений. `-force` не отменяет ни одной из этих проверок. Если невозможно получить достоверный upper потерянного хвоста, гарантия неповторения эпох недоказуема и восстановление по этому профилю не выполняется.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **секрет транспорта raft** сверх mTLS, если есть, и его оборот при отзыве;
2. **долговечность хранилища** (fsync, снимки raft: порог, интервал, хвост) — учебное хранилище может быть не долговечным, и это сказано в его описании (ADR-0070 п. 4); флаг стенда, который выключает барьеры, — в команде «Стенда», не в окружении (Н1.3 `durability`);
3. **учёт соединений демона** и переопределения пределов развёртыванием, `-tuning` для медленных сетей; нормативные умолчания — Н1.3;
4. **как `backup` получает согласованное состояние работающего демона** (Н2); требование к копии — норма Н2, не выбор.
5. **метку формата и профиль `file://`**: значения `format` и `version` своей метки `FORMAT` и какие версии своего формата читает сборка (Н1.3 `format`); формат на диске профиля `file://`; команду, которой с хранилища `file://` снимается копия Н1.3 `copy` (форма копии — норма) (пилот хранилища, А1, А2, А9).
6. **взаимное исключение запусков** `recover`, `restore`, `import` на одной установке (замок, файл-метка) — норма требует одной попытки (Н3 «Гонки: допуск и переходы восстановления»), способ — выбор (догадка стадии C S02).

## Чеклист готовности

Реализация соответствует главе, когда выполнена каждая норма; id нормы `P/01.3-MM` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **P/01.3-01** демон: флаги Н1.3, хранилище коробки без raft (`box`) — сц. 04 и чтением, `members` без `-api` — `{}` (сц. 16), отказы старта, размер 1/3/5, вступление и `-force`, `leave`/`admit`, mTLS, ожидание лидера 5 с, сокеты — учения; сц. 04, 07; три ветви 503 (нет лидера 5 с, ambiguous, unavailable с Retry-After при пределе соединений) — чтением Н1.3/Н4: сценарии не снимают большинство и не насыщают соединения
- [ ] **P/01.3-02** дверь без голоса: без raft, те же права, пересылка, строка `seen_at` собственной записью роли `configstore-door` (только эта строка), 503 без голосующих — учение 07
- [ ] **P/01.3-03** пол эпох: upper и формула поколения по часам с примером Н1.3, память повторов `floor` в хранилище, только вверх, только admin, `recover`/`restore`/`import` поднимают до первой строки — учение 06 ([системная приёмка](../../common/acceptance/system/README.md)); память повторов `floor` после перезапуска, только вверх (тот же и меньший пол с новым id — 409), только admin (ролевой сокет — 403) — сц. 08; `recover` без `-isolated` и с `-upper` ниже вычисленного — отказ до изменений, `-upper` только поднимает upper — учение 06 системной приёмки и чтением теста CLI реализации (догадка стадии C S02)
- [ ] **P/01.3-04** `import`/`restore`: свежая группа, неизменяемый вход, база ≥ наибольшей; неверный вход без изменений, после пола возможен частичный перенос, повтор той же попытки — чтением; причина — TSV не воспроизводит ошибку каждой строки и частичное восстановление после пола
- [ ] **P/01.3-05** метрики демона Н1.3 — сц. 04 (два ряда); остальные ряды и три тревоги — проверяется чтением: тест метрик реализации (предмет — перечень Н1.3); `configstore_doors` — число строк `platform/configstore-doors/<id>` — чтением: стенд не поднимает дверь без голоса, счёт видит учение 07 (решение «Архитектора» по хвостам переноса урока 1)
- [ ] **P/01.3-06** метка `FORMAT`: отказ старта с кодом 2 на чужом и непустом безметочном каталоге без изменений — сц. 10; первая запись метки в пустой каталог, старт на своём — сц. 08 шаг 2 (`@restart store`); копия `copy` — одна форма для `backup` и `import`, отказ входа целиком — сц. 11, 12; `restore` той же формой и копия другой реализации — чтением и матрицей ADR-0083 п. 5; флаги демона — закрытая таблица, `-dir` и `-id` в группе обязательны, плоские сокеты, унаследованные по `FileDescriptorName` — чтением: тест юнитов и флагов реализации (пилот хранилища)
- [ ] **P/01.3-07** служебные двери (сверка python и go М10/6–11): порядок «рамка → маршрут → личность → тело», 413 раньше 405, `join`/`leave` с сокета роли — 403, пустые `raft`/`api` — 400, `HEAD` — 405/404 — сц. 15; пол — целое JSON < 2^53: запись float и наибольший uint64 — 400, 2^53 − 2^32 допустим — сц. 08 шаги 10–12 (ревью стадии B 1–2, п. 8); память повторов не в копии — сц. 14; `-max-value` > 0 — чтением: тест флагов реализации (стенд флаги демона не задаёт)
- [ ] **P/01.3-08** жизненный цикл (сверка python и go М10/6–11): цель `backup` вне `-dir` — сц. 11 шаг 11 (`@backup store … in-data`); повтор завершённого `import`, `recover` на коробке — код 2 — чтением: тест CLI хранилища реализации (директивы `@backup`/`@import` пишут файл раннера и каждый раз свежий каталог, этих случаев не дают)
- [ ] **P/01.3-10** время приёма в записи журнала и снимке, продолжение от снимка, `admission_ahead` в `/v1/status` лидера сверх 60 с (Н1.3 `admission`) — проверяется чтением: стенд не двигает часы лидера и не снимает снимок по требованию
- [ ] **P/01.3-09** проверка TLS-пира демоном Н1.6: CN и SAN, одна роль `configstore` или `configstore-door`, алгоритмы подписи цепочки, доверие `ca.pem` и `ca.next.pem`, отзыв по содержимому без перезапуска — проверяется чтением: тесты реализации на тестовой CA (предмет — Н1.6: без сертификата, чужая CA, отозванный, чужая роль, своя); причина — CA и файловые права не меняются HTTP-TSV
