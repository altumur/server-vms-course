<!-- req: P/01.3-R037 -->
`daemon.flags` — The daemon MUST accept only the closed flag set of [forms/daemon-flags.tsv](../forms/daemon-flags.tsv); there is no flag `-socket`: the socket path is one, `-sockets`.

<!-- req: P/01.3-R038 -->
`daemon.refuse_start` — When the daemon refuses to start for any cause of this chapter, it MUST exit with code 2 (`RestartPreventExitStatus=2`: a configuration error is not restarted). If the data directory is owned by a live daemon, then the daemon MUST refuse to start (P/01.3-R181). If `-bootstrap` is given with `-join`, then the daemon MUST refuse to start. If `-group-size` is not from {1,3,5} (`group.sizes`), then the daemon MUST refuse to start. If any declared or listening address (`-api`, `-raft`, `-api-bind`, `-raft-bind`) is off the loopback without `-tls`, then the daemon MUST refuse to start with `start_config`, code 2. If a voter is started with a door certificate, then the daemon MUST refuse to start. If `-door` is given without `-voters`, then the daemon MUST refuse to start. If there is no `-dir`, then the daemon MUST refuse to start. If there is no `-id` and no `SERVER_NAME`, then the daemon MUST refuse to start. If there is no `-id` with `-join`, `-door` or `-group-size 3` | `5`, then the daemon MUST refuse to start. At TLS startup, both a voter and a door MUST verify that `-id` equals the server identity of their own leaf certificate (CN/SAN); a mismatch is a `start_config` refusal. If on a box the directory holds an unfinished `import`/`restore` attempt (after the floor, before the phase «Done» of N3), then the daemon MUST refuse to start; in a group — R156. If the directory holds the phase mark of an interrupted `recover` (N3 «recover the store» step 1), then the daemon MUST refuse to start. If the mark `FORMAT` is not its own (P/01.3-R088), then the daemon MUST refuse to start. If flags of a start mode that the build or the mode does not have are given (R164–R167), then the daemon MUST refuse to start.

`daemon.tuning` — The profile `lan` of `-tuning` MUST set the heartbeat 500 ms, the elections 500 ms and the leader lease 250 ms; the profile is the operator's word in `configstore.env`. The numeric settings of `default` and `slow` are chosen and documented by the implementation (Implementation decides, item 3); this lesson fixes no values for them.

<!-- req: P/01.3-R053 -->
`group.sizes` — The declared size of a group MUST be one of `1`, `3`, `5`; the set is `-group-size` of [forms/daemon-flags.tsv](../forms/daemon-flags.tsv). The declared size of a group MUST be the same on all servers.

<!-- req: P/01.3-R054 -->
`group.join` — When a daemon joins a group, it MUST start first and then join: ask `/v1/status`, start with the partners, `POST /v1/join`. If a joining makes the group even and `-force` is not given, then it MUST be 409 `refused`. If a joining makes the group even and `-force` is given, then it is a transitional state of reassembly. If a joining makes the group larger than declared, then it MUST be 409 `refused`, even with `-force`. The daemon MUST remember the partners and how it joined in `member.json`: a restart is not a joining.

<!-- req: P/01.3-R058 -->
`group.leave` — If one who left joins again before `admit <id>` on `admin.sock` of the leader, then the group MUST NOT accept it back (403 / raft).

<!-- req: P/01.3-R059 -->
`group.identity` — Daemons MUST verify each other by mTLS with certificates of the CA (CN `configstore.<server>`, SAN DNS `<server>`, URI `urn:w2c:role:configstore`). A certificate of a daemon of the group carries one role. The declared and listening addresses (`-api`, `-raft`, `-api-bind`, `-raft-bind`) MAY run without `-tls` only when all are on the loopback (the local box); any address off the loopback requires `-tls` (P/01.3-R038). `-join` MUST always come with `-tls` (group traffic). An additional transport secret is decided by the implementation («Implementation decides» item 1).

<!-- req: P/01.3-R063 -->
`leader_wait` — If there is no leader for the effective `-leader-wait` interval from the loss of the leader (not per request), then the request MUST get 503 `unavailable`.

<!-- req: P/01.3-R064 -->
`leader_wait` — If a write has gone to the leader without an answer, then its outcome MUST be `ambiguous` (chapter 1.1).

<!-- req: P/01.3-R065 -->
`sockets` — The sockets MUST be flat: `<-sockets>/admin.sock` and `<-sockets>/<role>.sock`; the daemon makes no subdirectories for the sockets. This is the layout of the sockets themselves, not a demand on the directory: an entry of another name in `-sockets`, a subdirectory among them, MUST NOT be a start refusal ([forms/refusals.tsv](../forms/refusals.tsv) has no such cause).

<!-- req: P/01.3-R067 -->
`sockets` — When sockets are inherited (the `sd_listen_fds` protocol: `LISTEN_FDS`, `LISTEN_FDNAMES`), the daemon MUST take them by `FileDescriptorName=admin` | `<role>`: the mode and the group were set by the unit (P/02.4 N1.1). If an inherited socket has a name that is neither `admin` nor a role of the rights file, then the daemon MUST refuse to start, code 2, and the log names the name.

<!-- req: P/01.3-R069 -->
`sockets` — When a socket was not passed, the daemon MUST create it itself in `-sockets`. When the daemon creates `admin.sock` itself, the socket MUST get the mode 0600. When the daemon creates `<role>.sock` itself, the socket MUST get the mode 0660. When the daemon creates `<role>.sock` itself, the socket MUST get the group of the process. The daemon MUST NOT take the group of a `<role>.sock` that it creates itself from the role: the group is that of the process whether or not the OS has a group of the role.

<!-- req: P/01.3-R070 -->
`sockets` — `admin.sock` is 0600 (root). `admin.sock` gives everything except `never` of chapter 1.2. `admin.sock` is not forwarded: at a follower its changes are `admin_not_leader` (R118).

<!-- req: P/01.3-R071 -->
`sockets` — `<role>.sock` is 0660. An inherited `<role>.sock` has the group of the role: `SocketGroup=` of its unit (P/01.2-R043); the daemon does not change its mode or group.

<!-- req: P/01.3-R072 -->
`sockets` — If a role header comes on a role socket, then the daemon MUST answer 403 (for the service doors — the row `sc-identity` of [forms/service-checks.tsv](../forms/service-checks.tsv)).

<!-- req: P/01.3-R073 -->
`sockets` — The daemon MUST trust a forwarding to the leader only from a daemon of the group — a voter or a door without a vote — by the role in SAN (chapter 1.2 N3).

<!-- req: P/01.3-R074 -->
`door` — A door without a vote is started with `-door -id -voters a@h:p,…`: without a vote. A door without a vote has the same sockets and rights as a voter. A door without a vote holds no replica of the rows.

<!-- req: P/01.3-R075 -->
`door` — The door MUST pass a request to the leader or to any voter (an attempt `DOOR_REQUEST_TIMEOUT`, the margin `DOOR_REQUEST_MARGIN`).

<!-- req: P/01.3-R076 -->
`door` — The door MUST read the group membership every `DOOR_MEMBERS_EVERY`.

<!-- req: P/01.3-R077 -->
`door` — The door MUST write the row `platform/configstore-doors/<id>` `{seen_at}` every `DOOR_SEEN_EVERY` (not under `platform/doors/` — there are the doors of servers, P/05 N1.4). The door MUST write this row itself: by a request to the leader over mTLS with its own role `configstore-door` (forwarding of roles of chapter 1.2 N3). The write of this row MUST be the command `put` of its own row without `cas` and `guard`, the only element `seen_at`. If the role `configstore-door` makes any other write, a batch `op: batch` included, then it MUST get 403.

<!-- req: P/01.3-R080 -->
`door` — When a foreign batch passes through the door, the door MUST forward it whole, in one request (chapter 1.1 N3 «write batch»).

<!-- req: P/01.3-R081 -->
`door` — «Own» is `<id>` = the server from the verified certificate of the peer (CN `configstore-door.<server>` / SAN DNS); if a claimed identity of the door (`<id>` of the key, the door name in the forwarding header) is not equal to it, then the write MUST get 403, nothing is written. `Cmd.id` of the replay memory (P/01.1) is not an identity: the daemon MUST NOT compare it with the server.

<!-- req: P/01.3-R083 -->
`door` — The door MUST NOT touch `admin.sock`. The door MUST NOT forward the requests of `admin.sock`.

<!-- req: P/01.3-R084 -->
`door` — A door MUST be counted in `configstore_doors` while its row reads in its own form and `seen_at` in it is not older than `DOOR_SEEN_PERIODS × DOOR_SEEN_EVERY` by the clock of the voter that gives the series (where and by whose clock — [forms/metrics.tsv](../forms/metrics.tsv)). If a door row does not read in its own form, then it MUST NOT be counted as a visible door. If a door row does not read in its own form, then the reason MUST go to the log of the leader without the value.

<!-- req: P/01.3-R086 -->
`door` — If all voters are unreachable, then the door MUST answer 503 `unavailable`.

<!-- req: P/01.3-R087 -->
`door` — After the request and identity checks of P/01.3-R221, the body form of P/01.3-R212/P/01.3-R223 and the own-membership check of P/01.3-R419, `join` and `leave` on a door MUST return 409 `refused` (`door_membership`, N4); no membership changes or forwarding occur.

<!-- req: P/01.3-R088 -->
`format` — In `FORMAT`, `format` and `version` MUST name the on-disk format of this implementation; `impl` is the name of the implementation, only for the log. The daemon MUST write `FORMAT` first into an empty directory (tmp + rename), before any other write. When the daemon starts and the directory is empty, it MUST write `FORMAT`. When the daemon starts, `format` and `version` are those that this build reads and the start mode is that of the directory (R402), it MUST start. If the directory is not empty but there is no `FORMAT`, then the daemon MUST refuse to start, code 2; the log names the directory and the mark found; nothing is written to or removed from the directory. If `format` or `version` of `FORMAT` is foreign, then the daemon MUST refuse to start, code 2; the log names the directory and the mark found; nothing is written to or removed from the directory. If `FORMAT` is out of form, then the daemon MUST refuse to start, code 2; the log names the directory and the mark found; nothing is written to or removed from the directory.

<!-- req: P/01.3-R092 -->
`format` — A change of implementation MUST go only by a copy (`copy`) into a fresh directory.

<!-- req: P/01.3-R402 -->
`format` — A directory MUST keep the start mode in which its `FORMAT` was written: a box, a voter of a group or a door without a vote (R163, R306, R307); how it keeps it is the implementation's choice (for example, in `format` of its `FORMAT`). If the daemon starts in another start mode on a non-empty directory, then it MUST refuse to start with `start_format`, code 2; the log names the directory and the mode found; nothing is written to or removed from the directory. If an offline `import` or `restore` goes into a directory of a group or a door, or `recover` into a directory of a box or a door, then it MUST be a refusal with `start_format`, code ≠ 0; nothing changes. A change of the start mode of a directory MUST go only by a copy (`copy`) into a fresh directory, as a change of implementation (R092).

<!-- req: P/01.3-R093 -->
`copy` — The backup copy and the import/restore input MUST be one format for all implementations: JSON Lines — UTF-8, a line is one JSON object. Every line, including the header, uses the door's strict JSON rules through the [shared json contract](../../common/contracts/json.md): a repeated member name in any object, BOM, non-JSON numbers (`NaN`, `Infinity`), non-UTF-8 bytes or depth beyond `JSON_DEPTH` refuse the whole input as `copy_input` before any effect. Every object, including the last, ends with LF. CRLF and EOF before that LF refuse the whole input as `copy_input` before any store change (P/01.3-R100). The first line of the copy MUST be the header `{"format": "w2c-configstore-copy", "version": 1, "index": <version>}`. `index` of the header is the version of the store at which the copy is taken, a JSON string as `Version` of chapter 1.1. `index` of the header MUST NOT be smaller than the `index` of any row of the copy. The exact store version used as header `index`, including for an empty store, is decided by the implementation and is not judged beyond the `Version` form and the lower bound set by the row indexes. After the header the copy MUST have a line per key: `{key, items, index}` (`items` and `index` as `Row` of chapter 1.1) or `{key, items: null, index, unreadable: true}` — a damaged row as read (`Row` of chapter 1.1). The writer MUST put the keys in ascending order of UTF-8 bytes.

<!-- req: P/01.3-R295 -->
`copy` — The reader of the copy MUST NOT require an order of the keys. `platform/epoch_floor` is included as an ordinary input row for upper and the `generation_at` clock check. `platform/epoch_floor` of the input MUST NOT be transferred. The id replay memory (chapter 1.1 N3) MUST NOT be part of the copy. The copy knows no manifests: rows of any families; a family check at import is not needed (P/01.3-R145).

<!-- req: P/01.3-R100 -->
`copy` — If the input has another `format` or `version`, then the whole input MUST be refused before the first write (N4). If the input has an extra or a missing field, then the whole input MUST be refused before the first write (N4). If an input line is not JSON, not by `Row`, uses CRLF or reaches EOF before its LF (P/01.3-R093), then the whole input MUST be refused as `copy_input` before the first write. If multiple input rows have the same `key` value, then the whole input MUST be refused before the first write (N4). If the input has an `index` of a row higher than the `index` of the header, then the whole input MUST be refused before the first write (N4). If an unreadable row is in the input, then the input MUST also be refused (N4). A copy of one implementation MUST be restorable by another.

<!-- req: P/01.3-R103 -->
`batch` — A batch (chapter 1.1 N3 «write batch») MUST be one raft log record: applied on all servers whole, it has one version and one admission time.

<!-- req: P/01.3-R104 -->
`batch` — On a box (`box`) and in the store `file://` a batch MUST have the atomicity property of the same chapter; the way is chapter 1.1 «Implementation decides» item 3. The copy `copy` MUST be taken between batches: it carries no half of a batch.

<!-- req: P/01.3-R106 -->
`admission` — The admission time of a record (chapter 1.1 N3 «Admission time») MUST be in every raft log record. The admission time MUST be in the raft snapshot together with the rows: the snapshot carries the admission time of the last record that entered it. A daemon raised from the raft snapshot MUST continue from the admission time that the snapshot carries.

<!-- req: P/01.3-R107 -->
`admission` — On a box (`box`) the admission time MUST be kept in the data directory with the same barrier as the rows. The copy `copy` MUST NOT carry the admission time (chapter 1.1 N3).

<!-- req: P/01.3-R109 -->
`admission` — If the admission time of the last record is ahead of the clock of the leader (or of a box) by more than `CLOCK_SKEW` (chapter 1.1 N0 «Cluster clocks»), then `/v1/status` of the leader (and of a box) MUST carry `admission_ahead`, by how many seconds; otherwise there is no field ([forms/status-fields.tsv](../forms/status-fields.tsv)).

<!-- req: P/01.3-R365 -->
`admission` — `/v1/status` of a follower and of a door without a vote MUST NOT carry `admission_ahead` ([forms/status-fields.tsv](../forms/status-fields.tsv)). While the flag stands, writes with `not_after` by the writers' clocks get `expired`: the leader's clock went ahead and came back.

<!-- req: P/01.3-R111 -->
`durability` — There MUST be no environment variable and no flag that turns off the durability barriers (chapter 1.1 «Implementation decides» item 3): the flag set is closed ([forms/daemon-flags.tsv](../forms/daemon-flags.tsv)), the stand and the units of P/02.4 N1.1 run the store with the barriers.

<!-- req: P/01.3-R112 -->
`durability` — A teaching store without durability MUST name this in its description («Implementation decides» item 2). `admin_ops` — `backup <file>` MUST write the file by R229 (0600) and P/01.3-R229 (tmp + rename).

<!-- req: P/01.3-R424 -->
`durability` — Proven corruption of a complete journal record with a complete intact record after it MUST cause daemon startup to refuse with exit code 2, without truncating or otherwise changing the input. This applies to a box and to a group, including the last journal segment. A proven unfinished append at the tail with no complete record after it is a separate case.

<!-- req: P/01.3-R114 -->
`admin_ops` — In a group (raft) `import` and `restore` MUST go only on `admin.sock` of the leader; their floor raise before the first transferred row follows R367. An ordinary `op: floor` follows R215.

<!-- req: P/01.3-R115 -->
`admin_ops` — On a box (`box`) `import` and `restore`, including their first floor write, MUST go into a fresh directory of a stopped daemon (R175). This restriction belongs to the transfer; an ordinary `op: floor` on the running box follows R215.

<!-- req: P/01.3-R116 -->
`admin_ops` — `recover` MUST run locally on a stopped daemon (there is no leader, no majority — N3 «recover»), not through a socket. `status`, `backup` and `leave` of oneself MAY run at any member.

<!-- req: P/01.3-R118 -->
`admin_ops` — On a follower's admin.sock, writes (Cmd/batch/floor), import/restore/admit and join/leave of another member MUST give `admin_not_leader`: 503 `unavailable`, no Retry-After or changes. No forwarding; repeat at `leader_id` of `/v1/status`. If the CLI sends such a request at a follower, then the CLI MUST be a refusal, code ≠ 0; nothing changes. The visible `admin_not_leader` refusal MUST follow request/identity/body-form errors but precede write-checks.tsv, membership errors and reading an import/restore copy. For join/leave the body id MUST distinguish oneself (R119) from another member before `admin_not_leader` can apply.

<!-- req: P/01.3-R119 -->
`admin_ops` — When `leave` or `join` of oneself comes at a follower, the daemon MUST pass it to the leader by an internal operation of the group, not by forwarding the authority of `admin.sock`.

<!-- req: P/01.3-R120 -->
`admin_ops` — `join [-force]`: the local daemon MUST send to the group its own join `{id: -id, raft: -raft, api: -api, force}` (`POST /v1/join` of N2) through the address of `-join` or the known leader; a repeat obeys `repeat`; on a box — join of its own id (P/01.3-R169).

<!-- req: P/01.3-R121 -->
`admin_ops` — If the path of the file of `backup <file>` (after resolving links) is not outside `-dir` of the daemon, then the CLI MUST refuse before writing, code ≠ 0, the data directory untouched: a copy into the own log of a live daemon spoils it.

<!-- req: P/01.3-R122 -->
`admin_ops` — If `import` goes into a directory where a former `import` has already finished (N3 phase «Done»), then it MUST be a refusal, code ≠ 0, nothing changes; an unfinished attempt is continued by a replay (P/01.3-R151).

<!-- req: P/01.3-R123 -->
`floor.generation` — A raise of the floor MUST compute the generation and the floor by `floor.generation`; example at 2026-10-17T12:30Z (6948 whole hours): upper 5 → generation max(1, 6948) = 6948, floor 29841432772608; upper 30064771072005 (7000 << 32 | 5) → generation max(7001, 6948) = 7001, floor 30069066039296. An epoch row of upper and of the checks of `import`, `restore` and `recover` MUST be the epoch row of never of chapter 1.2 (P/01.2-R122): `<x>/epoch/<y>`, an empty `<y>` included, not only the rows `<sub>/epoch/<id>` of P/03.2 N1.5. upper MUST be the maximum of `floor` of the row `platform/epoch_floor` and `epoch` of every epoch row in the whole verified input and in the saved state of the daemon (a fresh group has none); not a single row — 0; upper ≥ the current floor and all saved epochs.

<!-- req: P/01.3-R125 -->
`floor.generation` — The operator MUST confirm that the former installation handed out nothing above upper (for example, a copy after the writers were stopped). If there is no reliable bound of the lost tail, then the recovery MUST be refused.

<!-- req: P/01.3-R127 -->
`floor.when` — `restore` and `import` MUST raise the floor before the first row; on a box — as the first write into the directory of a stopped daemon (`box`, P/01.3-R175).

<!-- req: P/01.3-R367 -->
`floor.when` — In a group `restore` and `import` MUST raise the floor only by `op: floor` on `admin.sock` of the leader.

<!-- req: P/01.3-R128 -->
`floor.when` — `recover` MUST raise the floor locally in the dump of a stopped daemon (no socket, N3 «recover» step 1). The row `platform/epoch_floor` MUST NOT be written by `put`/`delete`. The floor MUST only grow.

<!-- req: P/01.3-R131 -->
`floor.when` — If the clock is earlier than `generation_at` and `-force` is not given, then the raise MUST be refused. `-force` allows only the clock going back: with `-force` a clock earlier than `generation_at` does not refuse the raise; a uint64 overflow stays a refusal (R027). `-force` MUST NOT allow a repeat or a lowering of the generation. `-force` MUST NOT allow a parallel recovery.

<!-- req: P/01.3-R132 -->
`floor.when` — If the current row `platform/epoch_floor` has `floor` or `generation_at` that does not read in the form of its family, then `op: floor` MUST be 409 `refused` (`floor_unreadable`), nothing is written, the log names the row. If instead its items read but its version is lost, `op: floor` MUST return 503 `unavailable` (`version_lost`, P/01.1-R212), without changing the row, issuing a version or occupying its id; the log names the row. For either damage, `restore`, `import` and `recover` MUST refuse as `recovery_unsafe` without changes; the current floor is not reset.

<!-- req: P/01.3-R134 -->
`floor.form` — If `floor` in `op: floor` is not a JSON integer without a fraction or an exponent (`20`, not `2.0e1` and not `20.0`) in 1 … 2^53 − 2^32, then it MUST be 400 `badrequest` before writing. Epochs are JSON integers < 2^53, so the floor leaves 2^32 numbers above itself: the generation MUST be ≤ 2^21 − 1 (hours since 2026-01-01 suffice for ~239 years). If a generation would give more, then the recovery MUST be refused, as an overflow.

<!-- req: P/01.3-R137 -->
`floor.issue` — An issue MUST give `next_epoch = max(current, floor) + 1` (P/03.2). An issue that read the floor before the raise can write a number below the floor — the worker does not start such an epoch: a confirmation after the write (P/03.2 N3 «take_epoch(id)»).

<!-- req: P/01.3-R138 -->
`import` (fresh) — import/restore MUST use an immutable copy and a fresh group: no rows except `platform/configstore-doors/<id>`; its periodic live-door updates (R077) do not cancel freshness. Continuation follows R151; the box follows R175.

<!-- req: P/01.3-R139 -->
`import` (door_rows) — During the transfer the write of a live door, like those of ordinary writers, MUST wait for «Done». A door row in the input MUST be transferred like a row of any family; the live door rewrites its own.

<!-- req: P/01.3-R140 -->
`import` (versions) — Transferred rows MUST keep the versions of the copy (`index` of the input row); `restore` the same.

<!-- req: P/01.3-R141 -->
`import` (base) — New versions MUST be higher than any version in the group, of door rows too. The base of new versions of `restore` is `index` of the header of the copy (`restore` has no `-index-base`): every write after the transfer MUST get a version above it and above any version of the group. `-index-base` MUST be ≥ the greatest version of the input. `-index-base` is the start of new versions: every write after the transfer MUST get a version above the base and above any version of the group. Copy versions may coincide with versions previously issued for fresh-group door rows. A door row MAY return to a lower version; the door rewrites it without cas above the base within 30 s (P/01.3-R077). The ordering comparisons of copy/import/restore for header and row indexes, bases and new versions (including F1) use decimal numeric values (`"10"` > `"9"`); caller opacity by P/01.1-R166 remains unchanged.

<!-- req: P/01.3-R145 -->
`import` (check) — import/restore MUST check the whole copy before any floor/row change: form (P/01.3-R093, P/01.3-R295, P/01.3-R100), keys/sizes, base (P/01.3-R141), epochs; any violation refuses without changes. If a key of an input row is not by chapter 1.1 N1, then `import` and `restore` MUST refuse without changes. If the size of an input row is above the row ceiling, then `import` and `restore` MUST refuse without changes. On a box the row ceiling of the check MUST be `-max-value` of the command `import`/`restore`, its default is that of the daemon in [forms/daemon-flags.tsv](../forms/daemon-flags.tsv). In a group the row ceiling of the check MUST be the effective `-max-value` of the leader. If an epoch row (P/01.3-R123) has `epoch` not a decimal integer, then upper is not reliable and the whole input MUST be refused. If `platform/epoch_floor` has `floor` not decimal, then upper is not reliable and the whole input MUST be refused. If an epoch or floor row is unreadable (outcomes of the families `epoch`, `epoch_floor`), then upper is not reliable and the whole input MUST be refused. `import` (families) — The copy knows no manifests: `import` MUST NOT check the families of rows; a row of any family is transferred.

<!-- req: P/01.3-R149 -->
`import` (floor_first) — The transfer MUST exclude the input `platform/epoch_floor`. For import/restore in either mode, the first write MUST be new F1: index above the base and all destination-issued versions, generation_at at the raise. Continuation keeps its exact index (R151); other input rows keep copy versions (R140).

<!-- req: P/01.3-R150 -->
`import` (complete) — Completeness MUST be every input row except that old floor, plus the new floor row.

<!-- req: P/01.3-R151 -->
`import` (replay) — A partial replay MUST preserve the exact saved F1 row (`items` and `index`). A partial replay MUST NOT copy back the old floor. A partial replay MUST NOT raise F1 again. A failure after F1 may leave partial rows. The same input bytes MUST continue that attempt with the same floor; byte-comparison mechanism is the implementation's choice. If another input comes before «Done», then it MUST be a refusal without changes (`import_other_input`, code ≠ 0).

<!-- req: P/01.3-R154 -->
`import` (replay) — A new full attempt with a new generation MUST come only after `recover` (N3 «recover the store»).

<!-- req: P/01.3-R155 -->
`import` (held_writers.box) — Until completion a box daemon MUST NOT start, exit 2; the log says to repeat import with the same input (P/01.3-R038).

<!-- req: P/01.3-R156 -->
`import` (held_writers.group) — In a group the daemon MUST start on such a directory. A group MUST hold writers until continuation through the leader's admin.sock: 503 `unavailable` (`import_held`), as R413 requires. The wait of held writers MUST obey the declared budget. While writers are held, reads MUST answer as the store `file://` (R159). If the majority is lost while writers are held, then the way out is `recover` (N3 «recover the store»). In a group `restore` MUST follow the same rule, because its phases are common with `import`.

<!-- req: P/01.3-R158 -->
`import` (held_writers.group) — `box` is the store without raft: a raft group, including one of a single voter (`-group-size 1`), is a group.

<!-- req: P/01.3-R159 -->
`import` (held_writers) — On a directory whose `import` or `restore` is not completed, the store `file://` in the process MUST answer writes and reads with 503 `unavailable`; the directory does not change.

`metrics` — `/metrics` MUST give the series of [forms/metrics.tsv](../forms/metrics.tsv), each by its emitter, labels, type and value rule.

### N1.6 Certificates: the side of the verifying peer

the part

counts:       the daemon log

<!-- req: P/01.3-R208 -->

<!-- req: P/01.3-R209 -->

<!-- req: P/01.3-R210 -->
`counts` — The count of invalid rereads of `revoked`/`crl.pem` and of stale CRLs (the revoke contract) MUST be lines of the daemon log; there are no `/metrics` series (the list of [forms/metrics.tsv](../forms/metrics.tsv) is closed).

### Snapshot output and orderly stop

<!-- req: P/01.3-R034 -->
A copy MUST pin one immutable version of the state. Blocking external output MUST run outside the lock that serializes ordinary mutations. The implementation declares finite bounds for lock wait, output, cancellation and orderly stop. A stalled receiver MUST NOT retain the mutation lock until transmission finishes. Success, failure and cancellation MUST release snapshot and transport ownership. An unrelated operation may keep its existing bounded pre-effect refusal; that response alone does not prove correct lock scope.

<!-- req: P/01.3-R277 -->
On stop, the daemon MUST cease admitting new work. A request that is read but not yet admitted at that moment gets 503 `unavailable`. On stop, connections whose request has not been read MUST be closed. On stop, the daemon MUST cancel or bound external I/O. On stop, the daemon MUST resolve or classify admitted work by its existing definite/ambiguous outcomes. On stop, the daemon MUST retire owned snapshots, connections and listeners within the declared orderly-stop bound. The orderly-stop bound MUST fit below the actual service-manager stop deadline with a separately measured teardown margin. The manager's old example is not a Go Shutdown budget; forced kill is not orderly success.

<!-- req: P/01.3-R349 -->
Raft Barrier is not evidence of a storage durability barrier. A Raft Shutdown return is not proof that the platform has drained its work.

<!-- req: P/01.3-R420 -->
**Scope: production.** On the declared workload/resource envelope, the implementation MUST complete and publish a whole backup within `BUDGET_BACKUP_ORDINARY` or `BUDGET_BACKUP_WORST` of the [performance goals](production-acceptance.md#performance-goals), and MUST meet `BUDGET_BACKUP_STALL` for concurrent ordinary reads and writes when a backup sink stalls. These goals preserve the one-index, publication and lock-scope obligations.

<!-- req: P/01.3-R421 -->
**Scope: production.** On the declared workload/resource envelope, the orderly stop of P/01.3-R277 MUST complete within `BUDGET_STOP` of the [performance goals](production-acceptance.md#performance-goals), from stop delivery through orderly exit and resource release. The declared stop bound remains below the actual manager deadline with teardown margin; a forced kill does not meet the goal.

<!-- req: P/01.3-R422 -->
**Scope: production.** On the declared workload/resource envelope, startup after a crash MUST restore ordinary read/write service within `BUDGET_REOPEN` of the [performance goals](production-acceptance.md#performance-goals). The interval starts with the daemon process start, including opening and replaying its state, and ends only when the restored service preserves the acknowledged state and can complete ordinary operations. The conditions of those goals apply; a separate required administrative recovery is not an ordinary reopen.

<!-- req: P/01.3-R423 -->
**Scope: production.** On the declared `WORKLOAD_ORDINARY` envelope, a restarted member of a group with restored connectivity and a viable quorum MUST return healthy within `BUDGET_MEMBER_RETURN` of the [performance goals](production-acceptance.md#performance-goals). From process start to healthy return the interval includes state opening, catch-up and renewed participation in group progress. The stable member id and membership are preserved; answering status alone does not establish healthy return.

<!-- req: P/01.3-R281 -->
Import's complete-input check, exact versions and floor/progress phases remain unchanged. Construction obeys [P/01.1 Persistence cost](01.1-store.norms.md#persistence-cost).

## Implementation decides

Each implementation names in its description:

1. **the raft transport secret** beyond mTLS, if there is one, and its rotation on revocation; the raft wire between members and the frame of `admin.sock`
   (read-fence, admit, import) remain internal to the implementation: a format with a name and a version, no new HTTP routes. The copy transfer itself uses the explicitly declared GET /v1/copy of N2; the members of one
   store cluster are one implementation, a mix of languages — only by clients through `configstore:///`;
2. **the durability of the store** (fsync, raft snapshots: threshold, interval, tail) — a teaching store MAY be non-durable, and this is said in its description; there is no flag or environment variable that turns the barriers off (N1.3 `durability`);
3. **the connection accounting of the daemon** and overrides of the limits by deployment, `-tuning` for slow networks; the normative defaults are N1.3;
4. **how `backup` obtains a consistent state of a running daemon** (N2); the requirement on the copy is a norm of N2, not a choice.
5. **the format mark and the profile `file://`**: the values `format` and `version` of its mark `FORMAT` and which versions of its format the build reads (N1.3 `format`); the on-disk format of the profile `file://`; the command by which a copy of N1.3 `copy` is taken from a store `file://` (the form of the copy is a norm).
6. **mutual exclusion of runs** of `recover`, `restore`, `import` on one installation (a lock, a mark file) — the norm requires one attempt (N3 «Races: admittance and recovery transitions»), the way is a choice. This also declares exclusive live-daemon ownership of `-dir`, refusal of a second daemon and local operations, and release on every process termination by N1.3, and the form and place of the phase mark of `recover` (N3 «recover the store» step 1).
7. **the internal contract of `file://`** (item 5): the format of the profile `file://` is the implementation's own, not a public contract. Its description
   and the library API are written in the implementation's repository by the owner of this chapter before the code: the physical layer and the command layer — conditional
   `put`/`delete` with `guard`, the batch `batch`, CAS by version, `not_before`/`not_after`, outcomes and refusal words as at the store door (P/01.1 N1,
   N4; without retelling the norms), with vectors from its own code. Other processes of the implementation (the installer, the worker) read only
   the contract and the API; a mix of languages on `file://` is not supported — through `configstore:///`.
8. **the finite budgets of this chapter**: the response-write budget, the commit wait, the number of door attempts and the replay-processing limit (R035), the limit of `admin.sock` (R008), the disk and descriptor budgets (R036). Each MUST be finite and positive; this chapter sets no value, flag or default for them. The implementation declares the value; the threshold of production acceptance is approved separately from the implementation, and a claim of the candidate alone is not enough.
