### N1.3 Store

<!-- req: P/01.3-R006 -->
```yaml
daemon:
  flags:        forms/daemon-flags.tsv
  refuse_start: exit 2
  tuning:       lan
group:
  sizes:        1 | 3 | 5
  library:      Go — github.com/hashicorp/raft (R180)
  join:         GET /v1/status, POST /v1/join, member.json
  leave:        POST /v1/leave, admit <id>
  identity:     mTLS; CN configstore.<server>, SAN DNS <server>, URI urn:w2c:role:configstore

sockets:   <-sockets>/admin.sock 0600, <-sockets>/<role>.sock 0660

durability: forms/daemon-flags.tsv
admin_ops: status | join [-force] | leave [id] | admit <id> | backup <file> | restore --from [-max-value N] [-force]
           | import --from <copy> [-index-base N] [-max-value N] [-force] | recover -id -dir -peers … -isolated [-upper N] [-force] | rights [-groups]
floor:                                        # platform/epoch_floor {floor, generation_at}
  generation: max((upper >> 32) + 1, whole hours of UTC since 2026-01-01); floor = generation << 32

metrics:   forms/metrics.tsv
box:       no -raft, no -door
repeat:    admit <id>, join, leave [id]
```

<!-- req: P/01.3-R037 -->
- `daemon.flags` — The daemon MUST accept only the closed flag set of [forms/daemon-flags.tsv](../forms/daemon-flags.tsv); there is no flag `-socket`: the socket path is one, `-sockets`.

<!-- req: P/01.3-R038 -->
- `daemon.refuse_start` — When the daemon refuses to start for any cause of this chapter, it MUST exit with code 2 (`RestartPreventExitStatus=2`: a configuration error is not restarted).

<!-- req: P/01.3-R039 -->
- `daemon.refuse_start` — If the data directory is owned by a live daemon, then the daemon MUST refuse to start (R184).

<!-- req: P/01.3-R040 -->
- `daemon.refuse_start` — If `-bootstrap` is given with `-join`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R041 -->
- `daemon.refuse_start` — If `-group-size` is not from {1,3,5} (`group.sizes`), then the daemon MUST refuse to start.

<!-- req: P/01.3-R042 -->
- `daemon.refuse_start` — If an address of `-api` or `-raft` is off the loopback without `-tls`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R043 -->
- `daemon.refuse_start` — If a voter is started with a door certificate, then the daemon MUST refuse to start.

<!-- req: P/01.3-R044 -->
- `daemon.refuse_start` — If `-door` is given without `-voters`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R045 -->
- `daemon.refuse_start` — If there is no `-dir`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R046 -->
- `daemon.refuse_start` — If there is no `-id` and no `SERVER_NAME`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R284 -->
- `daemon.refuse_start` — If there is no `-id` with `-join`, `-door` or `-group-size 3` | `5`, then the daemon MUST refuse to start.

<!-- req: P/01.3-R047 -->
- `daemon.refuse_start` — If with `-door` the `-id` is not equal to the server of its certificate (CN/SAN), then the daemon MUST refuse to start.

<!-- req: P/01.3-R048 -->
- `daemon.refuse_start` — If on a box the directory holds an unfinished `import`/`restore` attempt (after the floor, before the phase «Done» of N3), then the daemon MUST refuse to start; in a group — R156.

<!-- req: P/01.3-R049 -->
- `daemon.refuse_start` — If the directory holds the phase mark of an interrupted `recover` (N3 «recover the store» step 1), then the daemon MUST refuse to start.

<!-- req: P/01.3-R050 -->
- `daemon.refuse_start` — If the mark `FORMAT` is not its own (R091, R358, R359), then the daemon MUST refuse to start.

<!-- req: P/01.3-R051 -->
- `daemon.refuse_start` — If flags of a start mode that the build or the mode does not have are given (R164–R167), then the daemon MUST refuse to start.

<!-- req: P/01.3-R052 -->
- `daemon.tuning` — The profile `lan` of `-tuning` MUST set the heartbeat 500 ms, the elections 500 ms and the leader lease 250 ms; the profile is the operator's word in `configstore.env`.

<!-- req: P/01.3-R053 -->
- `group.sizes` — The declared size of a group MUST be one of `1`, `3`, `5`; the set is `-group-size` of [forms/daemon-flags.tsv](../forms/daemon-flags.tsv).

<!-- req: P/01.3-R285 -->
- `group.sizes` — The declared size of a group MUST be the same on all servers.

<!-- req: P/01.3-R054 -->
- `group.join` — When a daemon joins a group, it MUST start first and then join: ask `/v1/status`, start with the partners, `POST /v1/join`.

<!-- req: P/01.3-R055 -->
- `group.join` — If a joining makes the group even and `-force` is not given, then it MUST be 409 `refused`.

<!-- req: P/01.3-R352 -->
- `group.join` — If a joining makes the group even and `-force` is given, then it is a transitional state of reassembly.

<!-- req: P/01.3-R056 -->
- `group.join` — If a joining makes the group larger than declared, then it MUST be 409 `refused`, even with `-force`.

<!-- req: P/01.3-R057 -->
- `group.join` — The daemon MUST remember the partners and how it joined in `member.json`: a restart is not a joining.

<!-- req: P/01.3-R058 -->
- `group.leave` — If one who left joins again before `admit <id>` on `admin.sock` of the leader, then the group MUST NOT accept it back (403 / raft).

<!-- req: P/01.3-R059 -->
- `group.identity` — Daemons MUST verify each other by mTLS with certificates of the CA (CN `configstore.<server>`, SAN DNS `<server>`, URI `urn:w2c:role:configstore`). The transport of the group is the key `transport` of [forms/group.tsv](../forms/group.tsv).

<!-- req: P/01.3-R286 -->
- `group.identity` — A certificate of a daemon of the group carries one role.

<!-- req: P/01.3-R060 -->
- `group.identity` — `-api` and `-raft` on the loopback MAY run without `-tls` (the local box); outside the loopback they require `-tls` (R042).

<!-- req: P/01.3-R061 -->
- `group.identity` — `-join` MUST always come with `-tls` (group traffic).

<!-- req: P/01.3-R062 -->
- `group.identity` — An additional transport secret is decided by the implementation («Implementation decides» item 1).

<!-- req: P/01.3-R063 -->
- `leader_wait` — If there is no leader for the effective `-leader-wait` interval from the loss of the leader (not per request), then the request MUST get 503 `unavailable`.

<!-- req: P/01.3-R064 -->
- `leader_wait` — If a write has gone to the leader without an answer, then its outcome MUST be `ambiguous` (chapter 1.1).

<!-- req: P/01.3-R065 -->
- `sockets` — The sockets MUST be flat: `<-sockets>/admin.sock` and `<-sockets>/<role>.sock`; the daemon makes no subdirectories for the sockets.

<!-- req: P/01.3-R066 -->
- `sockets` — This is the layout of the sockets themselves, not a demand on the directory: an entry of another name in `-sockets`, a subdirectory among them, MUST NOT be a start refusal ([forms/refusals.tsv](../forms/refusals.tsv) has no such cause).

<!-- req: P/01.3-R067 -->
- `sockets` — When sockets are inherited (the `sd_listen_fds` protocol: `LISTEN_FDS`, `LISTEN_FDNAMES`), the daemon MUST take them by `FileDescriptorName=admin` | `<role>`: the mode and the group were set by the unit (P/02.4 N1.1).

<!-- req: P/01.3-R068 -->
- `sockets` — If an inherited socket has a name that is neither `admin` nor a role of the rights file, then the daemon MUST refuse to start, code 2, and the log names the name.

<!-- req: P/01.3-R069 -->
- `sockets` — When a socket was not passed, the daemon MUST create it itself in `-sockets`.

<!-- req: P/01.3-R353 -->
- `sockets` — When the daemon creates `admin.sock` itself, the socket MUST get the mode 0600.

<!-- req: P/01.3-R354 -->
- `sockets` — When the daemon creates `<role>.sock` itself, the socket MUST get the mode 0660.

<!-- req: P/01.3-R287 -->
- `sockets` — When the daemon creates `<role>.sock` itself, the socket MUST get the group of the process.

<!-- req: P/01.3-R399 -->
- `sockets` — The daemon MUST NOT take the group of a `<role>.sock` that it creates itself from the role: the group is that of the process (R287) whether or not the OS has a group of the role.

<!-- req: P/01.3-R070 -->
- `sockets` — `admin.sock` is 0600 (root).

<!-- req: P/01.3-R355 -->
- `sockets` — `admin.sock` gives everything except `never` of chapter 1.2.

<!-- req: P/01.3-R288 -->
- `sockets` — `admin.sock` is not forwarded: at a follower its changes are `admin_not_leader` (R118).

<!-- req: P/01.3-R071 -->
- `sockets` — `<role>.sock` is 0660.

<!-- req: P/01.3-R356 -->
- `sockets` — An inherited `<role>.sock` has the group of the role: `SocketGroup=` of its unit (P/01.2-R109); the daemon does not change its mode or group.

<!-- req: P/01.3-R072 -->
- `sockets` — If a role header comes on a role socket, then the daemon MUST answer 403 (for the service doors — the row `sc-identity` of [forms/service-checks.tsv](../forms/service-checks.tsv)).

<!-- req: P/01.3-R073 -->
- `sockets` — The daemon MUST trust a forwarding to the leader only from a daemon of the group — a voter or a door without a vote — by the role in SAN (chapter 1.2 N3).

<!-- req: P/01.3-R074 -->
- `door` — A door without a vote is started with `-door -id -voters a@h:p,…`: without a vote.

<!-- req: P/01.3-R289 -->
- `door` — A door without a vote has the same sockets and rights as a voter.

<!-- req: P/01.3-R282 -->
- `door` — A door without a vote holds no replica of the rows.

<!-- req: P/01.3-R075 -->
- `door` — The door MUST pass a request to the leader or to any voter (an attempt `DOOR_REQUEST_TIMEOUT`, the margin `DOOR_REQUEST_MARGIN`).

<!-- req: P/01.3-R076 -->
- `door` — The door MUST read the group membership every `DOOR_MEMBERS_EVERY`.

<!-- req: P/01.3-R077 -->
- `door` — The door MUST write the row `platform/configstore-doors/<id>` `{seen_at}` every `DOOR_SEEN_EVERY` (not under `platform/doors/` — there are the doors of servers, P/05 N1.4).

<!-- req: P/01.3-R078 -->
- `door` — The door MUST write this row itself: by a request to the leader over mTLS with its own role `configstore-door` (forwarding of roles of chapter 1.2 N3).

<!-- req: P/01.3-R290 -->
- `door` — The write of this row MUST be the command `put` of its own row without `cas` and `guard`, the only element `seen_at`.

<!-- req: P/01.3-R079 -->
- `door` — If the role `configstore-door` makes any other write, a batch `op: batch` included, then it MUST get 403.

<!-- req: P/01.3-R080 -->
- `door` — When a foreign batch passes through the door, the door MUST forward it whole, in one request (chapter 1.1 N3 «write batch»).

<!-- req: P/01.3-R081 -->
- `door` — «Own» is `<id>` = the server from the verified certificate of the peer (CN `configstore-door.<server>` / SAN DNS); if a claimed identity of the door (`<id>` of the key, the door name in the forwarding header) is not equal to it, then the write MUST get 403, nothing is written.

<!-- req: P/01.3-R082 -->
- `door` — `Cmd.id` of the replay memory (P/01.1) is not an identity: the daemon MUST NOT compare it with the server.

<!-- req: P/01.3-R083 -->
- `door` — The door MUST NOT touch `admin.sock`.

<!-- req: P/01.3-R291 -->
- `door` — The door MUST NOT forward the requests of `admin.sock`.

<!-- req: P/01.3-R084 -->
- `door` — A door MUST be counted in `configstore_doors` while its row reads in its own form and `seen_at` in it is not older than `DOOR_SEEN_PERIODS × DOOR_SEEN_EVERY` by the clock of the voter that gives the series (where and by whose clock — [forms/metrics.tsv](../forms/metrics.tsv)).

<!-- req: P/01.3-R085 -->
- `door` — If a door row does not read in its own form, then it MUST NOT be counted as a visible door.

<!-- req: P/01.3-R357 -->
- `door` — If a door row does not read in its own form, then the reason MUST go to the log of the leader without the value.

<!-- req: P/01.3-R086 -->
- `door` — If all voters are unreachable, then the door MUST answer 503 `unavailable`.

<!-- req: P/01.3-R087 -->
- `door` — The door does not do `join`/`leave`.

<!-- req: P/01.3-R088 -->
- `format` — In `FORMAT`, `format` and `version` MUST name the on-disk format of this implementation; `impl` is the name of the implementation, only for the log.

<!-- req: P/01.3-R089 -->
- `format` — The daemon MUST write `FORMAT` first into an empty directory (tmp + rename), before any other write.

<!-- req: P/01.3-R090 -->
- `format` — When the daemon starts and the directory is empty, it MUST write `FORMAT`.

<!-- req: P/01.3-R292 -->
- `format` — When the daemon starts, `format` and `version` are those that this build reads and the start mode is that of the directory (R402), it MUST start.

<!-- req: P/01.3-R091 -->

- `no_leader`: no leader for the effective `-leader-wait` interval. Caller action: wait; workers live by the lease.
- `leader_lost`: the leader is lost after a write is sent. Caller action: a replay with the same `id` (chapter 1.1).
- `connection_limit`: more connections than the limit. Caller action: repeat not before the deadline.
- `floor_socket`: `floor` not by admin. Caller action: —.
- `floor_not_higher_id`: `floor` not higher than the current one (a new id). Caller action: —.
- `floor_row_write`: `put`/`delete` of the floor row by an ordinary write. Caller action: only `op: floor`.
- `copy_input`: `import`/`restore`: the input is not in the form `copy` of N1.3; the base is smaller than the greatest version; a row larger than the ceiling (on a box — `-max-value` of the command, in a group — of the leader); an epoch or the floor is not decimal; unreadable (including an epoch row of R408 or `platform/epoch_floor` — upper is not reliable). Caller action: another base / fix the copy.
- `clock_early`: `recover`/`restore`: a clock earlier than `generation_at`. Caller action: `-force` removes only the clock refusal; the upper bound/isolation/monotonicity are required.
- `recovery_unsafe`: recovery: upper unknown, the old group not cut off, an overflow, the current floor does not read (`floor_unreadable`). Caller action: restore the preconditions; force does not help.
- `recover_isolated`: `recover` without `-isolated` (N3 step 0). Caller action: isolate the former group and the writers, repeat with `-isolated`.
- `recover_upper`: `recover -upper N`: N is out of the flag form or below the computed upper. Caller action: check the bound; `-upper` only raises.
- `recover_peers`: `recover -peers`: an element not `id@<raft host:port>/<api host:port>`, an empty element, a repeated id or no `-id` among them (N1.3 «Daemon flags» `-peers`). Caller action: fix the list.


- `copy_method`: unsupported method at /v1/copy. Caller action: use GET; HEAD remains bodyless.
- `copy_admin_only`: copy requested through an ordinary role socket or forwarding. Caller action: use the authorized local admin socket; no header grants it.
- `copy_snapshot_unavailable`: a consistent copy cannot be obtained before successful headers within the declared wait. Caller action: retry the read when available; no write outcome is ambiguous.

- `start_data_dir_owned`: a second daemon on a live-owned data directory (N1.3 «Data-directory ownership»). Caller action: do not take ownership; retry only after the owner exits.
- `local_data_dir_owned`: offline box import/restore or local recover on a live-owned directory (N1.3). Caller action: stop the owner first and retain the operation's other preconditions.
- `replay_limit`: a write above the declared replay-processing limit ([P/01.3-R035 «Waits of the doors»](#n2-doors): the limit and its unit are declared by the implementation), before admission; `Retry-After` is the time until admission in seconds, computed by the implementation. Caller action: repeat not before that deadline.
- `import_held`: in a group, a write held by an unfinished `import` or `restore` attempt (N1.3 `import`); nothing is written. Caller action: wait; the operator continues the attempt through `admin.sock` of the leader.
- `admin_not_leader`, `admin_not_leader_cli`: at a follower, on its `admin.sock`: a write, `op: floor`, `import`, `restore`, `POST /v1/join` or `/v1/leave` of another member; the CLI `admit`, `import`, `restore`, `leave <another>` (N1.3 `admin_ops`); nothing changes. Caller action: repeat at the leader (`leader_id` of `/v1/status`).
- `import_other_input`: `import`/`restore` with another input before «Done» of an unfinished attempt (N1.3 `import`); nothing changes. Caller action: repeat with the same input, or after `recover` a new full attempt.
- `floor_unreadable`: `op: floor`: the current `platform/epoch_floor` does not read in its family form (N1.3 `floor`); nothing is written, the floor is not reset. Caller action: repair the floor row; `restore`, `import`, `recover` report `recovery_unsafe`.

## Implementation decides

Each implementation names in its description:

1. **the raft transport secret** beyond mTLS, if there is one, and its rotation on revocation; the raft wire between members and the frame of `admin.sock`
   (read-fence, admit, import) remain internal to the implementation: a format with a name and a version, no new HTTP routes. The copy transfer itself uses the explicitly declared GET /v1/copy of N2; the members of one
   store cluster are one implementation, a mix of languages — only by clients through `configstore:///`;
2. **the durability of the store** (fsync, raft snapshots: threshold, interval, tail) — a teaching store MAY be non-durable, and this is said in its description; there is no flag or environment variable that turns the barriers off (N1.3 `durability`);
3. **the connection accounting of the daemon** and overrides of the limits by deployment, `-tuning` for slow networks; the normative defaults are N1.3;
4. **how `backup` obtains a consistent state of a running daemon** (N2); the requirement on the copy is a norm of N2, not a choice.
5. **the format mark and the profile `file://`**: the values `format` and `version` of its mark `FORMAT` and which versions of its format the build reads (N1.3 `format`); the on-disk format of the profile `file://`; the command by which a copy of N1.3 `copy` is taken from a store `file://` (the form of the copy is a norm).
6. **mutual exclusion of runs** of `recover`, `restore`, `import` on one installation (a lock, a mark file) — the norm requires one attempt (N3 «Races: admittance and recovery transitions»), the way is a choice. This also declares exclusive live-daemon ownership of `-dir`, refusal of a second daemon and local operations, and release on every process termination by N1.3, and the form and place of the phase mark of `recover` (N3 «recover the store» step 1).
7. **the internal contract of `file://`** (item 5): the format of the profile `file://` is the implementation's own, not a public contract. Its description
   and the library API are written in the implementation's repository by the owner of this chapter before the code: the physical layer and the command layer — conditional
   `put`/`delete` with `guard`, the batch `batch`, CAS by version, `not_before`/`not_after`, outcomes and refusal words as at the store door (P/01.1 N1,
   N4; without retelling the norms), with vectors from its own code. Other processes of the implementation (the installer, the worker) read only
   the contract and the API; a mix of languages on `file://` is not supported — through `configstore:///`.
8. **the finite budgets of this chapter**: the response-write budget, the commit wait, the number of door attempts and the replay-processing limit (R035), the limit of `admin.sock` (R008), the disk and descriptor budgets (R036). Each MUST be finite and positive; this chapter sets no value, flag or default for them. The implementation declares the value; the threshold of production acceptance is approved separately from the implementation, and a claim of the candidate alone is not enough.
