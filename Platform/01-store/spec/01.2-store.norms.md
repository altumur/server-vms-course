### N1.1 Roles

<!-- req: P/01.2-R006 -->
```yaml
roles:
  per_manifest:                              # from each manifest of the catalogue
    <sub>controller:     the controller of the manifest
    <sub>worker:         the worker of the manifest
  platform:              [resource, console, domain, domainconsole, domainagent] # console is one per cluster and writes the operator rows of all manifests; domain, domainconsole, domainagent are the roles of the domain (M11; domain is the signer with keys, domainconsole has no keys — P/08.2 N1.3)
  store_internal:        [admin, configstore (peer), configstore-door]     # not named in the rights file; configstore-door is the door without a vote (added by P/01.3 N1.3)
  reader_word_only:      [domainworker]    # (P/03.7 N1.6: a worker of a subsystem on the domain) a platform word in secrets.readers (P/02.5 N1.3):
                                         # it gives no role in the rights file —
                                         # it maps to the role <sub>domain of a manifest that has domain.kept or a portable book
                                         # (P/03.7 N1.6: a platform capability, not the removed process
                                         # domainpart) — and does not enter the comparison «declared = able to read»
name:      ^[a-z][a-z0-9_-]{0,63}$       # the role name; <sub> — by the grammar of the manifest name (P/02.1)
group:
  platform role:         w2c-<role>      # console, resource, domain* (M11), and every <sub>controller
  subsystem role:        <deployment>-<role>   # only <sub>worker: the controller is the platform role w2c-<sub>controller; deployment: ^[a-z][a-z0-9]*$
identity:
  cluster:  socket /run/configstore/<role>.sock (0660, the group of the role — SocketGroup= of the socket unit, P/02.4 N1.1); admin.sock (0600, root)
  box:      the writer's name at a store of files/memory + the same list of rights; the box door also opens a socket per role;
            there are no trusted forwarding senders on a box: a role header on any socket, admin.sock included, —
            403 with the role of the socket
  doors:    the role certificate — P/02.4 N1.6 `doors`; the form — the role certificate contract (`Platform/common/contracts/role-certificate.md`)
```

See also: P/01.1-R144, P/01.2-R010, P/01.2-R015, P/01.2-R017, P/01.2-R025, P/01.2-R029, P/01.3-R006, P/01.3-R009, P/01.3-R011, P/01.3-R016, P/01.3-R032, P/01.3-R033, P/01.3-R035.

### N1.2 Rights file

<!-- req: P/01.2-R007 -->
The file is a JSON object with the required field `roles` and the optional string `comment`.
`comment` is the generator's mark; it takes no part in granting rights. The mark necessarily names that the file is generated,
the deployment, the source manifests and «do not edit by hand»; for the same inputs its text is the same (P/02.5-01). Each role has the required `group`
(a non-empty string), `read` and `write` (arrays of strings); `delete` is an optional array of strings.
Unknown fields are rejected. Role names are checked whole, including the end of the string;
the internal roles of the store are not in the file. The full static form is `RightsFile` in N2.

See also: P/01.1-R018, P/01.2-R003, P/01.2-R008, P/01.2-R009, P/01.2-R029, P/01.2-R030, P/01.3-R007, P/01.3-R029.

<!-- req: P/01.2-R008 -->
```yaml
configstore-rights.json:
  comment:  <generator mark>          # optional; only a string, not rights
  roles:
    <role>:
      group:  <socket group>
      read:   [<pattern>…]
      write:  [<pattern>…]
      delete: [<pattern>…]            # the generator always writes it for every role: = write, unless the manifest separated them by
                                      # delete:; for the evaluator its absence is an empty list: no deletes (minimum of rights)
pattern:
  exact:    "testsub/next_id"            # equality to the key
  prefix:   "testsub/counters/*"         # * as the last character — a prefix; * not last — a literal character (literal below)
  deny:     "!domain/signer*"            # ! only as the first character; a negation wins everywhere in the list
  literal:  "", "!", "!*", "p/!x", "a*b"  # admissible in the file and match by the rules above: "" — only the empty key,
                                          # "!" — the negation of the empty key, "!*" — the negation of everything, "!" not first and "*" not
                                          # last — literal characters (vector Platform/01-store/vectors/rights-evaluator)
rules:
  - the file does not name admin, configstore, configstore-door; a wrong form — the whole file is refused
  - generated from the catalogue of manifests (MANIFEST_DIR) and the deployment name; not edited by hand
  - loaded at the daemon start (-rights); without the file only admin.sock opens; there is no live reload
  - the installer refuses to install a file not equal in meaning to the generated one (--check, P/02.5 N3 «install»)
  - the file is shown by the door only to admin
```

See also: P/01.1-R018, P/01.2-R003, P/01.2-R007, P/01.2-R009, P/01.2-R010, P/01.2-R029, P/01.2-R030, P/01.3-R007, P/01.3-R029.

<!-- req: P/01.2-R009 -->
The names of derived roles fit N1.1: the manifest name is limited to 32 characters
(P/02.1 N1.2), the suffix controller adds 10, worker — 6. The name is not truncated. The chapter sets no limit on the deployment
name: the group `<dep>-<s>worker` may be longer than 32 characters, the generator neither truncates it nor refuses; whether the OS creates it is up to the installer, P/02.4 «Implementation decides» item 1.
The comparison `--check` refers to one unchanging catalogue; publishing manifests during
generation and installation is excluded in this chapter by the conditions of service, not detected automatically.

See also: P/01.1-R018, P/01.2-R003, P/01.2-R007, P/01.2-R008, P/01.2-R029, P/01.2-R030, P/01.3-R007, P/01.3-R029.

### N1.3 Evaluator

<!-- req: P/01.2-R010 -->
```yaml
allowed(role, action, key):
  action ∈ {read, write, delete}
  role not in the file                                   → no
  any !pattern of the role for action matched            → no
  any pattern of the role for action matched             → yes
  otherwise                                              → no
never:                                                   # for admin too
  - delete of a row <x>/epoch/<y> — exactly one segment <y> after «<x>/epoch/», an empty one included (`t/epoch/`), x ≠ platform
    (the epoch row of P/03.2 <sub>/epoch/<id>)
  - delete under domain/ by a role that is not a domain role (domain, domainagent, <s>domain — in their own families by the rights derivation contract of P/02.5 N1.4, N1.4a)
    a domain role is the name domain, domainagent or <sub>domain (<sub> — the grammar of the subsystem name of P/02.1, `[a-z][a-z0-9_-]{0,31}`);
    never checks only this; «their own families» are set by the delete patterns of the rights file derived by the generator (P/02.5, the --check comparison),
    the store does not re-check them against the catalogue
  - write and delete of platform/epoch_floor (only the restore operation, P/01.3)
list:   names and versions under a prefix — to any role; values — no
guard:  a write with a guard requires the read right to the guard row; a guard does not extend rights
batch:  a batch (P/01.1 N3 «write batch») is judged per row: write or delete of every row of writes, read of every guard, never — for admin too; a refusal of one is a refusal of the whole batch
admin:  everything except never; peer (another daemon) — nothing of its own; configstore-door — only its own platform/configstore-doors/<id> (P/01.3 N1.3; not platform/doors/* of resources)
```

See also: P/01.1-R019, P/01.1-R020, P/01.1-R024, P/01.1-R058, P/01.1-R066, P/01.1-R074, P/01.1-R075, P/01.1-R101, P/01.1-R102, P/01.1-R119, P/01.1-R131, P/01.1-R144, P/01.1-R146, P/01.2-R006, P/01.2-R008, P/01.2-R014, P/01.2-R017, P/01.2-R019, P/01.2-R020, P/01.2-R021, P/01.2-R022, P/01.2-R023, P/01.2-R024, P/01.2-R025, P/01.2-R026, P/01.2-R029, P/01.3-R006, P/01.3-R009, P/01.3-R011, P/01.3-R016, P/01.3-R021, P/01.3-R026, P/01.3-R027, P/01.3-R029, P/01.3-R032, P/01.3-R033, P/01.3-R035.

## N2 Doors

<!-- req: P/01.2-R012 -->
The rights doors are the store doors of chapter 1.1, behind the role socket; request parsing is chapter 1.1 N2.1, for `GET /v1/rights` the query is not read. In addition:

<!-- req: P/01.2-R013 -->
The HTTP contract: [01-store.api.openapi.yaml](01-store.api.openapi.yaml).

<!-- req: P/01.2-R014 -->
`GET /v1/rights` returns the loaded object `RightsFile` whole, without an envelope;
if it has a comment, the field is returned too. While no file is loaded, the route answers `404 badrequest`;
an empty object `roles` does not stand in for the absence of the file. Access is checked by the identity admin,
before the file is given out. A successful `GET /v1/list` uses the `Listing` of chapter 1.1: without the values of rows,
with versions and the order of names by UTF-8 bytes. The presence of the path and the trust of the identity are checked
for list too; the absence of the read right does not prevent listing.

See also: P/01.1-R066, P/01.2-R010, P/01.2-R015, P/01.2-R019, P/01.2-R026, P/01.2-R029, P/01.3-R016.

<!-- req: P/01.2-R015 -->
The forms of all answers of the two routes are set in OpenAPI. The refusals `400` (`/v1/list` out of the form of chapter 1.1 N2.1), `403`, `404`, `503` are
exactly `{kind, error}` as strings, respectively `badrequest`, `forbidden`, `badrequest`, `unavailable`;
no `detail`/`fault` of the console. For a refusal of an operation on a row, `error` names the role,
the action and the key; for a refusal of the identity itself or of `/v1/rights` — the role and the cause/route.
With a role header on a role socket, the role of the socket is named,
not the role imposed by the header; parsing the key of the operation for diagnostics is not required.

See also: P/01.1-R144, P/01.2-R006, P/01.2-R014, P/01.2-R017, P/01.2-R026, P/01.2-R029, P/01.3-R006, P/01.3-R016, P/01.3-R033.

## N4 Refusals

<!-- req: P/01.2-R029 -->
The catalogue of these refusals — [`forms/refusals.tsv`](../forms/refusals.tsv): the form is the sole source of code, kind, fields, headers and log projection. The OpenAPI fault schemas and write-check order stay their owning forms; the causes, priority and caller actions below refer to stable refusal names, without duplicating the outcome cells.

- `list_form`: `/v1/list` out of the form of chapter 1.1 N2.1 (a repeated `prefix`). Caller action: fix the request.
- `rights_no_route`, `rights_store_unavailable`: no route; the store is unavailable (`/v1/list`, `/v1/rights`). Caller action: —.
- `read_forbidden`: a read without the right. Caller action: a deployment error or a foreign process.
- `write_forbidden`: a write/delete without the right. Caller action: the same.
- `guard_read_forbidden`: a guard on a row without the read right. Caller action: the same.
- `never`: a delete of an epoch row; a delete under `domain/` by a role that is not a domain role; a write and a delete of `platform/epoch_floor`. Caller action: never.
