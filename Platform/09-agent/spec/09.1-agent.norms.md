```yaml
                failed (the store did not answer): the key is not read; the count is in the memory of the agent since the launch, a failure of the write of
                domain/agent or of another read of the pass does not remove it — the next signed publication carries it (C09-SIGN-FAILURES-COUNT-01)

                a key spoiled on the fly would otherwise keep signing, and the member would look ok)
agent:          503 standby — «the holder is unavailable» for this pass: not a refusal, not a reason to look for another term (Н3 «follow»);
                the agent sends again at the next pass (added by М11/12 into the agent pass)   # М11/12 Н1.7 agent
```

## Н3 Procedures

### the agent turn (at start and every TURN_RENEW; DOM-AGENT-TURN-01)

```
1. read domain/agent-turn; unreadable → standby (Н1.13 standby), a journal entry
2. holder is this instance: rewrite by CAS of the read version; a conflict → standby
3. no row → CAS "" with holder = me; holder "" (given up, Н1.13 release) → CAS of the read version with holder = me;
   holder is foreign and its version has not changed for ≥ TURN_TERM by my monotonic clock → CAS of the read version with holder = me;
   success → active: the agent pass below and the other procedures of the chapter with the guard of Н1.13 guard; otherwise → standby
4. holder is foreign and fresh → standby
5. SIGTERM at the active one → holder "" by CAS of its own version (Н1.13 release), then exit
```

An unknown outcome of a write with the guard or of the turn row itself — as at the process domain ([P/08.10](../../08-domain/spec/08.10-domain.norms.md)
Н3 «the turn of the domain process», the paragraph after the steps; [the writer turn contract](../../common/contracts/turn.md) «An unknown outcome of a write of one's own turn row»). **Races** are the same: two agents after a giving up take the turn by CAS of one version — one passes;
a write of the former active one carries the guard of the former version and is refused.

### the agent pass (once per every, default REPORT_EVERY; only the active one, Н1.13) (М11/3 Н3)

```
1. domain/member-key: none — create it (Н1.1 born); read the key every pass, it did not read — do not sign (Н1.12
   key_read; reconciliation of М11, N1); read pinned (domain/root), keys_rev (domain/keys);
   for each heartbeat of the copy — the moment of its last change by its own monotonic clock → stale (Н1.2)
2. gather member_objects (Н1.2); not ready → GET /api/carry/<член> (the keys and the list without a report) and the next pass;
   200 GET /api/carry (here and in step 3) whose answer is trusted (Н1.4 from_carry) — apply it at home and take every
   (the holder's pace, not a confirmation of the publication); the confirmed base and last_rev — only by 200 POST (step 5)
   (C09-GET-CARRY-EVERY-01)
2а. retry_in of the former answer has not expired (Н1.2а) → the pass ends here: neither requests nor writes
2б. asks for parts (Н1.4 member_want)
3. last_rev = 0 (start of the process, after 409 rebase) → the body is whole (base 0); among the objects that the whole must carry
   (member_objects) there is an unreadable one (the outcomes of the families domain/reaches, domain/backup-taken, domain/shared-refused: the object is not
   taken) → do not send the whole: the holder's former copy stays whole; GET /api/carry/<член> and the other actions of the pass
   go on; the journal at every pass of waiting — «whole publication withheld: <n> objects do not read», without values;
   the publication resumes when the object reads again or its row is gone (then — an ordinary deletion) (C09-RETAIN99, the Architect's decision of 2026-10-26);
   otherwise base = last_rev, objects — those changed against the confirmed base (Н1.2 change), deleted — those gone from it;
   nothing changed → {sent_at, objects: {}, base, key, …}
4. sign (Н1.3) and send POST /api/member/<член> to the holder's door (DOMAIN_URL)
5. 200 → apply the answer (Н1.4); the confirmed base := the state of this request; last_rev = carry.rev; every = carry.every, no field — the former one
   (outside 1 … 3600 — the nearest bound, the answer is not rejected: the report reception contract «Ответ carry: every»)
   — only for an answer that is trusted: the outcome took or holding of the function keys over keys of this answer (Н1.4 from_carry);
   another outcome or no keys — the answer is not applied at all: the confirmed base, last_rev and every are the former ones, a journal entry
   (the set is rejected — its answer is not trusted, R2). A failure of a write at home (CAS, ring, copy) at an answer that is trusted
   does not roll back the base, last_rev and every: the confirmation is about the state of the holder, home catches up by the next pass
   (home_write) (C09-CARRY-TRUST-01)
   409 rebase → last_rev = 0 and at once one repeated sending as a whole; 409 same_sent_at → the next pass (a new sent_at)
   409 not_ready, 401, 403, 404 → a journal entry (one line per change of cause), the next pass; 404 with retry_in — not earlier than it (Н1.2а)
   429 busy → the next pass not earlier than retry_in (Н1.2а), last_rev and the base do not change, the journal one line per change of cause; the GET doors of steps 2, 2б — the same
   503 standby → the holder is unavailable for this pass: the next pass, last_rev does not change; not a refusal and not a reason to look for
   another term (Н1.12 agent; added by М11/12); 413 whole too large → domain/agent too_large, last_rev = 0; the same whole is not repeated until the objects change
   (Н1.2 body; reconciliation of М11, N9)
   no answer → the next pass; last_rev and the confirmed base do not change; an answer of the holder (carry POST and GET) larger than
   BATCH_LIMIT (the report reception contract «The relay batch: limits») — as «no answer», a journal entry without the value (C09-ANSWER-LIMIT-01,
   the Architect's decision of 2026-10-29)
```
