## Стенд

**Подготовка каждого сценария** — как README приёмки [главы 8.3](../../../../08-domain/ru/acceptance/3/README.md) («Подготовка
каждого сценария»; из README приёмки М11/03): раннер поднимает на одной машине три кластера — `hold`, `m1`, `m2`; у каждого
своё пустое хранилище, свой `{data}`, свои сокеты ролей и порты консоли и ресурса, своё кольцо (P/06.2 N1.2), каталог манифестов
— только `testsub`; консоль, контроллер и воркер `w-1` `testsub`, ресурс своего сервера (`srv-hold`, `srv-m1`, `srv-m2`).
Единиц нет. Домена нет: его ставит директива `@domain` первого шага каждого сценария. Имя домена — `acme`.

- `store` у `member <кластер>` — дверь хранилища кластера через `admin.sock` (подготовка и наблюдение строк домена у члена:
  `domain/agent`, `domain/member-key`, `domain/member-list/<part>`, `domain/keys`, `domain/member-topology`, `domain/grants`,
  `domain/backup-taken`, `domain/shared`, `domain/shared-refused`, `domain/root`, `domain/placed`, `domain/outcomes`,
  `domain/agent-turn`); `store` без `member` — хранилище `hold`.
- `resource` без префикса — дверь ресурса `hold`: через неё читаются объекты держателя `domain/members/<член>/…`.
- Часы не ускорять: `LOST_AFTER` 45 с, `REPORT_EVERY`, `MARK_REFRESH` 22,5 с, `VIEW_EVERY` 3 с; сроки `@until` взяты с
  запасом.
- Раннер ходит человеком `root` (первый администратор — глава 8.4).

## Хеш копии anywhere (G09-ANYWHERE-HASH-01)

Пять векторов фикстуры в [`inputs/anywhere-hash/cases.tsv`](../../../acceptance/1/inputs/anywhere-hash/cases.tsv) задают хеш всего тела
по P/08.4 N1.3 carry и проверку перед копией N1.4 member_anywhere. Колонка input называет JSON-файл
рядом с таблицей; expect — JSON-подмножество наблюдений, не вход реализации.

В каждом входе исходная сохранённая копия с точным индексом и последней подтверждённой меткой taken_sha256 и список attempts.
Каждая попытка независимо начинается с этого исходного состояния: доверенное объявление carry — advertised, настоящее
тело 200 `GET /api/anywhere/{member}` — UTF-8 текст body. Фикстура вызывает обычный код копирования агента с
телом и меткой и наблюдает операции хранилища и изменения метки. received_at — время приёма, domain_age — возраст ответа; каждый случай готовит пригодный доверенный carry сервера m1 и действующий guard агента. Она возвращает массивы в порядке attempts:
computed_sha256, copy_writes, marker_confirmed; при отказе также related_edits (правки, относящиеся к этой копии),
copy_items, copy_index и taken_sha256. Наблюдение хеша берётся из обычного пути, проверяющего тело;
фикстура не вычисляет его вместо этого пути. Три положительных вектора должны дойти до настоящей записи копии.

Эти входы может передать существующий шов IO agent-carry: файлы не объявляют новой нативной команды. Фикстура,
которая только вычисляет ожидаемый хеш, не проверяет отрицательные случаи: они требуют сохранения прежних копии, точного индекса
и метки и нуля записей копии и связанных правок. Пять случаев покрывают as_of в хеше, JCS
вместо записи на проводе, отказ хеша одного doc и отказ несовпавшего хеша всего тела.

Тело провода владельца содержит сырые строки KV doc и as_of. Для хеша канонизируется только внешний JSON; внутренний текст doc предварительно не нормализуется. Сосед с внутренним текстом имеет равные разобранные внутренние объекты, но разные строки и хеши, и наблюдает точные успешные copy_items. Доверенные advertised as_of, received_at и domain_age сохраняют прежние числовые типы. Прежние отказы сохраняют полную исходную сырую копию, индекс и пересчитанную метку нынешнего провода. Исполнение IO не объявляется успешным до запуска адаптера.
