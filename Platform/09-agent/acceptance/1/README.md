## Стенд

**Подготовка каждого сценария** — как README приёмки [главы 8.3](../../../08-domain/acceptance/3/README.md) («Подготовка
каждого сценария»; из README приёмки М11/03): раннер поднимает на одной машине три кластера — `hold`, `m1`, `m2`; у каждого
своё пустое хранилище, свой `{data}`, свои сокеты ролей и порты консоли и ресурса, своё кольцо (P/06.2 Н1.2), каталог спек
— только `testsub`; консоль, контроллер и воркер `w-1` `testsub`, ресурс своего сервера (`srv-hold`, `srv-m1`, `srv-m2`).
Единиц нет. Домена нет: его ставит директива `@domain` первого шага каждого сценария. Имя домена — `acme`.

- `store` у `member <кластер>` — дверь хранилища кластера через `admin.sock` (подготовка и наблюдение строк домена у члена:
  `domain/agent`, `domain/member-key`, `domain/member-list`, `domain/keys`, `domain/member-topology`, `domain/grants`,
  `domain/backup-taken`, `domain/shared`, `domain/shared-refused`); `store` без `member` — хранилище `hold`.
- `resource` без префикса — дверь ресурса `hold`: через неё читаются объекты держателя `domain/members/<член>/…`.
- Часы не ускорять: `LOST_AFTER` 45 с, `REPORT_EVERY` 5 с, `MARK_REFRESH` 22,5 с, `VIEW_EVERY` 3 с; сроки `@until` взяты с
  запасом.
- Раннер ходит человеком `root` (первый администратор — глава 8.4).

Отличия по сценариям (из README приёмок-источников):

- **Сценарии 01, 03, 06** (из README приёмки М11/12). Двери `holder`, `member`, `resource` и директивы `@domain`,
  `@start`/`@stop agent` — словарь «Стенда домена».
  - **01.** Член `m1` без изменений: после `@domain` и 10 с тишины его поколение стоит, а метка свежеет за 30 с (больше
    `MARK_REFRESH` и прохода). Индексы строк `domain/member-list` и `domain/keys` у `m1` не растут: агент пишет дома только
    при отличии. Строки `domain/agent` нет: её пишут только при сбое подписи или слишком большом целом. Окно наблюдения
    открывается только после резервной копии (глава 8.8): шаг 2 ждёт `BACKUP_EVERY` и проход после `@domain` — последняя
    копия держателя сделана; шаги 3–4 — `m1` (хранитель) записал у себя ту же копию, что указатель `domain/keepers/m1`
    держателя; шаг 5 — его отчёт с `domain/backup-taken` принят. Дальше содержимое `m1` не меняется, и `reported.rev`
    стоит. `@domain` копии у хранителей не ждёт.
  - **03.** Ключ члена `m1` испорчен через `admin.sock` при остановленном агенте: агент идёт, но не подписывает — строка
    `domain/agent` со счётом, член `silent` за `LOST_AFTER`. Ключ возвращён — `m1` снова `ok`. Шаги 12–14 портят ключ на
    ходу, без `@stop agent`: агент читает ключ каждый проход (Н1.12 `key_read`) — тот же счёт и `silent`; шаги 15–19
    возвращают ключ и перезапускают агента — член `ok`, строки прошлого запуска нет (Н1.12 `at`; сверка М11, N1, N2).
  - **06.** Правка топологии и грантов `m1` держателем (двери `holder`: глава 8.3, глава 8.4) — затем строки дома у `m1`
    два прохода агента не переписываются, `as_of` копии грантов не освежается раньше `FRESH_EVERY`.
- **Сценарии 04, 07, 08** (из README приёмки М11/06). Каталог `testsub` — `domain.edit: [start, labels]`, `domain.ref:
  name`. Двери `holder`, `member` и директивы `@domain`, `@cut`, `@mend`, `@clock` — словарь «Стенда домена»; у двери
  `holder` раннер ставит `Idempotency-Key` и у `PUT`/`DELETE`. `$id` — id хранимой правки из ответа 202. Правку держатель
  хранит (глава 8.6), применяет её агент `m1` (Н1.5) после `@mend`; условие `If-Match` двери единиц — сц. 14 приёмки
  [P/06.1](../../../06-console/acceptance/1/README.md). Сц. 08: `@clock m1 +90` — часы агента вне окна двери единиц
  `UNIT_WINDOW` 60 с ([договор подписи агента](../../../common/contracts/agent-signature.md)); шаг 10 возвращает часы.
- **Сценарий 11** (из README приёмки М11/10; модель Quint М11, сценарий Q3). Стенд с подписантом и на `m1`: двери
  `holder`, `member`, `signer` и директивы `@domain`, `@start domain on`, `@stop domain`, `@move` — словарь «Стенда
  домена». Отзыв после последней резервной копии не оживает после переноса: агент члена объединяет `domain/revoked` ответа
  со своей строкой (RV, Н1.4 `from_carry`), шаг 20 — 401.
- **Сценарии 05, 14** (из README приёмки М11/11). Каталог `testsub` с объявлением общего:
  - `domain.shared: [step, marks, {rounds}]`;
  - `step` — `int` с `inherit: 1`;
  - `marks` — `list` с `inherit: []`, `merge: union`.

  Двери `holder`, `member` и директивы `@domain`, `@on`, `@put object` — словарь «Стенда домена». Документ без подписи
  (`inputs/shared-doc-unsigned.json`, JCS без `issuer`, `kid`, `sig`) раннер кладёт объектом и указателем мимо правки:
  сц. 05 — с его суммой: член не берёт его — `record` отказывает `not_a_record` ([P/08.9 Н1.2](../../../08-domain/spec/08.9-domain.norms.md)
  `signature`, Н3 «взять документ» шаг 4), строки `domain/shared` у члена нет; сц. 14 — с чужой суммой: член не берёт —
  «does not match the pointer» (Н3 «взять документ» шаг 3). Значение при чтении `GET /domain/shared/testsub` (сц. 05 шаг 6)
  — консоль кластера (глава P/06.7, урок 10): сосед на стенде.
- **Сценарий 13** (из README приёмки М11/05). Каталог каждого кластера — `testsub` и `testsub2` (порядок — «Стенд» общего
  README приёмки); на каждом кластере работают контроллеры обеих, воркер `w-1` спеки `testsub`, воркер `t-1` спеки
  `testsub2` (с учебным писателем вкладов — [P/08.5](../../../08-domain/spec/08.5-domain.norms.md) Н5) и ресурс своего
  сервера `srv-<кластер>`; до шагов в хранилище каждого кластера есть счётчик `testsub` `c1-<кластер>` (свой ref у
  каждого: общий `c1` был бы спорным, и `@domain` не дождался бы `complete: true`) и полка `testsub2` `sh1` `{zone: z1,
  server: srv-<кластер>}`. `console2` у `member` — префикс `/testsub2`. Директива `@on m1 @sigkill t-1` убивает
  воркера-вкладчика: его строка не идёт в отчёт по сроку слота (Н1.2 `liveness`), книга `rolls` у `m2` — без записи `t4`.
  Дверь книги (`GET /domain/testsub2/books/rolls`) — консоль кластера (глава P/06.7, урок 10), сборка — глава 8.5: соседи
  на стенде.

## Сны (`@sleep`, ADR-0080 доп. (17) п. 4)

Ожидание события — `@until`: сц. 01 шаг 9 ждёт следующего отчёта того же поколения (`received_at` сменился, `rev` тот
же). Оставшиеся сны (из README приёмок М11/12 и М11/10):

| Сц./шаг | Сон | Причина |
|---|---|---|
| 01/2 | 35 с | время перед действием: первая резервная копия и её хранители после `@domain` — `BACKUP_EVERY` 30 с и проход агента 5 с |
| 01/5 | 10 с | время перед действием: член затих после записи `domain/backup-taken` — два прохода агента |
| 06/6 | 10 с | отсутствие: свежие копии с тем же содержимым не переписываются — переписывание было бы в ближайшем проходе агента (5 с), два прохода; `as_of` освежается не чаще `FRESH_EVERY` 60 с |
| 11/6 | 65 с | время перед действием: два окна `BACKUP_EVERY` после отзыва — копия с `bob` (шаг 9) делается сразу, а не через окно |
| 11/10 | 6 с | время перед действием: копия с `bob` — в ближайшем проходе держателя (3 с) с запасом |

## Свидетельства вне TSV

Проверяются чтением (норма главы, Н5 «Чтением»): нового поколения по времени агент не шлёт, правки держателя у себя,
страница тревог и срочный отчёт (стенд тревог не поднимает), агент в процессе (у стенда нет процесса без комплекта), поле
`sign_failures` публикации, `no_seal` и `domain.reports`, смены ключей у члена без связи, секреты книги у члена, копия
аварийной строки, агент хранителя, предел тела агента; клиент HTTPS и первый контакт (стенд без TLS). Байты подписи агента
— пакет [`agent-sig`](../../../common/vectors/agent-sig/README.md), функция `peer` — пакет
[`peer`](../../../common/vectors/peer/README.md), функция `follow` — пакет [`follow`](../../vectors/follow/README.md).
