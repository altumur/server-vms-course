# Приёмка P/09.2 — режим ретранслятора (стенд)

Стенд, словарь директив и дверей — [общий README приёмки](../../../common/acceptance/README.md#словарь-директив-и-дверей),
раздел [«Стенд домена»](../../../common/acceptance/README.md#стенд-домена) (стенд нескольких кластеров; прежде — словарь М11 README приёмки
М11/01; план переноса урока 8, В5). Норма главы — [`09.2-agent.norms.md`](../../spec/09.2-agent.norms.md) Н5. Сценарии
02–04 перенесены из приёмки М11/04 (стадия B, ADR-0083 доп. (1): без изменения поведения); номера, имена и шаги —
прежние, номер 01 пуст (сц. 01 М11/04 — приёмка [главы 8.3](../../../08-domain/acceptance/3/README.md) сц. 15). Всего 4
сценария / 49 шагов. Входов нет: входы `accept-*` М11/04 сняты с сц. 06 — те же случаи в пакете
[`accept`](../../../common/vectors/accept/README.md).

Деление (приложение плана переноса урока 8): исход всех трёх сценариев — дверь, пакет и проход ретранслятора. Соседи на
стенде: держатель на пакете ретранслятора и стук ([P/08.3](../../../08-domain/spec/08.3-domain.norms.md) Н3 «держатель на POST
/api/relay/<ретранслятор>»; P/08.3-07, P/08.3-13), приём и топология (глава 8.3), `join` и `domain/reached` агента члена за
ретранслятором (глава 9.1: P/09.1-05, P/09.1-21, P/09.1-24), молчание члена в виде (глава 8.1).

## Стенд

Подготовка — как README приёмки [главы 8.3](../../../08-domain/acceptance/3/README.md) («Стенд», «Подготовка каждого
сценария»; прежде — README приёмки М11/03), кластеров четыре: `hold`, `m1`, `m2`, `relay`. Агент `relay` всегда открывает
дверь ретранслятора (`RELAY=1`, `{relay_port}`); двери и директивы — раздел «Стенд домена» общего README приёмки
(`@domain <кластеры>`, `@start agent <кластер> via relay`, `@stop agent`, `@cut relay`, `@mend relay`, `@clock`).
Топология пуста до шага, который её пишет.

## scenarios.tsv

Формат — словарь «Стенда» и раздел «Стенд домена» общего README приёмки; ожидание — подмножество полей. `$fp2` — отпечаток
незнакомца, которого держатель узнал из стука, пришедшего пакетом ретранслятора.

- Сц. 02 шаги 11–14 (мутационная проверка 2026-10-18): ретранслятор проверяет подпись члена — с часами агента на 400 с
  вперёд член за ретранслятором `silent`, хотя ретранслятор жив; с верными — снова `ok`.
- Сц. 02 шаги 15–21: под `@cut relay` `domain/reached` не растёт. Шаг 16 связывает `$c` — `as_of` вида держателя сразу
  после разрыва; `ts` метки — момент последнего ответа держателя (`domain_age` — Н1.4 главы; `fresh` — глава 9.1), не
  позже разрыва, поэтому шаг 21 сравнивает `$t2` с `$c`, а не с `$t1`: прежнее сравнение двух чтений ловило отложенную на
  FRESH_EVERY запись последнего до разрыва значения (сверка М11 01–04, сц. 04/02 шаг 20 смеси).

- Сц. 05 `relay-moves` (DOM-AGENT-TURN-01, -02, согласие владельца 2026-10-26; глава 9.2 Н1.1 `door`, P/09.1 Н1.13): два агента ретранслятора (`@start agent relay
  second`), `RELAY_URL` члена `m2` — их двери по порядку; SIGTERM активного агента ретранслятора — ждущий берёт очередь и
  открывает дверь, член идёт по следующему адресу, отчёты через ретранслятор продолжаются.

## corrections.tsv

Журнал исправлений ИИ (ADR-0080 доп. 1): `date`, `sample`, `fix`, `languages`. Строки до переноса — из `corrections.tsv`
приёмки М11/04 по `sample` (сценарии 02–04) и строки без сценария, в начале журнала, с прежними путями и номерами (их
разрешает [`id-map.tsv`](../../../common/id-map.tsv)); строки входов `accept-*`, сц. 01 и 06 — история приёмки главы 8.3
(план переноса урока 8, § 3 «Журналы»; разбор ревью стадии B 6–7, № 18). Реализации и их раннеры проверяют свой
результат; этот каталог сам их не запускает.
