# P/05 — инструкция для реализации

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — [`../05-resource.md`](../05-resource.md).

## Задача

Дать платформе объекты, события и их чтение; ресурсу — уборку, зеркалирование и восстановление своих бакетов.

## Входы и их приоритет

- Канон — [нормы](05-resource.norms.md), определения Н0 — по P/01.1; файловые договоры —
  [журнал событий](../../common/contracts/event-journal.md) и [замок присутствия](../../common/contracts/presence-lock.md).
- [HTTP-контракт](05-resource.api.openapi.yaml) выражает Н2.
- [Приёмка](../acceptance/README.md) задаёт подготовку и наблюдения.
- [Лекция](../05-resource.md) объясняет причины и границы; [жизненный цикл](../lifecycle.md) — окружение, коды выхода.

Объекты используют словарь хранилища P/01.1, роли — [P/02.4 Н1.6](../../02-installer/spec/02.4-installer.norms.md) и
договор сертификата роли. `PUT /v1/objects/<sub>/blobs/<digest>` — Н1.1 «Тела у ресурса», Н2; `restore` (`GET /mirrored/<server>`) — Н1.4 «Восстановление бакетов».
Внутренние функции,
библиотеки и способ размещения обработчиков не предписаны.

## Что создать

Операции объектов и их разрешённую дверь; запись событий с бакетами и классами;
чтение дерева с ограниченным кэшем; запрос ресурса; подсказку wait;
проход ресурса retain → usage → relieve → mirror; `restore` при старте.
Целая копия файла, ответивший источник и опубликованная копия —
разные границы подтверждения, одна не доказывает другую.

## Порядок работы

1. Разделить файл и строку-объект. Проверить put_new и CAS по Н1.1, запрет выдавать
   строки-объекты дверью файлов, равные written и missing. Отсутствие ответа сервера
   не превращать в доказательство отсутствия объекта.
2. Записать событие под эпохой. Идентификатор различает процессы, коробки и перезапуски;
   поля платформы нельзя затереть полями подсистемы. Проверить оба класса, of, бакет
   по t и сохранение целой строки; fsync проверять отдельным свидетельством (подавление — глава 3.6).
3. Построить запрос над файлами: параметры, кандидаты, фильтр, приоритет тревог,
   limit и truncated. Одинаковый запрос с пустым кэшем и после его вытеснения даёт тот же
   результат при неизменных файлах. Порванный хвост даёт partial, не строку события.
4. Сделать wait по Н1.6: четыре закрытых ответа, личность при вытеснении, очередь и
   таймаут. Клиент продолжает периодический проход при потере подсказки, переполнении
   или перезапуске ресурса.
5. Выполнить проход ресурса. Неизвестное чтение retention/holds не даёт права удалять;
   free_ask не содержит unit и совпадает по server/volume. Имя тома — ASCII A-Z/a-z/0-9/_ длиной 1–64, без дефиса (Н1.4 `free_ask`); иной том не публикует просьбу и диагностируется. Снятие использует CAS версии,
   на которой проверены форма и владелец строки. Зеркало публикуется после проверки полного тела
   и суммы; неуспех сохраняет прежнюю копию.
   Строка двери несёт рядом с `room.<sub>` список `live.<sub>` — номера n ≥ 2 живых замков того же снимка (договор замка
   присутствия; ADR-0084 доп. (3) Р14′): контроллер считает по нему свободное место сервера.
6. Пройти 6 сценариев / 71 шаг приёмки по отдельности. Проверять полные ответы по владельцу формы,
   даже при ожидании только кода в TSV. Для каждого пункта чеклиста назвать отдельное
   наблюдение; пробы вне TSV перечислены в README приёмки.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Проверка |
|---|---|---|
| Н1.1/Н2 | prefix проверен как ключ; traversal прошёл декодирование | Пустой prefix допустим; пустой сегмент ключа, точка, две точки, обратная косая и управляющие — нет |
| Н1.2/Н1.3 | Поля события затёрли метаданные; PID повторился на другой коробке | Поля платформы защищены; id различает экземпляры |
| Н1.3 | bool принят за integer, NaN за число, обрезка за неполноту источников | Конечные числа, целый limit; разные truncated/partial |
| Н1.6/Н2 | JSONL обёрнут массивом; wait вернул события | Проверить форму, типы и отсутствие лишних полей |
| Н2 | После заголовков выдан второй JSON-отказ | Обрыв остаётся обрывом; неполная копия не публикуется |

## Готово, когда

Выполнен весь канонический чеклист, названы выборы реализации и свидетельства для
норм вне TSV. Раздельно показаны успех, известный отказ и неизвестный результат
публикации. Проверка схемы не проверяет файловую долговечность или гонку;
чтение алгоритма не доказывает исполнение в нескольких процессах.

## При расхождении

Передать «Спецификации» срез, место и контрпример; установить, был ли он до правки.
Исправить источник нормы и прямых потребителей, проверить весь связанный класс.
Не расширять урок новым механизмом ради случая вне объявленного профиля.

Дополнительная проверка после прогона 33: GET объекта: 64 МиБ/+1, без успешного усечения.

Проверить id на коллизии составных имён a-e1-j/node:1:aaaaaa и a/j-e1-node:1:aaaaaa, UTF-8, разные деревья/эпохи/параллельные номера, перезапуск и итог подавления; копии сохраняют исходный id. Для обоих перечней buckets/mirrored: отсутствующий, пустой известный и нечитаемый каталог различаются; ошибка до заголовков — 500 без тела, обрыв не даёт полного ответа. Дополнительные пробы вне TSV.
