## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0 P/01.1](../../01-store/spec/01.1-store.norms.md#время-в-строке): строка события — `t` ([договор журнала событий](../../common/contracts/event-journal.md)); объект пульса ресурса `platform/resources/<server>/heartbeat` — `ts`, `usage_at`, `pass_started`; строка двери `platform/doors/<сервер>` — `since`, `at`; `<sub>/requests/free-<server>-<volume>` — `at`; надгробие `.gone/<ключ>` — `written` (пишет консоль, урок 10).

**Данные** ([каталог](../../common/data/catalog.tsv)):
- владеет: `platform/resources/<server>/heartbeat`, `platform/doors/<сервер>`, `<sub>/requests/free-<server>-<volume>`, `<корень событий>/<sub>/<unit>/e<эпоха>/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/<sub>.alarms/<unit>/e<эпоха>/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/audit/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/audit.alarms/<роль>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/console/<экземпляр>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/console.alarms/<экземпляр>/e1/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/.mirror/<server>/<дерево>/<unit>/e<эпоха>/<YYYYMMDDTHHMMSSZ>.events.jsonl`, `<корень событий>/.workers/<sub>/<экземпляр>.lock`, `<корень событий или объектов>/<путь>/%h<sha256>.name`;
- пишет: `<sub>/blobs/sha256-<hex>` (put), `.gone/<ключ>` (cas);
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `platform/schema`, `<sub>/heartbeats/<имя>`, `platform/decommission/<сервер>`, `platform/doors/<сервер>`, `platform/resources/<server>/heartbeat`, `<sub>/retention`, `<sub>/alarms_retention`, `platform/space`, `platform/mirror`, `<sub>/<spec:tables>/<имя>`.

Копии тел ресурс кладёт соседу (put) и удаляет свою копию старше надгробия (delete); надгробия подтверждает (cas) и
снимает (delete) — Н1.1 «Тела у ресурса», «Надгробия».

### Н1.1 Объект

```yaml
object:
  rule:      целиком или никак; последний писатель побеждает; по ключу не ищут; размер — предел хранилища (0 = без)
  api:       put(key, bytes) | get(key) → bytes | null | list(prefix) → [key] (отсортировано, без .tmp) | delete(key)
             | put_new(key, bytes) → conflict, если есть  (создание-однажды) | get_at/put_at (запись по прочитанному индексу)
  key:       <семья>/… ; семьи платформы: heartbeats, contenders (P/03.4, P/03.2), controller (P/04), snapshot, blobs (добавлено М10/10),
             commands (М10/8 Н1.5 mark) — спека их не называет
  writer:    один каталог — один писатель: worker → <s>/heartbeats/*, <s>/contenders/*;
             controller → <s>/snapshot/* (добавлено М10/10), <s>/controller/*; console → <s>/blobs/* (добавлено М10/10); resource → platform/resources/*
  cluster:   файл на сервере писателя; при чтении свежая копия (written) побеждает; сервер, который не ответил, — missing
  row_object: ключи, чей следующий писатель может быть на другом сервере, — строки хранилища objects/<ключ>
             (objects.rows спеки; commands/* — всегда, у спеки с requests); put_new = запись с cas ""
  ops:       операции объектов сводятся к словарю P/01.1 и его отказам: put_new — «записать, если нет» (conflict, когда есть);
             get_at — чтение с индексом объекта; put_at — запись по прочитанному индексу (иной индекс → conflict, как cas строки);
             put_durable — запись тела целиком с барьером долговечности до публикации (строка ссылается на тело только после
             ответа — урок 10 Н1.5 `write`); delete_at — удаление по прочитанному индексу (иной индекс → conflict, объект не тронут — урок 10 Н1.5 `sweep`); append — дописать строку события в открытый бакет (только его писатель, Н1.2); иных атомарностей нет
  door:      только семьи PLATFORM_DOOR (platform/resources/*, domain/* (М11), */heartbeats/*, */contenders/*, */snapshot/*,
             */controller/*, */blobs/*; snapshot и blobs — добавлено М10/10) и objects.door спеки; иное — 403;
             `*` первой части — подсистема каталога спек: `other/heartbeats/x` без спеки other — 403 (сверка python и go М10/6–11, E5)
  disk:      <PLATFORM_DIR>/objects/<ключ>; каталог 0775, файл 0644; запись — temp + rename под замком каталога
```

Ключ объекта — непустой относительный путь: непустые сегменты, без точных `.`/`..`,
обратной косой черты и управляющих знаков. `prefix` — начало такого ключа, также пустота
или конец `/`; это не полный ключ. Объектная дверь не выдаёт строки-объекты даже из
разрешённого префикса. При равном `written` выбирается сервер с лексикографически большим
именем; отсутствие ответа называется `missing`, а не отсутствием объекта. При листинге
возвращается закрытая форма ObjectListing из Н2; удалённые объекты — надгробия `.gone/<ключ>` (ниже, «Надгробия»): обычный листинг их не показывает, `prefix=.gone/` —
листинг надгробий только для чтения (журнал cammeta-go, урок 10 № 2).

Листинг отдаёт только ключи семей двери под `prefix` — фильтр, а не отказ: `prefix=testsub/`, `prefix=t`, пустой
`prefix` — 200 с ключами семей двери, которые начинаются с него; ключи вне семей двери в листинг не попадают. `prefix`,
с которого не начинается ни один возможный ключ семей двери (`other/`), — 403. `prefix` не UTF-8 (`%FF`) — 400. Чтение
ключа: ключ не по грамматике (не UTF-8, Cc, Zl, Zp — в том числе U+2028, `.`/`..`, пустой сегмент) — 400; ключ вне семей
двери, включая каталог `testsub/heartbeats` из двух частей, — 403; ключ семьи, которого нет (в том числе каталог внутри
семьи, `testsub/heartbeats/sub`), — 404; ключ, отличный от записанного только регистром или нормализацией (`W-1` при
`w-1`), — свой ключ: 404, не чужой объект (сверка python и go М10/6–11, E1, E2, E4, E7, E8).

**Имена файлов в общих деревьях** — одно кодирование для всех реализаций: [договор журнала событий](../../common/contracts/event-journal.md#имена-файлов-в-общих-деревьях)
(перенесено туда из этого подраздела; разбор ревью стадии A 3–5, № 9).

Ошибка ФС после допуска — отказ записи, а не успех и не «файла нет».

**Тела у ресурса** (перенесено из [М10/10 Н1.5](../../../М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md) `mirror` и Н1.4, части
М10/10-06, -07, -08 по `note` id-map; решение «Спецификации» по вопросу В2 переноса; поле `blob`, дайджест, дверь байтов
консоли, уборка тел — М10/10, урок 6):

```yaml
mirror:   каждое локальное тело — следующим copies живым соседям кольца (Н1.4 mirror), всегда, независимо от mirror.enabled;
          copies — из строки platform/mirror (целое ≥ 0), строки нет или copies не читается — 1 (журнал cammeta-go, урок 10 № 1);
          приём: хэш по мере чтения; PEER_FAILS 3; дверь копии есть только у ключа `<sub>/blobs/sha256-<64 строчных hex>`
          подсистемы с blob-полем; иной ключ (заглавные hex, без `sha256-`, подсистема без blob-поля) — обычный объект,
          его пишет владелец: 405 (сверка python и go М10/6–11, T11)
```

Потолки ресурса (строки таблицы [М10/10 Н1.4](../../../М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md) «Потолки»; проверяются у двери до чтения тела, где
возможно; отказ — не усечение):

| Что | Предел | Где | Слова / код |
|---|---|---|---|
| объект у двери ресурса (чтение, копия тела, кусок зеркала) | 64 МиБ | дверь ресурса (Н2) | `413` |
| строк в ответе `/events` | 1000 по умолчанию, 10 000 предел | индекс (Н1.3) | обрезка, `truncated` |
| срок хранения | конечное число > 0 | ресурс (Н1.3 `retention`) | «не известно», ничего не убирать |
| хранилище объектов | `max_bytes` (0 — без потолка); хранилище само говорит | `put` | `TooLarge` «over this store's limit» |

Уборка тел (М10/10 Н3 «уборка тел»): в исключительном окне оператор закрывает и входящие зеркальные копии; копия, которую
надгробие удалившего новее, не принимается (Н4, «удалено позже» — 409).

**Надгробия и схождение копий тел** (перенесено из [М10/10 Н1.5](../../../М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md) `delete`,
М10/10-09; тела, их дайджест, дверь байтов консоли, зеркало тел у консоли и уборка остаются в М10/10):

```yaml
delete:   надгробие .gone/<ключ> у удалившего — объект {written, peers, acked}: written — стенные секунды удаления, peers —
          соседи кольца, у которых могла быть копия, acked — подтвердившие (журнал cammeta-go, урок 10 № 2); сосед раз в
          10 мин (проход ресурса) читает надгробия удалившего листингом /v1/objects?prefix=.gone/ (обычный листинг .gone/ не
          показывает, записи и удаления .gone/ дверь не принимает) и роняет копию старше written; удаливший раз в 10 мин
          спрашивает каждого из peers GET копии: 404 — подтверждение (в acked), копия есть, иной ответ или неответ — нет;
          объект с тем же ключом записан у удалившего снова после written — надгробие снимается без подтверждений;
          надгробие хранится не меньше 7 дней и снимается только когда все peers подтвердили удаление; неизвестный исход не
          подтверждение; у двери объектов DELETE нет
```

### Н1.2 Событие

Форма строки события (`line`), бакет и его путь (`bucket`), класс (`class`), журнал `audit` (`journal`), писатели файла
(`writer`), id события и экземпляр писателя — [договор журнала событий](../../common/contracts/event-journal.md)
(перенесено туда из этого подраздела; разбор ревью стадии A 3–5, № 9). Урок — его владелец: ресурс читает бакеты (Н1.3),
копирует закрытые (Н1.4 `mirror`), убирает по сроку (Н3 «проход ресурса»). Подавление повторов (`suppress`) —
[глава 3.6 Н1.2](../../03-worker/spec/03.6-worker.norms.md); `older_epochs` и отметки оператора (`marks`) —
[М10/8 Н1.2](../../../М10_Platform/spec/08-events-resource-requests.norms.md) (консоль, урок 6).

`subsystem` строки индекса — имя спеки, и у строк дерева тревог (`testsub`, не `testsub.alarms`; сверка python и go М10/6–11, E32).
`unit` в ответе индекса — полная ссылка `<дерево>/<единица>`;
у журнала это `audit/<роль>`, у отметки — `console/<экземпляр>`, а её `of` — адресат.

### Н1.3 Индекс и срок

```yaml
index:
  one_per_resource: над своим деревом и .mirror/<сервер>/ копиями; состояние всегда live; перестройки нет
  cache:    ограничен (64 MiB), выбрасывается без потери правильности; файл перечитывается по размеру/mtime/inode с места
  query:    from, to (секунды; умолчание 0..1e12), kind, subsystem, unit (<sub>/<id>; голый id — отказ), limit (1000;
            предел 10000), keep (newest | oldest), class, by (t | occurred; occurred читает на 3600 с дальше)
  row:      {id, subsystem, unit, of, epoch, t, kind, server, bucket, class, epoch_is, fenced, …поля}
            # epoch_is и fenced ставит консоль при слиянии; у ресурса строки без них (решение «Архитектора», ревью стадии A)
  epoch_is: current | fenced | earlier-run   # консоль — по current_epochs из <sub>/epoch/* и политике спеки
  cut:      до обрезки дубли по id убрать; сначала alarm, затем observation; внутри класса по by (newest — убывание, oldest — возрастание),
            при равном времени id лексикографически по байтам UTF-8; первые limit строк. truncated ресурса — число оставшихся после этой обрезки
  answer:   {events, state, truncated, partial?}; truncated — неотрицательное целое по cut/merge (всегда); partial: true — хотя бы один
            бакет читался с порванной последней строкой (она не отдана и в truncated не считается); консоль: + complete, incomplete {сервер: did not answer | said <state> | silent}
retention:
  <sub>/retention:        {days}      # умолчание 365; форма строки — P/02.4 Н1.9
  <sub>/alarms_retention: {days}      # умолчание 1095; audit — 1095; форма строки — P/02.4 Н1.9
  writer:   обеих строк — admin командой оператора w2cctl retention (P/02.4 Н1.9); ресурс и консоль их только читают
            (P/02.5 Н1.4; пилот хранилища, решение «Архитектора» 2026-10-18)
  rule:     на подсистему, не на единицу (ADR-0076); days — конечное число > 0, иное — «не известно», ничего не убирать;
            отметки консоли живут не меньше самого долгого дерева; удержания holds: сохраняют бакеты;
            копии зеркала — на час дольше; убранное — журнал events.removed
```

Слияние ответов ресурсов консолью (`merge`) — [М10/8 Н1.3](../../../М10_Platform/spec/08-events-resource-requests.norms.md)
и Н3 «слияние» (консоль, урок 6); форма ответа консоли (`answer` выше, `ConsoleEvents` контракта) — общая с ресурсом.

Запрос использует конечные `from`/`to`, `from ≤ to`; `limit` — целое 1…10000 (сверка python и go М10/6–11, E12–E15):
- `from`, `to` — десятичное число ASCII: необязательный `-`, цифры (между цифрами допустим `_`), необязательная точка с
  цифрами хотя бы с одной стороны, необязательная экспонента `e`/`E` со знаком; `1_0`, `.5`, `5.`, `1e3` — числа,
  `1e-400` — 0; `+1`, пробел (`%201`, `1%20`), не-ASCII цифры (`١`), `0x10`, переполнение — 400;
- `limit` — только цифры ASCII (ведущие нули допустимы: `01`), иначе 400; `since` подсказки — по Н1.6;
- `unit` — UnitRef `<sub>/<id>`: голый id, пусто, `testsub/`, `/c1` — 400;
- пустой или повторённый параметр — 400 (Н2); незнакомый непустой параметр не читается (у `/events/wait` — 400, Н1.6).

**Нечитаемая строка бакета** (P/01.1 Н0 «Устойчивость выдачи»; сверка python и go М10/6–11, E19, E24, E32). Строка, которая не JSON,
не объект, с BOM, с числом вне JSON (`NaN`), без `kind`, `t` или `id`, с `id` не строкой, а также файл не на своём месте
(путь бакета не по Н1.2, например `e01`) — пропускается: в `events` и `truncated` не входит, ответ — 200, а число таких
строк — `lines_garbled` ответа (поле есть, только когда больше 0). Порванная последняя строка — по-прежнему `partial`,
не `lines_garbled`. Консоль складывает `lines_garbled` ответивших ресурсов и сама пропускает строку ответа ресурса не
по форме EventRow, прибавляя её к своему `lines_garbled`. `events` в BucketInfo — число целых читаемых строк бакета;
500 перечня — только нечитаемый каталог или метаданные.

Для `by=occurred` строка без occurred использует t и при фильтре, и при сортировке.
Умолчания `keep=newest`, `by=t`; отсутствие `class` означает оба класса. Иная форма — 400,
включая NaN/Infinity, дробный limit и голый unit. Лимит возвращает выбранное подмножество;
`limit` ограничивает и каждый ресурс, и итог консоли. Ресурс считает в `truncated` подходящие
уникальные по id целые строки, не вошедшие в его локальный limit. Консоль возвращает сумму
локальных truncated ответивших источников плюс число отброшенных общей обрезкой строк
после дедупликации полученных кандидатов. Копии, пропущенные разными источниками, могут
учитываться несколько раз: это счётчик пропусков на стадиях, не число разных потерянных
событий и не число пропусков у молчащих источников. Дополнительного чтения всех скрытых
строк для точного глобального счёта урок не требует.
`fenced=true` тогда и только тогда, когда `epoch_is=fenced`; earlier-run не ограждён.
В этом уроке не обещан атомарный снимок нескольких файлов или ресурсов.
Неизвестное чтение срока или удержаний не равно отсутствию: зависимое дерево не удаляется
до достоверного чтения. Отсутствующая строка retention даёт умолчание, ошибка чтения — нет.
`complete` у консоли — отсутствие причин в `incomplete`; это полнота ответивших источников,
а не отсутствие обрезки по limit. `partial` переносится от ответившего ресурса, если true.

PULSE_LIMIT — конечный положительный предел длительности одного шага ресурса в секундах,
выбранный и объявленный реализацией до старта. Длительность измеряется местными
монотонными часами, а не t/at писателя; превышение даёт pass_stalled в следующем пульсе.
Это диагностический порог, не обещание остановить зависший вызов или дождаться ответа.

**Восстановление бакетов** (перенесено из [М10/11 Н1.4](../../../М10_Platform/spec/11-the-platform-on-a-box-and-a-cluster.norms.md)
`restore`, М10/11-09; отказ сервера и `power_pull` остаются в М10/11 и P/04):

```yaml
restore:    ресурс при старте тянет свои закрытые бакеты от соседей, чьи пульсы mirrors его называют: GET /mirrored/<я>,
            каждый бакет по сумме, tmp + rename; PEER_FAILS 3 подряд — сосед пропущен на попытку; RESTORE_RETRY 10 с,
            удвоение до 600; сделано, когда получены полные списки и проверены копии от всех известных необходимых соседей;
            необходимые соседи — чьи читаемые пульсы mirrors называют этот сервер; локальные события потеряны, а пульсы
            соседей не читаются или пульса соседа нет — необходимы все известные двери серверов (platform/doors, door_row выше),
            кроме своей: каждая обязана ответить полным перечнем GET /mirrored/<я> (полный пустой перечень и 404 — копий

            потом — переиндексация подсистемы; копия — никогда не источник, пока хозяин отвечает (mirror выше)
```

### Н1.6 Подсказка и представления HTTP

`GET /events/wait` ресурса — подсказка по ADR-0038, не доставка событий. Профиль урока:
`want` — непустой список через запятую `<sub>/<kind>[/<unit>]`; каждая часть из ASCII букв,
цифр, `_`, `-`, `.`, 1…64 знака, не начинается с точки. `client`, если передан, — 1…128
печатных ASCII-знаков без пробела. `since` — десятичный uint64 без знака/ведущих нулей,
по умолчанию 0. `timeout` — конечное число секунд в (0,30], по умолчанию 30.
Пустые/повторные параметры, незнакомые параметры (`&foo=1`), иные формы и значения вне области — 400; `since` и
`timeout` — только цифры ASCII (и точка у `timeout`), не-ASCII цифры — 400 (сверка python и go М10/6–11, E14, E16). `since=0` —
у клиента нет позиции: ответ сразу `{changed: true, seq, touched}`, если под want есть строки в бакетах ресурса любой
давности; seq — непрозрачное монотонное число процесса ресурса, клиент только сравнивает и передаёт его обратно
(сверка python и go М10/6–11, E46). Подсказку дают деревья подсистем каталога (`<sub>`, `<sub>.alarms`); деревья `console` и `audit`
подсказки не дают (обе реализации так, нормы не было).
Этот ограниченный профиль не требует принимать любые внутренние имена единиц: периодический
проход клиента остаётся обязательным и работает без подсказки.

Ответ — одна из закрытых форм WaitAnswer: `{changed:true, seq, touched:[…]}`,
`{changed:false, seq}`, `{changed:false, seq, full:true}` или
`{changed:false, seq, replaced:true}`. В touched — отсортированные уникальные
`<sub>/<kind>/<unit>`, подходящие want; самих событий нет. seq относится к одному процессу
ресурса; после перезапуска/неизвестной последовательности клиент делает обычный проход.
При full/replaced клиент не продвигает свой курсор по seq, а возвращается к обычному проходу.
По умолчанию до 16 ожиданий (параметр развёртывания LONG_POLL_WAITERS); новое ожидание при
заполнении отвечает 200/full. Именованный клиент вытесняет своё прежнее ожидание: 200/replaced.
В TLS личность — CN сертификата плюс client; другой CN не вытесняет ожидание (ADR-0075).
Без client развёртывание использует отдельное ожидание на адрес клиента; повтор при занятом
адресе — full. Наблюдение текущих бакетов каждые 0,1 с, пока есть ожидающие; пропущенная
подсказка или запись в старый бакет восполняется обычным проходом, а не обещанием доставки.

Пути `/mirror/{server}/{path}`, `/mirrored/{server}[/{path}]`, `/events/{path}` (сверка python и go М10/6–11, E26, E27, E29, E34):
`{server}` — один сегмент по грамматике имени сервера (P/02.4 Н1.2 `SERVER_NAME`); `{path}` — путь бакета Н1.2
(`<дерево>/<unit>/e<эпоха>/<начало>Z.events.jsonl`), ни один сегмент не пуст и не `.`/`..`, `%2F` — не разделитель,
`.tmp` — не бакет. Иное: `GET /mirrored/…` и `GET /events/…` — 404 без тела, `PUT /mirror/…` — 400 без тела. Файл вне
своего дерева (`.mirror/<server>/` у копий) ресурс не читает и не пишет никогда. `PUT /mirror` бакета, чей конец по имени
позже часов приёмника, — 400: зеркало принимает только закрытые бакеты. Значение `X-Sum` — поле HTTP: пробелы по краям
(OWS) отбрасываются до проверки формы (E35).

Представления HTTP — в схемах Н2. `BucketInfo` — описание одного бакета, не событие;
`/buckets` выдаёт UTF-8 JSON Lines: один объект на LF, без массива. `/mirrored/<server>`
по канону этого урока выдаёт `{copies:[{path,written,size,sum}]}`. Байты копии — отдельный
GET. Поле `sum` и заголовок X-Sum — 64 строчные hex-цифры SHA-256 целого тела.
Форма `answered` (метка-строка просьбы, AnsweredMark) — [М10/8 Н1.6](../../../М10_Platform/spec/08-events-resource-requests.norms.md)
(дверь консоли, урок 6).

## Н2 Двери

Полный контракт: [OpenAPI](05-resource.api.openapi.yaml).
GET объекта ограничен 64 МиБ по реально прочитанным байтам: ровно предел разрешён,
+1 байт — 413 ResourceError до успешных заголовков; тело до подтверждения размера
ограниченно буферизуется либо проверяется по неизменяемому объекту с достоверным размером.
Потолок самого хранилища может быть выше и этот предел двери не отменяет. Он различает
ресурс и консоль, JSON-ответы, поток байтов и отсутствие тела. Схемы задают обязательные
поля и допустимые расширения; проверки существования, прав, UTF-8-размера и состояния
исполняются отдельно. Внешний массив не заменяет JSON Lines.

| Вход | Успех | Прикладные отказы |
|---|---|---|
| ресурс GET /v1/objects | 200 ObjectListing | 400 ResourceError; 403 ResourceError или ResourceDenied; 503 ResourceError |
| ресурс GET /v1/objects/{key} | 200 байты; X-Written, X-Server, при необходимости X-Missing | 400/403/404/413/503 ResourceError |
| ресурс PUT /v1/objects/{не-блоб} | нет | 405 ResourceError; ключ/scope — 400 |
| ресурс GET /buckets/{sub}/{unit} | 200 JSON Lines из BucketInfo | 404/500 без тела |
| ресурс GET /events | 200 ResourceEvents; у ресурса `HEAD` — 405 | ресурс 400 ResourceError (разбор ниже); ресурс 503 ResourceError |
| ресурс GET /events/wait | 200 WaitAnswer, в том числе full/replaced | 400 ResourceError; общая полоса занята — 503 ResourceError |
| ресурс GET /events/{path} | 200 целые байты + X-Sum; 206 один диапазон + Content-Range | 404/500 без тела; 416 text/plain + Content-Range |
| ресурс PUT /mirror/{server}/{path} | 204 без тела; заголовок `X-Sum` — SHA-256 тела (64 строчных hex), обязателен | нет `X-Sum` или он не по форме — 400, тело не принимается; SHA-256 тела не совпала — 422; 408/413/500 — без тела |
| ресурс GET /mirrored/{server} | 200 MirroredListing | 404/500 без тела |
| ресурс GET /mirrored/{server}/{path} | 200 байты + X-Sum | 404/500 без тела |
| ресурс `PUT /v1/objects/<sub>/blobs/<digest>` | 204 без тела. Обязательны длина ≤64 МиБ, `X-Written` — неотрицательное время исходной копии (нет или не число — 400), имя sha256 с 64 строчными hex; байты не того дайджеста — 422; ключ не blob-формы или подсистема без blob-поля — 405, как у любого объекта (Н1.1 «Тела у ресурса» `mirror`; сверка python и go М10/6–11, T10, T11). При чтении проверяются фактический предел/сумма | 400/404/405/408/409/411/413/422/503 — `ResourceError`, 403 — он либо `ResourceDenied`. Общие отказы консоли сюда не применяются (перенесено из М10/10 Н2) |

`GET /events` консоли (слияние, ConsoleEvents, `HEAD`) и двери консоли `POST /marks`, `POST /{sub}/requests`,
`DELETE /{sub}/asked/{sha16}` — [М10/8 Н2](../../../М10_Platform/spec/08-events-resource-requests.norms.md) (урок 6); схемы
ответа `/events`, общие обеим дверям (`EventRow`, `UnitRef` и ниже), — в контракте этого урока.

Для обоих перечней (`/buckets/{sub}/{unit}` и `/mirrored/{server}`) все необходимые
чтения каталога/метаданных завершаются до успешных заголовков: неизвестность/ошибка —
500 без тела, не 404 и не пустой 200. Это наблюдённый перечень, не снимок нескольких файлов.
Обрыв уже начатой передачи перечня не является полным ответом; новый HTTP-статус
после заголовков не отправляется.

ResourceError — только `{error: текст}`. Отказ 404 при чтении объекта означает «нет среди ответивших»;
при неполном опросе X-Missing обязателен, полнота не выводится из самого кода 404.

**Разбор запроса.** Дверь ресурса — по P/01.1 Н2.1
(query, путь байт в байт, HTTP по RFC 9112, ранний отказ) с отступлениями: отказ разбора query — 400 ResourceError
`{error}`; пустой или повторённый параметр — 400; нет пути и неподдержанный метод — 404/405 без тела, в том числе
`OPTIONS`, `POST /events`, `PUT /v1/objects` (листинг), `GET`/`POST`/`DELETE` на `/mirror/…`; `PUT /v1/objects/{не-блоб}` —
прикладной 405 ResourceError (Н4); `/buckets/{sub}/{unit}` — ровно два непустых сегмента, `/buckets/testsub/`,
`/buckets/../objects`, `/buckets/testsub%2Fc1` — 404 без тела; тела `PUT` — байты, JSON не разбирается (сверка python и go М10/6–11,
E9, E10, E17, E30, E31, E36).

ResourceDenied (`error=refused`, detail,
role при отказе роли) — 403 шлюза ресурса, до обработчика маршрута. Отказ TLS до HTTP
не получает выдуманного HTTP-тела. Каждый применимый общий ответ внесён в OpenAPI.
При busy — Retry-After: 1. На неизвестном пути — 404; на неподдержанном методе известного
пути — 405; у ресурса оба без тела. Этого общего правила достаточно:
оно не создаёт отдельный метод OpenAPI для каждой невозможной операции.

**Допуск к дверям ресурса** (ADR-0075 доп. 2026-10-12 (3)). Ресурс с TLS проверяет клиента: цепочка до центра,
серийник не в `revoked` ([договор сертификата роли](../../common/contracts/role-certificate.md) `revoke`), ровно одна роль из строки маршрута, CN = `<роль>.<SAN DNS>`; иначе отказ
рукопожатия или 403 `ResourceDenied` с ролью и маршрутом. Клиент сверяет роль `resource` и SAN DNS сервера с хостом
адреса; IP при TLS — отказ клиента.

| Маршрут ресурса | Допущенные роли |
|---|---|
| `/events*`, `/buckets/`, `/mirrored/` | `console`, `resource`, `<sub>worker` спек каталога |
| `PUT /mirror/` | `resource` |
| чтение `/v1/objects` (семьи Н1.1 `door`); `PUT /v1/objects/<sub>/blobs/<digest>` (Н2) | любая роль с комплектом (P/02.4 Н1.6) |

**Ограничения профиля.** Файл бакета читается целиком или одним Range; составные Range и
условные HTTP-запросы не входят в урок. Размер ответа фиксируется перед чтением; ответ
не обещает снимка всего дерева. После начала выдачи обрыв потока не превращается во второй
HTTP-статус: вызывающий не принимает неполные байты как целую копию. Приём зеркала ограничен
64 MiB и объявленным развёртыванием сроком чтения; превышение размера — 413, срока — 408.
`PUT /v1/objects/<sub>/blobs/<digest>` — копия тела соседа (таблица выше; Н1.1 «Тела у ресурса»); `PUT /<rows>/<id>/<blob_field>`
целиком принадлежит [М10/10](../../../М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md) Н2 (дверь байтов консоли); прочие
объекты дверь ресурса не пишет — отказ записи не-блоба, частичной копии контракта блобов нет.

## Н3 Проход

### старт ресурса — проверка схемы

Перенесено из [М10/10 Н3](../../../М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md) «старт контроллера,
воркера, ресурса или консоли — проверка схемы» в части ресурса (часть М10/10-01; строка `platform/schema` и её подъём —
М10/10 Н1.1, урок 6; прочие процессы — там же и в P/03.2, P/04). Порядок старта ресурса — [жизненный цикл](../lifecycle.md).

```
первым шагом старта, до чтения спеки (P/02.3), у всех четырёх процессов:
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
  ошибка чтения → ждать доступности, не начиная работы; не стартовать — выход с кодом 2 и строкой лога
```

### записать событие (платформа, по observe подсистемы)

Сторона владельца файлового контракта; форма строки, бакет и писатели файла — [договор журнала событий](../../common/contracts/event-journal.md),
сторона писателя по `observe` — [глава 3.6](../../03-worker/spec/03.6-worker.norms.md).

```
1. class ∈ {alarm, observation}; поле class в строке — отказ; occurred не число — отказ; v — отказ
2. of: из about спеки (<sub>/<id>); строка подсистемы со своим of → отказ «of is the platform's to write»;
   деревья console и audit — своё of
3. подавление — глава P/03.6 Н1.2 (перенесено туда)
4. бакет по t: <root>/<дерево>/<unit>/e<эпоха>/<start>Z.events.jsonl; новый каталог — барьер каталога
5. дописать строку; тревога/журнал — fsync строки и каталогов до корня
```

**Гонки.** Один писатель на бакет (Н1.1; журнал — под блокировкой файла, договор журнала событий `writer`): дописывание не конкурирует; два процесса одного `of` (переезд, эпоха) пишут в разные пути — путь несёт эпоху — и не смешиваются; ротация бакета по `t` — закрытие старого и открытие нового в одном писателе.

### запрос (ресурс) → {events, state, truncated}

```
1. проверить параметры (Н1.3)                                          → 400 (у ресурса ResourceError, у консоли TextError)
2. кандидаты: окно ≤ 144 бакетов — имена по времени; шире — листинг каталога; если граница не представима именем календаря — листинг, без переполнения; оба дерева подсистемы (и .alarms);
   копии .mirror/*: тот же бакет — дубль, отвечает под именем хозяина
3. читать файлы с места прошлого чтения (кэш по размеру/mtime/inode); порванная строка — пропустить (partial);
   нечитаемая строка или файл не на месте — пропустить и счесть в lines_garbled (Н1.3), ответ не 503
4. фильтр: kind, subsystem, unit (и строки с of = unit), class, окно по t (или occurred, +3600)
5. epoch_is и fenced ресурс не ставит: их ставит консоль при слиянии (М10/8 Н3 «слияние»); права на <sub>/epoch/* ресурсу не нужны
6. убрать дубли id, упорядочить и взять первые limit по cut Н1.3; truncated = число кандидатов после дедупликации минус число выданных
→ строки Н1.3; больше 8 запросов разом → 503 busy, Retry-After: 1
```

**Гонки.** Чтение открытого бакета во время дописывания: отдаются только целые строки, порванная не отдаётся и ответ несёт `partial: true` (`truncated` — число, Н1); перечисление не фиксирует содержимое файлов: исчезнувший файл не подтверждает пустой бакет. Ошибка чтения файла или каталога не выдаётся как полный ответ; после начала HTTP-потока — обрыв, до него — 503 ResourceError. Нечитаемая строка — не ошибка чтения: она пропускается и считается (Н1.3, P/01.1 Н0 «Устойчивость выдачи»).

### проход ресурса — каждые 600 с

```
retain:  для каждого дерева: days = <sub>/retention | 365 (tree.alarms — alarms_retention | 1095; audit 1095;
         console — 1095, не раньше самого долгого дерева);
         days не число или ≤ 0 или строка не ответила → не известно: ничего не убирать, назвать в пульсе;
         убрать закрытые бакеты старше days (отметки консоли — не раньше самого долгого; holds сохраняют;
         копии зеркала — days + 1 ч); журнал events.removed; index.forget
usage:   измерить тома (зонд ≤ 5 с); пульс space/volumes
relieve: platform/space.enabled ∧ used/total > high → для спек с requests.free: need = used − total·low − Σ freeing
         need > 0 → записать free-<server>-<volume> {free: need, volume, server, at}: cas "" или cas по версии строки СВОЕЙ формы
         (без unit И с точными server/volume текущего тома); перед записью проверить грамматику Н1.4 `free_ask`;
         под этим ключом строка с unit, чужими server/volume или испорченной формой → не трогать, журнал free_ask.key_taken, пропустить;
         need ≤ 0 (всё нужное уже освобождается, ADR-0059) или ниже low → удалить строку своей формы, если есть: delete с cas версии,
         на которой проверены отсутствие unit И точное совпадение server/volume (P/01.1); conflict — под ключом уже другая строка (обычная просьба или новая своя) → не трогать,
         журнал free_ask.key_taken
mirror:  platform/mirror.enabled → соседи = следующие copies живых по имени; закрытые бакеты, которых у соседа нет
         (сумма) → PUT /mirror/<я>/<путь> с X-Sum = SHA-256 бакета; PEER_FAILS подряд → сосед пропущен на проход
каждый шаг — своя попытка; шаг дольше PULSE_LIMIT → pass_stalled в пульсе
```

**Гонки.** В одном проходе retain предшествует mirror; это не блокировка от другого чтения/очистки. Копируется только целый закрытый бакет с проверенной суммой; исчезновение/неполное чтение даёт неуспешную попытку, без публикации частичной копии. Следующий проход заново перечисляет доступные бакеты. Хозяин и копия: копия никогда не источник, пока хозяин отвечает; `restore` (Н1.4 «Восстановление бакетов») тянет копии обратно только по слову хозяина. Снятие `free_ask` и обычная просьба под тем же ключом: ресурс проверил форму на версии v и остановился; жнец снял его старую строку по ttl, консоль приняла обычную просьбу с тем же rid — у ключа версия v′; `delete` с cas v отвечает conflict, принятая просьба цела; без cas она была бы удалена без исхода (ADR-0054).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **хранилище объектов на коробке и в кластере** (`OBJECTS` URI, каталоги, надгробия удаления `.gone/<ключ>` — Н1.1 «Надгробия»), пределы размера;
2. ~~**как ресурс узнаёт присутствие процессов**~~ — нормировано: [договор замка присутствия](../../common/contracts/presence-lock.md) `presence_lock` (второй пилот, Н-1);
3. **политика вытеснения кэша индекса** в пределах 64 MiB (Н1.3); число полос слияния (8) и срок (3 с) — норма М10/8 Н3 «слияние», не выбор;
4. **долгий опрос `/events/wait`**: устройство памяти наблюдений и развёртываемый предел ожиданий; формы want/ответа и профиль таймаута — Н1.6, не выбор;
5. **строка журнала**: поля сверх `sub`/`target`/`addr` договора журнала событий `journal`, роль-писатель, эпоха дерева (`e1`);
6. **потоки и чтение тела**: срок приёма зеркала, способ проверки целого тела до публикации, различение отказа до заголовков и обрыва после (пределы и сроки POST консоли — М10/8 «Решает реализация» п. 8);
7. **PULSE_LIMIT** ресурса: конечное положительное число секунд из объявленного профиля, неизменное на протяжении прогона; Н1.4 задаёт измерение и исход, а не конкретное число.
