# Judge-only case data

This English text is the source; the Russian translation `ru/forms/README.cases.md` is derived from it (ADR-0121).

Generic rules remain in [README.md](README.md). The following original passages preserve the existing named case associations as judge-only provenance.

### Original passage 1

- s63 `resource-free-ask`: valid requests.free catalogue, volume events with total 1000 / used 800, high 0.85 / low 0.75, no unreflected freeing; need 50 is positive inside the band. Establish an actual own row with the supplied free/volume/server/at and confirmed version mapped to v1. Invoke and await the real synchronous relieve, then read the actual row and version and count actual writes/deletes. There is no sleep or separate completion API. Neither the input own_request nor expect is an output substitute.
- s64 `resource-query`: ordinary writer-published two events at 100/700 in their proper epoch/bucket paths. Run both supplied queries over unchanged actual files with all caches neutral. The windows contain 144/145 bucket names; record the actual candidate branch as names/listing from controlled file IO. Compare the complete actual answers for same_answer; events is their count and truncated is observed, not precomputed from fixtures.
- s65 `resource-query`: the same real two-event files, finite supplied calendar-unrepresentable bounds, listing fallback and the normal filter. Observe the real status/count and branch; a panic, overflow or synthetic empty answer fails.
- s66 `resource-restore`: a real complete listing of two checksum-valid closed buckets at necessary srv-b. Attempt 1 gets three actual unavailable pull replies and must make no further peer calls in that attempt. At the next admitted retry boundary attempt 2 has the supplied reply sequence over those pulls: unavailable, valid, unavailable, unavailable, valid. An actual successful bucket resets the local consecutive-failure sequence. Observe completion, actual call trace, next-attempt consultation and whether accumulated diagnostic counters reset; no synthetic diagnostic totals.
- s67 `resource-pass`: valid closed local buckets and a live srv-b door, the supplied copy reply sequences through two real passes at their normal admitted starts. The next pass is driven with a controlled clock according to PASS_EVERY, not bypassed or delayed by an invented bound. Observe no calls after the current-pass skip, consultation on the next pass, the successful-copy reset and monotonic cumulative diagnostics. The restore sequence is not shared with mirror.

### Original passage 2

- s38-s40, resource-body-copy: run two actual resources, srv-a and srv-b, with a schema-valid blob of source written 100. The controlled clock first admits a sweep batch marked at 101 and observes its unchanged version for 300 monotonic seconds. Stop and join all ordinary writers and incoming copies and confirm peers before the regular deletion helper used by the admitted sweep. Use delete_clock 100 or 50, preserve the exact removed version's stamp, then durably publish the actual tombstone and resume propagation. Drive the neighbour's ordinary pass and the deleter's ordinary GET/ack pass. Read tombstone_written from its body, not its object-listing write stamp. The old peer copy must disappear and GET 404 must supply ack; the distinct newer peer version 100.002 must stay with that source stamp and must not acknowledge deletion. copy_source_written_changed records an observed rewrite of the copy's version stamp. Never substitute a hand-built tombstone or the expected formula for the deletion helper.
- s41-s45, resource-presence: cold start with no remembered slot; listing succeeds and the listed file exists. Inject EACCES at the named open/read/flock/fstat/stat operation of the actual reader. Supply empty current lock content for a check error without an available name; for read use a real read error, not parse failure. A parse failure on an otherwise busy readable lock remains the old anonymous-live case s25. No file is removed on an unknown check. The other role testsub2 has one busy valid numbered lock n=2, HOST_MEMORY_MB=100 and WORKER_MEMORY_MB=1; its independent room is min(100-1,98-1)=97 and live is "2". Observe fields actually published by the heartbeat and door row; an absent aggregate is not a manufactured empty successful snapshot.
- s46, resource-wait: exactly 16 real pending waits include old; the other 15 have disjoint identities. The new verified CN/client equals old. Observe the old terminal WaitAnswer, the new connection still pending, and actual counters; do not open 16 additional waits beside old. Certificate validation is unchanged.
- s47-s48, resource-restore: a single necessary neighbour srv-b. empty_404 is an actual 404 without body for GET /mirrored/srv-a and completes that neighbour. complete is a full valid listing; bucket_replies 404 means the subsequent GET of that listed bucket returns 404 without body, repeated through PEER_FAILS. missing counts that unreceived listed bucket, not retries; done remains false. Never turn a failed GET into an empty listing.
- s49-s62, resource-retain: publish a whole closed bucket through the ordinary writer at its logical written, with the path window [0, 600). mtime is deliberately changed independently. Invoke the actual retention pass with a controlled wall clock; observe physical removal and the logical stamp read before deciding, not a decision computed by the adapter. Normal and alarm terms are 1 and 2 days respectively. audit keeps its default 1095 days; console's effective term is at least the longest tree, 1096 days in s55/s56. A late mirror has its own receiver written 90000 and source bucket written 100; its term adds 3600 seconds. For restore_copy_written, perform the real checksum-checked restore first at restore_clock 150000, then evict caches/reindex or restart and run retain; do not seed an already restored metadata answer. The copied stamp 90000 remains the local stamp. At each boundary equality deletes, the previous millisecond keeps. confirmed_hold supplies an actual readable hold that covers this unit/window; unreadable holds is an actual failed read. Both keep the bucket before the expiration predicate.
