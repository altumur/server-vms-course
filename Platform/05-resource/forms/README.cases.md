### Original passage 1

- s63 `resource-free-ask`: valid requests.free catalogue, volume events with total 1000 / used 800, high 0.85 / low 0.75, no unreflected freeing; need 50 is positive inside the band. Establish an actual own row with the supplied free/volume/server/at and confirmed version mapped to v1. Invoke and await the real synchronous relieve, then read the actual row and version and count actual writes/deletes. There is no sleep or separate completion API. Neither the input own_request nor expect is an output substitute.
- s64 `resource-query`: ordinary writer-published two events at 100/700 in their proper epoch/bucket paths. Run both supplied queries over unchanged actual files with all caches neutral. The windows contain 144/145 bucket names; record the actual candidate branch as names/listing from controlled file IO. Compare the complete actual answers for same_answer; events is their count and truncated is observed, not precomputed from fixtures.
- s65 `resource-query`: the same real two-event files, finite supplied calendar-unrepresentable bounds, listing fallback and the normal filter. Observe the real status/count and branch; a panic, overflow or synthetic empty answer fails.
- s66 `resource-restore`: a real complete listing of two checksum-valid closed buckets at necessary srv-b. Attempt 1 gets three actual unavailable pull replies and must make no further peer calls in that attempt. At the next admitted retry boundary attempt 2 has the supplied reply sequence over those pulls: unavailable, valid, unavailable, unavailable, valid. An actual successful bucket resets the local consecutive-failure sequence. Observe completion, actual call trace, next-attempt consultation and whether accumulated diagnostic counters reset; no synthetic diagnostic totals.
- s67 `resource-pass`: valid closed local buckets and a live srv-b door, the supplied copy reply sequences through two real passes at their normal admitted starts. The next pass is driven with a controlled clock according to PASS_EVERY, not bypassed or delayed by an invented bound. Observe no calls after the current-pass skip, consultation on the next pass, the successful-copy reset and monotonic cumulative diagnostics. The restore sequence is not shared with mirror.
