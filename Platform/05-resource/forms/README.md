# P/05 forms and resource seams

This English text is the source; `ru/forms/README.md` is its Russian translation for people, not in the export. These forms express the resource norms of the lesson.

## Process inputs and refusals

[daemon-flags.tsv](daemon-flags.tsv) uses `flag type default default_text required commands bad norm`. `$NAME` is an environment variable, never an added CLI flag; the process command is resource. Types and CEL are the P/01 and P/03 grammar. The launcher reads environment files, the process consumes environment. A missing bad expression removes no imported validation. Computed defaults in default_text are resolved by the cited norm; string input does not create a stricter hostname, URL or decimal spelling rule. Deployment ceilings with no named environment variable are not invented as environment.

[refusals.tsv](refusals.tsv) uses `chapter row name surface code kind fields headers log norm word response_schema cause outcome diagnostic caller`. Literal TAB without CSV quoting. Chapter is `5`; repeated row numbers are projections of one original refusal. The four final cells preserve its original N4 cells. `response_schema` names a component in the lesson OpenAPI, or `-` for no body/text. `kind` is `-`: ResourceError is an error-text object, not a P/01 Fault. Schema-required fields and constant values remain in the component. Success and truncation rows retained from N4 are not relabelled as an error. A call projection does not invent HTTP for an internal procedure.

## HTTP door

[door-roles.tsv](door-roles.tsv) uses `method path roles norm` over the existing [OpenAPI](../spec/05-resource.api.openapi.yaml) operations. In door mode `mtls`, a role is checked before its handler, after operation matching; `*` means any authenticated kit role, `<sub>worker` expands only over the loaded catalogue. TLS chain, role/CN/SAN and revocation remain the role certificate contract. An unknown path and an unsupported method have no body (P/05-R041 and P/05-R042), including HEAD /events; there is no Common404/405 response schema. The object PUT of a non-blob is a separate application 405 ResourceError.

Routing is declared by `x-route-priority`, `x-path-capture`, `x-path-decode`, `x-path-error` in that OpenAPI, under P/05-R057. Do not percent-decode the whole path before matching, split an encoded slash as a separator, normalize a trailing slash, or retry a less specific operation after a parameter error. Error body shape follows the parameter’s method projection; the ResourceError error string has no fixed wording.

## Seams

The synchronous CALL ports use the CALL/JSON grammar of [P/03](../../03-worker/forms/README.md) and [P/02](../../02-installer/forms/README.md): one JSON input, native JSON output, recursive object subset, exact arrays and empty objects. Chapter `5` uses acceptance/ directly. These ports normalize evidence, not the implementation API; invoke real resource functions and record their effects, never return an expected answer. Each scenario has a fresh temporary root and valid catalogue, directory, identity, limits, rows and files before its intervention. An unexpected panic or unrelated error fails; it is not a normal refusal.

Unspecified input values complete a valid neutral background, not an unavailable read. Fixture words select the byte/file or controlled-client setup below, not precomputed outcomes. Version labels v1/v2 denote fresh schema-valid versions of the controlled store; map observed versions back to these labels, never send those labels as malformed wire versions. Counters and body sizes come from actual calls and bytes. Absent optional lines_garbled/truncated normalize to zero only in their numeric observations.

They do not prove OS deployment, complete TLS/peer behaviour, disk durability, all late reads, or the complete resource lifecycle. [stages.tsv](stages.tsv) is a possible order, not a lesson norm; no kit-complete stage is claimed. The full acceptance remains the runner’s 35 scenarios and 304 steps plus the additional probes and common packages assigned by consumers.tsv.

## Numeric query lexemes

Under P/05-R022 and P/05-R031, the OpenAPI query Parameter Object uses the closed extension `x-query-lexeme`: required `pattern` (a full, anchored regular expression) and `parse` (`number`, `integer`, or `uint64`), optional `strip` (only the string `_`); no other keys. It applies to a supplied parameter after ordinary query percent decoding and `+` to space decoding, before typed range validation. An absent parameter still uses its existing default. Empty or repeated parameters follow the existing refusal, independently of this extension.

Match the decoded text against `pattern` before removing every `strip` character. `number` means a decimal finite binary64 value: a finite underflow becomes zero, an overflow is refused; schema type must be number. `integer` means an exact decimal integer, then the schema bounds, without rounding through binary64; schema type must be integer. `uint64` means an exact unsigned decimal integer in 0…18446744073709551615; schema type is string and the handler keeps the original canonical decimal text. `strip` is allowed only for number. A lexical, conversion or bound error takes the existing 400 ResourceError path; its error string is not fixed. The extension does not replace cross-parameter rules such as from ≤ to or late only with by=occurred.

The literal patterns in OpenAPI are the machine source. from/to accept underscores only between ASCII digits, optional minus, a decimal point with digits on at least one side and an optional exponent; no leading plus. limit/late accept ASCII digits including leading zeros. timeout accepts ASCII digits and at most one dot with digits on at least one side; no sign, exponent or underscores. since is canonical unsigned decimal. These are the existing resource spellings, not the different console query grammar.

## Resource witnesses

The additional seams s38-s62 use the same ports and real implementation paths. They add no native command, CLI, role, response word or kit part.

- resource-body-copy: run two actual resources with a schema-valid blob of the supplied source written. The controlled clock first admits a sweep batch at the supplied mark and observes its unchanged version for the supplied monotonic seconds. Stop and join all ordinary writers and incoming copies and confirm peers before the regular deletion helper used by the admitted sweep. Use the supplied delete_clock, preserve the exact removed version's stamp, then durably publish the actual tombstone and resume propagation. Drive the neighbour's ordinary pass and the deleter's ordinary GET/ack pass. Read tombstone_written from its body, not its object-listing write stamp. copy_source_written_changed records an observed rewrite of the copy's version stamp. Never substitute a hand-built tombstone or the expected formula for the deletion helper.
- resource-presence: cold start with no remembered slot; listing succeeds and the listed file exists. Inject the named error at the named open/read/flock/fstat/stat operation of the actual reader. Supply empty current lock content for a check error without an available name; for read use a real read error, not parse failure. A parse failure on an otherwise busy readable lock remains anonymous-live. No file is removed on an unknown check. Another role named in the input with a busy valid numbered lock keeps its own room and live, computed from the supplied memory budgets. Observe fields actually published by the heartbeat and door row; an absent aggregate is not a manufactured empty successful snapshot.
- resource-wait: the real pending waits include old; the others have disjoint identities. The new verified CN/client equals old. Observe the old terminal WaitAnswer, the new connection still pending, and actual counters; old is one of the pending waits, not an extra one. Certificate validation is unchanged.
- resource-restore: empty_404 is an actual 404 without body for the neighbour's mirrored listing GET. complete is a full valid listing; bucket_replies 404 means the subsequent GET of that listed bucket returns 404 without body, repeated through PEER_FAILS. missing counts that unreceived listed bucket, not retries; done comes from the real implementation. Never turn a failed GET into an empty listing.
- resource-retain: publish a whole closed bucket through the ordinary writer at its logical written, with the supplied path window. mtime is deliberately changed independently. Invoke the actual retention pass with a controlled wall clock; observe physical removal and the logical stamp read before deciding, not a decision computed by the adapter. audit keeps its default term; console's effective term is at least the longest tree. A late mirror has its own receiver written and source bucket written; its term adds MIRROR_RETENTION_EXTRA. For restore_copy_written, perform the real checksum-checked restore first at the supplied restore_clock, then evict caches/reindex or restart and run retain; do not seed an already restored metadata answer. The copied stamp remains the local stamp. At each boundary equality deletes, the previous millisecond keeps. confirmed_hold supplies an actual readable hold that covers this unit/window; unreadable holds is an actual failed read. Both keep the bucket before the expiration predicate.

These are mandatory source witnesses, pending actual generator/runner implementation and the joint normgen+kit GATE at coord103. Publishing these inputs is not execution of the resource, OS durability, TLS or SUT acceptance.

## Numeric source and completed calls

[runtime-constants.tsv](runtime-constants.tsv) is the sole numeric source of the 14 owned positive integer settings. The lesson [OpenAPI](../spec/05-resource.api.openapi.yaml) keeps the existing typed HTTP bounds/defaults; the P02 space schema keeps high/low. This adds no environment, CLI setting, public response word, native command or kit part. PEER_FAILS in s47/s48 uses this source, not a second value.

The five added calls use the previous 14 ports and fresh real setup:

- `resource-free-ask`: Establish an actual own row with the supplied free/volume/server/at and confirmed version. Invoke and await the real synchronous relieve, then read the actual row and version and count actual writes/deletes. There is no sleep or separate completion API. Neither the input own_request nor expect is an output substitute.
- `resource-query`: Run supplied queries over unchanged actual files with all caches neutral. Record the actual candidate branch as names/listing from controlled file IO. Compare the complete actual answers for same_answer; events is their count and truncated is observed, not precomputed from fixtures.
- `resource-query`: the same real event files, finite supplied calendar-unrepresentable bounds, listing fallback and the normal filter. Observe the real status/count and branch; a panic, overflow or synthetic empty answer fails.
- `resource-restore`: a real complete listing of checksum-valid closed buckets. An actual successful bucket resets the local consecutive-failure sequence. Observe completion, actual call trace, next-attempt consultation and whether accumulated diagnostic counters reset; no synthetic diagnostic totals.
- `resource-pass`: valid closed local buckets and a live door, the supplied copy reply sequences through real passes at their normal admitted starts. The next pass is driven with a controlled clock according to PASS_EVERY, not bypassed or delayed by an invented bound. Observe calls after the current-pass skip, consultation on the next pass, the successful-copy reset and cumulative diagnostics. The restore sequence is not shared with mirror.

All normalized booleans above are observations of actual calls/rows/counters. Adapter or producer support is a separate obligation; this source does not claim it executed any call. The current heartbeat reader and writer have the same mandatory door/waits/restore/mirror/units and mtls expiry, with genuine unknown-presence and incomplete-restore positives retained.

## Ordered decisions

[decision-order.tsv](decision-order.tsv) declares the orders for unknown-since WaitQuiet before wait replacement/capacity, retention diagnostics, a complete presence snapshot and object-key admission. The header defines its CEL boolean/integer observations and the existing outcomes. Read only the named procedure in increasing n; a stop row ends the decision, a next row applies its effect before the following check. These observations do not prescribe internal functions, add a public response word or claim generator support.
