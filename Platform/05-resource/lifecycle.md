# Ресурс — жизненный цикл (урок P/05)

Контракт жизненного цикла процесса `resource` (ADR-0083 доп. (2) п. 1). Строки ссылаются на нормы урока и их не
пересказывают (стадия B: ссылки на М10/8, М10/10, М10/11 перенацелены на P/05 и общие договоры).

## Запуск

- **Юнит** — `w2c-resource.service`, один процесс на сервер, без контроллера; `User=w2c`,
  `SupplementaryGroups=w2c-store w2c-events` ([P/02.4] Н1.1, [P/05] Н1.4).
- **Запуск** — через раннер `w2c-run.sh resource` с `W2C_ROLE=resource` ([P/02.4] Н1.1 — юнит его ставит, разбор ревью стадии B 3–5, № 29; Н1.9).
- **Порядок старта** — проверка схемы `platform/schema` и чтение строки манифеста до первой записи ([P/05] Н3 «старт ресурса
  — проверка схемы», [P/02.3] Н3 «Старт процесса»); затем пульс сразу, поток пульса, `restore` бакетов в своей попытке,
  строка двери `platform/doors/<сервер>` ([P/02.4] Н3 «старт сервера», шаг 2).

## Окружение

Окружение собирает раннер `w2c-run.sh` в порядке P/02.4 Н1.2: значения юнита → `roles/<W2C_ROLE>.env` → `w2c.env` →
файл подсистемы, раньше прочитанное побеждает; файлы — разбором, не `source` ([02-installer/lifecycle.md](../02-installer/lifecycle.md)).

| Переменная | Смысл | Умолчание | Норма |
|---|---|---|---|
| `W2C_ROLE` | роль `resource`; не та роль команды раннера — код 2 | задаёт юнит | [P/02.4] Н1.2 |
| `PLATFORM_STORE` | дверь хранилища — сокет роли `configstore:///run/configstore/resource.sock` | `file://<PLATFORM_DIR>/config` (профиль коробки одной реализации) | [P/02.4] Н1.2 |
| `PLATFORM_DIR` | корень состояния | `/data/platform` | [P/02.4] Н1.2 |
| `RESOURCE_ROOT` / `EVENTS` | корень деревьев событий; в нём же замки присутствия `.workers/` | `<PLATFORM_DIR>/events` | [P/02.4] Н1.2 «Канал настройки», [журнал событий], [замок присутствия] |
| `OBJECTS` / `PLATFORM_OBJECTS` | корень объектов двери объектов и копий тел | `<PLATFORM_DIR>/objects` | [P/02.4] Н1.2, [P/05] Н1.1 |
| `RESOURCE_HOST`, `RESOURCE_PORT` | адрес двери ресурса | `127.0.0.1`, `8090` | [P/02.4] Н1.1, Н1.2 |
| `RESOURCE_URL` | адрес двери, который ресурс пишет в строку двери | — | [P/02.4] Н1.2, [P/05] Н1.4 `door_row` |
| `RESOURCE_TLS` | дверь по TLS | — | [P/02.4] Н1.2, Н1.6 |
| `SERVER_NAME` | свой сервер: ключ пульса и строки двери; не по грамматике — код 2 | короткий hostname | [P/02.4] Н1.2 |
| `BOX_ID` | коробка | `/etc/machine-id`, иначе hostname | [P/02.4] Н1.2 |
| `BUILD` | слово сборки в пульсе | `dev` | [P/02.4] Н1.2 |
| `W2C_TLS_DIR` | корень комплектов; свой — `<W2C_TLS_DIR>/resource` | `/etc/w2c/tls` | [P/02.4] Н1.2, Н1.6 |
| `W2C_ENV` | файл общих настроек | `/etc/w2c/w2c.env` | [P/02.4] Н1.2 |

## Флаги

Нет: канал настройки — только окружение ([P/02.4] Н1.2 «Канал настройки и раскладка `PLATFORM_DIR`»).

## Каталоги и файлы

- **Корень событий** — бакеты всех деревьев сервера `<корень событий>/<дерево>/<unit>/e<эпоха>/<start>Z.events.jsonl`;
  ресурс — владелец файлового контракта журнала событий, пишут в него воркеры и консоль ([журнал событий], [P/05] Н1.2, [каталог]).
  Копии бакетов соседей — `<корень событий>/.mirror/<server>/…`, пишет только ресурс.
- **Замки присутствия** — `<корень событий>/.workers/<sub>/<экземпляр>.lock`: ресурс берёт `flock` без ожидания и выводит
  `runs`, `gone`, `unknown`; файл `gone` МОЖЕТ удалить под своим `flock` ([замок присутствия] `presence_lock`, [каталог]).
- **Корень объектов** — дверь объектов, копии тел `<sub>/blobs/sha256-<hex>` от соседей кольца, надгробия `.gone/<ключ>`, замки каталогов `<каталог>/~lock`
  ([P/05] Н1.1, Н1.1 «Надгробия»; ADR-0083 доп. (16)). Имена файлов в обоих корнях — одно кодирование `%XX` / `%h<sha256>` ([журнал событий]
  «Имена файлов в общих деревьях»; порог `%h` — по полному имени файла с суффиксом нормы и запасом временного имени, разбор ревью стадии B 3–5, № 20).
- **Строки хранилища** — пульс `platform/resources/<server>/heartbeat` (объект), строка двери `platform/doors/<сервер>`,
  просьбы освобождения `<sub>/requests/free-<server>-<volume>`; читает `platform/space`, `platform/mirror`,
  `<sub>/retention`, `<sub>/alarms_retention`, `platform/decommission/*`, `platform/schema`, `platform/manifest/<sub>` и метку
  `/rev` ([каталог], [P/02.5] Н1.4).
- **Свой журнал** — `<корень событий>/audit/resource/e1/…` под исключительной блокировкой файла ([журнал событий]
  `journal`, `writer`).

## Коды выхода

| Код | Когда | Норма |
|---|---|---|
| 0 | смена манифеста — стоп, супервизор запускает снова | [P/02.3] Н3 «Смена манифеста» |
| 2 | метка манифеста не по форме у работающего — остановка, рестарт отказывает до исправления метки оператором (разбор ревью стадии A 6–7, Б2) | [P/02.3] Н3 «Смена манифеста», Н4 |
| 2 | схема хранилища выше своей или не число | [P/05] Н3 «старт ресурса — проверка схемы» |
| 2 | строка манифеста не читается или отказана | [P/02.3] Н3 «Старт процесса» |
| 2 | файл окружения не по грамматике; `SERVER_NAME` не по грамматике; `W2C_ROLE` не роль команды | [P/02.4] Н1.2, Н4 |
| ≠ 0 | иной отказ старта — строка лога называет источник | [P/02.3] Н3 «Старт процесса» |

Вне петли без комплекта ресурс МОЖЕТ слушать по явному адресу с громкой строкой лога или отказать в старте
([P/02.4] Н1.6).

## Сигналы и готовность

- **Готовность** — порт `RESOURCE_PORT` и строка `platform/doors/<сервер>`; раннер стенда ждёт обоих ([Стенд], [P/05]
  Н1.4).
- **Пульс** — каждые 10 с; строка двери — каждые 15 с; проход — каждые 600 с, шаг дольше `PULSE_LIMIT` даёт
  `pass_stalled` ([P/05] Н1.4, «Решает реализация» п. 7 — значение `PULSE_LIMIT`).
- **SIGTERM/SIGKILL** — состояние в строках и файлах; после возврата сервера ресурс тянет свои закрытые бакеты от соседей
  (`restore`, [P/05] Н1.4 «Восстановление бакетов»).
- **Перезапуск** — `Restart=always`, `RestartSec=2`, кроме кода 2 ([P/02.4] Н1.1).

## Стенд

- Команда «Стенда» с подстановками `{rport}` — порт двери, `{server}` — имя сервера (`srv-a`; у стенда М11 —
  `srv-<кластер>`) ([Стенд] «Ресурс»).
- `{data}` — это `PLATFORM_DIR`: стенд ставит `PLATFORM_DIR={data}`, `RESOURCE_PORT={rport}`, `SERVER_NAME`, `BOX_ID`;
  корень событий — `{data}/events`, отдельного ключа нет ([Стенд] «Один каталог данных»).

## Открыто

- Корень событий у стенда нескольких серверов на одном `{data}` — ни один стенд так не устроен: у каждого сервера свой
  `{data}`.
- Значение `PULSE_LIMIT` — решает реализация ([P/05] «Решает реализация» п. 7).
