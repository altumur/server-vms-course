# Формы P/05 и швы ресурса

Текст производный от `forms/README.md`, руками не правится: источник — английский [`forms/README.md`](../../forms/README.md); перевод для человека, не в выгрузке. Формы выражают нормы ресурса урока.

## Входы процесса и отказы

[daemon-flags.tsv](../../forms/daemon-flags.tsv) имеет `flag type default default_text required commands bad norm`. `$NAME` — переменная окружения, не новый CLI-флаг; команда процесса — resource. Типы и CEL — грамматика P/01 и P/03. Файлы окружения читает раннер, процесс потребляет окружение. Пустой bad не отменяет импортированных проверок. Вычисляемые default_text разрешаются по норме; string не вводит более строгого написания hostname, URL или десятичного числа. Пределы развёртывания без названной переменной не превращаются в окружение.

[refusals.tsv](../../forms/refusals.tsv) имеет `chapter row name surface code kind fields headers log norm word response_schema cause outcome diagnostic caller`. Literal TAB без CSV-кавычек. Глава — `5`; повтор row — проекции одного исходного отказа. Четыре последние ячейки сохраняют его исходные ячейки N4. `response_schema` — компонент OpenAPI урока либо `-` без тела/текст. `kind` — `-`: ResourceError — объект текста ошибки, не Fault P/01. Обязательные поля и константы схемы остаются в компоненте. Сохранённые из N4 строки успеха и усечения не переименованы в ошибку. Проекция call не вводит HTTP для внутренней процедуры.

## Дверь HTTP

[door-roles.tsv](../../forms/door-roles.tsv) имеет `method path roles norm` по существующим операциям [OpenAPI](../../spec/05-resource.api.openapi.yaml). При режиме двери `mtls` роль проверяется до обработчика после выбора операции; `*` — любая проверенная роль своего комплекта, `<sub>worker` разворачивается только по загруженному каталогу. Цепочка TLS, роль/CN/SAN и отзыв — договор ролевого сертификата. У неизвестного пути и неподдержанного метода нет тела (P/05-R041 и P/05-R042), включая HEAD /events; схемы ответа Common404/405 нет. PUT обычного объекта вместо blob — отдельный прикладной 405 ResourceError.

Маршрутизация объявлена `x-route-priority`, `x-path-capture`, `x-path-decode`, `x-path-error` этого OpenAPI по P/05-R057. Нельзя декодировать весь путь до сопоставления, считать закодированный слэш разделителем, нормализовать завершающий слэш или пробовать менее приоритетную операцию после ошибки параметра. Тело ошибки — по проекции метода параметра; у error в ResourceError нет фиксированного текста.

## Швы

Синхронные порты CALL используют грамматику CALL/JSON [P/03](../../../03-worker/ru/forms/README.md) и [P/02](../../../02-installer/ru/forms/README.md): один JSON-вход, нативный JSON-выход, рекурсивное подмножество объекта, точные массивы и пустые объекты. Глава `5` использует acceptance/ напрямую. Порты нормализуют свидетельство, не API реализации: вызывают настоящие функции ресурса и записывают эффекты, не возвращают ожидаемый ответ. У сценария свежий временный корень и допустимые каталог, директория, личность, пределы, строки и файлы до вмешательства. Неожиданная паника или посторонняя ошибка — провал, не нормальный отказ.

Неуказанные входы дополняются допустимым нейтральным фоном, не неизвестным чтением. Слова fixture выбирают байты/файлы либо управляемый клиент ниже, не вычисленный исход. Метки версий v1/v2 обозначают свежие допустимые по схеме версии управляемого хранилища; наблюдённые версии отображаются обратно в метки, сами метки не посылаются в провод как испорченные версии. Счётчики и размеры тел берутся из вызовов и байтов. Отсутствующие необязательные lines_garbled/truncated нормализуются в ноль только в числовых наблюдениях.

| CALL port | Вмешательство и наблюдение |
|---|---|
| `resource-object-write` | Обычный локальный писатель объекта, дважды при same_bytes, часы clock и один ключ. Установить указанное читаемое или испорченное надгробие; проверить его до ответа записи. |
| `resource-body-copy` | Передать настоящую допустимую копию blob с верной суммой, неотрицательным X-Written, загруженным blob-манифестом и прежней копией. Локальные часы независимы от written источника. |
| `resource-object-read` | Создать настоящий разрешённый объект actual_bytes байт и прочитать настоящую дверь. Считать полученные байты; successful_headers означает отправленный успешный статус до отказа. Границу достигает длина настоящего файла, не подставленный размер. |
| `resource-listing` | Вызвать список бакетов с управляемой ошибкой I/O директории после допустимого запроса до заголовков. Это не пустой успешный список. |
| `resource-mirror-put` | Подготовить целый закрытый бакет и настоящие байты старой копии. complete_wrong_sum даёт правильную по форме X-Sum других байтов; cut_before_content_length обрывает настоящее тело до объявленного конца. same_valid_copy_twice повторяет те же полные байты и сумму. После ответа проверить публикацию и старые байты. |
| `resource-query` | Фикстура two_events — две допустимые полные строки; one_complete_one_torn добавляет допустимый префикс JSON без конечного LF; one_complete_one_bad_json — одну завершённую не-JSON строку. Пути бакетов и остальные поля допустимы. Вытеснить все кеши читателя и повторить по неизменным файлам, наблюдая обычный запрос. |
| `resource-event-write` | Использовать обычный писатель события с конфликтующими полями подсистемы. platform_overwritten показывает, переписала ли принятая строка платформенные поля. Допустимая явная ошибка может защитить их; падение не может. |
| `resource-wait` | Открыть настоящие ожидания обработчика с разными именованными клиентами, кроме явно заданных old/new. CN берётся из проверенного сертификата/контекста настоящей двери комплекта, не заголовка клиента. Держать запросы events в их настоящей полосе вычисления. Отключить настоящего клиента и исполнить отмену в нормативную секунду; timeout/full/replaced наблюдаются как нативные WaitAnswer. |
| `resource-restore` | Использовать известные server doors srv-b/srv-c. Complete — настоящий допустимый MirroredListing с получением и проверкой каждого бакета; unavailable — неответ. Нечитаемые heartbeat соседей требуют известного набора дверей, не отсутствия соседей. Проверять done после всей попытки. |
| `resource-retain` | Кандидаты — только старые закрытые бакеты testsub и testsub.alarms. Передать указанные чтения retention и исход holds настоящему проходу. Получить диагностику heartbeat из прохода, проверить настоящее удаление. |
| `resource-free-ask` | Использовать requests.free и один том с достаточным положительным usage и допустимыми полями free-ask. В гонке заменить проверенную просьбу новой подтверждённой обычной перед CAS-удалением. При нечитаемом heartbeat воркера не вычислять need подсистемы и не трогать её прежнюю просьбу. |
| `resource-presence` | Использовать настоящие файлы, OS flock и процесс-помощник с занятым lock; испорченное содержимое не делает занятый lock мёртвым. Для смены inode заменить имя после блокировки открытого inode до настоящего сравнения fstat/stat. Ошибка обхода — настоящая ошибка чтения директории после прежнего успешного снимка. presence_fields перечисляет присутствующие поля workers/running/unknown. |
| `resource-pass` | Запустить настоящий start/readiness и планировщик с управляемыми монотонными часами. Посчитать первый настоящий проход без продвижения часов через 600-секундный интервал и независимо начатые retain, usage, relieve, mirror после неответа retain. |
| `resource-route` | Запустить настоящую дверь с CA тестового комплекта и проверенным сертификатом роли, пустым читаемым корнем объектов и допустимым каталогом. Послать сырой target и метод без очистки пути клиентом. body_shape — none при нуле байт, resource_error только после проверки ResourceError, wait только после проверки WaitAnswer. В случае existing_bucket создать целый допустимый бакет по этому незакодированному пути: ошибочное разделение %2F тогда открыло бы настоящий файл вместо 404. Не подставлять результат маршрутизации или личность. |

Швы дополняют обычную процессную приёмку, общие векторы и чтение. Они не доказывают развёртывание ОС, весь TLS/peer, долговечность диска, все поздние чтения или полный жизненный цикл ресурса. [stages.tsv](../../forms/stages.tsv) — возможный порядок, не норма урока; полностью закрываемых пакетом этапов не заявлено. Полная приёмка — прежние 35 сценариев и 304 шага раннера вместе с дополнительными пробами и общими пакетами по consumers.tsv.

## Лексемы числовых query

По P/05-R022 и P/05-R031 у query Parameter Object OpenAPI закрытое расширение `x-query-lexeme`: обязательные `pattern` (полное регулярное выражение с якорями) и `parse` (`number`, `integer` или `uint64`), необязательное `strip` (только строка `_`); других ключей нет. Оно применяется к переданному параметру после обычного процентного декодирования query и преобразования `+` в пробел, до проверки типизированного диапазона. При отсутствии параметра действует прежнее значение по умолчанию. Пустой или повторный параметр получает прежний отказ независимо от расширения.

Декодированный текст сначала сопоставляется с `pattern`, затем из него удаляются все символы `strip`. `number` — десятичное конечное значение binary64: конечное исчезновение порядка даёт ноль, переполнение — отказ; тип схемы number. `integer` — точное десятичное целое с последующей проверкой границ схемы, без округления через binary64; тип схемы integer. `uint64` — точное беззнаковое десятичное целое 0…18446744073709551615; тип схемы string, обработчик получает исходный канонический десятичный текст. `strip` допустим только у number. Ошибка лексемы, преобразования или границы идёт прежним путём 400 ResourceError; текст error не закреплён. Расширение не заменяет межпараметрические условия from ≤ to и late только при by=occurred.

Буквальные pattern в OpenAPI — машинный источник. from/to допускают подчёркивание только между ASCII-цифрами, необязательный минус, точку с цифрами хотя бы с одной стороны и необязательную экспоненту; начального плюса нет. limit/late — ASCII-цифры, ведущие нули допустимы. timeout — ASCII-цифры и не более одной точки с цифрами хотя бы с одной стороны; без знака, экспоненты и подчёркиваний. since — каноническое беззнаковое десятичное. Это прежние лексемы ресурса; у консоли другая грамматика query.

## Свидетели ресурса

Дополнительные seams s38-s62 используют прежние порты и реальные пути реализации. Новых native-команд, CLI, ролей, слов ответа или частей kit нет.

- resource-body-copy: два настоящих ресурса, тело по схеме с названным исходным written. Управляемые часы сначала допускают пакет sweep с названной отметкой и наблюдают неизменную версию названное число монотонных секунд. Все обычные писатели и входящие копии остановлены и завершены, peers подтверждены до обычного помощника удаления окна sweep. delete_clock — названный; сохраняется отметка точной удаляемой версии, настоящее надгробие прочно публикуется, распространение возобновляется. Исполняются обычный проход соседа и обычный GET/ack удалившего. tombstone_written берётся из тела, не отметки записи листинга. copy_source_written_changed — наблюдаемая перезапись отметки версии копии. Ручное надгробие или ожидаемая формула не заменяют помощника удаления.
- resource-presence: холодный старт без памяти slot; листинг успешен, названный файл существует. Названная ошибка внедряется в указанную операцию open/read/flock/fstat/stat настоящего читателя. При ошибке проверки без доступного имени текущее содержимое замка пусто; read — настоящая ошибка чтения, не разбора. Ошибка разбора читаемого занятого замка остаётся безымянным живым. Неизвестная проверка не удаляет файл. Другая роль, названная во входе, с занятым корректным нумерованным замком сохраняет свои room и live, вычисленные из переданных бюджетов памяти. Наблюдать опубликованные поля пульса и строки двери; отсутствие общего снимка не подменять пустым успешным снимком.
- resource-wait: настоящие незавершённые ожидания включают old; остальные имеют разные личности. Проверенные CN/client нового равны old. Наблюдать окончательный WaitAnswer старого, продолжающее ждать соединение нового и настоящие счётчики; old — одно из незавершённых ожиданий, а не дополнительное. Проверка сертификатов прежняя.
- resource-restore: empty_404 — настоящий 404 без тела на GET листинга mirrored соседа. complete — полный правильный перечень; bucket_replies 404 означает 404 без тела на последующий GET названного бакета, повторяемый до PEER_FAILS. missing считает неполученный бакет, не повторы; done берётся из настоящей реализации. Не превращать неуспешный GET в пустой перечень.
- resource-retain: целый закрытый бакет публикуется обычным писателем в логический written, окно пути названное. mtime меняется независимо. Настоящий retain работает с управляемыми стенными часами; наблюдать удаление файла и прочитанную до решения логическую отметку, не вычислять решение в адаптере. audit сохраняет умолчание; эффективный console не меньше самого долгого дерева. Поздняя копия зеркала имеет собственный written приёмника и written исходного бакета; добавка срока — MIRROR_RETENTION_EXTRA. При restore_copy_written сначала исполнить настоящее восстановление с проверкой суммы при названном restore_clock, затем вытеснить кэш/перестроить индекс либо перезапустить и вызвать retain; не подставлять готовые метаданные восстановленного бакета. Отметка копии остаётся локальной. Равенство границе удаляет, предыдущая миллисекунда сохраняет. confirmed_hold — настоящая читаемая строка удержания этой единицы/окна; unreadable holds — настоящая ошибка чтения. Оба исхода сохраняют бакет до предиката срока.

Это обязательные исходные свидетели, ещё требующие реализации генераторов/раннера и общего normgen+kit GATE у coord103. Публикация входов не является исполнением ресурса, проверкой OS durability, TLS или приёмкой SUT.

## Числовой источник и завершённые вызовы

[runtime-constants.tsv](../../forms/runtime-constants.tsv) — единственный числовой источник 14 собственных положительных целых уставок. [OpenAPI](../../spec/05-resource.api.openapi.yaml) урока сохраняет нынешние типизированные HTTP-границы/умолчания, схема space P02 — high/low. Новых environment, CLI, публичных слов ответа, native-команд и kit-частей нет. PEER_FAILS у s47/s48 берётся из этого источника, не из второго значения.

Пять добавленных вызовов используют прежние 14 портов и настоящую свежую подготовку:

- `resource-free-ask`: Создать настоящую свою строку с названными free/volume/server/at и подтверждённой версией. Вызвать и дождаться настоящего синхронного relieve, затем прочитать действительную строку/версию и счесть настоящие записи/удаления. Сна и отдельного API завершения нет. Вход own_request и expect не заменяют результат.
- `resource-query`: Исполнить названные запросы над неизменёнными файлами при нейтральных кэшах. Ветвь names/listing записывается из действительного IO выбора кандидатов. Для same_answer сравнить полные настоящие ответы; events — их счёт, truncated наблюдается, не вычисляется заранее из фикстуры.
- `resource-query`: те же настоящие файлы событий, конечные названные границы вне календарного представления, fallback листинга и обычный фильтр. Наблюдать настоящий статус/счёт/ветвь; panic, переполнение и синтетический пустой ответ неуспешны.
- `resource-restore`: настоящий полный список закрытых бакетов с верной суммой. Настоящий успешный бакет сбрасывает локальную последовательность ошибок. Наблюдать завершение, действительную трассу вызовов, обращение в следующей попытке и сброс накопленных диагностических счётчиков; синтетических сумм диагностики нет.
- `resource-pass`: правильные закрытые локальные бакеты и живая дверь, названные ответы копии через настоящие проходы в их обычные разрешённые начала. Следующий проход запускается управляемыми часами по PASS_EVERY, без обхода или задержки новым сроком. Наблюдать вызовы после пропуска текущего прохода, обращение в следующем, сброс после успешной копии и накопленную диагностику. Последовательность restore не общая с mirror.

Все нормализованные флаги выше — наблюдения настоящих вызовов/строк/счётчиков. Поддержка адаптера/производителя — отдельная обязанность; этот источник не утверждает исполнения вызовов. Нынешние читатель/писатель пульса имеют одинаково обязательные door/waits/restore/mirror/units и срок mtls; настоящие положительные случаи неизвестности присутствия и неполного restore сохранены.

## Порядки решений

[decision-order.tsv](../../forms/decision-order.tsv) задаёт порядки WaitQuiet неизвестного since до замены/вместимости ожиданий, диагностики срока, полного снимка присутствия и допуска ключа объекта. Шапка определяет наблюдения CEL типов bool/int и существующие исходы. Читается только названная процедура по возрастанию n; stop завершает решение, next применяет эффект до следующей проверки. Наблюдения не предписывают внутренних функций, не вводят публичного слова ответа и не утверждают поддержку генератором.
