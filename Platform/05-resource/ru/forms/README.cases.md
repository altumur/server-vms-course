# Данные случаев только для судьи

Этот русский текст — производный от `forms/README.cases.md`, руками не правится (ADR-0121).

Общие правила остаются в [README.md](README.md). Следующие исходные отрывки сохраняют прежние связи именованных случаев как происхождение только для судьи.

### Исходный отрывок 1

- s63 `resource-free-ask`: правильный каталог requests.free, том events total 1000 / used 800, high 0.85 / low 0.75, неотражённого freeing нет; need 50 положителен внутри полосы. Создать настоящую свою строку с названными free/volume/server/at и подтверждённой версией, отображённой в v1. Вызвать и дождаться настоящего синхронного relieve, затем прочитать действительную строку/версию и счесть настоящие записи/удаления. Сна и отдельного API завершения нет. Вход own_request и expect не заменяют результат.
- s64 `resource-query`: два события обычного писателя при 100/700 в правильных путях эпох/бакетов. Исполнить оба названных запроса над неизменёнными файлами при нейтральных кэшах. Окна содержат 144/145 имён бакетов; ветвь names/listing записывается из действительного IO выбора кандидатов. Для same_answer сравнить полные настоящие ответы; events — их счёт, truncated наблюдается, не вычисляется заранее из фикстуры.
- s65 `resource-query`: те же настоящие файлы двух событий, конечные названные границы вне календарного представления, fallback листинга и обычный фильтр. Наблюдать настоящий статус/счёт/ветвь; panic, переполнение и синтетический пустой ответ неуспешны.
- s66 `resource-restore`: настоящий полный список двух закрытых бакетов с верной суммой у необходимого srv-b. Попытка 1 получает три настоящих unavailable при вытягивании и больше не вызывает соседа в этой попытке. На следующей разрешённой границе повторов попытка 2 имеет названную последовательность ответов: unavailable, valid, unavailable, unavailable, valid. Настоящий успешный бакет сбрасывает локальную последовательность ошибок. Наблюдать завершение, действительную трассу вызовов, обращение в следующей попытке и сброс накопленных диагностических счётчиков; синтетических сумм диагностики нет.
- s67 `resource-pass`: правильные закрытые локальные бакеты и живая дверь srv-b, названные ответы копии через два настоящих прохода в их обычные разрешённые начала. Следующий проход запускается управляемыми часами по PASS_EVERY, без обхода или задержки новым сроком. Наблюдать отсутствие вызовов после пропуска текущего прохода, обращение в следующем, сброс после успешной копии и монотонность накопленной диагностики. Последовательность restore не общая с mirror.

### Исходный отрывок 2

- s38-s40, resource-body-copy: два настоящих ресурса srv-a и srv-b, тело по схеме с исходным written 100. Управляемые часы сначала допускают пакет sweep с at 101 и наблюдают неизменную версию 300 монотонных секунд. Все обычные писатели и входящие копии остановлены и завершены, peers подтверждены до обычного помощника удаления окна sweep. delete_clock — 100 или 50; сохраняется отметка точной удаляемой версии, настоящее надгробие прочно публикуется, распространение возобновляется. Исполняются обычный проход соседа и обычный GET/ack удалившего. tombstone_written берётся из тела, не отметки записи листинга. Старая копия исчезает, GET 404 даёт ack; отдельная новая версия соседа 100.002 остаётся с исходной отметкой и не подтверждает удаление. copy_source_written_changed — наблюдаемая перезапись отметки версии копии. Ручное надгробие или ожидаемая формула не заменяют помощника удаления.
- s41-s45, resource-presence: холодный старт без памяти slot; листинг успешен, названный файл существует. EACCES внедряется в указанную операцию open/read/flock/fstat/stat настоящего читателя. При ошибке проверки без доступного имени текущее содержимое замка пусто; read — настоящая ошибка чтения, не разбора. Ошибка разбора читаемого занятого замка остаётся прежним безымянным живым s25. Неизвестная проверка не удаляет файл. У другой роли testsub2 один занятый правильный номерной замок n=2, HOST_MEMORY_MB=100 и WORKER_MEMORY_MB=1; независимый room — min(100-1,98-1)=97, live — "2". Наблюдать опубликованные поля пульса и строки двери; отсутствие общего снимка не подменять пустым успешным снимком.
- s46, resource-wait: ровно 16 настоящих незавершённых ожиданий, включая old; остальные 15 имеют разные личности. Проверенные CN/client нового равны old. Наблюдать окончательный WaitAnswer старого, продолжающее ждать соединение нового и настоящие счётчики; не открывать 16 дополнительных ожиданий помимо old. Проверка сертификатов прежняя.
- s47-s48, resource-restore: один необходимый сосед srv-b. empty_404 — настоящий 404 без тела на GET /mirrored/srv-a и завершает соседа. complete — полный правильный перечень; bucket_replies 404 означает 404 без тела на последующий GET названного бакета, повторяемый до PEER_FAILS. missing считает неполученный бакет, не повторы; done остаётся false. Не превращать неуспешный GET в пустой перечень.
- s49-s62, resource-retain: целый закрытый бакет публикуется обычным писателем в логический written, окно пути [0, 600). mtime меняется независимо. Настоящий retain работает с управляемыми стенными часами; наблюдать удаление файла и прочитанную до решения логическую отметку, не вычислять решение в адаптере. Обычный срок — 1 день, тревог — 2 дня. audit сохраняет умолчание 1095 дней; эффективный console не меньше самого долгого дерева, 1096 дней в s55/s56. Поздняя копия зеркала имеет собственный written приёмника 90000, исходный бакет written 100; добавка срока — 3600 секунд. При restore_copy_written сначала исполнить настоящее восстановление с проверкой суммы при restore_clock 150000, затем вытеснить кэш/перестроить индекс либо перезапустить и вызвать retain; не подставлять готовые метаданные восстановленного бакета. Отметка копии 90000 остаётся локальной. Равенство границе удаляет, предыдущая миллисекунда сохраняет. confirmed_hold — настоящая читаемая строка удержания этой единицы/окна; unreadable holds — настоящая ошибка чтения. Оба исхода сохраняют бакет до предиката срока.
