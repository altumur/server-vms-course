# P/05 — инструкция для реализации

Текст производный от `spec/05-resource.README.md`, руками не правится: источник — английский [`spec/05-resource.README.md`](../../spec/05-resource.README.md), правка идёт в него, русский пересобирается переводом.

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — `ru/05-resource.md` (для человека, в выгрузку не входит).

Сценарии, фикстуры и эталонные ответы не входят во вход модели; видимые нормы содержат все обязанности реализации. сц. NN обозначает сценарий NN этого урока, если не назван другой урок; имя `sNN-…` обозначает синхронный случай CALL, а `05-power-pull` — системное учение восстановления.

## Задача

Дать платформе объекты, события и их чтение; ресурсу — уборку, зеркалирование и восстановление своих бакетов.

## Входы и их приоритет

- Канон — [нормы](05-resource.norms.md), определения N0 — по P/01.1; файловые договоры —
  [журнал событий](../../../common/ru/contracts/event-journal.md) и [замок присутствия](../../../common/ru/contracts/presence-lock.md).
- [HTTP-контракт](../../spec/05-resource.api.openapi.yaml) выражает N2.
- Лекция (`ru/05-resource.md`, для человека, в выгрузку не входит) объясняет причины и границы; [жизненный цикл](../lifecycle.md) — окружение, коды выхода.

Объекты используют словарь хранилища P/01.1, роли — [P/02.4 N1.6](../../../02-installer/ru/spec/02.4-installer.norms.md) и
договор сертификата роли. `PUT /v1/objects/<sub>/blobs/<digest>` — N1.1 «Bodies at the resource», N2; `restore` (`GET /mirrored/<server>`) — N1.4 «Bucket restore».
Внутренние функции,
библиотеки и способ размещения обработчиков не предписаны.

## Что создать

Операции объектов и их разрешённую дверь; запись событий с бакетами и классами;
чтение дерева с ограниченным кэшем; запрос ресурса; подсказку wait;
проход ресурса retain → usage → relieve → mirror; `restore` при старте.
Целая копия файла, ответивший источник и опубликованная копия —
разные границы подтверждения, одна не доказывает другую.

## Порядок работы

1. Разделить файл и строку-объект. Проверить put_new и CAS по N1.1, запрет выдавать
   строки-объекты дверью файлов, равные written и missing. Отсутствие ответа сервера
   не превращать в доказательство отсутствия объекта.
2. Записать событие под эпохой. Идентификатор различает процессы, коробки и перезапуски;
   поля платформы нельзя затереть полями подсистемы. Проверить оба класса, of, бакет
   по t и сохранение целой строки; fsync проверять отдельным свидетельством (подавление — глава 3.6).
3. Построить запрос над файлами: параметры, кандидаты, фильтр, приоритет тревог,
   limit и truncated. Одинаковый запрос с пустым кэшем и после его вытеснения даёт тот же
   результат при неизменных файлах. Порванный хвост даёт partial, не строку события.
4. Сделать wait по N1.6: четыре закрытых ответа, личность при вытеснении, очередь и
   таймаут. Клиент продолжает периодический проход при потере подсказки, переполнении
   или перезапуске ресурса.
5. Выполнить проход ресурса. Неизвестное чтение retention/holds не даёт права удалять;
   free_ask не содержит unit и совпадает по server/volume. Имя тома — ASCII A-Z/a-z/0-9/_ длиной 1–64, без дефиса (N1.4 `free_ask`); иной том не публикует просьбу и диагностируется. Снятие использует CAS версии,
   на которой проверены форма и владелец строки. Зеркало публикуется после проверки полного тела
   и суммы; неуспех сохраняет прежнюю копию.
   Строка двери несёт рядом с `room.<sub>` список `live.<sub>` — номера n ≥ 2 живых замков того же снимка (договор замка
   присутствия): контроллер считает по нему свободное место сервера.
6. Пройти 35 сценариев / 292 шага приёмки по отдельности. Проверять полные ответы по владельцу формы,
   даже при ожидании только кода в TSV. Для каждого пункта чеклиста назвать отдельное
   наблюдение; пробы вне TSV перечислены в README приёмки.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Проверка |
|---|---|---|
| N1.1/N2 | prefix проверен как ключ; traversal прошёл декодирование | Пустой prefix допустим; пустой сегмент ключа, точка, две точки, обратная косая и управляющие — нет |
| N1.2/N1.3 | Поля события затёрли метаданные; PID повторился на другой коробке | Поля платформы защищены; id различает экземпляры |
| N1.3 | bool принят за integer, NaN за число, обрезка за неполноту источников | Конечные числа, целый limit; разные truncated/partial |
| N1.6/N2 | JSONL обёрнут массивом; wait вернул события | Проверить форму, типы и отсутствие лишних полей |
| N2 | После заголовков выдан второй JSON-отказ | Обрыв остаётся обрывом; неполная копия не публикуется |

## Готово, когда

Выполнен весь канонический чеклист, названы выборы реализации и свидетельства для
норм вне TSV. Раздельно показаны успех, известный отказ и неизвестный результат
публикации. Проверка схемы не проверяет файловую долговечность или гонку;
чтение алгоритма не доказывает исполнение в нескольких процессах.

## При расхождении

Передать «Спецификации» срез, место и контрпример; установить, был ли он до правки.
Исправить источник нормы и прямых потребителей, проверить весь связанный класс.
Не расширять урок новым механизмом ради случая вне объявленного профиля.

Дополнительная проверка: GET объекта: опубликованный байтовый потолок двери/+1, без успешного усечения.

Проверить id на коллизии составных имён a-e1-j/node:1:aaaaaa и a/j-e1-node:1:aaaaaa, UTF-8, разные деревья/эпохи/параллельные номера, перезапуск и итог подавления; копии сохраняют исходный id. Для обоих перечней buckets/mirrored: отсутствующий, пустой известный и нечитаемый каталог различаются; ошибка до заголовков — 500 без тела, обрыв не даёт полного ответа. Дополнительные пробы вне TSV.

## Формы и этапы реализации

Нормализованные входы процесса, каталог отказов, допуск ролей и CALL-порты — в [README форм](../forms/README.md). Публичные синхронные порты CALL дополняют процессные сценарии и обязанности общих векторов; они не заменяют полный зачёт раннера и методы чтения выше.

Числовой источник независимых уставок — [runtime-constants.tsv](../../forms/runtime-constants.tsv); HTTP-значения — нынешняя [OpenAPI-форма](../../spec/05-resource.api.openapi.yaml), high/low — форма space P/02. Объявленные s63–s67 и семейные клетки требуют реального выполнения, не ответа адаптера из ожидания. Поддержка ms пока отдельная зависимость, не PASS.
