## N0 Словарь слов

Нормативные слова (MUST, MUST NOT, SHOULD, MAY по RFC 2119 и RFC 8174) — по [канону курса](../../../common/ru/NORMATIVE-TERMS.md). Правила модуля — [P/01.1 N0](../../../01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

Для этого владельца действуют [общие эксплуатационные обязанности](../../../common/ru/contracts/production-obligations.md). Q1/Q5/Q6 и MB1: отказ до эффекта отличается от неизвестной долговечности публикации; нужные надгробия сохраняются, опасная уборка откладывается, тела копируются только от владельца. Соседская копия никогда не служит источником ретрансляции после `404`.

## N1 Форма

Независимые положительные целые уставки этого урока заданы в [runtime-constants.tsv](../../forms/runtime-constants.tsv); это их числовой источник. HTTP-границы и умолчания остаются в [OpenAPI](../../spec/05-resource.api.openapi.yaml), high/low — в существующей форме space P/02. ALIVE_EVERY/LOST_AFTER принадлежат договору наблюдения, JSON_DEPTH — P/01. Совпадение чисел не объединяет разные бюджеты. WAIT_OBSERVE_MS / 1000 — прежний период наблюдения в секундах. Ожидающая поддержка ms у читателя/валидатора — зависимость поставки, не исключение и не изменение физического срока.

**Время.** Поля времени строк и объектов урока — время по [канону N0 P/01.1](../../../01-store/ru/spec/01.1-store.norms.md#время-в-строке): строка события — `t` ([договор журнала событий](../../../common/ru/contracts/event-journal.md)); объект пульса ресурса `platform/resources/<server>/heartbeat` — `ts`, `usage_at`, `pass_started`; строка двери `platform/doors/<host>` — `since`, `at`; `<sub>/requests/free-<server>-<volume>` — `at`; надгробие `.gone/<object-key>` — `written` (пишет консоль, [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.5).

### N1.1 Объект

Форма `object` задана отдельными правилами: P/05-R059, P/05-R060, P/05-R061, P/05-R062, P/05-R063, P/05-R064, P/05-R065, P/05-R066.

**`client`.** Адрес OBJECTS, операции (rule, api, ops), чтение объектов кластера, исходы и действие клиента — договор клиента хранилища объектов common/contracts/object-client.md.

**`key`.** `<семья>`/… ; семьи платформы: heartbeats, contenders (P/03.4, P/03.2), controller (P/04), snapshot, blobs, commands (договор просьбы и её метки, «Mark» mark) — манифест их не называет.

**`writer`.** Один каталог — один писатель: worker → `<s>`/heartbeats/*, `<s>`/contenders/*; controller → `<s>`/snapshot/*, `<s>`/snapshot-tables/*, `<s>`/controller/*; console → `<s>`/blobs/*; resource → platform/resources/*.

**`cluster`.** Файл на сервере писателя; при чтении свежая копия (written) побеждает; сервер, который не ответил, — missing.

**`written`.** Отметка ресурса-хранителя при записи ключа (X-Written двери, written листинга), не поле времени тела. **Written объектов и надгробия.** Каждая запись ключа ставит written строго больше прежнего written того же ключа: часы не ушли вперёд — прежнее + 0,001 с. Новая запись тех же байтов — новая версия, тот же (server, written) — та же версия (договор наблюдения «changed»).

**Written объектов и надгробия.** Копия тела (PUT .../blobs/`<digest>` с X-Written, зеркало) хранит written исходной копии, не свой: иначе копия, лежавшая до удаления, оказалась бы новее надгробия. Уже лежащая копия того же ключа — written не уменьшается (большее из двух).

**Written объектов и надгробия.** У ключа, удалённого здесь, прежний written — written его надгробия `.gone/<object-key>`, пока оно лежит: новая запись — строго больше него (иначе соседи сочли бы её старше удаления, договор надгробий `drop`, `rewrite`). Отдельной памяти нет — надгробие и есть отметка. Запись после written снимает надгробие тем же действием, до ответа записи (договор надгробий `rewrite`). Надгробие снято — граница только прежние правила.

**Written объектов и надгробия.** Надгробие нечитаемо (garbled) — граница не известна, запись не отказывается: written по прежним правилам, надгробие остаётся (не снимается: запись после written не доказана), его перепишет следующее удаление тела.

**`row_object`.** Ключи, чей следующий писатель может быть на другом сервере, — строки хранилища objects/`<ключ>` (objects.rows манифеста; commands/* — всегда, у манифеста с requests); put_new = запись с cas "".

**`door`.** Только семьи PLATFORM_DOOR (platform/resources/*, domain/* (М11), */heartbeats/*, */contenders/*, */snapshot/*, */snapshot-tables/*, */controller/*, */blobs/*) и objects.door манифеста; иное — 403. **Допуск к объектной двери.** Надгробия .gone/`<ключ>` — только чтение: листинг prefix=.gone/ и GET тела (договор надгробий). `*` первой части — подсистема каталога манифестов: `other/heartbeats/x` без манифеста other — 403.

**Допуск к объектной двери.** Тела объектов двери ресурс не разбирает: объект, нечитаемый своей семьёй (пульс воркера, метка), отдаёт как есть, суждение — у читателя.

**`disk`.** `<PLATFORM_DIR>`/objects/`<ключ>`. **Локальные объекты.** Каталог 0775, файл 0644. Запись — temp + rename под замком каталога `<каталог>/~lock`, flock(LOCK_EX), файл не удаляется. Служебные имена (замок, временное имя) — договор журнала событий «File names».

Ключ объекта — непустой относительный путь: непустые сегменты, без точных `.`/`..`, обратной косой черты и управляющих знаков. **Ключи и префиксы.** `prefix` — начало такого ключа, также пустота или конец `/`; это не полный ключ.

**Строки-объекты и файловые объекты.** Объектная дверь не выдаёт строки-объекты даже из разрешённого префикса.

**Кластерное чтение и отсутствующие ответы.** При равном `written` выбирается сервер с лексикографически большим именем; отсутствие ответа называется `missing`, а не отсутствием объекта.

**Листинг объектов.** При листинге возвращается закрытая форма ObjectListing из N2; удалённые объекты — надгробия `.gone/<object-key>` (ниже, «Tombstones»): обычный листинг их не показывает, `prefix=.gone/` — листинг надгробий только для чтения. ObjectEntry надгробия содержит его object-written, сервер, хранящий выбранную копию, и размер выдаваемого тела; отметку удаления читают из тела, не из листинга. Листинг отдаёт только ключи семей двери под `prefix` — фильтр, а не отказ: `prefix=testsub/`, `prefix=t`, пустой `prefix` — 200 с ключами семей двери, которые начинаются с него; ключи вне семей двери в листинг не попадают. **Ключи и префиксы.** `prefix`, с которого не начинается ни один возможный ключ семей двери (`other/`), — 403. `prefix` не UTF-8 (`%FF`) — 400.

**Ключи и префиксы.** Чтение ключа: ключ не по грамматике (не UTF-8, Cc, Zl, Zp — в том числе U+2028, `.`/`..`, пустой сегмент) — 400. Ключ вне семей двери, включая каталог `testsub/heartbeats` из двух частей, — 403. Ключ семьи, которого нет (в том числе каталог внутри семьи, `testsub/heartbeats/sub`), — 404. Ключ, отличный от записанного только регистром или нормализацией (`W-1` при `w-1`), — свой ключ: 404, не чужой объект.

**Имена файлов в общих деревьях** — одно кодирование для всех реализаций: [договор журнала событий](../../../common/ru/contracts/event-journal.md#имена-файлов-в-общих-деревьях).

Ошибка ФС после допуска — отказ записи, а не успех и не «файла нет».

**Тела у ресурса** (поле `blob`, дайджест, дверь байтов консоли, уборка тел — [глава 6.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.5): **`mirror`.** Каждое локальное тело от владельца (принятая копия не источник) — следующим copies живым соседям кольца (N1.4 mirror), всегда, независимо от mirror.enabled. **Копии тел.** `copies` — из строки platform/mirror (целое ≥ 0), строки нет или поля copies нет — 1. Строка не читается — тела в этом проходе не копируются, причина в пульсе (settings_unread: mirror).

**Копии тел.** Приём: хэш по мере чтения; PEER_FAILS; дверь копии есть только у ключа `<sub>/blobs/sha256-<64 строчных hex>` подсистемы с blob-полем; иной ключ (заглавные hex, без `sha256-`, подсистема без blob-поля) — обычный объект, его пишет владелец: 405.

Потолки ресурса (общие потолки — [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.4; проверяются у двери до чтения тела, где возможно; отказ — не усечение):

| Что | Предел | Где | Слова / код |
|---|---|---|---|
| объект у двери ресурса (чтение, копия тела, кусок зеркала) | `Content-Length.maximum` операции копии blob из [HTTP-формы](../../spec/05-resource.api.openapi.yaml) | дверь ресурса (N2) | `413` |
| строк в ответе `/events` | `limit.default` и `limit.maximum` у `GET /events` в [HTTP-форме](../../spec/05-resource.api.openapi.yaml) | индекс (N1.3) | обрезка, `truncated` |
| срок хранения | конечное число > 0 | ресурс (N1.3 `retention`) | «unknown», ничего не убирать |
| хранилище объектов | `max_bytes` (0 — без потолка); хранилище само говорит | `put` | `TooLarge` «over this store's limit» |

Уборка тел ([P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N3 «body sweep»): в исключительном окне оператор закрывает и входящие зеркальные копии; копия, которую надгробие удалившего новее, не принимается (N4, «deleted later» — 409).

**Надгробия и схождение копий тел** (тела, их дайджест, дверь байтов консоли, зеркало тел у консоли и уборка — [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N1.5): **`delete`.** Надгробие .gone/`<ключ>` {written, peers, acked}, соседи peers, чтение соседом, подтверждение 404 и снятие — [договор надгробий](../../../common/ru/contracts/tombstone.md); у двери объектов DELETE нет.

### N1.2 Событие

Форма строки события (`line`), бакет и его путь (`bucket`), класс (`class`), журнал `audit` (`journal`), писатели файла (`writer`), id события и экземпляр писателя — [договор журнала событий](../../../common/ru/contracts/event-journal.md). Урок — его владелец: ресурс читает бакеты (N1.3), копирует закрытые (N1.4 `mirror`), убирает по сроку (N3 «resource pass»). Подавление повторов (`suppress`) — [глава 3.6 N1.2](../../../03-worker/ru/spec/03.6-worker.norms.md); `older_epochs` и отметки оператора (`marks`) — [глава 6.4](../../../06-console/ru/spec/06.4-console.norms.md) N1.2 (консоль).

**Метаданные записи бакета.** До реализации писателей владелец этого урока публикует в репозитории реализации локальный договор и API библиотеки сохранения и чтения `written` бакета. Все писатели событий и ресурс используют этот договор. Представление приватно для реализации, стенд его не разбирает; приёмка наблюдает отметку после append, перезапуска и restore и исход хранения по сроку. Публичного поля события и требования нового общего модуля это не вводит.

`subsystem` строки индекса — имя манифеста, и у строк дерева тревог (`testsub`, не `testsub.alarms`). **Запрос событий и слияние.** `unit` в ответе индекса — полная ссылка `<дерево>/<единица>`. у журнала это `audit/<роль>`, у отметки — `console/<экземпляр>`, а её `of` — адресат. Ссылка логическая: дерево — без суффикса `.alarms`, он — раскладка писателя ([договор журнала событий](../../../common/ru/contracts/event-journal.md) `class`); строка из `audit.alarms/<роль>` отвечает и выбирается запросом как `audit/<роль>`, из `<sub>.alarms/<unit>` — как `<sub>/<unit>`, вместе с наблюдениями (N3 «запрос» шаг 2).

### N1.3 Индекс и срок

Форма `index` задана отдельными правилами: P/05-R067, P/05-R069, P/05-R259, P/05-R071, P/05-R072, P/05-R073, P/05-R074, P/05-R075, P/05-R076.

**`index.one_per_resource`.** Над своим деревом и .mirror/`<сервер>`/ копиями; состояние всегда live; перестройки и отдельной стартовой фазы `no_index` нет. **`index.cache`.** Ограничен (INDEX_CACHE_BYTES), выбрасывается без потери правильности; файл перечитывается по размеру/mtime/inode с места.

**`index.query`.** Правила запроса, нужные слиянию (параметры, умолчания, by) — договор слияния журнала событий «Запрос и ответ ресурса»; грамматика параметров и отказы — ниже этого блока.

**`index.row`.** {id, subsystem, unit, of, epoch, t, kind, server, bucket, class, epoch_is, fenced, …поля}. **Строка события и запись.** `server` — хозяин бакета. Строка со своим полем server (строка о сервере: drain.*, server.decommission_*, workers.no_server) его сохраняет — в такой строке server — сервер, о котором строка, индекс его не перетирает, как class.

**Запрос событий и слияние.** `epoch_is` и fenced ставит сливающий — консоль или воркер по договору слияния журнала событий; у ресурса строки без них.

**`index.epoch_is`.** `current` | `fenced` | `earlier-run` | `unknown`   — по current_epochs из `<sub>`/epoch/* и политике манифеста; unknown — только у воркера для эпохи, которую он не объявил в worker.reads; нужная эпоха не прочитана — строка без epoch_is, incomplete[`<sub>`/epoch] (договор слияния журнала событий «Эпохи»).

**`index.cut, answer`.** Обрезка, копии зеркала, truncated, partial — договор слияния журнала событий «Запрос и ответ ресурса»; ответ сливающего (консоль, воркер: + complete, incomplete) — там же, «The answer».

**`retention.<sub>/retention`.** {days}      — умолчание — договор журнала событий «Срок дерева»; форма строки — P/02.4 N1.9.

**`retention.<sub>/alarms_retention`.** {days}      — умолчание — договор журнала событий «Срок дерева»; форма строки — P/02.4 N1.9.

**`retention.writer`.** Обеих строк — admin командой оператора w2cctl retention (P/02.4 N1.9); ресурс и консоль их только читают (P/02.5 N1.4).

**`retention.rule`.** На подсистему, не на единицу. **Срок хранения и удержания.** `days` — конечное число > 0, иное — «unknown», ничего не убирать.

**Срок хранения и удержания.** Отметки консоли живут не меньше самого долгого дерева.

**Срок хранения и удержания.** Удержания holds: сохраняют бакеты (договор удержаний).

**Срок хранения и удержания.** Копии зеркала — на час дольше.

**Срок хранения и удержания.** Убранное — журнал events.removed.

**Граница срока.** Использовать собственный сохранённый логический `written` бакета по разделу договора журнала событий «Время записи бакета».

**Срок хранения и удержания.** Сначала консервативно разрешить чтение сроков и holds; удержание или неизвестная зависимость сохраняют бакет.

**Срок хранения и удержания.** Закрытый неудержанный бакет с читаемым `written` удаляется ровно при `now >= written + seconds`: обычный `<sub>` — `seconds = retention.days * 86400`; `<sub>.alarms` — `alarms_retention.days * 86400`; `audit`/`audit.alarms` — свой срок журнала; `console`/`console.alarms` — свой срок с нижней границей самого долгого дерева. Копия зеркала — срок соответствующего дерева плюс `MIRROR_RETENTION_EXTRA`, от собственного `written` копии. Равенство удаляет, время ниже границы сохраняет. Начало/конец окна и `mtime` файла не заменяют `written`.

**Срок хранения и удержания.** `restore` сохраняет `written` копии и не начинает срок заново.

**Срок хранения и удержания.** Обычные консервативные исходы holds и чтения предшествуют этому предикату.

Слияние ответов ресурсов консолью (`merge`) — [глава 6.4](../../../06-console/ru/spec/06.4-console.norms.md) N1.3 и N3 «слияние» (консоль); форма ответа консоли (`answer` выше, `ConsoleEvents` контракта) — общая с ресурсом.

Запрос использует конечные `from`/`to`, `from ≤ to`; `limit` — целое в диапазоне `limit` HTTP-формы: - `from`, `to` — десятичное число ASCII: необязательный `-`, цифры (между цифрами допустим `_`), необязательная точка с цифрами хотя бы с одной стороны, необязательная экспонента `e`/`E` со знаком; `1_0`, `.5`, `5.`, `1e3` — числа, `1e-400` — 0; `+1`, пробел (`%201`, `1%20`), не-ASCII цифры (`١`), `0x10`, переполнение — 400. **Запрос событий и слияние.** `limit` — только цифры ASCII (ведущие нули допустимы: `01`), иначе 400; `since` подсказки — по N1.6. `unit` — UnitRef `<sub>/<id>`: голый id, пусто, `testsub/`, `/c1` — 400. `late` — целое ≥ 0 десятичной записью, только вместе с `by=occurred`: иное — 400. Пустой или повторённый параметр — 400 (N2); незнакомый непустой параметр не читается (у `/events/wait` — 400, N1.6).

**Нечитаемая строка бакета** (P/01.1 N0 «Stability of output»). Строка, которая не JSON, не объект, с BOM, с числом вне JSON (`NaN`), без `kind`, `t` или `id`, с `id` не строкой, а также файл не на своём месте (путь бакета не по N1.2, например `e01`) — пропускается: в `events` и `truncated` не входит, ответ — 200, а число таких строк — `lines_garbled` ответа (поле есть, только когда больше 0). **Строка события и запись.** Порванная последняя строка — по-прежнему `partial`, не `lines_garbled`.

**Запрос событий и слияние.** Консоль складывает `lines_garbled` ответивших ресурсов и сама пропускает строку ответа ресурса не по форме EventRow, прибавляя её к своему `lines_garbled`.

**Запрос событий и слияние.** `events` в BucketInfo — число целых читаемых строк бакета; 500 перечня — только нечитаемый каталог или метаданные.

Иная форма запроса — 400, включая NaN/Infinity, дробный limit и голый unit. `by`, умолчания, `truncated` ресурса и сливающего — договор слияния журнала событий «Запрос и ответ ресурса».

**Запрос событий и слияние.** `fenced=true` тогда и только тогда, когда `epoch_is=fenced`; earlier-run не ограждён.

**Запрос событий и слияние.** В этом уроке не обещан атомарный снимок нескольких файлов или ресурсов.

**Срок хранения и удержания.** Неизвестное чтение срока или удержаний не равно отсутствию: зависимое дерево не удаляется до достоверного чтения. Отсутствующая строка retention даёт умолчание, ошибка чтения — нет.

**Запрос событий и слияние.** `complete`, `partial` у сливающего — договор слияния журнала событий «The answer», «Запрос и ответ ресурса».

### N1.4 Ресурс

Форма `resource` задана отдельными правилами: P/05-R077, P/05-R199, P/05-R079, P/05-R080, P/05-R082, P/05-R083, P/05-R084, P/05-R085, P/05-R086, P/05-R087, P/05-R088, P/05-R089. На сервере один процесс ресурса, без контроллера.

**`heartbeat`.** Объект platform/resources/`<server>`/heartbeat каждые HEARTBEAT_EVERY {server, ts, url, schema, build, usage, usage_at, space: {total, free, used, full}, volumes, units: {sub: [id]}, workers, running, short, waits, mirrors: {server: n}, pass_started, pass_stalled, restore, mirror, door, retention_garbled?: [`<sub>`…], retention_withheld?: {`<sub>`: days_garbled | unknown | holds_unread}, …}. **Пульс ресурса.** `retention_garbled`, retention_withheld — причины прохода срока (N3 retain, N4; нет причины — полей нет). `settings_unread`?: [mirror | space] — строки настроек прохода, которые не прочитались: шаг mirror (и копии тел N1.1) или relieve в этом проходе не исполняется; по возрастанию байтов; нет таких — поля нет.

**Пульс ресурса.** `door`: {addr, mode: loopback | mtls, cert_until} — в каждом пульсе, пишет ресурс: addr — RESOURCE_HOST:RESOURCE_PORT. **Строка двери ресурса и свежесть.** `mode` — loopback без RESOURCE_TLS (только петля), mtls с RESOURCE_TLS=1. `cert_until` — стенные секунды конца срока сертификата сервера своего комплекта, при mtls. При mtls сервер предъявляет лист, затем его центр (договор сертификата роли server; клиент — own_client, договор клиента объектов tls); читает w2cctl tls status (P/02.4 N1.9).

**Пульс ресурса.** `waits`, restore, mirror, units — в каждом пульсе: units — {`<sub>`: [`<id>`…]} единиц, которые называют в status пульсы воркеров этой коробки из running, id по возрастанию байтов; нет таких — {}. Пульс воркера нечитаем (семья heartbeats P/03.4: объект целиком, для ресурса и элемент status[] не по форме) — его единицы в units не входят: нечитаемое не расширяет.

**`workers`.** [`<sub>`/`<имя слота>`…] — все слоты, о которых ресурс знает на своей коробке. **Присутствие воркера и room.** `running`: [`<sub>`/`<имя слота>`…] — с живым процессом (держит замок присутствия, содержимое по форме с непустым worker). `unknown`: [`<sub>`/`<имя слота>`…] — присутствие не прочлось, имя slot известно из текущего читаемого содержимого (иначе ниже неизвестный снимок всей роли): файл замка не читается или flock/stat замка дали ошибку, кроме «занят» и ENOENT у stat (договор замка присутствия). `instances`: {`<sub>`/`<имя слота>`: `<экземпляр>`}; ключ с подсистемой: имя слота уникально только внутри своей подсистемы (P/03.2 `<sub>/slots/<name>`), у двух подсистем с одним `slot.prefix` имена совпадают.

**Пульс ресурса.** `pass_stalled`: `<секунды>`, только пока проход завис (PULSE_LIMIT). Одна форма пульса: консоль выдаёт её как ResourceRow P/06.5 (производная выдача), контроллер выводит из неё присутствие (ниже, P/04 «судьба»).

**`usage`.** Целое — байты файлов бакетов деревьев этого сервера и копий в .mirror/. **Использование томов.** `usage_at` — стенные секунды замера. `space` — том дерева событий: total, free, used — байты (statfs), full — доля used/total от 0 до 1 (не признак). `volumes` — то же по каждому тому.

**`door_row`.** `platform/doors/<host>` {url, since, at, room.`<sub>`…, live.`<sub>`…}; at — каждые ALIVE_EVERY (договор наблюдения «Состояние ресурса»). **`room`.** Элементы room.`<sub>` и live.`<sub>` — по договору замка присутствия «Count room» (presence-lock.md). **Строка двери ресурса и свежесть.** Не писать дверь, пока стоит platform/decommission/`<мой сервер>` (договор наблюдения «Сервер выведен» narrower; консоль её удалила). Это ограничение относится к строке двери; пульс, HTTP и проходы ресурса продолжаются.

**`lost_after`.** LOST_AFTER                      — договор наблюдения «Freshness»; по смене на часах читателя.

**`pass`.** Первый — при старте, сразу после готовности (строка двери записана); дальше каждые PASS_EVERY от конца прохода: retain → usage → relieve → mirror; каждый шаг в своей попытке; pass_stalled при зависании.

**`space`.** `platform/space` {enabled, high, low}   — доли; форма и умолчания — P/02.4 N1.9, data/space.schema.json; включено, пока не выключили: **Место и просьбы освобождения.** Строки нет — включено с high/low по умолчаниям этой формы space. `enabled`: false — ресурс снимает свою строку free-*. Строка не читается — шаг relieve не исполняется: умолчания high/low формы space не подставляются, своя строка free-* не пишется и не снимается, причина в пульсе settings_unread: space форма строки — P/02.4 N1.9 (пишет admin, w2cctl space).

**`free_ask`.** `<sub>`/requests/free-`<server>`-`<volume>` {free, volume, server, at}   — своя форма: пишет и перезаписывает с cas только ресурс, не создание-однажды, без unit/digest/схемы семьи; для манифестов с requests.free, пока том > high. **Место и просьбы освобождения.** Для requests.free volume — непустое имя из ASCII A-Z/a-z/0-9/_, 1–64 байта, без дефиса (на коробке один том — файловая система дерева событий, имя events). `server` — непустой сегмент ключа P/01.1, дефисы допустимы. Разделение по последнему дефису однозначно. Иной volume — вне профиля: диагностировать конфигурацию, не создавать/менять просьбу этого тома.

**Место и просьбы освобождения.** `free` = used − total·low − Σ freeing из пульсов (только ещё не отражённое в used освобождение). При free ≤ 0 (и под отметкой low) строка снимается.

**Место и просьбы освобождения.** Никто её не исполняет и не метит.

**Место и просьбы освобождения.** Адресат — все воркеры подсистемы `<sub>` на сервере `<server>`; `<volume>` — том ресурса, не место подсистемы. Σ freeing — сумма freeing.`<volume>` (P/03.4 N1.1) по живым пульсам воркеров `<sub>` на этом сервере, поля нет — 0 (векторы 05-resource/vectors/relieve; запрос VMS freeing).

**Место и просьбы освобождения.** Между low и high, пока need > 0, своя строка стоит как есть — не снимается и не переписывается.

**Место и просьбы освобождения.** `short` учитывает только тома, у которых текущее used/total строго выше high. На high и ниже он равен нулю, даже если своя просьба между low и high остаётся неизменной; сохранённые `free` и `at` этой просьбы не становятся текущей нехваткой. Для учитываемых томов семейная форма задаёт максимум need по подсистемам, округление и насыщение. Непрочитанный вход прохода сохраняет прежнее значение с учётом независимо известного исхода отключённого space.

**`mirror`.** `platform/mirror` {enabled, copies}; строки нет или поля enabled нет — enabled: false, бакеты не копируются, пока не станет enabled: true. **Зеркало бакетов.** Строка не читается — шаг mirror не исполняется, причина в пульсе settings_unread: mirror, `copies 1, enabled false` не подставляются; тела — N1.1 mirror.

**Зеркало бакетов.** Соседи — следующие copies живых серверов по имени; живость — по строке двери platform/doors/`<сервер>`, как в договоре слияния «Живые ресурсы» (версия менялась в последние LOST_AFTER по часам этого ресурса, первый взгляд — как свежий), пульс соседа здесь не судит.

**Зеркало бакетов.** Только закрытые бакеты. Копия в .mirror/`<сервер>`/…. Копия — никогда не источник, пока хозяин отвечает; PEER_FAILS, бакет в пределах байтового потолка двери ресурса (OpenAPI Content-Length.maximum) целиком,.

**Зеркало бакетов.** Копия добавляет MIRROR_RETENTION_EXTRA к сроку.

**Зеркало бакетов.** Закрытый бакет больше этого потолка двери (предел приёма зеркала) не копируется: сборки из кусков и частичной копии нет, он входит в mirror.skipped пульса каждым проходом, остальные бакеты копируются. Форма строки platform/mirror — P/02.4 N1.9 (пишет admin, w2cctl mirror).

**`presence`.** `runs` | `gone` | `unlisted` | `unknown`   — о процессе воркера своей коробки — вывод из полей пульса выше: ключ `<sub>`/`<имя>` слота воркера подсистемы `<sub>`: в running — runs; в unknown — unknown; в workers, но не в running и не в unknown, — gone (ресурс знал процесс, он мёртв); не названо в workers — unlisted (у ресурса не зарегистрирован); пульс без этих полей — о воркере ничего (P/04 «судьба»); отсутствующее из трёх полей — пустой список, не нечитаемость: выбор — [decision-order.tsv](../../forms/decision-order.tsv), процедура `presence`. **Присутствие воркера и room.** Перечень `<корень событий>`/.workers/`<sub>`/ не получен (ошибка, кроме ENOENT ещё не созданного каталога — тот пуст): в пульсе нет всех трёх полей — о воркерах ничего (P/04 wait), прежние имена не переносятся, частичного набора нет; остальной пульс — как обычно. Как ресурс узнаёт присутствие — договор замка присутствия. `silent` — состояние самого ресурса (договор наблюдения), не значение присутствия.

**`presence_lock`.** `<корень событий>`/.workers/`<sub>`/`<экземпляр>`.lock — договор замка присутствия (presence-lock.md); после flock ресурс сверяет fstat(fd) и stat(путь), не совпало (ENOENT у stat тоже) — файл не трогает; flock воркера — блокирующий.

**Присутствие воркера и room.** Содержимое — семья presence-lock (data/presence-lock.schema.json, presence-lock.outcomes.tsv; ниже): {instance, sub, worker, server, pid}, worker "" до захвата имени; занятый замок с пустым или не по форме содержимым — живой процесс без номера (в room, не в workers, running, live); unknown — только нечитаемый файл и ошибка flock или stat, кроме «занят» и ENOENT.

**`requires`.** `placement.requires`: resource — воркер вне пула, пока ресурс его сервера silent (P/04).

**Формы писателя и читателя пульса**. Нынешние писатель и читатель MUST требовать `door`, `waits`, `restore`, `mirror` и `units`.

**Пульс ресурса.** При начальном состоянии до выполнения операций: `units = {}`, `restore = {}`, если необходимых соседей нет, `waits = {waiting:0, held:0, full:0, replaced:0, max:LONG_POLL_WAITERS}`, счётчики mirror `skipped`, `failed`, `peer_errors`, `lines_garbled` — нули. У имеющихся необходимых соседей остаются настоящие записи restore, включая неполные; нейтральные значения не стирают ошибку или незавершённую попытку.

**Пульс ресурса.** У `door` всегда настоящие `addr` и `mode`; `mtls` дополнительно требует действительный `cert_until` серверного сертификата.

**Пульс ресурса.** Обычный корень схемы требует эти нынешние поля и условие mtls в обоих режимах. Нарушение получает существующий исход нечитаемого пульса; читатель не выдумывает успех операций или состояние TLS по отсутствующему полю.

**Безымянная неизвестность присутствия**. Ошибка текущего замка без читаемого имени slot делает неизвестным снимок всей роли, даже при успешном листинге и холодном старте. **Присутствие воркера и room.** Действует раздел договора замка присутствия «Неизвестный снимок роли»: не писать `workers`, `running`, `unknown` и `instances` из этого снимка, у затронутой роли `room.<sub>` — `"unknown"`, `live.<sub>` отсутствует; независимо полные room/live других ролей сохраняются. Не выводить slot из имени файла, прежней памяти или другого замка; отсутствие полей не означает `unlisted` или `gone`.

**Присутствие воркера и room.** Содержимое замка присутствия — семья `presence-lock` урока: [схема](../../data/presence-lock.schema.json), [исходы](../../data/presence-lock.outcomes.tsv) (слои — [LAYERS](../../../common/ru/LAYERS.md)): экземпляр — `{key, file}`, текст файла с `x-encoding: json` у корня (LAYERS § 6), колонка `schema` строки каталога называет семью, раздел — «Семьи данных» ниже; смысл — [договор замка присутствия](../../../common/ru/contracts/presence-lock.md).

**Объекты кластера — через ресурс своего сервера**. Процесс платформы читает объекты других серверов (пульсы воркеров и ресурсов, отчёты прохода) дверью объектов ресурса своего сервера (N2, `scope`); без ресурса на своём сервере при `cluster://` — «unknown», не «нет» ([договор клиента хранилища объектов](../../../common/ru/contracts/object-client.md) `door`). Стенд, которому нужны пульсы воркеров, ставит ресурс на сервер читателя ([P/04](../../../04-controller/ru/spec/04-controller.norms.md) N3 «проход()» шаг 0).

PULSE_LIMIT — конечный положительный предел длительности одного шага ресурса в секундах, выбранный и объявленный реализацией до старта. Длительность измеряется местными монотонными часами, а не t/at писателя; пока шаг идёт сверх предела, каждый пульс несёт pass_stalled; поле снимается при завершении шага, в том числе до следующего пульса. Это диагностический порог, не обещание остановить зависший вызов или дождаться ответа.

**Восстановление бакетов** (отказ сервера и `power_pull` — [P/04](../../../04-controller/ru/spec/04-controller.norms.md) N1.4a): **`restore`.** Ресурс при старте тянет свои закрытые бакеты от соседей, чьи пульсы mirrors его называют: GET /mirrored/`<я>`, каждый бакет по сумме, tmp + rename.

**Восстановление и попытки соседей.** PEER_FAILS подряд — сосед пропущен до конца этой попытки restore; граница и следующая попытка — P/05-R307.

**Восстановление и попытки соседей.** Попытка restore обходит необходимый набор соседей и завершается после получения и проверки нужных перечней/копий либо пропуска оставшихся соседей по PEER_FAILS. За неполной попыткой следует следующая в том же процессе через RESTORE_RETRY; интервал между неполными попытками удваивается до RESTORE_RETRY_MAX. Следующая попытка снова рассматривает пропущенных соседей и сбрасывает только локальную последовательность подряд идущих неуспехов процедуры, не накопленные диагностики. Полностью завершённый restore больше не планирует попыток восстановления при этом старте. Backoff относится к промежутку между попытками, а не задаёт дополнительного обязательного интервала вызовов внутри попытки.

**Восстановление и попытки соседей.** Сделано, когда получены полные списки и проверены копии от всех известных необходимых соседей. Необходимые соседи — чьи читаемые пульсы mirrors называют этот сервер. Для необходимого набора дверей по P/05-R303 каждый чужой сервер должен ответить полным перечнем GET /mirrored/`<я>` (полный пустой перечень и 404 — копий нет, этот сосед завершён). 404 GET уже перечисленного бакета — недостающая копия, не пустой листинг: попытка остаётся неполной.

**Восстановление и попытки соседей.** Если пульс соседа отсутствует или нечитаем, необходимы все известные чужие двери серверов независимо от пустоты локального корня событий. Непустой корень не доказывает, что ни один бакет не потерян. Нельзя выводить локальную полноту из наличия другого бакета или подменять полный перечень неподтверждённым составом дверей.

**Восстановление и попытки соседей.** Восстановленный бакет сохраняет listed copy written как собственную отметку срока, не время приёма и не mtime файла.

**Восстановление и попытки соседей.** Не перезаписывать существующий локальный бакет копией того же пути с проверенной суммой, если байты различаются. Одинаковые байты/сумма не обновляют локальную отметку срока. Если локального бакета нет, первая проверенная копия может быть опубликована; последующая отличающаяся копия не откатывает опубликованные байты. Любое обнаруженное расхождение оставляет restore неполным и отражается существующей диагностикой; receiver `written` не выбирает победителя, строки не сливаются. Одна проверенная сумма не доказывает полноту восстановленных событий.

**Восстановление и попытки соседей.** Неизвестная или нечитаемая дверь оставляет восстановление неполным. Пропущенный/нечитаемый сосед оставляет восстановление неполным; 500 перечня и обрыв ответа по N2, N4 не считаются пустым полным списком. Если соседей никогда не было, удалённое восстановление отсутствует.

**Восстановление и попытки соседей.** `restored` пульса — только реально вытянутые у этого соседа бакеты; бакет, уже лежащий на томе, не считается.

**Восстановление и попытки соседей.** Потом — переиндексация подсистемы; копия — никогда не источник, пока хозяин отвечает (mirror выше).

**Восстановление и попытки соседей.** Локальная последовательность PEER_FAILS сбрасывается после успешной операции соседа и в начале следующей попытки restore или прохода mirror. Пропущенный необходимый сосед оставляет нынешний restore неполным; следующая попытка рассматривает его снова.

**Зеркало бакетов.** `mirror` снова рассматривает соседа в следующем проходе.

**Восстановление и попытки соседей.** Это отдельные локальные последовательности процедур; накопленные диагностические счётчики на этих границах не сбрасываются. Неуспех в такой последовательности — транспортная ошибка, истечение срока вызова или отказ зависимости; построчный отказ 400/409/422 последовательность не наращивает: не удалась только эта строка, остальные строки продолжаются. 404 при GET бакета, перечисленного соседом, — такой неуспех: сосед объявил копию и не отдал её.

**Диагностика restore.** Наличие необязательных расширений `restore.<name>` выбирает реализация, приёмка его не судит. Если поле выдано, `silent` означает текущую недоступность соседа; `last_ok` и `error_at` — wall-clock секунды последнего успеха и ошибки; `last_error` — текст причины; `next` — wall-clock секунды запланированной следующей попытки. Обязательные `done`, `restored`, `missing` и `failures` задают обязательное состояние восстановления; отсутствие расширения не доказывает done и не превращает неполного соседа в полного.

**Восстановление и попытки соседей.** Порядок бакетов между проходами договором не является.

### N1.6 Подсказка и представления HTTP

`GET /events/wait` ресурса — подсказка, не доставка событий. Профиль урока: `want` — непустой список через запятую `<sub>/<kind>[/<unit>]`; каждая часть из ASCII букв, цифр, `_`, `-`, `.`, 1…64 знака, не начинается с точки. **Подсказка событий и долгое ожидание.** `client`, если передан, — 1…128 печатных ASCII-знаков без пробела. `since` — десятичный uint64 без знака/ведущих нулей, по умолчанию 0. `timeout` — конечное число секунд с границами и умолчанием `GET /events/wait` в [HTTP-форме](../../spec/05-resource.api.openapi.yaml). Пустые/повторные параметры, незнакомые параметры (`&foo=1`), иные формы и значения вне области — 400; `since` и `timeout` — только цифры ASCII (и точка у `timeout`), не-ASCII цифры — 400.

**Подсказка событий и долгое ожидание.** `since=0` — у клиента нет позиции: ответ сразу `{changed: true, seq, touched}`, если под want есть строки в бакетах ресурса любой давности; seq — непрозрачное монотонное число процесса ресурса, клиент только сравнивает и передаёт его обратно. При `since`, равном последнему `seq` этого процесса ресурса, и отсутствии строк под `want`, записанных после этого `seq`, ожидание заканчивается по сроку `{changed: false, seq}`; строка под `want`, записанная после этого `seq`, даёт ответ `{changed: true, seq, touched}`.

**Подсказка событий и долгое ожидание.** Для неизвестного ненулевого `since` немедленно вернуть `WaitQuiet` с текущим `seq`. Применить процедуру `wait` из [decision-order.tsv](../../forms/decision-order.tsv): эта ветвь не попадает в очередь ожиданий, не замещает прежнее ожидание и не занимает место. Клиент по-прежнему выполняет обычный проход по P/05-R248.

**Подсказка событий и долгое ожидание.** Выдаваемый процессом ресурса `seq` положителен; нуль означает только отсутствие позиции у клиента. Начальное положительное значение выбирает реализация, приёмка его не судит; граница uint64 и монотонность внутри процесса сохраняются.

**Подсказка событий и долгое ожидание.** Подсказку дают деревья подсистем каталога (`<sub>`, `<sub>.alarms`); деревья `console` и `audit` подсказки не дают. Этот ограниченный профиль не требует принимать любые внутренние имена единиц: периодический проход клиента остаётся обязательным и работает без подсказки.

**Подсказка событий и долгое ожидание.** Сопоставлять `want` и формировать `touched` по логическому имени подсистемы манифеста без `.alarms`; подсказку дают оба её дерева — наблюдений и тревог. Синтаксически допустимый `want`, называющий `testsub.alarms`, не нормализуется и не совпадает ни с одной подсистемой; новый отказ 400 для него не вводится.

Ответ — одна из закрытых форм WaitAnswer: `{changed:true, seq, touched:[…]}`, `{changed:false, seq}`, `{changed:false, seq, full:true}` или `{changed:false, seq, replaced:true}`. **Подсказка событий и долгое ожидание.** В touched — отсортированные уникальные `<sub>/<kind>/<unit>`, подходящие want; самих событий нет.

**Подсказка событий и долгое ожидание.** `seq` относится к одному процессу ресурса; после перезапуска/неизвестной последовательности клиент делает обычный проход. При full/replaced клиент не продвигает свой курсор по seq, а возвращается к обычному проходу.

**Подсказка событий и долгое ожидание.** По умолчанию до LONG_POLL_WAITERS_DEFAULT ожиданий (параметр развёртывания LONG_POLL_WAITERS); новое ожидание при заполнении — 200/full. Применить [decision-order.tsv](../../forms/decision-order.tsv), процедуру `wait`, для замены и вместимости. При заполненном действующем LONG_POLL_WAITERS замена допускается и остаётся столько же; другой CN это место не освобождает.

**Подсказка событий и долгое ожидание.** Ожидание не занимает полосу вычисляемых /events по P/06.4 N3 merge (N3 «запрос»); оно держит своё соединение двери до ответа (changed, срок, full, replaced) или до замеченного ухода клиента (не позже WAIT_DISCONNECT_WITHIN) — «общая полоса» N2 — предел соединений двери ресурса («Решает реализация» п. 10).

**Подсказка событий и долгое ожидание.** В TLS личность — CN сертификата плюс client; другой CN не вытесняет ожидание.

**Подсказка событий и долгое ожидание.** Без client развёртывание использует отдельное ожидание на адрес клиента; повтор при занятом адресе — full.

**Подсказка событий и долгое ожидание.** Наблюдение текущих бакетов каждые WAIT_OBSERVE_MS / 1000 секунд, пока есть ожидающие; пропущенная подсказка или запись в старый бакет восполняется обычным проходом, а не обещанием доставки.

Пути `/mirror/{server}/{path}`, `/mirrored/{server}[/{path}]`, `/events/{path}`: `{server}` — один сегмент по грамматике имени сервера (P/02.4 N1.2 `SERVER_NAME`); `{path}` — путь бакета N1.2 (`<дерево>/<unit>/e<эпоха>/<начало>Z.events.jsonl`), ни один сегмент не пуст и не `.`/`..`, `%2F` — не разделитель, `.tmp` — не бакет. Иное: `GET /mirrored/…` и `GET /events/…` — 404 без тела, `PUT /mirror/…` — 400 без тела. **Сырые пути и сопоставление маршрутов.** Файл вне своего дерева (`.mirror/<server>/` у копий) ресурс не читает и не пишет никогда.

**Зеркало бакетов.** `PUT /mirror` бакета, чей конец по имени позже часов приёмника, — 400: зеркало принимает только закрытые бакеты.

**Зеркало бакетов.** `PUT /mirror/<свой сервер>/…` (копия от себя) — принять или отказать — «Решает реализация» п. 11.

**Представления и отказы потока.** Значение `X-Sum` — поле HTTP: пробелы по краям (OWS) отбрасываются до проверки формы.

Представления HTTP — в схемах N2. `BucketInfo` — описание одного бакета, не событие; `/buckets` выдаёт UTF-8 JSON Lines: один объект на LF, без массива.

**Зеркало бакетов.** `/mirrored/<server>` по канону этого урока выдаёт `{copies:[{path,written,size,sum}]}`. `written` копии — стенные секунды (N0), когда приёмник опубликовал эту копию у себя (время файла копии или своя запись): `PUT /mirror` времени исходного бакета не несёт, только `X-Sum`; байты бакета не меняются; повторный приём того же бакета с той же суммой `written` не сдвигает.

**Зеркало бакетов.** Байты копии — отдельный GET. Поле `sum` и заголовок X-Sum — 64 строчные hex-цифры SHA-256 целого тела.

**Операции владельца-консоли.** Форма `answered` (метка-строка просьбы, AnsweredMark) — [глава 6.4](../../../06-console/ru/spec/06.4-console.norms.md) N1.6 (дверь консоли).

## N2 Двери

Полный контракт: [OpenAPI](../../spec/05-resource.api.openapi.yaml).

**Независимые пределы размера и времени.** Байтовый потолок объекта не ограничивает GET `/events/{path}`: он отдаёт бакет целиком до зафиксированного для чтения размера с общими эксплуатационными бюджетами. GET объекта ограничен байтового потолка двери ресурса (OpenAPI Content-Length.maximum) по реально прочитанным байтам: ровно предел разрешён, +1 байт — 413 ResourceError до успешных заголовков; тело до подтверждения размера ограниченно буферизуется либо проверяется по неизменяемому объекту с достоверным размером. Потолок самого хранилища может быть выше и этот предел двери не отменяет. Он различает ресурс и консоль, JSON-ответы, поток байтов и отсутствие тела.

**Представления и отказы потока.** Схемы задают обязательные поля и допустимые расширения; проверки существования, прав, UTF-8-размера и состояния исполняются отдельно. Внешний массив не заменяет JSON Lines.

| Вход | Успех | Прикладные отказы |
|---|---|---|
| ресурс GET /v1/objects | 200 ObjectListing | 400 ResourceError; 403 ResourceError или ResourceDenied; 503 ResourceError |
| ресурс GET /v1/objects/{key} | 200 байты; X-Written, X-Server, при необходимости X-Missing | 400/403/404/413/503 ResourceError |
| ресурс PUT /v1/objects/{не-блоб} | нет | 405 ResourceError; ключ/scope — 400 |
| ресурс GET /buckets/{sub}/{unit} | 200 JSON Lines из BucketInfo | 404/500 без тела |
| ресурс GET /events | 200 ResourceEvents; у ресурса `HEAD` — 405 | ресурс 400 ResourceError (разбор ниже); ресурс 503 ResourceError |
| ресурс GET /events/wait | 200 WaitAnswer, в том числе full/replaced | 400 ResourceError; общая полоса занята — 503 ResourceError |
| ресурс GET /events/{path} | 200 целые байты + X-Sum; 206 один диапазон + Content-Range | 404/500 без тела; 416 text/plain + Content-Range |
| ресурс PUT /mirror/{server}/{path} | 204 без тела; заголовок `X-Sum` — SHA-256 тела (64 строчных hex), обязателен; 204 подтверждает, что проверенная копия и нужные ей метаданные переживают отказ в границах заявленной модели отказов, барьеры выбирает реализация | нет `X-Sum` или он не по форме — 400, тело не принимается; SHA-256 тела не совпала — 422; 408/413/500 — без тела |
| ресурс GET /mirrored/{server} | 200 MirroredListing | 404/500 без тела |
| ресурс GET /mirrored/{server}/{path} | 200 байты + X-Sum | 404/500 без тела |
| ресурс `PUT /v1/objects/<sub>/blobs/<digest>` | 204 без тела. Обязательны длина ≤байтового потолка двери ресурса (OpenAPI Content-Length.maximum), `X-Written` — неотрицательное время исходной копии (нет или не число — 400), имя sha256 с 64 строчными hex; байты не того дайджеста — 422; ключ не blob-формы или подсистема без blob-поля — 405, как у любого объекта (N1.1 «Bodies at the resource» `mirror`). При чтении проверяются фактический предел/сумма | 400/404/405/408/409/411/413/422/503 — `ResourceError`, 403 — он либо `ResourceDenied`. Общие отказы консоли сюда не применяются |

**Один диапазон байтов.** У одиночного диапазона `GET /events/{path}` конец за зафиксированным размером файла усечь до size−1. Начало на size или за ним, начало больше конца и любой суффиксный диапазон пустого файла дают 416 с `Content-Range: bytes */size`. Положительный суффикс длиннее непустого файла даёт весь файл с 206. Формы вне объявленного профиля одного диапазона, включая непо-шаблону или множественный Range и условные запросы, выбирает реализация, приёмка их не судит; нового обязательного отказа для них не назначается.

`GET /events` консоли (слияние, ConsoleEvents, `HEAD`) и двери консоли `POST /marks`, `POST /{sub}/requests`, `DELETE /{sub}/asked/{sha16}` — [глава 6.4](../../../06-console/ru/spec/06.4-console.norms.md) N2; схемы ответа `/events`, общие обеим дверям (`EventRow`, `UnitRef` и ниже), — в контракте этого урока.

Для обоих перечней (`/buckets/{sub}/{unit}` и `/mirrored/{server}`) все необходимые чтения каталога/метаданных завершаются до успешных заголовков: неизвестность/ошибка — 500 без тела, не 404 и не пустой 200. Это наблюдённый перечень, не снимок нескольких файлов. Читаемый существующий пустой каталог копий даёт 200 `{copies:[]}`; отсутствующий каталог копий — 404. Для restore оба завершают соседа без копий.

**Представления и отказы потока.** Обрыв уже начатой передачи перечня не является полным ответом; новый HTTP-статус после заголовков не отправляется.

**`scope`** У `/v1/objects` и `/v1/objects/{key}`: `local` (умолчание) — только каталог объектов этого сервера; `cluster` — объекты кластера по N1.1 `cluster` (свежая копия по `written` побеждает, сервер, который не ответил, — `missing`); иное значение — 400 (N4). Ресурс — дверь чтения объектов кластера для процессов своего сервера (N1.4 «Объекты кластера — через ресурс своего сервера»).

**Кластерное чтение и отсутствующие ответы.** При `scope=cluster` опрашивать локальный сервер и все чужие серверы подтверждённого перечня `platform/doors`; не фильтровать их по живости строки двери. Известный сервер, который не ответил или чья дверь нечитаема, — `missing`. При известном составе опроса листинг возвращает 200 с `missing` для таких серверов; чтение ключа — обычный исход с `X-Missing` при неполноте опроса. Неподтверждённый состав дверей или сбой локального чтения/листинга даёт прежний 503 ResourceError, не полный перечень. Опрос имеет конечный срок ожидания зависимости, объявленный реализацией по общим эксплуатационным обязанностям; числового значения этот урок не задаёт.

ResourceError — только `{error: text}`.

**Допуск к объектной двери.** Отказ 404 при чтении объекта означает «нет среди ответивших»; при неполном опросе X-Missing обязателен, полнота не выводится из самого кода 404.

**Разбор запроса.** Дверь ресурса — по P/01.1 N2.1 (query, путь байт в байт, HTTP по RFC 9112, ранний отказ) с отступлениями: отказ разбора query — 400 ResourceError `{error}`. **Сырые пути и сопоставление маршрутов.** пустой или повторённый параметр — 400, кроме пустого `prefix` листинга объектов (200).

**Сырые пути и сопоставление маршрутов.** нет пути и неподдержанный метод — 404/405 без тела, в том числе `OPTIONS`, `POST /events`, `PUT /v1/objects` (листинг), `GET`/`POST`/`DELETE` на `/mirror/…`. `PUT /v1/objects/{non-blob}` — прикладной 405 ResourceError (N4).

**Сырые пути и сопоставление маршрутов.** `/buckets/{sub}/{unit}` использует грамматику Subsystem без точки: `testsub.alarms` даёт 404 без тела и без нормализации; события тревог остаются доступны через query и известный путь бакета. Это ровно два непустых сегмента, `/buckets/testsub/`, `/buckets/../objects`, `/buckets/testsub%2Fc1` — 404 без тела.

**Представления и отказы потока.** тела `PUT` — байты, JSON не разбирается.

**Сырые пути и сопоставление маршрутов.** Общий слив P/01.1 R050 считает сырые байты HTTP-потока; абсолютный монотонный интервал начинается после отправки полного отказа, слив chunked не ждёт завершающей части. Ссылка разбора не заменяет собственные исходы или бюджеты тайм-аута ресурса отказами фаз ввода P/01 и не добавляет общего срока ответа потокам ресурса.

ResourceDenied (`error=refused`, detail, role при отказе роли) — 403 шлюза ресурса, до обработчика маршрута.

**Сырые пути и сопоставление маршрутов.** Отказ TLS до HTTP не получает выдуманного HTTP-тела. Каждый применимый общий ответ внесён в OpenAPI.

**Сырые пути и сопоставление маршрутов.** При busy — Retry-After: 1.

**Сырые пути и сопоставление маршрутов.** На неизвестном пути — 404; на неподдержанном методе известного пути — 405; у ресурса оба без тела. Этого общего правила достаточно: оно не создаёт отдельный метод OpenAPI для каждой невозможной операции.

**Форма сопоставления маршрутов.** У path item OpenAPI уникальный целый `x-route-priority`: меньше — раньше.

**Сырые пути и сопоставление маршрутов.** Сырой путь сопоставляется точно, без процентного декодирования литералов, нормализации пути и неявного завершающего слэша. Параметр пути объявляет `x-path-capture` (`segment` либо `remainder`, только в конце) и `x-path-decode: percent-segment`. Сырой остаток захватывается включая пустой хвост и пустые внутренние сегменты; каждый захваченный сегмент декодируется отдельно. Декодированный слэш не создаёт разделитель и недопустим. Пустое либо иное значение вне формы — ошибка параметра выбранной операции, не переход к другому маршруту.

**Сырые пути и сопоставление маршрутов.** Сначала структурно совпавшие шаблоны фильтруются по HTTP-методу, затем выбирается наименьший приоритет; лишь если такого метода нет — общий 405 без тела (нет совпавшего шаблона: 404 без тела).

**Сырые пути и сопоставление маршрутов.** `x-path-error` параметра отображает каждый применимый HTTP-метод в `{status, response_schema}`: имя существующего компонента OpenAPI либо `-` без тела.

**Сырые пути и сопоставление маршрутов.** В частности общий objects GET остаётся для ключа вида blob, когда специальный blob-маршрут имеет только PUT.

**Сырые пути и сопоставление маршрутов.** Точные приоритеты, вид захвата и проекции отказа — форма OpenAPI, без второго списка маршрутов в прозе.

**Сырые пути и сопоставление маршрутов.** Отказ схемы и декодирования не нормализует чужой или недопустимый ключ в путь файла.

**Представления и отказы потока.** Текст ошибки ResourceError остаётся непустой диагностикой, не новым фиксированным словом ошибки.

**Допуск к дверям ресурса**. Ресурс с TLS проверяет клиента: цепочка до центра, серийник не в `revoked` ([договор сертификата роли](../../../common/ru/contracts/role-certificate.md) `revoke`), ровно одна роль из строки маршрута, CN = `<роль>.<SAN DNS>`; иначе отказ рукопожатия или 403 `ResourceDenied` с ролью и маршрутом.

**TLS и допуск ролей.** Клиент сверяет роль `resource` и SAN DNS сервера с хостом адреса; IP при TLS — отказ клиента.

При режиме двери `mtls` таблица ролей по операциям — [forms/door-roles.tsv](../../forms/door-roles.tsv), пути и методы — из OpenAPI. **TLS и допуск ролей.** `<sub>worker` раскрывается только по загруженному каталогу манифестов; `*` — любая аутентифицированная роль с комплектом. Роль проверяется до обработчика совпавшей операции; проверки TLS выше обязательны.

**TLS и допуск ролей.** Режим loopback сохраняет допуск по договору ролевого сертификата. Неизвестные пути и методы это не допускает.

**Ограничения профиля.** Файл бакета читается целиком или одним Range; составные Range и условные HTTP-запросы не входят в урок.

**Представления и отказы потока.** Размер ответа фиксируется перед чтением; ответ не обещает снимка всего дерева.

**Представления и отказы потока.** После начала выдачи обрыв потока не превращается во второй HTTP-статус: вызывающий не принимает неполные байты как целую копию.

**Зеркало бакетов.** Приём зеркала ограничен байтового потолка двери ресурса (OpenAPI Content-Length.maximum) и объявленным развёртыванием сроком чтения; превышение размера — 413, срока — 408.

**Зеркало бакетов.** `PUT /mirror/{server}/{path}` принимает правильно оформленное chunked-тело без Content-Length с прежними проверками полного тела, суммы, срока приёма и фактического байтового предела. Фактические байты сверх предела дают прежний 413, оборванное тело — прежний 400 без публикации новой копии; 411 этому маршруту не назначается. Если Content-Length передан и выше предела, как прежде отказать до чтения тела.

**Копии тел.** `PUT /v1/objects/<sub>/blobs/<digest>` — копия тела соседа (таблица выше; N1.1 «Bodies at the resource»); `PUT /<rows>/<id>/<blob_field>` целиком принадлежит [P/06.1](../../../06-console/ru/spec/06.1-console.norms.md) N2 (дверь байтов консоли); прочие объекты дверь ресурса не пишет — отказ записи не-блоба, частичной копии контракта блобов нет.

## N3 Проход

### старт ресурса — проверка схемы

Входы процесса перечислены в [forms/daemon-flags.tsv](../../forms/daemon-flags.tsv); вычисляемые умолчания и общие проверки остаются правилами указанных договоров. CLI-флагов не добавляется.

Сторона ресурса общего блока [P/06.6](../../../06-console/ru/spec/06.6-console.norms.md) N3 «старт консоли — проверка схемы»; строка `platform/schema` и её подъём — P/06.6 N1.1a; прочие процессы — P/06.6, P/03.2, P/04. Порядок старта ресурса — [жизненный цикл](../lifecycle.md).

Первым шагом старта, до чтения манифеста (P/02.3), ресурс выполняет «Проверку при старте» [договора схемы](../../../common/ru/contracts/schema.md).

### записать событие (платформа, по observe подсистемы)

Шаги записи строки (класс, `of`, подавление, бакет по `t`, дописывание и `fsync`) и их «Гонки» — [договор журнала событий](../../../common/ru/contracts/event-journal.md) «Запись строки» (урок — владелец договора). Отказы записи — N4.

### запрос (ресурс) → {events, state, truncated}

Выполнить следующие шаги в указанном порядке: P/05-R093, P/05-R094, P/05-R095, P/05-R096, P/05-R097, P/05-R098.

**Шаг 1.** Проверить параметры (N1.3)                                          → 400 (у ресурса ResourceError, у консоли ConsoleRefusal).

**Шаг 2.** Кандидаты: окно ≤ QUERY_NAMED_BUCKET_LIMIT бакетов — имена по времени; шире — листинг каталога; если граница не представима именем календаря — листинг, без переполнения; порог выбирает лишь поиск кандидатов, не горизонт запроса и не потолок ответа; оба дерева подсистемы (и .alarms); копии .mirror/*: тот же бакет — дубль, отвечает под именем хозяина.

**Шаг 3.** Читать файлы с места прошлого чтения (кэш по размеру/mtime/inode); порванная строка — пропустить (partial); нечитаемая строка или файл не на месте — пропустить и счесть в lines_garbled (N1.3), ответ не 503.

**Шаг 4.** Фильтр: kind, subsystem, unit — логическая ссылка `<дерево>`/`<единица>`, у строки дерева .alarms — без суффикса (и строки с of = unit; параметр с суффиксом .alarms — форма UnitRef его допускает — не нормализуется и ни с одной строкой не совпадает: 200 без совпадений), class, окно from ≤ t < to (или так же по occurred: бакеты до to + late, договор слияния журнала событий `by`).

**Шаг 5.** `epoch_is` и fenced ресурс не ставит: их ставит сливающий (договор слияния журнала событий); права на `<sub>`/epoch/* ресурсу не нужны.

**Шаг 6.** Убрать дубли id, упорядочить и взять первые limit по cut (договор слияния журнала событий); truncated = число кандидатов после дедупликации минус число выданных → строки N1.3.

**Запрос событий и слияние.** Если разные файлы содержат читаемые строки с одним `id`, но разным содержимым, сохраняемое содержимое выбирает реализация; приёмка этот выбор не судит. Ответ по-прежнему содержит не более одной строки на `id` и выполняет обычные правила фильтра, порядка и правильности кэша. Внутри одного бакета действует прежнее правило первой строки договора журнала событий. Этот выбор не разрешает корректному писателю повторно использовать id или копии менять исходную строку.

**Запрос событий и слияние.** Ресурс отвечает `503 busy` с `Retry-After: 1`, когда число одновременно вычисляемых запросов `/events` превышает предел полосы слияния P/06.4 N3. Считаются только запросы, которые вычисляются сейчас; удержанное ожидание `/events/wait` не занимает эту полосу.

**Гонки.** Чтение открытого бакета во время дописывания: отдаются только целые строки, порванная не отдаётся и ответ несёт `partial: true` (`truncated` — число, N1); перечисление не фиксирует содержимое файлов: исчезнувший файл не подтверждает пустой бакет.

**Запрос событий и слияние.** Ошибка чтения файла или каталога не выдаётся как полный ответ; после начала HTTP-потока — обрыв, до него — 503 ResourceError. Нечитаемая строка — не ошибка чтения: она пропускается и считается (N1.3, P/01.1 N0 «Stability of output»).

### проход ресурса — при старте, затем каждые PASS_EVERY от конца прохода

Первый проход — сразу после готовности (строка двери записана), не через PASS_EVERY: сверка после перезапуска и края `free_ask` не ждут PASS_EVERY; следующий — через PASS_EVERY от конца предыдущего.

**Готовность и restore.** После проверок старта запустить отдельную попытку restore и публиковать дверь без ожидания done восстановления. Пульс и HTTP продолжаются при неполном restore. Первый проход ресурса начинается после readiness по P/05-R052 и не ждёт done восстановления; внутренний способ исполнения этих действий остаётся выбором реализации.

Выполнить следующие шаги в указанном порядке: P/05-R234, P/05-R100, P/05-R101, P/05-R102.

**`retain`.** Для каждого дерева: days = `<sub>`/retention | умолчание (tree.alarms — alarms_retention | умолчание; audit, console — умолчание; умолчания — договор журнала событий «Срок дерева»). **Срок хранения и удержания.** `days` не число или ≤ 0 или строка не ответила → не известно: ничего не убирать, назвать в пульсе — неверный days: `<sub>` в retention_garbled и retention_withheld[`<sub>`] = days_garbled; строка не ответила — retention_withheld[`<sub>`] = unknown; удержания не прочитаны (договор удержаний) — retention_withheld[`<sub>`] = holds_unread. Каждое дерево удерживается по своему сроку (`<sub>` — retention, `<sub>`.alarms — alarms_retention); retention_withheld[`<sub>`] — одна причина по [decision-order.tsv](../../forms/decision-order.tsv), процедура `retention`; retention_garbled — `<sub>`, у которой любой срок (retention или alarms_retention) неверен, независимо от retention_withheld. Применить включительную границу now >= written + seconds из N1.3 retention только к закрытым бакетам (отметки консоли — не раньше самого долгого; holds сохраняют — и бакеты единиц других подсистем, чьё about называет удержанную, и бакеты неизвестных единиц; что держит строка, окно, неполное объявление и нечитаемые строки — договор удержаний common/contracts/holds.md, P/06.4 N1.5; копии зеркала — срок дерева плюс MIRROR_RETENTION_EXTRA); журнал events.removed; index.forget.

**`usage`.** Измерить тома (зонд ≤ VOLUME_PROBE_WITHIN); пульс space/volumes.

**Непрочитанный вход тома.** Если текущая проба тома дала ошибку или превысила VOLUME_PROBE_WITHIN, не подставлять прежнее измерение used/total в relieve. Не писать и не снимать просьбы free, чей need зависит от непрочитанного измерения; для непрочитанного входа прохода сохранять прежний `short`. Независимые шаги продолжаются; подтверждённое `platform/space.enabled=false` по-прежнему снимает свои просьбы и задаёт `short=0` без вычисления need. Использовать прежние диагностики `volumes_stuck`/журнала, не новое значение `settings_unread`.

**`relieve`.** `platform/space.enabled` ∧ used/total > high → для манифестов с requests.free: need = used − total·low − Σ freeing (Σ — по живым пульсам воркеров этой подсистемы на этом сервере, freeing.`<volume>` этого тома; N1.4 free_ask). **Место и просьбы освобождения.** `platform/space` не читается — шаг не исполняется (N1.4 space). Пульс воркера этой подсистемы на этом сервере не читается — need этой подсистемы не считается, её строку free-* шаг не пишет и не снимает, причина в журнал.

**Место и просьбы освобождения.** `need` > 0 → записать free-`<server>`-`<volume>` {free: need, volume, server, at}: cas "" или cas по версии строки СВОЕЙ формы (без unit И с точными server/volume текущего тома); перед записью проверить грамматику N1.4 `free_ask`. Под этим ключом строка с unit, чужими server/volume или испорченной формой → не трогать, журнал free_ask.key_taken, пропустить.

**Место и просьбы освобождения.** `need` ≤ 0 (всё нужное уже освобождается) или ниже low → удалить строку своей формы, если есть: delete с cas версии, на которой проверены отсутствие unit И точное совпадение server/volume (P/01.1). `conflict` — под ключом уже другая строка (обычная просьба или новая своя) → не трогать, журнал free_ask.key_taken.

**`mirror`.** `platform/mirror` не читается → шаг не исполняется, settings_unread: mirror (N1.4 mirror); platform/mirror.enabled → соседи = следующие copies живых по имени (живость — строка двери, N1.4 mirror); закрытые бакеты, которых у соседа нет (сумма) → PUT /mirror/`<я>`/`<путь>` с X-Sum = SHA-256 бакета; PEER_FAILS последовательных ошибок → сосед пропущен до конца этого прохода mirror.

**Проход ресурса и зависшие шаги.** Каждый шаг — своя попытка; шаг, идущий дольше PULSE_LIMIT → pass_stalled в каждом пульсе, пока он идёт.

**Гонки.** В одном проходе retain предшествует mirror; это не блокировка от другого чтения/очистки.

**Зеркало бакетов.** Копируется только целый закрытый бакет с проверенной суммой; исчезновение/неполное чтение даёт неуспешную попытку, без публикации частичной копии.

**Зеркало бакетов.** Следующий проход заново перечисляет доступные бакеты.

**Зеркало бакетов.** Хозяин и копия: копия никогда не источник, пока хозяин отвечает; `restore` (N1.4 «Bucket restore») тянет копии обратно только по слову хозяина.

**Место и просьбы освобождения.** Снятие `free_ask` и обычная просьба под тем же ключом: ресурс проверил форму на версии v и остановился; жнец снял его старую строку по ttl, консоль приняла обычную просьбу с тем же rid — у ключа версия v′; `delete` с cas v отвечает conflict, принятая просьба цела; без cas она была бы удалена без исхода.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **хранилище объектов на коробке и в кластере** — раскладка на диске (каталоги, надгробия удаления `.gone/<object-key>` — договор надгробий) и пределы размера; адрес `OBJECTS` и обращение клиента — [договор клиента хранилища объектов](../../../common/ru/contracts/object-client.md). Стенд наблюдает чтение целого объекта, выбранные `written`/сервер и `missing` по P/05-R062, P/05-R105 и P/05-R167; запись выше объявленного потолка хранилища даёт `TooLarge` по P/05-R014.
2. ~~**как ресурс узнаёт присутствие процессов**~~ — нормировано: [договор замка присутствия](../../../common/ru/contracts/presence-lock.md) `presence_lock`;
3. **политика вытеснения кэша индекса** в пределах INDEX_CACHE_BYTES (N1.3); число полос слияния и срок — норма [P/06.4](../../../06-console/ru/spec/06.4-console.norms.md) N3 «слияние», не выбор. По неизменным файлам стенд наблюдает один и тот же полный ответ запроса до и после вытеснения по P/05-R067.
4. **долгий опрос `/events/wait`**: устройство памяти наблюдений и развёртываемый предел ожиданий; формы want/ответа и профиль таймаута — N1.6, не выбор. Стенд использует объявленный действующий предел и наблюдает закрытые ответы, замещение до проверки вместимости и освобождение при разрыве по P/05-R032, P/05-R152 и P/05-R153.
5. **строка журнала**: поля сверх `sub`/`target`/`addr` договора журнала событий `journal`, роль-писатель, эпоха дерева (`e1`). Стенд читает строку через запрос событий и проверяет обязательные поля платформы и путь журнала по P/05-R018 и P/05-R049; дополнительные поля их не заменяют.
6. **потоки и чтение тела**: срок приёма зеркала, способ проверки целого тела до публикации, различение отказа до заголовков и обрыва после (пределы и сроки POST консоли — [глава 6.4](../../../06-console/ru/spec/06.4-console.norms.md) «Решает реализация» п. 3). При превышении объявленного срока приёма стенд наблюдает прежний 408; неполное тело или тело с неверной суммой не публикует новую копию и сохраняет прежнюю, начатая выдача обрывается без второго статуса по P/05-R175, P/05-R179 и P/05-R174.
7. **PULSE_LIMIT** ресурса: конечное положительное число секунд из объявленного профиля, неизменное на протяжении прогона; N1.4 задаёт измерение и исход, а не конкретное число.
8. **команды записи и порчи объекта** для приёмки (`@put object <ключ> <файл>`, `@spoil object <ключ>` словаря «Стенда»): объект с байтами файла; после порчи чтение объекта — нечитаемо: испорчены байты объекта, не его файл или каталог — дверь отдаёт объект как есть (N1.1 `door`), garbled его считает читатель.
9. **внутренний договор локального объекта**: байты файла объекта на диске (семьи `heartbeats`, `contenders` и прочие
   объекты N1.1) — свои у реализации, не публичный договор; наблюдаемое — норма (N1.1 «целиком или никак», N4 «объект:
   копия/листинг не читается» — 503). Описание и API библиотеки пишет в репозитории реализации владелец этого урока до
   кода; воркер и другие писатели семей читают только договор и API; смесь языков в одной коробке не поддерживается. Стенд не разбирает внутренний формат файла: он наблюдает публикацию целого объекта и прежний 503 при нечитаемой копии/листинге по P/05-R066 и P/05-R056.
10. **предел соединений двери ресурса** («общая полоса» N2) на все маршруты: не меньше DOOR_CONNECTIONS_MIN разом и DOOR_PER_ADDRESS_MIN на адрес (не меньше
   LONG_POLL_WAITERS + число полос слияния P/06.4 с запасом, чтобы full и busy были достижимы); сверх — 503 busy, Retry-After: 1.
11. **`PUT /mirror/<свой сервер>/…`** — копия своего бакета от себя: принять (копия в `.mirror/<свой сервер>/`) или отказать
   (400 без тела); копия от себя ничего не ломает (копия — никогда не источник, пока хозяин отвечает, N1.4 `mirror`),
   приёмка этого не проверяет.
