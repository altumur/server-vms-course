## 1. [Блокер] Максимум уровней consolem не переводится в объединение платформенных полномочий

**Место:** ADR-0099 §2 (:73–77), §5 (:110–116), Consequences (:134–137); перевод уровней — ADR-0097 §7. Цитаты: «уровень — наибольший»; «роль переводится в строки без потерь и без расширения».

**Контрпример:** камера одновременно в папках F и G одной роли. F задаёт `cam: MON`, G — `cam: ONLY_ARCHIVE`. В consolem `MON` выше `ONLY_ARCHIVE` (`ACC_LV.cam`, `index.html:6293–6295`). Настоящий `accRoleLevel` выбирает MON: живое видео, **без архива** (`ACC_LV_HINT.cam`). По переводу ADR:

| Точка | cam | live | rec |
|---|---|---|---|
| F / MON | view | view | none |
| G / ONLY_ARCHIVE | view | none | view |
| максимум по каждой подсистеме у платформы | view | view | **view** |

Платформа открывает архив, которого итоговый уровень consolem не даёт. То же между двумя ролями: человек с одной ONLY_ARCHIVE видит архив; добавили MON — `accEffIn` показывает MON без архива, но платформенное объединение сохраняет архив. Это не вопрос функций `DEVICES_SETUP`: функций нет, используются объявленные уровни камеры.

**Источник нарушения:** решение владельца «смысл как у consolem», собственный первый Decision Driver, алгоритмы `accRoleLevel`/`accEffIn`; `may` проверяет подсистемы независимо. Отображение T уровней не сохраняет максимум: `T(max(MON, ONLY_ARCHIVE)) != max(T(MON), T(ONLY_ARCHIVE))`. В модели перебраны 36 упорядоченных пар шести переводимых уровней: две ориентации этой пары расходятся.

**Предложение:** решить конфликт модели до нормирования перевода. Для буквального consolem сначала выбирать итоговый исходный уровень по его порядку, затем выводить разрешения; независимое объединение строк по `sub` этого не реализует. Другой вариант требует явного изменения смысла consolem, согласования с владельцем/продуктом и интерфейса; до него непредставимые комбинации нельзя объявлять переводимыми. Одновременно обещать нынешний порядок consolem, неизменный перевод MON/ONLY_ARCHIVE и монотонное объединение платформенных прав невозможно.

## 2. [Блокер] Исключение корня домена теряется при слиянии с умолчанием в `*`

**Место:** ADR-0099 §5 (:110–114) и §2 (:60–61). Цитата: «умолчание (`*`) … корень домена — `*`».

**Контрпример:** у роли `global.dCam = FULL`, а `folderAccess[domainId].cam = FORBID`; объектного исключения нет. Корень входит в цепочку папки, а объект вне папок проверяется по самому домену. Настоящий `accRoleLevel` возвращает FORBID: явное значение корня важнее умолчания.

Предписанная запись всех точек создаёт для одной роли и подсистемы `edit cam scope:*` от умолчания и `none cam scope:*` от корня. Обе строки — один ярус 5; наибольший ранг — edit. Камера снова разрешена. `none` не может затенить разрешение **той же области** по определению §2; перестановка строк не помогает.

**Источник нарушения:** правило наследования consolem `accRoleLevel` (`index.html:6757–6771`), первая цель ADR, различие точек в самом §5.

**Предложение:** явно нормировать устранение коллизии корня и умолчания **по исходному полю вида до перевода в строки**: заданное значение корня заменяет наследуемое умолчание, а не добавляет к нему строку. Либо сохранить различимые области/приоритеты. Добавить случай «FULL по умолчанию, FORBID в корне» и обратный; не превращать none в глобальный запрет — это нарушит остальные ничьи и роли.

## 3. [Блокер] Пропуск повреждённой строки-исключения расширяет права роли

**Место:** ADR-0099 §1 (:49–52), §2, §6; неизменённое P/08.4 Н1.3 `unreadable` (:163–164), договор `may`, `lines_in`. Цитата действующей нормы: «строка lines, которая не по форме, — пропускается … остальные действуют».

**Контрпример:** у назначенной R две строки: `admin *` и `none unit:cam/7`, обе бессрочны. До повреждения камера 7 запрещена. У второй строки портится `until` (например, вместо числа — строка) либо другое поле формы. По действующему договору вызывающий отбрасывает её **до** `may`. Функция получает одну `admin *` и разрешает камеру 7. Согласованная таблица ролей и совпавший `doc_sha256` не доказывают полноту ограничений после разбора: отпечаток может относиться именно к документу с повреждённой строкой.

Это новое нарушение предпосылки старого пропуска: удаление положительного гранта сужало доступ; удаление отрицательной либо просто более точной низкой строки повышает его. Одновременное обновление старых читателей (§6) не исправляет правило **нового** читателя. Перенос неизвестных lines байт в байт, принятый в ADR-0098, также не делает их безопасными для исполнения оставшейся роли.

**Источник нарушения:** безопасные умолчания ADR-0012; заявленная безопасность роли; P/08.4 Н1.3 и договор `may` задают конкретный допустимый путь к расширению.

**Предложение:** добавить в это приращение новый исход повреждения строк политики ролей. Когда неполная строка могла ограничивать R, оставшиеся разрешения R не исполняются. Если надёжно определить субъект нельзя — не исполняются затронутые неопределённостью роли документа; независимые проверенные прямые разрешения могут сохраниться. Передавать признак неполноты до `may`, а не терять его при фильтрации; согласовать 503 с уже принятым исходом нечитаемой таблицы ролей ADR-0098 §4. В Confirmation — повреждённый none и повреждённый более точный view под admin, не только неизвестная таблица целиком.

## 4. [Блокер] Нечитаемые метки/about позволяют обойти исключение той же роли через `*`

**Место:** ADR-0099 §2 (:65–76), §3 (:88–91). Цитата: «Ярус 1–2 — без чтений». Защита от неопределённости задана для членства папок, но действующий договор сторожевой (:115–117) для `labels:` и `unit:` about требует строку единицы: если она нечитаема, «этот грант не покрывает … проверяется следующий».

**Контрпример А:** R содержит `edit *` и `none labels:private`; у U метка private. При читаемой строке U — deny на ярусе 4. Строка U повреждена или чтение не подтверждено: по сохранённому `scope` отрицательное labels не покрывает, ярус 4 пуст, ярус 5 даёт edit. Добавление чтения папок не поможет — folder-строк в R нет.

**Контрпример Б:** R содержит `edit *` и `none unit:cam/7`; проверяется det/5 с about cam/7. Чтобы узнать about по одному имени det/5 из пути, нужно прочитать строку det/5. При её нечитаемости старое правило не покрывает about-строку, и снова действует edit `*`. У `unit:` самой единицы такого чтения действительно нет; объединять оба случая в бесплатные ярусы 1–2 нельзя.

**Источник нарушения:** договор сторожевой `scope`, ADR-0012, собственное обоснование §2 (:75–76): неизвестность более точного исключения не должна превращаться в право общего яруса. Обоснование верно и для ярусов 2/4, а не только 3.

**Предложение:** определить неопределённое покрытие для всех ярусов с чтением. Если более точная потенциально ограничивающая строка роли не может быть проверена, не переходить к общему разрешению этой роли. Независимые роли/прямые строки судить отдельно. Во входе `may` различить отсутствие about, пустые метки/цепочки и неизвестность чтения; пересмотреть цену яруса 2. Confirmation — оба приведённых сбоя, а также работа независимого прямого разрешения.

## Остальная проверка и вопросы Архитектору

| Область чеклиста | Результат |
|---|---|
| Порядок ярусов, ничьи, несколько членств | Определены; self → about → ближайшая по каждой цепочке → labels → *. Ничьи одного яруса решает max. Запрет одной роли не глобален. Контроли модели проходят. |
| Старые прямые строки и читатели | Одно приращение ролей/none/ярусов закрывает старого читателя с неизвестным subject; прямые строки сохраняют объединение. Повреждённые строки нового читателя — находка 3. |
| Сроки | Назначение и строка действуют совместно; истёкшее исключение явно снимается. Расширение после его срока — объявленная политика, новой находкой не считается. Кэш назначения должен сохранять until и проверять now, как ADR-0098. |
| Цепочки, стоимость, кэш | Только живые цепочки, parent неизменен (ADR-0096). Для U различных единиц с about и F различных папок — до U чтений memberof и F чтений папок за запрос; результаты общие для ролей. Кэш членства между запросами запрещён ADR-0097. Цена about — находка 4; численные пределы остаются делом нормы. |
| Гонки записей | Стражи memberof при разрешении по общему ярусу с folder-строками нужны и заявлены; подтверждённое отсутствие тоже должно иметь стража отсутствующей строки. Окно удаления предка уже принято ADR-0097, повторной находкой не объявляется. |
| Лента и модуль консоли | Reset охватывает роли с folder-строками; быстрый view* роли запрещён при точных строках в проверяемой sub; сервер остаётся судьёй. Подсказке нужны та же неизвестность и те же цепочки, не пустые массивы вместо ошибок. |
| Приёмка и перенос в нормы | В плане названы владельцы и векторы; исправить перечисленные исходы до переноса. Пока нормы не обновлены, само их расхождение с proposed ADR находкой не считается. Здесь показаны конкретные несовместимые правила, которые план оставляет действовать. |

Вопросы для решения:

1. Что приоритетнее при конфликте находки 1: точный нынешний порядок consolem или монотонность полномочий при добавлении роли? Нынешний MON не включает архив ONLY_ARCHIVE. Ответ нужен для модели, а не только для частоты исключений у продукта.
2. Как передаются неизвестные метки/about/цепочки и неполный документ роли в `may` и подсказку P/07? Например, пустая цепочка и неизвестное членство имеют разные результаты; одного массива chains для обоих недостаточно. Это часть исправления 3/4, не новая находка.
