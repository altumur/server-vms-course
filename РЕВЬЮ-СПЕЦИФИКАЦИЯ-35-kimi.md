## Находки

### М10/10 (проявление), корень — зависимые М10/2–3

**K35-01 — существенная. Загрузчик не отвергает объявление `unit.fields` с именами платформенных элементов строки и полей; такие поля затем пишутся в строку и попадают в снимок, нарушая форму строки и конверт шарда.**
Место: `М10_Platform/spec/02-the-spec-and-the-strict-loader.norms.md:110–125` (правила Н1.3 — нет запрета имён платформенных полей) против `М10_Platform/spec/03-units-slots-epochs-lease.norms.md:55–57` (`deleted: "true"` — «только у надгробия; иначе элемента нет»), `:76` (`platform_fields: [id, revision, worker, placement, epoch, phase, observed_revision]`, «клиент не задаёт; в строке единицы только id и revision») и `М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md:44–46` (по умолчанию снимок берёт все поля, кроме *_secret/blob/server).
Что не так: цикл 34 закрыл соседние коллизии имён (rows=cluster/worker/ts, bytes+blob, server в snapshot, held_by/garbled/name у таблиц), но не имя объявляемого поля единицы. Для объявленного поля с платформенным именем: (а) оно не отвергается при загрузке; (б) при создании единицы состав клиентских полей пишет его значение/умолчание в строку (03: «При создании состав клиентских полей определяется для каждого поля спеки»; absent-правила Н1.2 покрывают только inherit и json null); (в) по умолчанию оно попадает в снимок.
Контрпример (минимальный): спека `unit: {rows: counters, id: name, fields: {name: {type: string, required: true}, deleted: {type: string, default: ""}}}` грузится по М10/2 (ни одно правило не отказывает); `deleted` не входит в platform_fields, поэтому отказ «a client may not set» не действует; создание `c1` пишет строку с элементом `deleted: ""` — прямое нарушение «иначе элемента нет» (03 Н1.2), и читатель, проверяющий присутствие `deleted`, принимает живую единицу за надгробие. Второй случай: поле `worker` — в platform_fields, клиенту запрещено, но умолчание пишется в строку, а снимок по умолчанию включает его: в строке шарда `[{id, revision, <поля snapshot:>, worker, server}]` (10 Н1.3) два источника `worker` — авторского и вычисляемого, какой побеждает, не определено (та же коллизия, из-за которой `server` запретили).
Основание: ADR-0080 (нормы не противоречат друг другу на допустимом входе; закрытые списки полны); ADR-0082 доп. 23 (класс коллизий имён закрывался именно сужением на загрузке — сиблинг пропущен).
Рекомендация: добавить в правила М10/2 Н1.3 отказ `refused:value` для `unit.fields.*` с именами из platform_fields и служебных элементов строки (`deleted`), симметрично запрету `server` в snapshot; либо явно исключить такие поля из записи строки и снимка в М10/3/М10/10.

### Зависимая М10/2

**K35-02 — мелкая. Маршрутный комментарий `snapshot` в Н1.2 не обновлён после запрета `server`.**
Место: `М10_Platform/spec/02-the-spec-and-the-strict-loader.norms.md:62–63` («отсутствует = все, кроме секретов и blob») против `:123` (новое правило: «нет snapshot — server исключается вместе с секретами/blob»).
Что не так: читатель маршрутного комментария получает прежний дефолт без исключения `server`.
Рекомендация: дополнить комментарий :62–63 словами про `server`.
