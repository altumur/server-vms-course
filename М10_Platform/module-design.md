# М10 Платформа: хранилище и спека — проектная записка

*Написано 14 октября 2026 («Архитектор», ADR-0082; дальше ведёт сессия «Спецификация»). О том, как модуль нарезан на уроки-спецификации по ADR-0080 и чем он отличается от прежних М10A и М11_Cluster.*

Решения о самой системе здесь не пересматриваются: они в `decisions/` (ADR-0001 граница, 0002 без хуков, 0003 без совместимости, 0012 строгий загрузчик, 0013 ключ платформы, 0014 чтение дверью, 0074 книги и `guard`). Записка — о форме изложения: что считается уроком, что нормой, что повествованием, что приёмкой.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Что такое урок | **Одна норма с приёмкой.** Урок нормирует одну вещь (словарь операций, спеку и загрузчик, слот, …), и у каждой его нормы ДОЛЖЕН есть сценарий приёмки или пометка «проверяется чтением» с причиной | ADR-0080 доп. 4: единица модуля — спецификация, единица урока — одна норма с приёмкой. Прежний урок был «один файл кода»; файл — дело реализации |
| Из чего пишется | **Из решений и прежних лекций; код — свидетель.** Старшинство источников: ADR и формы «до кода» в них → прежние уроки (повествование) → Go-продукт как дошедшая реализация (читается, не канон) → Python курса (отстаёт). Расхождение Go с ADR — находка «Архитектору», в норму не идёт | ADR-0082 п. 1 |
| Нормативное и повествование | **Лекция и нормы разделены по файлам**: повествование — `<NN>-<имя>.md` в каталоге модуля, канон — `spec/<NN>-<имя>.norms.md`. В каноне заголовки `## Н1 Форма` … `## Н5 Приёмка` плюс `## Н0 Словарь слов` во всех уроках: определяется в уроке 1, в остальных ссылка. Нормативные блоки пользуются словами ДОЛЖЕН / НЕ ДОЛЖЕН / СЛЕДУЕТ / НЕ СЛЕДУЕТ / МОЖЕТ; лекция требований не добавляет | ADR-0080 доп. 2, 3 и 2026-10-15 |
| Нотации | «Форма» — схема YAML в стиле спек подсистем; «Двери» и «Отказы» — отдельный `spec/<NN>-<имя>.api.openapi.yaml` (OpenAPI 3.1, один документ на урок с HTTP, коды закрыты; без HTTP состав согласуется в ADR — М10/5, теперь P/03, без OpenAPI по ADR-0082 доп. 13); «Проход» — псевдокод только на словаре операций хранилища урока 1, с подразделом «Гонки» у каждого прохода; «Приёмка» — таблицы сценариев в общих данных | ADR-0080 доп. 1, 2 и 2026-10-15 |
| Где приёмка | **`Source/tests/testdata/acceptance/М10_Platform/<NN>/`**: `scenarios.tsv` (дано — действие — ожидаемые байты, через двери), `corrections.tsv` (журнал исправлений ИИ). Прогон — «Приёмка» по дверям любой реализации; продукт забирает каталог `scripts/sync-course.sh` | ADR-0080 доп. 1, ADR-0082 п. 3 |
| Код в уроке | **Кода реализации нет.** Псевдокод прохода — да; Python или Go — нет, даже цитатой. Что хочется показать кодом, либо норма (тогда псевдокод), либо «решает реализация» (тогда ссылка на описание реализации) | Урок на трёх языках из одного текста (ADR-0080): код одного языка в норме — норма для одного языка |
| «Решает реализация» | Помечается словами **«решает реализация»** с перечнем того, что реализация обязана назвать в своём описании (ARCHITECTURE продукта, записка курса). Непомеченное — норма для всех | ADR-0080 доп. 3 п. 2 |
| Сквозной пример | **`testsub` и `testsub2`** (`Source/tests/testdata/`, общие с продуктом), не `counter` из прежнего текста | ADR-0080 доп. 4: пример должен грузиться обоими загрузчиками |
| Кластер | **Не отдельный модуль**: реплицированное хранилище — второй вариант развёртывания тех же норм. В уроке 1 словарь один на файлы, память и реплицированное хранилище; урок 11 — платформа на коробке и на кластере | ADR-0080 доп. 4: прежний М11_Cluster растворяется в М10 |
| Прежние уроки | **Удаляются по мере переноса, не раньше последнего урока, который забирает их содержимое.** Прежний урок, часть которого уже нормирована, получает в первой строке пометку «нормативно: М10/N», остальное в нём живёт до своего урока. Таблица соответствия — ADR-0080 доп. 4. Исполнено 2026-10-14 по слову владельца: `М10A_Platform/` и `М11_Cluster/` удалены целиком; записи о решениях «Оркестратор как форма поставки» и «Тонкий шов против провайдера» — в `_notes-ru/` | ADR-0003: двух версий одной нормы не бывает; но прежний урок несёт несколько норм, и рвать его по частям дороже пометки |
| Имя нормы и дельта | **Норма = строка чеклиста готовности с id `<модуль>/<урок>-NN`**; номер не переиспользуется, снятая норма остаётся строкой «снята: `<ADR>`». Решение владельца, меняющее урок, пишется в ADR дельтой `ADDED/MODIFIED/REMOVED/RENAMED` по этим id, «Спецификация» вливает её в урок до следующего окна по нему; невлитые дельты — долг в `ХОД-Спецификация.md` | ADR-0080 доп. 6, ADR-0081 поправка 2 (по сопоставлению с OpenSpec) |
| Форма таблицы приёмки | **По двери урока.** Дверь HTTP — `scenarios.tsv` (`scenario step request expect`, урок 1); загрузчик — `verdicts.tsv` (`case verdict`, файлы в `cases/`); форму и раннер описывает README каталога урока | Урок 2: дверь загрузчика — не HTTP, сценарий — файл и один ответ |
| Двери консоли в уроке | **Те, что зовёт общий модуль консоли** (контракт `КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`, один модуль у всех реализаций, ADR-0005): пути, методы, query и тела берутся оттуда, не сочиняются | М10/4: Н2 выдумал `/drain` с телом и `/decommission/<s>`, «Сборка» нашла по модулю |
| Что знает читатель | **Повествование опирается только на то, что уже введено.** Пример или история из более позднего урока в урок не входит: одна фраза «чем это оборачивается — урок N» (как «урок 6» у стража), а рассказ — в том уроке, где слова уже знакомы | Владелец 2026-10-14 по образцу М10/1: рассказ о продлении слота в уроке 1 не читается — читатель ещё не знает воркеров и слотов |
| Что читает «Архитектор» | Эту записку до урока 1; нормативные дифы каждого урока до следующего (ADR-0081 п. 7) | ADR-0082 п. 4 |

## Форма урока

Порядок сопровождения формы — проектный [lesson-spec](../skills/lesson-spec/SKILL.md):
[таблица связанных изменений](../skills/lesson-spec/references/change-map.md),
[ручной чеклист](../skills/lesson-spec/references/review-checklist.md), затем шаблоны и структурная
проверка. Инструкция не заменяет канон уроков; примеры М10/1–2 учитывают прогоны 17–20.

Лекция остаётся рядом с остальными лекциями модуля; у файлов спецификации общий префикс с её именем
(ADR-0080, уточнение владельца 2026-10-15):

```text
М10_Platform/
  <NN>-<имя>.md
  spec/
    <NN>-<имя>.norms.md
    <NN>-<имя>.api.openapi.yaml
    <NN>-<имя>.README.md
```

Лекция `<NN>-<имя>.md`:

```
# Урок N — <норма>
Модуль, что получит читатель, время.
## Зачем этот урок            — повествование
## Цели и не-цели             — обязательный подраздел повествования (ADR-0080 доп. 3)
## Что нужно знать заранее    — ссылки на уроки, чьи слова используются
## <повествование>            — сколько нужно, с примерами на testsub
```

Канон `spec/<NN>-<имя>.norms.md`:

```
## Н0 Словарь слов            — в каждом уроке; определён в уроке 1, в остальных ссылка
## Н1 Форма                   — схема YAML
## Н2 Двери                   — ссылка на <NN>-<имя>.api.openapi.yaml
## Н3 Проход                  — псевдокод на словаре урока 1; у каждого прохода «Гонки»
## Н4 Отказы                  — закрытый список: причина → код → тело → что делает вызывающий
## Н5 Приёмка                 — ссылка на каталог сценариев и их перечень
## Решает реализация          — перечень с тем, что реализация обязана назвать
## Чеклист готовности         — нормы ДОЛЖЕН → сценарии (или «проверяется чтением: причина»)
## Соответствие прежним урокам
```

`spec/<NN>-<имя>.README.md` задаёт инструкцию реализации: приоритет файлов, что создать, порядок работы,
ловушки языков, критерии готовности и действия при расхождениях. Он следует канону и не вводит новых норм.
Образец — урок 1; остальные уроки переводятся по одному после проверки его формы ревью либо по отдельному
поручению владельца. Урок 2 переведён по такому поручению 2026-10-15 отдельно от прогона 17 по уроку 1.
После закрытия его находок владелец включил в прогон 18 оба урока (ADR-0082 доп. 5).

Урок 3 переведён по отдельному поручению владельца 2026-10-15: четыре файла с префиксом
`03-units-slots-epochs-lease`, прежние 18 id и 11 сценариев / 44 шага сохранены. При переводе
дополнены схемы ответов Н2; по уточнению владельца одновременно доведены ответы уроков 1–2
(ADR-0082 доп. 11). Перенос норм выделен отдельно от дополнения контрактов и правил приёмки.

## Открытые вопросы

1. **Линтер OpenAPI и схем.** Нотация закреплена, инструмент — на образце (ADR-0080 доп. 1). Предложение: проверка в тесте документов курса, что каждый файл `*.api.openapi.yaml` (а до переноса — блок `yaml openapi` урока) разбирается и его коды ответов совпадают со списком «Н4 Отказы»; выбор библиотеки — «Спецификация».
2. **Прогон приёмки.** Формат `scenarios.tsv` задан уроком 1; исполнитель (сессия «Приёмка», ADR-0082 п. 5) ещё не заведён — до него сценарии проверяются чтением и прогоняются руками над продуктом.
3. **Пометки в прежних уроках** — решение этой записки, не ADR; «Архитектор» закрепляет его поправкой к ADR-0080 вместе с форматом образца, если владелец согласен.
