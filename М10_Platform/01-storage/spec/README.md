# М10/1 — инструкция для реализации

Этот файл — для агента (или человека), который пишет код по уроку. Объяснение «зачем» — [`../lecture.md`](../lecture.md).

## Задача

Реализовать хранилище строк урока М10/1 на языке `<LANG>` так, чтобы оно прошло приёмку Н5 [`norms.md`](norms.md) через дверь (HTTP на unix-сокете).

## Входы и их приоритет

| Файл | Роль | Приоритет |
|---|---|---|
| [`norms.md`](norms.md) | нормы: что ДОЛЖНО быть | 1 — канон |
| [`api.openapi.yaml`](api.openapi.yaml) | форма HTTP-запросов и ответов | 2 — при расхождении с `norms.md` прав `norms.md` |
| `Source/tests/testdata/acceptance/М10_Platform/01/` (`scenarios.tsv`, `README.md`) | приёмка | 3 — проверяет `norms.md`, не дополняет его |
| [`../lecture.md`](../lecture.md) | контекст, мотивация | не норма; требований из неё не выводить |

Правила:

- Не добавлять поведения, которого нет в `norms.md`. Не «улучшать» семантику: нормализация ключей, сравнение версий на больше/меньше, повтор при `guard`, новые коды и виды отказов — запрещены.
- Если `norms.md` молчит или противоречит себе — не угадывать. Записать вопрос в `QUESTIONS.md` реализации со ссылкой на раздел и выбрать самое консервативное поведение (отказ, а не допущение). Открытых вопросов у урока на 2026-10-15 нет: все известные закрыты в нормах.
- В коде ссылаться на нормы: комментарий `// norms Н3 записать, шаг 7` или `// М10/1-10` у места, которое исполняет норму.

## Что создать

1. **Ядро хранилища** — четыре операции Н3 (прочитать, перечислить, записать, удалить) за языковым интерфейсом. Отказы — типизированные значения с полями `kind`, `key`, `index`, `size`, `limit` (Н4), не строки и не общие исключения.
2. **Хотя бы одно хранилище данных**: в памяти и/или на файлах. Оба СЛЕДУЕТ: память — для тестов, файлы — для коробки без группы. Группа (реплицированный журнал) — урок 11.
3. **HTTP-сервер на unix-сокете** по [`api.openapi.yaml`](api.openapi.yaml), который переводит отказы ядра в коды Н4.
4. **Проверка прав** — точка расширения `authorize(caller, action, key) → allow | deny`, `action ∈ {read, write}` (удаление — запись). Кто такой `caller`, говорит сокет (урок 6). Политика — урок 6; для приёмки достаточно «полные права на префикс `acc/`, иначе deny».
5. **Описание реализации** (ARCHITECTURE) — ответ на каждый из семи пунктов «Решает реализация». Пункт без ответа — реализация не готова.
6. **Прогон приёмки** через дверь; реализации с API в процессе СЛЕДУЕТ гонять те же сценарии и через него (Н5, М10/1-21).

## Порядок работы

1. Прочитать `norms.md` целиком. Выписать в описание реализации черновые ответы на «Решает реализация».
2. Модель данных Н1: проверки `key`, `items`, `cas`, `guard`, `id` — отдельными чистыми функциями. Это первые тесты.
3. Хранилище в памяти: проходы Н3 строго по шагам, с тем же порядком проверок (страж раньше CAS).
4. HTTP-слой и отображение отказов Н4.
5. Прогнать сценарии 01–22. Каждое падение — сверить с `norms.md`, исправить **код**.
6. Хранилище на файлах: неделимость, версии, барьеры долговечности, повреждённая строка (`Row.unreadable`). Прогнать сценарии снова.
7. Пройти чеклист М10/1-01…23; у пунктов «проверяется чтением» указать в описании реализации, где в коде это обеспечено.

## Ловушки, которые зависят от языка

Места, где идиоматичный код на многих языках нарушает норму:

| Норма | Ловушка | Как правильно |
|---|---|---|
| порядок ключей перечисления — по байтам (Н3) | Java, C#, JS, Kotlin сортируют строки по UTF-16; `localeCompare` — по локали | сравнивать байты UTF-8 |
| вес и длина ключа — в байтах UTF-8 (Н1) | `len()` / `.length` считают символы или UTF-16 units | длина кодировки UTF-8 |
| версия непрозрачна (Н1) | разбор в число и сравнение `>` | хранить и сравнивать как строку; внутри хранилища счётчик МОЖЕТ быть числом |
| items — копия (Н3) | возврат ссылки на внутренний словарь | глубокая копия на входе и выходе |
| неделимость (Н3) | проверка и запись под разными блокировками; async-разрывы между шагами | шаги после «далее одной операцией» — в одной критической секции |
| страж раньше CAS (Н3) | проверка в порядке полей запроса | строго: страж, потом CAS |
| отказ не цитирует присланное (Н4) | сообщения вида `invalid value "<тело>"` из JSON-библиотек | своё сообщение, без присланных данных, кроме ключа |
| тело сверх предела → 413 (Н4) | фреймворк отвечает своим 413/400 без тела `Fault` | ограничить чтение тела самим и вернуть `Fault` |
| неизвестный маршрут → 404 badrequest (Н2) | стандартная 404-страница фреймворка | свой обработчик с `Fault` |
| `cas: null` ≡ поля нет (Н1) | JSON-библиотека различает null и отсутствие или путает `""` с null | три состояния: нет/null, `""`, версия |
| `items` у delete не читается (Н2) | строгий разбор тела отвергает лишнее поле | разбирать `Cmd` терпимо к `items` у delete |
| долговечность («Решает реализация» п. 3) | запись без fsync; rename без fsync каталога | fsync файла и каталога до ответа |

## Готово, когда

- [ ] сценарии 01–22 зелёные через дверь;
- [ ] (СЛЕДУЕТ) те же сценарии зелёные через API в процессе у каждого хранилища данных;
- [ ] описание реализации отвечает на все семь пунктов «Решает реализация»;
- [ ] каждый пункт чеклиста М10/1-01…23 либо закрыт сценарием, либо в описании указано место в коде;
- [ ] `QUESTIONS.md` пуст или каждый вопрос передан автору норм.

## При расхождении кода и норм

| Ситуация | Что править |
|---|---|
| сценарий красный, `norms.md` однозначен | код |
| `norms.md` неполон или противоречив | не обходить в коде; вопрос в `QUESTIONS.md`; правку делает автор норм, затем код |
| сценарий противоречит `norms.md` | дефект приёмки; вопрос автору; код — по `norms.md` |
| ИИ ошибся и был исправлен человеком | строка в `corrections.tsv` рядом со сценариями (ADR-0080 доп. 1) |
