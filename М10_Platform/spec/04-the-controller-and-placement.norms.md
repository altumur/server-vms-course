# М10/4 — Контроллер и размещение: нормы

Канон урока. [Лекция](../04-the-controller-and-placement.md); [инструкция](04-the-controller-and-placement.README.md).

## Н0 Словарь слов

ДОЛЖЕН, СЛЕДУЕТ, МОЖЕТ — по [общему словарю](01-storage.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](01-storage.norms.md#время-в-строке): `<sub>/placement/<id>` — `at`; `platform/doors/<сервер>` — `since`, `at`; `platform/drain` — `at`; `platform/decommission/<сервер>` — `at`; `<sub>/decommissioned/<сервер>` — `asked_at`, `at`; `<sub>/controller/placement_intent` — `at`; предложение слота — `offered_at` (урок 3); объект `<sub>/controller/pass` — `at`, `last_success`.

### Н1.1 Строки контроллера

```yaml
<sub>/placement/<id>:                     # решение; писатель — контроллер
  worker:    <имя воркера> | ""           # "" — не размещена; при active intent действует общее решение Н1.5
  reason:    <строка для человека>        # непустая; грамматика — Н3 «причина»
  at:        <стенные секунды контроллера>
  rev:       <десятичное целое ≥ 1>       # +1 на каждую запись
  spec_rev:  <ревизия спеки, под которой принято решение>   # ДОЛЖЕН у реализации с хранением спеки в строке (урок 2)
<sub>/workers/<имя>:                      # назначение; производное от строк размещения
  units:     <список id по правилу списка урока 3 (через запятую, иначе массив JSON)>   # отсортирован
  rev:       <десятичное целое ≥ 1>       # +1 только при изменении списка
<sub>/policy:                             # писатель — консоль; читает контроллер
  servers:   shared | distinct            # иное значение или ключ при чтении — умолчание спеки; при записи — отказ
platform/servers/<сервер>:                # писатель — консоль (ADR-0026)
  labels:    <метки через запятую>        # "" — ни одной; строка побеждает метки узла
platform/doors/<сервер>:                  # писатель — ресурс сервера (ADR-0045)
  url: <адрес двери>; since: <момент старта>; at: <момент последней отметки, каждые 15 с>
platform/drain:                           # писатель — консоль; одна строка на кластер
  server: <сервер>; at: <момент>
platform/decommission/<сервер>:           # писатель — консоль
  by: <кто>; at: <момент>; why: <слова>; gone: "true"?   # gone — подтверждение «сервера нет», когда ресурс никогда не слышали
<sub>/decommissioned/<сервер>:            # писатель — контроллер; снимается при отзыве запроса
  asked_at, at:  <стенные секунды запроса консоли и отметки контроллера>
  slots, units, holds:  <имена отданных слотов, id снятых единиц, места удержаний — по правилу списка урока 3; "" — ни одного>
                 # имена, не числа (сверка python и go 2026-10-18)
<sub>/slots/<prefix>-<n>  (предложение):  # писатель — контроллер, только записью с cas ""
  holder: ""; until: "0"; released: "false"; gen: "0"; offer: <набор меток>; offered_at: <момент>
```

### Н1.2 Отчёт прохода

Объект `<sub>/controller/pass`, пишется в конце каждого прохода; читают консоль (ряды `<sub>_reconcile_last_pass_age_seconds`, `<sub>_reconcile_pass_seconds`, `<sub>_reconcile_failures`, `<sub>_units_unplaced`, `<sub>_units_diverged` — урок 9 Н3 «/metrics — текст») и воркеры (`names_given`, `hung_move_after` — урок 3). Поля ниже ДОЛЖНЫ быть; реализация МОЖЕТ добавлять свои счётчики.

```yaml
pass:
  at:                   <момент конца прохода>
  ok:                   bool;  error: <текст последней ошибки или "">;  failures: <число>;  last_success: <момент>
  seconds:              <длительность прохода>
  spec_rev:             <ревизия спеки контроллера>;  spec_behind: <строк, решённых более новой спекой>
  names_given:          {<имя слота>: <версия строки слота, при которой имя отдано>}
  hung_move_after:      <секунды предела зависания, действующего у этого контроллера>
  fates:                {<имя>: {fate, server, why, rev, since}}   # только занятые неотданные слоты: holder непуст, released
                        #   не true, не предложение с gen 0; since — момент входа слота в этот fate на часах контроллера
                        #   (смена fate — новый since), не первый взгляд на слот (сверка python и go 2026-10-18)
  diverged:             <назначений, исправленных sync>
  unplaced:             <единиц без воркера, кроме снятых с эксплуатации>
  garbled:              <строк единиц, которые не читаются>
  reach_moves_total, slots_released_total, unplaced_deleted_total, servers_decommissioned_total,
  workers_hung, workers_hung_moved_total, workers_unsure_moved_total, name_conflicts: <числа>
  unplaceable:          {<id>: <why>}   # единицы без места этого прохода и непустая причина; из него консоль берёт why
                        #   /unplaceable и reason 404 /where/<id> у неразмещённой (Н2.2)
  short:                # только при placement.offers: true
    - {labels: [<метки>], units: <ждущих единиц веса>, workers: <нужно запасных>, groups?: <ждущих групп>,
       offered: <предложено>, withheld?: <слова, почему не предложено>}
```

### Н1.3 Ключи размещения и их смысл

Форма ключей — урок 2 (Н1.2). Здесь — что каждый значит для контроллера и умолчание.

| Ключ | Смысл | Умолчание |
|---|---|---|
| `capacity: {from, default, unit_mb, base_mb}` | ёмкость — поле пульса `from`; поля нет — `default`; поле есть, но не число (слово, булево) — воркер не принимает новых единиц, пока пульс не исправлен, уже назначенные не снимаются, причина — в отчёте прохода, поле `fates.<воркер>.why` (Н1.2): «capacity is not a number» (как вес, R25); `unit_mb`/`base_mb` — бюджет памяти воркера при старте (урок 5) | `from: capacity`; `default` обязателен |
| `headroom: {from}` | запас — поле пульса; контроллер суммирует по живым | `from: headroom` |
| `weight: {field, default}` | вес единицы — `int`-поле строки ≥ 1, при отсутствии поля — weight.default ≥ 1; неверное присутствующее значение не заменяется default: строка единицы нечитаема (`garbled` отчёта прохода), единица не размещается и не снимается, причина — в `unplaceable`; нагрузка = Σ весов (ADR-0078) | без ключа — вес 1 у всех |
| `constraint` | `none` \| `labels-subset`: метки единицы ⊆ меток воркера. Метки единицы — её поле `labels` типа `list` (поля нет — пустой набор, ограничение выполнено); метка — по азбуке Н2.1; метки воркера — строка `platform/servers/<сервер>` или метки узла | `none` |
| `tie_break` | `most-free-capacity` — единственное слово | оно же |
| `servers` | `shared` \| `distinct`: при `distinct` на одно место нести единицы может один воркер — с наибольшей нагрузкой, при равенстве первый в слотовом порядке М10/3 Н1.4; остальные простаивают | `shared`; строка `policy` переопределяет |
| `place_by` | что считать местом при `distinct`: сервер или поле пульса | `server` |
| `places: {table, where, server_field, lease}` | таблица мест и строка удержания `<sub>/holds/<место>` (урок 5 Н1.3); `lease: strict` — строгое место | — |
| `spread_by` | поле: две единицы с одним значением не на одном сервере; отсутствующее или пустое значение в разведении не участвует — единица без значения не ограничивает и не ограничивается (пара к `group_by`: пустое — не группа; сверка python и go М10/3–5, решение «Архитектора») | — |
| `group_by: {field, cut_at}` | группа — одно значение поля (для `url` — хост по `cut_at: host`); размещается только целиком на одном воркере (ADR-0011). Значения нет, оно пустое или не читается (у `url` — нечитаем по уроку 3 Н4), у `url` хоста нет (`schemes.<s>.none` урока 2 Н1.3, в том числе при `host: path`) — единица не в группе и размещается одна; общей «группы без значения» нет (сверка python и go 2026-10-18) | — |
| `near: {sub, by, of, prefer}` | предпочтение: рядом с держателем единицы соседней подсистемы, на которую ссылается `by`; `prefer` — порядок среди нескольких; сосед берётся из каталога спек | `none` |
| `home` | предпочтение: поле строки, называющее сервер (предпочтительны воркеры, чей `server` равен значению этого поля у первого члена в порядке UTF-8), или `near` — дом у соседа; следовать может лишь одна сторона пары | — |
| `affinity: {field, table, server_field, strict}` | фильтр: место из таблицы, которое принимает единицу; `admits: false` не берёт никого; связывающая строка ведёт единицу только на своё место. Место единицы — строка `table`, которую называет её `field` (значения нет или строки нет — affinity не действует). `strict` — предикат, который выбирает связывающие строки: строка связывающая, когда каждое поле `strict` равно значению или входит в список значений (И по полям, ИЛИ по списку). Связывающая строка ведёт единицу только на свой сервер (`server_field`); несвязывающая — предпочтение этого сервера, не фильтр. `admits` проверяется у фактического места единицы (журнал cammeta-go, урок 8 № 2) | — |
| `requires` | `none` \| `resource`: при `resource` воркер пригоден, только пока ресурс его сервера не молчит | `none` |
| `offers` | `true` — контроллер считает нехватку и предлагает имена запасным | `false` |
| `retire_when: {field, in}` | единица со значением поля из `in` не размещается и снимается с причиной — значением | — |
| `rebalance: {dead_band}` | перебалансировка по запросу: пока разброс нагрузки меньше — не двигать | `0.10` |
| `unplaced: {delete_after}` | строку единицы, которую никто не держит дольше N с по часам контроллера, контроллер удаляет (ADR-0067); снятая по `retire_when` — тоже: её никто не держит. Свои строки единиц МОЖЕТ удалять и воркер подсистемы по ключу `worker.deletes` — удаление с `cas` без права записи (ADR-0067 доп. 2026-10-17; учебного потребителя пока нет — долг в ХОД-Спецификация) | без ключа — никогда |

### Н1.4 Сроки и состояния судьи

```yaml
constants:
  LOST_AFTER:       45    # с; свежесть пульса и запас после SLOT_TERM наблюдения неизменной версии слота
  HUNG_MOVE_AFTER:  900   # с; возраст наблюдаемой версии слота до предела hung/unsure/wait; из окружения контроллера, публикуется в отчёте
  ALIVE_EVERY:      15    # с; ресурс переписывает at своей двери
  REACH_BUDGET:     10    # единиц за проход на переезды по достижимости; из окружения
  HOME_BUDGET:      1     # единица за проход на переезды домой
  OFFER_GRACE:      90    # с; взятое предложение без пульса считается «запускается»
resource_state:     # ресурс сервера — одно определение для всех наблюдателей (контроллер, консоль урока 9), по их
                    # монотонным часам; «менялся» — смена версии на глазах наблюдателя (урок 3 Н1.4), первый взгляд — свежий;
                    # правила — по порядку, первое совпавшее (сверка python и go 2026-10-18)
  live:         пульс ресурса читается и менялся в последние LOST_AFTER; нечитаемый пульс жизни не подтверждает, и его
                смена — тоже
  unreachable:  пульс не live (в том числе нечитаемый), строка двери platform/doors/<s> менялась в последние LOST_AFTER —
                ресурс есть, пульсов нет
  unknown:      наблюдатель не видел ни пульса, ни строки двери ни разу
  silent:       иначе; исключает и двигает только silent
process_presence:   # что ресурс говорит о процессе воркера: вывод урока 8 Н1.4 `presence` по ключу <sub>/<имя слота> своей подсистемы;
                    # только из пульса ресурса в состоянии live: устаревший пульс со словом runs присутствия не даёт, и слот
                    # судится по resource_state (сверка python и go 2026-10-18)
  runs | gone | unlisted | unknown   # unknown — неподтверждённое чтение; silent — только состояние ресурса выше
fate:               alive | wait | hung | hung_moved | unsure | unsure_moved | move | release
NAME_FATES:         [move, hung_moved, unsure_moved, release]   # + wait за пределом HUNG_MOVE_AFTER
MOVED_FATES:        [move, hung_moved, unsure_moved]
```

### Н1.5 Допуск размещения между контроллерами

У подсистемы один изменяющий размещение контроллер в каждый момент. Право задаётся строкой,
а не наличием процесса: поздние записи прежнего держателя отсекаются guard хранилища.
Новые служебные строки принадлежат роли контроллера; читают их также читатели размещения.
Двери хранилища и словарь операций остаются уроком 1.

```yaml
<sub>/controller/placement_turn:         # строка; писатель — контроллер
  holder: <уникальная метка попытки захвата> | ""  # новая попытка не повторяет метку прежней
  spec_rev: <ревизия спеки>              # не убывает; старый контроллер не захватывает новую ревизию
<sub>/controller/placement_intent:       # строка; после создания не удаляется
  state: active | idle
  spec_rev: <ревизия принятого решения>
  # только при active:
  members: <JSON-массив всех id решения; уникальны, отсортированы>
  target: <имя воркера> | ""             # одна цель всей группы; "" — снять размещение
  reason: <непустая причина>
  at: <стенные секунды принятия решения>
constants:
  TURN_TERM: 45                         # возраст неизменной версии на часах претендента
  TURN_RENEW: 10                        # продление между операциями; срок своего запроса — монотонный
```

Нечитаемая строка turn/intent — отказ изменения размещения с failures, не пустая строка. Строка intent не по форме
(`state` не `active`/`idle`; у active нет `members`, `target`, `reason`, `at` или они не по форме выше) — нечитаемая:
контроллер — отказ с failures, читатели (`/where`, `/unplaceable`, прогнозы меток) — 503 `unavailable`, не idle
(сверка python и go 2026-10-18).
Их исходное отсутствие допустимо; после создания обе строки не удаляются. Turn сохраняет
нижнюю границу spec_rev, idle сохраняется, чтобы версия intent не возвращалась к
версии отсутствия между двумя чтениями; это необходимо читателям ниже.

Active intent — принятое общее решение для members, пока отдельные placement и workers
доводятся до него. Для каждого его id решают target/reason/at/spec_rev intent; остальные id
решаются своими placement. Читатель (/where, unplaceable, прогнозы и контроллер) читает intent,
нужные placement и снова intent: при смене версии повторяет чтение. Только одинаковые версии
дают результат. Неподтверждённое чтение не означает idle. При idle все строки завершённого
решения уже доведены. Одним HTTP-чтением не обещан атомарный снимок всей подсистемы.

Для допуска нагрузка цели считается консервативно: сумма весов уникальных id, уже назначенных
ей **или** направленных туда эффективным решением. Двойной учёт одного id у одного воркера
исключён; ещё не снятое старое назначение удерживает место у прежнего воркера. Та же совокупность
учитывается для spread_by. Active intent резервирует всех members у target ещё до workers.
Показатели фактического назначения по-прежнему считают workers; резерв — условие допуска,
а не утверждение, что единица уже работает. Перед новым допуском незавершённый intent доводится.

Группа принимается одним intent со всеми её членами из свежего взгляда и одной общей целью;
предпочтения выбираются по первому id в порядке UTF-8, ограничения и вес — по всем членам.
Воркеры никогда не получают назначения членов этой операции одновременно на разных целях:
сначала снимаются все прежние назначения всех members, затем добавляются на одну цель.
Промежуточное отсутствие части назначений допустимо и чинится; частичное решение о вместимости — нет.
Изменения полей единиц, состава группы, ёмкости, политики и жизни после взгляда обрабатываются
следующим проходом: они не атомарны с допуском. При неизменных входах конкуренция контроллеров
не превышает ёмкость, не нарушает spread_by и не расщепляет группу.
Если после изменения состава группа размещена лишь частично и целиком на прежнюю цель не
помещается, её сначала целиком снимают intent с target ""; она ждёт или выбирает новую общую
цель следующим решением. Размещённую полностью группу без причины ухода не пересматривают.

## Н2 Двери

Двери консоли, через которые оператор говорит с контроллером. HTTP-формы и закрытые наборы кодов —
[OpenAPI](04-the-controller-and-placement.api.openapi.yaml); у каждого `GET` есть `HEAD` — тот же код и заголовки без тела (урок 9 Н2). Общие отказы консоли — урок 9 Н4;
это `{detail, error}`, а не Fault хранилища. Состояние, права и выбранный вид id проверяются
после статической формы. Новых дверей переезда и перебалансировки нет (ADR-0047).

### Н2.1 Входы

Разбор запроса — урок 9 Н2 «Разбор запроса консоли» (урок 1 Н2.1 с отступлениями консоли); своих отступлений у дверей
контроллера нет (повтор `server` у `POST /drain` — 400 по общему правилу).

`/policy`, `/unplaceable` и `/where/{id}` относятся к выбранной подсистеме; у корневой они
без префикса, у смонтированной — с `/<sub>`. `/drain` и `/servers/{server}/…` находятся
у корня консоли и охватывают все её спеки (ADR-0026). Префикс подсистемы не создаёт копии
кластерных строк. Права — роль `console` урока 6 Н1.4; порядок сторожевой — урок 9 Н1.3 `identity` и `need`. Стандартные servers у этих трёх path item
задают оба полных URL; общие /drain и /servers/{server}/… не наследуют префикс.
Имя sub явно выбирает загруженную спеку, включая CONSOLE_ROOT (М10/9 Н2).

| Операция | Вход | Успех |
|---|---|---|
| GET /policy | без тела | 200 Policy: `{servers: shared \| distinct}`, эффективное значение |
| PUT /policy | обязательный объект только с `servers` | 200 Policy после записи; журнал policy.changed |
| GET /drain | без тела | 200 DrainState, снимок состояния по уроку 10 Н1.2 |
| POST /drain | обязательный непустой query `server`, без тела; нет `server`, он пуст, повторён или не по грамматике имени сервера — 400 `{detail, error}` по Н4 | 200 `{draining: server}`; повтор того же сервера идемпотентен, иной при активном дренаже — 409 |
| DELETE /drain | без тела | 200 `{draining: ""}`, в том числе если уже снят |
| GET /servers/{server}/labels | необязательный query `labels`: метки через запятую, пустая строка — пустой набор; пустой элемент (`a,,b`) — 400 | 200 `{would_move: [<sub>/<id>…]}` — только единицы подсистем с `constraint: labels-subset`; с query — проба этого набора без записи, без query — проба текущих эффективных меток |
| PUT /servers/{server}/labels | обязательный объект только с `labels`: массив меток | 200 `{will_move: [<sub>/<id>…]}` после записи строки; это прогноз следующего прохода, не подтверждение переезда |
| DELETE /servers/{server}/labels | без тела | 200 `{}` после снятия строки; снова действуют метки узла |
| POST /servers/{server}/decommission | необязательное тело; отсутствие равно `{}`; разрешены только `why` (строка) и `gone` (булево) | 202 `{}` либо `{warning: <непустая строка>}` при подтверждённом выводе никогда не слышанного ресурса |
| DELETE /servers/{server}/decommission | без тела | 200 `{}` после снятия запроса; отметку снимает следующий проход контроллера |
| GET /unplaceable | без тела | 200 массив Unplaceable |
| GET /where/{id} | id по уроку 3, вид задаёт спека; пустой id (`/where/`) — не маршрут, 404 | 200 Where; не размещена — 404 `{reason: <непустая строка>}` |

Во всех строках таблицы JSON-объекты закрыты: неуказанных полей нет. Успех `{}` содержит JSON-объект,
а не пустое HTTP-тело. Метка — 1–64 ASCII-знака: первая буква/цифра, далее буква/цифра, `_`, `.`,
`:`, `-`; перевод строки недопустим. Список query разбирается по запятым, без пустых элементов,
кроме целиком пустой строки; сервер в path/query — имя сервера: имя хоста RFC 1123 — метки через «.», метка 1–63
знака `[A-Za-z0-9-]`, не начинается и не кончается «-», всего не больше 253 байт (`..`, `.`, пробел, `/` — не имя);
иное — 400 до проверки существования (сверка python и go 2026-10-18). В `will_move` и
`would_move` попадают только ссылки, доступные вызывающему по `view`; список может быть пуст.
Имя подсистемы в ссылке `<sub>/<id>`, ключах карт drain и поле `subsystem` следует М10/2 Н1.2,
включая весь закрытый список зарезервированных имён; грамматика самого id — М10/3 Н1.3.
Существование сервера определяется всеми подсистемами и ресурсами консоли: сервер известен, если есть хотя бы
одно свидетельство — пульс ресурса этого сервера, строка `platform/doors/<сервер>`, поле `server` пульса воркера
или слота любой подсистемы, а для операций меток ещё строка `platform/servers/<сервер>`. Для всех трёх операций
меток и обоих методов вывода неизвестный сервер — 404. Ошибочная форма тела/меток — 400 до этой проверки.

### Н2.2 Полные тела чтения

- **Unplaceable:** `{id, labels, workers_live, why?}`. `id` — строка; `labels` — массив меток;
  `workers_live` — целое ≥ 0; `why`, если есть, — непустая причина из поля `unplaceable` последнего
  отчёта прохода (Н1.2): решает контроллер, консоль читает. Это единицы без места,
  в том числе при пустом пуле, и единицы, для которых ограничения не дают кандидата.
- **Where:** `{worker, server, reason, directory, scans, door?}` по уроку 9 Н3 «`/where/<id>`». `worker` — непустое
  имя назначения по грамматике слота М10/3 Н1.4; `server` — из пульса воркера, иначе из поля `server` его строки слота,
  иначе null (сверка python и go 2026-10-18); `reason` —
  непустая причина решения; `directory` — имя из последнего скана назначений либо null;
  `scans` — число завершённых сканов ≥ 0 с запуска консоли. Кэш directory может отставать от решения;
  частота скана назначений — «Решает реализация» п. 9. У неразмещённой единицы 404 `{reason}` берёт причину
  из поля `unplaceable` отчёта прохода, а без неё — `not placed: no worker holds it`.
  Необязательная `door` содержит `url`, `token` (непустые строки), `expires` (число стенных секунд)
  и `routes` (массив непустых строк); условия выдачи (`view` на единицу, журнал `door.issued`) и срок (TTL 120 с) — урок 9 Н3 «`/where/<id>`», а не право, следующее из схемы.
- **DrainState:** `{draining, safe, would_strand, subsystems}`. `draining` — имя или `""`;
  `safe` — булево; `would_strand` — карта подсистема → массив id.
  Значение `subsystems[sub]`: `{draining, subsystem, workers, units, pending_writes, would_strand, safe, pending_unsaid?}`.
  `draining` — то же имя или `""`, `subsystem` равно ключу карты; `workers`, `units`,
  `pending_writes` — целые счётчики ≥ 0; `would_strand` — массив id; `pending_unsaid`, если есть,
  — массив имён воркеров по М10/3 Н1.4 без читаемого счётчика. `safe` считается по уроку 10 Н1.2, не по пустоте
  `would_strand` — без моделирования размещения: все единицы воркеров этого сервера и все неразмещённые единицы
  подсистемы. Единицы воркера — объединение его назначения (`<sub>/workers/<имя>`) и `status[].id` его пульса: пустой
  `status` при назначенных единицах не делает сервер пустым (сверка python и go 2026-10-18); `units` — их число. Без активного дренажа серверный набор пуст, счётчики 0, `safe: true`;
  проба неразмещённых единиц всё равно может дать непустой `would_strand`.
  Ключи двух карт совпадают и соответствуют видимым подсистемам; общий `safe` определяется всеми
  подсистемами, а не только видимыми, чтобы скрытые единицы не разрешали выключение сервера.

Если нужное чтение/запись хранилища не подтверждены, операция возвращает 503 `{detail, error: unavailable}`;
при неизвестном исходе записи клиент сначала перечитывает состояние. `busy` и `denied` имеют отдельные причины урока 9.
Коды и тела общих отказов описаны у каждой операции OpenAPI. Операционный 404 отличается от
`NoRoute`: у сервера — `{detail, error}`, у неразмещённой единицы — `{reason}`.
Отказ вывода 409 содержит `{detail, error: "server answers", server, may_confirm_gone}`;
`may_confirm_gone: true` разрешён только при никогда не слышанном ресурсе и отсутствии свежих
свидетельств воркера/слота/ресурса. При живом сервере `gone: true` не обходит отказ: любое свежее свидетельство —
409 с `may_confirm_gone: false`, и `gone: true` его не меняет.

---

delete_after применяется только к named id: numeric вместе с этим ключом отвергается загрузчиком М10/2. Контроллер не заменяет физическое удаление надгробием и не уничтожает историю числовых выдач.

## Н3 Проход

### получить и удерживать очередь размещения

```
1. прочитать placement_turn; нечитаема → отказ шага; spec_rev > моя → не менять, spec_behind
2. строки нет → cas ""; holder пуст → cas прочитанной версии;
   holder чужой и эта версия не менялась ≥ TURN_TERM по моим часам → cas прочитанной версии;
   иначе очередь занята, этот проход не меняет размещения; следующий попробует снова
3. записать {holder: новая уникальная метка этой попытки, spec_rev: моя} с выбранным cas;
   conflict → очередь не получена; подтверждено → запомнить версию turn и время отправки запроса
4. каждые TURN_RENEW, между операциями: переписать свою строку turn с cas своей версии;
   подтверждено → новый guard и начало своего срока от отправки; conflict/чужой holder → прекратить записи
5. пока свой подтверждённый запрос моложе TURN_TERM, каждая запись/удаление placement/*,
   workers/* и placement_intent, а также удаление строки единицы по delete_after имеет cas целевой строки И guard {key: placement_turn, index: моя версия};
   истёк свой срок → не писать до подтверждённого продления; 412 → прекратить текущую попытку
6. завершение прохода: записать holder: "" с cas своей версии; конфликт не повторять
```

Любой неответ, неизвестный исход, конфликт или 412 при изменении размещения прерывает
текущий план действий в памяти. Прежде чем продолжить, контроллер подтверждённо меняет версию
своего turn с cas (если holder уже чужой — останавливается), затем заново читает intent и строки.
Этот барьер отсекает и ещё летящую старую запись: она либо применена до барьера и видна чтению,
либо получает 412 после него. Неответ самого барьера запрещает продолжение. Нельзя просто
подставить более новую версию стража в прежнюю команду. Два изменяющих прохода одного процесса
тоже не идут одновременно под одним turn; продление не выполняется параллельно целевой записи.

**Гонки.** Из двух cas захвата проходит один. Новый держатель после захвата читает мир заново;
поздние placement/workers/intent и удаление по delete_after старого держателя отказаны стражем turn, даже если строка
самой единицы не менялась. Новый держатель успел разместить прежнюю версию единицы — старое удаление получает 412, строка сохраняется. Старый контроллер не продлевает и не освобождает чужой turn своим cas.
Новому наблюдателю чужой turn сначала свежий; ожидание не зависит от часов прежнего держателя.
Время отправки своего подтверждённого запроса — время первой отправки этой логической записи;
повтор с тем же id и ответ again его не сдвигают (то же правило у слота и аренды, урок 3).
Пропавший контроллер задерживает изменения максимум до следующей успешной попытки после
окна наблюдения, но срок ответа недоступного хранилища этим не ограничивается.

### принять и довести решение(members, target, reason)

```
0. очередь моя; active intent → сначала довести его, новых решений пока не принимать;
   spec_rev intent > моя → не изменять его и размещения; сообщить spec_behind
1. для нового решения: свежо прочитать единицы, эффективные решения, назначения и свойства кандидатов;
   хотя бы одна placement members имеет spec_rev > моя → не принимать intent, spec_behind;
   проверить всю группу/единицу, свободную ёмкость с резервами Н1.5, spread_by и прочие ограничения;
   для оценки переезда собственные прежние резервы members не считаются второй копией на цели;
   проверяется конечный набор: прежние id без members + ВСЕ members, включая spread_by между
   членами самой группы и по всем воркерам сервера цели;
   нет общей цели → нового допуска нет (снятие использует target "")
   полный ключ <sub>/placement/<id> хотя бы одного из members длиннее предела ключа хранилища
   (М10/1 Н1) → решения нет, intent не пишется; эти members — в unplaceable с why
2. записать active intent с cas прочитанного idle (или cas "" при исходном отсутствии) и guard turn;
   toolarge до подтверждённого active → отказ шага, placement/workers не менять, группу не делить
3. после подтверждённого intent свежо перечислить/прочитать ВСЕ workers;
   снять ВСЕ members из ВСЕХ назначений, включая target, каждой записью cas + guard turn;
   только подтверждённое завершение всех снятий разрешает идти дальше
4. каждой placement members присвоить target/reason/at/spec_rev intent с cas + guard turn,
   rev + 1; строка уже содержит эти поля → не переписывать; отсутствующая начинается с rev 1
5. target непуст → добавить ВСЕ members в его назначение одной записью cas + guard turn;
   target пуст → добавления нет; пока 3–4 не завершены, шаг 5 запрещён
6. только после подтверждения 3–5 записать intent {state: idle, spec_rev} с cas + guard turn
```

Каждая группа занимает одну запись intent; она не дробится ради потолка строки или назначения.
Вес обеих будущих строк (intent и полного назначения цели) проверяется до шага 2; превышение —
отказ шага с причиной и failures, без частичного размещения. До шага 2 так же проверяется, что
полный ключ `<sub>/placement/<id>` каждого из members представим в пределе ключа хранилища
(М10/1 Н1): id, допустимый уроком 3 для строки единицы, может не поместиться в более длинный
ключ размещения. Непредставимый ключ — решения нет, intent не пишется, группа не делится;
эти members попадают в `unplaceable` с `why`, остальные решения прохода продолжаются. Поэтому
недоводимого из-за длины ключа intent не бывает, и одна такая единица не останавливает размещение
подсистемы. Неполное чтение также запрещает допуск.
При смене держателя active intent восстанавливается **с шага 3**; новое решение и другое направление
для его members до завершения запрещены. Состав, цель и правило зафиксированы в intent;
изменения входов после его принятия обрабатываются следующим решением после восстановления.
После доведения все новые расчёты делают свежий взгляд, поэтому резерв предыдущего решения уже виден.

**Гонки.** Два допуска разных единиц не используют один остаток: B получает turn после A и видит
решение/назначение A либо его active intent, который обязан сначала довести. При capacity=1
второй вес 1 не проходит; при spread_by занятое значение уже видно. Два разных первых члена
группы не создают разные решения: один active intent фиксирует всех и одну цель. После обрыва
посреди снятий добавления не начинаются; после обрыва посреди placement новый держатель
повторяет снятия и доводит ту же цель. До добавления на новую цель у старых нет ни одного
назначения members. Это гарантия строк/назначений, а остановку действий старых процессов
обеспечивают их сверка и аренды уроков 3/5, а не одно изменение карты размещения.

### проход() — каждые 5 с

```
0. наблюдение: обновить память увиденных пульсов, слотов и ресурсов на своих часах;
   впервые увиденное = только что изменилось; получить очередь размещения по Н3 выше;
   занята → без изменяющего прохода, повтор через 5 с; моя → сначала довести active intent;
   затем свежий взгляд: единицы, размещения, назначения и свойства кандидатов;
   перед каждым новым решением взгляд обновляется, результаты предыдущего решения учитываются
1. ревизия: прочесть ревизию спеки; строки размещения без spec_rev — проштамповать своей (один раз)
2. вывод серверов: исполнить platform/decommission/*: отдать слоты, записать <sub>/decommissioned/<s>
3. судьба слотов (ниже); release → записать слот отданным; names_given; тревоги hung/unsure
4. разместить: снять удалённые (reason deleted) → снять retire_when → sync назначений с размещениями (diverged) →
   каждую неразмещённую единицу — выбрать (ниже), группу целиком у первого члена; каждая в своей попытке
5. достижимость: единицы, чей сервер больше не достаёт до их меток, — переезд в пределах REACH_BUDGET;
   группа — целиком, первая группа идёт и сверх бюджета; некуда — снять с причиной
6. уход: единицы воркеров, которые уходят (ниже), — переезд без бюджета; группа целиком или ждёт
7. дом: не больше HOME_BUDGET единиц — домой, если там есть место
8. неразмещённые дольше delete_after: под своим turn заново прочитать единицу и её эффективное размещение
   по Н1.5; есть назначение, intent active (при любой цели) или чтение не подтверждено → не удалять. Всё ещё неразмещена и срок подтверждён →
   удалить строку с cas её свежей версии И guard своей версии placement_turn (допуск шага 5 выше);
   conflict/412/неответ → барьер и новый план по правилу очереди, журнал unit.unplaced_deleted только при успехе
9. нехватка и предложения (offers: true): посчитать short, предложить/отозвать имена
10. отчёт <sub>/controller/pass; освободить очередь
каждый шаг — в своей попытке: ошибка шага — failures + 1, остальные шаги идут
```

Определённый badkey полного ключа хранилища — ошибка соответствующего шага, а не отсутствие
строки; данные по такому чтению не подменяются пустыми. Если ошибка не позволяет довести
active intent, новое решение не принимается: действует правило восстановления Н1.5/Н3.
Проход проверяет размещение и назначения; `unique`/`ref`/`must_match` полей единиц проверяются
предварительно дверью М10/3. Фоновый аудит и журналирование нарушения этих ограничений после
гонки отдельных записей этот проход не гарантирует (М10/3 Н3).

**Гонки.** Цель размещения/назначения изменяются только под очередью и через intent; один cas строки
единицы не заменяет общего допуска. Обрыв очереди/хранилища прекращает весь изменяющий проход,
а не только одну единицу; ошибки остальных независимых шагов учитываются обычным failures.
Следующий держатель сначала чинит незавершённое решение, затем принимает свои.
Штамп spec_rev без изменения цели — отдельная запись с cas и guard turn, intent ей не нужен.

### выбрать(единица) → воркер | нет

```
размещена (worker ≠ "")                                            → как есть; не пересматривать
retire_when                                                        → нет
живой воркер = пульс читается ∧ менялся < LOST_AFTER по часам контроллера ∧ слот читается, не отдан, holder непуст;
              пульс, чьё worker ≠ имени в ключе (урок 5 Н1.1), не читается: воркера нет в пуле
пул = живые − отданные слоты − дренируемый сервер − выведенные серверы − (requires: resource ∧ ресурс silent)
      − (distinct: все кроме хранителя места)
      хранитель: наибольшая нагрузка на месте, при равенстве — первый в слотовом порядке М10/3 Н1.4
пригодные = пул ∩ constraint ∩ spread_by ∩ affinity ∩ (группа уже у воркера → только он)
группа из нескольких ждущих: пригодные ∩ {принимает всех ∧ свободно ≥ Σ весов}; пусто → ждать, сказать
порядок: дом → предпочтение → все; предпочтение — один ранг: воркер рядом с соседом (near) или на сервере
         несвязывающей строки affinity (Н1.3) — любое из двух, оба сразу ранг не поднимают (журнал cammeta-go, урок 4 № 4);
         внутри ранга — свободно = ёмкость − нагрузка с резервами Н1.5,
         свободно ≥ вес единицы ∧ строго больше прежнего лучшего; равенство — первый по имени (ASCII, М10/3 Н1.4)
нашли → принять и довести решение для единицы или всей группы по Н3 выше;
         уже размещена за время получения очереди → не принимать прежний выбор, свежий взгляд
нет   → строка не пишется (или reason, почему), единица в unplaced; тяжелее любого — в unplaceable со словами
```

**Причина** (для человека, ДОЛЖНА быть непустой; СЛЕДУЕТ грамматике): `most free capacity (<свободно>) among <n> worker(s)` — `<n>` — число пригодных (после фильтров), не всех живых + `; weight <w>` — только у спеки с `placement.weight` + ` reaching <метки>` + `; on <сервер>` + `, whose resource is <state>` + пометка выбора (`, at home on <s>`, `, beside <их id> holding it`, ` (home <s> has no room)`, `; away from home <s>`). Уход: `slot <имя> released`, `resource on <s> silent`, `server <s> draining`, `server <s> decommissioned`, `<w> holds no <place> now`, `<w>'s <place> admits no unit`. Достижимость: `<s> no longer reaches <метка>; …` / `; nothing live reaches it`. Группа: `with <id>, one <group_by>: <why>; on <s>`. Удалённая: `deleted`.

**Материализация и sync.** Они используют тот же intent и очередь. Даже если правильное решение
уже есть, починка сначала фиксирует его для единицы/группы, снимает прежние назначения и доводит
одну цель. Частичного добавления по снимку начала прохода нет. Единственный guard целевой
записи — версия turn; стабильность решения обеспечивает исключительное владение очередью,
свежая проверка и неизменяемый до завершения intent. Это заменяет прежний guard отдельного placement.

### переехать(единица, от, к) → ok | уже перевезли

```
1. очередь текущего прохода моя и подтверждена; вне прохода сначала получить её;
   заново захватывать уже удерживаемую очередь не нужно; довести прежний active intent;
   свежо прочитать эффективное размещение;
   worker != от → Moved, не трогать; у группы проверить всех членов и общую цель
2. проверить к по всем ограничениям и свободной ёмкости с резервами;
   принять intent для всей единицы/группы и довести его шагами 2–6 выше
```

**Гонки.** A задержался после решения w-2, B получил очередь и довёл его, затем перевёз на w-3.
Каждая поздняя запись A имеет старый guard turn и отказана. Она не может ни добавить в w-2,
ни снять из уже нового w-3. Если A успел добавить до захвата B, B видит назначение при свежем
снятии. У одной единицы не возникает двух назначений; у группы до добавления новой цели сняты
все старые назначения. Мгновение без назначения и отставание directory остаются допустимы.

Во всех ветвях hung/unsure/wait HUNG_MOVE_AFTER отсчитывается от первого наблюдения
этим судьёй неизменной версии слота (возраст 0), не от until, конца SLOT_TERM или входа
в fate. Диагностическое fates.since не переносит этот срок. Новый судья начинает наблюдение заново.

### судьба(слот) → fate — по часам контроллера

```
читаемый слот не менялся < SLOT_TERM на часах этого судьи                  → alive
ресурс live ∧ присутствие gone ∧ назначенных единиц нет                  → release (без запаса; запись — ниже)
ресурс live ∧ присутствие gone (процесс мёртв, сервер жив)              → move  (без запаса)
та же версия слота наблюдается < SLOT_TERM + LOST_AFTER                   → alive (запас)
пульс менялся < LOST_AFTER назад                                         → alive
ресурс live ∧ процесс runs (ведёт единицы или держит замок присутствия)   → hung;   прошло ≥ HUNG_MOVE_AFTER → hung_moved
ресурс live ∧ о воркере ничего (полей нет ∨ unlisted)                    → wait;   дать имя через names_given — только
                                                                           после HUNG_MOVE_AFTER
ресурс live ∧ присутствие не прочлось (unknown)                          → unsure; прошло ≥ HUNG_MOVE_AFTER → unsure_moved
ресурс unreachable (resource_state Н1)                               → unsure; прошло ≥ HUNG_MOVE_AFTER → unsure_moved
ресурс silent (пульс и at не свежи или строки нет) ∧ воркер молчит       → move   (два молчания, ADR-0045);
                                                                           сервер — из пульса, иначе из Slot.server
сервер неизвестен вовсе                                                  → move   (два молчания)
единицы назначены ∧ ничего из выше                                       → move     (замыкающая строка)
нет назначенных единиц ∧ ничего из выше                                  → release  (замыкающая строка)
запись release: записать слот released (cas),
                                                                           holder/until/gen/server и offer-поля сохранить; порванную —
                                                                           целиком отданной и ничьей с сохранением читаемого gen и offer-полей;
                                                                           если gen не читается — строку не менять, разрешение
                                                                           на захват не выдавать (урок 3 Н1.4)
names_given[имя] = версия строки слота, на которой имя берётся: для move, hung_moved, unsure_moved и wait ≥ HUNG_MOVE_AFTER —
                   версия в момент суждения (контроллер строку не пишет); для release — версия ПОСЛЕ записи отдачи (ответ
                   этой записи): отданный слот берут по ней, и как «свободный» он тоже кандидат (урок 3 шаг 2c)
```

Нечитаемое gen существующего слота не заменяется нулём ни при release, ни при предложении имени;
такую строку сохраняют и не включают в names_given до восстановления поколения. Переназначение
единиц по судьбе не означает разрешения переписать повреждённое поколение слота.

**Переходы `release` (ADR-0080 доп. 12).** Ветвь `release` достижима строкой «gone без назначенных единиц»:
живой ресурс говорит о процессе одним из `runs`, `gone`, `unlisted`, `unknown` (урок 8 Н1.4; `silent` — состояние ресурса,
не присутствие), и каждое слово, кроме этого случая, перехватывает строка выше. Две замыкающие строки делают
таблицу полной и при определениях Н1 не достигаются.

| Участник и состояние | Событие и условие | Действие | Новое состояние или результат |
|---|---|---|---|
| судья, слот не менялся ≥ SLOT_TERM, назначенных единиц нет | ресурс live, присутствие `gone` | записать `released` с `cas` прочитанной версии | слот отдан; `names_given` — по версии после записи |
| судья, то же | держатель продлил слот между чтением и записью | `cas` отказан | слот не меняется; на следующем проходе — `alive` |
| судья, слот не менялся ≥ SLOT_TERM, единицы назначены | ресурс live, присутствие `gone` | ничего не писать | `move` без запаса; `names_given` — по версии суждения |
| судья, назначенных единиц нет | ресурс live, присутствие `unlisted` или полей нет | ничего не писать | `wait` (ADR-0048): имя за держателем до HUNG_MOVE_AFTER |
| судья, назначенных единиц нет | ресурс live, присутствие `runs` | ничего не писать | `hung` |

Порядок правил нормативен: более определённое знание раньше менее определённого; запас раньше суждений. Контроллер не пишет слот ни при каком исходе, кроме `release`, предложения и вывода сервера.

**Гонки.** Держатель продлил слот между суждением и захватом имени новым процессом: `names_given` привязан к версии, захват с `cas` по ней не пройдёт — имя остаётся. Два контроллера могут иметь разные истории наблюдения и потому разные суждения (ADR-0049); каждый использует свой возраст версии по уроку 3 Н1.4. Записи `release` идут с `cas` прочитанной версии, поэтому два решения не перезаписывают продление или чужой захват. Сдвиг часов писателя при одинаковой истории наблюдения не меняет судьбу.

### уходит(воркер) → причина | нет

Первое из: слот отдан; ресурс сервера silent; не держит место (`distinct`); место не принимает; сервер дренируется; сервер выведен; исход из MOVED_FATES — его `why`. Единицы уходящего — переезд (шаг 6) по правилам выбора; группа целиком или остаётся с тревогой `units.left_on_leaving`; строка размещения не очищается, пока не найдено новое место, — кроме отданного слота: его единицы, которым некому достаться, снимаются записью `worker: ""`, причина `slot <w> released; nothing live can take it` (воркер ушёл навсегда, строка с его именем говорила бы «размещена»; приёмка урока 5, сц. 03). Молчание хранилища не двигает ничего.

**Гонки.** Уход и оживший воркер: решение — по снимку прохода; воркер, вернувшийся после переезда, читает назначение без единицы и останавливает её (урок 5 Н3 «цикл()», шаг 2: ведомой нет в назначении → `stop_unit`); переезд не откатывается.

### нехватка() и предложить() — при offers: true

```
ждущие = единицы без размещения ∪ единицы уходящих ∪ вне достижимости; группа — одна штука; снятые по retire_when и
         нечитаемые строки единиц (garbled) не ждут: запасной их не разместит (сверка python и go 2026-10-18)
по набору меток: per = наименьшая положительная ёмкость подходящего живого воркера;
                 таких нет → placement.capacity.default, если он > 0;
                 нет и положительного default → предложения для набора не создавать, withheld: "no positive capacity estimate"
                 (нехватку веса и групп всё равно показать, workers: 0; с этим withheld ноль означает
                 отсутствие вычислимой оценки, а не отсутствие нехватки; это не ошибка шага)
                 иначе нужно = ceil(max(0, Σ весов ждущих − свободно у подходящих живых) / per) + по одному на группу,
                 которой нигде нет места
серверы для запасного: не дренируемые, не выведенные, ресурс не silent; при distinct — без своего воркера;
                 нет таких → withheld со словами, тревога spares.no_server
предложить:  строка слота <prefix>-<max+1> вида Н1.1 записью с cas ""; max и запись номера — М10/3 Н1.4;
            взятое без пульса с offer считается «запускается» не дольше OFFER_GRACE от первого наблюдения
            контроллером этого захвата (holder, gen). Возраст местный монотонный, продление той же пары его не сбрасывает;
            новый судья начинает с 0. taken_at — диагностика стенными часами, не основание этого срока
отозвать:    лишние невзятые предложения — удалить с cas по прочитанной, в обратном слотовом порядке М10/3 Н1.4;
            ждущих набора не осталось — все его невзятые предложения лишние (сверка python и go 2026-10-18);
            для создаваемых контроллером числовых имён это наибольший номер первым;
            conflict — оставить (запасной взял)
```

**Гонки.** Два контроллера предлагают одно имя: предложение — строка слота с `cas ""` и `gen 0`, второй получает `conflict`. Предложение против захвата: захват пишет `gen 1` с `cas` по версии предложения; устаревшее предложение не перезаписывается.

Невзятое предложение для отзыва — строка с offer, пустым holder и gen = 0.
Захват и фильтр набора запасного определены таблицей М10/3 Н3. Отдача или разрешение names_given
не снимают фильтр offer; обычный процесс не получает предложение через эти ветви.

### вывести_сервер(s) — запрос консоли, исполнение контроллером

```
консоль: ресурс, воркер или слот сервера слышны < LOST_AFTER назад                → 409 server answers
         ресурс никогда не слышали ∧ gone ≠ true                                   → 409, may_confirm_gone
         иначе записать platform/decommission/<s>                                   → 202, журнал
контроллер (шаг 2): отдать слоты сервера, записать <sub>/decommissioned/<s>; воркеры сервера — вне пула;
         единицы — уход «server <s> decommissioned»; удержания не отпускаются
консоль (на своём проходе, после отметки контроллера каждой спеки): удалить platform/doors/<s> с cas по прочитанной
         версии (право delete:, урок 6 Н1.4); ресурс выведенного сервера, пока стоит platform/decommission/<s>, свою дверь
         заново не пишет (урок 8 Н1.4 `door_row`)
отзыв:   DELETE → строка запроса снята, контроллер снимает отметку; дверь ресурс пишет снова своим пульсом
```

**Гонки.** Вывод сервера и возврат его воркеров: `decommissioned/*` пишется с `cas`; воркер этого сервера при захвате проверяет вывод (урок 5 Н3 «старт()», шаг 3: `platform/decommission/<s>` или `<sub>/decommissioned/<s>`) и имя не берёт; запрос консоли и проход контроллера разделены строкой — повтор запроса идемпотентен.

```
перед каждой записью строки размещения (разместить, переехать, снять): row.spec_rev > моя ревизия
```

## Решает реализация

Реализация обязана назвать в своём описании:

1. **предел повторов при `conflict`** (10); период прохода — 5 с, норма (ADR-0030 доп. 2026-10-07 п. 5), не выбор;
2. **кэш между проходами** — что держится по версии строки, и как это не меняет решений (решают строки, не кэш);
3. **как ресурс сервера сообщает присутствие процесса** (форма поля `workers` пульса ресурса — урок 8 Н1.4) и замок присутствия;
4. **откуда `HUNG_MOVE_AFTER`, `REACH_BUDGET`** (окружение) и их умолчания;
5. **как запрашивается перебалансировка** и кто её зовёт; бюджет;
6. **дополнительные поля отчёта** сверх Н1.2 и как из него делаются метрики (ряды `<sub>_reconcile_*`, `<sub>_units_unplaced`, `<sub>_units_diverged` — урок 9 Н3 «/metrics — текст»);
7. **точные тексты** причин и отказов сверх грамматики Н3/Н4;
8. **что делает спека без `offers`** с нехваткой (ничего не считает) и где живёт скрипт запасных (`w2c-spares.sh`, урок 11 Н1.5 `script`);
9. **частоту скана назначений** консоли для `Where.directory` и `scans`;
10. **команду печати отчёта прохода** `<sub>/controller/pass` для приёмки — по разделу «Стенд» README приёмки урока 1.
