# М10/2 — Спека подсистемы и строгий загрузчик: нормы

Канон урока М10/2 по ADR-0080. [Лекция](../02-the-spec-and-the-strict-loader.md) объясняет предмет и не добавляет требований.
[HTTP-контракт](02-the-spec-and-the-strict-loader.api.openapi.yaml) описывает `GET /spec`; [инструкция реализации](02-the-spec-and-the-strict-loader.README.md)
задаёт порядок работы по этим нормам. Приёмка — `Source/tests/testdata/acceptance/М10_Platform/02/`.

## Н0 Словарь слов

Значения ДОЛЖЕН / НЕ ДОЛЖЕН / СЛЕДУЕТ / НЕ СЛЕДУЕТ / МОЖЕТ и пометки «решает реализация» заданы
в [нормах урока 1](01-storage.norms.md), Н0. Непомеченное предложение нормативного раздела читается как ДОЛЖЕН.

## Н1 Форма

### Н1.1 Текст спеки

Спека — текст в кодировке UTF-8, читаемый как подмножество YAML 1.2 core. Загрузчик ДОЛЖЕН принимать ровно это подмножество и ДОЛЖЕН отказывать всему за его пределами, называя путь ключей и строку файла.

```yaml
text:
  encoding: UTF-8; без BOM; без NUL; отступы пробелами (табуляция в отступе — отказ)
  document: ровно один документ (второй `---`, `...` или директива `%` — отказ); корень — отображение
            (список, скаляр, пустой файл — отказ)
  refused:  якорь `&`, псевдоним `*`, ключ слияния `<<`, любой тег `!…`; ключ, сказанный дважды в одном отображении
            (и в потоковом `{a: 1, a: 2}`); ключ-отображение и ключ-список; вложенность глубже 64;
            строка файла, которую читатель не смог отнести ни к какому ключу
  scalars:
    bool:   только `true` / `false` (регистр любой); `On`, `Off`, `yes`, `No` — слова
    null:   `null`, `~`, пустое значение
    int:    десятичные цифры, со знаком; `010` — десять; `0x10`, `0o7`, `1_000`, `1:30` — слова;
            по модулю не больше 2^53 − 1
    float:  `1.5`, `1e308`, `.5`; `.inf`/`.nan` распознаются как float, но отказываются на шаге значений Н3
    string: всё остальное; слово в кавычках — слово, даже если похоже на число
  blocks:   отображения и списки отступом; потоковые `{a: b}` и `[a, b]` в одну строку; блочные скаляры `|` и `>`
            (с `-` или `+`); простое слово, перенесённое на строки глубже своего ключа
```

Что одна библиотека YAML читает, а другая нет — потоковая коллекция на несколько строк, строка в кавычках на несколько строк, явный указатель отступа (`|2`), сложный ключ (`? …`) — отказывается словами, а не читается «как получится».

Числа float в принятой спеке конечны и по модулю не больше `1.7976931348623157e308`.
NaN, обе бесконечности (в любом допускаемом YAML написании) и переполнение этого диапазона —
`refused:value` с путём значения на шаге 4; они не превращаются в строку или null.
Это правило действует во всём документе, включая default/inherit и вложенные числа JSON/opaque.
Непрозрачность отменяет проверку имён внутренних ключей, но не общие требования к числам и JSON.

### Н1.2 Документ

Корень — отображение с закрытым набором разделов. Незнакомый ключ на любом уровне — отказ (Н4). Раздел, отсутствующий в файле, значит умолчание своего урока; `name` и `placement.capacity.default` умолчания не имеют и обязательны.

```yaml
spec:
  name:        # ДОЛЖЕН: строка по грамматике ^[a-z][a-z0-9_-]{0,31}$; не из зарезервированных
               #   platform, domain, console и audit (деревья меток консоли и журнала, урок 8); имя — первый
               #   сегмент всех ключей подсистемы `<name>/…` и её места на домене
  unit:        # единица: rows, id, fields — грамматика поля Н1.3; смысл строки и слота — урок 3
  placement:   # размещение — урок 4; здесь: capacity.default ДОЛЖЕН быть целым ≥ 0; unplaced.delete_after —
               #   целое ≥ 1 и только когда у единицы нет fixed-полей кроме id и about только по id (ADR-0067)
  tables:      # таблицы подсистемы — урок 10; поле таблицы по Н1.3 без fixed, inherit, merge, unique
  requests:    # просьбы — урок 8
  holds:       # удержания — урок 8
  events:      # события — урок 8
  about:       # родитель единицы {sub, field}: оба обязательны, field — поле с fixed: true (урок 3)
  snapshot:    # поля, уходящие из кластера — урок 10; отсутствует = все, кроме секретов, blob и авторского server;
               #   `snapshot:` без значения — отказ; секрет, blob и server в списке — отказ
  rights:      # права — урок 6
  secrets:     # секреты — урок 7
  worker:      # что пишет, читает и просит воркер — уроки 5 и 6
  slot:        # слот — урок 3
  lease:       # аренда — урок 3; форма: {unconfirmed_max: forever | off | <целое ≥ 1>} и ничего иного;
               #   `lease:` без значения, с иным ключом, `0`, строка, дробь, булево — отказ
  heartbeat:   # слова биения — урок 5; `worker` — слово платформы, объявлять нельзя
  objects:     # семьи объектов — урок 8; rows не называет платформенную семью
  door:        # двери воркера — урок 9; routes — каждый маршрут один раз
  servers:     # страница серверов — урок 9; status[].of называет таблицу этой спеки
  display:     # слова консоли — урок 9; закрыт по разделам, внутри словарей — строки
  console:     # {running: <метрика этой спеки>} — урок 9
  metrics:     # метрики — урок 9 (/metrics)
  domain:      # вклад в домен — М11
closed_key_set:
  rule: на каждом уровне допустимы только ключи, которые читает платформа: на верхнем уровне и в заголовках разделов — Н1.2
        этого урока, внутри раздела — грамматика урока-владельца (3: unit, slot, lease; 4: placement; 5: heartbeat; 6: rights, worker.writes, worker.reads;
        7: secrets; 8: events, objects, requests, worker.requests, about, holds; 9: display, servers, console, door.routes, metrics — перечень ключей metrics[] в Н3 «/metrics»;
        10: tables, snapshot; 11: door.pass; М11: domain); ключ вне
        этих перечней — отказ; сводный перечень, каким его держит реализация, сверяется с уроками чтением (решает реализация, п. 1)
  named:   # уровни, где ключи — имена автора (поля, таблицы, виды токенов, книги, виды, слова опций):
    [unit.fields, tables, tables.*.fields, display.keys, display.options, display.kinds,
     display.fields, display.field_help, domain.books, domain.names, domain.tokens, events.suppress, secrets.readers,
     *.schemes]
  opaque:  # уровни, внутрь которых загрузчик не смотрит (содержимое — другой стандарт или другой урок):
    [*.schema (JSON Schema), unit.fields.*.default и inherit при type json, *.must_match, metrics.where,
     metrics.unless.where, metrics.labels, placement.near.prefer, placement.affinity.strict, placement.places.where,
     rights.unit_of, display.options.*]
```

Имена `unit.rows` и таблиц `tables` (в том числе списковой формы) — строки 1–32 ASCII-символа:
первый a-z, остальные a-z, 0-9, `_`, `-`; platform/domain/console/audit запрещены.
Значения вне этой области дают отказ загрузки `refused:value` с путём имени/значения.
Дополнительно действуют запреты пересечения служебных семейств и дверей из М10/3 Н1.1
и М10/10 Н1.6. Область named не отменяет эту грамматику; остальные авторские имена ею
автоматически не ограничиваются. `unit.rows` дополнительно не может быть cluster, worker
или ts: это имена оболочки снимка М10/10 Н1.3; отказ загрузки `refused:value`.

### Н1.3 Поле

Грамматика поля единицы (`unit.fields.<имя>`) и поля таблицы (`tables.<т>.fields.<имя>`). Смысл поля в строке, в форме и в домене — уроки 3, 9, М11; здесь — что проверяет загрузчик.

```yaml
field:
  type:       string | int | float | bool | list | json | url | blob      # закрыто; отсутствует = string
  required:   bool                        # только true/false; `yes`, `"true"` — отказ
  fixed:      bool                        # только у поля единицы
  # list — список строк; произвольные значения/структуры принадлежат типу json
  default:    одно значение типа поля     # json — любое значение JSON; отображение у string — отказ
  inherit:    одно значение типа поля     # только у поля единицы; последнее звено цепи наследования
  merge:      слово (например union)      # только у поля единицы и только с inherit
  enum:       [значения типа поля]        # только у string (строки) и bool (true/false); у int, float, list, json — отказ; default ДОЛЖЕН быть из enum
  unique:     true | canonical            # только у поля единицы; canonical — сравнение по канонической форме URL (урок 3 Н1.3)
  ref, bound_to, must_match, schema, schemes, credentials, secret_in:   # формы — уроки 3, 7, 10
rules:
  - unit.fields не объявляет id, revision, deleted, worker, placement, epoch, phase, observed_revision (platform_fields М10/3); refused:value с путём unit.fields.<имя> до проверки/материализации значения, включая default/inherit; запрет не переносится на поля таблицы
  - default и inherit на одном поле — отказ
  - поле таблицы с fixed, inherit, merge или unique — отказ
  - blob допустим только в unit.fields; имя — 1–64 ASCII, первый A-Z/a-z/_, остальные A-Z/a-z/0-9/_; пустое/непредставимое имя и blob в таблице — refused:value с путём поля (дверь байтов М10/10)
  - blob с required: true, с default или с inherit — отказ (дайджест приходит дверью байтов после создания единицы, урок 10; при создании поле всегда ""; умолчание или наследование писали бы дайджест в строку мимо неё)
  - unit.fields.bytes при наличии любого unit-поля type: blob — отказ загрузки refused:value (счётчик ответа М10/10); без blob обычное поле bytes допустимо
  - snapshot не включает поле server: нет snapshot — server исключается вместе с секретами/blob; явно названный server — отказ загрузки refused:value (М10/10 Н1.3)
  - таблица: held_by/garbled/by/at/made_at запрещены как поля (вычисляемые значения и штампы, независимо от наличия stamp); name допустимо только с типом string (явным или по умолчанию) и key: name (М10/10 Н1.6), иначе refused:value
  - имя поля unit.fields и tables.*.fields — только строковый ключ YAML; числовой, bool и null-ключ — refused:value с путём соответствующего fields. Преобразование имени в строку запрещено; на ключи значений json/display.options этот запрет не переносится
  - значение поля в строке хранилища — урок 3
```

### Н1.4 Ссылки между ключами

Ключ, называющий поле, таблицу, метрику или маршрут, ДОЛЖЕН называть то, что объявлено в **этой же** спеке; иначе отказ при загрузке, а не на странице и не на проходе.

| Ключ | Называет |
|---|---|
| `unit.id` | `numeric` или поле единицы |
| `snapshot[]`, `placement.spread_by`, `placement.group_by.field`, `placement.retire_when.field`, `placement.places.server_field`, `placement.places.where.*`, `placement.affinity.field`, `placement.affinity.server_field`, `placement.affinity.strict.*`, `holds.unit/since/until`, `metrics[].where.*`, `metrics[].unless.where.*`, `rights.unit_of.*`, `servers.show[].by`, `servers.show[].columns[]`, `display.fields.*`, `display.field_help.*`, `display.options.*`, `display.form[].fields[]`, `display.tree.columns[].field`, `display.tree.group_by` | поле единицы (`fields:`) или поле таблицы, если ключ стоит у таблицы; у `display.form[].status[].field` и `display.options.<поле>` слово из `status` — поле платформенной строки |
| `requests.key` | свойства `requests.schema.properties` — поля тела просьбы (урок 8): `{имя}` — значение как строка; `{имя:int}` — значение число, подставляется целая часть (`7.0` → `7`; не число — отказ подачи 400); имя вне схемы — отказ загрузки; поля единицы здесь ни при чём. Тот же шаблон у `tables.<t>.key` (урок 10) |
| `display.options.<имя>.*` | значения `enum` поля единицы или таблицы; у слова пульса из `display.form[].status[]` — любые строки (подписи значений); иное имя или поле без `enum` — отказ |
| `servers.status[].of`, `placement.places.table`, `placement.affinity.table`, `holds.table`, `metrics[].unless.table` | таблица из `tables:` |
| `console.running` | метрика из `metrics[]` |
| `about.field` | поле единицы с `fixed: true` |
| `door.routes[]` | маршрут, каждый один раз |
| `objects.rows[]` | семья, не платформенная (`heartbeats`, `contenders`, `snapshot`, `controller`, `blobs`, `commands`, `*`) |
| `worker.requests[]` | другая подсистема (своя — отказ); что она принимает просьбы — проверка каталога (Н3) |
| `worker.reads[]` | `<семья>/<имя>`, не голое слово |
| `placement.near.sub`, `placement.near.prefer` | соседняя подсистема и её поля — проверка каталога (Н3) |

`display.fields.<имя>` и `display.field_help.<имя>` называют поле единицы, поле таблицы, слово пульса из `display.form[].status[]` или одно из платформенных `worker`, `server`, `revision`, `observed_revision`, `phase`, `id` (их показывает модуль — урок 9 Н1.2); прочие платформенные имена (`epoch`, `placement`, `age`) и имена вне этих — отказ: `display.fields.epoch` отказан, `display.fields.seen` при `status[].field: seen` принят.

### Н1.5 Строка спеки в хранилище

```yaml
platform/spec/<sub>:            # одна строка на подсистему кластера
  yaml:    байты файла спеки как есть
  sha256:  hex-дайджест yaml
  rev:     десятичное целое ≥ 1 — ревизия правила; первая установка — 1, затем установщик поднимает на 1 записью с cas по этой строке
  shell:   страница подсистемы или "" (урок 9); МОЖЕТ отсутствовать у реализации без страниц
platform/spec/<sub>/rev:        # метка, пишется ПОСЛЕ строки; её читает работающий процесс
  rev:     то же число
  sha256:  тот же дайджест
rules:
  - rev строго растёт; метка никогда не понижается
  - одинаковые yaml и shell — «без изменений», rev не растёт
  - писатель строки и метки — только установщик (и кластер из одного процесса со встроенной спекой — сам себе)
```

## Н2 Двери

У загрузчика две двери: процедура загрузки, которой пользуются все процессы и установщик, и `GET /spec` консоли, которым модуль консоли (урок 9) узнаёт форму подсистемы.

### Процедура загрузки

Не HTTP: вход реализации, который получает байты и имя источника и отвечает спекой или отказом. Все пути чтения спеки — файл, строка хранилища, встроенная спека — ДОЛЖНЫ проходить через неё.

```
загрузить(байты, источник) → спека | отказ(источник, путь_ключей, причина)
загрузить_каталог([спека…])  → каталог | отказ(источник, путь_ключей, причина)     # проверки между спеками
```

### GET /spec

HTTP-контракт — [`02-the-spec-and-the-strict-loader.api.openapi.yaml`](02-the-spec-and-the-strict-loader.api.openapi.yaml) рядом (OpenAPI 3.1). Он задаёт маршрут `GET /spec`, схему `SpecView` и коды ответов. Процедура загрузки выше не является HTTP-дверью и в этот файл не входит.

Ревизии спеки в ответе нет: консоль, прочитавшая другую ревизию, уже не работает (Н3 «Смена спеки»).

Успех имеет форму `SpecView`. Имя следует Н1.2, а каждый описатель fields — Н1.3.
В описателе всегда присутствуют name, type, default и required. Отсутствующий default передаётся
как null (у json это также допустимое явное значение); required по умолчанию false. Inherit отсутствует,
если не задан; при заданном inherit поле default равно null. Merge выдаётся только вместе с inherit.
Enum возможен только у string/bool и содержит значения соответствующего типа; blob всегда имеет
required:false, default:null, без inherit/enum. Остальные default/inherit имеют тип поля
(list — массив строк); null у default означает отсутствие и допускается для любого типа.
Наличие default в enum и ограничения между именами проверяются по загруженной спеке отдельно:
обычная JSON Schema не сравнивает значение одного свойства с массивом в другом.
Общие отказы консоли — JSON-объект ровно с `detail` и `error`
(оба строки), без диагностических полей загрузчика и без `kind` хранилища. Для неизвестного маршрута
это `404 {detail: "no such route", error: "no such path"}`, для неверного метода —
`405 {detail: "method", error: "method"}`. Остальные общие коды, условия и заголовки —
[урок 9, Н4](09-the-console.norms.md#н4-отказы); они явно перечислены в контракте рядом с `200`.
Это отказы транспорта и сторожевой, а не попытка загрузить спеку запросом `GET /spec`.
У открытых путей действуют исключения сторожевой Н1.3 урока 9; список кодов не делает их закрытыми.

## Н3 Проход

### загрузить(байты, источник) → спека | отказ

```
1. текст:    прочитать байты как подмножество YAML (Н1.1)              → иначе отказ(источник, путь, строка файла)
             корень — отображение                                       → иначе отказ
2. имя:      name есть, по грамматике, не зарезервировано (Н1.2)        → иначе отказ(источник, "name")
3. ключи:    обойти документ как написан; каждый ключ на каждом уровне из закрытого набора своего места;
             в named — любые имена, в opaque — не заглядывать (Н1.2)    → иначе отказ со всеми путями, которых нет
4. значения: все числа конечны и в диапазоне Н1.1, в том числе в opaque;
             раздел за разделом: типы, грамматика поля (Н1.3), слова из закрытых перечней, обязательные ключи
             (capacity.default)                                          → иначе отказ(источник, путь, причина)
5. ссылки:   каждая ссылка Н1.4 — на объявленное в этой спеке          → иначе отказ(источник, путь, причина)
6. умолчания: заполнить отсутствующее умолчаниями уроков-владельцев; ослабляющие — только сказанные (Н1.2 lease,
             unplaced, places)
→ спека
```

Порядок шагов 1–3 нормативен: до проверки значений завершена проверка всех ключей; незнакомый ключ отказывается раньше, чем неверное значение в соседнем. Порядок внутри шагов 4–5 — решает реализация.

**Гонки.** Нет: загрузка чистая, без состояния и без хранилища.

### загрузить_каталог([спека…]) → каталог | отказ

Проверки, которым нужна не одна спека: `worker.requests` называет подсистему каталога, принимающую просьбы; `placement.near.sub` называет подсистему каталога, а `near.prefer` — её поля. Каталог — все спеки кластера (все строки `platform/spec/*`); отказ одной спеки каталога — отказ каталога.

**Гонки.** Проверка каталога получает готовый набор загруженных спек; две проверки не меняют входы друг друга.
Чтение источников до неё не обещает атомарного снимка всех файлов или строк. Если файл меняется во время чтения,
могут быть получены прежние, новые либо смешанные байты: допустимый документ загружается, недопустимый даёт отказ
по Н1. Сам факт изменения файла чистая процедура по байтам не обнаруживает. Неразрешённая связь между принятыми
спеками даёт отказ каталога; при любом таком отказе частичный каталог не выдаётся.

### Старт процесса

```
1. прочитать строку platform/spec/<sub> и метку /rev (все — для процессов, которым нужен весь каталог)
                                                                                            → нет строки или нет метки: не стартовать (код 2)
2. sha256 байт yaml равен записанному; у процесса со встроенной спекой — встроенные байты равны строке
                                                                                            → иначе не стартовать
3. загрузить(yaml, "platform/spec/<sub>") и загрузить_каталог                              → отказ: не стартовать
4. запомнить rev строки; служить. Метка ниже строки на старте (установщик между записями) — не отказ: процесс служит по
   строке, а метку сверяет со своей rev, только когда та стала не ниже неё (первая равная — «догнала», без перезапуска)
```

«Не стартовать» — завершиться с ненулевым кодом и строкой лога, называющей источник и путь. Процесс НЕ ДОЛЖЕН служить без отказанной подсистемы или с прежней спекой.

**Гонки.** Установщик пишет строку, потом метку. Процесс, стартовавший между ними, прочёл новую строку (rev 2) и прежнюю метку (rev 1): он служит по строке и, пока метка ниже его rev, не считает её сменой (шаг 4). Когда установщик доведёт метку до того же числа, перезапуска не будет; сменой считается метка с rev, отличной от запомненной и **не ниже** её. Процесс, прочитавший старую строку до записи новой, перезапустится после чтения новой метки. Один период обнаружения смены отсчитывается **от публикации новой метки**, при успешном чтении хранилища. Если установщик умер после записи строки, но до метки, старые процессы ещё видят прежнюю метку, а новые могут стартовать по новой строке. Их работа по разным ревизиям не ограничена этим периодом: метку доводит следующий `spec put`, срок его вызова не задан (гонки смены ниже).

### Смена спеки

```
установщик spec put <файл>:
  загрузить(байты, файл)                                → отказ: файл не кладётся, код возврата 2
  прочитать строку и метку
  строка есть и те же yaml и shell                      → «без изменений»; метки нет или она ниже строки → довести (ниже); выход 0
  строки нет                                           → новая rev := 1; условие cas := "" (создать, пока строки нет)
  строка есть                                          → новая rev := прежняя rev + 1; условие cas := прочитанная версия строки
  записать строку {yaml, shell (если страницы есть), sha256: sha256(yaml), rev: новая rev} с этим cas
                                                         → конфликт: перечитать и повторить
                                                         → toolarge: прекратить установку, код 2; stderr называет файл,
                                                           ключ platform/spec/<sub>, вес строки и потолок;
                                                           этот вызов не меняет строку и не переходит к записи метки
  довести метку: метки нет → записать {rev, sha256} строки с cas ""; есть и rev метки < rev строки → записать с cas по её версии
                                                         → конфликт: перечитать метку и повторить, пока она ниже строки; не ниже — ничего
работающий процесс, на каждом проходе и не реже чем раз в 30 с (ADR-0068):
  прочитать метку; rev метки ≥ запомненной и не равен ей, или метки нет → как смена: остановиться с кодом 0; супервизор запускает
  заново; метка ниже запомненной (установщик ещё не довёл её) — не смена, ждать
старт процесса: строки нет, не читается, sha256 не тот, спека отказана, встроенная не совпала (кластер из одного процесса)
                                                         → не старт, код 2, без перезапуска (ADR-0068)
```

**Гонки.** Два установщика разом: `cas` по строке пропускает одного, второй перечитывает и либо видит «без изменений», либо кладёт свою ревизию поверх; первое создание с `cas: ""` выдаёт rev 1, каждое последующее изменение поднимает rev на один. Метка только поднимается: её запись обусловлена `cas` и условием «ниже строки», поэтому отставший установщик (записал строку rev 2, задержался, другой успел положить rev 3 и метку 3) метку не понизит — его запись не проходит. Метка выше строки невозможна: пишется после строки и из неё. После смерти установщика между строкой и меткой метка остаётся позади, пока следующий `spec put` не доведёт её (в том числе в ветке «без изменений»); автоматического доведения этим проходом нет, срока следующего вызова нет. `spec status` только показывает расхождение (ADR-0068). Срок обнаружения смены работающими процессами начинается после публикации метки, а не после записи основной строки.

предыдущая основная строка и метка не меняются этим вызовом. В описании реализации указываются места
обработки этого отказа и формирования диагностики; прохождение загрузчика не выдаётся за эту проверку.

Диагностика проверяется отдельными ожиданиями `diagnostics.tsv`: `unknown_depth4` — полный путь опечатки,
`unknown_multiple` — все три неизвестных пути в одном отказе, `dup_top_key_name` — путь и строка повторного ключа.
Восемь случаев float/JSON проверяют путь отказанного числа, включая вложенный default. Диагностика прочих ветвей Н4 проверяется чтением: `verdicts.tsv` задаёт лишь вердикт, а ожидаемые пути и строки
для них пока не перечислены. В описании реализации указываются места, где каждая такая ветвь добавляет источник,
путь и, для ошибки текста, строку; прохождение таблицы вердиктов само по себе этого не доказывает.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **сводный закрытый перечень ключей** по уровням, каким его проверяет шаг 3 прохода (таблица в коде или данных), и как он сверяется с перечнями уроков-владельцев;
2. **сколько ошибок значений называет один отказ** (первую или все); незнакомые ключи называются все — норма Н3 шага 3, не выбор;
3. **форма строки лога** при остановке по смене метки (период не реже 30 с и код 0 — норма Н3, ADR-0068);
4. **форма строки лога** при отказе старта (код 2 — норма Н3, ADR-0068);
5. **имя и форму команды установщика** (`spec put`, `spec status`), где лежит исходный файл и как из него делаются права (урок 6);
6. **предел размера** строки спеки;
7. **способ хранения встроенной спеки** у процесса, который не читает хранилище при старте (кластер из одного процесса), и как он сверяет её с строкой.
