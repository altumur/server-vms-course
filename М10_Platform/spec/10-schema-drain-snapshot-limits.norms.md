## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](01-storage.norms.md#время-в-строке): `platform/schema` — `at`; объект `<sub>/snapshot/<воркер>` — `ts`; надгробие `.gone/<ключ>` — `written`; `<sub>/sweep` — `at`; штампы строк таблиц — `at`, `made_at`.

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `platform/schema`, `<sub>/snapshot/<воркер>`, `<sub>/snapshot/unplaced`, `<sub>/blobs/sha256-<hex>`, `.gone/<ключ>`, `<sub>/sweep`, `<sub>/<spec:tables>/<имя>`;
- пишет: `platform/drain` (put), `<sub>/<spec:unit.rows>/<id>` (cas);
- читает: `platform/spec/<sub>`, `<sub>/heartbeats/<имя>`, `<sub>/slots/<имя>`, `<sub>/workers/<имя>`, `<sub>/<spec:unit.rows>/<id>`, `platform/resources/<server>/heartbeat`, `platform/mirror`.

### Н1.1 Схема

```yaml
platform/schema:  {version: <целое ≥ 1>, at: <момент>}     # писатель — консоль (admin); нет строки = схема сборки (свежая установка)
SCHEMA:   число, которое понимает сборка; поле добавить — без нового номера; смысл поля сменить — новый номер
BUILD:    слово сборки для человека (env BUILD, умолчание dev); машина читает SCHEMA
heartbeat: каждый пульс воркера и ресурса несёт schema и build (урок 5); schema — целое JSON без дробной части и
          экспоненты (форма int урока 3 Н2), ≥ 1; `1.0`, `1e0`, `-1`, строка, null — схема процесса неизвестна (null в
          `processes`, Н2) (сверка python и go М10/6–11, T3); build — строка; не строка — `""` (сверка python и go М10/6–11, T27)
check:    при старте контроллера, воркера, ресурса и консоли: version > SCHEMA → не стартовать; строка не число → не стартовать;
          воркер проверяет и при продлении слота — сборка, которую хранилище переросло, отсекается и не воссоединяется
raise:    только оператор, PUT /schema?version=N в окне обслуживания Н3; назад — отказ; своя сборка и все живые процессы понимают ≥ N
```

### Н1.2 Дренаж

```yaml
platform/drain:  {server: <сервер> | "", at}          # один сервер за раз; писатель — консоль (admin); читает контроллер (урок 4)
state:
  draining:        <сервер> | ""
  safe:            все подсистемы safe
  would_strand:    {<sub>: [id…]}                      # проба без моделирования размещения: все единицы воркеров этого сервера
                                                         # и все неразмещённые (урок 4 Н2.2)
  subsystems:      {<sub>: {draining, subsystem, workers, units, pending_writes, pending_unsaid?, would_strand, safe}}
  safe(sub):       units == 0 ∧ pending_writes == 0 ∧ pending_unsaid пуст
  pending_writes:  Σ по воркерам сервера поля пульса pending_writes — целое JSON без дробной части и экспоненты,
                   0 ≤ x ≤ 2^53 − 1 (форма int урока 3 Н2): базовый воркер платформы (урок 5) пишет
                   в пульс 0 сам, если подсистема не сказала своё (подсистема с буфером на диске говорит своё число);
                   поля нет / слово / дробь, в том числе `0.0`, `1000.0`, `-0.0`, `1e3` / больше 2^53 − 1 / нечитаемый или
                   устаревший пульс → pending_unsaid (дренаж не safe) (сверка python и go М10/6–11, T1, T3, T4)
  server_of:       воркер сервера — по полю server читаемого пульса; пульс не читается — по server его слота
                   `<sub>/slots/<имя>` (урок 3 Н1.4): такой воркер — в pending_unsaid, единицы его назначения
                   `<sub>/workers/<имя>` — в units и would_strand (сверка python и go М10/6–11, T2)
journal:  drain.started {server, user}; drain.ended {server} — других видов журнала дренажа нет (`drain.cleared` нет)
          (сверка python и go М10/6–11, T22)
          # все журналы консоли этого урока (schema.raised, drain.*, <t>.written/<t>.deleted, unit.changed) — дерево
          # audit/console (урок 8 Н1.2 journal, роль console)
```

### Н1.3 Снимок

```yaml
<sub>/snapshot/<воркер> | <sub>/snapshot/unplaced:     # объекты; писатель — контроллер; имя воркера unplaced — отказ
  {cluster, worker: <имя> | null, ts, <rows>: [{id, revision, <поля snapshot:>, worker, server}]}
cluster:  имя установки — CLUSTER окружения (М10/11 Н1.2; имя члена домена, М11/1 Н1.1); не задано — "local" (вне домена)
fields:   snapshot: спеки (урок 2): нет ключа — все поля кроме *_secret и blob; [] — ни одного поля (id, revision, worker, server
          остаются); авторское поле server также исключено по умолчанию; секрет, blob или server в явном списке — спека не грузится; адреса — с маской
          урока 7 Н1.1а, той же, что в выдаче консоли (пароль → ***)
          объявленные поля единицы не включают platform_fields М10/3, включая deleted/worker: отказ загрузки М10/2;
          unit.rows не cluster/worker/ts: коллизия оболочки — отказ загрузки refused:value (М10/2)
publish:  после каждого прохода контроллера (урок 4), вне шагов его отчёта; шарды ушедших воркеров — пустые; без единиц — пустой unplaced
garbled:  строка единицы, чьё поле snapshot не читается своим типом по values_by_type урока 3 Н1.2, в шард не входит;
          шард публикуется с остальными единицами, строка лога раз на серию и счёт `snapshot_rows_garbled` отчёта прохода
          урока 4 Н1.2 (М10/1 Н0 «Устойчивость выдачи») (сверка python и go М10/6–11, T7)
ceiling:  L = min(max_bytes хранилища при max_bytes > 0, 64 МиБ двери ресурса); при max_bytes = 0 L = 64 МиБ.
          Размер — число байтов полного сериализованного объекта, включая оболочку и пустые шарды, с фактической
          записью ts (её длина входит в размер) (сверка python и go М10/6–11, совпало без нормы).
          Ровно L разрешено; больше L → TooLarge до put_durable, прежний шард не заменять.
          Диагностика: «N units on <шард>; snapshot is B bytes, limit is L bytes»; увеличение OBJECTS не снимает предел двери
age:      читатель — консоль на /metrics; возраст шарда — время по её монотонным часам с последней смены его содержимого,
          увиденной ею (первый взгляд — 0; урок 3 Н1.4 «возраст наблюдаемой версии»); ряд — максимум по шардам подсистемы;
          ошибка чтения не обновляет возраст и не означает свежий снимок; нет ни одного успешного наблюдения → -1 с диагностикой;
          шард не JSON или не объект шарда — пропущен и посчитан, /metrics — 200 с остальными (М10/1 Н0 «Устойчивость
          выдачи»), не 503 (сверка python и go М10/6–11, T6)
metrics:  <sub>_snapshot_age_seconds (−1 — нет ни одного успешного наблюдения шарда: не публиковали или консоль не прочла); <sub>_snapshot_ahead_shards — шарды, чей ts больше стенных часов консоли + 60 с;
          <sub>_snapshot_garbled_shards — шарды подсистемы, которые последнее чтение консоли не прочло (сверка python и go М10/6–11, T6)
```

### Н1.4 Потолки

Проверяются у двери до чтения тела, где возможно; отказ — не усечение. Ответ отказа до чтения тела доходит до клиента
по правилу урока 1 Н2.1 «Ранний отказ».

| Что | Предел | Где | Слова / код |
|---|---|---|---|
| строка хранилища (ключи + значения) | 512 КиБ | дверь хранилища и автомат (урок 1) | `413 toolarge`, `size`, `limit` |
| одно `json`-поле | 4000 байт канонического JSON | дверь единиц и таблиц | `400`, `fault: too_long`, `error` «<поле> is N bytes of JSON; the ceiling is 4000» (сверка python и go М10/6–11, T24) |
| тело запроса консоли | ≥ 1 МиБ (решает реализация) | до чтения, по заголовку | `413`, `detail` «a body of N bytes; this door takes at most L here» (сверка python и go М10/6–11, T25); chunked — `400` |
| глубина JSON тела | 64 | дверь | `400` «nests deeper than 64 levels» |
| тело (`blob`) через консоль | 32 МиБ | до чтения | `413`; одновременно — 2, дальше `503 Retry-After` |
| объект у двери ресурса (чтение, копия тела, кусок зеркала) | 64 МиБ | дверь ресурса (урок 8 Н2) | `413` |
| строк в ответе `/events` | 1000 по умолчанию, 10 000 предел | индекс (урок 8 Н1.3) | обрезка, `truncated` |
| глубина YAML спеки | 64 | загрузчик (урок 2) | отказ загрузки |
| глубина JSON Schema | 32 | загрузчик (урок 2) | отказ загрузки |
| ключ строки | 1024 байта | дверь (урок 1) | `400 badkey` |
| `Idempotency-Key`, `rid` | 200 байт UTF-8, один сегмент | дверь владельца (уроки 3/8) | `400` |
| имя единицы | один сегмент; полный ключ `<sub>/<rows>/<id>` ≤1024 байт UTF-8 по М10/1/3, с учётом объявленного меньшего предела хранилища | дверь единицы | `400 badkey` при непредставимом ключе |
| текст `error` метки | 200 знаков | держатель (урок 8 Н1.5) | усечение с «…» |
| список уборки | 64 дайджеста за проход | консоль | — |
| срок хранения | конечное число > 0 | ресурс (урок 8) | «не известно», ничего не убирать |
| хранилище объектов | `max_bytes` (0 — без потолка); хранилище само говорит | `put` | `TooLarge` «over this store's limit» |

### Н1.5 Тела

Blob объявляется только в unit.fields; blob в таблице вне профиля и отвергается загрузчиком.
Имя blob-поля — 1–64 ASCII: первый A-Z/a-z/_, остальные A-Z/a-z/0-9/_.
Пустое имя, разделитель пути, точка, процент, пробел, управляющий или не-ASCII символ
не представляют blob-дверь этого урока: отказ загрузки `refused:value` с путём поля.
Прочие поля этим ограничением автоматически не сужаются.

Спека с любым blob-полем единицы не объявляет unit.fields.bytes: отказ загрузки
`refused:value` по М10/2. Без blob поле bytes допустимо. Это ограничение сохраняет
полную Unit в ответе загрузки; переименование счётчика или новая оболочка не вводятся.

```yaml
field:    type: blob; в строке — "sha256-<64 hex>"; байты в теле строки → 400 «takes a digest, not the bytes (N of them):
          PUT the bytes to /<rows>/<id>/<поле> and the row gets the digest back»; в snapshot — спека не грузится
object:   <sub>/blobs/sha256-<hex>; имя — дайджест байтов; читатель сверяет (BlobMismatch — «the object was replaced»)
write:    объект прочно (fsync) → строка с дайджестом (revision + 1) → журнал unit.changed {fields, revision, digest}
mirror:   каждое локальное тело — следующим copies живым соседям кольца (урок 8), всегда, независимо от mirror.enabled;
          copies — из строки platform/mirror (целое ≥ 0), строки нет или copies не читается — 1 (журнал cammeta-go, урок 10 № 1);
          приём: хэш по мере чтения; PEER_FAILS 3; дверь копии есть только у ключа `<sub>/blobs/sha256-<64 строчных hex>`
          подсистемы с blob-полем; иной ключ (заглавные hex, без `sha256-`, подсистема без blob-поля) — обычный объект,
          его пишет владелец: 405 (сверка python и go М10/6–11, T11)
delete:   надгробие .gone/<ключ> у удалившего — объект {written, peers, acked}: written — стенные секунды удаления, peers —
          соседи кольца, у которых могла быть копия, acked — подтвердившие (журнал cammeta-go, урок 10 № 2); сосед раз в
          10 мин (проход ресурса) читает надгробия удалившего листингом /v1/objects?prefix=.gone/ (обычный листинг .gone/ не
          показывает, записи и удаления .gone/ дверь не принимает) и роняет копию старше written; удаливший раз в 10 мин
          спрашивает каждого из peers GET копии: 404 — подтверждение (в acked), копия есть, иной ответ или неответ — нет;
          объект с тем же ключом записан у удалившего снова после written — надгробие снимается без подтверждений;
          надгробие хранится не меньше 7 дней и снимается только когда все peers подтвердили удаление; неизвестный исход не
          подтверждение; у двери объектов DELETE нет
sweep:    <sub>/sweep {at, digests}  — писатель консоль; раз в 60 с
          # байты строки: at — стенные секунды первой отметки партии, текст по values_by_type урока 3 Н1.2 (float);
          # digests — список "sha256-<hex>" по правилу list урока 3 Н1.2 (через запятую); пустая партия — digests: ""
          # или строки нет, at тогда не читается; пример: {at: "1760700000.5", digests: "sha256-ab…,sha256-cd…"}
  mark:   только при пустой прежней партии дайджесты без ссылок из строк (≤ SWEEP_LIMIT 64) → записать с cas; непустую не освежать; ничего не удалять
  wait:   SWEEP_GRACE 300 с
  sweep:  удаление только в исключительном окне обслуживания Н3; обычный фоновый проход лишь отмечает/ждёт.
          После остановки писателей проверить ссылки снова; список снять с cas (конфликт — ничего не удалять); удалить объекты.
          put_blob снимает digest с cas; эта отмена — помощь отметкам, не защита параллельного удаления
  metrics: <sub>_blobs_total, <sub>_blobs_marked — у спек с blob-полем
```

### Н1.6 Объявленные таблицы

```yaml
tables:                                   # спека (форма — урок 2)
  <t>:
    key:      <несекретное поле type string> | <шаблон по М10/2 Н1.4, requests.key>   # число подстановок не ограничено двумя;
                                                     # пример: "{of}-{from:int}-{to:int}"; итоговое имя по Н2
    fields:   {<поле>: {type, required, enum, default, schema, ref, must_match, bound_to, credentials, secret_in, schemes}}
              # без fixed, inherit, merge, unique (урок 2)
    schema:   JSON Schema на всю строку
    stamp:    [by, at, made_at]                   # что консоль дописывает при каждой записи POST:
              # by — пользователь записи; at — стенные секунды этой записи; made_at — стенные секунды первой записи
              # строки, перезапись его сохраняет; в строке хранилища — текст по values_by_type урока 3 Н1.2 (float),
              # в TableRow — by строка, at и made_at числа; пример строки: {by: "admin", at: "1760700000.5",
              # made_at: "1760690000"} → TableRow {…, by: "admin", at: 1760700000.5, made_at: 1760690000}
    journal:  {written: <вид>, deleted: <вид>}    # умолчание <t>.written / <t>.deleted
  list_form:  tables: [<t>] — только имя семьи для прав консоли; дверей нет
field_names: held_by/garbled/by/at/made_at не объявляются (вычисляемые поля и штампы, независимо от stamp); name допустимо только с типом string (явным или по умолчанию) при key: name,
             иначе refused:value при загрузке. Прочие служебные имена единицы (id/revision/worker и т.д.)
             сами по себе полям таблицы не запрещены; значения проверяются по объявлению.
names:      грамматика имени и перечень запрещённых имён таблиц — сводная таблица М10/2 Н1.2а; не значение unit.rows;
            конфликт с любым именем подсистемы каталога — отказ каталога по М10/2 Н3, а не разрешённое пересечение root/mount
rows:       <sub>/<t>/<имя>; писатель — консоль; таблица из worker.writes (урок 6) — таблица воркера, без полей *_secret (урок 2 Н1.2а): он пишет строку целиком с cas,
            консоль только читает (GET с полями), POST/DELETE → 403 denied «written by its worker»; PUT → 405 как неподдержанный метод; секреты запечатаны (урок 7)
held_by:    у таблицы мест (placement.places.table) GET дописывает held_by: <воркер> | null
name:       TableRow.name — элемент name строки, как хранится; ключ `<sub>/<t>/<имя>` — адрес строки; если они разошлись
            (строка записана мимо консоли), GET отдаёт хранимое name (сверка python и go М10/6–11, совпало без нормы)
journal_form: <t>.written {sub, target, user, addr, fields, changed, was}, <t>.deleted {sub, target, user, addr}:
            sub — подсистема, target — `<t>/<имя>`, addr — адрес клиента (урок 8 Н1.2 journal); fields — имена полей
            записи, changed — имена изменившихся, was — true, если строка с этим именем была до записи (булево);
            unit.changed дверью байтов — {sub, target: <id>, user, addr, fields, revision, digest};
            schema.raised — {version, user, addr} (сверка python и go М10/6–11, T21)
rights:     чтение view, запись admin, ниже — по rights.routes; rights.unit_of фильтрует строки и гранты (урок 6)
```

## Н2 Двери

Пути таблиц и blob-полей единицы выбирают root либо /{sub} по М10/9 Н2.
В OpenAPI это стандартные servers + paths. /schema и /drain остаются общими,
/v1/objects — дверью ресурса: префикс консоли к ней не добавляется.

HTTP-контракт: [10-schema-drain-snapshot-limits.api.openapi.yaml](10-schema-drain-snapshot-limits.api.openapi.yaml).

Разбор запроса — урок 9 Н2 «Разбор запроса консоли» (урок 1 Н2.1 с отступлениями консоли; повтор `version` у `PUT /schema` —
400). Отступление двери байтов: тело — байты (`application/octet-stream`), JSON не разбирается. Иной метод у таблицы — `405 {detail: "/<t> takes GET, POST and DELETE of one row", error: "method"}` (контракт — `TableMethod`); метод проверяется до прав на запись. Общие отказы консоли, `HEAD` и предел чтения — М10/9 и полные формы М10/2.

| Дверь | Полное успешное тело / особые отказы |
|---|---|
| GET `/schema` | `{version, understood, builds, can_raise_to, processes, schema_unknown?}`: version — целое ≥1; нет строки — равно understood; испорченная строка — null и `schema_unknown: true` (у читаемой строки поля нет); understood — схема консоли; builds — различные `build` своей сборки (BUILD) и всех процессов processes, по возрастанию байтов UTF-8; processes — по пульсам (Н1.1 heartbeat), ключ с пространством имён: воркер — `<sub>/<имя слота>` (`testsub/w-1`), ресурс — `resource/<сервер>` (`resource/srv-a`); так не сталкиваются слоты разных подсистем с одним `slot.prefix` и сервер с именем слота; контроллер и консоль пульса не пишут и в processes не входят; значение — `{schema: целое ≥1 или null, build, ts, live}`, live — пульс менялся на глазах консоли < 45 с; can_raise_to — минимум understood и схем живых, при неизвестной живой — 0. Нечитаемое хранилище — 503 |
| PUT `/schema?version=N` | 200 `{version: N}`; 409 `{detail, error}` при понижении, испорченной строке, своей/живой старой сборке или конфликте CAS. Версия — десятичная строка положительного целого без знака и ведущих нулей, без верхней границы формы: N больше своей SCHEMA — 409 (Н3 шаг 3), а не 400; строка `platform/schema` с таким числом — GET отдаёт его точным числом JSON (сверка python и go М10/6–11, совпало без нормы). N, равная version строки (или understood при её отсутствии), разрешена: проверки Н3 пройдены — строка переписывается с новым at (cas), журнал schema.raised |
| GET/POST/DELETE `/drain` | Точные `DrainState`, `DrainStarted`, `DrainCleared` и отказы М10/4. После DELETE снят только дренаж: draining="", счётчики 0, safe=true; проба неразмещённых остаётся, would_strand не обязана быть пустой. Ключи would_strand/subsystems совпадают по М10/4 |
| PUT `/<rows>/<id>/<blob_field>` | Полная `Unit` М10/3 плюс `bytes` — число принятых байтов; 404 `{detail, error}` для отсутствующей единицы/поля; 409 для CAS; иной метод на этом пути, в том числе GET, POST и DELETE, — 405 (сверка python и go М10/6–11, T9; урок 3 Н2). `Content-Length` обязателен, иначе 400. `If-Match` и `Idempotency-Key` дверь байтов не читает (сверка python и go М10/6–11, совпало без нормы). Нет единицы — 404 `error` «no such unit», нет blob-поля — 404 `error` «no such blob field» (сверка python и go М10/6–11, T26). Каждый успешный новый вызов, даже с прежними байтами, увеличивает revision. Маршрут: любой PUT `/[<sub>/]<rows>/<id>/<x>` — дверь байтов: предел 32 МиБ и одно из двух мест (Н1.4) берутся до поиска единицы и поля; нет единицы или blob-поля `<x>` — 404 после чтения тела |
| GET `/<table>` | `{<table>: [TableRow…]}`; имя свойства равно имени таблицы. GET одной строки — `TableRow`; 404 `{detail, error}` при её отсутствии |
| POST `/<table>` | 201 `{row: TableRow}` — тот же TableRow, что GET одной строки (у таблицы мест — с `held_by`); 400 текстовый или структурный `FormRefusal` М10/3; 409 `ReferenceConflict` либо текстовый отказ. Это полная замена полей по спеке, не patch и не память заявок; Idempotency-Key не делает повтор безопасным |
| DELETE `/<table>/<name>` | 200 `{deleted: имя}`; 404 при отсутствии; 409 — исчерпаны повторы CAS. Ссылки на строку удалению не мешают: `ref` не требует существования цели, `must_match` связывает только с живой целью (урок 3 Н1.3, ADR-0057) |
| PUT ресурса `/v1/objects/<sub>/blobs/<digest>` | 204 без тела. Обязательны длина ≤64 МиБ, `X-Written` — неотрицательное время исходной копии (нет или не число — 400), имя sha256 с 64 строчными hex; байты не того дайджеста — 422; ключ не blob-формы или подсистема без blob-поля — 405, как у любого объекта (Н1.5 mirror; сверка python и go М10/6–11, T10, T11). При чтении проверяются фактический предел/сумма; 400/404/405/408/409/411/413/422/503 — `ResourceError` М10/8, 403 — он либо `ResourceDenied`. Общие отказы консоли сюда не применяются |

`TableRow` содержит обязательное `name`, объявленные поля и stamp; `held_by` добавляется только таблице мест, значение — имя воркера или null. Секретные ключи с суффиксом `_secret` исключаются рекурсивно, адреса маскируются по М10/7. Только уже прочитанная, но испорченная строка — значение объявленного поля не читается своим типом по values_by_type урока 3 Н1.2 — представляется `{name, garbled: true}`; сбой чтения/перечисления — 503, не пустой список и не garbled. Вход POST — собственная TableInput, не ClientFields единицы. Поле, не переданное в POST и без `default`, в строке и TableRow отсутствует: пустая форма урока 3 Н1.2 у таблиц не применяется; `default` подставляется. Необъявленные поля POST отвергаются по спеке; `name` вычисляется по key и может происходить из одноимённого объявленного поля тела. Вычисляемые `held_by`, `garbled` и штампы `by`, `at`, `made_at` клиент не задаёт; переданный штамп — 400 `unknown field`, даже если он не включён в stamp таблицы. Спека с их объявлением как редактируемых полей таблицы вне профиля этого урока и отвергается при загрузке. Формы `SnapshotUnit`/`SnapshotShard` описывают объект снимка, не новый HTTP-маршрут.

JSON-тела читаются с общим пределом ≥1 МиБ, blob с 32 МиБ, копия ресурса с 64 МиБ. Заголовок не заменяет счёт фактических байтов. Плохое framing/короткое тело — 400, таймаут — 408, превышение — 413, chunked консоли — 400. Отказы чтения/доверия/запечатывания дают 503 с полной формой `{detail, error}` по владельцу. Успех публикации объекта не доказывает успех следующей записи строки; при неизвестном исходе клиент сначала читает строку, автоматического повтора PUT/таблицы нет.

### Команда окна уборки

Исключительное окно уборки (Н3 «уборка тел») оператор открывает командой реализации `sweep` (её имя — «Решает
реализация» п. 3) с флагом `--writers-stopped`: им оператор подтверждает строку «допуск удаления» Н3. Команда
обходит все подсистемы каталога с blob-полем, сама выдерживает SWEEP_GRACE как новый наблюдатель версии списка,
затем выполняет фазы sweep и «завершение» Н3.

| Исход | Код выхода | Что сделано |
|---|---|---|
| окно выполнено, в том числе удалять нечего | 0 | doomed удалены, надгробия записаны |
| нет `--writers-stopped`; сбой чтения ссылок или списка; конфликт CAS списка | 2 | ничего не удалено |
| сбой после начала удалений: надгробие или исход удаления не подтверждён | 3 | писателей и копирование не открывать (Н3 «завершение») |

## Н3 Проход

### поднять_схему(N) — консоль, admin

```
1. строка N — только ASCII [1-9][0-9]* целиком (без знака, пробелов и ведущего нуля), значение ≥1 (Н2)                                            → иначе 400 «a version is a whole number from 1»
2. строка platform/schema: не число → 409 «mend the row first»; have > N → 409 «does not go back»
3. своя SCHEMA < N → 409; живые процессы (пульсы менялись на глазах читателя < 45 с):
   любой со schema < N или неизвестной → 409 «still running: …»; ошибка чтения → 503, не пустой состав
4. записать {version: N, at} с cas; журнал schema.raised
```

**Допуск.** Оператор запрещает старты и записи прежних сборок на всё окно, включая молчащие серверы; обновляет весь известный состав и оставляет одну совместимую консоль для подъёма. Пульсы — проверка наблюдённого состава, не доказательство отсутствия старого процесса. Без этого допуска конкурентный подъём вне профиля урока. После успешного CAS можно открывать старты только обновлённых сборок. Два admin всё равно защищены CAS: проигравший перечитывает состояние, не объявляет успех.

| Фаза | Допуск/переход | Отказ |
|---|---|---|
| Открытая установка | Оператор закрывает старты старых сборок, останавливает их писателей | Не удалось подтвердить остановку — не поднимать |
| Обслуживание | Полное чтение схемы и известных процессов; N допускается своей сборкой | Неизвестное чтение — 503; несовместимость — 409 |
| CAS | Зафиксировать версию; при обрыве перечитать | Не считать обрыв откатом |
| Завершено | Вернуть только совместимые сборки | Старая сборка отказывается стартовать |

### старт контроллера, воркера, ресурса или консоли — проверка схемы

Так же стартуют процессы домена — `domain`, агент, консоль домена (М11/12 Н1.8).

```
первым шагом старта, до чтения спеки (урок 2), у всех четырёх процессов:
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
  ошибка чтения → ждать доступности, не начиная работы; не стартовать — выход с кодом 2 и строкой лога
воркер: после каждого успешного продления слота — в шаге аренды и в подмене (урок 5 Н3) — прочитать platform/schema; version > SCHEMA или не число →
  отсечь (урок 5 Н3), отдать_имя(), выход с кодом 2; имени не искать, не воссоединяться; слот не отдаётся
  (released не пишется, отдать() урока 3 — не этот путь): имя освобождается сроком аренды (сверка python и go М10/6–11, T5);
  ошибка чтения схемы → продолжать: судьбу слота решает аренда (урок 5)
```

**Граница.** Демон строкового хранилища не толкует раскладку подсистемы и этой проверкой не блокируется: иначе нельзя было бы открыть хранилище для чтения/исправления схемы; его собственный формат — М10/1 и М10/11 Н1.3 (демон `configstore`: `member.json`, `backup`/`restore`). Проверка при продлении есть у воркера; она не доказывает безопасность всех остальных процессов. Их гонка со стартом исключена окном обслуживания выше. Сбой чтения — ждать доступности без работы; достоверно испорченная/слишком новая схема — отказ старта с кодом 2.

### дренаж — чтение состояния

```
для каждой спеки: воркеры сервера (пульсы; пульс не читается — server слота, Н1.2 server_of) → units = Σ назначений,
pending = Σ pending_writes (нет/слово/дробь/нечитаемый пульс → unsaid; сверка python и go М10/6–11, T2),
would_strand = все единицы воркеров сервера и все неразмещённые единицы подсистемы — без моделирования размещения (урок 4 Н2 `DrainState`)
safe = Σ units == 0 ∧ Σ pending == 0 ∧ unsaid пуст
```

**Гонки.** Контроллер читает draining раз за проход; ранее назначенное может доехать позже. `safe` — вывод по наблюдённым размещениям и свежим известным пульсам, не атомарный снимок и не блокировка новых назначений. Перед выключением оператор прекращает новые записи/назначения на сервер, дожидается завершения начатых действий и повторно проверяет состояние. Не удалось подтвердить покой — выключение откладывается; одного `safe: true` недостаточно.

### снимок — после прохода

```
по воркеру: строки единиц его назначения → [{id, revision, поля snapshot (маска адресов), worker, server}];
строка, чьё поле snapshot не читается своим типом, — пропустить, строка лога раз на серию и счёт в
`snapshot_rows_garbled` отчёта прохода (урок 4 Н1.2; Н1.3 garbled; сверка python и go М10/6–11, T7);
неразмещённые → unplaced; шард, который был и не заполнен → пустой; без единиц → пустой unplaced
сериализовать каждый шард; проверить размер по Н1.3 до записи; больше L → TooLarge, этот шард не писать;
допустимый шард записать; TooLarge хранилища → тот же отказ; ошибка публикации — одна строка лога на серию;
TooLarge до записи сохраняет прежний шард и его время; неизвестный исход записи не доказывает, что шард остался прежним.
При любой ошибке не публиковать пустой шард вместо непроверенных данных
```

**Гонки.** На одном сервере один контроллер спеки; разные серверы могут публиковать разные локальные копии одного логического ключа шарда. Выбор по written не создаёт общий момент чтения. Строки и шарды публикуются по отдельности: снимок — наблюдённая конфигурация, не согласованная резервная копия. Ошибка чтения строк/списка не разрешает публиковать пустой шард; ошибка одной записи не откатывает уже опубликованные. Потребитель проверяет revision и не выводит отсутствие из неполного набора.

### положить_тело(id, поле, байты)

```
1. общий конвейер консоли уже проверил framing, длину и потолок 32 МиБ по заголовку до двери (М10/9 Н3):
   нет Content-Length → 400, выше потолка → 413; затем поле blob и единица есть → иначе 404
2. digest = sha256(байты); снять digest со списка <sub>/sweep (cas), если там
3. put_durable(<sub>/blobs/<digest>) → TooLarge → 413 «a blob is what an object store is for»
4. правка строки {<поле>: digest} с cas, revision + 1; журнал unit.changed
5. перечитать объект blobs/<digest>: нет (уборка сняла его между шагами 3 и 4) → put_durable снова
```

**Гонки.** Две загрузки одинаковых байтов дают один digest; повторный put_durable может сохранить прежний индекс объекта. CAS строки защищает только строку. Параллельное удаление исключается допуском уборки ниже; отмена отметки и контрольное чтение не заменяют этот допуск. Неизвестный исход CAS разрешается чтением строки перед новым действием.

### уборка тел — отметки в фоне, удаление в окне обслуживания

| Фаза | Условия и действие | При сбое |
|---|---|---|
| mark | Каждые 60 с полный успешный обход; если текущая партия digests непуста — не переписывать at/версию и не добавлять новые. Если списка нет/пуст — CAS новой партии ≤64 без ссылок с at первой отметки | Неизвестный обход — ничего не отмечать/удалять |
| grace | Ждать 300 с наблюдения неизменной версии списка по местным монотонным часам. Первый взгляд/новая версия начинают с 0; put_blob может снять отметку | Повторить чтение позже |
| допуск удаления | Один оператор закрывает новые записи единиц/таблиц с blob, blob PUT, импорт/restore и входящие зеркальные копии; ждёт начатые операции. Один уборщик | Неизвестный исход писателя или неподтверждённый покой — удаления нет |
| sweep | В этом же окне перечитать все ссылки и список. doomed = отмеченные без ссылок; снять список CAS; только затем get_at и delete_at каждого doomed старше отметки | Ошибка чтения/конфликт — пропустить удаление, не считать отсутствие доказанным |
| завершение | Прочно записать надгробия удалённым; при частичном сбое сохранить запрет писателей до восстановления надгробий/определения исходов | Не открывать копирование, которое может воскресить удалённое |
| выход | После завершения окна вернуть писателей/копирование | Следующая уборка начинает новый обход |

mark/grace/sweep одного уборщика не пересекаются; в исключительном окне другие уборщики, включая mark, остановлены.

at — диагностическое время первой отметки партии, не скользящий срок. Уменьшение списка не добавляет новый дайджест и начинает новое консервативное окно наблюдения версии; новый наблюдатель всегда ждёт 300 с. Обходы в T0+60…540 не обновляют непустую неизменную партию, поэтому к T0+600 льгота уже выдержана. Новые кандидаты попадут только в следующую партию после опустошения прежней.

В обычном режиме раз в минуту исполняются только mark/grace. Удаление не является автоматическим действием живой установки. `delete_at` и CAS списка предотвращают часть конфликтов, но сами по себе не защищают от новой ссылки после проверки: это обеспечивает только окно без писателей. Полученные до остановки результаты обхода для sweep не используются.


### таблица — записать строку

```
порядок отказов — по шагам, первое нарушение даёт ответ (сверка python и go М10/6–11, T18, T19):
1. любое из by/at/made_at в теле → 400 «unknown field» до вычисления stamp и записи;
   имя из key (поля тела; шаблон): обычный источник — только строка, :int — конечное binary64-число |x|≤2^53−1 без bool, *_secret не допускается загрузчиком; отсутствует/иной тип → 400 «the body does not fill it in»; имя — не путь
   (пусто, `/`, `.`, `..`) → 400; имя проверяется раньше любого поля тела, в том числе необъявленного
1а. необъявленное поле → 400 «unknown field»; затем поля по порядку объявления в спеке: тип (null у поля не json —
   неверный тип, 400; сверка python и go М10/6–11, T15), enum, адрес по правилу поля (`schemes` — урок 3 Н1.3, иная схема — `bad_url`; T14),
   schema поля; затем schema строки
2. поля: типы, required, enum, schema на строку, ref/must_match в обе стороны, то же правило, что у единиц (урок 3 Н1.3) — (а) поля этой строки
   с ref/must_match к их живым целям (урок 3 Н1.3); (б) живые единицы и строки таблиц каталога, чьё поле с ref на эту
   таблицу и must_match называет эту строку, — их значения равны новым значениям строки; нарушение → 409 conflict,
   fault must_match; цель ссылки или ссылающаяся строка не читается → 409 fault garbled (урок 3 Н1.3; сверка python и go М10/6–11, T20); секреты:
   пустой — прежний, смена bound_to без нового секрета — 400 «must be given anew» по правилу урока 7 Н3 шаг 3,
   POST поверх строки с тем же именем — правка этой строки; stamp: by, at, made_at
3. запечатать; записать полную строку с CAS (конфликт → перечитать и снова проверить все зависимости;
   после ограниченного числа конфликтов 409; таблица без revision); журнал <t>.written {sub, target, user, addr, fields, changed, was}
   (форма — Н1.6 journal_form); at и made_at первой записи строки — одно и то же значение (сверка python и go М10/6–11, T23)
```

**Гонки.** Две записи одной строки таблицы: `cas` (урок 3); таблица воркера — один писатель, строкой целиком; консоль её не пишет (Н1).

## Решает реализация

Реализация обязана назвать в своём описании:

1. **предел тела консоли** (≥ 1 МиБ); одновременных тел — ровно два (Н1.4), выбора нет;
2. **хранилище объектов и его потолок** (`OBJECTS` URI, `max_bytes`), где лежат надгробия;
3. **имя команды окна уборки** (её флаг и коды — Н2) и как оператор исключает всех писателей до неё и завершает надгробия после кода 3; состояние сверх `{at, digests}`;
4. **как публикуется снимок** при отказе хранилища (лог раз на серию); период — после каждого прохода (Н1), выбора нет;
5. **способ ожидания между шагами обновления** (опрос, событие, срок); сам порядок обновления — норма урока 11 Н1.7 `upgrade`, не выбор;
6. ~~**откуда берётся `cluster` снимка**~~ — нормировано: `CLUSTER` окружения (Н1.3; М10/11 Н1.2), не задано — `local`.
