## Н1 Форма

### Н1.1 Схема

```yaml
platform/schema:  {version: <целое ≥ 1>, at: <момент>}     # писатель — консоль (admin); нет строки = схема сборки (свежая установка)
SCHEMA:   число, которое понимает сборка; поле добавить — без нового номера; смысл поля сменить — новый номер
BUILD:    слово сборки для человека (env BUILD, умолчание dev); машина читает SCHEMA
heartbeat: каждый пульс воркера и ресурса несёт schema и build (урок 5)
check:    при старте контроллера, воркера, ресурса: version > SCHEMA → не стартовать; строка не число → не стартовать;
          воркер проверяет и при продлении слота — сборка, которую хранилище переросло, отсекается и не воссоединяется
raise:    только оператор, PUT /schema?version=N; назад — отказ; вверх — только когда все живые процессы понимают ≥ N
```

### Н1.2 Дренаж

```yaml
platform/drain:  {server: <сервер> | "", at}          # один сервер за раз; писатель — консоль (admin); читает контроллер (урок 4)
state:
  draining:        <сервер> | ""
  safe:            все подсистемы safe
  would_strand:    {<sub>: [id…]}                      # проба: единицы этого сервера (и неразмещённые), которым вне него места нет
  subsystems:      {<sub>: {draining, subsystem, workers, units, pending_writes, pending_unsaid?, would_strand, safe}}
  safe(sub):       units == 0 ∧ pending_writes == 0 ∧ pending_unsaid пуст
  pending_writes:  Σ по воркерам сервера поля пульса pending_writes (целое ≥ 0; умолчание 0 у базы, подсистема с буфером
                   на диске говорит своё); нет / слово / дробь → pending_unsaid (дренаж не safe)
journal:  drain.started {server, user}; drain.ended {server}
```

### Н1.3 Снимок

```yaml
<sub>/snapshot/<воркер> | <sub>/snapshot/unplaced:     # объекты; писатель — контроллер; имя воркера unplaced — отказ
  {cluster, worker: <имя> | null, ts, <rows>: [{id, revision, <поля snapshot:>, worker, server}]}
fields:   snapshot: спеки (урок 2): нет ключа — все поля кроме *_secret и blob; [] — ни одного поля (id, revision, worker, server
          остаются); секрет или blob в списке — спека не грузится; адреса — с маской
publish:  после каждого прохода контроллера (урок 4), тем же шагом; шарды ушедших воркеров — пустые; без единиц — пустой unplaced
ceiling:  шард больше потолка объекта → TooLarge «N units on <шард>; the snapshot is already one object per worker,
          so the store is the thing to change (OBJECTS=…)»
age:      возраст самого старого шарда по часам читателя (смена на его глазах); нечитаемый шард — возраст now; не публиковали — нет
metrics:  <sub>_snapshot_age_seconds (−1 — не публиковали); <sub>_snapshot_ahead_shards — шарды с ts дальше 60 с вперёд
```

### Н1.4 Потолки

Проверяются у двери до чтения тела, где возможно; отказ — не усечение.

| Что | Предел | Где | Слова / код |
|---|---|---|---|
| строка хранилища (ключи + значения) | 512 КиБ | дверь хранилища и автомат (урок 1) | `413 toolarge`, `size`, `limit` |
| одно `json`-поле | 4000 байт канонического JSON | дверь единиц и таблиц | `400`, `fault: too_long`, «is N bytes of JSON; the ceiling is 4000» |
| тело запроса консоли | ≥ 1 МиБ (решает реализация) | до чтения, по заголовку | `413` «a body of N bytes; this door takes at most L here»; chunked — `400` |
| глубина JSON тела | 64 | дверь | `400` «nests deeper than 64 levels» |
| тело (`blob`) через консоль | 32 МиБ | до чтения | `413`; одновременно — 2, дальше `503 Retry-After` |
| объект у двери ресурса (чтение, копия тела, кусок зеркала) | 64 МиБ | дверь ресурса | `413` |
| строк в ответе `/events` | 1000 по умолчанию, 10 000 предел | индекс | обрезка, `truncated` |
| глубина YAML спеки | 64 | загрузчик (урок 2) | отказ загрузки |
| глубина JSON Schema | 32 | загрузчик | отказ загрузки |
| ключ строки | 1024 байта | дверь (урок 1) | `400 badkey` |
| `Idempotency-Key`, `rid`, имя единицы | 200 байт, один сегмент | дверь | `400` |
| текст `error` метки | 200 знаков | держатель | усечение с «…» |
| список уборки | 64 дайджеста за проход | консоль | — |
| срок хранения | конечное число > 0 | ресурс (урок 8) | «не известно», ничего не убирать |
| хранилище объектов | `max_bytes` (0 — без потолка); хранилище само говорит | `put` | `TooLarge` «over this store's limit» |

### Н1.5 Тела

```yaml
field:    type: blob; в строке — "sha256-<64 hex>"; байты в теле строки → 400 «takes a digest, not the bytes (N of them):
          PUT the bytes to /<rows>/<id>/<поле> and the row gets the digest back»; в snapshot — спека не грузится
object:   <sub>/blobs/sha256-<hex>; имя — дайджест байтов; читатель сверяет (BlobMismatch — «the object was replaced»)
write:    объект прочно (fsync) → строка с дайджестом (revision + 1) → журнал unit.changed {fields, revision, digest}
mirror:   каждое локальное тело — следующим copies живым соседям кольца (урок 8), всегда, независимо от mirror.enabled;
          приём: хэш по мере чтения; PEER_FAILS 3
delete:   надгробие .gone/<ключ> у удалившего; сосед сверяется с надгробиями раз в 10 мин и роняет копию старше надгробия;
          надгробие живёт 7 дней и снимается только когда все соседи ответили; у двери объектов DELETE нет
sweep:    <sub>/sweep {at, digests}  — писатель консоль; раз в 60 с
  mark:   дайджесты без ссылок из строк (≤ SWEEP_LIMIT 64) → записать с cas; ничего не удалять
  wait:   SWEEP_GRACE 300 с
  sweep:  проверить ссылки снова; список снять с cas (конфликт — ничего не удалять); удалить объекты; загруженное заново
          между отметкой и уборкой из списка уходит при записи строки (put_blob снимает дайджест с cas)
  metrics: <sub>_blobs_total, <sub>_blobs_marked — у спек с blob-полем
```

### Н1.6 Объявленные таблицы

```yaml
tables:                                   # спека (форма — урок 2)
  <t>:
    key:      <поле> | "{поле}-{поле:int}"      # имя строки из полей; {:int} — целая часть числа (урок 2 Н1.4, requests.key)
    fields:   {<поле>: {type, required, enum, default, schema, ref, must_match, bound_to, credentials, secret_in, schemes}}
              # без fixed, inherit, merge, unique (урок 2)
    schema:   JSON Schema на всю строку
    stamp:    [by, at, made_at]                   # что консоль дописывает
    journal:  {written: <вид>, deleted: <вид>}    # умолчание <t>.written / <t>.deleted
  list_form:  tables: [<t>] — только имя семьи для прав консоли; дверей нет
names:      не rows, policy, slots, holds, epoch, idem, requests, asked, servers, decommissioned; не первый сегмент дверей консоли платформы (закрытый список — урок 9 Н2)
rows:       <sub>/<t>/<имя>; писатель — консоль; таблица из worker.writes (урок 6) — таблица воркера: он пишет строку целиком с cas,
            консоль только читает (GET с полями), POST/PUT/DELETE → 403 denied «written by its worker»; секреты запечатаны (урок 7)
held_by:    у таблицы мест (placement.places.table) GET дописывает held_by: <воркер> | null
rights:     чтение view, запись admin, ниже — по rights.routes; rights.unit_of фильтрует строки и гранты (урок 6)
```

## Н3 Проход

### поднять_схему(N) — консоль, admin

```
1. N — целое ≥ 1 (Н1)                                            → иначе 400 «a version is a whole number from 1»
2. строка platform/schema: не число → 409 «mend the row first»; have > N → 409 «does not go back»
3. живые процессы (пульсы < 45 с): любой со schema < N или неизвестной → 409 «still running: …»
4. записать {version: N, at} с cas; журнал schema.raised
```

**Гонки.** Два `admin` поднимают схему разом: `cas` строки схемы — второй 409; подъём против старта процесса: процесс читает схему при старте и при каждом продлении (урок 3), старший уровень — остановка с кодом 0.

### старт процесса — проверка схемы

```
прочитать platform/schema: нет → своя SCHEMA; не число → не стартовать; version > SCHEMA → не стартовать
                                                                 («store is at schema N; this build understands M»)
воркер: та же проверка при каждом продлении слота: хранилище ушло вперёд → отсечься, имени не искать
```

**Гонки.** Нет: схема читается раз при старте; подъём после чтения ловится продлением.

### дренаж — чтение состояния

```
для каждой спеки: воркеры сервера (пульсы) → units = Σ назначений, pending = Σ pending_writes (нет/слово → unsaid),
would_strand = единицы сервера и неразмещённые, которым eligible вне сервера никого не находит (проба, без записи)
safe = Σ units == 0 ∧ Σ pending == 0 ∧ unsaid пуст
```

**Гонки.** Дренаж против новых единиц: контроллер читает `draining` раз на проход; единица, назначенная до чтения, доезжает и уезжает следующим проходом; `safe` считается по пульсам одного снимка.

### снимок — после прохода

```
по воркеру: строки единиц его назначения → [{id, revision, поля snapshot (маска адресов), worker, server}];
неразмещённые → unplaced; шард, который был и не заполнен → пустой; без единиц → пустой unplaced
записать объекты; TooLarge → перебросить со словами о числе единиц; ошибка публикации — одна строка лога на серию
```

**Гонки.** Два контроллера одной спеки на сервере невозможны (один на спеку на сервер, урок 11); контроллеры разных серверов пишут каждый свой объект, читатель берёт свежую копию по `written` (урок 8 Н1.1).

### положить_тело(id, поле, байты)

```
1. поле blob, единица есть                                       → иначе 404; размер по заголовку ≤ 32 МиБ → иначе 413
2. digest = sha256(байты); снять digest со списка <sub>/sweep (cas), если там
3. put_durable(<sub>/blobs/<digest>) → TooLarge → 413 «a blob is what an object store is for»
4. правка строки {<поле>: digest} с cas, revision + 1; журнал unit.changed
5. перечитать объект blobs/<digest>: нет (уборка сняла его между шагами 3 и 4) → put_durable снова
```

**Гонки.** См. «уборка тел»; две загрузки одного тела — один `digest`, `put_durable` идемпотентен; правка строки — `cas`. Ссылка на объект, который уборка уже решила удалить, обычной правкой строки возникнуть не может: правка полей принимает лишь прежний дайджест или `""` (урок 3 Н1.2, шаг 4 создания/правки); новый дайджест вводит только этот проход, а он снимает дайджест со списка до записи и перечитывает объект после (шаги 2, 5).

### уборка тел — консоль, каждые 60 с

```
список = <sub>/sweep; пуст → mark: дайджесты объектов blobs/ без ссылки из строк (≤ 64) → записать {at, digests} с cas
есть, at моложе 300 с → ждать
иначе → проверить ссылки снова; doomed = отмеченные без ссылок; снять список с cas (конфликт → ничего не удалять);
        для каждого из doomed (не из отмеченных: объект с найденной ссылкой не трогать): get_at → индекс и возраст объекта; старше at отметки → delete_at по этому индексу (новая загрузка
        между проверкой и удалением сменила индекс → conflict, объект живёт); надгробие;
        отчёт {marked, deleted, waiting}
```

**Гонки.** Загрузка тела во время льготы: `put_blob` снимает дайджест с `cas` — уборка, перечитав, его не тронет; уборка сняла список первой и удаляет: объект, положенный после `at` отметки, она не трогает (моложе отметки); объект, удалённый между `put_durable` и записью строки, `put_blob` кладёт снова, перечитав его после правки строки (шаг 5); надгробие старше объекта — копия живёт. Два уборщика (две консоли): `cas` на строке пропускает одного.

### таблица — записать строку

```
1. имя из key (поля тела; шаблон) → иначе 400 «the body does not fill it in»; имя — не путь
2. поля: типы, required, enum, schema на строку, ref/must_match (в обе стороны: единицы, указывающие на строку), секреты:
   пустой — прежний, смена bound_to — 400 (урок 7); stamp: by, at, made_at
3. запечатать; записать (последний пишет — побеждает; таблица без revision); журнал <t>.written {sub, target, user, fields, changed, was}
```

---

**Гонки.** Две записи одной строки таблицы: `cas` (урок 3); таблица воркера — один писатель, строкой целиком; консоль её не пишет (Н1).

| Причина | Код / исход | Тело | Что делает вызывающий |

## Решает реализация

Реализация обязана назвать в своём описании:

1. **предел тела консоли** (≥ 1 МиБ); одновременных тел — ровно два (Н1.4), выбора нет;
2. **хранилище объектов и его потолок** (`OBJECTS` URI, `max_bytes`), где лежат надгробия;
3. **состояние уборки в строке** сверх `{at, digests}` и порядок «снять список — удалить»;
4. **как публикуется снимок** при отказе хранилища (лог раз на серию); период — после каждого прохода (Н1), выбора нет;
5. **ночной порядок обновления** (дренаж → остановка → возврат → следующий; подъём схемы последним) — урок 11.
