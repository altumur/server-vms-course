# М10/6 — инструкция для реализации

## Задача

Получить одинаковый ответ оценщика прав в файловом хранилище, памяти и кластере;
генерировать права из каталога спек и показывать загруженный файл только admin.
Настройка пользователя, групп, сокетов и сертификатов связана с уроком 11: юниты Н1.1 (`User=`, `SupplementaryGroups=`), сокеты Н1.3 `sockets`, комплект Н1.6 `kit` и выпуск `w2c-ca.sh`.

## Входы и их приоритет

- Канон — [нормы](06-rights.norms.md), включая закрытую форму файла и приоритеты Н1.3.
- [OpenAPI](06-rights.api.openapi.yaml) задаёт полные тела `/v1/rights` и `/v1/list`.
- [Приёмка](../../Source/tests/testdata/acceptance/М10_Platform/06/README.md) задаёт подготовку и сравнение.
- [Лекция](../06-rights.md) объясняет механизм; операции хранилища принадлежат М10/1.

Проверка JSON не доказывает правильность разрешений. Внутренние классы, функции,
структура индекса образцов и способ интеграции оценщика остаются реализации.

## Что создать

Загрузку файла целиком, единый оценщик, генератор и проверку `--check`; привязку
личности к сокету/писателю и проверку доверенной пересылки. Нужны две HTTP-формы Н2,
исполнитель сценариев под разными ролями и описание выборов «Решает реализация».
Механизм выдачи сертификатов и генератор юнитов сюда не переносятся.

## Порядок работы

1. Зафиксировать набор спек и развёртывание на время генерации/установки. Сверить
   производные имена ролей с Н1.1: ограничение имени спеки уже обеспечивает их длину.
2. Загрузить форму Н1.2 целиком. Различать отсутствие delete и явный пустой список.
   В файле нет внутренних ролей, комментариев синтаксиса JSON и неизвестных полей.
   Необязательный строковый comment — метаданные; изменение его текста не меняет права
   и не сравнивается --check (сравнение по смыслу — Н3 «установить»); /v1/rights его возвращает.
3. Реализовать приоритет проверки из Н3: личность, особая операция list, never,
   разрешение admin/внутренних ролей, оценщик обычной роли, право чтения стража.
   Проверить отрицание при совпавшем разрешении и запреты на каждом действии отдельно,
   включая write/delete epoch_floor. Доверенный пересланный admin без файла разрешён
   после never; с файлом — отказ. Подменённая личность отказывается в обоих режимах.
4. Вывести таблицу Н1.4 по спеке, затем применить читателей секретов из М10/7 Н1.3 (`secrets.readers`, `secrets.reads`, `platform_readers`).
   Проверить точное имя против префикса и эффективное множество читателей, а не
   только присутствие строки в списке. До преобразования отвергать буквальный * и начальные !/delete: в объявлениях; не менять ключ. Проверить соседние vault, vault2, vault/nested: точное объявление vault не меняет их обычных прав. Поле delete генератор выдаёт явно.
5. Проверить две строки допуска контроллера по Н5: read/write разрешены, delete
   запрещён; остальные разрешённые удаления не исчезли. Сверить обе стороны
   boundary консоль/контроллер/воркер, не меняя протокол размещения урока 4.
6. Подготовить стенд по README приёмки: отдельный экземпляр для каждого сценария,
   пустые данные и память повторов, тот же файл прав, фоновые писатели остановлены.
   Выполнить все шаги, в том числе сценарий заголовка на одной коробке: и там хранилище открывает сокет на роль,
   заголовок роли на нём — 403 (Н1.1 `box`).
   У отказа личности проверять роль сокета и причину, у отказа операции — также действие/ключ.
7. Дополнить HTTP-сценарии чтением загрузчика/генератора и проверкой полных ответов Н2.
   Прогнать положительные и отрицательные примеры форм файла и Listing; параметры
   prefix не ограничивать грамматикой ключа. При незагруженном файле rights даёт 404.
8. Проверить все пункты канонического чеклиста. Сокеты, права файлов, TLS и сертификаты
   подтвердить структурным тестом юнитов и тестами центра М10/11 Н5 либо явно оставить без свидетельства
   исполнения: стенда с TLS в приёмке М10/11 нет, проверяется чтением (стенд урока 11).

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.1 | Имя роли усекли или заменили общим controller | Сохранить имя спеки и суффикс; текущие пределы совместимы |
| Н1.2 | Пустой delete подменён write через проверку «ложности» | Умолчание только при отсутствии поля |
| Н1.2/Н1.3 | Общий glob трактует звёздочку в середине как шаблон | Исполнить только точное имя/конечный префикс; прочее не совпадает |
| Н1.3 | Первое разрешение завершает поиск до отрицания | Отрицания имеют приоритет независимо от позиции |
| Н1.3/Н3 | admin отсутствует в roles и потому отказывает, list требует read | Явно исполнить особые правила после проверки личности |
| Н2 | Файл обёрнут в дополнительный объект, возвращены значения в list | Сверить целое тело с контрактом и смыслом Н2 |

## Готово, когда

Выполнен весь чеклист М10/6, названы выборы реализации, приёмка исполнена с указанной
изоляцией и исключениями. Свидетельства чтения называют файлы и проверенный предмет:
генератор, эффективность прав, never, отрицания, доверенная пересылка и настройки ОС.
Новый файл применяется при перезапуске; живое или атомарное переключение кластера
не выдаётся за требование этого урока. Проверка спецификации и запуск стенда — разные результаты.

## При расхождении

Сопоставить вход и исход с Н1–Н4, затем с файлом приёмки. Сообщить «Спецификации» место,
контрпример, происхождение относительно исходного среза и предлагаемое решение.
Решение меняет канон и связанные места; произвольное поведение реализации не дополняет норму.
