## Н1 Форма

### Н1.1 Что секрет

```yaml
secret_field:
  rule:   имя поля оканчивается на _secret — и только это; реестра нет; secret_note — не секрет
  type:   string (в строке — конверт); в спеке у поля: bound_to, иначе как у строки
  where:  поля единицы, поля таблиц, строки платформы (М11: domain/signer {issuing_key_secret, …}, door/signer
          {kid, seed_secret}, domain/member-key {seed_secret, …}, domain/break-glass/<к> {pwhash_secret, …}, …)
url_field:                                   # у поля type: url (форма — урок 2)
  credentials: {login: <поле строки, не url и не секрет>, secret: <поле *_secret>}
  secret_in:                                 # список, каждый элемент одного из трёх видов
    - {param: [<имя>…], login: [<имя>…]}     # имя: слово | =слово (целиком) | слово* (начало) | *слово (конец);
                                             # login ⊆ param — отказ, но не маска
    - {regex: '…(?P<login>…)(?P<secret>…)(?P<name>…)', in: path | query | authority | fragment | [список],
       schemes: [<схема>…], decoded: true | false}      # RE2; группы только login, secret, name; хотя бы одна из двух
    - {nested: [<имя>…]}                     # значение пары читается как адрес, не глубже 3
  bound_to: <поле> | [<поле>…]               # только у *_secret; одно имя — список из одного, /spec отдаёт списком (урок 2 Н2); поля той же строки, не секреты: адрес, к которому пароль
common_words: [password, passwd, pass, pwd, secret, token, key, credential, credentials, psk, privkey, apikey, =auth, =pin]
normalisation: percent-декодирование до неподвижной точки, NFKC, удалить U+200B ZERO WIDTH SPACE из имени параметра,
               свёртка регистра, часть после последней точки,
               слова по _ - + пробел и смене регистра (границы сохранить до свёртки), хвостовые цифры отброшены;
               преобразуется только имя для распознавания, не значение секрета/конверт/AAD; маска заменяет значение в исходном URL
mask:   "***"                                # показ непустого секрета; пустой — пустой; в адресе — где стоит
mask_in: значение из ≥ 3 знаков множества «* ＊ ∗ ⁎ ✱ • ● ∙ · ⋅ ◦ ○ ⚫» (пробелы по краям не в счёт) — отказ;
         a***b — пароль
```

### Н1.2 Конверт и кольцо

```yaml
envelope:  enc:v2:<kid>:<nonce>:<ct>
  kid:     ^(?!#)[^:\s]+(?![\s\S]); new → k1; rotate → k<max+1>
  nonce:   12 случайных байт, base64url без =
  ct:      AES-256-GCM(key, nonce, plaintext, aad) с тегом (16 байт), base64url без =
  aad:     <ключ строки> + "\0" + <имя поля>      # вложенный в JSON-элемент секрет: <ключ строки>#<элемент>, внутреннее имя
  plain:   байты UTF-8 значения как дано, без нормализации; пустое и уже запечатанное не запечатываются
  looks:   всё, что начинается с enc: — считается конвертом (на входе — отказ)
ring_file:                                   # SECRETS_KEY=<путь>; умолчание /etc/w2c/secrets/platform.key
  line:    <kid> <64 hex>                    # 32 байта ключа; первая запись ключа — текущая; пустые строки и отдельные строки комментариев пропускаются
  mode:    0640 root:w2c-secrets; каталог не доступен прочим; файл НЕ внутри каталога хранилища, объектов или их копий
  holders: группа w2c-secrets: консоль, воркеры, которым секрет нужен (камера, рекордер, шлюз), подписант домена, агент
           домена; контроллер, ресурс, консоль домена — без ключа
rotate:    новая строка сверху → перезапуск держателей → консоль при старте перезапечатывает свои строки под текущий kid
           (cas, revision не растёт) → secrets seal дозапечатывает остальное → status; все старые ключи сохраняются
no_key:
  unset:        SECRETS_KEY не задан → режим разработки с громкой строкой лога; чтение/PUT открытых значений сохранены;
                POST создания с переданным непустым *_secret на любой глубине запрещён до заявки (400, Н4)
  unreadable:   задан, но не читается → все POST/PUT единиц отказываются 503 `unavailable` (Н4),
                включая тело без секретного поля: кольцо нужно также для HMAC памяти повторов. Это не режим без ключа; GET/DELETE этим отказом не блокируются
  open_without: конверт без ключа / с чужим kid → Sealed «sealed and this process has no key» / «sealed with key <kid>,
                which this process does not hold»; единица не запускается, причина — в её статусе
print:     отпечаток идемпотентности тела с секретом — HMAC исходного запроса под производным ключом кольца
           (hmac:<kid>:<hex>); при повторе — kid сохранённой заявки, не текущий ключ.
           Без кольца POST с непустым секретом вне профиля; маска и голый хэш секретного тела не заменяют HMAC
```

В сообщении open_without `<kid>` заменяется именем ключа конверта, ключевые байты не выводятся.
Строка, первый непробельный знак которой `#`, целиком является комментарием. kid не начинается
с `#`; `#` внутри kid допустим. Запись содержит ровно два поля, разделённых пробелом
или табуляцией; второе — ровно 64 hex-цифры. Встроенные комментарии после записи ключа
не допускаются. Пробелы/табуляции по краям строки игнорируются.
Кольцо содержит хотя бы один ключ, все `kid` различны; пустой или неверный файл считается
нечитаемым, а не незаданным. `new` и `rotate` создают имена `kN`, где N — положительное
десятичное целое без ведущих нулей. Для `rotate` допускается только кольцо с такими именами:
другое имя — отказ команды без изменения файла. Чтение конверта и `seal` сохраняют общую
грамматику `kid` выше. `max+1` вычисляется по числам N, без машинного переполнения; если
реализация не может представить результат, команда отказывает до изменения файла.

Ротацию ведёт один оператор; обычные записи секретов остановлены на время смены кольца,
перезапечатывания и окончательной проверки `status`. Конкурирующие `rotate`, ручная правка
кольца исключены условиями обслуживания. Удаление прежних ключей целиком вне профиля
урока: ноль старых конвертов в status не разрешает удалить ключ. Он может быть нужен
живой pending/done-заявке с `hmac:<kid>:…` и копии, которую status не перечисляет.
Это сужение области команды, а не обещание транзакционного переключения всех процессов.
Переход к незаданному кольцу при сохранённых HMAC-заявках также вне профиля; режим
разработки без кольца начинают с новой пустой памятью заявок. Ротация не меняет уже
сохранённые отпечатки и не пытается восстановить исходный запрос из изменившейся единицы.

### Н1.3 Секретные строки и читатели

```yaml
secrets:                                     # раздел спеки (форма — урок 2)
  readers: {<строка или префикс>: [<роль>…]} # свои секретные строки и кто их читает
  reads:   [<строка или префикс>…]           # чужие секретные строки, которые читает воркер этой спеки
roles:     [console, controller, worker, domain, domainagent, resource, domainconsole]   # закрыто; domainpart снят ADR-0074 п. 6
platform_readers:                            # общая таблица platform_lists.tsv
  domain/break-glass/: [console, domain, domainagent]
  domain/signer:       [domain]
  domain/signer-pending: [domain]           # точное имя, не покрыто `domain/signer`
  domain/book-seal:    [domain]
  domain/users/:       [domain]
  domain/member-key:   [domainagent, console, domain]
  domain/backup:       [console, domain, domainagent]
  domain/backup-taken: [console, domain, domainagent]   # семья копии: три точных имени и префикс, читатели те же, что у backup
  domain/backup-doc:   [console, domain, domainagent]
  domain/backups/:     [console, domain, domainagent]
  door/signer:         []                    # читателя называет спека (cam: [console])
rule:      объявления secrets.readers/reads не содержат буквальный `*`, не начинаются с `!` или `delete:`;
           непредставимое объявление отвергается загрузчиком/генератором до выдачи файла, не экранируется и не усекается.
           Ограничение относится к объявлениям прав, не к общему ключу хранилища М10/1.
           Ключ с `/` на конце — префикс, без него — точный ключ (`domain/backup` не закрывает `domain/backups/*` — потому они названы отдельно);
           книга домена у члена — точное имя `domain/<sub>/<книга>`, её строки по кластерам у держателя — префикс `domain/<sub>/<книга>/` (спека называет оба);
           объявления не пересекаются по закрываемым строкам: два префикса, где один — начало другого (`a/` и `a/b/`), — отказ
           загрузчика; точное имя и префикс с тем же началом (`domain/signer` и `domain/signer-pending`, `domain/backup` и
           `domain/backups/`, `domain/<sub>/<книга>` и `domain/<sub>/<книга>/`) не пересекаются — точное имя закрывает одну строку,
           префикс — строки под `/`; потому «самого длинного совпавшего» нет: у строки ровно одно объявление; строка без читателя не читается никем, кроме admin;
           файл прав не генерируется, если читатели ≠ способные прочесть (урок 6)
```

### Н1.4 Где секрета нет

При создании единицы непереданное строковое поле без default/inherit получает пустую
строку по М10/3 Н1.2. Это относится и к объявленному `*_secret`: пустая строка выдаётся
пустой, непустой секрет — маской. Отсутствие поля у таблицы — другое правило ниже.

```yaml
never:
  reply:     201/200/GET — маска на любой глубине; таблицы — поле отсутствует
  idem:      копия ответа для повтора — с маской
  snapshot:  поля *_secret исключены по умолчанию; названы явно — спека не грузится; адреса — с маской
  domain:    *_secret в domain.edit / shared / show — спека не грузится; правка члена с *_secret на любой глубине — 400
  journal:   имена полей, не значения
  heartbeat: конверт, не значение; статус говорит «пароль не открывается: …», не пароль
  log:       MaskLog: Authorization (Basic/Bearer), пары с секретным именем, адреса
  argv:      никогда
  refusal:   текст отказа значение не повторяет
```

## Н2 Двери

Собственной HTTP-двери у урока нет (ADR-0082 доп. 14). Используется
[контракт единиц М10/3](03-units-slots-epochs-lease.api.openapi.yaml), а для чтения строк —
[контракт хранилища М10/1](01-storage.api.openapi.yaml). Здесь задаются правила полей
и отказов секретов поверх этих входов; новые маршруты и копия OpenAPI не создаются.

| Вход | Полное тело по контракту владельца | Ограничение этого урока |
|---|---|---|
| POST единицы, 201; PUT, 200 | CreatedUnit / UpdatedUnit | Непустые секреты маской; `id`, `revision` и прочие поля по М10/3; сохранённый ответ POST также с масками |
| GET списка единиц, 200 | UnitList (`rows`, `configured`) | Маска на любой глубине; таблица отдаётся без секретных полей, её дверь принадлежит М10/10 |
| POST/PUT, 400 | `{detail, error}`; при неверном url также `fault: bad_url` | Обе строки обязательны, значение секрета не повторяется; маска, конверт и смена bound_to не получают `bad_url`; только POST без кольца с непустым секретом — sealing key required без fault по Н4 |
| POST/PUT, 503 при нечитаемом кольце | SealingUnavailable: `{detail, error: "unavailable"}` | detail — `the sealing key is set and does not read`; без fault; общие отказы хранилища/полосы сохраняют собственные формы М10/3 |
| GET строки хранилища | Row либо ForbiddenFault М10/1 | У читателя в items конверт; у нечитателя 403, значение не выдаётся |

Загрузка спеки и правка члена через домен — входы своих уроков; HTTP-отказ домена не
выдаётся за ответ двери единиц. Формы успеха, прочие поля и общие коды транспорта берутся
из указанных контрактов, а не из сокращённых ожиданий TSV. Команды обслуживания:

```
w2cctl secrets new [<путь>]        — создать кольцо (O_EXCL, 0640; путь внутри хранилища — отказ)
w2cctl secrets seal [<префикс>…]   — запечатать/перезапечатать открытые и старые по cas; код 1, если что-то осталось
w2cctl secrets rotate [<путь>]     — новый ключ сверху
w2cctl secrets status [<префикс>…] — clear / current / older / ?; код 1, если есть открытое при наличии кольца
умолчание префиксов: domain/, identity/ и строки единиц и таблиц всех спек
```

Коды `seal`/`status` выше относятся к названным исходам; форма их текстового вывода остаётся
реализации. `new`/`rotate`: успех — 0, отказ — ненулевой код и причина без ключевого материала.
Отказ `new` при существующем файле его не меняет; отказ проверки кольца у `rotate` сохраняет
прежний файл. При недоступности обхода `seal`/`status` не заявляют успешное завершение и не
считают непрочитанные строки отсутствующими. Эта проверка не охватывает резервные копии:
вывод status не является разрешением удалять ключи — в профиле урока они сохраняются,
включая ключи конвертов, копий и отпечатков живых заявок. Вывод из обращения ключей требует
отдельной процедуры и в эту команду не входит (копии — М11).

## Н3 Проход

### создать/править строку единицы, в том числе с секретами (консоль; проход урока 3)

До шага 2 создания М10/3, после проверки заголовка и JSON-объекта, проверить профиль:
при незаданном кольце и переданном непустом *_secret на любой глубине POST даёт
400 без создания/снятия заявки, резервирования номера или записи единицы. Это проверка
входного тела, не маскированного ответа. При наличии кольца остаются порядок формы,
HMAC и владение заявкой М10/3; повторы проверяются под kid сохранённого отпечатка.
Заданное нечитаемое кольцо проверяется после разбора JSON-объекта и до HMAC/заявки/записи
для любого POST/PUT единицы; результат — 503 из Н4. Плохой framing/необъект до этого даёт свой 400.
Это более ранняя проверка того же условия, чем шаг запечатывания ниже; секретов в теле может не быть.

```
1. отказы формы (урок 3, шаг 4): url по правилу поля → bad_url; значение-конверт → 400; значение-маска → 400
2. ключ задан, но не читается                                                  → 503 unavailable (Н4);
   состояние своей заявки — по правилам 5xx и владения М10/3 Н3, чужую заявку не снимать
3. правка: пустое, null или отсутствующее *_secret → прежнее значение; сменилось поле из bound_to при пустом секрете
   → 400 «must be given anew» (проверяется внутри cas против строки как хранится)
4. запечатать каждое непустое *_secret: aad = <ключ строки>\0<поле>; уже конверт — как есть
5. записать строку; ответ — с маской; копия для повтора — с маской
```

**Гонки.** Две правки одной строки: `cas` (урок 3); `bound_to` проверяется внутри мутатора против строки как хранится — смена поля и смена пароля в двух правках разом: одна проходит, вторая перечитывает, видит новое поле и без секрета получает 400 «must be given anew».

### открыть (воркер, start_unit)

```
прочитать строку; для каждого *_secret: не конверт → как есть (строка до ключа); конверт → открыть ключом kid с aad строки и поля
  нет ключа / чужой kid / не открывается                           → Sealed: единицу не запускать, причина в статусе
значение — только получателю (драйверу, клиенту); в памяти, пульсе и логах — конверт
```

**Гонки.** Нет: чтение; кольцо сменилось между запечатыванием и открытием — `kid` конверта называет ключ: открывается им или `Sealed` с причиной.

### перезапечатать при старте (консоль)

```
для каждой строки своих семей: *_secret в открытом виде или под старым kid → запечатать текущим, cas по прочитанной,
revision не менять; enc:v1 — не трогать и считать «?» (мёртвый формат, ADR-0003)
```

**Гонки.** Две консоли перезапечатывают одно при старте: `cas` по строке — вторая видит новый `kid` и ничего не пишет; перезапечатывание против правки оператора — `cas`, проигравший перечитывает.

### Смена кольца: состояния обслуживания

Условия допуска — Н1.2: один оператор, обычные записи секретов остановлены; CAS
перезапечатывания остаётся обязательным. Таблица не вводит новых полей на диске.

| Состояние | Действие | Результат и отказ |
|---|---|---|
| Прежнее кольцо доступно, обслуживание допущено | Проверить кольцо; rotate добавляет новый kN сверху, старые ключи сохраняет | Ошибка проверки оставляет файл прежним; прежние конверты читаются старыми ключами |
| Новый файл установлен, держатели могут иметь старую копию | Перезапустить держателей с новым кольцом; затем консоль | До готовности держателей перезапечатывание не начинать; ошибка перезапуска оставляет обслуживание незавершённым |
| Держатели знают оба ключа | Консоль при старте и seal обходят строки с CAS по Н3 | Конфликт — перечитать; ошибка чтения/записи или неизвестный исход не равны завершению |
| Обход завершён | status проверяет тот же охват | Все прежние ключи сохранить, в том числе для pending/done HMAC и копий; ноль конвертов не разрешает удаление |

После обрыва оператор продолжает с подтверждённого состояния, сохраняя старые ключи;
автоматическое восстановление процесса обслуживания в урок не входит.

### прочитать адрес (любая дверь, принимающая url)

```
разобрать по схемам поля (урок 2); userinfo с паролем → отказ; логин перед @ без пароля → отказ (логин — в поле);
каждая пара имя=значение в query/path/fragment: имя по secret_in.param или общему словарю → отказ, в показе — маска;
regex-правила по in/schemes/decoded; nested — значение пары как адрес, ≤ 3; порт не число → «пароль на месте порта»
показ: логин как написан, пароль — ***, где стоит
```

**Гонки.** Две правки одной строки: `cas` урока 3; проверка привязки — внутри `cas` против строки как хранится, так что «прежний пароль остался у нового адреса» невозможно и при гонке. Смена ключа и держатели: держатели перезапускаются раньше консоли, иначе воркер со старым кольцом не откроет перезапечатанное.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **кто ещё держит ключ** сверх Н1.2 и как ключ попадает в процесс (`LoadCredential`, монтирование, переменная);
2. **как ведёт себя `status`/`seal`** без спек в хранилище;
3. **производный ключ отпечатка** идемпотентности и его строку; исходный запрос включает личность/метод/путь/тело по М10/3, маска не подменяет тело; повтор использует kid сохранённой заявки;
4. **как открывается `door/signer`** (консоль) и где живёт открытый ключ (`door/keys`);
5. **лог-маска**: какие ещё места текста маскируются сверх Н1.4;
6. **на платформах без групп** (macOS) — чем заменены `w2c-secrets` и `InaccessiblePaths`.
