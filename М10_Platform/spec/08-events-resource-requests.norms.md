### Н1.1 Объект

```yaml
object:
  rule:      целиком или никак; последний писатель побеждает; по ключу не ищут; размер — предел хранилища (0 = без)
  api:       put(key, bytes) | get(key) → bytes | null | list(prefix) → [key] (отсортировано, без .tmp) | delete(key)
             | put_new(key, bytes) → conflict, если есть  (создание-однажды) | get_at/put_at (запись по прочитанному индексу)
  key:       <семья>/… ; семьи платформы: heartbeats (P/03.4), contenders (P/03.2), controller (P/04), snapshot, blobs (добавлено М10/10),
             commands (Н1.5 mark) — спека их не называет
  writer:    один каталог — один писатель: worker → <s>/heartbeats/*, <s>/contenders/*;
             controller → <s>/snapshot/* (добавлено М10/10), <s>/controller/*; console → <s>/blobs/* (добавлено М10/10); resource → platform/resources/*
  cluster:   файл на сервере писателя; при чтении свежая копия (written) побеждает; сервер, который не ответил, — missing
  row_object: ключи, чей следующий писатель может быть на другом сервере, — строки хранилища objects/<ключ>
             (objects.rows спеки; commands/* — всегда, у спеки с requests); put_new = запись с cas ""
  ops:       операции объектов сводятся к словарю P/01.1 и его отказам: put_new — «записать, если нет» (conflict, когда есть);
             get_at — чтение с индексом объекта; put_at — запись по прочитанному индексу (иной индекс → conflict, как cas строки);
             put_durable — запись тела целиком с барьером долговечности до публикации (строка ссылается на тело только после
             ответа — урок 10 Н1.5 `write`); delete_at — удаление по прочитанному индексу (иной индекс → conflict, объект не тронут — урок 10 Н1.5 `sweep`); append — дописать строку события в открытый бакет (только его писатель, Н1.2); иных атомарностей нет
  door:      только семьи PLATFORM_DOOR (platform/resources/*, domain/* (М11), */heartbeats/*, */contenders/*, */snapshot/*,
             */controller/*, */blobs/*; snapshot и blobs — добавлено М10/10) и objects.door спеки; иное — 403;
             `*` первой части — подсистема каталога спек: `other/heartbeats/x` без спеки other — 403 (сверка python и go М10/6–11, E5)
  disk:      <PLATFORM_DIR>/objects/<ключ>; каталог 0775, файл 0644; запись — temp + rename под замком каталога
```

Ключ объекта — непустой относительный путь: непустые сегменты, без точных `.`/`..`,
обратной косой черты и управляющих знаков. `prefix` — начало такого ключа, также пустота
или конец `/`; это не полный ключ. Объектная дверь не выдаёт строки-объекты даже из
разрешённого префикса. При равном `written` выбирается сервер с лексикографически большим
именем; отсутствие ответа называется `missing`, а не отсутствием объекта. При листинге
возвращается закрытая форма ObjectListing из Н2; удалённые объекты — надгробия `.gone/<ключ>` урока 10 Н1.5 `delete`: обычный листинг их не показывает, `prefix=.gone/` —
листинг надгробий только для чтения (журнал cammeta-go, урок 10 № 2).

Листинг отдаёт только ключи семей двери под `prefix` — фильтр, а не отказ: `prefix=testsub/`, `prefix=t`, пустой
`prefix` — 200 с ключами семей двери, которые начинаются с него; ключи вне семей двери в листинг не попадают. `prefix`,
с которого не начинается ни один возможный ключ семей двери (`other/`), — 403. `prefix` не UTF-8 (`%FF`) — 400. Чтение
ключа: ключ не по грамматике (не UTF-8, Cc, Zl, Zp — в том числе U+2028, `.`/`..`, пустой сегмент) — 400; ключ вне семей
двери, включая каталог `testsub/heartbeats` из двух частей, — 403; ключ семьи, которого нет (в том числе каталог внутри
семьи, `testsub/heartbeats/sub`), — 404; ключ, отличный от записанного только регистром или нормализацией (`W-1` при
`w-1`), — свой ключ: 404, не чужой объект (сверка python и go М10/6–11, E1, E2, E4, E7, E8).

**Имена файлов в общих деревьях** — одно кодирование для всех реализаций: объекты и деревья событий (Н1.2, Н1.4) пишут
процессы разных реализаций на одной коробке (решение «Архитектора», второй пилот, Н-3; исполняет сверку python и go
М10/3–5 п. 14 и U20). Любой логический ключ, который разрешают грамматика P/01.1, грамматики id и слота М10/3 и предел
полного ключа, представим на диске. Раскладка каталогов — по логическому ключу, компонент за компонентом (между `/`):

- байт компонента из `[a-z0-9._-]` пишется как есть, любой другой байт UTF-8 — `%` и две строчные hex-цифры (`A` —
  `%41`, `:` — `%3a`, `%` — `%25`, `я` — `%d1%8f`); компонент `.` — `%2e`, `..` — `%2e%2e`;
- закодированный компонент длиннее 255 байт — имя `%h<sha256 hex байтов исходного компонента>`, рядом файл
  `%h<sha256>.name` с исходным компонентом (байты UTF-8, без перевода строки);
- раскодирование — обратное; усечение и нормализация ключа запрещены, разные ключи — разные пути, файлового профиля уже
  грамматики нет;
- кодируются компоненты, взятые из имён и ключей: `<sub>`, дерево, `<unit>`, роль, экземпляр, `<server>`, сегменты ключа
  объекта; компоненты, форму которых задаёт сама норма, пишутся как есть — имя бакета `<YYYYMMDDTHHMMSSZ>.events.jsonl`,
  `e<эпоха>`, суффикс `.alarms`, каталоги `.workers`, `.mirror`, `.gone`, окончания `.lock`, `.name` (`T` и `Z` имени
  бакета — не `%54`, `%5a`); составной компонент — закодированное имя плюс суффикс нормы: `testsub.alarms`,
  `<экземпляр>.lock` (журнал cammeta-go, урок 8 № 10; решение «Архитектора»). Шаг — сц. 08 шаги 12–16: бакет, который
  раннер пишет мимо писателя под именем нормы, ресурс читает.

Ошибка ФС после допуска — отказ записи, а не успех и не «файла нет».

### Н1.2 Событие

```yaml
line:                                        # одна строка JSON в файле бакета
  t:        <секунды стенных часов писателя, когда записали>      # ДОЛЖЕН; выбирает бакет
  kind:     <вид>                                                  # ДОЛЖЕН
  id:       e1-<hexUTF8(дерево)>-<hexUTF8(единица)>-<эпоха>-<hexUTF8(экземпляр)>-<номер>                   # ДОЛЖЕН; уникален; по нему убирают дубли копий
  of:       <sub>/<id>                                             # единица, про которую; ставит платформа из about;
                                                                   # своё of — только деревья console и audit
  class:    alarm                                                  # только у тревоги; observation не пишется
  occurred: <секунды>                                              # когда произошло; необязателен; число
  <поля>:   слова подсистемы                                       # v не пишется: отсутствие = версия 1
bucket:
  path:     <root>/<sub>/<unit>/e<epoch>/<YYYYMMDDTHHMMSSZ>.events.jsonl       # root: RESOURCE_ROOT | <PLATFORM_DIR>/events
  alarms:   <root>/<дерево>.alarms/<unit>/e<epoch>/…                              # своё дерево у каждого дерева
  span:     600 с; начало = floor(t / 600) × 600 по UTC; закрыт, когда end ≤ now; катится только по часам
  durable:  тревога и журнал — fsync строки и каталогов до корня; наблюдение — нет
  torn:     порванная последняя строка пропускается и считается
class:      [alarm, observation]             # закрыто; класс строки — её поле class: alarm — тревога, поля нет —
                                             # observation; индекс берёт класс из поля, дерево его не переопределяет;
                                             # раскладка .alarms — у писателя: тревогу он кладёт в <дерево>.alarms любого
                                             # дерева, в том числе audit.alarms и console.alarms (срок alarms_retention)
                                             # (решение «Архитектора», второй пилот, Н-2; меняет выбор сверки М10/6–11 E18)
suppress:   P/03.6 Н1.2 (стадия B)              # events.suppress.<kind>: {window, by}  (форма — P/02.1)
older_epochs: fenced | earlier-run           # слово для страницы; умолчание fenced
journal:    дерево audit/<роль>/e1/…: строки платформы о себе (unit.created|changed|deleted, door.issued, schema.raised,
            events.removed, policy.changed, drain.*, server.*, worker.name_taken (alarm), worker.name_back (observation; P/03.2 Н3 «никто и возврат имени», «воссоединиться»), worker.hung, clock.skew, free_ask.key_taken, …);
            поля: о чём строка — sub и target (единица; не subsystem/unit), адрес клиента у строк о двери — addr;
            второго имени у этих полей нет (ADR-0069)
marks:      дерево console/<экземпляр>/e1/…: отметки оператора, kind mark, of = единица, user — имя человека, доказанное
            сторожевой (без домена — operator, урок 9) (сверка python и go М10/6–11, E60); строка индекса —
            subsystem: "console", unit: "console/<экземпляр>", of — адресат
writer:     консоль — отдельный процесс; журнал и отметки она пишет в корень событий своего сервера (тот же, что
            у ресурса этого сервера), ресурс индексирует их как свои бакеты; у файла один писатель, кроме журнала:
            в audit/<роль>/e1 пишут все процессы этой роли на сервере (путь экземпляра не несёт, единица журнала — роль);
            строка дописывается целиком под исключительной блокировкой файла, строки разных процессов не перемешиваются,
            их различает id (экземпляр в нём); бакет — тот же по t у всех писателей (журнал cammeta-go, урок 8 № 5)
```

`hexUTF8` — строчные hex-пары байтов UTF-8 без префикса, разделителей и нормализации.
Дерево и единица — непустые компоненты пути бакета (для журнала audit/роль, для отметок
console/экземпляр). Эпоха — каноническое десятичное целое ≥0, номер — ≥1, без ведущих нулей.
Номер атомарно выделяется общим счётчиком экземпляра на каждую новую публикуемую строку,
включая итог подавления; не переиспользуется при смене единицы, дерева, эпохи или бакета.
Итог подавления получает новый id, а не id первой строки окна. Зеркало/повторная выдача
сохраняют id исходной строки. При исчерпании счётчика новые строки не публикуются до нового
уникального экземпляра; оборачивание счётчика запрещено.
Экземпляр писателя — непустая строка, уникальная с учётом коробок и перезапусков (`INSTANCE_ID`, `BOX_ID` — P/02.4 Н1.2); локального PID
недостаточно, повтор прежнего INSTANCE_ID новым процессом вне профиля. Экземпляр — один
компонент пути: не `.`/`..`, без `/`, `\`, `|`, `"`, запятой, Cc/Zl/Zp. Это условие
профиля действует и на INSTANCE_ID из окружения, и на вычисленное значение; проверяется
до старта/первой публикации вместе с файловой представимостью Н1.1. Нарушение — отказ
старта с диагностикой имени экземпляра, без усечения/нормализации. Hex-компоненты
не содержат разделитель `-`, поэтому разные допустимые кортежи не склеиваются в один id.
Поля платформы
в строке/ответе не перезаписываются произвольными полями подсистемы. Числа JSON конечны.
`subsystem` строки индекса — имя спеки, и у строк дерева тревог (`testsub`, не `testsub.alarms`; сверка python и go М10/6–11, E32).
`of` платформенной строки без единицы-адресата — пустая строка; у строки подсистемы
адресат определяется спекой. `unit` в ответе индекса — полная ссылка `<дерево>/<единица>`;
у журнала это `audit/<роль>`, у отметки — `console/<экземпляр>`, а её `of` — адресат.

Подавление — [P/03.6 Н1.2](../../Platform/03-worker/spec/03.6-worker.norms.md) (стадия B).

### Н1.3 Индекс и срок

```yaml
index:
  one_per_resource: над своим деревом и .mirror/<сервер>/ копиями; состояние всегда live; перестройки нет
  cache:    ограничен (64 MiB), выбрасывается без потери правильности; файл перечитывается по размеру/mtime/inode с места
  query:    from, to (секунды; умолчание 0..1e12), kind, subsystem, unit (<sub>/<id>; голый id — отказ), limit (1000;
            предел 10000), keep (newest | oldest), class, by (t | occurred; occurred читает на 3600 с дальше)
  row:      {id, subsystem, unit, of, epoch, t, kind, server, bucket, class, epoch_is, fenced, …поля}
            # epoch_is и fenced ставит консоль при слиянии; у ресурса строки без них (решение «Архитектора», ревью стадии A)
  epoch_is: current | fenced | earlier-run   # консоль — по current_epochs из <sub>/epoch/* и политике спеки
  cut:      до обрезки дубли по id убрать; сначала alarm, затем observation; внутри класса по by (newest — убывание, oldest — возрастание),
            при равном времени id лексикографически по байтам UTF-8; первые limit строк. truncated ресурса — число оставшихся после этой обрезки
  answer:   {events, state, truncated, partial?}; truncated — неотрицательное целое по cut/merge (всегда); partial: true — хотя бы один
            бакет читался с порванной последней строкой (она не отдана и в truncated не считается); консоль: + complete, incomplete {сервер: did not answer | said <state> | silent}
merge:      консоль спрашивает живые ресурсы, сливает, дубли копий — по id, state: live[; <s> unreachable][; <s> from mirror]
retention:
  <sub>/retention:        {days}      # умолчание 365
  <sub>/alarms_retention: {days}      # умолчание 1095; audit — 1095
  writer:   обеих строк — admin командой оператора w2cctl retention (P/02.4 Н1.9); ресурс и консоль их только читают
            (P/02.5 Н1.4; пилот хранилища, решение «Архитектора» 2026-10-18)
  rule:     на подсистему, не на единицу (ADR-0076); days — конечное число > 0, иное — «не известно», ничего не убирать;
            отметки консоли живут не меньше самого долгого дерева; удержания holds: сохраняют бакеты;
            копии зеркала — на час дольше; убранное — журнал events.removed
```

Запрос использует конечные `from`/`to`, `from ≤ to`; `limit` — целое 1…10000 (сверка python и go М10/6–11, E12–E15):
- `from`, `to` — десятичное число ASCII: необязательный `-`, цифры (между цифрами допустим `_`), необязательная точка с
  цифрами хотя бы с одной стороны, необязательная экспонента `e`/`E` со знаком; `1_0`, `.5`, `5.`, `1e3` — числа,
  `1e-400` — 0; `+1`, пробел (`%201`, `1%20`), не-ASCII цифры (`١`), `0x10`, переполнение — 400;
- `limit` — только цифры ASCII (ведущие нули допустимы: `01`), иначе 400; `since` подсказки — по Н1.6;
- `unit` — UnitRef `<sub>/<id>`: голый id, пусто, `testsub/`, `/c1` — 400;
- пустой или повторённый параметр — 400 (Н2); незнакомый непустой параметр не читается (у `/events/wait` — 400, Н1.6).

**Нечитаемая строка бакета** (P/01.1 Н0 «Устойчивость выдачи»; сверка python и go М10/6–11, E19, E24, E32). Строка, которая не JSON,
не объект, с BOM, с числом вне JSON (`NaN`), без `kind`, `t` или `id`, с `id` не строкой, а также файл не на своём месте
(путь бакета не по Н1.2, например `e01`) — пропускается: в `events` и `truncated` не входит, ответ — 200, а число таких
строк — `lines_garbled` ответа (поле есть, только когда больше 0). Порванная последняя строка — по-прежнему `partial`,
не `lines_garbled`. Консоль складывает `lines_garbled` ответивших ресурсов и сама пропускает строку ответа ресурса не
по форме EventRow, прибавляя её к своему `lines_garbled`. `events` в BucketInfo — число целых читаемых строк бакета;
500 перечня — только нечитаемый каталог или метаданные.

Для `by=occurred` строка без occurred использует t и при фильтре, и при сортировке.
Умолчания `keep=newest`, `by=t`; отсутствие `class` означает оба класса. Иная форма — 400,
включая NaN/Infinity, дробный limit и голый unit. Лимит возвращает выбранное подмножество;
`limit` ограничивает и каждый ресурс, и итог консоли. Ресурс считает в `truncated` подходящие
уникальные по id целые строки, не вошедшие в его локальный limit. Консоль возвращает сумму
локальных truncated ответивших источников плюс число отброшенных общей обрезкой строк
после дедупликации полученных кандидатов. Копии, пропущенные разными источниками, могут
учитываться несколько раз: это счётчик пропусков на стадиях, не число разных потерянных
событий и не число пропусков у молчащих источников. Дополнительного чтения всех скрытых
строк для точного глобального счёта урок не требует.
`fenced=true` тогда и только тогда, когда `epoch_is=fenced`; earlier-run не ограждён.
В этом уроке не обещан атомарный снимок нескольких файлов или ресурсов.
Неизвестное чтение срока или удержаний не равно отсутствию: зависимое дерево не удаляется
до достоверного чтения. Отсутствующая строка retention даёт умолчание, ошибка чтения — нет.
`complete` у консоли — отсутствие причин в `incomplete`; это полнота ответивших источников,
а не отсутствие обрезки по limit. `partial` переносится от ответившего ресурса, если true.

PULSE_LIMIT — конечный положительный предел длительности одного шага ресурса в секундах,
выбранный и объявленный реализацией до старта. Длительность измеряется местными
монотонными часами, а не t/at писателя; превышение даёт pass_stalled в следующем пульсе.
Это диагностический порог, не обещание остановить зависший вызов или дождаться ответа.

### Н1.6 Подсказка и представления HTTP

`GET /events/wait` ресурса — подсказка по ADR-0038, не доставка событий. Профиль урока:
`want` — непустой список через запятую `<sub>/<kind>[/<unit>]`; каждая часть из ASCII букв,
цифр, `_`, `-`, `.`, 1…64 знака, не начинается с точки. `client`, если передан, — 1…128
печатных ASCII-знаков без пробела. `since` — десятичный uint64 без знака/ведущих нулей,
по умолчанию 0. `timeout` — конечное число секунд в (0,30], по умолчанию 30.
Пустые/повторные параметры, незнакомые параметры (`&foo=1`), иные формы и значения вне области — 400; `since` и
`timeout` — только цифры ASCII (и точка у `timeout`), не-ASCII цифры — 400 (сверка python и go М10/6–11, E14, E16). `since=0` —
у клиента нет позиции: ответ сразу `{changed: true, seq, touched}`, если под want есть строки в бакетах ресурса любой
давности; seq — непрозрачное монотонное число процесса ресурса, клиент только сравнивает и передаёт его обратно
(сверка python и go М10/6–11, E46). Подсказку дают деревья подсистем каталога (`<sub>`, `<sub>.alarms`); деревья `console` и `audit`
подсказки не дают (обе реализации так, нормы не было).
Этот ограниченный профиль не требует принимать любые внутренние имена единиц: периодический
проход клиента остаётся обязательным и работает без подсказки.

Ответ — одна из закрытых форм WaitAnswer: `{changed:true, seq, touched:[…]}`,
`{changed:false, seq}`, `{changed:false, seq, full:true}` или
`{changed:false, seq, replaced:true}`. В touched — отсортированные уникальные
`<sub>/<kind>/<unit>`, подходящие want; самих событий нет. seq относится к одному процессу
ресурса; после перезапуска/неизвестной последовательности клиент делает обычный проход.
При full/replaced клиент не продвигает свой курсор по seq, а возвращается к обычному проходу.
По умолчанию до 16 ожиданий (параметр развёртывания LONG_POLL_WAITERS); новое ожидание при
заполнении отвечает 200/full. Именованный клиент вытесняет своё прежнее ожидание: 200/replaced.
В TLS личность — CN сертификата плюс client; другой CN не вытесняет ожидание (ADR-0075).
Без client развёртывание использует отдельное ожидание на адрес клиента; повтор при занятом
адресе — full. Наблюдение текущих бакетов каждые 0,1 с, пока есть ожидающие; пропущенная
подсказка или запись в старый бакет восполняется обычным проходом, а не обещанием доставки.

Пути `/mirror/{server}/{path}`, `/mirrored/{server}[/{path}]`, `/events/{path}` (сверка python и go М10/6–11, E26, E27, E29, E34):
`{server}` — один сегмент по грамматике имени сервера (P/02.4 Н1.2 `SERVER_NAME`); `{path}` — путь бакета Н1.2
(`<дерево>/<unit>/e<эпоха>/<начало>Z.events.jsonl`), ни один сегмент не пуст и не `.`/`..`, `%2F` — не разделитель,
`.tmp` — не бакет. Иное: `GET /mirrored/…` и `GET /events/…` — 404 без тела, `PUT /mirror/…` — 400 без тела. Файл вне
своего дерева (`.mirror/<server>/` у копий) ресурс не читает и не пишет никогда. `PUT /mirror` бакета, чей конец по имени
позже часов приёмника, — 400: зеркало принимает только закрытые бакеты. Значение `X-Sum` — поле HTTP: пробелы по краям
(OWS) отбрасываются до проверки формы (E35).

Представления HTTP — в схемах Н2. `BucketInfo` — описание одного бакета, не событие;
`/buckets` выдаёт UTF-8 JSON Lines: один объект на LF, без массива. `/mirrored/<server>`
по канону этого урока выдаёт `{copies:[{path,written,size,sum}]}`. Байты копии — отдельный
GET. Поле `sum` и заголовок X-Sum — 64 строчные hex-цифры SHA-256 целого тела.
`answered` — содержимое метки-строки Н1.5: строковые значения, включая времена, error и
late="true"; описание `{queued:rid}` не допускает замены rid объектом. Метка без начала
не содержит instance/slot/at/action/late; закрытие чужой begun сохраняет её поля, добавляет
unknown/ended_by/ended_at/error. Ответ начавшего не содержит ended_by. Эти три формы
различаются в AnsweredMark; begun без исхода возвращается как queued, не answered.

## Н2 Двери

Полный контракт: [OpenAPI](08-events-resource-requests.api.openapi.yaml).
GET объекта ограничен 64 МиБ по реально прочитанным байтам: ровно предел разрешён,
+1 байт — 413 ResourceError до успешных заголовков; тело до подтверждения размера
ограниченно буферизуется либо проверяется по неизменяемому объекту с достоверным размером.
Потолок самого хранилища может быть выше и этот предел двери не отменяет. Он различает
ресурс и консоль, JSON-ответы, поток байтов и отсутствие тела. Схемы задают обязательные
поля и допустимые расширения; проверки существования, прав, UTF-8-размера и состояния
исполняются отдельно. Внешний массив не заменяет JSON Lines.

| Вход | Успех | Прикладные отказы |
|---|---|---|
| ресурс GET /v1/objects | 200 ObjectListing | 400 ResourceError; 403 ResourceError или ResourceDenied; 503 ResourceError |
| ресурс GET /v1/objects/{key} | 200 байты; X-Written, X-Server, при необходимости X-Missing | 400/403/404/413/503 ResourceError |
| ресурс PUT /v1/objects/{не-блоб} | нет | 405 ResourceError; ключ/scope — 400 |
| ресурс GET /buckets/{sub}/{unit} | 200 JSON Lines из BucketInfo | 404/500 без тела |
| GET /events | ресурс: 200 ResourceEvents; консоль: 200 ConsoleEvents; у консоли также `HEAD` — код и заголовки `GET` без тела (М10/9 Н2), у ресурса `HEAD` — 405 | консоль 400 TextError, ресурс 400 ResourceError (разбор ниже); ресурс 503 ResourceError, консоль 503 TextError |
| ресурс GET /events/wait | 200 WaitAnswer, в том числе full/replaced | 400 ResourceError; общая полоса занята — 503 ResourceError |
| ресурс GET /events/{path} | 200 целые байты + X-Sum; 206 один диапазон + Content-Range | 404/500 без тела; 416 text/plain + Content-Range |
| ресурс PUT /mirror/{server}/{path} | 204 без тела; заголовок `X-Sum` — SHA-256 тела (64 строчных hex), обязателен | нет `X-Sum` или он не по форме — 400, тело не принимается; SHA-256 тела не совпала — 422; 408/413/500 — без тела |
| ресурс GET /mirrored/{server} | 200 MirroredListing | 404/500 без тела |
| ресурс GET /mirrored/{server}/{path} | 200 байты + X-Sum | 404/500 без тела |
| консоль POST /marks | 200 MarkWritten | 400 TextError |
| консоль POST /{sub}/requests | 202 Queued; 200 Answered | 400 RequestError; 404/409/429/503 TextError |
| консоль DELETE /{sub}/asked/{sha16} | 200 Cleared | 404 TextError |

Эти две двери всегда явно именуют подсистему, в том числе CONSOLE_ROOT. Короткие
/requests и /asked/{sha16} не объявлены: общий неизвестный маршрут консоли —404
по М10/9. Зарезервированное имя семьи само по себе не добавляет HTTP-дверь.

Для обоих перечней (`/buckets/{sub}/{unit}` и `/mirrored/{server}`) все необходимые
чтения каталога/метаданных завершаются до успешных заголовков: неизвестность/ошибка —
500 без тела, не 404 и не пустой 200. Это наблюдённый перечень, не снимок нескольких файлов.
Обрыв уже начатой передачи перечня не является полным ответом; новый HTTP-статус
после заголовков не отправляется.

ResourceError — только `{error: текст}`. TextError — только `{detail: текст, error: текст}`.
RequestError допускает дополнительно `fault:"too_long"` только при превышении длины
поля по requests.schema; остальные причины fault не получают. Применение схемы — до
проверки существования единицы. Отказ 404 при чтении объекта означает «нет среди ответивших»;
при неполном опросе X-Missing обязателен, полнота не выводится из самого кода 404.

**Разбор запроса.** Двери консоли этого урока — урок 9 Н2 «Разбор запроса консоли». Дверь ресурса — по P/01.1 Н2.1
(query, путь байт в байт, HTTP по RFC 9112, ранний отказ) с отступлениями: отказ разбора query — 400 ResourceError
`{error}`; пустой или повторённый параметр — 400; нет пути и неподдержанный метод — 404/405 без тела, в том числе
`OPTIONS`, `POST /events`, `PUT /v1/objects` (листинг), `GET`/`POST`/`DELETE` на `/mirror/…`; `PUT /v1/objects/{не-блоб}` —
прикладной 405 ResourceError (Н4); `/buckets/{sub}/{unit}` — ровно два непустых сегмента, `/buckets/testsub/`,
`/buckets/../objects`, `/buckets/testsub%2Fc1` — 404 без тела; тела `PUT` — байты, JSON не разбирается (сверка python и go М10/6–11,
E9, E10, E17, E30, E31, E36).

Общие отказы консоли по М10/9: 400/401/403/404/405/408/413/429/503;
тела TextError (у POST requests 400 — RequestError), у 401/403 error=denied.
Предел тела консоли объявляется развёртыванием и не меньше 1 MiB; chunked/короткое тело
даёт 400, превышение размера — 413, срока чтения — 408. При 429 действует предел входа.
Время чтения должно быть объявлено до запуска, не подбираться под запрос. ResourceDenied (`error=refused`, detail,
role при отказе роли) — 403 шлюза ресурса, до обработчика маршрута. Отказ TLS до HTTP
не получает выдуманного HTTP-тела. Каждый применимый общий ответ внесён в OpenAPI.
При busy — Retry-After: 1. На неизвестном пути — 404; на неподдержанном методе известного
пути — 405; у ресурса оба без тела, у консоли TextError. Этого общего правила достаточно:
оно не создаёт отдельный метод OpenAPI для каждой невозможной операции.

**Допуск к дверям ресурса** (ADR-0075 доп. 2026-10-12 (3)). Ресурс с TLS проверяет клиента: цепочка до центра,
серийник не в `revoked` (договор сертификата роли `revoke`), ровно одна роль из строки маршрута, CN = `<роль>.<SAN DNS>`; иначе отказ
рукопожатия или 403 `ResourceDenied` с ролью и маршрутом. Клиент сверяет роль `resource` и SAN DNS сервера с хостом
адреса; IP при TLS — отказ клиента.

| Маршрут ресурса | Допущенные роли |
|---|---|
| `/events*`, `/buckets/`, `/mirrored/` | `console`, `resource`, `<sub>worker` спек каталога |
| `PUT /mirror/` | `resource` |
| чтение `/v1/objects` (семьи Н1.1 `door`); `PUT /v1/objects/<sub>/blobs/<digest>` (М10/10 Н2) | любая роль с комплектом (P/02.4 Н1.6) |

`POST /marks`: unit обязателен и имеет форму полной ссылки; отсутствующий note — пустая строка,
переданный note — строка. Проверяется форма ссылки, не наличие живой строки единицы; отсутствие строки не вводит отдельный 404/400 этой двери. Лишние поля принимаются, но не попадают в событие. Дверь требует
грант edit на адресата по М10/9. `Idempotency-Key` здесь не обещает памяти повторов.
Для POST requests заголовок обязателен, безопасная форма/размер — как у двери единиц М10/3;
отпечаток, rid и память — собственные правила Н1.5/Н3, не копия pending/done единиц.
Поля сервера rid/digest/filed/by/at/group в теле клиента отвергаются; единственное
разрешённое служебное поле — valid_until. Поля тела дополнительно проверяются по
requests.schema и правилам stamp выбранной спеки, существование — после формы.

**Ограничения профиля.** Файл бакета читается целиком или одним Range; составные Range и
условные HTTP-запросы не входят в урок. Размер ответа фиксируется перед чтением; ответ
не обещает снимка всего дерева. После начала выдачи обрыв потока не превращается во второй
HTTP-статус: вызывающий не принимает неполные байты как целую копию. Приём зеркала ограничен
64 MiB и объявленным развёртыванием сроком чтения; превышение размера — 413, срока — 408.
`PUT /v1/objects/<sub>/blobs/<digest>` и `PUT /<rows>/<id>/<blob_field>` целиком принадлежат [М10/10](../10-schema-drain-snapshot-limits.md) Н2; в этом уроке
нормируется только отказ записи не-блоба, частичной копии контракта блобов нет.

## Н3 Проход

### записать событие (платформа, по observe подсистемы)

```
1. class ∈ {alarm, observation}; поле class в строке — отказ; occurred не число — отказ; v — отказ
2. of: из about спеки (<sub>/<id>); строка подсистемы со своим of → отказ «of is the platform's to write»;
   деревья console и audit — своё of
3. подавление (правило — P/03.6 Н1.2): kind в events.suppress → та же по by в открытом окне → repeats + 1, не писать;
   иначе записать первую, открыть окно; окно закрылось или проход flush → строка-итог
4. бакет по t: <root>/<дерево>/<unit>/e<эпоха>/<start>Z.events.jsonl; новый каталог — барьер каталога
5. дописать строку; тревога/журнал — fsync строки и каталогов до корня
```

**Гонки.** Один писатель на бакет (Н1.1; журнал — под блокировкой файла, Н1.2 `writer`): дописывание не конкурирует; два процесса одного `of` (переезд, эпоха) пишут в разные пути — путь несёт эпоху — и не смешиваются; ротация бакета по `t` — закрытие старого и открытие нового в одном писателе.

### запрос (ресурс) → {events, state, truncated}

```
1. проверить параметры (Н1.3)                                          → 400 (у ресурса ResourceError, у консоли TextError)
2. кандидаты: окно ≤ 144 бакетов — имена по времени; шире — листинг каталога; если граница не представима именем календаря — листинг, без переполнения; оба дерева подсистемы (и .alarms);
   копии .mirror/*: тот же бакет — дубль, отвечает под именем хозяина
3. читать файлы с места прошлого чтения (кэш по размеру/mtime/inode); порванная строка — пропустить (partial);
   нечитаемая строка или файл не на месте — пропустить и счесть в lines_garbled (Н1.3), ответ не 503
4. фильтр: kind, subsystem, unit (и строки с of = unit), class, окно по t (или occurred, +3600)
5. epoch_is и fenced ресурс не ставит: их ставит консоль при слиянии (ниже); права на <sub>/epoch/* ресурсу не нужны
6. убрать дубли id, упорядочить и взять первые limit по cut Н1.3; truncated = число кандидатов после дедупликации минус число выданных
→ строки Н1.3; больше 8 запросов разом → 503 busy, Retry-After: 1
```

**Гонки.** Чтение открытого бакета во время дописывания: отдаются только целые строки, порванная не отдаётся и ответ несёт `partial: true` (`truncated` — число, Н1); перечисление не фиксирует содержимое файлов: исчезнувший файл не подтверждает пустой бакет. Ошибка чтения файла или каталога не выдаётся как полный ответ; после начала HTTP-потока — обрыв, до него — 503 ResourceError. Нечитаемая строка — не ошибка чтения: она пропускается и считается (Н1.3, P/01.1 Н0 «Устойчивость выдачи»).

### слияние (консоль)

```
живые ресурсы — строки дверей platform/doors/<s>, чьё at менялось < 45 с по часам консоли (первый взгляд — как свежий;
пульс ресурса — объект его сервера, консоли другого сервера не виден) → параллельно (8 полос, 3 с); current_epochs — из <sub>/epoch/*; политика — из спек
дубли по id → одна; не ответил / сказал не live → incomplete[сервер]; state: live[; s unreachable][; s from mirror]
ресурс с несвежей строкой двери (silent) не спрашивается: incomplete[s] = silent, state «; s unreachable»; копии его
  бакетов в ответах других ресурсов отдаются, и тогда state ещё «; s from mirror» (сверка python и go М10/6–11, E23)
epoch_is: эпоха строки < current_epochs[unit] → политика спеки (fenced | earlier-run), иначе current; fenced — Н1.3
с unit: запрос без ограждения, затем разметка по эпохам (`epoch_is`, `fenced`, Н1.3): строка прежней эпохи отдаётся с
  `fenced: true`, не выбрасывается (сверка python и go М10/6–11, E21)
строка ответа ресурса не по форме EventRow → пропустить, lines_garbled консоли (Н1.3; E24)
полученные уникальные кандидаты упорядочить по cut Н1.3; оставить первые limit;
truncated = сумма truncated ответивших ресурсов + число кандидатов, не вошедших в общий limit;
дедупликация и отсечение по эпохам сами по себе в этот счётчик не входят; порядок выдачи — тот же, что cut
```

**Гонки.** Источники и эпохи могут изменяться между чтениями: общего снимка нет.
Счёт относится к наблюдённым ответам: локальная обрезка может скрыть копии и строки,
которые позже отсекаются по эпохе; результат не обещает глобальный top-k всех файлов.
Ответивший позже таймаута ресурс отмечается в incomplete этого ответа и может ответить
на следующий. Поздний ответ не дописывается в уже отданное тело.

### проход ресурса — каждые 600 с

```
retain:  для каждого дерева: days = <sub>/retention | 365 (tree.alarms — alarms_retention | 1095; audit 1095;
         console — 1095, не раньше самого долгого дерева);
         days не число или ≤ 0 или строка не ответила → не известно: ничего не убирать, назвать в пульсе;
         убрать закрытые бакеты старше days (отметки консоли — не раньше самого долгого; holds сохраняют;
         копии зеркала — days + 1 ч); журнал events.removed; index.forget
usage:   измерить тома (зонд ≤ 5 с); пульс space/volumes
relieve: platform/space.enabled ∧ used/total > high → для спек с requests.free: need = used − total·low − Σ freeing
         need > 0 → записать free-<server>-<volume> {free: need, volume, server, at}: cas "" или cas по версии строки СВОЕЙ формы
         (без unit И с точными server/volume текущего тома); перед записью проверить грамматику Н1.5;
         под этим ключом строка с unit, чужими server/volume или испорченной формой → не трогать, журнал free_ask.key_taken, пропустить;
         need ≤ 0 (всё нужное уже освобождается, ADR-0059) или ниже low → удалить строку своей формы, если есть: delete с cas версии,
         на которой проверены отсутствие unit И точное совпадение server/volume (P/01.1); conflict — под ключом уже другая строка (обычная просьба или новая своя) → не трогать,
         журнал free_ask.key_taken
mirror:  platform/mirror.enabled → соседи = следующие copies живых по имени; закрытые бакеты, которых у соседа нет
         (сумма) → PUT /mirror/<я>/<путь> с X-Sum = SHA-256 бакета; PEER_FAILS подряд → сосед пропущен на проход
каждый шаг — своя попытка; шаг дольше PULSE_LIMIT → pass_stalled в пульсе
```

**Гонки.** В одном проходе retain предшествует mirror; это не блокировка от другого чтения/очистки. Копируется только целый закрытый бакет с проверенной суммой; исчезновение/неполное чтение даёт неуспешную попытку, без публикации частичной копии. Следующий проход заново перечисляет доступные бакеты. Хозяин и копия: копия никогда не источник, пока хозяин отвечает; `restore` (урок 11) тянет копии обратно только по слову хозяина. Снятие `free_ask` и обычная просьба под тем же ключом: ресурс проверил форму на версии v и остановился; жнец снял его старую строку по ttl, консоль приняла обычную просьбу с тем же rid — у ключа версия v′; `delete` с cas v отвечает conflict, принятая просьба цела; без cas она была бы удалена без исхода (ADR-0054).

### Состояния исполняемой просьбы и её метки

Таблица применяется к обычной просьбе с unit, исполняемой держателем через метку.
Из неё исключены строки ресурса без unit, действия elsewhere и дозапись ADR-0054
(семья просьб спеки с `requests.outcome: fetched`: ключ из данных, например `<unit>-<from>-<to>`, исполнение идемпотентно по данным).
Класс определяется объявленной формой/действием спеки (`outcome`, `free`, `elsewhere`), не одним текстом rid.
Дозапись: консоль снимает строку по CAS после fetched и settle и освобождает её rid в asked
по CAS. Сторона держателя дозаписи — [P/03.6 Н3 «Дозапись ADR-0054»](../../Platform/03-worker/spec/03.6-worker.norms.md) (стадия B).
Признак дозаписи — `requests.outcome: fetched` (ADR-0054 доп. 2026-10-17); учебный потребитель — просьбы `testsub2`
(форма — README [приёмки P/03.6](../../Platform/03-worker/acceptance/6/README.md), обработчик — P/03.6 Н5). Жнец такую строку не метит и не снимает по одному `ttl`; сценарий 07 приёмки P/03.6.
Строки ресурса и elsewhere остаются у своих владельцев; жнец их не метит и не
переводит в протокол обычной просьбы. Elsewhere закрывает/снимает её владелец.

Для обычной просьбы подтверждение исхода — успешное чтение терминальной метки
с теми же unit/digest. Для дозаписи — подтверждённый fetched держателя по её строке: rid или SaidID(rid) в поле `fetched`
пульса `<sub>/heartbeats/*` любого воркера её спеки (P/03.4 Н1.1; чужих rid воркер не называет).
С этого первого наблюдения консоль считает settle местными монотонными часами;
при возрасте <settle строка не снимается ни clear, ни sweep. Равенство разрешает
попытку CAS, не обещает немедленного удаления. Повторное наблюдение и поздняя
замена unknown на performed не сдвигают начало для той же строки/unit/digest;
новая версия строки начинает новое наблюдение. После рестарта или
утраты памяти наблюдения возраст начинается заново, ended_at/fetched не служат
чужими часами. Неизвестное чтение не даёт удалить строку; перед CAS подтверждается
её текущая версия и основание снятия. Учёт отвеченной просьбы может освободиться
раньше удаления строки: settle ограничивает строку, не удержание per_person.
Для обычного профиля сначала проверяется существующая метка, затем срок/допуск; имя rid не определяет класс строки.
Каждое чтение даёт состояние только на момент чтения: конфликт возвращает к таблице.

| Участник / состояние | Условие | Действие | Исход |
|---|---|---|---|
| подача, метка с исходом | тот же unit и digest | вернуть метку, не создавать строку/учёт | 200 answered |

### подать просьбу (консоль, `POST /<sub>/requests`)

Проверка тела, digest/rid, создание строки и лимит человека общие. Шаги чтения
метки2/5 применяются только к обычному профилю таблицы выше. У дозаписи их нет:
совпавшая или созданная строка подтверждает202 queued, метка не требуется,
освобождение учёта — по fetched/правилу исключения, не по отсутствующей метке.

```
0. у спеки нет requests (или подсистема просьб не принимает) → 404 TextError; единицы unit нет (строки нет или deleted) —
   после схемы, шаг 1 → 404 TextError (Н4 «просьба: нет requests / нет единицы»)
1. Idempotency-Key (нет → 400, Н4); тело — объект с unit; схема; digest = sha256(JCS(тело без valid_until — единственного поля сервера, которое клиент вправе прислать)); rid: по requests.key — шаблон {поле} из тела ({поле:int} — целая часть числа, P/02.1 Н1.4; не число → 400; детерминированный: одинаковые
   поля — один rid, создание-однажды); иначе r-<sha16(Idempotency-Key)> — заголовок у двери обязателен, иной ветки нет (случайный rid — у воркера, пишущего строку сам);
   valid_for задан → valid_for ≤ most_valid (проверено загрузчиком), valid_until = now + valid_for; без valid_for строка без срока, действует ttl. valid_until из тела клиента при заданном most_valid —
   не позже now + most_valid, иначе 400 too far, и тогда он и есть срок; valid_until — конечное число JSON: null,
   строка, bool — 400; 0 и прошедшее принимаются и записываются как есть (срок вышел); у спеки без most_valid
   valid_until в теле — 400 «this subsystem takes no deadline» (сверка python и go М10/6–11, E50, E52, E54). Все отказы шага 1
   (форма, срок, шаблон) — раньше отказа «нет единицы» шага 0 (E51); тело не JSON — 400 RequestError без fault (E49);
   Idempotency-Key — форма двери единиц М10/3: `.` и `a,b` допустимы (E48); {поле:int} — каноническая десятичная запись:
   −0 → 0 (E53)
2. метка objects/<sub>/commands/<rid> уже есть (строка могла уйти по clear): тот же unit и digest и у метки есть исход (answer или
   no_begun) → 200 answered; тот же unit и digest, но только begun без исхода (исполняется) → 202 {queued: rid}; учёт и строку не трогать;
   иной unit или digest → 409 spent
3. per_person: прочитать учёт: недоступное/неподтверждённое чтение → 503; прочитана повреждённая форма
   (rids не список допустимых rid, неверные by/at) → 429, без изменения; rid уже в rids → учёт не менять и продолжить шагом 4, ответа здесь нет;
   иначе len(rids) ≥ per_person → 429; иначе добавить rid по cas и продолжить шагом 4; конфликт → перечитать учёт
4. записать строку cas ""; подтверждённое создание → шаг 5; уже есть: прочитать строку, тот же unit и digest → шаг 5;
   иной unit или digest → 409 exists (резерв не откатывать); исчезла при чтении → повторить шаг 4.
   Отказ или неизвестный исход записи/чтения → 503, один резерв не подтверждает постановку просьбы
5. перечитать метку: появилась после шага 2 с теми же unit/digest и **с исходом** (держатель исполнил) →
   снять rid из учёта, ответ 200 answered; строку оставить жнецу с соблюдением settle; тот же unit и digest, но только begun без исхода (держатель взял мою строку) →
   ничего не трогать, 202 {queued: rid}; иной unit или digest → удалить только свою строку по cas, резерв оставить, 409 spent
6. journal → строка журнала; 202 {queued: rid}
Ошибки чтения/записи → 503, не успех по предположению; успешно прочитанный, но повреждённый
учёт — отдельный 429 шага 3. При любом отказе после резерва (включая определённый отказ
создания и 409 exists) резерв не откатывается: его мог использовать параллельный повтор.
Повтор тем же rid заново читает строку и метку; обрыв после резерва до создания лечится
переходом из шага 3 к шагу 4, где отсутствующая строка создаётся. Ответ 202 разрешён только
после подтверждения строки в шаге 4 и проверки метки в шаге 5 либо по begun шага 2. Освобождение — только по подтверждённому
исходу с теми же unit/digest либо по обслуживанию ниже. Это консервативный лимит, не
транзакция учёта, строки, метки и журнала; лишний резерв может временно уменьшить доступность.
```

**Гонки.** Две одинаковые подачи с одним ключом: rid один, создание строки пропускает одну;
вторая получает queued или уже известный answered по Н3. При разном теле сравниваются
unit/digest, чужая версия не заменяется. Разные rid одной единицы — разные просьбы;
этот урок не обещает их глобального порядка. Подача против жнеца проверяет метку повторно
после создания строки; свежесть строки сама по себе не заменяет эту проверку.

### жнец (консоль): каждые 2 с — снять отвеченные; каждые 30 с — закрыть брошенные

```
clear:  обычная просьба: подтверждённая метка с исходом для тех же unit/digest;
        fetched — подсказка перечитать метку, отсутствие/вытеснение rid из пульса не отменяет подтверждённый исход;
        rid в fetched — имя rid или SaidID(rid) среди имён через запятую (P/03.4 Н1.1 `said_id`);
        дозапись ADR-0054: подтверждённый fetched держателя, метку не читать/не создавать;
        дождаться возраста ≥settle по правилу выше, подтвердить текущую строку и основание;
        удалить по cas; rid снять из учёта человека (rids − rid, cas); неизвестность → оставить
sweep:  ветвь меток — только обычный профиль; дозапись, elsewhere и строки ресурса не получают меток этого прохода.
        Обычная строка с valid_until + REAP_AFTER < now или старше ttl (без срока):
          метки нет → метка expired создание-однажды {ended_by: reaper, unit, digest из строки} (Н1.5 no_begun)
          метка begun без исхода → {outcome: unknown, ended_by: reaper, error: "begun and never answered"} по индексу
        удалить строку по cas только после подтверждённой метки с исходом и возраста ≥settle;
        conflict метки → перечитать; неизвестное чтение/запись → оставить строку;
        снять rid из учёта человека по cas; просьбы ресурса (строки без unit) без хозяина — по ttl.
        Дозапись без fetched не закрывать меткой и не снимать по одному возрасту; её завершает обработчик.
asked:  один возраст ttl/settle не разрешает снимать непустой учёт. В фоне снимать отдельный rid через CAS
        только после подтверждённой метки с исходом обычной просьбы либо подтверждения fetched дозаписи
        по правилу исключения; повторный CAS перечитывает весь список,
        не теряя новые rid. Пустую строку учёта можно удалить по CAS после ttl/settle.
        Резерв без доказанного исхода, включая отсутствие строки, автоматически не освобождается: запоздалая
        подача ещё может создать строку. Административный DELETE asked оператор вызывает только в окне, где остановлены
        и завершены все подачи этого человека и его оставшиеся просьбы закрыты. Неподтверждённый покой — оператор
        не вызывает DELETE; это допуск обслуживаемого профиля, автоматическое обнаружение окна не обещано.
```

**Гонки.** Два держателя одной единицы: `put_new` метки пропускает одного; второй держатель закрывает чужую `begun` за сроком словом `unknown` по индексу — начавший, получив поздний ответ, пишет исход безусловно поверх, `late: true`, как и после жнеца. Жнец против держателя, который начал в последнюю секунду: метка `begun` уже есть — жнец пишет `unknown` по индексу, держатель, получив ответ, пишет исход безусловно поверх `unknown` — побеждает держатель (ADR-0054), `late: true` у исхода после `unknown`; жнец пишет только по прочитанному индексу и слово держателя не затирает. Повтор подачи тем же rid: `cas ""` — второй получает «есть»; совпали unit/digest — queued без исхода, answered с исходом; чужое содержимое — exists/spent.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **хранилище объектов на коробке и в кластере** (`OBJECTS` URI, каталоги, надгробия удаления `.gone/<ключ>` — урок 10 Н1.5 `delete`), пределы размера;
2. ~~**как ресурс узнаёт присутствие процессов**~~ — нормировано: замок присутствия Н1.4 `presence_lock` (второй пилот, Н-1);
3. **политика вытеснения кэша индекса** в пределах 64 MiB (Н1); число полос слияния (8) и срок (3 с) — норма Н3, не выбор;
4. **пределы просьб**: повторы `cas` учёта; `FETCHED_COUNT`/`FETCHED_BYTES`, `MARK_SWEEP` — [P/03.6](../../Platform/03-worker/spec/03.6-worker.norms.md) «Решает реализация» п. 1 (стадия B);
5. **долгий опрос `/events/wait`**: устройство памяти наблюдений и развёртываемый предел ожиданий; формы want/ответа и профиль таймаута — Н1.6, не выбор;
6. **строка журнала**: поля сверх `sub`/`target`/`addr` Н1.2 `journal`, роль-писатель, эпоха дерева (`e1`);
7. **что считается «живым ресурсом»** у консоли в пределах правила 45 с (door row, пульс) и `OBJECTS_TIMEOUT`.
8. **потоки и чтение тела**: срок приёма зеркала, способ проверки целого тела до публикации,
   пределы/сроки POST по владельцу двери М10/9 Н1.3 `body` (предел ≥ 1 MiB, срок чтения — 408), различение отказа до заголовков и обрыва после.

9. **PULSE_LIMIT** ресурса: конечное положительное число секунд из объявленного профиля, неизменное на протяжении прогона; Н1.4 задаёт измерение и исход, а не конкретное число.
