# М10/1 — Словарь операций хранилища: нормы

Канон урока М10/1 (ADR-0080, форма «лекция + spec/» — ADR-0080 доп. 2026-10-15). Повествование для человека —
[`../01-storage.md`](../01-storage.md), оно не норма. Контракт двери — [`01-storage.api.openapi.yaml`](01-storage.api.openapi.yaml). Как по этим
файлам писать реализацию — [`01-storage.README.md`](01-storage.README.md). Приёмка — `Source/tests/testdata/acceptance/М10_Platform/01/`.
Разделы и id норм (`М10/1-NN`) — те же, что в прежнем однофайловом уроке: на них ссылаются решения, находки ревью и записи окон.

## Н0 Словарь слов

Нормативные разделы всех уроков курса пользуются только этими словами; повествование — нет.

| Слово | Значение | Нарушение |
|---|---|---|
| **ДОЛЖЕН / НЕ ДОЛЖЕН** | требование; без него реализация не соответствует уроку | несоответствие, приёмка красная |
| **СЛЕДУЕТ / НЕ СЛЕДУЕТ** | рекомендация; отступление допустимо, называется в описании реализации с причиной | не нарушение, если названо |
| **МОЖЕТ** | выбор реализации; любой из названных вариантов соответствует | — |
| **решает реализация** | норма не задана нарочно; реализация обязана назвать свой выбор в своём описании (ARCHITECTURE продукта, записка курса) | выбор не назван |

Непомеченное словами ДОЛЖЕН/СЛЕДУЕТ/МОЖЕТ предложение нормативного раздела читается как ДОЛЖЕН.

## Н1 Форма

```yaml
# Строка хранилища. Хранилище — отображение ключ → строка; других сущностей у него нет.
row:
  key:                       # имя строки
    type: string
    rules:
      - not empty
      - does not start with "/"
      - no segment (between "/") equals ".."
      - at most 1024 bytes                     # у двери; реализация на файлах МОЖЕТ отказать раньше (ниже)
    note: одно написание — одно место; ключ, нарушающий правило, — отказ badkey, не починка
  items:                     # содержимое
    type: map                # string → string; порядок полей не имеет значения
    rules:
      - every key and every value is a string
      - weight (sum of byte lengths of every key and every value) at most the store's ceiling
    ceiling: 524288          # 512 КиБ; как хранилище объявляет свой потолок и когда он меньше — урок 10
  index:                     # версия
    type: string             # непрозрачна: сравнивается только на равенство
    rules:
      - handed out by the store on every write; never the same twice within one store
      - '"" names an absent row and is no version'
    wire: десятичное число без знака и ведущих нулей, до 20 цифр, как строка JSON
    note: "форма провода — норма двери (так хранилище выдаёт версии); непрозрачность — норма вызывающего (не разбирает версию, сравнивает только на равенство); хранилище с иной формой версии подошло бы с иной Н2, не с иным клиентом"

# Условие записи.
cas:
  absent (поля нет или null): безусловно — пишется поверх того, что есть
  "":                          только пока строки нет (создание; первый выигрывает)
  <версия>:                    только пока версия строки ровно эта

# Условие по другой строке (ADR-0074 доп. 1).
guard:
  key:   string              # строка-страж: обычно слот писателя; те же правила ключа
  index: string              # её версия, "" — страж отсутствует
  note: проверяется в той же операции, что и cas; права на строку-страж — права чтения вызывающего (урок 6)

# Идентификатор записи.
id:
  type: string
  rules: [1 to 64 lowercase hex digits]
  note: "необязателен; клиенту СЛЕДУЕТ ставить его на каждую запись (32 шестнадцатеричных знака случайности): после ответа «неизвестно» безопасен только повтор с тем же id (Н4; на деле — урок 5)"
```

Реализация на файлах, где строка — файл с именем из ключа, МОЖЕТ отказать и ключу, который проходит предел двери, если его кодированное имя не помещается в имя файла; свой предел, меньший 1024 байт UTF-8, она называет в своём описании (решает реализация). Платформа своих ключей длиннее двухсот байт не пишет.

## Н2 Двери

Процесс говорит с хранилищем своего сервера по HTTP с JSON-телами через unix-сокет; на коробке без группы хранилище МОЖЕТ быть открыто в процессе без двери, но его семантика — та же, и приёмка гоняется через дверь. Кто такой вызывающий, говорит сокет (урок 6).

Контракт двери — файл [`01-storage.api.openapi.yaml`](01-storage.api.openapi.yaml) рядом (OpenAPI 3.1; проверяется загрузкой инструментом). Маршруты: `GET /v1/get?key=`, `GET /v1/list?prefix=`, `POST /v1/write` (`Cmd`: put | delete); схемы `Row`, `Listing`, `Cmd`, `Written`, `Fault`; коды — по Н4.

Маршрут, которого нет, — `404 {kind: badrequest}`. Список кодов и видов закрыт: новый — только правкой этого урока.

## Н3 Проход

Словарь, которым написаны все проходы курса. Операция — одно неделимое действие хранилища: между её шагами никто не приходит; всё, что приходит, приходит до или после. В группе серверов «неделимо» значит «одна запись журнала, применённая каждым сервером одинаково»; на одной коробке — «под одной блокировкой» (решает реализация, см. ниже).

### прочитать(key) → (items, index)

```
проверить ключ (Н1)                       → иначе badkey
если прав на чтение нет                   → forbidden (урок 6)
если строки key нет                       → (null, "")
иначе                                     → (копия items, index)
```

Чтение линеаризуемо: отдаёт состояние не старше последней сделанной записи, которую видел любой вызывающий. В группе это значит, что чтение проходит через лидера текущего срока (продление аренды — чтение, и ведомый, отрезанный от группы, не должен подтверждать эпоху, которую остальные уже сдвинули; урок 3). Механизм — решает реализация.

**Гонки.** Чтение между двумя записями видит либо первую, либо вторую, никогда половину. Нет других.

### перечислить(prefix) → {key: index}

```
для каждой строки, чей ключ начинается с prefix (сравнение байт) → её index
порядок ключей — по байтам
```

`prefix` — любая строка байт, не ключ: правила ключа Н1 к нему не применяются, сегмент `..` ничего не значит, пустой префикс — все строки; отказов 400 и 403 у перечисления нет (Н2: 200, 404 нет маршрута, 503). Перечисление не требует прав на чтение значений: оно называет имена и версии, не содержимое (ADR-0021). Префиксу СЛЕДУЕТ кончаться на `/`: `testsub/count` совпал бы и с `testsub/counters/…`, и с `testsub/countdown`.

**Гонки.** Запись во время перечисления: строка либо в списке со своей версией, либо нет; перечисление не блокирует запись. Нет других.

### записать(key, items, cas?, guard?, id?) → index

```
проверить ключ, форму cas, guard и id (Н1)        → иначе badkey / badrequest
проверить вес items против потолка                 → иначе toolarge      (ничего не записано)
если прав на запись key нет                        → forbidden (урок 6)
если guard задан и прав на чтение guard.key нет    → forbidden
— далее одной операцией —
если id задан и уже применялся:
    если та запись была иной (op, key, items, cas, guard)   → badrequest
    иначе                                                   → её ответ, again=true; состояние не меняется
current := версия строки key ("" если нет)
если guard задан:
    at := версия строки guard.key ("" если нет)
    если at ≠ guard.index                          → guard {key: guard.key, index: at}; ничего не записано
если cas задан и cas ≠ current                     → conflict {index: current}; ничего не записано
index := новая версия (больше любой выданной этим хранилищем)
строка key := (копия items, index)
если id задан: запомнить (id → эта запись, ответ)
→ index
```

Порядок проверок внутри операции нормативен: страж раньше CAS. Отказ стража значит «ты больше не владелец — остановись», отказ CAS значит «перечитай и повтори»; тому, кто потерял слот, повтор не нужен. Страж по отсутствующей строке (`index: ""`) держит, пока строки нет.

Версия выдаётся только сделанной записи: отказ версии не тратит. Items копируются: хранилище не делит память с вызывающим ни на входе, ни на выходе.

**Гонки.**
- Два писателя с одним `cas` на одну строку: проходит ровно один, второй получает `conflict` с версией первого.
- Два создания с `cas: ""`: проходит ровно одно.
- Запись под стражем и смена стража (новый захват слота) в любом порядке: либо запись сделана до смены, либо отказана `guard` с новой версией стража; состояния «записано после смены» нет.
- Повтор записи с тем же `id` после ответа «неизвестно»: если первая применилась — повтор отвечает её ответом и ничего не меняет; если нет — применяется как первая. Вызывающий не различает эти случаи и не должен.
- Повтор с тем же `id`, но иным содержимым (другое `items`, `cas` или `guard`): отказ `badrequest`, ничего не записано — идентификатор принадлежит одной записи.
- Смена лидера между приёмом и применением: вызывающий получает `ambiguous`; см. выше.

### удалить(key, cas?, guard?, id?) → index

Поле `items`, если прислано, не читается независимо от его JSON-типа; его наличие не является отказом.

```
проверить ключ, форму cas, guard и id (Н1)        → иначе badkey / badrequest
если прав на удаление key нет                      → forbidden (урок 6; удаление — запись)
если guard задан и прав на чтение guard.key нет    → forbidden
— далее одной операцией —
повтор по id — как у записи
current := версия строки key ("" если нет)
если guard задан и версия guard.key ≠ guard.index  → guard
если cas задан и cas ≠ current                     → conflict {index: current}
убрать строку key (отсутствующая — не ошибка)
index := новая версия                              # удаление тратит версию
если id задан: запомнить
→ index
```

Удаление тратит версию, чтобы устаревший `cas` на удалённую и созданную заново строку не прошёл. Удаление отсутствующей строки — сделано: повтор сделанного удаления — то же удаление.

**Гонки.** Как у записи. Удаление и запись одной строки с одним `cas` по **существующей** версии: проходит одно — удаление тратит версию. С `cas ""` у отсутствующей строки удаление ничего не меняет (строки как не было, так и нет; версия чтения остаётся `""`), и последующая запись с `cas ""` проходит — победителя здесь выбирать не из чего.

### Повтор по идентификатору — память хранилища

Хранилище ДОЛЖЕН отвечать повтору тем же ответом не меньше двух минут после первого применения, пока после него применено меньше 50 000 записей с идентификатором; дольше и больше — МОЖЕТ забыть. Забытый повтор применяется как новая запись — поэтому `cas` у каждой записи, которая имеет значение.

**Гонки.** Два повтора одного `id` разом: применяется один (под блокировкой или в журнале), второй получает тот же ответ с `again: true`; повтор и новая запись с тем же `id`, но иным содержимым — первой применяется та, что раньше, вторая получает 400.

## Н4 Отказы

Закрытый список. Текст `error` — для человека, не нормируется; нормируются код, `kind` и поля.

| Причина | Код | `kind` и поля | Что делает вызывающий |
|---|---|---|---|
| ключ не по правилам Н1 (пустой, с `/` в начале, с сегментом `..`, длиннее предела) — целевой; у строки-стража — непустой ключ не по правилам (пустой ключ стража — `badrequest`: не по форме `guard`) | 400 | `badkey` | ничего: ошибка кода |
| тело не JSON-объект; `op` не `put`/`delete`; `items` не объект строк у `put`; `cas`, `guard` или `id` не по форме; `id` уже принадлежит иной записи | 400 | `badrequest` | ничего: ошибка кода |
| нет маршрута | 404 | `badrequest` | ничего |
| прав нет (чтение, запись, удаление, чтение стража) | 403 | `forbidden` | ничего: ошибка развёртывания или чужой процесс (урок 6) |
| версия строки не та, что в `cas` | 409 | `conflict`, `index` — версия сейчас (`""` — строки нет) | перечитать, применить своё поверх, повторить |
| строка-страж не на той версии | 412 | `guard`, `key`, `index` — версия стража сейчас | не повторять: заново проверить владение (урок 5) |
| строка тяжелее потолка; тело больше, чем дверь читает | 413 | `toolarge`, `limit`; у строки — `key`, `size` (вес строки); у тела сверх читаемого `size` МОЖЕТ отсутствовать | ничего: то, что делает строку тяжёлой, — в объект (урок 10) |
| лидера не нашлось за срок ожидания или истёк срок ожидания местной блокировки (п. 1 «Решает реализация»); запись **не сделана** | 503 | `unavailable` | повторить на следующем шаге цикла; держать, что держишь |
| запись дошла до лидера, исход **неизвестен** | 503 | `ambiguous` | повторить только с тем же `id`; кому важно — сначала прочитать |
| строка уже опубликована, а барьер долговечности (п. 3 «Решает реализация») отказал — на одной коробке тоже **неизвестно** | 503 | `ambiguous` | повторить только с тем же `id`: повтор довершает барьеры и отвечает первым ответом (`again: true`), новой версии не выдаёт; барьер отказал снова — снова `ambiguous` |

Отказ не цитирует вызывающему присланное, кроме ключа: ответ не становится больше от большей ошибки. Обрезанный, нечитаемый или не пришедший ответ двери вызывающий ДОЛЖЕН читать как `unavailable` для чтения и как `ambiguous` для записи — не как «нет» и не как исключение, роняющее цикл.

## Н5 Приёмка

Сценарии — `Source/tests/testdata/acceptance/М10_Platform/01/scenarios.tsv`, прогоняются через дверь Н2 любой реализации ролью с полными правами на префикс `acc/`; формат — в `README.md` рядом. Путь к двери (unix-сокет; у продукта — дверь `configstore`) — параметр раннера, не норма урока. Журнал исправлений ИИ — `corrections.tsv` там же.

| № | Сценарий | Норма |
|---|---|---|
| 01 | отсутствующая строка читается как `null, ""` | прочитать |
| 02 | создание с `cas: ""` проходит один раз | записать; гонка создания |

| 10 | страж по отсутствующей строке | guard `""` |
| 11 | страж раньше CAS: оба нарушены — 412 | порядок проверок |

| 14 | плохая форма `cas` и `id` — 400 badrequest | Н1 cas, id |
| 15 | строка тяжелее потолка — 413 и не записана | toolarge |
| 16 | `items` не объект строк — 400 badrequest | Н1 items |

| 18 | отказ не цитирует присланного | Н4 |
| 19 | ключ длиннее предела — 400 badkey, у строки-стража тоже | Н1 key |
| 20 | формы стража: пустой ключ, ключ не путь, индекс не версия, лишнее поле — 400; ничего не записано | Н1 guard |

Реализации, у которой хранилище открывается в процессе без двери (файлы, память), СЛЕДУЕТ (не ДОЛЖЕН: приёмка нормирует поведение двери, внутренний API — выбор реализации, п. «Решает реализация») гонять те же сценарии
и через свой API, отображая отказы на коды Н4: так порядок «страж раньше CAS» и формы проверены во всех её хранилищах,
а не только за дверью (проба мутаций 2026-10-14: за дверью 39 % мутантов выжили, в хранилищах без двери — все).

Проверяются чтением (дверями не воспроизводятся детерминированно): `unavailable`/`ambiguous` при смерти лидера — стенд урока 11; `unavailable` при истечении срока ожидания местной блокировки — ветка отказа до записи; память повторов по времени; линеаризуемость чтения.

Независимость памяти `items` на входе и выходе проверяется чтением реализации операций: переданный вызывающим
словарь и словарь, возвращённый чтением, не делят изменяемую память с хранилищем. Причина: HTTP-сериализация
скрывает общую память, а сц. 03 только записывает и читает значение. Прогон тех же двух шагов через API в процессе
без последующего изменения переданного или возвращённого словаря тоже не проверяет копирование.

## Решает реализация

Каждая реализация называет в своём описании:
1. **механизм неделимости** на одной коробке (блокировка файла, мьютекс) и в группе (журнал консенсуса) и срок ожидания блокировки — что вызывающий получает по его истечении (как `unavailable`);
2. **как выдаётся версия**: счётчик в файле, индекс журнала плюс основание группы — лишь бы не повторялась; с какого числа начинается;
3. **раскладку на диске** и **барьеры долговечности** (запись доходит до носителя до публикации; удаление переживает потерю питания); режим без барьеров допустим только по явному слову окружения;
4. **предел длины ключа** реализации на файлах, если он меньше 1024;
5. **как хранилище, которое может прочитать свою строку не полностью** (повреждённый файл), сообщает об этом: форма ответа — норма (Н2 `Row.unreadable`, М10/1-18); здесь — как реализация обнаруживает порчу и что пишет в лог;
6. **срок и объём памяти повторов** сверх минимума Н3;
7. **как дверь отличает «не добавлено в журнал» от «неизвестно»**; срок ожидания лидера перед `unavailable` — 5 с от потери лидера, норма урока 11 Н1.3, не выбор.

## Чеклист готовности

Реализация соответствует уроку, когда выполнена каждая норма; id нормы `М10/1-NN` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **М10/1-01** отсутствующая строка — `null, ""`, не ошибка — сц. 01
- [ ] **М10/1-02** `cas: ""` создаёт один раз — сц. 02
- [ ] **М10/1-03** версия выдана записи и прочитана обратно со своим содержимым — сц. 03; `items` не делят память на входе и выходе — проверяется чтением: HTTP скрывает общую память, сц. 03 не меняет переданный или возвращённый словарь (Н5)
- [ ] **М10/1-04** устаревший `cas` — `409 conflict` с версией сейчас, ничего не записано — сц. 04, 06
- [ ] **М10/1-05** запись без `cas` — поверх — сц. 05
- [ ] **М10/1-06** удаление идемпотентно и тратит версию; присланное `items` не читается — сц. 06, 07
- [ ] **М10/1-07** версия никогда не повторяется — сц. 07; проверяется чтением: после перезапуска и выборов (урок 11)
- [ ] **М10/1-08** перечисление: префикс по байтам, порядок по байтам, версии — сц. 08; для `keys` проверяется и порядок имён в ответе (README приёмки)
- [ ] **М10/1-09** страж: `412 guard` с `key` и `index` сейчас, ничего не записано; по отсутствующей строке — `""` — сц. 09, 10
- [ ] **М10/1-10** страж раньше CAS — сц. 11
- [ ] **М10/1-11** повтор по `id`: первый ответ, `again: true`; иное содержимое — `400` — сц. 12; срок памяти — проверяется чтением
- [ ] **М10/1-12** ключи, формы, потолок, маршруты — `400`/`404`/`413` по Н4 — сц. 13–17
- [ ] **М10/1-13** отказ не цитирует присланного — сц. 18
- [ ] **М10/1-14** `unavailable` ≠ `ambiguous` ≠ `conflict`; обрыв ответа читается как первые два — проверяется чтением: стенд урока 11; таймаут местной блокировки — `unavailable` до записи, проверяется чтением ветки отказа (Н4)
- [ ] **М10/1-15** чтение линеаризуемо — проверяется чтением: механизм назван в описании реализации
- [ ] **М10/1-16** права: отказ 403 вне своего префикса, в том числе на строку-страж; перечисление имён без значений — сц. 21
- [ ] **М10/1-17** формы стража и предел ключа — `400` по Н1; тело сверх читаемого — `413` — сц. 19, 20, 22
- [ ] **М10/1-18** повреждённая строка читается как `{items: null, index, unreadable: true}`, запись с `cas` по этой версии заменяет её — проверяется чтением (реализации на файлах; у группы не бывает)
