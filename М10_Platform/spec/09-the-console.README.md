# М10/9 — Консоль: инструкция для реализации

## Задача

Создать процесс консоли, общий модуль и границу оболочки по Н1. Собственные HTTP-двери и все отказы — Н2; доменные, единичные и событийные двери подключаются по их владельцам, не заново определяются здесь.

## Входы и их приоритет

Канон — [нормы](09-the-console.norms.md). [OpenAPI](09-the-console.api.openapi.yaml) выражает HTTP-формы, [приёмка](../../Source/tests/testdata/acceptance/М10_Platform/09/README.md) — наблюдаемые примеры, [лекция](../09-the-console.md) объясняет причины. При противоречии записать место и контрпример и передать Спецификации; инструкция не вводит новый отказ. Внутренние типы, функции и устройство реализации остаются её выбором.

## Что создать

- Процесс консоли, общий модуль и границу оболочки, соблюдающие корневые и mounted-маршруты.
- Сессии, grants и собственные HTTP-двери по Н1–Н2; наблюдения `/servers`, `/resources`, `/where`.
- Полные ответы и безопасный вывод, включая отдельные проверки CSP, media type и HEAD без тела.

## Порядок работы

1. Составить закрытый список маршрутов, методов, полос и максимальных тел. Разобрать /session до обычного допуска, но стирать X-User до любой ветви. Для body-зависимого гранта получить требуемую возможность заранее, конкретные единицы — после ограниченного чтения; запись только после всех проверок (Н1.3, Н3).

2. Подключить три состояния сессии и закрытый may. Развести повтор одной заявки и новое действие; разрешать автоматический повтор только по памяти владельца. Для неизвестного PUT/таблицы сначала чтение (Н1.5).

3. Реализовать наблюдения /servers, /resources и /where. Хранить возраст увиденных изменений на местных монотонных часах. Недоступность обязательного чтения возвращать отказом; никогда не заменять ею доказанное отсутствие (Н3).

4. Подготовить свежий стенд testsub/testsub2 без домена и фоновых процессов. Выполнить 6 сценариев/26 шагов по README приёмки. Для каждого собственного ответа проверять полный контракт и media type, а не только подмножество TSV.

5. Отдельно проверить модуль/оболочку, grants и CSP; стенд с доменом и держателем нужен для ветвей, отсутствующих в TSV. Зафиксировать выбранные лимиты/полосы/таймауты из раздела «Решает реализация».

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.3/Н3 | Отсутствие ключа и ошибка чтения становятся одним пустым значением | 503 при неизвестном доверии; открыто только достоверное отсутствие ключей и следов. |
| Н1.5 | Кэш ключа по method/path/body сливает два нажатия | Ключ на логическое действие; новый вызов независим. |
| Н3 | Часы пульса считаются возрастом наблюдения | Считать возраст от местного изменения; часы автора не подтверждают свежесть. |
| Н2 | HEAD сериализует JSON или text/html проверяется как JSON | HEAD без тела; media type по каждой операции. |

## Готово, когда

Для всех 12 id приведено конкретное свидетельство или непроверенная зависимость. TSV подтверждает открытый локальный режим; он не доказывает безопасность доменного входа, порядок JS, атомарность снимка или эпоху двери. OpenAPI отдельно проверяет формы; совместимость общего console.js — отдельное сравнение байтов и тест контракта.

## При расхождении

Сравнить норму, форму ответа и сценарий. Зафиксировать точный вход и исход; отличие реализации не переносить молча в канон. Решение отражается в норме, контракте, инструкции и затронутой приёмке; происхождение ошибки и проверка связанного класса — в журнале Спецификации.

Дополнительная проверка после прогона 33: HTTP Where без достоверной двери не имеет поля door, а не содержит null. Библиотека для оболочки преобразует отсутствие в null. Проверить оба уровня отдельно, включая отрицательный HTTP-пример door:null.


## Сверка монтирования (G37-02/03)

Сверить полные URL по Н2 и контрактам владельцев3/4/10: читать standard servers вместе
с paths, а не только ключ paths или x-mounting. Провести одинаковый запрос к root
и /testsub2 с выбранной спекой. /servers наблюдения имеет оба варианта, а операции
/servers/{server}/labels и decommission остаются общими. Просьбы8 всегда идут через
/{sub}/requests и /{sub}/asked/{sha16}, даже для root; короткие пути не добавлять.
GET/HEAD страницы смонтированной подсистемы оба404, тело у HEAD отсутствует;
summary и текст405 должны соответствовать фактическому списку методов.
