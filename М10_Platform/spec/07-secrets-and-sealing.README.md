# М10/7 — инструкция для реализации

## Задача

Хранить секреты в конвертах, выдавать их маской, открывать только нужному получателю;
сохранять привязку к строке/полю и управлять кольцом в объявленной области обслуживания.

## Входы и их приоритет

- Канон — [нормы](07-secrets-and-sealing.norms.md).
- HTTP-входы — [единицы М10/3](03-units-slots-epochs-lease.api.openapi.yaml) и
  [хранилище М10/1](01-storage.api.openapi.yaml); применение тел — Н2 этого урока.
- [Приёмка](../../Source/tests/testdata/acceptance/М10_Platform/07/README.md) — таблицы и сценарии.
- [Лекция](../07-secrets-and-sealing.md) — объяснение причин и границ.

Урок не создаёт отдельную HTTP-дверь. CLI, HTTP и состояние единицы имеют разные
формы исхода. Внутренние функции, библиотеки и классы ошибок здесь не предписываются.

## Что создать

Распознавание и маскирование секретов, запечатывание/открытие по Н1.2, проверку
`bound_to`, обработку адресов по спеке, `new|seal|rotate|status` и их диагностику.
Читатели строк задаются здесь, генератор прав — уроком 6; память повторов — уроком 3.

## Порядок работы

1. Выписать выходы Н1.4: ответ, копия повтора, снимок, журнал, пульс, argv и отказ.
   Проверить секретные поля на любой глубине; таблица и строка единицы имеют разные
   правила выдачи. Текст отказа также является выходом, который может раскрыть секрет.
2. Проверить адресные правила на всех строках secret_in.tsv, а маску журналов —
   на всех строках log_mask.tsv. Использовать названные в таблице поля общих спек,
   не подменять их правилами testsub2. Сравнивать полный показ и отсутствие утечки в отказе.
3. Реализовать конверт, кольцо и состояния отсутствующего/нечитаемого ключа по Н1.2.
   Пустой/повреждённый файл не включает режим разработки. Проверить открытие с неверными
   ключом, kid, строкой и полем; видимый префикс enc:v2 не доказывает успешного шифрования.
   Проверить комментарии кольца: # в начале kid запрещён, внутри допустим; комментарий
   отдельной строкой, после записи ключа — отказ. В диагностике подставляется фактический kid.
4. Встроить запись в существующие POST/PUT М10/3. До заявки POST проверить ограничение
   режима без кольца: непустой секрет на любой глубине — 400 sealing key required,
   без новой заявки и изменения существующей. При кольце HMAC считают по исходному
   запросу, не маске; при повторе — под kid сохранённого отпечатка. Маска и внешний конверт отказываются;
   отсутствие, пустая строка и null при PUT сохраняют прежний секрет. Изменение bound_to
   проверяется против сохраняемой строки под CAS, включая повтор после конфликта.
5. Использовать правила владения заявкой М10/3: 5xx не становится done; чужую pending
   не снимать; подтверждённая или неизвестная запись единицы сохраняет pending.
   Для заданного нечитаемого кольца проверить SealingUnavailable на любом POST/PUT единицы, также без непустого секретного поля, до HMAC/заявки. GET/DELETE сохраняют свои исходы.
6. Выполнить обслуживание по таблице Н3. Один оператор, обычные записи остановлены;
   rotate принимает область kN, неподходящий вход сохраняет файл. Старые ключи остаются,
   полностью: удаление прежних ключей вне профиля урока. Ноль конвертов не снимает
   зависимость живых HMAC-заявок и копий. Ошибка обхода не означает ноль.
7. Подготовить отдельный экземпляр, кольцо и две спеки по README приёмки. Подготовить c1
   до HTTP-сценариев; выполнить файл целиком по порядку, сохраняя строки между сценариями.
   При повторном полном запуске использовать новые данные и память заявок. Проверить
   подстановки ключей и роль store, включая явное переключение в последнем сценарии.
8. Закрыть все пункты канонического чеклиста. Отдельные свидетельства нужны для открытия
   воркером, ротации, файловых прав, AAD, вложенных полей и отказа нечитаемого кольца.
   HTTP-сценарии этих свойств полностью не наблюдают.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.1/Н3 | Маску приняли за «оставить», null записали строкой | Маска — отказ; null/пустота/отсутствие при PUT — прежнее значение |
| Н1.2 | Нормализовали plaintext или заменили разделитель AAD | Байты UTF-8 как даны; AAD по точной форме строки/поля |
| Н1.2 | Ошибка чтения кольца стала отсутствием настройки | Различить состояния; заданное нечитаемое кольцо запрещает все POST/PUT единиц |
| Н1.2/Н3 | max для rotate применили к произвольным kid | Отказать вне kN; проверять номер до изменения файла |
| Н1.3 | Точное имя секрета трактуют как префикс | Префикс только с конечным `/`; сверить эффективных читателей с М10/6 |
| Н2/Н4 | 503 консоли выдали как `{kind,error}` хранилища | Для записи единицы нужны detail/error и установленная причина |
| Н1.4 | Отказ или отладочная строка повторяет пароль | Проверить выходы после маскирования, включая вложенные адреса |

## Готово, когда

Выполнен весь чеклист М10/7, таблицы и последовательный HTTP-файл, названы выборы
реализации и отдельные свидетельства чтения/стенда. Данные прошлых запусков не заменяют
подготовку нового. Режим разработки без кольца не объявляется проверкой запечатывания;
JSON-схема и маска ответа не объявляются проверкой криптографии.

## При расхождении

Сообщить «Спецификации» исходный срез, место, контрпример и происхождение ошибки.
Сначала проверить, принадлежит ли правило этому уроку, М10/3, генератору прав или М11.
При исправлении согласовать владельца нормы и прямых потребителей, сохранив границы
обслуживания; новый механизм не добавлять только ради неподдержанного случая.

Проба нормализации Н1: pass%E2%80%8Bword после декодирования/NFKC/удаления U+200B распознаётся как password; значение и исходное написание имени не нормализуются. Сравнить U+200B в начале/середине/конце и уже обычный password; проверять отображение маски по исходному URL.
