# М10/2 — инструкция для реализации

Этот файл — для агента или человека, который пишет реализацию урока на языке `<LANG>`.
Объяснение предмета — [лекция](../02-the-spec-and-the-strict-loader.md); для выполнения задания она не нужна.

## Задача

Реализовать строгую загрузку спеки и каталога спек по Н1–Н4, чтение и смену спеки в хранилище по Н3,
а также форму `GET /spec` по контракту. Пройти приёмку Н5 штатным путём загрузки и закрыть весь [чеклист готовности](02-the-spec-and-the-strict-loader.norms.md#чеклист-готовности).

Основной вход этого урока — процедура `загрузить(байты, источник)`, не HTTP-дверь.
Отдельный OpenAPI-файл описывает только `GET /spec`; в нём нет протокола вызова загрузчика или установщика.

## Что создать

Обязательное поведение — в каноне. Внутренние типы, функции, устройство ошибок и выбор библиотек остаются
реализации; названия процедур в Н2–Н3 обозначают их смысл, а не обязательные сигнатуры конкретного языка.

1. **Загрузку одной спеки** из байтов с именем источника: проверка текста, имени, ключей, значений и ссылок,
   затем заполнение умолчаний в порядке Н3. Результат — целая спека либо отказ с нужными сведениями по Н4. После проверки ключей отказать NaN, бесконечности и переполнению float, включая вложенные числа opaque/default/inherit; все принятые значения представимы JSON.
2. **Загрузку каталога** с проверками `worker.requests` и `placement.near` по Н3. Приёмка одного файла
   не подменяет проверку каталога; в раннер таблицы не добавляются не названные ею соседние спеки.
3. **Чтение и установку спеки в хранилище** по Н1.5 и Н3: первая строка с `rev: 1` и `cas: ""`, метка,
   дайджест, растущая ревизия, запись с `cas`, доведение метки, старт и остановка процессов.
   Неверный файл не устанавливается. При `toolarge` основной строки команда заканчивается кодом 2
   с диагностикой Н4 и не переходит к метке; при подсчёте веса учитываются исходные байты YAML и страница,
   а не только разобранные значения. Период обнаружения смены отсчитывается от публикации метки.
4. **Представление `SpecView` для `GET /spec`**. Дверь принадлежит консоли; её интеграция и общие отказы —
   по ссылкам Н2 и Н4 на урок 9. Встроенная процедура загрузки не получает новый HTTP-маршрут.
5. **Прогон общей таблицы** штатным путём загрузки согласно README приёмки. Те же файлы СЛЕДУЕТ прогнать
   через установку спеки (`spec put`), как указано в Н5 и М10/2-16.
6. **Описание реализации** с ответами на семь пунктов «Решает реализация» и указателями для тех пунктов
   чеклиста, которые проверяются чтением.

## Порядок работы

Это возможный порядок, а не дополнительная норма об устройстве кода.

1. Прочитать нормы целиком. Выписать границы закрытых, именованных и непрозрачных уровней из Н1.2,
   их уроки-владельцы и семь выборов реализации. Проверить обязательные unit/rows/id: загрузчик не придумывает семью или вид id; отсутствие unit.fields означает пустое отображение.
2. Настроить чтение байтов и разбор текста по Н1.1. Проверки, которым нужен исходный текст или список
   ключей до превращения в отображение, выполнить до потери этих сведений библиотекой.
3. Выполнить проход загрузки Н3 в заданном порядке. Сначала проверяются текст и имя, затем все неизвестные
   ключи; проверки значений и ссылок идут после этого. Заполнение умолчаний не скрывает ошибочный вход.
4. Прогнать `verdicts.tsv`: один файл — одна загрузка. Сверить множество файлов с таблицей;
   отказ засчитывать по правилам README, а не по любому исключению или ненулевому коду процесса.
   Выполнить дополнительные сравнения `diagnostics.tsv`; для остальных ветвей диагностики указать проверку
   чтением по Н5, поскольку одних вердиктов для проверки путей и номеров строк недостаточно.
5. Проверить каталог, затем хранение и смену спеки: повтор установки без изменений, конфликт `cas`,
   отставшая и отсутствующая метка, все причины отказа старта Н4 (включая неподтверждённое чтение строки/метки и несовпадение встроенной спеки), старт между двумя записями установщика, `toolarge` основной строки
   до записи метки. Для каталога не приписывать чтению атомарный снимок или обязательный отказ при любом
   изменении файла: проверяются фактически полученные байты и связи. Предметы проверки — Н3, Н5 и чеклист.
6. Сверить успешный ответ `GET /spec` со схемой `SpecView`, а общие отказы консоли — со схемами своего кода.
   Диагностика загрузки и stderr установщика не становятся телами этого GET. Завершить описание реализации и чеклист;
   проверку таблицы не объявлять проверкой всего жизненного цикла спеки.

## Ловушки, которые зависят от языка и библиотеки

| Норма | Ловушка | Как проверить |
|---|---|---|
| текст по Н1.1 | YAML-библиотека принимает больше конструкций, чем разрешено уроком | отдельно проверить границы подмножества, кодировку, документы, теги, якоря, глубину и отступы |
| повторные ключи запрещены (Н1.1) | библиотека уже заменила первое значение последним | обнаруживать повторы до потери пар ключ–значение, включая потоковые отображения |
| скаляры по Н1.1 | `Off` стал булевым, `010` восьмеричным, а строка в кавычках — числом | сверять вид исходного скаляра с правилами Н1.1; не приводить строку к числу по ожиданию поля |
| целое — не булево (Н1.2, Н1.3) | язык или приведение считает `true` единицей | различать JSON/YAML-типы до числовой проверки |
| предел целого 2^53 − 1 (Н1.1) | преобразование в число с плавающей точкой уже округлило вход | проверять точное значение целого до преобразования, которое может потерять разряды |
| отсутствие и сказанный ключ без значения различаются (Н1.2) | `null`, пустое отображение и отсутствие сведены к одному умолчанию | сохранять различие и применять правило конкретного раздела |
| именованные и непрозрачные уровни (Н1.2) | один обход либо запрещает имена автора, либо пропускает незнакомые ключи поля | менять способ проверки только на уровнях из перечней Н1.2 |
| незнакомые ключи раньше значений (Н3) | декодирование в типизированную структуру останавливается на первом неверном значении | сначала завершить проверку ключей и собрать все неизвестные пути |
| `blob` без `required: true`, `default`, `inherit` (Н1.3) | общее описание поля допускает свойства, запрещённые этому типу | применить ограничения типа после проверки общей формы поля |
| дайджест исходных байтов (Н1.5, Н3) | YAML разобран и записан заново перед вычислением SHA-256 | вычислять дайджест байтов `yaml`, хранящихся как есть |
| метка после строки, только вверх (Н3) | задержавшийся установщик записывает старую ревизию поверх новой; период чтения ошибочно считают от записи строки | следовать проверкам ревизии и `cas`; ветка «без изменений» тоже доводит метку; после обрыва установки это зависит от следующего `spec put`, срок которого не задан |
| `SpecView` — форма ответа (Н2) | сериализация внутренней структуры добавляет ревизию или служебные поля | сверить обязательные поля и закрытые объекты со схемой; ревизии в ответе нет |

## Проверка выдаваемой формы

Кроме вердиктов загрузки проверить GET /spec: имя по Н1.2, включая console/audit;
восемь типов полей, значения default/inherit по типу, enum только у string/bool.
Отсутствующий default — null, отсутствующий inherit не выдаётся; list — массив строк,
json сохраняет произвольную JSON-структуру с числовыми пределами Н1.1. Проверить не только
число в поле float, но и вложенные default/inherit типа json, а также display/servers/door/places/domain:
`1e309` и `-1e309` запрещены на любой глубине, `1e308`, `-1e308`, null, bool и строка "1e309"
не запрещаются этим ограничением. `JsonValue` рекурсивно описывает этот общий предел ответа;
точность исходного int и его лексический вид по-прежнему проверяет загрузчик до выдачи JSON.
Схема не проверяет принадлежность default значению
соседнего enum: её отдельно сверяют с загруженной спекой. Неверный SpecView не становится допустимым
из-за успешного разбора JSON или проверки только перечня типов.

## Готово, когда

- [ ] Все 272 файла дают вердикт из таблицы: 46 `ok`, 226 `refused`; множества файлов и случаев совпадают.
- [ ] Отказанные файлы дают объяснение с именем источника; авария или частично загруженная спека не засчитывается.
- [ ] Все случаи `diagnostics.tsv` дают ожидаемые пути и требуемые номера строк, включая отказы nonfinite/переполнения float и вложенного JSON; диагностика прочих ветвей проверена чтением по Н5 и названа в описании.
- [ ] Те же файлы прогнаны через установку спеки либо в описании названа причина отступления от СЛЕДУЕТ (М10/2-16).
- [ ] Все пункты нормативного чеклиста готовности закрыты указанными в них проверками; проверки чтением названы отдельно.
- [ ] Ответ `GET /spec` соответствует контракту; проверки двери выполняются по Н5 и уроку 9.
- [ ] Описание реализации отвечает на все семь пунктов «Решает реализация».
- [ ] Вопросы к нормам переданы их автору; собственные предположения не выданы за канон.

## При расхождении кода и норм

| Ситуация | Действие |
|---|---|
| Вердикт не совпал, норма однозначна | исправить загрузчик или его штатный путь, затем повторить случай |
| Таблица противоречит норме | передать автору норм дефект приёмки; не менять вердикт ради зелёного прогона |
| Норма неполна или противоречива | описать вопрос с входным файлом и ссылкой на раздел; согласовать правку канона |
| После исправления ИИ выявлено повторяющееся неверное толкование | записать образец и уточнение в `corrections.tsv` по ADR-0080 |
