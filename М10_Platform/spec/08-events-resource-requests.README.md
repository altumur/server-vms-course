# М10/8 — инструкция для реализации

## Задача

Дать платформе объекты, события и их чтение; ресурсу — уборку и зеркалирование;
держателю — исполнение просьбы с меткой до вызова и явным неизвестным исходом.

## Входы и их приоритет

- Канон — [нормы](08-events-resource-requests.norms.md), определения Н0 — по М10/1.
- [HTTP-контракт](08-events-resource-requests.api.openapi.yaml) выражает Н2.
- [Приёмка](../../Source/tests/testdata/acceptance/М10_Platform/08/README.md) задаёт подготовку и наблюдения.
- [Лекция](../08-events-resource-requests.md) объясняет причины и границы.

Объекты и метки используют словарь хранилища М10/1, роли — М10/6, общая дверь консоли —
М10/9. Полный PUT блобов принадлежит М10/10, restore — М10/11. Внутренние функции,
библиотеки и способ размещения обработчиков не предписаны.

## Что создать

Операции объектов и их разрешённую дверь; запись событий с бакетами, классами и подавлением;
чтение дерева с ограниченным кэшем; запрос ресурса и слияние консоли; подсказку wait;
проход ресурса retain → usage → relieve → mirror; подачу просьбы, учёт, держателя и жнеца.
Целая копия файла, ответивший источник, подтверждённая метка и опубликованный исход —
разные границы подтверждения, одна не доказывает другую.

## Порядок работы

1. Разделить файл и строку-объект. Проверить put_new и CAS по Н1.1, запрет выдавать
   строки-объекты дверью файлов, равные written и missing. Отсутствие ответа сервера
   не превращать в доказательство отсутствия объекта.
2. Записать событие под эпохой. Идентификатор различает процессы, коробки и перезапуски;
   поля платформы нельзя затереть полями подсистемы. Проверить оба класса, of, бакет
   по t, подавление и сохранение целой строки; fsync проверять отдельным свидетельством.
3. Построить запрос над файлами: параметры, кандидаты, фильтр, epoch_is, приоритет тревог,
   limit и truncated. Одинаковый запрос с пустым кэшем и после его вытеснения даёт тот же
   результат при неизменных файлах. Порванный хвост даёт partial, не строку события.
4. Слить ресурсы с дедупликацией и ограниченным ожиданием. Различить complete, partial
   и truncated; потерю источника назвать в incomplete. Поздний ответ не дописывается
   в уже отправленный JSON. Общего снимка ресурсов не обещать.
5. Сделать wait по Н1.6: четыре закрытых ответа, личность при вытеснении, очередь и
   таймаут. Клиент продолжает периодический проход при потере подсказки, переполнении
   или перезапуске ресурса.
6. Выполнить проход ресурса. Неизвестное чтение retention/holds не даёт права удалять;
   free_ask отличается наличием unit, а не префиксом rid. Снятие использует CAS версии,
   на которой проверена форма строки. Зеркало публикуется после проверки полного тела
   и суммы; неуспех сохраняет прежнюю копию.
7. Выполнить таблицу состояний просьбы Н3: допуск и срок, подтверждённая begun, единственный
   вызов. Проверить конфликт и неизвестный исход каждого чтения/изменения. Наличие begun
   ещё не доказывает вызов внешнего действия.
8. Закрыть жизненный цикл: итог начавшего побеждает закрытие чужой begun; жнец пишет
   по индексу и затем снимает строку. Учёт обновляется CAS. Метку удаляет только держатель
   после исчезновения строки и kept. Граница памяти повторов сообщается клиенту.
9. Пройти шесть изолированных сценариев. Проверять полные ответы по владельцу формы,
   даже при ожидании только кода в TSV. Для каждого пункта чеклиста назвать отдельное
   наблюдение; пробы вне TSV перечислены в README приёмки.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Проверка |
|---|---|---|
| Н1.1/Н2 | prefix проверен как ключ; traversal прошёл декодирование | Пустой prefix допустим; пустой сегмент ключа, точка, две точки, обратная косая и управляющие — нет |
| Н1.2/Н1.3 | Поля события затёрли метаданные; PID повторился на другой коробке | Поля платформы защищены; id различает экземпляры |
| Н1.3 | bool принят за integer, NaN за число, обрезка за неполноту источников | Конечные числа, целый limit; разные truncated/partial/incomplete |
| Н1.6/Н2 | JSONL обёрнут массивом; wait вернул события; метка выдана числами | Проверить форму, типы и отсутствие лишних полей |
| Н2 | После заголовков выдан второй JSON-отказ | Обрыв остаётся обрывом; неполная копия не публикуется |
| Н3 | Таймаут CAS сочли отсутствием метки | Нет подтверждения begun — нет вызова; unknown не разрешает повтор |
| Н3 | Старый жнец затёр исход или удалил новую строку | Закрытие/удаление по индексам; поздний итог начавшего сохраняется |

## Готово, когда

Выполнен весь канонический чеклист, названы выборы реализации и свидетельства для
норм вне TSV. Раздельно показаны успех, известный отказ и неизвестный результат
публикации. Проверка схемы не проверяет файловую долговечность или гонку;
чтение алгоритма не доказывает исполнение в нескольких процессах.

## При расхождении

Передать «Спецификации» срез, место и контрпример; установить, был ли он до правки.
Исправить источник нормы и прямых потребителей, проверить весь связанный класс.
Не расширять урок новым механизмом ради случая вне объявленного профиля.

Дополнительная проверка после прогона 33: После любого отказа подачи резерв сохраняется: им мог воспользоваться параллельный повтор. Проверить расписание A reserve → B accepted → A definite failure и отказ новой C при лимите 1; непустой учёт по одному возрасту не освобождать. Недоступное чтение учёта — 503, прочитанная испорченная форма — 429. GET объекта: 64 МиБ/+1, без успешного усечения. Сц.05 допускает быстрый 200, rid вычислен по заголовку до подачи.

Исход refused после вызова всегда имеет error, performed никогда; проверить и проход, и форму метки.

Проба обрыва между резервом и строкой: повтор с прежним ключом проходит шаги 4–5; один asked не разрешает 202. Проверить отсутствующую, совпадающую и чужую строку, готовую/begun метку и неизвестное чтение; чужая строка не меняется, отказ сохраняет резерв.
