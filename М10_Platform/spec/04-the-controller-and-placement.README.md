# М10/4 — инструкция для реализации

## Задача и входы

Реализовать контроллер спеки и операторские двери политики, дренажа, меток и вывода сервера.
Контроллер принимает решения строками; запуск процессов относится к уроку 11.

Источники по порядку: [нормы](04-the-controller-and-placement.norms.md), включая Н0;
[HTTP-контракт](04-the-controller-and-placement.api.openapi.yaml);
[приёмка](../../Source/tests/testdata/acceptance/М10_Platform/04/README.md).
[Лекция](../04-the-controller-and-placement.md) объясняет механизм.
Формы единицы и слота — [урок 3](03-units-slots-epochs-lease.norms.md), ключи спеки —
[урок 2](02-the-spec-and-the-strict-loader.norms.md). Пульс — [урок 5](05-the-worker-under-its-slot.norms.md).

## Что создать

- Чтение картины мира, эффективных меток и наблюдение свежести по своим часам; состояния ресурса и судьбы слота.
- Проход Н3 с отдельными попытками шагов, выбором кандидатов и записью решений через cas.
- Сверку назначений, переезд, уход, предложения запасным, вывод сервера и защиту spec_rev.
- HTTP-двери Н2, отчёт Н1.2 и свидетельства выполнения 22 пунктов чеклиста, включая допуск Н1.5.
- Описание всех восьми выборов реализации. Внутренние функции, типы и библиотеки выбирает реализация.

## Порядок работы

1. Выписать строки и писателей. Различить решение placement, производное workers, команду оператора
   и отчёт прохода. Версия строки хранилища, rev и spec_rev — разные значения.
2. Собрать картину мира: последние известные свойства отдельно от наблюдаемой свежести.
   Начать отсчёт с первого взгляда. Проверить нечитаемую строку меток, отсутствие строки и первый запуск.
3. Проверить выбор по порядку Н3: пул, ограничения, предпочтения, свободная ёмкость.
   Группа требует места на всех ожидающих; предпочтение дома не обходит ограничение.
   Уже размещённая единица не становится новой из-за появления более свободного воркера.
   Для distinct применить слотовый порядок М10/3 Н1.4, включая w-a/w-b и равные номера w-01/w-1.
   При равной свободной ёмкости сохраняется отдельное сравнение по полному имени ASCII.
   Предложение нового имени и отзыв используют определённые там же max и слотовый порядок.
4. Реализовать turn и intent по Н1.5/Н3: все изменения placement/workers защищены guard turn,
   а новое решение принимает свежую нагрузку с резервами. Группа получает одну цель, снятия всех
   предшествуют общему добавлению; незавершённый intent восстанавливается до следующего допуска.
   После неизвестного исхода сначала барьер версии turn, затем перечитка. Проверить два контроллера
   на разных единицах: capacity 1, одинаковый spread_by, разные home членов группы. Смена владельца
   не позволяет позднему писателю ни добавить в старое назначение, ни снять из нового.
5. Разобрать таблицу судеб по возрасту наблюдаемой версии слота: 45/90 с, gone, hung, wait, unsure, два молчания.
   Сдвиг until писателя и перезапуск судьи проверяются отдельно; будущий конечный until не порча.
   Проверить names_given при продлении между суждением и захватом; неизвестное gen не заменять нулём.
   Отдача сохраняет offer-поля, в том числе при восстановлении порванной строки с читаемым gen:
   предложение остаётся доступным только запасному своего набора по таблице захвата урока 3.
6. Сделать двери по Н2. Политика и where относятся к подсистеме; drain и servers — к корню консоли.
   В UnitRef и обеих картах drain имя подсистемы следует Н1.2 урока 2, включая запрет
   platform/domain/console/audit. Поле subsystem имеет ту же грамматику; совпадение ключей карт,
   значений subsystem и видимость проверяются отдельно от схемы.
   У меток проба не пишет, PUT возвращает прогноз will_move ссылками sub/id с фильтром view.
   Отделить 202 принятого вывода от фактического завершения контроллером и 404 отсутствующего маршрута
   от отсутствующего сервера или размещения. Gone не позволяет вывести отвечающий сервер.
7. Выполнить приёмку 04 на отдельном экземпляре без воркеров по её README: 6 сценариев / 21 шаг
   в порядке файла. Не сбрасывать u1 между 01 и 02. Повторный прогон очищает также заявки POST и память id.
8. Проверить полные HTTP-ответы по OpenAPI сверх частичных ожиданий TSV. Успех пустого объекта
   означает {}, не отсутствие тела. Для drain отдельно проверить согласование карт, счётчиков и safe;
   для where — права на door, причину и допустимое отставание directory. Схема не доказывает эти отношения.
9. Приложить свидетельства чтения по Н5 для ненаблюдаемых на пустом пуле ветвей. Стенд урока 5
   проверяет несколько случаев с воркером; он не заменяет гонки двух контроллеров и весь судья.

## Ловушки языка и библиотеки

| Предмет | Ловушка | Проверка |
|---|---|---|
| время | судить свежесть по ts чужого процесса | сдвинуть часы писателя, сохранить ритм наблюдаемых изменений |
| строки | считать отсутствие, нечитаемость и пустые метки одинаковыми | три разных исхода Н1/Н3 |
| вес | считать количество единиц вместо суммы весов | неодинаковые веса и группа, превышающая свободное место |
| порядок | нечисловое имя или равный номер не имеют определённого победителя | равная ёмкость: полное имя ASCII; distinct: слотовый порядок М10/3 Н1.4; проверить все допустимые формы |
| cas | после конфликта повторить готовое решение | перечитать и проверить мутатор и spec_rev заново |
| guard | заменить страж turn версией отдельной placement | поздний A после смены держателя получает 412 на любом изменении назначения |
| допуск | перечитать workers, но сохранить прежнюю оценку свободного места | новый расчёт под turn с резервом всего intent, вместимость/spread_by/группа |
| прогноз | min пустого пула или деление на ноль | положительный default как оценка; без него withheld с объяснением |
| метки | якорь $ пропускает конечный перевод строки | проверить a, vlan:a и a\n как разные случаи |
| счётчики | true принимается за 1 | JSON-булевы не числа |
| дренаж | would_strand принят за отрицание safe | неразмещённая единица может быть в пробе при safe: true |

Поля Where.worker и Where.directory (кроме null), а также элементы SubsystemDrain.pending_unsaid
используют имена слотов по М10/3 Н1.4.
Статическая форма одинакова с RunningUnit; совпадение prefix с загруженной спекой и наличие
соответствующего воркера проверяются по смыслу, а не одним валидатором схемы.

## Готово, когда

Выполнены М10/4-01…22, описаны выборы реализации, приёмка прошла с заявленным начальным состоянием,
полные ответы соответствуют Н2, а оставшиеся гарантии имеют свидетельства по Н5.
Указать срез, команды/стенд, наблюдения и ограничения. Проверка документов и OpenAPI не означает
прохождение реализации. Расхождение нормы и формы оформить с контрпримером по правилам проекта;
повторяемую ошибку приёмки записать в corrections.tsv.
