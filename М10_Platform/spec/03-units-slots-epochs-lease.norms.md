## Н0 Словарь слов

Нормативные слова — по [канону курса](../../НОРМАТИВНЫЕ-СЛОВА.md).
Непомеченное предложение нормативного раздела читается как ДОЛЖЕН.

## Н1 Форма

**Время.** Поля времени строк и объектов урока — время по [канону Н0](../../Platform/01-store/spec/01.1-store.norms.md#время-в-строке): `<sub>/slots/<имя>` — `until`; `platform/epoch_floor` — `generation_at`.

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `<sub>/<spec:unit.rows>/<id>`, `<sub>/next_id`, `<sub>/idem/<key>`, `<sub>/slots/<имя>`, `<sub>/epoch/<id>`;
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `<sub>/placement/<id>`, `<sub>/controller/pass`, `platform/epoch_floor`.

### Н1.1 Раскладка ключей подсистемы

`unit`, `unit.rows` и `unit.id` обязательны без умолчаний (P/02.1 Н1.2). `unit.rows` — имя по грамматике и не из перечня запрещённых имён сводной таблицы P/02.1 Н1.2а (служебные семьи
этой раскладки, первые сегменты платформенных дверей, семьи объектов, а также cluster, worker, ts из оболочки
снимка М10/10). Непредставимое имя — отказ загрузки, не недостижимая дверь.

Все ключи подсистемы начинаются с её имени (P/02.1). У каждой строки один писатель; у семьи их может быть несколько, когда урок-владелец делит её по форме строки (просьбы — строка `<sub>/requests/<rid>` урока 8 Н1.5, писатели по `worker.requests`; таблицы — `worker.writes` урока 10 Н1.6); права — роли и образцы P/02.5 Н1.4 (`console`, `<s>controller`, `<s>worker`).

```yaml
rows:                                  # строки хранилища (P/01.1)
  <sub>/<rows>/<id>:        {писатель: консоль; контроллер — только удаление по placement.unplaced.delete_after}
  <sub>/next_id:            {писатель: консоль; items: {n}}
  <sub>/idem/<key>:         {писатель: консоль; форма — решает реализация (п. 3); только консоль читает}
  <sub>/policy:             {писатель: консоль; items: {servers: shared | distinct}}        # урок 4
  <sub>/slots/<имя>:        {писатель: держатель; контроллер — отдать (урок 4 Н3 «судьба», release); форма Н1.4}
  <sub>/holds/<место>:      {писатель: держатель; форма слота без server, плюс by — урок 5 Н1.3}
  <sub>/epoch/<id>:         {писатель: воркер; items: {epoch}; никогда не удаляется}
  <sub>/placement/<id>:     {писатель: контроллер; items: {worker, reason, at, rev, spec_rev} — урок 4}
  <sub>/workers/<имя>:      {писатель: контроллер; items: {units, rev} — урок 4}
  <sub>/controller/placement_turn, <sub>/controller/placement_intent: {писатель: контроллер; строки допуска Н1.5 урока 4; не удаляются}
  <sub>/requests/*:         {писатели: консоль (дверь); воркер по worker.requests; ресурс — free_ask своей формы — урок 8}
  <sub>/asked/*:            {писатель: консоль; items: {rids, by, at} — учёт человека, урок 8 Н1.5 ledger}
  <sub>/<таблица>/*:        {писатель: консоль; таблица из worker.writes — её воркер, консоль только читает — урок 10}
  <sub>/sweep:              {писатель: консоль; items: {at, digests} — урок 10 Н1.5 sweep}
  <sub>/decommissioned/<сервер>: {писатель: контроллер — урок 4 Н1.1, Н3 «вывести_сервер»}
platform rows:
  platform/epoch_floor:     {items: {floor, generation_at}; писатель — операция «восстановить хранилище» P/01.3 Н3 (поднимает пол на поколение); право — только у неё (P/01.2 Н1.3 never)}
objects:                               # объекты, не строки; дверь объектов — урок 8 Н1.1
  # heartbeats — урок 5 Н1.1; contenders — урок 5 Н1.4; snapshot — урок 10 Н1.3; controller/pass — урок 4 Н1.2;
  # blobs — урок 10 Н1.5; метка просьбы — строка-объект objects/<sub>/commands/<rid> урока 8 Н1.5 mark (ключ
  # хранилища строк, не дверь объектов; каталог данных)
  <sub>/heartbeats/<имя>, <sub>/contenders/<имя>/<коробка>, <sub>/snapshot/*, <sub>/controller/pass,
  <sub>/blobs/<дайджест>
reserved_table_names:   <rows> и перечень запрещённых имён таблиц P/02.1 Н1.2а
```

`controller` не может быть именем unit.rows или таблицы подсистемы: этот префикс содержит
служебные строки допуска урока 4 Н1.5 (`placement_turn`, `placement_intent`). Загрузчик отказывает таким значениям (перечень P/02.1 Н1.2а).

### Н1.2 Строка единицы

```yaml
<sub>/<rows>/<id>:
  id:        <id как строка>                       # ДОЛЖЕН
  revision:  <десятичное целое ≥ 1>                # ДОЛЖЕН; 1 при создании, +1 на каждую правку, удаление не меняет
  deleted:   "true"                                # только у надгробия; иначе элемента нет
  <поле>:    <значение по типу>                    # каждое поле спеки, кроме отсутствующих (ниже)
values_by_type:
  string, url: как есть
  int:        десятичная запись
  float:      десятичная запись без экспоненты, кратчайшая, восстанавливающая число
  bool:       "true" | "false"
  list:       элементы через запятую; если есть пустой элемент, элемент содержит запятую или текст начинается с `[` — массив JSON;
              [] хранится как ""; [""] — как JSON-текст '[""]'. При чтении "" → [], ведущий '[' → JSON-массив,
              иначе разделить по запятым; непереданное при правке поле сохраняется в этой форме;
              поле меток размещения (`placement.constraint: labels-subset`) — только слова по азбуке меток урока 4 Н2.1 (1–64 ASCII: первая буква или цифра, далее буква, цифра, `_`, `.`, `:`, `-`)
  json:       канонический JSON (ADR-0072); значение null — элемента нет
  blob:       "sha256-<hex>"; байты — объект <sub>/blobs/sha256-<hex> (урок 10 Н1.5); в строку дайджест попадает
              только дверью байтов PUT /{rows}/{id}/{blob_field} (урок 10 Н2):
              правка полей принимает лишь прежний дайджест строки или "" (снять); при создании — только ""
  *_secret:   конверт enc:v2:… (урок 7 Н1.2); клиент никогда не получает значения: в ответе — маска "***" (урок 7 Н1.1)
absent:
  - поле с inherit, если не задано: элемента нет (не "" и не "null")
  - json-поле со значением null
platform_fields:   [id, revision, deleted, worker, placement, epoch, phase, observed_revision]
  # unit.fields не объявляет (отказ загрузки P/02.1), клиент не задаёт; в живой строке только id и revision,
  # deleted — только у надгробия; worker/placement — строка <sub>/placement/<id> (урок 4 Н1.1, добавлено М10/4);
  # epoch — строка эпохи; phase, observed_revision — status[].phase, status[].observed_revision
  # объекта <sub>/heartbeats/<имя> (урок 5 Н1.1, добавлено М10/5)
```

Поле bytes остаётся обычным полем единицы только в спеках без blob: сочетание с любым
blob-полем отвергается загрузчиком по P/02.1, чтобы счётчик `bytes` в ответе двери байтов `PUT /{rows}/{id}/{blob_field}` (М10/10 Н2) не затирал поле.

При создании состав клиентских полей определяется для каждого поля спеки (до записи строки):

1. Поле передано — взять именно переданное значение, включая `0`, `false`, `[]` и `null` (кроме `null` у поля с
   `inherit` — шаг 2); умолчание его не заменяет. Допустимость значения проверяется по Н3/Н4.
2. Поле не передано или передано `null` и имеет `inherit` — не создавать элемент; значение `inherit` является концом
   цепи чтения, а не значением для записи в новую строку.
3. Поле не передано и имеет `default` — взять значение `default` из загруженной спеки.
4. Иначе взять пустую форму типа из таблицы ниже. `default` и `inherit` вместе запрещены P/02.1.

| Тип | Пустое значение JSON | Элемент строки Н1.2 |
|---|---|---|
| string, url, blob | `""` | `""` |
| int, float | `0` | `"0"` |
| bool | `false` | `"false"` |
| list | `[]` | `""` |
| json | `null` | отсутствует |

Проверки типа и ограничений применяются к полученным значениям в порядке Н3; умолчание не обходит
`fixed`, `enum`, ссылки и остальные ограничения. Непереданное required-поле по-прежнему даёт отказ
Н3 шага 6: подготовка пустой формы или default не считается его передачей клиентом.
После проверки `json: null` не сохраняется. Секрет хранится конвертом (урок 7 Н1.2) и выдаётся маской `"***"` (урок 7 Н1.1), а blob при создании
пуст: default/inherit для blob запрещены P/02.1. При правке непереданные поля сохраняются из строки,
умолчания заново не применяются. Создание над надгробием применяет те же правила подготовки;
проверка fixed сравнивает подготовленное значение с надгробием.

Список имеет только строковые элементы; иной JSON-элемент — отказ типа поля (Н4).
Значение `int` на входе двери — JSON-число без дробной части и экспоненты в пределах ±(2^53 − 1): `1.0`, `1e2` и
`9007199254740992` у `int` — `not_number` (такое число читает клиент JSON любого языка). Число `-0` хранится как `0`
(JCS, ADR-0072).
Значение json-поля — любое значение JSON; его `schema` — JSON Schema 2020-12 из ключевых слов `type`, `enum`, `const`,
`properties`, `required`, `additionalProperties`, `items`, `minItems`, `maxItems`, `minLength`, `maxLength`, `minimum`,
`maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `pattern`, `if`/`then`/`else`, `allOf`, `anyOf`, `oneOf`, `not`;
схема с иным ключевым словом — отказ загрузки `refused:value` (P/02.1), поэтому все реализации проверяют одно и то же.
Пустой элемент допустим у обычного list, но не у меток размещения по азбуке урока 4 Н2.1.

### Н1.3 Идентификатор

```yaml
id:
  numeric:                                  # unit.id: numeric
    rule:    десятичное целое ≥ 1 из счётчика <sub>/next_id; первый — 1; номер не используется повторно никогда,
             в пути — десятичная запись без знака, пробелов и ведущих нулей (`01`, `+1` — 400 bad id);
             надгробия считаются; номер, выданный отказанной попытке, не возвращается
    recover: только при полном подтверждённом перечне строк/надгробий и живых заявок; утрата истории или ошибка чтения не считается пустотой и не разрешает автоматическое восстановление. Счётчик не читается → наибольший номер среди строк <rows>/ (с надгробиями) и номеров в живых заявках + 1, счётчик
             переписан целиком; номера отказанных попыток следов не оставляют и после восстановления МОГУТ выйти снова —
             единственное исключение из «никогда», журнал `next_id.recovered {from, to}`
  named:                                    # unit.id: <поле>
    rule:    значение несекретного поля type string, включая умолчание типа; источник с суффиксом _secret запрещён загрузчиком P/02.1; одна строка; ДОЛЖЕН быть непустым
    update:  поле-источник id неизменяемо даже без fixed в спеке; PUT может не передавать его или передать тот же id;
             другое значение — 400 «<поле> is fixed» без записи; переименование этой дверью не выполняется
    refused: пустое; "." и ".."; содержит `/`, `\`, `|`, `"`, `,`; управляющие знаки (Cc), разделители строк и
             абзацев (Zl, Zp); цифры вне 0–9 (Nd не ASCII); категории — по таблицам Unicode 15.0.0 (UnicodeData), как NFKC
             урока 7; знак, не назначенный в этой версии, ни к одной из них не относится (добавлено ревью стадии A 2)
  tombstone:                                # возврат имени после удаления
    rule:    создание над надгробием проходит только с теми же значениями fixed-полей; revision = надгробия + 1,
             записью с cas по версии надгробия; иначе 400 с именем поля
  unique:    true | canonical            # предварительная проверка нового значения по живым единицам;
                                         # canonical — URL в каноническом написании (ниже); конфликт — 409 unique;
                                         # атомарной уникальности между строками нет (Н3 «Гонки» правки)
  canonical_url:                         # синтаксический канон RFC 3986 §6.2.2 (ADR-0057)
    - схема и хост — нижним регистром; шестнадцатеричные цифры процент-кодирования — верхним
    - процент-кодированный незарезервированный знак (буква, цифра, - . _ ~) декодируется
    - точечные сегменты пути удаляются (RFC 3986 §5.2.4); пустой порт («host:») снимается
    - порт по умолчанию не снимается, query не сортируется, пустой путь не заменяется на «/»: «тот же поток» — смысл
      подсистемы, не платформы (ADR-0057)
ref_and_must_match:                      # поле единицы или таблицы (P/02.1 Н1.3)
  ref:        <подсистема>/<семья>       # цель значения v — строка <ref>/<v>
  must_match: {<поле цели>: <поле этой строки>}   # при живой цели значения равны; иначе 409 conflict, fault must_match;
                                                  # отсутствующий элемент цели не равен ничему, и "" тоже
  rules:
    - цели нет — не отказ: ref без must_match не требует существования цели (ADR-0057)
    - цель не читается — 409 conflict, fault garbled
    - в обе стороны (как у таблиц, урок 10 Н3 «таблица — записать строку», шаг 2): создание или правка единицы, которая
      сама — цель, проверяет живые единицы и строки таблиц каталога, чьё поле с ref на её семью и must_match называет её:
      их значения равны новым значениям цели, иначе 409 conflict, fault must_match; ссылающаяся строка не читается — fault garbled
```

Профиль восстановления numeric не совместим с физической уборкой: unit.id: numeric вместе с placement.unplaced.delete_after — отказ загрузки P/02.1. Успешные номера представлены сохранёнными строками/надгробиями; очистка done-заявок это не отменяет. Произвольная утрата этих строк не покрыта формулой recover.

Любое имя, которое разрешают грамматика id и слота и предел полного ключа P/01.1, хранит любая реализация: имена файлов
(каталоги бакетов М10/8 Н1.1) реализация кодирует сама, более узкого файлового профиля нет — иначе части разных
реализаций над одними данными несовместимы (сверка python и go М10/3–5, U20).

### Н1.4 Строка слота

```yaml
slot:                                     # раздел спеки (P/02.1 Н1.2); закрытый: два ключа
  prefix:   <1–8 строчных латинских>      # умолчание w; имя слота — <prefix>-<суффикс>
  name_env: <ИМЯ_ПЕРЕМЕННОЙ>              # ^[A-Z][A-Z0-9_]*$; переменная окружения, из которой воркер берёт предпочитаемое имя, когда его не дали аргументом (урок 5 Н3 «старт()», шаг 3); нет ключа — имя из окружения не берётся
<sub>/slots/<имя>:                        # имя: <prefix>-<суффикс>, суффикс ^[a-z0-9]+(-[a-z0-9]+)*$: числовой <n> — имена, которые
                                          # выдумывает захват без заданного имени; <сервер>-<n> — имя от юнита (P/02.4 Н1.1: экземпляр
                                          # %i = <prefix>-<сервер>-<n> аргументом, Н1.2; ADR-0043), <сервер> = SERVER_NAME (P/02.4 Н1.2);
                                          # n — десятичное целое без ведущих нулей: 1 — базовый процесс роли на сервере, 2…99 —
                                          # заказанные контроллером (урок 4 Н3 «заказать()»; ADR-0084); выбор по номеру (сокращение
                                          # урока 4, скрипт сервера урока 11) сравнивает n целым, не слотовым порядком ниже
  holder:    <экземпляр> | ""              # экземпляр: <коробка>:<pid>:<6 hex случайности>; коробка держателя — часть до первого «:»
  until:     <время (Н0 «Время в строке»)>   # часы писателя + 45; показ/расхождение, не свежесть
  released:  "true" | "false" | "taking"     # taking — первая запись захвата (Н3 «захватить» шаг 3; добавлено пилотом Quint, F2)
  gen:       <десятичное целое ≥ 0>        # исходное поколение отсутствующей строки — 0 (Н3 «захватить»); +1 на каждый захват; никогда не убывает
  server:    <сервер держателя> | ""       # пишется при каждом захвате и продлении; "" — сервер неизвестен (урок 5 Н1.1 server: "", ADR-0029)
states:
  held:      читаемый слот, holder ≠ "", released = false, gen ≥ 1, возраст наблюдаемой версии < SLOT_TERM
  lapsed:    те же поля, возраст наблюдаемой версии ≥ SLOT_TERM; само по себе не разрешает захват
  released:  released = true
  taking:    released = taking — захват в работе: для всех читателей не жив (как released), для захвата — свободный
             (как released: захватчик мог умереть между записями); контроллер уводит его единицы только после SLOT_TERM
             неизменной версии (урок 4 Н3 «уходит»); всякое «released» ниже без значения — released ≠ false
  torn:      строка не читается: until не число или не конечно, gen не десятичное целое ≥ 0;
             конечный until в прошлом/будущем относительно судьи не делает строку порванной
constants:
  SLOT_TERM: 45          # срок слота, с
  RENEW_EVERY: ~8.3      # (30 − 5) / 3 — шаг аренды (урок 5 Н1.2 LEASE_EVERY)
  TORN_STILL: 45 + 5     # сколько порванная строка с читаемым gen стоит без изменений до переписывания
```

**Порядок имён и следующий номер.** Имя проверяется по грамматике выше и prefix своей спеки.
«По имени» означает лексикографическое сравнение полного имени по байтам ASCII; собственный
префикс строки идёт раньше её продолжения. Локаль и порядок обхода хранилища не влияют на результат.
Для выбора свободного слота и хранителя места применяется **слотовый порядок**:

1. Сначала имена, у которых весь суффикс после `<prefix>-` состоит из цифр 0–9: по числовому
   значению суффикса, при равенстве — по полному имени. `w-01` и `w-1` — разные имена с равным номером.
2. Затем остальные допустимые имена — по полному имени. Последние цифры `w-srv-a-2` не выделяются
   в номер; это имя второй группы, как `w-a`.

Например: `w-0`, `w-01`, `w-1`, `w-2`, `w-10`, `w-a`, `w-b`, `w-srv-a-1`.
Номер сравнивается как неотрицательное десятичное целое без машинного переполнения; грамматика
не ограничивает длину суффикса. Для нового `<prefix>-<max + 1>` учитываются только цифровые
суффиксы этой подсистемы и prefix, включая занятые и отданные имена. Если их нет,
max = 0. Новый суффикс записывается без ведущих нулей. Остальные имена в max не участвуют.

Возраст наблюдаемой версии — время на монотонных часах конкретного судьи с момента, когда он
впервые успешно прочёл текущую версию строки. Первый взгляд, новая версия или изменённые байты
дают возраст 0; повторное чтение того же состояния и неответ хранилища его не обнуляют.
Память наблюдения своя у каждого судьи; после перезапуска первый взгляд снова свежий (ADR-0049).
Поэтому held/lapsed — состояния относительно наблюдателя, а не сравнение until с его часами.
Судьи с разной историей могут временно расходиться. Запись по чужим часам не даёт права на захват:
это право — released/свободное имя или names_given с точной версией, плюс исключения Н3.

Сам держатель для допуска своих записей помнит монотонный момент отправки последнего
подтверждённого захвата (завершающая запись released:false) или продления слота.
Свой срок кончается через SLOT_TERM от этого момента; время получения ответа и перечитка
его не продлевают. Поздний ответ, пришедший за этим пределом, не разрешает писать без нового
подтверждённого продления. Это локальный срок собственного запроса, отдельный от памяти судьи.
Для повтора одной записи с тем же id сохраняется момент её первой отправки; ответ again
не начинает новый срок. Новое продление — новая запись, не повтор прежнего подтверждения.

У отсутствующей строки исходное поколение — 0. У существующей строки отсутствие или недопустимость
`gen` не заменяются нулём: прежнюю нижнюю границу поколения восстановить из неё нельзя. Такой кандидат
не переписывается автоматически даже после `TORN_STILL` или разрешения контроллера; исход — отказ
захвата этого имени с причиной «поколение слота не читается». Строка сохраняется для восстановления.
Порча других полей при читаемом `gen` допускает захват после `TORN_STILL` с прежним `gen + 1`.
Если предпочтительного имени нет, отказ одного кандидата не мешает проверить следующие.

### Н1.6 Аренда

```yaml
lease:
  TTL: 30; MARGIN: 5                       # окно действия: 25 с от отправки последнего подтверждённого запроса (монотонные часы)
  states:
    confirmed:    выдача моей эпохи подтверждена или чтение несёт мой номер → last — наибольший момент отправки подтверждённых запросов
    fenced:       в строке другой номер, строка не читается или воркер отсечён → навсегда для этой эпохи
    silent:       хранилище не ответило, пока окно было открыто → unconfirmed считается от конца окна
    lost:         окно вышло без запроса (проспано), либо начальная выдача/запуск опоздали, либо эпоха ниже floor — не silent
  may_act:    not fenced and not lost and now − last < 25 and свой срок слота Н1.4 не истёк
              # lost и срок слота — добавлено пилотом Quint (F3): при потере записей и живых чтениях старый держатель
              # перестаёт действовать до переезда — свой срок 45 с от отправки продления, переезд не раньше 90 с
  may_write:  may_act or (silent and unconfirmed < unconfirmed_max)      # unconfirmed_max: off = 0, forever = ∞
  unconfirmed_max: из spec.lease (P/02.1): forever | off | <целое ≥ 1 с>; умолчание off
```

Момент запроса — перед первой отправкой логического вызова. Сетевые повторы внутри него,
в том числе повтор записи с тем же id/ответ again, этот момент не сдвигают. Новый запрос
подтверждения имеет свой t0; last от уже подтверждённых запросов не убывает. При первой
выдаче эпохи last устанавливается по подтверждённой записи, затем применяется Н3 «подтвердить».

Завершённый сохранённый ответ заявки с HTTP-кодом <500 ДОЛЖЕН сохраняться не менее
86400 секунд с момента его сохранения. Для очистки используется местный монотонный возраст;

## Н2 Двери

Пути единиц относятся к CONSOLE_ROOT без префикса или к явно названной подсистеме
под /{sub}, включая root. Полный URL в OpenAPI задают стандартные servers + paths
по М10/9 Н2; префикс не является частью id.

Дверь единиц — консоль подсистемы (урок 9 описывает страницу; здесь — строки). Все тела — JSON-объекты; ответ-отказ — `{detail, error, fault?}`.
Разбор запроса — урок 9 Н2 «Разбор запроса консоли» (P/01.1 Н2.1 с отступлениями консоли); своих отступлений у двери единиц нет.

[Контракт двери единиц](03-units-slots-epochs-lease.api.openapi.yaml) — OpenAPI 3.1.

Значения строки хранилища из Н1.2 и JSON-ответа различаются: в ответе числа и булевы имеют свои JSON-типы,
списки — массивы, `json` — значение JSON, строковые поля — строки; непустой секрет заменён `"***"`,
пустой остаётся пустым (урок 7). `id` выдаётся строкой, `revision` — целым числом от 1.
Отсутствующие `inherit` и `json: null` не добавляются в ответ. У поля с `inherit` значение `null` в теле создания или
правки значит «не задано»: элемента в строке нет, значение снова наследуется (`PUT {"step": null}` возвращает `step` к
наследуемому); у прочих полей, кроме json, `null` — 400 по типу. Путь сравнивается байт в байт (урок 9 Н3 шаг 5):
`/counters/` — не маршрут, 404. Сегмент id процент-декодируется после выбора маршрута (RFC 3986 §2.1): `/counters/a%20b` —
единица `a b`, `%31` у numeric — `1`; результат не UTF-8 или не по грамматике id Н1.3 — 400 `bad id`. Заголовки, которые
читает дверь (`Idempotency-Key`, `If-Match`): значение без OWS по краям (RFC 9112 §5.5); заголовок дважды — 400, как
повтор параметра; пустой `If-Match` — 400 «If-Match is a unit revision». Остальные имена полей определяет спека;
открытый набор свойств общей схемы не разрешает неизвестные поля.

| Операция | Успешное тело | Норма-владелец |
|---|---|---|
| POST | типизированная строка с `id`, `revision` и `worker: null`; при повторе — сохранённый ответ целиком | Н1.2, Н3 создать; М10/3-02, 03, 07 |
| PUT | типизированная строка после правки с `id` и новой `revision` | Н1.2, Н3 править; М10/3-02, 03 |
| DELETE | ровно `{deleted: <id как строка>}` | Н3 удалить; М10/3-10 |
| GET | ровно `{rows: [...], configured: [...]}`; `rows` — единицы пульса с `worker`, `server`, `age`, `worker_state` (правило ниже; пульсов нет — `[]`), `configured` — типизированные живые строки с масками (надгробий нет; порядок не нормирован); двери `GET /<rows>/<id>` нет | собственный контракт М10/3 Н2 (UnitList/RunningUnit); фильтрация по `view` — М10/9 Н1.3 `need` (GET/HEAD → view на единицу); форма пульса — М10/5 Н1.1 |

Ключ повторов POST — непустой сегмент без `/`, не равный `..`, не больше 200 UTF-8-байт. `maxLength` в схеме — только верхняя
граница числа символов; проверка байтов отдельная. POST и PUT требуют JSON-объект; набор `unit.fields`,
обязательность и типы проверяются по загруженной спеке в порядке Н3. Схема не заменяет проверок состояния,
ссылок, прав и размера. При отказе выдаются ровно `detail`, `error` и, только для причин Н4, `fault`.
У `409 conflict` поле `fault` обязательно; `exists`, `in flight` и `key reused` его не добавляют.


`HEAD /{rows}` — как `GET` без тела (урок 9 Н2); иной метод у `/{rows}` и `/{rows}/{id}` — `405`, путь длиннее `/{rows}/{id}` — `404` (Н4), кроме двери байтов `/{rows}/{id}/{blob_field}` урока 10 Н2: на ней иной метод, чем `PUT`, — `405`; общие коды консоли (401, 403, 408, 413, 429, 503 busy) — урок 9 Н4. Отдельной двери `GET /{rows}/{id}` нет: единицу читают в составе `GET /{rows}` (этот Н2; фильтрация по `view` — урок 9 Н1.3 `need`).

Двери слота, эпохи и аренды — хранилище P/01.1: воркер пишет и читает их сам. Нормативны проходы Н3.

**`rows` в `GET /{rows}`.** Каждый элемент `status` последнего пульса каждого воркера подсистемы, любого возраста
(урок 5 Н1.1), дополненный полями: `worker` — имя слота воркера; `server` — поле `server` пульса, а если его нет — `?`;
`age` — секунды, сколько эта консоль видит версию пульса неизменной, по её монотонным часам (первый взгляд — 0),
с одним знаком после точки; `worker_state` — `live` при `age` ≤ 45 с (LOST_AFTER урока 4), иначе `stale`. Элемент
без `id`, с `id` не по грамматике Н1.3 или с нецелыми `epoch`/`revision` пропускается; `worker` — имя слота из ключа
пульса `<sub>/heartbeats/<слот>`, а не поле пульса. Список упорядочен по id единицы (байты UTF-8), при равных — по имени слота воркера (байты UTF-8). Фильтр `view` — урок 9 Н1.3 `need`.

## Н3 Проход

### Полные ключи и отказ хранилища

Во всех операциях ниже правила ключа P/01.1 Н1 применяются после сборки полного пути Н1.1,
включая префикс, семейство и разделители; ключ стража проверяется так же. Грамматика UnitId,
WorkerName и 200-байтный предел компонента Idempotency-Key сохраняются. Схема компонента
не обещает вместимость полного ключа. Ключи не сокращаются и не хешируются при отказе.

Определённый `badkey` при чтении или записи — отказ этой операции, не отсутствие строки,
не CAS-conflict и не неответ. Применимые правила ключа можно проверить до вызова хранилища;
отказ меньшего объявленного предела файловой реализации обрабатывается тем же способом.

- Дверь единиц отвечает `400 {detail, error: "badkey"}`, без fault; detail называет семейство
  ключа и причину без содержимого секретов. У PUT/DELETE строка и revision не меняются.
  POST до получения своей pending отвечает без сохранения; после получения — завершает
  отказ шагом 9. Прежний резерв номера не возвращается. Отказ сохранения самого ответа
  на шаге 9 по-прежнему даёт 503, а не неподтверждённый 400. Правила утраты заявки/guard
  имеют прежний приоритет; чужую заявку не меняют.
- При выборе слота badkey означает отказ кандидата до первой записи: заданное имя оставляет
  процесс никем, при поиске проверяется следующий; отказ нового вычисленного имени завершает
  поиск никем. После начала захвата отказ операции прерывает попытку без выдачи живого слота;
  уже подтверждённые записи не откатываются. На продлении имя теряется; на записи под стражем
  отказывается запись, сама ошибка целевого ключа не доказывает потерю слота.
- При выдаче эпохи badkey запрещает запуск, при подтверждении — fenced без продления окна.
  Отказ ни в одной ветви не подменяется успехом, пустым чтением или бесконечным повтором.

**Владение заявкой.** Версия строки заявки — условие каждого изменения: записи/снятия самой заявки
идут с `cas` моей версии, резерв счётчика и создание единицы — со стражем этой версии вместе с `cas`
целевой строки. Проверить заявку отдельным чтением перед безусловной записью недостаточно.
После успешного изменения заявки исполнитель запоминает новую версию; перехват всегда меняет её.
После `412 guard` или конфликта `cas` заявки прежний исполнитель прекращает изменения и перечитывает
заявку, не присваивая себе её новую версию: тот же отпечаток и `done` → сохранённый ответ целиком;
тот же отпечаток и `pending` → `409 in flight`; иной отпечаток → `422 key reused`;
нет заявки или хранилище не ответило → `503 store unavailable`, клиент повторяет с тем же ключом.
Он не сохраняет этот отказ и не снимает чужую заявку. После неизвестного исхода записи он также
не продолжает со старым предположением об успехе: до выяснения сохраняется pending, клиент получает 503.

Отсутствующее после материализации поле веса (например, ненаданное inherit) не подменяет отказ
значения: для расчёта веса такой строки используется placement.weight.default. Присутствующие
0, отрицательное или нечисловое значение не заменяются этим default. Пустая форма int равна 0,
поэтому спека с полем веса без подходящего default может требовать явного положительного значения
при POST; правила материализации Н1.2 остаются общими.

**Гонки.** Две консоли с одним ключом: заявка с `cas ""` пропускает одну; вторая видит `pending` и отвечает `409 in flight`, потом — прежний ответ. Две консоли с разными ключами и одним именем: запись строки с `cas ""` пропускает одну; вторая получает `409 exists`. Консоль умерла после резерва номера: заявка через 30 с достаётся другой консоли, и та продолжает с шага 4 — проверки формы, обязательных полей и ссылок повторяются — и пишет на шаге 8 номером из заявки (numeric): строка с ним уже есть → тот же create, 201 та же строка; нет → записать её этим номером. Named: строка с этим именем есть, `revision: 1`, а ответа в заявке нет → записана этой заявкой, 201 (одноимённое чужое создание в то же окно 30 с неразличимо и принимается). Консоль умерла между резервом номера (cas счётчика) и записью номера в заявку: заявка без номера — резервировать заново с шага 3, прежний номер сгорел (две строки, две операции — неделимости между ними нет). Номер, записанный в заявку до смерти, не сгорает; сгорает номер отказанной попытки (шаги 5–7 вернули отказ).

Прежняя консоль A может ожить после перехвата консолью B. Если A зарезервировала 1, но не сохранила
его в заявке, её поздний `cas` заявки отказывается; A не доходит до записи единицы 1. B резервирует 2
и создаёт только её. Если номер 1 уже сохранён, B сохраняет его при перехвате: поздняя запись A
под старым стражем отказывается, а B продолжает с номером 1. Если A записала единицу до перехвата,
B находит эту же строку и сохраняет ответ; поздний `cas` ответа A не заменяет результат B.
Та же защита действует на отказ и снятие pending: A не удаляет заявку B. Потеря ответа о создании
не даёт права снять pending — сохранённый номер нужен продолжению. Эти исходы опираются на атомарные
`cas`/`guard` P/01.1, а не на предположение, что прежний исполнитель умер.

Превышение потолка служебной записи до шага 8 также даёт 413 row too large. Если pending ещё
не создана, сохранять ответ негде; если заявка своя — отказ завершается через шаг 9. Зарезервированный
номер не возвращается. Отказ сохранения результата на шаге 9 — 503: если единица уже записана или
исход неизвестен, pending остаётся для восстановления; чужую заявку не изменяют.

### править(id, тело) → 200 строка | отказ

`Idempotency-Key` у PUT не читается: правка сходится по `cas` прочитанной строки, а повтор PUT — новая правка,
которая снова поднимает `revision`.

**Условие `If-Match`** (М11/6: правка домена применяется агентом от ревизии, которую видел домен). Заголовок
`If-Match: <revision>` у `PUT` и `DELETE` необязателен, для любого вызывающего: значение — десятичное целое ≥ 1 без
знака и ведущих нулей, иначе 400 `{error: "If-Match is a unit revision"}` до чтения строки. Есть и не равно `revision`
прочитанной строки → 412 `{error: "revision moved", revision: <нынешняя>}`, ничего не записано; сравнение — на каждом
перечитывании прохода (после конфликта `cas` — с шага 3 снова). Нет — как прежде.

```
1. id по Н1.3; путь — ровно один id                                        → иначе 400 / 404
   тело — JSON-объект; заданное нечитаемое кольцо → 503 SealingUnavailable до правки/проверок полей (М10/7 Н3)
2. отказы формы (шаг 4 выше), кроме blob-подслучая «не прежний дайджест строки» — он после чтения; секрет пустой или null — сохранить прежний (урок 7 Н3 «создать/править», шаг 3; смена поля из bound_to при пустом секрете — 400 «must be given anew»)
3. прочитать строку; нет или deleted                                       → 404 no such unit
   (нет строки и свежий дайджест в теле — 404: строки нет, сравнивать не с чем)
3а. If-Match есть и не равен revision строки                                 → 412 revision moved {revision}
4. fixed-поле меняется или переданное поле-источник именованного id не равно id пути → 400 «<поле> is fixed»;
   blob-поле: значение не прежний дайджест строки и не ""                  → 400 (новый дайджест — только дверью байтов `PUT /{rows}/{id}/{blob_field}`, урок 10 Н2)
5. ссылки по новым значениям, must_match в обе стороны (Н1.3)               → 409 conflict с fault
6. записать {…прежние, …новые, revision: прежний + 1} с cas прочитанной версии;
   toolarge → 413 row too large, прежняя строка/revision сохранены; conflict → перечитать с шага 3;
   предел повторов при conflict исчерпан → 503 store unavailable, строка и revision прежние (журнал cammeta-go, урок 3 № 2)
```

**Гонки.** Две правки одной строки: `cas` пропускает одну, вторая перечитывает и накладывает свои поля поверх (шаг 6 → 3) — обе отвечают 200, у второй `revision` на два выше — кроме blob-поля: проверка «прежний дайджест строки» идёт на шаге 4 по **перечитанной** строке, и повтор, заставший `mask` снятым (`""`), с тем же дайджестом в теле получает 400, а не восстанавливает ссылку на тело, которое уборка могла уже снять; клиент версий не присылает, 409 — только `exists`/`conflict` ссылок. Правка против удаления: перечитав надгробие — 404.

Проверки `ref`/`must_match`/`unique` создания и правки выполняются до записи и не атомарны
с изменением других строк. Две правки разных единиц, обе проверившие прежние значения,
могут успешно записать одинаковое unique-значение. Аналогично результат проверки связи
может устареть из-за правки или удаления связанной строки. Последующий проход контроллера
размещения не проверяет эти ограничения; гарантии автоматического обнаружения, записи
диагностики или исправления такого расхождения нет. Проверка при следующем POST/PUT
выполняется по тем же правилам, а не служит фоновым аудитом. `ref` сам по себе не вводит
требование существования цели (ADR-0057): условия отказа остаются условиями соответствующего поля.

### удалить(id) → 200 | 404

```
0. If-Match не по форме                                                     → 400
1. прочитать строку; нет или deleted                                       → 404
1а. If-Match есть и не равен revision строки                                → 412 revision moved {revision}
2. записать {…строка, deleted: "true"} с cas прочитанной версии; revision не меняется; conflict → с шага 1
3. второй шаг — контроллер (урок 4 Н3 «проход()», шаг 4 «снять удалённые (reason deleted)»): снять с назначения, строка размещения {worker: "", reason: deleted, rev + 1}
```

**Гонки.** Удаление против правки: `cas` — проигравший перечитывает и повторяет (удаление — поверх правки, правка — 404 на надгробии); удаление против удаления — второе 404 (надгробие уже стоит); удаление при живом назначении — контроллер снимает единицу следующим проходом (урок 4 Н3 «проход()», шаг 4), воркер — при чтении назначения (урок 5 Н3 «цикл()», шаг 2: ведомой нет в назначении → stop_unit).

### захватить(имя?) → слот | никто

Вызов при первом старте экземпляра отличается от поиска имени после потери: исключение для своей
коробки ниже доступно только первому вызову из «старт» урока 5. Повторный поиск, воссоединение
и продолжение после отсечения не восстанавливают это право; способ хранить признак выбирает реализация.
Первый вызов, ни одно чтение кандидата которого не подтвердило строку или её отсутствие (хранилище не ответило),
право не тратит: оно переходит к следующему поиску (урок 5 Н3 «воссоединиться()»), пока такое чтение не случится
(добавлено пилотом Quint).

**Таблица переходов захвата.** Это локальные состояния попытки, а не новые поля строки.
Строки таблицы применяются сверху вниз: общий отказ имеет приоритет над разрешением ниже.
Проверки относятся к перечитанной версии; порядок кандидатов и записи выполняются псевдокодом после таблицы.
Вид воркера один: дополнительный процесс роли на сервере — тот же юнит со своим именем, захват обычный (ADR-0084).

| Состояние попытки | Состояние строки и условие | Действие | Следующее состояние / результат |
|---|---|---|---|
| Поиск | Чтение не подтвердило ни строку, ни её отсутствие | Не писать по неизвестному состоянию | Кандидат не захвачен |
| Допуск кандидата | Имя не по грамматике слота или без `slot.prefix` | Не писать слот и не объявлять живым; заданное имя — отказ старта, код 2 (урок 5 Н3 «старт()» шаг 2а) | Кандидат не захвачен |
| Поиск | Существующая строка с нечитаемым `gen` | Сохранить строку для восстановления | Отказ кандидата по Н1.4 |
| Поиск | Подтверждено отсутствие выбранного имени | Первая запись шага 3 с `cas: ""`, исходный gen = 0 | При успехе — чистка |
| Поиск | Порванная строка с читаемым gen, та же версия наблюдается меньше TORN_STILL | Не писать | Кандидат не захвачен |
| Поиск | Та же порванная строка наблюдается не меньше TORN_STILL | Первая запись шага 3 по этой версии | При успехе — чистка |

| Поиск | Читаемая занятая строка: её версия точно равна names_given для имени | Первая запись шага 3 | При успехе — чистка |

| Первая запись | CAS отказан | Не начинать чистку | Кандидат не захвачен |
| Запись/удаление | Исход операции не подтверждён | Не переходить к следующему шагу; повтор по правилам хранилища и М10/5-13 с тем же id | Текущий шаг ждёт определённого исхода; живой слот не выдан |

Таблица не разрешает переход к другому имени для именованного процесса.

```
1. прочитать строки слотов и поле names_given объекта <sub>/controller/pass (урок 4 Н1.2; привязан к версии строки слота);
   неответ не считать пустым списком или отсутствием строки → никто
2. оставить только допустимые имена своей спеки и кандидатов по таблице;
   порядок кандидатов (повторное имя пропустить):
   a. имя из окружения, если задано, — единственный кандидат (ADR-0043); к b–e не переходить
   b. имена, отданные контроллером, в порядке имён Н1.4
   c. свободные читаемые строки — в слотовом порядке Н1.4
   d. порванные с читаемым gen, простоявшие без изменений TORN_STILL, — в слотовом порядке
   e. только процесс без заданного имени: новое <prefix>-<max + 1> по Н1.4
3. для кандидата: перечитать строку и снова применить таблицу;
   основание выбранной ветви должно сохраниться: версия names_given точна, свободное осталось свободным,
   порванное не изменилось, новое имя по-прежнему отсутствует; иначе следующий кандидат;
   для заданного имени заново проверить условия таблицы, включая holder и признак первого старта;
   записать {holder: я, until: now + 45, released: "taking", gen: gen + 1, server} с cas прочитанной версии; conflict → следующий кандидат. Слот захвачен, но не жив: контроллер и
   агенты его живым не читают, контроллер не принимает его за отдачу (Н1.4 taking;
   добавлено пилотом Quint, F2), писать под ним нельзя (М10/3-13); с этой записи страж предшественника недействителен —
   его поздняя запись вклада получает 412
4. перечислить вклады предшественника под этим именем (строки, которые собирают, — М11) — уже после шага 3, поэтому
   список полон; удалить каждую записью под стражем {key: слот, index: версия записи шага 3}; затем записать
   released: "false", until: часы писателя + 45 с cas по той версии → слот жив; версия этой записи = страж на дальше (ADR-0074 C2: ни одна строка
   предшественника не видна под живым слотом нового держателя). Вкладов нет — вторая запись всё равно делается
→ слот; все кандидаты не прошли → никто
```

**Гонки.** Два процесса на одно имя: `cas` пропускает одного, второй идёт к следующему кандидату или становится никем.
B при старте забрал имя у A на той же коробке; A после отсечения повторяет поиск → стартового исключения
у A больше нет, живое имя B остаётся за B. Порча `gen` между выбором кандидата и перечиткой → отказ
кандидата без записи; изменение после перечитки отсекается `cas`. Чистка против нового-нового владельца: страж по версии слота — тот, у кого слот переписали, получает `412 guard` и не стирает чужое. Контроллер отдаёт имя (урок 4 Н3 «судьба», `names_given`) между моим чтением и записью: `names_given` привязан к версии строки, моя запись с `cas` по той же версии проходит; по новой — конфликт и перечитка.

### продлить() → ещё мой | потерян

```
каждые RENEW_EVERY:
  прочитать слот; holder/gen не мои, released или слот нечитаем             → потерян: стать никем (урок 5 Н3 «никто и возврат имени», отдать_имя())
  записать {…строка, until: now + 45, server} с cas; conflict               → перечитать и снова проверить все условия
  хранилище не ответило                                                     → всё ещё мой (решает аренда единиц)
```

**Гонки.** Продление против разрешённого захвата другим экземпляром: `cas` по прочитанной версии пропускает одного; проигравший видит чужой `holder`/`gen` — потерян. Молчание хранилища не продлевает свой срок: до подтверждения нового продления записи под слотом разрешены лишь в оставшемся местном окне Н1.4 и по условиям аренды единицы. Неподтверждённый запрос не меняет начало этого окна.

### отдать() — только при упорядоченной остановке

```
записать {…строка, released: "true", until: now} с cas; conflict — не повторять
```

**Гонки.** Отдача против захвата: `cas`; захват другим раньше отдачи — отдавать нечего (чужой `holder`), ничего не пишется. Отдача против подмены (урок 5 Н3 «подмена()»): подмена перечитывает слот перед продлением и видит `released`.

### писать_под_слотом(key, items) → index | отказ

```
перечитать слот; holder мой, gen мой, не отдан, читаем, свой подтверждённый срок Н1.4 ещё не истёк,
разрешено писать (writing_allowed, урок 5 Н3 «старт()», шаг 5) → иначе не писать
записать(key, items, guard: {key: слот, index: версия перечитанного слота})
412 guard → запись не сделана; перечитать слот и заново проверить владение и условия
  тот же holder и gen, слот жив, запись разрешена → имя сохраняется; допустима новая попытка с новой проверкой
  чужой holder/gen, отданный или нечитаемый слот → потерян: стать никем
  хранилище не ответило или истёк свой подтверждённый срок → не писать; успех и потерю по одному 412 не объявлять
```

**Гонки.** Запись под стражем против смены слота: 412 `guard`, запись не делается, перечитка
показывает нового держателя — прежний становится никем. Собственное продление v1 → v2 сохраняет
holder и gen: запись с v1 получает 412, но перечитка подтверждает владение; новая попытка проверяет
все условия и использует v2. Слепого повтора со старым стражем нет. Две записи одной строки под
одним стражем — решает `cas` строки, страж пропускает обе.

### взять_эпоху(id) → epoch | отказ

```
условия: я кто-то (слот мой); единица в назначении, которое ответило последним; с тех пор не потеряна
прочитать <sub>/epoch/<id>: нет → 0; не число → отказ EpochUnreadable (не 0)
прочитать platform/epoch_floor: floor (нет → 0; не читается → отказ выдачи, пол не подменяется 0)
t0 = now (монотонные, непосредственно перед отправкой записи)
записать {epoch: max(текущая, floor) + 1} с cas прочитанной версии;
  conflict → перечитать строку эпохи и пол и повторить с новым t0 для новой записи (пол — добавлено пилотом Quint, F1)
  исход не подтверждён → повтор тем же id по М10/5-13, t0 — первая отправка (Н1.6); не подтверждён и тогда — отказ,
                         новую аренду не выдавать
  подтверждено → last = t0; now − last ≥ 25 → lost, отказ запуска, не silent
перед start_unit — успешное «подтвердить» (ниже) с t0 после подтверждённой записи выдачи: эпоха ниже floor → lost,
  не запускать; иная или не читается → fenced; хранилище не ответило — не запускать, первый запуск silent не
  разрешает (добавлено пилотом Quint, F1)
→ epoch; аренда = новая с last = t0, только в оставшемся окне
```

**Гонки.** Два воркера на одну единицу (переназначение): оба поднимают эпоху, `cas` пропускает одного первым; второй перечитывает и берёт следующую — у каждого своя, старший отсекается на подтверждении. Пол поднялся между чтением и записью: `cas` по строке эпохи этого не видит, и чтение пола до записи от этого не защищает — строки не было (`cas ""`) или копия сохранила её версию, и запись со старым полом проходит; перечитка одной строки эпохи при conflict берёт старый пол. Защищает проверка после записи: пол перечитывается при conflict, а перед start_unit успешное «подтвердить» видит пол после записи — эпоха ниже пола `lost`, единица не запускается (добавлено пилотом Quint, F1). Восстановление, поднявшее пол (P/01.3 Н3 «восстановить хранилище»), процессы не перезапускает: пол читается на каждом шаге аренды (урок 5 Н3 «шаг_аренды()», шаг 2), и единица с эпохой ниже пола теряет аренду (`lost`) — её писатель останавливается сам.

Задержанный ответ выдачи не начинает новое окно: отправка в 0, успешный ответ в 30 — эпоха могла
быть записана, но старт уже запрещён. Номер не откатывается и не удаляется; поздний ответ не даёт
silent или права по unconfirmed_max, даже forever. Следующая попытка требует нового успешного
чтения назначения и вновь проходит ворота урока 5 Н3 «взять_эпоху(единица)». Перед самым start_unit ворота и may_act
проверяются ещё раз: пауза между возвратом выдачи и запуском не продлевает окно.

### подтвердить(id) — шаг аренды

```
t0 = now (монотонные); прочитать <sub>/epoch/<id> и platform/epoch_floor
  пол не читается             → fenced, как отказ подтверждения: пол не подменяется 0
  моя эпоха ниже floor       → lost (Н1.6; Гонки выдачи)
  несёт мою эпоху            → окно вышло без запроса (t0 − last ≥ 25 и не silent — проспал) → lost, не оживлять: урок 5 Н3
                               «шаг_аренды()», шаг 4 останавливает единицу (stop_unit); иначе last = max(last, t0), в том числе после silent:
                               успешное чтение своей эпохи возвращает аренду в confirmed
  иную или не читается       → fenced: остановить единицу, запомнить потерю эпохи (урок 5 Н3 «шаг_аренды()», шаг 4; строка эпохи не меняется)
  хранилище не ответило      → аренда не была silent и окно ещё открыто (t0 − last < 25) → silent с момента конца окна;
                               уже silent → остаётся silent (unconfirmed растёт до потолка); окно пропущено без запроса → lost
may_act / may_write — по Н1.6
```

**Гонки.** Подтверждение и смена эпохи другим воркером: чтение видит либо мою, либо новую —
в первом случае окно продлено на 25 с от t0, во втором — отсечён сразу. Срок переезда определяет
судьба слота, а не одно это чтение (М10/3-18). При silent действия прекращаются к концу окна;
данные — по unconfirmed_max: при off тоже к концу окна, при конечном потолке — по его достижении,
при forever конечный срок остановки данных из молчания не следует. Данные разных попыток различимы эпохами.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **разбивку семей** на строки и объекты сверх Н1.1, если она иная, и где лежат объекты;
2. **предел тела двери** (`413`); форма `*_secret` в строке — норма урока 7 Н1.2 (конверт), не выбор;
3. **форму строки заявки** `<sub>/idem/<key>`, срок хранения done-заявок (не меньше 86400 с — норма) и способ их очистки;
4. **точный текст** `detail`/`error` сверх слов Н4;
5. ~~**запись момента `until`**~~ — нормирована: время по Н0 «Время в строке» (писатель — дробная часть до 3 знаков, читатель — любая запись формы); сдвиг относительно часов читателя не является порчей (решение «Архитектора» 2026-10-18);

## Чеклист готовности

Реализация соответствует уроку, когда выполнена каждая норма; id нормы `М10/3-NN` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **М10/3-01** раскладка ключей Н1.1: семьи, зарезервированные имена таблиц; у строки один писатель, семья делится по форме строки только по правилу урока-владельца (просьбы — урок 8 Н1.5, таблицы — урок 10 Н1.6) — проверяется чтением (права — P/02.5 Н1.4); представимость обязательного файлового пути до публикации/захвата — чтением Н1.3 и README приёмки
- [ ] **М10/3-02** строка единицы: `id`, `revision`, значения по типам, обратимый list ([] и [""] различимы), заполнение default/пустой формы при создании по Н1.2, отсутствие ненаданных `inherit` и `json: null`; `null` у поля без `inherit` — 400 (сц. 03); `blob` в правке — только прежний дайджест или `""`, иначе 400 (сц. 04 урока 10) — сц. 01, 03, 09, 10
- [ ] **М10/3-03** `revision`: 1 при создании, +1 на каждую правку, удаление не меняет, возврат имени — надгробие + 1 — сц. 03, 07; условие `If-Match` у PUT и DELETE — сц. 14
- [ ] **М10/3-04** платформенные поля не принимаются и живут порознь — сц. 04; раздельное хранение — проверяется чтением
- [ ] **М10/3-05** числовой id: счётчик с `cas`, первый 1, не используется повторно (надгробия считаются), восстановление только по полному подтверждённому перечню строк/надгробий и живых заявок; numeric+delete_after запрещён P/02.1 (номера отказанных попыток после восстановления могут повториться — исключение названо), журнал восстановления — проверяется чтением (нужна спека с `unit.id: numeric`, README приёмки 03)
- [ ] **М10/3-06** именованный id: грамматика Н1.3, поле-источник неизменяемо, `409 exists` над живым, возврат над надгробием только с теми же `fixed` — сц. 02, 06, 07; неизменяемость поля-источника id — сц. 03 (PUT другого `name` — 400 «is fixed»); `fixed` — чтением (`testsub2`, поле `of: fixed`)
- [ ] **М10/3-07** идемпотентное создание: ключ обязателен и не равен '..', не длиннее 200 байт и без `/` — сц. 13; повтор — тот же ответ, иной отпечаток — 422, `in flight`, захват заявки через 30 с только тем же отпечатком (иной — 422), guard/cas всех изменений отсекают прежнего исполнителя; 5xx не запоминается как done, при записанной строке или неизвестном исходе pending сохраняется; toolarge строки/будущей done даёт 413 до создания, отказ завершается шагом 9 — сц. 01; пределы по README, захват, поздний исполнитель и две консоли — проверяется чтением; хранение ответа <500 ≥86400 с — чтением политики очистки: короткая HTTP-приёмка не измеряет сутки
- [ ] **М10/3-08** порядок отказов Н3 шаг 4 и строгие типы; вес placement.weight.field < 1 даёт 400 без записи; toolarge при PUT — 413 без изменения строки/revision — сц. 04, 05, 08; предел — отдельная проверка README
- [ ] **М10/3-09** `unique`/`ref`/`must_match` — предварительная проверка, `409 conflict` с `fault`; неатомарность между строками и отсутствие гарантии фонового обнаружения по Н3 — проверяется чтением (нужно поле с `unique`; `testsub2`); представимость обязательного файлового пути до публикации/захвата — чтением Н1.3 и README приёмки
- [ ] **М10/3-10** удаление в два шага: пометка без стирания, 404 после, второй шаг контроллера — сц. 07; второй шаг — урок 4 Н3 «проход()», шаг 4
- [ ] **М10/3-11** строка слота, два порядка имён и следующий номер Н1.4; held/lapsed по возрасту наблюдаемой версии, сдвиг конечного until не порча; `server` при каждой записи; `gen` не убывает, нечитаемый gen не сбрасывается и запрещает захват — проверяется чтением строк в приёмке урока 5 (сц. 01: `gen: 1`, `server`; сц. 04: `gen: 2`)
- [ ] **М10/3-12** захват по таблице Н3 (вид воркера один, ADR-0084); порядок кандидатов определён для всех имён Н1.4, истёкшее не отданное не берётся, отъём на своей коробке только при первом старте (после отсечения — никто), чужая коробка без разрешения контроллера — отказ, `cas` по прочитанной версии; номер n имени от юнита — целое 1…99 без ведущих нулей — проверяется чтением (сц. 04 приёмки урока 5)
- [ ] **М10/3-13** чистка входов предшественника под стражем слота: отдан → удалить под стражем → держим — проверяется чтением (приёмка М11 книг)

- [ ] **М10/3-15** запись под стражем слота только при читаемом своём слоте и неистёкшем собственном сроке Н1.4; `412 guard` требует перечитки владения: своё продление сохраняет имя, смена holder/gen или отданный/нечитаемый слот — никто — проверяется чтением
- [ ] **М10/3-16** эпоха: `max(текущая, пол) + 1` с `cas`, раз на взятие единицы воркером (перезапуск по revision у того же держателя — та же эпоха), нечитаемая — ошибка не ноль, строка не удаляется, номер в имени данных; первое окно от отправки подтверждённой записи, поздний ответ не разрешает запуск — проверяется чтением (README приёмок 03/05; сц. 02, 06 приёмки урока 5; урок 8 Н1.2 `e<epoch>` в пути бакета; учение 06 `@manual` `recover` приёмки урока 11)
- [ ] **М10/3-17** аренда: окно 25 с от момента запроса, подтверждение чтением эпохи и пола (эпоха ниже пола — `lost`; перед start_unit — подтверждение после записи выдачи, добавлено пилотом Quint), `fenced`/`silent`/`lost` по Н1.6, `may_act` — и не lost, и в своём сроке слота, действия только в окне, данные — по `unconfirmed_max` — проверяется чтением (урок 5 Н3 «шаг_аренды()», сц. 06 приёмки урока 5; пол — учение 06 `@manual` `recover` приёмки урока 11)

При неизвестности о процессе переезд не раньше 90 с наблюдения неизменной версии слота этим судьёй; при подтверждённом gone — после 45 с такого наблюдения, по уроку 4 Н3 «судьба».
