## Н1 Форма

### Н1.1 Раскладка ключей подсистемы

Все ключи подсистемы начинаются с её имени (урок 2). У каждой строки один писатель; у семьи их может быть несколько, когда урок-владелец делит её по форме строки (просьбы — урок 8, таблицы — урок 10); права — урок 6.

```yaml
rows:                                  # строки хранилища (урок 1)
  <sub>/<rows>/<id>:        {писатель: консоль; контроллер — только удаление по placement.unplaced.delete_after}
  <sub>/next_id:            {писатель: консоль; items: {n}}
  <sub>/idem/<key>:         {писатель: консоль; форма — решает реализация (п. 3); только консоль читает}
  <sub>/policy:             {писатель: консоль; items: {servers: shared | distinct}}        # урок 4
  <sub>/slots/<имя>:        {писатель: держатель; контроллер — отдать и предложить (урок 4); форма Н1.4}
  <sub>/holds/<место>:      {писатель: держатель; форма слота плюс by — урок 4}
  <sub>/epoch/<id>:         {писатель: воркер; items: {epoch}; никогда не удаляется}
  <sub>/placement/<id>:     {писатель: контроллер; items: {worker, reason, at, rev, spec_rev} — урок 4}
  <sub>/workers/<имя>:      {писатель: контроллер; items: {units, rev} — урок 4}
  <sub>/requests/*:         {писатели: консоль (дверь); воркер по worker.requests; ресурс — free_ask своей формы — урок 8}
  <sub>/asked/*:            {писатель: консоль — урок 8}
  <sub>/<таблица>/*:        {писатель: консоль; таблица из worker.writes — её воркер, консоль только читает — урок 10}
  <sub>/sweep, <sub>/decommissioned/<сервер>:  {уроки 10, 4}
platform rows:
  platform/epoch_floor:     {items: {floor, generation_at}; писатель — восстановление (урок 11)}
objects:                               # объекты, не строки (урок 5, 8, 10)
  <sub>/heartbeats/<имя>, <sub>/contenders/<имя>/<коробка>, <sub>/snapshot/*, <sub>/controller/pass,
  <sub>/blobs/<дайджест>, <sub>/commands/<id>
reserved_table_names:   [<rows>, policy, slots, holds, epoch, idem, requests, asked, servers, decommissioned]
```

### Н1.2 Строка единицы

```yaml
<sub>/<rows>/<id>:
  id:        <id как строка>                       # ДОЛЖЕН
  revision:  <десятичное целое ≥ 1>                # ДОЛЖЕН; 1 при создании, +1 на каждую правку, удаление не меняет
  deleted:   "true"                                # только у надгробия; иначе элемента нет
  <поле>:    <значение по типу>                    # каждое поле спеки, кроме отсутствующих (ниже)
values_by_type:
  string, url: как есть
  int:        десятичная запись
  float:      десятичная запись без экспоненты, кратчайшая, восстанавливающая число
  bool:       "true" | "false"
  list:       элементы через запятую; если элемент содержит запятую или текст начинается с `[` — массив JSON;
              поле меток размещения (`placement.constraint: labels-subset`) — только слова по азбуке меток (урок 4)
  json:       канонический JSON (ADR-0072); значение null — элемента нет
  blob:       "sha256-<hex>"; байты — в <sub>/blobs/ (урок 10); в строку дайджест попадает только дверью байтов:
              правка полей принимает лишь прежний дайджест строки или "" (снять); при создании — только ""
  *_secret:   запечатано (урок 7); клиент никогда не получает значения
absent:
  - поле с inherit, если не задано: элемента нет (не "" и не "null")
  - json-поле со значением null
platform_fields:   [id, revision, worker, placement, epoch, phase, observed_revision]
  # клиент не задаёт; в строке единицы только id и revision; worker/placement — строка размещения (урок 4);
  # epoch — строка эпохи; phase, observed_revision — пульс воркера (урок 5)
```

### Н1.3 Идентификатор

```yaml
id:
  numeric:                                  # unit.id: numeric
    rule:    десятичное целое ≥ 1 из счётчика <sub>/next_id; первый — 1; номер не используется повторно никогда,
             надгробия считаются; номер, выданный отказанной попытке, не возвращается
    recover: счётчик не читается → наибольший номер среди строк <rows>/ (с надгробиями) и номеров в живых заявках + 1, счётчик
             переписан целиком; номера отказанных попыток следов не оставляют и после восстановления МОГУТ выйти снова —
             единственное исключение из «никогда», журнал `next_id.recovered {from, to}`
  named:                                    # unit.id: <поле>
    rule:    значение поля; одна строка; ДОЛЖЕН быть непустым
    refused: пустое; "." и ".."; содержит `/`, `\`, `|`, `"`, `,`; управляющие знаки (Cc), разделители строк и
             абзацев (Zl, Zp); цифры вне 0–9 (Nd не ASCII)
  tombstone:                                # возврат имени после удаления
    rule:    создание над надгробием проходит только с теми же значениями fixed-полей; revision = надгробия + 1,
             записью с cas по версии надгробия; иначе 400 с именем поля
  unique:    true | canonical            # поле, чьё значение не повторяется у живых единиц; canonical — URL в
                                         # каноническом написании; проверяется, когда значение ново — 409 unique
```

### Н1.4 Строка слота

```yaml
slot:                                     # раздел спеки (урок 2 Н1.2); закрытый: два ключа
  prefix:   <1–8 строчных латинских>      # умолчание w; имя слота — <prefix>-<суффикс>
  name_env: <ИМЯ_ПЕРЕМЕННОЙ>              # ^[A-Z][A-Z0-9_]*$; переменная окружения, из которой воркер берёт предпочитаемое имя (урок 5)
<sub>/slots/<имя>:                        # имя: <prefix>-<суффикс>, суффикс ^[a-z0-9]+(-[a-z0-9]+)*$: числовой <n> — имена, которые
                                          # выдумывает захват и предлагает контроллер; <сервер>-<n> — имя от юнита (урок 11, ADR-0043)
  holder:    <экземпляр> | ""              # экземпляр: <коробка>:<pid>:<6 hex случайности>
  until:     <секунды стенных часов, десятичная запись>   # момент захвата/продления + 45
  released:  "true" | "false"
  gen:       <десятичное целое ≥ 0>        # 0 — предложение контроллера, ещё не взятое (урок 4); +1 на каждый захват; никогда не убывает
  server:    <сервер держателя>            # пишется при каждом захвате и продлении (ADR-0045)
  offer, offered_at, taken_at:             # предложение имени — урок 4; держатель сохраняет их при продлении
states:
  held:      holder ≠ "" и released = false и gen ≥ 1 и until ≥ now (по часам читающего)
  lapsed:    holder ≠ "" и released = false и until < now
  released:  released = true
  torn:      строка не читается: until не число или не конечно, gen не число, или until дальше чем now + 45 + допуск
constants:
  SLOT_TERM: 45          # срок слота, с
  RENEW_EVERY: ~8.3      # (30 − 5) / 3 — шаг аренды (урок 5)
  TORN_STILL: 45 + 5     # сколько порванная строка стоит без изменений, прежде чем её можно переписать
```

### Н1.5 Строка эпохи

```yaml
<sub>/epoch/<id>:
  epoch:   <десятичное целое ≥ 1>          # ДОЛЖЕН; растёт на 1 при каждом взятии единицы воркером (новый держатель или возврат после
                                          # потери); перезапуск той же единицы тем же держателем по смене revision эпоху не меняет; строка не удаляется
platform/epoch_floor:
  floor:          <десятичное целое ≥ 0>   # нижняя граница выдачи после восстановления (урок 11)
  generation_at:  <момент>
```

### Н1.6 Аренда

```yaml
lease:
  TTL: 30; MARGIN: 5                       # окно действия: 25 с от момента последнего подтверждения (монотонные часы)
  states:
    confirmed:    строка эпохи прочитана и несёт мой номер → last = момент запроса
    fenced:       в строке другой номер, или строка не читается → навсегда для этой эпохи
    silent:       хранилище не ответило, пока окно было открыто → unconfirmed считается от конца окна
    lost:         окно вышло без запроса (проспано) — не silent
  may_act:    not fenced and now − last < 25
  may_write:  may_act or (silent and unconfirmed < unconfirmed_max)      # unconfirmed_max: off = 0, forever = ∞
  unconfirmed_max: из spec.lease (урок 2): forever | off | <целое ≥ 1 с>; умолчание off
```

## Н2 Двери

Дверь единиц — консоль подсистемы (урок 9 описывает страницу; здесь — строки). Все тела — JSON-объекты; ответ-отказ — `{detail, error, fault?}`.

[Контракт двери единиц](03-units-slots-epochs-lease.api.openapi.yaml) — OpenAPI 3.1.


Иной метод у `/{rows}` и `/{rows}/{id}` — `405`, путь длиннее `/{rows}/{id}` — `404` (Н4); общие коды консоли (401, 403, 408, 413, 429, 503 busy) — урок 9 Н4. Отдельной двери `GET /{rows}/{id}` нет: единицу читают в составе `GET /{rows}` (урок 9).

Двери слота, эпохи и аренды — хранилище урока 1: воркер пишет и читает их сам. Нормативны проходы Н3.

## Н3 Проход

### создать(тело, ключ) → 201 строка | отказ

```
1. ключ идемпотентности: есть, один сегмент, ≤ 200 байт                    → иначе 400
   тело — JSON-объект                                                      → иначе 400 (fault по Н4)
2. заявка <sub>/idem/<ключ>: записать cas "" (в заявке — отпечаток запроса, время, pending)
   есть, done, тот же отпечаток (кто + метод + путь + тело)                → прежний ответ как есть
   есть, done, иной отпечаток                                              → 422 key reused
   есть, pending, стоит < 30 с по часам этой консоли                       → 409 in flight
   есть, pending, стоит ≥ 30 с, тот же отпечаток                           → забрать записью с cas; дальше как своя
   есть, pending, стоит ≥ 30 с, иной отпечаток                              → 422 key reused (заявку не трогать)
3. numeric: зарезервировать id — next_id записью с cas (повтор при conflict), номер записать в заявку
4. отказы формы по порядку: платформенные поля → незнакомые → blob (не дайджест; при создании не ""; при правке не прежний дайджест строки и не "" — новый дайджест только дверью байтов, урок 10) → json (not_json, too_long 4000 байт
   канонического текста, схема) → enum → типы значений (Н4 not_number) → url → группа (урок 4) → метки
5. named: id есть, по Н1.3; строка есть и не надгробие → 409 exists — кроме продолжения заявки (Гонки): строка с revision 1
   записана этой заявкой (ответа в заявке нет) → шаг 9 с этой строкой; надгробие с иными fixed → 400
6. обязательные: каждое required-поле задано и не ""                        → иначе 400 «needs a <поле>»
7. ссылки: ref / must_match / unique по живым строкам                       → 409 conflict с fault
8. записать строку {id, revision: 1 | надгробие + 1, поля} с cas "" | cas надгробия
   conflict: numeric с зарезервированным id и строка уже есть → это тот же create → 201 та же строка;
             named → 409 exists
9. запомнить ответ в заявке (всё < 500; 5xx — заявку снять); ответ 201 {строка, worker: null}
```

**Гонки.** Две консоли с одним ключом: заявка с `cas ""` пропускает одну; вторая видит `pending` и отвечает `409 in flight`, потом — прежний ответ. Две консоли с разными ключами и одним именем: запись строки с `cas ""` пропускает одну; вторая получает `409 exists`. Консоль умерла после резерва номера: заявка через 30 с достаётся другой консоли, и та продолжает с шага 4 — проверки формы, обязательных полей и ссылок повторяются — и пишет на шаге 8 номером из заявки (numeric): строка с ним уже есть → тот же create, 201 та же строка; нет → записать её этим номером. Named: строка с этим именем есть, `revision: 1`, а ответа в заявке нет → записана этой заявкой, 201 (одноимённое чужое создание в то же окно 30 с неразличимо и принимается). Консоль умерла между резервом номера (cas счётчика) и записью номера в заявку: заявка без номера — резервировать заново с шага 3, прежний номер сгорел (две строки, две операции — неделимости между ними нет). Номер, записанный в заявку до смерти, не сгорает; сгорает номер отказанной попытки (шаги 5–7 вернули отказ).

### править(id, тело) → 200 строка | отказ

```
1. id по Н1.3; путь — ровно один id                                        → иначе 400 / 404
2. отказы формы (шаг 4 выше), кроме blob-подслучая «не прежний дайджест строки» — он после чтения; секрет пустой или null — сохранить прежний (урок 7)
3. прочитать строку; нет или deleted                                       → 404 no such unit
   (нет строки и свежий дайджест в теле — 404: строки нет, сравнивать не с чем)
4. fixed-поле меняется                                                     → 400 «<поле> is fixed»;
   blob-поле: значение не прежний дайджест строки и не ""                  → 400 (новый дайджест — только дверью байтов, урок 10)
5. ссылки по новым значениям                                               → 409 conflict с fault
6. записать {…прежние, …новые, revision: прежний + 1} с cas прочитанной версии; conflict → перечитать с шага 3
```

**Гонки.** Две правки одной строки: `cas` пропускает одну, вторая перечитывает и накладывает свои поля поверх (шаг 6 → 3) — обе отвечают 200, у второй `revision` на два выше — кроме blob-поля: проверка «прежний дайджест строки» идёт на шаге 4 по **перечитанной** строке, и повтор, заставший `mask` снятым (`""`), с тем же дайджестом в теле получает 400, а не восстанавливает ссылку на тело, которое уборка могла уже снять; клиент версий не присылает, 409 — только `exists`/`conflict` ссылок. Правка против удаления: перечитав надгробие — 404. Проверка `ref`/`must_match`/`unique` идёт по живым строкам до записи и с ней не атомарна: две правки, каждая прошедшая проверку, могут нарушить `unique` — норма этого не обещает; расхождение видит проход контроллера (урок 4) и журнал.

### удалить(id) → 200 | 404

```
1. прочитать строку; нет или deleted                                       → 404
2. записать {…строка, deleted: "true"} с cas прочитанной версии; revision не меняется; conflict → с шага 1
3. второй шаг — контроллер (урок 4): снять с назначения, строка размещения {worker: "", reason: deleted, rev + 1}
```

**Гонки.** Удаление против правки: `cas` — проигравший перечитывает и повторяет (удаление — поверх правки, правка — 404 на надгробии); удаление против удаления — второе 404 (надгробие уже стоит); удаление при живом назначении — контроллер снимает единицу следующим проходом (урок 4), воркер — при чтении назначения (урок 5).

### захватить(имя?) → слот | никто

```
1. прочитать строки слотов и names_given контроллера (урок 4; привязан к версии строки слота)
2. кандидаты по порядку:
   a. имя из окружения, если задано, — единственный кандидат (ADR-0043): берётся, если свободно, отдано контроллером
      или держит прежний экземпляр с ЭТОЙ коробки; держит живой с другой коробки → отказ NameOnAnotherBox (соперник —
      урок 5); conflict или занято → никто, к b–e не переходит (урок 5 искать_имя)
   b. имена, отданные контроллером, по until
   c. свободные (released или holder "") по номеру
   d. порванные, простоявшие без изменений TORN_STILL
   e. <prefix>-<max + 1> среди числовых имён (имя от юнита не выдумывается — урок 11)
   истёкшее, но не отданное имя — не кандидат
3. для кандидата: перечитать строку; основание кандидата должно держаться на перечитанной версии — отданное: версия равна
   версии names_given; свободное: по-прежнему released или holder ""; порванное: без изменений; иначе (кто-то успел — продлил,
   захватил, сделал живым) → следующий кандидат; записать {holder: я, until: now + 45, released: "true", gen: gen + 1, server,
   offer-поля как были} с cas прочитанной версии; conflict → следующий кандидат. Слот захвачен, но не жив: контроллер и
   агенты его живым не читают, писать под ним нельзя (М10/3-13); с этой записи страж предшественника недействителен —
   его поздняя запись вклада получает 412
4. перечислить вклады предшественника под этим именем (строки, которые собирают, — М11) — уже после шага 3, поэтому
   список полон; удалить каждую записью под стражем {key: слот, index: версия записи шага 3}; затем записать
   released: "false" с cas по той версии → слот жив; версия этой записи = страж на дальше (ADR-0074 C2: ни одна строка
   предшественника не видна под живым слотом нового держателя). Вкладов нет — вторая запись всё равно делается
→ слот; все кандидаты не прошли → никто
```

**Гонки.** Два процесса на одно имя: `cas` пропускает одного, второй идёт к следующему кандидату или становится никем. Чистка против нового-нового владельца: страж по версии слота — тот, у кого слот переписали, получает `412 guard` и не стирает чужое. Контроллер отдаёт имя (урок 4) между моим чтением и записью: `names_given` привязан к версии строки, моя запись с `cas` по той же версии проходит; по новой — конфликт и перечитка.

### продлить() → ещё мой | потерян

```
каждые RENEW_EVERY:
  прочитать слот; holder ≠ я или released                                  → потерян: стать никем (урок 5)
  записать {…строка, until: now + 45, server} с cas; conflict               → перечитать: holder ≠ я → потерян
  хранилище не ответило                                                     → всё ещё мой (решает аренда единиц)
```

**Гонки.** Продление против захвата другим экземпляром (слот истёк): `cas` по прочитанной версии пропускает одного; проигравший видит чужой `holder`/`gen` — потерян. Молчание хранилища — ещё мой до `until`.

### отдать() — только при упорядоченной остановке

```
записать {…строка, released: "true", until: now} с cas; conflict — не повторять
```

**Гонки.** Отдача против захвата: `cas`; захват другим раньше отдачи — отдавать нечего (чужой `holder`), ничего не пишется. Отдача против подмены (урок 5): подмена перечитывает слот перед продлением и видит `released`.

### писать_под_слотом(key, items) → index | отказ

```
условия: слот мой, не отдан, until > now, разрешено писать (урок 5)         → иначе не писать
записать(key, items, guard: {key: слот, index: версия слота, какой я её держу})
412 guard                                                                   → имя переписали: стать никем
```

**Гонки.** Запись под стражем против смены слота: страж по версии слота — 412 `guard`, запись не делается; две записи одной строки под одним стражем — решает `cas` строки, страж пропускает обе.

### взять_эпоху(id) → epoch | отказ

```
условия: я кто-то (слот мой); единица в назначении, которое ответило последним; с тех пор не потеряна
прочитать <sub>/epoch/<id>: нет → 0; не число → отказ EpochUnreadable (не 0)
прочитать platform/epoch_floor: floor (нет → 0)
записать {epoch: max(текущая, floor) + 1} с cas прочитанной версии; conflict → перечитать и повторить
→ epoch; аренда = новая с last = now
```

**Гонки.** Два воркера на одну единицу (переназначение): оба поднимают эпоху, `cas` пропускает одного первым; второй перечитывает и берёт следующую — у каждого своя, старший отсекается на подтверждении. Пол поднялся между чтением и записью: `cas` по строке эпохи этого не видит — поэтому пол читают до и применяют `max`; восстановление, поднявшее пол (урок 11), процессы не перезапускает: пол читается на каждом шаге аренды (урок 5), и единица с эпохой ниже пола теряет аренду (`lost`) — её писатель останавливается сам.

### подтвердить(id) — шаг аренды

```
t0 = now (монотонные); прочитать <sub>/epoch/<id>
  несёт мою эпоху            → окно вышло без запроса (t0 − last ≥ 25 и не silent — проспал) → lost, не оживлять: урок 5
                               останавливает единицу; иначе last = max(last, t0)
  иную или не читается       → fenced: остановить единицу, запомнить потерю эпохи (урок 5; строка эпохи не меняется)
  хранилище не ответило      → аренда не была silent и окно ещё открыто (t0 − last < 25) → silent с момента конца окна;
                               уже silent → остаётся silent (unconfirmed растёт до потолка); окно пропущено без запроса → lost
may_act / may_write — по Н1.6
```

**Гонки.** Подтверждение и смена эпохи другим воркером: чтение видит либо мою, либо новую — в первом случае окно продлено на 25 с от t0, и за это время новый воркер ещё не пишет (зазор 20–65 с по ветке судьбы — М10/3-18); во втором — отсечён сразу. Молчание хранилища дольше `unconfirmed_max`: данные останавливаются, действия остановились ещё на 25-й секунде.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **разбивку семей** на строки и объекты сверх Н1.1, если она иная, и где лежат объекты;
2. **форму `*_secret` в строке** (урок 7) и предел тела двери (`413`);
3. **форму строки заявки** `<sub>/idem/<key>` и срок её хранения (не меньше суток для ответов < 500);
4. **точный текст** `detail`/`error` сверх слов Н4;
5. **момент времени `until`** (стенные секунды с дробной частью или без) и допуск вперёд, после которого строка слота считается порванной;
6. **периоды**: шаг продления, если не (30 − 5)/3; предел повторов при `conflict` на захвате, `next_id`, эпохе;
7. **как воркер узнаёт `names_given` и свою коробку** (`BOX_ID`, machine-id, hostname — урок 11).

## Чеклист готовности

Реализация соответствует уроку, когда выполнена каждая норма; id нормы `М10/3-NN` — то, на что ссылаются дельты решений, находки и записи окон (ADR-0080 доп. 6):

- [ ] **М10/3-01** раскладка ключей Н1.1: семьи, зарезервированные имена таблиц; у строки один писатель, семья делится по форме строки только по правилу урока-владельца (просьбы — урок 8, таблицы — урок 10) — проверяется чтением (права — урок 6)
- [ ] **М10/3-02** строка единицы: `id`, `revision`, значения по типам, отсутствие ненаданных `inherit` и `null`; `blob` в правке — только прежний дайджест или `""`, иначе 400 (сц. 04 урока 10) — сц. 01, 03, 09, 10
- [ ] **М10/3-03** `revision`: 1 при создании, +1 на каждую правку, удаление не меняет, возврат имени — надгробие + 1 — сц. 03, 07
- [ ] **М10/3-04** платформенные поля не принимаются и живут порознь — сц. 04; раздельное хранение — проверяется чтением
- [ ] **М10/3-05** числовой id: счётчик с `cas`, первый 1, не используется повторно (надгробия считаются), восстановление по наибольшему из строк и живых заявок (номера отказанных попыток после него могут повториться — исключение названо), журнал восстановления — проверяется чтением (стенд урока 9)
- [ ] **М10/3-06** именованный id: грамматика Н1.3, `409 exists` над живым, возврат над надгробием только с теми же `fixed` — сц. 02, 06, 07; `fixed` — проверяется чтением (стенд урока 9)
- [ ] **М10/3-07** идемпотентное создание: ключ обязателен, повтор — тот же ответ, иной отпечаток — 422, `in flight`, захват заявки через 30 с только тем же отпечатком (иной — 422), 5xx не запоминается — сц. 01; захват и две консоли — проверяется чтением
- [ ] **М10/3-08** порядок отказов Н3 шаг 4 и строгие типы значений — сц. 04, 05, 08
- [ ] **М10/3-09** `unique`/`ref`/`must_match` — `409 conflict` с `fault` — проверяется чтением (нужно поле с `unique`; `testsub2`)
- [ ] **М10/3-10** удаление в два шага: пометка без стирания, 404 после, второй шаг контроллера — сц. 07; второй шаг — урок 4
- [ ] **М10/3-11** строка слота Н1.4 и её состояния; `server` при каждой записи; `gen` не убывает — проверяется чтением строк в приёмке урока 5
- [ ] **М10/3-12** захват: порядок кандидатов, истёкшее не отданное не берётся, чужая коробка — отказ, `cas` по прочитанной версии — проверяется чтением (приёмка уроков 5, 11)
- [ ] **М10/3-13** чистка входов предшественника под стражем слота: отдан → удалить под стражем → держим — проверяется чтением (приёмка М11 книг)
- [ ] **М10/3-14** продление каждые ~8 с с `cas`; отказ или чужой `holder` — никто; молчание хранилища — ещё мой — проверяется чтением (приёмка урока 5)
- [ ] **М10/3-15** запись под стражем слота только при живом своём слоте; `412 guard` — никто — проверяется чтением
- [ ] **М10/3-16** эпоха: `max(текущая, пол) + 1` с `cas`, раз на взятие единицы воркером (перезапуск по revision у того же держателя — та же эпоха), нечитаемая — ошибка не ноль, строка не удаляется, номер в имени данных — проверяется чтением (приёмка уроков 5, 8, 11)
- [ ] **М10/3-17** аренда: окно 25 с от момента запроса, подтверждение чтением эпохи и пола (эпоха ниже пола — `lost`), `fenced`/`silent`/`lost` по Н1.6, действия только в окне, данные — по `unconfirmed_max` — проверяется чтением (приёмка урока 5, стенд урока 11)
- [ ] **М10/3-18** зазор: старый писатель стоит к 25 с; когда о процессе ничего не известно (завис, неизвестность), единица переезжает не раньше 90 с от последнего продления (зазор ≥ 65 с); при подтверждённом `gone` ресурса — после истечения слота, 45 с (зазор 20 с: писателя нет), урок 4 Н3 «судьба» — проверяется чтением (урок 4, стенд урока 11)
