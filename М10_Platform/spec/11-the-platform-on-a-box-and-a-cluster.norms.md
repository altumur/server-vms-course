## Н1 Форма

**Время.** Полей времени у строк урока нет: `platform/configstore-doors/<id>` (`seen_at`) и пол `platform/epoch_floor` перенесены в [P/01.3](../../Platform/01-store/spec/01.3-store.norms.md) (стадия B).

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):
- владеет: `/etc/w2c/roles/<роль>.env`, `/etc/w2c/tls/ca.pem`, `/etc/w2c/tls/ca.next.pem`, `/etc/w2c/tls/revoked`, `/etc/w2c/tls/crl.pem`, `/etc/w2c/tls/<роль>/server.pem`, `/etc/w2c/tls/<роль>/server.key`;
- пишет: `platform/mirror` (put), `platform/space` (put), `<sub>/retention` (put), `<sub>/alarms_retention` (put);
- читает: `platform/spec/<sub>`, `platform/spec/<sub>/rev`, `platform/doors/<сервер>`, `platform/resources/<server>/heartbeat`, `/etc/w2c/configstore-rights.json`.

### Н1.2 Контракт окружения

Порядок чтения раннера: значения юнита → файл роли `roles/<W2C_ROLE>.env` → `w2c.env` → файл подсистемы; раньше прочитанное побеждает. Каталог `roles/` лежит рядом с `w2c.env` (каталог файла `W2C_ENV`, по умолчанию `/etc/w2c/roles/`); другого места нет. `W2C_ROLE` юнита, который не совпадает с ролью команды раннера (`w2c-run.sh <команда>`, Н1.9), — отказ запуска с кодом 2 (сверка python и go М10/6–11, B20).

Файлы окружения (`w2c.env`, `roles/*.env`, файл подсистемы, `configstore.env`) читаются разбором, не
`source`: строка `KEY=VALUE`, `KEY` — `[A-Za-z_][A-Za-z0-9_]*`; необязательный префикс `export `; значение в парных `"…"`
или `'…'` — без кавычек, подстановок нет; пустая строка и строка, чей первый непробельный знак `#`, пропускаются. Иная
строка — отказ запуска с кодом 2 и строкой лога, которая называет файл и номер строки.

На краях (сверка python и go М10/6–11, B19): строки разделяет LF; знак CR в строке, BOM в начале файла, пробел или табуляция до или после
`=` и в имени — строка не по грамматике; `export` — ровно одно слово и один пробел перед `KEY`, `export` без `KEY=` — не по
грамматике; значение без кавычек — всё после `=` до конца строки как есть, без обрезки пробелов, `#` внутри значения —
часть значения, не комментарий; пустое значение (`KEY=`) — пустая строка; непарная кавычка — не по грамматике.

**Канал настройки и раскладка `PLATFORM_DIR`** (решение «Архитектора», второй пилот, Н-4):
- процессы платформы — консоль, контроллер, воркер, ресурс, процессы домена — настраиваются только переменными таблицы
  выше и аргументом имени воркера (экземпляр `%i` юнита); собственных флагов путей и адресов у них нет; флаги есть только у
  демона хранилища ([P/01.3](../../Platform/01-store/spec/01.3-store.norms.md) Н1.3 «Флаги демона»);
- хранилище — `<PLATFORM_DIR>/configstore` (`-dir` юнита Н1.1);
- объекты — корень `OBJECTS` / `PLATFORM_OBJECTS`, по умолчанию `<PLATFORM_DIR>/objects`;
- события — корень `RESOURCE_ROOT` / `EVENTS`, по умолчанию `<PLATFORM_DIR>/events`; замки присутствия — в корне
  событий (урок 8 Н1.4 `presence_lock`);
- кольцо — `SECRETS_KEY`, по раскладке Н1.1 — `<PLATFORM_DIR>/etc/secrets` (`/etc/w2c/secrets` — ссылка), вне каталога хранилища, корня объектов и корня событий: оно не уходит ни с копией хранилища, ни с
  объектами, ни с зеркалом событий (урок 7 Н1.2).

### Н1.4 Отказ сервера

```yaml
power_pull:
  moves:    единицы — по двум молчаниям (пульс воркера и слово ресурса), по допускам урока 4; 90 с + проход —
            ориентир исправного стенда с заранее известными пульсами, доступным хранилищем и ёмкостью, не общий deadline; новый держатель берёт
            следующую эпоху; при shared и distinct одинаково; назад само не едет, кроме объявленного `home` (урок 4 Н3 «проход()», шаг 7, HOME_BUDGET)
  stays:    архив на томе сервера — под старой эпохой, недоступен до возврата, не перестраивается, не теряется;
            единицы зависшего живого воркера — у него (один писатель)
  lost:     открытый бакет и закрытые бакеты без подтверждённой зеркальной копии; один голос группы.
            RPO в длину бакета допустим лишь при подтверждённом зеркале всех закрытых; иначе потеря больше
  store:    1 из 3 — выборы за секунды; 2 из 3 — 503 unavailable через 5 с, воркеры живут на последнем назначении по аренде
            и unconfirmed_max; восстановление — recover рукой
restore:    ресурс при старте тянет свои закрытые бакеты от соседей, чьи пульсы mirrors его называют: GET /mirrored/<я>,
            каждый бакет по сумме, tmp + rename; PEER_FAILS 3 подряд — сосед пропущен на попытку; RESTORE_RETRY 10 с,
            удвоение до 600; сделано, когда получены полные списки и проверены копии от всех известных необходимых соседей;
            необходимые соседи — чьи читаемые пульсы mirrors называют этот сервер; локальные события потеряны, а пульсы
            соседей не читаются или пульса соседа нет — необходимы все известные двери серверов (platform/doors, урок 4),
            кроме своей: каждая обязана ответить полным перечнем GET /mirrored/<я> (полный пустой перечень и 404 — копий
            нет); неизвестная или нечитаемая дверь оставляет восстановление неполным (журнал cammeta-go, урок 11 № 4);
            пропущенный/нечитаемый сосед оставляет восстановление неполным; 500 перечня и обрыв ответа по М10/8 не считаются пустым полным списком. Если соседей никогда не было, удалённое восстановление отсутствует;
            потом — переиндексация подсистемы; копия — никогда не источник, пока хозяин отвечает (урок 8)
fresh_controller: впервые увиденное — только что изменилось; ничего не двигает первые 45 с (урок 4)
return:     ресурс тянет бакеты; воркеры берут свободные имена; имя с истёкшим слотом — только по слову контроллера (урок 3)
presence:   ресурс говорит о процессах своей коробки полями пульса урока 8 Н1.4 (`workers`, `running`, `unknown`; слова и их
            вывод — там же, судьба — урок 4); как узнаёт — замок присутствия урока 8 Н1.4 presence_lock
            (<корень событий>/.workers/<sub>/<экземпляр>.lock, flock; второй пилот, Н-1); нечитаемое → unknown (слово
            закрытого перечня урока 4: контроллер ждёт его), никогда «ушёл»
```

### Н1.5 Воркеры по заказу

```yaml
order:        число процессов роли на сервере задаёт контроллер — строка <sub>/want/<сервер> (М10/4 Н1.1; ADR-0084):
              want — абсолютная цель 1…99, базовый <prefix>-<SERVER_NAME>-1 в неё входит; консоль отдаёт ряд

extra_unit:   дополнительный воркер — экземпляр того же юнита роли <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>, n 2…99
              (Н1.1): те же учётные данные, ключи, пользователь и группы; захват слота обычный (М10/3 Н3); особого юнита,
              файла и переменной нет
script:       w2c-workers.sh, раз в минуту таймером, User=w2c-workers без групп; один на сервер — все роли сервера;
              polkit: только start и stop, только пользователем w2c-workers, только полные имена
              <dep>-<sub>worker@<prefix>-<SERVER_NAME>-<n>.service ролей этого сервера, n — [2-9]|[1-9][0-9] без ведущих
              нулей; базовый -1, чужой сервер, иные юниты и глаголы — отказ (ADR-0084 доп. (1) Р11)
rules:
  1. читает свои ряды <sub>_workers_wanted{server=<SERVER_NAME>} всех ролей сервера из /metrics консоли, ряды других
     серверов не читает, команд не исполняет; по HTTPS — клиентом без комплекта с проверкой сервера (Н1.6 roles)
  2. ряда роли нет, он не читается (значение не по форме метрики М10/9 — целое без ведущих нулей, знака и дроби: `02`,
     `2.0`, `+2` — ряда нет, стадия A, A6 — или вне 1…99; строка не по формату текста — пропущена с
     диагностикой, прочие ряды прохода считаются, Н0 урока 1 «Устойчивость выдачи»), консоль молчит (сбор /metrics не
     удался, последний успешный сбор старше минуты по местным монотонным часам скрипта) или ряд
     <sub>_reconcile_last_success_age_seconds (урок 9 Н3 «/metrics — текст») больше 60 или −1 → у этой роли ничего не
     запускать и не останавливать: молчание — не повод (Р1)
  3. цель роли: работающих экземпляров с n ≥ 2 — want − 1; меньше — запустить наименьшие свободные номера, больше —
     остановить наибольшие; номер сравнивается как целое, не по порядку строк (Р4); базовый -1 скрипт не трогает
  4. перед запуском — память: потолок = floor(HOST_MEMORY_MB / WORKER_MEMORY_MB) из roles/<роль>.env (разбор, не source;
     нет файла — роль пропуск); оба бюджета — положительные целые, CAPACITY — целое > 0; unit_mb и base_mb скрипт не
     читает — это вход старта воркера (memory ниже, М10/5 Н1.2; добавлено ревью стадии A 2); значение не по форме или
     ноль делителя → роль пропустить с диагностикой; потолок — число процессов роли на сервере, каждый с WORKER_MEMORY_MB: работающие, базовый -1 и
     зарезервированные старты считаются (добавлено ревью стадии A 2); общий потолок памяти сервера по всем ролям не
     делится — предел схемы (Р12)
  5. проходы сериализованы; номер резервируется до start; неопределённый исход start или stop остаётся занятым до сверки
     systemd; второй проход при той же цели новых не запускает и лишних не останавливает
  6. ровно один механизм исполняет ряды на установке: таймер или рука; на стенде — директива @grow (README приёмки М10/01)
stop:         остановка — systemctl stop: воркер отдаёт слот штатно (М10/5 Н3 «остановка»); у воркера с непустым
              назначением это переезд единиц, не потеря (ADR-0084 п. 7); контроллер уменьшает want только после пустого
              назначения сокращаемого воркера (М10/4 Н3 «сократить()»)
memory:       воркер не стартует, если CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB (ADR-0070); GOMEMLIMIT = WORKER_MEMORY_MB
```

Сторона проверяющего TLS-пира у демона хранилища (деление М10/11-11) перенесена в [P/01.3 Н1.6](../../Platform/01-store/spec/01.3-store.norms.md) (стадия B); строки ниже — выпуск, центр, комплекты и прочие процессы.

```yaml
              одинаково); добавлено сверкой М11, D14, cammeta-python М11-08 № 21
client_cert:  дверь процесса domain (SIGNER_URL, М11/2 Н1.3) запрашивает сертификат клиента необязательно и доверяет только

              ретранслятора: это агент — М11/4, М11/8 Н1.6),
              <sub>controller (читает объекты и события дверью ресурса по HTTPS; журнал cammeta-go, урок 11 № 2),
              <sub>worker — комплект по W2C_ROLE/W2C_TLS_DIR; нет комплекта → дверь на петле, клиент только к http://;
              https:// без комплекта — отказ с причиной (ADR-0075 доп.3); узкое исключение — клиент агента в процессе
              кластера из одного, только к дверям держателя и ретранслятора, с проверкой сервера (М11/12 Н1.3); второе

              урок 11 № 5)
rotation:     ca.next.pem рядом — следующий центр, которому уже верят
```

```yaml
  1. POST /drain?server=<s>; ждать GET /drain safe: true (урок 10)
  2. подтвердить покой по М10/10 Н3, остановить сервер, обновить, запустить; DELETE /drain;

install:                                       # install.sh; повтор установки = обновление
  refuse:  /etc/w2c или /etc/<sub> — настоящий каталог, не ссылка; файл прав не равен сгенерированному (урок 6)
  steps:   код атомарно (Source.new → Source) → раннер и скрипты → пользователи и группы → /data и ссылки → спеки → окружение

  failure: до изменения файлов проверить все доступные входы, пути, права, спеки и генерацию. Ошибка — ненулевой
           выход с фазой/путём; не enable/start новые службы. После начала записи возможен частичный результат:
```

## Н2 Двери

Служебные двери демона хранилища (`/v1/status`, `/v1/join`, `/v1/leave`, `/v1/rights`, `/v1/write` с `op: floor`, `/metrics`), их разбор и CLI `backup`/`restore`/`import`/`recover`/`admit` перенесены в [P/01.3 Н2](../../Platform/01-store/spec/01.3-store.norms.md) (стадия B). Двери ресурса — урок 8 (`/mirrored/<server>` для `restore`); консоли — уроки 9, 10.

Установщик/раннер/CA/скрипт воркеров — входы Н1, их отказы Н4; новых HTTP-путей для них нет.

`door.pass` проверяет framing и фактические байты запроса до отправки, ограничивает чтение ответа 4 МиБ и не следует перенаправлению. Для этого профиля ответ буферизуется в пределах лимита до отправки заголовков клиенту: превышение/обрыв/таймаут — 502 `{detail, error}`; отсутствие клиента/живой двери — 503, ошибка тела запроса — 400/408/413 по М10/9. Локальные отказы имеют форму ConsoleRefusal М10/2, успех/отказ воркера передаётся как получен (статус, Content-Type, тело), без новой схемы подсистемы в этом уроке. Не отправлять повторно автоматически; данные оператора не пересылаются по redirect.

## Н3 Проход

### старт сервера

```
1. configstore: member.json есть → рестарт (не join); нет → -bootstrap (первый) | -join (остальные); сокеты ролей по файлу прав;
   без -rights — только admin.sock; адрес вне петли без -tls → не стартовать
2. ресурс: пульс сразу, поток пульса; restore (Н1.4) в своей попытке; строка двери platform/doors/<s> с at (урок 4)
3. контроллеры спек: спека из строки хранилища (урок 2); первые 45 с никого не судят
4. консоль: спеки из строк, оболочка root, перезапечатывание секретов (урок 7), жнец просьб и отметки тел;
   удаление тел — только в отдельном окне обслуживания М10/10
5. воркеры: спека, бюджет памяти, захват имени (урок 3)
6. скрипт воркеров по таймеру: ряды workers_wanted из /metrics → start/stop экземпляров n ≥ 2 в пределах потолка (Н1.5)
шаги 2–5: первым действием каждого процесса — проверка схемы (урок 10 Н3 «старт … — проверка схемы»), до чтения спеки
```

**Гонки.** `After` задаёт порядок запуска, но не готовность хранилища, прав или спеки. Каждый процесс ждёт достоверного чтения до своего первого действия; временная недоступность — ожидание с паузой, ошибочная конфигурация/схема — выход 2. Один экземпляр юнита не исключает другой юнит/ручной процесс; единственность писателя обеспечивают слоты и роли, не systemd.

### вырвать питание (ничего не делать)

```
t = 0      сервер выключен; его демон — минус голос; его пульсы и дверь перестают меняться
около 45 с контроллеры с уже известными пульсами: слоты истекают; ресурс молчит; допуски урока 4
около 90 с при всех допусках урока 4 и свободной ёмкости → move; новая эпоха. При unknown/недоступности/нехватке
           места общего срока нет; архив остаётся на томе. У соседей лишь подтверждённые зеркальные копии
возврат    демон рестартует с сохранённым member.json (не повторяет join); ресурс тянет бакеты (restore); воркеры берут свободные имена; имена с истёкшими
           слотами — по слову контроллера; ничего не едет назад, кроме объявленного `home` (урок 4 Н3 «проход()», шаг 7, HOME_BUDGET)
```

**Гонки.** Отказ совпадает с продлением, записью и зеркалированием; границы — уроки 4, 5, 8. Отсутствие действий оператора не превращает наблюдение в снимок. Указанные сроки — профиль учения, не гарантия произвольного отказа.

### восстановить хранилище (большинства нет)

Перенесено в [P/01.3 Н3](../../Platform/01-store/spec/01.3-store.norms.md#восстановить-хранилище-большинства-нет) (стадия B).

### выпустить и отозвать сертификат

```
issue: w2c-ca.sh issue <server> <роль> → комплект; own <dir> <роль> → режимы; скопировать на сервер; процесс читает по W2C_ROLE
revoke: w2c-ca.sh revoke <server> → revoked/crl; скопировать на каждый сервер (процессы перечитывают); configstore leave <server>
        у лидера; сервер без комплекта — дверь на петле
```

**Гонки.** Изменения состава выполняет один оператор последовательно; force допускает только временную чётность в пределах объявленного максимума. Сертификат и leave распространяются разными действиями: до доставки отзыва всем узлам нельзя утверждать, что он везде действует. Запуск и остановка скрипта воркеров сериализованы по Н1.5; отсутствие пульса не освобождает зарезервированный номер.
