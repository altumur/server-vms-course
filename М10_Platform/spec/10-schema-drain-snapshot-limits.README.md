# М10/10 — Схема, дренаж, снимки, пределы: инструкция для реализации

## Задача

Создать проверки схемы, наблюдение дренажа, публикацию шардов, ограниченную дверь blob, таблицы и обслуживаемую уборку. Окна обслуживания Н3 — обязательное условие допустимого исполнения, не дополнительный механизм блокировок.

## Входы и их приоритет

Канон — [нормы](10-schema-drain-snapshot-limits.norms.md). [OpenAPI](10-schema-drain-snapshot-limits.api.openapi.yaml) выражает HTTP-формы, [приёмка](../../Source/tests/testdata/acceptance/М10_Platform/10/README.md) — наблюдаемые примеры, [лекция](../10-schema-drain-snapshot-limits.md) объясняет причины. При противоречии записать место и контрпример и передать Спецификации; инструкция не вводит новый отказ. Внутренние типы, функции и устройство реализации остаются её выбором.

## Порядок работы

1. Ввести три исхода чтения схемы: отсутствует, прочитана, неизвестна. Перед поднятием запретить старты старых сборок/их писателей, включая молчащие узлы. Проверить свою и наблюдённые схемы, затем CAS (Н1.1, Н3).

2. Взять полные формы drain у М10/4. Отличать safe по наблюдениям от подтверждённого покоя перед выключением; missing/stale pending — неизвестно, не ноль (Н1.2).

3. Публиковать отдельные snapshot-шарды только после успешного чтения источника, маскировать адреса, исключать секреты/blob. Проверить пустой unplaced, ушедший воркер, отказ одного шарда и возраст после неудачного чтения (Н1.3, Н3).

4. Сначала прочно положить blob, затем CAS строки. Отметки разрешены в фоне; удаление только после остановки всех писателей/копирования, повторного полного обхода и по фазам Н3. Не использовать idempotent put как доказательство смены индекса.

5. Реализовать таблицы как полную замену по спеке с CAS, без выдуманной памяти Idempotency-Key. Секреты не выводить; испорченная строка отличается от сбоя чтения (Н1.6, Н2).

6. Подготовить свежий стенд для каждого сценария: схема сборки 1, тело 1 МиБ, testsub/testsub2, c1 только в 04/05. Пройти 6 сценариев/36 шагов, затем отдельные пробы окна обслуживания, полного ответа и отказов ресурса.

## Ловушки языка и библиотеки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| Н1.4/Н2 | maxLength считают пределом UTF-8 байтов или верят Content-Length | Считать реальные байты; отдельно 32 МиБ blob, 64 МиБ копия и 4000 JSON-поля. |
| Н3 | Повтор put_durable обязательно меняет индекс | Допуск удаления обеспечивает окно без писателей; проверять тот же digest/тот же индекс. |
| Н2 | Идентичный table POST считается безопасным повтором | Stamp/журнал меняются; неизвестный исход сначала выяснить чтением. |
| Н1.3 | Ошибка чтения обнуляет возраст/публикует пустой шард | Сохранить неизвестность и последнее наблюдение; пустота только из успешного обхода. |

## Готово, когда

Все 10 id имеют свидетельства. TSV не проверяет fsync, зеркало, надгробия, конкуренцию и реальное обслуживание: для них нужны трасса фаз и стенд с отказами. Перед выводом «безопасно удалить» подтвердить остановку писателей и копирования. Общий CLI lesson-spec пока не понимает эту приёмку; отдельная проверка формата не равна работе системы.

## При расхождении

Сравнить норму, форму ответа и сценарий. Зафиксировать точный вход и исход; отличие реализации не переносить молча в канон. Решение отражается в норме, контракте, инструкции и затронутой приёмке; происхождение ошибки и проверка связанного класса — в журнале Спецификации.

Дополнительная проверка после прогона 33: Для 400 таблицы проверить полные текстовый и структурный отказы. Общие TextRefusal/FormRefusal пересекаются без fault, поэтому anyOf, а не oneOf; все локальные oneOf проверять на пересечение ветвей.

Проверить шаблон таблицы notches с тремя подстановками по владельцу М10/2. Имена таблиц/rows: lowercase ASCII 1–32, запреты семейств/дверей, Audit и 33 символа отвергаются при загрузке. Схему при старте проверяет и консоль; демон непрозрачного строкового хранилища явно исключён.
