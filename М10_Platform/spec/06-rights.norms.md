## Н1 Форма

**Данные** ([каталог](../../Platform/common/data/catalog.tsv)):

### Н1.1 Роли

```yaml
roles:
  per_spec:                              # из каждой спеки каталога
    <sub>controller:     контроллер спеки
    <sub>worker:         воркер спеки
  platform:              [resource, console, domain, domainconsole, domainagent] # console одна на кластер, пишет строки оператора всех спек; domain, domainconsole, domainagent — роли домена (М11; domain — подписант с ключами, domainconsole без ключей — М11/2 Н1.3)
  store_internal:        [admin, configstore (peer), configstore-door]     # в файле прав не называются; configstore-door — дверь без голоса (добавлено М10/11 Н1.3)
  reader_word_only:      [domainworker]    # (М11/5 Н1.6: воркер подсистемы на домене) слово платформы в secrets.readers (М10/7 Н1.3; решение C7
                                         # decisions/inbox/2026-10-15-c7-общее-имя-роли.md): роли в файле прав не даёт —
                                         # отображается в роль <sub>domain спеки, где есть domain.kept или переносимая книга
                                         # (М11/5 Н1.6; ADR-0074 C7 п. 2 и доп. 5: платформенная способность, не снятый процесс
                                         # domainpart) — и в сравнение «объявленные = способные прочесть» не входит
name:      ^[a-z][a-z0-9_-]{0,63}$       # имя роли; <sub> — по грамматике имени спеки (урок 2)
group:
  platform role:         w2c-<роль>      # console, resource, domain* (М11), и каждый <sub>controller (ADR-0030)
  subsystem role:        <развёртывание>-<роль>   # только <sub>worker: контроллер — платформенная роль w2c-<sub>controller (ADR-0030); развёртывание: ^[a-z][a-z0-9]*$
identity:
  cluster:  сокет /run/configstore/<роль>.sock (0660, группа роли — SocketGroup= юнита сокета, урок 11 Н1.1); admin.sock (0600, root)
  box:      имя писателя у хранилища файлов/памяти + тот же список прав; дверь коробки тоже открывает сокет на роль;
            доверенных отправителей пересылки на коробке нет: заголовок роли на любом сокете, включая admin.sock, —
            403 с ролью сокета
  doors:    сертификат роли: SAN URI urn:w2c:role:<роль>, CN <роль>.<сервер>, SAN DNS <сервер>; комплект
            /etc/w2c/tls/<роль>, ключ 0640 root:<группа пользователя юнита> (w2c у юнитов платформы, `<пользователь подсистемы>` у воркера — М10/11 Н1.1), не группы ролевого сокета; роль берётся из W2C_ROLE процесса (ADR-0075)
```

### Н1.2 Файл прав

Файл — объект JSON с обязательным полем `roles` и необязательным строковым `comment`.
`comment` — пометка генератора; она не участвует в выдаче прав. Пометка обязательно называет, что файл сгенерирован,
развёртывание, исходные спеки и «не править вручную»; для одних входов её текст один и тот же (М10/6-07). У каждой роли обязательны `group`
(непустая строка), `read` и `write` (массивы строк); `delete` — необязательный массив строк.
Неизвестные поля отвергаются. Имена ролей проверяются целиком, включая конец строки;
внутренние роли хранилища в файл не входят. Полная статическая форма — `RightsFile` в Н2.

```yaml
configstore-rights.json:
  comment:  <пометка генератора>      # необязательно; только строка, не права
  roles:
    <роль>:
      group:  <группа сокета>
      read:   [<образец>…]
      write:  [<образец>…]
      delete: [<образец>…]            # генератор пишет у каждой роли всегда: = write, если спека не разнесла их через
                                      # delete:; у оценщика отсутствие — пустой список: удалять нельзя (минимум прав)
pattern:
  exact:    "testsub/next_id"            # равенство ключу
  prefix:   "testsub/counters/*"         # * последним знаком — префикс; * не последним — буквальный знак (literal ниже)
  deny:     "!domain/signer*"            # ! только первым знаком; отрицание побеждает везде в списке
  literal:  "", "!", "!*", "p/!x", "a*b"  # допустимы в файле и совпадают по правилам выше: "" — только пустой ключ,
                                          # "!" — отрицание пустого ключа, "!*" — отрицание всего, "!" не первым и "*" не
                                          # последним — буквальные знаки (сверка python и go М10/6–11: обе так; журнал
                                          # cammeta-go, урок 6 № 2; вектор Platform/01-store/vectors/rights-evaluator)
rules:
  - файл не называет admin, configstore, configstore-door; неверная форма — файл отказан целиком
  - генерируется из каталога спек (SPEC_DIR) и имени развёртывания; руками не правится
  - загружается при старте демона (-rights); без файла открывается только admin.sock; живой перезагрузки нет
  - установщик отказывается ставить файл, по смыслу не равный сгенерированному (--check, Н3 «установить»)
  - файл показывается дверью только admin
```

Имена производных ролей помещаются в Н1.1: имя спеки ограничено 32 знаками
(М10/2 Н1.2), суффикс controller добавляет 10, worker — 6. Имя не усекается. Предела имени развёртывания урок не
ставит: группа `<dep>-<s>worker` бывает длиннее 32 знаков, генератор её не усекает и не отказывает (сверка python и go
М10/6–11: обе так); создаёт ли её ОС — установщик, урок 11 «Решает реализация» п. 1.
Сравнение `--check` относится к одному неизменному каталогу; публикация спек во время
генерации и установки в этом уроке исключена условиями обслуживания, а не обнаруживается автоматически.

### Н1.3 Оценщик

```yaml
allowed(role, action, key):
  action ∈ {read, write, delete}
  role не в файле                                        → нет
  любой !образец роли для action совпал                  → нет
  любой образец роли для action совпал                   → да
  иначе                                                  → нет
never:                                                   # и для admin
  - delete строки <x>/epoch/<y> — ровно один сегмент <y> после «<x>/epoch/», в том числе пустой (`t/epoch/`), x ≠ platform
    (строка эпохи урока 3 <sub>/epoch/<id>) (сверка python и go М10/6–11, R12)
  - delete под domain/ не ролью домена (domain, domainagent, <s>domain — в своих семьях ниже)
  - write и delete platform/epoch_floor (только операция восстановления, урок 11)
list:   имена и версии под префиксом — любой роли; значения — нет
guard:  запись со стражем требует права read на строку-страж; страж права не расширяет (ADR-0074 доп. 3)
admin:  всё, кроме never; peer (другой демон) — ничего своего; configstore-door — только свою platform/configstore-doors/<id> (урок 11 Н1.3; не platform/doors/* ресурсов)
```

Положительные списки ниже — исходные права, не обход Н1.3: never применяется ко всем,
включая admin; отрицания секретных читателей М10/7 вычитаются из read.

### Н1.4 Вывод прав из спеки

Писатели семей — уроки 3, 4, 5; 8 Н1.5 (`<s>/requests/*`, `<s>/asked/*`); 10 Н1 (`platform/schema`, `platform/drain`, `<s>/sweep`, `<s>/<таблица>/*`); здесь сводка того, что генератор выводит для каждой роли из ключей спеки. Права чтения — положительные списки, выведенные так же; секретные строки читают только объявленные читатели (урок 7).

Общие правила вывода действуют на каждую строку таблицы, строка их не повторяет:

- в `read` каждой роли входит `platform/spec/*` — спеки кластера, по которым она работает (ADR-0068), если его
  не покрывает уже `platform/*`;
- в `read` входят все положительные образцы её `write`; образцы только удаления (`delete:…`) и отрицания `write`
  в `read` не входят;
- отрицания `!<s>/idem/*` и `!<s>/asked/*` (заявки и учёт людей — только консоль) получают только роли, чьи чтения
  их достают (образец, покрывающий `<s>/*`); файл прав для одних входов байт-стабилен;
- слова `secrets.readers`: `controller` и `worker` — роли объявляющей спеки (`<s>controller`, `<s>worker`),
  остальные — платформенные роли как есть, `domainworker` — по Н1.1; `secrets.reads` спеки `B` ДОБАВЛЯЕТ `Bworker`
  к читателям названной строки и ничего не отнимает; отрицания `!<образец>` прочим генератор выдаёт только для строк,
  объявленных секретными — в `secrets.readers` спеки каталога или в общей таблице `platform_lists.tsv` (М10/7 Н1.3);
  семья, названная в `secrets.reads`, но не объявленная секретной (строки единиц другой спеки — `testsub/counters/` у
  `testsub2`), даёт только чтение `Bworker`: её роли-владельцы читают её по своим правам, как без объявления;
- образец объектов `objects/<s>/commands/*` выдаётся в файл как есть образцом `write` (а с ним, по общим правилам, `read`
  и удаление) роли `<s>worker` у спеки с разделом `requests`: метки просьб пишет, закрывает и убирает держатель —
  воркер (М10/8 Н1.5 mark); строк хранилища он не касается, оценщик строк его не встречает (журнал cammeta-go, урок 8 № 4).

Объявления, переводимые в образцы (`worker.reads`, `secrets.readers`, `secrets.reads`), не содержат буквальный `*` и не начинаются с `!`/`delete:`; непредставимое объявление — отказ загрузки/генерации до файла. Это не запрет такого ключа в самом хранилище. Проверять не только читателей самого секрета, но и неизменность прав соседних обычных строк.

Правила генератора: роль удаляет то, что пишет (кроме меток команд у консоли и двух сохраняемых строк допуска у контроллера); образец `delete:<…>` даёт только удаление без записи (консоль — `platform/doors/*` выведенного сервера, контроллер — строки единиц при `delete_after`, воркер — строки своих единиц при `worker.deletes`, удаление с `cas` по прочитанной версии); `worker.writes` ДОЛЖЕН называть объявленную собственную таблицу; имя `unit.rows` и необъявленное имя дают отказ загрузки `refused:reference` (урок 2). Строки единиц остаются за консолью и удалением контроллера по допуску; исключение таблицы воркера не даёт ему прав на `unit.rows`; семьи `<s>/idem/*` и `<s>/asked/*` — отрицание `!` всем, кроме консоли; секретные строки (объявленные в `secrets.readers` или `platform_lists.tsv`) — читателям по `secrets.readers` и `secrets.reads`, прочим с досягающим правом — `!<образец>`; `secrets.reads` без такого объявления только добавляет чтение `Bworker` (Н1.4), где образец — ключ как объявлен: префикс с `/` → `<префикс>*`, точный ключ — без `*` (урок 7 Н1); генератор отказывается выдать файл, если множество объявленных обычных читателей секрета не равно множеству обычных ролей, которые его прочтут. Внутренний admin проверяется по особому правилу Н1.3, а не включается в объявление читателей.

### Н1.5 Ключи `rights:` спеки — граница прав людей

Не права процессов: что консоль спрашивает у грантов человека (`view`/`edit`/`admin`, М11) при правке. Форма — урок 2; смысл одинаков у обеих реализаций:

| Ключ | Смысл |
|---|---|
| `routes: {view: [семьи], edit: [семьи]}` | записи семьи требуют меньше, чем `admin`: `view` или `edit`; у строк единиц понижается только создание |
| `cluster_rows: true` | любая запись строки единицы требует гранта на кластер |
| `unit_of: {таблица: поле}` | строка таблицы принадлежит единице из поля; запись требует права на единицу прежней и новой строки |
| `reach: {group: [поля], cluster: [поля], requests: [действия]}` | что меняет правка сверх единицы: поле группы — все единицы старой и новой группы; поле кластера — грант на кластер; просьба с действием — `edit` на всю группу; `reach.group` требует `placement.group_by` |
| `names: [{field, unit, sub \| of}]` | единицы, которые строка называет внутри `json`-поля; их цели добавляются к досягаемости правки |

### Н1.6 Правило адреса

```yaml
address:
  store:    демон хранилища (raft, -api, дверь без голоса) вне петли — только с -tls; иначе отказ старта
  process:  дверь процесса без комплекта сертификатов — только 127.0.0.1; адрес вне петли без -tls — отказ старта
            (ADR-0075 п. 2); исключение: signer, relay, resource без комплекта МОГУТ слушать вне петли только по явному адресу
            (ADR-0075 доп. 2026-10-12 (2)); слушают — ДОЛЖНЫ при старте написать в лог строку «<роль> listens on <адрес>
            without a certificate kit: anyone who reaches it may call it»; отказ старта тоже соответствует (сверка python и go
            М10/6–11, R14)
  defaults: условных ослаблений нет: AUTH=0 нет, X-User / X-Operator без аутентификации не принимаются
  cert:     одна роль на сертификат; роль в сертификате ДОЛЖНА равняться роли процесса, иначе отказ рукопожатия
            или 403 с ролью и маршрутом (ADR-0075 доп. 3)
```

## Н2 Двери

Двери прав — двери хранилища урока 1, за сокетом роли; разбор запроса — урок 1 Н2.1, у `GET /v1/rights` query не читается. Дополнительно:

HTTP-контракт: [06-rights.api.openapi.yaml](06-rights.api.openapi.yaml).

`GET /v1/rights` возвращает загруженный объект `RightsFile` целиком, без оболочки;
если в нём есть comment, поле также возвращается. При отсутствии загруженного файла маршрут отвечает `404 badrequest`;
пустой объект `roles` не подменяет отсутствие файла. Доступ проверяется по личности admin,
до выдачи файла. Успешный `GET /v1/list` использует `Listing` урока 1: без значений строк,
с версиями и порядком имён по UTF-8-байтам. Наличие пути и доверие личности проверяются
также для list; отсутствие права read не препятствует перечислению.

Формы всех ответов двух маршрутов заданы в OpenAPI. Отказы `400` (`/v1/list` не по форме урока 1 Н2.1), `403`, `404`, `503` —
ровно `{kind, error}` строками, соответственно `badrequest`, `forbidden`, `badrequest`, `unavailable`;
никаких `detail`/`fault` консоли. Для отказа операции над строкой `error` называет роль,
действие и ключ; для отказа самой личности или `/v1/rights` — роль и причину/маршрут.
При заголовке роли на ролевом сокете называется роль сокета,
а не навязываемая заголовком роль; разбирать ключ операции ради диагностики не требуется.

Инструмент генерации — `rights` установщика (`w2cctl rights -deployment <имя>`): читает `SPEC_DIR`, пишет файл; `--check <файл>` сравнивает и возвращает ненулевой код при расхождении.

## Н3 Проход

### сгенерировать_права(каталог спек, развёртывание) → файл

```
1. роли: console, resource, domain, domainconsole, domainagent (М11); на каждую спеку — <s>controller, <s>worker
   и <s>domain — у спеки с domain.kept или переносимой книгой (воркер подсистемы на домене, М11/5 Н1.6; ADR-0074 C7
   п. 2, доп. 5); группы по Н1.1
2. для каждой роли — write по Н1.4 из ключей спеки; delete = write, минус все права «только write» Н1.4:
   метки команд у консоли, <s>/controller/placement_turn и <s>/controller/placement_intent у контроллера;
   плюс все delete-only из Н1.4: delete:platform/doors/* у консоли, delete:<s>/<rows>/* у контроллера при delete_after и
   у воркера по worker.deletes; список delete выдаётся явно,
   чтобы отсутствие поля не вернуло исключённые права через умолчание Н1.2
3. read по Н1.4; worker.reads: ключ с `/` на конце → префикс; domain/placed/<sub>/ дополнительно даёт domain/placement/<sub>/; исходное domain/placed/<sub>/ сохраняется
4. сначала проверить представимость всех объявлений Н1.4; отказ → файла нет;
   секреты: секретная строка — объявленная в secrets.readers спеки каталога или в platform_lists.tsv; её читатели — по
   secrets.readers/reads (и платформенные читатели, урок 7); secrets.reads на необъявленную строку — только +Bworker, без !;
   образец — ключ как объявлен (урок 7 Н1): префикс с `/` на конце → <префикс>*, точный ключ → сам ключ без `*`
   (`domain/<sub>/<книга>` не закрывает `domain/<sub>/<книга>/*`); объявления не вкладываются (урок 7 Н1.3) — отрицание одного не
   задевает другого; читателю — образец, если его чтения его не достают; нечитателю, чьи права его достают, — !<образец>
   множество объявленных обычных читателей ≠ множество обычных ролей, способных прочесть → отказ генерации;
   внутренний admin не сравнивается с этим множеством (его исключение — Н1.3 и М10/7 Н1.3)
5. выдать JSON с отсортированными образцами (байт-стабильно); «generated — do not edit» —
   поле comment либо сопроводительный текст вне JSON. Не писать комментарии синтаксиса // или /* */.
   Для одинаковых входов форма и текст пометки стабильны; --check сравнивает по смыслу (Н3 «установить»), не байты
```

**Гонки.** Вход — неизменный каталог по Н1.2. Две генерации с одинаковыми входами дают файл
байт в байт. Разные входы могут давать одинаковые права; проверка не доказывает неизменность
исходных файлов, а только совпадение файла прав с результатом генерации.

### проверить(роль, действие, ключ) — в каждом хранилище перед действием

```
роль — из сокета (кластер) | имени писателя (коробка); заголовок с ролью на сокете роли → 403 до разбора тела
  (тело не по форме с таким заголовком — тоже 403; сверка python и go М10/6–11: обе так)
пересланная роль: сначала проверить доверие демону группы и запрет пересланного admin (ниже)
list: после проверки личности вернуть имена и версии без проверки права read
never (Н1.3)                                                   → 403 forbidden
admin: после never разрешить операцию; внутренние роли — только по исключениям Н1.3
остальные: allowed(роль, действие, ключ) по Н1.3                → иначе 403 forbidden, до записи в журнал
запись со стражем: allowed(роль, read, страж)                   → иначе 403
  (admin читает страж по своему разрешению Н1.3)
в группе: проверяет принявший демон и ещё раз лидер под пересланной ролью; пересылке верят только от демона группы — голосующего или двери без голоса `configstore-door` (урок 11 Н1.3), по роли в SAN сертификата; пересланный admin при наличии файла прав — отказ
```

Условия пересылки применяются и к list, и к /v1/rights до выдачи данных. Локальный
admin из admin.sock и доверенный пересланный admin без файла доходят до особых правил
Н1.3; при загруженном файле пересланный admin отказывается раньше операции.
Отсутствие файла не отключает never и проверку доверия отправителю.

**Гонки.** Нет: права не меняются на ходу — новый файл = перезапуск демона.

### установить(файл прав)

```
rights --check <файл> против SPEC_DIR                          → расходится: установка отказана
  сравнение по смыслу: одинаковый набор ролей; у каждой роли равны group и множества образцов read, write, delete
  (порядок и повторы в списке не важны; нет delete — пустое множество, как у оценщика Н1.2); comment, порядок
  ключей и пробелы не сравниваются; файл не по форме Н1.2 — расходится
  (пилот хранилища, А5)
юниты: SupplementaryGroups=<группа роли>; PLATFORM_STORE=configstore:///run/configstore/<роль>.sock
демон: сокет на роль, 0660, группа роли — SocketGroup= юнита configstore-<роль>.socket (урок 11 Н1.1); admin.sock 0600
```

---

**Гонки.** Установка выполняется одним установщиком по неизменному каталогу; параллельная
установка и правка `SPEC_DIR` исключены из этого урока. Работающий демон сохраняет прежние
права до перезапуска. Перед стартом с новым файлом установка выполняет `--check`; при
расхождении демон с этим файлом не запускают. Живого переключения прав и атомарного
переключения всего кластера урок не обещает.

## Решает реализация

Реализация обязана назвать в своём описании:

1. **как раннер и тесты звонят ролью на одной коробке** (имя писателя, тестовый сокет);
2. **точный текст** `error` сверх «<роль> may not <действие> <ключ>» (имя файла, демона);
3. **флаги инструмента генерации** сверх `-deployment` и `--check` (сам инструмент — Н2), путь файла по умолчанию (`/etc/w2c/configstore-rights.json`), путь сокетов на не-Linux;
4. ~~**как демон попадает в группы ролей или обходится setgid-каталогами**~~ — нормировано: группу сокета роли задаёт `SocketGroup=` юнита сокета, демон в группы ролей не входит (урок 11 Н1.1, Н1.3 `sockets`; пилот хранилища, А4);

## Соответствие прежним урокам

Нормирует то, что рассказывали `М10A_Platform/02-Variables.md` (шаги 12–16: личность писателя, `as_writer`, оценщик, образцы и отрицание, один писатель на префикс), `М10A_Platform/09-SubsystemSpec.md` (шаги 14–18: `acl_console`, `acl_controller`, воркер, три токена из одного файла, все токены подсистемы, файл прав кластера), `М11_Cluster/05-rights-by-who-is-calling.md` (целиком: кто что пишет, файл прав и сокеты ролей, проверка на сервере, файл против кода, mTLS демонов — последнее как форма, выпуск и отзыв — урок 11), `М10A_Platform/20-ObjectACL-and-Sweep.md` (в части повторения оценщика и генератора; объекты и уборка — уроки 8, 10).
