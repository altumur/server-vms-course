## Существенные

**К-1 (существенная).** `exclusive` внутри `strict` сталкивается с ключами-полями.
- D9 п. 6: «`placement.affinity.strict` получает опцию `exclusive: true`».
- Нормы:
  - P/02.1:285: «`placement.affinity.strict` | отображение, opaque | необязателен | | ключи — поля таблицы»;
  - P/04:143: «связывающая строка ведёт единицу только на своё место»;
  - P/04:1132: «`affinity.strict` выбирает связывающие строки».
- Контрпример: запрос «строгое место» — `affinity.strict: {kind: [backup, edge], enabled: true}`.
  - С опцией по D9: `{kind: [backup, edge], enabled: true, exclusive: true}`.
  - Реализация А читает `exclusive` как опцию. Реализация Б — как поле таблицы `volumes`: связывающих строк с `exclusive = true` нет, и строгих мест нет вовсе.
  - Таблица с полем `exclusive` делает опцию неотличимой от условия.
- Предложение: опция — ключ рядом, не внутри: `placement.affinity.exclusive: true` (P/02.1 — новая строка, bool, умолчание `false`, только при `strict`). Отказ загрузчика: `exclusive` без `strict`.

**К-2 (существенная).** Исключительность у места, а размещение — у воркера: воркер с двумя местами блокирует обычное.
- D9 п. 6: «держатель такого места принимает только единицы, связанные с этим местом; прочие на него не размещаются».
- Нормы:
  - P/03.2 «взять_место» (:604–610): воркер берёт места из кандидатов подсистемы; сколько мест держит один воркер, норма не ограничивает;
  - P/04 `пригодные = пул ∩ constraint ∩ spread_by ∩ affinity ∩ …` (P/04:718) — фильтр по воркеру.
- Контрпример: сервер `srv2`, у `rec` один базовый регистратор `w-srv2-1`.
  - Он держит основной том `vol1` (обычное место) и резервный `bk1` (`exclusive`).
  - По D9 п. 6 воркер `w-srv2-1` — «держатель исключительного места», и запись с домом `vol1` на него «не размещается».
  - Основной том `vol1` держится, но писать на него некому. Без `grows` второго регистратора на `srv2` не будет; с `grows` нехватка закажет второй — и он может взять `bk1` следующим.
- Последствие: смысл «на резервный том не идёт ничто другое» (запрос) превращается в «на воркер с резервным томом не идёт ничто другое». Это разные правила, и реализации выберут разное.
- Предложение — назвать одно:
  - **воркер, держащий исключительное место, других мест не держит** (P/03.2 «взять_место»: исключительное место берёт только воркер без мест, и воркер с ним новых не берёт). Тогда D9 п. 6 о воркере верен;
  - либо исключительность — по единицам места: на воркера не размещается единица, место которой — его исключительное место… (т. е. фильтр по месту единицы, не по воркеру). Сложнее для P/04, но воркер держит несколько мест.

## Мелкие

1. **Разрешение `SERVER_NAME` на старте** (D9 п. 2).
   - Несколько адресов (IPv4 и IPv6) — какой слушать и с каким сравнивать явный `<ДВЕРЬ>_HOST`?
   - Временная ошибка разрешения при загрузке (DNS ещё не поднялся) — если это «отказ старта, код 2», `RestartPreventExitStatus=2` (P/02.4 Н1.1 `common`) оставит процесс лежать до оператора.
   - Сказать:
     - слушать все адреса разрешения;
     - явный — «не из их числа» — код 2;
     - неудача разрешения — ожидание с паузой (как недоступное хранилище, P/02.4 «Гонки» старта сервера), не код 2.
2. **Причина несостоявшегося места в пульсе.** D9 п. 5: «`place_by: ""` и слово причины» — но `place_by` — поле манифеста с одним значением (P/03.4:63), поля для причины нет. Назвать поле пульса (например, `place_why`, закрытый перечень: `sealed`, `not_open`…).
   - Попутно: секрет открывается «при взятии места». Оператор сменил `access_secret` у держимого места — новая ревизия строки. Держатель открывает заново или отпускает и берёт место снова, как единица при смене `revision`. Назвать.
3. **Ёмкость держателя исключительного места в нехватке.** Его свободная ёмкость (P/04 Н3 «нехватка()», «свободно воркера» в порядке наборов) другим единицам недоступна. Если её считать общей, нехватка недозакажет, и чужие единицы ждут при «свободной» ёмкости. Исключить из счёта для несвязанных.
4. **Место без сервера и без держателя; место, которое не открывается.**
   - D9 п. 6: «заказ воркера на сервер места». У места без `server_field` сервера нет: заказывать некуда. Сказать — «единица ждёт, место берёт любой воркер подсистемы».
   - Место с `Sealed` секретом остаётся «без держателя» при живых воркерах. Нехватка будет заказывать воркеров на его сервер, и каждый новый его тоже не откроет (до потолка `room`). Сказать: место, не взятое по причине из пульса (мелкое 2), заказа не вызывает — `withheld` с причиной.
