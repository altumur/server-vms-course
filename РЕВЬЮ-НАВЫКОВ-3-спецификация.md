## skills/lesson-spec/SKILL.md, review-checklist.md и ADR-0080 доп. 16

**1. Существенная — правило о байтах свидетелей и заморозка старого Python вместе запирают данные спецификации.**
- Места:
  - `SKILL.md:44–47` — «Байты данных, которые читают старые реализации-свидетели (`testsub*.yaml`, общие таблицы
    `testdata/*.tsv`, спеки `Source/vms/*.subsystem.yaml`), меняются только вместе с назначенным им долгом внедрения
    (ADR-0080 доп. 16 п. 3). При такой правке перед пушем … `python Source/tests/run.py test_boundary
    test_spec_verdicts test_platform_lists` не даёт новых отказов»;
  - чеклист `:26–27` — то же;
  - ADR `0080:937–940` — «старый Python заморожен … Его тесты общей приёмки читают её на закреплённом срезе курса
    `a0bd9e53` … Долгов старому Python больше не назначают».
- Противоречие: долг — единственный путь правки байтов, а долгов старому Python больше не будет. Закреплённый срез
  назван только для «общей приёмки», не для `testsub*` и спек VMS. Значит, байты, которые читает старый Python,
  нельзя менять до его вывода, то есть до перевода М11–М14. Команда шага 3 гоняет тесты именно замороженного
  Python против живых байтов.
- Контрпример — открытые долги в `ХОД-Спецификация.md`, которым теперь некуда сойти:
  - `testsub2` `reads` → `testsub/counters/` (откат `b7748839`);
  - `live.subsystem.yaml` `worker.deletes`;
  - потребитель дозаписи в `testsub2`.
  Норма М10/6 Н5 уже требует семью. Генератор `cammeta-python` получает `testsub2` из выгрузки с точным ключом.
- Последствие: канон и данные расходятся на неопределённый срок. Новые реализации генерируются по неверным данным,
  хотя свидетель, ради которого байты берегут, всё равно заморожен.
- Рекомендация (вопрос «Архитектору»):
  - закрепить за старым Python срез `a0bd9e53` для всех данных спецификации, а не только для приёмки;
  - свидетелем байтов оставить продукт (Go, `sync-course.sh`), долг ему — через «Сборку»;
  - в SKILL шаг 3 вместо тестов старого Python назвать проверку сверки продукта или «долг „Сборке“ назначен».
