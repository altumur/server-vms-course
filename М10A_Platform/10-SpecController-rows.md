# Урок 10 — `SpecController` I: строки

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** первую половину единственного контроллера курса: создание, правку и удаление по CAS, счётчик идентификаторов, производные строки и ту половину удаления, которую делает не консоль, а контроллер на следующем проходе.
**Время:** ~90 минут.

## Зачем этот урок

Спецификация умеет описывать форму и отказывать. Чтобы из неё получился контроллер, нужно соединить её с хранилищем — и почти весь код этого соединения уже написан: `Controller.write` из урока 8 делает «прочитать-изменить-записать по CAS», `SubsystemSpec.new_row` собирает запись, `refuse` отказывает. Остаётся сложить.

И всё же это не сложение в три строки, потому что каждая операция над строкой оператора отвечает на свой неочевидный вопрос. Создание: откуда берётся идентификатор и что делать, если такая единица уже была и её удалили. Правка: что происходит с ревизией и с производными строками. Удаление: почему оно делается **в два приёма** двумя разными процессами.

Последний вопрос — самый интересный, и ответ на него объясняет, почему у курса вообще два владельца конфигурации. Оператор нажал «удалить». Строку надо пометить — это может консоль. Но у единицы есть размещение и она лежит в назначении воркера, а туда консоль писать не вправе (урок 9). Значит, удаление не может быть одним действием; оно распадается на половину оператора и половину контроллера, разделённые несколькими секундами.

> **Что можно проверить без железа.** Всё. В коде курса это `Source/tests/test_lesson6_controller.py` — он гоняет контроллер на спеке VMS: создание, правка с ростом ревизии, пять отказов, удаление, два контроллера, размещающие сорок единиц в гонке; и `test_units_about.py` с `test_spec_declarations.py` — на `testsub` и подсистемах, придуманных прямо в тесте: неизменяемое поле, возврат имени, ссылки и уникальность. Ни один тест не поднимает ни сети, ни процесса.

## Что нужно знать заранее

- **Урок 8** — `Controller.write` и приём «мутатор вернул `None`».
- **Урок 9** — `row`/`items`, `refuse`, `new_row`, производные ряды.
- **Урок 2** — `cas=0` как «создать, только если нет».

## Чему вы научитесь

1. Соединять спецификацию с хранилищем так, чтобы ни одна операция не читала ключ дважды.
2. Выдавать идентификаторы счётчиком по CAS и говорить, почему не UUID.
3. Обрабатывать возврат единицы под тем же именем после удаления.
4. Объяснять, почему ревизию бумает контроллер, а не триггер базы и не клиент.
5. Писать производные строки без лишних записей.
6. Делить удаление на две половины и говорить, что произойдёт, если вторая опоздает.
7. Читать из спеки, на что строка может указывать и что одно на кластер (`ref`, `must_match`, `unique`, `fixed`), вместо того чтобы звать код подсистемы.

## Шаг 1 — Конструктор

```python
class SpecController(Controller):
    """The only writer of <name>/*, from a spec. Holds nothing; two instances
    are harmless; never on the recovery path. …"""

    def __init__(self, spec: SubsystemSpec, vars_: Variables, objects: ObjectStore, capacity: int | None = None,
                 wall=time.time, cluster: str | None = None):
        super().__init__(spec.sub, vars_, objects, wall)
        self.spec = spec
        self.capacity = capacity if capacity is not None else spec.capacity_default   # the FALLBACK for a worker whose heartbeat says nothing
        self.cluster = cluster or os.environ.get("CLUSTER", "room-a")                  # the name the snapshot carries; one box is a cluster of one
        self.rows_garbled = 0                                                            # rows the last `units()` could not parse (the review's second pass, M7)
        …
        from .sealing import Sealer
        self.sealer = Sealer.from_env()
```

Наследует базу из урока 8 и добавляет три главные вещи. `spec` — описание. `capacity` — **запасное** число ёмкости для воркера, чей heartbeat её не назвал. Умолчание — `placement.capacity.default` из YAML, и спека без него не загружается: пятьдесят единиц одного рода — маленький воркер, другого — невозможный, и это число подсистема говорит сама (у `testsub` — 4). Аргумент его перекрывает, и это лазейка для тестов, которым нужна ёмкость 2, чтобы заполнить воркера тремя единицами. `cluster` — имя, которое уедет в снимке (`$CLUSTER`, иначе `room-a`); на коробке это кластер из одного. Остальное в опущенной части — счётчики для отчёта прохода (урок 11) и `sealer`, которым консоль запечатывает поля `*_secret` по пути в хранилище (урок 18).

Первая строка docstring — то же обещание, что у базы, и оно здесь повторено, потому что теперь класс делает содержательные вещи: **не хранит ничего, два экземпляра безвредны, никогда не на пути восстановления.** Третье утверждение проверяет `test_lesson6_controller.py::test_the_failure_arithmetic`: контроллер остановлен, а воркер продолжает работать, и модель чтения отвечает из heartbeat'ов. И ни в одной строке класса нет имени подсистемы: что такое единица, знает только спека.

`row_key` — ключ строки единицы:

```python
    # `<name>/<rows>/<id>` — the key of a unit's row: what a subsystem reads a row by (exported for that, the boundary's
    # step 5: a subsystem's console called the private name).
    def row_key(self, uid) -> str:
        return self.sub.config(self.spec.rows, str(uid))
```

Имя строк — из YAML, ключ — через `Subsystem`: `counter/ticks/7`, `testsub/counters/c1`. Метод открытый: подсистема читает по нему строку своей единицы, а не лезет в частное имя платформы.

## Шаг 2 — Идентификатор

```python
    def _next_id(self):
        if self.spec.numeric:
            key = self.sub.config("next_id")

            def bump(it):
                n = NEXT_IDS.read(key, lambda: int(finite(it.get("n", 0) or 0)))
                return {"n": (self._largest_id() if n is None else n) + 1}
            new = self.write(key, bump)
            return int(new["n"])
        raise Refused(f"a {self.spec.name} unit is named by its {self.spec.id}")

    def _largest_id(self) -> int:
        prefix = self.sub.config(self.spec.rows, "")
        ids = [k[len(prefix):] for k in self.vars.list(prefix)]
        return max([n for i in ids if (n := numeric(i)) is not None] + [0])     # `doors.numeric`: not `isdigit` + `int`
```

Счётчик по CAS — тот же цикл, что у эпох, через общий `write`. Первый идентификатор — 1.

Почему счётчик, а не UUID. Потому что идентификатор попадает **в путь на диске** ресурса (`<подсистема>/7/e3/…`, урок 12), **в URL** (`/ticks/7`) и **на экран оператора**. UUID не диктуется техникой: гонки он не решает (её решает CAS), а читаемость убивает. «Номер семь» — это то, что человек скажет вслух по телефону в три часа ночи; `f47ac10b-58cc-…` — нет.

Цена — один ключ, за который борются все создатели строк этой подсистемы. При двух консолях и создании единицы раз в минуту это не борьба. Вторая цена — идентификаторы **не переиспользуются**: удалили седьмую, следующая будет восьмой. Так и должно быть, потому что под номером седьмой остались её данные — события на диске ресурса, всё, что воркер написал, — и новая единица с тем же номером смешала бы своё с чужим.

**Счётчик, который не читается** (седьмое ревью). Строка `n: "seven"`, поправленная руками, бросала исключение, и в подсистеме не создавалась ни одна единица, пока кто-нибудь не починит строку. Теперь её читает общий читатель строк (`NEXT_IDS`, урок 8): она считается испорченной один раз, а следующий номер — на единицу больше **наибольшего** id под `<подсистема>/<строки>/`, включая помеченные удалёнными. Удалённые строки остаются метками (шаг 6), поэтому номер, выданный однажды, не выдаётся снова и тут. CAS пишет строку счётчика целиком. Числом считается то, что скажет `doors.numeric`, — о нём ниже, у `create`.

Ветвь `raise` — для подсистем, где идентификатор берётся из поля (`testsub`: `id: name`, единица — именованный счётчик): номер там не нужен, и вызов — ошибка программиста, а не пользователя.

## Шаг 3 — Создание

```python
    def create(self, fields: dict, uid=None, reserve=None) -> dict:
        self.spec.refuse(fields)
        self._refuse_labels(fields, ())
        if uid is not None:
            old = self.unit(uid)
            if old is not None:
                return old                                              # created by the attempt whose reply was lost: the row is the answer
        if self.spec.numeric:
            uid = self._next_id() if uid is None else self.spec.parse_id(uid)
        else:
            uid = str(fields.get(self.spec.id) or "")
            if not uid:
                raise Refused(f"a {self.spec.name} unit needs a {self.spec.id}")
            # A named unit's id comes VERBATIM from the operator's body, and from here it becomes three
            # things: the key `<sub>/<rows>/<id>`, the prefix an ACL is matched against, and a directory on
            # a resource's disk (`events.unit_dir`). So it is a name, not a path: no separators, and not a
            # relative one. `variables.safe_path` refuses the same shapes one layer down — this one is a
            # 400 to the person who typed it rather than a 500 from the store.
            if "/" in uid or uid in (".", ".."):
                raise Refused(f"a {self.spec.name} {self.spec.id} is a name, not a path: {uid!r}")
            # …and a name that goes into other text whole (the review's eighth pass, part 4, and its question about `|`,
            # `"` and the newline): a label value on `/metrics` (escaped there too, for the names already stored —
            # `console.label`), a `|`-joined field of a heartbeat (`closed`, `hits`), a log line. Refused here, the rule
            # the domain keeps for a user's name (`domain/grants.py`, `name_refused`): no `"`, no `|`, no control
            # character or line or paragraph separator (Unicode Cc, Zl, Zp).
            # …and a unit's name is in lists and sorted as a number (the ninth pass, sibling B of the product team): no
            # `,` — an assignment is its units joined by one — and no digit but ASCII 0–9 (`doors.unnamable`, `unit`).
            bad = unnamable(uid, unit=True)
            if bad:
                raise Refused(f"a {self.spec.name} {self.spec.id} may not hold {', '.join(repr(c) for c in bad)}: {uid!r}")
        if reserve is not None:
            reserve(uid)                                                # into the claim, before the row exists
        self.refuse_refs(uid, None, self.spec.new_row(uid, fields))  # what its fields point at, what is one per cluster
        if not self.spec.numeric:
            old, idx = self.vars.get(self.row_key(uid))
            if old and old.get("deleted") != "true":
                raise Refused(f"{self.spec.name} unit {uid} exists")
            # A NAME STAYS ITS UNIT'S (the review's fifth pass, major). A unit's name is also the name of what it left
            # behind — what its workers wrote under it — and readers find that by the name. Deleted as one unit's and
            # created again about another, the name handed the first one's history to whoever may view the second.
            # The tombstone keeps every field, the `fixed` ones with them: the name comes back with the same values,
            # and with others it is refused — whatever was written under it is still there, and nothing here can know
            # when the last of it is gone, so "reuse once it is empty" is not a rule this controller could keep.
            moved = self.spec.fixed_changed(old, fields) if old else None
            if moved:
                raise Refused(f"the name {uid} was {moved} {old[moved]}'s, and what was written under it still is: "
                              f"create {moved} {fields[moved]}'s under another name")
            if old:                                                 # a named unit deleted earlier comes back under its name:
                r = self.spec.new_row(uid, fields)                  # a fresh row, one revision on from the old one, by CAS on it
                r["revision"] = int(old.get("revision", 0)) + 1
                self.vars.put(self.row_key(uid), self._sealed(self.spec.items(r), uid), cas=idx)
                wrote(self.spec.name, uid)                          # for this process's readers that remember (`take_written`)
                self._derived(r, uid)
                return r
        r = self.spec.new_row(uid, fields)
        self.vars.put(self.row_key(uid), self._sealed(self.spec.items(r), uid), cas=0)
        wrote(self.spec.name, uid)
        self._derived(r, uid)
        return r
```

Отказы первыми (`_refuse_labels` — алфавит меток, урок 11, шаг 1), потом развилка по виду идентификатора.

**Числовой путь** прост: взять следующий номер, собрать запись, записать с `cas=0`. Последнее — важная мелочь: `cas=0` значит «создать, только если ключа нет» (урок 2). Ключ с только что выданным номером существовать не может, и всё же проверка стоит — как утверждение, а не как защита. Если она когда-нибудь сработает, значит, счётчик разошёлся с реальностью, и лучше узнать об этом через исключение, чем через затёртую строку.

**Именованный путь** начинается с трёх отказов: нет имени, имя — путь, имя с запретными символами. Второй стоит того, чтобы на нём остановиться.

Идентификатор здесь приходит **из тела POST как есть** — в отличие от числового, который выдаёт контроллер. И дальше эта строка становится тремя вещами сразу: ключом `<подсистема>/<строки>/<id>`, префиксом, по которому сверяется ACL, и **каталогом на диске ресурса** (`unit_dir`, урок 12). Поэтому имя единицы — это имя, а не путь: разделителей в нём быть не может.

Проверьте сами, чем кончится `{"name": "../../other/7"}` у `testsub` без этой строки. Ключ получится `testsub/counters/../../other/7` — и он **пройдёт** проверку прав, потому что честно начинается с `testsub/counters/`, а права консоли именно этот префикс и разрешают. Дальше всё зависит от того, нормализует ли кто-нибудь путь по дороге: в хранилище на файлах получится мусорная строка, в хранилище за сетью — запись не туда, а `unit_dir(root, "testsub", uid)` — это `os.path.join` без всякого кодирования — построит `<корень>/testsub/../../other/7`, то есть каталог вне дерева событий вообще.

Та же проверка стоит и слоем ниже, в `safe_path` (урок 2). Дублирование намеренное и разное по смыслу: здесь это **400 тому, кто это напечатал**, с внятным текстом; там — последний рубеж для любого, кто дошёл до хранилища другим путём.

**Имя не может держать `"`, `|` и управляющие символы** (восьмое ревью, часть 4, и его вопрос к автору). Имя единицы попадает целиком и в другой текст: значением метки на `/metrics`, полем heartbeat'а, склеенным через `|`, строкой лога. Единица с именем `7"x` давала строку метрики `…{unit="7"x"}`, которую формат Prometheus не читает, и Prometheus отвергал весь скрейп подсистемы — вместе со всеми её алертами. Теперь `create` отказывает такому имени словами: `doors.unnamable(uid)` возвращает найденные запретные символы — `"`, `|` и символы Unicode категорий Cc (управляющие, в том числе перевод строки), Zl и Zp (разделители строк и абзацев). Та же функция стоит на id запроса в `POST /requests` консоли (урок 15) и на имени строки таблицы, которую объявила спека (`tables.refusal_of_name`). Это то же правило, что домен М12 держит для имени пользователя и субъекта гранта (`grants.refuse_name`, `name_refused`). Имена, записанные до правила, по-прежнему лежат в хранилище, поэтому `/metrics` ещё и экранирует каждое значение метки (`console.label`, урок 15). Тесты: `test_lesson11_edge.py::test_a_units_name_holds_no_quote_no_bar_and_no_control_character`, `test_row_reader.py::test_a_name_with_a_quote_or_a_newline_is_escaped_on_every_metrics_page`.

**Имя единицы не может держать запятую и цифру, которая не ASCII** (девятое ревью: minor и находка команды продукта в своём коде). Назначение воркера — это его единицы, склеенные через `,` (`contract.Assignment`), и так же склеены списки единиц в heartbeat'ах. Единица с именем `1,9` читалась обратно как `1` и `9`: её воркер брал `9` — чужую единицу или ничего — и никогда не запускал `1,9`. Отдельно: `"7²".isdigit()` — истина, а `int("7²")` бросает исключение. Создание единицы с именем `7²` отвечало 201, и после этого ни один список единиц её подсистемы не получал ответа: список сортируется по `_unit_key`, а тот считал «одни цифры» числом. Теперь `doors.unnamable(uid, unit=True)` к прежним символам добавляет `,` и любую цифру, кроме ASCII 0–9 (верхние индексы, арабско-индийские, полноширинные — `isdigit` говорит «да» им всем). Id запроса — не имя единицы, его правило прежнее. Для имён, записанных до правила, есть `doors.numeric(name)` — число, только если это ASCII-цифры и столько, сколько берёт `int` (пять тысяч девяток бросают). Через него идут `_unit_key`, `_largest_id` и `slot_number` платформы — и каждый читатель подсистемы, которому «одни цифры» значат число. `units()` ловит всё, что бросает разбор (`PARSE_ERRORS`, и само чтение строки файлового хранилища, которая не JSON), а строку с именем, которое сегодня не создать, отдаёт как есть, но считает и называет один раз (`UNIT_NAMES`): её стоит создать заново под другим именем. Имя с запятой не пишется ни в одно назначение (`Assignment.to_items`, `assign_add`; таблица `UNLISTED`): такая единица не размещена, но и не разрезана на чужие имена. Тест: `test_console_gate.py::test_a_units_name_holds_no_comma_and_no_digit_but_ascii_and_a_stored_one_stops_no_list` — через API: пять имён отказаны, хранимые `7²` и `1,9` в списке, список отвечает, в назначение `1,9` не попадает.

Остальные строки листинга разобраны в других уроках: `uid` и `reserve` — повтор запроса с ключом идемпотентности, который создаёт под тем же id (урок 15); `_sealed` — запечатанные поля `*_secret` (урок 18); `wrote` — отметка для читателя в том же процессе, который помнит строки между своими ходами (`take_written`). Две строки разберём здесь, потому что обе — про то, что хуков у платформы нет: правило о строке **объявляет спека**, а контроллер читает объявление.

**`refuse_refs` — на что указывает строка и что одно на кластер.** Подсистеме бывает нужно сказать: «значение этого поля — имя строки вон той таблицы, и та строка должна согласовываться с моей» или «двух единиц с одним значением быть не может». Код подсистемы, вызванный отсюда, был бы хуком; вместо него — три слова в описании поля. Подсистема `bin` из `test_spec_declarations.py` (там она словарь Python, здесь — те же поля в YAML):

```yaml
unit:
  rows: items
  id: name
  fields:
    name:  {type: string, required: true}
    owner: {type: string}
    home:  {type: string, ref: bin/bays, must_match: {owner: owner}}
    tag:   {type: string, unique: true}
    addr:  {type: url, unique: canonical}
```

`ref: <подсистема>/<строки>` — значение называет строку `<подсистема>/<строки>/<значение>`; `must_match: {<их поле>: <моё поле>}` — если в той строке поле заполнено, моё должно совпадать; строка, которая не разбирается, — не то, на что можно указать: отказ. Строки, которой нет, никто не спрашивает: необъявленное ничего не связывает. `unique: true` — ни у какой другой единицы того же значения; `unique: canonical` (только у `url`) — и того же адреса в другом написании (`canonical_url`: регистр схемы и хоста, процент-кодирование, точки в пути — RFC 3986, §6.2.2, и ничего, что значит сама схема). Всё это спрашивается, только когда значение для строки новое — при создании и при правке, которая его меняет, — и вызывает это и `create`, и `update`: каждый писатель строк проходит здесь. Тест: `test_spec_declarations.py::test_a_row_points_only_at_what_agrees_with_it_and_a_unique_value_is_one_units` — `home b1 is owner ann's`, `bin a has that tag already`. В М10B этими словами запись не ложится на карту памяти в чужой камере (`home: {ref: rec/volumes, must_match: {cam: cam}}`) — но это слова из YAML подсистемы, а контроллер знает только `ref` и `must_match`.

**`fixed` и надгробие — имя остаётся за своей единицей** (пятое ревью). Под именем удалённой единицы лежит то, что успели написать её воркеры, и читатели находят это по имени. Если имя вернуть с другим значением поля, по которому единица **о** другой единице (`about`, урок 9), история первой досталась бы тому, кто вправе смотреть вторую. Поэтому надгробие хранит все поля, а поле, помеченное в спеке `fixed: true`, сравнивается (`spec.fixed_changed`): имя возвращается с тем же значением и отказывается с другим. «Отдать имя, когда под ним всё опустеет» — не правило, которое этот контроллер мог бы держать: он не знает, когда опустеет. Тест на `testsub` и придуманной рядом подсистеме `tally`, единица которой **о** счётчике (`about: {sub: testsub, field: counter}`, `counter: {type: string, required: true, fixed: true}`): `test_units_about.py::test_a_fixed_field_does_not_change_and_a_deleted_name_comes_back_only_with_the_same_value` — `t1` про `c1` удалена, создать `t1` про `c2` нельзя (`the name t1 was counter c1's`), про `c1` — можно, и ревизия продолжает старую.

Остальная длина этой ветки — из-за одного случая. Единица опознаётся своим именем: `testsub/counters/c1` — это счётчик `c1`. Оператор удалил его (строка помечена удалённой), потом через час создал снова. Имя то же самое — другого быть не может: по нему находят и то, что под ним осталось.

Что делать? Отказать («уже существует») — неверно: удалённая единица не существует. Записать заново с `cas=0` — невозможно: ключ-то есть, помеченный. Стереть и создать — потеря истории: ревизия начнётся с единицы, и любой, кто помнил ревизию 5, увидит 1 и решит, что строка **откатилась**.

Выбрано четвёртое: **новая запись, ревизия на одну больше старой, по CAS на прочитанный индекс.** Строка вернулась к жизни как ревизия 6. Наблюдатели, сравнивающие ревизии через `>=`, ничего не заметят — а именно так их сравнивает цикл сверки.

`cas=idx` здесь обязателен: между чтением `old` и записью кто-то мог создать ту же единицу заново.

## Шаг 4 — Правка


Вся правка — внутри мутатора, то есть на данных, которые будут записаны. Прочитать строку, наложить присланные поля, проверить то, что зависит от старого и нового вместе, бумнуть ревизию, вернуть элементы.

`KeyError` для отсутствующей и для удалённой — одно и то же: удалённая единица не существует. Консоль превратит это в 404.

Три проверки в мутаторе, а не до него, — потому что им нужна строка, какой она **была**. **Поле `fixed` не меняется** (четвёртое ревью): единица, которая **о** другой, судится по той, которую её строка называет сейчас, и правка, сменившая поле, увезла бы к другой единице всю историю первой; то же значение — не перемена: страница присылает форму целиком. **Секрет привязан к адресу** (`bound_to`, уроки 9 и 18): адрес поменяли, а нового секрета не прислали — старый ушёл бы на хост, который называет новый адрес; отказ словами. И **`refuse_refs`** — с прошлой и новой строкой, чтобы спрашивать только новое (шаг 3). Строкой выше мутатора — правило продукта: секрет, присланный пустым или `null`, не стирает сохранённый, а оставляет его (страница, где поле набрали и очистили, присылает `""`).

Комментарий про М9 стоит развернуть. В М9 конфигурация жила в Postgres, и ревизию бумал **триггер базы** — `BEFORE UPDATE`, который сравнивал операторские колонки и увеличивал `revision`, если хоть одна изменилась. Триггер был хорош тем, что его нельзя обойти: кто бы ни правил строку, ревизия вырастет.

Здесь триггеров нет, и гарантия другая: правку строки может сделать **только** этот метод, потому что консоль — единственная роль, которой права хранилища разрешают этот префикс (`acl_console`, урок 9), а консоль ходит сюда. Гарантия слабее (можно написать код в обход), но проверяема: обход — это строка кода, которая ищется поиском.

Разница есть и в поведении. Триггер М9 сравнивал значения и не бумал ревизию, если правка ничего не изменила. Здесь ревизия растёт **всегда**, даже если оператор прислал то же самое. Дешевле: лишняя ревизия стоит одного перезапуска конвейера (цикл сверки увидит `revision > observed_revision`), и это заметная цена — но сравнение всех полей ради её избегания даёт больше кода, чем экономит. Курс выбрал простоту; в проектной записке это записано как принятая цена.

Последние две строки — производные строки, и пересчитываются они **только если правка задела поле-источник**. Проверка выглядит запутанно (`any(f in fields for d in derived for f in d.items.values())`), а означает простое: «есть ли среди присланных полей хоть одно, из которого делается производная строка».

## Шаг 5 — Производные строки

```python
    def _derived(self, row: dict | None, uid, deleted: bool = False) -> None:
        for d in self.spec.derived:
            path = self.sub.config(*d.row.replace("{id}", str(uid)).split("/"))
            if deleted:
                if d.on_delete is not None:
                    self.write(path, lambda it, v=d.on_delete: {k: str(x) for k, x in v.items()})
                continue
            # A field left to inherit gives no item: the derived row then says nothing, and its reader goes on
            # down its own chain — the resource's retention falls back to the subsystem's, then to a year.
            want = {k: self.spec.fields[f].to_item(row[f]) for k, f in d.items.items() if row.get(f) is not None}
            self.write(path, lambda it, want=want: None if it == want else want)
```

Путь собирается подстановкой `{id}` и разрезанием по слэшу — `retention/{id}` у подсистемы `counter` для единицы 7 дал бы `counter/retention/7`. Поле, оставленное наследовать (`inherit`, урок 9), элемента не даёт: производная строка тогда о нём молчит, и её читатель идёт дальше по своей цепочке.

**При удалении** пишется `on_delete` — есть производная строка или нет. Правило «писать, только если ключ существует: создавать строку для единицы, которой уже нет, незачем» выглядит бережливым и неверно для поля, которое **наследуют** (`inherit`, урок 9; М12, урок 12): у такой единицы производной строки нет вовсе, удаление ничего бы не написало, и то, чем строка управляет, жило бы дальше по умолчанию подсистемы — удалённая единица с унаследованным сроком хранила бы свои события ещё год (найдено при разборе обратной связи, BO). Производная строка без `on_delete` при удалении не трогается, и это тоже решение подсистемы: в М10B так устроен срок тревог VMS — `vms/alarms_retention/<id>` переживает камеру, и тревоги доживают своё.

**При создании и правке** — самая полезная строка метода:

```python
            self.write(path, lambda it, want=want: None if it == want else want)
```

Мутатор сравнивает то, что уже лежит, с тем, что нужно, и возвращает `None`, если они совпали. То есть **записи не будет, если ничего не изменилось.** Без этого каждая правка единицы переписывала бы её производную строку тем же значением: лишний индекс, лишняя запись, а в М11 — лишняя запись в raft.

`lambda it, want=want:` — связывание через аргумент по умолчанию, обычная защита от позднего связывания замыкания в цикле. Без неё все лямбды в цикле увидели бы последнее `want`.

## Шаг 6 — Удаление в два приёма

```python
    def delete(self, uid) -> None:
        """The operator's half: the row is marked. Its placement is the controller's
        half, taken back on the next pass (`unplace_deleted`) — the console's writer
        (`acl_console`) cannot touch an assignment, and does not need to."""
        self.write(self.row_key(uid), lambda it: {**it, "deleted": "true"} if it else None)
        self._derived(None, uid, deleted=True)
```

Половина оператора: пометить строку и обновить производные. Ключ **не удаляется** — ставится флаг. Почему: потому что размещение ещё живо, и воркер, читающий свои единицы, должен отличать «строка исчезла» (ошибка чтения, сеть) от «единицу удалили» (перестать её вести). Флаг — это явное «удалена», а отсутствие ключа — двусмысленность.

```python
    def unplace_deleted(self) -> list:
        """The controller's half of a delete: every placement whose unit is gone
        loses its assignment and its row says so. Runs first in every pass."""
        gone = []
        for p in self.vars.list(self.sub.config("placement") + "/"):
            uid = self._placed_id(p)
            it = self._placement_items(p)
            if uid is None or not it or not it.get("worker") or self.parsed_unit(uid) is not None:
                continue                                  # a row that does not parse EXISTS: it is not unplaced as deleted
            self.assign_remove(it["worker"], str(uid))
            self.write(p, lambda it: {"worker": "", "reason": "deleted", "at": self.wall(), "rev": _next_rev(it)})
            gone.append(uid)
        return gone
```

Половина контроллера: пройти по всем размещениям, найти те, чьей единицы больше нет, убрать из назначения и записать в строку размещения, что произошло.

Четыре условия пропуска в одной строке: имя строки размещения не годится в id ни одной единицы (`_placed_id`: чужая строка в `placement/` говорится в логе один раз и пропускается, а не роняет проход), строки нет или она не читается (`_placement_items`), воркер пустой (уже забрали), единица на месте. «На месте» спрашивает `parsed_unit`, а не `unit`: строка единицы, которая не разбирается, **существует** — её никто не удалял, и снимать её размещение как удалённой нельзя (урок 11, шаг 9). Остаются только настоящие сироты. `_next_rev` — следующий `rev`, и `rev`, который не разбирается, считается с нуля: слово в нём не должно мешать записи, которая строку чинит.

Порядок двух действий — **сначала назначение, потом строка размещения** — важен. Если контроллер упадёт между ними, останется размещение, указывающее на воркера, у которого единицы уже нет; следующий проход увидит сироту снова и доделает. Обратный порядок оставил бы единицу в назначении воркера без строки размещения — и её никто бы не нашёл, потому что проход идёт по размещениям.

Причина пишется словом `"deleted"`. Строка размещения не удаляется, а обнуляется, и в ней остаётся история: кто держал, когда отпустили, почему. Оператор, спросивший «а где единица 7», получит внятный ответ вместо пустоты.

И docstring называет главное: **писатель консоли не может тронуть назначение — и ему это не нужно.** Разделение не обходится, а именно обслуживается: каждая половина делается тем, у кого есть право.

Что если вторая половина опоздает? Контроллер стоит — и размещение живёт. Воркер при этом единицу **уже не ведёт**: в своём `reconcile_once` воркер подсистемы читает строки единиц из назначения и пропускает помеченные удалёнными. Сам рантайм воркера платформы (`w2cplatform/worker.py`, урок 8, шаг «Рантайм воркера») строк не читает — что такое строка единицы, знает подсистема; он даёт ей только `row_garbled` и `row_parsed`, чтобы строка, которая не разбирается, говорилась в логе один раз. Так устроен и воркер `counter` (урок 11, шаг 22). То есть видимый эффект наступает сразу, а уборка — когда контроллер вернётся. Это ровно то, чего добивается вся архитектура: контроллер не нужен для того, чтобы система работала правильно, только для того, чтобы она была прибрана.


Помеченные удалёнными не возвращаются никогда — для всех читателей выше они уже не существуют. Строка, которая не разбирается — поле поправили руками, другая сборка записала другую раскладку, — это **одна** единица, которую никто не обслуживает, а не конец прохода каждого вызывающего (второе ревью, M7): она пропускается, считается в `rows_garbled` (отчёт прохода и `<подсистема>_rows_garbled` на `/metrics`, урок 11) и говорится в логе один раз. Для цикла по уже размещённым единицам есть `parsed_unit(uid)`: строка, которая не разбирается, там не исключение, а метка `GARBLED_ROW` — «есть, но не читается».

**`units()` зовут много раз за проход, а читается он один раз.** Ничего не храня между проходами, контроллер не хранил ничего и внутри прохода: каждый шаг, отчёт и снимок заново перечитывали все строки и размещения (заход по масштабу после восьмого ревью). Теперь проход идёт внутри `one_pass` (урок 11, шаг 9): `unit`, `units` и `placement` читают ключ из хранилища первый раз, а дальше в том же проходе — из его памяти, и запись эту память о своём ключе сбрасывает. Вне прохода — у дверей консоли — всё как в листинге выше.

Сортировка — через `_unit_key`:

```python
def _unit_key(u: str):
    n = numeric(u)
    return (0, n) if n is not None else (1, str(u))
```

Числовые идентификаторы сортируются как числа (`1, 2, 10`, а не `1, 10, 2`), остальные — как строки, и числовые идут первыми. Одна функция на курс, потому что смешанных подсистем не бывает, но обе ветви нужны: `counter` числовая, `testsub` именованная. Число здесь — то, что скажет `doors.numeric`, а не `int(u) if u.isdigit()`: имя `7²` для `isdigit` — «одни цифры», а `int` на нём бросает, и падал бы каждый список его подсистемы (девятое ревью; правило имени — выше, у `create`).

```python
    def placement(self, uid) -> Placement | None:
        key = self.sub.config("placement", str(uid))
        it = self._placement_items(key)
        if not it or not it.get("worker"):
            return None
        return self._placement(uid, it)

    def load(self, worker: str) -> int:
        return len(self.assignment(worker).units)
```

Размещение с пустым воркером — это «не размещена» (после `unplace_deleted` или до первого прохода), и наружу это `None`, а не объект с пустым полем.

Решение в строке размещения — это `worker`; `reason`, `at` и `rev` — для человека (шестое ревью, продолжение). Строку одной единицы читают, пока размещают другие, и `at` со словом внутри останавливал их всех. Поэтому `_placement` читает решение как есть, а то, что рядом не разбирается, считает нулём и говорит один раз. Строка, которую хранилище держит и не может прочесть (`Garbled`), читается как «нигде не размещена» (`_placement_items`, одиннадцатое ревью): следующая запись контроллера заменит её целиком, и единица будет размещена снова.

`load` — сколько единиц несёт воркер. Одна строка, и вся она — про урок 11: **загрузка считается по назначению, а не по тому, что воркер о себе сказал.** Контроллер размещает по своему решению, а не по докладу; иначе воркер, отставший на проход, выглядел бы свободнее, чем он есть, и получил бы ещё работы.

**Результат:** первая половина `SpecController` — создание, правка, удаление, чтение; и объяснение своими словами, почему удаление делается в два приёма и что видно оператору, если вторая половина опаздывает.

| Симптом | Скорее всего |
|---|---|
| Ревизия «откатилась» после возврата удалённой единицы | Именованный путь создаёт запись с `revision = 1` вместо `старая + 1`. Наблюдатели с `>=` решат, что строка помолодела. |
| Каждая правка переписывает производную строку | Потерян мутатор `None if it == want else want`. В М11 это лишняя запись в raft на каждое нажатие. |
| Все производные строки получили одно значение | Позднее связывание в лямбде внутри цикла: нужен `lambda it, want=want:`. |
| Удалённая единица осталась в назначении навсегда | `unplace_deleted` не вызывается первым в проходе — или контроллер не запускался с момента удаления. Воркер её при этом уже не ведёт. |
| Размещение потеряно, единица «нигде» | Порядок в `unplace_deleted` обратный: сначала обнулили строку, потом упали. Сироту больше не по чему найти. |
| Размещение единицы снято, хотя её никто не удалял | `unplace_deleted` спрашивает `unit`, а не `parsed_unit`: строка, которая не разбирается, прочиталась как «нет единицы». |
| Удалённое имя вернулось о другой единице | Поле, по которому единица **о** другой, не помечено `fixed: true` — спека с `about` без него и не загрузится; или надгробие сравнивает не все `fixed`-поля. |
| Идентификаторы переиспользуются | Счётчик сбрасывается или вычисляется как «максимум + 1» по живым строкам, без помеченных удалёнными. На диске остались данные старой единицы. |
| `1, 10, 2` в списке на странице | Сортировка по строке. `_unit_key` для того и есть. |
| Ревизия растёт от правки, ничего не изменившей | Так и есть, цена принята. Триггер М9 сравнивал значения; здесь сравнения нет, и лишняя ревизия стоит одного перезапуска. |

## Итог

- Контроллер — это спецификация плюс `write`: ни одна операция не читает ключ дважды, потому что решение принимается внутри мутатора.
- Идентификаторы числовые и последовательные, потому что попадают в пути, URL и разговор людей; UUID не решает ни одной здешней задачи.
- Номера не переиспользуются: на диске остаются данные прежней единицы. Имя удалённой единицы возвращается только с теми же значениями `fixed`-полей.
- Что строка может называть и что одно на кластер, объявляет спека (`ref`, `must_match`, `unique`, `fixed`); контроллер читает объявление и не вызывает ничьего кода.
- Именованная единица, удалённая и созданная снова, продолжает нумерацию ревизий — иначе наблюдатели с `>=` увидят откат.
- Ревизию бумает контроллер. В М9 это делал триггер базы; гарантия слабее, но обход находится поиском.
- Производные строки пишутся, только если изменились: мутатор, вернувший `None`, экономит запись.
- Удаление — две половины у двух владельцев: консоль метит строку, контроллер забирает размещение на следующем проходе.
- Пока вторая половина не пришла, система уже ведёт себя правильно: воркер пропускает помеченные строки. Контроллер нужен для порядка, не для корректности.
- Загрузка воркера считается по назначению, а не по его докладу.

## Упражнения

1. Замените счётчик на UUID. Пройдите по курсу и найдите три места, где это ухудшает жизнь человека, а не программы.
2. Уберите `cas=0` из числового создания. Придумайте состояние хранилища, в котором это молча теряет строку.
3. Сделайте возврат удалённой именованной единицы через «стереть и создать». Напишите, что увидит цикл сверки воркера, помнящий ревизию 5.
4. Верните сравнение значений перед ростом ревизии (как триггер М9). Сколько строк это добавило и сколько перезапусков конвейеров за сутки сэкономило при десяти правках в день?
5. Поменяйте местами два действия в `unplace_deleted` и опишите состояние после падения между ними. Как его теперь чинить?
6. Удалите строку вместо пометки. Что теперь видит воркер, у которого пропала сеть на две секунды?
7. Сделайте `load` считающим по heartbeat'у воркера вместо назначения. Опишите, что произойдёт с воркером, отставшим на один проход, при размещении десяти новых единиц.
8. Уберите `fixed: true` у поля `counter` подсистемы `tally` из `test_units_about.py` и загрузите спеку. Почему загрузчик отказывает сразу, а не принимает файл и не ждёт первой правки?
