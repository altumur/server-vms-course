# Урок 16 — Модуль консоли и платформенная страница

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** `w2cplatform/console.js` — модуль консоли платформы, из которого строится любая страница: дерево единиц, общая форма из типов полей, серверы и воркеры, домен, права, журнал, вход, `api()` с одним ключом идемпотентности на отправку и вызовы, которыми страница подсистемы добавляет своё; `console.css` — его облик; `w2cplatform/console.html` — платформенная страница в двенадцать строк: модуль, стиль и `mount`. И три функции консоли, которые их отдают: `page_of`, `send_module`, `page_csp`.
**Время:** ~100 минут.

## Зачем этот урок

Единственный урок модуля, в котором почти нет Python. Он здесь не для полноты: экран — **последняя проверка того, что платформа действительно ничего не знает о подсистеме**.

Пока всё было на сервере, это утверждение держалось на тестах границы. Но экран — то место, где абстракции ломаются первыми: достаточно одного `if (subsystem === 'vms')`, одной колонки «Адрес камеры», одного захардкоженного `/cameras` — и граница, которую пятнадцать уроков держали, пробита в разметке.

Поэтому платформа отдаёт не страницу, а **модуль** (ADR 0005). Модуль строит из `/spec` и платформенных дверей всё, что у консоли общее для любой подсистемы: дерево единиц, карточку единицы, серверы, домен, права, журнал, вход. Страница подсистемы — **оболочка**: она подключает модуль и добавляет своё вызовами в его библиотеку. У VMS это видео, архив, тома, сценарии (М10B, [урок 12](../М10B_ServerVMS/12-the-vms-console.md)). У подсистемы без своей страницы — счётчика из урока 11, `testsub` — оболочка пустая, и это платформенная страница.

Граница здесь держится тремя проверками, и все буквальные. Исходник модуля проверяется словарём: в нём нет ни `vms`, ни `camera`, ни `архив`, ни `whep` (`module-contract.test.js`, и тот же словарь у `tests/test_boundary.py`, который читает и `.js`, и `.css`). Каждый запрос модуля в jsdom сверяется с закрытым списком маршрутов. А байтов модуль не грузит вовсе: дверь держателя он только отдаёт странице.

Второе, что показывает урок, — сколько стоит такой интерфейс. Ни сборки, ни фреймворка, ни `node_modules` в поставке, ни шага компиляции: три файла, которые консоль отдаёт как есть. Это не аскеза: коробка с камерами живёт годами, и всё, что требует пересборки, однажды не пересоберётся.

> **Проверка без железа.** Модуль проверяется в jsdom с поддельным API (`Source/tests/console/`: `boot.js` и `module-*.test.js`, `platform-page.test.js`); их гоняет `tests/run.py`, а без node или jsdom итоговая строка пишет пропуск с причиной (`npm install` в `tests/console` один раз). Как консоль отдаёт страницу и модуль, проверяет `tests/test_console_page.py` на настоящем порту.

## Шаг 1 — Три файла и один `mount`

Платформенная страница целиком:

```html
<!doctype html>
<!-- The platform's own console page: the platform's console module (/platform/console.js) and nothing else. … -->
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>console</title>
<link rel="stylesheet" href="/platform/console.css?v=1">
<div id="app"></div>
<script src="/platform/console.js?v=1"></script>
<script>window.platformConsole = PlatformConsole.mount(document.getElementById("app"));</script>
```

Модуль, его облик и `mount` — и больше ничего: ни своего скрипта, ни слов, ни маршрутов. Тест так и написан: два `<script>`, первый — модуль с `?v=1`, второй — ровно эта строка `mount`, в разметке ни одного `on…=` и ни одного `fetch(` (`test_the_platforms_page_is_the_console_module_and_its_mount_and_nothing_else`).

Какую страницу консоль отдаёт на `/`, решает файл, а не опция:

```python
PAGE = os.path.join(os.path.dirname(os.path.abspath(__file__)), "console.html")
MODULE = os.path.join(os.path.dirname(os.path.abspath(__file__)), "console.js")
MODULE_CSS = os.path.join(os.path.dirname(os.path.abspath(__file__)), "console.css")
MODULE_VERSION = "1"                   # the contract's version (КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md §3): `?v=` names it
SHELL = "{}.shell.html"

def page_of(spec) -> str:
    from . import catalog
    f = catalog.file_of(spec.name)
    own = os.path.join(os.path.dirname(f), SHELL.format(spec.name)) if f else None
    return own if own and os.path.isfile(own) else PAGE
```

Своя страница подсистемы — `<sub>.shell.html` рядом с файлом её спеки: у VMS `vms/vms.shell.html` рядом с `vms.subsystem.yaml`. Нет такого файла — платформенная. Спека, собранная в коде (`from_dict`), файла не имеет, а значит, и своей страницы. Страница чужого имени рядом со спекой — `shell.html`, `testsub2.shell.html` — не её (`test_a_subsystem_with_a_page_beside_its_spec_is_shown_with_it_and_one_without_with_the_platforms`).

**Страница одна на процесс, и она корня** (контракт, §1). `Mount` из урока 15 ставит каждой консоли `serves_page = console is self.root`, и диспетчер отвечает так:

```python
            if path in ("/", "/index.html"):
                if not self.serves_page:
                    return h._send(404, {"detail": f"{spec.name} is mounted: the page is the console root's",
                                         "error": "not found"})
                page = page_of(spec)
                return send_file(h, page, "text/html; charset=utf-8", headers=(("Content-Security-Policy", page_csp(page)),))
            if path in MODULE_ROUTES:
                return send_module(h, path, q)
```

Подсистема из `/mounts` своей страницы не отдаёт, даже если файл её имени лежит рядом: `/<sub>/` — 404. Её единицы показывает модуль на странице корня. Корень выбирает развёртывание (`CONSOLE_ROOT`), а не код (`test_only_the_consoles_root_serves_a_page_and_a_mounted_subsystem_none`).

Модуль и его облик отдаются по версии контракта:

```python
def send_module(h, path: str, q: dict) -> None:
    if q.get("v") not in (None, MODULE_VERSION):
        return h._send(404, {"detail": f"no console module of version {q['v'][:20]}; this platform serves {MODULE_VERSION}",
                             "error": "no such version"})
    raw = open(MODULE if path.endswith(".js") else MODULE_CSS, "rb").read()
```

`?v=1` — версия, которую страница ждёт. Другая — 404 со словами, какую платформа отдаёт. Старых версий платформа не держит (ADR 0003): несовместимая правка контракта — новый номер, и страница, написанная под старый, получает понятный отказ, а не модуль, который ведёт себя иначе.

Обе двери открыты: `MODULE_ROUTES` входят в `OPEN_ROUTES` вместе с `/`, `/metrics`, `/healthz`, `/session` и `/session/break-glass`. Причина простая: окно входа рисует сам модуль. Закрой его за входом — и человеку без сессии нечем было бы войти (`test_the_console_module_and_its_look_are_served_by_their_version_to_anybody`).

## Шаг 2 — Одна копия на курс и продукт

Модуль — общий код курса и продукта (контракт, §11, п. 6: «модуль переносится как есть»). Не «похожий», а тот же файл:

```python
FILES = ("console.js", "console.css", "console.html")
PRODUCT = "vmsworker/w2cplatform/"                      # on the product's `main`, relative to its root
DEBT = os.path.join(SOURCE, "tests", "testdata", "console_module_debt.txt")
```

`test_the_course_copy_of_the_console_module_is_the_products_but_for_the_debt` сравнивает три файла курса с файлами продукта на его `main` построчно. Разница допустима только в долге — `testdata/console_module_debt.txt`, строка на строку диффа: файл, знак, `sha1` строки, текст. Долг только сокращается: разница, которой в нём нет, — падение, а строка долга, которая перестала быть правдой, — тоже падение (`W2C_CONSOLE_SHRINK=1` переписывает файл без неё и никогда ничего не добавляет). Сегодня в долге ни одной строки: продукт взял всё, в чём курс шёл первым. Такие места помечены в исходнике `[course leads]` — например, группы из общих настроек домена (шаг 5).

Без продукта рядом с курсом тест пропускается: курс собирается и один.

Почему так строго. Две копии одного модуля, которые «примерно совпадают», через месяц расходятся в ключе идемпотентности, в правиле `may`, в экранировании — и каждое расхождение выглядит как ошибка в одном месте, хотя это ошибка в двух. Одна копия с долгом, который виден построчно, превращает «примерно» в число.

## Шаг 3 — Что модуль знает: спеки и платформенные двери

```js
    async function loadSpecs() {
      const subs = [];
      const rootSpec = await getJSON("/spec");
      subs.push({ name: rootSpec.name, base: "", spec: rootSpec });
      try {
        const m = await getJSON("/mounts");
        for (const [n, spec] of Object.entries(m.mounts || {})) if (spec && spec.rows) subs.push({ name: spec.name || n, base: "/" + n, spec });
      } catch (e) { /* one console, one spec */ }
      const want = opts.subsystems;
      st.subs = Array.isArray(want) ? subs.filter(s => want.includes(s.name)) : subs;
    }
```

Первая функция, и она задаёт всю страницу. Корень — `/spec`, остальные — из `/mounts`, каждая со своей базой пути: единицы корня — `/<rows>`, единицы смонтированной — `/<sub>/<rows>`. `opts.subsystems` сужает список: страница VMS показывает `["vms", "rec", "live"]`, остальные подсистемы консоли в её дерево не попадают.

**Зависимые подсистемы вкладываются сами.** Спека может сказать `about: {sub, field}` — её единицы про единицу другой подсистемы (урок 15, шаг 3):

```js
    function childrenOf(sub, row) {
      const out = [];
      for (const s of st.subs) {
        const a = aboutOf(s); if (!a || a.sub !== sub.name) continue;
        for (const u of st.units[s.name] || []) if (String(u[a.field]) === String(row.id)) out.push({ sub: s, row: u });
      }
      return out;
    }
```

Модуль не знает, что записи живут под камерами: это знание одно и лежит в спеке. Подсистема без `about` получает своё дерево.

**Слова — из спеки, данными.** Как называется единица, как подписаны поля, какие у них подсказки, как читается вид события — всё это раздел `display:` спеки:

```js
    const display = sub => sub.spec.display || {};   // what the spec calls things
    const unitWord = (sub, many) => { const d = display(sub); return (many ? d.units : d.unit) || (many ? sub.spec.rows : W.unit); };
    const kindWord = e => { const s = st.subs.find(x => x.name === e.subsystem); const k = s && display(s).kinds; return (k && k[e.kind]) || W.kinds[e.kind] || e.kind; };
```

Без `display` модуль пишет «единица», имя поля и вид события как есть. Свои слова у модуля тоже есть — `WORDS.en` и `WORDS.ru`, по одному словарю на язык (`opts.lang`), — но это слова платформы: сервер, воркер, слот, аренда, домен. Предметных среди них нет.

`display` закрыт по разделам, как всё в спеке (ADR 0012):

```python
DISPLAY_KEYS = ("unit", "units", "units_count", "section", "general", "fields", "field_help", "options", "form", "events",
                "kinds", "actions", "keys", "tree")
```

Раздел, которого нет в списке, — спека не грузится. Внутри раздела слова свободны, и проверяется одно: слово для поля называет поле, которое есть (`_card_words`). Логики, условий и маршрутов в `display` нет: это словарь. Отсюда свойство, ради которого так и сделано, — новое слово страницы схему не трогает.

**Чего модуль не делает** (контракт, §2). Он не называет подсистем. `live` — правило по токену: как состояние это платформенное слово (`live` и `silent` в `/servers`, гейджи `*_live`), запрещено оно только как имя подсистемы живого видео — `live_url`, `/live/`, `LIVE_…`. Он не ходит за пределы своих маршрутов; тест перехватывает `fetch` и сверяет каждый путь:

```js
const allowed=/^\/(spec|mounts|session|servers(\/.*)?|policy|drain|schema|unplaceable|where\/.*|events|marks|metrics|things(\/.*)?|sub\/(spec|parts(\/.*)?|unplaceable|where\/.*)|domain(\/.*)?)$/;
```

(`things` и `sub/parts` — строки и подсистема фиктивной спеки теста.) И он не грузит байты:

```js
    C.where = async ref => {
      const u = parseUnit(ref); if (!u) return null;
      try { const w = await getJSON(u.sub.base + "/where/" + encodeURIComponent(u.id)); return { worker: w.worker, server: w.server, door: w.door || null, reason: w.reason }; }
      catch (e) { return null; }
    };
```

Где единица и какая дверь у её держателя — модуль знает (урок 15, шаг 12). Идёт туда страница, если ей есть зачем: ни таймлайна, ни кусков, ни живого потока в модуле нет (ADR 0015).

## Шаг 4 — Наблюдаемое поверх настроенного

```js
    async function load() {
      for (const sub of st.subs) {
        try {
          const d = await getJSON(sub.base + "/" + sub.spec.rows);
          if (sub === st.subs[0]) st.loadErr = null;
          const by = {};
          for (const c of d.configured || []) by[c.id] = { ...c, phase: "silent", worker_state: "stale" };
          for (const r of d.rows || []) by[r.id] = { ...by[r.id], worker_state: undefined, ...r };   // heard of: its own word on staleness
```

Три строки, в которых лежит вся модель консоли.

Начинаем с **настроенного** — строк из хранилища (урок 10). Каждой сразу приписываем `phase: silent` и `worker_state: stale`: по умолчанию мы ничего о единице не наблюдаем.

Потом накладываем **наблюдаемое** — модель чтения из heartbeat'ов (урок 11). Строка говорит, что должно быть; heartbeat — что есть; на экране побеждает второе. `worker_state: undefined` перед `...r` — чтобы о свежести говорил сам heartbeat, а не умолчание, оставшееся от строки.

Отсюда три состояния, различимые с одного взгляда:

| Настроено | Наблюдается | Что видит оператор |
|---|---|---|
| да | да | обычная строка, значок по фазе |
| да | нет | «не размещена» или «воркер молчит» |
| нет | да | строка ещё есть, но её уже удалили; исчезнет на следующем проходе |

Третий случай — самый поучительный: удалённая единица, чей воркер ещё не дошёл до следующего цикла. Если бы модуль брал только `rows`, оператор решил бы, что удаление не сработало.

Дальше в том же `load` — `/servers`, `/unplaceable` каждой подсистемы, `/drain`, `/schema`, `/domain`, гейджи с `/metrics`. Гейджи модуль читает только те, что названы в спеке (`running_gauge`, `workers_gauge` в `/spec`), без зашитых суффиксов: счётчики в шапке — «12 камер», «3 воркера» — приходят из чисел, имена которых подсистема написала сама.

**Те же данные — та же картинка:**

```js
      const fp = JSON.stringify([st.units, st.servers, st.policy, st.dom, st.alarms, st.held, st.drain, st.unplaceable, st.schema, st.loadErr, st.shared]);   // [course leads] st.shared
      const same = fp === st.fp; st.fp = fp;
      if (!same) { const t = $(".pc-tree"), top = t ? t.scrollTop : 0; paintTree(); if (t) t.scrollTop = top; }
      if (!same || pageOwnsCard()) refreshMain();
```

Опрос раз в пять секунд по умолчанию (`poll_s`; в меню пользователя — 5, 15 секунд или вручную). Пустой опрос не трогает ни дерево, ни карточку: ни мерцания, ни сброшенной прокрутки, ни потерянного наведения. А когда данные новые, `refreshMain` всё равно не перерисовывает карточку **под руками человека**: не пока поле в ней в фокусе или отличается от того, что показала строка, не пока открыт диалог, и не пока вкладка страницы говорит `busy()` — у VMS это идущий просмотр (`module-poll.test.js`, `module-view.test.js`).

Никаких веб-сокетов, никакого SSE. Опрос проще, переживает разрыв сети без кода переподключения и на десятке камер стоит несколько запросов в секунду. Если единиц станут тысячи — это первое место, где придётся передумать.

**Разделы и две раскладки.** Лента модуля — три раздела: единицы, права, журнал (`opts.sections`, по умолчанию `["units", "access", "journal"]`; подпись первого — `display.section` спеки корня). Единицы, серверы и домен — один раздел и две раскладки одной панели:

```js
    const SECTIONS = { units: W.hwSection, access: W.access, journal: W.journal };
    const LAYOUT_OF = { units: "units", servers: "units", domain: "units" };   // what the rail shows as on
```

«По группам» — дерево единиц: группы по `display.tree.group_by`, зависимые подсистемы под своими единицами, поиск по имени, id и полям, избранное по `ref` (звезда на карточке; хранится в этом браузере). «По серверам» — домен, под ним серверы, под ними воркеры. Карточка сервера — его ресурс и место на диске, метки и откуда они (консоль, узел или «строка не читается»), таблицы подсистемы из `servers.show`, вывод из эксплуатации и списание; карточка воркера — слот, аренда, зависание, «жив ли — неизвестно», конфликт имени, его единицы. Всё это — платформенные двери и слова платформы (уроки 7, 11, 17; урок 15, шаг 10): ни одна подсистема их не повторяет. «Права» — люди домена, гранты по кластерам, аварийный пароль; «Журнал» — события всех подсистем, виды словами из `display.kinds` каждой.

## Шаг 5 — Общая форма из типов

Карточка единицы — общая форма модуля. Она строится из `/spec` по типам полей и обязана уметь всё, что из типов следует (контракт, §9):

```js
    function fieldInput(sub, f, row) {
```

По одному правилу на тип, и ни одного имени поля подсистемы:

- `bool` — переключатель, и у существующей единицы он пишется сразу, без «Сохранить»: выключить единицу хочется одним движением;
- секрет (`*_secret`, урок 18) — поле пароля, всегда пустое; подсказка говорит «задан» или «не задан», а маска `***` в поле не попадает никогда;
- `list` — строка через запятую; поле, по которому группирует дерево (`display.tree.group_by`), — блоком групп; поле `labels` подсказывает значения из меток серверов, потому что метка единицы имеет смысл, только если её несёт какой-то сервер (урок 11);
- поле с `enum` — выбор; **набор** значений из спеки, `display.options` даёт только их слова;
- `int` и `float` — числовое, с `step="any"` у дробного, иначе браузер не примет `1.5`; умолчание спеки у новой единицы — подсказкой;
- поле `fixed` у существующей единицы и любое поле без права `edit` — только для чтения.

Права модуль берёт из `/session` и отдаёт и себе, и странице одним правилом:

Без грантов в сессии ответ — да: проверяет каждый запрос сервер (урок 15, шаг 12а), а `may` только не показывает человеку то, в чём ему откажут.

Форма читается **по спецификации**, а не по DOM:

Цикл идёт по `spec.fields`, а не по `form.elements`. Поле, случайно попавшее в разметку, в тело не попадёт: `worker`, `epoch`, `revision` не отправятся никогда — их нет в `spec.fields`. Пустое значит «не задано»: умолчание спеки при создании, «не менять» при правке. При правке не уходит и поле, оставленное таким, каким его показала строка (`data-orig`): строка пришла с замаскированными секретами, и отправить её обратно целиком значило бы записать маску.

**Секрет, привязанный к полю** (`bound_to`, ADR 0020). Секрет годится только для того значения поля, для которого его задали (у камеры в М10B — пароль устройства для её адреса). Сменили такое поле и не вписали секрет заново — форма не отправляется и говорит, какое поле спросить: сервер отказал бы отдать сохранённый секрет новому значению.

**Группы.** Поле `group_by` раскладывает дерево по значениям поля-списка, а `nested_by` — разделитель пути: `Офис/Вход` — группа «Вход» внутри «Офис». У группы своя карточка, переименование переписывает поле у каждой её единицы одной операцией с отчётом о неудачах. Группа, которую создали, а единицы в неё ещё не положили, живёт в этом браузере, пока её значение не получит единица. И группы, которые предлагает домен: поле, которое спека делит с доменом (`domain.shared`), модуль читает сам — `GET /domain/shared/<sub>` — и ставит его группы в дерево даже без единиц ([урок 12 М12](../М12A_Domain/12-shared-settings-without-a-database.md); `module-shared-groups.test.js`). Спека, которая поле не делит, туда не ходит.

Чего здесь сознательно нет: поля, которые описание сказать не может. Разобрать адрес камеры на производителя и канал — знание подсистемы, и для него у страницы есть `addFieldEditor` (шаг 7). Если общей форме чего-то не хватает для любой подсистемы — это чинится в модуле.

## Шаг 6 — Один ключ на отправку и слова сервера

```js

      const sig = method + " " + path + " " + (text || "");

      for (let i = 0; ; i++) {
        …

          if (!r.ok) { const e = new Error(said || String(r.status)); e.status = r.status; e.body = d; throw e; }
          return d;
        }
        if (i >= C.retryWaits.length) { const e = new Error((lost || said || String(r && r.status)) + " — not lost: retry sends it again with the same key"); … throw e; }
        …
      }
    };
```

Одна функция на все записи — и модуля, и страницы. Правило одно, и потому сформулировать его стоит точно.

**Ключ живёт столько, сколько живёт отправка.** Тот же метод, путь и тело — тот же `Idempotency-Key`, пока ответ не окончательный. Сеть оборвалась, таймаут (`timeoutMs`, 20 с), 5xx, 409 «in flight» — это не ответ: запрос повторяется с тем же ключом (`retryWaits`: 2, 3, 5 с; `retry_after` сервера, если он его назвал). Консоль, получившая повтор, узнаёт ключ (урок 15, шаг 13) и отвечает тем, что уже сделала, — второй камеры не будет. 2xx и 4xx ключ закрывают: следующая отправка — новый ключ. `DELETE` без ключа и без повтора.

**Кончились попытки — «не потеряно».** Отказ так и говорит: *not lost: retry sends it again with the same key*. Тост с ним получает кнопку «Повторить», и она отправляет тот же метод, путь и тело — значит, и тот же ключ (`module-retry.test.js`, `module-session.test.js`). Человек, нажавший «Повторить» через минуту, не создаёт дубля того, что сервер на самом деле принял.

`d.detail || d.error` — **слова сервера, не свои**. Модуль нигде не сочиняет текст отказа: `refuse` из урока 9 уже написал человеческую фразу, и перевод её в свой словарь потерял бы точность.

**401 из любого запроса открывает окно входа** — и модульного, и страницы через `api()`. Вход — модуль: окно, `login_url` из `/session`, `POST /session {token}`, аварийный вход `POST /session/break-glass {who, why, password}`, выход `DELETE /session` в меню пользователя (урок 15, шаг 12а). Сессия одна, cookie платформы; своей страница не заводит.

## Шаг 7 — Что добавляет страница: вызовы в библиотеку

Модуль — библиотека платформы, оболочка — страница подсистемы, которая её вызывает. Вызовы ниже — страница, обращающаяся к библиотеке внутри себя, а не платформа, вызывающая подсистему; хуками в смысле ADR 0002 они не являются. Всё, что они получают, — функции страницы, которые модуль размещает и перерисовывает по своему опросу.

```js

    C.addTab = (kind, t) => { (shell.tabs[kind] = shell.tabs[kind] || []).push(t); return C; };
    C.addTreeNodes = (kind, fn) => { (shell.nodes[kind] = shell.nodes[kind] || []).push(fn); return C; };
    C.addFieldEditor = (kind, field, render) => { … };
    C.addCard = (prefix, render) => { (shell.cards = shell.cards || {})[prefix] = render; return C; };
    C.addMenu = (kind, fn) => { (shell.menus[kind] = shell.menus[kind] || []).push(fn); return C; };
    C.addDecor = (kind, fn) => { … };
```

По одной строке на каждый (контракт, §9):

| Вызов | Что страница получает |
|---|---|
| `on("select" \| "refresh" \| "logout", fn)` | выбор объекта, каждый опрос (`{units, servers, domain}` как пришли), выход |
| `select(ref)`, `selected()`, `refresh()` | выбрать объект по `ref` (`unit:<sub>/<id>`, `server:<s>`, `worker:<sub>/<w>`, `member:<m>`, `domain` или префикс страницы), спросить, перечитать |
| `api(method, path, body)` | запись с ключом идемпотентности (шаг 6) |
| `where(ref)` | `{worker, server, door, reason}` — где единица и дверь её держателя (шаг 3) |
| `may(action, ref)` | `view` / `edit` / `admin` по грантам сессии (шаг 5) |
| `display(name)`, `spec(name)` | слова спеки и её копия — для кода страницы (например, таблица мест `spec.places`); за `/spec` страница не ходит сама |
| `kindWord(e)`, `eventNote(e)`, `addEventNote(fn)` | вид и описание события: платформенных — словарь модуля, подсистемы — `display.kinds` и слова страницы |
| `addSection({id, label, icon, after, off, render})` | свой раздел в ленте |
| `addTab(kind, {id, label, render, busy})` | своя вкладка на карточке объекта вида `kind`; `busy()` запрещает перерисовку по опросу |
| `addBlock(kind, {id, covers, render})` | свой блок на общей вкладке карточки; `covers: "<sub>/<table>"` закрывает таблицу `servers.show` |
| `addAction(kind, fn)`, `addMenu(kind, fn)` | кнопки в шапке карточки, пункты меню узла |
| `addTreeNodes(kind, fn)`, `addCard(prefix, render)` | узлы дерева, которые не единицы ни одной подсистемы (`"servers"` — верхний уровень), и карточки для их `ref` |
| `addDecor(kind, fn)`, `addIcons(map)`, `icon(name)` | значок, метка и подсказка узла и заголовка; значки страницы по имени; разметка значка для своих строк |
| `addFieldEditor(kind, field, render)` | свой редактор одного поля внутри общей формы; `set(value)` отдаёт значение, отправляет форма |
| `addNote(kind, fn)` | слова страницы о единице, за которыми порог или логика, — предупреждением под «Размещением» |
| `dialog`, `confirm`, `toast` | диалог, подтверждение и уведомление модуля, чтобы страница выглядела как он |

Две вещи, которые здесь легко сделать неправильно.

**Страница не повторяет платформенного.** Своего входа, своего дерева серверов, своего домена, своего журнала у оболочки нет: это модуль. Тест страницы VMS проверяет это буквально (`shell-page.test.js`). Если странице не хватает чего-то, что нужно любой подсистеме, это задача модуля, а не причина рисовать своё.

**Страница не лезет в DOM модуля.** Карточке и разделу страницы модуль даёт собственный вложенный контейнер. Опоздавшая отрисовка после запроса страницы попадает в отсоединённый узел и не стирает карточку, выбранную позже.

У платформенной страницы ни одного такого вызова нет. Её подсистема — `testsub` в тестах, счётчик из урока 11 на коробке — показана целиком: дерево, форма, серверы, события, отметка, вход.

## Шаг 8 — Текст, а не разметка, и политика содержимого

```js
  const h = v => String(v ?? "").replace(/[&<>"']/g, c => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" }[c]));
```

Имя единицы, заметка к событию, подпись группы, имя человека в домене — текст, который кто-то напечатал. В `innerHTML` он попал бы как разметка: оператор с правом `edit` на одну единицу пишет заметку со `<script>`, администратор открывает единицу — и скрипт выполняется у него, с его правами. Модуль пропускает через `h` каждое значение, которое рисует; тест контракта кладёт вредную строку в поля фиктивной спеки и проверяет, что она не выполнилась и не стала элементом (`module-contract.test.js`, `platform-page.test.js`).

Второй рубеж — у консоли:

```python
def page_csp(path: str = PAGE) -> str:
    import base64, hashlib, re
    page = open(path, encoding="utf-8").read()
    scripts = [m.group(1) for m in re.finditer(r"<script>(.*?)</script>", page, re.S)]
    hashes = " ".join("'sha256-" + base64.b64encode(hashlib.sha256(s.encode("utf-8")).digest()).decode() + "'" for s in scripts)
    own = "'self' " if re.search(r"<script src=\"/", page) else ""
    return f"script-src {own}{hashes}; object-src 'none'; base-uri 'none'"
```

Браузер выполняет только встроенные скрипты страницы, каждый по его хешу, и — у страницы, которая подключает модуль, — файлы своего источника (`'self'`). Больше ничего: ни `<script>`, пронесённого заметкой в список, ни `onclick=` в имени единицы. Страница без `<script src>` своего источника не получает: только хеши (`test_the_console_names_the_pages_own_script_and_this_origin_in_a_content_security_policy_and_no_other`).

Работает это при одном условии: **в разметке нет обработчиков**. `onclick="…"` — встроенный код без хеша, и CSP его не пустит. Модуль навешивает всё из скрипта, платформенная страница не несёт ни одного атрибута `on…=`. Страница подсистемы под тем же правилом, и как его держит страница VMS — `data-act` и одна функция `wire` — показывает урок 12 М10B.

## Что может пойти не так

- **Значение в `innerHTML` мимо `h`.** Одна строка — и заметка к событию стала скриптом у администратора. Тест кладёт вредную строку в каждое поле.
- **Обработчик в разметке.** `onclick=` в странице — и CSP по хешу его не выполнит; уберёте CSP ради него — уберёте второй рубеж.
- **`if (spec.name === 'vms')` в модуле.** Одна такая строка — и через полгода их двенадцать. Словарь теста поймает `vms`; не поймает имя подсистемы, которой в словаре нет. Ловить придётся на ревью — и правилом: предметное знание идёт в спеку, в `display` или в страницу.
- **Модуль идёт за байтами.** Таймлайн или живой поток в модуле — это маршрут подсистемы в платформе. Закрытый список путей в тесте упадёт; правильное место — страница, через дверь из `where()`.
- **Форма, построенная из DOM, а не из `spec.fields`.** Первое же скрытое поле уедет на сервер, и `refuse` вернёт отказ, причину которого будут искать в браузере.
- **Новый ключ на каждую попытку.** Сеть оборвалась после того, как сервер записал, — повтор с новым ключом создаст вторую единицу.
- **Один ключ на форму навсегда.** Исправленное значение уйдёт под старым ключом и получит в ответ старую строку — правка «не применится» без единой ошибки. Поэтому ключ привязан к методу, пути и телу и закрывается окончательным ответом.
- **Перерисовка под руками.** Опрос, стирающий поле, которое человек правит, — правка, которую невозможно закончить.
- **Своя формулировка отказа вместо `detail`.** Оператор читает «Ошибка сохранения», а сервер сказал, какое поле и почему.
- **Вторая копия модуля «чуть поправленная».** Через месяц курс и продукт расходятся в правиле, которое должно быть одним. Долг сверки виден построчно — держите его пустым.

## Итог

- Платформа отдаёт модуль, а не страницу: `/platform/console.js` и `console.css` по версии контракта, открыто. Страница — файл `<sub>.shell.html` рядом со спекой корня, иначе платформенная `console.html`: модуль, стиль и `mount`.
- Страница одна на процесс, у корня; смонтированная подсистема своей не отдаёт.
- Модуль — один файл курса и продукта, сверенный построчно; разница только в долге, и долг только сокращается.
- Модуль знает спеки и платформенные двери: `/spec`, `/mounts`, строки, `/where`, `/servers`, `/session`, `/events`, `/marks`, `/domain/*`. Слова — из `display` спеки, вложенность — из `about`. Байтов не грузит: дверь держателя отдаёт странице.
- Настроенное и наблюдаемое накладываются, и слово heartbeat'а сильнее слова строки; опрос с теми же данными ничего не трогает, с новыми — не трогает того, что под руками.
- Общая форма — по типам полей: секрет пустой, `bound_to` спрашивает заново, отправляется только изменённое и только поля спеки.
- Один ключ идемпотентности на отправку, повтор с ним до окончательного ответа; текст отказа — сервера.
- Страница добавляет своё вызовами библиотеки и не повторяет платформенного.
- Всё, что рисуется, — текст; консоль ставит CSP по хешу скрипта страницы, поэтому обработчиков в разметке нет.

## Упражнения

1. Соберите тело формы из `form.elements` вместо `spec.fields`, добавьте в разметку скрытое поле `worker` и отправьте. Что ответит сервер и почему это правильно?
2. Уберите `worker_state: undefined` из наложения heartbeat'а на строку. Какая единица будет показана молчащей, хотя её воркер бьётся?
3. Сделайте ключ идемпотентности новым на каждую попытку. Оборвите сеть после того, как консоль записала строку, и посмотрите, сколько единиц стало.
4. Положите `testsub.shell.html` рядом с `testsub.subsystem.yaml` и смонтируйте `testsub` под корнем другой подсистемы. Что отдаёт `/testsub/` и почему?
5. Добавьте в платформенную страницу кнопку с `onclick="alert(1)"`. Что сделает браузер с политикой из `page_csp` и что покажет его консоль?
6. Добавьте в `display` спеки раздел `colors:`. Где это остановится и каким текстом?
7. Уберите проверку `busy()` из `refreshMain`. Что случится со страницей, у которой вкладка проигрывает видео?
8. Поменяйте в модуле одну строку и запустите `test_console_module.py` с продуктом рядом. Что он скажет — и что вы сделаете: правку в продукте или строку в долге?
