# Урок 3 — Контракт хранилища и второй бэкенд

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** шов в `variables.py` — `register_scheme` и `open_vars`, фабрику по схеме URL; `tests/test_variables_contract.py` — контракт из семи пунктов, который гоняется против любой реализации хранилища; и `memvariables.py` — второй настоящий бэкенд платформы, на котором этот контракт впервые что-то ловит.
**Время:** ~90 минут.

## Зачем этот урок

Урок 2 кончился объявлением, которое ничего не проверяет. `Variables` — это `Protocol`: он говорит, что `put` принимает `cas`, и не в силах сказать, что при несовпадении тот обязан бросить `Conflict`, а не записать поверх. Настоящий контракт — второе, и выразить его в сигнатуре нельзя.

Платформа до сих пор написана так, будто оркестратора не существует, — и дальше в курсе он не появится: кластер М11 стоит без оркестратора, на юнитах systemd и на своём реплицируемом хранилище. Но хранилище кластера — уже не файлы коробки, а у заказчиков бывают свои оркестраторы и свои хранилища. Соблазн, который губит такие системы, один и тот же: раз уж под тобой что-то есть — читать его переменные окружения, ходить в его HTTP, звать его индекс его именем. Через полгода «поставьте это в наш кластер Kubernetes» станет переписыванием, а не настройкой.

Поэтому вопрос этого урока не «как привязаться к оркестратору», а **«как не привязаться, ничего при этом не усложнив»**. Ответ короче, чем кажется: оркестратор может просочиться ровно в трёх местах, и в каждом хватает шва в несколько строк.

| Где он просачивается | Чем выглядит привязка | Шов |
|---|---|---|
| Где живёт состояние | конструктор хранилища вендора, названный по имени в каждом процессе | `open_vars(PLATFORM_STORE)` — фабрика по схеме URL |
| Что рантайм сообщает процессу | имя переменной окружения, которое придумал оркестратор (номер аллокации, ординал пода), прочитанное в цикле | нейтральные имена в `runtime.py` |
| Что такое версия записи | `if idx > old` | `Index = str | int`, только равенство |

Заметьте, чего в этом списке нет: **размещения**. Это не упущение, и в уроке 7 объяснено, почему его тут быть не должно.

> **Что можно проверить без железа.** Весь урок проверяется на коробке: `open_vars("file://" + tmp)` открывает файловое хранилище в процессе, а контракт-набор гоняется против него и против хранилища в памяти, у которого версия — строка `rv-7`. Ни кластер, ни Kubernetes для этого не нужны — в том и смысл. А тот же набор против хранилища кластера `configstore://` гоняют `test_configstorevars.py` и `test_configstore.py` (шаг 6).

## Что нужно знать заранее

- **Урок 2** — `FileVariables` целиком: `Protocol`, `Index = str | int`, CAS и `Conflict`, `as_writer` и `Forbidden`. Здесь всё это получает вторую реализацию и набор тестов.
- **Урок 1** — тест границы: правило «платформа не знает о подсистеме» получает второе издание — «платформа не знает о рантайме».

## Чему вы научитесь

1. Называть три места, где вендор просачивается в цикл согласования, и показывать шов в каждом.
2. Писать фабрику по схеме URL и регистрацию бэкенда — и объяснять, почему это фабрика, а не сервис.
3. Объяснять, чем набор тестов на контракт отличается от аннотации типа, и почему без него шов — обещание, а не факт.
4. Гонять настоящие CAS-циклы против хранилища, у которого версия — не число.

## Шаг 1 — Склад, сказанный как URL

Начнём с того места, где привязка была бы самой глубокой: с хранилища конфигурации. На нём стоит всё — эпохи, слоты, аренда, размещение, идемпотентность. Если конструктор хранилища назван по имени в каждом процессе, то замена хранилища — это правка каждого процесса.

Шов — две функции и таблица:

```python
STORE_SCHEME = "configstore"
_BUILTIN = {"file": "w2cplatform.variables", "memory": "w2cplatform.memvariables",
            STORE_SCHEME: "w2cplatform.configstorevars"}


def register_scheme(scheme: str, factory) -> None:
    """`factory(url, writer=…, acl=…) -> Variables`. A backend registers itself at import."""
    _SCHEMES[scheme] = factory


def open_vars(url: str, writer: str | None = None, acl: dict[str, list[str]] | None = None):
    """`file:///data/platform/config` · `configstore://…` · whatever else registered.

    A bare path is read as `file://` so the box keeps working with no URL at all."""
    if "://" not in url:
        return FileVariables(url, writer, acl)
    scheme, rest = url.split("://", 1)
    if scheme == "file":
        return FileVariables(rest or "/", writer, acl)
    factory = _SCHEMES.get(scheme)
    if factory is None and scheme in _BUILTIN:
        # A backend registers itself when its module is imported, and the platform's own second one is
        # imported here rather than from `__init__` — `import w2cplatform` still pulls in nothing, which is
        # a property the package states about itself and a test checks.
        __import__(_BUILTIN[scheme])
        factory = _SCHEMES.get(scheme)
    if factory is None:
        known = ", ".join(sorted({"file", *_BUILTIN, *_SCHEMES}))
        raise ValueError(f"no Variables backend for {scheme}://  (have: {known})")
    return factory(url, writer=writer, acl=acl)
```

(`_SCHEMES: dict[str, object] = {}` стоит выше, рядом с комментарием о шве.) Тридцать строк, и в них пять решений.

**`file://` разбирается здесь, а не регистрируется.** Платформа обязана работать на коробке, где ничего не установлено. Схема по умолчанию не может зависеть от того, что кто-то успел себя зарегистрировать.

**Голый путь читается как `file://`.** Хранилище можно не называть вовсе, и коробка работает. Это не удобство: это правило «конфигурация без значения — рабочая конфигурация», которое в М9 уже спасло не одну установку. Какое имя процесс читает, решает одна функция:

```python
def store_url(env=None, default: str | None = None) -> str | None:
    env = os.environ if env is None else env
    return env.get("PLATFORM_STORE") or default
```

Одно имя, `PLATFORM_STORE`, и больше никакого: на коробке оно обычно не задано (файлы под `$PLATFORM_DIR/config`), в кластере юнит говорит `configstore:///run/configstore/<роль>.sock`.

**Бэкенд регистрирует себя сам, при импорте.** Внизу `w2cplatform/configstorevars.py` — ручки хранилища кластера — стоит одна строка:

```python
register_scheme(STORE_SCHEME, _open)
```

**Свои бэкенды платформа знает по имени модуля, а не по импорту.** `_BUILTIN` — это те бэкенды, которые платформа **имеет**: `file://`, `memory://` (шаг 5) и `configstore://`. Их модуль импортируется в `open_vars` при первом открытии, а не в `__init__`: `import w2cplatform` по-прежнему не тянет ничего, и это свойство проверяет тест. Всё остальное — бэкенд, который платформа **допускает**: `k8s://` зарегистрирует модуль, который его реализует, а импортирует процесс, которому он нужен. Платформа не перечисляет вендоров нигде: **добавить Kubernetes — это добавить файл, а не ветку в `open_vars`**, и процесс, не импортировавший этот файл, не знает, что такая схема существует.

**Неизвестная схема — это `ValueError` со списком известных.** Опечатка в `PLATFORM_STORE` должна убивать процесс на старте с внятным текстом, а не оказываться молчаливым откатом на файлы — это была бы коробка, которая после установки в кластер тихо пишет в свой локальный диск и расходится с остальными.

### Почему фабрика, а не сервис

Соблазнительная альтернатива — вынести работу с хранилищем в отдельный процесс-посредник рядом с каждым нашим и ходить к нему через сокет. Тогда наш код не знает даже про URL.

Не делаем так, и довод стоит запомнить, потому что он не про удобство. Наш воркер отпускает слот **после** SIGTERM — в том окне, которое рантайм даёт на остановку. На коробке это запись в файл из того же процесса: писать есть куда по определению. С посредником это стала бы запись **в соседний контейнер, который уже получил свой SIGTERM**, и корректность освобождения слота начала бы зависеть от порядка остановки контейнеров. То есть свойство, ради которого мы абстрагируемся от оркестратора, стало бы зависеть от семантики оркестратора.

Фабрика же не добавляет ни процесса, ни хопа, ни протокола: на коробке `file://` — это объект в том же интерпретаторе.

А кластер М11? Там процесс ходит через сокет к демону `configstore` своего сервера — разве это не посредник? Нет, и разница в двух вещах. Демон — не сосед процесса, а юнит сервера, который останавливается **после** процессов (у их юнитов `After=… configstore.service`, а systemd останавливает в обратном порядке), так что освобождение слота при SIGTERM не зависит от порядка остановки соседей. И он нужен не ради абстракции от вендора, а ради консенсуса: raft-группа из процессов, которые перезапускаются при каждом обновлении, — не группа. Шов при этом тот же: для процесса `configstore://` — ещё одна схема `open_vars`.

## Шаг 2 — Версия записи, в которую нельзя смотреть

Третье место мы закрыли ещё в уроке 2 одной строкой:

```python
Index = str | int
```

Здесь — что она стоит на практике. У хранилища кластера М11 версия — индекс записи журнала raft плюс основание группы, число, растущее. Число провоцирует: сравнить на «больше», вычесть, посчитать, на сколько записей мы отстали, отсортировать по нему. У Kubernetes то же самое место называется `resourceVersion`, является строкой, и конвенции его API прямо запрещают её интерпретировать: клиент имеет право только вернуть её обратно.

Значит, правило простое и жёсткое: **индекс сравнивается только на равенство.** Никакого порядка, никакой арифметики, никакой сортировки. Проверить это на большой кодовой базе легко — достаточно поискать индекс рядом с `>`, `<`, `+` и `-`, — и один раз проверить стоит: одна такая строка отсекает половину возможных хранилищ, и отсекает молча, потому что с числовым индексом она работает.

Правило окупилось на переходе коробки в кластер. Коробка хранит строки в файлах со своим счётчиком, и переход — это разовый импорт в новую группу: `configstore import --from file:///data/platform/config`, с базой версий `-index-base` не ниже счётчика файла. Новые версии — выше всех старых, и версия, которую процесс запомнил из файла, не совпадает ни с одной: его CAS конфликтует, он перечитывает. Импорт возможен именно потому, что версию никто не интерпретирует — эпохи, поколения и ревизии лежат внутри значений, а индекс живёт ровно на время одного CAS (`test_configstorevars.py::test_a_box_imported_into_a_fresh_group_keeps_its_values_and_no_version_it_handed_out_matches`).

В продукте, где платформа написана на Go, то же самое сделано типом, который не поддерживает арифметику вовсе, — там компилятор отказывается собирать `idx - 1`. В Python компилятора нет, поэтому за это отвечает следующий шаг.

**И то единственное, что нужно знать при переносе.** Непрозрачный индекс стоил ровно того, чего должен был: литералы перестали компилироваться, и каждый из них пришлось назвать. Соответствие такое: `-1` → **`NoCAS`** (писать безусловно, что бы там ни лежало), `0` → **`Absent`** (создать, только если ключа нет). Два имени вместо двух чисел — и `put(..., 0)`, набранное по привычке, больше не значит «перезаписать».

## Шаг 3 — Форма не равна поведению

`Protocol` из урока 2 говорит, что `put` принимает `cas`. Он не в силах сказать, что при несовпадении `put` обязан **бросить `Conflict`, а не записать поверх**. А второе и есть весь смысл: реализация, которая молча перезаписывает, подходит по форме и уничтожает систему.

Поэтому контракт написан как набор тестов, а не как аннотация:

```python
def _store(writer=None, acl=None, url=None):
    """The backend under test: this box's files by default, whatever `CONTRACT_URL` says otherwise."""
    return open_vars(url or os.environ.get("CONTRACT_URL") or "file://" + tempfile.mkdtemp(), writer=writer, acl=acl)
```

Одна функция, и она превращает набор в переносимый. По умолчанию — файлы; с переменной окружения — что угодно, например сокет администратора демона хранилища кластера:

```bash
CONTRACT_URL=configstore:///tmp/cs/admin.sock python3 tests/run.py
```

Контракт — шесть пунктов:

1. ключ, который никогда не писали, читается как `(None, 0)` — не исключение и не `{}`;
2. `put` возвращает индекс, который опознаёт версию; следующее чтение отдаёт его же;
3. `cas` — вся история про конкурентность: N гонщиков, один победитель, N−1 отказов;
4. писатель может писать только свои префиксы, и снаружи он **получает отказ, а не игнорируется**;
5. индекс непрозрачен;
6. у ключа ровно одно написание: `..` и ведущий `/` **отвергаются, а не исправляются**.

Двенадцать тестов на шесть пунктов. Правило приёмки формулируется так: **бэкенд считается годным, когда этот файл зелёный против него, а не когда он выглядит правильно.**

Пункт 1 стоит отдельного слова. `(None, 0)` — это не «на всякий случай»: на нём стоит `next_epoch`, `claim_slot` и каждая запись контроллера. Все они начинаются с ключа, которого ещё нет, и пишут его с `cas=0`. Ноль — единственное значение индекса, которое что-то значит, и значит оно «ключа нет»; поэтому `cas=0` читается как «создать, только если не существует».

## Шаг 4 — Хранилище, у которого версия не число

Пятый пункт контракта нельзя проверить на файловом хранилище: у него индекс — число, и любая арифметика по нему прошла бы незамеченной. Нужен стор, который выдаёт версии, не являющиеся числами вообще:

```python
class OpaqueIndexStore:
    def put(self, path, items, cas=None):
        _, current = self.get(path)
        if cas is not None and cas != current:
            raise Conflict(f"{path}: cas={cas!r} but the version is {current!r}")
        self._n += 1
        idx = f"rv-{self._n}"                       # no order, no arithmetic, not even a number
        self._data[path] = ({k: str(v) for k, v in items.items()}, idx)
        return idx
```

Сорок строк в памяти, версия — `rv-1`, `rv-2`, `rv-3`. Это не мок: это рабочее хранилище с честной семантикой CAS, и Kubernetes выдаёт значения ровно такой природы.

И дальше — то, ради чего он написан. Против него гоняются **настоящие циклы платформы**, а не отдельная проверка типа:

```python
e1, idx1 = next_epoch(v, "vms/epoch/7")                     # read-modify-CAS, twice, on one key
e2, idx2 = next_epoch(v, "vms/epoch/7")
assert (e1, e2) == (1, 2) and idx1 != idx2                  # the EPOCH is a number; the index is not
```

Последняя строка — это весь урок в одном утверждении. **Эпоха** — число, она растёт, на её порядке стоит отсечение зомби, и это законно, потому что эпоху выдаём мы сами. **Индекс** — не наш, и потому не число. Дальше в том же тесте воркер захватывает слот, продлевает и освобождает его — три CAS-цикла поверх строковых версий. Если бы хоть один из них где-то сравнил индексы на «больше», это упало бы здесь.

## Шаг 5 — Второй бэкенд, и что меняется от того, что он есть

К этому месту у нас есть шов, контракт и **одна** реализация. Заявление «платформа не знает, какой бэкенд отвечает» с одной реализацией — это надежда: проверить его нечем, потому что проверять не с чем.

Поэтому платформа везёт второй бэкенд сама — `memory://`, сто строк:

```python
_BUILTIN = {"memory": "w2cplatform.memvariables"}
```

Это не мок и не «стор для тестов». Он регистрируется на том же шве, что `file://`, выбирается так же (`PLATFORM_STORE=memory://`) и держится того же стандарта:

```bash
CONTRACT_URL=memory:// python3 tests/run.py       # тринадцать тестов, семь пунктов — зелено
```

Зачем он нужен, по убыванию частоты: dev-коробка, где ничего не должно пережить перезапуск; тест, которому нужен настоящий стор, а не подделка под него; и dev-бинарь, где несколько ролей живут в одном интерпретаторе и открывают одно имя. Суть во втором: **подделка, реализующая контракт, — это бэкенд.**

### URL именует хранилище

Два открытия одного URL должны быть одним хранилищем — как два открытия `file://<dir>`. Отсюда два случая:

| URL | что открывается |
|---|---|
| `memory://<имя>` | одно хранилище на имя в пределах процесса |
| `memory://` | имени нет, делиться нечем: новое приватное на каждое открытие |

ACL при этом — у **дескриптора**, не у общего состояния: `as_writer` возвращает новый дескриптор со своим `acl`, как у `FileVariables`, и не меняет прав уже открытых. Первая версия писала ACL в общее состояние имени, и консоль, открывшая `memory://dev` вторым, меняла права контроллера (ревью платформы, m3). Тест: `test_memvariables.py`.

Первый — это dev-бинарь, в котором контроллер, консоль и воркер живут в одном процессе: они открывают одно имя и видят записи друг друга. Общий адресный пул — не общий писатель, и ACL между ними продолжает работать. Второй — то, что нужно контрактному набору, потому что каждый его пункт начинается с пустого хранилища.

### Седьмой пункт контракта, которого не было

А теперь то, ради чего это в уроке, — новый пункт:

7. Чтение отдаёт копию, а не само состояние хранилища.

У `FileVariables` каждое чтение разбирает JSON заново, поэтому вызывающий получает свежесобранный словарь **по построению**: испортить им хранилище невозможно, даже если очень стараться. Свойство было, но не как решение, а как побочный эффект формата. Никто его не формулировал, потому что нечему было сломаться.

А хранилище в памяти держит те самые словари, которые ему передали. Если `get` вернёт внутренний объект, а не копию, произойдёт вот что:

```python
items, idx = v.get("contract/copy")
items["n"] = "999"
again, idx2 = v.get("contract/copy")
assert again == {"n": "1"}          # ← падает: в хранилище уже "999"
assert idx2 == idx                  # ← версия та же, записи не было
```

И это не «некрасиво», а дыра в самом главном: запись произошла **мимо `put`**, то есть без CAS, без конфликта и без смены версии. Следующий читатель увидит чужое изменение, а версия скажет, что ничего не менялось — ровно та ситуация, ради предотвращения которой весь второй урок и написан, второй бэкенд нужен не затем, чтобы бэкендов было два, а затем, чтобы первый перестал быть единственным мерилом самого себя. Сегодня это `test_a_read_hands_back_a_copy` — седьмой пункт контракта. Машина состояний хранилища кластера держит словари в памяти так же, как `memory://`, и тот же пункт у неё проверяет `test_storemachine.py::test_what_the_machine_hands_out_is_a_copy`.

## Шаг 6 — Что из этого правда сегодня

Скажем прямо, чтобы урок не обещал больше, чем есть.

Написаны и работают три бэкенда, и все три зелёные против контракта:

| Схема | Где | Кто проверяет контракт |
|---|---|---|
| `file://` | коробка: файлы в процессе, без демона (`FileVariables`) | `test_variables_contract.py` как есть |
| `memory://` | dev-коробка и тесты (`memvariables.py`) | `CONTRACT_URL=memory://` |
| `configstore://` | кластер М11: сокет роли демона `configstore` на своём сервере, raft между серверами (`configstorevars.py` — ручка, `configstore.py` — демон, `storemachine.py` — машина состояний) | `test_storemachine.py` (машина), `test_configstorevars.py` (сокет демона), `test_configstore.py` (группа из одного и из трёх на настоящем raft; пропускается без `pysyncobj`) |

Коробка остаётся на `file://` и после того, как появился кластер: ни демона, ни журнала raft, ни лишних записей на флеш. Переход коробки в кластер — разовый импорт её строк в новую группу (шаг 2), а не смена хранилища у каждого процесса.

Хранилище кластера встало на шов так, как этот урок обещает: подсистемам для него не понадобилось менять ни строки — для них `configstore://` лишь другое значение `PLATFORM_STORE`. **Бэкенда Kubernetes нет.** Есть шов, нейтральные имена, непрозрачный индекс и набор, который его примет. Утверждение урока не «это работает на Kubernetes», а «в цикле не придётся менять ничего, когда дойдёт до дела» — и вызовы `open_vars` по коду вместо конструкторов, ноль чтений переменных оркестратора в цикле и четырнадцать зелёных тестов контракта в восьми пунктах (восьмой — урок 19) против трёх бэкендов — это то, чем оно подпирается.

Разница между этими двумя утверждениями существенна, и путать их не стоит ни в разговоре с заказчиком, ни с собой.

**Результат:** `open_vars` с файлами в самой фабрике и своими бэкендами платформы в `_BUILTIN`, `register_scheme` для любого другого; контракт из семи пунктов, зелёный против файлов и памяти — а в М11 и против `configstore://`; `memvariables.py`, у которого версия — не число; и сказанное вслух различие между «шов написан» и «бэкенд написан».

## Итог

- Оркестратор может просочиться ровно в трёх местах: где живёт состояние, что рантайм сообщает процессу, что такое версия записи. В каждом достаточно шва в несколько строк.
- Хранилище называется URL'ом, `PLATFORM_STORE`, и только им. `file://` разбирается в самой фабрике, свои бэкенды платформы (`memory://`, `configstore://`) импортируются по таблице при первом открытии, остальные схемы регистрируют себя при импорте, неизвестная схема — громкая ошибка на старте.
- Фабрика, а не процесс-посредник: посредник сделал бы освобождение слота при остановке зависимым от порядка остановки контейнеров — ровно от той семантики, от которой мы уходим.
- Индекс сравнивается только на равенство: индекс raft — число, `resourceVersion` у Kubernetes — строка, которую запрещено интерпретировать. На этом стоит и разовый импорт коробки в кластер.
- Контракт — исполняемый: тринадцать тестов, семь пунктов, `CONTRACT_URL` для любой реализации. Бэкенд принят, когда файл зелёный против него.
- Второй бэкенд (`memory://`) платформа везёт сама. Он и нашёл седьмой пункт: чтение отдаёт **копию** — свойство, которое файловый бэкенд имел случайно, а значит не имел никто. Третий, `configstore://`, — хранилище кластера М11, и он принят тем же набором.
- Настоящие циклы гоняются против хранилища с версией `rv-<n>`: эпоха — число, индекс — нет.

## Упражнения

1. Задайте `PLATFORM_STORE=redis://localhost` и запустите любой процесс. Прочитайте текст ошибки. Что в нём есть такого, чего не было бы в `KeyError`?
2. Уберите разбор `file://` из `open_vars`, оставив только `_SCHEMES`. Что перестанет работать на коробке и в какой момент это обнаружится?

## Что дальше

Но конфигурация — не всё, что система хранит: heartbeat воркера — десять килобайт, переписываемых целиком каждые десять секунд, и версии им не нужны вовсе.
