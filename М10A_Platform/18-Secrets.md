# Урок 18 — Секрет в строке

**Модуль:** М10A — Платформа (ServerVMS, часть первая)
**Вы напишете:** `w2cplatform/secrets.py` — правило суффикса и `mask_secrets`; три вызова в консоли, один из которых неочевиден; отказ спеке, кладущей секрет в снимок; тип поля `url`, отказывающий логину в URI.
**Время:** ~50 минут.

## Зачем этот урок

То, что открывает воркер, часто просит логин и пароль: устройство, бакет, чужой API. В М10B это камера — до сих пор у её строки было поле адреса и больше ничего, и это работало ровно до тех пор, пока источником был файл.

Вопрос выглядит как «где хранить пароль». На самом деле вопросов два, и первый решает второй.

**Кто вообще должен его видеть?** Пройдитесь по платформе, которую вы построили за семнадцать уроков. Контроллер размещает по меткам и свободной ёмкости — в адрес единицы он не смотрит ни разу. Консоль рисует строки. Ресурс работает с файлами на диске. Другие подсистемы, которым нужна эта единица, ходят к её воркеру, а не к тому, что он открывает.

Остаётся ровно один процесс: **воркер, держащий эту единицу, в момент, когда он открывает то, к чему нужен пароль.** Один потребитель — и всё остальное в этом уроке следует отсюда.

**Куда он утечёт, если не думать?** Здесь важно, что пути уже построены — вы построили их сами, и каждый в своё время был правильным решением:

| путь | урок | что происходит |
|---|---|---|
| `<sub>/snapshot/<worker>` | 11 | снимок покидает кластер и становится директорией домена М12 |
| `GET /<rows>` | 15 | модель чтения отдаёт настроенные строки целиком |
| ответ на `POST` | 15 | а его копия лежит под ключом идемпотентности — **в том же хранилище** |
| строка запуска | — | попадает в лог, в крэш-дамп и в вывод `ps` |
| бэкап хранилища | — | каталог конфигурации целиком, открытым текстом |

Третья строка — та, на которой это ломается у всех. Ответ на создание маскируют реже, чем список, а он к тому же **сохраняется**: `IdempotencyKeys` кладёт его, чтобы одинаково ответить на повтор. Незамаскированный ответ — это вторая копия пароля в хранилище, под ключом, куда никто не подумает заглянуть.

> **Проверка без железа.** Полностью. Всё, что здесь есть, — это строки, ответы HTTP и разбор спеки.

## Что нужно знать заранее

- **Урок 9** — подсистема как YAML: поля, типы, `snapshot`. Правило этого урока — ещё одно слово в том же файле.
- **Урок 15** — консоль как данные: откуда берутся `/<rows>` и ответы на запись; `Idempotency-Key`: повтор отвечают из хранилища, а не выполняют заново.
- **Урок 11** — снимок: что именно покидает кластер и зачем.

## Чему вы научитесь

1. Определять единственного законного потребителя секрета — и выводить из этого всё остальное.
2. Объявлять секрет одним словом так, чтобы это получили все подсистемы разом.
3. Находить неочевидные выходы наружу — тот, что сохраняется, опаснее того, что печатается.
4. Ставить отказ во время загрузки вместо бдительности во время ревью.
5. Говорить вслух, чего ваша защита **не** даёт.

## Шаги

### 1. Правило — это суффикс

```python
SECRET_MASK = "***"

def is_secret_field(name: str) -> bool:
    return name.endswith("_secret")
```

Соблазн — завести реестр: список имён полей, которые считаются секретными. Не надо. Реестр — это второе место, которое надо держать в согласии со спеками, и спеки победят: кто-то добавит поле, забудет строку в реестре, и защита промолчит.

Суффикс же объявляется там, где поле и живёт:

```yaml
cred_secret: {type: string}          # в М10B — пароль камеры (vms.subsystem.yaml)
```

Одно слово в YAML — и это работает для любой подсистемы: для VMS, для записи, для подсистемы, которую напишут через год. Платформа не знает и не должна знать, что этот секрет открывает — устройство, бакет или чужой API; она знает суффикс, и больше ничего. Тот же ход, что `type: int`.

### 2. Маскирование — это копия

```python
def mask_secrets(rows: list[dict]) -> list[dict]:
    rules = _rules(None)
    return [_masked(r, rules) for r in rows]


def _masked(v, rules: SecretRules, depth: int = 0):
    if depth > 64:                                       # a JSON reader stops far sooner; a structure built in code may not
        return SECRET_MASK
    if isinstance(v, dict):
        return {hide_in_url(k, rules): (SECRET_MASK if is_secret_field(str(k)) and x else _masked(x, rules, depth + 1))
                for k, x in v.items()}
    if isinstance(v, (list, tuple)):
        return [_masked(x, rules, depth + 1) for x in v]
    return hide_in_url(v, rules)
```

Сердце — одно условие: `SECRET_MASK if is_secret_field(str(k)) and x`. Остальное — две вещи, о которых ниже, в шаге 5 и в конце урока: адрес в строке теряет то, что в нём учётные данные (`hide_in_url`), а маска идёт вглубь списков и объектов.

Две детали, каждая из которых — ошибка, если сделать наоборот.

**Копия, а не на месте.** Тот, кто вызывает, обычно держит ту самую строку, которую сейчас отдаст воркеру. Замаскировав её на месте, вы отдадите воркеру `***` и получите единицу, которая не открывается, — причём отлаживать это будете долго, потому что в логе всё выглядит правильно.

**Пустой секрет остаётся пустым.** Маска поверх пустой строки делает каждую единицу настроенной на вид: страница больше не отличает «не задан» от «задан», и оператор не может понять, почему единица не подключается.

### 3. Три вызова, а не один

```python
    def create(self, body: dict, key: str | None = None, user: str = "operator") -> tuple[int, dict]:
        …
            return 201, {**mask_secrets([r])[0], "worker": None}      # placed by the controller's next pass, never by the console

    def update(self, uid, body: dict, user: str = "operator") -> tuple[int, dict]:
        …
            return 200, mask_secrets([row])[0]

# и в маршруте GET /<rows>:
                rows, configured = ctl.read_model(con.lost_after), mask_secrets(ctl.units())
```

Первый — тот, ради которого написан этот урок. Ответ на создание уходит не только клиенту: он ложится в `<sub>/idem/<key>`, чтобы повтор получил тот же ответ. Замаскируйте список и забудьте про ответы — и пароль будет лежать в хранилище дважды, а тест, который смотрит только на `GET /<rows>`, останется зелёным.

### 4. Снимок: отказ при загрузке

Снимок — это то, что покидает кластер. Значит секрет в нём — это секрет за пределами кластера, и поймать это надо один раз, а не на каждом ревью:

```python
leaks = [n for n in spec.snapshot if is_secret_field(n)]
if leaks:
    raise ValueError(f"spec {spec.name}: a secret may not be in the snapshot: {leaks} — "
                     f"the snapshot is what leaves the cluster")
```

А умолчание — «все поля» — секреты **не отказывает, а исключает** (и `blob` заодно: он не помещается в снимок по той же причине, по которой не помещается в строку):

```python
                   snapshot=(list(declared) if declared is not None else
                             [n for n, f in fields.items() if not is_secret_field(n) and f.type != "blob"]),
```

Разница принципиальная. Спека, назвавшая секрет явно, ошиблась — это заявление, и оно неверное. Спека, промолчавшая про снимок, ни о чём не заявляла, и безопасное прочтение молчания — то, при котором секрет остаётся внутри.

Заодно отказывайте снимку, называющему несуществующее поле: опечатка в этом списке стоит дорого, а находится иначе только по отсутствию данных в М12.

### 5. Тип `url` и тихая дверь

Всё вышеперечисленное обходится одной строкой, набранной оператором:

```
driverpack://root:hunter2@10.0.0.7/cam
```

Пароль оказался в поле адреса (в М10B — `source` камеры). Это обычное поле, маска смотрит только на `*_secret`, а снимок его содержит. Пароль уезжает в М12 и светится в каждой консоли.

Отсюда — тип поля `url`. Первая версия смотрела на `u.username`, `u.password` и `@` в `netloc`; ревью за ревью к ней добавлялись логин в пути, пары учётных данных, хост, который не прочесть, — и с тринадцатого ревью спека не держит своей копии, а зовёт общее правило адресов (`secrets.address_fault`, урок 9), то же, что спрашивают строки таблиц спеки и дверь домена. В `refuse` это одна строка — `why = f.refusal(fields[name])`, — а слова отказа собирает поле:

```python
    def refusal(self, value) -> str | None:
        got = address_fault(str(value), self.rules)
        if not got:
            return None
        why, kinds = got
        login, secret = self.credentials.get("login"), self.credentials.get("secret")
        if "secret" in kinds and secret:
            instead = (f"Put the login in {login} and the password or token in {secret}" if "login" in kinds and login
                       else f"Put the password or token in {secret}")
        elif "secret" not in kinds and login:
            instead = f"Put the login in {login}"
        else:
            instead = "A login and a password go in fields of their own"
        return (f"{self.name} may not be stored as typed: {why}. {instead} — an address is shown on every page and in "
                f"what leaves the cluster; a secret has a field of its own, sealed")
```

`address_fault` отвечает не только «почему», но и **что** найдено — логин, пароль или оба (`kinds`), — и отказ называет поле для найденного: пароль — поле секрета (и поле логина рядом, только если нашёлся и логин), логин без пароля — поле логина. Полей, которых платформа не знает, отказ не называет: куда класть логин и пароль, говорит спека поля, `credentials: {login: <поле>, secret: <поле *_secret>}` (в М10B у камеры — `cred_username` и `cred_secret`, у тома — `access_key` и `access_secret`). Спека без `credentials` получает общие слова.

Что считать учётными данными в адресе, платформа тоже делит со спекой. Сама она читает адрес так, как его пишет RFC 3986: логин перед `@`, порт, который не число, пары `имя=значение` в запросе и в сегменте пути, адрес, экранированный целиком в сегмент. И несколько имён, которыми любая система называет пароль, токен или ключ, у платформы свои (`secrets.COMMON_RULES`: `password`, `passwd`, `pass`, `pwd`, `secret`, `token`, `key` — целым именем или последним словом, `credential(s)`, `psk`, `privkey`, `apikey`, `=auth`, `=pin` — только целым именем); их читает каждый адрес, что бы ни говорило его поле. Остальное — знание подсистемы: какими ещё именами то, что она открывает, называет пароль (у камер М10B — `loginpas`, `adminpass`, `streamkey`…), какие написания логина оно принимает и в какой паре лежит другой адрес. Это говорит `secret_in` поля (`f.rules`, `secrets.SecretRules.parse`), списком записей трёх видов:

| Запись | Что значит |
|---|---|
| `{param: [имена], login: [имена]}` | пара `имя=значение` с именем из `param` несёт учётные данные; те из них, что названы и в `login`, — логин. Отказывают обеим, но значение пароля прячется, а логина — **показывается**: логин называет, чей это адрес, а не открывает его |
| `{regex: '…(?P<login>…)…(?P<secret>…)…(?P<name>…)…', in: path\|query\|authority\|fragment, schemes: [...], decoded: true\|false}` | написание, которое не пара, в этой части адреса — у перечисленных схем, без списка у любой: что нашла группа `secret`, отказано и спрятано на месте, что нашла `login` — отказано и показано; `name` — то, как отказ это назовёт; `decoded` (по умолчанию да) — искать в части с раскрытыми `%`-экранами |
| `{nested: [имена]}` | значение пары с таким именем — адрес (раскрытый из экранов; `<схема>:` перед его собственным `scheme://` — слово ретранслятора, а не адрес: `ffmpeg:https://…`), и он читается по тем же правилам, до трёх уровней вглубь |

Каждый вид по разу — у поля `feed` подсистемы `testsub2`, на которой платформа гоняет свои тесты:

```yaml
    feed:
      type: url
      unique: canonical
      …
      schemes: {https: {}, sftp: {}, mirror: {host: path, fragment: none, none: [local]}}
      credentials: {login: feed_user, secret: feed_secret}
      secret_in:
        - {param: [token*, "*key", =who], login: [=who]}
        - {nested: [via]}
        - {regex: '^~(?P<login>[^:]+):(?P<name>pin)=(?P<secret>.+)$', in: fragment, schemes: [sftp], decoded: false}
```

Имя пары читается так, как его прочёл бы тот, кто его принимает: экраны раскрыты, буквы приведены (NFKC: полноширинное `ｐｗｄ` — это `pwd`; невидимые знаки вроде U+200B выброшены), после последней `.` (`dev.adminPassword`), по словам — слово кончается на `_`, `-`, `+`, пробеле и там, где меняется регистр, и хвостовые цифры в него не входят (`apiKey2`, `api_key_2` — это `key`). `pwd` в списке — целое имя или его последнее слово, `=auth` — только целое имя (последним словом длинного оно называет режим: `enable_auth`), `pwd*` — какое-то слово с него начинается, `*pwd` — последнее слово им кончается. Имя пароля спрашивается раньше имени логина. Без `secret_in` платформа отказывает `@`, порту-не-числу и своим общим именам. Страница, ответ и дверь, которая не поле спеки, прячут адрес по правилам всех загруженных спек сразу (`catalog.secret_rules`). Таблица адресов — одна у курса и продукта, байт в байт (`tests/testdata/secret_in.tsv`, у каждой строки — как адрес показывается и какое поле называет его отказ: `cred_secret`, `cred_username` или никакое; `test_secret_in_table.py::test_every_address_of_the_shared_table_is_masked_and_refused_as_the_table_says`).

Копия правила отставала: камера пропускала `http://proxy/relay?src=rtsp%3A%2F%2Fadmin%3A…%40cam%2Fs` (адрес с логином внутри параметра — так ретранслятору вроде go2rtc говорят, что забрать), а двери, звавшие общее правило, — нет (тринадцатое ревью, блокер, воспроизведено запуском). Теперь общее правило читает значение пары, которую спека назвала в `nested` (у камеры — `[src, url]`), как адрес, до трёх уровней вглубь, и камера зовёт его же. Тесты: `test_credentials.py::test_an_address_inside_a_parameter_is_an_address_and_a_camera_asks_the_platforms_one_rule`, `test_credentials.py::test_the_vms_says_how_its_cameras_spell_a_login_and_the_platform_reads_it_from_the_spec`.

**Как говорится сохранённый адрес** (`hide_in_url`; так же читает продукт). Логин в userinfo показывается как написан, пароль — `***`: `rtsp://admin:***@cam/s`. Адрес, завёрнутый в пару из `nested` или экранированный в сегмент пути, прячется **целиком** и первым, если несёт пароль. Пароль userinfo тянется до **последнего** `@` слова и может начинаться с одного `/` (ключ объектного хранилища). Порт, который не число, прячется после **каждого** `://` (`s3://https://h:***/b`). Значение пароля в паре сегмента пути идёт через `/` до следующей `;` или `&` (`/a;AccountKey=***;EndpointSuffix=…`), а если за `/` начинается путь, `/` его кончает (`/a;pwd=***/ch/1`). Маски, которые перекрываются или касаются, — одна `***`.

**Свободный текст — не поле ничьей спеки.** Строка лога, ошибка, которую сказал драйвер, запрос, который он записал, JSON-документ: адреса в них ничьи, и `secret_in` к ним не приложить. Для них у платформы своя функция со своей таблицей — `secrets.mask_text` и `tests/testdata/log_mask.tsv` (тоже байт в байт продукта): каждый адрес говорится, как его говорит страница (адрес кончается там, где слово, кавычка или фраза, — `dial rtsp://cam:554: connection refused` остаётся как есть); вне адресов пара с именем пароля теряет значение до `&`, `;`, пробела или кавычки (строка подключения — до конца: спрятать больше, но не меньше); учётные данные заголовка `Authorization:` (Basic, Bearer; хэш Digest остаётся); член JSON с именем пароля. Ставит её на каждый обработчик лога `mask_logs()` — его зовут точки входа платформы (`python3 -m w2cplatform`, кластер) и VMS. Тесты: `test_secret_in_table.py::test_free_text_is_said_with_every_credential_in_it_hidden_as_its_table_says`, `…::test_the_platforms_log_lines_go_through_the_mask`.

Две вещи стоит заметить.

**Отказ, а не молчаливый перенос.** Перенести userinfo в поля `credentials` технически можно, и CLI продукта так и делает. В API — не надо: оператор, вставивший ссылку из браузера, должен узнать, что здесь эти вещи держат врозь. Молчаливое исправление учит противоположному.

**Проверка на записи, не на чтении.** `Field.parse` вызывается и когда строку читают из хранилища. Проверьте там — и строка, записанная до появления правила, станет нечитаемой тем самым правилом, которое её защищает. Дверь — это `refuse`, и только она.

    for path in box.vars.list(""):

## Шаг — Ключ кластера: секрет запечатан в хранилище

Всё, что выше, держит пароль подальше от экранов и копий, уходящих из кластера. Строку оно не трогает: пароль в ней лежит открытым текстом, и тот, кто читает `<sub>/<rows>/*`, копирует каталог хранилища или его резервную копию, читает все пароли всех единиц (записка продукта об аутентификации, раздел 3.6; порядок согласован с ним, обратная связь BP). Этот шаг закрывает именно это — `w2cplatform/sealing.py`.

**Ключ не в хранилище.** В этом весь замысел, и остальное из него следует. Ключ, лежащий рядом со строками, которые он защищает, не защищает ничего: копия хранилища — копия обоих. Поэтому ключ — **файл**, и дают его только процессам, которые секрет печатают или открывают:

| Роль | Что делает с ключом |
|---|---|
| консоль | **запечатывает** каждое значение `*_secret` по пути в хранилище: строки единиц (`SpecController._sealed`) и строки таблиц спеки (`tables.write_row`); и затравку ключа двери кластера (`door/signer`, урок 15) |
| воркер, который пользуется секретом | **открывает** его в последний момент, для того, что открывает сам (`open_row`) — в М10B держатель камеры (`VmsWorker._actuate`) и регистратор, открывающий секрет тома |
| подписант домена на держателе (М12A) | **один** держит и открывает ключи домена (ADR 0032): ключи подписи (`domain/signer`), хэши паролей людей (`identity/users/<id>`) и аварийные хэши кластеров (`domain/break_glass/<кластер>`) лежат **запечатанными**; при старте он запечатывает то, что нашёл открытым, а отдавая члену его строки через дверь домена (`GET /api/carry/<кластер>`, `w2cplatform/domain/carry.py`), открывает каждое `*_secret` своим кольцом и запечатывает ключом этого члена. Консоль домена кольца не получает вовсе: людей и аварийные хэши она пишет через дверь подписанта (`/api/people/…`) |
| агент домена на каждом сервере (М12) | открывает своим ключом члена то, что принёс домой, и держит это запечатанным своим кольцом; так же лежит и затравка самого ключа члена (`domain/member-key`, поле `seed_secret`) |

Контроллер, ресурс, остальные воркеры и любая резервная копия читают строку и получают шифртекст. На коробке файл `/etc/w2c/secrets/platform.key` смонтирован, одним файлом, в `/run/secrets/platform.key` только трёх юнитов — `w2c-console.container`, `vmsworker@.container`, `recworker@.container`, — и в каждом из них стоит `SECRETS_KEY`; `/etc/w2c/secrets` не монтируется больше никуда, а `/data/platform`, в чьём `etc/` он лежит, не монтируется целиком ни в один юнит (`deploy/w2c.env.example`). В кластере М11 на каждом сервере лежит тот же файл, а юниты этих процессов получают его учётными данными systemd (`LoadCredential=platform.key:/etc/w2c/secrets/platform.key`, `SECRETS_KEY=%d/platform.key`); так же — юниты домена М12A (`deploy/domain/systemd/`: подписант `w2c-domain`, `w2c-domainagent` и часть VMS на держателе, `vms-domainpart`, чьи книги несут токены `token_secret`). Консоль домена, `w2c-domain-console`, ключа не получает: ни `LoadCredential`, ни `SECRETS_KEY`, группы только `w2c-domainconsole w2c-store w2c-events`, своя роль хранилища `domainconsole` без `domain/signer*` на чтение и на запись и без `identity/*` (`w2cplatform/domain/rights.py`), а файл ключа и сокеты подписанта для неё закрыты `InaccessiblePaths` (ADR 0032). Интерфейс один — `SECRETS_KEY=<путь>` — во всех местах.

```python
    def seal(self, field: str, value: str, ctx: str) -> str:
        if not value or is_sealed(value):
            return value
        nonce = _secrets.token_bytes(12)
        ct = self._aead[self.current].encrypt(nonce, value.encode(), self._aad(field, ctx))
        b = lambda x: base64.urlsafe_b64encode(x).decode().rstrip("=")
        return f"{PREFIX}{self.current}:{b(nonce)}:{b(ct)}"
```

**Формат.** Файл — строки `<kid> <64 hex>`, первая — текущий ключ. Значение — `enc:v1:<kid>:<nonce>:<шифртекст>`, AES-256-GCM, связанные данные — **ключ строки и имя поля** (`<sub>/<rows>/<id>:<поле>`, в М10B — `vms/cameras/7:cred_secret`): запечатанный секрет, вставленный в другое поле или в другую строку, не откроется. Одного имени поля было мало (второе ревью): секрет единицы 7, скопированный в строку единицы 8, воркер открывал — для единицы 8, тому, кто её читает. Теперь консоль печатает с ключом своей строки (`_sealed(items, uid)`), воркер открывает для строки, которую ему дали (`open_row(…, ctx)`), а не для той, что строка назвала бы сама; строка таблицы спеки — для `<sub>/<table>/<name>` (`tables.write_row`). Значение, запечатанное до этого правила, открывается по одному полю **один раз** — и `seal_stored` при старте консоли перепечатывает его к строке. И второе правило из того же ревью: **на входе `enc:` не принимается** — `SubsystemSpec.refuse` отвергает `*_secret`, которое уже выглядит запечатанным (400): секрет приходит открытым и печатается здесь, а значение с чужой строки или с потерянным хвостом (`enc:v1:x`, которое останавливало бы проход воркера) не доходит до хранилища. Если оно всё же в хранилище — `Sealer.open` поднимает `Sealed` на любую порчу формата, и это статус одной единицы, не конец прохода. Смена ключа — строка **сверху**: новые записи запечатываются ею, старые открываются по `kid`, который в них назван. А при следующем старте консоли `seal_stored` перепечатывает старые под текущий ключ — ревизия не двигается, — и старую строку можно убрать из файла, когда лог консоли говорит, что перепечатано всё (второе ревью, вопрос 5: без этого старый ключ жил в связке вечно). Проход идёт по строкам единиц каждой спеки и по строкам каждой её таблицы, где есть поле `*_secret` (`build_console` в `w2cplatform/host.py`). Строки домена и людей (`domain/`, `identity/`) перепечатывает при своём старте подписант домена, а оператору то же самое даёт инструмент платформы: `python3 -m w2cplatform.w2cctl secrets status` считает по префиксам секреты открытые, под текущим ключом и под старым (и выходит с 1, если открытый есть, а кольцо есть), `secrets seal` перепечатывает их по CAS, не трогая смысла строки. Префиксы по умолчанию — `domain/`, `identity/` и строки единиц каждой загруженной спеки. Порядок операторский и важен: сначала перезапуск **воркеров, открывающих секреты**, — они читают файл при старте и иначе не откроют то, что консоль перепечатала новым ключом, — потом консоли. Тест: `test_a_rotated_key_reseals_what_the_old_one_sealed_so_the_old_line_can_go`. Новый файл: `python3 -m w2cplatform.sealing new /etc/w2c/secrets/platform.key` — связка платформы, путь тот же, что у продукта; `/etc/w2c` — ссылка в `/data/platform/etc`.

**Ключ читают по группе, а не как владелец** (ADR 0023: `platform.key` с группой `w2c-secrets`, 0640). `0600` пустил бы к файлу только владельца, а процессы, которым он нужен, — консоль, воркеры, открывающие секреты (в М10B — держатель и регистратор), подписант и агент домена (М12A), — разные, и в продукте каждый своим пользователем. Поэтому `new_key_file` создаёт его `0640` при любой маске (`fchmod` после `O_EXCL`), а группа — `w2c-secrets`: процесс, который печатает или открывает секрет, входит в неё (`SupplementaryGroups=… w2c-secrets` у каждого такого юнита), остальные — нет. Группу файл получает от каталога: `secrets/` — `2710 root:w2c-secrets`. Почему именно так: `x` без `r` — член группы проходит к файлу, путь которого ему назвали (`SECRETS_KEY`), но не видит, что ещё лежит в каталоге; setgid даёт новому ключу группу каталога без отдельного `chgrp`; владелец — root, потому что ключ пишет только установка, а не работающий процесс. И правило «никогда в хранилище» уточнилось: корень платформы `/data/platform` теперь держит и `etc/`, поэтому `sealing new` проверяет не корень, а сами хранилища — `config/`, `objects/`, `configstore/` (`platform_stores`). Тест: `test_sealing.py::test_the_key_is_never_made_inside_the_store_nor_over_another` — ключ в любом из трёх отвергнут, в `etc/secrets` под тем же корнем создан; права и группу проверяет каждый ключ тестов (`_key`).

**Без ключа — тоже режим, и он говорит о себе.** Нет `SECRETS_KEY` — секрет пишется открытым, и лог консоли один раз говорит, что секреты лежат открытым текстом. Значение запечатано, а у процесса нет ключа или нужного `kid` — ошибка в единственном месте, где это важно: единица не стартует, и причина называет ключ (`Sealed`: *… is sealed and this process has no key (SECRETS_KEY)*). Никогда — шифртекст, молча поданный вместо пароля. Незапечатанное значение открывается как есть: строки, записанные до ключа, продолжают работать, и следующая запись строки их запечатывает.

**Пять правил, которые нашёл продукт** (обратная связь CD):

- **Строку не забыть, и старое не открывается где попало.** У `seal`, `open`, `seal_items`, `open_row` нет умолчания `ctx=""`: каждый вызов называет строку, и воркер, открывавший секрет строки таблицы без неё (в М10B — регистратор с секретом тома), теперь не мог бы так написать (третье ревью, блокер 3). А значение, запечатанное по одному полю, открывается **только** внутри `seal_stored`, чтобы перепечатать его к строке (`fallback=True` там и нигде больше): с умолчанием `fallback=True` секрет единицы 7, вставленный в строку единицы 8, по-прежнему открывался бы (третье ревью, остаток второго).
- **Записанное до ключа запечатывается при старте.** `seal_items` запечатывает строку при следующей записи, а единицу, которую никто не трогает, никто и не перепишет: её пароль лежал бы открытым годами рядом с запечатанными. Консоль, стартуя с ключом, проходит хранилище (`seal_stored`): меняется только значение, на месте, по CAS. Ревизия не двигается, потому что смысл строки не изменился, а сдвинутая ревизия перезапустила бы каждый конвейер ради пароля, который у него уже есть. Тот же проход перепечатывает значения, запечатанные по одному полю, к их строкам. Скрывает он только `Conflict` — строку, которую кто-то переписал тем временем; отказ хранилища или его молчание он считает и называет в предупреждении («NOT sealed»), а не выдаёт за «запечатано своей записью» (второе ревью).
- **Ключ не создаётся внутри хранилища и поверх другого.** `new_key_file` отказывает, если путь внутри одного из хранилищ платформы (`platform_stores`: `config/`, `objects/`, `configstore/` под `PLATFORM_DIR`): ключ рядом со строками, которые он защищает, не защищает ничего, и каждая резервная копия хранилища несла бы оба. Поверх существующего файла тоже не пишет (`O_EXCL`): потерянный ключ — это все пароли, запечатанные им.
- **Единица, чей секрет не открыть, говорит об этом в статусе**, а не только в логе воркера. Это решение воркера, который открывает: в М10B держатель пишет в статус камеры `why` — *its password cannot be opened: … (SECRETS_KEY)*.
- **Секрет в строке таблицы запечатывается так же.** Поле `*_secret` строки любой таблицы спеки (`tables:`, `tables.write_row`) ложится в хранилище запечатанным, как секрет единицы. Открывает его воркер, которому он нужен, для своей строки (в М10B — `access_secret` тома `rec/volumes/<name>`, регистратор).

И дорога пароля мимо ключа, которую продукт нашёл у себя, а курс — у себя тоже: **правка камеры через домен**. Правку для выключенного кластера домен хранит (М12A, урок 9) — у держателя и в каждой резервной копии, на пути к члену её несёт ретранслятор, а поля правки — в журнале. Ключ кластера запечатывает секрет только на входе в хранилище самого кластера, а до него секрет ехал открытым. Теперь домен отказывает в любом `*_secret` (`ConsoleAPI._refuse_secrets` в `w2cplatform/domain/api.py`, 400): пароль задаётся в кластере камеры.

**И пароль в адресе — тоже пароль, и домену его не везти** (двенадцатое ревью, блокер, воспроизведено запуском; сверка продукта). Отказ смотрел на **имена** полей, и правка `{"source": "…?usr=admin&pwd=…"}` для выключенной камеры получала 202 с паролем в ответе, ложилась в `domain/pending/cam-4471` и применялась на камере, когда та возвращалась. Теперь `_refuse_secrets` пропускает каждое значение-адрес через правило кластера (`secrets.address_refusal`, `refuse_addresses` в `w2cplatform/domain/api.py`): логин, порт, который не число, пара с именем учётных данных в запросе или в пути — 400 на правке и на создании, до того как что-то сохранено или переслано; отказ называет поле и никогда — значение. Камера-кластер отказывает так же сама (`Device._update` в `vms/domainpart/device.py`): сохранённая правка доходит до неё и без двери домена. А под этим — пол: каждая запись строки `domain/pending` и каждый итог (`domain/outcomes`) говорят адреса так, как их говорит страница (`hide_in_reply`, `w2cplatform/domain/pending.py`), так что правка, сохранённая старым доменом, теряет пароль при следующей записи строки, и резервная копия держателя его не несёт. Тест: `tests/domain/test_lesson9_pending.py::test_an_address_with_a_password_is_refused_and_never_kept_carried_or_reported`. Что остаётся открытым: свою строку `domain/pending/<кластер>` агент получает через дверь домена (`GET /api/carry/<кластер>`) такой, какой она лежит у держателя, и кладёт домой как есть, — правка старого домена с паролем, не переписанная с тех пор, живёт в копии члена до следующего переноса, а применяясь, получает отказ камеры.

У продукта ключ, который назван, но не читается, отклоняет запись. В курсе такой ветки нет, потому что ключ читается при старте (`Sealer.from_env`): консоль с ненайденным ключом не поднимается вовсе.

**Копия для повтора хранит не хэш тела, а HMAC под ключом кластера** (тринадцатое ревью, major, воспроизведено запуском). Чтобы повтор с тем же `Idempotency-Key` от другого вызывающего или с другим телом получил 422, а не чужой ответ, заявка `<sub>/idem/<key>` держала sha256 тела — без соли, сутки. Строка единицы лежала запечатанной, а `admin123` и `qwerty2024` восстанавливались из заявок словарём из семи слов: тело — это `{"cred_secret": "…"}` и поля, которые читатель хранилища и так видит. Теперь `IdempotencyKeys._tag` делает:

```python
        if body is not None:
            raw = body if isinstance(body, bytes) else str(body).encode()
            if self.sealer is not None:
                out["mac"] = self.sealer.mac("idem", raw)
            out["digest"] = hashlib.sha256(self._said(raw)).hexdigest()
```

С ключом — `mac`: HMAC-SHA256 под ключом, выведенным из ключа связки для этой цели (`Sealer.mac`), так что ни один дайджест не сделан самим ключом печати; хранилище этого ключа не видит, а у всех консолей кластера связка одна, и повтор отвечает любая. `kid` в начале значения позволяет консоли, ушедшей на ротацию вперёд, проверить заявку тем ключом, которым она сделана. Рядом с `mac` всегда лежит `digest`: sha256 тела **так, как его сказала бы страница** (`mask_secrets`: `*_secret` — `***`, адреса скрыты), — словарю в нём искать нечего. Его спрашивают, только когда `mac` не сделать: `kid` за сутки заявки убрали из связки, и верный повтор иначе получал бы 422 (продукт, r28-secrets2). Без ключа есть только `digest`. Цена сказана честно: по `digest` повтор с другим паролем и тем же остальным телом — тот же запрос (первый ответ, вторая единица не создаётся); по `mac` — 422. Тест: `test_credentials.py::test_the_idempotency_claim_keeps_no_digest_a_dictionary_can_turn_back_into_the_password` — словарь ревьюера с ключом и без ключа не находит ничего; та же связка, связка на ротацию вперёд и чужая связка.

**Маска идёт вглубь** (тринадцатое ревью, minor, воспроизведено запуском в М12). `mask_secrets` смотрел только на строки верхнего уровня, а дверь домена спрашивала только значения-строки: `{"source": ["rtsp://admin:<пароль>@…"]}` получал 202, сохранялся, применялся на камере и публиковался как есть. Теперь `mask_secrets` маскирует `*_secret` и прячет адреса на любой глубине списка и объекта (и ключ объекта, если это адрес: `["rtsp://admin:***@…"]`), а `secrets.refusal_within` задаёт правило адресов каждой строке внутри и называет место (`source[0]`, `extra.url`), не значение; дверь домена и консоль камеры-кластера зовут его через `refuse_addresses` (`w2cplatform/domain/api.py`). Тесты: `test_credentials.py::test_a_value_inside_a_list_or_an_object_is_asked_and_masked_all_the_way_down`, в М12 — `tests/domain/test_domain_door.py::test_an_address_inside_a_list_or_an_object_is_refused_at_the_door_and_on_the_camera`.

**Пароль набирают в поле пароля** (тринадцатое ревью, minor). Страница рисовала секрет единицы (в М10B — `cred_secret` камеры) как `type="text"`: пароль был на экране, пока его набирают. Теперь каждое поле `*_secret` спеки — `type="password"` в общей форме модуля консоли (`fieldInput` в `w2cplatform/console.js`, урок 16). И форма правки оставляет его пустым, а в подсказке пишет, задан ли пароль: заполненная значением строки, `***`, она при следующем «Save» записывала `***` паролем (пустое поле — «не менять»). Тесты: jsdom `tests/console/module-contract.test.js` — у модуля (`secretEmpty`: поле пароля, пустое, подсказка «задан»); `test_credentials.py::test_the_page_asks_a_secret_in_a_password_field_and_never_fills_it_with_the_mask` — что страница VMS сама полей спеки не рисует, а единственный секрет, который спрашивает в своём диалоге (`access_secret` тома), тоже поле пароля без значения.

**Маска, пустое поле и новый адрес — на сервере** (тринадцатое ревью; правило продукта, один ключ YAML у обоих). Страница починена, но страница не единственный клиент. Поэтому три правила стоят в двери записи — `SpecController.create`/`update` для строк единиц и `tables.write_row` для строк таблиц спеки. Маска, какую бы ни рисовал клиент, — `***`, `•••`, `●●●`, `＊＊＊` или больше одного из этих знаков, — это пароль, которого никто не набирал: 400 «a secret was sent as its mask; leave the field out to keep it». Секрет, присланный при правке пустым или `null`, оставляет сохранённый: поле, в котором что-то набрали и стёрли, раньше стирало пароль. А если сменилось поле, к которому секрет привязан (`bound_to`, урок 9; в М10B `cred_secret` камеры — к `source`, `access_secret` тома — к `url`), и нового секрета нет — 400 словами, которые адреса не повторяют:

```python
def is_mask(v) -> bool:
    """`v` is a secret's mask as a page shows it — `***`, `•••`, `●●●`, `＊＊＊` or more of one of them."""
    s = v.strip() if isinstance(v, str) else ""
    return len(s) >= 3 and len(set(s)) == 1 and s[0] in MASK_CHARS


def unbound_secret(secret: str, bound: tuple, before: dict, after: dict) -> str | None:
    """Why an edit that sent no new `secret` may not keep the stored one — a field it is `bound` to changed — or None.
    Nothing stored: nothing to carry, nothing refused. The words never repeat an address."""
    moved = [b for b in bound if str(before.get(b) or "") != str(after.get(b) or "")]
    if moved and before.get(secret):
        return (f"{secret} was given for the {' and '.join(moved)} this row had; that changed and no new {secret} came. "
                f"A secret is not carried to another address — send the one for the new address")
    return None
```

У строки таблицы то же правило в `tables.write_row`: запись строки — это строка целиком, и секрет, которого форма не прислала, стирался бы; он остаётся таким, как сохранён (запечатан для той же строки, и `seal_items` его не трогает), если только поле из его `bound_to` не сменилось. `a***` — пароль, а не маска: знак должен быть один и тот же, не меньше трёх. Чего правило не умеет: снять пароль с единицы правкой нельзя — пустое поле значит «не менять»; единицу без пароля по новому адресу заводят заново или присылают новый пароль. Тесты: `test_sealing.py::test_every_mask_a_page_draws_is_refused_and_a_password_with_stars_in_it_is_not`, `test_sealing.py::test_a_secret_sent_empty_on_an_edit_keeps_the_stored_one_and_an_address_changed_without_one_is_refused`, `test_sealing.py::test_a_tables_key_not_sent_is_kept_and_a_new_address_needs_a_new_one`.

**Чего ключ не даёт.** Процесс консоли и процесс воркера, открывающего секрет, видят пароль — им он нужен; службы домена видят то, что держат и несут. Тот, кто может читать файл ключа **и** хранилище, читает и пароли: на коробке это процесс в группах `w2c-secrets` и `w2c-store` — и root. Ключ закрывает копии, резервные копии и процессы, которым пароль не нужен, — не машину целиком.

## Чего это не даёт

Скажите это вслух, себе и в комментарии к файлу, иначе защита начнёт казаться больше, чем она есть.

**Строка хранит пароль открытым текстом** — пока у консоли нет ключа кластера (шаг выше); с ключом в строке шифртекст. На коробке это файл под `PLATFORM_DIR/config`; у кого коробка без ключа — у того все пароли. В кластере это журнал configstore на диске каждого сервера (`/data/platform/configstore`): провод raft между серверами закрыт `raft.secret`, а шифрования журнала на диске configstore не обещает. Гарантия «в покое» — это ключ кластера, и только он.

**Контракт хранилища — про писателей.** Контракт из урока 2 говорит: писатель пишет только свои префиксы и получает отказ, а не тишину. Про **чтение** он не говорит ничего, и файловое хранилище коробки читает любой процесс группы `w2c-store`. Configstore кластера права на чтение держит — у каждой роли в файле прав есть `read`, — но права там по ключам и префиксам, не по полям: роль контроллера читает `<sub>/*`, потому что строки единиц ей нужны для размещения, а вместе со строкой — и поле `*_secret`, которое ей не нужно никогда.

Что спека может, — сказать, **кто читает её строки-секреты**, и платформа держит её на слове. `secrets: {readers: {<строка или префикс>: [<роль>]}, reads: [<строка или префикс>]}`: `readers` — какие роли (`console`, `controller`, `worker`, `domain`, `domainagent`, `resource`) читают секретную строку этой подсистемы, `reads` — чьи чужие строки читает её воркер. У `testsub2` — `secrets: {readers: {door/signer: [console]}, reads: [testsub/counters]}`: затравку ключа двери читает только консоль, которая подписывает токены, — никогда не воркер, иначе дверь могла бы сама делать токены, которые проверяет. Файл прав кластера из спек не генерируется, пока хоть одна роль читает объявленную строку, не будучи названной, или названа и не читает (`check_secrets` в `w2cplatform/cluster/rights.py`, М11): объявление — обещание, сверенное с правами, а не комментарий.

Сузить читателей до поля — это изменение контракта хранилища, а не этого файла, и оно не сделано. Цена такого изменения честная и немаленькая: каждый бэкенд обязан реализовать права на чтение, в контрактном наборе появляется новый пункт, а файловый бэкенд при этом **врёт** — файл на диске читает кто угодно, у кого есть каталог. Поэтому и нужен ключ: запечатанное поле читатель строки получает шифртекстом.

Альтернатива — вынести секрет в отдельное хранилище, а в строке оставить ссылку. Она покупает изоляцию на чтении и платит за неё вторым хранилищем, вторым швом, проблемой курицы и яйца (чем аутентифицироваться в хранилище секретов) — и ротацией, которую придётся изобретать заново. Сейчас смена секрета достаётся бесплатно именно потому, что секрет лежит в строке: новая запись строки — новый секрет у воркера (в М10B это разбирает урок 19).

## Что может пойти не так

- **Замаскировали на месте.** Воркер получает `***`, единица не открывается, а в логах всё выглядит правильно. `mask_secrets` возвращает копии, и тест это проверяет.
- **Замаскировали только список.** Пароль в хранилище дважды — второй раз под `<sub>/idem/<key>`. Скан всего хранилища.
- **Маска поверх пустой строки.** Каждая единица выглядит настроенной; оператор не видит, что пароль не задан.
- **Отказали умолчанию снимка.** Спека, которая ничего не заявляла, перестаёт загружаться. Умолчание фильтруют, явный список отказывают.
- **Проверили URL на чтении.** Строка, записанная вчера, перестала читаться сегодня — правилом, которое её охраняет.
- **Завели копию правила.** Одна дверь звала общее правило, другая держала своё, и своё отстало на одну находку (тринадцатое ревью). Правило адресов — одна функция, и все двери зовут её.
- **Положили хэш тела рядом с запечатанной строкой.** Тело с паролем — это пароль плюс поля, которые читатель хранилища видит и так; несолёный хэш отдаёт его словарю. HMAC ключом, которого хранилище не видит, или хэш без секретов.
- **Спрятали логин вместе с паролем.** Страница показывает `***@cam`, и оператор не видит, под чьим именем открыта единица. Логин называет, а не открывает: отказ ему — чтобы он лёг в своё поле, а в сохранённом адресе он показывается (`admin:***@`, `?usr=admin&pwd=***`).
- **Строку лога пропустили мимо маски.** Ошибка драйвера с адресом внутри уходит в журнал открытым текстом. `mask_logs()` на точке входа — и каждая строка проходит `mask_text`.
- **Завели реестр секретных полей.** Он разойдётся со спеками. Суффикс не расходится: он в том же файле, что и поле.

## Итог

Секрет имеет ровно две законные точки касания: оператор пишет, воркер читает. Всё между ними отдаёт `***`.

Правило — суффикс `_secret`, объявленный там же, где поле; маскирование — копия, три вызова, и самый важный из них тот, чей ответ сохраняется; снимок отказывает при загрузке, а по умолчанию фильтрует; тип `url` закрывает дверь, через которую пароль заезжает в поле, о котором маска не думает.

И то, чего это не даёт, записано рядом с тем, что даёт.
