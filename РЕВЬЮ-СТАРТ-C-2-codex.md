## SC2-01 — мелкая, сохранившаяся SC-02: исправление README не попало в закреплённую версию для C

**Места и цитаты.** `decisions/0090-сессии-vms-без-права-на-платформу.md:360–361`:
«Нормы платформы в ней те же, что в `542d089`; **стадия C остаётся на `542d089`**».
ADR-0083:558,564–565 также продолжает задавать C эту выгрузку.

Разбор первого прогона ссылается на исправление в `7122377`. Оно действительно есть:
`cammeta-specs@7122377:README.md:11–15` описывает `Platform/`, процессы, `spec/`, приёмку и общие договоры.
Но в **закреплённом** `cammeta-specs@542d089:README.md:10–12` по-прежнему написано:
«`М10_Platform/NN-*.md`», «`М10_Platform/spec/NN-*.{norms.md,api.openapi.yaml,README.md}`»,
«`Source/tests/testdata/acceptance/М10_Platform/NN/`».

**Контрпример.** Новая сессия C честно выбирает `542d089` по новым правилам и следует его README.
Каталоги М10 из инструкции отсутствуют в дереве этого коммита; `Platform/01-store/` есть.
Исправленный README другого коммита при таком checkout не читается. Следовательно, публикация исправления
сама по себе не закрыла ошибку входного пакета для C.

**Основание и последствие.** Инструкция начального пакета не соответствует назначенной раскладке по процессам.
Правильный путь из промпта позволяет обойти ошибку; нормы и поведение платформы не меняются — серьёзность **мелкая**.

**Рекомендация.** Явно разрешить C использовать `7122377` как исправленное издание того же набора норм
и обновить закреплённую версию в поручениях/дополнении. Между `542d089` и `7122377` реально изменён только
`README.md` (`git diff --name-only`); регенерации норм для этого не требуется.
Либо явно разделить нормативный срез и издание входной инструкции, чтобы C получала исправленный README.
Коммиты задним числом не менять.

**Происхождение.** Сохранилась SC-02 первого прогона; исправление текста опубликовано, но C оставлена на старом хеше.
Новая правка `f7c4ea53d` явно сохраняет это закрепление, а не вводит новую ошибку README.
