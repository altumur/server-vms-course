# V/12.1 — Раскладка плагина: нормы

Канон главы 1 урока V/12 «Плагины psim» (ADR-0080; модуль VMS — ADR-0090; плагины psim через адаптер — ADR-0071; подсистема
psim и описание вида — ADR-0115 с доп. (1)–(15)). [Лекция](../12-psim.md), [инструкция](12-psim.README.md). Платформа —
выгрузка `cammeta-specs` `7a875c75`; ключи загрузчика ADR-0115 — P/02.1 на main курса (Н1.6).

Плагин psim — чужой исполняемый файл с манифестом плагина `plugin.json` и переводами `langs/*.json`. У нас он становится
подсистемой: генератор (глава 2) строит из манифеста плагина манифест подсистемы, воркер-адаптер (глава 3) держит процесс
плагина и играет для него роль платформы psim. Глава нормирует, во что ложится каждое слово манифеста плагина: имя, единица,
таблицы видов, поля, подписи, события, команды, ресурсы, связи с другими плагинами. Сам плагин не меняется.

Id норм — `V/12.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Манифест плагина** — `plugin.json` по `schema/plugin.schema.json` psim-sdk `c3d9ebb`; **манифест подсистемы** — выход
  генератора `psim-<id>.subsystem.yaml`, который читает загрузчик P/02.1 (ADR-0071 доп. 2026-10-21).
- **Вид** — `object_type` манифеста плагина; **объект** — строка таблицы вида.
- **Единица-плагин** — единственная единица подсистемы, сам плагин: его `parameters`.
- **Владелец типа** — установленный плагин, у которого этот `object_type` объявлен.

## Н1 Форма

**Данные.** Семьи подсистемы — по раскладке ниже: строка единицы `psim-<id>/units/plugin`, таблицы видов `psim-<id>/<т>` и
`psim-<id>/<т>_seen`, кольца событий `psim-<id>/<т>_events`, состояние `psim-<id>/state/<имя>/plugin`, просьбы
`psim-<id>/requests/<rid>`, журнал событий единицы. Своих семей в каталоге VMS у урока нет: таблицы задаёт манифест плагина, а не урок.

### Н1.1 Имя и единица

- **Имя подсистемы** — `psim-` и `metadata.plugin_id` в нижнем регистре (ADR-0115 доп. (2) п. 2). Не проходит грамматику
  `name` P/02.1 (`[a-z][a-z0-9_-]{0,31}`) — отказ генератора.
- **Единица** — `unit.rows: units`, `unit.id: plugin` (решение «Спецификации VMS»). Поле `plugin` — `string`, `enum: [plugin]`,
  `fixed: true`; строка одна — `psim-<id>/units/plugin`, второй нет (доп. (5) п. 4, доп. (7) п. 2). Строку пишет шаг установки
  (глава 4), не `POST`.
- **Поля единицы** — `parameters` плагина по Н1.3, и поле `enabled`: `bool`, `default: true` (доп. (7) п. 4). Выключение —
  `enabled: false`: адаптер плагин не запускает, сборщик убирает виды объектов (глава 4). `required` у параметров не ставится:
  признака обязательности у psim нет; готовность судит адаптер (глава 3 Н1.4).
- **`readonly`-параметры плагина** — `unit.state.<имя>` со схемой по типу Н1.3 (доп. (2) п. 1). В поля единицы они не входят.
- **Размещение** — одна единица, один процесс адаптера на плагин: `placement: {capacity: {default: 1}}`, без `near`, `home`,
  `group_by`. Плагин с одним соединением к своей системе держится целиком, одним процессом (ADR-0071).

### Н1.2 Таблицы видов

- **Вид — таблица** (доп. (3) п. 1). Имя — `type` в нижнем регистре; не проходит `tableName` P/02.1, длиннее 25 знаков (иначе
  `<т>_events` не влезет в 32 знака `tableName`; доп. (14), строже 27 доп. (4) п. 2), равно `units`, `plugin`,
  `<т>_seen` или `<т>_events` другого вида — отказ генератора (доп. (8) п. 3, доп. (13) п. 1).
- **Поля таблицы:** `id` — ключ строки (`key: id`), id объекта psim; `plugin` — `string`, `enum: [plugin]`, `default: plugin`,
  `ref: psim-<id>/units`: поле единицы-плагина для прав (`rights.unit_of: {<т>: plugin}`, доп. (4) п. 2); у вида с `parent` —
  поле `parent`, `string`, `required: true`, `ref: psim-<id>/<т родителя>`. Прочие поля — `parameters` вида по Н1.3.
- **Корни.** Вид без `parent` — таблица без поля `parent`. Корневого вида нет: два корня — две таблицы (доп. (3) п. 1).
  `parent` на тип, которого в манифесте плагина нет, — отказ генератора.
- **`<т>_seen`** — вторая таблица у вида с `readonly`-параметрами (доп. (3) п. 2): `key: id`, поле `id` с `ref: psim-<id>/<т>`,
  поле `plugin` как выше, поля — `readonly`-параметры по Н1.3. Пишет её адаптер: `worker.writes`; консоль пишет только `<т>`.
  Строку `<т>_seen` адаптер снимает, когда строки `<т>` с тем же ключом нет (доп. (6) п. 3).
- **`<т>_events`** — кольцо событий у вида с `events`, на который ссылается `source` чужого установленного плагина (доп. (13)
  п. 1, доп. (14)); такие виды генератору называет сборщик (глава 4 Н1.3), без зависимых кольца нет: `key: "{slot:int}"`, поля `slot` — `int` от 0 до
  `PSIM_EVENTS_RING` − 1, `seq` — `int`, номер события вида по возрастанию, `event` — `<т>.<event id>`, `object` — id
  объекта, `params` — `json`, `t` — `float`, секунды Unix, `plugin` как выше. Пишет адаптер (`worker.writes`): событие `seq`
  ложится в слот `seq mod PSIM_EVENTS_RING`, поверх прежнего; строк кольцо не удаляет (доп. (15)).
  `PSIM_EVENTS_RING` = 1000 (доп. (13) п. 1). Его читает адаптер зависимого плагина (Н1.6); журнал событий единицы
  пишется, как прежде (Н1.5).
- **Имена.** Параметр с именем `id`, `plugin`, `parent`, `enabled`, с точкой или из запрещённых имён полей P/02.1 (`unit.fields`
  у параметров плагина, `tables.<имя>.fields` у параметров вида) — отказ генератора (доп. (4) п. 1, доп. (6) п. 3, доп. (8) п. 3).

### Н1.3 Поле из параметра

| Параметр psim | Поле манифеста подсистемы |
|---|---|
| `type: string` | `string` |
| `type: integer` | `int` |
| `type: float` | `float` |
| `type: boolean` | `bool` |
| `type: array`, `items.type: string` | `list` |
| `type: array`, `items.type: integer` или `float` | `json`, `schema: {type: array, items: {type: integer \| number}}` |
| `default` | `default` того же значения |
| `pattern`, `min`, `max` | `schema` поля: `pattern`; `minimum`, `maximum` (у `array` — к `items`) |
| `enum_values` у `string` | `enum` — список `value`; подписи — `display.options` (Н1.4) |
| `enum_values` у `integer`, `float` | `schema.enum` (доп. (2) п. 7) |
| `enum_values` у `array` | `schema: {items: {enum: […]}}` |
| `source` у `string` | `ref: <владелец>/<т>` и `ref_label: <display_field>` (умолчание `id`; доп. (5) п. 2) |
| `source` у `array` | `list` с `items.ref: <владелец>/<т>` и `ref_label` (доп. (2) п. 5) |
| `hidden: true` | `hidden: true` |
| `readonly: true` | не поле: `unit.state.<имя>` у плагина, поле `<т>_seen` у вида (Н1.1, Н1.2) |
| `secret: true` | поле `<имя>_secret`, только `string` (доп. (2) п. 4) |

- `source.value_field` не `id` — отказ генератора, предел первого этапа (доп. (5) п. 2). `source.provider` не
  `platform_objects` — отказ схемы psim.
- **Владелец `source`** — плагин, у которого `source.object_type` объявлен; его находит сборщик среди установленных (глава 4
  Н1.3; доп. (10) п. 1). Тип объявлен в самом плагине — владелец он сам, вызовы по нему обслуживает свой адаптер, просьб к
  себе нет (доп. (12)). Владельца нет — плагин ставится, поле без `ref`, перечень `source` пуст, вызовы по типу —
  `PERMISSION_DENIED` до установки владельца (глава 3 Н1.2). Камеры VMS (`cam`) владельцем типа psim не бывают: `CAM` — только
  вид плагина, предел (доп. (12)).
- **Секрет.** `secret` у не-`string` — отказ генератора, предел; `secret` и `readonly` вместе — отказ (секрет в `worker.writes`
  не кладётся); поля `x` и `x_secret` в одном виде — отказ (доп. (3) п. 6, доп. (4) п. 2). Обратно адаптер снимает суффикс:
  плагин получает параметр под своим именем (глава 3 Н1.3).

### Н1.4 Подписи и переводы

- **Ключ и текст.** Подпись — `{key, text}` (P/02.1 `label`): `key` — `name_key` psim, `text` — значение ключа в
  `langs/en.json`, нет его там — сам ключ (запасной язык psim — `en`, psim ADR-006; решение «Спецификации VMS»).
- **Где.** Параметр плагина — `display.fields.<поле>`, параметр вида — `display.fields.<т>.<поле>` (доп. (3) п. 3, доп. (4)
  п. 1); `description_key` — `field_help` по тому же имени; `enum_values[].name_key` — `display.options`; событие —
  `display.kinds.<вид события>`; вид — `display.tables.<т>` из `name_key` вида (ADR-0115 доп. (11); ключ загрузчика P/02.1 —
  доля «Спецификации»). Только у `<т>`: `<т>_seen` — не вид, `display.tables.<т>_seen` загрузчик отвергает (М ревью доп. (11)).
  Подписи вида нет — `UnitKind.label` по умолчанию — имя таблицы (V/11); у psim `c3d9ebb` `name_key` вида обязателен.
  `display.unit`, `display.units` — `plugin_id`: своего имени у плагина в манифесте нет.
- **Переводы** — `display.langs.<язык>`: каждый `langs/<язык>.json` целиком, только строковые значения (как хост psim).
  Имя файла не проходит грамматику языка P/02.1 — отказ генератора.

### Н1.5 События, команды, ресурсы

- **Событие** — вид `<т>.<event id>` в `events.kinds` с `severity` psim и подписью в `display.kinds` (доп. (5) п. 3, доп. (3)
  п. 6). Префикс `plugin.` — для событий самого плагина (доп. (7) п. 5); у psim `c3d9ebb` событий плагина нет, префикс занят.
  **Класс в журнале** — `alarm` при `severity: alarm` и `critical`, иначе (`info`, `warning`, `error`) — `observation`
  (доп. (10) п. 2).
- **Команда** — просьба `requests`: `schema` — объект `{action, object, params?}`, `action` — перечень `<т>.<command id>` всех
  видов, `object` — `string`, id объекта, `params` — объект; `required: [action, object]`; итог — `outcome: mark`. Адаптер
  исполняет просьбу вызовом `SendCommand` (глава 3 Н1.5).
- **Ресурс** `provides[]` типа `PROXY` — маршрут двери адаптера `door.routes`: имя — `path_prefix` без начального `/`. Не
  один сегмент по грамматике `name`, или `static` (маршрут занят, Н1.6) — отказ генератора (доп. (10) п. 2). Ресурсы `STATIC`,
  `LINK` маршрута не получают, предел: `STATIC` и хост psim не проксирует, у `LINK` адрес чужой.
- **Страница настройки** — ресурс `role: setup_ui` типа `PROXY`: её адрес `backend` отдаёт в описании вида (V/11), список
  `object_types` — строка через запятую psim. У ресурса не `PROXY` своей страницы нет, предел.
- **`requires`** непустой — отказ генератора: управляемых СУБД и API psim у нас нет (ADR-0071).

### Н1.6 Прочие ключи манифеста подсистемы

- **Дверь** — `door.routes`: маршруты ресурсов Н1.5 и `static` (глава 3 Н1.6).
- **Воркер** — `worker.exec: /usr/lib/psim/adapter /usr/lib/psim-<id>` (решение «Спецификации VMS»: один адаптер на все
  плагины, второе слово — каталог плагина, глава 4 Н1.1); `worker.writes` — все `<т>_seen` и `<т>_events`.
- **Чужой плагин** (доп. (10) п. 1, доп. (12)). Для каждого установленного владельца `source`, кроме самого плагина, — `worker.reads`: его таблицы
  видов `<владелец>/<т>/`, `<владелец>/<т>_seen/` и кольца `<владелец>/<т>_events/` (доп. (13) п. 1: права журнала у
  адаптера нет); `worker.requests: [<владелец>]`. Владельцев двое — отказ установки (глава 4).
- **Права** — `rights.unit_of` для каждой таблицы видов и `<т>_seen`: поле `plugin`. Права на отдельный объект плагина нет,
  только на плагин целиком, предел (доп. (3) п. 4).
- **Фрагмент для `backend`** — глава 2 Н1.3.

## Н2 Двери

Своих дверей у главы нет: строки — дверь консоли (P/06.1), маршруты — дверь адаптера (глава 3 Н1.6).

## Н3 Проход

```
plugin.json + langs/ → имя (Н1.1) → единица и поля (Н1.1, Н1.3) → таблицы видов и <т>_seen (Н1.2) → подписи (Н1.4)
  → события, команды, ресурсы (Н1.5) → дверь, воркер, связи с владельцами source, права (Н1.6) → манифест подсистемы
```

**Гонки.** Нет: раскладка — чистая функция манифеста плагина, переводов и списка установленных плагинов (глава 2).

## Н4 Отказы

Каждая строка — отказ генератора (глава 2 Н1.2): манифест подсистемы не строится, установка не идёт.

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| имя подсистемы не по грамматике | отказ, `plugin_id` | оператор установки | — (плагин не наш) |
| имя таблицы вида не по `tableName`, длиннее 25, `units`, `plugin`, столкнулось с `<т>_seen`, `<т>_events` | отказ, `type` | оператор | — |
| параметр `id`, `plugin`, `parent`, `enabled`, с точкой, запрещённое имя поля | отказ, вид и параметр | оператор | — |
| `parent` на необъявленный тип | отказ, `type` | оператор | — |
| `secret` не `string`, `secret` с `readonly`, `x` и `x_secret` | отказ, параметр | оператор | — |
| `source.value_field` не `id` | отказ, предел первого этапа | оператор | — |
| `path_prefix` не один сегмент `name` или `static` | отказ, ресурс | оператор | — |
| `requires` непустой | отказ | оператор | — |
| язык `langs/` не по грамматике | отказ, файл | оператор | — |
