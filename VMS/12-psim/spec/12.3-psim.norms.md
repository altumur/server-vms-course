# V/12.3 — The adapter and the page door: norms

This English text is the source; the Russian translation `ru/spec/12.3-psim.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 3 of lesson V/12 «Плагины psim» (ADR-0071; ADR-0115 item 4, addendum (1) item 1, addendum (2) items 1, 8,
addendum (3) item 2, addendum (5) items 3, 4, addendum (7) items 2, 4, addendum (8) items 1, 2, addendum (10)).
Lecture (`ru/12-psim.md`, for people, not in the export), [instructions](12-psim.README.md), the door — [`12-psim.api.openapi.yaml`](12-psim.api.openapi.yaml).
The platform is the export `cammeta-specs` `7a875c75`.

The adapter worker is the worker of the subsystem `psim-<id>` on the platform's base worker (P/03). For the plugin it is the psim
platform: it starts the plugin's process, gives it the address and the credentials, answers the calls of the service `Platform`, and
itself calls the service `Plugin` — passes parameters, objects, commands and collects events. Outward it has the process door: the
routes of the plugin's resources for its pages. The protocol is `proto/psim/platform/v1` of psim-sdk `c3d9ebb`; the host's behaviour
where the proto is silent is the psim emulator of the same commit.

Norm ids are `V/12.3-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../Platform/common/NORMATIVE-TERMS.md).
The words of the lesson are chapter 1 Н0.

- **Plugin process** — the executable file `process_name` of the plugin directory, a child of the adapter.
- **Session** — from the plugin's `Register` to the exit of its process; a new `Register` is a new session.

## Н1 Form

**Data.** The families of chapter 1: the row `psim-<id>/units/plugin`, the tables `<т>`, `<т>_seen`, `psim-<id>/state/<имя>/plugin`,
the requests, the event log of the unit. The adapter MUST write only `<т>_seen` and `<т>_events` (`worker.writes`), the state, the
result of requests and the events.

### Н1.1 The plugin process

- **When.** The adapter holds the unit `plugin` by placement (P/03). For a row with `enabled: false` the process MUST NOT be started,
  and the phase of the unit says «disabled» (addendum (7) item 4, addendum (8) item 3). For a parameter without `default` and
  without a value whose empty form does not pass the field's schema, the process MUST NOT be started: `unfit` with the names of the
  fields (addendum (5) item 4, addendum (8) item 1).
- **Start** — as the psim host does: the file `process_name` of the plugin directory, **without arguments**, the working directory is
  the plugin directory, the environment is the adapter's without `PLATFORM_ENDPOINT`, `PLUGIN_CLIENT_ID`, `PLUGIN_CLIENT_SECRET`
  (they would replace `stdin`).
- **`stdin`** — two frames and an empty line, exactly as the psim host (psim-sdk): `grpc-channel {"serverEndpoint":"127.0.0.1:<порт>"}`
  and `client-credentials {"client_id":"…","client_secret":"…"}`, then `\n`. The port is the adapter's `Platform` server (Н1.2); the
  channel is without TLS: loopback only. The credentials are new at every start, 32 random bytes in hex for each field, kept only in
  the adapter's memory (addendum (10) item 2). After the frames `stdin` MUST stay open until the end of the process — it is the
  lifeline: if the adapter dies, the plugin sees EOF. The adapter MUST NOT send `stdin` commands (`setloglevel` and the like).
- **`stdout`, `stderr`** — go into the worker log: a JSON line — as is, with the field `plugin`; any other line — in the field `raw`;
  `stderr` — at the level `error`. They do not go into the event log.
- **Readiness.** `Register` MUST come no later than 10 s after the start; then `grpc.health.v1.Health/Check` of the service
  `psim.platform.v1.Plugin` once every 1 s until `SERVING`, no longer than 15 s; afterwards once every 5 s, and three failures in a row
  take the process down. If the plugin does not make it in time, the adapter MUST take the process down (`SIGKILL`) and restart it by
  Н1.7 (the numbers are those of the psim emulator `c3d9ebb`).
- **Stop** of the unit or the worker — `Plugin.Shutdown`, wait for the exit up to `worker.stop_timeout` of the manifest (20 s), then
  `SIGKILL`.

### Н1.2 The `Platform` server

The adapter listens on `127.0.0.1:<свободный порт>` and answers `psim.platform.v1.Platform`:

| Call | The adapter's answer |
|---|---|
| `Authenticate` | the pair of Н1.1 and `plugin_id` of this plugin — an opaque token, `expires_in` 900 s; another pair — `UNAUTHENTICATED`, an empty field — `INVALID_ARGUMENT`. There is no refresh: on `UNAUTHENTICATED` the plugin logs in again |
| `Register` | `session_id`, `platform_version` and `api_version` of the emulator `c3d9ebb`; `plugin_endpoint` — the plugin's address, the adapter calls it on `127.0.0.1` with the same port; a second `Register` in a live session — `ALREADY_EXISTS` |
| `RegisterResource` | the resource is in `provides` and it is a `PROXY` — its `location` becomes the target of the door route (Н1.6); otherwise — `FAILED_PRECONDITION` |
| `UnregisterResource` | the route has no target: 502 until a new `RegisterResource` |
| `ListObjects`, `ListChildren`, `GetObject` | the rows of the tables of its own kinds and of the kinds of the `source` owners (Н1.5), the fields — the parameters under psim names (Н1.3), `readonly` — from `<т>_seen`; not found — `NOT_FOUND`; a type outside its own and outside `source`, a `source` type without an installed owner — `PERMISSION_DENIED` (addendum (12)); there are no masks and no pages, as with the emulator |
| `PullEvents` | events of its own kinds — from the stream of its own plugin (Н1.5), of the kinds of the `source` owners — from their rings `<т>_events` (Н1.5) by the selectors (OR between selectors, AND within one); an empty list — `INVALID_ARGUMENT`; `resume_after_sequence` is not kept: every stream starts from the current moment, a limit |
| `SendCommand` | an object of its own kind — Н1.5 by its own table; of a kind of a `source` owner — a request into the owner's `requests` (`worker.requests`) and its result; any other type — `PERMISSION_DENIED` |
| `UpdateObject` | only the `readonly` parameters of the object: the row `<т>_seen` (addendum (10) item 2); other fields — `INVALID_ARGUMENT` |
| `CreateObject`, `DeleteObject` | `UNIMPLEMENTED`, as the emulator does (addendum (10) item 2) |

- Every call except `Authenticate` MUST carry `authorization: Bearer <token>`; every call except `Authenticate` and `Register` MUST
  carry `x-session-id` of a live session. Missing or foreign — `UNAUTHENTICATED`.
- The adapter MUST NOT call `CanCreateChild`: the object row is written by the console door, the adapter has no veto, a limit
  (addendum (10) item 2).

### Н1.3 Parameters: `Configure`

- **When.** After `SERVING` and before the first `ChangeUnit` of every session; again — at every new revision of the row
  `psim-<id>/units/plugin`, except an edit of `enabled` alone.
- **What.** `params` — a full snapshot of the unit's fields except `plugin` and `enabled`, under psim names: the suffix `_secret` is
  removed, the value of a secret goes in plain text (psim intends it so: a Struct without a mask); `granted` — empty (we have no
  `requires`). An empty field goes as the empty form of its type (`""`, `0`, `false`, `[]`): the plugin cannot tell an unset field
  from an empty one, a limit.
- **The answer** `INVALID_ARGUMENT` or `FAILED_PRECONDITION` — `unfit` with the plugin's error text, objects are not passed, the
  process stays; the next revision of the row — a new `Configure` (addendum (8) item 1). `INTERNAL`, a broken connection — a restart
  by Н1.7.
- **The plugin's `readonly` parameters** are `unit.state.<имя>`: the adapter writes them on `UpdateObject` with a reference to the
  plugin itself (`type` empty, `id` — `plugin`); otherwise they would have nowhere to come from.

### Н1.4 Objects: `ChangeUnit`

- **Session start.** After `Configure` — `INITIAL` for every live row of the kinds' tables, a parent before its child (the order
  `parent` of chapter 1 Н1.2, within a level — by key); the plugin silently loses a child without a parent (the analysis of the
  psim-sdk devices).
- **Then** — by the change feed of its own tables (P/06.1 `/changes`): a new row — `NEW`, a new revision — `UPDATE`, a tombstone —
  `DELETE` with an empty `object`. A child row whose parent has not been passed yet waits for the parent.
- **`Unit`** — `object {type: <type psim>, id, plugin_id}`, `parent` — a reference to the parent or empty, `params` — the fields of
  the row `<т>` under psim names without `id`, `plugin`, `parent`; `readonly` — from `<т>_seen`.
- **An error** of `ChangeUnit` — the object stays in the row, its status in `<т>_seen` does not change; the adapter retries at the
  next revision of the row or in a new session. `DELETE` concerns only the plugin's memory.
- **`<т>_seen`.** On `NEW` the adapter MUST first overwrite the row `<т>_seen` of the same key with empty `readonly` (addendum (19)
  item 3). A row without `<т>` it does not delete: an orphan is a limit (addendum (17)).

### Н1.5 Commands and events

- **A command** is the row `psim-<id>/requests/<rid>` `{action: <т>.<cmd>, object, params?}` (chapter 1 Н1.5). The adapter calls
  `Plugin.SendCommand` with `Command {object: {type, id, plugin_id}, id: <cmd>, uuid: <rid>, params}`. The result goes into the
  label (P/06.4 Н1.5): the transport is not OK — `failed` with the gRPC code; `success: false` — `refused` with `error_code`,
  `error_message`; otherwise — `done` with `result`. The object is not in the table — `refused` `object not found` without a call.
- **Events.** `Plugin.PullEvents` is opened after `ChangeUnit(INITIAL)` of every session. An `EventMessage` is a row of the event log
  of the unit `plugin` (P/03.6 Н1.2): the kind `<т>.<event id>`, the field `object` — the object's id, `params` — the fields of the
  row, the class — by the `severity` of the kind (chapter 1 Н1.5). The same event is a row of the ring `<т>_events` with the next
  `seq` of the kind (chapter 1 Н1.2; addendum (13) item 1). After a restart and a move of the holder the first `seq` is the greatest
  `seq` of the ring + 1, for an empty ring — 0 (review finding «М» of addendum (15)): the number does not repeat while the ring is
  intact. If the kind is not in the plugin's manifest, the row is not written; the worker log notes it. If the stream broke — a new
  stream in the same session; repeats of psim events after a break are possible, a limit (the plugin does not keep
  `resume_after_sequence`).
- **A foreign plugin.** A plugin's command to an object of a `source` owner is a request into the owner's `requests` (Н1.2); the
  owner's events are the new rows of its ring `<владелец>/<т>_events` (`worker.reads`, chapter 1 Н1.6) in increasing `seq` from the
  moment the stream is opened; the adapter MUST read the ring by polling no less often than once every 1 s while a stream with this
  type is open (a decision of «Спецификация VMS», finding М4 of the norms review). An event evicted from the ring before it is read
  the dependent plugin will not see: the limit is the ring (addendum (13) item 1). A gap in `seq` between the one read and the next
  that is greater than `PSIM_EVENTS_RING` is an eviction: the dependent plugin adds the number of skipped events to the heartbeat
  counter `ring_lost` (the name is a decision of «Спецификация VMS»; review finding «М» of addendum (15)) and reads on. There is no
  other path to a foreign plugin (addendum (10) item 1).

### Н1.6 The page door

- **Routes** are `door.routes` of chapter 1 Н1.6. A request to a resource route goes to its `location` (Н1.2) with the tail of the
  path and the query, except `t`; WebSocket — straight through. No target — 502.
- **Headers** (addendum (16) item 1, addendum (18) item 1, addendum (19) item 2). Before forwarding, the door MUST remove `Cookie` and
  `Authorization` of the request entirely: the console cookie `w2c_token` (`Path=/`, host without port) and the cookies of other
  plugins MUST NOT go to foreign code. In the plugin's answer and in the answer of the WebSocket handshake the door MUST remove
  **all** `Set-Cookie`: the page session is only the door's own cookie.
- **Entry** (addendum (2) item 8). The first address is `…/<маршрут>/…?t=<токен двери>`: the console token from
  `GET /psim-<id>/where/plugin` (P/06.5 Н3 «`/where/<id>`»), the check is the door token contract at the holder (P/03.4 Н3
  «токен двери у держателя»). A valid one — the answer 303 to the same address without `t` and `Set-Cookie: psim_<plugin_id>=<сеанс>; HttpOnly; Secure; SameSite=Strict;
  Path=/<маршрут>/`, without `Domain` (addendum (16) item 1, addendum (19) item 2).
  The page session is 128 random bits in the adapter's memory with `user`, the `routes` of the token and a lifetime of 3600 s from
  the entry (a decision of «Спецификация VMS»: the door token lives 120 s, and the page lives longer). A restart of the adapter
  erases the sessions: 401, the page is opened anew from the form.
- **Admittance.** A request with the cookie `psim_<plugin_id>` of a live session to a route from its `routes` passes; without it — the token from `Authorization:
  Bearer` or `?t=`; otherwise — 401. The door does not set CSP `sandbox`: a psim page goes to its door with relative `fetch`
  (addendum (2) item 8).
- **`static`** — `GET /static/i18n.js` serves the bytes of `psim_platform_emulator/webui/i18n.js` of psim-sdk `c3d9ebb` (SHA-256
  `7ef4d865fbb3265c18af5ba6b0e8bb2c6c17b1838e20794592a9f4d9c5675584`), `Content-Type: application/javascript; charset=utf-8`,
  without a token or a cookie (addendum (10) item 2): psim pages load it by an absolute path. Any other path under `static` — 404.
- **Rights.** The right is `edit` of the unit `plugin`: a resource route is `rank: edit` (chapter 1 Н1.6; addendum (16) item 2,
  addendum (19) item 1); `/where` gives a token for it by the person's rank (P/06.5, the share of «Спецификация»; until then — by
  `view`, the limit of addendum (18) item 2). A person with only `view` does not get the link «Страница плагина» — a limit. There is
  no right on an object (chapter 1 Н1.6). The page writes through its plugin's own server, not through the console API (ADR-0115
  item 4.3).

### Н1.7 Crash and restart

- An exit of the process — the session is over, the routes have no target, the unit is `failed` with the exit code; the restart is
  the `Backoff` of the base worker (P/03), there is no final stop: the plugin is not ours, it is fixed by a new version.
- The worker's metrics MUST carry `plugin_id` and `plugin_version` from `metadata` (ADR-0071 Confirmation).

## Н3 Pass

1. The row `plugin`: `enabled`, the parameters are valid → the process (Н1.1): `stdin` → `Authenticate` → `Register` →
   `RegisterResource`… → `SERVING`.
2. → `Configure` (Н1.3) → `ChangeUnit` `INITIAL`… (Н1.4) → `PullEvents` (Н1.5).
3. → the feed: an edit of `plugin` — `Configure`; an edit of `<т>` — `NEW`/`UPDATE`/`DELETE`; a request — `SendCommand`; an event —
   the log.
4. → an exit of the process — `Backoff` (Н1.7); `enabled: false` — `Shutdown`, there is no process.

**Races.** An edit of the row `plugin` during `Configure` — the next `Configure` after the answer to the current one, by the latest
revision. Two revisions of the row `<т>` in a row — `UPDATE` of the latest. A request to an object deleted before execution — `refused` `object not
found`. A child before its parent in the feed waits for the parent (Н1.4).

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| `enabled: false` | no process, phase `disabled` | the form — the plugin is switched off | switch it on by an installation step (chapter 4) |
| a parameter without a value whose empty form does not fit the schema | `unfit` with the fields | the form | set a value |
| `Configure` rejected | `unfit` with the plugin's text | the form | fix the parameters |
| no `Register` within 10 s, no `SERVING` within 15 s, three health failures | the process is taken down, `Backoff` | the worker log, the phase | — |
| a call to a type outside its own and outside `source` | `PERMISSION_DENIED` | the plugin | — (a limit) |
| `CreateObject`, `DeleteObject` | `UNIMPLEMENTED` | the plugin | — (a limit) |
| a command to an object that does not exist | label `refused` `object not found` | the form | — |
| a page without a cookie or a token, or with a foreign route | 401 | the browser | open it from the form again |
| a person with only `view` | there is no link to the page | the form | — (a limit) |

## Н5 Acceptance

The stand of chapter 4 Н5 on `security_controller` and `camera` of psim-sdk `c3d9ebb` without changes: the process comes up and
stays up, a command gets through, the event `camera` `MD_START` makes `security_controller` raise the command `REC` to the camera (a
foreign plugin), the page `setup_ui` opens by a token and does not get the console token.
