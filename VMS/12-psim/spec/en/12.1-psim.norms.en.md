# V/12.1 — Plugin layout: norms

This English text is the source; the Russian [`12.1-psim.norms.md`](../12.1-psim.norms.md) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 1 of lesson V/12 «Плагины psim» (ADR-0080; the VMS module — ADR-0090; psim plugins through an adapter — ADR-0071; the subsystem
psim and the kind description — ADR-0115 with addenda (1)–(15)). [Lecture](../../12-psim.md), [instructions](../12-psim.README.md). The platform is
the export `cammeta-specs` `7a875c75`; the loader keys of ADR-0115 — P/02.1 on the main branch of the course (Н1.6).

A psim plugin is a foreign executable with the plugin manifest `plugin.json` and the translations `langs/*.json`. With us it becomes
a subsystem: the generator (chapter 2) builds the subsystem manifest from the plugin manifest, the adapter worker (chapter 3) holds the plugin process
and plays the role of the psim platform for it. The chapter sets norms for where each word of the plugin manifest goes: the name, the unit,
the kind tables, the fields, the labels, the events, the commands, the resources, the links to other plugins. The plugin itself does not change.

Norm ids are `V/12.1-MM`; the map to former lessons is [`id-map.tsv`](../../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../../НОРМАТИВНЫЕ-СЛОВА.md). The rules of the module «Платформа» are [P/01.1 Н0](../../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Plugin manifest** — `plugin.json` by `schema/plugin.schema.json` of psim-sdk `c3d9ebb`; **subsystem manifest** — the output of
  the generator `psim-<id>.subsystem.yaml`, which the loader of P/02.1 reads (ADR-0071 addendum 2026-10-21).
- **Kind** — an `object_type` of the plugin manifest; **object** — a row of the kind's table.
- **Plugin unit** — the only unit of the subsystem, the plugin itself: its `parameters`.
- **Type owner** — the installed plugin in which this `object_type` is declared.

## Н1 Form

**Data.** The families of the subsystem follow the layout below: the unit row `psim-<id>/units/plugin`, the kind tables `psim-<id>/<т>` and
`psim-<id>/<т>_seen`, the event rings `psim-<id>/<т>_events`, the state `psim-<id>/state/<имя>/plugin`, the requests
`psim-<id>/requests/<rid>`, the event log of the unit. The lesson has no families of its own in the VMS catalogue: the tables are set by the plugin manifest, not by the lesson.

### Н1.1 Name and unit

- **Subsystem name** — `psim-` and `metadata.plugin_id` in lower case (ADR-0115 addendum (2) item 2). If it does not pass the grammar
  of `name` of P/02.1 (`[a-z][a-z0-9_-]{0,31}`) — a generator refusal.
- **Unit** — `unit.rows: units`, `unit.id: plugin` (a decision of «Спецификация VMS»). The field `plugin` is `string`, `enum: [plugin]`,
  `fixed: true`; there is one row — `psim-<id>/units/plugin`, there is no second one (addendum (5) item 4, addendum (7) item 2). The row is written by the install step
  (chapter 4), not by `POST`.
- **Unit fields** — the plugin's `parameters` by Н1.3, and the field `enabled`: `bool`, `default: true` (addendum (7) item 4). Disabling is
  `enabled: false`: the adapter does not start the plugin, the assembler removes the object kinds (chapter 4). `required` is not set on parameters:
  psim has no mark of being mandatory; readiness is judged by the adapter (chapter 3 Н1.4).
- **Install step fields** (a decision of «Спецификация VMS»): `version` — `string`, `metadata.plugin_version` of the installed
  directory; `owners` — `json`, `{<object_type>: <plugin_id>}` — the owners chosen by `install --owner` (chapter 4 Н1.2).
  They are written by the install step; the form shows them read-only (V/11), they are not passed to the plugin (chapter 3 Н1.3).
- **`readonly` parameters of the plugin** — `unit.state.<имя>` with a schema by type per Н1.3 (addendum (2) item 1). They are not among the unit fields.
- **Placement** — one unit, one adapter process per plugin: `placement: {capacity: {default: 1}}`, without `near`, `home`,
  `group_by`. A plugin with one connection to its system is held whole, by one process (ADR-0071).

### Н1.2 Kind tables

- **A kind is a table** (addendum (3) item 1). The name is `type` in lower case; if it does not pass `tableName` of P/02.1, is longer than 25 characters (otherwise
  `<т>_events` does not fit into the 32 characters of `tableName`; addendum (14), stricter than the 27 of addendum (4) item 2), or is equal to `units`, `plugin`,
  or to `<т>_seen` or `<т>_events` of another kind — a generator refusal (addendum (8) item 3, addendum (13) item 1).
- **Table fields:** `id` — the row key (`key: id`), the psim object id; `plugin` — `string`, `enum: [plugin]`, `default: plugin`,
  `ref: psim-<id>/units`: the field of the plugin unit for rights (`rights.unit_of: {<т>: plugin}`, addendum (4) item 2); a kind with `parent` has
  the field `parent`, `string`, `required: true`, `ref: psim-<id>/<т родителя>`. The other fields are the kind's `parameters` by Н1.3.
- **Roots.** A kind without `parent` is a table without the field `parent`. There is no root kind: two roots are two tables (addendum (3) item 1).
  `parent` naming a type that is not in the plugin manifest — a generator refusal.
- **`<т>_seen`** — the second table of a kind with `readonly` parameters (addendum (3) item 2): `key: id`, the field `id` with `ref: psim-<id>/<т>`,
  the field `plugin` as above, the fields are the `readonly` parameters by Н1.3. It is written by the adapter: `worker.writes`; the console writes only `<т>`.
  A `<т>_seen` row without a `<т>` row with the same key the adapter does not delete (it does not delete rows of its own table, addendum (15)): such
  an orphan is not shown by `backend`, the operator removes it — a limit (addendum (17)). A new object (`NEW`) the adapter starts by
  overwriting `<т>_seen` of the same key: the orphan does not stick to it (addendum (19) item 3).
- **`<т>_events`** — the event ring of a kind with `events` that is referenced by a `source` of a foreign installed plugin (addendum (13)
  item 1, addendum (14)); such kinds are named to the generator by the assembler (chapter 4 Н1.3), without dependants there is no ring: `key: "{slot:int}"`, the fields `slot` — `int` from 0 to
  `PSIM_EVENTS_RING` − 1, `seq` — `int`, the number of the kind's event, ascending, `event` — `<т>.<event id>`, `object` — the id of
  the object, `params` — `json`, `t` — `float`, Unix seconds, `plugin` as above. It is written by the adapter (`worker.writes`): the event `seq`
  goes into the slot `seq mod PSIM_EVENTS_RING`, over the former one; the ring does not delete rows (addendum (15)).
  `PSIM_EVENTS_RING` = 1000 (addendum (13) item 1). It is read by the adapter of the dependent plugin (Н1.6); the event log of the unit
  is written as before (Н1.5).
- **Names.** A parameter named `id`, `plugin`, `parent`, `enabled`, `version`, `owners`, with a dot, or from the forbidden field names of P/02.1 (`unit.fields`
  for plugin parameters, `tables.<имя>.fields` for kind parameters) — a generator refusal (addendum (4) item 1, addendum (6) item 3, addendum (8) item 3).

### Н1.3 Field from a parameter

| psim parameter | Subsystem manifest field |
|---|---|
| `type: string` | `string` |
| `type: integer` | `int` |
| `type: float` | `float` |
| `type: boolean` | `bool` |
| `type: array`, `items.type: string` | `list` |
| `type: array`, `items.type: integer` or `float` | `json`, `schema: {type: array, items: {type: integer \| number}}` |
| `default` | `default` of the same value |
| `pattern`, `min`, `max` | the field's `schema`: `pattern`; `minimum`, `maximum` (for `array` — on `items`) |
| `enum_values` on `string` | `enum` — the list of `value`; labels — `display.options` (Н1.4) |
| `enum_values` on `integer`, `float` | `schema.enum` (addendum (2) item 7) |
| `enum_values` on `array` | `schema: {items: {enum: […]}}` |
| `source` on `string` | `ref: <владелец>/<т>` and `ref_label: <display_field>` (default `id`; addendum (5) item 2) |
| `source` on `array` | `list` with `items.ref: <владелец>/<т>` and `ref_label` (addendum (2) item 5) |
| `hidden: true` | `hidden: true` |
| `readonly: true` | not a field: `unit.state.<имя>` for the plugin, a field of `<т>_seen` for a kind (Н1.1, Н1.2) |
| `secret: true` | the field `<имя>_secret`, only `string` (addendum (2) item 4) |

- `source.value_field` other than `id` — a generator refusal, a limit of the first stage (addendum (5) item 2). `source` on `integer`, `float`,
  `boolean` — a generator refusal: the value of `id` is a string. `source.display_field` being a `readonly` parameter of the owner (it lives in
  `<владелец>/<т>_seen`, not in `<т>`) — a generator refusal (a decision of «Спецификация VMS», М5 of the norms review). `source.provider` other than
  `platform_objects` — a refusal of the psim schema.
- **The owner of a `source`** — the **enabled** plugin in which `source.object_type` is declared, or the one chosen by `install --owner`
  (the field `owners`); the assembler finds it among the installed ones (chapter 4 Н1.3; addendum (10) item 1, addendum (16) item 3). A disabled
  plugin is never an owner: disabling the second one is the choice itself. If the type is declared in the plugin itself, the owner is the plugin itself, calls on it are served by its own adapter, there are no requests to
  itself (addendum (12)). There is no owner — the plugin is installed, the field is without `ref`, the listing of `source` is empty, calls on the type are
  `PERMISSION_DENIED` until the owner is installed (chapter 3 Н1.2). VMS cameras (`cam`) are never the owner of a psim type: `CAM` is only
  a kind of a plugin, a limit (addendum (12)).
- **Secret.** `secret` on a non-`string` — a generator refusal, a limit; `secret` and `readonly` together — a refusal (a secret is not put into `worker.writes`);
  the fields `x` and `x_secret` in one kind — a refusal (addendum (3) item 6, addendum (4) item 2). On the way back the adapter strips the suffix:
  the plugin receives the parameter under its own name (chapter 3 Н1.3).

### Н1.4 Labels and translations

- **Key and text.** A label is `{key, text}` (P/02.1 `label`): `key` — the psim `name_key`, `text` — the value of the key in
  `langs/en.json`, and if it is not there — the key itself (the psim fallback language is `en`, psim ADR-006; a decision of «Спецификация VMS»).
- **Where.** A plugin parameter — `display.fields.<поле>`, a kind parameter — `display.fields.<т>.<поле>` (addendum (3) item 3, addendum (4)
  item 1); `description_key` — `field_help` under the same name; `enum_values[].name_key` — `display.options`; an event —
  `display.kinds.<вид события>`; a kind — `display.tables.<т>` from the kind's `name_key` (ADR-0115 addendum (11); the loader key of P/02.1 is
  the share of «Спецификация»). Only for `<т>`: `<т>_seen` is not a kind, the loader rejects `display.tables.<т>_seen` («М» of the review of addendum (11)).
  If there is no kind label, `UnitKind.label` defaults to the table name (V/11); in psim `c3d9ebb` the kind's `name_key` is mandatory.
  `display.unit`, `display.units` — `plugin_id`: the plugin has no name of its own in the manifest.
- **Translations** — `display.langs.<язык>`: each `langs/<язык>.json` whole, only string values (as the psim host does).
  If the file name does not pass the language grammar of P/02.1 — a generator refusal.

### Н1.5 Events, commands, resources

- **Event** — the kind `<т>.<event id>` in `events.kinds` with the psim `severity` and a label in `display.kinds` (addendum (5) item 3, addendum (3)
  item 6). The prefix `plugin.` is for events of the plugin itself (addendum (7) item 5); psim `c3d9ebb` has no plugin events, the prefix is taken.
  **Class in the log** — `alarm` for `severity: alarm` and `critical`, otherwise (`info`, `warning`, `error`) — `observation`
  (addendum (10) item 2).
- **Command** — a request `requests`: `schema` is the object `{action, object, params?}`, `action` — the listing of `<т>.<command id>` of all
  kinds, `object` — `string`, the object id, `params` — an object; `required: [action, object]`; the result is `outcome: mark`. The adapter
  performs the request by calling `SendCommand` (chapter 3 Н1.5).
- **Resource** `provides[]` of type `PROXY` — a route of the adapter door `door.routes`: the name is `path_prefix` without the leading `/`. If it is not
  one segment by the grammar of `name`, or is `static` (the route is taken, Н1.6) — a generator refusal (addendum (10) item 2). Resources `STATIC`,
  `LINK` get no route, a limit: the psim host does not proxy `STATIC` either, and the address of `LINK` is foreign.
- **Setup page** — a resource `role: setup_ui` of type `PROXY`: its address is given by `backend` in the kind description (V/11), the list
  `object_types` is a comma-separated psim string. A resource that is not `PROXY` has no page of its own, a limit.
- **`requires`** non-empty — a generator refusal: we have no managed DBMS and APIs of psim (ADR-0071).

### Н1.6 Other keys of the subsystem manifest

- **Door** — `door.routes`: the routes of the resources of Н1.5 — `{name: <маршрут>, rank: edit}`, and `static` (chapter 3 Н1.6). `rank: edit`:
  a token for the plugin page is given only to a person with `edit` (addendum (16) item 2, addendum (19) item 1; a decision of «Спецификация VMS» —
  for all resource routes: any plugin page writes through its own server). The key `rank` is P/02.1, P/06.5, the share of
  «Спецификация»; until it exists, `/where` issues the token by `view` — a limit (addendum (18) item 2).
- **Worker** — `worker.exec: /usr/lib/psim/adapter /usr/lib/psim-<id>` (a decision of «Спецификация VMS»: one adapter for all
  plugins, the second word is the plugin directory, chapter 4 Н1.1); `worker.writes` — all `<т>_seen` and `<т>_events`.
- **Foreign plugin** (addendum (10) item 1, addendum (12)). For each installed owner of a `source`, except the plugin itself — `worker.reads`: its kind
  tables `<владелец>/<т>/`, `<владелец>/<т>_seen/` and rings `<владелец>/<т>_events/` (addendum (13) item 1: the adapter has no right
  to the log); `worker.requests: [<владелец>]`. Two owners — an install refusal (chapter 4).
- **Rights** — `rights.unit_of` for each kind table and `<т>_seen`: the field `plugin`. There is no right to a separate object of the plugin,
  only to the plugin as a whole, a limit (addendum (3) item 4).
- **Fragment for `backend`** — chapter 2 Н1.3.

## Н2 Doors

The chapter has no doors of its own: rows — the console door (P/06.1), routes — the adapter door (chapter 3 Н1.6).

## Н3 Pass

```
plugin.json + langs/ → name (Н1.1) → unit and fields (Н1.1, Н1.3) → kind tables and <т>_seen (Н1.2) → labels (Н1.4)
  → events, commands, resources (Н1.5) → door, worker, links to the owners of source, rights (Н1.6) → subsystem manifest
```

**Races.** None: the layout is a pure function of the plugin manifest, the translations and the list of installed plugins (chapter 2).

## Н4 Refusals

Each row is a generator refusal (chapter 2 Н1.2): the subsystem manifest is not built, the installation does not go on.

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| the subsystem name is not by the grammar | refusal, `plugin_id` | the installing operator | — (the plugin is not ours) |
| the kind table name is not by `tableName`, longer than 25, `units`, `plugin`, collides with `<т>_seen`, `<т>_events` | refusal, `type` | operator | — |
| a parameter `id`, `plugin`, `parent`, `enabled`, `version`, `owners`, with a dot, a forbidden field name | refusal, the kind and the parameter | operator | — |
| `parent` naming an undeclared type | refusal, `type` | operator | — |
| `secret` not on `string`, `secret` with `readonly`, `x` and `x_secret` | refusal, the parameter | operator | — |
| `source.value_field` other than `id`, `source` neither on `string` nor on `array`, `display_field` is a `readonly` of the owner | refusal, a limit of the first stage | operator | — |
| `path_prefix` is not one segment of `name`, or is `static` | refusal, the resource | operator | — |
| `requires` non-empty | refusal | operator | — |
| a `langs/` language not by the grammar | refusal, the file | operator | — |
