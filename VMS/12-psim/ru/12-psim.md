# Урок V/12. Плагины psim

## Зачем этот урок

Плагин psim пишут другие люди. Это исполняемый файл и манифест `plugin.json`: какие объекты он ведёт, какие у них параметры,
события и команды, какие у него страницы. Мы хотим, чтобы такой плагин работал у нас без правки плагина, без правки платформы
и без ручного экрана в консоли под каждый новый плагин.

## Цели и не-цели

Цели:
- плагин становится подсистемой VMS: права, события, команды и страницы идут через загрузчик и обычные двери;
- страница настройки объекта плагина строится сама по описанию вида;
- новый плагин ставится на работающий кластер одной командой.

Не-цели:
- плагины с управляемой базой или API psim (`requires`) — их у нас нет;
- права на отдельный объект плагина — только на плагин целиком;
- полное удаление плагина с данными.

## Что нужно знать заранее

Манифест подсистемы и загрузчик (P/02.1), установка манифеста (P/02.3), базовый воркер (P/03), просьбы и журнал событий
(P/06.4, P/03.6), токен двери (P/06.5). Описание вида в консоли — V/11.

## Глава 1. Раскладка плагина

Каждое слово манифеста плагина должно куда-то лечь. Плагин целиком — одна единица подсистемы, его параметры — её поля. Вид
объектов — таблица, объект — строка. Параметр, который пишет сам плагин (`readonly`), лежит отдельно: консоль пишет одну
таблицу, адаптер — другую, и у каждой строки один писатель. Подписи остаются ключами перевода плагина, переводы — его же
файлы `langs/`. Событие получает имя `<kind>.<id>`, чтобы одинаковые id разных видов не сливались. Тревогой у нас становятся
только `alarm` и `critical`: слово `alarm` psim и класс тревоги VMS совпадают только по написанию.

Самое тонкое — связи плагинов друг с другом. `security_controller` ставит на запись камеру другого плагина, когда та видит
движение, но в его манифесте об этом ни слова: камера названа только как источник значений параметра. По этому источнику
мы и связываем плагины. Связь заводится при установке, когда владелец типа известен; если владельца ещё нет, плагин ставится
без связи и получает её, когда владелец придёт.

Точные правила — [нормы главы 1](spec/12.1-psim.norms.md).

## Глава 2. Генератор

Генератор — функция: одинаковый вход даёт одинаковый выход. Он проверяет манифест плагина по схеме psim, раскладывает его
и отдаёт два результата: манифест подсистемы и список дверей, которые понадобятся `backend`. Сам он ничего не ставит, и
поэтому его можно проверить векторами: вход, выход, отказ.

Точные правила — [нормы главы 2](spec/12.2-psim.norms.md).

## Глава 3. Адаптер

Для плагина адаптер — платформа psim. Он запускает процесс так же, как это делает хост psim: без аргументов, с адресом и
учёткой в `stdin`. Учётку он придумывает на каждый запуск и держит в памяти: она нужна только между адаптером и его ребёнком.
Дальше всё по протоколу psim: параметры — `Configure`, объекты — `ChangeUnit`, родитель раньше ребёнка, команды —
`SendCommand`, события — поток `PullEvents`. Где протокол молчит, мы делаем как эмулятор psim: плагины писали под него.

Страница плагина — чужой код, поэтому она живёт на двери адаптера, а не под консолью, и прав консоли не получает. Вход —
короткий токен консоли в адресе; дверь меняет его на свою куку и убирает токен из адреса. Токена в `#` нет и `sandbox` нет:
страница psim ходит на свою дверь обычными относительными запросами, и то и другое её бы сломало.

Точные правила — [нормы главы 3](spec/12.3-psim.norms.md).

## Глава 4. Установка

`backend` зовёт консоль только по закрытому перечню своего манифеста. Новому плагину нужны новые двери, поэтому установка
ставит две ревизии: манифест плагина и манифест `backend`. Последний не правится, а каждый раз собирается заново из канона
и фрагментов всех установленных плагинов. Так вторая установка не затирает первую, а обновление VMS не отрезает плагины.
Цена — `backend` перезапускается при каждой сборке.

Плагин не удаляют, а выключают: данные остаются, повторное включение видит прежние объекты. Начальное значение параметра
спрашивают, только если без него строка не пройдёт схему. Секрет вводят руками, в файле значений его быть не должно.

Точные правила — [нормы главы 4](spec/12.4-psim.norms.md).
