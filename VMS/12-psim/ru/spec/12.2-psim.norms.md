# V/12.2 — Генератор: нормы

Текст производный от en, руками не правится: источник — английский [`en/12.2-psim.norms.en.md`](en/12.2-psim.norms.en.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Канон главы 2 урока V/12 «Плагины psim» (ADR-0071; ADR-0115 доп. (5) п. 1, доп. (6) п. 1, доп. (7) п. 1, доп. (10) п. 1).
[Лекция](../12-psim.md), [инструкция](12-psim.README.md). Платформа — выгрузка `cammeta-specs` `7a875c75`.

Генератор — чистая функция: из каталога плагина и списка установленных плагинов он строит манифест подсистемы по
раскладке главы 1 и фрагмент `calls` для манифеста `backend`. Сам он ничего не устанавливает: его зовёт шаг установки
(глава 4), и только там результат попадает в хранилище. Глава нормирует вход, проверку, выход и отказы.

Id норм — `V/12.2-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Слова урока — глава 1 Н0.

- **Каталог плагина** — исполняемый файл `process_name` (умолчание `plugin`), `plugin.json` и `langs/*.json` рядом
  (так их ищет сам плагин: чтение манифеста и переводов psim-sdk).
- **Список установленных** — у каждого установленного плагина его `type`, типы `source` его параметров, `enabled` и `owners`
  строки `plugin`: `{plugin_id → {types, sources, enabled, owners}}`; его даёт сборщик (глава 4 Н1.3). По `sources` чужих плагинов генератор
  заводит кольцо `<т>_events` своего вида (глава 1 Н1.2; доп. (14)).

## Н1 Форма

**Данные.** Своих семей у главы нет. Вход и выход — файлы; векторы — [`vectors/generate`](../vectors/generate/README.md).

### Н1.1 Вход и проверка

- **Вход:** `plugin.json`, все `langs/<язык>.json`, список установленных. Других входов нет: время, окружение, имя
  машины на выход не влияют. Одинаковый вход — одинаковый выход.
- **Схема psim.** `plugin.json` проверяется по `schema/plugin.schema.json` psim-sdk `c3d9ebb` (JSON Schema draft-07, лишние
  ключи запрещены). Не проходит — отказ `plugin.json is not a psim manifest: <путь>: <ключевое слово>`. Плагин с другой
  схемой — новый пин psim-sdk, не правка генератора.
- **Переводы.** Каждый `langs/<язык>.json` — объект ключ → значение. Нестроковые значения отбрасываются, как у хоста psim
  (psim-sdk), файл не JSON-объект — отказ.
- **Раскладка** — по главе 1; её отказы — глава 1 Н4.

### Н1.2 Выход

1. **Манифест подсистемы** `psim-<id>.subsystem.yaml` по главе 1. Его грузит строгий загрузчик P/02.1 без правок: отказ
   загрузчика на выходе генератора — ошибка генератора, а не плагина.
2. **Фрагмент `calls`** для манифеста `backend` (доп. (5) п. 1, доп. (7) п. 1) — список дверей обратного вызова P/06.3 Н1.9:

   ```yaml
   plugin:   psim-<id>
   enabled:  [psim-<id>/units, GET psim-<id>/where, GET manifest/psim-<id>/source]   # вид экземпляра, страница, описание вида — всегда
   objects:  [psim-<id>/<т>…, GET psim-<id>/<т>_seen…, psim-<id>/requests]  # виды объектов — только включённого
   ```

   `psim-<id>/units` — чтение и запись параметров плагина `/units` по билету (доп. (7) п. 1); `GET psim-<id>/where` — адрес и
   токен двери страницы (глава 3 Н1.6); `GET manifest/psim-<id>/source` — полный вид манифеста для описания вида (V/11.14 Н1.1); `<т>` — объекты, `<т>_seen` — только чтение, `requests` — команды. Деление на
   `enabled` и `objects` — для выключения: сборщик берёт `objects` только у плагина с `enabled: true` (доп. (8) п. 2).
3. **Владельцы `source`** (доп. (10) п. 1, доп. (16) п. 3). Тип из `source` — по `owners` своей строки, иначе среди
   **включённых** плагинов списка: найден у одного — владелец он (глава 1 Н1.3, Н1.6); у двух и больше без `owners` — отказ
   `object type <T> has two owners: <a>, <b>`; `owners` называет плагин, у которого типа нет, — отказ; `owners`, названный выключенным
   плагином, не судится, а `owners`, называющий выключенный плагин, — «владельца нет» (ADR-0115 доп. (20) п. 2; М2 ревью норм
   слияния): второго включённого владельца молча не берут; ни у кого — поле без `ref`,
   `items.ref`, `ref_label` и без чтений и просьб к владельцу. Тип появится позже — сборщик перестроит манифест тем же
   проходом (глава 4 Н1.3).

### Н1.3 Отказ

Отказ — одна строка `psim: <plugin_id>: <причина>` и ничего не построено: ни манифеста, ни фрагмента. Причины — Н1.1, Н1.2 п. 3
и глава 1 Н4. Первый отказ по порядку раскладки (глава 1 Н3) — единственный.

## Н3 Проход

```
вход (Н1.1) → схема psim → переводы → раскладка (глава 1) с владельцами source (Н1.2 п. 3)
  → манифест подсистемы и фрагмент calls (Н1.2) | отказ (Н1.3)
```

**Гонки.** Нет: генератор — функция входа.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| `plugin.json` вне схемы psim | отказ, путь и ключевое слово | оператор установки | — |
| файл `langs/` не JSON-объект | отказ, файл | оператор | — |
| отказ раскладки (глава 1 Н4) | отказ, причина | оператор | — |
| тип `source` у двух установленных плагинов | отказ, тип и владельцы | оператор | снять один из владельцев |
