# V/12 Плагины psim — инструкция для реализации

Что строит реализация урока и как проверить результат. Канон — нормы глав `12.K-psim.norms.md`; эта инструкция их не
дополняет. Платформа — выгрузка `cammeta-specs` `7a875c75`; ключи загрузчика ADR-0115 — P/02.1 курса.

Текст производный от `spec/12-psim.README.md`, руками не правится: источник — английский [`spec/12-psim.README.md`](../../spec/12-psim.README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

## Входы и их приоритет

- Канон — нормы глав `12.K-psim.norms.md` (Н1–Н5 каждой главы; адреса `V/12.K Н…`).
- psim-sdk `c3d9ebb`, только для чтения: `schema/plugin.schema.json` (вход генератора), `proto/psim/platform/v1/*.proto`
  (протокол адаптера), `psim_platform_emulator/` (поведение хоста, где proto молчит), `psim_plugins/cmd/security_controller`,
  `camera` (приёмка). Байты `psim_platform_emulator/webui/i18n.js` — SHA-256
  `7ef4d865fbb3265c18af5ba6b0e8bb2c6c17b1838e20794592a9f4d9c5675584`.
- Дверь адаптера — [`12-psim.api.openapi.yaml`](../../spec/12-psim.api.openapi.yaml).
- Векторы генератора — [`vectors/generate`](../vectors/generate/README.md).
- Лекция (`ru/12-psim.md`, для человека, в выгрузку не входит) объясняет причины.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/12.1 | раскладка `plugin.json` → манифест подсистемы `psim-<id>`: единица `units/plugin`, таблицы видов и `<т>_seen`, поля из параметров, подписи `{key, text}` и `display.langs`, события `<т>.<id>` с классом по `severity`, команды просьбой, маршруты ресурсов `PROXY`, чтение и просьбы к владельцам `source` | векторы `generate` |
| V/12.2 | генератор — функция каталога плагина и списка установленных; проверка по схеме psim; манифест и фрагмент `calls` для `backend`; отказ одной строкой | векторы `generate` |
| V/12.3 | воркер-адаптер: процесс плагина как хост psim (`stdin`, учётка в памяти, готовность), сервер `Platform` на петле, `Configure`, `ChangeUnit`, команды и события, дверь страницы со входом по `?t=`, кукой сеанса и `static` | стенд |
| V/12.4 | шаг `psim` (`install`, `enable`, `disable`, `sync`): начальные значения, сборка манифеста `backend` из канона и фрагментов каталога, пересборка зависимых плагинов | стенд |

## Порядок

Сначала ключи загрузчика P/02.1 (ADR-0115; `display.tables` — доп. (11)), затем генератор и его векторы, затем адаптер и
шаг установки, затем стенд. `backend` строит описание вида плагина по V/11.

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/12.1 Н1.1 | ставить `required` параметрам | готовность судит адаптер (`unfit`), не консоль |
| V/12.1 Н1.3 | класть `readonly` в поля строки | `unit.state` у плагина, `<т>_seen` у вида: консоль их не пишет |
| V/12.2 Н1.2 | собирать `backend` из файлов генератора | фрагменты — из строк каталога `platform/manifest/psim-*` |
| V/12.3 Н1.1 | передавать адрес и учётку окружением | только кадры `stdin`; переменные psim не наследуются |
| V/12.3 Н1.3 | слать плагину `x_secret` | имя psim без суффикса, значение открытым текстом |
| V/12.3 Н1.4 | слать ребёнка раньше родителя | плагин молча его теряет |
| V/12.3 Н1.6 | ставить CSP `sandbox` или класть токен в `#` | страница psim ходит относительными `fetch` и `#` не читает |
| V/12.4 Н1.4 | принимать секрет из файла | только ввод; в файле — отказ |

## Готово, когда

Векторы `generate` проходят: манифесты грузит строгий загрузчик P/02.1 без правок; на стенде оба плагина psim-sdk работают
без правок по сценариям главы 4 Н5.

## При расхождении

Порядок источников: нормы главы → psim-sdk `c3d9ebb` (proto, затем эмулятор) → лекция. Норма молчит или противоречит себе —
вопрос «Спецификации VMS» с местом, контрпримером и предложением; новое слово манифеста — через «Архитектора» (ADR-0071).
