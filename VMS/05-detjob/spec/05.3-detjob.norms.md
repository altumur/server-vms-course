# V/05.3 — Бюджет, прогресс, события, итог: нормы

Канон главы 3 урока V/05 «Задача по интервалу архива» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../05-detjob.md),
[инструкция](05-detjob.README.md), манифест [`detjob.subsystem.yaml`](../detjob.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `db53315`.

Задача читает часы видео быстрее реального времени — значит, работает порциями, помнит, что уже прочитано, и пишет итог,
когда прочитано всё. Глава нормирует бюджет прохода, курсор, модель, события и итог. Чтение отрезка — глава 2; ожидание и
просьбы — глава 4.

Id норм — `V/05.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `t` строки события — **медийное** время кадра, не часы воркера; сроки — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — состояние
`detjob/state/cursor/<job>`, `detjob/state/result/<job>` ([P/03.6 Н1.7](../../../Platform/03-worker/spec/03.6-worker.norms.md)),
эпоху `detjob/epoch/<job>` (при взятии единицы, P/03.3), события — журнал ресурса своего сервера `detjob/<job>/e<эпоха>/`,
тревоги — `detjob.alarms/<job>/e<эпоха>/` (P/05 Н1.2); читает — тела масок `det/blobs/*`, `detjob/blobs/*`.

### Н1.1 Бюджет прохода

- За проход задача читает не больше `STRETCHES_PER_PASS` = 4 отрезков плана (глава 2 Н1.2): долгий проход оставил бы
  воркер без пульса, аренда истекла бы — второй писатель.
- Моделей одновременно воркер держит в пределах `capacity` (V/05.1 Н1.4); задача назначения без загруженной модели —
  фаза `queued` (глава 4), ёмкость не тратит.

### Н1.2 Курсор

- `unit.state.cursor` — `{revision, done: [[from, to], …], events}`: прочитанные промежутки медийного времени записи
  (объединённые, по возрастанию), строк записано, ревизия строки задачи, к которой курсор относится. Монотонен: `done`
  только растёт.
- Пишется **после** событий отрезка (сначала строки, потом отметка), не чаще `STATE_EVERY` = 10 с (P/03.6 Н1.7): после
  переезда новый держатель читает курсор и продолжает; повтор — до 10 с видео, его строки — под новой эпохой (Н1.4
  `earlier-run`).
- Курсор действует по `born` (P/03.6 Н1.7); курсор с чужой `revision` задача не применяет: правка задачи — скан заново,
  курсор перезаписывается.
- **Остаток** — `[from, to)` минус `done`, по **времени**, не по ключу и не по потоку: растущий спан меняет ключ отрезка,
  старшая эпоха забирает минуты перекрытия — прочитанное по времени не читается снова.

### Н1.3 Модель

Реестр видов — тот же, что у детектора (V/04.2 Н1.2): вида нет у воркера — `unsupported` (глава 4). Тело маски (`mask` —
`detjob/blobs/<digest>`; `mask_from` — `det/blobs/<digest>` по ссылке заказа, ADR-0091 п. 1) читается при запуске модели; не
читается — `failed` с повтором по отступу рантайма (P/03.3). Модели — кадры отрезка (`t0 ≤ ts < t1`, глава 2 Н1.3).

**Учебная `tick` в задаче** — в медийном времени: взгляд каждую секунду видео (`STEP` = 1 с, от начала отрезка), событие
`tick` на каждом третьем взгляде (каждые 3 с видео), поле `pass` — номер взгляда в отрезке; `t` — медийное время взгляда.
У детектора `tick` считает проходы (V/04.2 Н1.2): скан идёт быстрее реального времени.

### Н1.4 События

- Каждое событие модели — строка журнала писателем воркера (P/03.6 Н1.2): дерево `detjob`, единица — имя задачи, эпоха — её
  эпоха; `of: cam/<cam>` — из `about`: `/events?unit=cam/<cam>` сливает находки скана с живой детекцией (P/06.4 Н1.3), различает
  их поле `subsystem`. `t` — медийное время.
- Перед каждой записью — `may_write` (P/03.2 Н1.6). Ошибка записи — строка потеряна, счёт `events_refused`.
- Класс — по полю `alarms` задачи (V/05.1): `alarm` — в `detjob.alarms/…` с `fsync`, иначе `observation` (договор журнала
  событий «class»). Подавления нет (`events.suppress` у `detjob` не объявлен): окно подавления — по часам писателя, скан
  быстрее реального времени.
- `events.older_epochs: earlier-run` ([P/06.4 Н1.2](../../../Platform/06-console/spec/06.4-console.norms.md)): строки прежних
  эпох задачи (переезд, подмена) — прежний прогон для сравнения, не отсечённый писатель.

### Н1.5 Итог

Итог `unit.state.result` (V/05.1 Н1.3) держатель пишет один раз, CAS под стражем эпохи (P/03.6 Н1.7):

| Когда | `result` |
|---|---|
| остатка нет, ничего не пропущено (`missing` пуст), не `following` и не `fetching` (глава 4) | `{end: done, covered, asked, events}` |
| ожидание пропущенного вышло (`WAIT_MAX`, глава 4) | `{end: done, covered, asked, events, partial: […]}` |
| запуск или прогон модели не удаются до `stalled` рантайма (`RETRY_MAX`, P/03.3) | `{end: failed, covered, asked, events, why}` |

Есть действующий итог — задача не исполняется (новый держатель тоже), контроллер её снимает (`retire_when`, V/05.1).

## Н3 Проход

```
задача назначения (эпоха взята при взятии): итог действует → ничего; курсор своей revision → done; иначе done = []
модель (реестр det; маска телом) → не вышло: failed (отступ); stalled → итог failed
план (глава 2) − done по времени → остаток; до 4 отрезков: прочитать → события (may_write, класс) → done += отрезок
курсор — не чаще 10 с, после строк
остатка нет и ждать нечего (глава 4) → итог done
```

**Гонки.** Подмена посреди отрезка: старый держатель дописывает строки до потери аренды, новый читает курсор (до 10 с назад)
и пишет повтор под своей эпохой — читатель видит прежнюю эпоху как `earlier-run`. Итог пишут оба (поздний повтор) — CAS
под стражем эпохи пропускает только держателя текущей эпохи.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| тело маски не читается | `failed`, отступ; `stalled` — итог `failed` | пульс, итог | маска детектора |
| модели вида нет | `unsupported` (глава 4) | пульс | модель на воркер |
| запись строки не удалась | строка потеряна, `events_refused` | пульс | ресурс |
| курсор не записался | повтор до 10 с видео после переезда | — | — |

## Н5 Приёмка

Скан учебной моделью до итога `done` — приёмка 4 (глава 4, TLS-стенд); курсор, подмена, `failed` — чтением и тестом
реализации.

## Решает реализация

Реализация обязана назвать в своём описании: **сколько моделей** воркер держит одновременно в пределах `capacity` и как
подаёт модели кадры отрезка.
