# V/05 Задача по интервалу архива — инструкция для реализации

Что реализация подсистемы `detjob` делает и как проверить результат. Канон — нормы глав `05.K-detjob.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `db53315`.

## Входы и их приоритет

- Канон — нормы глав `05.K-detjob.norms.md` (Н1–Н5 каждой главы; адреса `V/05.K Н…`).
- Канон манифеста — [`detjob.subsystem.yaml`](../detjob.subsystem.yaml): байты как есть.
- Приёмка — [глава 1](../acceptance/1/README.md); стенд и словарь — [общий README приёмки VMS](../../common/acceptance/README.md); новых требований приёмка не вводит.
- Векторы — [`mask`](../../04-det/vectors/mask/README.md) (команда пакета).
- [Лекция](../05-detjob.md) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…` (их правит не VMS).

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/05.1 | манифест `VMS/05-detjob/detjob.subsystem.yaml` грузится строгим загрузчиком без правок (вместе с `rec` — заказчиком); дверь единиц консоли исполняет объявления задачи; итог и снятие — платформа | [приёмка 1](../acceptance/1/README.md) |
| V/05.2 | `/spans` у каждой живой двери (лист `detjobworker`), `silent`/`garbled`/`unread`, план по правилу эпохи, `/samples` со `stream` у двери спана, `covered`, `written_through` | чтением (стенд TLS VMS — позже) |
| V/05.3 | бюджет прохода (4 отрезка), курсор `unit.state.cursor`, модель реестра `det` (`tick` в медийном времени), события `detjob` с медийным `t` и классом по `alarms`, итог `unit.state.result` | чтением (стенд TLS VMS — позже) |
| V/05.4 | фазы с `reason`; ожидание пропущенного (`WAIT_MAX`, `partial`, `scan.partial`), `following` (`VISIBLE_LAG_SECONDS` в `/etc/detjob/detjob.env`), `fetching` (перечень устройства, просьба дозаписи подачей); пульс | чтением (стенд TLS VMS — позже) |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam`, `rec`, `det`, затем `detjob` — приёмка
VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/05.3 Н1.5 | держать итог из-за постоянной дыры | постоянные дыры итог не держат (`covered < asked`) |
| V/05.3 Н1.2 | считать сроки ожидания от часов прохода | `waited`, `fetch_waited` — накопленные секунды в курсоре |
| V/05.3 Н1.3 | выводить ошибку маски из-за удалённого детектора отступом | у задачи — итог `failed`: детектора нет |
| V/05.1 Н1.2 | заводить вторую задачу на равное окно сценария | одна задача на окно `(cam, rec, kind, from, to)`; повтор — `unchanged` |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; приёмка глав 1 проходит на платформе, прошедшей свою приёмку; векторы урока проходят командой пакета;
пункты чеклистов, отмеченные «чтением», подтверждены описанием реализации (раздел «Решает реализация» каждой главы).
Проверка схемы, загрузчика и стенда друг друга не подменяют.

## При расхождении

Порядок источников: нормы главы → OpenAPI → приёмка и векторы → лекция; платформа — нормы выгрузки пина VMS.
Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и предложением; норма
платформы — через «Архитектора». Дефект приёмки (ожидание против нормы) — тот же маршрут; закрытое решение
вносится в канон, а не остаётся в этой инструкции.
