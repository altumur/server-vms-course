# V/05 Задача по интервалу архива — инструкция для реализации

Что реализация подсистемы `detjob` делает и как проверить результат. Канон — нормы глав `05.K-detjob.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `db53315`.

## Результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/05.1 | манифест `VMS/05-detjob/detjob.subsystem.yaml` грузится строгим загрузчиком без правок (вместе с `rec` — заказчиком); дверь единиц консоли исполняет объявления задачи; итог и снятие — платформа | [приёмка 1](../acceptance/1/README.md) |
| V/05.2 | `/spans` у каждой живой двери (лист `detjobworker`), `silent`/`garbled`/`unread`, план по правилу эпохи, `/samples` со `stream` у двери спана, `covered`, `written_through` | чтением; TLS-стенд — приёмка 4 |
| V/05.3 | бюджет прохода (4 отрезка), курсор `unit.state.cursor`, модель реестра `det` (`tick` в медийном времени), события `detjob` с медийным `t` и классом по `alarms`, итог `unit.state.result` | чтением; приёмка 4 (глава 4) |
| V/05.4 | — (переводится) | — |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam`, `rec`, `det`, затем `detjob` — приёмка
VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).
