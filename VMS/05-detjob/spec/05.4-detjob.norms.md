# V/05.4 — Ждать, следовать, просить; пульс: нормы

Канон главы 4 урока V/05 «Задача по интервалу архива» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../05-detjob.md),
[инструкция](05-detjob.README.md), манифест [`detjob.subsystem.yaml`](../detjob.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `db53315`.

Не всё видео интервала можно прочитать сразу: дверь молчит, том никто не держит, запись ещё идёт, минут нет у нас, но есть
у камеры. Глава нормирует, когда задача ждёт и сколько, когда следует за записью, когда просит дозапись, и что говорит в
пульсе. Чтение — глава 2; итог — глава 3 Н1.5; дозапись у регистратора — [V/02.8](../../02-rec/spec/02.8-rec.norms.md) Н1.4.

Id норм — `V/05.4-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Медийное время интервала и спанов; `now` — часы воркера; сроки ожидания — по курсору (переживают переезд).

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — просьбы `rec/requests/<rid>`
(`worker.requests: [rec]`, [P/03.6 Н1.5](../../../Platform/03-worker/spec/03.6-worker.norms.md)), пульс; читает — пульсы
держателей `cam/heartbeats/*` (адрес перечня архива устройства, V/01.5), строку записи `rec/recordings/<rec>` (срок,
«видно с»). Файл подсистемы `/etc/detjob/detjob.env`: `VISIBLE_LAG_SECONDS` (умолчание 600).

### Н1.1 Фазы

Элемент `status[]` задачи — под взятой эпохой (V/05.3 Н1.3); `reason` — слова подсистемы, `why` — платформы:

| `phase` | Когда |
|---|---|
| `queued` | модель ещё не загружена (V/05.3 Н1.1) |
| `running` | отрезки плана читаются |
| `waiting` | ни одна дверь не ответила (`reason` `no recorder's archive door answered`) или что-то пропущено (`missing`, Н1.2) и всё пришедшее прочитано |
| `following` | запись ещё идёт к концу интервала (Н1.3) |
| `fetching` | минуты есть у устройства, просьба дозаписи подана (Н1.4) |
| `unsupported` | вида модели нет у воркера (V/04.2) |
| `failed` | модель или маска не запускаются (отступ рантайма; V/05.3 Н1.3) |

`done` — не фаза: это итог (V/05.3 Н1.5), после него задача снимается.

### Н1.2 Ждать пропущенное

- **Никто не ответил** — плана нет, `waiting` без срока: «никто» — не «ничего».
- **Пропущено** (`missing` — тома `silent`, `garbled`, `unread`, глава 2 Н1.1): пришедшее читается, итога `done` нет, пока
  пропущенное не прочитано. Начало ожидания — поле `waiting_since` курсора (первый проход с `missing`), снимается, когда
  `missing` пуст.
- **Срок** `WAIT_MAX` = 3600 с от `waiting_since`: вышел — итог `{end: done, …, partial: [<том>@<сервер>, …]}` и одна строка
  события `scan.partial` (`missing`, `waited`; `t` — `from` интервала; класс `observation`).

### Н1.3 Следовать за записью

`following`: `written_through < to` (глава 2 Н1.4) и `now < to + FOLLOW_LAGS × VISIBLE_LAG_SECONDS` (`FOLLOW_LAGS` = 2,
`VISIBLE_LAG_SECONDS` = 600 — худший путь кадра к видимости: размер блока движка на битрейт, V/02.3). Задача читает видимое и
ждёт прироста; растущий спан не читается дважды (остаток по времени, V/05.3 Н1.2). Интервал целиком в будущем — `following`,
не `waiting`. Срок вышел (камера погасла) — итог по видимому: `covered` < `asked`. Задержка задачи — лаг видимости; «смотри
сейчас» — дело детектора (V/04).

### Н1.4 Просить дозапись

- **Дыра** — минуты `[from, to)` без спанов в плане после «видно с» записи (V/02.5 Н1.2) и до `min(to, now)`. Минуты до «видно
  с» — дыра навсегда, их не просят (решение плана 8).
- **Есть ли у устройства:** перечень архива держателя `GET <index_url>?from&to` (V/01.5; лист роли `detjobworker`; сессию
  воспроизведения не тратит): `{spans: […]}` — просить пересечение; `[]` — у устройства нет, дыра остаётся; 501 `no index` или
  ошибка — по сводке `coverage` пульса держателя, оптимистично (весь кусок дыры). Ни спанов, ни минут у устройства — `waiting`
  `reason` `nothing recorded in that interval, in any volume`.
- **Просьба** — подача воркером: строка `rec/requests/<rid>` с телом `{unit: <rec>, from, to}` кусками не длиннее суток,
  `rid` — по ключу просьб `rec` (`{unit}-{from:int}-{to:int}`; повтор — та же строка), штампы `by: detjob/<job>`, `at`, `about`
  ([P/03.6 Н1.5](../../../Platform/03-worker/spec/03.6-worker.norms.md)); исполнение — регистратор (V/02.8 Н1.4), приехавшее —
  поток `…/backfill`, план берёт его без изменений (глава 2). Исход задача не ждёт: просьбу закрывает регистратор (`fetched`).
- `fetching` держится, пока дыра есть, не дольше `WAIT_MAX` = 3600 с от первой просьбы (поле `fetch_since` курсора); вышел —
  итог `done` с `partial`. Архив устройства задача сама не читает: у него две сессии на устройство — оператора и регистратора.

### Н1.5 Пульс и ряды

Форма — [P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md); платформа кладёт ёмкость, запас, `filings`
(подача просьб, P/03.6 Н1.5). `detjob` добавляет: верх — `events`, `events_refused` (счётчики с запуска); элемент задачи —
`phase`, `reason`, `from`, `to`, `asked`, `covered`, `done_through` (наибольший конец прочитанного — полоска прогресса, не точка
возобновления), `events`, `missing` (список `<том>@<сервер>`, при пропущенном). Ряды — `jobs_running` (`console.running`),
`filings_total` (манифест).

## Н2 Двери

Своей двери у главы нет: перечень архива — дверь держателя (V/01.5), просьба — строка хранилища (P/03.6 Н1.5).

## Н3 Проход

```
никто не ответил → waiting (без срока)
missing → читать пришедшее; waiting_since; WAIT_MAX вышел → итог done + partial, событие scan.partial
written_through < to и now < to + 2·lag → following
дыры после «видно с» → перечень устройства → просьбы кусками ≤ суток → fetching; WAIT_MAX от fetch_since → итог done + partial
остатка нет, missing пуст, не following, не fetching → итог done (V/05.3 Н1.5)
```

**Гонки.** Дозапись приехала между проходами — следующий план берёт поток `…/backfill`, дыра закрыта, `fetching` снят. Две
задачи попросили одни минуты — `rid` один, строка одна. Переезд посреди ожидания — сроки идут от курсора, не заново.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| ни одна дверь не отвечает | `waiting` без срока | пульс | поднять регистраторы |
| том не прочитан час | итог `done` + `partial`, `scan.partial` | итог, события | — |
| просьба не по схеме `rec` | не подаётся, `filings.refused` | пульс | — |
| регистратор отказал просьбе | дыра остаётся; `fetching` до `WAIT_MAX` | пульс регистратора (`requests_refused`) | — |
| запись погасла | итог по видимому через 2 лага | итог | — |

## Н5 Приёмка

Каталога приёмки у урока на стенде пока нет: скан требует TLS-стенда VMS (листы `recworker`, `detjobworker`) и видимости
записи — до `VISIBLE_LAG_SECONDS` (блоки движка), сценарий с учебной моделью стал бы минутным и зависел бы от темпа сброса
блоков. Глава и главы 2, 3 проверяются чтением и тестом реализации; сценарий скана (`tick` по записи до итога `done` и
снятия) появится со стендом TLS VMS.
