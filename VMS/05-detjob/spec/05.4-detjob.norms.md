# V/05.4 — Ждать, следовать, просить; пульс: нормы

Канон главы 4 урока V/05 «Задача по интервалу архива» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../05-detjob.md),
[инструкция](05-detjob.README.md), манифест [`detjob.subsystem.yaml`](../detjob.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `db53315`.

Не всё видео интервала можно прочитать сразу: дверь молчит, том никто не держит, запись ещё идёт, минут нет у нас, но есть
у камеры. Глава нормирует, когда задача ждёт и сколько, когда следует за записью, когда просит дозапись, и что говорит в
пульсе. Чтение — глава 2; итог — глава 3 Н1.5; дозапись у регистратора — [V/02.8](../../02-rec/spec/02.8-rec.norms.md) Н1.4.

Id норм — `V/05.4-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Медийное время интервала и спанов; `now` — часы воркера; сроки ожидания — накопленная длительность в курсоре
(`waited`, `fetch_waited`, секунды; переживают переезд, Н1.2).

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — просьбы `rec/requests/<rid>`
(`worker.requests: [rec]`, [P/03.6 Н1.5](../../../Platform/03-worker/spec/03.6-worker.norms.md)), пульс; читает — пульсы
держателей `cam/heartbeats/*` (адрес перечня архива устройства, V/01.5), строку записи `rec/recordings/<rec>` (срок,
«видно с»). Файл подсистемы `/etc/detjob/detjob.env` читает воркер задачи по договору файла окружения (нет файла —
умолчания; не читается или значение не по грамматике — отказ старта, код 2; сводка — V/09.2):

| Ключ | Читает | Грамматика | Умолчание | Норма |
|---|---|---|---|---|
| `VISIBLE_LAG_SECONDS` | воркер задачи | целое ≥ 0 | 600 | Н1.3 «следовать» |


### Н1.1 Фазы

Элемент `status[]` задачи — под взятой эпохой (V/05.3 Н1, P/03.3); `reason` — слова подсистемы, `why` — платформы:

| `phase` | Когда |
|---|---|
| `queued` | модель ещё не загружена (V/05.3 Н1.1) |
| `running` | отрезки плана читаются |
| `waiting` | всё пришедшее прочитано, а итога ещё нет: ни одна дверь не ответила, что-то пропущено (`missing`, Н1.2) или дыра ждёт перечня устройства (Н1.4); `reason` — таблица ниже |
| `following` | запись ещё идёт к концу интервала (Н1.3) |
| `fetching` | минуты есть у устройства, просьба дозаписи подана (Н1.4) |
| `unsupported` | вида модели нет у воркера (V/04.2): ждёт `WAIT_MAX` по `waited` (Н1.2), затем итог `failed` «`no model <kind> on this worker`» (V/05.3 Н1.5); правка `kind` или `labels` — задача заново (V/05.1 Н1.3) |
| `failed` | модель или маска не запускаются (отступ рантайма; V/05.3 Н1.3) |

`done` — не фаза: это итог (V/05.3 Н1.5), после него задача снимается.

**Причина `waiting`** — первое выполненное условие сверху (как V/04.2 «Нет источника»); слова — контракт:

| Условие | `reason` |
|---|---|
| ни одна дверь архива не ответила (Н1.2) | `no recorder's archive door answered` |
| пропущено `n` томов (`missing`, Н1.2) | `<n> volumes missing` |
| элемент камеры в пульсе держателя не читается (Н1.4) | `cam heartbeat unreadable: <поле>` |
| свежего пульса держателя камеры нет (Н1.4) | `camera holder not heard` |

### Н1.2 Ждать пропущенное

- **Никто не ответил** — плана нет, `waiting` без срока: «никто» — не «ничего».
- **Пропущено** (`missing` — тома `silent`, `garbled`, `unread`, глава 2 Н1.1): пришедшее читается, итога `done` нет,
  пока пропущенное не прочитано.
- **Срок — накопленная длительность** в курсоре: поле `waited` (секунды, ≥ 0). Держатель прибавляет к нему приращение
  своих монотонных часов между записями курсора, пока что-то пропущено, **или** модель `unsupported` (Н1.1), **или** дыра
  ждёт перечня устройства (Н1.4); новый держатель продолжает со значения курсора.
  Время без держателя (переезд, задача не размещена) не считается: за один переезд теряется не больше `STATE_EVERY`.
  Поле обнуляется, когда ничего из этого нет. Срок вышел — `waited` ≥ `WAIT_MAX` = 3600 с.
- **Срок вышел** — сначала одна строка события `scan.partial` (`partial` — те же элементы, что у итога; `waited` — вышедший
  срок; `t` — `from` интервала; класс `observation`) под `may_write`, затем итог CAS `{end: done, …, partial: […]}` (V/05.3 Н1.5). Ошибка записи строки итог
  не задерживает — счёт `events_refused`; обрыв между строкой и итогом — новый держатель пишет строку снова (V/05.3
  «Гонки»).
- **`partial`** — только то, чего не дождались, двух видов: `<том>@<сервер>` — том, не прочитанный к сроку (здесь);
  `device:<from:int>-<to:int>` — кусок просьбы дозаписи, не приехавший к сроку, или дыра, перечня устройства для которой
  так и не было (Н1.4). Постоянных дыр в нём нет. Та же строка `scan.partial` пишется и при выходе срока `fetch_waited`
  (Н1.4).

### Н1.3 Следовать за записью

`following`: `written_through < to` (глава 2 Н1.4) и `now < to + FOLLOW_LAGS × VISIBLE_LAG_SECONDS` (`FOLLOW_LAGS` = 2,
`VISIBLE_LAG_SECONDS` = 600 — худший путь кадра к видимости: размер блока движка на битрейт, V/02.3). Задача читает видимое и
ждёт прироста; растущий спан не читается дважды (остаток по времени, V/05.3 Н1.2). Интервал целиком в будущем — `following`,
не `waiting`. Срок вышел (камера погасла) — минуты за `written_through` становятся постоянной дырой, итог по видимому:
`covered` < `asked`. Задержка задачи — лаг видимости; «смотри
сейчас» — дело детектора (V/04).

### Н1.4 Просить дозапись

- **Дыра** — минуты `[from, to)` без отрезка плана (V/05.3 Н1.2). «Видно с» строки записи (V/02.5 Н1.2) задача берёт
  только здесь. Судьба дыры:
  - до «видно с», без спана в ответе двери — **постоянная дыра**: её не ждут и не просят (решение плана 8);
  - после «видно с» и до `min(to, now)` — вопрос устройству (ниже): `{spans}`, 501 или ошибка — просьба, `fetching` до
    `WAIT_MAX`; `[]` — постоянная дыра;
  - за `written_through` — `following` (Н1.3), пока не выйдет его срок, затем постоянная дыра.

  Постоянные дыры итог не держат (V/05.3 Н1.5): просмотрено не всё — говорит `covered` < `asked`.
- **Есть ли у устройства:** перечень архива держателя `GET <index_url>?from&to` (V/01.5; лист роли `detjobworker`; сессию
  воспроизведения не тратит): `{spans: […]}` — просить пересечение; `[]` — у устройства нет, постоянная дыра; 501
  `no index` или ошибка — по сводке `coverage` пульса держателя, оптимистично (весь кусок дыры). **Перечня нет** — элемент камеры в
  пульсе держателя не читается (`index_url`, `coverage` не по форме, V/01.2 Н1.4) или свежего пульса держателя нет (договор
  наблюдения `LOST_AFTER`): не прочитан, а не отсутствует — дыра этого куска ждёт (`waiting`, `reason` по таблице Н1.1), «у
  устройства нет» не ставится, следующий пульс — снова; ожидание копит `waited` (Н1.2), по `WAIT_MAX` — `partial` элементом
  `device:<from:int>-<to:int>` на весь кусок дыры, строка `scan.partial` и итог (V/05.3 Н1.5). Все двери ответили,
  план пуст, не `following` и не `fetching` — итог `done`, `covered: 0` (V/05.3 Н1.5).
- **Просьба** — подача воркером: строка `rec/requests/<rid>` с телом `{unit: <rec>, from, to}` кусками не длиннее суток,
  `rid` — по ключу просьб `rec` (`{unit}-{from:int}-{to:int}`; повтор — та же строка), штампы `by: detjob/<job>`, `at`, `about`
  ([P/03.6 Н1.5](../../../Platform/03-worker/spec/03.6-worker.norms.md)); исполнение — регистратор (V/02.8 Н1.4), приехавшее —
  поток `…/backfill`, план берёт его без изменений (глава 2). Исход задача не ждёт: просьбу закрывает регистратор (`fetched`).
- `fetching` держится, пока дыра есть, не дольше `WAIT_MAX` = 3600 с накопленного ожидания (поле `fetch_waited`
  курсора — по правилу `waited`, Н1.2); вышел — строка `scan.partial` (Н1.2), затем итог `done` с `partial` (недошедшие куски
  `device:<from:int>-<to:int>`). Архив устройства задача сама не читает: у него две сессии на устройство — оператора и
  регистратора.

### Н1.5 Пульс и ряды

Форма — [P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md); платформа кладёт ёмкость, запас, `filings`
(подача просьб, P/03.6 Н1.5). `detjob` добавляет: верх — `events_written`, `events_refused` (счётчики с
запуска; имя `events` занято полем платформы, P/03.4 Н1.1 `platform_strings`); элемент задачи —
`phase`, `reason`, `from`, `to`, `asked`, `covered`, `done_through` (наибольший конец прочитанного — полоска прогресса, не точка
возобновления), `events`, `missing` (список `<том>@<сервер>`, при пропущенном). Ряды — `jobs_running`
(`console.running`: метрика манифеста,
которую называет `console.running`, — по её объявлению `from`, `agg`, `equals`, `live`, как любой ряд `metrics[]`, P/06.5
Н3, C06-CONSOLE-RUNNING-DEF-01), `filings_total` (манифест).

## Н3 Проход

```
никто не ответил → waiting (без срока)
missing → читать пришедшее; waited += приращение; waited ≥ WAIT_MAX → строка scan.partial, затем итог done + partial
written_through < to и now < to + 2·lag → following
дыры: до «видно с» — постоянные; после — перечень устройства → [] постоянная | просьбы кусками ≤ суток → fetching
  перечня нет (пульс держателя не читается или не слышен) → waiting; waited ≥ WAIT_MAX → scan.partial, итог done + device:
  fetch_waited ≥ WAIT_MAX → строка scan.partial, затем итог done + partial
unsupported: waited += приращение; waited ≥ WAIT_MAX → итог failed
остатка нет, missing пуст, не following, не fetching, нет дыр, ждущих перечня (постоянные не держат) → итог done (V/05.3 Н1.5)
```

**Гонки.** Дозапись приехала между проходами — следующий план берёт поток `…/backfill`, дыра закрыта, `fetching` снят. Две
задачи попросили одни минуты — `rid` один, строка одна. Переезд посреди ожидания — сроки продолжают
накопленное в курсоре, не заново; время без держателя не считается.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| ни одна дверь не отвечает | `waiting` без срока | пульс | поднять регистраторы |
| том не прочитан час | итог `done` + `partial`, `scan.partial` | итог, события | — |
| просьба не по схеме `rec` | не подаётся, `filings.refused` | пульс | — |
| регистратор отказал просьбе | дыра остаётся; `fetching` до `WAIT_MAX` | пульс регистратора (`requests_refused`) | — |
| запись погасла | итог по видимому через 2 лага | итог | — |
| у устройства минут нет (`[]`), минуты до «видно с» | постоянная дыра; итог `done`, `covered` < `asked` | итог | — |
| элемент камеры в пульсе держателя не читается | дыра ждёт, `waiting`, `reason` «`cam heartbeat unreadable: <поле>`»; по `WAIT_MAX` — `partial` `device:` | пульс, итог | — |
| свежего пульса держателя камеры нет | дыра ждёт, `waiting`, `reason` «`camera holder not heard`»; по `WAIT_MAX` — `partial` `device:` | пульс, итог | поднять держатель камеры |
| кусок дозаписи не приехал за `WAIT_MAX` | строка `scan.partial`, итог `done` + `partial` `device:` | итог, события | — |
| модели вида нет час | итог `failed` «`no model <kind> on this worker`» | итог | модель на воркер, новая задача |

## Н5 Приёмка

Каталога приёмки у урока на стенде пока нет: скан требует TLS-стенда VMS (листы `recworker`, `detjobworker`) и видимости
записи — до `VISIBLE_LAG_SECONDS` (блоки движка), сценарий с учебной моделью стал бы минутным и зависел бы от темпа сброса
блоков. Глава и главы 2, 3 проверяются чтением и тестом реализации; сценарий скана (`tick` по записи до итога `done` и
снятия) появится со стендом TLS VMS.
