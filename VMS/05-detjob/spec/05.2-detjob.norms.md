# V/05.2 — Чтение интервала: нормы

Канон главы 2 урока V/05 «Задача по интервалу архива» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../05-detjob.md),
[инструкция](05-detjob.README.md), манифест [`detjob.subsystem.yaml`](../detjob.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `db53315`.

Видео задачи лежит в томах, которые держат регистраторы, — иногда в нескольких, в разных эпохах и на разных серверах.
Глава нормирует, у кого задача спрашивает, что записано за интервал, как отличает «никто не ответил» от «записи нет», как
строит план и читает каждый отрезок. Двери архива для процессов — [V/02.5](../../02-rec/spec/02.5-rec.norms.md) Н1.4, Н2;
правило эпохи — V/02.5 Н1.3; работа по плану — глава 3.

Id норм — `V/05.2-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Секунды Unix медийного времени; сроки вопросов — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — пульсы регистраторов
`rec/heartbeats/*`, таблицу `rec/volumes/*`, строку записи `rec/recordings/<rec>` (`worker.reads`, V/05.1).

### Н1.1 У кого спросить

**Живая дверь** — регистратор, чей читаемый пульс менялся за `LOST_AFTER` = 45 с по часам задачи (P/03.4 Н1.1) и чей
верх пульса несёт непустой `volume` (V/02.4 Н1.8); адрес — поле `url` его пульса. `url` или `volume` не по форме семьи
`rec-heartbeat-words` (V/02) — не прочитан, а не отсутствует: дверь на проходе не живая, её том — `unread`. Регистратор без тома
(`servers: distinct`, V/02.1 Н1.3; `volume: ""`) — штатный случай, не молчание: его не спрашивают. Задача спрашивает
**каждую** живую дверь: `GET /spans/<rec>?from=<from>&to=<to>` (V/02.5 Н1.4), лист роли
`detjobworker` (V/02.5 Н2; без комплекта процессные маршруты закрыты — 401 `no_role`, задача читать не может), срок вопроса
`ASK_WAIT` = 5 с. Ответы складываются множеством: один спан от двух дверей — один.

| Исход двери | Слово | Что значит для задачи |
|---|---|---|
| `{spans: […]}` | ответила | её спаны — в план |
| 503 `no volume open here` | тома нет | у двери тома нет (V/02.5 Н1.4): не `silent`, в `missing` не идёт; том, который никто не держит, ловит `unread` |
| нет ответа за 5 с, иной не 200, тело не `{spans: […]}` | `silent` | её тома не прочитаны |
| спан не разбирается (не числа, `end ≤ start`, нет `epoch`) | `garbled` | спан пропущен, его том не прочитан |
| включённый том `rec/volumes/*` без живого держателя, у которого есть хотя бы одна строка пульса `rec/heartbeats/*` (даже несвежая) с `volume` — этот том и элементом записи `<rec>` в `status[]` | `unread` | том не прочитан; таких строк нет — не `unread` |

**Никто не ответил** (`None`) — не «записи нет» (`[]`): ответ «ничего не записано» даёт только ответившая дверь. Время в
плане — из спанов, не из `current_epoch` двери: эпоха — в имени потока.

**Строка записи.** `rec/recordings/<rec>` нет или стоит надгробие — итог `failed` (V/05.1 Н1.1 «Правила держателя»):
чья это запись, сверить нечем. Строка не читается своей формой или хранилище не ответило — не «нет записи»: `waiting`,
`reason` `recording <rec> unreadable`, срок — `waited` (глава 4 Н1.2). `retention_days` не конечное неотрицательное
число — «видно с» = `now` (запасной исход V/02.5 Н1.2): дыры до него — постоянные (глава 4 Н1.4).

### Н1.2 План

Из спанов — отрезки по правилу «один момент — одна эпоха» (V/02.5 Н1.3 `authoritative`: элементарный промежуток — старшему по
`(epoch, live)`, при равной эпохе живой побеждает дозаписанный, копия `e0` проигрывает любой эпохе; отсечённая
`fenced` проигрывает и берётся только там, где её не покрывает старшая): отрезок `{stream, door, t0, t1}` — поток
(`<epoch>` или `<epoch>/backfill`), дверь,
назвавшая спан, и `[t0, t1)` — пересечение спана с `[from, to)`. Ключ отрезка — `<stream>@<t0>-<t1>` (три знака после точки).
План строится из спанов ответа двери **как есть**: дверь уже режет ответ по видимому множеству (V/02.5 Н1.2:
`[видно с, ∞)` с удержаниями), задача его повторно не режет. «Видно с» строки записи задача берёт только для дыр
(глава 4 Н1.4).

### Н1.3 Чтение отрезка

`GET /samples/<rec>?from=<t0>&to=<t1>&stream=<stream>` — у **той** двери, что назвала спан (без `stream` дверь решает эпоху
только по своему тому и может отдать другую). Ответ — записи SMPL подряд (договор `obsd` «Время и запись SMPL»), с подводкой
от ключевого кадра до `t0`; задача отдаёт модели кадры, у которых `t0 ≤ ts < t1` (`accepts`), подводку — только декодеру.
Обрыв или отказ двери посреди отрезка — отрезок не прочитан (глава 3: остаток), дверь — `silent` до следующего вопроса.

### Н1.4 Сколько и докуда

- `covered` — сумма секунд прочитанных отрезков: «просмотрено 40 из 60» — не «за 20 секунд ничего не случилось».
- `written_through` — конец последнего видимого спана записи: докуда запись есть сейчас; по нему — «следовать за записью»
  (глава 4).
- `asked` — `max(0, to − from)`; при `to ≤ from` модель не запускается (V/05.1 Н1.1, итог `failed`).

## Н3 Проход

```
строки rec/recordings/<rec> нет или надгробие → итог failed (V/05.1 Н1.1); to ≤ from → итог failed
строка не читается или хранилище молчит → waiting «recording <rec> unreadable», waited; WAIT_MAX → итог failed
живые двери (пульс 45 с, volume непуст) → /spans у каждой, 5 с → множество спанов
  503 «тома нет» — не silent; silent, garbled; unread — том без держателя, чья последняя строка пульса называла запись
никто не ответил → не план (глава 4: waiting)
план: правило эпохи → отрезки {stream, door, t0, t1} ∩ [from, to)
отрезок (глава 3, бюджет прохода): /samples со stream у своей двери → кадры t0 ≤ ts < t1 → модель
```

**Гонки.** Том сменил держателя между `/spans` и `/samples` — дверь, назвавшая спан, отвечает 503 `no volume open here`:
отрезок не прочитан, следующий проход спросит снова. Спан вырос между вопросами — ключ отрезка иной, остаток считается по
времени и записи, не по ключу (глава 3).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| ни одна дверь не ответила | плана нет, `waiting`; по `WAIT_MAX` — итог `failed` (глава 4 Н1.2) | пульс, итог | поднять регистраторы |
| дверь молчит, ответ не по форме | `silent`, её тома не прочитаны | пульс (`missing`, глава 4) | — |
| спан не разбирается | `garbled`, спан пропущен | пульс | — |
| том без живого держателя, последняя строка пульса называла запись | `unread` | пульс | поднять регистратор |
| `url` или `volume` пульса регистратора не по форме | дверь не живая, том — `unread` | пульс | исправить регистратор |
| у двери тома нет (503 `no volume open here` на `/spans`) | не `silent`, в `missing` не идёт | — | — |
| строки записи `rec` нет или надгробие | итог `failed` «`no recording <rec>: …`» | итог задачи | новая задача на живую запись |
| строка записи не читается, хранилище не ответило | `waiting` `recording <rec> unreadable`; по `WAIT_MAX` — итог `failed` | пульс, итог | исправить строку записи |
| нет комплекта роли | 401 `no_role` двери, читать нечем | пульс, журнал | комплект `detjobworker` |
| том сменил держателя посреди чтения | 503, отрезок не прочитан | — | повтор следующим проходом |

## Н5 Приёмка

Чтение требует TLS-стенда с регистратором и воркером `detjob` (лист `detjobworker`); сценария пока нет (глава 4 Н5) — чтением.

## Решает реализация

Реализация обязана назвать в своём описании: **клиент дверей архива** (TLS с листом роли, срок вопроса, разбор SMPL).
