# V/05.1 — Задача — единица, которая кончается: нормы

Канон главы 1 урока V/05 «Задача по интервалу архива» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../05-detjob.md),
[инструкция](05-detjob.README.md), манифест [`detjob.subsystem.yaml`](../detjob.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `db53315` (поток задачи — поток записи, `41d3ec8`).

Задача — одна модель на одном интервале одной записи. Её работа кончается: итог лежит в состоянии единицы, законченную
задачу платформа не размещает и через трое суток удаляет. Глава нормирует строку задачи, кто её заводит, итог, размещение и
снимок. Чтение — глава 2; работа и события — глава 3; ожидание и просьбы — глава 4.

Id норм — `V/05.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `from`, `to` — секунды Unix **медийного** времени (время видео), не момент создания задачи.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): строка `detjob/jobs/<name>` (P/06.1),
состояние `detjob/state/result/<job>`, `detjob/state/cursor/<job>` ([P/03.6 Н1.7](../../../Platform/03-worker/spec/03.6-worker.norms.md)),
снимок `detjob/snapshot/*`; своих семей сверх них у главы нет.

### Н1.1 Поля

`unit: {rows: jobs, id: name}`; `about: {sub: cam, field: cam}` — события, гранты и метки задачи — камеры.

| Поле | Форма | Смысл |
|---|---|---|
| `name` | `string`, обязательно | имя прогона; заказы — `rec-…`, `auto-…` (Н1.2) |
| `cam` | `string`, обязательно, `fixed` | камера, чьё видео смотрим; `of` каждой строки события; поток — тот, что пишет запись `rec` (её `stream`, V/02.1; своего поля `stream` у задачи нет) |
| `rec` | `string`, обязательно, `fixed`, `ref: rec/recordings`, `must_match: {cam: cam}` | запись **этой** камеры, чьи потоки читаем (V/02.1); запись другой камеры — отказ |
| `kind` | `string`, обязательно | вид модели — реестр детекторов (V/04.2 Н1.2), в том числе учебная `tick` |
| `params` | `string` | настройки модели, непрозрачны и малы (V/04.1) |
| `mask` | `blob` | маска телом (P/06.1 Н1.5) |
| `mask_from` | `string` | маска заказа ссылкой: `det/<id>@sha256-<hex>` — только у строки с `made`; тело — по дайджесту (ADR-0091 п. 1) |
| `alarms` | `list`, умолчание `["linecross", "lpr"]` | какие виды событий — тревоги (глава 3); заказы копируют из детектора |
| `from`, `to` | `float`, обязательно | интервал медийного времени, `[from, to)` |
| `labels` | `list`, умолчание `["gpu"]` | метки сервера воркера |

Полей `state` и `ended` у строки нет: итог — состояние единицы (Н1.3). Проверка строки, `fixed`, `ref`, `must_match` —
[договор проверки строки](../../../Platform/common/contracts/row-check.md); правка `rec` — от права на камеру
([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md) «Права по телу» `reach`).

### Н1.2 Кто заводит

- **Оператор** — дверью единиц консоли (`POST /detjob/jobs`, P/06.1) с интервалом шкалы. **Повторный прогон — новая
  строка** (новое имя): у законченной задачи итог действует, пока строка не правлена (Н1.3).
- **Регистратор** — заказом скана дозаписанных минут (`worker.creates` к `detjob`, ключ `{cam}-{rec}-{kind}-{from}-{to}`,
  строка `rec-<key>`; V/02.8 Н1.5): поля детектора (`params`, `labels`, `alarms`) и маска ссылкой `mask_from`.
- **Сценарий** — заказом скана вокруг события (`auto-…`; урок V/07).

Строка заказа несёт `made` ([P/03.6 Н1.6](../../../Platform/03-worker/spec/03.6-worker.norms.md)); оператор правит любые её
поля, кроме полей ключа.

### Н1.3 Итог и снятие

- **Итог** — `unit.state.result` `{end: done | failed, covered, asked, events, partial?, why?}`: пишет держатель под стражем
  эпохи (P/03.6 Н1.7); действует, пока строка задачи живая и её `born`, `revision` равны состоянию — переживает переезд: новый
  держатель законченную задачу не исполняет снова. `covered` — секунд просмотрено, `asked` — секунд интервала, `events` —
  строк записано, `partial` — чего не дождались (глава 4).
- **Снятие** — `retire_when: {state: result, field: end, in: [done, failed], delete_after: 259200}`
  ([P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md)): итог есть — контроллер задачу не размещает и
  снимает с причиной (`done` | `failed`); строку заказа (`made`) через трое суток после снятия удаляет; ручную — нет:
  у таблицы с `fixed`-полями срок удаляет только строки заказа, ручная снята (счёт `expired_kept`), удаляет её оператор. Факт «сделано» не может жить в пульсе: снятая задача ушла бы из пульса,
  её разместили бы снова и начали сначала.
- Фазы работы (глава 4) — только в пульсе; правка законченной задачи (`params`, интервал) меняет `revision` — итог перестаёт
  действовать, задача размещается и идёт заново.

### Н1.4 Размещение

| Ключ | Значение | Смысл |
|---|---|---|
| `capacity` | `{from: capacity, default: 2}` | задач на воркер — свой бюджет: ретро-поиск не тратит потоки живой детекции |
| `headroom` | `{from: headroom}` | запас — платформа (P/03.4 Н1.1) |
| `constraint` | `labels-subset` | |
| `requires` | `resource` | события — в ресурс своего сервера |
| `near` | `{sub: rec, by: rec}` | предпочтение: рядом с регистратором записи, которую задача читает (по полю `rec`, а не по имени задачи) — видео не пересекает сеть; не вышло — любой сервер с GPU, чтение через двери по сети |
| `tie_break` | `most-free-capacity` | |

`home` нет; `grows` нет. Снимок — `snapshot: [name, cam, kind, state.result]` (P/04 Н1.3а): домену — «камеру 7 сканируют» и
чем кончилось; интервал и запись выше кластера не нужны.

## Н2 Двери

Дверь единиц консоли — `POST|GET|PUT|DELETE /detjob/jobs[/<id>]`, маска — `PUT /detjob/jobs/<id>/mask` (P/06.1); своей двери у
`detjob` нет.

## Н3 Проход

Своего прохода у главы нет: снятие и удаление — проход контроллера (P/04 Н3), заказы — проходы заказчиков (P/03.6 Н1.6),
итог — держатель (глава 3).

**Гонки.** Итог записан, контроллер ещё не снял задачу — держатель читает действующий итог и задачу не исполняет; новый
держатель после переезда — так же. Оператор правит задачу, пока держатель пишет итог: итог старой `revision` не действует,
задача идёт заново.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| `rec` — запись другой камеры | 409 `must_match` | ответ | запись этой камеры |
| записи `rec` нет | 409 `ref` | ответ | — |
| `cam` или `rec` меняется | 400 «… is fixed» | ответ | новая задача |
| имя `rec-…`, `auto-…` вручную | 400 (имена заказчиков) | ответ | другое имя |
| нет `from`, `to`, `kind` | 400 | ответ | — |
