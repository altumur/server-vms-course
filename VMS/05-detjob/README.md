Статус: **переведён** — главы V/05.1–V/05.4 (2026-10-23; ревью — 2026-10-29); план ниже — история перевода (годен —

[`detjob.subsystem.yaml`](detjob.subsystem.yaml) (канон; ADR-0090 доп. (6) п. 8).

## Что такое урок V/05

Подсистема `detjob`: задача — одна модель на одном интервале одной записи («найти этот номер на камере 7 вчера с 10 до 11»).
Первая единица VMS, чья работа **кончается**. Воркер задачи читает видео из дверей архива регистраторов (V/02.5), прогоняет
модель того же реестра, что у детектора (V/04.2), пишет события в своё дерево с `of` камеры и кладёт итог в состояние
единицы; законченную задачу платформа не размещает, заказ через трое суток удаляет. Свой бюджет: ретро-поиск не тратит потоки
живой детекции. Заказчики — оператор, регистратор (скан дозаписанных минут, V/02.8 Н1.5), сценарий (V/07).

## Формы и двери

- **Строки и объекты:** `detjob/jobs/<name>`, состояние `detjob/state/result/<job>`, `detjob/state/cursor/<job>` (P/03.6 Н1.7),
  просьбы `rec/requests/<rid>` (подача), пульс `detjob/heartbeats/<воркер>`, события — журнал ресурса своего сервера
  `detjob/<job>/e<эпоха>/`, тревоги — `detjob.alarms/…`.
- **Двери:** своей HTTP-двери у `detjob` нет — строки дверью консоли (P/06.1), чтение — двери архива регистраторов (V/02.5)
  и перечень двери держателя (V/01.5) по сертификату роли `detjobworker`; OpenAPI урока нет — строка реестра
  `V/05 no-openapi` (запросом с главой V/05.1).
- **Семьи данных:** поля строк событий задачи — [`data/detjob-events`](data/) (учебная `tick` — `pass`, `scan.partial` —
  `missing`, `waited`; место — корень строки семьи событий платформы, деревья `detjob` и `detjob.alarms`; читают консоль и
  сценарии `auto`), строки — в каталоге VMS [`../common/data/catalog.tsv`](../common/data/catalog.tsv). Строки, состояние
  и пульс выражает манифест: пульс задачи другие процессы не читают.

## Решения для плана (приняты «Архитектором» 2026-10-23)

1. **Чтение чужого тома:** `/spans` у каждой живой двери архива (пульс `rec/*` за 45 с, адрес — `url`), каждый отрезок плана —
   `/samples?from&to&stream=<epoch>[/backfill]` у той двери, что назвала спан (без `stream` дверь решает эпоху только по своему
   тому); сертификат роли `detjobworker`; без комплекта задача читать не может (процессные маршруты — 401 `no_role`) — приёмка
   чтения только на TLS-стенде. `/where` странице — не процессу.
2. **Модели — реестр `det`** (тот же воркерный реестр видов, `unsupported` для неизвестного); учебная `tick` в задаче — в
   медийном времени: шаг взгляда `STEP` = 1 с, событие на каждом третьем взгляде (каждые 3 с видео), поле `pass` — номер
   взгляда в отрезке; отличие от V/04.2 Н1.2 (проходы) записывается.
3. **Прогресс — `unit.state.cursor`** (`{revision, done: [[from, to], …], events, waited?, fetch_waited?}`, монотонно
   растущее множество отрезков по
   записи, не чаще `STATE_EVERY` = 10 с); файл прогресса на ресурсе не переносится (теряется при переезде). Курсор с чужой
   `revision` воркер не применяет: правка задачи — скан заново.
4. **Итог — `unit.state.result`** `{end: done | failed, covered, asked, events, partial?, why?}`; `retire_when: {state: result,
   field: end, in: [done, failed], delete_after: 259200}`; фазы — только в пульсе. Поля `state`, `ended` снимаются (отказ
   загрузки при `unit.state`, P/02.1).
5. **Повторный прогон — новая строка** (новое имя); `earlier-run` — строки прежних эпох той же задачи (переезд, подмена).
6. **Класс событий — поле `alarms`** у задачи (умолчание как у `det`); заказчики копируют его из детектора вместе с `params`,
   `labels` — V/02.8 Н1.5 дополняется (`alarms`), V/07 — так же.
7. **Подавление `motion`** у задачи не объявляется: окно подавления — по часам писателя (P/03.6 Н1.2), скан идёт быстрее
   реального времени, окно по медийному `t` платформа не держит; строк скана — столько, сколько модель отдала.
8. **Потолок видимости — дыра, не просьба:** минуты до «видно с» записи (V/02.5 Н1.2) не просятся дозаписью; просьба —
   только `[max(from, видно с), min(to, now))` ∩ перечень устройства, кусками ≤ суток (иначе регистратор откажет).
9. **`worker.requests: [rec]` остаётся:** просьбу дозаписи подаёт воркер (P/03.6 Н1.5, `by: detjob/<job>`); исход регистратор
   держит у себя (`fetched`), задача его не ждёт вечно — `fetching` ограничен `WAIT_MAX`, затем `done` с `partial`.

## Запросы урока

Строка реестра `V/05 no-openapi` (своей двери у `detjob` нет) — запросом с главой V/05.1. Механизмов платформы сверх
выгруженных урок не просит.

## Отличия от свидетеля, которые урок записывает

Итог — `unit.state.result` держателя под стражем эпохи, а не поле `state` строки, которое двигал уборщик консоли;
`forget_finished` — `retire_when.delete_after`; прогресс — курсор состояния, не файл ресурса; заказ — `worker.creates`
заказчиков (имена `rec-…`, `auto-…`); подача просьбы — воркером (P/03.6 Н1.5), без зеркала фазы в строке; расширение задачи по
пересечению снято; маршрут чтения — `/spans` и `/samples` процессам (у свидетеля — `/timeline` страницы); эпоха — при взятии
единицы; запас — платформа.

## Правки манифеста при переводе

`detjob`: снять поля `state`, `ended`; добавить `mask_of` (было `mask_from`, снято ревью V/04–V/05), `alarms`; `unit.state: {result: …, cursor: …}`; `retire_when:
{state: result, field: end, in: [done, failed], delete_after: 259200}`; `snapshot: [name, cam, kind, state.result]`;
`worker: {exec, reads: [rec/heartbeats/, rec/volumes/, rec/recordings/, cam/heartbeats/, det/blobs/], requests: [rec]}`;
комментарии — без кода свидетеля и уборщика консоли, `/timeline` → `/spans`. `rec` (V/02.8 Н1.5): копируемые поля + `alarms`.
Продукт — строкой долга «Сборке».
