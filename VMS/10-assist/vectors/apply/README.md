# Сценарии применения — V/10.6

Применение проверенного плана (V/10.6 Н1.4) ядром страницы: записи `PUT` по строкам с `ifMatch`, исходы, неизвестный
исход — чтение, «Повторить». Консоль — [`../plan-check/stand3.console.json`](../plan-check/README.md); план один на все
случаи (строка `Gate-1` с двумя полями, строка `Office-2` с меткой секрета). Ядру дают `alive()` (V/10.3 Н1.6) и секреты
показанной версии; в DOM те же вмешательства — «Новый ход», отмена, выход, `pagehide` между строками и во время записи.

```yaml
id, rule:    имя и правило V/10.6
plan:        строки проверенного плана — unit, revision чтения, changes {field, from, to}
secrets:     значения секретов по номеру (в тело PUT — только они, вместо метки)
responses:   ответы на PUT по порядку: status (0 — сеть или тайм-аут), body; ответ не 200 — throw модуля {status, body}
read:        строки в чтении GET /<rows> после неизвестного исхода: {<id>: поля поверх строки консоли | null — строки нет}
expect:      sent — PUT по порядку (method, path, body, ifMatch); outcomes — исход каждой строки
reset:       сброс панели (V/10.3 Н1.6): alive() — нет с n-го вопроса; применение спрашивает перед каждой строкой и после
             её записи — 1: до первой строки, 2: пока первая в пути, 3: между первой и второй
again:       «Повторить» после первого итога: свои responses, read и expect
```
