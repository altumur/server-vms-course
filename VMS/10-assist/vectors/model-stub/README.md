# Файлы ответов заглушки модели — приёмка 2

Владелец — урок V/10 ([нормы главы 2](../../spec/10.2-assist.norms.md) Н5 «Заглушка модели»). Читает программа раннера
`model-stub`: стенд приёмки 2 называет файл сценария в `MODEL_COMMAND` (`{model_stub} {spec}/VMS/10-assist/vectors/model-stub/<сценарий>.tsv` — файл по имени сценария,
[README приёмки 2](../../acceptance/2/README.md)). Файл — не ожидание: он задаёт, что «модель» ответит; ожидания — в
`scenarios.tsv` приёмки.

Форма файла — UTF-8, LF, поля через TAB, строки с `#` — пояснения:
- первая строка — `load <секунды>` или `load hang`: столько секунд от запуска `GET /health` отвечает 503 (при `load hang`
  — всегда: модель не загружается), затем 200 — и во время шага;
- необязательная вторая строка `busy`: во время шага `GET /health` отвечает 503, как сервер с одним занятым слотом;
- дальше строка на каждый запрос `POST /v1/chat/completions` по порядку: `<после>` (секунды или `hang`), `<статус>`,
  `<тело ответа JSON>`; `hang` — ответа нет, пока держатель не оборвёт соединение; строк не хватило — 500.

| Файл | Сценарий | Что отвечает |
|---|---|---|
| `01-loading.tsv` | `01-loading` | не загружается никогда |
| `02-step.tsv` | `02-step` | загружена сразу; первый шаг — `готово`; второй — `hang`; третий — 500; четвёртый (шаг с историей) — `дальше` |
| `03-limits.tsv` | `03-limits` | два шага — `hang`; во время шага `/health` — 503 (`busy`) |
| `04-owner.tsv` | `04-owner` | один шаг — `для ann` |
