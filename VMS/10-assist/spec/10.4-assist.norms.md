# V/10.4 — Инструменты: нормы

Канон главы 4 урока V/10 «Ассистент» (ADR-0080; модуль VMS — ADR-0090; подсистема — ADR-0093 пп. 3, 8, доп. (1) п. 9,
доп. (2) п. 2, доп. (3), доп. (4) пп. 4, 5, доп. (5)). [Лекция](../10-assist.md), [инструкция](10-assist.README.md). Платформа — выгрузка
`cammeta-specs` `fbe9e93` (P/07 Н1.4, Н1.5 — модуль консоли; P/06.1 Н2 — дверь единиц; P/06.5 — `/manifest`, `/mounts`).

Модель ничего не читает сама: каждый её вызов страница исполняет дверями консоли сессией админа, через модуль консоли,
и отдаёт результат текстом. Поэтому модель видит ровно то, что видит админ, — и не больше: маски секретов, права `view`,
отбор консоли по гранту действуют как у формы. Набор закрыт: девять инструментов пакета передачи (ADR-0093 п. 8) —
шесть для чтения и три ответа админу. Фильтров у дверей консоли нет: страница читает список целиком и отбирает сама
(ADR-0093 доп. (2) п. 2). Глава нормирует набор, чтение консоли, каждый инструмент чтения и `ask_admin`; `propose_plan`
и проверка `refuse` — глава 5.

Id норм — `V/10.4-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Подсистема** — корень (подсистема страницы) и смонтированные консолью (P/06.5 Н1.1), из тех, с которыми страница
  смонтировала модуль консоли (`subsystems` в `mount`, V/08.1): только их единицы знает `may` модуля (P/07 Н1.5). Порядок
  подсистем — корень, затем прочие по имени. Это **охват** ассистента (ADR-0093 доп. (5)): обзор, инструменты и план —
  только по нему; шире — отдельным решением правкой V/08 (модуль со всеми подсистемами VMS), до него — пробел урока.
- **Строки подсистемы** — элементы `configured` ответа `GET` её строк (P/06.1 Н2): у корня `/<rows>`, у прочей
  `/<sub>/<rows>`; `rows` — `rows` манифеста. Id строки — поле `id`; поле имени — `id` манифеста (`id_field`).
- **Связанная подсистема** — по `about` манифеста (`about: {sub, field}`): строка ссылается на единицу той подсистемы
  полем `field`. `about.<поле>` — поле связанной единицы.
- **Манифест** подсистемы — `manifest(name)` модуля (P/07 Н1.5): копия `ManifestView`, которую модуль прочёл с `/manifest`
  и `/mounts` (P/06.5 Н2, [OpenAPI P/06](../../../Platform/06-console/spec/06-console.api.openapi.yaml)) — проекция
  манифеста с ключами верхнего уровня `name`, `rows`, `id`, `fields`, `about`, `display`, `servers`, `places` и прочими;
  инструменты читают только её (`fields` — поля строки в порядке манифеста). Подсистема страницы, которой модуль не
  смонтировал, в охват не входит. **Корень** — подсистема, чья это страница (`cam`): у неё строки — `/<rows>`.

## Н1 Форма

**Данные.** Своих семей нет. Читает — двери консоли (Н1.2); пишет — ничего.

### Н1.1 Набор

Инструменты — ровно [`harness/tools.json`](../harness/tools.json): `list_subsystems`, `get_manifest`, `get_schema`,
`find_units`, `field_values`, `list_table` (чтение), `propose_plan`, `ask_admin`, `refuse` (ответ админу). Имя, описание и
схема аргументов — байты файла; модель видит их в `tools` шага (глава 3 Н1.2). Иного вызова нет: имя не из набора —
результат `no tool <имя>` (глава 3 Н1.4); принадлежность набору — собственный ключ закрытого реестра, не свойство,
унаследованное от прототипа (`constructor`, `toString`, `__proto__` — `no tool`); так же имена полей, таблиц и слов,
которые пишет модель, ищутся только среди собственных ключей. Создать, удалить единицу, писать таблицы, серверы, политику, домен ассистент не
может — такой просьбе модель отвечает `refuse`.

### Н1.2 Чтение консоли

- **Только через модуль**: `console.api("GET", <путь>)` (P/07 Н1.5) сессией страницы. Пути — закрытый список:

```yaml
module:  manifest(name), may(cap, ref) — манифесты и право; свои двери консоли (/session, /mounts, /manifest) читает модуль
reads:   /schema, /<rows>, /<sub>/<rows>, /<table>, /<sub>/<table>, /<sub>/manifest (только «в охвате ли» — Н1.5 get_manifest)
         # <table> — таблица из tables подсистемы (list_subsystems): servers.show[].table и places.table манифеста;
         # у корня — /<rows>, /<table>, у прочей — /<sub>/<rows>, /<sub>/<table> (P/06.1 Н2)
never:   /session, /mounts, /manifest (граница оболочки P/06.5 Н1.1: сессию и манифесты держит модуль); запись (её делает
         только «Применить», V/10.6); двери держателей; /events; /domain/*
```

- **Свежесть.** Каждый вызов инструмента читает заново; обзор хода (глава 3 Н1.2) — один раз в начале хода. Внутри
  одного вызова одна дверь читается один раз.
- **Ошибка чтения** — ответ не 200 или `throw` модуля: вызов кончается ошибкой инструмента
  `GET <путь>: <статус> <detail>`; пустого или усечённого результата вместо ошибки нет (ADR-0093 доп. (1) п. 9). 401 —
  окно входа модуля; ход ждёт входа (глава 3 Н1.6).
- **Предел списка.** Строк подсистемы больше `LIST_MAX` — ошибка инструмента `<sub>: more than <LIST_MAX> units — too
  many to check here; refuse and say so`; так же у таблицы (ADR-0093 доп. (2) п. 2: предел и `refuse`, не усечённый
  отбор).

```yaml
LIST_MAX:   5000 строк одной двери
ROW_LIMIT:  50 — единиц и строк таблицы в результате инструмента; число — полное (count)
```

- **Право** единицы (`can_edit`) — возможность, которую требует дверь записи этой строки (`PUT /<rows>/<id>`), по
  `need` [договора сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md): `admin` на единицу —
  `rights.routes` у строк единиц понижает только создание (таблица «Права по телу» договора). Проверка — только
  `console.may("admin", "unit:<sub>/<id>")` модуля (P/07 Н1.5; гранты сессии, область — в том числе по `about`-единице),
  без своего чтения `grants`: аварийная сессия (break-glass) и открытый режим судятся внутри `may`, как у сервера. Одно правило — в обзоре, `find_units`, проверке
  плана, полноте и проверке `refuse` (ADR-0093 доп. (4) п. 4). Это предварительная проверка: ключа `rights` в
  `ManifestView` нет, поэтому `rights.cluster_rows` (у `auto` — запись требует гранта на кластер) и то, что правка
  задевает сверх строки (`rights.reach`, `names`), страница заранее не видит — их сервер проверяет при записи всегда
  (ADR-0093 доп. (1) п. 9; отказ — исход `refused`, V/10.6 Н1.4).
- **Нечитаемая подсистема** — чтение её строк кончилось ошибкой или `LIST_MAX`. Где инструмент или проверка
  перебирает все подсистемы (подсказки `find_units`, проверка `refuse` главы 5 Н1.5, имена единиц для чисел текста главы
  5 Н1.2), такая подсистема пропускается:
  опровергнуть ею нечего; подсказка `find_units` называет её: `subsystem <s> could not be read: <причина>`.

### Н1.3 Результат и ошибка

- Результат вызова — `content` сообщения `tool` (глава 3 Н1.2): JSON без пробелов, ключи в порядке форм ниже.
- **Ошибка инструмента** — `content` — `error: <слова>`; ход идёт дальше, модель исправляет вызов. Слова ошибок — в
  формах ниже, английские, как в замере пилота.
- `null` поля строки и отсутствие поля — одно: «не задано».

### Н1.4 Слова поля

Вид поля для модели (`get_manifest`, обзор) и слова для проверки (глава 5 Н1.2) берутся из `display` манифеста и
[`harness/words.json`](../harness/words.json) — данных урока, не настройки модели:

```yaml
field:      {name, type, required?, fixed?, enum?, default?, inherit?, bound_to?, label?, label_from?, help?, enum_labels?,
             words?, enum_words?, secret?} — ключи в этом порядке; ключ без значения (нет, false) не пишется
  type:     тип поля fields манифеста (string, int, float, bool, list, json, url, blob)
  label:    display.fields[name]; нет — words.json labels[sub][name] и label_from: "lesson"; нет и тип list — null;
            нет у иного типа — ключа нет
  help:     display.field_help[name]
  enum_labels: display.options[name]
  words:    words.json fields[sub][name] — слова операторов сверх подписи
  enum_words: words.json options[sub][name]
  secret:   true — имя кончается на _secret (P/02.1 Н1.3а)
```

### Н1.5 Инструменты чтения

**`list_subsystems`** `{}` → `{subsystems: [элемент]}` по порядку подсистем:

```yaml
элемент:  {sub, rows, id_field, unit_word, units_word, section, words?, unit_word_from?, about?, tables?}
  unit_word, units_word, section: display.unit, display.units, display.section (нет — null)
  words:  words.json units[sub]
  unit_word_from: нет display.unit, а подсистема, которая ссылается на эту по about, дала подсказку поля связи
          (display.field_help[about.field]) — unit_word = эта подсказка, unit_word_from: "no label in display; the word comes
          from the help of field <другая>.<поле>"
  about:  "each unit (\"<unit_word или sub>\") belongs to a unit of <about.sub> (\"<её unit_word или sub>\") via field
          <about.field>; that unit's fields in find_units are about.<field>"
  tables: имена таблиц servers.show[].table и places.table по имени; нет — ключа нет
```

**`get_manifest`** `{sub}` → `{sub, rows, id_field, about?, fields, word_unit?, word_units?, word_section?, word_general?,
form?, status_words?, notes}`:

- нет подсистемы — `error: no subsystem "<sub>"; there are: <подсистемы через ", ">`; подсистема смонтирована, но вне
  охвата (Н0) — `error: subsystem <sub> is outside the assistant's scope (this page: <подсистемы через ", ">) — refuse:
  not in scope, not a lack of rights` (ADR-0093 доп. (5) п. 1); так же у каждого инструмента и правки плана с этой
  подсистемой;
- `about` — `{sub, field, note, about_list_fields}`: `note` — `a unit belongs to a unit of <about.sub> whose name is in
  field <about.field>. That unit's fields are filters about.<field>: <about.<поле> связанной через ", ">. A unit's labels
  are the labels of the related unit: about.labels; its own list fields (<свои поля list через ", " или none>) are not
  labels`; `about_list_fields` — `about.<поле>` полей `list` связанной;
- `fields` — вид каждого поля `fields` манифеста (Н1.4) по порядку; `word_*` — `display.unit`, `units`, `section`,
  `general`; `form` — `[{title, fields}]` из `display.form`; `status_words` — `display.options` по именам, которых нет
  среди полей;
- `notes` — четыре строки:
  1. `look up field values (labels, zones, shelves) with field_values — the admin's words are stored as values (e.g.
     "northern" → north, "quiet" → plain)`;
  2. `a field with secret: true is hidden from you (the console shows ***); a new secret value is never written into a
     plan — only the secret label {"secret": N} the admin entered`;
  3. `a fixed field cannot be changed; the id_field is the unit's name, it is not changed`;
  4. `a field with inherit and no own value: find_units shows null, and inherited says what applies; from is null or
     the effective value`.

**`get_schema`** `{}` → ответ `GET /schema` как есть.

**`find_units`** `{sub, where?, fields?}` → `{sub, count, shown, units, can_edit_note?, query, hints?}`:

- **Условия** `where` — список `{field, op, value}`, все — И. Короткие записи: объект `{<поле>: <значение>, …}` — равенства;
  `{field, <op>: <значение>}` с одним ключом из `op` — этот `op`. `op` не задан — `eq`. Ошибки: иной ключ — `condition
  <условие>: extra keys <ключи>; the form is {"field": …, "op": "eq", "value": …}`; нет `value` у `op` не
  `exists`/`missing` — `condition <условие>: no value; …`; не объект или без `field` — `a condition is {field, op,
  value}`; `op` не из `eq ne in not_in contains not_contains gt gte lt lte exists missing` — `op "<op>": one of <список>`;
  поле не из полей строки, `id`, `revision` — `no field "<поле>" in <sub>; fields: <по имени>`; `about.<поле>` без `about`
  — `<sub> has no about`; `about.<поле>` не из полей связанной и `id` — `no field "<поле>" in the related subsystem <s>;
  its fields: <about.поле…> — filter about.<field>`.
- **Значение** условия у строки — её поле; `about.<поле>` — поле единицы связанной подсистемы с id, равным полю связи
  строки (нет такой — не задано).
- **Сравнение** `same(a, b)` — равенство значений JSON, но `true`/`false` не равны числам. `eq` — `same`; `ne` — не `same`;
  `in`/`not_in` — `same` с элементом списка значения; `contains` — поле-список содержит значение (значение-список — все его
  элементы); `not_contains` — отрицание `contains`; `exists`/`missing` — задано / не задано; `gt gte lt lte` — числа (не
  `bool`) у обоих, иначе не подходит.
- **Пустой список.** У поля `list`: `eq`/`ne` с `""`, `[]`, `null` и `exists`/`missing` судят «пусто или не задано»;
  не заданное поле с `inherit` — значение `inherit`. `eq`, `missing` — пусто; `ne`, `exists` — не пусто.
- **Единицы** — подходящие строки по id; в `units` — первые `ROW_LIMIT`: `{unit: "<sub>/<id>", …вид}`. Вид — поля строки
  (только из `fields`, если дан) без `id`, `revision`, поля имени, без пустой строки (если поле не просили), без `null`
  (если не просили); `[]` и `""` просимого поля видны. Не заданное поле с `inherit` (из просимых) — `null`, и
  `inherited: {<поле>: <значение inherit>}`. Есть `about`: `about.labels` — метки связанной единицы, если непусты;
  `about.<поле>` из `fields` — значение поля связанной единицы (не задано и есть `inherit` у поля той подсистемы —
  значение `inherit` и запись в `inherited`), и тогда же поле связи строки. Нет права (Н1.2) — `can_edit: false`.
- `count` — число подходящих, `shown` — число в `units`. Есть `can_edit: false` — `can_edit_note`: `can_edit: false — the
  admin has no edit right on this unit: leave it out of the plan, tell the admin in summary`. `query` — `{sub, where}`
  после коротких записей.
- **Найдено за ход.** Каждая показанная единица — в учёт хода `unit → право` (для проверки `refuse`, глава 5 Н1.5).
- **Подсказки** `hints` — при нуле находок и непустых условиях, по порядку, все сработавшие; ни одной — `["no matches
  anywhere; check the field's values with field_values"]`:
  1. одно поле дважды через `eq` — `field <поле> twice with eq — conditions are AND, one unit cannot equal two values;
     for "or" use {"field": "<поле>", "op": "in", "value": <значения>}`;
  2. значение условия (не `contains`/`not_contains`) — элемент поля-списка какой-нибудь строки подсистемы —
     `<значение> is an element of list field <поле> — a list needs op contains: {"field": "<поле>", "op": "contains",
     "value": …}` (одна на условие);
  3. есть `about`, строковое значение условия — значение или элемент поля связанной подсистемы (сначала `labels`) —
     `"<значение>" is in field <поле> of the related subsystem <s> — filter about.<поле>` (одна на значение);
  4. строковое значение условия — id единицы другой подсистемы — `"<значение>" is the name of a unit of subsystem <s>`;
  5. другая подсистема не читается (Н1.2) — `subsystem <s> could not be read: <причина>`.

**`field_values`** `{sub, field}` → `{sub, field, values, empty_units?, empty_note?}`: `values` — `[{value, units}]` значений
поля (у списка — элементов; `about.<поле>` — у связанных единиц; объекты, списки и не заданные — не считаются) по
убыванию `units`, при равенстве — по возрастанию значения как JSON. У поля `list` пустые или не заданные (с `inherit` —
по нему) — `empty_units` и `empty_note`: `empty or not set: {"field": "<поле>", "op": "eq", "value": []}`. Нет поля —
`no field "<поле>" in <sub>`; `about.<поле>` — как у `find_units`.

**`list_table`** `{sub, table}` → `{sub, table, rows, read_only: true}`: `rows` — первые `ROW_LIMIT` строк таблицы без полей
`by`, `at`, `held_by`. Таблицы нет среди `tables` подсистемы или в ответе — `no table "<table>" in <sub>`.

### Н1.6 Ответ админу

- **`ask_admin`** `{question}`: пустой — ошибка `question is one short question to the admin`. Иначе — принят: страница
  показывает вопрос и ждёт ответа (глава 3 Н1.4 п. 6); результат — текст ответа админа.
- **`refuse`** `{reason}`: пустой — ошибка `reason is why the request cannot be done (or that there are no such units)`;
  проверка отказа — глава 5 Н1.5; принят — исход «отказ» (глава 3 Н1.5).
- **`propose_plan`** — глава 5.

## Н3 Проход

```
вызов → имя из набора? иначе no tool
аргументы → короткие записи → проверка полей и op → ошибка инструмента | дальше
манифест — manifest(name) модуля; чтение строк (и связанной) — через api; не 200 → ошибка; > LIST_MAX → ошибка
отбор в странице → вид, can_edit (may), учёт найденного, hints → результат JSON
```

**Гонки.** Строки изменились между вызовами — каждый вызов читает заново; план проверяется по своему чтению (глава 5), а
применение — по `revision` этого чтения (V/10.6). Права сузились посреди хода — следующий вызов видит меньше.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| имя не из набора | `no tool <имя>` | модель | другой вызов |
| условие не по форме, нет поля, нет подсистемы, нет таблицы | ошибка инструмента со словами Н1.5 | модель | исправить вызов |
| чтение консоли не 200 | `GET <путь>: <статус> <detail>` | модель | `refuse` или повтор позже |
| строк больше `LIST_MAX` | ошибка «too many to check here» | модель | `refuse` |
| 401 консоли | окно входа | админ | войти |

## Н5 Приёмка

Своим прогоном jsdom VMS у раннера с заглушкой модуля консоли: векторы инструментов чтения — чтение консоли (строки,
манифесты, сессия) и вызов → результат или ошибка: короткие записи условий, каждый `op`, пустой список и `inherit`,
`about.<поле>`, `can_edit` по возможности двери записи (и аварийная сессия, открытый режим — через `may`), подсказки 1–5 и нечитаемая подсистема, `field_values`, `list_table`, ошибка чтения. Векторы —
[`vectors/plan-check/`](../vectors/plan-check/README.md) (случаи `tools-*` и переигровка основы пилота); `LIST_MAX` —
чтением (консоль на 5001 строку в векторы не кладётся).

---

## Решает реализация

Реализаций у главы нет: инструменты исполняет панель — канон страницы (`cam.shell.html`), её не генерируют.
