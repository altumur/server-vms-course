# V/10.2 — Дверь модели: нормы

Канон главы 2 урока V/10 «Ассистент» (ADR-0080; модуль VMS — ADR-0090; подсистема — ADR-0093, доп. (1) пп. 1, 2).
[Лекция](../10-assist.md), [инструкция](10-assist.README.md), [OpenAPI](10-assist.api.openapi.yaml), манифест
[`assist.subsystem.yaml`](../assist.subsystem.yaml). Платформа — выгрузка `cammeta-specs` `35582ba`.

Страница не говорит с моделью через консоль: она спрашивает у консоли адрес двери держателя модели и токен
(`GET /assist/where/<name>`) и зовёт дверь сама, как зритель зовёт шлюз (V/03.3). Учётные данные админа держателю не
уходят: токен двери узкий, на 120 с и к консоли не годится. Шаг модели идёт 10–50 с, поэтому дверь **асинхронная**:
поставить шаг, спросить его состояние или ответ, отбить. Шаг принадлежит человеку, чьё имя в токене; чужому его нет.
Глава нормирует маршрут `chat`, шаг и его жизнь, владельца шага, очередь, пределы, журнал и заглушку модели для приёмки.
Что страница шлёт в шаге (сообщения, описания инструментов) и что делает с ответом — главы 3–5.

Id норм — `V/10.2-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `expires` токена — секунды Unix (договор токена двери); сроки двери — монотонные часы процесса, секунды.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — `door/keys` (проверка
токена); пишет — журнал двери `audit/assistworker/e1` (договор журнала событий «Журнал двери процесса»), пульс (`queued`,
`active`, `steps`, глава 1 Н1.4). Шаги — только в памяти держателя: на диск, в хранилище и в журнал их тексты не идут.

### Н1.1 Адрес и токен

- `door: {routes: [chat]}` — маршрут-имя: допуск — токен двери консоли ([P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md)
  `door_admission` `token`; [договор токена двери](../../../Platform/common/contracts/door-token.md)). Адрес — правило
  `door_address` P/03.4 Н1.7 (с комплектом роли `assistworker` — `https://<SERVER_NAME>:<порт>`, без — петля), порт —
  `CHAT_PORT` файла подсистемы `/etc/assist/assist.env` (не задан или 0 — порт ОС); адрес — поле `url` пульса.
- Адрес и токен выдаёт консоль: `GET /assist/where/<name>` с правом `view` на строку модели → `door: {url, token,
  expires, routes}` ([P/06.5](../../../Platform/06-console/spec/06.5-console.norms.md) Н3 «`/where/<id>`»; TTL 120 с;
  журнал консоли `door.issued`). Страница — вызовом модуля `where(ref)` (P/07 Н1.5). Дверь есть у держателя строки:
  пока строку никто не держит, двери нет.
- Токен — `Authorization: Bearer` (P/03.4 Н3 «токен двери у держателя»); держатель проверяет его по договору: `unit` —
  `assist/<name>` пути запроса, `holder` — свой экземпляр, `routes` содержит `chat`, не истёк. Любой отказ токена — 403
  `{"error": "forbidden"}` без причины. Токен нужен на каждый запрос; истёк — страница берёт новый `where` (V/10.3).
- **Владелец шага** — `user` проверенного токена, которым шаг поставлен (ADR-0093 доп. (1) п. 2). Состояние, ответ и
  отбой — только запросом с токеном того же `user`; иному `user` шага нет — 404, как незнакомого. Новый токен того же
  `user` у того же держателя продолжает шаг: шаг привязан к человеку, а не к токену.

### Н1.2 Поставить шаг

`POST /chat/<name>/steps`, тело — JSON (`Content-Type: application/json`), форма OpenAI chat без потоковой выдачи:

```yaml
messages:          массив 1…512 сообщений {role: system | user | assistant | tool, content?: строка,
                   tool_calls?: [{id, type: function, function: {name, arguments: строка}}], tool_call_id?: строка}
tools:             массив 0…64 {type: function, function: {name, description?, parameters: объект JSON Schema}}; необязательно
tool_choice:       auto | required | none; необязательно, умолчание — auto
reasoning_effort:  low | medium | high; необязательно, умолчание — medium
max_tokens:        целое 1…context строки модели; необязательно
```

1. токен (Н1.1) → иначе 403;
2. `Content-Length` больше `BODY` = 1 МиБ — 413 до чтения тела (`door_limits` P/03.4 Н1.7); не JSON или не по форме выше —
   400 `{"error": "bad step", "detail": <первое нарушение>}`;
3. фаза строки модели (глава 1 Н1.4): `loading` — 503 `{"error": "loading", "retry_after": 5}`; `failed`, `stopped` — 503
   `{"error": "model unavailable", "detail": <reason>}`;
4. у владельца уже `PER_USER` = 2 незавершённых шага у этой модели — 429 `{"error": "too many steps"}`;
5. в очереди уже `QUEUE` = 4 шага — 503 `{"error": "busy", "retry_after": 1}`;
6. **202** `{step, state: "queued"}`, `Location: /chat/<name>/steps/<step>`; шаг встаёт в очередь (Н1.4).

`step` — `<instance>.<32 строчных hex>`: экземпляр держателя (`instance` пульса, P/03.4 Н1.1) и 128 случайных бит. Повтор
`POST` — новый шаг: памяти повторов у двери нет, неизвестный исход страница не повторяет сама (V/10.3).

### Н1.3 Состояние и ответ

`GET /chat/<name>/steps/<step>[?wait=<секунды>]`, `wait` — целое 0…20, умолчание 0.

1. токен → иначе 403;
2. экземпляр в `step` — не свой — 410 `{"error": "gone"}`: шаг был у другого держателя или до перезапуска этого; страница
   начинает ход заново (ADR-0093 доп. (1) п. 2);
3. шага нет или его владелец — не `user` токена — 404 `{"error": "no such step"}`;
4. шаг не завершён и `wait` > 0 — ответ ждёт завершения шага, но не дольше `wait` секунд;
5. **200** — состояние:

```yaml
step:           id шага
state:          queued | running | done | failed | cancelled
ahead:          шагов впереди в очереди — при queued
message:        при done — сообщение модели как есть: {role: assistant, content?, tool_calls?, reasoning_content?}
finish_reason:  при done — stop | tool_calls | length
usage:          при done — {prompt_tokens, completion_tokens}
seconds:        при done, failed — секунды модели на шаг
reason:         при failed, cancelled — слова таблицы ниже
```

| Исход | `state` | `reason` |
|---|---|---|
| модель ответила 200 | `done` | — |
| модель ответила не 200 или процесс модели упал | `failed` | `model failed` |
| шаг в работе дольше `STEP_MAX` = 180 с | `failed` | `too long` — запрос к модели оборван |
| шаг в очереди дольше `QUEUE_MAX` = 120 с | `failed` | `queue too long` |
| сообщения шага длиннее окна (`context`) | `failed` | `context exceeded` |
| правка строки модели, перезапуск процесса (глава 1 Н1.3) | `failed` | `model restarted` |
| `enabled: false` (глава 1 Н1.3) | `cancelled` | `disabled` |
| отбой владельцем (Н1.5) | — | шаг забыт, 404 |
| владелец не спрашивал незавершённый шаг дольше `ABANDON` = 30 с | `cancelled` | `abandoned` — запрос к модели оборван |

**Сколько живёт завершённый шаг.** После первой выдачи завершённого состояния — ещё `KEEP` = 60 с (повтор `GET` после
обрыва читает тот же ответ); не выданный — `KEEP_UNREAD` = 120 с после завершения. Затем шаг забыт — 404.

### Н1.4 Очередь и изоляция шагов

- **Один шаг модели за раз.** Держатель шлёт процессу модели один шаг (глава 1 Н1.3), остальные ждут в очереди по
  порядку постановки. Пределы — `QUEUE` и `PER_USER` (Н1.2).
- **Шаг — только то, что в нём.** Модель видит сообщения своего шага и ничего больше: истории между шагами держатель не
  ведёт, сообщений одного шага в другой не переносит. Историю хода несёт страница (V/10.3).
- **Кеш модели — не общий между людьми.** Кеш контекста (префикса) процесса модели переиспользуется только между шагами
  одного владельца. Перед шагом другого `user` держатель начинает модель с пустого кеша; как — называет реализация.
- **Смена держателя.** Строку взял другой воркер, или этот перезапущен, — шаги прежнего утрачены: 410 `gone` (Н1.3 шаг 2).
  Переноса шагов нет.

### Н1.5 Отбой

`DELETE /chat/<name>/steps/<step>`: токен — иначе 403; экземпляр не свой — 410 `gone`; шага нет или он чужой — 404
`no such step`; иначе — **200** `{step, state: "cancelled"}`: шаг в очереди снят, в работе — запрос к модели оборван
(глава 1 Н1.3 `step`), шаг забыт; уже завершённый шаг забыт, `state` — его исход (`done`, `failed`, `cancelled`).
Страница отбивает шаг, когда ход отменён или страница уходит (V/10.3); не успела — шаг снимет `ABANDON` (Н1.3). Иной метод
на маршруте — 405, иной путь — 404.

### Н1.6 Пределы, журнал, CORS

- **Пределы** — `door_limits` P/03.4 Н1.7 (соединения 32, с адреса 8, заголовки за 5 с, тело 1 МиБ, темп). Долгий опрос —
  не дольше 20 с: меньше `PACE_AFTER` = 30 с, и предел темпа его не обрывает. Своих значений `door_limits.other` у двери
  нет; `QUEUE`, `PER_USER`, `STEP_MAX`, `QUEUE_MAX`, `ABANDON`, `KEEP`, `KEEP_UNREAD` — константы урока.
- **Журнал** — общие поля журнала двери процесса (договор журнала событий) и сверх них одна строка на завершённый или
  забытый шаг: `assist.step` — `of` (`assist/<name>`), `step`, `user`, `state`, `reason`, `seconds`, `prompt_tokens`,
  `completion_tokens`. Текстов сообщений, описаний инструментов и ответов модели в журнале нет.
- **CORS** — P/03.4 Н1.7 `cors` (договор сертификата роли: методы `GET`, `POST`, `DELETE`, заголовки `Authorization`,
  `Content-Type`, `Expose-Headers: Location`, заголовки CORS на всех ответах). `Retry-After` в `Expose-Headers` нет,
  поэтому срок повтора дверь пишет в тело — `retry_after` (Н1.2).

## Н3 Проход

```
поставить: токен → тело → фаза → PER_USER → QUEUE → шаг (instance.random), очередь, 202
очередь:   первый в очереди и модель свободна → running → POST /v1/chat/completions процессу модели (глава 1 Н1.3)
           → ответ 200 → done | не 200, упал, STEP_MAX → failed | отбой, ABANDON → обрыв запроса, cancelled или забыт
           → журнал assist.step → следующий в очереди
спросить:  токен → свой экземпляр? → свой владелец? → ждать ≤ wait → состояние
отбить:    токен → свой экземпляр? → свой владелец? → снять или оборвать → забыть
```

**Гонки.** Отбой и ответ модели в один момент: что завершилось раньше под блокировкой шагов, то и исход; после отбоя
шаг забыт, поздний ответ модели отбрасывается. Два `POST` одного владельца сверх `PER_USER`: счёт — под той же
блокировкой, второй получает 429. Строку отпустили, пока шаг в работе: процесс модели гаснет (глава 1 Н1.3), шаги
забыты, у нового держателя — 410. Токен истёк посреди долгого опроса: ответ этого опроса выдаётся (токен проверен при
приёме запроса), следующий запрос просит новый `where`.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токена нет, не тот, истёк | 403 `forbidden` | страница | `where` снова, один раз |
| тело больше 1 МиБ | 413 | страница | — |
| тело не по форме шага | 400 `bad step`, `detail` | страница | — (ошибка страницы) |
| модель грузится | 503 `loading`, `retry_after` | страница | повтор через `retry_after` |
| модель `failed` или `stopped` | 503 `model unavailable`, `detail` | страница | слова админу |
| у владельца уже 2 шага | 429 `too many steps` | страница | дождаться или отбить свой шаг |
| очередь полна | 503 `busy`, `retry_after` | страница | повтор через `retry_after` |
| шаг у другого держателя или до перезапуска | 410 `gone` | страница | ход заново |
| шага нет, чужой или забыт | 404 `no such step` | страница | ход заново |
| соединений сверх предела | 503 `busy`, `Retry-After: 1` | страница | повтор |

## Н5 Приёмка

[Приёмка 2](../acceptance/2/README.md) — стенд с держателем модели и **заглушкой модели** вместо сервера модели
(ADR-0093 доп. (1) п. 11): фазы `loading` → `running`, шаг `202` → `done`, долгий опрос, `bad step`, 403 без токена,
владелец шага (чужой — 404; стенд домена, два человека), `PER_USER`, отбой, `abandoned`, `too long`, `failed`. Кеш между
людьми, журнал без текстов, 410 после смены держателя — чтением.

**Заглушка модели** — программа раннера `model-stub`, которую стенд называет в `MODEL_COMMAND` (глава 1 Н1.3) вместо
сервера модели. Поле строки модели её не включает: заглушка — свойство стенда, не настройка. Протокол заглушки:

```yaml
start:   model-stub <файл ответов>; окружение — как у процесса модели (глава 1 Н1.3); слушает ASSIST_MODEL_SOCKET
script:  файл ответов — UTF-8, LF, поля через TAB, строки с # — пояснения; первая строка — load <секунды>; дальше
         строка на каждый запрос POST /v1/chat/completions по порядку: <после, секунды> <статус> <тело ответа JSON>;
         <после> — hang: ответа нет, пока держатель не оборвёт соединение
health:  GET /health — 503 первые load секунд от запуска, затем 200
step:    запрос n получает строку n: через <после> секунд — статус и тело; строк не хватило — 500
seen:    заглушка пишет в свой stderr строку на запрос: n, число сообщений, обрыв (aborted) — без текстов
```
