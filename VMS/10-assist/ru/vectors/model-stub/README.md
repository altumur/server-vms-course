# Файлы ответов заглушки модели — приёмка 2

Владелец — урок V/10 ([нормы главы 2](../../spec/10.2-assist.norms.md) N5 «Заглушка модели»). Читает программа раннера
`model-stub`: стенд приёмки 2 называет файл сценария в `MODEL_COMMAND` (`{model_stub} {spec}/VMS/10-assist/vectors/model-stub/<scenario>.tsv` — файл по имени сценария,
[README приёмки 2](../../acceptance/2/README.md)). Файл — не ожидание: он задаёт, что «модель» ответит; ожидания — в
`scenarios.tsv` приёмки.

Текст производный от `vectors/model-stub/README.md`, руками не правится: источник — английский [`vectors/model-stub/README.md`](../../../vectors/model-stub/README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Форма файла — UTF-8, LF, поля через TAB, строки с `#` — пояснения:
- первая строка — `load <seconds>` или `load hang`: столько секунд от запуска `GET /health` отвечает 503 (при `load hang`
  — всегда: модель не загружается), затем 200 — и во время шага;
- необязательная вторая строка `busy`: во время шага `GET /health` отвечает 503, как сервер с одним занятым слотом;
- дальше строка на каждый запрос `POST /v1/chat/completions` по порядку: `<after>` (секунды или `hang`), `<status>`,
  `<JSON response body>`; `hang` — ответа нет, пока держатель не оборвёт соединение; строк не хватило — 500.

| Файл | Сценарий | Что отвечает |
|---|---|---|
| `01-loading.tsv` | `01-loading` | не загружается никогда |
| `02-step.tsv` | `02-step` | загружена сразу; первый шаг — `done`; второй — `hang`; третий — 500; четвёртый (шаг с историей) — `next` |
| `03-limits.tsv` | `03-limits` | два шага — `hang`; во время шага `/health` — 503 (`busy`) |
| `04-owner.tsv` | `04-owner` | один шаг — `for ann` |
