## Что такое урок V/10

Подсистема `assist`. Админ пишет на странице VMS обычным текстом: «включи запись по движению на камерах 3-го этажа,
хранить 14 дней». Модель — воркер подсистемы без своих прав — предлагает **план**: пакет правок строк. Цикл хода,
инструменты и проверку плана исполняет **браузер** сессией админа: модель видит только то, что видит админ, и не
делает больше, чем он. Проверенный план админ видит как diff «было → станет» и применяет сам. Запись идёт обычными
дверями консоли с CAS. Опасная ошибка модели — правдоподобная подмена поля, значения, действия или отбора, а не выдумка.
Её ловит детерминированная проверка плана вне модели, а не модель; ослабить проверку нельзя ни манифестом, ни моделью.

## Главы

| V/10.5 | **План и его проверка.** **Цели плана — закрытый список** (ревью С-6): правка полей строк единиц подсистем с манифестом (`PUT /<sub>/<rows>/<id>`). Без создания и удаления: «удали» — `refuse`. Таблицы, политика, вывод, метки серверов, люди, гранты, домен — вне V/10. Форма плана: `summary`, отбор (`named` или `where` в `select_sub`, связь `about` к `edit_sub`), `fields` (поле → слово админа), правки `{unit, field, from, to, why}`, `revision` строки на момент чтения. Чей это формат — Р8. Проверка детерминирована, идёт до показа админу и не настраивается: (а) форма и права, те же, что у ручного ввода: поле есть, не id, не `fixed`, не blob, тип и `enum`, обязательное, `from` равно нынешнему, правка не пустая, `why` не пуст, `may admin` на строку (Р6); (б) сверка с **текстом просьбы**: поле и значение правки — и **поле и значение каждого условия отбора** (ревью Б-3) — названы. Правила «названо» — закрытый список с вектором на каждое (ревью С-1, С-2); не названо — **структурное подтверждение**: оболочка сама показывает пару (единица или условие, поле подписью, было → станет), а не текст модели (ревью С-1); (в) полнота отбора: лишние и пропущенные единицы, списки — по изменению (v3.6); (г) действие вне набора и цели вне списка — отказ. Слова причины уходят модели. | цели и правила (а), (г) — свои; **до передачи**: алгоритм «названо» (нормализация, подписи, числа с единицами), (в), слова причин; подтверждение и отбор в (б) — **до разбора** | P/06.1 Н3; `row-check` Р2; P/02.1 (поля) |
| V/10.6 | **Применение и секреты.** Diff по подписям `display`: у каждой единицы — значение поля, по которому она попала в план, условие отбора словами. «Применить» — по правке PUT строки дверью консоли с `If-Match: <revision>` из плана (П1). Применение **частичное** (ревью С-4), исход по каждой правке: применена; отказ CAS (412 `revision moved`); иной отказ двери со словами (схему, `ref`, `must_match` проверяет только сервер, П2); неизвестно (таймаут) — строка читается заново, PUT сам не повторяется (P/07 Н1.5). Итог — админу; перестраиваются только неприменённые правки. Секрет: значение из поля секрета подставляет браузер при применении вместо метки; модель секрета не видит ни в просьбе, ни в чтении (маска). Журнал записи — `audit` консоли от имени админа. | не зависит | P/06.1 Н3 (`If-Match`, 412); P/06.2 Н1.4, Н3; P/07 Н1.5 |

Сведения урока (не нормы): набор оценки модели — наборы пилота R01–R20, H, K, L, M, N, английский — с замерами пакета
передачи (среднее и разброс, правило сравнения — ревью М-1); выбор модели и весов (gpt-oss-20b, Q8_0 ≈ 11 ГБ,
llama.cpp; шаг 25–50 с на M1 Pro, на целевом сервере не мерился).

Вне урока (ADR-0093 п. 9): облачная модель, MCP-сервер, фоновые задания без админа. Ход под сессией консоли домена —
тоже вне, если разбор не решит иначе (ревью М-3).

## Черновик манифеста `assist.subsystem.yaml`

```yaml
# Text-driven configuration (`assist`, V/10): a model proposes edits, the browser checks them, the admin applies them.
name: assist
slot: {prefix: m, name_env: ASSIST_NAME}
# The holder of a model row is a platform worker (P/03) with the model server beside it (Р4). It reads no other
# subsystem's rows, holds nobody's credentials and has no rights of its own: everything it is told comes from the
# page under the admin's session (V/10.3).
worker: {exec: /usr/lib/assist/worker, stop_timeout: 30}
lease: {unconfirmed_max: forever}       # a model answers nobody but the page; nothing it does is an action
unit:
  rows: models                          # assist/models/<name>: one model instance
  id: name
  fields:
    name:      {type: string, required: true}
    enabled:   {type: bool,   default: true}
    model:     {type: string, default: gpt-oss-20b, enum: [gpt-oss-20b]}   # weights in the package (Р3)
    quant:     {type: string, default: q8_0, enum: [q8_0]}
    context:   {type: int,    default: 16384, schema: {minimum: 4096, maximum: 65536}}
    reasoning: {type: string, default: medium, enum: [low, medium, high]}
    labels:    {type: list,   default: [assist]}   # placement: only a server labelled for the model's memory
placement:
  constraint: labels-subset
  capacity: {from: capacity, default: 1, base_mb: 64}   # no unit_mb: the model's memory is the label's promise (Р3)
snapshot: [model, labels]
# door: the model's door — Р2, until the review is settled (routes: [chat] with where(), or pass: [chat])
# rights: {routes: …} — who talks to the model: a grant on assist (review Б-1)
metrics:
  - {name: models_running, from: status.phase, agg: count, equals: running, live: true}
  - {name: steps_total,    from: heartbeat.steps, agg: sum}
console:
  running: models_running
display:
  unit: модель ассистента
  units: модели ассистента
  units_count: моделей ассистента
  section: Ассистент
  fields: {model: модель, quant: веса, context: окно, reasoning: рассуждение, labels: метки сервера}
```

Не решено в черновике: `door` и `rights` (Р2), ряды пульса, нужна ли часть `parts` (Р4), профиль приёмки с
заглушкой модели (ревью С-2 п. 3). `about` у строки модели нет: она ни о чём.

## Решения для плана — отличия от ADR-0093 и пилота (на решение «Архитектора»)

1. **Р1. Панель — раздел страницы VMS, своей оболочки нет.** Оболочку консоль отдаёт только у `CONSOLE_ROOT`;
   смонтированная подсистема получает 404 `is mounted` (P/06.5 Н1.1 `root`, Н4 `MountedPage`), а у VMS корень — `cam`.
   Поэтому `assist.shell.html` не будет страницей. Панель «Ассистент» — раздел страницы VMS (канон
   `VMS/01-cam/cam.shell.html`), как раздел «Сценарии» у `auto` (V/08.5). Поведение панели нормирует V/10.3–V/10.6, код
   живёт в каноне страницы. Это ответ на вопрос ревью С-7 «собирает ли панель `08-page`». ADR-0093 п. 1 называет
   `assist.shell.html` — нужна правка ADR.
2. **Р2. Доступ к двери модели — до разбора** (ревью Б-1, Б-2; «Архитектор» 2026-10-28: не фиксировать). В обоих
   вариантах протокол асинхронный (V/10.2) и есть отбой при уходе со страницы.
   - **(а) Дверь держателя через `where(ref).door`** с токеном двери (`door.routes: [chat]`, договор `door-token`: токен
     узкий, 120 с, к консоли не годится), как WHEP у `live`. Учётные данные админа воркеру не уходят. Шаг ведёт
     держатель строки модели — то есть сервер с моделью. Сроки — свои константы урока.
   - **(б) Передача консоли `door.pass`.** Воркер получает `Authorization` и `X-Operator` админа (gate-and-pass
     «Передача»), поэтому норма урока должна запретить ему любые обращения к консоли и хранилищу с ними, хранение и
     журнал, а сервер модели — держать без них. Ответ должен укладываться в `PASS_WAIT` 5 с. Передача идёт «живому
     воркеру с дверью (наименьшее имя)», не держателю строки модели: если серверов модели несколько или воркер стоит
     и на серверах без модели (Р3), её получит не тот процесс — обёртке пришлось бы пересылать шаг держателю.
   - Наблюдение «Спецификации VMS»: (а) ложится без новых механизмов и снимает и Б-1, и маршрут к серверу модели.
3. **Р3. Память — обещание метки, а не правило памяти воркера.** Базовый воркер `m-<SERVER>-1` ставится на каждом
   сервере (P/02.4 Н1.1), а `CAPACITY > 0` (P/02.4 Н1.5). С `unit_mb` ≈ 12 500 базовый воркер не стартовал бы на сервере
   без памяти под модель (P/03.4 Н1.2 `memory`). Поэтому `unit_mb` не задан, строка модели встаёт только на сервер с
   меткой (`labels-subset`). Метку оператор ставит серверу с памятью ≥ 16 ГБ, V/09.2 называет это предпосылкой.
   Остальные серверы держат лёгкий воркер без строк.
4. **Р4. Где живёт сервер модели** (ревью С-8 предлагает часть `parts`). Часть — служба `<dep>-assist-<часть>.service`,
   а она ставится на **каждом** сервере, где установлена подсистема (P/02.4 Н1.1 `units`). Тогда llama.cpp с весами
   13 ГБ поднялся бы везде, а не по метке. Варианты:
   - (а) **дочерний процесс держателя**: обёртка поднимает сервер модели для взятой строки и гасит его со строкой, как
     держатель `cam` — свой конвейер. Размещение по метке работает, память считается в PSS воркера (V/01.2-08);
   - (б) **часть, которая грузит веса лениво**: по сигналу обёртки, только на сервере, где взята строка. Это свой
     механизм поверх части.
   Рекомендация — (а).
5. **Р5. Чтение — целыми списками, фильтрует оболочка** (ревью С-3). У `GET /<rows>` нет фильтров и нет выдачи одной
   строки (P/06.1 Н2), поэтому `find_units` и `field_values` считает браузер над полным списком, как в пилоте. Урок
   называет предел строк на подсистему для хода (константа V/10.4); сверх него — `refuse` со словами.
6. **Р6. Право правки — `admin`.** PUT строки единицы требует `admin` на единицу (gate-and-pass), а не `edit`, как в
   пилоте. Проверка прав плана — `may("admin", <unit>)` модуля; окончательно проверяет сервер.
7. **Р7. Подписи — в `display` манифестов VMS.** Слова полей и вариантов модель берёт из `display.fields`,
   `field_help`, `options` (P/06.5 Н1.2). В манифестах VMS 01–07 их сейчас почти нет, пилот подкладывал свою накладку.
   Дополнить `display` манифестов `cam`, `rec`, `live`, `det`, `detjob`, `detedge`, `auto` — отдельной серией
   «Спецификации VMS» до глав V/10.4–V/10.5. Это заодно польза форме консоли.
8. **Р8. Формат пакета правок — не урока VMS** (ревью С-5). По заделу 2026-10-25 массовая правка — платформенная (страница
   над модулем, утилита, консоль домена), а платформа VMS не читает. Варианты: (а) формат сразу — договор платформы
   (`Platform/common/contracts/`, правкой «Спецификации» по запросу), V/10 ссылается; (б) у V/10 свой формат плана,
   который при проектировании массовой правки переезжает в договор платформы, а V/10 переходит на ссылку. План урока
   не называет формат «форматом массовой правки». До разбора V/10.5 пишет форму плана своей с пометкой.
9. **Р9. Состав уроков.** V/10 меняет состав уроков ADR-0090 доп. (2) (ревью С-7). Нужна строка в ADR-0093 и строка
   `VMS/common/lessons.tsv` с первой главой. Почему урок в `VMS/`, а не в `Platform/`: платформа не меняется (ADR-0093
   Context), а `assist` — подсистема со своим манифестом.

## Что нужно от платформы и модуля консоли, пробелы (входящим «Архитектору», не правкой)

| № | Что | Есть ли | Для какой главы | Блокер? |
|---|---|---|---|---|

## Приёмка

Оболочка — канон урока, её не генерируют реализации; реализации генерируют воркер (ревью С-2 п. 2). Поэтому:

- **Приёмка 1 — консоль:** манифест грузится строгим загрузчиком; строка модели, `labels-subset`, отказы формы у двери.
  Стенд VMS, `assist` смонтирован.
- **Протокол двери воркера** — приёмка реализаций раннером: сценарии стенда с **заглушкой модели** вместо llama.cpp и
  весов (проигрывает записанные шаги; профиль приёмки или ключ файла подсистемы её включает — ревью С-2 п. 3).
  Проверяются: постановка шага, состояние, отбой, `busy`, `loading`, допуск (без токена или гранта — отказ), текст не
  в журнале, учётных данных админа у воркера нет (в варианте Р2 (б) — воркер с пересланным токеном не обращается к
  консоли).
- **Векторы проверки плана** `vectors/plan-check/`: строка — просьба, план, обзор единиц (манифесты, строки, гранты
  сессии) → вердикт `ok` | `refused` | `confirm` и слово причины. Исполнитель — **jsdom над каноном страницы** в
  `tests/console` (гонит «Спецификация»), а не раннер. Формат — по образцу `VMS/04-det/vectors/mask/`. Классы: поле,
  значение, действие, отбор (условие, лишние, пропущенные, списки), права, `fixed`, id, тип (булевы строкой,
  `0 ≠ false`), секрет, цель вне списка. Строки (а), (г) — свои. Строки (б), (в) — после передачи: пакет несёт векторы,
  выданные проверкой пилота на его наборах, и канон страницы обязан их пройти (дифференциальная сверка переноса — ревью
  С-2 п. 4); инструменты пакета перед этим сверяются с выгрузкой, закреплённой для VMS.
- **Сценарии оболочки с заглушкой модели** — тоже jsdom: заглушка двери модели проигрывает записанные шаги (вызовы
  инструментов, план, `ask_admin`, `refuse`). Проверяются цикл, исполнение инструментов дверями консоли из перечня,
  остановка на вызове, возврат причины модели до N раз, структурное подтверждение, diff, частичное применение с
  `If-Match` (412, неизвестный исход → чтение), секрет не уходит в дверь модели.
- **Набор оценки модели — не приёмка:** сведения урока, `data/eval/` из пакета передачи; прогон — у пилота.
