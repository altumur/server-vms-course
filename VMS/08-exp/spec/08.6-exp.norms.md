# V/08.6 — Часть — единица выгрузки: нормы

Канон главы 6 урока V/08 «Выгрузка» (до 2026-11-03 — глава V/13.1, ADR-0118 доп. (1)) (ADR-0080; модуль VMS — ADR-0090; подсистема экспорта — ADR-0117 с доп. (1)–(6)).
[Лекция](../08-exp.md), [инструкция](08-exp.README.md), манифест [`exp.subsystem.yaml`](../exp.subsystem.yaml). Платформа —
выгрузка `cammeta-specs` `7a875c75`.

Выгрузка — копия отрезков архива или одного кадра в файлы со сроком. Заказ оператора может назвать несколько камер и
отрезков, но единица подсистемы — **часть**: одна камера, одна запись (или живое этой камеры), её отрезки и её файлы. Часть
стоит рядом со своей записью, режет видео, которое читает дверями регистратора, и держит файлы на своём томе, пока не выйдет
срок. Координатора нет: ход и итог заказа `backend` собирает чтением частей (V/11). Глава нормирует строку части, её
размещение, состояние, пределы, права и журнал.

Id норм — `V/08.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Заказ** — одна просьба оператора `POST /exports` (V/11); у заказа нет своей строки (доп. (5) п. 1).
- **Часть** — строка `exp/parts/<name>`; **ведущая часть** — часть, чьё `name` равно `export`: она несёт заказ.
- **Держатель части** — воркер `exp`, которому размещение отдало часть.

## Н1 Форма

**Данные.** Строки `exp/parts/<name>` (единицы), состояние `exp/state/cursor/<name>`, `exp/state/result/<name>` (P/03.6 Н1.7),
просьбы `exp/requests/<rid>`, журнал событий части `exp/<name>/e<эпоха>/` с `of: cam/<cam>` (P/03.6 Н1.2). Читает: пульсы
`rec/heartbeats/*`, строки `rec/recordings/*`, `rec/volumes/*`, `cam/cameras/*`, пульсы `live/heartbeats/*` (`worker.reads`);
заводит и продлевает `live/streams/<cam>` (`worker.creates`, глава 7 Н1.2); удаляет свои строки `exp/parts/*`
(`worker.deletes`, глава 8).

### Н1.1 Строка части

| Поле | Форма | Смысл |
|---|---|---|
| `name` | `string`, обязательно | id части: у ведущей — id заказа, у прочих — `<id заказа>-<n>`, `n` с 1 по порядку частей заказа |
| `export` | `string`, обязательно, `fixed` | id заказа — `name` ведущей части |
| `cam` | `string`, обязательно, `fixed` | камера; `about: {sub: cam, field: cam}` — права, метки и журнал камеры |
| `rec` | `string`, `fixed`, `ref: rec/recordings`, `must_match: {cam: cam}` | запись архива; у живого кадра — нет |
| `source` | `archive` \| `live`, обязательно, `fixed` | откуда кадры |
| `mode` | `video` \| `frame`, обязательно, `fixed` | видео или один кадр |
| `periods` | `json`, `fixed`: до 32 отрезков `[from, to)`, секунды Unix медийного времени | что выгрузить; у кадра — нет |
| `at` | `float`, `fixed` | момент кадра архива |
| `format` | `mkv` \| `mp4` \| `avi` \| `jpg` \| `pdf`, обязательно, `fixed` | контейнер; `jpg`, `pdf` — только `mode: frame` |
| `settings` | `json`, `fixed`, схема манифеста | `quality`, `width`, `height`, `fps_div`, `audio`, `titles`, `font`, `area`, `single_file`, `file_mb`, `chapters` (глава 7 Н1.4) |
| `password_secret` | `string` | пароль ZIP AES-256 или PDF; уходит вместе со строкой (доп. (4) п. 3) |
| `by` | `string`, обязательно, `fixed` | автор: человек билета, создавшего заказ; копия в каждой части (доп. (6) п. 4) |
| `comment` | `string` | слова автора; копия в каждой части |
| `supervised_by` | `string`, `fixed` | имя человека, подтвердившего заказ (ADR-0119 п. 5, доп. (1) п. 3); копия в каждой части; нет надзора — поля нет |
| `retry_of` | `string`, `fixed` | id заказа, неудачные части которого повторяет этот (V/11) |
| `keep` | `int` ≥ 60, умолчание 86400, `fixed`, `hidden` | сколько секунд живут файлы после конца части — `EXPORT_KEEP` (глава 8 Н1.4); описание вида его не показывает, человек видит `result.expires` (М3 ревью норм слияния; решение «Спецификации VMS») |
| `labels` | `list`, умолчание `[]` | `["gpu"]` у части, которой нужно перекодирование (глава 7 Н1.4) |

- **Кто пишет.** Части заказа пишет `backend` одним пакетом двери консоли (`BATCH_WRITES`) с билетом человека (V/11; доп. (4)
  п. 1): по части на камеру и запись, у живого кадра — одна часть без `rec`. Общие поля заказа (`by`, `comment`, `supervised_by`, `format`,
  `settings`, `keep`, `retry_of`) лежат в каждой части одинаковыми: дверь файла неведущей части судит своё `by`, а
  ведущая может сняться раньше прочих (доп. (6) п. 4).
- **Поля `fixed`** правкой не меняются (договор проверки строки); правки строки части нет — есть просьбы (глава 8).
- `jpg` или `pdf` у `mode: video`, `mkv`, `mp4`, `avi` у `mode: frame`, `periods` у кадра, `at` у видео, `source: live` с
  `rec` или с `at` — отказ `backend` при создании (V/11); держатель такую строку не исполняет: итог `failed`, `why` — поле.

### Н1.2 Размещение

| Ключ | Значение | Смысл |
|---|---|---|
| `capacity` | `{from: capacity, default: 64}` | частей, которые воркер **держит**, готовые тоже — до срока своих файлов (доп. (4) п. 2): это память о файлах, не работа (С1 ревью норм; слово «Архитектора») |
| `headroom` | `{from: headroom}` | сколько воркер ещё возьмёт |
| `constraint` | `labels-subset` | `labels` части ⊆ метки сервера: перекодирование — на сервере `gpu`; ни у одного сервера кластера метки `gpu` нет — `backend` отказывает заказу с перекодированием до записи (V/11; М2 ревью норм) |
| `near` | `{sub: rec, by: rec}` | сродство, не фильтр: рядом с регистратором записи (ADR-0117 п. 1.2) |
| `requires` | `resource` | строки журнала камеры — в ресурс своего сервера |
| `tie_break` | `most-free-capacity` | |

- **Работа** (С1 ревью норм): одновременно перекодируют не больше `EXP_ACTIVE` частей воркера — ключ файла подсистемы
  `/etc/exp/exp.env`, умолчание 2; прочие ждут без хода (`cursor.done` не растёт). Перепаковка и кадры `EXP_ACTIVE` не
  ограничены: до `capacity` частей воркера разом читают `/samples` регистраторов, а их двери на перегрузку отвечают пределами
  соединений (`door_limits`, V/02.5). Ответ `503 busy` двери записи часть считает неответившей дверью: отрезок — у другой двери
  с этим спаном, иначе итог `unreachable`, повтор — `retry-failed` (V/11) — предел (М1 ревью норм слияния; решение
  «Спецификации VMS»). Место — `no_space` тома (ниже).
- **Без `ends` и `retire_when`**: часть снимает её держатель удалением строки по сроку (глава 8 Н1.4; доп. (5) п. 4, доп. (6)
  п. 1). Закрепления за сервером после `done` в P/04 нет: держатель переехал — файлы части на прежнем томе потеряны, часть
  `expired` с причиной — предел (доп. (4) п. 2).
- **Том** — часть `files` подсистемы с `volumes: true` и долей `files` (`kind: dir`), её воркер берёт через `uses: [exp.files]`
  (ADR-0117 доп. (3) М; P/02.4 Н1.1). Кольцо архива том не трогает. Место — размер тома: нехватка — новая часть отказывается
  (`no_space`), чужие файлы не вытесняются (ADR-0117 п. 1.7).

### Н1.3 Состояние

- **`cursor`** — `{revision, done, bytes?, at}`: ревизия строки, к которой он относится; доля готового `0…1`; записано байт; когда
  записан. Пока часть идёт — не реже раза в 5 с (ADR-0117 § 2). Истина — `GET` строки, поток `backend` — его перевод.
- **`result`** — `{end, expires?, code?, partial?, files?, why?}`: `end` — `done` | `failed` | `canceled` | `expired`; `code` — `no_recording`,
  `unreachable`, `no_space`, `limit`, `offline` (§ 2); `partial` — дыры `[from, to)`; `files` — `[{id, name, size, sha256}]`,
  `id` — `f<n>`; `expires` — момент конца части + `keep`: конец файлов и строки (глава 8 Н1.4; М1 ревью норм); `why` — слова.
  Частичный успех — норма: `done` с `partial`.

### Н1.4 Пределы

Значения — «Архитектора», правятся замером (ADR-0117 § 3); все отдаются в `reference.export.limits` (V/11):

| Константа | Значение | Кто судит |
|---|---|---|
| `EXPORT_TOTAL_MAX` | 24 ч видео в заказе суммарно | `backend` при создании; держатель — у своей части |
| `EXPORT_PERIODS_MAX` | 32 | схема поля `periods`; `backend` — по заказу |
| `EXPORT_CAMERAS_MAX` | 16 | `backend` |
| `EXPORT_ACTIVE_PER_USER` | 4 незавершённых заказа человека | `backend` |
| `EXPORT_FILE_MB` | 4000 МБ — части файла, умолчание; окно правит в `settings.file_mb` до предела | схема `settings` |
| `EXPORT_LINK_TTL` | срок токена `where` платформы — 120 с (доп. (3) М) | консоль |
| просьбы человека | `per_person: 64` = `EXPORT_CAMERAS_MAX` × `EXPORT_ACTIVE_PER_USER`, `cancel` и `delete` вместе (М ревью доп. (6)) | консоль |
| частей, которые держит воркер | `capacity` 64 | размещение |
| одновременных перекодирований воркера | `EXP_ACTIVE` = 2 | воркер |

### Н1.5 Права

- **Создать** часть — `edit` на `exp` по камере (`rights.routes: {edit: [parts]}`; ADR-0117 п. 4.1), право — по `about`
  камеры. Функции роли `EXPORT`, `ALLOW_UNPROTECTED_EXPORT`, `ALLOW_SHOW_PRIVACY_VIDEO_IN_ARCHIVE` переводятся в ранги `exp`
  (V/11.8; доп. (4) п. 4, доп. (5) п. 3, доп. (6) п. 3): `edit` — `EXPORT`; `admin` — `EXPORT` и оба флага. Живой кадр — ещё
  право живого просмотра камеры: судит `backend` при создании (доп. (2) п. 3).
- **Без маски** выгрузка доступна только с `admin` на `exp`: маскирования пока нет, обязательная маска неисполнима (доп. (4)
  п. 5); `backend` отказывает до записи (доп. (2) п. 4).
- **Своё и чужое.** Ссылку и байты получает только автор — человек `by` части; право на журнал даёт только сведения о чужой
  части (доп. (2) п. 5). `admin` на `exp` снимает и чужие части своих камер (доп. (5) п. 3).
- **Надзор** (ADR-0119): требует ли роль автора подтверждения и подтверждает ли супервизор, судит консоль кластера
  проверкой `/domain/verify` с `need {admin, exp, [cam/<id>…]}` по билету `backend`; `backend` пишет части только после
  `200` с `supervision.ok` и `may: allow` у каждой камеры, с `supervised_by` — именем проверенного (V/11; доп. (5), (6)). Сам
  держатель части надзор не судит: строка без `supervised_by` при требовании надзора дверью `backend` не пишется.
- **`depth`** роли экспорт не судит, как и архив (V/11.8 — 422): предел первой генерации (доп. (5) п. 4).

### Н1.6 Журнал

Строки журнала событий части с `of: cam/<cam>` — журнал камеры (`about`); пишет держатель части (P/03.6 Н1.2), класс —
наблюдение:

| Вид | Когда | Поля |
|---|---|---|
| `export.made` | держатель начал часть | `export`, `by`, `source`, `mode`, `periods` или `at`, `format`, `password` — `true`, если пароль дан (сам пароль — нет), `mask`, `comment`, `supervised_by` — если есть |
| `export.refused` | держатель отказал части до работы (`limit`, `no_space`, поле не по форме) | `export`, `by`, `code`, `why` |
| `export.finished` | итог `done` | `export`, `files` (`name`, `size`, `sha256`), `partial` |
| `export.issued` | дверь файла впервые видит токен этого человека на эту часть | `export`, `user` |
| `export.read` | одно скачивание файла (глава 9 Н1.2) | `export`, `user`, `file` |
| `export.deleted` | файлы удалены: просьба, отмена или срок | `export`, `by` (кто), `why` (`delete` \| `cancel` \| `expired`) |

Отказ `backend` до записи частей (403, 422) — его ответ и журнал двери консоли, не журнал камеры: частей ещё нет.

## Н2 Двери

Строки — дверь консоли (P/06.1), пакет — `BATCH_WRITES` (V/11). Дверь файла — глава 9.

## Н3 Проход

```
backend: заказ → проверка (V/11) → пакет частей → размещение (near rec, labels) → держатель: export.made → работа (глава 7)
  → итог (Н1.3) → файлы до result.expires (глава 8) → удаление файлов и строки
```

**Гонки.** Две части одного заказа на разных серверах идут независимо; общий итог — сумма частей (V/11). Просьба `cancel`
раньше старта части — часть не начинается, итог `canceled` (глава 8).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| нет `edit` на `exp` по камере | 403 двери консоли, пакет не записан | `backend` → оператор | — |
| поле не по схеме манифеста | 400 двери консоли | `backend` | — |
| сочетание полей не то (Н1.1) | `backend` — 422; строка без него — итог `failed` | оператор | — |
| места на томе нет | итог `failed` `no_space`, `export.refused` | оператор | позже или меньше |
