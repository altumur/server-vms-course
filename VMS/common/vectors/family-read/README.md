# Векторы семей VMS (family-read)

Таблица `NN.tsv` на урок VMS, владеющий семьями `VMS/common/data/catalog.tsv` (решение «Архитектора» по запросу VMS
«семьи в открытых местах», вариант А). Строка: семья (`family`, `kind`, `place` — строка каталога VMS), конкретный ключ,
режим и роли (`who`), текст строки семьи платформы (`text`, как в `Platform/common/vectors/family-read/`), вердикт и пути
отказа (от корня строки), исход у каждого читателя (`outcome`: роль → пути строк `outcomes.tsv` семьи VMS, пути — от
значения места). Сначала строку судит семья платформы, затем схема VMS — значение в каждом экземпляре места `place`.
Строки, где отказывает сама семья платформы, сюда не входят — это векторы платформы.

Строит `python -m v7.vms --root . --tables` (из `skills/lesson-spec/scripts`), судит `check_spec`.

## Кто исполняет и провод

Как у пакета платформы `common/family-read`: таблицу `NN.tsv` исполняет урок-владелец её семей (колонка `owner`
каталога VMS) — `01.tsv` реализация `cam`, `02.tsv` — `rec`, `03.tsv` — `live`, `04.tsv` — `det`, `05.tsv` — `detjob`,
`06.tsv` — `detedge`, `07.tsv` — `auto`; таблицы нет — у урока нет семей. Пакет — `VMS/common/family-read` (путь в
выгрузке без `vectors/`), единая команда пакета векторов общего README приёмки платформы: профиль реализации объявляет
`vectors` → `VMS/common/family-read` своей командой с `{input}`. Вход — `cells` `family`, `key`, `kind`, `place`, `mode`,
`who`, `text` строкой ячейки (ожиданий, `case`, `note` во входе нет). Ответ — JSON `{"verdict", "paths", "outcome"}`, сравнение
как у платформы: строго вердикт, множество путей и исход по каждой роли `who`. Реализация судит строку семьёй платформы
и значение в каждом экземпляре места `place` схемой VMS (колонка `schema` каталога VMS); исходы — по `outcomes.tsv`
семьи VMS. Нет записи `vectors` у владельца таблицы — цель `blocked`.
