# V/04.3 — События детектора: нормы

Канон главы 3 урока V/04 «Живая детекция» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../04-det.md),
[инструкция](04-det.README.md), манифест [`det.subsystem.yaml`](../det.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `84a28c6`.

Выход детектора — не видео, а строки событий в журнале ресурса своего сервера. События — не подсистема: у события нет
единицы работы, его место решено писателем, чтение и слияние — платформа. Глава нормирует, что детектор пишет, какого
класса строка, что подавляется и как засечка доходит до экрана. Механизм журнала — [договор журнала событий](../../../Platform/common/contracts/event-journal.md),
писатель воркера — [P/03.6 Н1.2](../../../Platform/03-worker/spec/03.6-worker.norms.md).

Id норм — `V/04.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `t` строки — секунды Unix момента наблюдения модели (часы воркера).

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — файлы журнала ресурса
своего сервера `<корень событий>/det/<name>/e<эпоха>/…events.jsonl` и `<корень событий>/det.alarms/<name>/e<эпоха>/…`
([P/05](../../../Platform/05-resource/spec/05-resource.norms.md) Н1.2); `requires: resource` (V/04.1 Н1.4) ставит детектор
на сервер с ресурсом.

### Н1.1 Запись

Каждое событие модели `(kind, поля)` (глава 2 Н1.2) — одна строка журнала писателем воркера (P/03.6 Н1.2): дерево `det`,
единица — имя детектора, эпоха — его эпоха (глава 2 Н1.3); `of: cam/<cam>` — из `about` (V/04.1 Н1.1): события детектора —
события камеры, их находят запросом о камере. Подсистема, единица и эпоха в строке не повторяются — их говорит путь.

- Перед **каждой** записью воркер проверяет право писать под арендой ([P/03.2 Н1.6](../../../Platform/03-worker/spec/03.2-worker.norms.md)
  `may_write`; `unconfirmed_max` — умолчание `off`): аренда не подтверждена — строка не пишется, модель не останавливается до
  решения рантайма.
- Поля модели — верхние поля строки рядом с полями журнала (`t`, `id`, `kind`, `class`, `of`, `v`); модель не отдаёт полей с
  этими именами, своё `occurred` — только конечное число (договор журнала событий «line», «Отказы писателя»). Поле `cam` модель МОЖЕТ не говорить: связь с камерой — `of`.
- Строка не записалась — ошибка записи или аренда не подтверждена (`may_write` ложен): строка потеряна, счёт `events_refused`
  пульса (глава 4 Н1.1 — то же определение); модель идёт дальше.

### Н1.2 Класс строки

Класс решает писатель (договор журнала событий «class»): строка — `alarm`, если её `kind` есть в поле `alarms` строки
детектора (V/04.1 Н1.1; умолчание `["linecross", "lpr"]`), иначе `observation`. Тревога пишется с `fsync` в своё дерево
`det.alarms/…`, живёт сроком тревог и при переполнении окна идёт впереди наблюдений (P/05 Н1.2). Класс — факт о том, для
чего оператор поставил модель; платформа фиксирует только два слова.

### Н1.3 Подавление

`events.suppress.motion: {window: 30, by: [cam]}` (P/03.6 Н1.2): первая строка окна пишется как есть; повторы в окне
считаются; окно закрылось — одна строка `{…поля первой, id новый, repeats, since, until}`; сброс — на каждом проходе.
Подавление и без `by` раздельно по (дерево, единица, эпоха, `kind`, класс); `by: [cam]` — «любое движение этого детектора в
окне» (поле `cam` модели, отсутствующее — одно значение «отсутствует»): поля модели (оценка, рамка, счётчик) между двумя
взглядами на одну сцену плывут и наблюдений не множат. 30 с — число VMS: дерево на ветру — строка за окно, два человека с
разницей в минуту — две. `linecross` и `lpr` не подавляются: вторая машина через линию — вторая машина. `motion` подавляется и при `alarms: [motion]`:
подавление — по `kind`, класс даёт только отдельное окно (P/03.6 Н1.2).

### Н1.4 Путь засечки до экрана

Детектор никого не уведомляет: строка записана в файл ресурса — и всё. Индекс ресурса читает файлы в момент запроса
(P/05 Н1.3); страница спрашивает `/events?unit=cam/<cam>` консоли, консоль сливает ответы ресурсов всех серверов и помечает
строки прежних эпох `fenced` ([P/06.4 Н1.3](../../../Platform/06-console/spec/06.4-console.norms.md)); засечка детектора — на
шкале камеры (V/08). Пять шагов, четыре процесса, ни одного вызова от писателя к читателю.

## Н3 Проход

```
для каждого running-детектора: события модели → для каждого: may_write? → класс по alarms → подавление (motion) → строка
на каждом проходе: сброс закрытых окон подавления (строка итога)
```

**Гонки.** Подмена: новый воркер взял детектор с эпохой выше, прежний ещё пишет до потери аренды — строки прежней эпохи
читатель помечает `fenced` (P/06.4 Н1.3), дублей в одном дереве нет: эпоха — в пути.

---

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| аренда не подтверждена | строка не пишется | — | рантайм решает судьбу единицы (P/03.2) |
| запись не удалась | строка потеряна, `events_refused` | пульс | ресурс, диск |
| ресурса на сервере нет | детектор не размещается (`requires: resource`) | отчёт прохода | поставить ресурс |
