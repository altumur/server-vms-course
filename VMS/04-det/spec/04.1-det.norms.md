# V/04.1 — Детектор — единица: нормы

Канон главы 1 урока V/04 «Живая детекция» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../04-det.md),
[инструкция](04-det.README.md), манифест [`det.subsystem.yaml`](../det.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `84a28c6` (поток детектора `stream` — `41d3ec8`; маска со своим размером, `stream` — `b41527f`).

Детектор — одна модель на одной камере: «пересечение линии на камере 7». Глава нормирует строку детектора, кто её
заводит, срок, размещение и снимок. Источник и модель — глава 2; события — глава 3; пульс — глава 4.

Id норм — `V/04.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `until` — секунды Unix.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): строка `det/units/<name>` (P/06.1),
тело маски `det/blobs/sha256-<hex>` (P/06.1 Н1.5), снимок `det/snapshot/*` (P/04 Н1.3а); своих семей сверх них у главы нет.

### Н1.1 Поля

`unit: {rows: units, id: name}`; `about: {sub: cam, field: cam}` — события, гранты и метки детектора — камеры.

| Поле | Форма | Смысл |
|---|---|---|
| `name` | `string`, обязательно | имя пары; соглашение — `<cam>-<kind>` (`7-linecross`), не правило |
| `cam` | `string`, обязательно, `fixed` | id камеры `cam` (V/01.1), чей поток идёт в модель; другая камера — другой детектор; `about` |
| `stream` | `string`, `ref: cam/cameras`, `must_match: {main: cam}` | какой поток камеры идёт в модель: id прочего потока этой камеры; пусто — основной (id самой камеры — 409, V/01.1 Н1.1а); выбор пользователя; правится — перезапуск модели с новым источником, маска остаётся (масштаб — ниже) | воркер (источник, глава 2) |
| `kind` | `string`, обязательно | вид модели: `motion`, `linecross`, `lpr`, `tick` (учебная, глава 2) — реестр видов воркера |
| `params` | `string` | настройки модели, непрозрачны для платформы и **малы**: полигон — сюда |
| `mask` | `blob` | попиксельная маска со своим размером кадра (ниже «Маска и размер кадра»): строка держит `sha256-<hex>`, тело — объект `det/blobs/<digest>` (`PUT /det/units/<id>/mask`, [P/06.1 Н1.5](../../../Platform/06-console/spec/06.1-console.norms.md)); смена маски — смена строки — перезапуск модели (глава 2) |
| `mask_from` | `string` | маска заказа ссылкой: `det/<id>@sha256-<hex>` детектора оператора — только у строки с `made` (V/07.4 Н1.2; ADR-0091 п. 1) |
| `enabled` | `bool`, умолчание `true` | |
| `labels` | `list`, умолчание `["gpu"]` | где может работать: метки сервера воркера; модель без GPU снимает метку явно |
| `alarms` | `list`, умолчание `["linecross", "lpr"]` | какие виды событий детектора — тревоги (глава 3) |
| `until` | `float`, умолчание `0` | когда детектор перестаёт быть; `0` — никогда (Н1.3) |

**Маска и размер кадра.** Поток детектора выбирают и меняют (`stream`, V/01.1 Н1.1а), поэтому маска хранит свой размер:
тело — растр PGM (Netpbm `P5`, `maxval` ≤ 255), ширина и высота — в его заголовке; что значит значение точки — слово
модели, как `params`. Кадр того же размера — маска как есть. Кадр иного размера — маска масштабируется к кадру по каждой
оси ближайшим соседом: точка кадра `(x, y)` при кадре `W×H` и маске `w×h` берёт точку маски `(⌊x·w/W⌋, ⌊y·h/H⌋)`; детекция
не останавливается и не меняет фазу. Тело не PGM — маска не читается (глава 2: `failed`). Правило одно для детектора и
задачи скана (V/05.3 Н1.3): маска заказа ссылкой `mask_from` — то же тело.

Поля `cam`, `kind`, `enabled`, `params`, `labels`, `mask` читают и заказчики: регистратор (скан по `det/units/*`, V/02.8
Н1.5), задача по интервалу (V/05); их имена не меняются. Проверка строки — [договор проверки строки](../../../Platform/common/contracts/row-check.md).

### Н1.2 Кто заводит

- **Оператор** — дверью единиц консоли: `POST /det/units` (P/06.1). Формы детектора на странице VMS нет: детекторы видны
  в «Сценариях» (V/08), строки — дверью.
- **Сценарий** — заказом: `auto` объявляет `worker.creates: [{sub: det, rows: units, key: "{cam}-{kind}"}]`
  ([P/03.6 Н1.6](../../../Platform/03-worker/spec/03.6-worker.norms.md)): строка `det/units/auto-<cam>-<kind>` с `made`, срок
  — `until`; основа заказа (детектор оператора той же пары, `params` поверх) — урок V/07. Раздела `requests:` у `det` нет:
  просьб детекторам не подают.

### Н1.3 Срок

`placement.ends: {field: until, never: 0}` ([P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md)): `until`
прошёл — контроллер снимает строку с размещения, воркер останавливает модель. Строку заказа (`made`) контроллер удаляет;
строку оператора — нет: она снята и не размещается (счёт `expired_kept` отчёта прохода), удаляет её оператор (у таблицы с
`fixed`-полем и `about` не по id срок удаляет только строки с `made`).

### Н1.4 Размещение

| Ключ | Значение | Смысл |
|---|---|---|
| `capacity` | `{from: capacity, default: 8}` | потоков на воркер (декод и прогон на GPU) |
| `headroom` | `{from: headroom}` | запас — платформа: ёмкость − Σ весов назначения ([P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md)) |
| `constraint` | `labels-subset` | метки детектора ⊆ метки сервера |
| `requires` | `resource` | события пишутся в ресурс своего сервера (глава 3) |
| `near` | `{sub: cam, by: cam}` | предпочтение, не фильтр: рядом с держателем камеры — модель читает долю `cam.shm` своего сервера (глава 2); `by: cam` — сосед по полю `cam`, а не по имени детектора, которого держатель не знает |
| `tie_break` | `most-free-capacity` | |
| `rebalance` | `{dead_band: 0.10}` | |

`home` нет: на вопрос «на каком сервере живёт модель» отвечать некому. Предпочтение не выполнено — фильтры и
`most-free-capacity` разносят детекторы по серверам с GPU, источник — приёмник кластера (глава 2). `grows` нет: запасных
нет, воркеров ставит оператор (ADR-0084).

### Н1.5 Снимок

`snapshot: [name, cam, kind, enabled, until]` (P/04 Н1.3а).

## Н2 Двери

Дверь единиц консоли — `POST|GET|PUT|DELETE /det/units[/<id>]`, тело маски — `PUT /det/units/<id>/mask` (P/06.1, OpenAPI
P/06); своей двери у `det` нет.

## Н3 Проход

Своего прохода у главы нет: размещение и срок — проход контроллера (P/04 Н3), заказ — проход `auto` (P/03.6 Н1.6).

**Гонки.** Оператор и сценарий завели детектор одной пары: имена разные (`7-linecross` и `auto-7-linecross`) — работают оба;
сценарий второго детектора не заводит, если есть детектор оператора (правило V/07).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| нет `cam` или `kind` | 400 | ответ | — |
| `cam` меняется | 400 «cam is fixed …» | ответ | новый детектор |
| `stream` — поток другой камеры | 409 `conflict`, `fault: must_match` (P/06.1 Н4) | ответ | поток этой камеры |
| `stream` — id самой камеры | 409 `conflict`, `fault: must_match`: у камеры `main` пуст (V/01.1 Н1.1а) | ответ | основной поток — пустой `stream` |
| имя `auto-…` вручную | 400 (имена заказчика `auto`) | ответ | другое имя |
| маска сверх предела тела | 413 (P/06.1 Н1.5) | ответ | полигон — в `params` |
| нет сервера с метками детектора | `unplaceable` | отчёт прохода | метки сервера или детектора |

- [ ] **V/04.1-04** размещение Н1.4, снимок Н1.5: `capacity` 8, `labels-subset`, `requires`, `near` к держателю, без `home` и `grows` — чтением

## Соответствие прежним урокам

Из М10B/14 «Детекторы» — вводная, шаг 1 (единица как пара, поля, `about`, маска, `until`, размещение), шаг 6 (запас).
Отличия от свидетеля: `until` → `placement.ends`, ручная строка снимается, а не удаляется (у свидетеля — удаление
консолью, ADR-0091 п. 1, 2); раздел `requests:` (`detect`, `scan`) и исполнитель заданий детекторов сняты — детектор по
событию заводит `auto` строкой, скан — задача `detjob` (опись § 4); `near` — к держателю камеры, а не к регистратору (довод
«раздача читается по RTSP откуда угодно» снят, ADR-0075 окно 2); запас — по назначению (платформа), а не по работающим
моделям. Id ([id-map](../../common/id-map.tsv)): М10B/14 ш.1 → V/04.1-01…03; М10B/14 ш.1, 6 → V/04.1-04.
