## Подготовка

Стенд домена VMS (общий README приёмки VMS, «Стенд домена VMS»): `@domain m1`, на `m1` установлены манифесты `VMS/01-cam/cam.subsystem.yaml`, `VMS/02-rec/rec.subsystem.yaml`,
`VMS/04-det/det.subsystem.yaml`, `VMS/11-backend/backend.subsystem.yaml`, контроллеры всех четырёх. Консоль — `CONSOLE_ROOT=cam` (`member m1 console`), `backend` смонтирован:
`member m1 console2` — префикс `/backend`, поэтому API контракта — `member m1 console2 … /api/…`. Воркер `b-srv-a-1` запускает сценарий, держателей `cam`, `rec`, `det` на стенде нет: сценариям
нужны строки, а не камеры. Без комплектов TLS: обратный вызов — сокетом роли на петле (ADR-0094 доп. (6) п. 4). Файл подсистемы `backend` не задан: `/test/*` наборам не нужны.
Текущий человек после `@domain` — `root`, пароль `w2c test root password`; `@person -` — без токена. Каждый сценарий — на чистом экземпляре.

Id записей выводит V/11.4 Н1.6, поэтому сценарии пишут их значениями: домен — `d7329777-a64d-54c5-86fa-eda63d75d992`, камеры `1`, `2`, `3` — `068df1b2-b153-5712-bb0f-06efd7b21699`, `8b99c4f9-f9f1-5926-ab12-5925acb99a02`, `6a35f2a7-c9e9-5942-a4a4-5c242851765a`, человек `root` — `6ad9a883-cad5-5ab8-802f-0889506a2358`, роль `admin` — `cd290440-e663-50ed-bef1-7b3cdbab3c03`.

Черновик `POST /api/access/apply` — целиком в строке шага: своей правки снимка у раннера нет. Значения `global` — те, что снимок читает по Н1.4. Новых ролей, групп и людей сценарии называют id
клиента; люди с паролем заведены `holder POST /domain/users`, их id — v5 (Н1.2). Массивы `lines` сверяются с порядком: он канонический (P/08.4 `doc.lines`).

**Чтением** (состояние не собрать на стенде): email у читателя без права — порядок `users` норма не задаёт; уже сохранённая пара при правке другой роли — ключ папки в снимке и строке разный, связать их
раннер не может; `409 last admin` пакета — проверка Н1.8 отвечает раньше; `standby`, `frozen`, `deposed`, `names unknown`, `admin table too large`, `roles table too large`; тревога `domain.rights_via_backend`
