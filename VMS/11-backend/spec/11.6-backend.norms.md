# V/11.6 — Стенд и приёмка: нормы

Канон главы 6 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A5, Confirmation; доп. (2) п. 2; ADR-0050).
[Лекция](../11-backend.md), [инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json).
Платформа — выгрузка `cammeta-specs` `2110dbf` (пин VMS); нормы платформы B — после Go GREEN 01–10 (ADR-0094 «Порядок»
п. 1): стенд `backend` собирается только на выгрузке с ними.

Приёмку `backend` пишет не курс: критерий готовности — тесты API самого продукта, которые его бэкенд-команда гоняет против
своего сервера. Наш `backend` проходит те же тесты против нашего стенда — в профиле того, что у нас есть (глава 2).
Каталога приёмки у урока нет (`V/11 no-acceptance`). Глава нормирует стенд, профиль, служебные `/test/*` и `?selftest`.

Id норм — `V/11.6-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Тесты API продукта** — `tests/api-*.js` репозитория consolem на закреплённом коммите (страница `tests/api.html`, стенд
  тестов `tests/harness.js`; описание — `api/TESTS.md` продукта).
- **Профиль возможностей** — перечень операций и тестов, которые наш стенд проходит (операции «переводится» главы 2).

## Н1 Форма

### Н1.1 Стенд

- Стенд VMS ([общий README приёмки VMS](../../common/acceptance/README.md) «Стенд VMS») с манифестами `cam`, `rec`,
  `det`, `backend` (`auto` `backend` не нужен: «Автоматизация» не объявлена, ADR-0094 доп. (7)); консоль с нормами
  платформы B1 (передача с билетом), B2 (лента), B3–B6, B7 (статические файлы подсистемы); стенд с комплектами ролей
  (TLS): строка `backend/instances/main` с метками сервера стенда и воркер `backend` с листом роли `backend` (V/11.1
  Н1.2); файлы WebUI рядом с манифестом `backend` (V/11.1 Н1.4). Обратный вызов с листа чужой роли и с листа другого
  экземпляра — 401 (ADR-0094 доп. (6) п. 5; приёмка платформы B). Без комплекта — сокет роли на петле (доп. (6) п. 4).
  До приращения платформы стенда нет — глава проверяется чтением.
- Тесты зовут API по адресу консоли `/backend/…` (сервер контракта — V/11.1 Н1.5) сессией человека стенда (кука или
  `Authorization: Bearer`).

### Н1.2 Профиль возможностей

- Профиль — операции «переводится» главы 2 Н1.2. Тесты, которые зовут операции «`NO_ROUTE`», профиль исключает; тест,
  который проверяет сам `404 NO_ROUTE` неизвестной операции, — в профиле.
- Профиль — таблица урока [`data/profile.tsv`](../data/profile.tsv): строка на операцию контракта, `profile` — `in`, `out`
  (`404 NO_ROUTE`) или `stand` (`/test/*`); её читает драйвер стенда (ADR-0094 доп. (3) п. 10 (6)). Сверяется при новой
  версии контракта (глава 2). Продукт ответил (ADR-0094 доп. (4)): объявление возможностей — в `GET /reference`, набор —
  `one-domain`, часы — `--clock real`. `backend` отдаёт объявление по главе 2 Н1.5: его `operations` — строки `in`
  таблицы; тесты продукта пропускают необъявленное (строка `SKIP` с причиной) и отдельно проверяют, что каждая
  необъявленная операция отвечает `404 NO_ROUTE`. Объявление и таблица сверяются, расхождение — исправление таблицы, не
  молчаливая замена. «Автоматизация» не объявлена (ADR-0094 доп. (7)): `api-rules.js` — вне профиля.
- Тесты, которые опираются на эталонный набор продукта (домены, серверы, устройства его демо-данных), на нашем стенде идут
  против своего эталонного набора (Н1.3); где набор продукта у нас невыразим — тест вне профиля, причина — в списке.

### Н1.3 Служебные `/test/*`

- Только на стенде (ADR-0050: настройка процесса и петля): стенд задаёт ключ `TEST_SUPPORT` = `1` файла подсистемы, и
  исполняются только запросы с петли; иначе — `404 TEST_SUPPORT_OFF` (контракт; ADR-0094 доп. (2) п. 2). Файл подсистемы
  `/etc/backend/backend.env` читает воркер по [договору файла окружения](../../../Platform/common/contracts/env-file.md)
  (`W2C_SUB_ENV`, P/02.4 Н1.2; нет файла — умолчания; не читается или значение не по грамматике — отказ старта, код 2;
  сводка — V/09.2):

| Ключ | Читает | Грамматика | Умолчание | Норма |
|---|---|---|---|---|
| `TEST_SUPPORT` | воркер `backend` | `0` \| `1` | `0` | Н1.3 |

- `POST /test/reset` — стенд загружает свой эталонный набор заново (строки `cam`, `rec`, `det`, тома) дверями
  консоли по билету; поток шлёт `test.reset` (глава 5). `POST /test/clock` — сдвиг часов стенда, если стенд его даёт
  (часы платформы на стенде — норма стенда платформы), иначе — `404 TEST_SUPPORT_OFF`. `POST /test/events` — событие извне:
  строка события в журнал камеры стенда тем же путём, что событие держателя (V/01.2), видна `GET /journal`.
- Эталонный набор стенда — свой, данными урока **после стенда B** (ADR-0094 доп. (3) п. 10 (4)): набор продукта у нас
  невыразим целиком (домены, серверы, папки).

### Н1.4 `?selftest`

`?selftest` — самопроверка WebUI продукта изнутри страницы (сценарии интерфейса `tests/selftest.js` и `tests/ui-*.js`
продукта). Её открывают на стенде, когда WebUI отдаётся консолью (V/11.1 Н1.4): своя оболочка `backend.shell.html` и
файлы набора; до выноса приложения WebUI в файлы (запрос продукту, V/11.1 Н1.4) самопроверки на нашей странице нет.
Самопроверка в набор B7 не входит (V/11.1 Н1.4); по ответу продукта она пока идёт только на наборе `demo` (сценарии
написаны под весь контракт), не на `one-domain`.

## Н2 Двери

Своей двери у главы нет: `/test/*` — операции контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
стенд VMS с комплектами ролей + консоль с B1–B7 + backend по меткам (TEST_SUPPORT=1 файла подсистемы)
  тесты api-*.js профиля против /backend/… → исход по тестам продукта
  /test/* с петли → исполнить (Н1.3); не с петли или без ключа → 404 TEST_SUPPORT_OFF
```

## Н4 Отказы

| Причина | Код | `code` | Что делает вызывающий |
|---|---|---|---|
| `/test/*` вне стенда или не с петли | 404 | `TEST_SUPPORT_OFF` | — |
| `POST /test/clock` без часов стенда | 404 | `TEST_SUPPORT_OFF` | — |
| операция вне профиля | 404 | `NO_ROUTE` | — |

## Н5 Приёмка

Тесты API consolem в профиле возможностей и `?selftest` — на стенде Н1.1 после приращения платформы; до него — чтением.
Каталога приёмки нет (`V/11 no-acceptance`).
