# V/11.2 — Контракт и отличия: нормы

Канон главы 2 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A1, A5, A7). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `2110dbf` (пин VMS); нормы платформы B — после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1).

Дверь `backend` — API конфигуратора consolem как он есть: контракт ведёт продукт, мы его не правим (решение владельца 6).
Своё отличие — только две вещи: на операцию, которой у нас нет, — `404 NO_ROUTE`; что именно есть — объявление
возможностей в `GET /reference` (поле `capabilities` контракта, Н1.5). Глава нормирует закрепление контракта, судьбу
каждой из 89 операций, форму отказа, служебные `/test/*` и объявление.

Id норм — `V/11.2-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

### Н1.1 Закреплённый контракт

- Контракт — `api/openapi.json` репозитория продукта `github.com/ndm234234/consolem` на коммите
  `7683f54290562eacb634ff16b614257f3af3a889` от 2026-10-29 (OpenAPI 3.1.0, «Конфигуратор — API» 0.1.0): 89 операций —
  86 и три служебные `/test/*`.
- Копия — [`consolem.openapi.json`](../consolem.openapi.json), байты как в репозитории; SHA-256
  `c126b671a5e69ebd182cded4567e1d291f9fd04fd58a12a42a3a226c02dd1a6c` ([`consolem.openapi.json.sha256`](../consolem.openapi.json.sha256)).
  Реализация читает контракт из выгрузки, не из репозитория продукта.
- Новая правка контракта продуктом — новая сверка «Спецификацией VMS»: новый коммит, копия, SHA-256, таблица Н1.2
  (ADR-0094 A7). До сверки действует закреплённый коммит.
- Сервер контракта (`servers[0]`, `{baseUrl}`) у нас — адрес консоли с префиксом `/backend/api` (V/11.1 Н1.5; ADR-0094
  доп. (8) п. 2); схема
  безопасности контракта (`session`) — сессия консоли (кука или `Authorization: Bearer` человека для не браузеров).

### Н1.2 Каждая операция: переводится, `NO_ROUTE`, стенд

«Переводится» — `backend` отвечает по контракту, переводя запрос в двери консоли из перечня обратного вызова (V/11.1
Н1.5; главы 3–5). «`404 NO_ROUTE`» — такой вещи у нас нет, операция не объявлена (Н1.5): ответ — 404
`application/problem+json` с `code: NO_ROUTE` (Н1.3) раньше разбора адреса и тела, без обращений к консоли. «Только на
стенде» — Н1.4.

«Автоматизация» (тег `automation` контракта: правила с `triggers`, `conditions`, `steps`, пробный и ручной запуск, повтор
шагов, версии правил, `/schedules`, `/day-groups`, `/modes`, `/maintenance-windows`) на первом шаге не объявляется
(ADR-0094 доп. (7)): прежнее сопоставление `auto` ↔ `Rule` покрывает малую часть нового `Rule`, отображение — отдельным
решением о сценариях (вторая очередь C).

### Н1.3 Отказ — форма контракта

- Отказ — `application/problem+json`, схема `Problem` контракта: `code` (перечень `ProblemCode`), `message`, `field`,
  `params`, `current` (при 412). Своих кодов `backend` не вводит.
- Код по отказу консоли — глава 4 (таблица соответствия слов и кодов консоли кодам `ProblemCode`; коды и `field` консоли
  — норма платформы B5, после Go GREEN 01–10). До B5 код, который из слова консоли не выводится однозначно, — по
  умолчанию контракта (`VALIDATION_FAILED` без `field` у 4xx, иначе — код статуса).
- 401 — `UNAUTHORIZED`: WebUI идёт на вход консоли (V/11.1 Н1.3).

### Н1.4 Служебные `/test/*`

- `POST /test/reset`, `/test/clock`, `/test/events` (тег `test-support`) есть только на стенде: `backend` их исполняет,
  только если стенд это объявил переменной окружения процесса **и** запрос пришёл с петли (ADR-0050). Иначе — 404
  `TEST_SUPPORT_OFF` (код контракта «служебные операции тестового стенда выключены»; ADR-0094 доп. (2) п. 2 — A5 читается
  так: контракт не правим).
- Что они делают на нашем стенде (эталонный набор, часы, событие извне) — глава 6.

### Н1.5 Объявление возможностей

Что из контракта у нас есть (таблица Н1.2), WebUI и тесты продукта узнают объявлением возможностей: поле
`capabilities` ответа `GET /reference` (схема `Capabilities` контракта; ответ продукта на запрос владельца, ADR-0094
доп. (4)). Объявленное работает по контракту целиком; WebUI прячет необъявленное, тесты его пропускают.

- `operations` — `operationId` 24 операций «переводится» таблицы Н1.2 (с `getMe`, `getReference`, `stream`); служебные
  `/test/*` в список не входят. Список совпадает со строками `in` профиля урока (глава 6 Н1.2).
- `deviceTypes` — `["camera", "det"]` (глава 3). Создание устройства иного вида — 422 `NOT_SUPPORTED` с `field: type`, в
  `POST /devices` — строкой в `failed` (контракт).
- `features` — пусто: ролей и сети серверов, шифрования хранилищ у нас нет; запись такой настройки — 422 `NOT_SUPPORTED`.

## Н2 Двери

Дверь — контракт за передачей консоли (V/11.1 Н1.5); своих путей сверх контракта нет.

## Н3 Проход

```
запрос /backend/api/<путь>
  нет операции в контракте → 404 NO_ROUTE
  операция не объявлена (Н1.2 «NO_ROUTE», «Автоматизация» тоже) → 404 NO_ROUTE
  /test/* → стенд и петля? исполнить : 404 TEST_SUPPORT_OFF
  иначе → перевод (главы 3–5); отказ — Problem (Н1.3)
```

## Н4 Отказы

| Причина | Код | `code` | Что делает вызывающий |
|---|---|---|---|
| операции нет в контракте или она не объявлена | 404 | `NO_ROUTE` | — |
| вид устройства или настройка не объявлены | 422 | `NOT_SUPPORTED`, `field` | — |
| `/test/*` вне стенда | 404 | `TEST_SUPPORT_OFF` | — |
| сессии нет | 401 | `UNAUTHORIZED` | вход консоли |

## Н5 Приёмка

Тесты API consolem (`tests/api-*.js` на закреплённом коммите) против стенда в профиле возможностей; операции «`NO_ROUTE`»
профиль исключает (глава 6).
