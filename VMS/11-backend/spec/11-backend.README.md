# V/11 Бэкенд конфигуратора — инструкция для реализации

Что реализация подсистемы `backend` делает и как проверить результат. Канон — нормы глав `11.K-backend.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `2110dbf` (пин VMS); нормы платформы B (ADR-0094) —
после Go GREEN 01–10, отдельным перепином V/11.

## Входы и их приоритет

- Канон — нормы глав `11.K-backend.norms.md` (Н1–Н5 каждой главы; адреса `V/11.K Н…`).
- Канон манифеста — [`backend.subsystem.yaml`](../backend.subsystem.yaml): байты как есть; блоки второго вида передачи (B1),
  статических файлов (B7) — комментарии до норм платформы.
- Канон оболочки — [`backend.shell.html`](../backend.shell.html): байты как есть; реализация её не генерирует.
- Контракт двери — [`consolem.openapi.json`](../consolem.openapi.json) (закреплённый коммит, SHA-256 рядом), не правится.
- Сопоставление видов — данные [`data/mapping.tsv`](../data/mapping.tsv).
- Приёмка — тесты API consolem на закреплённом коммите в профиле возможностей (глава 6); каталога приёмки нет.
- [Лекция](../11-backend.md) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…`.

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/11.1 | манифест грузится строгим загрузчиком без правок; держатель строки `backend/instances/<name>` по меткам рядом с `live`, обратный вызов — TLS ролью `backend`; ответы передачи — только JSON или SSE; WebUI реализация не отдаёт (консоль — оболочкой `backend.shell.html` и статическими файлами подсистемы, B7); API — `/backend/api/` | чтением; тесты API |
| V/11.2 | 24 операции контракта переводятся, 62 — `404 NO_ROUTE` без обращений к консоли (из них 30 — «Автоматизация», не объявляется), `/test/*` — только стенд и петля, иначе `404 TEST_SUPPORT_OFF`; `GET /reference` несёт `capabilities` — список «переводится», `camera`, `det`; отказ — `Problem` контракта | тесты API в профиле |
| V/11.3 | перевод по таблице `mapping.tsv`: читается из данных, не зашит в код | тесты API; чтением |
| V/11.4 | сборка и разборка записей по частям, версия — склейка индексов хранилища частей и надгробий (B4), запись устройства одним пакетом B9, память повторов групповых записей, отказ консоли → код контракта, id — UUID v5 места строки | тесты API (после B3–B5) |
| V/11.5 | обратный вызов только с билетом своего запроса и только по перечню; `/stream` из `/changes` по таблице сообщений | тесты API; приёмка платформы B1, B2 |
| V/11.6 | профиль тестов продукта, ключ `TEST_SUPPORT` файла подсистемы и петля для `/test/*` | стенд после приращения платформы |

Пакет подсистемы несёт исполняемый `/usr/lib/backend/worker` и кладёт рядом с манифестом пять файлов набора WebUI
consolem с закреплённого коммита со сверкой SHA-256 каждого файла (V/09.3; их отдаёт консоль статическими файлами
подсистемы, B7); оболочка `backend.shell.html` — канон урока (со сборкой продукта под CSP — их `index.html` по SHA-256).

## Порядок

Сначала платформа с нормами B (после Go GREEN 01–10), затем `backend`: передача второго вида (билет) — условие включения
`backend`, нынешний `door.pass` с `Authorization` человека для него не допускается (V/11.1 Н1.3).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/11.1 Н1.3 | хранить или ждать `Authorization` человека | только билет запроса; своего входа нет |
| V/11.1 Н1.4 | отдавать WebUI из `backend`, особым путём или страницей `index_api_server.html` продукта; ужесточать CSP оболочки | оболочка `backend.shell.html` с CSP ровно минимум P/06.5 и статические файлы подсистемы по списку манифеста (B7) |
| V/11.1 Н1.5 | звать двери вне перечня (`/where`, гранты, `/operations`) | только перечень обратного вызова манифеста |
| V/11.2 Н1.1 | править контракт под себя | отличие — только `NO_ROUTE` и объявление возможностей |
| V/11.2 Н1.4 | держать `/test/*` открытыми вне стенда или отвечать `NO_ROUTE` | ключ `TEST_SUPPORT` стенда и петля, иначе `404 TEST_SUPPORT_OFF` |
| V/11.2 Н1.2 | переводить правила на сценарии `auto` по прежнему сопоставлению | «Автоматизация» не объявлена (ADR-0094 доп. (7)): `404 NO_ROUTE`, поля устройства от правил не отдаются |
| V/11.3 Н1.1 | зашить сопоставление в код | читать `data/mapping.tsv` |
| V/11.4 Н1.1 | считать версию камеры суммой ревизий частей или числом | непрозрачная строка: склейка индексов частей `c…r…d…`, равенство строки (ADR-0094 доп. (4) п. 1) |
| V/11.4 Н1.2 | писать части устройства по одной или откатывать их вручную | один пакет B9: записываемые с `cas`, прочие стражами; отказ — ничего не записано |
| V/11.5 Н1.3 | подделывать поток опросом до ленты | без `/changes` потока нет |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; тесты API consolem в профиле возможностей проходят на платформе с
нормами B; операции «`NO_ROUTE`» отвечают 404 без обращений к консоли; пункты чеклистов, отмеченные «чтением», подтверждены
описанием реализации (раздел «Решает реализация» каждой главы).

## При расхождении

Порядок источников: нормы главы → контракт consolem и таблица сопоставления → тесты продукта → лекция; платформа — нормы
выгрузки пина VMS. Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и
предложением; контракт — вопрос продукту через владельца; норма платформы — через «Архитектора».
