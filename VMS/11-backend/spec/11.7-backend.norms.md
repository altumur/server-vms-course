# V/11.7 — Ассистент конфигурирования в `backend`: нормы

Канон главы 7 урока V/11 «Бэкенд конфигуратора» (ADR-0093 доп. (6); ADR-0094 доп. (10)). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json); ассистент — урок
[V/10](../../10-assist/README.md). Платформа — выгрузка `cammeta-specs` `d3f8e05` (пин VMS); нормы платформы B1 (поток
по билету) и B9 — после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1).

Ассистент конфигурирования (ADR-0093) — администратор пишет просьбу словами, модель внутри кластера предлагает план,
код проверяет план, записывает только человек. У нашей страницы ход идёт в браузере (V/10.3). Для WebUI consolem ход
идёт в `backend` (решение владельца, ADR-0093 доп. (6)): у `backend` нет своих прав, обращения в консоль — правами
человека по билету, пока открыт его запрос (ADR-0094 B1). Одна норма, две реализации: инструменты, проверка плана и
векторы — канон V/10.4, V/10.5; панель страницы и `backend` исполняют их каждый у себя. Глава нормирует операцию хода,
цикл хода в `backend`, перевод плана в слова consolem и предел хода.

Id норм — `V/11.7-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Ход** — от просьбы админа до одного исхода: вопрос, план, отказ или ошибка (V/10.3 Н1.5 — смысл тот же).
- **Переписка** — тексты хода и сообщения шагов модели, которые держит клиент и возвращает с каждым запросом:
  своего состояния у `backend` нет (ADR-0094 A3).
- **План consolem** — проверенный план (V/10.5 Н1.1), переведённый в `items` формы `DevicesUpdateRequest` контракта.

## Н1 Форма

**Время.** Сроки главы — секунды монотонных часов процесса.

### Н1.1 Операция хода — по контракту после третьего запроса

- Операция хода — потоковая операция контракта consolem: рабочее имя `POST /assist/turns`, тело `{text, context?}`
  (`text` — что написал человек; `context` — непрозрачная строка из прошлого ответа разговора, клиент возвращает её
  как есть), ответ — поток SSE `text/event-stream` (ADR-0094 доп. (10) п. 2; третий запрос consolem — готовит «Консоль»,
  отправляет владелец). Точные имя, поля и события — по контракту после ответа продукта: тогда перепин V/11 (глава 2
  Н1.1), строка профиля и строка таблицы операций главы 2.
- **До перепина** операции в закреплённом контракте нет: путь — 404 `NO_ROUTE` (глава 2 Н1.2, «операции нет в
  контракте»), возможность `assist` в объявлении возможностей не объявляется (доп. (10) п. 3). Нормы главы ниже — то,
  что `backend` исполнит, когда операция войдёт в контракт.
- Маршрут передачи — `api/assist/turns`, **потоковый** (V/11.1 Н1.5; норма платформы B1): без предела 5 с и буфера
  4 МиБ; билет потока годится только на чтения — инструментам и проверке плана этого хватает (V/10.4, V/10.5 только
  читают). Предел ожидания маршрута — `ASSIST_TURN_MAX` (Н1.5).
- Закрытый поток — отмена хода: `backend` снимает шаг модели (`DELETE` шага, отбой V/10.2 Н1.5) и больше ничего не шлёт.
  Оборванный поток не продолжается: клиент повторяет запрос с тем же `context`.

### Н1.2 Цикл хода в `backend`

Цикл — канон V/10.3 Н1.2–Н1.5 (сообщения шага, окно, шаг, разбор ответа модели, исходы) с отличиями этой нормы:

- **Модель** — дверь модели V/10.2: `backend` берёт её по билету `GET /assist/where/<имя>` (обратный вызов из перечня,
  V/11.1 Н1.5; право `view` на строку модели — человека билета; ADR-0094 доп. (10) п. 1) и зовёт дверь сам: поставить
  шаг, долгий опрос, отбой (V/10.2 Н1.2, Н1.3, Н1.5). Модель хода — строка модели, которую называет `context`, без него
  — первая видимая человеку строка `assist/models` по имени с фазой `running`, как умолчание панели (V/10.3 Н1.1).
  Ключей и адреса модели клиент не видит.
- **Переписка** — в `context`: base64url без `=` UTF-8 JSON `{v: 1, model, turn, texts, messages}` — модель хода, `turn`
  хода (V/10.3 Н1.2), тексты хода и сообщения шагов, которые идут в историю (V/10.3 Н1.2). Каждый запрос — новый `text`
  добавляется к `texts`; `context` не читается или `v` не `1` — ход заново без истории (новый `turn`). Секретов в
  `context` нет: метки секретов живут только внутри одного хода (V/10.6 Н1.3), и новый ход их не наследует.
- **Вопрос** `ask_admin` кончает ход (в браузере ход ждёт ответа, здесь — нет): поток кончается событием `question`, ответ
  человека — новый запрос с `context` вопроса (ADR-0093 доп. (6) п. 2).
- **Инструменты** — закрытый набор V/10.4: те же имена, аргументы, результаты, ошибки и слова; чтения — двери консоли из
  перечня V/10.4 Н1.2 по билету потока, не модулем страницы. Двери, которых нет в перечне обратного вызова `backend`
  (V/11.1 Н1.5), — ошибка инструмента V/10.4 Н1.3 «нет доступа», как отказ консоли.
- **Проверка плана** — V/10.5 целиком (форма и права, сверка слов, отбор, вопрос и отказ), над свежим чтением консоли
  по билету; затем — перевод в план consolem (Н1.3). Модель план не проверяет: проверяет код.
- **Счёт вызовов** — `TURN_CALLS` = 25 на ход (V/10.3 Н1.2), `STEP_TRIES`, `RESTARTS`, `ENQUEUE_WAIT` — как у панели
  (V/10.3 Н1.3); исход за пределом — тот же: «ход не завершён».

### Н1.3 Перевод плана в слова consolem

- **Охват** (ADR-0093 доп. (6) п. 4). Проверка плана в `backend` пропускает только правки, у которых есть место в
  `DevicePatch` (V/11.3, таблица `mapping.tsv`): правка иного поля или иной единицы — отказ проверки с именем поля
  (`field`) и словами «сделайте это на странице консоли». Частичного плана нет: одна такая правка — отказ всего плана.
- **Правки с местом** — по единицам устройства (V/11.3 Н1.2):

| Правка плана (`unit`, `field`) | Поле `DevicePatch` устройства |
|---|---|
| `cam/<id>` (камера, пустой `main`): `name`, `enabled`, `cred_username` | камера: `name`, `enabled`, `login` |
| `cam/<id>`: `source`, меняются только хост и порт | камера: `ip`, `port` |
| `rec/<cam>`: `enabled` | камера: `recordMode` — `always` при `true`; при `false` — `replica`, если у камеры есть включённая резервная, иначе `none` (V/11.3 Н1.3) |
| `rec/<cam>`: `home`, `stream` | камера: `archiveId`, `stream` |
| `rec/<cam>-<том>`: `enabled` | камера: `extraArchives`, элемент тома — `recordMode` `always` \| `none` |
| `det/<cam>-<kind>`: `enabled` | детектор: `enabled` |
| `det/<cam>-<kind>`: `params`, меняется только ключ `sensitivity` | детектор: `sensitivity` (кодек V/11.3 Н1.3) |

  Иное — отказ проверки (выше): секреты (`cred_secret`, `access_secret`), тома, записи с иными именами, потоки,
  поля без строки в таблице, `source` с иным путём, `params` с иными ключами.
- **План consolem** — `items` формы `DevicesUpdateRequest.items` (`deviceId`, `version`, `set`) и к каждому устройству
  пояснение: имя и правки `{field, from, to, why}` в полях consolem. Правки строки камеры и её записей сходятся в
  элемент камеры, правки детектора — в свой элемент (детектор — своё устройство); `version` —
  версия устройства (V/11.4 Н1.1) по тому же чтению, по которому прошла проверка плана; `deviceId` — V/11.4 Н1.6.
  Порядок элементов — по `deviceId` байтами. Итог: `{summary, context, items}`.
- **«Применить»** — не операция хода: клиент шлёт `POST /devices/update` с `items` как есть и новым `idempotencyKey`
  (глава 4 Н1.5); устройство изменилось после плана — его элемент `failed` с 412, в нём ничего не записано (пакет,
  ADR-0094 доп. (9)).

### Н1.4 События потока

| Событие SSE (рабочие имена третьего запроса) | Когда | Тело |
|---|---|---|
| `progress` | шаг цикла начат: где модель, шаг модели, инструмент, проверка плана — сколько угодно раз | `{text}` — строка хода работы (V/10.3 Н1.1 «строка состояния»: «модель загружается», «модель занята», «читаю `<sub>`», «проверяю план») |
| `question` | принят `ask_admin` | `{text, context}` |
| `plan` | план прошёл проверку и перевод | `{summary, context, items}` (Н1.3) |
| `refused` | принят `refuse`; проверка плана отказала; правка вне охвата; «ход не завершён» (V/10.3 Н1.5) | `{text, context, field?}` — слова причины |
| `error` | отказ двери консоли или модели, который ходом не исправить | `{code, message}` — `code` из `ProblemCode` (глава 2 Н1.3) |

- Поток кончается ровно одним из `question`, `plan`, `refused`, `error`; затем `backend` закрывает поток.
- `id:` событий хода нет: ход не возобновляется по `Last-Event-ID` (оборванный — повтор запроса, Н1.1).

### Н1.5 Предел хода

- `ASSIST_TURN_MAX` = 7500 с — потолок хода V/10: `TURN_CALLS` (25) × предел вызова модели (`QUEUE_MAX` 120 с +
  `STEP_MAX` 180 с, V/10.2 Н1.3) (ADR-0094 доп. (10) п. 2). Это предел ожидания маршрута `api/assist/turns` у консоли
  (число — здесь, потолок — норма платформы B1) и предел хода у `backend`: ход, не кончившийся за него от начала
  запроса, кончается `refused` «ход не завершён: дольше предела хода»; повторы `STEP_TRIES`, `RESTARTS` и ожидание
  `ENQUEUE_WAIT` идут внутри него.

## Н2 Двери

Своей двери у главы нет: операция хода — контракт за передачей консоли (V/11.1 Н1.5), двери чтения — обратные вызовы
из перечня, дверь модели — V/10.2.

## Н3 Проход

```
POST /assist/turns (поток, билет потока) — после перепина на контракт с операцией; до него — 404 NO_ROUTE
  context → переписка (не читается — новый ход); text → тексты хода
  GET /assist/where/<имя> по билету → дверь модели
  цикл V/10.3: шаг модели → разбор → инструменты V/10.4 по билету → progress …
    ask_admin → question; refuse → refused
    propose_plan → проверка V/10.5 → охват DevicePatch → перевод → plan | refused (field)
  TURN_CALLS, ASSIST_TURN_MAX → refused «ход не завершён»
  поток закрыт клиентом → DELETE шага, конец
```

## Н4 Отказы

| Причина | Исход | Кто видит | Что делает вызывающий |
|---|---|---|---|
| операции нет в закреплённом контракте | 404 `NO_ROUTE` | WebUI (возможность `assist` не объявлена) | — |
| строки модели, видимой человеку, нет; дверь модели не отвечает | `refused` «модель недоступна» (V/10.3 Н1.3) | WebUI | оператор — строка модели (V/10.1) |
| правка вне охвата `DevicePatch` | `refused` с `field`: «сделайте это на странице консоли» | WebUI | страница консоли |
| проверка плана отказала | `refused` со словами проверки (V/10.5 Н1.6) | WebUI | переписать просьбу |
| `TURN_CALLS`, `ASSIST_TURN_MAX` | `refused` «ход не завершён» | WebUI | позже или короче |
| обратный вызов 401 (билет мёртв) | поток закрыт | WebUI | повтор запроса |

## Н5 Приёмка

Векторы V/10 — общие для панели и `backend` (ADR-0093 доп. (6) п. 3):
[`plan-check`](../../10-assist/vectors/plan-check/README.md) (инструменты и проверка плана) и
[`turn`](../../10-assist/vectors/turn/README.md) (цикл хода; вопрос здесь кончает ход) исполняет драйвер `backend` над
его реализацией с той же заглушкой консоли; заглушка модели — V/10.2 Н5. Перевод плана (Н1.3) и события (Н1.4) — тесты
продукта после третьего запроса (ассистент-заглушка с записанными потоками); до перепина — чтением.
