# V/11.5 — Обратный вызов и поток: нормы

Канон главы 5 урока V/11 «Бэкенд конфигуратора» (ADR-0094 B1, B2). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `5c8f9d6e` (пин VMS; приращение прав поверх норм B, ADR-0090 доп. (17); пометка «норма платформы B» — где глава на них опирается).

Воркер `backend` не держит ни удостоверения человека, ни своих прав: всё, что он читает и пишет, он зовёт у консоли с
билетом запроса, который сейчас переводит. Поток `/stream` контракта — те же билеты, но долгоживущий запрос: консоль
передаёт его потоком, а `backend` переводит её ленту изменений в сообщения контракта. Глава нормирует сторону `backend`:
когда и как он зовёт консоль и что шлёт в поток.

Id норм — `V/11.5-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Билет** — 128 случайных бит, которые консоль выдала на один открытый запрос человека и передала воркеру (B1).
- **Лента** — `GET /changes` консоли: сообщения «строка X — ревизия R / удалена», без значения (B2).

## Н1 Форма

**Время.** Сроки главы — секунды монотонных часов процесса.

### Н1.1 Обратный вызов по билету

- Воркер зовёт консоль только **с билетом того запроса**, который сейчас переводит, и только на двери перечня
  (V/11.1 Н1.5); билет не хранится после ответа на запрос, не передаётся другим запросам и не пишется в журнал.
- Консоль принимает билет, пока внешний запрос открыт, на слушателе обратного вызова (`CONSOLE_CALL_PORT`, адрес —
  заголовок `X-W2C-Pass-Console`) с листом роли `backend` сервера того экземпляра, которому передала запрос (без
  комплекта — сокетом роли; V/11.1 Н1.2, ADR-0094 доп. (6) пп. 1, 2), на двери перечня, при той же проверке, что токен двери (отзыв `jti`, срок `exp`, ключ `kid` записи билета у консоли),
  иначе — 401, и при свежем `may` человека, отказ — 403 (B1, ADR-0094 доп. (3) п. 1; норма платформы B). Воркер получает только 128 бит билета,
  полей записи не видит. Для `backend` 401 обратного вызова — конец перевода: ответ запросу — 401 `UNAUTHORIZED` (глава
  4 Н4), повтора с тем же билетом нет.
- Ответ человеку закрыт (браузер ушёл) — билет мёртв: воркер прекращает перевод, ничего не дописывает.
- Предел ожидания передачи — по маршруту (V/11.1 Н1.5): групповая запись (`api/devices`, `api/objects/delete`)
  успевает пакеты по порядку; не успела — консоль закрывает запрос, воркер видит мёртвый билет (как выше), а сделанные
  шаги уже записаны в память группы (глава 4 Н1.4): повтор её продолжит.

### Н1.2 Поток `/stream` из ленты `/changes`

- `GET /stream` (адрес консоли `/backend/api/stream`) передаётся потоком (маршрут `api/stream`, V/11.1 Н1.5; B1):
  билет потока годится только на чтения и `/changes`. Лента — длинный опрос, не SSE (P/06.1 Н2 «Лента изменений», B2):
  `GET /changes?after=<номер>&wait=<с>` → `{position, changes, reset?}`, `wait` не больше `CHANGES_WAIT`. На поток
  браузера `backend` держит один такой опрос за другим: следующий — с `after` = `position` прошлого ответа. Браузеру он
  шлёт `text/event-stream`: на сообщение — строки `id:` и `data:` (`StreamMessage`), без `event:` (контракт).
- Перевод сообщений ленты:

| Лента консоли (B2) | `StreamMessage` контракта |
|---|---|
| строка вида (глава 3) создана — `revision: 1` (созданная поверх надгробия — как изменённая, ниже) | `entity.created` (`kind`, `entityId`, `version`) |
| строка изменена — `revision: R`; `0` — ревизия не читается | `entity.changed` (`kind`, `entityId`, `version`) |
| строка удалена — `deleted` вместо `revision` (индекс надгробия, B4, ADR-0094 доп. (3) п. 9; `""` — надгробия нет) | `entity.deleted` (`kind`, `entityId`) |
| ответ с `reset: true` | `stream.reset` |
| строка части камеры (поток `cam`, запись `rec`, детектор `det` про камеру) | ещё `entity.changed` камеры (`kind: device`, её `entityId`, новая версия — глава 4 Н1.1) |
| строка `cam/devices/<хост>` | `entity.changed` `ipsrv` хоста и его каналов; появление или уход `ipsrv`, канала, `storage` — `entity.created`, `entity.deleted`; `entity.changed` камер хоста: `parentId`, `videoChannel` и версия (глава 3 Н1.3) |
| строка основная `type: ipsrv` | `entity.created`, `entity.changed`, `entity.deleted` `ipsrv` хоста (`entityId` — от хоста); `ipsrv` остаётся по `channels` — `entity.changed`; создание и снятие строки — ещё `entity.changed` камер хоста: `parentId` и версия (глава 4 Н1.1) |
| строка `cam/children/<id>`, `cam/child_settings/<id>` | `entity.created`, `entity.changed` ребёнка; `gone: true` — `entity.deleted`; настройка `gone`-строки не шлётся |
| строка `cam/device_units/<id>` | `entity.created`, `entity.changed`, `entity.deleted` единицы или встроенного детектора (`kind: device`) |
| строка тома `rec/volumes` | два вида одной строки: сообщение хранилища (`kind: archive`) и тома (`kind: volume`); запись `rec` на томе — ещё `entity.changed` хранилища (`retentionDays`); том `edge` свёрнутого члена — только сообщение `storage` камеры w2c (`kind: device`, глава 3 Н1.3) |
| строка папки `platform/folders/<id>` | папки нет в дереве потока (ниже) — `entity.created`, есть или дерева нет — `entity.changed` (`kind: folder`); `deleted` — `entity.deleted` папки и её потомков (ниже) |
| строка `backend/opdone/<id>/<i>` | `operation.progress` (`kind: operation`, `entityId`, `payload` — `{item: <OperationItem>, done, total}`, счётчики строки `backend/opcount/<id>`; ключи ждут сверки с consolem) |
| запись `backend/operations/<id>` с `state: done` | `operation.finished` (`kind: operation`, `entityId`, `payload` — `state`, `ok`, `failed`, `cancelled`) |
| строка `backend/undo/<id>` с `single: true`, `revision: 1`, `user` — человек потока; у групповой записи — строка `backend/repeats/<h>` с `state: done` и строка `undo` с её id (глава 4 Н1.12) | `operation.finished` на каждую одиночную правку (`entityId` — id в форме UUID, `payload` — `state: done`, `ok` — число шагов, `failed` 0, `cancelled` 0): иначе журнал «Операции» не перечитывается; чужая строка не шлётся |
| строка `cam/found/<h>` нынешнего поиска, пока он идёт, которая отдаётся в `candidates` (глава 4 Н1.9) | `discovery.progress` (`kind: discovery`, `entityId` — домен, `payload` — `{progress, candidate}`) |
| строка `cam/searches/<CLUSTER>` кластера входа со `stopped_at` | `discovery.finished` (`kind: discovery`, `entityId` — домен, `payload` — `{state: stopped, progress}`) |
| строка `detjob/jobs/<name>` | `entity.created`, `entity.deleted` (`kind: archiveScan`, `entityId`, `version`); итог — «Журнал и пульс» ниже |
| строка `detedge/watches/<name>` | `entity.created`, `entity.changed`, `entity.deleted` (`kind: archiveWatch`, `entityId`, `version`); рубеж не шлётся |
| строка `auto/scenarios/<id>` без `hidden`, выразимая в `Rule` | `entity.created`, `entity.changed`, `entity.deleted` (`kind: rule`, `entityId`, `version`) |
| строка `auto/rule_marks/<id>` | `entity.changed` правила (`kind: rule`, новая версия) |
| строка записи камеры (`hidden: record`), `cam/rule_state/<id>` | только `entity.changed` камеры (`kind: device`, новая версия — глава 4 Н1.1) |
| строка `auto/schedules/<id>`, `auto/day_groups/<id>`, `auto/windows/<id>` | `entity.*` (`kind: schedule`, `dayGroup`, `maintenanceWindow`, `entityId` — ключ, `version`) |
| строка `auto/modes/all` | `entity.changed` (`kind: modes`, `version`, без `entityId`) |
| строка `auto/mode_current/now` | `entity.changed` (`kind: objectMode`, `entityId` — режим, Н1.2 «Журнал и пульс») |
| строка `cam/searches/<CLUSTER>` без `stopped_at` | не шлётся; поток запоминает её `until`: срок вышел, а строка та же — `discovery.finished`, `payload` — `{state: done, progress: 100}` |
| строка, у которой вида нет (глава 3: `none`), `cam/unit_next`, `cam/ptz_moves`, `cam/preset_labels` (версия камеры не меняется: другая сессия увидит подпись при следующем чтении, предел), `auto/versions`, `auto/answers`, прочие строки `backend/repeats`, `undo`, строки `people`, `history`, `memberof`, иные строки операции | не шлётся |

Строка потока — часть камеры: `entity.changed` камеры, её `streams` и `version`. `kind: streamAccounts` не шлётся: учётки не объявлены (глава 4 Н1.18).

- **Производные сообщения** (разбор ревью V/11, Codex № 18, Claude С-15, вопрос 11). Одно сообщение ленты может дать
  несколько `StreamMessage` — по строкам таблицы выше, в порядке: сообщение своего вида строки, затем камеры, затем
  хранилища (у тома — `archive`, затем `volume`). У каждого свой `type`. Удалённый детектор: `entity.deleted`
  детектора (его id — из ключа надгробия), затем `entity.changed` камеры — её версия с индексом надгробия
  (`?deleted=1&about=`, глава 4 Н1.1); камеры уже нет — сообщения камеры нет.

- `version` сообщения — версия записи вида по главе 4 Н1.1 (индекс хранилища; B4): лента несёт «строка X — ревизия R»
  без индекса, поэтому `backend` дочитывает строку дверью перечня, прежде чем послать сообщение. Дочитывание ответило
  404 (строку уже сняли) или 403 — сообщение не шлётся: удаление придёт своим сообщением ленты; иной отказ дочитывания и
  три несовпадения двойного чтения — поток закрыт, как отказ ленты (Н4); `revision` прочитанной строки
  выше `R` — шлётся версия прочитанной (разбор ревью V/11, дополнение Kimi, № 6).
- **Поля тела** `StreamMessage` (контракт: обязательны `id`, `type`, `at`; дополнение Kimi, № 5, вопрос 2): `id` тела
  равен строке SSE `id:`; `at` — время события на сервере, не отправки, RFC 3339 UTC: у сообщения ленты — поле `at` ленты,
  число JSON, секунды такта консоли, увидевшего версию строки; позже приёма хранилищем оно не больше чем на такт, и
  досылка отдаёт то же значение (норма платформы B2); у событий хода
  ассистента (глава 7) — момент, когда `backend` их произвёл. Смысл `at` продукту названо в третьем запросе — подтвердить.
- **`id` сообщения** — `<p>-<k>`: `p` — номер, после которого лента отдаёт это сообщение (`n` предыдущего сообщения
  ответа, у первого — `after` запроса), `k` — номер производного сообщения в нём с 0 (вопрос 11). Берётся `p`, а не `n`:
  лента отдаёт только сообщения **после** номера, и обрыв между производными иначе потерял бы остаток. `-` в номере ленты
  нет (P/06.1 Н2). Для клиента `id` непрозрачен (контракт).
- **Начало подписки** (ADR-0094 доп. (3) п. 6): первый запрос без `after` сразу отвечает `{position, changes: []}`;
  `backend` шлёт браузеру строку SSE `id: <position>` без `data:` — по SSE она ставит последний `id` браузера и события не
  даёт, поэтому `StreamMessage` у неё нет и `type` не нужен. Клиент применяет сообщения с отбросом ревизии не выше
  прочитанной.
- **`Last-Event-ID`** браузера (заголовок проходит передачу второго вида, V/11.1 Н1.5): `<p>` — `after=<p>`; `<p>-<k>` —
  `after=<p>` и пропустить первые `k + 1` производных первого сообщения; иная форма — как начало подписки, с
  `stream.reset`.
- **`reset`** — ответ `{position, changes: [], reset: true}` (чужой или вытесненный номер, перезапуск экземпляра консоли,
  смена прав или меток человека, B2): `stream.reset` с `id` `<position>`, браузер перечитывает всё, опрос идёт с
  `after=<position>`.
- **Удаление папки** (ADR-0096 §3): лента несёт только саму папку, а подпапки недостижимы с того же индекса. Дочитывание строки папки — `GET /folders`
  целиком: это же чтение обновляет дерево потока. `backend` помнит дерево последнего чтения этого потока и после `entity.deleted` папки шлёт `entity.deleted` каждому потомку, который был достижим до удаления, в
  порядке `id`; это производные сообщения того же сообщения ленты. Дерева в памяти нет (начало потока) — только сама папка; браузер всё
  равно получит 404 на чтении потомка.
- **Строки операции.** Ленту по билету консоль отдаёт только операции автора (P/06.9 Н2), поэтому чужих сообщений поток не несёт. Значения —
  дочитыванием двери `GET /backend/operations/<id>`; порядок шагов сверх ленты не обещан, истина — `GET /operations/{id}`.
- **Права.** Строк домена лента не несёт: сообщений `kind: access` нет, WebUI перечитывает снимок сам. Сброс ленты при смене ролей — как
  прочий `reset`.
- **Конец поиска** по сроку ленте не виден: строки нет, поэтому `discovery.finished` шлёт таймер потока, поток запоминает `until` и при открытии, `id` — `<position>-<k>` последнего ответа ленты, `k` следующий.
  Обрыв потока такое сообщение не досылает: итог читается `GET` (глава 4 Н1.9).
- **Журнал и пульс** (ADR-0105): запуск правила — строка журнала, смена режима — слово пульса, а лента их не несёт (P/06.1 Н2 «Лента изменений» «Охват»). Поэтому после каждого ответа ленты поток читает `GET /events?subsystem=auto&from=<t>` с `t` последней строки и `GET /servers`: новая сработка `fired` — `entity.created` (`kind: ruleFire`, `entityId`, `payload: {ruleId}`), её вторая строка после `waiting` — `entity.changed` того же `kind`; иной `modeId` главы 4 Н1.11 — `entity.changed` (`kind: objectMode`, `entityId` — режим). Итог скана — состояние единицы, лента его тоже не несёт (V/05.1): пока у потока есть строка `scan-…` без итога, не чаще `VIEW_POLL` на поток он читает `GET /detjob/jobs`; заказы `rec-…`, `auto-…` форму не касаются; итог появился — `entity.changed` (`kind: archiveScan`, `entityId`, `version`). При открытии потока оба значения запоминаются, сообщений нет. `id` — как у конца поиска. Вопросы — та же очередь: не чаще `VIEW_POLL` на поток он читает `GET /auto/scenarios` своего кластера, цена постоянна, сравнивает вопросы главы 3 Н1.3 с запомненными: новый — `prompt.opened` (`kind: rulePrompt`, `entityId`, `payload: {ruleId, fireId, step, roleId, level}`), пропавший — `prompt.closed` с `payload: {ruleId, fireId, step, reason}`, `reason` по строке конца шага в журнале сработки (V/07.4 Н1.6): `note` `ask.answer`, `label` `esc.ack` — `answered`, ещё `answer` — `yes`, `no`, у `esc.ack` `ack`, и `by` — `user` строки; `note` `ask.noAnswer`, `answer.unread`, `label` `esc.none` — `expired`; `label` `esc.reset` — `reset`. Строка конца ложится после записи шага, поэтому сообщение ждёт её один `VIEW_POLL`; нет и тогда — `stopped`: снятый запуск таких строк не пишет. **Предел:** строка, легшая позже этого ожидания, и падение между записью и строкой (V/07.4 Н1.11) тоже читаются `stopped`: `VIEW_POLL` покрывает только обычную задержку строки. **Предел:** задержка — ответ ленты, до `CHANGES_WAIT`; обрыв не досылает: истина — `GET /rules/{id}/fires`, `GET /modes/current`, `GET /archive-scans`.
- **Чужое** (ADR-0110 доп. (2); глава 3 Н1.2а). Лента кластерная, чужих строк не несёт. Поэтому после ответа ленты, не чаще раза в `VIEW_POLL` = 5 с на поток, значение без опоры, поток читает одну страницу `GET domain` и таблицы только её членов `class: server`, камеры-кластеры сравниваются по `units` страницы, как перечень, с `If-None-Match` (глава 3 Н1.2а «Цена») и билетом потока, следующую страницу — на следующем `VIEW_POLL`, по кругу (ADR-0113 доп. (7)), и сравнивает записи `device`, `archive`, `volume`, `rule`, `schedule`, `dayGroup`, `maintenanceWindow` с тем, что запомнил о членах этой страницы; раздел из `unread` не сравнивается; новый id — `entity.created`, иная версия — `entity.changed`, id пропал — `entity.deleted`, только по члену пройденной страницы: круг доказательством полноты не служит; `version` — версия чужой записи (глава 3 Н1.3). Видит то, что видит человек билета. Первый проход страницы запоминает её значения, сообщений нет; страница одна — весь домен за `VIEW_POLL`, как было. `id` — как у конца поиска. Таблица члена не прочитана — записи этого вида у него не сравниваются: пропажа не доказана, `entity.deleted` нет. `Server` не сравнивается, как свой. **Предел:** цена потока постоянна, стареет свежесть: задержка — вид домена, ответ ленты и обход, число страниц × `VIEW_POLL`, при 250 000 членов ≈ 21 мин; память потока растёт с числом записей домена; записи ушедшего члена `entity.deleted` не дают, его нет на странице; обрыв не досылает: истина — `GET`.
- **Потеря связи с доменом** (Д-11). Чтение `GET domain` дало не 200 и не 403 — сравнение стоит, память держится, сообщений нет: записи живы, `entity.deleted` был бы ложью. Связь вернулась — сравнение с той же памятью. Сигнала потери связи в контракте нет, он ждёт контракта. **Предел:** до него браузер держит чужое, пока сам не перечитает, а `GET` его уже не отдаёт (глава 3 Н1.2а).
- `test.reset` не шлётся:
  `/test/reset` загружает набор обычными записями, и поток несёт их сообщения; узнать о сбросе другой экземпляр
  `backend` мог бы только мимо ленты (разбор ревью V/11, Claude С-19; глава 6 Н1.3).
- Билет потока живёт, пока открыт поток браузера; поток закрыт — `backend` прекращает опрос. Консоль закрывает открытый
  поток по билету при отзыве `jti`, выключении человека, на `exp` и когда свежий `may` по двери маршрута отказал (`unavailable` поток не закрывает; договор сторожевой и передачи `close`; доп. (3) п. 1); потоки идут отдельным пределом
  консоли, обратные вызовы — своей полосой (доп. (3) п. 7).

### Н1.3 Только лента

Источник сообщений о своих строках — только лента `/changes`: опросом строк `backend` поток не подделывает, кроме итога скана (выше). Ответ ленты, кроме `reset`, не
несёт значений: их дочитывает Н1.2. `ruleFire`, `objectMode` строки не имеют, их чтение — Н1.2 «Журнал и пульс». Чужих строк лента не несёт: Н1.2 «Чужое».

## Н2 Двери

Своей двери у главы нет: `/stream` — операция контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
запрос контракта с билетом
  каждый обратный вызов — с этим билетом, только дверь перечня
  401 обратного вызова → ответ 401 UNAUTHORIZED, перевод окончен
GET /stream (поток, билет потока)
  нет Last-Event-ID → GET /changes без after → id: <position> без data:
  Last-Event-ID <p> → after=<p>; <p>-<k> → after=<p>, пропустить k + 1 производных первого сообщения
  повторять GET /changes?after=<position>&wait=<с>:
    сообщение ленты → виды (глава 3) → дочитать строку → StreamMessage k = 0, 1, … (id <p>-<k>, data)
    reset: true → stream.reset (id <position>)
    новая сработка журнала, иной режим → ruleFire, objectMode (id <position>-<k>)
    GET domain, одна страница: 200 → таблицы её членов class server, units прочих, сравнение → entity.* чужих записей (id <position>-<k>); не 200, не 403 → сравнения нет
  поток браузера закрыт → опрос прекращён
```

## Н4 Отказы

| Причина | Исход | Кто видит | Что делает вызывающий |
|---|---|---|---|
| обратный вызов — 401 (билет мёртв, дверь вне перечня, нет сертификата роли `backend`, лист иного сервера) | ответ 401 `UNAUTHORIZED` | WebUI | вход консоли или повтор запроса |
| лента ответила `reset` | `stream.reset` | WebUI | перечитать всё |
| запрос ленты отказал или оборвался; дочитывание отказало не 404 и не 403 или дало три несовпадения | поток закрыт | WebUI | переподключиться с `Last-Event-ID` |

## Н5 Приёмка

Тесты API consolem (поток — `tests/api-read.js` на закреплённом коммите) и приёмка платформы B1, B2 (ADR-0094
Confirmation): билет мёртв после закрытия запроса, обратный вызов вне перечня, с листа чужой роли и с листа другого

Чего они не видят, проверяет [`acceptance/4/`](../acceptance/4/README.md) `09-stream` (ADR-0094 доп. (17)): скрытое в потоке, `stream.reset` при смене прав, `Last-Event-ID` после перезапуска воркера.
