# V/11.5 — Обратный вызов и поток: нормы

Канон главы 5 урока V/11 «Бэкенд конфигуратора» (ADR-0094 B1, B2). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `2110dbf` (пин VMS); билет, обратный вызов, передача потоком (B1) и лента изменений `/changes` (B2) —
нормы платформы B, после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1); где глава на них опирается, место помечено «норма
платформы B — после Go GREEN 01–10».

Воркер `backend` не держит ни удостоверения человека, ни своих прав: всё, что он читает и пишет, он зовёт у консоли с
билетом запроса, который сейчас переводит. Поток `/stream` контракта — те же билеты, но долгоживущий запрос: консоль
передаёт его потоком, а `backend` переводит её ленту изменений в сообщения контракта. Глава нормирует сторону `backend`:
когда и как он зовёт консоль и что шлёт в поток.

Id норм — `V/11.5-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Билет** — 128 случайных бит, которые консоль выдала на один открытый запрос человека и передала воркеру (B1).
- **Лента** — `GET /changes` консоли: сообщения «строка X — ревизия R / удалена», без значения (B2).

## Н1 Форма

**Время.** Сроки главы — секунды монотонных часов процесса.

### Н1.1 Обратный вызов по билету

- Воркер зовёт консоль только **с билетом того запроса**, который сейчас переводит, и только на двери перечня
  (V/11.1 Н1.5); билет не хранится после ответа на запрос, не передаётся другим запросам и не пишется в журнал.
- Консоль принимает билет, пока внешний запрос открыт, с транспорта роли воркера, на двери перечня, при свежем `may`
  человека; иначе — 401 (B1; норма платформы B — после Go GREEN 01–10). Для `backend` 401 обратного вызова — конец
  перевода: ответ запросу — 401 `UNAUTHORIZED` (глава 4 Н4), повтора с тем же билетом нет.
- Ответ человеку закрыт (браузер ушёл) — билет мёртв: воркер прекращает перевод, ничего не дописывает.
- Предел ожидания передачи — по маршруту (V/11.1 Н1.5): составная запись (`devices`, `objects`) успевает части по
  порядку; не успела — консоль закрывает запрос, воркер видит мёртвый билет (как выше).

### Н1.2 Поток `/stream` из ленты `/changes`

- `GET /stream` передаётся потоком (маршрут `stream`, V/11.1 Н1.5; B1): билет потока годится только на чтения и
  `/changes`. `backend` держит один запрос `GET /changes` консоли на поток браузера (B2; норма платформы B — после Go GREEN
  01–10) и шлёт `text/event-stream`: на сообщение — строки `id:` и `data:` (`StreamMessage`), без `event:` (контракт).
- Перевод сообщений ленты:

| Лента консоли (B2) | `StreamMessage` контракта |
|---|---|
| строка вида (глава 3) создана — ревизия 1 | `entity.created` (`kind`, `entityId`, `version`) |
| строка изменена — ревизия R | `entity.changed` (`kind`, `entityId`, `version`) |
| строка удалена | `entity.deleted` (`kind`, `entityId`) |
| `reset` ленты | `stream.reset` |
| строка части камеры (`rec`, `det` про камеру) | `entity.changed` камеры (`kind: device`, её `entityId`, новая версия — глава 4 Н1.1) |
| строка, у которой вида нет (глава 3: `none`) | не шлётся |

- `version` сообщения — версия записи вида по главе 4 Н1.1 (индекс хранилища; B4): лента несёт «строка X — ревизия R»
  без индекса, поэтому `backend` дочитывает строку дверью перечня, прежде чем послать сообщение. `id` сообщения — номер
  сообщения ленты.
- `Last-Event-ID` браузера — номер ленты: `backend` открывает ленту с него; лента ответила `reset` (чужой номер,
  перезапуск экземпляра консоли, смена прав или меток человека, B2) — `stream.reset`, браузер перечитывает всё.
- Сообщений `operation.*`, `discovery.*` нет (групповых операций и поиска у нас нет, глава 2); `test.reset` — только на
  стенде (глава 6).
- Билет потока живёт, пока открыт поток браузера; поток закрыт — `backend` закрывает ленту.

### Н1.3 До нормы B2

Ленты `/changes` до нормы B2 нет, передачи `backend` — до нормы B1 (V/11.1 Н1.3): поток, как и вся подсистема, работает
после приращения платформы; опросом вместо ленты `backend` поток не подделывает.

## Н2 Двери

Своей двери у главы нет: `/stream` — операция контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
запрос контракта с билетом
  каждый обратный вызов — с этим билетом, только дверь перечня
  401 обратного вызова → ответ 401 UNAUTHORIZED, перевод окончен
GET /stream (поток, билет потока)
  открыть GET /changes консоли (с Last-Event-ID → номер ленты)
  сообщение ленты → вид (глава 3) → дочитать строку → StreamMessage (id, data)
  reset ленты → stream.reset
  поток браузера закрыт → закрыть ленту
```

## Н4 Отказы

| Причина | Исход | Кто видит | Что делает вызывающий |
|---|---|---|---|
| обратный вызов — 401 (билет мёртв, дверь вне перечня, чужой транспорт) | ответ 401 `UNAUTHORIZED` | WebUI | вход консоли или повтор запроса |
| лента ответила `reset` | `stream.reset` | WebUI | перечитать всё |
| лента оборвалась | поток закрыт | WebUI | переподключиться с `Last-Event-ID` |

## Н5 Приёмка

Тесты API consolem (поток — `tests/api-read.js` на закреплённом коммите) и приёмка платформы B1, B2 (ADR-0094
Confirmation): билет мёртв после закрытия запроса, обратный вызов вне перечня и с чужого транспорта — 401, поток
закрывается с запросом, `reset` ленты; до приращения платформы — чтением.
