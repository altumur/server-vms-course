# V/11.5 — Обратный вызов и поток: нормы

Канон главы 5 урока V/11 «Бэкенд конфигуратора» (ADR-0094 B1, B2). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `d104c441` (пин V/11: приращение прав поверх норм B, ADR-0090 доп. (17); пометка «норма платформы B» — где глава на них опирается).

Воркер `backend` не держит ни удостоверения человека, ни своих прав: всё, что он читает и пишет, он зовёт у консоли с
билетом запроса, который сейчас переводит. Поток `/stream` контракта — те же билеты, но долгоживущий запрос: консоль
передаёт его потоком, а `backend` переводит её ленту изменений в сообщения контракта. Глава нормирует сторону `backend`:
когда и как он зовёт консоль и что шлёт в поток.

Id норм — `V/11.5-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Билет** — 128 случайных бит, которые консоль выдала на один открытый запрос человека и передала воркеру (B1).
- **Лента** — `GET /changes` консоли: сообщения «строка X — ревизия R / удалена», без значения (B2).

## Н1 Форма

**Время.** Сроки главы — секунды монотонных часов процесса.

### Н1.1 Обратный вызов по билету

- Воркер зовёт консоль только **с билетом того запроса**, который сейчас переводит, и только на двери перечня
  (V/11.1 Н1.5); билет не хранится после ответа на запрос, не передаётся другим запросам и не пишется в журнал.
- Консоль принимает билет, пока внешний запрос открыт, на слушателе обратного вызова (`CONSOLE_CALL_PORT`, адрес —
  заголовок `X-W2C-Pass-Console`) с листом роли `backend` сервера того экземпляра, которому передала запрос (без
  комплекта — сокетом роли; V/11.1 Н1.2, ADR-0094 доп. (6) пп. 1, 2), на двери перечня, при свежем
  `may` человека и той же проверке, что токен двери (отзыв `jti`, срок `exp`, ключ `kid` записи билета у консоли); иначе
  — 401 (B1, ADR-0094 доп. (3) п. 1; норма платформы B). Воркер получает только 128 бит билета,
  полей записи не видит. Для `backend` 401 обратного вызова — конец перевода: ответ запросу — 401 `UNAUTHORIZED` (глава
  4 Н4), повтора с тем же билетом нет.
- Ответ человеку закрыт (браузер ушёл) — билет мёртв: воркер прекращает перевод, ничего не дописывает.
- Предел ожидания передачи — по маршруту (V/11.1 Н1.5): групповая запись (`api/devices`, `api/objects/delete`)
  успевает пакеты по порядку; не успела — консоль закрывает запрос, воркер видит мёртвый билет (как выше), а сделанные
  шаги уже записаны в память группы (глава 4 Н1.4): повтор её продолжит.

### Н1.2 Поток `/stream` из ленты `/changes`

- `GET /stream` (адрес консоли `/backend/api/stream`) передаётся потоком (маршрут `api/stream`, V/11.1 Н1.5; B1):
  билет потока годится только на чтения и `/changes`. Лента — длинный опрос, не SSE (P/06.1 Н2 «Лента изменений», B2):
  `GET /changes?after=<номер>&wait=<с>` → `{position, changes, reset?}`, `wait` не больше `CHANGES_WAIT`. На поток
  браузера `backend` держит один такой опрос за другим: следующий — с `after` = `position` прошлого ответа. Браузеру он
  шлёт `text/event-stream`: на сообщение — строки `id:` и `data:` (`StreamMessage`), без `event:` (контракт).
- Перевод сообщений ленты:

| Лента консоли (B2) | `StreamMessage` контракта |
|---|---|
| строка вида (глава 3) создана — `revision: 1` | `entity.created` (`kind`, `entityId`, `version`) |
| строка изменена — `revision: R`; `0` — ревизия не читается | `entity.changed` (`kind`, `entityId`, `version`) |
| строка удалена — `deleted` вместо `revision` (индекс надгробия, B4, ADR-0094 доп. (3) п. 9; `""` — надгробия нет) | `entity.deleted` (`kind`, `entityId`) |
| ответ с `reset: true` | `stream.reset` |
| строка части камеры (поток `cam`, запись `rec`, детектор `det` про камеру) | ещё `entity.changed` камеры (`kind: device`, её `entityId`, новая версия — глава 4 Н1.1) |
| строка тома `rec/volumes` | два вида одной строки: сообщение хранилища (`kind: archive`) и тома (`kind: volume`); запись `rec` на томе — ещё `entity.changed` хранилища (`retentionDays`) |
| строка папки `platform/folders/<id>` | `entity.created`, `entity.changed` (`kind: folder`); `deleted` — `entity.deleted` папки и её потомков (ниже) |
| строка `backend/opdone/<id>/<i>` | `operation.progress` (`kind: operation`, `entityId`, `payload` — шаг `OperationItem` и счётчики строки `backend/opcount/<id>`) |
| запись `backend/operations/<id>` с `state: done` | `operation.finished` (`kind: operation`, `entityId`, `payload` — `state`, `ok`, `failed`, `cancelled`) |
| строка, у которой вида нет (глава 3: `none`; том `edge`, камера `kind: io`), строки `backend/repeats`, `people`, `history`, `memberof`, иные строки операции | не шлётся |

- **Производные сообщения** (разбор ревью V/11, Codex № 18, Claude С-15, вопрос 11). Одно сообщение ленты может дать
  несколько `StreamMessage` — по строкам таблицы выше, в порядке: сообщение своего вида строки, затем камеры, затем
  хранилища (у тома — `archive`, затем `volume`). У каждого свой `type`. Удалённый детектор: `entity.deleted`
  детектора (его id — из ключа надгробия), затем `entity.changed` камеры — её версия с индексом надгробия
  (`?deleted=1&about=`, глава 4 Н1.1); камеры уже нет — сообщения камеры нет.

- `version` сообщения — версия записи вида по главе 4 Н1.1 (индекс хранилища; B4): лента несёт «строка X — ревизия R»
  без индекса, поэтому `backend` дочитывает строку дверью перечня, прежде чем послать сообщение. Дочитывание ответило
  404 (строку уже сняли) — сообщение не шлётся: удаление придёт своим сообщением ленты; `revision` прочитанной строки
  выше `R` — шлётся версия прочитанной (разбор ревью V/11, дополнение Kimi, № 6).
- **Поля тела** `StreamMessage` (контракт: обязательны `id`, `type`, `at`; дополнение Kimi, № 5, вопрос 2): `id` тела
  равен строке SSE `id:`; `at` — время события на сервере, не отправки, RFC 3339 UTC: у сообщения ленты — поле `at` ленты,
  число JSON, секунды такта консоли, увидевшего версию строки; позже приёма хранилищем оно не больше чем на такт, и
  досылка отдаёт то же значение (норма платформы B2); у событий хода
  ассистента (глава 7) — момент, когда `backend` их произвёл. Смысл `at` продукту названо в третьем запросе — подтвердить.
- **`id` сообщения** — `<p>-<k>`: `p` — номер, после которого лента отдаёт это сообщение (`n` предыдущего сообщения
  ответа, у первого — `after` запроса), `k` — номер производного сообщения в нём с 0 (вопрос 11). Берётся `p`, а не `n`:
  лента отдаёт только сообщения **после** номера, и обрыв между производными иначе потерял бы остаток. `-` в номере ленты
  нет (P/06.1 Н2). Для клиента `id` непрозрачен (контракт).
- **Начало подписки** (ADR-0094 доп. (3) п. 6): первый запрос без `after` сразу отвечает `{position, changes: []}`;
  `backend` шлёт браузеру строку SSE `id: <position>` без `data:` — по SSE она ставит последний `id` браузера и события не
  даёт, поэтому `StreamMessage` у неё нет и `type` не нужен. Клиент применяет сообщения с отбросом ревизии не выше
  прочитанной.
- **`Last-Event-ID`** браузера (заголовок проходит передачу второго вида, V/11.1 Н1.5): `<p>` — `after=<p>`; `<p>-<k>` —
  `after=<p>` и пропустить первые `k + 1` производных первого сообщения; иная форма — как начало подписки, с
  `stream.reset`.
- **`reset`** — ответ `{position, changes: [], reset: true}` (чужой или вытесненный номер, перезапуск экземпляра консоли,
  смена прав или меток человека, B2): `stream.reset` с `id` `<position>`, браузер перечитывает всё, опрос идёт с
  `after=<position>`.
- **Удаление папки** (ADR-0096 §3): лента несёт только саму папку, а подпапки недостижимы с того же индекса. `backend` помнит дерево последнего
  чтения `GET /folders` этого потока и после `entity.deleted` папки шлёт `entity.deleted` каждому потомку, который был достижим до удаления, в
  порядке `id`; это производные сообщения того же сообщения ленты. Дерева в памяти нет (начало потока) — только сама папка; браузер всё
  равно получит 404 на чтении потомка.
- **Строки операции.** Ленту по билету консоль отдаёт только операции автора (P/06.9 Н2), поэтому чужих сообщений поток не несёт. Значения —
  дочитыванием двери `GET /backend/operations/<id>`; порядок шагов сверх ленты не обещан, истина — `GET /operations/{id}`.
- **Права.** Строк домена лента не несёт: сообщений `kind: access` нет, WebUI перечитывает снимок сам. Сброс ленты при смене ролей — как
  прочий `reset`.
- Сообщений `discovery.*` нет (поиска у нас нет, глава 2). `test.reset` не шлётся:
  `/test/reset` загружает набор обычными записями, и поток несёт их сообщения; узнать о сбросе другой экземпляр
  `backend` мог бы только мимо ленты (разбор ревью V/11, Claude С-19; глава 6 Н1.3).
- Билет потока живёт, пока открыт поток браузера; поток закрыт — `backend` прекращает опрос. Консоль закрывает открытый
  поток по билету при отзыве `jti`, выключении человека и на `exp` (доп. (3) п. 1); потоки идут отдельным пределом
  консоли, обратные вызовы — своей полосой (доп. (3) п. 7).

### Н1.3 Только лента

Источник потока — только лента `/changes`: опросом строк `backend` поток не подделывает. Ответ ленты, кроме `reset`, не
несёт значений: их дочитывает Н1.2.

## Н2 Двери

Своей двери у главы нет: `/stream` — операция контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
запрос контракта с билетом
  каждый обратный вызов — с этим билетом, только дверь перечня
  401 обратного вызова → ответ 401 UNAUTHORIZED, перевод окончен
GET /stream (поток, билет потока)
  нет Last-Event-ID → GET /changes без after → id: <position> без data:
  Last-Event-ID <p> → after=<p>; <p>-<k> → after=<p>, пропустить k + 1 производных первого сообщения
  повторять GET /changes?after=<position>&wait=<с>:
    сообщение ленты → виды (глава 3) → дочитать строку → StreamMessage k = 0, 1, … (id <p>-<k>, data)
    reset: true → stream.reset (id <position>)
  поток браузера закрыт → опрос прекращён
```

## Н4 Отказы

| Причина | Исход | Кто видит | Что делает вызывающий |
|---|---|---|---|
| обратный вызов — 401 (билет мёртв, дверь вне перечня, нет сертификата роли `backend`, лист иного сервера) | ответ 401 `UNAUTHORIZED` | WebUI | вход консоли или повтор запроса |
| лента ответила `reset` | `stream.reset` | WebUI | перечитать всё |
| запрос ленты отказал или оборвался | поток закрыт | WebUI | переподключиться с `Last-Event-ID` |

## Н5 Приёмка

Тесты API consolem (поток — `tests/api-read.js` на закреплённом коммите) и приёмка платформы B1, B2 (ADR-0094
Confirmation): билет мёртв после закрытия запроса, обратный вызов вне перечня, с листа чужой роли и с листа другого
сервера — 401 (доп. (6) п. 5), поток закрывается с запросом, `reset` ленты; до приращения платформы — чтением.

Чего они не видят, проверяет [`acceptance/4/`](../acceptance/4/README.md) `09-stream` (ADR-0094 доп. (17)): скрытое в потоке, `stream.reset` при смене прав, `Last-Event-ID` после перезапуска воркера.
