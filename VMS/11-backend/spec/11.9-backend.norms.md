# V/11.9 — Цикл хода: нормы

Канон главы 9 урока V/11 «Бэкенд конфигуратора», ассистент (ADR-0080; модуль VMS — ADR-0090; подсистема — ADR-0093 пп. 3, 5, 8, доп. (1)
пп. 2, 4, доп. (3) пп. 1, 3, 6, доп. (4) пп. 1, 2, 6, 7). [Лекция](../11-backend.md), [инструкция](11-backend.README.md). Платформа — выгрузка
`cammeta-specs` `7a875c75`.

Текст производный от en, руками не правится: источник — английский [`en/11.9-backend.norms.en.md`](en/11.9-backend.norms.en.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Ход ведёт `backend`, не модель и не консоль: цикл только здесь (ADR-0093 доп. (8) п. 2), панель страницы снята. `backend` шлёт шаги двери модели (V/10.2), исполняет вызовы инструментов модели дверями консоли по билету (глава 10), проверяет план (глава 11) и отдаёт итог потоком (глава 7). Модель отвечает только вызовом: план, вопрос или отказ. Харнес — системный текст, описания инструментов, политика цикла — передан пилотом (ADR-0093 п. 8, доп. (3)): основа — инструменты v4.0 и `tool_choice: required` (56 из 60 просьб набора пилота, ни одного сбоя разбора у сервера модели). Глава нормирует ход, сообщения шага, разбор ответа модели, исходы хода и его жизнь.

Id норм — `V/11.9-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/ru/spec/01.1-store.norms.md#н0-словарь-слов).

- **Ход** — от текста админа (просьбы) до исхода хода (Н1.5): принятого плана, отказа, «ход не завершён» или отмены.
  Вопрос модели (`ask_admin`) ход не кончает, кончает запрос: поток закрывается событием `question`, ответ админа — новый запрос с `context` вопроса (глава 7 Н1.2; ADR-0093 доп. (6) п. 2).
- **Тексты хода** — просьба и ответы админа на `ask_admin` этого хода, как их ввёл человек: текст записывает `backend` из
  ввода человека, не из вывода модели (ADR-0093 доп. (3) п. 1); по ним глава 11 сверяет «названо». Слова `backend` (обзор, сообщение о секретах, подсказки цикла) и слова модели в тексты
  хода не входят.
- **Вызов модели** — один шаг двери модели, дошедший до ответа модели (`done`, V/10.2 Н1.3).

## Н1 Форма

**Данные.** Своих семей у главы нет. Ход живёт в памяти `backend` на время запроса, между запросами — в `context` у клиента: тексты хода, история сообщений, ответы модели
в хранилище консоли и в журналы не идут. Харнес — данные урока, а не код `backend`:

| Файл | Что | Как `backend` его берёт |
|---|---|---|
| [`harness/system.md`](../harness/system.md) | системный текст (английский, как в замере пилота) | байты как есть — содержимое единственного сообщения `system` шага |
| [`harness/tools.json`](../harness/tools.json) | инструменты: имя, описание, схема аргументов (глава 10 Н1.1) | `tools` шага — Н1.2 |
| [`harness/words.json`](../harness/words.json) | данные локали проверки и цикла (глава 10 Н1.4, глава 11 Н1.2) | глава 11 |

`backend` несёт харнес байтами этих файлов; правка харнеса — правкой файлов.

Отличия от пакета передачи (замер — пакет пилота; ADR-0093 доп. (3) п. 6, доп. (4) п. 7) — **правки после замера**,
перечень с README урока:

1. Обзор кластера — первым сообщением `user`, не в `system`.
2. Метка секрета — `{"secret": N}` и сообщение «Secret N is entered» вместо текстового слота; `system.md` и заметка
   `get_manifest` — о метке.
3. Ответ админа — результат `ask_admin`, ход им не кончается; описание `ask_admin` и `system.md` — о том же.
4. Имена инструментов — без префикса пилота; `system.md` — «Use only the tools you are given».
5. Описание `list_table` — пример таблицы `rec`; `tools.json` кончается переводом строки.
6. Вызов, написанный текстом, не исполняется; подсказка без вызова — в счёт 25 (доп. (4) п. 6).
7. Сверка «названо» усилена (доп. (4) пп. 3, 5): имена `named` и строки — «имя в тексте», слово короче 4 букв — целиком
   или с окончанием `endings` (решение «Архитектора» по замеру), `stop`, полярность `bool` и снятия; слова ошибок «ask the
   admin so that the answer itself names…».
8. Данные `words.json`: русские строки; `rights`, `not_found`, `all` — с границами и формами; `polarity`, `endings`, `stop`;
   слова операторов VMS (`fields`, `options`, `units`).
9. Право — возможность двери записи (`need`), не `edit` (доп. (4) п. 4).
10. Принятый `ask_admin` останавливает вызовы ответа, неисполненным — `not executed`; результаты `ask_admin` окно не
    сокращает; перезапусков по 410/404 — не больше 2.
11. Обзор — без имени и грантов сессии (`/session` для обзора не читается);
    права модель видит по `can_edit` единиц; охват — подсистемы `backend` (ADR-0093 доп. (5)).
12. `refuse` с `other_kind` и строка `system.md` о просьбе другого типа (ADR-0093 доп. (13), V/11.7 Н1.6); в замере её не было.

Новая правка харнеса — решением «Архитектора» и строкой этого перечня; повторный замер — поручением пилоту.

### Н1.1 Панель

Снята (ADR-0093 доп. (8) п. 2). Ввод, вопросы, показ и выбор ведёт форма consolem, ход — операция `POST /assist/turns` (глава 7 Н1.1); модель хода — умолчание главы 7 Н1.2. Адрес нормы сохранён.

### Н1.2 Сообщения шага

Тело шага двери модели (V/10.2 Н1.2):

```yaml
messages:           [system, user-обзор, user-просьба, (user-секреты)?, …история хода]
  system:           {role: system, content: байты harness/system.md} — единственное сообщение system шага (V/10.2 Н1.4:
                    общий префикс без данных)
  user-обзор:       {role: user, content: "## Cluster overview\nA snapshot of the console doors (list_subsystems,
                    get_manifest of every subsystem, the admin's rights):\n```json\n<обзор>\n```\n"}
  обзор:            JSON без пробелов {subsystems, manifests, session}: subsystems — результат list_subsystems (глава 10),
                    manifests — {<sub>: результат get_manifest} каждой подсистемы из subsystems, session — {note: "the
                    admin's rights are per unit: find_units shows can_edit: false where the admin has no right; such units
                    are left out of the plan"} — без имени и грантов: /session для обзора не читается (было P/06.5
                    Н1.1), право — can_edit единиц (глава 10 Н1.2); строится один раз в начале хода
  user-просьба:     {role: user, content: просьба как её ввёл админ}
  user-секреты:     есть, если в ходе введён секрет (V/11.12 Н1.3): {role: user, content: "Secret N is entered." — по
                    строке на номер, по возрастанию}; новый секрет после начала хода — такое же сообщение в конце истории;
                    секреты живут с планом (V/11.12 Н1.3) — сообщение о них в каждом шаге хода, и при перезапуске по 410/404
  история:          сообщения модели как есть (V/10.2 Н1.3 message) без reasoning_content; результаты инструментов
                    {role: tool, tool_call_id, content}; ответы админа — результатом ask_admin (Н1.4); подсказки цикла
                    {role: user} (Н1.4)
tools:              harness/tools.json в форме OpenAI: [{type: function, function: {name, description, parameters:
                    inputSchema}}] — по порядку файла
tool_choice:        "required"
reasoning_effort:   "medium"
max_tokens:         нет
turn:               id хода — 32 строчных hex (128 случайных бит), один на ход (V/10.2 Н1.2, Н1.4)
```

- **Обзор — сообщением `user`**, не в `system`: в нём манифесты, которые человек видит, и его права; общий префикс кеша
  модели — только системный текст и инструменты (V/10.2 Н1.4; ADR-0093 доп. (3) п. 6). Обзор строится теми же функциями,
  что инструменты главы 10, и тем же чтением консоли.
- **Окно.** Окно — `context` строки модели хода (V/10.1 Н1.1). Перед шагом `backend` оценивает промпт: `prompt_tokens`
  прошлого вызова плюс прирост сообщений с тех пор, `CHARS_PER_TOKEN` знаков JSON на токен (без прошлого вызова — все
  сообщения так же). Оценка больше `context − RESERVE` — содержимое старейших результатов инструментов заменяется
  строкой `[result elided: context window; call the tool again if needed]`, по одному, пока оценка не уложится или
  не останется `KEEP_TOOL_RESULTS` последних результатов. `system`, обзор, тексты хода (и результаты `ask_admin` — это
  ответы админа) и сообщения модели не сокращаются.

```yaml
CHARS_PER_TOKEN:    3
RESERVE:            4096 токенов — запас окна под ответ модели
KEEP_TOOL_RESULTS:  4
TURN_CALLS:         25 — вызовов модели между текстами админа: после просьбы и после каждого ответа (ADR-0093 доп. (4) п. 2)
STEP_TRIES:         3 — попыток шага при failed `model failed` и `model restarted` (Н1.3)
RESTARTS:           2 — перезапусков хода по 410/404 за ход (ADR-0093 доп. (4) п. 2)
ENQUEUE_WAIT:       300 — с накопленного ожидания постановки шага: 503 `loading`, 429, 503 `busy` (Н1.3)
```

### Н1.3 Шаг

`backend` зовёт дверь модели маршрутом `/assist/chat/<имя>/…` по билету (глава 7 Н1.2; ADR-0093 доп. (7)): токена двери у него нет, `where` он не читает. Допуск (`view` на строку модели) судит консоль: отказ — ход не начинается. Один шаг хода за раз.

| Ответ двери | Что делает `backend` |
|---|---|
| `POST` 202 | `GET …/steps/<step>?wait=3` по кругу, короче предела маршрута `PASS_WAIT`, пока `state` не `done`, `failed`, `cancelled`; строка состояния — по `queued` (`ahead`) и `running` |
| `done` | вызов модели засчитан; ответ — Н1.4 |
| `failed` `model failed`, `model restarted` | тот же шаг снова, до `STEP_TRIES` попыток; не засчитывается; последняя не удалась — исход «ход не завершён», причина — `reason` |
| `failed` `too long`, `queue too long` | исход «ход не завершён», причина — `reason` |
| `failed` `context exceeded` | исход «ход не завершён»: «не уместилось в окно модели» |
| `cancelled` (не по отмене `backend`) | исход «ход не завершён», причина — `reason` |
| 503 `loading`, 429, 503 `busy` на `POST` | ждать `retry_after` тела (иначе 5 с) и поставить снова; строка состояния — «модель загружается» или «модель занята». Ожидание копится по всем трём отказам подряд и обнуляется принятием шага (202); дольше `ENQUEUE_WAIT` — исход «ход не завершён»: «модель занята» |
| 503 `model unavailable`, маршрута нет или сеть | исход «ход не завершён»: «модель недоступна», причина — `reason` тела, если есть |
| 403 на шаге начатого хода | исход «ход не завершён»: «шаг не удался» |
| 410 `gone`, 404 `no such step` | шаг утрачен (держатель сменился, V/10.2 Н1.3): ход начинается заново — новый `turn`, счёт вызовов с нуля, результаты инструментов читаются снова; тексты хода — одним сообщением `user` через пустую строку, как у перестройки (Н1.5); до `RESTARTS` раз за ход, затем исход «ход не завершён» |
| 400, 413 | исход «ход не завершён», причина — слова двери (ошибка `backend`, не модели) |
| сеть, нет ответа, 503 `busy` на `GET` | `POST` не повторяется сам (V/10.2 Н1.2: памяти повторов нет) — исход «ход не завершён»; `GET` — до 3 раз за шаг через 2 с, затем исход «ход не завершён»; шаг снимет `ABANDON` (V/10.2 Н1.5) |

### Н1.4 Ответ модели

Из `message` ответа (`done`) `backend` берёт вызовы:

1. **Вызовы.** `tool_calls` по порядку. Вызов, написанный текстом в `content`, не исполняется (ADR-0093 доп. (4) п. 6;
   ADR-0093 п. 3: ход кончается вызовом, не разбором текста).
2. **Нет вызова.** В историю — сообщение модели и подсказка `{role: user, content: "Use a tool call: answer the admin
   only with a tool call: a plan — propose_plan, a question — ask_admin, a refusal or \"there are no such units\" —
   refuse with the reason."}`, следующий вызов модели; вызов в счёт `TURN_CALLS` (Н1.4 п. 7). С `tool_choice:
   "required"` ответ без вызова не ожидается.
3. **Аргументы и имя.** Аргументы: строка — JSON, пустая — `{}`; готовый объект принимается; иное — результат `error: the
   arguments are not JSON: <первые 300 знаков>`. Имя не из набора главы 10 — инструмент, к которому подходят аргументы
   (ключи — из его свойств, обязательные — все), если такой ровно один; иначе результат `no tool <имя>`.
4. **Сначала данные.** Первый за ход `ask_admin` или `refuse`, а до него за ход не было ни одного `find_units`,
   `field_values`, `list_table`, — не исполняется; результат — ошибка (глава 10 Н1.3) `error: an answer not checked
   against the data. First find_units or field_values for the request's words (rights — can_edit of the units found,
   label codes — field_values); then a plan, a question or a refusal. If the request names neither a unit nor a value,
   call ask_admin again.` Один раз за ход.
5. **Исполнить** — по главе 10 (чтение) и главе 11 (`propose_plan`, проверка `refuse`). Результат — сообщение
   `{role: tool, tool_call_id, content}`; ошибка инструмента — тоже результат, ход идёт дальше (глава 10 Н1.3).
6. **Конец и вопрос.** Принятый `propose_plan` с `valid: true`, принятый `refuse` и принятый `ask_admin` останавливают
   исполнение вызовов этого ответа: каждый следующий вызов того же ответа не исполняется и получает результат
   `not executed: <причина>` — `the turn is over` после плана и отказа, `waiting for the admin's answer` после вопроса
   (пары вызов — результат в истории целы). План и отказ кончают ход. Вопрос кончает запрос: `backend` отдаёт
   вопрос событием `question`; ответ админа приходит новым запросом с `context` и становится результатом этого `ask_admin` (`content` — текст, как его ввёл человек; ADR-0093
   доп. (3) п. 1); он входит в тексты хода, счёт вызовов модели — с нуля, следующий вызов модели. У поля ответа —
   подсказка: «ответьте словами — назовите поле и значение; „да“ ничего не называет».
7. **Предел.** Вызовов модели после последнего текста админа — `TURN_CALLS`; следующего не будет — исход «ход не
   завершён» с последней причиной проверки (глава 11 Н1.6) или «предел хода», не `refuse` (ADR-0093 доп. (4) п. 2).

### Н1.5 Исходы хода

| Исход | Когда | Что видит админ |
|---|---|---|
| план | `propose_plan` с `valid: true` | блок отбора и diff (глава 11 Н1.7), `summary` — «слова модели», «Применить» (V/11.12) |
| отказ | принятый `refuse` | `reason` — «слова модели» |
| ход не завершён | Н1.3, Н1.4 п. 7, обзор не построен (Н1.2) | слова `backend` по виду причины («предел хода», «модель недоступна», «шаг не удался», «консоль не прочиталась», «план не прошёл проверку: <правило>»); исходный текст причины (ошибка проверки, `reason` двери) — свёрнутым под ними; админ может переписать просьбу |
| отменён | «Отменить ход», «Новый ход», обрыв потока до события конца, выход, смена сессии | — |

- **Слова «ход не завершён».** Предел хода после отвергнутых версий плана — «план не прошёл проверку: <правило>», где
  правило — вид первой ошибки последней версии (глава 11 Н1.6) словами `backend`:

```yaml
secret: метка секрета не на месте        rights: нет права записи на единицу     empty: пустая правка
twice: поле правится дважды              missing: пропущены отобранные единицы    extra: в плане лишние единицы
condition: условие отбора не из просьбы  named: единица не названа в просьбе     selection: отбор не сходится с правками
value: значение не названо в просьбе     list: правка списка без глагола          field: поле не названо в просьбе
form: правка не по форме поля            other: правило проверки
```

  Вид — по словам ошибки главы 11 (Н1.3, Н1.4): «secret label», «is a secret» — `secret`; «has no right to edit» —
  `rights`; «empty edit» — `empty`; «is edited twice» — `twice`; «selected but missing» — `missing`; «not selected (» —
  `extra`; «selection.where: condition» — `condition`; «selection.named:» — `named`; прочее «selection» — `selection`;
  «value … is not named» — `value`; «does not say to add, remove or replace» — `list`; «field … is not named»,
  «selection.fields» — `field`; ошибки формы Н1.3 — `form`; иное — `other`. Предел без версий плана — «предел хода»;
  шаг `cancelled` у двери — «шаг снят у двери модели»; неизвестная причина — «шаг не удался».
- Исход кончает ход. Новый текст без `context` — новая просьба, новый ход, новый `turn`; тексты прежнего хода в новый не
  переносятся. Новый текст с `context` исхода — **уточнение**: `plan` и `refused` несут `context`, форма шлёт его со словами «Уточнить», прежний план снят. Тот же `turn`, текст добавляется к текстам хода сообщением `user`: новый план заменяет прежний целиком, поэтому слова прежних текстов в сверке «названо» остаются; счёт вызовов с нуля.
- **Перестройка** после применения (V/11.12 Н1.4 «Итог») — новый ход: просьба — тексты прежнего хода, как ввёл админ,
  одним сообщением `user` через пустую строку; строки на перестройку `backend` называет отдельным сообщением `user`
  своих слов (имена единиц и исходы, без значений секретов), в тексты хода оно не входит.
- **Ответ модели не исполняется сам**: ни план, ни отказ ничего не пишут; пишет только «Применить» (V/11.12).

### Н1.6 Жизнь хода

Запрос живёт от `POST` до события конца (глава 7 Н0, Н1.1). Обрыв потока до события конца — отмена, отбой шага снимает `ABANDON` двери (V/10.2 Н1.3). Событие `question` — не обрыв: ход ждёт нового запроса у клиента. Своего состояния у `backend` нет, переписка у клиента (ADR-0094 A3), ответ модели, тексты хода в хранилище и журналы не идут. Метка секрета живёт только внутри хода (V/11.12 Н1.3).

## Н3 Проход

```
текст админа → (нет хода: новый ход, turn, обзор — глава 10) → тексты хода += текст; счёт = 0
цикл:
  счёт = TURN_CALLS → исход «ход не завершён» (последняя причина)
  окно (Н1.2) → шаг (Н1.3): 202 → опрос → done | failed (повтор до STEP_TRIES) | 410/404 → ход заново
    503 loading, 429, 503 busy → ждать retry_after, снова; накопленно дольше ENQUEUE_WAIT → «ход не завершён»
  счёт += 1; вызовы (Н1.4 пп. 1, 3); нет вызова → подсказка «use a tool call» (в счёт)
  каждый вызов по порядку:
    ask_admin/refuse без поиска за ход → ошибка «сначала данные» (раз за ход)
    иначе исполнить (глава 10, глава 11) → результат в историю
    propose_plan valid → исход «план»; refuse принят → исход «отказ»; ask_admin принят → событие question, запрос кончен; новый запрос с context → текст админа
    после принятого — остальные вызовы ответа: not executed
```

**Гонки.** Поток оборван, пока шаг идёт: шаг снимает `ABANDON`, поздний ответ модели не исполняется. Пока исполняются вызовы одного ответа, новый шаг не ставится. Права админа сузились посреди хода:
следующее чтение консоли и проверка плана видят новые (глава 10 Н1.2, глава 11); обзор хода — с начала хода, план
проверяется по свежему чтению.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| `TURN_CALLS` вызовов без исхода | «ход не завершён», последняя причина проверки | админ | переписать просьбу |
| шаг `failed` после `STEP_TRIES`, `too long`, `queue too long`, `context exceeded`, `cancelled` | «ход не завершён», `reason` | админ | позже или короче |
| модель недоступна (маршрута нет, 503 `model unavailable`) | «ход не завершён», причина | админ | оператор — строка модели (V/10.1) |
| шаг не поставлен за `ENQUEUE_WAIT` (503 `loading`, 429, 503 `busy`) | «ход не завершён»: «модель занята» | админ | позже |
| 400, 413 двери модели | «ход не завершён», слова двери | админ | — (ошибка `backend`) |
| обзор не построен (чтение консоли) | «ход не завершён»: «консоль не прочиталась» | админ | позже |
| шаг утрачен (410, 404) | ход заново, после `RESTARTS` — «ход не завершён» | админ | позже |
