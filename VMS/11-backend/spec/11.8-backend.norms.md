# V/11.8 — Права: нормы

Канон главы 8 урока V/11 «Бэкенд конфигуратора» (ADR-0097 §7, ADR-0098 §7, ADR-0099 §7, ADR-0100 §4; ADR-0094 доп. (11), (12)
п. 11; ADR-0110 доп. (4), (5); ADR-0111 пп. 12, 16, 17, 21). [Лекция](../11-backend.md), [инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json).
Платформа — выгрузка `cammeta-specs` `67336416` (пин VMS; приращение прав, ADR-0095–ADR-0100).

Права consolem — снимок целиком: роли с уровнями по полям, люди, группы, каталоги. Права платформы — роли и группы домена и
строки грантов каждого кластера (P/08.4 Н1.3а, договор `may`). Снимок один на домен. Перевод идёт в обе стороны: `GET /access` собирает снимок из
строк по грантам смотрящего, `POST /access/apply` разбирает черновик обратно: людей, группы и роли пишет одним пакетом домена, права роли — в её строку домена, откуда они расходятся по кластерам, строки одного кластера — отдельным пакетом. Своих прав у `backend` нет:
двери домена судят самого человека билета (P/06.3 Н1.9 «Двери домена»).

Id норм — `V/11.8-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Снимок** — схема `Access` контракта.
- **Черновик** — снимок с приложенными `changes` тела `POST /access/apply` (Н1.5 п. 1а).
- **Точка роли** — одно место consolem с одним значением поля: `*`, `folder:F`, `unit:cam/<id>` (Н1.3).
- **Уровень** — значение поля `cam` или `arch` из `reference.access.levels`.

## Н1 Форма

**Время.** Поля `expiresDate`, `roleUntil`, `rolesUntil` — даты в часовом поясе `timezone` ответа `GET /session`. Дата `D`
пишется концом дня: `expires`, `until` — стенные секунды полуночи дня, следующего за `D`, в этом поясе; обратно —
дата секунды `expires − 1`. `until = 0` и `expires = 0` — без срока, поле или ключ отсутствует, `null` у `expiresDate`,
`rolesUntil`.

**Данные.** Строки людей, групп, ролей и грантов — двери домена по билету (V/11.1 Н1.5). Своих семей две: таблицы манифеста
`backend/people/<h>` (Н1.2) и `backend/history/<id>` (Н1.7), обе `service: true`.

### Н1.1 Сборка снимка

`GET /access` (**цена:** при полном домене порядка 250 вызовов на чтение, оценка, предела нет) читает `GET /domain/users`, `/domain/groups`, `/domain/roles`, `/domain/grants`, `GET /domain/folders`, `GET /domain` всеми страницами `cursor`, `GET /cam/cameras`, `GET /live/accounts` (Н1.11), таблицы
`people` и `history`; камеры других кластеров — Н1.10. Двери домена судят смотрящего фильтром (P/10 Н1.2д; ADR-0110 доп. (5) п. 1): в ответе только его кластеры, ни одного — 403, отказ запроса: снимок частями не отдаётся. Перечень
камер нужен только для живости строк `unit:cam/<id>` (Н1.4): 403 его двери — своего нет, видимых камер нет, отказа нет: вошедший по гранту другого кластера на своём прав не имеет. Строки прав лежат у держателя. Чтение ответило 403 — 403 `PERMISSION_DENIED`: форма скрывает раздел, запуск идёт (ADR-0112). Иной отказ — Н4: форма и на него запуск не прерывает. Без связи `POST /access/apply` — 409 `SERVER_OFFLINE`.

| Вид | Поля | Откуда |

**Части** (ADR-0112 доп. (10)). `GET /access` — `roles`, `catalogs`, `streamGrants`, `version`. Перечни — тот же снимок, страницами главы 3 Н1.2б, место — последний id: `GET /access/users` (`q` — подстрока `login`, `name`), `/access/groups` (`q` — `name`), `/access/history`, `/access/cell-history` (`q` — `text`, Н1.7), `/access/roles/{id}/objects` (`q` — `objectId`; элемент `{objectId, levels}`, по `objectAccess` Н1.4, нет роли — 404 `NOT_FOUND`). **Предел** (ADR-0112 доп. (12) п. 5): снимок читается целиком на каждый запрос: версия покрывает всё, страницы экономят ответ, а не чтения; разделение версии — после замера.

`rolesUntil` обратно — наименьшая дата: снимок пишет одну дату на все роли группы, поэтому при пересохранении она только сужает.

**Версия снимка** — `a` и hex SHA-256 от строк `<вид> <имя> <индекс>\n` по байтам: вид — `user`, `group`, `role` (`lines` в строке роли), `grants`
(строка `domain` и строка каждого кластера снимка; у зрителя домена вместо индекса строки кластера — hex SHA-256 её строк без строк ролей с `lines` не `unit:`: проход держателя двигает индекс, а снимка не меняет), `history` (читаемые строки), `people` (только живых людей: строка без человека снимка не
меняет), `folder`, `camera` (камеры, названные строками `unit:cam/<id>` кластеров снимка, имя — `<кластер>/<id>`). Индекс — `index` элемента перечня, у грантов — `versions` ответа двери, у
`camera` — `1`, если камера есть в перечне, иначе `0`: правка камеры снимка не меняет, удаление меняет. Папки входят: от них зависят `folderAccess`. `ETag` — эта версия в кавычках.

Снимок покрывает всех людей, группы и роли домена, а права ролей — кластеров снимка (Н1.10). Поэтому `apply`
меняет только разницу и ничего не удаляет молча (Н1.5).

### Н1.2 Id людей, групп, ролей

- **Роль и группа.** Ключ строки домена — `id` consolem как есть: новая запись снимка пишется с `name` = `id` (ADR-0098 §7).
  Строка с иным `name` — встроенная `admin` и записи, заведённые мимо `backend`, — получает UUID v5 от `role:<имя>`,
  `group:<имя>` (глава 4 Н1.6).
- **Человек.** Имя человека — его вход, поэтому `id` не может быть ключом. `id` — поле строки `backend/people/<h>` рядом с полем `login` (имя), `h` — hex SHA-256
  имени: имя `.` или `..` ключом таблицы быть не может; строки нет — UUID
  v5 от `user:<имя>`, как `Me.userId` (глава 3 Н1.2). `GET /me` читает ту же строку: иначе `userId` разошёлся бы со снимком.
- Новый человек с `id` клиента: строка `people` ложится **после** пакета домена, вместе со строками истории (Н1.7), `cas ""`, поверх прежней — `cas`
  её индекса. Запись идёт правом следствий, поэтому раньше суда домена её быть не может: человек только с `view` писал бы таблицу и
  сдвигал версию всем. Обрыв между пакетом и этой записью оставляет человека с `id` v5: строку существующего человека ничто не дописывает, окно
  признано, `id` — подпись, права идут по имени.
- Удалённый человек: `apply` снимает его строку `people` тем же пакетом, что строки истории, `cas` — индекс снимка; строки нет — записи нет. У таблицы нет
  `delete_after`, без снятия она росла бы с каждым удалённым именем. Строка человека, удалённого мимо `backend`, остаётся: в снимок и версию
  она не идёт (Н1.1), а новый человек с этим именем получит её `id`, если `apply` не запишет свой.
- **`login` неизменен:** переименования человека у платформы нет. Иной `login` при том же `id` и тот же `login` при новом `id` — 422
  `NOT_SUPPORTED` (Н1.6): удаление и создание одного имени дали бы снятие и запись одного ключа `people` в одном пакете.

### Н1.3 Строки роли из уровней

Перевод уровня `cam` по подсистемам вида — `(cam, live, rec)`, ранги `0` — `none`, `1` — `view`, `2` — `edit`:

| Уровень | `cam` | `live` | `rec` |
|---|---|---|---|
| `FORBID` | 0 | 0 | 0 |
| `ONLY_ARCHIVE` | 1 | 0 | 1 |
| `MON` | 1 | 1 | 0 |
| `ARCHIVE` | 1 | 1 | 1 |
| `ARCH_MANAGE` | 1 | 1 | 2 |
| `FULL` | 2 | 1 | 2 |

- **Точки.** `*`: значение — `folderAccess[<id домена>].cam`, если есть, иначе `global.dCam`. Двух строк одного яруса от корня и
  от умолчания нет: ярус 4 взял бы из них наибольшее. `folder:F` — ключ `folderAccess` с полем `cam`. Если у корня задано
  значение, каждая папка первого уровня без своего значения получает строки корня: у consolem корень — звено каждой цепочки.
  `unit:cam/<id>` — ключ `objectAccess` камеры. `dCam`, `dArch` без значения — `FORBID` (поля необязательны в схеме).
- **Где лежит строка.** `*` и `folder:F` — поле `lines` строки роли домена (P/08.4 Н1.3а; ADR-0111 п. 16): источник на весь домен, кластеры и новый член получают их проходом держателя, отдельной рассылки нет. `unit:cam/<id>` — только грант кластера этой камеры: `id` камеры в другом кластере — другая единица, кластер и `id` дают обратный путь главы 4 Н1.6; в `lines` таких строк нет, проход их не трогает.
- **Строка на подсистему.** В каждой точке пишется строка `role:<имя>` на каждую из `cam`, `live`, `rec`, `det`, `detjob`, `detedge`, в том числе
  `none`: пустой ярус отдал бы решение более общему, а `detjob` и `detedge` наследуют цепочки камеры (`about`). `det`, `detjob`, `detedge` — `none`, пока
  функция не поднимет их: какие уровни показывают детекторы, спрошено у продукта (ADR-0097, «Запрос продукту» п. 3); это сужение.
- **Пара `MON` и `ONLY_ARCHIVE`** (ADR-0112) — `reference.access.joins`: вместе дают `ARCHIVE`, между папками одной роли и между ролями. Перевод тот же: ранги складываются по подсистемам, отказа нет. `MON_PROT` в пару не входит: уровень не переводится (Н1.6).
- **Функции** действуют только там, где уровень даёт что-то в этой подсистеме, это сужение до ответа продукта (ADR-0099 §7, файл решений, разбор ревью V/11, п. 3):

| `feat` | Условие в точке | Что меняет |
|---|---|---|
| `DEVICES_SETUP` | `cam` ≥ 1 | `cam` — `admin` |
| `ARCHIVES_SETUP` | `rec` ≥ 1 | `rec` — `admin`; правка через `backend` — ещё `admin` на `cam` (ниже) |
| `DETECTORS_SETUP` | уровень `cam` не `FORBID` | `det`, `detjob`, `detedge` — `admin`; отступление с причиной: ранг этих подсистем всегда 0, условие по подсистеме функцию убило бы; правка через `backend` — ещё `admin` на `cam` (ниже) |
| `EDIT_PTZ_PRESETS` | `cam` ≥ 1 | `cam` — не ниже `edit` |

- **Правка детектора и архива** идёт строкой-якорем `cam/cameras/<id>` (глава 4 Н1.2) и требует `admin` на `cam`; особого права нет. Роль с `DETECTORS_SETUP`, `ARCHIVES_SETUP` без `DEVICES_SETUP` на такой правке получает 403 `PERMISSION_DENIED`.

- **`arch`** (ADR-0099 §7, А4). `arch` есть только в точке `*`: значение — поле `arch` корня, если есть, иначе `dArch`. `FULL` даёт `view` на `*` в `rec`, только
  если уровень `cam` в точке `*` даёт `rec` ≥ 1. Иначе `arch` не переводится, строки не даёт и отказа нет: это сужение, шаблон
  «Оператор» (`dCam: MON`, `dArch: FULL`) применяется. Поэтому `dArch: FULL` не открывает записи всех камер при `dCam: MON`.
- **Экономия.** Строка точки `folder:F` не пишется, если равна строке ближайшей папки-предка с заданным значением. Относительно
  `*` строка не опускается: цепочка без строки `folder:` в ярус 3 ничего не даёт.
- **Встроенная роль** — `unr: true` только у роли `admin`, её строк в грантах нет, назначения — `assigned` (ADR-0100 §4).
- **Управляющий.** `USERS_RIGHTS_SETUP` с `ur: ALL` — строка `role:<имя> admin *` в `domain/grants/domain`.
- **`sub: platform`** перевод не пишет: ведение папок (ADR-0097, «Запрос продукту» п. 1), `<sub>/policy` и снимки настроек (ADR-0094 доп. (12) п. 11) остаются у встроенной
  роли; иному человеку такие двери отказывают, запись настройки — 422 `NOT_SUPPORTED`. Ассистент — `view` на строку модели `assist`, только у встроенной роли (там же).

### Н1.4 Уровни из строк

Чтение обратно перевода Н1.3 и идёт по точкам источника (Н1.10):

- **Ранг подсистемы в точке.** Экономия Н1.3 снимает строку, равную строке предка, поэтому нет строки подсистемы в `folder:F` — ранг берётся у
  ближайшей папки-предка с такой строкой, такой нет — ранг `0`. Точка без единой строки значения не имеет.
- Уровень точки по рангам `live` и `rec`: `(0, 0)` — `FORBID`, `(0, 1+)` — `ONLY_ARCHIVE`, `(1, 0)` — `MON`, `(1, 1)` — `ARCHIVE`,
  `(1, 2)` — `ARCH_MANAGE`, а при `cam` ≥ `edit` и `(1, admin)` с `cam` ≥ `edit` — `FULL`; `(1, admin)` иначе — `ARCHIVE`.
- Разные сочетания уровня и функций с одними строками читаются одним: `ARCHIVE` и `ARCH_MANAGE` с `ARCHIVES_SETUP`, `ARCH_MANAGE` с
  `EDIT_PTZ_PRESETS` и `FULL`. Строки у них одни, права не меняются; экран показывает прочитанное.
- Точка `*` — `global.dCam`; ключа корня в `folderAccess` чтение не даёт. `folder:F` и `unit:cam/<id>` — как есть, скопированные
  значения корня тоже: при пересохранении они дают те же строки.
- `feat`: `DEVICES_SETUP` — есть `admin` в `cam`; `ARCHIVES_SETUP` — `admin` в `rec`; `DETECTORS_SETUP` — `admin` в `det`;
  `EDIT_PTZ_PRESETS` — `cam` = `edit` в точке, уровень которой не `FULL`; `USERS_RIGHTS_SETUP` и `ur: ALL` — строка управляющего,
  иначе `ur: NO`.
- `dArch` — `FULL`, если ранг `rec` на `*` не меньше `view`, иначе `FORBID`. Значение, которое не стало строкой (Н1.3 `arch`),
  обратно не приходит: шаблон «Оператор» читается с `dArch: FORBID`.
- `dArch` не обратим: `FORBID` при ранге `rec` ≥ 1 читается `FULL`, значение от него не зависит (строк `arch` сверх `cam` нет).
- Прочие поля `global` — значения `reference.access`: `unr` — Н1.3, `map`, `alert`, `dMic`, `dSpk`, `dSens`, `dRelay`, `dPos`, `dMacro`,
  `dAcfa`, `dVw`, `dPlug` — `FORBID`, `dTel` — `NO`, `depth` — `0`, `restr` — `{}`.
- `bm` — `CREATE`, если ранг `cam` на `*` не меньше `edit`, иначе `NO`: право отметки у нас — `edit` на камеру (P/06.4 Н2, глава 4 Н1.24), своей строки нет. Не обратим, как `dArch`: значение, которое не стало строкой, обратно не приходит. **Предел:** `view` отметку не ставит, `PROTECT`, `EDIT` предмета не имеют.
- **Чужая строка** снимка не меняет и сохраняется как есть (Н1.5 «Разница»), в том числе у изменённой роли: строка, какой перевод не пишет (`labels:`, иная
  `sub`, срок `until`), и строка с областью без живого объекта — удалённая папка (ADR-0097 §5), удалённая камера. Иначе её ключ вернулся бы в черновик и
  запер `apply`: объекта на экране нет. Живость судится по чтениям Н1.1 с фильтром `view`: объект, которого читатель не видит, идёт наравне с удалённым:
  ключа в снимке нет, строка сохраняется, права не сужаются.

Перевод обратим на строках: разбор Н1.3 снимка, собранного по Н1.4, даёт те же строки (все пары «предок, потомок» и наборы функций сверены перебором).

### Н1.5 Применение

`POST /access/apply` — по порядку:

1. Тело не по схеме контракта — 422 `VALIDATION_FAILED`, `field` (глава 4 Н1.3), нет `version`, `changes` — тоже: версия идёт в теле, `If-Match` у двери нет. Снимок читается целиком (Н1.1); `version` не та — 412 `VERSION_MISMATCH`, `current`.
1а. **Черновик** — снимок, к которому `changes` приложены по порядку; дальше он судится как целый (ADR-0112 доп. (10)). `kind`: `role`, `user`, `group` — `set` запись целиком, новая или прежняя, `delete` — снять; у `role` `set` `objectAccess` берётся из снимка, `objectAccessCount`, `spread` не судятся. `roleObject` — `id` роль, `value {objectId, levels}`: ключ `objectAccess`, `levels: null` снимает. `streamGrants` — `id: grants`, `value {grants}`, список целиком (Н1.11). `catalog` — Н1.6. `delete` чего нет, `value` не того вида, `roleObject` роли, которой нет, — 422 `VALIDATION_FAILED`, `field: changes[i]`. Чего нет в `changes`, то не меняется и не судится.
2. **Проверки черновика** — без обращений к записям, первое нарушение отвечает:
   - судятся только созданные и изменённые относительно снимка записи: прежнюю запись правкой не поправить, а строки мимо `backend` бывают и без `title`, и с
     повтором;
   - пустое имя — 422 `NAME_REQUIRED`, `field: name`, `login`; повтор без учёта регистра и крайних пробелов — 409 `NAME_TAKEN` (роль,
     группа), 409 `LOGIN_TAKEN` (человек), поле: судится у созданной записи и у записи с новым именем, иначе дубль мимо `backend` запер бы правку
     роли человека; повтор `id` — 422 `VALIDATION_FAILED`, `field: id`;
   - ссылка никуда: `roleIds`, ключи `roleUntil`, `memberIds`, `UserGroup.roleIds`, `supervision.roleId` — 422 `VALIDATION_FAILED`, это поле;
   - у роли `admin` меняются только назначения: иное имя, `comment`, удаление — 409 `BUILTIN`;
   - непереводимое — Н1.6;
   - самоблокировка — Н1.8.
3. `dryRun: true` — 200 `{applied: false, access: null}`, `ETag` прежний. Пакета домена нет: его проверки (пп. 4–5) `dryRun` не судит.
4. **Разница.** Строка черновика сравнивается со снимком этой `version`; `roleIds`, `memberIds`, `UserGroup.roleIds` — как множества, порядок не судится, ответ `apply` отдаёт порядок снимка; `apply` не удаляет молча:
   - роль, группа, человек, которых нет в снимке, — создание; которые есть в снимке, но нет в черновике, — явное удаление
     (`op: delete` снимка этой версии); записи вне снимка быть не может: снимок покрывает весь домен;
   - права изменившейся роли — новые `lines`: перевод Н1.3 без `unit:` и чужие строки источника (Н1.4), кроме `unit:`, в форме `{cap, sub?, scope, until}`. Правка роли снимает её расхождение: `lines` новее строк кластера (P/08.4 Н3 «расхождение роли»);
   - строки `unit:` — на каждый кластер снимка отдельно: строки роли, чей вид в черновике не изменился, и чужие строки (Н1.4) — как прочитаны в этом кластере, без поля `by`: его ставит дверь;
     прочие заменяются переводом Н1.3; итог совпал с прочитанным — кластер не пишется; строки удалённой роли, чужие тоже, в запись `grants` не идут: их снимает каскад `op: delete`
     (P/08.4 Н2);
   - у администратора кластера (Н1.10) `lines` нет: вся разница прав изменившейся роли — строки его кластеров снимка, тем же порядком;
   - `domain/grants/domain` входит в пакет, только если изменилась строка управляющего.
5. **Пакет домена** — `POST /domain/batch`: разница людей, групп, ролей и строки `domain`, снимок целиком двери не идёт (файл решений, разбор ревью V/11, п. 4); `cas` каждой записи — индекс снимка;
   `kind: grants`, `name` — только `domain`; у роли `admin` `fields` несёт только `assigned`. Итог пакета домен считает по своему состоянию и разнице.
   Разница пуста, у `lines` и кластеров тоже, — записей нет: ни пакета (пустой дверь отвергает, `400 bad batch`), ни строк Н1.7. Суд права над `apply` — только двери записи (Н1.9): без него человек
   только с `view` писал бы историю и сдвигал версию всем. Ответ — 200 `{applied: true, access}` по снимку шага 1, `ETag` прежний.
   `Idempotency-Key` — hex SHA-256 от байтов `user`, нулевого байта, значения `version`, нулевого байта и SHA-256 тела: воркер повторяет
   те же байты пакета в том же проходе после потери ответа. Повтор клиента до пакета не доходит: первый успех сдвинул версию, шаг 1 отвечает 412 с `current`.
5а. **Права** (ADR-0110 доп. (5) п. 2, ADR-0111 пп. 12, 16). После пакета домена — групповая операция, отказ одной записи не откатывает прочие и не останавливает следующие. Сначала строки кластеров: по одному `POST /domain/batch` на кластер с разницей, по порядку имён в байтах UTF-8, одна запись `kind: grants`, `name` — кластер, `cas` — индекс снимка, строки нет — `""`. Затем `PUT /domain/roles/<имя>/lines` `{lines}` на каждую роль с разницей, по порядку имён, `If-Match: "<индекс снимка>"`; роль была в пакете домена — без условия: `cas` её уже сверил. Порядок важен: запись строк кластера позже `lines` дала бы кластеру слово `local`, и проход его пропустил бы. Итог на кластер считает проход, `role_spread` вида (Н1.10). Срок маршрута `api/access` вышел — оставшиеся записи не сделаны, это их отказ. Отказ записи — строка истории `actor: система`, `text` — `права роли «<имя>» не применены: <код>` или `права на кластере <кластер> не применены: <код>` (Н1.7). `Idempotency-Key` — как п. 5, с именем кластера или роли и нулевым байтом перед байтами `user`.
   **Итог.** `clusters` — сколько кластеров задела правка: есть запись `lines` — все кластеры снимка, иначе сколько пакетов кластера; записей нет — `0`. `notApplied` — отказ записи кластера: `{cluster, serverId?, code}`, `serverId` — первая по имени запись `Server` этого кластера, если видна; отказ `lines`: запись одна на домен, кластера у неё нет, поэтому `{cluster: <кластер входа>, roleId, code}`. `code` — слово Н4. Пусто — поля нет. Итог прохода держателя здесь не виден: он приходит в `RoleRow.spread` со следующим чтением.
   **`retryClusters`** — повтор расхода, `changes` могут быть пусты: имя вне кластеров снимка — 422 `VALIDATION_FAILED`, `field: retryClusters`. На каждый кластер, по порядку имён, тот же `POST /domain/batch` одной записью `kind: grants`: строки ролей с `lines` приводятся к `lines`, прочие и `unit:` как прочитаны; не разошлось — кластер не пишется. Отказ — как выше. Посылает только эти кластеры: новая запись `lines` тронула бы и правленные на месте.
   Не легла ни одна запись и пакета домена не было — ответ первого отказа по Н4, ничего не записано.
6. **Пароль.** `password` черновика — поле `password` записи `kind: user` пакета домена, новому человеку и при смене; в строки, историю и журналы воркера не попадает, в ответе его нет. `hasPassword`, `passwordByAdmin` черновика не берутся. Короче `PASSWORD_MIN` — 422 `PASSWORD_POLICY`, `field: password`, `params.id` — человек, судится до пакета и при `dryRun`; `bad password` двери — то же. Новый человек без `password`: `fields` несёт случайный пароль 256 бит hex, значение нигде не сохраняется и не отдаётся, войти он не может, пока пароль не задан: `hasPassword` при этом `true`, предел. Назначение `admin` человеку с чужим паролем судит только запись: `409 password set by a non-admin` — 409 `PASSWORD_NOT_ADMIN`, `field: roleIds`, `params.id` — человек, добавленный этой записью; `dryRun` этого не видит.
   Пароль через `backend` поднимает тревогу `domain.rights_via_backend`, как всякая такая правка (Н1.9).
7. После пакета — строки истории Н1.7. Ответ — 200 `{applied: true, access}`: снимок читается заново, `ETag` — его версия.

`412 conflict` пакета домена значит «снимок устарел»: 412 `VERSION_MISMATCH`, `current` — снимок, прочитанный заново (P/08.4 Н2 `repeat`); у записи п. 5а это отказ этой записи.

### Н1.6 Что `apply` не переводит

Отказ — 422 `NOT_SUPPORTED`, `field` — путь поля:

| Значение | Почему |
|---|---|
| `catalogs` не пусто, `UserGroup.source` не `null`, `AccessUser.catalogId` не `null` | каталогов нет (ADR-0098 §8) |
| новый человек с `enabled: false` (`field: enabled`) | поля `disabled` у `POST /domain/users` нет |
| иной `login` при том же `id` (`field: login`), тот же `login` при новом `id` (`field: id`) | Н1.2 |
| `loginSchedule` ≠ 0, `supervision` не по умолчанию, `webSessions`, `mobileSessions` ≠ 0 | ADR-0098 §7 |
| уровень `MON_PROT` | нет предмета (ADR-0111 п. 21) |
| в `global`: `bm` иной, чем вывод выше; `depth`, `restr`, `map`, `alert`, `dTel`, `dMic`, `dSpk`, `dSens`, `dRelay`, `dPos`, `dMacro`, `dAcfa`, `dVw`, `dPlug` не по умолчанию | нет предмета (ADR-0097 §7, ADR-0111 п. 21) |
| `feat` вне перечня Н1.3 и `USERS_RIGHTS_SETUP`, в том числе `PROGRAMMING_SETUP` | права автоматизации — гранты строк `auto` (`cluster_rows`), функции роли нет |
| `unr: true` у роли не `admin`, `unr: false` у `admin` | ADR-0100 §4 |
| `USERS_RIGHTS_SETUP` при `ur` не `ALL`; `ur: ALL` без неё; `ur: DEV` | ADR-0100 §4 |
| поле `folderAccess`, `objectAccess` не `cam` (у корня — ещё `arch`) | виды без подсистемы |
| новый ключ `objectAccess` не камера: хранилище, детектор, `vw:`, `macro:`, `plug:` | у тома нет единицы, А4 |
| новый ключ `folderAccess` не папка и не домен | 422 `VALIDATION_FAILED`, `field: folderAccess` |

Ограничение: `cas` пакета держит только изменённые строки, поэтому Н1.6 и Н1.8 судят прочитанное. Инвариант «остаётся администратор» держит платформа (Н1.8).

### Н1.7 История

`GET /access/history`, `/access/cell-history` — строки таблицы `backend/history/<id>`, `history`, `cellHistory` тела `apply` — новые строки, время и автора ставит `backend`: `kind` — `history` | `cell`, `when`, `entry`. Журнал
платформы ведётся своим чередом (`domain.*`, `via: backend/<экземпляр>`): эта таблица только показывает историю экрана.

- Строки ложатся пакетом `POST /console/batch` **после** пакета домена; пакета не было (пустая разница, Н1.5 п. 5) — строк нет: `id` — случайный UUID, `when` — часы ответа `GET /session`,
  `actor` — `user` билета, у строки отказа п. 5а — `система`. Сбой этой записи ответа не меняет: права уже записаны, истину хранит журнал, причина — в журнал воркера.
- Читается новыми сверху, `HISTORY_READ_MAX` = 1000 новейших строк: иначе снимок перерос бы предел ответа передачи 4 МиБ; срок — `delete_after` таблицы, 90 суток.
- В этом же пакете, первыми, — строки `people` новых и удалённых людей (Н1.2): каждая отвечает записи пакета домена, тех не больше 63, и
  `BATCH_WRITES` их вмещает. Записей истории в теле больше, чем остаётся места, — лишние не пишутся, отказа нет.

### Н1.8 Самоблокировка

`SELF_LOCKOUT` проверяет `backend` поверх платформы (ADR-0100 §4), по итоговому состоянию черновика. 409 `SELF_LOCKOUT`, если:

- у роли `admin` нет ни одного включённого назначения без истёкшего срока, прямого или через группу;
- человек запроса снимает с себя роль `admin` (прямо или через группу), выключает или удаляет себя, ставит себе прошедший `expiresDate` или прошедший срок
  своего назначения `admin`: контракт велит не лишать вас входа.

Инвариант «остаётся администратор» держит платформа: `409 last admin` пакета домена — тоже `SELF_LOCKOUT`. Проверка `backend` нужна
для `dryRun` и для снятия самого себя при втором администраторе, которого платформа разрешает.

### Н1.9 Кто применяет

Запись судит процесс `domain`, пакет — по строке (P/08.4 Н2 «Пакетная дверь»): `kind: grants` кластера — `admin` на `*` этого кластера, люди, группы, роли, `lines`, строка `domain` — администратор домена или управляющий (`batch_diff`, P/08.4 Н1.3в). Отказ `403 admin only` —
403 `PERMISSION_DENIED`, ничего не записано. Каждая правка класса «admin only» через `backend` поднимает тревогу
`domain.rights_via_backend` на стороне домена (ADR-0094 доп. (12) п. 10): `backend` сам её не шлёт.

Вход — через `backend` любого кластера: `need` передачи — грант в любом кластере домена, вход `anywhere` ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md) `need`; ADR-0110 Д-8).
Предел: управляющий доходит до `backend` положительной строкой гранта какого-нибудь кластера, своей или своей роли: строка управляющего лежит в `domain/grants/domain`, в `anywhere` не идёт и прав в кластерах не даёт
(P/08.4 Н1.3, Н1.3в). Все строки кластеров `none` (Н1.3) — 403 `PERMISSION_DENIED` консоли до воркера: ни `GET /access`, ни `apply` такому человеку недоступны.

Приём и исключение члена меняют состав домена: их судит `admin` домена, а не грант кластера (ADR-0110 доп. (6), ADR-0111 п. 17); двери — глава 4 Н1.14.

### Н1.10 Снимок домена

- **Кластеры снимка** — ключи `grants` ответа `GET /domain/grants`, кроме `domain`: кто не зритель домена, получает только кластеры, где у него `admin` на `*` (P/10 Н1.2д), чужого кластера в снимке нет. Есть ключ `domain` — ещё `members` `GET /domain` без своей строки: новый член, индекс `""`, строк нет; 403 этой двери — только ключи.
- **Источник значений.** Снимок несёт одно значение поля. Зрителю домена `global` и `folderAccess` читаются из `lines` роли: они новее строк кластера, ответ `apply` их уже показывает. Роль без `lines` — кластерная, как и у незрителя: строки кластера чтения; это свой кластер, если он в снимке, иначе наименьшее имя в байтах UTF-8. `objectAccess` — объединение кластеров снимка: ключ — id камеры своего кластера (глава 4 Н1.6). Папки — `GET /domain/folders`, id один на всех.
- **Камеры других кластеров.** Живость — `GET /domain/cam/tables/cameras?cluster=<кластер>`, только у кластеров со строками `unit:cam/` и `class: server`; у камеры-кластера — `GET /domain/cam/cameras?cluster=<кластер>` (ADR-0113 доп. (8) п. 1). 404 `not reported yet`, 503, отказ пересылки — камер кластера не видно, как в Н1.4: ключа нет, строка сохраняется, права не сужаются.
- **Расхождение видно** (ADR-0110 доп. (5) п. 2). Итог на кластер — `role_spread` `GET /domain` (P/08.4 Н3 «расхождение роли»). Каждая пара роль, кластер — элемент `RoleRow.spread` `{cluster, state, at}`, `at` — `at` строки роли; пара `local` при строках без `unit:`, равных `lines`, элемента не даёт. На каждую пару в начале первой страницы `GET /access/history`, по кластеру и ключу роли, запись `{id, at, actor: "система", text, roleId}`: `text` — `права роли «<имя>» на кластере <кластер> ` и `правлены на месте` (`local`), `ещё не дошли` (`pending`), `не применены` (`refused`); `at` — `at` строки роли, `id` — UUID v5 `accessNote:<кластер>/<ключ роли>`. `local` при строках без `unit:`, равных `lines`, записи не даёт: так помечает кластер запись `unit:`. Запись считается при чтении и не хранится: сошлись строки — её нет. Наблюдение, не настройка: версию снимка не двигает. Незрителю поля нет, записей нет: предел.
- **Правка на кластере** судится как обычно: дверь гранта этого кластера, последнее слово по времени записи (ADR-0111 п. 16): правка новее `lines` — кластер остаётся как есть, слово `local`; `lines` новее — проход перезаписывает, строки `unit:` остаются.
- **Администратор кластера** — `admin` на `*` в кластере без права на `domain/grants/domain`: ключа `domain` в снимке нет. Читает снимок своих кластеров. `apply` разбит по строкам: разница только в правах ролей — строки его кластеров снимка, пакетом на кластер (Н1.5 п. 5а), слово `local`; люди, группы, имена, `assigned`, новая или удалённая роль — 403 `PERMISSION_DENIED`, ничего не записано: пакет домена идёт первым, а они — зрителю домена. Дерево папок он не правит (P/08.5 Н1.8 `rights`), состав правит: в ответе — глава 4 Н1.7, на чтении — запись `система` в начале `GET /access/history`: `text` — `дерево папок правит администратор домена`, `at` — `at` строки роли `admin`, `id` — UUID v5 `accessNote:folders`.

### Н1.11 Учётки потоков

`Access.streamGrants` (ADR-0112) — строки грантов с `subject` = имя учётки (V/03.6 Н1.3), не роли: только складываются, исключений нет. Форма строки: `{subject, cap: view, sub: live, scope}`, шире `view` дверь не даёт (`names.stream-accounts/.grant`, P/08.5 Н1.7).

- **Чтение.** На учётку из `GET /live/accounts`, у которой есть строки в кластерах снимка: `all` — строка `*` в каждом кластере снимка `class: server`, `deviceIds` — строки `unit:cam/<id>`, id — глава 4 Н1.6, `folderIds` — строки `folder:<id>` живых папок (V/03.6 Н1.4). Чего запись не примет, чтение не показывает: строка снятой папки, снятой камеры, камеры-кластера — чужая строка (Н1.4), снимок её не показывает и не снимает, доступа она не даёт. Учётки без строк в списке нет. Дверь шлюза не ответила — поля `streamGrants` нет: запись без поля список не меняет. Версия снимка берёт строки грантов, а не ответ шлюза: мигание шлюза черновики не сбивает. Прочие строки учётки, метки, `*` не во всех таких кластерах, — чужие строки (Н1.4): снимок не меняют и сохраняются.
- **Запись.** Нет поля — не меняется. Поле — список целиком. Учётка не из `GET /live/accounts`, повтор учётки, `deviceIds` не камера, камера вне кластеров снимка или камеры-кластера, там шлюза нет, — 422 `VALIDATION_FAILED`, `field: streamGrants`, `folderIds` — неизвестная папка, тот же отказ; дверь шлюза судится первой. Разница — строки кластеров снимка: снимается только показанное снимком: учётка без элемента теряет `unit:cam/`, `folder:`, а `*` — только если снимок показывал `all: true`: прочие `*` — чужие строки; `all` — строка `*` в каждом кластере снимка `class: server`; `folderIds` — строки `folder:<id>` в каждом таком кластере. Дверь шлюза не ответила — 503 `UPSTREAM_UNAVAILABLE`, `dryRun` тоже. Запись — Н1.5 п. 5а, пакетом на кластер, `unknown subject` — 422 `VALIDATION_FAILED`, `field: streamGrants`.
- **Снятие.** Учётка снята: элемента нет, строки снимает сверка домена по субъекту (V/03.6 Н1.3); снятая камера и папка — чужие строки выше.
- **Пределы.** `all`, `folderIds` — строки только в кластерах снимка `class: server`: шлюзы есть только там, на всех членах это 250 000 записей; новый сервер строк не получает, пока снимок не применят заново (ADR-0112 доп. (7) п. 3).

## Н2 Двери

Своей двери у главы нет: `GET /access`, `POST /access/apply` — операции контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
GET /access
  двери домена, /domain/folders, /cam/cameras, таблицы people, history по билету; отказ чтения → отказ запроса (403 камер — видимых камер нет)
  кластеры снимка, источник значений (Н1.10); люди, группы, роли → виды контракта; строки role:<имя> → уровни (Н1.4); записи система; версия снимка → ETag
POST /access/apply
  тело не по схеме, нет version → 422; снимок; версия не та → 412, current; черновик из changes
  проверки черновика: имена, ссылки, непереводимое, пароль, учётки потоков, самоблокировка
  dryRun → 200 applied: false
  разница пуста → 200 applied: true, ETag прежний, записей нет
  разница людей, групп, ролей → POST /domain/batch (cas снимка, Idempotency-Key)
    412 conflict → 412 current; 409 last admin → SELF_LOCKOUT; иной отказ → Н4
  на кластер с разницей → POST /domain/batch (grants кластера); на роль с разницей → PUT /domain/roles/<имя>/lines: отказ — строка истории система, следующая запись; не легло ничего → первый отказ
  строки истории и people новых и удалённых людей → снимок заново → 200 applied: true, ETag
```

## Н5 Приёмка

Тесты API consolem `tests/api-access.js` на закреплённом коммите в профиле (глава 6): применение, `dryRun`, повторы имён, ссылки; набор `one-domain`
невыразим целиком: его роли несут непереводимые значения, тест идёт против своего набора (глава 6 Н1.3).

Н1.8, 428, 412, пустая разница, отказы домена. Тест самоблокировки и тест `catalogs` — вне профиля: `unr: false` у `admin` отвечает `NOT_SUPPORTED`
раньше (Н1.5 п. 2), каталогов нет. Перевод уровней сверх `acceptance/8/` — чтением.
