# V/11.8 — Права: нормы

Канон главы 8 урока V/11 «Бэкенд конфигуратора» (ADR-0097 §7, ADR-0098 §7, ADR-0099 §7, ADR-0100 §4; ADR-0094 доп. (11), (12)
п. 11). [Лекция](../11-backend.md), [инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../consolem.openapi.json).
Платформа — выгрузка `cammeta-specs` `fb57c112` (пин V/11: приращение прав, ADR-0095–ADR-0100).

Права consolem — снимок целиком: роли с уровнями по полям, люди, группы, каталоги. Права платформы — роли и группы домена и
строки грантов кластера (P/08.4 Н1.3а, договор `may`). Перевод снимка идёт в обе стороны: `GET /access` собирает снимок из
строк, `POST /access/apply` разбирает черновик обратно и пишет разницу одним пакетом домена. Своих прав у `backend` нет:
двери домена судят самого человека билета (P/06.3 Н1.9 «Двери домена»).

Id норм — `V/11.8-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Снимок** — схема `Access` контракта.
- **Черновик** — поле `access` тела `POST /access/apply`, схема `AccessWrite`.
- **Точка роли** — одно место consolem с одним значением поля: `*`, `folder:F`, `unit:cam/<id>` (Н1.3).
- **Уровень** — значение поля `cam` или `arch` из `reference.access.levels`.

## Н1 Форма

**Время.** Поля `expiresDate`, `roleUntil`, `rolesUntil` — даты в часовом поясе `timezone` ответа `GET /session`. Дата `D`
пишется концом дня: `expires`, `until` — стенные секунды полуночи дня, следующего за `D`, в этом поясе; обратно —
дата секунды `expires − 1`. `until = 0` и `expires = 0` — без срока, поле или ключ отсутствует, `null` у `expiresDate`,
`rolesUntil`.

**Данные.** Строки людей, групп, ролей и грантов — двери домена по билету (V/11.1 Н1.5). Своих семей две: таблицы манифеста
`backend/people/<h>` (Н1.2) и `backend/history/<id>` (Н1.7), обе `service: true`.

### Н1.1 Сборка снимка

`GET /access` читает `GET /domain/users`, `/domain/groups`, `/domain/roles`, `/domain/grants`, `GET /folders`, таблицы `people` и
`history`. Отказ двери домена (403 — нет `view` на `domain/grants/domain`) — отказ запроса: снимок частями не отдаётся.

| Вид | Поля | Откуда |
|---|---|---|
| `AccessUser` | `login`, `name`, `email`, `enabled` | `name`, `title`, `email` (нет у читателя — `""`), не `disabled` строки человека |
| | `id` | Н1.2 |
| | `roleIds`, `roleUntil` | элементы `{person}` поля `assigned` ролей; ключ `roleUntil` — только при `until ≠ 0` |
| | `expiresDate` | `expires` |
| | `lastLoginDate`, `catalogId` | `null` |
| | `webSessions`, `mobileSessions` | `0` |
| | `createdDate`, `syncedGroupId` | поля нет (ADR-0098 §7) |
| `UserGroup` | `id`, `name`, `comment` | Н1.2; `title`, при пустом — ключ строки; `comment` |
| | `memberIds` | `members`, переведённые в `id` людей |
| | `roleIds`, `rolesUntil` | элементы `{group}` ролей; `rolesUntil` — наименьшая дата по действующим назначениям группы, бессрочное в счёт не идёт |
| | `source` | `null` |
| `Role` | `id`, `name`, `comment` | Н1.2; `title`, при пустом — ключ строки, у роли `admin` — слово `Администратор`; `comment` |
| | `global`, `folderAccess`, `objectAccess` | строки `role:<имя>` гранта кластера — Н1.4 |
| | `loginSchedule`, `supervision` | `0`, `{roleId: null, login: false, export: false}` |
| `Access` | `catalogs` | `[]` |
| | `history`, `cellHistory` | Н1.7 |

`rolesUntil` обратно — наименьшая дата: снимок пишет одну дату на все роли группы, поэтому при пересохранении она только сужает.

**Версия снимка** — `a` и hex SHA-256 от строк `<вид> <имя> <индекс>\n` по байтам: вид — `user`, `group`, `role`, `grants`
(индекс строки кластера и строки `domain`), `history` (читаемые строки), `people` (только живых людей: строка без человека снимка не
меняет), `folder`. Индекс — `index` элемента перечня, у грантов — `versions` ответа двери. Папки входят: от них зависят `folderAccess`. `ETag` — эта версия в кавычках.

Снимок покрывает всех людей, группы и роли домена, а права ролей — только этого кластера (ADR-0098 §7). Поэтому `apply`
меняет только разницу и ничего не удаляет молча (Н1.5).

### Н1.2 Id людей, групп, ролей

- **Роль и группа.** Ключ строки домена — `id` consolem как есть: новая запись снимка пишется с `name` = `id` (ADR-0098 §7).
  Строка с иным `name` — встроенная `admin` и записи, заведённые мимо `backend`, — получает UUID v5 от `role:<имя>`,
  `group:<имя>` (глава 4 Н1.6).
- **Человек.** Имя человека — его вход, поэтому `id` не может быть ключом. `id` — поле строки `backend/people/<h>`, `h` — hex SHA-256
  имени: имя `.` или `..` ключом таблицы быть не может; строки нет — UUID
  v5 от `user:<имя>`, как `Me.userId` (глава 3 Н1.2). `GET /me` читает ту же строку: иначе `userId` разошёлся бы со снимком.
- Новый человек с `id` клиента: строка `people` ложится **после** пакета домена, вместе со строками истории (Н1.7), поверх прежней — `cas`
  её индекса. Запись идёт правом следствий, поэтому раньше суда домена её быть не может: человек только с `view` писал бы таблицу и
  сдвигал версию всем. Обрыв между пакетом и этой записью оставляет человека с `id` v5 до следующей правки: окно признано.
- **`login` неизменен:** переименования человека у платформы нет. Иной `login` при том же `id` — 422 `NOT_SUPPORTED`, `field: login`.

### Н1.3 Строки роли из уровней

Перевод уровня `cam` по подсистемам вида — `(cam, live, rec)`, ранги `0` — `none`, `1` — `view`, `2` — `edit`:

| Уровень | `cam` | `live` | `rec` |
|---|---|---|---|
| `FORBID` | 0 | 0 | 0 |
| `ONLY_ARCHIVE` | 1 | 0 | 1 |
| `MON` | 1 | 1 | 0 |
| `ARCHIVE` | 1 | 1 | 1 |
| `ARCH_MANAGE` | 1 | 1 | 2 |
| `FULL` | 2 | 1 | 2 |

- **Точки.** `*`: значение — `folderAccess[<id домена>].cam`, если есть, иначе `global.dCam`. Двух строк одного яруса от корня и
  от умолчания нет: ярус 4 взял бы из них наибольшее. `folder:F` — ключ `folderAccess` с полем `cam`. Если у корня задано
  значение, каждая папка первого уровня без своего значения получает строки корня: у consolem корень — звено каждой цепочки.
  `unit:cam/<id>` — ключ `objectAccess` камеры. `dCam`, `dArch` без значения — `FORBID` (поля необязательны в схеме).
- **Строка на подсистему.** В каждой точке пишется строка `role:<имя>` на каждую из `cam`, `live`, `rec`, `det`, `detjob`, `detedge`, в том числе
  `none`: пустой ярус отдал бы решение более общему, а `detjob` и `detedge` наследуют цепочки камеры (`about`). `det`, `detjob`, `detedge` — `none`, пока
  функция не поднимет их: какие уровни показывают детекторы, спрошено у продукта (ADR-0097, «Запрос продукту» п. 3); это сужение.
- **Функции** действуют только там, где уровень даёт что-то в этой подсистеме, это сужение до ответа продукта (ADR-0099 §7, файл решений, разбор ревью V/11, п. 3):

| `feat` | Условие в точке | Что меняет |
|---|---|---|
| `DEVICES_SETUP` | `cam` ≥ 1 | `cam` — `admin` |
| `ARCHIVES_SETUP` | `rec` ≥ 1 | `rec` — `admin` |
| `DETECTORS_SETUP` | уровень `cam` не `FORBID` | `det`, `detjob`, `detedge` — `admin`; отступление с причиной: ранг этих подсистем всегда 0, условие по подсистеме функцию убило бы |
| `EDIT_PTZ_PRESETS` | `cam` ≥ 1 | `cam` — не ниже `edit` |

- **`arch`** (ADR-0099 §7, А4). `arch` есть только в точке `*`: `dArch`, поле `arch` корня. `FULL` даёт `view` на `*` в `rec`, только
  если уровень `cam` в точке `*` даёт `rec` ≥ 1. Иначе `arch` не переводится, строки не даёт и отказа нет: это сужение, шаблон
  «Оператор» (`dCam: MON`, `dArch: FULL`) применяется. Поэтому `dArch: FULL` не открывает записи всех камер при `dCam: MON`.
- **Экономия.** Строка точки `folder:F` не пишется, если равна строке ближайшей папки-предка с заданным значением. Относительно
  `*` строка не опускается: цепочка без строки `folder:` в ярус 3 ничего не даёт.
- **Встроенная роль** — `unr: true` только у роли `admin`, её строк в грантах нет, назначения — `assigned` (ADR-0100 §4).
- **Управляющий.** `USERS_RIGHTS_SETUP` с `ur: ALL` — строка `role:<имя> admin *` в `domain/grants/domain`.
- **`sub: platform`** перевод не пишет: ведение папок (ADR-0097, «Запрос продукту» п. 1), `<sub>/policy` и снимки настроек (ADR-0094 доп. (12) п. 11) остаются у встроенной
  роли; иному человеку такие двери отказывают, запись настройки — 422 `NOT_SUPPORTED`. Ассистент — `view` на строку модели `assist`, до третьего запроса — только у встроенной роли (там же).

### Н1.4 Уровни из строк

Чтение обратно перевода Н1.3 и идёт по точкам:

- **Ранг подсистемы в точке.** Экономия Н1.3 снимает строку, равную строке предка, поэтому нет строки подсистемы в `folder:F` — ранг берётся у
  ближайшей папки-предка с такой строкой, такой нет — ранг `0`. Точка без единой строки значения не имеет.
- Уровень точки по рангам `live` и `rec`: `(0, 0)` — `FORBID`, `(0, 1+)` — `ONLY_ARCHIVE`, `(1, 0)` — `MON`, `(1, 1)` — `ARCHIVE`,
  `(1, 2)` — `ARCH_MANAGE`, а при `cam` ≥ `edit` и `(1, admin)` с `cam` ≥ `edit` — `FULL`; `(1, admin)` иначе — `ARCHIVE`.
- Разные сочетания уровня и функций с одними строками читаются одним: `ARCHIVE` и `ARCH_MANAGE` с `ARCHIVES_SETUP`, `ARCH_MANAGE` с
  `EDIT_PTZ_PRESETS` и `FULL`. Строки у них одни, права не меняются; экран показывает прочитанное.
- Точка `*` — `global.dCam`; ключа корня в `folderAccess` чтение не даёт. `folder:F` и `unit:cam/<id>` — как есть, скопированные
  значения корня тоже: при пересохранении они дают те же строки.
- `feat`: `DEVICES_SETUP` — есть `admin` в `cam`; `ARCHIVES_SETUP` — `admin` в `rec`; `DETECTORS_SETUP` — `admin` в `det`;
  `EDIT_PTZ_PRESETS` — `cam` = `edit` в точке, уровень которой не `FULL`; `USERS_RIGHTS_SETUP` и `ur: ALL` — строка управляющего,
  иначе `ur: NO`.
- `dArch` — `FULL`, если ранг `rec` на `*` не меньше `view`, иначе `FORBID`. Значение, которое не стало строкой (Н1.3 `arch`),
  обратно не приходит: шаблон «Оператор» читается с `dArch: FORBID`.
- `dArch` не обратим: `FORBID` при ранге `rec` ≥ 1 читается `FULL`, значение от него не зависит (строк `arch` сверх `cam` нет).
- Прочие поля `global` — значения `reference.access`: `unr` — Н1.3, `map`, `alert`, `dMic`, `dSpk`, `dSens`, `dRelay`, `dPos`, `dMacro`,
  `dAcfa`, `dVw`, `dPlug` — `FORBID`, `dTel`, `bm` — `NO`, `depth` — `0`, `restr` — `{}`.
- **Чужая строка** снимка не меняет и сохраняется как есть (Н1.5 «Разница»), в том числе у изменённой роли: строка, какой перевод не пишет (`labels:`, иная
  `sub`, срок `until`), и строка с областью без живого объекта — удалённая папка (ADR-0097 §5), удалённая камера. Иначе её ключ вернулся бы в черновик и
  запер `apply`: объекта на экране нет.

Перевод обратим на строках: разбор Н1.3 снимка, собранного по Н1.4, даёт те же строки (все пары «предок, потомок» и наборы функций сверены перебором).

### Н1.5 Применение

`POST /access/apply` — по порядку:

1. Нет `If-Match` — 428 `PRECONDITION_REQUIRED`. Снимок читается целиком (Н1.1); версия не совпала — 412 `VERSION_MISMATCH`, `current`.
2. **Проверки черновика** — без обращений к записям, первое нарушение отвечает:
   - судятся только созданные и изменённые относительно снимка записи: прежнюю запись правкой не поправить, а строки мимо `backend` бывают и без `title`, и с
     повтором;
   - пустое имя — 422 `NAME_REQUIRED`, `field: name`, `login`; повтор без учёта регистра и крайних пробелов — 409 `NAME_TAKEN` (роль,
     группа), 409 `LOGIN_TAKEN` (человек), поле; повтор `id` — 422 `VALIDATION_FAILED`, `field: id`;
   - ссылка никуда: `roleIds`, ключи `roleUntil`, `memberIds`, `UserGroup.roleIds`, `supervision.roleId` — 422 `VALIDATION_FAILED`, это поле;
   - у роли `admin` меняются только назначения: иное имя, `comment`, удаление — 409 `BUILTIN`;
   - непереводимое — Н1.6;
   - самоблокировка — Н1.8.
3. `dryRun: true` — 200 `{applied: false, access: null}`, `ETag` прежний. Пакета домена нет: его проверки (пп. 4–5) `dryRun` не судит.
4. **Разница.** Строка черновика сравнивается со снимком версии `If-Match`; `apply` не удаляет молча:
   - роль, группа, человек, которых нет в снимке, — создание; которые есть в снимке, но нет в черновике, — явное удаление
     (`op: delete` снимка этой версии); записи вне снимка быть не может: снимок покрывает весь домен;
   - строки гранта кластера: строки роли, чей вид в черновике не изменился, и чужие строки (Н1.4) — как прочитаны, без поля `by`: его ставит дверь;
     прочие строки изменившейся роли заменяются переводом Н1.3;
   - `domain/grants/domain` входит в пакет, только если изменилась строка управляющего.
5. **Пакет** — `POST /domain/batch`: разница, снимок целиком двери не идёт (файл решений, разбор ревью V/11, п. 4); `cas` каждой записи — индекс снимка;
   `kind: grants`, `name` — `CLUSTER` и `domain`; у роли `admin` `fields` несёт только `assigned`. Итог пакета домен считает по своему состоянию и разнице.
   `Idempotency-Key` — hex SHA-256 от байтов `user`, нулевого байта, значения `If-Match`, нулевого байта и SHA-256 тела: воркер повторяет
   те же байты пакета в том же проходе после потери ответа. Повтор клиента до пакета не доходит: первый успех сдвинул версию, шаг 1 отвечает 412 с `current`.
6. Новый человек: `fields` несёт случайный пароль 256 бит hex, значение нигде не сохраняется и не отдаётся. Пароля в контракте нет,
   поэтому войти такой человек не может, пока управляющий или администратор домена не задаст пароль (открытый пункт README).
   Пароль через `backend` поднимает тревогу `domain.rights_via_backend`, как всякая такая правка (Н1.9). Поля `disabled` у `POST /domain/users` нет: новый
   человек с `enabled: false` — 422 `NOT_SUPPORTED`, `field: enabled`.
7. Строки истории — Н1.7. Ответ — 200 `{applied: true, access}`: снимок читается заново, `ETag` — его версия.

`412 conflict` пакета значит «снимок устарел»: 412 `VERSION_MISMATCH`, `current` — снимок, прочитанный заново (P/08.4 Н2 `repeat`).

### Н1.6 Что `apply` не переводит

Отказ — 422 `NOT_SUPPORTED`, `field` — путь поля:

| Значение | Почему |
|---|---|
| `catalogs` не пусто, `UserGroup.source` не `null`, `AccessUser.catalogId` не `null` | каталогов нет (ADR-0098 §8) |
| `loginSchedule` ≠ 0, `supervision` не по умолчанию, `webSessions`, `mobileSessions` ≠ 0 | ADR-0098 §7 |
| уровень `MON_PROT` | спрошено у продукта (ADR-0099 §7) |
| в `global`: `depth`, `restr`, `map`, `alert`, `bm`, `dTel`, `dMic`, `dSpk`, `dSens`, `dRelay`, `dPos`, `dMacro`, `dAcfa`, `dVw`, `dPlug` не по умолчанию | ADR-0097 §7 |
| `feat` вне перечня Н1.3 и `USERS_RIGHTS_SETUP`, в том числе `PROGRAMMING_SETUP` | «Автоматизация» не объявлена |
| `unr: true` у роли не `admin`, `unr: false` у `admin` | ADR-0100 §4 |
| `USERS_RIGHTS_SETUP` при `ur` не `ALL`; `ur: ALL` без неё; `ur: DEV` | ADR-0100 §4 |
| поле `folderAccess`, `objectAccess` не `cam` (у корня — ещё `arch`) | виды без подсистемы |
| новый ключ `objectAccess` не камера: хранилище, детектор, `vw:`, `macro:`, `plug:` | у тома нет единицы, А4 |
| новый ключ `folderAccess` не папка и не домен | 422 `VALIDATION_FAILED`, `field: folderAccess` |
| **пара `MON` и `ONLY_ARCHIVE`** (ниже) | ADR-0099 §7, решение «Архитектора» 3 |

**Пара.** Проверяется итоговое состояние черновика: роли, назначения, группы. Отказ, если наибольшее может встретить `MON` и
`ONLY_ARCHIVE` одного поля на одной единице: внутри роли — две любые папки с такими значениями, копии корня Н1.3 считаются (состав папок меняется позже);
между действующими ролями одного человека, прямо или через группы, — одна роль даёт `MON`, другая `ONLY_ARCHIVE` в любой точке.
Исключение — две разные точки `unit:`: они одну единицу не покрывают. Судится только состояние, которое создаёт правка: уже сохранённую пару правка другой роли не отвергает. `field` — `roleIds` человека или `folderAccess` роли.

### Н1.7 История

`history`, `cellHistory` снимка — строки таблицы `backend/history/<id>`: `kind` — `history` | `cell`, `when`, `entry`. Журнал
платформы ведётся своим чередом (`domain.*`, `via: backend/<экземпляр>`): эта таблица только показывает историю экрана.

- Строки ложатся пакетом `POST /console/batch` **после** пакета домена: `id` — случайный UUID, `when` — часы ответа `GET /session`,
  `actor` — `user` билета. Сбой этой записи ответа не меняет: права уже записаны, истину хранит журнал, причина — в журнал воркера.
- Читается новыми сверху, `HISTORY_READ_MAX` = 1000 новейших строк: иначе снимок перерос бы предел ответа передачи 4 МиБ; срок — `delete_after` таблицы, 90 суток.
- В этом же пакете — строки `people` новых людей. Записей истории в теле больше, чем вмещает `BATCH_WRITES`, — лишние не пишутся, отказа нет.

### Н1.8 Самоблокировка

`SELF_LOCKOUT` проверяет `backend` поверх платформы (ADR-0100 §4), по итоговому состоянию черновика. 409 `SELF_LOCKOUT`, если:

- у роли `admin` нет ни одного включённого назначения без истёкшего срока, прямого или через группу;
- человек запроса снимает с себя роль `admin` (прямо или через группу), выключает или удаляет себя, ставит себе прошедший `expiresDate` или прошедший срок
  своего назначения `admin`: контракт велит не лишать вас входа.

Инвариант «остаётся администратор» держит платформа: `409 last admin` пакета домена — тоже `SELF_LOCKOUT`. Проверка `backend` нужна
для `dryRun` и для снятия самого себя при втором администраторе, которого платформа разрешает.

### Н1.9 Кто применяет

Запись судит процесс `domain`: человек — администратор домена или управляющий (`batch_diff`, P/08.4 Н1.3в). Отказ `403 admin only` —
403 `PERMISSION_DENIED`, ничего не записано. Каждая правка класса «admin only» через `backend` поднимает тревогу
`domain.rights_via_backend` на стороне домена (ADR-0094 доп. (12) п. 10): `backend` сам её не шлёт.

## Н2 Двери

Своей двери у главы нет: `GET /access`, `POST /access/apply` — операции контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
GET /access
  двери домена, /folders, таблицы people, history по билету; отказ двери → отказ запроса
  люди, группы, роли → виды контракта; строки role:<имя> → уровни (Н1.4); версия снимка → ETag
POST /access/apply
  нет If-Match → 428; снимок; версия не та → 412, current
  проверки черновика: имена, ссылки, непереводимое, пара, самоблокировка
  dryRun → 200 applied: false
  разница → POST /domain/batch (cas снимка, Idempotency-Key)
    412 conflict → 412 current; 409 last admin → SELF_LOCKOUT; иной отказ → Н4
  строки истории и people новых людей → снимок заново → 200 applied: true, ETag
```

## Н4 Отказы

| Отказ | Код | `code` |
|---|---|---|
| нет `If-Match` | 428 | `PRECONDITION_REQUIRED` |
| версия снимка не та; `412 conflict` пакета | 412 | `VERSION_MISMATCH`, `current` |
| 401, 403 двери домена, `403 admin only`, `403 denied` | 401, 403 | `UNAUTHORIZED`, `PERMISSION_DENIED` |
| `409 builtin`; правка, удаление роли `admin` | 409 | `BUILTIN` |
| повтор имени, логина | 409 | `NAME_TAKEN`, `LOGIN_TAKEN`, `field` |
| пустое имя | 422 | `NAME_REQUIRED`, `field` |
| Н1.6 | 422 | `NOT_SUPPORTED`, `field` |
| ссылка никуда; `unknown member`, `unknown subject`, `bad name`, `bad line`, `bad batch`, `bad body`, `grant too wide` | 422 | `VALIDATION_FAILED`, `field` — по записи пакета |
| `409 exists`, `name taken` | 409 | `NAME_TAKEN` (у человека — `LOGIN_TAKEN`), `field` |
| `409 being deleted`, `in flight` | 409 | `BUSY` |
| Н1.8; `409 last admin` | 409 | `SELF_LOCKOUT` |
| `409 too many admins`, `409 admin table too large`, `409 roles table too large` | 422 | `VALIDATION_FAILED`, `field: roleIds` |
| `409 password set by a non-admin` | 409 | кода нет: `VALIDATION_FAILED`, `field: roleIds`; спрошено у продукта (ADR-0100, «Запрос продукту» п. 3) |
| `413 batch too large`, `413 too large`: разница велика для одного пакета | 422 | `VALIDATION_FAILED`, `field: access`, `message` — «сохраните частями»: ничего не записано (ADR-0094 доп. (12) п. 4) |
| 4xx, слово не выводится однозначно | статус двери | `VALIDATION_FAILED` без `field` (глава 2 Н1.3) |
| `503 standby`, `unavailable`, `names unknown` | 502–504 | кода нет (глава 2 Н1.3) |

## Н5 Приёмка

Тесты API consolem `tests/api-access.js` на закреплённом коммите в профиле (глава 6): применение, `dryRun`, повторы имён, ссылки,
самоблокировка, 428, 412; синхронизация каталога — вне профиля. Перевод уровней — чтением до стенда; набор `one-domain`
невыразим целиком: его роли несут непереводимые значения, тест идёт против своего набора (глава 6 Н1.3).
