# V/11.4 — Перевод чтений и записей: нормы

Канон главы 4 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A3, A6; доп. (2) пп. 3, 4). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), таблица [`data/mapping.tsv`](../data/mapping.tsv), контракт
[`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка `cammeta-specs` `2110dbf` (пин VMS); нормы
платформы B (ADR-0094 B3, B4, B5) — после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1): где глава на них опирается, место
помечено «норма платформы B — после Go GREEN 01–10».

Глава 3 говорит, какой вид consolem какой подсистеме отвечает. Эта глава — как `backend` собирает запись вида из строк
подсистем, как разбирает правку обратно по строкам, как сверяет версию, что помнит о повторах и как переводит отказ
консоли в отказ контракта. Всё — обратными вызовами по билету запроса на двери перечня (V/11.1 Н1.5).

Id норм — `V/11.4-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Часть** — строка подсистемы, из которой собрана запись вида: у камеры — строка `cam/cameras/<id>`, её записи
  `rec/recordings` и детекторы `det/units`.
- **Индекс хранилища** — версия строки хранилища (P/01.1): не повторяется (рост доп. (4) не обещает); у надгробия — свой индекс
  ([договор надгробий](../../../Platform/common/contracts/tombstone.md)).
- **Групповая запись** — `POST /devices/update` и `POST /objects/delete` контракта: несколько объектов одним запросом с
  `idempotencyKey` в теле.

## Н1 Форма

**Время.** Срок памяти повторов — секунды стенных часов, как срок памяти `Idempotency-Key` у `POST` консоли (P/06.1).

**Данные.** Части читаются и пишутся дверями консоли по билету (V/11.1 Н1.3). Своих строк у главы одна семья — память
повторов группового ключа `backend/idem/<h>` (Н1.4): строки самого `backend` в хранилище, через консоль по
билету на свой префикс (V/11.1 Н1.5).

### Н1.1 Сборка записи (чтение)

- Камера (`Device`, `type: camera`) — строка `cam/cameras/<id>`, записи `rec/recordings` про эту камеру (`cam` записи —
  её id, V/02.1) и детекторы `det/units` про неё (`cam`, V/04.1), всё — дверями единиц консоли (`GET /<sub>/<rows>`),
  слова пульса — `GET /<sub>/<rows>` (`rows`, P/06.1 Н2). Поля — строками таблицы главы 3; `recordMode` — из состава
  записей камеры (глава 3 Н1.3).
- Детектор, хранилище, том — одна строка своей подсистемы (глава 3 Н1.2); правил нет — «Автоматизация» не объявлена
  (ADR-0094 доп. (7)).
- Id записи вида — Н1.6.
- **Версия** записи — непрозрачная строка контракта, сравнивается только на равенство (ADR-0094 доп. (4) п. 1). У записи
  из одной строки — индекс хранилища этой строки. У камеры — склейка индексов частей в постоянном порядке:
  `c<индекс cam>.r<индексы rec>.d<индексы det>`: после буквы части — индексы её строк через `-` в порядке ключа строки
  (байты UTF-8), у удалённой строки — индекс её надгробия, у части без строк — пусто (`c17.r.d`, `c17.r21-30.d44`).
  Индекс — провод P/01.1 Н2 (десятичные цифры), поэтому буквы `c`, `r`, `d`, точка и `-` склейку не путают. Строки `rec` и
  `det` части — строки этой подсистемы про камеру (`cam` строки — id камеры) и надгробия таких строк; надгробия частей
  не убираются, пока камера жива (доп. (4) п. 1 (в)). Индекс отдаёт `ETag` строки — норма платформы B4 (после Go GREEN
  01–10); индекс надгробия удалённой части — `ETag` ответа `DELETE` и 404 `GET` удалённой строки с надгробием, тоже B4
  (ADR-0094 доп. (3) п. 9); надгробия частей камеры `backend` находит дверью
  `GET /<rows>?deleted=1&about=<cam>` → `{deleted: [{id, index}]}` (надгробие хранит значение `about`; B4, доп. (5) п. 1). До B4 двери консоли индекса не отдают, и версии записи `backend` выдать не может: глава
  действует после приращения платформы (вместе с B1, без которого передачи `backend` нет, V/11.1 Н1.3). Как найти
  удалённые строки `rec` и `det` камеры, чтобы взять индексы их надгробий, — открытый вопрос урока (README).
- Ответ — `ETag` записи вида — её версия строкой в кавычках (`"c17.r21-30.d44"`); `If-Match` сверяется равенством
  строки целиком.

### Н1.2 Разборка правки (запись)

- Правка записи вида (`PATCH /devices/{id}`, `PATCH /archives/{id}`, `PATCH /volumes/{id}`) —
  правки строк её частей, каждая своей дверью консоли и **со своим `If-Match`** — индексом этой части **из того же
  снимка**, по которому сверена версия (Н1.3), не перечитанным; у таблиц и прочих записей — `If-Match` по норме B4. Часть,
  которой ещё нет (новая запись `rec`), пишется поверх её надгробия с `If-Match` его индекса, если надгробие было в
  снимке, иначе — созданием.
- `recordMode` камеры — состав её записей `rec` (глава 3 Н1.3): переход режима — создание, правка (`enabled`, `until`,
  роль тома) или снятие строк `rec` камеры; снятие — `DELETE` строки записи (её надгробие двигает версию камеры).
- Детекторы камеры, которых правка не называет, не трогаются; удаление камеры (`DELETE /devices/{id}`) — снятие строки
  `cam`, её записей и детекторов (контракт: «вместе с дочерними»).
- Создание (`POST /devices`, `POST /archives`) — `POST` строк частей; ключ повтора `Idempotency-Key` каждой — выведен из
  запроса так, что повтор того же запроса даёт тот же ключ (Н1.4), иначе — новый.
- Части пишутся по одной, по порядку: `cam`, затем `rec`, затем `det` (строки `rec` и `det` ссылаются на камеру). Отказ
  части — конец записи: уже записанные части не откатываются, ответ — отказ этой части (Н1.5) с текущей записью вида при
  412. Групповой отмены по шагам нет (групповые операции — ADR-0094 C).

### Н1.3 Сверка версии

- Запись без `If-Match` — 428 `PRECONDITION_REQUIRED` (контракт).
- `backend` читает части записи одним снимком и считает её версию (Н1.1); не совпала с `If-Match` — 412
  `VERSION_MISMATCH`, `current` — текущая запись вида (контракт). Совпала — правки частей (Н1.2), каждая с `cas` своего
  индекса из того же снимка (ADR-0094 доп. (3) п. 5). Правка той же части между сверкой и записью — 412 консоли по этой
  части, ответ — 412 `VERSION_MISMATCH` с текущей записью вида: потерянной правки части нет.
- **Ограничение.** Внешний `If-Match` сборной камеры — предварительная проверка по прочитанному снимку частей, а не
  одна запись: правку **другой** части в окне между сверкой и записью он не исключает, и запись может лечь «вперемешку»
  (часть — по новому чужому состоянию, часть — по нашему). Следующий читатель видит новую `version`. Ограничение названо
  продукту (запрос `api/requests/2026-10-29-w2c-webui-csp-request.md` в репозитории продукта, п. 2; ответа на
  закреплённом коммите нет); полный CAS сборки (несколько стражей в
  одной операции P/01.1 или атомарная запись строк одной единицы) — вторая очередь C, если продукт его потребует.

### Н1.4 Память повторов группового ключа — в хранилище, всегда

- Групповая запись несёт `idempotencyKey` в теле (контракт). `backend` помнит её **всегда** (не «до B3») и общей для
  экземпляров памятью: строка `backend/idem/<h>` в хранилище, `h` — SHA-256 (hex строчными) от байтов `user`, нулевого байта и внешнего
  `idempotencyKey` (`user` — человек билета); строка хранит `user` и ключ и сверяет их при поиске (доп. (5) п. 2); поля — отпечаток всего тела (операция и тело), итог группы, срок — тот же, что у памяти
  `Idempotency-Key` `POST` консоли (P/06.1) (ADR-0094 доп. (3) п. 4). Строку `backend` читает и пишет через консоль по
  билету на свой префикс (V/11.1 Н1.5).
- **Порядок.** Поиск строки — **до** сверки сборной версии и разрешения объектов (Н1.3, Н1.6). Строки нет — запись
  «начато» (отпечаток, без итога) **до первого шага**, затем шаги, затем итог в ту же строку. Повтор с тем же ключом и тем
  же телом: итог есть — сохранённый ответ без обращений к частям; итога нет (первый запрос ещё идёт или оборвался
  посередине) — шаги заново с теми же ключами шагов (ниже), консоль отвечает сохранённым ответом уже сделанных; с иным
  телом — отказ повторного использования по контракту: 422 `VALIDATION_FAILED`, `field: idempotencyKey` (кода «ключ занят
  иным телом» в контракте нет).
- **Ключи шагов.** `Idempotency-Key` каждого обратного вызова выводится из внешнего ключа и номера шага: повтор на другом
  сервере, после потери ответа или перезапуска воркера между шагами приходит в консоль с теми же ключами, и консоль
  отвечает сохранённым ответом своих `POST` (а с нормой платформы B3 — и правок `PUT`, `DELETE`, таблиц; после Go GREEN
  01–10).
- «Без своего состояния» воркера (ADR-0094 A3) читается так: без состояния вне хранилища платформы. Процесс воркера
  своей памяти между запросами не держит.

### Н1.5 Групповая запись — по элементу

- `POST /devices/update`: каждый элемент `{deviceId, version, set}` — отдельная правка записи (Н1.2, Н1.3 с `version`
  элемента вместо `If-Match`); итог — `{done: [Device…], failed: [{deviceId, code, field?}…]}`, частичный успех.
- `POST /objects/delete`: каждый элемент `{id, version}` — удаление записи своего вида (вид — по id, Н1.6) со сверкой
  версии; итог — `{done: [id…], failed: [{id, code}…]}`. Серверы и домены так не удаляются (контракт).
- Элементы исполняются по порядку тела; отказ элемента не останавливает следующие.

### Н1.6 Id записи вида

- Id записей контракта — UUID. Id вида у нас — строка подсистемы (`cam/cameras/<id>`, `rec/volumes/<name>`, …): `backend`
  выводит UUID из места строки детерминированно — UUID версии 5 (RFC 9562, SHA-1) над пространством имён урока; имя —
  байты UTF-8 ключа строки в хранилище `<sub>/<rows>/<id>` как он записан, без нормализации (регистр, Unicode, `/` — как
  есть); у таблицы — ключ строки таблицы `<sub>/<таблица>/<имя>` (ADR-0094 доп. (3) п. 10 (7)). Кластера в имени нет:
  `backend` кластера отдаёт записи своего кластера (домен consolem — наш кластер, глава 3). Обратный путь — по перечню
  строк вида. Пространство имён — константа урока `BACKEND_NS` = `4ffc0b08-e8bd-4a4e-b7fb-d4ecc8a83ecb`.

## Н2 Двери

Своей двери у главы нет: обратные вызовы — двери консоли из перечня (V/11.1 Н1.5).

## Н3 Проход

```
чтение вида → части дверями консоли по билету → поля по mapping.tsv → версия (склейка индексов частей; B4) → ETag
правка вида
  нет If-Match → 428 PRECONDITION_REQUIRED
  прочитать части одним снимком, склейка ≠ If-Match (строки) → 412 VERSION_MISMATCH, current
  части по порядку cam → rec → det, каждая с cas своего индекса из того же снимка (B4)
    отказ части → отказ контракта (Н1.5 таблица), записанное остаётся
групповая запись
  строка backend/idem/<h>: итог есть → ответ; иное тело → 422; нет → «начато» (до первого шага)
  элемент за элементом (Н1.5), ключи шагов из ключа и номера → итог в строку → {done, failed}
```

## Н4 Отказы

Слово отказа консоли → код контракта (до кодов консоли — нормы платформы B5, после Go GREEN 01–10; с ними — по коду и
`field` консоли):

| Отказ консоли | Код | `code` контракта |
|---|---|---|
| 401 сторожевой | 401 | `UNAUTHORIZED` |
| 403 `denied` | 403 | `PERMISSION_DENIED` |
| 404 строки нет | 404 | `NOT_FOUND` |
| 409 `unique` (имя) | 409 | `NAME_TAKEN` |
| 409 `unique` (адрес камеры) | 409 | `ADDRESS_TAKEN` |
| 409 прочее (`ref`, `must_match`, `fixed`) | 422 | `VALIDATION_FAILED`, `field` — поле контракта по таблице главы 3 |
| 400 схемы, поле названо в слове | 422 | `VALIDATION_FAILED`, `field` |
| 412 `revision moved` | 412 | `VERSION_MISMATCH`, `current` |
| 503, обрыв обратного вызова | 503 | код статуса без `field` (`message` — слово консоли) |
| 401 обратного вызова (билет мёртв) | 401 | `UNAUTHORIZED` |
| слово не выводится однозначно | статус консоли | `VALIDATION_FAILED` без `field` у 4xx, иначе — код статуса (глава 2 Н1.3) |
