# V/11.4 — Перевод чтений и записей: нормы

Канон главы 4 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A3, A6; доп. (2) пп. 3, 4). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), таблица [`data/mapping.tsv`](../data/mapping.tsv), контракт
[`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка `cammeta-specs` `fb57c112` (пин V/11: приращение прав поверх норм B, ADR-0090 доп. (16); пометка «норма платформы B» — где глава на них опирается).

Глава 3 говорит, какой вид consolem какой подсистеме отвечает. Эта глава — как `backend` собирает запись вида из строк
подсистем, как разбирает правку обратно по строкам, как сверяет версию, что помнит о повторах и как переводит отказ
консоли в отказ контракта. Всё — обратными вызовами по билету запроса на двери перечня (V/11.1 Н1.5).

Id норм — `V/11.4-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Часть** — строка подсистемы, из которой собрана запись вида: у камеры — строка камеры `cam/cameras/<id>` (пустой
  `main`) и её потоки (`cam/cameras` с `main` = id), её записи `rec/recordings` и детекторы `det/units` (глава 3 Н1.2).
- **Индекс хранилища** — версия строки хранилища (P/01.1): не повторяется (рост доп. (4) не обещает); у надгробия строки
  — свой индекс (P/06.1; ADR-0094 доп. (2) п. 4 (в), доп. (3) п. 9; не надгробие тела `.gone/` ресурса).
- **Групповая запись** — `POST /devices` (создание), `POST /devices/update` и `POST /objects/delete` контракта:
  несколько объектов одним запросом с `idempotencyKey` в теле; **шаг** — один элемент `items`.
- **Пакет** — пакетная запись хранилища B9 дверью консоли (ADR-0094 доп. (9); норма платформы B):
  у каждой записываемой строки свой `cas`, у прочитанных незаписываемых — стражи; всё или ничего.
- **Скрытый член** — член папки, которого нет в `deviceIds`: поток камеры, камера `kind: io`, член вне перечня читателя (Н1.7).
- **Корень цели** — строка операции, по которой консоль судит занятость (P/06.9 Н1.3): Н1.8.

## Н1 Форма

**Время.** Срок памяти повторов — `delete_after` таблицы `repeats`: его считает консоль от первого наблюдения версии
строки, не время хранилища, и строку снимает жнец платформы (Н1.4); стенных часов `backend` память не судит (разбор ревью V/11, Codex № 7, вопрос 3).

**Данные.** Части читаются и пишутся дверями консоли по билету (V/11.1 Н1.3). Своя семья главы — память повторов
группового ключа: таблица манифеста `backend/repeats/<h>` (Н1.4; форма — поля таблицы `repeats`
[манифеста](../backend.subsystem.yaml): семья таблиц платформы — со схемой `manifest`, P/06.1 Н1.6), дверью таблиц
консоли по билету (V/11.1 Н1.5).

### Н1.1 Сборка записи (чтение)

- Камера (`Device`, `type: camera`) — строка камеры `cam/cameras/<id>` (пустой `main`), её потоки (строки `cam/cameras`
  с `main` = id), записи `rec/recordings` про эту камеру (`cam` записи — её id, V/02.1) и детекторы `det/units` про неё
  (`cam`, V/04.1), всё — дверями единиц консоли (`GET /<sub>/<rows>`), слова пульса — `GET /<sub>/<rows>` (`rows`, P/06.1
  Н2). Поля — строками таблицы главы 3; `recordMode` — из записей `<cam>`, `<cam>-<том>` (глава 3 Н1.3). Строка
  `cam/cameras` с непустым `main` — поток своей камеры, отдельным устройством не отдаётся.
- Детектор, том — одна строка своей подсистемы (глава 3 Н1.2); хранилище — строка тома и записи на нём (`retentionDays`);
  правил нет — «Автоматизация» не объявлена (ADR-0094 доп. (7)).
- Id записи вида — Н1.6.
- **Версия** записи — непрозрачная строка контракта, сравнивается только на равенство (ADR-0094 доп. (4) п. 1). У
  детектора и тома — индекс хранилища строки. У камеры — склейка индексов частей в постоянном порядке: `c<индексы
  cam>.r<индексы rec>.d<индексы det>`: после буквы части — индексы её строк через `-` (у `c` — строка камеры, затем её
  потоки; у прочих — в порядке ключа строки, байты UTF-8), у удалённой строки `rec`, `det` — индекс её надгробия, у
  части без строк — пусто (`c17.r.d`, `c17-18.r21-30.d44`). У хранилища — `v<индекс тома>.r<индексы записей с home =
  том>` (от записей зависит `retentionDays`; разбор ревью V/11, Codex № 13). Индекс — провод P/01.1 Н2 (десятичные
  цифры), поэтому буквы, точка и `-` склейку не путают. Строки `rec` и `det` части — строки этой подсистемы про камеру
  (`cam` строки — id камеры) и надгробия таких строк; надгробия частей не убираются, пока камера жива (доп. (4) п. 1
  (в)). Потоки и записи хранилища входят живыми строками: надгробие потока не находится (у строки `cam` нет `about`),
  надгробие записи — по камере, не по тому. Поэтому версия камеры или хранилища может вернуться к прежней, если поток
  или запись тома завели и сняли мимо `backend`; видимая запись при этом та же — её поля — функция тех же строк тех же
  индексов (открытый пункт README: строгое «не возвращается» продукта).
- Индексы: индекс строки — в элементе списка `GET /<rows>` и таблиц (норма платформы B4; разбор
  ревью V/11, вопрос 6); надгробия частей камеры — `GET /<rows>?deleted=1&about=<cam>` → `{deleted: [{id, index}]}`
  (надгробие хранит значение `about`; B4, доп. (5) п. 1); индекс надгробия своей записи — `ETag` ответа `DELETE` и
  сообщение ленты. Двери одной строки у консоли нет: «404 с `ETag` надгробия» (доп. (3) п. 9) заменено этим чтением. До
  B4 двери консоли индекса не отдают, и версии записи `backend` выдать не может: глава действует после приращения
  платформы (вместе с B1, без которого передачи `backend` нет, V/11.1 Н1.3).
- Поля не из строк частей (пульсы, сервер держателя, `cam/devices`) в версию не входят (глава 3 Н1.3; разбор ревью V/11,
  Claude С-1).
- **Версия зависит от смотрящего** (ADR-0094 доп. (12) п. 12). Строки части, которых человек не видит, в склейку не входят:
  перечень отдаёт только разрешённые. Два человека с разными правами получают разные версии одной камеры, и `If-Match` сверяется с
  версией того, кто пишет. Часть без `view` страж не стережёт; строка, которой он не видит, в пакете отказывает тем же словом,
  что отсутствующая: наружу это 412.
- **Чтение двойное** (там же): строк частей две двери, поэтому снимок читается дважды подряд, пока индексы двух чтений не совпадут; не
  совпали за три попытки — 503: снимка, годного для версии, нет.
- Ответ — `ETag` записи вида — её версия строкой в кавычках (`"c17.r21-30.d44"`); `If-Match` сверяется равенством
  строки целиком.

### Н1.2 Разборка правки (запись)

- **Постоянные ключи частей** (разбор ревью V/11, вопрос 1 (а)): записи и детекторы, которые создаёт `backend`, — с
  ключами от камеры: основная запись — `rec/recordings/<cam>`, резервная на томе `<том>` — `rec/recordings/<cam>-<том>`,
  детектор — `det/units/<cam>-<kind>` (образец V/04). Одновременное создание одной части сходится на одном `cas ""`:
  второй пакет — отказ, ничего не записано.
- **Замок устройства — строка камеры** (вопрос 1 (б)). Каждый пакет части камеры **пишет** строку `cam/cameras/<id>` —
  `cas` её индекса из снимка, значение прежнее или новое: правка камеры, её записи или детектора, создание и удаление
  детектора, удаление камеры. Две записи одного устройства упорядочены строкой камеры: вторая — 412. Удаление камеры
  и запись её части не проходят обе.
- **Запись устройства — один пакет** (ADR-0094 доп. (9) п. 3). Правка камеры (`PATCH /devices/{id}`): строка камеры
  (замок), записываемые части — каждая с `cas` своего индекса **из того же снимка**, по которому сверена версия (Н1.3),
  не перечитанным; прочие части устройства из снимка — потоки, строки `rec` и `det` камеры — **стражами** с их
  индексами. Пакет проходит целиком или не проходит: изменилась хоть одна строка снимка — 412 консоли, не записано
  ничего. Часть, которой ещё нет, пишется в пакете поверх её надгробия с `cas` его индекса, если надгробие было в снимке,
  иначе — созданием (`cas ""`). Правка детектора (`Device`, `type: det`) — пакет из строки `det` и строки его камеры
  (замок). Строки про камеру, созданные мимо `backend` (прямые двери консоли) после снимка, пакет не стережёт: их видит
  следующее чтение — новая `version`.
- **`recordMode`** — переход по записям `<cam>`, `<cam>-<том>` (глава 3 Н1.3; разбор ревью V/11, вопрос 2), в одном пакете
  с прочей правкой:
  - `always` — основная `<cam>` `enabled: true`; её нет — создание на томе `archiveId` тела, а без него — 422
    `VALIDATION_FAILED`, `field: archiveId`;
  - `replica` — основная `<cam>`, если есть, `enabled: false`; включённой резервной нет и тело её не даёт — 422
    `VALIDATION_FAILED`, `field: extraArchives`;
  - `none` — все записи `<cam>`, `<cam>-<том>` — `enabled: false`;
  - `motion`, `sched` — 422 `NOT_SUPPORTED`, `field: recordMode`.
  `archiveId` — `home` основной `<cam>` (`null` — снять основную, `DELETE` в пакете); `extraArchives` — набор резервных:
  элемент — строка `<cam>-<том>` (`recordMode` элемента `null`, `always` — `enabled: true`, `none` — `false`, иное — 422
  `NOT_SUPPORTED`; `stream` — `stream` записи), строки вне набора снимаются; `stream` — `stream` основной; основной нет
  и тело её не создаёт (в том числе `archiveId: null` в том же `set`) — 422 `VALIDATION_FAILED`, `field: stream` (разбор
  ревью V/11, дополнение Kimi, № 8). Новая запись — со сроком хранилища своего тома (глава 3 Н1.3).
- **Создание камеры** (`POST /devices`, элемент `type: camera`) — один пакет: счётчик `cam/next_id` (`cas` прочитанного,
  значение `n + 1`; значение и индекс — `GET /cam/next_id`, P/06.1 Н2 «Дверь счётчика»), строка `cam/cameras/<n + 1>` (`cas ""`), записи `<n + 1>`, `<n + 1>-<том>` и детекторы
  `<n + 1>-<kind>` из `children` и полей записи (норма платформы B9, `POST /console/batch`, P/06.1 Н2 «Пакетная дверь»:
  номер называет вызывающий, счётчик идёт в том же пакете; разбор ревью V/11, вопрос 9). `n` —
  значение счётчика, прочитанное до пакета: последний выданный номер, новой камере — следующий (P/06.1 Н1.3). Счётчик
  сдвинули — 412 `row moved` с `key: cam/next_id`, пакет строится заново с новым чтением. Создание детектора — пакет из строки `<cam>-<kind>` (`cas ""`) и строки камеры (замок). Создание хранилища
  (`POST /archives`) — строка `rec/volumes/<name>` (`cas ""`) из полей хранилища и `firstVolume` (том = то же
  хранилище: `disk`, `sizeBytes`, адрес — строки таблицы `Volume`).
- **Удаление камеры** (`DELETE /devices/{id}`) — один пакет: снятие строки камеры, её потоков, записей и детекторов
  (контракт: «вместе с дочерними»), каждой с `cas` её индекса из снимка. **Удаление детектора** — пакет: снятие строки
  `det` и запись строки камеры (замок).
- **Каскады хранилища** (разбор ревью V/11, Codex № 14, Claude С-16) — один пакет на объект:
  - `DELETE /volumes/{id}` — «вместе с записями на нём»: снятие строки тома и записей с `home` = том; строки камер этих
    записей пишутся (замок);
  - `DELETE /archives/{id}` — «камеры не удаляются»: у камеры, чья основная `<cam>` на этом томе, основной становится
    первая резервная `<cam>-<Y>` по имени тома (основная `<cam>` получает `home: Y` и поля той резервной, `<cam>-<Y>`
    снимается), резервной нет — основная снимается (`recordMode: none`); резервные `<cam>-<том>` на этом томе
    снимаются; записи с иными именами на томе снимаются; строки затронутых камер пишутся (замок); затем снятие строки
    тома;
  - пакет больше предела B9 — отказ консоли, ничего не записано (Н4).
- **Предел частей.** `DEVICE_PARTS_MAX` = 56: потоков, записей и детекторов устройства (ADR-0094 доп. (12) п. 4). Он не выше предела
  стражей: стражи — части, цепочка папки до 7 и страж поколения дают 56 + 7 + 1 = 64 (`BATCH_GUARDS`); записи — камера, части,
  счётчик, строка `<h>`, папка, членство, итог и счётчики шага дают 1 + 56 + 6 = 63 ≤ 64 (`BATCH_WRITES`). `backend`
  держит его при создании части: запись `POST /devices`, `PATCH /devices` сверх предела — 422 `VALIDATION_FAILED`, `field:
  extraArchives` или `parentId`. Части, созданные мимо `backend`, предел обходят: такой пакет — 413 консоли, строка Н4.
- **Папки при удалении.** Камеру и детектор из папок снимает консоль тем же пакетом (P/06.8 Н3 «удаление единицы дверью»); `backend`
  этих строк не называет. Вес держит Н1.7 `DEVICE_FOLDERS_MAX`.
- **Отказ пакета** — любой строки: `cas` или страж (412), права, проверка строки, предел пакета — отказ всего пакета без
  записи (доп. (9) п. 2); ответ — отказ контракта (Н4), при 412 — с текущей записью вида. Записанного наполовину
  устройства не бывает.

### Н1.3 Сверка версии

- Запись без `If-Match` — 428 `PRECONDITION_REQUIRED` (контракт).
- `backend` читает части записи одним снимком и считает её версию (Н1.1); не совпала с `If-Match` — 412
  `VERSION_MISMATCH`, `current` — текущая запись вида (контракт). `If-Match` камеры — версия всего устройства. Совпала —
  пакет (Н1.2): строка камеры пишется, записываемые части с `cas`, прочие стражами, индексы — из того же снимка (ADR-0094
  доп. (9) п. 3). Правка **любой** строки снимка между сверкой и записью — 412 консоли по пакету, ничего не записано;
  ответ — 412 `VERSION_MISMATCH` с текущей записью вида. Перекоса по частям нет: прежнее ограничение (доп. (3) п. 5)
  снято доп. (9) — `412` значит «ничего не изменилось», связанные поля строк `rec` (`recordMode`, `archiveId`,
  `extraArchives`) при одновременных правках не расходятся.

### Н1.4 Память повторов группового ключа — своя таблица, всегда

- Групповая запись несёт `idempotencyKey` в теле (контракт). `backend` помнит её **всегда** (не «до B3») и общей для
  экземпляров памятью — своей таблицей манифеста `backend/repeats/<h>` (разбор ревью V/11, вопрос 3; Codex № 2, 3, 5–7,
  Claude Б-2, С-6–С-9). `h` — SHA-256 (hex строчными) от байтов `user`, нулевого байта и внешнего `idempotencyKey`
  (`user` — человек билета). Служебная семья `<sub>/idem/` консоли — не её. Дверь — дверь таблиц консоли по билету
  (V/11.1 Н1.5): таблица `service: true` (P/06.1 Н1.6, ADR-0094 доп. (15) п. 3) читается и пишется только по живому
  билету от листа роли `backend`, правом следствий, `may` человека не проверяется — людям строк на `sub: backend`
  перевод прав не даёт. Строка — `{h, user, idem_key, op, body, state, steps}`: `op` — `operationId` группы, `body` — SHA-256
  (hex) байтов тела запроса, `state` — `started` | `done`, `steps` — итоги шагов `[{index, outcome: done | failed, id?,
  code?, field?}]`. Форма — поля таблицы `repeats` манифеста со схемами полей (семья таблиц платформы — со схемой
  `manifest`, P/06.1 Н1.6); исход нечитаемой строки — ниже.
- **Порядок.** Первым — память, потом версия:
  1. Строка `<h>` создаётся `cas ""` — `{state: started, steps: []}` — **до** снимка и до первого шага.
  2. Создать не вышло (строка есть) — её читают. `user` и `idem_key` строки не те, что у запроса, — 422
     `VALIDATION_FAILED`, `field: idempotencyKey` (совпадение `h` разных ключей); `op` или `body` не те — то же 422
     (ключ занят иным телом; кода «ключ занят» в контракте нет); `state: done` — ответ из `steps` (ниже) без обращений к
     частям; `state: started` — ответ по завершении: повтор продолжает ту же группу (ниже), его ответ — из `steps`,
     когда строка `done`.
  3. Шаг: снимок и сверка версии элемента (Н1.3), затем пакет устройства (Н1.2), и в **том же пакете** — строка `<h>` с
     итогом шага в `steps` (`cas` её индекса): итог и запись шага ложатся вместе или не ложатся (норма платформы B9: пакет
     несёт строку таблицы `backend/repeats`). Отказ шага (ничего не записано) — итог `failed` пишется отдельно, `cas`
     строки `<h>`.
  4. После последнего шага — `state: done`, `cas` строки.
- **Повтор при `state: started`** — первый запрос ещё идёт или оборвался (жив ли он, `backend` не видит): повтор идёт
  по той же группе. Шаги с итогом в `steps` не исполняются снова и не сверяют версию; прочие — по порядку (шаг 3).
  Исполнителей может быть два, и их упорядочивает строка `<h>`: каждый пакет шага несёт её `cas`. Пакет шага ответил
  412 с `key: cam/next_id` — это не итог: номер взял другой запрос, шаг строится заново с новым чтением счётчика и
  строки `<h>` (Н1.2). Иной 412 — строку `<h>` перечитать: итог шага в ней есть (его записал другой исполнитель) — шаг окончен, иначе — итог
  `failed` `VERSION_MISMATCH`. Сделанный шаг не отвечает 412 на свою же запись: его итог лёг с ним в одном пакете.
  Оборванная группа так доходит до конца первым же повтором.
- **Ответ из памяти:** элемент `done` — запись вида, прочитанная сейчас (у удалённой — её id), элемент `failed` —
  сохранённые `code` и `field`; форма — `{done, failed}` операции.
- **Нечитаемая строка** `<h>` (не по полям таблицы) — неизвестный исход: 503 (код — глава 2 Н1.3), не повтор и не
  исполнение заново; строка не переписывается.
- **Срок** — `delete_after` таблицы `repeats`, 86400 с, как память повторов консоли (P/06.1 Н3): считает консоль от
  первого наблюдения версии строки, не время хранилища, поэтому срок может только удлиниться; строку снимает жнец
  (глава 6.4 Н3 `tables`; ADR-0094 шаг 3б). Строки нет — запрос первый. У приёма операции `OPS_KEEP` (P/06.9 Н1.6) не меньше этого
  срока, но часы разные, поэтому Н1.8 «Память и операция» называет, что бывает на стыке.
- **Ключи шагов.** `Idempotency-Key` обратного вызова шага — hex SHA-256 от `h` и номера шага (десятичная запись) —
  64 знака, один сегмент, в пределах ключа консоли (200 байт, P/06.1; разбор ревью V/11, Claude С-9). Повтор после
  потери ответа на тот же пакет приходит с тем же ключом, и консоль отвечает сохранённым ответом (B3, B9).
- «Без своего состояния» воркера (ADR-0094 A3) читается так: без состояния вне хранилища платформы. Процесс воркера
  своей памяти между запросами не держит.

### Н1.5 Групповая запись — по элементу

- `POST /devices` (разбор ревью V/11, Codex № 5, Claude С-6): элемент `items` `{device, domainId, parentId, folderId}` —
  создание устройства с дочерними одним пакетом (Н1.2); `domainId` — наш кластер (иной — `NOT_FOUND`), `parentId` камеры
  — `null`, детектора — id камеры; `folderId` не `null` — в пакете строки папки по Н1.7; `candidateId` не
  `null` — `failed` `NOT_SUPPORTED`, `field: candidateId` (поиска устройств нет; дополнение Kimi, № 7); вид вне
  `deviceTypes` — `failed` `NOT_SUPPORTED`, `field: type`. Итог — `{done: [{index, devices, folders}], failed:
  [{index, code, field?}]}`: `folders` — папка `folderId` после записи, иначе `[]`.
- `POST /devices/update`: каждый элемент `{deviceId, version, set}` — отдельная правка записи, свой пакет на устройство
  (Н1.2, Н1.3 с `version` элемента вместо `If-Match`; доп. (9) п. 3); итог — `{done: [Device…], failed: [{deviceId,
  code, field?}…]}`.
- `POST /objects/delete`: каждый элемент `{id, version}` — удаление записи своего вида со сверкой версии; вид — по имени
  UUID (Н1.6: `Archive` и `Volume` одной строки различаются id), каскад — как у одиночного `DELETE` (Н1.2), пакет на
  объект; папка — дверью `DELETE /folders/<id>` с `If-Match` (Н1.7), итог хранится в `steps`, как у прочих; `Archive` и `Volume` одной строки в одном теле — один объект хранилища: второй элемент — `done`, если первый
  его снял. Итог — `{done: [id…], failed: [{id, code}…]}`. Серверы и домены так не удаляются (контракт).
- Элементы исполняются по порядку тела; отказ элемента не останавливает следующие; частичный успех — по элементам,
  элемент в `failed` не записан ничем. Память — Н1.4.

### Н1.6 Id записи вида

- Id записей контракта — UUID. `backend` выводит UUID детерминированно — UUID версии 5 (RFC 9562, SHA-1) над
  пространством имён урока; имя — байты UTF-8 строки `<вид>:<место>` (разбор ревью V/11, вопрос 10): у записи из строки
  хранилища `<место>` — ключ строки `<sub>/<rows>/<id>` или `<sub>/<таблица>/<имя>` как он записан, без нормализации
  (регистр, Unicode, `/` — как есть; ADR-0094 доп. (3) п. 10 (7)); `<вид>` — `device`, `archive`, `volume`; у записей
  без строки хранилища — перечень главы 3 Н1.2 (`domain:`, `server:`, `user:`, `event:`). `Archive` и `Volume` одной
  строки `rec/volumes/<name>` получают разные id. Кластера в имени нет: `backend` кластера отдаёт записи своего кластера
  (домен consolem — наш кластер, глава 3). Обратный путь — по перечню строк вида (у удалённой — по надгробиям камеры).
  Ссылки (`parentId`, `archiveId`, `serverId`, `domainId`) — тем же правилом. Пространство имён — константа урока
  `BACKEND_NS` = `4ffc0b08-e8bd-4a4e-b7fb-d4ecc8a83ecb`.

### Н1.7 Папки

Папка — запись консоли, членство — её забота: `backend` переводит форму и хранит только правило скрытых членов (ADR-0096 §7).

- **Чтение.** `Folder` — элемент `GET /folders`, `GET /folders/<id>`: `id` — UUID v5 `folder:platform/folders/<id>`, `domainId` — наш
  кластер, `parentId` — id родителя или `null` при `parent: ""`, `version` — `index` строки, `deviceIds` — видимые члены по порядку.
  Обратный путь — по перечню `GET /folders`. Элемент `{id, garbled: true}` не отдаётся, а при чтении этой папки — 503.
- **Видимый член** — `cam/cameras/<id>` с пустым `main` и `kind: video`, `det/units/<id>` из перечня единиц читателя. Члена вне перечня перевод считает скрытым: права нет или он
  удалён мимо двери, по отфильтрованному перечню их не отличить, а контракт велит не раскрывать невидимое (ADR-0096 доп. (1)). Дверь папки отдаёт члены как есть, чтение платформой
  не меняется.
- **Создание** — `POST /folders` `{name, parent}`: `domainId` иной — 404 `NOT_FOUND`; `name` пустое — 422 `NAME_REQUIRED`.
- **Правка** (`PATCH`, `If-Match` — 428 без него) — `PUT /folders/<id>` с `If-Match: "<version>"`, поля `name`, `members`; `412 folder moved` — 412
  `VERSION_MISMATCH`, `current` из `row` ответа.
- **Скрытые члены** сохраняются: `members` — видимые в порядке `deviceIds`, а каждый скрытый член встаёт сразу за ближайшим видимым
  **перед ним** в прежнем списке, который остался, в прежнем порядке скрытых; такого нет — в начало списка. Состав читается из той же
  версии, что `If-Match`, поэтому член, добавленный мимо `backend`, не теряется: запись отвечает 412. Смена `version` папки от правки
  скрытого члена — ограничение: новая версия без видимого изменения.
- **Отказ цепочки** — 404 `NOT_FOUND` (ADR-0096 §7): предка нет, надгробие, 412 стража цепочки. В контракте `POST /folders` нет 409 и 412.
- **`folderId` создания и шаг `folderIds`** — пакет B9 со строками папок и членства (P/06.8 Н2 «Строки папок в пакетной двери»): новый член
  в конец; `cas` — индекс строки папки, строка членства из `GET /folders?member=` (`member.index`), стражи — цепочка предков каждой добавленной
  папки и строка единицы, если её нет в `writes`. Порядок папок устройства не хранится (ADR-0096, «Запрос продукту» п. 1).
- **Вес каскада.** `DEVICE_FOLDERS_MAX` = 15: различных папок у камеры и её детекторов вместе (решения норм прав, п. 18). Удаление устройства
  пишет строку каждой такой папки; `FOLDER_ROW_MAX` × 15 с ключами частей входит в тело пакета `-max-body` 1 МиБ (P/06.8 Н1.3).
  `backend` держит предел при `folderId`, шаге `folderIds` и `PATCH /folders` по перечню `GET /folders`: сверх него — 422 `VALIDATION_FAILED`,
  `field: folderId`, `folderIds` или `deviceIds`. Две одновременные записи и записи мимо `backend` предел обходят: удаление такого
  устройства — 413, строка Н4, ничего не записано; снять его из папок и повторить.

### Н1.8 Групповая операция

Операцию ведёт консоль (P/06.9), шаг переводит и пишет `backend`. Таблица операций `service: true`: двери — только по билету, людям строк
`sub: backend` перевод не даёт, чужая операция — 404 `NOT_FOUND` (решения норм прав, пп. 21, 22).

- **Id.** `id` операции — 128 случайных бит, называет `backend`; в контракте — те же биты в форме UUID 8-4-4-4-12. Обратный путь —
  снятие дефисов.
- **Приём** `POST /operations`, по порядку (ADR-0095 §2):
  1. Память первой: строка `<h>` с `op: createOperation` создаётся «начато» `cas ""`, как Н1.4. Строка есть: чужие `user`, ключ, `op`, `body` —
     422 `VALIDATION_FAILED`, `field: idempotencyKey`; `state: done` — 202 с той же операцией (`operation` строки); `state: started` — приём
     идёт заново по той же строке, спор решает `cas` памяти в пакете приёма.
  2. Цели читаются снимком (Н1.3) и сверяются с `expectedVersions`: расхождение хоть одной — 412 `VERSION_MISMATCH`, ничего не создано. Шаг
     `set` или `folderIds` без версии цели в `expectedVersions` — 428 `PRECONDITION_REQUIRED` (чтение ADR-0095 §2; «Запрос продукту» п. 1).
  3. `POST /backend/operations` `{id, items, memory}`: `items[]` — `{body, root, expected, secret?}`; `body` — элемент запроса без секрета;
     `root` — корень; `expected` — `{"versions": {<id объекта корня>: <версия>}}` по целям этого корня; `memory` — `{key: backend/repeats/<h>, fields:
     <строка с state: done и operation>, cas}`. Ответ — 202 `Operation`, все шаги `wait`.
  4. `409 root busy` — 409 `BUSY`, `412 row moved` с `field: /memory/cas` — другой исполнитель принял: перечитать строку и ответить, как `state: done`.
  Цель не найдена — 404 `NOT_FOUND`, ничего не создано: корень без неё не вычислить.
- **Корень** (ADR-0095 §1): `<cam>` — камера, у камеры и её детекторов один; `v-<name>` — строка тома, у `Archive` и `Volume` одной строки один;
  у шага над сервером и доменом — `<вид>-<id>`. Занятость и цепочка версий идут по корню.
- **Шаг.** Консоль зовёт `POST /opstep` `{id, index, body, secret?, expected, opcount}` с `X-W2C-Pass-Ticket` по маршруту объявления (P/06.9 Н2 «Вызов шага»);
  тело ответа консоль не читает, поэтому ответ — 200 без тела при любом исходе: исход — строка итога.
  1. **Сверка.** `expected` бывает двух форм. `{"versions": …}` — первый шаг над корнем: версии контракта, сверка как Н1.3. `{"rows": {<ключ строки>: <revision>}}` —
     цепочка корня: шаг после успешного шага; карта всех живых строк корня должна быть равна карте снимка. Версию контракта в цепочку положить нельзя: индекс
     пакета при его сборке неизвестен (P/06.1 «пакет»), а `revision` записанной строки предсказуем (файл решений, разбор ревью V/11, п. 1).
  2. `set` — как элемент `POST /devices/update` (Н1.5): снимок, пакет B9 с `cas` снимка и стражами частей; `create` — как элемент `POST /devices`, родитель —
     `targetId`; `folderIds` — Н1.7: состав папок цели становится списком тела, запись камеры не меняется, поэтому стражем идёт строка самой цели (P/06.8 Н3 шаг 7);
     пакету `folderIds` стражей частей нет места (P/06.8 Н1.3).
  3. В том же пакете — строка `backend/opdone/<id>/<i>` `cas ""` и `backend/opcount/<id>` с `cas` — значение `opcount` тела вызова шага (P/06.9 Н2). `versions` итога — карта `{"rows": …}`
     строк корня после шага: у записанной `revision` + 1, у новой 1, снятой нет, прочие из снимка. `version` итога не пишется, он необязателен; `created_id` — id созданного.
     `Idempotency-Key` — `step_key(id, i)` (P/06.9 Н2). `revision` снятой и созданной заново строки таблицы может вернуться (P/06.1 Н2 «Версии»): чужое снятие и создание
     той же строки внутри цепочки сверка не ловит, это ограничение.
  4. Отказ без записи (версия не та, `NOT_SUPPORTED`, `PERMISSION_DENIED`) — пакет из итога `fail` с кодом контракта и `field` и счётчиков, **без** ключа: `step_key` занят ответом
     пакета записи, а двойной итог отсекает `cas ""` (файл решений, разбор ревью V/11, п. 2).
  5. `412 row moved` — перечитать итог: есть — шаг окончен, нет — итог `fail` `VERSION_MISMATCH`. `412 leader moved` — закончить вызов, итога не писать: в память `step_key`
     этот ответ не ложится, это не исход шага (там же).
  6. `set` с `ServerPatch`, `DomainPatch` — итог `fail` `NOT_SUPPORTED`: эти правки у нас `NO_ROUTE` (глава 2 № 6, 13).
- **Чтение** `GET /operations/{id}`: `GET /backend/operations/<id>`; `createdAt`, `finishedAt` — секунды в RFC 3339 UTC; `retryOf` — `retry_of` в форме UUID;
  `revertOf` — `null`; `items[i]` — `{index: i, targetId, state, code, createdId?}`, `targetId` — из `items[i].body` ответа (P/06.9 Н2, при
  `service: true`), `code` — `code` итога или `null`. `not_run` наружу не идёт кодом контракта: кода нет, пункт открыт (глава 2 Н1.3); до ответа — `DEVICE_OFFLINE`.
- **Управление:** `pause`, `resume`, `cancel`, `retry-failed` — двери консоли, `409 operation done`, `409 operation running`, `409 nothing to retry` — 409 `BUSY`;
  у `retry-failed` `backend` называет новый `id`, памяти ключа нет: ключа в контракте нет.
- **Память и операция.** Числа равны, 86400 с, часы разные: `OPS_KEEP` считается от `finished_at`, срок строки `<h>` — от первого
  наблюдения её версии (Н1.4). Память может пережить операцию только на задержку наблюдения и период жнецов, если операция кончилась
  сразу: повтор ключа тогда получает 404 `NOT_FOUND` от чтения операции, спустя сутки при обещании контракта 10 минут. Операция может пережить память, она идёт до
  `OPS_RUN_MAX` и ещё `OPS_KEEP`: повтор ключа после срока памяти идёт как новый приём и получает 409 `BUSY` или 412 по версиям. Шаг, меняющий
  версию, дважды не исполняется ни там, ни там; операция только из `folderIds` версий не меняет: такой повтор — новая операция с тем же итогом.

## Н2 Двери

Своей двери у главы нет: обратные вызовы — двери консоли из перечня (V/11.1 Н1.5). Вызов шага — маршрут `opstep` манифеста, его зовёт только
консоль (Н1.8).

## Н3 Проход

```
чтение вида → части дверями консоли по билету → поля по mapping.tsv → версия (склейка индексов частей; B4) → ETag
правка вида
  нет If-Match → 428 PRECONDITION_REQUIRED
  прочитать части одним снимком, склейка ≠ If-Match (строки) → 412 VERSION_MISMATCH, current
  один пакет (B9): строка камеры пишется (замок), записываемые строки с cas, прочие части стражами — индексы из того
    же снимка (B4); новые части — постоянные ключи <cam>, <cam>-<том>, <cam>-<kind>; новая камера — с cam/next_id
    отказ пакета (412 cas или стража, права, проверка строки, предел) → ничего не записано → отказ контракта (Н4)
папка: чтение и запись — двери /folders; PATCH: видимые по телу, скрытые за ближайшим прежним видимым, If-Match — version
операция
  приём: <h> cas "" → снимок целей против expectedVersions → POST /backend/operations с memory → 202
  шаг: POST /opstep → снимок → пакет: запись цели + итог cas "" + счётчики; отказ без записи: итог fail + счётчики
    412 row moved → перечитать итог; 412 leader moved → кончить вызов, итога нет
групповая запись
  backend/repeats/<h> cas "" {started} — до снимка; строка есть: чужие user, ключ, op, body → 422; done → ответ из steps;
    started → продолжить ту же группу
  элемент за элементом (Н1.5): итог в steps? пропустить : снимок → пакет устройства + строка <h> с итогом шага
    412 key cam/next_id → шаг заново, перечитав счётчик и <h>
    иной 412 пакета → перечитать <h>: итог есть → дальше, нет → failed VERSION_MISMATCH
  строка <h> → done → {done, failed}; нечитаемая строка <h> → 503, не исполнять
```

## Н4 Отказы

Слово отказа консоли — поле `error`, постоянное слово перечня (норма платформы B5, ADR-0094 доп. (13)), фраза для
человека — `detail`; код контракта выводится только из слова и `field`, не из `detail`. `field` консоли — JSON Pointer:
`/<поле>` строки, в пакете `/writes/<номер>/fields/<поле>`; поле контракта — по таблице главы 3.

Отказ пакета (Н1.2) переводится по слову отказавшей строки; не записано ничего.

| Отказ консоли | Код | `code` контракта |
|---|---|---|
| 401 сторожевой | 401 | `UNAUTHORIZED` |
| 403 `denied` | 403 | `PERMISSION_DENIED` |
| 404 строки нет | 404 | `NOT_FOUND` |
| 409 `unique` (имя) | 409 | `NAME_TAKEN` |
| 409 `unique` (адрес камеры) | 422 | `VALIDATION_FAILED`, `field: ip` (`ADDRESS_TAKEN` контракта — про сервер; разбор ревью V/11, Claude С-17) |
| 409 прочее (`ref`, `must_match`, `fixed`) | 422 | `VALIDATION_FAILED`, `field` — поле контракта по таблице главы 3 |
| 400 схемы, поле названо в слове | 422 | `VALIDATION_FAILED`, `field` |
| 412 `row moved`, `key: cam/next_id` | — | наружу не идёт: пакет строится заново (Н1.2) |
| 412 `row moved`, разошлась строка `det/units/<cam>-<kind>` с `cas ""` (детектор того же вида у камеры уже есть) | 409 | `NAME_TAKEN`, `field: detectorKind` |
| 412 `row moved` прочее (не строка папки), 412 `revision moved` | 412 | `VERSION_MISMATCH`, `current` |
| 502, 503, 504, обрыв обратного вызова, нечитаемая строка памяти | 502–504 | кода нет — запрос продукту (глава 2 Н1.3) |
| 401 обратного вызова (билет мёртв) | 401 | `UNAUTHORIZED` |
| 413 `batch too large` (пакет больше предела B9) | 422 | `VALIDATION_FAILED` без `field` |
| 404 `no such folder`, `no such parent`, 409 `parent gone`, `folder gone`, 412 `parent moved` | 404 | `NOT_FOUND` (Н1.7) |
| 412 `row moved` по стражу цепочки папки (`key: platform/folders/<id>`) | 404 | `NOT_FOUND` (Н1.7) |
| 412 `folder moved` | 412 | `VERSION_MISMATCH`, `current` |
| 400 `bad member`, `too many folders`, `too many members`, `too deep`; 413 `row too large` папки | 422 | `VALIDATION_FAILED`, `field: deviceIds` (`too deep` — `parentId`) |
| 404 `no such operation`, `no operations` | 404 | `NOT_FOUND` |
| 409 `root busy`, `operation done`, `operation running`, `nothing to retry` | 409 | `BUSY` |
| 400 `too many steps`, `too many operations` | 422 | `VALIDATION_FAILED`, `field: items` |
| 4xx, слово не выводится однозначно | статус консоли | `VALIDATION_FAILED` без `field` (глава 2 Н1.3) |

## Н5 Приёмка

Тесты API consolem (`tests/api-devices.js`, `api-bulk.js`, `api-storage.js` на закреплённом коммите) против
стенда в профиле возможностей (глава 6); до приращения платформы — чтением.

Чего они не видят, проверяет [`acceptance/4/`](../acceptance/4/README.md) (ADR-0094 доп. (17), (18)): отказ обычному человеку, скрытое, память `backend/repeats` и перезапуск воркера,
`GET /domains`, `GET /servers`.
