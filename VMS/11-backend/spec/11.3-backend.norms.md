# V/11.3 — Сопоставление видов: нормы

Канон главы 3 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A6). [Лекция](../11-backend.md), [инструкция](11-backend.README.md),
таблица [`data/mapping.tsv`](../data/mapping.tsv), контракт [`consolem.openapi.json`](../consolem.openapi.json). Платформа —
выгрузка `cammeta-specs` `2110dbf` (пин VMS); нормы платформы B — после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1).

Конфигуратор consolem знает домены, серверы, устройства, папки, хранилища, тома, правила, журнал. У нас те же вещи —
строки подсистем VMS и двери консоли, но разрезаны иначе: камера consolem — одна запись, у нас — строка `cam`, записи
`rec` про неё и детекторы `det`. Глава нормирует, какой вид consolem какой подсистеме и какому полю отвечает. Как
собрать запись и разобрать правку — глава 4.

Id норм — `V/11.3-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Вид** — схема контракта (`Device`, `Archive`, `Rule`…); у `Device` вид уточняет `type`.
- **Сборка** — запись вида из нескольких строк наших подсистем.

## Н1 Форма

### Н1.1 Таблица — данные урока

- Сопоставление — данные урока [`data/mapping.tsv`](../data/mapping.tsv), а не код: реализация `backend` читает таблицу
  (ADR-0094 A6; АДАПТЕР-CONSOLEM § 4 — «таблицу лучше держать данными»). Владелец таблицы — «Спецификация VMS».
- Формат: UTF-8, LF, поля через TAB, строки с `#` — пояснения. Поля: `kind` (вид контракта, у `Device` — с `type`),
  `field` (поле контракта или несколько через запятую; `—` — вид целиком), `vms` (подсистема и место: `<sub>/<rows>`,
  `<sub>/<tables>`, `<sub>/heartbeats` или дверь консоли `GET /…`; `—` — у нас нет), `vms_field` (поле у нас, слово или
  описание), `way` (`read` — только чтение, `both` — чтение и запись, `none` — у нас нет), `note`.
- Каждое поле каждой схемы вида, которую переводят операции «переводится» (глава 2 Н1.2), названо в таблице: своим
  местом или `none`. Поле `none` в ответе — по умолчанию контракта (`required` — пустое значение своего типа, иначе поля
  нет); в записи — 422 `VALIDATION_FAILED` с `field` этого поля.

### Н1.2 Виды

| Вид consolem | У нас | Направление |
|---|---|---|
| `Domain` | наш кластер (ADR-0094 A6): одна запись — свой кластер; создание, имя, удаление — нет | чтение |
| `Server` | элемент `GET /servers` консоли (P/06.6); роль, сеть, телеметрия — нет | чтение |
| `Device`, `type: camera` | **сборка**: строка `cam/cameras/<id>` (V/01.1), записи `rec/recordings` про камеру (V/02.1), детекторы `det/units` про камеру (V/04.1); слова пульса `cam/heartbeats` и строка `cam/devices` (V/01.2, V/01.4) — чтение | чтение и запись |
| `Device`, `type: det` | строка `det/units/<name>`, `parentId` — `cam` | чтение и запись |
| прочие `Device` (`mic`, `spk`, `sensor`, `relay`, `storage`, `ipsrv`, `channel`, `eventsrc`, `acfa*`, `export`, `email`, `sms`) | нет: в списке их нет, создание — 422 `VALIDATION_FAILED`, `field: type` | — |
| `Folder` | нет: папки как записи — ADR-0094 C; у камеры — поле-список `folders` | — |
| `Archive` и `Volume` | строка таблицы `rec/volumes` (V/02.1): хранилище = один том; срок хранения — у записи (`retention_days`), не у тома | чтение и запись |
| `Rule`, `RuleFire` | строка `auto/scenarios` (V/07.1); срабатывания — события `auto` (`GET /events`) | чтение и запись; срабатывания — чтение |
| `JournalEvent` | `GET /events`: `audit` — журнал `audit/console`, `alarm` — класс `alarm`, `info` — прочее | чтение |
| `Me` | `GET /session` — кто я; `serverTime`, `timezone` — норма платформы B6 (после Go GREEN 01–10) | чтение |
| `Reference` | перечисления полей `GET /manifest` подсистем; модели устройств — таблица `cam/devices` | чтение |
| `StreamMessage` | лента `GET /changes` — норма платформы B2 (после Go GREEN 01–10), глава 5 | чтение |
| `Settings`, `License`, `Access`, `Operation`, `Discovery` | нет (глава 2 Н1.2: `NO_ROUTE`) | — |

### Н1.3 Поля и перечисления

- Поле ↔ поле и перечисление ↔ перечисление — строками таблицы. Секреты (`hasPassword`, `hasSecret`) — только признак
  «задан»: значения `*_secret` `backend` не читает и не отдаёт (маска консоли, P/06.1).
- `recordMode` камеры — не поле, а состав её записей `rec` (ADR-0094 доп. (2) п. 3; термины V/02): `none` — основной записи
  нет; `always` — основная запись есть и включена; `motion` — запись по событию (паузы между событиями, V/02.1); `sched` —
  запись по расписанию: срок `until` строки записи или сценарий `auto`, который её включает и выключает (V/02.1, V/07);
  `replica` — резервная запись (запись на томе с ролью резерва, V/02.6). Чтение выводит режим из записей камеры, запись
  режима — создание, правка или снятие строк `rec` (глава 4).
- `detectorKind` ↔ `det.kind`: виды `motion`, `linecross` — из реестра воркера (V/04.2); вида нет в реестре — строка
  пишется (`kind` как записан), детектор — `unsupported` (V/04.2 Н1.2), не отказ двери.
- Версия записи (`version`) — **индекс хранилища** строки (версия строки хранилища P/01.1 — не повторяется и только растёт;
  ADR-0094 доп. (2) п. 4): у записи из одной строки — индекс этой строки; у сборной камеры — **наибольший индекс
  среди её частей** (`cam`, `rec`, `det`) **и их надгробий**. Индекс хранилища глобальный и только растёт, удаление
  части — запись надгробия с новым индексом
  ([договор надгробий](../../../Platform/common/contracts/tombstone.md)), поэтому любая перемена части даёт новое значение,
  а прежнее не возвращается. `revision` строки (P/06.1) версией не служит: `DELETE` её не двигает, сумма ревизий давала
  бы ABA. Индекс строки консоль отдаёт `ETag` по норме B4 (норма платформы B — после Go GREEN 01–10; сейчас двери консоли
  индекса не отдают); правило действует до ответа продукта о версии сборной записи (вопрос продукту). Как `backend` его
  сверяет — глава 4.

## Н2 Двери

Своей двери у главы нет: таблица читается реализацией.

## Н3 Проход

```
операция «переводится» (глава 2) → вид контракта → строки таблицы mapping.tsv этого вида
  чтение: поля way read|both — из места vms; none — по умолчанию контракта
  запись: поля way both — в место vms (глава 4); none в теле записи — 422 VALIDATION_FAILED, field
```

## Н4 Отказы

| Причина | Код | `code` | Что делает вызывающий |
|---|---|---|---|
| запись поля, которого у нас нет (`way: none`) | 422 | `VALIDATION_FAILED`, `field` | убрать поле |
| создание устройства вида, которого нет | 422 | `VALIDATION_FAILED`, `field: type` | — |
