# V/11.3 — Сопоставление видов: нормы

Канон главы 3 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A6). [Лекция](../11-backend.md),
[инструкция](11-backend.README.md), таблица [`data/mapping.tsv`](../data/mapping.tsv), контракт
[`consolem.openapi.json`](../consolem.openapi.json). Платформа — выгрузка `cammeta-specs` `d3f8e05` (пин VMS); нормы
платформы B — после Go GREEN 01–10 (ADR-0094 «Порядок» п. 1).

Конфигуратор consolem знает домены, серверы, устройства, папки, хранилища, тома, правила, журнал. У нас те же вещи —
строки подсистем VMS и двери консоли, но разрезаны иначе: камера consolem — одна запись, у нас — строка `cam`, записи
`rec` про неё и детекторы `det`. Глава нормирует, какой вид consolem какой подсистеме и какому полю отвечает. Как
собрать запись и разобрать правку — глава 4. Правила consolem («Автоматизация») на первом шаге не объявляются
(ADR-0094 доп. (7); глава 2 Н1.2): прежнее сопоставление `auto` ↔ `Rule` снято.

Id норм — `V/11.3-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

- **Вид** — схема контракта (`Device`, `Archive`, `Rule`…); у `Device` вид уточняет `type`.
- **Сборка** — запись вида из нескольких строк наших подсистем.

## Н1 Форма

### Н1.1 Таблица — данные урока

- Сопоставление — данные урока [`data/mapping.tsv`](../data/mapping.tsv), а не код: реализация `backend` читает таблицу
  (ADR-0094 A6; АДАПТЕР-CONSOLEM § 4 — «таблицу лучше держать данными»). Владелец таблицы — «Спецификация VMS».
- Формат (эта норма): UTF-8, LF, поля через TAB, строки с `#` — пояснения. Поля: `kind` (вид контракта, у `Device` — с
  `type`), `field` (поле контракта или несколько через запятую; `—` — вид целиком), `vms` (подсистема и место:
  `<sub>/<rows>`, `<sub>/<tables>`, `<sub>/heartbeats` или дверь консоли `GET /…`; `—` — у нас нет), `vms_field` (поле у
  нас, правило или постоянное значение), `way`, `note`. `way`:
  - `read` — только чтение из места у нас; `both` — чтение и запись; `write` — только запись (входной секрет:
    `password`, `secret`), в ответе значения нет;
  - `const` — постоянное значение ответа, названное в `vms_field`: JSON или правило «наименьшее по схеме» (пустые
    списки и объекты, `0`, `""` — по каждому обязательному полю вглубь); `none` — у нас нет: необязательное поле в
    ответе отсутствует.
- **Полнота.** Каждое поле каждой схемы вида, которую переводят операции «переводится» (глава 2 Н1.2), и каждое поле их
  тел записи (`DeviceCreate`, `DevicePatch`, `ArchiveCreate`, `ArchivePatch`, `VolumeCreate`, `VolumePatch`) названо в
  таблице. Обязательное поле схемы ответа (`required`) — всегда `read`, `both` или `const` со значением, которое проходит
  схему (`enum`, `pattern`, `format`); «пустое значение типа» не выдаётся (разбор ревью V/11, Codex № 8, Claude С-3).
- **Поле в теле записи** (Claude Б-4):
  - `both`, `write` — в место у нас (глава 4);
  - `read`, `const` — значение, равное тому, что дало бы чтение (у создания — значению, которое запись получит по
    таблице), пропускается; иное — 422 `NOT_SUPPORTED`, `field` этого поля;
  - `none` — значение умолчания ответа контракта (поля нет, `null`, у `encrypted` — `false`) пропускается; иное — 422
    `NOT_SUPPORTED`, `field` (контракт, `Feature`: «поле есть в записи, но менять его нельзя»).

### Н1.2 Виды

| Вид consolem | У нас | Направление |
|---|---|---|
| `Domain` | наш кластер (ADR-0094 A6): одна запись — свой кластер; создание, имя, удаление — нет | чтение |
| `Server` | элемент `GET /servers` консоли (P/06.6); роль, сеть, телеметрия — постоянные значения таблицы | чтение |
| `Device`, `type: camera` | **сборка**: строка `cam/cameras/<id>` с пустым `main` — камера (V/01.1 Н1.1а); её потоки — строки `cam/cameras` с `main` = id камеры — части сборки: входят в версию, снимаются вместе с камерой, отдельными устройствами не отдаются (разбор ревью V/11, Claude Б-6); записи `rec/recordings` про камеру (V/02.1), детекторы `det/units` про камеру (V/04.1); слова пульса `cam/heartbeats` и строка `cam/devices` (V/01.2, V/01.4) — чтение. Камера `kind: io` устройством не отдаётся: вида для неё в контракте нет (подтип `io` — у IP-сервера, не наш вид) | чтение и запись |
| `Device`, `type: det` | строка `det/units/<cam>-<kind>`, `parentId` — камера `cam` | чтение и запись |
| прочие `Device` (`mic`, `spk`, `sensor`, `relay`, `storage`, `ipsrv`, `channel`, `eventsrc`, `acfa*`, `export`, `email`, `sms`) | нет: в списке их нет, в `deviceTypes` объявления тоже (глава 2 Н1.5); создание — 422 `NOT_SUPPORTED`, `field: type` | — |
| `Folder` | нет: папки как записи — ADR-0094 C; `folderId` создания не `null` — `NOT_SUPPORTED`, `field: folderId` строкой в `failed` | — |
| `Archive` и `Volume` | строка таблицы `rec/volumes` (V/02.1): хранилище = один том; два вида одной строки различаются id (глава 4 Н1.6); срок хранения — у записи (`retention_days`), не у тома. Том `kind: edge` (карта камеры) хранилищем не отдаётся: это память камеры, не хранилище конфигуратора | чтение и запись |
| `Rule`, `RuleFire`, `RuleVersion`, `Schedule`, `DayGroup`, `Modes`, `ObjectMode`, `MaintenanceWindow` | нет: «Автоматизация» не объявляется (ADR-0094 доп. (7); глава 2 Н1.2: `NO_ROUTE`); отображение на сценарии `auto` — вторая очередь C | — |
| `JournalEvent` | строка события `GET /events` (договор журнала событий: `t`, `kind`, `id`, `of`, `class`): `audit` — журнал `audit/console`, `alarm` — класс `alarm`, `info` — прочее | чтение |
| `Me` | `GET /session` — кто я; `serverTime`, `timezone` — норма платформы B6 (после Go GREEN 01–10) | чтение |
| `Reference` | перечисления полей `GET /manifest` подсистем; модели устройств — таблица `cam/devices`; `capabilities` — объявление `backend` (глава 2 Н1.5); справочники правил, раскладок и видеостены — пустые списки | чтение |
| `StreamMessage` | лента `GET /changes` — норма платформы B2 (после Go GREEN 01–10), глава 5 | чтение |
| `Settings`, `License`, `Access`, `Operation`, `Discovery` | нет (глава 2 Н1.2: `NO_ROUTE`) | — |

**Id записей вида** — UUID v5 над пространством имён урока (глава 4 Н1.6), имя — `<вид>:<место>` (разбор ревью V/11,
вопрос 10). `<вид>` — слово `kind` сообщений потока контракта: `domain`, `server`, `device`, `archive`, `volume`; у
записей без строки хранилища — свой постоянный ключ:

| Вид | Имя UUID |
|---|---|
| `Domain` | `domain:<CLUSTER>` — имя кластера установщика (P/02.4 Н1.2) |
| `Server` | `server:<имя сервера>` — `name` элемента `/servers` |
| `Device` камеры и детектора | `device:cam/cameras/<id>`, `device:det/units/<cam>-<kind>` |
| `Archive`, `Volume` | `archive:rec/volumes/<name>`, `volume:rec/volumes/<name>` — одна строка, два id |
| `Me.userId` | `user:<user>` — `user` сессии консоли |
| `JournalEvent` | `event:<id>` — `id` строки события (договор журнала событий) |

### Н1.3 Поля и перечисления

- Поле ↔ поле и перечисление ↔ перечисление — строками таблицы.
- **Секреты.** В ответе — только признак «задан» (`hasPassword`, `hasSecret`): значения `*_secret` `backend` не читает и
  не отдаёт (маска консоли, P/06.1). Входной секрет — `way: write` (разбор ревью V/11, Codex № 9): `password` камеры —
  `cam/cameras.cred_secret`, `password` и `secret` тома — `rec/volumes.access_secret` (у хранилища `block` — пароль NAS,
  у `object` — секрет бакета); поле отсутствует — секрет не трогается; `null` или `""` — секрет снимается (поле пишется
  пустым); строка — новый секрет. Повтор той же правки секрет не раскрывает: ответ его не несёт.
- **`recordMode`** камеры — не поле, а состав её записей `rec` (ADR-0094 доп. (2) п. 3; разбор ревью V/11, вопрос 2).
  Записи, которые ведёт `backend`, — с постоянными ключами (глава 4 Н1.2): основная — `rec/recordings/<cam>`, резервная
  на томе `<том>` — `rec/recordings/<cam>-<том>`. Режим — первое выполненное сверху:

| Условие | `recordMode` |
|---|---|
| основная `<cam>` есть и `enabled` | `always` |
| основной нет или она выключена, есть включённая резервная `<cam>-<том>` | `replica` |
| иначе (включённых записей камеры нет) | `none` |

  На первом шаге объявляются только эти три: `motion` и `sched` не объявляются вместе с «Автоматизацией» (ADR-0094
  доп. (7)) — без `auto` их нечем исполнить: в ответе не отдаются, запись — 422 `NOT_SUPPORTED`, `field: recordMode`;
  справочник `recordModes` — `["none", "always", "replica"]` (глава 2 Н1.5). Записи камеры с иными именами (заведены мимо
  `backend`) режим не меняют; в версию камеры они входят (Н1.3 «Версия»). Переходы режима — глава 4 Н1.2.
- **`archiveId`** камеры — том (`home`) основной `<cam>`, её нет — `null`; **`extraArchives`** — резервные `<cam>-<том>`
  в порядке имени тома байтами: `{archiveId: <id хранилища тома>, recordMode: "always" | "none" по enabled, stream}`;
  **`stream`** — поле `rec/recordings.stream` основной записи (выбор потока записи, V/02.1), не `cam/cameras.main`
  (принадлежность потока, `fixed`; разбор ревью V/11, Codex № 11, Claude Б-6). `recordDetectorIds` — `none`: записи по
  детектору у нас нет.
- **`sensitivity`** детектора ↔ `params` строки `det/units` (V/04.1: строка настроек модели; разбор ревью V/11, Codex
  № 12). Кодек: `params` — текст JSON-объекта (пустая строка — `{}`); `sensitivity` — целое значение его ключа
  `sensitivity`. Чтение: ключа нет или `params` не объект — поля в ответе нет. Запись: прочитать объект, заменить ключ
  `sensitivity` (`null` — снять ключ), прочие ключи сохранить в их порядке, новый — в конец, записать JSON без пробелов;
  `params` не JSON-объект — 422 `NOT_SUPPORTED`, `field: sensitivity` (настройки модели не теряются).
- **`detectorKind`** ↔ `det.kind`: виды `motion`, `linecross` — из реестра воркера (V/04.2); вида нет в реестре —
  строка пишется (`kind` как записан), детектор — `unsupported` (V/04.2 Н1.2), не отказ двери. Вид входит в ключ строки
  (`<cam>-<kind>`): правка `detectorKind` — 422 `NOT_SUPPORTED`, `field: detectorKind`.
- **Ключевое `name`** (разбор ревью V/11, Claude С-5): у детектора и тома `name` — ключ строки (`det/units` —
  `<cam>-<kind>`, `rec/volumes` — `name`), id записи выведен из него. Поле `read`: запись иного `name` — 422
  `NOT_SUPPORTED`, `field: name`, не переименование. Создание хранилища (`POST /archives`) берёт `name` ключом новой
  строки; создание детектора — `name`, равное `<cam>-<kind>`, иное — 422 `NOT_SUPPORTED`, `field: name`. `name` камеры —
  поле строки `cam/cameras`, правится.
- **`Archive.kind`** (разбор ревью V/11, Claude С-17) — по адресу тома: `file://` — `local`; адрес сетевой папки
  (`smb`, `nfs`) — `remote`; адрес бакета — `cloud`. Роль тома у нас (`backup`, `incidents`) в контракт не выходит; том
  `edge` хранилищем не отдаётся (Н1.2). Создание: `local` — `kind: local`, `remote`, `cloud` — `kind: network`.
- **`Archive.retentionDays`** (разбор ревью V/11, Codex № 13, Claude С-2) — срок у записей, не у тома: наибольший
  `retention_days` записей с `home` = этот том; записей нет — умолчание `retention_days` записи (30, V/02.1). Запись
  `retentionDays` — `retention_days` всех записей тома одним пакетом (глава 4 Н1.2); `0` («без ограничения» контракта)
  — 422 `NOT_SUPPORTED`, `field: retentionDays`: у записи срок не меньше 1 суток. Записей тома (со строками их камер —
  замок) больше, чем вмещает пакет B9, — тоже 422 `NOT_SUPPORTED`, `field: retentionDays`, не частичная запись
  (решение «Архитектора» к разбору ревью V/11, 2026-10-30). Создание хранилища: `retentionDays`,
  равное умолчанию записи, пропускается, иное — 422 `NOT_SUPPORTED` (у нового тома записей нет, хранить срок негде);
  новую запись на томе `backend` создаёт со сроком хранилища.
- Поля устройства от правил — `disabledByRuleId`, `disabledByRuleAt` (камеру выключило правило) и `armed` (камера на
  охране, только чтение) — не объявляются вместе с «Автоматизацией» (ADR-0094 доп. (7)): в схеме `Device` они
  необязательны, и `backend` их не отдаёт — поля в ответе нет (Н1.1, `none`). В правке устройства (`DevicePatch`) их нет.
- **Версия записи** (`version`) — **непрозрачная строка** контракта: сравнивается только на равенство, к прежнему
  значению не возвращается, склейка версий частей разрешена (ответ продукта, ADR-0094 доп. (4) п. 1). У записи из одной
  строки — индекс хранилища этой строки (версия строки P/01.1; провод — десятичное число без знака, Н2 P/01.1). У сборной
  камеры — **склейка индексов её частей** (строка камеры и её потоки, записи `rec`, детекторы `det`) в постоянном
  порядке частей; у хранилища — индекс строки тома и индексы записей на нём (от них зависит `retentionDays`); точная
  форма — глава 4 Н1.1. Удалённая часть входит индексом своего надгробия; часть, которой не было, — пусто. Надгробия
  частей не убираются, пока камера жива: снятое надгробие вернуло бы прежнюю склейку (ADR-0094 доп. (4) п. 1 (в)).
  `revision` строки (P/06.1) версией не служит: `DELETE` её не двигает. Индекс строки консоль отдаёт в элементе списка
  `GET /<rows>` и таблиц (норма платформы B4 — после Go GREEN 01–10; разбор ревью V/11, вопрос 6); индекс надгробия —
  `ETag` ответа `DELETE`, сообщение ленты об удалении и чтение `GET /<rows>?deleted=1&about=<cam>` (ADR-0094 доп. (5)
  п. 1). Двери одной строки у консоли нет, «404 с `ETag` надгробия» (доп. (3) п. 9) заменено этим чтением. Надгробие
  строки хранилища — не надгробие тела `.gone/` (договор надгробий ресурса): строка и её надгробие — P/06.1 и ADR-0094
  доп. (2) п. 4 (в). Сейчас двери консоли индекса не отдают.
- **Поля не из строк частей** (разбор ревью V/11, Claude С-1): слова пульса (`online`, `fault`, `usedPercent`,
  `state`), сервер держателя (`serverId` камеры) и строка устройства `cam/devices`, которую пишет держатель (`vendor`,
  `model`, `firmware`, `mac`), в версию не входят — это связь и наблюдение, не конфигурация (контракт: версию не меняют
  «чтение, связь, нагрузка»); `If-Match` о них не судит.

## Н3 Проход

```
операция «переводится» (глава 2) → вид контракта → строки таблицы mapping.tsv этого вида
  чтение: поля way read|both — из места vms; const — значение таблицы; none — поля нет; write — поля нет
  запись: both, write — в место vms (глава 4); read, const — равно прочитанному? пропуск : 422 NOT_SUPPORTED, field
        none — умолчание ответа? пропуск : 422 NOT_SUPPORTED, field
```
