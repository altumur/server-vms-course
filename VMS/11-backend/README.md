# V/11 Бэкенд конфигуратора

Статус: **переведён** (2026-10-30, «Спецификация VMS»; план принят «Архитектором»): главы V/11.1–V/11.7 — нормы; стенд —
по кандидату с нормами платформы B. Основание — ADR-0094 (A1–A7, доп. (1)–(16); B1–B7, B9 — нормы платформы), ADR-0095–ADR-0100.
Платформа — выгрузка `cammeta-specs` `226bd220` (пин VMS; приращение прав поверх норм B, ADR-0090 доп. (17)). Манифест — [`backend.subsystem.yaml`](backend.subsystem.yaml)
(канон; ADR-0090 доп. (6) п. 8). Источники — сессия «Консоль»
(сравнение с consolem, набросок адаптера; справка, не канон).

## Что такое урок V/11

Подсистема `backend`. Интерфейс конфигуратора consolem — наш форк (ADR-0112): WebUI и его контракт с сервером, REST API
`api/openapi.json`. `backend` отдаёт WebUI этот API, переводя каждый вызов в двери консоли платформы. Перевод — на
сервере, но у воркера нет ни своих прав, ни удостоверения человека: консоль передаёт ему запрос с **билетом** на этот
один запрос, и воркер зовёт двери консоли обратно по билету, только из закрытого перечня (ADR-0094 B1). WebUI отдаёт сама
консоль: оболочка `backend.shell.html` и файлы набора продукта (стили, шрифт, словарь); API — под `/backend/api/`.

## Приёмка

Приёмка — тесты API consolem (`tests/api-*.js` на закреплённом коммите) против стенда в профиле возможностей и свой набор
[`acceptance/`](acceptance/) того, чего эти тесты не видят (ADR-0094 доп. (17); глава 6 Н5); `?selftest` — проверка сборки продуктом под нашим CSP (ADR-0094
Confirmation; глава 6 Н1.4). Профиль — таблица урока [`data/profile-tests.tsv`](data/profile-tests.tsv) (V/11.6 Н1.2); она сверяется при новой версии контракта.

## Открытые вопросы

1. **Эталонный набор стенда** (V/11.6 Н1.3) — свой, данными урока **после стенда B** (ADR-0094 доп. (3) п. 10 (4)).
2. **Что от правил не объявлено**: `recordMode: sched` — контракт не называет расписание камеры, вопрос к consolem. `ask`, `escalate` ждут контракта: наша дверь ответа `POST /rules/{id}/fires/{fireId}/answer` спроектирована (V/11.4 Н1.10), вопрос у consolem (запрос 8 п. 2).
3. **Двери вне перечня билета** (P/06.3 Н1.9): `GET /live/where/<cam>` для `POST /devices/{id}/live`, `/live/accounts` для учёток потоков, запись меток серверов для `PATCH /servers/{id}` — не объявлены (V/11.2 № 13, 91, 102–106). Вопрос платформе, перевод учёток готов (V/11.4 Н1.18).
4. **Вопросы продукту с приращением прав**: пароль нового
   человека (`AccessUser` поля нет, V/11.8 Н1.5); какие уровни показывают детекторы; ведение папок; `MON_PROT`; пара `MON` и `ONLY_ARCHIVE`
   (ADR-0097, ADR-0099, ADR-0100, «Запрос продукту»). `dArch: FULL` при `dCam: MON` не становится строкой и читается `FORBID` (V/11.8 Н1.4).
5. **Версия, которая может вернуться** (V/11.4 Н1.1: части `h`, `i` стражами не идут и тоже могут вернуть склейку; у снимка прав V/11.8 Н1.1 то же, если строку завели и сняли): потоки камеры и записи тома входят в версию живыми строками —
   их надгробий по камере или тому не найти; создание и снятие такой строки мимо `backend` возвращает прежнюю склейку
   при той же видимой записи. Строгое «не возвращается» продукта здесь не держится.

7. **`probe` без учётных данных** (V/01.8 Н1.3, V/11.4 Н1.9): в `DeviceProbeRequest` нет логина и пароля, автоопределению они нужны; устройство, которое без входа модели не называет, даёт `model: null`. Ответа consolem нет (запрос 9, дополнение п. 4).
8. **Что не выражает закреплённый контракт** (V/11.3 Н1.3): источник `replica`, резерв `backup` ждут нового коммита контракта (ADR-0107). Имя пресета (V/11.4 Н1.16) и действие `unit` правила (V/11.3 Н1.3): места у нас нет.
9. **Сборка WebUI** (V/11.1 Н1.4): оболочка и набор — ещё `785824c`, контракт — `52c1113`. Форма `785824c` зовёт `GET /settings` без объявления и на `NO_ROUTE` не стартует: до байтов сборки `52c1113` стенд WebUI не поднять.
