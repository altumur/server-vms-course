# V/11.5 — Обратный вызов и поток: нормы

Канон главы 5 урока V/11 «Бэкенд конфигуратора» (ADR-0094 B1, B2). Лекция (`ru/11-backend.md`, для человека, в выгрузку не входит),
[инструкция](11-backend.README.md), контракт [`consolem.openapi.json`](../../consolem.openapi.json). Платформа — по [`VMS/PLATFORM_PIN`](../../../PLATFORM_PIN) (ADR-VMS-0002) (пин VMS; приращение прав поверх норм B, ADR-0090 доп. (17); пометка «норма платформы B» — где глава на них опирается).

Текст производный от `spec/11.5-backend.norms.md`, руками не правится: источник — английский [`spec/11.5-backend.norms.md`](../../spec/11.5-backend.norms.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Воркер `backend` не держит ни удостоверения человека, ни своих прав: всё, что он читает и пишет, он зовёт у консоли с
билетом запроса, который сейчас переводит. Поток `/stream` контракта — те же билеты, но долгоживущий запрос: консоль
передаёт его потоком, а `backend` переводит её ленту изменений в сообщения контракта. Глава нормирует сторону `backend`:
когда и как он зовёт консоль и что шлёт в поток.

Id норм — `V/11.5-MM`.

## N0 Словарь слов

Нормативные слова — по [канону курса](../../../../Platform/common/ru/NORMATIVE-TERMS.md). Правила модуля «Платформа» — [P/01.1
N0](../../../../Platform/01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

- **Билет** — 128 случайных бит, которые консоль выдала на один открытый запрос человека и передала воркеру (B1).
- **Лента** — `GET /changes` консоли: сообщения «строка X — ревизия R / удалена», без значения (B2).
- **Виды устройств** — виды, чей `uid` строится от имени `device:…` ([`mapping.tsv`](../../data/mapping.tsv), глава 4 N1.6): `camera`, `det`, `ipsrv`, `channel`, `sensor`, `relay`, `mic`, `spk`, `storage`, `eventsrc`, `acfa`, `acfa_sensor`, `acfa_lock`, `acfa_fence`, `stream`. **Решено:** это записи, которые прежние контракты отдавали как `kind: device`; контракт 0.2.0 называет каждую её видом (глава 14 N1.1).

## N1 Форма

**Время.** Сроки главы — секунды монотонных часов процесса.

### N1.1 Обратный вызов по билету

- Воркер зовёт консоль только **с билетом того запроса**, который сейчас переводит, и только на двери перечня
  (V/11.1 N1.5); билет не хранится после ответа на запрос, не передаётся другим запросам и не пишется в журнал.
- Консоль принимает билет, пока внешний запрос открыт, на слушателе обратного вызова (`CONSOLE_CALL_PORT`, адрес —
  заголовок `X-W2C-Pass-Console`) с листом роли `backend` сервера того экземпляра, которому передала запрос (без
  комплекта — сокетом роли; V/11.1 N1.2, ADR-0094 доп. (6) пп. 1, 2), на двери перечня, при той же проверке, что токен двери (отзыв `jti`, срок `exp`, ключ `kid` записи билета у консоли),
  иначе — 401, и при свежем `may` человека, отказ — 403 (B1, ADR-0094 доп. (3) п. 1; норма платформы B). Воркер получает только 128 бит билета,
  полей записи не видит. Для `backend` 401 обратного вызова — конец перевода: ответ запросу — 401 `UNAUTHORIZED` (глава
  4 N4), повтора с тем же билетом нет.
- Ответ человеку закрыт (браузер ушёл) — билет мёртв: воркер прекращает перевод, ничего не дописывает.
- Предел ожидания передачи — по маршруту (V/11.1 N1.5): групповая запись (`api/units`, `api/objects/delete`)
  успевает пакеты по порядку; не успела — консоль закрывает запрос, воркер видит мёртвый билет (как выше), а сделанные
  шаги уже записаны в память группы (глава 4 N1.4): повтор её продолжит.

### N1.2 Поток `/stream` из ленты `/changes`

- `GET /stream` (адрес консоли `/backend/api/stream`) передаётся потоком (маршрут `api/stream`, V/11.1 N1.5; B1):
  билет потока годится только на чтения и `/changes`. Лента — длинный опрос, не SSE (P/06.1 N2 «Лента изменений», B2):
  `GET /changes?after=<number>&wait=<s>` → `{position, changes, reset?}`, `wait` не больше `CHANGES_WAIT`. На поток
  браузера `backend` держит один такой опрос за другим: следующий — с `after` = `position` прошлого ответа. Браузеру он
  шлёт `text/event-stream`: на сообщение — строки `id:` и `data:` (`StreamMessage`), без `event:` (контракт).
- **`stream.hello`** — первое сообщение каждого соединения, и при `Last-Event-ID`: `clientId` — новые случайные 128 бит hex, `id` — `<position>`, `at` — момент открытия. После него — начало подписки ниже.
- **`PUT /stream/{clientId}/watch`** (`StreamWatch`): `ids` до `watchMax`, больше — 422 `VALIDATION_FAILED`, `field: ids`; заменяет прошлый список. Список держит поток, память процесса: нет такого потока или он другого человека — 404 `NOT_FOUND`. Записи нет: билет этого маршрута годится только на чтения (маршрут `api/stream`). При двух экземплярах `PUT` не тому — тоже 404: форма переоткрывает поток `GET /stream?watch=<id,id,…>` и перечитывает наблюдаемые (ADR-0112 доп. (12) п. 2).
- **`watch` запроса открытия:** id через запятую, до `watchMax`, больше — 422 `VALIDATION_FAILED`, `field: watch` до открытия потока; пусто — как нет параметра. Список действует с открытия, при `Last-Event-ID` тоже; `PUT` его заменяет.
- **Что идёт по наблюдаемым.** Виды устройств (N0) — только запись из `ids` и её дети: `entityId` в `ids` или `parentId` записи в `ids`, чтение строки всё равно есть (ниже). Новый список сообщений за прошлое не даёт: форма читает сама. Список пуст — событий устройств нет, в том числе у потока без `watch`, пока не дошёл `PUT`: форма шлёт его сразу после `stream.hello`, а `PUT` не тому экземпляру даёт 404 и новый поток со списком. Всплеска на соединение нет: досылка по `Last-Event-ID` тоже идёт по списку. Остальные `kind`, `tree.changed`, операции, правила — всем. Цена запроса — одно сравнение с памятью: постоянная; обход страниц («Чужое» ниже) остаётся.
- **`tree.changed`** (`layout`, `parentIds`) идёт за сообщением своего вида тем же номером `k + 1`, если запись родилась, снята, сменила имя или родителя: `folders` — `folder`, родитель-папка; `servers` — `server` и виды устройств, родитель — сервер, у камеры-кластера домен; `archives` — виды хранилищ `archive.*`, `volume`, родитель — хранилище, домен; `detectors` — `det`, родитель — камера. Сообщение идёт всем. **Предел:** состав папки в домене лента не несёт, `memberof` не шлётся: поток о нём молчит, форма видит его при раскрытии.
- **`kind` сообщения** — открытая строка (контракт; глава 14 N1.2): у записи `/units` — код вида записи (`camera`, `archive.local`, `volume`, `folder`, …, глава 14 N1.1), у остальных — слова таблицы ниже (`rule`, `operation`, `discovery`, `exportJob`, …). Иного значения `backend` не шлёт.

Строка потока — запись вида `stream` и часть камеры (глава 3 N1.3 «Потоки»): **Решено:** `entity.created`, `entity.changed`, `entity.deleted` потока (`kind: stream`), затем `entity.changed` камеры — её `version` (производные сообщения ниже). Сама строка камеры — и её основной поток (`uid` `…#main`, глава 3 N1.2): её правка даёт сначала `entity.changed` камеры (`kind: camera`), затем основного потока (`kind: stream`). `kind: streamAccounts` не шлётся: учётки не объявлены (глава 4 N1.18).

- **Производные сообщения** (разбор ревью V/11, Codex № 18, Claude S-15, вопрос 11). Одно сообщение ленты может дать
  несколько `StreamMessage` — по строкам таблицы выше, в порядке: сообщение своего вида строки, затем камеры, затем
  хранилища (у тома — вид хранилища `archive.<kind>`, затем `volume`). У каждого свой `type`. Удалённый детектор: `entity.deleted`
  детектора (его id — из ключа надгробия), затем `entity.changed` камеры — её версия с индексом надгробия
  (`?deleted=1&about=`, глава 4 N1.1); камеры уже нет — сообщения камеры нет.

- `version` сообщения — версия записи вида по главе 4 N1.1 (индекс хранилища; B4): лента несёт «строка X — ревизия R»
  без индекса, поэтому `backend` дочитывает строку дверью перечня, прежде чем послать сообщение. Дочитывание ответило
  404 (строку уже сняли) или 403 — сообщение не шлётся: удаление придёт своим сообщением ленты; иной отказ дочитывания и
  три несовпадения двойного чтения — поток закрыт, как отказ ленты (N4); `revision` прочитанной строки
  выше `R` — шлётся версия прочитанной (разбор ревью V/11, дополнение Kimi, № 6).
- **Поля тела** `StreamMessage` (контракт: обязательны `id`, `type`, `at`; дополнение Kimi, № 5, вопрос 2): `id` тела
  равен строке SSE `id:`; `at` — время события на сервере, не отправки, RFC 3339 UTC: у сообщения ленты — поле `at` ленты,
  число JSON, секунды такта консоли, увидевшего версию строки; позже приёма хранилищем оно не больше чем на такт, и
  досылка отдаёт то же значение (норма платформы B2); у событий хода
  ассистента (глава 7) — момент, когда `backend` их произвёл. Смысл `at` продукту названо в третьем запросе — подтвердить.
- **`id` сообщения** — `<p>-<k>`: `p` — номер, после которого лента отдаёт это сообщение (`n` предыдущего сообщения
  ответа, у первого — `after` запроса), `k` — номер производного сообщения в нём с 0 (вопрос 11). Берётся `p`, а не `n`:
  лента отдаёт только сообщения **после** номера, и обрыв между производными иначе потерял бы остаток. `-` в номере ленты
  нет (P/06.1 N2). Для клиента `id` непрозрачен (контракт).
- **Начало подписки** (ADR-0094 доп. (3) п. 6): первый запрос без `after` сразу отвечает `{position, changes: []}`;
  `backend` шлёт браузеру строку SSE `id: <position>` без `data:` — по SSE она ставит последний `id` браузера и события не
  даёт, поэтому `StreamMessage` у неё нет и `type` не нужен. Клиент применяет сообщения с отбросом ревизии не выше
  прочитанной.
- **`Last-Event-ID`** браузера (заголовок проходит передачу второго вида, V/11.1 N1.5): `<p>` — `after=<p>`; `<p>-<k>` —
  `after=<p>` и пропустить первые `k + 1` производных первого сообщения; иная форма — как начало подписки, с
  `stream.reset`.
- **`reset`** — ответ `{position, changes: [], reset: true}` (чужой или вытесненный номер, перезапуск экземпляра консоли,
  смена прав или меток человека, B2): `stream.reset` с `id` `<position>`, браузер перечитывает всё, опрос идёт с
  `after=<position>`.
- **Удаление папки** (ADR-0096 §3): лента несёт только саму папку, а подпапки недостижимы с того же индекса. Дочитывание строки папки — `GET /folders`
  целиком: это же чтение обновляет дерево потока. `backend` помнит дерево последнего чтения этого потока и после `entity.deleted` папки шлёт `entity.deleted` каждому потомку, который был достижим до удаления, в
  порядке `id`; это производные сообщения того же сообщения ленты. Дерева в памяти нет (начало потока) — только сама папка; браузер всё
  равно получит 404 на чтении потомка.
- **Строки операции.** Ленту по билету консоль отдаёт только операции автора (P/06.9 N2), поэтому чужих сообщений поток не несёт. Значения —
  дочитыванием двери `GET /backend/operations/<id>`; порядок шагов сверх ленты не обещан, истина — `GET /operations/{id}`.
- **Права.** Строк домена лента не несёт: сообщений `kind: access` нет, WebUI перечитывает снимок сам. Сброс ленты при смене ролей — как
  прочий `reset`.
- **Конец поиска** по сроку ленте не виден: строки нет, поэтому `discovery.finished` шлёт таймер потока, поток запоминает `until` и при открытии, `id` — `<position>-<k>` последнего ответа ленты, `k` следующий.
  Обрыв потока такое сообщение не досылает: итог читается `GET` (глава 4 N1.9).
- **Журнал потоком** (ADR-0112 доп. (13)). Поток с непустым списком наблюдения раз в `JOURNAL_POLL` = 3 с читает `GET /events?from=<t>` кластера и отбирает в памяти; окно сдвигается по `t` с запасом `JOURNAL_SETTLE` = 5 с: выборка `/events` идёт по `t`, строка другого ресурса приходит поздно, без запаса она терялась бы, дубли убирает `id`. Отбор: строка единицы из списка, её родителя или `eventsrc` с `camera` из списка — `journal.event`, `entityId` — устройство, `payload` — `JournalEvent` с `cameraId`; `kind: mark` — ещё `entity.created` `bookmark` всем, `entityId` — id отметки, `payload: {deviceId}`. Дубли — по `id`. Лента журнала не несёт, поэтому это опрос на поток, не сообщение. **Цена:** один вопрос раз в 3 с на поток, ответ растёт с журналом кластера. **Предел:** `truncated` теряет строки до следующего чтения формы; журнал чужого кластера поток не читает; задержка титра — до 3 с и `JOURNAL_SETTLE`.
- **Удержание:** строка `rec/keeps/<key>` — `entity.created`, `entity.changed`, `entity.deleted`, `kind: hold`, `entityId` — ключ, он не UUID, `payload: {deviceId}`, всем.
- **Выгрузка:** `export.progress`, `export.finished`, `kind: exportJob` (контракт: вид `export` занят объектом «Агент экспорта»), `entityId` — заказ, только автору (`by` частей — человек потока): состояния частей `exp/parts/<name>` в ленте нет, поэтому поток читает его не чаще `VIEW_POLL`, пока у автора есть незаконченный заказ, — глава 20 N1.9.
- **Журнал и пульс** (ADR-0105): запуск правила — строка журнала, смена режима — слово пульса, а лента их не несёт (P/06.1 N2 «Лента изменений» «Охват»). При открытии потока оба значения запоминаются, сообщений нет. `id` — как у конца поиска. Вопросы — та же очередь: не чаще `VIEW_POLL` на поток он читает `GET /auto/scenarios` своего кластера, цена постоянна, сравнивает вопросы главы 3 N1.3 с запомненными: новый — `prompt.opened` (`kind: rulePrompt`, `entityId`, `payload: {ruleId, fireId, step, roleId, level}`), пропавший — `prompt.closed` с `payload: {ruleId, fireId, step, reason}`, `reason` по строке конца шага в журнале сработки (V/07.4 N1.6): `note` `ask.answer`, `label` `esc.ack` — `answered`, ещё `answer` — `yes`, `no`, у `esc.ack` `ack`, и `by` — `user` строки; `note` `ask.noAnswer`, `answer.unread`, `label` `esc.none` — `expired`; `label` `esc.reset` — `reset`. Строка конца ложится после записи шага, поэтому сообщение ждёт её один `VIEW_POLL`; нет и тогда — `stopped`: снятый запуск таких строк не пишет. **Предел:** строка, легшая позже этого ожидания, и падение между записью и строкой (V/07.4 N1.11) тоже читаются `stopped`: `VIEW_POLL` покрывает только обычную задержку строки. **Предел:** задержка — ответ ленты, до `CHANGES_WAIT`; обрыв не досылает: истина — `GET /rules/{id}/fires`, `GET /modes/current`, `GET /archive-scans`.

Поэтому после ответа ленты, не чаще раза в `VIEW_POLL` = 5 с на поток, значение без опоры, поток читает одну страницу `GET domain` и таблицы только её членов `class: server`, камеры-кластеры сравниваются по `units` страницы, как перечень, с `If-None-Match` (глава 3 N1.2a «Цена») и билетом потока, следующую страницу — на следующем `VIEW_POLL`, по кругу (ADR-0113 доп. Таблица члена не прочитана — записи этого вида у него не сравниваются: пропажа не доказана, `entity.deleted` нет. ## N3 Проход

```
запрос контракта с билетом
  каждый обратный вызов — с этим билетом, только дверь перечня
  401 обратного вызова → ответ 401 UNAUTHORIZED, перевод окончен
GET /stream (поток, билет потока)
  нет Last-Event-ID → GET /changes без after → id: <position> без data:
  Last-Event-ID <p> → after=<p>; <p>-<k> → after=<p>, пропустить k + 1 производных первого сообщения
  повторять GET /changes?after=<position>&wait=<с>:
    сообщение ленты → виды (глава 3) → дочитать строку → StreamMessage k = 0, 1, … (id <p>-<k>, data)
    reset: true → stream.reset (id <position>)
    новая сработка журнала, иной режим → ruleFire, objectMode (id <position>-<k>)
    GET domain, одна страница: 200 → таблицы её членов class server, units прочих, сравнение → entity.* чужих записей (id <position>-<k>); не 200, не 403 → сравнения нет
  поток браузера закрыт → опрос прекращён
```

## N4 Отказы

| Причина | Исход | Кто видит | Что делает вызывающий |
|---|---|---|---|
| обратный вызов — 401 (билет мёртв, дверь вне перечня, нет сертификата роли `backend`, лист иного сервера) | ответ 401 `UNAUTHORIZED` | WebUI | вход консоли или повтор запроса |
| лента ответила `reset` | `stream.reset` | WebUI | перечитать всё |
| запрос ленты отказал или оборвался; дочитывание отказало не 404 и не 403 или дало три несовпадения | поток закрыт | WebUI | переподключиться с `Last-Event-ID` |
