# V/11.6 — Стенд и приёмка: нормы

Канон главы 6 урока V/11 «Бэкенд конфигуратора» (ADR-0094 A5, Confirmation; доп. (2) п. 2; ADR-0050).
Лекция (`ru/11-backend.md`, для человека, в выгрузку не входит), [инструкция](11-backend.README.md), контракт
[`consolem.openapi.json`](../../consolem.openapi.json). Платформа — по [`VMS/PLATFORM_PIN`](../../../PLATFORM_PIN) (ADR-VMS-0002) (пин VMS; приращение прав поверх норм B, ADR-0090 доп. (17); пометка «норма платформы B» — где глава на них опирается). Стенд `backend` собирается только на выгрузке с ними.

Текст производный от `spec/11.6-backend.norms.md`, руками не правится: источник — английский [`spec/11.6-backend.norms.md`](../../spec/11.6-backend.norms.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Приёмку `backend` пишет не курс: критерий готовности — тесты API самого продукта, которые его бэкенд-команда гоняет против
своего сервера. Наш `backend` проходит те же тесты против нашего стенда — в профиле того, что у нас есть (глава 2).
Чего эти тесты не видят, проверяет свой набор урока [`acceptance/`](../../acceptance/) (ADR-0094 доп. (17)). Глава нормирует стенд, профиль, служебные
`/test/*`, границу набора и место `?selftest`.

Id норм — `V/11.6-MM`; соответствие — [`id-map.tsv`](../../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../../Platform/common/ru/NORMATIVE-TERMS.md). Правила модуля «Платформа» — [P/01.1
Н0](../../../../Platform/01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

- **Тесты API продукта** — `tests/api-*.js` репозитория форка consolem на закреплённом коммите (страница `tests/api.html`, стенд
  тестов `tests/harness.js`; описание — `api/TESTS.md` продукта).
- **Профиль возможностей** — перечень операций и тестов, которые наш стенд проходит: операции «переводится» главы 2, таблица тестов — Н1.2.

## Н1 Форма

### Н1.1 Стенд

- Стенд VMS ([общий README приёмки VMS](../../../common/ru/acceptance/README.md) «Стенд VMS») с манифестами `cam`, `rec`,
  `det`, `auto`, `backend` и вычислителем `auto`: режим объекта и проба правила — его слова (глава 4 Н1.10, Н1.11); консоль с нормами
  платформы B1 (передача с билетом), B2 (лента), B3–B6, B7 (статические файлы подсистемы), B9 (пакетная запись); стенд с
  комплектами ролей (TLS): строка `backend/instances/main` с метками сервера стенда и воркер `backend` с листом роли
  `backend` (V/11.1 Н1.2); файлы WebUI рядом с манифестом `backend` (V/11.1 Н1.4). Обратный вызов с листа чужой роли и с
  листа другого сервера — 401 (ADR-0094 доп. (6) п. 5; приёмка платформы B). Без комплекта — сокет роли на петле (доп.
  (6) п. 4). До приращения платформы стенда нет — глава проверяется чтением.
- Тесты зовут API по адресу консоли `/backend/api/…` (сервер контракта — V/11.1 Н1.5) сессией человека стенда (кука или
  `Authorization: Bearer`).

### Н1.2 Профиль возможностей

- Профиль — операции «переводится» главы 2 Н1.2 и таблица тестов (ниже). Тесты, которые зовут операции «`NO_ROUTE`», профиль исключает; проверка самого
  `404 NO_ROUTE` неизвестной операции — в профиле.
- Профиль — таблица урока [`data/profile.tsv`](../../data/profile.tsv): строка на операцию контракта, `profile` — `in`, `out`
  (`404 NO_ROUTE`) или `stand` (`/test/*`); её читает драйвер стенда (ADR-0094 доп. (3) п. 10 (6)). Сверяется при новой
  версии контракта (глава 2). Продукт ответил (ADR-0094 доп. (4)): объявление возможностей — в `GET /reference`, набор —
  `one-domain`, часы — `--clock real`. `backend` отдаёт объявление по главе 2 Н1.5: его `operations` — строки `in`
  таблицы. Объявление и таблица сверяются, расхождение — исправление таблицы, не молчаливая замена. `api-rules.js` — в профиле, кроме строк `out` таблицы тестов.
- **Таблица тестов** — [`data/profile-tests.tsv`](../../data/profile-tests.tsv) (ADR-0094 доп. (18)): строка на проверку страницы на закреплённом коммите, `profile` —
  `in` (обязана пройти), `skip` (страница пропускает сама), `out` (вне профиля), с причиной: 68 / 87 / 206 из 361 (форк `cb728a4`, контракт 0.2.0: 357 тестов 16 файлов и 4 сквозные проверки). Страница пропускает только по `needs` теста (операции, `feature:`, `kind:`, `cap:`, `under:`, `class:`, `implements:`, `clock` против `capabilities` и `GET /kinds`), а не каждый тест
  называет, что ему нужно: на необъявленной операции тест падает, и `data-apitest` страницы даст `fail` на любом `backend`. Поэтому **судит драйвер**: один полный прогон, затем строки
  отчёта сверяются с таблицей. Строка `in` — только `PASS`, строка `skip` — только `SKIP`, строка `out` не судится; имя в отчёте без строки таблицы — провал. `&only=` не годится: при нём страница не доходит до сквозной проверки `Неподдержанные операции отвечают 404 NO_ROUTE`, а она в профиле. Тесты `out` исполняются в том же прогоне,
  не судится только их строка.
- **Перенос строки.** Строка `in` уходит в `out` только с причиной-нормой: падение без такой причины — ошибка `backend`, не правка таблицы. Если тест уносит операцию или норму, перенос
  идёт вместе с проверкой в `acceptance/` (ADR-0094 доп. (18) п. 3). Сквозная проверка `Каждая объявленная операция покрыта тестами` — `out`: `GET /exports`, `POST /exports/{exportId}/cancel`, `retry-failed`, `POST /exports/{exportId}/files/{fileId}/link` зовут только тесты `out`, которые падают раньше (выгрузка без держателя `exp` не завершается или `fixturePatch` на сбросе). Покрытие держит свой
  набор: 61 из 116 объявленных операций, которые не зовёт ни один тест `in` (чтением тел тестов), `@manual` там, где стенд не держит: `GET /me/export`, `POST /operations/{operationId}/cancel`, `retry-failed`, `POST`, `DELETE /domains/{domainId}/discovery`, `GET /rules`, `PUT`, `DELETE /schedules/{scheduleId}`, `GET /licenses`, `GET /journal`, пять операций `/stream-accounts…`, четыре `/archive-watches…`, три `/archive-scans…`, `GET /rule-prompts`, `POST /rule-prompts/{promptId}/answer`, `GET /tree/paths`, три `/domains/{domainId}/scenarios…`, две `/domains/{domainId}/relays…`, `DELETE /holds/{holdId}`, `POST /holds/{holdId}/verify`, `POST /kinds/{kind}/actions/{action}`, `POST /units/{uid}/move`; из `/units/{uid}/…` — `live` (`POST`, `PUT`), `talk`, `timeline`, `playback`, `holds` (`GET`, `POST`), `bookmarks` (`GET`, `POST`), `archive-fetch`, `ptz` (`PUT`, `DELETE`), `presets/{n}` (`PUT`, `DELETE`), `recording-target`, `recording-days`, `creatable`, `schema`; `POST /units/validate`; восемь операций `/exports…` (глава 2 Н1.2, № 115–122).
  Основа тестов продукта у нас уже, чем контракт: 65 тестов и 3 сквозные проверки из 361.
- **Набор.** Драйвер отдаёт набор в форме контракта 0.2.0: объекты — `units` (коды видов, `Unit.folders`), описания видов — `kinds` (те, что в `GET /kinds`). Разделы, из которых тесты берут ожидаемое (`FX.domains`, `servers`, `devices`, `folders` с `deviceIds`, `archives`, `volumes`), страница выводит из `units` сама (`legacyFixture` из `api/server.js`, `tests/harness.js`), поэтому заглушка грузит скрипты страницы как есть. По `kind:` тест пропускается, только если вид не объявлен или у него нет `create` и объекта этого вида в наборе нет (`tests/harness.js`): объектов видов `sensor`, `relay`, `mic`, `spk`, `storage`, `ipsrv`, `acfa…`, `eventsrc` в наборе нет — их пишут держатели, а держателей у стенда нет.
- **Часы.** При `clock=real` тесты с `needs: clock` страница пропускает (`skip`). Тест с веткой по времени стенда («Текущий администратор и часы сервера») — `in`.
- Тесты, которые опираются на эталонный набор продукта (домены, серверы, устройства его демо-данных), на нашем стенде идут
  против своего эталонного набора (Н1.3); где набор продукта у нас невыразим — тест вне профиля, причина — в списке.

### Н1.3 Служебные `/test/*`

- Только на стенде (ADR-0050: настройка процесса и петля): стенд задаёт ключ `TEST_SUPPORT` = `1` файла подсистемы, и
  исполняются только передачи с отметкой петли `X-W2C-Loopback: 1` — её ставит консоль, когда её TCP-клиент — петля
  (V/11.1 Н1.5; норма платформы B1; разбор ревью V/11, вопрос 4); иначе — `404 TEST_SUPPORT_OFF`
  (контракт; ADR-0094 доп. (2) п. 2). Свой TCP-пир `backend` не судит: это всегда консоль. Файл подсистемы
  `/etc/backend/backend.env` читает воркер по [договору файла окружения](../../../../Platform/common/ru/contracts/env-file.md)
  (`W2C_SUB_ENV`, P/02.4 Н1.2; нет файла — умолчания; не читается или значение не по грамматике — отказ старта, код 2;
  сводка — V/09.2):

| Ключ | Читает | Грамматика | Умолчание | Норма |
|---|---|---|---|---|
| `TEST_SUPPORT` | воркер `backend` | `0` \| `1` | `0` | Н1.3 |

- `POST /test/reset` — стенд приводит кластер к своему эталонному набору дверями консоли и домена по билету: отменяет незавершённые операции и ждёт их `state: done` (корни заняты до завершения, P/06.9 Н1.3): перечня операций у двери нет, поэтому id берёт обходом таблицы `backend/repeats`, строки `op: createOperation` с полем `operation`, завершённая отвечает 409 — пропустить; `retry-failed` строки памяти не имеет, поэтому при `TEST_SUPPORT` = `1` он пишет такую строку сам, `idem_key` — `retry:<новый id>`, `user` — человек билета, `h` — как у строки памяти (глава 4 Н1.4) от него и `idem_key`, `body` — SHA-256 тела запроса, `state: done`, снимает записи вне набора, пишет строки `cam`, `rec`, `det`, `auto` и её таблиц, тома, папки, людей, роли, гранты, а строки `history`, `undo`, `repeats` снимает: `GET /operations` читает их. Срок — ключ `api/test` в `wait` манифеста: пяти секунд `PASS_WAIT` на набор не хватит. Журнал растёт и сбросом не откатывается: его тесты — `out`.
  Номер камеры не повторяется, а id папки случаен (P/06.1, P/06.8): удалённую запись набора сброс с прежним id не вернёт, поэтому тесты, которые её удаляют, — `out`. Подмены id в заглушке нет.
  Тесты `out` исполняются, поэтому записи, удалённые ими, сброс не пишет и на них не падает, а тесты `in` на них не опираются: первая камера с дочерним и камера первого архива в наборе — разные.
  Всё это —  обычными записями, поэтому поток несёт их сообщения `entity.*`, а `test.reset` не шлётся (глава 5
  Н1.2; разбор ревью V/11, Claude С-19). Тесты, которые ждут `test.reset`, — вне профиля, строкой списка профиля с
  причиной. `POST /test/clock` — сдвиг часов стенда, если стенд его даёт (часы платформы на стенде — норма стенда
  платформы), иначе — `404 TEST_SUPPORT_OFF`.
- `POST /test/stream-elsewhere` — 204: открытые потоки этого экземпляра идут дальше, `PUT /stream/{clientId}/watch` на них — 404 `NOT_FOUND`, как у чужого экземпляра; поток, открытый после вызова, обычный. Метка в памяти потока, записи нет (глава 5 Н1.2).
- `POST /test/events` — `404 NO_ROUTE` (глава 2 Н1.2, № 55; разбор ревью V/11, Codex № 15): контракт обещает, что
  сервер меняет объект по событию извне (связь `online`, `fault`, найденный или пропавший объект, новый родитель; сигнал входа, запись журнала,
  исход сценария, связь домена, событие вида) и шлёт изменение в поток, а у нас это слова пульса держателей
  (`cam` — V/01.2) и домена, дверью их не подделать. Тесты, которые на него опираются, — вне профиля.
- `PUT /test/kinds/{kind}` — `404 NO_ROUTE` (глава 2 Н1.2, № 126): описания видов собираются из манифестов (глава 14 Н1.5),
  описание на ходу не заменяется. Тесты, которые на него опираются, — вне профиля.
- `fixturePatch`, `actAs` тела `POST /test/reset` стенд не исполняет: 422 `NOT_SUPPORTED`, `field: fixturePatch` | `actAs`; набор не `one-domain` в `fixture` — 404 `NOT_FOUND` (контракт: стенд умеет те наборы, что подходят его системе); `freezeClock: true` или нет поля `freezeClock` (умолчание контракта — «остановить часы») — 422 `NOT_SUPPORTED`, `field: freezeClock`: часы стенда идут (`--clock real`; контракт: стенд, который часы остановить не может, принимает только `false`). Эталонный набор один, а `actAs` у контракта — другой администратор, чего не видит
  и наш свой набор: второго человека с меньшими правами проверяет он (Н5). Их тесты — `out`.
- **Необязательные большие наборы.** `large` и `xl` — необязательные наборы upstream для замеров интерфейса, вне профиля этого стенда; они не требуются, этот стенд отвечает на них 404 `NOT_FOUND`.
- Эталонный набор стенда — свой, данными урока **после стенда B** (ADR-0094 доп. (3) п. 10 (4)): набор продукта у нас
  невыразим целиком (домены, серверы, роли с непереводимыми значениями). Ожидаемое тесты берут из `CONSOLEM_FIXTURES`, поэтому драйвер отдаёт им этот же набор, в форме
  `api/fixture.js`, под именем `one-domain`; каталогов в наборе нет, адреса `10.9.9.9:80` тоже (его берут новые камеры тестов, `unique`), сервер `online: false` есть: `api-hardware.js` читает его при загрузке, а тесты с ним — `out`.
  Набор держит по тому `backup`, `edge`, `incidents`: `api-archive.js` читает их при загрузке, иначе файл не загрузится и упадёт сквозная проверка. Камера «Главный вход» — без детектора `motion`: его создаёт тест дочернего объекта; хотя бы одна камера с детектором `motion` есть: тест `noDetector` ждёт отбора не всех камер. Камер с сервером на связи — не меньше 20: на них идёт длинная операция тестов занятости и паузы. Камеры верхнего уровня — на двух серверах и больше, запись сервера `online: false` годится: тест отбора потока берёт камеру на другом сервере, правка имени связи не требует. `kinds` набора — те, что в `GET /kinds`: `api-archive.js` читает при загрузке перечень `detectorKind` у `det` и `x-archive` у `archive.edge`. Распределённый сервер на связи с тремя свободными несистемными дисками есть, и каждое хранилище называет сервер набора: `api-storage.js` читает их при загрузке. Распределённый сервер на связи без `archive.edge` со свободным несистемным диском есть: тест `in` видов хранилищ строит на нём свою строку.
- **Правила набора.** Набор несёт правила и расписания с именами, которые ждут тесты (`Охрана входа ночью`, `Тревога на периметре`, `Камера пропала — писать соседнюю`, `Внерабочее время в будни`, `Ночь`, `По средам 02:00–03:00`, `Рабочие дни`, `Праздники РФ`), только с объявленными шагами (глава 2 Н1.5): `ask`, `wall`, `armed` набора продукта включённым правилом у нас не сохраняются. `recordMode: sched` в наборе нет. `ruleFires` набора пуст.
- **Двойник поиска.** Живого поиска стенд не даёт, поэтому строки базового воркера `cam` (V/01.8) пишет программа стенда дверью хранилища. После каждого `POST /test/reset` — законченный поиск: строка
  `cam/searches/<CLUSTER>` с вышедшим `until` и строки `cam/found` находок набора. На строку `cam/probes` — ответ с `model` по таблице набора, `vendor` вне таблицы — ответ без `model`. `network` и `discovery` набора `one-domain` — те же находки,
  `id` — по главе 4 Н1.6; `reference.deviceModels` набора называет `model` этих ответов.
- **Версии набора.** Индекс хранилища не повторяется, поэтому после сброса версии новые, а тесты шлют версии из `FX`, и объект там один на весь прогон. После каждого `POST /test/reset` заглушка
  перечитывает записи и обновляет `version` **на месте** в объектах `FX` (его `units` и выведенных разделах): файлы тестов исполняются как есть, `draft()` копирует `FX.access` при вызове и получает свежее.

### Н1.4 `?selftest`

`?selftest` — самопроверка WebUI продукта изнутри страницы (сценарии интерфейса `tests/selftest.js` и `tests/ui-*.js`
продукта). В сборку WebUI она не входит (V/11.1 Н1.4: встроенного сервера, наборов и самопроверки в сборке нет), поэтому
на нашем стенде её нет. Сборку под CSP консоли продукт проверяет сам: его проверка сборки поднимает стенд продукта в
роли консоли (`/backend/` с заголовком `script-src 'self'; object-src 'none'; base-uri 'none'`, API под
`/backend/api/`) и открывает самопроверку форка (ответ на запрос `2026-10-29-w2c-webui-csp-request.md`). Пункт `?selftest` ADR-0094 Confirmation исполняет
форк этой проверкой на каждой сборке, которую мы закрепляем; приёмка урока на нашем стенде — тесты API (Н1.2).

## Н2 Двери

Своей двери у главы нет: `/test/*` — операции контракта за передачей консоли (V/11.1 Н1.5).

## Н3 Проход

```
стенд VMS с комплектами ролей + консоль с B1–B7, B9 + backend по меткам (TEST_SUPPORT=1 файла подсистемы)
  тесты api-*.js полным прогоном против /backend/api/… → драйвер сверяет отчёт с data/profile-tests.tsv
  /test/reset, /test/clock, /test/stream-elsewhere с отметкой петли и TEST_SUPPORT=1 → исполнить (Н1.3); иначе → 404 TEST_SUPPORT_OFF
  fixturePatch, actAs, freezeClock не false в теле /test/reset → 422 NOT_SUPPORTED; fixture не one-domain → 404 NOT_FOUND
  /test/events, PUT /test/kinds/{kind} → 404 NO_ROUTE
```

## Н4 Отказы

| Причина | Код | `code` | Что делает вызывающий |
|---|---|---|---|
| `/test/reset`, `/test/clock`, `/test/stream-elsewhere` вне стенда или без отметки петли | 404 | `TEST_SUPPORT_OFF` | — |
| `/test/events`, `PUT /test/kinds/{kind}` | 404 | `NO_ROUTE` | — |
| `POST /test/clock` без часов стенда | 404 | `TEST_SUPPORT_OFF` | — |
| `fixturePatch`, `actAs`, `freezeClock` не `false` в теле `POST /test/reset` | 422 | `NOT_SUPPORTED`, `field` | — |

## Н5 Приёмка

Тесты API consolem в профиле возможностей — на стенде Н1.1 после приращения платформы; до него — чтением. `?selftest` —
проверка сборки продуктом (Н1.4).
Свой набор — [`acceptance/4/`](../acceptance/4/README.md), [`acceptance/8/`](../acceptance/8/README.md) (ADR-0094 доп. (17), (18)): только то, чего тесты consolem в профиле не
видят, каждая проверка это называет. Классы: отказ обычному человеку, перевод прав главы 8, сбои воркера и память `backend/repeats`, операции профиля без теста, поиск на двойнике. Исполняет раннер
приёмки через те же двери, что стенд Н1.1; первый прогон — с первой генерацией V/11, до него сценарии — текст нормы.

## Решает реализация

Реализация обязана назвать в своём описании команду, которой стенд гоняет тесты продукта.

Способ — **без браузера**: файлы тестов продукта исполняются как есть в Node.js, страницу заменяет заглушка стенда: скрипты страницы `api/*.js` и `tests/harness.js` грузятся, как их грузит страница, заглушка даёт (`location` с `?api=<адрес>/backend/api&fixture=one-domain&clock=real`,
`document`, `EventSource` поверх `fetch`), `fetch` несёт `Authorization: Bearer` человека стенда. Запрос без `Origin` не судится (договор сторожевой и передачи, `csrf`).
Проба на образце стенда продукта (`ef7175b`, на контракте 0.2.0 не повторялась):
84 прошли, 0 упали, 9 пропущены как неумение набора; с нашей консолью способ не проверен, это даст первый прогон.

Прочие способы не выполнимы (ADR-0094 доп. (17) п. 6: CORS не вводим):

- страница с диска, в том числе запуск её скриптами продукта: `Origin: null` по куке — чужой, 403, а иного входа у `api/client.js` нет: он шлёт только
  куку;
- страница с адреса консоли: статическая дверь `html` не отдаёт (P/06.5, таблица расширений), набор `files` манифеста — только файлы WebUI (V/11.1 Н1.4), а `tests/api.html` держит
  встроенный скрипт.
