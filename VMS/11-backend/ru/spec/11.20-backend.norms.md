# V/11.20 — Выгрузка: нормы

Канон главы 20 урока V/11 «Бэкенд конфигуратора» (ADR-0117 § 8, доп. (1)–(7); ADR-0119 п. 4, доп. (5)–(7), (10)–(12); решение «Архитектора» 2026-11-04 по контракту форка `a9a96e2`). Лекция (`ru/11-backend.md`, для человека, в выгрузку не входит),
[инструкция](11-backend.README.md), контракт — [`consolem.openapi.json`](../../consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `7a875c75` (пин VMS).

Текст производный от `spec/11.20-backend.norms.md`, руками не правится: источник — английский [`spec/11.20-backend.norms.md`](../../spec/11.20-backend.norms.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Окно выгрузки форка говорит о заказе (`Export`): камеры, отрезки, настройки, ход и файлы. Строки заказа у подсистемы `exp` нет: её единица — часть, одна камера, одна запись, её файлы ([V/08.6](../../../08-exp/ru/spec/08.6-exp.norms.md)). `backend` пишет части заказа одним пакетом, собирает заказ обратно чтением его частей, подаёт просьбы `cancel` и `delete` их держателям, берёт у консоли ссылку на файл и отдаёт ход в поток автора; байты идут мимо него (ADR-0015). Глава нормирует десять операций тега `export`, `Reference.export` и сообщения `export.progress`, `export.finished`.

Id норм — `V/11.20-MM`; соответствие прежним урокам — [`id-map.tsv`](../../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../../ru/НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../../Platform/01-store/ru/spec/01.1-store.norms.md#н0-словарь-слов). Слова выгрузки — заказ, часть, ведущая часть, держатель части — V/08.6 Н0.

- **Id заказа** — `name` ведущей части, поле `export` каждой части заказа.
- **Незаконченный заказ** — заказ, у которого хоть одна часть без `result` (V/08.6 Н1.3).
- **`may(c, u, s)`** — правило `may` модуля над грантами `GET /session` человека билета (P/07 Н1.5), как `can_edit` главы 7 Н1.2: право `c` на единицу `u` в подсистеме `s`.

## Н1 Форма

**Время.** Моменты контракта (`date-time`) ↔ секунды Unix строк частей (`periods`, `at`, `result.expires`), миллисекунды — дробью. Сутки и время в именах файлов — в поясе системы, `timezone` из `GET /session` (норма B6; решение «Архитектора» 2026-11-04).

**Данные.** Строки частей `exp/parts/<name>` с состоянием `cursor`, `result` (элемент `configured` из `GET /exp/parts`, P/06.1 Н2 «Состояние в ответе»), просьбы `POST /exp/requests`, ссылка `GET /exp/where/<часть>`, решение размещения и пульсы `exp` — всё дверями консоли по билету запроса (V/11.1 Н1.5). Своей семьи у главы нет; память повторов — таблица `backend/repeats` (глава 4 Н1.4). Ключ файла подсистемы `/etc/backend/backend.env` (глава 6 Н1.3):

| Ключ | Кто читает | Грамматика | Умолчание | Норма |
|---|---|---|---|---|
| `EXPORT_KEEP` | воркер `backend` | целое ≥ 60, секунды | `86400` | Н1.2, Н1.8 |

`EXPORT_KEEP` — настройка системы из V/08.8 Н1.4: `keep` каждой части нового заказа и `limits.keepSec`.

### Н1.1 Права: `getExportGrant`

Право создать часть — `edit` на `exp` по камере; функция `EXPORT` переводится в него, `admin` — `EXPORT` с обоими флагами (V/08.6 Н1.5, V/11.8). Маскирования пока нет, обязательную маску не исполнить: первая генерация выгружает только с `admin` на `exp` по каждой камере заказа (V/08.6 Н1.5 «Без маски»; ADR-0117 доп. (4) п. 5).

- **`GET /me/export?ids=`.** `ids` — id камер через запятую, до `idsMax`; больше или id не в форме UUID — 422 `VALIDATION_FAILED`, `field: ids`.
- `allowed` — гранты `GET /session` дают человеку `edit` или выше на `exp` хоть в одной точке (строка с `sub: exp` или без `sub`): это и есть функция `EXPORT`.
- `devices[]` — по id из `ids`, в их порядке: `archive` — `may("admin", "unit:cam/<id>", "exp")`; `live` — `archive` и `may("view", "unit:cam/<id>", "live")`, право живого просмотра (V/08.6 Н1.5). Камера другого кластера и id, который не камера своего кластера, — оба `false`: такой заказ отказывается (Н1.2).
- `passwordRequired`, `privacyForced` — `true`, если у камеры из `ids` `archive: false`; без `ids` — если `may("admin", "*", "exp")` не выполняется. Оба флага — один ранг, поэтому поля равны (ADR-0117 доп. (6) п. 3).
- `refusal` — при `allowed` и `privacyForced`: «маскирование обязательно по политике, а в системе его нет»; иначе поля нет (ADR-0117 доп. (2) п. 4).
- `supervisorRequired` — заголовок `X-W2C-Supervision` запроса называет `exp` или равен `*` (договор сторожевой и передачи «Supervision»; ADR-0119 доп. (7) п. 1); заголовка нет — 503 `UPSTREAM_UNAVAILABLE`.
- `watermark` — `false`: водяного знака нет (ADR-0117 § 4 п. 6). `depthHours` — `0`: `depth` роли выгрузка не судит (V/08.6 Н1.5), предел.
- Права — ответ, не суд: заказ судится заново при создании (Н1.2).

### Н1.2 Заказ: `createExport`, `checkExport`

Тело `ExportCreate` у обеих операций одно; `checkExport` делает те же чтения и проверки и ничего не пишет («Проверка» ниже).

**Части.** Часть на элемент `cameras`, в их порядке: `cameras[0]` — ведущая часть, `name` — id заказа; `cameras[k]`, k ≥ 1 — `<id заказа>-<k>` (V/08.6 Н1.1). Id заказа — `<t>-<r>`: `t` — десятичные секунды Unix по часам `backend` при создании, `r` — 16 случайных шестнадцатеричных цифр в нижнем регистре. `Export.id` — UUID v5 от `export:<CLUSTER>/exp/parts/<id заказа>` (глава 4 Н1.6); `Export.createdAt` — `t`: своего момента у строки части нет.

**Проверки** — в этом порядке; первый отказ — ответ, ничего не записано:

1. Тело не по схеме `ExportCreate` контракта — 422 `VALIDATION_FAILED`, `field` — указатель JSON места в теле (решение «Архитектора» 2026-11-04).
2. Объявление и справочник: таблица «Настройки»; `format` вне `Reference.export.formats` или с `kind` не `mode` — 422 `NOT_SUPPORTED`, `field: /format`; `singleFile: true` при формате, у которого `singleFile` не `tracks`, — `field: /singleFile`; `source: live` при `mode: video` — `field: /source`; больше одной камеры при `mode: frame` — 422 `NOT_SUPPORTED`, `field: /cameras` (решение «Архитектора» 2026-11-04).
3. Сочетания V/08.6 Н1.1 — 422 `VALIDATION_FAILED`: `mode: video` без `periods` — `field: /periods`, с `at` — `field: /at`; `mode: frame` с `periods` — `field: /periods`; `mode: frame`, `source: archive` без `at` — `field: /at`; `source: live` с `at` — `field: /at`, с `cameras[i].archiveId` — `field: /cameras/i/archiveId`. Отрезок, у которого `to` не позже `from`, — `field: /periods/i/to`. Рамка вне `w > 0`, `h > 0`, `x + w ≤ 1`, `y + h ≤ 1` — `field: /cameras/i/area` (ADR-0117 доп. (7) п. 3). Повтор `deviceId` в `cameras` — `field: /cameras/i`.
4. Пределы V/08.6 Н1.4 — 422 `LIMIT_EXCEEDED`: камер больше `EXPORT_CAMERAS_MAX` — `field: /cameras`; отрезков больше `EXPORT_PERIODS_MAX` или их сумма дольше `EXPORT_TOTAL_MAX` — `field: /periods`.
5. Камеры: `deviceId` — не запись устройства — 422 `VALIDATION_FAILED`, `field: /cameras/i/deviceId`; не камера — 422 `NOT_SUPPORTED`, тот же `field`; камера другого кластера — 409 `OTHER_CLUSTER`, `params.url` (глава 4 Н1.13; V/08.7 Н1.1); `archiveId` не называет записи камеры — 422 `VALIDATION_FAILED`, `field: /cameras/i/archiveId`; нет `archiveId` и нет основной записи — 422 `NO_RECORDING`, `field: /cameras/i`.
6. Права (Н1.1): нет `edit` на `exp` по камере — 403 `PERMISSION_DENIED`, `field: /cameras/i`; `edit` без `admin` — то же с `params.reason: privacy`: маска обязательна и не исполнима; живой кадр без `may("view", "unit:cam/<id>", "live")` — 403 `PERMISSION_DENIED`, `field: /cameras/i`.
7. Пароль: камера без `admin` и нет `password` — 422 `PASSWORD_REQUIRED`, `field: /password`. В первой генерации такой заказ раньше отказывает п. 6; пункт ждёт маскирования — предел.
8. Надзор (ADR-0119 п. 4, доп. (5)–(7)): заголовка `X-W2C-Supervision` нет — 503 `UPSTREAM_UNAVAILABLE`; он называет `exp` или равен `*`, а `supervisor` нет — 403 `SUPERVISOR_REJECTED`, `field: /supervisor`, `params.reason: required` (ADR-0119 доп. (5) п. 2 называет этот отказ `SUPERVISOR_REQUIRED`, такого кода в контракте нет); `supervisor` дан — «Супервизор» ниже.
9. Незаконченных заказов человека (`by` — он) — `EXPORT_ACTIVE_PER_USER` или больше — 409 `BUSY` (контракт: `limits.maxActivePerUser`).
10. До записи: (a) `source: archive` — по камере `GET /rec/where/<rec>` и `GET <door>/timeline/<rec>?from&to` за окно её отрезков, у кадра — `[at − FRAME_BACK, at]` (V/08.7 Н1.3); кусок с `source: device` не считается: часть читает только `/spans` регистраторов (V/08.7 Н1.1). Ни у одной камеры нет куска ни в одном отрезке — 422 `NO_RECORDING`, `field: /periods`, у кадра — `/at`; не ответившая дверь — и `GET /rec/where` без держателя — отказа не даёт, судит сама часть (`no_recording`, `unreachable`); пустые отрезки части — не отказ: часть идёт с `partial`. (b) Перекодирование, а ни у одного сервера кластера нет метки `gpu` (`GET /servers`), — 422 `NOT_SUPPORTED`, `field` — первый из `/quality`, `/titles`, `/cameras/i/area`, которому нужно перекодирование (V/08.6 Н1.2 `constraint`). (c) Живой кадр камеры, у которой `online` (глава 3) — `false`, — 409 `DEVICE_OFFLINE`; не известно — заказ идёт, судит сама часть (`offline`, V/08.7 Н1.2).

**Супервизор.** `supervisor.login` — автор (`by`) — 403 `SUPERVISOR_REJECTED`, `field: /supervisor`, без вызова (ADR-0119 п. 4). Иначе `POST /domain/verify {user: <login>, password, need: {cap: admin, sub: exp, units: [cam/<cam>…]}}` по билету (P/06.7 Н1.15): 200 с `may: allow` у каждой единицы и, при `supervision.required`, с `supervision.ok` — `supervised_by` равен `user` ответа; единица с `deny`, `ok: false`, 401 — 403 `SUPERVISOR_REJECTED`, `field: /supervisor`; `unavailable`, 503, `409 deposed` — 503 `UPSTREAM_UNAVAILABLE`; 429 — 503 `UPSTREAM_UNAVAILABLE` с его `Retry-After`. Ответ и заголовок разошлись — судит ответ (ADR-0119 доп. (7) п. 2).

**Запись.** Один пакет `POST /console/batch` по билету (V/08.6 Н1.1 «Кто пишет»; `writes_via: [backend]`): каждая часть с `cas ""`; с `idempotencyKey` — ещё строка `backend/repeats/<h>` по главе 4 Н1.4 с `op: createExport` и одним шагом: `steps` — `[{index: 0, outcome: done, id: <Export.id>}]`. Отказ пакета переводится по отказавшей строке: 403 — 403 `PERMISSION_DENIED`, `field: /cameras/i` этой части; 400 — 422 `VALIDATION_FAILED`; 412 на части (id занят) — новый `r`, один раз; прочие — глава 4 Н4. Ответ — 202 с `Export` записанных строк (Н1.3: все части `wait`), `Location` — путь `getExport` этого заказа.

**Повтор.** Тот же `idempotencyKey` — глава 4 Н1.4: при `state: done` — заказ, прочитанный сейчас (Н1.3), 202; ни одной части не осталось — 404 `NOT_FOUND`; другое тело — 422 `VALIDATION_FAILED`, `field: idempotencyKey`. Без ключа каждый запрос — новый заказ (V/08.8 Н1.5).

**Проверка** (`checkExport`). Пункты 1–10 без записи и без `/domain/verify`: каждый её вызов тратит предел попыток супервизора (P/08.4 Н1.10 `verify`). Отказ п. 1 — сам ответ 422; прочие дают 200 `ExportCheck`:

- `errors` — `Problem` на каждый отказ пп. 2–10, у каждого свой `field`, в порядке пунктов; после отказа камеры (`field` `/cameras/i…`) следующие пункты той же камеры не судятся; пункты всего заказа (`/cameras`, `/format`, `/periods`, `/password`, `/supervisor`, `BUSY`) пункты камер не останавливают. `ok` — `errors` пуст.
- `transcode` — переведённые `settings` требуют перекодирования по V/08.7 Н1.4.
- `files` — по камере `{deviceId, name}`: имя по «Имени файла» ниже с `n` = 1.
- `noRecording` — `{camera, period}`, номера в теле камеры и отрезка без куска по п. 10 (у кадра — `period: 0`); камера, чья дверь не ответила, не называется.
- `estimate` — поля нет: размер оценивает держатель перед стартом (V/08.7 Н1.4 «Место»), предел.

**Имя файла.** Имя — держателя (V/08.7 Н1.4): `backend` отдаёт `result.files[].name` как есть и строит то же имя в `checkExport`. Время в имени — в поясе системы (решение «Архитектора» 2026-11-04): `backend` пишет `settings.tz` каждой части — `timezone` из `GET /session`; держатель именует по нему (V/08.7 Н1.4).

### Н1.3 Чтение: `listExports`, `getExport`

- **Чтение.** `GET /exp/parts` по билету: строки, которые человек видит (фильтр двери `view` по камере, P/06.1), с `state` в `configured`. Части группируются по `export`; заказ собирается из видимых частей: ведущей может уже не быть (V/08.6 Н1.1). **Цена:** одно чтение всей таблицы на запрос.
- **`Export`.** `id`, `createdAt` — Н1.2; `by`, `supervisedBy` — `by`, `supervised_by` части; `retryOf` — UUID заказа `retry_of` по Н1.2; `transcode` — у части `gpu` в `labels`; `request` — тело, собранное обратно по таблицам Н1.2: `cameras[]` в порядке `n` (`deviceId`, `archiveId` — хранилище тома `home` записи `rec`, `area`), остальное — из ведущей части, иначе из части с наименьшим `n`; чего нет ни в одной части (`name`, `bookmarkId`, `idempotencyKey`, `supervisor`, `password`), — поля нет; `enforced` — поля нет: первая генерация выгружает только с `admin`, ничего не навязано (Н1.1).
- **`ExportPart`** на часть в порядке `n` (`n` = 0 — ведущая часть): `deviceId` — `cam`; `from`, `to` — начало первого и конец последнего отрезка `periods`; `at` — `at`; `state` — без `result`: `wait` без `cursor`, `run` с ним; при `result.end` `done` — `ok`, `failed` — `fail`, `canceled` — `cancel`, `expired` — `fail`; `percent` — ⌊100 × `cursor.done`⌋, с `result` — 100; `code` — `result.code`, при `expired` — `expired`; `partial` — `result.partial` не пуст.
- **`progress`:** `total` — число частей, `done` — с `result`, `percent` — ⌊100 × Σ s / total⌋, `s` — 1 у части с `result`, иначе `cursor.done`, без `cursor` — 0.
- **`state`:** часть без `result` — `running`, а если ни у одной части нет и `cursor`, — `queued`; у всех `result`: хоть одна `done` — `done`; иначе хоть одна `canceled` — `cancelled`; иначе все `expired` — `expired`; иначе `failed`.
- `finishedAt` — когда у всех частей `result`: самый поздний `result.expires` − `keep`; `expiresAt` — самый поздний `result.expires`.
- **`files`** — `result.files` частей в порядке `n`: `id` — `<n>-<id файла>`, `deviceId` — `cam` части, `name`, `sizeBytes` — `size`, `sha256`, `mediaType` — по расширению, как `Content-Type` двери файла (V/08.9 Н1.2), `expiresAt` — `result.expires` части. Чужой заказ — файлы названы, ссылка отказывается (Н1.6).
- **`GET /exports`.** `mine=true` — только заказы с `by`, равным человеку; `state` — значения `Export.state` через запятую, «или»; другое слово — 422 `VALIDATION_FAILED`, `field: state`. Новые сверху: по `t`, затем по `r`, по убыванию; страницы — общее правило главы 3 Н1.2б, место — id заказа.
- **`GET /exports/{id}`** — заказ, у которого `Export.id` равен `id` (обратный путь — по перечню, глава 4 Н1.6); видимой части нет — 404 `NOT_FOUND`.

### Н1.4 Просьбы: `cancelExport`, `deleteExport`

- Заказ — Н1.3; нет — 404 `NOT_FOUND`. Право — по части: автор (`by` — человек) или `may("admin", "unit:cam/<cam>", "exp")` (V/08.8 Н1.1); часть без него — 403 `PERMISSION_DENIED`, ничего не подано.
- **`POST /exports/{id}/cancel`.** У всех частей `result` — 409 `NOT_RUNNABLE`. Иначе `POST /exp/requests {unit: <часть>, action: cancel}` каждой части без `result` (V/08.8 Н1.2); 200 — заказ, прочитанный заново: держатели исполняют позже, истина — `GET` и поток.
- **`DELETE /exports/{id}`.** Каждой части — `POST /exp/requests {unit: <часть>, action: delete}` (V/08.8 Н1.3); часть без держателя (V/08.8 Н1.4 «Часть без держателя»: решение `exp/placement/<часть>` не называет воркера или строки решения нет, или пульс названного старше `LOST_AFTER`) — `DELETE /exp/parts/<часть>` по CAS ревизии, прочитанной вместе с решением; 412 — прочитать заново, один раз. 204.
- **Отказы подачи:** 403 — 403 `PERMISSION_DENIED`; 429 по `per_person` (V/08.8 Н4) — 503 `UPSTREAM_UNAVAILABLE` с `Retry-After`; уже поданные просьбы остаются, повтор подаёт остальные — предел. Отметка держателя (`refused` `not the author`, `done` `nothing to cancel`) приходит позже; `backend` её не ждёт.
- **Предел:** `cancel` части без держателя никто не исполняет: часть остаётся `wait` (Н1.3: нет `cursor`), пока её не возьмёт новый держатель или до `DELETE`.

### Н1.5 Повтор: `retryExport`

`POST /exports/{id}/retry-failed {password?}`: заказ — Н1.3, нет — 404 `NOT_FOUND`; нет части с `result.end: failed` — 409 `NOT_RUNNABLE`. Иначе новый заказ из этих частей по Н1.2: `cam`, `rec`, `source`, `mode`, `periods`, `at`, `format`, `settings`, `comment` части как есть, `password_secret` — `password` тела, `by` — человек, `retry_of` — id заказа (V/08.8 Н1.5); проверки — пп. 6–10 Н1.2 над этими частями. Ведущая часть нового заказа — первая из них по `n`: «в один файл» держит только повторённые части — предел. `supervisor` в теле нет: заказ под надзором повторяется новым `POST /exports` — предел. Памяти повторов нет: каждый вызов — новый заказ, как `retry-failed` операций (глава 6 Н1.3). 202 — новый `Export`.

### Н1.6 Ссылка на файл: `getExportFileLink`

`POST /exports/{id}/files/{fileId}/link`: заказ — Н1.3, нет — 404 `NOT_FOUND`; `fileId` — `<n>-<id файла>` из Н1.3: нет такой части или такого id в `result.files` — 404 `NOT_FOUND`; часть `expired` или её `result.expires` прошёл — 410 `EXPORT_EXPIRED`; `by` части — не человек — 403 `PERMISSION_DENIED`: только автор (V/08.6 Н1.5, V/08.9 Н1.2). Затем `GET /exp/where/<часть>` по билету ([V/08.9](../../../08-exp/ru/spec/08.9-exp.norms.md) Н1.1): `url` — адрес V/08.9 Н1.1 с `door` и `token` ответа и id файла части; `expiresAt` — `expires`, срок `EXPORT_LINK_TTL`. Отказ `where`: 403 — 403 `PERMISSION_DENIED`; 404 или нет `door` — 503 `UPSTREAM_UNAVAILABLE`: держатель не известен. Дверь судит токен заново (V/08.9 Н1.2). `stub://` тестового сервера форка `backend` не отдаёт никогда.

### Н1.7 Сутки с записью: `getRecordingDays`

`GET /devices/{id}/recording-days?from&to`: цель не камера — 422 `NOT_SUPPORTED`, `field: type`; записи нет — 404 `NOT_FOUND`. `from`, `to` — даты в поясе системы; нет — последние 31 сутки: сегодня и 30 до него; `to` раньше `from` — 422 `VALIDATION_FAILED`, `field: to`. Окно — от 00:00 даты `from` до 00:00 суток после `to`, в этом поясе.

- **Своя камера.** Записи — `GET /rec/recordings` с её `cam`; по записи `GET /rec/where/<запись>` и `GET <door>/timeline/<запись>?from&to` (глава 4 Н1.22, шаги 1 и 2 для своего кластера). Места таблицы мест (шаг 3) не читаются, а кусок с `source: device` не считается: часть их не читает (V/08.7 Н1.1). Ответ больше 1 MiB — окно делится, как в главе 4 Н1.22, до `TIMELINE_SPLITS`.
- `days` — каждые сутки окна по порядку, `recorded: true` — кусок записи пересекает сутки. `unavailable` — как у шкалы (глава 4 Н1.22 «`unavailable`»): не ответившая дверь, непрочитанный остаток окна; суток с записью может быть больше.
- **Камера другого кластера** — `unavailable` `{what: cluster, id: <член>}`, все сутки `recorded: false`: выгрузка туда не ходит (Н1.2 п. 5).
- **Цена:** 1 + 2R вызовов, R — записи камеры; шкала читает ещё и места. `depth` роли не судится — предел (V/08.6 Н1.5).

### Н1.8 Справочник: `Reference.export`

`Reference.export` отдаётся, раз `createExport` объявлена (глава 2 Н1.5); значения — из манифеста `exp` и V/08.6 Н1.4, и те же списки судят тело (Н1.2 п. 2).

- `formats`, в этом порядке:

| `id` | `kind` | `codecs` | `password` | `singleFile` | `entries` |
|---|---|---|---|---|---|
| `mkv` | `video` | `["source"]` | `zip` | `tracks` | `["archive"]` |
| `mp4` | `video` | `["source"]` | `zip` | `none` | `["archive"]` |
| `avi` | `video` | `["source"]` | `zip` | `none` | `["archive"]` |
| `jpg` | `frame` | `[]` | `zip` | `none` | `["archive", "live"]` |
| `pdf` | `frame` | `[]` | `native` | `none` | `["archive", "live"]` |

- `softTitles`, `chapters`, `player` — `false` у всех форматов: титры вшиваются перекодированием (V/08.7 Н1.4); у глав V/08.7 Н1.4 нет входа в контракте без `exportTracks`; плеера нет (ADR-0117 доп. (1) п. 1). Кодек перекодирования — реализации (V/08.7), поэтому `codecs` называет только `source`.

Оба списка — выбор главы.

- `limits`: `maxCameras` 16, `maxPeriods` 32, `maxTotalSec` 86400, `maxFileMbDefault` 4000, `maxFileMbMax` 4000, `maxActivePerUser` 4, `keepSec` — `EXPORT_KEEP`, `linkTtlSec` 120, `bookmarkPadSec` 30: выгрузка из отметки-момента — ±30 с, из отрезка — его границы (ADR-0117 доп. (1) п. 2); окно берёт их само (глава 4 Н1.24).

### Н1.9 Поток: `export.progress`, `export.finished`

Состояние части лента не несёт, как и итог скана (V/05.1; глава 5 Н1.3), поэтому поток читает его сам:

- Пока у человека потока есть свой незаконченный заказ (`by` — человек потока), не чаще `VIEW_POLL` на поток он читает `GET /exp/parts` и сравнивает `cursor` и `result` частей своих заказов с запомненными. О новом заказе узнаёт из ленты: строка `exp/parts/<name>` с `revision: 1`, её дочитывание даёт `by`. При открытии потока — одно чтение, значения запоминаются, сообщений нет.
- Изменились `cursor.done` или `result` части — `export.progress`: `kind: export`, `entityId` — `Export.id`, `payload` — `{progress, part}`: `Export.progress` и `ExportPart` этой части (Н1.3). Последняя часть заказа получила `result` — после него `export.finished`, `payload` — `{state, files}` заказа (Н1.3).
- Только автору: части с другим `by` сообщений не дают. `id` сообщения — как у конца поиска (глава 5 Н1.2); обрыв не досылает: истина — `GET`.
- **Цена:** чтение таблицы на `VIEW_POLL` на поток с незаконченным заказом; без него — чтения нет.

## Н3 Проход

```
права: /session → may(edit | admin, unit:cam/<id>, exp), may(view, unit:cam/<id>, live); X-W2C-Supervision → supervisorRequired
заказ: схема → справочник → сочетания (V/08.6 Н1.1) → пределы → камеры → права (admin) → пароль → надзор (/domain/verify)
  → незаконченные заказы → шкала (NO_RECORDING), gpu, online → один пакет частей (+ repeats) → 202 Export
проверка: то же без /domain/verify и без записи → 200 ExportCheck
чтение: GET /exp/parts → по export → Export (state, progress, parts, files, request)
отмена, удаление: право по части → POST /exp/requests на часть; удаление без держателя → DELETE строки по CAS
повтор: неудачные части → новый заказ с retry_of
ссылка: автор → GET /exp/where/<part> → {url, expiresAt}
сутки: записи → where → /timeline → сутки в поясе системы
поток: незаконченный заказ автора → GET /exp/parts на VIEW_POLL → export.progress, export.finished
```

**Гонки.** Два `POST /exports` с одним ключом — их упорядочивает строка `<h>` (глава 4 Н1.4). Часть кончилась между чтением и `cancel` — держатель отмечает `done` `nothing to cancel` (V/08.8 Н1.2). Вернувшийся держатель во время `DELETE` части без держателя его не останавливает (V/08.8 Н1.4).
