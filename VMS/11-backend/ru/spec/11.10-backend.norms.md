# V/11.10 — Инструменты: нормы

Канон главы 10 урока V/11 «Бэкенд конфигуратора», ассистент (ADR-0080; модуль VMS — ADR-0090; подсистема — ADR-0093 пп. 3, 8, доп. (1) п. 9,
доп. (2) п. 2, доп. (3), доп. (4) пп. 4, 5, доп. (5)). Лекция (`ru/11-backend.md`, для человека, в выгрузку не входит), [инструкция](11-backend.README.md). Платформа закреплена в [`VMS/PLATFORM_PIN`](../../../PLATFORM_PIN) (P/06.1 N2 — дверь единиц; P/06.5 — `/manifest`).

Текст производный от `spec/11.10-backend.norms.md`, руками не правится: источник — английский [`spec/11.10-backend.norms.md`](../../spec/11.10-backend.norms.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

В рабочей ветви модель ничего не читает сама: каждый её вызов `backend` исполняет дверями консоли по билету человека (глава 7 N1.2),
и отдаёт результат текстом. Поэтому модель видит ровно то, что видит админ, — и не больше: маски секретов, права `view`,
отбор консоли по гранту действуют как у формы. Рабочий набор закрыт: девять инструментов пакета передачи (ADR-0093 п. 8) —
шесть для чтения и три ответа админу. Фильтров у дверей консоли нет: `backend` читает список целиком и отбирает сама
(ADR-0093 доп. (2) п. 2). Глава нормирует набор, чтение консоли, каждый инструмент чтения и `ask_admin`; `propose_plan`
и проверка `refuse` — глава 11.

У отдельной ветви `learn` закрытый набор N1.7; рабочих чтений, обзора и инструментов плана она не получает. Она не заменяет рабочую ветвь из девяти инструментов и проверки плана V/11.11–11.13.

Id норм — `V/11.10-MM`.

## N0 Словарь слов

Нормативные слова — по [канону курса](../../../../Platform/common/ru/NORMATIVE-TERMS.md). Правила модуля «Платформа» — [P/01.1 N0](../../../../Platform/01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

- **Подсистема** — `cam`, `rec`, `det`: **охват** рабочего ассистента, константа (глава 7 N1.2; ADR-0093 доп. (5), (6)). Обзор, инструменты и план — только по нему. У типа `explain` охват ещё `auto`, только чтение (V/11.7 N1.7; ADR-0093 доп. (16)).
- **Строки подсистемы** — элементы `configured` ответа `GET` её строк (P/06.1 N2): у корня `/<rows>`, у прочей
  `/<sub>/<rows>`; `rows` — `rows` манифеста. Id строки — поле `id`; поле имени — `id` манифеста (`id_field`).
- **Связанная подсистема** — по `about` манифеста (`about: {sub, field}`): строка ссылается на единицу той подсистемы
  полем `field`. `about.<field>` — поле связанной единицы.
- **Манифест** подсистемы — `GET /manifest`, отфильтрованный по охвату (глава 7 N1.2): проекция манифеста с ключами `name`, `rows`, `id`, `fields`, `about`, `display`, `servers`, `places` и прочими. **Корень** — `cam`: у него строки — `/<rows>`.

## N1 Форма

**Данные.** Своих семей нет. Рабочие инструменты читают двери консоли (N1.2); они ничего не пишут. Учебные инструменты используют только единственный каталог поставки N1.7 и не читают рабочие объекты.

### N1.1 Набор

Инструменты типа `config` — ровно [`harness/tools.json`](../../harness/tools.json), набор типа `rules` — глава 13 N1.2: `list_subsystems`, `get_manifest`, `get_schema`,
`find_units`, `field_values`, `list_table` (чтение), `propose_plan`, `ask_admin`, `refuse` (ответ админу). Имя, описание и
схема аргументов — байты файла; модель видит их в `tools` шага (глава 9 N1.2). Иного вызова нет: имя не из набора —
результат `no tool <name>` (глава 9 N1.4); принадлежность набору — собственный ключ закрытого реестра, не свойство,
унаследованное от прототипа (`constructor`, `toString`, `__proto__` — `no tool`); так же имена полей, таблиц и слов,
которые пишет модель, ищутся только среди собственных ключей. Создать, удалить единицу, писать таблицы, серверы, политику, домен ассистент не
может — такой просьбе модель отвечает `refuse`.

### N1.2 Чтение консоли

Это чтение рабочих инструментов. `learn` не зовёт эти инструменты и не делает эти чтения для подготовки обзора, при продолжении вопроса или при перезапуске (N1.7).

- **Только по билету**: двери консоли человека (глава 7 N1.2). Пути — закрытый список:

```yaml
reads:   /schema, /manifest, /<rows>, /<sub>/<rows>, /<table>, /<sub>/<table>
         # <table> — таблица из tables подсистемы (list_subsystems): servers.show[].table и places.table манифеста;
         # у корня — /<rows>, /<table>, у прочей — /<sub>/<rows>, /<sub>/<table> (P/06.1 N2)
never:   /mounts; запись (её делает только «Применить», глава 12); двери держателей; /events; /domain/*
```

- **Свежесть.** Каждый вызов инструмента читает заново; обзор хода (глава 9 N1.2) — один раз в начале хода. Внутри
  одного вызова одна дверь читается один раз.
- **Ошибка чтения** — ответ не 200 или обрыв: вызов кончается ошибкой инструмента
  `GET <path>: <status> <detail>`; пустого или усечённого результата вместо ошибки нет (ADR-0093 доп. (1) п. 9). 403
  — «нет доступа»: человеку нельзя читать эту дверь, та же форма `GET <path>: 403 <detail>` (глава 7 N1.2), отдельной
  проверки права до чтения нет. 401 — билет мёртв: поток закрыт (глава 7 N4).
- **Предел списка.** Строк подсистемы больше `LIST_MAX` — ошибка инструмента `<sub>: more than <LIST_MAX> units — too
  many to check here; refuse and say so`; так же у таблицы (ADR-0093 доп. (2) п. 2: предел и `refuse`, не усечённый
  отбор).

```yaml
LIST_MAX:   5000 строк одной двери
ROW_LIMIT:  50 — единиц и строк таблицы в результате инструмента; число — полное (count)
```

- **Право** единицы (`can_edit`) — возможность, которую требует дверь записи этой строки (`PUT /<rows>/<id>`), по
  `need` [договора сторожевой и передачи](../../../../Platform/common/ru/contracts/gate-and-pass.md): `admin` на единицу —
  `rights.routes` у строк единиц понижает только создание (таблица «Права по телу» договора). Проверка — только
  правило `can_edit` главы 7 N1.2 (гранты человека билета, `sub` — подсистема двери записи, договор сторожевой и передачи «Подсистема проверки»; область — в том числе по `about`-единице),
  без своего чтения `grants`: аварийная сессия (break-glass) и открытый режим судятся как у сервера. Одно правило — в обзоре, `find_units`, проверке
  плана, полноте и проверке `refuse` (ADR-0093 доп. (4) п. 4). Это предварительная проверка: ключа `rights` в
  `ManifestView` нет, поэтому `rights.cluster_rows` (у `auto` — запись требует гранта на кластер) и то, что правка
  задевает сверх строки (`rights.reach`, `names`), `backend` заранее не видит — их сервер проверяет при записи всегда
  (ADR-0093 доп. (1) п. 9; отказ — исход `refused`, V/11.12 N1.4).
- **Нечитаемая подсистема** — чтение её строк кончилось ошибкой или `LIST_MAX`. Где инструмент или проверка
  перебирает все подсистемы (подсказки `find_units`, проверка `refuse` главы 11 N1.5, имена единиц для чисел текста главы
  5 N1.2), такая подсистема пропускается:
  опровергнуть ею нечего; подсказка `find_units` называет её: `subsystem <s> could not be read: <reason>`.

### N1.3 Результат и ошибка

- Результат рабочего вызова — `content` сообщения `tool` (глава 9 N1.2): JSON без пробелов, ключи в порядке форм ниже.
- **Ошибка инструмента** — `content` — `error: <words>`; ход идёт дальше, модель исправляет вызов. Слова ошибок — в
  формах ниже, английские, как в замере пилота.
- `null` поля строки и отсутствие поля — одно: «не задано».

### N1.4 Слова поля

Рабочий вид поля для модели (`get_manifest`, обзор) и слова для проверки (глава 11 N1.2) берутся из `display` манифеста и
[`harness/words.json`](../../harness/words.json) — данных урока, не настройки модели:

```yaml
field:      {name, type, required?, fixed?, enum?, default?, inherit?, bound_to?, label?, label_from?, help?, enum_labels?,
             words?, enum_words?, secret?} — ключи в этом порядке; ключ без значения (нет, false) не пишется
  type:     тип поля fields манифеста (string, int, float, bool, list, json, url, blob)
  label:    display.fields[name]; нет — words.json labels[sub][name] и label_from: "lesson"; нет и тип list — null;
            нет у иного типа — ключа нет
  help:     display.field_help[name]
  enum_labels: display.options[name]
  words:    words.json fields[sub][name] — слова операторов сверх подписи
  enum_words: words.json options[sub][name]
  secret:   true — имя кончается на _secret (P/02.1 N1.3a)
```

### N1.5 Инструменты чтения

**`list_subsystems`** `{}` → `{subsystems: [element]}` по порядку подсистем:

```yaml
элемент:  {sub, rows, id_field, unit_word, units_word, section, words?, unit_word_from?, about?, tables?}
  unit_word, units_word, section: display.unit, display.units, display.section (нет — null)
  words:  words.json units[sub]
  unit_word_from: нет display.unit, а подсистема, которая ссылается на эту по about, дала подсказку поля связи
          (display.field_help[about.field]) — unit_word = эта подсказка, unit_word_from: "no label in display; the word comes
          from the help of field <другая>.<поле>"
  about:  "each unit (\"<unit_word или sub>\") belongs to a unit of <about.sub> (\"<её unit_word или sub>\") via field
          <about.field>; that unit's fields in find_units are about.<field>"
  tables: имена таблиц servers.show[].table и places.table по имени; нет — ключа нет
```

**`get_manifest`** `{sub}` → `{sub, rows, id_field, about?, fields, word_unit?, word_units?, word_section?, word_general?,
form?, status_words?, notes}`:

- нет подсистемы — `error: no subsystem "<sub>"; there are: <subsystems joined by ", ">`; подсистема смонтирована, но вне
  охвата (N0) — `error: subsystem <sub> is outside the assistant's scope (this page: <subsystems joined by ", ">) — refuse:
  not in scope, not a lack of rights` (ADR-0093 доп. (5) п. 1); так же у каждого инструмента и правки плана с этой
  подсистемой;
- `about` — `{sub, field, note, about_list_fields}`: `note` — `a unit belongs to a unit of <about.sub> whose name is in
  field <about.field>. That unit's fields are filters about.<field>: <about.<field> joined by ", ">. A unit's labels
  are the labels of the related unit: about.labels; its own list fields (<own list fields joined by ", " or none>) are not
  labels`; `about_list_fields` — `about.<field>` полей `list` связанной;
- `fields` — вид каждого поля `fields` манифеста (N1.4) по порядку; `word_*` — `display.unit`, `units`, `section`,
  `general`; `form` — `[{title, fields}]` из `display.form`; `status_words` — `display.options` по именам, которых нет
  среди полей;
- `notes` — четыре строки:
  1. `look up field values (labels, zones, shelves) with field_values — the admin's words are stored as values (e.g.
     "northern" → north, "quiet" → plain)`;
  2. `a field with secret: true is hidden from you (the console shows ***); a new secret value is never written into a
     plan — only the secret label {"secret": N} the admin entered`;
  3. `a fixed field cannot be changed; the id_field is the unit's name, it is not changed`;
  4. `a field with inherit and no own value: find_units shows null, and inherited says what applies; from is null or
     the effective value`.

**`get_schema`** `{}` → ответ `GET /schema` как есть.

**`find_units`** `{sub, where?, fields?}` → `{sub, count, shown, units, can_edit_note?, query, hints?}`:

- **Условия** `where` — список `{field, op, value}`, все — И. Короткие записи: объект `{<field>: <value>, …}` — равенства;
  `{field, <op>: <value>}` с одним ключом из `op` — этот `op`. `op` не задан — `eq`. Ошибки: иной ключ — `condition
  <condition>: extra keys <keys>; the form is {"field": …, "op": "eq", "value": …}`; нет `value` у `op` не
  `exists`/`missing` — `condition <condition>: no value; …`; не объект или без `field` — `a condition is {field, op,
  value}`; `op` не из `eq ne in not_in contains not_contains gt gte lt lte exists missing` — `op "<op>": one of <list>`;
  поле не из полей строки, `id`, `revision` — `no field "<field>" in <sub>; fields: <by name>`; `about.<field>` без `about`
  — `<sub> has no about`; `about.<field>` не из полей связанной и `id` — `no field "<field>" in the related subsystem <s>;
  its fields: <about.field…> — filter about.<field>`.
- **Значение** условия у строки — её поле; `about.<field>` — поле единицы связанной подсистемы с id, равным полю связи
  строки (нет такой — не задано).
- **Сравнение** `same(a, b)` — равенство значений JSON, но `true`/`false` не равны числам. `eq` — `same`; `ne` — не `same`;
  `in`/`not_in` — `same` с элементом списка значения (значение не список — как список из одного); `contains` — поле-список содержит значение (значение-список — все его
  элементы); `not_contains` — отрицание `contains`; `exists`/`missing` — задано / не задано; `gt gte lt lte` — числа (не
  `bool`) у обоих, иначе не подходит.
- **Пустой список.** У поля `list`: `eq`/`ne` с `""`, `[]`, `null` и `exists`/`missing` судят «пусто или не задано»;
  не заданное поле с `inherit` — значение `inherit`. `eq`, `missing` — пусто; `ne`, `exists` — не пусто.
- **Единицы** — подходящие строки по id, id — байтами UTF-8 (дополнение Kimi к разбору ревью V/10, S5); в `units` —
  первые `ROW_LIMIT`: `{unit: "<sub>/<id>", …view}`. Вид — поля строки (только из `fields`, если дан) без `id`,
  `revision`, `index`, поля имени, без пустой строки (если поле не просили), без `null` (если не просили); `[]` и `""` просимого
  поля видны. Не заданное поле с `inherit` (из просимых) — `null`, и `inherited: {<field>: <inherit value>}`. Есть
  `about`: `about.labels` — метки связанной единицы, если непусты; `about.<field>` из `fields` — значение поля связанной
  единицы (не задано и есть `inherit` у поля той подсистемы — значение `inherit` и запись в `inherited`), и тогда же
  поле связи строки. Нет права (N1.2) — `can_edit: false`.
- `count` — число подходящих, `shown` — число в `units`. Есть `can_edit: false` — `can_edit_note`: `can_edit: false — the
  admin has no edit right on this unit: leave it out of the plan, tell the admin in summary`. `query` — `{sub, where}`
  после коротких записей.
- **Найдено за ход.** Каждая показанная единица — в учёт хода `unit → right` (для проверки `refuse`, глава 11 N1.5).
- **Подсказки** `hints` — при нуле находок и непустых условиях, по порядку, все сработавшие; ни одной — `["no matches
  anywhere; check the field's values with field_values"]`:
  1. одно поле дважды через `eq` — `field <field> twice with eq — conditions are AND, one unit cannot equal two values;
     for "or" use {"field": "<field>", "op": "in", "value": <values>}`;
  2. значение условия (не `contains`/`not_contains`) — элемент поля-списка какой-нибудь строки подсистемы —
     `<value> is an element of list field <field> — a list needs op contains: {"field": "<field>", "op": "contains",
     "value": …}` (одна на условие);
  3. есть `about`, строковое значение условия — значение или элемент поля связанной подсистемы (`labels`, затем ключи первой строки по порядку чтения, `id` в их числе) —
     `"<value>" is in field <field> of the related subsystem <s> — filter about.<field>` (одна на значение);
  4. строковое значение условия — id единицы другой подсистемы — `"<value>" is the name of a unit of subsystem <s>`;
  5. другая подсистема не читается (N1.2) — `subsystem <s> could not be read: <reason>`.

**`field_values`** `{sub, field}` → `{sub, field, values, empty_units?, empty_note?}`: `values` — `[{value, units}]`
значений поля (у списка — элементов; `about.<field>` — у связанных единиц; объекты, списки и не заданные — не считаются)
по убыванию `units`, при равенстве — по возрастанию значения как JSON: сначала тип в порядке строка, число, `bool`,
внутри типа — числа по значению, строки байтами UTF-8, `false` < `true` (дополнение Kimi к разбору ревью V/10, S5). У
поля `list` пустые или не заданные (с `inherit` — по нему) — `empty_units` и `empty_note`: `empty or not set: {"field":
"<field>", "op": "eq", "value": []}`. Нет поля — `no field "<field>" in <sub>`; `about.<field>` — как у `find_units`.

**`list_table`** `{sub, table}` → `{sub, table, rows, read_only: true}`: `rows` — первые `ROW_LIMIT` строк таблицы без полей
`by`, `at`, `made_at`, `held_by`, `revision`, `index`. Таблицы нет среди `tables` подсистемы или в ответе — `no table "<table>" in <sub>`.

### N1.6 Ответ админу

`ask_admin` общий с обучением по N1.7; `refuse` и `propose_plan` ниже относятся к рабочему набору и не предлагаются `learn`.

- **`ask_admin`** `{question}`: пустой — ошибка `question is one short question to the admin`. Иначе — принят: `backend`
  отдаёт вопрос событием `question` и кончает запрос (глава 9 N1.4 п. 6); результат — текст ответа админа из нового запроса.
- **`refuse`** `{reason, other_kind?}`: пустой — ошибка `reason is why the request cannot be done (or that there are no such units)`;
  проверка отказа — глава 11 N1.5; принят — исход «отказ» (глава 9 N1.5). `other_kind: true` — просьба другого типа: проверки нет, `backend` выбирает тип заново (V/11.7 N1.6).
- **`propose_plan`** — глава 11.

### N1.7 Учебные каталог и инструменты

У внутреннего типа `learn` (V/11.7 N1.10, V/11.9 N1.7; ADR-VMS-0004 по дополнения (1), (2)) ровно `open_chapter`, `no_chapter`, `ask_admin`, с `tool_choice: required`. Рабочих инструментов чтения, плана или маршрута применения нет. Имена инструментов — собственные ключи этого закрытого реестра, как в N1.1; ни имя из прототипа, ни имя рабочего инструмента не являются учебным вызовом.

- **Один источник каталога.** Каталог поставляется вместе с турами, по правилам поставки и SHA V/11.1. Он задаёт темы и главы устойчивыми ID и содержит версию или отпечаток, язык, название, цель, учебный набор и доступность в сборке. Значения приходят из этого источника; они не выдумываются в подсказке и не ведутся второй редактируемой копией текста. Учебная подсказка ставит этот каталог первым ради повторного использования префикса (V/11.9 N1.7). Язык главы показывается честно: русские туры не становятся английскими от английского рабочего интерфейса.
- **`open_chapter`** `{chapter: enum catalogue ID}` выбирает только один текущий ID главы. Перечисление строится из действительных ID глав каталога, не из второго рукописного списка. Модель не даёт URL, HTML, JavaScript или селектор; адрес страницы интерфейс строит из своей поставки. Код проверяет аргументы, текущий ID, версию или отпечаток каталога, использованного для подсказки, и доступность в сборке перед предложением проверенной ссылки; интерфейс ещё раз проверяет текущий ID и версию перед запуском. Версия сверяется с действительным каталогом, использованным для этого выбора, а не принимается на веру по словам модели. Грамматика модели эти проверки не заменяет.
- **`no_chapter`** — конечный выбор, когда подходящую доступную главу предложить нельзя. Он не обещает урок и предлагает ручной каталог или обычный поиск, когда они доступны. Неизвестный ID, чужая версия или недоступная глава тоже ничего не запускают и ведут к ручному каталогу, когда он доступен, а не к выдуманной главе или странице.
- **`ask_admin`** `{question}` — ровно N1.6: та же проверка короткого вопроса, событие `question`, новый запрос с `context` и ответ человека результатом инструмента. Второго протокола вопроса нет. Переписка относится только к этой учебной просьбе и продолжению её собственных вопросов и ответов; рабочие контекст, история, снимок, черновик или секрет не наследуются. Рабочее чтение «сначала данные» не является условием.
- **Действие и зависимость.** Проверенный выбор — типизированная логическая учебная ссылка, описанная как будущее `answer.learn` в V/11.7 N1.10; это не рабочий план и за него не проходит. Показ он не запускает: человек пользуется кнопкой по V/11.12. В нынешнем закрытом API cb728a4 нет `answer.learn`; перед его передачей нужны правка форка «Консолью», согласование договора и разрешённый перепин. Схемы JSON результата, флага запроса, события или переключателя времени исполнения здесь не вводится. Нынешняя поставка `--without-learn` и файлы рабочих инструментов не меняются. При недоступной модели — ручной каталог/поиск, когда они доступны; сборка без обучения не предлагает урок.

## N3 Проход

Следующий проход — для рабочего набора. Обучение выбирает только из N1.7: проверить вызов и текущие ID/версию каталога, затем проверенная логическая ссылка, ручной каталог или прежний обмен `ask_admin`; рабочих чтения, учёта отбора или проверки плана в этом проходе нет.

```
вызов → имя из набора? иначе no tool
аргументы → короткие записи → проверка полей и op → ошибка инструмента | дальше
манифест — GET /manifest по охвату; чтение строк (и связанной) — по билету; не 200 → ошибка; > LIST_MAX → ошибка
отбор в `backend` → вид, can_edit, учёт найденного, hints → результат JSON
```

**Рабочие гонки.** Строки изменились между вызовами — каждый вызов читает заново; план проверяется по своему чтению (глава 11), а
применение — по `revision` этого чтения (V/11.12). Права сузились посреди хода — следующий вызов видит меньше.

## N4 Отказы

Ниже — отказы рабочего чтения. Обучение использует прежнюю обработку неизвестного инструмента и аргументов, а для неизвестной или недоступной главы и чужой версии каталога — N1.7; рабочих объектов для разрешения этих случаев оно не читает.

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| имя не из набора | `no tool <name>` | модель | другой вызов |
| условие не по форме, нет поля, нет подсистемы, нет таблицы | ошибка инструмента со словами N1.5 | модель | исправить вызов |
| чтение консоли не 200 | `GET <path>: <status> <detail>` | модель | `refuse` или повтор позже |
| строк больше `LIST_MAX` | ошибка «too many to check here» | модель | `refuse` |
| 401 консоли, билет мёртв | поток закрыт (глава 7 N4) | WebUI | повтор запроса |

## N5 Приёмка

Для нынешнего рабочего набора, драйвером `backend` (глава 7 N5): векторы инструментов чтения — чтение консоли (строки,
манифесты, сессия) и вызов → результат или ошибка: короткие записи условий, каждый `op`, пустой список и `inherit`,
`about.<field>`, `can_edit` по возможности двери записи (и аварийная сессия, открытый режим), подсказки 1–5 и нечитаемая подсистема, `field_values`, `list_table`, ошибка чтения. Векторы —
[`vectors/plan-check/`](../vectors/plan-check/README.md) (случаи `tools-*` и переигровка основы пилота; `LIST_MAX` —
5000 читается, 5001 — ошибка, поле `bulk`). Эта правка норм не добавляет входов учебной приёмки, файлов каталога или новых данных харнеса; работа над этой приёмкой остаётся отдельно закрытой.
