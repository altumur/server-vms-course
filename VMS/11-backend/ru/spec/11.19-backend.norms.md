## Н1 Форма

**Время.** Секунды Unix; `within`, `valid_for` — секунды.

### Н1.1 Сценарии

- Список — `/auto/scenarios` (`configured` и `rows`): сценарий есть, пока есть его строка; слово — выключен, `running` —
  следит, `refused` — отказан, `unreadable` — не читается, иначе — размещается.
- **Ключ — номер.** Сценарий — `auto/scenarios/<id>`, `id` выдаёт дверь (V/07.1); список идёт по номеру, адрес, выбор и журнал — по номеру, люди видят `name`. Новый находится по строке из ответа `POST`.
- **Форма = схема:** «если» — 1–4 триггера `{sub, kind[, unit][, match]}` (V/07.1 Н1.1 `when`); включённому сценарию без `start` или с `start: event` нужен хотя бы один, выключенному и прочим — ни одного; `match` — объект JSON
  как
  есть (текст JSON, разбор, отказ «уточнения — объект JSON»): круг чтение–запись сохраняет типы, сравнение строгое (V/07
  вопрос 1, `"1"` ≠ `1`; случай: `{"pass": 3}` после правки уточнений остаётся числом); «то» — 1–4 действия, включённому нужно хотя бы одно, каждое —
  одна из пяти форм `then` манифеста `auto` с её обязательными полями (`cam output`: `unit`, `port`[, `state`, `pulse_ms`];
  `cam preset`: `unit`, `n`; `rec record`: `cam`, `minutes`[, `archive`]; `det detect`: `cam`, `kind`, `minutes`[, `params`];
  `det scan`: `cam`, `kind`[, `before`, `after`, `rec`, `params`]); шаг с `target` не требует `unit`, `cam`, а действие вне этих пяти показывается и пишется как есть. Форма пишет значения **типом схемы `then`** (форма в
  чужую строку не шире схемы владельца, класс V/07 Н-1): `port`, `n` — целые от 1, `pulse_ms` — целое от 0, `minutes` —
  число 1…1440, `before`, `after` — числа 0…3600; прочие — строки. `params` — строка настроек модели, как у владельца
  поля
  (`det.units.params`, V/04.1 Н1.1): текстовое поле «как есть», без разбора JSON. Действия `det` — только когда консоль
  монтирует `det`: `det` — в `/mounts` консоли (P/06.5 `root`), не в подсистемах модуля (`mount` страницы — `cam`,
  `rec`,
  `live`): предлагаются только тогда, сохранённое действие `det` показывается и пишется как есть. Виды триггера подсказывают
  слова `display.kinds` подсистемы триггера; иной вид вписывается.
- **Отказы формы — отказы двери** (V/07.1 Н4): пустое имя (имя — обычное поле: кириллица и пробелы можно, совпадение с другим сценарием — не отказ); пустые, где нужны, или больше четырёх
  `when`/`then`, незаполненное обязательное поле, значение не своего типа или вне границ схемы `then`, `match` не
  объект,
  `when`, `then` больше 4000 байт канонического JSON (P/06.1), `within` вне 0…3600, `rate_per_minute` вне 1…600 (0 — умолчание),
  `valid_for` вне 10…600 (0 — умолчание), — **и отказ
  двух полей вычислителя** (V/07.3 Н1.1): два триггера и больше без `within`, один триггер с `within`, `det scan` с
  `before` = `after` = 0 (пустое окно). Страница не пишет то, что
  откажут, и говорит это до записи.
- Запись — `POST /auto/scenarios {name, …}` или `PUT /auto/scenarios/<id>` (поля `enabled`, `when`, `then`, `within`,
  `rate_per_minute`, `valid_for`, `name` — если сменилось; поля правила, которых форма не показывает, не пишутся и остаются); удаление — `DELETE` с подтверждением («поданные заявки не отменяются»).
- **Слова вычислителя** — из элемента `status[]` (элементов несколько — `worker_state: live`, нет такого — последний): `refused` с `reason` — «вычислитель отказал: …»; `unfit` — «не годится: …»;
  `unchecked` — «не проверено» (V/07.3 Н1.2).
- **Сработки за сутки** — `/events?subsystem=auto&unit=auto/<id>` (V/07.4 Н1.6): события `fired`, последние 10 — время (`occurred`,
  нет поля — `t`), число поданного (`actions`), `late` — «срок прошёл, не подано».

### Н1.2 Домен

- Вид держателя — `/domain` (через модуль, `refresh`): камеры и записи членов в дереве под членом, их карточки; камера
  одного члена-камеры стоит вместо члена, её записи — под ней. Судит страница по числу единиц `cam` члена с пустым `main` —
  основных строк, как V/11.3 Н1.3 и V/01.6 Н1.5: потоки свёртку не отменяют (ADR-0110 доп. (23) п. 3); `source` в
  `Unit` нет (V/11.3 Н1.3 судит по строке снимка).
- **Папок и групп серверов на странице нет.** Дерево домена идёт по членам. Папки домена и их правка — модуля и двери домена (P/07 Н1.5 `tree`, P/06.8 Н1.2а); страница их не читает и не пишет. В карточке камеры поле «Сервер» — сервер единицы, нет — «—».
- **Назначение записи** (V/02.9 Н1.1; [P/08.6 Н1.1](../../../../Platform/08-domain/ru/spec/08.6-domain.norms.md)) — страница пишет
  только его: `PUT /domain/placement/rec/<ref> {cluster, origin, copies}`; `origin` — кластер камеры; основная — `cluster`;
  резерв — добавить кластер в `copies` (без `cluster`, без повторов, по возрастанию); резерв без основной — отказ словами.
  Есть слово `placement.if-match` (P/07 Н1.5) — `ifMatch`: `rev` прочитанного назначения; 412 — слова, назначение перечитано.
- **Строк записи страница через домен не создаёт и не удаляет:** это связка `backend` (V/11.4 Н1.13), а строку `rec/recordings` (`cam: ref:<ref>`, `ref`; у резерва — дом на резервном
  томе, `when: offline`) заводит оператор кластера записи формой единицы модуля — страница называет её ему. Перенос основной: прежняя запись
  встаёт и хранит архив до срока, её строку убирает оператор её кластера — страница это говорит.
- Таблица «Назначения записи» — `GET /domain/placement` (`records` с префиксом `rec/`): камера, основной, резервы.

### Н1.3 Учётки потоков

- Узел «Учётки потоков» в разделе прав; двери — `/live/accounts` (V/03.6 Н1.2) через консоль: список, создать (`POST
  {name}`), новый пароль (`POST …/password`), включить и отключить (`PUT {disabled}`), удалить (`DELETE`, с подтверждением —
  «её гранты снимаются»). Писать — только при `admin`; сервер проверяет сам.
- **Пароль — один раз:** из ответа `{account: {name, disabled, at, by}, password}`; живёт только в значении поля вывода —
  не в разметке, не в хранилище браузера, не в списке; забывается кнопкой, выбором другого объекта и уходом карточки.
  Ответ без пароля — «шлюз не вернул пароль; запросите новый».

## Н3 Проход

```
сценарий: черновик → отказы двери и двух полей до записи → POST/PUT → перечитать → слова status[] → сработки за сутки
домен: GET назначения → PUT {cluster, origin, copies} → назвать строку записи кластеру; прежнюю не трогать
учётка: POST → пароль в поле вывода один раз → забыть
```

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| форма сценария не по схеме или два поля | слова до записи | форма | поправить |
| дверь отказала 4xx | «Отказано: <слова>» | всплывающее | поправить |
| ответа нет или 5xx | «исход неизвестен», перечитать (глава 15 Н1.2) | всплывающее | по прочитанному |
| назначение изменилось (412) | слова, назначение перечитано | всплывающее | решить заново |
| вычислитель отказал, не годится | слова `reason`, `unfit` | карточка сценария | поправить сценарий или камеру |
| резерв без основной | «сначала назначьте основную» | всплывающее | назначить основную |
| назначение не читается | «назначение недоступно» | всплывающее | позже |
| шлюз не вернул пароль | слова | карточка учёток | новый пароль |


Слова отказа вызова модуля — по главе 16 Н4 (из тела ответа, `message` — только ошибке сети).
