# V/08.3 — Проигрывание и живое: нормы

Канон главы 3 урока V/08 «Страница VMS» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../08-page.md),
[инструкция](08-page.README.md), страница — [`cam.shell.html`](../../01-cam/cam.shell.html). Платформа — выгрузка
`cammeta-specs` `d3f8e05` (пин VMS; глава написана на `8fc3aa2`; раздача потока — `41d3ec8`; поток на двери шлюза —
`b41527f`).

Записанное страница проигрывает кусками с дверей регистраторов, живое — по WebRTC у двери шлюза. Глава нормирует куски и
правило «каждый момент — один раз», повтор отданного дверью отказа, порядок живого: раздача, оффер, повторы, отбой и
переподключение. Двери — V/02.5 Н1.6 (кусок), V/03.1–V/03.5 (шлюз).

Id норм — `V/08.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Секунды Unix; кусок — `PIECE` = 60 с.

### Н1.1 Куски

- Проигрывание — кусками по 60 с: `GET <door>/segment/<запись>/e<эпоха>/<fromMs>-<toMs>[.<источник>].mp4?t=<токен>` у двери,
  назвавшей спан (V/02.5 Н1.6; дверь отдаёт кусок потоком без длины и не больше часа за раз); кусок играет элемент видео
  страницы, следующий — по окончании.
- **Каждый момент — один раз:** спаны перекрываются (две эпохи, два тома, копия удержания); очередь строится от конца уже
  поставленного, а не от начала следующего спана; отсечённый спан (`fenced`) играет, если выбран сам (щелчок по спану)
  или
  если момент не покрыт неотсечённым (как V/02 вопрос 3: отсечённое проигрывает автоматическому выбору; его кадры —
  дубль,
  не порча). Переход по времени (событие, отметка) берёт неотсечённый спан над моментом, нет такого — отсечённый.
  Случай:
  e1 (`fenced`) и e2 на `[100, 200)`, переход к 150 — e2.
- С выбранного момента — куски, кончающиеся после него, первый — со сдвигом до момента.
- Подпись — интервал, эпоха, из резервного ли архива, дозаписано ли.
- Кусок не отдан: элемент видео не видит ни кода, ни заголовков (`busy` — 503 на 5 с, V/02.5 Н1.6, — и отказ токена
  неразличимы). Подпись и один повтор того же куска через 5 с **с новой дверью** (`where` заново: и новый токен); не
  вышло —
  очередь идёт дальше. Цена — один вопрос консоли на неудавшийся кусок.
- Шов между кусками раз в минуту — принятая цена (без склейки в браузере).

### Н1.2 Живое

1. **Раздача:** `POST /live/streams {cam, labels?}` через модуль (V/03.1); метки — явный выбор зрителя на вкладке
   «Видео»:
   «из локальной сети» (умолчание, `labels` не шлётся) или «извне» (`labels: ["public-address"]`, шлюз с публичным
   адресом,
   V/03.1 Н1.2); выбор не хранится (без хранилища браузера, как глава 5 Н1.3). 409 `exists` — норма (раздачу камеры уже
   смотрят): страница читает метки раздачи из строки `GET /live/streams`; созданы для другой сети — подпись «раздачу
   создали для другой сети», при праве `edit` — предложение «переразместить» (`PUT /live/streams/<cam> {labels}`:
   переразмещение рвёт сессии, V/03 вопрос 5). Сетки у страницы нет: поток сетки (`grid`) — для сетки продукта.
2. **Оффер:** WebRTC только на приём, кодек H.265 — с переносом статических номеров нагрузки в 96–127 (V/03.4 Н1.2);
   `POST <door>/whep/<cam>[?stream=<id>]` (дверь — `GET /live/where/<cam>`, глава 2 Н1.1) — `application/sdp`; `stream` —
   выбранный поток (вкладка «Видео» потока) или поток полного экрана камеры (`full`; пусто — основной, `stream` не шлётся;
   V/01.1 Н1.1а). 404 `not yet` — повтор (подписку потока заводит проход шлюза, V/03.3 Н1.2); 404 `stream refused` — слова
   `detail` зрителю, без повтора.
3. **Повторы:** 404 (`not yet` — подписки ещё нет), 503 (`full`, `busy`), 500 (`answer failed`) — снова через 1,5 с:
   первый оффер
   и не больше 8 повторов, всего 9 офферов (V/03.3 Н4), и только пока до конца `grace` строки раздачи (V/03.1, от её
   создания или чтения страницей) остаётся не меньше `ICE_WAIT`; исчерпаны — «шлюз не взял поток». `Retry-After` шлюза странице
   не виден (`cors` договора сертификата роли: `Expose-Headers` без него) — пауза постоянная; окно повторов — 8 × 1,5
   с =
   12 с плюс `ICE_WAIT` каждого из 9 офферов (до 9 × 5 с) — при умолчании `grace` 60 с оно помещается; при малом `grace`
   повторов меньше (решение «Архитектора» 2026-10-29). 403
   — `where` заново один раз (глава 2);
   иной ответ кроме 201 — словами отказа.
4. **Успех** — 201: ответ SDP, сессия — `Location` (`/whep/session/<sid>?gateway=<шлюз>`); подпись — через какой шлюз.
5. **Отбой** — `DELETE <door><Location>` свежим токеном при остановке, уходе с камеры и закрытии страницы (V/03.3 Н1.3).
   Работа, начатая для прежнего выбора, после ухода с него не публикуется: поздний 201 оффера — сразу отбой `DELETE
   <Location>` и закрытие соединения; поздний ответ шкалы прежней камеры не рисуется; таймер повтора куска снимается. Способ
   (поколение выбора, отмена) — канона, не норма.
6. **Переподключение:** соединение потеряно (`failed`, `closed`; `disconnected` — через 5 с) — новый оффер после паузы 1 с (5 с у
   `disconnected`) плюс случайные до 3 с: зрители одной камеры не приходят разом (V/03.2 Н1.3).
7. **Лента событий** при живом: каждые 3 с `/events` камеры с момента начала (−30 с), последние 30. Во вкладке потока —
   `unit=cam/<камера>` потока, как шкала: общее — у потока с его камеры (глава 1 Н1.5); оффер — поток. Показанное
   узнаётся по `id` строки (договор журнала событий: `id` уникален, дубли копий убирают по нему), не по `server`,
   `bucket`,
   `t`, `kind`. Случай: два `plate` одного `t` с разными `id` — оба. Порядок и подпись строки — время события: `occurred`,
   нет поля — `t` (одно время во всех местах страницы, как шкала, глава 2 Н1.3); окно опроса сдвигается по `t` — выборка
   `/events` идёт по `t` (дополнение Kimi к разбору ревью V/08, вопрос 1).

Пока идёт живое, согласование или проигрывание, вкладка «Видео» занята (`busy` вкладки модуля).

## Н3 Проход

```
проигрывание: спан → куски по 60 с от конца поставленного → /segment?t= → по окончании следующий; отказ — 5 с, один повтор с новым where
живое: POST /live/streams {cam, labels?} (409 — метки строки) → оффер → /whep/<cam>?stream=: 404 not yet/500/503 — 1,5 с × 8 повторов;
404 stream refused — слова; 403 — where; 201 — сессия
обрыв — пауза + случайное → новый оффер; стоп — DELETE <Location>
```

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| кусок не отдан | повтор через 5 с с новым `where`, затем дальше | подпись | — |
| шлюз не взял поток после 8 повторов | «шлюз не взял поток» | подпись | позже |
| раздача создана для другой сети | «раздачу создали для другой сети»; с `edit` — «переразместить» | подпись, диалог | переразместить или ждать конца `grace` |
| 409 `exists`, а строка раздачи не прочитана (метки неизвестны) | «метки раздачи не прочитаны», живое не начинается; поля `labels` нет — меток нет, локальная сеть | подпись | повторить |
| WHEP отказал (не 201, не повторяемый) | слова отказа | подпись | — |
| браузер без WebRTC | слова | подпись | — |


Слова отказа вызова модуля — по главе 2 Н4 (из тела ответа, `message` — только ошибке сети).
