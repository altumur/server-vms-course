# V/08.3 — Проигрывание и живое: нормы

Канон главы 3 урока V/08 «Страница VMS» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../08-page.md),
[инструкция](08-page.README.md), контракт — [`consolem.openapi.json`](../../11-backend/consolem.openapi.json). Платформа — выгрузка
`cammeta-specs` `67336416` (пин VMS; глава написана на `8fc3aa2`; раздача потока — `41d3ec8`; поток на двери шлюза —
`b41527f`).

Закладка «Просмотр» проигрывает записанное кусками с дверей регистраторов, живое — по WebRTC у двери шлюза. Адреса и токены даёт контракт, байты идут мимо `backend`. Глава нормирует клиента: куски и правило «каждый момент — один раз», повтор отказа, порядок живого, отбой, переподключение, ленту, титры, разговор, поворот и реле. Двери — V/02.5 Н1.6 (кусок), V/03.1–V/03.5 (шлюз); перевод — V/11.4 Н1.15, Н1.22.

Id норм — `V/08.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Секунды Unix; кусок — `PIECE` = 60 с.

### Н1.1 Куски

- Проигрывание — кусками по 60 с: форма зовёт `GET /devices/{id}/playback?at&spanId` и играет `url` ответа, `<door>/segment/<запись>/e<эпоха>/<fromMs>-<toMs>[.<источник>].mp4?t=<токен>` у двери,
  назвавшей спан (V/02.5 Н1.6; дверь отдаёт кусок потоком без длины и не больше часа за раз); кусок играет элемент видео
  закладки, следующий — по окончании. Адрес годится на кусок и начало следующего: токен 120 с (V/11.4 Н1.22). Кусок чужой записи — адрес у двери её кластера, за NAT `direct: false`: сквозь консоль не отдаётся (ADR-0112 доп. (13) п. 11).
- **Каждый момент — один раз:** спаны перекрываются (две эпохи, два тома, копия удержания); очередь строится от конца уже
  поставленного, а не от начала следующего спана; отсечённый спан (`fenced`) играет, если выбран сам (щелчок по спану)
  или
  если момент не покрыт неотсечённым (как V/02 вопрос 3: отсечённое проигрывает автоматическому выбору; его кадры —
  дубль,
  не порча). Переход по времени (событие, отметка) идёт без `spanId`, спан выбирает `backend`: неотсечённый спан над моментом, нет такого — отсечённый.
  Случай:
  e1 (`fenced`) и e2 на `[100, 200)`, переход к 150 — e2.
- С выбранного момента — куски, кончающиеся после него, первый — со сдвигом до момента.
- Подпись — интервал, эпоха, из резервного ли архива, дозаписано ли.
- Кусок не отдан: элемент видео не видит ни кода, ни заголовков (`busy` — 503 на 5 с, V/02.5 Н1.6, — и отказ токена
  неразличимы). Подпись и один повтор того же куска через 5 с **с новым адресом** (`playback` заново: и новый токен); не
  вышло —
  очередь идёт дальше. Цена — один вопрос `playback` на неудавшийся кусок.
- Шов между кусками раз в минуту — принятая цена (без склейки в браузере).

### Н1.2 Живое

1. **Раздача и адрес:** `POST /devices/{id}/live {width, height, network?, streamId?}` объединяет раздачу и `where` (V/11.4 Н1.15, V/03.1); сеть — явный выбор зрителя на закладке: «из локальной сети» (`local`, умолчание) или «извне» (`outside`, шлюз с публичным адресом, V/03.1 Н1.2); выбор не хранится. Ответ — `{whepUrl, token, expiresAt, gateway?}`. 409 `OTHER_NETWORK`, `params.labels` — подпись «раздачу создали для другой сети», при праве `admin` на камеру — «переразместить»: `PUT /devices/{id}/live {network}`, рвёт сессии всех зрителей (V/03 вопрос 5), затем снова `POST`. 409 `OTHER_CLUSTER` — кнопка «Открыть» по `params.url`, камера за NAT — словами `direct: false`.
2. **Оффер:** WebRTC только на приём, видео и звук (V/03.4 Н1.5), кодек H.265 — с переносом статических номеров нагрузки в 96–127 (V/03.4 Н1.2); камера отдаёт H.265, браузер его не показывает — отказ словами до оффера;
   `POST <whepUrl>` с `Authorization: Bearer <token>` — `application/sdp`;
   `streamId` — выбранный поток; без него — размер окна видео в пикселях экрана (`clientWidth`,
   `clientHeight` × `devicePixelRatio`, округление), поток выбирает шлюз (V/03.3 Н1.2); окно не размечено, размер 0 — параметров нет,
   основной. Размер берётся один раз на попытку показа: новое окно идущую сессию не меняет. 404 `not yet` — повтор (подписку потока заводит проход шлюза, V/03.3 Н1.2); 404 `stream refused` — слова
   `detail` зрителю, без повтора.
3. **Повторы:** 404 (`not yet` — подписки ещё нет), 503 (`full`, `busy`), 500 (`answer failed`; V/03.3 Н4), 5xx `POST /live` и
   сбой сети (до первого прохода шлюза двери нет, V/03.3 Н1.1) — снова через 1,5 с, в том же счёте:
   первый оффер
   и не больше 20 повторов, всего 21 оффер (V/03.1 Н1.1; поток в `idle` поднимается до 22 с, V/01.2 Н1.2в; оффер после 403 входит в 21), и только пока до `expiresAt` остаётся не меньше `ICE_WAIT` 5 с; исчерпаны — `POST /live` один раз: новый адрес — новая серия,
   тот же — «шлюз не взял поток». `Retry-After` шлюза форме
   не виден (`cors` договора сертификата роли: `Expose-Headers` без него) — пауза постоянная; окно повторов — 20 × 1,5
   с =
   30 с плюс `ICE_WAIT` каждого оффера, в пределах `grace` 60 с; при малом `grace`
   повторов меньше (решение «Архитектора» 2026-10-29). 403
   — `POST /live` заново один раз;
   иной ответ кроме 201 — словами отказа.
4. **Успех** — 201: ответ SDP, сессия — `Location` (`/whep/session/<sid>?gateway=<шлюз>`); подпись — через какой шлюз. Ответ не
   принят браузером — слова, отбой, соединение закрыто.
5. **Отбой** — `DELETE <Location>` свежим токеном при остановке, уходе с камеры, выходе из сессии
   и закрытии вкладки браузера (V/03.3 Н1.3); закладка той же камеры — не уход: «Просмотр» и «Видео» один клиент и не закрывают соединение. `Location` виден: шлюз отдаёт его в `Expose-Headers`. При закрытии — `keepalive` с токеном из памяти; не дошло —
   сессию снимает шлюз (V/03.5).
   Работа, начатая для прежнего выбора, после ухода с него не публикуется: поздний 201 оффера — сразу отбой `DELETE
   <Location>` и закрытие соединения; поздний ответ шкалы прежней камеры не рисуется; таймер повтора куска снимается. Способ
   (поколение выбора, отмена) — выбор форка, не норма.
6. **Переподключение:** соединение потеряно (`failed`, `closed`; `disconnected` — через 5 с) — живое заново с п. 1 (раздачу могли
   удалить, V/03.1 Н3) после паузы 1 с (5 с у `disconnected`) плюс случайные до 3 с: зрители одной камеры не приходят разом
   (V/03.2 Н1.3); предел — п. 3.
7. **Лента событий** при живом: снимок `GET /journal?deviceId&from=<начало − 30 с>&limit=30`, дальше поток `journal.event` по наблюдению (V/11.5 Н1.2). `deviceId` — и строки про камеру (`cameraId`). Показанное узнаётся по `id` строки: `id` уникален, дубли копий убирают по нему. Случай: два `lpr` одного `t` с разными `id` — оба. Порядок и подпись строки — время события: `occurred`, нет поля — `t`, одно время во всех местах, как шкала, глава 2 Н1.3. **Цена и предел** потока — V/11.5: опрос журнала раз в 3 с на поток со списком, `truncated` теряет строки.
8. **Звук:** дорожка того же потока браузера, играет элемент видео. Браузер отказал в автозапуске со звуком — элемент без звука (`muted`), зритель включает его сам кнопками элемента. Кусок записи со звуком
   (V/02.5 Н1.6) играет тот же элемент.
9. **Разговор** (V/03.3 Н1.2а): кнопка «Говорить» на закладке — первый по номеру живой невыключенный `spk` этой камеры (V/01.4 Н1.4а), при операции `startTalk`.
   Порядок: микрофон браузера; `POST /devices/{spk}/talk` → `{url, token, expiresAt}` (V/11.4 Н1.15: просьба `cam`, раздача, адрес); оффер только на отправку на `url`. 404 `not yet`, 500, 503 — снова через 1,5 с, всего 9 офферов, после 500 — и `POST` снова: шлюз положил трубку; 409 `busy` — «динамик занят»: его говорит дверь на оффере, не выдача адреса; иной ответ — слова отказа.
   201 — кнопка «Закончить разговор», отбой — п. 5; поздний 201 после ухода — сразу отбой. Уход с камеры, выход и закрытие вкладки браузера кончают разговор: микрофон открытым не остаётся.
10. **Титры** (ADR-0102 доп. (9) п. 6). Источник один, журнал: строки вида `text` (V/01.2 Н1.5) строк `eventsrc`, чей `camera` — эта камера (V/01.1 Н1.1г). В кадр не вжигаются (V/03.4 Н1.3): форма
    рисует их поверх видео, текстом, не разметкой. Живое: строки `journal.event` с `kind: text`, дубли — как п. 7, строка показывается через `overlayDelayMs` после прихода, держится `overlayDurationSec`, `0` и нет поля — до следующей; `Device` источника читается один раз на показ.
    Архив (куски, Н1.1), **в форме нет, глава 1 Н1.1**, на странице-свидетеле: те же строки за время куска, по `occurred`, нет поля — `t`, плюс `overlay_delay_ms`; показ по времени кадра. Строки прочитанных кусков остаются на время показа камеры: титр не обрывается на границе куска; перед куском, куда перешли, строки не читаются, титр появится со следующей: это предел. Живое снимает титры архива. `word` строки — цвета `color`, `bg` элемента `words` с тем же `msg`; нет такого — без цвета.
    Строка без `lines` или не по форме — титра нет, журнал её показывает как есть. Нет права `view` на строку `eventsrc` — строк нет, титров нет. `words`, `overlay_*` не прочитаны — без цвета, без задержки, до следующей: титр важнее оформления. Задержка титра — такт опроса журнала, V/11.5; её цена — на замере (ADR-0102 доп. (9) п. 6).
11. **Поворот и пресеты** (ADR-0112 доп. (4) п. 3): блок на закладке при `ptz`. Движение, пока кнопка нажата: `PUT /devices/{id}/ptz`, отпущена — `DELETE`, аренда — V/11.4 Н1.16. Кнопка «Пресет» заводит номер и положения не трогает; «Запомнить здесь» — `PUT /devices/{id}/presets/{n} {}`, запоминает нынешнее положение; имя — `PUT {name}`, положения не трогает никогда. Предел — `Device.presetMax`. Камера за NAT: **предел**, ADR-0111 доп. (1), V/11.4 Н1.16: положение пишет устройство, дверью правки не проходит, 409 `OTHER_CLUSTER`.
12. **Реле вручную:** `POST /devices/{relay}/operations/output {state, pulseMs?}`, замкнуть, разомкнуть, импульс; без связи кнопка неактивна (V/11.4 Н1.17).

Пока идёт живое, разговор, согласование или проигрывание, закладка не закрывает соединение при смене закладки той же камеры (п. 5).

## Н3 Проход

```
проигрывание: момент или спан → playback → url куска → по окончании следующий от конца поставленного; отказ — 5 с, один повтор с новым адресом
разговор: микрофон → POST talk → url: 404/500/503 — 1,5 с × 8 повторов; 409 busy — слова; 201 — сессия
живое: POST live {network, streamId} → оффер whepUrl: 404 not yet/500/503 — 1,5 с × 20 повторов;
404 stream refused — слова; 403 — POST live; 201 — сессия
обрыв — пауза + случайное → живое заново; стоп — DELETE <Location>
```

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| кусок не отдан | повтор через 5 с с новым адресом, затем дальше | подпись | — |
| шлюз не взял поток после 20 повторов | «шлюз не взял поток» | подпись | позже |
| раздача создана для другой сети | 409 `OTHER_NETWORK`, «раздачу создали для другой сети»; с `admin` — «переразместить» | подпись, диалог | переразместить или ждать конца `grace` |
| WHEP отказал (не 201, не повторяемый) | слова отказа | подпись | — |
| браузер без WebRTC | слова | подпись | — |
| камера H.265, браузер без него | слова до оффера | подпись | другой браузер |
| разговор: микрофон не дан, динамик занят, шлюз не взял разговор | слова | сообщение формы | позже |


Слова отказа — `Problem` контракта, по главе 2 Н4.
