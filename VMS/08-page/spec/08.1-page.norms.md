# V/08.1 — Оболочка над модулем: нормы

Канон главы 1 урока V/08 «Страница VMS» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../08-page.md),
[инструкция](08-page.README.md), страница — [`cam.shell.html`](../../01-cam/cam.shell.html). Платформа — выгрузка
`cammeta-specs` `f225f3ef` (пин VMS; глава написана на `8fc3aa2`; модуль консоли — `bbd52ce`: `features`, `pc.ready`,
`select` с вкладкой, `card.closed`; источник `size`, общие поля потока — `b41527f`).

Страница VMS — оболочка над модулем консоли платформы: рамку, дерево, карточки единиц, серверов, воркеров, домена, людей,
журнал и вход даёт модуль; страница добавляет то, что знает только VMS. Глава нормирует, как страница отдаётся и
подключается к модулю, что она добавляет, чего не делает, и часть камеры. Двери держателей и шкала — глава 2.

Id норм — `V/08.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Данные.** Своих строк у страницы нет; читает состояние модуля и двери консоли (главы 2–5).

### Н1.1 Отдача

- Канон страницы — `VMS/01-cam/cam.shell.html` (ADR-0090 доп. (6) п. 8). Установщик кладёт `<sub>.shell.html` рядом с
  манифестом и в поле `shell` строки `platform/manifest/cam` ([P/02.3 Н1.5](../../../Platform/02-installer/spec/02.3-installer.norms.md));
  консоль отдаёт его байт в байт на `/` только корнем `CONSOLE_ROOT=cam`; смонтированная подсистема страницу отдаёт только с
  `console.shell` ([P/06.5 Н1.1](../../../Platform/06-console/spec/06.5-console.norms.md) `mounted`): у VMS это `backend` (V/11.1), у `cam` смонтированной консоли страницы нет.
- Политика содержимого консоли исполняет только скрипт страницы по его хэшу и файлы своего источника; в разметке нет ни
  одного обработчика в атрибуте (`on…=`; текст скрипта — не разметка): установщик такую оболочку отвергает (код 2), консоль
  отвечает 503. Обработчики вешаются кодом по атрибуту `data-act`; всё, что страница рисует из данных (имя камеры, слова события, адрес тома), —
  текст: экранируется до вставки.

### Н1.2 Модуль

- Голова страницы — стили и библиотека модуля (`/platform/console.css`, `/platform/console.js`); до использования модуля
  страница сверяет `version` с той, под которую написана (`1`), иная — страница говорит это и модуль не монтирует
  ([P/07 Н1.5](../../../Platform/07-console-module/spec/07-console-module.norms.md) `version`). Новое сверх первых вызовов версии 1
  страница узнаёт по `PlatformConsole.features` (`select.tab`, `card.closed`, `api.if-match`, `placement.if-match`, `session`, `tree.repaint`), не по версии: строки нет — вызова нет.
- Готовность — `await pc.ready` (обещание: после `mount` и первого прочитанного `/manifest`, при 401 — после входа) до чтения
  манифестов.
- `mount(#app, {lang: ru, subsystems: [cam, rec, live]})`: записи и раздачи — «про» камеру (`about`), модуль вкладывает их
  под неё; страница читает манифесты подсистем (`manifest`), слова (`display`), права (`may`), состояние — событиями модуля
  (`refresh`, `select`).
- Запись — только `api()` модуля. Сам модуль повторяет только `POST` строк единиц (P/07 Н1.5); прочие записи страницы (`PUT`, `DELETE`, таблицы, `/marks`, `POST /rec/requests`) не повторяет: ответа нет или 5xx — исход неизвестен, страница отказа не утверждает; чтение
  консоли — запросами с той же сессией.

### Н1.3 Что страница добавляет

Вызовами модуля (P/07 Н1.5 `adds`, `cards`):

| Вызов | Что |
|---|---|
| `addIcons`, `addDecor("unit")` | значки камеры, устройства и тома; у камеры — значок и хост адреса бейджем, у потока — его имя и имя камеры, у строки не `camera` — слово её `type` (Н1.5) |
| `addTreeNodes("unit")`, `addCard("child")` | дети устройства под хозяином и их карточка (Н1.5) |
| `addFieldEditor("unit", "source")` | адрес камеры и что он говорит (хост, производитель, канал) — Н1.5 |
| `addNote("unit")`, `addEventNote` | заметки камеры, события VMS словами — Н1.5 |
| `addTab("unit")` | «Видео» (глава 2, 3), «Потоки» (Н1.5), «Архив» (глава 4) |
| `addTreeNodes("server" \| "servers")`, `addCard("vol" \| "netvols")`, `addBlock("server")`, `addAction("server")`, `addMenu("server" \| "vol")` | тома и «камеру в архив» (глава 4) |
| `addSection` | «Сценарии» (глава 5) |
| `addSection` | «Ассистент» (V/10.3–V/10.6: панель ассистента, код — в каноне `cam.shell.html`) |
| `addTreeNodes("member")`, `addCard("dc" \| "da")`, `addBlock("member" \| "domain")` | домен глазами VMS, назначения записи (глава 5) |
| `addTreeNodes("access")`, `addCard("streamaccounts")` | учётки потоков (глава 5) |
| `addMenu("unit")` | «Смотреть видео», «Архив» |

Виды — по P/07 Н1.5: `addBlock` — `server`, `member`, `domain`; `addTreeNodes` — `unit`, `servers`, `server`, `member`, `access`.

### Н1.4 Чего страница не делает

Своего входа, дерева серверов, карточки домена, журнала — нет (модуля). Байты — шкала, куски, живое — идут через двери
держателей, не через консоль (ADR-0015). Хуков нет. **Чужого DOM** нет: модуль — его, страница пользуется вызовами;
открыть вкладку — `select(ref, {tab})` с id вкладки из `addTab` (`vid`, `rec`), узнать, что карточку убрали, — событие
`card.closed {ref}` (и у карточки оболочки — `streamaccounts:local`; ADR-0091 доп. (22), (24), (25)). Без строки `features` —
только `select(ref)` (вкладку оператор открывает сам) и забывание по `select`; щелчков по разметке модуля и слежения за ней нет.

### Н1.5 Камера

- **Адрес** — разбор `source` для человека: `driverpack://<производитель>/<хост>/ch/<канал>`, иначе хост и порт адреса; правка —
  только с правом `edit` на камеру, форму шлёт модуль.
- **Заметки:** сбой устройства (`phase: failed`) — словами держателя (`reason`, иначе `why`), и при `device_state: opening`;
  только `device_state: opening` — проверить адрес, сеть, учётные данные; `phase: idle` — почему потока нет и когда он откроется (V/01.2 Н1.2в).
- **События словами:** виды VMS, у которых есть производитель, — `archive.volume.shrunk`, `archive.footage.dropped`,
  `card.prebuffer.short`, `card.failing`, `archive.backfill.refused`, `archive.backfill.unscanned` (V/02.3, V/02.4, V/02.6, V/02.8); слово вида — `display.kinds` его
  подсистемы, иначе любой подсистемы VMS, иначе модуля (`kindWord`); события платформы описывает модуль.
- **Потоки камеры** (V/01.1 Н1.1а; выгрузка `41d3ec8`). Поток — единица `cam` с `main`; модуль рисует его единицей (дерево для
  `about` на свою подсистему — запрос VMS после стадии C, п. 2), страница подписывает его бейджем «<имя потока> ↑ <камера>».
  Вкладка «Потоки» камеры (и потока — его камеры): потоки с хостом, фазой и `reason`; «Смотреть» — «Видео» потока
  (`select(ref, {tab})`); «＋ Поток» — `POST /cam/cameras {main, profile, source[, cred_username, cred_secret]}` (пароль пуст —
  пароль камеры, если хост тот же, V/01.2 Н1.2) — и только эти поля: общих полей потоку страница не даёт (V/01.1 Н1.1а).
  Поток просмотра выбирает шлюз по размеру окна (глава 3 Н1.2), страница выбора не хранит. Поток записи подсказывает: самый
  крупный кадр (глава 4). `size` (V/01.2 Н1.4) страница берёт там же, где фазу и `reason` единицы: элемент `status[]`
  пульса держателя приходит строкой `rows` ответа `GET /cam/cameras` ([P/06.1](../../../Platform/06-console/spec/06.1-console.norms.md) Н2), а единицы события
  `refresh` модуль отдаёт «как они пришли» ([контракт модуля](../../../КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md), `refresh`) — так
  страница читает и фазу; без `size` — подсказки нет, основной. Общее — шкала, события, удержания, «Архив» — у потока
  читается с его камеры.
- **Форма карточки** — блоки `display.form` манифеста `cam`, рисует модуль (P/07 Н1.5), своих полей страница не добавляет:
  «Идентификация» — `short`, `type` (слова `options.type`; при правке недоступен: `fixed`), «Подключение» — `mac`, «Потоки» —
  `resolution`, `fps`, «Положение» — `lat`, `lon`, `azimuth`. Поля положения — тип `json`: модуль показывает значение текстом и
  читает его обратно; пустое поле не шлётся: значение очищается словом `null` в поле.
- **Вид строки** (V/01.1 Н1.1б). Кадры, запись и детекторы — только у `camera`: строка `ipsrv`, `eventsrc`, `acfa` стоит в дереве значком
  устройства с бейджем-словом `type`, вкладки «Видео», «Потоки», «Архив» говорят, что кадров нет, меню «Смотреть видео» и «Архив» у
  неё нет, в выбор камеры записи (глава 4) она не идёт. Строка без поля `type` — `camera`: умолчание двери.
- **Дети устройства** (V/01.1 Н1.2а). `addTreeNodes("unit")` рисует под хозяином (камера или строка `ipsrv`) строки
  `cam/children` без `gone` — `sensor`, `relay`, `mic`, `spk`, по виду и номеру; подпись — `title` настройки, иначе слово вида и `number`;
  выключенный — приглушён по правилу V/01.4 Н1.4а. Обе таблицы страница читает при `refresh`; таблицы нет у консоли — детей нет; ответ
  не прочитан — прочитанное остаётся, заметка камеры называет причину; смена человека забывает обе таблицы. Таблицы сменились — страница зовёт `repaintTree()` модуля (`features`: `tree.repaint`, P/07 Н1.5): его данные не менялись, сам дерево он не перерисует. Карточка `child:<ключ>`: вид, номер, хозяин, поля `title`,
  `enabled` (три значения: не сказано, включён, выключен), у `sensor`, `relay` — `norm`. Запись — с правом `edit` на хозяина,
  `POST /cam/child_settings` строкой целиком (P/06.1 Н1.6); не сказанное поле не шлётся. `enabled` у `mic`, `spk` действует
  (V/01.4 Н1.4а); у `spk` на карточке — кнопка разговора (глава 3 Н1.2 п. 9).
- **Единицы устройства** (V/01.1 Н1.2б). `addTreeNodes("unit")` рисует под строкой её `cam/device_units` по `n`, плоско; подпись — `title`, иначе слово вида и `n`; `enabled: false` — приглушена. Читается с таблицами детей, по тем же правилам. Карточка `dunit:<ключ>`: вид, номер, шаблон, строка, владелец, `title`, `address`, `enabled`; запись — с правом `admin` на строку, `POST /cam/device_units` строкой целиком. Слово `units_down` (V/01.2 Н1.4) — словами; `device_state: lost` строки — «нет связи» у неё и у её единиц. С правом `edit` — операция: `POST /cam/requests {unit, action: "unit", n, operation}` (V/01.4 Н1.1); перечня операций у страницы нет, слово вводит оператор: `.rep` у неё нет. Заведение единиц — `backend` (V/11.4 Н1.2), кнопки у страницы нет.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| модуль другой версии | страница не монтирует модуль, слова | оператор | обновить консоль или страницу |
| обработчик в атрибуте | установщик — код 2, консоль — 503 | установщик, консоль | убрать |

## Н5 Приёмка

Каталога приёмки у урока нет (как P/07 Н5): своей подсистемы и двери у страницы нет — чтением и jsdom-тестами курса
(`Source/tests/console`, `shell-*`, в выгрузку не входят; проверки оболочки — по канону `VMS/01-cam/cam.shell.html`; тесты ведёт владелец `Source/tests`).

## Решает реализация

Реализаций у главы нет: страница — канон (`cam.shell.html`, ADR-0090 доп. (6) п. 8), её не генерируют; реализация
отдаёт её байты как есть (P/02.3 Н1.5), как модуль консоли. Раскладка, классы и тексты подписей — выбор канона, не
норма.

## Соответствие прежним урокам

Из М10B/12 «Страница VMS» — вводная, шаги 1 (консоль VMS — консоль платформы), 2 (страница рядом с манифестом), 3 (ни
одного обработчика в разметке), 4 (камера). Отличия от свидетеля: страница отдаётся полем `shell` манифеста корня (у
свидетеля — функция консоли искала файл); сверка `version` модуля; виды событий без производителя (`volume.missing`,
`camera.footage.lost`, `camera.uplink.short`) сняты; чужой DOM снят — `select(ref, {tab})`, `card.closed`, `features` (ADR-0091
доп. (22)–(25)); механизм сверки ядра страницы с
продуктом нормой не становится (ADR-0080). Id ([id-map](../../common/id-map.tsv)): М10B/12 ш.2 → V/08.1-01; М10B/12 ш.1, 2 →
V/08.1-02; М10B/12 ш.2 → V/08.1-03; М10B/12 ш.3 → V/08.1-04; М10B/12 ш.4 → V/08.1-05.
