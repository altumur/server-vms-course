## Что такое урок V/07

Подсистема `auto`: **сценарий** — «когда это случилось (и то, в пределах тридцати секунд), сделать вот это». Единица —
строка `auto/scenarios/<name>`; вычислитель — воркер `autoworker`, ровно один на сценарий (эпоха и аренда). Вычислитель —
вопрос к журналу событий, не автомат: читает слитый журнал кластера, решает сработку по завершающему событию и действует
через подсистемы-владельцы — просьбой держателю камеры (реле, пресет) или заказом строки на время (детектор, задача по
интервалу, запись). Сценарии между камерами разных членов живут в общих настройках домена, исполняет их вычислитель
кластера триггера, просьба идёт на приёмник камеры-цели с токеном `ask`.

## Формы и двери

- **Строки и объекты:** `auto/scenarios/<name>`, курсор `auto/state/cursor/<scenario>`, просьбы `cam/requests/<rid>` (подача),
  заказы `det/units/auto-…`, `detjob/jobs/auto-…`, `rec/recordings/auto-…`, вклад книги `auto/asks/<слот>`, копии
  `domain/shared`, `domain/auto/asks`; события `auto/<scenario>/e<n>` (`fired`, `suppressed`).
- **Двери:** своей HTTP-двери у `auto` нет — строки дверью консоли (P/06.1), общие настройки — дверь домена (P/08.9), просьба
  сценария — приёмник регистратора (V/02.9); OpenAPI урока нет — строка реестра `V/07 no-openapi` (запросом с главой V/07.1).

## Решения для плана (приняты «Архитектором» 2026-10-23)

1. **Запись на время — заказом:** `worker.creates: [{sub: rec, rows: recordings, key: "{cam}"}]` → `rec/recordings/auto-<cam>`,
   `until` = событие + `minutes`, `home` ← `archive`. Мешает: у `rec` поле `ref` `fixed`, но не `required` — проверка каталога
   (ключ называет каждое `fixed`-поле, подстановка — только обязательные, P/02.1 Н3) отказала бы. Решение подсистемы: у
   `rec.ref` снять `fixed` (V/02.1, V/02.9 Н1.1) — совпадение `ref` с камерой сверяет регистратор (`waiting` «ref differs from
   cam»); запроса не нужно.
2. **Маска заказанного детектора — `mask_from` у `det`** (как у `detjob`, ADR-0091 п. 1): заказ копирует маску детектора
   оператора ссылкой (`det/<id>@sha256-<hex>`), иначе детектор сценария смотрел бы весь кадр (P/03.6 Н1.6: blob заказа пуст);
   правка V/04.1, V/04.2 Н1.2 и манифеста `det` этой же главой V/07.4.
3. **Скан — заказом к `detjob`:** ключ `"{cam}-{rec}-{kind}-{from}-{to}"` (как у регистратора, V/02.8 Н1.5), окно
   `[occurred − before, occurred + after)`, умолчания 60/60 с, границы — целыми секундами (повтор той же сработки —
   `unchanged`); `rec` не указан — запись с id = `cam`, иначе первая по имени запись камеры; нет записи — отказ вычислителя;
   поля детектора оператора той же пары — `params` (поверх — заявки), `labels`, `alarms`, `mask_from`.
4. **Второй детектор не заводится:** включённый детектор оператора той же пары (`cam`, `kind`) без `made` с `until` = 0 —
   заказа нет (`watched` в пульсе); нужно `det/units/` в `worker.reads`.
5. **Чтение журнала — запрос** [`события для воркера`](../../decisions/inbox/2026-10-23-запрос-vms-события-для-воркера.md):
   рекомендация — дверь консоли `/events` воркеру по сертификату роли (слияние, `fenced`, `complete` — одно определение с
   консолью). Обход до решения: `GET /events` каждого живого ресурса и слияние по `id`, окно полное — все ответили без
   `truncated`; `fenced` не различается (долг).
6. **Имя поданной просьбы — запрос** [`rid подачи воркером`](../../decisions/inbox/2026-10-23-запрос-vms-rid-подачи-воркером.md):
   рекомендация — `rid` из ключа подателя (`<сценарий>-<id события>-<i>`). Обход: случайный `rid`, повтор в окне курсора
   (≤ 10 с) возможен — долг; сдерживает `valid_until`.
7. **Одно имя на обеих сторонах:** в документе домена `then.within` (срок просьбы) → `valid_for`, как у сценария кластера;
   `action` — `enum: [preset, output]`, `arg` → `n` / `port`, срок ≤ 600 с, `rate_per_minute` ≤ 600 — форма у двери домена
   ловит то, что можно поймать формой; смысл (что умеет цель) — отказ исполнителя и цели.
8. **`worker.reads`** + `cam/cameras/`, `cam/heartbeats/` (`can` камер), `cam/devices/`, `det/units/`, `rec/recordings/`,
   `rec/heartbeats/` (адреса приёмников для книги `asks`).
9. **Пульс и ряды:** фазы сценария `running` | `refused` | `failed` (под взятой эпохой), `why` — платформы, слова — `reason`,
   поля `unfit`, `unchecked`, `holding`, `decided_without`, `late`; ряды `creates_total{outcome}`, `made_rows`; ряд
   `wants_folded` снять (свёртки нет).
10. **Перенос просьбы ретранслятором** — протокол в V/07.5, сторона передатчика — строкой в V/02.9 Н1.8 со ссылкой.

## Отличия от свидетеля, которые урок записывает

Исполнитель заданий и `requests.elsewhere` сняты: детектор, скан и запись — заказ строки (`worker.creates`), реле и пресет —
подача воркером; курсор — `unit.state.cursor` (не файл); ответвление `domainpart` и издатель книг воркера VMS у держателя
сняты — книгу `asks` издаёт вычислитель узла пути (ADR-0074 C6); имена заказов — `auto-…`; свёртка `wants` снята; чтение
журнала — слитый журнал (запрос).

## Правки манифеста при переводе

`auto`: `worker.creates` + `rec`, `detjob`; `worker.reads` (решение 8); `unit.state.cursor`; документ `scenarios` (решение 7);

V/02.9 Н1.8 — перенос просьбы. Продукт — строкой долга «Сборке».
