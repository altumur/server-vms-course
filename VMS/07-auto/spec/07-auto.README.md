# V/07 Сценарии — инструкция для реализации

Что реализация подсистемы `auto` делает и как проверить результат. Канон — нормы глав `07.K-auto.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `226bd220`.

## Входы и их приоритет

- Канон — нормы глав `07.K-auto.norms.md` (Н1–Н5 каждой главы; адреса `V/07.K Н…`).
- Канон манифеста — [`auto.subsystem.yaml`](../auto.subsystem.yaml): байты как есть.
- Приёмка — [глава 1](../acceptance/1/README.md), [глава 6](../acceptance/6/README.md); векторы функции момента — [`moment`](../vectors/moment/README.md); стенд и словарь — [общий README приёмки VMS](../../common/acceptance/README.md); новых требований приёмка не вводит.
- [Лекция](../07-auto.md) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…` (их правит не VMS).

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/07.1 | манифест `VMS/07-auto/auto.subsystem.yaml` грузится строгим загрузчиком без правок (каталог VMS целиком); дверь единиц консоли исполняет ключ-номер, схемы `when`, `conditions`, `then` и границы полей; форму шага внутри ветки судит вычислитель | [приёмка 1](../acceptance/1/README.md) |
| V/07.2 | желания, чтение слитого журнала (участник договора `events-merge`, эпохи по `worker.reads`), сработка по завершающему событию, курсор `unit.state.cursor` (полное окно, `COLD_START`, новая `revision` по строке курсора), долгий опрос; запуск по расписанию и вручную; `LONG_POLL` в `/etc/auto/auto.env` | чтением |
| V/07.3 | отказ двух полей, сверка сценария с `can`, строками устройств, детекторов и записей (`unfit`, `unchecked`), тексты отказов | чтением |
| V/07.4 | просьбы `cam` (срок от события, `late`), заказы `rec`, `det` (основа, `mask_of`, второй не заводится), `detjob` (окно, поля детектора); действия `arm`, `disarm`, `disable`, `alarm`; проверки до действий, разворот целей, строка запуска `unit.state.runs` и шаги ожидания, `repeat`; потолки; события `fired`, `step`, `suppressed`; просьбы `run`, `retry`, дверь `test`; пульс и ряды | чтением, `@manual` приёмки 1 |
| V/07.5 | документ `auto.scenarios` (форма), исполнитель кластера триггера, вклад книги `asks`, просьба на приёмник с токеном `ask` и исходы, перенос через ретранслятор | чтением |
| V/07.6 | таблицы `auto`, функция момента `in_effect`, `sun`, режим `object_mode` и поле пульса, окна, `TIMEZONE` окружения, стенные минуты при переходах | [приёмка 6](../acceptance/6/README.md), векторы [`moment`](../vectors/moment/README.md) |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam`, `rec`, `det`, `detjob`, затем `auto` —
приёмка VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/07.2 Н1.3 | сравнивать поле события нестрого (`"1"` и `1`) | сравнение строгое, тип поля задаёт пишущий урок |
| V/07.2 Н1.3 | судить пару порядком появления строк или памятью | завершает позднейшая по `(t, id)`: одна сработка у любого держателя |
| V/07.4 Н1.3 | расширять или менять задачу скана повторным заказом | одна задача на окно, поля — первого заказа, повтор — `unchanged` |
| V/07.6 Н1.3 | считать хвост интервала частью следующего дня только внутри `valid` | срок судит день начала: хвост последнего дня приходит, хвост дня до срока — нет |
| V/07.6 Н1.4 | считать `sun` в местном поясе или брать знак остатка языка | сдвиг — `utc_offset_hours` строки, `fmod` со знаком делимого, округление `⌊x + 0.5⌋` |
| V/07.6 Н1.1 | считать нечитаемую строку таблицы отсутствующей | не прочитано — не отсутствует: `unknown`, `cond.unread` |
| V/07.5 Н1.4 | склеивать просьбы между камерами без `firing` | слияние по `(by, цель, действие, firing)`; строка у держателя — `rec.ask-<firing>-<i>` |
| V/07.4 Н1.1 | давать просьбе случайное имя | имя просьбы — `auto.<32 hex>-<i>` |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; приёмка глав 1, 6 и векторы `moment` проходят на платформе, прошедшей свою приёмку;
пункты чеклистов, отмеченные «чтением», подтверждены описанием реализации (раздел «Решает реализация» каждой главы).
Проверка схемы, загрузчика и стенда друг друга не подменяют.

## При расхождении

Порядок источников: нормы главы → OpenAPI → приёмка и векторы → лекция; платформа — нормы выгрузки пина VMS.
Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и предложением; норма
платформы — через «Архитектора». Дефект приёмки (ожидание против нормы) — тот же маршрут; закрытое решение
вносится в канон, а не остаётся в этой инструкции.
