# V/07.3 — Соответствие и отказы: нормы

Канон главы 3 урока V/07 «Сценарии» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../07-auto.md),
[инструкция](07-auto.README.md), манифест [`auto.subsystem.yaml`](../auto.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `002c6bf5`.

Форму сценария проверила дверь (глава 1); смысл — вычислитель: поднимает ли камера такое событие, есть ли у неё такой
выход и пресет, есть ли такой детектор, пишет ли кто-нибудь камеру, которую сценарий хочет сканировать. Глава нормирует
отказ двух полей, проверку против того, что сказали устройства, «не знаю» против «не умеет» и тексты отказов.

Id норм — `V/07.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — строки камер `cam/cameras/*`,
пульсы держателей `cam/heartbeats/*` (`can` камеры, V/01.4 Н1.4), строки устройств `cam/devices/*`, строки детей и настройки `cam/children/*`, `cam/child_settings/*` (V/01.1 Н1.2а), единицы `cam/device_units/*` (V/01.1 Н1.2б), строки детекторов
`det/units/*`, строки записей `rec/recordings/*`, папки `platform/folders/*` (`worker.reads`; у `auto` нет `about`, чужие строки — по объявлению,
[P/02.5 Н1.4](../../../Platform/02-installer/spec/02.5-installer.norms.md)), свои таблицы — глава 6.

### Н1.1 Отказ двух полей

Смысл, который форма одного поля не выражает, — отказ вычислителя (связь двух полей — правило вычислителя, как V/05
находка 2). Выключенный сценарий не судится: незаконченная строка с пустыми `when`, `then` хранится (V/07.1). Включённый — фаза `refused`, `reason` — слова первого выполненного условия сверху; он не срабатывает, просьба `run` отказана (глава 4 Н1.12):

| Условие | `reason` |
|---|---|
| `start: event`, `when` пуст | `an event scenario needs a trigger` |
| `start: schedule`, нет `run_at` или `days` пуст | `a scheduled scenario needs run_at` |
| в `then` нет ни одного действия, на любой глубине | `a scenario needs an action` |
| `start: event`, два триггера и больше при `within` = 0 | `two triggers need within: the window they must fall into` |
| `start: event`, один триггер при `within` > 0 | `within is the window between triggers; with one trigger there is nothing to window` |
| действие `det scan` с `before` = `after` = 0 (пустое окно) | `a scan window needs before or after` |
| цель `from_event` при `start` не `event` | `from_event needs an event: this scenario starts without one` |
| шаг без предмета: `sub` `ntf`, `net`, `client`, `alarm` | `<action> has nothing to act on here` |
| действие `rec record` с `duration: event`: конца события в журнале нет | `duration event needs the end of an event: the journal has none` |
| `escalate` со `stop: reset`, среди триггеров нет `io.input` | `a reset needs io.input among the triggers` |
| `cam output`, `state` нет или `pulse`, `pulse_ms` нет или 0: держатель откажет (V/01.4 Н1.1) | `pulse needs pulse_ms` |
| триггер с `target: null` или `from_event: true` | `trigger <i> is not complete` |
| шаг не по схеме (ветка, её форма дверь не судит), шаг без обязательного ключа, `target` `null`, `auto runrule` без `rule`; `ask`, `escalate` с `role: null`; `sec` вне 1…3600, `levels` пусты или больше 5, `wait_min` вне 1…120, у последнего уровня вне 0…120; событие `wait_event` с `target: null` или `from_event: true`; условие без своего поля (V/07.1) | `step <path> is not complete`, `condition <i> is not complete` |

Границы `sec`, уровней и `wait_min` держат срок шага внутри `delete_after` строки `answers`. Полнота шага с `target` — ключи V/07.1 Н1.3 без `unit`, `cam`; у `output` и `port` не обязателен: номер — ребёнка (глава 4 Н1.9).

Правка строки — проверка заново (строка целиком, какой она станет).

### Н1.2 Соответствие камерам и детекторам

Каждый проход вычислитель сверяет сценарий с тем, что сказали устройства (`can` в пульсе держателя — `{events, rays, relays,
ptz, presets}`, `rays` и `relays` — списки номеров детей этой камеры по возрастанию; `can` нет — `rays`, `relays`, `presets` не сказаны, `unchecked`; строка устройства `cam/devices/<хост>` даёт только `events`, строка без `events` (бывает `{device, videos}`) их не говорит; V/01.4 Н1.4) и какие единицы есть.
Пульс держателя — свежий по `LOST_AFTER`, чей `status[]` несёт камеру; из двух — с большей `epoch` элемента; свежего нет — `can`
нет. **Камера есть** — живая строка `cam/cameras/<cam>` с пустым `main`; строка потока, надгробие, `ref:…` — `there is no camera
<cam>` (запись чужой камеры заводит оператор, V/02.9 Н1.1):

| Что в сценарии | Сверка | Слова отказа |
|---|---|---|
| триггер `cam`, `kind` | камера есть; её устройство поднимает `kind` (`events`) | `camera <cam> does not raise '<kind>' — it raises <…>`, `there is no camera <cam>` |
| триггер `cam` без `unit` (широкий) | все камеры кластера сказаны, и ни одна не поднимает `kind` — не годится; есть несказанные — `unchecked`; `match.port` широкого триггера не сверяется (вход показывает само событие) | `no camera raises '<kind>'` |
| триггер `cam` с `unit`, `kind` = `io.input`, `match.port` | `p` входит в `rays`: номера сквозные по устройству и могут идти не с 1 (V/01.4 Н1.1); `p` не целое или `rays` пуст — то же слово | `camera <cam> has no input <p>: it has <…>` |
| триггер `auto` (`sub: auto`) | не годится: события `auto` — не триггеры (глава 2 Н1.2) | `events of auto are not triggers` |
| триггер `det` | детектор с таким `unit` есть; у модели реестра вид события — `kind` строки детектора (V/04.2 Н1.2), `kind` триггера другой — не годится, правило молчало бы; прочей модели каталога видов нет, вид — в `unchecked` (`detector <unit>: the kinds its model raises are not said`); широкий `det` — без сверки | `there is no detector <unit> — a detector is named by its unit: <cam>-<kind>`, `detector <unit> raises '<вид>', not '<kind>'` |
| действия `cam output`, `cam preset` | камера есть | `there is no camera <cam>` |
| действие `cam unit` | строка `cam/device_units/<unit>-<n>` есть, её `type` не `det`; `operation` сверяет держатель (V/01.4 Н1.4б); таблица не прочитана — `unchecked` | `there is no unit <unit>-<n>` |
| действие `det detect`, `kind: linecross` | `params` шага, нет его — основы (V/07.4 Н1.2) — объект с ключом `zone`, `{shape: line}`: заявка заменяет основу целиком, а без линии заказ — `failed` (V/04.2); строка основы не читается — `unchecked` | `detect linecross on <cam>: no line in params.zone` |
| условие `time`, `mode` | расписание, режим есть: иначе условие молча ложно; таблица не прочитана — `unchecked` | `condition <i>: there is no schedule <id>`, `there is no mode <id>` |
| действие `cam output` | `port` входит в `relays` | `camera <cam> has no output <p>: it has <…>` |
| действие `cam output`, выход есть | выход не выключен по правилу V/01.4 Н1.4а: настройка строки `<cam>-relay-<port>` и строк с теми же `device`, `type`, `number`, в том числе `gone`; строка не читается — `unchecked`, отказ даст держатель | `camera <cam> output <p> is disabled` |
| действие `cam preset` | `1 ≤ n ≤ presets` | `camera <cam> has <n> preset(s), not <p>` |
| действия `rec record`, `det detect`, `det scan` | камера есть; её `type` — `camera` (V/01.1 Н1.1б) | `there is no camera <cam>`, `camera <cam> has no stream` |
| действия `cam arm`, `cam disarm`, `cam disable` | камера есть | `there is no camera <cam>` |
| действие `det scan` | у камеры есть запись (`rec/recordings/*` с этой `cam`; при `rec` — эта запись этой камеры); запись — строка без надгробия, выключенная и заказанная тоже; нечитаемая не выбирается: записи нет, а нечитаемая строка есть — `unchecked`, отказ даст шаг (глава 4 Н1.3) | `nothing records camera <cam>: a scan reads the archive`; при `rec` — `there is no recording <rec> of camera <cam>` |

Перечень `<…>` — по возрастанию через `, `, пустой — `none`.

- **Не годится** — фаза `refused`, поле `unfit` — список слов, `reason` — эти слова через `; `; порядок — `when`, затем `then`,
  повтор слов — один; сценарий не срабатывает, пока не подойдёт (проверка — каждый
  проход: камеру переставили на устройство с выходами — сценарий оживает).
- **Неизвестно — не «не умеет»:** виды событий не сказаны (`can` нет и строка устройства их не говорит), входы, выходы, пресеты не сказаны (`can` нет), событие подсистемы, которой
  вычислитель не проверяет (кроме `cam` и `det`; `auto` — не годится, таблица выше), — сценарий работает, поле
  `unchecked` перечисляет непроверенное: `camera <cam> has not said what it raises: '<kind>' is not checked`, `camera <cam> has
  not said what it can do: cam <action> is not checked`, `camera <cam> has not said its inputs: port <p> is not checked`, `<sub> does not describe what its units raise: '<kind>' is not checked`.
  Подсистема вне объявленных эпох (глава 2 Н1.2): сценарий работает, не срабатывает, в `unchecked` — `<sub>: its epochs are not
  declared, its events fire nothing`. `can` в пульсе держателя есть, но не читается (не по форме V/01.4 Н1.4) — не
  прочитан, а не отсутствует и не «не умеет»: то же — сценарий работает, `unchecked` (не `unfit`).
- Держатель при исполнении проверяет то же сам (V/01.4 Н4): вычислитель не обещает, что команда выполнится.
- **Цель `target`** из одного устройства сверяется как `unit`, `cam` той же строки: ключ ребёнка — по его камере и номеру (`output` — номер в `relays`, `io.input` — в `rays`), камера у `output` — с `port` шага. У триггера `det` элемент `device` — камера: камера есть, и у неё есть детектор `<cam>-<kind>` или встроенный этого вида (V/01.1 Н1.2б), иначе то же слово `there is no detector <cam>-<kind>…`: правило молчало бы. У триггера и события `wait_event` папка, которой нет в таблице папок, снятая тоже: живых областей в цели не осталось — не годится, `there is no folder <id>`, правило молчало бы; иначе `unchecked` с тем же словом, правило со смешанной целью не гаснет (решение «Архитектора» 2026-11-02). Таблица не читается — `unchecked`. Папка шага `then`, сервер, домен, несколько устройств и `from_event` не сверяются: состав известен при запуске, не подошедшее устройство — отказ шага, а не сценария (глава 4 Н1.9); `gone` и область, которой нет, — то же. Шаг в ветке сверяется, как шаг верхнего уровня, событие `wait_event` — как триггер. `auto runrule` здесь не сверяется: цель цепочки может уйти после записи, остальные шаги идут, шаг судит глава 4 Н1.13.

### Н1.3 Нечитаемое — беда одного

Строка сценария не читается своим типом, значение `when` или `then` не по схеме: ни разу не прочитанная — фаза платформы
`unreadable`; запущенная идёт с последней прочитанной, `why` (P/03.3 Н3 шаг 2, P/03.4 Н1.1); прочие сценарии идут. Строка
камеры, устройства, детектора или записи не читается — эта единица непроверена: в `unchecked` — `<единица>: its row cannot be
read, it is not checked`, `<единица>` — `camera <id>`, `detector <id>`, `recording <id>`, настройка выхода — `camera <cam> output
<p>`, `schedule <id>`, `modes`, `window <id>`, `folder <id>`; сценарий работает, проверка на такой строке — `cond.unread` (глава 4 Н1.8). Пояс вне базы у сценария `schedule` — `timezone <имя> is not known: run_at is not checked`. Хранилище не ответило — всё читаемое из него непроверено: `unchecked`, не `unfit`.

## Н3 Проход

```
для сценария (каждый проход): два поля → refused | сверка Н1.2 → unfit → refused; неизвестное → unchecked; иначе годен
годен → сработки (глава 2) → действия (глава 4)
```

**Гонки.** Камеру переставили между проходами — сценарий проверяется по прочитанному в этом проходе; держатель отказывает
при исполнении, если устройство уже другое (V/01.4).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| два триггера без окна, окно у одного, нет триггера, `run_at`, действия | `refused`, `reason` | пульс, страница | поправить сценарий |
| камера не умеет (событие, вход, выход, пресет), строка без кадров, выход выключен, детектора нет, запись не ведётся | `refused`, `unfit` | пульс, страница | поправить сценарий или камеру |
| устройство не сказано | работает, `unchecked` | пульс | — |
| `can` в пульсе держателя не читается | работает, `unchecked` (не `unfit`) | пульс | — |
| строка единицы, таблицы главы 6, папки нечитаема | работает, `unchecked` | пульс | — |
