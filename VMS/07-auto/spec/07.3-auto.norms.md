# V/07.3 — Соответствие и отказы: нормы

Канон главы 3 урока V/07 «Сценарии» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../07-auto.md),
[инструкция](07-auto.README.md), манифест [`auto.subsystem.yaml`](../auto.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `d3f8e05`.

Форму сценария проверила дверь (глава 1); смысл — вычислитель: поднимает ли камера такое событие, есть ли у неё такой
выход и пресет, есть ли такой детектор, пишет ли кто-нибудь камеру, которую сценарий хочет сканировать. Глава нормирует
отказ двух полей, проверку против того, что сказали устройства, «не знаю» против «не умеет» и тексты отказов.

Id норм — `V/07.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — строки камер `cam/cameras/*`,
пульсы держателей `cam/heartbeats/*` (`can` камеры, V/01.4 Н1.4), строки устройств `cam/devices/*`, строки детекторов
`det/units/*`, строки записей `rec/recordings/*` (`worker.reads`; у `auto` нет `about`, чужие строки — по объявлению,
[P/02.5 Н1.4](../../../Platform/02-installer/spec/02.5-installer.norms.md)).

### Н1.1 Отказ двух полей

Смысл, который форма одного поля не выражает, — отказ вычислителя: два триггера и больше при `within` = 0 — «two triggers
need `within`: the window they must fall into»; один триггер при `within` > 0 — «`within` is the window between triggers; with
one trigger there is nothing to window»; действие `det scan` с `before` = `after` = 0 — «a scan window needs before or after»
(пустое окно; связь двух полей — правило вычислителя, как V/05 находка 2). Сценарий — фаза `refused`, `reason` — эти слова; он не срабатывает. Правка строки —
проверка заново (строка целиком, какой она станет).

### Н1.2 Соответствие камерам и детекторам

Каждый проход вычислитель сверяет сценарий с тем, что сказали устройства (`can` в пульсе держателя — `{events, rays, relays,
ptz, presets}`; строка устройства `cam/devices/<хост>` — его `events`; V/01.4 Н1.4) и какие единицы есть:

| Что в сценарии | Сверка | Слова отказа |
|---|---|---|
| триггер `cam`, `kind` | камера есть; её устройство поднимает `kind` (`events`) | `camera <cam> does not raise '<kind>' — it raises <…>`, `there is no camera <cam>` |
| триггер `cam` без `unit` (широкий) | все камеры кластера сказаны, и ни одна не поднимает `kind` — не годится; есть несказанные — `unchecked`; `match.port` широкого триггера не сверяется (вход показывает само событие) | `no camera raises '<kind>'` |
| триггер `cam`, `match.port` | `1 ≤ p ≤ rays` (нумерация входов, выходов и пресетов — с 1, V/01.4 Н1.1) | `camera <cam> has <n> input(s), not port <p>` |
| триггер `det` | детектор с таким `unit` есть; вид события с `kind` модели не сравнивается — модель отдаёт свой вид (V/04.2 Н1.2: `lpr` → `plate`); пока каталога видов событий модели нет, вид — в `unchecked` (`detector <unit>: the kinds its model raises are not said`); широкий `det` — без сверки | `there is no detector <unit> — a detector is named by its unit: <cam>-<kind>` |
| действие `cam output` | `1 ≤ port ≤ relays` | `camera <cam> has <n> relay(s), not port <p>` |
| действие `cam preset` | `1 ≤ n ≤ presets` | `camera <cam> has <n> preset(s), not <p>` |
| действия `rec record`, `det detect`, `det scan` | камера есть | `there is no camera <cam>` |
| действие `det scan` | у камеры есть запись (`rec/recordings/*` с этой `cam`; при `rec` — эта запись этой камеры) | `nothing records camera <cam>: a scan reads the archive` |

- **Не годится** — фаза `refused`, поле `unfit` — список слов; сценарий не срабатывает, пока не подойдёт (проверка — каждый
  проход: камеру переставили на устройство с выходами — сценарий оживает).
- **Неизвестно — не «не умеет»:** устройство не сказано (`can` нет, строки устройства нет), событие подсистемы, которой
  вычислитель не проверяет (кроме `cam` и `det`), — сценарий работает, поле `unchecked` перечисляет непроверенное. `can`
  в пульсе держателя есть, но не читается (не по форме V/01.4 Н1.4) — не прочитан, а не отсутствует и не «не умеет»: то же —
  сценарий работает, `unchecked` (не `unfit`).
- Держатель при исполнении проверяет то же сам (V/01.4 Н4): вычислитель не обещает, что команда выполнится.

### Н1.3 Нечитаемое — беда одного

Строка сценария не читается своим типом — фаза платформы `unreadable` (P/03.3, P/03.4 Н1.1), прочие сценарии идут. Строка
камеры, устройства или детектора не читается — эта единица непроверена: в `unchecked` — `<единица>: its row cannot be read,
it is not checked`; сценарий работает.

## Н3 Проход

```
для сценария (каждый проход): два поля → refused | сверка Н1.2 → unfit → refused; неизвестное → unchecked; иначе годен
годен → сработки (глава 2) → действия (глава 4)
```

**Гонки.** Камеру переставили между проходами — сценарий проверяется по прочитанному в этом проходе; держатель отказывает
при исполнении, если устройство уже другое (V/01.4).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| два триггера без окна, окно у одного | `refused`, `reason` | пульс, страница | поправить сценарий |
| камера не умеет (событие, вход, выход, пресет), детектора нет, запись не ведётся | `refused`, `unfit` | пульс, страница | поправить сценарий или камеру |
| устройство не сказано | работает, `unchecked` | пульс | — |
| `can` в пульсе держателя не читается | работает, `unchecked` (не `unfit`) | пульс | — |
| строка единицы нечитаема | работает, `unchecked` | пульс | — |
