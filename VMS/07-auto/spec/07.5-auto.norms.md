# V/07.5 — Сценарии между камерами: нормы

Канон главы 5 урока V/07 «Сценарии» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../07-auto.md),
[инструкция](07-auto.README.md), манифест [`auto.subsystem.yaml`](../auto.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `d3f8e05`.

«Машина у камеры ворот — камеру двора на пресет 3», когда камеры в разных членах домена. Такой сценарий — не единица
кластера: домен держит его целиком в общих настройках, исполняет вычислитель кластера камеры-триггера, а действие уходит
просьбой на приёмник, у которого камера-цель держит опрос. Глава нормирует документ, исполнителя, книгу `asks`, просьбу и
её исходы, перенос через ретранслятор. Форма камеры (токен `ask`, исполнение просьбы) — [V/01.6](../../01-cam/spec/01.6-cam.norms.md)
Н1.3, Н1.4; приёмник — [V/02.9](../../02-rec/spec/02.9-rec.norms.md).

Id норм — `V/07.5-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `valid_for` — секунды; срок просьбы — от момента события на часах камеры-триггера, приёмник переводит его на свои.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — копию общих настроек
`domain/shared` ([P/09.1 Н1.10](../../../Platform/09-agent/spec/09.1-agent.norms.md)), копию книги `domain/auto/asks`, копию
топологии `domain/member-topology`, пульсы регистраторов `rec/heartbeats/*` (адреса приёмников); пишет — вклад книги
`auto/asks/<слот>` ([P/03.7 Н1.2](../../../Platform/03-worker/spec/03.7-worker.norms.md)), события `fired`, пульс.

### Н1.1 Документ сценариев

`domain.shared: [{name: scenarios, type: json, schema}]` — значение `settings.shared.auto.scenarios` общих настроек домена
([P/06.7 Н1.14](../../../Platform/06-console/spec/06.7-console.norms.md), [P/08.9](../../../Platform/08-domain/spec/08.9-domain.norms.md)
Н1.2–Н1.3: подпись, правка `PUT /domain/shared {base_rev, shared}`, проверка схемы). Массив не больше 1000 сценариев:

| Поле | Форма | Смысл |
|---|---|---|
| `name` | строка, обязательно, уникально в массиве | имя сценария |
| `when` | `{camera, kind}`, обязательно | камера-триггер (`ref` камеры в домене) и вид события |
| `then` | `oneOf`: `{camera, action: preset, n, valid_for?}` или `{camera, action: output, port, valid_for?}`, ключ другой ветви запрещён | камера-цель (`ref`), `n`, `port` — целое ≥ 1 (нумерация V/01.4 Н1.1, как у сценария кластера), срок годности просьбы `valid_for` — целое 10…600 (умолчание 30; нижняя граница — как V/07.1) |
| `rate_per_minute` | целое 0…600 | потолок сработок; 0 — умолчание 6 |
| `enabled` | bool | выключенный не исполняется |

Между камерами — только `preset` и `output`: запись, детектор и скан — строки кластера, не просьба через домен. Срок просьбы —
`valid_for`, тем же именем, что у сценария кластера (V/07.1). Форма ловится у двери домена; смысл (что умеет цель) — отказ
исполнителя и цели.

### Н1.2 Исполнитель

Сценарий документа исполняет **вычислитель кластера камеры-триггера**: тот, у кого камера с `ref` = `when.camera` есть в
`cam/cameras/*` (камера-кластер — сама себе кластер, её вычислитель — в её процессе, P/02.4 Н1.10). Исполнение — как у
сценария кластера с одним триггером `{sub: cam, kind: when.kind, unit: <id камеры>}` (глава 2): журнал, сработка, курсор
(курсор документа — в памяти вычислителя; после перезапуска — с «сейчас»), потолок `rate_per_minute`, событие `fired`.
Сценарий без имени или с повтором имени — не исполняется, отказ в пульсе (поле `shared`, Н1.6). Исполняют только
сценарии своих камер-триггеров; первый по имени слота живой вычислитель кластера (услышанный за 30 с) — один на кластер.

### Н1.3 Книга `asks`

`domain.books.asks: {from: auto/asks/, key: target, pick: all, to: to}` (P/08.5): **дороги к цели** — у каких приёмников камера-
цель держит опрос. Вклад `auto/asks/<слот>` пишет первый живой вычислитель кластера (Н1.2) каждого узла пути — дома опроса
камеры-цели (её кластер записи или дом опроса, P/08.7 Н1.1), центра, ретранслятора триггера:

```yaml
target:   ref камеры-цели (ключ книги)
by:       [ref камер-триггеров документа с этой целью]
acts:     [действия документа к этой цели]
urls:     [ingest регистраторов своего кластера, услышанных за 30 с, по имени слота]
up?:      true — дорога в свой ретранслятор для подъёма к центру (цель за чужим ретранслятором)
to:       дом и центр — все члены; ретранслятор — члены за ним (via)
```

Элемент — только для целей, у которых в документе есть хоть один включённый сценарий: нет сценария — нет дороги.

### Н1.4 Просьба на приёмник цели

На сработку исполнитель:

1. просит токен `ask` через местную дверь агента (`ref` — цель, `by` — триггер; P/03.7 Н1.5; объём `scenario` — P/08.7 Н3: токен
   выдаётся, только если такой сценарий есть в документе, его `acts` — действия сценария); отказ выдачи — сработка без
   действия, `reason` в пульсе;
2. берёт дорогу к цели из копии книги `asks` (приёмники по порядку, первый ответивший);
3. подаёт обращение «просьба» (V/02.9 Н2) — токен, действие (`action`, `n` | `port`), `firing` — ключ сработки (`f` V/07.4
   Н1.1: первые 32 hex `sha256(UTF-8(<сценарий> + "\n" + <id события>))`), срок `occurred + valid_for` и своё «сейчас»
   (приёмник переводит срок на свои часы);
4. ждёт исход до срока + 5 с: `performed`, `refused: <почему>` (цель не умеет), `expired` (срок прошёл), `unknown` (приёмник
   потерял — перезапуск); исход — в событии `fired`.

**Сторона приёмника** (дополнение V/02.9 Н2 «просьба»): проверяет токен вида `ask` (`ref` — цель обращения, действие ∈ `acts`),
кладёт просьбу в ответ опроса цели (будит удержанный опрос); просьба с тем же (`by`, цель, действие, `firing`) — живая или с
исходом в памяти `REMEMBER` — тот же номер и тот же исход; разные `firing` — разные просьбы; не
больше `MAX_LIVE_ASKS` = 16 живых просьб на камеру; исходы помнит `REMEMBER` = 15 мин, не больше `OUTCOMES_KEPT` = 64 на
просящего; срок — конечный, позже «сейчас» и не дальше `ASK_DEADLINE_MAX` = 600 с, иначе отказ; истёкшие выметает любое
обращение. Цель исполняет просьбу как просьбу `cam` (V/01.6 Н1.4, V/01.4) и отвечает исходом следующим опросом; толкатель называет
строку `rec.ask-<firing>-<i>` (V/02.9 Н1.2; у сценария документа одно действие, `i` = 0): повтор через другой приёмник или
после перезапуска приёмника доходит до держателя тем же `rid` — `again` или `refused` по `digest`, второго исполнения нет.

### Н1.5 Через ретранслятор

Цель за своим ретранслятором — прямая дорога (книга ретранслятора). Цель за чужим — одна дорога в свой ретранслятор с `up`:
его передатчик (V/02.9 Н1.8) видит просьбу на своём приёмнике, просит свой токен `ask` к центру (`up` — центр; те же `by`,
`acts`; P/08.7 Н3 `up_claim`), несёт её центру с тем же `firing` и ждёт исхода у центра; исход идёт назад тем же путём. На каждом переходе —
свой срок, ничего не хранится; повтор после обрыва — через `period × U(0,5; 1,5)`, `period` = 2 с.

### Н1.6 Пульс

Поле `shared` вычислителя — `{<имя сценария документа>: {phase: running | refused, reason?, since, asked, outcomes: {<исход>: n}}}`
(`since` — момент, с которого исполнитель смотрит журнал) для
сценариев своих камер-триггеров; книги — `asks_published` (элементов вклада). События `fired` — с исходом просьбы.

## Н3 Проход

```
документ из копии domain/shared → сценарии своих камер-триггеров (первый вычислитель кластера)
сработка (глава 2, один триггер) → токен ask → дорога из книги asks → «просьба» на приёмник → исход → fired
вклад книги asks (первый вычислитель узла пути): цели документа → {target, by, acts, urls, up?, to}
```

**Гонки.** Документ сменился посреди просьбы — уже выданный токен действует до срока (P/03.7 Н1.5), новый не выдаётся, если
сценарий убран. Два вычислителя кластера сочли себя первыми — оба исполняют и издают: просьбы одной сработки несут один `firing` —
тот же номер у приёмника и тот же `rid` у держателя; вклады одного члена — `pick: all`, элементы одинаковы. Отставший
исполнитель подал сработку позже `REMEMBER` (15 мин) — приёмник выдаёт новый номер, но строка у держателя та же
(`rec.ask-<firing>-<i>`): `again`. Двойное исполнение остаётся, только если и строка держателя уже снята — принятый предел.
События между остановкой и стартом исполнителя документа и при смене первого вычислителя кластера не исполняются: курсор
документа — в памяти; поле `since` элемента `shared` (Н1.6) — момент, с которого исполнитель смотрит.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| сценарий без имени, повтор имени | не исполняется | пульс `shared` | поправить документ |
| токен не выдан (сценария нет, дома нет) | сработка без действия | пульс | — |
| дороги нет в книге | сработка без действия, `reason` | пульс | — |
| цель не умеет | `refused: <почему>` | событие `fired` | поправить документ |
| срок прошёл | `expired` | `fired` | шире `valid_for` |
| приёмник потерял просьбу | `unknown` через срок + 5 с | `fired` | — |
| больше 16 живых просьб на камеру | отказ приёмника | исход | — |

## Соответствие прежним урокам

Из М12A/12 — документ `auto.scenarios` в общих настройках, исполнитель, книга `asks`, просьба со сроком не сохраняется; из
М12B/03 шаг 8 — книга `asks`, токен `ask`, исходы, проверка смысла только проходом, между камерами только `preset` и `output`,
пределы приёмника; из М12B/04 шаг 7 — сценарий между ретрансляторами, подъём, ожидание исхода, повтор с разбросом. Отличия
от свидетеля: исполнитель — вычислитель кластера триггера, книгу издаёт вычислитель узла пути (ADR-0074 форма C6; у
свидетеля — ответвление воркера VMS у держателя); срок просьбы — `valid_for` (у свидетеля — `then.within`); `arg` → `n` | `port`;
`action` — перечнем. Id ([id-map](../../common/id-map.tsv)): М12A/12 → V/07.5-01, V/07.5-02; М12B/03 ш.8 → V/07.5-03, V/07.5-04;
М12B/04 ш.7 → V/07.5-05.
