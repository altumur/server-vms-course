# V/07.5 — Сценарии между камерами: нормы

Канон главы 5 урока V/07 «Сценарии» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../07-auto.md),
[инструкция](07-auto.README.md), манифест [`auto.subsystem.yaml`](../auto.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `d4fe1bf3`.

«Машина у камеры ворот — камеру двора на пресет 3», когда камеры в разных членах домена. Такой сценарий — не единица
кластера: домен держит его целиком в общих настройках, исполняет вычислитель кластера камеры-триггера, а действие уходит
просьбой на приёмник, у которого камера-цель держит опрос. Глава нормирует документ, исполнителя, книгу `asks`, просьбу и
её исходы, перенос через ретранслятор. Форма камеры (токен `ask`, исполнение просьбы) — [V/01.6](../../01-cam/spec/01.6-cam.norms.md)
Н1.3, Н1.4; приёмник — [V/02.9](../../02-rec/spec/02.9-rec.norms.md).

Id норм — `V/07.5-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `valid_for` — секунды; срок просьбы — от `occurred` события, «сейчас» обращения — часы вычислителя, их расхождение с
часами писателя события — принятый предел; приёмник переводит срок на свои часы.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — копию общих настроек
`domain/shared` ([P/09.1 Н1.10](../../../Platform/09-agent/spec/09.1-agent.norms.md)), разделы книги `domain/auto/asks/*/<раздел>` по своей просьбе (Н1.3), копию
топологии `domain/member-topology`, строки `domain/member-list/<раздел>` (`Entry.ca` кластера приёмника, Н1.4, V/02.9 Н2; чужого раздела нет — клиент peer просит его сам),
копию книги `domain/cam/sources` (дом опроса цели без назначения, Н1.3), назначения `domain/placed/rec/<ref>` (кластер записи
камеры-цели — её дом, Н1.3; P/08.6), пульсы регистраторов `rec/heartbeats/*` (адреса приёмников); пишет — вклад книги
`auto/asks/<слот>` ([P/03.7 Н1.2](../../../Platform/03-worker/spec/03.7-worker.norms.md)), пульс.

**Книги, топология и документ у кластера — держателя домена.** У кластера, который держит домен (запись `domain/holder` своего хранилища, основа роли P/02.5 Н1.4; не прошла `record` — признак не поднят, читаются копии), копий нет (P/09.1 Н1.4 `member_row`): книга читается из строки своего кластера `domain/<sub>/<книга>/<CLUSTER>`
([P/08.5](../../../Platform/08-domain/spec/08.5-domain.norms.md) Н1.3), топология — из строки `domain/topology`
([P/08.3](../../../Platform/08-domain/spec/08.3-domain.norms.md) Н1.2), документ — из объекта по полю `object` строки
`domain/shared`; у члена — объект `domain/shared` (P/06.7 Н1.14). Сумма `sha256` строки и подпись сверяются; не сошлось — прежний
документ. Так — во всех правилах главы, где сказано «копия».

### Н1.1 Документ сценариев

`domain.shared: [{name: scenarios, type: json, schema}]` — значение `settings.shared.auto.scenarios` общих настроек домена
([P/06.7 Н1.14](../../../Platform/06-console/spec/06.7-console.norms.md), [P/08.9](../../../Platform/08-domain/spec/08.9-domain.norms.md)
Н1.2–Н1.3: подпись, правка `PUT /domain/shared {base_rev?, shared}` с `If-Match`, проверка схемы). Массив не больше 1000 сценариев:

| Поле | Форма | Смысл |
|---|---|---|
| `name` | строка, обязательно, уникально в массиве | имя сценария |
| `when` | `{camera, kind, member?}`, обязательно | камера-триггер (`ref` камеры в домене), вид события и `member` — член, чья это камера: `ref` уникален только в кластере (V/01.6 Н1.2). Токен такому сценарию выдаётся только этому члену (P/08.7 Н3 `scenario`); нет поля — член не закреплён, сценарий достаётся единственному владельцу `ref` |
| `then` | `oneOf`: `{camera, member?, action: preset, n, valid_for?}` или `{camera, member?, action: output, port, valid_for?}`, ключ другой ветви запрещён | камера-цель (`ref`), `member` — член, чья это камера: `ref` уникален только в кластере (ADR-0112 доп. (10) п. 2); нет поля — единственный владелец `ref`; `n`, `port` — целое ≥ 1 (нумерация V/01.4 Н1.1, как у сценария кластера), срок годности просьбы `valid_for` — целое 10…600 (умолчание 30; нижняя граница — как V/07.1) |
| `rate_per_minute` | целое 0…600 | потолок сработок; 0 или нет поля — умолчание 6 |
| `enabled` | bool | выключенный не исполняется; нет поля — включён |

Между камерами — только `preset` и `output`: запись, детектор и скан — строки кластера, не просьба через домен. Срок просьбы —
`valid_for`, тем же именем, что у сценария кластера (V/07.1). Форма ловится у двери домена; смысл (что умеет цель) — отказ
цели; сверки главы 3 над документом нет, отказ исполнителя — Н1.2.

### Н1.2 Исполнитель

Сценарий документа исполняет **вычислитель кластера камеры-триггера**: тот, у кого камера с `ref` = `when.camera` есть в
`cam/cameras/*`, а `when.member`, если задан, называет этот кластер (камера-кластер — сама себе кластер, её вычислитель — в её процессе, P/02.4 Н1.10). Исполнение — как у
сценария кластера с одним триггером `{sub: cam, kind: when.kind, unit: <id камеры>}` (глава 2): журнал, сработка, курсор
(курсор документа — в памяти вычислителя; после перезапуска — с «сейчас»), `PER_PASS`, `COLD_START`, потолок
`rate_per_minute`; исход — в пульсе (Н1.6). Новый сценарий смотрит с момента, как увиден; правка курсора не сбрасывает; `reason`
снимает проход. Сценарий без имени или с повтором имени — не исполняется, отказ в пульсе (поле `shared`, Н1.6). Исполняют только
сценарии своих камер-триггеров; первый по имени слота живой вычислитель кластера (услышанный за 30 с по пульсу
`auto/heartbeats/*`, договор наблюдения `fresh`) — один на кластер.

### Н1.3 Книга `asks`

`domain.books.asks: {from: auto/asks/, key: target, pick: all, to: "*"}` (P/08.5): **дороги к цели** — у каких приёмников камера-
цель держит опрос. Вклад `auto/asks/<слот>` пишет первый живой вычислитель кластера (Н1.2) каждого узла пути — дома опроса
камеры-цели (её кластер записи или дом опроса, P/08.7 Н1.1), центра, ретранслятора триггера; не первый — вклад пуст. Узел
решает так: назначение цели есть — её дом `cluster` (в `star` — центр); нет — центр издаёт все цели документа, прочие берут дом
опроса по книге `domain/cam/sources`; цели в этой книге нет — ретранслятор (свой кластер в `relays` топологии) издаёт дорогу вверх для триггеров документа, чью дорогу брать, решает `aud` токена (Н1.4):

```yaml
target:   ref камеры-цели (ключ книги)
by:       [ref камер-триггеров документа с этой целью]
acts:     [действия документа к этой цели]
urls:     [ingest регистраторов своего кластера, услышанных за 30 с, по имени слота]
up?:      true — дорога в свой ретранслятор для подъёма к центру (цель за чужим ретранслятором)
```

Элемент — только для целей, у которых в документе есть хоть один включённый сценарий: нет сценария — нет дороги. `then.member` называет дом цели: узел судит назначение и книгу источников камеры этого члена. **Предел:** ключ книги — `ref`, цели с одним `ref` у двух членов делят элемент, а токен называет только `ref` (P/08.7 Н3).
`ingest` пульса регистратора не по форме семьи `rec-heartbeat-words` (V/02) — не прочитан, а не «приёмника нет»: на этом
проходе регистратор в `urls` не входит, прочие входят; читаемых нет — вклад держит `urls`, опубликованные последними: своя
строка вклада; её нет — элемента нет. Документ, топология не читаются — вклад не меняется.

Книга объявлена всем: `domain.books.asks.to: "*"`, поле `to` вклада не читается (P/08.5 Н1.3 `to_all`), отбор — `aud` токена (Н1.4). Разделы — `domain/auto/asks/*/<раздел>`, раздел — 12 бит SHA-256 ключа, ключ один у держателя и у копии. Без просьбы книга до члена не доходит: вычислитель на любом кластере, у держателя тоже, и при своём старте кладёт `domain/book-want/auto/asks/<раздел>` на цели правил своего кластера и обновляет `at` раз в `BOOK_WANT_EVERY` = 86400 с, пока правила цель называют; строки просьбы он не читает, поэтому при старте и при смене первого вычислителя кладёт все; сам ничего не удаляет, просьбу без обновления снимает агент через `BOOK_WANT_TTL` = 259200 с, копии без просьбы — он же, на смене срока вычислитель ничего не делает (P/09.1 Н1.4 `book_want`); раздел не пришёл — дороги нет, сработка кончается как без дороги.

**Предел:** строка раздела не больше 524288 байт (P/08.5): при элементе около 1 КиБ, оценка, — около 500 дорог на раздел; сверх — прежняя строка, журнал `domain.books.too_large` у держателя, новые дороги раздела не приходят. Копия на камере растёт с её правилами, а не с доменом (ADR-0113 доп. (11) п. 1). Новая просьба даёт дорогу не сразу: до периода отчёта члена и круга разделов, поэтому первое правило на новую цель может промолчать столько же (ADR-0113 доп. (13) п. 9).

### Н1.4 Просьба на приёмник цели

На сработку исполнитель:

1. берёт токен `ask`, новый или действующий, через местную дверь агента `POST /tokens/cam/ask` (`ref` — цель, `by` — триггер; P/03.7 Н1.5; объём `scenario` — P/08.7 Н3: токен
   выдаётся, только если такой сценарий есть в документе, его `acts` — действия сценария); отказ выдачи — сработка без
   действия, `reason` в пульсе;
2. берёт дорогу к цели из копии раздела книги `asks`: элементы с триггером в `by`, вкладчиком в `aud` токена и тем
   же `up`, в порядке копии; приёмники `urls` по порядку, первый ответивший;
3. подаёт обращение «просьба» (V/02.9 Н2) — токен, действие (`action`, `n` | `port`), `firing` — ключ сработки (`f` V/07.4
   Н1.1: первые 32 hex `sha256(UTF-8(<сценарий> + "\n" + <id события>))`), срок `occurred + valid_for` и своё «сейчас»
   (приёмник переводит срок на свои часы);
4. ждёт исход до срока + 5 с вне прохода: просьба в памяти, исход спрашивается повтором обращения на проходе: `performed`,
   `refused: <почему>` (цель не умеет), `expired` (срок прошёл), `unknown` (приёмник потерял — перезапуск — или исход держателя);
   исход — в пульсе `shared` (Н1.6).

**Сторона приёмника** (дополнение V/02.9 Н2 «просьба»): проверяет токен вида `ask` (`ref` — цель обращения, действие ∈ `acts`:
есть объект с теми же `action`, `n` или `port`; `camera`, `valid_for` не сравниваются),
кладёт просьбу в ответ опроса цели (будит удержанный опрос; просьба у соседа — просьба здесь, ответ опроса, исход отвечается там, где подана); просьба с тем же (`by`, цель, действие, `firing`) — живая или с
исходом в памяти `REMEMBER` — тот же номер и тот же исход; разные `firing` — разные просьбы; не
больше `MAX_LIVE_ASKS` = 16 живых просьб на просящего у приёмника, сверх — исход `refused: <почему>`; исходы помнит `REMEMBER` = 15 мин, не больше `OUTCOMES_KEPT` = 64 на
просящего у цели; просящий — `by` токена; срок — конечный, позже «сейчас» и не дальше `ASK_DEADLINE_MAX` = 600 с, иначе 400 `bad body`; истёкшие выметает любое
обращение. Цель исполняет просьбу как просьбу `cam` (V/01.6 Н1.4, V/01.4) и отвечает исходом следующим опросом; толкатель называет
строку `rec.ask-<firing>-<i>` (V/02.9 Н1.2; у сценария документа одно действие, `i` = 0): повтор через другой приёмник или
после перезапуска приёмника доходит до держателя тем же `rid` — `again` или `refused` по `digest`, второго исполнения нет.

### Н1.5 Через ретранслятор

Цель за своим ретранслятором — прямая дорога (книга ретранслятора). Цель за чужим — одна дорога в свой ретранслятор с `up`:
его передатчик (V/02.9 Н1.8) видит просьбу на своём приёмнике, просит свой токен `ask` к центру (`up` — центр; те же `by`,
`acts`; P/08.7 Н3 `up_claim`), несёт её центру с тем же `firing` и ждёт исхода у центра. У центра просьба уходит в ответ опроса
передатчика дома цели (V/02.9 Н1.7), тот кладёт её на свой приёмник, цель берёт обычным опросом; исход идёт назад тем же путём,
полем `outcomes`. На каждом переходе срок — тот же момент, переведённый на часы приёмника, ничего не хранится; повтор после
обрыва — до срока, через `period × U(0,5; 1,5)`, `period` = 2 с.

### Н1.6 Пульс

Поле `shared` вычислителя — `{<имя сценария документа>: {phase: running | refused, reason?, since, asked, outcomes: {<исход>: n}, holding?, decided_without?}}`
(`since` — момент, с которого исполнитель смотрит журнал; `outcomes` — четыре исхода Н1.4) для
сценариев своих камер-триггеров; книги — `asks_published` (элементов вклада). Его читает форма (V/11.4 Н1.21).

## Н3 Проход

```
документ из копии domain/shared → сценарии своих камер-триггеров (первый вычислитель кластера)
сработка (глава 2, один триггер) → токен ask → дорога из книги asks → «просьба» на приёмник → исход → пульс shared
вклад книги asks (первый вычислитель узла пути): цели документа → {target, by, acts, urls, up?}
```

**Гонки.** Документ сменился посреди просьбы — уже выданный токен действует до срока (P/03.7 Н1.5), новый не выдаётся, если
сценарий убран. Два вычислителя кластера сочли себя первыми — оба исполняют и издают: просьбы одной сработки несут один `firing` —
тот же номер у приёмника и тот же `rid` у держателя; вклады одного члена — `pick: all`, элементы одинаковы. Отставший
исполнитель подал сработку позже `REMEMBER` (15 мин) — приёмник выдаёт новый номер, но строка у держателя та же
(`rec.ask-<firing>-<i>`): `again`. Двойное исполнение остаётся, только если и строка держателя уже снята — принятый предел. У
камеры-кластера повтор отсекает только память приёмника `REMEMBER`; после перезапуска приёмника второе исполнение возможно —
принятый предел.
События между остановкой и стартом исполнителя документа и при смене первого вычислителя кластера не исполняются: курсор
документа — в памяти; поле `since` элемента `shared` (Н1.6) — момент, с которого исполнитель смотрит.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| сценарий без имени, повтор имени | не исполняется | пульс `shared` | поправить документ |
| токен не выдан (сценария нет, дома нет) | сработка без действия | пульс | — |
| дороги нет в книге | сработка без действия, `reason` | пульс | — |
| ни один приёмник не ответил, токен отвергнут | сработка без действия, `reason`, повтора нет | пульс | — |
| `ingest` регистратора не по форме | не в `urls` на проходе; читаемых нет — прежние `urls` | пульс | исправить регистратор |
| цель не умеет | `refused: <почему>` | пульс `shared` | поправить документ |
| срок прошёл | `expired` | пульс `shared` | шире `valid_for` |
| приёмник потерял просьбу | `unknown` через срок + 5 с | пульс `shared` | — |
| больше 16 живых просьб на просящего | исход `refused: <почему>` | пульс `shared` | — |
| срок не конечный, прошёл или дальше `ASK_DEADLINE_MAX` | 400 `bad body` | просящий | — |
