# V/07.6 — Расписания, режимы, окна: нормы

Канон главы 6 урока V/07 «Сценарии» (ADR-0080; модуль VMS — ADR-0090; ADR-0105 пп. 2, 9). Лекция (`ru/07-auto.md`, для человека, в выгрузку не входит),
[инструкция](07-auto.README.md), манифест [`auto.subsystem.yaml`](../../auto.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `7a875c75`.

Текст производный от `spec/07.6-auto.norms.md`, руками не правится: источник — английский [`spec/07.6-auto.norms.md`](../../spec/07.6-auto.norms.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Условие сценария спрашивает о моменте: действует ли расписание, какой режим объекта, идёт ли окно обслуживания. Глава
нормирует таблицы `auto`, которые хранят ответы, и функцию момента: она одна и считается в вычислителе. `backend` момент не
считает.

Id норм — `V/07.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../../ru/НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../../Platform/01-store/ru/spec/01.1-store.norms.md#n0-словарь-слов).

## Н1 Форма

**Время.** `t` и поля времени строк — секунды по канону P/01.1 Н0; сутки считаются минутами 0…1440.

**Данные** (общие семьи [каталога платформы](../../../../Platform/common/data/catalog.tsv)): таблицы `auto/<т>/<имя>` (P/06.1 Н1.6) и поле
пульса `object_mode`; своих семей сверх них у главы нет. Пояс — `TIMEZONE`, Н1.7.

### Н1.1 Таблицы

Двери таблиц P/06.1 Н1.6, форма — манифест. Вычислитель читает таблицы каждый проход, в начале; между проходами значения не
держит. Строки друг на друга не ссылаются защитой: что следует за снятием строки, делает `backend` (V/11).

| Таблица | Ключ | Строка | Пишет | Читает | Нечитаема | Строки нет |
|---|---|---|---|---|---|---|
| `schedules` | `id` | расписание: `kind` (`always`, `never`, `week`, `cycle`, `dates`, `astro`), `week`, `overrides`, `valid`, `cycle`, `dates`, `astro`, `owner`, `builtin` | `backend` или консоль | вычислитель | `unknown` | `false` |
| `day_groups` | `id` | группа особых дней: `rules` | `backend` или консоль | вычислитель | `unknown` у расписания, которое её называет | группа дня не содержит |
| `modes` | `all` — одна строка | весь список: `items`, `otherwise`; версия на весь список | `backend` или консоль | вычислитель, `backend` | `unknown` | режимов нет: `object_mode` не говорится, условие `mode` ложно |
| `mode_current` | `now` — одна строка | ручное включение: `mode`, `until` (`null` — до снятия), штамп `at` | `backend` или консоль | вычислитель | `unknown` | включения нет, режим по расписаниям |
| `windows` | `id` | окно обслуживания: `schedule`, `rules` (`null` — все сценарии), `enabled` | `backend` или консоль | вычислитель | `unknown` | окна нет |

| `rule_marks` | `scenario` | что сказано о сценарии и не правит его: `mute` (`{since, until, by, reason}` или `null`, истечение строку не меняет), `order` (`int`, умолчание 0): новой `revision` нет, идущие запуски не теряются (глава 4 Н1.11) | `backend` или консоль | вычислитель, `backend` | сработка не идёт: `cond.unread` (глава 4 Н1.8) | не приглушён, `order` 0 |

Не прочитано — не отсутствует: чтение таблицы не подтверждено — это не «строки нет».

**`unknown`.** Функции момента трёхзначны: `true`, `false`, `unknown`. Строка нечитаема — проверка главы 4 Н1.8 `ok: false`, `reason`
`cond.unread`, строка в `unchecked` (глава 3 Н1.3): действие в сомнении не выполняется. Хранилище не ответило — сработка не решена (глава 4 Н4).

Имя строки — поле `title`: таблица с ключом не `name` поля `name` не объявляет (P/06.1 Н1.6). Встроенные строки `schedules` `always`, `never` с `builtin: true` заводит и бережёт `backend` (V/11). Вычислитель `builtin` не читает.

### Н1.2 Группы дней

Строка `rules` — список правил, группа содержит дату `d`, если её содержит хоть одно. `dow(d)` — 1…7 с понедельника.

| `type` | Поля | Содержит `d` |
|---|---|---|
| `range` | `from`, `to`, `yearly` | `from` пусто — нет. `to` пусто или раньше `from` — `to` = `from`. Без `yearly`: `from` ≤ `d` ≤ `to`. С `yearly` сравниваются `ММ-ДД`: при `from` ≤ `to` — внутри отрезка, иначе отрезок идёт через новый год: `d` ≥ `from` или `d` ≤ `to` |
| `ord` | `nth` (1…5 или `last`), `dow`, `month` | `month` не 0 и не месяц `d` — нет. `dow(d)` ≠ `dow` — нет. `last`: `день + 7` > длины месяца. Иначе `⌈день / 7⌉` = `nth` |

Сравнение дат — строк `ГГГГ-ММ-ДД` по знакам. `nth` бывает строкой и числом (`"2"` = `2`).

### Н1.3 Функция `in_effect`

```
wall(t, tz) → (d, m)        d — местная дата момента t в поясе tz, m — местная минута суток, секунды и дробь отброшены

iv([с, до]) → [f, e]        читаются первые два элемента; f, e — минуты суток, 24:00 = 1440; e ≤ f → e + 1440

own(S, d) → список [a, b]
  S.valid.from непусто и d < from, или S.valid.to непусто и d > to → []
  первое по порядку o из S.overrides, чья группа day_group содержит d:
    none → []; full → [[0, 1440]]; same → iv каждого из S.week[o.dow − 1] (dow нет — 1); custom → iv каждого из o.intervals
  такого нет — по S.kind:
    always → [[0, 1440]]; never → []
    week   → iv каждого из S.week[dow(d) − 1]
    cycle  → k := (d − start в сутках) по модулю length, неотрицательный; iv каждого из days[k], элемента нет — []; start пуст или length 0 — []
    dates  → iv каждого из intervals первой записи с date = d; нет — []
    astro  → Н1.4

day(S, d) → объединение отрезков:
  для каждого [a, b] из own(S, d): [a, min(b, 1440)];
  для каждого [a, b] из own(S, d − 1) с b > 1440: [0, min(b − 1440, 1440)]     # хвост через полночь

in_effect(S, t, tz) → есть [a, b] в day(S, d), a < b, a ≤ m < b; (d, m) := wall(t, tz)
```

Поля строки нет (дверь требует только `id`, `title`, `kind`) — пустая форма: `overrides`, `valid` пусты, `week`, `cycle`, `dates`, `astro` дают `[]`. `24:MM` — 1440 + `MM`, начало за полночью хвостом не сдвигается: `["24:10", "24:20"]` даёт завтра `[0, 20)`. Особый день сильнее вида: `never` с особым днём `full` действует. `valid` судит день начала интервала: хвост последнего дня срока
приходит на следующий день, хвост дня до срока не приходит. Расписание `S` не нашлось — `false`; нечитаемо — `unknown`
(Н1.1). Группа, нечитаемая у расписания, которое её называет: день, который правила раньше неё не решили, не решён. `in_effect` читает два дня, `d` и `d − 1`: интервал решённого дня покрывает момент — `true`, неизвестное «или» не изменит; иначе хоть один день не решён — `unknown`.

### Н1.4 `astro`

Одна формула для всех реализаций; `S.astro`: `window` (`day`, `night`), `offset_start_min`, `offset_end_min`, `lat`, `lon`,
`utc_offset_hours`. Вычисление — binary64, углы в градусах, `sin`, `cos`, `tan`, `asin`, `acos`, `atan` от них и в них, `fmod` — остаток со
знаком делимого, `⌊⌋` — вниз.

```
sun(d, lat, lon, off, rise) → минута суток | day | night
  N  := номер дня d в году, 1 января — 1
  lh := lon / 15
  t  := N + ((rise ? 6 : 18) − lh) / 24
  M  := 0.9856 · t − 3.289
  L  := fmod(M + 1.916 · sin(M) + 0.02 · sin(2 · M) + 282.634 + 720, 360)
  RA := fmod(atan(0.91764 · tan(L)) + 720, 360)
  RA := (RA + ⌊L / 90⌋ · 90 − ⌊RA / 90⌋ · 90) / 15
  sd := 0.39782 · sin(L);  cd := cos(asin(sd))
  ch := (cos(90.833) − sd · sin(lat)) / (cd · cos(lat))
  ch > 1 → night;  ch < −1 → day
  H  := (rise ? 360 − acos(ch) : acos(ch)) / 15
  T  := H + RA − 0.06571 · t − 6.622
  x  := fmod(fmod(T − lh + off, 24) + 48, 24)
  → ⌊x · 60 + 0.5⌋

astro(S, d) → список [a, b]
  r, s := sun(d, …, true), sun(d, …, false); r′ := sun(d + 1, …, true)
  day:   r и s — минуты → [[r + offset_start_min, s + offset_end_min]]
         иначе первое слово из r, s равно day → [[0, 1440]], иначе []
  night: s — минута → [[s + offset_start_min, 1440 + (r′ — минута ? r′ : 0) + offset_end_min]]
         s = night → [[0, 1440]], иначе []
```

`utc_offset_hours` — поле строки, а не `TIMEZONE`: минуты `sun` стоят на этом сдвиге, летнее время формула не знает. Отрезок с
`a` ≥ `b` пуст. Отрезок с отрицательным `a` хвоста на вчера не даёт.

### Н1.5 Режим объекта

```
manual(t) → строка mode_current есть, её mode есть в items, at ≤ t и (until = null или t < until)
object_mode(t, tz):
  manual(t)                    → mode строки
  первый по порядку m из items с непустым schedule, in_effect(schedule, t, tz) = true → m.id
  иначе                        → otherwise
```

`in_effect` = `unknown` у режима раньше первого `true` — `object_mode` `unknown`. Режим сменяется течением времени, строка при этом не
меняется. Вычислитель говорит режим в пульсе, поле верха, каждый проход:

```yaml
object_mode: {mode: <id>, manual: <bool>, until: <время> | null}    # object_mode(now); until — только при manual
```

`unknown` или строки `modes` нет — поля нет. Все вычислители кластера считают одно и то же. `GET /modes/current` контракта читает пульс
первого по слоту услышанного вычислителя, `POST` пишет `mode_current` (V/11). Вычислителя нет — режима сказать некому: предел.

`mode_current` не хранит истории: снятое включение для момента до снятия не читается, условие `mode` судит по нынешней строке.

### Н1.6 Окно обслуживания и приглушение

```
window_hit(w, c, t, tz) → w.enabled и (w.rules = null или c ∈ w.rules) и in_effect(w.schedule, t, tz)
muted(c, t)             → mute строки rule_marks сценария c есть и since ≤ t < until
```

Окно и приглушение — проверки главы 4 Н1.8, ручной запуск они не останавливают. `rules` несёт номера сценариев
десятичной записью или числом, сравнение — по числу.

### Н1.7 Пояс и переходы

`tz` — `TIMEZONE`, настройка кластера: строка `w2c.env`, воркер берёт её из окружения раннера ([договор файла окружения](../../../../Platform/common/ru/contracts/env-file.md)),
часть подсистемы (`W2C_SUB_ENV`) её не получает, ключа в `/etc/auto/auto.env` нет. Не задана — `UTC`. Имя вне базы поясов вычислителя —
`in_effect` и `object_mode` `unknown` на каждом проходе, строка лога при старте: консоль сверяет только форму имени; `run_at` — глава 2 Н1.6.

Смена `TIMEZONE` действует с перезапуска вычислителя (P/02.4 Н1.7). Два вычислителя с разными строками `w2c.env` разойдутся: значение одно на
кластер, это забота установки.

**Переход на летнее время.** `in_effect` судит стенную минуту, поэтому:

- при переводе вперёд минуты промежутка нет: интервал внутри него в этот день не действует, интервал через него сокращается;
- при переводе назад минуты промежутка наступают дважды: интервал внутри него действует оба раза.

Те же стенные минуты судят момент `run_at` (глава 2 Н1.6): пропущенной минуты нет, повторённая даёт два кандидата.

### Н1.8 История версий

Строка `versions` — что было после правки содержимого сценария: `scenario` (номер), `number` (счётчик версий сценария с 1), `note` (`{code,
params}` или `null`), `rule` — текст JSON `{content, was}` (V/11.3 Н1.3; `json`-поле стоит на 4000 байтах, а содержимое несёт несколько таких полей), штампы `by`, `at`.
`number` — не `revision`. Приглушение и порядок версии не пишут: они не в строке сценария. Пишет `backend` тем же пакетом, что правку (V/11). Срока
нет: снимается с правилом.

### Н1.9 Ответ оператора

Строка `answers` — ответ на `ask` и квитирование `escalate`: `scenario`, `fire` (имя сработки), `step` (путь шага: `2.no.1`), `user` (кто отвечает), `answer` (`yes`, `no`,
`ack:<уровень>`), штампы `by`, `at`. Вычислитель читает её на шаге (глава 4 Н1.11).

**Кто отвечает.** Запись — `view` на сценарий (`rights.routes.view`, `unit_of`): отвечающий не правит правило. Роль шага судит вычислитель, и это суд последний: у `by` есть роль шага (`role` у `ask`, у уровня `escalate`) по копии таблицы ролей `domain/roles` кластера, раскрытой как `roles_in` договора сторожевой: `{role, until}`, `until` 0 или позже `at`; штамп `by` ставит консоль. `user` не равен `by` или чужая роль — строка не действует, строка `step` `result: fail`, `answer.refused` (форма — глава 4 Н1.6), по одной на строку ответа, поле `answers_refused` пульса; срок идёт дальше. Копии нет, она нечитаема или таблица говорит `unreadable` — строка пока не действует, шаг ждёт следующего прохода; срок сильнее: `until` без действующей строки — `default`, `note` `answer.unread` (глава 4 Н1.6).

**Один ответ.** Человек отвечает один раз: `backend` создаёт строку `cas ""`, поэтому чужая строка места не занимает. Дверь таблиц `POST` поверх строки правит её, ответ и `at` новые, пока шаг не решён: решённый шаг записан в строке запуска и от неё уже не зависит (глава 4 Н1.11). Вычислитель перечисляет строки шага и берёт действующую с наименьшим `at`; `at` равны — наименьший `user` байтами. Ответ после срока шага не действует, запуск уже пошёл по `default`. Новая `revision` сценария снимает запуск, строка остаётся без читателя и живёт `delete_after`.

Дверь ответа контракта — `POST /rule-prompts/{promptId}/answer` (V/11.4 Н1.10). `backend` судит роль у двери, чтобы ответить 403, и может не увидеть роль без строк грантов; вычислитель остаётся последним судьёй: строка мимо двери не действует по правилу выше. Вопрос закрывает конец шага, а не строка: отвергнутая шаг не двигает и вопроса никому не закрывает. Без ответа `ask` кончается `default`.

## Н3 Проход

```
начало прохода вычислителя (глава 2 Н3): прочитать таблицы Н1.1
tz: окружение, один раз при старте
now → object_mode(now, tz) → поле пульса
для сработки: t = occurred (глава 4 Н1.8); условия time, mode, окна, приглушение считаются по t
```

**Гонки.** Таблицы читаются отдельно от строк событий: правка расписания между проходами действует со следующего прохода, в том числе для
событий, случившихся раньше неё: истории таблиц нет, предел. Две сработки одного момента в разных проходах одного вычислителя могут
прочитать разные строки; имя сработки от этого не меняется, повтор безвреден (глава 4).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
