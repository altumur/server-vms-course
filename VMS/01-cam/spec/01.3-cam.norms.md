# V/01.3 — Источник `driverpack://file`: нормы

Канон главы 3 урока V/01 «Камера» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../01-cam.md),
[инструкция](01-cam.README.md), [приёмка](../acceptance/3/README.md). Платформа — выгрузка `cammeta-specs` `9b1a484`.

Между держателем и камерой стоит драйвер устройства: он знает вендоров, их SDK и прошивки (у продукта — DriverPack и
хост драйверов). Курс и стенд камер не имеют — у них есть файлы, которые ведут себя как камеры: адрес
`driverpack://file/<имя>`. Глава нормирует этот источник: какой адрес он принимает, как отказывает и что значит «файл
ведёт себя как камера» — то, на что опираются приёмки VMS (стенд — [общий README приёмки VMS](../../common/acceptance/README.md)).
Какие ещё схемы и драйверы открывает держатель, решает реализация; знание о вендорах — только в источнике: контроллер,
консоль и страница `source` не разбирают сверх правил V/01.1, и камера с адресом, который держатель не откроет,
размещается, правится и показывается как любая.

Id норм — `V/01.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Метки времени кадров — время потока источника (не стенное); Н1.2.

**Данные.** Читает файл `<MEDIA_DIR>/<имя>`; строк хранилища у главы нет.

### Н1.1 Адрес

`driverpack://file/<имя>` — файл `<MEDIA_DIR>/<имя>`:
- `<имя>` — ровно один сегмент пути: не пустой, без `/` и без `..`; подкаталогов нет;
- `MEDIA_DIR` — файл подсистемы `/etc/cam/cam.env` (V/01.2 Н1.7); умолчание — `/data/platform/subsystems/cam/media`
  (каталог состояния `cam`, [P/02.4 Н1.1](../../../Platform/02-installer/spec/02.4-installer.norms.md) `dirs`); держатель
  его только читает;
- хоста нет (`schemes.driverpack.none: [file]`, V/01.1 Н1.1): у такой камеры нет устройства — ни строки `cam/devices`,
  ни команд (V/01.4), ни архива устройства (V/01.5).

Отказ источника — слова со **скрытым адресом**: логин, пароль и всё перед `@` заменены, параметры — маской
[P/06.2 Н1.1а](../../../Platform/06-console/spec/06.2-console.norms.md) (слова уходят в журнал воркера и в `reason` пульса):

| Адрес | Слова отказа |
|---|---|
| не разбирается как адрес | `not an address: …` |
| `driverpack://<не file>/…` у реализации без драйвера этого вендора | `driverpack://<хост>/… names a vendor driver; …` |
| `driverpack://file/` с пустым именем, `/` или `..` | `bad media name in <скрытый адрес>` |
| схема, которую реализация не открывает | `not a <схема> source here: <скрытый адрес>` |

### Н1.2 Файл как камера

- **Темп реального времени:** кадр уходит дальше, когда время потока дошло до его метки; час файла — час потока
  (иначе час записи ляжет в том за мгновение).
- **Только видео:** дорожка H.264 файла; прочие дорожки не идут.
- **Цикл без шва:** конец файла — не конец потока: источник начинает файл сначала, и для всего, что ниже (подписчики,
  молчание 8 с, V/01.2 Н1.2), поток не прерывается — нет события `silent`, нет перезапуска.
- **Время не идёт назад:** метки времени растут, пока процесс жив; первый кадр нового круга — строго после последнего
  кадра прошлого (на длительность кадра при 25 к/с: другая частота даёт другой зазор на стыке, монотонность та же);
  новый круг начинается с ключевого кадра, старые кадры прошлого круга в поток не попадают.

Своей двери у главы нет: источник — часть потока держателя (V/01.2).

## Н3 Проход

### Открыть источник (start_unit держателя, V/01.2 Н3)

```
адрес не по Н1.1 → отказ со словами Н1.1: неудача запуска единицы (отступ P/03.3 Н1.2 retry), device_state refused, reason —
                   слова отказа (V/01.2 Н1.4); пути отказа особого нет: тот же, что у упавшей сети
файла нет или он не читается → неудача запуска, reason — слова ошибки чтения
иначе → поток по Н1.2
```

**Гонки.** Файл заменили, пока поток идёт: новый круг читает файл заново — чем он стал, тем и идёт; монотонность Н1.2
держится.

---

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| адрес не по Н1.1 | неудача запуска, `device_state: refused`, `reason` — слова Н1.1 | пульс, журнал воркера | исправить адрес |
| файла нет | неудача запуска, `reason` | пульс | положить файл в `MEDIA_DIR` |

## Н5 Приёмка

Сценарии — [`../acceptance/3/scenarios.tsv`](../acceptance/3/scenarios.tsv), стенд — [README](../acceptance/3/README.md) (стенд
главы 2). Поток из файла держится — приёмка 2 (`running`). Прогон — после первой генерации стадии C, прошедшей приёмку
платформы (ADR-0090 доп. (8), (9)).

Проверяются чтением: темп, цикл без шва и монотонность меток на стыке — часовой прогон у реализации (её описание
называет его результат); отказ вендорскому адресу — зависит от драйверов реализации.

---

## Решает реализация

Реализация обязана назвать в своём описании: **какие схемы и драйверы вендоров открывает держатель** (сверх
`driverpack://file`) и слова отказа для остальных; **часовой прогон** источника `driverpack://file` на монотонность меток.

## Соответствие прежним урокам

Из М10B/05 «`driverpacksrc`» — шаги 1 (чистый разбор, три отказа, скрытый адрес), 2 (темп, только видео), 3 (отказ
свойства → неудача → откат), 4 (пересчёт меток на стыке, EOS не пропускается, перемотка с ключевого кадра); устройство
элемента (бин, пады, регистрация, ранг — шаги 2, 5) — код, не переносится. Отличия от свидетеля: `MEDIA_DIR` по
умолчанию — `/data/platform/subsystems/cam/media`, а не `/data/media` (ADR-0091 п. 4); отказ `rtsp://` и прочих схем —
выбор реализации, не норма (у продукта — свой драйвер; манифест `cam` их объявляет, V/01.1 Н1.1). Id
([id-map](../../common/id-map.tsv)): М10B/05 ш.1 → V/01.3-01; М10B/05 ш.2, 4 → V/01.3-02; М10B/05 ш.3 → V/01.3-03.
