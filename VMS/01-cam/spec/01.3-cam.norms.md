# V/01.3 — The source `driverpack://file`: norms

This English text is the source; the Russian translation `ru/spec/01.3-cam.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 3 of lesson V/01 «Камера» (ADR-0080; the VMS module — ADR-0090). Lecture (`ru/01-cam.md`, for people, not in the export),
[instructions](01-cam.README.md), [acceptance](../acceptance/3/README.md). The platform — the export `cammeta-specs` `7a875c75`.

Between the holder and the camera stands the device driver: it knows the vendors, their SDKs and firmware (in the product — DriverPack and
the driver host). The course and the stand have no cameras — they have files that behave like cameras: the address
`driverpack://file/<имя>`. The chapter sets the norms of this source: which address it accepts, how it refuses and what «a file
behaves like a camera» means — what the VMS acceptances rely on (the stand — [the common README of VMS acceptance](../../common/acceptance/README.md)).
Which other schemes and drivers the holder opens, the implementation decides; knowledge of vendors is only in the source: the controller,
the console and the page do not parse `source` beyond the rules of V/01.1, and a camera with an address that the holder will not open
is placed, edited and shown like any other.

Norm ids are `V/01.3-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../НОРМАТИВНЫЕ-СЛОВА.md). The rules of the Platform module are [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-vocabulary).

## Н1 Form

**Time.** Frame timestamps are the stream time of the source (not wall time); Н1.2.

**Data.** Reads the file `<MEDIA_DIR>/<имя>`; the chapter has no store rows.

### Н1.1 Address

`driverpack://file/<имя>` — the file `<MEDIA_DIR>/<имя>`:
- `<имя>` is exactly one path segment of the address: `?…` and `#…` are not part of it and are not read by the holder; it is checked **after decoding** `%XX` (`%2F` is also `/`): not empty, not `.` and
  not `..`, without `/`, `\` and NUL; `..` inside a name (`a..b.mp4`) is allowed; there are no subdirectories;
- `MEDIA_DIR` — the subsystem file `/etc/cam/cam.env` (V/01.2 Н1.7); the default is `/data/platform/subsystems/cam/media`
  (the state directory of `cam`, [P/02.4 Н1.1](../../../Platform/02-installer/spec/02.4-installer.norms.md) `dirs`); the holder
  only reads it;
- there is no host (`schemes.driverpack.none: [file]`, V/01.1 Н1.1; the node — as written, the address contract «Схемы» `node`): such a camera has no device — no row `cam/devices`,
  no commands (V/01.4), no device archive (V/01.5).

A refusal of the source is words with a **hidden address**: the login, the password and everything before `@` are replaced, the parameters are masked by the
[address contract](../../../Platform/common/contracts/url-credentials.md) (owner — [P/06.2 Н1.1а](../../../Platform/06-console/spec/06.2-console.norms.md)) (the words go to the worker log and to `reason` of the heartbeat):

| Address | Refusal words |
|---|---|
| does not parse as an address | `not an address: …` |
| `driverpack://<не file>/…` at an implementation without a driver of this vendor | `driverpack://<хост>/… names a vendor driver; …` |
| `driverpack://file/` with a name that is empty, `.` or `..`, or with `/`, `\`, NUL after decoding | `bad media name in <скрытый адрес>` |
| a scheme that the implementation does not open | `not a <схема> source here: <скрытый адрес>` |

### Н1.2 File as a camera

- **Real-time pace:** a frame goes on when the stream time has reached its timestamp; an hour of the file is an hour of the stream
  (otherwise an hour of recording would land in the volume in an instant).
- **Video only:** the H.264 track of the file; other tracks do not go.
- **Seamless loop:** the end of the file is not the end of the stream: the source starts the file from the beginning, and for everything below (subscribers,
  the 8 s silence, V/01.2 Н1.2) the stream is not interrupted — no event `silent`, no restart.
- **Time does not go back:** timestamps grow while the process is alive; the first frame of a new round is strictly after the last
  frame of the previous one (by the duration of a frame at 25 fps: another frame rate gives another gap at the joint, the monotonicity is the same);
  a new round starts with a key frame, old frames of the previous round do not get into the stream.

## Н3 Procedures

### Open the source (start_unit of the holder, V/01.2 Н3)

The outcomes are one rule of [V/01.2 Н3](01.2-cam.norms.md) (the address is not read; a temporary failure); the chapter gives the words:

```
address not by Н1.1 → the address is not read by the subsystem (V/01.2 Н3): device_state refused, reason — the words of Н1.1; do not open,
                   no retries (phase pending), until the row is edited
the file is absent, is not readable or has no H.264 track with frames → a temporary failure (V/01.2 Н3): a start failure with backoff
                   P/03.3 (phase failed, stalled after RETRY_MAX), device_state opening, reason — the words of the read error
otherwise → the stream by Н1.2
```

**Races.** The file was replaced while the stream is going: a new round reads the file anew — whatever it has become, that is what goes; the monotonicity of Н1.2
holds.

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| address not by Н1.1 | not held, no retries: `device_state: refused`, `reason` — the words of Н1.1 (V/01.2 Н3) | heartbeat, worker log | fix the address |
| the file is absent, is not readable or has no H.264 track with frames | a start failure with backoff: `device_state: opening`, `reason` (V/01.2 Н3) | heartbeat | put the file into `MEDIA_DIR` |

Scenarios — [`../acceptance/3/scenarios.tsv`](../acceptance/3/scenarios.tsv), the stand — [README](../acceptance/3/README.md) (the stand
of chapter 2). A stream from a file is held — acceptance 2 (`running`). The run — after the first generation of stage C that has passed the acceptance

Checked by reading: the pace, the seamless loop and the monotonicity of timestamps at the joint — an hour-long run at the implementation (its description
names its result); the refusal of a vendor address — depends on the drivers of the implementation.

## Implementation decides

The implementation MUST name in its description: **which schemes and vendor drivers the holder opens** (beyond
`driverpack://file`) and the refusal words for the rest; **an hour-long run** of the source `driverpack://file` for the monotonicity of timestamps.
