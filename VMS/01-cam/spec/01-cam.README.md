# V/01 Камера — инструкция для реализации

Что реализация подсистемы `cam` делает и как проверить результат. Канон — нормы глав `01.K-cam.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `e0b19be`: реализация `cam` — подсистема на
платформе, она не правит и не повторяет её код.

## Входы и их приоритет

- Канон — нормы глав `01.K-cam.norms.md` (Н1–Н5 каждой главы; адреса `V/01.K Н…`).
- Канон манифеста — [`cam.subsystem.yaml`](../cam.subsystem.yaml): байты как есть.
- [Контракт](01-cam.api.openapi.yaml) выражает формы HTTP-входов канона.
- Приёмка — [глава 1](../acceptance/1/README.md), [глава 2](../acceptance/2/README.md), [глава 3](../acceptance/3/README.md), [глава 4](../acceptance/4/README.md), [глава 5](../acceptance/5/README.md); стенд и словарь — [общий README приёмки VMS](../../common/acceptance/README.md); новых требований приёмка не вводит.
- [Лекция](../01-cam.md) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…` (их правит не VMS).

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/01.1 | манифест `VMS/01-cam/cam.subsystem.yaml` грузится строгим загрузчиком без правок; дверь единиц консоли платформы исполняет объявления камеры | [приёмка 1](../acceptance/1/README.md) |
| V/01.2 | держатель `camworker`: желаемое, одно соединение, раздача RTSP и доля `cam.shm`, слова пульса, события; команда запуска держателя для «Стенда» приёмки называется в описании реализации | [приёмка 2](../acceptance/2/README.md) |
| V/01.3 | источник `driverpack://file/<имя>`: отказы Н1.1, файл как камера Н1.2; часовой прогон на монотонность меток — в описании реализации | [приёмка 3](../acceptance/3/README.md) |
| V/01.4 | исполнение просьб `output`, `preset` драйвером устройства, вопросы к устройству вне цикла, строка `cam/devices/<хост>`, `can` | [приёмка 4](../acceptance/4/README.md) |
| V/01.5 | дверь держателя (`/devices`, `/recordings`, `/playback`) по [OpenAPI](01-cam.api.openapi.yaml), пределы Н1.5, класс `role`; драйвер архива устройства | [приёмка 5](../acceptance/5/README.md) |
| V/01.6 | вклад в книгу `cam/sources/<слот>`, толкатель потока камеры (опрос приёмника, продолжение, заявки), `taken_by`; транспорт потока — в описании реализации | чтением (стенда домена VMS нет) |
| V/01.7 | воркер на домене `camdomain`: проверка подписи ключом вендора, счёт по виду домена, книга `licence`; держатель не держит камеру вне `licensed` | чтением (стенда домена VMS нет) |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8), не копирует и не
дополняет.

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы); затем `cam` над ней — приёмка VMS идёт только на
такой платформе (ADR-0090 доп. (8), (9)).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/01.2 Н1.3 | строить адрес доли `shm:///…/<id>-<эпоха>.shm` у читателя или писать в чужую эпоху | адрес доли берётся из пульса как есть; удаляет файл доли только его писатель |
| V/01.1 Н1.1, V/01.2 Н1.2 | снимать порт по умолчанию в каноне адреса двери или считать `ch/02` и `ch/2` одним каналом | канон адреса — по договору проверки строки; «тот же канал» (`busy`) — только равенство после снятия порта по умолчанию схемы |
| V/01.2 Н3 | повторять открытие адреса, который подсистема не читает | синтаксис — `refused`, без повторов; файла нет или устройство отказало — неудача запуска с отступом |
| V/01.7 Н1.3 | обслуживать камеру `unlicensed` хотя бы частично | команды `refused`, дверь — 404, элемента книги `sources` нет |
| V/01.4 Н1.1 | принимать строку `"1"` как целое | целое — только JSON-целое; входы, выходы и пресеты — с 1 |
| V/01.5 Н2 | обрывать рукопожатие на чужой роли | класс `role` как есть: 401 `no_role`, 403 `wrong_role`, `bad_chain` |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; приёмка глав 1, 2, 3, 4, 5 проходит на платформе, прошедшей свою приёмку;
пункты чеклистов, отмеченные «чтением», подтверждены описанием реализации (раздел «Решает реализация» каждой главы).
Проверка схемы, загрузчика и стенда друг друга не подменяют.

## При расхождении

Порядок источников: нормы главы → OpenAPI → приёмка и векторы → лекция; платформа — нормы выгрузки пина VMS.
Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и предложением; норма
платформы — через «Архитектора». Дефект приёмки (ожидание против нормы) — тот же маршрут; закрытое решение
вносится в канон, а не остаётся в этой инструкции.
