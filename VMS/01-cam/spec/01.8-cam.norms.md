# V/01.8 — Device search: norms

This English text is the source; the Russian translation `ru/spec/01.8-cam.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 8 of lesson V/01 «Камера» (ADR-0103 addendum (1)). Lecture (`ru/01-cam.md`, for people, not in the export), [instructions](01-cam.README.md), the manifest
[`cam.subsystem.yaml`](../cam.subsystem.yaml). The platform — the export `cammeta-specs` `7a875c75`. The driver entry points and `.rep` follow DriverPack
2026-10-02 and are reconciled against each new version.

A search finds devices in the network and creates nothing: the operator registers a discovery by an ordinary creation. A search is broadcast and
sees the subnet of its own server, so it runs on all servers of the cluster, while the result is one. The chapter norms the search row, the discovery,
the question "which model is at this address" and the entry into the driver. The translation into the consolem contract — [V/11.4 Н1.9](../../11-backend/spec/11.4-backend.norms.md).

Norm ids are `V/01.8-MM`; the map — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../НОРМАТИВНЫЕ-СЛОВА.md). The rules of the Platform module are [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#n0-vocabulary).

**The base worker of a server** — the slot `w-<сервер>-1` (P/02.4 Н1.1): one per server with the role `cam`, present even without cameras. The search and the model probe are executed
by it alone; the other workers of the server do not read the tables of the chapter.

## Н1 Form

**Time.** `started_at`, `until`, `stopped_at`, `found_at` are Unix seconds, time in the writer's form ([P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md)).
The one who reads compares them with its own clock.

**Data** (shared families `<sub>/…` of the [platform catalogue](../../../Platform/common/data/catalog.tsv); the chapter has no keys of its own beyond
them): the manifest tables `searches`, `probes` are console tables, written by `backend` by a ticket, read by the base worker; `found`,
`probe_replies` are worker tables (`worker.writes`), written by the base worker, read by `backend`. The term of the rows of all four is
`delete_after` 86400 s (a value without a basis, checked by measurement); they are removed by the console reaper (P/06.4 Н3 `tables`); the result lives from the search until a device is created.

### Н1.1 The search row

A search has no unit and no holder, while a request `requests:` requires a unit and goes to one holder (P/06.4 Н1.5); so a search is
one row per cluster, `cam/searches/<CLUSTER>`. It is read by the base worker of every server on its pass.

| Field | Form | Writer | Meaning |
|---|---|---|---|
| `cluster` | string, required | `backend` | the key: the cluster name (P/02.4 Н1.2) |
| `search` | 32 hex, required | `backend` | which search this is: a discovery names it |
| `started_at` | number, required | `backend` | the start |
| `until` | number, required | `backend` | `started_at` + `SEARCH_TIME` |
| `stopped_at` | number | `backend` | the search was stopped by a person; no field — not stopped |

- `SEARCH_TIME` = 30 s (a value without a basis, checked by measurement). The driver searches in rounds without end, so the end of a search is only the deadline or a stop. A worker searches no longer than
  `SEARCH_TIME` from its own start, whatever `until` is.
- A new search replaces the row whole: one search per cluster; the previous result is the rows with another `search`.
- **No row** — there is no search; one running on the server stops. **The row is unreadable** (`garbled`, a field not in form) — this does not mean "no
  search": the worker does not start a new one, the running one goes on to its own deadline, a log line.
- **Limit.** The subnet of a server is absent from the result, and the result does not say so, if the base worker of the server is dead, the server has no role `cam`, or the worker's clock is ahead by `SEARCH_TIME` or more: the deadline passed before the first look.

### Н1.2 The discovery

`cam/found/<h>` — a row per device. The key does not name the search: a device keeps its row from search to search. A discovery is only
what the device told the driver; nothing is created by itself.

| Field | Form | Source | Meaning |
|---|---|---|---|
| `h` | 64 hex, required | | SHA-256 hex of the text `<mac>\|<ip>:<port>`: `mac` — lower case, only the digits of the address, empty without a MAC. A zero or coinciding MAC does not merge devices |
| `search` | 32 hex, required | the search row | the search that found the device last |
| `vendor` | string, required | `GetBrand` | the brand |
| `model` | string, required | `GetModel` | the model |
| `ip` | non-empty string, required | `GetLANAddress` | the address |
| `port` | integer 0–65535, required | `GetPort` | the port |
| `mac` | string | `GetMac` | the MAC as the driver said it; empty — no field |
| `support` | `ok` \| `manual` \| `bad`, required | Н1.4 | what the drivers have |
| `found_at` | number, required | the worker's clock | the order of the result |

- `support` by the driver catalogue: the pair of brand and model exists — `ok`; there is no model, but the brand has `generic` — `manual`; otherwise `bad`. `ok`
  means "there is a driver", not "logged in".
- There is no login or password in a discovery: the search neither guesses nor stores them. The operator enters the credentials at creation (`cred_secret`, V/01.1).
- Two servers see a device at one address — there is one row. Limits: two devices in isolated subnets with one address and one MAC, or without a MAC — one row; a device with two addresses — two rows; a change of address — a new row.
- The search sets no labels: a device of another server's subnet is placed by the operator with `labels` (V/01.1).

### Н1.3 Which model

The probe `cam/probes/<id>` is set by `backend`: which model of `vendor` is at the address `ip`, `port`. Whose subnet it is, is not known in advance, so
the base worker of every server asks, and each one answers with its own row `cam/probe_replies/<probe>-<сервер>`.

| Field | Form | Writer | Meaning |
|---|---|---|---|
| `id` | 32 hex, required | `backend` | the probe key |
| `ip`, `port`, `vendor` | required, `port` 1–65535 | `backend` | the address and the brand |
| `until` | number, required | `backend` | the reply deadline: now + `PERFORM_TIMEOUT` = 10 s (P/03.6 Н1.5) |
| `probe`, `server` | required | worker | the reply key: the probe `id`, the server name |
| `model` | string | worker | the model; no field — this server did not find out |

**Limit.** There is no login or password in the probe; the driver gets empty ones: a device that does not name its model without a login gives no reply with `model`.
The question to consolem is open ([README V/11](../../11-backend/README.md), «Открытые вопросы»).

### Н1.4 Entry into the driver

| Work | Entry |
|---|---|
| search | `IDeviceManager::StartSearch` with a constant search, a discovery — `DeviceFound`, the end — `StopSearch`; a driver without `CreateSearchTool` is skipped |
| discovery | `IDeviceSearchResult`: `GetBrand`, `GetModel`; `IIpDeviceSearchResult`: `GetLANAddress`, `GetMac`, `GetPort` |
| model | `IDeviceManager::Autodetect(handler, connectInfo, brand)`, the answer — `Autodetected`, a failure — `Failed`, a stop — `StopAutodetect`; the driver — `IAutodetect::Start`; `connectInfo` — `<ip>:<port>::` |
| catalogue | `IDeviceManager::GetDeviceInfo`: the brand and model of the drivers from `.rep` |

The calls are made outside the pass loop, like questions to a device (V/01.4 Н1.3): the search holds neither the lease nor the heartbeat.

## Н3 Pass

### Search (the base worker, on the pass)

```
row cam/searches/<CLUSTER> unreadable → the running search goes on until its own deadline, no new one, log
no row, stopped_at present, until passed → the running search: StopSearch
search is not the one running, until not passed → the running one: StopSearch; StartSearch; own deadline = min(until, now + SEARCH_TIME)
own deadline passed → StopSearch
```

### Discovery (`DeviceFound`)

```
search no longer running | result not IP | no address → skip
h written in this search → skip: the driver repeats the discovery every round
read cam/found/<h>:
  absent | another search → write the row whole with cas (P/03.4 Н1.6), remember h
  the same search → remember h
  unreadable → do not touch, log
  read not confirmed → do not remember: next round
cas conflict → reread: the same step
```

### Probe (the base worker, on the pass)

```
row cam/probes/<id> unreadable → skip, log
until passed | own reply exists | probe already asked → skip
otherwise → Autodetect outside the loop
Autodetected → reply with model; Failed | until passed → StopAutodetect, reply without model
```

**Races.** Two servers found one device: `cas` lets one write through, the second reads the same `search`. A discovery at the moment the search is stopped
can land after `stopped_at`: it is in the result, nothing else changes. The operator removed the row while the search is running — another server will write it again.

## Н4 Refusals

The chapter has no refusal words of its own: it has no door answers. The refusals of the tables are the console's (P/06.1 Н4).

| Cause | What the worker does | Observability | What the caller does |
|---|---|---|---|
| a driver failure during a search | the discoveries stay, the search goes on until the deadline | log | a new search |
| a row of the chapter is unreadable | does not touch it (Н3) | log | a new search or probe |
| the driver did not return the model in time | a reply without `model` | the reply row | manual input |
