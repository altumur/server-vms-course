# V/01.8 — Поиск устройств: нормы

Канон главы 8 урока V/01 «Камера» (ADR-0103 доп. (1)). [Лекция](../01-cam.md), [инструкция](01-cam.README.md), манифест
[`cam.subsystem.yaml`](../cam.subsystem.yaml). Платформа — выгрузка `cammeta-specs` `504348e5`. Входы драйвера и `.rep` — по DriverPack
2026-10-02, сверяется по новой версии.

Поиск находит в сети устройства и ничего не заводит: находку заводит оператор обычным созданием. Поиск широковещательный и
видит подсеть своего сервера, поэтому идёт на всех серверах кластера, а итог один. Глава нормирует строку поиска, находку,
вопрос «какая модель по этому адресу» и вход в драйвер. Перевод в контракт consolem — [V/11.4 Н1.9](../../11-backend/spec/11.4-backend.norms.md).

Id норм — `V/01.8-MM`; соответствие — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

**Базовый воркер сервера** — слот `w-<сервер>-1` (P/02.4 Н1.1): один на сервер с ролью `cam`, есть и без камер. Поиск и вопрос о модели исполняет
он один, прочие воркеры сервера таблиц главы не читают.

## Н1 Форма

**Время.** `started_at`, `until`, `stopped_at`, `found_at` — секунды Unix, время по форме писателя ([P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md)).
Сравнивает со своими часами тот, кто читает.

**Данные** (общие семьи `<sub>/…` [каталога платформы](../../../Platform/common/data/catalog.tsv); своих ключей сверх них у главы
нет): таблицы манифеста `searches`, `probes` — таблицы консоли, пишет `backend` по билету, читает базовый воркер; `found`,
`probe_replies` — таблицы воркера (`worker.writes`), пишет базовый воркер, читает `backend`. Срок строк всех четырёх —
`delete_after` 86400 с (значение без опоры, проверяется замером), снимает жнец консоли (P/06.4 Н3 `tables`); итог живёт от поиска до создания устройства.

### Н1.1 Строка поиска

У поиска нет единицы и держателя, а просьба `requests:` требует единицу и идёт одному держателю (P/06.4 Н1.5), поэтому поиск —
одна строка на кластер, `cam/searches/<CLUSTER>`. Её читает базовый воркер каждого сервера на проходе.

| Поле | Форма | Пишет | Смысл |
|---|---|---|---|
| `cluster` | строка, обязательно | `backend` | ключ: имя кластера (P/02.4 Н1.2) |
| `search` | 32 hex, обязательно | `backend` | какой это поиск: находка называет его |
| `started_at` | число, обязательно | `backend` | начало |
| `until` | число, обязательно | `backend` | `started_at` + `SEARCH_TIME` |
| `stopped_at` | число | `backend` | поиск снят человеком; поля нет — не снят |

- `SEARCH_TIME` = 30 с (значение без опоры, проверяется замером). Драйвер ищет раундами без конца, поэтому конец поиска — только срок или снятие. Воркер ищет не дольше
  `SEARCH_TIME` от своего начала, каким бы ни был `until`.
- Новый поиск заменяет строку целиком: один поиск на кластер, прежний итог — строки с другим `search`.
- **Строки нет** — поиска нет, идущий на сервере останавливается. **Строка не читается** (`garbled`, поле не по форме) — не значит «поиска
  нет»: нового воркер не начинает, идущий доходит до своего срока, строка лога.
- **Предел.** Подсети сервера нет в итоге, и итог этого не говорит, если базовый воркер сервера мёртв, роли `cam` на сервере нет или часы воркера спешат на `SEARCH_TIME` и больше: срок вышел раньше первого взгляда.

### Н1.2 Находка

`cam/found/<h>` — строка на устройство. Ключ не называет поиск: устройство сохраняет строку от поиска к поиску. Находка — только
то, что сказало устройство драйверу; ничего не заводится само.

| Поле | Форма | Откуда | Смысл |
|---|---|---|---|
| `h` | 64 hex, обязательно | | SHA-256 hex текста `<mac>\|<ip>:<port>`: `mac` — нижний регистр, только цифры адреса, без MAC пусто. Нулевой или совпавший MAC устройства не склеивает |
| `search` | 32 hex, обязательно | строка поиска | поиск, нашедший устройство последним |
| `vendor` | строка, обязательно | `GetBrand` | бренд |
| `model` | строка, обязательно | `GetModel` | модель |
| `ip` | непустая строка, обязательно | `GetLANAddress` | адрес |
| `port` | целое 0–65535, обязательно | `GetPort` | порт |
| `mac` | строка | `GetMac` | MAC как сказал драйвер; пусто — поля нет |
| `support` | `ok` \| `manual` \| `bad`, обязательно | Н1.4 | что есть у драйверов |
| `found_at` | число, обязательно | часы воркера | порядок итога |

- `support` по каталогу драйверов: пара бренд и модель есть — `ok`; модели нет, у бренда есть `generic` — `manual`; иначе `bad`. `ok`
  значит «драйвер есть», а не «вошли».
- Логина и пароля в находке нет: поиск их не подбирает и не хранит. Учётные данные оператор вводит при создании (`cred_secret`, V/01.1).
- Два сервера видят устройство по одному адресу — строка одна. Пределы: два устройства в изолированных подсетях с одним адресом и одним MAC или без него — одна строка; устройство с двумя адресами — две строки; смена адреса — новая строка.
- Поиск не ставит меток: устройство подсети другого сервера оператор размещает `labels` (V/01.1).

### Н1.3 Какая модель

Вопрос `cam/probes/<id>` задаёт `backend`: какая модель `vendor` по адресу `ip`, `port`. Чья подсеть, заранее не известно, поэтому
спрашивает базовый воркер каждого сервера, и каждый отвечает своей строкой `cam/probe_replies/<probe>-<сервер>`.

| Поле | Форма | Пишет | Смысл |
|---|---|---|---|
| `id` | 32 hex, обязательно | `backend` | ключ вопроса |
| `ip`, `port`, `vendor` | обязательно, `port` 1–65535 | `backend` | адрес и бренд |
| `until` | число, обязательно | `backend` | срок ответа: сейчас + `PERFORM_TIMEOUT` = 10 с (P/03.6 Н1.5) |
| `probe`, `server` | обязательно | воркер | ключ ответа: `id` вопроса, имя сервера |
| `model` | строка | воркер | модель; поля нет — этот сервер не узнал |

**Предел.** Логина и пароля в вопросе нет, драйвер получает пустые: устройство, которое без входа модели не называет, ответа с `model`
не даёт. Вопрос к consolem открыт ([README V/11](../../11-backend/README.md), «Открытые вопросы»).

### Н1.4 Вход в драйвер

| Работа | Вход |
|---|---|
| поиск | `IDeviceManager::StartSearch` с постоянным поиском, находка — `DeviceFound`, конец — `StopSearch`; драйвер без `CreateSearchTool` пропускается |
| находка | `IDeviceSearchResult`: `GetBrand`, `GetModel`; `IIpDeviceSearchResult`: `GetLANAddress`, `GetMac`, `GetPort` |
| модель | `IDeviceManager::Autodetect(handler, connectInfo, brand)`, ответ — `Autodetected`, сбой — `Failed`, снятие — `StopAutodetect`; драйвер — `IAutodetect::Start`; `connectInfo` — `<ip>:<port>::` |
| каталог | `IDeviceManager::GetDeviceInfo`: бренд и модель драйверов из `.rep` |

Вызовы — вне цикла прохода, как вопросы к устройству (V/01.4 Н1.3): поиск не держит аренды и пульс.

## Н3 Проход

### Поиск (базовый воркер, на проходе)

```
строка cam/searches/<CLUSTER> не читается → идущий поиск до своего срока, нового нет, лог
строки нет, есть stopped_at, until вышел → идущий поиск: StopSearch
search не тот, что идёт, until не вышел → идущий: StopSearch; StartSearch; свой срок = min(until, сейчас + SEARCH_TIME)
свой срок вышел → StopSearch
```

### Находка (`DeviceFound`)

```
поиск уже не идёт | результат не IP | адреса нет → пропустить
h записан в этом поиске → пропустить: драйвер повторяет находку каждый раунд
прочитать cam/found/<h>:
  нет | другой search → записать строку целиком с cas (P/03.4 Н1.6), запомнить h
  тот же search → запомнить h
  не читается → не трогать, лог
  чтение не подтверждено → не запоминать: следующий раунд
конфликт cas → перечитать: тот же шаг
```

### Вопрос (базовый воркер, на проходе)

```
строка cam/probes/<id> не читается → пропустить, лог
until вышел | свой ответ есть | вопрос уже задан → пропустить
иначе → Autodetect вне цикла
Autodetected → ответ с model; Failed | until вышел → StopAutodetect, ответ без model
```

**Гонки.** Два сервера нашли одно устройство: `cas` пропускает одну запись, вторая читает тот же `search`. Находка в миг снятия поиска
может лечь после `stopped_at`: она в итоге, остальное не меняется. Строку снял оператор, а поиск идёт — другой сервер запишет её заново.

## Н4 Отказы

Своих слов отказа у главы нет: ответов двери нет. Отказы таблиц — консоли (P/06.1 Н4).

| Причина | Что делает воркер | Наблюдаемость | Что делает вызывающий |
|---|---|---|---|
| сбой драйвера в поиске | находки остаются, поиск идёт до срока | лог | новый поиск |
| строка главы не читается | не трогает её (Н3) | лог | новый поиск или вопрос |
| драйвер не вернул модель за срок | ответ без `model` | строка ответа | ввод руками |
