# V/01.6 — Камера на домене: нормы

Канон главы 6 урока V/01 «Камера» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../01-cam.md),
[инструкция](01-cam.README.md), манифест [`cam.subsystem.yaml`](../cam.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `f225f3ef` (поток в виде домена, `view.main` — `b41527f`).

Домен знает подсистему только по разделу `domain:` её манифеста ([P/02.1 Н1.2б](../../../Platform/02-installer/spec/02.1-installer.norms.md)).
Глава нормирует вклад `cam`: как камера называется во всём домене, что домен о ней видит и правит, какую книгу пишет её
держатель, какие токены `cam` объявляет, как камера толкает свой поток в приёмник кластера записи, что `cam`
добавляет к кластеру из одного и как держатель заказывает запись на карту своего сервера. Отдельного доменного процесса у VMS нет (ADR-0074): вклад пишет обычный держатель
`camworker`, собирает и несёт книги платформа (P/03.7, P/08.5, P/09.1); воркер на домене `camdomain` у `cam` есть только
ради переносимой книги `licence` (глава 7). Сторона приёмника — книги `primaries`, `polls`,
`upstream`, дозапись, резерв, свидетель — урок V/02; сценарии между камерами — V/07; учётки RTSP — V/03 (доп. (4) п. 5).

Id норм — `V/01.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `as_of` — секунды Unix (число JSON); `t` кадра — время съёмки по часам камеры (Н1.4).

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv); своих ключей сверх них у главы
нет; файл токена `stream` — не ключ хранилища, Н1.3): пишет держатель — вклад `cam/sources/<слот>` (P/03.7 Н1.2), строку заказа `rec/recordings/cam-<cam>-<том>` (Н1.7); читает — `rec/volumes/*` (Н1.7), `domain/rec/primaries`,
`domain/placed/rec/<ref>`, `domain/rec/polls` (копии, которые принёс агент, P/09.1; у кластера — держателя домена копий
нет, там читаются строки своего кластера `domain/rec/primaries/<CLUSTER>`, `domain/rec/polls/<CLUSTER>` — права на неё
воркеру выводит генератор прав по `CLUSTER` установщика, P/02.5 Н1.4, C02-OWN-BOOK-HOLDER-01; `worker.reads` манифеста
называет только копию; назначение у держателя — запись `domain/placement/rec/<ref>`, P/08.6 Н1.1 `readers`, права даёт `worker.reads` `domain/placed/rec/`), `domain/member-list`, `domain/view`, `domain/keys`, топологию (Н1.6) и решение лицензии (глава 7 Н1.3); пульс — поле `taken_by` (Н1.4). Переносимую книгу
`domain/cam/licence/<член>` пишет воркер на домене (глава 7 Н1.2).

### Н1.2 Вклад в книгу источников

Держатель пишет строку `cam/sources/<свой слот>` (P/03.7 Н1.2: элемент — объект с `key` и `to`; права — основа роли,
новый держатель слота чистит строки под ним): по элементу на камеру своего назначения, имя элемента — `id` камеры,

- **камера размещена** с `origin` = свой кластер (запись `domain/placed/rec/<ref>`, у держателя домена — `domain/placement/rec/<ref>`, P/09.1 Н1.5, P/08.6 Н1.1) —
  `{ref, to, live_url?, codec?, server?, as_of, push?}`: `to` — `cluster` + `copies` назначения; `live_url` — RTSP раздачи
  (V/01.2 Н1.3), пока она есть; `server` — сервер держателя (`SERVER_NAME`; не задан — поля нет); `push: true` — камера
  толкает поток сама, что бы ни было: камера-кластер (`source: cfw://local`, Н1.5) — всегда, серверная камера — поля нет
  (её забирает регистратор); в книгу `domain/rec/primaries` (`push`, V/02.9) его переносит регистратор, толкатель берёт
  его оттуда (Н1.4, Н1.6);
- **камеру никто не пишет** (назначения `domain/placed/rec/<ref>`, у держателя домена — `domain/placement/rec/<ref>`, нет), а опрашивать её нужно — камера `enabled`, с
  `ref`, толкает сама (`push`, камера-кластер): её поток доступен приёмникам только через опрос (Н1.4, V/02.9 Н1.7) —
  `{ref, to: [дом опроса] (+ центр, если дом ≠ центр), polls: true, server?, as_of}`; дом — по копии топологии, у держателя домена — по `domain/topology` (P/08.7
  Н1.1 `poll_home`); серверная камера без назначения элемента не получает (её раздача — RTSP держателя в своём кластере);
- камера `unlicensed` (глава 7 Н1.3) элемента не получает;
- запись `domain/placed/rec/<ref>` или топология не читается, хранилище не ответило — не прочитана, а не отсутствует:
  прежний элемент держится, журнал.

Поля «пусто, ложь, нет» отсутствуют: поле без значения (`live_url`, `server`, `codec`, `push`) опускается, `""` и `null`
не бывает (форма элемента — семьёй данных, класс VMS). `as_of` меняется только вместе с содержимым элемента: строка
лежит на носителе (у камеры-кластера — на флеше, Н1.5), перезапись без изменения — износ. Решение «забирать или
толкать», дозапись и достижимость — у регистратора-получателя (V/02).

`pick: unique` — один вклад на `ref` во всём домене: два — ключа в книге нет, он в `view.books.conflicts` (P/08.5 Н1.3);
одна камера с одним `ref` в двух кластерах — развести (`ref` уникален в кластере, не в домене). Вход не по форме
снимает весь вклад кластера (`bad_contribution`) — держатель пишет элементы только по форме выше.

### Н1.3 Токены

Форма вида, выдача, проверка у получателя — платформа ([P/08.7](../../../Platform/08-domain/spec/08.7-domain.norms.md) Н1.4,
Н3; [P/03.7 Н1.5](../../../Platform/03-worker/spec/03.7-worker.norms.md)); прав токен не несёт (ADR-0031); живёт только в памяти
просящего, кроме вида `stream` (`keep: true`, ниже); просят его через местную дверь агента (договор местной двери токенов; в камере-кластере — вызов).

| Вид | Объявление | Смысл | Кто просит |
|---|---|---|---|
| `stream` | `lifetime: 315360000` (10 лет), `claims: [aud, ref]`, `grant: [camworker, recworker]`, `placement: {sub: rec, caller: origin, ref_claim: ref, target_fields: [cluster, copies, star_centre], audience_claim: aud}` | ключ потока камеры в приёмники кластера записи и резервов (+ центр звезды); просит только кластер камеры (`origin`) | толкатель: держатель камеры-кластера или регистратор кластера серверной камеры |
| `poll` | `lifetime: 86400`, `claims: [aud, ref]`, `grant: [camworker, recworker]`, `unit: {ref_claim: ref, target_fields: [poll_home], audience_claim: aud}` | долгий опрос камеры, которую никто не пишет, на приёмнике дома опроса (адреса — `domain/rec/polls`) | так же |
| `ask` | `lifetime: 86400`, `claims: [aud, ref, by, acts, up]`, `grant: [autoworker, recworker]`, `scenario: {doc: auto, …, placement: rec, …}` | просьба сценария к камере-цели; поля документа сценариев — урок V/07 | исполнитель `auto` (V/07), регистратор-ретранслятор; камера-цель не просит |

Толкатель просит токен заново до `exp` и по смене назначения (`domain/placed/rec/<ref>`): старый токен не называет
нового кластера записи — приёмник ответит `wrong_audience`. Держатель недоступен дольше `lifetime` токена `poll` — токен
не продлить: камера без записи перестаёт опрашивать.

**Токен `stream` на запись** (ADR-0110 доп. (9)). Молчащий домен запись не останавливает, поэтому срок — 10 лет; форма вида
та же, `lifetime` обязателен.

- **Граница.** `aud` и `ref`: поток этой камеры в кластеры назначения; другой камеры и другого кластера токен не открывает.
- **Где лежит.** Вид `stream` объявлен `keep: true`, хозяин файла — вид: файл держит воркер, что просит токен, держатель камеры и регистратор, в своём каталоге состояния, на коробке это флеш, по P/03.7 Н1.5. Кольцо — файл `SECRETS_KEY`, воркеры `cam`, `rec` его держатели: у них секретные поля. В строку, книгу, отчёт и журнал токен не идёт.
- **Запись файла.** Заменяется только после первого принятого новым токеном обращения; до него в памяти оба: иначе перезагрузка при приёмнике без нового набора оставила бы один негодный.
- **Загрузка.** Файл открылся и в `aud` есть `cluster` копии назначения — толкатель берёт токен без просьбы, срок судит приёмник, не часы камеры: истёкший файл заменяется после отказа `expired`; домен не нужен, назначение и книга `primaries` лежат на флеше копиями. Файла нет, конверт не открылся, кластера нет в `aud` — токена нет: просьба; домен молчит — не толкать, пишет карта, журнал. **Предел:** `w2cctl secrets seal` файлов не обходит, а `rotate` прежний `kid` не снимает, поэтому смена кольца файл не трогает; кольцо потеряно или заменено — конверт не открылся, при молчащем домене толчок стоит.
- **Просит заново**, только при живом домене: смена назначения; `kid` заголовка токена не `current` своей `domain/keys`; до `exp`; приёмник отказал `expired`, `revoked`. Держит новый токен с `current` — не просит; `unknown_key` на токене с `current` — ждёт: приёмник не взял набор, новая выдача не поможет. Просьба не удалась — прежний токен держится.
- **Отзыв.** Домен помнит цель: `domain/issued/cam/stream/<sha16(ref)>`, только у `keep` (P/08.2 Н1.6а); выдача берёт `jti` из этой строки, поэтому `jti` цели постоянен и отзыв закрывает все её токены, старые и новые. Порядок: сначала снять назначение, иначе член сразу получит новый токен; затем `DELETE /domain/issued/cam/stream/<ref>`, `admin` домена: `jti` с наибольшим `exp` в `domain/revoked`, строка снимается. Запись стоит весь срок токена, до приёмника доходит при живом домене.
- **Предел кражи.** Кража камеры с кольцом даёт запись потока этой камеры в кластеры `aud`, пока токен не отозван. Смена назначения токен не отзывает: у прежнего кластера он годен до `exp`. Живых отзывов около 18 700 на домен: сверх — 409, журнал с 80 % (P/08.2 Н1.6а).

Смена ключа токенов доходит только через домен; `OLD_KEYS` = 3600 с ([P/08.2 Н1.6](../../../Platform/08-domain/spec/08.2-domain.norms.md)):

| Случай | Прежний ключ | Толкатель |
|---|---|---|
| плановая смена, камера на связи | годен до `until` | по новому набору просит токен; приёмник без набора — `unknown_key`, идёт прежний токен |
| плановая смена, камера не взяла набор за `OLD_KEYS`: нет связи с держателем, домен замолчал | годен для `keep` до `keep_until` (P/08.2 Н1.6) | идёт прежний токен; домен вернётся — просит |
| приёмник без связи с доменом | годен: набор у него прежний | идёт прежний токен; новый — `unknown_key` до доставки |
| перенос держателя без `stolen` (P/08.8 Н1.8 шаг 7) | годен для `keep` до `keep_until`, как при плановой | идёт прежний токен; домен вернётся — просит новому держателю |
| смена после кражи, перенос с `stolen` (P/08.2 Н3) | окна нет: `unknown_key`, как только приёмник взял набор | все токены домена разом; не толкает до нового токена, домен молчит — до его возврата; пишет карта. **Предел** |
| домена нет | смены нет | идёт до `exp` |

### Н1.4 Толкатель потока

Камера, которая толкает сама (`push`, камера-кластер), держит **один долгий опрос** к приёмнику кластера записи и
толкает поток, пока он кому-то нужен; протокол опроса и приём — приёмника (V/02). Сторона камеры:

- **когда:** желание приходит ответом опроса — регистратору всегда или на окно события, зрителю — пока смотрит и ещё
  `LINGER` = 10 с;
- **куда:** адреса приёмников — запись камеры в книге `domain/rec/primaries` (`ingest`, `push`; основной — по `cluster`
  назначения); перебор по порядку, не ответил ни один — не толкать; на резерв (второй сервер) — только если не ответил
  ни один приёмник основного или его приёмник сказал `uncovered`; ключ — токен `stream` (камера без записи — `poll` на
  `urls` из `domain/rec/polls`); элемент камеры в книге `primaries` или `polls` не по форме (семья V/02 `primaries-entry`,
  `polls-entry`) — не прочитан, а не отсутствует: толкатель держит приёмники, `push` и `urls` последнего прочитанного
  элемента; прочитанного с запуска нет — не толкает и не опрашивает, ждёт, журнал;
- **время кадра:** кадр несёт время съёмки `t` по часам камеры; одна линия времени ставится до любого читателя и
  переживает процесс; до NTP камера отказывает заявке раньше этой точки (`adrift`); кадры загрузки без поставленных
  часов в ответ не идут (`unplaced`); перевод на часы кластера — приёмник;
- **предзапись:** пока поток не нужен, камера держит последние `ring_seconds` = 60 с — сколько вмещает кольцо 32 МиБ (Н1.5), не больше; первая отправка после «толкай» начинается
  с них, помеченных; зритель получает только живой край;
- **звук** (ADR-0102 доп. (9) п. 7): камера шлёт кадры вида `audio` (V/02.9 Н1.3а, Н2) номеров из `audio` ответа опроса рядом с видео, `t` — той же линии; кольцо и карта держат оба вида, предзапись, продолжение по `have` и выгрузка заявки несут звук тех же времён; `have`, `hold_seconds`, `UPLINK_FREE` и срез судят видео: звук окно не держит; **предел:** строк детей у камеры-кластера нет (V/01.4 Н3), её `mic` выключить нечем;
- **заявка на архив:** в ответе опроса `{rid, from, to, recording, piece, audio?}` — камера читает карту и отдаёт кусками:
  `PIECE_BYTES` = 1 МиБ — тело обращения «выгрузка» целиком, с base64 кадров (предел двери `BODY`, V/02.9 Н2), с
  номером `seq` и пометкой `more`; пустая выгрузка без `more` — ответ целый; неподтверждённый кусок уходит снова под своим номером; карты нет или сегмент не дочитан — отказ, не пустота; кусок заявки уходит, только
  когда поток у живого края (`UPLINK_FREE` = 2 с);
- **обрыв продолжается:** ответ опроса несёт `have` — докуда записано; камера начинает с первого ключевого кадра после
  `have`: из кольца, затем с карты, затем живое; состояние двигается только после куска, который приёмник взял;
  продолжение идёт впереди живого края, назад не дальше `hold_seconds` = 30 с, не больше двух кусков за проход;
  отставание больше `2 × hold_seconds` — срез к ключевому кадру со счётом;
- **долг карте:** толкатель помнит, что приёмник взял и что привезла заявка, и говорит карте камеры, чего у сервера нет
  (`owed_spans`); как карта держит долг — V/02;
- **`taken_by`** в элементе `status[]` камеры (V/01.2 Н1.4) — список имён кластеров, которые сейчас забирают её поток;
  читатель читает список (иначе «неизвестно»);
- **просьба сценария** приходит ответом опроса и исполняется как просьба `cam` (V/01.4): `performed` или `refused` со
  словами;
- **три канала** — все открывает камера: проход агента (секунды — полминуты), долгий опрос (около секунды), поток
  (непрерывно).

### Н1.5 Камера как кластер из одного

Кластер из одного — коробка (камера) со всеми процессами, контроллером и агентом в процессе
([P/02.4 Н1.10, Н1.11](../../../Platform/02-installer/spec/02.4-installer.norms.md), [P/09.1 Н1.11](../../../Platform/09-agent/spec/09.1-agent.norms.md));
`cam` добавляет:
- строка `cam/cameras/1` с `source: cfw://local` (прошивка самой камеры, V/01.1 Н1.1), `ref` и `name` — серийный номер
  сознательно: это её имя для домена (правило «серийный номер кластер не покидает» — только об `identity` строки
  `devices`, V/01.1); её кладёт прошивка в `/etc/w2c/boot-rows.json`, консоль камеры при старте создаёт отсутствующую, штамп `by: boot`, строка есть — не трогает; файл не по форме — код 2, чтение не удалось — старт идёт, журнал, строка на следующей загрузке (P/02.4 Н1.10 `boot`);
- **в домене** (ADR-0110 доп. (3), (4) п. 2): признак камеры w2c — `source` строки, равный `cfw://local` байт в байт; поле идёт в `domain.view_tables` (Н1.1). Член, у которого из основных строк `cam/cameras` (пустой `main`) только эта, свёрнут: поток той же камеры сервера не делает; сервера нет, камера — запись `Device`, `serverId` — сервер приёмника, назначения нет — поля нет, группа «Без сервера» (V/11.3 Н1.3). Прошивка других строк не пишет: обычная строка камеры и поток с `main: 1` показывают член сервером;
- **карта** — строка тома `edge` в том же `boot-rows.json` (V/02.6 Н1.7): сервера, на котором оператор завёл бы том, у свёрнутого члена нет; том показывается записью `storage` (V/11.3 Н1.3);
- держатель — в процессе камеры; его пульс — слова V/01.2, V/01.5 и `taken_by`; эпоха — раз за загрузку (P/03.2 Н1.5);
- память кадров — 40 МиБ на камеру: кольцо 32 МиБ (окно 60 с, видео и звук) и два куска по 1 МиБ — камера; очередь к карте 6 МиБ — карта
  (урок V/02); толкатель своих кадров не держит — читает кольцо;
- **несколько камер:** кроме строки `cam/cameras/1` кластер из одного держит обычные строки камер своего сервера: держатель на камеру, эпоха и пульс — каждому, том `edge` один (Н1.7, V/02.6 Н1.7). Камера `cfw://local` на коробке одна; у прочих поток и ответ на заявку диапазона ведёт регистратор карты (V/02.9 Н1.2, V/02.6 Н1.7): он читает сегменты сам и выгружает протоколом камеры. **Предел:** память кадров растёт с числом камер, бюджет карты — нет;
- строка, эпоха, принесённое агентом и токен `stream` (Н1.3) — флеш; пульс и шард снимка — память (P/02.4 Н1.11): держатель пишет строку
  вклада только при изменении (Н1.2);
- двери камеры до первой публикации шарда отвечают 503 `not_ready`; копия `domain/grants` — в памяти, на флеш — при
  изменении содержимого и не чаще раза в час (решение запроса
  [кластер из одного](../../../decisions/inbox/2026-10-23-запрос-vms-кластер-из-одного.md); норма платформы — P/02.4 Н1.10,
  P/09.1 Н1.4).

### Н1.6 Что держатель читает из домена

`worker.reads` канона: `domain/rec/primaries`, `domain/placed/rec/`, `domain/rec/polls`, `domain/member-list`,
`domain/view`, `domain/member-topology`, `domain/topology` и решение лицензии — копия `domain/cam/licence`. У члена книга — копия по точному имени, у кластера — держателя домена копии нет
(запись `domain/holder` своего хранилища, основа роли P/02.5 Н1.4, проходит `record` и называет этот кластер; не прошла — признак не поднят, читаются копии, причина в журнал):
читается строка своего кластера `domain/<sub>/<книга>/<CLUSTER>` (права на неё воркеру выводит генератор прав по
`CLUSTER` установщика, P/02.5 Н1.4, C02-OWN-BOOK-HOLDER-01; манифест префикс не расширяет). Строки своего кластера ещё нет (окно после переноса, P/08.5 Н1.3 `contributes`) — книга не собрана, а не пуста: держится прочитанное последним с запуска; лицензия — только по главе 7 Н1.3:

| Копия | Зачем |
|---|---|
| `domain/rec/primaries` | адреса приёмников (`ingest`), `push`, роль записи — толкатель (Н1.4) |
| `domain/placed/rec/<ref>` | `to` элемента книги (`cluster` + `copies`); свой кластер — `origin` перед просьбой `stream` |
| `domain/rec/polls` | `urls` дома опроса для камеры, которую никто не пишет (`poll`) |
| `domain/member-list` | центр (`Entry.ca`) члена-адресата: толкатель проверяет сервер приёмника другого кластера как пира (P/03.4 Н1.7 `cross_cluster`) |
| `domain/member-topology` (у держателя домена — `domain/topology`) | дом опроса (Н1.2) |
| `domain/view` | `holds`: строка решения лицензии или копия (глава 7 Н1.3) |
| `domain/keys` (своя строка, основа роли P/02.5 Н1.4) | `current`: токен `stream` не под ним — просить заново (Н1.3) |
| `domain/cam/licence` (у держателя домена — `domain/cam/licence/<CLUSTER>`) | решение лицензии (глава 7 Н1.3) |

### Н1.7 Запись на карту сервера

Решение — ADR-0108 и его доп. (1). Том `edge` работает со всеми камерами своего сервера (V/02.6 Н1.7). Без строки записи у камеры нет единицы, эпохи, пульса с `coverage`, поэтому строку заказывает держатель: `worker.creates: [{sub: rec, rows: recordings, key: "{cam}-{home}"}]` — `rec/recordings/cam-<cam>-<том>` (P/03.6 Н1.6): по строке на карту, у камеры, сменившей сервер, их может быть две.

- **Кто и когда:** держатель камеры — основной строки `type: camera`, `live: always`, не `unlicensed` — читает `rec/volumes/*` с перечнем строк `rec` (V/01.2 Н1.2в). Есть включённый том `edge` с `server` = свой сервер (`SERVER_NAME`) и нет строки с этим домом — заказ; томов два — первый по имени байтами. Заказ один на строку.
- **Поля заказа:** `cam`, `ref` камеры (нет — поля нет), `home` — том, `when` — `when` тома, поля нет — по правилу V/02.6 Н1.7 на момент заказа; `until` нет, у записи 0. `t_E` — `now`.
- **Продления нет.** Повтор заказа пишет строку с `revision + 1` (P/03.6 Н3 шаг 4), новая `revision` перезапускает единицу (P/03.3), и кольцо записи теряется. Поэтому срока у строки нет, слово `when` регистратор карты берёт из тома.
- **Камера ушла на другой сервер.** Новый держатель сразу заказывает строку своей карты, эпоха — обычным правилом. Прежняя стоит `waiting` (V/02.6 Н1.7), её долг копируется; `near` камеры (V/01.1 Н1.3) может вернуть камеру к ней, пока строка жива. Снимает прежнюю строку регистратор карты: держатель не на сервере тома дольше `EDGE_UNTIL` = 7200 с и долга нет (V/02.6 Н1.7).
- **Том:** выключен, снят, нет на сервере — заказа нет, строку снимает регистратор (V/02.6 Н1.7). Строка `rec/volumes` или перечень не прочитаны — не прочитан, а не отсутствует: новых заказов нет, журнал.
- **Снять строку заказчик не может:** право роли на чужие строки — без удаления (P/02.5 Н1.4). Снимает держатель строки по `worker.deletes` манифеста `rec`.
- **Исходы** — `creates.<outcome>` пульса (P/03.4 Н1.1); строки нет — заказ на следующем чтении.
- **Выключить карту одной камере** можно только `enabled: false` в строке: дверь строку заказа не закрывает (P/06.1 Н1.1), заказ её не повторяет. Снятую оператором строку держатель заказывает снова.

## Н3 Проход

### Вклад (проход держателя)

```
для каждой камеры назначения (не unlicensed, глава 7): назначение domain/placed/rec/<ref> с origin = свой кластер →
  элемент «размещена» (Н1.2); назначения нет, enabled, ref, push → элемент «опрос»; иначе — нет элемента;
  запись назначения или топология не прочитаны → прежний элемент, журнал
поле без значения — опустить
собранный список ≠ строке cam/sources/<слот> → записать строку целиком (as_of — только у изменённых элементов)
```

### Заказ записи на карту (Н1.7)

```
с перечнем строк rec:
том edge своего сервера включён → нет строки cam-<cam>-<том> → заказ {cam, ref?, home, when}
                                   строка есть → заказа нет
тома нет → заказа нет; том не прочитан → заказа нет, журнал
```

### Толкнуть (камера с push, камера-кластер)

```
опрос приёмника (адрес — primaries, ключ — stream | poll) → ответ: желание, have, заявки, просьбы
желание есть → поток с предзаписи или продолжение от have (Н1.4); иначе — держать кольцо
заявка → куски по 1 МиБ, когда поток у живого края; неподтверждённый — тем же seq
просьба → V/01.4; ответ в следующем опросе
нет ответа ни от одного приёмника основного → резерв или не толкать; токен истекает, назначение сменилось, kid не current → новый токен (Н1.3)
```

**Гонки.** Два кластера заявили одну камеру (`ref`) — `conflicts` книги, ключа нет нигде; оператор разводит. Назначение
сменилось, пока поток идёт — старый токен отвергнут приёмником (`wrong_audience`), толкатель перепрашивает. Новый держатель
слота чистит строку под слотом — элементы прежнего уходят до первой записи нового.
