# V/01.1 — Камера — единица: нормы

Канон главы 1 урока V/01 «Камера» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../01-cam.md),
[инструкция](01-cam.README.md), [приёмка](../acceptance/1/README.md), манифест [`cam.subsystem.yaml`](../cam.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `e0b19be` (потоки камеры, Н1.1а, — `41d3ec8`; разбор ревью потоков — `b41527f`); ссылки `P/…` ведут в её `Platform/`
(раскладка курса, ADR-0090 п. 2).

Глава нормирует то, что подсистема `cam` объявляет о камере: поля оператора и их смысл, адрес устройства и учётные
данные, таблицу `devices`, значения размещения, снимок, права людей, слова консоли и подавление событий. Как платформа
исполняет каждое объявление — нормы платформы по ссылке; глава их не повторяет. Держатель камеры — [глава 2](01.2-cam.norms.md),
команды и строка `devices` со стороны писателя — глава 4, архив устройства — глава 5, раздел `domain:` — глава 6.

Id норм — `V/01.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у главы нет.

**Данные** (общие семьи `<sub>/…` [каталога платформы](../../../Platform/common/data/catalog.tsv); своих ключей сверх них у главы нет — [каталог VMS](../../common/data/catalog.tsv)): пишет оператор дверью единиц — `cam/cameras/<id>`,
`cam/next_id` (P/06.1 Н1.1, Н1.3); пишет держатель — `cam/devices/<хост>` (Н1.2; сторона писателя — глава 4); общие
сроки `cam/retention`, `cam/alarms_retention` — [P/05 Н1.3](../../../Platform/05-resource/spec/05-resource.norms.md)
(ADR-0076; срок видео — урок V/02).

### Н1.1 Камера

Единица подсистемы `cam` — **поток** канала устройства, который держит один воркер `camworker`: строка `cam/cameras/<id>`,
`unit.id: numeric` — id выдаёт дверь единиц по счётчику `cam/next_id` (P/06.1 Н1.3; id в теле `POST` — отказ P/06.1).
**Камера** — её основной поток (`main` пуст); прочие потоки камеры — Н1.1а. Устройство без картинки (вход, реле) — тоже
камера, `kind: io`, без прочих потоков.

| Поле | Тип и объявление | Смысл | Кто читает |
|---|---|---|---|
| `name` | `string`, `cam{id}` | имя камеры для людей; без имени — `cam<id>` | консоль, снимок, страница |
| `main` | `string`, `fixed` | id основного потока камеры; пусто — строка и есть камера (Н1.1а); `about` манифеста | держатель (глава 2), гранты, журнал (`of`) |
| `profile` | `string`, `main` | имя потока, любое слово оператора | страница (V/08), снимок |
| `grid`, `full` | `string` | у камеры: потоки живого видео для сетки и полного экрана — id прочих потоков этой камеры; пусто — основной; что поток — этой камеры, дверь не сверяет (Н1.1а) | страница, `live` (V/03.1) |
| `source` | `url`, `required`, `unique: canonical`, `schemes`, `credentials`, `secret_in` | адрес канала устройства; ключ устройства для `group_by` (Н1.3) | держатель (глава 2), дверь (P/06.1, P/06.2) |
| `enabled` | `bool`, `true` | держатель держит только включённую камеру | держатель |
| `priority` | `int`, `100` | слово оператора о порядке камер; размещение и держатель его не читают | снимок, консоль |
| `labels` | `list` | сети, из которых виден адрес камеры (`vlan:cctv-a`) | размещение (`constraint`, Н1.3) |
| `folders` | `list` | папки дерева консоли через `/`; на размещение не влияют; без наследования | страница (V/08) |
| `alarms` | `list`, `inherit: []`, `merge: union` | виды событий, которые на этом устройстве — тревога | держатель: класс строки события (глава 2); наследование и слияние — [P/06.7 Н1.14](../../../Platform/06-console/spec/06.7-console.norms.md) |
| `ref` | `string`, `unique: true` | имя камеры для слоя выше (домена); пустой `ref` в `unique` не участвует ([договор проверки строки](../../../Platform/common/contracts/row-check.md) RC-17) | раздел `domain:` (глава 6) |
| `cred_username` | `string` | логин устройства | держатель |
| `cred_secret` | `string`, `bound_to: [source]` | пароль устройства — секрет | держатель (P/03.5) |
| `live` | `string`, `enum: [always, on-demand]`, `always` | держать поток всегда или по требованию | держатель (глава 2) |
| `kind` | `string`, `video` | `video` — устройство с картинкой; `io` — без неё | держатель (глава 2) |

### Н1.1а Потоки камеры

Решение владельца 2026-10-26 (задел «Камера с профилями», пп. 1, 3 (Б)): потоков у камеры сколько угодно, каждый — своя
единица `cam`; механизмов платформы сверх объявленных это не требует.

- **Камера = основной поток.** Строка с пустым `main`. Общее для камеры — `name`, `labels`, `folders`, `alarms`, `ref`,
  `priority`, `kind`, `grid`, `full`, команды устройства (глава 4), события устройства и тревоги (глава 2 Н1.5) — **только**
  в ней: правка общего — одна запись.
- **Пароль — у камеры.** `cred_username`, `cred_secret` строки камеры; прочий поток на том же хосте берёт их у своей
  камеры (глава 2 Н1.2). Каналы одного устройства (регистратор на 16 каналов) — разные камеры, пароль у каждой: смена
  пароля устройства — запись в каждую камеру. Это принятая цена: строка `devices` — находка держателя, оператор её не
  пишет (Н1.2), и пароля «один раз в строке устройства» у `cam` нет.
- **Прочий поток** — строка с `main: <id камеры>`: свои `source`, `profile`, `enabled`, `live`. Поток на ином хосте, чем
  камера (транскодер, другой адрес того же устройства), — со своими `cred_*` открывается, без них — нет: пароль камеры
  чужому хосту не отдаётся (глава 2 Н1.2).
- **Общих полей у прочего потока нет.** Их читает платформа, а не только VMS: `ref` — снимок, домен
  ([P/08.1](../../../Platform/08-domain/spec/08.1-domain.norms.md) Н1.2) и счёт лицензии (глава 7); `labels` — размещение
  (`labels-subset`, Н1.3); `name`, `priority` — снимок; `folders` — дерево модуля. Поэтому у строки с непустым `main`
  общее поле — только умолчание (`name` — `cam{id}`, `priority` — `100`, `kind` — `video`, прочие — пусто). Запретить
  поле при непустом `main` дверью диалект манифеста не может (условного запрета поля у `unit.fields` нет, P/02.1 Н1.2а) —
  запрос VMS после стадии C ([список](../../../decisions/inbox/2026-10-26-запрос-vms-потоки-камеры.md) п. 4). До правила двери:
  - держатель поток с общим полем не держит: `pending`, `reason` `stream: carries <поле>` (глава 2 Н1.1);
  - счёт лицензии строку с непустым `main` не считает (глава 7 Н1.2; `main` — в `domain.view`, глава 6 Н1.1);
  - домен видит строку по её `ref`, как любую (правило платформы P/08.1 Н1.2), поэтому страница общих полей потоку не
    даёт (V/08.1 Н1.5); прямой `POST`/`PUT` двери с ними принимается — это ограничение урока до правила двери.
- **`about: {sub: cam, field: main}`** — поток про свою камеру: грант `unit:cam/<камера>` и `labels:L` (метки камеры)
  покрывают все её потоки ([договор права](../../../Platform/common/contracts/may.md) шаг 7; [договор сторожевой и
  передачи](../../../Platform/common/contracts/gate-and-pass.md) `scope`), строки событий потока — `of: cam/<камера>`
  ([договор журнала событий](../../../Platform/common/contracts/event-journal.md) шаг 2). Загрузчик `about` на свою же
  подсистему допускает (P/02.1: `about.sub` — грамматика имени; ребром порядка установки `about` не является).
- **У камеры `about` нет:** `main` пуст — единица без `about`, судится по себе. Это **допущение VMS**: о пустом значении
  поля `about` нормы платформы не говорят — запрос VMS после стадии C ([список](../../../decisions/inbox/2026-10-26-запрос-vms-потоки-камеры.md) п. 1).
- **Поток выбирают запись, детектор и живое видео** — пользователь, в форме из потоков камеры; страница только
  подсказывает (самый крупный — запись, самый мелкий — сетка: `size` пульса держателя, глава 2 Н1.4):
  - запись `rec` и детектор `det` называют камеру (`cam`, их `about`) и поток — `stream: {ref: cam/cameras, must_match:
    {main: cam}}`: id прочего потока этой камеры, пусто — основной; поток другой камеры — 409 `must_match`; id самой
    камеры — тоже 409 (у камеры `main` пуст, а пустое значение цели не равно ничему — [договор проверки
    строки](../../../Platform/common/contracts/row-check.md)): основной поток называется только пустым `stream`
    (V/02.1, V/04.1);
  - раздача `live` — так же `cam` и `stream`; имя её строки составное — `<cam>` у основного потока, `<cam>.<stream>` у
    прочего (V/03.1 Н1.1); какой поток смотреть в сетке и на полном экране — `grid`, `full` камеры (id прочего потока,
    пусто — основной);
  - `about` потребителя — на камеру, не на поток: `about` платформы одноуровневый, и `about` на поток не дал бы гранту
    на камеру записей и детекторов прочего потока.
- **Задача скана** (`detjob`) своего выбора не имеет: её поток — поток записи `rec`, которую она читает (V/05.1 Н1.1).
- **Обход архива устройства** (`detedge`) потока не имеет: архив устройства — у камеры (V/01.5 Н1.1а; V/06.1 Н1.2).
- **`cam` потребителя — камера.** Что строка `cam/cameras/<cam>` — камера (`main` пуст), дверь не сверяет: `must_match`
  требует равенства поля цели полю строки, а «поле цели пусто» диалект не выражает — запрос VMS после стадии C (список
  п. 6). До него регистратор, шлюз и детектор такую строку не берут: `waiting`, `reason` `cam <cam> is a stream of <main>`
  (V/02.4, V/03.2, V/04.2); задача скана и обход — следом: у записи такой камеры нет архива (V/05.2), у потока нет архива
  устройства (V/06.2) — их прежние `reason`.
- **`grid`, `full`** — тоже без проверки двери (поле своей же строки `must_match` не называет): поток не этой камеры
  шлюз не раздаёт (V/03.2 Н1.1), страница предлагает только потоки камеры.
- **Держатель потока** — пока держатель всех каналов устройства (`group_by`, Н1.3): одно соединение с устройством.
  Держатель потока у своего потребителя (вариант (Б) задела) требует группы на нескольких держателях с пределом сессий
  устройства — механизма P/04 нет, запрос VMS после стадии C (список п. 3).
- **Дерево консоли.** Модуль вкладывает единицы подсистемы с `about` под единицы родителя; `about` на свою подсистему
  там не определён — запрос VMS после стадии C (список п. 2); до него оболочка подписывает поток его камерой и
  показывает потоки во вкладке «Потоки» камеры (V/08.1 Н1.5).

**Имя по умолчанию.** `cam{id}`: дверь подставляет выданный id при создании, правка значение не пересчитывает
([P/02.1 Н1.3](../../../Platform/02-installer/spec/02.1-installer.norms.md), [договор проверки строки](../../../Platform/common/contracts/row-check.md) «Подготовка полей» шаг 3).

**Адрес и учётные данные.** Один канал — одна камера: двух живых камер с одним адресом в каноническом написании
RFC 3986 нет (`unique: canonical`, договор проверки строки «Идентификатор и ограничения полей», ADR-0057). Два написания, которые канон не различает (`…/ch/02` и
`…/ch/2`), находит держатель: второе — «устройство занято» в его пульсе (глава 2). Логин и пароль в адресе не живут:
`source` с ними — отказ двери, они идут в `cred_username` и `cred_secret` (`credentials`); где в адресе камеры логин и
пароль — правила `schemes` и `secret_in` манифеста по [договор адреса](../../../Platform/common/contracts/url-credentials.md) («Схемы», «Адрес: где в нём логин и пароль»; владелец —
P/06.2 Н1.1а); отказ (`bad_url`) и маска — там же. Схемы `cam`:

| Схема | Где хост | Смысл |
|---|---|---|
| `driverpack` | первый сегмент пути (`host: path`); узел `file` — без хоста (`none`) | устройство через DriverPack; `driverpack://file/<имя>` — файл как камера (глава 3) |
| `ipint` | по RFC 3986; фрагмента нет (`#` — знак) | адрес продукта |
| `rtsp`, `rtsps`, `http`, `https` | по RFC 3986 | прямой адрес устройства |
| `cfw` | узел `local` — без хоста (`none`); `cfw://local:80` — хост `local` | прошивка самой камеры (камера как кластер из одного, глава 6); строку пишет только она |

Узел `none` сравнивается как записан, с портом и userinfo, хост в нём — нижним регистром (договор адреса «Схемы»
`node`): `driverpack://FILE/x` — файл, `driverpack://file:1/x` — не файл; держатель читает узел так же (глава 3).

Смена `source` без нового `cred_secret` — отказ `bound_to` (P/06.2 Н1.1): пароль относится к адресу.

### Н1.2 Таблица `devices`

`tables.devices` — что устройство за каналами камер оказалось: строка `cam/devices/<хост>`, ключ `device` — хост,
которым устройство называют адреса его каналов (тот же, что `group_by`, Н1.3). Пишет держатель группы (`worker.writes:
[devices]`; сторона писателя — глава 4); дверь консоли строку отдаёт, запись оператором — отказ
([P/06.1 Н1.6](../../../Platform/06-console/spec/06.1-console.norms.md)); удаление оператором — `DELETE` с cas → 200, держатель
пишет строку заново, если её хост ещё в его группах (P/06.1 Н1.6).

| Поле | Тип | Смысл |
|---|---|---|
| `device` | `string`, обязательное | хост устройства |
| `events` | `list` | виды событий, которые поднимают его каналы |
| `rays` | `int`, `0` | входы (контакты) — `io.input` с портом |
| `relays` | `int`, `0` | выходы, которые можно попросить переключить (`output`, глава 4) |
| `ptz` | `bool`, `false` | устройство поворачивается |
| `presets` | `int`, `0` | позиции, в которые можно попросить перейти (`preset`, глава 4) |
| `identity` | `string`, не длиннее 200 | серийный номер, MAC — не возможность; кластер не покидает (не в снимке, не в домене) |

Строка — находка держателя, не решение оператора: читают её форма сценариев (`auto`, урок V/07) и страница.

### Н1.3 Размещение

Ключи и их смысл — [P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md); `cam` объявляет:

| Ключ | Значение | Почему |
|---|---|---|
| `capacity` | `{from: capacity, default: 50, unit_mb: 1, base_mb: 18}` | слово воркера в пульсе; бюджет памяти — глава 2 |
| `headroom` | `{from: headroom}` | запас из пульса |
| `constraint` | `labels-subset` | метки камеры ⊆ метки сервера держателя: адрес виден только из своих сетей |
| `group_by` | `{field: source, cut_at: host}` | все каналы одного устройства — у одного держателя: одно соединение с устройством, одна линия вопросов и команд (глава 4); группа и хост в одном написании — [договор группы по хосту](../../../Platform/common/contracts/group-of.md) |
| `requires` | `resource` | держатель пишет события в ресурс своего сервера |
| `tie_break` | `most-free-capacity` | — |
| `grows` | `true` | воркеров по заказу (P/04 Н3 «нехватка()», P/02.4 Н1.5); запасных нет (ADR-0084) |
| `near` | `{sub: rec, of: cam, prefer: {home.kind: [backup, edge], home.enabled: true}}` | держатель — рядом с регистратором своей камеры, первым — с тем, чья запись на резервном томе или карте (урок V/02): резервная пишет поток с коробки, а не через сеть ([P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md) `near`, ADR-0091 п. 10) |
| `home` | `near` | дом держится: контроллер возвращает камеру к якорю |
| `rebalance` | `{dead_band: 0.10}` | — |

### Н1.4 Снимок

`snapshot: [name, source, enabled, priority, labels, ref, live, main, profile]` — `main` и `profile` отличают поток от
камеры для читателя снимка (домен знает камеру по `ref`; у потока `ref` пуст — Н1.1а, и в виде домена его нет); форма и маска адреса —
[P/04 Н1.3а](../../../Platform/04-controller/spec/04-controller.norms.md). Не в снимке: `cred_*` (секрет и логин — читателя
снимка нет), `folders` (только дерево консоли), `alarms`, `kind` (читает держатель из строки). Снимок уходит из кластера
(домен, P/08.1); `identity` таблицы `devices` в нём не бывает.

### Н1.5 Права людей

`rights.reach` ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md) «Права по телу»; владелец — [P/06.3 Н1.5](../../../Platform/06-console/spec/06.3-console.norms.md)):
- `group: [source, labels]` — правка адреса или меток задевает все камеры устройства, которое камера покидает, и того,
  к которому переходит: перенос канала — действие над устройством;
- `cluster: [ref]` — имя камеры для домена меняет грант на кластер;
- создание потока — как любой строки `cam`: `admin` на `*` (строку единицы без `rights.routes` создаёт грант на кластер,
  договор сторожевой и передачи «строки единиц»); правка — `admin` на поток или его камеру (по `about`), смена `source`
  или `labels` — ещё на все камеры старой и новой группы устройства (`reach.group`); грант на камеру покрывает её потоки
  по `about` (Н1.1а);
- `requests: [output, preset]` — команда устройству требует `edit` на всю группу (глава 4).

### Н1.6 Слова консоли и подавление событий

## Н3 Проход

### Запись камеры (дверь единиц P/06.1)

Порядок проверок и исходы — P/06.1 Н3 «создать», «править», договор проверки строки «Порядок проверок» и договор адреса
«прочитать_адрес»; объявления этой главы
дают им значения:

```
тело → поля Н1.1 (лишнее поле, id в POST — отказ P/06.1)
source: нет → 400 required; схема не из schemes → 400; логин или пароль в адресе по schemes/secret_in → 400 с
        словом credentials (cred_username | cred_secret); каноническое написание есть у живой камеры → 409 unique
cred_secret: смена source без нового cred_secret → 400 bound_to; значение запечатывается (P/06.2)
live: вне enum → 400
права: reach.group — по камерам старой и новой группы source/labels; reach.cluster — по ref (договор сторожевой и передачи «Права по телу»)
main: правка иным значением → 400 «main is fixed» (P/06.1 Н4); что main называет камеру — не дверь, держатель (глава 2)
```

**Гонки.** Две записи с одним адресом одновременно: предварительная проверка `unique` у двери не атомарна с записью
(договор проверки строки); второе написание, проскочившее проверку, держатель находит как «устройство занято» (глава 2) — двух
соединений с одним каналом нет.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| нет `source` | 400 (P/06.1) | ответ двери | указать адрес |
| логин или пароль в `source` | 400 `fault: bad_url`, `error` с именами полей `credentials` (P/06.2 Н4) | ответ без значения | перенести в `cred_username`/`cred_secret` |
| схема не из `schemes` | 400 `bad_url` (P/06.1 Н4; договор адреса «Схемы») | ответ | — |
| адрес уже у живой камеры | 409 `conflict`, `fault: unique` (P/06.1 Н4) | ответ | другой канал или правка той камеры |
| смена `source` без `cred_secret` | 400 «source changed: cred_secret must be given anew» (P/06.2 Н4) | ответ | вписать пароль заново |
| правка `main` потока | 400 «main is fixed» (P/06.1 Н4) | ответ | поток другой камеры — новая строка |
| `POST` строки `devices` | 403 `denied` «written by its worker»; `PUT` — 405 (P/06.1 Н1.6) | ответ | строку пишет держатель |
