# V/01.1 — Камера — единица: нормы

Канон главы 1 урока V/01 «Камера» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../01-cam.md),
[инструкция](01-cam.README.md), [приёмка](../acceptance/1/README.md), манифест [`cam.subsystem.yaml`](../cam.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `f5b33e19` (потоки камеры, Н1.1а, — `41d3ec8`; разбор ревью потоков — `b41527f`; форма манифеста стандартом — `fbe9e93`); ссылки `P/…` ведут в её `Platform/`
(раскладка курса, ADR-0090 п. 2).

Глава нормирует то, что подсистема `cam` объявляет о камере: поля оператора и их смысл, адрес устройства и учётные
данные, таблицу `devices`, значения размещения, снимок, права людей, слова консоли и подавление событий. Как платформа
исполняет каждое объявление — нормы платформы по ссылке; глава их не повторяет. Держатель камеры — [глава 2](01.2-cam.norms.md),
команды и строка `devices` со стороны писателя — глава 4, архив устройства — глава 5, раздел `domain:` — глава 6.

Id норм — `V/01.1-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Полей времени у главы нет.

**Данные** (общие семьи `<sub>/…` [каталога платформы](../../../Platform/common/data/catalog.tsv); своих ключей сверх них у главы нет — [каталог VMS](../../common/data/catalog.tsv)): пишет оператор дверью единиц — `cam/cameras/<id>`,
`cam/next_id` (P/06.1 Н1.1, Н1.3), `cam/child_settings/<id>` (Н1.2а), `cam/device_units/<id>`, `cam/unit_next/<строка>` (Н1.2б), `cam/preset_labels/<camera>-<n>` дверью таблиц; пишет держатель — `cam/devices/<хост>`, `cam/children/<id>`, `cam/rule_state/<id>` (Н1.2, Н1.2а, Н1.2в; сторона писателя — глава 4); общие
сроки `cam/retention`, `cam/alarms_retention` — [P/05 Н1.3](../../../Platform/05-resource/spec/05-resource.norms.md)
(ADR-0076; срок видео — урок V/02).

### Н1.1 Камера

Единица подсистемы `cam` — **поток** канала устройства, который держит один воркер `camworker`: строка `cam/cameras/<id>`,
`unit.id: numeric` — id выдаёт дверь единиц по счётчику `cam/next_id` (P/06.1 Н1.3; id в теле `POST` — отказ P/06.1); в пакете `POST /console/batch` номер называет вызывающий вместе со строкой счётчика (P/06.1 Н2 «Пакетная дверь»; V/11.4 Н1.2).
**Камера** — её основной поток (`main` пуст); прочие потоки камеры — Н1.1а. Строка — не только камера: что она такое,
говорит `type` (Н1.1б).

| Поле | Тип и объявление | Смысл | Кто читает |
|---|---|---|---|
| `name` | `string`, `cam{id}` | имя камеры для людей; без имени — `cam<id>` | консоль, снимок, страница |
| `main` | `string`, `fixed`, `ref: cam/cameras`, `must_match: {type: type}` | id основного потока камеры; пусто — строка и есть камера (Н1.1а); `about` манифеста | держатель (глава 2), гранты, журнал (`of`) |
| `profile` | `string`, `main` | имя потока, любое слово оператора | страница (V/08), снимок |
| `source` | `url`, `required`, `unique: canonical`, `schemes`, `credentials`, `secret_in` | адрес канала устройства; ключ устройства для `group_by` (Н1.3) | держатель (глава 2), дверь (P/06.1, P/06.2) |
| `enabled` | `bool`, `true` | держатель держит только включённую камеру | держатель |
| `priority` | `int`, `100` | слово оператора о порядке камер; размещение и держатель его не читают | снимок, консоль |
| `labels` | `list` | сети, из которых виден адрес камеры (`vlan:cctv-a`) | размещение (`constraint`, Н1.3) |
| `alarms` | `list`, `inherit: []`, `merge: union` | виды событий, которые на этом устройстве — тревога | держатель: класс строки события (глава 2); наследование и слияние — [P/06.7 Н1.14](../../../Platform/06-console/spec/06.7-console.norms.md) |
| `ref` | `string`, `unique: true` | имя камеры для слоя выше (домена); пустой `ref` в `unique` не участвует ([договор проверки строки](../../../Platform/common/contracts/row-check.md) RC-17) | раздел `domain:` (глава 6) |
| `cred_username` | `string` | логин устройства | держатель |
| `cred_secret` | `string`, `bound_to: [source]` | пароль устройства — секрет | держатель (P/03.5) |
| `live` | `string`, `enum: [always, on-demand]`, `always` | `always` — держать поток; `on-demand` — поток не открывать, держать только устройство | держатель (глава 2) |
| `type` | `string`, `enum: [camera, ipsrv, eventsrc, acfa]`, `camera`, `fixed` | вид строки (Н1.1б); иное слово — отказ двери по `enum`, правка — `fixed` (P/06.1 Н4) | держатель (глава 2), `backend` (V/11), страница |
| `lat`, `lon`, `azimuth` | `json`, число или `null` | где стоит и куда смотрит: у камеры и строки `ipsrv`; `null` — не сказано, `0` — значение; дверь судит только форму | `backend`, страница; держатель не читает |
| `short` | `string` | номер для показа в дереве, слово для людей | `backend`, страница; держатель не читает |
| `mac` | `string` | MAC-адрес строки `ipsrv`, слово оператора; `identity` устройства он не заменяет. У камеры MAC — только из поиска, в строке не хранится | `backend`; держатель не читает |
| `camera` | `string`, `ref: cam/cameras` | у `eventsrc`: id камеры, над чьим видео идут строки (Н1.1г) | держатель, страница (V/08.3), `backend` |
| `words` | `json`, список `{msg, color?, bg?}` | у `eventsrc`: слова, которые ищет держатель, и их цвета (Н1.1г) | держатель, страница, `backend` |
| `overlay_delay_ms`, `overlay_duration_sec` | `int` ≥ 0 | у `eventsrc`: задержка показа строки, мс, и сколько её держать, с; `0` — до следующей строки | страница, `backend`; держатель не читает |
| `resolution` | `string`, `schema`: пусто или `<ширина>x<высота>` | настройка устройства для этого потока: держатель передаёт драйверу (глава 2 Н1.2а); пусто — настройка не трогается; список вариантов — `resolutions` (Н1.2) | держатель, `live` (V/03.3), `backend` |
| `fps` | `int` ≥ 0 | кадров в секунду, настройка устройства, как `resolution`; `0` — не трогается | держатель, `backend` |

Логин строки `ipsrv` — её `cred_username`. Пишет эти поля оператор дверью единиц; значение не по форме в хранилище — не прочитано, а
не отсутствует: умолчанием его не подменяют, читатель поля не отдаёт, держатель — глава 2 Н1.2а.

Камера `live: always` без потребителя держит устройство без потока (`idle`, глава 2 Н1.2в): поток открывается по потребителю. Камера `live: on-demand` держит устройство без потока (`held`, глава 2), и будить её некому: зритель получает `camera <поток>
is not running` (V/03.2 Н1.4), читатели потока — детектор (V/04.2), запись (V/02.4) — спроса не создают и ждут (`waiting`).
Пробуждение — вторая очередь, отдельным решением, если понадобится.

### Н1.1а Потоки камеры

Решение владельца 2026-10-26 (задел «Камера с профилями», пп. 1, 3 (Б)): потоков у камеры сколько угодно, каждый — своя
единица `cam`; механизмов платформы сверх объявленных это не требует.

- **Камера = основной поток.** Строка с пустым `main`. Общее для камеры — `name`, `labels`, `alarms`, `ref`,
  `priority`, `lat`, `lon`, `azimuth`, `short`, команды устройства (глава 4), события устройства и тревоги (глава 2 Н1.5) — **только**
  в ней: правка общего — одна запись.
- **Пароль — у камеры.** `cred_username`, `cred_secret` строки камеры; прочий поток на том же хосте берёт их у своей
  камеры (глава 2 Н1.2). Каналы одного устройства (регистратор на 16 каналов) — разные камеры, пароль у каждой: смена
  пароля устройства — запись в каждую камеру. Это принятая цена: строка `devices` — находка держателя, оператор её не
  пишет (Н1.2), и пароля «один раз в строке устройства» у `cam` нет.
- **Прочий поток** — строка с `main: <id камеры>`: свои `source`, `profile`, `enabled`, `live`, `resolution`, `fps`; `type` — всегда
  `camera` (Н1.1б). Поток на ином хосте, чем
  камера (транскодер, другой адрес того же устройства), — со своими `cred_*` открывается, без них — нет: пароль камеры
  чужому хосту не отдаётся (глава 2 Н1.2).
- **Общие поля прочего потока инертны.** Форма модуля (`display.form`, одна на единицу `cam`) даёт их и потоку, дверь их
  принимает; VMS у потока их не читает и поток из-за них не гасит:
  - держатель берёт общее со строки камеры (глава 2 Н1.1); класс событий, лицензия — по камере;
  - счёт лицензии строку с непустым `main` не считает (глава 7 Н1.2; `main` — в `domain.view`, глава 6 Н1.1); вклад книги
    источников и толкание — только камеры (глава 6 Н1.1);
  - что читает платформа, то и действует, как у любой единицы: `labels` потока — ограничение размещения (`labels-subset`,
    Н1.3; группа устройства размещается целиком, P/04 Н1.3 `group_by`); `ref` — имя единицы в виде домена
    ([P/08.1](../../../Platform/08-domain/spec/08.1-domain.norms.md) Н1.2): поток с `ref` виден там единицей, без лицензии и
    книги; `name`, `priority` — снимок и дерево модуля, слова;
  - вкладка «Потоки» общих полей потоку не предлагает (V/08.1 Н1.5).
- **`about: {sub: cam, field: main}`** — поток про свою камеру: грант `unit:cam/<камера>` и `labels:L` (метки камеры)
  покрывают все её потоки ([договор права](../../../Platform/common/contracts/may.md) шаги 7, 7а; [договор сторожевой и
  передачи](../../../Platform/common/contracts/gate-and-pass.md) `scope`), строки событий потока — `of: cam/<камера>`
  ([договор журнала событий](../../../Platform/common/contracts/event-journal.md) шаг 2). Загрузчик `about` на свою же
  подсистему допускает (P/02.1: `about.sub` — грамматика имени; ребром порядка установки `about` не является).
- **У камеры `about` нет:** `main` пуст — единица без `about`, судится по себе, строки её событий — `of: cam/<id>`
  ([договор журнала событий](../../../Platform/common/contracts/event-journal.md) шаг 2: при пустом значении поля — сама единица).
- **Поток выбирают запись и детектор** — пользователь, в форме из потоков камеры; страница только
  подсказывает (самый крупный — запись: `size` пульса держателя, глава 2 Н1.4). Живое видео выбирает `live` по окну зрителя:
  - запись `rec` и детектор `det` называют камеру (`cam`, их `about`) и поток — `stream: {ref: cam/cameras, must_match:
    {main: cam}}`: id прочего потока этой камеры, пусто — основной; поток другой камеры — 409 `must_match`; id самой
    камеры — тоже 409 (у камеры `main` пуст, а пустое значение цели не равно ничему — [договор проверки
    строки](../../../Platform/common/contracts/row-check.md)): основной поток называется только пустым `stream`
    (V/02.1, V/04.1);
  - раздача `live` — строка по камере (`live/streams/<cam>`, V/03.1 Н1.1); поток зритель называет на двери шлюза
    (`?stream=<id>`, V/03.3 Н1.2), шлюз раздаёт только поток этой камеры; не назвал — поток выбирает `live` по размеру из
    запроса (`resolution` строки, иначе `size` пульса; ADR-0104 п. 2);
  - `about` потребителя — на камеру, не на поток: `about` платформы одноуровневый, и `about` на поток не дал бы гранту
    на камеру записей и детекторов прочего потока.
- **Задача скана** (`detjob`) своего выбора не имеет: её поток — поток записи `rec`, которую она читает (V/05.1 Н1.1).
- **Обход архива устройства** (`detedge`) потока не имеет: архив устройства — у камеры (V/01.5 Н1.1а; V/06.1 Н1.2).
- **`cam` потребителя — камера.** Что строка `cam/cameras/<cam>` — камера (`main` пуст), дверь не сверяет: `must_match`
  требует равенства поля цели полю строки ([договор проверки строки](../../../Platform/common/contracts/row-check.md)
  `ref_and_must_match`), а «поле цели пусто» манифест не выражает: связи CEL формы (P/02.1 Н1.4, `relations.json`) —
  правила загрузчика над текстом манифеста, не проверка строки на двери — запрос VMS после стадии C (список п. 4).
  До него регистратор, шлюз и детектор такую строку не берут: `waiting`, `reason` `cam <cam> is a stream of <main>`
  (V/02.4, V/03.2, V/04.2); задача скана и обход — следом: у записи такой камеры нет архива (V/05.2), у потока нет архива
  устройства (V/06.2) — их прежние `reason`.
- **Держатель потока** — пока держатель всех каналов устройства (`group_by`, Н1.3): одно соединение с устройством.
  Держатель потока у своего потребителя (вариант (Б) задела) требует группы на нескольких держателях с пределом сессий
  устройства — механизма P/04 нет, запрос VMS после стадии C (список п. 3).
- **Дерево консоли.** Модуль вкладывает единицы подсистемы с `about` под единицы родителя; `about` на свою подсистему
  там не определён — запрос VMS после стадии C (список п. 2); до него оболочка подписывает поток его камерой и
  показывает потоки во вкладке «Потоки» камеры (V/08.1 Н1.5).

**Имя по умолчанию.** `cam{id}`: дверь подставляет выданный id при создании, правка значение не пересчитывает
([P/02.1 Н1.3](../../../Platform/02-installer/spec/02.1-installer.norms.md), [договор проверки строки](../../../Platform/common/contracts/row-check.md) «Подготовка полей» шаг 3).

**Адрес и учётные данные.** Один канал — одна камера: двух живых камер с одним адресом в каноническом написании
RFC 3986 нет (`unique: canonical`, договор проверки строки «Идентификатор и ограничения полей», ADR-0057; порт по умолчанию
канон не снимает). Написания, которые канон различает, а канал у них один — `rtsp://h/ch/1` и `rtsp://h:554/ch/1`, —
находит держатель: второе — «устройство занято» в его пульсе (глава 2 Н1.2 «Тот же канал»). Логин и пароль в адресе не живут:
`source` с ними — отказ двери, они идут в `cred_username` и `cred_secret` (`credentials`); где в адресе камеры логин и
пароль — правила `schemes` и `secret_in` манифеста по [договор адреса](../../../Platform/common/contracts/url-credentials.md) («Схемы», «Адрес: где в нём логин и пароль»; владелец —
P/06.2 Н1.1а); отказ (`bad_url`) и маска — там же. Схемы `cam`:

| Схема | Где хост | Смысл |
|---|---|---|
| `driverpack` | первый сегмент пути (`host: path`); узел `file` — без хоста (`none`) | устройство через DriverPack; `driverpack://file/<имя>` — файл как камера (глава 3) |
| `ipint` | по RFC 3986; фрагмента нет (`#` — знак) | адрес продукта |
| `rtsp`, `rtsps`, `http`, `https` | по RFC 3986 | прямой адрес устройства |
| `cfw` | узел `local` — без хоста (`none`); `cfw://local:80` — хост `local` | прошивка самой камеры (камера как кластер из одного, глава 6); строку пишет только она; `cfw://local` байт в байт — признак камеры w2c в домене (глава 6 Н1.5) |

Узел `none` сравнивается как записан, с портом и userinfo, хост в нём — нижним регистром (договор адреса «Схемы»
`node`): `driverpack://FILE/x` — файл, `driverpack://file:1/x` — не файл; держатель читает узел так же (глава 3).

Смена `source` без нового `cred_secret` — отказ `refused` по `bound_to` (P/06.2 Н1.1): пароль относится к адресу.

### Н1.1б Вид строки

`type` равен `Device.type` контракта consolem, перевода слова нет. Задаётся при создании и не меняется: строка не становится
другой вещью. Соединение и лицензия — у всех четырёх видов (глава 2 Н1.1, глава 7 Н1.2), остальное различается:

| `type` | Что это | Кадры, запись, детекторы | Хозяин детей (глава 4 Н1.4а) |
|---|---|---|---|
| `camera` | камера, канал устройства | да | да |
| `ipsrv` | устройство как целое: регистратор, блок входов и выходов, устройство без картинки | нет | да: блоки устройства |
| `eventsrc` | источник событий (POS, Н1.1г) | нет | нет |
| `acfa` | контроллер СКУД, его единицы — Н1.2б | нет | нет |

**Прочий поток — всегда `camera`.** `must_match: {type: type}` поля `main` держит пару на одном слове: `type` строки, отличный от `type`
живой строки `main`, — 409 `conflict`, `fault: must_match`. Поэтому поток, по умолчанию `camera`, у строки иного вида дверь не заводит, а
камере поток иного вида не даёт. Условия «поле этой строки равно слову» манифест не выражает (P/02.1): строка с `main` на строку того же
вида не `camera` и строка с `main` на несуществующую цель дверь проходят, держатель их не держит, слово в статусе (глава 2 Н1.1): это предел.

Единицы `cam/device_units` бывают на основной строке любого вида (Н1.2б): домофон со считывателем — строка `camera`, одна лицензия.
Строка `eventsrc`, `acfa` детей не имеет, у регистратора она хозяина не заменяет. События и команды — у всех видов (глава 2 Н1.5, глава 4 Н1.4б).

### Н1.1в Индекс видеоканала

Индекс видеоканала строки — слово источника, функция адреса, без соединения с устройством: выключенную строку источник не
открывает, а хозяина детей (глава 4 Н1.4а) она менять не должна. Индекс считается с 0.

| Адрес | Индекс |
|---|---|
| `ipint://…?source=<N>`, `N` — десятичные цифры | `N` |
| `ipint://…` без `source` | 0: умолчание адреса, индекс сказан |
| `driverpack://<вендор>/<хост>/ch/<N>`, `N` — десятичные цифры, значение ≥ 1 | `N` − 1; `ch/02` — `N` 2, индекс 1 |
| `ipint://…`, `source` не цифры; `driverpack://<вендор>/<хост>/ch/0`; `ch/` не цифрами; иной путь | не сказан |
| `driverpack://file/…`, `rtsp`, `rtsps`, `http`, `https`, `cfw` | не сказан |

Не сказан — поля нет, это не индекс 0. Индекс из адреса выводит только источник (держатель): двери, консоль и `backend` его из адреса
не выводят и берут из `videos` строки устройства (Н1.2). Разные адреса одного индекса (`ch/2` и `ch/02`, `source=1&stream=0` и
`source=1&stream=1`) — не отказ, хозяина выбирает глава 4 Н1.4а. Правка `source` меняет индекс: хозяин может смениться, это предел
главы 4 Н1.4а.

### Н1.1г Источник событий (POS)

Нормы главы по POS и единицам — по DriverPack 2026-10-02, сверяются по новой версии (ADR-0102 доп. (9), (10)). Работой не проверены.

**Адрес.** `ipint://<адрес>:<порт>/<бренд>/<модель>`. Драйвер кассы со словом «слушает» ниже ждёт подключения сам: `<адрес>` — адрес сервера или имя
кассы, `<порт>` — порт, который он слушает. `0.0.0.0` и `::` адресом не бывают: `group_by` собрал бы все POS в одно устройство; такой адрес — отказ
держателя (глава 2 Н1.2).

| Бренд | Соединение | Порт по умолчанию |
|---|---|---|
| `PosXml`, `POSLegacy`, `Commax`, `Commax Complex Server` | слушает: касса подключается к серверу | 2555 |
| `Live Eye` | подключается к устройству сам, как камера; прочий бренд — так же | — |

**Сервер.** Касса знает адрес одного сервера, поэтому строка привязана к нему меткой `server:<имя сервера>` в `labels` (`labels-subset`, Н1.3). Метку несёт
строка площадки `LABELS` этого сервера (V/09.2 Н1.2) или его метки в консоли (P/06.6); запись через consolem — `Device.serverId` (V/11.3 Н1.3). Сервер упал — строка не
переезжает: другого сервера с этой меткой нет, единица ждёт (`unplaceable`, P/04). Это предел: два сервера с одной меткой касса не различит.

**Поля.** Пишет оператор дверью единиц. `camera` не сверяется с целью и не меняет `about`: права на строки POS — права на строку `eventsrc`. `words` не
длиннее 4000 байт канонического JSON (предел поля `json`, P/06.1 Н1.4). Значение не по форме в хранилище — не прочитано, а не отсутствует:
`words` — держатель не ставит `word` и `warning` называет поле, `camera` — страница титров не рисует, `overlay_*` — страница показывает строку без задержки и до следующей.
Поле пропало — то же, что поля нет: держатель `word` не ставит, страница титров не рисует.

### Н1.2 Таблица `devices`

`tables.devices` — что устройство за каналами камер оказалось: строка `cam/devices/<хост>`, ключ `device` — хост,
которым устройство называют адреса его каналов (тот же, что `group_by`, Н1.3). Пишет держатель группы (`worker.writes:
[devices]`; сторона писателя — глава 4); дверь консоли строку отдаёт, запись оператором — отказ
([P/06.1 Н1.6](../../../Platform/06-console/spec/06.1-console.norms.md)); удаление оператором — `DELETE` с cas → 200, держатель
пишет строку заново, если её хост ещё в его группах (P/06.1 Н1.6).

| Поле | Тип | Смысл |
|---|---|---|
| `device` | `string`, обязательное | хост устройства |
| `events` | `list` | виды событий, которые поднимают его каналы |
| `channels` | `int` ≥ 0 | видеоисточники, которые назвало описание устройства: то же число, что `channels` записи двери (V/01.5 Н1.4). `0` — видео нет, поля нет — не сказано, а не «нет» (глава 4 Н1.4а) |
| `ptz` | `bool`, `false` | устройство поворачивается |
| `videos` | `json`, `{"<id камеры>": <индекс>}` | индексы видеоканалов (Н1.1в) основных строк `type: camera` этого хоста, у которых индекс сказан; поток, прочие виды и строка без индекса не входят. Пишется при смене строк группы, описания не ждёт (глава 4 Н1.4) |
| `resolutions` | `list` | разрешения `<ширина>x<высота>`, которые назвало описание устройства; поля нет — не сказано: до первого описания и у `generic` ввод руками (ADR-0104 п. 5) |
| `presets` | `int`, `0` | позиции, в которые можно попросить перейти (`preset`, глава 4) |
| `preset_names` | `json`, `{"<n>": "<имя>"}` | имена пресетов, если драйвер их называет (глава 4 Н1.4); поля нет — только номера до `presets` |
| `storage` | `bool`, `false` | у устройства свой архив: описание называет `embeddedStorageRef` и устройство не ответило, что архива не поддерживает (глава 4 Н1.4); не том `rec` |
| `identity` | `string`, не длиннее 200 | серийный номер, MAC — не возможность; это поле кластер не покидает (не в снимке, не в домене); `ref` и `name` камеры-кластера — её серийный номер сознательно: это её имя для домена (глава 6 Н1.5) |

Строка — находка держателя, не решение оператора: читают её форма сценариев (`auto`, урок V/07), страница и `backend` (V/11).
Входы и выходы — не числа этой строки, а строки детей (Н1.2а; ADR-0102).

`videos` читает `backend` (`Device.videoChannel`), `resolutions` — страница как подсказку выбора, `backend` как предел записи `res` (V/11.3 Н1.3). Поле не
читается — не прочитано, а не отсутствует: у `videos` индекс не «не сказан», у `resolutions` — ввод руками, сказанное значение
строки потока это не снимает. Поле или строка пропали — держатель пишет их следующим проходом (глава 4 Н1.4).

### Н1.2а Дети устройства: таблицы `children` и `child_settings`

Вход и выход устройства — своя строка, у неё есть имя, включённость и права. Строк две, с одним ключом и по одному
писателю (P/06.1 Н1.1; образец — `rec/keeps`): что есть — находка держателя, как зовётся и включено ли — слово
оператора. Правки платформы не нужны.

**`tables.children`** — строка `cam/children/<id>`, ключ `{camera}-{type}-{number:int}`, например `7-sensor-1`. Таблица
воркера (`worker.writes`): пишет держатель, строкой целиком (сторона писателя — глава 4 Н1.4а);
дверь консоли строку отдаёт, запись оператором — отказ, удаление — `DELETE` с cas → 200 (P/06.1 Н1.6), и держатель пишет
строку заново следующим проходом, если она ещё верна: ребёнка так не убрать. Отказ 422 `NOT_SUPPORTED` на `DELETE` ребёнка
(ADR-0102 доп. (1) п. 7) — дверь `backend`, перевод V/11, а не консоль. Строку `gone` так снять можно, и она не вернётся: что это значит для
выключенного выхода — предел главы 4 Н1.4а.

| Поле | Тип | Смысл |
|---|---|---|
| `camera` | `string`, обязательное | хозяин: id основной строки хоста, `camera` или `ipsrv` (глава 4 Н1.4а) |
| `type` | `sensor` \| `relay` \| `mic` \| `spk`, обязательное | вход, выход, микрофон, динамик |
| `number` | `int` ≥ 1, обязательное | сквозной номер по устройству, на каждый `type` свой; у `sensor`, `relay` это `port` события `io.input` и команды `output` |
| `device` | `string`, обязательное | хост, тот же, что ключ `cam/devices` |
| `gone` | `bool`, `false` | хозяин или номер больше не верны; строка остаётся |

**`tables.preset_labels`** — пресет, прошедший через `backend`: `cam/preset_labels/<camera>-<n>`, поля `camera`, `n`, `label`, `label` может быть пустым; подпись оператора старше имени драйвера. Таблица, а не поле строки: поле двигало бы `revision` и рвало соединение камеры на каждой подписи. Пишет `backend` (V/11.4 Н1.16), устройству подпись не идёт, положение — другая вещь. Срока у строки нет, строки снятой камеры лежат: номера камер не повторяются, это предел.

**`tables.child_settings`** — строка `cam/child_settings/<id>` с тем же ключом. Таблица консоли: пишет оператор дверью
таблиц (`POST`, правка — `POST` поверх той же строки, P/06.1 Н1.6). Шаблон ключа называет поля строки, поэтому `camera`,
`type`, `number` есть и здесь (P/02.1 Н1.4). `stamp: [at]`: консоль ставит `at` при каждой записи, и этот штамп упорядочивает слова `enabled` разных
строк (глава 4 Н1.4а).

| Поле | Тип | Смысл |
|---|---|---|
| `camera`, `type`, `number` | как у `children`, обязательные | ключ |
| `title` | `string` | имя, которое дал оператор. Не `name`: поле `name` у таблицы только при `key: name` (P/06.1 Н1.6) |
| `enabled` | `bool`, без умолчания | `false` — выключенный вход не пишет событие, выключенный выход и `spk` отвечают отказом, выключенный `mic` не даёт звука; `true` — включён, и позднейшее `true` снимает настройку родственной строки; поля нет — слова нет, решают родственные строки. Кто выключен — глава 4 Н1.4а. Умолчания нет: имя, данное строке, выход не включает |
| `norm` | `open` \| `closed`, без умолчания | нормальное состояние контакта `sensor`, `relay`: от него считаются начало и конец тревоги (глава 4 Н1.4а); поля нет — `open` |

Строки настроек нет — имени нет. Строка настроек без строки ребёнка не ошибка: дверь наличие ребёнка не
сверяет, строка `gone` своё имя не теряет, а имя можно дать заранее. `backend` собирает устройство из двух строк
(V/11).

Права идут за хозяином: обе таблицы в `rights.unit_of` (Н1.5), отдельного слоя прав у ребёнка нет. Членом папки бывает
единица, а не строка таблицы (P/06.8 Н1.1): в папке состоит камера, показ её детей там — перевод V/11. Блок входов идёт
камере своего видеоканала или строке устройства целиком, поконтактной привязки нет (глава 4 Н1.4а).

### Н1.2б Единицы устройства: таблицы `device_units` и `unit_next`

Единица — узел дерева DriverPack (дверь, считыватель, зона, сегмент ограждения): `.rep` называет, что может быть, но не что есть,
поэтому строки заводит оператор. Таблица консоли, читает держатель (сторона держателя — глава 4 Н1.4б). Единица не единица прав:
членом папки не бывает, права идут за строкой `camera`.

**`tables.device_units`** — строка `cam/device_units/<id>`, ключ `{camera}-{n:int}`, например `7-3`. Пишет оператор дверью таблиц.

| Поле | Тип | Смысл |
|---|---|---|
| `camera` | `string`, обязательное | основная строка `cam/cameras`, любого вида |
| `n` | `int` ≥ 1, обязательное | номер на этой строке, не повторяется (ниже); им зовёт единицу команда (глава 4 Н1.1) |
| `type` | `acfa_sensor` \| `acfa_lock` \| `acfa_fence` \| `relay` \| `controller` \| `det`, обязательное | вид контракта; `controller` — промежуточный узел дерева, в контракте — `Device.type: acfa` с родителем (V/11.3 Н1.2); `det` — детектор, который работает на устройстве (глава 4 Н1.4в) |
| `template` | `string`, обязательное | id шаблона `unit` в `.rep` модели, у `det` — id детектора; держатель передаёт его `CreateUnit`, у `det` — `CreateVideoAnalytics` |
| `address` | `string` | слово устройства, свойство `address` шаблона, передаётся как есть |
| `parent` | `int` ≥ 1 | `n` владельца на той же строке; поля нет — корень устройства; у `det` поля нет |
| `sensitivity` | `int` | только у `det`: чувствительность, диапазон — свой у модели (глава 4 Н1.4в) |
| `zone` | `json` | только у `det`: зона `{shape, points}` в долях кадра, пишет `backend` (V/11.3 Н1.3); поля нет — вся картинка (глава 4 Н1.4в) |
| `title` | `string` | имя, которое дал оператор |
| `enabled` | `bool`, `true` | `false` — держатель единицу не создаёт, вложенные тоже: им нет владельца |

Строка `det` — только на основной строке `type: camera`; вид контракта ↔ детектор — [`data/detector-kinds.tsv`](../data/detector-kinds.tsv), читает `backend` (V/11.3 Н1.3). Вид ↔ шаблон — [`data/unit-templates.tsv`](../data/unit-templates.tsv): по бренду, шаблону владельца и шаблону. Таблицу читает `backend` при создании
(V/11.4 Н1.2); дверь таблиц поле `template` не сверяет, неверный шаблон судит держатель. Свойств единицы (`guarded`, пороги) кроме `address` в строке нет: их нет в контракте.

**`tables.unit_next`** — строка `cam/unit_next/<строка>`, ключ `camera`, поле `n`: последний выданный номер. Номер новой единицы — большее из `n` и наибольшего номера живых строк, плюс 1, строка счётчика идёт
в том же пакете с `cas` (V/11.4 Н1.2). Не поле `cam/cameras`: правка строки перезапускает держателя (глава 2 Н1.1). Номер не повторяется: просьба, ждущая снятую единицу, и строка журнала не
должны попасть на новую. Строки счётчика нет — последний номер 0; строка не читается — номер не выдаётся, 503: это не отсутствие (V/11.4 Н1.2). Записавший `cam/device_units` мимо `backend` счётчик не двигает:
живую строку `backend` учтёт, снятую — нет, её номер может повториться: это предел двери таблиц.

Права — за строкой (`rights.unit_of`, Н1.5): читать — `view`, завести и снять — `admin` на неё. Строка, чьей `cam/cameras/<camera>` нет, держателем не читается, `backend` её не отдаёт;
id строки не повторяется, поэтому чужой она не станет. Цель `parent` и снятие вложенных — `backend` (V/11.4 Н1.2); мимо него снятая цель оставляет вложенные без владельца: держатель их не создаёт (глава 4 Н1.4б).

### Н1.2в Слова правил: таблица `rule_state`

`tables.rule_state` — что правила сказали о камере (ADR-0105 пп. 6, 8): строка `cam/rule_state/<id>`, ключ `camera`. Таблица воркера (`worker.writes`): пишет держатель камеры, исполняя просьбы `arm`, `disarm`, `disable` (глава 4 Н1.4д); дверь консоли отдаёт, запись оператором — отказ, снятая `DELETE` строка пишется держателем заново (P/06.1 Н1.6). Не поле `cam/cameras`: правка строки перезапускает держателя (глава 2 Н1.1).

| Поле | Тип | Смысл |
|---|---|---|
| `camera` | `string`, обязательное | основная строка `type: camera` (`rights.unit_of`) |
| `armed` | `bool`, `false` | на охране; читают условие правила (V/07) и `Device.armed` (V/11) |
| `disabled_by_rule` | `string` | номер сценария, который выключил; поля нет — не выключена |
| `disabled_at` | `float` | с какого момента, часы держателя; `Device.disabledByRuleAt` |
| `disabled_until` | `float` | выключена, пока «сейчас» раньше него (глава 4 Н1.4д) |

Строки нет — не на охране и не выключена. Значение не по форме в хранилище — не прочитано, а не отсутствует: глава 4 Н1.4д. Права — за строкой (`rights.unit_of`, Н1.5): читать — `view` на камеру.

### Н1.3 Размещение

Ключи и их смысл — [P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md); `cam` объявляет:

| Ключ | Значение | Почему |
|---|---|---|
| `capacity` | `{from: capacity, default: 50, unit_mb: 1, base_mb: 18}` | слово воркера в пульсе; бюджет памяти — глава 2 |
| `headroom` | `{from: headroom}` | запас из пульса |
| `constraint` | `labels-subset` | метки камеры ⊆ метки сервера держателя: адрес виден только из своих сетей |
| `group_by` | `{field: source, cut_at: host}` | все каналы одного устройства — у одного держателя: одно соединение с устройством, одна линия вопросов и один вызов команды за раз (глава 4); группа и хост в одном написании — [договор группы по хосту](../../../Platform/common/contracts/group-of.md) |
| `requires` | `resource` | держатель пишет события в ресурс своего сервера |
| `tie_break` | `most-free-capacity` | — |
| `grows` | `true` | воркеров по заказу (P/04 Н3 «нехватка()», P/02.4 Н1.5); запасных нет (ADR-0084) |
| `near` | `{sub: rec, of: cam, prefer: {home.kind: [backup, edge], home.enabled: true}}` | держатель — рядом с регистратором своей камеры, первым — с тем, чья запись на резервном томе или карте (урок V/02; строка `cam-<cam>-<том>`, глава 6 Н1.7): резервная пишет поток с коробки, а не через сеть ([P/04 Н1.3](../../../Platform/04-controller/spec/04-controller.norms.md) `near`, ADR-0091 п. 10) |
| `home` | `near` | дом держится: контроллер возвращает камеру к якорю |
| `rebalance` | `{dead_band: 0.10}` | — |

### Н1.4 Снимок

`snapshot: [name, source, enabled, priority, labels, ref, live, main, profile]` — `main` и `profile` отличают поток от
камеры для читателя снимка (домен знает камеру по `ref`; у потока `ref` обычно пуст, и в виде домена его нет; поток с
`ref` — Н1.1а); форма и маска адреса —
[P/04 Н1.3а](../../../Platform/04-controller/spec/04-controller.norms.md). Не в снимке: `cred_*` (секрет и логин — читателя
снимка нет), `alarms`, `type`, `resolution`, `fps` (читает держатель из строки), `lat`, `lon`, `azimuth`, `short`, `mac` (читателя снимка нет). Снимок уходит из кластера
(домен, P/08.1); `identity` таблицы `devices` в нём не бывает.

### Н1.5 Права людей

`rights.reach` ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md) «Права по телу»; владелец — [P/06.3 Н1.5](../../../Platform/06-console/spec/06.3-console.norms.md)):
- `group: [source, labels]` — правка адреса или меток задевает все камеры устройства, которое камера покидает, и того,
  к которому переходит: перенос канала — действие над устройством;
- `cluster: [ref]` — имя камеры для домена меняет грант на кластер;
- создание потока — как любой строки `cam`: `admin` на `*` (строку единицы без `rights.routes` создаёт грант на кластер,
  договор сторожевой и передачи «строки единиц»); правка — `admin` на поток или его камеру (по `about`), смена `source`
  или `labels` — ещё на все камеры старой и новой группы устройства (`reach.group`); грант на камеру покрывает её потоки
  по `about` (Н1.1а);
- `requests` — команда устройству требует `edit` на всю группу (глава 4), и у выхода с хозяином тоже:
  устройство исполняет команду одно на всю группу;
- `requests: [output, preset, unit]` — команда единице, как и выходу, судится по всей группе;
- `preset`, `preset_save`, `preset_clear`, `arm`, `disarm`, `disable` в `reach.requests` нет: цель — канал камеры или она сама, не устройство, хватает `edit` на камеру; `routes: {edit: [ptz_moves]}` — так же поворот (глава 4 Н1.4г);
- `unit_of: {children: camera, child_settings: camera, device_units: camera, unit_next: camera, ptz_moves: camera, rule_state: camera, preset_labels: camera}`, `routes: {edit: [child_settings, ptz_moves, preset_labels]}` — строка ребёнка и единицы принадлежит
  хозяину (Н1.2а): читать — `view` на хозяина, назвать или выключить — `edit` на него ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md));
  выход, выключенный настройкой прежнего хозяина, включает обладатель `edit` на нынешнего: настройкой своей строки (глава 4 Н1.4а); единицу заводит и снимает `admin` на строку: маршрута `edit` у таблицы нет.

## Н3 Проход

### Запись камеры (дверь единиц P/06.1)

Порядок проверок и исходы — P/06.1 Н3 «создать», «править», договор проверки строки «Порядок проверок» и договор адреса
«прочитать_адрес»; объявления этой главы
дают им значения:

```
тело → поля Н1.1 (лишнее поле, id в POST — отказ P/06.1)
source: нет → 400 required; схема не из schemes → 400; логин или пароль в адресе по schemes/secret_in → 400 bad_url,
        detail называет поле credentials (cred_username | cred_secret); каноническое написание есть у живой камеры → 409 conflict, fault: unique
cred_secret: смена source без нового cred_secret → 400 refused, field: /cred_secret; значение запечатывается (P/06.2)
live, type: вне enum → 400
resolution, fps: не по schema → 400 type
права: reach.group — по камерам старой и новой группы source/labels; reach.cluster — по ref (договор сторожевой и передачи «Права по телу»)
main, type: правка иным значением → 400 fixed, field: /main | /type (P/06.1 Н4)
main: живая цель иного type → 409 conflict, fault: must_match; что main называет камеру — не дверь, держатель (глава 2)
```

**Гонки.** Две записи с одним адресом одновременно: предварительная проверка `unique` у двери не атомарна с записью
(договор проверки строки); второе написание, проскочившее проверку, держатель находит как «устройство занято» (глава 2) — двух
соединений с одним каналом нет.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| нет `source` | 400 (P/06.1) | ответ двери | указать адрес |
| логин или пароль в `source` | 400 `error: bad_url`, `fault: bad_url`, `field: /source`, `detail` с именами полей `credentials` (P/06.2 Н4) | ответ без значения | перенести в `cred_username`/`cred_secret` |
| схема не из `schemes` | 400 `bad_url` (P/06.1 Н4; договор адреса «Схемы») | ответ | — |
| адрес уже у живой камеры | 409 `conflict`, `fault: unique` (P/06.1 Н4) | ответ | другой канал или правка той камеры |
| смена `source` без `cred_secret` | 400 `refused`, `field: /cred_secret`, `detail` «source changed: cred_secret must be given anew» (P/06.2 Н4) | ответ | вписать пароль заново |
| правка `main` потока | 400 `fixed`, `field: /main` (P/06.1 Н4) | ответ | поток другой камеры — новая строка |
| правка `type` | 400 `fixed`, `field: /type` (P/06.1 Н4) | ответ | другой вид — новая строка |
| `type` вне перечня | 400 `enum` (P/06.1 Н4) | ответ | — |
| поток с `type`, отличным от `type` живой строки `main` | 409 `conflict`, `fault: must_match` (договор проверки строки) | ответ | поток — `camera`, `main` — камера |
| `resolution` не `<ширина>x<высота>`, `fps` < 0 | 400 `type` (P/06.1 Н4) | ответ | пусто или значение по форме |
| `POST` строки `devices`, `children` | 403 `denied` «written by its worker»; `PUT` — 405 (P/06.1 Н1.6) | ответ | строку пишет держатель |
| `child_settings` без `camera`, `type`, `number`; `type`, `norm` вне перечня; `number` < 1 | 400 (P/06.1 Н4) | ответ | указать ключ |
| `device_units` без `camera`, `n`, `type`, `template`; `type` вне перечня; `n`, `parent` < 1 | 400 (P/06.1 Н4) | ответ | указать поля |
| `words` не по схеме, `overlay_*` < 0 | 400 (P/06.1 Н4) | ответ | значение по форме |
