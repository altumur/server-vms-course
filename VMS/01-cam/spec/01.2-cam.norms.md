# V/01.2 — The camera holder: norms

This English text is the source; the Russian translation `ru/spec/01.2-cam.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 2 of lesson V/01 «Камера» (ADR-0080; the VMS module — ADR-0090). Lecture (`ru/01-cam.md`, for people, not in the export),
[instructions](01-cam.README.md), [acceptance](../acceptance/2/README.md), manifest [`cam.subsystem.yaml`](../cam.subsystem.yaml).
The platform is the export `cammeta-specs` `7a875c75` (the keys `worker.stop_timeout`, `shares.<имя>.part`, the subsystem file —
P/02.1, P/02.4 Н1.1, Н1.2 by ADR-0091 addendum (2), (3); camera streams — `41d3ec8`, V/01.1 Н1.1а; the analysis of the streams review — `b41527f`).

The camera holder is the worker `camworker` of the subsystem `cam` that has the camera in its assignment. The chapter sets norms for what
only `cam` knows: which cameras the holder holds, what «hold» means (one connection to the channel and delivery of the stream
to subscribers), what it says about the camera in the heartbeat, which events it writes, what it does when the store is silent and at stop, and the
worker budget. The worker runtime — slot, epoch, lease, gate, loop, backoff, substitution, fence, stop — is the norms of
[P/03](../../../Platform/03-worker/spec/03-worker.README.md) by reference; the chapter does not repeat them. Commands and queries to the
device — chapter 4, the device archive and its door — chapter 5, the source `driverpack://file` — chapter 3.

Norm ids are `V/01.2-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

## Н1 Form

**Time.** `since` in the elements of `devices` of the heartbeat is time in the writer's form ([P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md)).

**Data** (the shared families `<sub>/…` of the [platform catalogue](../../../Platform/common/data/catalog.tsv); the chapter has no keys of its own
beyond them): reads — `cam/cameras/<id>` (the rows of its own units, P/03.3); writes — the heartbeat `cam/heartbeats/<воркер>` (an object,
[P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md)), event rows into the buckets `cam/<id>/e<эпоха>/` and
alarms into `cam.alarms/<id>/` ([P/03.6 Н1.2](../../../Platform/03-worker/spec/03.6-worker.norms.md), the event log contract
[P/05 Н1.2](../../../Platform/05-resource/spec/05-resource.norms.md)); frame files in the directory of the share `cam.shm` (Н1.3).

### Н1.1 Desired state

The holder MUST hold a camera of its assignment if the row is live (not a tombstone), `enabled: true`, and there is no reason of Н1.4
«does not hold»:

| Row | Holder |
|---|---|
| `live: always`, `type: camera` | holds: the connection to the channel (Н1.2); there is a consumer — the stream and delivery (Н1.3), there is none — phase `idle` (Н1.2в) |
| `live: on-demand`, `type: camera` | holds the device (the device archive, chapter 5); there is a consumer (Н1.2в) — the stream and delivery, as with `always`, there is none — phase `held` |
| `type`: `ipsrv`, `eventsrc`, `acfa` | holds only the device: the connection, events and commands (chapter 4), there is no stream and no delivery addresses; phase `held`; `live` is not read (V/01.1 Н1.1б). For `eventsrc` — also the text source (Н1.2б) |
| `enabled: false` | does not hold: phase `pending` |
| switched off by a rule (chapter 4 Н1.4д) | does not hold: phase `pending`, `reason` «rule: off»; once the deadline has passed, the next pass starts it |

A `type` outside the list (corruption; the door does not let such a value through) is not read, rather than taken as `camera`: the row is not held, phase `pending`, `reason`
«type: unreadable».

**A camera stream** (a row with a non-empty `main`, V/01.1 Н1.1а) is held, in addition, only if the camera row `cam/cameras/<main>`
is live, its `main` is empty, the `type` of it and of the stream itself is `camera`, and `enabled: true`; otherwise it is not held: phase `pending`, `reason` «main: `<what is missing>`»
(«main: missing», «main: is a stream», «main: no picture», «main: off», «main: off by rule» — the first unmet condition in this order; the last one — the camera is switched off by a rule, chapter 4 Н1.4д). The camera row
is not read (unreadable, the store is silent): a running stream goes on with the last one read, a stream not yet started is not started, phase
`pending`, `reason` «main: unreadable». The shared fields of the stream itself the holder does not read and does not stop the stream because of them (V/01.1 Н1.1а: inert). The holder reads the camera row itself (`cam/*`, P/02.5
Н1.4); an edit of it is a restart of the camera's streams, as an edit of the stream's own row. Of a stream only `source`, `enabled`, `live`, `type`, `resolution`, `fps`,
`cred_*` are read (V/01.1 Н1.1а); the event class, the licence and the shared fields — by the camera row.

An edit of the row (a new `revision`) is a restart under the same epoch by [P/03.3 Н3](../../../Platform/03-worker/spec/03.3-worker.norms.md)
step 2; the holder holds the camera with the new values, including a new password (rotation — by an edit of `cred_secret`).

### Н1.2 One connection

The holder MUST open the camera channel with **one** connection, however many subscribers there are, and multiply the stream itself:

- **a slow subscriber does not delay reading the camera:** the delivery branch to it loses old frames (no more than ≈ 1 s in
  the branch queue), the other branches and the camera reading do not wait;
- **holding does not depend on delivery subscribers:** there is a consumer (Н1.2в) but no subscriber — the stream is read and discarded, the connection is held; there is no consumer — Н1.2в;
- **the pace is set by the source**, the branches are not synchronized by a clock;
- **the camera is silent:** 8 s without a frame — the stream is considered fallen: a work failure of the unit (backoff — P/03.3 Н1.2 `retry`) and
  the event `silent` (Н1.5);
- **the password — only to the recipient:** the address and the password are passed to the source after the pipeline string is parsed, not in its
  command line, log or heartbeat; the envelope `cred_secret` is opened by the worker by [P/03.5 Н3](../../../Platform/03-worker/spec/03.5-worker.norms.md)
  «открыть» (before the epoch); it did not open — the unit does not run, the platform heartbeat element is `{id, phase: sealed, why, revision}`.
- **the same channel** (`busy`): the camera address and an address that the holder already holds for another camera are one channel when their
  canon by the row check contract (`unique: canonical`) coincides after removing the default port of the scheme (`rtsp` — 554,
  `rtsps` — 322, `http` — 80, `https` — 443); otherwise they are different channels: `ch/02` and `ch/2`, `rtsp` and `rtsps` on one host are
  two connections. The second in assignment order — `device_state: busy`, it is not opened. The rule judges only rows `type: camera`:
  a row of another kind holds no channel;
- **the stream password** (V/01.1 Н1.1а: the password belongs to the camera): `cred_secret` of the stream is set — the login and password of the stream; it is empty — the login and
  password of the camera (`cred_*` of the row `main`; a stream login without a password is not read), only if the host of the stream address is the same as the camera's, in the notation of
  the [host group contract](../../../Platform/common/contracts/group-of.md) (one group `group_by` — one holder,
  which opened the camera envelope itself); the host is different and there is no own password — the stream is not opened, `device_state: refused`, phase `pending`, `reason`
  «credentials: stream on another host»: the camera password is not given to a foreign host (`bound_to` of the platform keeps the password at
  its own address). A stream address without a host (`driverpack://file`, V/01.3 Н1.1) has no password: the host rule does not judge it, the stream
  is opened. The camera envelope did not open — the stream is not opened: `device_state: refused`, phase `pending`, `reason`
  «credentials: camera password does not open»; `sealed` of the platform is about its own row.

### Н1.2а Resolution and frames per second

`resolution`, `fps` of the row are a device setting for this stream (V/01.1 Н1.1; the camera and any other stream have their own). The holder
passes them to the driver when opening the stream; empty and `0` — the device setting is not touched, the size is taken from the heartbeat. An edit is a new
`revision`, a restart (Н1.1): a change alters the device setting, not only the row. A file (V/01.3) has no device and there is nothing
to pass; for a row that is not `camera` the fields are not read. A value not in form (corruption; the door does not let such a value through) is not read: it does not
go to the device, the stream is not opened, `device_state: refused`, phase `pending`, `reason` «settings: unreadable».

- **Address and field.** One setting in two places — `src.resolution`, `src.fps` in the `ipint://` address and a non-empty field — is a refusal of the holder,
  whether the values are equal or not: `device_state: refused`, phase `pending`, `reason` «settings: in the address and in the field: `<field name>`»,
  without repeats, an edit of the row is a new attempt (Н3). The door does not parse the address, hence the refusal here. Other addresses do not
  state this setting.
- **Mismatch.** The field `resolution` is not empty, the phase is `running` and `size` (Н1.4) is not equal to it — `warning`: the device is configured differently.
  The stream runs, the warning goes away together with the mismatch. `fps` is not checked: the heartbeat carries no frame rate.

### Н1.2б Event source and listening port

A row `eventsrc`: the holder opens the device with one connection and the text source of the description (`textEventSourceRef`, index from 0, `CreateTextEventSource`), the lines — Н1.5. By DriverPack 2026-10-02, to be checked against a new version.

- **Port.** The holder passes the port of the address as the description property `port`; there is no port in the address — the default of V/01.1 Н1.1г. The driver listens, and it does not return
  the refusal of a busy port: `SignalLost` and a new attempt. Therefore occupancy is judged by the holder.
- **Two per port.** Two `eventsrc` rows with the word «слушает» (V/01.1 Н1.1г), one port (explicit or default) and one label `server:*` at one holder: the port is held by the smallest id as a number, the assignment order does not matter, otherwise a restart would give the port to another till; the other one —
  `device_state: refused`, phase `pending`, `reason` «`port: taken by <id>`», without repeats: removing the first one is a new attempt on the next pass. A row with a smaller id has arrived — the running one yields the port: this is a limit. Rows of two workers of one server
  the holder does not compare: this is a limit, the second one is seen as `device_state: lost`.
- **The address `0.0.0.0`, `::`** — `device_state: refused`, `reason` «address: not a place» (V/01.1 Н1.1г), without repeats.
- **Without a label.** A row with the word «слушает» without a label `server:*` is held, with `warning` in the status: a move would take it away from the till.
- **Channel state.** `Started` — phase `held`; `SignalLost` — phase `held`, `device_state: lost`, the connection is held, the driver retries by itself; `Failed` at start — a start failure (Н3). For a listening driver `Started` means «the port is open», not «the till is connected»: the absence of the till
  is observed only by silence.

### Н1.2в Stream without a consumer

The decision — ADR-0107 addendum (2) item 1. Holding the device and reading the stream are different things: a row `type: camera`, `live: always` — the main stream and any other stream, each on its own — reads the stream only while it has a **consumer**. There is none — the connection is held, the stream is not open, phase `idle`.

| Consumer of the stream | How the holder knows |
|---|---|
| a recording with a live stream | a row `rec/recordings/*`: `enabled`, `cam` — this camera, `stream` — this stream (empty — the main one), `replica_from` is empty, `when` is not `offline`, `until` is 0 or has not passed; a backup `when: offline` is never a consumer by itself: it needs the stream together with the main recording, and that one is a consumer (V/02.6 Н1.5). A recording on an `edge` volume of its own server is a consumer at any `when`: the `when` of this row is a copy, the word of the volume changes without it |
| a detector on the stream | a row `det/units/*`: `enabled`, `cam`, `stream` likewise; the built-in detector (chapter 4 Н1.4в) does not use the stream |
| delivery | the stream is named in `asked` of an element or in `asked_solo` of a heartbeat `live/heartbeats/*` heard within 45 s (V/03.2 Н1.5) |
| another cluster | the main stream of a camera with `ref` whose assignment `domain/placed/rec/<ref>` (for the domain holder — `domain/placement/rec/<ref>`, V/01.6 Н1.2) names another cluster: the stream is pushed by the recorder of the holder's server (V/02.9 Н1.2) |

- **The card ring is a consumer.** A recording on the card of the holder's server (V/01.6 Н1.7) writes nothing while on hold, yet it needs the stream: otherwise there is no pre-recording, and on the card this is the only recording of the camera. The volume is read by the row `rec/volumes/*`; it is not read — the former word.
- **Reading.** The holder lists the `rec`, `det` rows at unit start and once per `HEARTBEAT_EVERY`, like `children` (chapter 4 Н1.4а); the gateway heartbeats — on every pass.
- **Not read is not absent.** The listing failed, a row is unreadable, a gateway heartbeat, its `asked` or `asked_solo` is not in the form of the family `live-heartbeat-words` — the consumer is considered present: a running stream goes on, an unopened one is opened. An extra stream costs the device; lost frames cannot be returned.
- **Opening.** A consumer has appeared — the stream with `resolution`, `fps` (Н1.2а); until the first frames the phase is `idle`, then `running` and the addresses (Н1.3). A failure is a work failure of the unit, as with a fallen stream.
- **Closing.** There has been no consumer for `IDLE_AFTER` = 60 s in a row — the stream ends, as in «Release a camera», without closing the connection; the addresses are removed, phase `idle`. `revision` and the epoch stay the same.
- **What the words mean.** `running` — the stream is open and frames are flowing. `silent` — only for an open stream: closing is not a break, and the 8 s are counted from opening. `live_url`, `live_shm`, the audio endpoints — only at `running`; in `idle` an audio endpoint answers 404, the RTSP endpoint of the gateway — 503 and asks for the stream (V/03.6 Н1.4). `size`, `codec` in `idle` — the last ones stated since the unit started. Commands, events, units, `can`, the device archive do not depend on the stream.
- **A source without a device** (a file, `rtsp://`): there is no connection that would remain to be held: `idle` means that the source is closed; the file is checked as in `held`.
- **A camera-cluster** (`cfw://local`) is not subject to this rule: its stream is decided by the pusher (V/01.6).
- **`live: on-demand`** — the consumers are the same as for `always`, and the viewer too; there has been no consumer for `IDLE_AFTER` — phase `held`, not `idle` (V/01.1 Н1.1; ADR-0103 addendum (7) item 3, (8) item 2).

**Limits.** A camera without a stream will not say `silent`: whether it is silent or not is seen only through the connection. Recording on a camera starts no earlier than the listing of rows, up to `HEARTBEAT_EVERY`. The first viewer of an `idle` camera waits for the gateway heartbeat, the holder's pass, the first frames and the holder's heartbeat: up to 22 s: the retry window of the page accommodates them (V/11.17).

### Н1.3 Delivery

Two kinds of delivery; which one to take is decided by the subscriber (`rec`, `live`, `det`, `detedge`), not by the holder:

| Kind | Address in the heartbeat | Who takes it |
|---|---|---|
| RTSP | `live_url`: `rtsp://127.0.0.1:<порт>/<id>` — the loopback only | a subscriber of its own server; between servers the stream goes through the receiver of the recording cluster (V/02.9; ADR-0075 window 2: `rtsps` is not introduced) |
| shared memory | `live_shm`: `shm://<каталог доли>/<id>-<эпоха>.shm` — an absolute path, three slashes (`shm:///run/vms-cam-shm/7-12.shm`) | a subscriber on the same server that declared the share `cam.shm` (`worker.uses: [cam.shm]`) |

- **RTSP:** one session per camera for all clients (shared); the transport is TCP or UDP, chosen by the client; not multicast
  (it needs a network with PIM/IGMP and has no sessions — this is not part of the system). The door listens **only on the loopback** `127.0.0.1`:`RTSP_PORT` of the
  subsystem file (Н1.7; `RTSP_PORT` is not set or is `0` — the port is chosen by the OS, in `live_url` — the actual one): ADR-0075 window 2 — RTSP
  does not go between servers, `rtsps` is not introduced; a subscriber of another server gets the stream through the receiver of the recording cluster
  (V/02.9).
- **Shared memory:** the share `shares: {shm: {kind: dir}}` of the `cam` manifest is the directory `SHM_DIR` of the subsystem file (Н1.7;
  default `/run/vms-cam-shm`: `/run/<dep>-cam-shm` [P/02.4 Н1.1](../../../Platform/02-installer/spec/02.4-installer.norms.md)
  `dirs`, `<dep>` of VMS is `vms`, V/09.1), the group `vms-cam-shm` (ADR-0091 item 5, addendum (3) item 3 — the directory in `ReadWritePaths`
  of the holder). The frame file is **its own for each epoch** of the camera holder: `<каталог>/<id>-<эпоха>.shm`, no more than 20 MB
  (about 1 s of H.264); the writer does not wait for the reader; the file is deleted only by its writer (at unit stop and at «отсечь»
  P/03.2 Н3); the exception — files of this camera with a smaller epoch: they have no writer, the holder deletes them at unit start;
  the former and the new epoch on one server do not share a file. A subscriber takes the exact address from the holder's heartbeat
  (`live_shm`) and does not build it itself. The format of the frame file is decided by the implementation (section «Implementation decides»): the share is an interface inside
  one VMS implementation; between implementations the interface is loopback RTSP.
- **Publication:** delivery addresses appear in the heartbeat only when the stream is running (the first frames have been read), and disappear at
  unit stop; a branch without an address (delivery not configured) does not exist — the stream does not go into it.

**Sound** (ADR-0102 addendum (9) item 7; by DriverPack 2026-10-02, to be checked against a new version). With `live_url` the RTSP door holds audio
endpoints: `<live_url>/mic` — the first by `number` live `mic` of the camera of this stream (the owner is its main row, [chapter 4](01.4-cam.norms.md)
Н1.4а); `<live_url>/mic/<n>` — the `mic` of number `n` of the device group, whoever it belongs to: at a recorder a microphone is not bound to a camera.
An endpoint is one track; `audio` 0 and the number of the first one are one endpoint: `Content-Base` of the `DESCRIBE` answer names `<live_url>/mic/<n>`; the codec is as from the device, the holder does not transcode; the subscriber reads it from `rtpmap` of the `DESCRIBE` answer, the heartbeat
has no word about the endpoints. The audio source of the device is opened by the first client of an endpoint and closed with the last one.
There is no `mic`, it is `gone` or switched off (chapter 4 Н1.4а), the owner is `unlicensed`, the description is not stated, the stream is not `running` — `DESCRIBE` 404: «no sound». The holder closes an open endpoint by the pass that read that the `mic` is switched off (when in doubt too), `gone`, or that the owner is `unlicensed`: the client sees the end of the stream.
**One time:** the frames of the stream and of the sound go by the holder's capture time; loopback RTSP, the stream and the endpoints, states it by its RTCP Sender Report, the share — by the frame time. The tolerance of divergence between the tracks — by a measurement after the first generation.
The source failed — the client sees the end of the stream; the video stream is not affected. Sound does not occupy the share `cam.shm`, its format says nothing about it.

### Н1.4 Heartbeat words

The heartbeat is the form of [P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md); `cam` adds:

**The element `status[]` of a unit** (beyond the platform fields `id`, `phase`, `epoch`, `revision`, `observed_revision`, `why?`,
`stalled?`, `lease?`, `unconfirmed_s?` — P/03.4 Н1.1; an unreadable row of a started camera — `why` «row unreadable: …», a row never
read — `{id, phase: unreadable, why, revision?}`, P/03.3 Н3 step 2; a sealed one — `{id, phase: sealed, why, revision}`;
`sealed` and `unreadable` have no `epoch` and `observed_revision` — they are phases of the platform, not of `cam`):

| Field | Value | Meaning |
|---|---|---|
| `phase` | `running` \| `idle` \| `pending` \| `held` \| `failed` \| `unlicensed` | runs; held, the stream is closed: there is no consumer (Н1.2в); switched off or waiting for start; held without a stream (`live: on-demand` without a consumer or a row that is not `camera`); the last start or work failed (backoff — `stalled` of the platform); outside the licence — not held ([chapter 7](01.7-cam.norms.md) Н1.3) |
| `live_url` | a string `rtsp://…` | Н1.3; only at `running` and `type: camera` |
| `live_shm` | a string `shm://…` | Н1.3; likewise |
| `type` | `ipsrv` \| `eventsrc` \| `acfa` | only for a row that is not `camera`; there are no delivery addresses |
| `size` | a string `<ширина>x<высота>` | the frame of the stream by the first frames; only at `running` and `type: camera`, in `idle` — the last one stated (Н1.2в); a hint for choosing a stream (V/01.1 Н1.1а) and the check of `resolution` (Н1.2а) |
| `codec` | `H264` \| `H265` | the codec of the stream by the first frames, the `rtpmap` name: the gateway checks it against the offer (V/03.3 Н1.2); only at `running` and `type: camera`, in `idle` — the last one stated (Н1.2в); another codec — no field; read-only, never a setting (ADR-0104 item 7) |
| `talk` | `{url, spk: {"<number>": "<кодек>"}}` | talk ([chapter 4](01.4-cam.norms.md) Н1.4а) at the owner row with a live `spk` that is not switched off: `url` — `<схема>://<хост>:<порт>/talk/<id>` of the holder's door (the address — [chapter 5](01.5-cam.norms.md) Н1.2), `spk` — the numbers of such ones and the codec that the device expects, by the `rtpmap` name; there is no such `spk` — no field; read by the gateway (V/03.3 Н1.2а) |
| `device_state` | `busy` \| `refused` \| `opening` \| `lost` | does not hold: the channel is already held by another camera (Н1.2 «the same channel»); the subsystem did not read the address (Н3, without repeats), the stream has no password (Н1.2), the port is taken (Н1.2б); the connection to the device is being opened ([chapter 4](01.4-cam.norms.md) Н1.3) or did not open; `lost` — the row is held, the event channel is lost (Н1.2б) |
| `units_down` | `{"<n>": <слово>}` | the units of the row that do not work (chapter 4 Н1.4б), the word `lost` \| `failed` \| `refused`; working and switched-off ones are absent; empty — no field |
| `ptz_reason` | a string | why PTZ is not executed (chapter 4 Н1.4г); it is executed or there are no lease rows — no field |
| `warning` | a string | warnings that do not stop the camera, joined by «; »: the row `cam/rule_state/<id>` is not in form (chapter 4 Н1.4д), the `identity` of the device coincided with the row of another host — the words of both names, the `identity` of the host changed, the camera's children moved to another host, the inputs and outputs of the device have no owner, a block is not resolved ([chapter 4](01.4-cam.norms.md) Н1.4, Н1.4а); `resolution` did not match `size` (Н1.2а); an `eventsrc` has no server label (Н1.2б), `words` is not read (Н1.5) |
| `reason` | a string | the subsystem's words about why the camera does not run (`why` — only the platform's reason, P/03.4); «type: unreadable» (Н1.1); «rule: off» (Н1.1); for a stream — «main: …» (Н1.1), «credentials: …» (Н1.2); «settings: …» (Н1.2а); «port: …», «address: …» (Н1.2б) |
| `can`, `playback_url`, `coverage`, `index_url`, `taken_by` | — | chapter 4 (`can`), chapter 5 (the device archive), chapter 6 (`taken_by`) |

**The top of the heartbeat:** `devices` — a list by the devices of the group, the form is an element of `GET /devices` of the holder's door
([chapter 5](01.5-cam.norms.md) Н1.4; a device that did not answer — without its own numbers), `devices_slow` — the number of slow devices
(only when not zero), the counters `door_reads_stuck`, `devices_opening`, `identity_changes`, `events_refused`,
`inputs_off`, `identity_coincidences`. The platform fields — `capacity`, `headroom`, `store_errors`, `pass_failures`, `was_fenced`, `unconfirmed`,
`garbled_rows` (P/03.4 Н1.1, Н1.2): the holder does not repeat them in its own words.

### Н1.5 Holder events

| Kind | When | Suppression (`events.suppress`) |
|---|---|---|
| `silent` | an open stream fell (Н1.2: 8 s without a frame or a source error; closing by Н1.2в is not a break); the only trace of the break — it is written whether anyone records the camera or not | `window: 60` |
| `io.input` | an input of the device changed its state: the fields `port` — the `number` of the input, a JSON integer from 1, the numbering of `output.port` (V/01.4 Н1.1, Н1.4а), `value` — `closed` the start of an alarm, `open` the end: counted from the `norm` of the input (V/01.4 Н1.4а) | `window: 30` |
| `source-stats` | a summary of the source: `dropped` — frames dropped over the window, `depth` — the depth of the source queue (both a JSON integer ≥ 0) | `window: 60`, `by: [dropped, depth]` |
| `text` | a row `eventsrc`: `EventData` of the text source: `lines` — `rawData`, a list of lines; `group` — an integer ≥ 1, the number of the `EventGroupBegan` group within the connection, outside a group there is no field; `camera` — the field of the row, there is none — no field; `word` — below; `occurred` — the driver's time | — |
| `unit` | a unit or the built-in detector raised an event (chapter 4 Н1.4б, Н1.4в): `unit` — the id of the row `cam/device_units`, `event` — the word of the template as is, `phase` — `begin`, `end` for a two-phase one, for an instantaneous one there is no field; `occurred` — the driver's time. For the built-in detector also `det_kind` — the kind by `detector-kinds.tsv` (`driver`, `template`), outside the table `other`: the event goes as `det` (ADR-0107 item 8, V/07.2 Н1.3). While the phase is open, the holder writes once per `DET_STILL` = 30 s a row with the same fields, `phase: still`, a new `id`, `occurred` — the moment of the repeat by the holder's clock: the deadline of the recording order is counted from it (V/07.4), otherwise recording by motion would end after a minute while the motion goes on (V/11.3 Н1.3). The value is the `motion` window of V/04.3. The driver gave `end`, and a new `begin` of the same `unit`, `event` came sooner than `DET_STILL` — the phase is not closed, there are no rows, otherwise flicker would give 120 rows per minute; **the price:** `end` is written `DET_STILL` later. The phase closes silently, without `still`: a break of the connection to the device, `enabled: false`, removal of the row, the camera switched off by a rule, a move. `DET_STILL_MAX` = 3600 s, the value is for measurement: a driver without `end`, the phase is longer than the ceiling — no `still` until the next `begin` | — |
| a kind from the source message | the source reported its own (`motion`, `person`…): the scalar fields — as is | — |

- **A row per `EventData`, not per group:** a group of a till lasts the whole receipt, and the caption is needed at once. `text`, `unit` are written into the bucket of the main row they belong to, of any kind.
- **`word`.** The holder searches the `msg` of the elements of `words` of the row as a substring in `lines`, case-sensitively, in list order; the first match is the field `word`, the value is `msg`. Colours are not copied: the page takes them from `words`. `words` is not read — no field, `warning` (V/01.1 Н1.1г).
- `EventData` that is not JSON or is without `rawData` — the row is dropped, `events_refused`.
- **The first word of an input.** A driver word with `initial: true` is the state of the input at subscription, not a change: the holder writes no event but remembers the state and judges the next change from it.
- **Source events — only at the camera.** `io.input` the holder writes into the bucket of the input's owner (V/01.4 Н1.4а), kinds from the
  source message — into the bucket of the camera (of the main stream); source messages of any other stream are not events, on the same host and on another one: on the same host the device
  is one, the row is one; on another one (a transcoder, another address) its source carries no events of the camera, and the stream has no events
  of its own. What is dropped is not counted and is not written to the log. `silent` and `source-stats` are each stream's own; their `of` is `cam/<камера>` by `about` (V/01.1 Н1.1а).
- The class of the row, of `text` and `unit` too: `alarm` if the kind is in `alarms` of the camera row (V/01.1 Н1.1; with inheritance P/06.7 Н1.14), otherwise
  `observation`. The holder writes under its own epoch, `of` is set by the platform — [P/03.6 Н1.2](../../../Platform/03-worker/spec/03.6-worker.norms.md).
- An event comes only from the camera source, not from the stream plumbing (messages of service elements are not camera events).
- An event row that cannot be written the holder drops and counts (`events_refused`); this does not interrupt the pass.
- An input without an owner, without a live row `sensor`, with an owner `unlicensed` or with a driver word outside `open`, `closed` (V/01.4 Н1.4а) — the same row: dropped, `events_refused`. A switched-off
  input (V/01.4 Н1.4а) — the event is not written, `inputs_off` + 1: usually this is the operator's word, when in doubt (a corrupted setting) — a loss, and the counter shows it.
- An event notifies no one: it is a bucket row; it is read by the console, the resource and the scenarios.

### Н1.7 Subsystem file and timeouts

The subsystem file `/etc/cam/cam.env` (ADR-0091 addendum (2) item 3; `0644`, it holds no secrets) is read by the holder by
the [environment file contract](../../../Platform/common/contracts/env-file.md): there is no file — the defaults; the file is unreadable or

| Key | Read by | Grammar | Default | Norm |

| `SHM_DIR` | holder | an absolute path | `/run/vms-cam-shm` | Н1.3 |

| `MEDIA_DIR` | holder | an absolute path | `/data/platform/subsystems/cam/media` | chapter 3 |
| `LOG_LEVEL` | holder | `off` \| `error` \| `warning` \| `info` \| `debug` | `info` | the pace of looking at requests — the platform, chapter 4 |

`CAPACITY` is in `roles/camworker.env` (P/02.4 Н1.2). The stop timeout is the default `worker.stop_timeout` 20 s: the holder writes nothing
to disk, it has nothing to close for longer.

**Worker budget.** The memory of the `cam` worker is `B + n·I`: `B` — the process without cameras, `I` — per camera, `n` — the number of cameras;
`CAPACITY = ⌊(бюджет − B) / I⌋`. PSS is what is measured (shared libraries are shared between holders); RSS is an upper bound, good
for a margin. The manifest: `capacity: {default: 50, unit_mb: 1, base_mb: 18}` — an RSS measurement (2026-10-11, macOS/arm64, the median
of 6 measurements at 10 and 50 cameras, `unit_mb = (RSS50 − RSS10)/40`, `base_mb = RSS10 − 10·unit_mb`, +25 %); the memory rule —
[P/03.4 Н1.2](../../../Platform/03-worker/spec/03.4-worker.norms.md); the values of `CAPACITY` by deployment roles — lesson V/09.

## Н3 Pass

### Hold a camera (start_unit, P/03.1 Н2)

The order of the gate, the epoch, the opening of the secret and the restart — [P/03.3 Н3](../../../Platform/03-worker/spec/03.3-worker.norms.md)
step 2 and [P/03.2 Н3](../../../Platform/03-worker/spec/03.2-worker.norms.md) «взять_эпоху»; the holder's `start_unit`:

```
enabled: false (Н1.1) → do not start; the phase by Н1.1
stream: the main row is not fit (Н1.1) → pending, reason «main: …»; do not start
camera outside the licence (V/01.7 Н3) → do not start; phase unlicensed, reason
stream on a host other than the camera's, without its own cred_secret → device_state refused, phase pending, reason «credentials: …»; do not open
stream without its own cred_secret, the camera envelope did not open (Н1.2) → device_state refused, phase pending, reason «credentials: …»; do not open
address — the same channel as that of a camera which the holder already holds (Н1.2) → device_state busy, phase pending; do not open
address not read by the subsystem (syntax) → device_state refused, reason; do not open, without repeats; phase pending
eventsrc: the port is taken by an own row, the address 0.0.0.0, :: (Н1.2б) → device_state refused, reason; do not open, without repeats; phase pending
resolution, fps unreadable or stated both by the address and by the field (Н1.2а) → device_state refused, reason «settings: …»; do not open, without repeats; phase pending
open the connection (the password — Н1.2; opening the device — chapter 4 Н1.3):
  did not return within DEVICE_GRACE → device_state opening, phase pending; do not open again until it returns or DEVICE_OPEN_WAIT expires
  returned, the unit is gone, the row changed revision or born (chapter 4 Н1.3) → close the connection; not a failure, the current unit opens its own
  refused, no file (chapter 3), DEVICE_OPEN_WAIT expired → device_state opening; a start failure (P/03.3 retry: failed, stalled at RETRY_MAX)
type camera, live always, there is a consumer (Н1.2в) → stream with resolution, fps (Н1.2а); first frames → publish live_url, live_shm (Н1.3); phase running
type camera, live always, there is no consumer → phase idle; for a file the opening step is the file check (chapter 3); one has appeared — as the line above
type camera, live on-demand, there is a consumer (Н1.2в) → as live always with a consumer; none for IDLE_AFTER → end of stream, remove the addresses, phase held
stream running, no consumer for IDLE_AFTER → end of stream, remove the addresses, phase idle; the connection is held
otherwise (live on-demand without a consumer, a row that is not camera) → phase held; for a file the opening step is the file check (chapter 3)
eventsrc → the text source (Н1.2б); the units of a row of any kind → the tree from the root (chapter 4 Н1.4б)
stream fell (Н1.2) → remove the addresses; event silent (Н1.5); a work failure of the unit (P/03.3 retry)
```

**Address and opening — one rule** (chapters 3 and 4 refer here): an address that the subsystem does not read by syntax
(a scheme without a driver, a file name not by chapter 3 Н1.1) — `device_state: refused`, `reason`, it is not opened and not
repeated, phase `pending` (an edit of the row is a new attempt); a temporary failure (there is no file, the device refused to
open, the timeout `DEVICE_OPEN_WAIT` expired, chapter 4 Н1.3) — a start failure of the unit with the backoff of P/03.3 Н1.2, `device_state: opening`; an opening that has not returned within
`DEVICE_GRACE` — phase `pending`, `device_state: opening`, until it returns or the timeout expires.

### Release a camera (stop_unit)

```
stream: let the last frames reach the subscribers (end of stream), then stop; remove the delivery addresses; units — bottom up, the text source; close the connection; the opening has not returned yet — the reconciliation closes it (chapter 4 Н1.3)
```

The stop order of the worker (place writers, heartbeat, place, slot) — [P/03.4 Н3](../../../Platform/03-worker/spec/03.4-worker.norms.md)
«остановка по SIGTERM»; the holder holds no places.

### Store silence

`lease: {unconfirmed_max: forever}` ([P/03.2 Н1.6](../../../Platform/03-worker/spec/03.2-worker.norms.md)): the holder holds the
cameras while the store is silent, however long it is silent — data flows (delivery, events under the former epoch), actions wait
(commands — strict `may_act`, chapter 4). The rationale: frames and buckets carry the epoch in their name — a second writer gives a duplicate, not
corruption; a reader takes the new epoch; stopping the delivery would surely lose frames; on a box the store is on the same
disk — there is no one to hand the camera to.

**Races.** Two holders of one camera (a move, a fence): the epoch in the name of the bucket, of the stream and of the share file (Н1.3) separates them
(P/03.2); the second one releases by P/03.2 Н3 «отсечь» and deletes only its own share file (already deleted by the new holder — not an error). Two addresses of one channel
(Н1.2 «the same channel») that slipped past the door (V/01.1 Н3): one is open, the other one is
`busy`; which one opens first depends on the assignment order — both outcomes are allowed, there are no two connections.

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| the channel is already held by another camera | not held, `pending`, `device_state: busy` | the heartbeat, `/cameras` | remove one of the cameras |
| the address is not read by the subsystem (syntax) | not held, `pending`, `device_state: refused`, `reason`; without repeats | the heartbeat | fix the address |
| the device refused to open, there is no file, the opening did not return within `DEVICE_OPEN_WAIT` | a start failure (`failed`), `device_state: opening`; backoff of P/03.3 | the heartbeat, `stalled` at `RETRY_MAX` | the device, the network, the password, the file |
| the opening did not return within `DEVICE_GRACE` | not held, `pending`, `device_state: opening`; not opened again until it returns or the timeout expires (chapter 4 Н1.3) | the heartbeat, `devices_opening` | the device, the network |
| one setting in the address and in the field, `resolution`, `fps` unreadable | not opened, `pending`, `device_state: refused`, `reason` «settings: …»; without repeats | the heartbeat | keep one place |
| two `eventsrc` rows on a port of one server at one holder | the second one is not opened, `pending`, `device_state: refused`, `reason` «port: …» | the heartbeat | another port |
| the `eventsrc` address is `0.0.0.0`, `::` | not opened, `pending`, `device_state: refused`, `reason` «address: …» | the heartbeat | the server address or the name of the till |
| the event channel is lost | `held`, `device_state: lost`, the driver retries by itself | the heartbeat | the device, the network |
| `EventData` not in form | the row is dropped, `events_refused` | the metric | the driver |
| `type` is unreadable | not held, `pending`, `reason` «type: unreadable» | the heartbeat | an edit of the row will not help: `type` is fixed, a new row |
| the stream fell (8 s without a frame) | a work failure, the event `silent` | the event log, the heartbeat | — |
| there is no consumer | the stream is not read, phase `idle`, the connection is held (Н1.2в) | the heartbeat | create a recording, a detector or watch |
| the consumer is not read | it is considered present: the stream is open (Н1.2в) | the heartbeat | — |
| the camera row of a stream is not fit | the stream is not held, `pending`, `reason` «main: …» | the heartbeat | fix `main` or the camera |
| a stream on another host without its own `cred_secret` | not opened, `pending`, `device_state: refused`, `reason` «credentials: …» | the heartbeat | a password in the stream row |
| for a stream without its own password the camera envelope did not open | not opened, `pending`, `device_state: refused`, `reason` «credentials: …» | the heartbeat | the holder's keyring |
| the password did not open | the unit does not run, `phase: sealed` of the platform (P/03.5, P/03.4 Н1.1) | the heartbeat | the holder's keyring |
| an event is not written | the row is dropped, `events_refused` | the metric | — |
| an input is switched off by the operator | no event, `inputs_off` | the metric | switch the input on |
