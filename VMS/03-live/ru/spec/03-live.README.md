# V/03 Живое видео — инструкция для реализации

Что реализация подсистемы `live` делает и как проверить результат. Канон — нормы глав `03.K-live.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `7a875c75`.

Текст производный от `spec/03-live.README.md`, руками не правится: источник — английский [`spec/03-live.README.md`](../../spec/03-live.README.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

## Входы и их приоритет

- Канон — нормы глав `03.K-live.norms.md` (Н1–Н5 каждой главы; адреса `V/03.K Н…`).
- Канон манифеста — [`live.subsystem.yaml`](../../live.subsystem.yaml): байты как есть.
- [Контракт](../../spec/03-live.api.openapi.yaml) выражает формы HTTP-входов канона.
- Приёмка — [глава 1](../acceptance/1/README.md), [глава 3](../acceptance/3/README.md); стенд и словарь — [общий README приёмки VMS](../../../common/ru/acceptance/README.md); новых требований приёмка не вводит.
- Лекция (`ru/03-live.md`, для человека, в выгрузку не входит) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…` (их правит не VMS).

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

| Глава | Что есть у реализации | Проверка |
|---|---|---|

| V/03.3 | дверь шлюза по [OpenAPI](../../spec/03-live.api.openapi.yaml): маршрут `whep`, токен двери, выбор потока по размеру, оффер без trickle, разговор, отбой, пределы, журнал `live.view*`, CORS маршрута | чтением (стенд WHEP — позже), [приёмка 3](../acceptance/3/README.md) `@manual` |
| V/03.4 | ветвление (очередь ≤ 1 с, тройник без ветвей), PT из оффера, H.264/H.265 без перекодирования, записка `codec`, звук с исключением Н1.5 | чтением; тест выбора PT над офферами |

| V/03.6 | таблица `accounts` (только шлюз), двери `/live/accounts` через `door.pass` по [OpenAPI](../../spec/03-live.api.openapi.yaml), проверка имени и снятие грантов через свою консоль, вклад в книгу `stream-accounts` (один шлюз кластера), дверь RTSP с Digest и грантами | чтением (стенд воркера `live` — позже) |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam` (V/01), `rec` (V/02), затем `live` —
приёмка VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/03.5 Н1.1 | считать клиента RTSP зрителем, который держит строку раздачи | строку держат только зрители WHEP; клиент RTSP — в `sessions`, не в `viewers` |
| V/03.3 Н1.2 | отвечать на первый оффер до параметров потока | первый оффер открывает источник и ждёт параметров в `ICE_WAIT`; не пришли — 404 `not yet` |
| V/03.6 Н1.2 | снимать гранты удалённой учётки шлюзом | гранты снимает сверка домена; шлюз удаляет только строку |
| V/03.1 Н1.2 | объединять метки зрителей | метки задаёт первый зритель; другой сети — 409 и адрес раздачи |
| V/03.4 Н1.1 | брать кадры из доли `cam.shm` | стык подсистем — RTSP петли |
| V/03.4 Н1.5 | отказывать зрителю, если звука нет | звук не держит видео: ни `not yet`, ни 400 |
| V/03.3 Н1.2а | считать токен правом говорить | токен выдаёт `view`; право — исполненная просьба `talk` с `edit` |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; приёмка глав 1 проходит на платформе, прошедшей свою приёмку;
пункты чеклистов, отмеченные «чтением», подтверждены описанием реализации (раздел «Решает реализация» каждой главы).
Проверка схемы, загрузчика и стенда друг друга не подменяют.

## При расхождении

Порядок источников: нормы главы → OpenAPI → приёмка и векторы → лекция; платформа — нормы выгрузки пина VMS.
Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и предложением; норма
платформы — через «Архитектора». Дефект приёмки (ожидание против нормы) — тот же маршрут; закрытое решение
вносится в канон, а не остаётся в этой инструкции.
