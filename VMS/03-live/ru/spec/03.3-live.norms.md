# V/03.3 — Дверь WHEP: нормы

Канон главы 3 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `7a875c75` (поток на двери шлюза — `b41527f`).

Текст производный от en, руками не правится: источник — английский [`en/03.3-live.norms.en.md`](en/03.3-live.norms.en.md), правка идёт в него, русский пересобирается переводом (ADR-0121).

Зритель не доходит до воркера через консоль: страница спрашивает у консоли адрес двери шлюза и токен
(`GET /live/where/<cam>`) и несёт оффер на дверь сама — байты идут шлюз ↔ браузер мимо консоли (решение владельца 1,
ADR-0015). Глава нормирует дверь шлюза: маршрут `whep`, оффер и ответ одним обменом (WHEP без trickle), отбой, коды,
разговор, пределы, журнал и CORS. Медиапуть ответа — глава 4; конец сессий — глава 5.

Id норм — `V/03.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/ru/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `expires` токена — секунды Unix (договор токена двери); сроки двери — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — `door/keys` (проверка
токена); пишет — журнал двери `audit/liveworker/e1` (договор журнала событий «Журнал двери процесса»), пульс (`headroom`,
`sessions`). Сессии — только в памяти шлюза.

### Н1.1 Адрес и токен

- `door: {routes: [whep, talk]}` — маршруты-имена: допуск — токен двери консоли ([P/03.4 Н1.7](../../../Platform/03-worker/ru/spec/03.4-worker.norms.md)
  `door_admission` `token`; [договор токена двери](../../../Platform/common/contracts/door-token.md)). Адрес двери — правило
  `door_address` P/03.4 Н1.7 (с комплектом роли `liveworker` — `https://<SERVER_NAME>:<порт>`, без — петля), порт —
  `WHEP_PORT` файла подсистемы `/etc/live/live.env` (не задан или 0 — порт ОС); адрес — поле `url` пульса.
- Адрес и токен выдаёт консоль: `GET /live/where/<cam>` с правом `view` на камеру → `door: {url, token, expires, routes}`
  ([P/06.5](../../../Platform/06-console/ru/spec/06.5-console.norms.md) Н3 «`/where/<id>`»; TTL 120 с; журнал консоли
  `door.issued`). Дверь есть у шлюза, чей пульс держит раздачу: до первого прохода шлюза двери нет.
- Токен — `Authorization: Bearer` или `?t=` (P/03.4 Н3 «токен двери у держателя»); шлюз проверяет его по договору: `unit` —
  `live/<cam>` пути запроса, `holder` — свой экземпляр, `routes` содержит `whep`, не истёк. Токен, выданный до ухода раздачи из назначения шлюза
  (`expires` − 120 раньше момента, когда шлюз увидел уход), — 403: шлюз помнит ушедшие с запуска на срок токена, 120 с. Прочая не взятая — шаг 3 Н1.2, `not yet`: `/where` выдаёт токен по строке размещения, и оффер может прийти раньше прохода, а зритель может вернуться к созданной заново раздаче. Любой отказ токена — 403
  `{"error": "forbidden"}` без причины. Токен нужен для открытия и отбоя; идущий поток живёт сессией. Предел: права зрителя шлюз не судит — таблицы ролей и цепочек папок у него нет, — поэтому снятый грант, выключение человека, отзыв токена и смена папки камеры идущую сессию не закрывают; она кончается отбоем (Н1.3) или по главе 5, срока у неё нет, окна отзыва [P/08.4 Н1.3](../../../Platform/08-domain/ru/spec/08.4-domain.norms.md) её не называют. Новый оффер требует нового токена, а его — `view` у консоли.

### Н1.2 Оффер

`POST /whep/<cam>[?stream=<id> | ?width=<ш>&height=<в>]`, тело — оффер SDP (`Content-Type: application/sdp`). `stream` — поток
камеры, который зритель называет (V/01.1 Н1.1а: id её прочего потока); `width`, `height` — окно зрителя в пикселях, поток
выбирает шлюз. Токен — на раздачу камеры: поток выбирается внутри права на камеру.

**Выбор потока** — после шага 2, по памяти последнего прохода (глава 2 Н1.1), без хранилища и пульсов:

- `stream` не пуст — этот поток, размер не судит; нет `width`, `height` — основной; камера другого кластера (`ref:<ref>`) — основной;
- **кандидат** — поток камеры (основной и строки с её `main`), чей элемент `status[]` проход нашёл с `phase: running` или `idle` (V/01.2 Н1.2в), спрос на который проход не отверг (глава 2 Н1.2), чей размер
  известен и чей кодек есть в оффере (проверка шага 6). Размер потока — `resolution` его строки, пусто — `size` элемента (V/01.2 Н1.4);
  значение не по форме — размер не прочитан, другим значением не подменяется, поток не кандидат. Кодек потока — `codec` элемента, имя `rtpmap` (глава 4 Н1.2).
  Поля нет при сказанном `size` — кодек иной (V/01.2 Н1.4), поток не кандидат; нет и `size` — кодек не сказан, поток не отсеивается;
- кандидатов нет — основной;
- из кандидатов с шириной ≥ `width` и высотой ≥ `height` — самый мелкий; таких нет — самый крупный. Мера — ширина × высота; из равных
  основной, затем меньший id числом.

**Предел** (ADR-0104 п. 2): закрытый поток без потребителя, у которого `size` не сказан и `resolution` пуст, не кандидат, спроса на него нет, поэтому выбор по окну его не откроет: живое идёт основным, дороже. Лечит поле `res` строки потока или явный `stream`.

Выбранный поток идёт дальше как названный: шаг 3 и последующие судят его, спрос записывается на него. Выбор живёт один оффер:
сессия поток не меняет, смена окна идущую сессию не трогает (V/11.17 Н1.2).

1. токен (Н1.1) → иначе 403; `may_act` взятой раздачи ложно ([P/03.2 Н1.6](../../../Platform/03-worker/ru/spec/03.2-worker.norms.md)) — 403
   `{"error": "forbidden"}`: шлюз не отвечает после конца аренды (V/03.1 Н1.4);
2. `Content-Length` больше `MAX_OFFER` = 256 КиБ — 413 до чтения тела; не число — 400; тип тела (без параметров) не
   `application/sdp` — 415;
3. подписки потока нет (глава 2 Н1.1–Н1.2; камера другого кластера `ref:<ref>` — только основной поток, ветвь главы 2
   Н1.1):
   - камера `ref:<ref>`, непустой `stream` — сразу 404 `{"error": "stream refused", "detail": "stream <stream> is not of camera
     <cam>"}`, спрос не записывается;
   - проход отверг спрос на поток — 404 `{"error": "stream refused", "detail": <слова прохода>}` (`stream <stream> is not of
     camera <cam>`, `cam <cam> is a stream of <main>`, слова «источника нет» главы 2 Н1.4): страница говорит их зрителю;
   - спросов у раздачи уже столько, сколько потоков у камеры по последнему проходу (глава 2 Н1.1), а этого среди них нет —
     404 `{"error": "stream refused", "detail": "too many streams asked"}`, спрос не записывается;
   - иначе — 404 `{"error": "not yet"}`; оффер записывает спрос на поток (основной — тоже), следующий проход сверяет его и
     заводит подписку; страница повторяет (V/11);
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; иначе место занято на время ответа (`answering + 1`);
5. источник подписки закрыт (первый зритель) — оффер открывает его до ответа (глава 4 «при первом зрителе») и ждёт
   параметров потока (кодек, профиль) в том же бюджете `ICE_WAIT`; источник открывается одним оффером: оффер, заставший
   открытие, ждёт те же параметры в своём бюджете, второго соединения нет; не пришли — место освобождается, 404
   `{"error": "not yet"}`: источник остаётся открытым до `grace`, повтор страницы (V/11) находит кодек;
6. оффер без секции `m=video` или без типа нагрузки кодека раздачи (глава 4 Н1.3) — 400 `{"error": "bad offer", "detail":
   …}`: ответ без видео не собрать; профиль или кодек, который браузер может не сыграть, — записка `codec` (глава 4 Н1.4),
   не отказ;
7. ответ — без trickle: удалённое описание, ответ, локальное описание, сбор кандидатов ICE в пределах `ICE_WAIT` = 5 с от
   начала шага 5 — все кандидаты в теле ответа; сбор не кончился к сроку — ответ с собранными; ответа нет или ни одного
   кандидата — ветвь не остаётся, 500 `{"error": "answer failed"}`;
8. подписку сняли, пока готовился ответ, — сессия закрывается, 404 `{"error": "not yet"}` (спрос записан заново: страница
   повторяет, как на шаге 3);
9. **201**, тело — ответ SDP (`Content-Type: application/sdp`), `Location: /whep/session/<sid>?gateway=<имя шлюза>`; `sid` —
   128 случайных бит шестнадцатеричным текстом; сессия запоминает владельца — `user` токена оффера; журнал `live.view`.

Любой выход после шага 4 — `answering − 1`. Сборка ответа (поток без перекодирования, тип нагрузки из оффера, звук) — глава 4; секция звука ответа оффер не отвергает и не держит (глава 4 Н1.5).
Хранилище и пульсы на пути оффера не читаются: оффер ждёт только блокировку подписок и сессий (глава 2 Н3); `door/keys`
читается проходом и живёт в памяти: хранилище молчит — держится прочитанное; не читалось или `kid` нет — 403, страница идёт
за `/where`.

### Н1.2а Разговор

`POST /talk/<cam>/<n>`, тело — оффер SDP: звук браузера идёт через шлюз к `spk` номера `n` хозяина `<cam>` (V/01.4 Н1.4а, ADR-0102 доп. (9) п. 7). `<cam>` — id строки-хозяина, в том числе
`ipsrv`: раздача `live/<cam>` создаётся как обычно, кадры ей не нужны. Токен — Н1.1, `routes` содержит `talk`. Его выдаёт `view`, поэтому право говорить — не токен, а исполненная просьба `talk`
с правом `edit` на хозяина: без неё держатель отвечает `no call`.

1. токен → иначе 403; `may_act` ложно — 403;
2. тело — шаг 2 Н1.2;
3. по памяти последнего прохода, элемент `<cam>` пульса держателя: раздача не взята или проход её ещё не читал — 404 `{"error": "not yet"}`, страница повторяет; не прочитан (V/01 `cam-heartbeat-words`) — 503 `{"error": "unavailable"}`, не «динамика нет»; `talk` нет или номера `n` в нём нет — 404
   `{"error": "no speaker"}`; кодек `spk` шлюз не кодирует (глава 4 Н1.5) — 503 `unavailable`, `detail` — слово кодека;
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; иначе место занято на время ответа;
5. оффер без секции `m=audio` с портом ≠ 0 и направлением `sendonly` или `sendrecv` либо без `opus` в ней — 400 `{"error": "bad offer", "detail": …}`;
6. открыть поток `POST <talk.url>/<n>?user=<user токена>` листом роли `liveworker` (V/01.5 Н1.3): 404 `no call` — 404 `{"error": "not yet"}`, страница повторяет; 409 `busy` — 409
   `{"error": "busy"}`; иной отказ или нет ответа за `ICE_WAIT` — 503 `{"error": "unavailable", "detail": …}`;
7. ответ — как шаг 7 Н1.2, `ICE_WAIT` от начала шага 6; не собран — поток к держателю закрыт, 500 `{"error": "answer failed"}`;
8. **201**, тело — ответ SDP, `Location: /whep/session/<sid>?gateway=<имя шлюза>`; сессия запоминает владельца; журнал `live.talk`.

Любой выход после шага 4 — `answering − 1`. Сессия разговора кончается отбоем (Н1.3), уборкой (глава 5) или концом потока к держателю: устройство положило трубку, держатель ушёл, — `why: device`.
Шлюз закрывает поток к держателю вместе с сессией.

### Н1.3 Отбой

`DELETE /whep/session/<sid>[?gateway=<имя>]` со свежим токеном на раздачу этой сессии, сессии зрителя и разговора (Н1.2а) — одна последовательность:

1. токен действителен (подпись, срок, `holder` — свой экземпляр, `routes` содержит `whep`; Н1.1) → иначе 403
   `{"error": "forbidden"}`;
2. `gateway` — известный параметр отбоя (его ставит `Location` оффера): своё имя шлюза — как без него; чужое — 404
   `{"error": "no session"}`;
3. сессия `<sid>` есть → иначе 404 `{"error": "no session"}`;
4. `unit` токена — раздача этой сессии (`live/<cam>`) и `user` токена — владелец сессии → иначе 403 `{"error": "forbidden"}`;
5. сессия закрыта — **204**, журнал `live.view.ended`, у разговора — `live.talk.ended`.

Токен проверяется до сессии: без действительного токена, есть ли сессия, не узнать. Ушёл последний зритель — отсчёт отсрочки раздачи (глава 5). Иной метод на маршруте — 405
(`PATCH` — trickle — тоже), иной путь — 404.

### Н1.4 Пределы, журнал, CORS

- **Пределы** — `door_limits` P/03.4 Н1.7 (соединения 32, с адреса 8, заголовки за 5 с, темп); тело — `MAX_OFFER` = 256 КиБ
  байтами по `Content-Length` (знаками его не мерить), константа урока (`door_limits.other`).
- **Разбор входа** — общий разбор [P/01.1 Н2.1](../../../Platform/01-store/ru/spec/01.1-store.norms.md) через P/03.4 Н1.7
  `door_limits` (рамка тела, `chunked`, ранний отказ — тело дочитывается в пределах `MAX_OFFER` или соединение закрывается)
  с отступлениями: тело — SDP как есть (не JSON); путь — байт в байт после раскодирования процентов (`/whep/7/`, пустые
  сегменты, иной путь — 404); `stream` — раскодированное значение; повтор `stream`, `width` или `height`, повреждённый `%` или
  значение не UTF-8 после раскодирования — 400 `{"error": "bad query"}`; `width`, `height` — оба или ни одного, каждый по форме `^[1-9][0-9]*$`,
  величина не ограничена: иначе 400 `bad query`, и при непустом `stream` тоже; пустой `stream` — как без него; иных параметров оффер не
  читает. Отбой читает только
  `gateway`: повтор, повреждённый `%` или не UTF-8 — 400 `bad query`, пустой — как без него, иные параметры не читаются. При
  токене в `?t=` раньше действует договор токена двери — 403. Порядок: путь → метод → токен → query → тело. Слова отказов разбора:
  404 `no such path`, 405 `method not allowed`, 413 `toolarge`, 415 `not playable`.
- **Разбор `talk`** — как оффер; `<n>` не целое ≥ 1 — 404 `no such path`; query не читается.
- **Журнал** — общие поля журнала двери процесса (договор журнала событий) и сверх них: `live.talk` — `target` (хозяин), `of` (`live/<cam>`), `spk` (номер), `session`, `user`; `live.talk.ended` — те же, `seconds`, `why` (как ниже, и `device`); `live.view` — `target` (камера),
  `of` (`live/<cam>`), `stream` (поток оффера, названный или выбранный, пусто — основной; как у точки RTSP, глава 6), `session`, `user`;
  `live.view.ended` — те же и `seconds` (сколько смотрел, целые, от 201), `why` (`hangup` |
  `swept` | `reset` | `stopped`, глава 5). Строка без запроса (`swept`, `reset`, `stopped`, RTSP) — без `status`, `bytes`. Сбой
  записи журнала ответа не меняет, строка журнала воркера. Кто смотрел камеру — строка журнала.
- **CORS** — `cors` [договора сертификата роли](../../../Platform/common/contracts/role-certificate.md) через P/03.4 Н1.7, без
  своего перечня: странице хватает нормы (`Location` ответа оффера ей видна по договору).

### Н1.5 Кадр для выгрузки

Живой кадр выгрузки берётся у шлюза (ADR-0117 доп. (2) п. 3, доп. (4) п. 5): RTSP при живом просмотре не гарантирован, а
учётки потока у `exp` нет.

- **Маршрут** `GET /frame/<cam>?stream=<id>` — `{name: frame, role: [expworker]}` манифеста: процессный, слова класса `role`
  договора сертификата роли, как процессные маршруты `rec` (V/02.5 Н2); токена у него нет, браузеру он закрыт. Без комплекта —
  401 `no_role`. Право автора выгрузки на живое судит `backend` при создании заказа (V/11), журнал — `export.made` части.
- **Раздача.** Шлюз отдаёт кадр только раздачи, которую держит (`live/streams/<cam>` своего назначения, глава 1). Строку заводит
  и продлевает воркер `exp` (`worker.creates`, V/08.7 Н1.2), как первый зритель; иначе — 404 `not yet`.
- **Кадр.** `stream` — поток камеры, без него — основной (Н1.2). Подписка на поток есть — следующий ключевой кадр; нет —
  шлюз открывает её, как для первого зрителя (глава 2 Н1.2), и после ответа отсчитывает отсрочку `grace` (глава 5), как после
  ухода последнего зрителя. Ключевой кадр декодируется в JPEG полного размера потока, качество 90 (решение «Спецификации VMS»):
  `200 image/jpeg`. Ключевого кадра нет за `FRAME_WAIT` = 10 с (решение «Спецификации VMS») — 504 `{"error": "no frame"}`;
  источника нет — 404 `stream refused` со словами прохода, как у оффера (Н1.2).
- **Журнал** — `live.frame`: `of` (`live/<cam>`), `stream`, `worker` (имя из листа роли), `status`.

## Н3 Проход

```
оффер: путь → метод → токен и may_act → query → пределы тела → выбор потока → подписка есть? → место (answering + 1) → источник открыт? (первый зритель —
       открыть, ждать параметров) → тип нагрузки в оффере → ответ (всё ≤ ICE_WAIT, вне блокировки) → сессия, Location,
       live.view
отбой: токен → gateway → сессия есть? → раздача и владелец токена → закрыть, live.view.ended → последний ушёл → отсчёт
       отсрочки
```

**Гонки.** Два оффера на последнее место: `answering` считается под блокировкой — второй получает 503. Подписку сняли (сверка,
глава 2), пока готовился ответ, — шаг 8, сессия не остаётся. Токен истёк между оффером и отбоем — отбой просит новый
`/where` (страница — один раз).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токен нет, не тот, истёк; токен выдан до ухода раздачи (Н1.1); `may_act` ложно | 403 `forbidden` | страница | `/live/where` снова, один раз |
| тело больше 256 КиБ | 413 `toolarge` | страница | — |
| тело не SDP | 415 `not playable` | страница | — |

| подписку сняли, пока готовился ответ | 404 `not yet`, сессия закрыта | страница | повтор (V/11) |

## Н5 Приёмка

Приёмка 3 — по стенду с воркером `live`: без токена — 403, тело сверх предела — 413, не SDP — 415, отбой без токена — 403
(токен до сессии), отбой незнакомой сессии со своим токеном — 404 `no session`; ответ, поток и разговор — чтением (стенду нужен клиент WebRTC), шаги `@manual` [приёмки 3](../acceptance/3/README.md). Сценарии появятся со стендом WHEP (воркер `live`,
браузерный клиент); до него глава проверяется чтением и тестом реализации. Выбор потока по размеру при двух потоках — шаги `@manual`
[приёмки 3](../acceptance/3/README.md).
