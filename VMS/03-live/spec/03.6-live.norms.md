# V/03.6 — Учётки потоков и дверь RTSP: нормы

Канон главы 6 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `f6f3895` (точка RTSP потока — грант по камере, `b41527f`).

Устройство — видеостена, чужая VMS, аналитика — говорит RTSP с Digest и токенами домена не пользуется. Ему кластер заводит
**учётку потока**: имя и пароль, права — гранты, как у человека. Учётки хранит и обслуживает шлюз; страница управляет ими
через консоль своего кластера (`door.pass`); домен несёт их другим членам книгой `stream-accounts`, и RTSP-дверь шлюза
пускает учётку к камерам, на которые у неё грант. Форма — C5 ADR-0074.

Id норм — `V/03.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `at` — секунды Unix.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — строки таблицы
`live/accounts/<имя>`, вклад `live/stream-accounts/<слот>` ([P/03.7
Н1.2](../../../Platform/03-worker/spec/03.7-worker.norms.md)); читает — копии `domain/live/stream-accounts`,
`domain/member-list`, `domain/grants` (P/09.1 Н1.4; `worker.reads`, гранты — основа роли при `door.routes`, P/02.5
Н1.4); у кластера — держателя домена копии книги нет: шлюз читает строку своего кластера
`domain/live/stream-accounts/<CLUSTER>` — чтение и секретного читателя этой одной строки выводит генератор прав по
`CLUSTER` установщика (P/02.5 Н1.4, C02-OWN-BOOK-HOLDER-01 — с выгрузки `9519b94`, действует с перепина на рубеже Go
GREEN 01–10), манифест называет только копию, префикса нет (он открыл бы шлюзу доставки всех членов); пишет журнал двери
(`live.rtsp.*`).

### Н1.1 Таблица `accounts`

`tables: [accounts]` — списочная форма: семья для прав, CRUD консоли нет ([P/06.1 Н1.6](../../../Platform/06-console/spec/06.1-console.norms.md)
`list_form`); `worker.writes: [accounts]` — пишет только шлюз; страница не пишет учётки мимо двери шлюза.

```yaml
live/accounts/<имя>:  {doc: {name, disabled, at, by}, password_secret}
  name:             имя учётки — грамматика имени человека домена (P/08.4 Н1.1 name); одно пространство с людьми (Н1.3)
  disabled:         bool; отключённая не играет
  at, by:           когда и кто последний раз менял (by — доказанное имя человека)
  password_secret:  пароль — 32 случайных знака; конверт кольца кластера (договор запечатывания); читатель — шлюз
```

`secrets.readers`: `live/accounts/` — `worker`; `live/stream-accounts/` — `worker`, `domainagent`; копия
`domain/live/stream-accounts` — `worker`, `domainagent`, `domain`; строки держателя `domain/live/stream-accounts/` —
`domainagent`, `domain` ([P/02.5 Н1.3](../../../Platform/02-installer/spec/02.5-installer.norms.md)); строка своего кластера у
держателя — ещё и `worker` (выводит генератор прав, Н1). Удаление учётки — удаление строки, без надгробия: повторный
`DELETE` — 404.

### Н1.2 Двери учёток

Учётками управляет `admin` кластера (C5: своя консоль, `door.pass`): создание, пароль, отключение и удаление доменных прав не
требуют. `door: {pass: [accounts]}` — консоль кластера передаёт `/live/accounts…` живому шлюзу с дверью (наименьшее имя),
проверив право человека раньше: `view` — чтение, `admin` — запись ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md)
«Передача `door.pass`»: тело ≤ 1 МиБ, заголовки `Authorization`, `Content-Type`, `Idempotency-Key`, `X-Operator`; шлюза не
слышно — 503 «no worker of live with a door is heard»; шлюз не ответил за `PASS_WAIT` — 502).

**Допуск двери учёток у шлюза** — норма урока (C5 доп. 2026-10-14 (2) п. 2), не `door.routes`: имена `pass` и `routes` не
пересекаются (P/02.1). Под TLS (комплект роли `liveworker`) — сначала лист роли `console` по классу `role`
[договора сертификата роли](../../../Platform/common/contracts/role-certificate.md) как есть (нет листа — 401 `no_role`; ролей в
SAN не ровно одна — 403 `no_role`; роль не `console` — 403 `wrong_role`; подпись вне `sig` — 403 `bad_chain`; цепочка,
отвергнутая TLS, — отказ рукопожатия), затем — удостоверение человека, переданное консолью: шлюз проверяет его снова и
право `view`/`admin` по нему. Без комплекта — правило `no_kit` [P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md):
маршрут закрыт, 401 `no_role`, строка журнала при старте.

**Разбор входа** — общий разбор [P/01.1 Н2.1](../../../Platform/01-store/spec/01.1-store.norms.md) через P/03.4 Н1.7
`door_limits` с отступлениями: путь — байт в байт после передачи: пустой сегмент (`/live/accounts/`), лишний сегмент, иной путь,
`%`-кодирование не в UTF-8 — 404 `no such path`; имя в пути раскодировано, но не по грамматике — 400 `bad name`; query не
читается; тело — один объект JSON строго (UTF-8, повторный ключ, не конечное число) и без неизвестных полей
(`additionalProperties` OpenAPI), иначе 400 `bad body`; у `GET` и `POST …/password` тела нет — непустое тело не читается. Порядок: путь → метод → допуск → тело.

| Запрос | Ответ | Смысл |
|---|---|---|
| `GET /live/accounts` | 200 `{accounts: [{name, disabled, at, by}]}` | список; паролей нет |
| `POST /live/accounts {name}` | 201 `{account, password}` | новая учётка; пароль — **один раз**, в ответе |
| `POST /live/accounts/<имя>/password` | 200 `{account, password}` | новый пароль, прежний не действует |
| `PUT /live/accounts/<имя> {disabled}` | 200 `{account}` | включить или отключить |
| `DELETE /live/accounts/<имя>` | 200 `{deleted}` | удалить строку учётки; гранты снимает сверка домена (Н1.3); повтор — 404 |

Отказы — `{error, detail}`, слова `error` — закрытый перечень: 400 `bad body` — тело не по разбору или неизвестное поле,
400 `bad name` — имя (в пути или в теле) не по грамматике, 400 `bad disabled` — нет `disabled` или не bool; 401/403 —
допуск (выше, слова класса `role`); 403 `denied` — домен не дал проверить имя (Н1.3); 404 `no such path` — путь (выше),
404 `no such account` — учётки нет; 409 `name taken` — имя занято человеком домена или учёткой (Н1.3); 503 `unavailable`
— пароль не открылся или консоль не отвечает. Одно слово на случай; порядок — как «Разбор входа». `account` —
`{name, disabled, at, by}`.

### Н1.3 Имя, гранты, книга

- **Имя.** Перед созданием шлюз спрашивает `GET /domain/users` **через свою консоль** как этот человек (у процессов члена одна
  дорога к домену — его консоль, она передаёт маршрут держателю): человек с таким именем — 409. Домен отказал (401, 403) —
  403 `{error: "denied", detail: "checking the name needs view of the domain's people"}`, учётка не создаётся; домена нет
  (`domain/keys` нет) — проверяются только своя таблица и копия книги; консоль не ответила — 503. Без ранней проверки
  исключение имён держит сам домен (`exclusive_with`, `reverse`); ранняя проверка — удобство. Учётка того же имени — по
  своей таблице и своей копии книги; проверка по копии частичная: одно имя одновременно в двух кластерах — спор `unique`
  книги (ни одна не доставляется), он виден по индексу имён `domain/names/live/stream-accounts`
  ([P/08.5 Н1.7](../../../Platform/08-domain/spec/08.5-domain.norms.md)).
- **Гранты** — строки грантов домена с `subject` = имя учётки (на кластер, камеру или метки; P/08.4 Н3); дверь людей домена
  не даёт гранту учётки быть шире `view` (`names.stream-accounts/.grant: view`, P/08.5 Н1.7). **Гранты шлюз не снимает:**
  `DELETE` удаляет строку и отвечает 200, элемент уходит из вклада следующим пульсом, гранты снимает сверка процесса
  `domain` — строки грантов, чей `subject` не человек и не ключ ни одного индекса имён, снимаются раньше освобождения имени
  для `POST /domain/users` (запрос к платформе, P/08.4). Состояние «строки нет, гранты ещё есть» безопасно: учётки нет,
  играть ей нечем.
- **Книга.** `domain.books.stream-accounts: {from: live/stream-accounts/, key: name, pick: unique, to: to}`,
  `domain.names.stream-accounts/: {exclusive_with: domain/users, grant: view}`. Вклад `live/stream-accounts/<слот>` выводится
  из таблицы на каждом пульсе: пишет **один шлюз кластера** — живой с наименьшим именем слота среди услышанных за
  `PEER_LOST_AFTER` = 30 с, прочие пишут пустую строку; элемент на учётку `{name, to, disabled, password_secret}`, `to` — все
  члены `domain/member-list`; доставку по гранту отсекает сборщик (P/08.5 Н1.3 `grant`). Строка переписывается только при
  изменении. Книга — только в установленном домене (есть `domain/keys`).

### Н1.4 Дверь RTSP

- Включена портом `RTSP_PORT` файла подсистемы `/etc/live/live.env`; не задан — двери нет (строка журнала при старте).
  Адрес — P/03.4 Н1.7 `door_address`, схема `rtsp` (с комплектом роли `liveworker` — адреса `SERVER_NAME`, без — петля); в
  пульсе — поле `rtsp` (`rtsp://<SERVER_NAME>:<порт>`). Пределы — `door_limits`. RTSP без TLS (`rtsps` не вводится,
  ADR-0075 окно 2); пароль — Digest, не Basic.
- **Точка** — `/<поток>` (id строки `cam`) на каждый поток камеры кластера (V/01.1 Н1.1а), чей держатель `running` (пульсы
  `cam/heartbeats/*`, глава 2). **Камера точки** — строка `cam/cameras/<поток>`, если её `main` пуст, иначе строка, которую
  называет её `main`; строки потока или камеры нет — точки нет (RTSP 404). Источник — по правилу главы 2 Н1.1 для потока
  точки, одна подписка шлюза на пару (камера, поток) — глава 5 Н1.1: подписка раздачи этого шлюза на ту же пару — её (клиент
  RTSP строку раздачи не держит), иначе самостоятельная, открывается первым клиентом и закрывается через `LINGER` = 10 с после
  последнего; переходы между ними — без закрытия источника (глава 5 Н1.1). Клиент RTSP — сессия (`sessions`), ёмкость
  (`headroom`), ветвь (глава 4); в `viewers` раздачи он не входит.
- **Кто играет:** учётки своей таблицы и учётки других кластеров из копии книги `domain/live/stream-accounts` (у держателя
  домена — строка своего кластера `domain/live/stream-accounts/<CLUSTER>`, Н1), не `disabled`; учётка играет точку, если у неё грант `view` на кластер, на камеру точки или её
  метки (по камере, не по строке потока: у потока меток нет, V/01.1 Н1.1а)
  (копия `domain/grants`, читается раз за проход: отзыв и истечение действуют со следующего прохода). Иначе — 401 (Digest
  заново) или 403.
- **Нечитаемая книга — не отсутствующая** (форма элемента — семья [`stream-accounts-entry`](../data/stream-accounts-entry.schema.json)):
  элемент копии (у держателя — строки своего кластера) не по форме или конверт `password_secret` не открывается (договор
  запечатывания) — для этой учётки шлюз держит элемент, прочитанный последним с запуска; такого нет — учётка не играет;
  строка журнала без значений; прочие элементы идут. Книга целиком не читается или хранилище не ответило — последняя
  прочитанная с запуска копия; прочитанной нет — играют только учётки своей таблицы.
- **Журнал** — `live.rtsp.play` (`user` — учётка, `target` — камера точки, `of` — `live/<cam>`: раздача камеры точки,
  V/03.1 Н1.1, `stream` — поток точки, `session`, `addr`) и
  `live.rtsp.ended` (те же и `seconds`).

## Н2 Двери

Учётки — [OpenAPI урока](03-live.api.openapi.yaml) (`/live/accounts…`, через `door.pass` консоли); дверь RTSP — RTSP
(RFC 2326/7826) с Digest, не HTTP.

## Н3 Проход

```
вклад (первый шлюз кластера): элементы из таблицы accounts → live/stream-accounts/<слот>, при изменении; прочие — пустая строка
дверь RTSP: точки — камеры с running держателем; учётки — своя таблица + копия книги; гранты — копия domain/grants (раз за проход)
двери учёток — по запросу (door.pass): путь → метод → допуск (лист console, затем человек) → тело → операция
```

**Гонки.** Два кластера создали учётку одного имени одновременно — спор `unique` книги, не доставляется ни одна, индекс имён
показывает обе; оператор переименовывает. Два шлюза кластера сочли себя первыми — оба пишут одинаковые элементы: `pick:
unique` у одного члена — повтор ключа снимает вклад члена (`bad_contribution`) до следующего прохода; поэтому прочие пишут
**пустую** строку, как только слышат шлюз меньшего имени.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| шлюза нет | 503 (передача) | страница | поднять шлюз |
| нет `admin` на запись | 403 (сторожевая консоли) | страница | — |
| нет листа `console` под TLS; без комплекта | 401 `no_role` (403 `no_role`/`wrong_role`/`bad_chain`) | консоль, журнал | комплект роли |
| домен не дал проверить имя | 403 `denied` | страница | право `view` на людей домена |
| имя занято человеком или учёткой | 409 `name taken` | страница | другое имя |
| пароль не открылся, консоль не отвечает | 503 `unavailable` | страница | — |
| тело не по разбору или неизвестное поле; имя не по грамматике; нет `disabled` или не bool | 400 `bad body`; `bad name`; `bad disabled` | страница | исправить запрос |
| путь не дверь учёток; учётки нет | 404 `no such path`; `no such account` | страница | — |
| учётка без гранта на камеру | 403 RTSP | устройство | грант `view` |
| учётка отключена или неверный пароль | 401 RTSP | устройство | — |
| элемент книги учёток не по форме, конверт не открылся | прежний элемент с запуска, нет — учётка не играет | журнал шлюза | починить вклад кластера-владельца |

## Н5 Приёмка

Приёмка 6 — учётки через `door.pass` на стенде с воркером `live` с комплектом роли (лист `console` у консоли): создание
(пароль в ответе один раз), список без паролей, новый пароль, отключение, удаление, повторное удаление — 404, 400 по имени,
404; 409 по имени человека, 403 `denied` проверки имени и снятие грантов сверкой домена — стенд с доменом; игра по
RTSP — чтением (у стенда нет клиента RTSP с Digest). Сценарии появятся со стендом воркера `live`; до него — чтением.

---

## Решает реализация

Реализация обязана назвать в своём описании: **RTSP-сервер с Digest** (библиотека; как запоминает проверенную учётку за
клиентом до `PLAY`) и **кэш HA1**, если он есть. Пароль в строке и в книге — открываемый секрет (C5, ADR-0074); HA1 —
только местный кэш шлюза из пароля и своего `realm`, в строку и во вклад он не пишется.

## Соответствие прежним урокам

Из М12B/01 шаг 6а — учётки RTSP, имена в одном пространстве с людьми, книга, дверь RTSP шлюза, журнал игры; форма — C5
ADR-0074 и её поправки (списочная таблица в `worker.writes`, `door.pass`, дорога шлюза к домену через свою консоль).
Отличия от свидетеля: `domain/cam/stream-clients/*`, книга `cam.stream-accounts`, `kept: [stream-clients/]`, двери
`/stream-clients…` и `DOMAIN_CONSOLE_URL` — сняты (C5): таблица `live/accounts`, двери `/live/accounts` через `door.pass`,
книга `live.stream-accounts`; переменная двери RTSP — `RTSP_PORT` файла подсистемы `live` (у свидетеля — `LIVE_RTSP_LISTEN`);
шлюза не слышно — 503 договора передачи (у C5 — 409; решение плана 5). Id ([id-map](../../common/id-map.tsv)): М12B/01
ш.6а → V/03.6-01…04.
