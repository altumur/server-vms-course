# V/03.6 — Учётки потоков и дверь RTSP: нормы

Канон главы 6 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `79c08b27` (точка RTSP потока — грант по камере, `b41527f`).

Устройство — видеостена, чужая VMS, аналитика — говорит RTSP с Digest и токенами домена не пользуется. Ему кластер заводит
**учётку потока**: имя и пароль, права — гранты, как у человека. Учётки хранит и обслуживает шлюз; страница управляет ими
через консоль своего кластера (`door.pass`); домен несёт их другим членам книгой `stream-accounts`, и RTSP-дверь шлюза
пускает учётку к камерам, на которые у неё грант. Форма — C5 ADR-0074.

Id норм — `V/03.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `at` — секунды Unix.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — строки таблицы
`live/accounts/<имя>`, вклад `live/stream-accounts/<слот>` ([P/03.7
Н1.2](../../../Platform/03-worker/spec/03.7-worker.norms.md)); читает — копии `domain/live/stream-accounts`,
`domain/grants` (P/09.1 Н1.4; `worker.reads`, гранты — основа роли при `door.routes`, P/02.5
Н1.4); у кластера — держателя домена копии книги нет: шлюз читает строку своего кластера
`domain/live/stream-accounts/<CLUSTER>` — чтение и секретного читателя этой одной строки выводит генератор прав по
`CLUSTER` установщика (P/02.5 Н1.4, C02-OWN-BOOK-HOLDER-01), манифест называет только копию, префикса нет (он открыл бы
шлюзу доставки всех членов). Кластер держит домен — запись `domain/holder` своего хранилища (основа роли, P/02.5 Н1.4) проходит
`record` и называет этот кластер; не прошла — признак не поднят, читаются копии, причина в журнал. Пишет журнал двери (`live.rtsp.*`).

### Н1.1 Таблица `accounts`

`tables: [accounts]` — списочная форма: семья для прав, CRUD консоли нет ([P/06.1 Н1.6](../../../Platform/06-console/spec/06.1-console.norms.md)
`list_form`); `worker.writes: [accounts]` — пишет только шлюз; страница не пишет учётки мимо двери шлюза.

```yaml
live/accounts/<имя>:  {doc: <текст JSON {name, disabled, at, by}>, password_secret, revision}
  name:             имя учётки — грамматика имени человека домена (P/08.4 Н1.1 name); одно пространство с людьми (Н1.3)
  disabled:         bool; отключённая не играет
  at, by:           когда и кто последний раз менял (by — доказанное имя человека)
  password_secret:  пароль — 32 знака base64url из 24 случайных байт; конверт кольца кластера (договор запечатывания); читатель — шлюз
  revision:         поле платформы, ведёт база воркера (P/03.4 Н1.6); конфликт cas — перечитать и посчитать заново
```

Секрет таблицы запечатывает шлюз при записи и сам перезапечатывает при старте ([P/03.4 Н1.6](../../../Platform/03-worker/spec/03.4-worker.norms.md)
`list_secret`), `revision` при этом не меняется.

`secrets.readers`: `live/accounts/` — `worker`; `live/stream-accounts/` — `worker`, `domainagent`; копия
`domain/live/stream-accounts` — `worker`, `domainagent`, `domain`; строки держателя `domain/live/stream-accounts/` —
`domainagent`, `domain` ([P/02.5 Н1.3](../../../Platform/02-installer/spec/02.5-installer.norms.md)); строка своего кластера у
держателя — ещё и `worker` (выводит генератор прав, Н1). Удаление учётки — удаление строки, без надгробия: повторный
`DELETE` — 404.

### Н1.2 Двери учёток

Учётками управляет `admin` кластера (C5: своя консоль, `door.pass`): пароль, отключение и удаление доменных прав не
требуют; создание в домене требует ещё `view` на людей домена — этим правом шлюз проверяет имя (Н1.3). `door: {pass: [accounts]}` — консоль кластера передаёт `/live/accounts…` живому шлюзу с дверью
(наименьшее имя) путём `/accounts…` без префикса монтирования (при любом корне; договор передачи,
C06-DOOR-PASS-PATH-01), проверив право человека раньше: `view` на что-либо — чтение, `admin` на `*` — запись (`admin` одной
камеры записи не даёт; аварийная сессия к шлюзу не передаётся — 403 `denied` у консоли; [договор сторожевой и
передачи](../../../Platform/common/contracts/gate-and-pass.md) «Передача `door.pass`»: тело ≤ 1 МиБ, заголовки
`Authorization`, `Content-Type`, `Idempotency-Key`, `X-Operator`; шлюза не слышно — 503 «no worker of live with a door
is heard»; шлюз не ответил за `PASS_WAIT` — 502).

**Допуск двери учёток у шлюза** — норма урока (C5 доп. 2026-10-14 (2) п. 2), не `door.routes`: имена `pass` и `routes` не
пересекаются (P/02.1). Под TLS (комплект роли `liveworker`) — сначала лист роли `console` по классу `role`
[договора сертификата роли](../../../Platform/common/contracts/role-certificate.md) как есть (нет листа — 401 `no_role`; ролей в
SAN не ровно одна — 403 `no_role`; роль не `console` — 403 `wrong_role`; подпись вне `sig` — 403 `bad_chain`; цепочка,
отвергнутая TLS, — отказ рукопожатия), затем — удостоверение человека, переданное консолью: токен в `Authorization: Bearer`
(токен куки консоль кладёт туда же); шлюз проверяет его снова функцией `token` с `expect {kind: person, cluster: null}`, нет или
неверен — 401 `denied`; домена нет (`domain/keys` нет) — проверять нечем, допуск — лист `console`, `by` — `operator`; право
`view`/`admin` решает сторожевая консоли раньше ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md) «Передача `door.pass`»): таблицы ролей у шлюза нет. Без комплекта — правило `no_kit` [P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md):
маршрут закрыт, 401 `no_role`, строка журнала при старте.

**Разбор входа** — общий разбор [P/01.1 Н2.1](../../../Platform/01-store/spec/01.1-store.norms.md) через P/03.4 Н1.7
`door_limits` с отступлениями: путь — байт в байт после передачи: пустой сегмент (`/accounts/`), лишний сегмент, иной
путь, `%`-кодирование не в UTF-8 — 404 `no such path`; имя в пути раскодировано, но не по грамматике — 400 `bad name`;
query не читается; тело — один объект JSON строго (UTF-8, повторный ключ, не конечное число) и без неизвестных полей
(`additionalProperties` OpenAPI), иначе 400 `bad body`; у `GET`, `DELETE` и `POST …/password` тела нет — непустое тело не
читается. Порядок: путь → метод → допуск → тело.

| Запрос | Ответ | Смысл |
|---|---|---|
| `GET /live/accounts` | 200 `{accounts: [{name, disabled, at, by}]}` | список; паролей нет |
| `POST /live/accounts {name}` | 201 `{account, password}` | новая учётка; пароль — **один раз**, в ответе |
| `POST /live/accounts/<имя>/password` | 200 `{account, password}` | новый пароль, прежний не действует |
| `PUT /live/accounts/<имя> {disabled}` | 200 `{account}` | включить или отключить |
| `DELETE /live/accounts/<имя>` | 200 `{deleted}` | удалить строку учётки; гранты снимает сверка домена (Н1.3); повтор — 404 |

Отказы — `{error, detail}`, слова `error` — закрытый перечень: 400 `bad body` — тело не по разбору или неизвестное поле,
400 `bad name` — нет `name`, не строка или имя (в пути или в теле) не по грамматике, 400 `bad disabled` — нет `disabled` или не
bool; 401/403 — допуск (выше, слова класса `role`), 401 `denied` — удостоверения нет или неверно; 403 `denied` — домен не дал
проверить имя (Н1.3); 404 `no such path` — путь (выше), 404 `no such account` — учётки нет; 405 `method not allowed`; 409
`name taken` — имя занято человеком домена, учёткой или строкой гранта (Н1.3); 413 `toolarge`; 503 `busy` — пределы двери; 503 `unavailable`
— пароль не открылся или консоль не отвечает. Одно слово на случай; порядок — как «Разбор входа». `account` —
`{name, disabled, at, by}`.

### Н1.3 Имя, гранты, книга

- **Имя.** Порядок проверки: своя таблица, домен, копия книги. Перед созданием шлюз спрашивает `GET /domain/users` **через свою консоль** как этот человек (у процессов члена одна
  дорога к домену — его консоль, она передаёт маршрут держателю): человек с таким именем — 409. Той же дорогой — `GET /domain/grants`: строка с
  `subject` = этому имени в любом кластере — 409: это гранты другой учётки или прежней, которые сверка ещё не сняла, и имя свободно только после снятия, как у
  двери людей (P/08.4 Н3, шаг 7а). Домен отказал (401, 403) —
  403 `{error: "denied", detail: "checking the name needs view of the domain's people"}`, учётка не создаётся; домена нет
  (`domain/keys` нет) — проверяются только своя таблица и копия книги; консоль не ответила или ответила иначе, чем 200, 401,
  403, — 503 `unavailable`. Без ранней проверки
  исключение имён держит сам домен (`exclusive_with`, `reverse`); ранняя проверка — удобство: исключения она не держит, но её отказ учётку не создаёт. Учётка того же имени — по
  своей таблице и своей копии книги; проверка по копии частичная: одно имя одновременно в двух кластерах — спор `unique`
  книги (ни одна не доставляется), он виден по индексу имён `domain/names/live/stream-accounts`
  ([P/08.5 Н1.7](../../../Platform/08-domain/spec/08.5-domain.norms.md)).
- **Гранты** — строки грантов домена с `subject` = имя учётки (на кластер, камеру или метки; `sub` — нет или `live`, Н1.4; P/08.4 Н3); дверь людей
  домена не даёт гранту учётки быть шире `view` (`names.stream-accounts/.grant: view`, P/08.5 Н1.7). **Гранты шлюз не
  снимает:** `DELETE` удаляет строку и отвечает 200, элемент уходит из вклада следующим пульсом, гранты снимает сверка
  процесса `domain` — строки грантов, чей `subject` не человек и не ключ ни одного индекса имён, снимаются раньше
  освобождения имени для `POST /domain/users` (P/08.4 Н3, шаг 7а двери людей, C08-GRANTS-ORPHAN-01). Состояние «строки
  нет, гранты ещё есть» безопасно: учётки нет, играть ей нечем. Предел: гранты следуют за именем — учётка снята, а имя осталось ключом индекса у другого
  кластера (спор `unique`, Н3), — сверка строк не снимает, и они достаются его учётке; разводя спор, оператор проверяет гранты этого имени.
- **Книга.** `domain.books.stream-accounts: {from: live/stream-accounts/, key: name, pick: unique, to: to}`,
  `domain.names.stream-accounts/: {exclusive_with: domain/users, grant: view}`. Вклад `live/stream-accounts/<слот>` выводится
  из таблицы на каждом пульсе: пишет **один шлюз кластера** — живой с наименьшим именем слота среди услышанных за
  `PEER_LOST_AFTER` = 30 с, прочие пишут пустую строку; элемент на учётку `{name, to, disabled, password_secret}`, `to` — `"servers"`, все члены
  `class: server` прохода (P/08.5 `recipient`): копия на камере не нужна, шлюза там нет (ADR-0113 доп. (8) п. 4); доставку по гранту отсекает сборщик (P/08.5 Н1.3 `grant`). `password_secret` вклада — пароль
  строки таблицы, запечатанный под ключ вклада (P/03.7 Н1.2 `at_rest`); пароль не открылся — элемента нет, строка журнала.
  Строка переписывается только при изменении открытого содержимого. Книга — только в установленном домене (есть `domain/keys`).

### Н1.4 Дверь RTSP

- Включена портом `RTSP_PORT` файла подсистемы `/etc/live/live.env`; не задан — двери нет (строка журнала при старте).
  Адрес — P/03.4 Н1.7 `door_address`, схема `rtsp` (с комплектом роли `liveworker` — адреса `SERVER_NAME`, без — петля); в
  пульсе — поле `rtsp` (`rtsp://<SERVER_NAME>:<порт>`, без комплекта `rtsp://127.0.0.1:<порт>`; двери нет — поля нет). Пределы —
  `door_limits`; `door_limits.other`: `PACE_FLOOR` не действует на поток, `CONNECTIONS` = `capacity`. RTSP без TLS (`rtsps` не
  вводится, ADR-0075 окно 2); пароль — Digest, не Basic.
- **Точка** — `/<поток>` (id строки `cam`) на каждый поток камеры кластера (V/01.1 Н1.1а), чей держатель `running` или `idle` (пульсы
  `cam/heartbeats/*`, глава 2). `DESCRIBE` на точку `idle` — спрос (глава 2 Н1.5): он держится `LINGER` = 10 с от последнего `DESCRIBE`, ответ — RTSP 503 с `Retry-After: 1`: поток откроется, клиент повторит. **Камера точки** — строка `cam/cameras/<поток>`, если её `main` пуст, иначе строка, которую
  называет её `main`; строки потока или камеры нет — точки нет (RTSP 404). Источник — по правилу главы 2 Н1.1 для потока
  точки, одна подписка шлюза на пару (камера, поток) — глава 5 Н1.1: подписка раздачи этого шлюза на ту же пару — её (клиент
  RTSP строку раздачи не держит), иначе самостоятельная: её заводит сам клиент из источника прохода, открывает первым и ждёт
  параметров потока `ICE_WAIT` (не пришли — RTSP 503), закрывается она через `LINGER` = 10 с после
  последнего; переходы между ними — без закрытия источника (глава 5 Н1.1). Клиент RTSP — сессия (`sessions`), ёмкость
  (`headroom`), ветвь (глава 4); в `viewers` раздачи он не входит. `sessions + answering ≥ capacity` — RTSP 503; место занимается
  на `PLAY`.
- **Кто играет:** учётки своей таблицы и учётки других кластеров из копии книги `domain/live/stream-accounts` (у держателя
  домена — строка своего кластера `domain/live/stream-accounts/<CLUSTER>`, Н1), не `disabled`; другой кластер — `member` элемента
  копии ≠ свой, элемент своего кластера не читается: свою учётку решает таблица; учётка играет точку, если в копии `domain/grants` есть действующая строка
  её `subject` (`until` не вышел): ранг не ниже `view`, `sub` нет или `live` (как у доставки книги, P/08.5 Н1.3 `grant`), область — `*`, камера точки
  или её метки (по камере, не по строке потока: у потока меток нет, V/01.1 Н1.1а); строка `folder:` точки не открывает: цепочек папок шлюз не читает.
  Копия старше `as_of` + `GRANT_LIFETIME` прав не даёт ([договор права](../../../Platform/common/contracts/may.md) шаг 4);
  читается раз за проход: отзыв и истечение действуют со следующего прохода. Иначе — 401 (Digest
  заново) или 403. Копия не прочитана (строка есть, но не читается, хранилище не ответило) — проход и `PLAY` судят прочитанной последней с запуска, старость — по её
  `as_of`: отзыв с неё не приходит, но срок идёт; прочитанной нет — RTSP 503. Строки копии нет (домена нет или она ещё не пришла) — гранта нет: заведённая учётка
  не играет ни одной точки (RTSP 403), играть она начинает с грантом домена в копии. Проход закрывает идущие сессии учёток, которые больше не играют (отключена,
  удалена, гранта на точку нет, копия стара), журнал `live.rtsp.ended`; новый пароль идущую сессию не закрывает.
- **Нечитаемая книга — не отсутствующая** (форма элемента — семья [`stream-accounts-entry`](../data/stream-accounts-entry.schema.json)):
  элемент копии (у держателя — строки своего кластера) не по форме или конверт `password_secret` не открывается (договор
  запечатывания) — для этой учётки шлюз держит элемент, прочитанный последним с запуска; такого нет — учётка не играет;
  строка журнала без значений; прочие элементы идут. Элемента чужой учётки в прочитанной копии нет, а `member` её элемента, прочитанного последним с запуска, — в
  `missing` этой копии с причиной, по которой вклада нет (`silent`, `never`, `no_copy`, `bad_contribution`, `secret_unopened`; `unseen` вкладывает, и элемента в его вкладе нет: учётка удалена;
  [P/08.5 Н1.3](../../../Platform/08-domain/spec/08.5-domain.norms.md)): учётка неизвестна, а не удалена — шлюз держит тот элемент не дольше
  `GRANT_LIFETIME` от первой такой копии, срока кластера без связи; гранты судятся как обычно. Предел: отключение, новый пароль и удаление на молчащем кластере в
  этом окне до шлюза не доходят. Книга целиком не читается, хранилище не ответило или у держателя строки своего кластера ещё нет (окно после переноса, P/08.5 Н1.3 `contributes`) — последняя
  прочитанная с запуска копия; прочитанной нет — играют только учётки своей таблицы. Строка своей таблицы нечитаема — учётка
  держит прочитанное с запуска, такого нет — не играет, строка журнала; `GET` и запись — 503 `unavailable`.
- **Журнал** — `live.rtsp.play` (`user` — учётка, `target` — камера точки, `of` — `live/<cam>`: раздача камеры точки,
  V/03.1 Н1.1, `stream` — поток точки, пусто — основной, `session`, `addr`) и
  `live.rtsp.ended` (те же и `seconds`).

## Н2 Двери

Учётки — [OpenAPI урока](03-live.api.openapi.yaml) (`/live/accounts…`, через `door.pass` консоли); дверь RTSP — RTSP
(RFC 2326/7826) с Digest, не HTTP.

## Н3 Проход

```
вклад (первый шлюз кластера): элементы из таблицы accounts → live/stream-accounts/<слот>, при изменении; прочие — пустая строка
дверь RTSP: точки — камеры с running или idle держателем; учётки — своя таблица + копия книги; гранты — копия domain/grants (раз за проход);
закрыть идущие сессии учёток, которые больше не играют
двери учёток — по запросу (door.pass): путь → метод → допуск (лист console, затем человек) → тело → операция
```

**Гонки.** Два кластера создали учётку одного имени одновременно — спор `unique` книги, не доставляется ни одна, индекс имён
показывает обе; оператор переименовывает. Два шлюза кластера сочли себя первыми, в том числе новый первый, пока слот прежнего
ещё держат, — оба пишут одинаковые элементы: равные элементы одного члена — один вход ([P/08.5](../../../Platform/08-domain/spec/08.5-domain.norms.md)
Н3 шаг 4а, C08-BOOK-SAME-ITEM-01), вклад цел. Предел: учётка сменилась в этом окне — неравные элементы снимают вклад члена
(`bad_contribution`), пока строка прежнего слота не уйдёт. Прочие пишут **пустую** строку, как только слышат шлюз меньшего имени.

## Н5 Приёмка

Приёмка 6 — учётки через `door.pass` на стенде с воркером `live` с комплектом роли (лист `console` у консоли): создание
(пароль в ответе один раз), список без паролей, новый пароль, отключение, удаление, повторное удаление — 404, 400 по имени,
404; 409 по имени человека и по строке гранта, 403 `denied` проверки имени и снятие грантов сверкой домена — стенд с доменом; игра по
RTSP, в том числе RTSP 503 без прочитанной копии грантов, RTSP 403 без строки копии и срок элемента при `missing` — чтением (у стенда нет клиента RTSP с Digest). Сценарии появятся со стендом воркера `live`; до него — чтением.

---

## Решает реализация

Реализация обязана назвать в своём описании: **RTSP-сервер с Digest** (библиотека; как запоминает проверенную учётку за
клиентом до `PLAY`) и **кэш HA1**, если он есть. Пароль в строке и в книге — открываемый секрет (C5, ADR-0074); HA1 —
только местный кэш шлюза из пароля и своего `realm`, в строку и во вклад он не пишется.
