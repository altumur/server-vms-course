# V/03.6 — Учётки потоков и дверь RTSP: нормы

Канон главы 6 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `f6f3895` (точка RTSP потока — грант по камере, `b41527f`).

Устройство — видеостена, чужая VMS, аналитика — говорит RTSP с Digest и токенами домена не пользуется. Ему кластер заводит
**учётку потока**: имя и пароль, права — гранты, как у человека. Учётки хранит и обслуживает шлюз; страница управляет ими
через консоль своего кластера (`door.pass`); домен несёт их другим членам книгой `stream-accounts`, и RTSP-дверь шлюза
пускает учётку к камерам, на которые у неё грант. Форма — C5 ADR-0074.

Id норм — `V/03.6-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `at` — секунды Unix.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — строки таблицы
`live/accounts/<имя>`, вклад `live/stream-accounts/<слот>` ([P/03.7 Н1.2](../../../Platform/03-worker/spec/03.7-worker.norms.md));
читает — копии `domain/live/stream-accounts`, `domain/member-list`, `domain/grants` (P/09.1 Н1.4; `worker.reads`, гранты —
основа роли при `door.routes`, P/02.5 Н1.4); пишет журнал двери (`live.rtsp.*`).

### Н1.1 Таблица `accounts`

`tables: [accounts]` — списочная форма: семья для прав, CRUD консоли нет ([P/06.1 Н1.6](../../../Platform/06-console/spec/06.1-console.norms.md)
`list_form`); `worker.writes: [accounts]` — пишет только шлюз; страница не пишет учётки мимо двери шлюза.

```yaml
live/accounts/<имя>:  {doc: {name, disabled, at, by}, password_secret}
  name:             имя учётки — грамматика имени человека домена (P/08.4 Н1.1 name); одно пространство с людьми (Н1.3)
  disabled:         bool; отключённая не играет
  at, by:           когда и кто последний раз менял (by — доказанное имя человека)
  password_secret:  пароль — 32 случайных знака; конверт кольца кластера (договор запечатывания); читатель — шлюз
```

`secrets.readers`: `live/accounts/` — `worker`; `live/stream-accounts/` — `worker`, `domainagent`; копия
`domain/live/stream-accounts` — `worker`, `domainagent`, `domain`; строки держателя `domain/live/stream-accounts/` —
`domainagent`, `domain` ([P/02.5 Н1.3](../../../Platform/02-installer/spec/02.5-installer.norms.md)). Удаление учётки — удаление
строки, без надгробия.

### Н1.2 Двери учёток

`door: {pass: [accounts]}` — консоль кластера передаёт `/live/accounts…` живому шлюзу с дверью (наименьшее имя), проверив
право человека раньше: `view` — чтение, `admin` — запись ([договор сторожевой и передачи](../../../Platform/common/contracts/gate-and-pass.md)
«Передача `door.pass`»: тело ≤ 1 МиБ, заголовки `Authorization`, `Content-Type`, `Idempotency-Key`, `X-Operator`; шлюза не
слышно — 503 «no worker of live with a door is heard»; шлюз не ответил за `PASS_WAIT` — 502). Шлюз проверяет учётные данные
человека снова.

| Запрос | Ответ | Смысл |
|---|---|---|
| `GET /live/accounts` | 200 `{accounts: [{name, disabled, at, by}]}` | список; паролей нет |
| `POST /live/accounts {name}` | 201 `{account, password}` | новая учётка; пароль — **один раз**, в ответе |
| `POST /live/accounts/<имя>/password` | 200 `{account, password}` | новый пароль, прежний не действует |
| `PUT /live/accounts/<имя> {disabled}` | 200 `{account}` | включить или отключить |
| `DELETE /live/accounts/<имя>` | 200 `{deleted}` | удалить учётку и снять её гранты (Н1.3) |

Отказы — `{error, detail}`: 400 — имя не по грамматике, нет `disabled` или не bool; 404 — учётки нет; 409 `name taken` —
имя занято человеком домена или учёткой (Н1.3); 503 — пароль не открылся или консоль не отвечает. `account` —
`{name, disabled, at, by}`.

### Н1.3 Имя, гранты, книга

- **Имя.** Перед созданием шлюз спрашивает `GET /domain/users` **через свою консоль** как этот человек (у процессов члена одна
  дорога к домену — его консоль, она передаёт маршрут держателю): человек с таким именем — 409. Учётка того же имени — по
  своей таблице и своей копии книги; проверка по копии частичная: одно имя одновременно в двух кластерах — спор `unique`
  книги (ни одна не доставляется), он виден по индексу имён `domain/names/live/stream-accounts`
  ([P/08.5 Н1.7](../../../Platform/08-domain/spec/08.5-domain.norms.md)).
- **Гранты** — строки грантов домена с `subject` = имя учётки (на кластер, камеру или метки; P/08.4 Н3); дверь людей домена
  не даёт гранту учётки быть шире `view` (`names.stream-accounts/.grant: view`, P/08.5 Н1.7). `DELETE` снимает гранты на имя
  через свою консоль: `GET /domain/grants`, `PUT /domain/grants/<кластер>` без строк этого `subject`.
- **Книга.** `domain.books.stream-accounts: {from: live/stream-accounts/, key: name, pick: unique, to: to}`,
  `domain.names.stream-accounts/: {exclusive_with: domain/users, grant: view}`. Вклад `live/stream-accounts/<слот>` выводится
  из таблицы на каждом пульсе: пишет **один шлюз кластера** — живой с наименьшим именем слота среди услышанных за
  `PEER_LOST_AFTER` = 30 с, прочие пишут пустую строку; элемент на учётку `{name, to, disabled, password_secret}`, `to` — все
  члены `domain/member-list`; доставку по гранту отсекает сборщик (P/08.5 Н1.3 `grant`). Строка переписывается только при
  изменении. Книга — только в установленном домене (есть `domain/keys`).

### Н1.4 Дверь RTSP

- Включена портом `RTSP_PORT` файла подсистемы `/etc/live/live.env`; не задан — двери нет (строка журнала при старте).
  Адрес — P/03.4 Н1.7 `door_address`, схема `rtsp` (с комплектом роли `liveworker` — адреса `SERVER_NAME`, без — петля); в
  пульсе — поле `rtsp` (`rtsp://<SERVER_NAME>:<порт>`). Пределы — `door_limits`. RTSP без TLS (`rtsps` не вводится,
  ADR-0075 окно 2); пароль — Digest, не Basic.
- **Точка** — `/<поток>` (id строки `cam`) на каждый поток камеры кластера (V/01.1 Н1.1а), чей держатель `running` (пульсы
  `cam/heartbeats/*`, глава 2). **Камера точки** — строка `cam/cameras/<поток>`, если её `main` пуст, иначе строка, которую
  называет её `main`; строки потока или камеры нет — точки нет (RTSP 404). Источник — по правилу главы 2 Н1.1 для потока
  точки, одна подписка шлюза на поток: раздача этого шлюза с тем же потоком — её подписка, иначе своя, открывается первым
  клиентом и закрывается через `LINGER` = 10 с после последнего. Клиент RTSP — зритель: сессия, ёмкость (`headroom`),
  ветвь (глава 4).
- **Кто играет:** учётки своей таблицы и учётки других кластеров из копии книги `domain/live/stream-accounts` (у держателя
  домена — свои строки), не `disabled`; учётка играет точку, если у неё грант `view` на кластер, на камеру точки или её
  метки (по камере, не по строке потока: у потока меток нет, V/01.1 Н1.1а)
  (копия `domain/grants`, читается раз за проход: отзыв и истечение действуют со следующего прохода). Иначе — 401 (Digest
  заново) или 403.
- **Журнал** — `live.rtsp.play` (`user` — учётка, `target` — камера точки, `of` — `live/<имя>`: имя раздачи этого потока,
  V/03.1 Н1.1, `session`, `addr`) и
  `live.rtsp.ended` (те же и `seconds`).

## Н2 Двери

Учётки — [OpenAPI урока](03-live.api.openapi.yaml) (`/live/accounts…`, через `door.pass` консоли); дверь RTSP — RTSP
(RFC 2326/7826) с Digest, не HTTP.

## Н3 Проход

```
вклад (первый шлюз кластера): элементы из таблицы accounts → live/stream-accounts/<слот>, при изменении; прочие — пустая строка
дверь RTSP: точки — камеры с running держателем; учётки — своя таблица + копия книги; гранты — копия domain/grants (раз за проход)
двери учёток — по запросу (door.pass)
```

**Гонки.** Два кластера создали учётку одного имени одновременно — спор `unique` книги, не доставляется ни одна, индекс имён
показывает обе; оператор переименовывает. Два шлюза кластера сочли себя первыми — оба пишут одинаковые элементы: `pick:
unique` у одного члена — повтор ключа снимает вклад члена (`bad_contribution`) до следующего прохода; поэтому прочие пишут
**пустую** строку, как только слышат шлюз меньшего имени.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| шлюза нет | 503 (передача) | страница | поднять шлюз |
| нет `admin` на запись | 403 (сторожевая консоли) | страница | — |
| имя занято человеком или учёткой | 409 `name taken` | страница | другое имя |
| пароль не открылся, консоль не отвечает | 503 | страница | — |
| учётка без гранта на камеру | 403 RTSP | устройство | грант `view` |
| учётка отключена или неверный пароль | 401 RTSP | устройство | — |

## Н5 Приёмка

Приёмка 6 — учётки через `door.pass` на стенде с воркером `live`: создание (пароль в ответе один раз), список без паролей,
новый пароль, отключение, удаление, 400 по имени, 404; 409 по имени человека и снятие грантов — стенд с доменом; игра по
RTSP — чтением (у стенда нет клиента RTSP с Digest). Сценарии появятся со стендом воркера `live`; до него — чтением.

---

## Решает реализация

Реализация обязана назвать в своём описании: **RTSP-сервер с Digest** (библиотека; как запоминает проверенную учётку за
клиентом до `PLAY`) и хранение HA1 Digest, если пароль не хранится как есть.
