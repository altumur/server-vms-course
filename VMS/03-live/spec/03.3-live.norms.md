# V/03.3 — Дверь WHEP: нормы

Канон главы 3 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `180c6c5` (поток на двери шлюза — `b41527f`).

Зритель не доходит до воркера через консоль: страница спрашивает у консоли адрес двери шлюза и токен
(`GET /live/where/<cam>`) и несёт оффер на дверь сама — байты идут шлюз ↔ браузер мимо консоли (решение владельца 1,
ADR-0015). Глава нормирует дверь шлюза: маршрут `whep`, оффер и ответ одним обменом (WHEP без trickle), отбой, коды,
пределы, журнал и CORS. Медиапуть ответа — глава 4; конец сессий — глава 5.

Id норм — `V/03.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `expires` токена — секунды Unix (договор токена двери); сроки двери — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — `door/keys` (проверка
токена); пишет — журнал двери `audit/liveworker/e1` (договор журнала событий «Журнал двери процесса»), пульс (`headroom`,
`sessions`). Сессии — только в памяти шлюза.

### Н1.1 Адрес и токен

- `door: {routes: [whep]}` — маршрут-имя: допуск — токен двери консоли ([P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md)
  `door_admission` `token`; [договор токена двери](../../../Platform/common/contracts/door-token.md)). Адрес двери — правило
  `door_address` P/03.4 Н1.7 (с комплектом роли `liveworker` — `https://<SERVER_NAME>:<порт>`, без — петля), порт —
  `WHEP_PORT` файла подсистемы `/etc/live/live.env` (не задан или 0 — порт ОС); адрес — поле `url` пульса.
- Адрес и токен выдаёт консоль: `GET /live/where/<cam>` с правом `view` на камеру → `door: {url, token, expires, routes}`
  ([P/06.5](../../../Platform/06-console/spec/06.5-console.norms.md) Н3 «`/where/<id>`»; TTL 120 с; журнал консоли
  `door.issued`). Дверь есть у шлюза, чей пульс держит раздачу: до первого прохода шлюза двери нет.
- Токен — `Authorization: Bearer` или `?t=` (P/03.4 Н3 «токен двери у держателя»); шлюз проверяет его по договору: `unit` —
  `live/<cam>` пути запроса, `holder` — свой экземпляр, `routes` содержит `whep`, не истёк. Любой отказ токена — 403
  `{"error": "forbidden"}` без причины. Токен нужен для открытия и отбоя; идущий поток живёт сессией.

### Н1.2 Оффер

`POST /whep/<cam>[?stream=<id>]`, тело — оффер SDP (`Content-Type: application/sdp`). `stream` — поток камеры, который
зритель смотрит (V/01.1 Н1.1а: id её прочего потока); нет или пусто — основной. Токен — на раздачу камеры: поток выбирается
внутри права на камеру.

1. токен (Н1.1) → иначе 403;
2. `Content-Length` больше `MAX_OFFER` = 256 КиБ — 413 до чтения тела; не число — 400; тип тела не `application/sdp` — 415;
3. подписки этого потока нет (глава 2 Н1.1–Н1.2; камера другого кластера `ref:<ref>` — только основной поток, ветвь главы 2
   Н1.1):
   - проход отверг спрос на поток — 404 `{"error": "stream refused", "detail": <слова прохода>}` (`stream <stream> is not of
     camera <cam>`, слова «источника нет» главы 2 Н1.4): страница говорит их зрителю;
   - спросов у раздачи уже столько, сколько потоков у камеры по последнему проходу (глава 2 Н1.1), а этого среди них нет —
     404 `{"error": "stream refused", "detail": "too many streams asked"}`, спрос не записывается;
   - иначе — 404 `{"error": "not yet"}`; оффер записывает спрос на поток (основной — тоже), следующий проход сверяет его и
     заводит подписку; страница повторяет (V/08);
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; иначе место занято на время ответа (`answering + 1`);
5. источник подписки закрыт (первый зритель) — оффер открывает его до ответа (глава 4 «при первом зрителе») и ждёт
   параметров потока (кодек, профиль) в том же бюджете `ICE_WAIT`; не пришли — место освобождается, 404
   `{"error": "not yet"}`: источник остаётся открытым до `grace`, повтор страницы (V/08) находит кодек;
6. оффер без секции `m=video` или без типа нагрузки кодека раздачи (глава 4 Н1.3) — 400 `{"error": "bad offer", "detail":
   …}`: ответ без видео не собрать; профиль или кодек, который браузер может не сыграть, — записка `codec` (глава 4 Н1.4),
   не отказ;
7. ответ — без trickle: удалённое описание, ответ, локальное описание, сбор кандидатов ICE в пределах `ICE_WAIT` = 5 с от
   начала шага 5 — все кандидаты в теле ответа; не вышло — место освобождается, ветвь не остаётся, 500
   `{"error": "answer failed"}`;
8. подписку сняли, пока готовился ответ, — сессия закрывается, 404 `{"error": "not yet"}` (спрос записан заново: страница
   повторяет, как на шаге 3);
9. **201**, тело — ответ SDP (`Content-Type: application/sdp`), `Location: /whep/session/<sid>?gateway=<имя шлюза>`; `sid` —
   128 случайных бит шестнадцатеричным текстом; сессия запоминает владельца — `user` токена оффера; журнал `live.view`.

Сборка ответа (поток без перекодирования, тип нагрузки из оффера) — глава 4. Хранилище и пульсы на пути оффера не читаются:
оффер ждёт только блокировку подписок и сессий (глава 2 Н3).

### Н1.3 Отбой

`DELETE /whep/session/<sid>[?gateway=<имя>]` со свежим токеном на раздачу этой сессии — одна последовательность:

1. токен действителен (подпись, срок, `holder` — свой экземпляр, `routes` содержит `whep`; Н1.1) → иначе 403
   `{"error": "forbidden"}`;
2. `gateway` — известный параметр отбоя (его ставит `Location` оффера): своё имя шлюза — как без него; чужое — 404
   `{"error": "no session"}`;
3. сессия `<sid>` есть → иначе 404 `{"error": "no session"}`;
4. `unit` токена — раздача этой сессии (`live/<cam>`) и `user` токена — владелец сессии → иначе 403 `{"error": "forbidden"}`;
5. сессия закрыта — **204**, журнал `live.view.ended`.

Токен проверяется до сессии: без действительного токена, есть ли сессия, не узнать. Ушёл последний зритель — отсчёт отсрочки раздачи (глава 5). Иной метод на маршруте — 405
(`PATCH` — trickle — тоже), иной путь — 404.

### Н1.4 Пределы, журнал, CORS

- **Пределы** — `door_limits` P/03.4 Н1.7 (соединения 32, с адреса 8, заголовки за 5 с, темп); тело — `MAX_OFFER` = 256 КиБ
  байтами по `Content-Length` (знаками его не мерить), константа урока (`door_limits.other`).
- **Разбор входа** — общий разбор [P/01.1 Н2.1](../../../Platform/01-store/spec/01.1-store.norms.md) через P/03.4 Н1.7
  `door_limits` (рамка тела, `chunked`, ранний отказ — тело дочитывается в пределах `MAX_OFFER` или соединение закрывается)
  с отступлениями: тело — SDP как есть (не JSON); путь — байт в байт после раскодирования процентов (`/whep/7/`, пустые
  сегменты, иной путь — 404); `stream` — раскодированное значение; повтор `stream` или значение не UTF-8 после раскодирования — 400
  `{"error": "bad query"}`; пустой `stream` — основной; иных параметров оффер не читает. Отбой читает только `gateway`:
  повтор или не UTF-8 — 400 `bad query`, пустой — как без него, иные параметры не читаются. Порядок: путь → метод → токен →
  тело.
- **Журнал** — общие поля журнала двери процесса (договор журнала событий) и сверх них: `live.view` — `target` (камера),
  `of` (`live/<cam>`), `stream` (поток оффера, пусто — основной; как у точки RTSP, глава 6), `session`, `user`;
  `live.view.ended` — те же и `seconds` (сколько смотрел), `why` (`hangup` |
  `swept` | `reset` | `stopped`, глава 5). Кто смотрел камеру — строка журнала.
- **CORS** — `cors` [договора сертификата роли](../../../Platform/common/contracts/role-certificate.md) через P/03.4 Н1.7, без
  своего перечня: странице хватает нормы (`Location` ответа оффера ей видна по договору).

## Н2 Двери

Дверь шлюза — [OpenAPI урока](03-live.api.openapi.yaml): `POST /whep/{cam}`, `DELETE /whep/session/{session}`. Дверь
`/live/where/<cam>` — консоли (P/06.5).

## Н3 Проход

```
оффер: путь → метод → токен → пределы тела → подписка есть? → место (answering + 1) → источник открыт? (первый зритель —
       открыть, ждать параметров) → тип нагрузки в оффере → ответ (всё ≤ ICE_WAIT, вне блокировки) → сессия, Location,
       live.view
отбой: токен → gateway → сессия есть? → раздача и владелец токена → закрыть, live.view.ended → последний ушёл → отсчёт
       отсрочки
```

**Гонки.** Два оффера на последнее место: `answering` считается под блокировкой — второй получает 503. Подписку сняли (сверка,
глава 2), пока готовился ответ, — шаг 8, сессия не остаётся. Токен истёк между оффером и отбоем — отбой просит новый
`/where` (страница — один раз).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токен нет, не тот, истёк | 403 `forbidden` | страница | `/live/where` снова, один раз |
| тело больше 256 КиБ | 413 | страница | — |
| тело не SDP | 415 | страница | — |
| подписки ещё нет; параметры потока не пришли за `ICE_WAIT` (первый зритель) | 404 `not yet` | страница | повтор (V/08) |
| поток не этой камеры; у потока нет источника; спросов больше, чем потоков камеры | 404 `stream refused`, `detail` — слова прохода или `too many streams asked` | страница | слова зрителю, без повтора; другой поток |
| подписку сняли, пока готовился ответ | 404 `not yet`, сессия закрыта | страница | повтор (V/08) |
| шлюз полон | 503 `full` | страница, `headroom` | повтор; новые раздачи размещаются на других шлюзах, рост (`grows`) — по ждущим раздачам, не по зрителям занятой (глава 1 Н1.3) |
| оффер без видео или без типа нагрузки кодека раздачи | 400 `bad offer` | страница | — |
| повтор `stream` или `gateway`, значение не UTF-8 | 400 `bad query` | страница | — |
| путь не тот (`/whep/7/`, пустой сегмент) | 404 | страница | — |
| ответ не собран за 5 с | 500 `answer failed` | страница, журнал воркера | повтор |
| отбой: токен не тот | 403 `forbidden` | страница | `/live/where` снова |
| отбой: сессии нет или `gateway` чужой | 404 `no session` | страница | — |
| отбой чужой сессии (раздача или владелец не те) | 403 `forbidden` | страница | — |
| соединений сверх предела | 503 `busy`, `Retry-After: 1` | страница | повтор |

## Н5 Приёмка

Приёмка 3 — по стенду с воркером `live`: без токена — 403, тело сверх предела — 413, не SDP — 415, отбой без токена — 403
(токен до сессии), отбой незнакомой сессии со своим токеном — 404 `no session`; ответ и поток — чтением (стенду нужен клиент WebRTC). Сценарии появятся со стендом WHEP (воркер `live`,
браузерный клиент); до него глава проверяется чтением и тестом реализации.

---

## Решает реализация

Реализация обязана назвать в своём описании: **сборку ответа WebRTC** (библиотека, сбор кандидатов в пределах `ICE_WAIT`) и
команду запуска шлюза для «Стенда».
