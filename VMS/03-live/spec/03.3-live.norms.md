# V/03.3 — The WHEP door: norms

This English text is the source; the Russian translation `ru/spec/03.3-live.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 3 of lesson V/03 «Живое видео» (ADR-0080; the VMS module — ADR-0090). Lecture (`ru/03-live.md`, for people, not in the export),
[instructions](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), manifest [`live.subsystem.yaml`](../live.subsystem.yaml).
The platform is the export `cammeta-specs` `7a875c75` (the stream on the gateway door — `b41527f`).

The viewer does not reach the worker through the console: the page asks the console for the address of the gateway door and a token
(`GET /live/where/<cam>`) and carries the offer to the door itself — the bytes go gateway ↔ browser bypassing the console (the owner's decision 1,
ADR-0015). The chapter sets norms for the gateway door: the route `whep`, the offer and the answer in one exchange (WHEP without trickle), hangup, codes,
talk, limits, the log and CORS. The media path of the answer — chapter 4; the end of sessions — chapter 5.

Norm ids are `V/03.3-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../Platform/common/NORMATIVE-TERMS.md). The rules of the module «Платформа» are [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#n0-vocabulary).

## Н1 Form

**Time.** `expires` of the token is Unix seconds (the door token contract); the door's timeouts are the process's monotonic clock.

**Data** (the shared families of the [platform catalogue](../../../Platform/common/data/catalog.tsv)): reads — `door/keys` (token
verification); writes — the door log `audit/liveworker/e1` (the event log contract «Журнал двери процесса»), the heartbeat (`headroom`,
`sessions`). Sessions live only in the gateway's memory.

### Н1.1 Address and token

- `door: {routes: [whep, talk]}` — the routes are names: admittance is the console door token ([P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md)
  `door_admission` `token`; [the door token contract](../../../Platform/common/contracts/door-token.md)). The door address is the rule
  `door_address` of P/03.4 Н1.7 (with a kit of the role `liveworker` — `https://<SERVER_NAME>:<порт>`, without one — loopback), the port is
  `WHEP_PORT` of the subsystem file `/etc/live/live.env` (not set or 0 — an OS port); the address is the field `url` of the heartbeat.
- The address and the token are issued by the console: `GET /live/where/<cam>` with the right `view` on the camera → `door: {url, token, expires, routes}`
  ([P/06.5](../../../Platform/06-console/spec/06.5-console.norms.md) Н3 «`/where/<id>`»; TTL 120 s; the console log
  `door.issued`). A door exists at the gateway whose heartbeat holds the delivery: before the gateway's first pass there is no door.
- The token is `Authorization: Bearer` or `?t=` (P/03.4 Н3 «токен двери у держателя»); the gateway MUST verify it by the contract: `unit` is
  `live/<cam>` of the request path, `holder` is its own instance, `routes` contains `whep`, it has not expired. A token issued before the delivery left the gateway's assignment
  (`expires` − 120 earlier than the moment the gateway saw the departure) — 403: the gateway remembers the departed deliveries since its start for the token's lifetime, 120 s. Any other delivery that is not taken — step 3 of Н1.2, `not yet`: `/where` issues a token by the placement row, and the offer may arrive before the pass, and the viewer may return to a delivery created anew. Any token refusal is 403
  `{"error": "forbidden"}` without a reason. The token is needed for opening and for hangup; a running stream lives by the session. Limit: the gateway does not judge the viewer's rights — it has no table of roles and folder chains — therefore a revoked grant, switching a person off, revocation of a token and a change of the camera's folder do not close a running session; it ends by hangup (Н1.3) or by chapter 5, it has no deadline, the revocation windows of [P/08.4 Н1.3](../../../Platform/08-domain/spec/08.4-domain.norms.md) do not name it. A new offer requires a new token, and that one requires `view` at the console.

### Н1.2 Offer

`POST /whep/<cam>[?stream=<id> | ?width=<ш>&height=<в>]`, the body is an SDP offer (`Content-Type: application/sdp`). `stream` is the stream
of the camera that the viewer names (V/01.1 Н1.1а: the id of its other stream); `width`, `height` are the viewer's window in pixels, the gateway
chooses the stream. The token is for the camera's delivery: the stream is chosen within the right on the camera.

**Stream choice** — after step 2, by the memory of the last pass (chapter 2 Н1.1), without the store and heartbeats:

- `stream` is not empty — this stream, the size is not judged; no `width`, `height` — the main one; a camera of another cluster (`ref:<ref>`) — the main one;
- a **candidate** is a stream of the camera (the main one and the rows with its `main`) whose element `status[]` the pass found with `phase: running` or `idle` (V/01.2 Н1.2в), the demand for which the pass did not reject (chapter 2 Н1.2), whose size
  is known and whose codec is in the offer (the check of step 6). The size of a stream is `resolution` of its row, empty — `size` of the element (V/01.2 Н1.4);
  a value not in form — the size is not read, it is not substituted by another value, the stream is not a candidate. The codec of a stream is `codec` of the element, the `rtpmap` name (chapter 4 Н1.2).
  The field is absent while `size` is said — the codec is a different one (V/01.2 Н1.4), the stream is not a candidate; `size` is absent too — the codec is not said, the stream is not filtered out;
- there are no candidates — the main one;
- of the candidates with width ≥ `width` and height ≥ `height` — the smallest; there are none such — the largest. The measure is width × height; of equal ones
  the main one, then the one with the numerically smaller id.

**Limit** (ADR-0104 item 2): a closed stream without a consumer whose `size` is not said and whose `resolution` is empty is not a candidate, there is no demand for it, therefore the choice by window will not open it: live goes by the main stream, which costs more. The cure is the field `res` of the stream row or an explicit `stream`.

The chosen stream goes on as a named one: step 3 and the following ones judge it, the demand is recorded for it. The choice lives for one offer:
the session does not change the stream, a change of the window does not touch a running session (V/11.17 Н1.2).

1. token (Н1.1) → otherwise 403; `may_act` of the taken delivery is false ([P/03.2 Н1.6](../../../Platform/03-worker/spec/03.2-worker.norms.md)) — 403
   `{"error": "forbidden"}`: the gateway does not answer after the end of the lease (V/03.1 Н1.4);
2. `Content-Length` greater than `MAX_OFFER` = 256 KiB — 413 before reading the body; not a number — 400; the body type (without parameters) is not
   `application/sdp` — 415;
3. there is no subscription of the stream (chapter 2 Н1.1–Н1.2; a camera of another cluster `ref:<ref>` — only the main stream, the branch of chapter 2
   Н1.1):
   - a camera `ref:<ref>`, a non-empty `stream` — at once 404 `{"error": "stream refused", "detail": "stream <stream> is not of camera
     <cam>"}`, the demand is not recorded;
   - the pass rejected the demand for the stream — 404 `{"error": "stream refused", "detail": <слова прохода>}` (`stream <stream> is not of
     camera <cam>`, `cam <cam> is a stream of <main>`, the words «источника нет» of chapter 2 Н1.4): the page tells them to the viewer;
   - the delivery already has as many demands as the camera has streams by the last pass (chapter 2 Н1.1), and this one is not among them —
     404 `{"error": "stream refused", "detail": "too many streams asked"}`, the demand is not recorded;
   - otherwise — 404 `{"error": "not yet"}`; the offer records the demand for the stream (for the main one too), the next pass reconciles it and
     sets up the subscription; the page repeats (V/11);
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; otherwise a slot is taken for the time of the answer (`answering + 1`);
5. the source of the subscription is closed (the first viewer) — the offer opens it before the answer (chapter 4 «при первом зрителе») and waits for
   the stream parameters (codec, profile) within the same budget `ICE_WAIT`; the source is opened by one offer: an offer that finds the
   opening in progress waits for the same parameters within its own budget, there is no second connection; they did not arrive — the slot is released, 404
   `{"error": "not yet"}`: the source stays open until `grace`, the page's repeat (V/11) finds the codec;
6. an offer without a section `m=video` or without the payload type of the delivery's codec (chapter 4 Н1.3) — 400 `{"error": "bad offer", "detail":
   …}`: an answer without video cannot be assembled; a profile or codec that the browser may fail to play — the note `codec` (chapter 4 Н1.4),
   not a refusal;
7. the answer — without trickle: remote description, answer, local description, gathering of ICE candidates within `ICE_WAIT` = 5 s from
   the start of step 5 — all candidates in the answer body; gathering has not finished by the deadline — the answer with the gathered ones; no answer or not a single
   candidate — the branch does not remain, 500 `{"error": "answer failed"}`;
8. the subscription was removed while the answer was being prepared — the session is closed, 404 `{"error": "not yet"}` (the demand is recorded anew: the page
   repeats, as at step 3);
9. **201**, the body is the SDP answer (`Content-Type: application/sdp`), `Location: /whep/session/<sid>?gateway=<имя шлюза>`; `sid` is
   128 random bits as hexadecimal text; the session remembers its owner — `user` of the offer's token; the log `live.view`.

Any exit after step 4 — `answering − 1`. The assembly of the answer (the stream without transcoding, the payload type from the offer, sound) — chapter 4; the sound section of the answer neither rejects nor holds the offer (chapter 4 Н1.5).
The store and heartbeats are not read on the offer path: the offer waits only for the lock of subscriptions and sessions (chapter 2 Н3); `door/keys`
is read by the pass and lives in memory: the store is silent — what was read is kept; never read or no `kid` — 403, the page goes
for `/where`.

### Н1.2а Talk

`POST /talk/<cam>/<n>`, the body is an SDP offer: the browser's sound goes through the gateway to the `spk` with the number `n` of the owner `<cam>` (V/01.4 Н1.4а, ADR-0102 addendum (9) item 7). `<cam>` is the id of the owner row, including
`ipsrv`: the delivery `live/<cam>` is created as usual, it needs no frames. The token — Н1.1, `routes` contains `talk`. The token is issued for `view`, therefore the right to talk is not the token but an executed request `talk`
with the right `edit` on the owner: without it the holder answers `no call`.

1. token → otherwise 403; `may_act` is false — 403;
2. body — step 2 of Н1.2;
3. by the memory of the last pass, the element `<cam>` of the holder's heartbeat: the delivery is not taken or the pass has not read it yet — 404 `{"error": "not yet"}`, the page repeats; not read (V/01 `cam-heartbeat-words`) — 503 `{"error": "unavailable"}`, not «no speaker»; `talk` is absent or the number `n` is not in it — 404
   `{"error": "no speaker"}`; the gateway does not encode the codec of `spk` (chapter 4 Н1.5) — 503 `unavailable`, `detail` is the codec word;
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; otherwise a slot is taken for the time of the answer;
5. an offer without a section `m=audio` with port ≠ 0 and direction `sendonly` or `sendrecv`, or without `opus` in it — 400 `{"error": "bad offer", "detail": …}`;
6. open the stream `POST <talk.url>/<n>?user=<user токена>` with the role leaf of `liveworker` (V/01.5 Н1.3): 404 `no call` — 404 `{"error": "not yet"}`, the page repeats; 409 `busy` — 409
   `{"error": "busy"}`; another refusal or no answer within `ICE_WAIT` — 503 `{"error": "unavailable", "detail": …}`;
7. the answer — as step 7 of Н1.2, `ICE_WAIT` from the start of step 6; not assembled — the stream to the holder is closed, 500 `{"error": "answer failed"}`;
8. **201**, the body is the SDP answer, `Location: /whep/session/<sid>?gateway=<имя шлюза>`; the session remembers its owner; the log `live.talk`.

Any exit after step 4 — `answering − 1`. A talk session ends by hangup (Н1.3), by cleanup (chapter 5) or by the end of the stream to the holder: the device hung up, the holder left — `why: device`.
The gateway closes the stream to the holder together with the session.

### Н1.3 Hangup

`DELETE /whep/session/<sid>[?gateway=<имя>]` with a fresh token for the delivery of this session; for viewer sessions and talk sessions (Н1.2а) — one sequence:

1. the token is valid (signature, expiry, `holder` is its own instance, `routes` contains `whep`; Н1.1) → otherwise 403
   `{"error": "forbidden"}`;
2. `gateway` is a known hangup parameter (it is set by the `Location` of the offer): the gateway's own name — as without it; a foreign one — 404
   `{"error": "no session"}`;
3. the session `<sid>` exists → otherwise 404 `{"error": "no session"}`;
4. `unit` of the token is the delivery of this session (`live/<cam>`) and `user` of the token is the owner of the session → otherwise 403 `{"error": "forbidden"}`;
5. the session is closed — **204**, the log `live.view.ended`, for a talk — `live.talk.ended`.

The token is checked before the session: without a valid token one cannot learn whether the session exists. The last viewer has left — the countdown of the delivery's grace (chapter 5). Another method on the route — 405
(`PATCH` — trickle — too), another path — 404.

### Н1.4 Limits, log, CORS

- **Limits** — `door_limits` of P/03.4 Н1.7 (connections 32, per address 8, headers within 5 s, rate); the body — `MAX_OFFER` = 256 KiB
  in bytes by `Content-Length` (not measured in characters), a constant of the lesson (`door_limits.other`).
- **Input parsing** — the shared parsing of [P/01.1 Н2.1](../../../Platform/01-store/spec/01.1-store.norms.md) through P/03.4 Н1.7
  `door_limits` (body framing, `chunked`, early refusal — the body is read to the end within `MAX_OFFER` or the connection is closed)
  with deviations: the body is SDP as is (not JSON); the path — byte for byte after percent-decoding (`/whep/7/`, empty
  segments, another path — 404); `stream` — the decoded value; a repeat of `stream`, `width` or `height`, a damaged `%` or a
  value that is not UTF-8 after decoding — 400 `{"error": "bad query"}`; `width`, `height` — both or neither, each of the form `^[1-9][0-9]*$`,
  the magnitude is not limited: otherwise 400 `bad query`, also with a non-empty `stream`; an empty `stream` — as without it; the offer reads no other
  parameters. The hangup reads only
  `gateway`: a repeat, a damaged `%` or not UTF-8 — 400 `bad query`, empty — as without it, other parameters are not read. With the
  token in `?t=`, the door token contract applies earlier — 403. Order: path → method → token → query → body. The refusal words of parsing:
  404 `no such path`, 405 `method not allowed`, 413 `toolarge`, 415 `not playable`.
- **Parsing of `talk`** — as the offer; `<n>` is not an integer ≥ 1 — 404 `no such path`; the query is not read.
- **Log** — the shared fields of the process door log (the event log contract) and beyond them: `live.talk` — `target` (the owner), `of` (`live/<cam>`), `spk` (the number), `session`, `user`; `live.talk.ended` — the same, `seconds`, `why` (as below, and `device`); `live.view` — `target` (the camera),
  `of` (`live/<cam>`), `stream` (the stream of the offer, named or chosen, empty — the main one; as at the RTSP endpoint, chapter 6), `session`, `user`;
  `live.view.ended` — the same and `seconds` (how long watched, integers, from 201), `why` (`hangup` |
  `swept` | `reset` | `stopped`, chapter 5). A row without a request (`swept`, `reset`, `stopped`, RTSP) — without `status`, `bytes`. A failure
  to write the log does not change the answer; it is a row of the worker log. Who watched the camera is a log row.
- **CORS** — `cors` of the [role certificate contract](../../../Platform/common/contracts/role-certificate.md) through P/03.4 Н1.7, without
  a list of its own: the norm is enough for the page (the `Location` of the offer answer is visible to it by the contract).

### Н1.5 Frame for export

The live frame of an export is taken from the gateway (ADR-0117 addendum (2) item 3, addendum (4) item 5): RTSP is not guaranteed under live viewing, and
`exp` has no stream account.

- **Route** `GET /frame/<cam>?stream=<id>` — `{name: frame, role: [expworker]}` of the manifest: a process route, the words of the class `role`
  of the role certificate contract, as the process routes of `rec` (V/02.5 Н2); it has no token, it is closed to the browser. Without a kit —
  401 `no_role`. The export author's right to the live is judged by `backend` when the order is created (V/11), the log — `export.made` of the part.
- **Delivery.** The gateway MUST give a frame only of a delivery that it holds (`live/streams/<cam>` of its own assignment, chapter 1). The row is created
  and renewed by the worker `exp` (`worker.creates`, V/08.7 Н1.2), as a first viewer; otherwise — 404 `not yet`.
- **Frame.** `stream` is a stream of the camera, without it — the main one (Н1.2). There is a subscription to the stream — the next key frame; there is none —
  the gateway opens it, as for the first viewer (chapter 2 Н1.2), and after the answer counts down the grace `grace` (chapter 5), as after
  the last viewer leaves. The key frame is decoded into a JPEG of the stream's full size, quality 90 (a decision of «Спецификация VMS»):
  `200 image/jpeg`. No key frame within `FRAME_WAIT` = 10 s (a decision of «Спецификация VMS») — 504 `{"error": "no frame"}`;
  no source — 404 `stream refused` with the words of the pass, as at the offer (Н1.2).
- **Log** — `live.frame`: `of` (`live/<cam>`), `stream`, `worker` (the name from the role leaf), `status`.

## Н3 Pass

```
offer:  path → method → token and may_act → query → body limits → stream choice → subscription exists? → slot (answering + 1) → source open? (first viewer —
        open, wait for parameters) → payload type in the offer → answer (all ≤ ICE_WAIT, outside the lock) → session, Location,
        live.view
hangup: token → gateway → session exists? → delivery and owner of the token → close, live.view.ended → the last one left → countdown
        of grace
```

**Races.** Two offers for the last slot: `answering` is counted under the lock — the second gets 503. The subscription was removed (reconciliation,
chapter 2) while the answer was being prepared — step 8, the session does not remain. The token expired between the offer and the hangup — the hangup asks for a new
`/where` (the page — once).

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| no token, the wrong one, expired; the token was issued before the delivery left (Н1.1); `may_act` is false | 403 `forbidden` | the page | `/live/where` again, once |
| the body is larger than 256 KiB | 413 `toolarge` | the page | — |
| the body is not SDP | 415 `not playable` | the page | — |
| no subscription yet; the stream parameters did not arrive within `ICE_WAIT` (the first viewer) | 404 `not yet` | the page | repeat (V/11) |
| the stream is not of this camera; the stream has no source; more demands than the camera has streams | 404 `stream refused`, `detail` — the words of the pass or `too many streams asked` | the page | the words to the viewer, without a repeat; another stream |
| the subscription was removed while the answer was being prepared | 404 `not yet`, the session is closed | the page | repeat (V/11) |
| the owner has no `spk` with this number | 404 `no speaker` | the page | — |
| frame: no role leaf, the role is not `expworker` | 401 `no_role`, 403 `wrong_role` | the worker `exp` | — |
| frame: no key frame within `FRAME_WAIT` | 504 `no frame` | the worker `exp` | the outcome of the part `offline` (V/08.7 Н1.2) |
| the request `talk` is not executed yet, its deadline has passed, the delivery is new and the pass has not read it | 404 `not yet` | the page | repeat (V/11) |
| the speaker is busy (V/01.4 Н1.4а) | 409 `busy` | the page | later |
| the holder's heartbeat is not read, the codec of `spk` is not encoded, the holder did not answer | 503 `unavailable` | the page, `detail` | later |
| the gateway is full | 503 `full` | the page, `headroom` | repeat; placement counts deliveries, not viewers, growth (`grows`) — by waiting deliveries, not by the viewers of an occupied one (chapter 1 Н1.3) |
| an offer without video or without the payload type of the delivery's codec; a talk offer without `m=audio` for sending or without `opus` | 400 `bad offer` | the page | — |
| a repeat of `stream`, `width`, `height` or `gateway`, a damaged `%`, a value that is not UTF-8; `width`, `height` not in form or one without the other | 400 `bad query` | the page | — |
| the wrong path (`/whep/7/`, an empty segment); another method | 404 `no such path`; 405 `method not allowed` | the page | — |
| the answer is not assembled within 5 s, there are no candidates | 500 `answer failed` | the page, the worker log | repeat |
| hangup: the wrong token | 403 `forbidden` | the page | `/live/where` again |
| hangup: no session or a foreign `gateway` | 404 `no session` | the page | — |
| hangup of someone else's session (the delivery or the owner do not match) | 403 `forbidden` | the page | — |
| connections beyond the limit | 503 `busy`, `Retry-After: 1` | the page | repeat |

## Н5 Acceptance

Acceptance 3 — on a stand with the worker `live`: without a token — 403, a body beyond the limit — 413, not SDP — 415, hangup without a token — 403
(the token before the session), hangup of an unknown session with one's own token — 404 `no session`; the answer, the stream and the talk — by reading (the stand needs a WebRTC client), steps `@manual` of [acceptance 3](../acceptance/3/README.md). Scenarios will appear with the WHEP stand (the worker `live`,
a browser client); until then the chapter is checked by reading and by a test of the implementation. Stream choice by size with two streams — steps `@manual`
of [acceptance 3](../acceptance/3/README.md).
