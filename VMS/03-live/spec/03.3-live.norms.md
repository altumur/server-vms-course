# V/03.3 — Дверь WHEP: нормы

Канон главы 3 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), [OpenAPI](03-live.api.openapi.yaml), манифест [`live.subsystem.yaml`](../live.subsystem.yaml).
Платформа — выгрузка `cammeta-specs` `180c6c5`.

Зритель не доходит до воркера через консоль: страница спрашивает у консоли адрес двери шлюза и токен
(`GET /live/where/<поток>`) и несёт оффер на дверь сама — байты идут шлюз ↔ браузер мимо консоли (решение владельца 1,
ADR-0015). Глава нормирует дверь шлюза: маршрут `whep`, оффер и ответ одним обменом (WHEP без trickle), отбой, коды,
пределы, журнал и CORS. Медиапуть ответа — глава 4; конец сессий — глава 5.

Id норм — `V/03.3-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** `expires` токена — секунды Unix (договор токена двери); сроки двери — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — `door/keys` (проверка
токена); пишет — журнал двери `audit/liveworker/e1` (договор журнала событий «Журнал двери процесса»), пульс (`headroom`,
`sessions`). Сессии — только в памяти шлюза.

### Н1.1 Адрес и токен

- `door: {routes: [whep]}` — маршрут-имя: допуск — токен двери консоли ([P/03.4 Н1.7](../../../Platform/03-worker/spec/03.4-worker.norms.md)
  `door_admission` `token`; [договор токена двери](../../../Platform/common/contracts/door-token.md)). Адрес двери — правило
  `door_address` P/03.4 Н1.7 (с комплектом роли `liveworker` — `https://<SERVER_NAME>:<порт>`, без — петля), порт —
  `WHEP_PORT` файла подсистемы `/etc/live/live.env` (не задан или 0 — порт ОС); адрес — поле `url` пульса.
- Адрес и токен выдаёт консоль: `GET /live/where/<поток>` с правом `view` на камеру → `door: {url, token, expires, routes}`
  ([P/06.5](../../../Platform/06-console/spec/06.5-console.norms.md) Н3 «`/where/<id>`»; TTL 120 с; журнал консоли
  `door.issued`). Дверь есть у шлюза, чей пульс держит раздачу: до первого прохода шлюза двери нет.
- Токен — `Authorization: Bearer` или `?t=` (P/03.4 Н3 «токен двери у держателя»); шлюз проверяет его по договору: `unit` —
  `live/<поток>` пути запроса, `holder` — свой экземпляр, `routes` содержит `whep`, не истёк. Любой отказ токена — 403
  `{"error": "forbidden"}` без причины. Токен нужен для открытия и отбоя; идущий поток живёт сессией.

### Н1.2 Оффер

`POST /whep/<поток>`, тело — оффер SDP (`Content-Type: application/sdp`):

1. токен (Н1.1) → иначе 403;
2. `Content-Length` больше `MAX_OFFER` = 256 КиБ — 413 до чтения тела; не число — 400; тип тела не `application/sdp` — 415;
3. подписки раздачи ещё нет (проход её не завёл, глава 2) — 404 `{"error": "not yet"}`: страница повторяет (V/08);
4. `sessions + answering ≥ capacity` — 503 `{"error": "full"}`; иначе место занято на время ответа (`answering + 1`);
5. оффер без секции `m=video` или без кодека раздачи (глава 4) — 400 `{"error": "bad offer", "detail": …}`;
6. ответ — без trickle: удалённое описание, ответ, локальное описание, сбор кандидатов ICE не дольше `ICE_WAIT` = 5 с — все
   кандидаты в теле ответа; не вышло — место освобождается, ветвь не остаётся, 500 `{"error": "answer failed"}`;
7. подписку сняли, пока готовился ответ, — сессия закрывается, 404;
8. **201**, тело — ответ SDP (`Content-Type: application/sdp`), `Location: /whep/session/<sid>?gateway=<имя шлюза>`; `sid` —
   128 случайных бит шестнадцатеричным текстом; сессия запоминает владельца — `user` токена оффера; журнал `live.view`.

Сборка ответа (поток без перекодирования, тип нагрузки из оффера) — глава 4. Хранилище и пульсы на пути оффера не читаются:
оффер ждёт только блокировку подписок и сессий (глава 2 Н3).

### Н1.3 Отбой

`DELETE /whep/session/<sid>` со свежим токеном на раздачу этой сессии: сессии нет — 404 `{"error": "no session"}`; токен
не на её раздачу или `user` токена — не владелец сессии — 403 `{"error": "forbidden"}`; иначе сессия закрыта — **204**,
журнал `live.view.ended`. Ушёл последний зритель — отсчёт отсрочки раздачи (глава 5). Иной метод на маршруте — 405
(`PATCH` — trickle — тоже), иной путь — 404.

### Н1.4 Пределы, журнал, CORS

- **Пределы** — `door_limits` P/03.4 Н1.7 (соединения 32, с адреса 8, заголовки за 5 с, темп); тело — `MAX_OFFER` = 256 КиБ,
  константа урока (`door_limits.other`).
- **Журнал** — общие поля журнала двери процесса (договор журнала событий) и сверх них: `live.view` — `target` (камера),
  `of` (`live/<поток>`), `session`, `user`; `live.view.ended` — те же и `seconds` (сколько смотрел), `why` (`hangup` |
  `swept` | `reset` | `dropped` | `stopped`, глава 5). Кто смотрел камеру — строка журнала.
- **CORS** — P/03.4 Н1.7 `cors` (`CONSOLE_ORIGINS` — `w2c.env`, P/02.4 Н1.2; preflight до допуска; методы `POST`, `DELETE`, заголовок `Content-Type`,
  `Expose-Headers: Location`; заголовки CORS — на всех ответах, и отказах; ADR-0091 доп. (16), (19)): странице хватает нормы.

## Н3 Проход

```
оффер: токен → пределы → подписка есть? → место (answering + 1) → ответ ≤ 5 с (вне блокировки) → сессия, Location, live.view
отбой: сессия есть? → владелец и раздача токена → закрыть, live.view.ended → последний ушёл → отсчёт отсрочки
```

**Гонки.** Два оффера на последнее место: `answering` считается под блокировкой — второй получает 503. Подписку сняли (сверка,
глава 2), пока готовился ответ, — шаг 7, сессия не остаётся. Токен истёк между оффером и отбоем — отбой просит новый
`/where` (страница — один раз).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| токен нет, не тот, истёк | 403 `forbidden` | страница | `/live/where` снова, один раз |
| тело больше 256 КиБ | 413 | страница | — |
| тело не SDP | 415 | страница | — |
| подписки ещё нет | 404 `not yet` | страница | повтор (V/08) |
| шлюз полон | 503 `full` | страница, `headroom` | повтор; контроллер растит шлюзы |
| оффер без видео или без кодека раздачи | 400 `bad offer` | страница | — |
| ответ не собран за 5 с | 500 `answer failed` | страница, журнал воркера | повтор |
| отбой чужой сессии | 403 | страница | — |
| соединений сверх предела | 503 `busy`, `Retry-After: 1` | страница | повтор |

## Н5 Приёмка

Приёмка 3 — по стенду с воркером `live`: без токена — 403, тело сверх предела — 413, не SDP — 415, отбой незнакомой сессии
без токена — 403; ответ и поток — чтением (стенду нужен клиент WebRTC). Сценарии появятся со стендом WHEP (воркер `live`,
браузерный клиент); до него глава проверяется чтением и тестом реализации.

---

## Решает реализация

Реализация обязана назвать в своём описании: **сборку ответа WebRTC** (библиотека, сбор кандидатов в пределах `ICE_WAIT`) и
команду запуска шлюза для «Стенда».
