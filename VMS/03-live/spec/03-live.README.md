# V/03 Живое видео — инструкция для реализации

Что реализация подсистемы `live` делает и как проверить результат. Канон — нормы глав `03.K-live.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `f6f3895`.

## Результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/03.1 | манифест `VMS/03-live/live.subsystem.yaml` грузится строгим загрузчиком без правок; дверь единиц консоли исполняет объявления раздачи; размещение — контроллер платформы | [приёмка 1](../acceptance/1/README.md) |
| V/03.2 | источник по пульсам (RTSP петли своего сервера, иначе приёмник своего кластера листом роли `liveworker`), одна подписка, эпоха, сверка (`resets`), `waiting` с причинами | чтением |
| V/03.3 | дверь шлюза по [OpenAPI](03-live.api.openapi.yaml): маршрут `whep`, токен двери, оффер без trickle, отбой, пределы, журнал `live.view*`, CORS маршрута | чтением (стенд WHEP — позже) |
| V/03.4 | ветвление (очередь ≤ 1 с, тройник без ветвей), PT из оффера, H.264/H.265 без перекодирования, записка `codec` | чтением; тест выбора PT над офферами |
| V/03.5 | отсрочка и удаление строки по `cas` (`worker.deletes`), уборка сессий (`CONNECT_SECONDS`), пульс (ёмкость, счётчики, элемент раздачи), `streams_live`, остановка | чтением |
| V/03.6 | — (переводится) | — |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam` (V/01), `rec` (V/02), затем `live` —
приёмка VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).
