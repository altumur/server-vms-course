# V/03.5 — Конец спроса, пульс и отказы: нормы

Канон главы 5 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), манифест [`live.subsystem.yaml`](../live.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `f6f3895` (отсрочка у каждой подписки, одно условие удаления — `b41527f`).

Раздачу создаёт зритель, а удаляет шлюз — через отсрочку после последнего; мёртвые сессии шлюз убирает сам. Глава нормирует
отсрочку и удаление строки, уборку сессий, пульс шлюза (элемент раздачи, ёмкость, счётчики), ряд `streams_live`,
остановку и арифметику отказов. Шлюз ничего не хранит: перезапуск узнаёт всё заново из строк и пульсов.

Id норм — `V/03.5-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Отсрочка и сроки сессий — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): удаляет — строки `live/streams/*`
своего назначения (`worker.deletes: [streams]`, [P/02.5 Н1.4](../../../Platform/02-installer/spec/02.5-installer.norms.md));
пишет — пульс `live/heartbeats/<воркер>`, журнал двери (`live.view.ended`, глава 3).

### Н1.1 Отсрочка и удаление строки

**Подписка и её потребители.** Источником владеет подписка шлюза на пару (камера, поток) — одна на шлюз (глава 2 Н1.2); её
потребители — сессии WHEP (глава 3) и клиенты RTSP (глава 6 Н1.4). Пока строка раздачи этой камеры в назначении шлюза,
подписка принадлежит раздаче и закрывается по `grace` строки (ниже); без раздачи — это самостоятельная подписка точки RTSP,
она закрывается через `LINGER` после последнего клиента (глава 6 Н1.4). Клиент RTSP строку не держит: отсчёт и удаление
строки ниже считают только зрителей WHEP. Строку удалили, а у подписки остались клиенты RTSP — подписка становится
самостоятельной, без закрытия источника и без разрыва клиентов; обратно — раздача на этом шлюзе забирает самостоятельную
подписку той же пары (источник открыт один раз). «Зритель» ниже — сессия WHEP.

- Подписка рождается свободной (глава 2 Н1.2): отсчёт отсрочки — свой у каждой подписки, с её заведения; ушёл последний
  зритель потока — отсчёт заново.
- Проход: у подписки (основной или прочей) нет зрителей и прошло `grace` строки — подписка уходит из раздачи: без клиентов
  RTSP шлюз снимает её и закрывает источник, с клиентами RTSP она становится самостоятельной (без закрытия источника и без
  разрыва клиентов, закрывается через `LINGER` после последнего клиента — глава 6 Н1.4); строка живёт.
- **Отсчёт строки** — с последнего из: взятия строки шлюзом, спроса на любой поток (глава 2 Н1.1), ухода последнего зрителя
  любой подписки. **Удаление строки — одно условие:** ни у одной подписки нет зрителей и отсчёт строки старше `grace`
  (умолчание 60 с, V/03.1 Н1.1). Тогда шлюз удаляет строку раздачи по `cas` прочитанной ревизии (`worker.deletes`, P/04 Н1.3 `unplaced`: «свои строки единиц МОЖЕТ удалять и
  воркер подсистемы» — удаление без права записи), затем снимает подписки и закрывает источники. Размещение снимает контроллер
  следующим проходом.
- Раздача без источника (глава 2 Н1.4) — по тому же условию: спрос без подписки зрителей не даёт, и через `grace` после
  последнего спроса строка удалена. Отсутствие подписки одного потока — основного тоже — строку не удаляет.

**Случаи** (V/03.5-01):

| Что с потоками | Подписки и `phase` | Строка |
|---|---|---|
| основной не идёт, прочий идёт и его смотрят | подписка прочего — со зрителями; спрос основного — 404 `stream refused` со словами; `phase: running` | живёт, пока смотрят прочий |
| основной идёт и его смотрят, прочий не идёт | подписка основного; оффер прочего — 404 `stream refused`, его спрос снимается через `grace`; `phase: running` | живёт, пока смотрят основной |
| не идёт ни один | подписок нет; `phase: waiting`, `reason` — слова первого спроса | удалена через `grace` после последнего спроса |
| идут оба, никто не смотрит | каждая подписка снята через `grace` после ухода её последнего зрителя; без подписок — `waiting`, `no stream asked` | удалена через `grace` после ухода последнего зрителя |
- `cas` не прошёл (строку правили) или хранилище молчит — строка не удаляется, отсчёт держится, следующий проход пробует
  снова. Зритель пришёл в окно до удаления — отсчёт снят, раздача живёт.
- Отсрочка — гистерезис: без неё повторное открытие вкладки стоило бы новой строки, размещения и подписки.
- Строку, которую не держит никто, удаляет контроллер (`unplaced.delete_after` 30, V/03.1 Н1.3); раздачу, которую шлюз
  держит, — только шлюз.

### Н1.2 Уборка сессий

Каждый проход шлюз закрывает сессии: соединение WebRTC ушло (`closed` или `failed`) — сразу; соединения нет дольше
`CONNECT_SECONDS` = 30 с подряд — тоже. Время без соединения копится в обеих фазах ожидания: после ответа, пока
соединение не установилось (`new`, `connecting`), и после установленного, пока оно прервано (`disconnected`), — и
обнуляется, только когда соединение `connected`; прерванное соединение, которое не стало `failed`, иначе висело бы без
срока. Счёт `swept`, журнал `live.view.ended` с `why: swept`. Без уборки шлюз
наполнялся бы мёртвыми сессиями и отвечал 503 `full`. Ушёл последний — отсчёт отсрочки (Н1.1).

### Н1.3 Пульс

Форма — [P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md); `live` добавляет:

| Поле | Значение | Смысл |
|---|---|---|
| `capacity` | целое | зрителей на шлюз (V/03.1 Н1.3; умолчание 100) |
| `headroom` | целое | `max(0, capacity − sessions − answering)` |
| `sessions` | целое | сессий сейчас — WHEP и клиенты RTSP (глава 6 Н1.4) |
| `subscriptions` | целое, счётчик | открытий источника с запуска (глава 2 Н1.2) |
| `resets` | целое, счётчик | сверок, закрывших сессии (глава 2 Н1.3) |
| `swept` | целое, счётчик | убранных сессий (Н1.2) |
| `codec` | `{<cam>: {<поток>: слова}}` | записки о кодеке (глава 4 Н1.4) |

**Элемент `status[]` раздачи** (сверх полей платформы): `phase` — `running` (заведена хоть одна подписка) | `waiting` (ни
одной; `reason` — глава 2 Н1.4); эпоха раздачи взята всегда — элемента без эпохи у подсистемы нет (P/03.4 Н1.1), `why` —
поле платформы; `viewers` — сессий WHEP раздачи по всем подпискам (клиенты RTSP в `viewers` не входят — они в `sessions`); `source` — `{<поток>: rtsp | ingest}` по подпискам (`""` —
основной; глава 2 Н1.1).

### Н1.4 Ряд и `console.running`

`metrics: [{name: streams_live, from: status.phase, agg: count, equals: running, live: true}]`, `console.running:
streams_live` ([P/06.5](../../../Platform/06-console/spec/06.5-console.norms.md) Н3 «/metrics»): ряд `live_streams_live` —
раздачи с поднятой подпиской; его читает проверка здоровья консоли.

### Н1.5 Остановка и перезапуск

- Цикл, аренды и пульс — рантайм платформы ([P/03.3](../../../Platform/03-worker/spec/03.3-worker.norms.md), P/03.4): сбой
  прохода не останавливает продление аренд.
- SIGTERM — P/03.4 Н3: каждая раздача снимается (сессии закрыты, журнал `live.view.ended` с `why: stopped`, источник закрыт),
  последний пульс, слот возвращён; строки раздач шлюз при остановке не удаляет — их подхватит другой шлюз. Срок остановки —
  умолчание `worker.stop_timeout`.
- Перезапуск: состояния нет — подписки заводятся из назначения, сессии браузеров переподключаются (страница, V/08).

### Н1.6 Арифметика отказов

| Что упало | Что видно |
|---|---|
| консоль кластера | новых зрителей нет (`/live/where` не отвечает); идущие сессии живут — байты мимо консоли |
| шлюз | живое видео его зрителей встало; запись идёт (V/02); раздачи подхватывает другой шлюз (размещение), страница переподключается |
| держатель камеры | сверка закрывает сессии (`resets`), новый источник — при переезде держателя |
| приёмник | следующий приёмник кластера; ни одного — `waiting` |

## Н3 Проход

```
уборка сессий (Н1.2) → отсрочка: без зрителей дольше grace → удалить строку по cas → снять подписку
пульс: capacity, headroom, sessions, счётчики, codec; элемент на раздачу — phase, reason, viewers, source
```

**Гонки.** Зритель пришёл, пока шлюз удаляет строку: удаление по `cas` прошло — оффер получает 404 (подписки нет), страница
создаёт раздачу заново (V/03.1 Н1.2); не прошло — раздача живёт. Два прохода одного шлюза не пересекаются (рантайм).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| хранилище молчит при удалении | строка остаётся, повтор следующим проходом | пульс | — |
| соединения нет 30 с подряд (не установилось после ответа или прервалось) | сессия убрана, `swept` | журнал, пульс | страница переподключается |
| шлюз полон | 503 `full`, `headroom` 0 | страница, ряды | повтор; новые раздачи размещаются на других шлюзах, рост (`grows`) — по ждущим раздачам (P/04 Н3 «нехватка»), не по зрителям занятой: зрителей одной камеры не больше ёмкости одного шлюза, у раздачи один держатель |

## Н5 Приёмка

Каталога приёмки у главы нет: отсрочка и уборка требуют зрителей WebRTC (стенд WHEP — позже); удаление строки по `cas` —
механизм P/04, приёмка P/04 (`worker.deletes`). Чтением, как и переход подписки с клиентами RTSP в самостоятельную
(клиентов RTSP у стенда нет).

## Решает реализация

Реализация обязана назвать в своём описании: **как шлюз узнаёт состояние соединения** зрителя (ушло, не установилось).

## Соответствие прежним урокам
