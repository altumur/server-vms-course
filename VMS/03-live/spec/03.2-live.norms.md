# V/03.2 — Источник и одна подписка: нормы

Канон главы 2 урока V/03 «Живое видео» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../03-live.md),
[инструкция](03-live.README.md), манифест [`live.subsystem.yaml`](../live.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `f6f3895` (подписка по (`cam`, `stream`) — `b41527f`).

Шлюз держит одну подписку на поток камеры при любом числе зрителей. Глава нормирует, откуда шлюз берёт поток — RTSP
держателя на своём сервере или приёмник своего кластера, — когда открывает источник, как сверяется с держателем и что
говорит, когда источника нет. Раздача держателя — [V/01.2](../../01-cam/spec/01.2-cam.norms.md) Н1.3; приёмник —
[V/02.9](../../02-rec/spec/02.9-rec.norms.md) Н1.3; зрители — главы 3, 4; отсрочка и удаление — глава 5.

Id норм — `V/03.2-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Сроки — монотонные часы процесса.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — строки `live/streams/*`
своего назначения, строки камер `cam/cameras/*` (основа роли — строки единиц `about`, [P/02.5 Н1.4](../../../Platform/02-installer/spec/02.5-installer.norms.md)),
пульсы держателей `cam/heartbeats/*` и регистраторов `rec/heartbeats/*` (`worker.reads`: пульсы чужой подсистемы основа роли
не даёт); пишет — эпоху раздачи `live/epoch/<cam>` (P/03.2 Н1.5), пульс.

**Файл подсистемы** `/etc/live/live.env` (секретов нет) читает шлюз по [договору файла окружения](../../../Platform/common/contracts/env-file.md): нет
файла — умолчания; не читается или значение не по грамматике — отказ старта, код 2 (сводка по VMS — V/09.2):

| Ключ | Читает | Грамматика | Умолчание | Норма |
|---|---|---|---|---|
| `WHEP_PORT` | шлюз | целое 0…65535 | порт ОС (`0` — так же) | [глава 3](03.3-live.norms.md) Н1.1 |
| `RTSP_PORT` | шлюз | целое 1…65535 | ключа нет — двери RTSP нет | [глава 6](03.6-live.norms.md) Н1.4 |

### Н1.1 Где поток камеры

Каждый проход шлюз ищет источник каждой **подписки** — по пульсам, раз за проход на все. Подписка — пара (камера, поток),
одна на шлюз (Н1.2), и любая — **по спросу**: основная (`stream` пуст) так же, как прочая. Спрос даёт оффер, назвавший
поток (`?stream=`, нет — основной; глава 3 Н1.2), или клиент точки RTSP (глава 6); без спроса подписок нет.

**Камера другого кластера** (`cam: ref:<ref>` раздачи; её пишет этот кластер, V/02.9 Н1.2) — ветвь до местных сверок:
строк `cam/cameras/*` шлюз не читает (камеры в своём кластере нет); поток — только основной: непустой `stream` спроса —
`stream <stream> is not of camera <cam>`; предел спросов — 1; источник — приёмник своего кластера по `ref` (таблица ниже).
Случай: первый оффер такой камеры записывает спрос на основной и получает 404 `not yet` (глава 3 Н1.2 шаг 3), следующий
проход заводит подписку на приёмнике.

Для камеры своего кластера:
Спросов у раздачи — не больше потоков её камеры по последнему проходу (основной и строки `cam` с её `main`); лишний
оффер получает отказ сразу, без записи (глава 3 Н1.2). Ищется элемент `status[]` с id потока (у основного — id
камеры); «камера» в таблице — этот поток. До поиска шлюз сверяет (V/01.1 Н1.1а):
- строка `cam/cameras/<cam>` — камера (её `main` пуст), иначе раздача `waiting`, `reason` `cam <cam> is a stream of <main>`;
- поток спроса — этой камеры: строка `cam/cameras/<stream>` называет `main: <cam>`; иначе подписки нет, спрос отвергнут
  словами `stream <stream> is not of camera <cam>` — их получает оффер (глава 3 Н1.2):

| Камера | Источник |
|---|---|
| держатель на **своём** сервере: элемент `status[]` камеры в пульсе `cam/heartbeats/*` с `phase: running` и `live_url`, поле пульса `server` = свой `SERVER_NAME`, пульс услышан за `LOST_AFTER` = 45 с | RTSP раздачи держателя — `live_url` (петля, V/01.2 Н1.3), TCP, задержка приёма 200 мс; `live_shm` не берётся: стык подсистем — RTSP петли, формат доли кадров — внутри одной реализации `cam` (V/01.2 «Решает реализация») |
| держатель на **другом** сервере кластера | приёмник своего кластера: обращение «подписка» листом роли `liveworker` — `cam` и `stream` подписки (V/02.9 Н2) |
| камера другого кластера (`cam: ref:<ref>`, её пишет этот кластер, V/02.9 Н1.2) | так же — приёмник своего кластера, по `ref`; только основной поток (спрос на прочий отвергнут: `stream <stream> is not of camera <cam>`; V/01.6 Н1.1, V/02.9 Н1.3) |
| строки камеры нет; держатель не `running` нигде; приёмника в кластере нет | источника нет — `waiting` (Н1.4) |

RTSP чужого сервера — не источник: раздача держателя слушает только петлю (ADR-0075 окно 2). **Приёмник своего кластера** —
адрес из поля `ingest` пульса регистратора `rec/heartbeats/*`, услышанного за `PEER_LOST_AFTER` = 30 с: регистратор своего
сервера, иначе первый по имени слота; приёмник не ответил — следующий. Желание шлюза у любого приёмника — желание у всех
(V/02.9 Н1.5): камеру толкает её кластер (камера-кластер — сама, серверную — регистратор сервера держателя, V/02.9 Н1.2) туда,
куда она уже толкает, а приёмник передаёт соседу с подписчиком. Подписка — живой край (зрителю не отдаётся кольцо
предзаписи), желание живёт, пока шлюз подписан, и ещё `LINGER` = 10 с после отписки (V/02.9 Н1.3).

Раздача камеры другого кластера — единица с именем `ref:<ref>` (имя допускает двоеточие, договор проверки строки
«Идентификатор»); `about` её камеру не разрешает — право зрителя требует гранта на `*` (V/03.1 Н1.2 `unresolved`).

### Н1.2 Одна подписка

- **Подписка** — запись шлюза о паре (камера, поток), **одна на шлюз**: источник (адрес, сервер), эпоха держателя. Ею
  владеет шлюз, её потребители — сессии WHEP (глава 3) и клиенты RTSP (глава 6). Заводится проходом по спросу (Н1.1),
  основная и прочая одинаково; рождается свободной — без потребителей, с отсчётом отсрочки (глава 5).
- **Чья подписка.** Пока строка раздачи камеры в назначении шлюза, подписка принадлежит раздаче и закрывается по `grace`
  строки (глава 5). Без раздачи это самостоятельная подписка точки RTSP: закрывается через `LINGER` = 10 с после последнего
  клиента (глава 6). Клиент RTSP строку раздачи не держит: отсчёт отсрочки и удаление строки (глава 5 Н1.1) считают только
  сессии WHEP. Строку удалили, а у подписки есть клиенты RTSP, — подписка становится самостоятельной без закрытия
  источника и без разрыва клиентов; обратно — раздача на этом шлюзе забирает самостоятельную подписку той же пары (одно
  открытие источника). Клиент RTSP входит в `sessions` и `headroom` шлюза, в `viewers` элемента раздачи — нет (`viewers`
  — сессии WHEP; глава 5 Н1.3). Спрос, по которому подписка не заведена (поток не этой камеры, источника нет), держит слова
  отказа до следующего прохода и снимается, если оффера за `grace` раздачи не было.
- **Источник открывается при первом зрителе** (глава 4), не при заведении подписки: соединение RTSP или подписка на приёмнике
  — одно на подписку, сколько бы зрителей ни было; счётчик пульса `subscriptions` — сколько раз источник открывался.
  Пятьдесят зрителей одного потока — одно открытие; сетка и полный экран одной камеры — два (два потока — две подписки).
- **Эпоха раздачи** — шлюз берёт эпоху единицы при её взятии ([P/03.3](../../../Platform/03-worker/spec/03.3-worker.norms.md)
  запуск единицы; [P/03.2 Н1.5](../../../Platform/03-worker/spec/03.2-worker.norms.md)), до поиска источника: два шлюза на
  одной камере видны по эпохе (подмена, переезд). Эпоху взять не удалось — единица не взята: элемента раздачи в пульсе нет
  (форма P/03.4 Н1.1: элемент без эпохи — только фазы платформы `sealed`, `unreadable`), строка журнала воркера, повтор
  следующим проходом; прочие раздачи идут дальше.
- Раздача ушла из назначения — подписка снимается, зрители отключены (их сессии закрыты), источник закрыт.

### Н1.3 Сверка с держателем

Каждый проход шлюз сверяет подписку с пульсом держателя: сменились источник (держатель переехал на другой сервер, другой
`live_url`) или эпоха держателя, или источник мёртв (RTSP оборван или 8 с без кадра; приёмник не отвечает) — сессии
зрителей закрываются (трубки положены), подписка получает новый источник, источник открывается при первом вернувшемся
зрителе; счёт `resets`. Повтор и разброс переподключения — у страницы (V/08). Хранилище молчит — держится последний
прочитанный источник; пульс держателя не читается — беда этой камеры, не прохода.

### Н1.4 Источника нет

Подписка без источника не заводится; слова — `no camera <поток>`, `camera <поток> is held by nobody`, `camera <поток> is not
running`, `no ingest in this cluster`, `stream <stream> is not of camera <cam>` (сверка Н1.1). Зрители этого потока получают
их в 404 `stream refused` оффера (глава 3 Н1.2). Состояние раздачи — по всем её подпискам и спросу, не по основному потоку:
`running`, если заведена хоть одна подписка (источник найден; открывается он при первом зрителе — `running` не значит
«поток поднят»); иначе `waiting` (глава 5 Н1.3; эпоха взята), `reason` — слова первого по
времени спроса, `cam <cam> is a stream of <main>` или, без спроса, `no stream asked`. Удаление строки — одно правило главы 5
Н1.1; отсутствие подписки одного потока строку не удаляет.

## Н3 Проход

```
источники: пульсы cam/heartbeats/*, rec/heartbeats/* — по разу; для каждой раздачи назначения: строка cam — камера (иначе
waiting); спрос (офферы, точки RTSP) → сверка «поток этой камеры», источник, подписка — или слова отказа; phase — по подпискам
для новых: эпоха (P/03.2, при взятии) → не взялась — элемента нет, журнал; с источником → подписка (свободная)
ушедшие из назначения → снять подписку, закрыть сессии и источник
сверка (Н1.3): источник или эпоха держателя сменились, источник мёртв → закрыть сессии, новый источник, resets + 1
без источника → phase waiting, reason (Н1.4)
```

Хранилище читается вне блокировки, которую ждёт зритель (оффер, глава 3): под блокировкой меняются только подписки и сессии.

**Гонки.** Держатель переехал между проходами — зритель, пришедший в окно, получает поток старого источника до сверки
следующего прохода. Два шлюза взяли одну раздачу (подмена) — у второго эпоха выше: первый при следующем пульсе видит
потерю аренды (P/03.2) и снимает подписку (`unconfirmed_max: off`, V/03.1 Н1.4).

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| камеры нет, держатель не `running` | `waiting` с причиной; удаление через `grace` | пульс | — |
| приёмника в кластере нет | `waiting` «no ingest in this cluster» | пульс | поставить регистратор |
| приёмник не ответил | следующий приёмник; ни один — `waiting` | пульс | — |
| эпоха не взята | единица не взята, элемента нет, строка журнала; повтор следующим проходом | журнал воркера | — |
| источник умер, держатель переехал | сессии закрыты, `resets` + 1, новый источник | пульс, страница | страница переподключается |

## Н5 Приёмка

Каталога приёмки у главы нет: источник требует держателя камеры и воркера `live` с WebRTC — стенду нужен браузерный
клиент; одна подписка, сверка и `waiting` — чтением и тестом реализации (счётчик `subscriptions` при пятидесяти зрителях —
1). Сценарий появится со стендом WHEP.

## Решает реализация

Реализация обязана назвать в своём описании: **как шлюз принимает поток** — RTSP-клиент (задержка 200 мс, TCP) и клиент
приёмника (транспорт приёмника — V/02.9 «Решает реализация»).
