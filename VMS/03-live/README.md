## Что такое урок V/03

Подсистема `live` — шлюз живого видео. Единица — раздача камеры зрителям («камеру 7 смотрят через шлюз g-2»): одна на
камеру, её создаёт первый зритель (`POST /live/streams`, право `view` на камеру) и удаляет шлюз через отсрочку после
ухода последнего. Воркеры — шлюзы `liveworker`: без состояния, число — по спросу, ёмкость — в зрителях. Шлюз держит одну
подписку на поток камеры при любом числе зрителей и отдаёт её браузерам по WebRTC (WHEP: оффер и ответ одним обменом, без
trickle), без перекодирования; устройствам (видеостена, чужая VMS) — по RTSP с учётками кластера. Байты идут шлюз ↔
браузер мимо консоли (решение владельца 1, ADR-0015): консоль выдаёт адрес двери и токен (`GET /live/where/<cam>`).
Общее — размещение, рантайм воркера, двери консоли, токен двери, книги домена — нормы платформы по ссылке (P/…).

## Формы и двери

- **Строки и объекты:** `live/streams/<cam>` (единица), таблица `live/accounts/<имя>` (`password_secret`), вклад
  `live/stream-accounts/<слот>`, копия книги `domain/live/stream-accounts`; пульс `live/heartbeats/<воркер>`; журнал
  шлюза (`live.view*`, `live.rtsp.*`).
- **Двери:** дверь шлюза `whep` (страница, токен двери консоли) и `/live/accounts` через `door.pass` — OpenAPI урока
  `spec/03-live.api.openapi.yaml`; дверь RTSP шлюза — RTSP с Digest (не HTTP), глава 6.

## Решения, принятые для плана (приняты «Архитектором» 2026-10-23)

1. **Источник на другом сервере — приёмник своего кластера.** RTSP держателя — только петля (V/01.2 Н1.3, ADR-0075 окно 2),
   ожидание `RTSP_HOST` свидетеля снимается. Шлюз на сервере без держателя хочет поток у приёмника своего
   кластера (живой край, `LINGER` 10 с) — так же для камеры другого кластера. Для этого V/02.9 дополняется в главе V/03.2:
   (а) толкатель серверной камеры (первый регистратор сервера держателя, V/02.9 Н1.2) толкает и в приёмник **своего**
   кластера, когда тот её хочет (не только по назначению в чужой); (б) приёмник допускает процессы своего кластера по
   сертификату роли (`liveworker`, `recworker`) рядом с токеном домена — класс `mixed`, как дверь архива (ADR-0091 доп. (7)).
   Альтернатива — размещать шлюз у держателя (`near`) — ломает `labels` зрителей (публичный адрес); не беру.
2. **Право зрителя проверяет дверь шлюза** по токену двери консоли (М10B/13, `door.routes: [whep]`); «шлюз передаёт и не
   авторизует», проверка права точкой подключения кластера (М12A/03) — снимается.
3. **Кодек — без перекодирования, H.264 и H.265 проводятся** с типом нагрузки из оффера (оболочка переносит PT H.265 в
   96–127). Уточнено ревью (вопрос 6): первый оффер открывает источник до ответа и ждёт параметров потока в бюджете
   `ICE_WAIT` (не пришли — 404 `not yet`); типа нагрузки кодека раздачи нет в оффере — 400 `bad offer`; профиль или
   кодек, который браузер может не сыграть, — записка `codec` в пульсе, не отказ (V/03.3 Н1.2, V/03.4). Перекодирование,
   fMP4 и TURN шлюза (М12A/03) — не переносятся.
4. **Константы — V/03:** `MAX_OFFER` 256 КиБ, ICE ≤ 5 с, `CONNECT_SECONDS` 30, `grace` 60 (поле), задержка RTSP 200 мс;
   повторы страницы (1,5 с × 8, переподключение) — V/08.
5. **`door.pass` без шлюза** — 503 договора gate-and-pass («no worker of live with a door is heard»), не 409 формы C5.
6. **Две отсрочки:** строка без держателя — контроллер (`unplaced.delete_after` 30); строка с держателем, но без источника
   (камеры нет, не `running`) — шлюз, через `grace` с первого прохода, который это увидел.
7. **`worker.reads` дополняется `cam/heartbeats/`** — держатель и `live_url` по пульсу `cam` (P/02.5 Н1.4; у `rec` — так же,
   `33d1fbde3`); поиск держателя — чтение пульсов, своей нормы платформы не нужно.

## Запросы урока

Предварительно нет: пределы двери (опись § 6 № 13) — P/03.4 Н1.7 `door_limits`; адрес двери — P/03.4 Н1.7; журнал и CORS —
ADR-0091 доп. (7), (8). RTSP-сервера с Digest в курсе нет: дверь RTSP нормируется по поведению, сервер — решает реализация;
приёмка учёток — через `/live/accounts`, игра по RTSP — чтением (стенд без RTSP-клиента с Digest).

## Отличия от свидетеля, которые урок записывает

`worker: {writes: [streams]}` → `deletes: [streams]` (ADR-0067); `offers`/`live_workers_needed` → `grows`/`workers_wanted`
(ADR-0084); источник чужого сервера — приёмник, не RTSP; проверка токена шлюзом — токен двери платформы (P/03.4 Н3); свой цикл
прохода — рантайм P/03.3, P/03.4; медиакод и точка входа свидетеля, ответвление `domainpart` — не переносятся (реализация);
`stream-clients`, `DOMAIN_CONSOLE_URL`, `accounts_secret` → `live/accounts`, `/live/accounts` через `door.pass`,
`password_secret` (форма C5, ADR-0074); маршрут `POST /whep` → `POST /whep/<cam>`.
