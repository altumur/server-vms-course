# V/06 Детекция по архиву устройства — инструкция для реализации

Что реализация подсистемы `detedge` делает и как проверить результат. Канон — нормы глав `06.K-detedge.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `d3f8e05` (пин VMS).

## Входы и их приоритет

- Канон — нормы глав `06.K-detedge.norms.md` (Н1–Н5 каждой главы; адреса `V/06.K Н…`).
- Канон манифеста — [`detedge.subsystem.yaml`](../detedge.subsystem.yaml): байты как есть.
- Приёмка — [глава 1](../acceptance/1/README.md); стенд и словарь — [общий README приёмки VMS](../../common/acceptance/README.md); новых требований приёмка не вводит.
- Векторы — [`mask`](../../04-det/vectors/mask/README.md) (команда пакета).
- [Лекция](../06-detedge.md) объясняет причины; платформа — нормы выгрузки пина VMS по адресам `P/…` (их правит не VMS).

Противоречие записать с местом и контрпримером (раздел «При расхождении»); произвольный отказ не заменяет
отсутствующую норму. Устройство кода остаётся реализации в рамках канона.

## Что создать — результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/06.1 | манифест `VMS/06-detedge/detedge.subsystem.yaml` грузится строгим загрузчиком без правок; дверь единиц консоли исполняет объявления обхода | [приёмка 1](../acceptance/1/README.md) |
| V/06.2 | держатель по пульсу, окно (`SETTLE` 30, 600 с за проход), перечень `/recordings` (`None` ≠ `[]`, нормализация спанов), чтение `/playback` по 60 с медиа вне цикла рантайма, одна сессия на устройство, 4 чтения за проход, 503 (в том числе запас двери `PLAYBACK_SPARE`) — ожидание | чтением |
| V/06.3 | курсор-рубеж (первое взятие `now`/`earliest`, движение по окну, по непрерывному началу, по досмотренному; «события → подачи → курсор»), стёртое кольцом — прыжок и `detedge.overrun`, рубеж впереди архива — `detedge.rewound`; модель реестра `det` (`tick` на абсолютной сетке, маска — векторы `mask`), события по правилам V/05.3 | чтением, векторы `mask` |
| V/06.4 | `keep: hits` — отрезки вокруг находок (склейка, ∩ засчитанное), просьба дозаписи подачей в запись `rec` до курсора (целые секунды, до «видно с», куски ≤ суток); фазы; пульс (`events_written`, `through`, `lag`, `overrun`) | чтением |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam`, `rec`, `det`, затем `detedge` — приёмка
VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).

## Ловушки

| Норма | Возможная ошибка | Как сохранить поведение |
|---|---|---|
| V/06.3 Н1.2 | двигать курсор раньше исхода подач | события → подачи → курсор; курсор — когда у каждой подачи исход |
| V/06.3 Н1.4 | ставить такт `tick` от начала прохода | абсолютная сетка `t_n = n × 1 с` |
| V/06.3 Н1.3 | молча продолжать, когда курсор впереди архива | сброс как при первом взятии и событие `detedge.rewound` |
| V/01.5 Н1.5 | занимать у двери держателя последнюю сессию устройства | запас `PLAYBACK_SPARE` держит дверь: на последнюю — 503, ожидание |

## Готово, когда

Манифест грузится строгим загрузчиком без правок; приёмка глав 1 проходит на платформе, прошедшей свою приёмку; векторы урока проходят командой пакета;
пункты чеклистов, отмеченные «чтением», подтверждены описанием реализации (раздел «Решает реализация» каждой главы).
Проверка схемы, загрузчика и стенда друг друга не подменяют.

## При расхождении

Порядок источников: нормы главы → OpenAPI → приёмка и векторы → лекция; платформа — нормы выгрузки пина VMS.
Норма молчит или противоречит себе — вопрос «Спецификации VMS» с местом, контрпримером и предложением; норма
платформы — через «Архитектора». Дефект приёмки (ожидание против нормы) — тот же маршрут; закрытое решение
вносится в канон, а не остаётся в этой инструкции.
