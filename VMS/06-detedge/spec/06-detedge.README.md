# V/06 Детекция по архиву устройства — инструкция для реализации

Что реализация подсистемы `detedge` делает и как проверить результат. Канон — нормы глав `06.K-detedge.norms.md`; эта
инструкция их не дополняет. Платформа — выгрузка `cammeta-specs` `d3f8e05` (пин VMS).

## Результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/06.1 | манифест `VMS/06-detedge/detedge.subsystem.yaml` грузится строгим загрузчиком без правок; дверь единиц консоли исполняет объявления обхода | [приёмка 1](../acceptance/1/README.md) |
| V/06.2 | держатель по пульсу, окно (`SETTLE` 30, 600 с за проход), перечень `/recordings` (`None` ≠ `[]`, нормализация спанов), чтение `/playback` по 60 с медиа вне цикла рантайма, одна сессия на устройство, 4 чтения за проход, 503 (в том числе запас двери `PLAYBACK_SPARE`) — ожидание | чтением |
| V/06.3 | курсор-рубеж (первое взятие `now`/`earliest`, движение по окну, по непрерывному началу, по досмотренному; «события → подачи → курсор»), стёртое кольцом — прыжок и `detedge.overrun`, рубеж впереди архива — `detedge.rewound`; модель реестра `det` (`tick` на абсолютной сетке, маска — векторы `mask`), события по правилам V/05.3 | чтением, векторы `mask` |
| V/06.4 | `keep: hits` — отрезки вокруг находок (склейка, ∩ засчитанное), просьба дозаписи подачей в запись `rec` до курсора (целые секунды, до «видно с», куски ≤ суток); фазы; пульс (`events_written`, `through`, `lag`, `overrun`) | чтением |

Манифест — данные спецификации: реализация читает его байты как есть (ADR-0090 доп. (6) п. 8).

## Порядок

Сначала платформа (генерация стадии C, прошедшая приёмку платформы), затем `cam`, `rec`, `det`, затем `detedge` — приёмка
VMS идёт только на такой платформе (ADR-0090 доп. (8), (9)).
