# V/06.4 — Смотреть всё, сохранять интересное; пульс: нормы

Канон главы 4 урока V/06 «Детекция по архиву устройства» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../06-detedge.md),
[инструкция](06-detedge.README.md), манифест [`detedge.subsystem.yaml`](../detedge.subsystem.yaml). Платформа — выгрузка
`cammeta-specs` `84958d6`.

Обход уже потратил сеть, чтобы посмотреть минуты; если модели что-то понравилось, эти минуты можно сохранить, не копируя
остального. Глава нормирует, какие отрезки вокруг находок обход просит сохранить, как подаёт просьбу дозаписи регистратору,
фазы обхода и его пульс. Исполнение просьбы — [V/02.8](../../02-rec/spec/02.8-rec.norms.md) Н1.4.

Id норм — `V/06.4-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Медийное время архива устройства.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): пишет — просьбы `rec/requests/<rid>`
(`worker.requests: [rec]`, [P/03.6 Н1.5](../../../Platform/03-worker/spec/03.6-worker.norms.md)), пульс; читает — строку
записи `rec/recordings/<rec>` (`worker.reads`; срок `retention_days`).

### Н1.1 Отрезки вокруг находок

При `keep: hits` и заданном `rec` (V/06.1 Н1.2), после того как рубеж засчитал куски прохода (глава 3 Н1.2):

1. каждая находка этих кусков (строка события модели) даёт отрезок `[t − pre, t + post)`;
2. отрезки сортируются; соседние, между которыми не больше `join` секунд, склеиваются — промежуток тоже;
3. склеенные отрезки пересекаются с засчитанными кусками: в паузу записи устройства `pre` не уходит.

Просить можно только засчитанное. `keep: hits` без `rec` — не действует: поле `keep_off` элемента пульса — `keep: hits needs
rec`; обход смотрит дальше.

### Н1.2 Просьба дозаписи

- Подача воркером (P/03.6 Н1.5; V/02.8 Н1.4): строка `rec/requests/<rid>`, тело `{unit: <rec>, from, to}` (`unit` — id записи),
  `rid` — по ключу просьб `rec` (`{unit}-{from:int}-{to:int}`; повтор — та же строка), штампы `by: detedge/<watch>`, `at`,
  `about`; тело проверяется по схеме просьб `rec` до подачи, не по схеме — не подаётся (`filings.refused`).
- Отрезок подрезается снизу до «видно с» записи (`now − retention_days × 86400`, V/02.5 Н1.2) и режется на куски не длиннее
  суток; кусок короче секунды не подаётся (регистратор отказал бы, V/02.8 Н1.4). При `start: earliest` с бэклогом часть
  находок уже за сроком записи — не просится.
- Исход задача не ждёт: просьбу закрывает регистратор (`fetched`); приехавшее — поток `…/backfill` записи с её сроком,
  отдельного архива улик нет. Учёт `per_person` к подаче воркером не относится: он — учёт людей у двери консоли (P/06.4 Н1.5),
  подача воркером идёт мимо неё.

### Н1.3 Фазы

Элемент `status[]` обхода — под взятой эпохой (глава 3); `reason` — слова подсистемы, `why` — платформы:

| `phase` | Когда |
|---|---|
| `running` | обход читает архив (глава 2 Н1.4) |
| `caught_up` | рубеж у края (`newest − SETTLE`), читать нечего (глава 2 Н1.2) |
| `waiting` | держателя или архива нет, держатель не отвечает, свободной сессии нет (глава 2; `reason`) |
| `pending` | `enabled: false`: модель остановлена, чтения нет |
| `unsupported` | вида модели нет у воркера (V/04.2) |
| `failed` | модель или маска не запускаются; модель упала (глава 3; отступ рантайма) |

### Н1.4 Пульс и ряды

Форма — [P/03.4 Н1.1](../../../Platform/03-worker/spec/03.4-worker.norms.md); платформа кладёт ёмкость, запас, `filings`.
`detedge` добавляет: верх — `events`, `events_refused` (счётчики с запуска); элемент обхода — `phase`, `reason`, `through`
(рубеж), `lag` = `max(0, newest − through)` (насколько обход отстаёт от края архива), `events` (строк этого обхода с запуска),
`overrun` (секунд, стёртых до рубежа, глава 3 Н1.3), `index_garbled` (битых кусков перечня, глава 2 Н1.3), `keep_off` (Н1.1).
Ряды — `watches_running` (читающие обходы, `console.running`), `filings_total` (манифест).

Растущий `lag` и `overrun` — обход не успевает: тридцать два канала требуют 32× реального времени, а GPU даёт 4× — обход
для такого архива — на субпотоке и редких кадрах.

## Н3 Проход

```
после засчитанных кусков (глава 3): keep: hits и rec → отрезки вокруг находок → склеить по join → ∩ засчитанное
→ подрезать до «видно с», куски ≤ суток, ≥ 1 с → подача rec/requests/<rid> (by: detedge/<watch>)
пульс: events, events_refused; элемент — phase, reason, through, lag, events, overrun, index_garbled, keep_off
```

**Гонки.** Две находки соседних проходов дали пересекающиеся отрезки — разные `rid`, регистратор дописывает перекрытие один
раз (вычитание, V/02.8 Н1.1). Переезд после подачи — повтор подачи тех же кусков даёт те же `rid`.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| `keep: hits` без `rec` | не действует, `keep_off` | пульс | задать `rec` |
| находка за сроком записи | не просится | — | — |
| тело не по схеме `rec` | не подаётся, `filings.refused` | пульс | — |
| регистратор отказал просьбе | дыра остаётся | пульс регистратора (`requests_refused`) | — |
