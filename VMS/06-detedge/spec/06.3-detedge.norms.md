# V/06.3 — Frontier, model, events: norms

This English text is the source; the Russian [`06.3-detedge.norms.md`](../06.3-detedge.norms.md) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 3 of lesson V/06 «Детекция по архиву устройства» (ADR-0080; the VMS module — ADR-0090). [Lecture](../../06-detedge.md),
[instructions](../06-detedge.README.md), manifest [`detedge.subsystem.yaml`](../../detedge.subsystem.yaml). The platform is the export
`cammeta-specs` `7a875c75` (the VMS pin).

The watch goes forward through the device archive, and all its memory is the **frontier**: how far it has watched. The chapter sets norms
for the cursor, how the frontier moves when the door is free, when it is busy and when the model crashes, what to do with what the device
ring has erased, the model and the events. Reading — chapter 2; keeping findings — chapter 4.

Norm ids are `V/06.3-MM`; the map to former lessons is [`id-map.tsv`](../../../common/id-map.tsv).

## Н1 Form

**Time.** The frontier is media time of the device archive. `t` of an event row is the writer's clock; the media time of the row is `occurred`
(the event log contract `line`).

**Data** (the shared families of the [platform catalogue](../../../../Platform/common/data/catalog.tsv)): writes — the cursor
`detedge/state/cursor/<watch>` ([P/03.6 Н1.7](../../../../Platform/03-worker/spec/03.6-worker.norms.md)), the epoch (when the
unit is taken, P/03.3), events — into the resource log of its own server `detedge/<watch>/e<эпоха>/`, alarms — `detedge.alarms/…`; reads
— the mask bodies `detedge/blobs/*`.

### Н1.1 Cursor

`unit.state.cursor` is `{through, events, overrun?}`: the frontier (media seconds watched contiguously), the rows written, the seconds
erased by the device ring before the frontier (Н1.3). The holder MUST write it under the epoch guard, no more often than `STATE_EVERY` = 10 s; it
is bound to `born` — an edit of the row (`params`, `kind`) does not reset the frontier; it survives a move (P/03.6 Н1.7). The frontier and the
times of a row are rounded down to milliseconds: a small repeat is better than a gap (Н1.2).

**First take.** If there is no cursor, the holder MUST write it at once (without waiting for a read), `{through, events: 0}`, and this write counts
towards the 10 s limit: `start: now` — `through = max(oldest, newest − SETTLE)` (an archive shorter than `SETTLE` gives no fictitious `overrun`),
`start: earliest` — `through = oldest` (chapter 2 Н1.1, Н1.2); there is no holder yet — wait (`waiting`, chapter 2). A frontier reset uses the same
formula (Н1.3). The cursor, `overrun`, `rewound` exist only for a watch that has got as far as reading: `pending`,
`unsupported`, `failed` of the mask end the pass earlier (chapter 4 Н1.3). If the store did not answer the read of the cursor, this is not «no
cursor»: the cursor is not written, `waiting`, `reason` `cursor unreadable`.

### Н1.2 Movement of the frontier

| How the read of the pass window ended | Frontier |
|---|---|
| the door is free, the window is read to the end | the end of the window: pauses of the device recording between pieces of the listing — there is nothing to watch, no reason to come back |
| the door is busy (503), the pass budget is exhausted (4 reads), a break | the end of the **contiguously watched beginning of the window**: from `at` through the pauses of the listing (and garbled pieces, `index_garbled`) to the end of the last whole read (chapter 2 Н1.4), after which nothing is skipped; if nothing of a window with pieces was read, it stays |
| the model crashed in the middle of a piece | right after the last watched frame: this frame is not repeated; the model is stopped (`failed`), the restart — by the next pass after the runtime backoff (P/03.3). The write chain runs to the end on a crash too: the cursor — by the limit `STATE_EVERY`; a restart under the same epoch goes from the frontier and the filings in memory |

Exactly what was done is credited: a frontier at the end of the window with a busy door would skip unread minutes; a frontier left in place
would mean a repeat and duplicate event rows of the same piece.

**Write order** (question 1 of the analysis of the V/06 review): event rows of the credited pieces → filings of the segments that
this frontier credits (chapter 4 Н1.1, Н1.2) → the cursor. The cursor MUST be written only when each such filing has got the outcome `filed`, `again`
or `refused` (P/03.6 Н1.5); if a filing was not written (a store error, `may_write` is false), the cursor is not written further, `waiting`,
`reason` `a request to keep minutes was not filed`, and the next pass first, before the holder, files it again from memory and only
then reads anything new. A break before the cursor — the new holder repeats the pieces from the former frontier: event rows — under the new epoch
(`earlier-run`, Н1.5); the same piece — the same `rid`, outcome `again`, the row removed — `filed`; a different cut — a different `rid`,
the recorder discards the overlap (V/02.8 Н1.3). A repeat after a move is all the work after the last written cursor: up to
`STATE_EVERY` of the holder's work, more if the cursor write is refused; there is no limit in seconds of video (reading is faster than real
time), and the repeat loses no findings. `stop_unit` breaks off the read, the memory of the frontier and of the filings is lost: the work after the written
cursor is repeated under the same epoch, rows — with a new `id`, filings — `again`.

### Н1.3 Erased by the device ring

`through < oldest` (the ring erased what the watch had not reached) — the frontier jumps to `oldest`, the cursor's `overrun` grows by
`oldest − through`, one event row `detedge.overrun` per jump (`from` — the former frontier, `to` — `oldest`; `occurred` —
`from`; class `observation`), at once; the cursor — with the nearest allowed write; a break before the cursor — the row is repeated under the new
epoch (`earlier-run`), `overrun` is not doubled. A watch that cannot keep up with the recording loses minutes explicitly, not silently.

**Trimming inside a read.** The ring erased the beginning of the read `[a, b)` between the listing and `/playback`: the door returns the trimmed part, the answer
is whole (chapter 2 Н3 «Гонки»), the frontier goes past the erased part, and the check above does not see it. Therefore the frontier is reconciled with what the door
returned: `first` — the timestamp of the first frame of the read (no bytes — `b`), `door_from` — the header `X-Coverage-From` of the answer, the edge at which the door
trimmed (V/01.5 Н1.3); if there is no header or it is not a number, there is no reconciliation, the read is whole, a log entry. `a < min(first, door_from)` — `[a, min(first, door_from))` is erased: `overrun` grows by its length, a row `detedge.overrun` (`from` — `a`, `to` — the end of the
erased part; `occurred` — `from`; class `observation`), the erased part is not credited (chapter 4 Н1.1), the frontier — by Н1.2. Frames later than `a` with
`door_from ≤ a` are a pause or a key frame, no count. **Limit:** the device summary lags behind its ring: what is erased but not yet known to the holder goes as a pause.

**Frontier ahead of the archive.** `through > newest` (in the normal course the frontier is no further than `newest − SETTLE`, and `newest` does not decrease) —
the archive of the frontier has ended: the card was changed or the device clock went back. The frontier is set as at the first take by `start`
(Н1.1), one event row `detedge.rewound` (`from` — the former frontier, `to` — the new one; `occurred` — `to`; class `observation`)
is written at once, the cursor — with the nearest allowed write: the limit `STATE_EVERY` (P/03.6 Н1.7) applies to every write of the
cursor, the reset included (the Architect's decision on the analysis of the V/06 review, Kimi's addition, question 3). Without this the watch would silently
stay in `caught_up` until the archive outgrows the former frontier.

### Н1.4 Model

The registry of kinds is that of detectors (V/04.2 Н1.2): no kind — `unsupported` (chapter 4). The mask body (its own field `mask`,
`detedge/blobs/<digest>`) is read at model start; if it cannot be read or does not follow the PGM profile — `failed` with backoff; if the sizes of the mask and the frame
do not match, this is not a refusal: the mask is mapped onto the frame by nearest neighbour ([V/04.1](../../../04-det/spec/04.1-det.norms.md) Н1.1 «Маска и размер кадра»,
V/04.2 Н1.2). The watch has no reference to a detector's mask (`mask_of`): the operator uploads the mask for the watch.

The teaching model `tick` works in media time, on an **absolute grid**: a look at the moments `t_n = n × STEP` (`STEP` = 1 s, `n` an
integer, Unix seconds of the archive) only inside a read segment (`t0 ≤ t_n < t1`; a read without bytes is not a read segment:
`tick` is silent in it); an event — at `n` a multiple of 3 and `n ≥ 3`, as for the job of V/05.3 Н1.3: there is no zero event (Kimi's
addition, question 2); the field `pass` = `n`, `occurred` = `t_n`. Cutting
into reads, a move and a frontier jump do not shift the grid; the grid needs no new state. The event rules are those of V/05.3 Н1.3,
except the grid. Cases for the implementation test: a piece with a fractional start, `t_n` on the right bound, continuation after the cursor,
an `overrun` jump.

### Н1.5 Events

The row rules are as for the job ([V/05.3](../../../05-detjob/spec/05.3-detjob.norms.md) Н1.4): the worker writer (P/03.6 Н1.2),
`of: cam/<cam>` from `about`, `t` — the writer's clock, `occurred` — the media time of the frame, `may_write` before each write,
`events_refused` on an error; the tree — `detedge`, the unit — the watch name. The class of a model finding is by the watch's `alarms` (default
`[]` — all findings are observations); `detedge.overrun`, `detedge.rewound` are always observations (Н1.3). There is no suppression (media is faster than
real time). A reader by the time of minutes MUST ask `by=occurred` with `late` no less than the age of these minutes: a row about an
old archive is written now, and one written later than `to + late` is not visible to the request (the merge contract of the event log `by`,
C05-QUERY-LATE-01). `events.older_epochs: earlier-run` ([P/06.4 Н1.2](../../../../Platform/06-console/spec/06.4-console.norms.md)):
after a move the rows of the former epoch are the only record of those minutes.

## Н3 Pass

```
unfiled filings of the previous pass → file them again (before the holder and before reading anything new); not written → waiting
the assignment's watch (the epoch is taken when the unit is taken): pending, unsupported, failed of the mask → end of the pass (chapter 4 Н1.3)
no cursor → write the first one (now | earliest); not read → waiting
through < oldest → jump, overrun, the event detedge.overrun at once, the cursor — with the nearest write
through > newest → the frontier as at the first take (start), the event detedge.rewound at once, the cursor — with the nearest write
window and read (chapter 2) → frames of the piece → model → events (may_write, class by alarms)
reconciliation of the read with what was returned: erased [a, min(first, door_from)) → overrun, the event detedge.overrun
frontier: the whole window — the end of the window; broken off — the end of the contiguous beginning; the model crashed — what was watched
event rows → filings of segments (chapter 4) → the cursor, once each filing has an outcome; no more often than 10 s
```

**Races.** A substitution in the middle of a piece: the former holder keeps writing until it loses the lease, the new one reads the frontier (the last written
cursor) and repeats the work after it under its own epoch — the reader sees the former epoch as `earlier-run`; the same piece — the same
`rid`, outcome `again`, the row removed — `filed`; a different cut — a different `rid`, the recorder discards the overlap (V/02.8
Н1.3; the bounds are whole seconds, chapter 4 Н1.2).

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| the ring erased what was not watched | a frontier jump, `overrun`, the event `detedge.overrun`; inside a read — `overrun`, the event, the frontier by Н1.2 | heartbeat, events | a lighter model, a substream, fewer watches per GPU |
| the frontier is ahead of the archive (`through > newest`) | the frontier as at the first take, the event `detedge.rewound` | heartbeat, events | — |
| a segment filing was not written | the cursor stays, the filing is repeated first, `waiting` | heartbeat | the store |
| the cursor is not read: the store did not answer | the cursor is not written, `waiting` | heartbeat | the store |
| the model crashed in the middle of a piece | the frontier by what was watched, `failed`, backoff | heartbeat | — |
| the mask body cannot be read | `failed`, backoff | heartbeat | — |
| a row write failed | the row is lost, `events_refused` | heartbeat | the resource |
