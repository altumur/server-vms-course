# V/09 Развёртывание VMS — инструкция для реализации

Что реализация установки VMS делает и как проверить результат. Канон — нормы глав `09.K-deploy.norms.md`; эта инструкция их
не дополняет. Платформа — выгрузка `cammeta-specs` `d3f8e05`.

## Результат по главам

| Глава | Что есть у реализации | Проверка |
|---|---|---|
| V/09.1 | источник: семь манифестов, страница, `worker.exec`, часть `obsd`, ключ вендора; `W2C_DEPLOYMENT=vms`; порядок `manifest put` (`requests` и виды токенов; `near` — не ребро, одним проходом); после установки — тома части смонтированы, том сервера объявлен строкой `rec/volumes` | чтением; установка на стенде |
| V/09.2 | пример файла каждой подсистемы с ключами уроков 01–07; строки площадки `SERVER_NAME`, `LABELS`, `CONSOLE_ORIGINS`; файлы семи ролей в пакете, проходящие правило памяти (`recworker` ≥ 1951 МБ при `CAPACITY=50`), `CAPACITY` по правилу и названному пределу нагрузки | чтением; установка на стенде |
| V/09.3 | один пакет на все виды кластеров (различие — свойство сервера, `BUILD`); состав — исполняемые, байты канона, `obsd` с патчами 01–07, медиабиблиотека из пакетов ОС, файлы ролей; доставка толканием или вытягиванием; уведомления и фраза о лицензии каждой зависимости | чтением; установка на стенде |
| V/09.4 | здоровье — отказ (`/<sub>/unplaceable`, фазы «отказ» владельцев, `workers_live`), ряд `console.running` — диагностика; «архив пополняется» — `recordings_running`, `writer` ok, `volume_error` 0, `archive_failure` нет (`last_frame_age` — подсказка) | чтением; установка на стенде |

Установка — механизм платформы (P/02.4): реализация VMS даёт источник и значения, а не свой установщик.
