# V/09.2 — The environment: norms

This English text is the source; the Russian translation `ru/spec/09.2-deploy.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 2 of lesson V/09 «Развёртывание VMS» (ADR-0080; the VMS module — ADR-0090). Lecture (`ru/09-deploy.md`, for people, not in the export),
[instructions](09-deploy.README.md). The platform is the export `cammeta-specs` `7a875c75`.

The platform lays out and reads the environment files: the unit values → the role file `roles/<роль>.env` → `w2c.env` → the subsystem file
`/etc/<sub>/<sub>.env`, what is read earlier wins ([P/02.4](../../../Platform/02-installer/spec/02.4-installer.norms.md) Н1.2;
the parsing — [the contract `env-file`](../../../Platform/common/contracts/env-file.md)). The chapter gathers what VMS expects in these files:
the keys of the subsystem files (for reference — the value and the default are set by the owner lesson), the site lines that VMS reads, and
how to compute the `CAPACITY` of the roles.

Norm ids are `V/09.2-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../НОРМАТИВНЫЕ-СЛОВА.md). The rules of the module «Платформа» are [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-vocabulary).

## Н1 Form

### Н1.1 Subsystem files

The file `/etc/<sub>/<sub>.env` (a link into `/data/platform/etc/subsystems/<sub>/`, 0644 `root:root`, it holds no secrets — secrets are in
the store, P/06.2); no file — the subsystem defaults, not an error; unreadable — a start refusal, code 2 (P/02.4 Н1.1, Н1.2).
The installer puts the file in place only if it is absent (P/02.4 Н1.7 `steps`): the package gives an example with the defaults and words at each key.

### Н1.2 Site lines `w2c.env`

Platform keys (P/02.4 Н1.2); VMS relies on them:

- `SERVER_NAME` — the address of the doors of the VMS processes by the kind of door: HTTP doors (holder, archive, WHEP) — `door_address` P/03.4 Н1.7
  (`https://<SERVER_NAME>:<порт>` with a kit, the loopback `http://127.0.0.1` without one); RTSP of `live` — `rtsp://<SERVER_NAME>:<порт>`,
  without TLS (V/03.6 Н1.4); RTSP of the holder `cam` — loopback only `rtsp://127.0.0.1:<порт>/<id>` (V/01.2 Н1.3), `SERVER_NAME` does not
  set it; and the slot name; the names of the cluster servers resolve at each other and at the operator's workstation — a premise (P/02.4 Н1.7 `warn`).
- `LABELS` — the server labels: all VMS subsystems place by `labels-subset` (the unit labels ⊆ the server labels, P/04 Н1.3);
  a gateway with a public address, a server with a GPU — a property of the server by labels, not by name. A server to which tills connect carries the label
  `server:<SERVER_NAME>`: it is read by the binding of the POS row (V/01.1 Н1.1г).
- `CONSOLE_ORIGINS` — the origins of the console page, in a domain — also the origins of the consoles of the members whose pages view the archive of this
  cluster: without them the page does not reach the archive and WHEP doors (CORS, P/03.4 Н1.7; V/02.5, V/03.3).
- `CONSOLE_CALL_PORT` — the listener of the console callback (default 8081, only with a kit; P/02.4 Н1.7): `backend` calls
  the console on it (V/11.1 Н1.2, V/11.5 Н1.1); the port is reachable between the cluster servers.
- `TIMEZONE` — the cluster time zone (default `UTC`; P/02.4 Н1.7): `backend` computes dates by it (V/11.8); the installation
  does not rewrite an existing `w2c.env`; the operator writes a different time zone in by hand.
- `W2C_DEPLOYMENT=vms` — chapter 1 Н1.2.
- `DOMAIN_SERVER` — `yes` on a server that holds the domain or stands as a spare (default `no`; P/02.4 Н1.7 `w2c_env`):
  only there the installation turns on the domain and the units of the domain workers, among them `vms-camdomain` (V/01.7).
- `PUBLIC_URL` — the address of the cluster entry for people (the environment file contract): the agent carries it into the domain view; `backend`
  answers with it for the live and the presets of a camera of another cluster (`members[].url`, V/11.4 Н1.13); behind NAT it is not set.

### Н1.3 Role files and `CAPACITY`

The role of a subsystem worker is `<sub>worker`; the file `roles/<роль>.env` holds `CAPACITY`, `WORKER_MEMORY_MB`, `HOST_MEMORY_MB` (P/02.4
Н1.2, Н1.5). The worker states `CAPACITY` in the heartbeat, the controller takes it (`capacity.from: capacity`), the manifest default is for
a silent one. The worker MUST NOT start if `CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB` (P/03.4 Н1.2; without `unit_mb`, `CAPACITY` or
`WORKER_MEMORY_MB` — not checked, the capacity is `capacity.default`).

**Rule:** with `unit_mb` in the `capacity` of the role's manifest — `CAPACITY = min(⌊(WORKER_MEMORY_MB − base_mb) / unit_mb⌋, предел
нагрузки)`, where «предел нагрузки» is the load limit; without `unit_mb` there is no memory side in the `min` — `CAPACITY` = the load limit (for `det` — the model device, GPU); the load limit — the processor, disks,
network of the server — is measured and named by the implementation (Implementation decides); the measurement of `unit_mb`, `base_mb` — by the owner lesson (the manifest).
`⌊…⌋` less than 1 — the budget is too small for the role: raise `WORKER_MEMORY_MB`; `CAPACITY` is not below 1 (P/02.4 Н1.5 item 4).

| Role | `capacity` of the manifest | `WORKER_MEMORY_MB` at least (with the default `CAPACITY`) |
|---|---|---|
| `camworker` | `default: 50, unit_mb: 1, base_mb: 18` | 68 |
| `recworker` | `default: 50, unit_mb: 42, base_mb: 51` (`unit_mb` computed from the ring size, checked by measurement) | 2151 |
| `liveworker` | `default: 100, unit_mb: 2, base_mb: 48` | 248 |
| `autoworker` | `default: 50, unit_mb: 1, base_mb: 21` | 71 |
| `detworker` | `default: 8` | not checked (the unit is a detection stream); `CAPACITY` — the load limit; the memory budgets are named by the implementation |
| `detjobworker` | `default: 2` | not checked (the unit is a scan); `CAPACITY` — the load limit; the memory budgets are named by the implementation |
| `detedgeworker` | `default: 2` | not checked (the unit is a watch); `CAPACITY` — the load limit; the memory budgets are named by the implementation |
| `assistworker` | `default: 1`, without `unit_mb` | `CAPACITY` — exactly 1 (not set — 1; anything else — a start refusal, code 2; V/10.1 Н1.2); the model does not compute the memory rule. On a server with the model label — at least 13,600: the holder tree (the worker and the model process) — by the pilot measurement the peak of the model process `gpt-oss-20b` `q8_0` with the window 16384 is 13.2 GB (the harness handover package, ADR-0093 item 8); the number is for the pinned model and window (`gpt-oss-20b` `q8_0`, 16384) by the pilot measurement: a change of the model, the weights or the window — a new measurement and a new number in this row (a decision of «Архитектор» 2026-10-30); other servers — the budget of a light worker is named by the implementation |
| `backendworker` — with the generation of V/11 | `default: 1`, without `unit_mb` | not checked (the unit is an instance, one per server, V/11.1 Н1.2); the memory budgets are named by the implementation; on the camera — by measurement on the first candidate, the threshold and the sample — the owner's word, V/11.1 Н1.1 (ADR-0110 addendum (17)) |

**The package role files are mandatory and pass the memory rule.** The package MUST give `roles/<роль>.env` for each of the nine roles
(`backendworker` — with the generation of V/11) (the installer puts it in place if the file is absent, P/02.4 Н1.7 `steps`): `CAPACITY` — the default
`capacity` of the manifest (the operator — Н3), `WORKER_MEMORY_MB` — not less than the number of the table, `HOST_MEMORY_MB` — the server memory for the role:
named by the implementation for the reference server, the operator edits it for their own; both are positive integers for each role (P/02.4 Н1.5
item 4); for the roles without `unit_mb` the implementation names them together with the load limit. Otherwise the first installation yields a worker that does not start: for `recworker` `CAPACITY=50` requires 2151 MB, and the budget
of the camera worker (460 MB) would give a start refusal, code 2 — with it `CAPACITY = ⌊(460 − 51) / 42⌋ = 9`. A separate check of
the installer does not exist and is not needed: the worker start checks the rule itself and refuses loudly (P/03.4 Н1.2); the package — by reading and
the stand. The manifest default of `rec` (50) stays: it is the measurement of the recorder load and the controller's word for a silent
worker; a smaller budget is a smaller `CAPACITY` in the server's role file. `HOST_MEMORY_MB` is the ceiling of the number of processes of the role on
the server (P/02.4 Н1.5 item 4). For `assistworker` the package puts the budget of a light worker; on a server with the model label the operator writes
at least 13,600 into the role file together with the label (V/10.1 Н1.2). The domain worker `camdomain` has no role file (a skip, the contract
`env-file`).

## Н3 Pass

```
package: an example subsystem file (defaults and words) → the installer puts it in place if the file is absent → the operator edits the values
role: the package puts roles/<роль>.env (CAPACITY = default, WORKER_MEMORY_MB by the table) → the operator for their own server:
  HOST_MEMORY_MB, CAPACITY = min(memory, load) with unit_mb, otherwise the load limit → the start checks memory (with unit_mb) → the worker states CAPACITY in the heartbeat
```

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| the subsystem file is unreadable | start refusal, code 2 | log | fix the file |
| `CAPACITY` does not fit into `WORKER_MEMORY_MB` | start refusal, code 2 | log | a smaller `CAPACITY` or a larger budget |
| `<ДВЕРЬ>_HOST` not among the addresses of `SERVER_NAME`, `0.0.0.0` | start refusal, code 2 | log | remove or fix |
| a set port is taken | start refusal, code 2 | log | an OS port or a free port |
| there is no `CONSOLE_ORIGINS` | the page does not reach the doors (CORS) | browser | write in the console origin |
| a label outside the label alphabet | start refusal of the worker, code 2 | log | fix `LABELS` |

## Implementation decides

The implementation MUST name in its description: **the load limit** of each role on the reference server (processor, disks, network) and
how it was measured — the second side of the `min` in `CAPACITY`; **`HOST_MEMORY_MB`** of the package role files.
