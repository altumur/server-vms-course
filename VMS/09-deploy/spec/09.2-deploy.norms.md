# V/09.2 — Окружение: нормы

Канон главы 2 урока V/09 «Развёртывание VMS» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../09-deploy.md),
[инструкция](09-deploy.README.md). Платформа — выгрузка `cammeta-specs` `d3f8e05`.

Платформа раскладывает и читает файлы окружения: значения юнита → файл роли `roles/<роль>.env` → `w2c.env` → файл подсистемы
`/etc/<sub>/<sub>.env`, раньше прочитанное побеждает ([P/02.4](../../../Platform/02-installer/spec/02.4-installer.norms.md) Н1.2;
разбор — [договор `env-file`](../../../Platform/common/contracts/env-file.md)). Глава собирает, что VMS ждёт в этих файлах:
ключи файлов подсистем (справочно — значение и умолчание нормирует урок-владелец), строки площадки, которые VMS читает, и
как считать `CAPACITY` ролей.

Id норм — `V/09.2-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

### Н1.1 Файлы подсистем

Файл `/etc/<sub>/<sub>.env` (ссылка в `/data/platform/etc/subsystems/<sub>/`, 0644 `root:root`, секретов в нём нет — секреты в
хранилище, P/06.2); файла нет — умолчания подсистемы, не ошибка; не читается — отказ старта, код 2 (P/02.4 Н1.1, Н1.2).
Установщик кладёт файл, только если его нет (P/02.4 Н1.7 `steps`): пакет даёт пример с умолчаниями и словами у каждого ключа.

| Подсистема | Ключ | Умолчание | Смысл | Норма |
|---|---|---|---|---|

`DETJOB_NAME`, `DETEDGE_NAME`, `AUTO_NAME` — `slot.name_env` манифеста) даёт юнит, не файл (P/02.4 Н1.1). Прочие переменные движка —
умолчания движка, файл подсистемы их не задаёт (V/02.2 Н1.3). Таблица — сводка ссылками: ключи нормирует таблица главы-
владельца (у `rec` — V/02.2 Н1.3, «все ключи `rec` — эта таблица»); ключа, которого нет в таблице урока-владельца, VMS не
читает; сводка расходится с владельцем — прав владелец.

### Н1.2 Строки площадки `w2c.env`

Ключи платформы (P/02.4 Н1.2); VMS на них опирается:

- `SERVER_NAME` — адрес дверей процессов VMS по виду двери: HTTP-двери (держатель, архив, WHEP) — `door_address` P/03.4 Н1.7
  (`https://<SERVER_NAME>:<порт>` с комплектом, петля `http://127.0.0.1` без него); RTSP `live` — `rtsp://<SERVER_NAME>:<порт>`,
  без TLS (V/03.6 Н1.4); RTSP держателя `cam` — только петля `rtsp://127.0.0.1:<порт>/<id>` (V/01.2 Н1.3), `SERVER_NAME` её не
  задаёт; и имя слота; имена серверов кластера разрешаются друг у друга и у рабочего места оператора — предпосылка (P/02.4 Н1.7 `warn`).
- `LABELS` — метки сервера: все подсистемы VMS размещают по `labels-subset` (метки единицы ⊆ метки сервера, P/04 Н1.3);
  шлюз с публичным адресом, сервер с GPU — свойство сервера метками, не именем.
- `CONSOLE_ORIGINS` — источники страницы консоли: без них страница не дойдёт до дверей архива и WHEP (CORS, P/03.4 Н1.7;
  V/02.5, V/03.3).
- `W2C_DEPLOYMENT=vms` — глава 1 Н1.2.

### Н1.3 Файлы ролей и `CAPACITY`

Роль воркера подсистемы — `<sub>worker`; файл `roles/<роль>.env` — `CAPACITY`, `WORKER_MEMORY_MB`, `HOST_MEMORY_MB` (P/02.4
Н1.2, Н1.5). Воркер говорит `CAPACITY` в пульсе, контроллер берёт его (`capacity.from: capacity`), умолчание манифеста — для
молчащего. Воркер не стартует, если `CAPACITY × unit_mb + base_mb > WORKER_MEMORY_MB` (P/03.4 Н1.2; без `unit_mb` — не
проверяется).

**Правило:** при `unit_mb` в `capacity` манифеста роли — `CAPACITY = min(⌊(WORKER_MEMORY_MB − base_mb) / unit_mb⌋, предел
нагрузки)`; без `unit_mb` сторона памяти в `min` нет — `CAPACITY` = предел нагрузки (для `det` — устройство моделей, GPU); предел нагрузки — процессор, диски,
сеть сервера — мерит и называет реализация (Решает реализация); замер `unit_mb`, `base_mb` — урок-владелец (манифест).

| Роль | `capacity` манифеста | `WORKER_MEMORY_MB` не меньше (при умолчании `CAPACITY`) |
|---|---|---|
| `camworker` | `default: 50, unit_mb: 1, base_mb: 18` | 68 |
| `recworker` | `default: 50, unit_mb: 38, base_mb: 51` | 1951 |
| `liveworker` | `default: 100, unit_mb: 2, base_mb: 48` | 248 |
| `autoworker` | `default: 50, unit_mb: 1, base_mb: 21` | 71 |
| `detworker` | `default: 8` | не проверяется (единица — поток детекции); `CAPACITY` — предел нагрузки; бюджеты памяти называет реализация |
| `detjobworker` | `default: 2` | не проверяется (единица — скан); `CAPACITY` — предел нагрузки; бюджеты памяти называет реализация |
| `detedgeworker` | `default: 2` | не проверяется (единица — наблюдение); `CAPACITY` — предел нагрузки; бюджеты памяти называет реализация |

**Файлы ролей пакета — обязательны и проходят правило памяти.** Пакет даёт `roles/<роль>.env` каждой из семи ролей (установщик
кладёт, если файла нет, P/02.4 Н1.7 `steps`): `CAPACITY` — умолчание `capacity` манифеста, `WORKER_MEMORY_MB` — не меньше
числа таблицы, `HOST_MEMORY_MB` — память сервера под роль; оба — положительные целые у каждой роли (P/02.4 Н1.5 п. 4),
у ролей без `unit_mb` их называет реализация вместе с пределом нагрузки. Иначе первая установка даёт воркер, который не стартует: у
`recworker` `CAPACITY=50` требует 1951 МБ, и бюджет камерного воркера (460 МБ) дал бы отказ старта, код 2 — при нём
`CAPACITY = ⌊(460 − 51) / 38⌋ = 10`. Отдельной проверки установщика нет и не нужно: старт воркера проверяет правило сам
и отказывает громко (P/03.4 Н1.2); пакет — чтением и стендом. Умолчание манифеста `rec` (50) остаётся: это замер нагрузки
регистратора и слово контроллера для молчащего воркера; меньший бюджет — меньший `CAPACITY` в файле роли сервера.
`HOST_MEMORY_MB` — потолок числа процессов роли на сервере (P/02.4 Н1.5 п. 4).

## Н3 Проход

```
пакет: пример файла подсистемы (умолчания и слова) → установщик кладёт, если файла нет → оператор правит значения
роль: пакет кладёт roles/<роль>.env (CAPACITY = умолчание, WORKER_MEMORY_MB по таблице) → оператор под свой сервер:
  CAPACITY = min(память, нагрузка) при unit_mb, иначе предел нагрузки → старт проверяет память (при unit_mb) → воркер говорит CAPACITY в пульсе
```

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| файл подсистемы не читается | отказ старта, код 2 | журнал | поправить файл |
| `CAPACITY` не помещается в `WORKER_MEMORY_MB` | отказ старта, код 2 | журнал | меньше `CAPACITY` или больше бюджета |
| `<ДВЕРЬ>_HOST` не из адресов `SERVER_NAME`, `0.0.0.0` | отказ старта, код 2 | журнал | убрать или поправить |
| нет `CONSOLE_ORIGINS` | страница не доходит до дверей (CORS) | браузер | вписать источник консоли |
| метка вне азбуки меток | отказ старта воркера, код 2 | журнал | поправить `LABELS` |

## Решает реализация

Реализация обязана назвать в своём описании: **предел нагрузки** каждой роли на эталонном сервере (процессор, диски, сеть) и
как он мерился — вторая сторона `min` в `CAPACITY`.

## Соответствие прежним урокам

Из М10B/17 шаг 8 — файлы окружения на разделе данных, настройка коробки против настройки экземпляра; из М10B/28 шаг 1 —
`CAPACITY = ⌊(бюджет − B) / I⌋`, PSS, слово воркера в пульсе. Отличия от свидетеля: один `vms.env` и `/etc/vms` → файл каждой
подсистемы `/etc/<sub>/<sub>.env` (P/02.4); `CAPACITY` — в файле роли, не подсистемы; `ARCHIVE_VOLUME`, `ARCHIVE_QUOTA_BYTES`,
`SPOOL`, `SEGMENT_SECONDS` — сняты (том — строка), `OBSD_SOCKET` — ключ файла `rec` (обёртка части передаёт его движку), `OBSD_TIMEOUT` — константа
10 с (V/02.2), не ключ; файл ключей
`<ДВЕРЬ>_HOST` и `BACKFILL_*` назван у уроков-владельцев. Id ([id-map](../../common/id-map.tsv)): М10B/17 ш.8 → V/09.2-01,
V/09.2-02; М10B/28 ш.1 → V/09.2-03.
