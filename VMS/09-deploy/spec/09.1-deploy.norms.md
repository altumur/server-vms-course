# V/09.1 — What is installed and in what order: norms

This English text is the source; the Russian translation `ru/spec/09.1-deploy.norms.md` (for people, not in the export) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 1 of lesson V/09 «Развёртывание VMS» (ADR-0080; the VMS module — ADR-0090). Lecture (`ru/09-deploy.md`, for people, not in the export),
[instructions](09-deploy.README.md). The platform is the export `cammeta-specs` `7a875c75`.

The installation mechanism — users, groups, units, directories, the order and refusals — is the platform's
([P/02.4](../../../Platform/02-installer/spec/02.4-installer.norms.md) Н1.1, Н1.7; the installation source —
[P/02.3](../../../Platform/02-installer/spec/02.3-installer.norms.md)). The chapter sets norms for what VMS gives the installer, with which
name base it is installed, in what order its manifests come up and what the operator does after installation.

Norm ids are `V/09.1-MM`; the map to former lessons is [`id-map.tsv`](../../common/id-map.tsv).

## Н1 Form

### Н1.1 Installation source

`MANIFEST_DIR` (P/02.3 «Установочный источник») MUST hold the manifests of the nine subsystems, the bytes of the canon; the page of a subsystem is the file
`<sub>.shell.html` next to its manifest (P/02.3 writes it into the field `shell` of the manifest row) (Kimi's addition to the analysis of the
V/09 review, question 1):

| Subsystem | Manifest | Executable |
|---|---|---|
| `cam` | [`cam.subsystem.yaml`](../../01-cam/cam.subsystem.yaml) and the root shell [`cam.shell.html`](../../01-cam/cam.shell.html) (the field `shell` of the root, V/11.15 Н1.1) | `/usr/lib/cam/worker` |
| `rec` | [`rec.subsystem.yaml`](../../02-rec/rec.subsystem.yaml) | `/usr/lib/rec/worker`; the part `obsd` — the wrapper `/usr/lib/rec/obsd-part`, the engine `/usr/local/bin/obsd` (V/02.2 Н1.1) |
| `live` | [`live.subsystem.yaml`](../../03-live/live.subsystem.yaml) | `/usr/lib/live/worker` |
| `det` | [`det.subsystem.yaml`](../../04-det/det.subsystem.yaml) | `/usr/lib/det/worker` |
| `detjob` | [`detjob.subsystem.yaml`](../../05-detjob/detjob.subsystem.yaml) | `/usr/lib/detjob/worker` |
| `detedge` | [`detedge.subsystem.yaml`](../../06-detedge/detedge.subsystem.yaml) | `/usr/lib/detedge/worker` |
| `auto` | [`auto.subsystem.yaml`](../../07-auto/auto.subsystem.yaml) | `/usr/lib/auto/worker` |
| `assist` | [`assist.subsystem.yaml`](../../10-assist/assist.subsystem.yaml) | `/usr/lib/assist/worker`; the model command `/usr/lib/assist/model-server` and the weights of the pair (`model`, `quant`) — the package (chapter 3; V/10.1 Н1.3) |
| `backend` — with the generation of V/11 | [`backend.subsystem.yaml`](../../11-backend/backend.subsystem.yaml) and the shell [`backend.shell.html`](../../11-backend/backend.shell.html) (`index.html` of the consolem build, V/11.1 Н1.4); next to it — the WebUI suite B7 (chapter 3) | `/usr/lib/backend/worker` |

- The executables are the paths `worker.exec` and `parts.obsd.exec` of the manifests; the package puts them in place (chapter 3).
- **`backend`** (ADR-0094 «Порядок»): its manifest, shell and suite are installed together with the generation of V/11; the norms B (B1, B7,
  B9) are on the pin; before the generation the VMS source is eight subsystems, and the `backend` rows of this chapter and of chapters 2–4 do not apply. The delegation of lessons V/10, V/11 here (source, order, roles, package, health)
  remains.
- **The vendor key** (V/01.7): `/etc/cam/vendor.pem` is a file of the settings directory of `cam` (`/data/platform/etc/subsystems/cam`, 0640
  `root:vms-cam`, P/02.4 Н1.1); the package file `cam/vendor/vendor.pem` lies next to the manifest, settings files are `cam/<имя>`; the installer puts it in place after the users step (P/02.4 Н1.7
  `files`); the operator does not edit it, a new package replaces it; the key is missing, unreadable or not in form — the licence signature does not match
  (`invalid`, with an earlier decision — `degraded`; V/01.7 Н3), and the domain worker goes on working.

### Н1.2 OS name base

- VMS MUST be installed with `W2C_DEPLOYMENT=vms` (P/02.4 Н1.2): the users and groups `vms-<sub>`, the units, the share directories
  `/run/vms-cam-shm`, `/run/vms-rec-obsd`. The base is one per installation: the installer writes it into `w2c.env`; a different one on a repeat is a refusal
  before changes (P/02.4 Н1.7 `w2c_env`).
- The reason: the engine of the `rec` part listens on the socket `OBSD_SOCKET` of the subsystem file, default `/run/vms-rec-obsd/obsd.sock` (it is
  passed by the wrapper `parts.obsd.exec`, V/02.2 Н1.1), the share directory is `/run/<dep>-rec-obsd` (P/02.4 Н1.1), the default of `OBSD_CLIENT_GROUP` is `vms-rec-obsd` (V/02.2). With a different base the part socket and the client group do not match
  the share: the recorder does not connect to the engine. If a different base is needed — `OBSD_SOCKET` and `OBSD_CLIENT_GROUP` of the subsystem file
  of `rec` and `SHM_DIR` of the file of `cam`, not an edit of the manifest for the installation.
- The VMS console MUST be installed with `CONSOLE_ROOT=cam` (an installer input, P/02.4 Н1.7): the page of `cam` is served at `/` (V/11.15).

### Н1.3 The order of `manifest put`

By P/02.4 Н1.7 `order` the target comes before the client; among the ready ones — by name, in bytes. The VMS edges (`assist` and `backend`
have no edges: they have no `worker.requests`; the callback of `backend` by ticket is not an edge):

| Client | Target | Why |
|---|---|---|
| `rec` | `cam` | `worker.requests: [cam]` (V/02.9 Н1.2); `door.routes ingest.domain` — the kinds `stream`, `poll`, `ask` from `domain.tokens` of `cam` (V/01.6); `upstream` is declared by `rec` itself: a link to itself does not count as an edge (P/02.1 Н3) |
| `detjob` | `rec` | `worker.requests: [rec]` (V/05.4) |
| `detedge` | `rec` | `worker.requests: [rec]` (V/06.4) |
| `auto` | `cam` | `worker.requests: [cam]` (V/07.4) |

`placement.near` does not set the order (P/02.4 Н1.7 `order`; ADR-0091 addendum (26)): `cam` near `rec`, `det` and `detedge`
near `cam`, `detjob` near `rec`; while the subsystem `near.sub` is not yet in the catalogue, the affinity waits (`near_waiting` in
the report of the controller pass, P/04; a line of the installer output — if the subsystem is neither in the installation nor in the store, P/02.4 Н1.7 `warn`), and the check of `near.of`, `near.prefer` is postponed until it
appears (P/02.1). `worker.creates` (`auto`, `rec`, `cam`) and `worker.uses` do not set the order. The order of the first installation:
**`assist`, `backend`, `cam`, `auto`, `det`, `live`, `rec`, `detedge`, `detjob`** (without `backend` before the generation of V/11 — the
same order without it).


### Н1.4 After installation

1. **The volumes of the part `obsd`** (`parts.obsd.volumes`) — the operator mounts a disk at `/data/platform/subsystems/rec/obsd/volumes/<n>`,
   the owner is the part user `vms-rec-obsd`; the installer does not create and does not mount them; a foreign owner is a start refusal of the part,
   code 2 (P/02.4 Н1.1). The part checks the owner at start: having mounted the volumes, the operator restarts the part. The number of volumes is a property of the server.
2. **The server volume** is the row `rec/volumes/<имя>` (V/02.1 Н1.2): `kind: local`, `server: <сервер>`, `url:
   file:///data/platform/subsystems/rec/obsd/volumes/<n>`, `quota_bytes` — the ring size (V/02.6 Н1.2), — by the console table door
   (`POST /rec/volumes`, the right `admin`, P/06.1 Н1.6) or by the page (V/11.18). There is no volume variable: places are only the rows of
   `volumes` (V/02.4). Without the row recordings are not placed — visible at once (`/rec/unplaceable`, P/04; the short `/unplaceable` — with `CONSOLE_ROOT` = `cam`).
3. Server certificates are the operator's hand (P/02.4 Н1.7 `not`); health — chapter 4.
4. **Site lines** (V/09.2 Н1.2): `SERVER_NAME` — into `w2c.env` before `install.sh`, it enters the name of the base slot (P/02.4 Н1.1);
   `LABELS`, `CONSOLE_ORIGINS` — after: the processes read them at start, a restart of the server's workers is needed.

### Н1.5 Upgrade

Server by server (P/02.4 Н1.7 `upgrade`). The manifest of the new revision — `manifest put` by P/02.3 — is put after all servers:
the new build works on the previous manifest. Units that have nowhere to go (a recording with its home on one volume, a cluster of one)
do not give `safe: true`: the operator accepts their downtime explicitly, `would_strand` names them (P/06.6 Н1.2), there is no deadline. The keys of the
installation source (`parts`, `worker.stop_timeout`, `shares`, `worker.uses`) take effect only after a reinstallation on the
servers (P/02.3). A change of `worker.reads`, `writes`, `requests` changes the rights file: the new rights come with the new file and a restart of the
store (P/02.5). The part `obsd` comes up with the server before the workers. The grace `OBSD_WRITER_GRACE_S` applies on a restart
of the recorder without the part (V/02.2 Н1.3); a restart of the engine does not keep it.

## Н3 Pass

```
source (nine manifests, backend — with the generation of V/11; pages, executables, vendor key)
→ install.sh with W2C_DEPLOYMENT=vms, CONSOLE_ROOT=cam
→ manifest put: assist, backend, cam, auto, det, live, rec, detedge, detjob (in one pass; near is not an edge)
→ operator: mount the volumes of the part obsd, restart the part, declare rec/volumes/<имя> → health (chapter 4)
```

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| a volume of the part with a foreign owner | start refusal of the part, code 2 | the part log | `chown` the volume to the part user, start the part |
| there is no row `rec/volumes` | recordings are not placed | `/rec/unplaceable` | declare the server volume |
| the name base is not `vms` | the recorder does not connect to the engine | recording status, log | `W2C_DEPLOYMENT=vms` or the keys of Н1.2 |
| the vendor key is missing, unreadable or not in form | `invalid` — not a single licensed camera, all `unlicensed`; with an earlier decision of the member — `degraded`, the set is frozen (V/01.7 Н1.2, Н1.3) | `domain/cam/licence`, heartbeat, the camera phase `/cam/cameras` | reinstall the package |
