## Что такое урок V/09

Как VMS ставится на кластер платформы. Механизм установки — пользователи и группы, юниты воркеров и частей, доли, файлы
окружения, порядок `manifest put`, обновление сервер за сервером — платформы (P/02.3, P/02.4) и в уроке не пересказывается.
Урок нормирует то, чего платформа не знает: что лежит в установочном источнике VMS, какие значения VMS кладёт в файлы,
которые платформа только читает, что оператор делает после установки, из чего собран пакет и по каким числам видно, что
VMS работает.

## Решения для плана

1. **Урок с главами без подсистемы** (как V/08): своей двери и манифеста нет; строки реестра `V/09 no-openapi`,
   `V/09 no-acceptance` — запросом с главой V/09.1. Проверка — чтением и установкой на стенде (стенд — реализации).
2. **Нормативно — то, чего платформа не знает:** состав источника, значения, шаги оператора после установки, числа здоровья.
   Механизм — ссылкой на P/02.3, P/02.4. Сводная таблица ключей V/09.2 — справочная: значение и умолчание нормирует
   урок-владелец; где урок-владелец не назвал файл (`PLAYBACK_HOST`, `ARCHIVE_HOST`, `BACKFILL_BUDGET`, `BACKFILL_WINDOW`) —
   правка урока-владельца (файл подсистемы) в коммите V/09.2.
3. **`W2C_DEPLOYMENT=vms`.** Часть `rec` слушает `--socket /run/vms-rec-obsd/obsd.sock` (`parts.obsd.exec`), а каталог доли —
   `/run/<dep>-rec-obsd` (P/02.4 Н1.1); умолчание `OBSD_CLIENT_GROUP` — `vms-rec-obsd` (V/02.2). Установка VMS задаёт основу имён
   ОС `vms`; иная основа — `exec` части и `OBSD_CLIENT_GROUP` не совпадут с долей (строка урока: «основа — `vms`, иначе поправить
   оба»). Подставлять `<dep>` в `exec` норма P/02.3 не умеет — запрос не нужен, пока основа одна.
4. **Порядок установки — запрос** [`порядок установки`](../../decisions/inbox/2026-10-23-запрос-vms-порядок-установки.md):
   `rec` просит `cam` (`worker.requests`, виды `stream`, `poll`, `ask`), `cam` стоит рядом с `rec` (`placement.near.sub`) — цикл,
   первая установка — код 2 (вектор `install-order` `cycle`). Обход: два прохода (первый — `cam` без `near`/`home: near`, второй —
   `cam` целиком); долг V/09.1.
5. **Том сервера — строка таблицы, не переменная.** Свой том без строки (`ARCHIVE_VOLUME`, `ARCHIVE_QUOTA_BYTES`, `OWN_VOLUME`)
   снят в V/02.4 (места только из `volumes`). После установки оператор монтирует том части (`/data/platform/subsystems/rec/obsd/
   volumes/<n>`, владелец — пользователь части; установщик не монтирует, P/02.4 Н1.1) и объявляет `rec/volumes/<имя>` (`kind:
   local`, `server`, `url: file:///data/platform/subsystems/rec/obsd/volumes/<n>`, `quota_bytes`) дверью консоли или страницей
   (V/08.4); без строки регистратор не пишет никуда — это видно (`/unplaceable`).
6. **Ключ вендора (V/01.7)** — файл каталога настроек `cam`: `/etc/cam/vendor.pem` (0640 `root:vms-cam`, P/02.4 Н1.1 — иные
   файлы каталога подсистемы); кладёт пакет, оператор не правит; путь называет урок, форму подписи — М14.
7. **Значения `CAPACITY` по ролям** — правило и пример, не таблица чисел: `CAPACITY = ⌊(WORKER_MEMORY_MB − base_mb) / unit_mb⌋`
   по `capacity` манифеста роли (замер — у урока-владельца), меньшее из этого и предела нагрузки, который реализация называет
   (процессор, сеть); пример — бюджет 460 МБ для `camworker`.
8. **Снять:** юниты Quadlet, `Containerfile`, `vms.env` одним файлом и `/etc/vms` — ссылка (файлы подсистем и `/etc/<sub>`,
   P/02.4 Н1.1, Н1.2), глаголы точек входа (`worker.exec`), `jobs`, `domainpart`, запасные (P/02.4 Н1.5 — воркеры по заказу),
   `SPOOL`, `SEGMENT_SECONDS`, проверка юнитов регулярным выражением (юниты — платформы).

## Отличия от свидетеля, которые урок записывает

Контейнеров нет — юниты и раннер платформы (P/02.4); файлы окружения — по подсистемам, не `vms.env`; свой том — строка
`volumes`, не переменная; основа имён ОС — `vms` (`W2C_DEPLOYMENT`); порядок `manifest put` — норма P/02.4 Н1.7 (у свидетеля
порядка не было).
