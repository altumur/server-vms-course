# V/02.2 — The engine `obsd` — a part of `rec`: norms

This English text is the source; the Russian [`02.2-rec.norms.md`](../02.2-rec.norms.md) is derived from it by translation and is not edited by hand (ADR-0121).

The canon of chapter 2 of lesson V/02 «Запись» (ADR-0080; the VMS module — ADR-0090). [Lecture](../../02-rec.md),
[instructions](../02-rec.README.md), [the contract `obsd`](../02-rec.obsd.contract.md), manifest [`rec.subsystem.yaml`](../../rec.subsystem.yaml).
The platform is the export `cammeta-specs` `7a875c75`.

Video lies in the volumes of the archive engine `obsd` (ObjectStorage): it is a host service, not a library inside the recorder process and not a
container, — one daemon per server, so that «one writer per volume» means something: all recorders of the server ask one
daemon. For the platform the engine is a **part** of the subsystem `rec` with its own service and user (ADR-0091 item 5); the platform
does not know video. The socket protocol and the properties of the engine are the [contract `obsd`](../02-rec.obsd.contract.md) (chapters V/02.3–V/02.5
refer to it and do not repeat it); the chapter sets norms for what `rec` declares and requires from the part: the service, the socket share,
the environment, the timeouts, the engine version, the duties of the client.

Norm ids are `V/02.2-MM`; the map to former lessons is [`id-map.tsv`](../../../common/id-map.tsv).

## Н0 Vocabulary

Normative keywords (MUST, MUST NOT, SHOULD, MAY by RFC 2119 and RFC 8174) follow the [course canon](../../../../НОРМАТИВНЫЕ-СЛОВА.md). The rules of the module «Платформа» are [P/01.1 Н0](../../../../Platform/01-store/spec/01.1-store.norms.md#н0-vocabulary).

## Н1 Form

**Time.** The archive time is the contract `obsd` «Время и запись SMPL».

**Data.** The chapter has no store rows: the volumes are files and buckets of the engine; the state of the part is
`/data/platform/subsystems/rec/obsd` ([P/02.4 Н1.1](../../../../Platform/02-installer/spec/02.4-installer.norms.md) `dirs`).

### Н1.1 The part `obsd`

`parts: {obsd: {exec: "/usr/lib/rec/obsd-part", volumes: true, stop_timeout: 60}}` — the VMS wrapper; the engine is `/usr/local/bin/obsd`
([P/02.1](../../../../Platform/02-installer/spec/02.1-installer.norms.md) `parts`; the unit of the part, the user, the directories, the runner
`w2c-run.sh part rec obsd` — P/02.4 Н1.1, Н1.9; the socket path is `OBSD_SOCKET` of the subsystem file, Н1.3, not an argument of `exec`; the engine does not read the subsystem file — it takes its keys
from the environment (the socket — `OBSD_SOCKET` or the argument `--socket`, without them — its own path `/run/vms/obsd.sock`), and the unit of the part
gives no environment from a file (P/02.4 Н1.1: only `W2C_SUB_ENV`, `EnvironmentFile=` is not used); therefore the `exec` of the part is
the VMS wrapper: it reads the subsystem file by `W2C_SUB_ENV` (the environment file contract) and starts the engine with the four keys `OBSD_*`
of the table Н1.3 in the environment, the value — from the file or the default of the table; it passes no other names):

- the service `vms-rec-obsd.service`, the user and group `vms-rec-obsd`; the part starts by itself before the workers of `rec`; the unit
  of the recorder is `After=` the part without `Wants`: a restart of the recorder does not touch the engine, loss of the engine does not stop the
  recorder (the recorder survives it by itself — chapter 4);
- the state is `/data/platform/subsystems/rec/obsd` (`0700`); the volumes are mount points
  `/data/platform/subsystems/rec/obsd/volumes/<n>` of the part's user (`volumes: true`; the operator mounts them, the part
  checks the owner at start);
- `stop_timeout: 60`: on SIGTERM the engine closes all writers in parallel, each up to 30 s, and exits no later than 45 s with
  code 3, naming the stuck ones (the contract «Остановка демона»).

### Н1.2 The socket share

`shares: {obsd: {kind: socket, part: obsd}}` — a share of the part: the directory `/run/vms-rec-obsd` `2750 vms-rec-obsd:vms-rec-obsd`,
the socket `obsd.sock` `0660` — the default of `OBSD_SOCKET` (Н1.3) `/run/vms-rec-obsd/obsd.sock` (P/02.4 Н1.1 `dirs`;
ADR-0091 addendum (2) item 4, addendum (3) item 3 — the directory in `ReadWritePaths` of the part); the recorder declares `worker.uses: [rec.obsd]` and gets the group of the part. The socket path is shorter than `sun_path` (the contract
«Транспорт»). The daemon admits a peer of a foreign uid only from `OBSD_CLIENT_GROUP` = `vms-rec-obsd`.

### Н1.3 The subsystem file

The subsystem file `/etc/rec/rec.env` (`W2C_SUB_ENV`, P/02.4 Н1.2) is one for the part and the recorders of the server: the runner of the part
reads the values of the unit and only it, the recorder reads it together with the platform files ([environment file
contract](../../../../Platform/common/contracts/env-file.md): there is no file — the defaults; a line not by the grammar of the contract or
an unreadable file — a start refusal, code 2). All keys of `rec` are this table; the chapters refer here. A value not by the grammar
of the key is a start refusal of whoever reads it, code 2, the log line names the key (the value — without secrets: there are none here). The port `ARCHIVE_PORT` is taken — likewise; growth on the server
(`grows`) — with the OS port.

| Key | Read by | Grammar | Default | Why, where the norm is |
|---|---|---|---|---|
| `OBSD_SOCKET` | the `exec` wrapper of the part (to the engine — through the environment), the recorder | an absolute path shorter than `sun_path` (the contract «Транспорт») | `/run/vms-rec-obsd/obsd.sock` | the socket of the share Н1.2; the stand sets its own instance directory (the common README of VMS acceptance) |
| `OBSD_WRITER_GRACE_S` | the part | an integer ≥ 1 | `90` | the grace of a writer of the same `owner` (the contract «Отсрочка») is longer than the seat timeout of P/03.2 Н1.2 (45 + `HOLD_SKEW` = 50): a restarted recorder picks up its volume (`reattached`) before the seat goes away |
| `OBSD_CLIENT_GROUP` | the part | a group name | `vms-rec-obsd` | Н1.2 |
| `OBSD_LOG_LEVEL` | the part | `off` \| `error` \| `warning` \| `info` \| `debug` | `warning` | — |
| `SEQUENCE_FLUSH_MS` | the recorder | an integer ≥ 0; 0 — the engine default | `10000` | the period of cutting the sequence, chapter 3 Н1.5 |
| `BLOCK_FLUSH_S` | the recorder | an integer ≥ 0; 0 — the engine default | `5` | the period of flushing a block, chapter 3 Н1.5 |
| `ARCHIVE_HOST` | the recorder | optional; when set — an address by the door rule: `SERVER_NAME` with a role kit, `127.0.0.1` without it | — (by the rule) | the address of the archive door, chapter 5 Н1.7; another one or `0.0.0.0` — start refusal, code 2 |
| `ARCHIVE_PORT` | the recorder | an integer 0–65535; 0 — the OS port | `0` | the port of the archive door, chapter 5 Н1.7 |
| `BACKFILL_BUDGET` | the recorder | an integer ≥ 0; 0 — only requests | `1` | catch-up recording ranges per pass, chapter 8 Н1.2 |
| `BACKFILL_WINDOW` | the recorder | `^(\d\|1\d\|2[0-3])-(\d\|1\d\|2[0-3])$` — the hours of start and end by the local hour of the server: the hour in `[a, b)`, crossing midnight (`22-6`), `a = b` — the whole day | none — any hour | the catch-up recording window, chapter 8 Н1.2 |

Other engine variables (`OBSD_SESSION_LINGER_MS` 3000, `OBSD_MAX_FRAME`, `OBSD_RESIZE_STEP_MB` 1024, threads) are the engine
defaults; the subsystem file does not set them.

### Н1.4 Engine version

ObjectStorage is the tree `2bbee4a` (2026-10-02) with patches 01–07 (`standalone-build/patches/`): 01 — build on macOS; 02, 03 —
tests; 04 — waking up by the block flush timer (without it a block closes after a minute, not after
`blockFlushPeriodSec`); 05 — index reads in portions (a timeline over ≥ 6 days); 06 — armv7 (header fields by value);
07 — the fence of the volume lock and `WRITER_ABANDON` (`37e2d0e`). Without 07 the daemon is not fit: the course does not support it — the recorder
checks `WRITER_ABANDON` at connection with the call `{writer: 0}` (the daemon does not issue 0): `UNKNOWN_OP` — no fence, any other
answer status — there is one; no answer — `away`; a new `pid` of the daemon — check again. The build is `standalone-build/build.sh` into
`/usr/local/bin/obsd`; what puts it into the image is lesson V/09.

### Н1.5 Duties of the client

The recorder is a client of the engine (chapter 4); from the client `rec` requires:
- `client` in `HELLO` is the role of the process (`recworker`), not the product name;
- the `owner` of a writer is `rec:<том>`: the same at a restarted recorder of the same seat (the grace picks up the volume);
  uniqueness is given by the platform seat (P/03.2), not by the engine;
- the call timeout is `OBSD_TIMEOUT` = 10 s; engine calls are not on the lease thread: a long call does not delay
  the renewal of the seat; only `FINISH_MEDIA` and `WRITER_CLOSE` are waited for longer than the call timeout: on leaving a volume and at stop —
  until «конец закрытия» of chapter 4 Н1.5, at `seal` — chapter 4 Н1.7 (`WRITER_CLOSE` — no longer than the 30 s of the contract);
- a break after sending a non-idempotent request — MUST NOT be retried blindly (the contract «Повтор»); an unanswered
  `VOLUME_MOUNT_RW` is a possible writer without a handle: release the session without `BYE`, mount again with the same `owner`
  (chapter 3 Н3);
- the volume parameters are `params`, not `uri`: the bucket key does not get into the address and the log (V/02.1 Н1.2, P/06.2).

## Н3 Pass

The chapter has no pass of its own: the part lives by its unit (P/02.4 Н1.1), the protocol is the contract, the client is chapters 3, 4.

**Races.** Two recorders of one server on one volume — the second `VOLUME_MOUNT_RW` gets `ALREADY_LOCKED` (one writer per
host); on different servers — the fence of patch 07 by the volume lock and the platform seat (P/03.2) — chapter 3.

## Н4 Refusals

| Cause | Outcome | Who sees it and how | What the caller does |
|---|---|---|---|
| the socket path is longer than `sun_path` | the daemon does not start | the log of the part's unit | a shorter path |
| `OBSD_CLIENT_GROUP` is an unknown group | the daemon does not start | the log | the group of the part |
| the peer is not in the group | the connection is rejected | the recorder — `away` (chapter 3) | `worker.uses: [rec.obsd]` |
| the daemon without patch 07 | `WRITER_ABANDON` — `UNKNOWN_OP` | the recorder: the volume is not taken, the log | an engine with patches 01–07 |
