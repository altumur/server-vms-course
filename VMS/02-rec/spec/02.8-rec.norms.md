# V/02.8 — Дозапись и заказ скана: нормы

Канон главы 8 урока V/02 «Запись» (ADR-0080; модуль VMS — ADR-0090). [Лекция](../02-rec.md),
[инструкция](02-rec.README.md), манифест [`rec.subsystem.yaml`](../rec.subsystem.yaml). Платформа — выгрузка `cammeta-specs`
`006a56b`.

Когда связи с камерой не было, у записи дыра, а на карте камеры (или в регистраторе) эти минуты есть. Дозапись — сверка
двух покрытий: регистратор забирает с устройства то, чего нет у него, в свой том. Глава нормирует план дозаписи, её бюджет и
окно, выкачку и посадку, просьбу «закрепить» (дозапись по запросу), и заказ скана: те же минуты, что не записались, не
прошли детекцию — регистратор, который их привёз, заказывает задачу `detjob`. Дверь архива устройства — V/01.5; поток
`…/backfill` — [глава 3](02.3-rec.norms.md) Н1.1; копия из резервной — [глава 6](02.6-rec.norms.md) Н1.6; видимость —
[глава 5](02.5-rec.norms.md).

Id норм — `V/02.8-MM`; соответствие прежним урокам — [`id-map.tsv`](../../common/id-map.tsv).

## Н0 Словарь слов

Нормативные слова — по [канону курса](../../../НОРМАТИВНЫЕ-СЛОВА.md). Правила модуля «Платформа» — [P/01.1 Н0](../../../Platform/01-store/spec/01.1-store.norms.md#н0-словарь-слов).

## Н1 Форма

**Время.** Секунды Unix; окно дозаписи — часы местного времени сервера.

**Данные** (общие семьи [каталога платформы](../../../Platform/common/data/catalog.tsv)): читает — просьбы
`rec/requests/<rid>` (P/06.4), строки `det/units/*` (детекторы камеры; `worker.reads`), пульсы держателей и регистраторов;
пишет — видео в свой том (поток `…/backfill`), поле пульса `fetched` (P/03.4 Н1.1), строки заказа `detjob/jobs/rec-<key>`
(`worker.creates`, [P/03.6 Н1.6](../../../Platform/03-worker/spec/03.6-worker.norms.md)), события `archive.backfill.refused`.

### Н1.1 План: дыры вычитанием

Дозапись — работа регистратора записи; источники — по порядку: архив устройства (держатель камеры по пульсу, `playback_url`
и `coverage`, V/01.5 Н1.1; не на чужой петле), затем резервные записи (глава 6 Н1.6). Нет держателя — нет источника.
Дыра записи для источника:

```
ours  = видимое покрытие записи в томе — все её потоки и эпохи, швы ≤ 2 с склеены (глава 5)
lo    = max(начало покрытия источника, now − срок записи, видно с (глава 5 Н1.2), начало ours)   # только дыры внутри записанного
hi    = min(конец покрытия источника, конец видимого ours, now − 900)                         # верх — по видимому
дыры  = [lo, hi) − ours − «у источника нет» (по паре запись × источник) − брошенное − садящееся, ещё не видимое
```

План — только дыры **внутри** записанного: запись по событию не становится постоянной, план не гонится за хвостом кольца.
Нечитаемая сводка источника или срок записи — плана нет.

### Н1.2 Бюджет и окно

- За проход — `BACKFILL_BUDGET` диапазонов (умолчание 1; 0 — только просьбы), диапазон — не длиннее 600 с (остаток — следующим
  проходом).
- Окно `BACKFILL_WINDOW` (`22-6`) — по **местному** часу сервера, с переходом через полночь; без переменной — любой час;
  у источника-карты (`edge`) решает слово камеры `stream.lagging` (свободен — можно, отстаёт — нельзя, молчит — окно).
- Выкачка — на своей нити, одна за раз (у устройства один канал), не на потоке цикла и аренд; проход её не ждёт дольше
  0,5 с.
- Том ничего не принимает (`archive_error`, нет писателя) — дозапись ждёт тома; полного диска не ждёт: том — кольцо,
  выкачанное ложится в голову кольца (позавчерашний час кольцо отдаст позже вчерашнего).

### Н1.3 Выкачка и посадка

- Только под `may_write` и текущей эпохой регистратора (эпоха — «кто записал», не «когда снято»); в поток `…/backfill`
  своего тома, в том, на котором выкачка началась (том сменился — не садить).
- Кусками по 60 с, резанными по ключевому кадру: кусок садится прежде, чем просят следующий; сбойный кусок обрывает
  диапазон — остаток просят снова.
- **Только дыры** второй раз — по группе кадров (от ключевого до ключевого): группа, пересекающая уже наше или садящееся, —
  отброшена; группа без ключевого кадра — отказ. Разрыв больше 2 с закрывает последовательность, следующая — с ключевого
  кадра.
- Отказ движка (`SEQUENCE_*`) — группа не взята; кусок, отвергнутый трижды, — брошен (`backfill.refused_seconds` в пульсе),
  счёт сбрасывается, когда кусок сел.
- «У источника нет» — только после чистой выкачки: то, чего источник не отдал, по паре (запись, источник); сумма —
  `nowhere_seconds` в пульсе.

### Н1.4 Просьба «закрепить»

Раздел `requests:` манифеста ([P/06.4 Н1.5](../../../Platform/06-console/spec/06.4-console.norms.md)): тело `{unit, from, to, lost?}`
(`unit` — id записи), ключ `{unit}-{from:int}-{to:int}`, `per_person: 7`, `settle: 60`, `ttl: 86400`, `stamp: [by, at,
about]`, журнал `archive.backfill.asked`, **`outcome: fetched`** — профиль дозаписи: итог — rid в поле `fetched` пульса
регистратора, метки нет; жнец снимает строку по подтверждённому `fetched` (P/06.4 Н3 «жнец»). Подают оператор (кнопка
«закрепить» на промежутке устройства) и воркеры — задача `detjob` (V/05) и детекция по архиву устройства (V/06) — подачей
воркером (P/03.6 Н1.5).

Регистратор, держащий запись, на каждую свою просьбу (вне бюджета и окна, под `may_act`, под «том принимает»):

```
диапазон не конечные числа | to ≤ from | длиннее суток | короче секунды | to ≤ видно с   → отказ (fetched + отказ)
to > now + 60                                                                            → ждать (не окончательно)
у идущей записи to = min(to, конец видимого или now − 900); from = первая не показанная томом секунда
всё уже есть → fetched
нет источников / источник ошибся / том не принимает → ждать (строка стоит)
источники по очереди до первого без ошибки; выкачано до to → fetched; не до конца → запомнить, ждать
просьба старше ttl (86400) и не обслуживается → fetched с отказом «too old»                (закрывает регистратор, не возраст)
```

Отказ — rid в `fetched`, слово в `requests_refused` пульса (последние 50), событие `archive.backfill.refused` (`request`,
`error`, `of: cam/<камера>`). Нижней границы по началу покрытия у просьбы нет. `lost` — слово продукта (потерянное
регистратором); курс его не подаёт.

Просьба о записи, которой нет (строки нет или надгробие), — не дело регистратора: её закрывает жнец исходом `gone` и
освобождает резерв `per_person` ([P/06.4 Н3](../../../Platform/06-console/spec/06.4-console.norms.md) «жнец» `gone`; ADR-0091 доп. (11) п. 4).

### Н1.5 Заказ скана

Минуты, которые дозапись привезла, не прошли детекцию: события пишет держатель эпохи камеры, а его в это время не было.
Регистратор, посадивший дозапись (`kept > 0` — привезено новое; «уже наше» — не заказывать), заказывает задачу `detjob`
для каждого включённого детектора камеры (`det/units/*` той же `cam`, `enabled`) — пара «диапазон × детектор»:

- `worker.creates: [{sub: detjob, rows: jobs, key: "{cam}-{rec}-{kind}-{from}-{to}"}]` — строка `detjob/jobs/rec-<key>`
  (P/03.6 Н1.6, ADR-0091 п. 1): `cam`, `rec` — запись, `kind` — модель детектора, `from`, `to` — севший отрезок; основа —
  настройки детектора (`params`, `labels` — при создании), маска — ссылкой `mask_from` (задача — V/05);
- время события — момент посадки; горизонт `ORDER_HORIZON` 600 с (старше — `expired`); повтор после `expired` или `refused`
  **с прежним** временем события (новое время возродило бы удалённую оператором задачу — надгробие `made.gone` + 60);
  дыра в сработках, оставшаяся после `expired`, — для человека;
- исходы — `creates.<outcome>`, остаток своих строк — `made_rows` в пульсе (P/03.4 Н1.1); удаление законченной задачи —
  V/05 (`retire_when.delete_after`).

### Н1.6 Шкала

Четыре вида промежутка: записано нами (эпоха записи); `source: backfill` — было на устройстве, теперь наше (то же кольцо,
те же двери); `source: device`, `yields: true` — есть только на устройстве (исчезнет по его кольцу; место кнопки
«закрепить»); пусто — не записано нигде («у источника нет» делает это состоянием). Вычитание «наше побеждает» — одно
правило: страница решает, что показать (урок V/08), регистратор — что забрать (Н1.1).

## Н3 Проход

```
нить дозаписи (одна за раз; том принимает): просьбы (Н1.4) → план (Н1.1) в пределах бюджета и окна (Н1.2) → выкачка и
  посадка (Н1.3) → kept > 0 → заказ скана (Н1.5)
```

**Гонки.** Две просьбы одного диапазона — один rid по ключу; разное тело под тем же rid — 409 `exists` (P/06.4). Живая
запись и дозапись над одной минутой — правило эпохи (глава 5): при равной эпохе живой поток побеждает. Держатель камеры
переехал посреди выкачки — источник ошибся, диапазон спросят снова.

## Н4 Отказы

| Причина | Исход | Кто и как видит | Что делает вызывающий |
|---|---|---|---|
| диапазон нечитаем, пуст, длиннее суток, короче секунды, за потолком | `fetched` + отказ | пульс `requests_refused`, событие `archive.backfill.refused` | другой диапазон |
| диапазон в будущем | ждать | — | — |
| нет источника, источник ошибся, том не принимает | ждать | строка стоит | — |
| просьба старше суток не обслуживается | `fetched` + отказ «too old» | так же | подать снова |
| восьмая неотвеченная просьба человека | 429 (P/06.4) | ответ | ждать |
| записи нет (удалена) | жнец закрывает исходом `gone`, резерв `per_person` свободен | — | — |
| заказ скана: событие старше 600 с | `expired` | `creates.expired` | — |

## Соответствие прежним урокам

Из М10B/16 «Дозапись из края» — шаги 1–11 (чья работа, покрытие, дыры, бюджет и окно, дозаписанное — наше, последовательность
на отрезок, только дыры, «закрепить», ждать тома, находки, что видит оператор); механика просьб — P/06.4, P/03.6. Из М10B/22
«Две дыры, одна причина» — регистратор знает, что привёз, и заказывает скан; окно `closed` и проход `vms jobs` — не
переносятся (ADR-0091 п. 1). Из М10B/15 шаги 7–9 — промежуток устройства и вычитание (дверь — глава 5, страница — V/08).
Отличия от свидетеля: профиль `fetched` (просьбу закрывает регистратор, а не `ttl` жнецом); диапазон в будущем — ждать, не
отказ (P/03.6); `unit` — id записи, не `rec/<id>`; `requests.elsewhere: [record]` снят (запись по сценарию заводит `auto`,
V/07); заказ скана — `worker.creates` под эпохой регистратора с именем `rec-<key>` (у свидетеля — окно `closed` и `vms jobs`);
горизонт 600 с (у свидетеля — 60); своих рядов `/metrics` нет (`nowhere_seconds`, `backfill.refused_seconds`, `creates`,
`made_rows` — в пульсе). Id ([id-map](../../common/id-map.tsv)): М10B/16 ш.1–3 → V/02.8-01; М10B/16 ш.4, 9 → V/02.8-02;
М10B/16 ш.5–7, 10 → V/02.8-03; М10B/16 ш.8 → V/02.8-04; М10B/22 → V/02.8-05; М10B/16 ш.11, М10B/15 ш.8–9 → V/02.8-06.
