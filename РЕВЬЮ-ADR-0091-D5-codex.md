## Закрытие собственных находок d4

### R91-D4-01 — закрыто решением; прежняя серьёзность: блокер

Место исправления: `decisions/0091-механизмы-платформы-по-запросам-vms.md:330–334`, доп. (5), п. 2.

Точная цитата: «argv — разбиение по пробелу, единственное. Раннер исполняет argv сам (без оболочки)».

Ранее строка `/opt/a/worker --label "front desk"` допускала различные разборы без оболочки. Теперь кавычки запрещены; такой вход получает отказ загрузчика с путём ключа. На разрешённом входе `/opt/a/worker --label=front-desk` определён ровно массив `[/opt/a/worker, --label=front-desk]`. Один U+0020 между словами, запрет пустых слов, печатные ASCII и закрытый список запрещённых знаков исключают прежнюю неоднозначность. Правило общее для `worker.exec` и `parts.<часть>.exec`. Строка `exec` не попадает в `ExecStart=`, поэтому дополнительного разбора этой строки менеджером служб решение не требует.

Это явное сужение входной формы. Требование поддерживать кавычки или пути с пробелами из прежней находки не следует.

### R91-D4-02 — закрыто решением; прежняя серьёзность: существенная

Место исправления: тот же ADR, строки 325–329 и 335–339, доп. (5), пп. 1, 3; проверка результата — строки 345–346, п. 6.

Точная цитата: «Раннер берёт `exec` из строки манифеста `platform/manifest/<sub>` при каждом запуске».

Прежний контрпример: после успешного `manifest put` с v1 → v2 супервизор вновь исполнял v1, зафиксированную в установленном юните. Теперь юнит запускает раннер, а раннер каждый раз выбирает программу из принятой строки. Смена команды включена в обычный переход P/02.3; п. 6 отдельно требует проверять исполнение v2 после перезапуска для кластера и домена. Повторное использование старой команды из статического юнита этому решению уже не соответствует.
