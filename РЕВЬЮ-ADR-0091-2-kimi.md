## Проверено без находок

- **П. 1, страж своей эпохи против P/01.1 (guard).** P/01.1 (:93–96): guard проверяется в той же операции, что и cas; право на строку-страж — read вызывающего (P/01.2). Воркер имеет `<s>/epoch/*` write→read, значит `guard {key: <заказчик>/epoch/<unit>, index: моя эпоха}` исполним.
- **П. 1, общее правило строки против P/06.1.** Добавление поля `made` в platform_fields — P/06.1 назван в перечне правок (Consequences); «создание над надгробием, revision = надгробия + 1» (P/06.1) не нарушается.
- **П. 1, наследование эпохи.** «Под той же эпохой/арендой через локальный переход, без новой выдачи» соответствует P/03.3 (наследование эпохи действия).
- **П. 1, поведение свидетеля сверх названных отличий.** Продление только вперёд, `until: 0` не трогается (М10B/25); надгробие по действию (scan — нет, record/detect — да); «строка без `made` от этого заказчика — занята» закрывает коллизию id с ручной строкой; двухписательность названа с порядком; п. 10 («по имени соседа», М10B/26) и п. 7 (`filings.<outcome>`, М10B/25) на месте.
- **П. 3, ABA.** Новая жизнь ключа → новый `born` → состояние от прошлой жизни не действует; ABA по revision невозможен.
- **П. 3, поздний повтор отсечённого держателя.** Закрыт стражем эпохи; номера эпох монотонны (floor P/03.2), ABA эпохи невозможен.
- **П. 3, гонка «прочитал rev R → оператор правил → записал с rev R».** Консервативно безопасна: записанное состояние не действует, уборка — проходом контроллера; Confirmation требует отрицательные сценарии.
- **П. 3, переезд.** Итог переживает переезд (моя находка 1 первой редакции закрыта).
- **П. 3 против P/03.2.** Ограждения NoSlot/Fenced/NotReadThisPass и окно записи места (WRITE_WINDOW/CLOSE_BY) не затронуты; перезапуск по revision без выдачи эпохи на месте.
- **П. 6.** «Цель вызова — группа, цели размещаются вместе, ADR-0011» названо явно — находка 3 первой редакции закрыта.
- **Закрытие находок первой редакции (разбор).** Kimi 1 → п. 3 ✓; Kimi 2 → вариант (Г), контроллера-заказов нет вовсе ✓; Kimi 3 → п. 6 ✓; Kimi 4 → Context переписан без числового счёта ✓.

## Находки

### 1. Существенная — п. 1: «узкое право с id по шаблону» невыразимо в грамматике прав P/01.2 / P/02.5

- **Место:** decisions/0091-….md :37–38 («Права P/02.5 выводятся из объявления: создание, правка, удаление строк этой таблицы с id по шаблону»).
- **Что не так:** P/01.2 (:65–71): образец ключа — exact, prefix (`*` только последним знаком) или отрицание (`!` первым). Суффиксный шаблон вида `<cam>-auto` / `<cam>-<kind>-auto` не выразить ни префиксом, ни отрицанием. Значит право выдаётся либо на всю таблицу чужой подсистемы (`rec/recordings/*` и т. п.) — шире заявленного «узкого», и защита от занятой ручной строки держится только библиотекой, а не правами хранилища; либо требуется новая форма образца. ADR не называет, какое из двух.
- **Контрпример:** rec объявляет таблицу для auto с шаблоном `<cam>-record-auto`. Право `rec/recordings/*-record-auto` невозможно записать; единственный исполнимый вариант — `rec/recordings/*`, который позволяет auto править и ручные строки rec.
- **Источник:** P/01.2 :65–71 (грамматика образцов), P/02.5 Н1.3 («образцы только удаления и отрицания»).
- **Рекомендация:** назвать выбор: (а) право на всю таблицу адресата + обязанность библиотеки как норма, либо (б) расширение грамматики образцов суффиксом/двусторонним шаблоном как отдельной нормой P/01.2.

### 2. Мелкая — п. 1: не записана замена защиты метки от повторной подачи

- **Место:** decisions/0091-….md, п. 1 (вариант Г) — раздел о снятии меток для заказа.
- **Что не так:** у свидетеля метка давала `False` при повторной подаче после исполнения и уборки строки (М10B/25). В варианте (Г) защита собирается из частей: детерминированный id + CAS + «продление только вперёд» + курсор п. 3, переживающий переезд (дыра «свежий процесс на другом сервере» закрыта именно этим). В ADR эта сборка не записана; остаётся неназванное окно: падение заказчика между созданием строки адресатом и сдвигом своего курсора → повторное продление. Оно безвредно (секунды, продление идемпотентно вперёд), но стоит одной фразы, чтобы исполнитель не искал защиту там, где её нет.
- **Источник:** М10B/25 (метка, повторная подача `False`).
- **Рекомендация:** одна фраза в п. 1: «защита от повторной подачи — детерминированный id, CAS, продление вперёд и курсор п. 3; окно падения до сдвига курсора безвредно».
