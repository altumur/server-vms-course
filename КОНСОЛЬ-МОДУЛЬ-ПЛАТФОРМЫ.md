# Платформенный модуль консоли: контракт

2026-10-04. Записка «Консоли» к шагу 3 записки о границе (`ГРАНИЦА-ПЛАТФОРМЫ-И-ПОДСИСТЕМЫ.md`, §2.2, §6.1; ответы «Архитектора» на пять вопросов). Принята «Архитектором» с правками; правки внесены. Кода по ней ещё нет.

Контракт публичный. Его читают курс (`Source/`) и продукт (`vmssubsystem`), по нему пишется страница любой подсистемы.

## 1. Что это

Платформа отдаёт один модуль, `GET /platform/console.js`. Модуль строит из спеки и платформенных дверей всё, что у консоли общее для любой подсистемы:

- дерево единиц;
- вход и сессию;
- серверы;
- домен;
- права;
- журнал.

Страница подсистемы — это **оболочка**. Лежит она рядом с файлом спеки подсистемы как `shell.html` (соглашение курса, 2026-10-05, то же, что ADR-0018 для продукта): корень консоли отдаёт её, если она есть, иначе платформенную страницу; никакой опции `Page` в коде нет, страница это файл. Она подключает модуль, монтирует его разделы, добавляет свои и подписывается на выбор объекта. Платформенная страница `console.html` — та же оболочка в минимальном виде: модуль и больше ничего.

```
<script src="/platform/console.js"></script>
<div id="app"></div>
<script>PlatformConsole.mount(document.getElementById("app"))</script>
```

## 2. Чего модуль НЕ делает

- **Не называет подсистем.** В исходнике модуля нет ни имён подсистем, ни их предметных слов. Словарь запрещённых слов тот же, что у теста границы (§2.7 записки о границе): `vms`, `cam`, `camera`, `камер`, `rec`, `det`, `auto`, `live`, `archive`, `архив`, `footage`, `video`, `видео`, `rtsp`, `device`, `recorder`, `volume`, `whep`, `timeline`. Подписи для единиц и полей приходят из спеки данными (§6).

  **`live` — правило по токену.** `live` как состояние — платформенное слово: живой пульс, `live` и `silent` в `/servers` и `/events`, гейджи `*_live`. Запрещено оно только как имя подсистемы живого видео: `live_url`, `LIVE_NAME` и любой `LIVE_…`, `/live/`, `livecontroller`, `liveworker`. Тест проверяет токены, а не подстроку: `live_url` в модуле не пройдёт, `state === "live"` пройдёт.
- **Не знает других маршрутов.** Модуль ходит только в:
  - `/spec` и `/<sub>/spec` для подсистем из `/mounts`;
  - `/<rows>` и `/<rows>/<id>` (имя `rows` из спеки), и так же под `/<sub>/…`;
  - `/<sub>/<table>` — таблицы, которые спека объявила в `servers.show` (§8);
  - `/where/<id>`;
  - `/servers` и `/servers/<s>/…` (метки, списание);
  - `/policy`, `/drain`;
  - `/domain/*`;
  - `/session` и вход у держателя (`login_url` из `/session`);
  - `/events`, `/marks`;
  - `/metrics` — только гейджи, названные в спеке (`running_gauge`, `workers_gauge`), без зашитых суффиксов;
  - `/mounts`.

  Любой другой маршрут — дело оболочки.
- **Не грузит ничего по адресам, которые ему не принадлежат.** Адрес двери держателя единицы (`/where` → `door`) модуль только отдаёт оболочке через `where()`. Сам он туда не ходит: ни таймлайна, ни кусков, ни WHEP.
- **Не держит свою сессию для оболочки.** Сессия одна, cookie платформы (§5). Оболочка свою не заводит.
- **Не перехватывает чужие разделы.** Карточки и разделы, которые добавила оболочка, модуль только размещает и не трогает их DOM.

## 3. Подключение и жизненный цикл

`PlatformConsole.mount(root, opts) → console` — модуль рисует каркас в `root`:
- полоса разделов;
- дерево;
- инспектор;
- строка состояния;
- окно входа.

Возвращает объект `console`, через который оболочка с ним разговаривает.

Параметры `opts`, все необязательные:

| Параметр | Что |
|---|---|
| `sections` | какие платформенные разделы показывать и в каком порядке: `["units", "access", "journal"]` по умолчанию. Серверы и домен не разделы ленты, а вторая раскладка панели единиц, «По серверам», где домен — корень (как в прежней консоли продукта) |
| `subsystems` | какие спеки дают единицы в дерево: по умолчанию все из `/mounts`. Подсистема, чья спека говорит `about` (§7), вкладывается узлами под единицы родителя; без `about` — своё дерево. Оболочка может сузить список |
| `lang` | `ru` или `en`, язык платформенных подписей модуля; предметные подписи всё равно из спеки |
| `poll_s` | период опроса, 5 с по умолчанию |

`console.version` — версия контракта, целое число, сейчас `1`. Несовместимое изменение — новая версия. Оболочка проверяет версию до вызовов. Модуль отдаётся как `/platform/console.js?v=<версия>`; старые версии не отдаются: обратная совместимость по решению владельца (2026-10-04) не держится, пока система работает только на одной машине.

## 4. Объекты и выбор

Всё, что выбирается в дереве, — объект со ссылкой `ref`, строкой:

| `ref` | Объект |
|---|---|
| `unit:<sub>/<id>` | единица подсистемы `<sub>` (`<sub>` — имя спеки) |
| `server:<s>` | сервер |
| `worker:<sub>/<w>` | воркер подсистемы |
| `member:<m>` | член домена |
| `domain` | домен целиком |
| `person:<name>` | человек домена |
| `<prefix>:<…>` | объект оболочки: префикс выбирает оболочка, модуль его только хранит и отдаёт |

API выбора:

- `console.select(ref)` — выбрать: модуль подсвечивает узел дерева и открывает карточку.
- `console.selected()` → `ref` или `null`.
- `console.on("select", (ref, obj) => …)` — после каждого выбора. `obj` — то, что модуль знает об объекте: строка единицы из `/<rows>`, строка сервера из `/servers`, строка члена домена.
- `console.on("refresh", data => …)` — после каждого опроса: `{units, servers, domain}` как они пришли.
- `console.on("logout", …)`.

## 5. Сессия и запросы

- Вход — модуль: окно входа, `login_url` из `/session`, `POST /session {token}`, break-glass, выход. Cookie сессии ставит платформа, она общая для всех дверей кластера (§6.1 записки о границе: тот же токен на двери воркера).
- `console.api(method, path, body)` — запрос с сессией и тем же правилом ключа, что сейчас в странице продукта: один `Idempotency-Key` на одну отправку; повтор с тем же ключом после сети, таймаута, 5xx и 409 «in flight»; 2xx и 4xx ключ закрывают. Оболочка шлёт все свои записи через него, чтобы правило было одно.
- `console.kindWord(e)` и `console.eventNote(e)` — слово и описание события: для платформенных видов (`server.*`, `worker.*`) из словаря модуля, для видов подсистемы из `display.kinds` её спеки. Оболочка события платформы сама не называет.
- `console.where(ref)` → `{worker, server, door, reason}` — где единица и адрес двери её держателя. Оболочка сама идёт на `door` за байтами, с той же cookie.
- 401 из любого запроса, модульного или оболочки через `api()`, открывает окно входа.
- **Права.** `/session` отдаёт гранты вызывающего: `view` / `edit` / `admin` и скоупы (`unit:<sub>/<id>`, `labels:<…>`, `*`). Модуль сам прячет правку и действия, на которые прав нет, и отдаёт `console.may(action, ref)` → `true | false`, чтобы оболочка делала то же для своих вкладок. Действия: `view`, `edit`, `admin`. Правило, чья единица под каким скоупом, одно и живёт в модуле; оболочка его не повторяет. Сервер всё равно проверяет каждый запрос, а `may` только не показывает человеку то, в чём ему откажут.

## 6. Слова из спеки: `display`

Модуль не знает, что единица — камера. Спека может нести слова для показа:

```yaml
display:
  unit: камера
  units: камеры
  field_help:
    labels: сети, в которых виден адрес камеры (vlan:cctv-a)
    source: адрес устройства
```

Ещё ключи (все — слова и один флаг, без логики):

```yaml
display:
  section: Камеры            # подпись первого раздела ленты
  tree:
    group_title: Папки       # раскладка по group_by: заголовок и подсказка
    group_hint: по папкам камер
    filter: имя, адрес, метка  # подсказка фильтра
    no_group: без папки      # строка единиц без группы
    children: false          # не вкладывать в дереве единицы подсистем, чей about указывает на эту
    contents_title: Состав папки   # подписи карточки группы
    group_word: Папка
    no_group_suffix: без папки
    pick_note: выберите камеру в дереве   # пояснение обзора раздела, когда ничего не выбрано
    new_root: ＋ Папка           # и «Создать папку» в меню «без группы»
    new_sub: ＋ Подпапка         # и «Создать подпапку» в меню группы
    add_here: Добавить камеру сюда
    new_group_note: Папка создана — добавьте в неё камеру, иначе она не сохранится   # без него модуль пишет общее со словом из display.unit
  units_count: камер         # множественное в родительном падеже для счётчиков: «12 камер», «Камер внутри»
```

Создание единицы — кнопкой «＋ <единица>» в шапке обзора раздела и в шапке группы (из группы новая единица сразу в ней). Карточка может положить `<button class="pc-hdbtn">` сразу под свой `<h1>`, модуль переносит такие кнопки в шапку рядом с `addAction`; путь карточки — `<span class="pc-crumbs" data-crumbs='[[слово, ref]]'>` внутри `<h1>`, модуль рисует его крошками. Членов домена модуль вкладывает в дерево сам по `topology.via`. Обзор «По серверам» — блок «Кластер»: счётчики, политика юнитов на сервере, версия раскладки из `/schema`.

Ключи карточки единицы (слова, раскладка и один флаг, без логики):

```yaml
display:
  general: Камера                    # подпись вкладки общей формы
  fields: {source: Адрес, live: Живой поток}   # подписи полей
  options: {live: {always: всегда, on-demand: по требованию}}   # слова значений; НАБОР значений — из schema.enum поля спеки, не отсюда
  form:                              # блоки общей формы по порядку; поле вне блоков не показывается; без form — один блок со всеми полями
    - {title: Устройство, fields: [name, source, cred_username, cred_secret], state: true}   # state — значок состояния единицы
    - {title: Размещение, placement: true, note: "…"}   # placement — «Воркер · сервер», состояние, причина из /where, «Удалить»; note — пояснение под блоком
    - {title: Состояние, status: [{field: stream, since: stream_since, title: Поток}]}   # status — поля статуса воркера только для чтения, «с какого момента» из since; слова значений из options
  events: false                      # модуль не добавляет свою вкладку «События» (журнал единицы и отметки): их показывает страница
  tree: {not_in: "…", add_to: "Добавить в папку…", no_others: "…", new_group: "＋ Новая папка", remove: "…"}   # слова блока групп в форме; без них — общие
```

Карточке страницы (`addCard`) и её разделу (`addSection`) модуль даёт собственный вложенный контейнер: опоздавшая отрисовка после запроса страницы попадает в отсоединённый узел и не стирает карточку, выбранную позже.

Поведение карточки: карточка пишет `<h1>` и `nav.pc-tabs`, модуль переносит их в шапку (путь, звезда, «на весь экран», вкладки); разделы с `<h2>` модуль делает блоками `.card`; форму сохраняет подвал; логическое поле существующей единицы пишется сразу, как переключатель.

И три ключа:

```yaml
display:
  kinds:                 # виды строк журнала и событий единицы, словами
    camera.clock.step_forward: часы камеры скакнули вперёд
  actions:               # подписи действий единицы, если спека объявляет действия
    restart: перезапустить
  tree:
    group_by: folders    # группировать дерево по полю-списку; модуль не знает, что это папки
```

Модуль пишет «камеры воркера», «добавить камеру», подсказки к полям, виды строк из `display`. Без `display` он пишет «единица», «единицы», имя поля и вид строки как есть. `display` — только словарь: в нём нет логики, условий и маршрутов.

## 7. Разделы модуля

| Раздел | Что в нём | Маршруты |
|---|---|---|
| `units` | дерево единиц по спекам из `opts.subsystems`; подсистемы с `about` — узлами под единицами родителя (ниже); группировка по `display.tree.group_by`; избранное по `ref` (localStorage); карточка единицы: поля из спеки, правка (секреты пустые, уходят только изменённые поля), вкл/выкл, удаление, где и почему (`/where`), события единицы и отметка | `/spec`, `/<rows>`, `/where`, `/events`, `/marks` |
| `servers` (раскладка «По серверам» панели единиц) | дерево «домен → сервер → воркеры»; карточка сервера: ресурс, воркеры, метки (`platform/servers/<s>`), `servers.show` из спеки (§8), вывод из эксплуатации, списание; карточка воркера: слот, аренда, зависание, конфликт имени, единицы воркера | `/servers`, `/servers/<s>/labels`, `/servers/<s>/decommission`, `/drain`, `/policy` |
| — | Воркер, чей пульс несёт `server_unsaid` (ADR-0029: не назвал свой сервер при `placement.places.server_field`), — метка «сервер не назван» в строке дерева с текстом базы в подсказке и предупреждение с тем же текстом в карточке воркера. Слово модуля, без логики, без ключей `display`, в `/metrics` не идёт | пульс |
| `domain` (корень раскладки «По серверам») | члены, ключи, топология, перенос, тревоги, keys-view | `/domain/*` |
| `access` | люди, гранты, break-glass | `/domain/users`, `/domain/grants`, `/domain/break-glass` |
| `journal` | события всех подсистем, виды строк словами из спеки (`display.kinds`) | `/events` |

### Что ещё модуль делает сам (сверка с консолью продукта, решения «Архитектора»)

1. **Создание единицы.** Кнопкой «＋ <единица>» в шапке обзора раздела и в шапке группы (из группы — сразу в ней); общая форма по типам для новой единицы с умолчаниями из спеки, `POST /<rows>`. Номер numbered-подсистемы даёт сервер, новая единица выбирается. Немедленное создание с адресом-заглушкой, как в прежней консоли, не воспроизводится: `source` обязателен и уникален (ADR-0002), вторая заглушка была бы отказана.
2. **Пользователь, выход, аварийный вход.** Имя вошедшего и «Выйти» (`DELETE /session`) в меню шапки. В окне входа — аварийный вход: `POST /session/break-glass {who, why, password}`.
3. **«Повторить» у тоста.** Запись, исчерпавшая повторы с тем же ключом, показывается тостом с кнопкой. Кнопка отправляет тот же метод, путь и тело, значит и тот же ключ.
4. **Записанное сервером.** Витрина «кто какую строку написал» — платформенная (записка о границе §3 п. 5, шаг 7 у «Платформы»): маршрут `/servers/<s>/writes` отдаёт платформа по спекам, вкладка в модуле. До маршрута платформы — вкладки оболочки над маршрутом `vms/console.go`, временно.
5. **Версия раскладки хранилища.** `/schema` показывается в блоке «Кластер»; подъёма (`PUT /schema`) в прежней консоли не было, в контракт он не входит.
6. **Неразмещённые.** Карточка «Не размещены» из `/unplaceable`: почему каждая единица без места и какие метки у серверов.
7. **Таблица.** Не делается: в прежней консоли продукта табличного вида с массовой правкой не было (остались только стили), так что в «точь-в-точь» он не входит. Если владелец захочет, это новая функция модуля: вторая раскладка дерева с колонками из `display.tree.columns`, сортировкой и массовой правкой полей спеки через общую форму.
8. **Группы.** Узел группы по `display.tree.group_by` — объект с `ref` `group:<sub>/<field>/<значение>` и своей карточкой: значение, число единиц, список. Действия:
   - переименовать — перезаписать значение в поле-списке у всех единиц группы через `console.api`, одним ключом на операцию, с отчётом, что не удалось;
   - создать — значение появляется, когда его получает первая единица, а пустая группа — это только фильтр;
   - «без группы» — особый узел.

   Пустая группа («＋ Папка», «＋ Подпапка») живёт в браузере, пока её не получит единица; меню группы: создать подгруппу, переименовать, добавить единицу сюда; у «без группы» — создать группу. Всё это модуль, обобщённо для групп. В меню любой единицы модуль даёт «Удалить» по `may(admin)`. Значения групп без единиц из общих настроек домена модуль читает сам (`/domain/shared/<sub>`). Оболочка добавляет через `addCard`/`addMenu`/`addTab` только своё.

Мелочи: тема светлая/тёмная вручную — модуль; выключенная вкладка «Детекторы», меню камеры («Смотреть видео», «Запись») и общие настройки домена — оболочка.

### Зависимые подсистемы: `about`

Шаг 2 записки о границе вводит в спеку `about: {sub: vms, field: cam}`: единицы этой подсистемы — про единицу подсистемы `vms`, связь по полю `cam`. Модуль использует это сам: записи, детекторы, сценарии одной камеры показываются узлами под этой камерой, словами из `display` своей спеки, с карточкой по своей спеке. Оболочке не нужно знать, что записи живут под камерами: это знание одно и лежит в спеке. `addTreeNodes` (§9) остаётся для того, что не единица ни одной подсистемы: например, тома, которые хранятся в таблице, а не в единицах.

## 8. Таблицы подсистемы на карточке сервера: `servers.show`

Модуль рисует их всегда: это карточка сервера для подсистемы без своей страницы (платформенная страница, `testsub`). Страница продукта может закрыть то же место своим блоком (`addBlock`) с кнопками и состоянием; тогда таблица `servers.show` для этой таблицы не рисуется. Страница говорит об этом ключом `covers: "<sub>/<table>"` у `addBlock` (`addBlock("server", {id, covers: "rec/volumes", render})`). Модуль рисует таблицу блоком `.card` с заголовком `title`, строки `GET <base>/<table>` с `row[by] === имя сервера`, колонки из `columns` с подписями из `display.fields` подсистемы (иначе имя поля; `columns` проверяются против полей таблицы в спеке), секреты маской, пусто — «Нет строк».

```yaml
servers:
  show:
    - {table: volumes, by: server, title: тома, columns: [name, kind, quota_bytes]}
```

Модуль читает таблицу `<sub>/<table>` через `/<sub>/<table>` и показывает строки, у которых `by` равно имени сервера. Что такое том, он не знает: показывает колонки из `columns` и подпись из `title`.

## 9. Что добавляет оболочка

Модуль — библиотека платформы, оболочка — страница продукта, которая её вызывает. Вызовы ниже — это оболочка, обращающаяся к библиотеке внутри своей страницы, а не платформа, вызывающая подсистему; хуками в смысле записки о границе (§1.1) они не являются.

- `console.addSection({id, label, icon, after, off, render(host)})` — свой раздел в ленте: в продукте «Сценарии». `after` — id раздела, за которым он стоит; `off` — раздел виден, но выключен, с причиной в подсказке.
- `console.addBlock(kind, {id, render(host, ref, obj)})` — свой блок на общей вкладке карточки объекта вида `kind`, после блоков модуля, в порядке добавления (в продукте: «Архивы сервера» и выключенный «Видеоускоритель» на обзоре сервера).
- `console.icon(name)` — разметка значка по имени (значка модуля или добавленного через `addIcons`), чтобы собственные строки страницы выглядели как строки модуля.
- `console.addAction(kind, (ref, obj) => [{label, run}])` — кнопки страницы в шапке карточки объекта вида `kind`, перед звездой (в продукте: «＋ Камеру в архив» у сервера).
- Подзаголовок карточки: `<p class="pc-hdsub">` сразу после `<h1>` модуль переносит в шапку под заголовок (модуль так пишет «Держатель домена — …»; у члена домена — вид сервера из `title` в `addDecor`).
- Семьи ключей домена на вкладке «Ключи» — НЕ вызов. Свои семьи модуль подписывает сам (члены, публикации членов, сети держателя, топология, правки в ожидании, итоги правок, вид домена); семьи подсистемы это декларация её части домена в спеке (раздел `domain:` — что подсистема несёт в `domain/<sub>/…`, с словами в `display`), модуль читает их из `/spec`: состав из `spec.domain.keys` — `[{id, keys?, prefix?}]`, слова из `display.keys` — `{id: {title, about, absent?}}`, слитые по `id`; ключ вне семей — «Прочие ключи». До появления раздела `domain:` в спеке оболочка передаёт семьи временным параметром `opts`, как раньше `about`, и этот параметр удаляется вместе с его тестами, когда раздел появится (правило владельца о совместимости).
- `console.spec(name)` — копия спеки подсистемы из `/spec` для кода страницы (например, таблица мест из `spec.places`); страница спеку не разбирает сама и не ходит за ней отдельно.
- `addGroupValues` удалён (2026-10-05): значения групп без единиц модуль читает сам из `/domain/shared/<sub>` по `domain.shared` спеки (ADR-0010).
- `console.addNote(kind, (ref, row) => text | [text])` — слова страницы о единице, которых спека сказать не может, потому что за ними порог или логика (в продукте: «открытие не завершается дольше 15 с», «сбой устройства»); показываются предупреждениями под «Размещением».
- `console.addEventNote((e) => text)` — описание событий подсистемы словами (суммы, причины) везде, где модуль показывает события, включая «Журнал». Слово вида остаётся из `display.kinds`, события платформы модуль описывает сам; страница не зовёт модуль повторно для того же события (у оболочки защита от повторного входа).
- `console.addIcons({имя: svg})` — значки страницы по имени: внутренность svg 16×16, это код страницы, не данные. Свои значки модуль рисует сам (разделы, сервер, воркер, домен, папка, человек, фильтр, поиск); имя, которого никто не нарисовал, показывается точкой. `addDecor().icon` и `addSection({icon})` называют значки по этим именам.
- `console.addTab(kind, {id, label, render(host, ref, obj), busy})` — своя вкладка на карточке объекта вида `kind` (`unit`, `server`, `worker`, `member`, `domain`). В продукте это:
  - вкладки «Видео» и «Архив» у `unit:/…`;
  - «Тома» у `server:…`, если их не покрыл `servers.show`.
  `busy()` — необязательная функция вкладки: пока она возвращает `true`, модуль не перерисовывает карточку по опросу (в продукте: пока идёт просмотр и согласование живого потока). Модуль не знает, что именно занято; это обычный вызов оболочки в библиотеку.
- `console.addTreeNodes(kind, (ref, obj) => [{ref, label, icon, count, kids, badge, tags, dot, title, off, open, after, replaces}])` (`count` — счётчик справа; `kids` — вложенные узлы той же формы; `badge` — значок; `tags: [text | {text, title}]`; `dot: [цвет, слово]`; `title` — подсказка; `off` — выключен; `open` — раскрыт, пока не свернули; `after` — ставится после членов за ретранслятором; `replaces` — узел стоит на месте строки члена домена, так сервер-камера становится своей камерой) — дочерние узлы своих объектов, которые не единицы ни одной подсистемы (единицы зависимых подсистем модуль вкладывает сам по `about`, §7): например, тома под сервером. Их `ref` с префиксом оболочки. Выбор такого узла приходит в `on("select")`, карточку рисует оболочка в `render` своего раздела.
- `console.addCard(prefix, render(host, ref))` — карточка объектов оболочки (их `ref` с её префиксом: `vol:<имя>`, `rec:<запись>`) в инспекторе модуля, на том же месте, со звездой и полным экраном; без этого карточку узла оболочки было негде рисовать, кроме как лезть в DOM модуля.
- `addTreeNodes` принимает и верхний уровень: `addTreeNodes("servers", () => [...])` — узлы оболочки на верхнем уровне дерева серверов, без родителя (объекты, которые ничьи и которые обслуживает любой сервер); `addTreeNodes("server", (ref, obj) => [...])` — узлы под конкретным сервером.
- `console.addMenu(kind, (ref, obj) => [{label, run}])` — пункты контекстного меню узла.
- `console.addDecor(kind, (ref, obj) => ({icon, badge, title}))` — иконка, значок и подсказка узла дерева и заголовка карточки объекта вида `kind`. `icon` — имя значка из `addIcons` или из значков модуля; `badge` и `title` — текст, модуль его экранирует. Логики в модуле нет, это тот же вызов оболочки в библиотеку, что `addTab`. В продукте так приходят иконки серверов (центр, офисный, камера).

**Карточка единицы: общая форма и своя.** Общая форма модуля строится из `/spec` по типам полей и обязана уметь всё, что из типов следует: поле `list` редактируется строкой через запятую, поле `group_by` — блоком групп, поле `secret` показывается пустым с подсказкой «задан» и правилом `bound_to`, поле `labels` подсказывает значения из меток серверов, «где и почему» берётся из `/where`. Это платформенная работа, и в оболочку она не уходит. Оболочке остаётся то, что из спеки не следует, двумя вызовами:
- `console.addFieldEditor(kind, field, render(host, ref, obj, value, set))` — свой редактор одного поля внутри общей формы (в продукте: разбор `source` на адрес, производителя и модель); `set(value)` отдаёт значение форме, отправка остаётся за формой.
- `console.addTab(kind, {id: "general", label, render(host, ref, obj)})` — своя карточка вместо общей, когда нужна другая компоновка; внутри неё оболочка вставляет общую форму хелпером `console.unitForm(host, ref)` и не повторяет ни одного поля спеки сама. Обязательства те же: правка через `console.api`, секреты пустые, `bound_to`, `may()`.
Правило выбора: если чего-то не хватает общей форме для любой подсистемы, это чинится в модуле; `general` берут только ради компоновки.

**Оформление** (решение владельца 2026-10-04: новая консоль выглядит и работает точь-в-точь как прежняя консоль продукта). Облик модуля — это облик консоли продукта, общий для всех страниц: шапка со счётчиками из гейджей спеки и меню пользователя (тема, частота обновления, «Обновить», «Выйти»), лента разделов, панель дерева с раскладкой, фильтром, звездой и «⋯», изменяемая ширина, подвал «Отменить»/«Сохранить», карточки. Общие стили — файл модуля `w2cplatform/console.css`, отдаётся платформой рядом с `console.js`; классы в нём нейтральные, словарь §2 действует и на имена классов. Стили предметных вкладок (видео, архив, карточка камеры) остаются в странице продукта. Страница может переопределить тему, но ничего не обязана.

Всё, что оболочка добавила, модуль размещает и перерисовывает по своему опросу, вызывая `render` снова. Прокрутку и фокус внутри хоста сохраняет модуль (тот же `paintInto`, что сейчас в продукте).

## 10. Без оболочки: минимальная страница и `testsub`

Это и есть тест контракта.

- **Платформенная страница** (`w2cplatform/console.html` в продукте `vmssubsystem`, `Source/w2cplatform/console.html` в курсе) — три строки из §1 и больше ничего. Ничего не добавляет и работает на любой спеке.
- **`testsub`** — фиктивная подсистема (`testsub.subsystem.yaml`, §2.3 записки о границе). Тест поднимает консоль только с ней и открывает минимальную страницу в jsdom. Проверяет:
  - дерево единиц;
  - добавление, правку и удаление;
  - события и отметку;
  - серверы, вывод и списание;
  - вход;
  - что в DOM нет ни одного слова из словаря §2;
  - что модуль не сделал ни одного запроса вне списка §2: тест перехватывает `fetch` в jsdom и сверяет каждый путь со списком. Это и есть проверка «не знает других маршрутов».
- **Тест словаря** по исходнику `/platform/console.js` и `console.html`: уже есть для нынешней страницы, `vms/consoletest/platform-page.test.js`.
- **Страница продукта** (`vms/shell.html` рядом со спекой, в продукте и в курсе; прежняя `vms/console.html` удалена, ADR-0018) подключает модуль и добавляет видео, тома, сценарии. Её тест проверяет, что она не дублирует платформенные разделы: в ней нет своего входа, своего дерева серверов, своего домена.

## 10a. Страница держателя домена

Страница держателя домена — модуль: `PlatformConsole.mount(app, {sections: ["domain"]})`, ничего своего. Дверь держателя (`cmd/domain`) отдаёт для неё те же пути, что консоль кластера:
- `GET /spec`, `GET /mounts` (по `SPEC_DIR`, без своих слов);
- `GET|POST|DELETE /session`; `login_url` — `/api/login`;
- `GET /domain` (вид), `GET /domain/alarms`, `GET /domain/keys`;
- `POST /domain/members`, `DELETE /domain/members/<m>`, `PUT /domain/topology`;
- `GET|PUT /domain/shared` — `GET` отдаёт `{doc, delivery, declared: {<sub>: [{name, type}]}}` (объявленные поля из `domain.shared` спек и их типы); `PUT {base_rev, shared: {<sub>: {<поле>: значение|null}}}`;
- `POST /domain/handover {to}`, `POST /domain/stranded/apply {path, key}`;
- `GET /domain/users`, `/domain/grants`, `/domain/break-glass` и их правки;
- `/domain/<sub>/<rows>|<table>` по объявлению; `/domain/<sub>/…` на дверь воркера подсистемы (только настройки и строки; байты мимо консоли, ADR-0015).

`/servers`, `/drain`, `/schema`, `/unplaceable`, `/metrics`, `/events` у держателя не нужны: модуль переживает их отсутствие. Одни пути буквально: консоль кластера пересылает `/domain/X` на `/domain/X` держателя без переписывания; все людские маршруты держателя живут под `/domain/*` (`members`, `topology`, `users`, `grants`, `break-glass`, `pending/`, `shared`, `alarms`, `handover`, `stranded/apply`, `<sub>/<rows>`, `<sub>/<table>`), а `/api/*` остаётся процессам (`carry/`, `member/`, `relay/`, `backup`, `holder`) и входу `/api/login`. Все людские `/api/*` (включая `/api/state`, `/api/keys`) уходят в коммите, где страница становится модулем (ADR-0003); курс переименовывает свои людские `/api/*` в консоли домена на `/domain/*` в тот же день (правило 5 `СЕССИИ.md`). В модуле раздел `domain` показывает раскладку «По серверам» с доменом в корне; карточка домена несёт срок и передачу, «применить заново», единицы по подсистемам, общие настройки по `declared` и правки для кластеров (pending и outcomes). До этого коммита у держателя временная урезанная `page.html` без VMS-ного (долг в PROVENANCE).

## 11. Порядок работ

1. Записка (эта) → просмотр «Архитектора».
2. Модуль в продукте: из `vms/console.html` выносится платформенная часть (вход, дерево, инспектор, серверы, домен, права, журнал, `api()`, `paintInto`). Предметные слова заменяются на `display`. Модуль отдаётся платформой по `/platform/console.js`. Нужен бэкенд «Сборки»:
   - маршрут `/platform/console.js`;
   - `display`, `servers.show`, `about`, `running_gauge` в спеке и в `/spec`;
   - гранты вызывающего в `/session`;
   - `platform/servers/<s>` для меток;
   - `door` в `/where`.
3. Минимальная страница и тест `testsub` (§10).
4. `vms/console.html` продукта становится оболочкой: видео, архивы, тома, сценарии, ингест и пересечения домена.
5. `domain/page.html` удаляется: платформенная часть домена в модуле, камеры и пересечения в `shell.html` продукта; опции `Page` нет (§1).
6. Курс: модуль переносится как есть (это JS, общий для курса и продукта `vmssubsystem`), `vms/console.html` курса пишется по образцу продукта, урок 16 делится на два (ответ 4).

## 12. Решения по вопросам («Архитектор», 2026-10-04)

1. **Язык модуля.** `opts.lang`; словари платформенных подписей внутри модуля, по одному на язык; предметные слова только из спеки.
2. **Учётки потребителей потока** (`/domain/stream-clients`). Это часть VMS в домене: `domain/vms/…` пишет воркер VMS. Оболочка показывает их своей вкладкой в разделе `access`.
3. **Раскладка «по папкам».** `display.tree: {group_by: folders}` — общее «группировать дерево по полю-списку»; модуль не знает, что это папки. Избранное в модуле, по `ref`.
4. **Подсистемы в дереве.** Модулю хватает `/mounts` и `about` (§7): по умолчанию все подсистемы, зависимые вложены под родителя, остальные отдельным деревом.
