## Разбор п. 3 по перечню поручения (щели)

Правило: клиент двери своего кластера, чей адрес — петля (`127.0.0.0/8`, `::1`), соединяется с этим адресом, а имя сервера (SNI и проверка SAN DNS) берёт из `SERVER_NAME` своего `w2c.env`; центр, роль и отзыв — без изменений; `SAN IP` не добавляется.

- **Клиент на петле, дверь чужого кластера той же машины** (стенд из трёх кластеров на 127.0.0.1): имя по своему `SERVER_NAME` может совпасть (общий hostname), но центр — свой `ca.pem`, цепочка чужой консоли к нему не сойдётся → отказ (`peer` шаг 3 / `bad_chain`). Закрыто центром, не именем — и это названо («центр … без изменений»).
- **SNI**: клиент шлёт `SERVER_NAME`; у двери один лист её роли — выбору сервера нечего менять, небезопасного подбора по SNI нет.
- **`::1`**: клиентская часть признаёт `::1` петлей — см. находку 1 о привязке.
- **Агент к своей консоли** (доп. (7): петля, подпись агента): покрыт общей фразой «клиент двери своего кластера»; класс `unasked` листа клиента не запрашивает — своего комплекта агенту не нужно, `ca.pem` на коробке с комплектом есть; подпись агента поверх TLS сохраняется.
- **Скрипт воркеров** (P/02.4 Н1.6 `roles`, второе узкое исключение: без комплекта, только GET публичной `/metrics` консоли, проверка сервера — центр `ca.pem`, роль `console` в SAN, имя, отзыв): «имя» там не имело источника; п. 3 даёт его (`SERVER_NAME`) — согласовано, не ослабляет.
- **Пересылка консоли домена своей коробки** (консоль кластера держателя → дверь класса `role` консоли домена): при `DOMAIN_CONSOLE_URL` на петле имя — по `SERVER_NAME` своей коробки, лист консоли домена — `domainconsole.<SERVER_NAME>` того же центра → сходится; клиентский лист `console` у консоли кластера с комплектом есть. Закрыто.
- **Отказ по имени при чужом `SERVER_NAME`** (клиент с w2c.env, чужим к коробке двери): лист `console.<чужое имя>` не сойдётся с SAN DNS → `wrong_name`, закрыт, громко.
- **`CONSOLE_ORIGINS` со схемой `https`**: при комплекте источник страницы — `https://<SERVER_NAME>[:порт]`; байтовое сравнение CORS (P/03.4 Н1.7 `cors`) не меняется; устаревший `http://` в списке даёт отсутствие заголовков CORS — видимый отказ, не щель.

## Находки

### 1. Привязка консоли с комплектом к петле не названа по версиям IP — мелкая

- Место: decisions/0075-…-окна.md, доп. 2026-10-26 (2) п. 3: «Консоль с комплектом — TLS и на петле»; петля клиента определена как `127.0.0.0/8`, `::1`.
- Что не так: клиентское правило знает обе петли, а серверная привязка не названа: `door_address` `no_kit` знает только `127.0.0.1` (P/03.4 Н1.7), и если консоль с комплектом слушает только v4-петлю, клиент на `::1` получает отказ соединения. Не щель (хуже — нет соединения, а не тихий допуск), но две реализации могут разойтись.
- Рекомендация: в строке нормы п. 3 (пишет «Спецификация») назвать привязку — `127.0.0.1` и `::1` обе или одна.
