**Согласовано:**
- **Один слушатель с необязательным сертификатом** — повтор проверенного класса `signer` (RC:109–122). Вариант (б) запроса выбран обоснованно: два слушателя дали бы два адреса в пульсе.
- **Адрес** (D7 п. 3) согласован с P/02.4 Н1.6:
  - `process` — вне петли только с комплектом;
  - `doors` — SAN DNS `<сервер>`, IP SAN нет.
  - Поэтому хост `SERVER_NAME` и отказ `0.0.0.0` — следствие нормы, а не новое правило.
- **Журнал двери** в `audit/<роль>/e1` своим писателем — та же раскладка, что строка подачи просьбы воркера (P/03.6 Н1.5).
- **Токен места** (D7 п. 2) — ровно рекомендация запроса.

## Сводка

**Блокеров нет. Четыре существенных:**
- **З-1.** CORS разрешает «консоль кластера и консоль домена своей установки», но откуда двери знать их источники (`Origin` = схема, хост, порт, как видит браузер), не сказано. Публичного адреса консоли кластера среди переменных платформы нет.
- **З-2.** Страница ходит к двери держателя напрямую, по `https://SERVER_NAME:порт` с листом центра кластера. Предпосылка D7 п. 3 — только «серверы кластера друг у друга». Браузер оператора должен и разрешать `SERVER_NAME`, и доверять `ca.pem` кластера — это не названо.
- **З-3.** Маршрут с допуском `role` без комплекта (дверь на петле, `http`) недостижим: сертификата нет — всегда 403. Однокоробочная установка без комплекта (ADR-0075) и стенд приёмки без TLS теряют процессные маршруты.
- **З-4.** «Каждый маршрут… объявлен в `door.routes` с допуском; без допуска — отказ загрузчика» меняет форму ключа: сейчас это список имён (P/02.1:413). Новая форма, утверждение `routes` токена и переход данных (`testsub2`, корпус) не названы.

**Мелкие** — шесть.

**Вывод: с правками.**

## Существенные

**З-1 (существенная).** Источник разрешённых `Origin` для CORS не назван.
- D7 п. 5: «разрешённые источники — консоль кластера и консоль домена своей установки».
- Нормы:
  - P/02.4 Н1.2: у консоли кластера — `CONSOLE_HOST`/`CONSOLE_PORT` (привязка, по умолчанию `127.0.0.1:8080`), публичного адреса нет;
  - `DOMAIN_CONSOLE_URL` — переменная только процесса `domain` (P/08.1:21; `08-domain/lifecycle.md:30`);
  - консоль кластера проверяет чужой `Origin` у себя (P/06.5:311), а дверь процесса — не консоль.
- Контрпример: консоль за прокси оператора `https://vms.example:443`, процесс слушает `CONSOLE_HOST=127.0.0.1:8080`.
  - Реализация А отвечает `Access-Control-Allow-Origin: http://127.0.0.1:8080` — браузер отвергает.
  - Б — `https://<SERVER_NAME>:8080` для каждого сервера.
  - В — `*`: запрещено, ведь `Authorization`.
  - Страница не проигрывает видео ни у одной.
- Предложение: переменная `w2c.env` — **`CONSOLE_ORIGINS`**, список источников через запятую: консоль кластера на каждом сервере, консоль домена. Её читают двери процессов. Нет переменной — CORS-заголовков нет, страница другого источника не ходит. Сравнение с `Origin` — байт в байт.

**З-2 (существенная).** Путь страницы до двери держателя требует того, чего предпосылка не называет.
- D7 п. 3: хост — `SERVER_NAME`, схема `https`; «Имена серверов кластера друг у друга разрешаются — предпосылка развёртывания».
- P/06.5 Н3 «`/where`»: консоль отдаёт странице `url` двери держателя из пульса (P/03.4 Н1.1 `url`), страница зовёт его сама (CORS D7 п. 5, `<video crossOrigin>` — запрос).
- Сертификат двери — лист роли от центра кластера (P/02.4 Н1.6 `doors`, Н1.6 `ca` — самоподписанный центр установки).
- Контрпример:
  - Оператор открывает консоль с ноутбука. Страница получает `https://srv2:8084/timeline/…`.
  - Ноутбук не разрешает `srv2`: DNS кластера внутренний, файл хостов — у серверов.
  - Если разрешает — лист выпущен центром, которому браузер не доверяет: ошибка сертификата, `fetch` падает без диалога.
- Последствие: страничные маршруты (`/timeline`, `/segment`, `/keeps`) не работают в обычной установке, хотя нормы и приёмка зелёные (стенд — один хост, `http`).
- Предложение — назвать одно:
  - **предпосылку развёртывания для рабочих мест:** браузер оператора разрешает `SERVER_NAME` серверов и доверяет `ca.pem` установки (урок 09-deploy, инструкция оператору);
  - или ход страницы через консоль (пересылка `/where/…` консолью кластера, своей дверью). Тогда CORS и предпосылка не нужны, но поток видео идёт через консоль.

**З-3 (существенная).** Допуск `role` без комплекта не определён — процессные маршруты на петле недостижимы.
- D7 п. 1: «с комплектом — TLS…; `role: [<роли>]` — нужен предъявленный сертификат одной из ролей, иначе 403 `no_role`».
- Нормы:
  - P/02.4 Н1.6 `roles`: «нет комплекта → дверь на петле, клиент только к http://»;
  - `defaults`: «условных ослаблений нет»;
  - P/02.4 Н1.10 / RC `stand`: TLS стенд не поднимает.
- Контрпример: коробка без комплекта (ADR-0075 разрешает).
  - `detjob` сканирует запись — `GET http://127.0.0.1:8084/samples/…` к регистратору. Сертификата по `http` нет — 403 `no_role`.
  - Скан не идёт, копия резервной не идёт.
  - Приёмка «процесс с ролью» (D7 п. 6) на стенде без TLS невозможна.
- Предложение — назвать одно:
  - без комплекта маршрут с `role` — **отказ старта** у подсистемы, которой эти маршруты нужны. Честно: без комплекта процессный доступ не открыт;
  - или на петле без комплекта роль подтверждается иначе — Unix-сокет двери и `SO_PEERCRED` (пользователь юнита → роль по `users_groups`). Так стенд проверяет «с ролью и без» без TLS.
  - Приёмку D7 п. 6 положить на TLS-стенд (`common/acceptance/tls`) явно.

**З-4 (существенная).** Новая форма `door.routes` не названа, хотя отказ загрузчика в ней введён.
- D7 п. 1: «Каждый маршрут двери объявлен в манифесте (`door.routes`) с допуском…; маршрут без допуска — отказ загрузчика».
- Нормы:
  - P/02.1:413 — `door.routes` — «список, элемент — по определению `name`»: допуску в нём места нет;
  - DT:29–30 — `routes` токена — «массив путей двери только чтения (door.routes манифеста)».
- Данные `1512a89`:
  - `testsub2.subsystem.yaml:151`: `door: {routes: [read, play], pass: [entries]}`;
  - 82 случая корпуса загрузчика с `door:`.
- Последствие:
  - форму каждая реализация придумает сама (`{read: token}`, `[{name, allow}]`, …);
  - нынешние `routes: [read, play]` — по D7 «без допуска», то есть отказ;
  - токен может унести маршруты с `role` в своё утверждение `routes`.
- Предложение:
  - форма в P/02.1 — например, `door.routes: {<сегмент>: token | {role: [<роль>…]}}`, сегмент — по грамматике `name`;
  - `routes` токена — только сегменты с допуском `token` (DT:29–30);
  - переход — механически, как доп. (5) п. 4: `testsub2` и корпус получают `token` у нынешних маршрутов, канонические ожидания пересчитываются.

## Мелкие

1. **Слова отказа — как у двери роли P/10.** P/10 Н1.4:214: «сертификата клиента нет — 401 no_role; no_role, wrong_role, bad_chain — 403 с этим словом». D7 п. 1 — «иначе 403 `no_role`» на всё. Взять слова P/10: нет листа — 401 `no_role`, чужая роль — 403 `wrong_role`, `sig`/`revoked` — 403 `bad_chain`. Тогда одна роль — один словарь на всех дверях.
2. **Возобновление и версия TLS.** D7 п. 1 говорит «проверяется в рукопожатии, как у класса `signed`», но не берёт строку `signer` целиком: «сессий не возобновляет… TLS ≥ 1.2» (RC:118–122). Без неё отзыв (`revoked`) не виден возобновлённому соединению. Сказать «как `signer`: без возобновления, TLS ≥ 1.2».
3. **Договор токена двери не поправлен.** DT:53 у проверяющего: «`unit` и `holder` — свои». D7 п. 2 для двери места: `unit` — «единица, чьи данные лежат в месте держателя». Назвать правку DT («у двери места — `unit`, чьи данные в моём месте») и вектор `verify.tsv` для чужой единицы на своём месте.
4. **Привязка к конкретному адресу.** `0.0.0.0` — отказ, значит, оператор задаёт `<ДВЕРЬ>_HOST` — адрес интерфейса. В пульсе — `SERVER_NAME`. Если имя разрешается в другой интерфейс, клиенты стучат мимо. Предварительную проверку установщика (D7 п. 3) расширить: `SERVER_NAME` разрешается в адрес привязки двери, иначе предупреждение.
5. **CORS для видео.**
   - `Range` не всегда «простой» заголовок: из JS (MSE) — preflight с `Range`.
   - Странице нужны `Content-Range`, `Accept-Ranges`, `Content-Length` — `Access-Control-Expose-Headers`.
   - Ответ меняется по `Origin` — `Vary: Origin`.
   - Назвать в D7 п. 5: `Allow-Headers: Authorization, Range`; `Expose-Headers` — эти три; `Vary: Origin`.
6. **Необязательный сертификат и браузер.** При `CertificateRequest` без списка центров браузер с личными сертификатами может спросить человека, какой предъявить. Сказать: запрос сертификата несёт `certificate_authorities` — центры кластера (`ca.pem`, `ca.next.pem`). Тогда браузер без листа кластера молчит.
