## Каталог данных

### RA1-01 — существенная: читатели не выражают динамические разрешения из спеки

**Место:** `Platform/common/data/catalog.tsv:19`, также 17, 30, 34. Цитата читателей строки единицы:
`console, <s>controller, <s>worker, <s>domain, resource, domain, domainagent`.

**Основание:** решение «Каталог данных — вопросы», п. 3: `readers` — разрешённые таблицей прав **∪** названные нормами.
М10/6 Н1.4, `06-rights.norms.md:312`, прямо называет чтение `testsub/counters/` ролью `testsub2worker` через
`worker.reads`/`secrets.reads`. Н1.4 и Н3 шага генерации добавляют такие чтения по объявлениям каталога спек.

**Контрпример:** установлены `testsub` и `testsub2` из данных курса; роль `testsub2worker` читает
`testsub/counters/c1`. При связывании `<s>` с владельцем строки каталог даёт `testsubworker`, но не `testsub2worker`.
Если же раскрывать `<s>worker` как всех воркеров, получат чтение и воркеры без такого объявления.
Также `door/signer` в строке 17 всегда имеет читателя `console`, хотя М10/7 Н1.3, строка 291, оставляет список
пустым до объявления читателя спекой. Статический перечень не различает эти допустимые каталоги спек.

**Последствие:** вывод из каталога сужает разрешённое межподсистемное чтение либо расширяет его/чтение секрета.
Это не просьба выдать новые права: требуется сохранить нынешние.

**Рекомендация:** выразить условные/добавочные читатели через объявления спек и вычитание секретных читателей;
сохранить генератор из спеки до доказанной эквивалентности. Уточнение параметрической формы — вопрос «Архитектору».

### RA1-02 — существенная: удаление единицы контроллером потеряло страж `placement_turn`

**Место:** `Platform/common/data/catalog.tsv:19`: `delete=<s>controller(placement.unplaced.delete_after, cas по прочитанной версии)`.

**Основание:** М10/4 Н3, `04-the-controller-and-placement.norms.md:383`, шаг 8: удаление с CAS свежей версии единицы
**и** guard своей версии `placement_turn`; М10/4-17 и М10/4-22. ADR-0083 доп. (2) п. 2 требует условий участника операции.

**Контрпример:** A прочитал неразмещённую единицу с версией u7 и очередь t4. B захватил очередь t5 и разместил
единицу, не меняя строку единицы u7. Позднее удаление A с CAS u7 проходит; с guard t4 оно получает 412.
Состояние и вмешательство входят в объявленный профиль нескольких контроллеров.

**Последствие:** каталог разрешает позднему контроллеру удалить уже размещённую единицу.

**Рекомендация:** добавить к условию удаления контроллера атомарный guard `placement_turn`, сохранив отдельное
условие удаления воркером по `worker.deletes`.

### RA1-03 — существенная: CAS-записи классифицированы как безусловный `put`

**Места:** `Platform/common/data/catalog.tsv:44`: `put=console(PUT /schema?version=N в окне обслуживания, только вверх)`;
строка 50: `put=console(POST таблицы: полная строка с CAS, кроме таблиц worker.writes)`.

**Основание:** форма каталога, п. 1: `put` — запись без условия, `cas` — по прочитанной версии.
М10/10 Н3, `10-schema-drain-snapshot-limits.norms.md:240`: `записать {version: N, at} с cas`;
строка 342: `записать полную строку с CAS`. М10/10-01, М10/10-10.

**Контрпример:** два admin на совместимой консоли прочли схему 1. B поднял её до 3; поздний `put` A версии 2
понизит её, тогда как CAS A должен конфликтовать и привести к перечитыванию. Окно обслуживания это вмешательство
не исключает: Н3 отдельно описывает защиту двух admin. Для таблицы два POST по одной прочитанной строке также
должны перечитать зависимости после конфликта, а не перетирать их без проверки.

**Последствие:** потребитель столбца `ops` получает иной протокол, а у таблицы строка противоречит сама себе.

**Рекомендация:** отнести условные записи консоли к `cas` (с созданием по пустой версии там, где оно применимо),
согласовать абзац «Данные» М10/7, который уже ссылается на CAS таблицы.

### RA1-04 — существенная: образец `objects.rows` не представляет точное имя

**Места:** `Platform/common/data/catalog.tsv:34`: `objects/<sub>/<spec:objects.rows>/*`;
`М10_Platform/spec/08-events-resource-requests.norms.md:15`, тот же ключ в «владеет».

**Основание:** М10/6 Н1.4, `06-rights.norms.md:133`: `семья fam/ → objects/<s>/fam/*, точное имя — без *`;
М10/8 Н1.1 `row_object`, М10/6-13. Решение по форме `<spec:…>` называет её переменной-сегментом, не оператором
переписывания произвольного образца.

**Контрпример:** допустимое объявление `objects.rows: [memo]` даёт строку-объект `objects/testsub/memo`.
Подстановка каталога создаёт `objects/testsub/memo/*`, который точное имя не покрывает.
Для префикса `fam/` буквальная подстановка ещё и требует отдельного правила снятия завершающего `/`.

**Последствие:** допустимая строка-объект не имеет представления в каталоге или получает другую область прав.

**Рекомендация:** явно представить обе формы объявления и их разворачивание, не добавляя `/*` к точному имени.
Расширение грамматики образца — вопрос «Архитектору».

### RA1-05 — существенная: читатели файлов ключей шире объявленных держателей

**Места:** `Platform/common/data/catalog.tsv:58`, `server.key` имеет `readers = *`;
строка 28: для кольца перечислен `<s>worker` без условия о секретных полях.

**Основание:** М10/11 Н1.6, `11-the-platform-on-a-box-and-a-cluster.norms.md:335`: ключ — 0600 пользователю
юнита либо 0640 root и группе пользователя юнита; М10/11-11. М10/7 Н1.2,
`07-secrets-and-sealing.norms.md:230`: держатели кольца — воркеры подсистем, **в спеке которых есть секретные поля**.
По форме каталога `*` означает все роли кластера.

**Контрпример:** воркер учебной подсистемы не является пользователем/группой демона `configstore`.
Он не может читать `/etc/w2c/tls/configstore/server.key` с режимом 0600 configstore; каталог считает его читателем.
Воркер спеки без секретных полей аналогично не должен автоматически получать кольцо.

**Последствие:** каталог описывает отсутствующую связь с закрытыми ключами; генерация доступов/комплектования
по нему способна раздать ключи лишним процессам.

**Рекомендация:** назвать читателя соответствующего комплекта и условие держателя кольца; не использовать `*`
для закрытого ключа. Общие открытые сертификаты с этим не смешивать.

### RA1-06 — существенная: ресурс отсутствует среди участников удаления собственных данных и копий

**Места:** `Platform/common/data/catalog.tsv:39`–42 содержат только `append`, без `delete=resource`;
строка 47 допускает удаление blob только консолью.

**Основание:** М10/8 Н3, `08-events-resource-requests.norms.md:525`: ресурс убирает закрытые бакеты по сроку;
М10/8-09. М10/10 Н1.5, `10-schema-drain-snapshot-limits.norms.md:134`: сосед на проходе ресурса читает надгробие
и удаляет свою копию старше `written`; М10/10-09. Это не удаление оригинала консолью в окне уборки.

**Контрпример:** закрытый бакет без удержаний достоверно старше retention — ресурс должен его удалить, но
операции для этого в строке файла нет. Второй пример: ресурс B получил надгробие A для прежней копии blob;
удалять эту копию должна роль `resource` на B, которой строка 47 даёт только `put`.

**Последствие:** участник обязательной очистки исчезает из производного контракта; сохранение только названных
операций не исполняет retention и схождение копий.

**Рекомендация:** добавить удаления ресурсом с раздельными условиями срока/удержаний и подтверждённого надгробия;
сохранить ограничение окна у удаления оригинала консолью.

### RA1-07 — существенная: нет местных деревьев тревог `audit.alarms` и `console.alarms`

**Места:** `Platform/common/data/catalog.tsv:39`–43; список «владеет»
`М10_Platform/spec/08-events-resource-requests.norms.md:15`.
Цитаты имеющихся форм: `<sub>.alarms/<unit>/…`, `audit/<роль>/e1/…`, `console/<экземпляр>/e1/…`.

**Основание:** М10/8 Н1.2, `08-events-resource-requests.norms.md:93`–94:
`раскладка .alarms — у писателя`, включая `audit.alarms и console.alarms`;
решение второго пилота Н-2, М10/8-04.

**Контрпример:** `worker.name_taken` — тревога журнала. Её местный файл
`<root>/audit.alarms/testsubworker/e1/20261018T000000Z.events.jsonl` не относится ни к одной местной форме.
`audit.alarms` не может подставляться вместо `<sub>`: это не имя спеки. Форма под `.mirror/` описывает другую копию.

**Последствие:** именно новые после пилота пути тревог теряются при переносе по каталогу.

**Рекомендация:** добавить обе местные формы тревог либо общий образец дерева с явной областью значений,
писателями и операциями; согласовать «Данные» М10/8.

### RA1-08 — существенная: пропущены общие файлы, без которых другой процесс не прочитает данные

**Места:** `Platform/common/data/catalog.tsv:3` — состав таблицы; строк 4–58 и 113 для двух форм ниже нет.
Существующая строка файла, для сравнения: `/etc/w2c/secrets/platform.key` (28).

**Основание:** ADR-0083 доп. (2) п. 1.3 включает в договор данных общие файлы; форма каталога допускает `kind=file`.
М10/8 Н1.1, `08-events-resource-requests.norms.md:66`–67: рядом файл `%h<sha256>.name` с исходным компонентом.
М10/6 Н1.2, `06-rights.norms.md:73`: демон загружает файл при старте (`-rights`), генерирует/проверяет установщик.
Lifecycle хранилища и установщика сами называют `/etc/w2c/configstore-rights.json`.

**Контрпример:** разрешённое именованное id из 128 букв `A` имеет компонент `%41…` длиной 384 байта:
писатель заменяет его хэш-именем, ресурс восстанавливает имя через `.name`. Для этого разделяемого файла
нет владельца/писателя/читателя в каталоге. Файл прав также передаётся от установщика другой реализации демона,
но его контракт есть только в lifecycle/норме, без строки каталога и без «Данные» М10/6.

**Последствие:** каталог общих файлов неполон, хотя оба файла обязательны для межпроцессной связи;
это не внутренний неопределённый формат БД демона.

**Рекомендация:** внести нормированные sidecar-файлы имён и файл прав с их владельцами, участниками и читателями;
подключить владельцев/потребителей в «Данные».

### RA1-09 — существенная: файл запасного приписан роли `admin`, которой у его писателя нет

**Место:** `Platform/common/data/catalog.tsv:52`: `create=admin(w2c-spares.sh до systemctl start: tmp + rename, 0644, одна строка SPARE_FOR)`.

**Основание:** М10/11 Н1.5, `11-the-platform-on-a-box-and-a-cluster.norms.md:303`: файл пишет скрипт запасных,
владелец `w2c-spares`; строка 307: скрипт — `User=w2c-spares без групп`.
М10/11-10, М10/11-18, ADR-0046. Решение формы требует для обычного файла ту же роль процесса-писателя.

**Контрпример:** штатный таймер запускает `w2c-spares.sh` без доступа к admin.sock и без привилегий root;
скрипт атомарно кладёт свой env-файл в принадлежащий ему `/run/w2c-spares`. Каталог вместо этого описывает участника admin.

**Последствие:** потерян самостоятельный непривилегированный писатель файла; вывод прав/поставки не должен ради
этой строки делать скрипт администратором хранилища.

**Рекомендация:** вопрос «Архитектору»: представить участника общих файлов без роли хранилища и назвать
`w2c-spares`; право admin не добавлять.

### RA1-10 — существенная: операции просьб потеряли ветви профиля и `no_begun` держателя

**Места:** `Platform/common/data/catalog.tsv:33`: `mark=<s>worker(begun до вызова),console(no_begun жнецом)`;
строка 30: `delete=console(жнец: отвеченная по settle, брошенная по ttl или valid_until)`.

**Основание:** М10/8 Н3, `08-events-resource-requests.norms.md:663`: держатель создаёт метку expired без начала,
следом refused до вызова. Строка 689: `дозапись, elsewhere и строки ресурса не получают меток этого прохода`;
Н1.5 `elsewhere`: жнец их не трогает. М10/8-14, М10/8-15, М10/8-19, ADR-0054.

**Контрпримеры:** у обычной просьбы вышел срок до взгляда держателя: воркер должен сделать `put_new` expired,
но его условие `mark` каталога разрешает только begun. У просьбы действия `elsewhere` прошли ttl/valid_until:
обобщённое условие строки 30 разрешает её удалить жнецу, тогда как обработка остаётся за другим владельцем.

**Последствие:** выписка операций не сохраняет ветвление одного протокола просьб: разрешает чужое завершение
и не выражает собственный исход без начала.

**Рекомендация:** перенести условия обычного/дозаписного/elsewhere профилей и допустимые `no_begun` держателя
в соответствующие условия операций, не меняя сам автомат М10/8.

### RA1-11 — существенная: условие блокировки общего журнала присоединено только к последней роли

**Место:** `Platform/common/data/catalog.tsv:41`:
`append=console,<s>controller,<s>worker,resource,domain,domainconsole,domainagent(все процессы роли на сервере, строка целиком под исключительной блокировкой файла, fsync)`.

**Основание:** принятое решение формы каталога: `условие — у участника, а не у операции`.
М10/8 Н1.2, `08-events-resource-requests.norms.md:112`: все процессы роли дописывают журнал под исключительной
блокировкой, с fsync журнала. ADR-0083 доп. (2) п. 2; второй пилот Н-2.

**Контрпример:** два процесса роли `console` пишут в один бакет `audit/console/e1/…`.
Разбор по утверждённой грамматике даёт `console` без условия, а блокировку/fsync — только `domainagent`.
Читатель, использующий эту структуру, не получает обязательного условия для консоли.

**Последствие:** свойство безопасной совместной дозаписи потеряно именно в строке с несколькими участниками.

**Рекомендация:** прикрепить условие к каждому участнику либо утвердить отдельную явно общую часть операции;
пунктуацией списка ролей область условия не расширять.

### RA1-12 — существенная: абзацы не перечисляют уже существующие чужие операции и чтение метки

**Места:** `М10_Platform/spec/04-the-controller-and-placement.norms.md:15`:
`пишет: <sub>/slots/<имя> (create), <sub>/<spec:unit.rows>/<id> (delete)`;
строка 16 — «читает». Абзацы М10/5:16, М10/8:17, М10/9:15, М10/10:17 также называют основную спеку без `/rev`.

**Основание:** форма абзаца «Данные», п. 2: «пишет» — чужие семьи, в которые урок вводит операцию, «читает» —
чужие читаемые семьи. М10/4 Н3, `04-the-controller-and-placement.norms.md:473` — release с CAS;
строка 528 — удаление невзятого предложения с CAS. М10/2 Н3,
`02-the-spec-and-the-strict-loader.norms.md:508` — работающий процесс читает метку на каждом проходе и не реже 30 с.

**Контрпример:** контроллер отдаёт слот или отзывает предложение. Каталог содержит CAS/delete слота (строка 22),
но «Данные» урока, вводящего эти операции, содержит только create. При публикации следующей ревизии процессам
нужен ключ `platform/spec/<sub>/rev`; это отдельная строка каталога (5), а не основная строка (4), которую абзацы перечисляют.

**Последствие:** по зависимостям из «Данные» нельзя восстановить даже уже выписанный протокол; обратная
структурная сверка ownership это не обнаруживает.

**Рекомендация:** дополнить чужие операции М10/4 и зависимость потребителей от метки `/rev`; проверить полноту
именно «пишет/читает», не только совпадение «владеет».

## Жизненный цикл

### RA1-13 — существенная: у консоли два несовместимых пути кольца стенда

**Место:** `Platform/06-console/lifecycle.md:85`: `SECRETS_KEY — кольцо стенда вне {data}`;
строка 91: `в {data}/etc/secrets/platform.key`.

**Основание:** README приёмки М10/01, строки 22–24 и 46: раннер создаёт кольцо и ставит
`SECRETS_KEY={data}/etc/secrets/platform.key`; М10/11 Н1.2 «Канал настройки» отделяет кольцо от каталогов
хранилища/объектов/событий, а не от всего `PLATFORM_DIR`. Решение второго пилота Н-4 и последующее уточнение.

**Контрпример:** `{data}=/tmp/stand-a`: раннер создал `/tmp/stand-a/etc/secrets/platform.key`.
Обёртка по строке 85 должна выбрать путь вне `/tmp/stand-a`; это другой файл, и POST/PUT получает 503 при
заданном нечитаемом кольце либо использует другой ключ. Строка 91 при этом требует первоначальный путь.

**Последствие:** описание не позволяет однозначно подготовить консоль на одном кольце с остальными процессами.

**Рекомендация:** согласовать «Стенд» с уже принятым путём внутри `{data}/etc`, снять устаревшее «вне {data}».

### RA1-14 — существенная: lifecycle из отсутствия старта запасного вывел несуществующий обязательный код ошибки

**Место:** `Platform/02-installer/lifecycle.md:68`:
`≠ 0 | скрипт запасных ничего не запустил: нет файла роли, консоль молчит, polkit отказал (не отказ процесса — лог)`.

**Основание:** М10/11 Н4, `11-the-platform-on-a-box-and-a-cluster.norms.md:529`, даёт исход
`ничего не запущено` и `лог`, без назначения кода; Н1.5 правила 2, 4 требуют пропустить запуск/роль.
В отличие от этого, отказ самого запасного без env-файла имеет явный код 2 и является другим случаем.
ADR-0083 доп. (1), (2): стадия выписки не меняет поведение; каждый договор жизненного цикла опирается на норму.

**Контрпример:** oneshot скрипт штатно пропустил роль без её файла, записал причину и завершился 0.
Ничего не запущено, требование Н4 выполнено. Новый lifecycle запрещает этот результат и делает службу ошибочной.

**Последствие:** производный документ незаметно добавил обязательное наблюдаемое поведение.

**Рекомендация:** не назначать отсутствующий код из строки Н4; если нужен общий код скрипта, сначала согласовать
его отдельной нормой, а не выдавать за уже существующий.

### RA1-15 — существенная: окружение демона объявлено ненужным, хотя через него передаются сокеты

**Место:** `Platform/01-store/lifecycle.md:22`:
`Сам демон окружения не читает: его настройка — флаги (ниже). Окружение читает раннер, который собирает флаги.`
В строке 28 этого же файла перечислены `LISTEN_FDS`, `LISTEN_FDNAMES`.

**Основание:** М10/11 Н1.3, `11-the-platform-on-a-box-and-a-cluster.norms.md:153`–157:
демон берёт унаследованные сокеты протокола `sd_listen_fds` по имени `admin`/роли.
М10/11-16; решение первого пилота А10. В закрытой таблице флагов нет замены переданным дескрипторам и их именам.

**Контрпример:** systemd уже открыл `admin.sock` и сокеты ролей, передал дескрипторы 3… и их имена окружением.
Раннер передал обычные флаги демону, который по первой фразе не читает переменные протокола. Создавать вместо
переданного сокета новый по `-sockets` нельзя: путь занят, а режим/группа заданы юнитом. Таблица требует принять
унаследованные сокеты, вступительный абзац исключает вход, позволяющий их распознать.

**Последствие:** производный контракт теряет обязательный способ запуска демона через socket units.

**Рекомендация:** ограничить утверждение настройками из конфигурационных env-файлов и явно оставить
переменные передачи сокетов входом самого демона, а не только раннера.

## Векторы

### RA1-16 — существенная: HTTP-прогон оценщика считает сбоевый ответ положительным вердиктом

**Места:** `Platform/01-store/vectors/rights-evaluator/README.md:8`:
`allow` — `любой иной ответ`; то же в `Platform/01-store/vectors/rights-evaluator/expect.tsv:2`.

**Основание:** М10/6 Н1.3 `allowed`, М10/6-03; М10/1 Н2/Н4 различает отказ прав, чтение отсутствующей строки
и недоступность. Общий чеклист навыка, «Приёмка и доказательства»: ожидание проверяет именно требуемое поведение,
не посторонний исход. ADR-0083 доп. (2) п. 1.5 — вектор проверяет договор алгоритма.

**Контрпример:** строка `acc read acc/exact allow` на свежем пустом хранилище.
Нормальный ответ — 200 с `items: null`, `index: ""`. Ответ 500/503 также будет засчитан как allow по README,
хотя успешного наблюдения разрешённого чтения нет. Все отрицательные строки могут при этом вернуть 403:
отказы положительных проб не превращаются в падение набора.

**Последствие:** объявленный способ прогона даёт положительный итог при неисполненных положительных пробах;
арифметическая сверка самих 15 ожидаемых булевых значений этот дефект раннера не устраняет.

**Рекомендация:** для чтения требовать успешный ответ формы Row, для разрешённой записи — подтверждённый
успех; 5xx/ошибку транспорта считать неопределённой или неуспешной пробой, а не allow.

## Можно ли получить из каталога прежний файл прав

**Пока нет.** Прямой свёртки `ops → write/delete`, `readers → read` недостаточно даже для М10; отказ от
источника-спеки сейчас нарушит условие перехода `Platform/module-design.md:42` (эквивалентность через `--check`).
Доменная часть файла в этом ревью не оценивалась, поэтому вывод относится к достаточности уже части М10.

1. **Читатели зависят от всей спеки.** Пример `testsub2worker → testsub/counters/`, объявления секретов,
   дополнительные `secrets.reads`, `about.sub` и `worker.reads` нельзя заменить нынешним статическим перечнем
   одной строки каталога (RA1-01). `door/signer` показывает также ошибку противоположного направления.
2. **Разрешение шире штатной операции.** М10/6 Н1.4 выдаёт консоли write/delete `next_id`, `policy`, `sweep`;
   в каталоге `next_id` нет delete, у `policy` только put, у `sweep` только cas. Само отсутствие штатной операции
   удаления не означает отсутствие ACL-разрешения. Например, ролевой DELETE `testsub/next_id` разрешён
   исходной таблицей прав. И наоборот, CAS и guard не являются отдельными правами файла.
3. **Есть широкие права и запреты вне набора конкретных форм.** `read: <s>/*`, `platform/*`, вычитание
   `idem/asked` и секретных образцов, `never`, особые admin/configstore-door не выводятся простой суммой
   читателей отдельных каталогизированных ключей. Ключ `testsub/unlisted` допустим по М10/1 и попадает под
   широкое чтение консоли, хотя не является строкой прикладного каталога. Нужна эквивалентность образцов,
   а не только совпадение на известных строках установки.
4. **Нельзя смешивать носители.** `kind=file/object` не означает разрешение `read/write` ролевого сокета;
   `.gone`, бакеты, файл TLS и строка-объект требуют разных проекций. Служебный `op: floor` нельзя превратить
   в обычный put из-за имени операции каталога (его условие в строке 24 это уже верно оговаривает).

Рекомендация «Архитектору»: сохранить направление ADR-0083, но сначала явно описать проекцию операционных
участников в исходные ACL с условиями и отрицаниями. Затем сравнить наборы ролей, группы и множества образцов
read/write/delete по Н3 М10/6 на `testsub`, `testsub2` и вариантах М10/6. Совпадение нескольких разрешённых
запросов не заменяет `--check`; отсутствие генератора/запуска здесь не объявляется дефектом реализации.
