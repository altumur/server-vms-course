## Находки

### K26-01 — существенная (урок 2, инструкция)

- **Место:** `М10_Platform/spec/02-the-spec-and-the-strict-loader.README.md:103`.
- **Что не так:** «Готово, когда» требует «**Три** случая `diagnostics.tsv` дают все ожидаемые пути
  и требуемый номер строки». Файл `diagnostics.tsv` содержит 11 случаев (3 прежних + 8 float/JSON
  прогона 25), и канон требует проверки всех: Н5 норм — «Для случаев `diagnostics.tsv` дополнительно
  сравниваются пути ключей и номера строк… один правильный вердикт без требуемой диагностики не
  закрывает эти случаи» и «Восемь случаев float/JSON проверяют путь отказанного числа». Числа в
  инструкции не обновлены после R25-01 (строка 101 того же списка обновлена до 164/23/141).
- **Правило:** ADR-0080 — инструкция не снижает канон и согласуется с данными приёмки; согласованность
  внутри урока (id М10/2-01/02/03 ссылаются на `diagnostics.tsv` целиком).
- **Контрпример:** реализация, идущая по README, сверяет 3 случая; её загрузчик для
  `float_default_nan` называет путь `["unit","fields","rate"]` без сегмента `default` — вердикт
  `refused` проходит, требуемая проверка пути не выполнена, несоответствие Н5 остаётся незамеченным,
  а пункт «Готово, когда» при этом формально закрыт.
- **Рекомендация:** «Все 11 случаев `diagnostics.tsv`…» либо убрать число («случаи `diagnostics.tsv`»).
- **Серьёзность:** существенная (инструкция занижает обязательную часть приёмки).

### K26-02 — мелкая (урок 4, OpenAPI)

- **Место:** `М10_Platform/spec/04-the-controller-and-placement.api.openapi.yaml:706` и `:740`
  (`SubsystemDrain.draining`, `DrainState.draining`).
- **Что не так:** оба поля — свободный `type: string`. Н2.2 задаёт «`draining` — имя или `""`», а имя
  сервера по Н2.1 — «непустое имя одного сегмента» (схема `Server`: `minLength 1`, без `/` и `\`).
  Соседний `DrainStarted.draining` (строка 533) использует `Server` — внутри одного файла строгость
  разная; схема ответа слабее нормы.
- **Контрпример:** ответ `{"draining": "a/b", "safe": true, "would_strand": {}, "subsystems": {}}`
  проходит проверку по схеме, хотя такое значение не producible по Н2 (server валидируется формой
  `Server` при POST /drain); регрессия выдачи сырого значения строки `platform/drain` схемой не
  ловится.
- **Рекомендация:** ввести `anyOf: [$ref Server, {const: ''}]` (или схему `ServerOrEmpty`) для обоих
  полей.
- **Серьёзность:** мелкая (точность контракта; поведение сервера нормой ограничено).
