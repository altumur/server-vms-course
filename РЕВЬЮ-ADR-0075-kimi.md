- Следов переменных в спецификации нет: `CONSOLE_TLS`/`DOMAIN_CONSOLE_TLS` по всему дереву — только decisions/0075 и догадка в inbox; `Platform/06-console/lifecycle.md` и `env-file.md` приведены коммитом 9c436c455 ещё до записи доп. — доп. фиксирует свершившееся, ничего не висит.
- `DOMAIN_CONSOLE_TLS` в `Platform/` не было никогда (`git log -S` пуст) — снятие касается только текста ADR.
- «Частичный комплект — код 2» дословно совпадает с договором сертификата роли `kit_absent` (role-certificate.md:211–213, RC-NOKIT).
- «Адрес вне петли без комплекта — отказ старта» для консолей согласован с P/02.4 Н1.6 «Правило адреса» `process` (консоли вне перечня исключений signer/relay/resource) и с P/02.4 Н1.6 `roles` («нет комплекта → дверь на петле»), на которое ссылаются P/06.3 (:65) и P/06.4 (:43).
- С доп. 2026-10-21 не спорит: класс `signed` для входящих из других кластеров на слушателе консоли сохраняется (P/06.7 Н1.7 `server`); консоль без комплекта — на петле, входящих из других кластеров у неё и не может быть (доп. (6): домен между машинами требует комплекта у каждого кластера).
- `RESOURCE_TLS` «не меняется» — согласовано: нормы P/05 действительно держат `RESOURCE_TLS`/`door.mode` (05-resource.norms.md:33, 193–194, 392), строка в env-file.md на месте.

## Находки

### 1. «SIGNER_TLS — тем же правилом» не называет судьбу исключения адреса signer — существенная

- Место: decisions/0075-…:293 («`SIGNER_TLS` — тем же правилом») против P/02.4 Н1.6 «Правило адреса» `process` (02.4-installer.norms.md:289–293).
- Цитата нормы: «исключение: signer, relay, resource без комплекта МОГУТ слушать вне петли только по явному адресу (ADR-0075 доп. 2026-10-12 (2)); слушают — ДОЛЖНЫ при старте написать в лог строку …».
- Что не так: правило доп., к которому отсылает «тем же правилом», включает «нет комплекта: только петля; адрес вне петли без комплекта — отказ старта, код 2». Прочитанное оптом, оно молча снимает исключение signer из Н1.6 — и при этом асимметрично: relay из того же перечня исключений доп. не упомянут вовсе, его исключение остаётся. Прочитанное узко (только «TLS по комплекту»), у signer остаются два разных правила адреса — Н1.6 и доп.
- Рекомендация: одной строкой в доп. — «исключение адреса signer/relay/resource (доп. 2026-10-12 (2)) сохраняется» либо «снято» (тогда и relay).
- Источник: ADR-0075 доп. 2026-10-12 (2); P/02.4 Н1.6.

### 2. `RELAY_TLS` не назван — мелкая

- Место: decisions/0075-…:293; переменная введена той же фразой, что и `SIGNER_TLS` (уточнение 3 окна 4, :231–232: «Переключатели `SIGNER_TLS=1` … и `RELAY_TLS=1`»).
- Что не так: судьба `SIGNER_TLS` названа, о `RELAY_TLS` доп. молчит. Исход выводим (дверь ретранслятора — это агент, роль `domainagent`, класс `signed`; role-certificate.md:73–74), но читатель ADR-0075 судьбу переменной не видит.
- Рекомендация: «`RELAY_TLS` — тем же правилом» одной строкой.

### 3. Снятый случай «консоль с комплектом без TLS» не назван последствием — мелкая (ответ на вопрос поручения)

- Место: decisions/0075-…:291–292; мотив флага — доп. (7) :269 («Дверь консоли — дверь людей, по `http://` процесс сертификата не покажет»).
- Что не так: случай, ради которого доп. (7) делало флаг добровольным — консоль на коробке с комплектом, служащая по plain HTTP (в том числе местный браузер на `http://127.0.0.1:8080`), — снят. Это осознано (догадка C06-TLS-ENV-138-11: «комплект есть — дверь по TLS», «Тихого HTTP вне петли нет»), но доп. не называет последствие: на коробке с комплектом браузеру нужны `https://<SERVER_NAME>` и доверенный CA кластера (путь из доп. (7) — CA в доверенных машинах, deploy/README.md — сохраняется). Стенд приёмки P/06.3-02 (консоль открыта, раннер с петли) безкомплектный — не задет.
- Рекомендация: если последствие осознано — одна строка в доп. («консоль с комплектом по HTTP не служит и на петле»), чтобы читатель не считал это упущением; вопроса владельцу не требуется.
- Источник: ADR-0075 доп. (7); догадка C06-TLS-ENV-138-11.

### 4. Пометка «TLS — по комплекту роли» не дошла до lifecycle P/10 — мелкая

- Место: Platform/10-domain-console/lifecycle.md:27 (`DOMAIN_CONSOLE_HOST/PORT`, умолчание `0.0.0.0:8444`) против Platform/06-console/lifecycle.md:42, где пометка есть (9c436c455).
- Что не так: по новому правилу умолчание `0.0.0.0:8444` без комплекта — «адрес вне петли без комплекта — отказ старта», то есть умолчание годно только с комплектом; lifecycle консоли домена этого не говорит, lifecycle консоли кластера — говорит. Не противоречие (домен между машинами требует комплектов — доп. (6)), но асимметрия текста.
- Рекомендация: симметричная пометка «TLS — по комплекту роли» у `DOMAIN_CONSOLE_HOST/PORT`.

3. № 2 — `RELAY_TLS` без судьбы в тексте ADR.
