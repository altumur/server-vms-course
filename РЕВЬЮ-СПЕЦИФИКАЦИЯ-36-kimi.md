## Урок 1 (01-storage)

**K36-1-01 — существенная. Н3: неоднозначность сличения повтора по `id` для delete.**
Место: `М10_Platform/spec/01-storage.norms.md:151` (повтор иной записи сличает
`(op, key, items, cas, guard)`), `:177` (у delete «Поле `items`, если прислано, не читается»),
`:184` («повтор по id — как у записи»). Контрпример: первая
`{"op":"delete","key":"k","items":42,"id":"X"}` → 200; повтор с тем же id и
`items:{"a":"b"}` — реализация, сличающая кортеж с `items`, отвечает 400 badrequest;
реализация, не читающая `items` у delete, отвечает 200 again:true. Обе ссылаются на текст,
расхождение наблюдаемо на проводе и не закреплено приёмкой (сц. 06/12 такой повтор не строят).
Основание: ADR-0080 (две реализации расходятся — дыра в лекции); review-checklist «повторы
одного id рассмотрены отдельно».
Рекомендация: в Н3 «удалить» явно сказать, что `items` в сличение повтора не входит
(последовательно с «не читается»).

**K36-1-02 — мелкая. Н3 требует монотонности версии, Н1 и «Решает реализация» — только неповторяемости.**
Место: `01-storage.norms.md:157` («новая версия (больше любой выданной этим хранилищем)»)
против `:43` («never the same twice») и `:275` (п. 2: «лишь бы не повторялась»).
Реализация с уникальными, но немонотонными версиями соответствует Н1/п. 2 и нарушает Н3;
на клиентов влияния нет (версия непрозрачна, сравнение на равенство, приёмка не проверяет).
Рекомендация: записать в Н3 «новая, ранее не выдававшаяся версия» либо поднять монотонность в Н1.

**K36-1-03 — мелкая. Грамматика `request` в README приёмки 01 не покрывает два шага сц. 17.**
Место: `Source/tests/testdata/acceptance/М10_Platform/01/README.md:35` (только
`GET <путь с query>` и `POST /v1/write <JSON-тело>`); scenarios.tsv:81 (сц. 17 шаг 4 —
`POST /v1/get` без тела), scenarios.tsv:78 (шаг 1 — тело `not json`). Раннер, следующий
README буквально, эти шаги построить не может.
Рекомендация: записать форму как `POST <путь> [<тело>]` (тело — произвольные байты после подстановок).
