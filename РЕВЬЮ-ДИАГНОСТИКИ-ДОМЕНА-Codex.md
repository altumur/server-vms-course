## P2 — эхо токена остаётся в диагностике повреждённого JSON

Место: [admission_body, m11stand.py:100](/Users/murat/w2c/cammeta-diff/acceptance-server/review-domain-diagnostics-727210b/check-input/runner/runner/m11stand.py:100).

`collect()` извлекает значения полей токена только после успешного разбора JSON. При ошибке разбора он возвращается. Последующая регулярная очистка удаляет само поле `token`, но не запоминает его значение для удаления повторений в других полях. Список известных секретов в таком случае содержит только авторизацию запроса.

Контрольный пример с синтетическими значениями:

```python
body = b'{"token":"issued-fixture-secret","detail":"issued-fixture-secret","broken"'
text = admission_body(body, "Bearer known-fixture-auth")
assert "issued-fixture-secret" not in text
```

Подтверждённый результат: значение удаляется у поля `token`, но остаётся в `detail`. Такие байты могут попасть в причину отказа `@domain` через последний неуспешный GET или POST и затем в сохранённый отчёт. Это нарушает заявленную очистку токенов и их эха для не-JSON тел.

Исправление должно исключать эхо распознанного credential и при ошибке JSON-разбора. Нужен отдельный отрицательный контроль с полем токена и его повторением в повреждённом теле.
