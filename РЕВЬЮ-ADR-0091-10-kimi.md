## Находки

### 1. Существенная — п. 1: «при двух равно близких — чётная последняя цифра» противоречит ECMA-262, на который фраза ссылается

- **Место:** decisions/0091-….md, п. 1 («`float` — цифры и показатель по ECMAScript Number::toString, как в JCS RFC 8785: кратчайшие, из них ближайшая к точному значению, при двух равно близких — с чётной последней цифрой»).
- **Что не так:** ECMA-262 (все редакции, включая действующую) в Number::toString при двух равно близких `n` предписывает **«pick the larger n»** — большую цифру, а не чётную. Когда большая цифра нечётна (тай между `…4` и `…5`), правило ADR и правило ECMAScript дают разные id. Реализация, доверившаяся ссылке и вызвавшая платформенный `Number::toString` (JS/V8, double-conversion), разойдётся с реализацией, исполнившей текст ADR (и с библиотеками типа Ryu, где тай-брейк — к чётному). Объявленные векторы с тай-кейсом встанут в противоречие с одной из сторон.
- **Контрпример:** двоичное значение ровно посередине между двумя кратчайшими кандидатами `…4` и `…5` (оба round-trip): по тексту ADR id получает `…4`, по ECMA-262 — `…5`; заказчик на одной реализации и дверь/приёмка на другой видят разные id одного события.
- **Источник:** ECMA-262, Number::toString: «Let n be an integer for which n / 10^f − x is as close to zero as possible. If there are two such n, pick the larger n» — [tc39.es/ecma262](https://tc39.es/ecma262/2024/multipage/numbers-and-dates.html); та же формула в изданиях 3, 5.1.
- **Рекомендация:** выбрать одно и убрать противоречие: либо собственное правило «чётная» без ссылки «как в ECMAScript/JCS» (с вектором тай-кейса, исполняемым одинаково на обеих реализациях), либо следовать ECMA-262 («большая») и поправить текст.
