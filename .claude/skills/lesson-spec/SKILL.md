# Работа над спецификацией урока

Это проектная инструкция автора и ревьювера. Источники требований — решения в `decisions/`,
канон урока и правила владения из `СЕССИИ.md`. Этот файл помогает их сопровождать и не вводит
нового поведения продукта. Поручение владельца определяет объём работы и запуска ревью.

## Где что лежит

От корня репозитория:

```text
М<модуль>_<имя>/NN-slug.md
М<модуль>_<имя>/spec/NN-slug.norms.md
М<модуль>_<имя>/spec/NN-slug.api.openapi.yaml
М<модуль>_<имя>/spec/NN-slug.README.md
Source/tests/testdata/acceptance/М<модуль>_<имя>/NN/
```

Если собственной HTTP-двери нет, состав без OpenAPI фиксируется в ADR (М10/5: ADR-0082 доп. 13).
Не создавать пустой контракт ради раскладки. Лекция объясняет. `.norms.md` — канон; контракт и приёмка выражают его, а не добавляют требования.
При противоречии сначала исправляется источник нормы и зависимые места. Если вопрос вне полномочий
автора, передай его по `СЕССИИ.md` с местом, контрпримером и предложением; не придумывай новый отказ.
Не выводи из шаблона обязательные типы, сигнатуры, отдельные функции или новый HTTP-маршрут.

## Изменение существующего урока

1. Установи исходный срез и границу правки; прочитай относящиеся решения и сам канон.
2. Выбери строки [таблицы связанных изменений](references/change-map.md). Для каждой отметь
   затронутые файлы и применимость; не меняй файл только ради заполнения таблицы.
3. Исправь норму и связанные места. Сохрани адреса Н0–Н5 и id; новую норму добавляй с новым id,
   не перенумеровывай существующие. Перенос отделяй от изменения поведения обозримым diff.
4. Проверь весь класс ошибок, связанный с исправлением: назови общее нарушенное правило,
   найди все его применения в текущем охвате и зависимых местах, проверь аналогичные поля/ветви,
   границы и близкие допустимые значения. Исходный контрпример — начало этой проверки.
   Для имени просмотри все поля его выдачи; для срока — начальные точки, повторы и поздние ответы;
   для отмены — все пути запуска, перезапуска и возврата. Укажи ограничения выполненных проверок.
5. Пройди [чеклист](references/review-checklist.md). Для чтения назови предмет и границу доказательства.
   Сценарий проверяет только наблюдаемые им свойства; ссылка на сценарий не равна покрытию нормы.
6. Запиши класс ошибки, охват авторской проверки, результаты и ограничения в существующем журнале
   проекта. Отчёт независимого ревью сохраняй без правок; решение по находке — в общем ответе.
   Обновляй `corrections.tsv`, когда меняется приёмка или исправляется повторяемая ошибка её толкования.

По решению владельца (ADR-0080 доп. 11) отдельный повторный проход ревьюверов по закрытию
исправлений не назначается: исходный контрпример и связанный класс проверяет автор,
независимое ревью ищет новые дефекты. Новое ревью запускается только в пределах поручения;
текущее поручение и условия остановки сверяются с `ХОД-Спецификация.md`.

Долг схем ответов Н2 переносится поурочно (ADR-0082 доп. 7/11/13): закрыт у М10/1–4,
у М10/5 собственной HTTP-двери нет, по М10/6–11 остаётся. Успех проверки формата его не закрывает.
Для М10/1–2 примеры в таблице и чеклисте основаны на прогонах 17–20. Они не делают детали хранилища
обязательными для всех следующих уроков.

## Новый урок или перевод следующего

После выбора норм используй шаблоны в `assets/`: `lecture.md`, `norms.md`, `instructions.md`,
`api.openapi.yaml`. Подстановка `{{...}}` обозначает работу автора, не будущую норму.
Инструкции по заполнению — [templates.md](references/templates.md).
Н0 подключай ссылкой на канон курса; локальную копию словаря не заводи.

При переносе сначала сверь сохранность требований и приёмки с исходником. Затем отдельными правками
закрывай найденные противоречия. Старую опубликованную версию снимают в том же окне переноса по правилам
репозитория; временный исходник сохраняется историей Git или своей веткой.

## Проверка

Сначала ручной чеклист, затем механические проверки по [validation.md](references/validation.md).
Зелёный результат не доказывает полноту норм, выполнимость гонок, качество лекции или соответствие кода.
Код реализаций и чужие рабочие деревья проверяются только в пределах поручения и правил владения.
Не откатывай файл целиком поверх чужих изменений и не запускай новый независимый прогон без поручения.
