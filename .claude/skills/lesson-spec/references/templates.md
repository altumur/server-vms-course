# Как применять шаблоны

Шаблоны заполняются после таблицы связанных изменений и чеклиста. Они помогают разместить готовое
содержание, но не принимают архитектурных решений. При переносе источник разделов — существующий урок;
не заменять его правила образцами из М10/1.

| Исходник | Назначение в модуле | Подстановки |
|---|---|---|
| `assets/lecture.md` | `NN-slug.md` | `STEM`, `TITLE`, `MODULE`, `LESSON`, ссылки и объяснение |
| `assets/norms.md` | `spec/NN-slug.norms.md` | те же; `ID_PREFIX`, `N0_LINK`, `ACCEPTANCE_LINK`, формы и проходы |
| `assets/instructions.md` | `spec/NN-slug.README.md` | те же; конкретная подготовка и проверка реализации |
| `assets/api.openapi.yaml` | `spec/NN-slug.api.openapi.yaml` | `TITLE`; реальные маршруты, схемы и ответы |

`STEM` — полное имя без расширения, например `03-units-slots-epochs-lease`.
`ID_PREFIX` — адрес норм, например `М10/3`; буква модуля допустима (`М12A/1`).
`ACCEPTANCE_LINK` из `spec/` модуля — например
`../../Source/tests/testdata/acceptance/М10_Platform/03/README.md`.
`N0_LINK` у следующего урока М10 — `01-storage.norms.md#н0-словарь-слов`;
в другом модуле вычислить относительный путь к тому же канону. Не копировать Н0 дословно.

## Условные части

- Н1: оставить формы, которые реально пересекают провод/диск или нужны для наблюдаемой семантики.
  Статические ограничения HTTP-входа выразить схемой; проверки состояния/байтов/прав назвать отдельно.
- Н2: описать каждый настоящий вход. Загрузчик по байтам, команда установки и HTTP-дверь — разные входы.
  Если HTTP нет, не создавать маршрут ради шаблона; согласовать состав файлов с действующим ADR.
  Пустой `paths` в шаблоне — незаполненная работа, не готовый контракт.
- Н3: перечислить действительные действия и исходы. Не добавлять память `id`, CAS, журнал или лидера
  в урок, где их нет. Каждый проход получает разбор применимых гонок или обоснованное «нет».
  Для механизма с жизненным циклом и разными участниками допуск и переходы записать таблицей:
  участник/состояние → событие/условие → действие → новое состояние/результат. При пересечении условий
  задать приоритет. Псевдокод ссылается на условия таблицы и раскрывает чтения, CAS/guard, записи
  и исходы обрыва. Таблица не означает атомарности составной операции. Пример — М10/3 Н3 «захватить».
  Для простой операции без такого цикла достаточно псевдокода; пустую таблицу не оставлять.
- Н4: выбрать поля для данного входа; код завершения CLI не превращать в HTTP-код, произвольному отказу
  не приписывать `Fault.kind`. Схемы ответов заполнять по решению об охвате долга, не по удобству шаблона.
- Н5: выбрать формат данных под механизм. М10/1 использует `scenarios.tsv`, М10/2 — `verdicts.tsv`,
  `cases/` и `diagnostics.tsv`. README определяет подготовку, подстановки, точное сравнение и исключения.
- Лекция: оставить объяснения и примеры, помогающие этому уроку. Таблицы всех полей или отказов не обязательны;
  вместо копирования полного канона дать ссылку на нужный раздел.
- Инструкция: описать результат и проверку. Внутренний API, типы ошибок, функции и библиотеки не нормировать
  без явного основания. Если показан пример реализации, пометить его как пример.

Все `{{...}}`, комментарии автора и незаполненные строки заменить или удалить до публикации.
Нормы должны быть читаемы без шаблона. Сверить заполненный комплект с чеклистом и исходной версией:
сохранность id и поведения при переносе проверяется сравнением, а не совпадением заголовков.
