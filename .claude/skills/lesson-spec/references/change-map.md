# Таблица связанных изменений

Выбрать строки по смыслу правки. Для каждого места записать «изменено», «проверено — согласовано»
или «не относится» с причиной. Указанные разделы — адреса проверки, а не требование дублировать текст.
Примеры сверены с М10/1–2 после исправлений прогона 20; точные нормы всегда читать в текущих файлах.

| Что меняется | Где искать связанные правила | Что должно остаться согласованным | Пример М10/1–2 |
|---|---|---|---|
| Поле, тип, грамматика, обязательность | Н1; входная схема Н2; чтение/выдача поля в Н3; Н4; данные приёмки | Один набор допустимых значений; тип, пустота и отсутствие различаются; байты не заменены числом символов | R17-01: `cas`, закрытый `guard`; R20-01: `Key` в query, команде и страже, допустимый `..foo`, отдельный предел UTF-8 |
| Причина отказа и наблюдаемый результат | Ветвь Н3 или транспорт Н2; строка Н4; соответствующий вход/маршрут контракта; действие вызывающего; чеклист | Для этой причины определены код, поля, изменение состояния и возможность повтора; общие наборы кодов не заменяют сверку по операциям | R19-04: `toolarge` установщика — выход 2 и stderr до метки; это не ответ `GET /spec` |
| Поля ответа | Н1/Н2; место формирования в Н3; Н4; правило сравнения README; ожидания | Обязательное/необязательное поле, единицы и смысл одинаковы; лишние поля не скрываются общим игнорированием | R20-02: `limit` тела и строки различны; необязательный `size` тела проверяется отдельно от обязательного веса строки |
| Поведение, порядок, точка публикации | Н3; гонки; сроки; лекция; Н5; чеклист | Гарантия следует из названных операций; отсчёт срока привязан к наблюдаемому событию | R18-02: срок от метки, не от записи основной строки; R19-03: полученные байты не доказывают неизменность файла |
| Повтор и память идентификаторов | Н1 идентификатора; Н3 успех/отказ/повтор; гонки; начальное состояние приёмки; чеклист | Повтор сравнивает нужное содержимое, не добавляет изменение; очистка строк не объявлена очисткой памяти `id` | М10/1 сц. 12 и R19-01: отдельный экземпляр при повторном прогоне, пустая память `id` |
| Подготовка и изоляция приёмки | Н5; README приёмки; все зависимости сценариев; инструкции раннеру | Названы начальные данные, права, память, время и параметры; параллельный/повторный прогон не получает чужое состояние | R19-01: пусты `acc/` и `other/`, права проверяемой роли только `acc/`; R20-02: отдельно потолок строки и предел тела |
| Предел или способ измерения | Н1/Н2; Н4; «Решает реализация»; параметры Н5; байты запросов и ожидаемых ответов | Известны единицы, включаемые поля, граница равенства, место проверки; тест достигает нужной ветви | М10/1 сц. 15 помещается в тело, но пересекает потолок строки; сц. 22 пересекает предел тела |
| Диагностика | Н4; исходный файл; ожидания диагностик; правила сравнения; чеклист | Вердикт не выдаётся за проверку сообщения; все пути и обязательные номера проверяются явно | R18-04: три случая `diagnostics.tsv`, второй `name` на строке 36; остальные ветви назначены чтением |
| Установка и составная запись | Н3 по каждой записи; конфликт/отказ; гонки старта и чтения; Н4; Н5 | Начальная ревизия, CAS, отставшая метка и обрыв описаны; допустимый вход загрузчика может не поместиться при установке | R18-03: первая `rev: 1`, `cas: ""`; R19-04: исходный YAML с большим комментарием |
| Выбор реализации | Раздел выбора; README реализации; условия совместимости; чеклист | Нормативное наблюдаемое поведение не превращено в выбор; внутренний API не стал обязательным из примера | Предел тела объявляется отдельно; схема `Fault` не предписывает класс исключения или тип внутреннего результата |
| Перенос, переименование, ссылка или копия схемы | Все входящие ссылки; Н2; приёмка; владельцы копий; карта модуля | Один опубликованный канон, устойчивые id; зависимая копия либо синхронизирована, либо явно оформлена дельта | R19-02: неверное «урок 2»; копии `Key`/`Cmd` урока 11 при изменении урока 1 |

Лекцию и инструкцию проверять при каждой смысловой правке: если они объясняют изменённое правило,
согласовать объяснение; если не затронуты, не добавлять в них полную копию нормы.

Для отчёта о правке достаточно: изменённая норма/id → затронутые файлы → способ проверки →
что осталось открытым. Не объявлять весь отложенный долг закрытым по одному исправленному месту.
