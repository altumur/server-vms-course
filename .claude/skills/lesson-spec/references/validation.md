# Автоматическая проверка после ручного чеклиста

Запуск из корня репозитория; скрипт только читает документы и данные. Код реализаций не импортируется,
приёмочные запросы не выполняются, контракты из сети не загружаются.

```sh
uv run --no-project --with pyyaml --with openapi-spec-validator --with markdown-it-py python \
  .claude/skills/lesson-spec/scripts/check_spec.py \
  М10_Platform/01-storage.md М10_Platform/02-the-spec-and-the-strict-loader.md
```

В подготовленном окружении с `PyYAML`, `openapi-spec-validator` и `markdown-it-py` можно запускать `python3` напрямую.
Код 0 — описанные структурные проверки пройдены; 1 — найдены дефекты, 2 — ошибка вызова.
Отсутствующая зависимость завершает запуск с ошибкой и не считается пропуском успешной проверки.

| Проверяется автоматически | Граница результата |
|---|---|
| Четыре файла урока в новой раскладке, отсутствие однострочных и многострочных `{{...}}` | Качество содержания — вручную; сами шаблоны `assets/` не являются опубликованным уроком |
| Относительные ссылки CommonMark: inline и reference (полная, сокращённая и короткая формы) | Якоря, HTML, изображения, словесные ссылки «урок N» и смысл ссылок — вручную; примеры ссылок в коде не исполняются |
| Уникальные YAML-ключи контракта, OpenAPI 3.1, локальные `$ref` в позициях ссылок OpenAPI/JSON Schema | Поддерживаются корневые JSON Pointer `#`/`#/…`; другие способы разрешения явно отклоняются. Поле `$ref` в данных `example`/`Example.value` не является ссылкой |
| Разделы Н0–Н5, наличие разделов выбора/чеклиста, уникальность и принадлежность id | Сохранность id относительно исходного среза и содержание пунктов — сравнение вручную |
| `scenarios.tsv`: столбцы, шаги, HTTP/ASSERT, JSON ожидаемых ответов | Неверный JSON входа может быть намеренным; запросы, переменные, подстановки и их семантика — вручную |
| `verdicts.tsv`: уникальность, значения, все имена в `cases/` без фильтра суффиксов и вид каждого входа (файл) | Заведомо плохие YAML/кодировка не разбираются как контракты; правильность вердиктов требует загрузчика или чтения |
| `diagnostics.tsv`: отказанный случай, уникальность, форма путей и целых номеров | Совпадение путей/номеров с исходником и фактической диагностикой — вручную/раннером |
| Четыре столбца `corrections.tsv` | Полнота журнала — вручную |

Скрипт рассчитан на нынешнюю раскладку приёмки уроков 1–2: в корне только `README.md`, `corrections.tsv`,
`scenarios.tsv`, `verdicts.tsv`, `diagnostics.tsv` и `cases/` (не все обязаны присутствовать).
Любой другой файл или каталог требует расширения проверки, даже рядом с поддерживаемой таблицей.
Каталог `cases/` требует `verdicts.tsv`; его содержимое точно соответствует именам `<case>.subsystem.yaml`.

Обход ссылок следует позициям объектов [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html#media-type-object)
и стандартным ключам вложенных схем JSON Schema 2020-12. Внешние ссылки, якоря, `$id`, динамические/
рекурсивные ссылки и другие диалекты требуют отдельного разрешателя; сейчас это явная ошибка
«unsupported», а не подтверждение или опровержение валидности контракта. Загрузка внешних ресурсов
отключена и в стороннем валидаторе. Ссылки из расширений проверяются, если на них ссылается объект контракта.
Ограничение зависимости: `openapi-spec-validator` ошибочно разыменовывает объект `default` с полем `$ref`.
Такой контракт требует отдельной проверки; не менять допустимые данные ради зелёного результата инструмента.
Значения `example`, `Schema.examples`, `const`, `enum` и `Example.value` с таким полем проходят проверку.

Скрипт не сравнивает коды ответов общим набором вместо операций, не определяет полноту Н4 поиском слов,
не запрещает слово МОЖЕТ и не требует копии Н0. Эти эвристики не заменяют смысловую проверку.

Отдельно по таблице связанных изменений проверять: грамматику запросов положительными/отрицательными
пробами; порядок отказов; реальные размеры после подстановок; изоляцию и память повторов;
момент публикации, исходы чтения и установщика. При правке соответствующего места нужны целевые пробы,
а не повтор всех проверок продукта. Долг схем ответов не закрывается валидностью OpenAPI.

Изменение самого скрипта проверяется его тестами на испорченных копиях документов:

```sh
uv run --no-project --with pyyaml --with openapi-spec-validator --with markdown-it-py python -m unittest discover \
  -s .claude/skills/lesson-spec/scripts -p 'test_check_spec.py'
```
