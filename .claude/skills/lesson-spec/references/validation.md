# Автоматическая проверка после ручного чеклиста

Запуск из корня репозитория; скрипт только читает документы и данные. Код реализаций не импортируется,
приёмочные запросы не выполняются, контракты из сети не загружаются.

```sh
uv run --no-project --with pyyaml --with openapi-spec-validator --with markdown-it-py python \
  .claude/skills/lesson-spec/scripts/check_spec.py \
  М10_Platform/01-storage.md М10_Platform/02-the-spec-and-the-strict-loader.md
```

В подготовленном окружении с `PyYAML`, `openapi-spec-validator` и `markdown-it-py` можно запускать `python3` напрямую.
Код 0 — описанные структурные проверки пройдены; 1 — найдены дефекты или неподдержанный формат,
2 — ошибка вызова. Неполная проверка завершается `FAIL`, а не `PASS`.
Отсутствующая зависимость завершает запуск с ошибкой и не считается пропуском успешной проверки.

| Проверяется автоматически | Граница результата |
|---|---|
| Четыре файла урока в новой раскладке, отсутствие однострочных и многострочных `{{...}}` | Качество содержания — вручную; сами шаблоны `assets/` не являются опубликованным уроком |
| Относительные ссылки и изображения CommonMark: inline и reference (полная, сокращённая и короткая формы) | Проверяется существование локального пути. Якоря, внешние адреса, смысл ссылок и содержимое изображений — вручную; примеры в коде не исполняются. Сырой HTML явно отклоняется как неподдержанный |
| Уникальные YAML-ключи контракта, OpenAPI 3.1, локальные `$ref` в позициях ссылок OpenAPI/JSON Schema | Поддерживаются корневые JSON Pointer `#`/`#/…` с проверкой грамматики, URI-декодирования и разрешения; другие способы явно отклоняются. Поле `$ref` в данных `example`/`Example.value` не является ссылкой |
| Настоящие заголовки h2 Н0–Н5, разделы выбора/чеклиста, id в пунктах чеклиста до следующего h2 или h1; примеры кода и цитаты их не заменяют; уникальность и принадлежность id | Сохранность id относительно исходного среза и содержание пунктов — сравнение вручную |
| `scenarios.tsv`: столбцы, шаги, HTTP/ASSERT, JSON ожидаемых ответов | Неверный JSON входа может быть намеренным; запросы, переменные, подстановки и их семантика — вручную |
| `verdicts.tsv`: уникальность, значения, все имена в `cases/` без фильтра суффиксов и вид каждого входа (файл) | Заведомо плохие YAML/кодировка не разбираются как контракты; правильность вердиктов требует загрузчика или чтения |
| `diagnostics.tsv`: отказанный случай, уникальность, форма путей и целых номеров | Совпадение путей/номеров с исходником и фактической диагностикой — вручную/раннером |
| Четыре столбца `corrections.tsv` | Полнота журнала — вручную |

Скрипт рассчитан на нынешнюю раскладку приёмки уроков 1–2: в корне только `README.md`, `corrections.tsv`,
`scenarios.tsv`, `verdicts.tsv`, `diagnostics.tsv` и `cases/` (не все обязаны присутствовать).
Любой другой файл или каталог требует расширения проверки, даже рядом с поддерживаемой таблицей.
Каталог `cases/` требует `verdicts.tsv`; его содержимое точно соответствует именам `<case>.subsystem.yaml`.

Формат `scenarios.tsv` М10/3 пока не поддержан общим CLI: у него есть строка заголовка,
`@key`/`@nokey` и ожидания только кода без тела. Он требует отдельной проверки по своему README;
ошибки общего CLI не заменяют её и не дают PASS уроку 3. У М10/4 также есть заголовок, 2xx/4xx
и ожидания кода без тела; у М10/5 добавлены store/console и директивы управления процессами.
Они требуют отдельной проверки формата по README. Комплект М10/5 без OpenAPI разрешён ADR-0082
доп. 13, но общий CLI пока требует этот файл: полный PASS ему не заявляется. Проверки Markdown,
разделов норм и реальных OpenAPI применимы отдельно; сценарный парсер и распознавание комплекта
при переводе 3–5 не расширялись.

М10/6 использует заголовок TSV, `@as`/`@header` и ожидания кода без тела; М10/7 —
`console`/`store`, `@key`, проверки подстрок/отсутствия и отдельные `secret_in.tsv`/`log_mask.tsv`.
Оба формата проверяются отдельно по README. Урок 7 также не имеет собственного OpenAPI
(ADR-0082 доп. 14); проверяется дельта существующего контракта М10/3. Полный CLI06/07
не поддержан, PASS им не заявляется; скрипт при переводе этих уроков не расширялся.

М10/8 имеет собственный OpenAPI, но TSV с заголовком, тремя дверями, @start/@until/@key
и кодами без тела требует отдельного разбора по README. JSON Lines и байты не являются
JSON-ответами: x-line-schema описывает одну строку потока, а не всё HTTP-тело. Полный
CLI08 не поддержан, PASS уроку не заявляется; сценарный парсер не расширялся.

Сырой HTML вне строк/блоков кода (включая комментарии, `<a>` и `<img>`) требует отдельной проверки:
скрипт выдаёт `unsupported raw HTML` и код 1. Это граница инструмента, а не запрет HTML в лекции.
Его наличие не позволяет объявить локальные цели проверенными. Для Markdown-изображений проверяется
`src`; содержимое alt-текста не считается самостоятельной ссылкой или HTML-разметкой.

JSON Pointer проверяется по [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901): после строгого декодирования
URI-фрагмента и UTF-8 разрешены только escape-последовательности `~0`/`~1`; индекс массива — `0` или
ASCII-цифры без ведущего нуля. Знак, пробелы, не-ASCII цифры, `-` и выход за массив дают ошибку.
Для ключа объекта цифровые ограничения не применяются; пустой ключ и экранированные `~`/`/` допустимы.

Обход ссылок следует позициям объектов [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html#media-type-object)
и стандартным ключам вложенных схем JSON Schema 2020-12. Рекурсия через локальный `$ref` поддерживается.
Внешние ссылки, якоря, `$id`, ключевые слова `$dynamicRef`/`$recursiveRef` и другие диалекты
требуют отдельного разрешателя; сейчас это явная ошибка
«unsupported», а не подтверждение или опровержение валидности контракта. Загрузка внешних ресурсов
отключена и в стороннем валидаторе. Ссылки из расширений проверяются, если на них ссылается объект контракта.
Ограничение зависимости: `openapi-spec-validator` ошибочно разыменовывает объект `default` с полем `$ref`.
Такой контракт требует отдельной проверки; не менять допустимые данные ради зелёного результата инструмента.
Значения `example`, `Schema.examples`, `const`, `enum` и `Example.value` с таким полем проходят проверку.

Скрипт не сравнивает коды ответов общим набором вместо операций, не определяет полноту Н4 поиском слов,
не запрещает слово МОЖЕТ и не требует копии Н0. Эти эвристики не заменяют смысловую проверку.

Отдельно по таблице связанных изменений проверять: грамматику запросов положительными/отрицательными
пробами; порядок отказов; реальные размеры после подстановок; изоляцию и память повторов;
момент публикации, исходы чтения и установщика. При правке соответствующего места нужны целевые пробы,
а не повтор всех проверок продукта. Долг схем ответов не закрывается валидностью OpenAPI.

Изменение самого скрипта проверяется его тестами на испорченных копиях документов:

```sh
uv run --no-project --with pyyaml --with openapi-spec-validator --with markdown-it-py python -m unittest discover \
  -s .claude/skills/lesson-spec/scripts -p 'test_check_spec.py'
```
