# Пробы ревью 16: общие сроки событий и тревог

Механизм ADR-0076. Пробы независимы от тестовых помощников автора. Они создают бакеты через `EventLog`, реальные
отметки `mark` консоли и проверяют файлы и журнал после `retain`. Проверяемые checkout не меняются: `run.py` создаёт
снимки через `git archive`, Go-пробу добавляет только в снимок и убирает снимки после прогона.

Требования: Python 3.12 с зависимостями курса; для Go-половины — Go версии из `go.work` продукта. Полные наборы и стенд этот скрипт
не запускает. Точки одновременного исполнения задаются управляемо: новая единица действительно записывает бакет,
а не добавляется в искусственный список.

```bash
/Users/murat/w2c/vms-nightly/venv/bin/python РЕВЬЮ-КУРС-16/probes/run.py \
  --course-repo /Users/murat/w2c/server-vms-course \
  --output /tmp/review16-evidence
```

Код выхода 1 ожидается на снимках ревью: находки воспроизводятся. Сводка содержит полные хеши и нарушенные
сценарии; подробные факты в логах. Для повтора на исправленном дереве передать `--after <хеш>` и `--product <хеш>`.
Снимок `--before` остаётся историческим и сохраняет ошибки; общий код выхода поэтому по-прежнему 1.

Для ночного прогона Go-половины (на продукте текущей ночи):

```bash
python3 РЕВЬЮ-КУРС-16/probes/run.py --go-only \
  --product-repo /path/to/vmssubsystem --product <хеш-ночи> \
  --output /path/to/night/review16
```

При старте прохода роль требовала два дерева. Во время прогона ADR-0052 разделил роли; уже полученные
Go-факты и файлы сохранены для отдельного ревью продукта и ночного прогона. По умолчанию `run.py` теперь читает
только курс. Исторический объединённый прогон воспроизводится с `--include-product`; этот режим для сессии,
которой разрешено читать обе стороны.

`retention_probe.py <снимок>/Source` и `concurrent_unit_probe.py <снимок>/Source` выводят наблюдения JSON;
самостоятельно не выставляют ошибку за известный дефект. Её выставляет `run.py`. Go-пробы содержат утверждения:
`TestReview16RetentionEvidence` падает при потере отметки о сохранившихся тревогах;
`TestReview16ConcurrentUnitEvidence` проверяет завершение уборки с записью в журнал.

`contract_probe.py <снимок>/Source` проверяет создание, изменение и повторное удаление камеры,
отказ старого `derived` и защиту событий и тревог удержанием до его отпускания. Это положительная проверка
закрытых пунктов ADR-0076; результат записывается отдельно от двух находок.

Факты первого прогона сохранены в `evidence/`. Новые результаты писать в отдельный каталог.
