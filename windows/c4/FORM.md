# C4: принятая форма до реализации

Источник: ADR-0074, main ce7f1a83. C3b разрешён a8f2d5d4 и слит b96c2d9d.
Мутационная проба после него завершена; собственная запись windows/m10-1-mutation-trial.
Ни C5, ни C6/C6b, ни удаление domainpart C7 в это окно не входят.

**Форма C4 продукта (2026-10-13, «Сборка», принята; байты ключей для зеркала курса).** Ключи:
`rec: domain.books.polls: {from: rec/polls/, key: ref, pick: unique, to: to}`;
`cam: domain.tokens.poll: {lifetime: 86400, claims: [aud, ref], grant: [camworker, recworker], unit: {ref_claim: ref,
target_fields: [poll_home], audience_claim: aud}}` — новый объём `unit` рядом с `placement` (у вида один объём, либо
тот, либо другой): подписант проверяет, что член-заявитель сам сообщает единицу спеки с этим `ref` (по `domain.ref`
спеки, из его принятого отчёта); `poll_home` — дом опроса единицы: `via` кластера-заявителя в топологии, иначе
центр, иначе кластер держателя; `sub` = заявитель; закрытый набор `target_fields` объёма `unit` — `poll_home`;
`cam: worker.reads` += `domain/rec/polls`. Уходят без алиаса: `cam: domain.books.polls: {}`, семья ключей `polls` и её
слова `display`, в `domainpart` — книга опросов и `PollHome` (дороги `asks` до C6 берут дом опроса тем же правилом,
функция одна на обе стороны).
*Как дом узнаёт камеру* (поправка к форме C2): воркер камеры пишет элемент `sources` и для опрашивающей камеры без
назначения — **без адреса**: `{ref, to: [дом] (+ центр, если дом ≠ центр), polls: true, live_url: "", server,
as_of}`; `live_url` пуст только у такого элемента; адрес и учётные данные никуда не уходят, дом и центр получают
лишь «камера `ref` кластера X опрашивает». Дом воркер считает сам по копии топологии и записи держателя.
*Издатель* — рекордер дома опроса: `rec/polls/<рекордер>` после пульса, элемент на каждую камеру из `domain/cam/sources`
у себя с `polls: true` без назначения, чей дом — этот кластер: `{ref, to: [кластер камеры], urls: [ingest-адреса
кластера]}`; один издатель на кластер — как у `upstream`. *Читатель* — толкатель камеры: `domain/rec/polls`
(собранная), `urls` и кластер = `member`, токен вида `poll` свой через дверь агента (vmscam — в процессе), в книге
токена нет, без источника — ERROR. Записанные камеры опрашивают кластер записи (C2).
*Пробел C3 (`upstream` камер только с опросом) — закрывается в C6, не здесь*: у вида один объём, второй объём у
`upstream` ломал бы C3; C6 переделывает дороги через центр; на стенде и в ночном таких камер нет.
*Приёмка*: камера без записи (новая на cam-b, `VMS_POLLS`) опрашивает relay-b; при снятом `via` — центр; без центра —
держатель; просьба сценария доходит; книга `polls` не несёт адреса; смена топологии переносит опрос; «Ночному» — та же
камера в e2e. Ветка одна: `platform:` (объём `unit`, `poll_home`, ключ загрузчика — на чтение) и `vms:`; полный прогон.
