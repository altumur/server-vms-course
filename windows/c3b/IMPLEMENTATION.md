# Реализация C3b

Форма не расширяется относительно FORM.md. `ingest_cluster` не меняет
назначение: это адресат транспорта в наблюдении. Камера не выводит его
из своей топологии; аудиенцию выводит generic-подписант из топологии
держателя. Только primary в star добавляет centre, копия в star — нет.
Отсутствующая конфигурация топологии не добавляет аудиторию (обычное
назначение продолжает работать); повреждённая конфигурация даёт 409.
Существующий target centre продолжает требовать подтверждённый центр.

Рекордер star использует только полный unique upstream своего центра.
При missing/конфликте/плохом издателе не публикует собственный ingest
как ложный fallback. Primary/backup вне star сохраняют свой ingest.

Живой тракт: camera AssignedPush читает ingest_cluster из primary,
центр проверяет stream aud/ref, ретранслятор получает поток своим
upstream token через C3 pull. Канал камеры по-прежнему один на primary,
резервы независимы, искусственная копия центра не заводится.

Диапазон: RecWorker.host_ingest связывает существующий card_range с
форвардером; для star тот читает current upstream и просит centre.fetch
с собственным upstream token. Ingest проверяет kind/aud/ref, затем
исполняет прежний fetch_range: именованный запрос карты, ожидание её
загрузки, очистка partial/result/failed при завершении и timeout.
После ответа форвардер заново проверяет scope; ответ прежнего центра
не применяется. Отказ токена очищает кэш и идёт в повтор. Обычный
рекордер читает диапазон через свой local ingest без токена центра.
Это методы реализации Python над прежним диапазоном, новых полей
книги/токена/диска и новых HTTP-путей не вводится.

Отдельно сохранены тесты v2 подтверждения центра и его смены при
чтении. Новые модули и общую acceptance ведёт «Спецификация»; здесь
только код Python и его тесты. C4–C7 не переносятся вместе с C3b.
