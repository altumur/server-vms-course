# C5 — утверждённая форма до кода

Источник: ADR-0074 и решения b2204ff6/557540a8. Ниже точные выдержки; позднее решение снимает противоречащую раннюю поправку. Новых форм этот файл не вводит.


**Форма C5 продукта (2026-10-13, «Сборка», принята; байты ключей для зеркала курса).** Ключи:
`live: domain.books.stream-accounts: {from: live/stream-accounts/, key: name, pick: unique, to: to}`;
`live: domain.names.stream-accounts/: {exclusive_with: domain/users, grant: view}` — имена на книге с `from`;
`live`: таблица `accounts` (строки `live/accounts/<имя>` `{doc: {name, disabled, at, by}, password_secret}`, пишет
только роль шлюза, секрет запечатан ключом кластера); `live: worker.reads` += `domain/live/stream-accounts`,
`domain/member-list`. Уходят без алиаса: у `cam` — `books.stream-accounts: {}`, `kept: [stream-clients/]`,
`names.stream-clients/`, семьи ключей и их слова; в `domainpart` — учётки, выдача и двери `/stream-clients…`.
*Долговечность*: строка вклада живёт со слотом (доп. 6), поэтому учётка хранится строкой таблицы кластера, а вклад
`live/stream-accounts/<шлюз>` выводится из неё на каждом пульсе; один издатель на кластер — живой шлюз с наименьшим
именем, остальные пишут пустую строку. *Элемент* `{name, to, disabled, password_secret}`, ключ `name`; `to` — все
члены списка `domain/member-list` (у члена нет чужих грантов), доставку по гранту отсекает сборщик по
`names.<семья>.grant` (C1) — это и было назначено платформе в доп. 2, слова «издатель считает по grants» сняты.
*Двери* — у шлюза: `POST /live/accounts {name}` → пароль один раз; `POST /live/accounts/<имя>/password`; `PUT
/live/accounts/<имя> {disabled}`; `DELETE /live/accounts/<имя>` плюс снятие грантов на имя через дверь консоли домена;
консоль кластера пропускает `/live/accounts` к шлюзу своего кластера (без шлюза — 409). Проверка имени при создании:
человек (`GET /domain/users`), учётка по своей копии книги — частичная: одновременное имя в двух кластерах — конфликт
`unique`, недоставка обеих, виден по индексу `domain/names/live/stream-accounts` (доп. 2). Страница — `/live/accounts`
своей консоли. *Читатель* — RTSP-дверь шлюза: `domain/live/stream-accounts` через `MemberBook`, учётки не `disabled`,
пароль — открытый секрет записи. *Стенд*: прежние строки в сторону без переноса (ADR-0003), учётка стенда заводится
заново у шлюза srv с новым грантом. *Приёмка*: учётка с cam-a играет на RTSP-двери кластера с грантом и не играет без
него; имя человека и имя учётки другого кластера — 409; отключение и новый пароль доходят; перезапуск шлюза учётку не
теряет; удаление снимает гранты. Полный прогон.

**Поправка к форме C5 (2026-10-13, вопрос «Сборки», правило загрузчика — обе стороны).** `worker.writes` может называть
таблицу **списочной** формы (`tables: [accounts]` — семья, которую консоль не обслуживает): ACL воркера получает
`<sub>/<таблица>/*`, консоль её CRUD не отдаёт, права консоли по списочной форме не меняются. Таблица объектной формы
(с CRUD консоли) в `worker.writes` — отказ загрузчика: два писателя одной строки. Так страница не пишет учётки мимо
двери шлюза. Одна проверка загрузчика и случай вердикта.

**Поправка к форме C5 (2026-10-13, по чтению ядра продукта): ключ `door.pass` и форма карты в `worker.writes`.**
Спека: `door: {routes: [<маршрут>…], pass: [<маршрут>…]}` — `pass` называет маршруты подсистемы без единицы, которые
консоль кластера **пропускает** к одному живому воркеру своей подсистемы: наименьшее имя среди живых с дверью; имена
`pass` не пересекаются с `routes`, строками и `where`. Консоль сама проверяет право человека (view — чтение, admin —
запись), затем пересылает метод, путь, запрос, тело до 1 МБ и заголовки `Authorization`, `Content-Type`,
`Idempotency-Key`, `X-Operator`; нет клиента или воркера — 503, воркер не ответил — 502; клиент консоли — к роли
воркера под её комплектом (ADR-0075). Воркер у себя проверяет личность человека ещё раз и к домену ходит через свою
консоль как этот человек. У `live`: `door: {pass: [accounts]}`. Форма карты в `worker.writes` («только названные
поля», как `cam: devices`) остаётся разрешённой; отказ — на семью, которой нет.



## 2026-10-14-c5-ответы-учёток.md

## Решение («Архитектор», 2026-10-14)

Принято как подано — байты совпадают с продуктом (`liveproc/accounts.go`): `GET /live/accounts → 200 {accounts: [{name, disabled, at, by}]}` (у продукта `disabled`, `at`, `by` опускаются при нуле — курс так же; без пароля); `POST /live/accounts {name}` и `POST /live/accounts/<имя>/password → 200 {account, password}` — пароль только этим ответом; `PUT /live/accounts/<имя> {disabled} → 200 {account, disabled}`; `DELETE → 200 {account, deleted: true, grants_changed: [<кластер>…]}`. Имена `account`/`accounts`; прежние `client`/`clients` и их двери уходят без алиасов (ADR-0003). Неизвестность `GET /domain/users` — 503; одновременное создание в двух кластерах — конфликт `unique`; проверка имени по копии книги частичная — как в ADR-0074.



## 2026-10-14-c5-комплект-tls.md

## Решение («Архитектор», 2026-10-14)

**Форма — ADR-0075 доп. 3 дословно, входит в C5** как зеркало клиентской половины окна 1, в той же ветке до `door.pass`, платформенно и без знания `live`. Корень `W2C_TLS_DIR` (на Linux `/etc/w2c/tls`): `ca.pem` и `revoked` общие на сервер, `<роль>/server.{pem,key}` на роль — та же пара служит и клиентом (serverAuth+clientAuth); один загрузчик комплекта роли (в Python уже `tls.Bundle(dir, role)`), роль из `W2C_ROLE`. Клиент консоли к воркеру: сертификат роли `console`; у сервера — цепочка до CA, не отозван, ровно одна роль из SAN URI `urn:w2c:role:<роль>` и она `<sub>worker`, SAN DNS равен хосту адреса; IP при TLS — отказ клиента. Без комплекта клиент ходит только к `http://`, `https://` без комплекта — отказ с причиной: это не fallback, а режим коробки без TLS (доп. 3), «отсутствие комплекта закрывает соединение» верно для `https://`. Сервер шлюза подтверждает роль `console` и отдельно проверяет токен человека — как подано. Тестовый injectable-клиент остаётся только в тестах.



## 2026-10-14-c5-таблица-devices.md

## Решение («Архитектор», 2026-10-14)

**Объектная форма остаётся, второй писатель снимается у консоли, не у таблицы.** Таблица, названная в `worker.writes`, — таблица воркера: он пишет строку целиком с `cas` (как сейчас `device_row`), консоль её **только читает** — `GET /<т>` и `GET /<т>/<id>` остаются с полями и `identity`, `POST`/`PUT`/`DELETE` отвечают `403 {error: denied, detail: "written by its worker"}`; страница формы не показывает. Объявление `tables.devices` с полями не меняется, `worker.writes: [devices]` — тоже; `write_row`, `auto.Catalog`, `device_identities` не трогаются. Отказ загрузчика «объектная таблица в `worker.writes`» (поправка 13.10) снят — его нет ни в уроке 2, ни в продукте (`cam: writes: [devices]` грузится); заменён этим правилом в уроке М10/10 Н1 и дополнении к ADR-0074 этим коммитом. Списочная форма (`tables: [<т>]`) — по-прежнему для семьи без дверей консоли (`accounts`). Новой формы read-only таблицы не нужно: право читать даёт объявление, право писать — `worker.writes`. Старый тест `GET /devices/<host>` остаётся, к нему — отказ консоли на запись.



## 2026-10-14-c5-tls-дверь-шлюза.md

## Решение («Архитектор», 2026-10-14)

**Одна дверь шлюза — да; переключатель — комплект, не `GATEWAY_URL`.** По уроку М10/11 Н1 (строка `<sub>worker`) и ADR-0075 доп. 3: есть `W2C_ROLE=liveworker` и комплект в `W2C_TLS_DIR` — дверь говорит TLS с `<роль>/server.{pem,key}`, общими `ca.pem`/`revoked`, и объявляет себя `https://`; нет комплекта — дверь только на петле и `http://`. Явный `GATEWAY_URL` должен согласоваться с режимом: `https://` без комплекта и `http://` с комплектом вне петли — отказ старта с причиной; IP в TLS-адресе — отказ. Клиентский сертификат на этой двери — по желанию (`VerifyClientCertIfGiven`, как у консоли домена, ADR-0075 доп. 7): показан — проверяется CA/CRL и роль; `/live/accounts[/…]` в TLS-режиме требует роль `console`, затем отдельно токен человека; WHEP — прежний токен человека, `/metrics` — как в ADR-0075. Второй двери, порта, env и полей пульса нет. Продукт сегодня: дверь шлюза `LIVE_URL` http без комплекта — долг окна 1 ADR-0075 у `liveworker`, «Сборке» сказано.
