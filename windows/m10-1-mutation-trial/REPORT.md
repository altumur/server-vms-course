# Результаты мутационной пробы М10/1

Норма — [М10/1](../../М10_Platform/01-storage/lecture.md), идентификаторы чеклиста `М10/1-NN`; форма прогона — [README окна](README.md).
Исходники курса и общая приёмка не исправлялись. База и хеши входов — [inputs.json](inputs.json).

## Baseline: 23 отказавших шага в 11 сценариях

Из 98 шагов 75 совпали с TSV, 23 нет. Все шаги исполнены, блокировок из-за несвязанных переменных и транспортных ошибок нет.

Это слой `shape` в [baseline/api.json](baseline/api.json), **не добавленные отказы TSV**: переменная `$a` универсальна и связана с фактическим числом. Эти наблюдения не увеличивают 23 шага и не участвуют в kill ratio.

## Ровно 12 одиночных мутантов

Курсивом «не достигнут» обозначен пробел пути исполнения, не эквивалентность мутанта. Полные патчи, функции и все свидетели — в каталогах мутантов и [mutants.tsv](mutants.tsv).

| Мутант | Единственная поломка | Shared API: новый свидетель | Существующие unit |
|---|---|---|---|
| S01-cas | StoreMachine игнорирует CAS | убит: 02/2, 04/3, 06/2, 07/4 получают запись вместо конфликта | убит: CAS и version-тесты |
| S02-guard | StoreMachine игнорирует стража | убит: 09/4 возвращает 200 вместо 412 и меняет строку | убит: `test_guard` |
| S03-replay | память id не читается при повторе | убит: 12/2 возвращает 409 вместо первого ответа 200 | убит: повтор после потери ответа |
| S04-id-content | коллизия id не сравнивает содержимое | убит: 12/4 возвращает 200 вместо 400 | убит: `test_an_operation_id_is_answered_from_memory_only_for_its_own_write` |
| S05-delete-version | DELETE возвращает старую версию | убит: 07/5 `ASSERT` на разные версии | убит: `test_a_version_is_the_log_index_above_the_base_and_is_never_handed_out_twice` |
| S06-read-copy | get отдаёт собственный dict StoreMachine | **выжил**, участок исполнен: сериализация HTTP скрыла совместное владение памятью | убит: `test_what_the_machine_hands_out_is_a_copy` |
| S07-limit | потолок уменьшен с 512 до 256 КиБ | убит: 15/1 limit=262144; 15/3 отказывает в разрешённой строке | **выжил**: границы unit вычисляются из мутировавшей `MAX_VALUE` |

| V11-key | safe_path принимает сегмент `..` | убит: 13/3–4 принимают плохой ключ | убит: ключи и guard формы |

Все 12 синтаксически валидны, импортируются и обслуживают сценарии; 0 ошибок транспорта и 0 невалидных мутантов. Вызовы целевых функций подтверждены `api-calls.json`, а не выводятся из одного цвета тестов.
Kill считается по новому facet относительно baseline. Пример: baseline 09/4 уже красный из-за отсутствующего `kind`, но его статус 412 верен; S02 добавляет **новое** нарушение статуса — 200. У S05 новый отказ только в `ASSERT` 07/5. Исходно красные 23 шага не засчитаны 12 убийствами.

**Знаменатели:** API — 9 исполняемых мутантов: 8 убито + 1 выжил; среди всех 12 ещё 3 недостижимы. Unit — 10 убито + 2 выжило. Вместе — 11 убито + 1 выжил = **8,33 % выживших** фиксированной выборки.
Состав selection не случайный: этот процент не оценка качества всех возможных мутаций курса.

## Общий survivor не эквивалентен исходнику

Диагностика V12 выполнена **отдельно от existing unit**, напрямую через публичный API FileVariables в отдельном Python-процессе; это не новый daemon backend и не добавленный shared-сценарий.

| Контроль | Первая версия | После DELETE и нового PUT | Старый CAS |
|---|---:|---:|---|
| [baseline](baseline/non-scoring-delete-witness.json) | 1001 | 1003 | отказан, строка `n=2` |
| [V12](V12-file-delete-version/non-scoring-delete-witness.json) | 1001 | 1001 | принят, строка `n=late` |

Следовательно нарушаются `М10/1-06`, `М10/1-07` и отсечение устаревшего писателя. Диагностика объясняет survivor, но **не превращает** его в kill существующей приёмки.

## Рекомендации следующему окну

1. **Сначала закрыть baseline-расхождения** по идентификаторам таблицы, сохранив общий TSV. Несовпадение 17/1 при точном сравнении JSON разобрать отдельно от неверных кодов и состояния строки. Нормы в этой пробе не менялись.
2. **М10/1-06, -07, -04:** существующий сценарий 07 обязан быть применён к публичному API файлового и остальных in-process хранилищ. Сейчас он действительно прогонялся только за дверью StoreMachine. Не объявлять три недостижимых мутанта эквивалентными. В unit файлового хранилища добавить последовательность create → delete → create → попытка со старым CAS: она должна видеть новую версию и отказ. Такой новый тест не включён задним числом в текущую долю.
3. **М10/1-03:** round-trip сценарий 03 подтверждает значения, но не доказывает отсутствие общих ссылок внутри backend. Сохранить существующий тест копии с изменением входного/прочитанного словаря на всех in-process реализациях. Сериализация отдельного daemon-процесса делает S06 ненаблюдаемым для этих HTTP-запросов.
4. **М10/1-12:** потолок в API ловится общим сц. 15, однако существующий unit берёт и вход, и ожидаемый ответ из той же `MAX_VALUE`. Если unit должен проверять соответствие норме 512 КиБ, нужен независимый эталон предела, а не величина из изменяемой реализации.
5. **Н1 / провод:** вывести тип версии в отдельную обязательную проверку формы ответа, не меняя универсальное связывание `$var`. Иначе произвольный тип, однажды связанный с переменной, остаётся зелёным. Зафиксированные 54 наблюдения сейчас намеренно не маскируют CAS, guard и id-проверки.

Дальнейшая разработка адаптера, изменение общей приёмки, исправление платформы и постоянное место mutation testing требуют отдельного окна. Здесь сохранены воспроизводимая проба и фактические свидетельства.
