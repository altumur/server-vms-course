# М10/1: проба завершена; baseline и один общий survivor

## Контекст
После C3b b96c2d9d выполнена назначенная узкая проба variables.py/storemachine.py
на опубликованном ce7f1a83. Запись windows/m10-1-mutation-trial/:
REPORT.md, README.md, summary.json, 12 точных патчей, baseline и мутантные
логи с exit, вызовы целевых функций и SHA256 в evidence.json.
Source, новые уроки, shared acceptance, продукт и его ведомости не менялись.

## Результат
12 валидных одиночных мутантов; API: 8 убито, 1 выжил, 3 недостижимы
(LocalBackend не исполняет FileVariables). Existing unit: 10 убито, 2 выжили.
Вместе 11/1 = **8,33 % выживших** фиксированной выборки.
Убийство — новый facet против baseline; исходное красное не засчитывали.

Shared TSV исполнен весь: 22 сценария, 98 шагов, 75 совпали, 23 нет в
11 сценариях; unit baseline46/0/0, exit0. Все API через unix HTTP настоящего
StoreDaemon в отдельном процессе с правами только acc/*. 13 собственных
демонов остановлены, exit0. run.exit0 означает завершение пробы, не зелёную
приёмку. 23 несовпадения и нормы перечислены в REPORT.md/baseline-failures.tsv.
Отдельно54 ответа с числовыми версиями вместо строк по Н1; универсальные
переменные TSV связывали фактические значения, без ложного type-fail.

Общий survivor V12 сбрасывает счётчик FileVariables при DELETE. Отдельный
non-scoring witness доказывает повтор версии1001 и приём старого CAS;
исходник даёт1003 и отказ. Новый witness не включён задним числом в kill ratio.
S06 copy скрыт сериализацией API, но убит unit; S07 половинный потолок убит
API, но unit выжил, поскольку строит эталон из мутируемой MAX_VALUE.

## Рекомендация
1. Считать назначенную пробу завершённой; постоянный mutation-конвейер пока
не вводить. После неё начали C4 отдельной веткой, как поручено в ответе C3b.
2. Baseline исправлять отдельным окном платформы Python по неизменной норме
М10/1 и текущему TSV: строковые версии на проводе, guard с пустой версией,
формы cas/id/items/guard, kind/again и сведения о потолке. Отличать лишнее
поле fault в17/1 от неверных кодов и изменения состояния. Это не предложение
ослабить приёмку, не перенос контрактов продукта.
3. В собственные unit добавить независимый от MAX_VALUE эталон512КиБ и
create→delete→create→stale-CAS для FileVariables. Общий сценарий07 потом
применять и к файловому API; HTTP-сериализация не проверяет aliasing памяти.
4. Команде «Спецификация» предлагаем отдельную обязательную проверку типов
версий Н1, сохранив универсальное связывание $var. Её acceptance-файлы сами
не меняем. До этих дополнений три недостижимых участка не считать
эквивалентными, текущую пробу не объявлять зелёной приёмкой хранилища.

Просим зафиксировать судьбу результатов и порядок отдельного storage-окна.
C4 не меняет variables/storemachine и в этот отчёт не смешан.

## Решение («Архитектор», 2026-10-14)

выживших сценариями 19–22 и вторым раннером по `p.Variables`). Дальше одно окно хранилища Python по неизменной норме
М10/1: все 23 шага baseline, 54 числовые версии (Н1: строка на проводе) и V12 (`М10/1-06`, `-07`). Шаг 17/1 — не
артефакт сравнения: форма `Fault` в Н4 закрыта, поле `fault` лишнее — убрать. В том же окне — второй исполнитель тех
же сценариев через API `FileVariables`/`MemVariables` без двери (СЛЕДУЕТ урока; делает V09/V10/V12 достижимыми).
