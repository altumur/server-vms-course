### SA1-17 — requests_body.tsv требует fault:not_json/not_number у двери просьб, которых норма запрещает — вопрос Архитектору

- Место: `Source/tests/testdata/requests_body.tsv:35-36` — «ANY door … 400 with `fault` (not_json / not_number)»; строки :105-111 — request с телом `NaN` → `not_json`, `1e999`/`1e400` → `not_number`, `"\ud800"` → `not_json`, `Infinity` → `not_json`.
- Основание: `М10_Platform/spec/08-events-resource-requests.norms.md:411-412` — «RequestError допускает дополнительно fault:"too_long" только при превышении длины поля; остальные причины fault не получают»; Н4 там же :741 — «тело не JSON — без fault»; OpenAPI `М10_Platform/spec/08-events-resource-requests.api.openapi.yaml:1077` — `fault: const: too_long`; приёмка `Source/tests/testdata/acceptance/М10_Platform/08/scenarios.tsv:81` — `400 {"fault": "@absent"}`.
- Контрпример: допустимый запрос POST двери просьб с телом `NaN` — таблица векторов требует ответ с `fault:not_json`, а закрытый список Н2/Н4 урока 8 допускает только `too_long` либо отсутствие fault.
- Замечание: у двери единиц not_json/not_number есть (М10/3 Н4:659,662) — конфликт именно у двери просьб, а строка :35-36 объявлена для «ANY door».
- Последствие: векторный прогон двери просьб и спека дают противоположные ответы на одном входе; стадия B унаследует противоречие.
- Рекомендация: привести requests_body.tsv к норме урока 8 (убрать fault у request-строк) либо изменить норму решением.

### SA1-18 — log_mask.tsv маскирует proxy-authorization вне закрытого перечня нормы — вопрос Архитектору

- Место: `Source/tests/testdata/log_mask.tsv:28` — `proxy-authorization: bearer abc.def → ***`.
- Основание: `М10_Platform/spec/07-secrets-and-sealing.norms.md:319` — закрытый перечень маскируемого: только заголовок `Authorization` (Basic/Bearer), пары «имя=значение» с секретным именем, адреса с секретами.
- Контрпример: строка лога `proxy-authorization: bearer abc.def` — по таблице маскируется, по норме обязана остаться открытой; зеркально — реализация по норме пропустит в лог секрет, который таблица считает маскируемым.
- Последствие: норма пропускает секрет в лог либо вектор врёт о норме; утечка/несоответствие приёмки.
- Рекомендация: либо расширить перечень нормы (запись о proxy-authorization), либо убрать строку из таблицы.
