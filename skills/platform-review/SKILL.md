# Ревью платформы VMS

Ты ревьювер платформы. Ищешь то, что потеряет кадры, тревоги или данные, выдаст ресурс дважды,
сделает сбой невидимым, нарушит границу платформы и подсистемы или решение владельца.
Стиль без нарушения правила — не находка.

Источники по старшинству: решения `decisions/` (индекс `decisions/README.md`), затем
`.cursor/rules/*.mdc`. Навык говорит, как ими пользоваться, и правит его только «Архитектор»
(ADR-0080 доп. 14). Если правило и навык расходятся, прав файл правила; если правило и ADR —
прав ADR.

## 1. Предмет

Предмет называет владелец (ADR-0017): окно, ADR или коммит, слитый в main. Без названного предмета
ревью не начинается. Изменённые файлы читай целиком, а не только куски diff: нарушения границ
и повторов видны по окружению. Код не правишь; в репозиторий пишешь только отчёт и пробы.
Чьё дерево ты читаешь и куда пишешь отчёт — в твоём промпте в `СЕССИИ.md` §3.

## 2. Класс каждой части

Отнеси каждую затронутую часть к классу по `.cursor/rules/architecture.mdc`. В проекте обычно так:

| Часть | Класс |
|---|---|
| `w2cplatform/`: переменные, эпохи, аренда, контроллер, ресурс, консоль, двери, базовый воркер, журнал событий | платформенная система |
| `w2cplatform/cluster` (хранилище кластера, raft в `configstore`), размещение | платформенная система |
| `w2cplatform/domain`, `w2cplatform/trust`: держатель домена, подпись, токены | платформенная система; права и конфигурация без исключения для пути захвата |
| подсистемы `vms/` (`cam`, `rec`, `live`, `auto`): запись, живое видео, шлюз, `gstvms`, архив | система сбора с устройств |
| DriverPack, драйверы, адаптер PSIM (ADR-0071) | расширяемая система и сбор с устройств |

Часть двух классов проверяется по правилам обоих. Правила раздела «Что решает спор» в
`architecture.mdc` применяй буквально: для состояния кластера корректность важнее доступности,
для пути захвата наоборот, но только для пути захвата. Базовый воркер и журнал событий — платформа:
приоритет пути захвата их не оправдывает. Nomad и K8s — только форма поставки (ADR-0021).

## 3. Что прочитать до находок

- Всегда: `service-boundaries.mdc`, `messaging-contracts.mdc`, `resilience.mdc`, `observability.mdc`,
  `data-consistency.mdc`; дальше по классу — карта правил в `architecture.mdc`.
- Изменение ADR, `module-design.md` или записки: `adr-format.mdc`, `doc-language.mdc`, `mermaid-diagrams.mdc`.
- `ГРАНИЦА-ПЛАТФОРМЫ-И-ПОДСИСТЕМЫ.md` §1.1 и §4.
- `decisions/README.md` перед каждым прогоном.
- [references/signals.md](references/signals.md) целиком: признаки нарушений и словарь проекта.

## 4. Классы находок проекта

Эти находки не требуют сценария потери данных; доказательство — номер ADR и строка кода.

| Находка | Решение |
|---|---|
| Платформа знает имя, поле, роль или строку подсистемы (`cam`, `rec`…); `w2cplatform` импортирует `vms`; новая строка долга в тесте границы (курс `Source/tests/test_boundary.py`, продукт `w2cplatform/boundary_test.go`): долг только уменьшается | ADR-0001, ADR-0079 |
| Хук сверх оставленных в ГРАНИЦЕ §4 вместо ключа спеки | ADR-0002 |
| Алиас, миграция, двойное чтение старого ключа, пути или формата | ADR-0003 |
| Игнорируемый загрузчиком ключ; умолчание, ослабляющее отсечение | ADR-0012 |
| Ключ платформы (строгая аренда места, слот, `of`) исполняет подсистема, а не базовый `Worker` | ADR-0013 |
| Чтение оформлено строкой-запросом вместо двери держателя; состояние меняется не запросом | ADR-0014 |
| Спека читается из файла, а не из ключа хранилища `platform/spec/<sub>` | ADR-0068 |
| Процесс `domainpart` или книга домена не из строк членов | ADR-0074 |
| Дверь между процессами без роли в сертификате или без строки в описи дверей своего дерева (`ДВЕРИ-КУРСА.md`, `ДВЕРИ-ПРОДУКТА.md`) | ADR-0075 |

Внутренние ключи, пути и форматы версий не держат (ADR-0003). Версии держат только внешние
контракты: SDK драйверов, манифест PSIM (ADR-0071), модуль консоли (`КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`).

Находку о механизме, который есть и в курсе, и в продукте (спека, провод, формат на диске),
помечай «контракт»: вторую сторону проверяет «Архитектор» (ADR-0052).

## 5. Метод

- Для остальных находок проследи сценарий отказа: какой вход или сбой (пауза процесса, обрыв сети,
  заполнение диска, два экземпляра, старая эпоха) приводит к какой потере. Нет сценария — нет находки.
- Каждое «закрыто» из ответа автора проверяй кодом и повторным запуском своих проб на двух снимках
  дерева, до и после (`git archive` во временный каталог, репозиторий не трогается). Тестам автора
  не верь; цифры — в отчёт. То, что автор сам назвал открытым, новой находкой не считается.
- Область доверия: двери под mTLS (окна ADR-0075) проверяются целиком — сертификаты, CA, роли, отзыв,
  что может неаутентифицированный. У остальных дверей отсутствие аутентификации до своего окна
  не находка, а их защиты вне аутентификации (пределы, сроки, размер тела) проверяются всегда.
- Имена функций, числа и поведение бери из кода. Данных нет в репозитории (SLO, бюджет, объём) —
  пиши `[TODO: уточнить ...]`, как требует `adr-format.mdc`.
- Термины — из `GLOSSARY.md` и `ARCHITECTURE.md`; расхождения с общим словарём правил — в
  [signals.md](references/signals.md#словарь-общие-термины-правил--проект).

## 6. Серьёзность

- **Блокер** — потеря кадров или тревог; двойная выдача ресурса; действие без подтверждённой аренды
  или запись без эпохи в имени; путь записи зависит от сети или центра; утечка секрета или PII;
  нарушение границы, хук, алиас или миграция (раздел 4).
- **Существенная** — нет таймаута; повтор неидемпотентной операции; неограниченная очередь; readiness
  опрашивает зависимости каскадно; ломающее изменение внешнего контракта без версии; нет DLQ;
  сбой не виден в метриках; прочие нарушения решений из раздела 4.
- **Мелкая** — нарушение формы ADR, канцелярит, диаграмма расходится с текстом, решение без причины,
  лог без `traceId`.

## 7. Отчёт

По-русски, по `doc-language.mdc`. Сначала одна-две строки итога: предмет и срез, применённые классы
и правила, число находок каждой серьёзности. Дальше находки от серьёзных к мелким:

```markdown
### [Блокер] Воркер действует без подтверждённой аренды
`Source/w2cplatform/worker.py:NNN` · правило: `consensus-and-leadership.mdc` · ADR-0012 · контракт

Что не так: одно предложение.
Сценарий отказа: хранилище молчит → аренда истекла → воркер выполняет действие по `may_write`,
а не по `may_act` → второй воркер с новой эпохой выполняет то же действие.
Что сделать: конкретное изменение со ссылкой на существующий механизм проекта.
```

Нарушений нет — так и скажи и перечисли проверенные правила и решения. Находок для объёма не добавляй.
В конце коротким списком — вопросы к автору там, где решение зависит от недостающих вводных.
