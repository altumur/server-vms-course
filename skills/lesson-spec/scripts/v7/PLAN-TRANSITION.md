## 1. Навык `lesson-spec` («Архитектор»), до норм

Навык должен уметь всё, что `check_spec` делает сейчас из диалекта, — из стандартных файлов. Порядок:

1. **Генератор → строитель стандартных файлов.** `v7/build.py` пишет не в `v7/out/`, а по местам из п. 2.1 (одним
   прогоном; второй прогон — байт в байт). Каждая схема самодостаточна: нужные определения `common.form.yaml` — копиями в
   её `$defs`, `$ref` только внутри файла (`#/…`); так генератор пишет и сейчас. Плюс `common/data/common.schema.json` —
   справочно, не норма. После перехода источник — сами стандартные файлы (ADR-0092 п. 12): генератор
   «диалект → стандарт» остаётся только за меткой, правки идут в стандартные файлы руками.
2. **Разделы норм из стандартных файлов** (ADR-0087 п. 3 остаётся): построитель раздела «Форма» P/02.1, «Семьи данных»
   глав-владельцев, «Форма канонического вида» P/02.2 — из JSON Schema и `*.layers.tsv` (сейчас — `section.py`,
   `families.FamilySection`, `canonical.ViewSection` из `Form` диалекта). Новый модуль читает схему: `properties`,
   `required`, `default`, `description`, `x-owner`, `x-default-text`, правила `if/then`, `patternProperties` с
   `x-complement-of`, `x-*` слоёв. Текст разделов меняется (слова стандарта) — это правка норм п. 2.2, байты сверяет
   `check_spec`.
3. **`check_spec` на стек В7:**
   - корпус P/02.1 — `v7.stack.Manifest` со своим слоем 1 (`textv7`) вместо `form_source.judge.Loader`;
   - мутанты связей и `rows_coverage` (`--strict-coverage`) — по строкам CEL (`*.relations.json`): снятие строки
     меняет вердикт хоть одного случая;
   - проба мутаций `canonical` (снятие `default`, `x-ordered`, шага П1–П5 меняет байты вектора) — на `v7.project`;
   - каталог: колонка `schema` — `NN-<процесс>/data/<семья>.schema.json` (сейчас `families.SCHEMA_PATH` ждёт
     `.form.yaml`); `outcomes.tsv` — путь — место схемы (`place` по JSON Schema вместо `Form`);
   - переносимость `pattern` (п. 14): каждое `pattern` схем компилируется в RE2 (Go `regexp`, через `v7check`) и в
     ECMA-262 `u` (если на стенде есть node — иначе правило синтаксиса `regex.portable`);
   - самодостаточность схем: `$ref` вне `#/…` — красное; ни одна норма не ссылается на `common.schema.json`;
   - пакет `family-read` (п. 2.5) — проверка формы пакета, как у прочих векторов: таблица на каждого урока-владельца
     семьи каталога, каждая семья каталога — в своей таблице, `who` — по каталогу.
4. **Тесты навыка**: `test_form_source.py`, `test_families.py`, `test_canonical.py` переписываются на стек В7 (вход
   — стандартные файлы); `v7/test_v7.py` — как есть (34 теста, ловушки и D1–D18).
5. **Стенд в выгрузке**: `v7/requirements.txt` (хеши), `v7/go/go.mod`, `go.sum`, `VERSIONS.md` — в пин выгрузки
   (ADR-0083 доп. (37) п. 2; ADR-0092 п. 9): реализации ставят те же версии.

## 7. Вопросы плана — решения «Архитектора» (2026-10-27)

1. **Имена и места.** Каждый стандартный файл самодостаточен: копии нужных `$defs` из общего — внутри схемы, без `$ref`
   между файлами. Файлы лежат рядом с нынешним файлом диалекта того же базового имени: `<семья>.schema.json` в `data/`
   урока-владельца; манифест — `02.1-installer.schema.json`, `02.1-installer.relations.json` (CEL) и
   `02.1-installer.layers.tsv` в `spec/` урока 02. `common.form.yaml` — источник генератора до перехода, после —
   `common.schema.json` справочно (пп. 1.1, 2.1, 5).
2. **`diagnostics.tsv`** — остаётся подсказкой: раннер строго сверяет только вердикт и код выхода, строки диагностики —
   в отчёт без провала (ADR-0092 п. 5; пп. 2.3.4, 3.1).
3. **`family-read`** — весь набор, один пакет `Platform/common/vectors/family-read`, таблица на урока-владельца семьи
   (01–06 сейчас, 08–10 добавятся); «кто исполняет» — роли, пишущие и читающие семью по каталогу (п. 2.5).
4. **Эталона слоёв на Go в навыке нет**: курс не несёт кода реализаций; реализации пишут слои сами и проверяются
   `family-read` и корпусом; урок D18 — строкой в README пакета (пп. 2.5, 4.1).
5. **`requests.schema`** манифеста — вне В7 (ADR-0087 доп. (9) п. 7): остаётся проверкой своего подмножества.
