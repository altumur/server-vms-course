# Чеклист автора и ревьювера

У каждого пункта один результат: выполнено (с местом или проверкой), дефект (с контрпримером)
или неприменимо (с причиной). Чеклист не добавляет норм продукту: предмет проверки задают канон
и поручение. Находка вне пунктов допустима, если названы контрпример и нарушенный источник
(норма, ADR, стандарт). Стиль без нарушения источника — не находка.

Общие правила генераторов, судей, чисел, З-10 и пересылок — `decisions/0129-*.md`, доп. (26) «Действующие правила».

## Объём и источники

- [ ] Названы срез (коммит), уроки, документы и допустимые проверки. Известный долг записан
      отдельно от новых находок.
- [ ] Решения и нормы прочитаны; лекция и приёмка не стали источником нового требования.
- [ ] Лекция лежит в модуле, файлы с её префиксом — в общей `spec/`; состав без OpenAPI — по templates.md, Н2.
      Ссылки и словесные ссылки «урок N» верны.
- [ ] Перенос отделён от правки смысла; id норм и сценариев сохранены, новые номера не сдвигают старые.
      Снятая норма остаётся строкой «снята: `<ADR>`», её номер не переиспользуется; решение владельца, меняющее урок,
      записано в ADR дельтой по id (ADDED, MODIFIED, REMOVED, RENAMED; ADR-0080 доп. 6).
- [ ] В уроке нет кода реализации, даже цитатой: проход — псевдокодом на словаре хранилища P/01, выбор языка —
      «Решает реализация» (ADR-0080: код одного языка в норме — норма для одного языка).
- [ ] Повествование опирается только на уже введённые слова: пример или история из более позднего урока — одной
      фразой «чем это оборачивается — урок N», рассказ — в том уроке, где слова уже знакомы.
- [ ] Ссылка на более поздний урок называет интерфейс, на который урок опирается (операция, форма, ключ), а не только
      номер урока. Строка закрытого списка, добавленная другим уроком, помечена его номером. Ссылка на непереведённый
      модуль — долг с адресом в `ХОД-Спецификация.md`.
- [ ] Правило, которое реализация обязана исполнить, записано в норме словами: генератор реализации видит
      спецификацию, но не ADR (ADR-0080 доп. 16). Номера ADR в тексте M нет — это происхождение, его место — столбец
      `source` файла истории (решение «Архитектора» 2026-11-11 п. 2). Нарушение — исполнимое правило, которое есть
      только в ADR, таблице приёмки или другом источнике вне норм, или номер ADR вне надгробия (формы — после
      P01.176).
- [ ] В тексте M (нормы, формы, контракт, lifecycle, README урока, приёмки и векторов, общая приёмка) нет вставок
      происхождения: решений с датой, сверок реализаций, «moved from», номеров ревью, находок и прогонов. Происхождение —
      строкой `history-<K>.tsv` или `history.tsv` с адресом места; снятая вставка не унесла нормативный текст
      (ADR-0133 доп. (56) п. 3). Надгробие и «снята: `<ADR>`» — не история. Нарушение — вставка с местом или условие,
      пропавшее вместе со скобкой.
- [ ] Указатель главы полон для тем, разнесённых по нескольким местам, и не несёт тем одного места (абзац с
      несколькими правилами — одно место); каждый R-id указателя живой, адрес файла существует. Строк «See also» у
      требований нет (навигация — указатель). Новая норма темы внесена в указатель той же правкой. Нарушение —
      правило темы нескольких мест, которого нет в её строке, строка темы одного места или строка «See also».
- [ ] Страница «What this lesson takes from common» README урока называет каждый внешний файл и раздел, на который
      ссылаются файлы M урока; ссылки ведут на существующие якоря. У урока узкого M пары (`m_form.M_NARROW`) таблица
      — его список зависимостей: файл другого урока вне неё в M пары не входит, ссылку на него ловит `check_spec`.
      Нарушение — ссылка из M урока в common или другой урок, которой нет на странице.
- [ ] Раскладка требований — по уроку (SKILL.md, «Форма M для чтения»). У P/01 (ADR-0133 доп. (93)) один R-id
      открывает смысловой абзац одного наблюдаемого предмета, правил в нём может быть несколько; через заголовок,
      смену роли или режима, фазу и границу «Scope: production.» не сливают; каждое условие, предел и приоритет
      отказов исходного пункта есть в абзаце; слитый id — строкой карты `req-id-map.tsv` и истории, ссылки на него
      переведены. У остальных уроков, пока их задача не приняла абзацы, — одно требование — один пункт с id
      (доп. (61) п. 1). У всех значение YAML не несёт правил, YAML-блок — данные без прозы. Нарушение — абзац двух
      предметов или через границу, потерянное при слиянии условие, у урока с пунктами — два правила под одним id,
      правило внутри значения ключа.
- [ ] Нормы и приёмка платформенного модуля называют только учебные подсистемы `testsub` и `testsub2`. Механизм
      платформы, у которого пока один потребитель — подсистема VMS, получает потребителя в `testsub`/`testsub2`
      (ADR-0001, ADR-0080 доп. 4); подсистемы VMS в лекции — только как пример. Имена полей подсистем VMS
      допустимы как данные приёмки с объявлениями в самой приёмке, без ссылки на каталог VMS (`07/fields.yaml`).
- [ ] Правка данных спецификации: байты `testsub*` и общих таблиц `testdata/*.tsv` — по канону, правка записана
      долгом продукта в `ХОД-Спецификация.md`; файлы модуля консоли `Source/w2cplatform/console.{js,css,html}` —
      по его контракту (ADR-0005), тоже долгом продукта; манифесты VMS правятся только в каноне `VMS/<NN-sub>/` (ADR-0090
      доп. (6) п. 8); `Source/vms/*` — байты замороженного свидетеля, их не правит никто (доп. (7) п. 4). Нарушение —
      правка этих байтов без строки долга или любая правка `Source/vms/*`.
- [ ] Новое ограничение формы имеет свой id и входные случаи либо пункт «проверяется чтением»
      с причиной. Общий пункт «грамматика поля» не заменяет проверку каждой вновь суженной области.

## Нынешний формат без совместимости

- [ ] Норма, формы, данные, контракт и приёмка требуют только то, что пишет нынешняя реализация.
      Нет требований поддержки старых форматов, данных, состояний, миграций или прежних идентификаторов
      (`former ids`). Исторический документ не стал входом генерации (ADR-0129 доп. (12), З-10).
- [ ] Пределы чтения совпадают с пределами записи. Строка сверх предела получает существующий
      `unreadable`; нет специальных переходов, отказов или укорачивания ради старых состояний.
      Отрицательная проверка такого исхода не объявляется поддержкой старого формата.
- [ ] Область положительного профиля задана состояниями нынешних писателей. За её пределами не введён
      скрытый долг совместимости; полнота самого профиля и исполнение восстановления проверены отдельно.
- [ ] В отчёте названы проверяемый срез и места этого критерия: лишние требования перечислены находками,
      либо явно записано, что в проверенном объёме их нет. Старое ревью не заменяет новый критерий.

## Поля, значения, отказы

- [ ] Статическая грамматика выражена схемой: тип, обязательность, пустота, лишние поля, допустимые
      значения. Ограничения состояния, прав и байтового размера названы отдельно и не выдаются
      за проверку схемой.
- [ ] Каждая операция над значением (сравнение, сортировка, выделение номера, max, следующее имя,
      преобразование) определена на всей разрешённой области Н1. У частичной операции названы область
      и исход вне неё. Пробы включают нечисловые имена, равные выделенные числа, длинные значения,
      пустоту, отсутствие и близкие допустимые случаи. Область не сужена молча ради удобства операции.
- [ ] Для составного ключа измерен результат с префиксами и разделителями, а не только компонент.
      Отказ потребителя прослежен до исхода вызывающего, в том числе после частичной записи.
- [ ] Границы и близкие допустимые значения проверены (`..` и `..foo`, пустота, `null`, отсутствие,
      `true` и `false`); запрет не расширен случайно.
- [ ] Отсутствие, неверное значение и состояние «неизвестно» имеют разные исходы: ноль не заменяется
      умолчанием, неизвестное не подменяется соседним полем, пустой набор не попадает в min или деление
      без определённого исхода.
- [ ] Каждое допустимое значение входа представимо в обещанном ответе: конечность float, диапазон int,
      вложенные значения, default и inherit. Лексическое распознавание YAML не считается проверкой значения.
- [ ] Коды и поля сверены для конкретного входа и операции. Команда CLI, процедура и HTTP-маршрут
      не смешаны; общий набор кодов не заменяет сверку по операциям.
- [ ] Отказ возникает в описанной ветви; понятно, что уже изменилось, что осталось прежним и допустим
      ли повтор. Валидатор не меняет класс отказа: частная причина не становится общим `badrequest`.
- [ ] Совмещённые отказы идут в одном порядке у владельца двери и у использующих её уроков;
      конвейер проверок включает и общие, и специальные двери. Порядок проверок входа задан формой по образцу
      `forms/write-checks.tsv` (ADR-0133 доп. (61) п. 1), норма ссылается на форму и не пересказывает её. Нарушение —
      порядок, который реализация сводит из прозы нескольких мест.
- [ ] Формы Status, двери и метрик выбраны по цене: поле или серия, которые зависят от режима и роли, — строкой
      таблицы; текст остался там, где таблица дороже правила. Нарушение — ячейка таблицы или значение YAML, которое
      держит весь договор ответа.

## Права и секреты

- [ ] Исходные права, эффективные права после `never` и отрицаний и загруженный артефакт различаются.
      Неработающий положительный грант сам по себе не противоречие и не разрешение.
- [ ] У манифеста курса с `requests.elsewhere` и `rights.reach.requests` в схеме просьбы `requests.schema` есть поле
      `action`, иначе ветвь `elsewhere` недостижима (разбор ревью стадии B 6–7, №17).
- [ ] Опубликованная копия секрета в id, имени или другом выдаваемом поле считается выдачей секрета;
      проверены все источники значения и маскирование.

## Начальное состояние и повтор

- [ ] Для сценария известны прикладные данные, служебная память, права испытуемой роли и права подготовки.
- [ ] Повторный и параллельный прогон не наследуют состояние, влияющее на ожидаемые байты:
      пустота одного префикса не заменяет пустоту другого или памяти `id`.
- [ ] Наблюдение после отказа отличает отсутствие изменения от скрытой успешной записи.
- [ ] Повторы одного `id` с тем же и иным содержимым рассмотрены отдельно. Сроки памяти не подменены
      очисткой данных; HTTP-сценарий не объявлен проверкой памяти внутри процесса.

## Проход, гонки, сроки

- [ ] Проход с жизненным циклом и разными участниками задан таблицей Н3 по
      [templates.md](templates.md); общий запрет нельзя обойти другой ветвью, повтором или сменой
      состояния перед CAS. Разобраны обрыв составного перехода и неподтверждённый исход;
      таблица не обещает атомарности (ADR-0080 доп. 12).
- [ ] У каждого прохода есть применимые вмешательства и их исходы; «нет гонок» обосновано входами и действиями.
- [ ] Гарантия не сильнее механизма: получение допустимых байтов не доказывает неизменность файла
      во время чтения или атомарный снимок нескольких источников.
- [ ] Независимость памяти проверена способом, который может наблюдать общую память; сериализация
      через HTTP это свойство скрывает.
- [ ] Общая гарантия проверена на разных единицах и контроллерах: ёмкость, разнесение на одном сервере,
      группа, обрыв между записями, позднее снятие или добавление, неизвестный исход. CAS одной единицы
      не объявлен общим допуском; читатели и права согласованы с восстановлением. Нарушение — сценарий
      из этого перечня, где две единицы или два контроллера по норме получают несовместимый исход.
- [ ] У срока названы начальная точка (наблюдение) и условия. Основная строка и метка — разные
      публикации; обрыв между ними не получает придуманного срока восстановления. Повторный проход
      или продление не начинают новую льготу без явного правила.
- [ ] Часы писателя сдвинуты в обе стороны; отдельно проверены новый наблюдатель и позднее подтверждение.
      Стенное время не заменяет возраст версии на часах судьи или срок собственного запроса.
- [ ] Первое окно аренды проверено на границе и после задержки до запуска; повторы одной записи
      не обновляют начало. Отсечение до и после принятия запуска, позднее завершение и возврат имени
      не оживляют отменённую попытку; перезапуск по ревизии проверен.

## Установщик и пределы

- [ ] Установка начинается с определённой ревизии и условия CAS; последующие записи, конфликты
      и метка описаны до конца, включая остановку между записями.
- [ ] Успех загрузчика отделён от успеха установки: исходный YAML с комментариями может превысить потолок.
      Для отказа заданы выход команды, диагностика и отсутствие перехода к метке.
- [ ] У каждого предела названы единицы и состав измеряемого (байты ключа, вес элементов, полное
      HTTP-тело); поле `limit` относится к сработавшей границе.

## Вход двери

- [ ] Каждая HTTP-дверь урока ссылается на общий разбор запроса (урок 1 Н2.1) или называет своё отступление.
      Нарушение — дверь без ссылки и без отступления; проверить и путь с `/` на конце и пустым сегментом,
      повтор параметра, ранний отказ при недочитанном теле.
- [ ] Разбор query задан целиком: `+` и `%XX`, повтор параметра, его отсутствие, байты не UTF-8 после декодирования;
      у каждого случая определённый исход.
- [ ] Разбор тела задан целиком: повтор имени поля, одиночный суррогат, `NaN`/`Infinity`, BOM, глубина вложенности;
      у каждого случая определённый исход, вид отказа один для всех реализаций.
- [ ] Неизвестный метод, неизвестный маршрут и неразбираемый запрос HTTP отвечают кодом и формой из закрытого
      списка урока, а не кодом или страницей сервера по умолчанию.

## Двери и маршруты (OpenAPI)

- [ ] Каждый обещанный полный URL корня и монтирования выражен стандартными `paths` и `servers`
      своего владельца: подстановка переменных сервера плюс путь операции. Пояснение `x-mounting`
      или текст о префиксе URL не задают. `servers` на уровне пути не монтирует соседнюю общую дверь.
- [ ] Шаблоны путей с одинаковой иерархией и разными именами параметров не заводятся (OpenAPI 3.1,
      Paths Object). Вариант без параметра тоже имеет исход.
- [ ] Пространства имён корня и монтирования не пересекаются на всём каталоге; псевдоним не добавлен
      из пояснения или зарезервированного имени, если владелец его не объявил.
- [ ] Пары GET и HEAD согласованы по всему каталогу, включая скопированные страницы отказов.
- [ ] Каждая схема-объект говорит свою открытость: `additionalProperties: false` (закрыта), схемой (карта) или `true`
      с причиной в `description`; составная (`allOf`/`oneOf`/`if`) закрывается на себе `unevaluatedProperties: false`,
      её части, базы, на которые они ссылаются, и условия `not` открытость не говорят. Общий движок (судья) сверяет ответ с контрактом:
      несказанная открытость — лишнее поле проходит.

## Приёмка и доказательства

- [ ] Каждая норма имеет сценарий или пункт «проверяется чтением» с предметом, причиной и местом
      доказательства. Каждый сценарий проверяет существующую норму; совпадение результата
      не объясняется иной ветвью отказа.
- [ ] Ссылка файла M на конкретный файл, строку или сценарий вне M (`judge_only` в `forms/export.json` урока,
      `scenarios.tsv`, `seams.tsv`, `inputs/`, `*.cases.md`, `id-map.tsv`; файл другого урока вне узкого M пары)
      нужна и несёт «(judge-only: …)» в той же фразе; определение, нужное реализации, есть в M (ADR-0133 доп. (94)).
      Где ссылка снята, пометки нет, а условие из скобки сказано словами; R-id рядом с пометкой не повторяется.
      Нарушение — ссылка без пометки, ссылка, без которой норма однозначна, обязательная ссылка на закрытое
      определение или условие, пропавшее вместе со скобкой.
- [ ] Каждое требование с меткой «Scope: production.» проверяет боевая приёмка урока, а не функциональный сценарий;
      каждое MUST, которое текст ограничивает боевой квалификацией, несёт метку и свой R-id. Нарушение — оговорка «for
      production qualification» внутри абзаца без метки или метка у правила, которое судит функциональная приёмка.
- [ ] Вход Q (ADR-0130 доп. (20)): каждое обязательство боевого свойства стоит в M словами и полно без Q (условия,
      пределы, стадии и исходы); Q (`qualification/`) содержит только процедуры — группы случаев, бюджеты,
      измерения, пробы и долг проб, D7, окружение стенда, программу прогона, доказательства — и не вводит новой нормы,
      отказа, предела или исхода кандидата. Ссылка из M на Q несёт «(judge-only: …)» или снята. Фильтр
      `Platform/common/qualification-input-filter.json` называет все файлы Q и явные зависимости процедур, не весь M
      и не весь J. Нарушение — рецепт стенда в M, норма, которая живёт только в Q, или процедура без файла во входе Q.
- [ ] Параметры стенда заданы до запуска, и тест действительно достигает нужной ветви.
      Неподготовленный стенд не считается зелёным.
- [ ] Приёмка «любой реализации» выполнима без её внутреннего API: как движок (судья) получает изолированный
      экземпляр и как сверяет параметры стенда (поведением на границе ±1), названо; способ запуска реализация
      называет в «Решает реализация».
- [ ] Новая директива или дверь стенда (`@…`, имя двери) определена в словаре раздела «Стенд» README приёмки урока 1
      с номером урока, который её ввёл: общий словарь — `Platform/common/acceptance/README.md`, словарь модуля (его урок 1) — только новые слова модуля
      и ссылка на общий; README урока только ссылается на словарь.
- [ ] Необязательное поле не игнорируется без проверки: если оно есть, оно точное; лишние поля
      не допускаются; JSON-число не подменено строкой или булевым.
- [ ] Сравнение сохраняет значимый порядок; сортировка фактического ответа не скрывает его нарушение.
- [ ] Диагностика (пути, номера строк) проверяется отдельно от вердикта: для списка — полнота
      и отсутствие лишнего, для повтора — нужное вхождение.
- [ ] Границы проверяются на фактических байтах после подстановок; сериализация движком (судьёй)
      не меняет предмет проверки без явного правила.
- [ ] Неудачная попытка ожидания или сравнения не фиксирует новые переменные; разные порядки полей
      и повтор одной переменной проверены.
- [ ] Ожидание события — `@until` по наблюдаемому признаку (строка, ответ двери, запись журнала), не `@sleep`:
      шаг кончается, как только признак есть, а срок `@until` — верхняя граница. `@sleep` — только когда шаг
      проверяет, что за срок ничего не случилось (отсутствие события, неизменность строки), или норма требует
      прошедшего времени перед действием, а не перед наблюдением; длина сна — наименьшая, при которой нарушение
      успело бы проявиться (срок нормы плюс шаг цикла), и сон с причиной назван в README приёмки урока
      (ADR-0080 доп. (17) п. 4). Признак `@until` ложен в начале шага при любом допустимом порядке: не
      подмножество ожидания предыдущего шага по тому же запросу, база `@not(…)` связана после события-причины.
      Подтверждение кругом обмена — две смены отметки круга, связанной после события; круг не наблюдаем или
      проверка берёт ответ того же круга (`@carry`) — сон с причиной. Сон-длительность (N продлений) — N событий.
- [ ] Сигнал процессу подаётся после полного подтверждения нужного состояния, а не промежуточной записи;
      контроль ожидания снимается после выхода процесса.
- [ ] Сгенерированные случаи сверены целиком: общий фон, типы YAML-скаляров и положительные контроли,
      а не только целевая мутация.
- [ ] Порядок отказов: у каждого перечня «по порядку» (Н2, Н3) есть шаги с двумя ошибками сразу — для каждой
      соседней пары (N, N+1), достижимой одним запросом или входом, ожидание — отказ N. Шаги по одной ошибке
      порядка не проверяют (мутации М11, прогон 41).
- [ ] Границы констант и пределов проверены с обеих сторон: на самой границе и на шаг за ней (сроки, размеры,
      счёты, длины). Одна сторона или далёкая точка не отличает `<` от `<=`.
- [ ] У каждой проверки подписи, записи, срока, отпечатка или права есть отрицательный шаг: подделка, чужой ключ,
      просроченный элемент цепочки, неподписанный документ не принимаются. Счастливый путь проверку не доказывает.
- [ ] Ожидание не слабее нормы: где норма называет тело, значение или первое значение счётчика, шаг сверяет их,
      а не голый статус или `@any`; ожидание срока короче соседнего срока, который дал бы тот же итог иначе.
- [ ] Счёт сценариев, шагов, вердиктов, диапазоны id и номера сценариев в Н5, README приёмки и инструкции
      совпадают с фактическими таблицами. Это единственное место правила о счётах; формы, которые сверяет скрипт,
      названы в [validation.md](validation.md), остальные («N HTTP-шагов», «N автоматических») сверяются вручную.
- [ ] Для необязательной возможности проверяются условия выбранного варианта; слово МОЖЕТ само по себе
      не дефект. Отступление от СЛЕДУЕТ оформляется по Н0.

## Лекция и инструкция

- [ ] Лекция объясняет причину и пример и не обещает больше нормы; её таблицы, перечни, условия и пороги
      (включая «и»/«или») соответствуют текущему канону. Лекция согласована при каждой смысловой правке, но не копирует
      норму целиком: нарушение — утверждение лекции, которое расходится с нормой того же среза.
- [ ] Инструкция содержит разделы шаблона: приоритет входов, глоссарий (если в нормах есть слово с несколькими
      значениями), что создать, порядок работы, ловушки языка, «Готово, когда», «При расхождении» (ADR-0080,
      дополнение 2026-10-15 «форма урока — лекция и `spec/`»).
- [ ] Инструкция позволяет начать реализацию без угадывания входов и подготовки: догадка чистой комнаты
      о видимом снаружи поведении (ADR-0080 доп. 15–16) — дефект инструкции или нормы. Примеры внутреннего
      устройства не стали обязательными сигнатурами, типами ошибок, функциями или HTTP-маршрутами.
- [ ] Названы ограничения проверок: чтение документов, проверка схем, запуск реализации и стенд —
      разные результаты.

## Самостоятельный профиль приёмки (З-16)

- [ ] По README приёмки урока и единому английскому формату в `Platform/common/acceptance/`
      реализация пишет собственный профиль без догадок: названы нужные ключи стенда и назначение каждого,
      команды, обязательные флаги и адаптеры, их входы/выходы и условия применения. Конкретные имена
      своих исполняемых файлов выбирает реализация; готовый профиль и внутренний README раннера не стали посевом.
- [ ] Общая форма описана один раз; урок не копирует её. Недостающее назначение ключа или обязанность запуска
      исправлены в README приёмки этого урока в рамках его обычного ревью/правок, с точным местом и примером
      неразрешённой догадки. Для P/01 и P/02 пункт включён в их текущие ревью/исправления.
- [ ] Отдельный проход по всем урокам ради этого пункта не назначался. Чтение формы, проверка профиля,
      запуск стенда и исполнение реализации названы раздельно; публикация договора не объявлена их PASS.

## Отчёт ревьювера

- [ ] Находки сгруппированы по урокам или по файлам предмета ревью; короткая сводка называет блокеры.
- [ ] У каждой находки есть серьёзность по шкале ниже, место `файл:строка`, точная цитата, контрпример,
      нарушенный источник и последствие. Цитату и пробу ревьювер берёт из файла и запуска, а не пересказывает.
      Находку без проверяемого места автор не принимает (ADR-0080 доп. 14).
- [ ] Одна причина — одна находка; в отчёте не больше 40 находок. Несогласие с ADR оформлено находкой
      «урок расходится с ADR-NNNN», а не предложением менять ADR.
- [ ] Находка, которая меняет решение «Архитектора» или общую таблицу `Source/tests/testdata/*.tsv`,
      помечена как вопрос «Архитектору», а не как требование правки.
- [ ] «Новых находок нет» относится только к проверенному срезу и охвату; отложенный долг
      и второй ревьювер не закрываются автоматически.

**Шкала серьёзности.**

- **Блокер** — норма невыполнима или противоречит себе; две реализации, следующие канону, расходятся
  в наблюдаемом поведении на допустимом входе; приёмка отвергает верную реализацию или принимает
  потерю данных, двойную выдачу ресурса либо выдачу секрета.
- **Существенная** — расхождение норм, контракта, приёмки или уроков, которое старшинство источников
  разрешает однозначно, но реализация по младшему источнику ошибётся; пропущенный исход в Н4;
  сценарий не достигает своей ветви.
- **Мелкая** — текст, ссылка, счёт, оформление или лекция без изменения наблюдаемого поведения.

Дефект скрипта проверки — не находка ревью спецификации (см. [SKILL.md](../SKILL.md)).

Автор может понизить серьёзность с причиной в общем ответе.
