# Таблица связанных изменений

Выбери строки по смыслу правки. Столбец «Где искать» — адреса проверки, а не требование
дублировать текст. Как записать результат и проверить класс ошибки — шаги 2, 4 и 6 в
[SKILL.md](../SKILL.md); что проверять в каждом месте — [чеклист](review-checklist.md).

| Что меняется | Где искать связанные правила | Что должно остаться согласованным |
|---|---|---|
| Поле, тип, грамматика, обязательность | Н1; входная схема Н2; чтение и выдача поля в Н3; Н4; данные приёмки | Один набор допустимых значений; тип, пустота и отсутствие различаются; байты не заменены числом символов |
| Причина отказа и наблюдаемый результат | Ветвь Н3 или транспорт Н2; строка Н4; вход или маршрут контракта; действие вызывающего | Для причины определены код, поля, изменение состояния и возможность повтора |
| Поля ответа | Н1, Н2; место формирования в Н3; Н4; правило сравнения в README; ожидания приёмки | Обязательность, единицы и смысл поля одинаковы; лишние поля не скрыты общим игнорированием |
| Поведение, порядок, точка публикации | Н3; гонки; сроки; лекция; Н5 | Гарантия следует из названных операций; отсчёт срока привязан к наблюдаемому событию |
| Допуск участника и переход состояния | Таблица Н3; все ветви выбора; перечитка перед CAS; повтор и возврат; Н5 | Общий запрет действует во всех ветвях; составной переход имеет определённый исход обрыва |
| Операция над допустимым значением | Область Н1; сравнения и преобразования Н3; генерация имён; потребители результата; Н5 | Операция определена на всей объявленной области; у частичной названы область и исход вне неё |
| Повтор и память идентификаторов | Н1 идентификатора; успех, отказ и повтор в Н3; гонки; начальное состояние приёмки | Повтор сравнивает нужное содержимое и не добавляет изменения; очистка строк не объявлена очисткой памяти `id` |
| Подготовка и изоляция приёмки | Н5; README приёмки; зависимости сценариев; инструкции раннеру | Названы начальные данные, права, память, время и параметры; повторный или параллельный прогон не получает чужое состояние |
| Предел или способ измерения | Н1, Н2; Н4; «Решает реализация»; параметры Н5; байты запросов и ожиданий | Известны единицы, состав, граница равенства и место проверки; тест достигает нужной ветви |
| Диагностика | Н4; исходный файл; ожидания диагностик; правила сравнения | Вердикт не выдаётся за проверку сообщения; пути и номера проверяются явно |
| Установка и составная запись | Н3 по каждой записи; конфликт и отказ; гонки старта и чтения; Н4; Н5 | Начальная ревизия, CAS, отставшая метка и обрыв описаны; вход, допустимый загрузчику, может не поместиться при установке |
| Выбор реализации | «Решает реализация»; README реализации; условия совместимости | Наблюдаемое поведение не превращено в выбор; внутренний API не стал обязательным из примера |
| Перенос, переименование, ссылка или копия схемы | Входящие ссылки; Н2; приёмка; владельцы копий; карта модуля | Один опубликованный канон и устойчивые id; зависимая копия синхронизирована или оформлена дельтой |
| Число между YAML, строкой и JSON | Лексика и проверка значений Н3; default и inherit; схема ответа; диагностика | Каждое допустимое значение представимо в ответе; пределы int и float, bool и нечисловые значения различаются |
| Общий допуск и составное решение | Все писатели общего состояния; CAS и guard; восстановление; читатели решения; права и зарезервированные пути | Остаток ёмкости не расходуется дважды; группа принимается целиком; неизвестный исход не разрешает продолжать старый план |
| Часы и истечение | Начальная точка наблюдателя; продление; окно писателя; тесты времени | Смещение часов писателя не меняет возраст наблюдаемой версии; поздний ответ не продлевает срок запроса |
| Запуск и отсечение | Выдача эпохи; первое окно аренды; все запуски, включая по ревизии; потеря и возврат имени; Н5 | Поздний ответ не продлевает первое окно; отменённая попытка не оживает; принятие запуска упорядочено с отсечением |
| Переменные ожидания приёмки | README раннера; код ответа; полное сравнение; повтор ожидания | Привязки фиксируются только после полного совпадения |
| Список имён, норм или сценариев | Все перечни, счёты и диапазоны id в Н5, README приёмки и инструкции; потребители списка | Каждый потребитель видит новый элемент; счёт — по пункту «Счёт…» чеклиста |
| Данные спецификации (`testsub*`, общие `testdata/*.tsv`, манифесты `Source/vms/*.yaml`, файлы модуля консоли) | Продукт (`sync-course.sh`); выгрузка `cammeta-specs`; копии в `cases/` урока 2; старый Python читает их на закреплённом срезе | По пункту чеклиста «Правка данных спецификации» |
| Форма манифеста подсистемы (P/02.1 Н1.1–Н1.4) или корпус главы 2.1 | Источник формы `Platform/02-installer/spec/02.1-installer.form.yaml` с `.references.tsv` и `.scalars.tsv` (ADR-0087; пара схемы ADR-0085 снята); `verdicts.tsv`, `classes.tsv` | `check_spec` прогоняет корпус через источник формы без расхождений, `--strict-coverage` — покрытие правил; источник правится той же правкой, что норма, и идёт в выгрузку |
| Генерация случаев приёмки или библиотека YAML | Весь фон входа; типы скаляров; положительные контроли; целевые причины отрицательных случаев | Меняется только целевая мутация; фон и контроли остаются верными |
| Префиксный маршрут или монтирование | Полный каталог имён; корень и монтирование; `servers` и `paths`; коды GET и HEAD; владельцы общих дверей | Полный URL выражен стандартными полями; пространства имён не пересекаются |
| Публичный идентификатор | Все источники его значения; маскирование; права на чтение | Секрет не попадает в id, имя или другое выдаваемое поле |
| Разделы Markdown | Уровни заголовков; положительные и отрицательные документы | Проверяется фактическая область раздела; примеры в коде не становятся нормами |
