# Механическая проверка после ручного чеклиста

Скрипт только читает документы и данные из корня репозитория. Код реализаций не импортируется,
приёмочные запросы не выполняются, контракты из сети не загружаются. Что проверять вручную —
[чеклист](review-checklist.md); этот файл описывает только границы инструмента.

```sh
# окружение — одно, закреплённое с хешами: skills/lesson-spec/scripts/requirements.txt (стек В7 и пакеты check_spec)
ENV="uv run --no-project --python 3.12 --with-requirements skills/lesson-spec/scripts/requirements.txt"
# все уроки курса (Platform/lessons.tsv) — без аргументов; итог не зависит от маски оболочки
$ENV python skills/lesson-spec/scripts/check_spec.py [--strict-coverage]
# source-proof: полный checkout курса на exact SHA из обеих вложенных меток выгрузки
COURSE_SOURCE=/home/pilot/<exact-course-checkout>
$ENV python skills/lesson-spec/scripts/check_spec.py --root "$COURSE_SOURCE" \
  --exceptions "$COURSE_SOURCE/skills/lesson-spec/exceptions.tsv" \
  --cyrillic-debt "$COURSE_SOURCE/skills/lesson-spec/cyrillic-debt.tsv"
# export-proof: отдельная копия реестра того же source SHA; исходный реестр не меняется
EXPORT_TREE=/home/pilot/<export-checkout>
EXPORT_DEBT=/tmp/<owned-export-debt.tsv>
cp "$COURSE_SOURCE/skills/lesson-spec/cyrillic-debt.tsv" "$EXPORT_DEBT"
$ENV python skills/lesson-spec/scripts/check_cyrillic.py --root "$EXPORT_TREE" \
  --debt "$EXPORT_DEBT" --export --shrink
$ENV python skills/lesson-spec/scripts/check_cyrillic.py --root "$EXPORT_TREE" \
  --debt "$EXPORT_DEBT" --export
```

`check_spec --root` принимает **полный источник курса**, по умолчанию текущий каталог; `--exceptions` — реестр
(по умолчанию `exceptions.tsv` навыка). `--root <export>` явно даёт FAIL: выгрузка `Platform/` + `VMS/` не содержит
`decisions/history/platform/id-map.tsv`, журналов и замороженных свидетелей. Отсутствие или порча карты в source
остаётся ошибкой; нет отката к старому пути, пустой карте или пропуска history-проверок. Историю не нужно добавлять
в выгрузку. Без аргументов проверяются все
уроки `Platform/lessons.tsv`, у которых есть лекция; аргументы — отдельные уроки (частичный прогон: число
исключений у него своё). Окружение сверяется с `scripts/requirements.txt` первым делом: пакет не установлен или
не той версии — ошибка `environment: <пакет> …, pinned …` с командой установки, а не пропуск проверки; итог
одного дерева в любом окружении — один. `regress` — для [схемы формы](#схема-формы-манифеста-adr-0085) (ADR-0085):
пары ADR-0085 нет ни у одной главы курса, но её проверку держат тесты скрипта.

Для root GATE нужны **оба** доказательства на одном exact SHA курса:

- Source-proof: полный checkout (Git HEAD, отсутствие правок проверяемых файлов и используемый код судьи записаны
  в отчёт) на SHA из `Platform/COURSE_COMMIT` и `VMS/COURSE_COMMIT`. Обычный полный `check_spec` с его реестрами,
  строгой картой истории и журналами; сохраняются отдельные счётчики active corpus `verdicts=947`,
  `canonical_vectors=220`, `numeric_loader_cases=9`, `id_map_ids=532`. Числа относятся к назначенному current joint;
  новый срез требует собственного отчёта, а не наследования PASS.
- Export-proof: равные метки — каждая ровно 40 строчных hex-цифр и один LF; корневого `COURSE_COMMIT` нет.
  Они связывают выгрузку с source-proof, но сами не доказывают содержимое. Root GATE независимо сверяет **весь**
  retained roster из Git exact source с экспортом: каждый путь, mode/type/blob, длину и SHA-256 фактических байтов;
  отсутствие, добавление, подмена и утечки за пределы разрешённого состава — FAIL. В составе только `Platform/**`
  и `VMS/**` без человеческих `ru/` и истории, плюс две созданные оператором вложенные метки. `Source/`, корневые
  записки/псевдонимы, exporter README и прежние debt-файлы не экспортируются. Отдельно выполняется полный судья
  кириллицы с `--export`. Пустой каталог с двумя метками не является успешным export-proof.

Эти два отчёта и точные команды/хеши сохраняет coord103 в root GATE. Кириллический судья не заменяет проверку
retained roster, а `check_spec` не выдаёт усечённый PASS для выгрузки. Пути и ссылки судятся по канону:
`Platform/common/NORMATIVE-TERMS.md`, `Platform/07-console-module/CONSOLE-MODULE.md` и ровно два
`Platform/common/data/testsub/testsub{,2}.subsystem.yaml`. Старые копии `Source/` — неизменяемые свидетели,
а не резервный вход. Перенесённый legacy-корпус — отдельная структурная сверка индекса
`Platform/02-installer/acceptance/1/spec_verdicts/spec_verdicts.tsv`: без заголовка, две колонки `case/verdict`,
138 строк/файлов (19 `ok`, 119 `refused` на назначенном срезе). `legacy_spec_verdicts` не входит в `verdicts`,
не заменяет active corpus 947 и сам по себе не доказывает поведение загрузчика.

## Кириллица в источнике и выгрузке — ADR-0121 доп. (8)

Каждый вызов `check_spec`, включая выбор отдельных уроков, отдельно запускает
`scripts/check_cyrillic.py`. В **курсе** проверяются весь `Platform/**` и принятая часть `VMS/**` (ADR-0083 доп. (128)); `tools/normgen/**` заморожен и не судится, его тесты не обязательны (ADR-0125 доп. (14), `check_cyrillic.FROZEN_SOURCE`).
Перенесённые записки, testsub и корпус теперь входят в `Platform/**`; `Source/` — замороженный свидетель.
Для работы судьи скрипт экспорта не требуется и не запускается.
В SOURCE-режиме Git читаются отслеживаемые файлы текущего дерева (включая добавленные
в индекс); неотслеживаемый файл нужно сначала добавить в индекс. В EXPORT-режиме
всегда обходится дерево на диске, независимо от наличия Git: учитываются untracked,
ignored, скрытые файлы, новые каталоги и данные в `__pycache__`. Локальные метаданные
`.git` в корне проверяемого дерева не читаются: ни каталог, ни файл ссылки Git worktree.
Одноимённые файлы и каталоги внутри данных исключением не являются. Git-free SOURCE-фикстуры
сохраняют прежний обход канонических каталогов без `.git` и `__pycache__`.
Файлы читаются как байты без исполнения; символические ссылки и специальные файлы — ошибка.
Невалидные байты UTF-8 не скрывают корректно закодированные кириллические буквы рядом с ними.

**Выгрузка** распознаётся по любой существующей или отслеживаемой вложенной метке
`Platform/COURSE_COMMIT` / `VMS/COURSE_COMMIT`; старый корневой маркер тоже включает полный охват, но даёт FAIL:
в ней проверяется **каждый файл**, а не белый список имён — в том числе корневой
`README.md`, `.gitignore`, метаданные и любой новый дом. Удаление отслеживаемого
вложенной метки не сужает охват. Для каталога без маркеров обязателен явный
`check_cyrillic.py --export`: отсутствие обоих маркеров в этом режиме — FAIL.
Обычный `check_spec --root <выгрузка>` — FAIL контекста source-proof. Наличие старого README, дополнительных
каталогов и скрытых файлов не сужает обход: новый состав проверяет отдельное доказательство roster.

Постоянных исключения два: человеческие зеркала `Platform/ru/**`, `Platform/common/ru/**`,
`Platform/NN-*/ru/**` и соответствующие `VMS/ru/**`, `VMS/common/ru/**`, `VMS/NN-*/ru/**`; **ячейки данных** колонки `ru` точного файла
`Platform/07-console-module/data/localization.tsv`. Заголовок последнего обязан однозначно
называть `key`, `en`, `ru`; обычный и `# `-заголовок допустимы, порядок колонок не важен.
Комментарии, остальные колонки и неоднозначная форма не получают исключения.
Произвольный вложенный `ru/` зеркалом не считается.
Журналы, HTML, комментарии кода и строки в кавычках проверяются как остальной текст.
Оговорки проверки **пар** `en_mirror` ниже не отменяют эту отдельную проверку.

Буква — `Script=Cyrillic` и `General_Category=L*` по закреплённому
[Unicode 17.0.0 Scripts.txt](https://www.unicode.org/Public/17.0.0/ucd/Scripts.txt):
449 символов, диапазоны и SHA256 источника в скрипте. Знаки и комбинируемые диакритики
без категории буквы не считаются; результат не зависит от базы Unicode установленного Python.
Судья проверяет буквы в содержимом файлов, не качество перевода и не язык смысла.

Единственный список готовности и переходного долга — `skills/lesson-spec/cyrillic-debt.tsv`:
`kind<TAB>path<TAB>letters`, строки `debt` с положительным числом букв **по файлу** и
`ready` с каталогом и `-`. Исходный долг снят с `ae526056c`; ни P/01–P/05, ни `common`
в нём ещё не объявлены готовыми: в их журналах и других файлах осталась кириллица.
Новая кириллица и увеличение любого файла — FAIL, в том числе до готовности.
Уменьшение или исчезновение старого долга — FAIL с требованием сократить реестр.
Это не заморозка содержания: замена текста с тем же числом букв не доказывает корректности перевода.
В готовом каталоге долг запрещён; объявленный каталог должен существовать и быть чистым.
Долг не добавляется к числу исключений `check_spec`: отдельные счёты `cyrillic_debt_files`,
`cyrillic_debt_letters`, `cyrillic_ready`, `cyrillic_scanned_files`, `cyrillic_non_utf8`.

```sh
# Обычная проверка ничего не записывает
python skills/lesson-spec/scripts/check_cyrillic.py
# После перевода: только снижение/удаление старых строк; новый долг блокирует запись
python skills/lesson-spec/scripts/check_cyrillic.py --shrink
# После сдачи доли: сокращение долга и объявление чистого каталога готовым
python skills/lesson-spec/scripts/check_cyrillic.py --ready Platform/01-store
```

Изменение долга/готовности коммитится вместе с переводом; готовность не снимается при shrink.
Режима создания или увеличения долга нет: отсутствующий/невалидный реестр — FAIL,
запись выполняется атомарной заменой только после успешной проверки всего охвата.
Для другого среза передайте его реестр `--cyrillic-debt` в `check_spec` (`--debt` в отдельном судье).
Выгрузка исключает журналы и другие файлы курса: для её проверки нужна отдельная **копия** реестра
того же SHA обеих вложенных `COURSE_COMMIT`, сокращённая `--root <выгрузка> --debt <копия> --shrink`.
Сокращение копии не изменяет реестр курса; новый долг в выгрузке по-прежнему запрещён.
VMS проверяется в курсе и выгрузке без русских UI-исключений: приняты V/01–V/10, V/12 и common.
Новый файл, скрытый каталог или новый дом внутри VMS не выпадает из контроля.
Весь `VMS/11-backend/**` явно исключён из текущей поставки, а не объявлен прошедшим.
Единственная отложенная карта `VMS/common/id-map.tsv` остаётся на прежнем каноническом пути:
судья допускает только точные исторические байты SHA256
`051e5dd75360a2645e0f1035a0c745d6e688175ca8436b0597683fcaa33048b0`
из source/data-base `2a197ab0a5eeb155b31fc3bd2d13c9d295aacb59`, в обычном файле без symlink.
Добавление или изменение любых байтов даёт FAIL, в том числе при `--shrink`; нового бюджета нет.
В source отсутствие карты по-прежнему даёт FAIL проверки VMS; если экспорт не несёт историю,
это не требует добавлять в него карту. Копия на новом пути не подменяет канон.
Метки `--ready VMS` и `--ready VMS/common` запрещены, поскольку включают отложенный остаток.
Готовность всей VMS и V11 не выводится из готовности принятого подмножества.
Новой `VMS/common/localization.tsv` и исключения для неё нет. Канонические байты нового модуля
`Platform/07-console-module/module/console.{js,css,html}` проверяются целиком, включая строки и комментарии.
Замороженные файлы `Source/w2cplatform/console.*` не являются каноном или исключением выгрузки.
`cyrillic_export=1` в COUNTS обозначает полный охват выгрузки.
Расширение охвата само не создаёт нового долга: кириллица в новых путях даёт FAIL,
в том числе при `--shrink`; словарь долга автоматически не увеличивается.

Разовое решение ADR-0083 доп. (114) отдельно закрепило начальный долг **ровно 38**
файлов нового охвата `CONSOLE-MODULE.md` / `Source/tests/testdata`: 13843 буквы.
Старые 671 записи / 590257 букв не изменены; итог checkpoint — **709 / 604100, ready 0**.
Точные пути, исходные SHA256 и доказательство сохранности старых строк —
[свидетельство checkpoint](../../../decisions/inbox/ревью/ПРОВЕРКА-судьи-кириллицы-bootstrap38-Codex.md).
Это одна фиксация в истории Git: режима bootstrap/reset в программе нет, последующий
новый долг и рост запрещены, дальнейшее сокращение — только `--shrink`.

**Урок модуля «Платформа»** (`Platform/`, ADR-0083) — тот же вызов с путём лекции:
`check_spec.py Platform/01-store/ru/01-store.md` (все — без аргументов). Нормы — по главам `spec/NN.K-<процесс>.norms.md` (id `P/NN.K-MM`;
у урока без глав — `spec/NN-<процесс>.norms.md`, id `P/NN-MM`); каждая глава проверяется как урок: Н0–Н5, чеклист,
«Данные», своя приёмка `acceptance/K/` (набор таблиц — ниже). Одна инструкция `spec/NN-<процесс>.README.md`
и один OpenAPI на урок. Счёты лекции и инструкции — суммы по главам. Ключ реестра — `P/NN`, значение
`acceptance-entry` — `K/имя`. Рядом с главами `acceptance/K/` урок с главами держит только **каталоги стендов**
`acceptance/<стенд>/` (`<стенд>` — `[a-z][a-z0-9-]*`, не номер): каталог стенда законен, когда элемент столбца
`acceptance` какой-либо строки `forms/targets.routing.tsv` (урока или общей) — `Platform/NN-<процесс>/acceptance/<стенд>`
или путь внутри него, например `PASS/stand<TAB>run<TAB>["Platform/06-console/acceptance/pass"]<TAB>all<TAB>[]<TAB>[]<TAB>whole`; каталог без
такой строки — ошибка, строка без каталога (или у урока без глав) — ошибка в строке реестра; число принятых — счёт
`acceptance_stands`. Содержимое стенда — по его README и цели реестра; набор таблиц глав к нему не применяется. Иной файл
или каталог рядом с главами — ошибка. У VMS каталогов стендов нет. Стенд директив — `Platform/common/acceptance/README.md` и словарь README урока 1 модуля. У главы с корпусом урока 2 — пара схемы ADR-0085 (`spec/NN.K-<процесс>.schema.yaml`, `.references.tsv`) до
перехода, после — [источник формы](#источник-формы-манифеста-adr-0087); оба у одной главы — ошибка.

**Модуль VMS** (`VMS/`, ADR-0090 доп. (1), (2)) проверяется при каждом вызове, если каталог есть: таблицы
`VMS/common/lessons.tsv` (`# lesson<TAB>dir<TAB>title<TAB>subsystem<TAB>status`; статус `translated` | `not translated`),
`VMS/common/data/catalog.tsv` и `VMS/common/id-map.tsv` (заголовки как у `Platform/common/`); у каждого урока есть
каталог `VMS/NN-<имя>/` и, если названа подсистема, манифест `<subsystem>.subsystem.yaml` в нём; каждый манифест
`VMS/*/` — в каталоге урока, которому его отдаёт `lessons.tsv`. Счёты `vms_lessons`, `vms_manifests`,
`vms_table_rows`. Байты `Source/vms/` заморожены со старта (доп. (7) п. 4): каждый файл там (кроме кешей байткода) —
в списке `tools/vms-boundary/source-vms.sha256` с тем же sha256, других файлов нет (счёт `vms_frozen`); без списка
(выгрузка) — не проверяется.

**Урок модуля VMS** — тот же вызов с путём лекции: `check_spec.py VMS/01-cam/ru/01-cam.md`; разбор — как у урока
«Платформы» (главы `spec/NN.K-<имя>.norms.md`, приёмка `acceptance/K/`, одна инструкция, OpenAPI или строка
`no-openapi`), с отличиями: id `V/NN.K-MM`, ключ реестра `V/NN`; урок — строка `VMS/common/lessons.tsv`; id-map —
`VMS/common/id-map.tsv`; «Данные» — по каталогу платформы (общие семьи `<sub>/…`); проверок процесса платформы
(`lessons.tsv` process/unit, роли процесса в каталоге, канон урока 2) нет; стенд директив — ещё
`VMS/common/acceptance/README.md`, если он есть. **Глава-заглушка** — строка `**Статус: ждёт решения запроса**` и ссылка
на существующий `decisions/inbox/<дата>-запрос-vms-<тема>.md`: разделы Н0–Н5 есть, чеклист пуст, приёмки нет; заглушка с
id чеклиста — ошибка (строка статуса уходит с первой нормой), без ссылки на запрос — ошибка (счёт `vms_stub_chapters`).

## Итог

- Код 0 и строка `PASS` — описанные структурные проверки пройдены.
- Код 0 и строка `PASS with N exceptions` — пройдены, кроме отступлений из реестра; каждое напечатано
  строкой `EXCEPTION` с причиной.
- Код 1 и строка `FAIL` — найдены дефекты или неподдержанный формат. Неполная проверка даёт `FAIL`, а не `PASS`.
- Код 1 и `Missing dependency…` без строки `FAIL` — нет зависимости; это не пропуск успешной проверки.
- Код 1, `FAIL` и ошибка `environment: …` — окружение не то, что закреплено в `scripts/requirements.txt`: пакета нет
  или версия иная; проверка не пропускается, результат прочих проверок в таком окружении не засчитывается.
- Код 2 — неверные аргументы командной строки.

## Реестр исключений

[`exceptions.tsv`](../exceptions.tsv) называет разрешённые отступления (ADR-0080 доп. 14): урок
(`модуль/NN`), вид, значение и причину. Виды:

- `no-openapi` — у урока нет своего контракта по ADR; проверка OpenAPI пропускается;
- `scenarios-format` `own` — свой формат `scenarios.tsv` (директивы `@…`, ожидание кода без тела): общая
  грамматика запроса и ожидания не применяется, приёмка проверяется по своему README; число столбцов
  и нумерация шагов проверяются и у своих форматов;
- `acceptance-entry` — дополнительный файл в каталоге приёмки, например таблицы урока 7;
- `no-acceptance` — у урока нет своей приёмки (вся перенесена или библиотека в браузере); каталог приёмки рядом
  делает строку устаревшей;
- `no-schema` — строка каталога (`row`, `object`) без `schema`, которую читает или пишет процесс перенесённого
  урока: урок — `owner` строки, значение — `key`, причина — строка долга (ADR-0083 доп. (11)). Строка
  устаревает, когда у строки появилась `schema` или её не касается ни один перенесённый урок;
- `data-paragraph` — урок `P/NN`, значение — `key` строки каталога: снимает для этой строки требование «туда»
  сверки «Данные» по ролям процесса; строка устаревает, когда абзац снова согласован с каталогом.

Строка реестра для проверяемого урока, которой урок не воспользовался (контракт появился, файл удалён,
общая грамматика проходит, файл и так поддержан), — ошибка: её снимают в той же правке. Новый файл приёмки
автор присылает «Архитектору» вместе со строкой реестра до своего коммита, и оба коммита идут подряд:
иначе main краснеет на `unsupported acceptance entry`. Счёт и сверка счётов работают и для своих форматов;
строка заголовка в счёт не входит.

## Раскладка урока (ADR-0124)

Скрипт понимает обе раскладки на время переноса (доп. (1) п. 6): урок (или `common/`) с каталогом `ru/` — новая, без —
прежняя ADR-0121. Корень курса и каталог модуля с `ru/` — мелкие дома: пара — свой файл `X` ↔ `ru/X`
(`НОРМАТИВНЫЕ-СЛОВА.md`, `КОНСОЛЬ-МОДУЛЬ-ПЛАТФОРМЫ.md`, `VMS/README.md`), прочие файлы рядом не судятся как пары.

| Проверка | Граница результата |
|---|---|
| Пары `X` ↔ `ru/X` (`en_mirror`): у каждого источника есть перевод с шапкой «производный от `X`, руками не правится»; в `ru/` без источника — только лекция; разделы, номера норм, id чеклиста, числа, коды, слова отказов, цели ссылок (`ru/Y#русский` ≡ `Y#английский` по парам заголовков) — те же; кириллица в источнике — только в `code`, «…», номерах `Н…` и именах файлов | Смысл перевода — вручную |
| Источник не ссылается в `ru/` и `journal/` ссылкой Markdown (их нет в выгрузке): лекцию называют текстом | Ссылку текстом скрипт не судит |
| Формы ADR-0120 — в `forms/`, не в `data/`; журналы Platform и принятой VMS — `decisions/journal/{platform,vms}/<урок>/corrections-<глава>.tsv`, исключённый V11 — прежний `VMS/11-backend/journal/`; отсутствие нового журнала не включает откат на старый путь | — |
| Якоря ссылок `#…` — заголовки цели, как их строит GitHub (у источника заголовки английские) | — |

**Временно (ADR-0124 доп. (1) п. 6; замечание М2 ревью пилота):** проверки норм (Н0–Н5, чеклист, «Данные», счёты,
семьи) у перенесённого урока читают перевод `ru/X` — их слова пока русские. Источник `X`, который читает модель,
они видят только через сверку пары `en_mirror`; поэтому правка нормы идёт в источник и в перевод одним коммитом.
Проверки переходят на источник после переноса всего курса (вместе с `VMS/common`) — отдельной правкой навыка.

- **`qualification_refs`.** Файлы Q — источники Q дерева (файлы git, вне git — обход каталога); перевод файла Q судится

## Каталог ⊆ права (ADR-0083 доп. (6))

`scripts/catalog_rights.py --catalog Platform/common/data/catalog.tsv --rights <файл прав> --manifest <манифест>…` проверяет,
что каждую операцию каждого участника каталога (строки хранилища) и каждое чтение читателя разрешает файл прав,
выведенный из этих манифестов по P/02.5 Н1.4 (команда `rights` любой реализации), оценщиком P/01.2 Н1.2.
- `DENIED` — безусловный участник без права: ошибка строки каталога или пробел прав.
- `CONDITIONAL` — участник с условием, которое может называть другой манифест: проверяется чтением.
- `ABSENT` — роль, которую вывод для этих манифестов не создаёт.

Объекты, файлы и `<manifest:…>`-строки скрипт не проверяет: права хранилища их не касаются или нужны имена манифеста.

## Чтение YAML контракта

Профиль — JSON-совместимый YAML 1.2 Core: `on`, `off`, `yes`, `no` — строки; `012` — десятичное 12;
`0o12` — восьмеричное 10; дата без тега — строка; ключи объектов только строки. `<<` и `=` — обычные
строки, `<<` не сливает отображения; тег `!!merge` даёт отказ. Дубли ключей, NaN, Infinity и явные
не-JSON типы отказываются. Это профиль чтения контрактов, а не грамматика манифеста подсистемы P/02.1.
Основания: [OpenAPI 3.1 §4.2](https://spec.openapis.org/oas/v3.1.0.html#format),
[YAML 1.2.2 Core](https://yaml.org/spec/1.2.2/#103-core-schema).

## Ссылки внутри контракта

JSON Pointer проверяется по [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901) после строгого
декодирования URI-фрагмента и UTF-8: escape только `~0` и `~1`; индекс массива — `0` или ASCII-цифры
без ведущего нуля; знак, пробел, не-ASCII цифры, `-` и выход за массив — ошибка. Для ключа объекта
цифровые ограничения не действуют; пустой ключ и экранированные `~` и `/` допустимы.

Обход следует позициям объектов [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html#media-type-object)
и ключам вложенных схем JSON Schema 2020-12; рекурсия через локальный `$ref` поддержана.
Внешние ссылки (кроме [ссылок между контрактами платформы](#ссылки-между-контрактами-платформы)),
якоря, `$id`, `$dynamicRef`, `$recursiveRef` и другие диалекты дают «unsupported»: это не подтверждение
и не опровержение контракта. Загрузка внешних ресурсов отключена и в валидаторе.

## Ссылки между контрактами платформы

Урок, который отдаёт форму другого урока, не копирует схему, а ссылается на неё (план переноса урока 6, В7):

```yaml
schema: {$ref: '../../05-resource/spec/05-resource.api.openapi.yaml#/components/schemas/Event'}
```

Путь относителен к файлу, в котором стоит `$ref`; после `#` — корневой JSON Pointer по тем же правилам, что у
локальной ссылки. Скрипт проверяет:

- форму: относительный путь без схемы, хоста и запроса, файл `*.openapi.yaml`, указатель после `#` обязателен;
  ссылка на свой же файл путём — ошибка (нужна локальная `#/…`);
- место: после нормализации пути и разрешения символьных ссылок файл лежит внутри `Platform/`, в каталоге урока
  `NN-<процесс>/` или в `common/`; ссылка из контракта вне `Platform/` (М10, М11) — ошибка;
- порядок: контракт урока N ссылается на урок M < N или на общий договор `common/`; иначе «reference to a lesson
  read later». Общий договор ссылается только на общие договоры, поэтому всё, что достижимо из урока N, — общее
  или уроки раньше N. Порядок берётся по номерам: таблица «Порядок чтения» в `Platform/module-design.md`
  перечисляет главы, а уроки 2, 3, 5 и 6 читаются частями между другими уроками (2.4 — после 7, 3.3 — после 4,
  первая глава 5 — в общих договорах шага 3а), так что «урок M прочитан раньше урока N» по ней не определено;
- существование файла и узла по указателю;
- циклы: ошибка — замкнутая цепочка `$ref`, которая проходит через другой файл и возвращается к той же паре (URI файла, JSON Pointer); сообщение показывает цепочку. Возврат к другому указателю того же файла допустим. Локальная рекурсия JSON Schema внутри одного файла допустима; каждый контракт-цель проверяется один раз за прогон;
- контракт-цель: читается и проверяется один раз за прогон теми же проверками, что контракт урока (профиль YAML,
  OpenAPI 3.1, диалект, его собственные ссылки, валидатор, открытость схем-объектов), даже если его урока нет в
  командной строке; HTTP-пути у цели не обязательны (общий договор может держать только `components`). Ошибка
  цели сообщается для её файла, ссылающийся контракт получает «the target contract … has errors»;
- валидатор ссылающегося контракта разрешает межфайловую ссылку через уже прочитанные и проверенные файлы
  (обработчик `file`, сеть закрыта); локальные `#/…` внутри цели разрешаются в файле цели.

Ошибка называет место: `файл:JSON Pointer` позиции `$ref`, например
`Platform/06-console/spec/06-console.api.openapi.yaml:#/paths/~1events/get/…/schema/$ref`. Схема цели, которая
стоит частью композиции (`allOf` и т. п.) только в чужом контракте, говорит открытость в своём файле: правило
«кроме частей композиции» действует внутри одного файла. Число позиций межфайловых `$ref` (каждая один раз за
прогон) — `openapi_cross_refs` в строке `COUNTS`.

`openapi-spec-validator` ошибочно разыменовывает объект `default` с полем `$ref`; такой контракт
проверяется отдельно, допустимые данные ради зелёного результата не меняются. `example`, `examples`,
`const`, `enum` и `Example.value` с таким полем проходят.

Скрипт не исполняет маршрутизацию: полный URL из `servers` и `paths` и неразличимые шаблоны путей
проверяются вручную по чеклисту. Он также не сверяет коды ответов общим набором, не оценивает полноту
Н4 поиском слов и не требует копии Н0.

файлов диалекта (после пакета п. 2) и у тестов Go без собранного `v7check` — их причина печатается.

Сверка пар принятой VMS включает латинские метки и номера N…, строгий счёт шагов;
шесть прежних отсрочек шагов сняты после проверки 108 фактических пар.
Отсрочки меток/шагов V11 сохранены; `NUMBERS_DONE` и `FULL_ENGLISH_DONE` называют только
принятые каталоги V/01–V/10, V/12/common и `VMS/README.md`, а не всю VMS.
Историческая карта проверяется отдельным точным контролем байтов и не становится английским источником.
