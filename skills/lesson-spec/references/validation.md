# Механическая проверка после ручного чеклиста

Скрипт только читает документы и данные из корня репозитория. Код реализаций не импортируется,
приёмочные запросы не выполняются, контракты из сети не загружаются. Что проверять вручную —
[чеклист](review-checklist.md); этот файл описывает только границы инструмента.

```sh
# все уроки в курсе: перенесённые Platform/ и М11
uv run --no-project --with pyyaml --with openapi-spec-validator --with markdown-it-py \
  --with jsonschema --with ruamel.yaml --with regress python \
  skills/lesson-spec/scripts/check_spec.py Platform/0*-*/0*.md М11_Domain/[0-9]*.md
# выгрузка cammeta-specs: --root — её корень, уроки — её пути, реестр — того же коммита курса
S=/Users/murat/w2c/cammeta-specs
uv run … python skills/lesson-spec/scripts/check_spec.py --root $S \
  --exceptions <(git show "$(cat $S/COURSE_COMMIT)":skills/lesson-spec/exceptions.tsv) $S/Platform/0*-*/0*.md $S/М11_Domain/[0-9]*.md
```

`--root` — корень раскладки (по умолчанию текущий каталог), `--exceptions` — реестр (по умолчанию
`exceptions.tsv` навыка). Для выгрузки реестр берётся того же коммита курса, что её `COURSE_COMMIT`:
строка реестра для файла, которого в выгрузке ещё нет, даёт «stale exception». В окружении с `PyYAML`,
`openapi-spec-validator`, `markdown-it-py`, `jsonschema`, `ruamel.yaml` и `regress` можно запускать `python3`
напрямую. Последние три нужны [схеме формы](#схема-формы-спеки-adr-0085) (ADR-0085); после перехода главы P/02.1 на источник формы её нет ни у
одной главы, в выгрузке — тоже, и там они не используются.

**Урок модуля «Платформа»** (`Platform/`, ADR-0083) — тот же вызов с путём лекции:
`check_spec.py Platform/01-store/01-store.md` (все — `Platform/0*-*/0*.md`). Нормы — по главам `spec/NN.K-<процесс>.norms.md` (id `P/NN.K-MM`;
у урока без глав — `spec/NN-<процесс>.norms.md`, id `P/NN-MM`); каждая глава проверяется как урок: Н0–Н5, чеклист,
«Данные», своя приёмка `acceptance/K/` (тот же набор таблиц, что у М11). Одна инструкция `spec/NN-<процесс>.README.md`
и один OpenAPI на урок. Счёты лекции и инструкции — суммы по главам. Ключ реестра — `P/NN`, значение
`acceptance-entry` — `K/имя`. Стенд директив — `Platform/common/acceptance/README.md` (прежний стенд М10 снят: скрипт
читает его, только если файл есть). У главы с корпусом урока 2 — пара схемы ADR-0085 (`spec/NN.K-<процесс>.schema.yaml`, `.references.tsv`) до
перехода, после — [источник формы](#источник-формы-спеки-adr-0087); оба у одной главы — ошибка.

## Итог

- Код 0 и строка `PASS` — описанные структурные проверки пройдены.
- Код 0 и строка `PASS with N exceptions` — пройдены, кроме отступлений из реестра; каждое напечатано
  строкой `EXCEPTION` с причиной.
- Код 1 и строка `FAIL` — найдены дефекты или неподдержанный формат. Неполная проверка даёт `FAIL`, а не `PASS`.
- Код 1 и `Missing dependency…` без строки `FAIL` — нет зависимости; это не пропуск успешной проверки.
- Код 1, `FAIL` и ошибка `form schema check needs jsonschema, ruamel.yaml and regress … run: uv run …` — у урока есть
  схема формы, а её зависимостей нет; проверка не пропускается.
- Код 2 — неверные аргументы командной строки.

## Реестр исключений

[`exceptions.tsv`](../exceptions.tsv) называет разрешённые отступления (ADR-0080 доп. 14): урок
(`модуль/NN`), вид, значение и причину. Виды:

- `no-openapi` — у урока нет своего контракта по ADR; проверка OpenAPI пропускается;
- `scenarios-format` `own` — свой формат `scenarios.tsv` (директивы `@…`, ожидание кода без тела): общая
  грамматика запроса и ожидания не применяется, приёмка проверяется по своему README; число столбцов
  и нумерация шагов проверяются и у своих форматов;
- `acceptance-entry` — дополнительный файл в каталоге приёмки, например таблицы урока 7;
- `no-acceptance` — у урока нет своей приёмки (вся перенесена или библиотека в браузере); каталог приёмки рядом
  делает строку устаревшей;
- `no-schema` — строка каталога (`row`, `object`) без `schema`, которую читает или пишет процесс перенесённого
  урока: урок — `owner` строки, значение — `key`, причина — строка долга (ADR-0083 доп. (11)). Строка
  устаревает, когда у строки появилась `schema` или её не касается ни один перенесённый урок;
- `data-paragraph` — урок `P/NN`, значение — `key` строки каталога: снимает для этой строки требование «туда»
  сверки «Данные» по ролям процесса; строка устаревает, когда абзац снова согласован с каталогом.

Строка реестра для проверяемого урока, которой урок не воспользовался (контракт появился, файл удалён,
общая грамматика проходит, файл и так поддержан), — ошибка: её снимают в той же правке. Новый файл приёмки
автор присылает «Архитектору» вместе со строкой реестра до своего коммита, и оба коммита идут подряд:
иначе main краснеет на `unsupported acceptance entry`. Счёт и сверка счётов работают и для своих форматов;
строка заголовка в счёт не входит.

## Что проверяется

| Проверка | Граница результата |
|---|---|
| Файлы урока по составу ADR в раскладке `spec/` (без OpenAPI — по реестру); нет однострочных и многострочных `{{...}}` | Качество содержания — вручную; шаблоны `assets/` не опубликованный урок |
| Относительные ссылки и изображения CommonMark: inline и reference (полная, сокращённая, короткая) | Проверяется существование локального пути; абсолютный локальный путь — ошибка. Якоря, внешние адреса и смысл ссылок — вручную; примеры в коде не исполняются. Сырой HTML вне кода (`<a>`, `<img>`, комментарии) даёт `unsupported raw HTML` и прерывает проверку ссылок файла; это граница инструмента, а не запрет HTML |
| Уникальные YAML-ключи контракта, OpenAPI 3.1, локальные `$ref` в позициях ссылок OpenAPI и JSON Schema; каждая схема-объект говорит открытость (`additionalProperties`, у составной — `unevaluatedProperties`), кроме частей композиции | Поддержаны корневые JSON Pointer `#` и `#/…`. Поле `$ref` в данных примеров не ссылка. `$ref` внутри расширения `x-…` проверяется, только если на это расширение ссылается объект контракта |
| [Межфайловые `$ref`](#ссылки-между-контрактами-платформы) между контрактами `Platform/`: форма, файл внутри `Platform/`, указатель, порядок уроков, нет циклов; контракт-цель проходит те же проверки | Число позиций — `openapi_cross_refs` в строке `COUNTS`. Порядок — по номерам уроков, не по таблице «Порядок чтения» глав |
| В нормах h2 Н0–Н5, «Решает реализация», «Чеклист готовности», id пунктов чеклиста до следующего h2 или h1; примеры в коде и цитатах их не заменяют; id уникальны | Сохранность id относительно исходного среза и содержание пунктов — вручную. «Соответствие прежним урокам» в нормах и «Цели и не-цели» в лекции скрипт не проверяет |
| `scenarios.tsv`: столбцы, шаги, HTTP и ASSERT, трёхзначный ASCII-код 100–599, JSON ожидаемых ответов | Неверный JSON входа может быть намеренным; запросы, переменные и подстановки — вручную |
| `verdicts.tsv`: уникальность, значения, все имена в `cases/` и вид каждого входа | Правильность вердиктов требует загрузчика или чтения |
| `diagnostics.tsv`: отказанный случай, уникальность, форма путей и целых номеров | Совпадение с фактической диагностикой — вручную или раннером |
| `classes.tsv` (`case<TAB>class`): отказанный случай, уникальность, класс из `text`, `key`, `value`, `reference`, `name`, `catalogue` (М10/2 Н4); в путях `diagnostics.tsv` ключ — непустая строка, индекс списка — целое ≥ 0 | Совпадение с фактическим классом — раннером |
| Четыре столбца `corrections.tsv` | Полнота журнала — вручную |
| Счёты и диапазоны в нормах, инструкции и README приёмки: «N сценариев / M шагов» (N — и словом до двадцати, с одним словом перед «сценари…»: «восемь независимых сценариев, 121 шаг»), «Всего M шаг…» в начале предложения, «scenarios.tsv (01–NN)», корпус «N файлов/вердиктов … A ok / B refused», номера `| NN |` таблицы Н5 норм против имён сценариев; в инструкции и README приёмки также «<урок>-01…NN», «N id», «N пунктов чеклиста», «все N норм» — против фактических таблиц и числа id чеклиста | Распознаются только эти формы и только как счёт всего урока; другие формулировки (подмножество, число в другом падеже) — вручную по чеклисту. Число сверенных фраз — `count_phrases` в строке `COUNTS` |

## Схема формы спеки (ADR-0085)

Если рядом с нормами урока лежат `spec/<урок>.schema.yaml` и `spec/<урок>.references.tsv` (после перехода P/02.1 на источник формы — ни у одной главы),
скрипт прогоняет каждый случай `verdicts.tsv` урока через прогонщик [`scripts/spec_schema/run.py`](../scripts/spec_schema/run.py):
слой текста (`textlayer.py`), схему JSON Schema 2020-12 и проход ссылок (`refs.py`). Схема — проверка рядом с нормой,
не норма: норма — проза Н1.1–Н1.4; профиль схемы — её шапка. Байты схемы и ссылок правит «Спецификация» той же правкой,
что норму урока 2; прогонщик — «Архитектор».

| Что проверяется | Что остаётся ручным |
|---|---|
| Схема проходит метасхему 2020-12 и профиль: ключевые слова из закрытого перечня, тип у каждого объявленного свойства, `pattern` по ECMA-262; строки ссылок — четыре столбца, слово из словаря прохода | Согласие схемы с прозой там, где корпус молчит |
| Вердикт каждого случая — как в `verdicts.tsv`; у случая из `classes.tsv` — тот же класс. Расхождение — ошибка случая с ожидаемым, полученным и слоем (`text:<правило>`, `schema`, `global`, `refs`) | Путь и строка диагностики (`diagnostics.tsv`) — не сверяются; класс случаев вне `classes.tsv` |
| Одна из пары файлов без другой, схема без `verdicts.tsv` — ошибка | — |

Расхождение означает дефект схемы, нормы или корпуса: схему, отставшую от нормы, правят вместе с нормой; норму и корпус —
по правилам урока. Число прогнанных случаев — `schema_cases` в строке `COUNTS`. Отдельный прогон файлов:
`python skills/lesson-spec/scripts/spec_schema/run.py FILE…` (JSON-строка на файл; `--schema`, `--references`).

## Источник формы спеки (ADR-0087)

Если рядом с нормами главы лежит `spec/NN.K-<процесс>.form.yaml` (с `.references.tsv` и `.scalars.tsv` той же главы),
скрипт строит из источника загрузчик и раздел урока ([`scripts/form_source/`](../scripts/form_source/): разбор источника,
интерпретатор диалекта, раздел, канонический вид). Источник — норма; байты пишет «Спецификация», построитель —
«Архитектор». Форма читается слоем текста Н1.1, таблицы — как TSV (UTF-8 без BOM, LF, TAB, строка `#` — комментарий).

| Что проверяется | Что остаётся ручным |
|---|---|
| Сборка: слова диалекта, `pattern` в подмножестве § 4 (повтор ≤ 1000), каждый путь правила и отношения — место формы, ключи правила — ключи отображения, регулярное выражение отношения — строка в кавычках, `ordered` — у отображения имён со значением-объектом без `name`, `scalars.tsv` согласна со слоем текста. Ошибка сборки — ошибка файла формы | Смысл источника против прозы урока |
| Раздел: построенный текст стоит в нормах главы байт в байт между строками `<!-- form:begin -->` и `<!-- form:end -->` (одна пара); вписать — `python skills/lesson-spec/scripts/form_source/build.py <нормы главы>` | Связующий текст урока вокруг раздела |
| Корпус главы через построенный загрузчик: вердикт (`verdicts.tsv`), класс (`classes.tsv`), множество путей и обязательные строки (`diagnostics.tsv`); все спеки курса (`Source/vms/`, `Source/tests/testdata/`) — `ok` | Диагностика случаев вне `diagnostics.tsv` |
| Покрытие `references.tsv`: строка держится, если без неё меняется вердикт или класс хоть одного случая (`form_rows_held` из `form_rows` в `COUNTS`); с `--strict-coverage` недержащаяся строка — ошибка | — |

Числа — `form_cases`, `form_specs`, `form_rows`, `form_rows_held` в `COUNTS`. Канонический вид — следующий раздел.

## Канонический вид (ADR-0089, глава 2.2)

Проекция принятой спеки по источнику формы главы 2.1 — [`scripts/form_source/canonical.py`](../scripts/form_source/canonical.py):
сахар урока 2 (`tables` списком, `bound_to` одним именем, `in` элемента `secret_in` одним словом — имена норм Н1.1), умолчания
источника внутри присутствующего родителя (Р10), вычисляемые умолчания (П1 `snapshot`, П2 `tables.<т>.journal`,
П3 `display.form`, П4 `default` описателя поля, П5 `decoded` у `secret_in` с `regex`), `ordered` — список `{name, …}` в
порядке автора; байты — JCS. Перечень шагов закрыт (`STEPS`); шаг действует, если его места есть в форме. Из той же
формы строятся форма вида (ключ с умолчанием или шагом — обязателен, сахар — одна форма, правил формы спеки нет) и её
JSON Schema 2020-12 (файлом в спеке не хранится: реализации строят её из источника, команда `schema` — для чтения); повтор `name` в списке `ordered` схема называет словом `x-unique-by`, проверяет его скрипт.
Векторы, проба мутаций и `puts.tsv` главы — [`scripts/form_source/vectors.py`](../scripts/form_source/vectors.py).
Байты норм, векторов и приёмки — «Спецификация», построитель — «Архитектор».

```sh
# из корня раскладки (курс или выгрузка)
python skills/lesson-spec/scripts/form_source/build_canonical.py section   # раздел в нормы 2.2 между маркерами (без них — stdout)
python skills/lesson-spec/scripts/form_source/build_canonical.py schema   # JSON Schema вида в stdout (не хранится)
python skills/lesson-spec/scripts/form_source/build_canonical.py vectors   # cases.tsv (строки corpus-*, course-*) и expect/
```

| Что проверяется | Что остаётся ручным |
|---|---|
| Переход: нет ни `spec/02.2-installer.norms.md`, ни `vectors/canonical/`, ни `acceptance/2/` урока 2 — проверка пропускается, `canonical=absent` в `COUNTS`; иначе `canonical=present` | — |

| Раздел: если в нормах главы 2.2 есть строки `<!-- canonical:begin -->` и `<!-- canonical:end -->` (одна пара), текст между ними — построенный байт в байт; без маркеров (переход) — не ошибка, `canonical_section=absent` в `COUNTS`. | Связующий текст норм |
| Векторы `vectors/canonical/`: только `README.md` (обязателен), `cases.tsv`, `expect/`, `inputs/`. `cases.tsv` — заголовок `case<TAB>input<TAB>expect<TAB>note`; `case` уникален, `[A-Za-z0-9][A-Za-z0-9_.-]*`; `input` — путь файла спеки от корня раскладки (без `..`), загрузчик 2.1 его принимает; `expect` — ровно `expect/<case>.json`, байты — построенный вид (JCS, без перевода строки). Каждый принятый вход корпуса и курса — вход хотя бы одной строки; лишний файл `expect/`, `inputs/` — ошибка (`canonical_vectors`) | Строки-примеры по правилам записки умолчаний — чтением |
| Проба мутаций: снять каждый `default` и каждый `ordered` источника, пропустить каждый шаг; мутант, на котором все векторы дают прежние байты, выжил (`canonical_mutants`, `canonical_mutants_killed`); с `--strict-coverage` выживший — ошибка: нужна строка-пример | — |
| `puts.tsv` глав 2.2 и 2.3 урока P/02 (`PUTS_CHAPTERS`, без строк реестра): заголовок `case<TAB>puts<TAB>expect<TAB>canonical` у 2.2, `case<TAB>puts<TAB>expect` у 2.3; `case` — `[a-z0-9_]+`, уникален; `puts` — имена `puts/<имя>.subsystem.yaml` через пробел, между ними директивы `@view-delete` (admin `delete` вида) и `@view-spoil` (admin `put` вида с иным `spec`), первым и последним — файл; `expect` — `<0\|2> <rev\|->`; `canonical` — `-` (вида нет) или `case` вектора: при коде 0 — вид последнего файла, при коде 2 — вид одного из файлов строки; при коде 0 `-` — ошибка. Каждый файл `puts/` ставит хоть одна строка (`canonical_puts` — 2.2, `puts_cases` — 2.3) | Порядок записи, `rev`, `toolarge` и граница потолка — сценариями и чтением |

## Каталог данных (ADR-0083)

Если в корне есть `Platform/common/data/catalog.tsv`, скрипт проверяет его и абзацы «Данные» уроков. Форма каталога
— `decisions/inbox/2026-10-18-каталог-данных-форма.md`.

| Что проверяется | Что остаётся ручным |
|---|---|
| Заголовок из девяти полей. Ключ уникален. `kind`: `row`, `object`, `file` или `dir`. `owner` и `norm` указывают на существующий урок. `version` ≥ 1. `schema` — `-`, `spec` (форму задаёт манифест подсистемы: ключ называет `<spec:unit.rows>`, `<spec:tables>`, `<spec:objects.rows>`, `<spec:domain.books.from>` или `<spec:domain.kept>`; семьи в `data/` нет) или файл `NN-<процесс>/data/<семья>.form.yaml` под `Platform/` урока-владельца (`owner` — `P/NN` или его глава), только у `row`, `object` и `file` с содержимым JSON (корень схемы файла — `encoding: json` или `jcs`, проверяет построение семьи) ([семьи данных](#семьи-данных-adr-0088)) | Совпадение формы с нормой |
| `ops`: операции из закрытого набора, каждая один раз, через `; `. Условие стоит у участника. Участники и читатели — роли М10/6 Н1.1 или `*` | Верны ли условия |
| Пересечение образцов при равной узости — ошибка | Пересечения, которые снимает грамматика широкого образца |
| Абзац «Данные» Н1: ключи есть в каталоге; «владеет» = строки с `owner` урока; у «пишет» операция есть в `ops`. Урок без абзаца, которому каталог отдаёт строки, — ошибка | Полнота «читает» у уроков М10 и М11; совпадение прав из каталога с выводом из спеки (до решения п. 12) |
| Перенесённый урок (`Platform/NN-*` с лекцией) по ролям своего процесса: процесс из `Platform/lessons.tsv` (`<sub>worker` — `<s>worker` и `<s>domain`, `<sub>controller` — `<s>controller`, `configstore` — `configstore-door`, `w2cctl` — `admin`, иначе имя процесса) и `proc:NN-<процесс>`. Строку, где роль процесса — участник операции, какая-то глава называет в «пишет»; где роль — среди читателей (не `*`), — в «читает» или «пишет»; строки урока — в «владеет». Обратно: у ключа «пишет» операция с ролью процесса среди участников; у ключа «читает» роль процесса среди читателей или участников, читатели `*` или владелец — этот урок (разбор ревью стадии B 3–5, №10). «Туда» пропускает строку владельца М11, которую не называет ни одна норма урока (до переноса уроков 8–10), и строку с исключением `data-paragraph` | Что роль процесса в каталоге названа верно |
| `owner` строки — не перенесённый урок М10/М11: не урок, все id которого в `id-map.tsv` имеют `new` в чеклистах `Platform/`, и не строка, чья `norm` целиком перенесена — каждый адрес в `Platform/` или раздел прежнего урока, где осталось только «Перенесено в …» без «Остаётся здесь» (№35) | Куда переадресовать |
| Чеклист главы перенесённого урока и `id-map.tsv`: каждый id чеклиста есть в колонке `new`; каждый `new` этой главы есть в чеклисте, кроме строк, чей `old` ещё в чеклисте прежнего урока (норма переедет с ним, глава позднего слоя) (№36) | Предмет и `note` строки |
| Строка `row` или `object`, которую читает или пишет процесс перенесённого урока (владелец — этот урок или роль его процесса среди участников или читателей), имеет `schema` (семью или `spec`) или исключение `no-schema` (ADR-0083 доп. (11)) | Строка долга исключения |

## Имена процессов (`Platform/lessons.tsv`)

Колонки `process` и `unit` после `title`: имя процесса урока — роль и аргумент раннера `w2c-run.sh` — и имя его юнита
systemd в блоке `units:` P/02.4 Н1.1 (`Platform/02-installer/spec/02.4-installer.norms.md`); `-` — процесса или юнита
нет. Проверка идёт один раз за прогон, при первом уроке модуля «Платформа»; рядом с кодом — `process_names`,
`unit_entries`, `lifecycle_head` в `check_spec.py`.

| Что проверяется | Что остаётся ручным |
|---|---|
| Заголовок таблицы — `lesson dir title` или `lesson dir title process unit`; при обеих колонках значения у каждой строки обязательны | — |
| `process` ≠ `-`: шапка `Platform/<dir>/lifecycle.md` (заголовок и первый абзац — до пустой строки, списка, заголовка или таблицы) называет процесс в обратных кавычках `` `<process>` ``; нет `lifecycle.md` — ошибка | Имя процесса в остальном тексте жизненного цикла |
| `unit` ≠ `-`: в блоке `units:` первого yaml-блока после заголовка «Н1.1» есть запись `  <unit>:` (отступ два; продолжения — строки глубже до следующей записи). В записи каждое `роль <R>` и `w2c-run.sh <A>` — ровно `process`; шаблоны (`<sub>controller`) сравниваются как строка | Остальные поля юнита против норм |
| Каждая запись `….service` блока с `роль <R>`: `R` есть в колонке `process`. Исключения — `common` и `w2c-workers.service/.timer` (`UNITS_EXEMPT`: не юнит одного процесса) | Записи без `роль` (`configstore.service`, ресурс, консоль, воркер) |
| Переход: колонок нет — не ошибка, `process_names=absent` в `COUNTS`; есть — `process_names` — сколько уроков проверено (`process` или `unit` ≠ `-`) | — |

## Семьи данных (ADR-0088)

Семья главы — строка каталога, чей `owner` — эта глава (`P/NN.K`), с колонкой `schema`: схема
`NN-<процесс>/data/<семья>.form.yaml` (`dialect: data-form/1`, определения `ref: common.<имя>` —
`Platform/common/data/common.form.yaml`) и исходы `<семья>.outcomes.tsv` рядом ([диалект](../../../Platform/common/DIALECT.md)
§ 8–9). Код — [`scripts/form_source/families.py`](../scripts/form_source/families.py): разбор тем же построителем, что
форма 2.1, со словами схем семей (`type: time`, `whole`, `max_items`, `max_bytes`, `encoding: json|jcs`, `writer`, код
знака `\x{HHHH}` в `pattern`; в форме манифеста их нет), раздел и судья экземпляра. Байты схем — «Спецификация»,
построитель — «Архитектор».

| Что проверяется | Что остаётся ручным |
|---|---|
| Сборка каждой семьи главы: слова диалекта, `whole` — у целого, `max_bytes` — у строки, `max_items` — у списка или имён, `ref` без граней рядом (кроме пометок и `whole`); у `row` корень — отображение `properties`. Ошибка — ошибка файла схемы | Смысл схемы против прозы нормы |
| Исходы: заголовок `path<TAB>outcome<TAB>priority<TAB>unit<TAB>norm`; путь пустой (строка целиком — обязателен) или JSON Pointer места схемы (индекс списка — цифры); путь один раз; `priority` — целое ≥ 0; `unit` — `строка`, `поле`, `элемент`; исход и норма названы. Нет файла — ошибка | Верен ли исход; единица нечитаемости против нормы |
| Раздел: если в нормах главы есть строки `<!-- families:begin -->` и `<!-- families:end -->` (одна пара), текст между ними — построенный байт в байт: все семьи главы в порядке каталога, у каждой таблица полей тем же языком, что раздел «Форма» 2.1, правила, определения и таблица исходов. Маркеры у главы без семей — ошибка. Вписать — `python skills/lesson-spec/scripts/form_source/build_families.py <нормы главы>`; без маркеров команда печатает раздел в stdout | Связующий текст нормы вокруг раздела |
| Переход: нормы без маркеров — не ошибка; `families_with_section` и `families_without_section` в `COUNTS` — сколько семей главы с разделом и без; `family_schemas`, `family_outcomes` — сколько схем собрано и строк исходов прочитано | Когда урок заменяет псевдо-YAML разделом (ADR-0088 п. 8) |

Судья `families.Judge(form, mode)` — обход формы загрузчика 2.1 (`judge.Loader.node`) с кодеком `codec.tsv`: `row` —
объект строк `items`, раскодированный по типу узла (писатель — строгая запись, читатель — терпимая; `whole` — целый знак
и у читателя), `object` — значение JSON; ответ — вердикт и множество путей отказа JSON Pointer. `outcomes_for(outcomes,
paths)` — исходы по DIALECT § 9: строки, чей путь — префикс хоть одного пути отказа, из них — с наименьшим приоритетом.
Корпуса примеров строк по семьям (ADR-0088 п. 7) ещё нет — формат файла не решён; судья прогоняется тестами навыка.

## Каталог ⊆ права (ADR-0083 доп. (6))

`scripts/catalog_rights.py --catalog Platform/common/data/catalog.tsv --rights <файл прав> --spec <спека>…` проверяет,
что каждую операцию каждого участника каталога (строки хранилища) и каждое чтение читателя разрешает файл прав,
выведенный из этих спек по М10/6 Н1.4 (команда `rights` любой реализации), оценщиком Н1.3.
- `DENIED` — безусловный участник без права: ошибка строки каталога или пробел прав.
- `CONDITIONAL` — участник с условием, которое может называть другую спеку: проверяется чтением.
- `ABSENT` — роль, которую вывод для этих спек не создаёт.

Объекты, файлы и `<spec:…>`-строки скрипт не проверяет: права хранилища их не касаются или нужны имена спеки.

В каталоге приёмки урока обязательны `README.md` и `corrections.tsv` и хотя бы одна из таблиц
`scenarios.tsv` или `verdicts.tsv`. Допустимы ещё `diagnostics.tsv` и `classes.tsv` (только при `verdicts.tsv`)
и `cases/` (только при `verdicts.tsv`, имена — ровно `<case>.subsystem.yaml` из таблицы); у глав 2.2 и 2.3 урока P/02 —
`puts.tsv` и `puts/` ([канонический вид](#канонический-вид-adr-0089-глава-22)).
Любой другой файл или каталог — `unsupported acceptance entry`.

## Чтение YAML контракта

Профиль — JSON-совместимый YAML 1.2 Core: `on`, `off`, `yes`, `no` — строки; `012` — десятичное 12;
`0o12` — восьмеричное 10; дата без тега — строка; ключи объектов только строки. `<<` и `=` — обычные
строки, `<<` не сливает отображения; тег `!!merge` даёт отказ. Дубли ключей, NaN, Infinity и явные
не-JSON типы отказываются. Это профиль чтения контрактов, а не грамматика спеки подсистемы М10/2.
Основания: [OpenAPI 3.1 §4.2](https://spec.openapis.org/oas/v3.1.0.html#format),
[YAML 1.2.2 Core](https://yaml.org/spec/1.2.2/#103-core-schema).

## Ссылки внутри контракта

JSON Pointer проверяется по [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901) после строгого
декодирования URI-фрагмента и UTF-8: escape только `~0` и `~1`; индекс массива — `0` или ASCII-цифры
без ведущего нуля; знак, пробел, не-ASCII цифры, `-` и выход за массив — ошибка. Для ключа объекта
цифровые ограничения не действуют; пустой ключ и экранированные `~` и `/` допустимы.

Обход следует позициям объектов [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html#media-type-object)
и ключам вложенных схем JSON Schema 2020-12; рекурсия через локальный `$ref` поддержана.
Внешние ссылки (кроме [ссылок между контрактами платформы](#ссылки-между-контрактами-платформы)),
якоря, `$id`, `$dynamicRef`, `$recursiveRef` и другие диалекты дают «unsupported»: это не подтверждение
и не опровержение контракта. Загрузка внешних ресурсов отключена и в валидаторе.

## Ссылки между контрактами платформы

Урок, который отдаёт форму другого урока, не копирует схему, а ссылается на неё (план переноса урока 6, В7):

```yaml
schema: {$ref: '../../05-resource/spec/05-resource.api.openapi.yaml#/components/schemas/Event'}
```

Путь относителен к файлу, в котором стоит `$ref`; после `#` — корневой JSON Pointer по тем же правилам, что у
локальной ссылки. Скрипт проверяет:

- форму: относительный путь без схемы, хоста и запроса, файл `*.openapi.yaml`, указатель после `#` обязателен;
  ссылка на свой же файл путём — ошибка (нужна локальная `#/…`);
- место: после нормализации пути и разрешения символьных ссылок файл лежит внутри `Platform/`, в каталоге урока
  `NN-<процесс>/` или в `common/`; ссылка из контракта вне `Platform/` (М10, М11) — ошибка;
- порядок: контракт урока N ссылается на урок M < N или на общий договор `common/`; иначе «reference to a lesson
  read later». Общий договор ссылается только на общие договоры, поэтому всё, что достижимо из урока N, — общее
  или уроки раньше N. Порядок берётся по номерам: таблица «Порядок чтения» в `Platform/module-design.md`
  перечисляет главы, а уроки 2, 3, 5 и 6 читаются частями между другими уроками (2.4 — после 7, 3.3 — после 4,
  первая глава 5 — в общих договорах шага 3а), так что «урок M прочитан раньше урока N» по ней не определено;
- существование файла и узла по указателю;
- циклы: цепочка межфайловых ссылок, вернувшаяся в файл, который ещё проверяется, — ошибка с цепочкой файлов;
- контракт-цель: читается и проверяется один раз за прогон теми же проверками, что контракт урока (профиль YAML,
  OpenAPI 3.1, диалект, его собственные ссылки, валидатор, открытость схем-объектов), даже если его урока нет в
  командной строке; HTTP-пути у цели не обязательны (общий договор может держать только `components`). Ошибка
  цели сообщается для её файла, ссылающийся контракт получает «the target contract … has errors»;
- валидатор ссылающегося контракта разрешает межфайловую ссылку через уже прочитанные и проверенные файлы
  (обработчик `file`, сеть закрыта); локальные `#/…` внутри цели разрешаются в файле цели.

Ошибка называет место: `файл:JSON Pointer` позиции `$ref`, например
`Platform/06-console/spec/06-console.api.openapi.yaml:#/paths/~1events/get/…/schema/$ref`. Схема цели, которая
стоит частью композиции (`allOf` и т. п.) только в чужом контракте, говорит открытость в своём файле: правило
«кроме частей композиции» действует внутри одного файла. Число позиций межфайловых `$ref` (каждая один раз за
прогон) — `openapi_cross_refs` в строке `COUNTS`.

`openapi-spec-validator` ошибочно разыменовывает объект `default` с полем `$ref`; такой контракт
проверяется отдельно, допустимые данные ради зелёного результата не меняются. `example`, `examples`,
`const`, `enum` и `Example.value` с таким полем проходят.

Скрипт не исполняет маршрутизацию: полный URL из `servers` и `paths` и неразличимые шаблоны путей
проверяются вручную по чеклисту. Он также не сверяет коды ответов общим набором, не оценивает полноту
Н4 поиском слов и не требует копии Н0.
