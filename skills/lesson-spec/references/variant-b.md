# Готовность урока к варианту Б (генерация с нуля и суд движком)

Опыт P/01 (ADR-0133, ADR-0135, ADR-0130 Addendum (19), ADR-0125 доп. (12), (13)). Урок готов к первой попытке, когда выполнено всё ниже; аудит готовности идёт по этому списку с местом каждого «нет».

1. **Пункты перечней норм и этапы.** Каждый пункт `- [ ] **P/NN.K-MM**` в `spec/*.norms.md` стоит ровно на одном этапе в столбце `norms` файла `forms/stages.tsv` — на самом позднем этапе, где реализован последний предмет пункта; грамматика ячейки — в шапке файла. Пункт называет режим и предмет однозначно (ящик или группа, последователь или лидер): тест другого режима пункт не закрывает — это проверяется чтением названного теста (ревью чтением попытки 5 P/01: 6 из 16 пунктов группы закрыты тестами ящика). Урок входит в перечень обязательных у `check_spec`, когда переходит на трассировку (ADR-0133 доп. (43), `P01.117`). На переходе раскладки пункты и строки сверяются в паре `X` ↔ `ru/X`; для M действует источник `X`.
2. **Проверки кода.** Строки `forms/code-rules.tsv` урока по словарю `Platform/common/acceptance/forms/code-rules.tsv`: вид, абстрактное имя, этап, норма; ворота `code:*` в `stages.tsv` на этапе строки или позже (ADR-0133 доп. (39)). Имена связывает с кодом сама модель полем `code` профиля. Строки не содержат ожидаемых ответов (доп. (39) п. 2).
3. **Реестр целей судьи.** Строки урока в `targets.tsv` (M) и `targets.routing.tsv` (J), сценарии `acceptance/K/scenarios.tsv`, векторы через `wire.tsv` и `consumers.tsv` (строка чужого owner в описи цели отсутствует). Без реестра движок урок не судит (ADR-0135 доп. (2)).
4. **Никакой прозы там, где судят.** Пробы, шаги и ожидания — данными по закрытому словарю общей приёмки (`Platform/common/acceptance/README.md`); новое слово — в этот README на двух языках, не код под урок (P/AC-R002, `P01.142`). Проза без машинной формы получает `no_machine_form` и не засчитывается.
5. **Ключи и подстановки профиля** — только из `profile-keys.tsv` (с типом) и `profile-substitutions.tsv`; окружение стенда — по «One data directory» README общей приёмки.
6. **M и J.** Фильтр режет только целые файлы. Признак готовности — каждый файл урока есть в паспорте M (`operator/m_passport.py`) и в дереве J-входа, пара M ⊂ J сверена побайтно (`P01.121`, `P01.131`); цикл проверяет корень M по паспорту, а не по шаблонам путей. Занесение файлов в фильтры выгрузки — работа стороны выгрузки, не признак готовности урока.
7. **Зависимости.** Модули — только `require` из кэша стенда, без копий, `replace`, `vendor`, `go.work` (`versions/README.md`, строка `requires_module`).
8. **Боевая проверка.** Нормы боевых свойств урока (аналоги D1–D7: стоимость записи, сроки фаз, замки и остановка, исход при сбое, повтор и память) есть в M и стоят в перечнях норм со столбцом `norms` по п. 1 (ADR-0130 Addendum (19) п. 2). В функциональном суде — только минимальный набор процессных проб без приборов D7 и без других уроков (ADR-0130 Addendum (19) п. 7); с D7 или несколькими уроками — этап системы.
9. **Формы.** TSV-формы — со схемой Frictionless Table Schema и `foreignKeys` между формами, JSON-формы — JSON Schema (ADR-0125 доп. (13), `OBSH.39`), по мере перевода.
10. **Вход не меняется посреди попытки.** Правка нормы — новая пара выгрузок; цикл отмечает смену входа (`P01.146`), но это аварийный путь, не порядок работы.
11. **Форма M для чтения** (P01.175; ADR-0133 доп. (56), (61), (93), (94)). В M нет истории и номеров ADR вне надгробий ([SKILL.md](../SKILL.md), «История вне текста норм»); у главы — указатель только тем нескольких мест (без «See also»); пометка judge-only — только у ссылки, которая называет файл, строку или сценарий вне M, без повтора R-id; лишнюю ссылку снимают, а условие говорят словами; M пары узкий (фильтры режут целыми файлами), и файл другого урока, на который ссылается M, назван в «What this lesson takes from common» урока; боевые требования — отдельным R-id с меткой «Scope: production.»; у README урока — «What this lesson takes from common», у инструкции — глоссарий и один абзац о том, что сценарии, фикстуры и эталоны модели не даны. Раскладка требований — по уроку: у P/01 абзац с одним R-id и несколькими правилами, слитые id — в карте `req-id-map.tsv` журнала; у остальных уроков, пока их задача не приняла абзацы, — одно требование — один пункт с id; YAML-блоки без прозы; порядки проверок — формами по образцу `write-checks.tsv`; формы Status, двери и метрик — по цене (SKILL.md, «Форма M для чтения»). Урок входит в перечень формы M у `check_spec` (validation.md, «Форма M»), когда его форма приведена.
12. **Проход по итогам попыток 7–8** (ADR-0133 доп. (107) п. 1; образец — `P02.63`). Новые нормы — только решением «Архитектора».
    - **Развилки.** Пункт «Решает реализация» называет наблюдаемый исход выбора — что видит судья или стенд; без исхода это вопрос «Архитектору» (урок 1, `P01.186` O1: канал внутренних кадров не назван, прокси стенда понимал только HTTP).
    - **Надёжность.** Норма аварии, порчи, отказа диска, повтора или восстановления — со сценарием J, швом или записью Q из существующих средств стенда либо с записанной причиной «проверяется чтением»: средства нет или боевая приёмка (урок 1, `P01.305` Б01–Б03: долговечность в M без сценария — кандидат зелёный на суде и теряет подтверждённые записи).
    - **Пакет норм этапа.** Из столбца `norms` `stages.tsv` цикл режет пакет норм этапа (доп. (104) п. 1): часть раздела — точный заголовок `P/NN.K «Title»`, весь раздел — голый номер; свободные слова после номера — ошибка `check_spec` (validation.md, строка «Ссылки форм»). Пункт перечня — на этапе, где строится его поведение (`P01.316` М9: предел соединений урока 1 стоял на group, строится в http).
    - **Машинные формы.** `write-checks`, `refusals`, `daemon-flags`, `service-checks`/`status-fields` дают внешне наблюдаемый исход каждой строки, чтобы исполнитель форм судил их на стенде этапа (доп. (104) п. 2).
13. **Уроки по договорам и общие модули** (ADR-0133 доп. (115); `Platform/common/modules.md`). Урок N пользуется предыдущими только через их договоры — двери и OpenAPI, формы, схемы, интерфейсы векторов клиента; код предыдущих уроков во вход не идёт, M урока включает договоры, на которые он ссылается, по таблице «What this lesson takes from common» README урока (`m_form.M_NARROW`). Стенд урока N поднимает предыдущие уроки любыми сборками, функционально зелёными по своему J; несхождение с настоящей сборкой — находка в договор. Общий модуль из «Module inventory» `modules.md` обязателен потребителю: строка `requires_module` с точным путём модуля и `from` = `Platform/common/versions/go.mod` и строка `forbid_imports` (прямой `encoding/json` запрещён; исключение — только в `allow` с нормой урока); код урока под общий договор заново не пишется. Генерация урока — после пинов нужных ему общих модулей.
