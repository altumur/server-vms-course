# Правила работы сессий курса (по итогам кодогенерации стадии C)

Решение владельца 2026-10-30 (ADR-0083, правка того же дня). Правила собраны из опыта стадии C: что помогало, а что давало
простои, лимиты, лишние окна и переделки. Маршруты сообщений — `ВЗАИМОДЕЙСТВИЕ-СЕССИЙ.md`, состав сессий — `СЕССИИ.md`,
машины — `ИНФРАСТРУКТУРА.md`.

Этот файл читают все сессии, в том числе линии генерации (c-go, c-go-exec, c-python-v7): он — исключение из запрета
читать курс (ADR-0087 доп. (11) п. 3), потому что несёт только порядок работы, без норм и кода. Прочие файлы курса линиям
по-прежнему закрыты.

## 1. Модели

- **Ведущая линии — Claude** (c-go, c-python-v7): ставит задачи, принимает работу, ведёт кандидатов.
- **Исполнитель линии — Codex** (постановка для MiniMax, ревью, проверки). Линия Go — только Codex.
- **Код пишет MiniMax.** MiniMax в лимите — Go: исполнитель пишет код сам; Python: ждёт сброса.
- **Kimi — только для работы, которая может переждать лимит:** ревью, пилоты, вспомогательные срезы; не больше 3–4 окон
  разом. Не на критическом пути. Части с распределённым состоянием (консенсус, группы, перенос) — не без отдельного
  ревьювера свойств модели (итог пилота урока Go 01).
- **Лимит провайдера — переключение без вопроса владельцу.** Сессии критического пути сразу переходят на другого
  провайдера с HANDOFF; вторая линия (Python) останавливается первой.

## 2. Сколько сессий

| Роль | Сессий | Когда больше |
|---|---|---|
| Линия Go | ведущая + 1 исполнитель | второй исполнитель — только на явно независимую работу и на срок задачи |
| Линия Python | 1 ведущая, уроки по порядку | — |
| Спецификации | «Спецификация» (уроки 01–10, common, выгрузка) + «Спецификация VMS» | — |
| Приёмка | раннер + 1 исполнитель | +1 сессия стендов на этап VMS и на стенд приращения B |
| Сервер | «Машины» + «Сторож» | — |
| Ревьюверы | 3 постоянных окна: Codex, Claude, Kimi | новых окон не открывать — ревью в существующие |
| По вызову | генератор В7, assist-пилот, «Консоль» | открывать при задаче, после — закрывать |

Сессия «на урок» или «на срез» не заводится: много параллельных сессий дают простой на лимитах и путаницу адресов, а
выигрыша мало (уроки Go 08–09 — девять сессий).

## 3. Кандидат и зачётный прогон

- **Пин кандидата — последняя выгрузка с выпуском раннера.** Отложенные нормы не копятся: линия подтягивает выгрузку
  ежедневно (переезд кандидата 01–10 с `22950e7` на `8d67ccd` стоил 16 норм и полдня).
- **Своя проверка перед заморозкой — как у драйвера:** окружение `plain`, `PATH` драйвера, без `--build`; артефакты всех
  модулей сборки — в коммите; интерпретатор и версия — явно (`python3.12`, Go линии). Скрипт `check-candidate.sh` —
  обязателен у обеих линий (две попытки Python P/01 упали до запуска целей).
- **Зачётный прогон ведут «Машины» на CT 102;** кандидат критического пути (сейчас Go 01–10) — первым.

## 4. Ревью

- **Каждый ADR — трём ревьюверам**, затем разбор; где владелец не нужен — решает «Архитектор».
- **Код с распределённым состоянием** — ревью свойств модели, а не только слов нормы: отдельный ревьювер (Codex или
  Claude) на рубеже урока.
- **Приёмка должна видеть свойства группы:** сценарии группы, которые сейчас `@manual`, переводятся в автоматические
  («Спецификация», начиная с P/01 сц. 07).

## 5. Окна и уборка

- **Перед перезапуском** — найти живое окно роли по заголовку (`orca terminal list`), не только по реестру. После
  перезапуска — сразу `tools/sessions/registry.sh set` и строка «Сторожу».
- **Свёрнутая сессия** — HANDOFF, коммит, окно закрыто, в реестре «-».
- **Уборка веток и деревьев — по правилу ADR-0083 (правка 2026-10-30):** влитое — сразу; незакоммиченное — сначала
  владельцу; кандидаты зачётных и живое не трогаются. Временные файлы сессии (`/private/tmp/<сессия>-*`) удаляет ведущая
  при её закрытии.
- **Ресурсы ноутбука:** диск ниже 30 ГиБ — «Машины» сами чистят кеш Go и временные файлы; сон от простоя отключён
  `caffeinate` (ИНФРАСТРУКТУРА.md).

## 6. Что несут владельцу

Только то, что меняет решения или уходит вовне: новый ADR и его спорные места; выбор модели и провайдера; запросы
продукту («пушь»); удаление незакоммиченной работы; сеть и питание. Остальное решает «Архитектор» и записывает.
