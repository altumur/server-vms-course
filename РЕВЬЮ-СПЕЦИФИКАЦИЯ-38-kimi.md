## Находки

### K38-01 — существенная — урок 2 (М10/2-24): закрытый список из 21 зарезервированного слова покрыт приёмкой 4 словами

- Места: `М10_Platform/spec/02-the-spec-and-the-strict-loader.norms.md` (Н1.2, грамматика `spec.name`: 21 слово), чеклист `М10/2-24`, Н5; данные `Source/tests/testdata/acceptance/М10_Platform/02/cases/`.
- Наблюдение: входы с зарезервированным именем существуют только для `platform` (`name_reserved_platform`, старый) и `where`/`healthz`/`metrics` (`r37_sub_*`, новые). Остальные 17 слов — `domain, console, audit, spec, session, mounts, servers, resources, unplaceable, policy, drain, schema, events, marks, requests, asked, api` — не имеют ни одного входа и не помечены «проверяется чтением» (`21-targeted.log`: счётчик по каждому слову; `23-targeted3.log` подтверждает форму r37_sub-кейсов).
- Контрпример (допустимый вход, не наблюдаемый приёмкой): спека `name: events` с корректным фоном testsub → по норме отказ загрузки; регрессия (например, выпадение слова из проверки загрузчика или из enum OpenAPI) приёмкой 02 не будет поймана.
- Основание: правило lesson-spec «каждый id покрыт сценарием или помечен "проверяется чтением"»; прецедент K37-03 этого же окна: трёхэлементный закрытый список (`rows ∈ cluster/worker/ts`) автор закрыл тремя отдельными входами.
- Происхождение: смешанная. Для `domain`/`console`/`audit` пробел старый (на `47cc741e` входов нет, прежние циклы его не фиксировали); расширение списка до 21 в окне 37→38 (коммиты `8f20ef4a`, `daf01742`, `057e1c92`-окно) добавило входы только для 3 новых слов — наведено частично.
- Рекомендация: 17 механических отказных входов (или явная пометка в М10/2-24, что полный перечень проверяется чтением реализации по закрытому enum).

### K38-02 — существенная — урок 2 (М10/2-24): норма непересечения имени подсистемы с rows/tables каталога («включая собственные») не имеет ни одного наблюдаемого входа

- Места: `spec/02-the-spec-and-the-strict-loader.norms.md` Н3 `загрузить_каталог` («Для любых подсистем A и B, включая A=B, имя B не совпадает с unit.rows или именем любой таблицы A, включая списковые tables») и Н4 (`refused:catalogue`); чеклист М10/2-24; `acceptance/М10_Platform/02/README.md` (новый раздел «Проверка класса ошибок R37»).
- Наблюдение: закреплённые за нормой в чеклисте `r37_sub_where/r37_sub_metrics/r37_sub_healthz/r37_sub_where2` проверяют зарезервированные слова: у всех четырёх `name ∈ {where, healthz, metrics, where2}`, секции `tables:` у файлов нет (`23-targeted3.log`: `grep '^tables:'` пуст; diff пар показывает единственную мутацию `name`). Скан всех 234 входов: 0 случаев `name == own rows` или `name ∈ own tables` (`23-targeted3.log`). Пометка «парная проверка чтением Н3 и README» охватывает пару A≠B; подслучай A=B (каталог из одной спеки) наблюдаем одиночным verdict, но ни входа, ни отдельной пометки для него нет; списковая форма `tables: [ledger]` (как у testsub) в контексте пересечения тоже ни разу не использована.
- Контрпример: одиночный файл `name: b`, `unit.rows: b` → по норме `refused:catalogue` даже в каталоге из одной спеки; приёмка это нигде не наблюдает.
- Основание: то же правило покрытия чеклиста; противоречия норме нет — дефект приёмки/пометок id.
- Происхождение: наведена окном 37→38 — сама норма введена исправлением R37-07 (доп. 29), входы не добавлены.
- Рекомендация: 2–4 одиночных входа (`name==own rows`; `name==own table`, map-форма; `name==own table`, списковая форма; положительный контроль) либо явная пометка «включая собственные — проверяется чтением» в М10/2-24.

### K38-03 — мелкая — урок 10 (Н1.1): задвоенные слова в закрытом перечне запрещённых имён таблиц

- Место: `М10_Platform/spec/10-schema-drain-snapshot-limits.norms.md`, Н1.1 `names` — перечень «не spec, session, mounts, healthz, metrics, servers, resources, where, unplaceable, policy, drain, schema, events, marks, requests, asked, platform, domain, api» повторяет уже названные выше в той же строке `policy`, `requests`, `asked`, `servers` (union старого и нового списков без дедупликации).

- Основание: правило точности закрытых перечней (та же строка сверяется с `SubsystemName` в контракте).
- Происхождение: была раньше — строка дословно есть на `47cc741e` (строка без изменений вошла в контекст диффа `05-diff-norms-8-10.log`).
- Рекомендация: дедуплицировать перечень одной правкой.
