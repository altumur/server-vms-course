# __main__.py — `python3 -m cluster worker | controller | recorder | reccontroller | console | resource | rights`: the entry points of a cluster server's units

**Role in the module.** What every unit of a server runs (`deploy/w2c-run.sh <verb>`, from `deploy/systemd/*.service` and `deploy/launchd/*.plist`), dispatched by `sys.argv[1]`. It is М10's `vms/__main__.py` (see `../../../vmsserver/vms/__main__.py.md`) with the stores of a cluster: the store is THIS server's `configstore` daemon through the socket of the verb's role (`ROLES`), and the objects are `cluster://` on this server, whose create-only rows go through that same handle. Everything each process *does* is М10's class; what this file adds is which environment variable feeds which constructor, and the loop cadence. The module docstring is the environment contract for the units: `PLATFORM_STORE` (the older `CONFIG_URL`), `OBJECTS`, `WORKER_NAME` (from the unit, `w-%l-1`, product P4), `SPARE_FOR` (a spare `w2c-spares.sh` started), `SERVER_NAME`/`LABELS` (`/etc/w2c/w2c.env`), `ARCHIVE`, `OBSD_SOCKET`, `ARCHIVE_URL`/`ARCHIVE_HOST`/`ARCHIVE_PORT`, `RESOURCE_URL`, `CAPACITY`, `COMMANDS_BEAT`. `WORKER_NAME` and `SPARE_FOR` need nothing here: `VmsWorker` reads them from `os.environ` (`w2cplatform/runtime.py`). `python3 -m cluster rights` prints the configstore's rights file (`rights.py`).

## Module-level names
- `ROLES` — verb → the role of the rights file it runs as: `worker` → `vmsworker`, `recorder` → `recworker`, `controller` → `vmscontroller`, `reccontroller`, `console`, `resource`. The role is the socket (`/run/configstore/<role>.sock`), and the socket is what the daemon judges by.
- `OBJECTS` — `cluster:///data/platform/objects?resource=http://127.0.0.1:8090`, the default object store.
- `logging.basicConfig(...)` — level from `LOG_LEVEL` (default `INFO`); one format for every process, so the journal reads alike.
- `stop` — a `threading.Event` set by `SIGTERM` or `SIGINT`; the handler is installed when the module is run (`if __name__ == "__main__"`), never at import, so a process that imports it — a test run — keeps its own signals. systemd stops a unit with SIGTERM and waits `TimeoutStopSec` (20 s for the worker); every loop below polls `stop` so that a stop is orderly — for the worker that means `release_slot()`, which is what turns a stop into "redistribute" rather than "a crash".
- `_failing` — a `set` of `(loop, step)` pairs: the controller steps that are failing now, so `_steps` says a failure once per spell and says when it works again.
- `archive` — `runtime.events_root(os.environ)`: `ARCHIVE` from `/etc/w2c/w2c.env`, else `<PLATFORM_DIR>/events` — the platform's events archive on this server (`/data/platform/events`, WP-E), the resource's tree: every subsystem's events, and where every process that holds a slot registers. A recorder's own volume is NOT beside it: `ARCHIVE_VOLUME`, else `vms.config.OWN_VOLUME` (`/data/vms/obsd/volume`).
- `CLUSTER` — `room-a`: the snapshot's cluster name when `/etc/vms/vms.env` says none — the name the env example, the Nomad appendix and М12 give the module's cluster (it was `cluster-a` here; the twelfth review's «Вопросы»).

## Functions

### `stores(role, env=None) -> (vars_, objects)`
The process's two stores, opened when it runs and never at import (a test imports this module, and `ClusterObjectStore` makes its directory when built): `open_vars(store_url(env, "configstore:///run/configstore/<role>.sock"))` — `PLATFORM_STORE` first, `CONFIG_URL` the older name, else the role's own socket — and `open_store(OBJECTS, vars_=vars_)`, so a worker's mark before a device command is a row through ITS socket and its rights, not a second handle opened from the environment. A spare's template names its role's socket as the role's unit does (`vms-vmsworker-spare@.service`); a process that names none gets its verb's role's socket by this default. `tests/test_lesson2_jobs.py::test_each_process_opens_its_roles_socket_and_its_objects_on_its_own_server`.

### `make_worker(vars_, objects, actuator=None, env=None, **kw)`, `make_recorder(...)`
Build the process AND register it with its server's resource (`Worker.present(w.archive_root)`: a lock in `<events archive>/.workers` for as long as the process lives, its name beside it), as the box's entry point does (`vms/__main__._present`). The cluster's entry points did not register (the twelfth review's «Вопросы», defect 1): every resource heartbeat said `workers`/`running` empty, a dead process on a live server was `wait` for ever and `release_unlisted` never worked. The units run these two and so does the stand (`tests/conftest.py`): `test_lesson4_failover.py::test_every_unit_registers_with_its_servers_resource_and_a_process_that_ended_moves_when_its_slot_runs_out`, `::test_the_worker_entry_point_registers_its_process_before_it_runs`.

### `worker()`
The worker's unit: holds cameras, records nothing. Builds a `GstActuator()` (the fan-out on `:8554`, bound to `RTSP_HOST`, which the unit opens) if GStreamer imports, otherwise logs a warning and passes `None` (→ `FakeActuator`). Its fan-out's port is the unit's too (`RTSP_PORT`, `auto` for a spare beside the server's own worker), and what the OS gave is announced. Then `make_worker(*stores("vmsworker"), act)` — built and registered: the name from the unit (`WORKER_NAME`) claimed by CAS — or, a spare, an offer of its label set (`SPARE_FOR`) — the server and labels from the environment (see `worker.py.md`). Logs name/server/instance/labels and calls `w.run(stop=stop, beat=commands_beat(os.environ))` — М10's poll loop (reconcile, lease pass, heartbeat), with a look at the request rows every `COMMANDS_BEAT` seconds between passes (0.25; `0` — only on the pass): each look is one list of `vms/requests/` through this server's configstore, a read through the log — which on `stop` releases the slot.

### `recorder()`
`make_recorder(*stores("recworker"), GstRecActuator(), env=…, archive_root=archive)` — built and registered, its own volume `ARCHIVE_VOLUME` or `config.OWN_VOLUME` said in its environment as on a box: takes a volume, opens it through the host's `obsd` (`OBSD_SOCKET`; the unit says `/run/vms-obsd/obsd.sock`, where `vms-obsd.service` listens), serves it at its archive door — bound where `ARCHIVE_URL` says it is reachable, else loopback, never every interface — and runs М10's `RecWorker` loop. Its heartbeat says `ARCHIVE_URL` only when that names the port the door got: a spare recorder asks the OS for one (`ARCHIVE_PORT=0`) and announces what it bound.

### `reccontroller()`
`SpecController(REC_SPEC, *stores("reccontroller"), capacity=CAPACITY|50)` on the same five-second pass as `controller` (`_placement_pass("rec placement", ctl)`). A unit on every server, safe at several.

### `_steps(what, *steps)`
Each step of a controller's pass in a try of its own (the review's seventh pass, part 2): they shared one, so a step that raised — one row it could not read — skipped every step after it, the snapshot the layer above reads included. A step's name is its `__name__`, or `step <i>` for a lambda. **Said once per spell** (the eighth review's minor, closed in the ninth): the trace went into the log on every pass, every five seconds for as long as the step kept failing. Now the first failure logs the trace (`logging.exception`) and adds `(what, name)` to the module-level `_failing`; later failures of the same step say nothing; the first success after them logs a warning "`<what>: <name> works again`" and drops the pair — as М12's `domain/steps.py` says it. The same rule for the steps inside `pass_once` is checked by `vmsserver/tests/test_garbled_rows.py::test_a_pass_report_counting_past_any_number_stops_no_pass_and_a_step_that_fails_every_pass_is_said_once`.

### `_placement_pass(what, ctl)`
One pass of a placement controller, the same as the box's loop makes it (`vms/__main__._controller_loop`; the review's eighth pass, found by the coordinator). `with ctl.one_pass():` then `_steps(what, lambda: ctl.pass_once(1), ctl.publish_snapshot)`. `pass_once(1)` places, moves, brings ONE unit home — each step in a try of its own — and writes the pass report `<sub>/controller/pass`, which is where `/metrics` reads `<sub>_units_unplaced`, `<sub>_reconcile_pass_seconds`, the last pass and the last success (the cluster's loops called the three steps one by one and wrote no report: those metrics said 0 and -1 for ever). Then the snapshot, in a step of its own — the recordings' too, as on a box (`rec_snapshot_age_seconds` was -1 here). **Both in ONE pass of reads** (`contract.one_pass`; the scaling pass after the eighth review): the snapshot asks every unit's row, placement and server, and the placement pass has just read them — a thousand cameras cost the two together some 64 000 reads of the store's leader every five seconds, 2 000-odd now (`vmsserver/tests/test_read_budget.py::test_an_idle_controller_pass_over_a_thousand_cameras_reads_each_row_once`). Used by `controller()` and `reccontroller()`; the cluster's test: `tests/test_lesson5_controller.py::test_the_clusters_controller_loops_write_the_pass_report_its_metrics_read`.

### `controller()`
The controller's unit, on every server — safe at several, because every write is a CAS (lesson 10) — no HTTP (the docstring: "nothing asks it anything"). `ClusterController(*stores("vmscontroller"), capacity=CAPACITY|50, cluster=CLUSTER|room-a)` — М10's `VmsController`. Every 5 seconds `_placement_pass("placement", ctl)` (above): `pass_once(1)` — the decommissions, `ensure_placed()`, the moves off dead slots and silent servers, `redistribute()`, `ensure_home(1)`, the offers for the workers it is short of (`offer_spares`) and the pass report — then `publish_snapshot()`. It starts no process: `w2c-spares.sh` reads the numbers and starts spares. The rights file is what limits its socket to placement.

### `console()`
The console's unit, one on every server. `stores("console")` — the console's socket: the operator's rows and nothing else (the rights file, not the class) — a `ClusterController` over them, then `cluster.console.serve(ctl, CONSOLE_HOST|0.0.0.0, CONSOLE_PORT|8080, archive_root=archive if it exists, rec_ctl=…)`. No index of its own: `/events` asks every live resource's `GET /events` and merges. Beside its door, the box's console loop (`_console_loop`, `console_turn`): what a request asked turned into work and a recording on request ended at its `until` (`vms/__main__._requests_turn`), the answered requests cleared (`clear_requests`) every two seconds, the reaper's pass every thirty — the cluster's console ran none of them, and nobody in М11 kept a request's `until` (the twelfth review, on the author's answer: REREAD). Every server's console runs it; its writes are CASes. `tests/test_lesson5_controller.py::test_the_clusters_console_keeps_a_requests_until_as_the_boxs_does`. Then it waits for `stop` and shuts the HTTP server down.

### `resource()`
The platform's resource with the VMS registered on it (`w2c-resource.service`). `server` is `runtime.server(os.environ)`; `url` from `RESOURCE_URL` (default `http://<server>:8090`) — what peers and the console dial, and what its heartbeat says in `platform/doors/<server>` (the door every `cluster://` reader's resource asks). `cluster_resource(archive, server, url, *stores("resource"))`; `w2cplatform.resource.serve(res, 0.0.0.0, RESOURCE_PORT|8090)` serves the platform's `/buckets`, `/events`, `/mirror`, `/mirrored` and `/v1/objects` — nothing of footage. Before the loop: one heartbeat, then `res.restore()` — "back with an empty disk? pull my buckets from my peers first". Loop every 10 seconds, three tries, each in its own try (the review's seventh pass, part 2): the heartbeat; every 600 seconds `res.pass_()` (retention, the events mirror, the blob mirror), `last_policy` set before the call so a pass that raised is tried in ten minutes; and `res.restore()` again whenever `res.restore_due()` says so (the eighth review). Tests: `vmsserver/tests/test_row_reader.py::test_a_restore_takes_what_every_peer_gives_and_asks_again_for_what_did_not_come`, `::test_a_restore_that_met_no_live_peer_or_raised_whole_is_asked_again_and_a_late_peer_is_asked`. The first heartbeat and the first restore are each in a try too: a store away at the start does not end the process.

### `if __name__ == "__main__"`
`rights` first (`cluster.rights.main`, its exit code); else the signal handlers, then a dict dispatch on `sys.argv[1]`; an unknown verb is a `KeyError` traceback, and systemd starts the unit again (and says so).

## Notes
- `console` and `controller` build the same `ClusterController`; the difference between the two processes is entirely the socket their units name and the group they join — the rights the daemon applies to it.
- Nothing is opened at import: `python3 -m cluster worker` with no daemon on this server fails at its first store call (the handle tries a refused connection again for 5 s, then `StoreUnavailable`), not at import.
