# __main__.py — `python3 -m cluster worker | controller | recorder | reccontroller | console | resource`: the six Nomad jobs' entry points

**Role in the module.** The one process image the cluster runs (`deploy/Containerfile`), dispatched by `sys.argv[1]` into one of four long-running functions — one per jobspec in `deploy/`. It is М10's `vms/__main__.py` (see `../../../vmsserver/vms/__main__.py.md`) with the stores replaced: `NomadVariables` (raft, the task's own `NOMAD_TOKEN`) instead of file Variables, and `open_store(OBJECTS)` — by default Variables under `objects/…` — instead of a directory. Everything each job *does* is М10's class; what this file adds is which environment variable feeds which constructor, and the loop cadence. The module docstring is the environment contract for the jobspecs: `NOMAD_ADDR`/`NOMAD_TOKEN` (workload identity), `OBJECTS`, `NOMAD_ALLOC_INDEX`/`NOMAD_NODE_NAME`/`NOMAD_META_labels`, `ARCHIVE`, `OBSD_SOCKET`, `ARCHIVE_HOST`/`ARCHIVE_PORT`, `RESOURCE_URL`, `CAPACITY`.

## Module-level names
- `logging.basicConfig(...)` — level from `LOG_LEVEL` (default `INFO`); one format for all four jobs so Nomad's `alloc logs` read alike.
- `stop` — a `threading.Event` set by `SIGTERM` or `SIGINT`; the handler is installed when the module is run (`if __name__ == "__main__"`), never at import, so a process that imports it — a test run — keeps its own signals. Nomad stops a task with SIGTERM and waits `kill_timeout` (20 s for the worker, see `deploy/vmsworker.nomad.hcl.md`); every loop below polls `stop` so that a stop is orderly — for the worker that means `release_slot()`, which is what turns a scale-in into "redistribute" rather than "a crash".
- `objects` — the object store, opened once from `OBJECTS` (default `variables://objects`, i.e. heartbeats and the snapshot as Nomad Variables; `s3+http://…` for MinIO/S3; `file:///path` on a bench). Shared by all four functions.
- `_failing` — a `set` of `(loop, step)` pairs: the controller steps that are failing now, so `_steps` says a failure once per spell and says when it works again.
- `archive` — `ARCHIVE` (default `/data/archive`): the resource's tree on this server — every subsystem's events — mounted by the jobspecs' `volumes`; a recorder's own volume lives beside it (`/data/volume`), opened by the host's `obsd`.

## Functions

### `worker()`
The `vmsworker` job: holds cameras, records nothing. Builds a `GstActuator()` (the fan-out on `:8554`) if GStreamer imports, otherwise logs a warning and passes `None` (→ `FakeActuator`). No footage — that is the `recorder` job's: `ClusterRecorder(NomadVariables(), objects, GstRecActuator(), archive_root=archive)`, which takes a volume, opens it through the host's `obsd` (`OBSD_SOCKET`, default `/run/vms/obsd.sock`), serves it at its archive door (`ARCHIVE_HOST`/`ARCHIVE_PORT`, default `0.0.0.0:8084`) and runs М10's `RecWorker` loop; `reccontroller` is `SpecController(REC_SPEC)` on the same five-second pass as `controller` (`_placement_pass("rec placement", ctl)`: `pass_once(1)`, then the recordings' snapshot). Then `ClusterWorker(NomadVariables(), objects, act)`: the slot is claimed from `NOMAD_ALLOC_INDEX` by CAS, the server and labels come from the environment (see `worker.py.md`). Logs name/server/alloc/labels and calls `w.run(stop=stop, beat=commands_beat(os.environ))` — М10's poll loop (reconcile, lease pass, heartbeat), with a look at the request rows every `COMMANDS_BEAT` seconds between passes (0.25; `0` — only on the pass): on a cluster each look is one list of `vms/requests/` in Nomad's Variables, an ordinary read answered by the leader — which on `stop` releases the slot. `CAPACITY` is read inside `VmsWorker` from the environment.

### `_steps(what, *steps)`
Each step of a controller's pass in a try of its own (the review's seventh pass, part 2): they shared one, so a step that raised — one row it could not read — skipped every step after it, the snapshot the layer above reads included. A step's name is its `__name__`, or `step <i>` for a lambda. **Said once per spell** (the eighth review's minor, closed in the ninth): the trace went into the log on every pass, every five seconds for as long as the step kept failing. Now the first failure logs the trace (`logging.exception`) and adds `(what, name)` to the module-level `_failing`; later failures of the same step say nothing; the first success after them logs a warning "`<what>: <name> works again`" and drops the pair — as М12's `domain/steps.py` says it. The same rule for the steps inside `pass_once` is checked by `vmsserver/tests/test_garbled_rows.py::test_a_pass_report_counting_past_any_number_stops_no_pass_and_a_step_that_fails_every_pass_is_said_once`.

### `_placement_pass(what, ctl)`
One pass of a placement controller, the same as the box's loop makes it (`vms/__main__._controller_loop`; the review's eighth pass, found by the coordinator). `with ctl.one_pass():` then `_steps(what, lambda: ctl.pass_once(1), ctl.publish_snapshot)`. `pass_once(1)` places, moves, brings ONE unit home — each step in a try of its own — and writes the pass report `<sub>/controller/pass`, which is where `/metrics` reads `<sub>_units_unplaced`, `<sub>_reconcile_pass_seconds`, the last pass and the last success (the cluster's loops called the three steps one by one and wrote no report: those metrics said 0 and -1 for ever). Then the snapshot, in a step of its own — the recordings' too, as on a box (`rec_snapshot_age_seconds` was -1 here). **Both in ONE pass of reads** (`contract.one_pass`; the scaling pass after the eighth review): the snapshot asks every unit's row, placement and server, and the placement pass has just read them — a thousand cameras cost the two together some 64 000 reads of Nomad's leader every five seconds, 2 000-odd now (`vmsserver/tests/test_read_budget.py::test_an_idle_controller_pass_over_a_thousand_cameras_reads_each_row_once`). Used by `controller()` and `reccontroller()`; the cluster's test: `tests/test_lesson5_controller.py::test_the_clusters_controller_loops_write_the_pass_report_its_metrics_read`.

### `controller()`
The `vmscontroller` job, `count = 1`, no HTTP (the docstring: "nothing asks it anything"). `ClusterController(open_vars(CONFIG_URL), objects, capacity=CAPACITY|50, cluster=CLUSTER|"cluster-a")` — М10's `VmsController`. Every 5 seconds `_placement_pass("placement", ctl)` (above): `pass_once(1)` — `ensure_placed()` (which also runs `unplace_deleted()` inside the platform's `SpecController`), `redistribute()` (released slots' cameras moved), `ensure_home(1)` and the pass report `vms/controller/pass` — then `publish_snapshot()` (the one object that leaves the cluster, `objects/vms/snapshot`). A step that raises is said once and the others go on; nothing else is retried because every write is a CAS and the next pass re-reads. The controller's token (`deploy/vmscontroller-policy.hcl`) is what limits it to placement.

### `console()`
The `console` job, `type = system`: one per server that has a resource. Builds a `ClusterController` with the *console's* token (the same class as the controller — what it may write is decided by `deploy/console-policy.hcl`, not by the class), then `cluster.console.serve(ctl, CONSOLE_HOST|0.0.0.0, CONSOLE_PORT|8080, archive_root=archive if it exists)`. No index of its own: `make_console` defaults `index` to a `MergedIndex`, so `/events` asks every live resource's `GET /events` and merges. `archive_root` is where the console's own marks bucket goes — this server's resource — which is why the jobspec constrains the console to `meta.archive` servers. Then it waits for `stop` and shuts the HTTP server down. `worst_failover` is not passed, so `/metrics` reports `vms_failover_seconds{kind="worst"} 0.0` plus each worker's own measurement.

### `resource()`
The platform's `resource` job with the VMS registered on it. `server` is `runtime.server(os.environ)` — `SERVER_NAME`, which the jobspec maps from `${node.unique.name}`, else the hostname; `url` from `RESOURCE_URL` (default `http://<server>:8090`) — what peers and the console dial. `cluster_resource(archive, server, url, open_vars(CONFIG_URL), objects)` builds `w2cplatform.resource.Resource` with the event index (see `resource.py.md`); `w2cplatform.resource.serve(res, 0.0.0.0, RESOURCE_PORT|8090)` serves the platform's `/buckets`, `/events`, `/mirror`, `/mirrored` — nothing of footage. Before the loop: one heartbeat, then `res.restore()` — "back with an empty disk? pull my buckets from my peers first" (the reverse of mirror); the event index `cluster_resource` attached (`res.index`) needs no start: it reads THIS tree where it lies at each query, the restored buckets included, and `serve` answers `GET /events` from it while `res.retain()` tells it what it removed. Loop every 10 seconds, three tries — as М10's resource loop has them (`vms/__main__.py`; the review's seventh pass, part 2: they shared one here, so a heartbeat that raised skipped the pass, and a pass that raised was tried again every ten seconds instead of every ten minutes): heartbeat (`objects/platform/resources/<server>/heartbeat`); every 600 seconds `res.pass_()` — the platform's retention/mirror pass plus every registered hook (none of the VMS's: footage is in volumes), with `last_policy` set before the call, so a pass that raised is tried in ten minutes, not in ten seconds; and `res.restore()` again ("restore again: …" in the log) whenever `res.restore_due()` says so (the eighth review: the restore ran once at start, and what it missed stayed with the peers until their retention took it). `restore_due` is the platform's (`w2cplatform/resource.py`): its pause first — `RESTORE_RETRY` (10 s), doubling up to `RESTORE_RETRY_MAX` (600 s) — then due if the restore never ran through with somebody to ask, left buckets with peers, or a peer gave no listing; and, done, if a live peer holds copies of this server it has not given (looked for every `RESTORE_RETRY_MAX`). A restore that raises in the loop is logged ("restore failed again; asked again later") and the loop goes on. Tests: `vmsserver/tests/test_row_reader.py::test_a_restore_takes_what_every_peer_gives_and_asks_again_for_what_did_not_come` and `::test_a_restore_that_met_no_live_peer_or_raised_whole_is_asked_again_and_a_late_peer_is_asked`. The first heartbeat and the first restore are each in a try too (the eighth and the seventh review): a store away at the start does not end the process.

### `if __name__ == "__main__"`
A dict dispatch on `sys.argv[1]`; an unknown verb is a `KeyError` traceback, which is fine for a job that Nomad would restart anyway.

## Notes
- `console` builds its `ClusterController` with the same constructor as `controller`; the difference between the two processes is entirely in the token Nomad injects (`identity { env = true }`) and the policy bound to the job.
- `OBJECTS`, `ARCHIVE` and `objects` are evaluated at import, so `python3 -m cluster` with `OBJECTS=variables://…` and no `NOMAD_ADDR` still constructs a `NomadVariables` pointed at `http://127.0.0.1:4646` — the first `put` is what fails, not the import.
