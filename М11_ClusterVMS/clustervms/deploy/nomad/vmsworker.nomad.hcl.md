# vmsworker.nomad.hcl — the appendix: the worker as a Nomad service job

**Role in the module.** The appendix «форма поставки», and the job М12 Lesson 8 renders three ways (`domain/cloud.py`, `render_three_ways`: the datacenter and `OBJECTS` differ, `worker_stanza` from `group` down does not). The same worker as `vms-vmsworker.service` — `raw_exec` of `w2c-run.sh worker` as `vms`, `PLATFORM_STORE` the node's configstore socket — with the one thing an orchestrator adds: it starts the worker again on another node when its node is lost. So the name comes from the allocation's index (`SLOT_INDEX`, `w-<index>`), which moves with the allocation, and `disconnect { lost_after = "45s" }` is the margin the controller otherwise waits. `count` is the operator's; no autoscaler. The cost: `raw_exec` has no per-task groups, so the node's `vms` user is a member of its roles' groups and any `vms` process could open any `vms-*` socket — weaker than a unit's `SupplementaryGroups=`.
