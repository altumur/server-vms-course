# com.w2c.vms.console.plist — the console, on a macOS server

**Role in the module.** Lesson 3. The twin of `deploy/systemd/vms-console.service`: `__BOX__/bin/w2c-run.sh` with the same verb, `KeepAlive` and a 2 s `ThrottleInterval` for systemd's `Restart=always`/`RestartSec=2`, the store's socket under `__BOX__/state/run/configstore`. A box on macOS is a directory (`install.sh --box <dir>`, the thirteenth review, major 15: there is no /data on a Mac): `__BOX__` is replaced by it, `W2C_BOX` names it to the runner, which reads the box's `w2c.env` and `vms.env`. launchd has no `%l` and no groups per job: `install.sh` puts this host's short name in place of `@HOST@`; the plist goes to the user's `~/Library/LaunchAgents` and runs as that user — a developer's server, not a production one. Logs in `__BOX__/state/logs/com.w2c.vms.console.log`. Its environment is the unit's, name for name: `CONSOLE_UNIX` under `/var/run/vms-console` and `SECRETS_KEY` — without it the console on macOS stored passwords in the clear. `tests/test_units.py::test_every_plist_is_its_units_twin`, `::test_every_plist_says_what_its_unit_says_name_for_name` (the twelfth review, major 12).
