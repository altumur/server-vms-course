# vms-vmsworker-spare@.service — a spare worker, started by `w2c-spares.sh`

**Role in the module.** Lesson 4. `vms-vmsworker.service` line for line — the same user, groups, socket, key, umask, watchdog, protection — but no name: no `WORKER_NAME`; its label set from a file the script writes before it starts the instance, named by `Environment=SPARE_FILE=/run/w2c-spares/%n.env`, of which `w2c-run.sh` takes the line `SPARE_FOR=<set>` and nothing else, checked against the labels' alphabet (a spare whose set is not said, or not a set, does not start, else it would be a worker taking any free name). Not `EnvironmentFile=` (the product's cross-check, 4 Oct): whoever could write the file could set any variable — `LD_PRELOAD` too — in a process holding the role's key; its fan-out on a port the OS gives (`RTSP_PORT=auto`), 8554 being the server's own worker's. No `[Install]`: never enabled, only its instances started (`systemctl start vms-vmsworker-spare@<n>`). It replaced `systemd-run … w2c-run.sh worker`, a root process without the key or the opened fan-out (the twelfth review, blocker 6). A template and not a list of properties in the script: one file beside the role's, shown by `systemctl cat`, `%d` expanded, held to the role's unit by a test.
